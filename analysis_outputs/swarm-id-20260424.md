# Classifying Swarm

What would indicate a real swarm is not “many agents,” but local interaction rules producing useful global behavior.

Good indicators would be:

- Decentralization: no single boss/planner/router deciding everything.
- Local rules: agents act on partial information and simple neighbor-level signals.
- Emergent coordination: system-level behavior arises from interactions, not from a fixed top-down workflow.
- Adaptive self-organization: roles, clusters, routes, or priorities change in response to conditions without a central controller scripting it.
- Stigmergy or shared-environment coordination: agents coordinate indirectly through a shared workspace, memory field, blackboard, or state traces.
- Swarm-style search/exploration: multiple agents explore solution space, exchange weak signals, reinforce promising directions, and abandon bad ones.
- Robustness: system still works reasonably if some agents fail or communication is partial.
- Simple agents, strong collective behavior: each unit can be pretty dumb, but the ensemble is effective.

Concretely, examples of things that would feel swarm-like:

- agents leaving scored traces in a shared memory that attract or repel later actions
- dynamic clustering/splitting of agents around subproblems
- reputation/pheromone-style reinforcement of useful plans or tools
- consensus forming from repeated local voting, not a single judge
- task allocation emerging from bidding/competition, not a planner assigning tasks
- routing that evolves from interaction history rather than a predefined DAG
- What does not, by itself, indicate swarm:
- 
- a planner-worker architecture
- manager/subordinate trees
- fixed pipelines
- debate + judge
- majority voting once at the end
- “auto-build agents from prompt”

Compact test: If I can summarize the system as “a workflow with roles,” it’s probably not a swarm. If I summarize it as “many simple actors following interaction rules, and the structure of coordination emerges,” then it starts to qualify.
