# The Role of Global and Local Context in Named Entity Recognition

## Quick Facts
- arXiv ID: 2305.03132
- Source URL: https://arxiv.org/abs/2305.03132
- Reference count: 12
- Primary result: Global context retrieval outperforms local context for NER in long documents

## Executive Summary
This study addresses the challenge of processing long documents for Named Entity Recognition by investigating how local and global context affect performance. Transformer models struggle with long documents due to quadratic self-attention complexity, forcing sequential processing that loses global context. The authors propose retrieving additional context sentences using different heuristics and demonstrate that global context retrieval, particularly using common noun matching, significantly outperforms local context approaches. Even simple retrieval methods can substantially improve NER performance when global context is leveraged.

## Method Summary
The authors evaluate NER performance by retrieving additional context sentences from the document using six different heuristics: before, after, surrounding (local), random, samenoun (global), and BM25 (global). They use a BERT-based NER model and test both oracle versions (where the most beneficial sentence is selected) and heuristic versions. The study focuses on the first chapter of 40 novels from the BookNLP dataset, using strict token-level evaluation. Performance is measured using F1 score across different numbers of retrieved sentences.

## Key Results
- Global context retrieval, particularly the "samenoun" heuristic, outperforms local context approaches
- Oracle experiments show single retrieved sentence can significantly improve performance
- Removing local context while using global context has minimal impact on NER accuracy
- Best performance (F1 ≈ 0.945) achieved with oracle versions of retrieval heuristics
- Global approaches consistently outperform local ones in oracle settings

## Why This Works (Mechanism)
Assumption: Global context retrieval works better because entity mentions in long documents often have dependencies that span beyond adjacent sentences. The "samenoun" heuristic is particularly effective because it captures semantically related entities across the document, allowing the model to resolve coreferences and understand entity relationships that would otherwise be missed when processing in isolation.

## Foundational Learning
Unknown: The paper does not explicitly discuss whether the model exhibits foundational learning capabilities or how prior knowledge affects its ability to leverage retrieved context. The BERT-based NER model likely relies on pre-trained language understanding but the study focuses on context retrieval rather than model architecture innovations.

## Architecture Onboarding
Assumption: The study uses a standard BERT-based NER architecture where the context retrieval module serves as a preprocessing step. The retrieved sentences are concatenated with the target sentence before being fed into the BERT encoder, allowing the model to process both local and global context together. This approach is architecture-agnostic and could be applied to other transformer-based NER models.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal number of retrieved sentences for maximizing NER performance in long documents?
- Basis in paper: The paper shows performance peaks when retrieving a single sentence with oracle versions of retrieval heuristics, but does not explore intermediate values systematically.
- Why unresolved: The paper focuses on comparing different retrieval strategies rather than optimizing the number of retrieved sentences. The performance plateau around 1-2 sentences suggests diminishing returns, but the exact optimal number for different document types remains unknown.
- What evidence would resolve it: Systematic experiments varying the number of retrieved sentences (e.g., 1, 2, 4, 8, 16) across different document types and lengths would reveal optimal ranges for different contexts.

### Open Question 2
- Question: How do more sophisticated retrieval methods compare to the simple heuristics tested in this paper?
- Basis in paper: The authors explicitly state their heuristics are "naive on purpose" and acknowledge "stronger retrieval heuristics may achieve better results."
- Why unresolved: The paper uses only basic retrieval approaches (random, BM25, noun matching) without exploring more advanced techniques like semantic similarity, entity linking, or learned retrieval models.
- What evidence would resolve it: Comparative experiments using advanced retrieval methods such as semantic search, transformer-based sentence embeddings, or learned retrieval models would establish performance gaps.

### Open Question 3
- Question: How does the effectiveness of global context retrieval vary across different document types and genres?
- Basis in paper: The experimental dataset is homogeneous (literary novels), and the authors acknowledge this limitation. Different genres may have different entity mention patterns and context distributions.
- Why unresolved: The paper uses only the first chapter of 40 novels, limiting generalizability to other document types like news articles, scientific papers, or dialogue-heavy texts.
- What evidence would resolve it: Experiments across diverse document types (news, biomedical texts, social media, technical documentation) would reveal whether the findings generalize or if document type significantly affects context retrieval effectiveness.

## Limitations
- Oracle retrieval assumes perfect knowledge of beneficial context sentences, not reflecting real-world conditions
- Experiments limited to novels, raising questions about generalizability to other document types
- Focus on specific dataset (BookNLP) may not represent all long document scenarios
- Heuristic versions may not fully capture the potential improvements shown in oracle experiments

## Confidence
- Core finding that global context is more valuable than local context: High
- Practical utility of specific retrieval heuristics: Medium
