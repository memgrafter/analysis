# Data augmentation for machine learning of chemical process flowsheets

## Quick Facts
- arXiv ID: 2302.03379
- Source URL: https://arxiv.org/abs/2302.03379
- Reference count: 1
- Key outcome: Data augmentation improved transformer-based flowsheet autocompletion perplexity by 14.7%

## Executive Summary
This paper introduces a data augmentation technique for chemical process flowsheets represented in SFILES 2.0 notation by randomizing branching decisions during graph traversal. The method generates multiple valid string representations of the same flowsheet, effectively increasing training data diversity without altering the underlying process information. Applied to a transformer-based flowsheet autocompletion model, the augmentation improved fine-tuning perplexity by 14.7% compared to non-augmented training, particularly effective in low-data regimes and reducing overfitting.

## Method Summary
The method involves randomizing branching decisions during SFILES 2.0 string generation to create multiple valid representations of the same flowsheet graph. During traversal, when encountering a splitter node, the order of branches is permuted randomly rather than following canonical ordering. This generates synthetic training data that preserves semantic meaning while increasing dataset size. The augmented SFILES strings are used to pretrain and fine-tune transformer-based flowsheet autocompletion models, with the augmented pretraining data leading to better fine-tuning performance on real flowsheet data.

## Key Results
- Data augmentation improved fine-tuning perplexity by 14.7% compared to non-augmented training
- The approach is particularly effective in low-data regimes and reduces overfitting
- Augmented SFILES strings are valid flowsheet representations that help models learn SFILES grammar and chemical process structure

## Why This Works (Mechanism)

### Mechanism 1
Randomizing branching decisions during SFILES generation creates syntactically valid but structurally distinct representations of the same flowsheet graph. The SFILES 2.0 notation encodes flowsheet graphs as strings by traversing nodes in a specific order. When encountering a branching point (e.g., a splitter), the traversal order of branches can be permuted. This permutation yields different SFILES strings that map back to the identical underlying graph, effectively generating synthetic data without altering the process information.

### Mechanism 2
Data augmentation reduces overfitting by increasing training data diversity without increasing model capacity. By generating multiple SFILES for each flowsheet, the training set size increases, exposing the model to more variations of the same underlying process. This expanded diversity helps the model generalize better, as evidenced by smaller gaps between training and test perplexity.

### Mechanism 3
Pretraining with augmented data improves fine-tuning performance in low-data regimes. The pretraining phase learns general SFILES grammar and structure from a large, generated dataset. Augmenting this pretraining data increases its diversity, leading to a better initialization for fine-tuning on the small real dataset. This results in lower perplexity after fine-tuning.

## Architecture Onboarding

- **Component map**: SFILES 2.0 parser/generator -> Transformer-based autocompletion model -> Datasets (generated for pretraining, real for fine-tuning) -> Evaluation pipeline (perplexity computation)

- **Critical path**: 1) Generate or load flowsheet graphs 2) Convert graphs to SFILES strings using augmented generator 3) Split data into training/validation/test sets 4) Pretrain transformer on augmented generated dataset 5) Fine-tune transformer on augmented real dataset 6) Evaluate perplexity on test set

- **Design tradeoffs**: Number of augmentations per flowsheet (more increases diversity but also training time), branch order randomization strategy (full vs. controlled randomization), integration with existing SFILES 2.0 library (modifying vs. separate module)

- **Failure signatures**: Perplexity does not improve or worsens after augmentation, training and test perplexity remain significantly different (indicating overfitting), generated SFILES strings are invalid or don't map back to original graph, model training time increases disproportionately

- **First 3 experiments**: 1) Implement SFILES 2.0 parser/generator with branch order randomization and verify augmented strings map back to original graph 2) Train small transformer model on toy flowsheet dataset with/without augmentation, comparing training/test perplexity 3) Scale to full flowsheet autocompletion model, pretraining on generated dataset with augmentation and fine-tuning on real dataset, measuring perplexity improvement

## Open Questions the Paper Calls Out

- **Optimal number of augmentations**: How does the number of augmentations per flowsheet affect model performance and training time? The paper tests only 5 augmentations and suggests this warrants further investigation through systematic experiments varying augmentation numbers.

- **Generalization to other NLP models**: Can the data augmentation method be extended to other NLP models beyond the transformer-based autocompletion model tested? The paper only demonstrates effectiveness on one specific model type and aims to apply the methodology to further NLP models.

- **Optimal strategy for combining augmentation with synthetic data generation**: What is the optimal balance between synthetic data generation and augmentation? The paper uses both methods but doesn't explore the optimal combination through experiments comparing models trained with only synthetic data, only augmented real data, and various combinations.

## Limitations
- The method is specific to SFILES 2.0 notation and may not generalize to other flowsheet representations
- Effectiveness of branch order randomization needs further validation across diverse flowsheet structures
- The study relies on a relatively small real-world dataset (223 flowsheets) for fine-tuning

## Confidence
- **High Confidence**: Core mechanism of generating multiple valid SFILES strings through branch order randomization is well-established; 14.7% perplexity improvement is directly measurable
- **Medium Confidence**: Claims about overfitting reduction are supported by perplexity gaps but lack statistical significance testing; benefits transfer from pretraining to fine-tuning assumes consistent learning dynamics
- **Low Confidence**: Generalizability to other flowsheet notations or chemical engineering tasks remains unproven; optimal augmentation strategy is not thoroughly explored
