# Neural Architecture Search for Parameter-Efficient Fine-tuning of Large Pre-trained Language Models

## Quick Facts
- arXiv ID: 2305.16597
- Source URL: https://arxiv.org/abs/2305.16597
- Reference count: 10
- One-line primary result: Neural architecture search discovers PET architectures using fewer parameters than hand-designed methods while achieving comparable or better GLUE performance

## Executive Summary
This paper introduces a pruning-based neural architecture search method to automatically learn parameter-efficient fine-tuning (PET) architectures for large pre-trained language models. The approach uses a first-order approximation of loss change from pruning to identify which parameters to fine-tune within modules like bias terms and LoRA updates. Experiments on the GLUE benchmark show that the learned architectures achieve comparable or better performance than established hand-designed PET methods while using fewer parameters, with the key insight that bias parameters in middle layers are most parameter-efficient to fine-tune.

## Method Summary
The method begins with a maximum-size PET architecture (e.g., BitFit or LoRA) and iteratively prunes parameters based on a first-order approximation of loss change, computed as the sum of -θ·∂L/∂θ averaged over all training steps to smooth SGD noise. The search space includes structured and unstructured variants for both bias-tuning and LoRA update modules. After pruning to meet a parameter budget, the architecture is re-initialized and retrained. The process iterates to find architectures that maximize validation performance within budget constraints, with experiments conducted on GLUE tasks using RoBERTa-Large.

## Key Results
- Unstructured bias-tuning architecture with 25k parameters achieves similar GLUE performance to WARP while using only 9% of all bias parameters
- Structured bias-tuning requires tuning all bias parameters to match BitFit performance, while unstructured can achieve similar results with fewer parameters
- Bias parameters in middle layers are identified as most parameter-efficient to fine-tune across tasks
- Learned architectures consistently outperform hand-designed PET methods at equivalent parameter budgets

## Why This Works (Mechanism)

### Mechanism 1
First-order approximation of loss change from pruning provides effective signal for identifying parameters to remove. The paper uses the gradient magnitude multiplied by parameter value (-θ * ∂L/∂θ) as pruning criterion, averaging this over all training steps to smooth SGD noise and identify which parameters contribute least to training loss. Core assumption: Parameters with small gradients relative to their magnitude contribute minimally to model performance and can be pruned without significant loss. Break condition: If parameter importance is non-monotonic during training, averaging over steps could mask critical periods where certain parameters are temporarily important.

### Mechanism 2
Structured vs unstructured pruning offers different efficiency vs performance tradeoffs in PET architectures. Structured pruning removes entire parameter groups (like all parameters in a bias vector) while unstructured pruning can remove individual parameters, allowing more fine-grained control over parameter budget. Core assumption: The distribution of important parameters across modules determines whether structured or unstructured approaches are more parameter-efficient. Break condition: If important parameters cluster in specific modules, structured pruning could achieve better efficiency than unstructured.

### Mechanism 3
Middle-layer parameters are most parameter-efficient to fine-tune in transformer architectures. The learned architectures show consistent preference for fine-tuning parameters in middle layers, suggesting these layers capture the most transferable representations. Core assumption: Middle layers contain the most general linguistic features that benefit from task-specific adaptation. Break condition: If task-specific features are primarily captured in early or late layers for certain tasks, this middle-layer preference may not generalize.

## Foundational Learning

- Concept: First-order Taylor approximation for loss change
  - Why needed here: Provides computationally efficient way to estimate importance of parameters without expensive retraining
  - Quick check question: If you have a parameter θ with gradient ∂L/∂θ = -0.1 and current value θ = 0.2, what is the estimated loss change from removing this parameter?

- Concept: Structured vs unstructured pruning in neural networks
  - Why needed here: Different pruning granularities affect both the efficiency of the search space and the final parameter efficiency
  - Quick check question: What's the key tradeoff between structured pruning (removing entire vectors/rows) versus unstructured pruning (removing individual elements)?

- Concept: Transformer layer architecture and parameter distribution
  - Why needed here: Understanding which parameter types (biases, attention weights, FFN weights) are in which layers is crucial for interpreting the learned architectures
  - Quick check question: In a typical transformer block, which modules contain bias parameters that could be targeted by bias-tuning methods?

## Architecture Onboarding

- Component map: NAS controller -> pruning module -> parameter budget manager -> training loop
- Critical path: 1. Initialize PET architecture with maximum allowed parameters 2. Train on downstream task 3. Compute pruning criteria averaged over all training steps 4. Sequentially prune parameters by increasing criterion value until budget met 5. Reinitialize pruned architecture with same initialization as original 6. Retrain and evaluate on validation set
- Design tradeoffs:
  - First-order approximation vs higher-order methods: faster computation but potentially less accurate
  - One-shot vs iterative pruning: simpler implementation but may miss optimal architectures
  - Structured vs unstructured: more efficient search space vs finer parameter control
  - Zero initialization for bias updates vs learned initialization: simplicity vs potential performance gains
- Failure signatures:
  - Poor validation performance despite reasonable parameter budget → likely pruning criterion not capturing true parameter importance
  - High variance across random initializations → initialization sensitivity or optimization instability
  - No improvement over uniform architectures → pruning criterion not providing useful signal or search space too constrained
- First 3 experiments:
  1. Verify baseline: Run BitFit with all bias parameters on GLUE to establish performance floor
  2. Test pruning criterion: Apply criterion to identify "unimportant" parameters, then randomly prune same number and compare performance degradation
  3. Validate middle-layer hypothesis: Manually restrict pruning to early/middle/late layers and measure parameter efficiency tradeoff

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do learned PET architectures compare to hand-designed ones across different types of NLP tasks beyond GLUE, such as generation tasks or tasks with very limited training data?
- Basis in paper: The paper only tests on GLUE tasks and does not explore other domains.
- Why unresolved: The experiments are limited to a single benchmark, leaving generalization to other tasks unknown.
- What evidence would resolve it: Systematic experiments on diverse NLP benchmarks (e.g., SuperGLUE, XTREME, summarization, question generation) comparing learned vs. hand-designed PET architectures.

### Open Question 2
- Question: Does the effectiveness of bias-tuning in middle layers generalize to other pre-trained models like GPT, T5, or multilingual models?
- Basis in paper: The analysis of bias-tuning is based on RoBERTa-Large; the authors do not test other architectures.
- Why unresolved: The paper only examines one model type and scale, so architectural insights may not transfer.
- What evidence would resolve it: Replicating the NAS method on different transformer architectures and analyzing learned architectures for common patterns.

### Open Question 3
- Question: Can iterative pruning improve performance in the very small parameter budget regime (<25k parameters)?
- Basis in paper: The authors suggest iterative pruning might improve results in the 10k parameter regime, where current performance is lower than WARP.
- Why unresolved: The paper only uses one-shot pruning; iterative pruning is mentioned as a future direction but not tested.
- What evidence would resolve it: Experiments comparing one-shot vs. iterative pruning at small parameter budgets and measuring downstream task performance.

## Limitations
- Results primarily demonstrated on GLUE benchmark, limiting generalization to other NLP tasks
- First-order approximation may miss important temporal patterns in parameter importance during training
- Averaging pruning criterion over all SGD steps could smooth out critical temporary importance signals

## Confidence
- Medium-High: The overall effectiveness of the pruning-based NAS approach for PET
- Medium: The specific finding that middle-layer parameters are most parameter-efficient
- Medium: The superiority of unstructured over structured bias-tuning at equivalent parameter budgets

## Next Checks
1. **Ablation on pruning criterion averaging**: Compare architectures learned with full averaging versus shorter time windows to test if temporal patterns in parameter importance are being missed
2. **Cross-task generalization test**: Apply the learned bias-tuning architecture from GLUE to non-GLUE NLP tasks (e.g., SuperGLUE, domain-specific text classification) to validate generalizability
3. **Scaling analysis**: Test whether the middle-layer preference holds for larger models (e.g., 20B+ parameter models) and smaller models (e.g., 100M-1B parameter range)
