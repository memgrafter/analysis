# Parameter-Efficient Fine-Tuning without Introducing New Latency

## Quick Facts
- arXiv ID: 2305.16742
- Source URL: https://arxiv.org/abs/2305.16742

## Executive Summary
This paper introduces two parameter-efficient fine-tuning (PEFT) methods that address key limitations of existing approaches. PaFi provides task-agnostic sparse fine-tuning by selecting parameters based on magnitude information without requiring any training data, while HiWi applies adapters directly to pre-trained parameters instead of hidden representations to eliminate inference latency. Both methods achieve competitive performance on GLUE benchmark tasks while using significantly fewer trainable parameters than full fine-tuning or existing PEFT methods.

## Method Summary
The paper proposes PaFi (Parameter-efficient Fine-tuning) and HiWi (Hidden Weights Infusion) as complementary approaches to parameter-efficient fine-tuning. PaFi uses magnitude-based parameter selection to create task-agnostic sparse masks, identifying the bottom-k parameters with smallest absolute magnitudes as trainable. HiWi applies adapter modules directly to pre-trained parameters rather than hidden representations, computing final parameters before inference to eliminate adapter-related latency. Both methods were evaluated on GLUE benchmark, a newly constructed VariousGLUE benchmark, and machine translation tasks.

## Key Results
- PaFi achieves same GLUE performance as full fine-tuning using only 0.5% of parameters
- HiWi outperforms all baseline methods with just 0.03% of parameters
- HiWi eliminates inference latency by discarding adapter parameters after training
- PaFi excels on middle-resource tasks while HiWi performs better on low-resource tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Task-agnostic mask generation through magnitude-based parameter selection enables sparse fine-tuning without task-specific training.
- Mechanism: PaFi selects bottom-k parameters with smallest absolute magnitudes as trainable, based on hypothesis that important parameters learned more generic representations during pre-training.
- Core assumption: Pre-trained parameters with smallest absolute magnitudes are less important for language representation.
- Evidence anchors:
  - [abstract] "Our approach, which relies solely on the magnitude information of pre-trained parameters, surpasses existing methodologies by a significant margin"
  - [section 3.1] "Another method is magnitude-based. We simply consider the pre-trained parameters with the smallest absolute magnitude as the unimportant ones"
  - [corpus] Weak evidence - corpus neighbors mention Fisher information and sensitivity-aware methods but not magnitude-based selection
- Break condition: If downstream tasks require parameters with small magnitudes for important representations, this method would fail.

### Mechanism 2
- Claim: Adapter applied directly to pre-trained parameters eliminates inference latency while maintaining performance.
- Mechanism: HiWi applies adapters to pre-trained weights/biases instead of hidden representations, allowing adapter parameters to be discarded after training.
- Core assumption: Pre-trained parameters contain sufficient information to guide adapter learning when used as input to adapter layers.
- Evidence anchors:
  - [abstract] "HiWi is an infused fine-tuning method that applies the adapters directly to pre-trained parameters instead of hidden representations"
  - [section 3.2] "Another advantage is: we can replace the weight matrix in Equation 7 with the bias term"
  - [corpus] Weak evidence - corpus neighbors discuss various adapter methods but not parameter-to-parameter adapters
- Break condition: If adapter learning requires hidden representation context rather than parameter values, performance would degrade.

### Mechanism 3
- Claim: Combining parameter magnitude selection with adapter application creates complementary strengths for different resource settings.
- Mechanism: PaFi excels in high-resource tasks with more trainable parameters, while HiWi excels in low-resource settings due to efficient parameter utilization.
- Core assumption: Different PEFT methods have optimal operating regimes based on task resource levels and parameter budgets.
- Evidence anchors:
  - [section 5.4] "For the high-resource task, HiWi performs the worst and is stable with an increasing number of trainable parameters, while PaFi shows a well-behaved pattern"
  - [section 5.4] "For low-resource tasks, HiWi performs the best"
  - [corpus] Weak evidence - corpus neighbors discuss various PEFT methods but not systematic comparison across resource levels
- Break condition: If task complexity doesn't correlate with resource requirements as assumed, method selection would be suboptimal.

## Architecture Onboarding

- Component map:
  Input: Pre-trained transformer weights/biases
  PaFi: Magnitude-based parameter selection + sparse mask generation
  HiWi: Parameter-to-parameter adapter layers + post-training parameter computation
  Output: Fine-tuned model with minimal storage requirements

- Critical path:
  1. Pre-train transformer model
  2. For PaFi: Compute parameter magnitudes → Select bottom-k → Generate mask
  3. For HiWi: Apply adapters to weights/biases → Train → Compute final parameters
  4. Deploy fine-tuned model

- Design tradeoffs:
  - PaFi: Simple but may miss task-specific important parameters
  - HiFi: Requires adapter computation but eliminates inference overhead
  - Storage vs performance: More parameters generally improves performance but increases storage

- Failure signatures:
  - PaFi: Poor performance on tasks requiring specific parameter configurations
  - HiWi: Degradation when hidden representations are more informative than parameter values
  - Both: Catastrophic forgetting if parameter selection is too aggressive

- First 3 experiments:
  1. Implement PaFi on small classification task, compare with BitFit and full fine-tuning
  2. Implement HiWi with weight adapters on translation task, measure inference latency vs LoRA
  3. Test both methods on low-resource tasks to validate resource-specific performance claims

## Limitations
- Claims about task-agnostic parameter selection lack strong theoretical justification
- HiWi's "identical inference speed" claim depends on successful adapter discarding implementation
- Methods primarily validated on English NLU and machine translation tasks

## Confidence
- High confidence: PaFi and HiWi achieve stated parameter efficiency targets on GLUE benchmark
- Medium confidence: Task-agnostic nature of PaFi and inference latency claims for HiWi
- Low confidence: Claims about superiority of magnitude-based selection and general applicability to all task types
