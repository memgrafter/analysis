# A Picture is Worth a Thousand Words: Language Models Plan from Pixels

## Quick Facts
- arXiv ID: 2303.09031
- Source URL: https://arxiv.org/abs/2303.09031
- Reference count: 26
- This paper proposes a simple approach to use language models (LMs) to reason about plan sequences from text instructions and visual observations in embodied visual environments. It shows that LMs can plan accurately even when observations are directly encoded as input prompts for the LM. This approach outperforms prior approaches in experiments on the ALFWorld and VirtualHome benchmarks.

## Executive Summary
This paper introduces Visual Prompt Planning (VP2), a method that enables language models to plan action sequences in embodied environments using raw visual observations. The key innovation is embedding visual observations as soft prompts directly into the language model's input context, allowing joint optimization of both the visual encoder and language model. VP2 achieves state-of-the-art performance on household planning tasks in VizALF and VirtualHome benchmarks, demonstrating that language models can effectively reason about visual information without requiring external text-based intermediaries like captions or affordance functions.

## Method Summary
The method uses a pre-trained CLIP visual encoder to convert raw images into embedding vectors that serve as visual prompts. These prompts are inserted directly into the input context of a fine-tuned GPT2-medium language model alongside text representations of goals and past actions. The model is trained end-to-end to predict the next action, allowing it to learn how to best use visual information for planning. Visual prompts can be learned through fine-tuning the entire model or through prompt tuning, with fine-tuning generally providing better performance.

## Key Results
- VP2 achieves 70.1% success rate on VizALF in-distribution tasks, outperforming baselines
- CLIP visual encoder significantly outperforms ResNet50 on all benchmarks
- Full fine-tuning of the language model provides better performance than prompt tuning alone

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Directly encoding visual observations as soft prompts into the language model enables end-to-end training without requiring external text-based intermediaries like captions or affordance functions.
- Mechanism: Visual observations are passed through a learned observation encoder to produce a sequence of embedding vectors. These embeddings are inserted directly into the language model's input context alongside text tokens representing goals and past actions. The model is trained jointly to predict the next action, allowing the visual encoder and language model to learn to use visual information optimally for planning.
- Core assumption: Visual observations can be encoded into a sequence of embeddings that the language model can process and use for next-action prediction.
- Evidence anchors:
  - [abstract] "In contrast, we show that PLMs can accurately plan even when observations are directly encoded as input prompts for the PLM."
  - [section] "Visual Prompt Planning...we propose the simple approach of embedding visual observations ('visual prompts') and directly inserting them as PLM input embeddings."
  - [corpus] Weak evidence - no direct mention of soft prompt mechanisms, but related work on CLIPCap suggests feasibility of embedding images as prompts.
- Break condition: If the observation encoder fails to produce meaningful embeddings, or if the language model cannot process the visual prompt embeddings in its context, the approach will fail.

### Mechanism 2
- Claim: Using a powerful pre-trained visual encoder like CLIP produces observation features that are more easily interpreted by the language model compared to simpler encoders like ResNet.
- Mechanism: The observation encoder uses a pre-trained CLIP visual encoder as its backbone, followed by a small feed-forward network to map to the language model's embedding dimension. This leverages CLIP's image-text alignment training to produce visual features that are more compatible with the language model's representations.
- Core assumption: Pre-training on image-text alignment tasks produces visual features that are more useful for language-conditioned tasks than generic visual features.
- Evidence anchors:
  - [section] "We also test how using pre-trained visual prompts can affect performance... Replacing the CLIP visual encoder with a Resnet50 significantly degrades the performance."
  - [section] "This suggests that the image-text alignment pre-training of CLIP helps produce observation features that are more easily interpreted by the language model."
  - [corpus] Weak evidence - no direct mention of CLIP vs ResNet comparison, but CLIPCap and related work suggest CLIP features are useful for vision-language tasks.
- Break condition: If the pre-trained visual encoder's features are not aligned with the language model's representations, or if fine-tuning the full model is not possible, performance may degrade.

### Mechanism 3
- Claim: Fine-tuning the full language model (rather than freezing it and only tuning prompts) provides better performance than prompt tuning alone.
- Mechanism: The language model is fine-tuned end-to-end with the visual prompts and task prompt tokens. This allows the model to adapt its internal representations and attention patterns to better use the visual information, rather than just learning to interpret the prompts.
- Core assumption: Fine-tuning the full language model allows it to better integrate visual information into its planning process than prompt tuning alone.
- Evidence anchors:
  - [section] "We found that freezing the language model generally performs worse than fine-tuning it."
  - [section] "The drop in performance can be attributed to the limited influence of prompt tokens alone in controlling the language model's behavior."
  - [corpus] Weak evidence - no direct mention of fine-tuning vs prompt tuning, but related work on prompt tuning suggests it may be less effective than full fine-tuning for complex tasks.
- Break condition: If fine-tuning the full model is not feasible due to computational constraints, or if the model overfits to the training data, performance may suffer.

## Foundational Learning

- Concept: Embodied planning in household environments
  - Why needed here: The method is evaluated on tasks that require an agent to navigate and manipulate objects in simulated household environments based on natural language instructions. Understanding the setup and action space is crucial for implementing and debugging the approach.
  - Quick check question: What are the valid actions and objects in the VizALF and VirtualHome environments, and how are they represented as text?

- Concept: Prompt tuning and prefix tuning for language models
  - Why needed here: The approach builds on prompt tuning, where tunable embeddings are inserted into the language model's input. Understanding how this works and how it differs from fine-tuning is important for implementing the visual prompt mechanism.
  - Quick check question: How do you insert soft prompts into a GPT2 model's input, and how do you optimize them with respect to a target objective?

- Concept: Vision-language pre-training and alignment
  - Why needed here: The approach uses a pre-trained CLIP visual encoder to produce observation features. Understanding how CLIP and similar models are trained, and how they align visual and language representations, is important for debugging and potentially improving the observation encoder.
  - Quick check question: How does CLIP's image-text alignment pre-training work, and what makes its visual features potentially more useful for language-conditioned tasks than generic features?

## Architecture Onboarding

- Component map:
  - Observation encoder: Maps raw visual observations (HWC images) to a sequence of embedding vectors using a pre-trained CLIP encoder and small MLP
  - Language model: GPT2-medium, fine-tuned end-to-end to predict next actions given text goals, past actions, and visual prompts
  - Visual prompts: Soft embeddings learned by the observation encoder, inserted into the language model's input context
  - Task prompts: Additional soft embeddings learned for each task, inserted into the language model's input context
  - Training loop: Jointly optimize observation encoder and language model parameters to minimize next action prediction loss

- Critical path:
  1. Receive visual observation, goal text, and past action sequence
  2. Encode visual observation using observation encoder to produce visual prompts
  3. Construct input context by concatenating goal text, past actions, and visual prompts
  4. Feed context into language model to predict next action distribution
  5. Optimize model parameters using next action prediction loss

- Design tradeoffs:
  - Using CLIP vs ResNet: CLIP produces more aligned features but is larger and may overfit
  - Fine-tuning vs prompt tuning: Fine-tuning allows better integration but is more expensive and may overfit
  - Visual prompt size: Larger prompts can encode more information but increase context length and may hurt performance
  - Auxiliary tasks: May improve grounding but can cause overfitting to in-distribution tasks

- Failure signatures:
  - Poor performance: May indicate issues with observation encoder, language model, or joint optimization
  - Overfitting: May indicate too many parameters, insufficient regularization, or lack of data diversity
  - Slow convergence: May indicate learning rate issues, poor initialization, or insufficient training data

- First 3 experiments:
  1. Implement observation encoder using pre-trained CLIP and small MLP, verify it produces meaningful embeddings for a few sample observations
  2. Implement prompt insertion mechanism, verify visual prompts are properly inserted into GPT2's input context
  3. Implement joint training loop, verify model can learn to predict next actions for a small dataset and that both observation encoder and language model parameters are being updated

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal prompt size for visual observations in the Visual Prompt Planning (VP2) approach?
- Basis in paper: [explicit] The paper tests prompt sizes of 1, 5, 10, and 20, with 10 being the default, but notes that both smaller and larger sizes impact performance differently.
- Why unresolved: The paper only tests a limited range of prompt sizes and does not explore intermediate values or provide a theoretical explanation for the observed performance trends.
- What evidence would resolve it: A more comprehensive study varying prompt sizes within and beyond the tested range, potentially combined with analysis of how different sizes affect the LM's context window and information retention.

### Open Question 2
- Question: How does the choice of visual encoder affect the performance of VP2 in different domains or task complexities?
- Basis in paper: [explicit] The paper compares CLIP visual encoder with ResNet50, showing CLIP performs better, but does not explore other encoders or their performance across different environments.
- Why unresolved: The study is limited to one alternative encoder and two specific environments, leaving open questions about generalizability and the impact of encoder choice on more complex or diverse tasks.
- What evidence would resolve it: Experiments testing multiple visual encoders (e.g., ViT, EfficientNet) across a wider range of environments with varying visual complexity and task requirements.

### Open Question 3
- Question: Can auxiliary tasks improve generalization of VP2 to out-of-distribution (OD) tasks, or do they always lead to overfitting?
- Basis in paper: [explicit] The paper tests auxiliary tasks (inverse dynamics, captions, goal prediction) and finds they improve in-distribution performance but worsen OD performance, suggesting overfitting.
- Why unresolved: The paper does not explore methods to mitigate overfitting from auxiliary tasks or test whether different auxiliary task combinations or training strategies could improve OD generalization.
- What evidence would resolve it: Experiments using techniques like data augmentation, regularization, or curriculum learning to train auxiliary tasks, measuring their impact on both ID and OD performance.

## Limitations

- Evaluation primarily compares against simple baselines without more recent and sophisticated vision-language planning approaches
- Out-of-distribution generalization tests only minor variations of training tasks, not substantially different environments
- The mechanism explanation for why CLIP works better is speculative without deeper analysis

## Confidence

**High confidence** in the core empirical findings:
- VP2 outperforms baseline methods on VizALF and VirtualHome benchmarks
- CLIP features provide better performance than ResNet features
- Full fine-tuning outperforms frozen language model approaches

**Medium confidence** in the broader claims about LM reasoning:
- While results show LMs can use visual information for planning, the extent to which this represents genuine reasoning versus pattern matching is unclear
- The paper's interpretation that LMs "understand" visual information is stronger than the evidence strictly supports

**Low confidence** in claims about mechanism and generalization:
- The explanation for why CLIP works better is speculative
- OD generalization is tested only on minor variations of training tasks
- The limits of this approach for substantially different environments are unknown

## Next Checks

1. **Benchmark expansion**: Replicate the experiments including more recent and sophisticated vision-language planning baselines such as BLIP-2 based approaches, Flamingo-based methods, or specialized visual planning models like VINet to establish clearer relative performance.

2. **Mechanism analysis**: Conduct controlled experiments to isolate what aspects of CLIP features specifically contribute to the performance gain - test whether it's the image-text alignment, the ViT architecture, or other factors by comparing against different visual encoder combinations.

3. **Stress test generalization**: Evaluate the approach on substantially different environments and tasks beyond the minor variations in current OD tests - for example, transfer to entirely different household layouts, object types, or even non-household environments to assess true generalization capability.
