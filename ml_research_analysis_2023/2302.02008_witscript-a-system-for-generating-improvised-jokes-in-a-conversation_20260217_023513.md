# Witscript: A System for Generating Improvised Jokes in a Conversation

## Quick Facts
- arXiv ID: 2302.02008
- Source URL: https://arxiv.org/abs/2302.02008
- Reference count: 11
- Primary result: Generates improvised jokes in conversation with 40% human-verified joke rate

## Executive Summary
This paper presents Witscript, a novel system for generating improvised jokes in conversations. The system uses natural language processing tools to extract keywords from user input, employs wordplay to connect these keywords, and uses a pretrained neural network language model to generate text that links the topic to the punchline. Human evaluators judged Witscript's responses as jokes over 40% of the time, compared to less than 20% for a baseline conversational model. This represents an important step toward giving chatbots a humanlike sense of humor, which can make them seem more likeable. The Witscript system could be integrated into open-domain chatbots to provide an entertaining and social companion for users.

## Method Summary
Witscript generates improvised jokes by first extracting keywords from user input using natural language processing tools. The system then employs wordplay techniques to create potential punchline connections between these keywords. A pretrained neural network language model generates text to bridge the topic and punchline, forming a complete joke response. The system is designed to work within open-domain conversational contexts, producing humor that responds directly to user input rather than relying on pre-written jokes.

## Key Results
- Human evaluators identified Witscript's responses as jokes over 40% of the time
- Baseline conversational model achieved less than 20% joke identification rate
- System successfully generated contextually relevant humor in conversational settings

## Why This Works (Mechanism)
Witscript leverages the linguistic creativity of neural language models combined with structured wordplay techniques. By extracting meaningful keywords and forcing connections through pun-based relationships, the system provides the language model with constrained but creative prompts. This approach harnesses the model's ability to generate fluent text while directing it toward humorous outcomes through the initial keyword linkage and punchline setup.

## Architecture Onboarding

Component map: User Input -> Keyword Extraction -> Wordplay Module -> Language Model -> Joke Output

Critical path: The system processes user input through keyword extraction, applies wordplay to create punchline candidates, then uses the language model to generate the complete joke. Each component must function correctly for successful joke generation.

Design tradeoffs: The system prioritizes contextual relevance over joke quality, accepting that not all generated outputs will be high-quality humor in exchange for ensuring jokes relate to the conversation. This tradeoff increases user engagement but may sacrifice comedic excellence.

Failure signatures: Common failures include nonsensical punchlines, inappropriate humor, or complete non-sequiturs when the language model cannot effectively bridge the topic and punchline. The system may also produce jokes that are technically correct but lack comedic timing or delivery.

## Limitations
- Human evaluation used only 30 test sentences, providing limited statistical power
- Evaluators only indicated whether responses were "jokes" without assessing quality or appropriateness

- System's reliance on wordplay may limit sophistication and variety of generated humor
