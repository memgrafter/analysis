# Membership Inference Attacks against Synthetic Data through Overfitting Detection

## Quick Facts
- arXiv ID: 2302.12580
- Source URL: https://arxiv.org/abs/2302.12580
- Reference count: 36
- Primary result: DOMIAS outperforms previous MIA methods by detecting local overfitting through density ratio comparisons

## Executive Summary
This work introduces DOMIAS, a realistic membership inference attack (MIA) framework against synthetic data that leverages reference datasets to detect local overfitting in generative models. Unlike previous methods that either provide false privacy assurances or require unrealistic access to model parameters, DOMIAS compares density estimates between synthetic and real data distributions. The method achieves superior performance particularly for detecting membership of underrepresented groups in the data, revealing significant privacy vulnerabilities in synthetic data generation.

## Method Summary
DOMIAS performs membership inference by computing the ratio of generator output density to real data density at each test point. The method requires access to a reference dataset from the same distribution as the original training data, which is used to estimate the real data density. Density estimators (such as BNAF) are trained separately on the reference and synthetic datasets, and membership scores are calculated as the density ratio. High scores indicate local overfitting, suggesting the test point was likely in the training set. The approach is invariant to bijective transformations of data representation.

## Key Results
- DOMIAS consistently outperforms baseline MIA methods across multiple datasets
- The method is particularly effective at detecting membership of underrepresented groups
- DOMIAS reveals significant privacy risks that previous methods fail to capture

## Why This Works (Mechanism)

### Mechanism 1
- Claim: DOMIAS detects membership by targeting local overfitting of generative models using density ratios.
- Mechanism: DOMIAS computes a membership score as the ratio of the generator's output density to the real data density at each test point. Overfitted regions have inflated local density in the generator output relative to the real distribution, leading to high scores.
- Core assumption: Access to a reference dataset from the same distribution as the original training data, enabling accurate estimation of the real data density.
- Evidence anchors:
  - [abstract]: "DOMIAS detects local overfitting by comparing density estimates of the generator output and the real distribution."
  - [section 3.2]: "We propose the DOMIAS framework: Detecting Overfitting for Membership Inference Attacks against Synthetic Data... We change Eq. 1 to: ADOMIAS(x*) = f (pG(x*)/pR(x*))"
  - [corpus]: Weak evidence - corpus neighbors discuss MIAs but do not explicitly reference density ratio approaches or overfitting detection.
- Break condition: If the reference dataset is not representative of the training data distribution, or if the density estimators are poorly trained, the density ratio will not accurately reflect overfitting.

### Mechanism 2
- Claim: DOMIAS's density ratio approach is invariant to bijective transformations of the data representation.
- Mechanism: The probability ratio pG(X)/pR(X) remains unchanged under invertible transformations of the data space, ensuring consistent membership scores regardless of representation.
- Core assumption: The transformation between representations is bijective and differentiable almost everywhere.
- Evidence anchors:
  - [section 3.2]: "Theorem 1... the same score is obtained for either data representations."
  - [corpus]: Weak evidence - corpus neighbors discuss MIAs but do not explicitly reference invariance to data transformations.
- Break condition: If the transformation between representations is not bijective or not differentiable, the invariance property breaks down.

### Mechanism 3
- Claim: DOMIAS outperforms previous methods by leveraging reference data and targeting local overfitting directly.
- Mechanism: Previous methods rely on the generator output density alone (Eq. 1), which does not account for the real data distribution and is representation-dependent. DOMIAS corrects this by using the density ratio and reference data.
- Core assumption: Access to a reference dataset enables accurate estimation of the real data density.
- Evidence anchors:
  - [abstract]: "Previous works... either display low performance—giving the false impression that data is highly private—or need to assume access to internal generative model parameters...   - [corpus]: Weak evidence - corpus neighbors discuss MIAs but do not explicitly reference the advantages of using reference data or targeting local overfitting.
- Break condition: If the reference dataset is not available or not representative, or if the density estimators are poorly trained, the performance advantage over previous methods diminishes.

## Architecture Onboarding

- Component map: Reference dataset -> Density estimator (pR) -> Synthetic dataset -> Density estimator (pG) -> Test point -> Density ratio computation -> Membership score

- Critical path:
  1. Obtain reference dataset (Dref) from the same distribution as the training data
  2. Generate synthetic dataset (Dsyn) using the target generative model
  3. Train density estimators on Dref and Dsyn to learn pR(X) and pG(X)
  4. Compute membership scores for test points using the density ratio pG(x)/pR(x)
  5. Apply thresholding to determine membership

- Design tradeoffs:
  - Choice of density estimator: More powerful estimators (e.g., BNAF) can handle higher-dimensional data but may require more training data and computational resources
  - Amount of reference data: More reference data leads to better density estimates but may be harder to obtain in practice
  - Threshold selection: Stricter thresholds reduce false positives but may miss some overfitted samples

- Failure signatures:
  - Poor density estimates leading to uninformative membership scores
  - Overestimation of privacy due to lack of representation invariance in previous methods
  - Vulnerability to shifts between reference and training data distributions

- First 3 experiments:
  1. Evaluate DOMIAS's performance against previous methods on a simple synthetic dataset with known overfitting patterns
  2. Test DOMIAS's invariance to data representation by applying bijective transformations and comparing membership scores
  3. Investigate the impact of reference dataset size on DOMIAS's performance and the accuracy of density estimates

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does DOMIAS perform on very large-scale image datasets (e.g., ImageNet) with complex distributions?
- Basis in paper: [inferred] The paper mentions preliminary results on CelebA, a relatively small image dataset, and discusses the challenge of density estimation in high dimensions. It suggests domain-specific density estimators or lower-dimensional embeddings could be used, but does not evaluate this approach on larger or more complex image datasets.
- Why unresolved: The paper only provides initial results on CelebA and does not explore the performance of DOMIAS on larger, more complex image datasets with higher dimensionality and more intricate distributions. The scalability and effectiveness of DOMIAS on such datasets remain unknown.
- What evidence would resolve it: Experiments applying DOMIAS to large-scale image datasets like ImageNet, using appropriate density estimation methods or embeddings, would provide evidence of its performance and scalability in such settings.

### Open Question 2
- Question: How does the choice of density estimator affect DOMIAS' performance and computational efficiency across different data types and scales?
- Basis in paper: [explicit] The paper discusses using BNAF as the density estimator and compares it to Gaussian KDE, noting that BNAF performs better with more data while KDE is better with less data. However, it does not extensively explore other density estimators or their performance across various data types and scales.
- Why unresolved: While the paper mentions different density estimators and their trade-offs, it does not provide a comprehensive analysis of how various density estimators impact DOMIAS' performance and computational efficiency across different data types (e.g., tabular, image, text) and scales (e.g., small datasets, large datasets).
- What evidence would resolve it: Systematic experiments comparing DOMIAS' performance and computational efficiency using various density estimators (e.g., flow-based models, kernel density estimators, normalizing flows) across different data types and scales would provide insights into the optimal choices for different scenarios.

### Open Question 3
- Question: How can DOMIAS be adapted to handle distributional shifts between the reference dataset and the training data used to generate the synthetic data?
- Basis in paper: [explicit] The paper discusses the scenario where the reference dataset may have a distributional shift compared to the training data. It provides an example with the Heart Failure dataset and varying the proportion of diabetic patients, showing that DOMIAS' performance degrades with increasing shift. However, it does not propose or evaluate methods to adapt DOMIAS for such cases.
- Why unresolved: While the paper acknowledges the issue of distributional shifts and provides an example, it does not explore potential solutions or adaptations to make DOMIAS more robust to such shifts. It remains unclear how DOMIAS can be effectively used when the reference dataset and training data come from different distributions.
- What evidence would resolve it: Research into methods to adapt DOMIAS for handling distributional shifts, such as domain adaptation techniques or robust density estimation methods, followed by experiments evaluating their effectiveness in mitigating the impact of shifts on DOMIAS' performance, would provide evidence of how to address this challenge.

## Limitations

- Dependence on reference dataset quality and representativeness
- Performance constrained by density estimation accuracy, especially in high dimensions
- Practical feasibility of obtaining reference data in real-world scenarios remains uncertain
