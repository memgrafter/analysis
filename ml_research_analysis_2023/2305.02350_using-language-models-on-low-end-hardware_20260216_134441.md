# Using Language Models on Low-end Hardware

## Quick Facts
- arXiv ID: 2305.02350
- Source URL: https://arxiv.org/abs/2305.02350
- Reference count: 38
- One-line primary result: Fixed language models with CNN feature extraction achieve competitive text classification accuracy on low-end hardware, using <1.7 GiB VRAM versus 10.3 GiB for fine-tuning.

## Executive Summary
This paper investigates the viability of using fixed language models for text classification on low-end hardware, focusing on scenarios where fine-tuning is computationally expensive. The authors propose a method combining fixed language models (BERT, RoBERTa, BERT-Tiny) with a CNN feature extraction module. They benchmark this approach on 8 datasets covering single-label and multi-label classification tasks, comparing it to fine-tuning and word embeddings. Key findings include: for single-label classification, feature extraction achieves competitive results (within ~1% of fine-tuning accuracy) while requiring only 1.7 GiB VRAM versus 10.3 GiB for fine-tuning. For multi-label tasks, feature extraction underperforms by ~8% but remains viable under strict memory constraints. Small models like BERT-Tiny are highly efficient, using <1 GiB VRAM and achieving results comparable to word embeddings while reducing per-epoch training time by 95%. Overall, the study demonstrates that fixed language models offer a practical alternative for resource-constrained environments.

## Method Summary
The authors evaluate fixed language models for text classification by freezing pre-trained models and extracting features through a CNN module. They test BERT, RoBERTa, BERT-Tiny, and other variants on 8 English text classification datasets including AG News, 20NEWS, DBpedia, TREC-6, TREC-50, YELP, RCV1-v2, BlurbGenreCollection_EN, and Ohsumed. The CNN feature extractor consists of 4 convolutional layers with kernel sizes 3, 4, 5, and 6, each with 100 filters. Models are trained using Adam optimizer with learning rate 5e-5, with batch size 50 for feature extraction and 40 for fine-tuning. Single-label tasks use categorical cross-entropy with softmax, while multi-label tasks use binary cross-entropy with sigmoid. Results are averaged over 3 runs with standard deviation reported.

## Key Results
- Feature extraction achieves competitive results within ~1% of fine-tuning accuracy for single-label classification
- Multi-label classification underperforms by ~8% but remains viable under strict memory constraints
- BERT-Tiny uses <1 GiB VRAM and achieves results comparable to word embeddings while reducing per-epoch training time by 95%
- Memory usage is 1.7 GiB for feature extraction versus 10.3 GiB for fine-tuning large models

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Fixed (non-fine-tuned) language models retain enough semantic information to support effective text classification when combined with a CNN feature extractor.
- Mechanism: Pre-trained language models already encode rich linguistic features. A CNN can extract discriminative patterns from these embeddings without the need to update the model weights, reducing memory overhead while preserving classification accuracy.
- Core assumption: The general semantic knowledge in pre-trained models transfers sufficiently to downstream tasks without task-specific fine-tuning.
- Evidence anchors:
  - [abstract] "This paper evaluates the viability of using fixed language models for training text classification networks on low-end hardware."
  - [section] "In most cases, the smallest language model, BERT-Tiny, trained with feature extraction is on par with the word embeddings."
  - [corpus] Weak corpus signal: No direct citations supporting this claim; based on experimental results.
- Break condition: Performance drops below a threshold (e.g., >10% below fine-tuning accuracy) or when task-specific nuances are critical.

### Mechanism 2
- Claim: Using a smaller model like BERT-Tiny significantly reduces memory and training time while maintaining competitive performance.
- Mechanism: Smaller models have fewer parameters and require less VRAM for both storing weights and intermediate activations. This makes them feasible on low-end hardware without sacrificing too much accuracy.
- Core assumption: Model size reduction does not drastically degrade feature quality for classification tasks.
- Evidence anchors:
  - [abstract] "Small models like BERT-Tiny are highly efficient, using <1 GiB VRAM and achieving results comparable to word embeddings."
  - [section] "The small memory footprint enables training on older hardware while maintaining a comparable performance."
  - [corpus] No direct corpus support; relies on paper's internal benchmarks.
- Break condition: When task complexity exceeds the representational capacity of the small model.

### Mechanism 3
- Claim: Fixed language models with CNN feature extraction are more memory-efficient than fine-tuning, making them viable for hardware with limited VRAM.
- Mechanism: Fine-tuning requires storing gradients for all parameters, increasing memory usage. Fixed models avoid this overhead, allowing larger batch sizes or training on lower-spec hardware.
- Core assumption: Memory savings from avoiding gradient storage outweigh any potential loss in model adaptability.
- Evidence anchors:
  - [abstract] "requiring only 1.7 GiB VRAM versus 10.3 GiB for fine-tuning."
  - [section] "While the memory usage of GloVe is the same as BERT-base concerning feature extraction, a large reduction is possible with the smallest BERT models."
  - [corpus] Weak signal; inference based on paper's experimental setup.
- Break condition: When memory constraints are relaxed or when fine-tuning becomes feasible.

  - Memory errors during training (indicating batch size or model size too large)
  - Poor accuracy compared to baselines (suggesting insufficient model capacity or inappropriate architecture)

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of fixed language models scale when applied to domain-specific datasets outside of the 8 benchmark datasets used in the study?
- Basis in paper: [inferred] The paper evaluates performance on 8 general datasets but doesn't explore domain-specific applications or how performance might vary across different text domains.
- Why unresolved: The study focuses on general classification tasks but doesn't test whether the findings generalize to specialized domains like medical literature, legal documents, or technical manuals where language patterns differ significantly.
- What evidence would resolve it: Empirical results comparing fixed language models vs fine-tuning across multiple domain-specific datasets would clarify if the observed trade-offs hold or if certain domains benefit more from fine-tuning.

### Open Question 2
- Question: What is the impact of using different CNN architectures (beyond the 4-layer model with fixed kernel sizes) on the performance trade-offs between fixed and fine-tuned language models?
- Basis in paper: [inferred] The paper uses a specific CNN architecture but doesn't explore whether alternative CNN designs might narrow the performance gap between feature extraction and fine-tuning.
- Why unresolved: The study fixes the CNN architecture, so it's unclear whether more sophisticated or deeper CNN designs could compensate for the limitations of feature extraction.
- What evidence would resolve it: Comparative experiments using various CNN architectures (different depths, kernel sizes, attention mechanisms) would reveal if architecture choices can mitigate the performance gap.

### Open Question 3
- Question: How do the memory and time trade-offs change when applying these methods to multilingual text classification tasks?
- Basis in paper: [inferred] The study uses only English datasets, but the authors mention applications in the Global South where multilingual capabilities would be valuable.
- Why unresolved: The paper doesn't test whether the observed efficiency gains of fixed models translate to multilingual settings where language models may need to handle multiple vocabularies and scripts.
- What evidence would resolve it: Experiments comparing fixed vs fine-tuned models on multilingual datasets would show if the memory and time advantages persist across languages.

### Open Question 4
- Question: What are the long-term performance implications of using fixed language models in dynamic environments where data distributions change over time?
- Basis in paper: [explicit] The authors discuss scenarios with "limited access to infrastructure" and "privacy, security, or budget reasons" but don't address how well fixed models adapt to concept drift.
- Why unresolved: The study evaluates static datasets but doesn't investigate whether fixed models can maintain performance as the underlying data distribution evolves.
- What evidence would resolve it: Longitudinal studies tracking model performance on streaming data would reveal if fixed models degrade faster than fine-tuned ones in changing environments.

- **Low**: The assertion that multi-label classification is "viable" despite ~8% performance drop is somewhat subjective and depends on application requirements.
