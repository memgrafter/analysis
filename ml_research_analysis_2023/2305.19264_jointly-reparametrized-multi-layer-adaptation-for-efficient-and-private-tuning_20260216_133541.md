# Jointly Reparametrized Multi-Layer Adaptation for Efficient and Private Tuning

## Quick Facts
- arXiv ID: 2305.19264
- Source URL: https://arxiv.org/abs/2305.19264
- Reference count: 20
- Key outcome: SLaSh achieves GLUE performance within 5% of full fine-tuning using as few as 4,100 parameters per task

## Executive Summary
This paper introduces SLaSh (Shared Layer Shift) and JR-WARP, parameter-efficient tuning methods for large language models. SLaSh uses task-specific parameters derived from a single trainable vector, added as shifts to transformer block output activations. JR-WARP improves prompt tuning by distributing task-specific embeddings across multiple layers. Both methods achieve competitive performance with drastically fewer parameters than full fine-tuning, making them particularly suitable for low-resource and privacy-constrained applications.

## Method Summary
SLaSh introduces task-specific parameters derived from fixed random projections of a single trainable vector, enabling fine-tuning with significantly fewer parameters while maintaining performance. The method trains only a small vector z and classifier head while keeping the pretrained model frozen. JR-WARP extends this concept to prompt tuning by inserting prompts in multiple transformer layers rather than just the input. Both methods are evaluated on GLUE benchmark tasks using RoBERTa and BERT models, demonstrating competitive performance with parameter counts as low as 4,100 per task.

## Key Results
- SLaSh achieves GLUE performance within 5% of full fine-tuning using as few as 4,100 parameters per task
- The method outperforms other parameter-efficient approaches using similar parameter counts
- SLaSh demonstrates competitive utility compared to recent fine-tuning methods under the same privacy constraints
- Training and inference are highly efficient, requiring only the task-specific vector and classifier to be trained

## Why This Works (Mechanism)

### Mechanism 1
- Claim: SLaSh achieves competitive performance with drastically fewer parameters by sharing a single trainable vector across all transformer layers
- Mechanism: A single vector z is projected via fixed random matrices to generate layer-specific shift vectors. These shifts are added to the output activations of each transformer block, effectively tuning only the biases while leveraging parameter sharing
- Core assumption: Task-specific information can be effectively encoded in a low-dimensional shared vector and distributed across layers via random projections
- Evidence anchors: [abstract] "These parameters are derived from fixed random projections of a single trainable vector, enabling finetuning with significantly fewer parameters while maintaining performance"
- Break condition: If the intrinsic dimensionality of the task exceeds what can be captured by the shared vector, or if random projections fail to preserve discriminative information across layers

### Mechanism 2
- Claim: JR-WARP improves prompt tuning by distributing task-specific embeddings across multiple layers instead of just the input
- Mechanism: Task-specific prompts are derived from a single trainable vector and inserted in each transformer block, allowing information to propagate more effectively through deeper layers
- Core assumption: Multilayer prompts improve information flow and reduce the number of trainable parameters compared to single-layer prompt insertion
- Evidence anchors: [abstract] "We make two modifications — a) Insert prompts in different layers, and b) Prompts are derived from a single vector"
- Break condition: If prompt length or dimensionality is insufficient to capture task-specific features, or if layer-wise insertion introduces optimization instability

### Mechanism 3
- Claim: The efficiency gains in training and inference make SLaSh particularly suitable for low-resource and privacy-constrained settings
- Mechanism: Since only a small vector z and classifier parameters are trained, memory usage and computational overhead are minimal. At inference, precomputed shifts can be fused with model biases, eliminating runtime overhead
- Core assumption: Parameter efficiency directly translates to training speed, memory savings, and better differential privacy performance
- Evidence anchors: [abstract] "All these make our method particularly appealing for low-resource applications"
- Break condition: If the reduction in parameters leads to significant underfitting, or if the privacy budget is too tight for the model to learn effectively

## Architecture Onboarding

- Component map: Input text sequence -> Token embeddings -> Transformer blocks (frozen) -> Add shifts from z -> Final representation -> Classifier head -> Prediction
- Critical path: 1) Token embeddings → Transformer blocks 2) In each block: Apply self-attention → Add shift vector (Wl*z) to output activation 3) Final representation → Classifier head → Prediction 4) Loss computed and backpropagated only through z and classifier
- Design tradeoffs: Fewer parameters → faster training, lower memory, better privacy but potential underfitting; Random projections → fixed, no training overhead but may limit representational capacity; Shift location (output activation) → minimal interference with internal representations but may limit depth of influence
- Failure signatures: Training diverges or collapses → likely issues with initialization or gradient clipping; Performance plateaus far below baseline → may need larger z or different shift location; Memory spikes during training → projection matrices not being freed or generated on-the-fly
- First 3 experiments: 1) Implement SLaSh with d=1024 on MNLI using RoBERTa-base, compare to full fine-tuning 2) Vary d across {1024, 5120, 10240} and measure performance vs parameter count 3) Replace output activation shifts with attention activation shifts, measure impact on RTE and CoLA

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of SLaSh and JR-WARP scale with model size (e.g., RoBERTa-large vs. RoBERTa-base vs. larger models)?
- Basis in paper: [explicit] The paper notes that SLaSh and JR-WARP may be more effective for larger models as they are easier to tune with fewer parameters, but does not provide extensive experimental validation across a range of model sizes
- Why unresolved: The paper primarily focuses on RoBERTa-base and RoBERTa-large, leaving the performance on other model sizes unexplored
- What evidence would resolve it: Experiments comparing SLaSh and JR-WARP across a wider range of model sizes (e.g., smaller models, larger models, or different architectures) would provide insight into their scalability

### Open Question 2
- Question: What is the impact of using different initialization strategies (e.g., orthogonal initialization, Xavier initialization) for the random projection matrices Wl on the performance of SLaSh and JR-WARP?
- Basis in paper: [inferred] The paper only explores Gaussian and Uniform initialization for Wl, but does not investigate other initialization strategies that could potentially improve performance
- Why unresolved: The choice of initialization for Wl is a design decision that could influence the learning dynamics and final performance of the models
- What evidence would resolve it: Experiments comparing SLaSh and JR-WARP with different initialization strategies for Wl would reveal the impact of this choice on their performance

### Open Question 3
- Question: How does the performance of SLaSh and JR-WARP compare to other parameter-efficient methods on generative tasks (e.g., text summarization, machine translation)?
- Basis in paper: [explicit] The paper mentions that SLaSh struggles with generative tasks such as text summarization, but does not provide a comprehensive comparison with other parameter-efficient methods on such tasks
- Why unresolved: The paper primarily focuses on classification tasks, leaving the performance on generative tasks unexplored
- What evidence would resolve it: Experiments comparing SLaSh and JR-WARP with other parameter-efficient methods on a variety of generative tasks would provide a more complete picture of their strengths and limitations

## Limitations
- Evaluation focuses primarily on classification tasks with limited analysis of generation or retrieval tasks
- Does not address potential degradation in out-of-distribution performance or robustness to adversarial examples
- Theoretical analysis of why random projections work effectively for task adaptation is limited

## Confidence

- **High confidence** in the parameter efficiency claims and relative performance comparisons on GLUE tasks
- **Medium confidence** in the privacy-utility tradeoff claims, as the differential privacy experiments are promising but use a limited threat model
- **Medium confidence** in the generalizability across tasks, given that most experiments focus on RoBERTa-base and GLUE
