# Query-Efficient Black-Box Red Teaming via Bayesian Optimization

## Quick Facts
- arXiv ID: 2305.17444
- Source URL: https://arxiv.org/abs/2305.17444
- Authors: 
- Reference count: 40
- Key outcome: This work addresses black-box red teaming for large-scale generative models, focusing on discovering diverse failure cases under limited query budgets. The proposed method, Bayesian Red Teaming (BRT), leverages Bayesian optimization to iteratively identify positive test cases leading to model failures by utilizing a pre-defined user input pool and past evaluations. BRT employs Gaussian Process surrogate models to estimate the probability of a user input leading to offensive outputs while maintaining diversity. Experimental results on various user input pools across open-domain dialogue, prompt continuation, and text-to-image generation tasks demonstrate that BRT consistently discovers significantly more diverse positive test cases than baseline methods under limited query budgets. Notably, edit-based BRT achieves over 3x more positive test cases with higher diversity than baselines on the Bloom ZS user input pool against BlenderBot-3B under a 20,000 query limit.

## Executive Summary
This paper proposes Bayesian Red Teaming (BRT), a query-efficient method for black-box red teaming of large-scale generative models. BRT uses Bayesian optimization with Gaussian Process surrogate models to discover diverse positive test cases that lead to model failures, specifically offensive outputs, under limited query budgets. The method iteratively selects user inputs from a pre-defined pool, evaluates them on the victim model, and updates the GP model to estimate the probability of finding offensive outputs while maintaining diversity. Experiments across three tasks (open-domain dialogue, prompt continuation, and text-to-image generation) demonstrate that BRT consistently discovers significantly more diverse positive test cases than baseline methods.

## Method Summary
The Bayesian Red Teaming (BRT) method addresses the challenge of discovering diverse failure cases in black-box generative models under limited query budgets. BRT uses Bayesian optimization with Gaussian Process surrogate models to iteratively select user inputs from a pre-defined pool that are most likely to generate offensive outputs from the victim model. The method employs an expected improvement acquisition function that balances exploration and exploitation, augmented with diversity constraints using Self-BLEU scores. Two variants are proposed: BRT(s) for standard selection and BRT(e) for edit-based selection that extends the search space to the ε-ball of the user input pool through word replacement operations. An adaptive diversity trade-off coefficient λ is used to maintain diversity throughout the search process.

## Key Results
- BRT consistently discovers more diverse positive test cases than baseline methods across three tasks
- Edit-based BRT achieves over 3x more positive test cases with higher diversity than baselines on the Bloom ZS user input pool against BlenderBot-3B under 20,000 queries
- BRT variants maintain higher diversity (lower Self-BLEU scores) while achieving comparable or better red teaming success rates
- Feature augmentation with input offensiveness scores improves correlation with red team scores

### Mechanism 1
- Claim: Bayesian optimization (BO) with Gaussian Process (GP) surrogate models enables efficient discovery of diverse positive test cases under limited query budgets.
- Mechanism: BO iteratively selects inputs to maximize an acquisition function (expected improvement) based on the posterior mean and variance from the GP surrogate model, incorporating both black-box red team scores and white-box diversity constraints.
- Core assumption: The black-box red team score function f(u) can be approximated by a GP surrogate model using continuous features extracted from user inputs.

- Break condition: If the GP surrogate model fails to capture the true structure of f(u), BO will select suboptimal test cases, leading to poor red teaming performance.

- Core assumption: The ϵ-ball Bϵ({u}) contains sufficiently diverse test cases that can lead to offensive outputs when edited from safe user inputs.

## Architecture Onboarding

- Component map:
  - User input pool -> Victim model -> Red team classifier -> Input offensiveness classifier -> GP surrogate models -> Acquisition function -> Determinantal Point Process (DPP) prior -> Evaluation pipeline

- Critical path:
  1. Construct user input pool.
  2. Initialize test case set and evaluation history.
  3. Fit GP surrogate models using Subset of Data (SoD) method.
  4. Compute acquisition function (EI) using GP posterior.
  5. Select batch of test cases using Determinantal Point Process (DPP) prior.
  6. Evaluate selected test cases and update evaluation history.
  7. Adjust diversity trade-off coefficient λ based on current diversity.
  8. Repeat steps 3-7 until query budget is exhausted.

- Design tradeoffs:
  - Exploration vs exploitation: Balancing the need to explore diverse user inputs with the goal of finding high-scoring offensive outputs.
  - Query efficiency vs diversity: Trading off the number of queries needed to discover positive test cases with the diversity of the resulting test set.
  - Model complexity vs interpretability: Using more complex GP surrogate models may improve performance but reduce interpretability.

- Failure signatures:
  - Poor red teaming performance: If the GP surrogate models fail to capture the true structure of the red team score function, leading to suboptimal test case selection.
  - Overfitting to red team classifier: If the discovered test cases overfit the red team classifier, resulting in false positive test cases that are not truly offensive.
  - Insufficient diversity: If the diversity constraint is not properly enforced, leading to a set of positive test cases that are too similar to each other.

- First 3 experiments:
  1. Evaluate the correlation between input offensiveness scores and red team scores on the user input pool to determine if feature augmentation is beneficial.
  2. Compare the performance of BRT (s) and BRT (e) on a small user input pool against a simple victim model to validate the effectiveness of the edit-based approach.
  3. Test the impact of the diversity trade-off coefficient λ on the red teaming performance by varying its value and measuring the resulting RSR and Self-BLEU(k) scores.

## Limitations

- Query Efficiency Trade-offs: The computational cost of fitting Gaussian Process models and computing acquisition functions is not fully quantified, making it unclear how query efficiency translates to actual runtime efficiency.
- Generalizability of Results: The experiments focus on specific combinations of victim models, red team classifiers, and user input pools, so performance may vary significantly with different model architectures or input distributions.
- Dependency on Input Pool Quality: The method's success heavily depends on the quality and diversity of the pre-defined user input pool, which could limit its effectiveness if the initial pool lacks diverse or boundary-case inputs.

## Confidence

- High Confidence: The claim that BRT discovers more diverse positive test cases than baselines under limited query budgets is supported by experimental results across multiple tasks and input pools.
- Medium Confidence: The mechanism by which Bayesian optimization with Gaussian Processes improves red teaming efficiency is theoretically sound but relies on several assumptions about the function space that are not fully validated.
- Low Confidence: The assertion that input offensiveness scores meaningfully improve the GP surrogate model's predictions is based on observed correlations but lacks rigorous ablation studies demonstrating the causal impact of this feature augmentation.
