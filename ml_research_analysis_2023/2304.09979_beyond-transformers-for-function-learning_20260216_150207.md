# Beyond Transformers for Function Learning

## Quick Facts
- arXiv ID: 2304.09979
- Source URL: https://arxiv.org/abs/2304.09979
- Reference count: 2
- Primary result: Two cognitive science-inspired inductive biases (Relational Bottleneck and Adaptive Attention Window) improve transformer performance on function extrapolation tasks

## Executive Summary
This paper introduces two inductive biases from cognitive science models to enhance transformer performance on function extrapolation tasks. The Relational Bottleneck forces models to process similarity patterns rather than raw values, while the Adaptive Attention Window limits attention to nearby points with learnable length scales. These biases were implemented in transformer architectures and tested on linear, sinusoidal, and RBF function extrapolation tasks. The combined approach achieved superior performance compared to standard transformers, with the relational transformer also providing native uncertainty estimates without requiring separate modeling.

## Method Summary
The paper proposes two inductive biases adapted from cognitive science models: the Relational Bottleneck and Adaptive Attention Window. The Relational Bottleneck constructs a similarity matrix from function values and restricts transformer processing to this matrix rather than raw values. The Adaptive Attention Window applies a learnable multiplicative mask to attention weights based on horizontal and vertical distances, allowing the model to discover optimal window lengths for each function type. These biases were implemented in a transformer architecture with 256 embedding dimensions, 8 attention heads, and 12 layers. Models were trained on synthetic functions (linear, sine, RBF) with 320,000 training curves and evaluated on 2,500 test curves.

## Key Results
- Both the Relational Bottleneck and Adaptive Attention Window individually improved transformer performance on function extrapolation
- The greatest performance gains were achieved when combining both biases
- The relational transformer provided uncertainty estimates natively without requiring separate uncertainty modeling
- Performance improvements were consistent across linear, sinusoidal, and RBF function classes

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The Relational Bottleneck improves transformer function extrapolation by forcing the model to process similarity patterns instead of raw values, which aligns with human-like abstract reasoning.
- Mechanism: The model constructs a similarity matrix between function values and restricts the transformer to operate solely on this matrix. This separation between content and relations forces the model to learn and apply relational patterns rather than memorizing specific values.
- Core assumption: Human function learning benefits from abstracting relationships between data points rather than processing raw values directly.
- Evidence anchors: [abstract] "The Relational Bottleneck enforces processing only on similarity patterns rather than raw values"; [section] "the critical inductive bias in the ESBN and CoRelNet architectures is the imposition of an architectural constraint to allow the 'reasoner' in the model to see only similarity scores between pairs of inputs, rather than raw input values"

### Mechanism 2
- Claim: The Adaptive Attention Window improves extrapolation by learning the appropriate length scale for function dependencies, preventing overfitting to local patterns while maintaining computational efficiency.
- Mechanism: The model applies a learnable multiplicative mask to attention weights based on horizontal and vertical distances within the similarity matrix. This allows the model to discover the optimal window length for each function type during training.
- Core assumption: Function values depend primarily on nearby values with a learnable length scale, rather than on all previous values equally.
- Evidence anchors: [abstract] "Adaptive Attention Window limits attention to nearby points with learnable length scale"; [section] "we map the window length L to the transformer implementations simply by masking out any attention weights between observations that are separated by a distance > L on the x-axis"

### Mechanism 3
- Claim: The Relational Transformer provides native uncertainty estimation by treating the output as an ensemble of predictions from similarity profiles, eliminating the need for separate uncertainty modeling.
- Mechanism: Since the model predicts similarity profiles and then converts these to raw values through an invertible transformation, each similarity prediction yields an independent estimate of the target value. The standard deviation across these estimates provides uncertainty.
- Core assumption: The invertible similarity function allows multiple independent predictions to be combined into a coherent uncertainty estimate.
- Evidence anchors: [abstract] "The relational transformer also provided uncertainty estimates natively, unlike standard transformers"; [section] "we can naturally give both a point estimate and an uncertainty estimate for yN+1. We define the point estimate as... The uncertainty estimates are treated similarly, with the uncertainty in the estimate being defined as the sample standard deviation of the ensemble"

  - Why needed here: The paper builds on standard transformer components (self-attention, masking, positional encoding) and modifies them with new inductive biases
  - Quick check question: What properties of transformers (permutation equivariance, masking) are exploited to implement the relational bottleneck and adaptive window?

  - Why needed here: The adaptive window is inspired by linear autoregressive models, and understanding this connection helps explain the inductive bias
  - Quick check question: How does the learned attention window relate to the linear autoregressive assumption that f(i) depends on a small number of preceding values?

## Architecture Onboarding

- Component map: Input -> Similarity matrix construction -> Transformer (with bottlenecks) -> Similarity predictions -> Raw value conversion -> Output
- Critical path: Input → Similarity matrix construction → Transformer (with bottlenecks) → Similarity predictions → Raw value conversion → Output
- Design tradeoffs:
  - Memory vs. accuracy: Using only lower triangular similarity matrix halves memory but requires symmetry exploitation
  - Model complexity vs. interpretability: Learnable window parameters add complexity but enable data-driven discovery of length scales
  - Uncertainty vs. point estimate: Ensemble approach provides uncertainty but may reduce point estimate sharpness
- Failure signatures:
  - High training loss but low validation loss: Overfitting to similarity patterns
  - Uncertainty estimates consistently too high/low: Learnable window parameters not converging properly
  - Performance worse than baseline: Similarity function choice inappropriate for data distribution
- First 3 experiments:
  1. Train relational transformer without learned window on synthetic linear data to verify basic functionality
  2. Add learned window and train on mixed function data to test combined effect
  3. Compare uncertainty estimates against ground truth noise levels on synthetic data

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal similarity function for relational transformers in function learning tasks?
- Basis in paper: [explicit] The paper notes that while they motivated their choice of signed Euclidean distance from mathematical considerations, it's unclear whether this is the best possible choice and suggests exploring whether models could learn appropriate similarity functions directly from data.
- Why unresolved: The paper uses a fixed similarity function based on signed distance without exploring alternatives or learned similarity functions. There's no systematic comparison with other possible similarity measures.
- What evidence would resolve it: Empirical comparison of different similarity functions (cosine similarity, learned similarity functions, other distance metrics) on function learning tasks, showing which yields best extrapolation performance and uncertainty calibration.

### Open Question 2
- Question: How do the learned attention window lengths in transformers compare to the window parameters estimated from human function learning data?
- Basis in paper: [explicit] The paper mentions that in (Segert & Cohen, 2022a), the window length parameter L is treated as a descriptive hyperparameter without principled normative account, and their Learnable Window implementation promotes L to a learnable parameter. They suggest it would be "extremely interesting" to compare the L of learned models with those estimated from human data.
- Why unresolved: The paper implements a learnable attention window but doesn't compare the learned window lengths to psychological estimates of human function learning window parameters.
- What evidence would resolve it: Direct comparison between the learned window length parameters from transformer models and empirically estimated window parameters from human participants performing similar function learning tasks.

### Open Question 3
- Question: Can relational transformers maintain their uncertainty estimation benefits when relaxing the invertibility requirement of the similarity function?
- Basis in paper: [explicit] The paper notes that their current implementation requires an invertible similarity function to read out raw values, and suggests this is why they used signed rather than unsigned distance. They propose this as a limitation and future work direction to "relax this assumption while keeping the same ensembling property."
- Why unresolved: The paper's relational transformer relies on signed distance specifically because it's invertible, but this constraint may limit the generality of the approach to other similarity functions.
- What evidence would resolve it: Successful implementation of relational transformers using non-invertible similarity functions (like unsigned distance or learned similarity functions) that maintain uncertainty estimation capabilities through alternative readout mechanisms.

## Limitations
- Limited empirical validation on synthetic functions with known structure, leaving questions about real-world data performance
- Critical dependency on choice of similarity function, yet only fixed negative Euclidean distance explored
- Adaptive window's learnable parameterization lacks sufficient specification for faithful reproduction
- Uncertainty estimates validated only qualitatively against synthetic noise levels rather than through rigorous probabilistic calibration metrics

## Confidence

- High confidence: The baseline transformer implementation and synthetic data generation procedures appear well-specified and reproducible.
- Medium confidence: The relational transformer's core mechanism (similarity matrix construction and processing) is clearly described, though implementation details like symmetry exploitation could affect results.
- Low confidence: The adaptive attention window's learnable parameterization and the exact combination of both biases in the full model lack sufficient specification for faithful reproduction.

## Next Checks

1. **Sensitivity Analysis on Similarity Functions**: Replace the fixed negative Euclidean distance with learned similarity metrics (cosine similarity, learned kernels) and measure impact on extrapolation performance across all three function classes.

2. **Uncertainty Calibration Testing**: Generate synthetic functions with known noise distributions and evaluate whether the relational transformer's uncertainty estimates properly capture true aleatoric uncertainty through proper scoring rules (CRPS, calibration curves).

3. **Real-World Function Transfer**: Test the best-performing model (relational + learned window) on real-world function extrapolation tasks like time series forecasting or physical system modeling to assess generalization beyond synthetic data.
