# DisasterResponseGPT: Large Language Models for Accelerated Plan of Action Development in Disaster Response Scenarios

## Quick Facts
- arXiv ID: 2306.17271
- Source URL: https://arxiv.org/abs/2306.17271
- Reference count: 40
- Three LLM backends (GPT-3.5, GPT-4, Bard) generated comparable plans of action to human-generated ones for an earthquake-triggered landslide scenario

## Executive Summary
DisasterResponseGPT leverages large language models to accelerate plan-of-action development in disaster response scenarios. The method uses in-context learning with a prompt incorporating FEMA guidelines and scenario details to generate multiple plans of action within seconds. Users can refine outputs through natural language interaction. Three LLM backends (GPT-3.5, GPT-4, Bard) were evaluated on a simulated earthquake-triggered landslide scenario. All models produced comparable plans of action to human-generated ones, with GPT-3.5 closest matching human output. Generated plans included objectives, critical tasks, asset allocation, and end states, but none could automatically produce visual sketches.

## Method Summary
DisasterResponseGPT employs in-context learning with large language models to generate disaster response plans. The system prompt incorporates FEMA disaster response guidelines, planning guidance, and scenario details. Users provide scenario description, main objective, available assets, main problems, and assumptions. The LLM generates three alternative plans following a structured format (objective, critical tasks, operations, end states). Users can refine any plan through natural language interaction with the LLM until satisfied. The method was tested using GPT-3.5, GPT-4, and Bard backends on an earthquake-triggered landslide scenario, comparing generated plans to human-generated ones across feasibility, acceptability, suitability, and distinguishability metrics.

## Key Results
- All three LLM backends (GPT-3.5, GPT-4, Bard) generated plans of action comparable to human-generated plans
- GPT-3.5 produced plans closest to human output format compliance
- Generated plans included all required components: objectives, critical tasks, asset allocation, and end states
- None of the LLMs could generate visual sketches of planned operations

## Foundational Learning

- Concept: In-context learning
  - Why needed here: Enables LLMs to perform task-specific planning without fine-tuning, using only prompt-based conditioning
  - Quick check question: What happens if the prompt contains conflicting instructions or incomplete information?

- Concept: Structured output generation
  - Why needed here: Ensures generated plans follow the required format (objective, critical tasks, operations, end states) for usability
  - Quick check question: How does the model handle missing required fields in the output structure?

- Concept: User feedback integration
  - Why needed here: Allows iterative improvement of plans based on expert judgment and changing conditions
  - Quick check question: What types of user feedback are most effective for plan refinement?

## Architecture Onboarding

- Component map:
  System prompt (FEMA guidelines + output format) -> User input processor (scenario, assets, problems) -> LLM backend (plan generation) -> Refinement interface (natural language feedback) -> Output formatter (structured plan presentation)

- Critical path:
  1. User provides scenario details
  2. System prompt + user input → LLM
  3. LLM generates 3 plans
  4. User selects/refines plan
  5. LLM updates plan based on feedback
  6. Final plan delivered

- Design tradeoffs:
  - Prompt complexity vs. generation speed
  - Number of plans generated vs. cognitive load
  - Model choice (cost, capability, format compliance)
  - Real-time refinement vs. plan stability

- Failure signatures:
  - Missing critical tasks in generated plans
  - Inconsistent asset allocation across operations
  - LLM ignoring user feedback during refinement
  - Output format violations despite prompt constraints

- First 3 experiments:
  1. Test baseline plan generation with simplified scenario
  2. Evaluate refinement accuracy with controlled feedback
  3. Compare plan quality across different LLM backends

## Limitations
- Tested only on a single earthquake-triggered landslide scenario, limiting generalizability to other disaster types
- No quantitative metrics for plan quality assessment beyond structural compliance
- Unable to generate visual sketches or diagrams for operational planning
- Real-time refinement effectiveness not evaluated for convergence or quality improvement

## Confidence
- **High confidence**: LLMs can generate structurally valid plans of action when provided with appropriate prompts and scenario details
- **Medium confidence**: Different LLM backends produce comparable plan quality when given identical inputs
- **Low confidence**: Real-time refinement through natural language interaction consistently improves plan quality across diverse scenarios

## Next Checks
1. **Multi-scenario robustness test**: Evaluate plan generation across 10+ diverse disaster scenarios (floods, hurricanes, industrial accidents) to assess generalizability beyond the single earthquake-triggered landslide case

2. **Quantitative plan quality assessment**: Develop and apply objective metrics for comparing LLM-generated plans against human plans, including task completeness, resource efficiency, and risk mitigation effectiveness

3. **Visual output capability evaluation**: Test whether fine-tuning or specialized prompting techniques enable LLMs to generate basic visual sketches or diagrams alongside textual plan descriptions, measuring the improvement in operational utility
