# RoPAWS: Robust Semi-supervised Representation Learning from Uncurated Data

## Quick Facts
- arXiv ID: 2302.14483
- Source URL: https://arxiv.org/abs/2302.14483
- Reference count: 40
- Key outcome: RoPAWS improves semi-supervised learning under uncurated data by calibrating the prediction of PAWS from a probabilistic view

## Executive Summary
RoPAWS addresses the challenge of semi-supervised learning when unlabeled data contains out-of-class samples (uncurated data). It improves upon PAWS by interpreting it as a generative classifier using kernel density estimation (KDE), then calibrating predictions through Bayes' rule based on densities of both labeled and unlabeled data. The method also controls out-of-class data by modeling an in-domain prior distribution and computing a reweighted loss, making the model robust to uncurated data. Experiments show RoPAWS significantly improves PAWS for uncurated Semi-iNat by +5.3% and curated ImageNet by +0.4%.

## Method Summary
RoPAWS builds on PAWS by adding probabilistic calibration and in-domain prior modeling. It interprets PAWS as performing KDE over representation space to estimate class-conditional densities, then applies Bayes' rule to derive calibrated predictions. An in-domain prior based on maximum similarity to labeled data is used to weight the contribution of unlabeled samples in the posterior prediction. The method also performs label propagation between unlabeled data to reduce confirmation bias. The key innovation is a closed-form solution that combines these elements for robust semi-supervised learning under uncurated data.

## Key Results
- Improves PAWS on uncurated Semi-iNat dataset by +5.3%
- Improves PAWS on curated ImageNet dataset by +0.4%
- Outperforms FixMatch and OpenMatch on uncurated Semi-iNat dataset
- Provides robustness to out-of-class data through in-domain prior modeling

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: RoPAWS improves robustness by calibrating pseudo-labels through probabilistic density modeling.
- **Mechanism**: Interprets PAWS as a generative classifier using kernel density estimation (KDE). Computes densities over representations for both labeled and unlabeled data, then applies Bayes' rule to derive calibrated predictions. This corrects overconfident predictions for out-of-class data by incorporating similarities to both labeled and unlabeled samples.
- **Core assumption**: The representation space learned by PAWS preserves meaningful density structure that can be estimated via KDE, and that similarities in this space correlate with class membership.
- **Evidence anchors**:
  - [abstract]: "RoPAWS improves semi-supervised learning under uncurated data by calibrating the prediction of PAWS from a probabilistic view."
  - [section 3.2]: "We first introduce a new interpretation of PAWS as a generative classifier, modeling densities over representation by kernel density estimation (KDE)."
  - [corpus]: Weak - no direct corpus matches found for KDE-based calibration.
- **Break condition**: If the learned representation does not preserve density structure (e.g., due to severe domain shift), KDE-based calibration would fail.

### Mechanism 2
- **Claim**: RoPAWS controls out-of-class data by modeling an in-domain prior distribution.
- **Mechanism**: Computes an in-domain prior based on maximum similarity to labeled data. Uses this prior to weight the contribution of unlabeled samples in the posterior prediction, effectively down-weighting samples far from the labeled distribution.
- **Core assumption**: Proximity in representation space to labeled data is a reliable indicator of in-domain membership.
- **Evidence anchors**:
  - [abstract]: "RoPAWS also controls out-of-class data by modeling a prior distribution and computing a reweighted loss."
  - [section 3.3]: "Let pin_u ∈ RM×1 be the in-domain prior for each sample. Then, we set the prior belief p(y) of in-class as pin_u/C."
  - [corpus]: Weak - no corpus matches for in-domain prior modeling.
- **Break condition**: If out-of-class data are distributed similarly to in-class data (near-distribution shift), the in-domain prior would not effectively distinguish them.

### Mechanism 3
- **Claim**: Label propagation between unlabeled data improves calibration and reduces confirmation bias.
- **Mechanism**: Uses the calibrated prediction formula to iteratively propagate labels from labeled data to unlabeled data and between unlabeled data themselves. This refines pseudo-labels over iterations, reducing overconfidence in incorrect predictions.
- **Core assumption**: The similarity structure in the representation space allows meaningful label propagation that improves over iterations.
- **Evidence anchors**:
  - [section 3.3]: "This formula can also be interpreted as label propagation (Zhou et al., 2003; Bengio et al., 2006; Iscen et al., 2019) of labels py|x_l and priors py_u of unlabeled data to get the posterior py|x_u."

- **Break condition**: If the similarity graph is poorly connected or contains many incorrect edges, label propagation could amplify errors.

## Architecture Onboarding

- **Component map**: Encoder (fθ) -> Similarity computation -> KDE density estimation -> Bayes' rule calibration -> In-domain prior weighting -> Reweighted loss computation

- **Critical path**:
  1. Compute embeddings for labeled and unlabeled batches
  2. Calculate similarities between unlabeled and labeled/unlabeled embeddings
  3. Apply in-domain prior to unlabeled similarities
  4. Compute calibrated target predictions using closed-form label propagation formula
  5. Compute output predictions using standard PAWS approach
  6. Calculate reweighted cross-entropy loss

- **Design tradeoffs**:
  - Temperature τprior for in-domain prior: Lower values make the model more conservative (less confident in uncertain samples)
  - Ratio r of labeled to unlabeled batch sizes: Higher ratios give more weight to certain labeled data
  - Power k for reweighting: Higher values make the model focus more on confident samples

- **Failure signatures**:
  - Poor performance on curated data: May indicate over-regularization from in-domain prior
  - No improvement over PAWS: Could suggest the representation space doesn't preserve density structure
  - Degraded calibration: Might indicate incorrect temperature settings for prior or reweighting

- **First 3 experiments**:
  1. Run RoPAWS on CIFAR-10 with CIFAR-100 as unlabeled data, comparing with PAWS using 25 labels per class
  2. Vary τprior from 0.1 to 3.0 on Semi-iNat uncurated data to find optimal regularization strength
  3. Test RoPAWS with only in-domain prior (no label propagation) to isolate the contribution of each component

## Limitations
- The KDE-based calibration assumes the learned representation preserves meaningful density structure, which may not hold for severely uncurated data.
- The in-domain prior calculation using max similarity to labeled data is simple but may fail when out-of-class data shares similar features with in-class data.
- The label propagation interpretation lacks empirical validation on its convergence properties and sensitivity to hyperparameters.

## Confidence
- **High Confidence**: The mathematical formulation of KDE-based calibration and in-domain prior reweighting is internally consistent and the closed-form solution is correctly derived.
- **Medium Confidence**: The empirical improvements on curated and uncurated datasets are statistically significant, but the ablation studies could be more comprehensive in isolating mechanism contributions.
- **Low Confidence**: The assumption that representation space learned by PAWS preserves density structure suitable for KDE, and that max similarity to labeled data reliably identifies in-domain samples, lacks rigorous validation.

## Next Checks
