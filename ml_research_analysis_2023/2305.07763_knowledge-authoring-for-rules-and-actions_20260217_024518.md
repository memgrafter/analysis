# Knowledge Authoring for Rules and Actions

## Quick Facts
- arXiv ID: 2305.07763
- Source URL: https://arxiv.org/abs/2305.07763

## Executive Summary
This paper introduces KALM RA, an extension of the KALM FL system that enables authoring of rules and actions through factual English statements. The system supports rule authoring using if-then statements and reasoning with actions using the Simplified Event Calculus. KALM RA demonstrates high accuracy on two benchmarks: 100% on the UTI guidelines for rule authoring and 99.3% on the bAbI Tasks for action reasoning. The system's approach bridges natural language input to logical representations through frame-based parsing and Logical Variable Patterns (LVPs).

## Method Summary
KALM RA extends the KALM FL system to support rule and action authoring through factual English sentences. The system uses frame-based parsing with LVPs to map natural language to logical representations, employing the mStanza parser for syntactic analysis and neuralcoref for coreference resolution. For reasoning, KALM RA uses DLV (a disjunctive version of Datalog) with the Simplified Event Calculus to handle actions and their temporal effects. The system evaluates performance on two benchmarks: the UTI guidelines for rule authoring and the bAbI Tasks for action reasoning.

## Key Results
- 100% accuracy on rule authoring using the UTI guidelines benchmark
- 99.3% accuracy on authoring and reasoning with actions using the bAbI Tasks benchmark
- Demonstrates superiority over ChatGPT in logical reasoning tasks

## Foundational Learning

- Concept: Factual English as a controlled natural language
  - Why needed here: KALM RA's accuracy depends on users writing sentences that can be parsed by the LVP system. Factual English provides clear boundaries for acceptable input.
  - Quick check question: Can you identify which of these sentences would be accepted by KALM RA: "Mary buys a car" vs. "Mary wants to buy a car"?

- Concept: Frame-based knowledge representation
  - Why needed here: Frames capture the semantic structure of sentences (who does what to whom) in a way that maps to logical predicates. This is essential for translating natural language to reasoning.
  - Quick check question: Given the sentence "Daniel administers an antimicrobial therapy for Mary," what frame would KALM RA trigger and what roles would be filled?

- Concept: Answer Set Programming and disjunctive logic
  - Why needed here: KALM RA uses DLV for reasoning, which requires understanding how disjunctive heads and negation work in ASP. This is necessary for interpreting the output of rule reasoning.
  - Quick check question: What's the difference between brave and cautious reasoning modes in DLV?

## Architecture Onboarding

- Component map: User input → mStanza parser → neuralcoref resolver → LVP matching → frame construction → ULR generation → DLV reasoning with SEC axioms
- Critical path: User input → syntactic parsing → LVP matching → role extraction → frame construction → ULR generation → reasoning with DLV. The most critical step is accurate syntactic parsing feeding correct LVPs.
- Design tradeoffs: The system trades expressive power for accuracy by restricting input to factual English and using controlled rule syntax. This avoids the ambiguity of full natural language but requires user training.
- Failure signatures: Low accuracy in parsing suggests mStanza needs retraining on domain-specific text. Incorrect role extraction indicates missing or incorrect LVPs. Reasoning errors may point to missing SEC axioms or DLV model issues.
- First 3 experiments: 1) Parse a simple factual sentence and verify the generated ULR matches expectations. 2) Create a training sentence with a new LVP and test parsing of a similar sentence. 3) Encode a simple SEC axiom and verify reasoning about action effects.

## Limitations

## Confidence

- Medium confidence in the reported accuracy metrics: While the results are impressive, the evaluation methodology lacks detail about test/train splits and potential overfitting.
