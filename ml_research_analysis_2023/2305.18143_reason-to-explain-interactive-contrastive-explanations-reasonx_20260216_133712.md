# Reason to explain: Interactive contrastive explanations (REASONX)

## Quick Facts
- arXiv ID: 2305.18143

## Executive Summary
This paper introduces reasonx, an explanation tool based on Constraint Logic Programming (CLP) that generates interactive contrastive explanations augmented by background knowledge. reasonx provides factual and contrastive decision rules as well as closest contrastive examples for decision trees. It is built on CLP(R) for reasoning over linear constraints, but offers a Python layer for accessibility. The tool is illustrated on a synthetic dataset and a credit application example using the Adult Income dataset. reasonx allows under-specified information, background knowledge in the form of linear constraints, and interactive querying to build personalized explanations.

## Method Summary
REASONX leverages Constraint Logic Programming (CLP) to generate interactive contrastive explanations for decision tree models. The approach translates decision trees into linear constraints expressed as Prolog facts, enabling reasoning under under-specified information and integration of background knowledge. A Python layer interfaces with the CLP(R) core, allowing users to interactively query for factual and contrastive explanations. The system supports optimization to find closest contrastive examples and projection over feature subsets to handle incomplete information.

## Key Results
- reasonx generates factual and contrastive decision rules as well as closest contrastive examples for decision trees
- The tool allows reasoning under under-specified information and integration of background knowledge in the form of linear constraints
- reasonx is demonstrated on a synthetic dataset and a credit application example using the Adult Income dataset

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Constraint Logic Programming (CLP) enables flexible reasoning under under-specified information.
- Mechanism: CLP(R) supports satisfiability checking, projection over feature subsets, and MILP optimization over linear constraints, allowing explanations to be computed even when not all feature values are fixed.
- Core assumption: The decision model can be expressed as linear constraints over features, and the underlying Prolog system correctly implements CLP(R) operations.
- Evidence anchors:
  - [abstract] "reasonx allows to operate under a setting of under-specified information"
  - [section] "projecting over some features w ⊆ x, i.e., computing ∃x\w φ"
  - [corpus] Weak evidence - no direct mention of CLP in neighbors
- Break condition: If the decision tree cannot be translated into linear constraints, or if the Prolog system's CLP(R) implementation has bugs.

### Mechanism 2
- Claim: Background knowledge integration improves explanation quality by constraining admissible contrastive regions.
- Mechanism: Linear constraints representing background knowledge (e.g., immutability of certain features) are added to the Prolog facts representing the decision tree, which restricts the space of valid contrastive examples.
- Core assumption: Background knowledge can be accurately formalized as linear constraints and meaningfully constrains the explanation space.
- Evidence anchors:
  - [abstract] "background knowledge has the potential to significantly improve their quality"
  - [section] "Adding background knowledge to an explanation has the potential to significantly improve its quality"
  - [corpus] No direct mention of background knowledge integration
- Break condition: If background knowledge cannot be accurately formalized, or if the constraints are too restrictive, eliminating all valid explanations.

### Mechanism 3
- Claim: Interactivity allows end-users to build personalized explanations through iterative querying.
- Mechanism: The Python layer translates user queries into Prolog constraints and retrieves results, enabling dynamic addition/removal of constraints and re-computation of explanations based on user feedback.
- Core assumption: Users can formulate meaningful queries in terms of constraints and understand the resulting explanations.
- Evidence anchors:
  - [abstract] "interactivity is a property of an explanation that is important"
  - [section] "Repeated specification of background knowledge and querying are a central part of this dialogue between the end-user and reasonx"
  - [corpus] No direct mention of interactive explanation systems
- Break condition: If the query interface is too complex for users, or if the explanation results are not interpretable by the target audience.

## Architecture Onboarding

- Component map:
  - Python layer: User interface, query translation, result formatting
  - Prolog/CLP(R) core: Constraint reasoning, optimization, satisfiability checking
  - Decision tree translator: Converts tree structure into Prolog facts
  - Background knowledge module: Manages user-provided constraints

- Critical path: User query → Python translation → Prolog constraint solving → Python result formatting → User output

- Design tradeoffs:
  - Expressiveness vs. efficiency: More complex constraints allow richer explanations but increase solving time
  - Generality vs. specificity: Using decision trees as base models limits applicability but simplifies constraint generation
  - Interactivity vs. usability: More query options increase flexibility but may overwhelm users

- Failure signatures:
  - Empty result sets: Constraints may be too restrictive or inconsistent
  - Slow response times: Complex constraint systems may require optimization
  - Uninterpretable results: Translation between Prolog and Python may introduce errors

- First 3 experiments:
  1. Test basic constraint satisfaction with a simple decision tree and known background knowledge
  2. Verify under-specified information handling by providing partial feature values
  3. Validate interactivity by performing a sequence of constraint additions and removals

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can the effectiveness and usefulness of REASONX's explanations be quantitatively evaluated compared to other XAI methods?
- Basis in paper: [explicit] The paper acknowledges that a thorough evaluation of REASONX is currently missing, and that developing suitable evaluation methods is a priority for future work.
- Why unresolved: Existing evaluation methods for XAI may not be suitable for reasonx due to its unique reliance on symbolic reasoning and CLP capabilities.
- What evidence would resolve it: Development and application of novel quantitative evaluation metrics specifically designed for explanation tools utilizing CLP, potentially including user studies and validation on real-world data.

### Open Question 2
- Question: How can REASONX be extended to handle unstructured data types such as text and images?
- Basis in paper: [explicit] The paper mentions that while extending REASONX to multi-class problems is straightforward, extending it to unstructured data needs to be strictly formalized.
- Why unresolved: The current implementation of REASONX is designed for tabular data, and the methods for handling unstructured data may differ significantly.
- What evidence would resolve it: Development and demonstration of REASONX extensions for text and image data, potentially leveraging existing techniques such as concept-based explanations for images.

### Open Question 3
- Question: How can REASONX be improved to account for fairness considerations in its explanations?
- Basis in paper: [explicit] The paper discusses the importance of fairness in explanations and mentions that explanations can be unfair to different subgroups.
- Why unresolved: The current implementation of REASONX does not explicitly address fairness considerations, and incorporating them may require significant modifications.
- What evidence would resolve it: Development and demonstration of REASONX extensions that incorporate fairness metrics and ensure that explanations are fair to all subgroups.

## Limitations
- The scalability of the Prolog-based reasoning system for large decision trees is uncertain
- The practical usability of the interactive interface for non-expert users has not been validated
- The assumption that decision trees can be accurately represented as linear constraints may not hold for complex models

## Confidence
- High confidence in the technical feasibility of the CLP-based approach
- Medium confidence in the practical utility and user experience
- Low confidence in the empirical validation of claimed benefits
