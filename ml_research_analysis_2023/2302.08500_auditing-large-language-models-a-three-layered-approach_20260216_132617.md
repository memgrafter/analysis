# Auditing large language models: a three-layered approach

## Quick Facts
- arXiv ID: 2302.08500
- Source URL: https://arxiv.org/abs/2302.08500
- Reference count: 40
- Primary result: Proposes a three-layered auditing framework for LLMs combining governance, model, and application audits

## Executive Summary
This paper introduces a novel three-layered approach to auditing large language models (LLMs) that addresses the limitations of existing AI auditing procedures. The framework consists of governance audits examining technology providers' practices, model audits assessing LLMs before release, and application audits evaluating downstream uses. The approach aims to ensure LLMs are designed and deployed in ethical, legal, and technically robust ways. While the framework offers a promising structure for comprehensive LLM auditing, the paper acknowledges several implementation challenges and limitations.

## Method Summary
The paper synthesizes existing auditing practices and identifies gaps specific to LLM assessment, proposing a comprehensive framework that addresses multiple levels of the AI development and deployment lifecycle. The approach integrates governance-level oversight with technical model evaluation and practical application assessment, creating a holistic auditing structure. The framework emphasizes the need for systematic evaluation across different stages of LLM development and deployment to capture various risk dimensions.

## Key Results
- Three-layered auditing framework addresses limitations in current AI auditing procedures for LLMs
- Combines governance audits of providers, pre-release model audits, and downstream application audits
- Framework aims to ensure ethical, legal, and technically robust LLM design and deployment

## Why This Works (Mechanism)
The three-layered approach works by creating comprehensive coverage across the LLM lifecycle through parallel but interconnected audit streams. Governance audits establish accountability structures at the organizational level, model audits provide technical assessment of capabilities and risks before deployment, and application audits ensure responsible use in specific contexts. This multi-layered structure captures risks that single-layer approaches might miss, while creating multiple intervention points throughout the development and deployment process.

## Foundational Learning

### Governance Audit Concepts
- **Technology provider accountability frameworks**: Why needed: Establishes organizational responsibility for LLM development; Quick check: Review corporate policies and governance structures

### Model Audit Concepts
- **Pre-release capability assessment methodologies**: Why needed: Identifies potential risks before public deployment; Quick check: Test model behavior across diverse scenarios

### Application Audit Concepts
- **Context-specific risk evaluation**: Why needed: Addresses unique risks in different deployment scenarios; Quick check: Map application use cases to potential harms

## Architecture Onboarding

### Component Map
Governance Audit -> Model Audit -> Application Audit

### Critical Path
1. Governance audit establishes baseline standards and accountability
2. Model audit verifies technical compliance with standards
3. Application audit ensures real-world implementation aligns with standards

### Design Tradeoffs
The framework balances comprehensive coverage against practical implementation complexity, potentially sacrificing speed for thoroughness in audit processes.

### Failure Signatures
- Incomplete risk coverage if any layer is neglected
- Audit fatigue from overlapping requirements
- Difficulty in coordinating between different audit layers

### First 3 Experiments
1. Pilot governance audit on LLM development team documentation
2. Model capability testing using standardized benchmark suite
3. Application scenario analysis for representative use cases

None identified in the provided content.

## Limitations
- Difficulty operationalizing normative concepts into measurable audit criteria
- Absence of established institutional ecosystems for conducting comprehensive audits
- Technology-level focus may inadequately address broader societal risks and systemic impacts

## Confidence

| Layer | Confidence | Rationale |
|-------|------------|-----------|
| Governance Audit | High | Well-established precedents in technology regulation and corporate governance |
| Model Audit | Medium | Rapidly evolving capabilities and lack of standardized testing methodologies |
| Application Audit | Low | Vast diversity of use cases and challenge of anticipating all deployment scenarios |

## Next Checks

1. Implementation trial: Conduct pilot audits using the three-layered framework on existing LLM deployments to assess practical feasibility and identify implementation challenges.

2. Stakeholder feedback: Gather input from diverse stakeholders (developers, users, regulators, ethicists) to evaluate the framework's comprehensiveness and usability in real-world contexts.

3. Risk coverage assessment: Systematically map the framework's coverage against documented LLM incidents and harms to identify potential gaps in risk detection capabilities.
