# Do Models Really Learn to Follow Instructions? An Empirical Study of Instruction Tuning

## Quick Facts
- arXiv ID: 2305.11383
- Source URL: https://arxiv.org/abs/2305.11383
- Reference count: 10
- Models achieve comparable performance using simplified task definitions or misleading examples, suggesting reliance on output format rather than instruction semantics

## Executive Summary
This paper investigates whether instruction-tuned models truly learn to follow instructions or merely exploit superficial patterns. Through controlled experiments comparing models trained with original, simplified (output space only), and empty task definitions or examples, the study reveals that models achieve comparable performance across these variations. A random baseline guessing within the correct output space achieves nearly identical accuracy (40%) to instruction-tuned models (48%), suggesting that much of the perceived improvement comes from learning output formatting rather than instruction understanding. The findings challenge the common assumption that instruction tuning enables genuine instruction following and highlight the need for more robust instruction tuning methods and evaluation frameworks.

## Method Summary
The study employs controlled experiments using the NatInst-V2 dataset with 800+ English tasks and TK-Instruct (770M parameters T5-large-lm-adapt). Researchers create three levels of task definition alterations (Original, Simplified, Empty) and three levels of task example alterations (Original, Delusive, Empty). Models are trained with varying numbers of instances per task (10, 20, 50, 200, 800) and evaluated using exact match for classification and ROUGE-L for generative tasks. The key innovation is comparing performance across these variations and against a random baseline that guesses within the correct output space, revealing whether models learn instruction semantics or merely output formatting patterns.

## Key Results
- Models trained with simplified task definitions (output space only) achieve almost the same results as those trained with original semantic instructions
- Models trained with delusive examples (incorrect input-output mappings) perform comparably to those trained with original examples when training instances are limited
- A random baseline guessing within the correct output space achieves 40% accuracy, nearly matching instruction-tuned models at 48%

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Models learn output formatting and guessing rather than semantic instruction understanding
- Mechanism: During instruction tuning, models exploit the structure of output spaces (label sets) to format responses correctly, achieving high performance without needing to understand task semantics
- Core assumption: The majority of performance gains come from learning superficial patterns (output format and guessing) rather than deeper instruction comprehension
- Evidence anchors:
  - [abstract] "we introduce a random baseline to perform zero-shot classification tasks, and find it achieves similar performance (42.6% exact-match) as IT does (43% exact-match) in low resource setting"
  - [section] "Random baseline that simply guesses within the correct output space. Figure 4 shows the results. First, IT improves format correctness from 0.11% to 91% by training with only one instance per task, and the accuracy improves from 0.08% to 40%. Further providing more training instances per task(> 20) can improve accuracy to 48%. However, while the performance gains seem impressive, the Random baseline can also achieve 40% accuracy."
- Break condition: If models are tested on tasks requiring novel reasoning or understanding beyond output space formatting, the superficial learning mechanism would fail

### Mechanism 2
- Claim: Models rely on output space information rather than task semantics during instruction tuning
- Mechanism: By providing simplified task definitions that only include output labels (removing semantic instructions), models achieve comparable performance to those trained with full semantic instructions
- Core assumption: The semantic content of instructions is not necessary for models to learn task execution during instruction tuning
- Evidence anchors:
  - [abstract] "models trained on simplified task definition or delusive examples can achieve comparable performance to the ones trained on the original instructions and examples"
  - [section] "models trained with Simplified instructions achieve almost the same results as models trained with Original definitions both on Classification and Generative tasks"
- Break condition: If tasks require understanding complex semantic relationships that cannot be captured by output space alone, simplified definitions would fail

### Mechanism 3
- Claim: Input-output mapping from examples is not crucial during instruction tuning but is important during inference (in-context learning)
- Mechanism: Models can learn task patterns from examples without understanding the specific input-output mappings, but during inference, they rely on correct mappings for accurate predictions
- Core assumption: The relationship between inputs and outputs in examples is less important than the format and output space during training, but becomes critical during inference
- Evidence anchors:
  - [abstract] "models trained with delusive examples can achieve comparable performance to the ones trained on the original instructions and examples"
  - [section] "models trained with Delusive task examples can achieve almost the same performance as Original task examples when the number of training instances per task is small (≤ 50)"
- Break condition: If models are required to generalize to tasks where input-output relationships are fundamentally different from training examples, incorrect mappings would lead to failure

## Architecture Onboarding

- Component map: Pre-trained T5 model -> Instruction tuning pipeline -> Evaluation framework -> Random baseline generator
- Critical path:
  1. Load pre-trained T5 model
  2. Prepare instruction tuning dataset with original, simplified, and empty task definitions/examples
  3. Train model with instruction tuning using various training instance counts
  4. Evaluate on zero-shot tasks using exact-match and ROUGE-L metrics
  5. Compare with random baseline performance
- Design tradeoffs:
  - Simplified task definitions vs. original semantic instructions: simplified versions reduce training complexity but may limit performance on semantically complex tasks
  - Number of training instances per task: more instances improve performance but increase computational cost
  - Use of delusive examples: allows testing model's reliance on input-output mappings but may introduce noise
- Failure signatures:
  - High format correctness but low exact-match accuracy indicates superficial learning
  - Performance drop when using delusive examples during inference indicates reliance on input-output mappings
  - Minimal difference between original and simplified instruction performance suggests lack of semantic understanding
- First 3 experiments:
  1. Train model with simplified task definitions and evaluate zero-shot performance vs original definitions
  2. Train model with delusive examples and compare performance with original examples during both training and inference
  3. Implement random baseline that guesses within output space and compare performance with instruction-tuned models

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Do instruction-tuned models truly understand task semantics beyond learning output format and format correctness?
- Basis in paper: [explicit] The paper's experiments show models trained with simplified task definitions (removing semantic components) and delusive examples (incorrect input-output mappings) achieve comparable performance to those trained with original instructions, suggesting reliance on superficial patterns rather than instruction understanding
- Why unresolved: The study focused on controlled experiments with specific manipulations (simplified definitions and delusive examples) but did not explore whether models possess any deeper semantic understanding that emerges with larger model sizes, different architectures, or alternative instruction tuning methods
- What evidence would resolve it: Systematic testing with progressively more complex semantic manipulations (e.g., paraphrases, semantically equivalent but syntactically different instructions) across various model scales and architectures, combined with interpretability analyses of model attention and internal representations

### Open Question 2
- Question: How do different instruction tuning methods (e.g., RLHF, prompt-based tuning) compare in their ability to learn genuine instruction following versus superficial pattern matching?
- Basis in paper: [explicit] The paper's limitations section notes they only analyzed one SOTA IT method (TK-Instruct) and did not explore other methods like RLHF used in InstructGPT, suggesting potential differences in how these approaches utilize instructions
- Why unresolved: The analysis was limited to a single instruction tuning approach on one dataset, leaving open the possibility that alternative methods might better capture instruction semantics rather than superficial patterns
- What evidence would resolve it: Direct comparative studies of multiple instruction tuning methods (RLHF, prompt-based tuning, supervised fine-tuning with instructions) on the same benchmark tasks, measuring both performance and the degree of instruction utilization through similar ablation studies

### Open Question 3
- Question: At what scale or with what architectural modifications do instruction-tuned models begin to genuinely follow instructions rather than relying on output format and guessing?
- Basis in paper: [inferred] The limitations section mentions potential emergent abilities of larger language models and the possibility that some instruction understanding may exist in pre-trained LLMs, suggesting that current findings might not generalize to larger scales or different architectures
- Why unresolved: The experiments were conducted on T5-large models (770M parameters), and the paper acknowledges that emergent abilities might appear in larger models, but did not test this hypothesis
- What evidence would resolve it: Scaling experiments with increasingly larger models (from 1B to 100B+ parameters) and architectural variations (transformers with different attention mechanisms, retrieval-augmented models) tested with the same instruction manipulation techniques to identify thresholds where genuine instruction following emerges

## Limitations

- Model architecture dependency: The study relies on T5-large-lm-adapt (770M parameters), which may not generalize to larger or different model architectures
- Dataset composition and representation: The NatInst-V2 dataset may contain implicit patterns or biases that facilitate the superficial learning mechanisms observed
- Evaluation metric limitations: Exact-match accuracy and ROUGE-L metrics may not capture nuanced aspects of instruction following, as evidenced by the random baseline achieving 40% accuracy

## Confidence

**High Confidence**: The experimental methodology and controlled comparison between original, simplified, and empty task definitions/examples is robust and well-documented. The finding that models achieve similar performance with simplified definitions strongly supports the conclusion about superficial learning patterns.

**Medium Confidence**: The claim that much of instruction tuning's perceived improvement comes from output formatting rather than semantic understanding is supported by evidence but requires further validation across different model architectures and datasets to generalize.

**Low Confidence**: The assertion that random guessing within the correct output space achieves nearly identical accuracy (40% vs 48%) to instruction-tuned models needs more rigorous statistical validation and should be tested across different task distributions to rule out dataset-specific artifacts.

## Next Checks

1. **Architecture Generalization Test**: Replicate the core experiments using different model architectures (e.g., GPT-3, BERT, or larger T5 variants) to determine if the superficial learning patterns are architecture-dependent or universal across language models

2. **Dataset Robustness Analysis**: Conduct ablation studies on the NatInst-V2 dataset to identify specific task characteristics that enable superficial learning, including analysis of task complexity, semantic richness, and output space diversity

3. **Alternative Evaluation Framework**: Develop and implement evaluation metrics that can better distinguish between format-based guessing and genuine semantic understanding, such as probing tasks that require novel reasoning or cross-task transfer that cannot be solved through output space formatting alone
