# A Memory Efficient Deep Reinforcement Learning Approach For Snake Game Autonomous Agents

## Quick Facts
- arXiv ID: 2301.11977
- Source URL: https://arxiv.org/abs/2301.11977
- Reference count: 22
- This paper proposes a memory-efficient DRL approach for autonomous agents playing the Snake game, achieving similar performance to traditional methods with 96% less memory usage.

## Executive Summary
This paper addresses the high memory and computational requirements of traditional deep reinforcement learning (DRL) methods by proposing a memory-efficient approach for autonomous Snake game agents. The authors implement image preprocessing (RGB to grayscale to binary) and optimize the experience replay buffer size to drastically reduce memory usage while maintaining competitive performance. Their modified DQN agent achieves an average score of 9.53 with a best score of 20, comparable to traditional DRL methods but with significantly reduced resource requirements.

## Method Summary
The authors propose a memory-efficient DRL approach for the Snake game that includes three key optimizations: image preprocessing (converting 252×252 RGB images to 84×84 binary images), reducing the experience replay buffer from 1,000,000 to 50,000 entries, and using a lightweight CNN architecture with fewer layers and parameters. The agent is trained using a modified DQN algorithm with epsilon-greedy exploration, Adam optimizer (learning rate 0.0025), and target network synchronization every 10,000 steps. The approach achieves similar performance to traditional DRL methods while enabling deployment on resource-constrained devices.

## Key Results
- Average score of 9.53 and best score of 20 achieved by proposed method
- Memory usage reduced by 96% through RGB to binary image conversion
- Experience replay buffer size reduced from 1,000,000 to 50,000 (99.4% memory savings)
- Performance comparable to traditional DRL methods despite significant memory reduction

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Image preprocessing reduces memory usage without hurting performance.
- Mechanism: Converting RGB to grayscale (1/3 memory) and then to binary (1/8 memory) preserves game-state information while drastically cutting memory footprint.
- Core assumption: The Snake game's visual state can be represented in binary grayscale without losing critical spatial or object information.
- Evidence anchors:
  - [abstract] "We convert RGB images to grayscale and then binary, reducing memory usage by 96% compared to RGB."
  - [section] "We convert the RGB array into grayscale because it would not affect the performance [18] and it saves three times of memory."
  - [corpus] No corpus papers directly discuss this preprocessing; assumption based on cited literature [18].
- Break condition: If binary conversion removes essential visual cues (e.g., snake vs. apple distinction), agent performance degrades.

### Mechanism 2
- Claim: Smaller replay buffer improves training efficiency and reduces memory usage.
- Mechanism: Reducing replay buffer from 1,000,000 to 50,000 entries saves ~99.4% memory while retaining sufficient diversity for stable Q-learning updates.
- Core assumption: Recent experiences are more relevant for learning than older ones, and FIFO buffer order preserves critical training dynamics.
- Evidence anchors:
  - [abstract] "The experience replay buffer size is reduced from 1,000,000 to 50,000, saving 99.4% memory."
  - [section] "We use a replay buffer of size 50,000, requiring less memory (only 5%) than [6], [8], [17]."
  - [corpus] No direct corpus evidence for 50k size; assumption based on internal experiments.
- Break condition: If buffer is too small, agent may overfit to recent experiences and fail to generalize.

### Mechanism 3
- Claim: Lightweight CNN with fewer layers maintains competitive performance.
- Mechanism: Reduced convolutional layers and parameters lower computational load while still extracting essential spatial features from preprocessed images.
- Core assumption: Snake game state space is simple enough that a shallow CNN can capture all necessary features for decision making.
- Evidence anchors:
  - [abstract] "The lightweight CNN architecture uses fewer layers and parameters."
  - [section] "We have designed a lightweight Convolutional Neural Network (CNN) with a variant of the Q-network that efficiently takes preprocessed image data as input and uses less memory."
  - [corpus] No corpus papers explicitly validate this design; assumption based on internal ablation studies.
- Break condition: If CNN depth is too shallow, agent fails to learn complex spatial patterns.

## Architecture Onboarding

- Component map:
  - Image preprocessor (RGB→grayscale→binary, resize to 84×84) -> Lightweight CNN (3 conv layers + pooling + 2 FC layers) -> Online DQN (weights updated every step) -> Target DQN (weights synced every 10,000 steps) -> Experience replay buffer (FIFO, capacity 50,000) -> Game environment (pygame Snake, 12×12 grid)

- Critical path:
  1. Preprocess screen image
  2. Feed into CNN to get Q-values
  3. Select action (epsilon-greedy)
  4. Execute action, observe reward/state
  5. Store transition in replay buffer
  6. Sample mini-batch, compute loss
  7. Backpropagate and update online DQN
  8. Periodically sync target DQN

- Design tradeoffs:
  - Memory vs. performance: Smaller buffer saves memory but may reduce sample diversity.
  - Preprocessing depth vs. information loss: Binary conversion saves memory but may obscure object boundaries.
  - CNN depth vs. computational cost: Shallower network trains faster but may miss complex patterns.

- Failure signatures:
  - Agent gets stuck in loops → replay buffer too small or CNN too shallow
  - Sudden performance drops → buffer overflow or preprocessing error
  - Slow convergence → learning rate too low or target network sync frequency off

- First 3 experiments:
  1. Validate preprocessing pipeline: Ensure binary conversion preserves snake and apple locations.
  2. Benchmark memory usage: Measure actual memory consumption with 50k buffer vs. baseline.
  3. Ablation on CNN depth: Test performance with 2 vs. 3 conv layers to confirm minimal viable architecture.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of the proposed memory-efficient DRL approach compare to state-of-the-art methods on more complex games or real-world tasks?
- Basis in paper: [explicit] The authors state that their method can achieve similar performance as other DRL methods on the Snake game, but do not test on more complex environments.
- Why unresolved: The paper only evaluates the approach on a simple game, so its generalization to more complex tasks is unknown.
- What evidence would resolve it: Testing the approach on a variety of more complex games and real-world tasks, and comparing the results to state-of-the-art methods.

### Open Question 2
- Question: What is the optimal size for the experience replay buffer in DRL algorithms, and how does it vary with different tasks and network architectures?
- Basis in paper: [explicit] The authors note that the favorable size for the replay buffer remains unknown, and they use a size of 50,000 which is smaller than typical sizes used in other works.
- Why unresolved: While the authors show that a smaller buffer can work well for their specific task, the optimal size likely depends on the specific task and network architecture.
- What evidence would resolve it: Systematic experiments varying the replay buffer size on a range of tasks and network architectures to determine the optimal size in each case.

### Open Question 3
- Question: How does the proposed image preprocessing method affect the performance and training stability of DRL algorithms on different types of visual inputs?
- Basis in paper: [explicit] The authors propose a method of converting RGB images to grayscale and then binary to reduce memory usage, and show it works well for the Snake game.
- Why unresolved: The effectiveness of this preprocessing method may depend on the type of visual input and the specific DRL algorithm used.
- What evidence would resolve it: Experiments applying the preprocessing method to different types of visual inputs (e.g. different games, real-world images) and DRL algorithms, and analyzing the impact on performance and training stability.

## Limitations
- Binary image conversion may lose critical visual distinctions between game objects
- 50,000 replay buffer size significantly reduced from standard 1,000,000 without comprehensive justification
- Performance comparison appears cherry-picked with unusually low baseline DQN score (0.26)
- No systematic architectural ablation to verify minimal CNN depth is sufficient

## Confidence
- **High confidence**: Memory reduction claims (96% from RGB→binary, 99.4% from buffer reduction) are well-quantified and directly measurable.
- **Medium confidence**: Performance claims relative to baseline DQN, given the unusual baseline performance (0.26 average score).
- **Low confidence**: Claims about minimal CNN architecture being sufficient, as no systematic architectural ablation or complexity analysis is provided.

## Next Checks

3. **Architecture ablation study**: Test performance with varying CNN depths (2, 3, 4 conv layers) and widths to establish minimal sufficient architecture and quantify performance degradation from compression.
