# RaViTT: Random Vision Transformer Tokens

## Quick Facts
- arXiv ID: 2306.10959
- Source URL: https://arxiv.org/abs/2306.10959
- Reference count: 27
- Primary result: RaViTT improves ViT accuracy by 1.23%–4.32% across four datasets, even with fewer tokens and lower GFLOPs.

## Executive Summary
RaViTT introduces a random patch sampling strategy for Vision Transformers that replaces regular grid patch extraction with randomly sampled overlapping patches. This approach expands the input space, centers relevant features within patches, and can reduce computational load while improving accuracy. Evaluated on ImageNet-1k, CIFAR-100, G. CANCER, and DeFungi, RaViTT outperforms baseline ViT and state-of-the-art augmentation techniques, especially on datasets with limited annotations.

## Method Summary
RaViTT randomly selects a subset of patches from an image, allowing for overlapping patches and breaking the regular grid pattern used in standard ViTs. This increases the diversity of input patterns and can improve feature extraction. The method can be used with any ViT backbone and is compatible with standard positional encodings. RaViTT was tested with different sampling ratios (r ∈ {0.5, 1, 2, 3, 4}), showing accuracy gains even with fewer tokens, thus reducing computational cost.

## Key Results
- RaViTT increases baseline ViT accuracy across all four datasets tested.
- Outperforms SOTA augmentation (e.g., RandAugment) on 3 out of 4 datasets by 1.23%–4.32%.
- Achieves accuracy improvements with fewer tokens, reducing GFLOPs for a given accuracy.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Random sampling expands the input space by allowing overlapping patches that can center relevant features within individual tokens.
- Mechanism: By selecting patches from random positions instead of a regular grid, RaViTT increases the diversity of patch locations fed into the transformer. Overlapping patches ensure that features of interest are not constrained to fixed grid boundaries, which can lead to better feature extraction.
- Core assumption: The transformer's self-attention mechanism can effectively integrate information from overlapping and randomly positioned patches.
- Evidence anchors:
  - [abstract] "By randomly sampling patches, it is possible to replicate and to center relevant features or phenomena within individual patches. Additionally, this approach can expand the space of possible inputs for the linear projection model..."
  - [section] "The core idea behind RaViTT is to randomly select r · L patches of (P, P) pixels from the input image x, allowing overlapping among patches to occur."
- Break condition: If the transformer's self-attention cannot reconcile the spatial relationships of randomly sampled patches, performance may degrade.

### Mechanism 2
- Claim: Random sampling improves robustness to dataset size and class imbalance by increasing effective training sample diversity.
- Mechanism: Randomized patch sampling creates a wider variety of input patterns, effectively augmenting the dataset without needing explicit data augmentation transforms. This is especially beneficial for small or imbalanced datasets.
- Core assumption: Increased input pattern diversity improves model generalization, particularly when training data is limited.
- Evidence anchors:
  - [abstract] "This approach could be especially beneficial for datasets with limited training samples or objects at the patch level."
  - [section] "RaViTT improves upon the baseline ViT-S/16 method. In the datasets with larger image sizes... this improvement is greater than the baseline ViT trained with SOTA data augmentation methods."
- Break condition: If the random sampling introduces too much noise or irrelevant context, it may hinder rather than help model convergence.

### Mechanism 3
- Claim: RaViTT allows for accuracy gains with fewer tokens, reducing computational load.
- Mechanism: By carefully choosing r < 1, RaViTT can sample fewer patches than the baseline ViT while still improving accuracy. This reduces the sequence length L and thus the computational cost (GFLOPs).
- Core assumption: A smaller, strategically sampled set of patches can capture sufficient discriminative information for classification.
- Evidence anchors:
  - [abstract] "Interestingly, RaViTT accuracy improvements can be achieved even with fewer tokens, thus reducing the computational load of any ViT model for a given accuracy value."
  - [section] "RaViTT was tested with values of r ∈ {0.5, 1, 2, 3, 4}... Results reveal that RaViTT with r = 1, corresponding to the same number of tokens as the baseline ViT-S/16, achieves slightly higher efficiency in all datasets. Also, r = 0.5 yields the highest efficiency in all datasets..."
- Break condition: If r is reduced too much, important spatial information may be lost, causing accuracy to drop.

## Architecture Onboarding

- Component map:
  - Input image -> Random patch sampler (RaViTT) -> Patch embeddings -> Positional encodings (2D sin/cos) -> Transformer encoder -> Classification head (GAP + linear)
- Critical path:
  1. Random patch selection (coordinate generation and sampling)
  2. Patch embedding projection (linear/conv layer)
  3. 2D positional encoding per patch
  4. Transformer forward pass
- Design tradeoffs:
  - More overlapping patches (higher r) -> higher accuracy but more GFLOPs
  - Fewer patches (lower r) -> reduced compute but risk of underfitting
  - Mode A (random train/test) vs Mode B (random train, regular test) affects evaluation consistency
- Failure signatures:
  - Accuracy plateaus or drops when r is too low
  - Training instability if random patches are too small or too large
  - Overfitting if positional encodings are not adapted to random patch layout
- First 3 experiments:
  1. Run baseline ViT with r=1 (same number of tokens) and compare accuracy/GFLOPs.
  2. Try r=0.5 to verify computational savings and accuracy retention.
  3. Test Mode B (random train, regular test) to see if inference performance differs from Mode A.

## Limitations
- Limited dataset diversity and generalization: Only four datasets tested, no systematic evaluation on extremely small datasets or fine-grained domains.
- Lack of ablation on positional encoding sensitivity: No investigation into how choice of positional encoding affects performance with random patches.
- Mode B evaluation not fully validated: No thorough comparison between Mode A and Mode B across datasets and r values.

## Confidence
- High confidence: RaViTT with r=1 consistently improves accuracy over baseline ViT-S/16 across all four datasets.
- Medium confidence: RaViTT achieves higher accuracy than SOTA augmentation on 3 out of 4 datasets.
- Low confidence: RaViTT is especially beneficial for datasets with limited training samples or class imbalance.
