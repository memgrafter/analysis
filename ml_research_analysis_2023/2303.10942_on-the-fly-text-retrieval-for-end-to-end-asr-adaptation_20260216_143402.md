# On-the-fly Text Retrieval for End-to-End ASR Adaptation

## Quick Facts
- arXiv ID: 2303.10942
- Source URL: https://arxiv.org/abs/2303.10942
- Reference count: 0
- Primary result: Retrieval-based adaptation reduces RNN-T WER by up to 9% relative on QA datasets, with further 13% gains when combined with shallow fusion.

## Executive Summary
This paper introduces a retrieval-based approach to improve RNN-T speech recognition by dynamically fetching context-relevant text continuations from an external datastore. Unlike traditional language model fusion, this method adapts recognition without retraining and shows notable gains for rare entities. Experiments on QA datasets demonstrate significant WER reductions and robust performance even with millions of irrelevant tokens in the datastore.

## Method Summary
The approach augments RNN-T with a retrieval module that queries an external datastore for context-relevant text continuations during inference. The retrieved text is then used to guide the decoder, allowing adaptation to new domains or rare entities without model retraining. This retrieval step is integrated directly into the ASR pipeline, enabling real-time adaptation as new context becomes available.

## Key Results
- Retrieval-based adaptation reduces WER by up to 9% relative on QA datasets, especially for named entities.
- Combining retrieval with shallow fusion yields an additional 13% WER improvement.
- Performance remains stable even when the datastore contains millions of unrelated tokens, suggesting scalability.

## Why This Works (Mechanism)
The retrieval module dynamically injects relevant context into the RNN-T decoder, effectively biasing recognition toward domain-specific or rare terms that the base model might miss. By avoiding full model retraining, the system adapts quickly to changing vocabularies or domains. The integration with shallow fusion further refines predictions, allowing complementary strengths of retrieval and traditional language modeling to combine.

## Architecture Onboarding
- **Component Map:** ASR Input -> RNN-T Encoder -> Retriever (queries datastore) -> RNN-T Decoder (with retrieved context) -> Output
- **Critical Path:** Audio input flows through RNN-T encoder, retriever module fetches relevant context, decoder uses both encoder output and retrieved text to produce final transcript.
- **Design Tradeoffs:** Retrieval adds latency but avoids costly retraining; trade-off between datastore size (coverage vs. noise) and inference speed.
- **Failure Signatures:** Retrieval noise can mislead decoder; irrelevant context may degrade performance; latency spikes if retrieval is slow.

## Limitations
- Results are based on a limited set of clean QA datasets, so generalization to noisy, conversational speech is uncertain.
- Claims about robustness to irrelevant tokens lack ablation studies to isolate the effect of datastore noise.
- No empirical testing on rapidly changing domains like live news or technical support.
- Latency and computational overhead are not discussed, leaving deployment readiness unclear.

## Confidence
- General WER reduction and named-entity gains: **Medium**
- Robustness to irrelevant datastore entries: **Low**
- Practical scalability and deployment readiness: **Low**

3. Benchmark end-to-end latency and memory usage in a real-time ASR pipeline to evaluate deployment feasibility.
