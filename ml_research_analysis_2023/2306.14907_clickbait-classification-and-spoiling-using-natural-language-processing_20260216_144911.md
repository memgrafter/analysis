# Clickbait Classification and Spoiling Using Natural Language Processing

## Quick Facts
- arXiv ID: 2306.14907
- Source URL: https://arxiv.org/abs/2306.14907
- Reference count: 11
- Primary result: Classification accuracy of 0.7884/0.799 vs baseline 0.7157; spoiler generation BLEU-4 of 0.13 vs baseline 0.688

## Executive Summary
This work addresses clickbait spoiling by classifying clickbait titles into three types (phrase, passage, multi) and generating spoiler text. The authors develop two binary BERT classifiers that outperform the baseline dataset authors' models. For spoiler generation, they use one-shot prompting with GPT-3, though this approach underperforms the baseline due to evaluation metric mismatch. The classification approach handles class imbalance through a two-stage process, while the generation approach struggles with BLEU-4 evaluation that penalizes generative variation.

## Method Summary
The authors tackle clickbait spoiling through two parallel pipelines. For classification, they use two binary deBERTa classifiers: the first distinguishes multi-spoiler from other types, and the second separates phrase from passage spoilers. This two-stage approach handles the imbalanced dataset better than multi-class classification. For spoiler generation, they employ GPT-3 with one-shot prompting using different templates for each clickbait type. The system is trained on the SemEval Clickbait dataset (4000 entries) with hyperparameter optimization using WandB. The classification models achieve 0.7884 and 0.799 balanced accuracy, while the GPT-3 approach achieves 0.13 BLEU-4 compared to the baseline of 0.688.

## Key Results
- Classification models achieve 0.7884 and 0.799 balanced accuracy, outperforming baseline of 0.7157
- GPT-3 spoiler generation achieves 0.13 BLEU-4, significantly underperforming baseline of 0.688
- Two-stage binary classification approach handles imbalanced dataset better than multi-class classification
- BLEU-4 evaluation is identified as poorly suited for generative spoiler text

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Two-stage classification approach outperforms baseline by better leveraging imbalanced dataset
- Mechanism: First classifier isolates multi-spoiler cases, then second handles more balanced phrase vs passage distinction, reducing class imbalance effects
- Core assumption: Separating multi class first makes remaining classification problem more balanced and easier to learn
- Evidence anchors: Abstract states two binary classifiers determine spoiler type; section 4.3 details hyperparameter tuning; no direct comparison in related work
- Break condition: If multi-spoilers aren't truly separable or if class imbalance persists within sub-tasks

### Mechanism 2
- Claim: One-shot prompting with GPT-3 can generate spoilers, but BLEU-4 evaluation is mismatched for generative outputs
- Mechanism: GPT-3 prompted with example generates spoiler; BLEU-4 compares generated to gold using exact n-gram overlap, penalizing generative variation
- Core assumption: Generative models produce semantically correct but lexically different spoilers than extractive methods
- Evidence anchors: Abstract mentions two approaches including LLM generation; section 5.3 notes significant underperformance vs baseline; corpus explicitly states evaluation metric mismatch
- Break condition: If evaluation metric changes to semantic similarity rather than exact string match

### Mechanism 3
- Claim: Balanced accuracy metric appropriately handles class imbalance in three-type classification
- Mechanism: Balanced accuracy computes mean of sensitivity and specificity across classes, preventing majority class dominance
- Core assumption: Dataset's skewed class distribution makes standard accuracy misleading
- Evidence anchors: Section 4.4 explains balanced accuracy use due to unequal spoiler amounts; notes multi class significantly outnumbered others; no comparison to other imbalanced learning metrics in related work
- Break condition: If classes become balanced or if precision/recall trade-offs become more important

## Foundational Learning

- Concept: Binary classification with imbalanced datasets
  - Why needed here: Multi-spoiler class is much smaller than phrase and passage, requiring special handling to avoid bias
  - Quick check question: Why did the authors choose balanced accuracy over standard accuracy?

- Concept: One-shot prompting for LLMs
  - Why needed here: Finetuning GPT-3 is expensive, so one-shot prompting provides cost-effective way to guide generation
  - Quick check question: What are limitations of one-shot prompting compared to few-shot or fine-tuning?

- Concept: BLEU metric for text generation evaluation
  - Why needed here: BLEU-4 measures n-gram overlap between generated and reference text, problematic for generative models
  - Quick check question: Why does BLEU-4 penalize generative models more than extractive models?

## Architecture Onboarding

- Component map: Input (title) → Model 1 (multi vs others) → Model 2 (phrase vs passage) → Output (spoiler type). Separate pipeline: Input (title + article) → GPT-3 prompt → Output (spoiler text)
- Critical path: Classification pipeline runs first to determine spoiler type, then appropriate GPT-3 prompt selected for generation
- Design tradeoffs: Two-stage classification adds complexity but handles imbalance better; generative approach allows flexible spoilers but suffers evaluation mismatch
- Failure signatures: Poor classification accuracy indicates input format or hyperparameter issues; low BLEU scores indicate prompt quality or evaluation metric mismatch
- First 3 experiments:
  1. Test Model 1 with default hyperparameters to establish baseline performance
  2. Run hyperparameter optimization search for Model 2 to see if phrase vs passage distinction improves

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How would expanding hyperparameter search space affect classification accuracy?
- Basis in paper: Authors mention hyperparameter search limited by hardware constraints (RTX 3070 with OOM errors beyond batch size 24), suggesting broader search might yield better results
- Why unresolved: Authors constrained by computational resources and could only explore limited portion of hyperparameter space
- What evidence would resolve it: Running same classification task with expanded hyperparameter ranges on more powerful hardware and comparing accuracy improvements

### Open Question 2
- Question: Would including article text as input improve classification performance?
- Basis in paper: Authors note only used title as input because "article text had little to no correlation with performance," but suggest this could be error source
- Why unresolved: Authors only experimented with title-only input despite speculating article text might improve results
- What evidence would resolve it: Training classification models using both title and article text as inputs and measuring accuracy improvements vs title-only models

### Open Question 3
- Question: Would few-shot prompting outperform one-shot approach for spoiler generation?
- Basis in paper: Authors state used one-shot prompting "because other methods resulted in input being too large for API" and suggest few-shot might improve performance
- Why unresolved: API limitations prevented testing few-shot approaches, though authors hypothesized it could yield better results
- What evidence would resolve it: Comparing GPT-3's performance on spoiler generation using few-shot prompts vs one-shot prompts on same validation set

### Open Question 4
- Question: Would alternative evaluation metrics better assess generative spoiler quality?
- Basis in paper: Authors acknowledge BLEU-4 score of 0.13 was "significantly lower than baseline" and attribute this to BLEU being "fundamentally flawed at evaluating similarity between generated text and gold standard" for generative models
- Why unresolved: Authors used BLEU-4 because it was baseline metric, but explicitly note its limitations for evaluating generated text
- What evidence would resolve it: Evaluating same generated spoilers using metrics designed for generative text (like ROUGE-L, BERTScore, or human evaluation) and comparing results to BLEU-4 baseline

## Limitations

- BLEU-4 evaluation is poorly suited for generative spoiler text, creating artificial underperformance of the generative approach
- Dataset size (4000 entries) may limit generalizability to larger-scale applications
- Two-stage classification approach adds complexity without clear demonstration that simpler approaches couldn't achieve similar results

## Confidence

- **High Confidence:** Classification approach's improved balanced accuracy (0.7884 and 0.799 vs baseline 0.7157) is well-supported by experimental results and methodology
- **Medium Confidence:** Claim that BLEU-4 is poorly suited for evaluating generative spoilers is reasonable but not definitively proven
- **Low Confidence:** Assertion that two-stage classification specifically handles class imbalance better than alternatives lacks direct comparative evidence

## Next Checks

1. **Evaluation Metric Validation:** Re-run GPT-3 spoiler generation experiment using semantic similarity metrics (BERTScore or ROUGE-L) alongside BLEU-4 to determine if generative approach is genuinely underperforming or poorly evaluated

2. **Classification Ablation Study:** Test single multi-class BERT classifier alongside two-stage binary approach on same dataset to quantify actual benefit of proposed method for handling class imbalance

3. **Dataset Scale Validation:** Evaluate both classification and generation models on larger, independently collected clickbait dataset to assess whether results generalize beyond original 4000-entry corpus
