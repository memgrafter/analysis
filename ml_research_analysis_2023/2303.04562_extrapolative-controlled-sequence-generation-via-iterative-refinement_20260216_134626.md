# Extrapolative Controlled Sequence Generation via Iterative Refinement

## Quick Facts
- arXiv ID: 2303.04562
- Source URL: https://arxiv.org/abs/2303.04562
- Authors: 
- Reference count: 28
- Primary result: Iterative Controlled Extrapolation (ICE) enables generating sequences with attribute values beyond training distribution through iterative local editing

## Executive Summary
This paper addresses the challenge of extrapolative controlled generation - creating sequences with attribute values outside the training distribution. The proposed method, Iterative Controlled Extrapolation (ICE), iteratively refines sequences using a trained editor model that learns from synthetic pairs with small attribute improvements. Experiments demonstrate that ICE significantly outperforms existing approaches like Genhance and PPLM on sentiment control and protein engineering tasks, achieving consistent extrapolation to attribute values outside the training range.

## Method Summary
ICE trains a local editor model to make small, targeted edits to sequences that improve their attribute values. The method creates synthetic training data by perturbing sequences from the training set using masked language modeling, then trains a transformer encoder-decoder to predict these improvements. At inference, ICE iteratively applies the editor for a fixed number of steps, optionally using a scorer for guidance. The key insight is that learning transformations between similar sequences generalizes better than learning distributions of very different sequences.

## Key Results
- ICE generates ACE2 mutants with lower ddG values (more stable) than training region
- On sentiment control, ICE successfully generates reviews with sentiment scores beyond training range
- Outperforms state-of-the-art methods (Genhance, PPLM) across all tested tasks
- Achieves strong performance even without scorer guidance

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Decomposing the problem into making a series of local improvements is more generalizable than directly generating sequences with out-of-distribution attribute values.
- Mechanism: By training on synthetic pairs of sequences with small improvements in attribute values, the local editor learns transformations that are more likely to generalize beyond the training distribution.
- Core assumption: The transformation from one sequence to a slightly better sequence is more generalizable across different attribute values than the distribution of sequences with very different attribute values.
- Evidence anchors:
  - [abstract] "Our key observation is that although sequences of disjoint target values (e.g., stable and unstable proteins) have very different distributions, the transformation from one sequence to a slightly better sequence is more generalizable across different attribute values."
  - [section 1] "Instead, in this work, we proposeIterative Controlled Extrapolation (ICE) which iteratively makes local edits to a sequence to enable extrapolation."

### Mechanism 2
- Claim: The iterative refinement process allows for gradual improvement of attribute values, enabling extrapolation beyond the training region.
- Mechanism: By repeatedly applying the local editor to a sequence, each iteration moves the attribute value closer to the target direction, eventually reaching values outside the training distribution.
- Core assumption: Each local edit is sufficient to make meaningful progress toward the target attribute value, and the cumulative effect of multiple edits can achieve extrapolation.
- Evidence anchors:
  - [section 1] "Our key observation is that although sequences of disjoint target values (e.g., stable and unstable proteins) have very different distributions, the transformation from one sequence to a slightly better sequence is more generalizable across different attribute values."
  - [section 3.1] "At inference time, starting with an initial example x0, we edit it iteratively to achieve extrapolation, i.e., xk+1∼p(·|xk,c ) k = 1,...,K."

### Mechanism 3
- Claim: Using control tags (<inc> and <dec>) to specify the direction of improvement allows the model to learn a more general editing strategy that can be applied in both directions.
- Mechanism: By training the model on examples with both positive and negative improvements, it learns a more flexible editing strategy that can be applied to increase or decrease attribute values as needed.
- Core assumption: The editing strategy learned from both positive and negative improvements is general enough to be applied to new sequences in either direction.
- Evidence anchors:
  - [section 3.1] "At inference time, starting with an initial example x0, we edit it iteratively to achieve extrapolation, i.e., xk+1∼p(·|xk,c ) k = 1,...,K. Each iteration is expected to move the attribute value toward the target direction."
  - [section 3.2] "Given x and its perturbation ˜x, we then create two examples for the editor: generating ˜x from x, and vice versa. We annotate the control token by comparing the attribute values of the two sequences using the scorerfs."

## Architecture Onboarding

- Component map:
  - Local editor (pθ) -> Scorer (fs) -> Synthetic data generator -> Iterative refinement loop

- Critical path:
  1. Create synthetic training data by perturbing sequences from the training set and annotating control tokens based on attribute value differences.
  2. Train the local editor (pθ) on the synthetic data to learn editing strategies for improving attribute values.
  3. At inference time, start with an initial sequence and iteratively apply the local editor to gradually improve its attribute value in the desired direction.
  4. Optionally use the scorer (fs) to guide the generation process by selecting the best candidate at each iteration.

- Design tradeoffs:
  - Number of iterations: More iterations allow for greater extrapolation but increase computational cost and risk of overfitting or divergence.
  - Amount of perturbation in synthetic data: Larger perturbations may better capture the editing strategies needed for extrapolation but may also introduce noise or unrealistic examples.
  - Use of scorer guidance: While the scorer can help guide the generation process, it may not be reliable in the extrapolation region and could potentially mislead the model.

- Failure signatures:
  - Poor extrapolation performance: The model may not be able to generate sequences with attribute values significantly outside the training distribution.
  - Unstable or divergent behavior: The iterative refinement process may lead to unstable or divergent sequences if the editing strategies are not well-controlled.
  - Overfitting to synthetic data: The model may overfit to the synthetic training data and fail to generalize to real-world examples.

- First 3 experiments:
  1. Train the local editor on synthetic data with small perturbations and evaluate its ability to improve attribute values on a validation set.
  2. Implement the iterative refinement loop and test its ability to extrapolate beyond the training region on a small set of examples.
  3. Compare the performance of the iterative refinement approach with and without scorer guidance on a larger set of examples.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the masking strategy impact the quality of generated sequences in different domains (e.g., natural language vs. proteins)?
- Basis in paper: [explicit] The authors compare different masking strategies (Small, Medium, Large, Super Large) and observe that the Super Large variant yields the best extrapolation results for sentiment control.
- Why unresolved: While the authors demonstrate the impact of masking strategies on sentiment control, they do not explore its effect on protein engineering tasks (ACE2 and AAV). The optimal masking strategy might vary across domains due to differences in sequence structure and complexity.
- What evidence would resolve it: Experiments comparing the performance of different masking strategies on protein engineering tasks, similar to the sentiment control task, would reveal if a universal optimal masking strategy exists or if domain-specific strategies are required.

### Open Question 2
- Question: Can ICE be extended to handle multiple attributes simultaneously, and how would this affect its performance?
- Basis in paper: [inferred] The authors mention that potential future directions include extending the iterative approach to multiple attributes, but they do not provide any experimental results or analysis.
- Why unresolved: The paper focuses on single-attribute controlled generation, and the impact of extending ICE to multiple attributes is unexplored. Handling multiple attributes might introduce challenges such as attribute trade-offs and increased complexity in the iterative refinement process.
- What evidence would resolve it: Experiments evaluating ICE's performance on tasks requiring the control of multiple attributes simultaneously, along with an analysis of the challenges and trade-offs involved, would provide insights into the feasibility and effectiveness of multi-attribute controlled generation with ICE.

### Open Question 3
- Question: How does the choice of the scorer model impact ICE's performance, especially in the extrapolation region?
- Basis in paper: [explicit] The authors note that the scorer's guidance is beneficial for ICE in the ACE2 task but less effective in the AAV task. They also mention that the scorer provides unreliable guidance in the extrapolation region.
- Why unresolved: The paper does not explore the impact of different scorer models on ICE's performance or investigate strategies to improve the scorer's reliability in the extrapolation region. The choice of scorer might significantly affect ICE's ability to generate high-quality sequences outside the training distribution.
- What evidence would resolve it: Experiments comparing ICE's performance using different scorer models (e.g., varying architectures, training data) and analyzing the impact of scorer reliability on the quality of generated sequences in the extrapolation region would provide insights into the importance of the scorer choice and potential strategies for improvement.

## Limitations

- Synthetic data quality uncertainty: The method's success depends heavily on the quality of synthetic training pairs created through masked language modeling, which is not extensively validated.
- Domain transferability concerns: While successful in sentiment control and protein engineering, the method's limitations across different domains and attribute types are not thoroughly explored.
- Iteration count sensitivity: The method uses fixed iteration counts without exploring the sensitivity of results to different numbers of iterations or providing theoretical guidance for selection.

## Confidence

- **High Confidence**: The core claim that local iterative refinement can achieve extrapolation beyond training distributions is well-supported by experimental results across multiple tasks. The comparison with Genhance and PPLM baselines provides strong evidence for the method's effectiveness.
- **Medium Confidence**: The claim about the editor model learning generalizable transformations from small perturbations is plausible but relies on the assumption that attribute-attribute transformations are more uniform than sequence-attribute distributions. The paper provides theoretical motivation but limited empirical validation of this assumption.
- **Low Confidence**: The claim that the method is "simple yet effective" without extensive hyperparameter tuning may overstate the practical applicability. The paper doesn't explore the sensitivity to hyperparameters like perturbation magnitude, masking strategy, or learning rates in depth.

## Next Checks

1. **Synthetic Data Quality Analysis**: Generate synthetic pairs using different perturbation strategies (varying masking approaches, perturbation magnitudes) and analyze whether the resulting pairs capture realistic attribute improvements. Compare the distribution of synthetic pairs to actual attribute-improving transformations in the training data.

2. **Iteration Count Sensitivity Study**: Systematically vary the number of iterations (K) across a wider range (e.g., K=1, 3, 5, 10, 15, 20) and measure the trade-off between extrapolation success and sequence quality/diversity. Identify the optimal K for different target extrapolation distances.

3. **Cross-Domain Generalization Test**: Apply ICE to a different controlled generation task (e.g., toxicity control, topic control, or a different molecular property) with a different attribute type and sequence domain. Evaluate whether the method's success transfers to tasks with different characteristics (e.g., multi-dimensional attributes, discrete vs. continuous attributes).
