# Exploration of Unranked Items in Safe Online Learning to Re-Rank

## Executive Summary
This paper addresses the challenge of exploring unranked items in safe online learning to rank (OLTR) systems. The proposed KL-UCB-BR algorithm extends BubbleRank by using Kullback-Leibler upper confidence bounds (KL-UCB) to efficiently select unranked items for exploration while maintaining safety constraints. The algorithm maintains three rankings (leader, temporary, and display) and uses pairwise comparison statistics to ensure that re-ranking decisions do not degrade user experience below a guaranteed threshold.

## Method Summary
KL-UCB-BR is a safe OLTR algorithm that explores both ranked and unranked items without violating safety constraints. It maintains three rankings: a leader ranking (best safe ranking found so far), a temporary ranking (for experimentation), and a display ranking (shown to users). The algorithm uses KL-UCB indices to select unranked items optimistically based on their estimated attractiveness relative to the current worst-ranked item. Pairwise comparisons using click difference statistics ensure that ranking updates are only made when confidence exceeds a safety threshold, guaranteeing that the expected cumulative clicks won't fall below a specified bound.

## Key Results
- KL-UCB-BR achieves lower cumulative expected regret than BubbleRank without safety violations
- The algorithm demonstrates particularly strong performance in late learning rounds
- Performance is consistent across both Position-Based Model (PBM) and Cascade Model (CM) click models
- Safety constraint is maintained throughout all experiments with zero violations

- Mechanism: The algorithm uses statistics based on observed click differences between item pairs to determine whether swapping items is safe, only allowing swaps when confidence exceeds a threshold.

- Claim: The two-ranking structure (leader and temporary) enables efficient exploration while preserving safety.
- Mechanism: The leader ranking tracks the best safe ranking found so far, while the temporary ranking allows experimentation with new items before committing to updates.

## Architecture Onboarding

- Component map:
  - Leader ranking -> Maintains the best safe ranking found so far
  - Temporary ranking -> Allows experimentation with new items
  - Display ranking -> Shown to users, updated conservatively
  - KL-UCB index calculator -> Computes optimism scores for unranked items
  - Pairwise comparison module -> Evaluates safety of item swaps using click statistics
  - Click feedback processor -> Updates statistics based on user interactions

- Critical path:
  1. Initialize leader ranking with original ranking
  2. Select unranked item using KL-UCB index
  3. Build temporary ranking with new item
  4. Evaluate pairwise comparisons for safety
  5. Update display ranking if safe
  6. Process click feedback and update statistics
  7. Update leader ranking if temporary ranking is superior

- Design tradeoffs:
  - Exploration vs. safety: More aggressive exploration could find better rankings faster but risks safety violations
  - Statistical efficiency vs. computational complexity: More sophisticated confidence bounds could be more efficient but require more computation
  - Adaptiveness vs. stability: Faster adaptation to new items could improve performance but might cause instability in rankings

- Failure signatures:
  - Safety violations: Display rankings that significantly underperform the original ranking
  - Poor exploration: Rankings that don't improve over time despite better items being available
  - High regret: Persistent performance gap between the algorithm's rankings and the optimal ranking
  - Excessive conservatism: Rankings that change very slowly, maintaining suboptimal item positions

- First 3 experiments:
  1. Test the algorithm with a synthetic dataset where item attractiveness is known, measuring both regret and safety violations
  2. Evaluate performance under different click models (PBM vs CM) to verify robustness
  3. Compare KL-UCB-BR against baselines with varying numbers of unranked items to assess scalability

## Limitations
- The algorithm's safety guarantee depends critically on accurate click model parameter estimation
- Performance may degrade with limited user interactions or highly skewed item attractiveness distributions
- The assumption that users click on attractive items within their examination range may break down under certain user behaviors

## Confidence
