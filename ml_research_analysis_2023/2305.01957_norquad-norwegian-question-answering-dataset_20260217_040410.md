# NorQuAD: Norwegian Question Answering Dataset

## Quick Facts
- arXiv ID: 2305.01957
- Source URL: https://arxiv.org/abs/2305.01957
- Reference count: 7
- First Norwegian question answering dataset for machine reading comprehension with 4,752 manually created question-answer pairs

## Executive Summary
This paper introduces NorQuAD, the first Norwegian question answering dataset designed for machine reading comprehension tasks. The dataset contains 4,752 manually created question-answer pairs derived from Wikipedia and news articles. The paper presents detailed methodology for data collection, provides comprehensive dataset statistics, and benchmarks several multilingual and Norwegian monolingual language models on the task. Human evaluation demonstrates that while automated models achieve reasonable performance (69.68% exact match, 81.27% F1), human performance remains significantly higher at 78.13% exact match and 91.14% F1 score on the test set.

## Method Summary
The NorQuAD dataset was created through a manual annotation process where annotators generated question-answer pairs from Norwegian Wikipedia articles and news content. The dataset construction followed established QA dataset creation methodologies, ensuring that questions were answerable from the provided context passages. The annotation process involved careful quality control measures to maintain consistency across the dataset. The resulting dataset was split into training, development, and test sets for benchmarking purposes. Multiple language models including multilingual and Norwegian-specific models were evaluated on the dataset using standard QA metrics of exact match and F1 score.

## Key Results
- Best performing model achieved 69.68% exact match and 81.27% F1 score on test set
- Human performance measured at 78.13% exact match and 91.14% F1 score on test set
- Dataset available at https://github.com/ltgoslo/NorQuAD for research and development

## Why This Works (Mechanism)
The dataset creation mechanism leverages manual annotation of high-quality Norwegian text sources, ensuring natural question formulation and accurate answer extraction. The use of both Wikipedia and news articles provides diverse domain coverage while maintaining topical coherence. The manual creation process allows for careful control over question difficulty and answer specificity, creating a challenging but learnable task for machine reading comprehension systems.

## Architecture Onboarding

Component Map: Wikipedia/News Articles -> Question Generation -> Answer Extraction -> Dataset Curation -> Model Training -> Evaluation

Critical Path: Data Collection → Manual Annotation → Quality Control → Dataset Splitting → Model Training → Performance Evaluation

Design Tradeoffs: The manual annotation approach ensures high-quality data but limits dataset size compared to automated methods. Using Wikipedia and news sources provides topical diversity but may bias the dataset toward certain domains and writing styles.

Failure Signatures: Poor model performance may indicate insufficient training data, annotation inconsistencies, or domain mismatch between training and test sets. Human performance gaps suggest areas where models struggle with nuanced understanding or require additional training data.

## Limitations
- Dataset size of 4,752 pairs is relatively small compared to large-scale QA datasets in high-resource languages
- Domain coverage limited primarily to Wikipedia and news articles, potentially missing other Norwegian text genres
- Benchmark results may not be directly comparable to larger datasets due to domain and size differences

## Confidence

High confidence: Dataset creation methodology and basic statistics are well-documented and reproducible. NorQuAD is confirmed as the first Norwegian QA dataset for machine reading comprehension.

Medium confidence: Benchmark results and human performance metrics are reasonable given dataset characteristics, though direct comparisons to larger datasets may be limited.

Low confidence: Claims about dataset sufficiency for comprehensive Norwegian QA system development are constrained by relatively small size and narrow domain coverage.
