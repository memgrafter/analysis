# RescueSNN: Enabling Reliable Executions on Spiking Neural Network Accelerators under Permanent Faults

## Quick Facts
- arXiv ID: 2304.04041
- Source URL: https://arxiv.org/abs/2304.04041
- Authors: 
- Reference count: 11
- Key outcome: RescueSNN improves SNN accuracy by up to 80% on MNIST and 47% on Fashion MNIST datasets while maintaining throughput reduction below 25% in high fault rates.

## Executive Summary
RescueSNN addresses permanent faults in spiking neural network (SNN) hardware accelerators that degrade accuracy and cause system malfunctions. The approach employs fault-aware mapping (FAM) that leverages the fault map of the SNN compute engine to minimize weight corruption and selectively avoid faulty neurons. Lightweight hardware enhancements support FAM through bit-shuffling using multiplexers and barrel shifters. Experimental results demonstrate significant accuracy improvements without requiring retraining, making SNNs more reliable for deployment in real-world applications.

## Method Summary
RescueSNN implements three variants of fault-aware mapping (FAM1, FAM2, FAM3) that leverage the fault map of SNN compute engines to minimize weight corruption and selectively employ faulty neurons. FAM1 avoids all faulty neurons, FAM2 adds bit-shuffling to map significant weight bits to non-faulty memory cells, and FAM3 selectively avoids only neurons with faulty 'Vmem reset' operations. Hardware enhancements include 8-bit barrel shifters per compute engine column and an Enhancement Control Unit (ECU) for bit-shifting control. The method is evaluated using Python-based simulation framework with MNIST and Fashion MNIST datasets on fully-connected SNN models with up to 3600 neurons.

## Key Results
- Accuracy improvement up to 80% on MNIST and 47% on Fashion MNIST datasets
- Throughput reduction maintained below 25% even in high fault rates (0.5)
- No retraining required for fault mitigation
- Three FAM variants offer tradeoffs between accuracy and throughput

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Bit-shuffling in FAM minimizes weight corruption by mapping significant bits to non-faulty memory cells.
- Mechanism: When a synapse has faulty weight memory cells, the most significant bits of its weight are circularly shifted into the contiguous block of non-faulty cells. This preserves the magnitude of the weight and reduces error propagation.
- Core assumption: The significance of a weight bit is proportional to its position in the fixed-point representation.
- Evidence anchors:
  - [section] "Our FAM techniques leverage the fault map of the compute engine to perform the following key mechanisms. 1. Mapping the significant weight bits on the non-faulty weight memory cells of the synapses (weight registers) to minimally pollute/change the weight values."
  - [abstract] "Our FAM technique leverages the fault map of SNN compute engine for (i) minimizing weight corruption when mapping weight bits on the faulty memory cells..."

### Mechanism 2
- Claim: Selective neuron usage avoids columns with faulty 'Vmem reset' operations that cause continuous spiking.
- Mechanism: The mapping strategy omits any column whose neuron has a 'Vmem reset' fault, because such faults force the neuron to continuously generate spikes, dominating classification and degrading accuracy.
- Core assumption: Neurons with faulty 'Vmem reset' operations produce a disproportionately high spike rate compared to other faulty operations.
- Evidence anchors:
  - [section] "We study the accuracy under faulty neuron operations, by injecting faults on the neuron operations, while considering fault-free weight registers. Experimental results are shown in Fig. 8... Faulty 'Vmem reset' operations cause significant accuracy degradation, as these operations make the corresponding neurons dominate classification."
  - [abstract] "Our FAM technique leverages the fault map of SNN compute engine for (ii) selectively employing faulty neurons that do not cause significant accuracy degradation..."

### Mechanism 3
- Claim: Lightweight hardware enhancement reorders shuffled weight bits back to original order using a shared barrel shifter per column.
- Mechanism: A Hardware Enhancement Block (HEB) per column contains a barrel shifter controlled by the Enhancement Control Unit (ECU). Each synapse accesses the HEB in turn, applying the inverse shuffle to restore original bit order for neuron computation.
- Core assumption: A single barrel shifter per column can handle all synapses in the column without creating a timing bottleneck.
- Evidence anchors:
  - [section] "Our enhancements shuffle the weight bits from the synapses by employing simple combinational logic units, such as multiplexers, so that these weight bits can be used for SNN computations."
  - [section] "To optimize the overheads (e.g., area), we share a hardware enhancement block (HEB) with all synapses in the same column of compute engine, and different synapses will access the enhancement block at a different time..."

## Architecture Onboarding

- Component map: Synapse crossbar (256x256 array of 8-bit weight registers) -> LIF neurons (one per column) -> Hardware Enhancement Block (HEB) -> Neuron computation pipeline

- Critical path: Synapse -> HEB (for FAM2/FAM3) -> Neuron computation pipeline

- Design tradeoffs:
  - Accuracy vs. throughput: FAM1 avoids all faulty neurons (high accuracy, low throughput); FAM3 selectively avoids only 'Vmem reset' faults (balanced)
  - Hardware overhead: Shared HEB reduces area but adds access latency
  - Mapping complexity: FAM3 requires more complex mapping logic than FAM1

- Failure signatures:
  - Continuous spiking in a neuron column -> likely 'Vmem reset' fault
  - Reduced classification accuracy without throughput loss -> likely weight bit corruption in synapses
  - Increased energy consumption without accuracy loss -> likely extra computations due to shared HEB contention

- First 3 experiments:
  1. Inject only 'Vmem reset' faults across columns; verify FAM3 maintains accuracy by avoiding those columns
  2. Inject stuck-at faults in weight registers; verify FAM2 maps significant bits to non-faulty cells and improves accuracy
  3. Combine both fault types; measure accuracy, throughput, and energy for FAM1, FAM2, FAM3 versus baseline

## Limitations
- Evaluation relies on synthetic fault injection rather than post-manufacturing testing of real chips
- Performance metrics are measured in simulation; actual hardware overhead could differ due to routing delays and process variations
- Mapping strategy assumes uniform fault distribution, which may not reflect real-world defect patterns

## Confidence
- High confidence: FAM mechanism effectiveness in reducing weight corruption (supported by controlled fault injection experiments)
- Medium confidence: Throughput claims (simulation-based measurements with shared hardware resources)
- Low confidence: Real-world applicability without retraining (synthetic evaluation only)
