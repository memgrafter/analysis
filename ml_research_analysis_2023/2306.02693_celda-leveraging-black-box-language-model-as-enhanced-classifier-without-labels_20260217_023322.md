# CELDA: Leveraging Black-box Language Model as Enhanced Classifier without Labels

## Quick Facts
- arXiv ID: 2306.02693
- Source URL: https://arxiv.org/abs/2306.02693
- Reference count: 17
- Key outcome: CELDA improves text classification accuracy using large language models as fixed black-box feature extractors without access to internal parameters or labels.

## Executive Summary
CELDA addresses the challenge of improving text classification accuracy when using large language models (LMs) as fixed black-box feature extractors without access to internal parameters or labels. The method generates pseudo-labels from an unlabeled dataset using prompting, then clusters and filters out uncertain samples based on cluster entropy to create a cleaner training set. This dataset is used to train a Linear Discriminant Analysis (LDA) classifier stacked on top of the LM's representations. Experiments on 8 datasets show CELDA consistently outperforms other zero-shot and weakly-supervised baselines and closes the gap with fully supervised LDA.

## Method Summary
CELDA uses a two-step approach to improve text classification: first, it extracts refined pseudo-labeled datasets from unlabeled data using prompting and clustering; second, it trains an LDA classifier on top of LM representations. The method involves passing unlabeled data through an LM to get embeddings and pseudo-labels, clustering and filtering uncertain samples using entropy, and recursively training LDA with moving average updates to avoid oscillation. The approach leverages the LM as a black-box feature extractor without requiring access to internal parameters.

## Key Results
- CELDA consistently outperforms zero-shot and weakly-supervised baselines on 8 benchmark datasets
- The method closes the performance gap with fully supervised LDA classification
- CELDA scales well with LM size and works effectively with few-shot active learning for fine-grained tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Pseudo-label entropy filtering improves classification accuracy by removing low-confidence samples from training data.
- Mechanism: Clustering extracts pseudo-labels from LM outputs, then computes cluster entropy to identify uncertain samples; these are filtered out to create a cleaner training set for LDA.
- Core assumption: Samples within high-entropy clusters are more likely to be misclassified, so removing them improves model robustness.
- Evidence anchors:
  - [abstract] "We accomplish the first goal by sorting out some uncertain data points via clustering the features from LM."
  - [section 4.2] "We measure the entropy weight (EW) of each cluster to estimate their uncertainty" and "By setting a threshold, τ, we are able to select a portion of certain clusters Kclean while removing several uncertain clusters."
- Break condition: If cluster entropy thresholds are set too high, meaningful samples may be discarded, reducing training set size and hurting performance.

### Mechanism 2
- Claim: Stacked LDA on LM features achieves better generalization than fine-tuning the LM itself.
- Mechanism: LDA is trained on pseudo-labeled data using a shared covariance assumption, which reduces parameters and improves robustness to noise compared to Gaussian Mixture Models.
- Core assumption: Shared covariance is sufficient for class separation and reduces overfitting when training data is noisy and limited.
- Evidence anchors:
  - [section 3.3] "LDA assumes the class conditional densities follow multivariate Gaussian distribution with tied covariance over classes."
  - [section 4.3] "The mentioned characteristics of LDA are highly valuable in our scenario, where the training dataset is noisy and a portion of the available data is discarded during the previous data cleansing stage."
- Break condition: If data is abundant and clean, shared covariance may hurt performance compared to class-specific covariances.

### Mechanism 3
- Claim: Iterative pseudo-label refinement with moving average updates improves decision boundary precision.
- Mechanism: Trained LDA generates new pseudo-labels; these are used to re-cluster and re-filter data; LDA parameters are updated via moving average to prevent oscillation.
- Core assumption: LDA's improved pseudo-labels are more accurate than initial LM-generated labels, enabling progressive refinement.
- Evidence anchors:
  - [section 4.3] "we recursively train LDA by updating the pseudo labels with the trained model and repeating the previous data cleansing steps" and "we employ moving average (MA): ˆµt+1 = t − 1/t ˆµt−1 + 1/t ˆµt".
  - [section 5.4] "another noteworthy observation is that CELDA approaches the fully supervised LDA with a small spread on most benchmarks."
- Break condition: If updates cause label oscillations beyond threshold δ, training stops to prevent divergence.

## Foundational Learning

- Concept: K-means clustering on high-dimensional LM embeddings
  - Why needed here: Groups semantically similar sentences so entropy can identify uncertain samples.
  - Quick check question: What happens to cluster entropy if clusters contain only one class vs. mixed classes?

- Concept: Multivariate Gaussian discriminant analysis with tied covariance
  - Why needed here: Enables efficient parameter estimation and robustness to noise in small, pseudo-labeled datasets.
  - Quick check question: How does tied covariance reduce parameters compared to per-class covariances?

- Concept: Entropy as uncertainty measure in classification
  - Why needed here: Quantifies confidence of pseudo-labels within clusters to guide filtering.
  - Quick check question: What entropy value indicates maximum uncertainty for a binary classification cluster?

## Architecture Onboarding

- Component map: LM feature extractor -> Pseudo-label generator -> Clustering + entropy filter -> LDA trainer with moving average updates -> Active learning hook (optional)

- Critical path: Feature extraction → Pseudo-labeling → Clustering → Entropy filtering → LDA training → (Iterate if needed)

- Design tradeoffs:
  - Shared covariance vs. class-specific: fewer parameters but potential underfitting
  - Entropy threshold τ: higher → cleaner but smaller dataset; lower → more data but noisier
  - Number of clusters: more → finer granularity but unreliable entropy estimates

- Failure signatures:
  - Performance plateaus early: likely over-filtering or poor pseudo-labels
  - High variance across runs: unstable clustering or entropy estimates
  - Degradation vs. baselines: shared covariance insufficient for data complexity

- First 3 experiments:
  1. Ablation: Run CELDA without entropy filtering; compare accuracy drop
  2. Sensitivity: Vary cluster count K and observe performance curve
  3. Active learning: Apply 8-shot per class on Banking77 and measure improvement

## Limitations
- The method relies heavily on the quality of pseudo-labels generated by prompting the LM, which is not directly evaluated
- The exact implementation details for prompting templates, entropy thresholds, and cluster counts are not fully specified
- The experimental setup uses a fixed set of 8 datasets without exploring diverse data characteristics or domain shifts

## Confidence

**High Confidence**: The core contribution of leveraging LM as a black-box feature extractor with pseudo-label generation and entropy filtering is well-defined and experimentally validated on multiple benchmarks.

**Medium Confidence**: The iterative refinement mechanism and its convergence properties are supported by results but lack detailed analysis of failure cases or sensitivity to threshold parameters.

**Low Confidence**: The exact implementation details for prompting templates, entropy thresholds, and cluster counts are not fully specified, making exact reproduction challenging.

## Next Checks
