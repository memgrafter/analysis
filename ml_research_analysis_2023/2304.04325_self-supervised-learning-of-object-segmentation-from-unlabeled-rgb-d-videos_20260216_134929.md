# Self-Supervised Learning of Object Segmentation from Unlabeled RGB-D Videos

## Quick Facts
- arXiv ID: 2304.04325
- Source URL: https://arxiv.org/abs/2304.04325
- Reference count: 40
- Primary result: Achieves 0.87 IoU on real dataset and 0.88 IoU on synthetic dataset for unsupervised object segmentation

## Executive Summary
This paper proposes a self-supervised method for segmenting rigid objects in RGB images using unlabeled RGB-D videos. The key innovation is using graph matching on over-segmented point clouds reconstructed from these videos to identify recurring object patterns and generate pseudo labels. These pseudo labels are then used to train a pixel-wise feature extractor via contrastive learning, which can be used for object segmentation via clustering. The method significantly outperforms existing unsupervised methods on both real and synthetic video datasets, demonstrating the effectiveness of using geometric inductive bias and object reappearance across different scenes for segmenting previously seen objects.

## Method Summary
The method processes unlabeled RGB-D videos through 3D reconstruction, over-segmentation, and graph-based pattern matching to identify recurring objects across scenes. It first reconstructs 3D scenes using KinectFusion, then applies LCCP and SymSeg for consistent over-segmentation. A graph matching algorithm identifies recurring subgraph patterns across scenes, which are verified using point cloud registration to filter false matches. The resulting object pseudo-labels are used to train a pixel-wise feature extractor through contrastive learning, with final segmentation achieved via mean-shift clustering on the learned features.

## Key Results
- Achieves 0.87 IoU on real dataset, significantly outperforming unsupervised baselines (0.42 IoU)
- Achieves 0.88 IoU on synthetic dataset, demonstrating strong performance across different data types
- Successfully segments 7 non-convex objects in real-world testing, showing robustness to geometric complexity

## Why This Works (Mechanism)

### Mechanism 1
The graph-matching algorithm can reliably find recurring object patterns across different scenes by matching over-segmented 3D parts. Over-segmented 3D point clouds from different scenes are represented as graphs where nodes are segments and edges connect adjacent segments. A binary linear program (BLP) finds subgraph isomorphisms between these graphs based on feature similarity, identifying groups of segments that consistently co-occur across scenes as parts of the same object. The same object instance will be over-segmented into similar sets of parts across different scenes, and these part arrangements will be unique enough to distinguish one object from another. If the over-segmentation is inconsistent across scenes or if different objects share similar part arrangements, the graph matching will fail to correctly identify object instances.

### Mechanism 2
Contrastive learning on over-segmented parts can learn distinctive features that enable accurate object segmentation. Pixel features are trained to be similar within the same 3D segment (positive pairs) and dissimilar across different segments (negative pairs). This creates a feature space where pixels belonging to the same object are clustered together, enabling segmentation via clustering. Points within the same 3D segment belong to the same object, and objects have consistent visual appearance across different views. If the over-segmentation produces segments that cross object boundaries, or if objects have inconsistent appearance across views, the contrastive learning will not produce discriminative features.

### Mechanism 3
Combining graph matching with point cloud registration can reliably filter out false matches and produce accurate object pseudo-labels. After graph matching identifies candidate matching segments across scenes, point cloud registration is used to verify these matches. Segments that don't register well (low precision/recall) are rejected, ensuring only true object parts are combined into pseudo-labels. True object parts will register well between different views, while false matches will not. If the point cloud registration fails due to clutter, occlusion, or geometric complexity, false matches may not be filtered out, leading to incorrect pseudo-labels.

## Architecture Onboarding

- **Component map**: Video pre-processing -> Over-segmentation -> Graph construction -> Graph matching -> False match pruning -> Feature learning -> Inference
- **Critical path**: Video pre-processing → Over-segmentation → Graph construction → Graph matching → False match pruning → Feature learning → Inference
- **Design tradeoffs**:
  - Over-segmentation granularity: Too coarse → objects not separable; too fine → inconsistent segmentation across scenes
  - Graph matching parameters: Thresholds for match cost and registration precision/recall need tuning for different object sets
  - Feature learning: Temperature parameter in contrastive loss, embedding dimension, and clustering parameters affect segmentation quality
- **Failure signatures**:
  - Graph matching produces no matches: Likely due to inconsistent over-segmentation or insufficient object reappearance across scenes
  - Segmentation is too coarse: Likely due to over-segmentation being too coarse or graph matching merging too many segments
  - Segmentation is too fine: Likely due to over-segmentation being too fine or graph matching not merging enough segments
  - Feature learning fails: Likely due to poor quality pseudo-labels or inappropriate contrastive learning parameters
- **First 3 experiments**:
  1. Verify graph matching works on simple synthetic scenes with known object arrangements
  2. Test over-segmentation consistency across different views of the same scene
  3. Validate feature learning produces discriminative features for simple objects before applying to full pipeline

## Open Questions the Paper Calls Out

### Open Question 1
How does the performance of the graph matching algorithm scale with the number of input videos and scenes? The paper mentions that pairwise matching across 30 scenes can be done within 10 minutes on an AMD Ryzen 5900 CPU, but does not provide a detailed analysis of scalability. Conducting experiments with varying numbers of input videos and scenes to measure running time and accuracy would resolve this question.

### Open Question 2
Can the proposed method handle deformable objects or objects with significant changes in appearance across different scenes? The paper mentions that the method cannot handle deformable objects in general, as it requires matched objects to be identical in both texture and geometry. Conducting experiments with deformable objects or objects with significant changes in appearance would evaluate the method's performance and identify potential limitations.

### Open Question 3
How does the proposed method perform when the initial object over-segmentation is not consistent across different scenes? The paper mentions that the method relies on consistent object over-segmentation across different scenes and discusses potential issues when this is not achieved. Conducting experiments with scenes where the initial object over-segmentation is not consistent would evaluate the method's performance and identify potential improvements.

## Limitations

- The method requires object reappearance across scenes, making it unable to segment objects that appear only once
- Performance on non-convex objects is notably lower than convex objects, indicating geometric complexity remains challenging
- The approach requires relatively clean 3D reconstructions from RGB-D data, making it sensitive to sensor noise and reconstruction artifacts

## Confidence

- **High confidence** in the core mechanism of using graph matching to identify recurring object patterns across scenes, supported by quantitative results showing substantial improvement over unsupervised baselines (0.87 IoU vs 0.42 baseline on real data)
- **Medium confidence** in the overall pipeline's generalizability beyond the tested scenarios, given the limited diversity of object sets and scene configurations in the evaluation datasets
- **Medium confidence** in the feature learning effectiveness, as the paper demonstrates good segmentation quality but doesn't thoroughly explore the feature space or provide ablation studies on the contrastive learning components

## Next Checks

1. Test the method on scenes where objects appear only once or in highly variable configurations to assess the fundamental limitation of requiring object reappearance

2. Evaluate performance degradation as sensor noise increases or reconstruction quality decreases to understand robustness to real-world sensing conditions

3. Conduct ablation studies removing the point cloud registration step to quantify its contribution to filtering false matches and improving segmentation accuracy
