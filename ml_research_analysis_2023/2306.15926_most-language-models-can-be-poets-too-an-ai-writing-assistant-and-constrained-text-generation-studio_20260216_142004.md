# Most Language Models can be Poets too: An AI Writing Assistant and Constrained Text Generation Studio

## Quick Facts
- arXiv ID: 2306.15926
- Source URL: https://arxiv.org/abs/2306.15926
- Reference count: 7
- The paper introduces a filter-based method for enforcing lexical constraints on any language model without fine-tuning, and demonstrates it through CTGS, an AI writing assistant for constrained text generation.

## Executive Summary
This paper presents a novel plug-and-play technique for enforcing constraints on language model outputs through vocabulary filtering, eliminating the need for fine-tuning or architectural modifications. The method enables arbitrary constraints (lexical, semantic, phonetic) to be applied during generation by filtering the model's vocabulary before each prediction step. The authors demonstrate this approach through CTGS, a writing assistant that allows users to impose various constraints during text generation, and validate it on a novel Lipogram-e dataset of prose without the letter "e."

## Method Summary
The core technique involves applying filter functions to the language model's vocabulary before each generation step, dynamically constraining which tokens can be selected based on user-defined rules. These filters can enforce various constraints including character bans, rhyme requirements, or syllable counts by modifying the probability distribution over the vocabulary. The approach is implemented as a wrapper around any language model, requiring no modifications to the model itself. For evaluation, the authors created a Lipogram-e dataset of prose excluding the letter "e" and compared their filtering approach against fine-tuned models, demonstrating lower perplexity and zero constraint violations.

## Key Results
- The filtering approach achieves strictly lower perplexity than fine-tuned models on the Lipogram-e dataset
- Zero constraint-violation errors were observed when using the filtering method
- The CTGS writing assistant successfully enables users to impose various lexical, semantic, and phonetic constraints during text generation

## Why This Works (Mechanism)
The filtering method works by intercepting the model's output vocabulary at each generation step and removing tokens that would violate the specified constraints. This creates a constrained probability distribution that maintains the model's learned knowledge while enforcing user-defined rules. The approach is model-agnostic because it operates externally to the language model itself, making it compatible with any autoregressive model without requiring architectural changes or retraining.

## Architecture Onboarding

**Component map**: User Interface -> Constraint Parser -> Filter Function -> Language Model -> Text Output

**Critical path**: User specifies constraint → Constraint parser converts to filter function → Filter applied to vocabulary → Language model generates constrained text → Output displayed

**Design tradeoffs**: The approach trades some vocabulary diversity for guaranteed constraint satisfaction. While fine-tuning might preserve more natural language patterns, filtering provides exact constraint enforcement without model retraining.

**Failure signatures**: Constraint violations (if filters are incorrectly implemented), reduced vocabulary diversity leading to repetitive text, increased generation latency due to filtering overhead.

**First experiments**: 1) Test basic character filtering on simple text generation, 2) Evaluate rhyme constraint enforcement on poetry generation, 3) Measure latency impact of filtering during real-time generation.

## Limitations
- The approach may significantly reduce vocabulary diversity during generation, potentially leading to less creative or more repetitive text under strict constraints
- Computational overhead from filtering is not thoroughly analyzed, particularly for real-time applications
- Performance across different model sizes and architectures remains unexplored, limiting generalizability claims

## Confidence

- High confidence: The core claim that filtering-based constraint enforcement produces strictly lower perplexity and zero constraint-violation errors compared to fine-tuned models alone
- Medium confidence: The generalizability claim that this approach works "with any language model" without fine-tuning
- Low confidence: The practical usability claims for the CTGS writing assistant in real-world creative writing scenarios
