# A Mental Model Based Theory of Trust

## Quick Facts
- arXiv ID: 2301.12569
- Source URL: https://arxiv.org/abs/2301.12569
- Reference count: 32
- Primary result: Proposes a formal theory of human trust in AI based on mental models and Bayesian belief updating

## Executive Summary
This paper introduces a mental model based theory of trust (MMbTT) that formalizes human trust in AI systems through probabilistic beliefs about agent capabilities. The theory models trust as a function of human beliefs over possible agent models, using Bayesian updating to capture trust evolution. Human subject studies compared MMbTT against the Muir trust scale, showing that changes in likelihood of satisfying contracts produce different effects on trust components, supporting the theory's predictive power.

## Method Summary
The paper develops a theoretical framework where trust is computed as a weighted sum of likelihoods that each possible agent model can satisfy a contract. Trust evolution is modeled as Bayesian updates to the human's belief distribution over agent models based on observed behavior or explanations. The theory is validated through human subject studies comparing trust predictions to questionnaire responses, using a running example of a robot in a hallway navigation task.

## Key Results
- Trust is formalized as T(C) ∝ F(P(CH)) where P(CH) = Σ P(CH|M)×PM(M)
- Trust evolution occurs through Bayesian updates to the human's belief distribution over agent models
- Human subject studies show changes in contract satisfaction likelihood produce different effects on trust components
- The theory provides a framework for appropriate trust calibration between human beliefs and actual agent capability

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Trust is formalized as a probabilistic belief about an agent's ability to satisfy a contract, allowing it to be directly computed from mental models.
- Mechanism: The human maintains a set of possible agent models (MR_h) with associated likelihoods. Trust in the agent with respect to a contract C is computed as a weighted sum of the likelihood each model can satisfy C, i.e., T(C) ∝ F(P(CH)) where P(CH) = Σ P(CH|M)×PM(M).
- Core assumption: Humans reason about agent behavior using Bayesian updating over a set of candidate models.
- Evidence anchors:

  - [section] "We will assume that the human reasoning can be captured using the probabilistic graphical model presented in Figure 3(A)"
  - [corpus] Weak - no direct evidence in neighbors about Bayesian trust computation
- Break condition: If humans do not update their beliefs about MR_h in a Bayesian fashion, or if the model set is not sufficiently expressive, the computed trust will not match actual trust.

### Mechanism 2
- Claim: Trust evolution is modeled as changes in the posterior distribution over the human's beliefs about the agent's model.
- Mechanism: As the agent behaves or explains, the human updates PM(M) for each M in MR_h. This update changes P(CH), and thus T(C), in a predictable direction depending on whether the update increases or decreases the likelihood of satisfying the contract.
- Core assumption: Observed agent behavior or explanations cause humans to update their beliefs about the agent's true model in a way that aligns with Bayesian inference.
- Evidence anchors:
  - [section] "As the human's trust is directly tied to their uncertainty about the agent model, their trust evolves as their belief over MR_h changes"
  - [abstract] "models trust evolution as changes in the human's belief over MR_h"
  - [corpus] Weak - neighbors discuss ToM and mental models but not Bayesian updating of trust
- Break condition: If the human's belief updates are not driven by new evidence (e.g., if updates are arbitrary or based on unrelated factors), trust evolution will not align with predictions.

### Mechanism 3
- Claim: The "appropriate" level of trust is defined as the human's belief about the agent's ability to satisfy a contract matching the agent's actual ability.
- Mechanism: Formally, trust is appropriate if P(CH) = P(CR|MR), where CR is the random variable for the agent actually achieving the contract.
- Core assumption: Appropriate trust requires calibration between the human's estimate and the agent's true capability.
- Evidence anchors:
  - [section] "trust level is appropriate, if P(CH) = Σ P(CH|M)×PM(M) = P(CR|MR)"
  - [abstract] "formalization of the appropriate level of trust in the agent"
  - [corpus] Weak - no neighbor evidence about calibration or appropriateness of trust
- Break condition: If the human's beliefs are systematically biased (e.g., over- or under-confidence) or the agent's actual capability is not well-defined, the appropriate trust condition will not be met.

## Architecture Onboarding

- Component map:
  - Agent model (MR): The AI agent's internal model of itself
  - Human's model set (MR_h): The human's set of possible models of the agent, each with a likelihood PM(M)
  - Human's task model (M*_h): The human's expectations about the task, used to define the contract
  - Trust function: Computes T(C) as a function of P(CH), which is derived from MR_h and the contract
  - Belief updater: Updates PM(M) for each M in MR_h based on observed agent behavior or explanations

- Critical path:
  1. Define the contract C from M*_h
  2. Compute initial P(CH) from MR_h and contract
  3. Compute initial trust T(C)
  4. Observe agent behavior or explanation
  5. Update PM(M) for each M in MR_h
  6. Recompute P(CH) and T(C)
  7. Compare T(C) to appropriate trust threshold

- Design tradeoffs:
  - Expressive vs. tractable model set: Larger MR_h increases expressiveness but makes computation harder
  - Specificity of contract: More specific contracts may lead to better-calibrated trust but require more detailed models
  - Explanation vs. behavior: Explanations can directly update MR_h but may be less convincing than observed behavior

- Failure signatures:
  - Trust not updating after agent behavior: Likely issue with belief updater or model set
  - Trust higher than actual capability: Over-confidence in MR_h or inappropriate contract definition
  - Trust not aligned with questionnaire responses: Model assumptions about trust computation may not match human psychology

- First 3 experiments:
  1. Implement trust computation for a simple agent with 2-3 possible models. Verify that trust changes as the human's belief about the agent's model changes.
  2. Add belief updating based on simulated agent behavior. Verify that trust evolves in the expected direction.
  3. Compare trust predictions to human responses on a trust questionnaire for a controlled task. Identify where the model diverges from human judgments.

## Limitations

- The theory assumes humans reason about AI agents using Bayesian inference over mental models, which lacks strong empirical support in the neighboring literature
- The framework requires a well-defined set of possible agent models (MR_h) and a clear contract, which may not always be available in complex real-world scenarios
- The assumption that the agent's actual capability (CR|MR) is known and can be compared to human beliefs may not hold in practice

## Confidence

- **High Confidence**: The mathematical formalization of trust as P(CH) and the definition of appropriate trust as P(CH) = P(CR|MR) are internally consistent and logically sound
- **Medium Confidence**: The mechanism of trust evolution through Bayesian updating of beliefs over MR_h is theoretically plausible but lacks empirical validation in the provided literature
- **Low Confidence**: The assumption that humans naturally reason about AI agents using Bayesian inference over mental models is not well-supported by the neighboring literature, which discusses mental models and ToM but not Bayesian trust computation
