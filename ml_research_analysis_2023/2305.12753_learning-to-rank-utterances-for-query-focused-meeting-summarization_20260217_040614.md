# Learning to Rank Utterances for Query-Focused Meeting Summarization

## Quick Facts
- arXiv ID: 2305.12753
- Source URL: https://arxiv.org/abs/2305.12753
- Reference count: 9
- This paper introduces a ranker-generator framework for query-focused meeting summarization that learns to rank utterances by pairwise and listwise comparison

## Executive Summary
This paper addresses the challenge of query-focused meeting summarization by proposing a ranker-generator framework that learns to rank utterances based on their relative quality rather than absolute scores. The approach uses a two-stage ranking process: first conducting sample-wise pairwise ranking within utterance groups, then applying global listwise re-ranking to the top utterances before passing them to the generator. The framework demonstrates superior performance on the QMSum dataset compared to existing multi-stage models while using fewer parameters, and shows improved query relevance and factual consistency in human evaluations.

## Method Summary
The proposed ranker-generator framework consists of two ranking stages followed by a generator. The first stage divides utterances into samples and performs pairwise ranking within each sample using a cross-encoder model to compute query-utterance relevance scores. The second stage applies listwise re-ranking to the top utterances from all samples using top-k permutation probability distribution to capture global ordering relationships. Finally, the top K utterances are concatenated and passed to a BART generator to produce the final summary. The model is trained using pairwise ranking loss and listwise re-ranking loss, with MiniLM as the backbone for both ranking modules.

## Key Results
- Achieves 35.51 ROUGE-1 score on QMSum test set, outperforming previous best (34.91)
- Uses fewer parameters than baseline multi-stage models while maintaining superior performance
- Extracts top-5 utterances with 20.07 ROUGE-1 score compared to 18.02 for baseline
- Human evaluation shows better query relevance and factual consistency

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Learning to rank utterances improves query relevance by capturing relative quality between utterances rather than absolute scores
- Mechanism: The ranker learns pairwise and listwise comparisons between utterances based on their relative ROUGE scores with the gold summary, enabling it to distinguish query-relevant utterances more effectively than binary classification or score regression
- Core assumption: The relative order of utterances' relevance to the query is more informative than absolute relevance scores for the generator's input selection
- Evidence anchors: "comparison orders are more important than specific scores" and "we care more about the relative orders of utterances"

### Mechanism 2
- Claim: Two-stage ranking reduces computational complexity while maintaining ranking accuracy
- Mechanism: First stage divides utterances into samples and performs pairwise ranking within each sample, then second stage applies listwise re-ranking only to top utterances from different samples, avoiding quadratic complexity of full pairwise ranking
- Core assumption: Top utterances within samples are likely to be top utterances globally, making sample-wise ranking sufficient for initial filtering
- Evidence anchors: "The computing complexity of full-pairwise ranking grows at a square rate as the number of utterances grows" and "we adopt a two-stage ranking framework"

### Mechanism 3
- Claim: Top-k listwise re-ranking produces more accurate global ordering than pairwise ranking alone
- Mechanism: After sample pairwise ranking, the model performs listwise re-ranking on top utterances from different samples using top-k permutation probability distribution to capture global ordering relationships
- Core assumption: The top utterances from different samples need global context to determine their relative quality, which pairwise ranking within samples cannot provide
- Evidence anchors: "the top utterances in different samples are gathered in the re-ranking module" and "Experimental results show that the model without re-ranking module reduces 2.49 ROUGE-1, 2.50 ROUGE-2, 2.13 ROUGE-L scores"

## Architecture Onboarding

- Component map: Sample Pairwise Ranking → Global Listwise Re-ranking → Generator
- Critical path: Sample Pairwise Ranking → Global Listwise Re-ranking → Generator (each stage must complete before the next can begin)
- Design tradeoffs:
  - Two-stage ranking vs single-stage: Two-stage reduces computational complexity but adds latency; single-stage would be simpler but infeasible for long meetings
  - Cross-encoder vs bi-encoder: Cross-encoder provides better accuracy but higher computational cost; bi-encoder would be faster but less accurate
  - Fixed top-k vs adaptive selection: Fixed top-k simplifies implementation but may miss relevant utterances; adaptive selection would be more flexible but harder to implement
- Failure signatures:
  - Low ROUGE scores despite high pairwise ranking accuracy: Generator may not be effectively using ranked utterances
  - High computational cost during pairwise ranking: Sample division may be too granular or utterance count too high
  - Re-ranking produces little improvement: Sample pairwise ranking may already be producing good global ordering
- First 3 experiments:
  1. Verify pairwise ranking works: Test pairwise ranking on a small meeting with known utterance order, check if predicted order matches gold order
  2. Test re-ranking effectiveness: Compare top-5 utterances from pairwise ranking vs re-ranking using ROUGE scores against gold summary
  3. End-to-end integration test: Run full pipeline on a single meeting, verify generator receives correct top-k utterances and produces reasonable summary

## Limitations
- The framework relies on ROUGE scores as ground truth for ranking, which may not fully capture semantic relevance to queries
- Computational complexity is reduced but still significant for very long meetings with thousands of utterances
- Performance may degrade when utterances within samples are not comparable in quality

## Confidence
- High Confidence: The core mechanism of using pairwise and listwise ranking to improve query relevance is well-supported by experimental results
- Medium Confidence: The assumption that relative utterance quality is more informative than absolute scores for generator input selection is plausible but could benefit from ablation studies
- Medium Confidence: The sample-wise ranking approach for computational efficiency is reasonable, but optimal sample size needs further validation
- Low Confidence: The claim about top-k listwise re-ranking providing significant improvement needs more investigation across diverse meeting types
