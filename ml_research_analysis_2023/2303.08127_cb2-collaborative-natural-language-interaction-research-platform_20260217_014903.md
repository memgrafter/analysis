# CB2: Collaborative Natural Language Interaction Research Platform

## Quick Facts
- arXiv ID: 2303.08127
- Source URL: https://arxiv.org/abs/2303.08127
- Reference count: 3
- Primary result: CB2 is a multi-agent platform to study collaborative natural language interaction in a grounded task-oriented scenario with a 3D hexagonal grid environment and asymmetric agent observability.

## Executive Summary
CB2 is a research platform designed to study collaborative natural language interaction between agents in a grounded, task-oriented scenario. It features a procedurally generated 3D hexagonal grid environment where a leader agent with full overhead view provides natural language instructions to a follower agent with limited first-person view. The platform includes a Python server, Unity client, and Python headless client to support both human-human and human-agent interactions, enabling scalable studies of instruction following, communication emergence, and collaborative problem-solving.

## Method Summary
CB2 uses a procedurally generated 3D hexagonal grid environment where two agents (leader and follower) collaborate to complete tasks involving selecting valid sets of cards based on shape and color. The leader has full overhead observability while the follower has limited first-person view. Agents communicate via unidirectional natural language instructions. The platform supports both human-human interaction for data collection and human-agent interaction for evaluating learned models. A behavior cloning approach using a Decision Transformer architecture with HEXACONV embeddings is demonstrated for training follower agents from human-human interaction data.

## Key Results
- Platform provides tools for studying collaborative natural language interaction with asymmetric agent observability
- Includes Python server, Unity client, and Python headless client for scalable studies
- Demonstrates baseline instruction following agent trained via behavior cloning on human-human data

## Architecture Onboarding

- Component map: Python server -> Unity web client and Python headless client -> Data portal
- Critical path: Server generates map and initializes game state -> Players connect to server -> Server manages game state and player actions -> Server records game events and updates data portal
- Design tradeoffs:
  - Using asynchronous coroutines in the server allows for efficient handling of multiple concurrent connections but may introduce complexity in managing game state.
  - The Python headless client enables fast interaction for machine learning but may not provide all the features of the Unity client.
- Failure signatures:
  - High latency or server crashes may indicate issues with the asynchronous server architecture or insufficient compute resources.
  - Poor agent performance may indicate issues with the Python headless client or the machine learning model.
- First 3 experiments:
  1. Test the Python headless client by running a simple script that connects to the server and performs a series of actions.
  2. Deploy a basic machine learning model using the Python client and evaluate its performance in interacting with a human leader.
  3. Collect data from human-human interactions and use it to train a more advanced instruction following model.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does collaboration between agents affect the difficulty and nature of the symbol grounding problem compared to single-agent instruction following?
- Basis in paper: [explicit] The paper states that collaboration "dramatically alters both interaction and learning through joint presence and action" and introduces challenges like "constant distribution shift."
- Why unresolved: The paper discusses the potential effects but does not provide empirical evidence comparing symbol grounding in collaborative vs. single-agent scenarios.
- What evidence would resolve it: A controlled study comparing symbol grounding performance and learning dynamics in CB2's collaborative setting versus a single-agent version of the same environment.

### Open Question 2
- Question: What is the optimal balance between leader observability and follower autonomy for maximizing task completion and language richness in CB2?
- Basis in paper: [explicit] The paper introduces optional features like hidden card patterns and fog of war for the follower, and discusses the importance of leader planning due to asymmetries.
- Why unresolved: The paper presents these features as optional modifications but does not explore how different configurations affect performance and language.
- What evidence would resolve it: Systematic experiments varying the observability features and measuring task completion rates, language complexity, and instruction quality.

### Open Question 3
- Question: How can CB2 be used to study and mitigate language drift in emergent communication between agents?
- Basis in paper: [explicit] The paper mentions CB2 is "particularly well suited to study emergent communication" and discusses the potential to "address the language drift problem" by alternating between agent-agent and agent-human interactions.
- Why unresolved: While the paper identifies this as a potential application, it does not provide a concrete methodology or results for studying language drift.
- What evidence would resolve it: An experiment tracking language evolution over time in agent-agent interactions, comparing scenarios with and without human interaction, and measuring semantic consistency.
