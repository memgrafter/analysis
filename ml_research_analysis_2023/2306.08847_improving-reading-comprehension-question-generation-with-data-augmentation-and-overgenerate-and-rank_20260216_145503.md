# Improving Reading Comprehension Question Generation with Data Augmentation and Overgenerate-and-rank

## Quick Facts
- **arXiv ID**: 2306.08847
- **Source URL**: https://arxiv.org/abs/2306.08847
- **Reference count**: 20
- **Primary result**: Achieves 5% absolute ROUGE-L improvement over state-of-the-art on FairytaleQA dataset

## Executive Summary
This paper addresses the challenge of generating high-quality reading comprehension questions in educational contexts, where multiple valid questions can exist for the same context-answer pair. The authors propose a two-pronged approach: data augmentation to enrich training data with diverse, consistent questions using a large language model, and an overgenerate-and-rank method to select the most human-preferred question from multiple candidates. Experiments on the FairytaleQA dataset demonstrate significant improvements, particularly for implicit questions where answers are not explicitly stated in the text.

## Method Summary
The approach combines fine-tuning a Flan-T5-Large model with data augmentation and an overgenerate-and-rank pipeline. Data augmentation uses OpenAI Codex to generate diverse questions per context-answer pair, filtered by ROUGE consistency matching. The overgenerate-and-rank method produces multiple candidates using nucleus sampling or contrastive search, then ranks them using either perplexity or a BERT-based distribution matching model trained to align with human preferences as measured by ROUGE-L similarity to ground truth.

## Key Results
- 5% absolute improvement in ROUGE-L over previous state-of-the-art on FairytaleQA
- Particularly effective on implicit questions where answers are not explicitly in the text
- Best performance achieved with distribution matching-based ranking over perplexity-based ranking
- Data augmentation shows benefits primarily for minority attribute types

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Data augmentation enriches training data with diverse questions that match the context-answer pair, improving the model's ability to generate varied question candidates.
- Mechanism: Large language model (Codex) generates multiple candidate questions per context-answer pair, which are then filtered using a consistency matching criterion (ROUGE similarity between generated and ground-truth answers) to ensure relevance.
- Core assumption: Generated questions can be effectively filtered for consistency without losing diversity, and the filtered set will improve model robustness.
- Evidence anchors:
  - [abstract]: "a data augmentation method that enriches the training dataset with diverse questions given the same context and answer"
  - [section]: "We first generate synthetic data, i.e., M = 4 diverse question candidates ... using the OpenAI Codex LM ... to first generate diverse questions for each context-answer pair and then filter out unsuitable questions with consistency matching"
  - [corpus]: Weak - no direct citation of Codex filtering methods in neighbors.
- Break condition: If the consistency threshold is too high, valid diverse questions are excluded; if too low, irrelevant questions are included, harming model training.

### Mechanism 2
- Claim: Overgenerate-and-rank enables selection of the most human-preferred question among multiple valid candidates by learning a ranking distribution aligned with human educator preferences.
- Mechanism: Multiple question candidates are generated (via nucleus sampling or contrastive search), then ranked either by perplexity (lower is better) or by a BERT-based model trained to minimize KL divergence between predicted scores and ROUGE-L scores relative to ground truth.
- Core assumption: The ranking model can learn a probability distribution over generated questions that correlates with human preference as measured by ROUGE-L similarity to ground truth.
- Evidence anchors:
  - [abstract]: "an overgenerate-and-rank method to select the best question from a pool of candidates"
  - [section]: "We propose an overgenerate-and-rank method which first overgenerates several question candidates ... We then rank these generated questions based on a criterion ... distribution matching-based ranking"
  - [corpus]: Weak - no direct mention of KL divergence ranking in neighbors.
- Break condition: If the ranking model overfits to ROUGE-L at the expense of linguistic quality, or if generated candidates are too homogeneous, ranking becomes ineffective.

### Mechanism 3
- Claim: Fine-tuning Flan-T5 (instead of vanilla T5 or GPT-2) leverages its instruction-tuned nature for better performance on question generation tasks.
- Mechanism: Flan-T5's pre-training on diverse QA/QG tasks gives it superior zero-shot and fine-tuning capabilities compared to base models not optimized for instruction following.
- Core assumption: Instruction tuning provides task-specific inductive biases that improve fine-tuning efficiency and final performance.
- Evidence anchors:
  - [section]: "We use a pre-trained Flan-T5-Large model ... We also tried using vanilla T5 and GPT-2 as our base LM which gave a comparable but lower performance, possibly because Flan-T5 is instruction fine-tuned on a large number of tasks relevant to both QA and QG."
  - [abstract]: "Built on top of a Flan-T5 fine-tuning backbone"
  - [corpus]: Weak - no explicit discussion of Flan-T5 vs T5/GPT-2 in neighbors.
- Break condition: If the instruction tuning bias does not align with the task distribution, performance gains may not materialize.

## Foundational Learning

- Concept: Consistency matching via ROUGE similarity between generated and reference answers.
  - Why needed here: Ensures that synthetically generated questions are valid and answerable with the given answer, preventing noise in the augmented dataset.
  - Quick check question: If a generated question's answer has ROUGE-1 F1 score of 0.3 with the ground-truth answer, should it be included when the threshold is 0.5? (Answer: No.)

- Concept: KL divergence minimization for distribution matching in ranking.
  - Why needed here: Aligns the model's predicted ranking distribution with human preference distribution (ROUGE-L scores), improving selection of high-quality questions.
  - Quick check question: In distribution matching, does minimizing KL divergence encourage higher scores for questions with higher ROUGE-L similarity to ground truth? (Answer: Yes.)

- Concept: Nucleus sampling for diverse text generation.
  - Why needed here: Generates varied question candidates instead of repetitive, high-probability outputs, increasing the chance of finding human-preferred questions.
  - Quick check question: Does nucleus sampling with p=0.9 allow lower-probability tokens to be sampled compared to p=0.5? (Answer: Yes.)

## Architecture Onboarding

- Component map:
  - Base QG model: Flan-T5-Large fine-tuned on (context, answer) → question
  - Data augmentation pipeline: Codex (in-context prompting) → ROUGE filtering → augmented dataset
  - Ranking model: ConvBERT fine-tuned to predict scores minimizing KL divergence to ROUGE-L distribution
  - Decoder strategies: Nucleus sampling (p=0.9) and contrastive search (top-k=4, alpha=0.6) for candidate generation

- Critical path:
  1. Fine-tune Flan-T5 on original FairytaleQA training set
  2. Generate synthetic questions using Codex for minority attributes
  3. Filter synthetic questions via consistency matching
  4. Fine-tune Flan-T5 on augmented dataset (weight λ=0.8 for human, 0.2 for synthetic)
  5. Generate K=10 candidates per test sample using nucleus or contrastive search
  6. Rank candidates using perplexity or trained ranking model
  7. Select top-ranked question as final output

- Design tradeoffs:
  - Diversity vs. quality in data augmentation: Higher diversity may introduce noise; lower diversity may not improve robustness
  - Ranking method choice: Perplexity-based is simpler but may not capture human preference; distribution matching is more aligned but requires extra training
  - Decoding strategy: Nucleus sampling ensures diversity; contrastive search balances diversity and quality but may be computationally heavier

- Failure signatures:
  - Poor ROUGE-L improvement: Likely due to ineffective data augmentation or poor ranking model generalization
  - High variance in generated question quality: May indicate inconsistency in filtering threshold or base model instability
  - Overfitting to synthetic data: Model may generate unnatural questions not aligned with human style

- First 3 experiments:
  1. Fine-tune Flan-T5 on original FairytaleQA and evaluate ROUGE-L; compare to BART baseline
  2. Implement data augmentation for minority attributes only; fine-tune and evaluate; compare to step 1
  3. Add overgenerate-and-rank (perplexity-based) to step 2; evaluate; compare to step 2

## Open Questions the Paper Calls Out
- What is the optimal number of synthetic questions (M) to generate for each context-answer pair in the data augmentation method?
- How does the performance of the data augmentation method change when using different large language models for synthetic question generation?
- What is the impact of using different ranking criteria beyond perplexity and distribution matching for the overgenerate-and-rank method?

## Limitations
- The exact implementation details of consistency matching and ranking model parameters are underspecified
- Potential biases introduced by using OpenAI Codex for synthetic data generation are not addressed
- The ranking model's ability to capture human preference may be limited as ROUGE-L doesn't fully represent educational quality

## Confidence
- **High Confidence**: The effectiveness of the Flan-T5 base model for question generation, supported by direct comparison with T5 and GPT-2 baselines showing lower performance
- **Medium Confidence**: The improvement from data augmentation, as the filtering mechanism is well-defined but the impact of synthetic data quality on final performance is not thoroughly validated
- **Low Confidence**: The ranking model's ability to capture human preference, given that ROUGE-L may not fully represent educational quality and the training procedure lacks details on hyperparameter tuning

## Next Checks
1. Implement the two-stage ROUGE filtering process with varying thresholds (0.4, 0.5, 0.6) and measure the impact on synthetic data quality and downstream model performance to determine optimal threshold settings
2. Train the ConvBERT ranking model with and without the distribution matching objective, comparing perplexity-based vs KL divergence-based ranking performance across different decoding strategies to isolate the contribution of each ranking method
3. Evaluate the complete pipeline (data augmentation + ranking) on a held-out subset of FairytaleQA with different question attributes (e.g., focusing on implicit vs explicit questions) to assess robustness and identify potential overfitting to specific question types
