# SemiMemes: A Semi-supervised Learning Approach for Multimodal Memes Analysis

## Quick Facts
- **arXiv ID**: 2304.00020
- **Source URL**: https://arxiv.org/abs/2304.00020
- **Reference count**: 29
- **Primary result**: SemiMemes achieves up to 0.039 higher F1-score and 0.009 higher AUROC than state-of-the-art models on harmful meme detection while using significantly fewer parameters.

## Executive Summary
This paper proposes SemiMemes, a semi-supervised multimodal learning approach for sentiment analysis of harmful content in memes. The method addresses the challenge of detecting harmful memes that require understanding both images and text, while reducing the need for extensive manual labeling. The approach introduces CROM-AE, a cross-modal auto-encoder pre-trained on unlabeled data, and RA W-N-COOK, a supervised model that combines raw CLIP features with learned latent representations. Experiments on two datasets—Multimedia Automatic Misogyny Identification and Hateful Memes—demonstrate that SemiMemes outperforms state-of-the-art multimodal supervised and semi-supervised models.

## Method Summary
SemiMemes uses a two-stage approach: first, CROM-AE (Cross Modality Auto Encoder) is pre-trained unsupervised on unlabeled data to learn cross-modal alignment between image and text features. The model consists of two auto-encoders that reconstruct each modality from the other, learning latent representations in the process. In the second stage, RA W-N-COOK (Raw and Cooked Features Classification Model) combines raw CLIP features with the "cooked" latent representations from CROM-AE for classification. The method leverages pre-trained CLIP models for feature extraction and is evaluated across three labeling scenarios (5%, 10%, and 30% labeled data) on two harmful content detection datasets.

## Key Results
- Achieves up to 0.039 higher F1-score than state-of-the-art multimodal supervised models on MAMI dataset
- Achieves up to 0.009 higher AUROC than state-of-the-art multimodal semi-supervised models on Hateful Memes dataset
- Uses significantly fewer parameters compared to baseline models
- Demonstrates effectiveness across three different labeling ratios (5%, 10%, and 30% labeled data)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: CROM-AE learns cross-modal alignment that captures semantic correlations between image and text features.
- Mechanism: By training AEimage to reconstruct Ftext from Fimage and vice versa, the encoders learn to map each modality's CLIP features into a shared latent space where semantically related concepts are aligned.
- Core assumption: The CLIP features already encode meaningful semantic relationships that can be leveraged for cross-modal reconstruction.
- Evidence anchors:
  - [section]: "The latent representations of images are driven by the distribution of the remaining text p(text), which may contain the information of the posterior distribution p(y|text)"
  - [abstract]: "Building on the insights gained from Contrastive Language-Image Pre-training, which is an effective multimodal learning technique"
- Break condition: If CLIP features are not semantically rich or if cross-modal correlations are too weak, reconstruction will fail and learned latent features will be uninformative.

### Mechanism 2
- Claim: Combining raw CLIP features with "cooked" (CROM-AE learned) features provides complementary information that improves classification.
- Mechanism: The classification model fuses both original CLIP features (capturing pre-trained knowledge) and CROM-AE latent features (capturing cross-modal semantic structure), allowing the model to benefit from both sources.
- Core assumption: The cooked features contain additional useful information not present in raw CLIP features, and their combination is more informative than either alone.
- Evidence anchors:
  - [section]: "our intuition is that Zimage, and Ztext are informative features because they were learned on a large unlabeled dataset"
  - [section]: "Therefore, we decided to fuse Zimage and Ztext (cooked features) with the original features outputted from CLIP Fimage,Ftext (raw features)"
- Break condition: If cooked features add noise rather than signal, or if the fusion mechanism doesn't properly integrate the two feature types, performance may degrade.

### Mechanism 3
- Claim: Semi-supervised pre-training on unlabeled data reduces the need for labeled examples while maintaining or improving performance.
- Mechanism: By first training CROM-AE on unlabeled data to learn cross-modal representations, the subsequent supervised classification can leverage this pre-trained knowledge, requiring fewer labeled examples to achieve good performance.
- Core assumption: The unlabeled data distribution is similar enough to the labeled data distribution that pre-training provides useful inductive bias.
- Evidence anchors:
  - [abstract]: "achieving up to 0.039 higher F1-score... with significantly fewer parameters"
  - [abstract]: "make use of the resourceful unlabeled data"
- Break condition: If the unlabeled data is too different from labeled data, or if there's insufficient unlabeled data, pre-training may not provide meaningful benefit.

## Architecture Onboarding

- Component map:
  (image, text) pairs -> CLIP encoders -> CROM-AE pre-training -> Feature fusion -> Classification -> Prediction

- Critical path:
  CLIP encoding → CROM-AE pre-training (unsupervised) → Feature fusion → Classification → Prediction

- Design tradeoffs:
  - Using pre-trained CLIP features vs training from scratch: Leverages existing knowledge but may limit adaptation
  - Freezing CROM-AE encoders vs fine-tuning: Preserves pre-trained knowledge but may miss task-specific improvements
  - Combining raw and cooked features vs using only one type: Provides complementary information but increases complexity

- Failure signatures:
  - Poor reconstruction in CROM-AE indicates weak cross-modal correlations
  - Minimal performance difference between raw-only and combined features suggests cooked features add little value
  - Degradation when using unlabeled data suggests domain mismatch

- First 3 experiments:
  1. Train CROM-AE on unlabeled data and evaluate reconstruction quality (MSE between reconstructed and original features)
  2. Compare classification performance using only raw features vs only cooked features vs combined features
  3. Vary the ratio of labeled to unlabeled data to identify the point where semi-supervised approach stops providing benefits

## Limitations
- The approach assumes CLIP features already contain meaningful cross-modal semantic relationships, which may not hold for all meme types or domains
- Performance gains are demonstrated only on specific datasets (MAMI and Hateful Memes) with particular labeling ratios, limiting generalizability
- The paper doesn't address potential domain shift between unlabeled pre-training data and labeled fine-tuning data

## Confidence
- **High confidence**: The architectural design and training procedure are clearly specified with detailed implementation steps
- **Medium confidence**: The claim that CROM-AE learns useful cross-modal representations relies on assumptions about CLIP feature quality
- **Low confidence**: The scalability of the approach to larger datasets or more complex multimodal tasks isn't demonstrated

## Next Checks
1. **Cross-domain validation**: Test SemiMemes on memes from different cultural contexts or social media platforms to assess robustness to domain shift
2. **Ablation of CROM-AE contributions**: Systematically remove CROM-AE and test with raw CLIP features only, then with alternative cross-modal alignment methods
3. **Scaling study**: Evaluate performance as the amount of unlabeled data increases beyond the scenarios tested, and determine if there's a point of diminishing returns
