# Harris Hawks Feature Selection in Distributed Machine Learning for Secure IoT Environments

## Quick Facts
- arXiv ID: 2302.12205
- Source URL: https://arxiv.org/abs/2302.12205
- Reference count: 20
- Primary result: Up to 99.9% F-measure on IoT botnet detection using HHO-RWN feature selection

## Executive Summary
This paper proposes a feature selection model for IoT botnet attack detection using Harris Hawks Optimization (HHO) combined with Random Weight Network (RWN). The approach simultaneously optimizes feature selection and RWN architecture (hidden neuron count) through a wrapper-based method. Experiments on N-BaIoT and Phishing legitimate datasets demonstrate the method achieves up to 99.9% F-measure, outperforming baseline classifiers. The framework is evaluated under both centralized and distributed machine learning paradigms, with distributed ML maintaining competitive performance while preserving data privacy.

## Method Summary
The method combines HHO for wrapper-based feature selection with RWN as the base classifier. HHO encodes solutions where binary bits indicate feature selection and hidden neuron count simultaneously. The fitness function optimizes classification error, feature count, and model complexity together. RWN uses random input weights and hidden biases with analytical output weight computation via Moore-Penrose pseudo-inverse. The framework is applied under both centralized training (full dataset) and distributed ML (local training on IoT devices) to compare performance while preserving privacy.

## Key Results
- Achieves up to 99.9% F-measure on IoT botnet detection
- Outperforms baseline classifiers (KNN, SVM, Adaboost, DT) in accuracy, recall, precision, and F-measure
- Distributed ML model maintains competitive performance against centralized ML while preserving data privacy
- Successfully applies to two benchmark datasets: N-BaIoT (9 devices, 115 features, 7M instances) and Phishing legitimate (48 features, 10K instances)

## Why This Works (Mechanism)

### Mechanism 1
HHO optimizes both feature selection and hidden neuron count in RWN simultaneously by encoding both objectives in the same solution space. The joint encoding allows the fitness function to balance classification accuracy, feature sparsity, and model complexity together.

### Mechanism 2
Distributed ML preserves privacy while maintaining detection performance by training local models on IoT devices without transmitting raw data to a central server. Each device trains on its own subset, avoiding the privacy risks of centralized data aggregation.

### Mechanism 3
RWN's random weights and analytical output computation enable fast training and good generalization. Input weights and hidden biases are randomly initialized while output weights are computed via Moore-Penrose pseudo-inverse, avoiding slow gradient descent and reducing local minima risks.

## Architecture Onboarding

- Component map: Data preprocessing -> HHO search -> RWN training -> Evaluation (accuracy, recall, precision, F-measure)
- Critical path: 1) Preprocess datasets, 2) Encode solutions (first L bits = feature mask, last M bits = hidden neuron count), 3) Run HHO for 100 iterations, population size 200, 4) Train RWN with selected features and neuron count, 5) Evaluate on test set; track F-measure
- Design tradeoffs: Larger hidden neuron range increases representational power but increases search space; higher population size improves diversity but increases runtime; more training iterations improve convergence but risk overfitting
- Failure signatures: Convergence curves plateau early (exploration insufficient), F-measure drops significantly in distributed mode (non-IID data partitions), high variance across 30 runs (stochastic instability)
- First 3 experiments: 1) Run HHO-RWN on centralized training set, record convergence and best F-measure, 2) Run HHO-RWN on distributed subsets, compare F-measure vs centralized, 3) Replace RWN with KNN baseline, repeat both centralized and distributed runs to confirm claimed improvement

## Open Questions the Paper Calls Out

### Open Question 1
How does the performance of the HHO-RWN approach scale when applied to larger IoT datasets with more devices and features? The paper uses relatively small datasets (N-BaIoT has ~7 million instances, Phishing has 10,000 instances), so performance on truly large-scale IoT data remains unknown.

### Open Question 2
How does the HHO-RWN approach compare to federated learning frameworks in terms of privacy preservation and detection accuracy? The paper only uses distributed ML but not federated learning specifically, so direct comparison between these privacy-preserving approaches is missing.

### Open Question 3
What is the optimal population size and iteration count for HHO-RWN when balancing detection accuracy and computational efficiency? The paper uses fixed parameters (200 population, 100 iterations) without systematic analysis of how these affect performance and efficiency.

## Limitations
- Exact RWN implementation details and distributed training setup are not fully specified, making exact reproduction difficult
- Claim of up to 99.9% F-measure is based on specific datasets that may not generalize to all IoT attack scenarios
- Distributed ML performance comparison assumes balanced, non-IID data distributions which may not hold in practice
