# Iteratively Improving Biomedical Entity Linking and Event Extraction via Hard Expectation-Maximization

## Quick Facts
- arXiv ID: 2305.14645
- Source URL: https://arxiv.org/abs/2305.14645
- Reference count: 24
- Primary result: Joint framework achieves 3.12% F1 gain for event extraction and 3.73% accuracy gain for entity linking on biomedical datasets

## Executive Summary
This paper addresses the challenge of jointly performing biomedical entity linking and event extraction, which are crucial for understanding and retrieving information from biomedical texts. The authors propose a joint framework that leverages the intrinsic relationship between these two tasks to iteratively improve their performance. They treat event structures and entity references as latent variables and employ a hard Expectation-Maximization (EM) style learning strategy. This involves (1) predicting missing variables for each partially annotated dataset using current models, and (2) updating model parameters on the augmented pseudo-completed datasets. Experiments on the Genia 2011 and BC4GO datasets demonstrate significant improvements in both tasks compared to strong baselines.

## Method Summary
The approach combines two task-specific models: JOINT 4E-EL for entity linking enhanced with event information, and JOINT 4E-EE for event extraction enhanced with entity knowledge. The method employs hard EM-style iterative training where each model generates pseudo-labels for the other task, creating augmented datasets for parameter updates. The process alternates between an E-step (generating pseudo-labels) and an M-step (updating model parameters) for multiple rounds. The entity linking model incorporates event argument roles and types into the input sequence, while the event extraction model integrates entity definitions from knowledge bases. Both models are initialized with base models trained on individual tasks before entering the iterative training loop.

## Key Results
- JOINT 4E-EL improves entity linking accuracy by 3.73% over baseline
- JOINT 4E-EE improves event extraction F1 score by 3.12% over baseline
- Iterative training shows progressive improvement across multiple rounds
- Ablation studies confirm the importance of incorporating cross-task information

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Joint training with event knowledge improves entity linking by providing structural context that disambiguates biomedical concepts.
- Mechanism: Event structures (triggers and argument roles) provide precise contextual cues that narrow down the pool of candidate biomedical concepts for a given entity mention. When JOINT 4E-EL incorporates event information (argument role and event type) into the input sequence, it uses this structural context to disambiguate the entity mention's meaning.
- Core assumption: The structural context from event extraction (argument roles and event types) contains discriminative information that helps distinguish between semantically similar biomedical concepts.
- Evidence anchors:
  - [abstract]: "entity linking disambiguates the biomedical concepts by referring to external knowledge bases and the domain knowledge further provides additional clues to understand and extract the biological processes"
  - [section 4.2]: "we inject event information into the input sequence... Each entity only participates in a single event τi with a unique argument role αi (if any). We insert the name of the argument role αi after the tokens of mi in the original text xL and append the name of the event type τi at the end of the sentence xL"
  - [corpus]: Weak evidence - corpus shows related work in biomedical entity linking but doesn't directly validate this specific mechanism
- Break condition: If the event structures contain ambiguous or noisy information, or if the argument roles don't provide meaningful disambiguation cues for specific entity types.

### Mechanism 2
- Claim: Joint training with entity knowledge improves event extraction by providing domain-specific semantic information that disambiguates entity mentions in biological contexts.
- Mechanism: Entity definitions from knowledge bases (like GO) provide domain-specific semantic information that helps the event extraction model understand the biological function and context of entities, leading to more accurate trigger and argument identification.
- Core assumption: The semantic definitions of biomedical entities in knowledge bases contain relevant information about their biological functions and relationships that can inform event extraction.
- Evidence anchors:
  - [abstract]: "entity linking maps the mentions in the text to biomedical concepts in external knowledge bases and provides additional domain knowledge and semantic information (e.g., the definitions in Gene Ontology) for extracting biological processes"
  - [section 4.1]: "we propose JOINT 4E-EE, a dual encoder framework that incorporates the external domain knowledge of the given entities by the base entity linking model such that it can better extract biological processes from unstructured texts"
  - [corpus]: Weak evidence - corpus shows related work in knowledge-enhanced NLP but doesn't directly validate this specific mechanism
- Break condition: If the entity definitions are too generic, too specific, or not relevant to the biological processes being described in the text.

### Mechanism 3
- Claim: Hard-EM style iterative training progressively improves both tasks by alternately estimating missing variables and updating model parameters on pseudo-completed datasets.
- Mechanism: The iterative process alternates between estimating latent variables (pseudo-labels for one task using the other task's model) and updating parameters on augmented datasets. This creates a positive feedback loop where improvements in one task benefit the other.
- Core assumption: The pseudo-labels generated by each model are sufficiently accurate to serve as training signals for the other model, and the iterative process converges to better solutions than individual training.
- Evidence anchors:
  - [abstract]: "updating the two task-specific models in a hard Expectation–Maximization (EM) fashion: (1) predicting the missing variables for each partially annotated dataset based on the current two task-specific models, and (2) updating the parameters of each model on the corresponding pseudo completed dataset"
  - [section 4.3]: "We formulate our Hard EM style iterative training algorithm... we first estimate missing variables (i.e., predict pseudo labels) for each partially annotated dataset, and then update the parameters of both models on the datasets that are augmented by pseudo labels"
  - [corpus]: Weak evidence - corpus shows EM-style training in other domains but doesn't directly validate this specific mechanism
- Break condition: If the pseudo-labels are too noisy or incorrect, the iterative process could diverge or get stuck in poor local optima.

## Architecture Onboarding

- Component map:
  - JOINT 4E-EL: Entity linking model enhanced with event information (argument roles and event types)
  - JOINT 4E-EE: Event extraction model enhanced with entity knowledge (definitions from knowledge bases)
  - Base-EL: Baseline entity linking model without event information
  - Base-EE: Baseline event extraction model without entity knowledge
  - Knowledge base (GO, UMLS): Source of entity definitions and candidate concepts
  - Iterative training loop: Hard-EM style alternating parameter updates

- Critical path:
  1. Preprocess datasets and retrieve candidate concepts
  2. Train base models on individual tasks
  3. Enter iterative training loop:
     - E-step: Generate pseudo-labels for one task using the other task's model
     - M-step: Update parameters on augmented datasets
  4. Evaluate performance on development/test sets

- Design tradeoffs:
  - Hard vs. soft EM: Hard EM selects most likely pseudo-labels (more stable but potentially less informative)
  - Number of training rounds: More rounds may improve performance but risk overfitting or noise accumulation
  - Candidate retrieval strategy: Retrieving more candidates may improve coverage but increase computational cost

- Failure signatures:
  - Performance plateaus or decreases after certain training rounds
  - Pseudo-labels become too noisy or inconsistent
  - One task improves while the other degrades
  - Candidate retrieval fails to include true target entities

- First 3 experiments:
  1. Verify baseline model performance on individual tasks
  2. Test single round of joint training (E-step + M-step) and compare to baselines
  3. Test multi-round joint training and monitor performance changes across rounds

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of the joint framework vary when using different knowledge bases (e.g., UMLS instead of Gene Ontology) for biomedical entity linking?
- Basis in paper: [explicit] The paper mentions that the framework was tested on NCBI Disease corpus with UMLS and achieved promising results.
- Why unresolved: The paper only provides results for one additional dataset (NCBI Disease) and knowledge base (UMLS). It's unclear how the framework would perform with other knowledge bases or in different biomedical domains.
- What evidence would resolve it: Conducting experiments using various knowledge bases (e.g., UniProt, EMBL) and testing the framework on diverse biomedical datasets from different domains would provide a comprehensive understanding of its generalizability.

### Open Question 2
- Question: What is the impact of increasing the number of candidate concepts retrieved for each entity mention on the performance of the joint framework?
- Basis in paper: [explicit] The paper mentions that 30 candidates were retrieved for each mention, and increasing this number did not significantly improve performance.
- Why unresolved: The paper does not explore the effects of retrieving a larger number of candidates or the optimal number of candidates for different entity types or domains.
- What evidence would resolve it: Conducting experiments with varying numbers of retrieved candidates (e.g., 50, 100) for different entity types and domains would help determine the optimal number of candidates and its impact on performance.

### Open Question 3
- Question: How does the joint framework handle entity mentions that have multiple correct mappings in the knowledge base?
- Basis in paper: [explicit] The paper mentions that the mappings between entity mentions and entities in the Gene Ontology knowledge base are not surjective, meaning each entity mention can be mapped to multiple entities.
- Why unresolved: The paper does not provide details on how the framework deals with mentions that have multiple correct mappings or how it determines the most appropriate mapping.
- What evidence would resolve it: Analyzing the framework's performance on entity mentions with multiple correct mappings and comparing it to other methods that handle such cases would provide insights into its effectiveness in resolving ambiguity.

## Limitations
- Limited analysis of pseudo-label quality across training rounds
- Reliance on Gene Ontology knowledge base may limit generalizability to other biomedical domains
- Assumption that event structures provide sufficient discriminative information for entity disambiguation may not hold for all entity types

## Confidence
- **High confidence** in the core experimental results showing improvements over baselines on the Genia 2011 and BC4GO datasets
- **Medium confidence** in the proposed mechanism explaining why joint training improves both tasks, as the evidence is largely circumstantial from ablation studies
- **Medium confidence** in the generalizability of the approach to other biomedical entity linking and event extraction datasets or domains

## Next Checks
1. **Pseudo-label quality analysis**: Analyze the accuracy and consistency of pseudo-labels generated during the E-step across multiple training rounds. Compare the pseudo-label quality to the final model performance to establish correlation and identify potential failure modes.

2. **Cross-domain generalization**: Test the framework on a different biomedical domain (e.g., clinical texts or drug discovery literature) with different entity types and event structures to evaluate whether the proposed mechanisms generalize beyond the Genia/BC4GO domains.

3. **Alternative knowledge base evaluation**: Replace Gene Ontology with UMLS or other biomedical knowledge bases to assess whether the approach's effectiveness depends on the specific knowledge base structure and coverage, or whether the core mechanisms are knowledge base agnostic.
