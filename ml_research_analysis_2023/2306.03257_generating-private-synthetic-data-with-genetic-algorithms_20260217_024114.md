# Generating Private Synthetic Data with Genetic Algorithms

## Quick Facts
- arXiv ID: 2306.03257
- Source URL: https://arxiv.org/abs/2306.03257
- Reference count: 40
- Primary result: Genetic algorithm achieves better accuracy on non-differentiable queries than first-order optimization methods while maintaining comparable performance on differentiable queries

## Executive Summary
This paper introduces PRIVATE-GSD, a genetic algorithm for generating private synthetic data that matches statistical queries on mixed-type data (both discrete and real-valued attributes). Unlike prior methods that rely on first-order optimization and require differentiable objectives, PRIVATE-GSD uses zeroth-order optimization through genetic operators (mutation and crossover) to directly optimize non-differentiable queries like halfspaces and prefix queries. Experiments on American Community Survey data show that PRIVATE-GSD outperforms the state-of-the-art RAP++ on non-differentiable queries while achieving comparable accuracy on differentiable ones like categorical and binary-tree marginals. The method also demonstrates strong performance in downstream machine learning tasks, though synthetic data for ML remains challenging.

## Method Summary
PRIVATE-GSD is a genetic algorithm that generates private synthetic data by evolving a population of candidate datasets to match statistical queries. The algorithm maintains an elite population of top-performing solutions and uses mutation and crossover operators to explore the search space. Unlike first-order methods that require relaxation of non-differentiable objectives, PRIVATE-GSD directly optimizes the original query without approximation. The algorithm operates under differential privacy constraints using zCDP composition across generations, with mutation and crossover rates tuned for computational efficiency and quick convergence.

## Key Results
- PRIVATE-GSD outperforms RAP++ on non-differentiable queries (prefix and halfspace) by avoiding relaxation-induced error
- Achieves comparable accuracy to first-order methods on differentiable queries like categorical and binary-tree marginals
- Demonstrates strong performance in downstream ML tasks despite the inherent challenges of synthetic data generation

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: PRIVATE-GSD can directly optimize non-differentiable queries like prefix and halfspace queries without relaxation.
- **Mechanism**: Uses zeroth-order genetic operators (mutation and crossover) to explore the synthetic dataset space, avoiding the need for differentiable surrogate objectives.
- **Core assumption**: The genetic operators can incrementally improve synthetic datasets even without gradient information.
- **Evidence anchors**: [abstract]: "PRIVATE-GSD uses zeroth-order optimization through genetic operators (mutation and crossover) to directly optimize non-differentiable queries like halfspaces and prefix queries."
- **Break condition**: If the elite population converges to a local minimum too early, the algorithm may fail to explore better solutions.

### Mechanism 2
- **Claim**: Genetic algorithm avoids error from relaxation that first-order methods incur.
- **Mechanism**: Directly optimizes the original non-differentiable objective rather than a differentiable surrogate, eliminating relaxation-induced error.
- **Core assumption**: The relaxation step in first-order methods introduces significant error compared to direct optimization.
- **Evidence anchors**: [abstract]: "their approach, RAP++, can directly optimize over a large class of statistical queries. However, their method induces additional error due to the relaxation of the original minimization problem."
- **Break condition**: If the genetic algorithm's exploration is too sparse, it may miss optimal regions of the search space.

### Mechanism 3
- **Claim**: Crossover operator significantly improves convergence rate by combining successful traits from elite solutions.
- **Mechanism**: Crossover selects two rows from the current best and an elite member, copying a feature value to create a new candidate that inherits good properties.
- **Core assumption**: Combining partial solutions from different elites can create better solutions than mutation alone.
- **Evidence anchors**: [section 4.2]: "The crossover operator plays an integral role in improving the convergence rate of PRIVATE-GSD. Figure 2 shows the convergence of the P RIVATE-GSD algorithm with and without the crossover operator."
- **Break condition**: If crossover rate is too high, it may disrupt good solutions by combining incompatible traits.

## Architecture Onboarding

- **Component map**: Query processing module -> Genetic algorithm core -> Privacy budget tracker -> Evaluation engine
- **Critical path**: Initialize population → Evaluate fitness → Select elites → Apply mutation/crossover → Update population → Check convergence → Return best solution
- **Design tradeoffs**:
  - Population size vs computational cost: Larger populations explore more but increase runtime
  - Mutation vs crossover rates: Balance between local improvement and global recombination
  - Early stopping vs full convergence: Trade accuracy for runtime efficiency
- **Failure signatures**:
  - Stagnant elite population: Indicates premature convergence
  - High variance in fitness scores: Suggests poor selection pressure
  - Slow improvement over generations: May indicate inappropriate mutation/crossover rates
- **First 3 experiments**:
  1. Run PRIVATE-GSD on synthetic data with known ground truth to verify it can match simple marginals
  2. Compare convergence rates with and without crossover operator on prefix queries
  3. Test different population sizes (Pmut, Pcross) on the same dataset to find optimal configuration

## Limitations
- Limited evaluation to a single dataset (American Community Survey) and specific query types
- Genetic algorithm's convergence properties on other data distributions and query families remain unverified
- No evidence provided about performance on more complex query families or in higher-dimensional settings

## Confidence
- Claim about handling non-differentiable queries without relaxation: Medium
- Claim about crossover operator significantly improving convergence: Low
- Claim about broad applicability to any statistical query type: Low
