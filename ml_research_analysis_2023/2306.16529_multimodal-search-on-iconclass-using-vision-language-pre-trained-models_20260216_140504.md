# Multimodal Search on Iconclass using Vision-Language Pre-Trained Models

## Quick Facts
- arXiv ID: 2306.16529
- Source URL: https://arxiv.org/abs/2306.16529
- Reference count: 2
- Key outcome: A multimodal search engine for Iconclass using CLIP retrieves broader, more exhaustive results than TF-IDF text search, favoring recall over precision.

## Executive Summary
This paper presents a multimodal search engine for Iconclass, an iconography classification system, that leverages OpenAI's CLIP vision-language model to retrieve Iconclass concepts using both visual and textual queries. The system indexes approximately 500,000 annotated images and uses CLIP embeddings to find semantically related Iconclass notations rather than relying on exact keyword matching. A small user study (10 participants) compared this approach to traditional TF-IDF search, finding no marked preference but noting that when CLIP was preferred, it was primarily due to the exhaustiveness of results.

## Method Summary
The system uses OpenAI's CLIP model to encode both images and text queries into a shared embedding space, then performs k-nearest neighbor search using a Faiss index to retrieve the top-K most similar annotated images. Instead of querying the Iconclass hierarchy directly, users search through a database of ~500,000 annotated images from Arkyves, with the system returning associated Iconclass notations sorted by frequency. The approach aims to leverage semantic similarity beyond exact keyword matching, using human-curated annotations as a proxy for expert knowledge.

## Key Results
- CLIP-based search retrieves broader, more exhaustive result sets compared to TF-IDF, favoring recall over precision
- User preference study (n=10) showed no marked preference between multimodal and TF-IDF search
- When multimodal search was preferred, it was mainly due to the exhaustiveness of results rather than pinpoint accuracy
- System successfully handles both visual and textual queries through the same semantic embedding framework

## Why This Works (Mechanism)

### Mechanism 1
- Claim: CLIP's vision-language embeddings enable semantic similarity retrieval beyond exact keyword matching.
- Mechanism: CLIP encodes both images and text into a shared embedding space, so semantically related items appear close in the embedding space even without exact textual overlap.
- Core assumption: The CLIP model's pre-training on 400M image-caption pairs successfully captures cross-modal semantic relationships relevant to iconography.
- Evidence anchors: [abstract] "The novelty of this system is the use of a pre-trained vision-language model, namely CLIP, to retrieve and explore Iconclass concepts using visual or textual queries."
- Break condition: If the CLIP model's training corpus is too culturally narrow or biased, embeddings for iconography-specific concepts may not align well, leading to irrelevant retrieval results.

### Mechanism 2
- Claim: Using annotated images as a proxy query target improves accessibility for non-expert users.
- Mechanism: Instead of querying the Iconclass hierarchy directly, the system searches annotated images and derives relevant Iconclass notations from those annotations, indirectly leveraging expert curation.
- Core assumption: The annotations in the image database are sufficiently accurate and representative of Iconclass concepts to guide retrieval.
- Evidence anchors: [section 2] "It is important to note that a user does not directly query the complete Iconclass hierarchy, but a set of annotated images..."
- Break condition: If the image database is incomplete or annotations are noisy, the system may retrieve misleading or overly broad notation sets, reducing precision.

### Mechanism 3
- Claim: CLIP-based search retrieves broader, more exhaustive result sets compared to TF-IDF, favoring recall over precision.
- Mechanism: By measuring similarity in embedding space rather than term overlap, CLIP retrieves notations associated with visually and semantically related images, not just exact matches.
- Core assumption: Users benefit more from discovering related concepts than from pinpoint precision in iconography classification tasks.
- Evidence anchors: [section 3] "when multimodal search was preferred, it was mainly due to exhaustiveness of the results."
- Break condition: If users require high precision for specific classification tasks, the broader recall could overwhelm them with irrelevant notations, making TF-IDF preferable.

## Architecture Onboarding

- Component map: User Query -> CLIP Encoder -> Faiss Index -> Images-DB -> Iconclass Notations
- Critical path:
  1. User submits image or text query
  2. CLIP encoder generates embedding
  3. Faiss index retrieves top-K similar images
  4. System returns associated Iconclass notations sorted by frequency
- Design tradeoffs:
  - Exhaustiveness vs. precision: CLIP favors broader recall, potentially overwhelming users
  - Model dependency: System relies on CLIP's pre-trained embeddings, limiting adaptability without fine-tuning
  - Annotation quality: Retrieval quality depends heavily on the accuracy of the image annotations
- Failure signatures:
  - Retrieval of unrelated notations → embedding space misalignment
  - Missing relevant notations → incomplete or biased image database
  - Slow responses → Faiss index not properly optimized or too large for hardware
- First 3 experiments:
  1. Query "street" and compare CLIP results to TF-IDF for precision vs. recall balance
  2. Submit an image of a dog and verify if notations for "dog" and related objects appear
  3. Vary K (number of nearest neighbors) to see how retrieval breadth affects usability

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What are the limitations of CLIP-based results in the Iconclass multimodal search engine, and how can they be objectively evaluated using ground-truths?
- Basis in paper: [explicit] The paper states that "the quality of CLIP-based results is still to be adequately estimated by using objective ground-truths."
- Why unresolved: The paper acknowledges that the quality of CLIP-based results has not been adequately evaluated, and it is unclear what specific limitations exist and how to objectively measure them.
- What evidence would resolve it: Conducting an evaluation study with a diverse set of queries and ground-truth annotations to measure the accuracy, precision, and recall of CLIP-based results compared to traditional text-based search methods.

### Open Question 2
- Question: How can the multimodal search engine be improved to combine results from different search systems, such as visual similarity and word similarity, to provide more comprehensive and accurate search results?
- Basis in paper: [explicit] The paper mentions that "the possibility to combine results coming from different search systems for Iconclass, e.g. both from visual similarity and word similarity, can and will be taken in consideration."
- Why unresolved: While the paper acknowledges the potential of combining results from different search systems, it does not provide specific details on how this can be achieved or what benefits it would bring to the search engine's performance.
- What evidence would resolve it: Developing and implementing a hybrid search algorithm that combines visual and textual similarity measures, and evaluating its performance through user studies and objective metrics to determine its effectiveness in improving search results.

### Open Question 3
- Question: What new features and services can be introduced to enhance the user experience and accessibility of the Iconclass multimodal search engine?
- Basis in paper: [explicit] The paper mentions that "new features and services for Iconclass users will be introduced, such as the publication of a SPARQL endpoint to enable external web services to exploit the new similarity-based search."
- Why unresolved: While the paper mentions the introduction of a SPARQL endpoint, it does not provide details on other potential features and services that could be developed to improve the user experience and accessibility of the search engine.
- What evidence would resolve it: Conducting user research and usability studies to identify pain points and areas for improvement in the current search engine, and developing and implementing new features and services based on user feedback and needs assessments.

## Limitations
- Small-scale user evaluation (n=10) with unclear selection criteria and no detailed demographic reporting
- System relies on a single pre-trained model (CLIP) without exploring fine-tuning options or comparing alternative VLMs
- Performance fundamentally bounded by quality and coverage of image annotations in the database

## Confidence
- CLIP semantic retrieval mechanism: High
- Exhaustiveness advantage: Medium
- Practical usability: Low
- Annotation quality impact: High
