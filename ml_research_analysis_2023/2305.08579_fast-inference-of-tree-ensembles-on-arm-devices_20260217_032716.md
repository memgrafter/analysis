# Fast Inference of Tree Ensembles on ARM Devices

## Quick Facts
- arXiv ID: 2305.08579
- Source URL: https://arxiv.org/abs/2305.08579
- Reference count: 19
- One-line primary result: Adapted QuickScorer algorithms achieve up to 9.4x speedup on ARM devices with quantized models outperforming floating-point in speed

## Executive Summary
This paper addresses the challenge of efficiently deploying tree ensemble models on resource-constrained IoT devices with ARM processors. The authors adapt the QuickScorer algorithm family from Intel AVX to ARM NEON instruction sets, enabling SIMD acceleration for tree traversal. They also explore fixed-point quantization to further improve inference speed on ARM CPUs that often lack hardware floating-point units. Experimental results demonstrate significant speedups (up to 9.4x) compared to baseline implementations, with quantized models consistently outperforming floating-point models while maintaining classification accuracy.

## Method Summary
The authors adapt QuickScorer, V-QuickScorer, and RapidScorer algorithms from Intel AVX to ARM NEON instruction sets for tree ensemble inference. They implement fixed-point quantization using 16-bit integers with a scaling constant (2^15) to leverage faster integer operations on ARM devices. The method involves training Random Forest models (1024 trees, 32-64 leaves) on various datasets (Adult, EEG, Fashion, Magic, MNIST), then deploying them on ARM hardware (Raspberry Pi 3 Model B+, Odroid-XU4). Performance is measured in terms of inference speed (µs per instance) and classification accuracy compared to baseline implementations.

## Key Results
- ARM NEON adaptation of QuickScorer variants achieves up to 9.4x speedup compared to baseline implementations
- Quantized models consistently outperform floating-point models in inference speed with minimal accuracy loss
- Algorithm choice (QuickScorer vs V-QuickScorer vs RapidScorer) significantly impacts performance depending on ARM device and forest configuration
- Fixed-point quantization is particularly effective for datasets with many unique node values like EEG

## Why This Works (Mechanism)

### Mechanism 1
Converting AVX tree ensemble traversal algorithms to ARM NEON enables SIMD acceleration on resource-constrained devices. The QuickScorer algorithm family exploits vectorized operations to evaluate multiple decision tree nodes in parallel. AVX provides 256-bit SIMD registers on Intel CPUs, whereas NEON provides 128-bit SIMD registers on ARM. By translating AVX intrinsics to NEON equivalents, the algorithm retains parallel processing capability but at reduced width, still delivering significant speedups. This relies on NEON providing equivalent primitive operations to AVX, allowing direct translation without algorithmic redesign.

### Mechanism 2
Fixed-point quantization reduces inference latency on ARM CPUs without severely degrading model accuracy. ARM CPUs often lack hardware floating-point units, causing emulated floating-point operations to be slow. By quantizing thresholds and leaf values to 16-bit integers using a scaling constant, the algorithm can use NEON's integer comparison and arithmetic intrinsics, which are faster than float emulation. This doubles the number of parallel comparisons possible within a 128-bit register. The approach assumes integer comparisons and arithmetic are significantly faster than emulated floating-point operations on ARM, and the quantization error is tolerable for the given classification task.

### Mechanism 3
The choice of tree ensemble traversal algorithm impacts performance differently depending on the ARM device and forest configuration. Each algorithm has different memory access patterns and SIMD utilization strategies. RapidScorer optimizes for fewer comparisons by merging equivalent nodes and uses a transposed bitvector layout, which benefits certain datasets and device cache architectures. V-QuickScorer processes multiple instances in parallel, benefiting from NEON's integer comparison speedup after quantization. The best algorithm depends on the number of trees, leaves, and the specific ARM core's pipeline and cache characteristics, as architectural differences between ARM cores influence cache behavior and SIMD throughput enough to change the optimal algorithm choice.

## Foundational Learning

- **Concept:** SIMD vectorization and instruction set differences (AVX vs. NEON)
  - **Why needed here:** The performance gain comes from processing multiple tree nodes or instances in parallel using SIMD instructions. Understanding how AVX maps to NEON is essential to adapt the algorithm correctly.
  - **Quick check question:** What is the width of NEON SIMD registers, and how does it compare to AVX?

- **Concept:** Fixed-point quantization and scaling constants
  - **Why needed here:** Quantization replaces floating-point values with scaled integers to leverage faster integer operations on ARM. Choosing the scaling constant correctly ensures no overflow and minimal precision loss.
  - **Quick check question:** If a leaf value is 0.75 and the scaling constant is 2^15, what is the quantized integer value?

- **Concept:** Memory layout and cache behavior for tree traversal
  - **Why needed here:** The efficiency of tree ensemble inference depends heavily on data locality. Transposed layouts (as in RapidScorer) can reduce cache misses when accessing multiple instances' bitvectors.
  - **Quick check question:** How does a row-major vs. column-major storage of bitvectors affect cache line utilization during tree traversal?

## Architecture Onboarding

- **Component map:** Input data preprocessing -> Feature scaling and quantization -> Tree ensemble model -> Traversal algorithm (QuickScorer family) -> SIMD execution (NEON intrinsics) -> Score accumulation
- **Critical path:** Feature value -> SIMD comparison with thresholds -> Bitmask update -> Exit leaf identification -> Score accumulation
- **Design tradeoffs:**
  - Precision vs. speed: Higher precision (e.g., 32-bit floats) increases accuracy but reduces SIMD parallelism on ARM
  - Algorithm choice vs. hardware: VQS may be better for large batches, RS for smaller, cache-sensitive workloads
  - Quantization vs. model fidelity: Aggressive quantization speeds up inference but risks accuracy loss on sensitive datasets
- **Failure signatures:**
  - Incorrect quantized values leading to wrong predictions (accuracy drop)
  - SIMD register overflow if scaling constant too large
  - Cache thrashing if data layout mismatches traversal pattern
  - Performance regression if NEON intrinsics not optimally used
- **First 3 experiments:**
  1. Implement QS with NEON and validate against a float baseline on a small dataset (e.g., MNIST with 32 leaves, 1024 trees)
  2. Add quantization (16-bit) and measure speed and accuracy change
  3. Compare VQS and RS variants with and without quantization on two ARM devices (Raspberry Pi and Odroid)

## Open Questions the Paper Calls Out

### Open Question 1
What are the optimal quantization schemes for different ARM architectures to maximize inference speed while minimizing accuracy loss? The paper discusses fixed-point quantization but uses a fixed scaling constant (2^15) for all experiments. The optimal quantization scheme may vary based on specific ARM architecture, dataset, and ensemble configuration. Experiments comparing different quantization schemes on various ARM devices and datasets would resolve this.

### Open Question 2
How do architectural differences between ARM Cortex-A53 and Exynos 5422 impact the performance of QuickScorer variants? The paper observes performance differences between Raspberry Pi (Cortex A53) and Odroid-XU4 (Exynos 5422) but doesn't provide detailed architectural analysis. A detailed analysis focusing on cache size, SIMD instruction support, and memory access patterns, followed by validation experiments, would resolve this.

### Open Question 3
What is the impact of tree ensemble pruning on the inference speed of QuickScorer on ARM devices? The paper mentions ensemble pruning can improve accuracy while reducing memory consumption but doesn't investigate its impact on inference speed. Experiments comparing inference speed of pruned vs. unpruned ensembles on ARM devices while measuring accuracy impact would resolve this.
