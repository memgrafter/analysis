# Goal Alignment: A Human-Aware Account of Value Alignment Problem

## Quick Facts
- arXiv ID: 2302.00813
- Source URL: https://arxiv.org/abs/2302.00813
- Authors: 
- Reference count: 16
- Key outcome: Novel goal alignment algorithm reduces queries by leveraging human mental models, with significant performance gains in larger state spaces

## Executive Summary
This paper introduces goal alignment as a human-aware formulation of the value alignment problem, addressing the inherent asymmetry between human expectations and agent behavior. The authors develop an interactive algorithm that queries humans about relevant fluents in order of their estimated value, using the human's mental model to guide the query process. The algorithm can terminate early when a superset of the true goal is achievable, reducing the number of required queries. Empirical evaluation on IPC benchmark problems demonstrates significant query reduction compared to naive approaches, particularly in domains with larger state spaces.

## Method Summary
The proposed algorithm works by having a human specify a goal GH and plan πH based on their mental model. The robot then computes the expected state SH_G* from executing this plan in the human model. If the specified goal is unachievable or the expected state is already achievable, the process terminates immediately. Otherwise, the algorithm computes a probability for each fluent being in the true goal based on how plan costs change when that fluent is included. Queries are made in order of these probabilities until termination conditions are met: either finding a plan for a superset of the goal, discovering the true goal, or exhausting all possible queries.

## Key Results
- Significant reduction in query count across most domains compared to naive upper bounds
- Best performance in problems with larger state spaces (blocksworld being the exception)
- Early termination possible when achieving a superset of the true goal is sufficient
- Algorithm effectiveness depends on the accuracy of the human's mental model

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The algorithm uses the human's mental model to approximate which fluents are most likely part of the true goal
- Mechanism: The algorithm computes a probability for each fluent being in the true goal based on the difference between the human's plan cost and the optimal plan cost in the human model. Fluents that make the optimal plan closer to the human's plan get higher probability.
- Core assumption: Humans are approximately rational decision-makers, so their suboptimal plans provide information about their true goals
- Evidence anchors: [abstract] "The algorithm uses an approximation-based approach to query the human about relevant fluents in order of their value"; [section 6] "Now to calculate the probability, we will employ a strategy similar to the ones used in goal recognition... if the inclusion of a fluent f in the goal set... makes the optimal plan for the new goal in the human model closer to the cost of the specified plan"

### Mechanism 2
- Claim: The algorithm can terminate early by finding plans that achieve supersets of the true goal
- Mechanism: The algorithm maintains a current set C of fluents known to be in the goal. It checks if the robot can achieve GH ∪ C ∪ Q (where Q is the remaining unqueried fluents). If yes, it can terminate early without querying all fluents.
- Core assumption: If a plan achieves a superset of the true goal, the human will be satisfied with the outcome
- Evidence anchors: [section 5] "Note that the solution we propose of finding a plan that results in a superset of G* is still consistent with cases where the human may want to avoid some undesirable side effects"; [section 6] "We will end the query process under one of the three conditions... 3. There exists a plan that can achieve the current subset of fluents the human has said yes to can be achieved along with GH and any unqueried fluent"

### Mechanism 3
- Claim: The algorithm reduces query complexity by leveraging the upper bound from the human's expected state
- Mechanism: The algorithm only needs to query about fluents in SH_G* \ GH (the difference between the state the human expects and the goal they specified), not all possible fluents in the domain
- Core assumption: The true goal is a subset of the state the human expects from their plan
- Evidence anchors: [section 5] "Now let SH_G* represent the state that results from executing the plan πH in the human model... we will define the value associated with querying about each fluent"; [section 7] "The most striking result to note is the fact that, apart from the blocksworld domain, we see a significant drop in the number of queries in almost all the domains"

## Architecture Onboarding

- Component map:
  - Human model -> Query engine -> Plan generator -> Probability estimator -> Robot model

- Critical path:
  1. Human specifies goal GH and plan πH
  2. Compute SH_G* = T(πH, IH, DH)
  3. If GH is unachievable or SH_G* is achievable, return immediately
  4. Compute probability for each fluent in SH_G* \ GH
  5. Query fluents in order of value until termination condition
  6. Return plan achieving GH plus confirmed fluents

- Design tradeoffs:
  - Independence assumption: Assumes fluents are independently achievable, which may not hold
  - Rationality assumption: Assumes human is approximately rational in their planning
  - Upper bound reliance: Relies on the human's expected state as an upper bound, which requires access to their mental model

- Failure signatures:
  - High query count despite small goal states: May indicate the independence assumption is violated
  - No early termination possible: May indicate the human's mental model is very different from the robot model
  - Plan generation fails after queries: May indicate the true goal requires fluents not in SH_G*

- First 3 experiments:
  1. Run on a simple blocksworld problem where the human's mental model is slightly incorrect
  2. Test with a problem where the true goal requires a fluent not in SH_G* to verify failure handling
  3. Compare query counts on problems with varying numbers of fluents to validate the complexity claims

## Limitations

- The independence assumption for fluents may lead to overestimation of probabilities when fluents are highly interdependent
- Early termination assumes achieving a superset of the goal is acceptable, which may not hold for safety-critical domains
- Algorithm effectiveness heavily depends on the accuracy of the human's mental model relative to the robot's true model

## Confidence

- Medium confidence: The overall approach of using human mental models to reduce query complexity is sound and builds on established goal recognition literature, but the specific implementation details and their robustness to model inaccuracies need more validation
- Low confidence: The claim about significant query reduction across domains, particularly given the independence assumption, needs more empirical validation. The paper shows promising results but doesn't thoroughly explore failure modes or the impact of model mismatches
- Medium confidence: The termination conditions are theoretically well-defined but their practical effectiveness depends heavily on the accuracy of the human model and the domain structure

## Next Checks

1. **Stress test the independence assumption**: Create synthetic domains where fluents are strongly interdependent and measure how the probability estimates degrade. This would validate whether the algorithm remains effective when the key assumption is violated.

2. **Safety-critical domain evaluation**: Test the algorithm in domains where achieving supersets of goals could have negative consequences (e.g., robotics tasks where unintended object manipulation could be dangerous) to validate the early termination mechanism's safety.

3. **Model mismatch robustness**: Systematically vary the distance between human and robot models and measure query complexity and success rates to understand the algorithm's robustness to realistic levels of human model inaccuracy.
