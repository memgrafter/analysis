# "You might think about slightly revising the title": identifying hedges in peer-tutoring interactions

## Quick Facts
- arXiv ID: 2306.14911
- Source URL: https://arxiv.org/abs/2306.14911
- Reference count: 15
- Hybrid rule-based and ML approach outperforms baseline for hedge detection in peer-tutoring

## Executive Summary
This paper proposes a hybrid approach for identifying hedges in peer-tutoring conversations, combining rule-based classifiers with machine learning models. The authors use a peer-tutoring dataset and compare approaches relying on pre-trained resources with others integrating insights from social science literature. Their best performance involves a hybrid approach that outperforms the existing baseline while being easier to interpret. They employ a model explainability tool to explore the features that characterize hedges in peer-tutoring conversations, identifying some novel features and the benefits of such a hybrid model approach.

## Method Summary
The method involves a rule-based classifier using regular expressions to identify hedge classes, followed by feature extraction including unigrams, bigrams, POS n-grams, LIWC categories, tutoring moves, and nonverbal behaviors. A LightGBM gradient boosting model is trained on these Knowledge-Driven features, with SHAP used for post-hoc interpretability. The approach is compared against BERT fine-tuning and other baseline models using 5-fold cross-validation on a peer-tutoring dataset with nearly 24,000 clauses.

## Key Results
- Hybrid approach combining rule-based labels with LightGBM achieves best F1-scores for hedge detection
- Unigrams and bigrams significantly improve performance over rule-based features alone
- SHAP analysis reveals novel linguistic features characterizing different hedge classes

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Hybrid integration of rule-based features and machine learning improves hedge detection over either approach alone.
- Mechanism: Rule-based classifiers provide interpretable linguistic signals (e.g., regex matches for "I think", "kind of") that boost model performance when combined with statistical learners, compensating for class imbalance and ambiguous lexical cues.
- Core assumption: Hedge indicators have consistent lexical and syntactic patterns that rules can capture, and these patterns are not fully encoded in pre-trained embeddings.
- Evidence anchors:
  - [abstract]: "Our best performance involved a hybrid approach that outperforms the existing baseline while being easier to interpret."
  - [section 5.2]: "The introduction of n-grams significantly improved the performance of our classifier, suggesting that some lexical and syntactic information describing the hedge classes was not present in the rule-based model."
  - [corpus]: No direct evidence of corpus patterns; relies on annotation manual and prior linguistic literature.
- Break condition: If hedge patterns shift substantially across domains or speakers, rule-based patterns may no longer generalize, reducing hybrid advantage.

### Mechanism 2
- Claim: Gradient boosting with interpretable features is more effective than deep learning embeddings for this task.
- Mechanism: LightGBM leverages explicit features (unigrams, POS n-grams, LIWC categories) to directly model hedge-related lexical and syntactic cues, outperforming black-box embeddings that may not separate nuanced hedge functions.
- Core assumption: Hedge classes are largely distinguishable via surface lexical and syntactic features rather than abstract semantic embeddings.
- Evidence anchors:
  - [section 5.2]: "The low scores obtained by the LGBM, LSTM and MLP models with pre-trained sentence embeddings versus Knowledge-Driven features might signal that the word patterns characterizing hedges are not salient in these representations."
  - [section 5.3]: "Unigrams (Oh, Sorry, just, Would, and I) are also present in the 5 top-ranked features."
  - [corpus]: No direct corpus validation; inference drawn from model performance comparison.
- Break condition: If hedges become semantically encoded in contextual embeddings more strongly in other corpora, the advantage of explicit features may diminish.

### Mechanism 3
- Claim: SHAP interpretability reveals novel linguistic features that improve understanding of hedge classes.
- Mechanism: Model-agnostic SHAP analysis assigns feature importance per prediction, uncovering features like utterance length, LIWC informal words, and specific POS n-grams that correlate with hedge types beyond prior literature.
- Core assumption: Local feature contributions can be aggregated to reveal global patterns without overfitting to dataset noise.
- Evidence anchors:
  - [section 5.3]: "We discovered that features like utterance size can also serve as indicators of certain classes of hedges."
  - [section 5.3]: "The presence of Oh also has high importance for the characterization of Apologizer."
  - [corpus]: No direct corpus-level evidence; relies on SHAP aggregation across annotated instances.
- Break condition: If feature correlations are spurious due to small sample sizes in minority classes, SHAP importance may mislead model interpretation.

## Architecture Onboarding

- Component map:
  - Rule-based classifier (regex patterns for hedge classes)
  - Feature extractor (unigrams, bigrams, POS n-grams, LIWC, tutoring moves, nonverbal behaviors)
  - LightGBM model (gradient boosting on rule-based labels + features)
  - SHAP explainer (post-hoc interpretability)
- Critical path:
  1. Preprocess utterances → tokenize and POS tag
  2. Apply rule-based classifier → generate rule-based labels
  3. Extract features → build feature vector
  4. Train LightGBM → classify hedges
  5. Apply SHAP → interpret feature contributions
- Design tradeoffs:
  - Rule-based vs. learned features: Rules are interpretable but brittle; learned features generalize but are opaque.
  - Feature richness vs. sparsity: Including many features risks overfitting; LightGBM mitigates via feature selection.
  - Multimodal features vs. text-only: Nonverbal cues didn't improve performance here but may in other contexts.
- Failure signatures:
  - Rule-based classifier precision drops if hedge markers change across domains.
  - LightGBM overfits to minority classes if regularization is too weak.
  - SHAP explanations mislead if feature correlations are spurious due to class imbalance.
- First 3 experiments:
  1. Run rule-based classifier alone on test set; record precision/recall per class.
  2. Train LightGBM with only rule-based label feature; compare performance to rule-based baseline.
  3. Add unigrams and bigrams incrementally; observe performance gains and feature importance shifts.

## Limitations
- Class imbalance heavily skews performance metrics, with over 90% of clauses labeled "Not hedged," potentially inflating baseline performance and masking weaknesses in minority class detection.
- The rule-based classifier relies on fixed regular expressions that may not generalize across domains or capture evolving hedge patterns, limiting scalability.
- Limited evidence for the claimed superiority of hybrid features over contextual embeddings; improvements may be dataset-specific rather than generalizable.

## Confidence
- **High confidence** in the observation that unigrams and bigrams significantly improve performance over rule-based features alone, supported by clear performance gains in section 5.2.
- **Medium confidence** in the claim that LightGBM outperforms BERT-based models for this task, as the comparison is limited to this specific corpus and may not hold in other domains.
- **Low confidence** in the interpretability of SHAP-derived features for novel hedge discovery, given the potential for spurious correlations in imbalanced datasets and lack of external validation.

## Next Checks
