# Dataset and Baseline System for Multi-lingual Extraction and Normalization of Temporal and Numerical Expressions

## Quick Facts
- arXiv ID: 2303.18103
- Source URL: https://arxiv.org/abs/2303.18103
- Reference count: 13
- Primary result: NTX dataset covering 8 numerical and 10 temporal sub-types across 14 languages with rule-based baseline system

## Executive Summary
This paper introduces NTX, a multi-lingual evaluation dataset for temporal and numerical expression extraction, normalization, and resolution. The dataset addresses limitations of previous work by providing comprehensive coverage of 18 entity sub-types across 14 languages, totaling over 26,000 sentences. A robust rule-based baseline system is provided, designed with determinism, recall prioritization, and accessibility for modifications without expert knowledge.

## Method Summary
The NTX dataset covers 8 numerical sub-types (cardinal, ordinal, percentage, numerical range, age, currency, dimension, temperature) and 10 temporal sub-types (date, time, datetime, date range, time range, datetime range, holiday, duration, timezone, recurring set). The rule-based baseline system follows three key principles: determinism for reproducible results, prioritizing recall to capture all possible entities, and accessibility allowing non-experts to modify rules. The dataset was constructed by combining existing temporal and numerical resources, then annotating for extraction, normalization, and resolution tasks.

## Key Results
- Comprehensive schema covering 18 entity sub-types across 14 languages
- Over 26,000 annotated sentences for temporal and numerical expressions
- Rule-based baseline system designed for deterministic results and recall prioritization
- Multi-lingual coverage including English, Spanish, Chinese, Arabic, and 10 other languages
- Combined extraction, normalization, and resolution framework for downstream usability

## Why This Works (Mechanism)
The approach works by providing a unified schema that goes beyond simple entity extraction to include normalization and resolution, making the dataset immediately useful for downstream applications. The rule-based system's deterministic nature ensures reproducible results, while the recall-first design captures comprehensive entity coverage across diverse languages and expression types.

- **Entity resolution techniques**: Critical for practical applications; quick check: validate resolved entities against ground truth
- **Deterministic processing pipelines**: Ensures reproducibility; quick check: verify identical outputs for identical inputs
- **Recall-prioritization strategy**: Maximizes entity capture at potential precision cost; quick check: measure precision-recall tradeoff

## Architecture Onboarding
**Component map**: Data sources -> Annotation pipeline -> Entity extraction rules -> Normalization rules -> Resolution rules -> Evaluation metrics

**Critical path**: Data collection → Annotation → Rule development → System integration → Baseline evaluation

**Design tradeoffs**: Deterministic rules provide reproducibility but may miss complex patterns that ML approaches could capture; recall prioritization ensures comprehensive coverage but may introduce false positives.

**Failure signatures**: Ambiguous expressions may be incorrectly normalized; cross-lingual variations may not be fully captured by rule sets; complex nested expressions may be missed by deterministic rules.

**First experiments**:
1. Run rule-based system on small sample from each language to verify basic functionality
2. Test normalization accuracy on known edge cases (e.g., relative dates, mixed formats)
3. Validate resolution accuracy for numerical expressions requiring unit conversion

## Limitations
- Rule-based system acknowledged as strong baseline but not state-of-the-art
- Deterministic approach may sacrifice precision for complex edge cases
- Dataset construction relies on existing resources, potentially introducing biases
- Systematic evaluation metrics for baseline system performance not provided
