# Mixed Precision Post Training Quantization of Neural Networks with Sensitivity Guided Search

## Quick Facts
- arXiv ID: 2302.01382
- Source URL: https://arxiv.org/abs/2302.01382
- Authors: 
- Reference count: 13
- Primary result: Up to 50% model size reduction and 27.59% (ResNet50) and 34.31% (BERT) latency reductions while maintaining ≤1% accuracy degradation

## Executive Summary
This paper addresses the challenge of efficiently deploying large neural networks by proposing a mixed precision post-training quantization approach that reduces memory footprint and latency while maintaining accuracy. The authors introduce three sensitivity metrics—quantization error, noise-based accuracy degradation, and Hessian trace—to guide the search for optimal quantization configurations. Two search algorithms, bisection and greedy, progressively determine per-tensor precision settings to meet accuracy targets. Evaluated on ResNet50 and BERT, the Hessian-guided greedy search achieved significant model compression and latency reduction compared to 16-bit baselines.

## Method Summary
The method employs post-training quantization with scale adaptation, using three sensitivity metrics to guide configuration search. Quantization scales are first estimated using calibration data, then refined via backpropagation to minimize model loss. Two search algorithms progressively determine optimal quantization configurations: bisection uses threshold-based quantization while greedy sequentially evaluates each layer at lower precision. The approach targets up to 50% model size reduction and significant latency improvements while guaranteeing ≤1% accuracy degradation compared to 16-bit baselines.

## Key Results
- Hessian-guided greedy search achieved up to 50% model size reduction
- 27.59% latency reduction on ResNet50 and 34.31% on BERT compared to 16-bit baselines
- Hessian-based metric consistently outperformed quantization error and noise-based metrics
- Greedy search algorithm outperformed bisection in model compression efficiency

## Why This Works (Mechanism)

### Mechanism 1
The Hessian-based sensitivity metric captures second-order derivative information, estimating local curvature of the loss function. Layers with high curvature are more sensitive to precision changes, while flat regions tolerate lower precision without accuracy loss. This works under the assumption that model accuracy is robust to perturbations in values occupying flat regions of the loss function.

### Mechanism 2
Progressive search algorithms efficiently navigate the exponential configuration space by starting with full precision and iteratively quantizing layers based on sensitivity ordering. The bisection search uses threshold-based quantization while greedy sequentially evaluates each layer at lower precision, both working under the assumption that sensitivity ordering enables efficient exploration without exhaustive search.

### Mechanism 3
Post-training quantization with scale adaptation maintains accuracy by first estimating quantization scales using calibration data, then refining them via backpropagation. This two-step approach compensates for quantization errors without updating original model parameters, working under the assumption that scale adaptation can effectively compensate for quantization errors.

## Architecture Onboarding

- Component map: Sensitivity metric computation (QE, noise injection, Hessian trace) -> Scale calibration and adjustment pipeline -> Search algorithm implementation (bisection and greedy) -> Performance evaluation framework -> Hardware latency estimation module

- Critical path: 1. Compute sensitivity metrics for all layers 2. Execute chosen search algorithm 3. Apply quantization with scale adaptation 4. Evaluate accuracy and latency 5. Iterate if accuracy target not met

- Design tradeoffs: QE vs Hessian (computational cost vs accuracy), Bisection vs Greedy (guaranteed convergence vs faster execution), Calibration data size vs scale adaptation quality, Hardware latency estimation accuracy vs implementation complexity

- Failure signatures: Accuracy degradation despite meeting sensitivity thresholds, Inconsistent results across random seeds, Latency improvements not matching theoretical expectations, Sensitivity metrics showing unexpected layer orderings

- First 3 experiments: 1. Implement and compare all three sensitivity metrics on a small network 2. Test bisection and greedy algorithms with random sensitivity ordering 3. Validate scale adaptation step with synthetic quantization errors

## Open Questions the Paper Calls Out

### Open Question 1
How would using multi-bit precision quantization affect the results, compared to the fixed 4-bit and 16-bit configurations used in the paper? The study only focuses on these two specific precisions, leaving the potential impact of other bit-widths unexamined.

### Open Question 2
How do different calibration datasets affect the sensitivity metrics and the resulting quantization configurations? The paper uses a fixed calibration dataset without considering how different datasets might influence the sensitivity metrics and quantization outcomes.

### Open Question 3
Can the Hessian-based metric be further optimized to improve its computational efficiency and effectiveness in guiding the quantization process? While the paper approximates the Hessian trace using Hutchinson's algorithm, it does not explore potential optimizations for this metric.

## Limitations
- Hessian-based metric requires second-order derivative computation, potentially prohibitive for very large models
- Search algorithms assume layer independence, potentially missing cross-layer interactions
- Latency measurements rely on specific hardware and libraries (NVIDIA A100, cuQuantization, TensorRT)

## Confidence
- High confidence: Core methodology of using sensitivity metrics for quantization configuration search is sound and well-validated
- Medium confidence: Hessian-based metric consistently outperforms others, though computational cost may limit scalability
- Medium confidence: Bisection and greedy algorithms efficiently navigate configuration space, but layer independence assumptions may introduce errors
