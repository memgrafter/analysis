# PRESTO: A Multilingual Dataset for Parsing Realistic Task-Oriented Dialogs

## Quick Facts
- arXiv ID: 2303.08954
- Source URL: https://arxiv.org/abs/2303.08954
- Reference count: 11
- PRESTO contains over 550K conversations across 6 languages with realistic conversational phenomena

## Executive Summary
PRESTO is a large-scale multilingual dataset for task-oriented dialog parsing that addresses limitations of existing datasets by including realistic phenomena like disfluencies, code-switching, and user revisions, along with structured context such as contacts and lists. The dataset was collected from native speakers across 6 languages (English, Spanish, Arabic, Hindi, Vietnamese, and Mandarin) and includes annotations for semantic parsing and linguistic phenomena. Experiments using mT5 models show that while performance improves with more training data, modeling these phenomena remains challenging, especially in low-resource settings. The dataset enables research on conversational parsing with rich, realistic data.

## Method Summary
The PRESTO dataset contains 550K+ conversations across 6 languages, collected from native speakers rather than translated from English. It includes semantic annotations for intents and slots, along with annotations for linguistic phenomena (code-switching, disfluencies, user revisions). The parsing approach uses mT5-based text-to-text models fine-tuned on varying amounts of training data. Input sequences are constructed by serializing the user utterance, previous turns, and structured context with separator tokens. Models are trained for 20K steps with Adafactor optimizer and evaluated using exact match accuracy.

## Key Results
- Multilingual models outperform monolingual models in low-resource settings, converging to similar performance with sufficient data
- Code-switching remains the most challenging phenomenon, with zero-shot performance at 44.4% exact match
- Including structured context provides only marginal improvements, suggesting challenges in context utilization

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Including structured context as part of the input sequence improves parsing accuracy for contextual examples.
- Mechanism: By serializing context tokens and appending them to the input with separator tokens, the model can condition its predictions on relevant structured information like contacts, lists, and notes.
- Core assumption: The model can effectively learn to use structured context when it is available and relevant to the current utterance.
- Evidence anchors: [abstract] "It is the only large scale human generated conversational parsing dataset that provides structured context such as a user's contacts and lists for each example." [section 4.6] "We linearize and prepend the context tokens to the T5 parser input with [SEP] tokens as shown in the example presented in 4.1." [corpus] Weak evidence - while the dataset includes structured context, the experimental results in Table 5 show only marginal improvement, suggesting the assumption may not fully hold.
- Break condition: If the model learns to ignore context or if the context representation is too noisy or irrelevant, performance gains will be minimal.

### Mechanism 2
- Claim: Training on a diverse set of conversational phenomena (code-switching, disfluencies, user revisions) improves model robustness to these phenomena.
- Mechanism: By including examples with these phenomena in the training data, the model learns to parse utterances containing them, leading to better generalization on test examples with similar characteristics.
- Core assumption: Exposure to these phenomena during training is necessary for the model to learn to handle them effectively.
- Evidence anchors: [section 4.2] "Our results show that in lower data regimes there is a clear gap between monolingual and multilingual models, but when using all training instances in the dataset, monolingual and multilingual models converge towards similar performance." [section 4.3] "Surprisingly, even at 0 shot we see a relatively high performance for this phenomenon. We hypothesize that this is due to using a LangID to identify code-switching utterances which may cause code-switched utterances to leak into the training set." [corpus] Moderate evidence - the dataset contains thousands of examples per language for each phenomenon, supporting the feasibility of this approach.
- Break condition: If the model fails to generalize from the training examples or if the phenomena are too rare or diverse, performance may not improve significantly.

### Mechanism 3
- Claim: Multilingual training improves performance, especially in low-resource settings, compared to monolingual models.
- Mechanism: By training a single model on data from all languages, the model can leverage cross-lingual transfer and shared representations, leading to better performance, particularly when data is scarce for individual languages.
- Core assumption: The languages in the dataset share enough linguistic and semantic structure for useful transfer to occur.
- Evidence anchors: [section 4.7] "Our results show that in lower data regimes there is a clear gap between monolingual and multilingual models, but when using all training instances in the dataset, monolingual and multilingual models converge towards similar performance." [section 1] "Unlike in other datasets, conversations in each language were not obtained by translating English dialog, but instead contributed by native speakers of each language." [corpus] Moderate evidence - the dataset covers 6 diverse languages, providing a reasonable basis for multilingual training, but the effectiveness depends on the similarity between languages.
- Break condition: If the languages are too dissimilar or if the model overfits to the majority language, multilingual training may not provide benefits.

## Foundational Learning

- Concept: Semantic parsing of task-oriented dialogs
  - Why needed here: The core task is to map user utterances to structured semantic representations (intents and slots) that can be executed by a virtual assistant.
  - Quick check question: Given an utterance like "Call mom", what is the intent and what is the slot value?

- Concept: Handling conversational phenomena (code-switching, disfluencies, user revisions)
  - Why needed here: Realistic dialogs often contain these phenomena, and the model must be able to parse utterances containing them accurately.
  - Quick check question: How would you parse the utterance "I want to call mom no wait call dad" considering it contains a user revision?

- Concept: Incorporating structured context (contacts, lists, notes)
  - Why needed here: The context provides additional information that can be crucial for correctly interpreting user utterances, e.g., resolving ambiguous references.
  - Quick check question: If a user says "Add apples to my shopping list" and the context includes a list named "Groceries", how should the model interpret this utterance?

## Architecture Onboarding

- Component map: User utterance -> Previous turns -> Structured context -> mT5 model -> Semantic parse (intent + slots)

- Critical path:
  1. Preprocess input: Serialize utterance, previous turns, and context with separator tokens
  2. Encode input using mT5 model
  3. Decode output semantic parse
  4. Post-process output if necessary

- Design tradeoffs:
  - Using a single multilingual model vs. multiple monolingual models
  - Including all structured context vs. filtering context based on relevance
  - Training on all phenomena vs. focusing on specific phenomena

- Failure signatures:
  - Low exact match accuracy on test sets
  - Model fails to handle code-switching, disfluencies, or user revisions
  - Model ignores structured context when it is relevant
  - Overfitting to training data or majority language

- First 3 experiments:
  1. Train a multilingual mT5 model on all data and evaluate on the overall test set
  2. Train a model on data without specific phenomena and evaluate on focused test sets for each phenomenon
  3. Train models with varying amounts of data for each phenomenon and plot performance curves

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal way to represent structured context in conversational parsing models?
- Basis in paper: [explicit] The paper discusses the challenges of representing structured context in the dataset and mentions that feeding a simple representation of the structured context to the model does not yield large improvements on contextual examples.
- Why unresolved: While the paper acknowledges the importance of structured context, it does not provide a definitive solution or optimal representation method for incorporating this context into conversational parsing models.
- What evidence would resolve it: A comparative study of different context representation methods (e.g., filtered context, linearized context, attention-based methods) and their impact on model performance across various linguistic phenomena and languages would provide insights into the optimal approach.

### Open Question 2
- Question: How can we improve model performance on code-switched utterances with limited training data?
- Basis in paper: [explicit] The paper presents experiments on code-switched utterances, showing that even with a large number of multilingual examples, model performance on code-switching remains significantly lower compared to other linguistic phenomena.
- Why unresolved: The paper demonstrates the challenge of parsing code-switched utterances but does not provide a clear solution or strategy for improving model performance when only a limited number of code-switching examples are available in the training data.
- What evidence would resolve it: Experiments comparing different techniques for handling code-switching, such as data augmentation, code-switching detection and adaptation, or cross-lingual transfer learning, would help identify effective strategies for improving model performance in low-resource code-switching scenarios.

### Open Question 3
- Question: What is the impact of linguistic phenomena on model performance in a low-resource setting?
- Basis in paper: [explicit] The paper discusses the performance of models on various linguistic phenomena (user revisions, disfluencies, code-switching) and mentions that the challenges are more pronounced in a low-resource setup.
- Why unresolved: While the paper provides insights into model performance on linguistic phenomena with varying amounts of training data, it does not specifically analyze the impact of these phenomena in a low-resource setting where only a limited number of examples are available for each phenomenon.
- What evidence would resolve it: A detailed analysis of model performance on linguistic phenomena in a low-resource setting, comparing the performance of models trained on a small number of examples for each phenomenon, would provide a clearer understanding of the challenges and potential strategies for addressing them in such scenarios.

## Limitations

- Data contamination in code-switching experiments due to language ID classifier limitations
- Marginal improvements from structured context suggest challenges in context utilization
- Cross-lingual transfer effectiveness across diverse languages remains uncertain

## Confidence

**High Confidence**:
- The PRESTO dataset successfully addresses gaps in existing task-oriented dialog datasets by including realistic conversational phenomena and structured context
- Multilingual models show advantages over monolingual models in low-resource settings, converging to similar performance with sufficient data

**Medium Confidence**:
- The mT5-based parsing approach can handle code-switching, disfluencies, and user revisions when trained on relevant examples
- The dataset's size and diversity (550K+ conversations across 6 languages) provides sufficient coverage for meaningful experiments

**Low Confidence**:
- Zero-shot performance on code-switching phenomena accurately reflects true generalization capability
- The context serialization approach provides meaningful performance improvements

## Next Checks

1. **Verify Data Segregation**: Implement a stricter language ID filtering mechanism with manual validation to ensure code-switched examples are completely excluded from training data, then re-run zero-shot code-switching experiments to establish true baseline performance.

2. **Context Relevance Analysis**: Conduct ablation studies where context is systematically included or excluded based on semantic similarity scores (trigram overlap >0.6) and measure the impact on exact match accuracy, particularly for examples where context should be highly relevant.

3. **Cross-Lingual Transfer Validation**: Design experiments comparing multilingual models trained on diverse language pairs (e.g., English-Spanish vs. English-Arabic) to assess whether transfer effectiveness correlates with linguistic similarity, providing insights into the dataset's utility for truly low-resource languages.
