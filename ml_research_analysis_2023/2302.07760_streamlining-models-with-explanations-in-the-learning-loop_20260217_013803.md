# Streamlining models with explanations in the learning loop

## Quick Facts
- arXiv ID: 2302.07760
- Source URL: https://arxiv.org/abs/2302.07760
- Reference count: 35
- Primary result: Iterative Dataset Weighting and Targeted Replacement Values methods generate streamlined models with higher explanation compactness and global similarity while preserving accuracy.

## Executive Summary
This paper introduces two methodologies, Iterative Dataset Weighting (IDW) and Targeted Replacement Values (TRV), to create streamlined black-box models that produce more compact and consistent explanations. The methods leverage local linear explanations (LLEs) from an initial model to engineer new datasets for training streamlined models. Experiments on four tabular datasets demonstrate that these approaches preserve model accuracy while significantly improving explanation compactness and consistency compared to baseline models and regularized alternatives.

## Method Summary
The paper proposes IDW, which iteratively combines datasets with explanation scores using Hadamard product to suppress non-relevant features, and TRV, which replaces non-relevant features with neutral values while maintaining a fixed cognitive budget of relevant features. Both methods use SHAP explanations from an initial model to engineer new datasets for training streamlined models. The approaches are evaluated on four tabular datasets using accuracy, explanation compactness percentage (XCP), global similarity (Sim), and fairness metrics.

## Key Results
- Streamlined models preserve accuracy while producing significantly more compact explanations compared to baseline models
- IDW and TRV achieve higher XCP values (e.g., 75.1% vs 48.5% for baseline on Kidney dataset)
- Streamlined models show improved global similarity scores, indicating more consistent explanations
- TRV with K=3 provides optimal balance between accuracy preservation and explanation compactness

## Why This Works (Mechanism)

### Mechanism 1
- Claim: IDW transforms the original dataset into a new representation where feature importance modulates the feature values via element-wise Hadamard product, effectively reducing the influence of non-relevant features.
- Mechanism: The SHAP explanation matrix E0 contains importance weights for each feature per sample. By multiplying |E0| element-wise with the original data D0, IDW scales each feature value by its relative importance, then rescales columns to maintain z-score normalization. This creates D1 where less important features are suppressed, forcing the model to rely on locally relevant features.
- Core assumption: The SHAP importance weights computed from the baseline model f0 are reliable indicators of which features drive classification for each sample, and that suppressing non-relevant features preserves accuracy.
- Evidence anchors:
  - [abstract] "IDW iteratively combines datasets with explanation scores using Hadamard product"
  - [section] "A new dataset D1 is obtained by combining the matrix |E0| with the initial dataset matrix D0 using the element-wise Hadamard product, i.e. D1 =|E0|⊙ D0"
- Break condition: If SHAP scores are noisy or systematically biased, the Hadamard product will propagate this error, degrading model performance rather than streamlining it.

### Mechanism 2
- Claim: TRV replaces non-relevant features with neutral values identified per feature, maintaining a fixed cognitive budget K of relevant features per sample.
- Mechanism: TRV first computes a thresholded SHAP score matrix E0, then for each feature j computes a replacement value R[j] as the median of all feature values whose absolute SHAP scores fall below threshold ε. During dataset transformation, each sample keeps only the top K features by SHAP score and replaces the rest with R[j], creating a masked dataset D1.
- Core assumption: There exists a well-defined neutral value per feature that, when substituted, does not bias the model's predictions, and that K can be chosen to balance accuracy and interpretability.
- Evidence anchors:
  - [abstract] "TRV replaces non-relevant features with neutral values"
  - [section] "the replacement value for that feature is computed as the median value of all values in the dataset D0 for that feature that have a corresponding absolute SHAP score in E0 smaller than ϵ"
- Break condition: If the neutral value is not truly neutral (e.g., skewed by outliers) or K is too small, the streamlined model may lose predictive power.

### Mechanism 3
- Claim: By iteratively applying IDW, the model progressively focuses on fewer features, producing increasingly compact explanations while maintaining accuracy.
- Mechanism: Each iteration i generates a new background set Bi, trains a new model hi on Di, and computes new SHAP scores Ei. The Hadamard product at each step further suppresses features with low cumulative importance, concentrating the model's attention on a shrinking feature set.
- Core assumption: The iterative suppression does not catastrophically reduce the model's ability to separate classes, and that the SHAP explanations remain stable across iterations.
- Evidence anchors:
  - [abstract] "IDW iteratively combines datasets with explanation scores"
  - [section] "Once D1 is generated, the entire process can be repeated iteratively, generating a new background sample set B1, a new black-box model h1, a new SHAP scores matrix E1, and a new combined dataset D2."
- Break condition: After several iterations, the remaining features may be insufficient for accurate classification, leading to accuracy collapse.

## Foundational Learning

- Concept: SHAP (Shapley Additive exPlanations)
  - Why needed here: SHAP provides the local linear explanations (LLEs) that quantify feature importance per sample, which are the basis for both IDW and TRV feature engineering.
  - Quick check question: How does SHAP ensure that the sum of feature importance scores plus the baseline equals the model's prediction for a given sample?

- Concept: Hadamard (element-wise) product
  - Why needed here: IDW uses the Hadamard product to scale each feature value by its importance weight, effectively modulating the dataset representation.
  - Quick check question: What is the shape of the result when multiplying a feature importance matrix with a data matrix using the Hadamard product?

- Concept: Cognitive load / explanation compactness
  - Why needed here: The metrics XCP and Sim measure how compact and consistent explanations are, guiding the design of streamlined models that are easier for humans to understand.
  - Quick check question: If a model's explanations use only 30% of the original features, what is its XCP value?

## Architecture Onboarding

- Component map: Data → Preprocess → Model f0 → SHAP → Explanation matrix E0 → IDW/TRV → Streamlined dataset D1 → Train h1 → SHAP → New explanations → Evaluate
- Critical path: Preprocess → Train f0 → Compute SHAP → Apply IDW/TRV → Train h1 → Evaluate
- Design tradeoffs: IDW applies a smooth linear transformation to all features but requires iterative recomputation; TRV applies hard masking with a fixed K but needs careful choice of neutral values and K.
- Failure signatures: Accuracy drops sharply, SHAP scores become uniformly small, XCP does not improve despite engineering.
- First 3 experiments:
  1. Train f0 on a small tabular dataset, compute SHAP, apply IDW once, train h1, compare accuracy and XCP.
  2. Repeat with TRV using K=3, compare accuracy, XCP, and Sim scores.
  3. Iterate IDW twice, observe how accuracy and feature importance distributions change.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the Iterative Dataset Weighting (IDW) methodology perform on datasets with hundreds of features compared to the tested datasets with fewer features?
- Basis in paper: [inferred] The paper mentions that the chosen threshold for identifying relevant features requires tuning, and a smaller threshold could be needed for larger datasets.
- Why unresolved: The experiments were conducted on datasets with a limited number of features (ranging from 30 to 43). The performance of IDW on high-dimensional datasets is not explored.
- What evidence would resolve it: Conducting experiments with IDW on datasets with hundreds of features and comparing the results with the current findings would provide insights into its scalability and performance.

### Open Question 2
- Question: Can the streamlining methodologies (IDW and TRV) be effectively applied to regression tasks or image classification tasks?
- Basis in paper: [explicit] The paper states that future work includes exploring the streamlining concept on different learning tasks such as regressions or image classification.
- Why unresolved: The current study focuses on binary classification tasks using tabular datasets. The applicability and effectiveness of IDW and TRV on other types of tasks and data formats are not investigated.
- What evidence would resolve it: Applying IDW and TRV to regression and image classification tasks and evaluating their performance compared to traditional methods would determine their versatility and potential benefits in different domains.

### Open Question 3
- Question: How do the streamlining methodologies (IDW and TRV) impact the fairness of models when dealing with datasets containing protected attributes?
- Basis in paper: [inferred] The paper mentions that fairness metrics were considered to ensure that the feature engineering process did not significantly harm model fairness. However, the impact of IDW and TRV on fairness is not thoroughly explored.
- Why unresolved: The experiments include fairness metrics evaluation, but the specific effects of IDW and TRV on fairness, especially in the presence of protected attributes, are not explicitly discussed or analyzed.
- What evidence would resolve it: Conducting experiments that specifically focus on the fairness implications of IDW and TRV when dealing with datasets containing protected attributes would provide insights into their potential biases and fairness trade-offs.

## Limitations

- The methods assume SHAP explanations from baseline models are reliable and stable enough to drive feature engineering
- Performance on high-dimensional datasets with hundreds of features remains unexplored
- Applicability to regression tasks and image classification has not been investigated

## Confidence

- **SHAP score reliability**: Medium - methods depend on accurate SHAP explanations that may not be stable across model iterations
- **Hyperparameter sensitivity**: Low - K in TRV and iteration count in IDW are treated as hyperparameters without rigorous sensitivity analysis
- **Generalizability**: Low - methods demonstrated only on four small tabular datasets; scalability to other data types is unknown

## Next Checks

1. **Stability test**: Run IDW and TRV with multiple random seeds; quantify variance in XCP and accuracy to assess robustness to stochastic elements (e.g., K-means initialization)

2. **Hyperparameter sweep**: Systematically vary K (for TRV) and iteration count (for IDW) across a range; plot accuracy vs. XCP to identify optimal operating points

3. **Out-of-distribution test**: Apply streamlined models to held-out test data or slightly modified datasets (e.g., feature permutations) to ensure explanations and accuracy are not artifacts of overfitting to training SHAP scores
