# How to Design Translation Prompts for ChatGPT: An Empirical Study

## Quick Facts
- **arXiv ID**: 2304.02182
- **Source URL**: https://arxiv.org/abs/2304.02182
- **Reference count**: 9
- **Key outcome**: Designed prompts specifying translation direction and domain significantly improve ChatGPT translation quality, achieving competitive results with commercial systems for high-resource languages

## Executive Summary
This paper investigates how prompt design affects ChatGPT's machine translation performance. The authors systematically test different prompt strategies including specifying translation direction (TD), data domain (DD), incorporating POS tags, and using few-shot examples. They evaluate these approaches across high-resource (English↔Spanish/French), low-resource (English↔Turkish/Romanian), multi-reference, and domain-specific translation tasks. The study finds that explicit prompt specifications consistently improve translation quality, with few-shot prompting showing particularly robust gains. While ChatGPT still lags behind commercial systems for low-resource translations, the consistent improvements from prompt engineering demonstrate its potential for specialized translation tasks.

## Method Summary
The authors conducted systematic experiments using ChatGPT via web interface with various prompt designs. They prepared datasets including Flores-101 for high/low-resource language pairs, WMT 2014 for multi-reference evaluation, and Hendy et al. (2023) for domain-specific tests. Different prompt types were tested: TP3 (baseline task description), TD (translation direction), DD (domain specification), TD-pos/DD-pos (with POS tags), and few-shot variants. Translation outputs were evaluated using BLEU, ChrF++, and TER metrics, then compared against Google Translate and DeepL baselines. The study employed sampling to select test sentences and used LaBSE similarity for few-shot example selection.

## Key Results
- ChatGPT with TD/DD prompts achieved competitive or superior performance over commercial systems for high-resource translations
- Few-shot prompts provided consistent improvements across different base prompts, with 1-5 shot setups showing substantial gains
- Incorporating POS tags as auxiliary information yielded mixed results, sometimes improving and sometimes degrading performance
- Domain-specific prompts (DD) improved performance on domain-specific datasets when combined with relevant keywords
- ChatGPT still lags in low-resource translations, though prompt engineering provides consistent gains

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Providing explicit translation direction (TD) and domain (DD) information in prompts focuses ChatGPT on the current input data, reducing interference from its general multilingual pretraining
- Mechanism: The model's pretraining on diverse multilingual data creates a "prior knowledge" bias. By specifying TD/DD, the prompt acts as a constraint that shifts the generation distribution toward the desired translation direction and domain-specific language patterns
- Core assumption: The model's response is sensitive to prompt wording and can dynamically adjust its internal bias based on explicit instructions
- Evidence anchors: [abstract], [section 3.1]
- Break condition: If the model's bias from pretraining is too strong, or if the prompt specification is ambiguous, the effect may be negligible or even harmful

### Mechanism 2
- Claim: Incorporating POS tags as auxiliary information can disambiguate word senses and grammatical structure, improving translation accuracy, especially for low-resource languages
- Mechanism: POS tags provide syntactic information that helps the model understand the grammatical role of each word, reducing ambiguity in translation. This is particularly useful when the source and target languages have different grammatical structures
- Core assumption: The model can effectively utilize POS tag information when provided in the prompt
- Evidence anchors: [abstract], [section 3.5]
- Break condition: If the POS tags introduce noise or increase input complexity, the model's performance may degrade, as observed in some translation directions

### Mechanism 3
- Claim: Few-shot prompts (in-context learning) improve ChatGPT's translation performance by providing examples of desired output, especially when the base prompt is less informative (e.g., TP3)
- Mechanism: The model learns from the provided examples and adjusts its generation to match the style and quality of the examples. This is particularly effective when the base prompt lacks specific instructions
- Core assumption: The model can effectively learn from a small number of high-quality examples without parameter updates
- Evidence anchors: [abstract], [section 3.8]
- Break condition: If the examples are of poor quality or not representative of the test data, the model's performance may not improve or may even degrade

## Architecture Onboarding

- **Component map**: Source sentence + prompt -> ChatGPT API -> Translated sentence -> BLEU/ChrF++/TER evaluation
- **Critical path**:
  1. Prepare source sentences and corresponding prompts
  2. Send prompt + source sentence to ChatGPT API
  3. Receive translated output
  4. Evaluate translation quality using chosen metrics
  5. Analyze results and iterate on prompt design
- **Design tradeoffs**:
  - Using more specific prompts (TD/DD) vs. general prompts (TP3): Specific prompts may improve accuracy but could also introduce bias or limit flexibility
  - Incorporating auxiliary information (POS tags) vs. relying on model's internal knowledge: Auxiliary information can disambiguate but may also introduce noise
  - Using few-shot examples vs. relying on base prompt: Few-shot examples can improve performance but require careful selection and may not generalize
- **Failure signatures**:
  - Poor translation quality despite well-designed prompts: May indicate that the model's pretraining bias is too strong or that the prompt specification is ambiguous
  - Degradation in performance when incorporating auxiliary information: May indicate that the auxiliary information is introducing noise or increasing input complexity
  - Inconsistent results across different translation directions: May indicate that the model's performance is influenced by the specific language pair or domain
- **First 3 experiments**:
  1. Compare ChatGPT's performance with TP3 (baseline) vs. TD/DD prompts on a high-resource language pair (e.g., English→French)
  2. Incorporate POS tags into TD/DD prompts and evaluate their impact on low-resource language pairs (e.g., English↔Turkish)
  3. Test few-shot prompts with 1 and 5 examples on a challenging translation direction (e.g., Spanish→English) and compare with 0-shot performance

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What specific types of auxiliary information (beyond POS tags) can be effectively incorporated into ChatGPT prompts to improve low-resource translation performance?
- Basis in paper: The paper discusses incorporating POS tags as auxiliary information but notes instabilities in low-resource translations, suggesting the need to explore other types of auxiliary data
- Why unresolved: The paper only experimented with POS tags and observed mixed results, indicating that other forms of auxiliary information might be more effective or need different integration methods
- What evidence would resolve it: Conducting experiments with various auxiliary information types (e.g., dependency parse trees, named entity recognition, semantic roles) and comparing their impact on translation quality across different resource levels

### Open Question 2
- Question: How does the quality and selection of few-shot examples impact the effectiveness of in-context learning for ChatGPT in translation tasks?
- Basis in paper: The paper performs few-shot experiments but notes that providing more high-quality examples doesn't necessarily lead to greater improvements, suggesting quality and selection matter
- Why unresolved: The paper only uses top-scoring translation pairs based on LaBSE similarity, but doesn't explore how different selection criteria or example diversity affect performance
- What evidence would resolve it: Systematic experiments varying the number, diversity, and selection criteria of few-shot examples while measuring translation quality across different language pairs and domains

### Open Question 3
- Question: What is the optimal balance between domain-specific prompts and general translation prompts for maximizing ChatGPT's performance across diverse translation scenarios?
- Basis in paper: The paper finds that domain-specific prompts (DD) improve performance on domain-specific datasets but observes variability when comparing to translation direction prompts (TD) across different test sets
- Why unresolved: The paper doesn't explore hybrid approaches or systematically compare when each type of prompt is most beneficial, leaving uncertainty about when to prioritize domain information versus translation direction
- What evidence would resolve it: Comparative studies testing various combinations of domain and translation direction information across multiple test sets with different characteristics, measuring performance trade-offs

## Limitations
- The study relies on ChatGPT as a black-box model without access to internal mechanisms, limiting understanding of why prompts work
- Only one version of ChatGPT was tested, leaving open whether results generalize to other model versions
- The study uses predefined prompt templates without exploring the full space of possible prompt variations
- The definition of "low-resource" is based on dataset availability rather than true linguistic resource scarcity

## Confidence
- **High confidence**: The empirical finding that specifying translation direction (TD) and domain (DD) in prompts consistently improves translation quality over the baseline TP3 prompt across multiple language pairs and domains
- **Medium confidence**: The claim that few-shot prompting provides consistent improvements, as this depends heavily on the quality and representativeness of the selected examples
- **Medium confidence**: The observation that POS tags provide mixed results, given that the negative effects observed in some translation directions suggest context-dependent behavior
- **Low confidence**: The interpretation that observed improvements stem primarily from reducing interference from general multilingual pretraining, as this mechanism cannot be directly verified with the black-box model

## Next Checks
