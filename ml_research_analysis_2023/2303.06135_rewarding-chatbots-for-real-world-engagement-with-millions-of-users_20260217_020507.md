# Rewarding Chatbots for Real-World Engagement with Millions of Users

## Quick Facts
- **arXiv ID**: 2303.06135
- **Source URL**: https://arxiv.org/abs/2303.06135
- **Reference count**: 21
- **Primary result**: A/B testing shows up to 70% increase in mean conversation length, translating to 30% higher user retention

## Executive Summary
This paper presents a method for developing social chatbots that prioritize user engagement and retention through automatic pseudo-labeling of conversation data. The approach uses user interaction patterns to generate binary labels indicating engaging versus unengaging responses, which train a reward model that can reject low-scoring responses at inference time. A/B testing on a chatbot platform with 10,000 daily users demonstrates that this method significantly increases conversation length and user retention, particularly when combined with best-of-N rejection sampling and larger reward model training datasets.

## Method Summary
The method involves fine-tuning a base LLM (GPT-J 6B) on literature, then training a reward model (GPT-2 variants) using pseudo-labels derived from user conversation continuation patterns. At inference, the system generates N candidate responses and uses the reward model to select the most engaging one via best-of-N rejection sampling. The pseudo-labels are created by assuming the last K responses in a conversation were unengaging and all previous ones were engaging. The approach is evaluated using mean conversation length (MCL) as a proxy for engagement, with A/B testing showing significant improvements in both conversation length and user retention.

## Key Results
- A/B testing shows up to 70% increase in mean conversation length (MCL)
- This translates to more than 30% increase in user retention for GPT-J 6B model
- Linear scaling observed between log of reward model training data size and MCL improvement
- Best-of-N rejection sampling with N=4 provides optimal balance of engagement gains versus computational cost

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Pseudo-labels derived from conversation continuation serve as effective proxies for user engagement.
- Mechanism: Conversations that continue beyond the current turn are assumed to have received engaging responses, so responses before the final K messages are labeled as engaging (y=1) and the last K as unengaging (y=0).
- Core assumption: Users only stop conversing because they received unengaging responses, not due to external factors.
- Evidence anchors:
  - "Therefore a very natural idea is to assume that the last few system responses were not engaging to the user, and that all previous ones were."
  - "Use of these pseudo-labels is naturally expected to directly optimise the mean conversation length, MCL (Equation 2) engagement evaluation metric."
- Break condition: If user drop-off is driven by factors unrelated to engagement (e.g., time constraints, app crashes), pseudo-labels will misattribute engagement signals.

### Mechanism 2
- Claim: Reward model trained on pseudo-labels can rank generated responses at inference time to improve engagement.
- Mechanism: Best-of-N rejection sampling uses the reward model to select the highest-scoring response from N candidates, replacing the standard response with the one most likely to continue the conversation.
- Core assumption: The reward model's ranking of responses generalizes to new contexts and accurately reflects true engagement.
- Evidence anchors:
  - "A/B testing on groups of 10,000 new daily chatbot users on the Chai Research platform shows that this approach increases the MCL by up to 70%..."
  - "At inference time, N responses are statistically drawn from the fine-tuned chatbot model... and the response with the highest reward score is then selected and given to the user"
- Break condition: If the reward model overfits to training pseudo-labels or fails to generalize, selected responses may not actually improve engagement.

### Mechanism 3
- Claim: Increasing dataset size and model capacity for the reward model improves engagement outcomes.
- Mechanism: Larger training datasets and bigger reward model architectures yield better discrimination between engaging and unengaging responses, leading to greater MCL improvement.
- Core assumption: Reward model performance scales predictably with data and model size.
- Evidence anchors:
  - "The MCL improvement appears to grow linearly with the log of the number of rows that the GPT-2 small reward model was trained on."
  - "We can therefore conclude that in increasing the reward model fine-tuning dataset size by a factor of ten is more than twice as effective at increasing the MCL improvement than increasing the model size by a factor of ten."
- Break condition: If the reward model reaches a performance plateau, further increases in data or size yield diminishing returns.

## Foundational Learning

- **Concept**: Supervised classification with binary labels
  - Why needed here: Reward model must learn to classify responses as engaging (y=1) or unengaging (y=0) using pseudo-labels.
  - Quick check question: If you have 1000 responses labeled as engaging and 200 as unengaging, what class imbalance issue might arise and how would you address it?

- **Concept**: Reinforcement learning from human feedback (RLHF)
  - Why needed here: The paper builds on RLHF methodology, using human-derived signals (pseudo-labels) to train reward models that align chatbot behavior with user preferences.
  - Quick check question: How does using pseudo-labels instead of explicit human rankings change the data collection cost and potential label quality?

- **Concept**: Best-of-N sampling / rejection sampling
  - Why needed here: At inference time, multiple responses are generated and the reward model selects the most engaging one, improving user experience without retraining the base model.
  - Quick check question: If N=4 and each response takes 50ms to generate, what is the total added latency to each user turn?

## Architecture Onboarding

- **Component map**: User -> Base LLM (GPT-J 6B) -> N candidate responses -> Reward Model (GPT-2) -> Selector -> Highest-scoring response -> User
- **Critical path**:
  1. User sends message to chatbot
  2. Base LLM generates N candidate responses
  3. Reward model scores each candidate
  4. Highest-scoring response is selected and sent to user
  5. User interaction data (continuation, retry, rating) is logged for pseudo-label creation

- **Design tradeoffs**:
  - N vs latency: Higher N improves selection quality but increases response time
  - Context window size: Larger windows may capture more relevant history but increase computational cost
  - Pseudo-label type: Conversation continuation vs retry prediction vs star rating each optimize different engagement aspects

- **Failure signatures**:
  - MCL stagnates or decreases despite reward model updates
  - High retry rate indicates reward model consistently selects poor responses
  - User retention drops, suggesting the model is optimizing for short-term engagement at the cost of long-term satisfaction

- **First 3 experiments**:
  1. Compare baseline (no reward model) vs reward model with N=4, K=1 pseudo-labels on conversation continuation
  2. Vary context window size (128, 256, 512 tokens) while keeping other parameters fixed to measure impact on MCL improvement
  3. Test different pseudo-label strategies (continuation vs retry prediction) to determine which yields higher retention

## Open Questions the Paper Calls Out

### Open Question 1
- **Question**: How does the reward model's performance scale with dataset size beyond the tested range (e.g., 100M+ rows)?
- **Basis in paper**: [explicit] The paper observes linear scaling with log of dataset size up to 48M rows and mentions future work to use latest user conversations for fine-tuning.
- **Why unresolved**: The study only tested up to 48M rows; scaling behavior beyond this point remains unknown.
- **What evidence would resolve it**: A/B testing with reward models trained on datasets of 100M+ rows, measuring MCL improvement and retention rates.

### Open Question 2
- **Question**: What is the optimal balance between number of samples (N) and inference latency for maximizing user engagement?
- **Basis in paper**: [explicit] The paper finds linear improvement in MCL with log(N) but also observes negative impact of added latency on MCL.
- **Why unresolved**: The paper suggests an optimal N of 26.42±0.32 but doesn't test this range experimentally.
- **What evidence would resolve it**: A/B testing varying N from 4 to 100+ samples, measuring both MCL improvement and actual latency impact on user retention.

### Open Question 3
- **Question**: How do different reward model architectures (e.g., RoBERTA vs GPT-2) compare in terms of engagement improvement?
- **Basis in paper**: [explicit] The paper mentions RoBERTA-based reward models in Section 5.1 but only tests GPT-2 models.
- **Why unresolved**: The study focuses exclusively on GPT-2 based reward models, leaving comparison with alternative architectures unexplored.
- **What evidence would resolve it**: A/B testing comparing GPT-2 and RoBERTA reward models with matched parameters, measuring MCL improvement and user retention.

### Open Question 4
- **Question**: What is the long-term impact of reward model fine-tuning on chatbot performance (e.g., after 6+ months of deployment)?
- **Basis in paper**: [inferred] The paper mentions a "data fly-wheel" approach for future work and observes improvements over 30-day retention periods.
- **Why unresolved**: The study only examines short-term effects (up to 30 days) and doesn't test the proposed iterative fine-tuning approach.
- **What evidence would resolve it**: Longitudinal study tracking chatbot performance over 6+ months with periodic reward model updates using recent conversations.

## Limitations

- The effectiveness of pseudo-labeling relies heavily on the assumption that conversation termination is primarily driven by unengaging responses, which remains untested against external factors.
- The A/B testing results show correlation between MCL improvement and retention gains, but the causal mechanism linking these metrics remains unclear.
- The reward model's generalization capabilities across diverse user populations and conversation topics are not thoroughly examined.

## Confidence

- **High confidence**: The technical implementation of best-of-N rejection sampling is sound and well-documented.
- **Medium confidence**: The scaling relationships between dataset size, model capacity, and MCL improvement are supported by empirical evidence, though the analysis is limited to specific reward model architectures.
- **Low confidence**: The claim that the approach translates to a "more than 30% increase in user retention" is based on aggregate metrics without establishing the causal mechanism or controlling for confounding variables.

## Next Checks

1. **Pseudo-label validity validation**: Conduct a user study where human annotators rate the same responses used to generate pseudo-labels, comparing human engagement scores against pseudo-label assignments to quantify labeling accuracy and identify systematic biases.

2. **Retention mechanism analysis**: Implement a randomized controlled trial varying only conversation length (via forced response generation) while holding other factors constant, measuring whether MCL directly causes retention changes or if both respond to shared quality factors.

3. **Generalization stress test**: Deploy the reward model across diverse user segments and conversation topics, measuring performance variance to identify whether the approach maintains effectiveness across different user demographics, cultural contexts, and conversation domains.
