# Augmenting data-driven models for energy systems through feature engineering: A Python framework for feature engineering

## Quick Facts
- arXiv ID: 2301.01720
- Source URL: https://arxiv.org/abs/2301.01720
- Reference count: 37
- Primary result: Python framework for feature engineering improves energy demand prediction accuracy in building energy systems

## Executive Summary
This paper introduces a Python framework for feature engineering designed to enhance data-driven models in energy systems. The framework implements methods for feature creation (cyclic and categorical encoding), expansion (polynomial and spline), selection (correlation-based), and transformation (filtering, Box-Cox). A case study on energy demand prediction in a mixed office-campus building demonstrates the framework's effectiveness, with an engineered model achieving significantly better performance than a basic linear regression model across multiple metrics including R², CV-RMSE, and MAPE.

## Method Summary
The framework provides a scikit-learn compatible pipeline for feature engineering in energy systems. It implements four main categories of methods: feature creation (including cyclic encoding for time-based features and categorical encoding), feature expansion (polynomial features and spline transformations), feature selection (correlation-based selection using Pearson correlation coefficient), and feature transformation (filtering techniques like Butterworth filtering and Box-Cox transformations). The framework is demonstrated on a case study using hourly energy consumption data from a mixed office-campus building, comparing a basic linear regression model against an engineered model that incorporates the framework's preprocessing methods.

## Key Results
- Engineered model achieves R² of 0.638, CV-RMSE of 0.201, and MAPE of 17.493%
- Basic model performance: R² 0.548, CV-RMSE 0.267, MAPE 22.764%
- Timeseries analysis shows cyclic behavior of day-night changes is more accurately replicated by the engineered model
- Prediction error plots confirm reduced residual error in the engineered model

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Cyclic encoding of time-based features captures periodic patterns in energy demand
- Mechanism: Sinusoidal signals model periodic phenomena (day/night cycles, seasonal trends) by transforming discrete time values into continuous cyclic features
- Core assumption: Energy demand exhibits periodic dependencies that are better captured by continuous cyclic representations than discrete time features
- Evidence anchors: [abstract] "The timeseries analysis showed that the cyclic behavior of the day-night changes in the energy demand could be more accurately replicated by the model with engineered features."

### Mechanism 2
- Claim: Feature selection using Pearson Correlation Coefficient removes redundant features and improves model generalization
- Mechanism: Threshold-based selection discards features with low correlation to the target variable, reducing multicollinearity and model complexity
- Core assumption: Low correlation features contribute little to prediction accuracy and may cause overfitting
- Evidence anchors: [section II.B] "While the Pearson correlation identifies linear correlations, non-linear dependencies are not detected."

### Mechanism 3
- Claim: Dynamic timeseries unrolling creates lagged features that capture temporal dependencies in energy consumption
- Mechanism: Convolution with Kronecker delta creates delayed versions of input features, allowing the model to learn temporal patterns
- Core assumption: Current energy consumption depends on past values of relevant features
- Evidence anchors: [section II.A] "The framework implements a method of dynamic timeseries unrolling to create features xn−1, xn−2, ... xn−N from an existing feature x."

## Limitations
- Limited generalizability due to single building type case study
- Framework effectiveness for other energy systems not demonstrated
- Computational efficiency for large-scale implementations not evaluated

## Confidence
Confidence in the main claims is **Medium**. The paper provides clear methodology and reproducible code, with performance metrics showing improvement from feature engineering. However, the case study is limited to a single building type and one-year dataset, restricting generalizability.
