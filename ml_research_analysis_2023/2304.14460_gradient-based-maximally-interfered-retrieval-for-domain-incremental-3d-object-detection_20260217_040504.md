# Gradient-based Maximally Interfered Retrieval for Domain Incremental 3D Object Detection

## Quick Facts
- arXiv ID: 2304.14460
- Source URL: https://arxiv.org/abs/2304.14460
- Authors: 
- Reference count: 30
- Primary result: GMIR eliminates catastrophic forgetting and improves performance on both clear and adverse weather domains compared to naive fine-tuning, achieving competitive mAP to scratch training with 46.25% reduction in training time.

## Executive Summary
This paper addresses catastrophic forgetting in 3D object detection models when adapting from clear to adverse weather domains. The authors propose Gradient-based Maximally Interfered Retrieval (GMIR), an offline replay-based continual learning method that periodically selects samples from the old domain whose gradients maximally interfere with the current update, to be replayed during fine-tuning. GMIR is evaluated on the STF dataset using PointRCNN and VoxelRCNN, showing that it not only eliminates forgetting but also improves performance on both domains compared to scratch training. With a replay buffer size of 5% and a 46.25% reduction in training time, GMIR outperforms naive fine-tuning, regularization methods, and other replay baselines in terms of backward and forward transfer.

## Method Summary
GMIR periodically retrieves samples from the previous domain dataset whose gradient vectors show maximal interference with the gradient vector of the current update. During finetuning on new domain data, the model periodically re-samples the replay buffer to keep samples whose gradient vectors have high negative cosine similarity with the current update direction. This ensures that parameters are updated in a way that minimizes loss increase on old domain data. Instead of updating replay samples every iteration (as in MIR), GMIR resamples every n epochs. By selecting top K maximally interfering samples from the old dataset, GMIR captures the most critical forgetting cases without needing the entire old dataset in memory.

## Key Results
- GMIR eliminates catastrophic forgetting when adapting from clear to adverse weather domains
- Achieves competitive mAP to scratch training on all data with only 5% replay buffer size
- Provides 46.25% reduction in training time compared to scratch training while maintaining performance

## Why This Works (Mechanism)

### Mechanism 1
- Claim: GMIR mitigates catastrophic forgetting by periodically replacing replay samples with those whose gradients maximally interfere with the current parameter update.
- Mechanism: During finetuning on new domain data, the model periodically re-samples the replay buffer to keep samples whose gradient vectors have high negative cosine similarity with the current update direction. This ensures that parameters are updated in a way that minimizes loss increase on old domain data.
- Core assumption: Gradient direction misalignment between current update and old domain samples directly correlates with forgetting risk.
- Evidence anchors:
  - [abstract]: "GMIR periodically retrieves samples from the previous domain dataset whose gradient vectors show maximal interference with the gradient vector of the current update."
  - [section III. METHOD]: Interference score is defined as I(xi,yi) = −⟨g,gi⟩/∥g∥∥gi∥, explicitly using negative cosine similarity between gradient vectors.
  - [corpus]: No direct evidence; corpus focuses on weather robustness but not on gradient interference sampling.
- Break condition: If gradient interference is not a reliable proxy for forgetting risk, or if gradients become too noisy, the selection may degrade performance.

### Mechanism 2
- Claim: Periodic resampling of the replay buffer balances stability and adaptability, improving both backward and forward transfer.
- Mechanism: Instead of updating replay samples every iteration (as in MIR), GMIR resamples every n epochs. This allows the model to converge more stably on each replay buffer before changing it, reducing noisy updates.
- Core assumption: Longer dwell time on each replay buffer leads to more stable optimization and better minima for both old and new domains.
- Evidence anchors:
  - [section III. METHOD]: "We periodically resample the old domain samples to update the replay buffer with the latest interfering samples."
  - [section V. RESULTS AND DISCUSSION]: "resampling every 10 epochs instead of every epoch allows the model to iteratively learn on the same group of samples for more iterations, which results in better performance."
  - [corpus]: No direct evidence; related work does not discuss epoch-based resampling frequency.
- Break condition: If n is too small, updates are too noisy; if n is too large, the replay buffer may become stale and miss new forgetting patterns.

### Mechanism 3
- Claim: Using only a small subset (e.g., 5%) of old domain data in the replay buffer is sufficient to prevent forgetting due to redundancy in LiDAR point clouds.
- Mechanism: By selecting top K maximally interfering samples from the old dataset, GMIR captures the most critical forgetting cases without needing the entire old dataset in memory.
- Core assumption: LiDAR point clouds contain redundant information, so a small diverse set of high-interference samples suffices to represent forgetting risk.
- Evidence anchors:
  - [section V. RESULTS AND DISCUSSION]: "A striking revelation is that D = 20% gives similar average performance compared to D = 50% and D = 100%."
  - [section IV. EXPERIMENTS]: "We can conclude that GMIR provides the best performance and time tradeoff."
  - [corpus]: No direct evidence; corpus does not discuss data redundancy in replay buffers.
- Break condition: If the old dataset lacks redundancy or if high-interference samples are not representative, performance may degrade.

## Architecture Onboarding

- Component map: Pretrained 3D object detector (PointRCNN/VoxelRCNN) -> GMIR sample selector (interference scoring) -> Replay buffer of old domain samples -> Joint training on new domain + replay buffer
- Critical path: Forward pass on old domain samples -> Compute gradient interference score -> Select top K interfering samples -> Populate replay buffer -> Train on new domain + replay buffer
- Design tradeoffs: Higher D increases memory usage but may improve forgetting prevention; lower D reduces time but risks forgetting. Higher K improves coverage but increases compute. Lower n increases update frequency but may destabilize training.
- Failure signatures: If forgetting occurs, replay buffer likely lacks diverse or high-interference samples. If forward transfer is poor, replay buffer may dominate training and slow new domain learning.
- First 3 experiments:
  1. Compare GMIR with naive finetuning on PointRCNN to verify forgetting reduction.
  2. Vary K (e.g., 1%, 5%, 10%) to find the smallest effective buffer size.
  3. Compare epoch-based resampling (n=10) vs iteration-based resampling (as in MIR) to validate stability benefits.

## Limitations

- The effectiveness of GMIR relies heavily on the assumption that gradient interference is a reliable proxy for forgetting risk, which is not empirically validated beyond observed performance gains.
- The optimal replay buffer size (K) and resampling frequency (n) appear dataset-dependent and may not generalize to other domains or modalities.
- The paper does not address potential class imbalance effects between clear and adverse weather data, which could bias interference score calculations.

## Confidence

- High confidence: The core mechanism of using gradient interference for sample selection is well-defined and consistently applied across experiments.
- Medium confidence: Claims about data redundancy in LiDAR point clouds reducing required replay buffer size are supported by ablation results but lack theoretical justification.
- Low confidence: The assertion that GMIR "improves performance on both domains compared to scratch training" requires careful interpretation, as it depends on the specific initialization and domain characteristics.
