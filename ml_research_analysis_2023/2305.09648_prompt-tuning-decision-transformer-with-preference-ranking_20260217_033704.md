# Prompt-Tuning Decision Transformer with Preference Ranking

## Quick Facts
- arXiv ID: 2305.09648
- Source URL: https://arxiv.org/abs/2305.09648
- Reference count: 40
- One-line primary result: Prompt-Tuning DT achieves comparable performance to full-model fine-tuning using only 0.03% of parameters in low-data scenarios

## Executive Summary
This paper introduces Prompt-Tuning DT, a method that optimizes trajectory segment prompts to guide reinforcement learning agents without updating the full model parameters. The approach uses Gaussian noise perturbations and a preference ranking oracle to perform black-box optimization of prompts, achieving parameter efficiency while maintaining competitive performance. Extensive experiments demonstrate that this method can match or exceed full-model fine-tuning in low-data regimes, making it particularly valuable for few-shot generalization tasks.

## Method Summary
Prompt-Tuning DT optimizes trajectory prompts rather than full model parameters to guide Decision Transformers in RL tasks. The method starts with expert trajectory segments as initial prompts, then uses ZO-RankSGD to optimize these prompts via Gaussian noise perturbations and preference ranking oracles. The ranking oracle can be either an offline loss function using pre-collected data or an online reward function from environment interactions. This approach achieves significant parameter efficiency by tuning only prompt tokens (0.03% of total parameters) while maintaining performance comparable to full-model fine-tuning.

## Key Results
- Prompt-Tuning DT achieves comparable performance to full-model fine-tuning with limited ranking oracle calls
- Fine-tuning dataset size significantly impacts the effectiveness of the prompt-tuning approach
- The quality and quantity of the prompt influence the effectiveness of the prompt-tuning approach

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Gaussian noise perturbations enable gradient-free optimization of prompts in RL contexts.
- Mechanism: The approach introduces Gaussian noise to trajectory prompts and uses a preference ranking oracle to determine the optimization direction without requiring explicit gradient computation.
- Core assumption: The ranking oracle can provide meaningful preference information between perturbed prompts that correlates with improved task performance.
- Evidence anchors:
  - [abstract] "Our approach involves randomly sampling a Gaussian distribution to fine-tune the elements of the prompt trajectory and using preference ranking function to find the optimization direction"
  - [section 3.2] "With the ranking oracle O(m,k)_f and a starting point x, we can query O(m,k)_f with the inputs x_i = x + μξ_i, ξ_i ~ N(0,I_d), for i = 1,...,m"
  - [corpus] "Found 25 related papers (using 8). Average neighbor FMR=0.522, average citations=0.0" - Weak corpus evidence for this specific mechanism
- Break condition: If the ranking oracle cannot distinguish between meaningful and random prompt variations, or if the Gaussian noise scale μ is inappropriate for the prompt space.

### Mechanism 2
- Claim: Trajectory segments as prompts can guide RL agents in acquiring environmental information.
- Mechanism: The method represents prompts as sequences of state-action-reward triplets (trajectory segments) that condition the Decision Transformer to predict actions for new tasks.
- Core assumption: The trajectory prompt contains sufficient information about the task structure while being shorter than the full task horizon.
- Evidence anchors:
  - [abstract] "using trajectory segments as prompts to guide RL agents in acquiring environmental information"
  - [section 3.1] "Prompt-DT defines a trajectory prompt as a sequence of a few trajectory segments. Each trajectory segment contains multiple tuples of states*, action a* and reward-to-go r*"
  - [section 4.2] "the trajectory prompt utilized in the decision transformer comprises tokens that possess distinct expressions and physical meanings"
- Break condition: If the prompt length K* is too short to capture task-relevant information or too long causing overfitting.

### Mechanism 3
- Claim: Prompt-tuning with ranking optimization can achieve comparable performance to full-model fine-tuning while using only 0.03% of parameters.
- Mechanism: By optimizing only the prompt tokens rather than all model parameters, the method achieves significant parameter efficiency while maintaining performance.
- Core assumption: The pre-trained Decision Transformer contains sufficient knowledge that can be effectively steered by prompt optimization rather than parameter updates.
- Evidence anchors:
  - [abstract] "with only 0.03% of the parameters learned, Prompt-Tuning DT achieves comparable or even better performance than full-model fine-tuning"
  - [section 4.1] "Our approach combines the advantages of both approaches to fine-tune the prompts"
  - [section 5.3] "all three fine-tuning methods outperform Prompt-DT, with prompt-tuning achieving comparable or superior performance to full-model fine-tuning while utilizing only approximately 0.03% of the parameters"
- Break condition: If the pre-trained model lacks sufficient task-relevant knowledge or if the prompt space is too constrained for effective adaptation.

## Architecture Onboarding

- Component map:
  Pre-trained Decision Transformer -> Trajectory prompt (K* tokens) -> Gaussian noise generator -> Preference ranking oracle -> Optimization loop

- Critical path:
  1. Initialize prompt from expert trajectories
  2. Generate m perturbed prompts using Gaussian noise
  3. Evaluate each prompt using ranking oracle (offline loss or online reward)
  4. Construct DAG from rankings and compute rank-based gradient estimator
  5. Update prompt using computed gradient direction
  6. Repeat for T iterations
  7. Deploy optimized prompt for evaluation

- Design tradeoffs:
  - Parameter efficiency vs. adaptation capability: Tuning only 0.03% of parameters limits expressivity but saves memory
  - Prompt length vs. information content: Longer prompts capture more task information but increase computational cost
  - Ranking oracle type: Offline loss function requires pre-collected data while online reward function needs environment access

- Failure signatures:
  - Performance degradation with random prompt initialization
  - Catastrophic deviation early in fine-tuning process
  - Lack of monotonic improvement with increasing fine-tuning samples
  - Sensitivity to Gaussian noise scale μ

- First 3 experiments:
  1. Verify prompt-tuning matches full-model fine-tuning on a simple task with known optimal prompt
  2. Test sensitivity to prompt length K* by varying from 2 to 10 tokens
  3. Evaluate performance degradation when ranking oracle provides random preferences instead of meaningful rankings
