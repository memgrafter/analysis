# Continual Learning with Scaled Gradient Projection

## Quick Facts
- arXiv ID: 2302.01386
- Source URL: https://arxiv.org/abs/2302.01386
- Reference count: 40
- Key outcome: Up to 3.5% higher accuracy and 12% more accumulated reward in RL tasks compared to state-of-the-art methods

## Executive Summary
This paper introduces Scaled Gradient Projection (SGP), a continual learning method that combines orthogonal gradient projections with scaled gradient updates along important gradient spaces of past tasks. The method uses singular value decomposition (SVD) on input representations to identify and store bases of important gradient spaces, then scales gradient updates based on the importance of these bases. SGP achieves better performance than previous methods while using less memory and computational overhead.

## Method Summary
SGP addresses continual learning by decomposing gradients into orthogonal and along-components relative to past important gradient spaces. During training, orthogonal components are preserved while along-components are scaled based on importance values derived from singular values of input representations. The method accumulates importance vectors over tasks, gradually restricting updates along frequently used directions while allowing new learning in unconstrained spaces. This approach balances plasticity for new tasks with stability for preserving past knowledge without requiring replay buffers or storing raw data.

## Key Results
- Up to 3.5% higher accuracy on image classification tasks compared to state-of-the-art methods
- 12% more accumulated reward in reinforcement learning tasks
- Less training overhead and memory usage than competing approaches
- Better backward transfer (BWT) while maintaining forward transfer

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Scaled gradient updates along important gradient spaces reduce forgetting while improving new task learning
- Mechanism: Gradients are decomposed into orthogonal and along-components relative to past important gradient spaces. The orthogonal component is preserved, while the along-component is scaled based on importance values from singular values of input representations
- Core assumption: Singular values of input representations reflect the importance of gradient directions for past tasks
- Evidence anchors: Abstract states importance depends on singular values from SVD; section 3 describes efficient importance computation using SVD
- Break condition: If singular value distribution doesn't correlate with gradient importance, scaling may be suboptimal

### Mechanism 2
- Claim: Accumulated importance vectors dynamically adapt to task sequence, maintaining balance between preserving past knowledge and allowing new learning
- Mechanism: After each task, importance of existing bases is updated by adding new task projections onto those bases. This accumulation pushes importance toward 1 over time, gradually restricting updates along those directions
- Core assumption: Importance of a basis for past tasks can be inferred from its contribution to representing current task data
- Evidence anchors: Section 3 describes accumulated importance updates; section 4 explains gradual restriction along directions to prevent forgetting
- Break condition: If projection-based importance transfer doesn't accurately reflect true past task importance, accumulated vector may misguide scaling

### Mechanism 3
- Claim: Using SVD on input representations efficiently identifies core gradient spaces without storing past task data
- Mechanism: For each task, SVD is performed on input representations to find top-k singular vectors spanning most important gradient space. These bases are stored and their importance derived from singular value distribution
- Core assumption: Subspace spanned by top singular vectors of input representations is equivalent to subspace of important gradients for that task
- Evidence anchors: Section 3 describes SVD on input representations; references Saha et al. showing bases equivalently span important gradient space
- Break condition: If input representation subspace doesn't align with gradient subspace due to nonlinear transformations, identified bases may not effectively constrain forgetting

  - Why needed here: Method aims to solve catastrophic forgetting by controlling gradient updates

## Architecture Onboarding

- Component map: Input representation matrix construction -> SVD module -> Basis storage (GPM) -> Importance computation -> Gradient projection and scaling -> Accumulator

- Critical path:
  1. Forward pass to build representation matrix
  2. SVD to extract bases and singular values
  3. Importance calculation and accumulation
  4. During training: gradient decomposition → orthogonal projection → scaled update
  5. Repeat for each layer and task

- Design tradeoffs:
  - Memory vs. performance: Storing more bases (larger k) improves forgetting resistance but increases memory usage
  - Training time vs. accuracy: Computing SVD and importance adds overhead but enables better balance than strict orthogonal projection
  - Hyperparameter sensitivity: Choice of scale coefficient α and threshold ϵth affects performance; requires tuning per dataset

- Failure signatures:
  - High forgetting despite scaling: Importance values may be poorly estimated; check singular value distributions
  - Poor new task learning: Scaling may be too restrictive; try reducing α or increasing k
  - Degraded performance over long task sequences: Accumulated importance may overly constrain; consider resetting or decaying importance

- First 3 experiments:
  1. Implement on simple two-task split MNIST with small MLP; verify SGP reduces forgetting compared to GPM
  2. Vary α on CIFAR-100 split; observe trade-off between ACC and BWT
  3. Measure training time overhead on miniImageNet; compare to GPM and TRGP

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does choice of α impact trade-off between plasticity and stability in SGP across different network architectures and datasets?
- Basis in paper: Explicit - paper mentions α controls balance between SGP and GPM, provides examples of α values for different datasets
- Why unresolved: While examples are provided, comprehensive analysis across wider range of scenarios is missing
- What evidence would resolve it: Systematic study of α impact on SGP performance across different architectures, datasets, and task sequences

### Open Question 2
- Question: How does performance of SGP compare to other continual learning methods when number of tasks or complexity of tasks increases?
- Basis in paper: Inferred - paper shows better performance on tested datasets but doesn't explore scenarios with significantly larger number of tasks or more complex tasks
- Why unresolved: Paper only tests SGP on limited number of tasks and datasets
- What evidence would resolve it: Testing SGP on wider range of datasets with larger number of tasks or more complex tasks

### Open Question 3
- Question: Can SGP be extended to other continual learning setups beyond task-incremental learning, such as class-incremental learning or domain-incremental learning?
- Basis in paper: Inferred - paper focuses on task-incremental learning where each task has separate classifier head, doesn't explore other setups
- Why unresolved: Paper only explores one type of continual learning setup
- What evidence would resolve it: Adapting SGP to other continual learning setups and evaluating performance

## Limitations

- The assumption that singular values of input representations accurately reflect gradient importance has not been rigorously validated, especially in deep networks with nonlinear transformations
- Experimental results show improvements but lack statistical significance testing across multiple runs
- Hyperparameter selection (α, k, ϵth) appears dataset-dependent without clear optimal selection guidelines
- Reinforcement learning comparisons are limited to only two baselines, missing potentially stronger competitors

## Confidence

- High: The general framework of combining orthogonal projection with importance-based scaling is technically sound
- Medium: Experimental results show consistent improvements over GPM, but statistical significance is unclear
- Low: The assumption that input representation SVD captures gradient importance is asserted but not empirically validated

## Next Checks

1. Conduct statistical significance testing (e.g., paired t-tests) across multiple random seeds for all reported experiments
2. Perform ablation studies varying k and α to establish sensitivity and optimal ranges
3. Test the method on a simpler dataset (e.g., split MNIST) with controlled experiments to verify that singular values indeed correlate with gradient importance for past tasks
