# RepCL: Exploring Effective Representation for Continual Text Classification

## Quick Facts
- arXiv ID: 2305.07289
- Source URL: https://arxiv.org/abs/2305.07289
- Reference count: 32
- Primary result: RepCL achieves average accuracies of 85.6% on FewRel, 78.6% on TACRED, 75.9% on MA VEN, and 84.8% on HWU64, outperforming state-of-the-art methods

## Executive Summary
This paper addresses catastrophic forgetting in continual text classification by proposing RepCL, a replay-based method that mitigates representation bias through contrastive and generative learning. The key insight is that representation bias occurs when models learn task-specific features that fail to generalize across tasks, which can be addressed by learning class-relevant features rather than task-irrelevant noise. RepCL combines contrastive learning to maximize mutual information between same-class instances with generative learning via cross-masked language modeling to encourage class-discriminative representations. Additionally, it introduces an adversarial replay strategy to prevent overfitting during memory replay.

## Method Summary
RepCL employs a two-stage training framework with BERT-base encoder, using contrastive learning (SupInfoNCE), generative learning (cross-masked language modeling), and adversarial replay with FreeLB. During initial training, the model learns on current task data with CE + Lcon + Lxmlm losses. Memory selection uses K-means clustering to store exemplars, followed by memory replay with CE + Ladv losses. The contrastive component uses a momentum encoder and projection layers to maximize mutual information between same-class instances, while XMLM concatenates main branch representations with masked tokens from same-class instances to encourage class-relevant features.

## Key Results
- RepCL consistently outperforms state-of-the-art methods across three tasks (relation extraction, event classification, intent detection)
- Achieves average accuracies of 85.6% on FewRel, 78.6% on TACRED, 75.9% on MA VEN, and 84.8% on HWU64
- Demonstrates lower forgetting rates compared to baselines through effective representation learning
- Ablation studies confirm the individual contributions of contrastive learning, generative learning, and adversarial replay mechanisms

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Representation bias in continual learning arises from the information bottleneck compression discarding task-irrelevant but class-relevant features needed for future tasks.
- Mechanism: During individual task training, the IB compression term I(X;Z) is minimized, which inadvertently removes features that are not useful for the current task but could be useful for distinguishing future classes.
- Core assumption: Features that are useful for distinguishing between classes within a task are likely to remain useful across tasks, even if the specific classes change.
- Evidence anchors:
  - [abstract] "Recent CL studies find that the representations learned in one task may not be effective for other tasks, namely representation bias problem."
  - [section 4.2] "Due to the compression effect of IB, the learned representations in each individual task may be insufficient for the entire continual task."
  - [corpus] Weak - no direct mentions of IB or representation bias in neighbors.

### Mechanism 2
- Claim: Contrastive learning maximizes mutual information between representations of instances from the same class, capturing more class-relevant features.
- Mechanism: By using SupInfoNCE loss, the model pulls representations of same-class instances together and pushes apart representations of different-class instances, encouraging the model to learn features that distinguish classes.
- Core assumption: The mutual information between same-class instances is a good proxy for class-relevant features that will be useful across tasks.
- Evidence anchors:
  - [section 5.1] "We use contrastive loss SupInfoNCE... as a proxy to maximize a lower bound on I(f(X);f(X+)) to learn more class-relevant features."
  - [section 7.1] "We find that the three core mechanisms of RepCL... are conducive to the model performance."
  - [corpus] Weak - no direct mentions of contrastive learning in neighbors.

### Mechanism 3
- Claim: Generative learning via cross-masked language modeling encourages representations to contain more class-relevant information by requiring them to help reconstruct corrupted sentences from the same class.
- Mechanism: The XMLM objective concatenates the main branch representation with masked tokens from a same-class instance, forcing the model to learn representations that contain information useful for recovering class-specific content.
- Core assumption: If a representation contains class-relevant information, it will be helpful for reconstructing other instances from the same class.
- Evidence anchors:
  - [section 5.2] "The generative objective instructs the representation learning process through reconstructing corrupted sentences from the same class, which implicitly makes the model capture more class-relevant features."
  - [section 7.1] "We attribute this to the fact that negative instances for contrastive learning are not sampled from the whole input space... we additionally introduce a novel cross masked language modeling (XMLM) training objective."

## Architecture Onboarding

- Component map: BERT-base encoder -> Momentum encoder (EMA-updated) -> Projection layer -> Contrastive loss -> Classifier MLP
- Critical path:
  1. Initial training: Train on current task data with CE + Lcon + Lxmlm losses
  2. Memory selection: Cluster representations and store exemplars
  3. Memory replay: Train on balanced memory with CE + Ladv losses
- Design tradeoffs:
  - Using EMA momentum encoder vs. storing all encoder weights: Saves memory but may have stale gradients
  - Using XMLM vs. vanilla MLM: XMLM explicitly encourages class-relevant features but adds complexity
  - Using adversarial replay vs. standard replay: May better recover old knowledge but adds training time
- Failure signatures:
  - If contrastive learning is ineffective: I(Z;Z+) will be low and final accuracy will suffer
  - If XMLM is ineffective: Replacing it with MLM should lead to performance drop
  - If adversarial replay is ineffective: Performance will degrade with smaller memory sizes
- First 3 experiments:
  1. Ablation study removing Lcon to measure its impact on I(Z;Z+) and final accuracy
  2. Ablation study removing Lxmlm to compare with vanilla MLM
  3. Vary memory size (M=5,10,20) to measure dependence on replay buffer

## Limitations

- The analysis of representation bias relies heavily on proxy metrics (MI and averaged cosine similarity) that may not fully capture the semantic nature of the bias
- The claim that contrastive learning maximizes class-relevant information assumes mutual information between same-class instances is a reliable indicator of useful features for future tasks, but this relationship is not rigorously proven
- The XMLM objective's effectiveness depends on the assumption that reconstructing same-class instances requires class-relevant features, which may not hold for all text classification tasks

## Confidence

- **High Confidence**: The empirical results showing RepCL outperforming baseline methods on the four benchmark datasets, with average accuracies ranging from 75.9% to 85.6% and lower forgetting rates compared to baselines.
- **Medium Confidence**: The theoretical claims about representation bias arising from information bottleneck compression and the effectiveness of maximizing mutual information for capturing class-relevant features.
- **Low Confidence**: The specific implementation details of the contrastive learning component, particularly the temperature values used in SupInfoNCE and the exact handling of multiple positive samples.
