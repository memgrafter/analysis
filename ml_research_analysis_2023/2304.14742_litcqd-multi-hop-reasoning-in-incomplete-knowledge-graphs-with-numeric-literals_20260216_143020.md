# LitCQD: Multi-Hop Reasoning in Incomplete Knowledge Graphs with Numeric Literals

## Quick Facts
- arXiv ID: 2304.14742
- Source URL: https://arxiv.org/abs/2304.14742
- Reference count: 0
- Key outcome: LitCQD achieves higher MRR and Hits@k scores than prior methods on multi-hop queries with numeric literals

## Executive Summary
LitCQD is a neural reasoning approach for answering multi-hop queries on incomplete knowledge graphs that include numeric literals. It extends the CQD framework by integrating a knowledge graph embedding model (e.g., ComplEx-N3) for predicting missing entities/relations with a literal-aware embedding model (e.g., TransEA) for predicting missing numeric attribute values. The method supports two key query types: (1) entity answers with numerical filtering conditions, and (2) literal answers via aggregation functions. LitCQD introduces continuous attribute filter functions with existence checks to efficiently handle incomplete attribute data.

## Method Summary
LitCQD extends CQD by combining a KGE model (ComplEx-N3) that predicts missing entities/relations with a literal KGE model (TransEA) able to predict missing numerical literal values. The two embedding models are trained jointly using a combined loss function. For query answering, LitCQD uses beam search with t-norm aggregation to recursively apply projection and filtering operations. Continuous attribute filter functions with existence checks handle incomplete numeric attributes during query answering.

## Key Results
- LitCQD achieves higher MRR and Hits@k scores than prior methods on non-literal queries (e.g., 0.301 MRR vs 0.295 for CQD)
- Outperforms baselines on literal queries (e.g., 0.050 MAE on average age prediction)
- Enables new query types involving numeric filters and predictions that were previously unsupported

## Why This Works (Mechanism)

### Mechanism 1
LitCQD extends CQD by combining ComplEx-N3 (for entity/relation prediction) with TransEA (for numeric literal prediction) to jointly learn embeddings that incorporate both graph structure and attribute values. The two embedding models are trained jointly using a combined loss function. Core assumption: Joint training of entity/relation and literal embeddings improves generalization compared to training them separately.

### Mechanism 2
LitCQD introduces continuous attribute filter functions with existence checks to handle incomplete numeric attributes during query answering. For each attribute filter (lt, gt, eq), LitCQD computes a score based on the predicted attribute value and the query threshold, then multiplies by an existence score from a dummy relation. Core assumption: The existence predictor accurately reflects whether an entity actually has a given attribute.

### Mechanism 3
LitCQD's beam search with t-norm aggregation can answer complex queries involving both entity and literal predicates by recursively applying projection and filtering operations. The beam search maintains a set of candidate entity bindings for each query variable. Core assumption: The recursive decomposition of queries into single-hop subqueries preserves the semantics of the original query when scores are aggregated with t-norms.

  - Why needed here: LitCQD uses beam search to find the top-k entity bindings for query variables. Understanding beam search parameters (width, pruning) is crucial for balancing accuracy and efficiency.

## Architecture Onboarding

- Component map: Query parser -> ComplEx-N3 model + TransEA model -> Beam search with t-norm aggregation -> Ranked entity list or predicted literal value

- Critical path:
  1. Parse query into conjunctive/disjunctive structure
  2. Initialize beam with anchor entities
  3. For each variable in dependency order:
     - If relation predicate: apply ComplEx-N3 link predictor
     - If attribute predicate: apply TransEA attribute predictor + existence check
     - Aggregate scores using t-norm
     - Prune beam to top-k candidates
  4. Return final ranking or aggregate literal values

- Design tradeoffs:
  - Joint vs. separate training: Joint training allows cross-modal learning but may suffer from negative transfer if one modality is sparse
  - Beam width vs. efficiency: Larger beams improve recall but increase computation quadratically
  - T-norm choice: Gödel t-norm is more conservative (min operation) while product t-norm is smoother but may over-aggregate low scores

- Failure signatures:
  - All-zero scores: Likely attribute existence check is failing (dummy relations not trained properly)
  - Poor ranking quality: May indicate suboptimal t-norm choice or insufficient beam width
  - High variance across runs: Could indicate unstable joint training (try gradient clipping or learning rate adjustment)

- First 3 experiments:
  1. Ablation study: Run LitCQD with only ComplEx-N3 (no TransEA) on queries with literals to quantify the benefit of joint training
  2. T-norm sweep: Evaluate Hits@10 for Gödel, product, and Łukasiewicz t-norms on 2p and 3p queries
  3. Beam width scaling: Measure MRR and runtime for beam widths {4, 8, 16} on ai and pai query types

## Open Questions the Paper Calls Out
- Supporting string literals, Boolean literals, and datetime literals in future work
- Handling more complex query patterns involving disjunction and negation
- Scaling to larger knowledge graphs and more complex queries

## Limitations
- Evaluation relies on a single augmented dataset (FB15k-237 with literals), limiting generalizability to other KGs
- Performance gains over CQD are modest (0.6% MRR improvement on non-literal queries), suggesting the method may not be essential for KGs without rich numeric attributes
- Claims about handling complex disjunctive queries are not empirically validated, as the evaluation focuses on conjunctive queries

## Confidence
- High: The architectural design combining ComplEx-N3 and TransEA for joint training is sound and well-motivated by the literature
- Medium: The evaluation methodology is appropriate, but the dataset augmentation details are underspecified, making exact reproduction challenging
- Low: Claims about handling complex disjunctive queries are not empirically validated, as the evaluation focuses on conjunctive queries
