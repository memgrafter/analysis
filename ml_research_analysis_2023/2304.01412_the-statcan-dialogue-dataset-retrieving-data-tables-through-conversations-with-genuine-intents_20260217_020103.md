# The StatCan Dialogue Dataset: Retrieving Data Tables through Conversations with Genuine Intents

## Quick Facts
- arXiv ID: 2304.01412
- Source URL: https://arxiv.org/abs/2304.01412
- Reference count: 40
- Authors: Statistics Canada research team
- One-line primary result: Novel dialogue dataset for table retrieval shows significant temporal generalization gaps and moderate improvements from retrieval-augmented generation

## Executive Summary
This paper introduces the StatCan Dialogue Dataset, containing 19,379 English and French conversation turns between Statistics Canada agents and users seeking published data tables. The authors establish two tasks: table retrieval from ongoing conversations and automatic generation of agent responses. Through comprehensive experiments, they demonstrate that models struggle with temporal generalization, particularly when encountering new tables and shifting user interests. The dataset poses significant challenges to current models and provides a foundation for advancing research in practical dialogue systems for data retrieval.

## Method Summary
The authors create a dialogue dataset from Statistics Canada's actual user interactions, focusing on conversations where agents return data tables. They establish two tasks: table retrieval using DPR, TAPAS, and BM25 models with various metadata representations, and response generation using T5 with optional retrieval augmentation. The evaluation employs temporal data splits, using the most recent conversations as the test set to assess generalization to future data. Performance is measured using recall metrics for retrieval and multiple generation metrics including METEOR, ROUGE-L, BERTScore, MoverScore, and title accuracy.

## Key Results
- Models show significant performance drops when evaluated on temporal test sets versus validation sets, revealing poor generalization to future conversations
- Retrieval-augmented T5 models achieve modest improvements in title accuracy (3.86% absolute gain) compared to non-augmented models
- Including member items alongside titles and basic information yields significant improvements in retrieval recall (p = 0.014)
- All models struggle with the decision of when to return tables in generated responses, despite achieving reasonable R@K scores

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Temporal data splits reveal true generalization gaps that random splits hide.
- Mechanism: Using the most recent conversations as the test set forces models to handle unseen tables and new subject distributions, exposing temporal drift.
- Core assumption: Future conversations will differ in both table availability and user interests from historical data.
- Evidence anchors:
  - [abstract] "Experiments on a temporal data split reveal that all models struggle to generalize to future conversations, as we observe a significant drop in performance across both tasks when we move from the validation to the test set."
  - [section] "This lets us test a model's capability to adapt to temporal shifts in the data (such as new data releases and novel events)."
  - [corpus] Weak evidence - no explicit temporal corpus analysis provided.
- Break condition: If future conversations are artificially constrained to only reuse existing tables, the temporal signal weakens.

### Mechanism 2
- Claim: Retrieval-augmented generation improves response quality over generation-only baselines.
- Mechanism: DPR-retrieved table titles provide explicit context that helps T5 decide when to include table links versus generating clarification questions.
- Core assumption: The presence of relevant table titles in the input stream enables better decision-making about table inclusion.
- Evidence anchors:
  - [abstract] "We find that retrieval-augmented T5 models more frequently return the correct tables, although its title accuracy is still lower than the corresponding recall of the DPR retriever."
  - [section] "retrieval-augmented models show modest improvements on the 4 non-task specific metrics... the top-5 augmented model achieves an absolute improvement of 3.86% in title accuracy"
  - [corpus] Weak evidence - corpus shows related work but no direct comparison of augmentation effects.
- Break condition: If DPR retrieves irrelevant or low-quality titles, augmentation could degrade generation quality.

### Mechanism 3
- Claim: Metadata representation significantly impacts retrieval performance.
- Mechanism: Including member items alongside titles and basic information provides richer semantic context for matching user queries to relevant tables.
- Core assumption: User queries often reference specific dimensions or member items that are not captured by titles alone.
- Evidence anchors:
  - [section] "including basic information... yields slight improvements, and further adding member items results in a significant difference from only using title (p = 0.014)"
  - [section] "only using member item result in drastic decrease in recall (p = 0.00086), indicating the importance of the title"
  - [corpus] Weak evidence - corpus mentions related work but doesn't analyze metadata representation effects.
- Break condition: If metadata becomes too verbose or noisy, retrieval performance may degrade due to context window limitations.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do the models perform on the full dataset (all intents) compared to the subset focused on table retrieval?
- Basis in paper: [explicit] The paper states "Although a variety of user intents can be found in the broader dataset of over 25K conversations, we focus on a single intent by selecting all conversations where the agent returns a data table."
- Why unresolved: The paper only evaluates models on the subset of conversations focused on table retrieval. It does not provide results on the full dataset including other intents like obtaining metadata, table manipulation, or out-of-domain requests.
- What evidence would resolve it: Evaluating the retrieval and generation models on the full dataset of 25K+ conversations and comparing performance to the table retrieval subset.

### Open Question 2
- Question: How do the models generalize to tables from different subject categories not well-represented in the training data?
- Basis in paper: [inferred] The paper shows a significant performance drop on the test set which includes new tables not seen during training. It also mentions that users' interests have shifted to new subjects like businesses, health and IT compared to training.
- Why unresolved: The paper does not analyze model performance on specific subject categories or tables not well-represented in the training data. It only shows aggregate performance drops.
- What evidence would resolve it: Analyzing model performance on tables from different subject categories, especially those with few examples in training. Comparing performance on common vs. uncommon tables.

### Open Question 3
- Question: How do the models handle multi-table conversations where the user is looking for multiple tables in a single conversation?
- Basis in paper: [explicit] The paper states "When the agent shares multiple non-repeating PIDs within a conversation, each unique occurrence is treated as a separate sample."
- Why unresolved: The paper treats each table retrieval as a separate sample, but does not analyze how well models handle conversations where the user is looking for multiple tables. It does not evaluate if models can track which tables have already been retrieved.
- What evidence would resolve it: Analyzing model performance on conversations with multiple table retrievals. Evaluating if models can track which tables have been retrieved and avoid repetition.

## Limitations
- The temporal generalization gap may reflect dataset-specific characteristics rather than fundamental model limitations
- Retrieval augmentation provides only modest improvements (3.86% absolute gain in title accuracy), suggesting suboptimal integration between components
- The paper does not fully explore the causes of performance degradation in temporal splits through ablation studies

## Confidence
- **High confidence**: The retrieval performance metrics (Recall@K scores) and their comparative analysis across different metadata representations are well-supported by the experimental results presented in Section 4.1.
- **Medium confidence**: The generation model improvements from retrieval augmentation are demonstrated but the modest absolute gains suggest room for uncertainty about whether this approach represents the optimal solution for the task.
- **Medium confidence**: The temporal split methodology and its implications for model generalization are clearly described, but the underlying causes of the performance degradation are not fully explored or validated through ablation studies.

## Next Checks
1. Conduct an ablation study isolating the effects of temporal vs. distributional differences by creating test sets that vary only one factor (e.g., same tables but different conversation styles, or same conversation patterns but entirely new tables).
2. Test alternative integration strategies between DPR retrieval and T5 generation, such as using top-5 titles as additional context rather than decision signals, or implementing a two-stage model that first decides "return table vs. ask question" before generating the response.
3. Analyze the semantic drift between validation and test sets by comparing topic distributions, query complexity, and table relevance patterns to determine whether the performance gap stems from temporal factors or other dataset characteristics.
