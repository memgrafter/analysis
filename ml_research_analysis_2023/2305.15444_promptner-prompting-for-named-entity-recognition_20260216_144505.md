# PromptNER: Prompting For Named Entity Recognition

## Quick Facts
- arXiv ID: 2305.15444
- Source URL: https://arxiv.org/abs/2305.15444
- Authors: 
- Reference count: 22
- Key outcome: Few-shot and cross-domain NER method using LLM prompting with entity definitions achieves 4-11% F1 improvement on few-shot tasks and 3% F1 improvement on cross-domain tasks.

## Executive Summary
This paper introduces PromptNER, a novel few-shot and cross-domain Named Entity Recognition (NER) method that leverages large language models (LLMs) with prompting. PromptNER requires entity definitions and a few examples to adapt to new NER tasks. Given a sentence, it prompts an LLM to produce a list of potential entities with explanations for their compatibility with the provided entity type definitions. The method achieves state-of-the-art performance on few-shot NER, improving F1 scores by 4-11% on various datasets, and on cross-domain NER, outperforming prior methods by an average of 3% F1 despite using less than 2% of the available data.

## Method Summary
PromptNER adapts to new NER tasks by providing entity definitions in natural language along with few-shot examples, then prompting an LLM to output potential entities with reasoning explanations. The method uses chain-of-thought prompting to structure the LLM's reasoning process, generating a list of candidate entities and justifications for their compatibility with entity type definitions. This approach departs from traditional discriminative NER models by using generative LLMs to directly output entity spans, avoiding combinatorial explosion issues with multi-word entities.

## Key Results
- Achieves state-of-the-art performance on few-shot NER, improving F1 scores by 4-11% across various datasets
- Outperforms prior methods by an average of 3% F1 on cross-domain NER despite using less than 2% of the available data
- Shows consistent improvements across different model sizes (GPT4, GPT3.5, T5XXL, T5XL) with clear benefits to scaling the backbone LLM

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Chain-of-thought prompting with explicit reasoning steps improves entity recognition accuracy compared to standard prompting.
- Mechanism: By requiring the model to output candidate entities alongside explanations for why they are or are not entities, the LLM is incentivized to perform explicit reasoning rather than pattern matching alone. This structured output format mimics human reasoning about entity boundaries.
- Core assumption: LLMs can perform meaningful reasoning when prompted to do so, and this reasoning translates to better entity classification decisions.
- Evidence anchors:
  - [abstract]: "PromptNER prompts an LLM to produce a list of potential entities along with corresponding explanations justifying their compatibility with the provided entity type definitions."
  - [section 3]: "Recent work on Chain-of-Thought Prompting has shown that incentivizing the model to output its answer in a structure which facilitates reasoning like steps along with the final answer can significantly boost the performance of large language models."
  - [corpus]: Found 25 related papers with average neighbor FMR=0.557, suggesting this is an active research area with multiple related approaches exploring reasoning in NER.

### Mechanism 2
- Claim: Modular definitions of entity types allow better adaptation to diverse NER domains than example-only approaches.
- Mechanism: By providing explicit natural language descriptions of what constitutes an entity type, the system can handle subtle differences between domains where the same phrase might or might not be considered an entity depending on context.
- Core assumption: Natural language definitions can capture the nuances of entity types better than a few examples alone, especially when entity concepts vary across domains.
- Evidence anchors:
  - [abstract]: "To adapt to any new NER task PromptNER requires a set of entity definitions in addition to the standard few-shot examples."
  - [section 3]: "the modular definition consists of a natural language description of what does (and does not) constitute an entity. This can be useful in instances where the typical natural language connotation of the word 'entity' may include concepts the specific NER task would want to exclude."
  - [corpus]: Weak evidence - the corpus contains related papers but doesn't directly support the definition mechanism claim.

### Mechanism 3
- Claim: Using generative LLMs for NER rather than discriminative models handles multi-word entities and combinatorial complexity better.
- Mechanism: The sequence-to-sequence formulation can directly generate entity spans without needing to search over all possible n-grams or combinations, avoiding the combinatorial explosion problem.
- Core assumption: Generative models can be prompted to output entity spans directly, and this is more efficient than discriminative token-by-token classification approaches.
- Evidence anchors:
  - [section 3]: "We believe that a sequence-to-sequence formulation of NER has an advantage over these other formulations because it resolves the combinatorial explosion which occurs when entities can be more than a single word long."
  - [abstract]: "We leverage the power of pretrained LLMs which have been trained on conditional generation tasks. This is a departure from several works in the field that consider the NER problem as a sequence to label (or discriminative) problem."

## Architecture Onboarding

- Component map:
  - Entity type definition module (natural language descriptions) -> Few-shot example module (task-specific examples) -> Prompt template generator (combines definition, examples, and CoT structure) -> LLM backbone (GPT4, GPT3.5, T5XXL, etc.) -> Output parser (extracts entities and explanations from LLM output) -> Final Entity List

- Critical path: Definition → Examples → Prompt Template → LLM → Output Parsing → Final Entity List

- Design tradeoffs:
  - Using larger LLMs improves performance but increases cost and latency
  - More detailed definitions improve accuracy but require more human effort
  - Including candidate entities in output improves recall but adds complexity
  - The system trades training time for inference-time reasoning

- Failure signatures:
  - Poor performance across domains: likely LLM reasoning limitations or inadequate definitions
  - High variance between runs: possibly sensitivity to prompt ordering or LLM stochasticity
  - Systematic misses of certain entity types: definition may not capture important edge cases
  - Performance degradation on longer texts: likely context window limitations

- First 3 experiments:
  1. Test with and without entity definitions to measure their impact on a single domain
  2. Compare standard prompting vs chain-of-thought prompting on a representative dataset
  3. Test different LLM sizes (GPT3.5 vs GPT4) to quantify the scaling benefits

## Limitations

- Heavy dependence on large language model capabilities, with performance significantly varying based on LLM size and reasoning ability
- Results may not generalize to entity types fundamentally different from those tested (organization, person, location)
- Exact prompt templates and entity definitions are not fully specified, making faithful reproduction challenging

## Confidence

**High Confidence**: The core mechanism of using chain-of-thought prompting with entity definitions is well-supported by the empirical results, showing consistent improvements across multiple datasets and model sizes.

**Medium Confidence**: The claim about outperforming previous few-shot NER methods by 4-11% F1 is well-supported within the tested datasets, but the absolute numbers may not generalize to all NER scenarios or entity types.

**Low Confidence**: The assertion that PromptNER requires "less than 2% of the available data" while outperforming prior methods is somewhat misleading, as the comparison is between few-shot settings and full-data training, making the comparison less meaningful for practical deployment scenarios.
