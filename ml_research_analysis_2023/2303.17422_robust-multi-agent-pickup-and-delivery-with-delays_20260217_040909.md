# Robust Multi-Agent Pickup and Delivery with Delays

## Quick Facts
- arXiv ID: 2303.17422
- Source URL: https://arxiv.org/abs/2303.17422
- Reference count: 21
- Primary result: Two algorithms (k-TP and p-TP) significantly reduce replans from delays in MAPD with little runtime increase

## Executive Summary
This paper addresses the Multi-Agent Pickup and Delivery problem with execution delays (MAPD-d), where agents experience delays during task execution that can cause collisions and require replanning. The authors propose two robust planning algorithms: k-TP provides deterministic guarantees by using k-extension constraints to prevent collisions when agents are delayed up to k steps, while p-TP provides probabilistic guarantees by modeling paths as Markov chains and bounding collision probability below threshold p. Experiments show both algorithms dramatically reduce the number of replans compared to baseline Token Passing with replanning, while maintaining solution quality and runtime efficiency.

## Method Summary
The paper builds on the Token Passing (TP) framework for decentralized MAPD, where agents take turns planning paths to assigned tasks using a shared token. Two robust variants are introduced: k-TP extends path planning with k-extension constraints that treat vertices within k steps before, at, and after each path vertex as obstacles for subsequent agents, ensuring deterministic collision avoidance under delays up to k consecutive steps. p-TP models each agent's path as a Markov chain where transitions represent delay probability p_d versus moving forward, computing collision probabilities between paths and only accepting those below threshold p. Both algorithms integrate with A* path planning using Manhattan distance heuristic on 4-connected warehouse grids.

## Key Results
- k-TP and p-TP reduce replanning frequency by orders of magnitude compared to baseline TP with replanning
- Solution cost (makespan) increases by less than 5% for k-TP and p-TP compared to baseline
- Runtime overhead is minimal for k-TP and moderate for p-TP, scaling reasonably with problem size
- k-TP provides deterministic guarantees while p-TP provides probabilistic guarantees under delay uncertainty

## Why This Works (Mechanism)

### Mechanism 1
- Claim: k-TP achieves deterministic robustness by extending path constraints with a k-horizon buffer
- Mechanism: Before inserting a new path into the token, k-extension constraints treat all vertices within k steps before, at, and after each vertex in the path as obstacles for subsequent agents, ensuring no collisions occur even with delays up to k consecutive steps
- Core assumption: Delays are bounded and independent; k-extension buffer prevents collisions under maximum delay assumption
- Evidence anchors: [abstract] "k–TP offers deterministic guarantees (k–robustness)"; [section] "To create 𝑘–robust plans, an algorithm should ensure that, when an agent leaves a vertex, that vertex is not occupied by another agent for at least 𝑘 time steps"
- Break condition: If an agent is delayed more than k consecutive time steps, deterministic guarantee fails and collisions may occur

### Mechanism 2
- Claim: p-TP provides probabilistic robustness by modeling agent paths as Markov chains and bounding collision probability
- Mechanism: Each agent's path is modeled as a Markov chain where transitions represent delay probability p_d versus moving forward; collision probability between paths is computed by combining probability distributions of agent locations over time, and paths are only accepted if collision probability is below threshold p
- Core assumption: Delay events are independent across agents and time steps; Markov model accurately captures stochastic delay behavior
- Evidence anchors: [abstract] "p–TP provides probabilistic guarantees (p–robustness)"; [section] "A 𝑝–robust plan guarantees to keep collision probability below a certain threshold 𝑝"
- Break condition: If actual delay probability differs significantly from modeled p_d, or if delays are correlated, probabilistic guarantee may be violated

### Mechanism 3
- Claim: Baseline TP with replanning reacts to collisions by reassigning token to colliding agents
- Mechanism: When collision is detected during execution, non-delayed colliding agents are assigned the token to compute new collision-free paths, ensuring feasibility but potentially incurring high replanning overhead
- Core assumption: Replanning can be performed quickly enough to handle dynamic environment; token mechanism allows efficient reassignment without deadlock
- Evidence anchors: [section] "When a collision is detected between agents following their paths, the token is assigned to one of the colliding agents to allow replanning of a new collision–free path"
- Break condition: If multiple delays create deadlocks, or if replanning is too slow, system may fail to maintain feasibility

- Component map: Token (shared memory block containing paths, task set, assignments) -> PathPlanner (A* with Manhattan distance) -> Collision detection -> k-extension generation or Markov chain collision probability calculation -> Token reassignment for replanning
- Critical path: Task arrival -> Path planning with robustness constraints -> Path insertion into token -> Execution with delay monitoring -> Collision detection and handling
- Design tradeoffs: Deterministic vs. probabilistic robustness guarantees; planning time vs. runtime replanning overhead; solution cost vs. robustness level
- Failure signatures: High number of replans indicates insufficient robustness; increased makespan suggests overly conservative robustness constraints; algorithm timeouts during path planning

## Limitations

- Simulation-only validation without real-world hardware testing or deployment
- Limited delay distribution analysis using fixed delay probability without exploring different delay patterns
- Scalability gaps with experiments only covering up to 24 agents without analysis for larger systems
- Insufficient quantification of robustness-cost tradeoffs across different robustness levels

## Confidence

- **High Confidence**: The fundamental mechanism of k-extension for deterministic robustness (k-TP) - this follows logically from collision avoidance principle and is well-explained
- **Medium Confidence**: The probabilistic robustness guarantee (p-TP) - while Markov chain modeling is sound, practical effectiveness depends heavily on delay distribution assumptions
- **Low Confidence**: The claim of "little or no increase in solution cost" - experimental evidence is limited and doesn't provide systematic tradeoff analysis across different robustness levels
