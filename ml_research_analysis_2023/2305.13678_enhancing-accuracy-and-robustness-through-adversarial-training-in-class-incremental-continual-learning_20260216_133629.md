# Enhancing Accuracy and Robustness through Adversarial Training in Class Incremental Continual Learning

## Quick Facts
- arXiv ID: 2305.13678
- Source URL: https://arxiv.org/abs/2305.13678
- Reference count: 9
- Key outcome: EAT achieves 24% robustness on CIFAR-10 (vs 16% for standard ER) and 23% on Tiny-ImageNet (vs 17% for standard ER) in CICL settings

## Executive Summary
This paper addresses a critical challenge in applying adversarial training to class-incremental continual learning (CICL), where class imbalance between current and previous tasks causes ineffective defense against adversarial attacks. The authors propose External Adversarial Training (EAT), which generates adversarial examples using an external model trained only on current task data, then applies these examples to train the target model. This approach effectively excludes imbalanced adversarial attacks between different tasks that distort decision boundaries. Experiments on CIFAR-10 and Tiny-ImageNet benchmarks demonstrate that EAT significantly improves both accuracy and robustness compared to naive adversarial training in CICL settings, achieving state-of-the-art defense performance while maintaining computational efficiency.

## Method Summary
The External Adversarial Training (EAT) method addresses class imbalance in CICL by using an auxiliary external model to generate adversarial examples. At each time step, EAT creates an external model with the same architecture as the target model and trains it on current task data using 4-step PGD adversarial training. The external model generates adversarial examples that are then used to train the target model alongside clean current task data and replayed samples from the memory buffer. This approach excludes inter-task adversarial attacks that cause decision boundary distortion while maintaining robustness across all tasks. EAT can be applied to any experience replay-based method (ER, DER, DERpp) without requiring additional external memory.

## Key Results
- EAT achieves 24% robustness on CIFAR-10 compared to 16% for standard ER
- EAT achieves 23% robustness on Tiny-ImageNet compared to 17% for standard ER
- EAT improves both accuracy and robustness while maintaining computational efficiency

## Why This Works (Mechanism)

### Mechanism 1
- Claim: EAT reduces decision boundary distortion by excluding inter-task adversarial attacks
- Mechanism: EAT trains an external model only on current task data to generate adversarial examples, preventing adversarial examples from overwhelming minority classes from previous tasks
- Core assumption: Distortion in standard adversarial training arises primarily from imbalanced adversarial attacks between different tasks
- Evidence anchors: "EAT effectively excludes imbalanced adversarial attacks between different tasks that distort decision boundaries" [abstract]
- Break condition: If current task data contains significant overlap with previous tasks

### Mechanism 2
- Claim: EAT maintains robustness across all tasks while improving accuracy for older tasks
- Mechanism: The external model generates adversarial examples representative of current task distribution without bias from previous tasks' class imbalance
- Core assumption: External model can generate effective adversarial examples without access to previous task data
- Evidence anchors: "EAT achieves state-of-the-art defense performance, with 24% robustness on CIFAR-10 (vs 16% for standard ER)" [abstract]
- Break condition: If external model overfits to current task data

### Mechanism 3
- Claim: EAT provides a practical solution without requiring additional memory
- Mechanism: EAT leverages class imbalance as inherent to CICL and excludes cases of applying AT over different tasks
- Core assumption: Class imbalance problem is inherent to CICL and cannot be easily solved without additional resources
- Evidence anchors: "EAT can be easily applied to any method using experience replay" [abstract]
- Break condition: If class imbalance can be solved without excluding AT between tasks

## Architecture Onboarding

- Component map:
  - Target model (main model for continual learning) -> External model (auxiliary model for generating adversarial examples) -> Memory buffer (stores previous task data)

- Critical path:
  1. At each time step, create external model with same architecture as target model
  2. Train external model on current task data using adversarial training
  3. Generate adversarial examples using trained external model
  4. Train target model on clean current task data, replayed samples, and generated adversarial examples

- Design tradeoffs:
  - Computational cost: Requires training additional model at each time step
  - Memory efficiency: No additional memory required compared to standard experience replay
  - Robustness vs. accuracy: Aims to improve both, but may have tradeoffs in some cases

- Failure signatures:
  - Significant drop in accuracy for older tasks
  - Poor robustness on adversarial examples from previous tasks
  - Overfitting to current task data, resulting in poor generalization

- First 3 experiments:
  1. Compare EAT with standard adversarial training on simple class-incremental task with 2-3 classes
  2. Evaluate EAT's performance on CIFAR-10 with more classes and tasks
  3. Test EAT's robustness to different types of adversarial attacks (FGSM, PGD) on continual learning benchmark

## Limitations

- Limited experimental validation to two image classification datasets (CIFAR-10 and Tiny-ImageNet)
- Performance on larger-scale problems, different data modalities, or varying memory budgets is unknown
- Introduces additional computational overhead by requiring training an auxiliary model at each time step

## Confidence

- High confidence in the core mechanism: EAT's approach of using external model to generate task-specific adversarial examples is theoretically sound and well-motivated
- Medium confidence in empirical results: Substantial improvements reported but limited to two datasets with specific experimental setups
- Low confidence in scalability claims: No evidence provided for EAT's performance on larger-scale problems or different data types
