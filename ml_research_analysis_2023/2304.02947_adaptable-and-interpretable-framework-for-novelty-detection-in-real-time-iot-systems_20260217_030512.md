# Adaptable and Interpretable Framework for Novelty Detection in Real-Time IoT Systems

## Quick Facts
- arXiv ID: 2304.02947
- Source URL: https://arxiv.org/abs/2304.02947
- Reference count: 22
- Primary result: RAID algorithm achieves 48.70% F1 score on SKAB benchmark and successfully detects anomalies with root cause isolation in battery energy storage systems

## Executive Summary
This paper presents RAID (Real-time Adaptive and Interpretable Detection), a novel anomaly detection algorithm for multivariate dynamic processes in IoT systems. The key innovation is combining adaptability to non-stationary effects like data drift and change points with root cause isolation capabilities. The method uses a dynamic joint probability distribution model that updates incrementally using Welford's online algorithm, allowing real-time adaptation without storing historical data. Two case studies demonstrate the approach: one on SKAB benchmark data showing 48.70% F1 score (slightly outperforming reference methods), and another on a battery energy storage system where the method successfully detected anomalies, adapted to environmental changes after relocation, and identified root causes.

## Method Summary
The RAID algorithm implements real-time anomaly detection using a dynamic joint probability distribution that updates incrementally through Welford's online algorithm. The method maintains running mean and covariance statistics while allowing samples to expire after a configurable period through inverse Welford operations. Detection occurs at two levels: global anomalies are identified using log-probability of the entire observation vector, while individual signal diagnostics use percent-point function calculations to establish dynamic process limits. The algorithm adapts to both normal data and anomalies based on probabilistic thresholds, enabling self-supervised learning without requiring labeled data. The framework provides both system-level anomaly detection and signal-level root cause analysis, making it suitable for long-term deployment across different domains without infrastructure changes.

## Key Results
- Achieves 48.70% F1 score on SKAB benchmark dataset, slightly outperforming reference methods
- Successfully detects anomalies and adapts to environmental changes in battery energy storage system case study
- Provides interpretable root cause isolation through dynamic process limits for individual signals
- Demonstrates real-time capability with incremental updates without storing historical data

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The dynamic joint probability distribution with incremental Welford updates enables real-time adaptation to data drift and change points without storing historical data.
- Mechanism: The algorithm maintains running mean and covariance matrix using Welford's online algorithm, updating parameters incrementally as new samples arrive. When samples expire beyond the configured window, inverse Welford operations revert their influence, allowing the model to adapt to recent data patterns.
- Core assumption: The underlying process follows a multivariate Gaussian distribution over bounded time frames related to system dynamics.
- Evidence anchors:
  - [abstract] "The method uses a dynamic joint probability distribution model that updates incrementally using Welford's online algorithm, allowing real-time adaptation without storing historical data."
  - [section] "Update of the mean vector µi and covariance matrix Σi is governed by Welford's online algorithm using equation (2) and (4) respectively. Samples after the expiration period te are forgotten in the second pass."
- Break condition: If the underlying distribution significantly deviates from Gaussian, the model's assumptions break and detection accuracy degrades.

### Mechanism 2
- Claim: The two-level detection approach (global log-CDF for system anomalies, individual signal thresholds for root cause isolation) provides both interpretability and diagnostic capability.
- Mechanism: Global anomalies are detected by computing log-probability of the entire observation vector against the joint distribution. Individual signal diagnostics use percent-point function (PPF) to establish dynamic process limits for each signal independently.
- Core assumption: Anomalies can be identified as observations that significantly deviate from the mean vector, and individual signals contribute to global anomalies.
- Evidence anchors:
  - [abstract] "The algorithm provides both global anomaly detection and signal-level diagnostics through dynamic process limits"
  - [section] "For root cause isolation, inputs are tested against the interval given by lower and upper threshold values, xl from (12) and xu from (13) respectively."
- Break condition: If signal interactions are non-linear or complex, simple threshold-based isolation may miss root causes that require considering signal combinations.

### Mechanism 3
- Claim: Self-supervised learning with adaptive adaptation period allows the model to update on both normal and anomalous data based on probabilistic thresholds.
- Mechanism: The model uses a probabilistic approach where adaptation occurs on observations when the number of anomalies in a window exceeds 2*(q-0.5), allowing controlled updates on outlier data while maintaining normal operation characterization.
- Core assumption: The number of anomalies in a given time frame follows the assumed probability distribution, allowing controlled adaptation.
- Evidence anchors:
  - [section] "Given the predicted system anomaly state from (14) as yi over the window of past observations yi = {yi-ta,...,yi}, the following test holds when adaptation is performed on outlier: ∑y∈yiy n(yi) > 2 ∗ (q − 0.5)."
- Break condition: If anomaly patterns are persistent or systematic rather than random, the adaptation mechanism may incorrectly incorporate anomalous behavior into the normal model.

## Architecture Onboarding

- Component map: Data Ingestion Layer -> Parameter Update Engine -> Detection Engine -> Output Interface, with Expiration Manager and Adaptation Controller operating asynchronously
- Critical path: Data ingestion → Parameter update → Detection computation → Output generation, with expiration and adaptation occurring asynchronously
- Design tradeoffs:
  - Window size (expiration period) vs adaptation speed: Longer windows provide stability but slower adaptation to change points
  - Threshold value vs false positive rate: Higher thresholds reduce false positives but may miss subtle anomalies
  - Dimensionality vs computational complexity: Higher dimensions increase detection capability but require more computation per sample
- Failure signatures:
  - Persistent high false positive rate: Likely indicates window size too short or threshold too low
  - Missed change points: Window size too long or adaptation period too restrictive
  - System instability: Numerical issues in covariance matrix inversion (indicates poor conditioning)
  - Excessive computation time: Dimensionality too high for real-time processing

  1. Implement parameter update engine with synthetic Gaussian data and verify mean/covariance convergence
  2. Add expiration manager and test reversion of expired samples on time-varying synthetic data
  3. Integrate detection engine and validate anomaly detection on benchmark dataset with known anomalies

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the RAID algorithm's performance scale with increasing dimensionality of multivariate systems beyond the 8-feature case study?
- Basis in paper: [explicit] The paper mentions "scalability" and "false positive rate reduction" as future work areas, noting that "high dimensional data" may increase latency
- Why unresolved: The case studies only tested on 8 features, and the paper explicitly identifies scalability as an open issue
- What evidence would resolve it: Systematic testing of RAID on multivariate systems with 10, 50, 100+ features to measure performance degradation and computational overhead

### Open Question 2
- Question: What is the optimal trade-off between expiration period length and change point detection speed in real-world deployments?
- Basis in paper: [explicit] The paper discusses "expiration period te" as a hyperparameter affecting "change point adaptation capacity" but doesn't provide systematic optimization guidelines
- Why unresolved: The paper provides only general guidance ("as a general rule of thumb") without empirical studies on the trade-offs
- What evidence would resolve it: Controlled experiments varying expiration periods across different system dynamics to establish performance curves for adaptation speed vs. detection accuracy

### Open Question 3
- Question: How does RAID perform on non-Gaussian distributed data compared to Gaussian-based assumptions?
- Basis in paper: [inferred] The paper assumes "Gaussian normal distribution of variables is a reasonable assumption for process measurements" but only mentions that "Kolmogorov–Smirnov test did not reject this hypothesis" without testing alternative distributions
- Why unresolved: The paper doesn't test the algorithm on datasets with known non-Gaussian distributions or compare against non-parametric alternatives
- What evidence would resolve it: Testing RAID on datasets with heavy-tailed, multimodal, or other non-Gaussian distributions while comparing performance against distribution-agnostic anomaly detection methods

## Limitations
- Evaluation relies heavily on two case studies (SKAB benchmark and single battery system), limiting generalizability claims
- Performance on high-dimensional data beyond 8 features is not thoroughly characterized
- Self-supervised adaptation mechanism's behavior under persistent systematic anomalies versus random noise is not explicitly validated

## Confidence
- **High confidence**: The core statistical mechanisms (Welford's algorithm, multivariate Gaussian modeling, log-CDF computation) are mathematically sound and well-established
- **Medium confidence**: The benchmark performance claims are credible given the methodology, though the slight edge over reference methods may not be statistically significant across different datasets
- **Medium confidence**: The battery system case study demonstrates practical utility, but represents a single deployment scenario that may not generalize
