# Multimodal Short Video Rumor Detection System Based on Contrastive Learning

## Quick Facts
- arXiv ID: 2304.08401
- Source URL: https://arxiv.org/abs/2304.08401
- Reference count: 6
- Primary result: Achieves 87.7% accuracy on custom dataset using multimodal fusion and contrastive learning

## Executive Summary
This paper presents a multimodal short video rumor detection system that combines visual, textual, and audio features using contrastive learning and vector database retrieval. The system extracts features using TSN for video, OCR/ASR for text, and fuses them with BERT, then applies contrastive learning to cluster similar samples and uses external knowledge retrieval for final classification. Experiments on a custom dataset show the model outperforms unimodal and multimodal baselines, with ablation studies confirming that image and text features contribute most to performance.

## Method Summary
The system extracts visual features using TSN (RGB and optical flow), textual features via OCR and ASR, and fuses them using BERT with a text-dominant ratio (25 video tokens vs 485 text tokens). Contrastive learning is applied to cluster same-class samples in the embedding space using pairwise labeling and margin-based cosine distance. External knowledge is crawled, embedded, stored in a vector database (HNSW or IVF-PQ), and retrieved by similarity to input video features. Final classification uses weighted voting from top-10 similar knowledge items.

## Key Results
- Achieves 87.7% accuracy on custom short video rumor detection dataset
- Outperforms unimodal and multimodal baselines in triple classification (rumor, non-rumor, disinformation)
- Ablation studies show image and text features contribute most to performance

## Why This Works (Mechanism)

### Mechanism 1
Multimodal feature fusion improves rumor detection by combining complementary cues from visual, textual, and audio modalities. Visual features (RGB + optical flow) capture spatial and motion context, OCR and ASR extract embedded text, and BERT fuses these into a unified representation with text dominance (25 video tokens vs 485 text tokens). Core assumption: Different modalities encode non-redundant rumor indicators that are jointly discriminative. Break condition: If modalities are highly correlated or one modality is consistently noisy, fusion may not help and could even degrade performance.

### Mechanism 2
Contrastive learning clusters same-class samples and separates different-class samples in the embedding space, improving retrieval-based classification. Randomly paired samples are labeled 1 (same class) or 0 (different class); contrastive loss pulls similar pairs together and pushes dissimilar pairs apart using cosine distance with margin 0.5. Core assumption: Embedding space can be shaped such that semantic similarity aligns with class membership. Break condition: If classes are not linearly separable in the embedding space or if the margin is improperly set, contrastive learning may not improve classification.

### Mechanism 3
External knowledge retrieval via vector database provides additional context that improves rumor detection accuracy. External knowledge is crawled, embedded, stored in a vector database (HNSW or IVF-PQ), and retrieved by similarity to the input video features; top-10 similar vectors vote weighted by similarity to produce the final label. Core assumption: External knowledge contains discriminative signals that are not captured by the multimodal fusion alone. Break condition: If external knowledge is irrelevant, outdated, or noisy, retrieval-based classification may degrade accuracy.

## Foundational Learning

- **Feature extraction pipelines for multimodal data**: TSN for video, OCR/ASR for text, BERT for fusion. Why needed: Each modality requires domain-specific processing before fusion; TSN extracts spatiotemporal features, OCR/ASR extract embedded text, BERT fuses into a single representation. Quick check: What are the output dimensions of TSN, OCR, and ASR before BERT fusion in this system?

- **Contrastive learning objectives and loss functions**: Pairwise labeling, margin-based cosine distance. Why needed: Contrastive learning shapes the embedding space to improve retrieval-based classification by clustering same-class samples. Quick check: How does the margin parameter in contrastive loss affect the separation of different classes in the embedding space?

- **Vector database indexing and approximate nearest neighbor search**: HNSW, IVF-PQ. Why needed: Efficient retrieval of similar knowledge items from large external corpora is essential for real-time classification. Quick check: What is the trade-off between search speed and recall when using HNSW vs IVF-PQ indexing?

## Architecture Onboarding

- **Component map**: Data collection → Multimodal feature extraction (TSN, OCR, ASR) → BERT fusion → Contrastive learning → Vector database indexing → Retrieval-based classification
- **Critical path**: Feature extraction → BERT fusion → Contrastive learning → Vector database retrieval → Classification
- **Design tradeoffs**: Multimodal fusion favors text (25 video tokens vs 485 text tokens) for accuracy but may miss visual cues; contrastive learning improves retrieval but adds training complexity; external knowledge retrieval adds context but depends on corpus quality
- **Failure signatures**: Low accuracy with multimodal input but high with unimodal suggests fusion misalignment; poor contrastive learning performance suggests embedding space misalignment; low retrieval accuracy suggests vector database indexing or knowledge quality issues
- **First 3 experiments**: 1) Train and evaluate with and without multimodal fusion to measure modality contributions; 2) Train with and without contrastive learning to measure its impact on retrieval accuracy; 3) Evaluate retrieval accuracy with different vector database indexing methods (HNSW vs IVF-PQ) and similarity thresholds

## Open Questions the Paper Calls Out

### Open Question 1
How do the detected features vary across different types of short video rumors (e.g., disinformation vs. rumors), and what implications does this have for detection accuracy? The paper mentions using a vector database to store and retrieve features for rumor classification but does not explore how different types of rumors are represented in the feature space. A comparative analysis of feature vectors for different rumor types would provide insights into the model's ability to differentiate between rumor types.

### Open Question 2
How does the inclusion of external knowledge from vector databases impact the detection of emerging rumors that are not yet present in the knowledge base? The paper discusses using a vector database to introduce external knowledge into classification but does not address limitations for new or emerging rumors. Experiments evaluating performance on newly emerging rumors with and without external knowledge would clarify the impact on detection accuracy.

### Open Question 3
What are the computational trade-offs between using different multimodal fusion techniques, such as BERT versus other fusion methods, in terms of detection accuracy and processing time? The paper mentions using BERT for fusing text and video features but does not compare its performance with other multimodal fusion techniques. A comparative study of different fusion techniques in terms of both detection accuracy and processing time would provide insights into the most efficient approach.

## Limitations
- Limited generalizability beyond custom dataset without evaluation on established rumor detection benchmarks
- Heavy text dominance in multimodal fusion (25:485 ratio) may miss visual misinformation cues
- External knowledge retrieval effectiveness depends entirely on quality and relevance of crawled corpora, which are not specified

## Confidence

**High confidence** in multimodal fusion architecture and feature extraction pipeline (TSN, OCR, ASR, BERT) as these components are well-established in the literature.

**Medium confidence** in contrastive learning mechanism for rumor detection since while contrastive learning is proven in representation learning, its specific application to short video rumor detection lacks direct empirical validation in the corpus.

**Low confidence** in external knowledge retrieval component's effectiveness due to absence of corpus evidence supporting knowledge-based rumor detection improvements and lack of detail about knowledge source quality and relevance.

## Next Checks

1. **Cross-dataset evaluation**: Test the system on established rumor detection benchmarks (Twitter15/20, Weibo) to assess generalizability beyond the custom dataset and identify potential overfitting to specific video characteristics.

2. **Ablation study with varying text dominance**: Systematically vary the text-to-video token ratio in BERT fusion (e.g., 50:475, 200:300, 400:100) to determine optimal balance and assess whether visual features contribute meaningfully beyond simple text analysis.

3. **Knowledge retrieval quality assessment**: Conduct a human evaluation of retrieved external knowledge items for relevance and accuracy, measuring precision@k for different similarity thresholds to quantify the actual contribution of knowledge retrieval to classification performance.
