# SwitchPrompt: Learning Domain-Specific Gated Soft Prompts for Classification in Low-Resource Domains

## Quick Facts
- arXiv ID: 2302.06868
- Source URL: https://arxiv.org/abs/2302.06868
- Reference count: 19
- Authors: 
- Key outcome: SwitchPrompt achieves up to 10.7% accuracy improvement over P-tuning methods in few-shot text classification across three domain benchmarks

## Executive Summary
SwitchPrompt introduces a novel prompting method that dynamically combines general and domain-specific knowledge through trainable gates to adapt pre-trained language models to low-resource domains. The approach constructs soft prompts by concatenating general soft prompts with domain-specific keywords selected via term-frequency analysis, then uses sigmoid gates to control the influence of each component. Experiments on clinical, materials science, and general domain classification tasks demonstrate that SwitchPrompt outperforms state-of-the-art prompting methods, particularly in few-shot settings where it effectively reduces the performance gap between general-domain and domain-specific language models.

## Method Summary
SwitchPrompt is a parameter-efficient prompting method that addresses domain adaptation for pre-trained language models in low-resource settings. It creates domain-specific soft prompts by extracting keywords from the target domain using term-frequency differences compared to general domain corpora. These keywords are combined with general soft prompts and controlled by two sigmoid gates that dynamically switch between general and domain-specific knowledge based on the input representation. The method is trained using P-tuning v2 architecture while keeping the underlying language model frozen, making it computationally efficient for few-shot learning scenarios.

## Key Results
- Achieves up to 10.7% accuracy improvement over P-tuning methods on three domain benchmarks
- Effectively reduces performance gap between general-domain and domain-specific language models
- Demonstrates strong performance particularly in few-shot settings with limited labeled data

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Dynamic switching between general and domain-specific knowledge via trainable gates reduces domain gap in few-shot settings
- Mechanism: SwitchPrompt concatenates general soft prompts (Pg) with domain-specific keyword vectors (Kn), then uses two sigmoid gates (g1, g2) to dynamically control the influence of each component based on input sentence representation
- Core assumption: The domain-specific keywords capture semantic information unique to the target domain while the general prompts provide foundational knowledge, and the gates can learn when to prioritize each
- Evidence anchors:
  - [abstract]: "Using domain-specific keywords with a trainable gated prompt, SwitchPrompt offers domain-oriented prompting, that is, effective guidance on the target domains for general-domain language models"
  - [section 3.1]: "The motivation behind our proposed prompts P ∈ Rl×e is to allow the model to dynamically switch between a general-domain prompt Pg and a domain-specific prompt Pd in order to retrieve different kinds of knowledge from the pre-trained LM based on the current input"
  - [corpus]: Weak evidence - no direct citations found in corpus signals
- Break condition: Gates become stuck in extreme values (near 0 or 1) preventing dynamic switching, or keywords fail to capture meaningful domain distinctions

### Mechanism 2
- Claim: Term-frequency-based keyword selection identifies domain-specific terms while avoiding general-domain noise
- Mechanism: Keywords are selected using normalized term frequencies from general domain (tfg) and target domain (tfd) with negative alpha weighting: c(w) = α· tfg(w) + tfd(w), α < 0
- Core assumption: Domain-specific terms will have higher frequency in the target domain than in general domain, while common terms will have similar frequencies across both
- Evidence anchors:
  - [section 3.1]: "Using α < 0, we are able to select terms that are representative for the target domain and avoid terms that are frequent in the general domain"
  - [section 5 Analysis]: "Since we compute keywords automatically (see Section 3), we analyze the extracted keywords in more detail" showing qualitative evaluation
  - [corpus]: Weak evidence - no direct citations found in corpus signals
- Break condition: Term frequency distributions are too similar between domains, or domain-specific terms are rare in available data

### Mechanism 3
- Claim: Preserving input sentence structure while adding prompts maintains LM's learned representations
- Mechanism: Unlike P-tuning which replaces input with differential embeddings, SwitchPrompt prepends prompts to the original input sequence, allowing the pre-trained LM to process both domain guidance and the original sentence
- Core assumption: The pre-trained LM's attention mechanisms can effectively integrate information from both the prompts and the original input
- Evidence anchors:
  - [section 3.2]: "Since our proposed method is a new definition of soft prompts, it can be integrated into any existing model that uses soft prompts"
  - [section 4.4]: "P-tuning outperforms our method" suggesting input replacement has different tradeoffs
  - [section 4.4]: "P-Tuning v2 is a little bit faster than our approach as it does not need to train the gating parameters" indicating architectural differences
- Break condition: Input length constraints prevent effective prompt addition, or attention mechanisms fail to integrate prompt and input information

## Architecture Onboarding

- Component map:
  Input layer → Pre-trained LM → Soft prompts (general + domain-specific) → Gates (g1, g2) → Classification head
  Domain-specific keywords extracted from corpus using term frequency analysis
  Two trainable weight vectors (w1, w2) for gate computation

- Critical path:
  1. Extract domain-specific keywords using term frequency analysis
  2. Initialize soft prompts and gate weights
  3. Compute gate values based on input representation
  4. Construct dynamic prompt using gating functions
  5. Feed concatenated input and prompt through frozen LM
  6. Apply classification head to [CLS] token

- Design tradeoffs:
  - Input preservation vs replacement: SwitchPrompt keeps original input vs P-tuning's input replacement
  - Single gate vs multiple gates: Two gates provide more control but add complexity
  - Keyword selection method: Term frequency is simple but may miss nuanced domain distinctions

- Failure signatures:
  - Performance degrades with more shots (opposite of expected behavior)
  - Training instability with extreme gate values
  - Keywords fail to capture domain-specific semantics

- First 3 experiments:
  1. Implement basic SwitchPrompt architecture with toy dataset to verify prompt concatenation and gating functionality
  2. Test keyword extraction pipeline on small domain corpora to validate term frequency selection
  3. Compare SwitchPrompt performance against baseline soft prompting methods on a single domain dataset

## Limitations
- Limited evaluation to three specific domains (clinical, materials science, general) raises generalization concerns
- Term-frequency-based keyword selection sensitivity to corpus size and parameter choices not fully quantified
- Training stability and gate convergence issues not thoroughly addressed

## Confidence

**High Confidence Claims**:
- SwitchPrompt outperforms P-tuning and P-tuning v2 on the evaluated benchmarks (3/3 domains, 5/5 settings show improvement)
- The gated prompting architecture is implementable and functional as described
- Domain-specific keyword extraction using term frequency is viable for the tested domains

**Medium Confidence Claims**:
- SwitchPrompt reduces the performance gap between general and domain-specific models across all scenarios
- The method generalizes well to unseen domains beyond the three evaluated
- The keyword selection method captures meaningful domain-specific semantics in all cases

**Low Confidence Claims**:
- SwitchPrompt's performance advantage scales linearly with domain specificity
- The approach is equally effective for all types of low-resource domains (e.g., emerging vs. established domains)
- The gating mechanism never becomes stuck in suboptimal states during training
