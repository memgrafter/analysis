# Going faster to see further: GPU-accelerated value iteration and simulation for perishable inventory control using JAX

## Quick Facts
- arXiv ID: 2303.10672
- Source URL: https://arxiv.org/abs/2303.10672
- Reference count: 40
- One-line primary result: GPU acceleration enables value iteration for large perishable inventory problems with up to 16 million states

## Executive Summary
This paper demonstrates how GPU acceleration using the JAX library can make value iteration tractable for large perishable inventory problems that were previously considered computationally infeasible. The authors implement value iteration and simulation environments in a high-level API that efficiently utilizes GPU hardware, enabling optimal policy computation for problems with up to 16 million states. They compare these optimal policies against heuristic policies fitted using GPU-accelerated simulation optimization, finding that the heuristics achieve a maximum optimality gap of 2.49%. The methodology extends to various operational research problems benefiting from large-scale parallel computation.

## Method Summary
The authors use JAX's function transformations (vmap, pmap) and XLA compiler to implement GPU-accelerated value iteration and simulation for perishable inventory control. They define a base VIRunner class with eight scenario-specific methods, implementing three perishable inventory scenarios with increasing complexity. Value iteration updates use nested vmap operations over states, actions, and random outcomes instead of loops. Simulation optimization uses vmap over rollouts and parameter sets for parallel evaluation. The method is demonstrated using Google Colab notebooks for reproducibility, with results showing significant computational speedups compared to CPU-based approaches.

## Key Results
- GPU acceleration reduces wall time for value iteration by updating many states simultaneously
- Heuristic policies achieve a maximum optimality gap of 2.49% compared to optimal policies
- The approach extends value iteration to problems previously considered infeasible due to computational complexity
- Value iteration for the largest problem (16 million states) took 18 hours on an NVIDIA Tesla V100 GPU

## Why This Works (Mechanism)

### Mechanism 1
- Claim: GPU acceleration makes value iteration tractable for large perishable inventory problems
- Mechanism: Value iteration updates many independent states in parallel; GPUs have thousands of cores optimized for parallel workloads
- Core assumption: The value iteration update for each state is independent of others within the same iteration
- Evidence anchors:
  - [abstract] "The parallel processing capabilities of modern GPUs can reduce the wall time required to run value iteration by updating many states simultaneously."
  - [section 3.2] "For our basic value iteration update, set out in Algorithm 1, we nest vmap operations over states, actions, and random outcomes instead of using nested loops."
  - [corpus] Found 25 related papers; average FMR=0.487 suggests moderate relevance. Several GPU-accelerated simulation frameworks exist, supporting this approach.
- Break condition: When state space is too large to fit in GPU memory, requiring state batching that reduces parallelization efficiency.

### Mechanism 2
- Claim: High-level JAX API provides GPU acceleration without low-level CUDA programming
- Mechanism: JAX's composable transformations (vmap, pmap) and XLA compiler translate high-level Python operations into optimized CUDA kernels
- Core assumption: JAX's JIT compilation produces CUDA code that efficiently utilizes GPU hardware
- Evidence anchors:
  - [abstract] "We used the Python library JAX to implement value iteration and simulators of the underlying Markov decision processes in a high-level API, and relied on this library's function transformations and compiler to efficiently utilize GPU hardware."
  - [section 3.2] "Functions transformed by pmap are automatically JIT compiled with XLA, a domain-specific compiler for linear algebra."
  - [corpus] Several GPU-accelerated simulation frameworks exist (Isaac Lab, DiffAero), supporting this approach.
- Break condition: When custom CUDA optimization is needed for specific operations not well-handled by XLA.

### Mechanism 3
- Claim: Simulation optimization with GPU acceleration finds good heuristic policies faster than value iteration
- Mechanism: Parallel evaluation of multiple policy parameters across thousands of simulated years using vmap over rollouts and parameter sets
- Core assumption: Multiple policy parameter evaluations are independent and can be run in parallel without communication
- Evidence anchors:
  - [abstract] "The heuristic policies gave a maximum optimality gap of 2.49%. The authors show that their method can extend value iteration to problems previously considered infeasible due to computational complexity."
  - [section 3.3] "We can simultaneously evaluate multiple sets of parameters for the same policy on a shared set of random seeds by nesting vmapped functions."
  - [corpus] Found 25 related papers; average FMR=0.487 suggests moderate relevance. Several GPU-accelerated simulation frameworks exist, supporting this approach.
- Break condition: When the parameter space is too large for exhaustive evaluation, requiring sequential optimization steps.

- Component map:
  - VIRunner base class with 8 placeholder methods for scenario-specific implementations
  - JAX-based value iteration using vmap/pmap transformations
  - gymnax reinforcement learning environments for simulation
  - Optuna for parameter search in simulation optimization
  - Google Colab notebook for reproducibility

- Critical path:
  1. Define state space, actions, and transition dynamics for the specific scenario
  2. Implement the 8 VIRunner methods for that scenario
  3. Run value iteration with JAX transformations
  4. Extract optimal policy from converged value function
  5. Implement simulation environment using gymnax
  6. Use simulation optimization to fit heuristic policies
  7. Compare performance of optimal vs heuristic policies

- Design tradeoffs:
  - Double-precision vs single-precision: Double provides stable convergence but is ~2× slower
  - State batching: Required when state space doesn't fit in GPU memory, reducing parallelization efficiency
  - Checkpoint frequency: Every 100 iterations saves time vs every iteration but risks losing work if interrupted

- Failure signatures:
  - Convergence test never passes: May indicate insufficient precision or incorrect reward function
  - GPU memory error: State space too large for available GPU RAM
  - Poor heuristic performance: Reward function doesn't capture important real-world factors

- First 3 experiments:
  1. Scenario A with m=2, L=1: Smallest problem, should run in seconds, validates basic implementation
  2. Scenario B with m=2: Tests multi-product handling and substitution logic
  3. Scenario C with m=3, exogenous uncertainty: Tests periodic demand and complex transition dynamics

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the optimality gap between heuristic policies and optimal policies scale as problem size increases beyond the tested scenarios?
- Basis in paper: [inferred] The authors note that "the optimality gap in our experiments was never larger than 2.5%, and in the experiments from Scenario A and Scenario B the optimality gap decreased as the demand and/or maximum useful life of the product increased."
- Why unresolved: The paper only tests three scenarios with specific parameter ranges. The relationship between problem size and optimality gap is not explicitly modeled or extrapolated.
- What evidence would resolve it: Additional experiments testing a wider range of problem sizes and complexities, with systematic variation of key parameters like maximum useful life, demand distributions, and substitution probabilities.

### Open Question 2
- Question: Can the proposed GPU-accelerated value iteration method be extended to handle multi-echelon inventory systems with more complex supply chain structures?
- Basis in paper: [explicit] The authors state "Our approach is broadly similar to that of Duarte et al. (2020) and Sargent and Stachurski (2022) who used machine learning frameworks to implement GPU-accelerated value iteration for economics models."
- Why unresolved: The paper focuses on single-echelon problems. Extending to multi-echelon systems would require additional modeling of inventory flows between echelons and potentially different computational approaches.
- What evidence would resolve it: Implementation and testing of the method on multi-echelon inventory problems, demonstrating scalability and performance compared to existing approaches.

### Open Question 3
- Question: How sensitive are the results to the choice of convergence criteria for value iteration in the different scenarios?
- Basis in paper: [explicit] The authors use different convergence tests for each scenario: "De Moor et al. (2022) did not specify a particular convergence test for their value iteration experiments... For each value of m, Mirjalili (2022) investigated five different settings for the distribution of useful life on arrival..."
- Why unresolved: The paper does not systematically compare the impact of different convergence criteria on the final policies and performance metrics.
- What evidence would resolve it: Comparative analysis of results using alternative convergence criteria for each scenario, evaluating the trade-off between computational efficiency and policy quality.

## Limitations
- Comparison between optimal and heuristic policies relies on simulation results that may not capture long-term convergence properties
- Computational speedup claims are based on specific GPU hardware (NVIDIA Tesla V100) and may vary significantly across different GPU architectures
- Methodology's applicability to more complex inventory scenarios (e.g., with dynamic pricing or multi-echelon systems) remains untested

## Confidence
- High confidence in the core claim that GPU acceleration makes value iteration tractable for large perishable inventory problems, supported by direct computational evidence
- Medium confidence in the optimality gap measurements between heuristic and optimal policies, as these depend on simulation accuracy and random seed quality
- Medium confidence in the JAX implementation's efficiency claims, though performance may vary with different problem structures
