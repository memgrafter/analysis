# Instance-based Explanations for Gradient Boosting Machine Predictions with AXIL Weights

## Quick Facts
- arXiv ID: 2301.01864
- Source URL: https://arxiv.org/abs/2301.01864
- Reference count: 31
- Method introduces AXIL weights for instance-based explanations of GBM predictions

## Executive Summary
This paper introduces AXIL weights (Additive eXplanations with Instance Loadings), a method for interpreting gradient boosting machine (GBM) predictions by expressing them as linear combinations of training data target instances. The authors prove that any GBM regression prediction can be represented as a weighted sum of training data targets, where the weights are calculated using an algorithm that exploits the structure of tree ensembles. These weights serve as instance importance measures, complementing existing feature importance methods like SHAP and LIME. The approach is demonstrated on a smoking prevalence dataset, showing how predictions can be explained in terms of similar training instances. The method offers both local (per-instance) and global explanations, enabling clustering and network-based analysis of instance relationships.

## Method Summary
AXIL weights are computed by first training a gradient boosting machine on the training data, then traversing each tree in the ensemble to calculate contribution scores for each training instance at each leaf node. These contribution scores are aggregated across all trees to produce a weight vector for each test instance, representing the linear combination of training targets that reconstructs the prediction. The method leverages the additive nature of tree ensemble predictions and the discrete partitioning of feature space by decision trees. The weight calculation algorithm operates by tracking which training instances fall into each leaf node across all trees, then computing normalized contribution scores based on the prediction values at those leaves.

## Key Results
- Any GBM regression prediction can be represented as a weighted sum of training data target instances
- AXIL weights provide instance-level importance measures that complement existing feature attribution methods
- Demonstrated on smoking prevalence dataset with both local and global explanation capabilities
- Enables clustering and network analysis of instance relationships through weight similarity

## Why This Works (Mechanism)
The method works because gradient boosting machines make predictions as additive sums of tree outputs, and each tree partitions the feature space into disjoint regions (leaves) where instances receive the same prediction. By tracking which training instances fall into each leaf across all trees, the algorithm can attribute prediction contributions to specific training instances. The weights are calculated by normalizing these contributions across all training instances, creating a linear combination that exactly reconstructs the GBM prediction when multiplied by the training target values.

## Architecture Onboarding

**Component Map**: Training Data -> GBM Training -> Tree Ensemble -> Leaf Instance Tracking -> Contribution Calculation -> AXIL Weight Computation -> Prediction Reconstruction

**Critical Path**: The critical path involves training the GBM, then performing post-hoc analysis by traversing all trees to track instance contributions. This requires access to both the trained model and the original training data.

**Design Tradeoffs**: The method trades computational efficiency for interpretability, requiring multiple tree traversals and instance tracking. It provides instance-level explanations at the cost of not scaling well to very large datasets.

**Failure Signatures**: Method fails when trees have missing values, when feature interactions are too complex, or when training data is not accessible. Performance degrades with extremely large datasets due to computational complexity.

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions beyond the mentioned limitations regarding computational complexity for large datasets and restriction to regression tasks.

## Limitations
- Limited to regression tasks, cannot handle classification directly
- Requires access to training data, which may not always be available
- Computational complexity scales poorly with dataset size, making it impractical for very large datasets
- Theoretical framework assumes tree ensembles without missing values or complex feature interactions

**Generalizability across datasets and tasks**: Low - Only tested on one regression dataset
