# Pre-computed memory or on-the-fly encoding? A hybrid approach to retrieval augmentation makes the most of your compute

## Quick Facts
- arXiv ID: 2301.10448
- Source URL: https://arxiv.org/abs/2301.10448
- Reference count: 39
- Primary result: LUMEN outperforms MemoryFiD and FiD at equivalent FLOPs, with advantage scaling with model size

## Executive Summary
LUMEN introduces a hybrid approach to retrieval-augmented language models that combines the benefits of pre-computed memory with on-the-fly encoding. The method partially pre-computes encoder representations into memory while finalizing representations dynamically based on the question and task. This hybrid strategy achieves superior performance compared to both pure pre-computed (MemoryFiD) and pure on-the-fly (FiD) approaches while maintaining the same computational budget. The performance advantage becomes more pronounced as model scale increases, suggesting significant efficiency gains for larger implementations.

## Method Summary
LUMEN operates by strategically splitting the encoding process between pre-computation and on-the-fly computation. The approach pre-computes static portions of document representations and stores them in memory, while dynamically computing task-specific and question-dependent components during inference. This hybrid design allows the model to leverage the speed of memory retrieval while maintaining the adaptability of on-the-fly encoding. The key innovation lies in determining which components benefit from pre-computation versus those requiring dynamic computation, optimizing the balance between computational efficiency and representation quality.

## Key Results
- LUMEN achieves higher performance than both MemoryFiD and FiD on open-domain QA tasks
- The performance advantage of LUMEN increases with model scale
- LUMEN maintains the same FLOPs budget as baseline methods while delivering superior results
- The hybrid approach successfully combines benefits of both pre-computation and on-the-fly encoding strategies

## Why This Works (Mechanism)
The hybrid approach works by optimizing the trade-off between computational efficiency and representation adaptability. Pre-computing static document representations reduces redundant computation during inference, while on-the-fly encoding allows the model to tailor representations to specific questions and tasks. This selective computation strategy ensures that the model focuses computational resources where they matter most - on the dynamic aspects of the query-document interaction rather than on static document content that can be pre-computed.

## Architecture Onboarding

Component Map: Document Corpus -> Pre-computed Static Encoder -> Memory Store -> Dynamic Task Encoder -> Fusion Layer -> Output

Critical Path: Query → Dynamic Task Encoder → Similarity Search in Memory → Retrieved Documents → Fusion Layer → Final Answer Generation

Design Tradeoffs: The primary tradeoff involves determining the optimal split between pre-computed and on-the-fly components. More pre-computation reduces inference time but increases memory requirements and may reduce adaptability. Less pre-computation increases flexibility but requires more computation during inference.

Failure Signatures: The system may fail when the static pre-computed representations are insufficient for capturing query-specific nuances, or when the dynamic components cannot effectively leverage the pre-computed information. Performance degradation may occur if the balance between pre-computation and on-the-fly encoding is suboptimal.
