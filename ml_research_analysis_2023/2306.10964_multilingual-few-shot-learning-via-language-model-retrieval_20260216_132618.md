# Multilingual Few-Shot Learning via Language Model Retrieval

## Quick Facts
- arXiv ID: 2306.10964
- Source URL: https://arxiv.org/abs/2306.10964
- Reference count: 13
- Primary result: Semantic similarity-based few-shot example retrieval improves multilingual few-shot learning when retrieved examples share the same label

## Executive Summary
This paper investigates the impact of semantic similarity-based few-shot example retrieval in multilingual and cross-lingual settings for language model prompting. The authors propose retrieving semantically similar samples from a training set using a multilingual encoder to form context prompts, then using those prompts for few-shot in-context learning with language models. Experiments on five datasets across four languages demonstrate that nearest-neighbor retrieval consistently outperforms random sampling when similar examples share labels, though retrieval can hurt performance when similar examples have different labels.

## Method Summary
The method involves computing sentence-level embeddings using XLM-RBASE for all training examples and queries, then retrieving top-k semantically similar examples using cosine or Euclidean distance. These retrieved examples form prompts for few-shot in-context learning with GPT-J NEO (1.3B, English) or XGLM (1.7B, multilingual). The approach is evaluated across five datasets (SNIPS, MultiNLU, MTOP, TREC, SST2) in English, French, German, and Spanish, comparing retrieval strategies (random, nearest, farthest) and similarity measures while measuring accuracy over 5 runs.

## Key Results
- Nearest-neighbor retrieval consistently outperforms random sampling when retrieved examples share the same labels
- Farthest examples generally hurt performance compared to random sampling
- Cross-lingual retrieval is effective using multilingual encoder embeddings across languages
- SST2 dataset shows degradation with nearest-neighbor retrieval when semantically similar examples have different labels

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Semantic similarity-based retrieval improves few-shot performance when retrieved examples share the same label as the query.
- Mechanism: Retrieving examples with high semantic similarity ensures that the retrieved examples are contextually relevant and provide meaningful guidance for the model to infer the correct label.
- Core assumption: The multilingual encoder (XLM-R) produces embeddings that accurately reflect semantic similarity across languages and tasks.
- Evidence anchors:
  - [abstract] "We conduct a comprehensive study of retrieving semantically similar few-shot samples and using them as the context... The proposed method consistently outperforms random sampling in monolingual and cross-lingual tasks in non-English languages."
  - [section 4] "We find that retrieving similar samples consistently outperforms random sampling, when the semantically similar examples have the same labels as query."
  - [corpus] No direct evidence from corpus; relies on abstract and experimental results.
- Break condition: If semantically similar examples do not share the same label, retrieval can hurt performance (as observed in SST2).

### Mechanism 2
- Claim: The choice of retrieval strategy (nearest vs. farthest) significantly impacts few-shot performance.
- Mechanism: Nearest-neighbor retrieval selects examples most contextually similar to the query, providing better guidance. Farthest examples are less relevant and can confuse the model.
- Core assumption: Contextual similarity correlates with label relevance in the dataset.
- Evidence anchors:
  - [section 4] "In general, the nearest strategy consistently outperforms random and farthest, except in SST2 dataset."
  - [section 4] "We observe that the model's performance decreases when we use less similar samples as context."
  - [corpus] No direct evidence from corpus; relies on experimental results.
- Break condition: If the dataset or encoder embeddings do not align semantic similarity with label relevance (e.g., SST2), nearest-neighbor retrieval may not be optimal.

### Mechanism 3
- Claim: Cross-lingual retrieval is effective when using a multilingual encoder to compute embeddings.
- Mechanism: A multilingual encoder (XLM-R) can compute embeddings for queries and examples in different languages, enabling retrieval of semantically similar examples across languages.
- Core assumption: The multilingual encoder produces comparable embeddings across languages for semantically similar content.
- Evidence anchors:
  - [section 4] "Furthermore, we evaluate them in the downstream natural language understanding (NLU) tasks in four different languages: English, French, German, and Spanish... retrieving samples from multilingual LM is able to select semantically similar samples across different languages."
  - [section 2] "We compute the D-dimensional sentence-level embeddings... by aggregating the subword embeddings through average pooling over all subwords."
  - [corpus] No direct evidence from corpus; relies on experimental results and encoder design.
- Break condition: If the multilingual encoder's embeddings are not comparable across languages, cross-lingual retrieval will fail.

## Architecture Onboarding

- Component map:
  - Multilingual encoder (XLM-R) → Computes sentence embeddings
  - Distance/similarity function → Measures similarity between embeddings
  - Retrieval module → Selects top-k nearest (or farthest) examples
  - Language model (GPT-J NEO/XGLM) → Performs in-context learning with retrieved examples
  - Dataset → Source of training and test examples

- Critical path:
  1. Compute embeddings for all training examples
  2. Compute embedding for query
  3. Calculate similarity scores
  4. Retrieve top-k examples
  5. Construct prompt with retrieved examples
  6. Run in-context learning with language model

- Design tradeoffs:
  - Embedding quality vs. computation cost (average pooling vs. more complex methods)
  - Retrieval strategy (nearest vs. farthest vs. random)
  - Similarity measure (Euclidean vs. cosine distance)
  - Number of retrieved examples (k) vs. prompt length constraints

- Failure signatures:
  - Performance drops when retrieved examples don't share labels with query
  - Cross-lingual retrieval fails if embeddings aren't comparable across languages
  - Nearest-neighbor retrieval may not help if dataset or encoder doesn't align semantic similarity with label relevance

- First 3 experiments:
  1. Compare nearest-neighbor retrieval vs. random sampling on a single dataset/language pair
  2. Test different similarity measures (Euclidean vs. cosine) on the same dataset
  3. Evaluate cross-lingual retrieval by retrieving examples from a different language than the query

## Limitations
- Performance degradation occurs when semantically similar examples have different labels (SST2)
- Cross-lingual effectiveness not systematically validated with alternative encoders
- Lack of analysis on computational costs and scalability of retrieval approach

## Confidence
- **Medium**: Core finding that nearest-neighbor retrieval outperforms random sampling when retrieved examples share labels - supported by experimental results but depends on assumptions about embedding quality
- **Low**: Cross-lingual effectiveness claims - lacks ablation studies on embedding quality or language relatedness effects
- **Medium**: Comparative analysis of retrieval strategies - consistent across datasets but depends on specific language model and encoder

## Next Checks
1. Conduct ablation studies comparing XLM-R embeddings against alternative multilingual encoders (e.g., LaBSE, mBERT) to verify embedding quality isn't the limiting factor
2. Perform error analysis on SST2 specifically to understand when and why semantically similar examples have different labels, and whether filtering by label similarity improves results
3. Test the retrieval approach with different k values (number of examples) and prompt formats to establish robustness across prompt engineering variations
