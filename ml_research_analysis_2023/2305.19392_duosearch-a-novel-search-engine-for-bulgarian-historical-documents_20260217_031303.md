# DuoSearch: A Novel Search Engine for Bulgarian Historical Documents

## Quick Facts
- arXiv ID: 2305.19392
- Source URL: https://arxiv.org/abs/2305.19392
- Reference count: 8
- Key outcome: Introduces DuoSearch, a search engine for Bulgarian historical newspapers using OCR error correction and orthographic normalization, achieving 18.7% improvement in text correction accuracy over baseline.

## Executive Summary
DuoSearch is a novel search engine designed to handle Bulgarian historical newspaper collections plagued by OCR errors and orthographic variation from multiple language reforms. The system combines ElasticSearch with machine learning models—including a BERT-based error detection model and a character-level sequence-to-sequence correction model—to clean and standardize OCRed text before indexing. It also includes a spelling converter to handle historical orthographic forms. Tested on a 4 GB dataset, the prototype achieved an F-score of 0.79 and demonstrated an 18.7% improvement in text correction accuracy over baseline models. This is the first search engine tailored to Bulgarian historical documents and offers a replicable model for similar multilingual, error-prone collections.

## Method Summary
The system preprocesses OCRed historical Bulgarian text using a multi-stage pipeline: a BERT-based model detects OCR errors, a character-level sequence-to-sequence model corrects them, and a spelling converter normalizes historical orthographic forms. The cleaned text is then indexed in ElasticSearch, enabling both regular and extended search capabilities via a web interface. The approach addresses both OCR noise and language reform-induced orthographic variation, making the documents searchable despite their degraded and historically variable nature.

## Key Results
- F-score of 0.79 on ICDAR 2019 competition dataset
- 18.7% improvement in text correction accuracy over baseline model
- 9% improvement over prior state-of-the-art correction approach

## Why This Works (Mechanism)
The system leverages machine learning to correct both OCR errors and historical orthographic variation, which are the primary barriers to effective search in digitized historical Bulgarian newspapers. By combining error detection (BERT) with correction (sequence-to-sequence) and orthographic normalization, the pipeline standardizes text before indexing, enabling more accurate retrieval. ElasticSearch then provides scalable, full-text search capabilities over the cleaned corpus.

## Foundational Learning

1. **OCR error detection with BERT**
   - Why needed: OCR errors in historical documents are diverse and context-dependent, requiring semantic understanding for accurate detection.
   - Quick check: Model correctly flags known OCR errors in sample historical text.

2. **Character-level sequence-to-sequence correction**
   - Why needed: OCR errors often involve character substitutions, insertions, or deletions that require fine-grained correction.
   - Quick check: Corrected text matches ground truth for a set of annotated OCR errors.

3. **Orthographic normalization across language reforms**
   - Why needed: Bulgarian spelling has changed over time due to multiple language reforms, creating variation in historical texts.
   - Quick check: Historical spellings are correctly mapped to modern equivalents.

4. **ElasticSearch indexing of cleaned text**
   - Why needed: Full-text search requires consistent, normalized text to ensure recall and precision.
   - Quick check: Search queries return relevant documents with cleaned, normalized content.

5. **Web interface for search**
   - Why needed: Accessibility for end users, especially historians and researchers.
   - Quick check: Search interface returns results and handles user queries as expected.

## Architecture Onboarding

**Component Map**
OCR text -> BERT error detection -> Character-level correction -> Orthographic normalization -> ElasticSearch index -> Web interface

**Critical Path**
OCR text → BERT error detection → Character-level correction → ElasticSearch indexing → Search query → Web interface display

**Design Tradeoffs**
- Pre-processing overhead vs. search accuracy: cleaning text before indexing improves recall but increases preprocessing time.
- Model complexity vs. deployment feasibility: BERT and sequence models are accurate but resource-intensive.

**Failure Signatures**
- Missed OCR errors lead to poor recall in search results.
- Incorrect orthographic normalization causes false negatives.
- Indexing errors result in missing or malformed search results.

**3 First Experiments**
1. Verify OCR error detection model flags synthetic and real OCR errors with high precision.
2. Test orthographic normalization on a small set of known historical spellings.
3. Index a small subset of cleaned text and confirm search returns expected results.

## Limitations
- Evaluation based on a small dataset (4 GB) and single external benchmark (ICDAR 2019).
- Performance metrics may not generalize to the full 200 GB collection.
- Claims about being the "first search engine tailored to Bulgarian historical documents" lack comparative analysis with existing systems.
