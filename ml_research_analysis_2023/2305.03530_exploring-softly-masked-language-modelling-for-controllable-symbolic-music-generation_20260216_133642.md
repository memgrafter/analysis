# Exploring Softly Masked Language Modelling for Controllable Symbolic Music Generation

## Quick Facts
- arXiv ID: 2305.03530
- Source URL: https://arxiv.org/abs/2305.03530
- Reference count: 16
- Key outcome: SMLM enables controllable symbolic music generation by allowing partial information in masked elements rather than binary known/unknown states

## Executive Summary
This paper introduces Softly Masked Language Modelling (SMLM), a generalization of masked language modeling that allows elements to be partially known rather than strictly known or unknown. The authors apply SMLM to controllable symbolic music generation using a transformer encoder architecture trained on 64-step music loops from the MetaMIDI dataset. By representing music as note events with pitch, onset, and duration attributes, and using soft masking to add "false" activations during training, the model learns to generate music that satisfies various constraints like specific scales, duration ranges, or rhythm patterns.

## Method Summary
The method uses a transformer encoder architecture with element-wise representation of music notes, where each note is decomposed into pitch, onset, and duration attributes. During training, soft masking adds "false" activations to one-hot vectors, creating multi-hot vectors that indicate multiple possible values. The model learns to predict masked elements from these probabilistic ground truth signals. For generation, constraints are expressed as masks that limit possible values for each attribute, and the model samples from remaining possibilities to produce music satisfying the specified constraints.

## Key Results
- SMLM successfully generates music satisfying various constraints including pitch scales, duration ranges, and rhythm patterns
- The model trains effectively using the soft masking approach, achieving training/validation loss around 1.80/1.75
- Generation quality is demonstrated through examples showing constraint satisfaction across multiple musical dimensions

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Softly masked language modeling generalizes masked language modeling by allowing elements to be partially known rather than strictly known or unknown
- Mechanism: The model learns to predict masked elements from a set of possible values, where the mask can indicate multiple possible values rather than a single value
- Core assumption: The model can effectively learn from probabilistic ground truth signals rather than binary masks
- Evidence anchors:
  - [abstract] "SMLM can be seen as a generalisation of masked language modelling (MLM), where instead of each element of the input set being either known or unknown, elements can be partly known."
  - [section 2] "We choose the following soft masking process: starting from a one hot vector xi, we add new, 'false' activations so that it becomes a multi-hot vector."
- Break condition: If the model cannot effectively learn from multi-hot vectors rather than one-hot vectors, performance will degrade

### Mechanism 2
- Claim: The transformer encoder architecture can effectively process and generate symbolic music with the proposed representation
- Mechanism: The transformer processes element embeddings (derived from pitch, onset, and duration attributes) through self-attention layers to capture musical dependencies
- Core assumption: The element-wise attribute encoding and pooling strategy effectively captures musical information for the transformer
- Evidence anchors:
  - [section 3.4] "We encode each element attribute with attribute specific encoders... The element attributes are pooled by summing the embedding of each attribute to form an element embedding."
  - [section 3.4] "For our main block, we use a neural network with the transformer encoder architecture"
- Break condition: If the element representation fails to capture important musical relationships, the model will generate incoherent music

### Mechanism 3
- Claim: The soft masking approach enables controllable generation by constraining note attributes to sets of values
- Mechanism: During generation, constraints are expressed as masks that limit the possible values for each attribute, and the model samples from the remaining possibilities
- Core assumption: The model can effectively generate music that satisfies constraints by sampling from masked distributions
- Evidence anchors:
  - [section 3.6] "In order to generate note that satisfy a constraint, we express our constraint in the form of a mask... We then generate the composition by sampling attributes from notes in random order."
  - [section 4] Multiple examples showing generation with various constraints (pitch scales, duration ranges, rhythm patterns)
- Break condition: If the sampling process produces invalid combinations or fails to satisfy constraints, the approach breaks down

## Architecture Onboarding

- Component map: Input → Attribute Encoders → Element Pooling → Transformer Encoder → Attribute Decoders → Output
- Critical path: The transformer encoder block is the core processing unit. All other components serve to prepare inputs and decode outputs for this central module.
- Design tradeoffs: The representation limits notes to 36 pitches and 64 steps, trading generality for computational efficiency. The soft masking approach trades some training signal clarity for greater generation flexibility.
- Failure signatures: If generation produces invalid attribute combinations (e.g., defined pitch with undefined duration), the normalization function isn't working. If constrained generation ignores constraints, the masking implementation is broken.

## Open Questions the Paper Calls Out

- Basis in paper: [inferred] The paper mentions future work to "Perform qualitative and quantitative evaluation of the system" but does not compare to existing methods
- Why unresolved: The authors only demonstrate SMLM on their own dataset without benchmarking against established approaches
- What evidence would resolve it: Comparative studies measuring constraint satisfaction rates, generation quality metrics, and human evaluations against other controllable music generation systems

### Open Question 2
- Question: How does the choice of masking strategy during training affect the model's ability to generalize to unseen constraints?
- Basis in paper: [explicit] The paper describes a two-stage masking scheme but states it was chosen for simplicity without exploring alternatives
- Why unresolved: The authors don't investigate how different masking strategies impact model performance or constraint satisfaction
- What evidence would resolve it: Systematic experiments varying masking strategies (e.g., soft vs hard masking, different masking ratios) and measuring their effects on generation quality and constraint adherence

## Limitations
- The soft masking mechanism's effectiveness depends on unspecified masking distribution parameters, making it difficult to assess consistent learning
- The representation's restriction to 36 pitches and 64-step segments significantly limits musical complexity and expressiveness
- The paper lacks quantitative evaluation metrics beyond training loss, making it difficult to assess improvements over existing approaches

- The soft masking process can be implemented as described, creating multi-hot vectors from one-hot vectors through additive "false" activations
- The constraint satisfaction mechanism can enforce attribute-specific constraints during generation by masking invalid values

**Medium Confidence Claims:**
- SMLM provides meaningful generalization over traditional masked language modeling by handling partial information
- The learned representations capture musically relevant dependencies between note attributes
- The generation quality is sufficient for practical music composition tasks

**Low Confidence Claims:**
