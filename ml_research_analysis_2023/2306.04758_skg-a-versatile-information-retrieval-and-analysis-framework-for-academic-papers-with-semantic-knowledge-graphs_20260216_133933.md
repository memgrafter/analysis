# SKG: A Versatile Information Retrieval and Analysis Framework for Academic Papers with Semantic Knowledge Graphs

## Quick Facts
- arXiv ID: 2306.04758
- Source URL: https://arxiv.org/abs/2306.04758
- Reference count: 40
- This paper presents a framework for efficient information retrieval and analysis from academic papers using a Semantic Knowledge Graph (SKG)

## Executive Summary
This paper introduces SKG, a framework for information retrieval and analysis from academic papers using Semantic Knowledge Graphs. The framework integrates semantic concepts extracted from abstracts with metadata to enable flexible semantic queries. A semi-supervised knowledge extraction module combines unsupervised entity recognition with human annotation to train NER models, applied to a large visualization literature dataset (VISBank). The framework demonstrates high-quality concept extraction with f1-scores ranging from 0.5 to 0.9 across different concept types, and includes a dataflow system for interactive querying and analysis.

## Method Summary
The SKG framework constructs a semantic knowledge graph from academic papers by extracting five types of concepts (application, data, method, visualization, evaluation) from abstracts. A semi-supervised NER pipeline first uses unsupervised candidate entity extraction via POS tagging and rule-based noun n-grams, then classifies entities using a QA model fine-tuned on SQuAD2.0. High-confidence samples are refined by human annotators to create a training set for fine-tuning a RoBERTa model. Extracted concepts are normalized using DBpedia Spotlight and represented as RDF triples. The framework includes a dataflow system with operator components (querier, expander, comparer) and viewer components (node visualizer, table viewer, node viewer) for interactive semantic querying.

## Key Results
- SKG achieves f1-scores ranging from 0.5 to 0.9 across different concept types in entity extraction
- The dataflow system enables non-programmers to construct complex semantic queries interactively without learning SPARQL
- Real-world case studies demonstrate the framework's effectiveness for literature review and knowledge discovery in the visualization domain

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The semi-supervised knowledge extraction module significantly reduces the need for manual labeling while maintaining high-quality NER results.
- Mechanism: The unsupervised pipeline first extracts candidate entities using POS-based rules and then classifies them using a QA model fine-tuned on SQuAD2.0. High-confidence samples are selected and refined by human annotators to create a high-quality training set, which is then used to fine-tune a language model (RoBERTa) for final NER.
- Core assumption: A QA model can accurately classify entities into semantic categories based on contextual understanding derived from pre-training on general QA datasets.
- Evidence anchors:
  - [abstract] "To extract knowledge from unstructured text, we develop a Knowledge Extraction Module that includes a semi-supervised pipeline for entity extraction and entity normalization."
  - [section 3.2.2] "We utilize a Question-Answering (QA) model to generate labels for entities based on their contextual information."
  - [section 5] "The unsupervised pipeline achieved an f1-score of over 0.5, except for the data and method classes."
- Break condition: If the QA model cannot generalize entity classification beyond the patterns seen in SQuAD2.0, or if human annotation effort increases significantly due to ambiguous cases.

### Mechanism 2
- Claim: Integrating semantic concepts from abstracts with metadata enables more flexible and semantically rich queries than metadata-only knowledge graphs.
- Mechanism: By extracting five types of concepts (application, data, method, visualization, evaluation) from abstracts and linking them to papers, authors, venues, and journals, the SKG supports multi-hop semantic queries that combine content understanding with bibliographic data.
- Core assumption: Abstracts contain sufficient semantic information to categorize research contributions accurately and that these categories align with user information needs.
- Evidence anchors:
  - [abstract] "The SKG integrates semantic concepts from abstracts and other meta-information to represent the corpus."
  - [section 3.1] "Concepts with different semantic roles are captured in relationships between Paper and Concept."
  - [section 3.3] "Semantic queries share a common characteristic of identifying a set of starting entities and specifying search criteria to navigate SKG and reach the target entities."
- Break condition: If abstracts are too terse or domain-specific terminology is not captured by the NER model, the semantic richness will degrade, limiting query effectiveness.

### Mechanism 3
- Claim: The dataflow system enables non-programmers to construct complex semantic queries interactively without learning SPARQL or other query languages.
- Mechanism: The system provides operator components (querier, expander, comparer) and viewer components (node visualizer, table viewer, node viewer) that users can connect via drag-and-drop to build analysis pipelines. Each component has predefined inputs/outputs matching SKG entity types and relationships.
- Core assumption: Visual programming metaphors are intuitive enough for domain experts to construct queries that would otherwise require structured query language expertise.
- Evidence anchors:
  - [abstract] "Furthermore, we design and develop a dataflow system that demonstrates how to conduct various semantic queries flexibly and interactively over the SKG."
  - [section 3.4.2] "The system comprises a set of components with predefined inputs and outputs that users can choose and connect to construct their customized analysis pipeline."
  - [section 5.2] "Emily is satisfied that various relationship types in SKG can be utilized to retrieve documents in succinct way without the troublesome of relying on multiple resources."
- Break condition: If the component abstraction becomes too complex or users cannot map their information needs to the available component combinations, the system will fail to lower the barrier to query construction.

## Architecture Onboarding

- Component map:
  Data layer: VISBank dataset (raw papers with metadata and abstracts)
  Extraction layer: Semi-supervised NER module (unsupervised pipeline → human refinement → fine-tuned RoBERTa model)
  Graph layer: SKG construction (entities + RDF triples + DBpedia integration)
  Query layer: Dataflow system (operator components + viewer components)
  Visualization layer: Interactive node-link diagrams, Sankey diagrams, tables, and web viewers

- Critical path:
  1. Load VISBank dataset
  2. Extract candidate entities via POS-based rules
  3. Classify entities using QA model
  4. Human refine high-confidence samples
  5. Fine-tune RoBERTa on refined dataset
  6. Run inference on all abstracts to extract concepts
  7. Normalize concepts via DBpedia Spotlight
  8. Construct SKG in RDF format
  9. Deploy dataflow system for querying

- Design tradeoffs:
  - Semi-supervised vs fully supervised: Reduces labeling cost but may sacrifice some precision compared to fully supervised approaches
  - Abstract-only vs full-text processing: Abstracts are more manageable and standardized but may miss important concepts mentioned only in full text
  - Visual dataflow vs query language: Lowers barrier to entry but may limit expressiveness for complex queries
  - DBpedia integration vs custom ontology: Leverages existing knowledge but may introduce noise or miss domain-specific concepts

- Failure signatures:
  - Low NER precision/recall indicates the QA model or fine-tuning process is not capturing domain-specific terminology
  - Concept extraction misses important entities suggests the unsupervised pipeline rules or QA model are too restrictive
  - Dataflow system becomes unwieldy indicates the component abstraction is not matching user mental models
  - RDF graph is too sparse or disconnected suggests the entity extraction or relationship identification is failing

- First 3 experiments:
  1. Run the unsupervised pipeline on a small subset of abstracts and manually verify the candidate entity extraction and initial classification accuracy
  2. Test the human refinement process by having annotators correct the high-confidence samples and measure inter-annotator agreement
  3. Build a minimal dataflow pipeline that queries for papers by a specific concept and visualizes the results to validate the end-to-end integration

## Limitations

- The semi-supervised approach shows variable performance across concept types with f1-scores ranging from 0.5 to 0.9, indicating potential inconsistency in entity recognition quality
- Reliance on abstracts rather than full-text processing may miss important domain-specific concepts that appear only in methodology sections or discussions
- DBpedia-based normalization could introduce noise or fail to capture visualization-specific terminology not present in general knowledge bases

## Confidence

- High confidence: The overall framework architecture and dataflow system design are well-documented and reproducible
- Medium confidence: The semi-supervised NER module's effectiveness, as the exact implementation details and performance across different datasets are not fully specified
- Medium confidence: The query flexibility claims, as the paper provides case studies but limited quantitative evaluation of the system's expressiveness
