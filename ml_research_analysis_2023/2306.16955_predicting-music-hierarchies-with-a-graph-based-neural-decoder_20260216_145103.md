# Predicting Music Hierarchies with a Graph-Based Neural Decoder

## Quick Facts
- arXiv ID: 2306.16955
- Source URL: https://arxiv.org/abs/2306.16955
- Authors: 
- Reference count: 0
- Key outcome: A transformer-based graph neural decoder achieves 79.2% head accuracy on jazz chord trees and 57.9% on monophonic melody trees, outperforming grammar-based parsers.

## Executive Summary
This paper presents a data-driven approach to parse musical sequences into dependency trees, a hierarchical structure used in music cognition research and analysis. The method involves using a transformer encoder to enrich the input sequence with contextual information, followed by a classifier that filters the graph of all possible dependency arcs to produce the dependency tree. This approach can be easily integrated into modern deep-learning pipelines and can consider multiple musical features simultaneously, making use of sequential context information and producing partial results for noisy inputs. The system was tested on two datasets of musical trees—time-span trees of monophonic note sequences and harmonic trees of jazz chord sequences—and showed improved performance compared to previous methods.

## Method Summary
The method uses a transformer encoder to contextualize input features (pitch, duration, metrical position) and an MLP to predict the probability of each possible dependency arc. All arc predictions are made in parallel, and the Eisner algorithm ensures the output forms a valid tree. The model is trained with a combination of binary and multi-class cross-entropy losses. The architecture is evaluated on two datasets: the GTTM dataset of monophonic melodies with time-span trees, and the Jazz Harmony Treebank of chord sequences with harmonic trees.

## Key Results
- The model achieves 79.2% head accuracy on the Jazz Harmony Treebank and 57.9% on the GTTM dataset.
- The graph-based approach outperforms grammar-based parsers on both datasets.
- The method can consider multiple musical features simultaneously and produces partial results for noisy inputs.

## Architecture Onboarding

- Component map:
  1. Feature extraction layer: Converts raw musical input into categorical features
  2. Embedding layer: Maps categorical features to continuous vectors
  3. Transformer encoder: Produces contextualized embeddings
  4. Arc predictor (MLP): Predicts dependency arcs from contextualized embeddings
  5. Post-processing (Eisner algorithm): Ensures output is a valid tree structure

- Critical path: Feature extraction → Embedding → Transformer encoding → Arc prediction → Post-processing

- Design tradeoffs:
  - Using a transformer encoder vs. an LSTM for contextual information
  - Concatenating vs. summing or multiplying head and dependent embeddings
  - Using BCE loss, CE loss, or both for training
  - Implementing post-processing for projective trees vs. non-projective trees

- Failure signatures:
  - Low head accuracy but high arc accuracy: Model is connecting correct notes but in the wrong direction
  - Low span accuracy: Model is struggling to connect the correct notes
  - High accuracy on training set but low on test set: Overfitting to training data

- First 3 experiments:
  1. Ablation study: Remove the transformer encoder and replace with an LSTM to measure the impact on accuracy
  2. Loss function comparison: Train with only BCE loss, only CE loss, and both losses to determine the best combination
  3. Post-processing evaluation: Compare accuracy with and without post-processing to assess its impact on tree structure formation

## Open Questions the Paper Calls Out

- Question: Can the proposed model architecture scale to longer musical sequences without sacrificing performance, and what are the computational limits?

- Why unresolved: The paper only tests the model on datasets with relatively short sequences (up to 127 notes for the GTTM dataset and up to 38 chords for the JHT dataset). ## Limitations

- The model's performance on longer musical sequences is untested, and the cubic complexity of the post-processing algorithm may limit scalability.
- The absence of a validation set means model selection relies entirely on the cosine annealing schedule, which may not reliably prevent overfitting.
- The post-processing step using the Eisner algorithm constrains predictions to projective trees, potentially excluding valid non-projective structures that appear in music.

## Confidence

**High Confidence**: The core architecture design (transformer encoder + MLP arc predictor + Eisner post-processing) is clearly specified and represents a reasonable approach to the problem. The reported accuracy improvements over previous methods are well-documented.

**Medium Confidence**: The training procedure and hyperparameter choices are described with sufficient detail for reproduction, though some implementation specifics (like exact relative position encoding) remain unclear. The dataset preprocessing steps are mostly clear but contain some ambiguities.

**Low Confidence**: The generalization of the model to other musical structures beyond the two tested domains (monophonic melodies and jazz chord sequences) is not demonstrated. The impact of the graph-based approach's independence assumption on long-range dependencies in music remains unclear.
