# A Simple Algorithm For Scaling Up Kernel Methods

## Quick Facts
- arXiv ID: 2301.11414
- Source URL: https://arxiv.org/abs/2301.11414
- Reference count: 20
- Key outcome: Introduces FABR algorithm enabling kernel methods with virtually infinite random features through recursive eigenvalue decomposition

## Executive Summary
This paper presents FABR (Fast Annihilating Batch Regression), a scalable random feature regression algorithm that overcomes computational bottlenecks in traditional kernel methods. By leveraging linear algebraic properties of covariance matrices, FABR recursively updates eigenvalue decompositions to efficiently optimize across large grids of ridge parameters without storing full feature matrices. The method demonstrates superior performance on CIFAR-10 compared to both deep neural networks and compositional kernel methods, particularly in small-data regimes, while maintaining computational efficiency for high-dimensional feature spaces.

## Method Summary
FABR addresses the scalability challenge in kernel methods by processing random features in blocks and recursively updating the eigenvalue decomposition of the covariance matrix. The algorithm uses a rank-ν approximation to eliminate small eigenvalues, enabling efficient computation even with millions of features. For each ridge parameter in a predefined grid, FABR computes the regression solution using stored eigenvectors rather than the full feature matrix. The method can be modified for mini-batch processing, creating ensembles that often achieve better generalization than full-sample regression. Experiments validate the approach on synthetic datasets and CIFAR-10 classification.

## Key Results
- FABR outperforms both deep neural networks and compositional kernel methods on CIFAR-10, especially in small-data regimes
- With sufficient model complexity and appropriate regularization, FABR achieves accuracy comparable to or exceeding ResNet-34 and Neural Tangent Kernels
- The algorithm is significantly faster than existing implementations for high-dimensional feature spaces
- Mini-batch FABR and FABR-ν variants sometimes achieve higher accuracy than full-sample regression on moderately-sized datasets

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Recursive eigenvalue decomposition of covariance matrices enables scalable kernel methods
- Mechanism: The algorithm recursively updates the eigenvalue decomposition of the feature covariance matrix, allowing efficient optimization across a large grid of ridge parameters without storing full feature matrices
- Core assumption: Eigenvalues of the empirically observed covariance matrices decay quickly, making low-rank approximations effective
- Evidence anchors: [abstract] "use linear algebraic properties of covariance matrices to recursively update the eigenvalue decomposition of the feature covariance matrix"; [section] "we can fix a ν ∈ N and design a simple, rank −ν approximation to ΨK by annihilating all eigenvalues belowλν(ΨK)"
- Break condition: When eigenvalues don't decay quickly enough, making rank-ν approximations ineffective

### Mechanism 2
- Claim: Block-wise processing eliminates memory bottlenecks for infinite features
- Mechanism: Features are processed in blocks, computing (SS⊤ + zI)−1y instead of (S⊤S + zI)−1S⊤y, allowing single-block storage and recursive computation
- Core assumption: Matrix identity (S⊤S/N + zI)−1S⊤ = S⊤(SS⊤/N + zI)−1 holds and can be computed efficiently
- Evidence anchors: [section] "we can compute β(z) as β(z) = S⊤(SS⊤/N +zI)−1y/N" and "We start with a simple observation that the following identity implies that storing all these features is not necessary"
- Break condition: When matrix multiplication or eigenvalue decomposition of intermediate blocks becomes the bottleneck

### Mechanism 3
- Claim: Mini-batch processing enables both scalability and improved generalization
- Mechanism: The algorithm can be modified to use mini-batches, creating an ensemble of predictions that achieves lower generalization error than full-sample regression
- Core assumption: Mini-batch linear regression can lead to performance gains in high-complexity regimes through ensemble averaging
- Evidence anchors: [section] "our regression method can be easily modified to allow for mini-batches" and "one can run regression on mini-batches and then treat the obtained predictions as an ensemble"
- Break condition: When mini-batch size becomes too small to capture important eigenvalue information

## Architecture Onboarding

- Component map: Feature generation → Covariance accumulation → Eigenvalue update → Ridge solution → Prediction
- Critical path: Feature generation → Covariance accumulation → Eigenvalue update → Ridge solution → Prediction
- Design tradeoffs:
  - Block size vs memory usage: Larger blocks reduce recursion overhead but increase memory requirements
  - Rank approximation (ν) vs accuracy: Higher ν preserves more information but increases computation
  - Number of ridge parameters vs runtime: More parameters provide better model selection but increase computation time
- Failure signatures:
  - Memory errors: Indicates blocks too large or insufficient eigenvalue compression
  - Slow convergence: Suggests eigenvalues don't decay quickly enough for effective rank approximation
  - Poor accuracy: May indicate insufficient model complexity or inappropriate random feature mapping

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Can the FABR algorithm be effectively extended to handle extremely large datasets where even storing the covariance matrix becomes infeasible?
- Basis in paper: [inferred] The paper mentions that for very large sample sizes N, the algorithm uses a rank-ν approximation to the covariance matrix, but it's unclear if this approach scales to truly massive datasets.
- Why unresolved: The paper only provides preliminary results for moderate dataset sizes and doesn't explore the limitations or performance of the rank-ν approximation for extremely large N.
- What evidence would resolve it: Experiments demonstrating FABR's performance and scalability on datasets with millions or billions of samples, comparing different rank-ν values and their impact on accuracy and computation time.

- Basis in paper: [explicit] The paper acknowledges that FABR uses simple random feature mappings and suggests that more complex kernels might be necessary for competitive performance on large datasets, but doesn't explore this experimentally.
- Why unresolved: The paper focuses on simple random features and doesn't investigate how different feature mappings or kernel choices impact FABR's performance.
- What evidence would resolve it: Comparative experiments using FABR with various random feature mappings (e.g., different activation functions, deeper networks) and more complex kernels, measuring accuracy and computational efficiency across different dataset sizes.

### Open Question 3

- Relies on specific assumptions about eigenvalue decay patterns that may not generalize to all datasets
