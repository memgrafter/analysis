# Multipath agents for modular multitask ML systems

## Quick Facts
- **arXiv ID**: 2302.02721
- **Source URL**: https://arxiv.org/abs/2302.02721
- **Reference count**: 10
- **Key outcome**: Multipath agents can improve task performance by combining frozen modules from different tasks via trainable connectors and router, achieving gains over singlepath baselines on ImageNet2012 and VTAB-1k.

## Executive Summary
This work introduces multipath agents as a method for extending modular multitask ML systems by enabling parallel routing of frozen paths. The approach is demonstrated on the µ3Net system, which solves 124 image classification tasks. Each multipath agent generates architectures that activate multiple parallel paths, with trainable connectors and routers learning to combine representations from frozen singlepath models. The method shows quality gains by training only a fraction of the parameters while leveraging knowledge from diverse tasks.

## Method Summary
The method extends a multitask system by introducing multipath agents that can combine frozen paths from different tasks. Each agent samples models from an evolutionary population, mutates them by changing support paths and hyperparameters, and trains only the connector and router modules. The router applies per-sample softmax weights over paths during forward pass, while backprop decoupled routing ensures unscaled gradients during backward pass to prevent early convergence to a single path. The process runs for 15 evolutionary cycles with 10 independent system replicas.

## Key Results
- Multipath agents achieve quality gains over singlepath baselines by training only connectors and router modules.
- Backprop decoupled routing prevents router collapse to main path only, which occurs in ablation experiments.
- Per-sample routing via the router improves performance compared to static aggregation methods.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Multipath agents can reuse frozen modules from different tasks to improve performance on a target task without retraining those modules.
- Mechanism: Paths are frozen modules that can be combined in parallel with trainable connector modules and a router. The router conditions path aggregation on each input sample.
- Core assumption: Knowledge from different tasks is complementary and can be effectively combined via learned connectors and router weights.
- Evidence anchors:
  - [abstract] "Diverse agents can compete to produce the best performing model for a task by reusing the modules introduced to the system by competing agents."
  - [section 2.1] "Each multipath agent combines available models/paths in a frozen state... connected with trainable connector modules."
- Break condition: If frozen modules are incompatible or redundant, the connectors and router cannot recover performance gains.

### Mechanism 2
- Claim: Backprop decoupled routing prevents early convergence to a single path, allowing all paths to continue learning.
- Mechanism: During forward pass, router weights are applied; during backward pass, gradients are unscaled and applied equally to all modules regardless of router weight.
- Core assumption: The rich gets richer effect causes routers to converge prematurely to a single path if gradients are scaled by router weights.
- Evidence anchors:
  - [section 2.1.2] "This effect is more accentuated for the proposed multipath method, because the main path is initialized with a converged model, while the support paths require training of the connector."
  - [section 2.1.2] "This allows the modules to receive unscaled gradients, independently from the selection choice of the router."
- Break condition: If training is too short or paths are too dissimilar, the unscaled gradients may not be sufficient to train less-used paths.

### Mechanism 3
- Claim: Per-sample routing allows the model to adapt its behavior based on input characteristics, improving generalization.
- Mechanism: Router module produces a softmax over paths conditioned on main path logits, allowing sample-specific path selection.
- Core assumption: Different samples from the same task benefit from different combinations of paths based on their features.
- Evidence anchors:
  - [abstract] "The router learns to weigh the activated paths conditioning on features of each input sample."
  - [section 2.1] "The router learns to weigh the activated paths conditioning on features of each input sample."
- Break condition: If the router cannot distinguish relevant features or if all samples benefit from the same path combination, per-sample routing adds unnecessary complexity.

## Architecture Onboarding

- Component map:
  - Main path: Frozen path from singlepath agent solving target task
  - Support paths: Additional frozen paths from other tasks
  - Connectors: Trainable fully connected layers mapping support path representations to target logits space
  - Router: Trainable fully connected layer producing per-sample softmax weights over paths
  - Aggregation: Weighted sum of logits during forward pass, sum during backward pass

- Critical path:
  1. Sample parent multipath model from population or initialize randomly
  2. Mutate by changing support paths and/or hyperparameters
  3. Train only connectors and router
  4. Evaluate on validation set
  5. Keep best scoring model, discard others
  6. Repeat for 15 evolutionary cycles

- Design tradeoffs:
  - More support paths increase parameter count and potential performance but also training time and risk of overfitting
  - Router learning rate multiplier allows independent optimization but adds hyperparameter tuning complexity
  - Backprop decoupled routing prevents rich gets richer but may slow convergence on clearly superior paths

- Failure signatures:
  - Router collapsing to main path only (ablation study showed this happens without backprop decoupling)
  - Test accuracy not improving beyond main path accuracy
  - High variance across evolutionary cycles indicating unstable learning

- First 3 experiments:
  1. Run multipath agent with backprop decoupled routing disabled to observe router collapse behavior
  2. Test different router learning rate multipliers (0.01, 0.1, 1.0) to find optimal scaling
  3. Compare per-sample routing vs. static aggregation to measure benefit of adaptive weighting

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal number of support paths to activate in parallel for maximizing quality gains while minimizing computational cost?
- Basis in paper: [inferred] The paper discusses randomly sampling support paths from the available paths in the system and mentions that the search space grows rapidly as more tasks are added, making exhaustive exploration infeasible.
- Why unresolved: The paper does not provide empirical evidence to determine the optimal number of support paths. It only mentions that the default number of used paths is 2 and the maximum is 3.
- What evidence would resolve it: Experiments comparing the performance of multipath agents with different numbers of support paths, controlling for other factors like model size and training budget.

### Open Question 2
- Question: How does the proposed multipath agent method compare to other ensemble learning techniques in terms of quality gains and computational efficiency?
- Basis in paper: [explicit] The paper discusses the similarities and differences between the proposed method and ensemble learning, noting that the proposed method combines models trained on different tasks and requires training of connector modules.
- Why unresolved: The paper does not provide a direct comparison between the multipath agent method and other ensemble learning techniques.
- What evidence would resolve it: Experiments comparing the performance of the multipath agent method to other ensemble learning techniques, such as model ensembling and mixture-of-experts, on the same tasks and datasets.

### Open Question 3
- Question: What are the limitations of the proposed backprop decoupled routing technique, and are there alternative solutions that could address these limitations?
- Basis in paper: [explicit] The paper discusses the backprop decoupled routing technique as a solution to the rich gets richer effect, but also mentions that it does not allow modules to specialize on the subset of samples for which the router selects them with higher weight.
- Why unresolved: The paper does not explore alternative solutions to the rich gets richer effect that could allow for module specialization while still being compatible with the modular nature of the proposed research methodology.
- What evidence would resolve it: Experiments comparing the performance of the backprop decoupled routing technique to alternative solutions, such as auxiliary loss factors and hard routing extensions, on the same tasks and datasets.

## Limitations

- The method relies on compatibility of frozen modules across tasks; incompatible modules may degrade performance.
- Backprop decoupled routing prevents module specialization on subsets of samples selected by the router.
- The optimal number of support paths and router hyperparameters require additional tuning and experimentation.

## Confidence

- **High Confidence**: The multipath architecture design (frozen paths + trainable connectors + router) is well-specified and experimentally validated on ImageNet2012 and VTAB-1k tasks.
- **Medium Confidence**: The backprop decoupled routing mechanism effectively prevents router collapse, though its impact on convergence speed requires further analysis.
- **Low Confidence**: The generalization of per-sample routing benefits across diverse task distributions and the scalability to larger module populations remain unproven.

## Next Checks
