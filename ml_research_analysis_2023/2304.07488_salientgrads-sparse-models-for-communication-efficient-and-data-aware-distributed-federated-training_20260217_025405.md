# SalientGrads: Sparse Models for Communication Efficient and Data Aware Distributed Federated Training

## Quick Facts
- arXiv ID: 2304.07488
- Source URL: https://arxiv.org/abs/2304.07488
- Reference count: 17
- Key outcome: 1.27-2.32× communication speedup with 90% sparsity on CIFAR-10

## Executive Summary
This paper introduces SalientGrads, a sparse federated learning approach that addresses communication efficiency challenges by identifying and training only a subset of neural network parameters. The method uses data-aware saliency scores computed from local client data to create a global mask that identifies important parameters before training begins. By transmitting only sparse gradients in compressed sparse row format, SalientGrads achieves significant communication time improvements while maintaining competitive accuracy on CIFAR-10 classification tasks.

## Method Summary
SalientGrads proposes a novel federated learning paradigm where clients first compute parameter saliency scores from their local data, which are then aggregated on the server to create a global mask identifying the most important parameters. This mask is broadcast to all clients, and training proceeds with only these selected parameters being updated and communicated. The method eliminates the need to share full model weights during training by having all clients start from the same initialization and apply the same mask throughout training. Sparse gradients are transmitted in CSR format, achieving 90% sparsity while maintaining accuracy between 84.62-93.74% across different ResNet architectures.

## Key Results
- 1.27-2.32× communication time speedup compared to FedAvg baseline
- 90% parameter sparsity maintained while achieving 84.62-93.74% accuracy on CIFAR-10
- Performance consistent across ResNet-20, ResNet-32, ResNet-44, ResNet-56, and ResNet-110 architectures
- Communication efficiency gains achieved without significant accuracy degradation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Saliency scores computed from local client data can identify a global sparse subnetwork that works across all clients.
- Mechanism: Each client computes parameter saliency scores using local data, aggregates them on the server, and selects top-k parameters to form a shared mask. This mask is broadcast once and used throughout training.
- Core assumption: The intersection of locally important parameters is globally important enough to maintain model accuracy.
- Evidence anchors:
  - [abstract] "simplifies the process of sparse training by choosing a data aware subnetwork before training, based on the model-parameter's saliency scores, which is calculated from the local client data"
  - [section 4.1] "To create the global mask mg we average all the saliency scores from N different sites and apply the top-k operator"
  - [corpus] Weak - related work focuses on dynamic pruning but not on static data-aware initialization
- Break condition: If client data distributions are too heterogeneous, the averaged saliency scores may select parameters that work poorly for some clients.

### Mechanism 2
- Claim: Transmitting only sparse gradients instead of full model weights reduces communication bandwidth while preserving convergence.
- Mechanism: After the initial mask is shared, each client computes gradients, masks them with the global mask, and sends only the non-zero entries in CSR format to the server for aggregation.
- Core assumption: Sparse gradient updates contain sufficient information for the server to compute effective global updates.
- Evidence anchors:
  - [abstract] "only highly sparse gradients are transmitted between the server and client models during the training process"
  - [section 4.2] "client models only share their sparse masked gradients gm = ∇θL(Dk) ⊙ mg to the server in the compressed sparse row (CSR) encoding"
  - [corpus] Weak - corpus neighbors discuss compression but not CSR-encoded sparse gradients specifically
- Break condition: If gradient sparsity is too high, the aggregated updates may become too sparse to capture necessary learning signals.

### Mechanism 3
- Claim: Starting from the same initialization and mask eliminates the need to share model weights during training.
- Mechanism: All clients begin with identical model parameters and apply the same mask, so they only need to exchange gradients, not weights.
- Core assumption: Parameter symmetry across clients means no weight synchronization is needed beyond the initial broadcast.
- Evidence anchors:
  - [section 4.2] "Since the server and all the client models start from the same initialization and have the same mask, we never need to share model weights during the training"
  - [section 4.1] "We consider a neural network f parametrized by θ ∈ Rd with the parameters at initialization θ0"
  - [corpus] Weak - related works focus on dynamic masks rather than static initialization
- Break condition: If clients diverge significantly during local training, weight synchronization may become necessary despite the shared initialization.

## Architecture Onboarding

- Component map:
  Server -> Clients (initialize model) -> Clients (compute saliency scores) -> Server (aggregate scores, create mask) -> Clients (apply mask) -> Training loop (compute masked gradients -> send sparse gradients -> aggregate -> broadcast updates)

- Critical path:
  1. Server initializes model and sends to all clients
  2. Each client computes saliency scores from local data
  3. Server aggregates scores and generates global mask
  4. Server broadcasts mask to all clients
  5. Training loop: clients compute masked gradients → send to server → server aggregates → sends back to clients

- Design tradeoffs:
  - Higher sparsity reduces communication but may hurt accuracy
  - Static mask vs dynamic masks: static is communication-efficient but less adaptive
  - CSR encoding reduces bandwidth but adds encoding/decoding overhead

- Failure signatures:
  - Accuracy drops significantly: mask may be too sparse or poorly chosen
  - Training instability: gradient aggregation may be insufficient due to high sparsity
  - Slow convergence: communication overhead may still be high despite sparsity

- First 3 experiments:
  1. Baseline FedAvg with full model communication on CIFAR-10
  2. SalientGrads with 90% sparsity on CIFAR-10, measure communication time and accuracy
  3. Vary sparsity levels (50%, 70%, 90%) to find accuracy-communication tradeoff point

## Limitations
- Limited evaluation scope: Experiments conducted only on CIFAR-10 with ResNet architectures
- Theoretical grounding: Limited theoretical analysis of why saliency-based subnetwork selection works
- Scalability concerns: Performance on larger-scale datasets or more complex models remains unverified

## Confidence
- High confidence: Communication efficiency improvements (1.27-2.32× speedup) - directly measured and validated against FedAvg baseline
- Medium confidence: Accuracy maintenance with 90% sparsity - demonstrated on CIFAR-10 but needs validation on diverse datasets
- Low confidence: Scalability to real-world federated learning scenarios - limited to controlled experiments with 5 clients
