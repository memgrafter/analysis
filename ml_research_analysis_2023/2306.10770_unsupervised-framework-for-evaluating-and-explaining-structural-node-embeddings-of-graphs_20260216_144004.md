# Unsupervised Framework for Evaluating and Explaining Structural Node Embeddings of Graphs

## Quick Facts
- arXiv ID: 2306.10770
- Source URL: https://arxiv.org/abs/2306.10770
- Reference count: 36
- Key outcome: Introduces an unsupervised framework that evaluates structural node embeddings by measuring feature preservation and identifies important embedding dimensions, showing classical embeddings like Node2Vec struggle with structural properties while structural embeddings perform better.

## Executive Summary
This paper presents an unsupervised framework for evaluating and explaining structural node embeddings in graphs. The core idea is to measure how well embedding algorithms preserve predefined node features by clustering nodes in feature space and comparing distances to the embedded space. The framework outputs a quality score ψ (0=good, 1=bad) and identifies which embedding dimensions are important for feature preservation. Experiments on synthetic and real-world networks demonstrate that classical embeddings like Node2Vec and DeepWalk struggle to capture structural properties, while structural embeddings like LSME, Struc2Vec, and RolX perform better.

## Method Summary
The framework clusters nodes in feature space using k-means, samples node pairs with probability proportional to intra-cluster pair counts, computes distances in both feature and embedded spaces, and measures correlation between these distances. The quality score ψ is defined as 1 - r² where r is the Pearson correlation coefficient. An optimization step identifies important embedding dimensions by finding weights that minimize ψ. The framework evaluates how well structural properties are preserved in the embedding space without requiring labeled data.

## Key Results
- Classical embeddings (Node2Vec, DeepWalk) show higher ψ scores indicating poor preservation of structural features compared to structural embeddings
- The framework successfully identifies which embedding dimensions carry information about specific node features through the weight vector w
- Results correlate well with supervised role classification tasks, validating the framework's effectiveness
- Structural embeddings (LSME, Struc2Vec, RolX) demonstrate superior performance in preserving structural properties

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The framework's core insight is that structural embeddings should be evaluated by their ability to preserve classical node features in the embedding space.
- Mechanism: The algorithm clusters nodes in the feature space, computes distances between sampled pairs within and across clusters, then measures correlation between these feature-space distances and distances in the embedding space. Low correlation (high ψ) indicates poor preservation of structural features.
- Core assumption: If an embedding algorithm captures structural properties well, it should preserve distances between nodes in the feature space when mapping to the embedding space.
- Evidence anchors:
  - [abstract] "The framework outputs a quality score ψ (0=good, 1=bad) and identifies which embedding dimensions are important for feature preservation."
  - [section 3.2] "The framework outputs a quantitative metric ψ, which measures how well an embedding algorithm has learned a given feature (or a collection of features)."
  - [corpus] Weak evidence for this specific mechanism in related papers; they focus on different evaluation approaches.
- Break condition: If structural features are not the primary signal for the downstream task, or if the clustering in feature space poorly represents the true structure, the metric becomes misleading.

### Mechanism 2
- Claim: The optimization step identifies which embedding dimensions carry the information relevant to each feature, enabling interpretability.
- Mechanism: A weight vector w is optimized to minimize ψ, where w scales each embedding dimension in the distance calculation. Dimensions with near-zero weights after optimization are deemed unimportant for that feature.
- Core assumption: Structural features are represented linearly or can be approximated linearly in the embedding space, so weighted Euclidean distance is a meaningful similarity measure.
- Evidence anchors:
  - [abstract] "The framework outputs a quality score ψ (0=good, 1=bad) and identifies which embedding dimensions are important for feature preservation."
  - [section 3.2] "Optimize vector w to minimize ψ, where the final value of ψ is referred to as the post-optimization ψ. These optimized vectors reflect the importance of embedded dimensions for selected features."
  - [corpus] Related papers mention interpretability but not this specific weighted dimension analysis.
- Break condition: If the relationship between features and embedding dimensions is highly nonlinear, the linear weighting may miss important structure.

### Mechanism 3
- Claim: Sampling strategy balances computational efficiency with evaluation quality by focusing on pairs likely to be close in feature space.
- Mechanism: Pairs are sampled with probability proportional to intra-cluster pair counts, ensuring that p fraction of sampled pairs are from the same cluster. This makes the correlation metric sensitive to preservation of local structure.
- Core assumption: Local structure in the feature space is more informative for evaluating structural embeddings than global distances.
- Evidence anchors:
  - [section 3.2] "sample m = min{⌊p·c/k⌋, Σ_{1≤a≤s} (ca choose 2)} unique pairs of nodes within clusters"
  - [section 3.3] "Achieving a good ψ score ensures that close pairs of nodes in the feature space are close in the embedded space. On the other hand, if some pairs of nodes are far in the feature space, then the framework puts less weight on the fact whether they are close or not in the embedded space."
  - [corpus] No direct evidence; this appears to be a novel design choice.
- Break condition: If the feature-space clusters are poorly formed or if global structure matters more than local for the task, this sampling bias reduces evaluation quality.

## Foundational Learning

- Concept: k-means clustering for grouping nodes by structural features
  - Why needed here: The framework clusters nodes in feature space to identify which nodes should be close in the embedding space if structural properties are preserved.
  - Quick check question: If you have a set of node features (degree, clustering coefficient, etc.), how would you determine which nodes are structurally similar before applying an embedding algorithm?

- Concept: Pearson correlation as a measure of linear relationship
  - Why needed here: The framework uses 1 - r² (where r is Pearson correlation) as the quality metric ψ, so understanding correlation is essential to interpret results.
  - Quick check question: If two sets of distances have a Pearson correlation of 0.8, what would the ψ value be, and what does that indicate about the embedding's quality?

- Concept: Distance metrics in high-dimensional spaces
  - Why needed here: The framework computes Euclidean distances in both feature and embedding spaces, so understanding how distance behaves in high dimensions is important for interpreting results.
  - Quick check question: In high-dimensional spaces, what happens to the ratio of nearest to farthest neighbor distances, and how might this affect the framework's distance-based evaluation?

## Architecture Onboarding

- Component map:
  Input layer (node features and embeddings) -> Standardization -> k-means clustering -> Pair sampling -> Distance computation (feature and embedding spaces) -> Correlation calculation -> Optimization -> Output (ψ score and weight vector w)

- Critical path:
  1. Feature and embedding standardization
  2. k-means clustering of feature vectors
  3. Sampling pairs of nodes
  4. Computing distances in both spaces
  5. Calculating correlation and ψ
  6. Optimizing weights to minimize ψ
  Any failure in preprocessing or sampling propagates through the entire pipeline.

- Design tradeoffs:
  - Fixed vs. adaptive number of clusters (s): Fixed (default √n) ensures stability but may not capture optimal structure
  - Pair sampling ratio (p): Balances focus on local vs. global structure preservation
  - Distance metric: Euclidean is simple but may miss nonlinear relationships
  - Standardization method: MinMax preserves relative scales, StandardScaler normalizes variance

- Failure signatures:
  - ψ ≈ 1 for all features: Embedding fails to preserve any structural information
  - ψ ≈ 0 for all features: Embedding perfectly preserves all selected features (unlikely in practice)
  - Highly uneven weight vector w: One or few dimensions dominate, suggesting embedding redundancy
  - Instability across runs: Indicates sensitivity to random initialization or sampling

- First 3 experiments:
  1. Run framework on a synthetic graph with known structure using both a structural embedding (LSME) and a classical embedding (Node2Vec). Verify that structural embeddings show lower ψ for structural features while classical embeddings show higher ψ.
  2. Vary the number of clusters s from √n/2 to 2√n and observe how ψ changes. Identify the stability region and verify default value is reasonable.
  3. Test different standardization methods (MinMax vs StandardScaler) on the same embedding and features. Confirm that results are invariant as claimed in section 3.3.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can the proposed framework be extended to handle dynamic graphs where node features and embeddings evolve over time?
- Basis in paper: [inferred] The paper focuses on static graphs and does not address the challenges of analyzing embeddings in dynamic networks.
- Why unresolved: Dynamic graphs introduce additional complexity in tracking feature preservation across time, requiring methods to handle temporal changes and concept drift.
- What evidence would resolve it: A modified version of the framework that can process graph snapshots over time and measure feature preservation in temporal embeddings.

### Open Question 2
- Question: What is the optimal number and selection of node features to use as reference points for evaluating structural embeddings across different graph types?
- Basis in paper: [explicit] The paper acknowledges that the set of reference features is modifiable but does not provide guidelines for feature selection.
- Why unresolved: Different graph types may require different feature sets, and selecting too few or too many features could impact evaluation accuracy.
- What evidence would resolve it: Systematic studies comparing framework performance across different feature sets and graph types to identify optimal selection criteria.

### Open Question 3
- Question: How does the framework perform when evaluating embeddings that capture higher-order structural properties beyond immediate neighbors?
- Basis in paper: [inferred] The paper focuses on basic node features and does not explore evaluation of embeddings capturing more complex structural patterns.
- Why unresolved: The framework's effectiveness for higher-order structural features is unknown, which could limit its applicability for certain embedding algorithms.
- What evidence would resolve it: Experiments testing the framework's ability to evaluate embeddings that capture community structures, motifs, or other higher-order patterns.

## Limitations

- The framework assumes linear relationships between features and embedding dimensions, which may not capture complex nonlinear structures in some embeddings
- k-means clustering on feature space may not accurately capture true structural neighborhoods, especially in graphs with overlapping or hierarchical roles
- The evaluation is limited to pre-defined node features and may miss emergent structural patterns that embeddings capture but aren't explicitly measured

## Confidence

- **High confidence**: The framework provides a quantitative metric ψ for evaluating structural embedding quality and identifies important embedding dimensions through optimization
- **Medium confidence**: Structural embeddings (LSME, Struc2Vec, RolX) outperform classical embeddings on structural feature preservation tasks
- **Medium confidence**: The framework's correlation-based evaluation captures meaningful relationships between feature space and embedding space distances

## Next Checks

1. **Nonlinear relationship test**: Apply the framework to embeddings known to have nonlinear structure (e.g., deep graph neural networks) and compare results with a kernelized distance metric to assess linear approximation limitations.

2. **Cluster stability analysis**: Run the framework multiple times with different random seeds for k-means initialization on the same data and measure variance in ψ scores to quantify sensitivity to clustering instability.

3. **Feature coverage evaluation**: Design an experiment where embeddings are trained to capture specific structural patterns not included in the evaluation features, then verify whether the framework detects this preservation despite missing features.
