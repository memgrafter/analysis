# PyBADS: Fast and robust black-box optimization in Python

## Quick Facts
- **arXiv ID**: 2306.15576
- **Source URL**: https://arxiv.org/abs/2306.15576
- **Reference count**: 10
- **Primary result**: Provides fast and robust Python implementation of BADS algorithm for black-box optimization

## Executive Summary
PyBADS is a Python package implementing the Bayesian Adaptive Direct Search (BADS) algorithm for black-box optimization. The algorithm addresses optimization problems with expensive, non-convex, possibly noisy objective functions without gradient information. It combines Bayesian Optimization search stages with Mesh Adaptive Direct Search poll stages, providing a fail-safe mechanism when the Gaussian process surrogate model fails. The algorithm efficiently handles problems with up to 20 continuous parameters and supports bounded variables. Benchmarks show PyBADS performs on par with or better than many state-of-the-art optimizers, typically requiring only a few hundred function evaluations. The package features a user-friendly Pythonic interface, sensible defaults, and requires only a Python function for the target evaluation.

## Method Summary
PyBADS implements the Bayesian Adaptive Direct Search (BADS) algorithm, which alternates between Bayesian Optimization search stages and Mesh Adaptive Direct Search poll stages. The search stage uses a Gaussian process surrogate model to intelligently explore promising regions, while the poll stage provides systematic local exploration as a fallback mechanism. This hybrid approach achieves both sample efficiency and computational efficiency, making it suitable for functions that take 0.1+ seconds per evaluation. The algorithm uses a lower confidence bound acquisition strategy to balance exploration and exploitation, and handles bounded or unbounded continuous parameters with up to approximately 20 dimensions.

## Key Results
- Performs on par with or better than many state-of-the-art optimizers
- Typically requires only a few hundred function evaluations
- Efficiently handles problems with up to ~20 continuous parameters
- Features user-friendly Pythonic interface with sensible defaults

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The alternating search-poll strategy provides fail-safe robustness against GP surrogate model failures.
- Mechanism: When the Bayesian Optimization search stage fails to improve over current point, the algorithm automatically falls back to the more conservative Mesh Adaptive Direct Search (MADS) poll stage. The poll stage systematically evaluates points on a mesh in the neighborhood, guaranteeing progress even when the GP model is inaccurate.
- Core assumption: The GP surrogate model will occasionally fail to accurately represent the true objective function in some regions, necessitating a fallback mechanism.
- Evidence anchors:
  - [abstract]: "combines Bayesian Optimization search stages with Mesh Adaptive Direct Search poll stages, providing a fail-safe mechanism when the Gaussian process surrogate model fails"
  - [section]: "This alternation between the two stages makes BADS uniquely robust and effective... Notably, this strategy is fail-safe in that if the GP fails to locally model the target, the search will fail and PyBADS will fall back to the safer poll method"
  - [corpus]: Weak evidence - corpus focuses on other BO approaches without similar fail-safe mechanisms
- Break condition: If the poll stage also fails to find improvements consistently, the algorithm may stall or converge to suboptimal solutions.

### Mechanism 2
- Claim: The hybrid approach achieves both sample efficiency and computational efficiency.
- Mechanism: Bayesian Optimization provides intelligent exploration using GP surrogate models to suggest promising regions with few function evaluations, while MADS provides systematic local exploration. This combination allows the algorithm to find good solutions with typically only "a few hundred" function evaluations, making it suitable for functions that take 0.1+ seconds per evaluation.
- Core assumption: The target functions are expensive enough (moderate evaluation cost) that the optimization overhead is justified, but not so expensive that even a few hundred evaluations is prohibitive.
- Evidence anchors:
  - [abstract]: "typically requiring only a few hundred function evaluations"
  - [section]: "PyBADS is both fast in terms of wall-clock time and sample-efficient in terms of the number of target evaluations (typically of the order of a few hundred)"
  - [corpus]: Weak evidence - corpus papers focus on different optimization regimes without addressing this specific efficiency tradeoff
- Break condition: For extremely expensive functions (evaluation cost >> 1 hour), even hundreds of evaluations may be prohibitive, and traditional BO methods might be preferred.

### Mechanism 3
- Claim: The lower confidence bound (LCB) acquisition strategy effectively balances exploration and exploitation.
- Mechanism: During the search stage, new points are chosen based on an LCB strategy that considers both the GP mean (exploitation of promising regions) and GP uncertainty (exploration of uncertain regions). This allows the algorithm to intelligently navigate the search space without requiring extensive tuning.
- Core assumption: The GP surrogate model can provide reasonable uncertainty estimates that guide the exploration-exploitation tradeoff.
- Evidence anchors:
  - [section]: "New points to evaluate are quickly chosen according to a lower confidence bound strategy that trades off between exploration of uncertain regions (high GP uncertainty) and exploitation of promising solutions (low GP mean)"
  - [abstract]: "New points to evaluate are quickly chosen according to a lower confidence bound strategy"
  - [corpus]: Weak evidence - corpus papers discuss different acquisition functions without addressing LCB specifically
- Break condition: If the GP uncertainty estimates are poorly calibrated or the function landscape is highly multimodal, the LCB strategy may get trapped in local optima or explore inefficiently.

## Architecture Onboarding

- Component map: Search stage -> GP surrogate modeling + LCB acquisition function -> Poll stage -> MADS mesh exploration with adaptive step sizing -> Controller -> Alternates between stages based on success/failure criteria -> User interface -> Pythonic API accepting objective function and bounds -> Evaluation manager -> Handles function evaluation tracking and caching

- Critical path: User provides objective function -> PyBADS initializes GP model -> Search stage proposes points -> Evaluate -> If search fails, switch to poll stage -> Continue until termination

- Design tradeoffs: 
  - GP complexity vs. evaluation speed (moderate complexity chosen for 0.1+ second functions)
  - Exploration aggressiveness vs. local convergence speed
  - Memory usage for storing evaluated points vs. computational efficiency

- Failure signatures:
  - GP model consistently fails to improve predictions (search stage stalls)
  - Poll stage step size becomes very small without finding improvements
  - Objective function evaluations fail or return NaN/Inf values
  - User-specified bounds may be too restrictive for the global optimum

- First 3 experiments:
  1. Rosenbrock function (2D) - test basic functionality and visualize search-poll alternation
  2. Noisy quadratic function - verify robustness to stochastic evaluations
  3. 10D bounded optimization problem - test scalability and constraint handling

- Basis in paper: [inferred] The paper focuses on "up to D ≈ 20 continuous input parameters" and mentions "bounded variables" but does not explicitly discuss handling of discrete variables.

- Why unresolved: The paper mentions heuristics for handling noise but does not provide formal convergence guarantees or bounds on convergence rates for noisy functions.
- What evidence would resolve it: Mathematical proof of convergence properties, or extensive empirical validation showing convergence behavior across varying noise levels and problem types.

- Why unresolved: The benchmarks focus on model-fitting problems from neuroscience and cognitive science, but do not systematically compare against specialized algorithms for other domains like deep learning or engineering design.

## Limitations
- Scalability limited to approximately 20 continuous parameters due to GP surrogate model complexity
- Performance heavily dependent on GP surrogate model quality, which may struggle with highly multimodal or discontinuous functions
- Excessive reliance on poll stage indicates fundamental issues with GP modeling that may require manual intervention

## Confidence
