# r-softmax: Generalized Softmax with Controllable Sparsity Rate

## Quick Facts
- arXiv ID: 2304.05243
- Source URL: https://arxiv.org/abs/2304.05243
- Authors: 
- Reference count: 21
- Primary result: Introduces r-softmax, a generalized softmax with controllable sparsity rate that outperforms sparse alternatives in multi-label classification and improves transformer attention when fine-tuned on NLP tasks.

## Executive Summary
This paper introduces r-softmax, a generalization of the standard softmax function that outputs sparse probability distributions with controllable sparsity rate. The key innovation is parameterizing the softmax weights using a sparsity rate parameter r, which determines the fraction of zero components in the output. This allows for more intuitive and interpretable representations compared to standard softmax, particularly in multi-label classification where it eliminates the need for manual threshold selection. The paper demonstrates that r-softmax outperforms other sparse alternatives while being competitive with the original softmax on multi-label classification tasks, and shows improved performance when replacing softmax in transformer self-attention modules.

## Method Summary
The r-softmax function generalizes the standard softmax by introducing a sparsity rate parameter r that controls the fraction of zero components in the output distribution. The method computes a threshold t using the quantile function of the input logits, zeroing out components below this threshold while maintaining the remaining probabilities. For multi-label classification, a custom loss function accounts for the sparse outputs, and the sparsity rate can be either fixed or learned during training. The approach is evaluated on synthetic datasets, image classification (VOC 2007, COCO), and NLP tasks (GLUE benchmark) using two-layer neural networks, ResNet architectures, and pre-trained BERT models respectively.

## Key Results
- Outperforms sparsemax and other sparse alternatives on multi-label classification while maintaining competitive performance with standard softmax
- Eliminates need for manual threshold selection in multi-label classification by learning sparsity rate during training
- Improves transformer attention performance when fine-tuned on GLUE benchmark tasks (MRPC, RTE, SST-2, QNLI, QQP)
- Produces sparse probability distributions that are more interpretable than dense softmax outputs

## Why This Works (Mechanism)

### Mechanism 1
- Claim: r-softmax enables controllable sparsity by parameterizing softmax weights using a sparsity rate r, which determines the fraction of zero components in the output.
- Mechanism: The sparsity rate r is implemented by adjusting the threshold t in t-softmax. The parameter t is computed as t_r = -quantile(x, r) + max(x), where quantile(x, r) returns the value such that the probability of {x_i : x_i ≤ v} equals r. This ensures that a fraction r of the components are zeroed out.
- Core assumption: The quantile function can be computed efficiently and provides a meaningful threshold for controlling sparsity.
- Evidence anchors:
  - [abstract] "The key idea is to parameterize the softmax weights using a sparsity rate parameter r, which determines the fraction of zero components in the output."
  - [section] "To have the control of the number of non-zero weights, we may inspect the range [min_i(x), max_i(x)] and take t satisfying x_i < t < x_j to zero out i-th component but keep the j-th component non-zero. This rule can be realized using the quantile of the set of x's coordinates {x_1, ..., x_n} (understood as a set of values)."
- Break condition: If the quantile function is computationally expensive or inaccurate, the sparsity control mechanism may fail.

### Mechanism 2
- Claim: r-softmax improves model interpretability and eliminates the need for manual threshold selection in multi-label classification.
- Mechanism: By producing zero probabilities for irrelevant classes, r-softmax allows the model to clearly indicate negative classes without requiring a manual threshold. The sparsity rate r can be learned during training, eliminating the need for hyperparameter tuning.
- Core assumption: Zero probabilities in r-softmax are meaningful indicators of negative classes, and the model can learn an appropriate sparsity rate during training.
- Evidence anchors:
  - [abstract] "This allows for more intuitive and interpretable representations compared to standard softmax."
  - [section] "Since the softmax function does not return zero probabilities, we cannot easily say what probability should be converted to a positive label and which should not. In consequence, we arrive at a problem of manually introducing a threshold below which the label is considered negative."
- Break condition: If the model fails to learn an appropriate sparsity rate, or if zero probabilities are not meaningful indicators of negative classes, the interpretability benefits may not be realized.

### Mechanism 3
- Claim: r-softmax improves transformer attention by allowing the model to ignore irrelevant tokens.
- Mechanism: By replacing softmax with r-softmax in the self-attention module, the model can assign zero probability to irrelevant tokens, reducing computational overhead and potentially improving performance on downstream NLP tasks.
- Core assumption: The self-attention module benefits from ignoring irrelevant tokens, and the sparsity rate can be effectively learned during fine-tuning.
- Evidence anchors:
  - [abstract] "Additionally, replacing softmax with r-softmax in the self-attention module of a pre-trained transformer language model leads to improved performance when fine-tuning on various NLP tasks."
  - [section] "By applying softmax, we force the model to consider all components as relevant, which usually is not the case. The attention module should be able to ignore unnecessary information by assigning zero probability to selected components."
- Break condition: If the self-attention module does not benefit from sparsity, or if the sparsity rate cannot be effectively learned during fine-tuning, the performance improvements may not be realized.

## Architecture Onboarding

- Component map:
  Input logits -> r-softmax function (with sparsity rate r) -> Sparse probability distribution -> Custom loss function -> Backpropagation (updates model parameters and r)

- Critical path:
  1. Compute raw logits from the neural network
  2. Apply r-softmax to the logits using a specified sparsity rate r
  3. Compute the custom loss function, taking into account the sparse output
  4. Backpropagate the loss and update the model parameters, including the sparsity rate r

- Design tradeoffs:
  - Controllable sparsity vs. computational complexity: The r-softmax function introduces additional computational overhead due to the quantile function used to compute the threshold t.
  - Interpretability vs. performance: While r-softmax offers improved interpretability through sparse outputs, it may not always outperform the original softmax function in terms of raw performance.
  - Sparsity rate selection: Choosing an appropriate sparsity rate r is crucial for the success of r-softmax. This can be done manually or learned during training, each with its own trade-offs.

- Failure signatures:
  - If the sparsity rate r is set too high, the model may produce overly sparse outputs, leading to poor performance.
  - If the quantile function is not implemented correctly or is computationally expensive, the r-softmax function may not work as intended.
  - If the custom loss function is not properly designed to handle zero probabilities, the training process may fail or converge to suboptimal solutions.
