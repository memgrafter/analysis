# AdaTT: Adaptive Task-to-Task Fusion Network for Multitask Learning in Recommendations

## Quick Facts
- **arXiv ID**: 2304.04959
- **Source URL**: https://arxiv.org/abs/2304.04959
- **Reference count**: 37
- **Key outcome**: AdaTT achieves up to 0.845% improvement in Normalized Entropy (NE) for classification tasks compared to shared-bottom models

## Executive Summary
AdaTT introduces a multi-level fusion network that explicitly models task-to-task interactions for multitask learning in recommendation systems. The architecture uses task-specific and optional shared fusion units with residual and gating mechanisms to adaptively learn shared and task-specific knowledge across varying task relationships. Experiments on a large-scale short video recommendation system and public datasets demonstrate consistent improvements over state-of-the-art MTL baselines.

## Method Summary
AdaTT employs a multi-level fusion network where each task has dedicated experts that are combined through task-specific fusion units (using native experts with linear fusion) and optional shared fusion units (using gating over all tasks' experts). The architecture uses residual connections to preserve task-specific knowledge while enabling adaptive sharing through input-dependent gating. Multiple fusion levels allow progressive refinement of task relationships at different abstraction levels.

## Key Results
- Up to 0.845% improvement in Normalized Entropy (NE) for classification tasks on industrial dataset
- Consistent gains across diverse task groups including classification and regression tasks
- Ablation studies confirm importance of separate fusion modules for task-specific and shared learning

## Why This Works (Mechanism)

### Mechanism 1
- Claim: AdaTT's residual and gating mechanisms enable dynamic task-to-task knowledge sharing that adapts to varying task relationships
- Mechanism: Gating modules compute task-specific weights over all experts from other tasks, allowing flexible fusion based on input context. Residual design adds native expert contributions to gated fusion output, preserving task-specific knowledge while enabling adaptive sharing
- Core assumption: Task relationships vary across examples, requiring input-dependent gating rather than static weight sharing
- Evidence anchors: [abstract] "By leveraging a residual mechanism and a gating mechanism for task-to-task fusion, these units adaptively learn shared knowledge and task specific knowledge."

### Mechanism 2
- Claim: Separate fusion modules for task-specific and shared learning prevent negative transfer while maintaining cross-task regularization benefits
- Mechanism: AdaTT uses distinct fusion units with different expert sets and fusion strategies. Task-specific units combine native experts with lightweight linear fusion, while shared units use gating over all tasks' experts
- Core assumption: Task-specific and shared learning benefit from different optimization dynamics and expert compositions
- Evidence anchors: [abstract] "For synergistic task specific learning and shared learning, we distinguish and model the two in separate fusion modules, with different experts and fusion strategy applied in each."

### Mechanism 3
- Claim: Multi-level fusion architecture enables learning at different abstraction levels, improving both shallow pattern matching and deep semantic understanding
- Mechanism: AdaTT stacks multiple fusion levels, where each level takes outputs from the previous level as input. Lower levels capture immediate task correlations while higher levels develop more abstract shared representations
- Core assumption: Task relationships manifest at different levels of abstraction, and single-level fusion cannot capture the full spectrum of dependencies
- Evidence anchors: [abstract] "Furthermore, we employ multiple levels of fusion, each specialized for different functionality, to enhance learning performance."

## Architecture Onboarding

- **Component map**: Input layer → Fusion network (multiple levels) → Task towers → Outputs
- **Critical path**: Input → First fusion level experts → Gating weights computation → Expert fusion → Residual addition → Next fusion level → Final task-specific fusion → Task tower → Output prediction
- **Design tradeoffs**: More experts per task increase model capacity but also computational cost and overfitting risk; more fusion levels improve abstraction capability but may cause gradient vanishing or overfitting
- **Failure signatures**: Performance plateaus or degrades with additional fusion levels (indicates overfitting or gradient issues); one task dominates training loss while others stagnate (suggests task imbalance or gating failure)
- **First 3 experiments**: 1) Train with single fusion level and one expert per task to establish baseline performance, 2) Add second fusion level while keeping one expert per task to test deeper architecture benefits, 3) Increase experts per task from 1 to 2 while maintaining single fusion level to evaluate impact of increased capacity

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does AdaTT perform in scenarios with more than 5 tasks or with tasks having significantly different scales?
- Basis in paper: [inferred] The paper evaluates AdaTT on up to 5 tasks and does not explore extreme imbalances in task scales or larger task sets
- Why unresolved: Experiments focus on limited number of tasks (1-5) and balanced datasets
- What evidence would resolve it: Empirical results on datasets with 10+ tasks or highly imbalanced task sample sizes

### Open Question 2
- Question: How sensitive is AdaTT's performance to the choice of expert module architecture (e.g., MLPs vs. transformers)?
- Basis in paper: [explicit] The paper states AdaTT is "generic" and supports "flexible choices of expert modules" but does not explore architectural variations
- Why unresolved: Experiments use fixed expert architecture
- What evidence would resolve it: Comparative studies replacing MLP experts with transformers while keeping other components fixed

### Open Question 3
- Question: Can the task-to-task fusion mechanism in AdaTT be extended to handle dynamic task relationships that evolve over time?
- Basis in paper: [inferred] AdaTT uses static gating mechanisms conditioned on inputs but does not address temporal dynamics
- Why unresolved: Paper focuses on static datasets and does not explore online or streaming scenarios
- What evidence would resolve it: Experiments applying AdaTT in online learning framework with tasks whose relationships change over time

## Limitations

- Key architectural details like the gating mechanism function g^l_t are not fully specified, making exact reproduction difficult
- Hyperparameter tuning process for optimal numbers of experts and fusion levels is not provided
- Multi-level fusion benefits lack theoretical grounding and comparison to alternative hierarchical approaches

## Confidence

- **High**: The core architectural design of task-specific and shared fusion units with residual connections is well-specified and empirical results show consistent improvements
- **Medium**: The theoretical motivation for separating task-specific and shared learning is compelling but requires further validation
- **Low**: The multi-level fusion benefits are supported by ablation studies but lack theoretical grounding
