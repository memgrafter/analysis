# Graph Exploration Matters: Improving both individual-level and system-level diversity in WeChat Feed Recommender

## Quick Facts
- arXiv ID: 2306.00009
- Source URL: https://arxiv.org/abs/2306.00009
- Reference count: 40
- One-line primary result: Significantly improves individual-level diversity (IDL +2.003), system-level diversity (RD +4.678), user engagement (VV +2.397), and commercial revenue (AD +1.143) in WeChat Top Stories.

## Executive Summary
This paper tackles the challenge of simultaneously improving both individual-level and system-level diversity in large-scale feed recommender systems. The authors propose a framework that leverages graph-based retrieval and reranking using Determinantal Point Process (DPP) with real-time personalized diversity propensity. The key innovation is reusing graph embeddings across multiple stages and capturing user's changing diversity preference over time. Offline simulations and online A/B tests show the proposed method significantly outperforms baselines across multiple metrics.

## Method Summary
The proposed method combines graph-based retrieval using GraphSage embeddings, real-time personalized DPP reranking with dynamic diversity propensity tracking, and graph exploration updates. Graph embeddings are generated once during retrieval and reused in reranking to compute item similarity and personalize DPP diversity weighting. User's recent interaction similarity is computed from graph embeddings within a sliding time window to generate a personalized diversity factor that adjusts the DPP trade-off. After reranking, positive interactions in the same session create new edges in the item-item graph, which are merged to improve future retrieval diversity.

## Key Results
- Individual-level diversity (IDL) improved by 2.003 percentage points
- System-level diversity (RD) improved by 4.678 percentage points
- User engagement (VV) increased by 2.397 percentage points
- Commercial revenue (AD) increased by 1.143 percentage points

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Reusing graph embeddings across retrieval and reranking stages improves both individual-level and system-level diversity without retraining.
- Mechanism: Graph embeddings are generated once during retrieval using GraphSage on the user-item interaction graph, then reused in reranking to compute item similarity and personalize DPP diversity weighting. This avoids retraining separate semantic embeddings and captures interaction-based similarity.
- Core assumption: Graph embeddings learned from interaction patterns contain sufficient information to reflect both semantic similarity and behavioral diversity.
- Evidence anchors:
  - [abstract] "The key innovation is reusing graph embeddings across multiple stages..."
  - [section] "The graph embeddings are online trained... reused in different phases... doesn't rely on extra pre-trained embeddings..."
  - [corpus] Weak - no corpus papers explicitly discuss embedding reuse across stages.
- Break condition: If the graph becomes too sparse or dominated by heavy users, embedding quality degrades, reducing diversity gains.

### Mechanism 2
- Claim: Real-time personalization of DPP diversity weight using temporal user behavior improves individual-level diversity.
- Mechanism: User's recent interaction similarity is computed from graph embeddings within a sliding time window, standardized with z-score, and passed through a sigmoid to generate a personalized diversity factor f^u_t. This factor adjusts the DPP trade-off between relevance and diversity for each user in real time.
- Core assumption: Users' diversity preferences shift over time and can be captured by recent interaction patterns.
- Evidence anchors:
  - [abstract] "we also propose to capture the user's real-time personalized propensity to the diversity."
  - [section] "We observe that users' preference for diversity changes over time... propose a function to quantify user's real-time propensity..."
  - [corpus] Weak - no corpus papers discuss temporal personalization of diversity propensity.
- Break condition: If user behavior is too sparse or erratic, the sliding window similarity measure becomes unstable, leading to noisy personalization.

### Mechanism 3
- Claim: Graph exploration through edge updates after reranking improves system-level diversity over time.
- Mechanism: After reranking, positive interactions in the same session create new edges in the item-item graph. These new edges enrich future retrieval diversity by expanding the neighborhood of items available for matching, thus breaking popularity bias.
- Core assumption: User interactions in the reranked feed meaningfully reveal new item-item relationships that improve retrieval coverage.
- Evidence anchors:
  - [abstract] "The selected sub-graph... is then formed as a feed for users to explore edges between diversified items... merged to the huge graph to improve the system-level diversity."
  - [section] "Those graph exploration are then merged in the huge item-item graph to increase the system-level diversity."
  - [corpus] Weak - no corpus papers explicitly discuss post-reranking graph updates for diversity.
- Break condition: If graph updates are too slow or sparse, system-level diversity improvements plateau quickly.

## Foundational Learning

- Concept: Determinantal Point Process (DPP) for diversity-aware ranking
  - Why needed here: DPP provides a principled probabilistic framework to select diverse item subsets by modeling negative correlations between items via a kernel matrix combining similarity and relevance.
  - Quick check question: What does a higher determinant of the DPP kernel matrix indicate about the selected item set?

- Concept: Graph neural networks for inductive representation learning
  - Why needed here: GraphSage enables efficient, scalable embeddings for both seen and unseen items based on their local neighborhood structure, allowing the system to match items even if they lack explicit interaction history.
  - Quick check question: How does GraphSage's aggregation function update a node's embedding from its neighbors?

- Concept: Temporal sliding window for behavior analysis
  - Why needed here: Captures recent user interaction patterns to reflect current diversity preferences, accommodating shifts in interest over time.
  - Quick check question: What effect does increasing the sliding window size have on the stability and responsiveness of the diversity factor?

## Architecture Onboarding

- Component map:
  - GraphSage embedding trainer (offline/online) -> User behavior history store (sliding window) -> Retrieval matcher (cosine similarity on embeddings) -> Ranking model (relevance scores) -> DPP reranker (kernel matrix + personalized diversity factor) -> Graph update engine (add edges from reranked interactions)
- Critical path: User request → Graph embeddings → Retrieval → Ranking → DPP reranking → Exposure → Interaction logging → Graph update → Next request
- Design tradeoffs:
  - Reuse embeddings to save compute vs. training separate semantic embeddings for higher accuracy
  - Temporal sliding window length vs. responsiveness to user preference shifts
  - DPP kernel trade-off tuning vs. simplicity of fixed diversity weight
- Failure signatures:
  - Diversity gains stagnate → Graph too sparse or dominated by heavy users
  - Personalization noise → Too short sliding window or sparse behavior
  - Slow diversity improvement → Graph update frequency too low
- First 3 experiments:
  1. Compare retrieval diversity with and without graph embedding reuse
  2. Test personalization impact by disabling the temporal diversity factor
  3. Measure system-level diversity growth over time with and without graph edge updates

## Limitations

- The exact mechanism for constructing the item-item graph is underspecified, relying only on "positively interacted in one user's behavior session" without detailing edge weighting or filtering criteria.
- Key hyperparameters (DPP trade-off θ, GraphSage dimensions, sliding window size) are not reported, making faithful reproduction difficult.
- No quantitative comparison of retrieval diversity with and without graph embedding reuse, weakening evidence for Mechanism 1.

## Confidence

- **High**: The overall framework combining graph retrieval, DPP reranking, and graph updates is technically sound and well-motivated.
- **Medium**: The claims about real-time personalization of diversity propensity (Mechanism 2) are plausible but lack ablation studies isolating their effect.
- **Low**: The evidence for system-level diversity improvement via graph exploration (Mechanism 3) is weak, with no explicit comparison of diversity growth over time with/without graph updates.
