# GVdoc: Graph-based Visual Document Classification

## Quick Facts
- arXiv ID: 2305.17219
- Source URL: https://arxiv.org/abs/2305.17219
- Reference count: 20
- Outperforms SOTA on OOD visual document classification

## Executive Summary
This paper introduces GVdoc, a graph-based visual document classification model that addresses the challenge of robust performance on out-of-distribution (OOD) data. Existing methods struggle with OOD examples due to token serialization problems and high computational requirements. GVdoc generates a document graph using layout information and learns node and graph embeddings through a graph neural network (GNN). The model demonstrates superior performance on OOD data while maintaining comparable accuracy on in-distribution test sets.

## Method Summary
GVdoc constructs document graphs using a combination of β-skeleton and paragraph-level edges, then learns node and graph embeddings through a Graph Attention Network (GAT). The model incorporates cross-attention fusion of text and layout embeddings to improve robustness to OCR errors. Pre-training involves masked language modeling, masked paragraph modeling, and contrastive paragraph prediction tasks. The model is fine-tuned on the RVLCDIP dataset and evaluated on both in-distribution and OOD datasets.

## Key Results
- Achieves higher accuracy on RN (OOD but in-domain) compared to other models
- Demonstrates better area under the ROC curve (AUC) scores on OOD data
- Shows lower false positive rates and higher energy-based AUC scores, indicating effective differentiation between in-distribution and out-of-distribution data

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Graph construction with β-skeleton + OCR-based paragraph edges captures layout sparsity while preserving reading order context
- Mechanism: β-skeleton edges encode spatial proximity; paragraph-level edges encode sequential reading order. The union yields a sparse but context-rich graph
- Core assumption: OCR reading order errors are localized and can be compensated by spatial β-skeleton edges
- Evidence anchors:
  - [abstract] "generates a document graph based on its layout"
  - [section 3] "we take the union of the edges from the β-skeleton graph and the paragraph-based neighborhood"
  - [corpus] "Enhancing Document AI Data Generation Through Graph-Based Synthetic Layouts" — weak signal, no explicit discussion of edge types
- Break condition: If OCR is highly unreliable, spatial edges alone may dominate, potentially losing sequential semantics

### Mechanism 2
- Claim: Cross-attention fusion of text and layout embeddings improves robustness to OCR errors
- Mechanism: Query from text, key/value from layout (and vice versa) enables selective integration of layout cues, mitigating noisy OCR
- Core assumption: Layout embeddings contain enough redundancy to correct minor OCR mis-orderings
- Evidence anchors:
  - [section 4.2] "Our cross-attention module tries to find the most relevant layout embeddings based on text attention weights"
  - [abstract] "learns node and graph embeddings through a graph neural network"
  - [corpus] "FuDoBa: Fusing Document and Knowledge Graph-based Representations" — no direct support for text-layout fusion
- Break condition: If layout embeddings are corrupted (e.g., wrong bounding boxes), fusion may propagate errors

### Mechanism 3
- Claim: Graph attention network pre-training with MLM, MPM, and CPP tasks yields robust node representations that transfer well to OOD data
- Mechanism: Masked objectives force the GNN to infer context from neighboring nodes, building robust, generalizable embeddings
- Core assumption: Pre-training captures enough document structure to generalize beyond training distribution
- Evidence anchors:
  - [section 4.3] "We chose Graph Attention Network (GAT) as a message passing network"
  - [section 5.4] "pre-trained on the following three tasks"
  - [corpus] "Benchmarking Graph Representations and Graph Neural Networks for Multivariate Time Series Classification" — not directly relevant to document tasks
- Break condition: If pre-training data distribution is too narrow, learned representations may still overfit

## Architecture Onboarding

- Component map: OCR tokens + bounding boxes → Text & Layout Embeddings → Cross-attention → Node Embeddings → β-skeleton + Paragraph edges → GAT layers → Super-node → Graph-level logits for classification
- Critical path:
  1. OCR → bounding boxes → embeddings
  2. Fusion → node features
  3. GAT layers → message passing
  4. Super-node → classification
- Design tradeoffs:
  - Sparsity vs completeness: Fewer edges speed training but may lose context; β-skeleton + paragraph edges balance this
  - OCR vs visual features: Text+layout only reduces complexity but may miss visual cues; adding vision could improve but increase cost
  - GAT vs Transformer: GAT is more memory efficient but may limit long-range interactions; transformer layers could be added for deeper reasoning
- Failure signatures:
  - Accuracy drops on RN → likely insufficient layout generalization
  - High energy scores on RO → possible overfitting to training layout patterns
  - Convergence issues → check edge feature scaling or neighbor selection
- First 3 experiments:
  1. Ablation: Remove β-skeleton edges, keep only paragraph edges; measure RN accuracy drop
  2. Ablation: Remove cross-attention, use simple addition of embeddings; measure impact on OOD detection
  3. Stress test: Increase OCR noise (synthetic bounding box jitter); observe degradation in graph embeddings

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of GVdoc vary when using different OCR engines (e.g., Microsoft Azure OCR vs. Tesseract) for text and layout extraction?
- Basis in paper: [explicit] The paper mentions that using Tesseract OCR instead of Microsoft Azure OCR led to a 7% decrease in performance for LayoutLMv2
- Why unresolved: The paper only uses Tesseract OCR and does not compare the performance with other OCR engines
- What evidence would resolve it: Running experiments with different OCR engines and comparing the performance metrics (accuracy, AUC, FPR95) of GVdoc on the same datasets

### Open Question 2
- Question: How does the inclusion of visual features impact the performance of GVdoc on out-of-distribution data?
- Basis in paper: [inferred] The paper mentions that GVdoc relies on textual and layout features, neglecting the visual component. Other works have witnessed improvements by utilizing visual features along with textual and layout features
- Why unresolved: The paper does not explore the integration of visual features into GVdoc
- What evidence would resolve it: Incorporating visual features into GVdoc and comparing the performance metrics on out-of-distribution datasets with the current version of GVdoc

### Open Question 3
- Question: What is the impact of different graph generation methods (e.g., varying the number of neighbors per token) on the robustness of GVdoc to changes in the test distribution?
- Basis in paper: [explicit] The paper includes an ablation study on the effect of different graph generation methods, showing that using only paragraph-level graphs leads to poorer performance on out-of-distribution data compared to using both β-skeleton and paragraph-level graphs
- Why unresolved: The paper only explores a limited set of graph generation methods and does not provide a comprehensive analysis of their impact on robustness
- What evidence would resolve it: Conducting experiments with various graph generation methods (e.g., different numbers of neighbors per token, different edge types) and analyzing their impact on the robustness of GVdoc to changes in the test distribution

## Limitations

- Unknown hyperparameter values (β-skeleton β and maximum neighbor count) could significantly affect graph sparsity and model performance
- Exact fusion module architecture details are not specified, leaving room for architectural differences in reproduction
- Limited corpus evidence directly supports the claimed mechanisms; most supporting literature is tangential or not directly related to document classification

## Confidence

- **High**: GVdoc improves OOD detection performance (measured via energy scores and FPR95) while maintaining in-distribution accuracy
- **Medium**: Graph construction with β-skeleton + OCR edges captures layout sparsity and reading order context
- **Low**: Cross-attention fusion effectively mitigates OCR errors; pre-training with MLM, MPM, CPP yields robust generalizable representations
