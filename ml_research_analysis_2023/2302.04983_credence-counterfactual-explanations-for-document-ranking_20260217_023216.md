# CREDENCE: Counterfactual Explanations for Document Ranking

## Quick Facts
- arXiv ID: 2302.04983
- Source URL: https://arxiv.org/abs/2302.04983
- Reference count: 12
- Primary result: First tool capable of generating diverse counterfactual explanations for document rankers, enabling users to understand ranking decisions and extract insights about queries, documents, and rankers.

## Executive Summary
CREDENCE is a system that generates counterfactual explanations for document ranking, filling a gap in current explainable AI tools for information retrieval. It produces three types of explanations: document perturbations that lower a document's rank, query perturbations that raise a document's rank, and similar non-relevant documents for a given relevant document. The system uses iterative algorithms that prioritize perturbations based on importance scores and evaluates them in order of minimal perturbation size to ensure explanation minimality. An interactive builder allows users to create and test their own document perturbations.

## Method Summary
CREDENCE implements iterative algorithms to generate counterfactual explanations for document ranking. For document perturbations, it removes sentences scored by query-term frequency, prioritizing those with the highest scores. For query perturbations, it adds terms scored by TF-IDF, selecting those most frequent in the document and rare in the corpus. For instance-based explanations, it computes similarity using either Doc2Vec embeddings or BM25 vectors. The system is implemented as a FastAPI backend with a React frontend, using Lucene indexing via Pyserini and a monoT5 neural ranker. Explanations are generated by repeatedly querying the ranker with perturbed inputs.

## Key Results
- First system to generate diverse counterfactual explanations for document rankers.
- Enables users to understand ranking decisions and extract insights about queries, documents, and rankers.
- Supports interactive creation and testing of document perturbations.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Sentence removal with query-term frequency scoring reliably lowers document rank.
- Mechanism: Each sentence is scored by the count of its terms appearing in the query. Sentences with higher scores are removed first because their absence most likely reduces relevance.
- Core assumption: Query terms are strongly indicative of relevance; removing sentences containing more query terms will drop rank below threshold k.
- Evidence anchors:
  - [abstract] "we present counterfactual explanations in terms of document perturbations, query perturbations, and even other documents."
  - [section] "The algorithm then iterates through explanations in sorted order. Candidate documents are first sorted by perturbation size (i.e., number of removed sentences) in increasing order, then by their importance score (i.e., the sum of importance scores across removed sentences) in decreasing order."
  - [corpus] Weak evidence: no direct support for query-term frequency scoring; assumption based on IR intuition.
- Break condition: If the ranker uses features beyond document body (e.g., metadata), sentence removal may not consistently lower rank.

### Mechanism 2
- Claim: TF-IDF scoring of candidate query augmentation terms prioritizes additions that increase document rank.
- Mechanism: Terms from the instance document are scored by TF-IDF; high-scoring terms (frequent in doc, rare in corpus) are appended to query first, maximizing relevance lift.
- Core assumption: TF-IDF accurately captures term importance for relevance in the ranking model.
- Evidence anchors:
  - [section] "we choose to score each candidate term using TF-IDF, which scores terms based on their frequency in, and exclusivity to, the instance document d (among the set of ranked documents DM)."
  - [abstract] "we present counterfactual explanations in terms of document perturbations, query perturbations, and even other documents."
  - [corpus] Weak evidence: no explicit validation of TF-IDF for this use case; assumption drawn from standard IR practice.
- Break condition: If the ranker uses dense embeddings or non-term-based features, TF-IDF scoring may not align with actual relevance.

### Mechanism 3
- Claim: Document similarity via embeddings or BM25 vectors identifies plausible counterfactual documents.
- Mechanism: Similarity is computed (cosine for embeddings or BM25 vectors); non-relevant documents most similar to a relevant doc are returned as counterfactuals.
- Core assumption: A highly similar non-relevant document indicates a decision boundary; differences explain why the relevant doc was ranked higher.
- Evidence anchors:
  - [section] "In the first method, we train a Doc2Vec embedding model [12]. In the second method, we build numeric vector representations of each corpus document using their BM25 scores..."
  - [abstract] "users may build and test their own perturbations, and extract insights about their query, documents, and ranker."
  - [corpus] Weak evidence: no direct proof that similarity-based counterfactuals are more interpretable; based on design intuition.
- Break condition: If similarity metrics do not capture relevance-relevant features, the counterfactual documents may not be meaningful.

## Architecture Onboarding

- Component map:
  Frontend (React app with Material UI) -> Backend (FastAPI ASGI server) -> Retrieval (Lucene index via Pyserini) -> Ranking (monoT5 neural ranker) -> Explanation modules (iterative algorithms)

- Critical path:
  1. User submits query and selects k.
  2. Backend ranks top-k documents using monoT5.
  3. User selects a document and explanation type.
  4. Backend runs corresponding counterfactual algorithm, repeatedly querying the ranker.
  5. Results returned and rendered in the UI.

- Design tradeoffs:
  - Using black-box ranker assumptions vs. access to model internals.
  - Iterative perturbation search vs. closed-form solutions.
  - Sentence removal (grammatically safe) vs. term-level edits (finer control).

- Failure signatures:
  - Slow response times when generating many perturbations (iterative loop).
  - Explanations that do not change rank (ranker insensitive to perturbations).
  - UI errors when rendering large documents or complex topic models.

- First 3 experiments:
  1. Verify that removing the highest-scoring sentence lowers document rank as expected.
  2. Test that appending a high-TF-IDF term from the document raises its rank.
  3. Confirm that a similar non-relevant document is returned by both Doc2Vec and BM25 methods.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do different importance scoring methods (e.g., query term frequency vs. TF-IDF) affect the quality and interpretability of counterfactual explanations in document ranking?
- Basis in paper: [explicit] The paper discusses using query term frequency for document perturbations and TF-IDF for query perturbations, but does not compare their effectiveness or interpretability.
- Why unresolved: The paper does not provide empirical comparisons or user studies to evaluate which scoring method produces more meaningful or actionable counterfactual explanations.
- What evidence would resolve it: Comparative experiments measuring user comprehension, explanation usefulness, and ranking model insights across different scoring methods.

### Open Question 2
- Question: How does the choice of similarity measure (e.g., cosine similarity on BM25 scores vs. Doc2Vec embeddings) impact the plausibility and relevance of instance-based counterfactual explanations?
- Basis in paper: [explicit] The paper describes two methods for instance-based counterfactuals using cosine similarity on BM25 scores and Doc2Vec embeddings, but does not compare their effectiveness.
- Why unresolved: The paper does not evaluate which similarity measure produces more plausible or relevant counterfactual instances that better help users understand ranking decisions.
- What evidence would resolve it: User studies comparing the plausibility and usefulness of counterfactual instances generated by different similarity measures, or objective metrics measuring instance relevance to the original document.

### Open Question 3
- Question: How do counterfactual explanations affect user trust and decision-making when interacting with document ranking systems?
- Basis in paper: [inferred] The paper emphasizes that explanations build trust and enable auditing in critical applications, but does not empirically investigate how counterfactual explanations specifically impact user trust or decision-making.
- Why unresolved: The paper does not include user studies or experiments measuring changes in user trust, confidence in the ranking system, or decision-making quality after receiving counterfactual explanations.
- What evidence would resolve it: Controlled user studies measuring trust metrics, decision accuracy, or user confidence before and after exposure to counterfactual explanations in various ranking scenarios.

## Limitations
- System relies on black-box access to ranker, making explanations dependent on ranker's sensitivity to perturbations.
- Iterative perturbation search can be computationally slow for large corpora or complex explanations.
- Assumes sentence removal or query term addition will consistently affect rank, which may not hold for rankers using complex, non-textual features or dense embeddings.

## Confidence
Confidence in the core claims is **Medium**. The system's design is well-motivated by established IR principles (TF-IDF, query-term frequency, BM25, embeddings), but there is limited empirical validation of the effectiveness and interpretability of the generated counterfactual explanations. The claims about explanation minimality and diversity are supported by the algorithmic approach, but not rigorously tested across diverse datasets or ranker types.

## Next Checks
1. **Validation of explanation minimality**: Systematically test whether the iterative perturbation algorithms consistently produce the smallest possible changes that alter document rank, across multiple queries and rankers.
2. **Cross-ranker robustness**: Evaluate the system's explanations using different rankers (e.g., neural, traditional, dense) to confirm that perturbations reliably affect rank as expected.
3. **User study for interpretability**: Conduct a user study to assess whether the generated counterfactual explanations help users understand and trust the ranking model, compared to baseline explanation methods.
