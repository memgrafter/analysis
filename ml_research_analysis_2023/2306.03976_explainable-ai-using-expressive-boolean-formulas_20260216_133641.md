# Explainable AI using expressive Boolean formulas

## Quick Facts
- arXiv ID: 2306.03976
- Source URL: https://arxiv.org/abs/2306.03976
- Reference count: 0
- Primary result: We propose an interpretable ML classification model based on expressive Boolean formulas that can include any operator applied to Boolean variables.

## Executive Summary
This paper presents an interpretable machine learning approach for explainable AI using expressive Boolean formulas as classification rules. The method allows for tunable complexity and includes any operator applicable to Boolean variables, providing higher expressivity than rigid rule-based or tree-based approaches. The classifier is trained using native local optimization techniques, efficiently searching the space of feasible formulas, with the option to use fast ILP or QUBO solvers for shallow rules and quantum devices for non-local moves.

## Method Summary
The approach uses expressive Boolean formulas as classification rules, where formulas can include operators like And, Or, AtLeast, AtMost, and Choose with arbitrary nesting. Training involves a native local optimizer using simulated annealing with local moves (add/remove/modify literals or operators), combined with periodic non-local moves that optimize entire subtrees using ILP or QUBO formulations. The method handles binary classification by optimizing a tradeoff between accuracy and formula complexity, with shallow rules solvable via fast solvers and deeper rules via the native local approach.

## Key Results
- Expressive Boolean formulas achieve competitive performance with other classifiers on benchmark datasets
- Non-local moves improve convergence speed, potentially enabling speedup with specialized or quantum hardware
- The approach provides interpretable rules with tunable complexity for explainable AI applications

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The native local solver efficiently explores expressive Boolean formulas through small local changes
- Mechanism: Uses simulated annealing with Metropolis criterion and geometrically decreasing temperature, starting from random depth-one rules
- Core assumption: Search space is connected through local moves and objective landscape isn't too rugged
- Evidence: "The classifier is trained using native local optimization techniques, efficiently searching the space of feasible formulas" and Metropolis acceptance with temperature schedule

### Mechanism 2
- Claim: Non-local moves escape local minima by optimizing entire subtrees
- Mechanism: Periodically replaces subtrees with optimized versions found by ILP/QUBO solvers on data subsets
- Core assumption: Subproblem optimization is fast and representative subsets capture dataset patterns
- Evidence: "We combine the expressivity and efficiency of the native local optimizer with the fast operation of these devices by executing non-local moves that optimize over subtrees"

### Mechanism 3
- Claim: Expressive formulas provide more compact representations than rigid approaches
- Mechanism: Parameterized operators and arbitrary nesting encode complex relationships with fewer nodes
- Core assumption: Threshold-based relationships in data are well-suited to expressive formulas
- Evidence: "Expressive Boolean formulas ('Rule') are by far the most efficient at encoding these rules" compared to decision trees and CNF

## Architecture Onboarding

- **Component map**: Data -> Binarizer -> Native Local Solver (with Local Moves) -> Non-Local Move Generator -> Best Formula
- **Critical path**: 1) Preprocess data and binarize features 2) Initialize with random depth-one rules 3) Iteratively propose local moves 4) Periodically evaluate non-local moves 5) Track best solution 6) Evaluate on test data
- **Design tradeoffs**: Depth-one vs. deeper rules (expressivity vs. interpretability), ILP vs. QUBO (optimality vs. hardware acceleration), subset size for non-local moves (quality vs. speed)
- **Failure signatures**: Solver stalls (adjust temperature/schedule), non-local moves timeout (reduce subset size), overly complex rules (increase regularization)
- **First 3 experiments**: 1) Native local solver on Breast Cancer dataset, 2) Add non-local moves and measure improvement, 3) Vary binarization method and observe effects

## Open Questions the Paper Calls Out

- **Open Question 1**: How does runtime of native local solver with non-local moves compare to pure local optimization using specialized/quantum hardware?
  - Basis: Paper mentions "using specialized or quantum hardware could lead to a speedup" but provides no empirical comparison
  - Evidence needed: Runtime comparisons of hardware-accelerated vs. pure local optimization

- **Open Question 2**: What's the tradeoff between sampling size and model performance for different dataset characteristics?

  - Evidence needed: Systematic experiments varying sampling sizes across datasets with different characteristics

## Limitations
- Scalability concerns for high-dimensional datasets due to ILP/QUBO solver overhead
- Computational cost of non-local moves may limit practical applicability
- Limited guidance on optimal binarization strategies for different data types

## Confidence
- **High confidence**: Basic local optimization framework effectiveness (supported by extensive benchmarking)
- **Medium confidence**: Superiority of expressive formulas over rigid approaches (based on limited synthetic examples)
- **Medium confidence**: Speedup potential from quantum/non-local moves (theoretical justification, limited empirical validation)
