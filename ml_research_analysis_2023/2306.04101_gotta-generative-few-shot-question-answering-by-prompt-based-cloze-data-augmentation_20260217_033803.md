# Gotta: Generative Few-shot Question Answering by Prompt-based Cloze Data Augmentation

## Quick Facts
- arXiv ID: 2306.04101
- Source URL: https://arxiv.org/abs/2306.04101
- Reference count: 40
- Key outcome: Generative prompt-based data augmentation framework that outperforms competitive few-shot QA baselines by 2-3 F1 points

## Executive Summary
This paper introduces Gotta, a generative prompt-based data augmentation framework for few-shot question answering. The core innovation is integrating a cloze task as a companion to the main QA task using entity-aware text masking and prompt-style data augmentation. By formatting both tasks identically and using a unified prompt-based loss function, the model learns both tasks seamlessly together. Experiments on widely used benchmarks demonstrate consistent improvements over competitive baselines, validating the effectiveness of prompt-tuning-based cloze task integration for few-shot QA.

## Method Summary
Gotta is a generative prompt-based data augmentation framework that fine-tunes a pre-trained BART model for few-shot QA. It extracts entities from context passages using Wikidata-based recognition, masks these entities to create cloze-style training examples, and constructs prompt-style data combining original QA and augmented cloze data. The framework uses a weighted sum of original QA loss and augmented cloze loss with hyperparameter λ balancing the two tasks. This approach contrasts with standard fine-tuning or multi-task learning by leveraging prompt-tuning benefits and entity-aware context.

## Key Results
- Outperforms competitive few-shot QA baselines (RoBERTa, SpanBERT, Splinter, FewshotQA) by 2-3 F1 points on MRQA 2019 datasets
- Entity-aware text masking shows significant improvement over random masking (Gotta-random variant)
- Prompt-based loss function incorporates auxiliary cloze task better than multi-task learning approach
- Performance generally improves with more augmented data across all tested datasets

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Entity-aware text masking provides more relevant context than random masking for few-shot QA.
- **Mechanism:** By focusing on entities recognized by Wikidata, the model learns to reason about entity relationships rather than arbitrary tokens.
- **Core assumption:** QA performance improves when models learn to identify and understand entity relationships in context.
- **Evidence anchors:**
  - [abstract] "MLM randomly masks word tokens while entity-aware text masking only targets entities that are more likely to be relevant to the QA task."
  - [section] "For each training sample, we extract all the text spans recognized as Wikidata entities."
- **Break condition:** If entity masking degrades performance or introduces noise, the core assumption fails.

### Mechanism 2
- **Claim:** Prompt-style data augmentation aligns cloze and QA tasks for seamless learning.
- **Mechanism:** By formatting both tasks identically, the model can leverage prompt-tuning benefits without additional parameters.
- **Core assumption:** Sharing the same prompt format allows the model to transfer knowledge between cloze and QA tasks effectively.
- **Evidence anchors:**
  - [abstract] "Following the recent success of prompt-tuning, we present the cloze task in the same format as the main QA task, allowing the model to learn both tasks seamlessly together."
  - [section] "We formally formulate the following template to integrate QA and cloze tasks"
- **Break condition:** If separate task formatting performs better, the prompt alignment assumption is invalid.

### Mechanism 3
- **Claim:** Prompt-based loss function incorporates auxiliary cloze task better than multi-task loss.
- **Mechanism:** Unified prompt format allows single loss function to capture relationships between both tasks.
- **Core assumption:** Prompt-based loss provides better supervision than separate loss functions for each task.
- **Evidence anchors:**
  - [abstract] "Further analysis shows that the prompt-based loss incorporates the auxiliary task better than the multi-task loss"
  - [section] "Gotta-MTL has apparently worse performance than Gotta"
- **Break condition:** If multi-task loss with separate decoders outperforms prompt-based loss.

## Architecture Onboarding

- **Component map:** Entity extraction module (Wikidata) -> Prompt template generator -> BART encoder-decoder backbone -> Loss function (weighted sum of QA and cloze losses)

- **Critical path:**
  1. Extract entities from context passages
  2. Generate cloze examples using prompt templates
  3. Combine original and augmented data
  4. Train encoder-decoder with unified loss function

- **Design tradeoffs:**
  - Entity selection (Wikidata vs random masking)
  - Prompt format complexity vs effectiveness
  - Loss weight λ balancing QA vs cloze contribution

- **Failure signatures:**
  - High variance in F1 scores across runs
  - Performance degradation when adding cloze task
  - Entity extraction producing irrelevant or noisy examples

- **First 3 experiments:**
  1. Compare Gotta with Gotta-random (random masking) to validate entity-aware masking
  2. Test Gotta vs Gotta-MTL to verify prompt-based loss superiority
  3. Vary λ parameter to find optimal task balancing weight

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of Gotta vary with different entity masking strategies beyond the Wikidata-based approach?
- Basis in paper: [inferred] The paper mentions that Gotta uses entity-aware text masking based on Wikidata entities. It also compares Gotta with a random masking variant (Gotta-random) and finds entity masking beneficial.
- Why unresolved: The paper only tests one specific entity masking strategy (Wikidata-based) and a random baseline. Other entity masking strategies (e.g., using different knowledge bases, entity types, or masking patterns) could potentially yield different results.
- What evidence would resolve it: Experiments comparing Gotta's performance using different entity masking strategies (e.g., different knowledge bases, entity types, masking ratios, or patterns) on the same QA benchmarks would help determine the impact of entity masking choices.

### Open Question 2
- Question: What is the optimal balance between original QA data and augmented cloze data for maximizing Gotta's performance?
- Basis in paper: [explicit] The paper mentions a hyperparameter λ that balances the QA and cloze tasks in the loss function. It also discusses the effect of augmented data in Section 4.3.4, showing that performance generally improves with more augmented data.
- Why unresolved: While the paper shows that more augmented data generally helps, it doesn't explore the optimal ratio of original to augmented data. The impact of this ratio on performance could vary depending on the specific QA task and dataset.
- What evidence would resolve it: Experiments systematically varying the ratio of original to augmented data and measuring Gotta's performance on different QA tasks would help determine the optimal balance for maximizing performance.

### Open Question 3
- Question: How does Gotta's performance compare to other few-shot QA methods that use different pre-training strategies or knowledge integration techniques?
- Basis in paper: [explicit] The paper compares Gotta to four competitive few-shot QA methods (RoBERTa, SpanBERT, Splinter, FewshotQA) and shows that Gotta outperforms them. However, it doesn't compare Gotta to methods that use different pre-training strategies or knowledge integration techniques.
- Why unresolved: The paper only compares Gotta to methods that use similar pre-training strategies (fine-tuning pre-trained language models) or knowledge integration techniques (entity masking). Other methods that use different strategies (e.g., meta-learning, domain adaptation) or knowledge integration techniques (e.g., knowledge graphs, external databases) could potentially outperform Gotta.
- What evidence would resolve it: Experiments comparing Gotta's performance to other few-shot QA methods that use different pre-training strategies or knowledge integration techniques on the same QA benchmarks would help determine Gotta's relative effectiveness.

## Limitations

- Entity extraction quality and coverage across different domains remains unclear
- Modest performance gains (2-3 F1 points) may not generalize across different few-shot settings
- Prompt template construction is underspecified, making exact reproduction challenging
- Limited evaluation on extreme few-shot scenarios (5-10 examples) or non-standard domains

## Confidence

**High confidence** in the core observation that entity-aware text masking provides relevant context for few-shot QA training. The mechanism is well-grounded in prior work on entity-centric reasoning.

**Medium confidence** in the superiority of prompt-based loss over multi-task loss. While the experimental results show better performance, the comparison is limited to a single alternative approach without exploring the design space of multi-task learning configurations.

**Low confidence** in the generalizability of the approach across different few-shot ratios and domains. The paper primarily evaluates on standard MRQA datasets without exploring extreme few-shot scenarios or non-standard domains.

## Next Checks

1. **Entity extraction quality audit**: Systematically evaluate the precision and recall of Wikidata entity extraction across all MRQA datasets, measuring false positives (non-entities masked) and false negatives (entities missed) to quantify the noise introduced by this approach.

2. **Cross-architecture validation**: Implement Gotta on a smaller encoder-decoder model (e.g., T5-small) and compare performance with BART to determine if the approach scales to resource-constrained few-shot settings.

3. **Extreme few-shot evaluation**: Test Gotta with 5, 10, and 20 training examples per dataset to identify the break point where the augmentation strategy stops providing benefits, comparing against standard fine-tuning and transfer learning baselines.
