# Complexity and scalability of defeasible reasoning in many-valued weighted knowledge bases with typicality

## Quick Facts
- arXiv ID: 2303.04534
- Source URL: https://arxiv.org/abs/2303.04534
- Reference count: 5
- Primary result: Improving complexity of deciding ϕ-coherent entailment from Π p 2 to PNP[log] and introducing scalable ASP encodings for weighted DLs with typicality

## Executive Summary
This paper addresses the complexity and scalability of defeasible reasoning in weighted Description Logics (DLs) with typicality under a many-valued semantics. The authors improve the theoretical complexity of deciding ϕ-coherent entailment by showing an algorithm with parallel NP oracle queries, reducing the upper bound from Π p 2 to PNP[log]. To address practical scalability, they introduce new Answer Set Programming (ASP) encodings that handle weighted DLs with large search spaces, taking advantage of order encoding and weight constraints. Empirical results on synthetic KBs demonstrate that the new encodings scale significantly better than previous implementations.

## Method Summary
The paper presents both theoretical and practical contributions to defeasible reasoning in weighted DLs with typicality. Theoretically, the authors establish PNP[log]-completeness by reducing from the max sat odd problem and providing an algorithm with parallel NP oracle queries. Practically, they develop ASP encodings that replace weak constraints with order encoding and custom propagators with weight constraints to improve scalability. The experiments use synthetic KBs encoding fully-connected neural networks of varying dimensions, testing both the base encoding and the optimized variants on truth spaces with different numbers of truth degrees.

## Key Results
- PNP[log]-completeness of ϕ-coherent entailment decision problem, improving from previous Π p 2 bound
- Order encoding eliminates weak constraint level dependence, enabling strict PNP[log] upper bound
- Weight constraints enforce ϕ-coherence more efficiently than custom propagators in practice
- New ASP encodings scale significantly better on synthetic KBs with large search spaces

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Parallel NP oracle queries reduce theoretical complexity from Π p 2 to PNP[log].
- Mechanism: The ASP encoding is designed so that all n NP oracle calls can be executed in parallel rather than sequentially, collapsing the complexity class.
- Core assumption: ASP solver calls can be truly parallelized without interference and each remains in NP.
- Evidence anchors:
  - [abstract] states the upper bound improvement to PNP[log] by showing an algorithm running in polynomial time with parallel queries to an NP oracle.
  - [section] describes the algorithm using parallel queries for both steps (a) and (b), reducing n+1 sequential calls to 2n parallel ones.
  - [corpus] has no direct citations but the claim aligns with standard results like Buss and Hay 1991.
- Break condition: If parallelization is not achievable due to solver limitations or shared resources, the complexity reverts to Π p 2.

### Mechanism 2
- Claim: Order encoding eliminates weak constraint level dependence, enabling strict PNP[log] upper bound.
- Mechanism: Replacing the weak constraint in line 15 with an order encoding of truth degrees removes the need for level-based preferences, which would otherwise yield only PNP.
- Core assumption: The order encoding faithfully represents the valuation without introducing additional computational overhead.
- Evidence anchors:
  - [section] explicitly states that the base encoding's weak constraint uses a linear number of levels and replacing it with order encoding removes weights to achieve PNP[log].
  - [section] shows the rules for eval_ge/2 implementing the order encoding.
  - [corpus] has no direct citations but the technique is standard in ASP optimization.
- Break condition: If the order encoding increases grounding size beyond tractable limits, the theoretical gain is nullified by practical inefficiency.

### Mechanism 3
- Claim: Weight constraints enforce ϕ-coherence more efficiently than custom propagators.
- Mechanism: Instead of materializing weight sums via custom propagators, weight constraints directly check membership in relevant intervals, avoiding grounding bottlenecks.
- Core assumption: The interval checks are sufficiently expressive to enforce all ϕ-coherence requirements.
- Evidence anchors:
  - [section] describes both custom propagators and weight constraints, noting that weight constraints perform better empirically.
  - [section] provides the specific weight constraint rules in Figure 3.
  - [corpus] has no direct citations but the approach is common in ASP for large search spaces.
- Break condition: If the interval-based checks miss some ϕ-coherence inferences that propagators would catch, the semantics may be incorrectly enforced.

## Architecture Onboarding

- Component map:
  - Input parser: Reads weighted DL KBs and queries, converts to ASP facts.
  - Base encoding: Implements many-valued semantics with eval/3 atoms and concept evaluations.
  - Order encoding module: Replaces weak constraints with eval_ge/2 atoms for PNP[log] bound.
  - ϕ-coherence enforcer: Either custom propagators or weight constraints.
  - Solver interface: Manages parallel NP oracle calls and aggregates results.
  - Output formatter: Presents entailment result and typicality assignments.

- Critical path:
  1. Parse KB and query into ASP facts.
  2. Generate base encoding with eval/3 rules.
  3. Apply order encoding to eliminate weak constraint levels.
  4. Enforce ϕ-coherence (prefer weight constraints).
  5. Execute parallel NP oracle calls for all candidate truth degrees.
  6. Determine highest consistent degree and check for counterexamples.
  7. Output entailment decision.

- Design tradeoffs:
  - Custom propagators vs. weight constraints: propagators are more expressive but cause grounding bottlenecks; weight constraints are faster but may miss some inferences.
  - Sequential vs. parallel NP calls: parallel reduces theoretical complexity but may strain solver resources.
  - Crisp vs. many-valued typicality: crisp is simpler but less expressive; many-valued captures nuanced preferences.

- Failure signatures:
  - Grounding timeout: Indicates the search space is too large, consider simplifying KB or using order encoding.
  - Solver returns no answer sets: Likely a modeling error or unsatisfiable constraints; check ϕ-coherence enforcement.
  - Inconsistent entailment results: May indicate incorrect parallel call aggregation or missing ϕ-coherence inferences.

- First 3 experiments:
  1. Run the base encoding on a small synthetic KB (e.g., 10 nodes, 50 edges) to verify basic functionality.
  2. Replace the base encoding with the order encoding on the same KB to confirm PNP[log] bound.
  3. Swap weight constraints for custom propagators on a medium KB (e.g., 20 nodes, 200 edges) to compare runtime and grounding behavior.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the exact computational complexity of deciding entailment for weighted DL KBs under the finitely many-valued semantics with Godel logic connectives, beyond the current P^NP[log] upper bound?
- Basis in paper: [explicit] The paper improves the upper bound from Π p 2 to PNP[log] and proves PNP[log]-completeness by reducing the max sat odd problem, but does not provide tighter bounds.
- Why unresolved: The reduction to max sat odd only shows PNP[log]-hardness, and while the algorithm is in PNP[log], there could be tighter complexity classes within PNP[log].
- What evidence would resolve it: A tighter reduction showing membership in a more specific subclass of PNP[log], or a separation result proving the problem is complete for that subclass.

### Open Question 2
- Question: How does the choice of activation function ϕ impact the scalability and performance of the ASP encodings for defeasible reasoning?
- Basis in paper: [inferred] The paper assumes a fixed ϕ function and mentions the possibility of using different ϕi functions for different concepts, but does not investigate the practical impact of varying ϕ.
- Why unresolved: The experiments only use one ϕ function, and the impact of different activation functions on grounding, search space size, and runtime is unknown.
- What evidence would resolve it: Empirical results comparing the performance of ASP encodings with different ϕ functions on a variety of weighted DL KBs, including analysis of grounding times and search space sizes.

### Open Question 3
- Question: Can the ASP encodings be extended to handle more expressive DL fragments beyond LCn, such as ALC with roles and universal/existential restrictions?
- Basis in paper: [explicit] The paper mentions that the approach can be extended to more expressive and lightweight DLs, such as EL, but does not provide concrete extensions or complexity results.
- Why unresolved: The complexity results and ASP encodings are specific to LCn, and it is unclear how they would generalize to more expressive DLs with additional constructors.
- What evidence would resolve it: Formal proofs of complexity results for more expressive DL fragments, along with ASP encodings that handle the additional constructors, and empirical evaluation on test cases.

- Performance impact of varying the activation function ϕ not systematically studied
