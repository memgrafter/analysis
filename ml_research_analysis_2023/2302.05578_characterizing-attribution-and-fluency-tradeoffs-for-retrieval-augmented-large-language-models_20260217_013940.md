# Characterizing Attribution and Fluency Tradeoffs for Retrieval-Augmented Large Language Models

## Quick Facts
- arXiv ID: 2302.05578
- Source URL: https://arxiv.org/abs/2302.05578
- Reference count: 26
- The paper investigates the relationship between fluency and attribution in retrieval-augmented large language models using the QReCC dataset.

## Executive Summary
This paper characterizes the tradeoff between fluency and attribution in retrieval-augmented large language models by systematically evaluating PaLM models of different sizes (8B, 62B, 540B) with varying temperature settings and prompt structures. Using both human evaluation and auto-metrics aligned with human preferences, the authors find that model size and temperature have comparable effects on the global tradeoff, while top-k retrieval improves attribution at the cost of fluency under context constraints. They also demonstrate that re-ranking outputs from multiple inferences with small models can achieve performance comparable to large models with oracle knowledge.

## Method Summary
The authors evaluate fluency and attribution tradeoffs using the QReCC dataset with PaLM models across different configurations. They develop auto-metrics (auto-SSA for fluency using PaLM-based sensibleness rating, and auto-AIS for attribution using NLI with localized evidence windows) aligned with human preferences from a pilot study. Experiments vary model size, temperature, prompt structure (evidence presence, dialog history, instructions), and retrieval strategy (top-1 vs top-k), with additional synthetic experiments to analyze local tradeoffs under restricted context ratios.

## Key Results
- Larger models consistently outperform smaller ones in both fluency and attribution when provided with golden evidence
- Top-k retrieval improves attribution but reduces fluency compared to top-1 retrieval under restricted context
- Re-ranking outputs from multiple inferences with small models achieves F1 scores comparable to large models with oracle knowledge

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Larger models consistently outperform smaller ones in both fluency and attribution when provided with golden evidence.
- Mechanism: Increased model capacity enables better integration of retrieved evidence into coherent, fluent responses while maintaining factual accuracy.
- Core assumption: The model has sufficient capacity to process both dialog context and evidence without exceeding context window limits.
- Evidence anchors:
  - [abstract] "We show that larger models tend to do much better in both fluency and attribution"
  - [section 7.2] "In other words, for our selection of models, sampling temperature and model size have comparable effect on the value of the global tradeoff"
- Break condition: If context window is exceeded or if evidence quality is too poor for even large models to integrate effectively

### Mechanism 2
- Claim: Top-k retrieval improves attribution scores but reduces fluency compared to top-1 retrieval under restricted context.
- Mechanism: Top-k retrieval provides more evidence options, increasing recall and attribution probability, but context competition reduces fluency as the model must balance multiple evidence sources.
- Core assumption: Context window constraints force a tradeoff between evidence quantity and quality of integration.
- Evidence anchors:
  - [abstract] "top-k retrieval improves attribution but hurts fluency compared to top-1 retrieval under restricted context"
  - [section 7.4] "we might be losing fluency while gaining attributability" when comparing top-3 vs top-1 evidence
- Break condition: When context window is sufficiently large that all top-k evidence can be incorporated without competition

### Mechanism 3
- Claim: Re-ranking outputs from multiple inferences with small models can achieve F1 scores comparable to large models with oracle knowledge.
- Mechanism: Multiple inference attempts with different evidence selections are generated, then re-ranked by auto-metrics to select the optimal combination of fluency and attribution.
- Core assumption: Auto-metrics accurately align with human preferences and can effectively distinguish between good and poor generations.
- Evidence anchors:
  - [abstract] "Re-ranking outputs from multiple inferences with small models allows achieving F1 scores comparable to large models with oracle knowledge"
  - [section 7.5] "performing multiple inferences with small model (8B) and then re-ranking them by auto-metrics allows to get F1 values of global tradeoff comparable to the ones produced from large model (540B) without re-ranking"
- Break condition: If auto-metrics poorly align with human preferences or if re-ranking computational cost exceeds benefits

## Architecture Onboarding

- Component map:
  Retrieval system (BM25 or similar) → Evidence selection (top-1 vs top-k) → Prompt construction (with/without instructions, dialog history) → Model inference (various sizes and temperatures) → Auto-metric scoring → Re-ranking (optional)
  Key components: QReCC dataset interface, BM25 retriever, PaLM models (8B, 62B, 540B), NLI-based attribution scorer, PaLM-based fluency scorer, re-ranking pipeline

- Critical path:
  1. Load dialog context and question from QReCC
  2. Retrieve relevant evidence passages
  3. Construct prompt with evidence and context
  4. Generate response using selected model configuration
  5. Score response using auto-metrics
  6. (Optional) Re-rank multiple responses if using re-ranking approach

- Design tradeoffs:
  - Model size vs computational cost: Larger models perform better but are more expensive to run
  - Top-1 vs top-k retrieval: Top-k improves attribution but hurts fluency under context constraints
  - Re-ranking vs single inference: Re-ranking improves F1 but increases inference cost by factor of K2
  - Prompt complexity vs performance: More complex prompts may improve performance but are harder to optimize

- Failure signatures:
  - Low F1 scores across all configurations: Indicates fundamental issues with dataset, metrics, or model capabilities
  - High attribution but low fluency: Suggests evidence is being incorporated but not integrated smoothly
  - High fluency but low attribution: Suggests model is generating plausible responses without grounding in evidence
  - Inconsistent results between human and auto-metrics: Indicates poor alignment between evaluation methods

- First 3 experiments:
  1. Run 540B model with temperature=0.0, golden evidence, full dialog history to establish upper bound performance
  2. Run 8B model with temperature=0.7, no evidence, only question to establish lower bound performance
  3. Run 62B model with temperature=0.0, top-1 retrieval, full dialog history to compare medium model performance against baselines

## Limitations
- Auto-metric alignment with human preferences is validated only through a limited pilot study, which may not generalize well across different domains
- The restricted context simulations assume linear relationships between dialog and evidence that may not capture real-world complexity
- Computational expense of the re-ranking approach (K2 inferences) may limit practical applicability

## Confidence
**High Confidence**: The observed effects of model size and temperature on the fluency-attribution tradeoff are supported by direct experimental results across multiple model scales (8B, 62B, 540B) with consistent patterns.

**Medium Confidence**: The local tradeoff analysis under restricted context is mechanistically sound but relies on synthetic experiments that may not fully capture real-world retrieval and generation dynamics.

**Low Confidence**: The claimed comparability between re-ranking with small models and using large models with oracle knowledge requires further validation, as the evaluation relies entirely on auto-metrics without human confirmation.

## Next Checks
1. **Human validation of re-ranking benefits**: Conduct human evaluation comparing re-ranked outputs from small models against direct outputs from large models on the same set of examples to verify the auto-metric alignment claims.

2. **Context window sensitivity analysis**: Systematically vary context window sizes (e.g., 1000, 2000, 4000 tokens) to determine if the observed top-k vs top-1 tradeoff persists or changes with different capacity constraints.

3. **Cross-domain generalization test**: Apply the same evaluation framework to a different conversational dataset (e.g., Wizard of Wikipedia or Natural Questions) to assess whether the identified tradeoff patterns hold beyond the QReCC domain.
