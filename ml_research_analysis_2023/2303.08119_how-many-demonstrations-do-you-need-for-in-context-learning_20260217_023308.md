# How Many Demonstrations Do You Need for In-context Learning?

## Quick Facts
- arXiv ID: 2303.08119
- Source URL: https://arxiv.org/abs/2303.08119
- Authors: 
- Reference count: 4
- Primary result: One correct demonstration outperforms using all demonstrations in in-context learning

## Executive Summary
This paper investigates how many demonstrations are needed for effective in-context learning (ICL) with large language models. Surprisingly, using just one randomly chosen demonstration performs nearly as well as using all demonstrations. The key finding is that most test queries have mostly correct demonstrations, making random selection sufficient for these "easy" queries. However, using one correct demonstration significantly outperforms using all demonstrations (including wrong ones), revealing that LLMs struggle to identify correct demonstrations among multiple options and are easily distracted by misleading information.

## Method Summary
The study uses the code-davinci-002 model (GPT-3 Codex) on reasoning datasets including GSM8K, MultiArith, AddSub, SVAMP, AQuA, SingleOp, CSQA, and Coin-flip. Hand-crafted demonstrations from Wei et al. (2022) are categorized as "correct" or "wrong" based on whether they lead to correct answers for specific test queries. Experiments compare ICL performance using one random demo versus all demos, and one correct demo versus all demos, with and without chain-of-thought prompting. The authors also incrementally add correct and wrong demos to analyze interference effects.

## Key Results
- Using one random demonstration performs similarly to using all demonstrations
- Using one correct demonstration significantly outperforms using all demonstrations
- Adding more correct demonstrations to easy queries degrades accuracy, while adding wrong demonstrations to hard queries improves accuracy
- Most test queries have a high proportion of correct demonstrations, creating an inherent dataset bias

## Why This Works (Mechanism)

### Mechanism 1
- Claim: ICL performance drops only marginally when using one random demo instead of all demos
- Mechanism: Most test queries in the studied datasets have a high proportion of correct demos, so randomly selecting one demo still yields a correct result for these "easy" queries
- Core assumption: The datasets used in ICL research contain an inherent bias toward easy queries where most demos are correct
- Evidence anchors:
  - [abstract]: "most demos are correct for a majority of test queries, which explains the good performance of using one random demo"
  - [section]: "Statistics on all the datasets reveal a widely existing bias of easy queries, i.e., most demos are correct for a majority of queries"

### Mechanism 2
- Claim: Adding more correct demos to easy queries degrades accuracy while adding more wrong demos to hard queries improves accuracy
- Mechanism: LLMs struggle to identify and filter out irrelevant or misleading information from multiple demos, leading to interference and spurious correlations that degrade performance on easy queries but can provide helpful diversity for hard queries
- Core assumption: LLMs have difficulty distinguishing between useful and misleading demonstrations when multiple options are presented
- Evidence anchors:
  - [abstract]: "ICL can be easily misguided by interference among demos and their spurious correlations"
  - [section]: "composing multiple correct demos that individually generate the correct answer may hamper the model's performance"

### Mechanism 3
- Claim: Using one correct demo significantly outperforms using all demos (including both correct and wrong demos)
- Mechanism: The presence of wrong demos in multi-demo ICL creates noise that the LLM cannot effectively filter out, leading to poorer performance than using a single correct demo
- Core assumption: LLMs are not good at identifying correct demos among multiple options and are easily distracted by wrong demos
- Evidence anchors:
  - [abstract]: "ICL (with and w/o CoT) using only one correct demo significantly outperforms all-demo ICL"
  - [section]: "LLMs fail to capture the most effective demo and are easily distracted by Wrong demos"

## Limitations

- The findings are based on a specific model (code-davinci-002) and may not generalize to other LLMs or task domains
- The categorization of demos as "correct" or "wrong" is binary and may not capture more nuanced quality distinctions
- The observed dataset bias toward easy queries with mostly correct demos may be specific to the studied benchmarks rather than representative of all ICL scenarios
