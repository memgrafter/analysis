# Adaptive Parameterization of Deep Learning Models for Federated Learning

## Quick Facts
- arXiv ID: 2302.02949
- Source URL: https://arxiv.org/abs/2302.02949
- Reference count: 20
- Reduces communication overhead by approximately 90% while maintaining similar inference performance to full model fine-tuning

## Executive Summary
This paper introduces parallel Adapters for Federated Learning, where clients train only domain-specific adapter parameters instead of the full model. The approach achieves similar inference performance to full model fine-tuning while reducing communication payload by approximately 90%. Experiments on SVHN, CIFAR10, and FashionMNIST datasets demonstrate effectiveness across various non-IID data distributions in both cross-silo and cross-device settings.

## Method Summary
The method uses a pre-trained ResNet26 base model with parallel 1x1 convolutional adapters injected after each 3x3 convolutional layer. Clients train only adapter parameters on their local data while keeping the base model frozen. Only adapter parameters and batch normalization statistics are transmitted during federated aggregation. The approach is tested with FedAvg, FedProx, and FedNova algorithms across 50 communication rounds with batch size 64.

## Key Results
- Achieves ~90% reduction in communication overhead compared to full model fine-tuning
- Maintains similar inference performance to full model training across multiple datasets
- FedProx generally performs best across non-IID distributions
- Training instability observed with quantity-based label imbalance (M=1)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Adapters reduce communication overhead by a factor of ~9 in federated learning.
- Mechanism: Only domain-specific adapter parameters and batch normalization statistics are exchanged instead of full model parameters, achieving 90% reduction.
- Core assumption: Base model parameters are frozen and shared across all clients.
- Evidence anchors:
  - [abstract] "reducing the communication overhead by roughly 90%"
  - [section] "Since the ResNet26 uses 3×3 convolutional layers and the Adapters are 1× 1 convolutional layers, we can effectively lower the amount of parameters that needs to be transmitted by a factor of approximately 9."
- Break condition: If base model parameters need fine-tuning or differ across clients.

### Mechanism 2
- Claim: Adapters enable similar inference performance to full model fine-tuning while reducing communication.
- Mechanism: Pre-trained base model provides general feature extraction while adapters adapt to domain-specific characteristics.
- Core assumption: Base model learns sufficiently general features adaptable through small modifications.
- Evidence anchors:
  - [abstract] "We highlight that our approach can achieve similar inference performance compared to training the full model"
- Break condition: If local data distributions are too dissimilar from pre-training data.

### Mechanism 3
- Claim: Adapters increase security by preventing model functionality without base model access.
- Mechanism: Only adapter parameters are transmitted, making intercepted communications useless without base model access.
- Core assumption: Base model parameters are securely distributed or pre-existing on client devices.
- Evidence anchors:
  - [abstract] "It increases security as only Adapters are exchanged among the clients in each communication round"
- Break condition: If base model parameters are compromised or reverse-engineered.

## Architecture Onboarding

- Component map:
  - Base Model: Frozen ResNet26 pre-trained on ImageNet
  - Adapters: Parallel 1x1 convolutional filters after each 3x3 convolutional layer
  - Batch Normalization: Domain-specific parameters maintained per client
  - Aggregation: Server averages adapter parameters from participating clients
  - Communication: Only adapter and batch norm parameters transmitted

- Critical path:
  1. Server distributes base model to all clients
  2. Clients train local adapters on their data
  3. Clients send adapter updates to server
  4. Server aggregates adapter parameters
  5. Server broadcasts aggregated adapters back to clients
  6. Clients update local adapter parameters

- Design tradeoffs:
  - Communication vs. Performance: 90% reduction at potential cost of some accuracy
  - Base Model Dependency: Requires trusted distribution of base model
  - Storage Requirements: Clients need to store both base model and adapters
  - Training Stability: Batch normalization issues in non-IID settings require careful learning rate tuning

- Failure signatures:
  - Training instability with quantity-based label imbalance (M=1)
  - NaN values during FedNova aggregation due to batch normalization statistics
  - Degradation in performance when feature distributions diverge significantly
  - Convergence issues with insufficient client participation fractions

- First 3 experiments:
  1. Baseline: Run FedAvg with full model fine-tuning on homogeneous data distribution
  2. Adapter Test: Implement adapters with FedAvg on the same homogeneous distribution
  3. Non-IID Challenge: Test both approaches on distribution-based label imbalance (Dir(0.5))

## Limitations
- Evaluation restricted to three datasets and ResNet26 architecture may not generalize to more complex tasks
- Training instability with quantity-based label imbalance and NaN values during FedNova aggregation
- Security benefit claims are theoretical without empirical validation or attack simulations

## Confidence
- High Confidence: Communication reduction mechanism is well-established and mathematically sound (90% reduction verified through parameter counting)
- Medium Confidence: Performance parity claims with full model fine-tuning supported by experiments but may be dataset-specific
- Low Confidence: Security benefit claims lack empirical validation and real attack scenario testing

## Next Checks
1. Generalize evaluation to larger datasets (ImageNet-1K or COCO) and deeper architectures (ResNet50/101) to assess scalability and whether 9x reduction factor holds
2. Conduct penetration testing by simulating communication interception attacks to verify whether attackers can reconstruct functional models from intercepted adapter parameters
3. Implement and test alternative batch normalization strategies (instance normalization or synchronized batch normalization) to address NaN issues observed with FedNova in quantity-based non-IID scenarios
