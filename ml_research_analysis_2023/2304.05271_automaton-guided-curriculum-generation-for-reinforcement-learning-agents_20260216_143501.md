# Automaton-Guided Curriculum Generation for Reinforcement Learning Agents

## Quick Facts
- arXiv ID: 2304.05271
- Source URL: https://arxiv.org/abs/2304.05271
- Reference count: 4
- Key outcome: Automaton-guided curriculum learning achieves better time-to-threshold performance compared to state-of-the-art curriculum learning and automaton-guided RL baselines

## Executive Summary
This paper introduces AGCL (Automaton-Guided Curriculum Learning), a method for automatically generating curricula to learn complex sequential decision-making tasks in reinforcement learning. The approach encodes task specifications as deterministic finite automata (DFA) combined with Object-Oriented MDP (OOMDP) representations. AGCL produces directed acyclic graphs (DAGs) where vertices represent tasks and edges indicate knowledge transfer directions, enabling both sequence-based and graph-based curricula. The method significantly outperforms existing approaches in terms of time-to-threshold performance and reduces the number of interactions with the target environment by orders of magnitude.

## Method Summary
AGCL generates curricula by leveraging logical specifications of tasks encoded as deterministic finite automata (DFA) and Object-Oriented MDP (OOMDP) representations. The method constructs directed acyclic graphs (DAGs) where each vertex represents a task and edges denote knowledge transfer directions between tasks. Two curriculum types are produced: sequence-based curricula with ordered tasks and graph-based curricula enabling parallel learning with knowledge transfer. The approach automatically identifies which subtasks should be learned first and how knowledge transfers between them, without requiring manual curriculum design. The framework demonstrates robustness to noise in OOMDP descriptions and can handle distractor objects not included in the logical specifications.

## Key Results
- AGCL achieves significantly better time-to-threshold performance compared to state-of-the-art curriculum learning and automaton-guided RL baselines
- The method reduces the number of interactions with the target environment by orders of magnitude
- AGCL performs well even with noisy OOMDP descriptions and handles distractor objects not modeled in logical specifications

## Why This Works (Mechanism)
AGCL works by decomposing complex tasks into simpler subtasks based on their logical specifications encoded in DFAs. The automaton structure naturally captures the sequential dependencies between subtasks, allowing the method to identify prerequisite relationships. By representing tasks as OOMDPs, AGCL can abstract away irrelevant details and focus on the essential state features needed for each subtask. The DAG curriculum structure enables both sequential learning (where simpler tasks are learned first) and parallel learning with knowledge transfer between related tasks. This decomposition approach allows agents to learn complex behaviors more efficiently than attempting to learn the entire task at once, while the automaton-guided structure ensures that learned skills transfer appropriately to the full task.

- Object-Oriented MDPs (OOMDPs): Why needed - to provide appropriate state abstractions and focus learning on relevant features; Quick check - confirm OOMDP captures essential state information
- Directed Acyclic Graphs (DAGs): Why needed - to represent curriculum structure and knowledge transfer relationships; Quick check - ensure graph is acyclic and properly connected
- Curriculum Learning: Why needed - to break down complex tasks into learnable subtasks; Quick check - verify curriculum improves learning efficiency over direct learning

## Architecture Onboarding

Component Map:
OOMDP Representations -> DFA Specifications -> DAG Curriculum Generation -> Task Learning with Knowledge Transfer

Critical Path:
OOMDP specification → DFA encoding → DAG curriculum construction → Sequential/parallel task learning → Knowledge transfer → Target task performance

Design Tradeoffs:
- Choice between sequence-based (simpler, more structured) vs graph-based (more flexible, parallel) curricula
- Level of abstraction in OOMDP representation (too coarse loses information, too fine increases complexity)
- Balance between curriculum complexity and learning efficiency
- Handling of noise in specifications vs strict adherence to correct models

Failure Signatures:
- Poor performance indicates incorrect OOMDP abstractions or faulty DFA specifications
- Curriculum that doesn't improve over direct learning suggests inappropriate task decomposition
- Knowledge transfer failures may indicate missing connections in DAG structure
- Excessive computational overhead could indicate overly complex curriculum graphs

3 First Experiments:
1. Verify OOMDP abstraction correctly captures essential state features for simple tasks
2. Test DFA encoding on tasks with known sequential dependencies
3. Evaluate curriculum performance on toy problems where optimal curriculum is known

None

## Limitations
- Heavy reliance on accurate OOMDP representations and DFA specifications, though some robustness to noise is demonstrated
- Experimental validation limited to gridworld and robotics domains, which are relatively constrained environments
- Performance gains may not directly translate to more complex, high-dimensional state spaces or partially observable environments

## Confidence

High confidence: The core algorithmic framework and DAG-based curriculum representation are sound and well-defined

Medium confidence: Performance claims relative to baselines are supported by experimental results, though the choice of baselines and evaluation metrics could be more comprehensive

Medium confidence: Claims about noise robustness in OOMDP descriptions, while demonstrated, need broader validation across different types of specification errors

## Next Checks

1. Evaluate AGCL's performance on partially observable environments where the DFA specification may not capture all relevant state information

2. Test the approach with varying levels of specification noise to quantify the degradation in performance and identify breaking points

3. Compare against additional curriculum learning baselines, particularly those using learned curricula rather than hand-designed specifications
