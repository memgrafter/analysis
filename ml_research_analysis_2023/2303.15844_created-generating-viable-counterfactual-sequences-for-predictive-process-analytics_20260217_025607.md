# CREATED: Generating Viable Counterfactual Sequences for Predictive Process Analytics

## Quick Facts
- arXiv ID: 2303.15844
- Source URL: https://arxiv.org/abs/2303.15844
- Reference count: 24
- Primary result: Framework generates viable counterfactual sequences without domain knowledge, outperforming baselines in viability and matching state-of-the-art methods that require domain expertise

## Executive Summary
This paper introduces CREATED, a framework that generates viable counterfactual sequences for predictive process analytics using evolutionary algorithms. The method learns process behavior from event logs through a Markov model and optimizes counterfactuals across four criteria: feasibility, delta in outcome prediction, similarity to original sequence, and sparsity. The framework achieves high viability scores without requiring domain knowledge, making it applicable to diverse process domains.

## Method Summary
CREATED employs an evolutionary algorithm to generate counterfactual sequences, using a pre-trained LSTM model to predict outcomes and a Markov model to assess sequence feasibility. The framework optimizes four components of viability: feasibility (likelihood under learned process model), delta (change in prediction), similarity (to original sequence), and sparsity (number of changes). Case-based initialization seeds the evolutionary population with actual process instances, and the algorithm iteratively selects, recombines, and mutates sequences to maximize the composite viability score.

## Key Results
- CREATED outperforms baseline methods in generating viable counterfactual sequences across 10 real-life process datasets
- Case-based initialization is identified as the most important configuration, consistently producing the best results
- The framework generates counterfactuals with similar quality to state-of-the-art methods that require domain knowledge
- The viability measure effectively balances prediction changes with process realism across all datasets

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The evolutionary algorithm improves counterfactual viability by optimizing across four complementary measures (feasibility, delta, similarity, sparsity).
- Mechanism: The evolutionary operators iteratively generate candidate sequences, evaluate them with a composite viability score, and select the best candidates to produce offspring. This process progressively refines sequences to balance prediction changes with process realism.
- Core assumption: The composite viability measure accurately captures the trade-offs between counterfactual quality criteria.
- Evidence anchors:
  - [abstract] "Our framework contains three components... The third component implements the evolutionary algorithm, which generates counterfactual sequences that should be of high quality. To quantify the quality of counterfactual sequences and select the best ones, we define a viability measure as our third component, which takes four measures into account..."
  - [section] "The framework contains three components. The first component is a pre-trained predictive model... The second component implements the evolutionary algorithm... To select the most viable counterfactual candidate, we evaluate their viability score using a custom metric. The metric incorporates four criteria for viable counterfactuals."
- Break condition: If the viability measure weights are poorly calibrated, the algorithm may converge to locally optimal but unrealistic counterfactuals.

### Mechanism 2
- Claim: Training a Markov model on the event log enables feasibility assessment without domain knowledge.
- Mechanism: The Markov model estimates transition probabilities between events and feature emission probabilities given activities, allowing the viability measure to score how likely a counterfactual sequence is under the learned process model.
- Core assumption: The Markov assumption (each event depends only on the current activity) is sufficient to capture process behavior.
- Evidence anchors:
  - [section] "To determine the feasibility of a counterfactual trace, it is important to consider two aspects... Second, we have to compute the feasibility of the individual feature values given the sequence. We can relax the computation of this probability using the Markov Assumption."
- Break condition: If the process exhibits long-range dependencies beyond first-order Markov, the feasibility estimates will be inaccurate.

### Mechanism 3
- Claim: Case-based initialization provides superior starting points for the evolutionary search compared to random or sampling-based approaches.
- Mechanism: By seeding the population with actual process instances from the log, the evolutionary algorithm begins with realistic sequences that are more likely to evolve into viable counterfactuals than random sequences.
- Core assumption: The log contains diverse enough examples to cover the search space relevant to counterfactual generation.
- Evidence anchors:
  - [section] "According to Figure 3, CBI-ES-UC3-SBM-RR, CBI-RWS-OPC-SBM-FSR, and CBI-RWS-OPC-SBM-FSR are the best model configurations. As all best-performing model-configurations use the Case-Based Initiation-operator, we identify it as the most important configuration."
- Break condition: If the log is too small or unrepresentative, case-based initialization may bias the search toward suboptimal regions.

## Architecture Onboarding

- Component map:
  Predictive Model -> Evolutionary Generator -> Markov Feasibility Model -> Viability Measure

- Critical path:
  1. Train predictive model on event log
  2. Train Markov model on event log
  3. Initialize evolutionary population (preferably case-based)
  4. Iterate: evaluate viability → select → crossover → mutate → recombine
  5. Output top counterfactuals

- Design tradeoffs:
  - Markov model simplicity vs. ability to capture complex dependencies
  - Evolutionary search breadth vs. computational efficiency
  - Composite viability weights vs. optimization focus

- Failure signatures:
  - Low feasibility scores indicate sequences that violate learned process patterns
  - High delta but low similarity suggests unrealistic counterfactuals
  - Poor convergence indicates need for parameter tuning or operator changes

- First 3 experiments:
  1. Compare case-based vs. random vs. sampling initialization on a small dataset
  2. Test different evolutionary operator combinations while holding other parameters constant
  3. Vary mutation rate to find optimal exploration-exploitation balance

## Limitations

- The Markov model assumption of first-order dependencies may be overly simplistic for complex business processes with long-range temporal dependencies
- The viability measure combines four components through weighted summation without systematic sensitivity analysis of weight combinations
- The generalizability of the viability measure weights across different process domains remains uncertain without cross-domain validation

## Confidence

- **High confidence**: The evolutionary algorithm framework and its implementation details are well-described and technically sound. The case-based initialization showing superior performance is convincingly demonstrated.
- **Medium confidence**: The Markov model approach for feasibility assessment is reasonable but may not capture complex process patterns. The experimental results showing superiority over baselines are promising but limited to 10 datasets.
- **Low confidence**: The generalizability of the viability measure weights across different process domains remains uncertain without cross-domain validation.

## Next Checks

1. **Dependency Analysis**: Test the Markov model's ability to capture complex dependencies by comparing first-order versus higher-order Markov models on datasets known to have long-range temporal patterns.

2. **Weight Sensitivity**: Perform systematic sensitivity analysis by varying the four viability measure weights across multiple datasets to determine if optimal weight combinations are domain-specific or generalizable.

3. **Real-World Deployment**: Conduct a user study with domain experts to evaluate whether the generated counterfactuals are not only technically viable but also practically actionable and interpretable in real business contexts.
