# EAMDrift: An interpretable self retrain model for time series

## Quick Facts
- arXiv ID: 2305.19837
- Source URL: https://arxiv.org/abs/2305.19837
- Reference count: 40
- Primary result: EAMDrift achieves 20% better performance than individual baseline models while maintaining interpretability through ensemble selection based on statistical features and learned rules

## Executive Summary
EAMDrift is an interpretable ensemble model for time series forecasting that automatically adapts to concept drift while maintaining model transparency. The approach encodes different data concepts using distinct base models (Prophet, SARIMA, LSTM, Transformer) and employs a RuleFit model to select the most appropriate predictor based on statistical features and covariates extracted from sliding windows. The system detects concept drift using KSWIN and triggers automatic retraining to maintain forecasting accuracy. Experimental results show EAMDrift outperforms individual models by 20% and achieves comparable accuracy to non-interpretable ensembles.

## Method Summary
EAMDrift processes historical time series data by splitting it into sliding windows, extracting statistical features using tsfresh, and processing covariates (numerical and categorical). The system trains individual base models on each window, records the best-performing model and associated covariates, then trains a RuleFit ensemble model to predict model weights based on these statistics. The ensemble combines base model predictions using probabilities from RuleFit, while a KSWIN drift detector monitors incoming data and triggers retraining when distribution changes are detected. The model accepts external covariates and automatically adds time-based features (day, month, year) for enhanced interpretability.

## Key Results
- Achieves 20% better performance than individual baseline models on real-world datasets
- Maintains comparable accuracy to non-interpretable ensemble models
- Successfully handles concept drift through automatic retraining mechanism
- Provides interpretable predictions by showing which base models are activated for different data concepts

## Why This Works (Mechanism)

### Mechanism 1: Interpretable Ensemble Selection
- Claim: EAMDrift uses interpretable ensemble selection based on statistical features and learned rules to identify the best model for each concept in the data.
- Mechanism: The model encodes different data concepts as distinct sliding windows, extracts statistical features from each window, and trains a RuleFit model to predict which base model performs best for that concept. At prediction time, the RuleFit outputs probabilities for each base model, which are combined to produce the final forecast.
- Core assumption: Different base models (e.g., Prophet, SARIMA, LSTM) are effective at modeling different data concepts, and statistical features can reliably indicate which concept is present.

### Mechanism 2: Concept Drift Detection and Adaptation
- Claim: EAMDrift automatically detects and adapts to concept drift in the data by retraining the ensemble model when distribution changes are detected.
- Mechanism: The model uses a concept drift detector (specifically KSWIN) to monitor incoming data for changes in the input-output relationship. When drift is detected, the model triggers a retraining process using the updated data to adapt to the new concept.
- Core assumption: Concept drift in the data can be detected using statistical tests on the input-output relationship, and the ensemble model can be retrained quickly enough to adapt to the new concept.
- Evidence anchors:

## Architecture Onboarding

### Component Map

### Critical Path
Data preprocessing → RuleFit ensemble training → Drift detection → Prediction

### Design Tradeoffs
- Interpretability vs. accuracy: Using RuleFit for ensemble selection prioritizes interpretability over the potential accuracy gains from a more complex, non-interpretable model.
- Retraining frequency vs. stability: Retraining too frequently can lead to instability in the model's performance, while retraining too infrequently can cause the model to miss important concept drifts.

### Failure Signatures
- High variance in base model predictions: Indicates that the RuleFit model is struggling to identify the best model for each concept.
- Frequent retraining triggered by the drift detector: Suggests that the model is experiencing frequent concept drift or that the drift detector is overly sensitive.
- Poor performance on certain data patterns: May indicate that the statistical features or covariates are not capturing important aspects of those patterns.
