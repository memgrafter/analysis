# Faster Causal Attention Over Large Sequences Through Sparse Flash Attention

## Quick Facts
- arXiv ID: 2306.01160
- Source URL: https://arxiv.org/abs/2306.01160
- Reference count: 40
- This paper introduces Sparse Causal Flash Attention (SCFA), a GPU kernel that extends FlashAttention to handle arbitrary sparsity patterns in attention matrices, achieving up to 3.3x speedup for 16k token sequences with dynamic query/key dropping.

## Executive Summary
This paper presents Sparse Causal Flash Attention (SCFA), a GPU kernel that extends FlashAttention to handle dynamic sparsity patterns in attention matrices. SCFA relaxes the constraint that causal masks must be triangular, allowing for arbitrary sparsity patterns that arise from query/key dropping and hashing-based attention. The method significantly improves runtime efficiency, particularly for longer sequences, while maintaining model quality. Experiments demonstrate 2.0x and 3.3x speedups for 8k and 16k token sequences respectively, without sacrificing perplexity.

## Method Summary
The method introduces SCFA kernels implemented in Triton language that can compute attention matrices with arbitrary sparsity patterns, including non-triangular causal masks. The approach supports two dynamic sparsity patterns: QK-sparse attention (dynamic key/query dropping) and Hash-sparse attention (dynamic hashing-based attention). For QK-sparse, the method dynamically selects which keys and queries to drop for each head, creating compact representations. For Hash-sparse, it clusters keys and queries using hash codes and computes attention within these clusters. The SCFA kernel computes attention blocks using the GPU memory hierarchy, minimizing memory I/O and avoiding materializing the full attention matrix.

## Key Results
- SCFA achieves 2.0x and 3.3x speedups for 8k and 16k token sequences with query/key dropping compared to FlashAttention
- Hash-based attention implemented with SCFA shows significant runtime improvements over standard attention
- Model perplexity is maintained across all experiments while achieving faster training speeds

## Why This Works (Mechanism)

### Mechanism 1
- Claim: SCFA can efficiently compute attention matrices with arbitrary sparsity patterns that include non-triangular causal masks
- Mechanism: SCFA extends FlashAttention by relaxing the constraint that causal masks must be triangular, using query and key indices to determine necessary sub-blocks of the attention matrix
- Core assumption: The causal structure can be expressed through a range of keys per query, maintaining information flow even with non-triangular causal masks
- Evidence anchors:
  - [abstract] "Our contribution is threefold: ... We present the SCFA GPU kernel, which relaxes the constraint that the causal mask has to be triangular."
  - [section] "We propose an extension of FlashAttention—Sparse Causal Flash Attention (SCFA)— that addresses this constraint."
- Break condition: If sparsity patterns cannot be expressed through key ranges per query, or if causal information flow is disrupted by non-triangular masks

### Mechanism 2
- Claim: Hash-based attention can be implemented efficiently using SCFA by clustering keys and queries with the same hash code
- Mechanism: Hashing keys and queries allows them to cluster together, with SCFA computing attention only within these clusters while maintaining causal masking
- Core assumption: Hashing preserves similarity information necessary for attention, and clustering is stable enough to maintain causal order
- Evidence anchors:
  - [abstract] "We show that SCFA permits to revisit the promising paradigm of dynamic hash-based attention."
  - [section] "We devise an algorithm that builds upon the fundamental idea of Reformer (Kitaev et al., 2020) to restrict the computation of the attention matrix over 'hash collision blocks'."
- Break condition: If hash function doesn't preserve similarity effectively or clustering disrupts causal order

### Mechanism 3
- Claim: Query/key dropping can be efficiently implemented using SCFA by dynamically selecting which keys and queries to include
- Mechanism: SCFA allows dynamic selection of keys and queries to drop for each head, creating compact representations and computing attention only on remaining elements
- Core assumption: Dropping subsets doesn't significantly impact model performance, and overhead of compact representations is compensated by reduced computation
- Evidence anchors:
  - [abstract] "We propose a new approach implemented with SCFA that reduces computation by dynamically selecting, for each head, keys and queries to be removed from the attention operation."
  - [section] "We propose a new approach implemented with SCFA that reduces computation by dynamically selecting, for each head, keys and queries to be removed from the attention operation, superseding existing methods that limited pruning to entire heads or entire queries/keys."
- Break condition: If dropping significantly impacts model performance or overhead outweighs computation reduction

## Architecture Onboarding

- Component map: Hash module -> Dropping module -> SCFA kernel -> Post-processing
- Critical path:
  1. Compute hash codes for keys and queries (hash-based attention) or determine which elements to drop (query/key dropping)
  2. Reshape and reorder tensors based on hash codes or dropped elements
  3. SCFA kernel computes attention on reshaped tensors, applying causal masking and sparsity constraints
  4. Post-process attention output to restore original tensor shapes
- Design tradeoffs:
  - Sparsity vs. performance: Higher sparsity reduces computation but may impact model performance
  - Hash function quality vs. speed: Better hash functions preserve similarity but may be slower to compute
  - Dropping strategy vs. overhead: More aggressive dropping reduces computation but increases overhead of creating compact representations
- Failure signatures:
  - NaNs in attention output: May indicate issues with causal masking or handling of dropped elements
  - Slow runtime: Could be due to poor hash function quality, inefficient dropping strategy, or overhead of pre/post-processing steps
  - Degraded model performance: May suggest sparsity pattern or dropping strategy is too aggressive
- First 3 experiments:
  1. Implement SCFA kernel and verify it correctly computes attention with non-triangular causal masks on synthetic data
  2. Integrate hash-based attention with SCFA and measure runtime improvements compared to FlashAttention on sequences of varying lengths
  3. Implement query/key dropping with SCFA and evaluate tradeoff between sparsity level and model performance on a language modeling task

## Limitations

- Preprocessing overhead can negate benefits for shorter sequences (under 2000 tokens)
- Assumes sparsity patterns can be expressed through key ranges per query, which may not hold for all dynamic patterns
- Hash function quality directly impacts both runtime efficiency and model performance in hash-based attention

## Confidence

- **High confidence** in core technical contribution: SCFA kernel design is mathematically sound and empirical speedups are well-documented
- **Medium confidence** in practical utility: Significant speedups for long sequences demonstrated, but overhead on shorter sequences and impact on model quality need more validation
- **Medium confidence** in generalization claims: Focus on language modeling tasks with limited evaluation on other domains
