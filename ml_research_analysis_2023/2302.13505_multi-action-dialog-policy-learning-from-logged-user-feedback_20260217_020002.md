# Multi-Action Dialog Policy Learning from Logged User Feedback

## Quick Facts
- **arXiv ID:** 2302.13505
- **Source URL:** https://arxiv.org/abs/2302.13505
- **Reference count:** 9
- **Primary result:** BanditMatch achieves 9-23% higher Inform F1 than state-of-the-art methods while maintaining task success.

## Executive Summary
This paper tackles the challenge of learning multi-action dialog policies from logged user feedback, which is more realistic and cost-effective than traditional supervised methods. The authors propose BanditMatch, a novel method that combines semi-supervised learning (SSL) and counterfactual bandit learning (CBL) to leverage both full and partial label feedback. By partitioning data into fully labeled, pseudo-labeled, and partially labeled subsets, and using feedback-enhanced thresholding (FET) to dynamically adjust confidence thresholds, BanditMatch effectively explores the action space while avoiding unrealistic action combinations through KL control.

## Method Summary
BanditMatch learns multi-action dialog policies from logged user feedback by combining semi-supervised learning and counterfactual bandit learning. The method partitions logged data into three subsets: fully labeled positive examples, pseudo-labeled confident negative examples, and partially labeled unconﬁdent negative examples. Semi-supervised learning is applied to the ﬁrst two subsets using a FixMatch-style consistency training objective, while counterfactual bandit learning handles the partially labeled subset using a pseudoinverse estimator. A feedback-enhanced thresholding module dynamically adjusts per-class confidence thresholds to improve pseudo-label selection, and KL control from the logging policy prevents unrealistic action combinations.

## Key Results
- BanditMatch outperforms state-of-the-art methods in task success rate on MultiWOZ.
- The method generates more concise and informative responses, with 9% to 23% increase in Inform F1 score.
- BanditMatch effectively leverages partial feedback to improve policy learning compared to baselines using only positive or full feedback.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** BanditMatch improves multi-action dialog policy learning by partitioning logged data into fully labeled, pseudo-labeled, and partially labeled subsets.
- **Mechanism:** The method applies semi-supervised learning (SSL) to fully and pseudo-labeled examples while using counterfactual bandit learning (CBL) for partially labeled examples. This allows the model to learn from both explicit user feedback and explore potential actions not seen during logging.
- **Core assumption:** The logging policy provides a reasonable initial coverage of the action space, and pseudo-labeling can reliably extend supervision to high-confidence predictions.
- **Evidence anchors:**
  - [abstract]: "The proposed method, BanditMatch, combines semi-supervised learning and bandit learning to effectively utilize both full and partial label feedback."
  - [section 4.1]: "The bandit data is partitioned into three parts: fully labeled positive examples DL, pseudo-labeled confident negative examples DP, and partially labeled unconﬁdent negative examples DU."
  - [corpus]: Weak - corpus does not directly address the partitioning strategy.
- **Break condition:** If the logging policy is too biased or covers too little of the action space, pseudo-labeling will generate incorrect labels, degrading performance.

### Mechanism 2
- **Claim:** Feedback-enhanced thresholding (FET) dynamically adjusts confidence thresholds per class, improving pseudo-label selection.
- **Mechanism:** FET computes per-class thresholds based on the model's performance on positive examples, scaling them by comparing correctness between positive and negative examples. This resists over- or under-selecting examples compared to fixed thresholds.
- **Core assumption:** The distribution of confidence scores for correct predictions on positive examples is representative of correct predictions on negative examples.
- **Evidence anchors:**
  - [abstract]: "It employs a feedback-enhanced thresholding strategy to dynamically adjust confidence thresholds for each class, improving the exploration of the action space."
  - [section 4.1]: "We propose the feedback-enhanced thresholding (FET) module to evaluate model performance with the feedback data and adjust the conﬁdence threshold for each individual class at each single training step."
  - [corpus]: Weak - corpus does not discuss dynamic thresholding strategies.
- **Break condition:** If the model's predictions on positive examples are unreliable, the thresholds will be misaligned, causing poor pseudo-label selection.

### Mechanism 3
- **Claim:** KL control from the logging policy prevents the learned policy from generating unrealistic action combinations.
- **Mechanism:** A KL divergence term is added to the loss to keep the learned policy close to the logging policy distribution, ensuring generated action combinations remain plausible.
- **Core assumption:** The logging policy encodes valid action combinations, and staying close to it ensures realism.
- **Evidence anchors:**
  - [section 4.2]: "To address this issue, we directly incorporate knowledge of the logging policy, which imitates expert dialog action combinations, into the training process through KL control."
  - [section 5.2]: "KL control also works by improving Inform F1 score like pseudo-labeling while less effective."
  - [corpus]: Weak - corpus does not discuss KL control in this context.
- **Break condition:** If the logging policy itself generates poor action combinations, KL control will enforce suboptimal behavior.

## Foundational Learning

- **Concept:** Semi-supervised learning (SSL)
  - **Why needed here:** Allows learning from both labeled (positive feedback) and unlabeled (negative feedback) data, crucial when only partial feedback is available.
  - **Quick check question:** What are the two main loss terms in FixMatch-style SSL and how are they computed?

- **Concept:** Counterfactual risk minimization (CRM)
  - **Why needed here:** Enables learning from partially labeled data by estimating the expected reward under the logging policy, crucial for leveraging negative feedback.
  - **Quick check question:** How does the pseudoinverse estimator in CRM use propensity scores to correct for the logging policy's bias?

- **Concept:** Multi-label classification
  - **Why needed here:** Dialog actions are independent; each can be present or absent. Treating them as multi-label rather than multi-class allows flexible action combinations.
  - **Quick check question:** In a multi-label setting, how do you compute the loss when each example can have multiple positive and negative labels?

## Architecture Onboarding

- **Component map:** Data pipeline → FET module → Partition → SSL+CBL modules → KL control → Policy update
- **Critical path:** Data → FET → Partition → SSL+CBL → KL control → Policy update
- **Design tradeoffs:**
  - Dynamic vs. fixed thresholds: Dynamic FET adapts to model performance but adds computation; fixed thresholds are simpler but less robust.
  - Pseudo-label confidence: High thresholds reduce noise but may discard useful data; low thresholds increase coverage but risk errors.
  - KL control weight: Balances exploration vs. realism; too high stifles learning, too low risks unrealistic actions.
- **Failure signatures:**
  - Low Inform F1 but high Success: Policy is generating correct actions but with redundancy.
  - High variance in evaluation metrics: Thresholding or pseudo-labeling is unstable.
  - KL divergence increasing: Policy drifting too far from logging policy, risking unrealistic actions.
- **First 3 experiments:**
  1. Run BanditMatch with fixed thresholds (no FET) to measure FET's impact on performance.
  2. Disable CBL to see how much the unconﬁdent examples contribute to learning.
  3. Remove KL control to quantify its effect on action combination realism.

## Limitations

- The effectiveness of feedback-enhanced thresholding depends on the reliability of pseudo-labeling, which is contingent on the logging policy's coverage of the action space.
- The paper does not provide ablations isolating the contribution of the semi-supervised learning component to the overall performance.
- KL control assumes that the logging policy encodes valid action combinations, but the paper does not test what happens if the logging policy is suboptimal.
