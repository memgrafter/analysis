# Conditional Online Learning for Keyword Spotting

## Quick Facts
- arXiv ID: 2305.13332
- Source URL: https://arxiv.org/abs/2305.13332
- Reference count: 0
- This paper introduces a simple but effective online continual learning method for keyword spotting (KWS) that updates a pre-trained model on-device via SGD as new data becomes available.

## Executive Summary
This paper presents COOL (Conditional Online Learning), a simple yet effective online continual learning method for keyword spotting that enables on-device model updates via SGD as new audio data becomes available. The method mitigates catastrophic forgetting by conditioning model updates on performance observed with a small hold-out set drawn from the training distribution. Through experiments with dynamic audio streams, COOL demonstrates 34% improvement in accuracy compared to naive online learning while maintaining performance on previously seen data. The results suggest that simple regularization strategies can effectively improve KWS model accuracy in changing data regimes without requiring complex architectures or extensive computational resources.

## Method Summary
The paper introduces a conditional online learning approach that updates a pre-trained small-footprint CNN keyword spotting model using stochastic gradient descent (SGD) on streaming audio data. The key innovation is conditioning model updates on performance observed with a small hold-out set from the training distribution. The method maintains separate buffers for target and non-target samples, forming balanced batches before attempting updates. Updates are only accepted if they decrease the loss on the current batch while not increasing the loss on the hold-out dataset, effectively preventing catastrophic forgetting. The approach is designed to be computationally feasible for execution on low-resource edge devices, using lightweight operations without requiring complex model architectures.

## Key Results
- COOL improves pre-trained small-footprint KWS model accuracy by 34% compared to naive online learning
- The method effectively mitigates catastrophic forgetting through conditional updates based on hold-out set performance
- Simple regularization strategies can significantly improve KWS model accuracy in changing data regimes
- The approach is computationally feasible for edge device deployment with limited resources

## Architecture Onboarding

- Component map:
  Pre-trained CNN model -> Hold-out dataset (Dv) -> Target and non-target sample buffers (St, Sn) -> Online batch formation and conditional update logic -> Loss evaluation functions for batch and hold-out data

- Critical path:
  1. Receive new sample (Xi, yi)
  2. Add to St or Sn based on label
  3. If buffers have enough samples, form balanced batch B
  4. Compute loss on B, update model via SGD
  5. Evaluate losses on B and Dv
  6. Keep update only if both conditions are met
  7. Discard used samples from buffers

- Design tradeoffs:
  - Simplicity vs. sophistication: The method favors simplicity for edge deployment over more complex continual learning techniques.
  - Fixed hold-out vs. adaptive regularization: Uses a static hold-out set rather than dynamically adjusting regularization strength.
  - Balanced batching vs. sample efficiency: Waiting for balanced buffers may delay updates if data is imbalanced.

- Failure signatures:
  - If updates are never accepted, the hold-out loss condition may be too strict or the incoming data too different.
  - If performance degrades over time, the hold-out dataset may no longer represent the original distribution.
  - If updates are too frequent, the model may overfit to recent data and forget older patterns.

- First 3 experiments:
  1. Test the conditional update logic in isolation: feed a sequence of samples and verify updates are only kept when both loss conditions are satisfied.
  2. Measure catastrophic forgetting: train on a sequence of tasks and check if performance on earlier tasks degrades without the hold-out check.
  3. Benchmark on-device feasibility: profile memory and compute usage of the online learning loop on a target edge device.
