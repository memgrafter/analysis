# Stop Pre-Training: Adapt Visual-Language Models to Unseen Languages

## Quick Facts
- arXiv ID: 2306.16774
- Source URL: https://arxiv.org/abs/2306.16774
- Authors: 
- Reference count: 10
- Primary result: Achieves SOTA on visual entailment and visual reasoning tasks for unseen languages without large parallel corpora

## Executive Summary
This paper proposes a method to adapt vision-language pre-trained models to unseen languages without requiring large parallel corpora. The approach aligns a monolingual vision-language model's text encoder with a multilingual language model using small in-domain parallel text corpus created through machine translation. This alignment is achieved by minimizing the mean squared error between contextualized token embeddings of aligned words. The adapted model is then used for zero-shot transfer to the target language. The method is evaluated on three tasks from the IGLUE benchmark: image-text retrieval, visual entailment, and visual reasoning. Results show that the proposed approach outperforms state-of-the-art multilingual vision-language models on visual entailment and visual reasoning tasks, with significant improvements on low-resource languages like Tamil and Swahili. For image-text retrieval, it performs comparably to other models except one that used additional pre-training data.

## Method Summary
The method adapts a monolingual vision-language pre-trained model (ALBEF) to unseen languages by aligning its text encoder with a multilingual language model (mBERT) using small in-domain parallel text corpus created through machine translation. The alignment minimizes mean squared error between contextualized token embeddings of aligned words. After alignment, the monolingual text encoder is swapped with the aligned multilingual encoder for zero-shot transfer to the target language. The approach is evaluated on three tasks from the IGLUE benchmark without requiring large parallel corpora or additional pre-training data.

## Key Results
- Outperforms state-of-the-art multilingual vision-language models on visual entailment and visual reasoning tasks
- Achieves significant improvements on low-resource languages like Tamil and Swahili (±4% over CCLM)
- Performs comparably to other models on image-text retrieval except one using additional pre-training data
- Demonstrates effective zero-shot transfer capability across six different languages

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Cross-lingual contextualized token embeddings alignment transfers VL model performance to unseen languages without requiring large parallel corpora.
- Mechanism: The approach aligns contextualized embeddings from the source language VL model text encoder with those from a multilingual pre-trained language model (e.g., mBERT) using small in-domain parallel text corpus created through machine translation. The alignment is achieved by minimizing mean squared error between aligned word pairs.
- Core assumption: Contextualized embeddings from mBERT and the VL model text encoder can be meaningfully aligned even when trained on different corpora and objectives.
- Evidence anchors:
  - [abstract]: "We utilize a cross-lingual contextualized token embeddings alignment approach to train text encoders for non-English languages."
  - [section 2]: "We propose CLiCoTEA, an approach to transfer a monolingual vision-language (VL) pre-trained model in one language L1...to a second language L2...by aligning a pre-trained multilingual LM...with the text encoder of the VL pre-trained model using the list of aligned tokens."
- Break condition: The alignment fails if the contextualized embeddings from the two models are not sufficiently similar in structure or if the parallel text corpus contains too much noise that prevents meaningful alignment.

### Mechanism 2
- Claim: Using small in-domain parallel text corpus created through machine translation is sufficient for alignment.
- Mechanism: The approach creates a parallel text corpus by translating the training set from the source language to the target language using neural machine translation. This corpus is then used to extract aligned tokens and perform the embedding alignment.
- Core assumption: Neural machine translation produces sufficiently accurate translations for the in-domain text, and the resulting parallel corpus contains enough meaningful word alignments for the embedding alignment to work.
- Evidence anchors:
  - [section 2]: "We utilize a cross-lingual contextualized token embeddings alignment approach to train text encoders for non-English languages...Our approach does not require image input and primarily uses machine translation, eliminating the need for target language data."
- Break condition: The alignment fails if the machine translation introduces too much noise or if the in-domain text is too specific/specialized for the translation to be accurate.

### Mechanism 3
- Claim: The adapted model can be used for zero-shot transfer to the target language.
- Mechanism: After aligning the text encoders, the adapted model can be used for zero-shot transfer by swapping the monolingual text encoder from the VL pre-trained model with the aligned multilingual text encoder.
- Core assumption: The aligned multilingual text encoder can effectively replace the monolingual text encoder in the VL model architecture without significant performance degradation.
- Evidence anchors:
  - [abstract]: "The adapted model is then used for zero-shot transfer to the target language."
  - [section 2]: "Zero-shot transfer to L2 by swapping the monolingual text encoder from the VL pre-trained model with the aligned multilingual text encoder learned in step 5."
- Break condition: The zero-shot transfer fails if the aligned text encoder does not capture the necessary information for the VL tasks or if the VL model architecture is too dependent on the specific monolingual text encoder.

## Architecture Onboarding

- Component map:
  ALBEF (VL pre-trained model) -> mBERT (multilingual language model) -> awesome-align (token alignment) -> parallel text corpus (machine translation)

- Critical path:
  1. Fine-tune the VL pre-trained model on the downstream task in the source language
  2. Create a parallel text corpus by translating the training set to the target language
  3. Extract aligned tokens from the parallel corpus
  4. Align the contextualized token embeddings of the source and target language encoders
  5. Swap the monolingual text encoder with the aligned multilingual text encoder for zero-shot transfer

- Design tradeoffs:
  - Using a small in-domain parallel corpus vs. a large general-purpose parallel corpus
  - Aligning only the text encoder vs. aligning other components of the VL model
  - Using mBERT vs. other MPLMs (e.g., XLM-R) for alignment

- Failure signatures:
  - Poor alignment between the contextualized token embeddings
  - Significant performance degradation on the downstream tasks after zero-shot transfer
  - Inability to handle certain types of input or tasks due to the alignment process

- First 3 experiments:
  1. Verify that the alignment process can be successfully performed on a small subset of the parallel corpus and that the aligned embeddings show improved similarity.
  2. Test the zero-shot transfer on a simple downstream task (e.g., image classification) to ensure that the adapted model can handle the target language.
  3. Evaluate the performance of the adapted model on the full downstream task and compare it to the baseline models to assess the effectiveness of the alignment approach.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of CLiCoTEA compare to other approaches when adapting to low-resource languages beyond Tamil and Swahili?
- Basis in paper: [explicit] The paper mentions that CLiCoTEA significantly outperforms CCLM by ±4% on low-resource languages like Tamil and Swahili.
- Why unresolved: The paper only provides results for Tamil and Swahili as examples of low-resource languages. There could be other low-resource languages where the performance difference is even more significant or less pronounced.
- What evidence would resolve it: Conducting experiments with a wider range of low-resource languages and comparing the performance of CLiCoTEA to other approaches would provide a more comprehensive understanding of its effectiveness.

### Open Question 2
- Question: Can CLiCoTEA be effectively applied to generation tasks that require a multilingual text decoder?
- Basis in paper: [inferred] The paper mentions that CLiCoTEA is currently not applicable to generation tasks where a multilingual text decoder is needed to generate text in unseen languages.
- Why unresolved: The paper does not explore the potential of adapting CLiCoTEA for generation tasks. It would be interesting to investigate if the approach can be extended to handle such tasks.
- What evidence would resolve it: Conducting experiments to adapt CLiCoTEA for generation tasks and evaluating its performance compared to other approaches would provide insights into its applicability in this domain.

### Open Question 3
- Question: How does the performance of CLiCoTEA compare to the Translate-Test baseline for high-resource languages?
- Basis in paper: [explicit] The paper mentions that current multilingual VL models, including CLiCoTEA, still do not surpass the Translate-Test baseline on the tasks from the IGLUE benchmark.
- Why unresolved: The paper does not provide specific performance comparisons between CLiCoTEA and the Translate-Test baseline for high-resource languages. It would be valuable to understand the gap in performance and identify areas for improvement.
- What evidence would resolve it: Conducting experiments to compare the performance of CLiCoTEA and the Translate-Test baseline for high-resource languages would provide insights into the effectiveness of CLiCoTEA in this context.

## Limitations
- Limited evaluation scope: Only three tasks from IGLUE benchmark across six languages
- Machine translation dependency: Entire approach relies on NMT quality, especially problematic for low-resource languages
- Token alignment quality: Uses awesome-align but doesn't analyze alignment quality variations or corpus size sensitivity
- Architecture constraints: Tested only with ALBEF, doesn't establish generalizability to other VL architectures

## Confidence
- High confidence: The core methodology of aligning contextualized embeddings between text encoders is sound
- Medium confidence: The claim that small parallel corpora are sufficient for alignment is supported but needs more comparative analysis
- Low confidence: The assertion that this approach is "stop pre-training" is somewhat misleading as it still requires fine-tuning and alignment training

## Next Checks
1. **Translation quality analysis**: Conduct human evaluation of machine-translated sentences for low-resource languages (Tamil, Swahili) to quantify translation quality and correlate with downstream task performance.

2. **Corpus size ablation study**: Systematically vary the size of the parallel corpus used for alignment (10%, 25%, 50%, 100%) and measure performance degradation to establish minimum viable corpus size.

3. **Cross-architecture validation**: Apply the same alignment methodology to a different VL architecture (e.g., CLIP or LXMERT) and evaluate on the same tasks to test generalizability.
