# Performance-Preserving Event Log Sampling for Predictive Monitoring

## Quick Facts
- arXiv ID: 2301.07624
- Source URL: https://arxiv.org/abs/2301.07624
- Reference count: 40
- Key outcome: Up to 50x faster training while maintaining comparable accuracy for next activity and remaining time prediction

## Executive Summary
This paper addresses the computational inefficiency of machine learning-based predictive process monitoring by proposing an instance selection procedure that samples training process instances. The method preserves variant information and selects representative cases based on data attribute distributions, achieving significant training speed improvements while maintaining prediction accuracy. Evaluated on three real-life event logs using LSTM and XGBoost for next activity and remaining time prediction, the approach demonstrates up to 50x faster training while preserving accuracy metrics.

## Method Summary
The proposed method employs instance selection to sample training process instances while preserving variant information and data attribute distributions. For each variant in the event log, the method computes distributions of different data attributes and selects representative cases based on these distributions. The sampling is performed using three strategies: unique (preserves all variants), division (retains cases proportionally), and logarithmic (reduces case count exponentially). The method is evaluated using LSTM and XGBoost models for next activity and remaining time prediction tasks on three real-life event logs.

## Key Results
- Achieved up to 50x faster training speed while maintaining comparable accuracy
- For next activity prediction, F1-score remained similar (0.79-0.82) between sampled and full logs
- For remaining time prediction, MAE and RMSE were preserved across different sampling methods

## Why This Works (Mechanism)

### Mechanism 1
Sampling reduces training time by removing redundant process traces while preserving predictive accuracy. The method retains at least one instance from each variant and prioritizes cases based on data attribute distributions, ensuring the sampled subset represents the original log's diversity. Core assumption: Variants encode sufficient predictive information, and their frequency distributions can be approximated with fewer cases if representative ones are selected. Break condition: If selected cases no longer represent data attribute distributions, accuracy degrades sharply.

### Mechanism 2
Logarithmic and division-based sampling strategies preserve predictive performance by maintaining variant diversity. The sampling functions control how many cases per variant are retained, ensuring all variants are present in the sampled log. Core assumption: Sequence models rely on variant patterns, so preserving all variants ensures model robustness. Break condition: Oversampling removes too many infrequent variants, causing accuracy drops in imbalanced datasets.

### Mechanism 3
Predictive accuracy remains stable because models trained on sampled logs generalize similarly to those trained on full logs. By sampling proportionally to variant frequency, the model sees a representative distribution of cases, so learned patterns transfer well to unseen data. Core assumption: The sampled training distribution approximates the original, so model generalization is preserved. Break condition: When target attributes depend more on non-variant data, insufficient cases lead to higher bias and lower accuracy.

## Foundational Learning

- Concept: Event log structure (cases, variants, activities)
  - Why needed here: Sampling operates on cases grouped by variants; understanding this structure is essential for implementing the selection logic
  - Quick check question: In a log with 3 variants, if variant A has 10 cases, B has 5, and C has 2, how many unique variants are there?

- Concept: Feature extraction for predictive monitoring
  - Why needed here: The sampling method only affects training data; features must be extracted identically from sampled and full logs for fair comparison
  - Quick check question: If a case has activities ⟨a,b,c⟩ and we extract partial sequences, what features are generated for next activity prediction?

- Concept: Machine learning training time vs dataset size
  - Why needed here: The speedup claim depends on empirical relationship between log size and training duration for LSTM/XGBoost
  - Quick check question: If doubling dataset size increases training time by 1.8×, what speedup factor do you expect when reducing size by half?

## Architecture Onboarding

- Component map: Event log parser → Variant extractor → Attribute distribution calculator → Case sorter → Sampler (logarithmic/division/unique) → Output sampled log
- Critical path: Variant extraction → Attribute distribution → Case sorting → Sampling selection (order matters for representativeness)
- Design tradeoffs:
  - Sampling strategy: Logarithmic (fastest reduction) vs division (preserves all variants) vs unique (preserves variant set only)
  - Attribute selection: Using more attributes increases sorting complexity but improves representativeness
  - Sampling granularity: Case-level vs event-level sampling (case-level preserves variant integrity)
- Failure signatures:
  - Accuracy drop > 10% from baseline → likely oversampling removed critical variants
  - Training time unchanged → sampling ratio too high, no effective reduction
  - Model bias increases → insufficient cases per variant for robust learning
- First 3 experiments:
  1. Run full training on original log (baseline accuracy, training time)
  2. Apply division(k=2) sampling, extract features, train, compare accuracy and speedup
  3. Apply logarithmic(k=3) sampling, repeat training, compare accuracy and speedup to identify break point

## Open Questions the Paper Calls Out

- What are the specific event log characteristics that make one sampling method more suitable than another, and can these characteristics be automatically detected to recommend optimal sampling parameters? The paper acknowledges the need to understand the relationship between event log characteristics and sampling parameters but does not provide a systematic analysis or automated detection method.

- How does the proposed sampling approach perform with streaming event data where the underlying process may continuously evolve, and what mechanisms can be implemented to adapt sampling strategies in real-time? The current evaluation is based on static event logs, and the paper does not explore the dynamic adaptation of sampling strategies as new data arrives or process behavior changes over time.

- What is the optimal balance between feature selection and instance selection for predictive process monitoring, and how do these two reduction strategies interact to affect overall model performance and training efficiency? While the paper focuses on instance selection, it does not explore the combined effects of feature selection and instance selection, or determine whether one approach is more effective than the other for different prediction tasks.

## Limitations
- Evaluation relies on only three real-life event logs, limiting generalizability across diverse process domains
- The 50x speedup claim is based on specific sampling ratios that may not translate to all process types
- The method's effectiveness depends heavily on variant preservation, which may not hold for logs with many rare variants

## Confidence
- Sampling speed improvement claims: High - directly measured and reproducible
- Accuracy preservation claims: Medium - supported by experiments but limited to three datasets
- Variant preservation necessity: High - clearly demonstrated through controlled experiments
