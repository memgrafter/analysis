# Revisiting Machine Translation for Cross-lingual Classification

## Quick Facts
- **arXiv ID**: 2305.14240
- **Source URL**: https://arxiv.org/abs/2305.14240
- **Reference count**: 16
- **Primary result**: Stronger MT systems and addressing training-inference mismatch can substantially improve translate-test performance in cross-lingual classification

## Executive Summary
This paper re-examines machine translation (MT) as a baseline for cross-lingual classification, challenging the assumption that multilingual models are always superior. The authors demonstrate that by using stronger MT systems (NLLB 3.3B) and mitigating the mismatch between training on original text and inference on translated text, translate-test approaches can perform substantially better than previously assumed. However, they find that the optimal approach varies significantly across different tasks, with translate-test excelling at simpler classification tasks while struggling with complex reasoning tasks. The paper identifies multiple sources of cross-lingual transfer gap and shows that the effectiveness of different approaches depends heavily on task characteristics.

## Method Summary
The authors evaluate three main approaches for cross-lingual classification: translate-test (translating test data to English and using monolingual models), translate-train (translating training data to target languages and using multilingual models), and zero-shot (using multilingual models without translation). They employ NLLB 3.3B as the MT system with both beam search and nucleus sampling, and experiment with document-level fine-tuning of the MT model on back-translated downstream data. For adaptation, they implement round-trip translation of training data. The evaluation uses 6 classification datasets (XNLI, PAWS-X, MARC, XCOPA, XStoryCloze, EXAMS) with English monolingual models (RoBERTa, DeBERTa) and multilingual model (XLM-R), measuring classification accuracy across all languages and runs.

## Key Results
- Translate-test with strong MT (NLLB 3.3B) achieves substantial improvements over previous baselines
- Document-level fine-tuned NLLB consistently outperforms vanilla NLLB across most benchmarks
- The optimal approach (translate-test vs translate-train vs zero-shot) is highly task-dependent
- Simpler tasks like sentiment analysis (MARC) benefit more from translate-test, while complex reasoning tasks (XStoryCloze) perform better with translate-train
- Training data adaptation through round-trip translation helps mitigate distribution shift in translate-test

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Using a stronger MT system in translate-test improves accuracy by reducing translation errors and information loss
- Mechanism: Stronger MT systems generate more accurate and fluent translations, preserving more semantic content from the original text and reducing the gap between training on human-generated English text and inference on machine-translated text
- Core assumption: Translation quality directly correlates with downstream task performance
- Break condition: If the downstream task is highly sensitive to translation errors, even a strong MT system may not fully mitigate performance loss

### Mechanism 2
- Claim: Adapting the MT system to mimic the style and structure of the training data improves translate-test performance
- Mechanism: Fine-tuning the MT model on back-translated downstream training data teaches it to generate translations that are more similar in style and structure to the original training data
- Core assumption: The mismatch between human-generated and machine-translated text style/structure is a significant source of performance degradation
- Break condition: If training data is highly diverse or requires strict adherence to original meaning, style adaptation may introduce unwanted biases

### Mechanism 3
- Claim: Training the model on back-translated data reduces the distribution shift between training and inference in translate-test
- Mechanism: By translating training data into a target language and back into English, the model is exposed to data that resembles the machine-translated inference data
- Core assumption: The distribution shift between human-generated and machine-translated text is a major factor in performance degradation
- Break condition: If back-translation introduces significant noise or artifacts, this approach may degrade performance

## Architecture Onboarding

- **Component map**: NLLB 3.3B (MT system) -> RoBERTa/DeBERTa/XLM-R (pretrained models) -> XNLI/PAWS-X/MARC/XCOPA/XStoryCloze/EXAMS (datasets) -> Fine-tuning pipeline -> Evaluation metrics

- **Critical path**:
  1. Select and prepare the dataset
  2. Fine-tune the pretrained model on the original or augmented training data
  3. Translate the test data using the MT system
  4. Run inference on the translated test data
  5. Evaluate and analyze the results

- **Design tradeoffs**:
  - MT System Choice: Stronger MT systems may improve accuracy but increase computational cost
  - Fine-tuning Strategy: Training on original data preserves quality but may suffer from distribution shift; training on augmented data mitigates shift but may introduce noise
  - Translation Level: Sentence-level translation is faster but may lose context; document-level translation preserves context but is slower

- **Failure signatures**:
  - Significant performance drop when using machine-translated data compared to human-generated data
  - Inconsistent results across different tasks or languages
  - Degradation in performance when using stronger MT systems (indicating task-specific sensitivity to translation quality)

- **First 3 experiments**:
  1. Compare translate-test performance using different MT systems (e.g., vanilla NLLB vs. fine-tuned NLLB) on a simple task like sentiment analysis (MARC)
  2. Evaluate the impact of training data adaptation (back-translation) on translate-test performance using a task with high translation sensitivity (e.g., XCOPA)
  3. Analyze the sources of cross-lingual transfer gap by comparing zero-shot, translate-train, and translate-test approaches on a task with complex reasoning requirements (e.g., XStoryCloze)

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the quality of machine translation affect cross-lingual classification performance across different tasks and language pairs?
- Basis in paper: The paper extensively discusses the impact of machine translation quality on translate-test and translate-train approaches, showing that it varies significantly across tasks like XCOPA, XNLI, MARC, etc.
- Why unresolved: While the paper identifies trends, it doesn't provide a comprehensive model for predicting MT quality impact across arbitrary task-language combinations
- What evidence would resolve it: Systematic experiments measuring performance degradation across a wide range of MT quality levels and language pairs for diverse task types

### Open Question 2
- Question: Are there specific linguistic or task characteristics that make certain types of cross-lingual classification tasks more suitable for translate-test versus translate-train approaches?
- Basis in paper: The paper identifies that tasks requiring commonsense or factual knowledge benefit more from translate-test, while shallower tasks like sentiment analysis work better with translate-train, but doesn't fully explain the underlying mechanisms
- Why unresolved: The paper identifies patterns but doesn't establish a theoretical framework for predicting approach suitability based on task characteristics
- What evidence would resolve it: Development of a predictive model based on linguistic complexity, domain specificity, and other task features that determines optimal approach

### Open Question 3
- Question: How can we effectively mitigate the distribution shift between original and machine-translated data beyond the techniques explored in this paper?
- Basis in paper: The paper addresses this issue through document-level fine-tuning and round-trip translation but acknowledges limitations and suggests room for improvement
- Why unresolved: The proposed solutions are task-specific and don't provide a general framework for addressing the distribution shift problem
- What evidence would resolve it: Development and validation of new techniques that can generalize across different task types and language pairs, with measurable improvements in cross-lingual classification performance

## Limitations

- Evaluation is limited to 6 classification tasks, which may not represent the full diversity of cross-lingual classification problems
- The paper does not extensively explore the computational cost trade-off of using stronger MT systems versus performance gains
- The exact contribution of each factor to cross-lingual transfer gap remains unclear due to interconnected nature of translation quality, data distribution, and task complexity

## Confidence

**High Confidence**: The empirical finding that stronger MT systems improve translate-test performance is well-supported by experimental results across multiple benchmarks. The observation that translate-test can outperform translate-train on certain tasks is robust, as demonstrated by consistent improvements on MARC and XNLI.

**Medium Confidence**: The claim that "the optimal approach is highly task dependent" is supported by the data but requires further validation. While the paper shows different approaches work best for different tasks, the underlying reasons for these differences are not fully explained.

**Low Confidence**: The assertion that "translate-test deserves more attention as a baseline" is a recommendation rather than an empirical finding. The paper provides evidence that translate-test can be competitive, but does not conclusively prove it should replace multilingual models as the default approach for all cross-lingual classification tasks.

## Next Checks

1. **Task Complexity Analysis**: Conduct a systematic study across a wider range of tasks with varying complexity levels to better understand when translate-test outperforms translate-train. Include tasks requiring different types of reasoning (logical, causal, commonsense) and analyze whether translation quality requirements scale with task complexity.

2. **Cost-Benefit Evaluation**: Measure the computational cost (latency, memory usage) of stronger MT systems and compare it against performance gains. Calculate the accuracy improvement per unit of computational overhead to determine the practical viability of translate-test approaches in resource-constrained settings.

3. **Generalization Across Languages**: Test the proposed approaches across a more diverse set of languages, particularly focusing on low-resource languages where translation quality may be more variable. Examine whether the performance patterns observed for high-resource languages hold when translation quality degrades.
