# Zero-Shot Listwise Document Reranking with a Large Language Model

## Quick Facts
- arXiv ID: 2305.02156
- Source URL: https://arxiv.org/abs/2305.02156
- Reference count: 7
- Key outcome: LRL outperforms zero-shot pointwise rerankers by 6 points nDCG@10 on TREC datasets and 15 points on MIRACL

## Executive Summary
This paper introduces a listwise reranking approach using large language models (LLMs) that directly generates a reordered list of document identifiers given a query and candidate documents. Unlike traditional pointwise methods that score documents independently, LRL leverages the LLM's ability to attend to all candidate documents simultaneously through self-attention. The method demonstrates significant improvements over existing zero-shot rerankers on both English web search datasets and multilingual retrieval tasks.

## Method Summary
The method uses GPT-3 to perform listwise reranking by prompting it to directly output an ordered list of document identifiers based on relevance to the query. For long candidate lists exceeding the model's input capacity, a progressive reranking strategy with a sliding window approach is employed. The model is prompted with the query, candidate documents, and an instruction to sort the documents by relevance, then outputs the document IDs in ranked order. This seq2seq approach naturally leverages the LLM's cross-document attention capabilities.

## Key Results
- LRL achieves 6 points higher nDCG@10 than the previous best zero-shot reranker on TREC web search datasets
- On MIRACL multilingual retrieval, LRL improves over BM25 by 15 points nDCG@10 on average
- The approach generalizes well across languages including Chinese, Swahili, and Yoruba
- LRL can also serve as a final-stage reranker to improve the top-ranked results of a pointwise method

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The listwise reranking approach allows the model to attend to all candidate documents simultaneously, enabling better relative relevance judgments than pointwise methods.
- Mechanism: By taking multiple documents as input and generating a reordered list of document identifiers, the model can leverage cross-document attention to understand the relative importance of each document to the query.
- Core assumption: The transformer architecture's self-attention mechanism can effectively capture inter-document relationships when all candidates are presented together.

### Mechanism 3
- Claim: The progressive reranking strategy effectively handles input length limitations while still improving the top-ranked results.
- Mechanism: By using a sliding window approach that re-ranks subsets of documents and promotes the most relevant ones, the method approximates full listwise ranking even for long candidate lists.
- Core assumption: Re-ranking smaller windows of documents and promoting the top results will converge to a good overall ranking, even if perfect ordering is not achieved.

## Architecture Onboarding

- Component map: Query -> Candidate documents -> LLM Reranker -> Ordered list of document IDs
- Critical path:
  1. Retrieve candidate documents using a first-stage retriever (e.g., BM25)
  2. Format the query and candidates according to the prompt template
  3. Send the prompt to the LLM
  4. Parse the LLM's output to extract the ordered document IDs
  5. Return the ranked list

- Design tradeoffs:
  - Listwise vs. Pointwise: Listwise leverages inter-document relationships but requires more input tokens and may be slower
  - Progressive reranking: Improves efficiency for long lists but may not achieve perfect ordering
  - Prompt complexity: More detailed prompts may improve output quality but increase token usage and cost

- Failure signatures:
  - Incorrect output format: The model may not follow the prompt structure, requiring prompt redesign
  - Suboptimal rankings: If the model fails to capture inter-document relationships, rankings may be similar to pointwise approaches
  - Input length errors: Exceeding the model's token limit will cause failures, necessitating progressive reranking

- First 3 experiments:
  1. Compare listwise vs. pointwise reranking on a small dataset to validate the core mechanism
  2. Test progressive reranking with different window sizes to find the optimal balance of accuracy and efficiency
  3. Evaluate the impact of prompt structure on output quality and consistency

## Limitations
- The approach relies heavily on prompt engineering, with performance potentially sensitive to prompt structure
- Progressive reranking introduces complexity that may affect reproducibility
- The study focuses primarily on zero-shot settings, leaving questions about few-shot adaptation and domain transfer unanswered

## Confidence
- High Confidence: The core claim that listwise reranking outperforms pointwise methods by leveraging inter-document attention is well-supported by experimental results across multiple datasets.
- Medium Confidence: The generalizability to multilingual retrieval is demonstrated but based on a limited number of languages and datasets.
- Low Confidence: The robustness of the progressive reranking strategy across different candidate list characteristics and its optimal parameter settings remain under-explored.
