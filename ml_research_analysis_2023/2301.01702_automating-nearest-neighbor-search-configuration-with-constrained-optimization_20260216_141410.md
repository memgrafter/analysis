# Automating Nearest Neighbor Search Configuration with Constrained Optimization

## Quick Facts
- arXiv ID: 2301.01702
- Source URL: https://arxiv.org/abs/2301.01702
- Reference count: 40
- One-line primary result: Constrained optimization-based approach generates ANN hyperparameter tunings very close to the speed-recall Pareto frontier

## Executive Summary
This paper addresses the challenge of tuning hyperparameters for quantization-based approximate nearest neighbor (ANN) search algorithms. The authors propose a constrained optimization-based approach that takes desired search cost or recall as input and generates tunings very close to the speed-recall Pareto frontier. The core method involves deriving theoretically-grounded models for recall and search cost, and using Lagrange multipliers to optimize these metrics. Experiments on million-scale and billion-scale datasets show that the proposed technique achieves leading performance, outperforming grid search and black-box optimizers.

## Method Summary
The method uses constrained optimization with Lagrange multipliers to find optimal hyperparameter settings for quantization-based ANN algorithms. It constructs a convex loss function based on per-quantization recall statistics and a linear cost model, then optimizes this function subject to search cost constraints. The approach requires a query sample to compute proxy metrics, and relies on the convexity of the loss function and the linearity of the cost model to enable efficient optimization.

## Key Results
- On the Glove1M benchmark, the method's tunings are almost identical to optimal grid-searched settings
- On billion-scale datasets, the approach achieves superior speed-recall tradeoffs compared to other methods
- The method generalizes well to new queries not seen during optimization

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The Lagrange multiplier optimization efficiently finds near-optimal hyperparameter settings by exploiting convexity and the piecewise nature of the Pareto frontier.
- Mechanism: The method constructs a convex loss function based on per-quantization recall statistics and a linear cost model. It then uses Lagrange multipliers to optimize this function subject to search cost constraints. The convexity allows efficient binary search over the finite set of relevant Lagrange multiplier values.
- Core assumption: The per-quantization recall loss functions are convex or can be made convex through convex hull approximation, and the search cost model is linear.
- Evidence anchors:
  - [abstract]: "Our technique takes just a desired search cost or recall as input, and then generates tunings that, empirically, are very close to the speed-recall Pareto frontier"
  - [section]: "Because the objective function is a sum of m functions, each a convex hull defined by n points, the Pareto frontier itself will be piecewise, composed of at most nm points"
  - [corpus]: No direct evidence; this is a theoretical claim
- Break condition: If the per-quantization loss functions are highly non-convex or the search cost model is significantly non-linear, the optimization may not find near-optimal solutions.

### Mechanism 2
- Claim: The proxy metrics for recall and search cost accurately predict the actual performance of the ANN index.
- Mechanism: The method derives theoretically-grounded models for recall and search cost based on single-layer candidate set statistics. These models are validated empirically to have high correlation with actual recall and throughput measurements.
- Core assumption: The single-layer candidate set statistics are good proxies for the multi-layer search process, and the search cost model captures the dominant factors affecting query latency.
- Evidence anchors:
  - [abstract]: "tuning these parameters has traditionally been a manual process, demanding in-depth knowledge of the underlying search algorithm"
  - [section]: "In Figure 4, we take the DEEP1B hyperparameter tunings used above in Section 5.2 and plot their respective modeled recalls against empirical recall@10, and modeled search costs against measured reciprocal throughput"
  - [corpus]: No direct evidence; this is an empirical validation claim
- Break condition: If the proxy metrics poorly predict actual performance on a new dataset or ANN algorithm, the optimization will optimize the wrong objective.

### Mechanism 3
- Claim: The method generalizes well to new queries not seen during optimization.
- Mechanism: The optimization uses statistics computed from a sample of representative queries to tune the ANN index. These statistics are assumed to be representative of the overall query distribution, leading to good generalization.
- Core assumption: The query sample is representative of the overall query distribution and large enough to capture the necessary statistics.
- Evidence anchors:
  - [abstract]: "Our technique takes just a desired search cost or recall as input, and then generates tunings that, empirically, are very close to the speed-recall Pareto frontier"
  - [section]: "We test generalization capability by randomly splitting the 104 queries in the DEEP1B dataset into two equal-sized halves Q1 and Q2. Then we compare the resulting Pareto frontiers of training on Q1 and testing on Q2 (out-of-sample), versus training and testing both on Q2 (in-sample)"
  - [corpus]: No direct evidence; this is an empirical validation claim
- Break condition: If the query sample is not representative or too small, the optimization may overfit to the sample and generalize poorly to new queries.

## Architecture Onboarding

- Component map: ANN index -> query sample -> proxy metric computation -> constrained optimization -> hyperparameter settings
- Critical path: The critical path is: build ANN index -> compute proxy metrics from query sample -> run constrained optimization -> use resulting hyperparameters. The proxy metric computation and constrained optimization are the most computationally intensive steps.
- Design tradeoffs: The method trades off some accuracy in the proxy metrics for computational efficiency. It also assumes the query sample is representative, which may not always hold. The optimization assumes convexity, which may not hold for all ANN algorithms.
- Failure signatures: If the optimization fails to find good hyperparameters, it may be due to non-representative query samples, non-convex loss functions, or inaccurate proxy metrics. If the proxy metrics are inaccurate, the optimization will optimize the wrong objective.
- First 3 experiments:
  1. Verify the proxy metrics accurately predict recall and throughput on a small dataset with known optimal hyperparameters.
  2. Test the optimization on a dataset with a simple ANN algorithm to verify it finds near-optimal hyperparameters.
  3. Test the generalization of the optimization by using a query sample and testing on held-out queries.

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions, but it does acknowledge limitations in extending the approach to non-quantization-based ANN algorithms and the need for the user to pick the VQ codebook size.

## Limitations
- The method's generalizability to diverse datasets and ANN algorithms is uncertain.
- The assumption of convexity for the loss functions and linearity for the cost model may not hold for all real-world scenarios.
- The quality of the query sample is critical, and a non-representative sample could lead to suboptimal tuning.

## Confidence
- High confidence: The overall approach of using constrained optimization for ANN tuning is sound and well-supported by the theoretical framework and empirical results.
- Medium confidence: The proxy models for recall and search cost are likely accurate for the tested datasets and ANN algorithms, but their generalizability to other scenarios is uncertain.
- Low confidence: The assumption of convexity and linearity, while theoretically justified, may not hold for all real-world datasets and ANN algorithms, potentially limiting the method's effectiveness.
