# LMGQS: A Large-scale Dataset for Query-focused Summarization

## Quick Facts
- arXiv ID: 2305.13086
- Source URL: https://arxiv.org/abs/2305.13086
- Authors: 
- Reference count: 19
- Key outcome: LMGQS enables state-of-the-art zero-shot and supervised performance on multiple QFS benchmarks through fine-tuning

## Executive Summary
This paper introduces LMGQS, a large-scale dataset for query-focused summarization created by converting four generic summarization datasets using InstructGPT to generate hidden queries for each summary sentence. LMGQS contains over 1.1 million document-query-summary triplets covering diverse document types and query formats. The authors demonstrate that finetuning a BART model on LMGQS enables state-of-the-art zero-shot and supervised performance on multiple existing QFS benchmarks, showcasing the dataset's quality and diversity.

## Method Summary
The authors create LMGQS by converting four generic summarization datasets (CNN/DailyMail, XSUM, SAMSum, and DialogSum) into query-focused format. For each summary sentence, they use InstructGPT with one-shot prompting to generate a query that captures the information need behind that sentence. This produces over 1.1 million document-query-summary triplets. They then finetune a BART model on LMGQS by concatenating document and query as input and training it to generate the summary. The model is evaluated on existing QFS benchmarks in both zero-shot and supervised settings.

## Key Results
- LMGQS achieves state-of-the-art zero-shot performance on multiple QFS benchmarks
- Finetuning on LMGQS enables strong supervised performance on QFS tasks
- The dataset covers diverse document types and query formats, enabling generalization

## Why This Works (Mechanism)

### Mechanism 1
- Claim: InstructGPT can recover "hidden queries" that capture the information needs behind generic summary sentences
- Mechanism: By prompting InstructGPT with a document, summary, and one-shot example of query generation, the model generates queries that reflect the information requirements of the original summary writer
- Core assumption: Each summary sentence implicitly answers a specific information need that can be expressed as a query
- Evidence anchors: [abstract], [section], [corpus]
- Break condition: If the summary sentences don't correspond to specific information needs, or if InstructGPT cannot infer those needs from the document-summary pairs

### Mechanism 2
- Claim: Finetuning a language model on LMGQS enables strong zero-shot QFS performance on unseen benchmarks
- Mechanism: The model learns to condition on both document and query to generate summaries that satisfy the query's information requirements, generalizing from LMGQS to other QFS datasets
- Core assumption: The diversity and scale of LMGQS provides sufficient coverage of query types and document domains to enable generalization
- Evidence anchors: [abstract], [section], [corpus]
- Break condition: If the target QFS benchmarks have query types or document domains not well-represented in LMGQS

### Mechanism 3
- Claim: Query unification via LMGQS finetuned models can convert diverse query formats into natural questions
- Mechanism: A BART model finetuned to generate queries from document-summary pairs can transform non-natural queries into natural question format, enabling LMGQS to be applied zero-shot
- Core assumption: The model learns a general mapping from any query format to natural questions when trained on LMGQS
- Evidence anchors: [section], [corpus]
- Break condition: If the transformation requires more than document and summary context, or if the model cannot generalize to query formats very different from those in LMGQS

  - Quick check question: What properties of the source datasets enable effective conversion to query-focused format?

  - Why needed here: LMGQS finetuned models need to perform well on unseen QFS benchmarks without additional training

## Architecture Onboarding

- Component map: Generic summarization datasets -> InstructGPT query generation -> LMGQS construction -> BART finetuning -> Zero-shot QFS performance
- Critical path: Document + Summary -> InstructGPT query generation -> LMGQS -> BART finetuning -> Zero-shot QFS performance
- Design tradeoffs:
  - One-shot vs few-shot vs zero-shot prompting: Tradeoff between quality and cost in query generation
  - Wh-queries vs yes/no queries: Different coverage of information needs and summarization patterns
  - Single vs multi-document training: LMGQS focuses on single documents for simplicity, requiring iterative approaches for multi-doc scenarios
- Failure signatures:
  - Low ROUGE scores on target benchmarks: May indicate query generation quality issues or insufficient diversity in LMGQS
  - High stance/relevance accuracy but low ROUGE: May indicate summaries answer queries but lack informativeness
  - Query unification failure: May indicate target query formats are too different from LMGQS patterns
- First 3 experiments:
  1. Generate queries using different example counts (0, 1, 3, 5) to find optimal tradeoff
  2. Compare wh-query vs yes/no query generation on downstream QFS performance
  3. Test query unification on a held-out subset of LMGQS to validate the approach before applying to external benchmarks

## Limitations
- The paper lacks human evaluation of the generated queries to verify they accurately capture information needs
- Zero-shot performance comparisons don't include ablation studies to isolate the contribution of dataset scale versus query quality
- The query unification mechanism is described but not thoroughly validated on diverse query formats

## Confidence

- High confidence: The dataset construction pipeline (converting existing datasets via InstructGPT) is clearly described and reproducible
- Medium confidence: The zero-shot performance improvements are demonstrated but the extent to which they generalize beyond tested benchmarks is unclear
- Low confidence: The claim that InstructGPT can recover "hidden queries" that accurately capture original information needs lacks direct validation

## Next Checks

1. **Query quality validation**: Conduct human evaluation of 100 randomly sampled generated queries from LMGQS to assess whether they accurately represent the information needs that would have produced the original summaries
2. **Ablation study**: Compare LMGQS performance against variants with (a) fewer examples in InstructGPT prompting, (b) different query types (wh- vs yes/no), and (c) random query generation to isolate the contribution of scale vs quality
3. **Domain transfer test**: Evaluate LMGQS-finetuned models on a held-out domain (e.g., scientific articles) to assess generalization beyond the four source domains in the dataset
