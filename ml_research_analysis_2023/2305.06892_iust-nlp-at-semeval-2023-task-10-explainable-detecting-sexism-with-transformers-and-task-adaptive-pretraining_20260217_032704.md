# IUST_NLP at SemEval-2023 Task 10: Explainable Detecting Sexism with Transformers and Task-adaptive Pretraining

## Quick Facts
- arXiv ID: 2305.06892
- Source URL: https://arxiv.org/abs/2305.06892
- Reference count: 4
- F1-scores: 83% (Subtask A), 64% (Subtask B), 47% (Subtask C)

## Executive Summary
This work addresses the challenge of detecting and classifying sexist content in online environments through SemEval-2023 Task 10 on Explainable Detection of Online Sexism (EDOS). The system employs transformer-based pre-trained models (BERT, RoBERTa, DeBERTa) combined with task-adaptive pretraining and ensemble learning. Key contributions include performance analysis of different transformer models, ensemble integration, and task-adaptive pretraining on large unlabeled datasets. The approach incorporates class-weighting to handle data imbalance across subtasks.

## Method Summary
The method uses transformer-based pre-trained models with task-adaptive pretraining and ensemble learning. Class-weighting is applied to handle data imbalance. The approach involves fine-tuning pre-trained transformers on labeled datasets, with additional task-adaptive pretraining on 900,000 unlabeled sentences from Gab and Reddit using MLM and NSP objectives. An ensemble model combines multiple transformer outputs through concatenation and dense layers with dropout.

## Key Results
- F1-score of 83% for binary sexism detection (Subtask A) on test dataset
- F1-score of 64% for sexism category classification (Subtask B) on test dataset
- F1-score of 47% for fine-grained sexism vector classification (Subtask C) on test dataset
- Class-weighting significantly improved performance on imbalanced subtasks B and C
- Ensemble approaches demonstrated effectiveness in improving detection performance

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Class-weighting in the loss function improves performance on imbalanced datasets by assigning higher importance to minority classes.
- Mechanism: The model adjusts the cross-entropy loss to multiply each class's loss by a weight inversely proportional to its frequency in the training data.
- Core assumption: The minority class instances contain proportionally more signal about the task objective than majority class instances.
- Evidence anchors:
  - [abstract] "We have also explored several other strategies. On the test dataset, our system achieves F1-scores of 83%, 64%, and 47% on subtasks A, B, and C, respectively."
  - [section] "Using the DeBERTabase, task-adaptive, and ensemble models, we were able to achieve promising results in subtask A, with the best performance belonging to model DeBERTa base on the test set. For subtasks B and C, we obtained the best results on the test sets using the DeBERTabase model with class-weight."
  - [corpus] No direct evidence of class distribution analysis in corpus data.
- Break condition: When class weights become extreme (e.g., 1:100 ratio), the model may overfit to minority class examples and generalize poorly.

### Mechanism 2
- Claim: Task-adaptive pretraining on domain-specific unlabeled data improves performance by aligning the model's representations with the target task distribution.
- Mechanism: The model first pretrains on 900,000 unlabeled sentences from the same source domains (Gab and Reddit) using MLM and NSP objectives, then fine-tunes on the labeled dataset.
- Core assumption: The unlabeled data shares similar linguistic patterns and domain characteristics with the labeled data.
- Evidence anchors:
  - [abstract] "We propose a set of transformer-based pre-trained models with task-adaptive pretraining and ensemble learning."
  - [section] "We also presented a task-adaptive system in the domain of this particular task. In the above sections, we examined the essential components for ensuring the repeatability of our systems and evaluated the performance of the architectures."
  - [corpus] The corpus neighbors show similar work using pretraining strategies, but no quantitative evidence of domain alignment is provided.
- Break condition: If the unlabeled data contains significant domain drift or noise, the pretraining may introduce harmful patterns that reduce downstream performance.

### Mechanism 3
- Claim: Ensemble learning combining multiple transformer architectures captures complementary features and reduces model variance.
- Mechanism: Three pre-trained models (DeBERTa, RoBERTa, ERNIE) process the same input, their outputs are concatenated and passed through dense layers with dropout before final classification.
- Core assumption: Different transformer architectures learn different representations of the same input that are complementary rather than redundant.
- Evidence anchors:
  - [abstract] "We propose a set of transformer-based pre-trained models with task-adaptive pretraining and ensemble learning."
  - [section] "In this model, we experiment with the combination of transformer-based models. The architecture of the ensemble model is shown in Figure 4."
  - [corpus] No direct evidence from corpus data showing diversity of learned representations.
- Break condition: When individual models become too similar (e.g., same architecture with different random seeds), the ensemble provides minimal benefit over a single well-tuned model.

## Foundational Learning

- Concept: Cross-entropy loss for multi-class classification
  - Why needed here: The task requires predicting one class from multiple possible categories (2, 4, or 11 classes) in each subtask
  - Quick check question: How does cross-entropy loss handle multi-class classification differently from binary classification?

- Concept: Class imbalance handling techniques
  - Why needed here: The dataset shows significant imbalance across all three subtasks, with some categories having far fewer examples than others
  - Quick check question: What is the relationship between class frequency and the weight applied in weighted cross-entropy?

- Concept: Transformer-based model fine-tuning
  - Why needed here: Pre-trained transformers need to be adapted to the specific domain of online sexism detection rather than general language understanding
  - Quick check question: Why might fine-tuning a pre-trained model on a small dataset lead to overfitting?

## Architecture Onboarding

- Component map: Input → Tokenizer → Pre-trained Transformer (BERT/RoBERTa/DeBERTa) → Classification Head → Output. Ensemble variant adds a feature fusion layer combining multiple transformer outputs.
- Critical path: Data preprocessing → Model selection (with/without class-weight) → Hyperparameter tuning (learning rate, batch size, epochs) → Fine-tuning → Evaluation
- Design tradeoffs: Using class-weight improves minority class performance but may reduce majority class accuracy; ensemble models increase robustness but require more computational resources; task-adaptive pretraining improves domain alignment but adds training complexity.
- Failure signatures: Overfitting indicated by large gap between train and dev performance; class imbalance failure shown by consistently low F1 on minority classes; ensemble failure when individual models show high correlation in predictions.
- First 3 experiments:
  1. Baseline: Fine-tune BERT without class-weight on subtask A to establish minimum performance
  2. Class-weighting: Add class-weight to BERT and compare F1 scores on dev set for all subtasks
  3. Ensemble comparison: Train ensemble model and individual base models on subtask B to measure variance reduction

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does task-adaptive pretraining performance scale with increasing amounts of unlabeled data?
- Basis in paper: [explicit] The authors used 2 million unlabeled examples for task-adaptive pretraining and noted "it is also promising to use more data to train the task-adaptive model" in the conclusion
- Why unresolved: The paper only reports results from a single pretraining dataset size (2 million examples), without exploring performance gains from larger datasets
- What evidence would resolve it: Systematic experiments varying unlabeled dataset sizes (e.g., 1M, 2M, 5M, 10M) and reporting corresponding performance metrics for all three subtasks

### Open Question 2
- Question: What is the impact of using different ensemble combinations of transformer models on performance?
- Basis in paper: [explicit] The authors state "We tested different combinations of transformer-based models" in the ensemble section but only report results from one specific combination
- Why unresolved: The paper only presents results for the DeBERTa+RoBERTa+ERNIE ensemble without comparing to other combinations like BERT+RoBERTa or DeBERTa+BERT
- What evidence would resolve it: Comparative results showing performance of different transformer model combinations (at least 3-4 variations) for each subtask

### Open Question 3
- Question: How do different class weighting strategies affect model performance on imbalanced datasets?
- Basis in paper: [explicit] The authors used class weights calculated as "the ratio of the number of samples in each class to the total number of samples" but don't explore alternative weighting schemes
- Why unresolved: Only one class weighting approach was tested, despite noting class imbalance as a challenge and observing that "class-weight was able to significantly improve the performance"
- What evidence would resolve it: Experiments comparing different class weighting strategies (e.g., inverse frequency, focal loss, oversampling) with corresponding performance metrics

## Limitations
- Limited data availability with performance degrading significantly as task complexity increases (F1-scores drop from 83% to 47%)
- Unverified domain alignment between unlabeled pretraining data and labeled task data
- Missing ablation studies to quantify individual component contributions

## Confidence
- High confidence: Transformer-based models with class-weighting improve performance on imbalanced datasets
- Medium confidence: Task-adaptive pretraining provides domain-specific benefits
- Medium confidence: Ensemble learning captures complementary features

## Next Checks
1. Ablation study on component contributions: Train and evaluate models with individual components removed to quantify each mechanism's contribution to the 83%/64%/47% F1 scores.
2. Domain alignment verification: Compute and report KL divergence or other distributional similarity metrics between unlabeled pretraining data and labeled task data to validate the task-adaptive pretraining assumption.
3. Generalization stress test: Apply the best-performing model to an external dataset of online sexist content from different platforms (e.g., Twitter) to assess cross-domain robustness and identify potential overfitting to Gab/Reddit-specific patterns.
