# How Does Generative Retrieval Scale to Millions of Passages?
## Quick Facts
- arXiv ID: 2305.11841
- Source URL: https://arxiv.org/abs/2305.11841
- Reference count: 21
- Primary result: Generative retrieval can match BM25 on MS MARCO with synthetic queries but effectiveness plateaus with model scaling

## Executive Summary
This paper investigates how generative retrieval scales to large document collections, specifically the full MS MARCO passage ranking task with 8.8M passages. The authors find that using synthetic queries as document representations is crucial for effectiveness as corpus size grows, while other proposed methods like architectural changes are not effective when accounting for compute cost. Surprisingly, scaling model parameters improves retrieval performance initially but effectiveness plateaus beyond a certain point, with the largest model (T5-XXL, 11B parameters) actually performing worse than smaller variants. The best approach uses only synthetic queries and Naive IDs, achieving 26.7 MRR@10 with T5-XL (3B parameters), but the authors conclude that generative retrieval remains an unsolved challenge at scale requiring more fundamental advances.

## Method Summary
The paper reformulates retrieval as a seq2seq task where a single Transformer maps queries to document identifiers. They explore multiple strategies for scaling to millions of passages: (1) generating synthetic queries for each document as representations, (2) architectural modifications including embedding concatenation and using long sequence lengths, and (3) scaling model parameters from 770M to 11B. The synthetic query approach generates multiple queries per document using a T5 model, which are then used as the document representation during retrieval. All models are trained on the MS MARCO passage ranking dataset and evaluated on both in-domain (MS MARCO Dev) and out-of-domain (TREC DL 2019/2020) benchmarks.

## Key Results
- Synthetic queries as document representations are crucial for effectiveness at scale
- Architectural changes (concatenation, long sequences) do not improve performance when accounting for compute cost
- Scaling model parameters improves performance up to T5-XL (3B), but T5-XXL (11B) performs worse
- Generative retrieval can match BM25 performance (26.7 vs 27.1 MRR@10) on MS MARCO
- Effectiveness plateaus beyond certain model sizes, contrary to typical scaling expectations

## Why This Works (Mechanism)
The core insight is that traditional generative retrieval, which uses document IDs as representations, becomes ineffective at scale because ID-based representations lack semantic information. Synthetic queries provide rich semantic representations that capture document content, enabling the model to generalize better to unseen queries. This semantic information becomes increasingly important as the corpus grows, since the model needs to distinguish between more similar documents. The synthetic queries act as a bridge between the query and document spaces, allowing the generative model to leverage its strong language understanding capabilities even when retrieving from millions of passages.

- **Synthetic query generation**: Using a T5 model to generate multiple queries per document to serve as semantic representations. Why needed: ID-based representations lack semantic information at scale. Quick check: Compare retrieval effectiveness using synthetic queries vs. raw IDs.
- **Parameter scaling**: Increasing model size from 770M to 11B parameters to improve capacity. Why needed: Larger models typically show better performance on language tasks. Quick check: Track performance changes as parameters increase.
- **Dense vs sparse retrieval**: Comparing generative retrieval against traditional sparse methods like BM25. Why needed: Establishes baseline performance and practical viability. Quick check: Measure whether generative retrieval matches or exceeds BM25.
- **In-domain vs out-of-domain evaluation**: Testing on both MS MARCO Dev and TREC DL 2019/2020 benchmarks. Why needed: Assesses generalization beyond training data. Quick check: Compare performance drop between benchmarks.

## Architecture Onboarding
**Component Map**: Query Encoder -> Document Encoder -> Scoring Function -> Ranking Module
**Critical Path**: The model processes the input query, generates document identifiers (either IDs or synthetic queries), and scores them against the query representation to produce a ranked list.
**Design Tradeoffs**: The key tradeoff is between using raw document IDs (computationally efficient but semantically poor) versus synthetic queries (semantically rich but computationally expensive to generate). Another tradeoff is model size versus training/inference cost.
**Failure Signatures**: Performance degradation when scaling to millions of passages using only document IDs, lack of improvement from architectural modifications, and potential optimization issues at very large model scales.
**First Experiments**: 1) Train a baseline model using only document IDs on a small corpus to establish performance floor, 2) Generate synthetic queries for a subset of documents and measure improvement, 3) Scale model parameters incrementally to identify the point of diminishing returns.

## Limitations
- The performance drop with T5-XXL (11B parameters) may be due to optimization difficulties rather than fundamental scaling limitations
- The comparison with BM25 doesn't account for training data differences - BM25 requires no training while generative retrieval needs substantial supervised data
- The conclusions about parameter scaling are uncertain due to the unexpected performance drop at the largest scale

## Confidence
- Synthetic queries effectiveness: High confidence based on consistent experimental results
- Parameter scaling trends: Medium confidence due to contradictory results (improvement then deterioration)
- Architectural modifications ineffectiveness: Medium confidence, but compute cost considerations may mask subtle improvements
- BM25 comparison validity: Medium confidence due to training data asymmetry

## Next Checks
1. Re-run T5-XXL experiments with alternative optimization strategies (different learning rates, optimizers, or training schedules) to determine if the performance drop is due to optimization rather than scaling limitations
2. Conduct head-to-head comparisons between generative retrieval and learned sparse methods (like SPLADE) that require similar training data to isolate whether observed performance differences stem from model architecture or training methodology
3. Test the synthetic query approach on a larger corpus (beyond MS MARCO's 8.8M passages) to verify whether the effectiveness trends continue to hold at truly massive scales
