# Generative Sequential Recommendation with GPTRec

## Quick Facts
- arXiv ID: 2306.11114
- Source URL: https://arxiv.org/abs/2306.11114
- Reference count: 40
- One-line primary result: GPTRec achieves competitive results with state-of-the-art models while reducing embedding table size by 40% and supporting more flexible recommendation generation strategies.

## Executive Summary
This paper addresses two key challenges in sequential recommendation: the inefficiency of large embedding tables for item vocabularies and the limitations of Top-K recommendation strategies for complex objectives like diversity and coverage. The authors propose GPTRec, a generative model based on GPT-2 that uses a novel SVD-based tokenization method to split items into sub-tokens, reducing memory usage, and supports a Next-K recommendation strategy that generates recommendations iteratively, allowing for more flexible objectives. Experiments on the MovieLens-1M dataset show that GPTRec achieves competitive results with state-of-the-art models like SASRec while reducing embedding table size by 40% and supporting more flexible recommendation generation strategies.

## Method Summary
GPTRec is a generative sequential recommendation model built on GPT-2 architecture that addresses memory inefficiency through SVD-based tokenization and supports Next-K recommendation strategy for complex objectives. The model tokenizes items using truncated SVD decomposition of the user-item interaction matrix, quantizes the resulting embeddings into sub-item tokens, and trains using a language modeling objective with cross-entropy loss. The Next-K strategy generates recommendations iteratively, considering previously recommended items to address diversity and redundancy issues. The model was evaluated on MovieLens-1M dataset with leave-one-out strategy, comparing against SASRec and BERT4Rec using NDCG@10 and Recall@10 metrics.

## Key Results
- GPTRec achieves competitive NDCG@10 and Recall@10 results compared to SASRec and BERT4Rec
- SVD tokenization reduces GPU memory usage by 40% compared to one-token-per-item mode
- Next-K strategy enables more flexible recommendation generation, addressing diversity and redundancy issues

## Why This Works (Mechanism)

### Mechanism 1
- Claim: SVD Tokenisation reduces embedding table size while maintaining item similarity
- Mechanism: SVD decomposes the user-item interaction matrix into latent components, producing item embeddings that capture usage patterns. These embeddings are then normalised, quantised into bins, and offset per dimension to create sub-item tokens. Similar items have similar embeddings, thus similar token representations.
- Core assumption: SVD provides meaningful embeddings where similar items cluster, and quantisation preserves enough information for downstream tasks.
- Evidence anchors:
  - [abstract] "split item ids into sub-id tokens using a novel SVD Tokenisation algorithm based on quantised item embeddings from an SVD decomposition"
  - [section 4.2] "SVD Tokenisation algorithm builds a user-item interaction matrix 𝑀 and performs a truncated SVD decomposition...quantises item embeddings...each value in the quantised embeddings represents one token"
- Break condition: If item embeddings from SVD do not preserve similarity structure, quantisation will collapse distinct items into same token sequences, harming recommendation quality.

### Mechanism 2
- Claim: Cross-Entropy loss outperforms Binary Cross-Entropy for next-item prediction
- Mechanism: LM training with Cross-Entropy directly models the probability of the next token given history, aligning with the next-item prediction task. Binary Cross-Entropy treats each item as independent binary classification, which is less aligned.
- Core assumption: The shifted sequence prediction task is better modelled as a multi-class problem (next token among all possible) than as independent binary classifications.
- Evidence anchors:
  - [section 5] "GPTRec differs from SASRec by using the Cross-Entropy loss...Binary Cross-Entropy used by SASRec is a heuristic, which...underperforms compared to Cross-Entropy loss"
  - [section 6.2] "GPTRec-TopK achieves similar results to BERT4Rec and outperforms SASRec" - attributed to loss difference
- Break condition: If the dataset has extreme class imbalance or if the task requires independent scoring, Binary Cross-Entropy might be preferable.

### Mechanism 3
- Claim: Next-K strategy enables interdependent recommendations, addressing diversity and redundancy
- Mechanism: By generating recommendations iteratively, each new recommendation considers previously generated items, allowing the model to adjust scores based on what's already recommended (e.g., avoid recommending multiple similar coffee beans).
- Core assumption: The model can learn to adjust its scoring based on previously recommended items when trained appropriately.
- Evidence anchors:
  - [abstract] "generates recommendations item-by-item, considering already recommended items"
  - [section 3.2] "recommendation decides what to recommend at position 𝑘 only after generating recommendations at position 1..𝑘 − 1"
- Break condition: If the scoring function cannot effectively incorporate previous recommendations or if the computational cost is prohibitive, the benefits may not outweigh the costs.

## Architecture Onboarding

- Component map:
  - GPT-2 decoder blocks (multi-head self-attention, feed-forward, layer norm)
  - Item embedding table (or SVD-based token embeddings in multi-token mode)
  - Tokeniser (SVD-based or identity in one-token mode)
  - Loss function (cross-entropy)
  - Generation strategy (Top-K or Next-K)

- Critical path:
  1. Tokenise input sequence (SVD or identity)
  2. Embed tokens
  3. Process through Transformer decoder blocks
  4. Apply softmax to last position output
  5. Generate recommendations (Top-K: select top scores; Next-K: iterative generation)

- Design tradeoffs:
  - SVD tokenisation: Memory efficiency vs. information loss from quantisation
  - Next-K vs Top-K: Flexibility for complex objectives vs. computational cost
  - Cross-entropy vs Binary Cross-Entropy: Task alignment vs. potential implementation simplicity

- Failure signatures:
  - Poor NDCG/Recall: Could indicate SVD tokenisation losing too much information or Next-K strategy not aligned with training
  - High GPU memory usage: Likely in one-token-per-item mode with large item vocabulary
  - Slow inference: Especially with Next-K strategy due to iterative generation

- First 3 experiments:
  1. Verify SVD tokenisation produces similar items with similar token sequences on a small dataset
  2. Compare cross-entropy vs binary cross-entropy loss on a simple next-item prediction task
  3. Implement and test Top-K generation with multi-token-per-item mode, measuring memory usage and recommendation quality

## Open Questions the Paper Calls Out

## Limitations
- SVD tokenization mechanism lacks detailed implementation specifications, creating uncertainty about faithful reproduction
- Empirical evaluation is limited to a single dataset (MovieLens-1M) with relatively modest scale
- Next-K strategy's practical benefits for diversity and coverage are demonstrated only through methodology description rather than rigorous quantitative comparison

## Confidence
- **High confidence**: The core architecture using GPT-2 decoder for sequential recommendation is well-established and the memory reduction claim from SVD tokenization is mechanistically sound.
- **Medium confidence**: The empirical results showing competitive performance with SASRec and memory reduction appear valid but are limited by single-dataset evaluation and lack of ablation studies.
- **Low confidence**: The claimed advantages of Next-K strategy for diversity and coverage, and the superiority of cross-entropy loss, lack direct experimental validation.
