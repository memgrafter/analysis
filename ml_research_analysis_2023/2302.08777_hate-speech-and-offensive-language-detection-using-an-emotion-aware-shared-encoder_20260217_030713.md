# Hate Speech and Offensive Language Detection using an Emotion-aware Shared Encoder

## Quick Facts
- arXiv ID: 2302.08777
- Source URL: https://arxiv.org/abs/2302.08777
- Reference count: 28
- Key outcome: 3% performance improvement in hate speech detection using multi-task learning with emotion features

## Executive Summary
This paper proposes a multi-task learning approach for hate speech and offensive language detection that leverages emotion-aware features through a shared BERT/mBERT encoder. The method jointly trains on abusive content detection and emotional analysis tasks, using hard parameter sharing to increase data efficiency and reduce overfitting. Experimental results demonstrate a 3% performance improvement in hate speech detection over baseline models, with notable reductions in false positive errors for both tasks.

## Method Summary
The approach uses hard parameter sharing in multi-task learning, where a shared BERT/mBERT encoder is jointly trained on emotion classification and abuse detection tasks. The model incorporates external emotional features from another corpus, using Ekman's six basic emotions plus neutral. Task-specific heads are added for emotion classification and abuse detection, with the shared encoder updated via backpropagation from both tasks. The method is evaluated on English and multilingual datasets for hate speech and offensive language detection.

## Key Results
- 3% performance improvement in hate speech detection over baseline models
- Significant reduction in false positive errors for both hate speech and offensive language tasks
- MTL model achieves 98.94% true positive rate for offensive content detection
- Improvements in offensive language detection were not statistically significant

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Emotion-aware features improve hate speech detection by providing affective context that aligns with the psychological state of abusive speakers
- Mechanism: The MTL model learns shared representations between emotion categories and abusive content, leveraging the correlation between emotional states (anger, disgust, fear, sadness) and hate speech/offensive language
- Core assumption: There is a strong psychological and linguistic link between emotional expression and abusive language
- Evidence anchors: Psychology study showing correlation between speaker's emotional state and abusive speech; stylometric study demonstrating emotional features improve hate speech detection
- Break condition: If emotional signals are uncorrelated with abuse, the MTL model will not gain performance benefits

### Mechanism 2
- Claim: Hard parameter sharing in MTL reduces overfitting and increases data efficiency by forcing the model to learn a generalized representation across tasks
- Mechanism: A shared BERT/mBERT encoder is trained jointly on emotion and abuse detection tasks, with separate task-specific heads
- Core assumption: Tasks are sufficiently related so that shared representations capture useful commonalities without introducing harmful interference
- Evidence anchors: Abstract stating MTL increases data efficiency and reduces overfitting; description of hard parameter sharing architecture
- Break condition: If tasks interfere negatively, MTL performance may degrade relative to single-task models

### Mechanism 3
- Claim: The MTL model exhibits fewer false positive errors than single-task models by leveraging affective knowledge to disambiguate borderline cases
- Mechanism: Emotion analysis provides additional context that helps the model distinguish truly abusive content from non-abusive but emotionally charged text
- Core assumption: Many false positives in abuse detection arise from emotional but non-abusive language; emotion knowledge helps correct this
- Evidence anchors: Abstract noting MTL exhibits less false positive errors; results showing BERT-MTL has least misclassification error rate
- Break condition: If emotional features are noisy or poorly aligned with abuse categories, false positives may actually increase

## Foundational Learning

- Concept: Multi-task learning (MTL) vs. single-task learning (STL)
  - Why needed here: To leverage auxiliary emotion data to improve abuse detection performance and reduce overfitting on small, imbalanced datasets
  - Quick check question: What is the key architectural difference between hard and soft parameter sharing in MTL?

- Concept: Transformer-based pre-trained models (BERT/mBERT) and fine-tuning
  - Why needed here: The shared encoder is based on BERT/mBERT; understanding how fine-tuning works on downstream tasks is critical to adapting the MTL architecture
  - Quick check question: How does the shared encoder update differ in MTL vs. training two separate BERT models?

- Concept: Cross-entropy loss and weighted metrics for imbalanced data
  - Why needed here: The datasets are highly imbalanced; proper loss weighting and evaluation metrics (macro vs. weighted F1) are necessary for fair model comparison
  - Quick check question: Why is weighted F1 preferred over macro F1 for imbalanced abuse detection datasets?

## Architecture Onboarding

- Component map: Input text → Tokenizer (BERT/mBERT) → Embeddings → Shared BERT/mBERT encoder → Task-specific heads → Emotion and abuse predictions
- Critical path: 1) Tokenize and embed input text, 2) Pass through shared BERT/mBERT encoder, 3) Compute task-specific logits via heads, 4) Calculate combined loss and backpropagate, 5) Generate predictions for both tasks
- Design tradeoffs: Shared vs. separate encoders (sharing reduces parameters but risks interference), task weighting (equal weighting may not reflect task difficulty), emotion categories (using 6+neutral reduces noise vs. 27 categories)
- Failure signatures: Performance plateau or degradation in one task while the other improves, high variance in MTL vs. STL across runs, confusion matrices showing increased false positives in abuse detection
- First 3 experiments: 1) Train STL BERT baseline on hate speech detection only, 2) Train MTL BERT with emotion task and compare metrics, 3) Swap BERT for mBERT and repeat experiment

## Limitations

- The paper lacks quantitative evidence demonstrating actual correlation between emotional states and abusive language in target datasets
- Results don't include ablation studies to isolate contribution of emotion features versus other factors
- Lack of statistical significance testing for offensive language detection improvements raises questions about reliability
- Architecture's reliance on external emotion datasets introduces potential domain mismatch issues

## Confidence

- **High confidence**: Methodological soundness of MTL framework implementation
- **Medium confidence**: Reported performance improvements for hate speech detection
- **Low confidence**: Mechanism-based explanation linking emotion features to abuse detection performance

## Next Checks

1. **Correlation Analysis**: Conduct statistical analysis on target datasets to quantify actual correlation between emotion categories and abuse labels using contingency tables and chi-square tests

2. **Ablation Study**: Perform controlled experiments removing emotion features from MTL model to isolate their specific contribution and analyze changes in false positive rates

3. **Cross-Dataset Generalization**: Test MTL model on held-out test sets from different social media platforms to assess whether emotion-based improvements generalize beyond training data distribution
