# Shoggoth: Towards Efficient Edge-Cloud Collaborative Real-Time Video Inference via Adaptive Online Learning

## Quick Facts
- arXiv ID: 2306.15333
- Source URL: https://arxiv.org/abs/2306.15333
- Reference count: 26
- Primary result: Shoggoth achieves 15–20% higher accuracy than edge-only approaches while consuming 24× less uplink bandwidth than cloud-only approaches

## Executive Summary
Shoggoth addresses data drift in real-time video inference by creating an efficient edge-cloud collaborative system. The approach decouples knowledge distillation by offloading labeling to the cloud and adaptive training to edge devices, using replay memory and small batches to mitigate catastrophic forgetting and constrained edge resources. Adaptive frame sampling adjusts upload rates based on scene change, accuracy, and resource usage to improve robustness while reducing bandwidth consumption. Evaluated on object detection tasks using realistic datasets, Shoggoth demonstrates superior accuracy-bandwidth trade-offs compared to both edge-only and cloud-only approaches.

## Method Summary
Shoggoth is an edge-cloud collaborative system for real-time video inference that addresses data drift through online knowledge distillation and adaptive training. The cloud provides high-quality pseudo-labels using a complex teacher model (Mask R-CNN with ResNeXt-101), while the edge performs lightweight training on small batches with replay memory to maintain past knowledge. Adaptive frame sampling based on scene change rate, inference accuracy, and resource usage adjusts frame upload frequency to balance accuracy and bandwidth. The edge uses YOLOv4 with ResNet18 backbone for inference, and the system employs H.264 compression for efficient frame transmission.

## Key Results
- Achieves 15–20% higher accuracy than edge-only approaches on object detection tasks
- Consumes 24× less uplink bandwidth than cloud-only approaches while maintaining competitive accuracy
- Demonstrates robustness across diverse datasets (UA-DETRAC, KITTI, Waymo) with varying weather and illumination conditions

## Why This Works (Mechanism)

### Mechanism 1: Decoupled Knowledge Distillation
- Claim: Separating cloud labeling from edge training reduces bandwidth and catastrophic forgetting
- Mechanism: Cloud provides high-quality pseudo-labels; edge performs lightweight training with replay memory
- Core assumption: Cloud pseudo-labels are sufficiently accurate to guide edge adaptation
- Break condition: Domain shift or teacher model bias degrades pseudo-label quality

### Mechanism 2: Adaptive Frame Sampling
- Claim: Sampling rates adjusted by scene change, accuracy, and resource metrics improve robustness while reducing bandwidth
- Mechanism: Cloud computes scene change from teacher outputs; edge estimates accuracy and monitors resources
- Core assumption: Teacher model outputs reliably measure scene change rate
- Break condition: Teacher model failure or inaccurate accuracy estimation causes misadjustment

### Mechanism 3: Replay Memory for Catastrophic Forgetting
- Claim: Storing activations at specific layers prevents forgetting while minimizing training overhead
- Mechanism: Current batch and replay activations concatenated during training; selective weight updates preserve learned features
- Core assumption: Freezing front layers while learning after replay layer preserves low-level features
- Break condition: Replay memory aging causes stored activations to deviate from current model behavior

## Foundational Learning

- Concept: Knowledge distillation
  - Why needed here: Enables lightweight edge models to benefit from complex cloud models without transferring entire model
  - Quick check question: What is the difference between hard labels and soft labels in knowledge distillation?

- Concept: Catastrophic forgetting
  - Why needed here: Edge models must adapt to changing scenes without losing previously learned knowledge
  - Quick check question: How does replay memory help prevent catastrophic forgetting compared to elastic weight consolidation?

- Concept: Online learning
  - Why needed here: Video inference requires continuous adaptation as scenes change over time
  - Quick check question: What distinguishes online learning from offline training in terms of data availability and model updates?

## Architecture Onboarding

- Component map: Edge device (YOLOv4-ResNet18, adaptive training, replay memory) -> Frame sampling -> Compressed frame upload -> Cloud server (Mask R-CNN-ResNeXt-101, online labeling, sampling rate controller) -> Labeled frames return

- Critical path: Edge inference → Frame sampling → Compressed frame upload → Cloud labeling → Labeled frames return → Edge adaptive training → Updated edge model

- Design tradeoffs:
  - Accuracy vs bandwidth: Higher sampling rates improve adaptation but increase uplink costs
  - Training frequency vs inference performance: More frequent training improves accuracy but reduces FPS
  - Replay memory size vs storage: Larger memory better prevents forgetting but requires more edge storage

- Failure signatures:
  - Edge FPS drops below 15: Indicates training is consuming too many resources
  - mAP improvement stalls: Suggests labeling quality has degraded or replay memory is ineffective
  - Uplink bandwidth exceeds 200 Kbps: Indicates sampling rate controller is not properly adjusting rates

- First 3 experiments:
  1. Run edge-only inference on UA-DETRAC dataset and measure baseline mAP and FPS
  2. Implement cloud labeling only (no adaptive training) and measure bandwidth usage and accuracy improvement
  3. Add adaptive training with fixed sampling rate (2 fps) and compare to adaptive sampling version on bandwidth and accuracy

## Limitations
- Evaluation scope limited to object detection tasks on three datasets, raising generalizability concerns
- Implementation details for adaptive sampling parameters and replay memory management are underspecified
- Training frequency impact on inference performance is inadequately analyzed

## Confidence

**High Confidence Claims:**
- Shoggoth achieves 15-20% higher accuracy than edge-only approaches
- Shoggoth consumes 24× less uplink bandwidth than cloud-only approaches
- Decoupled architecture effectively reduces bandwidth while maintaining accuracy

**Medium Confidence Claims:**
- Adaptive frame sampling improves robustness based on scene change, accuracy, and resource usage
- Replay memory effectively prevents catastrophic forgetting during edge adaptation
- Freezing front layers while allowing full learning after replay layer preserves features

**Low Confidence Claims:**
- Cloud pseudo-labels maintain accuracy across all domain shifts
- Adaptive sampling controller maintains optimal performance across diverse scenarios
- System performance generalizes beyond tested datasets and conditions

## Next Checks

1. **Generalization Testing**: Implement Shoggoth on additional object detection datasets (COCO, Cityscapes) and non-detection tasks (semantic segmentation, pose estimation) to assess cross-task performance and validate the decoupling mechanism's effectiveness beyond the original scope.

2. **Parameter Sensitivity Analysis**: Conduct systematic experiments varying replay memory size, training frequency, and adaptive sampling parameters to quantify their impact on accuracy-bandwidth trade-offs and identify optimal configurations for different scenarios.

3. **Real-world Deployment Testing**: Deploy Shoggoth in realistic edge environments with varying network conditions (3G/4G/5G) and edge device capabilities to evaluate performance under practical constraints and validate the system's robustness to network variability.
