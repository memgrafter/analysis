# Private Training Set Inspection in MLaaS

## Quick Facts
- arXiv ID: 2305.09058
- Source URL: https://arxiv.org/abs/2305.09058
- Authors: 
- Reference count: 40
- One-line primary result: Up to 0.87 accuracy for membership inspection and up to 99.3% confidence in estimating diversity and fairness distributions

## Executive Summary
This work addresses the challenge of inspecting private training datasets in Machine Learning as a Service (MLaaS) platforms for diversity and fairness without direct data access. The authors propose a novel approach that combines shadow training techniques from membership inference with multiple instance learning to estimate origin-level metrics for membership, diversity, and fairness. By leveraging a shadow model and featurization schemes, the method enables inspectors to assess dataset properties while preserving privacy and addressing regulatory requirements.

## Method Summary
The approach involves training a shadow model with identical architecture to the target model on a proxy dataset, then using this shadow model to generate reference data by querying it with auxiliary data from various origins. The reference data is featurized using histogram-based methods, and a meta-classifier is trained to map these features to origin membership labels. This mapping is then applied to the target model's outputs to infer origin membership in the private training set. Diversity and fairness metrics are estimated by combining membership results with inter-origin similarity and behavior bias calculations.

## Key Results
- Up to 0.87 accuracy for origin membership inference in BERT-based text review polarity classification
- 99.3% confidence in estimating diversity and fairness distributions using Kolmogorov-Smirnov test
- Successful application to real-world IMDB movie review dataset with multiple data origins

## Why This Works (Mechanism)

### Mechanism 1
Shadow training combined with multiple instance learning enables origin-level membership inference without direct access to private training data. A shadow model with identical architecture to the target model is trained on a proxy dataset, then used to generate reference data by querying it with auxiliary data from various origins. The reference data is featurized using histogram-based methods, and a meta-classifier is trained to map these features to origin membership labels. This mapping is then applied to the target model's outputs to infer origin membership in the private training set.

### Mechanism 2
Inter-origin similarity can be used as a proxy for dataset diversity at the origin level. For each data origin, the average cosine similarity between samples from that origin and samples from all other origins is calculated. This inter-origin similarity is then used to estimate the overall diversity of the dataset by sampling from various origins.

### Mechanism 3
Behavior bias at the origin level can be used as a proxy for dataset fairness. For each data origin, the difference in prediction outcomes between sensitive and non-sensitive attribute groups is calculated. This behavior bias is then used to estimate the overall fairness of the dataset by sampling from various origins.

  - Why needed here: Provides a statistical measure of how well the estimated diversity and fairness metrics match the true distribution in the private training set
  - Quick check question: How does the choice of significance level affect the interpretation of the KS test results for diversity and fairness inspection?

## Architecture Onboarding

- Component map: Shadow model trainer -> Reference data generator -> Featurizer -> Meta-classifier trainer -> Origin membership inferer -> Diversity and fairness estimator

- Critical path: Shadow model training → Reference data generation → Featurization → Meta-classifier training → Origin membership inference → Diversity and fairness estimation

- Design tradeoffs:
  - Shadow model architecture: More complex architectures may better mimic the target model but require more computational resources
  - Featurization method: Histogram-based features are efficient but may lose some information compared to raw model outputs
  - Meta-classifier choice: Lighter-weight models are faster to train but may be less accurate than more complex models

- Failure signatures:
  - Low accuracy in origin membership inference: Indicates issues with shadow model training or featurization
  - Poor diversity and fairness estimation: Suggests problems with the assumptions about inter-origin similarity and behavior bias consistency

- First 3 experiments:
  1. Test the shadow model's ability to mimic the target model's behavior for a single origin with known membership
  2. Evaluate the featurization method's impact on meta-classifier accuracy for a small set of origins
  3. Assess the consistency of inter-origin similarity and behavior bias across disjoint datasets for a few origins

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How robust is the assumption that data origins maintain consistent inter-origin similarity across different datasets?
- Basis in paper: The authors state "Assumption 2. For an origin, its inter-origin similarity maintains its distribution across any disjointed dataset, which involves this origin" and validate this empirically using Kolmogorov-Smirnov test on OpenImage V6.
- Why unresolved: While the authors provide empirical validation for their specific dataset and application, they don't explore whether this assumption holds across different domains, data types, or when data collection methods vary significantly.
- What evidence would resolve it: Extensive cross-domain studies showing consistent inter-origin similarity patterns across diverse datasets and collection methods would validate this assumption broadly.

### Open Question 2
- Question: Can the inspection framework be extended to handle temporal changes in data origins over time?
- Basis in paper: The current framework assumes static data origins and doesn't address scenarios where data origins might evolve or change characteristics over time, which is common in real-world applications.
- Why unresolved: The paper focuses on a single point-in-time inspection without considering how data origins might shift, new origins might emerge, or existing origins might change their characteristics over time.
- What evidence would resolve it: Developing and validating temporal extension methods that can track and adapt to changing data origin patterns would address this limitation.

### Open Question 3
- Question: What is the optimal balance between inspector capability and inspection accuracy across different MLaaS scenarios?
- Basis in paper: The authors discuss different inspector capabilities (individuals/SMEs vs. larger enterprises vs. professional institutions) but don't provide a systematic analysis of how different capability levels affect inspection performance or establish optimal thresholds.
- Why unresolved: While the paper describes different inspector roles, it doesn't quantify the relationship between inspector resources (data access, computational power) and inspection accuracy, nor does it provide guidance on matching inspector capabilities to specific inspection requirements.
- What evidence would resolve it: Empirical studies comparing inspection accuracy across different resource-constrained scenarios and establishing performance benchmarks would provide actionable guidance for real-world deployment.

## Limitations
- Shadow model transferability may not hold for complex models or diverse datasets with significant architectural differences
- Inter-origin similarity consistency assumption may not generalize across all data types and domains
- Behavior bias generalizability may be limited for certain types of bias or sensitive attributes

## Confidence
- High confidence: The overall methodology combining shadow training and multiple instance learning for origin membership inference is well-established in the literature and theoretically sound
- Medium confidence: The extension of shadow training to estimate diversity and fairness metrics using inter-origin similarity and behavior bias is novel but relies on assumptions that may not generalize across all domains and datasets
- Low confidence: The specific experimental results, particularly the 99.3% confidence in estimating diversity and fairness distributions, may not be replicable in real-world scenarios with more complex models and diverse datasets

## Next Checks
1. Cross-architecture transferability test: Evaluate the method's performance when the shadow model's architecture differs from the target model (e.g., using a smaller BERT variant as the shadow model for a larger BERT model)
2. Domain generalization test: Apply the method to datasets from different domains (e.g., image classification, tabular data) to evaluate the generalizability of the inter-origin similarity and behavior bias assumptions across data types
3. Bias type robustness test: Extend the fairness estimation to multiple types of bias (e.g., disparate impact, equal opportunity difference) and sensitive attributes to assess the method's ability to capture various fairness metrics beyond the binary gender attribute used in the experiments
