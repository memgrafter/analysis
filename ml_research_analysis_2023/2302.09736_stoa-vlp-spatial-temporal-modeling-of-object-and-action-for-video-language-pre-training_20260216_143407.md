# STOA-VLP: Spatial-Temporal Modeling of Object and Action for Video-Language Pre-training

## Quick Facts
- arXiv ID: 2302.09736
- Source URL: https://arxiv.org/abs/2302.09736
- Reference count: 22
- Achieves 3.7 Rouge-L improvements on MSR-VTT video captioning benchmark

## Executive Summary
This paper proposes STOA-VLP, a novel video-language pre-training framework that explicitly models object trajectories and multiple action features across spatial and temporal dimensions. The key innovation is to encode temporal-aware object trajectories and spatial-temporal action features, then design two auxiliary pre-training tasks to align them with text tokens. Extensive experiments on three downstream tasks (video captioning, text-video retrieval, and video question answering) demonstrate the effectiveness of STOA-VLP, achieving significant improvements over previous approaches.

## Method Summary
STOA-VLP uses multiple Transformer-based encoders (video, text, object trajectory, spatial-temporal action, and fusion encoders) to process and align multimodal data. The framework extracts object trajectories using bounding box features across frames and multiple action features using action query tokens. Two auxiliary pre-training tasks are introduced: Object-Text Alignment (OTA) dynamically matches object trajectories with noun tokens in text using bipartite matching, while Spatial-Temporal Action Set Prediction (ASP) predicts actions from verb tokens using spatial-temporal action features. The model is pre-trained on WebVid-2M dataset with standard video-text contrastive objectives plus the two fine-grained alignment tasks.

## Key Results
- Achieves 3.7 Rouge-L improvements on MSR-VTT video captioning benchmark
- Improves accuracy by 2.9% on MSVD video question answering benchmark
- Outperforms existing approaches on text-video retrieval tasks

## Architecture Onboarding

- Component map:
  - Video Encoder -> Object Trajectory Encoder -> Fusion Encoder
  - Text Encoder -> Spatial-Temporal Action Encoder -> Fusion Encoder
  - Video Encoder -> Spatial-Temporal Action Encoder -> Fusion Encoder
  - Text Encoder -> Object Trajectory Encoder -> Fusion Encoder

- Critical path:
  1. Video and text encoders process raw inputs.
  2. Object and action encoders generate fine-grained features.
  3. Fusion encoder integrates all features for downstream tasks.
  4. Auxiliary tasks (OTA, ASP) optimize alignment during pre-training.

- Design tradeoffs:
  - Increased computational cost due to additional encoders and fine-grained modeling.
  - Improved fine-grained alignment at the expense of model complexity.
  - Tradeoff between the number of object trajectory and action tokens for optimal performance.

- Failure signatures:
  - Poor downstream task performance if object detection fails frequently.
  - Degraded alignment if text lacks clear noun or verb references.
  - Overfitting if auxiliary tasks are too restrictive.

- First 3 experiments:
  1. Ablation study: Remove object trajectory and action encoders to test baseline performance.
  2. Vary the number of object trajectory and action tokens to find optimal settings.
  3. Test downstream task performance (e.g., video captioning) with and without OTA/ASP tasks.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of STOA-VLP change with different numbers of object trajectory tokens and action tokens during pre-training?
- Basis in paper: [explicit] The paper shows results for varying numbers of object trajectory tokens (5, 10, 20, 30) and action tokens (2, 4, 8) in Figure 3, indicating that 4 action tokens and 20 object trajectory tokens yield the best performance on MSR-VTT retrieval.
- Why unresolved: The paper only evaluates a limited range of token numbers and specific downstream tasks. It's unclear if these optimal numbers generalize across different datasets and tasks.
- What evidence would resolve it: Comprehensive ablation studies testing a wider range of token numbers across multiple downstream tasks and datasets would provide clearer guidance on optimal settings.

### Open Question 2
- Question: How does STOA-VLP's performance compare when pre-trained on instructional videos (like HowTo100M) versus web-collected videos (like WebVid-2M)?
- Basis in paper: [explicit] The paper mentions that HowTo100M contains 136M noisy pre-training data while WebVid-2M contains 2.5M web-collected video-text pairs, but only evaluates on WebVid-2M due to computational constraints.
- Why unresolved: The paper does not compare the effectiveness of different pre-training datasets, leaving uncertainty about whether the choice of dataset significantly impacts performance.
- What evidence would resolve it: Direct comparison of STOA-VLP pre-trained on HowTo100M versus WebVid-2M across multiple downstream tasks would clarify the impact of pre-training data choice.

### Open Question 3
- Question: How does STOA-VLP's fine-grained modeling of object trajectories and actions contribute to its performance compared to methods that only use overall video-text alignment?
- Basis in paper: [explicit] The paper proposes two auxiliary tasks (OTA and ASP) for fine-grained alignment and claims they build a coarse-to-fine cross-modal connection, but does not provide a detailed ablation showing the isolated impact of these fine-grained components.
- Why unresolved: While the paper shows that incorporating object trajectories and action modeling improves performance, it's unclear how much of the improvement comes specifically from the fine-grained modeling versus other factors.
- What evidence would resolve it: Detailed ablation studies isolating the effects of the fine-grained modeling components (object trajectory encoder, spatial-temporal action encoder, OTA task, ASP task) would clarify their individual contributions.

## Limitations

- The paper lacks detailed implementation specifications for the object trajectory and spatial-temporal action encoders, making faithful reproduction challenging.
- The core assumptions about noun-to-object and verb-to-action mappings are not empirically validated against diverse video-text pairs where such correspondences may be ambiguous or missing.
- The computational complexity trade-offs of the additional encoders and auxiliary tasks are not quantified, leaving open questions about scalability to larger video datasets.

## Confidence

- **High Confidence**: The general framework design combining object trajectories and action features with auxiliary alignment tasks is technically sound and follows established transformer-based multimodal pre-training principles.
- **Medium Confidence**: The specific implementation details for OTA and ASP tasks using bipartite matching are plausible but lack validation on edge cases where text lacks clear noun/verb references.
- **Low Confidence**: The claims about complementary information in object trajectories and action features are not directly supported by ablation studies showing what happens when either component is removed.

## Next Checks

1. **Ablation Study**: Remove the object trajectory and spatial-temporal action encoders from the pre-training pipeline and evaluate downstream task performance to quantify the actual contribution of these fine-grained features.

2. **Edge Case Analysis**: Test the OTA and ASP tasks on video-text pairs where nouns are abstract concepts or verbs are ambiguous (e.g., "the feeling of victory" or "something happened") to assess robustness of the matching algorithms.

3. **Computational Complexity Evaluation**: Measure training time and memory usage with different numbers of object trajectory and action tokens to establish the practical scalability limits of the proposed architecture.
