# Large Language Models are Strong Zero-Shot Retriever

## Quick Facts
- arXiv ID: 2304.14233
- Source URL: https://arxiv.org/abs/2304.14233
- Authors: 
- Reference count: 38
- Key outcome: LameR achieves best retrieval qualities on most datasets compared to other zero-shot competitors, surpassing LLM-based retrievers with in-context demonstrations and outperforming baseline retrievers fine-tuned on full datasets.

## Executive Summary
This paper introduces LameR, a zero-shot large-scale retrieval method that uses only a large language model (LLM) and BM25 without any learnable retrieval models. The approach augments queries by having an LLM generate potential answers based on BM25-retrieved candidates, then uses these augmented queries for final retrieval. The method demonstrates state-of-the-art performance on multiple benchmark datasets while remaining simple and efficient compared to other zero-shot approaches.

## Method Summary
LameR works by first using BM25 to retrieve top-M candidates for a given query, then prompting an LLM (gpt-3.5-turbo by default) with the query and candidates to generate N candidate answers. The original query is concatenated with all generated answers to form an augmented query, which is then used with BM25 to retrieve final results. The method requires no labeled data, no training of retrieval models, and relies solely on the frozen LLM's ability to generate useful query expansions based on retrieved candidates.

## Key Results
- Outperforms all other zero-shot competitors on most benchmark datasets
- Surpasses LLM-based retrievers that use in-context labeled demonstrations
- Outperforms baseline retrievers that were fine-tuned on full training datasets
- Achieves strong retrieval quality while remaining simple and efficient

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Retrieval quality improves because LLM generates query augmentations that incorporate in-collection patterns and genres.
- Mechanism: The LLM receives retrieved candidates as part of its prompt, allowing it to learn domain-specific query patterns even when candidates are incorrect.
- Core assumption: LLM can effectively extract patterns from incorrect candidates and apply them to generate more precise queries.
- Evidence anchors: [abstract] "As such, the LLMs are prone to distinguish and imitate the candidates... while summarizing or/and re-writing new ones with internal knowledge" [section] "Regardless of correct or wrong candidates, they can at least provide demonstrations about in-domain patterns and knowledge" [corpus] Weak - no direct evidence that incorrect candidates actually help, only that they "at least make LLM aware of in-collection patterns"
- Break condition: If LLM fails to extract useful patterns from candidates, performance may degrade.

### Mechanism 2
- Claim: Non-parametric lexicon-based retrieval (BM25) enables transparent LLM output usage without performance bottlenecks.
- Mechanism: BM25 directly uses LLM-generated text for retrieval without converting to embeddings, bypassing the bottleneck of weak self-supervised retrievers.
- Core assumption: LLM outputs contain sufficient lexical overlap with relevant documents for BM25 to work effectively.
- Evidence anchors: [abstract] "LameR makes the retrieval procedure transparent to the LLM, thus circumventing the performance bottleneck" [section] "In contrast to model-specific compressed and/or latent embeddings... LameR makes the retrieval procedure transparent to the LLM" [corpus] Weak - assumption about lexical overlap effectiveness not directly tested
- Break condition: If LLM-generated queries lack lexical overlap with relevant documents, BM25 will fail.

### Mechanism 3
- Claim: Simple QA prompts with retrieved candidates are sufficient for effective query augmentation without complex prompt engineering.
- Mechanism: The prompt structure of "question + candidates + instruction" is simple yet effective for eliciting useful query expansions.
- Core assumption: Basic prompt structure works across different retrieval tasks without task-specific customization.
- Evidence anchors: [section] "We did not carefully craft the prompts in this work but directly adapted the prompts in (Gao et al., 2022)" [section] "we use gpt-3.5-turbo as the LLM to perform answer generation by default" [corpus] Moderate - same prompts used across multiple datasets with varying success
- Break condition: If different tasks require different prompt structures, this simple approach will fail.

## Architecture Onboarding

- Component map: Query → BM25 retrieval → Candidate list (M documents) → Query + candidates → LLM prompt → Multiple answer generations (N outputs) → Original query + N answers → Concatenated augmented query → BM25 retrieval → Final results
- Critical path: Query augmentation (LLM + candidates) → BM25 retrieval with augmented query
- Design tradeoffs:
  - Simple BM25 vs. learned retriever: Faster, no training, but relies on lexical overlap
  - Few candidates (M) vs. many: Faster but potentially less effective
  - Few generations (N) vs. many: Faster but potentially less diverse
- Failure signatures:
  - Low nDCG scores: LLM not generating useful augmentations
  - High variance across queries: Candidates not providing useful patterns
  - Performance similar to BM25 alone: LLM augmentations not adding value
- First 3 experiments:
  1. Run baseline: Original query through BM25, measure nDCG
  2. Test with M=1, N=1: One candidate, one generation, measure improvement
  3. Sweep M and N: Find optimal tradeoff between performance and computation cost

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of LameR scale with the size of the retrieval collection (D)? Are there diminishing returns or potential bottlenecks as the collection size increases?
- Basis in paper: Inferred. The paper evaluates LameR on benchmark datasets but does not explicitly explore the impact of varying collection sizes.
- Why unresolved: The paper focuses on demonstrating LameR's effectiveness on existing benchmark datasets, without investigating its scalability to larger collections. Understanding the relationship between collection size and performance is crucial for real-world applications.
- What evidence would resolve it: Conducting experiments on collections of varying sizes, from small to extremely large, would provide insights into LameR's scalability. Analyzing the retrieval quality (e.g., MAP, nDCG) and computational efficiency across different collection sizes would reveal potential bottlenecks and scaling patterns.

### Open Question 2
- Question: How does LameR handle queries with multiple intents or ambiguous phrasing? Does the candidate-prompted answer generation effectively disambiguate such queries?
- Basis in paper: Inferred. The paper mentions that queries can be "intent-ambiguous" but does not delve into how LameR addresses this issue specifically.
- Why unresolved: Real-world queries often contain multiple intents or ambiguous phrasing, which can pose challenges for retrieval systems. It's unclear whether LameR's candidate-prompted answer generation is robust enough to handle such queries effectively.
- What evidence would resolve it: Evaluating LameR on datasets containing queries with multiple intents or ambiguous phrasing would provide insights into its disambiguation capabilities. Analyzing the generated answers and their relevance to the different intents within the queries would reveal the effectiveness of LameR's approach.

### Open Question 3
- Question: How does LameR perform in cross-lingual retrieval scenarios? Can it effectively retrieve relevant documents in languages other than the language of the query?
- Basis in paper: Inferred. The paper focuses on monolingual retrieval and does not explore cross-lingual capabilities.
- Why unresolved: With the increasing need for cross-lingual information access, understanding LameR's performance in cross-lingual scenarios is important. It's unclear whether the LLM-based query augmentation and lexicon-based retrieval are effective across different languages.
- What evidence would resolve it: Evaluating LameR on cross-lingual retrieval benchmarks, where queries and documents are in different languages, would provide insights into its cross-lingual capabilities. Analyzing the retrieval quality and comparing it to other cross-lingual retrieval methods would reveal its effectiveness in this domain.

## Limitations

- The claim that incorrect candidates still help LLM generate better queries through pattern imitation lacks direct empirical validation
- The assumption that LLM-generated queries will have sufficient lexical overlap with relevant documents for BM25 to work effectively is not thoroughly tested
- The simple QA prompt structure may not be optimal for all retrieval tasks and is not systematically compared against more complex prompt engineering approaches

## Confidence

- High confidence: BM25-based transparent retrieval mechanism and overall retrieval performance on benchmark datasets
- Medium confidence: Effectiveness of simple QA prompts across different retrieval tasks
- Low confidence: The claim that incorrect candidates still help LLM generate better queries through pattern imitation

## Next Checks

1. **Pattern Extraction Test**: Design an experiment comparing LLM performance when given only correct vs. only incorrect candidates to directly measure how much learning occurs from wrong examples.

2. **Lexical Overlap Analysis**: Quantify the actual lexical overlap between LLM-generated augmented queries and relevant documents to validate the BM25 assumption.

3. **Prompt Structure Sensitivity**: Systematically test different prompt formats (beyond the simple QA template) to determine if the current approach is optimal or just one of many viable options.
