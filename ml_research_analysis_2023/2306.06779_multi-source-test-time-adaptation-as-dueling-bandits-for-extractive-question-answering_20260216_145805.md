# Multi-Source Test-Time Adaptation as Dueling Bandits for Extractive Question Answering

## Quick Facts
- arXiv ID: 2306.06779
- Source URL: https://arxiv.org/abs/2306.06779
- Reference count: 17
- Key outcome: Co-UCB outperforms standard UCB in multi-source test-time adaptation for extractive QA by enabling pairwise model collaboration

## Executive Summary
This paper addresses the challenge of adapting multiple pre-trained models to an unknown target domain during inference time using only unlabeled test data and user feedback. The authors cast this as a stochastic decision-making problem, comparing two frameworks: multi-armed bandit learning (UCB) and multi-armed dueling bandits (Co-UCB). Their key contribution is Co-UCB, which selects pairs of models at each step and collaboratively updates them using the better prediction from each pair, enabling weaker models to benefit from stronger ones. Experiments across six QA datasets show that Co-UCB achieves superior F1 scores compared to UCB and strong baselines.

## Method Summary
The proposed method involves K pre-trained models from distinct domains that are continually updated with unlabeled test data from an unknown target domain. The adaptation process uses either UCB (selecting one model per batch with binary feedback) or Co-UCB (selecting two models per batch with preference feedback). Co-UCB's core innovation is collaborative updating: at each time step, it selects a pair of models, obtains their predictions, and updates both models using the better prediction from the pair. The model selection in Co-UCB is based on maximizing a confidence bound that considers both the average rewards and the number of times each pair has been selected. Both methods use simulated user feedback based on index-wise F1 scores between predicted and annotated answer spans.

## Key Results
- Co-UCB consistently outperforms UCB across all six QA datasets tested
- Co-UCB achieves higher F1 scores while using fewer adaptation steps compared to UCB
- The collaborative update mechanism in Co-UCB enables weaker models to benefit from stronger ones
- Co-UCB shows better robustness to noise in user feedback compared to UCB

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Co-UCB outperforms UCB because it leverages pairwise model collaboration during adaptation.
- Mechanism: At each time step, Co-UCB samples a pair of models (i, j) and uses the better of their predictions to update both models jointly. This allows the weaker model to benefit from the stronger one's prediction.
- Core assumption: The better prediction in a pair is more likely to be closer to the true answer, providing useful training signal even for the weaker model.
- Evidence anchors:
  - [abstract] "Compared to multi-armed bandit learning, the dueling framework allows pairwise collaboration among K models, which is solved by a novel method named Co-UCB proposed in this work."
  - [section 5.1] "With the predictions from model i and j, we obtain the better one ⟨y∗(1)t , y∗(2)t ⟩... Then we jointly update the two models by the loss: Lt = (ri + rj)⊤L(y∗(1)t , y∗(2)t )/|Bt|"
- Break condition: If user feedback becomes highly unreliable (e.g., noise rate > 0.5), the collaborative updates may reinforce incorrect predictions, degrading performance.

### Mechanism 2
- Claim: Co-UCB reduces exploration variance by focusing on the most promising model pairs.
- Mechanism: Co-UCB selects pairs ⟨i, j⟩ that maximize (¯µi + ¯µj)/2 + sqrt(2 ln(N)/ni,j), where ¯µi and ¯µj are average rewards. This balances exploitation of strong models with exploration of uncertain pairs.
- Core assumption: The average reward ¯µi accurately reflects how often model i wins duels against other models.
- Evidence anchors:
  - [section 5.1] "The combination ⟨i, j⟩ selected at time t should maximize (¯µi + ¯µj)/2 + sqrt(2 ln(N)/ni,j)"
  - [section 6.4] "For Co-UCB, the models 0 and 2 are the best and second best model respectively, so its combination ⟨0, 2⟩ is chosen most of the time."
- Break condition: If initial reward estimates are misleading (e.g., due to early noise), Co-UCB might over-commit to suboptimal pairs.

### Mechanism 3
- Claim: Preference feedback enables effective collaboration without requiring labeled data.
- Mechanism: Users compare two model predictions and indicate preference, which serves as a reward signal. This allows models to be trained using only unlabeled test data.
- Core assumption: User preference correlates with answer quality and can be simulated using index-wise F1 scores.
- Evidence anchors:
  - [section 5.1] "For the chosen models i and j at time t, the batch of input Bt ~ X will be given to them independently... Then the users need to compare the two predictions to indicate a preference"
  - [section 5.1] "We use the index-wise F1 value as the quality score, which calculates the F1 score over the predicted indices and the annotated indices"
- Break condition: If the simulated preference feedback doesn't match actual human judgment, the model updates may not improve real-world performance.

## Architecture Onboarding

- Component map: Pre-trained models -> Co-UCB module -> Adaptation loop -> Feedback simulator -> Model updates -> Evaluation module

- Critical path:
  1. Receive batch of test data
  2. Co-UCB selects model pair (i, j)
  3. Both models generate predictions
  4. Simulated preference feedback generated
  5. Both models updated using better prediction
  6. Repeat until adaptation budget exhausted
  7. Select best-performing model for inference

- Design tradeoffs:
  - Pairwise collaboration vs. single-model adaptation: Collaboration improves performance but doubles inference cost per step
  - Preference feedback vs. binary feedback: Preference provides richer signal but requires more user effort
  - Noise tolerance: Co-UCB is more robust to noise but performance degrades with high noise rates

- Failure signatures:
  - High variance in F1 scores during adaptation
  - Slow convergence to optimal model pair selection
  - Degradation in performance with increased noise rates

- First 3 experiments:
  1. Compare Co-UCB vs UCB on a single target domain with low noise to verify collaboration benefit
  2. Test noise sensitivity by varying noise rate from 0 to 0.5 and measuring performance degradation
  3. Analyze model pair selection patterns to understand how Co-UCB identifies strong collaborations

## Limitations

- The method's performance degrades with high noise rates in user feedback (above 0.5)
- The approach is evaluated only on extractive QA tasks and may not generalize to other NLP tasks
- The scalability of the method with a large number of source models is not thoroughly explored
