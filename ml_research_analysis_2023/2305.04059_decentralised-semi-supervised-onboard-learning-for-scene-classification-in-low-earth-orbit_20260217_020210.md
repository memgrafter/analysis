# Decentralised Semi-supervised Onboard Learning for Scene Classification in Low-Earth Orbit

## Quick Facts
- arXiv ID: 2305.04059
- Source URL: https://arxiv.org/abs/2305.04059
- Reference count: 9
- Key outcome: Trained semi-supervised neural network achieving 91.51% accuracy with only 5 labeled examples per class on satellite constellation

## Executive Summary
This study demonstrates the feasibility of training a semi-supervised neural network for scene classification on a satellite constellation using the MSMatch method and decentralized learning. The authors simulate training across 8 satellites in a Sentinel-like orbit, incorporating operational constraints like power budgets and communication windows through PASEOS. Using only 5 labeled examples per class from the EuroSAT RGB dataset, the model achieves over 91% accuracy within 24 hours across three different communication scenarios, proving that effective onboard learning is possible with minimal labeled data.

## Method Summary
The approach combines MSMatch semi-supervised learning with decentralized federated averaging across a satellite constellation. Each satellite trains locally using EfficientNet-lite0 as the backend model on the EuroSAT RGB dataset, with only 5 labeled examples per class distributed across satellites and the remainder unlabeled. PASEOS simulates operational constraints including power budgets, thermal management, and communication windows based on orbital dynamics. MPI facilitates parameter exchanges during communication windows, with three scenarios tested: ground station relay, inter-satellite swarm communication, and federated relay via EDRS-C. The training runs for 24 hours with accuracy and resource usage monitored throughout.

## Key Results
- Achieved 91.51% accuracy using only 5 labeled examples per class within 24 hours
- Performance scales with labeled data: 96.2% accuracy with 100 labeled examples per class
- Swarm configuration transfers 1168 MB total data, while ground station approach uses only 186 MB

## Architecture Onboarding

- Component map: Satellites with ML hardware -> PASEOS for constraint simulation -> MPI for distributed training -> Ground stations/EDRS-C for federated learning -> EuroSAT RGB dataset

- Critical path:
  1. Load labeled and unlabeled data onto satellites
  2. Initialize local models
  3. Train locally with MSMatch
  4. Exchange model parameters via communication windows
  5. Aggregate models in federated scenarios
  6. Monitor accuracy and operational constraints

- Design tradeoffs:
  - Labeled data quantity vs. model accuracy
  - Communication frequency vs. power consumption
  - Model complexity vs. training time and resource usage
  - Centralized vs. decentralized learning approaches

- Failure signatures:
  - Low accuracy despite training (insufficient labeled data or ineffective semi-supervised learning)
  - Inconsistent model performance across satellites (communication issues or data distribution problems)
  - Excessive power consumption or thermal issues (inefficient training or inadequate constraint modeling)

- First 3 experiments:
  1. Test MSMatch training with varying numbers of labeled examples to find the minimum required for acceptable accuracy.
  2. Simulate training under different power and thermal constraints to identify critical thresholds.
  3. Compare centralized vs. decentralized learning approaches to determine the optimal architecture for the given scenario.
