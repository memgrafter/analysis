# Hierarchical Attention Encoder Decoder

## Quick Facts
- arXiv ID: 2306.01070
- Source URL: https://arxiv.org/abs/2306.01070
- Reference count: 11
- Achieves 1.37 bits per dimension on WikiText-103 and 4.05 bits per dimension on Imagenet-32

## Executive Summary
This paper introduces the Hierarchical Attention Encoder-Decoder (HAED) architecture that independently encodes input sub-sequences without global context, processes these sequences using a lower-frequency model, and decodes outputs at the original data frequency. The key innovation is interpreting the encoder as an implicitly defined embedding matrix and using sampled softmax estimation to train without a high-frequency decoder. This approach significantly reduces memory requirements and improves training wall-clock time while achieving state-of-the-art performance on character-level WikiText-103 and pixel-level Imagenet-32.

## Method Summary
The HAED architecture consists of three main components: an MLP encoder that independently processes non-overlapping sub-sequences, a Transformer main model that operates at lower frequency on the encoded outputs, and an LSTM decoder (used only in final training phase) that generates at original data frequency. The model is trained using an Implicit Embedding Matrix (IEM) algorithm where the encoder's outputs are treated as implicit embeddings, and negative samples from the same batch are used to approximate the softmax normalizing factor. This allows training without explicitly computing the exponentially large embedding matrix.

## Key Results
- Achieves 1.37 bits per dimension on WikiText-103 compared to 1.52 for baseline HRED
- Achieves 4.05 bits per dimension on Imagenet-32 compared to 4.17 for baseline HRED
- Replacing LSTM with Transformer in main model provides significant performance gains without major compute increase
- Reduces memory requirements by avoiding explicit high-frequency decoder computation

## Why This Works (Mechanism)

### Mechanism 1
The encoder can be interpreted as an implicit embedding matrix, allowing training without a high-frequency decoder. By encoding sub-sequences independently without global context, the encoder effectively defines a fixed mapping from each possible subsequence to a vector representation. This creates an embedding matrix where each row corresponds to a unique subsequence.

### Mechanism 2
Replacing LSTM with Transformer in the main model significantly improves performance without major compute increase. Transformers can capture long-range dependencies more effectively than LSTMs, and since the main model operates at lower frequency, the computational overhead is manageable.

### Mechanism 3
Using sampled softmax with batch negative samples provides effective training signal despite bias. The softmax normalizing factor cannot be computed due to exponential embedding matrix size, so negative samples from the same batch are used to approximate it.

## Architecture Onboarding

- Component map: Input sequence -> Sub-sequence splitter -> 2-layer MLP encoder -> Transformer main model -> (Final phase) LSTM decoder -> Output sequence
- Critical path: 1. Input sequence split into non-overlapping sub-sequences 2. Encoder processes each sub-sequence independently 3. Main Transformer processes the resulting lower-frequency sequence 4. (Final phase) Decoder trained to generate original frequency outputs
- Design tradeoffs:
  - Independent encoding vs global context: Faster but potentially loses some information
  - MLP encoder vs RNN: Much faster computation but less expressive
  - Implicit embedding vs explicit embedding: Saves memory but requires specialized training algorithm
  - Lower frequency main model: Better performance but requires hierarchical decomposition
- Failure signatures:
  - Poor performance on tasks requiring global context across sub-sequences
  - Difficulty with very long sub-sequences that exceed the main model's capacity
  - Training instability when batch negative sampling provides insufficient signal
- First 3 experiments:
  1. Implement the independent sub-sequence encoding and verify the output sequence has the expected length reduction
  2. Train just the encoder + main model pipeline using the implicit embedding matrix loss and measure performance
  3. Add the decoder in the final training phase and compare end-to-end performance to baseline models

## Open Questions the Paper Calls Out

### Open Question 1
How does the performance of the HAED model scale with larger model sizes, especially in comparison to multi-billion parameter models used for state-of-the-art results? The paper mentions that experiments were conducted using relatively small models and raises questions about the potential scalability of the approach.

### Open Question 2
How sensitive is the HAED architecture to errors within learned hierarchies compared to hard-coded hierarchies? The paper uses hard-coded hierarchies and acknowledges that numerous techniques for learning hierarchies exist, but none are flawless or demonstrate consistency on par with hard-coded hierarchies.

### Open Question 3
How can the negative sampling method in the Implicit Embedding Matrix (IEM) algorithm be improved to better align with the true loss and further enhance performance? The paper mentions that the way negative samples are selected is probably suboptimal and suggests that carefully crafted negative samples could improve the alignment of the pretraining loss with the true loss.

## Limitations

- The exponential growth of the embedding matrix with sub-sequence length remains a fundamental limitation
- The negative sampling approach using only batch samples is acknowledged as suboptimal
- The paper doesn't explore how performance degrades when sub-sequences exceed 12 characters and require word-level tokenization

## Confidence

**High Confidence**: The core architectural innovation of interpreting the encoder as an implicit embedding matrix is well-supported by the experimental results, with statistically significant performance improvements on both benchmark datasets.

**Medium Confidence**: The claim that replacing LSTM with Transformer provides significant performance gains without major compute increase is supported by results but lacks detailed computational complexity analysis.

**Low Confidence**: The assertion that the IEM training algorithm can effectively train without a high-frequency decoder relies heavily on the assumption that batch negative sampling provides sufficient learning signal, which the paper acknowledges as a simplification.

## Next Checks

1. **Scaling Analysis**: Test the HAED architecture on datasets requiring longer sub-sequences (e.g., 24+ characters) to understand how performance degrades as the embedding matrix grows exponentially.

2. **Negative Sampling Evaluation**: Implement and compare alternative negative sampling strategies (e.g., noise-contrastive estimation, importance sampling) against the batch sampling approach.

3. **Computational Overhead Analysis**: Conduct detailed wall-clock time measurements comparing HAED with different main model architectures (LSTM vs Transformer) at various sequence lengths.
