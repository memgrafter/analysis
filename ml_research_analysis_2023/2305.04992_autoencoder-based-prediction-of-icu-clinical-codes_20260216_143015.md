# Autoencoder-based prediction of ICU clinical codes

## Quick Facts
- arXiv ID: 2305.04992
- Source URL: https://arxiv.org/abs/2305.04992
- Reference count: 18
- Primary result: Adversarial autoencoders with structured data achieved F1=0.32 and MAP=0.25 on MIMIC-III clinical code prediction

## Executive Summary
This paper addresses the challenge of predicting missing clinical codes in ICU patient records using machine learning. The authors frame the task as a recommendation problem and evaluate various autoencoder architectures (vanilla, denoising, variational, and adversarial) on the MIMIC-III dataset. The study compares these approaches to two baseline methods: item co-occurrence and SVD matrix factorization. The primary finding is that adversarial autoencoders, particularly when using both clinical codes and structured patient data as input, achieved the best performance with an F1 score of 0.32 and MAP of 0.25.

## Method Summary
The study uses the MIMIC-III dataset containing 49,002 admissions with clinical codes and structured patient data (vital signs, demographics). The task is framed as a recommendation problem where a sparse matrix represents patient-code relationships. Five autoencoder architectures are implemented and compared: vanilla, denoising, variational, and adversarial autoencoders, along with two baselines (item co-occurrence and SVD). Models are trained using 5-fold cross-validation with 80/10/10 train/validation/test splits, and evaluated on 50% randomly sampled code subsets. The input configurations include clinical codes only and clinical codes plus structured patient data.

## Key Results
- Adversarial autoencoders achieved the best performance (F1=0.32, MAP=0.25) when using both clinical codes and structured patient data
- Including structured patient data (vital signs, demographics) improved predictive performance across most autoencoder types
- The recommendation problem framing and matrix factorization approach outperformed baseline methods
- Performance varied across autoencoder architectures, with adversarial models showing superior results

## Why This Works (Mechanism)

### Mechanism 1
Adversarial autoencoders outperform other autoencoder types because they can model complex, non-normal prior distributions of clinical codes. AAEs use a discriminator to match the aggregated posterior of the latent code to a chosen prior, allowing more flexible distribution modeling than VAEs which penalize KL divergence from a normal prior. Core assumption: Clinical code distributions are better approximated by flexible priors than by normal distributions.

### Mechanism 2
Including structured patient data (vital signs, demographics) improves predictive performance by providing additional context for code prediction. Supplementary information provides signal about patient state that correlates with missing codes, helping the model learn more discriminative representations. Core assumption: Vital signs and demographics contain predictive information about which clinical codes should be present.

### Mechanism 3
Framing clinical code prediction as a recommendation problem better captures the sparse, relational nature of clinical coding. The recommendation framework naturally handles the sparsity of the patient-code matrix and the co-occurrence patterns between codes. Core assumption: Clinical codes exhibit recommendation-like patterns (item-item relationships, sparsity) rather than being independent classification targets.

## Architecture Onboarding

- Component map: MIMIC-III extraction -> code filtering (≥50 occurrences) -> patient demographics and vital signs aggregation -> model training (5-fold CV) -> hyperparameter tuning -> performance evaluation
- Critical path: MIMIC-III data extraction → code and patient filtering → structured data aggregation → model training and evaluation → performance comparison
- Design tradeoffs: Including structured data adds information but increases dimensionality and computational cost; adversarial autoencoders are more complex than vanilla but potentially more expressive; 50% code masking for evaluation is arbitrary and may not reflect real-world missingness patterns
- Failure signatures: Performance degradation when adding structured data indicates noisy or irrelevant features; VAE underperformance relative to other autoencoders suggests normal prior is inappropriate for clinical code distributions; low F1/MAP scores overall indicate fundamental limitations in the approach or data quality issues
- First 3 experiments: 1) Train and evaluate vanilla autoencoder on codes-only input to establish baseline performance; 2) Train and evaluate adversarial autoencoder on codes + structured data to verify it achieves best reported performance; 3) Compare co-occurrence baseline to SVD baseline to confirm the slight performance advantage observed in the study

## Open Questions the Paper Calls Out

### Open Question 1
How does performance vary across different categories of clinical codes (e.g., diagnostic vs procedural codes)? The authors state it would be interesting to see how performance varies between different categories of clinical codes. This remains unresolved because the paper reports overall performance metrics across all clinical diagnostic and procedure codes without subgroup analysis.

### Open Question 2
What is the optimal proportion of codes to hide during evaluation for measuring model performance? The study fixed the hidden code proportion at 50% for all experiments without exploring sensitivity to this parameter. This remains unresolved because the authors note it would be valuable to investigate its impact on model performance.

### Open Question 3
How does including rare clinical codes (occurring less than 50 times) affect model performance? The analysis was limited to codes with at least 50 occurrences, excluding potentially clinically important rare codes. This remains unresolved because the authors suggest future research should evaluate the impact on performance when including rare codes.

### Open Question 4
What is the clinical utility of the proposed autoencoder-based recommendation system in real-world EHR settings? The study focuses on technical performance metrics without assessing real-world implementation impact or user acceptance. This remains unresolved because the authors note the utility of introducing such a tool in practice must be evaluated before clinical deployment.

## Limitations

- Overall performance metrics (F1=0.32, MAP=0.25) remain relatively low, suggesting fundamental challenges in the approach
- Filtering of clinical codes to only those appearing ≥50 times may introduce bias by excluding rare but clinically important codes
- The 50% random masking of codes for evaluation may not reflect realistic missingness patterns in clinical practice

## Confidence

- High confidence: The comparative performance ranking of autoencoder architectures (AAE > other autoencoders > baselines) and the general observation that structured data improves performance
- Medium confidence: The specific mechanism by which adversarial autoencoders outperform other types (non-normal prior modeling) and the robustness of performance gains across folds
- Low confidence: The clinical utility of the predicted codes given the modest absolute performance, and the generalizability to other clinical coding systems beyond ICD-9

## Next Checks

1. **Distribution validation**: Verify whether clinical code distributions in MIMIC-III actually deviate from normality using statistical tests (e.g., Kolmogorov-Smirnov) to confirm the AAE advantage is justified
2. **Real-world missingness simulation**: Replace random 50% masking with realistic missingness patterns based on actual clinical coding practices (e.g., time-dependent missingness, coder expertise effects)
3. **Rare code evaluation**: Assess performance on codes just above the 50-occurrence threshold versus more frequent codes to determine if filtering introduced bias and whether the model can handle clinically important but rare codes
