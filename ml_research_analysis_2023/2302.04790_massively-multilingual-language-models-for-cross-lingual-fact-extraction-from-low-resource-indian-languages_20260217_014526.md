# Massively Multilingual Language Models for Cross Lingual Fact Extraction from Low Resource Indian Languages

## Quick Facts
- arXiv ID: 2302.04790
- Source URL: https://arxiv.org/abs/2302.04790
- Reference count: 14
- Key outcome: End-to-end mT5 generative model achieves 77.46% F1 score, outperforming pipeline approaches for cross-lingual fact extraction

## Executive Summary
This paper introduces Cross Lingual Fact Extraction (CLFE), the task of extracting structured English triples from natural text in low-resource Indian languages. The authors propose two approaches: a two-phase pipeline (TERC) that first extracts tail entities then predicts relations, and an end-to-end generative model using mT5. The end-to-end generative model achieves the best performance with an overall F1 score of 77.46%, outperforming the pipeline approach and showing the benefits of joint modeling. Training separate bilingual models for each language further improves results for English and Bengali, the two most frequent languages in the dataset.

## Method Summary
The authors introduce two approaches for cross-lingual fact extraction: a two-phase pipeline (TERC) that first extracts tail entities using spaCy noun chunk extraction then predicts relations using a MuRIL-based classifier, and an end-to-end generative approach using mT5 fine-tuned on linearized facts. The pipeline approach handles the two tasks separately while the generative approach jointly models them, allowing bidirectional information flow. The mT5 model is trained on all languages together, with options for script unification (transliterating to Devanagari) and bilingual models per language.

## Key Results
- End-to-end mT5 generative approach achieves 77.46% overall F1 score, outperforming pipeline approach
- Multilingual training provides shared learning benefits across Indian languages
- Script unification specifically benefits Dravidian languages (te, ta, kn)
- Bilingual models further improve performance for high-resource languages (English, Bengali)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Joint modeling of tail entity extraction and relation prediction improves performance over pipeline approaches
- Mechanism: The end-to-end generative model allows bidirectional information flow between tail extraction and relation prediction, where context from relation prediction can inform better tail entity selection and vice versa
- Core assumption: Tail extraction and relation prediction are interdependent tasks where information from one task can improve the other
- Evidence anchors:
  - [abstract]: "end-to-end generative approach for the same which achieves an overall F1 score of 77.46"
  - [section 4.2]: "Advantage of this approach over the pipeline approach mentioned above is that there is a two way interaction between tail extraction and relation prediction which improves performance of both the tasks as they are not independent of each other"
  - [corpus]: Weak evidence - corpus only shows related work on multilingual models but no direct evidence about joint modeling benefits

### Mechanism 2
- Claim: Multilingual training provides shared learning benefits across Indian languages
- Mechanism: Training a single model across multiple languages allows transfer of linguistic patterns and structural knowledge between related languages
- Core assumption: Indian languages share sufficient linguistic features and structural similarities to enable positive transfer
- Evidence anchors:
  - [abstract]: "Training separate bilingual models for each language further improves results for English and Bengali"
  - [section 6]: "multilingual training proves to be useful over all, because of the shared learning across Indian languages"
  - [corpus]: Weak evidence - corpus shows related multilingual work but no specific evidence about shared learning benefits for Indian languages

### Mechanism 3
- Claim: Script unification (transliteration to Devanagari) helps Dravidian languages specifically
- Mechanism: Unifying scripts reduces vocabulary fragmentation and allows the model to recognize shared lexical patterns across languages that use similar scripts
- Core assumption: Dravidian languages share script-based lexical patterns that can be leveraged when unified to a common script
- Evidence anchors:
  - [section 4.2]: "script uniﬁcation (transliterating input scripts to Devanagari), speciﬁcally beneﬁts all the Dravidian languages (te, ta, kn) of our dataset"

## Architecture Onboarding

- Component map: Input text + head entity → Preprocessing (script unification if enabled) → mT5 generation → Postprocessing (fact linearization) → Evaluation
- Critical path: Input → Preprocessing (script unification if enabled) → mT5 generation → Postprocessing (fact linearization) → Evaluation
- Design tradeoffs:
  - Pipeline vs end-to-end: Pipeline allows modular improvements but loses cross-task interaction benefits
  - Single multilingual vs bilingual models: Single model benefits from shared learning but bilingual models can capture language-specific nuances
  - Strict vs relaxed evaluation: Strict matching is more precise but may penalize semantically equivalent predictions
- Failure signatures:
  - Low precision: Model generating incorrect or hallucinated facts
  - Low recall: Model missing valid facts due to overly strict matching criteria
  - Script unification degradation: Performance drop when transliteration introduces ambiguity
- First 3 experiments:
  1. Run baseline pipeline approach (TERC) on sample data to establish performance floor
  2. Test end-to-end mT5 model without script unification to compare against pipeline
  3. Enable script unification for Dravidian languages and measure specific improvements

## Open Questions the Paper Calls Out
- How would the performance of the CLFE models change if the partially aligned nature of the dataset were addressed?
- Would incorporating contextual embeddings or more advanced NLP techniques improve the performance of the TERC pipeline's tail entity extraction step?
- How would the CLFE models perform on languages not included in the current dataset, particularly other low-resource languages?
- What is the impact of using different pre-trained language models (other than MURIL and mT5) on the performance of the CLFE task?

## Limitations
- Evaluation relies on strict word matching which may underestimate model performance
- Dataset covers only 8 Indian languages with limited low-resource representation (0.5K pairs per language)
- Script unification's benefits claimed for Dravidian languages but lack quantitative ablation studies

## Confidence
- **High Confidence**: End-to-end generative approach outperforming pipeline (77.46% F1 vs baseline), multilingual training providing overall benefits, bilingual models improving results for high-resource languages
- **Medium Confidence**: Script unification specifically benefiting Dravidian languages (limited quantitative support in main results)
- **Low Confidence**: Exact contribution of each architectural component due to lack of ablation studies

## Next Checks
1. Conduct ablation study removing script unification to quantify its specific contribution to Dravidian language performance
2. Implement relaxed semantic matching evaluation to assess if strict word matching underestimates true performance
3. Test model performance on genuinely low-resource languages (beyond Bengali/English) to validate cross-lingual transfer claims
