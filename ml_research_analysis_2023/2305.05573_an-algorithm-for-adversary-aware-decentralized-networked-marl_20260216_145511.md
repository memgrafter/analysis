# An Algorithm For Adversary Aware Decentralized Networked MARL

## Quick Facts
- arXiv ID: 2305.05573
- Source URL: https://arxiv.org/abs/2305.05573
- Reference count: 32
- Key outcome: Proposes filtering mechanism for consensus-based MARL that maintains agreement among non-adversarial agents by removing extreme parameter estimates from neighbors

## Executive Summary
This paper addresses decentralized multi-agent reinforcement learning (MARL) in adversarial environments where some agents may act maliciously. The proposed algorithm extends consensus-based MARL by introducing a parameter filtering mechanism where each agent removes the highest and lowest parameter estimates from its neighbors before aggregation. This allows non-adversarial agents to reach consensus even when up to a fraction of neighbors are adversarial, operating in a fully decentralized manner without centralized training. The approach combines policy gradient methods with consensus updates while maintaining robustness against adversarial interference.

## Method Summary
The algorithm operates in a fully decentralized networked environment where agents share parameter estimates with neighbors. Each agent independently updates its policy using policy gradient methods while aggregating filtered parameter estimates from neighbors. The key innovation is the filtering mechanism: at each time step, agents remove the highest and lowest parameter estimates from their neighbors before computing the consensus update. The adversarial model assumes that for each node, no more than a fraction of its neighbors can be adversaries, and these adversaries are restricted to form an F-local set. The method maintains consensus among non-adversarial agents despite adversarial presence, though formal convergence proofs are left for future work.

## Key Results
- Algorithm maintains consensus among non-adversarial agents despite adversarial presence
- Filtering mechanism effectively removes influence of adversarial agents by eliminating extreme parameter estimates
- Method works in fully decentralized setting without requiring centralized training or parameter sharing

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Filtering out the highest and lowest parameter estimates from neighbors prevents adversarial agents from skewing the consensus.
- Mechanism: Non-adversarial agents maintain robustness by removing extreme parameter estimates before aggregation, reducing the influence of malicious agents on the consensus update.
- Core assumption: Adversarial agents send parameter estimates that are either consistently high or low compared to non-adversarial agents.
- Break condition: If adversarial agents can mimic legitimate parameter distributions, the filtering becomes ineffective.

### Mechanism 2
- Claim: Maintaining consensus among non-adversarial agents despite adversarial presence enables continued policy improvement through policy gradient methods.
- Mechanism: By ensuring consensus among legitimate agents, the algorithm preserves the conditions needed for policy gradient theorem application, allowing non-adversarial agents to continue learning optimal policies.
- Core assumption: The policy gradient theorem requires consensus among agents for valid gradient estimates.
- Break condition: If consensus cannot be maintained due to high adversarial density or sophisticated attacks.

### Mechanism 3
- Claim: The constrained adversarial setup (F-local, fraction limit) ensures that filtering is sufficient to maintain consensus among non-adversarial agents.
- Mechanism: By limiting adversarial agents to form an F-local set and constraining their fraction, the algorithm guarantees that enough non-adversarial neighbors remain after filtering for valid consensus.
- Core assumption: The adversarial constraint ensures that at least some non-adversarial neighbors remain after removing the highest and lowest parameter states.
- Break condition: If adversarial fraction exceeds the filtering capacity or if adversarial agents coordinate to mimic legitimate behavior.

## Architecture Onboarding

- Component map: State observation -> Policy evaluation -> Advantage calculation -> Parameter sharing -> Consensus with filtering -> Policy update
- Critical path: State observation → Policy evaluation → Advantage calculation → Parameter sharing → Consensus with filtering → Policy update
- Design tradeoffs:
  - Filtering parameter estimates vs. computational overhead
  - Conservative filtering (high threshold) vs. maintaining sufficient neighbors for consensus
  - Decentralized operation vs. potential vulnerability to coordinated adversarial attacks
- Failure signatures:
  - Oscillating parameter estimates across agents
  - Policy performance degradation despite apparent consensus
  - High variance in advantage estimates
  - Communication overhead increasing with network size
- First 3 experiments:
  1. Baseline test: Run algorithm with no adversarial agents to establish performance baseline
  2. Single adversarial agent test: Introduce one adversarial agent with extreme parameter values to verify filtering effectiveness
  3. Varying adversarial fraction test: Systematically increase adversarial fraction to identify the threshold where consensus breaks down

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Does the proposed filtering mechanism (removing highest and lowest parameter estimates) guarantee convergence of the consensus algorithm in the presence of adversarial agents?
- Basis in paper: The paper states "We did not provide a formal argument for the convergence of the consensus updates with our adversarial framework which we leave as one of the immediate next steps of this work."
- Why unresolved: The authors acknowledge this as a limitation and explicitly state it as future work without providing any proof or theoretical guarantees.
- What evidence would resolve it: A formal mathematical proof demonstrating that the filtering mechanism ensures convergence of non-adversarial agents' parameters to a common value despite the presence of adversarial agents.

### Open Question 2
- Question: How does the performance of the adversary-aware algorithm scale with increasing numbers of adversarial agents and varying network topologies?
- Basis in paper: The paper mentions considering "more than a single adversarial agent" but doesn't provide systematic analysis of how performance degrades with increasing adversarial presence or different network structures.
- Why unresolved: The experimental section only briefly mentions that the algorithm "perform well in various multi-agent cooperative environment" without quantifying performance across different adversary ratios or network configurations.
- What evidence would resolve it: Comprehensive empirical studies showing algorithm performance (convergence rate, reward accumulation, policy quality) across different fractions of adversarial agents (e.g., 10%, 25%, 50%) and various network topologies (fully connected, sparse, time-varying).

### Open Question 3
- Question: How does the filtering mechanism perform when adversarial agents collude or coordinate their attacks rather than acting independently?
- Basis in paper: The paper assumes "adversaries are restricted to form an F-local set" but doesn't explore coordinated adversarial strategies or whether the filtering mechanism remains effective against sophisticated attacks.
- Why unresolved: The analysis assumes independent adversarial behavior without considering strategic coordination among adversaries, which could potentially defeat the simple filtering approach.
- What evidence would resolve it: Experiments and theoretical analysis demonstrating whether coordinated adversarial strategies (e.g., synchronized parameter injection, strategic positioning in the network) can overcome the filtering mechanism, and what modifications would be needed to defend against such attacks.

## Limitations
- Algorithm effectiveness depends on the assumption that no node has more than a fraction of adversarial neighbors
- Lack of formal convergence guarantees under adversarial conditions
- Filtering mechanism assumes adversarial agents consistently provide extreme parameter estimates

## Confidence
- **High Confidence**: The filtering mechanism works as described for the constrained adversarial model presented
- **Medium Confidence**: The algorithm maintains consensus among non-adversarial agents when adversarial fraction remains below threshold
- **Low Confidence**: The algorithm's robustness to coordinated adversarial attacks or sophisticated mimicry strategies
