# A Three-regime Model of Network Pruning

## Quick Facts
- arXiv ID: 2305.18383
- Source URL: https://arxiv.org/abs/2305.18383
- Reference count: 40
- One-line primary result: Three-regime model explains how temperature-like and load-like hyperparameters affect neural network pruning performance

## Executive Summary
This work presents a three-regime model for understanding and improving neural network pruning performance. By analyzing the loss landscape connectivity and model similarity, the authors identify three distinct regimes that characterize how pruning outcomes vary with model density (load) and training hyperparameters (temperature). They find a sharp transition phenomenon where increasing temperature improves pruning for low-density (high-load) models in Regime I but degrades performance for high-density models in Regime II. The model enables practical applications including optimal hyperparameter tuning, model selection without exhaustive search, and adaptive tuning of the Sharpness Aware Minimization method for better pruning.

## Method Summary
The method trains dense models with varying temperature-like hyperparameters (training epochs, batch size), prunes them to different densities, and retrains the pruned models. For each configuration, Linear Mode Connectivity (LMC) and Centered Kernel Alignment (CKA) similarity metrics are computed to classify the pruned model into one of three regimes. The framework then uses these regime classifications to guide optimal hyperparameter adjustments and model selection. The approach is validated on PreResNet-20 with CIFAR-10 and Transformer-base with WMT14 German-English datasets.

## Key Results
- Three-regime model successfully predicts optimal hyperparameter adjustments for pruning across different model densities
- Temperature-tuning scheme improves test error by 1.33% on CIFAR-10 and 2.65% on WMT14
- Model selection without exhaustive search achieves comparable performance to grid search methods
- SAM hyperparameter tuning guided by the three-regime model improves pruning outcomes

## Architecture Onboarding

- Component map: Dense model training (with temperature-like parameters) -> Pruning stage (with load-like parameters) -> Retraining of pruned model -> Loss landscape metric computation (LMC and CKA similarity) -> Three-regime classification system

- Critical path:
  1. Train dense model with specific temperature-like hyperparameters
  2. Prune model to target density (load-like parameter)
  3. Compute LMC and CKA similarity on pruned model
  4. Classify into one of three regimes based on LMC and CKA values
  5. Adjust temperature-like hyperparameters based on regime classification
  6. Repeat steps 1-5 until optimal hyperparameters are found

- Design tradeoffs:
  - Computational cost vs. performance: Loss landscape metrics add overhead but lead to better hyperparameter choices
  - Model architecture dependence: Three-regime model may need recalibration for different architectures
  - Dataset dependence: Performance may vary across datasets, requiring careful validation

- Failure signatures:
  - LMC and CKA similarity metrics not correlating with pruning performance
  - Three-regime classification failing to generalize across different settings
  - Optimal hyperparameter adjustments not leading to improved pruning results

- First 3 experiments:
  1. Verify three-regime taxonomy on PreResNet-20 with CIFAR-10 using different training epochs and model densities
  2. Test temperature-tuning scheme by comparing test error improvements with and without regime-based adjustments
  3. Validate model selection method by comparing performance against grid search across multiple architectures and datasets

## Limitations
- Three-regime model may not generalize to architectures beyond PreResNet-20 and Transformer-base
- Computational overhead from loss landscape metric calculations may be prohibitive for very large models
- Regime boundaries (particularly LMC threshold of -0.05) may require recalibration for different pruning methods or datasets
