# causalgraph: A Python Package for Modeling, Persisting and Visualizing Causal Graphs Embedded in Knowledge Graphs

## Executive Summary
causalgraph is a Python package that provides a standardized way to represent causal information as a knowledge graph. It allows users to model, save, and visualize causal graphs embedded in knowledge graphs, preventing information loss and facilitating the transfer of data between causal discovery and causal inference. The package offers functions for graph modeling and plotting, such as editing, adding, and deleting nodes and edges. It is also compatible with widely used graph data science libraries such as NetworkX and Tigramite and incorporates a specially developed causalgraph ontology in the background. The package is designed to serve as an interface between causal discovery and causal inference, enabling researchers and practitioners to work more efficiently with graph-based knowledge representations.

## Method Summary
The causalgraph package uses RDF and a custom ontology to store causal relationships and metadata. It provides functions for creating, modifying, and persisting causal graphs, with import/export functionality for compatibility with NetworkX and Tigramite. The package leverages RDF reification to attach metadata (e.g., confidence scores, time lags) to individual causal relationships, preserving context when transferring between tools. A SQL backend enables persistent storage and runtime adaptation of causal information.

## Key Results
- Prevents information loss during transfer between causal discovery and causal inference by embedding causal graphs in a knowledge graph structure using RDF reification
- Provides a standardized representation format (causalgraph ontology) that enables interoperability between different causal analysis tools
- Enables seamless workflow transitions between causal graph modeling and causal analysis through integration with NetworkX and Tigramite

## Architecture Onboarding

- Component map:
  Core Graph class -> RDF storage layer -> Ontology system -> Import/Export modules -> Visualization module -> Utility functions

- Critical path:
  1. Instantiate Graph() object
  2. Add CausalNodes and CausalEdges with metadata
  3. Persist graph to SQL database
  4. Export to target format (NetworkX/Tigramite/GML/GraphML)
  5. Import back to causalgraph or use in other tools

- Design tradeoffs:
  - Simplicity vs. expressivity: The ontology is kept relatively simple to ensure broad compatibility, potentially at the cost of some specialized causal relationship types
  - Performance vs. flexibility: Using RDF reification provides flexibility but may introduce overhead compared to direct graph representations
  - SQL persistence vs. in-memory: SQL storage enables persistence and concurrent access but adds complexity

- Failure signatures:
  - Lost metadata during import/export: Check conversion functions and target library compatibility
  - Ontology validation errors: Verify individual assignments and property types match ontology constraints
  - Database corruption: Check SQL connection settings and exclusive access flags
  - Visualization rendering issues: Verify vis-network and Matplotlib dependencies

- First 3 experiments:
  1. Create a simple causal graph with two nodes and one edge, add metadata (confidence, time lag), and verify persistence by reloading from the database
  2. Export the graph to NetworkX MultiDiGraph format, modify it using NetworkX functions, then re-import and verify all metadata is preserved
  3. Import a third-party ontology (e.g., pizza ontology example), create individuals of those types, and verify they inherit CausalNode properties when referenced in CausalEdges
