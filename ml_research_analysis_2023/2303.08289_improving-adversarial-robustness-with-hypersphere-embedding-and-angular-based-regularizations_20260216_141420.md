# Improving Adversarial Robustness with Hypersphere Embedding and Angular-based Regularizations

## Executive Summary
This paper proposes Angular-AT, a method to improve adversarial robustness in deep neural networks by leveraging angular discriminative information within the hypersphere embedding framework. The approach introduces two angular-based regularization terms to the adversarial training objective: weight-feature compactness and inter-class separation. These regularizations encourage compact decision boundaries and larger angular margins between classes, leading to improved robustness against various adversarial attacks.

## Method Summary
The Angular-AT method integrates angular softmax-cross-entropy loss with two regularization terms during adversarial training. The weight-feature compactness term minimizes the angle between adversarial feature vectors and their corresponding true class weight vectors, while the inter-class separation term maximizes the minimum angles between class weight vectors. This framework encourages the model to learn discriminative angular features in the hypersphere embedding space, leading to more robust decision boundaries.

## Key Results
- Achieves 64.32% accuracy against Autoattack on CIFAR10
- Achieves 63.28% accuracy against PGD-500 on CIFAR10
- Achieves 56.25% accuracy against CW attacks on CIFAR10
- Consistent improvements across CIFAR100 and TinyImagenet datasets

## Why This Works (Mechanism)
The method works by constraining the decision boundaries to be more compact and well-separated in the angular space. By minimizing the angle between adversarial features and their true class weights, the model learns to make decisions based on angular similarity rather than Euclidean distance. The inter-class separation regularization further ensures that classes are well-separated in the angular space, creating larger margins that are more robust to adversarial perturbations.

## Foundational Learning
1. **Hypersphere Embedding**: Learning features on a unit hypersphere to utilize angular information for classification
   - Why needed: Angular information provides more discriminative power for classification tasks
   - Quick check: Features should lie on a unit hypersphere after normalization

2. **Adversarial Training**: Training models with adversarial examples to improve robustness
   - Why needed: Standard training leads to models vulnerable to adversarial attacks
   - Quick check: Model should maintain reasonable accuracy on clean data

3. **Angular Softmax Loss**: Modified softmax that uses angular distances instead of Euclidean distances
   - Why needed: Angular distances provide better discriminative power in hypersphere space
   - Quick check: Loss should decrease during training while maintaining angular separation

## Architecture Onboarding

**Component Map**: Input -> Feature Extractor -> Angular Softmax + Regularizations -> Output

**Critical Path**: Feature extraction → Angular feature normalization → Softmax classification + regularization → Loss computation

**Design Tradeoffs**: 
- Regularization strength vs. clean accuracy tradeoff
- Computational overhead of angular computations vs. robustness gains
- Choice of angular margin vs. classification difficulty

**Failure Signatures**:
- Poor robustness: Insufficient regularization strength or improper angular scaling
- Numerical instability: Incorrect angle computation or normalization
- Clean accuracy drop: Overly aggressive regularization or margin
