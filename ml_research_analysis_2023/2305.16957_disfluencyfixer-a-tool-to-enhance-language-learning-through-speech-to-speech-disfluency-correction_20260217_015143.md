# DisfluencyFixer: A tool to enhance Language Learning through Speech To Speech Disfluency Correction

## Quick Facts
- arXiv ID: 2305.16957
- Source URL: https://arxiv.org/abs/2305.16957
- Reference count: 0
- A speech-to-speech disfluency correction tool for English and Hindi with 48-user study showing average scores of 4.26-4.42 out of 5

## Executive Summary
DisfluencyFixer is an interactive web-based tool that helps language learners improve their speech fluency by automatically detecting and correcting disfluencies in spoken English and Hindi. The system integrates automatic speech recognition, disfluency correction, and text-to-speech synthesis into a pipeline that provides learners with corrected fluent speech alongside the original disfluent transcript. A user study with 48 language learners showed positive reception, with average scores of 4.26-4.42 out of 5 for ASR performance, disfluency correction, and ease of use.

## Method Summary
The tool employs a three-stage pipeline: first, XLSR-wav2vec 2.0 ASR model transcribes spoken input into text; second, a MuRIL-based transformer classifier identifies and removes disfluent words to produce a fluent transcript; third, a Forward Tacotron model with CARGAN vocoder converts the corrected text back into fluent speech. For English, the disfluency correction model is trained on the Switchboard corpus, while for Hindi it uses synthetic data in a zero-shot learning approach. The system provides an interactive ReactJS frontend where users can record speech, view transcripts, receive disfluency type information and counts, and listen to the corrected output.

## Key Results
- User study with 48 language learners achieved average scores of 4.26 for ASR performance, 4.29 for disfluency correction performance, and 4.42 for ease of use (out of 5)
- The tool successfully processes both English and Hindi speech, though Hindi relies on synthetic training data
- The pipeline produces corrected fluent speech output with accompanying transcripts and disfluency annotations

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The integration of ASR, disfluency correction, and TTS into a single pipeline produces fluent speech output that aids language learning.
- Mechanism: The ASR module transcribes spoken input into text, the disfluency correction module removes filler words, repetitions, and other disfluencies from the transcript, and the TTS module converts the corrected text back into fluent speech. This end-to-end pipeline provides learners with corrected speech output alongside the original disfluent transcript, allowing them to compare and learn.
- Core assumption: The ASR, disfluency correction, and TTS models are sufficiently accurate in their respective tasks to produce useful corrections for language learners.
- Evidence anchors:
  - [abstract] "Our proposed system removes disfluencies from input speech and returns fluent speech as output along with its transcript, disfluency type and total disfluency count in source utterance"
  - [section] "DisfluencyFixer is an online web service created using ReactJS frontend and Python backend. It consists of an interactive user interface for automatic disfluency correction in input speech generating fluent output speech with transcription, information about the total disfluency count and type of disfluency."

### Mechanism 2
- Claim: The disfluency correction module, trained on Switchboard corpus for English and synthetic data for Hindi, can effectively identify and remove disfluencies in spontaneous speech.
- Mechanism: The disfluency correction module is based on the MuRIL transformer architecture and is trained to classify each word in a sentence as disfluent or fluent. By removing the disfluent words, the module produces a fluent transcript. The use of synthetic data for Hindi allows the model to handle this low-resource language.
- Core assumption: The training data (Switchboard for English, synthetic data for Hindi) is representative of the types of disfluencies found in spontaneous speech.
- Evidence anchors:
  - [abstract] "Our DC system is based on the MuRIL transformer architecture and trained on annotated disfluent English sentences from the Switchboard corpus. For Hindi, we train the system in a zero-shot setting using synthetically generated data."
  - [section] "The final fluent text is obtained by removing all the disfluent words marked by the model."

### Mechanism 3
- Claim: The user study results indicate that DisfluencyFixer is perceived as a useful tool for language learning, with high scores for ASR performance, disfluency correction performance, and ease of use.
- Mechanism: By presenting users with corrected speech output, disfluency type information, and a disfluency count, the tool provides valuable feedback on their speech fluency. The high scores in the user study suggest that learners find this feedback helpful for improving their speech.

## Architecture Onboarding

- Component map: User Recording -> ASR (XLSR-wav2vec 2.0) -> Disfluency Correction (MuRIL) -> TTS (Forward Tacotron + CARGAN) -> Fluent Speech Output
- Critical path: User recording → ASR transcription → Disfluency correction → TTS synthesis → Fluent speech output
- Design tradeoffs:
  - Using a pipeline of separate models (ASR, DC, TTS) vs. a single end-to-end model for speech-to-speech disfluency correction
  - Prioritizing accuracy vs. speed in the ASR and disfluency correction models
  - Using pre-trained models vs. training from scratch for each module
- Failure signatures:
  - High word error rate in ASR output leading to incorrect disfluency correction
  - Disfluency correction module misclassifying fluent words as disfluent or vice versa
  - TTS module producing unnatural or unintelligible speech output
- First 3 experiments:
  1. Evaluate the performance of each individual module (ASR, DC, TTS) on a held-out test set to identify bottlenecks or weaknesses.
  2. Conduct a user study with a small group of language learners to gather feedback on the tool's usefulness and identify areas for improvement.
  3. Perform an ablation study, removing each module in turn to quantify its impact on the overall system performance and user experience.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of the DisfluencyFixer tool compare when using high-quality microphones versus built-in device microphones?
- Basis in paper: [explicit] The authors note that the tool performs better when users test it on laptops/desktops compared to mobile phones/tablets, implying performance correlates with microphone quality.
- Why unresolved: The study did not systematically control for or measure microphone quality differences between devices used by participants.
- What evidence would resolve it: A controlled experiment testing the tool's ASR and DC performance across a range of microphone qualities while keeping other factors constant.

### Open Question 2
- Question: Can the disfluency correction model be improved by incorporating phonetic features or pronunciation information beyond just text transcripts?
- Basis in paper: [inferred] The authors mention that the ASR model makes phonetic mistakes that are propagated to the DC model, suggesting room for improvement in handling pronunciation variations.
- Why unresolved: The current pipeline relies solely on ASR transcripts without incorporating any phonetic or pronunciation features that could help the DC model handle ASR errors better.
- What evidence would resolve it: Comparative experiments testing DC performance with and without phonetic/prosodic features as additional inputs to the model.

### Open Question 3
- Question: How does the performance of the Hindi disfluency correction compare to English, given that it was trained using synthetic data in a zero-shot setting?
- Basis in paper: [explicit] The authors mention training the Hindi DC system in a zero-shot setting using synthetically generated data, unlike the English system which was trained on annotated Switchboard data.
- Why unresolved: The paper does not provide a detailed comparison of DC performance between the two languages, nor does it quantify the impact of using synthetic versus real annotated data.
- What evidence would resolve it: A detailed error analysis and performance comparison of the DC models for both languages on held-out test sets of real human-annotated disfluent speech.

## Limitations

- The Hindi disfluency correction model's performance is uncertain due to training on synthetic data rather than real human-annotated data
- The user study sample size of 48 participants may not be representative of the broader language learning population
- The tool's performance is constrained by the weakest link in its pipeline, with ASR errors potentially cascading through to disfluency correction and TTS
