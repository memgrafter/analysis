# Aligning benchmark datasets for table structure recognition

## Quick Facts
- arXiv ID: 2303.00716
- Source URL: https://arxiv.org/abs/2303.00716
- Reference count: 28
- Key outcome: Correcting annotation inconsistencies across TSR benchmarks improves model performance from 69% to 81% exact match accuracy

## Executive Summary
This work addresses benchmark misalignment in table structure recognition (TSR) by demonstrating that annotation inconsistencies and errors across datasets harm model performance. The authors propose a data-centric approach that corrects and aligns two large training datasets (FinTabNet and PubTables-1M) and a small evaluation dataset (ICDAR-2013) through automated procedures including missing annotation completion, error detection/correction, consistency adjustments, and canonicalization. Using a single fixed Table Transformer architecture, they show that aligning these benchmarks substantially improves performance, establishing new baselines for TSR and highlighting the importance of benchmark alignment for ML tasks.

## Method Summary
The method involves a sequential data processing pipeline that starts with three benchmark datasets (FinTabNet with 113k financial tables, PubTables-1M with nearly 1M scientific tables, and ICDAR-2013 with 258 expert-labeled tables). The pipeline applies six modification steps to FinTabNet: missing annotation completion, error detection/correction, consistency adjustments, canonicalization of table structures, quality control filtering, and combination with PubTables-1M. All datasets are processed using the canonicalization procedure from [21] to minimize inconsistencies. The Table Transformer (TATR) model is held fixed throughout experiments, trained for 30 epochs with 720k samples per epoch, and evaluated using AccCon (exact match), GriTS metrics (Con, Loc, Top), and DAR measures.

## Key Results
- Aligning FinTabNet and PubTables-1M datasets improves AccCon from 68% to 81% on ICDAR-2013 evaluation
- Canonicalization alone provides significant performance boost, with FinTabNet.a4 outperforming FinTabNet.a1 on self-evaluation
- Performance degrades when combining misaligned datasets (FinTabNet.a1 with PubTables-1M) compared to aligned versions
- New performance baselines established: 81% AccCon exact match accuracy for ICDAR-2013 benchmark

## Why This Works (Mechanism)

### Mechanism 1
Removing inconsistencies between datasets improves model performance because the model no longer has to reconcile conflicting annotations during training. Inconsistent labels act as noise, forcing the model to learn ambiguous patterns that do not generalize. By aligning datasets, the training signal becomes cleaner, allowing the model to focus on true structural patterns. The core assumption is that annotation inconsistencies are genuine errors rather than valid alternative interpretations of the same table structure.

### Mechanism 2
Canonicalization of table annotations improves performance by providing a consistent interpretation framework across datasets. The canonicalization algorithm infers column headers and projected row headers automatically, creating a standardized representation that enables better cross-dataset learning and evaluation. The core assumption is that tables can be meaningfully canonicalized without losing essential structural information, and the canonicalization algorithm is sufficiently accurate.

### Mechanism 3
The data-centric approach (fixing data instead of model architecture) reveals that dataset quality is a bottleneck for performance. By holding the Table Transformer architecture fixed, improvements can be attributed solely to data quality changes rather than model improvements, isolating the impact of data cleaning. The core assumption is that the chosen model architecture is sufficiently expressive to capture the underlying patterns once the data is cleaned.

## Architecture Onboarding

- Component map: Dataset processing pipeline -> Table Transformer model -> Evaluation framework. The dataset pipeline includes steps for missing annotation completion, error detection/correction, consistency adjustments, canonicalization, and quality control filtering.

- Critical path: The critical path is the sequential dataset processing pipeline. Errors in earlier stages (like missing annotations) can propagate to later stages (like canonicalization), so the pipeline must be executed in the specified order. The model training and evaluation stages depend entirely on the processed datasets.

- Design tradeoffs: The work balances competing objectives - maximizing dataset size vs. quality, preserving diversity vs. enforcing consistency, correcting errors vs. removing ambiguous samples. The choice of when to filter vs. correct represents a key tradeoff. Additionally, canonicalization provides consistency but may remove valid variations.

- Failure signatures: Performance degradation despite data cleaning could indicate that inconsistencies were actually valid interpretations rather than errors. If canonicalization fails to converge or produces poor results, it may indicate the algorithm assumptions don't hold for certain table types. If performance on individual datasets degrades after combination, it may indicate incompatible annotation schemes.

## Open Questions the Paper Calls Out

### Open Question 1
How would the results change if different model architectures were used instead of the fixed TATR model? The authors hold the TATR model fixed throughout their experiments and demonstrate improvements through data-centric changes alone, but the paper only tests one model architecture, leaving open the question of whether architectural improvements could further enhance performance on aligned datasets.

### Open Question 2
What is the optimal trade-off between dataset diversity and annotation consistency when designing benchmarks? The authors note that "when cleaning a pre-existing dataset these goals potentially compete and trade-offs must be made," particularly when they had to remove tables with inconsistent annotations, but the paper doesn't systematically explore how much diversity can be preserved while maintaining consistency.

### Open Question 3
How general is the benchmark alignment approach across different domains and tasks? The authors state "Overall we believe our work has significant implications for benchmark design for TSR and potentially other tasks as well," but while the paper shows clear benefits for TSR, it doesn't test whether the same alignment principles apply to other domains like NER, image classification, or speech recognition.

### Open Question 4
What is the long-term impact of using canonicalization on model generalization to unseen table layouts? The authors find that canonicalization "has a significantly positive effect on performance" but don't explore whether this might overfit models to canonicalized structures at the expense of handling novel layouts, as the paper doesn't test models on tables with deliberately non-canonical structures.

## Limitations
- Assumes all annotation inconsistencies represent errors rather than valid alternative interpretations of table structure
- Canonicalization algorithm assumptions may not hold for all table types, potentially removing legitimate variations
- Fixed TATR architecture may have fundamental limitations that prevent optimal performance regardless of data quality improvements

## Confidence

High confidence in the dataset alignment methodology and its positive impact on performance (supported by systematic ablation studies). Medium confidence in the assumption that all inconsistencies are errors rather than valid interpretations. Medium confidence that the TATR architecture is sufficiently expressive once data quality issues are resolved. Low confidence that the specific improvements will transfer to other table recognition tasks or domains.

## Next Checks
