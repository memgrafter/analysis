# Graphtester: Exploring Theoretical Boundaries of GNNs on Graph Datasets

## Quick Facts
- arXiv ID: 2306.17482
- Source URL: https://arxiv.org/abs/2306.17482
- Reference count: 40
- Key outcome: GRAPHTESTER provides a tool for analyzing theoretical limits of GNNs on graph datasets using the Weisfeiler-Lehman test

## Executive Summary
GRAPHTESTER is a comprehensive tool that analyzes the theoretical limits of Graph Neural Networks (GNNs) on graph datasets by leveraging the Weisfeiler-Lehman (WL) test. The tool determines upper bounds on GNN performance based on the number of layers and available node/edge features, supporting various graph tasks and performance measures. By extending to higher-order WL tests and Graph Transformers with positional encodings, GRAPHTESTER provides a unified framework for understanding GNN expressiveness across different architectures and datasets.

## Method Summary
GRAPHTESTER automates the process of running the edge-feature-aware 1-WL (1-WLE) algorithm on graph datasets to compute theoretical upper bounds on performance metrics. The tool takes graph datasets as input, preprocesses them, runs the 1-WLE algorithm until convergence to determine node hashes, and uses these hashes to estimate upper bounds on accuracy, MSE, and other metrics. It supports analysis of different numbers of GNN layers, edge features, higher-order WL tests, and Graph Transformers with positional encodings. The package includes a synthetic dataset for benchmarking node and edge features.

## Key Results
- GRAPHTESTER provides theoretical upper bounds on GNN performance for over 40 graph datasets
- Edge features significantly improve GNN expressiveness and upper bounds
- Graph transformers with positional encodings are bounded by the WL test, similar to GNNs
- Many graph datasets are not fully solvable by GNNs regardless of architecture or features

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The Weisfeiler-Lehman (WL) test determines theoretical limits on what Graph Neural Networks (GNNs) can achieve on graph datasets.
- Mechanism: The WL test iteratively refines node labels based on neighboring node labels, providing a way to compare the structure of different nodes. If two nodes have identical WL labels, a standard GNN cannot distinguish them, imposing a theoretical upper bound on performance.
- Core assumption: The WL test's power directly bounds the expressive power of GNNs.
- Evidence anchors:
  - [abstract] "The main approach for analyzing the theoretical power of GNN architectures relies on showing equivalence to the Weisfeiler-Lehman (WL) graph isomorphism test (Xu et al., 2019b)."
  - [section 2.3] "The Weisfeiler-Lehman (WL) test is a well-known graph isomorphism test that has been linked to the expressive power of message-passing-based GNNs (Morris et al., 2019; Xu et al., 2019a)."
- Break condition: If the GNN architecture deviates from the standard message-passing paradigm or uses positional encodings that enhance its expressive power beyond the WL test.

### Mechanism 2
- Claim: Edge features significantly improve the expressiveness of GNNs.
- Mechanism: The edge-feature-aware 1-WL (1-WLE) algorithm incorporates edge labels into the node label refinement process, allowing GNNs to distinguish nodes that would be indistinguishable with only node features.
- Core assumption: Edge features provide additional structural information that can be leveraged by the WL test to distinguish nodes.
- Evidence anchors:
  - [section 3.2] "We now present the edge-feature-aware 1-WL (1-WLE). At each iteration, the algorithm updates the node labels based on both the neighboring node labels and the edge labels of the connecting edges."
  - [section 4.4] "One other important observation here is the need for using available edge features in 1-WL context to achieve better upper bounds."
- Break condition: If the edge features are not informative or do not capture relevant structural information for the task at hand.

### Mechanism 3
- Claim: Graph transformers with positional encodings are bounded by the WL test.
- Mechanism: Positional encodings provide additional information about node positions in the graph, but the theorem proves that even with this information, graph transformers cannot exceed the expressive power of the WL test.
- Core assumption: The theorem's proof holds for graph transformers with positional encodings, extending the WL test's bound to this class of models.
- Evidence anchors:
  - [abstract] "We prove that graph transformers making use of positional encodings for nodes are also bounded in power by the Weisfeiler-Lehman (1-WL) graph isomorphism test, thereby resulting in the same upper bounds as a GNN with additional encoding information."
  - [section 3.1] "Theorem 3.1. The 1-WL test is at least as powerful as GTs with positional encodings for nodes, e.g., GraphTrans (Wu et al., 2022b) or GraphGPS (Rampásek et al., 2022), if node encodings are also provided as initial color classes for the 1-WL algorithm."
- Break condition: If the positional encodings provide information that is not captured by the WL test or if the graph transformer architecture deviates significantly from the assumed model.

## Architecture Onboarding

- Component map: Input datasets -> Preprocessing -> 1-WLE algorithm -> Node hash computation -> Upper bound estimation -> Output results
- Critical path: The critical path involves running the 1-WLE algorithm on the graph dataset until convergence, determining node hashes, and using these hashes to estimate upper bounds on various performance metrics.
- Design tradeoffs: The tool supports different numbers of GNN layers, edge features, and higher-order WL tests, allowing for a comprehensive analysis of GNN performance. However, this flexibility comes at the cost of increased computational complexity.
- Failure signatures: If the 1-WLE algorithm does not converge or if the estimated upper bounds are unrealistic, it may indicate issues with the input dataset or the chosen configuration of the tool.
- First 3 experiments:
  1. Analyze a simple graph dataset (e.g., MUTAG) without edge features to establish a baseline for GNN performance.
  2. Repeat the analysis with edge features to observe their impact on the upper bounds.
  3. Compare the performance of GNNs with different numbers of layers on a more complex dataset (e.g., ZINC) to understand the trade-off between model complexity and performance.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What are the theoretical limits of using positional encodings to improve GNN performance on graph datasets that are not fully solvable?
- Basis in paper: [explicit] The paper discusses using positional encodings to enhance node and graph identifiability, but notes that improved node-based identifiability may lead to overfitting.
- Why unresolved: While the paper provides some empirical results on the effectiveness of positional encodings, it does not provide a theoretical analysis of their impact on GNN performance for unsolvable datasets.
- What evidence would resolve it: A theoretical framework that quantifies the trade-off between improved identifiability and overfitting risk for positional encodings on unsolvable datasets.

### Open Question 2
- Question: How do edge features compare to node features in terms of improving GNN expressiveness, and are there specific graph structures where edge features are particularly beneficial?
- Basis in paper: [explicit] The paper discusses the importance of edge features for GNN expressiveness, but does not provide a detailed comparison with node features or identify specific graph structures where edge features are most useful.
- Why unresolved: While the paper demonstrates the importance of edge features, it does not provide a comprehensive analysis of their relative impact compared to node features or identify specific graph structures where they are most beneficial.
- What evidence would resolve it: A detailed empirical study comparing the impact of edge and node features on GNN performance across various graph structures, identifying scenarios where edge features provide the most significant improvement.

### Open Question 3
- Question: What are the limitations of using centrality measures as positional encodings, and how can they be overcome to improve GNN performance?
- Basis in paper: [explicit] The paper discusses using centrality measures as positional encodings and provides some empirical results, but does not analyze their limitations or propose methods to overcome them.
- Why unresolved: While the paper demonstrates the potential of centrality measures as positional encodings, it does not provide a comprehensive analysis of their limitations or propose methods to overcome them.
- What evidence would resolve it: A theoretical analysis of the limitations of centrality measures as positional encodings, along with proposed methods to overcome these limitations and improve GNN performance.

## Limitations
- The theoretical upper bounds may not always reflect practical achievable performance due to optimization challenges
- Computational cost of running 1-WL tests on large datasets can be significant
- The synthetic dataset for benchmarking positional encodings covers only a specific subset of graph structures

## Confidence
- **Mechanism 1 (WL-GNN equivalence)**: High confidence - well-established theoretical foundation with extensive prior work
- **Mechanism 2 (Edge features)**: Medium confidence - empirical evidence supports the claim, but the magnitude of improvement may vary across datasets
- **Mechanism 3 (Graph transformers)**: Medium confidence - the theoretical extension is sound, but practical implementations may introduce additional complexities
