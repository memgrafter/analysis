# How does the task complexity of masked pretraining objectives affect downstream performance?

## Quick Facts
- arXiv ID: 2305.10992
- Source URL: https://arxiv.org/abs/2305.10992
- Reference count: 28
- More complex masked pretraining objectives generally yield better downstream performance

## Executive Summary
This study investigates how the complexity of masked pretraining objectives impacts downstream performance. The authors propose a control task, masked n-character prediction, which allows varying complexity by predicting the first or last n characters of masked tokens. Through experiments with 14 different models, they demonstrate that more complex objectives tend to achieve better results on GLUE, SQuAD, and Universal Dependencies benchmarks. The findings reveal a tradeoff between computational efficiency and downstream performance, suggesting that at least half of MLM's complexity is needed to perform comparably to standard masked language modeling.

## Method Summary
The researchers pretrain 14 BERT-base models using a masked n-character prediction objective with varying complexity (n=1-9 for first and last characters). They use English Wikipedia and BookCorpus datasets (10 million samples, 4.9 billion tokens) for pretraining, then evaluate models on GLUE, SQuAD v1.1, and UD v2.10 benchmarks. The study analyzes the relationship between task complexity, downstream performance, and computational efficiency measured in FLOPs. Each model is pretrained for 500k steps, and the authors compare performance across different complexity levels to identify thresholds for competitive performance with standard MLM.

## Key Results
- More complex masked pretraining objectives yield better downstream performance on GLUE, SQuAD, and UD benchmarks
- At least half of MLM's complexity (n=4) is needed to achieve comparable performance to standard MLM
- Clear tradeoff exists between computational efficiency and downstream performance

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Task complexity directly influences downstream performance by determining the number of classes the model must predict.
- Mechanism: The model receives more informative training signals when predicting a larger number of classes, which helps it learn richer representations.
- Core assumption: The number of prediction classes is the primary driver of representation quality in masked pretraining.
- Evidence anchors:
  - [abstract]: "we validate whether more complex masked objectives can achieve better results and investigate how much complexity they should have to perform comparably to MLM"
  - [section]: "Our main hypothesis is that the more complexity, i.e., the number of classes to be predicted, masked pretraining objectives have, the better the downstream performance they will achieve"
  - [corpus]: Weak - corpus contains papers about MLM variations but none directly measure class count vs performance correlation
- Break condition: If downstream tasks do not benefit from more granular distinctions in representations, or if the relationship between class count and performance is non-monotonic

### Mechanism 2
- Claim: The task complexity-performance relationship follows a threshold effect where minimum complexity is required for competitive performance.
- Mechanism: Below a certain complexity threshold (around 35.7% of MLM's class count), models cannot learn sufficient distinctions to match MLM performance, but above this threshold, performance plateaus.
- Core assumption: There exists a minimum viable complexity for masked pretraining to be effective
- Evidence anchors:
  - [abstract]: "at least half of the MLM complexity needed to perform comparably to MLM"
  - [section]: "at leastn = 4 complexity is necessary to achieve comparable results to MLM"
  - [corpus]: Missing - no corpus papers specifically measure threshold effects of complexity
- Break condition: If different downstream tasks have different complexity thresholds, or if the relationship is more continuous than threshold-based

### Mechanism 3
- Claim: Computational efficiency scales inversely with task complexity, creating a tradeoff space.
- Mechanism: More complex tasks require more floating point operations (FLOPs) but yield better downstream performance, while simpler tasks are computationally cheaper but may underperform.
- Core assumption: FLOP count is a reasonable proxy for computational cost in masked pretraining
- Evidence anchors:
  - [section]: "Table 2 shows the number of floating-point operations (FLOPs) required for n Chars, First Char, Last Char, and MLM along with its downstream performance"
  - [section]: "We can see a clear tradeoff between computational efficiency and downstream performance"
  - [corpus]: Weak - corpus papers discuss MLM efficiency but not specifically FLOP-complexity-performance tradeoffs
- Break condition: If other computational factors (memory, parallelism) dominate the efficiency tradeoff, or if the FLOP-performance relationship is not linear

## Limitations
- Limited to BERT-base architecture and English-only data, restricting generalizability to other model sizes and languages
- Focus on a single complexity metric (number of prediction classes) may miss other important factors
- FLOP count as a proxy for computational efficiency may not capture real-world training costs

## Confidence

**High Confidence**: The observation that increased task complexity generally improves downstream performance across multiple benchmarks. The experimental design provides clear evidence for this monotonic relationship within the tested range.

**Medium Confidence**: The specific threshold claim that n=4 complexity is necessary for competitive performance with MLM. While supported by the data, this appears sensitive to experimental conditions and may not generalize beyond the specific setup.

**Low Confidence**: The generality of the complexity-performance relationship to other architectures, languages, and pretraining objectives. The study's focus on BERT-base and English limits broader applicability.

## Next Checks

1. **Architecture Scaling Test**: Replicate the character prediction experiments with BERT-large and GPT-style decoder models to determine if the complexity-performance relationship scales with model capacity. This would validate whether the observed threshold effects are architecture-dependent.

2. **Multilingual Generalization**: Apply the same complexity gradient to multilingual BERT pretraining on mC4 or similar datasets, then evaluate on cross-lingual benchmarks like XNLI and PAWS-X. This would test whether the minimum viable complexity threshold shifts in multilingual settings.

3. **Alternative Complexity Metrics**: Design experiments varying semantic granularity (e.g., predicting word senses, syntactic categories, or semantic roles) rather than just character sequences, while keeping class counts comparable. This would isolate whether class count or task semantics drives the observed effects.
