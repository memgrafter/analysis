# Towards Unbiased Training in Federated Open-world Semi-supervised Learning

## Quick Facts
- arXiv ID: 2305.00771
- Source URL: https://arxiv.org/abs/2305.00771
- Authors: 
- Reference count: 13
- Key outcome: Achieves up to 14.76% improvement in unseen class accuracy compared to existing methods

## Executive Summary
This paper addresses the challenge of federated semi-supervised learning in open-world settings where unseen classes exist in unlabeled data across distributed clients. The authors identify that standard federated learning approaches create biased training when unseen classes are heterogeneously distributed across clients. They propose FedoSSL, a novel framework that distinguishes between locally unseen classes (appearing in multiple clients) and globally unseen classes (appearing only in one client), applying differentiated training strategies to each. The framework combines an uncertainty-aware suppressed loss with a calibration module that aligns heterogeneous classifier outputs across clients.

## Method Summary
FedoSSL operates through a client-server architecture where each client trains a local model on its labeled and unlabeled data. The method introduces three key innovations: (1) an uncertainty-aware suppressed loss that applies stronger penalties to high-uncertainty samples, particularly benefiting globally unseen classes, (2) a calibration module that computes and aggregates local centroids using Sinkhorn-Knopp clustering to align classifier outputs across clients, and (3) a redefinition of unseen classes into locally unseen and globally unseen categories to enable fine-grained treatment of training bias. During aggregation, the server combines both model parameters and centroids, then redistributes them to clients for continued training.

## Key Results
- FedoSSL achieves up to 14.76% improvement in unseen class accuracy compared to state-of-the-art baselines
- The framework demonstrates robustness across CIFAR-10, CIFAR-100, and CINIC-10 datasets
- Performance gains are particularly pronounced for globally unseen classes, addressing the core bias problem

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The uncertainty-aware suppressed loss reduces training bias between locally unseen and globally unseen classes by applying stronger penalties to high-uncertainty samples.
- Mechanism: The loss function Ri uses both confidence (1 - max probability) and class imbalance weight ρ(nc) to penalize uncertain predictions more heavily. Locally unseen classes, which benefit from cross-client collaboration, tend to have higher confidence and thus lower penalties, while globally unseen classes receive stronger regularization to prevent premature overcommitment.
- Core assumption: Uncertainty measured via softmax confidence and class frequency is a reliable proxy for training progress differentiation between locally and globally unseen classes.
- Evidence anchors:
  - [abstract] "We adopt an uncertainty-aware suppressed loss to alleviate the biased training between locally unseen and globally unseen classes."
  - [section 3.2.2] "Ri = 1/nu_i * sum |π(xu_j)| where π(xu_j) = ρ(nc|argmax_c p(xu_j;θ))[1 - max_c p(xu_j;θ)]"
  - [corpus] Weak evidence - related papers focus on class imbalance but don't explicitly discuss uncertainty-based suppression for federated open-world settings.
- Break condition: If uncertainty estimation becomes unreliable due to poor model calibration or if the confidence gap between locally and globally unseen classes is negligible.

### Mechanism 2
- Claim: The calibration module with global centroids prevents conflicting knowledge transfer by aligning heterogeneous classifier outputs across clients.
- Mechanism: After local training, each client uploads centroids computed via Sinkhorn-Knopp clustering. The server aggregates these into global centroids, which are then used as self-supervised targets (Lce_i and Lcluster_i) to align each client's classifier outputs on unseen classes, ensuring consistent labeling across clients.
- Core assumption: Sinkhorn-Knopp clustering produces consistent cluster assignments for the same unseen classes across different clients when given heterogeneous data distributions.
- Evidence anchors:
  - [abstract] "we enable a calibration module supplementary to the global aggregation to avoid potential conflicting knowledge transfer caused by inconsistent data distribution among different clients."
  - [section 3.2.3] "we introduce a calibration module to produce corresponding global centroids to perform dedicated local adjusting on each client."
  - [section 3.3] "Calculate local centroidsmi" and "Update global centroidsm"
- Break condition: If cluster assignment becomes unstable or if the number of local centroids is too small to capture class diversity.

### Mechanism 3
- Claim: Redefining unseen classes into locally unseen and globally unseen categories enables fine-grained treatment of training bias in federated settings.
- Mechanism: By recognizing that some unseen classes appear across multiple clients while others are client-specific, the framework can apply differentiated training strategies - collaboration benefits locally unseen classes while globally unseen classes need additional regularization and calibration support.
- Core assumption: The distinction between locally unseen and globally unseen classes meaningfully captures the heterogeneity of distributed data and its impact on training dynamics.
- Evidence anchors:
  - [abstract] "the locally unseen classes (exist in multiple clients) are likely to receive differentiated superior aggregation effects than the globally unseen classes (exist only in one client)."
  - [section 3.2] "Definition 1 (locally unseen & globally unseen class)" and "the advent of a certain unseen class depends on a client basis"
  - [corpus] Moderate evidence - related work addresses class imbalance but doesn't make this specific distinction in federated open-world settings.
- Break condition: If the locally vs globally unseen distinction doesn't correlate with actual training performance differences.

## Architecture Onboarding

- Component map:
  - Feature extractor (φ) -> Classifier (w) -> Uncertainty-aware loss module -> Calibration module -> Sinkhorn-Knopp clustering -> Server aggregation logic

- Critical path:
  1. Client downloads global model and centroids
  2. Client performs local training with uncertainty-aware loss
  3. Client computes local centroids
  4. Client uploads model parameters and centroids
  5. Server aggregates models (weighted average) and centroids (Sinkhorn-Knopp)
  6. Server distributes updated model and centroids

- Design tradeoffs:
  - Local vs global classifier: FedRep keeps classifiers local to avoid aggregation conflicts, while FedoSSL calibrates them using global centroids
  - Number of local centroids: More centroids provide better representation but increase communication cost
  - Uncertainty measurement: Confidence-based vs entropy-based uncertainty estimation

- Failure signatures:
  - Performance degradation on globally unseen classes despite good locally unseen accuracy
  - Instability in cluster assignments across communication rounds
  - Model convergence issues when β or γ parameters are poorly tuned

- First 3 experiments:
  1. Implement basic FedAvg with uncertainty-aware loss but without calibration module
  2. Add calibration module with fixed global centroids (no Sinkhorn-Knopp)
  3. Full FedoSSL with dynamic centroid computation and uncertainty-aware loss

## Limitations
- The framework's scalability to real-world federated settings with hundreds of clients and non-IID data remains theoretical, as experiments use only 4-8 clients
- The effectiveness of Sinkhorn-Knopp clustering for centroid aggregation hasn't been validated against simpler alternatives
- The assumption that uncertainty measured via softmax confidence reliably distinguishes locally vs globally unseen classes may not hold in more complex data distributions

## Confidence
- **High confidence**: The experimental methodology and baseline comparisons are sound
- **Medium confidence**: The core mechanisms (uncertainty-aware loss, calibration module) work as described in controlled settings
- **Low confidence**: Real-world applicability with heterogeneous client populations and complex data distributions
