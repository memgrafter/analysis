# Pre-train and Search: Efficient Embedding Table Sharding with Pre-trained Neural Cost Models

## Quick Facts
- arXiv ID: 2305.01868
- Source URL: https://arxiv.org/abs/2305.01868

## Executive Summary
NeuroShard introduces a novel "pre-train, and search" framework for optimizing embedding table sharding in distributed training of recommendation models. The framework pre-trains universal neural cost models on augmented data to predict computation and communication costs, enabling rapid cost estimation for any sharding plan. By combining these models with beam search and greedy grid search algorithms, NeuroShard jointly optimizes both column-wise and table-wise sharding decisions. When deployed on a production DLRM with multi-terabyte tables across 128 GPUs, the approach delivers significant improvements in both embedding costs and overall training throughput.

## Method Summary
NeuroShard addresses the challenge of embedding table sharding in distributed recommendation model training by introducing a two-phase approach: pre-training and searching. The framework first trains universal neural cost models that can predict computation and communication costs for any given sharding plan. These models are trained on augmented data to ensure generalization across different scenarios. During the search phase, NeuroShard employs beam search and greedy grid search algorithms to explore the sharding space efficiently. The key innovation is the ability to rapidly estimate costs for any sharding configuration without expensive profiling, enabling more thorough exploration of the optimization space and ultimately leading to better sharding decisions.

## Key Results
- Achieves up to 23.8% improvement in embedding costs over state-of-the-art methods on DLRM benchmark datasets
- Delivers 6.6% end-to-end training throughput improvement when deployed in production with multi-terabyte tables across 128 GPUs
- Demonstrates effectiveness of pre-trained neural cost models for rapid sharding optimization

## Why This Works (Mechanism)

The framework's effectiveness stems from its ability to decouple cost estimation from the search process. By pre-training neural models on augmented data, NeuroShard can quickly evaluate any sharding plan's computational and communication costs without expensive profiling. This enables more comprehensive exploration of the sharding space compared to methods that require costly evaluation of each candidate. The combination of beam search and greedy grid search allows for efficient joint optimization of both column-wise and table-wise sharding decisions, addressing the complexity of modern recommendation models with numerous large embedding tables.

## Foundational Learning

1. **Embedding Table Sharding** - The process of partitioning large embedding tables across multiple devices to enable distributed training
   - Why needed: Large embedding tables often exceed memory capacity of single devices
   - Quick check: Verify that total sharded size equals original table size

2. **Cost Modeling in Distributed Systems** - Predicting computational and communication costs for different hardware configurations
   - Why needed: Enables rapid evaluation of sharding strategies without expensive profiling
   - Quick check: Model predictions should correlate with actual measurements

3. **Beam Search Algorithm** - A heuristic search algorithm that explores a graph by expanding the most promising nodes
   - Why needed: Efficiently explores large sharding configuration spaces
   - Quick check: Beam width should balance exploration vs. computational cost

## Architecture Onboarding

**Component Map**: Data Augmentation -> Neural Cost Model Pre-training -> Beam Search -> Greedy Grid Search -> Sharding Plan Output

**Critical Path**: The framework's performance bottleneck lies in the pre-training phase of neural cost models, which must be comprehensive enough to handle diverse sharding scenarios while remaining computationally efficient.

**Design Tradeoffs**: The approach trades off model pre-training time and complexity against faster runtime optimization. More complex cost models could improve accuracy but would increase pre-training time and computational requirements.

**Failure Signatures**: Poor sharding performance may indicate insufficient diversity in pre-training data, inadequate neural model capacity, or suboptimal search algorithm parameters.

**First Experiments**:
1. Test cost model prediction accuracy against ground truth profiling on simple sharding configurations
2. Evaluate search algorithm performance with varying beam widths and grid resolutions
3. Measure pre-training time and model size requirements for different embedding table dimensions

## Limitations

- Framework primarily validated on DLRM models, with unclear performance on other recommendation architectures
- Scalability to larger GPU counts and more complex table configurations not extensively studied
- Performance heavily depends on quality and diversity of pre-training data for neural cost models

## Confidence

- **High Confidence**: Core methodology of pre-training cost models and using them for sharding optimization is technically sound
- **Medium Confidence**: Reported improvements are based on benchmark comparisons but need careful validation
- **Low Confidence**: Scalability claims based on single case study with 128 GPUs lack comprehensive analysis
