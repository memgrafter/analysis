# Query Understanding in the Age of Large Language Models

## Quick Facts
- arXiv ID: 2306.16004
- Source URL: https://arxiv.org/abs/2306.16004
- Reference count: 40
- One-line primary result: Interactive query rewriting using LLMs can reduce hard query rewrites by providing early user feedback on machine intent descriptions

## Executive Summary
This paper proposes replacing traditional multi-component query understanding pipelines with a single LLM-based component that generates natural language descriptions of machine intent. The framework presents these descriptions to users, allowing them to provide early feedback through three interaction modes: committing to a rewrite, editing the rewrite (soft rewrite), or exploring alternative intents (refinement). This approach aims to reduce hard query rewrites, improve transparency, and provide more interpretable explanations of ranking decisions. Initial experiments using GPT-3 variants show promising results in generating plausible rewrites that can potentially improve downstream retrieval performance, with in-context learning approaches performing particularly well.

## Method Summary
The framework uses LLMs to generate natural language descriptions of query intent, presenting multiple options to users for feedback. It leverages TREC Web Track queries (2009-2012) augmented with Google People Also Asked data, using few-shot prompting and in-context learning with models like BART, GPT2, and GPT3 variants. The approach focuses on qualitative evaluation of generated rewrites for plausibility and faithfulness to original intent, with the goal of reducing hard rewrites and improving downstream retrieval performance through interactive user feedback.

## Key Results
- LLM-generated intent descriptions can be plausible and faithful to original query intent
- In-context learning approaches with GPT-3 variants show particularly promising results for query rewriting
- The framework can potentially reduce hard query rewrites by providing early user feedback on machine intent

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Interactive query rewriting using LLMs can reduce hard query rewrites by providing early user feedback on machine intent
- Mechanism: The framework presents natural language descriptions of machine intent to users before retrieval, allowing them to commit, edit, or explore alternatives
- Core assumption: Users can understand and provide meaningful feedback on machine-generated intent descriptions
- Evidence anchors:
  - [abstract] "These descriptions are presented to users, allowing them to provide early feedback through three interaction modes: committing to a rewrite, editing the rewrite (soft rewrite), or exploring alternative intents (refinement)"
  - [section] "Our main contributions are outlined below: (1) A proposal to replace the multi-component query understanding pipeline with a monolithic LLM that can perform versatile query transformations"
- Break condition: If users cannot understand the machine intent descriptions or if the descriptions are too far from user intent, the framework fails to reduce hard rewrites

### Mechanism 2
- Claim: LLM-based query rewriters can generate more interpretable and controllable query transformations than traditional multi-component pipelines
- Mechanism: A single LLM replaces multiple query understanding components (spell checkers, classifiers, expansions) with natural language query descriptions
- Core assumption: LLMs can capture the complexity of query understanding that traditionally required multiple specialized components
- Evidence anchors:
  - [abstract] "This approach aims to reduce hard query rewrites, improve transparency, and provide more interpretable explanations of ranking decisions"
  - [section] "We propose a new paradigm for query understanding for keyword search and answer generation, where the aim of the re-writer query is to present a plausible natural language descriptions of the underlying machine intent to the user"
- Break condition: If the LLM cannot generate accurate or diverse enough intent descriptions, or if it performs worse than the traditional pipeline

### Mechanism 3
- Claim: User interaction data from query rewriting can provide more reliable training signals than click data, reducing position and trust biases
- Mechanism: Direct feedback on machine intents replaces indirect click-based feedback, providing clearer signals of user satisfaction
- Core assumption: Users will provide meaningful feedback on machine intent descriptions that correlates with actual relevance
- Evidence anchors:
  - [abstract] "We propose a design for a framework which incorporates direct and indirect feedback to fine-tune the rewriter and ranker to yield a mutually reinforcing relationship between the components"
  - [section] "We argue that our framework of collecting direct feedback data on interactive query understanding, to a large extent, reduces the over-dependence on click data and therefore substantially reduces some of the known biases"
- Break condition: If users do not provide consistent feedback or if the feedback does not correlate with actual relevance

## Architecture Onboarding

- Component map:
  User Interface -> LLM-based Query Rewriter -> Feedback Collector -> Ranker -> Training Module

- Critical path:
  1. User submits query
  2. LLM generates multiple machine intent descriptions
  3. User provides feedback (commit/edit/explore)
  4. Selected intent is used for retrieval
  5. Feedback is collected for training

- Design tradeoffs:
  - Model size vs. efficiency: Larger LLMs may generate better rewrites but are slower and more expensive
  - Number of intent descriptions: More descriptions provide better coverage but may overwhelm users
  - Feedback collection vs. user experience: More detailed feedback improves training but may increase user burden

- Failure signatures:
  - High rate of hard rewrites (users abandon machine intent descriptions)
  - Low diversity in generated intent descriptions
  - User confusion about machine intent descriptions
  - Poor downstream retrieval performance despite plausible rewrites

- First 3 experiments:
  1. Compare the quality of LLM-generated intent descriptions against human-written descriptions for a sample of queries
  2. Measure the reduction in hard rewrites when using the interactive framework versus traditional query understanding
  3. Test the correlation between user feedback on machine intent descriptions and actual document relevance

## Limitations

- The evaluation methodology relies heavily on qualitative assessment rather than quantitative validation of downstream retrieval performance
- The framework assumes users can meaningfully engage with and provide feedback on machine-generated intent descriptions, which remains largely untested
- The claim that user feedback will provide more reliable training signals than click data remains speculative without empirical validation

## Confidence

**High Confidence**: The technical feasibility of using LLMs for query rewriting and intent generation is well-established. The paper correctly identifies that LLMs can generate diverse, natural language descriptions of query intent, and the basic framework for interactive query rewriting is sound.

**Medium Confidence**: The claim that this approach can reduce hard query rewrites and improve transparency is plausible but not rigorously validated. While the qualitative examples show promising results, there's insufficient evidence that users will consistently understand and engage with the machine intent descriptions in practice.

**Low Confidence**: The assertion that user feedback on machine intent descriptions will provide more reliable training signals than click data remains speculative. The paper doesn't demonstrate that such feedback correlates with actual relevance or that it can effectively train the rewriter and ranker components.

## Next Checks

1. **A/B Test Retrieval Performance**: Implement a controlled experiment comparing traditional query understanding pipelines against the LLM-based interactive framework using standard retrieval metrics (NDCG, MRR) on a held-out test set of queries with relevance judgments.

2. **User Study on Intent Comprehension**: Conduct a user study where participants are shown both traditional query rewrites and LLM-generated intent descriptions, then measure their ability to understand each type and their confidence in selecting appropriate options.

3. **Bias Analysis of Feedback Data**: Collect a dataset of user feedback on machine intent descriptions and analyze whether this feedback exhibits position bias, trust bias, or other systematic patterns that might limit its effectiveness for training purposes.
