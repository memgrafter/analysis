# Towards Integration of Discriminability and Robustness for Document-Level Relation Extraction

## Quick Facts
- arXiv ID: 2304.00824
- Source URL: https://arxiv.org/abs/2304.00824
- Reference count: 8
- Achieves SOTA on DocRED, Re-DocRED, and robustness tests with up to 3-point F1 improvements

## Executive Summary
This paper introduces PEMSCL, a novel method for document-level relation extraction that addresses both discriminability and robustness challenges. PEMSCL integrates a pairwise moving-threshold loss with entropy minimization to sharpen distinctions between relations, along with supervised contrastive learning adapted for multi-label, long-tailed scenarios. The method also incorporates negative label sampling to improve robustness against annotation errors. Experimental results demonstrate state-of-the-art performance across standard benchmarks and new robustness evaluation regimes.

## Method Summary
PEMSCL combines several key components to improve document-level relation extraction: a pairwise moving-threshold loss with entropy minimization that dynamically adjusts classification thresholds to enhance discriminability between relation types; supervised contrastive learning adapted for multi-label and long-tailed distributions to learn more discriminative representations; and negative label sampling to mitigate the impact of annotation errors. These components work together to address both the inherent challenges of document-level relation extraction and the practical issues of noisy annotations.

## Key Results
- Achieves state-of-the-art performance on DocRED benchmark
- Demonstrates 3-point F1 improvements on robustness evaluation regimes
- Shows effectiveness on Re-DocRED (cleaned version of DocRED)
- Outperforms existing methods on long-tailed relation distributions

## Why This Works (Mechanism)
PEMSCL works by simultaneously optimizing for both discriminability and robustness. The pairwise moving-threshold loss with entropy minimization sharpens the decision boundaries between different relations by dynamically adjusting thresholds based on the current model predictions and relation distributions. This approach is particularly effective for long-tailed distributions where traditional fixed thresholds fail. The supervised contrastive learning component helps the model learn more discriminative representations by pulling together instances of the same relation type while pushing apart different types, adapted specifically for the multi-label nature of document-level relation extraction. The negative label sampling strategy improves robustness by explicitly accounting for annotation errors during training, allowing the model to learn from imperfect data without being overly influenced by noise.

## Architecture Onboarding
Component map: Input Documents -> Entity Pair Extraction -> Pairwise Moving-Threshold Loss + Entropy Minimization -> Supervised Contrastive Learning -> Negative Label Sampling -> Final Predictions

Critical path: The core training pipeline processes documents through entity pair extraction, applies the pairwise moving-threshold loss with entropy minimization for discriminability, incorporates supervised contrastive learning for representation quality, and uses negative label sampling for robustness. The model learns simultaneously from all these components through end-to-end training.

Design tradeoffs: The method balances between discriminability (through dynamic thresholds and contrastive learning) and robustness (through negative sampling), but this introduces additional computational complexity. The pairwise approach assumes independence between relation instances, which may not always hold. The contrastive learning component requires careful tuning of temperature parameters and batch size for optimal performance.

Failure signatures: Poor performance on extremely rare relations despite long-tail handling, overfitting to synthetic noise patterns rather than real annotation errors, threshold instability during training leading to oscillating performance, and degraded performance when negative sampling rate is too high.

## Limitations
- Evaluation on synthetic robustness tests may not fully represent real-world annotation noise
- Computational overhead of pairwise moving-threshold and contrastive learning not discussed
- Pairwise independence assumption may not hold for all document-level scenarios
- Code and data for new robustness evaluation sets not publicly available
