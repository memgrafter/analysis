# Privately generating tabular data using language models

## Quick Facts
- arXiv ID: 2306.04803
- Source URL: https://arxiv.org/abs/2306.04803
- Reference count: 20
- Primary result: Language model approach achieves better likelihood metrics than marginal-based methods while maintaining differential privacy

## Executive Summary
This paper introduces SynLM, a method for generating synthetic tabular data using transformer language models with differential privacy. The approach treats each table row as a sentence and trains a GPT-style model to predict column values sequentially, achieving competitive performance against state-of-the-art marginal-based methods. SynLM demonstrates better negative log-likelihood on most datasets while scaling linearly with the number of columns, making it particularly effective for complex data with higher dimensionality.

The method uses techniques like trie-guided generation to ensure valid outputs and achieves (ε=5, δ=10⁻⁶) differential privacy through DP-SGD. Results show SynLM outperforms AIM on likelihood metrics across multiple UCI datasets, particularly for complex data with higher dimensionality, while still approximating low-order marginal statistics reasonably well.

## Method Summary
SynLM treats tabular data generation as a sequence modeling problem, where each row is represented as a sentence with column values as tokens. A transformer language model is trained to predict each column value sequentially, conditioned on previous values. The model uses differential privacy (DP-SGD) to ensure privacy guarantees while generating synthetic data. Trie-guided generation ensures that only valid values from the training data are generated, maintaining data integrity. The approach scales linearly with the number of columns, unlike marginal-based methods that scale exponentially.

## Key Results
- SynLM achieves better negative log-likelihood than AIM across most UCI datasets
- Linear scaling with number of columns versus exponential scaling for marginal-based methods
- Achieves (ε=5, δ=10⁻⁶) differential privacy while maintaining data utility
- Particularly effective for complex data with higher dimensionality

## Why This Works (Mechanism)
The method works by leveraging the strong sequence modeling capabilities of transformers to capture dependencies between columns in tabular data. By treating each row as a sentence and training the model to predict column values sequentially, it can capture complex, higher-order relationships that marginal-based methods miss. The differential privacy mechanism (DP-SGD) adds calibrated noise during training to ensure privacy while the trie-guided generation maintains valid output spaces.

## Foundational Learning
1. **Differential Privacy (DP)** - Why needed: Ensures individual privacy when generating synthetic data from real datasets
   Quick check: Understand (ε, δ) parameters and how DP-SGD adds noise to gradients

2. **Transformer Language Models** - Why needed: Captures sequential dependencies and complex patterns in tabular data
   Quick check: Know how GPT-style models predict next tokens based on context

3. **Marginal-Based Methods** - Why needed: Current state-of-the-art for synthetic tabular data generation
   Quick check: Understand how they compute and sample from marginal distributions

4. **Trie-Guided Generation** - Why needed: Ensures generated values are valid and from the original data distribution
   Quick check: Understand how tries efficiently store and retrieve valid value sequences

5. **Negative Log-Likelihood (NLL)** - Why needed: Primary metric for evaluating generative model quality
   Quick check: Know how lower NLL indicates better model fit to data

6. **KL Divergence** - Why needed: Measures distributional similarity between real and synthetic data
   Quick check: Understand how it quantifies difference between probability distributions

## Architecture Onboarding

**Component Map**: Data Preprocessing -> Trie Construction -> Model Training (DP-SGD) -> Generation (Trie-Guided)

**Critical Path**: The most critical components are the transformer model architecture, the DP-SGD training loop with proper privacy accounting, and the trie-guided generation to ensure valid outputs.

**Design Tradeoffs**: The method trades computational efficiency during training (due to DP-SGD overhead) for better likelihood performance and linear scaling. The trie-guided generation ensures validity but may limit diversity compared to unrestricted sampling.

**Failure Signatures**: Poor likelihood metrics suggest the model isn't capturing data dependencies well. High privacy loss (ε) indicates insufficient noise addition. Invalid generated values suggest trie construction or generation issues.

**First Experiments**:
1. Train SynLM on a simple dataset (e.g., Iris) and verify it generates valid rows with reasonable likelihood
2. Compare NLL between SynLM and marginal-based methods on a medium-sized dataset
3. Test privacy accounting by varying noise multiplier and batch size to observe ε changes

## Limitations
- Evaluation focuses on likelihood metrics which may not fully capture utility for downstream tasks
- Computational scaling claims are theoretical with limited empirical runtime comparisons
- Performance on mixed data types and complex real-world dependencies needs more validation

## Confidence

**High confidence**: Core methodology of using transformers with differential privacy is technically sound and well-established.

**Medium confidence**: Claims about computational efficiency and scalability need more empirical validation. Comparison with marginal-based methods is limited to specific metrics and datasets.

**Medium confidence**: Privacy guarantees are theoretically sound but practical implications for different data domains need more exploration.
