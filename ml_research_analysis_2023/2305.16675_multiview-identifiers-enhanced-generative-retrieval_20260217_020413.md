# Multiview Identifiers Enhanced Generative Retrieval

## Quick Facts
- arXiv ID: 2305.16675
- Source URL: https://arxiv.org/abs/2305.16675
- Reference count: 12
- Primary result: MINDER achieves 65.8% and 29.5% in hits@5 on NQ and MSMARCO, respectively, outperforming previous generative retrieval methods.

## Executive Summary
This paper introduces MINDER, a generative retrieval framework that enhances passage ranking through synthetic and multiview identifiers. The approach generates pseudo-queries that span multiple sentences in passages, capturing contextualized information that traditional title-based or substring-based identifiers lack. By simultaneously considering titles, substrings, and synthetic identifiers through a multiview approach, MINDER achieves state-of-the-art results among generative retrieval methods on three widely-used datasets.

## Method Summary
MINDER employs BART-large as its core autoregressive language model, augmented with an FM-index data structure to enable constrained generation of valid identifiers. The framework generates synthetic identifiers (pseudo-queries) based on passage content spanning multiple segments, while also leveraging traditional title and substring views. During training, the model learns to generate these identifier sequences using labeled query-passage pairs, with pseudo-queries created through an unsupervised process. At inference, MINDER uses the FM-index to efficiently generate identifiers for ranking passages based on their coverage of query-related content.

## Key Results
- MINDER achieves 65.8% hits@5 on NQ dataset, outperforming previous generative retrieval methods
- On MSMARCO, MINDER reaches 29.5% hits@5, demonstrating strong performance on web search queries
- The multiview approach consistently outperforms single-view methods across all tested datasets

## Architecture Onboarding

- Component map: Query text + identifier prefix -> BART-large model -> FM-index -> Identifiers -> Ranking -> Passages
- Critical path: Query → Prefix → Model → FM-index → Identifiers → Ranking → Passages
- Design tradeoffs:
  - Memory vs. coverage: More identifier views improve coverage but increase memory usage
  - Generation speed vs. quality: Larger beam sizes improve quality but slow inference
  - Unsupervised data inclusion: Improves training but may introduce noise
- Failure signatures:
  - Poor retrieval performance: Check if FM-index is properly built and identifiers are being generated correctly
  - Slow inference: Verify beam size settings and FM-index efficiency
  - Memory issues: Monitor identifier storage requirements
- First 3 experiments:
  1. Verify FM-index can generate valid identifiers for each view type
  2. Test retrieval performance with single identifier view vs. multiview
  3. Evaluate impact of beam size on retrieval quality and speed
