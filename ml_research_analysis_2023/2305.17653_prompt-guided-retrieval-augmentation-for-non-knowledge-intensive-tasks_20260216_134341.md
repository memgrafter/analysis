# Prompt-Guided Retrieval Augmentation for Non-Knowledge-Intensive Tasks

## Quick Facts
- arXiv ID: 2305.17653
- Source URL: https://arxiv.org/abs/2305.17653
- Authors: 
- Reference count: 4
- Primary result: PGRA outperforms state-of-the-art retrieval-augmented methods on NKI tasks while maintaining low training cost

## Executive Summary
This paper explores retrieval-augmented methods for non-knowledge-intensive (NKI) tasks, which have been under-explored compared to knowledge-intensive tasks. The authors propose PGRA, a two-stage framework that addresses the challenge of diverse relevance score functions while avoiding expensive index updates. The method leverages a static task-agnostic retriever and a prompt-guided reranker to achieve strong performance across various NKI tasks including sentiment analysis, linguistic acceptability, question classification, and subjectivity analysis.

## Method Summary
PGRA is a two-stage framework that first uses a task-agnostic retriever to build a shared static index and select candidate evidence, then employs a prompt-guided reranker to reorder evidence based on task-specific relevance. The retriever uses BERT-base-uncased to encode evidence into dense representations, while the reranker leverages OPT-13b with in-context learning via task-specific prompts. A Fusion-in-Decoder reader using T5-base or T5-large generates final answers from the reranked evidence. The method avoids expensive training by using a static index and training-free prompt-guided reranking.

## Key Results
- PGRA outperforms state-of-the-art retrieval-augmented methods on NKI tasks
- Sentence-level evidence granularity significantly surpasses passage-level setup across all NKI tasks
- Maintains reasonably low training cost by avoiding periodical index updates
- Accuracy improvements range from 1-3% over baseline methods across different NKI tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: PGRA's two-stage retrieval process solves the training cost vs. performance dilemma by avoiding frequent index updates.
- Mechanism: A static, task-agnostic retriever is built once, followed by a training-free prompt-guided reranker that adds task-specific relevance without retraining the index.
- Core assumption: Static indexes can serve as effective initial candidates across diverse NKI tasks if reranking is sufficiently task-aware.
- Evidence anchors:
  - [abstract]: "By leveraging textual prompts, our framework can satisfy the demand for diverse relevance score functions. As both the retriever and the reranker are training-free, the expensive computational cost of periodical index update in training is avoided."
  - [section 2.1]: "In the first stage, we use a task-agnostic retriever to recall candidate evidence, which builds a shared static index for all tasks."
  - [section 2.2]: "To avoid expensive calculations for training a task-specific retriever per NKI task, we exploit the in-context learning ability of prompt-guided PLMs."
- Break condition: If task-specific evidence distribution varies drastically across tasks, static retriever recall quality drops below threshold for reranker to correct.

### Mechanism 2
- Claim: Task-specific relevance is better captured via prompt-guided PLM representations than fixed similarity functions.
- Mechanism: Few-shot prompts condition a large PLM to generate task-aware representations for both queries and evidence, enabling better alignment with task-specific relevance.
- Core assumption: PLMs can adapt their representations to reflect task-specific semantics via in-context learning without parameter updates.
- Evidence anchors:
  - [abstract]: "In the second stage, we design a prompt-guided reranker to rerank the nearest evidence according to task-specific relevance for the reader."
  - [section 2.2]: "Through in-context learning with prompt guidance, the representations of the inputs and external evidence encoded by the PLM implicitly contain different critical features to solve various tasks."
  - [section 4.1]: "We use a T5-base model fine-tuned on the specific task...to generate pseudo-label for all text in the external resource."
- Break condition: If prompt design is suboptimal, PLM representations may not capture task-specific nuances, reducing reranking effectiveness.

### Mechanism 3
- Claim: Sentence-level evidence granularity improves retrieval quality for NKI tasks compared to passage-level.
- Mechanism: Fine-grained sentence retrieval enables more precise matching of sentiment, acceptability, and other NKI signals than longer passages.
- Core assumption: NKI tasks depend on explicit, localized cues rather than context-heavy reasoning that benefits from passages.
- Evidence anchors:
  - [section 4.4]: "We use WikiDPR (Chen et al., 2017) as external resources...Across all NKI tasks, our sentence-level setup performances significantly surpass passage-level setup."
  - [section 2.3]: "To encode useful information from the reranked evidence and infer the final answer for the query text q..."
  - [corpus]: Weak evidence - no external citations in corpus confirming sentence-level superiority for NKI tasks.
- Break condition: If tasks require broader context, sentence-level retrieval may miss critical evidence spanning multiple sentences.

## Foundational Learning

- Concept: Dense retrieval via learned embeddings (e.g., DPR, SimCSE).
  - Why needed here: Enables efficient similarity search over large static indexes in the first stage.
  - Quick check question: What distance metric is used to rank evidence in the first-stage retriever?
- Concept: Prompt-based in-context learning.
  - Why needed here: Allows PLMs to simulate task-specific relevance scoring without fine-tuning.
  - Quick check question: How many examples are used per prompt in the reranker stage?
- Concept: Fusion-in-Decoder (FiD) architecture.
  - Why needed here: Reader stage must aggregate multiple retrieved evidences efficiently.
  - Quick check question: What is the role of cross-attention in the FiD reader?

## Architecture Onboarding

- Component map: Query → Dense retrieval (k candidates) → Prompt-guided reranking (d evidence) → FiD reader → Answer
- Critical path: Query → Dense retrieval (k candidates) → Prompt-guided reranking (d evidence) → FiD reader → Answer
- Design tradeoffs:
  - k vs. d: Larger k increases recall but computational cost; larger d improves evidence diversity but may dilute signal.
  - PLM size vs. cost: Larger OPT models improve consistency scores but increase inference latency.
  - Index granularity (sentence vs. passage): Sentence-level improves precision for NKI but may hurt tasks needing broader context.
- Failure signatures:
  - Low pseudo-label consistency → Reranker not capturing task-specific relevance.
  - Stable accuracy across k/d sweeps → Retriever recall already near optimal for task.
  - Degradation with larger k → Retriever noise outweighs recall gains.
- First 3 experiments:
  1. Vary k from 50 to 200 and plot accuracy to find saturation point.
  2. Swap sentence-level datastore for passage-level and measure performance drop.
  3. Replace prompt-guided reranker with fixed similarity (e.g., cosine) and compare results.

## Limitations
- Effectiveness on knowledge-intensive tasks remains under-explored
- Performance depends heavily on quality of pseudo-labels generated by task-specific models
- Prompt design quality significantly impacts reranking effectiveness but lacks systematic analysis

## Confidence
- **High confidence**: The core architectural claim that separating retriever and reranker improves training efficiency while maintaining performance is well-supported by ablation studies.
- **Medium confidence**: The claim that sentence-level evidence granularity outperforms passage-level for NKI tasks is supported by experimental results but lacks theoretical justification.
- **Low confidence**: The assertion that prompt-guided rerankers can effectively capture diverse task-specific relevance functions without task-specific fine-tuning is plausible but not rigorously validated across different prompt designs.

## Next Checks
1. **Prompt sensitivity analysis**: Systematically vary prompt templates and few-shot examples for each task to measure impact on reranking quality and downstream performance.
2. **Cross-task generalizability test**: Apply PGRA trained on one NKI task (e.g., sentiment analysis) to another NKI task (e.g., subjectivity analysis) without task-specific adaptation.
3. **Evidence quality attribution**: Analyze which retrieved evidence sentences most strongly influence correct predictions across tasks to understand whether the model is leveraging task-relevant features or exploiting spurious correlations.
