# Efficient and Direct Inference of Heart Rate Variability using Both Signal Processing and Machine Learning

## Quick Facts
- arXiv ID: 2303.13637
- Source URL: https://arxiv.org/abs/2303.13637
- Reference count: 40
- Primary result: Compound method combining signal processing and ML achieves 3.5-25.7% HRV estimation errors, outperforming signal-processing-only and ML-only approaches

## Executive Summary
This paper presents a compound method for directly estimating heart rate variability (HRV) metrics from photoplethysmography (PPG) signals by combining signal processing and machine learning. The approach first removes noise and generates heart rate estimations through signal processing, then applies ML models to directly infer HRV metrics (RMSSD/SDNN). Using a dataset of 2-hour PPG/ECG traces from one subject, the method demonstrates superior accuracy compared to signal-processing-only and ML-only approaches, with Decision Trees and Multi-layer Perceptrons showing particular promise for embedded devices.

## Method Summary
The method employs a two-stage approach: first, signal processing techniques (Z-score outlier adjustment and moving average smoothing) remove noise from raw PPG signals and generate heart rate estimations. Second, machine learning models (Decision Trees, Random Forests, K-Nearest Neighbors, Support Vector Machines, and Multi-layer Perceptrons) directly predict HRV metrics (RMSSD and SDNN) from the processed data. The method was evaluated using 2-hour PPG/ECG traces from one subject performing various activities, with hyperparameters tuned to avoid generating models too large for embedded devices.

## Key Results
- Compound method achieves 3.5% to 25.7% MAPE errors across activities, outperforming signal-processing-only and ML-only approaches
- Decision Trees and Multi-layer Perceptrons are most suitable for embedded devices with average errors of 13.0% and 9.1%
- Model sizes remain under 500KB and inference times under 1ms for embedded-compatible models

## Why This Works (Mechanism)

### Mechanism 1
Signal processing removes noise before ML inference by using Z-score outlier adjustment and moving average smoothing to eliminate large outliers and local noise from PPG signals. This preprocessing simplifies the ML model's task, allowing it to focus on subtle signal variations rather than removing gross artifacts.

### Mechanism 2
Direct inference of HRV metrics avoids error amplification from indirect methods. Instead of estimating RR intervals and then converting to HRV metrics (which amplifies errors), ML models directly predict RMSSD and SDNN from processed PPG data, bypassing the error multiplication that occurs in traditional approaches.

### Mechanism 3
Signal processing enables smaller, faster models suitable for embedded devices. By removing major noise components before ML inference, simpler models (Decision Trees, MLPs) can achieve good accuracy without the complexity required for ML-only approaches that must learn to denoise from raw signals.

## Architecture Onboarding

- **Component map**: PPG Signal Collection (25Hz) → Signal Processing (Peak detection, Z-score filtering, Moving average smoothing) → ML Model (DT, RF, KNN, SVM, MLP) → HRV Output (RMSSD, SDNN)

- **Critical path**: PPG → Signal Processing → ML Inference → HRV Output. Each component must function correctly; failure in early stages propagates to final output.

- **Design tradeoffs**:
  - Sampling rate (25Hz vs higher rates): Lower sampling saves power but may lose information
  - Signal processing complexity vs ML model size: More aggressive preprocessing enables smaller ML models
  - Direct HRV inference vs RR interval approach: Direct is more accurate but may be harder to train

- **Failure signatures**:
  - Poor signal quality: ML models produce erratic outputs or default to mean values
  - Insufficient training data for specific activity: High error rates for that activity type
  - Model overfitting: Excellent training performance but poor generalization

- **First 3 experiments**:
  1. Test signal processing pipeline alone on noisy PPG data to verify outlier removal and smoothing effectiveness
  2. Train simple ML model (DT) on processed data from one activity type to establish baseline performance
  3. Compare direct HRV inference vs RR interval approach on same dataset to quantify error amplification effects
