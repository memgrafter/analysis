# OneCAD: One Classifier for All image Datasets using multimodal learning

## Quick Facts
- arXiv ID: 2305.07167
- Source URL: https://arxiv.org/abs/2305.07167
- Reference count: 6
- Primary result: A multimodal learning framework that enables a single model architecture to classify datasets with varying numbers of classes without changing the architecture.

## Executive Summary
This paper introduces OneCAD, a framework that enables a single model architecture to classify datasets with varying numbers of classes without changing the architecture. The approach extends the PIXEL model by using multimodal learning with Masked-Image-Modeling (MIM), where rendered text labels are masked and the model learns to predict them. During inference, OCR is used to convert predicted text pixels back to class labels. Preliminary results show good accuracy on MNIST, CIFAR10, CIFAR100, and COVIDx datasets, with potential for improvement through better OCR and pretraining.

## Method Summary
OneCAD adapts the PIXEL model—a Vision Transformer with a lightweight decoder—to multimodal learning by embedding both the resized image and a rendered text label onto a fixed 368x368 canvas. The label text patches are masked during training, and the model learns to reconstruct them via MIM. At inference, the predicted text region is cropped and OCR is used to recover the class name. This design avoids explicit classification layers, making the architecture independent of the number of classes.

## Key Results
- Model achieves competitive accuracy on MNIST, CIFAR10, CIFAR100, and COVIDx without architecture changes.
- Accuracy can be further improved with more training epochs, multi-modal pretraining, and better OCR.
- OCR accuracy is sensitive to brightness variations in predicted text pixels.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Using rendered text pixels as class representation avoids the need for one-hot encoding and its parameter explosion.
- Mechanism: Each class label is rendered as an image patch sequence, and the model learns to predict these text pixels using MIM, thereby representing any number of classes with a fixed number of output patches.
- Core assumption: Text pixels can be rendered and reconstructed reliably by the PIXEL model, and OCR can convert them back to class names during inference.
- Evidence anchors:
  - [abstract] "Representing and predicting the class output by visual-text allows model to predict large number of classes with limited number of pixels/patches."
  - [section] "This work proposes a solution using multi-modal learning as shown in Figure 1. Masked-Auto-Encoder (MAE) Vision-Transformer model called PIXEL (Rust et al., 2022) is used to predict the masked image patches with class name (text) in it."
- Break condition: OCR fails to recognize predicted text due to inconsistent brightness or rendering quality, causing accuracy to drop significantly.

### Mechanism 2
- Claim: The PIXEL model's decoder reconstructs the full image, so predicting masked text patches is a form of masked language modeling that can be repurposed for classification.
- Mechanism: During training, the label text patches are masked; the decoder learns to reconstruct them from context, thus learning the mapping between image content and label text without explicit classification layers.
- Core assumption: The decoder's reconstruction loss encourages it to infer the correct text pixels from the masked image patches.
- Evidence anchors:
  - [section] "Mean-squared-error loss is used as loss function during training."
  - [section] "The PIXEL model takes this masked input image and tries predicts text-pixels matching to the label."
- Break condition: The reconstruction loss is too weak or the decoder lacks capacity to infer correct text pixels, leading to poor classification accuracy.

### Mechanism 3
- Claim: Using a fixed 368x368 canvas with embedded image and rendered text allows a single model architecture to handle datasets of varying class counts.
- Mechanism: The input size and patch structure remain constant regardless of the number of classes; only the text rendered changes.
- Core assumption: The Vision Transformer processes patches independently enough that class count does not affect the architecture.
- Evidence anchors:
  - [abstract] "This allows model’s architecture to be independent of the dataset it is trained on."
  - [section] "When running classiﬁcation task on different datasets, there is no change in model architecture."
- Break condition: If the number of classes grows beyond the capacity of the fixed text patch sequence (e.g., more than ~1014 words with 10 patches), collisions or ambiguity may occur.

  - Why needed here: OCR converts predicted text pixels back to class labels; its accuracy directly affects classification performance.
  - Quick check question: Why might OCR fail when the brightness of predicted text varies?

## Architecture Onboarding

- Component map: Input layer (368x368 image + rendered text) -> ViT encoder (16x16 patches → 529 patches) -> Light-weight decoder (368x368 output) -> MSE loss -> OCR inference on 32x160 cropped text region

- Critical path:
  1. Prepare 368x368 input (resize image + render label)
  2. Mask label text patches
  3. Forward through ViT encoder
  4. Decode to full image
  5. During inference, OCR predicted text region

- Design tradeoffs:
  - Fixed input size (368x368) simplifies architecture but may waste computation for small datasets
  - Text rendering quality vs. OCR accuracy
  - Number of text patches vs. class vocabulary size

- Failure signatures:
  - OCR cannot read predicted text → accuracy drops
  - Decoder fails to reconstruct text → high MSE loss
  - Model overfits to training text rendering style → poor generalization

- First 3 experiments:
  1. Train on MNIST with varying brightness scaling to test OCR robustness
  2. Evaluate CIFAR10 accuracy with and without image normalization
  3. Test COVIDx binary classification with varying training set sizes

## Limitations

- The reliance on OCR introduces brittleness; text brightness or rendering quality variations can cause significant accuracy drops.
- Lack of explicit PIXEL model architecture details and unspecified training hyperparameters makes faithful reproduction difficult.
- Scalability to very large numbers of classes has not been demonstrated; the fixed 10-text-patch limit may cause collisions or ambiguity.

## Confidence

- High Confidence: The multimodal MIM framework can, in principle, decouple class count from architecture design, as evidenced by consistent experimental setup across datasets.
- Medium Confidence: Preliminary accuracy results on MNIST, CIFAR-10/100, and COVIDx suggest the approach works, but the OCR bottleneck and lack of large-scale class tests temper strong conclusions.
- Low Confidence: Claims about robustness to brightness scaling and generalization to very large vocabularies are not yet validated empirically.

## Next Checks

1. **OCR Robustness Under Brightness Perturbation**: Systematically vary text brightness and font rendering in MNIST test images; measure OCR accuracy and downstream classification performance to quantify the sensitivity to rendering quality.

2. **Scaling Test on Large-Vocabulary Dataset**: Apply OneCAD to a dataset with >1,000 classes (e.g., iNaturalist) to empirically test whether the fixed 10-text-patch limit remains sufficient or causes accuracy degradation.

3. **Hyperparameter Sensitivity Analysis**: Re-run CIFAR-10 experiments across a grid of learning rates and batch sizes; document performance variance to assess how much tuning is required for stable results.
