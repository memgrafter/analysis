# PromptRank: Unsupervised Keyphrase Extraction Using Prompt

## Quick Facts
- arXiv ID: 2305.04490
- Source URL: https://arxiv.org/abs/2305.04490
- Authors: 
- Reference count: 40
- Key outcome: PromptRank outperforms state-of-the-art MDERank with significant F1@5/10/15 improvements across 6 datasets

## Executive Summary
This paper introduces PromptRank, an unsupervised keyphrase extraction method that leverages prompt learning with an encoder-decoder architecture. The approach calculates the probability of generating candidate-filled prompts using a pre-trained language model, incorporating position information to adjust final scores. Experiments demonstrate that PromptRank achieves state-of-the-art performance across six widely used datasets, showing the effectiveness of prompt-based methods for keyphrase extraction.

## Method Summary
PromptRank extracts keyphrases by ranking candidate phrases based on their probability of being generated as part of a designed prompt. The method feeds the document into an encoder and calculates the probability of generating the candidate-filled prompt using a decoder. Position information is incorporated to adjust the final score of each candidate. The approach uses T5-base as the default PLM and evaluates performance using F1@5, F1@10, and F1@15 metrics across six datasets including Inspec, SemEval2017, SemEval2010, DUC2001, NUS, and Krapivin.

## Key Results
- PromptRank outperforms MDERank, the previous state-of-the-art method
- Achieves significant F1 score improvements for 5, 10, and 15 returned keyphrases
- Demonstrates effectiveness of prompt-based probability ranking for unsupervised keyphrase extraction

## Why This Works (Mechanism)

### Mechanism 1
- Claim: PromptRank leverages encoder-decoder architecture to align document and candidate representations in a shared latent space.
- Mechanism: The document is fed into the encoder and the probability of generating the candidate-filled prompt is calculated by the decoder. Higher probability indicates better alignment between document and prompt, suggesting the candidate is more important.
- Core assumption: The encoder-decoder architecture can effectively map document and prompt to a shared latent space where similarity reflects importance.
- Evidence anchors:
  - [abstract] "PromptRank feeds the document into the encoder and calculates the probability of generating the candidate with a designed prompt by the decoder."
  - [section 2] "We employ an encoder-decoder architecture to transform the original document and candidate-filled templates into a shared latent space."
  - [corpus] Weak - no direct evidence, but related papers like "Pre-Trained Language Models for Keyphrase Prediction: A Review" support the general approach of using PLMs for keyphrase extraction.
- Break condition: If the encoder-decoder architecture fails to align document and prompt representations, or if the probability calculation does not reflect true importance.

### Mechanism 2
- Claim: Position penalty modulates the log probability of candidates based on their position in the document.
- Mechanism: Candidates appearing earlier in the document receive a smaller position penalty, increasing their final score. The position penalty is calculated as pos/len + β, where pos is the position of the first occurrence, len is the document length, and β is a parameter that decreases with document length.
- Core assumption: Candidates appearing earlier in a document are more likely to be keyphrases.
- Evidence anchors:
  - [section 3.3] "When writing an article, it is common practice to begin with the main points of the article... we use a position penalty to modulate the log probability of the candidate."
  - [section 4.4] "Results show that most datasets fit this conjecture [that position information is effective]."
  - [corpus] Weak - no direct evidence, but the general intuition that important information appears early in documents is widely accepted.
- Break condition: If the position information does not correlate with importance, or if the dynamic adjustment of β is not optimal.

### Mechanism 3
- Claim: Using prompts mitigates the length discrepancy between documents and candidates that plagues embedding-based methods.
- Mechanism: By filling candidates into a designed prompt template, the length of the candidate representation is increased to be more comparable to the document length. This allows for more effective comparison between document and candidate.
- Core assumption: Increasing the length of candidate representations to match document length improves the effectiveness of similarity calculations.
- Evidence anchors:
  - [abstract] "We propose to expand the candidate length by putting them into a well-designed template (i.e., prompt)."
  - [section 2] "Inspired by the work CLIP... we propose to expand the candidate length by putting them into a well-designed template (i.e., prompt)."
  - [section 4.4] "Templates with lengths greater than or equal to 5 better solve the length discrepancy, providing guidance for template selection."
  - [corpus] Weak - no direct evidence, but the general approach of using prompts to handle length discrepancies is supported by related work like "Enhancing Keyphrase Extraction from Long Scientific Documents using Graph Embeddings".
- Break condition: If the prompt template does not effectively increase candidate length or if the increased length does not improve similarity calculations.

## Architecture Onboarding

- Component map:
  Document input -> Encoder (T5-base) -> Prompt templates -> Decoder (T5-base) -> Position information module -> Candidate ranking module

- Critical path:
  1. Generate candidate set from document
  2. For each candidate, fill into prompt template
  3. Feed document to encoder
  4. Calculate probability of generating filled prompt by decoder
  5. Calculate position penalty
  6. Combine probability and penalty to get final score
  7. Rank candidates by final score

- Design tradeoffs:
  - Using T5-base vs other PLMs: T5-base offers a good balance of performance and computational efficiency, but other PLMs like BART or larger T5 variants might offer better performance at higher computational cost.
  - Prompt template design: Hand-crafted templates require manual effort but can be optimized for performance, while automated template generation would be more scalable but might not achieve optimal results.
  - Position penalty calculation: The dynamic adjustment of β based on document length helps adapt to different document lengths, but the exact formula might need tuning for optimal performance.

- Failure signatures:
  - Poor performance on long documents: This could indicate issues with the prompt template design or the encoder-decoder architecture's ability to handle long inputs.
  - Inconsistent performance across datasets: This could suggest the position penalty calculation or prompt template design is not robust across different domains.
  - Slow inference time: This could indicate the encoder-decoder architecture is too computationally expensive, or the prompt templates are too long and complex.

- First 3 experiments:
  1. Vary the length of the prompt template (0, 2, 5, 10, 20) and measure the impact on performance across different document lengths.
  2. Experiment with different noun words in the prompt template (e.g., "Book", "Passage", "News") and measure the impact on performance.
  3. Compare the performance of PromptRank using different PLMs (e.g., T5-base, T5-large, BART-base, BART-large) to identify the best model for the task.

## Limitations
- The reliance on hand-crafted prompt templates may limit generalizability across different document types and domains
- The position penalty mechanism assumes early position correlates with importance, which may not hold for all document genres
- Performance improvements are primarily demonstrated on English datasets, raising questions about cross-lingual applicability

## Confidence
- High Confidence: The fundamental mechanism of using encoder-decoder architecture to calculate generation probability is well-supported by experimental results and aligns with established PLM principles
- Medium Confidence: The effectiveness of position information incorporation shows promise but may be dataset-dependent
- Low Confidence: The generalizability of prompt template design choices across different domains and languages is not thoroughly validated
