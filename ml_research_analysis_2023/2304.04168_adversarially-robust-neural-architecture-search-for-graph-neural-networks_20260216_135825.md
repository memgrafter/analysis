# Adversarially Robust Neural Architecture Search for Graph Neural Networks

## Quick Facts
- arXiv ID: 2304.04168
- Source URL: https://arxiv.org/abs/2304.04168
- Reference count: 40
- Key outcome: Proposed NAS framework achieves 12.1% to 23.4% accuracy improvements under adversarial attacks compared to manually designed robust GNNs and vanilla graph NAS baselines.

## Executive Summary
This paper introduces a novel neural architecture search (NAS) framework designed to automatically discover robust graph neural network (GNN) architectures that can defend against adversarial attacks. The key innovation lies in designing a specialized search space that incorporates graph structure mask operations as defensive mechanisms. By combining this search space with a custom robustness metric based on KL divergence and an evolutionary search algorithm, the framework can identify architectures that maintain performance under graph perturbations. Experimental results demonstrate significant improvements in adversarial robustness across multiple benchmark datasets.

## Method Summary
The method constructs a supernet containing all possible GNN architectures based on a fine-grained search space that includes six adjustable components: graph structure mask, node correlation coefficient, neighbor aggregator, combine function, skip connection, and layer aggregator. The framework trains this supernet using a single-path one-shot approach, then employs an evolutionary algorithm to search for robust architectures. The search uses a custom robustness metric that measures the KL divergence between predictions on clean and perturbed graphs. Top architectures are then retrained from scratch and evaluated under various perturbation rates.

## Key Results
- Achieves 12.1% to 23.4% accuracy improvements over manually designed robust GNNs under adversarial attacks
- Demonstrates consistent robustness gains across Cora, CiteSeer, PubMed, ogbn-arxiv, Amazon photo, and Wisconsin datasets
- Shows effectiveness of graph structure mask operations through ablation studies
- Provides insights into robustness mechanisms of GNN architectures

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The proposed search space includes graph structure mask operations that can defend against adversarial attacks.
- Mechanism: By adding graph structure mask operations into the search space, the framework can automatically select the most appropriate defensive strategies when confronting perturbed graphs. These mask operations include low rank approximation, node feature similarity, neighbor importance estimation, and variable power operator, which cover important robust essences of graph structure.
- Core assumption: The graph structure mask operations can effectively identify and mitigate the impact of adversarial perturbations in the graph structure.
- Evidence anchors:
  - [abstract]: "Specifically, the search space includes defensive operation candidates such as low rank approximation, node feature similarity, neighbor importance estimation, and variable power operator."
  - [section]: "We design a fine-grained search space following the message-passing paradigm. In total, there are six adjustable components in our GNN architecture: the graph structure mask, the nodes correlation coefficient, the neighbor aggregator, the combine function, the skip connection, and the layer aggregator."
- Break condition: If the graph structure mask operations fail to identify the true structure of the graph or introduce too much noise, the framework's robustness will be compromised.

### Mechanism 2
- Claim: The robustness metric can properly measure the architecture's robustness and guide the search procedure.
- Mechanism: The robustness metric is defined as the negative expected Kullback-Leibler divergence between the model's predictions on clean and perturbed graphs. This metric encourages the search algorithm to find architectures that are less sensitive to adversarial perturbations.
- Core assumption: The Kullback-Leibler divergence is a suitable measure of the difference between the model's predictions on clean and perturbed graphs.
- Evidence anchors:
  - [section]: "We define a robustness metric as R(A, f) = -EA'[1/N ∑i=1N DKL(f(A)i||f(A')i)], A' = TΔ(A), where f indicates the GNN, f(A)i is the probability prediction vector for node i and DKL(p||q) = ∑i pi log pi/qi denotes the Kullback-Leibler (KL) divergence between two distribution p and q."
  - [section]: "A larger R(A, f) indicates a smaller distance between the prediction of clean data and the perturbed data, and consequently, more robust GNN architectures."
- Break condition: If the robustness metric does not accurately reflect the model's true robustness or if the search algorithm is unable to find architectures that optimize this metric, the framework's performance will be limited.

### Mechanism 3
- Claim: The evolutionary algorithm can effectively search for optimal robust architectures based on the proposed robustness metric.
- Mechanism: The evolutionary algorithm uses the fitness function ACCval(α) + λR(α) to select top-k robust candidates and generate new architectures through crossover and mutation operations. This process is repeated for a fixed number of iterations to find the best architectures.
- Core assumption: The evolutionary algorithm can efficiently explore the search space and find architectures that optimize the fitness function.
- Evidence anchors:
  - [section]: "In our work, we adopt an evolutionary algorithm to search for optimal robust graph architectures with the proposed robustness metric. Instead of training each candidate architecture from scratch, we leverage the evolutionary algorithm only for inference and search."
  - [section]: "In one search epoch, we select top-k robust candidates via the fitness function ACCval(α)+ λR(α). Crossover and mutation are followed to generate children architectures from population candidates."
- Break condition: If the evolutionary algorithm gets stuck in local optima or fails to explore the search space effectively, it may not find the truly optimal robust architectures.

## Architecture Onboarding

- Component map:
  - Search Space: Graph structure mask operations, correlation coefficients, neighbor aggregators, combine functions, skip connections, layer aggregators
  - Supernet: Contains all possible architectures based on the search space
  - Robustness Metric: Measures the architecture's robustness using KL divergence between clean and perturbed graph predictions
  - Evolutionary Algorithm: Searches for optimal robust architectures based on the robustness metric and validation accuracy
  - Retraining: Retrains the top-selected architectures from scratch for final evaluation

- Critical path:
  1. Construct the supernet based on the designed search space
  2. Train the supernet in a single-path one-shot way
  3. Generate adversarial samples using an attack proxy
  4. Search for robust architectures using the evolutionary algorithm and robustness metric
  5. Retrain the top-selected architectures from scratch
  6. Evaluate the final architectures on perturbed graphs

- Design tradeoffs:
  - Search space complexity vs. computational efficiency: A more expressive search space may lead to better performance but also increase the search time and computational cost.
  - Robustness vs. accuracy: There may be a trade-off between the robustness of the architecture and its performance on clean data.
  - Attack proxy strength vs. generalizability: Using a stronger attack proxy may lead to more robust architectures but may also overfit to that specific attack.

- Failure signatures:
  - Poor performance on clean data: Indicates that the search process may have overfit to robustness at the expense of accuracy.
  - Sensitivity to the choice of attack proxy: If the architecture's robustness varies significantly depending on the attack proxy used, it may not generalize well to unseen attacks.
  - Long search times or convergence issues: Suggests that the search space may be too complex or the optimization algorithm may need tuning.

- First 3 experiments:
  1. Evaluate the performance of the proposed method on a clean graph dataset to ensure that the search process does not degrade the model's accuracy.
  2. Test the robustness of the searched architectures against a simple adversarial attack (e.g., random edge perturbation) to verify that the method can defend against basic attacks.
  3. Compare the performance of the proposed method with a strong adversarial attack (e.g., Nettack) to assess its effectiveness against more sophisticated attacks.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the proposed robustness metric (KL divergence between clean and adversarial predictions) relate to actual model performance under unseen adversarial attacks?
- Basis in paper: [explicit] The paper defines the robustness metric R(A, f) using KL divergence between predictions on clean and perturbed graphs, and shows it correlates with accuracy decrease under Mettack.
- Why unresolved: The evaluation only considers one specific attack (Mettack) with a fixed perturbation budget. It's unclear if this metric generalizes to other attack methods or perturbation rates.
- What evidence would resolve it: Extensive experiments comparing the metric's predictive power across multiple attack methods (random, DICE, Nettack) and varying perturbation budgets would demonstrate its generalizability.

### Open Question 2
- Question: What is the optimal balance between model accuracy and robustness when tuning the hyperparameter λ in the search process?
- Basis in paper: [explicit] The paper mentions that λ balances accuracy and robustness in the fitness function, and conducts sensitivity analysis showing trade-offs at different λ values.
- Why unresolved: The paper doesn't provide a principled method for selecting λ, only suggesting a range based on empirical results. The optimal value likely depends on the specific application's risk tolerance.
- What evidence would resolve it: Developing a systematic approach to determine λ based on application requirements, or providing a sensitivity analysis across more datasets and attack scenarios would help establish best practices.

### Open Question 3
- Question: How does the proposed framework handle feature-based adversarial attacks in addition to structural attacks?
- Basis in paper: [inferred] The framework focuses on structural attacks through graph structure mask operations, but the appendix mentions an extension to feature attacks using a similar KL divergence metric.
- Why unresolved: The paper only evaluates the framework on structural attacks, and the feature attack extension is not experimentally validated.
- What evidence would resolve it: Experimental results comparing the framework's performance on feature attacks versus structural attacks, and demonstrating the effectiveness of the proposed feature attack extension would validate its applicability to this important attack vector.

## Limitations
- The method's robustness is primarily evaluated against the Mettack attack, with unknown performance against other attack strategies like feature injection or node deletion.
- The computational cost of the evolutionary search with robustness evaluation across multiple perturbed graphs may limit scalability to larger graph datasets.
- The framework focuses on structural attacks through graph structure mask operations, with the feature attack extension not experimentally validated.

## Confidence
- **High Confidence:** The effectiveness of the proposed search space with graph structure mask operations is well-supported by experimental results showing consistent improvements over baselines.
- **Medium Confidence:** The robustness metric's ability to guide the search is supported by ablation studies, but the choice of KL divergence as the optimal measure could benefit from comparison with alternatives.
- **Medium Confidence:** The evolutionary algorithm's search efficiency is demonstrated, but the sensitivity to hyperparameters like population size and mutation rate requires further investigation.
