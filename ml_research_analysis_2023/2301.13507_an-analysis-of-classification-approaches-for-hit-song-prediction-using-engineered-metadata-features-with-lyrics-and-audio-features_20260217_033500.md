# An Analysis of Classification Approaches for Hit Song Prediction using Engineered Metadata Features with Lyrics and Audio Features

## Quick Facts
- arXiv ID: 2301.13507
- Source URL: https://arxiv.org/abs/2301.13507
- Reference count: 21
- Primary result: Random Forest with engineered metadata features achieves 89.1% accuracy and 0.91 AUC for hit song prediction

## Executive Summary
This study investigates hit song prediction using machine learning with engineered metadata features, including Spotify audio features, song lyrics, and novel metadata (title topic, popularity continuity, genre class). Five models—kNN, Naive Bayes, Random Forest, Logistic Regression, and MLP—were trained and tested on Billboard Hot 100 data. Random Forest and Logistic Regression with all features achieved the highest accuracy (89.1% and 87.2%) and AUC (0.91 and 0.93), outperforming baseline models. Novel features significantly improved performance, with popularity continuity and lyrics topics contributing most to discriminative power.

## Method Summary
The study combines Billboard Hot 100 chart data (2007-2017) with Spotify audio features and song lyrics to predict top 10 hits. Researchers engineered novel metadata features including popularity continuity (chart duration), genre class, and topic models for song titles and lyrics using LDA. Five classification models were trained: kNN, Naive Bayes, Random Forest, Logistic Regression, and MLP. The dataset was split 80:20 for training and testing, with SMOTE oversampling applied to address class imbalance. Forward feature selection was used to optimize feature sets, and models were evaluated using 5-fold cross-validation with accuracy and AUC metrics.

## Key Results
- Random Forest achieved highest accuracy (89.1%) and AUC (0.91) when using all features including engineered metadata
- Logistic Regression performed second-best with 87.2% accuracy and 0.93 AUC
- Novel metadata features (popularity continuity, genre class, title topic) contributed most to model discriminative performance
- Popularity continuity showed strong predictive power, indicating chart duration correlates with hit potential

## Why This Works (Mechanism)

### Mechanism 1
Combining engineered metadata features with audio and lyrics features improves hit song prediction accuracy. Metadata features capture cultural and temporal context that audio and lyrics alone cannot, while audio features encode timbral and rhythmic properties. The combination provides complementary predictive signals. Core assumption: Different feature types encode independent information about song success; their combination yields non-redundant predictive power. Evidence anchors: Random Forest and Logistic Regression with all features outperform other models; novel music metadata features contributed most to discriminative performance.

### Mechanism 2
Popularity continuity is a strong predictor because it encodes prior chart performance and audience familiarity. Songs already present in the chart for more weeks have higher exposure and social proof, increasing likelihood of becoming hits. This temporal signal is not captured by static audio features. Core assumption: Chart duration correlates with hit potential beyond the intrinsic song qualities. Evidence anchors: The utility of popularity continuity indicates that longer chart presence increases hit likelihood. Break condition: If popularity continuity is a proxy for already successful songs, it may not generalize to new releases.

### Mechanism 3
Topic modeling of song titles and lyrics reveals thematic signals that distinguish hits from non-hits. Certain topics (e.g., love, relationships) appear more frequently in hit songs. Latent topics capture cultural resonance that is not directly encoded in audio features. Core assumption: Thematic content of lyrics and titles has predictive power independent of musical characteristics. Evidence anchors: Certain topically-coherent sets of terms are more likely to appear in hits than non-hits. Break condition: If topic distributions are uniform across hits and non-hits, thematic modeling adds no value.

## Foundational Learning

- Concept: Feature engineering and selection
  - Why needed here: The study shows that engineered features outperform raw audio/lyrics features. Understanding how to create and select such features is critical.
  - Quick check question: What steps would you take to engineer a new feature from song metadata, and how would you validate its predictive power?

- Concept: Handling class imbalance in classification
  - Why needed here: The dataset is highly imbalanced (few hits vs many non-hits). SMOTE is used to oversample the minority class, which is essential for training effective models.
  - Quick check question: How does SMOTE work, and what are potential pitfalls of using it in highly imbalanced datasets?

- Concept: Model evaluation metrics (accuracy vs AUC)
  - Why needed here: The study reports both accuracy and AUC. Accuracy can be misleading in imbalanced datasets; AUC better captures ranking ability.
  - Quick check question: When would you prioritize accuracy over AUC, and vice versa, in a binary classification task?

## Architecture Onboarding

- Component map: Data ingestion -> preprocessing (cleaning, normalization) -> feature engineering (metadata, topics, audio) -> class balancing (SMOTE) -> model training (kNN, NB, RF, LR, MLP) -> evaluation (accuracy, AUC) -> feature importance analysis
- Critical path: Feature engineering -> SMOTE balancing -> model training -> evaluation. Without proper feature engineering, models underperform; without balancing, minority class is ignored.
- Design tradeoffs: Rich feature set improves accuracy but increases training time and complexity. Simpler models (NB) are faster but less accurate. Deep models (MLP) need more data to avoid overfitting.
- Failure signatures: Low AUC despite high accuracy indicates poor ranking of hits. Overfitting is signaled by high training accuracy but low test accuracy. Missing feature importance suggests redundant or noisy features.
- First 3 experiments:
  1. Train baseline model (e.g., RF) using only audio features; record accuracy/AUC.
  2. Add engineered metadata features; compare performance gain.
  3. Apply SMOTE and retrain; verify improvement in minority class recall.

## Open Questions the Paper Calls Out

### Open Question 1
How do temporal factors affect hit song prediction accuracy over longer time periods? The paper mentions they intend to consider more complex models that include temporal aspects to model changes in genres and topical popularity over time as future work. Why unresolved: The current study treats each song as an individual and does not consider temporal factors in their experiment. What evidence would resolve it: Testing the current models on extended time periods with temporal features included and comparing accuracy metrics.

### Open Question 2
Which audio features contribute most to hit song prediction when combined with metadata and lyrics features? The paper notes that some of the Spotify audio features such as key, liveness, energy, and danceability are also important when classifying hit songs but less consistently so than novel features and song lyrics feature. Why unresolved: While some audio features were identified as important, the relative contribution of different audio features was not thoroughly analyzed or compared. What evidence would resolve it: Systematic ablation studies testing different combinations of audio features with metadata and lyrics to determine individual feature importance scores.

### Open Question 3
How generalizable are the models to songs outside the Billboard Top 100 charts? The paper states the model generalisation ability may need more tests, particularly adding songs never achieved in billboard top 100. Why unresolved: The current models were only tested on songs that appeared in the Billboard Hot 100, not on songs that never charted. What evidence would resolve it: Testing the trained models on datasets containing songs that never appeared in any charts and measuring performance metrics on this out-of-distribution data.

## Limitations

- Model relies heavily on popularity continuity, which may not generalize to new songs without prior chart performance
- Dataset spans 2007-2017, potentially missing recent trends in music consumption
- Feature engineering procedures, particularly LDA topic modeling parameters and SMOTE implementation details, lack full specification

## Confidence

- **High confidence**: The comparative model performance (RF > LR > other models) and the benefit of engineered metadata features are well-supported by the experimental results.
- **Medium confidence**: The mechanism by which popularity continuity predicts hits is plausible but not rigorously tested against alternative explanations.
- **Medium confidence**: Topic modeling utility is demonstrated but could be affected by preprocessing choices and topic coherence quality.

## Next Checks

1. **Temporal validation**: Retrain models using only data from 2007-2012 and test on 2013-2017 to assess temporal generalization.
2. **Ablation study**: Systematically remove each engineered feature to quantify individual contribution to performance.
3. **Cross-dataset evaluation**: Test the trained models on a separate hit prediction dataset to assess domain transferability.
