# A Model for Translation of Text from Indian Languages to Bharti Braille Characters

## Quick Facts
- arXiv ID: 2305.06475
- Source URL: https://arxiv.org/abs/2305.06475
- Reference count: 16
- Key outcome: Hybrid approach combining rule-based mapping and LSTM disambiguation achieved 100% overall accuracy across 13 Indian languages and 10 scripts

## Executive Summary
This paper presents a hybrid system for converting text from major Indian languages into Bharti Braille. The approach combines a rule-based transliteration system with an LSTM-based disambiguation model. The rule-based component handles the majority of straightforward character-to-Braille mappings using predefined transliteration rules for consonants, vowels, and vowel symbols. When ambiguities arise with characters that have multiple possible Braille encodings, the LSTM model analyzes contextual information to resolve the correct translation. The system was evaluated on 1,000 sentences per language across 13 Indian languages and 10 scripts, achieving perfect accuracy.

## Method Summary
The translation system employs a two-stage approach. First, it extracts phonemes from input text and segments them into characters. A rule-based system then maps these characters to Bharti Braille using predefined transliteration rules for three character classes: consonants, vowels, and vowel symbols/matra. When the rule-based system encounters characters with multiple possible Braille encodings, the text is passed to a bidirectional LSTM model that analyzes the context (previous, current, and next states) to predict the correct encoding. This hybrid approach leverages the efficiency of rule-based mapping for straightforward cases while using the LSTM model to handle ambiguous cases where context determines the correct translation.

## Key Results
- Rule-based system achieved accuracies ranging from 0.925 to 0.94 across different languages
- LSTM disambiguation model achieved 100% accuracy on ambiguous cases
- Overall system achieved 100% accuracy across all 13 languages and 10 scripts
- Tested on 1,000 sentences per language (total of 13,000 sentences)

## Architecture Onboarding

- Component map: Input preprocessing -> Phoneme extraction -> Character segmentation -> Rule-based mapping -> Ambiguity detection -> LSTM disambiguation (if needed) -> Output formatting
- Critical path: Input → Phoneme extraction → Character segmentation → Rule-based mapping → Ambiguity detection → LSTM disambiguation (if needed) → Output formatting
- Design tradeoffs:
  - Accuracy vs. efficiency: Using rule-based system for most cases and LSTM only for ambiguous cases optimizes for both accuracy and computational efficiency
  - Coverage vs. complexity: Including more detailed rules increases coverage but also increases system complexity and maintenance burden
  - Model size vs. performance: Larger LSTM models may provide better disambiguation but require more computational resources
- Failure signatures:
  - Rule-based failures: Incorrect Braille output for characters with missing or incorrect rules
  - LSTM failures: Incorrect disambiguation for context-dependent characters
  - System failures: Performance degradation when processing languages/scripts not adequately covered by the rule base
- First 3 experiments:
  1. Test the rule-based system independently on a corpus of unambiguous text to establish baseline accuracy and identify gaps in rule coverage
  2. Test the LSTM disambiguator on a controlled set of ambiguous cases to evaluate its accuracy in isolation
  3. Run end-to-end tests on mixed-content text to measure the combined performance of the hybrid system and identify any integration issues between components

## Limitations
- The claim of 100% overall accuracy requires careful scrutiny as it may be overly optimistic without detailed error analysis and specification of ambiguous case frequency
- The paper lacks detailed information on the LSTM architecture, training data, and how the bidirectional LSTM specifically captures contextual features for disambiguation
- No discussion of computational resource requirements or processing time for the LSTM disambiguation component, which are critical for practical deployment

## Confidence
- **High confidence**: The basic hybrid architecture combining rule-based and LSTM approaches is technically sound and represents a reasonable methodology for the translation task
- **Medium confidence**: The reported accuracy ranges for the rule-based system (0.925-0.94) are plausible given the structured nature of Indian scripts and Bharti Braille, though the variation across languages warrants investigation
- **Low confidence**: The claim of 100% overall accuracy is questionable without detailed error analysis, specification of ambiguous case frequency, and independent validation of the LSTM disambiguation performance
