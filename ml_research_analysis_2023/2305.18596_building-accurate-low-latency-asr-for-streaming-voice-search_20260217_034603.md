# Building Accurate Low Latency ASR for Streaming Voice Search

## Quick Facts
- arXiv ID: 2305.18596
- Source URL: https://arxiv.org/abs/2305.18596
- Reference count: 10
- 3.69% WER without EOS and 4.78% WER with EOS on Hinglish voice search

## Executive Summary
This work addresses the challenge of building accurate, low-latency streaming ASR for voice search in Hinglish, where traditional streaming models suffer from lower accuracy due to lack of future context. The authors propose a streaming ASR model combining LSTM, windowed self-attention, and hierarchical CTC losses, trained with a CTC-based end-of-speech detection mechanism. Evaluated on Flipkart's voice search with 6 million daily queries, the model achieves 3.69% WER without EOS and 4.78% WER with EOS, while reducing search latency by ~1300 ms (46.64%) compared to an independent VAD. The approach bridges the accuracy gap between streaming and non-streaming models and demonstrates significant gains over baseline systems.

## Method Summary
The proposed model uses a 3-level hierarchical CTC architecture with LSTM-attention blocks. The first level predicts characters, the second level predicts short subwords, and the third level predicts long subwords. A time convolution layer reduces time steps between levels 2 and 3. Windowed multi-head self-attention with a 5-frame window enriches context without breaking streaming constraints. The model is trained with label smoothing and fine-tuned for end-of-speech detection using dynamic thresholding on the < /s > token probability.

## Key Results
- Achieves 3.69% WER without EOS and 4.78% WER with EOS
- Reduces search latency by ~1300 ms (46.64%) compared to independent VAD
- Demonstrates 64.13% EOS coverage with dynamic thresholding

## Why This Works (Mechanism)

### Mechanism 1
The windowed self-attention mechanism improves streaming ASR accuracy by increasing the effective receptive field without breaking the streaming constraint. By restricting the multi-head attention to a 5-frame window (t ± 2), the model can extract richer context from neighboring frames compared to a vanilla LSTM, which only has access to the current and past frames. This helps the model make better predictions in the current frame based on a wider temporal context.

### Mechanism 2
The hierarchical CTC loss structure enables the model to learn multi-level representations from characters to subwords, improving overall accuracy. The model predicts characters (73 tokens), short subwords (300 tokens), and long subwords (5000 tokens) at different levels. The hierarchical structure forces the model to learn representations at multiple granularities, with lower levels providing fine-grained predictions and higher levels capturing longer linguistic units. The combined CTC loss from all levels acts as an ensemble, improving convergence and final accuracy.

### Mechanism 3
The dynamic threshold for EOS detection with the n/β term reduces latency while maintaining accuracy by adapting to the model's confidence patterns. The EOS detection uses a dynamic threshold that starts at α and decreases by nt/β with each EOS peak, where nt is the number of EOS peaks before time t. This accounts for the model's tendency to give lower probability to the < /s > token after each EOS peak, allowing for earlier detection while preventing premature termination.

## Foundational Learning

- Concept: Connectionist Temporal Classification (CTC)
  - Why needed here: CTC is the loss function that allows the model to learn alignment between input audio frames and output text without requiring pre-segmented training data. It's fundamental to understanding how the streaming ASR model can output text in real-time.
  - Quick check question: How does CTC handle the many-to-one mapping between audio frames and text tokens, and why is this important for streaming ASR?

- Concept: Attention mechanisms in neural networks
  - Why needed here: The model uses windowed self-attention to enrich the context available to each LSTM layer. Understanding how attention works and its streaming vs non-streaming variants is crucial for grasping the architectural improvements.
  - Quick check question: What's the key difference between standard self-attention and windowed self-attention, and why does this difference matter for streaming applications?

- Concept: Hierarchical modeling in machine learning
  - Why needed here: The hierarchical CTC structure predicts at multiple levels (characters, short subwords, long subwords). Understanding hierarchical modeling helps explain why this approach can capture different linguistic granularities simultaneously.
  - Quick check question: How does training a model to predict at multiple hierarchical levels simultaneously differ from training separate models for each level, and what are the potential benefits?

## Architecture Onboarding

- Component map: Audio input → log-mel-spectrogram → stacked frames → Level 1 LSTM-attention → CTC loss (characters) → Level 2 LSTM-attention → CTC loss (short subwords) → Time convolution → Level 3 LSTM-attention → CTC loss (long subwords) → Prefix beam search → EOS detection → KenLM rescoring

- Critical path: Audio input → log-mel-spectrogram → stacked frames → Level 1: LSTM-attention → CTC loss (characters) → Level 2: LSTM-attention → CTC loss (short subwords) → Time convolution (reduce time steps by 3x) → Level 3: LSTM-attention → CTC loss (long subwords) → Prefix beam search decoding from level 3 → EOS detection using dynamic threshold on < /s > probability → KenLM rescoring of top hypotheses

- Design tradeoffs:
  - Streaming vs accuracy: The 5-frame attention window balances improved accuracy from context with the need to maintain streaming capability
  - Model complexity vs latency: 3-level hierarchy with attention adds parameters and computation but improves accuracy; time convolution reduces time steps for efficiency
  - EOS aggressiveness vs search impact: Lower α threshold reduces latency but may cause early termination affecting search results

- Failure signatures:
  - High WER: Could indicate issues with attention window size, CTC loss configuration, or insufficient training data
  - Excessive latency: May suggest α threshold too high or EOS detection not triggering appropriately
  - Poor EOS detection: Could result from incorrect EL penalty training or inappropriate threshold parameters

- First 3 experiments:
  1. Ablation study: Remove windowed attention and measure WER increase to quantify its contribution
  2. Threshold sweep: Systematically vary α and β parameters to find optimal EOS detection performance
  3. Lookahead analysis: Measure accuracy impact of increasing/decreasing the attention window size beyond 5 frames

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How would larger models with 100M+ parameters perform on the Hinglish voice search task compared to the current 60M parameter model?
- Basis in paper: The authors note their current model is limited to 60 million parameters due to deployment constraints and suggest future work exploring larger models.
- Why unresolved: The paper explicitly acknowledges this limitation and states larger models could potentially improve performance.
- What evidence would resolve it: Training and evaluating models with 100M+ parameters on the same dataset while maintaining similar inference latency requirements.

### Open Question 2
- Question: Can a single joint model effectively handle ASR, EOS detection, and spoken language understanding simultaneously for the Hinglish voice search task?
- Basis in paper: The authors state they are "keen on exploring the development of a single joint model for Automatic Speech Recognition (ASR), End-of-Speech (EOS) detection, and Spoken Language Understanding (SLU)."
- Why unresolved: This is identified as future work but no experiments or feasibility analysis are provided.
- What evidence would resolve it: Training and evaluating a multi-task model that jointly performs all three tasks and comparing its performance to separate specialized models.

### Open Question 3
- Question: How would the proposed streaming ASR model perform on other Indian languages with limited data compared to Hinglish?
- Basis in paper: The authors mention they want to "extend its applicability to other Indian languages, which typically have less available data compared to Hinglish."
- Why unresolved: The paper only evaluates on Hinglish, which has substantial training data (22.5k hours), while other Indian languages would have significantly less.
- What evidence would resolve it: Training and evaluating the same model architecture on low-resource Indian languages with limited labeled data and comparing performance metrics to the Hinglish results.

## Limitations

- Data domain specificity: Model trained and evaluated on Flipkart's voice search data with Hinglish focus, limiting generalizability
- Architecture complexity: Three-level hierarchical CTC structure with attention mechanisms creates complex model with many interacting components
- EOS detection reliability: 64.13% EOS coverage indicates 35.87% of cases either failed to detect EOS or triggered it incorrectly

## Next Checks

1. **Architecture ablation study**: Systematically remove the windowed attention mechanism and hierarchical CTC structure to quantify their individual contributions to the 3.69% WER. This should include training simplified versions with: (a) vanilla LSTM without attention, (b) single-level CTC without hierarchy, and (c) full model without EOS detection to establish baseline performance gains.

2. **Cross-domain generalization test**: Evaluate the trained model on voice search data from different e-commerce platforms or general conversational speech to assess performance degradation. This should include testing on: (a) voice commands from smart home devices, (b) customer service call transcriptions, and (c) social media voice content to determine the model's domain adaptability.

3. **EOS detection robustness analysis**: Conduct a comprehensive analysis of EOS failure modes by categorizing errors into: (a) premature termination cases, (b) missed speech segments, and (c) latency outliers. For each category, identify whether failures correlate with specific acoustic conditions (background noise, speaker accent, speech rate) and whether the dynamic threshold parameters (α, β) need domain-specific tuning.
