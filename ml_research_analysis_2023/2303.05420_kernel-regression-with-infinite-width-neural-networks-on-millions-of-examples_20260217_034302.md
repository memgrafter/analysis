# Kernel Regression with Infinite-Width Neural Networks on Millions of Examples

## Quick Facts
- arXiv ID: 2303.05420
- Source URL: https://arxiv.org/abs/2303.05420
- Authors: 
- Reference count: 19
- Primary result: Achieves 91.2% test accuracy on CIFAR-10 using kernel methods with 20× data augmentation, setting SotA for pure kernel methods

## Executive Summary
This paper presents a scalable framework for neural kernel regression on datasets with millions of examples. By combining distributed kernel computation with a distributed preconditioned conjugate gradient solver, the authors enable kernel regression at previously infeasible scales. The work demonstrates power-law scaling of neural kernels across four to five orders of magnitude on CIFAR-5m and achieves state-of-the-art results for pure kernel methods through extensive data augmentation.

## Method Summary
The method uses Neural Tangents library to compute exact infinite-width neural network kernels (NTK/NNGP) in parallel across multiple GPUs/TPUs. These kernels are stored in sharded blocks on disk for out-of-core access. A distributed preconditioned conjugate gradient solver runs on a CPU host with worker CPUs computing kernel-vector products on demand. The approach is applied to CIFAR-5m for scaling law studies, CIFAR-10 with data augmentation for accuracy benchmarking, and protein/molecular datasets for cross-domain validation.

## Key Results
- Power-law scaling of neural kernels across 4-5 orders of magnitude on CIFAR-5m dataset
- 91.2% test accuracy on CIFAR-10 with 20× data augmentation, SotA for pure kernel methods
- Competitive performance on protein sequence prediction and small molecule property prediction tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Neural kernels benefit from dataset scaling in a power-law fashion when the model capacity scales with data.
- Mechanism: The kernel's implicit prior allows it to automatically adjust capacity as more data arrive, avoiding underfitting or overfitting.
- Core assumption: Training data are i.i.d. from the test distribution; the kernel's spectrum is well-conditioned enough for conjugate gradients to converge.
- Evidence anchors:
  - [abstract] "We study scaling laws of several neural kernels across many orders of magnitude for the CIFAR-5m dataset."
  - [section 3] "Empirically, it has been found that performance improves as a power law, for which many works seek to estimate the exponent."
  - [corpus] Weak; no directly comparable study in corpus neighbors.
- Break condition: Non-i.i.d. or heavy-tailed label noise could invalidate the power-law extrapolation.

### Mechanism 2
- Claim: Distributed preconditioned conjugate gradients (PCG) can solve linear systems for kernels with millions of examples without explicitly storing the full kernel.
- Mechanism: PCG only needs kernel-vector products; partitioning kernel computation across machines keeps memory and communication tractable.
- Core assumption: Kernel-vector products can be computed in parallel with minimal inter-machine coordination.
- Evidence anchors:
  - [section 2] "We use a host CPU to run the main CG algorithm and act as a server to control worker CPUs who compute kernel-vector products."
  - [abstract] "We combine this with a distributed, preconditioned conjugate gradients algorithm to enable kernel regression at a large scale."
  - [corpus] No corpus evidence; this is a novel distributed computation approach.
- Break condition: Communication overhead or load imbalance could dominate if kernel partitions are poorly sized.

### Mechanism 3
- Claim: Data augmentation applied to kernel regression yields accuracy gains comparable to those seen in SGD-trained networks.
- Mechanism: Augmenting the dataset creates new effective training examples that the kernel interpolates between, mimicking inductive bias shifts.
- Core assumption: Augmentation transformations preserve the semantic label of examples; kernel interpolation handles the expanded dataset.
- Evidence anchors:
  - [abstract] "Using data augmentation to expand the original CIFAR-10 training dataset by a factor of 20, we obtain a test accuracy of 91.2% (SotA for a pure kernel method)."
  - [section 4] "Following Li et al. [2019], Shankar et al. [2020], a 2× augmentation factor is given by horizontally flipping all images."
  - [corpus] No direct evidence; augmentation is rarely applied to kernel methods at this scale.
- Break condition: Poorly chosen augmentations could degrade kernel similarity estimates, hurting performance.

## Foundational Learning

- Concept: Neural Tangent Kernel (NTK) and Neural Network Gaussian Process (NNGP) equivalence
  - Why needed here: The paper relies on the fact that infinite-width networks have deterministic kernels (NTK/NNGP) that can be computed exactly for inference.
  - Quick check question: If a two-layer ReLU network has infinite width, what is the covariance between two inputs?
    - Answer: It is given by the arc-cosine kernel of order 1.

- Concept: Conjugate Gradients for kernel regression
  - Why needed here: Solving (K + σ²I)α = y for large K is infeasible by direct inversion; CG only requires matrix-vector products.
  - Quick check question: Why is a preconditioner essential for ill-conditioned kernels?
    - Answer: It clusters the eigenvalues of the system matrix, reducing the number of CG iterations needed.

- Concept: Data augmentation in kernel methods
  - Why needed here: Augmentation enlarges the training set, and the kernel naturally interpolates between the original and augmented examples.
  - Quick check question: How does RandAug differ from simple horizontal flips in the kernel context?
    - Answer: RandAug applies a random sequence of intensity-preserving transformations, increasing diversity beyond left-right symmetry.

## Architecture Onboarding

- Component map: Kernel builder -> Kernel store -> CG driver -> Worker pool -> Hyperparameter tuner
- Critical path:
  1. Compute and store kernel blocks.
  2. Load necessary blocks for each CG iteration.
  3. Perform preconditioned CG updates until residual threshold.
  4. Return final predictor coefficients.

- Design tradeoffs:
  - Memory vs speed: Storing full kernel in RAM is fastest but often infeasible; disk storage trades off latency for scalability.
  - Block size vs communication: Smaller blocks reduce per-node memory but increase communication overhead.
  - Precision: float64 improves accuracy at higher compute cost; float32 may be faster but less stable for ill-conditioned kernels.

- Failure signatures:
  - CG iterations plateau without reaching residual threshold → likely ill-conditioning or poor preconditioner.
  - Kernel computation stalls → check block distribution and inter-node bandwidth.
  - Accuracy plateaus at moderate data sizes → possible need for stronger augmentation or kernel architecture changes.

- First 3 experiments:
  1. Run FC3 kernel regression on CIFAR-10 with 10k examples, verify accuracy matches published results (~70%).
  2. Scale to 100k examples, measure kernel storage and CG iteration count; confirm preconditioner effectiveness.
  3. Apply 2× horizontal flip augmentation, compare to baseline; ensure accuracy improves as in Table 1.

## Limitations
- Kernel spectrum conditioning may cause convergence issues for deeper architectures
- Power-law extrapolation beyond tested ranges remains speculative
- Comparative advantage versus SGD-trained networks not thoroughly benchmarked

## Confidence
- High confidence: Distributed kernel computation methodology and PCG implementation are technically sound and reproducible
- Medium confidence: Scaling law observations are robust within tested ranges but their extrapolation is uncertain
- Low confidence: The comparative advantage of neural kernels versus other large-scale regression methods is not thoroughly benchmarked across all task types
