# Zero-shot Faithful Factual Error Correction

## Quick Facts
- arXiv ID: 2305.07982
- Source URL: https://arxiv.org/abs/2305.07982
- Authors: 
- Reference count: 24
- Key outcome: ZEROFEC achieves strong faithfulness in factual error correction without supervision, outperforming fully-supervised models on FEVER and SCIFACT datasets.

## Executive Summary
This paper introduces ZEROFEC, a zero-shot framework for factual error correction that prioritizes faithfulness by grounding corrections in provided evidence. Unlike prior approaches that focus solely on factuality, ZEROFEC ensures corrections are consistent with evidence through a decomposable pipeline involving claim answer extraction, question generation, QA-based answer retrieval, and entailment-based candidate selection. The framework operates without supervision and demonstrates strong performance on both Wikipedia and biomedical datasets, with particular attention to preventing misleading outputs through faithful corrections.

## Method Summary
ZEROFEC decomposes factual error correction into five steps: extracting claim information units (noun chunks, named entities, verbs, adjectives, negation terms) using Spacy and Stanza, generating questions about each unit using MixQG, answering questions using evidence with UnifiedQA-v2, converting Q&A pairs into candidate corrections using a Seq2Seq model, and selecting the most faithful correction via entailment scoring (DocNLI) and relevance scoring (ROUGE-1). The framework optionally adapts QA and entailment components to biomedical domains using BioASQ and PubMedQA datasets for SCIFACT evaluation.

## Key Results
- ZEROFEC outperforms fully-supervised models on FEVER and SCIFACT datasets for factual error correction
- SARI is identified as the most reliable automatic metric for faithfulness evaluation in this context
- Domain adaptation improves performance on biomedical datasets without degrading performance on Wikipedia datasets
- Human evaluations confirm ZEROFEC's superiority in producing faithful, intelligible corrections

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Decomposing factual error correction into question generation, QA, and entailment scoring allows the framework to ensure faithfulness by grounding corrections directly in the evidence.
- **Mechanism**: The framework first extracts information units from the input claim, generates questions about each unit, and then uses a QA model to retrieve correct answers from the evidence. These QA pairs are converted into candidate corrections, which are scored by an entailment model. The highest-scoring candidate is selected as the final correction.
- **Core assumption**: Each factual error can be localized to a specific information unit in the claim, and the evidence contains the correct information for that unit.
- **Evidence anchors**:
  - [abstract] "formulates questions about input claims, looks for correct answers in the given evidence, and assesses the faithfulness of each correction based on its consistency with the evidence."
  - [section 3] "Our method ensures the corrected information units are derived from the evidence, which helps improve the faithfulness of the generated corrections."
- **Break condition**: If the evidence does not contain the correct answer for a given information unit, or if the QA model fails to extract the correct answer, the framework cannot produce a faithful correction.

### Mechanism 2
- **Claim**: Using entailment scoring (DocNLI) to evaluate candidate corrections ensures that the final output is factually consistent with the evidence.
- **Mechanism**: After generating candidate corrections from QA pairs, each candidate is scored using DocNLI, which measures the entailment between the candidate and the evidence. The candidate with the highest entailment score is selected as the final correction.
- **Core assumption**: The entailment score between a candidate correction and the evidence accurately reflects the faithfulness of the correction.
- **Evidence anchors**:
  - [section 3.5] "The final correction is produced by scoring the faithfulness of each candidate correction from the previous steps w.r.t. the evidence. We use entailment score to approximate faithfulness."
  - [section 4.4] "DocNLI is more generalizable than other document-sentence entailment models, such as FactCC, since it was trained on five datasets of various tasks and domains."
- **Break condition**: If the entailment model is not well-calibrated or fails to capture the nuances of faithfulness, the selected correction may not be faithful to the evidence.

### Mechanism 3
- **Claim**: Domain adaptation of the QA and entailment components improves performance on biomedical datasets without degrading performance on Wikipedia datasets.
- **Mechanism**: The QA and entailment components are fine-tuned on biomedical QA datasets (BioASQ and PubMedQA) to improve their performance on the SCIFACT dataset, which contains biomedical claims.
- **Core assumption**: Fine-tuning the QA and entailment components on biomedical data will improve their ability to handle biomedical claims and evidence.
- **Evidence anchors**:
  - [section 3.6] "we adapt UNIFIED QA-V2 and DOCNLI on two biomedical QA datasets, PUBMEDQA and BIOASQ, by further fine-tuning them for a few thousand steps."
  - [section 5.1] "The first example in Table 2 illustrates an instance where domain adaptation fixes an error made by ZEROFEC. The absence of domain adaptation results in incorrect predictions by ZEROFEC, as DocNLI assigns a significantly lower entailment score to the correct candidate."
- **Break condition**: If the biomedical data used for fine-tuning is not representative of the SCIFACT dataset, or if the fine-tuning process overfits to the biomedical data, the performance on SCIFACT may not improve.

## Architecture Onboarding

- **Component map**: Claim Answer Generation -> Question Generation -> Question Answering -> QA-to-Claim -> Correction Scoring

- **Critical path**: Claim Answer Generation → Question Generation → Question Answering → QA-to-Claim → Correction Scoring

- **Design tradeoffs**:
  - Using a multi-component architecture allows for better interpretability and control over the correction process, but increases the inference time and memory usage compared to a single Seq2Seq model.
  - Fine-tuning the QA and entailment components on biomedical data improves performance on SCIFACT, but requires additional training data and computation.

- **Failure signatures**:
  - If the Claim Answer Generation fails to extract all relevant information units, the framework may miss some factual errors.
  - If the Question Generation or Question Answering fails, the framework may generate incorrect candidate corrections.
  - If the Correction Scoring fails, the framework may select an unfaithful correction as the final output.

- **First 3 experiments**:
  1. Test the framework on a small dataset with simple factual errors to ensure that each component is working correctly.
  2. Test the framework on a dataset with more complex factual errors to evaluate its ability to handle diverse error types.
  3. Test the framework with and without domain adaptation to measure the impact of the adaptation on performance.

## Limitations
- The framework's multi-component architecture introduces multiple potential failure points that could propagate through the pipeline
- Domain adaptation effectiveness is demonstrated through qualitative examples rather than comprehensive quantitative analysis
- The claim about SARI being the most reliable metric for faithfulness evaluation needs further validation across diverse datasets

## Confidence
- **High Confidence**: The core framework architecture and its decomposition approach are well-specified and theoretically sound
- **Medium Confidence**: Performance claims on FEVER and SCIFACT datasets are supported by both automatic metrics and human evaluations
- **Low Confidence**: The claim about SARI being the most reliable metric for faithfulness evaluation is based on correlation analysis that may not generalize
