# Cooperative Multi-Agent Reinforcement Learning for Inventory Management

## Quick Facts
- arXiv ID: 2304.08769
- Source URL: https://arxiv.org/abs/2304.08769
- Reference count: 27
- Primary result: CMARL outperforms base-stock policies, single-agent RL, and other MARL configurations in terms of reward for managing single-product inventory

## Executive Summary
This paper presents a multi-agent reinforcement learning system for inventory management across a supply chain with one warehouse and multiple stores. The proposed Cooperative MARL (CMARL) system features an enhanced warehouse agent with extended state and action spaces to learn an allocation policy, and a shared reward structure to encourage system-wide cooperation. The environment is implemented using GPU-parallelized CuPy for efficient computation. Experiments show that CMARL outperforms base-stock policies, single-agent RL, and other MARL configurations in terms of reward for managing inventory of a single product.

## Method Summary
The CMARL system introduces a cooperative multi-agent reinforcement learning framework where the warehouse agent has an extended state and action space to learn optimal allocation policies. The system implements a shared reward structure across all agents to encourage system-wide cooperation rather than individual optimization. The environment leverages GPU parallelization through CuPy for efficient computation. The approach is evaluated against traditional base-stock policies and various MARL configurations, demonstrating improved performance in minimizing stockouts and holding costs while achieving faster convergence to optimal policies.

## Key Results
- CMARL outperforms base-stock policies, single-agent RL, and other MARL configurations in terms of reward for managing single-product inventory
- The system achieves higher rewards compared to a shared policy variant when handling 10 products simultaneously
- CMARL enables faster convergence to optimal policies and better inventory management

## Why This Works (Mechanism)
The cooperative framework works by extending the warehouse agent's state and action spaces to capture more comprehensive inventory dynamics and allocation decisions. The shared reward structure aligns agent incentives toward system-wide optimization rather than local store-level gains. The GPU parallelization enables efficient computation of complex state transitions and reward calculations across multiple agents and time steps. The enhanced warehouse agent can learn sophisticated allocation policies that balance stock levels across stores while considering overall system costs.

## Architecture Onboarding

**Component Map**: Environment (CuPy) -> Warehouse Agent (extended state/action) -> Store Agents (standard) -> Shared Reward Calculator -> RLLib Trainer

**Critical Path**: State observation → Warehouse allocation decision → Store ordering → Reward calculation → Policy update

**Design Tradeoffs**: Extended warehouse state/action spaces increase learning complexity but enable better allocation policies; shared rewards promote cooperation but may cause credit assignment issues; GPU parallelization improves speed but adds implementation complexity

**Failure Signatures**: Poor allocation policies manifest as unbalanced stock levels across stores; lack of cooperation shows as agents optimizing for local rather than system-wide rewards; slow convergence indicates insufficient state information or reward signal
