# Just Tell Me: Prompt Engineering in Business Process Management

## Quick Facts
- arXiv ID: 2304.07183
- Source URL: https://arxiv.org/abs/2304.07183
- Reference count: 23
- Primary result: Prompt engineering enables effective use of pre-trained LMs for BPM tasks without fine-tuning, reducing data requirements

## Executive Summary
This paper presents a conceptual framework for leveraging prompt engineering in business process management (BPM) applications. The authors identify six key potentials of prompt engineering, including effective use of limited data, natural language-based interaction, and computational efficiency gains. The paper also outlines six associated challenges, such as process representation in prompts and limited prompt length constraints. While the theoretical foundation is sound, the paper lacks empirical validation and quantitative analysis to support its claims about improved explainability and computational efficiency.

## Method Summary
The paper takes a conceptual approach to exploring prompt engineering applications in BPM, identifying potentials and challenges through theoretical analysis rather than empirical experimentation. The authors synthesize existing knowledge about language model capabilities and BPM requirements to propose how prompt engineering could address current limitations in the field. The methodology focuses on mapping BPM task characteristics to prompt engineering capabilities, but does not include experimental validation or performance metrics.

## Key Results
- Identifies six potentials of prompt engineering for BPM: effective use of limited data, natural language interaction, input optimization, task specificity reduction, computational efficiency, and explainability
- Outlines six challenges: process representation in prompts, limited prompt length, pre-trained model selection, prompt transferability, output processing, and template evaluation
- Proposes prompt engineering as an alternative to fine-tuning for leveraging pre-trained LMs in BPM tasks

## Why This Works (Mechanism)
Prompt engineering works for BPM by enabling direct interaction with pre-trained language models through carefully constructed input patterns, eliminating the need for task-specific fine-tuning. This approach leverages the model's existing knowledge and reasoning capabilities while constraining outputs through prompt structure. The mechanism relies on the model's ability to understand context, follow instructions embedded in prompts, and generate relevant responses based on its pre-training data, which often includes process-related documentation and business concepts.

- **Language model limitations**: Knowing token limits, context window constraints, and model-specific behaviors is critical for effective prompt design. Quick check: What are the token limits of your target LM?
- **BPM task characteristics**: Understanding the specific requirements of process mining, compliance checking, and other BPM tasks determines prompt engineering strategies. Quick check: Which BPM tasks are most suitable for prompt-based approaches?
- **Domain-specific terminology**: BPM uses specialized vocabulary that may not be well-represented in general pre-training data, affecting prompt effectiveness. Quick check: How does your LM handle BPM-specific terminology?
- **Evaluation metrics for prompts**: Unlike traditional models, prompt effectiveness requires new evaluation approaches that capture both task completion and prompt quality. Quick check: What metrics will you use to evaluate prompt performance?

## Architecture Onboarding
- **Component map**: BPM task → Prompt template → Pre-trained LM → Output processing → BPM result
- **Critical path**: Prompt template design → Model selection → Input preparation → Output interpretation → Task validation
- **Design tradeoffs**: Fine-tuning vs. prompt engineering (data requirements vs. flexibility), prompt complexity vs. model comprehension, specificity vs. generalizability
- **Failure signatures**: Incorrect task framing in prompts, domain terminology misunderstanding, token limit exceeded, output format mismatch
- **First experiments**: 1) Test simple process description prompts on different LMs, 2) Compare prompt-based vs. fine-tuned approaches on small BPM datasets, 3) Evaluate prompt transferability across different BPM subtasks

## Limitations
- Lacks empirical validation and experimental results to support theoretical claims
- Superficial treatment of technical constraints like token limits and model selection
- Overstated claims about explainability improvements compared to fine-tuning approaches
- No discussion of how domain-specific BPM terminology affects prompt effectiveness

## Confidence
- High confidence in the basic premise of reduced data requirements through prompt engineering
- Medium confidence in the general classification of potentials and challenges
- Low confidence in specific claims about explainability improvements and computational efficiency gains
