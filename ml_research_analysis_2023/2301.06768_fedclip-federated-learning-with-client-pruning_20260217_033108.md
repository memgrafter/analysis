# FedCliP: Federated Learning with Client Pruning

## Quick Facts
- arXiv ID: 2301.06768
- Source URL: https://arxiv.org/abs/2301.06768
- Reference count: 10
- Primary result: Reduces communication overhead by up to 70% while maintaining accuracy within 1%

## Executive Summary
FedCliP introduces a federated learning framework that dynamically prunes clients based on reliability scores to reduce communication overhead. The framework uses Gaussian Scale Mixture (GSM) modeling to identify and remove redundant clients during training, combining local training loss and model divergence metrics. Experimental results show significant communication efficiency improvements across multiple datasets while maintaining model accuracy.

## Method Summary
FedCliP employs a reliability score based on GSM modeling that combines local training loss and model divergence to identify clients with less potential contributions. The framework calculates this score for each client during communication rounds and prunes those below a threshold. Client pruning begins after 20 communication rounds to avoid early instability, with the GSM reliability metric updated periodically to adapt to changing client contributions.

## Key Results
- Achieved 70% communication overhead reduction on MNIST with only 0.2% accuracy loss
- Reduced communication by 50% on FMNIST and 15% on CIFAR-10 with less than 1% accuracy loss
- Demonstrated effectiveness under both IID and non-IID data distributions

## Why This Works (Mechanism)
The framework leverages GSM modeling to create a statistical reliability score that captures both local training effectiveness and model divergence. By pruning clients with low reliability scores, FedCliP reduces redundant communications while preserving the most informative client contributions. The approach balances communication efficiency with model convergence by strategically timing the pruning process.

## Architecture Onboarding

**Component Map:** Global server -> Client selection -> GSM reliability calculation -> Client pruning -> Model aggregation

**Critical Path:** GSM calculation → Reliability thresholding → Client pruning → Federated averaging

**Design Tradeoffs:** Early pruning risks convergence instability vs. delayed pruning reduces communication savings; GSM complexity vs. simple threshold methods

**Failure Signatures:** Model divergence spikes after pruning, accuracy plateaus prematurely, communication overhead remains high despite pruning
