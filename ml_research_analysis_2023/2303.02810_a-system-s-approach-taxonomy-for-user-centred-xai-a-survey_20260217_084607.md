# A System's Approach Taxonomy for User-Centred XAI: A Survey

## Quick Facts
- arXiv ID: 2303.02810
- Source URL: https://arxiv.org/abs/2303.02810
- Authors: 
- Reference count: 16
- Primary result: Presents a user-centred taxonomy for XAI based on General System's Theory, revealing that most methods prioritize domain expert needs over end-user comprehension

## Executive Summary
This paper addresses the gap in existing method-centric XAI frameworks by proposing a user-centred taxonomy based on General System's Theory principles. The framework views XAI as a system of interrelated elements including explanation types, properties, user domain knowledge, human-in-the-loop requirements, XAI approaches, and performance metrics. This holistic approach enables both qualitative and quantitative assessment of XAI methods, supporting the development of more user-centric explainable AI systems. The taxonomy was validated by evaluating a range of XAI approaches from literature, revealing significant gaps in end-user consideration.

## Method Summary
The study systematically evaluated 13 XAI methods from literature across different domains (business, medical, computer science) and ML models (NN, LRM, SVM, RFC, GLM, NB, DT). The evaluation applied the proposed taxonomy framework by classifying each method against seven core elements: explanation types, properties, user domain knowledge requirements, human-in-the-loop requirements, XAI approaches, performance metrics, and evaluation methods. The analysis identified patterns in how existing methods address (or fail to address) different user types, particularly highlighting the gap between domain expert and end-user considerations.

## Key Results
- Most existing XAI methods prioritize domain expert needs while lacking explicit evaluation of end-user comprehension
- Understanding is universally valued as a non-functional property, but there is insufficient attention to quantifying user comprehension and trust from end-user perspectives
- The taxonomy enables both qualitative and quantitative assessment of XAI methods, revealing gaps in current approaches
- All evaluated methods appear to require users to possess background knowledge equivalent to domain experts

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The taxonomy integrates system elements into a coherent framework that addresses both functional and non-functional explainability requirements
- Mechanism: By viewing XAI as a system of interrelated elements (explanation types, properties, user domain knowledge, human-in-the-loop requirements, XAI approaches, and performance metrics), the framework captures dependencies that method-centric taxonomies miss
- Core assumption: Explainability emerges from the interaction of multiple elements rather than from individual methods alone
- Evidence anchors:
  - [abstract] "The proposed taxonomy views XAI as a system of interrelated elements - explanation types, properties, user domain knowledge, human-in-the-loop requirements, XAI approaches, and performance metrics"
  - [section 4] "By bringing these elements together, we can conceptualise them based on their interrelationship and underlying contribution in designing XAI architectures"
- Break condition: If user comprehension cannot be improved by adjusting multiple elements simultaneously, the system view becomes unnecessarily complex

### Mechanism 2
- Claim: User-centered evaluation reveals that most XAI methods prioritize domain experts while neglecting end-user comprehension needs
- Mechanism: The taxonomy enables both qualitative and quantitative assessment of XAI methods against different user types, exposing gaps in end-user consideration
- Core assumption: Different user types have fundamentally different explainability requirements that must be explicitly addressed
- Evidence anchors:
  - [abstract] "revealing that most methods prioritize domain expert needs and lack explicit evaluation of end-user comprehension"
  - [section 5] "All methods appear to require users to possess background knowledge equivalent to those of domain experts"
- Break condition: If end-user comprehension can be achieved through domain expert methods with minimal adaptation

### Mechanism 3
- Claim: The Input-Process-Output (IPO) model classification reveals explainability opportunities at multiple system levels
- Mechanism: By classifying XAI methods according to whether they provide explanations at input (pre-model), process (in-model), or output (post-model) levels, the framework identifies gaps and opportunities for comprehensive explainability
- Core assumption: Different explainability requirements can be addressed at different points in the ML pipeline
- Evidence anchors:
  - [section 4] "The pertinent opportunity here is to investigate whether an ML method could be made explainable at the input level (pre-model), process level (in-model) or at the output level (post-model)"
  - [section 5] "In all the methods investigated, along with identifying and explaining the causal pattern of predictive decisions, line of reasoning for predictive behaviours seem to be the two main types of explanations"
- Break condition: If post-hoc methods alone can provide sufficient explainability for all use cases

## Architecture Onboarding

- Component map: Explanation types -> Properties -> User domain knowledge -> Human-in-the-loop requirements -> XAI approaches -> Performance metrics
- Critical path: Start with problem domain → identify user types → select appropriate explanation types → evaluate against properties → assess human-in-the-loop requirements → choose XAI approach → measure performance
- Design tradeoffs: Balancing comprehensiveness (covering all user types) against complexity (simpler taxonomies may be easier to apply but miss important distinctions)
- Failure signatures: Methods that work well for domain experts but fail end-user comprehension tests; frameworks that cannot distinguish between different user types
- First 3 experiments:
  1. Apply the taxonomy to a simple decision tree model, classifying it across all six elements
  2. Evaluate a post-hoc explanation method (like LIME) using the user comprehension criteria
  3. Compare two XAI methods (one domain-specific, one agnostic) using the IPO classification approach

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can we effectively quantify end-user comprehension and trust in XAI systems, given that most existing methods primarily evaluate domain expert understanding?
- Basis in paper: [explicit] The paper states that while understanding is universally valued as a non-functional property, there is insufficient attention to quantifying user comprehension and trust from end-user perspectives.
- Why unresolved: Current XAI evaluation frameworks focus predominantly on technical performance metrics and domain expert comprehension, with little emphasis on measuring how well end-users actually understand and trust AI-generated explanations.
- What evidence would resolve it: Development and validation of standardized metrics and experimental protocols that measure end-user comprehension, trust levels, and perceived usefulness of explanations across diverse user groups and application domains.

### Open Question 2
- Question: What is the optimal balance between information completeness and user comprehensibility in XAI explanations, and how does this balance vary across different application domains?
- Basis in paper: [explicit] The paper notes that a challenge is to strike an appropriate balance between information completeness and user comprehensibility.
- Why unresolved: Different application domains (e.g., medical vs. business) have varying requirements for explanation detail and complexity, yet there is no systematic framework for determining the optimal trade-off between providing complete information and ensuring user comprehension.
- What evidence would resolve it: Empirical studies comparing user performance and satisfaction across different levels of explanation completeness in various application domains, leading to domain-specific guidelines for explanation design.

### Open Question 3
- Question: How can knowledge-based systems be effectively integrated into existing AI models to enhance user-comprehensible explanations for different types of users?
- Basis in paper: [explicit] The paper suggests that building domain-independent XAI architectures integrated with knowledge-based systems deserves further investigation to enhance user-comprehensible explanations.
- Why unresolved: While the integration of knowledge-based systems with AI models is proposed as a promising direction, there is limited research on practical implementation strategies and evaluation of such integrated systems.
- What evidence would resolve it: Development and empirical evaluation of prototype XAI systems that integrate knowledge-based reasoning with machine learning, demonstrating improved explanation quality and user comprehension across different user types.

## Limitations
- The empirical validation of the taxonomy framework lacks detailed specification of selection criteria and evaluation methodology
- The study relies on qualitative analysis rather than systematic user studies or quantitative metrics to assess user comprehension gaps
- The framework's generalizability across diverse application domains remains uncertain, as evaluation focused on business, medical, and computer science contexts
- Confidence in claims about user-centered gaps is Medium due to limited empirical evidence from actual end users

## Confidence
- Empirical validation claims: Medium
- User-centered gap identification: Medium
- Framework generalizability: Low-Medium
- Taxonomy comprehensiveness: Medium-High
