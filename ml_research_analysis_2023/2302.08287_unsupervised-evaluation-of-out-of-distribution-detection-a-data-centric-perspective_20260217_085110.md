# Unsupervised Evaluation of Out-of-distribution Detection: A Data-centric Perspective

## Quick Facts
- arXiv ID: 2302.08287
- Source URL: https://arxiv.org/abs/2302.08287
- Reference count: 40
- Primary result: Introduces Gscore for unsupervised OOD detection evaluation with strong correlation to detection performance

## Executive Summary
This paper addresses the challenge of evaluating out-of-distribution (OOD) detection methods without ground truth OOD labels. The authors propose Gscore, an unsupervised metric that measures the distributional difference between in-distribution (IND) and OOD test data using clustering or density estimation techniques. They construct Gbench, a benchmark of 200 real-world OOD datasets, and demonstrate that Gscore strongly correlates with OOD detection performance metrics. The method enables accurate performance prediction without requiring OOD labels and generalizes across various detection methods, datasets, and architectures.

## Method Summary
Gscore computes the distributional difference between IND and OOD scores using unsupervised methods. The approach employs three techniques: Kmeans clustering, Gaussian Mixture Models (GMM), and Unilateral Density Estimation (UDE). These methods cluster OOD scores into IND/OOD groups or estimate IND density, then calculate distance metrics (L2, KL, Wasserstein) between the resulting distributions. A linear regression model maps Gscore values to expected OOD detection performance metrics like AUROC and FPR@TPR95. The method is validated on Gbench, a benchmark containing 200 diverse OOD datasets.

## Key Results
- Gscore shows strong quantitative correlation with OOD detection performance (mean correlation values of 0.911 and 0.936 for FPR@TPR95 and AUROC)
- UDE outperforms Kmeans and GMM by leveraging prior knowledge of IND distribution from training data
- Gscore generalizes well across different OOD detection methods, IND/OOD datasets, backbones, and dataset sizes
- The method achieves state-of-the-art performance for unsupervised OOD detection evaluation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Gscore measures the distributional difference between IND and OOD test data using unsupervised clustering and density estimation.
- Mechanism: The algorithm clusters OOD scores into IND/OOD groups (via Kmeans/GMM) or estimates IND density (via UDE), then computes distance metrics (L2, KL, Wasserstein) between the two distributions.
- Core assumption: OOD scores naturally form bimodal distributions where IND and OOD data occupy distinct regions.
- Evidence anchors:
  - [abstract]: "we design Gscore to reflect such separability, the value of which increases from left to right."
  - [section 5.1]: "We observe that the OOD scores on the test data usually form a bimodal distribution...we set the number of components in Kmeans and GMM to 2."
  - [corpus]: Weak - related papers discuss OOD detection but not specifically bimodal score distributions.
- Break condition: If OOD scores do not form distinct bimodal distributions (e.g., overlapping or unimodal distributions), the separability measure fails.

### Mechanism 2
- Claim: Strong correlation exists between Gscore and OOD detection performance metrics like AUROC and FPR@TPR95.
- Mechanism: A linear regression model maps Gscore values to expected OOD detection performance, enabling prediction without OOD labels.
- Core assumption: The separability captured by Gscore is linearly predictive of detection performance across diverse datasets and detection methods.
- Evidence anchors:
  - [abstract]: "we find a strong quantitative correlation between Gscore and the OOD detection performance."
  - [section 6.2]: "We clearly observe that Gscore has a strong correlation with FPR@TPR95 and AUROC...mean absolute values of γ and ρ are 0.911 and 0.936."
  - [corpus]: Weak - neighboring papers focus on different OOD detection approaches without addressing correlation prediction.
- Break condition: If the relationship between distribution separability and performance is non-linear or dataset-dependent, regression predictions become inaccurate.

### Mechanism 3
- Claim: UDE outperforms Kmeans/GMM because it incorporates prior knowledge of IND distribution from training data.
- Mechanism: UDE uses validation set IND samples to estimate a Gaussian model of IND scores, then applies this model to unlabeled test data to separate IND/OOD scores before computing Gscore.
- Core assumption: IND data follows a predictable score distribution that can be estimated from training data and applied to test data.
- Evidence anchors:
  - [section 5.1]: "UDE achieves better performance under both conditions" (referring to overlapping data and imbalanced sample numbers).
  - [section 5.2]: "UDE leverages a part of meta-train IND set as validation set, and thus can better estimate the two distributions."
  - [corpus]: Weak - no direct corpus evidence supporting UDE superiority over other clustering methods.
- Break condition: If IND score distribution changes significantly between training and test environments, UDE estimates become invalid.

## Foundational Learning

- Concept: Bimodal distribution formation in OOD score space
  - Why needed here: Understanding why OOD scores naturally separate into two modes is critical for grasping Gscore's design rationale
  - Quick check question: Why would IND and OOD samples produce different OOD score distributions in well-trained detectors?

- Concept: Density estimation and distribution distance metrics
  - Why needed here: Gscore computation relies on accurately modeling score distributions and measuring their differences
  - Quick check question: What's the key difference between KL divergence and Wasserstein distance when comparing two Gaussian distributions?

- Concept: Linear regression for performance prediction
  - Why needed here: The method uses regression to map unsupervised Gscore to supervised performance metrics
  - Quick check question: Under what conditions might a linear model fail to capture the relationship between Gscore and OOD detection performance?

## Architecture Onboarding

- Component map: OOD scores extraction -> Kmeans/GMM/UDE clustering -> Distance metric calculation -> Linear regression -> Performance prediction
- Critical path: Test data -> OOD score extraction -> Gscore computation -> Regression prediction -> Performance estimate
- Design tradeoffs:
  - Clustering (Kmeans/GMM) vs. density estimation (UDE): Clustering is simpler but UDE leverages training data knowledge
  - Distance metric choice: L2 is simple, KL captures distributional differences, Wasserstein handles non-overlapping distributions
  - Regression model complexity: Linear regression is interpretable but may miss non-linear relationships
- Failure signatures:
  - Gscore values near zero indicate overlapping distributions (poor separability)
  - Inconsistent predictions across repeated runs suggest unstable clustering
  - Large prediction errors indicate model overfitting or distribution shift
- First 3 experiments:
  1. Generate bimodal score distributions with varying separation and verify Gscore increases with separability
  2. Test regression model on held-out datasets to validate correlation strength
  3. Compare UDE performance against Kmeans/GMM on overlapping and imbalanced datasets

## Limitations
- The method assumes OOD scores naturally form bimodal distributions, which may not hold for all detection methods or dataset combinations
- The linear correlation between Gscore and detection performance could be dataset-dependent and may not generalize to all OOD scenarios
- UDE's effectiveness depends on the stability of IND score distributions across training and test environments

## Confidence

- **High Confidence**: The observation that OOD scores form bimodal distributions in many cases, and the correlation between separability measures and detection performance
- **Medium Confidence**: The generalizability of Gscore across different OOD detection methods and the superiority of UDE over clustering approaches
- **Medium Confidence**: The practical utility of Gscore for performance prediction without OOD labels

## Next Checks

1. Test Gscore correlation strength on datasets where OOD scores are known to be unimodal or highly overlapping to verify break conditions

3. Compare Gscore's prediction accuracy against supervised baselines using small amounts of OOD labels to assess the practical value of fully unsupervised evaluation
