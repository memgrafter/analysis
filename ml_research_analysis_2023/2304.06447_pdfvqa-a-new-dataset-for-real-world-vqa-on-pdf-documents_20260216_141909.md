# PDFVQA: A New Dataset for Real-World VQA on PDF Documents

## Quick Facts
- arXiv ID: 2304.06447
- Source URL: https://arxiv.org/abs/2304.06447
- Reference count: 40
- Key outcome: Introduces PDF-VQA dataset for multi-page document VQA with 15K+ questions across three tasks, and proposes a graph-based model that outperforms baselines by explicitly modeling spatial and hierarchical relationships

## Executive Summary
This paper introduces PDF-VQA, a new dataset for real-world visual question answering on PDF documents. The dataset contains questions that examine document understanding from various aspects, including document element recognition, layout structural understanding, and contextual understanding. The dataset extends the current scale of document understanding from single pages to full documents with multiple pages. A graph-based VQA model is proposed that explicitly integrates the spatial and hierarchical structural relationships between different document elements to boost document structural understanding. The performance of the proposed model is compared with several baselines over different question types and tasks, and the results show that the proposed model outperforms all baselines.

## Method Summary
The PDF-VQA dataset is constructed from 1,562 publicly available PDF scientific articles, containing 15,622 questions across three tasks: A) Page-level Document Element Recognition, B) Page-level Document Layout Structure Understanding, and C) Full Document-level Understanding. Questions are automatically generated using predefined templates and XML annotations, with answers extracted via functional programs. The proposed LoSpa model constructs spatial (SR) and logical (LR) relational graphs between document elements, processes them through GCNs to enhance features, then uses a transformer encoder-decoder architecture with pointer network for answer prediction.

## Key Results
- LoSpa model outperforms all baselines (VisualBERT, ViLT, LXMERT, BERT, LayoutLM2, M4C) across all three tasks
- SR graph significantly improves performance on Tasks A and B, while LR graph is crucial for Task C's cross-page understanding
- Multi-page processing provides 15-25% accuracy improvement on Task C compared to single-page approaches
- Object-level features outperform token-level features for this document VQA task

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The graph-based VQA model outperforms baselines by explicitly modeling spatial and hierarchical relationships between document elements.
- Mechanism: The model uses two graphs - a spatial relational graph (SR) and a logical relational graph (LR). The SR graph encodes relative positions between elements (e.g., "top", "bottom-left") while the LR graph captures parent-child relationships based on document structure. These graphs are processed through Graph Convolutional Networks (GCNs) to enhance element representations before VQA prediction.
- Core assumption: Document understanding requires explicit modeling of element relationships beyond visual features alone.
- Evidence anchors:
  - [abstract] "A graph-based VQA model is proposed that explicitly integrates the spatial and hierarchical structural relationships between different document elements to boost document structural understanding."
  - [section] "We also propose a graph-based model to give insights into how those graphs can be used to gain a deeper understanding of document element relationships from different aspects."
  - [corpus] Weak - only one related paper mentions graph-based approaches for document understanding, but not specifically VQA.

### Mechanism 2
- Claim: The dataset's multi-page focus addresses a gap in current document VQA by requiring cross-page understanding.
- Mechanism: Questions in Task C require identifying information that spans multiple pages, such as finding all sections that reference a particular table. This forces models to develop holistic document comprehension rather than page-by-page processing.
- Core assumption: Real-world document understanding requires integration of information across pages, not just individual page comprehension.
- Evidence anchors:
  - [abstract] "Our PDF-VQA dataset extends the current scale of document understanding that limits on the single document page to the new scale that asks questions over the full document of multiple pages."
  - [section] "Answering a question in Task C requires reviewing the full document contents and identifying the contents hierarchically related to the queried item in the question."
  - [corpus] Moderate - related papers discuss document understanding and VQA but don't specifically address multi-page document VQA.

### Mechanism 3
- Claim: Automatic question generation with controlled templates enables large-scale dataset creation while maintaining diversity.
- Mechanism: The system uses predefined question templates with parameters like element types, positional relationships, and document content. These parameters are filled from XML annotations of scientific articles, and functional programs extract answers by applying logical operations over the document structure.
- Core assumption: Structured document metadata can be reliably used to generate meaningful QA pairs that test specific understanding capabilities.
- Evidence anchors:
  - [section] "Based on this structural information and the pre-defined question template, we applied an automatic question-generation process to generate large-scale question-answer pairs efficiently."
  - [section] "To automatically generate the ground truth answers to our questions, we first represent each document page... with all the document elements and the associated relations from the two relational graphs..."
  - [corpus] Moderate - related papers discuss question generation but not specifically for document VQA with structured templates.

## Architecture Onboarding

- Component map: Question encoding → Element feature extraction → Graph construction → GCN processing → Feature fusion → Transformer encoding → Decoding → Answer prediction

- Critical path: Question encoding → Element feature extraction → Graph construction → GCN processing → Feature fusion → Transformer encoding → Decoding → Answer prediction

- Design tradeoffs:
  - Using separate SR and LR graphs allows modeling different relationship types but increases complexity
  - Object-level features vs. token-level features: Object features work better for PDF-VQA but may lose fine-grained text information
  - Fixed answer space limits Task A but simplifies training; Tasks B and C require index-based retrieval

- Failure signatures:
  - GCNs produce noisy representations if graph construction is incorrect
  - Transformer layers may not effectively integrate graph-enhanced features
  - Pointer network fails if document element indexing is inconsistent
  - Model overfits to specific question patterns rather than learning general document understanding

- First 3 experiments:
  1. Test GCN effectiveness: Train model with SR graph only, LR graph only, and both, comparing performance to ablate the contribution of each graph type
  2. Validate multi-page processing: Compare single-page vs. multi-page input processing on Task C to quantify the benefit of cross-page understanding
  3. Baseline comparison: Implement and test standard vision-language models (e.g., VisualBERT) on the dataset to establish performance floor before adding graph components

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions, but several remain implicit: (1) How does the proposed graph-based model (LoSpa) compare to state-of-the-art document layout analysis models on the PDF-VQA dataset? (2) How does the automatic question generation process affect the quality and diversity of the questions in the PDF-VQA dataset? (3) How does the performance of the models vary across different types of document layouts (e.g., scientific articles, invoices, forms)?

## Limitations
- The automatic question generation process relies heavily on structured XML metadata, which may limit the dataset's generalizability to documents without such annotations
- The effectiveness of the graph-based approach depends on accurate document element detection and relationship extraction, which could fail on poorly formatted PDFs
- The dataset focuses on scientific articles, potentially limiting real-world applicability to other document types

## Confidence

- **Medium confidence**: Claims about multi-page document understanding are supported by task design but require empirical validation across diverse document types
