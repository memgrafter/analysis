# Distributed Learning in Heterogeneous Environment: federated learning with adaptive aggregation and computation reduction

## Quick Facts
- arXiv ID: 2302.10757
- Source URL: https://arxiv.org/abs/2302.10757
- Reference count: 15
- Primary result: Adaptive mixing aggregation (AMA) framework increases test accuracy by up to 19.77% and improves training stability by up to 93.10% compared to naive FL

## Executive Summary
This paper addresses three major challenges in federated learning: non-iid data distribution across devices, system heterogeneity with computation-limited devices, and asynchronous model updates due to dynamic wireless conditions. The authors propose a comprehensive framework called AMA-FES that combines feature extractor sharing to reduce computation burden, adaptive mixing aggregation to handle non-iid data, and staleness-based weighting to manage asynchronous updates. The framework is evaluated on MNIST and FMNIST datasets, demonstrating significant improvements in both accuracy and training stability compared to baseline federated learning approaches.

## Method Summary
The proposed AMA-FES framework introduces three key innovations to address federated learning heterogeneity. First, feature extractor sharing (FES) allows devices to download a pre-trained feature extractor and only train the classifier locally, significantly reducing computation burden on resource-constrained devices. Second, the adaptive mixing aggregation (AMA) scheme combines current and previous model updates using a weighted function that adapts based on data heterogeneity and model performance. Third, a staleness-based weighting function is incorporated to handle asynchronous updates, where devices with different communication delays contribute to the global model based on their update freshness. The framework operates through iterative local training on heterogeneous data followed by weighted aggregation of model updates at the server.

## Key Results
- AMA-FES framework increases test accuracy by up to 19.77% compared to naive federated learning
- Achieves 2.38% accuracy improvement over FedProx baseline on MNIST and FMNIST datasets
- Improves training stability by up to 93.10% as measured by reduced variance in model updates
- Tolerates up to 15 rounds of communication delay without significant accuracy degradation

## Why This Works (Mechanism)
The framework works by addressing the fundamental tension between model accuracy and computational efficiency in heterogeneous federated learning environments. By sharing the feature extractor, devices only need to train a small classifier, reducing computational load while maintaining model expressiveness. The adaptive mixing aggregation dynamically balances between incorporating new local updates and maintaining stability from previous updates, which is crucial when dealing with non-iid data distributions. The staleness weighting ensures that fresher updates from devices with better connectivity have more influence on the global model, preventing stale information from degrading model quality.

## Foundational Learning
- **Feature Extractor Sharing**: Separates feature extraction from classification to reduce local computation. Needed because many edge devices have limited computational resources. Quick check: Verify that feature extractor weights remain stable across training rounds.
- **Adaptive Mixing Aggregation**: Dynamically combines current and historical model updates based on performance metrics. Needed to handle non-iid data where local models may diverge significantly. Quick check: Monitor weight adaptation rates across different data heterogeneity levels.
- **Staleness-Based Weighting**: Assigns higher weights to fresher model updates. Needed to handle asynchronous communication in wireless networks. Quick check: Track accuracy degradation as communication delay increases.
- **Model Aggregation**: Centralized combination of distributed model updates. Needed to create a global model that benefits from all participating devices. Quick check: Verify aggregation weights sum to 1 across all participants.
- **Local Training with Partial Models**: Devices train only a subset of the model parameters. Needed to reduce computation while maintaining learning capability. Quick check: Compare local training time with full-model training.

## Architecture Onboarding

**Component Map**: Client Devices -> Local Training -> Model Upload -> Server Aggregation -> Global Model Distribution -> Client Devices

**Critical Path**: The most critical sequence is: Feature Extractor Distribution → Local Classifier Training → Model Upload → AMA Aggregation → Global Model Distribution. Any delay or failure in this path directly impacts learning progress and model quality.

**Design Tradeoffs**: The framework trades some model accuracy for significant computation reduction through feature extractor sharing. While the adaptive mixing provides robustness to non-iid data, it adds computational overhead at the server for calculating adaptive weights. The staleness weighting improves handling of asynchronous updates but requires tracking and managing update timestamps across all devices.

**Failure Signatures**: Communication failures manifest as missing model updates, which the staleness mechanism partially mitigates but may slow convergence. Severe non-iid data can cause local models to diverge, requiring the adaptive mixing to be more conservative in incorporating new updates. Computation failures on client devices may result in partial or no model updates being uploaded.

## Limitations
- Evaluation limited to simple MNIST and FMNIST datasets, raising questions about applicability to complex real-world tasks

- No comparison against recent state-of-the-art federated learning methods beyond FedProx
