# Interpretable Out-Of-Distribution Detection Using Pattern Identification

## Quick Facts
- arXiv ID: 2302.10303
- Source URL: https://arxiv.org/abs/2302.10303
- Reference count: 16
- Key outcome: Interpretable OoD detection method using pattern identification achieves comparable performance to state-of-the-art methods across multiple datasets and definitions of OoD

## Executive Summary
This paper introduces an interpretable out-of-distribution (OoD) detection method based on pattern identification in latent representations. The approach uses the PARTICUL algorithm to identify recurring patterns in the last convolutional layer of a pre-trained classifier, training pattern detectors on in-distribution data without requiring classifier retraining. The method provides interpretability through visualization of detected patterns, allowing users to understand why certain inputs receive low confidence scores. Experiments demonstrate competitive performance against state-of-the-art OoD-agnostic methods across multiple datasets and OoD definitions, including a novel perturbation-based benchmark.

## Method Summary
The method operates on pre-trained classifiers by extracting features from their last convolutional layer and applying the PARTICUL algorithm to identify recurring patterns. These patterns are then used to train pattern detectors that output correlation scores, which are converted to confidence values using logistic distribution fitting. Two variants are proposed: vanilla PARTICUL with global detectors and class-based PARTICUL with detectors per class. During inference, confidence scores are computed based on maximum correlation with detected patterns, and visualizations are generated using Smoothgrad to highlight pattern locations. The approach is OoD-agnostic as it requires no classifier retraining and works with any pre-trained model.

## Key Results
- Achieves comparable AUROC performance to state-of-the-art OoD-agnostic methods on multiple datasets
- Class-based PARTICUL variant shows improved performance on heterogeneous datasets compared to vanilla approach
- Method demonstrates sensitivity to dataset perturbations, with Spearman correlation indicating robustness to distributional shifts
- Performance varies significantly across classifier architectures, with VGG19BN outperforming ResNet50 on certain datasets

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Pattern detectors trained on latent representations provide interpretable confidence scores.
- Mechanism: The PARTICUL algorithm identifies recurring patterns in the last convolutional layer of a pre-trained classifier. Each pattern detector outputs a maximum correlation score with the input's latent map, modeled as a logistic distribution to generate a confidence value. Visualization of these patterns allows human interpretation.
- Core assumption: Latent representations of in-distribution data contain recurring patterns that are less prominent in out-of-distribution data.
- Evidence anchors:
  - [abstract] "pattern identification allows us to provide images from the IoD dataset as reference points to better explain the confidence scores"
  - [section 4] "PARTICUL aims at identifying recurring patterns in the latent representation of a set of images processed through a CNN"
  - [corpus] Weak: No direct evidence of pattern-based interpretability in neighbor papers
- Break condition: If latent representations of OoD data contain patterns similar to IoD, or if the classifier's latent space is too noisy for consistent pattern detection.

### Mechanism 2
- Claim: Class-based pattern detectors improve OoD detection for heterogeneous datasets.
- Mechanism: Instead of global detectors, this variant trains p detectors per class using class labels during training. During inference, only detectors corresponding to the predicted class contribute to the confidence score.
- Core assumption: Class-specific patterns are more discriminative than global patterns for heterogeneous datasets.
- Evidence anchors:
  - [section 4] "learn more specific detectors to be learnt than the vanilla-PARTICUL approach"
  - [section 5] "For Caltech101 as the reference set, class-based PARTICUL provides similar (CUB200) or better (Stanford Cars) results than vanilla PARTICUL"
  - [corpus] Missing: No neighbor papers discuss class-based pattern detectors for OoD detection
- Break condition: If the classifier frequently misclassifies OoD samples, confidence scores become unreliable regardless of detector quality.

### Mechanism 3
- Claim: OoD detection robustness depends on both dataset characteristics and classifier architecture.
- Mechanism: The paper demonstrates that the same OoD detection method performs differently across architectures (ResNet50 vs VGG19BN) and dataset types (homogeneous vs heterogeneous).
- Core assumption: Classifier architecture influences how well latent representations capture distinguishing features for OoD detection.
- Evidence anchors:
  - [abstract] "Our experiments show that the robustness of all metrics under test does not solely depend on the nature of the IoD dataset or the OoD definition, but also on the architecture of the classifier"
  - [section 5] "Interestingly, when using a VGG19BN (Simonyan & Zisserman (2015)) classifer trained on CUB200, we obtain better results"
  - [corpus] Moderate: Neighbor papers discuss architecture dependence in general OoD detection
- Break condition: If all tested architectures share similar weaknesses against specific OoD types, or if dataset characteristics dominate over architectural differences.

## Architecture Onboarding

- Component map:
  Pre-trained classifier → Last convolutional layer → Pattern detectors → Confidence scores → Visualization

- Critical path: Feature extraction → Pattern detector computation → Confidence score generation
  - The classifier must be pre-trained and frozen
  - Pattern detectors are trained only on IoD training data
  - Confidence scores are computed in real-time during inference

- Design tradeoffs:
  - Global vs class-based detectors: Global detectors work well for homogeneous datasets but may miss class-specific patterns in heterogeneous datasets
  - Number of detectors: More detectors increase specificity but also computational cost and potential overfitting
  - Architecture dependency: Method performance varies across classifier architectures, requiring architecture-specific evaluation

- Failure signatures:
  - High variance in confidence scores across IoD test set indicates poor pattern consistency
  - Low correlation between perturbation magnitude and confidence changes suggests insensitivity to distributional shifts
  - Similar confidence scores for IoD and OoD samples indicate inadequate discrimination

- First 3 experiments:
  1. Verify pattern detection on a homogeneous dataset (CUB200): Train 6 global detectors and visualize their most correlated regions on test images
  2. Compare class-based vs global detectors on a heterogeneous dataset (Caltech101): Train both variants with 4 detectors per class and evaluate AUROC against cross-dataset OoD
  3. Test perturbation sensitivity: Apply Gaussian noise with increasing intensity to CUB200 and measure Spearman correlation between noise level and average confidence scores

- Why unresolved: The current experiments were conducted on smaller datasets (Caltech-101, CUB-200, Stanford Cars, CIFAR-100).

## Limitations

- Method performance shows significant variation across different classifier architectures, suggesting it is not truly architecture-agnostic
- While visualizations are provided, there is limited quantitative validation that these actually improve human understanding of model uncertainty
- The approach relies on the assumption that latent patterns are meaningful and consistent, which may not hold for all datasets or architectures

## Confidence

- Mechanism 1 (pattern-based interpretability): Medium - supported by qualitative evidence but lacking quantitative human studies
- Mechanism 2 (class-based detectors): High - strong experimental support across multiple heterogeneous datasets
- Mechanism 3 (architecture dependency): Medium - demonstrated empirically but not theoretically explained
