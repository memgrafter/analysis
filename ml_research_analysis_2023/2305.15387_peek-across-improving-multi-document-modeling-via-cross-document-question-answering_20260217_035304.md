# Peek Across: Improving Multi-Document Modeling via Cross-Document Question-Answering

## Quick Facts
- **arXiv ID:** 2305.15387
- **Source URL:** https://arxiv.org/abs/2305.15387
- **Reference count:** 31
- **Primary result:** Novel cross-document QA pre-training objective significantly improves multi-document modeling across QA, summarization, and query-focused summarization tasks

## Executive Summary
This paper introduces QAMDEN, a novel pre-training approach for multi-document language models that uses cross-document question answering to improve the model's ability to capture relationships across topically-related documents. The method generates semantically-oriented questions from salient sentences in one document and challenges the model to answer them using information from other related documents. This approach artificially increases pre-training data diversity while directing the model to better recover cross-text informational relationships. QAMDEN is pre-trained using this objective and evaluated on multiple multi-document tasks, demonstrating superior performance compared to existing models and significantly outperforming zero-shot GPT-3.5 and GPT-4 on these tasks.

## Method Summary
The method involves generating question-answer pairs from clusters of topically-related documents using a salience scoring mechanism and the QASem parser to create semantically-oriented questions. The pre-training data is constructed in three modes: excluding the source document, masking the salient sentence, and masking the answer. These question-answer pairs are then used to pre-train a Longformer Encoder-Decoder (LED) model, which is subsequently fine-tuned on downstream multi-document tasks including QA, summarization, and query-focused summarization. The approach effectively increases the pre-training data size by creating multiple views of each document cluster while teaching the model to connect information across documents.

## Key Results
- QAMDEN outperforms existing models on HotpotQA, Multi-News, and D-QFS datasets
- Significantly surpasses zero-shot GPT-3.5 and GPT-4 performance on multi-document tasks
- Successfully enables both short text generation (QA) and long text generation (summarization) capabilities
- Artificially increases pre-training data size through multiple question-answer views per document cluster

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The cross-document question answering objective directs the model to better recover cross-text informational relations
- Mechanism: By generating semantically-oriented questions from salient sentences and requiring the model to answer them using information from other topically-related documents, the model learns to identify and connect relevant information across multiple texts
- Core assumption: The model can effectively learn cross-text relationships through the process of answering questions that require information from multiple documents
- Evidence anchors:
  - [abstract] "This novel multi-document QA formulation directs the model to better recover cross-text informational relations"
  - [section] "Our approach allows us to provide multiple views for every single cluster of documents, thereby artificially increasing the pre-training data size"
- Break condition: If the questions generated do not require information from multiple documents or if the model cannot effectively connect the information across documents

### Mechanism 2
- Claim: The novel multi-document QA formulation enables the model to perform tasks that involve both short text generation (e.g., QA) and long text generation (e.g., summarization)
- Mechanism: The model is pre-trained to generate both the answer to a question and the salient sentence from which the question was generated, allowing it to learn both short and long text generation
- Core assumption: The model can effectively learn both short and long text generation through the process of generating answers and salient sentences
- Evidence anchors:
  - [abstract] "our pre-training objective formulation enables the model to perform tasks that involve both short text generation (e.g., QA) and long text generation (e.g., summarization)"
  - [section] "In the pre-training evaluation phase, the held-out set was split and the loss was measured separately for each mode of the data"
- Break condition: If the model cannot effectively generate both short and long text or if the generated text is not relevant to the task

### Mechanism 3
- Claim: The number of pre-training examples generated by the suggested method is not bounded by the number of clusters, allowing the production of a variety of cross-document contexts
- Mechanism: The approach generates multiple question-answer pairs from each document cluster, providing multiple views of the same cluster and increasing the pre-training data size
- Core assumption: The model can effectively learn from the multiple views of the same cluster and generalize to new contexts
- Evidence anchors:
  - [abstract] "introduces a natural augmentation that artificially increases the pre-training data"
  - [section] "we propose an effective method for expanding the multi-document pre-training corpora"
- Break condition: If the model cannot effectively learn from the multiple views of the same cluster or if the generated data does not improve performance

## Foundational Learning

- **Concept: Cross-document relationships**
  - Why needed here: The model needs to understand how to connect information across multiple documents to effectively answer questions and generate summaries
  - Quick check question: Can you identify the key information from multiple documents that is relevant to answering a specific question?

- **Concept: Question generation and answering**
  - Why needed here: The model needs to be able to generate semantically-oriented questions and answer them using information from multiple documents
  - Quick check question: Can you generate a question from a given sentence and answer it using information from other documents?

- **Concept: Text generation (short and long)**
  - Why needed here: The model needs to be able to generate both short answers to questions and long summaries of multiple documents
  - Quick check question: Can you generate a concise answer to a question and a longer summary of multiple documents?

## Architecture Onboarding

- **Component map:** Pre-training data generation -> Model (LED) pre-training -> Fine-tuning on downstream tasks
- **Critical path:** Pre-training data generation -> Model pre-training -> Fine-tuning on downstream tasks
- **Design tradeoffs:** Increased pre-training data size vs. computational resources required; complexity of question generation vs. quality of generated questions; model size vs. performance on downstream tasks
- **Failure signatures:** Poor performance on downstream tasks; inability to generate relevant answers or summaries; overfitting to the pre-training data
- **First 3 experiments:**
  1. Evaluate the model on a multi-document QA task (e.g., HotpotQA)
  2. Evaluate the model on a multi-document summarization task (e.g., Multi-News)
  3. Compare the performance of the model with and without the cross-document question answering pre-training objective

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does QASem perform on different types of predicates (verbs, nominalizations, discourse relations) in the context of cross-document question generation?
- Basis in paper: Explicit
- Why unresolved: The paper mentions that verbal predicates were specifically targeted for question-answer generation, but does not provide a direct comparison of QASem's performance across different predicate types
- What evidence would resolve it: A detailed analysis comparing the performance of QASem on different predicate types, including quantitative metrics such as question quality scores or downstream task performance

### Open Question 2
- Question: What is the impact of the question filtering strategy on the overall performance of QAMDEN, and how does it compare to other filtering methods?
- Basis in paper: Explicit
- Why unresolved: The paper mentions that question filtering was found to harm the downstream results of QAMDEN, but does not provide a detailed comparison of different filtering methods or their impact on model performance
- What evidence would resolve it: A comprehensive study comparing the performance of QAMDEN with and without question filtering, using different filtering methods, and measuring their impact on various downstream tasks

### Open Question 3
- Question: How does the performance of QAMDEN vary across different domains, and what factors contribute to domain-specific performance differences?
- Basis in paper: Inferred
- Why unresolved: The paper evaluates QAMDEN on datasets from various domains, but does not provide a detailed analysis of domain-specific performance differences or the factors contributing to these differences
- What evidence would resolve it: A systematic study evaluating QAMDEN on a diverse set of datasets from different domains, along with an analysis of the factors contributing to domain-specific performance differences, such as data distribution, language complexity, or task characteristics

## Limitations

- Evaluation scope is narrow, focusing only on three downstream tasks without broader comparison across model families and architectures
- Model's dependence on topically-related document clusters may limit applicability to domains without clear document relationships
- Quality heavily depends on the effectiveness of the QASem parser and salience scoring mechanism, which are not fully detailed

## Confidence

**High Confidence Claims:**
- The cross-document question answering pre-training objective does improve multi-document modeling performance compared to standard LED models on the evaluated tasks
- The approach successfully generates multiple views of document clusters, effectively increasing pre-training data diversity
- QAMDEN demonstrates superior performance on multi-document tasks compared to zero-shot GPT-3.5 and GPT-4

**Medium Confidence Claims:**
- The mechanism by which cross-document QA specifically improves cross-text informational relationships
- The claim that this approach enables both short and long text generation capabilities
- The assertion that this method provides a general solution for multi-document modeling challenges

**Low Confidence Claims:**
- Generalizability beyond the specific tasks and domains tested
- Performance relative to other multi-document pre-training approaches not included in comparisons
- Scalability to larger document collections or different document types

## Next Checks

1. **Domain Generalization Test:** Evaluate QAMDEN on multi-document tasks from completely different domains (e.g., legal documents, scientific literature, or technical manuals) to assess how well the pre-training approach generalizes beyond news articles.

2. **Baseline Expansion:** Compare QAMDEN against other specialized multi-document architectures like Pegasus-Multi, PEGASUS-M, or recent transformer-based models designed for long document processing to establish relative performance positioning.

3. **Ablation Study:** Conduct a systematic ablation of the pre-training components by testing models trained with: only cross-document questions, only document-level questions, and no question generation to isolate the specific contribution of the cross-document QA objective to performance improvements.
