# torchosr -- a PyTorch extension package for Open Set Recognition models evaluation in Python

## Quick Facts
- arXiv ID: 2305.09646
- Source URL: https://arxiv.org/abs/2305.09646
- Reference count: 23
- Primary result: Python package with state-of-the-art OSR methods and automated evaluation framework

## Executive Summary
torchosr is a Python package compatible with PyTorch that offers tools for Open Set Recognition (OSR) in deep neural networks. The package includes two state-of-the-art OSR methods (Thresholded Softmax and Openmax), functions for generating derived datasets with various Openness values, and utilities for experimental analysis. It enables proper evaluation by allowing experiments on multiple configurations and cross-validation folds. The primary goal is to simplify and promote correct experimental evaluation in OSR tasks, where some classes are considered unknown during testing.

## Method Summary
The package provides a unified implementation of Thresholded Softmax and Openmax methods through OSRModule subclasses. It includes automated dataset configuration generation using configure_division and configure_oneclass_division functions, cross-validation support with get_train_test and get_train_test_outlier functions, and evaluation metrics including Inner, Outer, Halfpoint, and Overall scores. The framework supports multiple base datasets (MNIST_base, Omniglot_base, CIFAR10_base, CIFAR100_base, SVHN_base) and provides three baseline architectures for integration with OSR methods.

## Key Results
- Unified, open-source implementation of Thresholded Softmax and Openmax methods
- Automated generation of derived datasets with varying Openness values
- Cross-validation support for proper evaluation in OSR tasks
- Integration with PyTorch and compatibility with standard datasets

## Architecture Onboarding

- **Component map:** Data Module -> Models Module -> Architectures Module -> Utils Module
- **Critical path:** 1. Load base dataset (e.g., MNIST_base) 2. Generate KKC/UUC configurations using configure_division 3. Split data into folds with get_train_test 4. Initialize chosen OSR method with architecture 5. Train and evaluate across configurations
- **Design tradeoffs:** Automating dataset splits increases usability but may limit custom experimental designs. Including only two OSR methods keeps the package focused but may require future extensions for newer algorithms.
- **Failure signatures:** Misconfigured KKC/UUC assignments lead to inflated accuracy. Incorrect epsilon parameter selection causes poor detection of unknown samples. Data leakage from UUC into training folds invalidates cross-validation results.
- **First 3 experiments:**
