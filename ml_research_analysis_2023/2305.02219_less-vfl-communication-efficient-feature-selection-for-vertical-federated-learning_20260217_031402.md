# LESS-VFL: Communication-Efficient Feature Selection for Vertical Federated Learning

## Quick Facts
- arXiv ID: 2305.02219
- Source URL: https://arxiv.org/abs/2305.02219
- Reference count: 40
- One-line primary result: LESS-VFL achieves 20x lower communication cost than group lasso while maintaining comparable accuracy in vertical federated learning feature selection

## Executive Summary
LESS-VFL addresses the challenge of communication-efficient feature selection in vertical federated learning (VFL) systems where multiple parties with vertically partitioned data collaborate to train a model. The method introduces a three-stage approach that first pre-trains the model, then performs embedding component selection on the server side, and finally enables parties to perform local feature selection using the server's guidance. This approach significantly reduces communication overhead compared to standard group lasso methods while achieving comparable accuracy and spurious feature removal rates.

## Method Summary
LESS-VFL proposes a three-stage framework for communication-efficient feature selection in VFL. Stage 1 involves collaborative pre-training of the model using standard VFL training. Stage 2 has the server identify significant embedding components by solving a group lasso optimization problem on pre-trained embeddings. Stage 3 allows parties to perform local feature selection using these significant embedding components as proxies for the true loss function, without requiring further communication with the server. This approach leverages the server's global view to guide local decisions, minimizing the need for iterative communication while still effectively removing spurious features.

## Key Results
- LESS-VFL achieves 20x lower communication cost than group lasso on the Phishing dataset
- Maintains comparable test accuracy to group lasso while removing a similar percentage of spurious features
- Asymptotically removes spurious features with polynomial convergence rate in the number of training samples

## Why This Works (Mechanism)

### Mechanism 1
- Claim: LESS-VFL asymptotically removes spurious features by first identifying significant embedding components through server-side group lasso, then allowing parties to perform local feature selection without further communication.
- Mechanism: The server solves an embedding component selection problem using pre-trained embeddings as fixed inputs, sparsifying the server model's input layer weights. The resulting significant embedding component indices are shared with parties, who then solve a local feature selection problem using these components as a proxy for the true loss function.
- Core assumption: The pre-trained model parameters are close to the optimal parameter set T*, and the set of significant embedding components found by the server accurately represents the loss landscape for local feature selection.

### Mechanism 2
- Claim: LESS-VFL achieves high accuracy by minimizing risk through a three-stage optimization process that preserves significant features while removing non-significant ones.
- Mechanism: Stage 1 pre-trains the model to find approximate optimal parameters. Stage 2 identifies significant embedding components that serve as proxies for the true loss function. Stage 3 allows parties to minimize a proxy risk function that depends only on significant embedding components, effectively removing non-significant features.
- Core assumption: The distance between the learned model and the generating model Θ⋄ decreases at a polynomial rate with respect to the number of training samples N, and the proxy risk function accurately approximates the true risk function.
- Evidence anchors:
  - [abstract] "We analytically prove that LESS-VFL removes spurious features from model training."
  - [section] "Theorem 4.3 (ii) states if we run each LESS-VFL stage to convergence, then we approach a model that minimizes the risk and removes non-significant features at a polynomial rate in terms of the number of training samples N."

### Mechanism 3
- Claim: LESS-VFL significantly reduces communication cost compared to standard group lasso by performing feature selection locally after a single round of embedding sharing.
- Mechanism: Instead of communicating embeddings at every iteration of training, LESS-VFL only communicates once after pre-training to share significant embedding component indices. Parties then perform local feature selection using these indices without further communication.
- Core assumption: The significant embedding component indices can be determined with high accuracy using a small number of pre-training epochs, and local feature selection using these indices is sufficient to remove spurious features.
- Evidence anchors:
  - [abstract] "Experimental results on various datasets show that LESS-VFL achieves comparable accuracy and removes a similar percentage of spurious features as group lasso, but with significantly lower communication cost (e.g., 20x lower on the Phishing dataset)."
  - [section] "Stages 2 and 3 only require one round of communication where parties send current embeddings to the server."

## Architecture Onboarding

- Component map:
  - Parties (M parties with vertically partitioned data) -> Server (stores labels and fusion model) -> Communication channel (for embedding sharing and significant component indices)

- Critical path:
  1. Pre-training: Parties and server train their models collaboratively using standard VFL training.
  2. Embedding Component Selection: Server identifies significant embedding components using group lasso regularization.
  3. Feature Selection: Parties perform local feature selection using significant component indices as proxies for loss function.

- Design tradeoffs:
  - Communication vs. Accuracy: LESS-VFL trades off some accuracy for significant communication savings compared to standard group lasso.
  - Pre-training vs. Feature Selection: The number of pre-training epochs affects both the accuracy of embedding component selection and the communication cost.
  - Regularization Parameters: The choice of λs and λm affects the sparsity of embedding components and feature weights, respectively.

- Failure signatures:
  - Low Accuracy: If pre-training is insufficient or embedding component selection fails, accuracy may be lower than expected.
  - Incomplete Feature Removal: If regularization parameters are too low, some spurious features may not be removed.
  - High Communication Cost: If pre-training requires many epochs, communication cost may be higher than expected.

- First 3 experiments:
  1. Verify Communication Efficiency: Compare communication cost of LESS-VFL vs. standard group lasso on a small dataset.
  2. Test Feature Removal: Evaluate the percentage of spurious features removed by LESS-VFL on a dataset with known spurious features.
  3. Measure Accuracy: Assess the test accuracy of LESS-VFL compared to standard VFL with and without spurious features.

## Open Questions the Paper Calls Out

- How does LESS-VFL perform with different neural network architectures beyond the dense networks used in experiments?
- What is the theoretical impact of using approximate solutions (finite iterations) instead of exact solutions in each stage?
- How does LESS-VFL scale with larger numbers of parties (M > 4)?
- How does the method handle non-continuous features or mixed feature types?

## Limitations

- The method's performance heavily depends on proper pre-training and parameter tuning, which may require dataset-specific optimization
- Theoretical guarantees assume convergence to optimal parameters, which may not be practical in real-world scenarios with finite iterations
- Communication savings may be reduced if pre-training requires many epochs, especially on complex datasets

## Confidence

- Communication Efficiency Claims: Medium - Experimental results show significant improvements, but the 20x reduction on Phishing dataset needs further validation across diverse datasets
- Feature Selection Effectiveness: Medium - While the paper proves asymptotic convergence, the practical performance on small datasets may vary
- Theoretical Guarantees: High - The mathematical proofs are rigorous, though they rely on assumptions about model convergence
