# Fairlearn: Assessing and Improving Fairness of AI Systems

## Quick Facts
- arXiv ID: 2303.16626
- Source URL: https://arxiv.org/abs/2303.16626
- Reference count: 7
- Primary result: Fairlearn is an open source Python library supporting disaggregated evaluation and algorithmic mitigation of AI fairness issues, integrated with sociotechnical learning resources.

## Executive Summary
Fairlearn is an open source project designed to help AI practitioners assess and improve the fairness of their systems. The associated Python library provides tools for evaluating model performance across different demographic groups and includes several algorithmic approaches for mitigating fairness-related harms. The project takes a sociotechnical perspective, recognizing that fairness challenges extend beyond technical metrics to include broader societal context and considerations.

## Method Summary
Fairlearn implements a comprehensive framework for fairness assessment and mitigation in AI systems. The library provides MetricFrame for disaggregated evaluation across sensitive groups, three categories of mitigation algorithms (pre-processing, in-training, and post-processing), and integrated learning resources covering sociotechnical fairness concepts. The approach centers on evaluating allocation and quality-of-service harms while acknowledging that complete "de-biasing" is not possible. The tools are designed to work with existing ML pipelines and support multiple model frameworks including scikit-learn, PyTorch, and TensorFlow.

## Key Results
- Fairlearn provides MetricFrame for systematic identification of performance disparities across sensitive groups
- The library offers reduction-based and adversarial mitigation methods that integrate with existing ML pipelines
- Learning resources are embedded in the API documentation to encourage sociotechnical consideration of fairness

## Architecture Onboarding

- Component map:
  - `fairlearn.metrics.MetricFrame`: Core class for disaggregated evaluation
  - `fairlearn.metrics`: Contains fairness-specific metric functions and `make_derived_metric`
  - `fairlearn.reductions`: Reduction-based mitigation algorithms (e.g., ExponentiatedGradient)
  - `fairlearn.adversarial`: Adversarial mitigation algorithms (e.g., AdversarialClassifier)
  - `fairlearn.preprocessing`: Pre-processing mitigation (e.g., CorrelationRemover)
  - `fairlearn.postprocessing`: Post-processing mitigation (e.g., ThresholdOptimizer)
  - `fairlearn.datasets`: Educational datasets for tutorials
  - Learning resources: Integrated tutorials and user guide sections

- Critical path:
  1. Import and initialize MetricFrame with metrics, y_true, y_pred, and sensitive_features
  2. Compute disaggregated metrics and compare across groups
  3. If disparities found, select appropriate mitigation algorithm based on pipeline stage
  4. Apply mitigation and re-evaluate using MetricFrame
  5. Iterate until acceptable fairness-performance tradeoff is achieved

- Design tradeoffs:
  - Flexibility vs. ease of use: Wrapping arbitrary models enables broad applicability but increases complexity
  - Technical vs. sociotechnical focus: Embedding learning resources ensures context but may be skipped by practitioners seeking quick fixes
  - Performance vs. fairness: Mitigation algorithms introduce tradeoffs that must be managed explicitly

- Failure signatures:
  - MetricFrame raises errors if sensitive_features don't match y_true/y_pred length
  - Reduction algorithms fail if base model doesn't support required interface (e.g., sample weighting)
  - Adversarial algorithms require compatible neural network definitions for PyTorch/TensorFlow
  - Documentation links broken or tutorials inaccessible

- First 3 experiments:
  1. Run MetricFrame on a binary classification dataset with a known sensitive feature to verify disaggregated evaluation works
  2. Apply ThresholdOptimizer to a pre-trained model and observe changes in group-wise metrics
  3. Use ExponentiatedGradient with LogisticRegression to see how reduction-based mitigation affects both accuracy and fairness metrics
