# Correcting Semantic Parses with Natural Language through Dynamic Schema Encoding

## Quick Facts
- arXiv ID: 2305.19974
- Source URL: https://arxiv.org/abs/2305.19974
- Reference count: 10
- Key outcome: DestT5 achieves new state-of-the-art correction accuracy on SPLASH dataset, beating previous best by 12.33%

## Executive Summary
This paper introduces DestT5, a novel approach for interactive semantic parsing in text-to-SQL tasks using natural language feedback. The key innovation is dynamic schema encoding that decouples semantic and syntactic challenges by introducing an auxiliary schema prediction model. This allows the text-to-SQL model to focus on generating valid SQL syntax while leveraging feedback. The authors demonstrate that this approach achieves a new state-of-the-art correction accuracy on the SPLASH dataset, improving upon the previous best by 12.33%, and show effectiveness on a new test set based on errors from modern parsers.

## Method Summary
The method uses an auxiliary schema prediction model (T5-large or RoBERTa-large) to identify relevant database schema items, which are then serialized and used as input for a T5-base text-to-SQL model. The system takes as input a natural language question, incorrect SQL parse, natural language feedback, and database schema. The schema prediction model outputs only those schema items that appear in the gold SQL, allowing the text-to-SQL model to focus solely on generating valid SQL syntax while incorporating feedback. The model is fine-tuned on the Spider dataset for text-to-SQL and the SPLASH dataset for schema prediction.

## Key Results
- DestT5 achieves 53.43% Exact Set Match accuracy on SPLASH test set, beating previous best by 12.33%
- The approach demonstrates 26% improvement in accuracy by separating semantic and syntactic challenges
- Shows effectiveness in zero-shot generalization to errors made by EditSQL, TaBERT, and RAT-SQL parsers

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Dynamic schema encoding separates semantic and syntactic parsing challenges, improving text-to-SQL accuracy.
- Mechanism: An auxiliary schema prediction model identifies relevant database schema items, which are then serialized into the input for the final text-to-SQL model. This allows the text-to-SQL model to focus solely on generating valid SQL syntax.
- Core assumption: Decoupling schema selection from SQL generation reduces the complexity of the parsing task and improves overall accuracy.
- Evidence anchors: [abstract] "By separating the semantic and syntactic difficulties of the task, we show that the accuracy of text-to-SQL parsers can be boosted by up to 26%..."; [section] "We take a similar approach with the SPLASH dataset, separating the semantic and syntactic challenges of text-to-SQL by introducing an auxiliary schema prediction model."

### Mechanism 2
- Claim: Using natural language feedback allows for interactive correction of semantic parse errors.
- Mechanism: When the text-to-SQL model makes an error, natural language feedback is provided to explain how the parse should be corrected. This feedback is incorporated into the model's input, allowing it to learn from its mistakes and improve its accuracy.
- Core assumption: Natural language feedback provides sufficient information for the model to understand and correct its errors.
- Evidence anchors: [abstract] "We explore semantic parse correction with natural language feedback..."; [section] "As a majority of parsing mistakes that neural text-to-SQL parsers make are minor, it is often feasible for humans to suggest fixes for such mistakes using natural language feedback."

### Mechanism 3
- Claim: DestT5 achieves state-of-the-art correction accuracy on the SPLASH dataset.
- Mechanism: DestT5 combines dynamic schema encoding with a T5-based text-to-SQL model and natural language feedback to achieve superior correction accuracy compared to previous methods.
- Core assumption: The combination of dynamic schema encoding and natural language feedback provides a significant improvement in correction accuracy.
- Evidence anchors: [abstract] "We achieve a new state-of-the-art on the interactive parsing task SPLASH, beating the best published correction accuracy (Elgohary et al., 2021) by 12.33% using DestT5."; [section] "Achieving an EM score of 53.43%, DestT5 beats the previous best score of NL-EDIT by 12.33%."

## Architecture Onboarding

- Component map: Natural language question -> Schema prediction model (T5-large/RoBERTa-large) -> Serialized schema items + Natural language feedback + Incorrect SQL parse -> Text-to-SQL model (T5-base) -> Corrected SQL query

- Critical path:
  1. Input natural language question, incorrect SQL parse, natural language feedback, and database schema
  2. Schema prediction model identifies relevant schema items
  3. Predicted schema items are serialized and used as input for text-to-SQL model
  4. Text-to-SQL model generates final SQL query using predicted schema items and feedback
  5. Output corrected SQL query

- Design tradeoffs:
  - Using a separate schema prediction model adds complexity but improves accuracy
  - Natural language feedback is more intuitive but may be less precise than structured feedback
  - T5-based models are powerful but require significant computational resources

- Failure signatures:
  - Schema prediction model fails to identify relevant schema items
  - Text-to-SQL model generates invalid SQL syntax
  - Natural language feedback is ambiguous or insufficient to correct the error

- First 3 experiments:
  1. Evaluate the accuracy of the schema prediction model on the SPLASH test set
  2. Compare the performance of DestT5 with and without natural language feedback
  3. Test the zero-shot generalization of DestT5 to errors made by other parsers (e.g., EditSQL, TaBERT, RAT-SQL)

## Limitations
- Approach relies on the assumption that schema prediction can be effectively separated from SQL generation, which may not generalize well to more complex schemas or cross-database tasks.
- Evaluation is limited to the Spider dataset and a modified version of SPLASH, raising questions about applicability to other text-to-SQL benchmarks or real-world scenarios.
- Reliance on natural language feedback assumes availability of high-quality feedback data, which may not always be practical in real-world applications.
