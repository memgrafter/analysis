# HPN: Personalized Federated Hyperparameter Optimization

## Quick Facts
- arXiv ID: 2304.05195
- Source URL: https://arxiv.org/abs/2304.05195
- Reference count: 8
- Key outcome: Novel HPN achieves up to 2.8% relative improvement in test accuracy for personalized federated hyperparameter optimization, particularly effective under high data heterogeneity

## Executive Summary
This paper introduces personalized federated hyperparameter optimization (pFedHPO) to address the challenge of tuning hyperparameters for heterogeneous clients in federated learning. The authors propose a HyperParameter Network (HPN) that learns to generate client-specific hyperparameters based on privacy-preserving client encodings computed using random Fourier features. To efficiently train HPN, they design a random start training mechanism that balances fidelity and efficiency. Extensive experiments on diverse federated learning tasks (NLP, graph, image) demonstrate that HPN outperforms non-personalized federated hyperparameter optimization methods, with relative improvements in test accuracy of up to 2.8%.

## Method Summary
The method involves a HyperParameter Network (HPN) that takes client encodings as input and outputs distributions over the hyperparameter search space. Client encodings are computed via random Fourier features (RFF) to protect privacy while capturing data distribution. A Random Start Training (RST) mechanism is used for efficient low-fidelity evaluations, where FL training starts from random checkpoints to estimate hyperparameter quality. The HPN is trained using policy gradient, where the validation performance serves as the reward signal. The approach is tested on three federated learning tasks with varying data heterogeneity levels.

## Key Results
- HPN achieves up to 2.8% relative improvement in test accuracy compared to non-personalized methods
- Under high data heterogeneity (α=0.05), HPN outperforms random search by up to 1.5% in accuracy
- HPN demonstrates consistent performance improvements across NLP, graph, and image federated learning tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The HPN learns client-specific hyperparameter distributions via a shared policy network, reducing sample complexity by sharing model parameters across clients.
- Mechanism: Each client's encoding is fed into a shared hyperparameter network, which outputs parameters of a distribution over the hyperparameter space. The network is updated via policy gradient using the validation performance as reward.
- Core assumption: Client encodings are informative enough to reflect each client's data distribution and enable the network to output appropriate hyperparameters.
- Evidence anchors:
  - [abstract] "We propose learning a HyperParameter Network (HPN) fed with client encoding to decide personalized hyperparameters."
  - [section] "Considering the above two factors in optimizing Eq. (3), we propose to learn a HyperParameter Network (HPN) shared by all the clients to decide their hyperparameter configuration based on their client encodings."
- Break condition: If client encodings fail to capture meaningful differences between clients, the HPN will output ineffective hyperparameter distributions.

### Mechanism 2
- Claim: Random Fourier Features (RFF) are used to compute client encodings that protect privacy while reflecting data distribution.
- Mechanism: RFF transform local training data into frequency domain, and client encodings are obtained by averaging RFF vectors across all examples. This transformation obfuscates raw data patterns.
- Core assumption: RFF can approximate translation-invariant kernels and capture general data distribution shapes, providing sufficient information for HPN while preserving privacy.
- Evidence anchors:
  - [abstract] "The client encoding is calculated with a random projection-based procedure to protect each client's privacy."
  - [section] "To overcome this challenges, we propose to exploit random Fourier features (RFF) for client encoding. RFF are generated by randomly sampling frequency vectors from a normal distribution and then projecting data points onto them."
- Break condition: If the RFF transformation loses too much information about the data distribution, the client encodings will be uninformative for HPN.

### Mechanism 3
- Claim: Random Start Training (RST) balances efficiency and accuracy in low-fidelity evaluations by starting FL training from random checkpoints.
- Mechanism: Before HPN training, complete FL courses are run to save model checkpoints. During HPN training, each trial starts from a randomly selected checkpoint and runs for a few communication rounds. The validation performance gain over the checkpoint is used as reward.
- Core assumption: The validation performance gain from a random starting point provides a reasonable estimate of hyperparameter quality across the entire FL course.
- Evidence anchors:
  - [abstract] "Besides, we design a novel mechanism to debias the low-fidelity function evaluation samples for learning HPN."
  - [section] "To solve this problem, we propose Random Start Training (RST)... Since RST only trains FL for Ts rounds at each trail, the communication cost of RST is much less than that of the method which runs a complete FL course for evaluation."
- Break condition: If the random starting points are too far from optimal, the performance gains will not correlate well with true hyperparameter quality.

## Architecture Onboarding

- Component map:
  - Client side: Each client has local data, computes RFF-based encoding, runs local training with received hyperparameters, and returns validation results
  - Server side: Maintains hyperparameter network (HPN), computes client encodings, generates hyperparameter distributions, orchestrates FL training, updates HPN via policy gradient, and manages RST checkpoints
  - Communication: Clients send encodings and local models; server broadcasts global model and hyperparameters

- Critical path:
  1. Compute client encodings using RFF
  2. HPN generates hyperparameter distributions from encodings
  3. Clients receive hyperparameters and run local training
  4. Clients return validation results
  5. Server updates HPN using policy gradient with validation results
  6. Repeat until convergence

- Design tradeoffs:
  - Privacy vs. informativeness of client encodings (RFF transformation)
  - Efficiency vs. accuracy of hyperparameter evaluation (RST vs. full training)
  - Sample complexity vs. personalization (shared HPN vs. individual hyperparameter tuning)

- Failure signatures:
  - HPN outputs similar hyperparameters for all clients despite different encodings (encoding failure)
  - HPN fails to converge or oscillates (learning rate too high, insufficient exploration)
  - Validation performance does not improve over time (poor hyperparameter space, ineffective policy gradient)

- First 3 experiments:
  1. Verify that client encodings computed via RFF preserve some information about data distribution by comparing similarity in encoding space to similarity in raw data space
  2. Test the HPN's ability to generate different hyperparameter distributions for different client encodings by feeding in synthetic encodings and checking output diversity
  3. Evaluate the effectiveness of RST by comparing the correlation between validation performance gains from RST and full training for a set of hyperparameters

## Open Questions the Paper Calls Out

- The paper mentions potential issues in pFedHPO include handling adversarial clients and communication-efficient pFedHPO.

## Limitations
- The effectiveness of RFF for client encodings may vary across different data types and distributions
- RST's efficiency gains depend on the correlation between validation gains and true hyperparameter quality, which may not hold universally
- The policy gradient approach requires careful hyperparameter tuning and may struggle with exploration-exploitation balance

## Confidence
- Mechanism 1 (HPN learning client-specific distributions): Medium - well-supported by experimental results but theoretical guarantees are limited
- Mechanism 2 (RFF for privacy-preserving encodings): Medium - practical approach but limited theoretical analysis of privacy-utility tradeoff
- Mechanism 3 (RST for efficient evaluation): Low - innovative but lacks extensive validation across different FL scenarios
