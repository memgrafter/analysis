# Learning Density-Based Correlated Equilibria for Markov Games

## Quick Facts
- arXiv ID: 2302.08001
- Source URL: https://arxiv.org/abs/2302.08001
- Reference count: 40
- Key outcome: Introduces Density-Based Correlated Equilibria (DBCE) for Markov games, enabling explicit control over state visitation frequencies while maintaining CE constraints, with DBCPI algorithm outperforming existing methods in satisfying safety, frequency, and fairness requirements.

## Executive Summary
This paper introduces Density-Based Correlated Equilibria (DBCE) as a novel solution concept for Markov games that explicitly incorporates state-density requirements without modifying the original game or shrinking the feasible CE set. Unlike existing approaches that implicitly handle requirements like safety and fairness by modifying rewards or adding constraints, DBCE treats these as explicit objectives while maintaining CE constraints as hard constraints. The authors propose the Density-Based Correlated Policy Iteration (DBCPI) algorithm, which iteratively updates policies and occupancy measures to converge to a valid DBCE under certain assumptions. Experiments on three games demonstrate that DBCPI outperforms existing methods in finding CEs that better satisfy specified state-density requirements.

## Method Summary
The method introduces DBCE for Markov games by integrating state-density constraints directly into CE optimization through a unified representation using occupancy measures. DBCPI algorithm is proposed to compute DBCE through iterative policy evaluation and improvement steps, where each stage game is solved via linear programming to find the optimal policy. The approach unifies the representation of state density and expected returns in the same space, enabling joint optimization without altering the original feasible CE set. Convergence is guaranteed when stage games have globally optimal solutions.

## Key Results
- DBCPI achieves lower MaxReg and MaxBF values compared to constrained methods and risk-sensitive reward modification baselines
- DBCE better satisfies state-density requirements (safety, frequency, fairness) across all three tested games
- The algorithm generates more accurate trajectories that match specified density constraints
- Converges to valid DBCE equilibria while maintaining the original game structure

- **Claim**: DBCE integrates state-density constraints directly into CE optimization without altering the feasible CE set.
- **Mechanism**: DBCE treats state-density requirements as an objective function (density error) while maintaining CE constraints as hard constraints. This allows explicit control over state visitation frequencies without changing the underlying game or shrinking the CE polytope.
- **Core assumption**: The density error function can be expressed in terms of occupancy measures, which share the same representation space as expected returns.

- **Claim**: DBCPI converges to a valid DBCE under certain assumptions by alternating between policy evaluation and improvement.
- **Mechanism**: DBCPI iteratively solves a sequence of stage games where Q-values are fixed, finding a DBCE for each stage. Policy evaluation updates Q-values using the current policy, while policy improvement solves the constrained LP for the next stage. Convergence is guaranteed when each stage game has a globally optimal solution.

### Mechanism 3
- **Claim**: Occupancy measures unify the representation of state density and expected returns, enabling joint optimization.
- **Mechanism**: Both the density function ρᵖ(s) and expected return E[Q] can be rewritten in terms of occupancy measures f(s,a). This allows the constrained optimization problem to be solved in a single space rather than two separate ones, making the problem tractable.
- **Core assumption**: The Bellman flow constraints ensure that f is a valid occupancy measure corresponding to some stationary policy π.
- **Evidence anchors**:

## Architecture Onboarding

- **Component map**: Game environment (S, A, P, r, η, γ) -> DBCE solver (occupancy measure computation via LP) -> Policy evaluation module (Q-value updates) -> Density error calculator (for MDCE, FMCE, MDGCE) -> Trajectory generator (for evaluation)

- **Critical path**: 
  1. Initialize Q-values and policy
  2. Solve LP to find DBCE occupancy measure
  3. Convert occupancy measure to policy
  4. Evaluate policy to update Q-values
  5. Repeat until convergence

- **Design tradeoffs**:
  - Computational cost vs accuracy in LP solver
  - Learning rate decay schedule impact on convergence
  - Choice of density error function affects which DBCE is found
  - Number of iterations vs policy quality

- **Failure signatures**:
  - MaxReg > 0 indicates policy deviates from CE set
  - Large MaxBF indicates occupancy measure doesn't match policy
  - Error not converging suggests stage games lack optimal solutions
  - High variance across runs suggests instability in learning
