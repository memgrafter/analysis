# Combining Self-labeling with Selective Sampling

## Quick Facts
- arXiv ID: 2301.04420
- Source URL: https://arxiv.org/abs/2301.04420
- Reference count: 31
- Primary result: Method combines self-labeling with selective sampling in active learning, performing comparably to other AL algorithms on smaller datasets and better on larger ones.

## Executive Summary
This paper proposes a method that combines self-labeling with selective sampling in active learning using an ensemble of classifiers. The approach uses ensemble disagreement as an informativeness signal to decide whether to request a label from an oracle or apply self-labeling. A prior filter mechanism is introduced to address class imbalance issues that arise from naive self-labeling. The method is designed to be robust to initial model accuracy and seed size, making it suitable for low-data regimes.

## Method Summary
The method employs an ensemble of classifiers to evaluate prediction inconsistency and decide between requesting a label or using self-labeling. When at least half of the ensemble members predict the same class with confidence above threshold τ, the sample is self-labeled; otherwise, an oracle query is made. Bootstrapping with Poisson resampling (λ=1) is used during training to improve ensemble diversity. A prior filter mechanism monitors the proportion of predicted classes in the last k labels to prevent class imbalance from biased self-labeling.

## Key Results
- Performs comparably to other active learning algorithms on smaller datasets
- Outperforms other methods on larger datasets
- Shows robustness to initial model accuracy and seed size
- Effective in low-data regimes

## Why This Works (Mechanism)

### Mechanism 1
- Ensemble disagreement serves as an informativeness signal for deciding between querying labels or applying self-labeling
- When ensemble members agree confidently on the same class, self-labeling is applied; otherwise, oracle queries are made
- Core assumption: Confident ensemble agreement indicates correct predictions that don't need labeling
- Evidence anchors: [abstract], [section 3.2], [corpus]
- Break condition: Ensemble predictions become too diverse due to concept drift or poor initial performance

### Mechanism 2
- Bootstrapping during training reduces variance and improves ensemble diversity
- Labeled data is resampled using Poisson distribution (λ=1) to create multiple training sets
- Core assumption: Resampling introduces diversity that helps ensemble generalization
- Evidence anchors: [section 3.2], [section 3.6], [corpus]
- Break condition: Bootstrapping leads to overfitting on noisy self-labeled data

### Mechanism 3
- Prior filter prevents imbalance caused by biased self-labeling
- Compares predicted class proportion among last k labels to ideal balanced prior
- Core assumption: Model predictions are biased toward certain classes and filtering can correct this
- Evidence anchors: [abstract], [section 3.4], [corpus]
- Break condition: Prior filter incorrectly rejects many samples, slowing learning

## Architecture Onboarding

- **Component map**: Input stream → Ensemble predictions → Confidence/agreement check → Prior filter → Dataset update (self-label or query) → Bootstrapped training → Output model
- **Critical path**: Data stream → Ensemble inference → Decision (self-label vs. query) → Dataset update → Retraining
- **Design tradeoffs**: Self-labeling increases data volume but risks noise; bootstrapping improves diversity but increases computation; prior filter mitigates imbalance but may reject useful samples
- **Failure signatures**: Frequent oracle queries indicate poor ensemble agreement; rapid majority class growth indicates prior filter failure; performance plateau suggests bootstrapping overfitting
- **First 3 experiments**:
  1. Run with synthetic balanced data, no prior filter, to observe imbalance growth
  2. Run with real imbalanced dataset, enable prior filter, measure class distribution over time
  3. Run ablation removing bootstrapping, compare ensemble diversity and performance

## Limitations

- Prior filter mechanism lacks precise implementation details, particularly calculation of k and handling of class imbalance
- Exact hyperparameter ranges used in random search are not specified
- Method's performance on highly imbalanced real-world datasets is not thoroughly validated

## Confidence

- **High Confidence**: Ensemble disagreement mechanism for deciding between self-labeling and oracle queries
- **Medium Confidence**: Bootstrapping technique for improving ensemble diversity
- **Low Confidence**: Prior filter's effectiveness in real-world imbalanced datasets
