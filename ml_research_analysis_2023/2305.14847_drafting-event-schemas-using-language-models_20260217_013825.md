# Drafting Event Schemas using Language Models

## Quick Facts
- **arXiv ID:** 2305.14847
- **Source URL:** https://arxiv.org/abs/2305.14847
- **Reference count:** 14
- **Primary result:** Large language models can generate event schemas with moderate recall against human-curated schemas, achieving better results when using multiple prompts or samples.

## Executive Summary
This paper explores the use of large language models for drafting event schemas in natural language, evaluating their performance against human-curated schemas. The authors demonstrate that zero-shot and one-shot prompting can elicit structured event sequences from models like GPT-3.5 and Flan-T5, achieving moderate recall rates of 32-42% when compared to gold schemas using textual entailment methods. The work establishes a framework for prompt-based schema generation and evaluation, showing that stylistic control improves when demonstration schemas are provided, and that textual entailment offers a viable approach for measuring semantic overlap between generated and gold schemas.

## Method Summary
The authors employ large language models (GPT-3.5 and Flan-T5) with zero-shot and one-shot prompting strategies to generate event schemas for specific domains. Zero-shot prompts use verbalizers to specify domains, while one-shot prompts condition generation on demonstration schemas. Generated schemas are evaluated against gold schemas from RESIN-11 and CuratedSchemas datasets using textual entailment models (roberta-large-wanli) to measure recall in both any-directional and bidirectional modes. Human evaluation via AMT validates entailment model judgments, and experiments compare single versus multiple prompt sampling strategies.

## Key Results
- Language models achieve moderate recall (32-42%) against human-curated schemas when using textual entailment evaluation
- Multiple prompts or samples consistently improve recall over single prompts
- One-shot prompting with demonstration schemas provides better stylistic control over generated schemas
- Textual entailment methods effectively capture semantic overlap between generated and gold schemas

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Large language models can generate event schemas with moderate recall against human-curated schemas when given appropriate prompts.
- **Mechanism:** The language models leverage their training on large corpora to surface events characteristic to specific domains. Zero-shot prompting with carefully designed verbalizers enables the model to produce structured event lists without requiring task-specific training.
- **Core assumption:** The pre-training corpus contains sufficient domain-relevant events and the model's generation capabilities are strong enough to extract and organize them coherently.
- **Evidence anchors:**
  - [abstract] "We show that large language models are able to achieve moderate recall against schemas taken from two different datasets"
  - [section 2] "We explore both zero-shot and few-shot (specifically one-shot) prediction of schemas"
- **Break condition:** If the domain is too niche or the relevant events are underrepresented in the training corpus, the model will fail to generate relevant schemas.

### Mechanism 2
- **Claim:** Textual entailment methods can effectively evaluate overlap between generated and gold schemas by capturing semantic similarity between events.
- **Mechanism:** Textual entailment models assess whether a generated event semantically entails or is entailed by a gold event. This bidirectional approach handles variations in specificity and phrasing while measuring recall.
- **Core assumption:** The entailment model can reliably capture semantic equivalence even when surface forms differ significantly.
- **Evidence anchors:**
  - [section 3] "We use entailment to compare our drafted schemas to two sources of ground-truth schemas"
  - [section 5] "The recall score r for an event s ∈ S∗ is then given by r(s, Ŝ) = max_{ŝ∈Ŝ} (max(E(s, ŝ), E(ŝ, s)))"
- **Break condition:** If the entailment model's performance degrades on longer or more complex event descriptions, the evaluation will become unreliable.

### Mechanism 3
- **Claim:** One-shot prompting with demonstration schemas can guide language models to generate schemas matching the stylistic features of target datasets.
- **Mechanism:** By conditioning generation on a hand-authored schema from a different domain, the model learns stylistic patterns (event specificity, sentence length, structure) that can be applied to the target domain.
- **Core assumption:** The model can generalize stylistic features from the demonstration to new domains without losing domain relevance.
- **Evidence anchors:**
  - [section 2] "We also explore one-shot models P(S | v(d), S_{demo}) that condition on a schema demonstration"
  - [section 5.2] "We can much better match the style of schemas by providing them as demonstrations in one-shot prompts"
- **Break condition:** If the demonstration schema is too domain-specific, the model may struggle to adapt the style to a different domain.

## Architecture Onboarding

- **Component map:**
  - Domain Specification -> Prompt Generator -> Language Model Interface -> Schema Parser -> Entailment Evaluator -> Evaluation Results

- **Critical path:**
  1. Receive domain specification
  2. Generate prompts (zero-shot or one-shot)
  3. Query language model and parse output
  4. Evaluate against gold schemas using entailment
  5. (Optional) Validate entailment decisions with human evaluation

- **Design tradeoffs:**
  - Zero-shot vs. one-shot: Zero-shot is simpler but one-shot provides better stylistic control
  - Single vs. multiple prompts: Multiple prompts increase recall but also increase computation and potential redundancy
  - Entailment strictness: Any-directional is more permissive (higher recall) while bidirectional is stricter (higher precision)

- **Failure signatures:**
  - Low recall despite multiple prompts: Indicates domain may be underrepresented in training data
  - High human disagreement with entailment: Suggests entailment model may not capture domain-specific semantic nuances
  - Stylistic mismatch in one-shot generation: May require better demonstration schemas or alternative prompting strategies

- **First 3 experiments:**
  1. Generate schemas for a simple domain (e.g., "getting coffee") using zero-shot prompting to verify basic functionality
  2. Test one-shot prompting by providing a demonstration schema and measuring stylistic similarity
  3. Compare any-directional vs. bidirectional entailment on a small dataset to understand precision-recall tradeoff

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** How does the quality of generated event schemas vary across different domains of events?
- **Basis in paper:** [explicit] The paper discusses experiments on six different domains: international conflict, natural disaster, IED attacks, disease outbreak, mass shooting, and kidnapping.
- **Why unresolved:** While the paper reports average recall scores across all domains, it does not provide a detailed analysis of how schema generation performance varies by domain.
- **What evidence would resolve it:** A breakdown of recall scores for each domain, along with qualitative analysis of the types of errors or omissions common in each domain.

### Open Question 2
- **Question:** How effective are the generated event schemas for downstream tasks like event prediction or forecasting?
- **Basis in paper:** [inferred] The paper discusses using schemas for explainable predictions and forecasting, but does not report on actual performance on these tasks.
- **Why unresolved:** The paper focuses on schema generation and evaluation, but does not demonstrate the practical utility of the schemas for prediction or forecasting.
- **What evidence would resolve it:** Experiments showing improved performance on event prediction or forecasting tasks when using the generated schemas as input, compared to baselines without schemas.

### Open Question 3
- **Question:** How sensitive is the evaluation using textual entailment to stylistic differences between the generated and gold schemas?
- **Basis in paper:** [explicit] The paper discusses stylistic differences between datasets and generations, and shows that one-shot prompting can better match the style of gold schemas.
- **Why unresolved:** While the paper shows that entailment-based evaluation is reliable, it does not explore how sensitive the results are to stylistic differences between the schemas being compared.
- **What evidence would resolve it:** An analysis of how recall scores change when comparing schemas with varying degrees of stylistic similarity, and an exploration of whether entailment models can be fine-tuned to be more robust to stylistic differences.

## Limitations

- Recall rates remain substantially below production requirements (approximately 60-68% of gold events missing)
- Evaluation methodology relies on a single entailment model without domain-specific tuning
- One-shot prompting shows inconsistent performance across domains
- Manual verification process covered only 200 event pairs out of 1,000+ comparisons

## Confidence

- **High confidence**: Language models can generate coherent event schemas for multiple domains when given appropriate prompts; one-shot prompting effectively controls stylistic features; textual entailment provides a viable evaluation framework for schema comparison
- **Medium confidence**: Multiple prompts consistently improve recall; the proposed evaluation methodology is robust across domains; stylistic transfer through one-shot prompting generalizes well
- **Low confidence**: The specific recall improvements from one-shot prompting are consistent and predictable; entailment model performance is uniform across all domains; the proposed approach scales to more complex schema representations

## Next Checks

1. **Domain-specific entailment tuning**: Evaluate whether fine-tuning the entailment model on domain-specific data improves recall accuracy by 10-15% for domains with low current performance (e.g., RESIN-11).

2. **Schema complexity scaling**: Test schema generation on domains requiring temporal ordering and argument relationships (beyond simple event sequences) to identify performance degradation points.

3. **Human evaluation expansion**: Conduct comprehensive human evaluation of all generated schemas against gold schemas to establish ground truth performance of the entailment-based evaluation methodology.
