# Semantic Web Enabled Geographic Question Answering Framework: GeoTR

## Quick Facts
- arXiv ID: 2301.04752
- Source URL: https://arxiv.org/abs/2301.04752
- Reference count: 0
- A Turkish geographic question answering framework combining NLP with linked data achieves 71% F-measure

## Executive Summary
GeoTR presents a novel framework for answering geographic questions in Turkish by combining natural language processing with linked data technologies. The system addresses the gap in Turkish question answering systems that utilize linked data in the geographic domain. The framework interprets Turkish natural language queries and generates SPARQL queries over a novel Turkish geography ontology, handling both informative and quantitative reasoning questions. The hybrid approach combining NLP output with ontology validation outperforms pure ontology-based approaches in experimental evaluations.

## Method Summary
The GeoTR framework employs a three-layer architecture for geographic question answering. The first layer performs question pre-processing using Turkish NLP techniques including tokenization, stemming, and named entity recognition. The second layer formulates SPARQL queries through a hybrid approach that combines NLP output with ontology validation to ensure semantic correctness. The third layer executes queries on the developed GEO-TR ontology and returns results to users. The framework specifically handles two types of questions: informative questions requiring factual answers and quantitative reasoning questions requiring calculations based on geographic data.

## Key Results
- Hybrid approach (Method 1) achieves 77% precision, 68% recall, and 71% F-measure
- Ontology-based approach alone (Method 2) achieves 64% precision, 57% recall, and 60% F-measure
- Learning model for quantitative questions achieves 72% accuracy

## Why This Works (Mechanism)
The hybrid approach works by leveraging both linguistic patterns from Turkish NLP and semantic validation from the geography ontology. This combination allows the system to correctly interpret natural language queries while ensuring that generated SPARQL queries are semantically valid within the geographic domain. The ontology provides structured knowledge about Turkish geography that NLP alone cannot capture, while NLP handles the variability and ambiguity of natural language questions.

## Architecture Onboarding

Component map: Turkish Question -> NLP Preprocessing -> Query Formulation -> GEO-TR Ontology -> SPARQL Query -> Results

Critical path: Question input → NLP preprocessing → Hybrid query formulation → Ontology validation → SPARQL execution → Result generation

Design tradeoffs: The hybrid approach trades computational complexity for improved accuracy by running both NLP and ontology validation, whereas simpler approaches might be faster but less accurate.

Failure signatures: Performance degradation occurs with complex multi-hop queries, questions with ambiguous geographic references, and when Turkish NLP preprocessing fails to correctly identify named entities.
