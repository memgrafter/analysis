# Prototype-Sample Relation Distillation: Towards Replay-Free Continual Learning

## Quick Facts
- arXiv ID: 2303.14771
- Source URL: https://arxiv.org/abs/2303.14771
- Reference count: 11
- Primary result: Achieves state-of-the-art performance in replay-free continual learning, matching or exceeding replay-based methods on CIFAR100, MiniImageNet, and ImageNet32 without storing prior task data

## Executive Summary
This paper introduces Prototype-Sample Relation Distillation (PRD), a replay-free continual learning method that avoids catastrophic forgetting without storing prior task data. The method combines supervised contrastive learning with evolving class prototypes and a novel distillation loss that maintains relative similarities between prototypes and current task samples. PRD enables the model to adapt representations to new tasks while preserving the relevance of old class prototypes, achieving strong performance in both task-incremental and class-incremental settings.

## Method Summary
PRD employs a neural network with an encoder mapping inputs to features and a projection head mapping features to a contrastive space. The model is trained using three loss components: supervised contrastive loss for discriminative representation learning, prototype learning loss for maintaining class prototypes without contrastive suppression, and prototype-sample relation distillation loss for preserving relative similarity distributions. The method evolves prototypes in the same embedding space as samples, enabling classification without stored data, while distillation constrains prototypes to maintain relative similarities to new task data through KL divergence minimization.

## Key Results
- Matches or exceeds replay-based methods with large buffers on CIFAR100, MiniImageNet, and ImageNet32
- Demonstrates strong performance in both task-incremental and class-incremental settings
- Maintains effective plasticity-stability trade-off with low representation forgetting
- Outperforms recent replay-free methods while using no stored data

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Supervised contrastive loss preserves discriminative representation structure across tasks, reducing representation forgetting even without replay buffers.
- **Mechanism:** The supervised contrastive loss pulls together embeddings of samples from the same class while pushing apart embeddings from different classes, forming tight, well-separated class clusters in the embedding space.
- **Core assumption:** The embedding space remains stable enough that old class clusters remain separable after new task learning, even without explicit constraints on old data.
- **Evidence anchors:** [abstract] "samples are mapped to an embedding space where the representations are learned using a supervised contrastive loss"; [section] "it was observed that when performing continual learning with the Supervised Contrastive Loss (Khosla et al., 2020) and no CL constraints, the efficiency of representations on old task data tends to match that of complex CL data-storage methods"
- **Break condition:** If the embedding space undergoes large shifts due to new tasks, old class clusters may become poorly separated, invalidating the assumption.

### Mechanism 2
- **Claim:** Prototypes evolve in the same embedding space as samples, enabling direct similarity-based classification without needing stored data.
- **Mechanism:** Each class is represented by a prototype vector in the embedding space; new samples are classified by their similarity to these prototypes. Prototypes are updated incrementally via tightness loss only, avoiding negative interference with old prototypes.
- **Core assumption:** Prototypes remain representative of their classes even after embedding shifts, because the tightness loss maintains positive alignment without contrastive suppression.
- **Evidence anchors:** [abstract] "Class prototypes are evolved continually in the same latent space, enabling learning and prediction at any point"; [section] "For each class c we initialize a random prototype pc ∈ Rd. We want to optimize these prototypes to be representatives of current classes samples without introducing any suppression to prototypes of previous classes"
- **Break condition:** If prototypes drift too far from their class distributions due to embedding changes, classification accuracy degrades.

### Mechanism 3
- **Claim:** Prototype-Sample Relation Distillation (PRD) preserves relative similarities between old prototypes and current samples, allowing the embedding to adapt while keeping old prototypes relevant.
- **Mechanism:** Before each task, compute the softmax similarity distribution of each old prototype over the current task's samples. During training, distill this distribution by minimizing KL divergence between current and previous similarity rankings.
- **Core assumption:** Maintaining relative similarity orderings is sufficient to keep old prototypes relevant even if absolute positions shift.
- **Evidence anchors:** [abstract] "a novel distillation loss that constrains class prototypes to maintain relative similarities as compared to new task data"; [section] "During the new training session, we propose to minimize the KL divergence between the similarities distribution of prototypes to minibatch samples, enforcing current similarities to be similar to previous similarities"
- **Break condition:** If the embedding shift is too large, preserving relative rankings may not prevent prototype obsolescence.

## Foundational Learning

- **Concept:** Supervised contrastive learning (SupCon)
  - Why needed here: Provides strong discriminative representations that resist forgetting, forming the backbone for stable prototypes.
  - Quick check question: In SupCon, what is the difference between positive and negative pairs, and how does this shape the embedding space?

- **Concept:** Knowledge distillation via KL divergence
  - Why needed here: Enables transfer of similarity structure from old to new model without storing raw data.
  - Quick check question: How does minimizing KL divergence between two softmax distributions preserve relative rankings?

- **Concept:** Prototype-based classification
  - Why needed here: Allows classification without storing exemplars, relying only on prototype vectors in embedding space.
  - Quick check question: What is the classification rule when using prototypes, and how does it differ from softmax over logits?

## Architecture Onboarding

- **Component map:** Input → Encoder (f) → Projection Head (g) → Embedding Space → Prototypes (P) → Losses (Lsc, Lp, Ld) → Backward Pass
- **Critical path:** Input → f → g → Lsc + Lp + Ld → backward → update encoder + prototypes
- **Design tradeoffs:** SupCon requires larger batch sizes for good negatives; prototype-only updates avoid gradient interference; relation distillation adds compute but preserves old knowledge.
- **Failure signatures:** High forgetting in linear probe → embedding drift; sudden accuracy drop → prototype drift; stable accuracy but poor plasticity → over-regularization.
- **First 3 experiments:**
  1. Run SupCon only on first task, then fine-tune on second task without constraints; check representation forgetting via linear probe.
  2. Add prototype learning (Lp) on top of SupCon; verify prototypes remain meaningful.
  3. Introduce relation distillation (Ld); measure improvement in old task accuracy while learning new task.

## Limitations

- Method relies heavily on stability of embedding space across tasks - large representation shifts could invalidate maintained prototype-sample relationships
- Effectiveness of preserving only relative similarity rankings lacks theoretical guarantees for extreme embedding shifts
- Assumes supervised contrastive learning alone provides sufficient stability for old prototypes, which may not hold for highly diverse or domain-shifted task sequences

## Confidence

- **High confidence:** Overall experimental methodology and reported performance gains on standard benchmarks (CIFAR100, MiniImageNet, ImageNet32)
- **Medium confidence:** Effectiveness of relation distillation in preserving prototype relevance across tasks
- **Medium confidence:** Claim that PRD matches or exceeds replay-based methods without storing any data
