# Intent Induction from Conversations for Task-Oriented Dialogue Track at DSTC 11

## Quick Facts
- arXiv ID: 2304.12982
- Source URL: https://arxiv.org/abs/2304.12982
- Reference count: 24
- This work introduces a new benchmark for intent induction from human-to-human conversations, proposing two tasks and evaluating clustering metrics to accelerate task-oriented dialogue system development.

## Executive Summary
This paper introduces a new benchmark for intent induction from human-to-human conversations, a critical task for accelerating task-oriented dialogue system development. The benchmark proposes two tasks: Task 1 focuses on clustering intentful turns in conversations, while Task 2 aims to induce a training set of utterances labeled with induced intents for intent classification. Both tasks are evaluated using clustering metrics and intent classifier performance on held-out test sets. Three datasets spanning insurance, banking, and finance domains were collected, featuring realistic, noisy human-to-human dialogues with long-tailed intent distributions. The evaluation framework emphasizes realistic intent induction by measuring the effectiveness of induced intents in training a classifier. A simple baseline using K-means clustering and a pre-trained sentence encoder is provided. The benchmark aims to encourage further research into unsupervised intent induction methods, addressing the gap in realistic, human-to-human conversational datasets.

## Method Summary
The method involves extracting turns labeled with automatic InformIntent predictions from conversation transcripts, computing sentence embeddings using ALL-MPNet-Base-V2, and applying K-means clustering with k selected based on silhouette scores. For Task 2, the clustering is performed on the induced training set for intent classification. The clustering results are evaluated against a reference intent schema using metrics like ACC, F1, NMI, and ARI. The baseline method uses K-means with pre-trained sentence embeddings and silhouette-based k selection.

## Key Results
- ACC is used as the primary metric for ranking systems for both tasks, balancing the trade-off between predicting too few vs. too many intents.
- Leveraging automatic InformIntent predictions for Task 2 approximates a realistic intent extraction pipeline.
- Fine-tuning pre-trained sentence encoders with contrastive objectives improves clustering quality.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Using clustering accuracy (ACC) balances the trade-off between predicting too few vs. too many intents.
- Mechanism: ACC uses the Hungarian algorithm to optimally map predicted clusters to reference intents, then penalizes mismatches. It counts correct assignments over total, so solutions with missing or extra clusters are naturally penalized.
- Core assumption: The reference intent schema is fixed and can serve as a ground truth for comparison.
- Evidence anchors:
  - [abstract]: "ACC is defined as ... Solutions with too few intents, or broad intents that are split between multiple different reference intents, will have lower precision/purity."
  - [section]: "ACC is used as the primary metric for ranking systems for both tasks."
- Break condition: If the reference schema itself is incomplete or misaligned with actual intent distribution, ACC will misjudge clustering quality.

### Mechanism 2
- Claim: Leveraging automatic InformIntent predictions for Task 2 approximates a realistic intent extraction pipeline.
- Mechanism: InformIntent predictions flag turns that likely contain customer intents, so clustering operates only on these candidates rather than requiring manual turn labeling. This mimics a production setting where a dialogue act classifier pre-filters intentful utterances.
- Core assumption: The InformIntent classifier is reasonably accurate at identifying intentful turns without labeling noise.
- Evidence anchors:
  - [abstract]: "However, to simplify system development for the task, automatic dialogue act classifier predictions for InformIntent are provided to participants."
  - [section]: "To account for this, the goal of Task 2 is to instead generate a training set for an intent classifier given a set of unlabeled conversations."
- Break condition: If the InformIntent model mislabels many non-intent turns as intentful, clustering quality degrades and evaluation becomes noisy.

### Mechanism 3
- Claim: Fine-tuning pre-trained sentence encoders with contrastive objectives improves clustering quality.
- Mechanism: Pre-trained models like MPNet or RoBERTa are adapted via contrastive learning (e.g., SimCSE, DSE, or SCCL) to learn discriminative utterance embeddings that map similar intents close together in vector space, improving K-means or HDBSCAN performance.
- Core assumption: The contrastive objective captures semantic similarity relevant to intent clusters better than general sentence embeddings.
- Evidence anchors:
  - [section]: "Teams T00, T15, T23 and T34 used DSE-pretrained encoders ... which learn sentence representations tailored for dialogues using contrastive learning."
  - [section]: "Several submissions used clustering approaches that jointly learn input representations and cluster assignments."
- Break condition: If the contrastive objective diverges from intent semantics (e.g., overfits to superficial lexical cues), embeddings will mislead clustering.

## Architecture Onboarding

- Component map: Data loader -> Conversation transcripts with speaker tags -> InformIntent predictor (Task 2 only) -> Turn filtering -> Encoder fine-tuner -> Contrastive pre-training on utterances -> Clustering engine -> K-means or HDBSCAN -> Cluster selector -> Silhouette score or HDBSCAN auto-k -> Evaluation pipeline -> ACC/F1/NMI/ARI comparison to reference
- Critical path: Data -> Encoder fine-tuning -> Clustering -> Evaluation
- Design tradeoffs:
  - Using K-means (simple, fast) vs. HDBSCAN (handles noise but slower)
  - Silhouette-based k selection vs. HDBSCAN auto-k
  - Fine-tuning on public data vs. relying on base model
- Failure signatures:
  - Very low ACC but high NMI: Possible cluster over-splitting
  - High ACC but low F1: Might be assigning many turns to one cluster
  - Cluster counts far from reference intent count: Poor k selection
- First 3 experiments:
  1. Run baseline K-means on ALL-MPNet embeddings with Silhouette k selection; report ACC.
  2. Apply HDBSCAN on same embeddings; compare ACC, cluster count, and noise rate.
  3. Fine-tune ALL-MPNet with SimCSE on available labeled data; repeat clustering and evaluate improvement.

## Limitations

- The benchmark's reliance on reference intent schemas for evaluation assumes these schemas are complete and accurately represent the true intent distribution.
- The use of automatic InformIntent predictions introduces potential noise, particularly if the classifier has high false-positive rates.
- The evaluation framework assumes that induced intents can be meaningfully mapped to reference intents, which may not hold for novel or domain-specific intents not present in the reference.

## Confidence

- High: Basic task definition and dataset availability
- Medium: Effectiveness of clustering metrics (ACC/F1) for evaluating intent induction
- Medium: Baseline results showing K-means with MPNet embeddings as reasonable starting point
- Low: Generalizability of results across diverse domains and real-world deployment scenarios
