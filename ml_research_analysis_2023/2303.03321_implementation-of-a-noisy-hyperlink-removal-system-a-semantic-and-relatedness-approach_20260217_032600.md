# Implementation of a noisy hyperlink removal system: A semantic and relatedness approach

## Quick Facts
- arXiv ID: 2303.03321
- Source URL: https://arxiv.org/abs/2303.03321
- Reference count: 36
- Key outcome: Proposed semantic and relatedness approach achieves 81.8% accuracy in distinguishing useful vs noisy hyperlinks

## Executive Summary
This paper presents a semantic and relatedness-based approach for removing noisy hyperlinks from web structure graphs. The method constructs a dataset of hyperlinks using an interactive crawler and analyzes their semantic and relatedness structures through the DBpedia ontology. Noisy hyperlinks are identified using a reasoner on the ontology, with experiments demonstrating high accuracy in distinguishing between useful and noisy hyperlinks. The approach achieves an accuracy rate of 81.8% in topic identification and shows scalability in handling large datasets efficiently.

## Method Summary
The study proposes a semantic and relatedness approach for removing noisy hyperlinks from web structure graphs. The method constructs a dataset of hyperlinks using an interactive crawler and analyzes their semantic and relatedness structures through the DBpedia ontology. Noisy hyperlinks are identified using a reasoner on the ontology. The approach involves constructing a dataset of hyperlinks, extracting features using text mining techniques, and applying supervised topic classification methods to identify topics. The DBpedia ontology and a reasoner are then used to analyze semantic and relatedness similarities to detect noisy hyperlinks.

## Key Results
- Achieved 81.8% accuracy in distinguishing between useful and noisy hyperlinks
- Successfully identified topic-relatedness in 81.8% of cases during topic identification experiments
- Demonstrated scalability of the reasoner in handling large datasets efficiently

## Why This Works (Mechanism)
The approach works by leveraging semantic relationships encoded in the DBpedia ontology to understand the context and relatedness of hyperlinks beyond simple string matching. By using a reasoner to analyze these semantic relationships, the system can identify when hyperlinks lack meaningful connections to their target pages, indicating potential noise.

## Architecture Onboarding

**Component Map**: Interactive Crawler -> Text Mining -> Topic Classifier -> DBpedia Ontology -> Reasoner -> Noisy Link Filter

**Critical Path**: Hyperlink collection → feature extraction → topic classification → semantic analysis → noise detection

**Design Tradeoffs**: The system trades computational complexity for higher accuracy by using a reasoner on the ontology rather than simpler string-based methods.

**Failure Signatures**: Poor feature extraction leads to inaccurate topic classification, causing incorrect noise identification; reasoner unable to find semantic properties results in misclassification of valid hyperlinks.
