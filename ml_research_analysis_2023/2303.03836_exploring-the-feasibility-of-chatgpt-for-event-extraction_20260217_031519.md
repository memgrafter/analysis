# Exploring the Feasibility of ChatGPT for Event Extraction

## Quick Facts
- arXiv ID: 2303.03836
- Source URL: https://arxiv.org/abs/2303.03836
- Reference count: 2
- Key outcome: ChatGPT achieves 64.00 F1 on event extraction, significantly lagging task-specific models like EEQA (81.82 F1), especially in long-tail and complex scenarios.

## Executive Summary
This paper investigates ChatGPT's capability for event extraction, a complex NLP task requiring identification of event triggers and types in text. Unlike simpler NLP tasks, event extraction demands detailed instructions about event schemas and definitions. The study compares ChatGPT against task-specific models (EEQA, Text2Event) on the ACE 2005 dataset using F1 score as the primary metric. ChatGPT achieves only 64.00 F1 on random samples versus EEQA's 81.82 F1, and performs at just 51.04% of EEQA's capability in long-tail and complex scenarios. Usability tests reveal that ChatGPT is not robust—performance does not improve consistently with prompt refinement—and is highly sensitive to prompt styles across different users. Results indicate that while ChatGPT can output structured events, its reliability and accuracy lag behind specialized models, highlighting challenges in applying LLMs to complex event extraction tasks.

## Method Summary
The study evaluates ChatGPT's zero-shot event extraction capability by comparing it against task-specific models (EEQA, Text2Event) on the ACE 2005 dataset. ChatGPT is prompted with task descriptions, event type definitions, and demonstration examples to generate structured JSON outputs. Performance is measured using F1 score for event detection, focusing on trigger identification only. The evaluation includes random samples, long-tail scenarios (low-frequency events), and complex scenarios (texts with multiple overlapping events). Usability testing involves different annotators using varying prompt styles to assess robustness and sensitivity to prompt formulation.

## Key Results
- ChatGPT achieves 64.00 F1 on random samples versus EEQA's 81.82 F1
- Performance drops to 51.04% of EEQA's capability in long-tail and complex scenarios
- Prompt sensitivity: F1 scores range from 26.92 to 64.00 across different annotators
- Removing positive examples or event definitions significantly degrades performance (F1 drops from 64.00 to 52.05 or 57.83)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: ChatGPT can perform event extraction when given explicit task instructions, event type definitions, and positive/negative examples in prompt format.
- Mechanism: The model treats the task as multi-turn question answering, mapping unstructured text to structured JSON outputs by leveraging in-context learning from provided examples.
- Core assumption: The LLM has sufficient world knowledge and schema understanding to generalize from examples to new instances.
- Evidence anchors:
  - [abstract] "Unlike other tasks, event extraction requires the model to be provided with a complex set of instructions defining all event types and their schemas."
  - [section] "To utilize ChatGPT for event extraction, the model must be provided with a schema for each event type, including the triggers and arguments to be extracted."
  - [corpus] Weak evidence: Only 1 of 5 neighbor papers explicitly mentions structured output requirements for event extraction with LLMs.
- Break condition: If prompt lacks either event definitions or positive examples, performance degrades significantly (Table 2 shows F1 drops from 64.00 to 52.05 or 57.83).

### Mechanism 2
- Claim: Performance degrades in long-tail and complex scenarios compared to task-specific models.
- Mechanism: ChatGPT's in-context learning struggles with low-frequency event types and texts with multiple overlapping events due to limited exposure in examples.
- Core assumption: The model cannot generalize well beyond the distribution of examples provided in the prompt.
- Evidence anchors:
  - [abstract] "Our results show that ChatGPT has, on average, only 51.04% of the performance of a task-specific model such as EEQA in long-tail and complex scenarios."
  - [section] "ChatGPT's performance on both simple and complex samples is significantly worse than that of EEQA and Text2Event."
  - [corpus] Weak evidence: No neighbor papers provide quantitative comparison for long-tail scenarios with LLMs.
- Break condition: When test samples contain events with frequency <10 in training corpus or more than 2 events per text.

### Mechanism 3
- Claim: ChatGPT is not robust to prompt style variations and does not improve consistently with prompt refinement.
- Mechanism: Different users applying different prompt formulations yield widely varying performance, and iterative refinement does not guarantee improvement.
- Core assumption: The model's output is highly sensitive to phrasing and ordering of prompt elements.
- Evidence anchors:
  - [abstract] "Our usability testing experiments indicate that ChatGPT is not robust enough, and continuous refinement of the prompt does not lead to stable performance improvements."
  - [section] "Different annotators utilized different prompt styles, resulting in significant performance variations for ChatGPT... the lowest is only 26.92."
  - [corpus] Moderate evidence: 2 neighbor papers on LLM usability testing report sensitivity to prompt formulation.
- Break condition: When different annotators use semantically equivalent but syntactically different prompts.

## Architecture Onboarding

- Component map:
  Prompt generator (task description + event schema + examples) -> ChatGPT API endpoint (model inference) -> Output parser (JSON extraction) -> Evaluation pipeline (precision/recall/F1 computation)

- Critical path:
  Prompt → ChatGPT → Structured JSON → Evaluation → Performance metrics

- Design tradeoffs:
  - Using longer prompts with more examples may improve accuracy but risks hitting context window limits.
  - Providing event definitions helps but increases prompt complexity and user burden.
  - Removing negative examples can improve performance but reduces instructional clarity.

- Failure signatures:
  - Output is not JSON-structured (fails parse)
  - Event triggers misidentified due to schema ambiguity
  - Performance varies widely across users
  - No improvement after multiple prompt refinements

- First 3 experiments:
  1. Run full prompt vs prompt without event definitions on 20 random samples to measure impact on F1.
  2. Test long-tail scenario by sampling low-frequency events (<10 occurrences) and measuring relative performance vs EEQA.
  3. Conduct usability test with 3 annotators using different prompt styles on same 10 samples to quantify performance variance.

## Limitations
- Zero-shot prompting inherently disadvantages ChatGPT compared to fine-tuned task-specific models
- Performance highly sensitive to prompt engineering skill rather than model capability
- Only evaluates trigger detection, omitting more complex argument extraction component
- Model requires extensive scaffolding to produce structured output, raising questions about true understanding

## Confidence

**High Confidence**: The finding that ChatGPT's performance (64.00 F1) lags significantly behind EEQA (81.82 F1) on random samples is robust, given the controlled comparison and consistent methodology. The sensitivity to prompt style variations is also well-supported by the data showing performance ranging from 26.92 to 64.00 across annotators.

**Medium Confidence**: The claim about long-tail scenario performance (51.04% of EEQA's performance) is less certain due to limited testing on truly rare events and unclear definitions of "complex scenarios." The mechanism by which prompt refinement fails to improve performance consistently is plausible but not definitively proven.

**Low Confidence**: The assertion that ChatGPT can "output structured events" is somewhat misleading, as the model requires extensive scaffolding (definitions, examples, specific formatting instructions) to produce even semi-structured JSON output, which represents a narrow interpretation of structured event extraction.

## Next Checks
1. **Prompt Ablation Study**: Systematically remove each component (event definitions, positive examples, negative examples) from the prompt and measure performance impact on a fixed set of 50 samples to isolate which elements are truly essential versus beneficial.

2. **Few-Shot vs Zero-Shot Comparison**: Test ChatGPT with 5 demonstration examples (few-shot) versus no examples (zero-shot) on the same samples to quantify the marginal benefit of in-context learning and determine if performance approaches that of fine-tuned models.

3. **Full Event Extraction Evaluation**: Extend the evaluation to include argument extraction (identifying event participants and their roles) using the same prompt format, measuring whether the performance degradation observed in trigger detection is amplified when argument extraction is required.
