# A Scalable Space-efficient In-database Interpretability Framework for Embedding-based Semantic SQL Queries

## Quick Facts
- arXiv ID: 2302.12178
- Source URL: https://arxiv.org/abs/2302.12178
- Reference count: 40
- Primary result: Probabilistic Count-Min sketch provides same interpretability quality as exact approach with 8X space savings and scalable runtime

## Executive Summary
This paper presents a scalable interpretability framework for AI-DB systems that process semantic SQL queries using database embedding models like db2Vec. The framework provides both global (query-agnostic) and local (query-specific) interpretability through Influence and Discriminator scores. A key innovation is the use of probabilistic Count-Min sketches for space-efficient co-occurrence counting between relational entities, achieving significant storage savings while maintaining interpretability quality. The approach enables understanding of self-supervised embedding models without requiring user intervention.

## Method Summary
The framework leverages a self-supervised database embedding model (db2Vec) to generate vector representations of database entities. It introduces a probabilistic approach using Count-Min sketches to store co-occurrence counts between entities, which are then used to compute Influence and Discriminator scores. Influence scores measure how much each entity contributes to the overall embedding space structure, while Discriminator scores identify which entities help distinguish between different semantic concepts. The framework operates without user intervention, automatically providing interpretability insights for both individual queries and the overall model behavior.

## Key Results
- Probabilistic Count-Min sketch approach achieves 8X space savings compared to exact co-occurrence counting
- Interpretability quality remains equivalent between probabilistic and exact approaches
- Runtime performance scales efficiently with increasing database size and query complexity
- Framework provides both global and local interpretability without user intervention
- Influence and Discriminator scores effectively capture model behavior and input data characteristics

## Why This Works (Mechanism)
The framework works by leveraging the self-supervised nature of db2Vec embeddings, which capture semantic relationships between database entities. The Count-Min sketch efficiently approximates co-occurrence statistics needed to understand these relationships while using minimal space. The Influence scores identify entities that shape the embedding space structure, while Discriminator scores highlight entities that create meaningful separations between different semantic concepts. This dual-score approach provides comprehensive interpretability by examining both the constructive and discriminative aspects of the embedding model.

## Foundational Learning
- **Count-Min Sketch**: Probabilistic data structure for approximate frequency counting - needed for space efficiency with large-scale co-occurrence tracking; quick check: verify error bounds scale appropriately with sketch parameters
- **Self-supervised Embeddings**: Vector representations learned without explicit labels - needed to capture semantic relationships in database entities; quick check: confirm embeddings preserve relational semantics
- **Influence Scoring**: Measurement of entity impact on model behavior - needed to identify key contributors to embedding structure; quick check: validate scores correlate with perturbation sensitivity
- **Discriminator Scoring**: Identification of distinguishing features between concepts - needed to understand what makes entities semantically unique; quick check: test if scores align with human-defined entity differences

## Architecture Onboarding

**Component Map**: SQL Query -> db2Vec Embeddings -> Co-occurrence Counting -> Count-Min Sketch -> Influence/Discriminator Scores -> Interpretability Insights

**Critical Path**: The critical execution path flows from SQL query processing through embedding generation, co-occurrence counting via Count-Min sketch, and finally score computation. The probabilistic counting step is the performance bottleneck, but scales efficiently due to the sketch's constant-time operations.

**Design Tradeoffs**: The framework trades exact co-occurrence precision for significant space savings (8X). While this introduces bounded probabilistic error, experiments show this doesn't impact interpretability quality. The choice of Count-Min over alternatives like HyperLogLog was driven by its ability to support both insert and query operations needed for score computation.

**Failure Signatures**: Performance degradation typically manifests as increased runtime with sketch size rather than accuracy loss. Accuracy issues would appear as degraded interpretability quality metrics or scores that don't correlate with entity importance. Memory pressure would be minimal due to the sketch's space efficiency.

**First 3 Experiments**: 1) Benchmark space usage of Count-Min sketch vs exact counting across varying database sizes, 2) Measure interpretability quality degradation as sketch error rate increases, 3) Profile runtime performance scaling with concurrent query load.

## Limitations
- Evaluation lacks ablation studies examining individual contributions of Influence and Discriminator scores
- Generalizability to complex or non-relational database schemas remains untested
- Depth and practical utility of generated insights for real-world database administrators underexplored

## Confidence
- **High confidence**: Space-efficiency claims and runtime scalability (8X savings, stable performance)
- **Medium confidence**: Interpretability quality equivalence (single metric, limited evaluation methods)
- **Medium confidence**: User-intervention-free insights (practical utility not fully explored)
