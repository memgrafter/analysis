# Learning Prototype Classifiers for Long-Tailed Recognition

## Quick Facts
- arXiv ID: 2302.00491
- Source URL: https://arxiv.org/abs/2302.00491
- Reference count: 6
- Primary result: Prototype classifier outperforms or matches state-of-the-art on long-tailed recognition benchmarks

## Executive Summary
This paper introduces prototype classifiers as an alternative to softmax classifiers for long-tailed recognition. The key insight is that softmax classifiers exhibit a bias where classifier norms correlate with class size, while prototype classifiers based on Euclidean distances to learnable prototypes avoid this issue. The method employs a two-stage training procedure: first pre-training representations with instance-balanced sampling and weight regularization, then learning prototypes with class-balanced sampling and logit adjustment. Channel-dependent temperature parameters are also introduced to enable independent distance scales across feature dimensions. Experiments on CIFAR100-LT, ImageNet-LT, and iNaturalist18 demonstrate superior or comparable performance to state-of-the-art methods.

## Method Summary
The proposed method uses prototype classifiers that compute class probabilities based on Euclidean distances to learnable prototypes in the representation space. The training involves two stages: first, a feature extractor is pre-trained on imbalanced data using instance-balanced sampling with high weight decay; second, prototypes are initialized as empirical centroids and learned using class-balanced sampling with logit adjustment. Channel-dependent temperature parameters are learned to enable independent distance scales across feature dimensions. The cross-entropy loss with logit adjustment is used for optimization, with specific learning rates for prototype and temperature parameter updates.

## Key Results
- Prototype classifier outperforms or matches state-of-the-art methods on CIFAR100-LT, ImageNet-LT, and iNaturalist18
- Avoids the classifier norm bias present in softmax classifiers that correlates with class size
- Channel-dependent temperatures provide 0.5% improvement in overall accuracy and 4% in few-shot accuracy
- Stable gradient-based optimization properties are robust to outliers

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Prototype classifiers avoid the bias in softmax classifiers that correlates classifier norm with class size
- Mechanism: Prototype classifiers use Euclidean distances to learnable prototypes instead of dot-product with learnable weights, naturally avoiding the correlation between prototype norm and class size
- Core assumption: The representations g(x) are fixed and pre-trained, allowing prototypes to be learned independently of class size
- Evidence anchors: [abstract] "Most recent works in LTR use softmax classifiers that are biased in that they correlate classifier norm with the amount of training data for a given class. On the other hand, Prototype classifiers do not suffer from this shortcoming..."; [section 3.1] "The Prototype classifier does not suffer from the bias learned by softmax classifiers, making it an ideal choice for long-tailed recognition."
- Break condition: If representations are not fixed or pre-trained, the prototypes may still correlate with class size

### Mechanism 2
- Claim: Learning prototypes using Euclidean distance leads to stable gradient-based optimization that is robust to outliers
- Mechanism: The L2 norm of the gradient on a prototype from a point x is always equal in magnitude to the misclassification probability, and the gradient is oriented along the line joining the prototype to x
- Core assumption: The class-conditional distribution p(g(x)|y) is a Gaussian with unit variance centered around the prototype
- Evidence anchors: [section 3.2] "Theorem 1. Let Lxy denote the NLL loss on a single sample x with label y. Then, the L2 norm of the gradient on prototype cz is given by..."; [section 3.2] "In both cases, the L2 norm of the gradient is equal to 1, leading to stable gradient updates. Importantly, it is invariant to d(g(x),cz), thus both inliers and outliers contribute equally."
- Break condition: If the class-conditional distribution is not Gaussian or the variance is not unit, the gradient updates may not be stable

### Mechanism 3
- Claim: Learning channel-dependent temperature parameters enables independent distance scales along each channel, leading to better performance
- Mechanism: Channel-dependent temperatures allow the model to learn feature scaling in the distance function, and by letting the temperature approach very high values, the model can also filter out potentially harmful features
- Core assumption: All dimensions in the representation space may not have the same distance scale
- Evidence anchors: [section 3.4] "While computing distances for prototype classifiers, it is worthwhile to consider that all dimensions in the representation space may not have the same distance scale..."; [section 3.4] "By letting the temperature approach very high values the model can also filter out potentially harmful features, i.e, feature selection."; [section 4.4] "Adding channel dependent temperatures (CDT) to PC further improves the results by 0.5% on All accuracy and 4% on Few accuracy."
- Break condition: If the temperature parameters are not learnable or the distance scales are not independent, the performance gain may not be realized

## Architecture Onboarding

- Component map: Pre-trained feature extractor (g_θ) -> Learnable prototypes (c_y) -> Channel-dependent temperature parameters (T_i) -> Logit adjustment weight (τ) -> Cross-entropy loss with logit adjustment

- Critical path:
  1. Pre-train the feature extractor on the long-tailed dataset using instance-balanced sampling and weight regularization
  2. Initialize the prototypes as empirical centroids computed from the pre-trained representations
  3. Learn the prototypes using Euclidean distance-based cross-entropy loss with logit adjustment
  4. Learn the channel-dependent temperature parameters to enable independent distance scales
  5. Evaluate the performance on the balanced test set

- Design tradeoffs:
  - Using Euclidean distance vs. squared Euclidean distance or cosine distance for prototype learning
  - Learning prototypes vs. using fixed empirical centroids (NCM)
  - Learning channel-dependent temperatures vs. using fixed temperatures or no temperature scaling
  - Applying logit adjustment vs. using the standard cross-entropy loss

- Failure signatures:
  - High correlation between prototype norm and class size, indicating that the prototypes are not well-separated
  - Unstable gradient updates during prototype learning, leading to poor convergence
  - Poor performance on tail classes, indicating that the model is biased towards head classes
  - Overfitting to the training data, leading to poor generalization on the test set

- First 3 experiments:
  1. Compare the performance of the prototype classifier with NCM and softmax classifiers on a long-tailed dataset
  2. Analyze the effect of different distance metrics (Euclidean, squared Euclidean, cosine) on prototype learning and performance
  3. Investigate the impact of learning channel-dependent temperature parameters on the model's ability to handle imbalanced data

## Limitations

- Theoretical gaps in assuming Gaussian class-conditional distributions with unit variance may not hold in practice
- Method relies on several critical hyperparameters that require careful tuning
- Performance is tightly coupled with the quality of the representation learning stage
- Limited evaluation on real-world datasets with complex distributions and noise

## Confidence

- High Confidence: The core observation that softmax classifiers correlate prototype norms with class size is well-established and empirically demonstrated
- Medium Confidence: Claims about stable gradient updates and benefits of channel-dependent temperatures are supported by theory and experiments but could benefit from more extensive validation
- Low Confidence: Assertion that prototype classifier "naturally" avoids bias without careful consideration of representation quality may be overstated

## Next Checks
