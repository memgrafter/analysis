# Understand the Dynamic World: An End-to-End Knowledge Informed Framework for Open Domain Entity State Tracking

## Quick Facts
- arXiv ID: 2304.13854
- Source URL: https://arxiv.org/abs/2304.13854
- Authors: 
- Reference count: 40
- Key outcome: KIEST framework significantly outperforms T5, GPT-2, GPT-3.5, and GPT-4 on OpenPI dataset with Exact Match, BLEU-2, and ROUGE-L metrics

## Executive Summary
This paper introduces KIEST, a knowledge-informed framework for open domain entity state tracking that predicts entity state changes from action descriptions. The key innovation is retrieving relevant entities and attributes from ConceptNet and dynamically incorporating them into an encoder-decoder model through position-aware cross-attention mechanisms. KIEST employs constrained decoding and a coherence reward to improve output quality. Experimental results on the OpenPI dataset demonstrate significant improvements over strong baselines including T5, GPT-2, GPT-3.5, and GPT-4 across multiple evaluation metrics.

## Method Summary
KIEST processes procedural paragraphs containing action descriptions to predict entity state changes. The framework retrieves entities and attributes from ConceptNet using entity relatedness within 2 hops, then filters them through selection models trained with triplet loss. The Dynamic Knowledge Grained Encoder-Decoder (DKGED) incorporates this knowledge via position-aware cross-attention during generation. Constrained decoding limits candidate tokens to contextually relevant ones, while a coherence classifier provides rewards during training to encourage valid outputs. The model is trained with combined cross-entropy and reinforcement learning loss on the OpenPI dataset.

## Key Results
- KIEST achieves state-of-the-art performance on OpenPI dataset with significant improvements in Exact Match, BLEU-2, and ROUGE-L metrics
- Outperforms strong baselines including T5, GPT-2, GPT-3.5, and GPT-4 in entity state tracking accuracy
- Coherence classifier achieves 98% accuracy in distinguishing valid vs invalid state changes
- Constrained decoding with threshold γ=0.4 effectively reduces generation of irrelevant entities and attributes

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Knowledge graph retrieval provides relevant entities/attributes that language models alone miss.
- Mechanism: ConceptNet is queried with action anchors to retrieve contextually relevant entities/attributes, which are then filtered by selection models trained on positive/negative examples from OpenPI.
- Core assumption: Relevant entity/attribute knowledge is encoded in ConceptNet and can be retrieved via entity relatedness.
- Evidence anchors: [abstract] "explicitly retrieves the relevant entities and attributes from external knowledge graph (i.e., ConceptNet)", [section 3.1] "we propose to acquire a rich set of entities and attributes that are relevant to state changes from ConceptNet [26]"
- Break condition: If ConceptNet lacks relevant concepts for a given action or selection models fail to distinguish relevant vs irrelevant entities.

### Mechanism 2
- Claim: Dynamic knowledge integration at decoding time improves attribute/entity prediction accuracy.
- Mechanism: During generation, the decoder attends to entity knowledge when predicting entities, attribute knowledge when predicting attributes, and action context otherwise, using position-aware cross-attention.
- Core assumption: Attribute/entity prediction benefits from explicit external knowledge rather than relying solely on language model context.
- Evidence anchors: [abstract] "incorporates them to autoregressively generate all the entity state changes with a novel dynamic knowledge grained encoder-decoder framework", [section 3.2] "we design three Cross Attention mechanisms while each Cross Attention is the same as Multi-Head Attention defined in Transformer"
- Break condition: If cross-attention integration introduces noise or if language model already captures needed knowledge internally.

### Mechanism 3
- Claim: Coherence reward and constrained decoding improve output validity.
- Mechanism: A classifier is trained to distinguish coherent vs incoherent state changes, and this is used as a reward in policy learning; constrained decoding limits vocabulary to contextually relevant tokens.
- Core assumption: Model-generated outputs often violate commonsense coherence and can be improved with explicit coherence checking.
- Evidence anchors: [abstract] "we design a new constraint decoding strategy and an Entity State Change Coherence Reward (ESCCR) to improve the decoding process", [section 3.3] "we further design a constrained decoding strategy to select a subset of candidate tokens that are more related to the input action description"
- Break condition: If classifier reward is noisy or constrained decoding overly restricts valid outputs.

## Foundational Learning

- Concept: Knowledge graph retrieval and filtering
  - Why needed here: Open domain entity state tracking requires identifying relevant entities/attributes that are not explicitly mentioned in action descriptions.
  - Quick check question: How would you retrieve entities related to "cut" from ConceptNet, and how would you filter irrelevant ones?

- Concept: Dynamic attention mechanisms in sequence generation
  - Why needed here: Standard encoder-decoder models use static attention; this work needs to switch attention sources based on what part of the template is being generated.
  - Quick check question: What is the difference between using fixed cross-attention vs. position-aware cross-attention in this context?

- Concept: Reward shaping in reinforcement learning for text generation
  - Why needed here: Cross-entropy loss alone doesn't capture coherence of multi-part outputs; reward shaping encourages globally coherent entity state changes.
  - Quick check question: How does adding a coherence reward change the optimization objective compared to pure cross-entropy?

## Architecture Onboarding

- Component map: Input → Entity/Attribute Retrieval → Selection Models → Dynamic Knowledge Grained Encoder-Decoder → Constrained Decoding → Coherence Reward → Output
- Critical path: Action description → Entity/attribute selection → Dynamic knowledge integration during decoding → Coherence reward optimization
- Design tradeoffs: Using ConceptNet adds coverage but introduces noise; selection models reduce noise but require training data; coherence reward improves validity but adds complexity to training.
- Failure signatures: Low precision indicates noisy entity/attribute selection; low recall indicates overly restrictive constrained decoding or selection thresholds; coherence reward may cause mode collapse if too strong.
- First 3 experiments:
  1. Compare entity state tracking performance with and without ConceptNet retrieval.
  2. Test different thresholds for entity/attribute selection to balance precision and recall.
  3. Evaluate impact of coherence reward strength on output validity vs. diversity.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can we further improve the coherence of generated entity state changes beyond the current classifier-based reward?
- Basis in paper: [explicit] The paper mentions that the coherence of generated entity state changes is still not perfect and discusses the effectiveness of the classifier-based coherence reward.
- Why unresolved: While the coherence reward improves coherence, the paper acknowledges that the generated entity state changes still have limited coherence compared to human-generated ones.
- What evidence would resolve it: Experiments comparing the coherence of entity state changes generated by KIEST with and without additional coherence improvement techniques (e.g., beam search with coherence constraints, fine-tuning on coherence-annotated data).

### Open Question 2
- Question: Can we extend the open domain entity state tracking task to handle multimodal inputs (e.g., text and images)?
- Basis in paper: [inferred] The paper discusses the limitations of handling only textual descriptions of actions and mentions the potential of leveraging multimodal pre-trained language models.
- Why unresolved: The current framework only processes textual action descriptions, ignoring potential information from images or videos that could provide valuable context for predicting entity state changes.
- What evidence would resolve it: Experiments comparing the performance of KIEST on multimodal inputs (text + images) against its performance on text-only inputs.

### Open Question 3
- Question: How can we design more effective prompts to stimulate large language models like GPT-3.5 or GPT-4 to generate coherent entity state changes?
- Basis in paper: [explicit] The paper discusses the limitations of using GPT-3.5 and GPT-4 for open domain entity state tracking and suggests that better prompts could improve their performance.
- Why unresolved: The paper only experiments with a limited set of prompts and acknowledges that large language models still have limited capability to perform complex reasoning tasks without fine-tuning.
- What evidence would resolve it: Experiments comparing the performance of GPT-3.5 or GPT-4 on open domain entity state tracking using different prompt engineering techniques (e.g., few-shot learning, chain-of-thought prompting).

## Limitations

- Knowledge graph coverage dependency: Framework effectiveness depends on ConceptNet containing relevant entities/attributes for OpenPI actions, with no analysis of coverage completeness
- Architectural integration complexity: Multiple sophisticated components create potential interaction effects without ablation studies showing individual contributions
- Human evaluation coverage: Limited human evaluation beyond specific examples raises questions about generalizability of coherence improvements

## Confidence

- Knowledge Graph Retrieval Effectiveness: Medium confidence - shows quantitative improvements but lacks ablation studies isolating ConceptNet's impact
- Dynamic Knowledge Integration Mechanism: Medium confidence - theoretically sound but no comparison with static knowledge integration baselines
- Coherence Reward Impact: Low-Medium confidence - classifier accuracy is high but may reflect pattern matching rather than genuine commonsense reasoning

## Next Checks

1. **Knowledge Coverage Analysis**: Analyze what fraction of entity/attribute concepts needed for OpenPI actions are actually present in ConceptNet to validate whether framework performance is limited by knowledge graph coverage versus model architecture.

2. **Component Ablation Study**: Systematically remove each major component (ConceptNet retrieval, cross-attention mechanisms, coherence reward) to quantify their individual contributions to overall performance gains and distinguish architectural innovations from implementation details.

3. **Generalization Testing**: Evaluate the trained model on a held-out subset of OpenPI with actions from domains not seen during training, or on a different procedural dataset entirely, to test whether the framework has learned genuine commonsense reasoning versus memorizing OpenPI's specific patterns.
