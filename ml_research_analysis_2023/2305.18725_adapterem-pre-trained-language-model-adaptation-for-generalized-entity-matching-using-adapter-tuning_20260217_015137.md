# AdapterEM: Pre-trained Language Model Adaptation for Generalized Entity Matching using Adapter-tuning

## Quick Facts
- **arXiv ID**: 2305.18725
- **Source URL**: https://arxiv.org/abs/2305.18725
- **Reference count**: 33
- **Key outcome**: AdapterEM achieves comparable or superior performance to full fine-tuning and prompt-tuning baselines while using only ~13% of PrLM parameters on the Machamp benchmark.

## Executive Summary
This paper proposes AdapterEM, a parameter-efficient approach for generalized entity matching (GEM) using adapter-tuning on pre-trained language models. GEM involves identifying matching entities across heterogeneous data sources with varying formats. Traditional fine-tuning of overparameterized language models can cause catastrophic forgetting, especially in low-resource scenarios. AdapterEM addresses this by freezing the original model parameters and fine-tuning only small adapter modules inserted between transformer layers. Experiments show that AdapterEM achieves comparable or superior performance to full-scale fine-tuning and prompt-tuning baselines while using significantly fewer parameters, reducing memory usage and training times while maintaining high accuracy.

## Method Summary
AdapterEM freezes pre-trained language model (PrLM) parameters and updates only small adapter modules inserted between transformer layers. The adapters use a bottleneck architecture with down-projection, non-linearity, and up-projection. Three configurations are explored: task-only adapters, adapters combined with pre-trained adapters (e.g., from SNLI), and adapters combined with invertible language adapters trained via masked language modeling on target domain data. The approach uses Houlsby adapter architecture and is evaluated on the Machamp benchmark for generalized entity matching tasks.

## Key Results
- AdapterEM achieves comparable or superior performance to full fine-tuning and prompt-tuning baselines
- Uses only ~13% of PrLM parameters while maintaining high accuracy
- Significantly reduces memory usage and training times
- Alleviates catastrophic forgetting in both low-resource and sufficient-resource settings

## Why This Works (Mechanism)

### Mechanism 1
- Claim: AdapterEM mitigates catastrophic forgetting by freezing PrLM parameters and only updating small adapter modules.
- Mechanism: Adapters are bottleneck layers inserted between transformer layers. During fine-tuning, only adapter parameters and classifier weights are updated while original PrLM weights remain frozen.
- Core assumption: The frozen PrLM retains sufficient semantic knowledge while adapters learn task-specific representations without interference.
- Evidence anchors:
  - [abstract] "by optimizing only the adapter and classifier weights while the PrLMs parameters are frozen"
  - [section 3.1] "During fine-tuning, we update 𝜙 while keeping Φ fixed"
  - [corpus] Weak - corpus contains related adapter-tuning papers but none specifically address catastrophic forgetting in EM context
- Break condition: If adapter bottleneck size is too large relative to PrLM capacity, or if task requires significant modification of base representations, catastrophic forgetting may still occur despite parameter freezing.

### Mechanism 2
- Claim: Composability of adapters enables transfer learning by stacking language-specific and task-specific adapters.
- Mechanism: Multiple adapters can be stacked vertically within each transformer block. Pre-trained adapters (from tasks like SNLI) or MLM-trained invertible adapters can be combined with randomly initialized task adapters, allowing knowledge transfer from related domains.
- Core assumption: Knowledge captured by pre-trained or MLM-trained adapters is complementary to task-specific learning and improves generalization.
- Evidence anchors:
  - [section 3.2] "we devise three strategies; (i) using a task adapter in each Transformer block, (ii) fusing a pre-trained adapter with a task adapter"
  - [section 4.3] describes MLM training of invertible adapters on target domain data
  - [corpus] Strong - multiple papers (TransFR, One Adapter for All Programming Languages) demonstrate adapter composability benefits
- Break condition: If pre-trained adapters are from unrelated domains, their combination with task adapters may introduce noise rather than beneficial knowledge transfer.

### Mechanism 3
- Claim: Parameter efficiency (using ~13% of PrLM parameters) enables practical deployment through reduced memory usage and training time.
- Mechanism: Adapters contain bottleneck layers that reduce parameter count significantly compared to full fine-tuning. This allows training on limited GPU memory and faster iteration.
- Core assumption: Small parameter count does not significantly compromise model capacity for the task at hand.
- Evidence anchors:
  - [abstract] "achieving comparable or superior performance to full-scale PrLM fine-tuning and prompt-tuning baselines while utilizing a significantly smaller computational footprint ≈ 13% of the PrLM parameters"
  - [section 2.1] "Adapters are stitched into a PrLM as task-specific or language-specific"
  - [corpus] Moderate - TransFR and Efficient Adapter Tuning papers support computational efficiency claims for adapters
- Break condition: If the task complexity exceeds what can be captured by the reduced parameter budget, performance degradation may occur despite efficiency gains.

- Concept: Catastrophic forgetting in neural networks
  - Why needed here: Understanding why freezing PrLM parameters prevents loss of pre-trained knowledge during task adaptation
  - Quick check question: What happens to a neural network's ability to perform previous tasks when it is fine-tuned on new data without any mechanism to preserve old knowledge?

  - Why needed here: The bottleneck design with down-projection, non-linearity, and up-projection is fundamental to understanding how adapters work
  - Quick check question: How does the dimension reduction in adapter bottleneck layers enable parameter efficiency while maintaining representational capacity?

- Concept: Masked Language Modeling (MLM) objective
  - Why needed here: MLM training of invertible adapters is a key technique for capturing token-level language representations in domain-specific contexts
  - Quick check question: Why is corrupting a larger proportion of tokens (higher masking probability) beneficial when training invertible adapters via MLM?

## Architecture Onboarding

- Component map:
  - Input data serialization -> [CLS] token embedding through frozen PrLM -> Adapter module processing (task adapter + optional language adapters) -> Classification head prediction -> Cross-entropy loss computation -> Backpropagation through adapter parameters only

- Critical path:
  1. Input data serialization to token sequences
  2. [CLS] token embedding through frozen PrLM
  3. Adapter module processing (task adapter + optional language adapters)
  4. Classification head prediction
  5. Cross-entropy loss computation
  6. Backpropagation through adapter parameters only

- Design tradeoffs:
  - Parameter efficiency vs. representational capacity: Bottleneck size must balance memory savings with task performance
  - Adapter composition strategy: Pre-trained vs. MLM-trained adapters have different knowledge transfer properties
  - Training stability: Frozen PrLM provides stability but may limit task-specific adaptation

- Failure signatures:
  - Underfitting: Low performance on both training and validation suggests adapter capacity is insufficient
  - Overfitting: High training performance but low validation performance suggests need for regularization or more training data
  - Memory issues: Unexpected OOM errors may indicate incorrect adapter configuration or batch size issues

- First 3 experiments:
  1. Baseline test: Implement AdapterEM with only task adapters on a single Machamp dataset (e.g., R-HET) and compare with full fine-tuning
  2. Adapter composition test: Add pre-trained SNLI adapter to the task adapter and measure performance improvement
  3. MLM pre-training test: Train invertible adapter on target dataset via MLM and stack with task adapter to evaluate domain adaptation benefits

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do invertible language adapters perform compared to pre-trained adapters when applied to different domains beyond E-commerce and geospatial data?
- Basis in paper: [explicit] The paper explores using pre-trained adapters and invertible adapters for capturing token-level language representations and demonstrates their benefits for transfer learning on the generalized EM benchmark.
- Why unresolved: The experiments were conducted on specific datasets (Machamp benchmark and a geospatial database), but the paper does not discuss how these adapter configurations would generalize to other domains or data types.
- What evidence would resolve it: Conducting experiments with AdapterEM on datasets from diverse domains (e.g., medical records, scientific literature, social media) and comparing the performance of invertible adapters versus pre-trained adapters across these domains.

### Open Question 2
- Question: What is the optimal masking probability for invertible adapter training in MLM, and how does it affect performance across different resource settings?
- Basis in paper: [explicit] The paper mentions that invertible adapters are trained via MLM with a slightly higher masking probability (inspired by [27]) and asks about the impact of masking probability on performance.
- Why unresolved: While the paper uses a specific masking probability, it does not systematically explore different masking probabilities or their effects on low-resource versus sufficient-resource settings.
- What evidence would resolve it: Conducting a comprehensive study varying the masking probability during invertible adapter training and measuring performance across different resource settings and dataset types.

### Open Question 3
- Question: How does the performance of AdapterEM compare to other parameter-efficient methods like prefix-tuning when applied to GEM tasks?
- Basis in paper: [inferred] The paper mentions prefix-tuning as another parameter-efficient method but notes that prior works have not investigated it for GEM, and AdapterEM outperforms full-scale fine-tuning and prompt-tuning baselines.
- Why unresolved: The paper does not directly compare AdapterEM to prefix-tuning on GEM benchmarks, leaving an open question about relative performance.
- What evidence would resolve it: Implementing prefix-tuning for GEM tasks and conducting head-to-head comparisons with AdapterEM on the Machamp benchmark and other relevant datasets.

## Limitations
- Lack of ablation studies comparing different adapter configurations across all datasets
- Limited quantitative evidence for catastrophic forgetting mitigation in sufficient-resource settings
- Unclear generalizability to datasets beyond the Machamp benchmark

## Confidence
- **High confidence**: Parameter efficiency claims (13% of PrLM parameters) and catastrophic forgetting mitigation are well-supported
- **Medium confidence**: Performance comparisons with baselines are credible but would benefit from more extensive hyperparameter tuning
- **Low confidence**: Specific benefits of invertible adapters trained via MLM are not clearly demonstrated relative to other adapter composition strategies

## Next Checks
1. **Ablation study on adapter composition**: Systematically test each adapter configuration (task-only, task + pre-trained, task + invertible) across all Machamp datasets to identify which approach works best for structured vs. unstructured data types.

2. **Memory and runtime profiling**: Conduct detailed profiling of AdapterEM vs. full fine-tuning across different GPU configurations, batch sizes, and sequence lengths to verify the claimed 13% parameter efficiency translates to practical training speedups.

3. **Cross-dataset generalization test**: Evaluate AdapterEM on entity matching datasets outside the Machamp benchmark (e.g., Magellan datasets) to assess whether the approach generalizes beyond the specific data distributions used in the paper.
