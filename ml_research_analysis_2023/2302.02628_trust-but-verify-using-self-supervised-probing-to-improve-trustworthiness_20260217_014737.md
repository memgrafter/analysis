# Trust, but Verify: Using Self-Supervised Probing to Improve Trustworthiness

## Quick Facts
- arXiv ID: 2302.02628
- Source URL: https://arxiv.org/abs/2302.02628
- Reference count: 36
- Primary result: Self-supervised probing confidence correlates with classification accuracy and improves trustworthiness methods across multiple tasks

## Executive Summary
This paper introduces a self-supervised probing framework that enhances the trustworthiness of neural network predictions by extracting probing confidence from auxiliary probing tasks like rotation and translation prediction. The probing confidence serves as an auxiliary indicator that correlates with classification accuracy and can be combined with existing trustworthiness methods (MSP, entropy, temperature scaling) to improve performance across misclassification detection, out-of-distribution detection, and calibration. Experiments on CIFAR-10, CINIC-10, and STL-10 demonstrate consistent gains in metrics such as FPR@95%, AUPR-ERR, AUROC, and calibration scores. The approach is plug-and-play, requires no retraining, and works effectively with multiple probing tasks.

## Method Summary
The method involves training separate probing classifiers on top of a fixed backbone for self-supervised tasks (rotation and translation prediction). These probing classifiers predict which transformation was applied to input images. The probing confidence (softmax probability for the identity transformation) is then combined with existing trustworthiness scores through additive combination or input-dependent temperature scaling. The framework is applied to three trustworthiness tasks: misclassification detection, out-of-distribution detection, and calibration, showing improvements across all tasks without requiring model retraining.

## Key Results
- Probing confidence shows clear positive correlation with classification accuracy on CIFAR-10 and CINIC-10 across rotation and translation tasks
- Combining probing confidence with MSP, entropy, and temperature scaling improves FPR@95%, AUPR-ERR, AUROC, and calibration metrics
- The method works as a plug-and-play addition to existing trustworthiness methods without requiring model retraining
- Performance gains are consistent across multiple datasets (CIFAR-10, CINIC-10) but show degradation on smaller datasets like STL-10

## Why This Works (Mechanism)

### Mechanism 1
Probing confidence correlates with classification accuracy at the instance level. Self-supervised probing tasks like rotation and translation are semantically related to classification, and the probing classifier uses the fixed backbone to predict applied transformations. Higher probing confidence (identifying identity transformation) indicates stronger semantic understanding, which correlates with correct classification.

### Mechanism 2
Combining probing confidence with existing trustworthiness scores provides complementary information. The self-supervised probing score (SSSP) adds weighted probing confidence to existing confidence scores (MSP, entropy, etc.), creating a better discriminator between trustworthy and untrustworthy predictions.

### Mechanism 3
Input-dependent temperature scaling uses probing confidence to adjust calibration. Samples with high probing confidence receive lower temperatures (sharper distributions), while those with low probing confidence receive higher temperatures (flatter distributions), improving calibration while maintaining predicted labels.

## Foundational Learning

- **Self-supervised learning**: Needed to provide semantic relevance to classification tasks without labeled data, enabling probing confidence extraction. Quick check: Why can rotation prediction accuracy indicate classification accuracy at the dataset level?

- **Probing frameworks**: Needed to analyze learned representations without modifying the model, enabling post-hoc trustworthiness assessment. Quick check: How does fixing the backbone during probing training ensure we're not modifying the original model?

- **Temperature scaling**: Needed to calibrate softmax outputs, with our input-dependent variant using probing confidence for sample-specific scaling. Quick check: Why does dividing all logit outputs by the same temperature preserve the predicted label?

## Architecture Onboarding

- **Component map**: Backbone (fixed) → Probing classifier heads (trainable) for each task → Probing confidence computation → Combination with existing scores or temperature scaling → Original classifier remains unchanged

- **Critical path**: 1) Train probing classifiers (parallel training for each task) 2) Compute probing confidence for test samples 3) Combine with existing scores (misclassification/OOD detection) or use for temperature scaling (calibration)

- **Design tradeoffs**: Probing task complexity vs. correlation strength (more complex tasks may reduce correlation); number of transformations vs. dataset size (smaller datasets need simpler tasks); weighting of probing confidence vs. existing scores (hyperparameter tuning required)

- **Failure signatures**: Low probing classifier training accuracy (poor task design or insufficient data); negative correlation between probing confidence and classification accuracy (semantic mismatch); performance degradation when adding probing confidence (noisy signals)

- **First 3 experiments**: 1) Verify positive correlation between probing confidence and classification accuracy on validation set using rotation and translation tasks 2) Test different combinations of probing tasks (rotation only, translation only, both) on misclassification detection 3) Experiment with varying numbers of transformations to find optimal complexity for dataset size

## Open Questions the Paper Calls Out

### Open Question 1
How do probing confidence scores compare with existing trustworthiness indicators (entropy, Trust Score) in terms of correlation with true class probability? The paper doesn't provide direct comparison of these correlations.

### Open Question 2
What is the optimal number of transformations in probing tasks for different dataset sizes? The paper shows performance varies with transformation count but doesn't specify optimal values.

### Open Question 3
Can self-supervised probing be effectively applied to other trustworthiness tasks like continual learning or open-world settings? The paper suggests potential but doesn't explore these applications.

## Limitations

- Probing task design is highly dataset-dependent, with STL-10 showing significant degradation compared to CIFAR-10/CINIC-10
- The approach requires training multiple probing classifiers, adding computational overhead without discussion of training time or memory requirements
- Performance depends heavily on semantic relevance between probing tasks and classification, limiting generality across different domains

## Confidence

- **High confidence**: Core claim that self-supervised probing enhances trustworthiness is well-supported by consistent improvements across multiple datasets and evaluation metrics
- **Medium confidence**: Practical utility is promising but paper doesn't address computational costs, hyperparameter sensitivity, or robustness to adversarial examples
- **Low confidence**: Generality of approach is limited as success depends heavily on probing task selection and semantic relevance, which may not transfer well to different domains

## Next Checks

1. **Probe task ablation study**: Systematically vary the number and complexity of transformations in rotation and translation tasks to identify optimal configurations for different dataset sizes, particularly for smaller datasets like STL-10.

2. **Cross-dataset probing transfer**: Train probing classifiers on one dataset and evaluate probing confidence correlation on a different dataset to test whether the semantic relationship between probing tasks and classification is dataset-specific or more general.

3. **Computational overhead analysis**: Measure and compare training times and memory usage for baseline methods versus probing-enhanced versions across different model sizes to quantify practical costs.
