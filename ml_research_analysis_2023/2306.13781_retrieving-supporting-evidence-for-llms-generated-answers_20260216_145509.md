# Retrieving Supporting Evidence for LLMs Generated Answers

## Quick Facts
- arXiv ID: 2306.13781
- Source URL: https://arxiv.org/abs/2306.13781
- Reference count: 32
- Primary result: LLM can verify its own answers against retrieved evidence with 70-80% accuracy

## Executive Summary
This paper presents a method for detecting hallucinations in large language model (LLM) outputs by having the LLM verify its generated answers against an external corpus using retrieval techniques. The approach involves prompting an LLM to answer a question, retrieving supporting passages using either BM25 or neural retrieval methods, and then having the same LLM assess whether the retrieved evidence supports, contradicts, or is unrelated to its answer. Experiments on the MS MARCO dataset demonstrate that this self-verification approach achieves 70-80% accuracy in detecting hallucinations when appropriate supporting material is available, though performance is notably lower for answers involving numbers. The study highlights both the promise and limitations of using LLMs for self-verification of their own outputs.

## Method Summary
The proposed method consists of a three-step pipeline: first, an LLM generates an answer to a given question; second, a retrieval system (either BM25 or neural stack) finds relevant passages from an external corpus using the question-answer pair as a query; third, the LLM evaluates the consistency between its generated answer and the retrieved passage, classifying the relationship as supporting, contradicting, or unrelated. The neural retrieval stack combines multiple methods (SPLADE, ANCE, MonoT5, DuoT5) to improve passage relevance. A reader component can optionally extract concise answers from retrieved passages to enhance classification accuracy. The entire process is evaluated on the MS MARCO dataset using gpt-3.5-turbo with temperature set to 0 for deterministic outputs.

## Key Results
- LLM self-verification achieves 70-80% accuracy in detecting hallucinations when provided with relevant supporting evidence
- Classification accuracy drops significantly for answers involving numbers (e.g., phone numbers, quantities)
- Using a reader to extract concise answers from retrieved passages slightly improves classification accuracy
- Neural retrieval methods generally outperform BM25 but at higher computational cost

## Why This Works (Mechanism)
The approach works by leveraging the LLM's ability to understand and reason about text relationships, allowing it to assess whether retrieved evidence supports its own claims. When provided with relevant passages from an external corpus, the LLM can compare the factual content and determine consistency. This creates a form of external validation that doesn't rely solely on the model's internal knowledge. The mechanism is particularly effective when the retrieval system can find passages that directly address the core claims in the generated answer.

## Foundational Learning

**Neural retrieval stack**: Why needed - to improve passage relevance using learned representations; Quick check - compare neural vs BM25 retrieval quality on sample queries

**LLM classification**: Why needed - to determine consistency between answer and evidence; Quick check - test LLM's ability to identify supporting/contradicting evidence

**Reader extraction**: Why needed - to distill key information from passages for easier comparison; Quick check - verify extracted answers match source passages

## Architecture Onboarding

**Component map**: Question -> LLM Answer Generation -> Retrieval (BM25/Neural) -> Passage Retrieval -> LLM Classification -> Consistency Assessment

**Critical path**: The core pipeline is LLM generation followed by retrieval and classification. The reader component is optional but can improve accuracy. The retrieval method choice significantly impacts downstream classification performance.

**Design tradeoffs**: BM25 is faster and more interpretable but less accurate than neural methods. Using the same LLM for generation and verification may inherit knowledge limitations. The approach cannot verify claims about entities absent from the corpus.

**Failure signatures**: Numerical answer verification fails due to precision issues. Reader hallucination occurs when LLM generates additional information not in source passages. Poor retrieval quality leads to incorrect classifications.

## Limitations
- Relies on LLM self-verification which may inherit the same knowledge limitations and biases as the original model
- Cannot verify claims about entities or facts absent from the external corpus
- Performance degrades substantially for numerical answers
- Results may not generalize beyond MS MARCO dataset or to other LLM architectures

## Confidence

**High confidence**: The experimental methodology and retrieval pipeline implementation are clearly described and reproducible

**Medium confidence**: The 70-80% accuracy claims are supported by MS MARCO experiments but may not generalize to other domains or LLM models

**Medium confidence**: The observation about numerical answer verification being more challenging is plausible but would benefit from more detailed analysis
