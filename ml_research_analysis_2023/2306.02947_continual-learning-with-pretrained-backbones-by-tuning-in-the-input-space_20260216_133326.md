# Continual Learning with Pretrained Backbones by Tuning in the Input Space

## Quick Facts
- **arXiv ID**: 2306.02947
- **Source URL**: https://arxiv.org/abs/2306.02947
- **Authors**: 
- **Reference count**: 40
- **Primary result**: Input Tuning (IT) outperforms fine-tuning and regularization-based CL methods in class-incremental and domain-incremental settings, achieving up to ~8% better average accuracy with lower forgetting.

## Executive Summary
This paper introduces Input Tuning (IT), a continual learning method that avoids catastrophic forgetting by keeping a pre-trained backbone frozen and instead learning small, task-specific input transformations (e.g., learnable padding or perturbations) alongside a task-specific classifier head. IT is designed for edge devices, requiring less memory and compute than fine-tuning while achieving superior or comparable accuracy. Tested on four image classification datasets with ResNet-18, IT consistently outperforms or matches standard fine-tuning and regularization-based baselines, especially in scenarios with heterogeneous data sources.

## Method Summary
The method uses a pre-trained ResNet-18 backbone, frozen during training. For each new task, a randomly initialized classification head is added, and small learnable input transformations (IT-PAD for padding, IT-ADD for perturbations) are optimized jointly with the head. The transformations adapt the input to better suit the frozen backbone's features. In heterogeneous multi-source data scenarios, separate transformations per task (parallel classifier) are learned. Training uses cross-entropy loss and Adam optimizer, with the label trick to update only relevant head neurons per task. At test time, transformations are applied in parallel and predictions are aggregated based on the continual learning setting.

## Key Results
- IT achieves up to ~8% higher average accuracy than partial fine-tuning across four datasets.
- IT significantly reduces forgetting compared to fine-tuning baselines.
- Separate input transformations per task (parallel classifier) improve performance in heterogeneous multi-source data scenarios.
- IT is more memory- and compute-efficient than fine-tuning, making it suitable for edge devices.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Learning small, task-specific transformations in the input space (IT) preserves backbone knowledge better than fine-tuning.
- Mechanism: Instead of updating the pre-trained backbone weights, IT introduces a small set of learnable parameters (θg) that transform the input image (e.g., learnable padding or additive perturbations). This transformation is optimized jointly with the task-specific classifier head. Since the backbone is kept frozen, the rich representations it learned during pre-training are preserved, and the transformation adapts the input to make these representations more suitable for the new task.
- Core assumption: The pre-trained backbone is sufficiently generic to provide useful features for the new task, and a small transformation can bridge the gap between the backbone's feature space and the new task's requirements.
- Evidence anchors:
  - [abstract] "by avoiding to update the pre-trained part of the network and learning not only the usual classification head, but also a set of newly-introduced learnable parameters that are responsible for transforming the input data."
  - [section III] "We focus on a specific type of tuning that is not restricted to Transformer models, and that we study in the the context of CL."
- Break condition: If the pre-training task and the new task are too dissimilar, the backbone's features may be irrelevant, and no amount of input transformation will help.

### Mechanism 2
- Claim: Learning separate input transformations per task (parallel classifier) is beneficial for Multiple Source Data.
- Mechanism: In scenarios with data from multiple, heterogeneous sources, a single input transformation may not be optimal for all tasks. The parallel classifier approach learns a different transformation (θgj) for each task j. At test time, each transformation is applied in parallel, and the results are combined to make the final prediction. This allows the model to adapt to the specific characteristics of each task without interfering with others.
- Core assumption: The tasks are sufficiently different that a single transformation cannot optimally adapt the input for all of them.
- Evidence anchors:
  - [section III] "Whenever a continual learning problem spans clearly heterogeneous distributions... sharing the exact same transformation g(·, θg) for all the tasks... may not be optimal."
  - [section IV-D] "In FIVEDS/T5 (Multiple Source Data)... IT-PAD and IT-ADD provide valuable improvement when implemented in the parallel classifier."
- Break condition: If the tasks are too similar or the input space is homogeneous, the overhead of learning and applying multiple transformations may not be justified.

### Mechanism 3
- Claim: IT is more memory- and compute-efficient than fine-tuning, making it suitable for edge devices.
- Mechanism: Fine-tuning requires updating and storing gradients for a large number of backbone parameters, which can be prohibitive on edge devices with limited memory and computational power. IT, on the other hand, only introduces a small number of learnable parameters (e.g., 0.1M for IT-PAD vs. 4.7M-8.4M for partial fine-tuning). This drastically reduces the memory footprint and computational cost.
- Core assumption: The edge device has sufficient memory and compute to store and process the small number of IT parameters and apply the input transformation, but not enough to handle the full fine-tuning process.
- Evidence anchors:
  - [abstract] "This process allows the network to effectively leverage the pre-training knowledge and find a good trade-off between plasticity and stability with modest computational efforts, thus especially suitable for on-the-edge settings."
  - [section IV-C] "it requires smaller memory and it is less computationally demanding (compared to those instances of Transformer models with a relatively smaller number of parameters - such as ViT-B/16, 84M parameters)."
- Break condition: If the edge device has enough resources to handle fine-tuning, the additional complexity of IT may not be necessary.

## Foundational Learning

- Concept: Catastrophic forgetting
  - Why needed here: Continual learning involves learning new tasks sequentially without forgetting previously learned ones. Catastrophic forgetting is the phenomenon where a model forgets old tasks when learning new ones, which is the primary problem IT aims to solve.
  - Quick check question: What happens to a model's performance on old tasks when it is fine-tuned on new tasks without any regularization?

- Concept: Transfer learning and pre-trained backbones
  - Why needed here: The paper assumes the availability of a pre-trained backbone (e.g., ResNet-18) that has been trained on a large dataset (e.g., ImageNet). Understanding how to effectively transfer this knowledge to new tasks is crucial for the proposed IT method.
  - Quick check question: What are the advantages and disadvantages of using a pre-trained backbone versus training a model from scratch for a new task?

- Concept: Input space transformations
  - Why needed here: IT works by learning small transformations in the input space (e.g., learnable padding or additive perturbations) rather than modifying the backbone weights. Understanding how these transformations affect the model's behavior is key to understanding IT.
  - Quick check question: How does adding a learnable padding to an image or adding a learnable perturbation affect the features extracted by a pre-trained backbone?

## Architecture Onboarding

- Component map:
  Pre-trained backbone (ResNet-18) -> Input transformation (g) -> Task-specific classifier head -> Loss function (cross-entropy) -> Optimizer (Adam)

- Critical path:
  1. Load pre-trained backbone and freeze its weights.
  2. Initialize task-specific classifier head and input transformation parameters.
  3. For each task:
     a. Apply input transformation to the training data.
     b. Extract features using the frozen backbone.
     c. Classify features using the task-specific classifier head.
     d. Compute loss and update the classifier head and input transformation parameters.
  4. At test time, apply the appropriate input transformation (standard or parallel classifier) and classify the transformed input.

- Design tradeoffs:
  - Fine-tuning vs. IT: Fine-tuning updates the backbone weights, which can lead to catastrophic forgetting but may achieve better performance if the tasks are very similar. IT preserves the backbone knowledge but may not achieve the same level of performance.
  - Standard IT vs. parallel classifier: Standard IT uses a single transformation for all tasks, which is simpler and more efficient but may not be optimal for heterogeneous tasks. The parallel classifier learns separate transformations for each task, which can improve performance but increases complexity and memory usage.

- Failure signatures:
  - Poor performance on new tasks: The input transformation may not be effective in adapting the backbone's features to the new task.
  - Catastrophic forgetting: The input transformation may be overfitting to the new task and not generalizing well to old tasks (in the standard IT case).
  - High memory usage: The parallel classifier may be using too much memory, especially for a large number of tasks.

- First 3 experiments:
  1. Implement and test the baseline model (only training the classifier head) on CIFAR100/T10.
  2. Implement and test IT-PAD (learnable padding) on CIFAR100/T10 and compare its performance to the baseline.
  3. Implement and test the parallel classifier version of IT-PAD on FIVEDS/T5 (Multiple Source Data) and compare its performance to the standard IT-PAD and other baselines.

## Open Questions the Paper Calls Out

- **Question 1**: How do the benefits of Input Tuning (IT) scale with the size and complexity of the pre-trained backbone, and is there an optimal trade-off point beyond which further increases in backbone capacity provide diminishing returns?
  - Basis in paper: [inferred] The paper mentions focusing on ResNet-18 as a relatively small and edge-friendly architecture. It would be valuable to know how these results translate to larger backbones.
  - Why unresolved: The experiments are limited to ResNet-18, so the impact on larger models remains unknown.
  - What evidence would resolve it: Comparative experiments applying IT to larger backbones (e.g., ResNet-50, ResNet-101) on the same datasets, measuring accuracy, forgetting, and computational cost.

- **Question 2**: Can Input Tuning be effectively extended to continual learning scenarios beyond supervised classification, such as object detection, semantic segmentation, or generative modeling?
  - Basis in paper: [inferred] The study is restricted to image classification. The paper suggests future work to gain deeper insights into the learning dynamics of the proposed method.
  - Why unresolved: The method's adaptability to other task types and architectures is not explored.
  - What evidence would resolve it: Experiments applying IT to other computer vision tasks, reporting performance metrics and comparing against existing continual learning approaches.

- **Question 3**: What is the impact of Input Tuning on the robustness and generalization of the model to domain shifts, adversarial attacks, or out-of-distribution samples, especially when used in an online or streaming data setting?
  - Basis in paper: [inferred] The paper discusses multiple source data scenarios and mentions online learning as a potential extension, but does not explore robustness or security aspects.
  - Why unresolved: The study focuses on accuracy and forgetting, without investigating model robustness under distribution shift or adversarial conditions.
  - What evidence would resolve it: Experiments evaluating model performance under adversarial attacks, domain shift, and out-of-distribution detection, both with and without IT.

## Limitations

- The exact implementation details for the transformation functions (IT-PAD, IT-ADD) are not fully specified, which could affect reproducibility.
- The memory-efficiency claims are based on parameter counts, but actual runtime and memory usage on edge devices are not reported.
- The effectiveness of the parallel classifier in the Multiple Source Data setting is shown but lacks analysis of scalability with increasing task diversity.

## Confidence

- **High**: IT outperforms fine-tuning in accuracy and forgetting metrics across tested datasets.
- **Medium**: IT is significantly more memory-efficient than fine-tuning.
- **Medium**: Separate input transformations per task improve performance in heterogeneous settings.

## Next Checks
