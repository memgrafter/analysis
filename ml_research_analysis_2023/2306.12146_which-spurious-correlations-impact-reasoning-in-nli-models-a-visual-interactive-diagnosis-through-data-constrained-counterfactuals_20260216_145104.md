# Which Spurious Correlations Impact Reasoning in NLI Models? A Visual Interactive Diagnosis through Data-Constrained Counterfactuals

## Quick Facts
- arXiv ID: 2306.12146
- Source URL: https://arxiv.org/abs/2306.12146
- Authors: 
- Reference count: 7
- Key outcome: Visual interactive dashboard for diagnosing spurious correlations in NLI models through data-constrained counterfactuals and GPT-3 suggestions

## Executive Summary
This work introduces a visual interactive dashboard that enables users to diagnose spurious correlations in natural language inference (NLI) models through data-constrained counterfactuals. The approach identifies existing examples in datasets that share features with others but have different labels, then uses nearest neighbor comparisons and GPT-3 suggestions to generate new challenging examples. The dashboard provides model feedback on example difficulty, helping users refine counterfactuals that effectively test model reasoning. Through this process, the authors identify four main categories of spurious correlations: semantic relevance, logical fallacies, biases, and annotation artifacts.

## Method Summary
The method identifies data-constrained counterfactuals (DCCs) by finding examples that share features with other data points but have different labels and are hard for the model to predict. The interactive dashboard displays DCC information including data map location, shows nearest neighbor similarities and label differences, and integrates GPT-3 suggestions with model feedback on difficulty. Users explore similarities and differences between DCCs and their neighbors, generate new counterfactuals using GPT-3 guided by few-shot examples, and refine suggestions based on data map location estimation. The approach enables bi-directional explanation of reasoning patterns and supports diversifying training data based on discovered patterns.

## Key Results
- Identified four categories of spurious correlations: semantic relevance, logical fallacies, biases, and annotation artifacts
- Generated 80 counterfactual examples from 40 DCCs, with GPT-3 suggestions rated helpful by users
- Found that a robust NLI model achieved only 30% accuracy on generated examples, demonstrating their difficulty
- Successfully used the dashboard to diagnose reasoning patterns and generate challenging test cases for model evaluation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The system identifies spurious correlations by leveraging data-constrained counterfactuals (DCCs) as starting points for diagnosis.
- Mechanism: DCCs are defined as existing examples in the dataset that share features with other examples but have different labels, and are hard for the model to predict correctly. By analyzing similarities and differences between DCCs and their nearest neighbors, the system can pinpoint features that correlate spuriously with labels.
- Core assumption: The assumption is that features shared between a DCC and its nearest neighbors with different labels are likely to be spurious correlations.
- Evidence anchors:
  - [abstract] "The approach identifies existing counterfactual examples in datasets (data-constrained counterfactuals) and uses them to guide users in diagnosing spurious correlations through nearest neighbor comparisons and label analysis."
  - [section] "A data-constrained counterfactual is a data point that shares some features with other data points in the dataset but has a different label."
- Break condition: If the model's representation space does not capture meaningful semantic similarities, nearest neighbor comparisons may not reveal true spurious correlations.

### Mechanism 2
- Claim: GPT-3 suggestions enable efficient generation of diverse counterfactual examples that follow specific reasoning patterns.
- Mechanism: The system uses few-shot prompting with GPT-3, providing examples of nearest neighbors with the same label as the DCC to guide the generation of new counterfactuals. This leverages GPT-3's ability to understand and replicate reasoning patterns.
- Core assumption: GPT-3 can understand the reasoning pattern from the few-shot examples and generate valid counterfactuals that follow the same pattern but have different labels.
- Evidence anchors:
  - [abstract] "The dashboard enables users to generate diverse and challenging examples by drawing inspiration from GPT-3 suggestions."
  - [section] "Suggestions are generated by few-shot prompt the GPT-3 davinci-003 model using four nearest neighbors to the DCC with the same label."
- Break condition: If GPT-3 fails to capture the correct reasoning pattern or generates examples that are semantically close but logically inconsistent, the generated counterfactuals may not be useful.

### Mechanism 3
- Claim: Data map location estimation provides feedback on the difficulty of newly generated counterfactuals for the model.
- Mechanism: After generating a new counterfactual, the system estimates its location in the data map by measuring the model's confidence and variance across saved checkpoints. This helps users refine examples that are too easy for the model to predict.
- Core assumption: The data map location (confidence and variance) is a good indicator of how challenging a counterfactual is for the model.
- Evidence anchors:
  - [abstract] "users can receive feedback from a trained NLI model on how challenging the newly created example is and make refinements based on the feedback."
  - [section] "One of the common errors with GPT-3 suggestions is that the suggestion might be easy for the model to learn. To filter those suggestions, after labeling the example, the user can request an estimate of the data map location."
- Break condition: If the model's confidence and variance across checkpoints do not accurately reflect the difficulty of new examples, the data map estimation may not be reliable.

## Architecture Onboarding

- Component map:
  - Frontend: Interactive dashboard with visualization components
  - Backend: Model inference, data processing, and GPT-3 integration
  - Data: SNLI dataset, model checkpoints, generated counterfactuals

- Critical path:
  1. User selects a DCC from the dataset
  2. Dashboard displays DCC and its data map location
  3. User explores similarities and differences with nearest neighbors
  4. GPT-3 generates counterfactual suggestions based on user's findings
  5. User refines suggestions using data map feedback
  6. New counterfactuals are added to the dataset

- Design tradeoffs:
  - Using existing DCCs vs. generating new ones from scratch
  - Relying on GPT-3 for suggestion generation vs. manual creation
  - Providing data map feedback vs. other forms of model uncertainty estimation

- Failure signatures:
  - Nearest neighbor comparisons not revealing meaningful spurious correlations
  - GPT-3 generating semantically inconsistent or logically flawed counterfactuals
  - Data map estimation not accurately reflecting the difficulty of new examples

- First 3 experiments:
  1. Verify that the system can correctly identify DCCs in the SNLI dataset using the defined similarity metric and data map location.
  2. Test GPT-3's ability to generate valid counterfactuals based on few-shot examples from the same reasoning pattern.
  3. Evaluate the effectiveness of data map location estimation in identifying easy-to-learn counterfactuals that need refinement.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How effective are the data-constrained counterfactuals (DCCs) in identifying spurious correlations compared to traditional minimal-edit approaches?
- Basis in paper: [explicit] The paper contrasts DCCs with minimal-edit approaches, stating that minimal edits "do not necessarily improve the generalization of models and might even hurt the performance."
- Why unresolved: The paper does not provide direct experimental comparisons between DCCs and minimal-edit approaches in terms of effectiveness.
- What evidence would resolve it: Empirical results comparing model performance on out-of-domain data when trained with DCCs versus minimal-edit counterfactuals.

### Open Question 2
- Question: Can the dashboard's approach to generating counterfactuals be generalized to other NLP tasks beyond NLI, and what adaptations might be necessary?
- Basis in paper: [explicit] The authors mention that "our dashboard can be extended to various tasks in natural language processing" but focus on NLI for this work.
- Why unresolved: The paper does not explore or provide evidence of the dashboard's effectiveness on tasks other than NLI.
- What evidence would resolve it: Successful application and evaluation of the dashboard on other NLP tasks, demonstrating its adaptability and effectiveness.

### Open Question 3
- Question: What is the long-term impact of using the dashboard to diversify training data on model robustness and performance?
- Basis in paper: [explicit] The paper suggests that diversifying training data based on discovered patterns is a research opportunity, but does not provide long-term impact data.
- Why unresolved: The paper does not include follow-up studies or long-term evaluations of models trained with diversified data.
- What evidence would resolve it: Longitudinal studies showing sustained improvements in model robustness and performance on various datasets and tasks after training with diversified data.

## Limitations
- The evaluation relies on a single dataset (SNLI) and one robust NLI model, limiting generalizability
- GPT-3 suggestion effectiveness is validated only through qualitative user feedback rather than systematic evaluation
- The categorization of spurious correlations is based on manual inspection without statistical validation of their prevalence

## Confidence

- **High Confidence:** The technical framework for identifying data-constrained counterfactuals using similarity metrics and data map locations is well-specified and reproducible.
- **Medium Confidence:** The categorization scheme for spurious correlations is intuitive and well-documented, though empirical validation across multiple datasets is needed.
- **Low Confidence:** The claim that GPT-3 suggestions effectively generate diverse counterfactuals lacks quantitative validation beyond user satisfaction metrics.
