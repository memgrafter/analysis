# MyDigitalFootprint: an extensive context dataset for pervasive computing applications at the edge

## Quick Facts
- arXiv ID: 2306.15990
- Source URL: https://arxiv.org/abs/2306.15990
- Reference count: 40
- Primary result: Large-scale dataset combining smartphone sensors, proximity data, and social network interactions for pervasive computing at the edge

## Executive Summary
MyDigitalFootprint is a comprehensive dataset for pervasive computing applications that captures two months of smartphone sensor data, physical proximity information, and online social network interactions from 31 volunteer users. The dataset addresses the gap in publicly available resources that capture the complexity of user context in mobile environments. By combining heterogeneous data sources from both physical and virtual domains, MDF enables advanced context recognition and social relationship modeling for edge computing applications. The dataset supports three machine learning applications: social link prediction, daily-life activity recognition, and context-aware recommendation systems.

## Method Summary
The dataset was collected using an Android application built on the ContextKit framework, which unobtrusively monitored smartphone-embedded sensors, physical proximity data, and online social network interactions. Data collection occurred in the background without interfering with users' natural behavior over a two-month period. The dataset captures various sensor modalities including accelerometer, gyroscope, GPS, Wi-Fi, and Bluetooth data, along with Facebook interactions and proximity information. The collected data was uploaded to a remote backend server for aggregation and subsequent analysis using machine learning techniques.

## Key Results
- MDF is the first dataset to combine heterogeneous data from both physical and virtual domains for comprehensive user context modeling
- Three ML applications demonstrated high accuracy: social link prediction (AUC 0.75), context recognition (accuracy 73%), and context-aware recommendations
- The dataset shows significant class imbalance in context recognition, with Home and Free Time contexts dominating the data distribution

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** MDF combines heterogeneous data sources to model both physical and virtual user context, enabling more accurate pervasive computing applications.
- **Mechanism:** The dataset integrates smartphone sensor data (accelerometer, gyroscope, GPS, Wi-Fi, Bluetooth) with online social network interactions (Facebook posts, reactions, followed pages) and physical proximity data, creating a unified representation of user behavior across physical and cyber domains.
- **Core assumption:** Combining physical and virtual context data improves modeling accuracy compared to using either domain alone.
- **Evidence anchors:**
  - [abstract] "unique in combining heterogeneous data collected in the wild, providing an invaluable resource for validating new research in mobile and edge computing"
  - [section] "MDF is the first dataset presented in the literature that contains such heterogeneous data, aimed at modeling all the aspects of the user's context, combining information generated in both the physical and the cyber worlds"
  - [corpus] Weak - corpus neighbors focus on edge computing applications but don't specifically mention social-physical data integration
- **Break condition:** If either physical or virtual data streams become unavailable, the combined context modeling advantage diminishes significantly.

### Mechanism 2
- **Claim:** Local processing of user context data at edge devices improves privacy and reduces latency compared to cloud-based solutions.
- **Mechanism:** By processing sensor data directly on mobile devices rather than sending it to remote servers, the system avoids data transmission delays and eliminates the need to trust third-party entities with sensitive personal information.
- **Core assumption:** Local computation on mobile devices is sufficiently fast and capable for context recognition tasks.
- **Evidence anchors:**
  - [abstract] "user privacy can considerably benefit from the use of such a decentralized approach" and "shifting the computation from remote servers to the source of the context data (i.e., the user's mobile device) allows the system to preserve the user's privacy"
  - [section] "Processing user data directly on the local device provides two main advantages... user privacy can considerably benefit from the use of such a decentralized approach"
  - [corpus] Weak - corpus neighbors mention edge computing but don't specifically address privacy advantages of local processing
- **Break condition:** If mobile device computational resources become insufficient for the required processing tasks, the system must fall back to cloud processing, losing privacy benefits.

### Mechanism 3
- **Claim:** Machine learning models trained on MDF data can accurately predict social interactions and recognize user contexts for pervasive applications.
- **Mechanism:** The paper demonstrates three ML applications: social link prediction using proximity and OSN data, context recognition using multimodal sensor features, and context-aware recommendation systems, all achieving high accuracy on MDF data.
- **Core assumption:** The labeled data in MDF is representative and sufficient for training generalizable ML models.
- **Evidence anchors:**
  - [abstract] "we present three context-aware applications based on different machine learning tasks: (i) a social link prediction algorithm based on physical proximity data, (ii) daily-life activity recognition using smartphone-embedded sensors data, and (iii) a pervasive context-aware recommender system"
  - [section] "the prediction of physical contacts is based on proximity and Online Social Network data, the context recognition exploits sensing data to predict 6 daily-life activities"
  - [corpus] Weak - corpus neighbors focus on edge computing applications but don't specifically validate ML models on MDF
- **Break condition:** If the data distribution changes significantly in real-world deployment scenarios, model accuracy may degrade substantially.

## Architecture Onboarding

- **Component map:** Android app (ContextKit) -> Sensor data collection -> Local processing -> ML inference -> Context-aware applications
- **Critical path:** Sensor data → ContextKit collection → Local processing → ML inference → Application response
  - Latency bottleneck typically occurs at ML inference stage
  - Privacy bottleneck at data transmission stage (avoided by local processing)
- **Design tradeoffs:**
  - Sampling rate vs battery life: Higher sampling rates provide more detailed context but drain battery faster
  - Model complexity vs on-device computation: More complex models may be more accurate but require more computational resources
  - Data granularity vs privacy: More detailed data enables better context recognition but raises privacy concerns
- **Failure signatures:**
  - High false positives in context recognition → Check sensor calibration and feature engineering
  - Poor social link prediction accuracy → Verify proximity data quality and OSN data completeness
  - Battery drain issues → Review sampling rates and background process optimization
- **First 3 experiments:**
  1. Validate basic sensor data collection by running the Android app for 24 hours and checking data completeness
  2. Test context recognition accuracy using a simple decision tree on a subset of labeled data
  3. Evaluate social link prediction performance using basic heuristics (Common Neighbors, Jaccard Index) on proximity data

## Limitations

- Limited generalizability due to small sample size (31 users) and specific time period
- Significant class imbalance in context recognition data affects model performance for minority classes
- Unknown sampling rates and preprocessing steps create reproduction challenges

## Confidence

- **Medium:** Dataset uniqueness and integration value are well-supported but lack independent validation
- **Medium:** Privacy and latency benefits are theoretically sound but not empirically measured
- **Medium:** ML application results are promising but based on limited user sample size
