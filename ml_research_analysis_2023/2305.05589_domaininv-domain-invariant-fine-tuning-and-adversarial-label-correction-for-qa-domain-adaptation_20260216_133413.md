# DomainInv: Domain Invariant Fine Tuning and Adversarial Label Correction For QA Domain Adaptation

## Quick Facts
- arXiv ID: 2305.05589
- Source URL: https://arxiv.org/abs/2305.05589
- Reference count: 28
- Primary result: DomainInv achieves 2.59% EM and 2.17% F1 improvement over QADA baseline on average across multiple QA target domains

## Executive Summary
This paper proposes DomainInv, an unsupervised domain adaptation method for extractive QA systems that combines domain invariant fine-tuning with adversarial label correction. The approach injects target domain style information into source domain features through transformation layers at each transformer layer, then identifies and corrects target instances far from the source domain support. DomainInv is evaluated on five target QA datasets (HotpotQA, NaturalQuestions, NewsQA, SearchQA, TriviaQA) and demonstrates consistent improvements over strong baselines including QADA and CAQA, with an average gain of 2.59% EM and 2.17% F1.

## Method Summary
DomainInv addresses unsupervised domain adaptation for QA by first performing domain invariant fine-tuning, where transformation layers inject target domain style into source domain features through a learnable domain shift vector. This is followed by adversarial label correction that identifies target instances with inconsistent predictions between source-only and target-aware classifiers, then minimizes sliced Wasserstein distance to align these instances with source domain support. The framework iterates between these two components, progressively improving domain adaptation performance.

## Key Results
- DomainInv achieves 2.59% EM and 2.17% F1 improvement over QADA baseline on average
- Outperforms strong baselines (QADA, CAQA) across all tested target domains
- Demonstrates effective domain adaptation without requiring labeled target domain data

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Domain invariant fine-tuning with transformation layers enables the model to incorporate target domain style information while maintaining source domain supervision
- Mechanism: The transformation layer adds a domain shift vector at each transformer layer, calculated as the difference between average pooled target and source domain hidden states. This allows the model to inject target domain style information into the source domain features during fine-tuning.
- Core assumption: The domain shift information can be captured by the difference between average pooled source and target domain representations
- Evidence anchors:
  - [abstract] "we proposed the idea of domain invariant fine tuning along with adversarial label correction to identify the target instances which lie far apart from the source domain"
  - [section 4.2] "Let φ(x,x′) be the learnable domain shift vector between the source instance x and target domain instance x′"
  - [corpus] Weak evidence - the corpus neighbors don't directly discuss transformation layers but mention domain adaptation and adversarial training
- Break condition: If the domain shift information is too complex to be captured by a simple difference vector, or if the target domain is too dissimilar from the source domain

### Mechanism 2
- Claim: Adversarial label correction identifies target instances far from source domain and optimizes them to lie near source domain support
- Mechanism: The method uses a minmax game where the model first identifies target instances with inconsistent labels between source and target aware classifiers, then minimizes the sliced Wasserstein distance to bring these instances closer to source domain support
- Core assumption: Target instances that are far from source domain support can be identified by label inconsistency between source-only and target-aware classifiers
- Evidence anchors:
  - [abstract] "adversarial label correction to identify the target instances which lie far apart from the source domain"
  - [section 4.3] "We consider these instances as the one which are far apart from the source domain and the QA model is least confident about these"
  - [corpus] Weak evidence - the corpus neighbors discuss adversarial domain adaptation but don't specifically address label correction
- Break condition: If the label inconsistency doesn't reliably indicate distance from source domain support, or if the sliced Wasserstein distance minimization doesn't effectively bring instances closer

### Mechanism 3
- Claim: The iterative training process of fine-tuning followed by adversarial correction progressively improves domain adaptation
- Mechanism: The method alternates between domain invariant fine-tuning (incorporating target style) and adversarial label correction (aligning distant instances), repeating this process to iteratively improve performance
- Core assumption: The alternating optimization process converges to a better domain-adapted model than either component alone
- Evidence anchors:
  - [section 4.3] "Algorithm 1 DomainInv Training for UDA" shows the iterative process
  - [section 5.2] "DomainInv Framework outperforms all, on average it outperforms the best baseline by 2.59% and 2.17% in EM and F1 respectively"
  - [corpus] Weak evidence - the corpus neighbors discuss iterative training but don't specifically address the alternating fine-tuning/correction approach
- Break condition: If the alternating process doesn't converge or if performance plateaus early in the iterations

## Architecture Onboarding

- Component map:
  - BERT encoder with L transformer layers
  - Domain transformation layer at each transformer layer
  - Source domain classifier (C1)
  - Target domain classifier (C2)
  - Sliced Wasserstein distance calculation

- Critical path:
  1. Domain invariant fine-tuning: Update BERT encoder and C2 using source domain supervision with target style augmentation
  2. Adversarial label correction: Identify inconsistent target instances and minimize sliced Wasserstein distance to align them with source support

- Design tradeoffs:
  - Transformation layer dimension (k): Higher values capture more domain shift information but increase computational cost
  - Parallel sample selection: Sampling target domain instances with similar question types to source improves alignment but may limit diversity

- Failure signatures:
  - Performance plateauing early in iterations
  - No improvement on target domains compared to baseline
  - High variance in results across different target domains

- First 3 experiments:
  1. Implement domain invariant fine-tuning with k=256 and evaluate on a single target domain
  2. Add adversarial label correction and compare performance with and without this component
  3. Test the full DomainInv framework on all target domains and compare with QADA baseline

## Open Questions the Paper Calls Out

- **Transformation Layer Effectiveness**: The paper suggests exploring attention-weighted representations instead of simple average pooling for calculating domain shift vectors, but doesn't test this alternative approach.

- **Source Domain Inclusion**: The authors propose that incorporating source domain data during adversarial label correction could improve performance, but the current framework only uses target domain data.

- **Optimal Parallel Instance Ratio**: While the paper uses the same batch size for parallel target instances as source instances, it doesn't investigate whether this is optimal or explore different ratios.

## Limitations

- The transformation layer uses simple average pooling to capture domain shift, which may not adequately represent the complex relationships between tokens learned through self-attention mechanisms.

- Adversarial label correction may struggle with long-context datasets like SearchQA where answers are far from the beginning of the context.

- The method's effectiveness across all target domains is uncertain, with potential failure modes for domains with significantly different characteristics from the source domain.

## Confidence

- **High Confidence**: The overall framework design and the claim that DomainInv outperforms baseline methods (QADA, CAQA) on average across multiple target domains.

- **Medium Confidence**: The specific mechanisms of how domain transformation layers capture domain shift and how adversarial label correction identifies distant instances.

- **Low Confidence**: The claim that DomainInv works equally well across all target domains, particularly for long-context datasets like SearchQA.

## Next Checks

1. **Ablation Study on Transformation Layer Dimension**: Systematically vary k (transformation space dimension) and measure both performance impact and actual domain shift captured in the transformation vectors.

2. **Direct Analysis of Adversarial Correction**: For target instances identified as "far from source domain," analyze whether they truly have different answer distributions or if the label inconsistency is driven by other factors.

3. **Convergence Analysis of Iterative Training**: Track performance across iterations for each target domain separately, measuring whether improvements consistently occur and identifying at which iteration performance plateaus.
