# Practice with Graph-based ANN Algorithms on Sparse Data: Chi-square Two-tower model, HNSW, Sign Cauchy Projections

## Quick Facts
- **arXiv ID**: 2306.07607
- **Source URL**: https://arxiv.org/abs/2306.07607
- **Reference count**: 40
- **Primary result**: Sparse embeddings with ReLU activation reduce memory and similarity computation costs while maintaining high recall in ANN search

## Executive Summary
This study integrates graph-based approximate nearest neighbor (ANN) search with sparse embeddings for efficient embedding-based retrieval (EBR). The authors propose a "chi-square two-tower" model that produces highly sparse embeddings when combined with ReLU activation, and integrate sign cauchy random projections (SignCRP) to further compress vectors to bits. Experiments on ads targeting and public datasets show that sparse embeddings reduce memory and similarity computation costs, while maintaining high recall and classification accuracy. HNSW with sparse or hashed representations achieves 90%+ recall with up to 3x faster similarity computation and up to 18x speedups in retrieval time compared to dense representations.

## Method Summary
The method combines a chi-square two-tower neural network architecture with ReLU activation for producing sparse embeddings, integrated with HNSW (Hierarchical Navigable Small World) graph-based ANN search. The chi-square similarity function replaces the standard inner product in two-tower models, with sum-to-one normalization constraints enforced through ReLU activation. For further compression, Sign Cauchy Random Projections (SignCRP) compress sparse chi-square embeddings to binary representations while preserving similarity structure. The approach is evaluated on both proprietary ads targeting data (4.5 billion records) and public datasets including Webspam, News20, RCV1, and MNIST.

## Key Results
- Sparse embeddings with ReLU activation achieve up to 3x faster similarity computation and up to 18x faster retrieval times
- HNSW maintains 90%+ recall with sparse representations using smaller search parameters (L=5 vs L=30 for dense)
- SignCRP compresses chi-square embeddings to 32 integers (4 bytes) while preserving similarity structure for ANN search
- Classification accuracy remains stable when using sparse embeddings for 10-NN classification

## Why This Works (Mechanism)

### Mechanism 1
- Claim: ReLU activation combined with normalization constraints produces sparse embeddings in two-tower models
- Mechanism: ReLU sets negative values to zero, and when combined with sum-to-one normalization, the vector naturally develops many near-zero entries, leading to sparsity
- Core assumption: The network learns to distribute activation mass efficiently, concentrating it on few dimensions while setting others near zero
- Evidence anchors:
  - [section] "In fact, the sum-to-one constraint is the same as the 𝑙1 (lasso) constraint in non-negative data [33]. When we use the ReLU activation, we observe that both the cosine two-tower model and the chi-square two-tower model produce sparse embeddings, as expected [10, 13, 26]."
  - [section] "Figure 4 visualizes the (average) sparsity values for embedding sizes varying from 𝑘 = 128 to 𝑘 = 2048. As the cosine two-tower model also uses the ReLU activation function, we can see that the model is also quite sparse especially for large embedding size 𝑑."
  - [corpus] "No direct corpus evidence about ReLU-induced sparsity in this specific context. Evidence is primarily from paper text."
- Break condition: If ReLU activation is replaced with unbounded activation (e.g., linear) or normalization is removed, sparsity will decrease significantly.

### Mechanism 2
- Claim: Graph-based ANN search algorithms like HNSW achieve high recall with small search parameter L when using sparse embeddings
- Mechanism: Sparse embeddings reduce the computational cost per similarity comparison, allowing HNSW to explore more candidates within the same time budget, thus maintaining high recall even with small L values
- Core assumption: The search quality in HNSW is primarily limited by the number of similarity computations, which are reduced with sparse data
- Evidence anchors:
  - [section] "Figure 5 reports the top-1 and top-10 recalls for 𝑑 = 256 and 𝑑 = 1024. We observe from the experiments that for both models, the number of retrieved data points at the same 𝐿 is very close"
  - [section] "For example, with 𝑑 = 1024, we just need 𝐿 = 5 to achieve a top-1 recall of 0.9, while we need 𝐿 = 30 to achieve 0.9 if 𝑑 = 256."
  - [section] "Figure 6 shows that we achieve a 3-fold reduction in time for computing similarities by using the sparse format when 𝑑 = 1024."
- Break condition: If data becomes dense again or if HNSW implementation doesn't optimize for sparse operations, the benefit disappears.

### Mechanism 3
- Claim: Sign Cauchy Random Projections (SignCRP) can compress sparse chi-square embeddings to bits while preserving similarity structure
- Mechanism: SignCRP projects high-dimensional sparse vectors to lower-dimensional binary space where the collision probability between bit vectors is proportional to chi-square similarity
- Core assumption: The random projection preserves the relative similarity ordering needed for ANN search, even after aggressive compression
- Evidence anchors:
  - [section] "Specifically, let 𝑥 𝑗 = Í𝑑 𝑖=1 𝑢𝑖𝑟𝑖 𝑗 and 𝑦 𝑗 = Í𝑑 𝑖=1 𝑣𝑖𝑟𝑖 𝑗, 𝑗 = 1 to 𝑘, where {𝑟𝑖 𝑗 } is a random matrix with entries 𝑟𝑖 𝑗 sampled i.i.d. from the standard cauchy distribution. It was shown in [21] that the collision probability 𝑃 (𝑠𝑖𝑔𝑛 (𝑥 𝑗 ) = 𝑠𝑖𝑔𝑛 (𝑦 𝑗 )) is proportional to the chi-square similarity."
  - [section] "Figure 11 reports the experiments on Webspam, which has 3720 nonzeros per vector. With 𝑘 = 1024 sign cauchy projections for estimating the original chi-square in HNSW, we only need 1024/32 = 32 (4-byte) integers."
  - [corpus] "No direct corpus evidence about SignCRP implementation in HNSW context. Evidence is primarily from paper text."
- Break condition: If the number of projections k is too small or the original data is not well-suited to chi-square similarity, the approximation quality degrades.

## Architecture Onboarding

- Component map: Input layer (features) -> Shared embedding layer -> Two-tower architecture (query/item towers with ReLU) -> Normalization layer (sum-to-one) -> Similarity layer (chi-square or cosine) -> Loss layer (cross-entropy with temperature) -> ANN search component (HNSW with sparse/hashed representations) -> Output (ranked items)

- Critical path: Feature → Embedding → Tower processing → Similarity computation → ANN search → Ranking

- Design tradeoffs:
  - Sparsity vs. expressiveness: Higher embedding dimensions yield sparser vectors but may increase storage for dense formats
  - Precision vs. speed: Larger k in SignCRP improves similarity approximation but increases Hamming distance computation cost
  - Search quality vs. latency: Larger L in HNSW improves recall but increases query time

- Failure signatures:
  - Very low sparsity (<1%) defeats the sparse optimization benefits
  - Poor ANN recall despite high L values suggests graph construction issues
  - Classification accuracy degradation after compression indicates excessive information loss

- First 3 experiments:
  1. Train both cosine and chi-square two-tower models on a small dataset, measure sparsity levels and AUC scores to confirm the sparsity benefit
  2. Implement sparse-aware similarity computation in HNSW and measure speedups vs. dense implementation on sparse embeddings
  3. Apply SignCRP to chi-square embeddings with varying k values and measure recall and compression ratios on a test dataset

## Limitations
- The sparsity benefits may not generalize to domains beyond ads targeting and specific public datasets tested
- The chi-square similarity assumption may not work well for all embedding types, particularly those without non-negative values
- The optimal number of SignCRP projections likely varies by dataset and may require tuning

## Confidence
- **High confidence**: Sparse embeddings significantly reduce memory and similarity computation costs when combined with ReLU activation and normalization constraints
- **Medium confidence**: HNSW maintains high recall with sparse embeddings due to reduced per-comparison costs, though this may depend on specific HNSW implementation optimizations
- **Medium confidence**: SignCRP provides effective compression while preserving chi-square similarity structure, but the optimal k value likely varies by dataset

## Next Checks
1. **Cross-domain sparsity validation**: Train the chi-square two-tower model on a non-advertising dataset (e.g., recommendation or search) with different feature distributions to verify that sparsity patterns and AUC improvements persist across domains.

2. **Dense data scenario testing**: Evaluate the chi-square two-tower model on datasets where embeddings are inherently dense (e.g., image embeddings) to determine whether the sparsity advantage diminishes and whether alternative activation functions might be needed.

3. **Graph quality sensitivity analysis**: Systematically vary the HNSW parameter L across multiple orders of magnitude while measuring recall and search time on both sparse and dense embeddings to precisely quantify the performance trade-offs and identify break points.
