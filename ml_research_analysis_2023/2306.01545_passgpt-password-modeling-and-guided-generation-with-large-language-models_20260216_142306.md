# PassGPT: Password Modeling and (Guided) Generation with Large Language Models

## Quick Facts
- arXiv ID: 2306.01545
- Source URL: https://arxiv.org/abs/2306.01545
- Reference count: 40
- PassGPT outperforms GAN-based password guessing methods by approximately 2x on unseen passwords

## Executive Summary
PassGPT introduces a novel approach to password modeling using a large language model (GPT-2 architecture) that treats passwords as sequences of characters. Unlike existing GAN-based methods, PassGPT explicitly models password probabilities through autoregressive generation, enabling both superior password guessing performance and the novel capability of guided password generation with arbitrary character-level constraints. The model demonstrates strong generalization across multiple password datasets without requiring retraining, and its probability distribution correlates with established password strength estimators like zxcvbn.

## Method Summary
PassGPT uses a GPT-2 transformer decoder architecture trained on password leaks to model passwords as sequences of UTF-8 characters. The model employs a 256-character vocabulary and is trained for one epoch on password datasets including RockYou, LinkedIn, phpBB, MySpace, and Hotmail. Passwords are generated character-by-character using autoregressive sampling, with the model predicting each character conditioned on all previous characters. A companion model, PassVQT, extends this approach using vector quantization to represent passwords as sequences of subwords. The training procedure involves standard transformer training with cross-entropy loss, and evaluation focuses on guessing previously unseen passwords from test sets.

## Key Results
- PassGPT guesses twice as many unseen passwords compared to state-of-the-art GAN-based methods
- The model successfully generates passwords matching arbitrary character-level constraints (guided generation)
- Password probabilities from PassGPT align with established strength estimators like zxcvbn
- PassGPT demonstrates superior generalization across multiple password datasets without retraining

## Why This Works (Mechanism)

### Mechanism 1
- Claim: PassGPT uses autoregressive generation to model password probabilities explicitly.
- Mechanism: PassGPT predicts each character conditioned on all previous characters using a transformer decoder, allowing explicit calculation of password probabilities via chain rule.
- Core assumption: Passwords can be treated as sequences of characters with conditional dependencies.
- Evidence anchors:
  - [abstract] "PassGPT is an LLM trained on password leaks for password generation"
  - [section] "PassGPT, depicted in Figure 1, is an implementation of the GPT-2 architecture [39]"
  - [corpus] No direct evidence about autoregressive mechanics in related work
- Break condition: If password generation doesn't follow sequential character prediction, the explicit probability modeling breaks.

### Mechanism 2
- Claim: Guided password generation enables character-level constraints during sampling.
- Mechanism: Since PassGPT samples one character at a time, constraints can be applied by restricting the sampling distribution to specific character subsets at each position.
- Core assumption: Sequential sampling allows intervention at each character position.
- Evidence anchors:
  - [abstract] "we introduce the concept of guided password generation, where we leverage PassGPT sampling procedure to generate passwords matching arbitrary constraints"
  - [section] "PassGPT models each token separately, granting full control over each character"
  - [corpus] Weak - related work doesn't mention character-level guidance
- Break condition: If the model switches to whole-password generation, character-level guidance becomes impossible.

### Mechanism 3
- Claim: PassGPT's probability distribution aligns with password strength estimators.
- Mechanism: PassGPT assigns lower probabilities to passwords that are considered strong by existing strength estimators like zxcvbn.
- Core assumption: Password strength and model probability are inversely correlated.
- Evidence anchors:
  - [abstract] "We show that password probabilities align with state-of-the-art password strength estimators"
  - [section] "We computed the log probability and entropy for every position in all unique passwords... using PassGPT"
  - [corpus] No direct evidence about probability-strength alignment in related work
- Break condition: If the model learns patterns that contradict strength indicators, alignment breaks.

## Architecture Onboarding

- Component map:
  Tokenizer -> GPT-2 decoder (12 heads, 8 layers) -> Linear layer -> Softmax -> Character sampling -> Next input

- Critical path: Input characters → Tokenizer → GPT-2 decoder → Linear layer → Softmax → Character sampling → Next input

- Design tradeoffs:
  - Autoregressive vs whole-password generation: Enables guided generation but sequential computation
  - Vocabulary size (256): Covers all UTF-8 but increases computation
  - Single epoch training: Faster but may limit performance

- Failure signatures:
  - Low diversity in generated passwords: Check temperature and sampling strategy
  - Poor generalization to unseen datasets: Verify training data coverage
  - High computational cost: Profile transformer layers and consider optimization

- First 3 experiments:
  1. Generate passwords with different temperatures (0.5, 1.0, 1.5) and measure uniqueness
  2. Apply character-level constraints (e.g., fixed first character, length requirements) and verify generation
  3. Compare generated password probabilities with zxcvbn strength scores on a held-out set

## Limitations

- Generalization claims to unseen datasets are based primarily on English alphanumeric passwords and may not extend to structurally different password distributions
- Guided generation capability lacks comprehensive validation with complex, real-world constraint scenarios
- Probability-strength alignment may reflect correlation through shared training patterns rather than fundamental password strength capture

## Confidence

**High Confidence**: The core claim that PassGPT outperforms GAN-based approaches in password guessing accuracy is well-supported by quantitative comparisons across multiple datasets. The architectural implementation (GPT-2-based autoregressive generation) is standard and verifiable.

**Medium Confidence**: Claims about guided password generation capability are technically sound but lack comprehensive practical validation. The mechanism is correct, but real-world effectiveness across diverse constraint types needs verification.

**Low Confidence**: Generalization claims to truly unseen password distributions and the strength-alignment claims require more rigorous testing on diverse datasets to establish robustness.

## Next Checks

1. Cross-Character Set Evaluation: Test PassGPT on password datasets containing non-Latin characters (Cyrillic, Chinese, Arabic) to verify true zero-shot generalization beyond English alphanumeric patterns.

2. Complex Constraint Testing: Implement and evaluate guided generation with multi-dimensional constraints (minimum special characters, maximum repeated patterns, specific length distributions) to assess practical usability.

3. Independent Strength Correlation: Compare PassGPT's probability distribution with password strength on datasets not used in any related work to establish whether the alignment is fundamental or coincidental.
