# Supporting Qualitative Analysis with Large Language Models: Combining Codebook with GPT-3 for Deductive Coding

## Quick Facts
- arXiv ID: 2304.10548
- Source URL: https://arxiv.org/abs/2304.10548
- Reference count: 18
- Primary result: LLM-based deductive coding achieved fair to substantial agreement with expert coders (Cohen's kappa 0.61 for complexity, 0.38 for syntactic structure)

## Executive Summary
This study explores using large language models to support deductive coding in qualitative analysis, a traditionally labor-intensive process requiring extensive expertise. The approach combines expert-developed codebooks with GPT-3 through prompt learning, avoiding the need for task-specific model training. In a case study analyzing children's curiosity-driven questions, the method achieved fair to substantial agreement with expert-coded results, demonstrating the feasibility of LLM-assisted qualitative coding. The research identifies optimal prompt design strategies and highlights both opportunities and challenges for integrating LLMs into qualitative research workflows.

## Method Summary
The study employed a deductive coding task on a dataset of 668 French children's curiosity-driven questions, annotated by experts for question complexity (binary) and syntactic structure (4 categories). The method involved constructing prompts using expert codebooks and testing different configurations: zero-shot, one-shot, and few-shot settings, combined with codebook-centered and example-centered prompt designs. GPT-3 (davinci-text-002) was used with temperature set to 0.0 for reproducible results. Performance was evaluated using Cohen's kappa agreement with expert-coded results, comparing various prompt strategies to identify optimal approaches for LLM-assisted qualitative coding.

## Key Results
- Codebook-centered prompt design achieved fair to substantial agreement with expert coding (Kappa 0.61 for complexity, 0.38 for syntactic structure)
- One-shot prompting showed the largest performance gain over zero-shot, with diminishing returns for additional examples
- The approach successfully demonstrated LLM capability for deductive coding without task-specific model training

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Using expert-developed codebooks with LLMs improves coding agreement over unsupervised methods
- Mechanism: Codebooks provide explicit semantic structure that guides LLM output space, while LLMs apply pattern recognition across examples
- Core assumption: LLMs can generalize from codebook examples to unseen data without fine-tuning
- Evidence anchors:
  - [abstract] "by combining GPT-3 with expert-drafted codebooks, our proposed approach achieved fair to substantial agreements with expert-coded results"
  - [section] "We selected a deductive coding task as our starting point. The goal of deductive coding is to label the data based on a codebook."
- Break condition: If codebook descriptions are ambiguous or contradictory, LLM performance degrades due to lack of clear semantic boundaries

### Mechanism 2
- Claim: Codebook-centered prompt design outperforms example-centered design for this task
- Mechanism: Codebook-centered prompts provide direct semantic mappings while example-centered prompts require inference of semantic relationships from examples
- Core assumption: LLMs better understand explicit semantic descriptions than implicit semantic patterns
- Evidence anchors:
  - [section] "We found the codebook-centered design performs better than the example-centered designs"
  - [section] "Codebook-centered prompts with examples achieves the highest agreement"
- Break condition: If examples are more informative than descriptions, or if the LLM has strong in-context learning capabilities, example-centered might become competitive

### Mechanism 3
- Claim: Zero-shot performance is poor but improves significantly with one example per code
- Mechanism: LLMs require minimal examples to understand task boundaries but don't benefit much from additional examples beyond one per category
- Core assumption: LLMs can learn task semantics from a single example but additional examples provide diminishing returns
- Evidence anchors:
  - [section] "We observed the largest performance gain when shifting from a zero-shot to a one-shot setting"
  - [section] "However, the performance between one-shot and few-shot settings did not differ much"
- Break condition: If examples are highly diverse or if task boundaries are complex, more examples might be needed for optimal performance

## Architecture Onboarding

- Component map: Expert codebooks -> Prompt template generator -> GPT-3 API -> Response -> Kappa Evaluation
- Critical path: Codebook → Prompt Template → GPT-3 API → Response → Kappa Evaluation
- Design tradeoffs:
  - Using zero-shot vs. few-shot prompting affects latency and cost
  - Codebook-centered prompts require careful semantic formulation
  - Temperature setting of 0.0 ensures reproducibility but may reduce creativity
- Failure signatures:
  - Low Kappa scores indicate poor prompt design or codebook ambiguity
  - Inconsistent outputs suggest temperature or prompt structure issues
  - API errors indicate model capacity or rate limit problems
- First 3 experiments:
  1. Test zero-shot performance with only codebook descriptions
  2. Test one-shot performance with single example per code
  3. Compare codebook-centered vs. example-centered prompt structures with same examples

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can we design a codebook specifically for LLMs that maximizes task performance while maintaining interpretability for human researchers?
- Basis in paper: [explicit] The paper notes that "We constructed our prompts using the codebook for experts. Although it provides transparency and explicit control, it may limit the model’s performance" and suggests "Future study is required to understand how to design a more effective codebook for task performance and model understanding."
- Why unresolved: The paper only identifies this as a future research direction without exploring what specific features or structures would make a codebook more effective for LLM prompting versus human use.
- What evidence would resolve it: Comparative studies testing different codebook designs (e.g., different levels of detail, structure, examples) on LLM performance across multiple qualitative analysis tasks.

### Open Question 2
- Question: What is the optimal number of examples to include in LLM prompts for qualitative coding tasks, and does this vary by task complexity?
- Basis in paper: [explicit] The paper explores zero-shot, one-shot, and few-shot settings, finding "the largest performance gain when shifting from a zero-shot to a one-shot setting" but "performance between one-shot and few-shot settings did not differ much."
- Why unresolved: The study only tested up to five examples per code, leaving uncertainty about whether more examples might help for more complex tasks, or whether the optimal number varies by coding dimension.
- What evidence would resolve it: Systematic experiments varying the number of examples (e.g., 1, 3, 5, 10, 20) across multiple coding tasks with different complexity levels to identify patterns in performance improvement.

### Open Question 3
- Question: How can we effectively extend LLM-based qualitative analysis to support inductive coding where researchers develop codes during analysis rather than using predetermined ones?
- Basis in paper: [explicit] The paper states "However, for inductive coding, where the process is more bottom-up and exploratory, novel interaction and Human-AI collaboration diagrams are required."
- Why unresolved: The paper only identifies this as a future challenge without proposing specific interaction techniques or collaboration models for the inductive coding process.
- What evidence would resolve it: Prototype systems that enable real-time code suggestion, collaborative refinement of emerging themes, and visualization of coding patterns that adapt as researchers iterate on their codebook.

### Open Question 4
- Question: What specific error patterns emerge when LLMs perform qualitative coding, and how can these inform model improvements and interface design?
- Basis in paper: [explicit] The paper notes "To better understand model capability, we ought to conduct more detailed error analyses on disagreed items" but does not perform such analysis.
- Why unresolved: The paper only measures agreement levels without examining the nature of disagreements to understand whether errors are systematic, contextual, or related to specific code types.
- What evidence would resolve it: Detailed analysis of cases where LLM and human coders disagree, categorizing error types and developing targeted interventions (e.g., specific prompt modifications, confidence thresholds, or human review requirements for certain error types).

## Limitations
- Dataset limited to French children's questions, potentially limiting generalizability to other languages and domains
- Relies on expert-developed codebooks, which may not be available for all qualitative research contexts
- Only examines deductive coding with predetermined categories, not inductive coding where codes emerge from data
- Single LLM (GPT-3) used, limiting generalizability to other models or versions

## Confidence
- **High Confidence**: The core finding that codebook-centered prompts outperform example-centered designs is well-supported by experimental results
- **Medium Confidence**: The claim that one-shot prompting achieves optimal performance is supported but could benefit from testing on more diverse datasets
- **Medium Confidence**: The fair to substantial agreement (Kappa 0.61 for complexity, 0.38 for syntactic structure) represents meaningful performance but should be interpreted cautiously given specific task constraints
