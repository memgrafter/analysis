# A Case Study on Designing Evaluations of ML Explanations with Simulated User Studies

## Quick Facts
- arXiv ID: 2302.07444
- Source URL: https://arxiv.org/abs/2302.07444
- Reference count: 6
- One-line primary result: SimEvals correctly predicted user study findings that explanations don't improve fraud detection performance, suggesting SimEvals can help select promising explanation methods before costly user studies

## Executive Summary
This paper presents a case study comparing simulated user evaluations (SimEvals) against a real-world user study in fraud detection decision support. The study evaluates whether explanations improve human decision-making by training machine learning models to predict fraud labels using either (transaction, explanation) pairs or (explanation only) pairs. The results show that SimEvals correctly predict the original user study finding: no explanation method outperforms the baseline without explanations, and all three explanation methods perform similarly. Additionally, SimEvals suggest that for two explanation methods (TreeInterpreter and TreeSHAP), removing the transaction input while keeping only the explanation and model score has minimal performance impact, potentially enabling faster analyst review. Brief analyst interviews indicate that TreeInterpreter and TreeSHAP explanations align better with analyst feature preferences than LIME, though user studies would be needed to validate this approach. The findings provide initial evidence that SimEvals can help select promising explanation methods before costly user studies and explore alternative study designs.

## Method Summary
The study uses simulated user evaluations (SimEvals) to predict the outcomes of a real-world user study evaluating explanation methods in fraud detection. SimEvals train Random Forest models to predict fraud labels using the same information tuple (x, ŷ, E(x,f)) that would be presented in a user study, where x is transaction data, ŷ is the model score, and E(x,f) is the explanation. The performance of these models on a validation set serves as a proxy for how much predictive information the explanations contain. The study compares SimEval results against the original user study findings and explores alternative experimental designs by modifying the input tuple to (ŷ, E(x,f)) to evaluate whether explanations alone provide sufficient predictive signal.

## Key Results
- SimEvals correctly predicted the original user study finding that no explanation method outperforms the baseline without explanations
- All three explanation methods (TreeInterpreter, TreeSHAP, LIME) performed similarly in both SimEvals and the user study
- For TreeInterpreter and TreeSHAP, removing transaction input while keeping only explanation and model score had minimal performance impact in SimEvals
- Analyst interviews suggested TreeInterpreter and TreeSHAP explanations aligned better with feature preferences than LIME

## Why This Works (Mechanism)

### Mechanism 1
- Claim: SimEvals can identify promising explanation methods before costly user studies.
- Mechanism: SimEvals train ML models to predict the ground truth label using the same information tuple (x, ŷ, E(x,f)) that would be presented in a user study. The performance of these models on a validation set serves as a proxy for how much predictive information the explanations contain, allowing researchers to eliminate weak explanation methods early.
- Core assumption: The ML model's ability to extract predictive signal from the explanation correlates with human ability to extract useful information from the same explanation.
- Evidence anchors:
  - [abstract] "Our results suggest that SimEvals could have helped to select better candidate explainers in the original user study, reducing its cost and improving its chance of locating a successful explainer."
  - [section 2.4] "TheSimEval results show that the overlap in the actual information provided to the analysts across explanations are roughly the same (noting the error bars in theSimEvals column), which supports the general finding from Amarasinghe et al. (2022) that all explainers lead to comparable performance as the baseline"
- Break condition: If human analysts use domain knowledge or heuristics that are not captured by the ML model, or if the ML model fails to extract predictive information that humans can extract.

### Mechanism 2
- Claim: SimEvals can be used to explore alternative experimental designs cheaply.
- Mechanism: By modifying the input tuple (x, ŷ, E(x,f)) to (ŷ, E(x,f)) or other variations, SimEvals can evaluate whether the explanation alone provides sufficient predictive signal, suggesting whether it could replace full transaction data in human studies.
- Core assumption: If the SimEval model performs similarly with and without the transaction data, the explanation contains enough predictive signal to potentially replace it for human analysts.
- Evidence anchors:
  - [abstract] "We also explore the use ofSimEvals as a cheap proxy to explore an alternative user study set-up... Our preliminary findings suggest that a subset of the explainers considered in the original study can be used as a human-centric dimensionality reduction technique"
  - [section 3] "Our preliminary findings suggest that a subset of the explainers considered in the original study can be used as a human-centric dimensionality reduction technique (i.e., there is not statistically less signal in only presenting the explanation on its own)"
- Break condition: If humans need the full transaction context for reasons beyond pure predictive signal (e.g., verifying data quality, understanding edge cases).

### Mechanism 3
- Claim: SimEvals help avoid parroting degenerate strategies where models simply threshold the model score.
- Mechanism: By evaluating SimEval performance with and without explanations, researchers can determine if explanations add predictive value beyond what the model score already provides, ensuring the study isn't just measuring redundant information.
- Core assumption: If explanations contain predictive information that improves SimEval performance beyond the baseline model score, they are not simply parroting the model's prediction.
- Evidence anchors:
  - [section 2.3] "we find that all explanations improved in PDR when explainers were included, suggesting that theSimEvals could not have utilized only ŷ when making predictions"
  - [section 2.4] "Comparison of aggregate performance... the overlap in the actual information provided to the analysts across explanations are roughly the same (noting the error bars in theSimEvals column)"
- Break condition: If the model score ŷ is already highly predictive of the ground truth, making it difficult for any explanation to add meaningful signal.

  - Why needed here: The paper uses PDR as the primary evaluation metric, which measures revenue lost due to incorrect decisions relative to perfect classification. Understanding this metric is crucial for interpreting results.
  - Quick check question: How does PDR differ from traditional accuracy or F1-score metrics in classification tasks?

  - Why needed here: The paper compares three specific explanation methods, and understanding their characteristics helps interpret why some performed better than others in SimEvals.

## Architecture Onboarding

- Component map: Transaction data with ground truth fraud labels → SimEval model (Random Forest) trained on (x, ŷ, E(x,f)) tuples → PDR metric calculation on validation set → Comparison with original user study outcomes → Alternative design exploration with modified input combinations
- Critical path: Data → SimEval Training → PDR Evaluation → Comparison with User Study
- Design tradeoffs: SimEvals vs. Human Studies (cost vs. validity), different explanation methods (model-specific vs. model-agnostic), different input combinations for alternative design exploration
- Failure signatures: SimEval results that don't correlate with human study results, explanations that don't improve SimEval performance beyond baseline, significant performance drop when removing transaction data
- First 3 experiments:

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Under what conditions do SimEvals fail to predict user study findings, and what are the key factors that cause these failures?
- Basis in paper: [explicit] The paper discusses limitations of SimEvals, noting that they do not aim to replicate a user's decision-making process and may fail to capture human behavior when outside domain knowledge is important or when analysts lack time to examine information carefully.
- Why unresolved: The paper only provides initial evidence that SimEvals can corroborate user study findings in one specific fraud detection use case. The conditions under which SimEvals fail are not fully explored.
- What evidence would resolve it: Testing SimEvals across diverse use cases with varying levels of domain complexity, time constraints, and reliance on external knowledge would reveal when SimEvals break down.

### Open Question 2
- Question: Can SimEvals be used to predict the magnitude of performance differences between explanation methods, or only whether differences exist?
- Basis in paper: [inferred] The paper notes that while SimEvals can identify whether explanations contain predictive information, they only provide "an estimate of which explainers have the highest performance with no guarantee of how large the difference will actually be in a user study."
- Why unresolved: The study only tested whether SimEvals could detect the presence/absence of performance differences, not their magnitude. The limited sample size also prevented detection of smaller performance gaps.
- What evidence would resolve it: Conducting user studies with larger sample sizes across multiple explanation methods would allow comparison of predicted vs. actual performance gaps identified by SimEvals.

### Open Question 3
- Question: Does the proposed dimensionality reduction approach (showing only explanations without transaction details) actually reduce analyst review time without compromising accuracy?
- Basis in paper: [explicit] The paper found that for TreeInterpreter and TreeSHAP, removing transaction input while keeping only explanation and model score had minimal performance impact in SimEvals, and analyst interviews suggested the explanations aligned with their feature preferences.
- Why unresolved: The paper only provides preliminary evidence through SimEvals and brief interviews. No actual user study was conducted to measure real review time and accuracy trade-offs.
- What evidence would resolve it: A controlled user study comparing analyst performance and review time between the traditional (transaction + explanation) and proposed (explanation only) approaches would provide definitive evidence.

## Limitations
- SimEval performance may not correlate with human performance in realistic settings due to differences in how ML models and humans extract information
- The small sample size (1000 training transactions) limits the generalizability of findings
- The study only tested one specific use case (fraud detection) and may not generalize to other domains

## Confidence
- High confidence: SimEvals correctly predicted the original study's finding that no explanation method outperforms baseline
- Medium confidence: SimEvals can identify weak explanation methods before user studies
- Low confidence: SimEvals can reliably replace user studies for evaluating explanation methods in general

## Next Checks
1. Replicate the SimEval approach on a different user study with different explanation methods and tasks to test generalizability
2. Conduct a controlled experiment where both SimEvals and humans evaluate the same explanations on held-out data
3. Test whether SimEval performance correlates with specific human metrics like trust, satisfaction, or task completion time, not just accuracy
