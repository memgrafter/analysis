# Policy-Based Self-Competition for Planning Problems

## Quick Facts
- arXiv ID: 2306.04403
- Source URL: https://arxiv.org/abs/2306.04403
- Reference count: 40
- Primary result: GAZ PTP achieves optimality gaps under 0.2% for 20-node TSP instances and under 2% for 100-node instances.

## Executive Summary
This paper introduces GAZ PTP, a method that enhances AlphaZero-style planning algorithms for single-player tasks by incorporating historical policy versions directly into the planning process, rather than using scalar performance baselines. Instead of predicting episode outcomes, the algorithm compares states at similar timesteps between the current agent and its historical version to guide tree search. This approach is motivated by the observation that scalar baselines carry limited strategic information for improvement. Experiments on the Traveling Salesman Problem (TSP) and Job-Shop Scheduling Problem (JSSP) demonstrate that GAZ PTP consistently outperforms several single-player variants of GAZ, even when using only half the simulation budget.

## Method Summary
GAZ PTP uses a historical policy as a baseline opponent in a self-competitive framework, comparing states at the same timesteps during planning rather than predicting scalar episode outcomes. The algorithm employs a value network that outputs [-1, 1] to indicate whether the current policy is winning or losing against the historical policy at each state pair. MCTS is used to search for actions that improve upon the historical policy's trajectory, with the learned improvements distilled back into the policy network. Periodically, the best historical policy is updated based on performance in an arena evaluation.

## Key Results
- GAZ PTP achieves optimality gaps under 0.2% for 20-node TSP instances and under 2% for 100-node instances
- For JSSP, GAZ PTP reaches makespan gaps under 20% on 15×15 instances
- GAZ PTP outperforms single-player GAZ variants even with half the simulation budget
- The state-pair comparison approach provides more informative guidance than scalar baselines for planning improvement

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Self-competition with state-pair comparisons provides more informative guidance than scalar baselines for planning improvement.
- Mechanism: Instead of predicting whether a full trajectory beats a scalar baseline, the agent compares states at the same timestep between current and historical policies, creating a richer signal for policy improvement.
- Core assumption: Intermediate state comparisons contain more actionable information than final trajectory outcomes for learning better policies.
- Evidence anchors: The authors observe that scalar baselines only carry limited information about strategies to improve, and state-pair comparisons directly incorporate a historical policy into the planning process.

### Mechanism 2
- Claim: Policy improvements in the two-player game propagate to the original single-player problem via the advantage-based update.
- Mechanism: The GAZ policy improvement formula preserves improvements when comparing against historical states rather than scalar values, as shown by Lemma 1.
- Core assumption: The policy improvement guarantee from GAZ's tree search extends to the self-competitive formulation with state-pair comparisons.
- Evidence anchors: By Lemma 1, if π′ improves policy π baselined by µ, then π′ improves π in the original MDP.

### Mechanism 3
- Claim: Limiting tree search to one player while using the other as a fixed baseline reduces computational complexity while maintaining exploration benefits.
- Mechanism: Only the learning player uses MCTS, while the greedy player's actions are either sampled or chosen greedily, reducing the branching factor in the search tree.
- Core assumption: A fixed opponent provides sufficient diversity for the learning player to explore and improve without requiring full two-player MCTS.
- Evidence anchors: The authors note that by limiting the tree search to the learning actor, they can distill even incremental policy improvements to the policy network effectively.

## Foundational Learning

- Concept: Markov Decision Processes with episodic rewards
  - Why needed here: The algorithm operates on MDPs where the reward is only given at the end of episodes, requiring the agent to learn from delayed rewards
  - Quick check question: How does the absence of intermediate rewards affect the difficulty of learning value functions in this context?

- Concept: Advantage-based policy improvement in MCTS
  - Why needed here: GAZ uses advantage estimates (Q-value minus value) to update policy logits, which is central to both the original algorithm and the self-competitive extension
  - Quick check question: What role does the advantage function play in determining which actions to explore more deeply in the tree search?

- Concept: Self-play and self-competition mechanisms
  - Why needed here: The algorithm uses a historical version of itself as a baseline opponent, which requires understanding how self-play differs from self-competition
  - Quick check question: How does self-competition with a scalar baseline differ from the state-pair comparison approach used in this work?

## Architecture Onboarding

- Component map: Policy network πθ -> Value network Vν -> MCTS with GAZ selection rules -> Arena mode -> Replay buffer

- Critical path: Initialize with random policy and value networks -> Play game episodes against historical policy -> Store state pairs and binary outcomes in replay buffer -> Train networks on replay buffer data -> Periodically update historical policy if current policy performs better on arena set -> Repeat until convergence

- Design tradeoffs: State-pair comparison vs scalar baseline (more informative but requires comparing two states at each timestep) -> Sampling vs greedy opponent actions (sampling encourages exploration but increases computational cost) -> Arena set size (larger sets provide better evaluation but increase computation time)

- Failure signatures: Training plateaus early (historical policy may be too strong or weak, or value network cannot learn the sign comparison) -> Value network outputs random values (insufficient diversity in state pairs or poor network architecture) -> Policy doesn't improve over time (advantage estimates may be noisy or MCTS search budget insufficient)

- First 3 experiments: Verify that GAZ PTP outperforms GAZ Single Vanilla on TSP with small instances (n=20) -> Test sensitivity to simulation budget by comparing 50 vs 100 simulations in GAZ PTP -> Evaluate whether sampling greedy actor actions in MCTS improves exploration compared to greedy selection

## Limitations
- The exact network architectures and hyperparameters are not fully specified, making exact reproduction challenging
- Computational complexity of state-pair comparisons versus scalar baselines is not quantified, leaving scalability questions open
- The paper does not provide detailed analysis of failure modes or sensitivity to hyperparameters

## Confidence
- **High Confidence:** The core mechanism of using state-pair comparisons instead of scalar baselines is well-motivated and theoretically grounded
- **Medium Confidence:** The claim that GAZ PTP outperforms single-player GAZ variants is supported by experiments, but computational cost differences are not fully characterized
- **Low Confidence:** The generality of the approach to other planning problems beyond TSP and JSSP is suggested but not demonstrated
