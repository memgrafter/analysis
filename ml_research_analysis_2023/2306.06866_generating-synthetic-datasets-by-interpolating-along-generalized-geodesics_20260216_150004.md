# Generating Synthetic Datasets by Interpolating along Generalized Geodesics

## Quick Facts
- arXiv ID: 2306.06866
- Source URL: https://arxiv.org/abs/2306.06866
- Authors: 
- Reference count: 35

## Executive Summary
This paper proposes a novel approach to generating synthetic datasets for transfer learning by interpolating between existing datasets along generalized Wasserstein geodesics. The method finds optimal convex combinations of source datasets that minimize a (2,Q)-dataset distance to a target dataset, enabling interpolation even between datasets with disjoint label sets. Two methods are presented for estimating optimal transport maps: a barycentric projection approach and a neural network-based approach. The authors demonstrate improved transfer learning performance on both small-scale NIST datasets and large-scale VTAB datasets compared to baselines like Mixup and single-dataset pretraining.

## Method Summary
The method generates synthetic datasets by finding optimal convex combinations of training datasets that minimize distance to a target dataset using generalized Wasserstein geodesics. It estimates optimal transport (OT) maps between the target and training datasets using either barycentric projection or neural network methods, then computes (2,Q)-dataset distances to find optimal interpolation weights via quadratic programming. The synthetic dataset is generated by convexly combining mapped samples from the training datasets, which is then used to pretrain models before fine-tuning on the target dataset.

## Key Results
- OTDD-based interpolation achieves higher transfer learning accuracy than Mixup and single-dataset pretraining on NIST datasets
- The method successfully interpolates between datasets with disjoint label sets using neural OT maps
- On VTAB datasets, the approach outperforms baselines while maintaining computational efficiency through (2,Q)-distance approximation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Interpolating along generalized Wasserstein geodesics produces datasets more similar to target domain than individual sources
- Mechanism: OTDD distance measures similarity via optimal transport couplings accounting for feature distance and label alignment, finding convex combinations that better represent target distribution
- Core assumption: Wasserstein metric preserves meaningful dataset similarity correlating with transfer performance
- Evidence anchors: [abstract] "closest (in terms of a metric between datasets) to the target"; [section] "d2_OT(DP, DQ) = min π∈Π(P,Q) ∫∥x − x′∥2 + W2(αy, αy′) dπ(z, z′)"
- Break condition: OTDD metric doesn't correlate with transfer performance or geodesic doesn't capture relevant distribution structure

### Mechanism 2
- Claim: Optimal transport maps can be learned between datasets with disjoint label sets
- Mechanism: OTDD neural map learns pushforward feature map and labeling function through adversarial training minimizing OTDD distance
- Core assumption: Neural networks can approximate optimal transport maps between complex distributions with label structure
- Evidence anchors: [abstract] "interpolate even between datasets with distinct and unrelated label sets"; [section] "parameterize the map TN: Rd × [0,1]CQ → Rd × [0,1]CP"
- Break condition: Neural network cannot capture transport map complexity or adversarial training fails to converge

### Mechanism 3
- Claim: (2,Q)-dataset distance provides computationally efficient proxy for Wasserstein distance
- Mechanism: (2,Q)-distance measures squared distance via OTDD maps to target without requiring optimization, enabling QP solution for interpolation weights
- Core assumption: (2,Q)-distance preserves distance ordering relevant to optimization
- Evidence anchors: [abstract] "approximated projection bPa as the minimizer of function W2(Pa, Q)"; [section] "W2,Q is a valid metric"
- Break condition: (2,Q)-distance doesn't preserve relevant distance ordering for optimization

## Architecture Onboarding

- Component map: OTDD coupling solver -> OTDD neural map trainer -> Interpolation weight optimizer -> Dataset generator -> Transfer learning pipeline
- Critical path: 1) Compute OTDD couplings between target and all sources; 2) Estimate OTDD maps (barycentric or neural); 3) Compute (2,Q)-distances between all pairs; 4) Solve for optimal weights via QP; 5) Generate synthetic dataset via convex combination; 6) Train model on synthetic; 7) Fine-tune on target
- Design tradeoffs: Barycentric projection vs neural maps (stable vs continuous generation); feature space vs pixel space (semantic similarity vs simplicity); (2,Q) approximation vs exact Wasserstein (fast vs potentially less accurate)
- Failure signatures: Poor transfer accuracy despite low W2(Pa, Q) suggests OTDD doesn't correlate with transfer performance; training instability suggests adversarial objective or architecture needs adjustment; heavily skewed weights suggest limited source diversity or poor target-source alignment
- First 3 experiments: 1) Verify OTDD correlation by computing distances between all NIST datasets and correlating with individual dataset pretraining accuracy; 2) Test barycentric vs neural maps on simple target like MNIST; 3) Validate (2,Q) approximation by comparing optimal weights from (2,Q)-distance QP with direct Wasserstein computation on small synthetic example

## Limitations
- OTDD barycentric projection becomes computationally prohibitive for large-scale datasets due to quadratic complexity
- Neural map approach introduces training instability risks despite addressing scalability
- Claim that OTDD distance correlates with transfer learning performance lacks rigorous theoretical justification
