# Few-shot learning approaches for classifying low resource domain specific software requirements

## Quick Facts
- arXiv ID: 2302.06951
- Source URL: https://arxiv.org/abs/2302.06951
- Reference count: 27
- Primary result: SciBERT and DeBERTa achieve best performance with 15 samples/class; T5 models show largest improvement (6.33 pp) when scaled to 50 samples/class

## Executive Summary
This work evaluates five transformer-based approaches for few-shot classification of domain-specific automotive software requirements, where annotated data is scarce. The authors fine-tune SciBERT, DeBERTa, Siamese MiniLM, and two T5 variants on only 15 samples per class and evaluate on approximately 3000 Bosch automotive requirements. The study demonstrates that transformer models can effectively adapt to domain-specific tasks with minimal labeled data, with SciBERT and DeBERTa leading in strict few-shot settings while T5 models benefit most from additional training samples.

## Method Summary
The study compares five transformer-based models reformulated as different NLP tasks: SciBERT with linear classification head, DeBERTa with NLI head, Siamese MiniLM with semantic similarity head, T5 with semantic similarity target, and T5 with generative target. All models are fine-tuned on 15 samples per class of Bosch automotive requirements, with an augmented version using 50 samples per class via WordNet synonym replacement. The evaluation uses macro F1, weighted F1, and accuracy metrics on a test set of approximately 3000 samples. Models are trained with fixed hyperparameter settings from Table I, and performance is compared across the different task reformulations.

## Key Results
- SciBERT and DeBERTa achieve the highest performance in the strict 15-sample setting
- T5-based models show the largest improvement (up to 6.33 percentage points) when training data increases from 15 to 50 samples per class
- All models converge toward similar performance levels as more training samples become available
- The reformulated task approaches demonstrate viability for few-shot domain-specific classification

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Transformer-based models trained on general language can adapt to domain-specific tasks with very few examples if fine-tuned properly.
- Mechanism: Pre-trained transformers encode rich linguistic representations from large-scale general corpora; fine-tuning on small domain-specific data leverages these representations to bootstrap task-specific classification.
- Core assumption: The semantic and syntactic patterns learned during pre-training are transferable to the automotive domain's domain-specific terminology and grammatical structures.
- Evidence anchors:
  - [abstract] "With the advent of strong pre-trained natural language processing models like BERT, DeBERTa, MiniLM, T5, the data requirement for industries to fine-tune these models to their niche use cases has drastically reduced"
  - [section] "Pre-trained transformer models such as BERT [3], DeBERTa [4], RoBERTa [5], MiniLM [6], T5 [7] have lead to state-of-the-art performance on several NLP tasks"
- Break condition: If domain-specific language is too divergent from general training corpora (e.g., highly specialized jargon or novel grammatical structures), the pre-trained representations may not transfer well, causing performance to plateau or degrade.

### Mechanism 2
- Claim: Reformulating the classification task as different NLP sub-tasks (linear classification, NLI, semantic similarity, generation) allows the same data to be reused in multiple ways to improve model learning.
- Mechanism: Each reformulation exploits different capabilities of transformer models—linear heads use direct mapping, NLI uses entailment reasoning, similarity uses metric learning, and generation uses language modeling—thus providing complementary learning signals.
- Core assumption: The underlying transformer encoder can effectively encode the input in a way that supports diverse downstream tasks with minimal task-specific adaptation.
- Evidence anchors:
  - [section] "We tackle the task of pattern classification by reformulating the problem as 5 different NLP tasks to test their performance in a FSL setting."
  - [section] "SciBERT is pre-trained on a large corpus of scientific text, including research articles, patent applications, and scientific books."
- Break condition: If the reformulated task does not align well with the pre-training objective, the model may fail to generalize even with task-specific fine-tuning.

### Mechanism 3
- Claim: Increasing the number of training samples from 15 to 50 per class yields diminishing returns for some models but significant gains for others, especially generative T5-based models.
- Mechanism: Models that rely more heavily on task-specific adaptation (like T5's text-to-text framework) benefit more from additional data because they must learn the mapping from input to output representation, whereas models with simpler classification heads may already have captured most useful information with fewer samples.
- Core assumption: The model's architecture determines the rate at which additional labeled data improves performance in the few-shot regime.
- Evidence anchors:
  - [abstract] "T5-based models show the greatest improvement (up to 6.33 percentage points) when the training set is expanded to 50 samples per class."
  - [section] "Further, it can be seen from the Δ values that for A2, both the T5 based models showed large improvement across the metrics."
- Break condition: If the added samples are not diverse or are noisy, additional data could lead to overfitting or performance degradation instead of improvement.

## Architecture Onboarding

- Component map:
  Input preprocessing -> Transformer encoder (SciBERT/DeBERTa/MiniLM/T5) -> Task-specific head (linear/NLI/similarity/generation) -> Output processing (softmax/cosine/Levenshtein distance)

- Critical path:
  1. Load and preprocess 15 samples per class (plus augmented samples)
  2. Fine-tune chosen transformer model with appropriate head and task formulation
  3. Evaluate on held-out test set (~3000 samples)
  4. Repeat with 50 samples per class to measure scalability

- Design tradeoffs:
  - Simpler heads (linear, NLI) are faster to train and require less adaptation but may not capture complex relationships
  - T5-based approaches are more flexible and can generate outputs but require more compute and careful decoding strategies
  - Siamese networks require constructing positive/negative pairs, increasing data preparation complexity

- Failure signatures:
  - High variance across random seeds: suggests instability due to very limited data
  - Little to no improvement when increasing samples: indicates model capacity saturation or poor task formulation
  - Output mismatch in T5-based generation: may need better decoding or post-processing

- First 3 experiments:
  1. Fine-tune SciBERT with linear head on 15 samples per class and evaluate accuracy
  2. Fine-tune DeBERTa with NLI head on same data and compare performance
  3. Fine-tune T5 with semantic similarity reformulation and assess improvement when increasing samples to 50

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions, but several remain implicit based on the methodology and results presented.

## Limitations
- Small sample size (15 per class) may lead to unstable performance estimates and limit generalizability
- Use of augmented data (50 samples) blurs the line between true few-shot and low-resource settings
- Single dataset from automotive domain limits external validity and cross-domain applicability
- Only 3 classes evaluated, which may not reflect complexity of real-world multi-class scenarios

## Confidence
- High confidence: Pre-trained transformers can achieve reasonable performance in few-shot settings; performance convergence with increased data
- Medium confidence: Model ranking (SciBERT/DeBERTa best at 15 samples, T5 improves most at 50 samples); mechanism explaining T5's data benefit
- Low confidence: Task reformulation as primary driver of performance differences

## Next Checks
1. Reproduce with multiple random seeds and report variance: Run each model configuration (15 and 50 samples per class) with at least 5 different random seeds and report mean ± standard deviation for all metrics to assess stability.
2. Test on a multi-class, multi-domain dataset: Evaluate the same set of models on a dataset with more than 3 classes and from a different domain (e.g., biomedical or legal text) to assess generalizability.
3. Ablation study on task reformulation: Implement a controlled experiment where the same transformer model (e.g., SciBERT) is fine-tuned with different task formulations (linear, NLI, similarity) while keeping all other factors constant to isolate the effect of reformulation.
