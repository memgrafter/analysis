# Tuning structure learning algorithms with out-of-sample and resampling strategies

## Quick Facts
- arXiv ID: 2306.13932
- Source URL: https://arxiv.org/abs/2306.13932
- Reference count: 16
- Key outcome: OTSL improves F1 score by 2.3-2.5% compared to unoptimized defaults when tuning EBICnormalized γ

## Executive Summary
This paper proposes OTSL (Out-of-sample Tuning for Structure Learning), a novel hyperparameter tuning method for structure learning algorithms in Bayesian networks. The method employs bootstrapping to generate multiple training and test datasets, then optimizes hyperparameters by maximizing either the EBICnormalized γ or BDeuiss objective scores on test data. Synthetic experiments on 6 case studies with sample sizes of 1k and 10k show that OTSL consistently improves graphical accuracy across different structure learning algorithms including PC-Stable, HC, FGES, and MMHC.

## Method Summary
OTSL uses bootstrapping to create multiple train/test splits from the input data. For each hyperparameter configuration, it runs structure learning on each training set and evaluates the specified score (EBICnormalized γ or BDeuiss) on the corresponding test set. The average score across all iterations is computed, and the configuration with the highest average score is selected as optimal. This out-of-sample approach aims to find hyperparameters that generalize well across data variations rather than overfitting to a single dataset split.

## Key Results
- OTSL improves F1 score by 2.3-2.5% compared to unoptimized defaults when tuning EBICnormalized γ
- The improvement is consistent across different structure learning algorithms including PC-Stable, HC, FGES, and MMHC
- OTSL outperforms other hyperparameter tuning methods like OCT and StARS in terms of both F1 and SHD scores

## Why This Works (Mechanism)

### Mechanism 1
Out-of-sample resampling with bootstrapping improves hyperparameter estimation by exposing the model to data variations that mimic real-world uncertainty. By repeatedly sampling with replacement, OTSL generates multiple train/test splits, allowing each hyperparameter configuration to be evaluated on held-out data, reducing overfitting to a single dataset split. Core assumption: The underlying true graph and its structure are consistent across bootstrap samples; variations are due to sampling noise rather than structural changes.

### Mechanism 2
Score-based tuning on test data (EBICnormalized γ) leads to better structural accuracy than relying on default hyperparameters. Hyperparameters are selected by maximizing the average EBICnormalized γ score over K bootstrap iterations, ensuring the chosen configuration generalizes across data perturbations. Core assumption: EBICnormalized γ is sensitive to hyperparameter changes in a way that correlates with structural accuracy (F1, SHD).

### Mechanism 3
OTSL outperforms in-sample methods like StARS and out-of-sample methods like OCT by combining resampling with score-based evaluation. OTSL uses out-of-sample evaluation (test data) while resampling increases statistical stability, avoiding pitfalls of in-sample stability metrics (StARS) or predictive MB-based tuning (OCT). Core assumption: The test data splits are representative enough to provide meaningful score estimates for hyperparameter selection.

## Architecture Onboarding

- Component map: Input data -> Bootstrap resampling engine -> Structure learning executor -> Score evaluator -> Output optimal configuration
- Critical path:
  1. Generate K bootstrap train/test splits
  2. For each config in C, run structure learning on each train set
  3. Evaluate score on corresponding test set
  4. Average scores across K iterations
  5. Select config with highest average score
- Design tradeoffs:
  - Resampling vs. cross-validation: Resampling increases data variation but may introduce redundancy; cross-validation ensures disjoint splits but fewer iterations
  - Score choice: EBICnormalized γ correlates well with structure accuracy; BDeuiss is less sensitive to hyperparameter changes
  - Runtime vs. accuracy: More iterations improve stability but increase runtime
- Failure signatures:
  - Low variance in scores across bootstrap iterations → data may be too homogeneous or too small
  - Optimal config close to default → hyperparameter space may be poorly explored or defaults are already good
  - Runtime timeouts → structure learning algorithms are computationally heavy; consider limiting K or dataset size
- First 3 experiments:
  1. Run OTSL on a small synthetic BN (e.g., Asia) with K=5 to validate bootstrap splits and score averaging
  2. Compare OTSL's optimal γ vs. default γ on a mid-size BN (e.g., Alarm) to confirm improvement in F1
  3. Benchmark OTSL vs. StARS on the same BN to measure relative performance gains

## Open Questions the Paper Calls Out

### Open Question 1
Does OTSL's out-of-sample tuning approach work equally well for hybrid structure learning algorithms as it does for score-based and constraint-based algorithms? The paper provides results for hybrid algorithms in initial experiments but does not include them in comparisons with other tuning methods.

### Open Question 2
How does OTSL's computational efficiency scale with the number of variables and sample size in real-world datasets? The paper mentions OTSL's runtime is similar to StARS but does not provide detailed analysis of computational complexity scaling.

### Open Question 3
Can OTSL be extended to optimize hyperparameters for structure learning algorithms that use continuous variables or mixed data types? The paper focuses on discrete data and does not discuss applicability to algorithms handling continuous or mixed data types.

## Limitations
- Generalizability to real-world datasets beyond tested synthetic and small real datasets remains uncertain, particularly for complex structures with many variables
- Computational cost of bootstrapping across multiple structure learning algorithms is a practical limitation for large-scale applications
- Assumption that bootstrap samples adequately represent the true underlying structure may not hold for datasets with significant sampling bias or rare variable states

## Confidence
- High confidence: The mechanism that out-of-sample evaluation with bootstrapping reduces overfitting to single dataset splits
- Medium confidence: The claim that EBICnormalized γ tuning provides consistent improvement across different algorithms, given the evidence is primarily from synthetic experiments
- Low confidence: The comparative performance claims against OCT and StARS, as the corpus lacks direct evidence for these specific comparisons
