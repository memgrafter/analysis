# On The Convergence Of Policy Iteration-Based Reinforcement Learning With Monte Carlo Policy Evaluation

## Quick Facts
- arXiv ID: 2301.09709
- Source URL: https://arxiv.org/abs/2301.09709
- Reference count: 40
- Primary result: Proves convergence of policy iteration using Monte Carlo policy evaluation with single sample trajectory per policy

## Executive Summary
This paper addresses a longstanding open problem in reinforcement learning by proving convergence of policy iteration algorithms that use Monte Carlo policy evaluation with a single sample trajectory per policy. The key innovation is the use of lookahead policies that enable the algorithm to act as a contraction mapping, even with noisy Monte Carlo estimates. The authors provide both asymptotic and finite-sample error bounds, extending results to linear function approximation. This work bridges the gap between classical policy iteration methods and modern trajectory-based reinforcement learning approaches.

## Method Summary
The method uses a policy iteration framework where each iteration involves computing a lookahead policy (H-step optimal policy) and evaluating it using a single trajectory. The lookahead ensures the Bellman operator acts as a contraction, enabling convergence via stochastic approximation techniques. For function approximation, linear combinations of feature vectors approximate value functions, with convergence guaranteed within approximation error bounds.

## Key Results
- Proves convergence of first-visit Monte Carlo ES algorithm with lookahead policies
- Shows convergence is a contraction when α^H-1 + 2(1+α^m)α^H-1/(1-α) < 1
- Extends to linear function approximation with convergence within δ_app error
- Provides finite-sample error bounds of order 1/(1-α)^(H-1)(1-α)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Sufficient lookahead turns policy iteration into a contraction mapping
- Mechanism: When lookahead depth H is large enough, the Bellman operator applied H times contracts towards the optimal value function J* with contraction factor α^H-1/(1-α). This contraction property enables convergence via stochastic approximation techniques even with noisy Monte Carlo estimates.
- Core assumption: α^H-1 + 2(1+α^m)α^H-1/(1-α) < 1 (sufficient lookahead condition)
- Evidence anchors:
  - [abstract]: "The key insight is that sufficient lookahead makes the algorithm a contraction, enabling application of stochastic approximation techniques"
  - [section 3.1]: "With sufficiently large lookahead, we can show that T^m_{μk+1} T^{H-1}V_k is a contraction towards J* for any m and H"
  - [corpus]: Weak evidence - related papers focus on policy gradient and tree search but don't directly address convergence proofs
- Break condition: If lookahead depth H is insufficient, the contraction factor exceeds 1 and convergence fails

### Mechanism 2
- Claim: Single trajectory Monte Carlo policy evaluation works with lookahead
- Mechanism: By using a single trajectory from each policy and computing returns only for states visited, the algorithm still converges because the lookahead policy computation ensures the value function estimates contract toward optimality. The sampling noise averages out due to square-summable stepsizes.
- Core assumption: Exploring starts condition (each state has positive probability of being visited)
- Evidence anchors:
  - [abstract]: "We prove convergence of a first-visit Monte Carlo ES algorithm using lookahead policies"
  - [section 3]: "We consider a version of the Monte Carlo ES algorithm... At each iteration, k, the algorithm stores an estimate of the optimal value function, V_k"
  - [corpus]: Weak evidence - most related work focuses on policy gradient rather than trajectory-based policy iteration
- Break condition: If the exploring starts condition fails, some states may never be visited, preventing convergence

### Mechanism 3
- Claim: Linear function approximation extends convergence to high-dimensional spaces
- Mechanism: By mapping states to feature vectors and using linear combinations to approximate value functions, the algorithm converges within approximation error δ_app. The lookahead ensures the projected Bellman operator remains a contraction in the feature space.
- Core assumption: Feature vectors satisfy the contraction condition 0 < α^H-1 + κ·2α^H-1/(1-α) < 1
- Evidence anchors:
  - [abstract]: "We extend results to linear function approximation, showing convergence within an approximation error"
  - [section 4]: "We show that when the lookahead is sufficiently large, there is convergence to within a function approximation error"
  - [corpus]: Weak evidence - related papers mention function approximation but don't provide convergence proofs for trajectory-based methods
- Break condition: If feature vectors are insufficiently expressive, approximation error δ_app remains large

## Foundational Learning

- Concept: Contraction mappings and Banach fixed-point theorem
  - Why needed here: The proof relies on showing the Bellman operator with lookahead is a contraction, which guarantees convergence to a unique fixed point
  - Quick check question: What is the contraction factor for the H-step lookahead Bellman operator, and how does it depend on the discount factor α and lookahead depth H?

- Concept: Stochastic approximation and averaging
  - Why needed here: The algorithm uses noisy Monte Carlo estimates with diminishing stepsizes; convergence requires showing the noise averages out while the contraction drives iterates toward the optimal value
  - Quick check question: Why do we need square-summable stepsizes (∑γ_i^2 < ∞) in addition to summable stepsizes (∑γ_i = ∞)?

- Concept: Linear function approximation and projection
  - Why needed here: When extending to high-dimensional problems, we need to approximate value functions using feature vectors and understand how the projection affects convergence
  - Quick check question: How does the choice of feature vectors affect the approximation error δ_app, and what conditions ensure κ < 1 in the contraction analysis?

## Architecture Onboarding

- Component map:
  - Policy improvement: Compute H-step lookahead policy μ^{k+1} = argmin_μ T^H V_k
  - Policy evaluation: Generate trajectory under μ^{k+1}, compute returns T^m_{μk+1} T^{H-1} V_k + w_k for visited states
  - Value update: V_{k+1}(i) = (1-γ_k)V_k(i) + γ_k pk,μk(i)(T^m_{μk+1} T^{H-1} V_k(i) + w_k(i)) for i in visited set
  - Feature approximation (optional): Maintain θ_k ∈ R^d, compute E[Φθ_{μk+1}] using linear least squares or TD learning

- Critical path:
  1. Compute lookahead policy for states visited by trajectory
  2. Generate trajectory and compute returns
  3. Update value function estimates with appropriate weighting
  4. (Optional) Project onto feature space using linear approximation

- Design tradeoffs:
  - Lookahead depth H vs. computational cost: Larger H improves contraction but increases tree search complexity
  - Trajectory length m vs. estimation accuracy: Longer trajectories reduce sampling variance but increase computation
  - Feature dimension d vs. approximation quality: Higher dimensions can better approximate value functions but require more data

- Failure signatures:
  - Non-convergence: Check if α^H-1 + 2(1+α^m)α^H-1/(1-α) ≥ 1
  - Oscillations: Verify exploring starts condition and stepsize requirements
  - Large approximation error: Assess feature vector expressiveness and κ value

- First 3 experiments:
  1. Verify contraction property: Implement H-step lookahead Bellman operator and measure spectral radius for various H and α values
  2. Test trajectory-based convergence: Run policy iteration with lookahead on small MDPs, comparing convergence with and without lookahead
  3. Evaluate function approximation: Compare convergence rates using different feature representations and measure δ_app across various problem instances

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the lookahead depth H affect the convergence rate and approximation error in practical reinforcement learning applications?
- Basis in paper: [explicit] The paper states that "when α is very close to 1, which is often the case in practice, reducing the bound by a factor of 1/(1-α) significantly improves the performance of the algorithms" and shows bounds of order 1/(1-α)^(H-1)(1-α).
- Why unresolved: While the paper provides theoretical bounds, it doesn't empirically test different lookahead depths on real-world problems or benchmark datasets to quantify the practical impact.
- What evidence would resolve it: Empirical studies comparing convergence rates and final performance across different lookahead depths (H values) on standard RL benchmarks like Atari games or continuous control tasks.

### Open Question 2
- Question: What is the optimal trade-off between lookahead depth and Monte Carlo rollout length m for balancing computational cost and convergence quality?
- Basis in paper: [inferred] The paper analyzes both H (lookahead) and m (rollout length) separately but doesn't provide guidance on their joint optimization. The bounds involve terms like α^(H-1) and α^m.
- Why unresolved: The paper treats these parameters independently in its analysis without addressing how to jointly select them given computational constraints.
- What evidence would resolve it: Empirical or theoretical analysis showing the optimal ratio or relationship between H and m for different problem classes, or adaptive algorithms that adjust both parameters during training.

### Open Question 3
- Question: How do the convergence guarantees extend to non-tabular settings with continuous state spaces or high-dimensional observations?
- Basis in paper: [explicit] The paper extends results to linear function approximation but states "When the sizes of the state and action spaces are very large" and focuses on tabular settings for the main convergence proof.
- Why unresolved: The analysis relies on finite state spaces and doesn't address function approximation with nonlinear architectures like neural networks or handle continuous state spaces.
- What evidence would resolve it: Extension of the convergence analysis to nonlinear function approximation, or empirical validation of the algorithm's behavior with deep neural networks on continuous control problems.

## Limitations

- The convergence proof relies heavily on the exploring starts condition, which is often violated in practical implementations
- The lookahead depth requirement α^H-1 + 2(1+α^m)α^H-1/(1-α) < 1 may be difficult to satisfy for practical discount factors and MDP structures
- The function approximation extension assumes access to feature vectors that satisfy the contraction condition, but the paper doesn't specify how to construct such features for general problems

## Confidence

- High confidence in the lookahead-based contraction mechanism, as this follows directly from Bellman operator properties and stochastic approximation theory
- Medium confidence in the Monte Carlo trajectory-based evaluation claims due to the strong exploring starts assumption and lack of practical implementation discussion
- Low confidence in the function approximation extension due to the abstract nature of the feature vector requirements and lack of empirical validation
