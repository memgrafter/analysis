# A Sequence-to-Sequence&Set Model for Text-to-Table Generation

## Quick Facts
- arXiv ID: 2306.00137
- Source URL: https://arxiv.org/abs/2306.00137
- Authors: 
- Reference count: 5
- This paper proposes a sequence-to-sequence&set model that significantly outperforms baseline methods on text-to-table generation tasks by addressing order bias and error propagation through parallel body row generation.

## Executive Summary
This paper addresses the limitations of traditional sequence-to-sequence models for text-to-table generation, specifically order bias and error propagation. The authors propose a novel approach that first generates a table header as an ordered sequence, then generates table body rows in parallel as an unordered set. The model uses learnable row and column embeddings to enhance semantic consistency, and employs a bipartite matching strategy during training to align generated rows with target rows. Experimental results demonstrate state-of-the-art performance across multiple datasets, with improved F1 scores and inference efficiency compared to existing methods.

## Method Summary
The proposed sequence-to-sequence&set (Seq2Seq&set) model consists of three modules: a text encoder, a table header generator, and a table body generator. The text encoder (initialized with BART-base) processes input text. The table header generator produces an ordered header sequence, while the table body generator produces a set of table body rows in parallel using learnable row and column embeddings. During training, a bipartite matching strategy based on the first cells of generated and target rows is used to determine target assignments. The model is trained using a combined loss function that accounts for both header and body generation.

## Key Results
- Achieved state-of-the-art performance on multiple text-to-table datasets (Rotowire, E2E, WikiTableText, WikiBio)
- Demonstrated significant improvements in F1 scores compared to baseline sequence-to-sequence models
- Showed improved inference efficiency through parallel generation of table body rows
- Reduced error rate representing percentage of erroneous format tables

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Decomposing table generation into header + parallel body rows eliminates order bias.
- **Mechanism:** The model first generates a fixed-order table header, then generates body rows as a set in parallel using learnable row embeddings. This separates the order-sensitive header from the order-insensitive body rows.
- **Core assumption:** Table body rows can be generated in any order without affecting semantic quality.
- **Evidence anchors:**
  - [abstract] "the generation of most table body rows is order-insensitive"
  - [section] "experimental results show that these models exhibit similar performance"
  - [corpus] Weak - no direct corpus evidence; relies on controlled reordering experiments
- **Break condition:** If table body rows contain implicit ordering (e.g., chronological events), this mechanism fails.

### Mechanism 2
- **Claim:** Bipartite matching between first cells resolves row-to-target correspondence ambiguity.
- **Mechanism:** During training, the model generates first cells of each body row, then uses Hungarian algorithm to match them to target rows, ensuring unique supervision signals.
- **Core assumption:** First cells uniquely identify rows and contain sufficient information for matching.
- **Evidence anchors:**
  - [abstract] "we propose a target assignment strategy based on the bipartite matching between the first cells"
  - [section] "efficiently determine target assignments according to the matching results between the first cells"
  - [corpus] Weak - no corpus examples of matching quality or failure cases
- **Break condition:** If first cells are non-unique (e.g., multiple players named "John Smith"), matching becomes ambiguous.

### Mechanism 3
- **Claim:** Parallel generation with column embeddings reduces error propagation compared to autoregressive generation.
- **Mechanism:** Column embeddings provide shared context across cells in the same column, while parallel row generation means errors don't cascade through sequential predictions.
- **Core assumption:** Error propagation is worse in long autoregressive sequences than in parallel generation.
- **Evidence anchors:**
  - [abstract] "error propagation problem becomes serious when the model outputs a long token sequence"
  - [section] "our model is able to not only alleviate the order bias... but also reduce the effect of error propagation"
  - [corpus] Moderate - speedup evidence suggests parallel efficiency, but not direct error propagation measurement
- **Break condition:** If column dependencies are strong (e.g., dependent calculations), parallel generation may miss cross-row context.

## Architecture Onboarding

- **Component map:** Text Encoder -> Table Header Generator -> Table Body Generator -> Bipartite Matching Module
- **Critical path:** Input text → Text Encoder → Header Generator → Body Generator → Bipartite Matching → Loss calculation
- **Design tradeoffs:**
  - Parallel vs sequential generation: Speed vs potential loss of cross-row dependencies
  - First cell matching vs full-row matching: Efficiency vs matching accuracy
  - Fixed row count M vs dynamic row generation: Simplicity vs flexibility
- **Failure signatures:**
  - Repeated identical rows in output
  - Header-column mismatch in generated tables
  - Degraded performance on tables with strong row ordering
  - Training instability due to matching ambiguity
- **First 3 experiments:**
  1. Train without bipartite matching to observe performance degradation and verify matching necessity
  2. Test on tables with strong row ordering to measure impact on order-sensitive data
  3. Vary row embedding dimension to find optimal representation size for row distinction

## Open Questions the Paper Calls Out

The paper acknowledges several limitations and areas for future work:
1. Handling more complex table formats with merged cells
2. Reducing training time to match seq2seq baseline efficiency
3. Evaluating performance on more complex reasoning-intensive datasets like WebNLG

## Limitations

- The assumption that table body rows are order-insensitive may not hold for all table types, particularly those with temporal or hierarchical relationships
- The bipartite matching strategy's reliance on unique first cells may lead to incorrect supervision when first cells are non-unique
- The model is currently designed for ordinary tables and may struggle with more complex table formats involving merged cells
- Training time is longer compared to seq2seq baselines due to inherent instability in target assignments
