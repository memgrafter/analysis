# OVRL-V2: A simple state-of-art baseline for ImageNav and ObjectNav

## Quick Facts
- arXiv ID: 2303.07798
- Source URL: https://arxiv.org/abs/2303.07798
- Reference count: 40
- State-of-the-art ImageNav success rate improved from 54.2% to 82.0%

## Executive Summary
OVRL-V2 introduces a model-free navigation agent achieving state-of-the-art performance on both ImageNav and ObjectNav tasks using a general-purpose architecture. The key innovation is a compression layer over vision transformer patch representations that preserves spatial information, combined with visual pretraining using masked autoencoding. These modifications enable consistent improvements when scaling model size and address a reward-hacking issue in prior work, leading to improved path efficiency.

## Method Summary
OVRL-V2 employs a simple yet effective architecture combining vision transformers, convolutions, and LSTMs without task-specific modules. The critical innovation is a compression layer that processes ViT patch representations while preserving spatial information, outperforming [CLS] token or global average pooling approaches. Visual pretraining with masked autoencoding unlocks positive scaling laws for ViTs in visual navigation. The proposed reward function corrects potential reward-hacking issues present in prior work, resulting in more efficient navigation paths.

## Key Results
- ImageNav success rate improved from 54.2% to 82.0%
- Competitive ObjectNav performance with 64.0% success rate
- Positive scaling laws demonstrated for ViTs with visual pretraining
- Compression layer significantly outperforms [CLS] token and global average pooling

## Why This Works (Mechanism)
The compression layer preserves spatial information from ViT patch representations, enabling the model to maintain critical geometric relationships necessary for effective navigation. Visual pretraining with masked autoencoding provides rich feature representations that scale positively with model size, addressing the previous limitation where larger ViTs failed to improve navigation performance. The corrected reward function eliminates exploitation of reward loopholes, forcing the agent to learn genuinely efficient navigation strategies rather than gaming the reward system.

## Architecture Onboarding

Component Map:
Input RGB → ViT Backbone → Compression Layer → LSTM → Policy Network → Action Output

Critical Path:
ViT patches → Compression layer → LSTM → Action selection

Design Tradeoffs:
The choice between [CLS] token, global average pooling, and compression layer represents a fundamental tradeoff between simplicity and spatial information preservation. While [CLS] token and pooling are computationally simpler, they discard spatial relationships crucial for navigation. The compression layer adds complexity but maintains geometric awareness.

Failure Signatures:
- Degraded performance on spatially complex navigation tasks suggests compression layer inadequacy
- Poor generalization to novel environments indicates insufficient visual pretraining
- Inefficient paths may reveal reward function exploitation
