# Towards Flow Graph Prediction of Open-Domain Procedural Texts

## Quick Facts
- arXiv ID: 2305.19497
- Source URL: https://arxiv.org/abs/2305.19497
- Reference count: 10
- Primary result: Proposed flow graph prediction framework achieves 76.5%+ F1 for node prediction and 58.7%+ F1 for edge prediction in non-cooking domains

## Executive Summary
This paper introduces a flow graph prediction framework for open-domain procedural texts, extending beyond traditional recipe-based approaches to handle diverse domains. The authors create the wikiHow-FG corpus from wikiHow articles and demonstrate that domain adaptation from cooking recipes to target domains (electronics, plumbing) outperforms training solely on either domain, particularly in low-resource settings. The framework achieves strong performance metrics while addressing the challenge of predicting procedural text structures in open-domain scenarios.

## Method Summary
The authors propose a novel flow graph prediction framework that constructs directed graphs representing procedural text structures. The approach uses domain adaptation from cooking recipes to target domains under low-resource conditions, leveraging transfer learning to improve performance. The framework predicts both nodes (steps/actions) and edges (temporal/causal relationships) in procedural texts, with the wikiHow-FG corpus serving as the evaluation dataset. The model architecture combines sequence-to-graph prediction with domain adaptation techniques to handle the open-domain nature of procedural texts.

## Key Results
- Domain adaptation models outperform those trained only on cooking or target domain data
- Node prediction achieves 76.5% or more F1 in target domains
- Edge prediction achieves 58.7% or more F1 in target domains
- Low-resource domain adaptation setting shows significant performance improvements

## Why This Works (Mechanism)
The framework's success stems from leveraging transfer learning from the well-structured cooking domain to less-structured procedural domains. By learning rich representations of procedural steps and relationships from abundant cooking recipe data, the model can generalize to new domains with limited training examples. The flow graph representation captures both sequential and hierarchical relationships in procedural texts, while the domain adaptation component bridges the gap between cooking-specific language patterns and those found in other procedural domains.

## Foundational Learning

- Domain adaptation techniques - needed to transfer knowledge from cooking to other procedural domains; quick check: measure performance drop when removing adaptation layer
- Sequence-to-graph prediction - needed to convert linear procedural text into structured graph format; quick check: validate predicted graphs against human-annotated ground truth
- Cross-domain representation learning - needed to handle semantic differences between cooking and non-cooking procedural language; quick check: compare embedding similarity across domains

## Architecture Onboarding

Component map: Input Text -> Encoder -> Domain Adaptation Layer -> Node Predictor -> Edge Predictor -> Flow Graph Output

Critical path: The model processes procedural text through an encoder that generates contextual representations, passes them through a domain adaptation layer that transfers knowledge from cooking to target domains, then uses separate predictors for nodes and edges to construct the final flow graph. The domain adaptation layer is critical as it enables effective transfer learning from the cooking domain.

Design tradeoffs: The framework balances between domain-specific adaptation and general procedural understanding. Using cooking recipes as a source domain provides rich training data but may introduce domain-specific biases. The model must handle varying levels of resource availability in target domains while maintaining structural accuracy in predicted flow graphs.

Failure signatures: The model may struggle with domain-specific terminology not present in cooking recipes, produce incorrect temporal orderings in complex procedures, or fail to capture domain-specific action patterns. Edge prediction tends to be more error-prone than node prediction, particularly for non-temporal relationships.
