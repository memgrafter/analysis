# Constructing Tree-based Index for Efficient and Effective Dense Retrieval

## Quick Facts
- arXiv ID: 2304.11943
- Source URL: https://arxiv.org/abs/2304.11943
- Reference count: 40
- Primary result: JTR achieves state-of-the-art retrieval performance with significantly lower latency compared to baselines on MS MARCO datasets

## Executive Summary
This paper proposes JTR, a novel tree-based index for efficient dense retrieval that jointly optimizes both the tree structure and query encoder through unified contrastive learning. The method introduces overlapped clustering to allow documents to belong to multiple clusters, improving recall while maintaining efficiency. Experiments demonstrate that JTR outperforms traditional ANN baselines like IVFFlat, PQ, and HNSW on MS MARCO benchmarks while achieving significantly lower query processing times.

## Method Summary
JTR constructs a tree-based index by recursively clustering document embeddings using k-means, then jointly optimizes both the tree structure and query encoder through a unified contrastive learning loss. The method employs tree-based negative sampling by selecting brother nodes as negatives, and uses overlapped clustering to allow documents to appear in multiple leaf nodes (up to λ times). The unified contrastive loss directly optimizes cluster node embeddings using positive and negative samples from the tree structure itself, enabling end-to-end training of the index and encoder.

## Key Results
- JTR achieves new state-of-the-art retrieval performance on MS MARCO datasets
- Demonstrates significantly lower query processing latency compared to IVFFlat, PQ, and HNSW baselines
- Shows strong effectiveness-efficiency trade-off with optimal balance of recall and speed

## Why This Works (Mechanism)

### Mechanism 1
Joint optimization of tree structure and query encoder through unified contrastive learning loss improves retrieval performance. The unified contrastive learning loss directly optimizes cluster node embeddings using positive and negative samples derived from the tree structure itself, rather than relying on separate MSE loss for index structure and ranking loss for encoder.

### Mechanism 2
Tree-based negative sampling strategy improves performance by selecting semantically closer negative samples. Brother nodes of positive samples (nodes sharing the same parent) are selected as negative samples because they are closer in embedding space due to k-means clustering, making the contrastive learning task more challenging.

### Mechanism 3
Overlapped clustering allows documents to belong to multiple clusters, improving retrieval performance. Documents can appear in multiple leaf nodes (up to λ times), allowing them to be retrieved through different semantic paths and increasing recall.

  - Why needed here: Used to jointly optimize both query encoder and cluster node embeddings in an end-to-end manner

  - Why needed here: Ensures that the parent of the optimal node is also optimal at upper levels, supporting effective beam search
  - Quick check question: How does the maximum heap property relate to the effectiveness of beam search in tree-based retrieval?

- Concept: K-means clustering algorithm
  - Why needed here: Forms the basis of the tree structure by recursively clustering document embeddings
  - Quick check question: What are the limitations of using k-means for document clustering in information retrieval?

## Architecture Onboarding

- Component map: Query encoder → Unified contrastive loss → Tree structure (cluster nodes + assignments) → Retrieval (beam search)
- Critical path: Query encoding → Tree traversal (beam search) → Document ranking within selected leaf nodes
- Design tradeoffs: Balance between effectiveness (larger λ, b) and efficiency (smaller λ, b, shallower tree)
- Failure signatures: Poor MRR/R@100 scores despite fast query processing indicates effectiveness issues; slow query processing despite good scores indicates efficiency issues
- First 3 experiments:
  1. Verify tree construction with varying β and γ parameters on a small dataset
  2. Test unified contrastive learning loss vs separate losses on a validation set
  3. Evaluate overlapped clustering with different λ values on retrieval performance

## Open Questions the Paper Calls Out

### Open Question 1
How does the performance of JTR compare when using different query encoders (e.g., other transformer architectures) instead of BERT? The paper uses BERT as the query encoder but does not explore other architectures or compare their performance.

### Open Question 2
What is the impact of the overlapped clustering parameter λ on retrieval performance for different corpus sizes and query distributions? The paper explores λ values from 1 to 5 but does not investigate how this parameter scales with corpus size or different query distributions.

### Open Question 3
How does JTR perform on multilingual or cross-lingual retrieval tasks compared to existing ANN methods? The experiments are conducted only on English datasets (MS MARCO), with no evaluation of multilingual or cross-lingual capabilities.

## Limitations

- The paper lacks ablation studies isolating the contribution of individual components (unified loss, tree-based negative sampling, overlapped clustering)
- No comparison against more recent tree-based methods like SPANN or SPANN-quick that combine tree structures with inverted indexes
- Limited analysis of how tree depth affects performance, especially for the document retrieval task where the tree has only 2 levels

## Confidence

**High Confidence**: The effectiveness improvements over traditional baselines (IVFFlat, PQ, HNSW) are well-supported by experimental results on standard benchmarks.

**Medium Confidence**: The claimed advantages of joint optimization and overlapped clustering are theoretically sound but lack extensive ablation studies to isolate their individual contributions.

**Low Confidence**: The assertion that tree-based negative sampling always provides better semantic coverage needs empirical validation across diverse datasets and domains.

## Next Checks

1. Implement ablation studies to quantify the individual contributions of unified contrastive learning, tree-based negative sampling, and overlapped clustering
2. Test JTR on passage retrieval benchmarks with much larger collections (e.g., Natural Questions) to evaluate scalability beyond MS MARCO
3. Compare JTR against hybrid tree-inverted index methods to establish its position in the current state-of-the-art landscape
