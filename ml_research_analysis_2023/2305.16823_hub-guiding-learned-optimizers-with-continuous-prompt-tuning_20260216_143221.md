# HUB: Guiding Learned Optimizers with Continuous Prompt Tuning

## Quick Facts
- **arXiv ID**: 2305.16823
- **Source URL**: https://arxiv.org/abs/2305.16823
- **Reference count**: 40
- **Key outcome**: Hybrid-update-based (HUB) optimization strategy improves learned optimizers by 94% of cases across 17 tasks

## Executive Summary
This paper addresses limitations of learned optimizers (e.g., VeLO) including unstable training curves, poor fine-tuning performance, and difficulty generalizing to unseen architectures. The authors propose a hybrid-update-based (HUB) optimization strategy inspired by continuous prompt tuning techniques. HUB combines outputs of learned and hand-designed optimizers using a gradient-based weighting matrix that adapts to per-parameter gradient magnitudes. This allows leveraging stability from hand-designed rules and exploration capability from learned models. Extensive experiments show HUB outperforms all baselines in 94% of cases with improved testing accuracy and robustness.

## Method Summary
HUB is a hybrid optimization strategy that computes a weighting matrix using softmax over absolute gradient values within each layer. This weighting matrix determines how much influence each optimizer (learned and hand-designed) has on parameter updates. Parameters with small gradients receive more weight from the learned optimizer, while parameters with large gradients receive more weight from the hand-designed optimizer. For fine-tuning tasks, the weighting can be inverted to preserve pre-trained weights while allowing exploration of unstable parameters. The method is designed to be easily applied to any task involving hand-designed or learned optimizers.

## Key Results
- HUB outperforms all baselines in 94% of tested cases across 17 tasks (13 from-scratch and 4 fine-tuning)
- Testing accuracy and robustness improved compared to pure learned optimizers
- Successfully extends VeLO to situations where it previously failed to converge, such as fine-tuning tasks
- Theoretical analysis shows HUB mitigates instability by reducing weight on poorly performing parameters

## Why This Works (Mechanism)

### Mechanism 1
- Claim: HUB stabilizes learned optimizers by adaptively combining them with hand-designed optimizers based on per-parameter gradient magnitudes.
- Mechanism: The HUB strategy computes a weighting matrix σ(g(t)) using softmax over absolute gradient values within each layer. Parameters with small gradients (likely near local minima) get more weight from the learned optimizer UL, while parameters with large gradients (needing careful descent) get more weight from the hand-designed optimizer UH.
- Core assumption: Gradient magnitude within a layer correlates with the parameter's optimization state - small gradients indicate proximity to local minima where learned optimizers excel, while large gradients indicate regions where hand-designed optimizers provide stability.
- Evidence anchors:
  - [abstract] "This approach can be easily applied to any task that involves hand-designed or learned optimizer. By incorporating hand-designed optimizers as the second component in our hybrid approach, we are able to retain the benefits of learned optimizers while stabilizing the training process and, more importantly, improving testing performance."
  - [section 3.2] "Based on this conclusion, we choose to evaluate the gradient value of each parameter within the same layer. Specifically, we apply the softmax function to the absolute value of the gradient matrix in each layer and generate a hybrid reference weighting matrix for the corresponding update matrix."
- Break condition: If gradient magnitudes no longer correlate with optimization state (e.g., in highly non-convex landscapes with pathological gradient patterns), the adaptive weighting may misallocate trust between optimizers.

### Mechanism 2
- Claim: HUB mitigates instability in learned optimizers by reducing weight on poorly performing parameters during optimization.
- Mechanism: When the learned optimizer makes poor decisions (causing loss to increase), the gradient magnitude for affected parameters increases. The softmax weighting then shifts more weight toward the hand-designed optimizer for these parameters, effectively overriding the learned optimizer's mistakes.
- Core assumption: Learned optimizer instability manifests as parameter updates that increase loss, which in turn produces large gradients that the HUB mechanism can detect and correct.
- Evidence anchors:
  - [abstract] "Theoretical analysis reveals that HUB can mitigate instability in learned optimizers by reducing weight on poorly performing parameters."
  - [section 3.3] "In the later stages of training, VeLO experiences a rapid increase in loss, indicating potential instability that can negatively impact the optimization process. Upon careful observation of the HUB method, we notice that its curve exhibits numerous smaller bumps after 5000 steps. This indicates that the HUB method also experiences sudden changes in gradient but manages to return to the vicinity of the previous local minimum value within a short number of steps."
- Break condition: If the learned optimizer's instability doesn't manifest as increased loss or if the gradient magnitude changes don't accurately reflect optimization quality.

### Mechanism 3
- Claim: HUB enables learned optimizers to handle fine-tuning tasks by preserving pre-trained weights while allowing exploration of unstable parameters.
- Mechanism: For fine-tuning tasks, HUB can invert the weighting matrix, giving more weight to the learned optimizer for parameters with large gradients (unstable parameters needing adjustment) while preserving stable pre-trained parameters through the hand-designed optimizer.
- Core assumption: Fine-tuning requires preserving most pre-trained parameters while allowing exploration of parameters that need adjustment to bridge domain gaps.
- Evidence anchors:
  - [abstract] "poor performance in fine-tuning tasks impede their widespread adoption" and "successfully extend VeLO to situations where it previously failed to converge (such as fine-tuning tasks)"
  - [section C.1] "Unlike training from scratch, here we aim to avoid disturbing pre-trained weights and biases, so we rely on learned optimizers for unstable parameters with higher gradients in this case."
- Break condition: If the distinction between stable and unstable parameters during fine-tuning isn't well-captured by gradient magnitude, or if pre-trained weights require more nuanced preservation strategies.

  - Quick check question: Given gradient magnitudes [2, 5, 3] for three parameters in a layer, what would be the approximate softmax weights for each parameter?

  - Why needed here: Understanding how optimizers use gradients to update parameters is fundamental to grasping why HUB's adaptive weighting approach works.
  - Quick check question: In standard gradient descent, how does the update direction relate to the gradient vector, and why might this be problematic in non-convex optimization?

  - Why needed here: VeLO uses LSTMs as part of its architecture, and understanding their gating nature helps explain why learned optimizers might exhibit instability.

## Architecture Onboarding

- Component map:
  - Target model parameters (θ) → gradient computation → loss function
  - Gradient matrix (g(t)) → HUB weighting computation (σ(g(t)))
  - HUB output: weighted combination of UH(g(t), θH) and UL(g(t), θL)
  - HUB output → parameter update → new model state
  - Two optimizer states maintained: learned optimizer state and hand-designed optimizer state

- Critical path: Parameter update loop where HUB computes hybrid updates at each optimization step, requiring gradient computation, weighting matrix calculation, and weighted combination of both optimizers' outputs.

- Design tradeoffs:
  - HUB adds computational overhead per step due to weighting matrix computation and dual optimizer evaluation
  - The adaptive approach trades some of the learned optimizer's exploration capability for stability
  - Different tasks may benefit from different HUB variations (standard vs. inverted weighting)

- Failure signatures:
  - HUB performance degrades when gradient magnitudes don't correlate with optimization quality
  - For extremely wide networks, the softmax weighting may approach uniform distribution, reducing HUB's effectiveness
  - In fine-tuning tasks, incorrect weighting inversion may either over-disturb pre-trained weights or fail to adjust necessary parameters

- First 3 experiments:
  1. Implement HUB with Adam and VeLO on a simple MLP training task, comparing convergence curves and final performance against each optimizer alone
  2. Test HUB's stability on a synthetic optimization problem with known local minima to verify the stability mechanism
  3. Apply inverted weighting HUB to a fine-tuning task to verify its ability to preserve pre-trained weights while allowing necessary adjustments

## Open Questions the Paper Calls Out
- How to effectively leverage prior knowledge encoded in optimization rules designed by humans through guided training of learned optimizers
- The theoretical upper bound on improvement that HUB can provide over pure learned optimizers
- How HUB's performance scales with increasing model size and complexity beyond tested architectures

## Limitations
- The method assumes gradient magnitude correlates with optimization state, which may break down in highly non-convex landscapes
- Maintaining two separate optimizer states becomes computationally prohibitive for extremely large models
- Limited systematic study of sensitivity to different hand-designed optimizers and their hyperparameters

## Confidence
- **High confidence**: HUB's ability to improve stability and performance over pure learned optimizers on training-from-scratch tasks
- **Medium confidence**: HUB's effectiveness on fine-tuning tasks (limited testing with specific inversion strategy required)
- **Medium confidence**: The theoretical mechanism explaining how gradient-based weighting mitigates learned optimizer instability
