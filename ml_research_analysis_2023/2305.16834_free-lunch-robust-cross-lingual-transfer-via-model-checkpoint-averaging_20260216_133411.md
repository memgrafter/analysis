# Free Lunch: Robust Cross-Lingual Transfer via Model Checkpoint Averaging

## Quick Facts
- arXiv ID: 2305.16834
- Source URL: https://arxiv.org/abs/2305.16834
- Authors: 
- Reference count: 40
- One-line primary result: Checkpoint averaging consistently improves cross-lingual transfer robustness without requiring target language validation data

## Executive Summary
This paper addresses the overestimation of cross-lingual transfer performance in zero-shot and few-shot setups, where models are often evaluated at checkpoints that best generalize to target language validation data, violating true XLT assumptions. The authors propose a simple method of checkpoint averaging (CA) that averages model snapshots during task fine-tuning, improving robustness and performance without requiring target language validation data. CA consistently yields performance gains across diverse target languages in both higher-level semantic tasks (NLI, extractive QA) and lower-level token classification tasks (NER, POS), while also desensitizing XLT to varying hyperparameters.

## Method Summary
The method involves fine-tuning a multilingual model on source language task data while periodically saving checkpoints. These checkpoints are then averaged to create a single averaged model (CA), or averaged across multiple independent runs (RA), or combined both (RA-CA). The approach works by smoothing out idiosyncratic variations in parameter trajectories that arise from stochastic optimization, effectively denoising learned representations and improving generalization across target languages. For RA, classifiers are frozen from an initial run to ensure trajectory alignment across runs, creating a more effective ensemble.

## Key Results
- Checkpoint averaging (CA) yields systematic and consistent performance gains across diverse target languages in all tested tasks
- CA reduces variance in results between runs with different learning rates and within runs with the same learning rate
- In few-shot cross-lingual transfer (FS-XLT), CA most often surpasses oracle target-language validation selection (TRG-DEV) since all target languages are included in training

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Checkpoint averaging reduces variance in model performance across runs and learning rates, leading to more robust zero-shot and few-shot cross-lingual transfer (XLT)
- Mechanism: By averaging model snapshots from multiple training steps, CA smooths out idiosyncratic variations in parameter trajectories that arise from stochastic optimization, effectively denoising the learned representations and improving generalization across target languages
- Core assumption: The variation between checkpoints is primarily noise rather than systematic divergence in useful features; averaging preserves useful signal while averaging out noise
- Evidence anchors: [abstract] "The results indicate that averaging model checkpoints yields systematic and consistent performance gains across diverse target languages in all tasks"; [section] "In comparison with SRC-DEV, CA reduces the variance in results between runs with different learning rates as well within different runs with the same rate for both tasks"
- Break condition: If checkpoints diverge too much in functional behavior (e.g., early stopping before convergence or severe mode collapse), averaging could degrade performance by combining incompatible models

### Mechanism 2
- Claim: Run averaging (RA) with frozen classifiers aligns parameter trajectories across runs, enabling effective ensemble gains in XLT
- Mechanism: Freezing classifiers from an initial run ensures that subsequent runs start from a shared classifier initialization, forcing Transformer "body" parameters to align across runs and complement each other in ensemble
- Core assumption: Random initialization of classifiers causes runs to converge to orthogonal solutions, so freezing them prevents this divergence and allows meaningful averaging
- Evidence anchors: [section] "We suspect that the different random-uniform initialized classifiers from different runs draw models into unrelated training trajectories... We address this shortcoming in two steps... freeze all the classifiers of the R models to the parameters to which the initial run converged"; [abstract] "We also show that checkpoint averaging benefits performance when further combined with run averaging"
- Break condition: If the task is simple enough that a single run already saturates performance (e.g., POS tagging), or if classifier freezing overly constrains model capacity, gains may be minimal or negative

### Mechanism 3
- Claim: CA in FS-XLT outperforms oracle target-language validation selection (TRG-DEV) because all target languages are included in training, making averaged checkpoints more representative of the multilingual task distribution
- Mechanism: In FS-XLT, each run incorporates few-shot target-language data, so averaging checkpoints captures a more stable and diverse representation of the multilingual space than selecting a single best checkpoint for each language individually
- Core assumption: Including target-language shots in training aligns model representations sufficiently across languages that averaging checkpoints yields better transfer than cherry-picking per-language checkpoints
- Evidence anchors: [section] "Unlike in ZS-XLT, in FS-XLT CA most often surpasses the oracle TRG-DEV, since all target languages (with few shots) are now part of training"; [abstract] "Importantly, it simultaneously substantially desensitizes XLT to varying hyperparameter choices in the absence of target language validation"
- Break condition: If target-language shots are extremely few or highly noisy, averaging may dilute useful language-specific adaptation

## Architecture Onboarding

- Component map: Multilingual pretrained model (XLM-R base) -> fine-tuning loop with periodic checkpoint saving -> optional classifier freezing for RA -> checkpoint averaging -> inference
- Critical path: 1) Load pretrained MMT and task-specific head; 2) Fine-tune on source language data, saving checkpoints at regular intervals; 3) If doing RA: run additional fine-tuning with frozen classifiers, saving checkpoints; 4) Average saved checkpoints (within-run for CA, across runs for RA); 5) Evaluate averaged model on target language data
- Design tradeoffs: Checkpoint frequency vs. memory (saving every epoch is simple but may miss optimal intermediate states; more frequent saves increase robustness but memory cost); Classifier freezing in RA (ensures alignment but may limit adaptation; skipping it risks orthogonal solutions); Averaging vs. ensembling (averaging is parameter-efficient; ensembling with voting can be more robust but requires storing multiple full models)
- Failure signatures: Degraded performance if checkpoints are saved too early (underfit) or too late (overfit); Poor RA gains if classifiers diverge significantly across runs (fix by freezing); Inconsistent results if learning rates or batch sizes vary too widely without averaging
- First 3 experiments: 1) Implement CA on a single XNLI run: save checkpoints every epoch, average, compare to LAST and SRC-DEV; 2) Add classifier freezing: run RA-CA with 5 seeds, compare to RA-LAST and single-run CA; 3) Vary learning rates: train with {1e-5, 2e-5, 3e-5}, apply CA, measure variance reduction vs. SRC-DEV

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the effectiveness of checkpoint averaging (CA) vary across different types of tasks (e.g., classification vs. structured prediction) and what are the underlying reasons for any observed differences?
- Basis in paper: [explicit] The paper discusses CA performance across various tasks (NLI, QA, NER, POS) but doesn't provide a detailed comparative analysis of why CA might work better for some tasks than others
- Why unresolved: The paper presents overall performance gains but lacks a deeper investigation into task-specific mechanisms behind CA's effectiveness
- What evidence would resolve it: Systematic analysis comparing CA's impact on different task architectures, sequence lengths, and output structures would clarify its varying effectiveness

### Open Question 2
- Question: What is the optimal strategy for selecting checkpoints to average, and how does this selection impact CA's performance in zero-shot and few-shot cross-lingual transfer?
- Basis in paper: [explicit] The authors mention they use a straightforward CA strategy without exploring more sophisticated checkpoint selection methods, acknowledging this as a potential area for improvement
- Why unresolved: The paper focuses on simple CA implementations and doesn't investigate more advanced checkpoint selection strategies that could potentially enhance performance
- What evidence would resolve it: Comparative studies of different checkpoint selection methods (e.g., based on validation performance, gradient norms, or other criteria) would determine the optimal approach

### Open Question 3
- Question: How does checkpoint averaging interact with different multilingual model architectures (e.g., mBERT, XLM-R, mT5) and pretraining objectives, and are there specific model characteristics that make CA more or less effective?
- Basis in paper: [explicit] The experiments primarily use XLM-R, with preliminary validation on other models, but don't provide a comprehensive analysis of CA's interaction with different model architectures
- Why unresolved: The paper's focus on a single model architecture limits understanding of CA's generalizability across different multilingual models and pretraining approaches
- What evidence would resolve it: Extensive experiments comparing CA's effectiveness across various multilingual models with different architectures and pretraining objectives would reveal architectural dependencies

## Limitations
- The benefits of checkpoint averaging are evaluated primarily through relative performance gains rather than absolute metrics, making practical significance difficult to assess
- The optimal checkpoint selection strategy remains unexplored, with the paper using simple periodic saving without investigating adaptive selection methods
- Computational overhead of saving and averaging multiple checkpoints is not quantified, which could be significant for large models or resource-constrained scenarios

## Confidence
- **High Confidence**: The claim that checkpoint averaging improves robustness to hyperparameter choices (learning rate, batch size) is well-supported by experimental results showing reduced variance across runs with different settings
- **Medium Confidence**: The assertion that RA-CA outperforms single-run CA in most settings is supported by results, but the underlying mechanism (classifier freezing ensuring trajectory alignment) is somewhat speculative
- **Medium Confidence**: The claim that FS-XLT CA outperforms oracle TRG-DEV is empirically demonstrated but relies on the specific experimental setup where target languages are included in training with few shots

## Next Checks
1. **Ablation on checkpoint selection strategy**: Compare periodic checkpoint averaging against selection based on validation performance or training dynamics (e.g., averaging only checkpoints from periods of stable loss improvement). This would clarify whether the benefits come from the averaging mechanism itself or from implicitly selecting good checkpoints.

2. **Resource overhead quantification**: Measure and report the additional computational cost (storage, memory, training time) of checkpoint averaging compared to single-model selection. This would provide practical guidance for deployment decisions, especially for larger models or constrained environments.

3. **Cross-task generalization**: Test checkpoint averaging on middle-level semantic tasks such as semantic parsing or structured prediction that involve both token-level and sequence-level decisions. This would validate whether the observed benefits generalize beyond the higher-level semantic and lower-level token classification tasks examined in the current work.
