# Curriculum Modeling the Dependence among Targets with Multi-task Learning for Financial Marketing

## Quick Facts
- arXiv ID: 2305.01514
- Source URL: https://arxiv.org/abs/2305.01514
- Reference count: 21
- Primary result: PIMM achieves significant AUC improvements over baselines in modeling sequential task dependencies for financial marketing

## Executive Summary
This paper introduces PIMM (Prior Information Merged Model), a novel multi-task learning architecture designed to address error accumulation in sequential task prediction. The core innovation is a curriculum learning strategy that dynamically adjusts the sampling probability of prior information during training, transitioning from ground truth labels to predicted probabilities. PIMM explicitly models logical dependencies among tasks in online marketing scenarios, achieving state-of-the-art performance on both public (Ali-CCP) and industrial datasets. The approach demonstrates significant improvements in core conversion rates in real-world deployment within a large-scale FinTech platform.

## Method Summary
PIMM employs a multi-task learning framework with task-specific towers, self-attention layers, and Prior Information Merged (PIM) modules. The PIM modules use curriculum learning to select either true labels or predicted probabilities as explicit premise information for downstream tasks, gradually transitioning from ground truth to predictions as training progresses. The model combines implicit task-specific representations from tower networks with explicit prior information, using self-attention to create task-specific outputs. Training uses the Adam optimizer with learning rates swept over {0.0005, 0.001, 0.0015, 0.002}.

## Key Results
- PIMM outperforms state-of-the-art baselines (shared-bottom, MMoE, ESMM, PLE, AITM, MNCM) on both Ali-CCP and industrial datasets in terms of AUC metrics
- Online experiments show 2.73% CTR increase, 3.82% CVR increase, and 2.01% core conversion rate increase compared to baseline
- Curriculum learning strategy effectively mitigates error accumulation in sequential task prediction

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Curriculum learning strategy gradually transitions from ground truth labels to predicted probabilities to mitigate error accumulation in sequential multi-task learning
- Mechanism: At the beginning of training, PIM selects true labels with high probability to provide accurate prior information to downstream tasks. As training progresses and model predictions improve, PIM gradually shifts to selecting predicted probabilities, aligning training and inference distributions
- Core assumption: Early-stage predictions are unreliable and can harm downstream tasks, but become increasingly accurate as training converges
- Evidence anchors:
  - [abstract]: "we dynamically adjust the sampling probability to ensure that the downstream task will get the effective information along with the training"
  - [section 2.3]: "At the beginning of training, p is a large value and gradually decreases as the training process advances until p reaches the set lower limit"

### Mechanism 2
- Claim: Explicit premise information (true label or predicted probability) is merged with implicit task-specific representations to capture both logical dependence and task-specific knowledge
- Mechanism: PIM module transforms selected explicit information into a d-dimensional vector and adds it to the implicit representation from the former task's tower network, creating enriched prior information for downstream tasks
- Core assumption: Both explicit logical dependencies and implicit task-specific knowledge are valuable for modeling sequential task relationships
- Evidence anchors:
  - [section 2.3]: "To leverage the explicit premise information from the former task, a naive idea is directly transferring the predicted result of (t-1)-th task"
  - [section 2.3]: "PIM first calculates the sampling probability p according to the current training step"

### Mechanism 3
- Claim: Self-attention mechanism combines tower-specific representations with prior information merged representations to create task-specific outputs
- Mechanism: For each task except the first, PIMM uses self-attention to weigh the tower output and the prior information merged representation, creating a weighted sum that forms the final task representation
- Core assumption: The combination of tower-specific features and prior information provides better task representations than either alone
- Evidence anchors:

## Foundational Learning

- Concept: Curriculum learning
  - Why needed here: The sequential dependence among tasks creates error accumulation, and curriculum learning provides a principled way to gradually introduce more challenging (predicted) information as the model becomes more reliable
  - Quick check question: Why not use predicted probabilities from the start, or always use true labels?

- Concept: Multi-task learning with task dependencies
  - Why needed here: The sequential nature of user behavior (impression → click → conversion) requires modeling logical dependencies between tasks, not just learning them independently
  - Quick check question: How does this differ from standard multi-task learning where tasks are assumed independent?

- Concept: Error accumulation in sequential prediction
  - Why needed here: Downstream tasks in sequential paths suffer from errors propagated from upstream tasks, requiring mitigation strategies like curriculum learning
  - Quick check question: What would happen if we didn't address error accumulation in this sequential setting?

## Architecture Onboarding

- Component map: Shared Embedding -> Task-specific Towers -> PIM Modules -> Self-attention -> Output Layer
- Critical path: Input → Shared Embedding → Task Towers → PIM Modules → Self-attention → Output Layer
  - The PIM modules and self-attention layers are the key innovations that distinguish this architecture
- Design tradeoffs:
  - Curriculum learning parameters (initial probability, decrease rate, lower limit) require tuning and may need task-specific adjustment
  - The additional complexity of PIM modules increases computational overhead but provides better modeling of task dependencies
  - Gradient truncation in PIM prevents affecting upstream task learning but may limit information flow
- Failure signatures:
  - Poor performance on early tasks with good performance on later tasks: curriculum parameters may be too conservative
  - Degradation in performance when removing true labels entirely: curriculum transition may be too aggressive
  - Similar performance to baseline models: PIM modules may not be effectively capturing dependencies
- First 3 experiments:
  1. Compare performance with fixed sampling probability (no curriculum) vs. curriculum learning to isolate the curriculum effect
  2. Test with true labels only vs. predicted probabilities only to establish baseline performance levels
  3. Vary the transition speed in curriculum learning to find optimal balance between stability and adaptation

## Limitations

- Evaluation limited to binary sequential tasks in marketing/finance contexts, with unknown performance on more complex task dependencies or non-binary tasks
- Curriculum learning parameters presented as fixed values without sensitivity analysis, raising questions about generalizability
- Computational overhead from PIM modules and attention layers not quantified, particularly for real-time inference in production systems

## Confidence

**High Confidence**: The architectural design of PIMM with PIM modules and the theoretical motivation for curriculum learning in sequential task settings are well-founded. The mathematical formulation and component descriptions are clear and implementable.

**Medium Confidence**: The empirical results showing AUC improvements over baselines are convincing within the tested datasets, but the generalizability to other domains and task structures requires further validation.

**Low Confidence**: The claims about online experiment improvements (2.73% CTR increase, 3.82% CVR increase, 2.01% core conversion rate increase) lack statistical significance testing and detailed methodology description for the online deployment.

## Next Checks

1. **Cross-domain validation**: Test PIMM on sequential task datasets from non-marketing domains (e.g., healthcare diagnosis with sequential symptoms → disease → treatment response) to assess generalizability beyond financial marketing applications

2. **Curriculum parameter sensitivity**: Conduct ablation studies varying the curriculum learning parameters (initial probability, decrease rate, lower limit) to identify optimal ranges and determine if these are task-specific or transferable

3. **Computational overhead analysis**: Measure inference latency and resource utilization of PIMM compared to baseline models in production-like environments to quantify the practical trade-offs of the improved accuracy
