# Task2KB: A Public Task-Oriented Knowledge Base

## Quick Facts
- arXiv ID: 2302.00654
- Source URL: https://arxiv.org/abs/2302.00654
- Reference count: 4
- Primary result: Automated extraction of comprehensive task information from WikiHow to create a general-purpose task-oriented knowledge base

## Executive Summary
Task2KB is a novel knowledge base constructed from WikiHow data to support task-oriented conversational systems. The key contribution is an automated method for extracting comprehensive task information including methods, sub-tasks, slot names, quality scores, and auxiliary attributes like tips and reviews. The knowledge base covers 44,831 task documents across Food/Entertainment, Travel, Holiday, and Health domains. Task2KB provides an API enabling retrieval of relevant tasks from text descriptions and detailed task information including slot names and sub-tasks. The approach addresses the limitation of existing task datasets that have limited domain coverage, enabling development of general-purpose task completion assistants.

## Method Summary
Task2KB is constructed by crawling WikiHow articles from four domains (Food/Entertainment, Travel, Holiday, Health) totaling 44,831 documents. The system extracts structured task information including methods, sub-tasks, slot names, quality scores, and auxiliary attributes. Quality estimation uses seven features (recency, normalized views, normalized votes, introduction, summary, description, and step information) processed through BERT and LongFormer models with a convolutional neural network. Slot names are automatically extracted by identifying entities in task descriptions, collecting Wikipedia attributes for these entities, and selecting top-K similar attributes based on BERT embeddings. The resulting knowledge base is accessible through an API supporting task retrieval from text descriptions and detailed task information queries.

## Key Results
- Successfully constructed a task-oriented knowledge base from 44,831 WikiHow articles across four domains
- Automated extraction of comprehensive task information including methods, sub-tasks, slot names, and quality scores
- Developed quality estimation methodology using multi-modal features processed through BERT/LongFormer models
- Created API enabling retrieval of relevant tasks from text descriptions with detailed task information

## Why This Works (Mechanism)

### Mechanism 1
WikiHow's instructional articles provide rich, structured task information that can be systematically extracted into a knowledge base. The knowledge base construction extracts methods, sub-tasks, slot names, quality scores, and auxiliary attributes (tips, reviews) from WikiHow articles through automated processing. This works because WikiHow articles contain sufficient structure and metadata to enable automated extraction of task-oriented information.

### Mechanism 2
Quality estimation using multi-modal features improves the reliability of task articles in the knowledge base. Quality scores are computed using seven types of features including recency, normalized views, normalized votes, introduction, summary, description, and step information, processed through BERT and LongFormer models. This approach assumes these seven features collectively represent the quality and usefulness of task articles.

### Mechanism 3
Automated slot name extraction from Wikipedia attributes enables scalable task representation for conversational systems. For each task, entities are extracted from descriptions, Wikipedia attributes are collected for these entities, and top-K similar attributes based on cosine similarity are used as slot names. This mechanism assumes Wikipedia attributes are semantically relevant to task requirements and can be effectively matched using embeddings.

## Architecture Onboarding

- **Component map:**
  Web crawler → Article parser → Quality estimator → Slot extractor → Knowledge base storage → API server → Client interface
  Quality estimator uses BERT for short text and LongFormer for long step descriptions
  Slot extractor uses Wikipedia API for attribute lookup and BERT for embedding similarity

- **Critical path:**
  Crawling WikiHow articles → Parsing structured content → Computing quality scores → Extracting slot names → Storing in knowledge base → Enabling API access
  Any failure in crawling or parsing blocks the entire pipeline

- **Design tradeoffs:**
  Coverage vs quality: Crawling more domains increases coverage but may reduce average quality
  Automation vs accuracy: Fully automated slot extraction may miss domain-specific nuances
  API simplicity vs feature richness: Simpler APIs are easier to use but may lack advanced filtering options

- **Failure signatures:**
  Crawling failures: Incomplete knowledge base with missing domains
  Parsing errors: Broken task structures with missing methods or steps
  Quality estimation drift: Declining quality scores over time
  Slot extraction failures: Missing or irrelevant slots for certain tasks

- **First 3 experiments:**
  1. Verify crawling by checking the count and distribution of articles across the four initial domains
  2. Test quality estimation by comparing scores of known high-quality vs low-quality articles
  3. Validate slot extraction by manually reviewing slot assignments for sample tasks from different domains

## Open Questions the Paper Calls Out

- **How does the quality estimation model perform in terms of precision and recall for identifying high-quality task articles compared to human judgments?**
  - Basis: The paper mentions using a deep neural model with multiple convolutional layers for article quality prediction but does not report performance metrics or validation against human judgments.
  - Why unresolved: The paper lacks quantitative evaluation of the quality estimation model's accuracy and reliability.
  - What evidence would resolve it: Experimental results showing precision, recall, F1-score, or other metrics comparing the model's predictions to human-labeled quality scores.

- **What is the optimal value of K (number of top attributes) for identifying slot names that balances comprehensiveness with precision?**
  - Basis: The paper mentions using top K similar attributes as slot names but does not specify how K was chosen or what value provides the best trade-off between coverage and relevance.
  - Why unresolved: The selection of K is presented as a parameter without justification or empirical validation of its impact on slot name quality.
  - What evidence would resolve it: Ablation studies or sensitivity analysis showing how different K values affect slot name accuracy and usefulness.

- **How does Task2KB's coverage and quality compare to domain-specific task knowledge bases in terms of task diversity and practical utility?**
  - Basis: The paper claims Task2KB has higher coverage than existing related knowledge graphs but does not provide comparative analysis or benchmarks.
  - Why unresolved: The paper makes claims about superiority without empirical comparison to other task-oriented knowledge bases.
  - What evidence would resolve it: Comparative studies measuring coverage metrics, task diversity indices, and user studies evaluating practical utility against established domain-specific knowledge bases.

## Limitations

- The knowledge base construction relies heavily on WikiHow's structure remaining stable, with potential vulnerability to website changes or paywalls that could break automated crawling
- Automated slot extraction from Wikipedia attributes may miss domain-specific nuances and could fail if Wikipedia's attribute structure changes
- Quality estimation depends on specific feature combinations and model architectures that may not generalize well if article quality signals change over time

## Confidence

- **High confidence**: The general approach of extracting structured task information from WikiHow articles is well-supported by the evidence
- **Medium confidence**: The quality estimation methodology using multi-modal features is sound, but specific model details are underspecified
- **Low confidence**: The automated slot extraction method's effectiveness across diverse domains is not fully validated
