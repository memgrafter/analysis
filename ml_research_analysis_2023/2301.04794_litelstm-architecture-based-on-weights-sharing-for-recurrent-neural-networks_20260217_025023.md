# LiteLSTM Architecture Based on Weights Sharing for Recurrent Neural Networks

## Quick Facts
- arXiv ID: 2301.04794
- Source URL: https://arxiv.org/abs/2301.04794
- Reference count: 40
- Reduces LSTM parameters by ~33% while maintaining accuracy on multiple tasks

## Executive Summary
This paper introduces LiteLSTM, a lightweight recurrent neural network architecture that addresses the computational burden of standard LSTM models. By sharing weights between gates (inspired by GRU) while retaining the memory cell and peephole connections, LiteLSTM achieves approximately one-third fewer trainable parameters without sacrificing performance. The architecture is particularly suited for resource-constrained environments where traditional LSTM models are impractical.

## Method Summary
LiteLSTM modifies the standard LSTM architecture by implementing weight sharing among the input, forget, and output gates, similar to the approach used in GRU networks. This architectural change reduces the number of trainable parameters by approximately one-third while maintaining the memory cell structure and peephole connections that prevent vanishing/exploding gradients. The model preserves LSTM's ability to capture long-term dependencies while improving computational efficiency, making it suitable for deployment on devices with limited processing power and memory.

## Key Results
- Achieves 96.07% accuracy on MNIST handwritten digit classification
- Delivers 99.60% accuracy for binary classification on IEEE IoT Network Intrusion Dataset
- Obtains 95.989% accuracy on TESS speech emotion recognition task

## Why This Works (Mechanism)
LiteLSTM works by strategically reducing parameter redundancy in the LSTM architecture. The weight sharing between gates reduces computational overhead while the retained memory cell structure maintains the model's ability to capture long-term dependencies. The peephole connections preserve LSTM's gradient stability mechanisms, preventing the vanishing/exploding gradient problems that plague simpler recurrent architectures. This balance allows LiteLSTM to maintain performance while significantly reducing the computational resources required.

## Architecture Onboarding

**Component Map**: Input -> Gate Weight Sharing -> Memory Cell -> Peephole Connections -> Output

**Critical Path**: The gate weight sharing mechanism followed by memory cell updates represents the core computational pathway that distinguishes LiteLSTM from standard LSTM.

**Design Tradeoffs**: Weight sharing reduces parameters but may limit gate specialization; memory cell retention maintains gradient stability but adds computational overhead.

**Failure Signatures**: Reduced gate specialization could manifest as lower performance on tasks requiring distinct gate behaviors; weight sharing might cause training instability on very long sequences.
