# Toward Open-domain Slot Filling via Self-supervised Co-training

## Quick Facts
- arXiv ID: 2303.13801
- Source URL: https://arxiv.org/abs/2303.13801
- Reference count: 40
- Primary result: Zero in-domain labeled data required for open-domain slot filling

## Executive Summary
This paper introduces SCot, a self-supervised co-training framework for open-domain slot filling without any in-domain labeled data. SCot operates in three phases: automatic generation of complementary pseudo labels using knowledge graphs and a zero-shot learning model; fine-tuning BERT using these pseudo labels; and iterative self-supervised co-training with high-confidence soft labels to progressively reduce noise. Experiments on SGD and MultiWoZ datasets show SCot outperforms state-of-the-art models by 45.57% and 37.56% respectively, and achieves comparable performance to fully supervised methods despite using zero in-domain labeled examples.

## Method Summary
SCot is a three-phase self-supervised framework that addresses open-domain slot filling without in-domain labeled data. Phase 1 generates two sets of complementary pseudo labels: KG-based labels using knowledge graphs, NER/POS taggers, and GPT-2 scoring; and zero-shot labels from a pre-trained model trained on out-of-domain data. Phase 2 fine-tunes multilingual BERT on both pseudo label sets using early stopping and multiple random initializations to obtain two peer models. Phase 3 implements iterative co-training where peers generate high-confidence soft labels for each other, progressively refining predictions through confidence-weighted updates.

## Key Results
- Outperforms state-of-the-art models by 45.57% on SGD and 37.56% on MultiWoZ datasets
- Achieves comparable performance to fully supervised methods despite zero in-domain labeled examples
- Successfully handles domains with 240 slot types, demonstrating scalability to large label spaces

## Why This Works (Mechanism)

### Mechanism 1
Complementary pseudo labels from KG and zero-shot learning reduce label noise and incompleteness. KG-based labels provide structured knowledge about entities and their types, while zero-shot labels capture generalizable slot patterns from other domains. Their combination covers both explicit entity knowledge and implicit domain-agnostic slot mention patterns. Core assumption: KG entries are sufficiently comprehensive for target domain entities, and zero-shot model generalizes well to unseen domains.

### Mechanism 2
Fine-tuning multilingual BERT with pseudo labels mitigates noise and leverages pre-trained language knowledge. BERT's MLM objective aligns with slot filling's need to predict tokens based on bidirectional context. Fine-tuning on pseudo labels adapts BERT to slot filling while early stopping and multiple random initializations prevent overfitting to noisy labels. Core assumption: BERT's pre-trained representations are sufficiently rich to transfer to slot filling and tolerate noisy supervision.

### Mechanism 3
Self-supervised co-training with high-confidence soft labels progressively refines peer models. Each peer generates soft labels for the other based on current model predictions. High-confidence tokens (max probability > threshold) are selected to update the peer model. This iterative refinement reduces noise and improves generalization. Core assumption: Peers have complementary strengths, and high-confidence selections avoid propagating errors.

## Architecture Onboarding

- Component map: Unlabeled utterances -> KG+taggers+GPT-2 scorer + zero-shot model -> pseudo labels -> Fine-tune BERT -> Two peer models -> Iterative co-training with soft labels -> Slot filling predictions
- Critical path: Phase 1 → Phase 2 → Phase 3 (co-training iterations)
- Design tradeoffs:
  - KG comprehensiveness vs. label accuracy: More KG entries improve recall but may introduce noise
  - Early stopping vs. model fitting: Too early stops underfitting; too late causes overfitting to noise
  - Confidence threshold vs. training data: Higher threshold reduces noise but limits training examples
- Failure signatures:
  - Phase 1: Low recall if KG lacks target domain entities; poor precision if taggers misclassify
  - Phase 2: Overfitting to noisy labels (check training/validation gap); underfitting (check performance plateau)
  - Phase 3: Error propagation (check if F1 score decreases over iterations); convergence to local minima (check peer model similarity)
- First 3 experiments:
  1. Verify KG coverage: Count how many target domain slot values have KG entries
  2. Test BERT fine-tuning: Compare F1 score on validation set with/without early stopping
  3. Validate co-training: Monitor F1 score and peer model divergence over co-training iterations

## Open Questions the Paper Calls Out

The paper does not explicitly call out open questions, but several remain unresolved based on the experimental setup and methodology.

## Limitations

- Implementation details for GPT-2-based scorer and zero-shot model are not fully specified, limiting reproducibility
- Computational overhead of iterative co-training is not reported, making practical deployment assessment difficult
- Performance scaling to datasets with thousands of slot types remains unexplored
- Sensitivity to knowledge graph quality and coverage across different domains is not analyzed

## Confidence

- **High Confidence**: Overall framework design and three-phase approach are well-articulated and logically sound
- **Medium Confidence**: Reported performance improvements are likely valid but exact reproducibility is limited by implementation details
- **Low Confidence**: Claim of achieving comparable performance to fully supervised methods without in-domain labeled data requires further validation on truly open-domain datasets
