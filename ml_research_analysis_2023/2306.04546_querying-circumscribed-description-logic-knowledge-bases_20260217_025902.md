# Querying Circumscribed Description Logic Knowledge Bases

## Quick Facts
- arXiv ID: 2306.04546
- Source URL: https://arxiv.org/abs/2306.04546
- Reference count: 40
- Primary result: Establishes decidability and complexity bounds for conjunctive and atomic query evaluation under circumscription in various description logics

## Executive Summary
This paper investigates the complexity of conjunctive and atomic query evaluation on description logic knowledge bases extended with circumscription. The authors establish decidability for all considered description logics, ranging from ALCHIO to DL-Lite variants, and provide a complete complexity picture. The results show that combined complexity is generally high (2EXP-complete for ALCHIO and EL), while data complexity ranges from CONP-complete for DL-Lite to ΠP2-complete for ALCHIO and EL.

## Method Summary
The paper uses theoretical analysis to establish decidability and complexity bounds for query evaluation under circumscription. The approach involves introducing a novel "core lemma" that reduces the search space for minimal models, employing quotient constructions and mosaic techniques to verify query non-entailment, and analyzing the impact of circumscription patterns on different description logic variants. The complexity analysis considers both combined and data complexity, providing upper and lower bounds for each scenario.

## Key Results
- Decidability of (U)CQ evaluation on circumscribed DL KBs is established for all considered DLs
- Combined complexity is 2EXP-complete for ALCHIO and EL, ranging from 2EXP to CONEXP for DL-Lite variants
- Data complexity is ΠP2-complete for ALCHIO and EL, and CONP-complete for DL-Lite variants
- Atomic query evaluation has lower complexity than UCQ evaluation, but remains high for expressive DLs

## Why This Works (Mechanism)

### Mechanism 1
- Claim: UCQ evaluation is decidable for all considered DLs with circumscription.
- Mechanism: The paper introduces a novel "core lemma" that reduces the search space for minimal models to a finite, bounded set of types, and uses quotient constructions and mosaic techniques to verify query non-entailment in a single exponential time.
- Core assumption: Every model of the KB can be transformed into a "core model" where the types of elements are drawn from a finite set TP(T), and this core is sufficient to check both satisfiability and query non-entailment under circumscription.
- Evidence anchors:
  - [abstract] "proves decidability of (U)CQ evaluation on circumscribed DL KBs"
  - [section] "We use a mosaic approach... to verify Condition (I)" and "We introduce a variation of Lemma 9"
- Break condition: If the type set TP(T) becomes infinite (e.g., with infinite models), the core lemma fails and the algorithm cannot terminate.

### Mechanism 2
- Claim: Data complexity for ALCHIO and EL drops from CONP to ΠP2 under circumscription, while DL-Lite variants remain in CONP.
- Mechanism: For ALCHIO/EL, the algorithm guesses a polynomial-sized countermodel and uses a ΠP2 oracle to check minimality. For DL-Lite, the structure of the logic allows decomposing the model into a polynomial number of small "base parts" and "tree extensions," enabling a CONP check.
- Core assumption: The size of a minimal countermodel is bounded by a polynomial in the TBox and query size, and the complexity of checking minimality under circumscription can be reduced to a ΠP2 or CONP oracle call.
- Evidence anchors:
  - [abstract] "data complexity, however, there is a significant increase from CONP- to ΠP2-completeness"
  - [section] "guess a model I of K with I ̸| = q(¯a) and |∆I| bounded... verify that I is minimal w.r.t. <CP"
- Break condition: If the size bound on countermodels fails (e.g., with unbounded role chains), the data complexity jumps beyond CONP/ΠP2.

### Mechanism 3
- Claim: Atomic query (AQ) evaluation remains 2EXP-complete for ALCHIO/EL and drops to PTIME for DL-Lite under data complexity.
- Mechanism: For ALCHIO/EL, the proof adapts the UCQ machinery to AQs by showing that a single exponential-sized model suffices and the check is in 2EXP NP. For DL-Lite, the proof uses a type-based ABox reduction to a constant-sized KB, enabling a PTIME check.
- Core assumption: AQs are a special case of UCQs where the query size is constant, so the exponential blowup in combined complexity can be avoided in data complexity for DL-Lite.
- Evidence anchors:
  - [abstract] "AQ evaluation in both ALCHIO and EL are ΠP2-complete w.r.t. data complexity"
  - [section] "AQ evaluation on circumscribed DL-Lite H bool KBs is in PTIME w.r.t. data complexity"
- Break condition: If the type-based reduction fails (e.g., with negative role inclusions), the complexity jumps back to ΠP2.

## Architecture Onboarding

- Component map:
  - Core lemma: Reduces model search to a finite type set
  - Quotient construction: Collapses large models into small, equivalent ones
  - Mosaic approach: Assembles models from small pieces for combined complexity
  - Type-based ABox reduction: Shrinks ABoxes for data complexity in DL-Lite
  - Preference check: Verifies model minimality under circumscription

- Critical path:
  1. Parse TBox and ABox, normalize to normal form
  2. Build type set TP(T) and identify minimized/fixed concept names
  3. For UCQ/AQ evaluation: guess a countermodel up to the size bound
  4. For data complexity: reduce ABox or use type-based decomposition
  5. Check model satisfiability and query non-entailment
  6. Verify minimality under circumscription using the core lemma or preference check

- Design tradeoffs:
  - Combined vs. data complexity: Combined allows guessing models but is expensive; data complexity uses fixed queries and exploits structure for tractability
  - DL-Lite vs. ALCHIO: DL-Lite's simpler syntax enables polynomial decompositions; ALCHIO requires exponential machinery
  - Fixed vs. minimized concepts: Fixed concepts simplify reasoning; minimized ones increase complexity but enable defeasible reasoning

- Failure signatures:
  - Model not found: The core lemma or size bound may fail; check for infinite models or unbounded role chains
  - Minimality check fails: The preference relation may be too complex; verify that the chosen model is indeed minimal
  - Type set explosion: TP(T) may be too large; check for overly expressive TBoxes

- First 3 experiments:
  1. Implement the core lemma for a simple ALCHI TBox and verify it correctly identifies minimal models
  2. Test the quotient construction on a small DL-Lite KB and check that it preserves query answers
  3. Run the type-based ABox reduction on a DL-Lite bool KB and confirm that the reduced KB yields the same query answers

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Can the complexity of CQ evaluation on DL-Lite cKBs be improved to match UCQ complexity, or is the gap inherent to the logic?
- Basis in paper: [inferred] The paper proves UCQ evaluation is 2EXP-hard for DL-Lite H core and CONEXP-hard for DL-Lite bool, but the complexity for CQs remains open.
- Why unresolved: The reduction from UCQ evaluation to CQ evaluation may not be straightforward, and the lower bounds for UCQs rely on specific query structures that may not translate to CQs.
- What evidence would resolve it: A direct reduction from CQ evaluation to UCQ evaluation, or a proof that the lower bounds for UCQs do not extend to CQs.

### Open Question 2
- Question: Does the complexity of query evaluation decrease when the preference relation in circumscription patterns is forced to be empty?
- Basis in paper: [explicit] The paper mentions that some lower bounds rely on the preference relation and it remains open whether the complexity decreases when the preference relation is empty.
- Why unresolved: The preference relation introduces additional complexity, but it is unclear if its absence simplifies the problem.
- What evidence would resolve it: A complexity analysis of query evaluation under empty preference relations, or a proof that the lower bounds still hold.

### Open Question 3
- Question: Are ontology-mediated querying problems with circumscription still decidable for existential rules or guarded (negation) fragment of first-order logic?
- Basis in paper: [explicit] The paper suggests that these problems are likely decidable but does not provide a proof.
- Why unresolved: The decidability of query evaluation with circumscription on these more expressive logics is not established.
- What evidence would resolve it: A decidability proof for query evaluation with circumscription on existential rules or the guarded (negation) fragment of first-order logic.

## Limitations

- The complexity bounds rely on idealized constructions like the "core lemma" and type-based reductions, which may not hold in all cases
- The exact complexity bounds for DL-Lite variants are intricate and may require further analysis to verify
- The paper does not provide implementation details or empirical validation of the theoretical results
