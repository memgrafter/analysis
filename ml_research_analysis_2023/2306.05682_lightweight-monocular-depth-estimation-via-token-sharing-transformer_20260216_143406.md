# Lightweight Monocular Depth Estimation via Token-Sharing Transformer

## Quick Facts
- arXiv ID: 2306.05682
- Source URL: https://arxiv.org/abs/2306.05682
- Reference count: 35
- Achieves 63.4 FPS on NVIDIA Jetson Nano and 142.6 FPS on NVIDIA Jetson TX2 for monocular depth estimation

## Executive Summary
Token-Sharing Transformer (TST) is a lightweight monocular depth estimation method optimized for embedded devices. The key innovation is using global token sharing in a hybrid CNN-Transformer architecture to achieve high throughput while maintaining accuracy. TST combines hierarchy-focused (multi-level features) and bottleneck-focused (low-resolution tokens) architectures by injecting global information into multi-level features via shared global tokens. On NYU Depth V2 dataset, TST achieves real-time performance on embedded devices while outperforming existing lightweight methods in both accuracy and speed.

## Method Summary
TST extracts multi-level features from a lightweight CNN (MobileNetV2-based), using the high-level feature as a shared global token. Each Transformer block computes cross-attention between the shared global token and each local token, injecting global information into local features. Local tokens are downsampled to reduce computational complexity before cross-attention, then upsampled back after feature refinement. The architecture replaces Layer Normalization with Batch Normalization and GELU with ReLU6 activation functions for better embedded device optimization. Depth maps are reconstructed using a GLPDepth decoder from the refined features.

## Key Results
- Achieves 63.4 FPS on NVIDIA Jetson Nano and 142.6 FPS on NVIDIA Jetson TX2
- Outperforms existing lightweight methods in both accuracy and speed on NYU Depth V2
- Successfully combines hierarchy-focused and bottleneck-focused architectural benefits

## Why This Works (Mechanism)

### Mechanism 1
Token-sharing transformer achieves better accuracy and throughput by injecting global information into multi-level features via shared global tokens. The architecture extracts multi-level features from a lightweight CNN, using the high-level feature as a shared global token. Each Transformer block computes cross-attention between the shared global token and each local token, effectively injecting global information into local features. The local tokens are downsampled to reduce computational complexity before cross-attention, then upsampled back after feature refinement.

### Mechanism 2
TST achieves real-time performance on embedded devices by combining hierarchy-focused and bottleneck-focused architectural concepts. The architecture uses multi-level features (like hierarchy-focused) while applying self-attention only to low-resolution tokens (like bottleneck-focused). The global token sharing allows the model to learn rich global information with high throughput.

### Mechanism 3
The replacement of Layer Normalization with Batch Normalization and GELU with ReLU6 activation functions improves optimization for embedded devices. Following Efficientformer observations, TST uses these computationally efficient alternatives that are better suited for optimization on embedded hardware.

## Architecture Onboarding

- Component map: Input image → Encoder (MobileNetV2-based CNN) → Connection Modules (TST blocks with cross-attention) → Decoder (GLPDepth) → Output depth map

- Critical path: Input image → Encoder → Connection Modules (TST blocks) → Decoder → Output depth map

- Design tradeoffs:
  - Accuracy vs. Speed: Hierarchy-focused architectures provide better accuracy but lower throughput; bottleneck-focused provide faster inference but lower accuracy
  - Complexity vs. Efficiency: More complex token sharing and cross-attention improves accuracy but increases computational overhead
  - Feature resolution vs. Computational cost: Downsampling local tokens reduces computation but may lose spatial details

- Failure signatures:
  - Low FPS: Check TensorRT optimization, batch size, and model complexity
  - Poor depth accuracy: Verify global token sharing is functioning correctly, check cross-attention implementation
  - Memory issues: Monitor feature map sizes during downsampling/upsampling operations

- First 3 experiments:

  2. Token sharing validation: Compare performance with and without global token sharing to verify its impact
