# Voting from Nearest Tasks: Meta-Vote Pruning of Pre-trained Models for Downstream Tasks

## Quick Facts
- arXiv ID: 2301.11560
- Source URL: https://arxiv.org/abs/2301.11560

## Executive Summary
This paper introduces Meta-Vote Pruning (MVP), a method that reuses pruned models from similar tasks to efficiently prune pre-trained networks for new downstream tasks. The authors empirically demonstrate that more similar tasks share more filters/nodes/heads in their pruned models, especially in deeper layers. MVP leverages this observation by initializing a sub-network for a new task through majority voting from its nearest tasks' pruned models, followed by limited fine-tuning. Experiments across multiple datasets and architectures show MVP's advantages over state-of-the-art pruning methods when computational resources are limited.

## Method Summary
MVP operates by first computing task similarity using metrics like LEEP or WordNet, then identifying the N nearest tasks to the target task. It extracts the pruned models of these nearest tasks and performs majority voting on filters/nodes/heads in each layer. The voting results are converted to softmax probabilities, which are used to sample an initialization for the target task. This initialized sub-network is then fine-tuned for a limited number of iterations (100) rather than the full iterative pruning process (1000 iterations). The method is evaluated on CNNs (ResNet-18, ResNet-50) and Vision Transformers using datasets like CIFAR-100, ImageNet, and fine-grained classification tasks.

## Key Results
- More similar tasks share significantly more filters/nodes/heads in their pruned models (higher IoU), especially in deeper layers.
- MVP initialization with limited iterations (100) achieves comparable accuracy to full iterative pruning (1000 iterations).
- MVP outperforms random pruning and matches or exceeds state-of-the-art methods like HRank and SFP in the limited computation regime.
- MVP shows strong generalization when pruned models from one dataset (e.g., CIFAR-100) are used for tasks from different datasets (e.g., Caltech-256).

### Mechanism 1
- Claim: More similar tasks tend to share more filters/nodes/heads in their pruned models, especially in deeper layers.
- Mechanism: Similarity metrics (LEEP, WordNet) capture task relationships, and deeper layers learn more task-specific features, leading to higher overlap in pruned sub-networks.
- Core assumption: Task similarity can be accurately measured using semantic labels or learned representations.

- Break condition: If similarity metrics fail to capture true task relationships or if task-specific features are not learned in deeper layers.

### Mechanism 2
- Claim: Majority voting from nearest tasks' pruned models can effectively initialize a sub-network for a new task.
- Mechanism: Filters/nodes/heads selected by more similar tasks have higher probability of being included in the initialization through softmax over vote counts.
- Core assumption: Important filters for a new task are likely to be preserved in pruned models of similar tasks.
- Evidence anchors:
  - [abstract]: "initializes a sub-network for a new task by sampling filters/nodes/heads in each layer using majority voting from its nearest tasks"

- Break condition: If nearest tasks' pruned models don't contain relevant filters for the new task or if voting distribution becomes too uniform.

### Mechanism 3
- Claim: Limited pruning iterations with MVP initialization can achieve comparable accuracy to full iterative pruning.
- Mechanism: MVP initialization provides a good starting point by leveraging knowledge from similar tasks, reducing the need for extensive fine-tuning.
- Core assumption: A well-initialized sub-network can converge quickly with minimal iterations.

- Break condition: If the initialized sub-network is not close enough to the optimal solution or if the task requires more extensive adaptation.

## Architecture Onboarding

- Component map:
  Task Similarity Module -> Pruned Model Zoo -> Voting Module -> Initialization Module -> Fine-tuning Module

- Critical path:
  1. Compute similarity between target task and all training tasks
  2. Select N nearest tasks
  3. Extract their pruned models
  4. Perform majority voting and softmax calculation
  5. Sample initialization based on probabilities
  6. Fine-tune for limited iterations

- Design tradeoffs:
  - Number of nearest tasks (N): More neighbors provide better coverage but increase computation
  - Pruning ratio: Higher ratios give smaller models but may lose important features
  - Iteration limit: Fewer iterations save computation but may underfit

- Failure signatures:
  - Low accuracy despite high similarity scores: Voting mechanism may not be capturing relevant features
  - High variance in results: Insufficient neighbors or unstable voting distribution
  - Slow convergence: Initialization may be too far from optimal solution

- First 3 experiments:
  1. Test MVP with different numbers of nearest neighbors (N=1, 3, 5) on CIFAR-100 tasks
  2. Compare MVP performance using LEEP vs. WordNet similarity metrics
  3. Evaluate MVP with different iteration limits (20, 50, 100) to find optimal tradeoff

## Limitations
- The statistical significance of IoU differences between similar and dissimilar tasks is not established.
- Claims about carbon footprint reduction and scalability to billions of edge devices are not substantiated with actual measurements.
- The computational overhead of similarity metric computation for large model zoos is not quantified.

## Confidence
**High Confidence**: MVP provides computational savings over full iterative pruning. The ablation showing MVP outperforms random pruning and matches or exceeds baselines in limited-iteration regimes is convincing.

**Medium Confidence**: The core hypothesis that task similarity predicts pruning overlap. While qualitative trends are observed, quantitative analysis of when similarity metrics fail or how they compare to alternatives is missing.

**Low Confidence**: Claims about carbon footprint reduction and scalability to billions of edge devices. These assertions are not substantiated with actual measurements or deployment scenarios.

## Next Checks
1. Conduct statistical significance tests on IoU differences between similar vs. dissimilar task pairs across all datasets and architectures.
2. Implement and compare MVP using alternative similarity metrics (taskonomy embeddings, CLIP similarity, or learned task representations) against LEEP and WordNet.
3. Measure end-to-end computational overhead including similarity metric computation, and profile memory usage when scaling to larger model zoos with thousands of pruned models.
