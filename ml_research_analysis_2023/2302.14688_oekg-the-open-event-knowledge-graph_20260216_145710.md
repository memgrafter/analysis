# OEKG: The Open Event Knowledge Graph

## Quick Facts
- arXiv ID: 2302.14688
- Source URL: https://arxiv.org/abs/2302.14688
- Reference count: 22
- Primary result: Integration of seven diverse datasets into a multilingual event-centric knowledge graph with over 400 million triples

## Executive Summary
The Open Event Knowledge Graph (OEKG) is a multilingual, event-centric knowledge graph that integrates seven diverse datasets from question answering, entity recommendation, and named entity recognition domains. The authors developed an efficient integration pipeline that links new datasets to EventKGlight through RDF named graphs, enabling robust and scalable data integration. The resulting OEKG contains over 400 million triples and provides three practical use cases: type-specific image retrieval, hybrid question answering, and language-specific event recommendation. The resource is publicly available through downloadable dumps, a SPARQL endpoint, and a web interface.

## Method Summary
The OEKG integration pipeline follows a three-step process: entity linking to EventKGlight resources via API, graph creation using RDFLib to serialize triples as N-Triples, and graph upload via API to add data under unique named graphs. The pipeline first attempts to transform data using the EventKGlight schema, then uses standard vocabularies like schema.org, and finally creates schema extensions for remaining requirements. This modular approach allows each dataset to be added independently while maintaining connections to the core EventKGlight graph.

## Key Results
- Successfully integrated seven diverse datasets into a unified multilingual knowledge graph
- Created over 400 million triples with RDF named graph approach
- Demonstrated three practical use cases: image retrieval, hybrid question answering, and event recommendation

## Architecture Onboarding

- Component map:
  EventKGlight -> Integration pipeline (entity linking, graph creation, graph upload) -> Named graphs -> API services -> SPARQL endpoint -> Web interface

- Critical path:
  1. Dataset preparation and transformation to RDF format
  2. Entity linking to EventKGlight resources via API
  3. Graph creation using RDFLib and serialization to N-Triples
  4. Graph upload via API to add named graph to OEKG
  5. Schema validation and extension if needed
  6. SPARQL query testing and performance optimization

- Design tradeoffs:
  - Named graphs vs. unified schema: Isolation vs. simplified queries
  - EventKGlight vs. full EventKG: Easy integration vs. provenance traceability
  - Standard vocabularies vs. custom extensions: Compatibility vs. domain specificity

- Failure signatures:
  - Integration failures: Entity linking returns no matches
  - Schema conflicts: RDF validation errors during graph creation
  - Performance degradation: SPARQL queries become slow with dataset growth
  - Data quality issues: Inconsistent labels or missing relationships

- First 3 experiments:
  1. Add a small, well-structured dataset to verify complete integration pipeline
  2. Test complex query spanning multiple named graphs for cross-dataset linking
  3. Integrate dataset with partial EventKGlight mappings to validate fallback mechanisms
