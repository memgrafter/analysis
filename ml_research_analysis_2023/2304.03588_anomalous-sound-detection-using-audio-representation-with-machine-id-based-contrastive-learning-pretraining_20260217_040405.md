# Anomalous Sound Detection using Audio Representation with Machine ID based Contrastive Learning Pretraining

## Quick Facts
- **arXiv ID**: 2304.03588
- **Source URL**: https://arxiv.org/abs/2304.03588
- **Reference count**: 0
- **Key outcome**: Achieves 93.75% average AUC and 88.48% average pAUC on DCASE 2020 Task2, outperforming state-of-the-art methods.

## Executive Summary
This paper proposes a two-stage contrastive learning method for anomalous sound detection (ASD) that leverages machine ID metadata. The method first pretrains audio representations using contrastive learning that clusters embeddings of sounds from the same machine ID while separating those from different IDs. It then fine-tunes the model with a self-supervised classifier to further enhance discrimination. Experiments on DCASE 2020 Task2 dataset show the proposed method achieves 93.75% average AUC and 88.48% average pAUC, outperforming state-of-the-art methods including self-supervised classification and contrastive learning approaches. The method also demonstrates improved stability in detection performance across machine types.

## Method Summary
The proposed method uses a two-stage training approach: (1) Contrastive learning based pretraining using a metadata-based contrastive learning (CL-Meta) loss to learn audio embeddings, and (2) Self-supervised classification based fine-tuning using an ArcFace loss to further enhance the distinguishing ability of the learnt audio representation. The method employs a backbone module (STgram-MFN) for audio feature extraction and a projector module (MLP) to obtain audio embeddings. The model is pretrained using the CL-Meta loss with a batch size of 246, learning rate of 0.0005, and 100 epochs, followed by fine-tuning using the ArcFace loss with a batch size of 128, learning rate of 0.0001, and 300 epochs.

## Key Results
- Achieves 93.75% average AUC and 88.48% average pAUC on DCASE 2020 Task2 dataset
- Outperforms state-of-the-art methods including IDNN, MobileNetV2, Glow Aff, STgram-MFN (ArcFace), and AADCL
- Demonstrates improved stability in detection performance across machine types

## Why This Works (Mechanism)

### Mechanism 1
Using machine ID as the contrastive learning grouping signal improves inter-class separation compared to sample-level augmentation. Contrastive learning loss (CL-Meta) clusters embeddings of sounds from the same machine ID while pushing embeddings from different IDs apart, enforcing tighter intra-ID clusters. Core assumption: Audio features from the same machine ID share sufficient similarity to benefit from contrastive clustering, while different IDs provide meaningful negative pairs. Break condition: If machine IDs do not correspond to consistent acoustic characteristics, or if ID classes are too diverse within type, contrastive loss may fail to improve separation.

### Mechanism 2
Two-stage training (contrastive pretraining + self-supervised fine-tuning) yields more discriminative audio representations than either stage alone. Pretraining stage aligns embeddings within machine IDs; fine-tuning stage sharpens inter-ID discrimination using ArcFace loss. Core assumption: The learned contrastive embeddings provide a good initialization for subsequent classification fine-tuning. Break condition: If the contrastive stage overfits to ID clusters without preserving anomaly-relevant features, fine-tuning may not recover discriminative power.

### Mechanism 3
Using spectral-temporal features (STgram) as backbone input captures richer acoustic patterns for ASD. STgram-MFN backbone extracts time-frequency coupled features, providing a strong representation for contrastive and classification learning. Core assumption: Spectral-temporal fusion improves anomaly discrimination over pure spectral or temporal inputs. Break condition: If STgram features are noisy or overfit to normal sounds, anomaly detection performance may degrade.

  - Why needed here: Captures both frequency and temporal dynamics, critical for ASD

## Architecture Onboarding

- **Component map**: Input → STgram-MFN (backbone) → Projector (MLP) → CL-Meta loss (pretraining) → ArcFace classifier (fine-tuning) → Anomaly score (ID prediction mismatch)
- **Critical path**: Backbone → Projector → Contrastive pretraining → Fine-tuning → Inference
- **Design tradeoffs**: Contrastive pretraining with ID labels vs. self-supervised classification alone; trade-off between embedding tightness (contrastive) and classification margin (ArcFace)
- **Failure signatures**: (1) High AUC but poor mAUC indicates instability across machines; (2) Low contrastive loss but high fine-tuning loss suggests poor initialization; (3) Degraded performance on unseen IDs indicates overfitting to training IDs
- **First 3 experiments**:
  1. Ablation: Remove contrastive pretraining, use ArcFace only from scratch; compare AUC/pAUC
  2. Sensitivity: Vary temperature τ in CL-Meta loss; plot performance vs. τ
  3. Stability test: Train on subsets of machine IDs, evaluate mAUC across held-out IDs to measure generalization

## Open Questions the Paper Calls Out

### Open Question 1
How does the proposed method's performance compare when applied to datasets with more diverse machine types or real-world industrial settings beyond the DCASE 2020 dataset? Basis in paper: The paper states that experiments were conducted on the DCASE 2020 dataset, which includes four machine types from the MIMII dataset and two from the ToyADMOS dataset. However, it does not explore performance on more diverse or real-world industrial datasets. Why unresolved: The current evaluation is limited to specific datasets, and the generalizability to other machine types or real-world industrial environments is not addressed. What evidence would resolve it: Performance evaluation on additional datasets representing a broader range of machine types and real-world industrial settings, comparing the proposed method with other state-of-the-art methods.

### Open Question 2
What is the impact of different augmentation techniques on the performance of the proposed contrastive learning method? Basis in paper: The paper mentions that existing contrastive learning methods use augmentations like time masking and frequency masking. However, it does not explore the impact of different augmentation techniques on the proposed method's performance. Why unresolved: The study focuses on metadata-based contrastive learning but does not investigate how various augmentation strategies might affect the model's ability to learn effective audio representations. What evidence would resolve it: Comparative analysis of the proposed method using different augmentation techniques, evaluating their impact on detection performance and stability.

### Open Question 3
How does the proposed method handle domain shifts or distribution changes in machine sounds over time? Basis in paper: The paper mentions that the DCASE 2022 Challenge Task2 dataset, designed to investigate domain shifts, was not used because it is out of the scope of the current work. This implies that the proposed method's handling of domain shifts is not explored. Why unresolved: The study addresses audio representation learning under known conditions but does not investigate the model's robustness to changes in data distribution or domain shifts. What evidence would resolve it: Experiments evaluating the proposed method's performance on datasets with known domain shifts, comparing its adaptability to other methods designed for handling such shifts.

## Limitations
- The paper's performance claims rely heavily on contrastive pretraining with machine ID labels, but the evidence base for this mechanism is weak due to lack of ablation studies.
- The STgram-MFN backbone architecture details are missing, making it difficult to assess the specific contributions of spectral-temporal feature extraction.
- The method's generalization to unseen machine IDs is not thoroughly validated, raising concerns about overfitting to training IDs.
- The corpus lacks discussion of failure modes, such as how the model handles ambiguous or partially anomalous sounds.

## Confidence

- **High Confidence**: The use of contrastive learning with machine ID metadata is a valid and established approach for representation learning in ASD tasks. The reported AUC and pAUC metrics are consistent with state-of-the-art performance in the field.
- **Medium Confidence**: The two-stage training (contrastive pretraining + ArcFace fine-tuning) is plausible and likely beneficial, but lacks direct comparative evidence in the corpus.
- **Low Confidence**: The specific contributions of the STgram-MFN backbone and the CL-Meta loss formulation are not well-supported by the corpus evidence.
