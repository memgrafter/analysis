# A weighted subspace exponential kernel for support tensor machines

## Quick Facts
- arXiv ID: 2302.08134
- Source URL: https://arxiv.org/abs/2302.08134
- Reference count: 13
- Key outcome: WSEK kernel outperforms state-of-the-art tensor kernels on fMRI datasets with higher accuracy and lower computational time

## Executive Summary
This paper introduces a weighted subspace exponential kernel (WSEK) for support tensor machines that leverages Tucker decomposition with reweighted factors based on HOSVD singular values. The kernel balances contributions from both Tucker factors and the core tensor, leading to improved classification performance. Extensive experiments on synthetic data and real-world fMRI datasets (ADNI and ADHD) demonstrate that WSEK outperforms existing methods like tensor train multi-way multi-level kernel while maintaining computational efficiency.

## Method Summary
The method uses Tucker decomposition with weighted factors from HOSVD, where each factor is scaled by a tunable power of its corresponding singular value. The WSEK kernel computes Euclidean distances between these reweighted Tucker factors, summing over exponential kernels of all combinations. This approach captures information from both the Tucker factors (subspaces) and the core tensor, providing a balance between subspace kernel (which only considers subspaces) and DuSK (which considers CP decomposition factors). The method is implemented within the KSTM framework and evaluated using LIBSVM with hyperparameter tuning.

## Key Results
- WSEK achieves higher classification accuracy than subspace kernel, DuSK, and Gaussian kernels on ADNI and ADHD datasets
- Computational time is significantly lower than DuSK while maintaining comparable performance to subspace kernel
- WSEK shows robustness across different tensor ranks and noise levels in synthetic experiments
- The kernel successfully handles scenarios where class-discriminative information is distributed between Tucker factors and core tensor

## Why This Works (Mechanism)

### Mechanism 1
- Claim: WSEK kernel improves classification accuracy by reweighting Tucker factors with tunable powers of singular values from the HOSVD decomposition.
- Mechanism: The WSEK kernel computes Euclidean distances between reweighted Tucker factors, where each factor is scaled by a tunable power of its corresponding singular value. This allows the kernel to balance contributions from both Tucker factors and the core tensor in building the nonlinear decision boundary.
- Core assumption: The HOSVD decomposition provides a meaningful basis for comparing tensors, and reweighting by singular values captures relevant structural information for classification.
- Evidence anchors:
  - [abstract] "For this kernel the Tucker factors are computed based on re-weighting of the Tucker matrices with tuneable powers of singular values from the HOSVD decomposition."
  - [section 3.2] "we can shift any power of the singular values into either the left or the right singular matrices" and "we compute the Euclidean distances instead and sum over the exponential kernels of all combinations"
- Break Condition: If the singular values do not capture meaningful variance for the classification task, or if the reweighting causes numerical instability.

### Mechanism 2
- Claim: WSEK kernel provides better classification than existing tensor kernels by combining strengths of subspace kernel and DuSK.
- Mechanism: WSEK captures information from both Tucker factors (subspaces) and the core tensor, whereas the subspace kernel only considers subspaces and DuSK only considers CP decomposition factors. By using weighted Tucker factors, WSEK can adapt to scenarios where classification information is stored in either the factors or the core.
- Core assumption: Classification-relevant information can be distributed between Tucker factors and core tensor, and a kernel that captures both will be more robust.
- Evidence anchors:
  - [section 4.1] "The subspace kernel introduced in Section 3 can only see the subspaces... DuSK includes extra information so that it performs better in the core-scenario"
  - [section 5.2] "Our real world experiments show superior performance of the WSEK both in terms of classification accuracy and running time"
- Break Condition: If classification information is exclusively in one component (factors or core) with no overlap, or if the weighting mechanism doesn't adapt well to the data structure.

### Mechanism 3
- Claim: WSEK kernel is computationally efficient compared to DuSK and Gaussian kernel approaches.
- Mechanism: WSEK leverages the Tucker decomposition structure to avoid the computational complexity of full tensor operations. It computes distances between reweighted factors rather than between full tensors, reducing complexity from O(IM) to O(MIR²Tucker).
- Core assumption: Low-rank tensor approximations preserve sufficient information for classification while reducing computational burden.
- Evidence anchors:
  - [section 3.3] "Table 2 summarizes the computational complexity for a single entry of the kernel matrix" showing WSEK complexity as O(MIR²Tucker)
  - [section 5.2] "Computation of DuSK however quickly becomes prohibitive and takes a long time in these experiments" versus "Subspace kernel and WSEK can be computed efficiently"
- Break Condition: If Tucker decomposition ranks are too high, or if the computational savings are offset by the cost of decomposition.

## Architecture Onboarding

- Component map: Input tensor → HOSVD decomposition → Reweighted factors → WSEK kernel computation → Kernel matrix → SVM optimization → Model evaluation

- Critical path:
  1. Input tensor → HOSVD decomposition (Algorithm 1)
  2. Reweighted factors → WSEK kernel computation
  3. Kernel matrix → SVM optimization (LIBSVM)
  4. Model evaluation → Accuracy metrics

- Design tradeoffs:
  - Rank selection: Higher ranks capture more information but increase computation
  - Weighting parameter p: Default p=1/M distributes norm equally, but optimal value may vary
  - Tucker vs TT: Tucker provides interpretability but TT may be more efficient for very high dimensions

- Failure signatures:
  - Poor classification accuracy: Check if singular values capture relevant variance, verify rank selection
  - High computational cost: Monitor Tucker rank growth, check for numerical instability in HOSVD
  - Convergence issues: Verify kernel matrix is positive semi-definite, check SVM hyperparameter tuning

- First 3 experiments:
  1. Synthetic data test: Generate tensors where classification information is in factors vs core, compare WSEK vs subspace vs DuSK
  2. Rank sensitivity: Test WSEK with varying Tucker ranks on real data to find optimal rank
  3. Computational benchmark: Measure WSEK vs DuSK vs Gaussian kernel computation times on same datasets

- Optimal weighting parameter p is presented without extensive sensitivity analysis across different datasets
- Computational efficiency claims rely on Tucker rank assumptions that may not hold for all data types
