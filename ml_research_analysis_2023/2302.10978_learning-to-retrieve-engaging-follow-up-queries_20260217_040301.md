# Learning to Retrieve Engaging Follow-Up Queries

## Quick Facts
- arXiv ID: 2302.10978
- Source URL: https://arxiv.org/abs/2302.10978
- Reference count: 3
- Key outcome: Trained ranking model achieves MRR of ~0.80, Hit@1 of 68%, and Hit@3 of 89% on FQ-Bank dataset

## Executive Summary
This work addresses the challenge of proactively suggesting relevant follow-up queries to users in conversational settings, such as voice assistants. The authors create FQ-Bank, a synthetic dataset built by simulating various confounders (paraphrases, irrelevant entities, ASR errors, etc.) on the OR-QuAC multi-turn dialog dataset. They train a ranking model to distinguish valid follow-up queries from invalid ones using fine-tuned BERT or RoBERTa models, achieving strong performance metrics that demonstrate the model's ability to rank valid follow-ups higher than confounders.

## Method Summary
The approach involves constructing FQ-Bank by applying controlled transformations to OR-QuAC conversations to generate synthetic negative examples. These confounders are paired with valid follow-up queries to create labeled training data. A ranking model is then trained by fine-tuning BERT or RoBERTa for binary classification, where each candidate query is concatenated with the dialog context and classified as relevant or irrelevant. The binary relevance score serves as the ranking score. The system is evaluated using standard ranking metrics including MRR, Hit@1, and Hit@3.

## Key Results
- Best model achieves MRR of approximately 0.80 on test set
- Hit@1 score reaches 68%, indicating valid follow-ups ranked first about two-thirds of the time
- Hit@3 score of 89% shows valid follow-ups appear in top 3 positions most frequently
- Demonstrates effective ranking of valid follow-ups above synthetic confounders

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Synthetically generated confounders enable training without manual annotation
- Mechanism: Controlled transformations on OR-QuAC create negative examples paired with valid follow-ups for supervised ranking
- Core assumption: Adversarially crafted confounders mimic real-world retrieval noise patterns
- Evidence anchors: Abstract mentions "invalid candidates are generated to simulate various syntactic and semantic confounders"; section 3.1 describes creating a search index and analyzing irrelevant results
- Break condition: If confounders don't match real-world retrieval error distributions, generalization suffers

### Mechanism 2
- Claim: Fine-tuning BERT/RoBERTa for binary classification effectively ranks follow-up queries
- Mechanism: Concatenating dialog context with candidate, feeding to model, using binary relevance score as ranking score
- Core assumption: Binary classification on dialog + candidate pairs captures sufficient contextual features
- Evidence anchors: Abstract mentions "train ranking models on FQ-Bank"; section 4.2 describes translating problem to binary classification
- Break condition: If model overfits to synthetic confounders and cannot generalize to unseen patterns

### Mechanism 3
- Claim: Dataset construction with paraphrases and entity substitutions ensures robust learning
- Mechanism: Paraphrases and entity substitutions introduce lexical variance while preserving semantic context
- Core assumption: Semantic similarity alone is insufficient; models must capture deeper dialog coherence
- Evidence anchors: Section 3.1 explains paraphrase as asking same question differently; section 3.3 describes using BART for paraphrase generation
- Break condition: If paraphrases and substitutions are too similar to valid follow-ups, model may not differentiate

## Foundational Learning

- Concept: Adversarial data synthesis
  - Why needed here: To create labeled training data without expensive manual annotation
  - Quick check question: How would you generate a negative example that is a paraphrase of the original query?

- Concept: Pre-trained language model fine-tuning
  - Why needed here: To leverage contextualized embeddings for semantic ranking beyond lexical matching
  - Quick check question: What loss function is used for the binary classification head in BERT/RoBERTa?

- Concept: Ranking evaluation metrics (MRR, Hit@1/3)
  - Why needed here: To measure ability to surface correct follow-up above confounders
  - Quick check question: If a valid follow-up is ranked 2nd out of 5 candidates, what is its reciprocal rank?

## Architecture Onboarding

- Component map: OR-QuAC → synthetic confounders → FQ-Bank dataset → BERT/RoBERTa fine-tuning → ranking model → evaluation metrics
- Critical path: Dialog history → candidate retrieval → ranking model → output follow-up
- Design tradeoffs:
  - Synthetic confounders avoid annotation but may not reflect all real noise types
  - Fine-tuning pre-trained models reduces data needs but requires GPU resources
  - Binary classification simplifies ranking but loses granular relevance scores
- Failure signatures:
  - Low MRR/Hit@1: Model unable to distinguish valid follow-ups from confounders
  - High paraphrase scores: Model relying on lexical overlap instead of contextual coherence
  - Poor generalization: Synthetic confounders too dissimilar from real search engine noise
- First 3 experiments:
  1. Train BERT on FQ-Bank and measure MRR, Hit@1/3 on validation set
  2. Compare unsupervised Glove/SentenceBERT vs. fine-tuned BERT on ranking performance
  3. Ablate each confounder type (remove paraphrases, irrelevant entities, etc.) and observe impact on MRR

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does performance vary across different domains (general knowledge, music, smart home, etc.)?
- Basis in paper: FQ-Bank limited to knowledge-seeking queries, suggesting different performance across domains
- Why unresolved: Paper focuses on overall performance rather than domain-specific analysis
- What evidence would resolve it: Detailed analysis across diverse domains including knowledge-seeking and non-knowledge-seeking

### Open Question 2
- Question: How can external knowledge sources improve follow-up question retrieval accuracy?
- Basis in paper: Mentions integrating entity information from knowledge bases could be helpful
- Why unresolved: No concrete method provided for integrating external knowledge sources
- What evidence would resolve it: Experimental comparison with and without external knowledge source integration

### Open Question 3
- Question: How does performance change when considering user preferences, time of day, and repetition?
- Basis in paper: Dataset limited to knowledge-seeking queries without considering user preferences, time, or repetition
- Why unresolved: Paper doesn't explore impact of these factors on system performance
- What evidence would resolve it: Analysis incorporating user-specific data and temporal factors

## Limitations
- Reliance on synthetic confounders rather than real-world retrieval noise may not capture full complexity of actual failures
- No external validation on real retrieval systems or human evaluations to confirm transfer to production settings
- Dataset limited to knowledge-seeking queries without considering user preferences, time of day, or longer-term repetition patterns

## Confidence
- Medium: Experimental results show strong performance on synthetic FQ-Bank dataset, but lack external validation
- Medium: Binary classification approach is well-established but may oversimplify relevance ranking
- Low: Assumption that synthetic confounders accurately represent real-world noise patterns is not empirically validated

## Next Checks
1. **Cross-dataset generalization test**: Evaluate trained model on separate, independently collected conversational dataset to assess performance beyond synthetic FQ-Bank environment

2. **Real-world noise simulation**: Replace synthetic confounders with actual top-N retrieval failures from deployed voice assistant system and measure changes in MRR and Hit@1/3

3. **Human preference evaluation**: Conduct user study judging quality and relevance of follow-up suggestions from trained model versus unsupervised baselines to validate that higher MRR corresponds to better user experience
