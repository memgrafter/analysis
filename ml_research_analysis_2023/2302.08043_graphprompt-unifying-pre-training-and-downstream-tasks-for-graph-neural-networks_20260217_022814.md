# GraphPrompt: Unifying Pre-Training and Downstream Tasks for Graph Neural Networks

## Quick Facts
- arXiv ID: 2302.08043
- Source URL: https://arxiv.org/abs/2302.08043
- Reference count: 40
- Primary result: GraphPrompt unifies pre-training and downstream tasks through subgraph similarity, outperforming state-of-the-art methods especially in few-shot learning scenarios.

## Executive Summary
GraphPrompt introduces a framework that unifies pre-training and downstream tasks for graph neural networks by leveraging subgraph similarity as a common task template. The approach employs learnable prompts to guide task-specific aggregation during the ReadOut operation, enabling effective knowledge transfer from pre-training to downstream tasks like node and graph classification. Extensive experiments on five public datasets demonstrate significant performance improvements over state-of-the-art baselines, particularly in few-shot learning scenarios where labeled data is scarce.

## Method Summary
GraphPrompt follows a two-phase approach: pre-training and downstream adaptation. During pre-training, a GNN encoder is trained using self-supervised link prediction on label-free graphs. For downstream tasks, the framework extracts contextual subgraphs for each instance and employs task-specific learnable prompts to guide subgraph aggregation in the ReadOut operation. The prompts are optimized using limited labeled data while the pre-trained GNN weights remain frozen, reducing parameter count and improving few-shot learning performance. The method unifies node and graph classification tasks by converting them into subgraph similarity learning problems.

## Key Results
- GraphPrompt significantly outperforms state-of-the-art baselines on five benchmark datasets (Flickr, PROTEINS, COX2, ENZYMES, BZR)
- Demonstrates superior performance in few-shot learning scenarios (1-5 shot tasks)
- Achieves better parameter efficiency by freezing pre-trained weights and only tuning prompt vectors
- Effectively addresses the discrepancy between pre-training and downstream objectives

## Why This Works (Mechanism)

### Mechanism 1
- Claim: GraphPrompt achieves effective knowledge transfer by unifying pre-training and downstream tasks into a common template based on subgraph similarity.
- Mechanism: By representing both node-level and graph-level instances as subgraphs, all tasks are converted into subgraph similarity learning. This creates compatibility between pre-training and downstream objectives.
- Core assumption: Subgraph similarity is a universal representation that captures relevant information for both pre-training and downstream tasks.
- Evidence anchors:
  - [abstract]: "GraphPrompt not only unifies pre-training and downstream tasks into a common task template, but also employs a learnable prompt to assist a downstream task in locating the most relevant knowledge from the pre-train model in a task-specific manner."
  - [section 4.1]: "Based on the above subgraph definitions for both node- and graph-level instances, we are ready to unify different tasks to follow a common template. Specifically, the link prediction task in pre-training and the downstream node and graph classification tasks can all be redefined as subgraph similarity learning."
  - [corpus]: Weak - the corpus contains related papers but none explicitly confirm the effectiveness of subgraph similarity unification.
- Break condition: If subgraph similarity fails to capture task-relevant information for specific downstream tasks, the unification framework would not bridge the gap between pre-training and downstream objectives.

### Mechanism 2
- Claim: Task-specific learnable prompts enable effective exploitation of pre-trained knowledge for different downstream tasks.
- Mechanism: Learnable prompt vectors guide the ReadOut operation to perform feature-weighted aggregation appropriate for each task. This allows the same pre-trained model to be used differently for node vs. graph classification.
- Core assumption: Different downstream tasks benefit from different aggregation schemes during subgraph representation.
- Evidence anchors:
  - [abstract]: "GraphPrompt employs a learnable prompt to guide task-specific aggregation in the ReadOut operation, allowing different downstream tasks to exploit the pre-trained model in a task-specific manner."
  - [section 4.3]: "In particular, node classification pays more attention to features that are topically more relevant to the target node. In contrast, graph classification tends to focus on features that are correlated to the graph class."
  - [corpus]: Weak - related papers mention prompting but don't provide direct evidence for the specific feature-weighted aggregation approach.
- Break condition: If the learnable prompts cannot effectively differentiate between task requirements or if the aggregation becomes too simplistic, task-specific optimization would fail.

### Mechanism 3
- Claim: Freezing pre-trained weights while only tuning prompts reduces parameter count and improves few-shot learning performance.
- Mechanism: By keeping the GNN weights fixed after pre-training and only updating the prompt vectors, the number of parameters to be learned downstream is drastically reduced, making the approach more parameter-efficient.
- Core assumption: The pre-trained model contains sufficient general knowledge that can be effectively accessed through prompt tuning without fine-tuning.
- Evidence anchors:
  - [abstract]: "GraphPrompt significantly outperforms state-of-the-art baselines, especially in few-shot learning scenarios, by addressing the discrepancy between pre-training and downstream objectives and reducing reliance on labeled data."
  - [section 4.3]: "Note that, the prompt tuning loss is only parameterized by the learnable prompt vector p𝑡 , without the GNN weights. Instead, the pre-trained GNN weights Θ0 are frozen for downstream tasks, as no fine-tuning is necessary."
  - [corpus]: Weak - while the concept exists in NLP, direct evidence for graph prompting parameter efficiency is limited in the corpus.
- Break condition: If the frozen pre-trained weights are not sufficiently general or if the prompts cannot adequately guide task-specific behavior, performance would degrade compared to fine-tuning approaches.

## Architecture Onboarding

- Component map: Pre-train GNN -> Extract subgraphs -> Design prompts -> Prompt tune for downstream tasks -> Evaluate performance
- Critical path: Pre-train GNN → Extract subgraphs → Design prompts → Prompt tune for downstream tasks → Evaluate performance
- Design tradeoffs:
  - Prompt complexity vs. parameter efficiency: Simpler prompts (vectors) are more efficient but may be less expressive than matrices
  - Subgraph radius δ vs. computational cost: Larger radii capture more context but increase computation exponentially
  - Pre-training task choice vs. downstream applicability: Link prediction is general but other tasks might be more suitable for specific domains
- Failure signatures:
  - Poor few-shot performance despite good pre-training: Indicates prompt design is insufficient for task adaptation
  - High variance across runs: Suggests instability in prompt initialization or optimization
  - Degraded performance with larger subgraph radii: Points to over-smoothing issues
- First 3 experiments:
  1. Verify subgraph extraction: Implement and test contextual subgraph extraction for nodes with varying radii
  2. Validate pre-training: Run link prediction pre-training and measure AUC improvement with more training data
  3. Test prompt effectiveness: Compare performance with and without prompts on a simple node classification task

## Limitations

- The subgraph similarity unification mechanism lacks direct empirical validation beyond the main experiments
- The prompt mechanism's effectiveness is not thoroughly examined across diverse task types
- The theoretical justification for why subgraph similarity serves as an effective universal template requires more rigorous analysis
