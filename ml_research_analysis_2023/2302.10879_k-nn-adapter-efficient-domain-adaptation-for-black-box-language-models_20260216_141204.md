# $k$NN-Adapter: Efficient Domain Adaptation for Black-Box Language Models

## Quick Facts
- arXiv ID: 2302.10879
- Source URL: https://arxiv.org/abs/2302.10879
- Authors: 
- Reference count: 13
- Key outcome: kNN-Adapter achieves 1-3 perplexity point gains over kNN-LM across four domains while requiring far fewer trainable parameters than full fine-tuning

## Executive Summary
This paper addresses the challenge of domain adaptation for large language models (LLMs) when fine-tuning is infeasible due to black-box access constraints. The proposed kNN-Adapter method builds upon the kNN-LM framework by adaptively learning interpolation coefficients and temperature parameters to combine the LLM's output with retrieval results from a domain-specific datastore. Experiments across four domains demonstrate that kNN-Adapter significantly improves perplexity over baseline kNN-LM, particularly under limited API access and with scarce target domain data.

## Method Summary
kNN-Adapter adapts black-box LLMs to new domains by building a datastore of domain-specific examples and learning to interpolate between the LLM's output probabilities and kNN retrieval results. The method introduces adaptive interpolation coefficients that can be applied at the token level or context-aware level, allowing different tokens or contexts to blend LLM output and kNN retrieval based on their relative effectiveness. The approach requires training only a small number of parameters (thousands) compared to billions in full fine-tuning, making it suitable for black-box scenarios where internal model modifications are impossible.

## Key Results
- kNN-Adapter achieves 1-3 perplexity point gains over kNN-LM across WikiText-103, BookCorpus, Enron, and Amazon Reviews domains
- Performance improvements are more significant under limited API access (top-k probabilities) and with scarce target domain data
- kNN-Adapter outperforms direct fine-tuning in few-shot settings (<10⁴ tokens) while requiring far fewer trainable parameters
- Analysis shows infrequent tokens in pretraining benefit more from kNN retrieval, and pronouns receive higher interpolation weights in most domains

## Why This Works (Mechanism)

### Mechanism 1: Token-wise Adaptive Interpolation
- Claim: The token-wise adaptive interpolation coefficient improves performance by allowing different tokens to blend LLM output and kNN retrieval based on their relative effectiveness in the target domain.
- Mechanism: Each token has its own learnable interpolation coefficient, with the model learning which tokens benefit more from kNN retrieval versus the original LLM.
- Core assumption: Different tokens have varying reliability between the original LLM and kNN retrieval across domains.
- Evidence anchors: [abstract], [section 2.2.1], [corpus]
- Break condition: If token effectiveness patterns are uniform across domains, the additional complexity provides no benefit.

### Mechanism 2: Context-aware Token-wise Interpolation
- Claim: The context-aware token-wise interpolation captures interactions between specific contexts and token blending effectiveness.
- Mechanism: The model learns a context-dependent adjustment to token-wise coefficients by combining token embeddings with context embeddings.
- Core assumption: The optimal blending ratio for a token depends not just on the token itself but also on the specific context in which it appears.
- Evidence anchors: [section 2.2.1], [section 3.2], [corpus]
- Break condition: If context has minimal impact on token blending effectiveness, this mechanism adds unnecessary complexity.

### Mechanism 3: Limited API Access Compensation
- Claim: The kNN-Adapter is particularly effective when LLM API access is limited because it learns optimal blending strategies using minimal information.
- Mechanism: By learning to interpolate between whatever LLM information is available and kNN retrieval, the adapter compensates for missing probability distribution information.
- Core assumption: Limited API access degrades LLM performance more than kNN retrieval, making intelligent blending especially valuable.
- Evidence anchors: [section 3.3], [section 3.3], [corpus]
- Break condition: If kNN retrieval also requires full probability distributions or is equally affected by API limitations.

## Architecture Onboarding

- Component map: LLM (black-box) -> kNN retrieval module -> kNN-Adapter with learnable interpolation coefficients -> output probability
- Critical path: Context → kNN retrieval → compute pkNN → blend with pLM using learned Λ → output probability
- Design tradeoffs:
  - Single vs. token-wise vs. context-aware coefficients: Increasing granularity improves performance but adds parameters
  - Fixed vs. adaptive temperature: Adaptive temperature offers marginal benefits for significant complexity
  - Number of learnable parameters: Few thousand vs. billions in full fine-tuning
- Failure signatures:
  - No improvement over kNN-LM: Check initialization of Λ (should start around 0.1-0.2)
  - Performance degradation: Check if the datastore is properly built from target domain data
  - Slow convergence: Verify learning rate and batch size settings
- First 3 experiments:
  1. Run kNN-Adapter with token-wise Λ initialized to 0.1 on WikiText-103 and compare perplexity to baseline kNN-LM
  2. Test limited API access scenario with only top-5 probabilities and measure adaptation performance
  3. Vary the initialization value of Λ from 0.0 to 0.5 and observe impact on final perplexity

## Open Questions the Paper Calls Out

The paper does not explicitly call out open questions, but several remain based on the methodology and results.

## Limitations

- Reliance on high-quality domain-specific datastores for effectiveness
- Sensitivity to initialization parameters requiring extensive tuning
- Assumes fixed and accessible LLM encoding function, which may not be available with truly black-box systems
- Effectiveness in multi-domain or continuous adaptation scenarios remains unexplored

## Confidence

**High Confidence Claims:**
- kNN-Adapter outperforms baseline kNN-LM across all tested domains
- The method is effective under limited API access
- kNN-Adapter requires significantly fewer trainable parameters than full fine-tuning

**Medium Confidence Claims:**
- Token-wise adaptive interpolation coefficients provide consistent improvements across domains
- Context-aware adjustments offer additional benefits, particularly for the Enron Email domain
- Infrequent tokens in pretraining benefit more from kNN retrieval

**Low Confidence Claims:**
- The relative importance of different components across all domains
- Generalizability to domains outside the tested corpus
- Performance stability across different LLM architectures beyond GPT-2 variants

## Next Checks

1. **Robustness to initialization**: Systematically test kNN-Adapter performance across a wider range of initialization values (e.g., Λ from 0.05 to 0.5 in increments of 0.05) to quantify sensitivity and identify optimal initialization strategies for different domains.

2. **Scalability analysis**: Evaluate kNN-Adapter's performance and computational overhead when scaling to larger LLM models (e.g., GPT-3 175B parameters) and larger datastores, measuring both perplexity improvements and query latency.

3. **Cross-domain generalization**: Test kNN-Adapter on a diverse set of domains including highly specialized technical domains (medical, legal, scientific) to assess whether the observed token-frequency patterns and interpolation strategies generalize beyond general text domains.
