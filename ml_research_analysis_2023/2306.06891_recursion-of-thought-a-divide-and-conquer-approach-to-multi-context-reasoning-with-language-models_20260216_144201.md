# Recursion of Thought: A Divide-and-Conquer Approach to Multi-Context Reasoning with Language Models

## Quick Facts
- **arXiv ID**: 2306.06891
- **Source URL**: https://arxiv.org/abs/2306.06891
- **Reference count**: 40
- **Key outcome**: RoT enables solving problems with solutions containing hundreds of thousands of tokens by recursively creating multiple contexts using special tokens, dramatically improving reasoning capability on extremely long arithmetic and algorithmic tasks where standard Chain of Thought fails.

## Executive Summary
Recursion of Thought (RoT) is a novel framework that enables language models to solve problems with solutions far exceeding their context limits by recursively creating multiple contexts using special tokens (GO, STOP, THINK, TAIL). The method allows models to divide complex problems into subproblems and solve them within individual context limits, with results combined to solve the overall problem. Extensive experiments with GPT-3 and smaller models demonstrate that RoT dramatically improves reasoning capability, achieving near-perfect accuracy on extremely long arithmetic and algorithmic tasks where standard Chain of Thought fails due to context constraints.

## Method Summary
RoT introduces a special token mechanism that allows language models to perform divide-and-conquer reasoning by recursively creating and managing multiple contexts. When encountering complex subproblems, the model outputs a THINK token, which triggers the creation of a new context for that subproblem. Once solved, the subproblem's answer replaces the THINK token in the parent context. The framework is model-agnostic, requiring only that the model can infer the probability of the next token given a sequence. Training uses supervised learning with ground truth intermediate steps constructed following elementary school math procedures, and evaluation employs an efficient algorithm that avoids duplicate context evaluations while aggregating results across subproblems.

## Key Results
- RoT dramatically improves language models' inference capability to solve problems whose solutions consist of hundreds of thousands of tokens
- Models with RoT achieve near-perfect accuracy on extremely long arithmetic and algorithmic tasks where standard Chain of Thought fails due to context limits
- Extensive experiments with multiple architectures including GPT-3 show RoT's effectiveness without requiring task-specific components like calculators

## Why This Works (Mechanism)

### Mechanism 1
RoT enables language models to handle problems with solutions far exceeding maximum context length by recursively dividing problems into smaller subproblems. The framework introduces special tokens (GO, STOP, THINK, TAIL) that trigger context-related operations. When a complex subproblem is encountered, the model outputs THINK, creating a new context for the subproblem. Once solved, the answer replaces the THINK token in the parent context. This assumes the model can be trained to correctly use these tokens for context management.

### Mechanism 2
By recursively creating multiple contexts, RoT allows models to solve subproblems within individual context limits. Each subproblem is solved in a separate context, with results combined to solve the overall problem. This contrasts with Chain of Thought, which generates all intermediate steps in a single context, quickly exceeding limits for complex problems. The approach assumes subproblems can be defined to allow independent solution within context constraints.

### Mechanism 3
RoT is a model-agnostic framework that only requires the ability to infer the probability of the next token given a sequence. This allows application to various models including GPT-3, Transformers, and LSTMs. The framework assumes the model has sufficient capacity to learn the recursive problem-solving strategy and correctly use the special tokens.

## Architecture Onboarding

- **Component map**: Special Tokens (GO, STOP, THINK, TAIL) -> Context Management System -> Recursive Solver -> Result Aggregator

- **Critical path**:
  1. Initialize context with the main question
  2. Generate subproblems and output THINK tokens
  3. Create new contexts for subproblems
  4. Solve subproblems recursively
  5. Combine results to solve the overall problem

- **Design tradeoffs**:
  - Context limit vs. problem complexity: RoT allows solving more complex problems but requires more context switching
  - Model capacity vs. training data: RoT requires learning a new reasoning strategy, potentially needing more training data
  - Computational cost vs. accuracy: RoT can achieve higher accuracy but may be more computationally expensive due to recursive nature

- **Failure signatures**:
  - Model fails to correctly use special tokens
  - Model gets stuck in infinite recursion loops
  - Model produces incorrect results due to context mismanagement

- **First 3 experiments**:
  1. Implement RoT for simple arithmetic (2-digit addition) and compare to standard CoT
  2. Implement RoT for complex arithmetic (4-digit multiplication) and analyze context length distribution
  3. Implement RoT for simple algorithmic problems (longest common subsequence of short sequences) and evaluate accuracy

## Open Questions the Paper Calls Out

- **Open Question 1**: How can RoT be extended to natural language reasoning tasks beyond synthetic arithmetic and algorithmic problems? The paper demonstrates effectiveness on arithmetic and algorithms but acknowledges current experiments are limited to synthetic tasks.

- **Open Question 2**: Can RoT be trained with less supervision than full ground truth intermediate steps? The paper identifies this as a key limitation and suggests reinforcement learning-based methodologies as possible approaches.

- **Open Question 3**: How can RoT be integrated with length-generalizing architectures to overcome Transformer limitations? The paper notes RoT cannot facilitate length generalization and attributes this to fundamental Transformer limitations.

- **Open Question 4**: What is the optimal strategy for dynamic programming caching in RoT to minimize redundant computations? The paper mentions RoT can utilize dynamic programming for caching but does not explore systematic strategies.

- **Open Question 5**: How does RoT scale with increasing context limits in modern language models? The paper focuses on demonstrating benefits at fixed context limits without exploring how benefits change as context limits increase.

## Limitations

- **Context Management Overhead**: The framework introduces computational overhead through recursive context switching and result aggregation, with no quantitative analysis of efficiency trade-offs
- **Model Capacity Requirements**: Success depends heavily on the model's ability to learn and consistently apply the special token mechanism, potentially requiring larger models for complex problems
- **Generalization to Non-Deterministic Problems**: Evaluation focuses on deterministic arithmetic and algorithmic problems; effectiveness on open-ended reasoning tasks remains untested

## Confidence

**High Confidence Claims**:
- RoT framework can solve problems exceeding context limits by recursive decomposition (supported by experimental results showing solutions with hundreds of thousands of tokens)
- RoT outperforms Chain of Thought on long arithmetic and algorithmic tasks (demonstrated through controlled experiments)
- RoT is model-agnostic and can be applied to various sequence models (verified through experiments with GPT-3 and smaller models)

**Medium Confidence Claims**:
- RoT achieves near-perfect accuracy on extremely long tasks (results are promising but sample sizes for longest problems are limited)
- The special token mechanism is sufficient for general problem decomposition (assumes framework can handle arbitrary problem structures)
- Training data generation procedures are sufficient for learning recursive reasoning (effectiveness depends on quality and diversity of synthetic data)

**Low Confidence Claims**:
- RoT will scale to real-world reasoning tasks beyond arithmetic and algorithms (no evaluation on natural language reasoning or practical applications)
- Computational efficiency is comparable to or better than alternatives (no complexity analysis or runtime comparisons provided)
- The framework will work equally well with all model architectures (only tested on specific architectures, generalization to others untested)
