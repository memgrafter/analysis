# Real-Time Network-Level Traffic Signal Control: An Explicit Multiagent Coordination Method

## Quick Facts
- arXiv ID: 2306.08843
- Source URL: https://arxiv.org/abs/2306.08843
- Reference count: 40
- Key outcome: Proposes an Explicit Multiagent Coordination (EMC) framework for real-time network-level traffic signal control, showing significant improvements in average travel time and scalability compared to existing methods.

## Executive Summary
This paper introduces an Explicit Multiagent Coordination (EMC) framework for real-time network-level traffic signal control. The approach models each intersection as an autonomous agent and uses a balance index to characterize coordination efficiency between neighboring intersections. A decentralized message-passing algorithm is developed to optimize network-level coordination in real-time. The EMC method is evaluated on both synthetic and real-world datasets, demonstrating significant improvements in average travel time and scalability compared to existing reinforcement learning and heuristic methods. The results show that EMC can effectively reduce congestion and improve traffic flow in city-scale scenarios with hundreds of intersections.

## Method Summary
The EMC framework addresses real-time network-level traffic signal control by modeling intersections as autonomous agents in a coordination graph. The method consists of two main phases: network-level coordination (NL-Coor) using a decentralized message-passing algorithm based on Max-sum ADVP, and local individual action improvement (Loc-IAI). The coordination is guided by a balance index that quantifies the sum of squares of queue lengths across movements. The algorithm can interrupt at any time when the real-time limit is reached, with agents selecting optimal decisions based on current messages. The method is proven to guarantee network stability under certain conditions and is evaluated on synthetic and real-world datasets with varying network sizes.

## Key Results
- EMC achieves 10-15% improvement in average travel time compared to state-of-the-art methods like MaxPressure and PressLight
- The method scales effectively to large networks (up to 20×20 intersections) while maintaining real-time performance
- EMC demonstrates superior coordination efficiency through its balance index, which correlates strongly with system performance

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The explicit multiagent coordination (EMC) framework uses a balance index to quantify coordination efficiency between neighboring intersections.
- Mechanism: The balance index is defined as the sum of squares of all movements' queue lengths at an intersection. This metric directly aligns with minimizing average travel time, providing a meaningful proxy for system performance.
- Core assumption: The balance index is a valid proxy for minimizing average travel time, and lower balance values correspond to better traffic flow.
- Evidence anchors:
  - [abstract] "we propose a balance index to explicitly characterize the coordination efficiency among neighbor intersections."
  - [section] "Definition 1. The Balance Index... B(t) =P i∈N Bi(t)... - Break condition: If the relationship between balance index and travel time breaks down (e.g., in highly irregular traffic patterns), the coordination may not effectively minimize travel time.

### Mechanism 2
- Claim: The decentralized message-passing algorithm allows real-time optimization of network-level coordination.
- Mechanism: Agents exchange messages containing cost values related to action variables with their neighbors. The algorithm can interrupt at any time when the real-time limit is reached, and agents select optimal decisions based on current messages.
- Core assumption: The message-passing process converges quickly enough for real-time applications and provides near-optimal solutions within the time constraints.
- Evidence anchors:
  - [abstract] "A decentralized message-passing algorithm is developed to optimize network-level coordination in a real-time manner."
  - [section] "By decentralization, each agent can only exchange messages of coordination function with neighbors. By real-time, the message passing procedure can interrupt at any time when the real time limit is reached and each agent selects the optimal signal decisions by summarizing the current message."
- Break condition: If communication delays become too high or the convergence time exceeds the real-time limit, the algorithm may fail to provide timely solutions.

## Architecture Onboarding

- Component map: Intersection agents -> Balance index calculation -> Network-level coordination (NL-Coor) -> Local individual action improvement (Loc-IAI) -> Signal decisions

- Critical path:
  1. Collect real-time traffic information (queue lengths, saturation flows, turning proportions).
  2. Execute network-level coordination (NL-Coor) to minimize network balance.
  3. Perform local individual action improvement (Loc-IAI) to optimize individual queue balances.
  4. Select and implement the final signal decisions.

- Design tradeoffs:
  - Coordination vs. responsiveness: More coordination may improve network-level performance but could increase computation time.
  - Global vs. local optimization: Balancing network-wide coordination with individual intersection optimization.
  - Centralized vs. decentralized: Choosing between global coordination and local decision-making.

- Failure signatures:
  - Increased average travel time despite coordination efforts.
  - Failure to meet real-time constraints, leading to suboptimal or delayed decisions.
  - Network instability, with queue lengths growing unbounded over time.

- First 3 experiments:
  1. Compare EMC with MaxPressure and PressLight on synthetic datasets with varying network sizes (4x4, 15x15, 20x20).
  2. Evaluate EMC's performance on real-world datasets (NewYork, Manhattan, Jinan, Hangzhou) under different traffic conditions.
  3. Test EMC's robustness to communication delays and time budget variations in large-scale scenarios (e.g., 20x20 network).

- The evaluation focuses primarily on average travel time, potentially overlooking other important performance indicators such as fairness across different regions of the network
