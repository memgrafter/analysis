# IDGI: A Framework to Eliminate Explanation Noise from Integrated Gradients

## Quick Facts
- arXiv ID: 2303.14242
- Source URL: https://arxiv.org/abs/2303.14242
- Reference count: 40
- Primary result: IDGI improves attribution quality by 20-60% on Insertion Score across 11 image classifiers

## Executive Summary
This paper addresses the persistent problem of noise in saliency maps generated by Integrated Gradients (IG) and its variants. The authors identify the source of noise as integrating gradients in the "original direction" rather than the "important direction" - the direction of maximum change. They propose IDGI, a framework that computes attributions using only the important direction, eliminating noise contribution from orthogonal directions. Extensive experiments on 11 image classifiers demonstrate significant improvements across multiple evaluation metrics compared to baseline IG-based methods.

## Method Summary
IDGI is a general framework that modifies existing IG-based methods by integrating gradients only in the important direction (gradient direction) rather than the original path direction. For each integration step, IDGI computes a step size based on the function value change and uses only the normalized gradient direction. This ensures each step explains exactly the change in prediction score, eliminating noise from orthogonal components. The framework preserves theoretical properties of IG methods (Completeness, Sensitivity, Implementation Invariance, Symmetry) while not satisfying Linearity due to its non-linear integration approach.

## Key Results
- Improves Insertion Score by 20-60% across all 11 tested models (DenseNet, InceptionV3, MobileNetV2, ResNet, VGG, Xception)
- Achieves F1 scores of 0.687-0.746 compared to 0.648-0.745 for baseline methods
- Outperforms baseline methods (IG, GIG, BlurIG, VG) across all evaluation metrics: AIC, SIC, ROC-AUC, MAE
- Demonstrates consistent improvement across diverse model architectures and evaluation measures

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The noise in saliency maps comes from integrating gradients along the original path direction rather than the important direction of maximum function change.
- Mechanism: The original path direction can be decomposed into two components - the important direction (gradient direction) and the noise direction (orthogonal to gradient). Since the true gradient is orthogonal to the noise direction, integrating along the noise direction adds no meaningful information to the attribution.
- Core assumption: The gradient direction represents the maximum rate of change of the function, and any orthogonal component contributes zero to the function value change.
- Evidence anchors:
  - [abstract] "analytically identify the source of this noise as stemming from integrating gradients in the 'original direction' rather than the 'important direction' - the direction of maximum change"
  - [section 3.1] "Each path segment has a noise direction where gradient integration with that direction contributes nothing to output values"

### Mechanism 2
- Claim: IDGI eliminates noise by using only the important direction in each integration step, computing the exact attribution needed to explain the function value change.
- Mechanism: Instead of multiplying the gradient by the original path segment distance, IDGI computes a step size based on the function value change and uses only the gradient direction. This ensures each step explains exactly the change in prediction score.
- Core assumption: The function evaluation along the path is strictly monotonic, ensuring consistent attribution direction.
- Evidence anchors:
  - [abstract] "IDGI, a framework that computes attributions using only the important direction, eliminating the noise contribution from the orthogonal noise direction"
  - [section 3.2] "IDGI then determines the unit important direction vector of g as g/|g| and the step size fc(xj+1)−fc(xj)/|g| rather than multiplying g with the distance xj+1 − xj"

### Mechanism 3
- Claim: IDGI preserves theoretical properties of IG methods while eliminating noise, maintaining interpretability guarantees.
- Mechanism: IDGI satisfies Completeness, Sensitivity(a/b), Implementation Invariance, and Symmetry preserving axioms of IG methods, but not Linearity due to its non-linear integration approach.
- Core assumption: The underlying IG-based method satisfies certain axioms, which IDGI inherits.
- Evidence anchors:
  - [section 3.3] "IDGI satisfies all of them except Linearity" and detailed discussion of each axiom
  - [abstract] "IDGI, a general framework to eliminate the explanation noise in IG-based methods, and investigate its theoretical properties"

## Foundational Learning

- Concept: Riemann Integration and numerical approximation
  - Why needed here: IDGI modifies the Riemann integration process used by all IG-based methods, so understanding how numerical integration works is essential
  - Quick check question: How does Riemann integration approximate a definite integral, and what are its sources of numerical error?

- Concept: Conservative vector fields and gradient orthogonality
  - Why needed here: The key insight that noise direction is orthogonal to gradient relies on understanding conservative vector fields and their properties
  - Quick check question: Why is the gradient always orthogonal to level sets of a function, and what does this imply for function value changes?

- Concept: Attribution methods and saliency map evaluation metrics
  - Why needed here: IDGI's performance is evaluated using multiple metrics (Insertion Score, AIC, SIC, F1, ROC-AUC, MAE), requiring understanding of what these measure
  - Quick check question: What's the difference between AIC and SIC, and why would MS-SSIM be a better information level measure than normalized entropy?

## Architecture Onboarding

- Component map: Input Image -> Path Generation (IG/GIG/BlurIG) -> Gradient Computation -> Important Direction Extraction -> Step Size Calculation -> Attribution Accumulation -> Output Attribution Map
- Critical path: For each point on the path: compute gradient → extract important direction → calculate step size → accumulate attribution
- Design tradeoffs: IDGI trades computational simplicity (single path) for noise reduction, versus multiple-path methods like SmoothGrad that average out noise but require more computation
- Failure signatures: Zero gradients along path, non-monotonic function behavior, incorrect gradient computation
- First 3 experiments:
  1. Apply IDGI to a simple 2D function with known gradient and verify noise reduction on synthetic data
  2. Compare IDGI with IG on a pre-trained model using Insertion Score on a small validation set
  3. Test IDGI with GIG and BlurIG paths on the same model to verify orthogonal improvement across methods

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions, but the limitations section identifies several areas for future work.

## Limitations
- Limited to image classification models and does not test on other domains (text, tabular, graph data)
- Computational overhead is not analyzed, leaving scalability questions unanswered
- No systematic exploration of parameter sensitivity (step size, number of steps) or convergence properties

## Confidence
- **High Confidence**: The core mechanism of eliminating noise by using only the gradient direction (Mechanism 2) - well-supported by mathematical formulation and experimental results.
- **Medium Confidence**: The theoretical analysis of noise sources and the claim that IDGI preserves IG properties (Mechanism 1 and 3) - supported by axiomatic analysis but limited to specific function classes.
- **Low Confidence**: The claim that MS-SSIM is a superior information level measure compared to normalized entropy - while proposed as a contribution, lacks extensive comparative analysis.

## Next Checks
1. Apply IDGI to transformer-based vision models (e.g., ViT) to verify noise reduction effectiveness beyond CNN architectures.

3. Investigate IDGI's behavior on non-monotonic functions and functions with discontinuous gradients to identify failure modes and limitations.
