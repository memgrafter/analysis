# RePAD2: Real-Time, Lightweight, and Adaptive Anomaly Detection for Open-Ended Time Series

## Quick Facts
- arXiv ID: 2303.00409
- Source URL: https://arxiv.org/abs/2303.00409

## Executive Summary
This paper introduces RePAD2, a lightweight real-time anomaly detection approach for open-ended time series, to address the resource exhaustion issue faced by its predecessor RePAD when working on long time series. RePAD2 improves RePAD by redesigning the adaptive detection threshold using a sliding window concept, which restricts the number of historical AARE values considered in threshold calculation. Experimental results based on real-world time series datasets demonstrate that RePAD2 can offer comparable detection accuracy and slightly less time consumption than RePAD and ReRe while effectively addressing the resource exhaustion issue. The sliding window size has a significant impact on the detection accuracy and time consumption of RePAD2, and it is recommended to use a sufficiently large sliding window for optimal performance.

## Method Summary
RePAD2 introduces a sliding window mechanism to RePAD's adaptive anomaly detection framework. Instead of using all historical AARE values to calculate detection thresholds, RePAD2 maintains only the most recent W AARE values in a fixed-size buffer. The detection threshold is computed using the Three-Sigma Rule on this sliding window, significantly reducing memory growth while maintaining detection accuracy. The approach employs an LSTM-based one-step-ahead predictor and triggers retraining when anomaly detection frequency exceeds a threshold.

## Key Results
- RePAD2 effectively addresses resource exhaustion by bounding historical AARE values to a sliding window
- Larger sliding window sizes improve precision by stabilizing detection thresholds
- Time consumption slightly decreases with larger window sizes due to reduced computational overhead

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Sliding window reduces memory growth by capping historical AARE values.
- Mechanism: The detection threshold is recomputed using only the most recent 𝑊 AARE values rather than all historical ones, preventing unbounded memory use.
- Core assumption: Older AARE values become less relevant for detecting current anomalies due to concept drift.
- Evidence anchors:
  - [abstract] "RePAD2 improves RePAD by redesigning the adaptive detection threshold using a sliding window concept, which restricts the number of historical AARE values considered in threshold calculation."
  - [section 4] "Instead of relying on all historical AARE values to calculate the detection threshold, RePAD2 only calculates the detection threshold based on a fixed number of recently derived AARE values."
- Break condition: If concept drift occurs faster than the sliding window, older values become irrelevant too quickly and detection accuracy suffers.

### Mechanism 2
- Claim: Larger sliding window size improves precision by stabilizing the detection threshold.
- Mechanism: More historical AARE values in the threshold calculation reduce sensitivity to outliers, lowering false positives.
- Core assumption: AARE values over time form a relatively stable distribution that converges as more samples are included.
- Evidence anchors:
  - [section 5.1] "When 𝑊 was increased to 4032 or 8064, the threshold curve became flatter (see Figures 6 and 7) since RePAD2 used more historical AARE values to calculate its detection threshold."
  - [section 5.1] "it is recommended to choose a sufficiently long sliding window (e.g., 4032) for RePAD2 so as to reduce false positives."
- Break condition: When the time series experiences abrupt regime shifts, a large window may slow adaptation and miss new patterns.

### Mechanism 3
- Claim: Sliding window slightly reduces time consumption during LSTM retraining.
- Mechanism: Fewer AARE values to average and compute standard deviation leads to marginal speedup per retraining iteration.
- Core assumption: The computational overhead of maintaining and processing a larger AARE history is proportional to its size.
- Evidence anchors:
  - [section 5.1] "When 𝑊 was increased, the retraining ratio of RePAD2 reduced and stabilized, and it is comparable to that of RePAD and less than that of ReRe."
  - [section 5.2] "the time consumption of RePAD2 (as shown in Table 9) slightly reduced as 𝑊 was increased, and RePAD2 is slightly more efficient than RePAD and ReRe."
- Break condition: If retraining occurs very frequently, the constant factor savings become negligible compared to LSTM training time.

## Foundational Learning

- Concept: Sliding window in time series processing
  - Why needed here: It bounds memory usage and controls how much historical context influences the current detection threshold.
  - Quick check question: What happens to the detection threshold if the sliding window is too small relative to the data's periodicity?

- Concept: Three-Sigma Rule for anomaly detection
  - Why needed here: It provides a statistically grounded method to set detection thresholds based on mean and standard deviation of AARE values.
  - Quick check question: Under what condition might the Three-Sigma Rule produce overly conservative thresholds?

- Concept: LSTM-based one-step-ahead prediction
  - Why needed here: It enables the system to forecast the next data point and compare it to the observed value to compute AARE.
  - Quick check question: How does changing the look-back window size from 3 to a larger value affect prediction accuracy and computational cost?

## Architecture Onboarding

- Component map: Data ingestion -> Sliding window AARE buffer -> Threshold calculator -> LSTM predictor -> Anomaly decision engine
- Critical path: New data point -> AARE calculation -> Threshold update -> LSTM retraining (if needed) -> Anomaly output
- Design tradeoffs:
  - Window size vs. memory: Larger 𝑊 improves precision but increases threshold computation time and memory use.
  - Frequency of threshold update vs. responsiveness: Per-point updates allow adaptation but cost more computation.
  - Retraining trigger sensitivity: Strict triggers reduce false positives but may delay adaptation to real changes.
- Failure signatures:
  - False positives: Likely caused by small sliding window or threshold instability.
  - False negatives: May result from large window delaying adaptation to new patterns.
  - Resource exhaustion: Original RePAD without sliding window accumulates unbounded AARE history.
- First 3 experiments:
  1. Compare RePAD2 with 𝑊=100 vs. 𝑊=1000 on a synthetic step-change dataset to measure precision and retraining frequency.
  2. Benchmark time per point and memory usage on a long synthetic series (e.g., 1M points) to confirm resource bounds.
  3. Test on a multivariate open-ended series to identify any assumption violations in univariate AARE aggregation.

## Limitations
- The optimal sliding window size appears dataset-dependent, requiring manual tuning
- The study only evaluates univariate time series, leaving multivariate extension effectiveness unverified
- Computational savings from the sliding window are marginal compared to the dominant LSTM retraining cost

## Confidence
- **High**: The sliding window successfully bounds memory usage and prevents resource exhaustion (supported by experimental results and clear mechanism).
- **Medium**: Larger sliding windows improve precision by stabilizing thresholds (supported by empirical observations but requires more diverse datasets for generalization).
- **Medium**: The approach offers comparable detection accuracy to RePAD and ReRe (based on the specific datasets tested, but limited to the evaluated scenarios).

## Next Checks
