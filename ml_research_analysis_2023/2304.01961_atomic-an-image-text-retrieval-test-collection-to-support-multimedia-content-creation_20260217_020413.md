# AToMiC: An Image/Text Retrieval Test Collection to Support Multimedia Content Creation

## Quick Facts
- arXiv ID: 2304.01961
- Source URL: https://arxiv.org/abs/2304.01961
- Reference count: 40
- Key outcome: AToMiC dataset addresses limitations of existing image-text retrieval datasets by leveraging Wikipedia's hierarchical structure and image-document associations to create a more realistic testbed for multimedia content creation.

## Executive Summary
This paper introduces AToMiC, a dataset for image/text cross-modal retrieval designed to support multimedia content creation tasks. The authors argue that existing datasets like COCO or Flickr30k oversimplify the relationship between images and text, limiting their applicability to real-world multimedia authoring. AToMiC addresses this by leveraging Wikipedia's large-scale image-document associations to provide more diverse and hierarchical text collections and richer image styles. The dataset defines two retrieval tasks—image suggestion (T2M) and image promotion (M2T)—both based on realistic user needs in multimedia authoring. Experiments using transformer-based models show that while BM25 with oracle captions performs best, transformer models still achieve reasonable effectiveness on large corpora, establishing AToMiC as a challenging testbed for cross-modal retrieval in multimedia contexts.

## Method Summary
The AToMiC dataset is constructed from Wikipedia articles, using image-section associations as sparse binary relevance judgments. The dataset includes training, validation, and test splits with approximately 3M training texts, 17K validation texts, 9K test texts, and 3M training images. Two retrieval tasks are defined: image suggestion (T2M) where text sections retrieve relevant images, and image promotion (M2T) where images retrieve relevant text sections. The dataset leverages Wikipedia's hierarchical structure including page/section titles, hierarchy, and context descriptions. Evaluation uses MRR@10, R@10, and R@1K metrics, comparing BM25 with oracle captions against transformer models (CLIP, BLIP, FLAVA, BM25). Fine-tuning experiments use contrastive loss with in-batch negatives for 9,075 steps.

## Key Results
- Transformer models like OpenCLIP ViT-G-14 achieve reasonable effectiveness (MRR@10 ~ 0.09) on large corpora (~10M items) despite sparse labels
- BM25 with oracle captions significantly outperforms all transformer approaches, highlighting room for improvement
- Fine-tuned OpenCLIP models show catastrophic forgetting on COCO after training on AToMiC
- Sparse binary relevance judgments from Wikipedia associations enable scalable evaluation without manual annotations

## Why This Works (Mechanism)

### Mechanism 1: Wikipedia's hierarchical structure enables richer retrieval tasks
- Claim: Leveraging Wikipedia's hierarchical text and image-document associations enables richer and more realistic multimodal retrieval tasks
- Mechanism: Wikipedia's structure provides sections, hierarchies, and contextual descriptions that go beyond simple image-caption pairs, enabling more complex and contextually grounded relevance judgments
- Core assumption: Wikipedia editors' image-section associations reflect realistic multimedia content creation intents
- Evidence anchors: [abstract] "leverage hierarchical structures and diverse domains of texts, styles, and types of images" and [section] "we introduce the Authoring Tools for Multimedia Content (AToMiC) dataset to study this gap"
- Break condition: If Wikipedia's editorial biases or incomplete coverage misalign with real-world authoring needs, the dataset's relevance judgments may not generalize

### Mechanism 2: Sparse relevance labels enable scalable evaluation
- Claim: Sparse relevance labels derived from Wikipedia associations enable scalable evaluation of cross-modal retrieval without requiring manual annotations
- Mechanism: Binary associations between sections and images serve as proxy relevance judgments, enabling large-scale experiments without dense annotations
- Core assumption: Binary associations (section-image linked vs. not linked) are sufficient to model real retrieval needs in multimedia authoring
- Evidence anchors: [abstract] "relevance in this context is operationalized as 'this image would be appropriate to attach to this section'" and [section] "We define all other pairs as non-relevant"
- Break condition: If many relevant images are falsely marked non-relevant, retrieval metrics will not reflect true system performance

### Mechanism 3: Pretrained vision-language transformers enable domain adaptation
- Claim: Pretrained vision-language transformers like CLIP can be fine-tuned on the dataset to improve cross-modal retrieval performance
- Mechanism: Transfer learning from contrastive pretraining allows models to adapt to the domain-specific characteristics of Wikipedia's image-text pairs
- Core assumption: Vision-language transformers capture transferable representations useful for retrieval in this domain
- Evidence anchors: [abstract] "Experiments using transformer-based models... show that while BM25 with oracle captions performs best, transformer models like OpenCLIP ViT-G-14 still achieve reasonable effectiveness"
- Break condition: If fine-tuning leads to catastrophic forgetting or the dataset's distribution is too different, transfer benefits may vanish

## Architecture Onboarding

- Component map: Data ingestion -> Text/image parsing from Wikipedia -> Relevance judgment construction -> Dataset splits -> Model encoding (CLIP/BLIP/FLAVA) -> Retrieval pipeline (BM25 or FAISS) -> Evaluation (MRR@10, R@10, R@1K)
- Critical path: Data ingestion -> Text/image parsing -> Relevance judgment construction -> Model training/fine-tuning -> Retrieval experiments -> Evaluation
- Design tradeoffs:
  - Using sparse binary relevance judgments simplifies dataset creation but may reduce evaluation fidelity
  - Fine-tuning vision-language transformers enables adaptation but risks catastrophic forgetting
  - Expanding corpus to include non-associated images/texts improves realism but increases noise
- Failure signatures:
  - Poor MRR@10 despite high R@1K suggests rank position issues
  - Fine-tuned models underperforming on validation/test sets suggest overfitting or catastrophic forgetting
  - Low coverage between BM25 and transformer-based models indicates complementary information gaps
- First 3 experiments:
  1. Run zero-shot retrieval using pre-trained models (e.g., OpenCLIP ViT-G-14) on AToMiC-Base setting to establish baseline
  2. Fine-tune OpenCLIP ViT-B-32 and ViT-L-14 models on training data and evaluate on validation set
  3. Conduct ablation study removing different text fields (title, context) to assess feature importance

## Open Questions the Paper Calls Out

### Open Question 1: Text feature contributions by image type
- Question: How do specific text features (e.g., context vs. titles) differentially contribute to retrieval effectiveness for different image types (e.g., photographs vs. artworks)?
- Basis in paper: [explicit] The authors performed an ablation study on text fields using OpenCLIP ViT-L-14 and found that context (S) was most useful, but did not analyze differential contributions by image type
- Why unresolved: The paper focused on overall effectiveness but did not explore how different text features interact with different image styles or domains
- What evidence would resolve it: Experiments measuring retrieval effectiveness for different text features (titles, hierarchy, context) broken down by image style categories (photographs, artworks, maps, etc.) using the same models

### Open Question 2: Fine-tuning vs. zero-shot transfer
- Question: Would fine-tuning vision-language models on AToMiC data improve performance on this domain compared to zero-shot transfer from image-caption datasets?
- Basis in paper: [explicit] The authors conducted fine-tuning experiments but observed mixed results - while R@1K improved, MRR@10 did not improve and the models performed worse on COCO after fine-tuning on AToMiC
- Why unresolved: The paper suggests room for improvement in their fine-tuning approach but did not explore alternative fine-tuning strategies or architectures
- What evidence would resolve it: Experiments with different fine-tuning strategies (e.g., gradual unfreezing, curriculum learning, contrastive loss variations) and architectures that explicitly model the section-image relationship

### Open Question 3: Popularity bias impact
- Question: How does the popularity bias in Wikipedia affect retrieval effectiveness metrics and model training?
- Basis in paper: [explicit] The authors note that Wikipedia's natural distribution introduces popularity bias and that macro-averaging over all queries may not adequately capture long-tail cases
- Why unresolved: The paper acknowledges this issue but did not investigate its impact on retrieval metrics or propose methods to mitigate it
- What evidence would resolve it: Analysis of retrieval performance broken down by article category popularity, experiments with reweighting schemes during training, and evaluation using metrics that account for popularity bias

## Limitations
- Sparse binary relevance judgments may miss many relevant image-text pairs and reduce evaluation fidelity
- Wikipedia's popularity bias affects both dataset construction and evaluation metrics
- Focus on English Wikipedia limits cross-lingual applicability
- Catastrophic forgetting occurs when fine-tuning models on AToMiC data

## Confidence
- Confidence in dataset utility claims: Medium - design addresses real-world needs but evaluation constrained by sparse labels
- Confidence in cross-modal retrieval effectiveness: Medium-High - reasonable transformer performance despite limitations
- Confidence in dataset's representation of multimedia authoring needs: Medium - acknowledged Wikipedia editorial biases may limit generalizability
