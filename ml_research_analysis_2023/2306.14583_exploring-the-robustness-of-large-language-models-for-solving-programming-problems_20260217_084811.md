# Exploring the Robustness of Large Language Models for Solving Programming Problems

## Quick Facts
- arXiv ID: 2306.14583
- Source URL: https://arxiv.org/abs/2306.14583
- Reference count: 40
- Primary result: Large language models show varying robustness to superficial modifications in programming problem descriptions, with InstructGPT and ChatGPT demonstrating superior robustness compared to Codex and CodeGen

## Executive Summary
This paper investigates whether large language models truly understand programming problem descriptions or simply retrieve source code from training data based on superficial cues. The authors systematically test the robustness of several prominent LLMs (InstructGPT, ChatGPT, Codex, and CodeGen) by formatting problem descriptions in different ways and modifying problem descriptions through variable renaming, string anonymization, synonym replacement, and inverse specification. The experimental results reveal significant performance differences across models and formatting conditions, with newer models like InstructGPT and ChatGPT showing substantially higher robustness to superficial modifications compared to older models like Codex and CodeGen.

## Method Summary
The authors conducted experiments using the APPS dataset, testing four LLMs (InstructGPT, ChatGPT, Codex, and CodeGen) on programming problems formatted in five different ways: Raw HTML, parsed plain text, AlphaCode-inspired, APPS-inspired, and fully Markdown-formatted. They then systematically modified problem descriptions by randomizing variable names, anonymizing output strings, replacing words with synonyms, and inverting problem specifications. For each model and condition, they measured the solved rate - the percentage of problems where the generated code produced correct outputs. The experiments compared performance across these different formatting and modification conditions to assess model robustness.

## Key Results
- Codex showed a 9.0% improvement in solved rate between worst and best formatting conditions
- Prompt formatting significantly affected performance, with Codex improving by 25.9% and CodeGen by 14.7% across different formats
- InstructGPT and ChatGPT demonstrated substantially higher robustness to superficial modifications compared to Codex and CodeGen
- Codex was particularly sensitive to randomized variable names, showing significant performance degradation

## Why This Works (Mechanism)
The observed robustness differences stem from the models' training data composition, architectural differences, and fine-tuning approaches. InstructGPT and ChatGPT were fine-tuned with reinforcement learning from human feedback (RLHF), which likely improved their ability to understand semantic intent rather than relying on surface-level patterns. Codex and CodeGen, while trained on more code-specific data, appear to have learned stronger correlations between specific problem wording patterns and code solutions, making them more vulnerable to superficial modifications that break these spurious correlations.

## Foundational Learning
- Programming problem understanding: LLMs must parse natural language descriptions and map them to executable code - quick check: can the model generate code from varied problem formulations?
- Spurious correlation detection: Models may rely on surface patterns rather than semantic understanding - quick check: does performance drop when superficial features are altered?
- Robustness evaluation methodology: Systematic testing requires controlled modifications to isolate specific model capabilities - quick check: are modifications truly superficial or do they alter semantic content?

## Architecture Onboarding
**Component Map:** Input processing -> Semantic understanding -> Code generation -> Output validation
**Critical Path:** Problem description formatting → Model input → Code generation → Execution and testing
**Design Tradeoffs:** Specialized code models (Codex/CodeGen) vs. general-purpose models (InstructGPT/ChatGPT) trade code-specific training data for broader generalization capabilities
**Failure Signatures:** Performance drops on variable renaming indicate over-reliance on specific naming patterns; synonym sensitivity suggests pattern matching rather than semantic understanding
**3 First Experiments:** 1) Test models on identical problems with systematic variable name variations, 2) Evaluate performance on problems with semantically equivalent but syntactically different descriptions, 3) Measure robustness to code-style formatting conventions (camelCase vs snake_case)

## Limitations
- The study focuses on a relatively narrow set of problem modifications that may not capture deeper semantic understanding
- Sample size and specific problem set details are not provided, limiting generalizability
- The modifications tested may not represent real-world usage scenarios where problems are described in diverse ways

## Confidence
High confidence: The systematic experimental approach and clear performance differences between models under different formatting conditions provide robust evidence for the main claims.
Medium confidence: Claims about specific mechanisms (e.g., Codex relying on variable names) are plausible but alternative explanations cannot be definitively ruled out.

## Next Checks
1. Conduct ablation studies using the same problem set with additional formatting variations to verify the mechanism behind performance differences
2. Test the models on a larger, more diverse problem set from multiple sources to assess whether robustness patterns generalize
3. Perform human evaluation of model outputs to determine whether performance differences reflect genuine understanding versus pattern matching
