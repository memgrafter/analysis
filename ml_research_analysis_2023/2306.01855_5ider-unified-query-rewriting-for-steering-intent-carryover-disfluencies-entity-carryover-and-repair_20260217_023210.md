# 5IDER: Unified Query Rewriting for Steering, Intent Carryover, Disfluencies, Entity Carryover and Repair

## Executive Summary
This paper introduces 5IDER, a unified non-autoregressive query rewriting architecture that handles five conversational use-cases—steering, intent carryover, disfluencies, entity carryover, and repair—as well as their compositions. The model is built on an encoder-only framework with three distinct heads for replacement detection, replacement resolution, and deletion, each trained with separate supervision. 5IDER achieves strong performance on both single-task and multi-task experiments, demonstrating data efficiency and speed advantages over T5-Small. The approach is validated on both single-task and compositional multi-task scenarios, highlighting its ability to generalize across conversational challenges.

## Method Summary
5IDER is a unified, non-autoregressive query rewriting model designed to handle five distinct conversational phenomena—steering, intent carryover, disfluencies, entity carryover, and repair—and their combinations. It uses an encoder-only architecture with three specialized heads: replacement detection (identifies which tokens to modify), replacement resolution (generates new tokens), and deletion (decides if tokens should be removed). Each head is supervised separately. The model is trained on synthetic data generated for single and compositional use-cases, and leverages start and end position indices to guide rewriting. By explicitly modeling the relationships between original and rewritten tokens, 5IDER achieves significant improvements in compositional tasks while being 15x smaller and 25x faster than T5-Small.

## Key Results
- 5IDER outperforms T5-Small on compositional query rewriting tasks, achieving 88.4% average accuracy in multi-task experiments with 15x fewer parameters and 25x lower latency.
- In single-task settings, 5IDER reaches 88.3% average exact match accuracy, demonstrating competitive performance against strong baselines.
- 5IDER exhibits strong data efficiency, requiring only 500 training samples to surpass T5 trained with 10k samples in compositional tasks.

## Why This Works (Mechanism)
The unified non-autoregressive architecture of 5IDER enables efficient and targeted query rewriting by decomposing the rewriting process into three modular, supervised tasks: detecting tokens to replace, resolving replacements, and deciding on deletions. This decomposition allows the model to explicitly model token-level relationships, making it well-suited for compositional tasks that combine multiple conversational phenomena. The encoder-only design avoids the computational cost of autoregressive decoding, while synthetic data generation provides ample training for both single and compositional scenarios. The approach balances expressiveness and efficiency, enabling strong performance with a smaller, faster model.

## Foundational Learning
- **Non-autoregressive query rewriting**: Rewriting without generating output token-by-token, improving speed and efficiency.
- **Synthetic data generation**: Automatically creating training examples for single and compositional use-cases to enable robust multi-task learning.
- **Multi-task learning**: Jointly training on multiple conversational phenomena to capture their interactions and improve generalization.
- **Encoder-only architectures**: Using only an encoder (no decoder) to reduce computational cost while retaining sufficient expressiveness for structured rewriting tasks.
- **Replacement detection and resolution**: Identifying and generating specific token replacements rather than rewriting entire utterances, improving precision.

## Architecture Onboarding

**Component Map:** Input Query -> Encoder -> Replacement Detection Head, Replacement Resolution Head, Deletion Head -> Output (Rewritten Query)

**Critical Path:** Input Query -> Encoder Embeddings -> Three heads (detection, resolution, deletion) -> Output Token Indices & Deletions -> Final Rewritten Query

**Design Tradeoffs:** The model sacrifices the full generative capacity of autoregressive models for speed and parameter efficiency. The explicit modeling of token positions and deletions aids precision but requires careful supervision. Using synthetic data for compositional tasks enables scalability but may not fully capture real-world conversational complexity.

**Failure Signatures:** If the model fails to detect replacements or deletions accurately, it may output incomplete or incorrect rewritten queries. Over-reliance on synthetic data could lead to poor generalization on naturally occurring conversational phenomena not seen during training.

**First Experiments:**
1. Train and evaluate 5IDER on a single conversational use-case (e.g., steering) to verify component functionality.
2. Combine two use-cases (e.g., steering + disfluencies) in a compositional setting to test the model’s ability to generalize.
3. Conduct an ablation study by removing one of the three heads to assess its impact on performance.

## Limitations
- The model is only evaluated on the five defined conversational use-cases and their synthetic compositions, with no assessment of performance on naturally occurring conversational phenomena beyond these scenarios.
- Reliance on synthetic data generation may not fully capture the complexity and diversity of real user utterances.
- The necessity and relative contribution of each architectural component (replacement detection, replacement resolution, deletion) are not fully clarified through ablation studies.
