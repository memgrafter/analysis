# Sanity Checks for Saliency Methods Explaining Object Detectors

## Quick Facts
- arXiv ID: 2306.02424
- Source URL: https://arxiv.org/abs/2306.02424
- Reference count: 40
- Primary result: Explanation quality is more dependent on detector model than explanation method itself

## Executive Summary
This paper investigates the reliability of saliency methods for explaining object detector decisions through systematic sanity checks. The authors extend established sanity check frameworks from classification to object detection, evaluating three popular detectors (Faster R-CNN, SSD, and EfficientDet-D0) with four explanation methods (Guided Backpropagation, Integrated Gradients, and their SmoothGrad variants). Their comprehensive analysis reveals that explanation quality is primarily determined by the underlying detector architecture rather than the explanation method used, with EfficientDet-D0 consistently producing the most interpretable results.

## Method Summary
The study applies model and data randomization tests to evaluate explanation methods for object detectors. Model randomization progressively removes information from the detector, while data randomization gradually degrades input quality. The authors use SSIM (Structural Similarity Index) for quantitative evaluation and qualitative analysis to assess explanation interpretability. They test both classification and bounding box decisions across three object detection architectures and four explanation methods, systematically comparing how each responds to randomization.

## Key Results
- Explanation quality depends more on detector model architecture than explanation method
- EfficientDet-D0 consistently produces most interpretable explanations and passes sanity checks with minimal issues
- SSD and Faster R-CNN show greater sensitivity to randomization, with Faster R-CNN exhibiting checkerboard artifacts

## Why This Works (Mechanism)
The effectiveness of sanity checks stems from their ability to reveal whether explanations capture meaningful detector behavior versus superficial patterns. By systematically degrading either the model (removing learned features) or the data (reducing input quality), the tests expose whether explanations remain consistent with the actual decision-making process. When explanations fail to degrade appropriately with model or data degradation, they likely capture spurious correlations rather than genuine decision logic.

                          -> Regression Head -> Bounding Boxes
                                  -> Saliency Method -> Explanation Maps

Critical Path:
Input -> Detector Forward Pass -> Feature Extraction -> Classification/Regression -> Saliency Computation

Design Tradeoffs:
- Detector complexity vs. explanation quality
- Computational efficiency vs. explanation resolution
- Granularity of explanations (per-class vs. combined)

Failure Signatures:
- Checkerboard artifacts in explanations
- Insensitivity to model/data randomization
- Misalignment between explanation maps and actual detections

## Limitations
- Limited to three object detection architectures and four explanation methods
- SSIM may not fully capture explanation quality for object detection
- Qualitative analysis is subjective and may not be reproducible
- No investigation of computational efficiency for practical deployment
