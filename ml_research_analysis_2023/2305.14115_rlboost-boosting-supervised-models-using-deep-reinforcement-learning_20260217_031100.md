# RLBoost: Boosting Supervised Models using Deep Reinforcement Learning

## Quick Facts
- **arXiv ID**: 2305.14115
- **Source URL**: https://arxiv.org/abs/2305.14115
- **Reference count**: 7
- **Key outcome**: RLBoost outperforms state-of-the-art algorithms like LOO, DataShapley, and DVRL across various tabular and image datasets, achieving higher accuracy scores and better stability, especially in the presence of noise.

## Executive Summary
RLBoost introduces a novel approach that leverages deep reinforcement learning, specifically Proximal Policy Optimization (PPO), to evaluate the quality of training data for supervised learning models. The method treats data selection as a bandit problem where the agent selects a subset of records from a batch to maximize the model's validation score. By using multi-attention strategies via Transformer Encoders, RLBoost captures contextual information of data samples, demonstrating superior performance over existing data valuation methods across multiple datasets with varying noise levels.

## Method Summary
RLBoost uses PPO as a bandit agent to select data subsets from training datasets, treating each selection as a single-step decision with immediate reward. The method employs a value function to estimate the complete batch's value and uses Transformer Encoders with a learnable CLS token to capture contextual information across the batch. The agent is trained for 1e5 steps with a batch size of 64, using logistic regression as the internal estimator. The approach is evaluated on tabular datasets (Adult, A5A, W5A, binarized CIFAR10) and image datasets (MNIST) with varying noise rates (0%, 15%, 30%).

## Key Results
- RLBoost achieves higher accuracy scores compared to LOO, DataShapley, and DVRL across multiple datasets
- The method demonstrates superior stability and performance in the presence of noise (15% and 30% noise rates)
- ROC curves show RLBoost's effectiveness in detecting noisy data, with better AUC scores than baseline methods

## Why This Works (Mechanism)

### Mechanism 1
- Claim: RLBoost treats data selection as a bandit problem by reformulating PPO to work without trajectories.
- Mechanism: By setting γ=0 and assuming a single-step decision, the generalized advantage estimation collapses to A(s,a,π) = r - Vϕ(s,π). The policy loss becomes Lclip(θ) = min(δR(θ), δclip(R(θ), 1-ϵ, 1+ϵ)), and the critic loss becomes LV F(ϕ) = ||r - Vϕ(s,π)||²₂.
- Core assumption: The immediate reward (difference in validation score) is sufficient to capture the data's value without considering future states.
- Evidence anchors: Experimental results show RLBoost outperforms state-of-the-art algorithms; simplified approach established as starting point for improvement.
- Break condition: If the data's value depends on context beyond the immediate batch, the single-step formulation will fail to capture interactions.

### Mechanism 2
- Claim: The Transformer encoder with a CLS token captures contextual information across the entire batch, allowing the value function to estimate the batch's overall impact.
- Mechanism: Each data sample is vectorized and passed through L Transformer encoders. A learnable CLS token aggregates the contextual representation of the full batch. This CLS output feeds the critic to predict whether the current batch selection will improve the validation score.
- Core assumption: The CLS token's learned representation effectively summarizes the batch context relevant to the downstream model's performance.
- Evidence anchors: Output of Transformer Encoders corresponding to the CLS Token is expected to capture contextual information; experimental results show improved accuracy.
- Break condition: If the batch size becomes too large or the data distribution too diverse, the CLS token may fail to capture meaningful context.

### Mechanism 3
- Claim: Entropy bonus in PPO encourages exploration, helping the agent discover better data subsets rather than getting stuck in local optima.
- Mechanism: The entropy term S(θ) = -πθ(a,s)log(πθ(a,s)) is added to the loss function, pushing the policy to maintain higher entropy and explore more diverse selections during training.
- Core assumption: Maintaining exploration during training leads to better final data subsets than greedy selection.
- Evidence anchors: PPO incorporates an intrinsic reward mechanism via an entropy term to promote exploration; Tables show RLBoost with different entropy coefficients achieving better results than DVRL.
- Break condition: If the entropy coefficient is too high, the agent may never converge to a stable policy; if too low, it may get stuck in suboptimal local optima.

## Architecture Onboarding

- Component map: Data vectorizer -> Batch of vectorized data samples -> Transformer encoder stack (L layers) -> CLS token (learnable vector) -> Actor network (policy πθ) -> Critic network (value function Vϕ) -> PPO loss computation with clipping and entropy -> Validation score calculator -> Reward computation (score difference)

- Critical path: 1. Vectorize batch of data 2. Pass through Transformer encoders with CLS token 3. Use CLS output to compute value function estimate 4. Actor produces selection probabilities 5. Sample subset and train supervised model 6. Compute validation score difference as reward 7. Update actor and critic using PPO loss

- Design tradeoffs:
  - Single-step vs. multi-step: Simpler bandit formulation vs. potential loss of contextual information
  - Batch size: Larger batches provide more context but increase computational cost
  - Entropy coefficient: Higher values encourage exploration but may slow convergence
  - Transformer depth: More layers capture more complex relationships but increase training time

- Failure signatures:
  - No improvement over baseline: Likely issues with reward signal or agent architecture
  - High variance in results: May need to adjust entropy coefficient or batch size
  - Slow convergence: Could indicate learning rate issues or insufficient exploration
  - Poor performance on noisy data: May need to adjust the reward function or add noise detection mechanisms

- First 3 experiments:
  1. Run RLBoost with 1e-3 entropy coefficient on Adult dataset with 15% noise, compare to baseline
  2. Vary entropy coefficient (1e-1, 1e-2, 1e-3, 1e-4) and measure impact on accuracy and AUC
  3. Test RLBoost on MNIST with different batch sizes to find optimal batch size for image data

## Limitations
- The single-step bandit formulation may not capture complex dependencies between data samples
- Transformer encoder's CLS token representation may become ineffective with very large or heterogeneous batches
- Performance heavily depends on the choice of entropy coefficient, requiring empirical tuning

## Confidence
- **High confidence**: The theoretical reformulation of PPO as a bandit algorithm is mathematically sound and directly implementable
- **Medium confidence**: The Transformer encoder with CLS token can capture meaningful batch context, though performance may degrade with very large batches
- **Medium confidence**: Entropy bonus improves exploration and final performance, but optimal coefficient selection requires empirical tuning
