# Learning and Leveraging Verifiers to Improve Planning Capabilities of Pre-trained Language Models

## Quick Facts
- arXiv ID: 2305.17077
- Source URL: https://arxiv.org/abs/2305.17077
- Reference count: 4
- Achieves 27% improvement in success rate on Blocksworld test instances

## Executive Summary
This work addresses the challenge of poor planning performance in pre-trained large language models, which often generate invalid actions that violate pre-conditions. The proposed solution trains a verifier to classify actions as valid or invalid in a given state, using randomly sampled negative examples from the dataset. By combining a generator with diverse sampling and a verifier that prunes invalid trajectories, the method achieves a 27% improvement in success rate on Blocksworld test instances. The approach demonstrates that finetuning the generator to create the verifier generalizes better than finetuning the base GPT-2.

## Method Summary
The proposed method trains a verifier to classify actions as valid or invalid in a given state by using randomly sampled negative examples from the dataset. This verifier is combined with a generator that uses diverse sampling to explore the action space. The generator-verifier pipeline works by having the generator propose multiple potential actions, which the verifier then evaluates for validity. This approach allows for more effective exploration of the solution space while filtering out invalid actions, ultimately leading to improved planning performance.

## Key Results
- Goal-reaching rate increases from 37.5% to 65.5%
- Bad transition rate drops from 52.5% to 5%
- 27% improvement in success rate on Blocksworld test instances

## Why This Works (Mechanism)
The generator-verifier pipeline leverages diverse sampling to explore the action space while the verifier filters out invalid actions. This combination allows the system to maintain exploration capabilities while ensuring that only valid trajectories are considered, leading to more effective planning. The sampling temperature controls the exploration-exploitation tradeoff, allowing for fine-tuning of the system's behavior.

## Foundational Learning

1. **Verifier Training**: Training a model to distinguish valid from invalid actions is crucial for improving planning capabilities. Why needed: Without this filtering mechanism, language models often generate actions that violate pre-conditions. Quick check: Measure verifier accuracy on held-out negative examples.

2. **Negative Sampling**: Using randomly sampled negative examples for training the verifier is an effective strategy. Why needed: Provides the verifier with examples of invalid actions to learn from. Quick check: Compare performance with different negative sampling strategies.

3. **Generator-Verifier Pipeline**: Combining diverse sampling with verification creates a powerful planning framework. Why needed: Allows for exploration while maintaining validity constraints. Quick check: Measure success rates with and without the verifier.

## Architecture Onboarding

Component Map: Generator (diverse sampling) -> Verifier (validity check) -> Valid action selection

Critical Path: Generator proposes actions → Verifier evaluates validity → Valid actions selected for execution

Design Tradeoffs:
- Exploration vs. exploitation controlled by sampling temperature
- Computational cost of verification vs. improved planning quality
- Generalization of verifier across different planning domains

Failure Signatures:
- High bad transition rate indicates verifier is not filtering effectively
- Low success rate despite high verifier accuracy suggests generator limitations
- Performance degradation on new domains indicates poor generalization

First Experiments:
1. Test verifier accuracy on randomly sampled negative examples
2. Measure success rate improvement with and without verifier
3. Evaluate performance across different sampling temperatures

## Limitations
- Verifier performance tested only on randomly sampled negatives, not challenging counterexamples
- Assumption that verifier accuracy transfers across domains remains unproven
- Scalability to larger or more complex planning problems has not been demonstrated

## Confidence
- High confidence in baseline performance metrics (37.5% to 65.5% success rate improvement)
- Medium confidence in effectiveness of generator-verifier pipeline
- Low confidence in temperature-based exploration-exploitation tradeoff claims

## Next Checks
1. Test the verifier on adversarially selected negative examples rather than random sampling
2. Evaluate performance on planning domains beyond Blocksworld with different action space characteristics
3. Measure computational overhead of the verifier in real-time planning scenarios to assess practical deployment feasibility
