# XWikiGen: Cross-lingual Summarization for Encyclopedic Text Generation in Low Resource Languages

## Quick Facts
- arXiv ID: 2303.12308
- Source URL: https://arxiv.org/abs/2303.12308
- Reference count: 16
- Key outcome: Two-stage cross-lingual summarization approach using HipoRank+mBART achieves ROUGE-L 21.04, chrF++ 23.44, METEOR 15.35 on test set

## Executive Summary
This paper addresses the challenge of generating encyclopedic text for low-resource languages on Wikipedia by proposing XWikiGen, a cross-lingual multi-document summarization approach. The system takes reference URLs in multiple languages and generates Wikipedia-style section text in a target low-resource language. The core innovation is a two-stage architecture that first extracts salient sentences from reference documents and then uses multilingual abstractive models to generate coherent section summaries. Extensive experiments across 8 languages and 5 domains demonstrate that multi-lingual-multi-domain training with HipoRank extraction and mBART abstraction provides the best results for this task.

## Method Summary
XWikiGen employs a two-stage approach: extractive summarization followed by abstractive generation. The extractive stage uses either Salience or HipoRank to identify top-K salient sentences from reference documents, addressing the quadratic complexity issue of Transformer models with long inputs. The abstractive stage then generates section-specific text using multilingual models like mBART-large or mT5-base. The system is trained in three configurations: multi-lingual, multi-domain, and multi-lingual-multi-domain, with the latter showing superior performance. The dataset XWikiRef contains ~69K Wikipedia articles across 8 languages (bn, en, hi, ml, mr, or, pa, ta) and 5 domains (books, films, politicians, sportsmen, writers).

## Key Results
- Multi-lingual-multi-domain setup with HipoRank extraction and mBART abstraction achieves best performance
- ROUGE-L score of 21.04, chrF++ of 23.44, and METEOR of 15.35 on test set
- Multi-domain training outperforms multilingual setup on average across all metrics
- HipoRank consistently outperforms Salience in extractive summarization across all configurations

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Two-stage extractive-then-abstractive approach effectively handles long input text for cross-lingual summarization
- Mechanism: First stage (extractive) uses salience or HipoRank to identify top-K salient sentences from reference URLs, reducing input length before passing to abstractive stage
- Core assumption: Long documents can be meaningfully compressed by selecting representative sentences without losing core information needed for section-specific summaries
- Evidence anchors:
  - [abstract] "Given the quadratic complexity of Transformer-based methods, it is infeasible to feed such long inputs to an encoder-decoder model and expect it to be able to output reasonable summaries."
  - [section] "Table 6 shows the average number of sentences in references of a section for each domain and language in our dataset. Combined with the number of references per section as shown in Table 5, the overall text input is very large."
  - [corpus] Weak evidence - corpus doesn't directly support this mechanism; based on model architecture reasoning
- Break condition: If extractive stage fails to capture domain-specific or section-specific context, the abstractive stage may generate irrelevant or off-topic summaries

### Mechanism 2
- Claim: Multi-lingual-multi-domain training outperforms single language or single domain training for cross-lingual summarization
- Mechanism: Training on combined data from all 8 languages and 5 domains allows models to learn shared linguistic and domain-agnostic patterns, improving generalization for low-resource languages
- Core assumption: Low-resource languages benefit from transfer learning across languages and domains due to shared semantic structures
- Evidence anchors:
  - [abstract] "Extensive experiments show that multi-domain training is better than the multilingual setup on average."
  - [section] "Previous literature in multi-lingual cross-lingual natural language generation has shown that multilingual models tend to be better than individual ones, especially for low-resource languages."
  - [corpus] Weak evidence - corpus provides dataset stats but not direct performance comparison across setups
- Break condition: If language pairs are too dissimilar or domains too heterogeneous, transfer learning may introduce noise rather than improvement

### Mechanism 3
- Claim: HipoRank combined with mBART provides superior results due to hierarchical document structure modeling and strong multilingual generation capabilities
- Mechanism: HipoRank uses mBERT to build hierarchical graphs capturing intra- and inter-sectional importance, while mBART leverages large-scale multilingual pretraining for coherent abstractive generation
- Core assumption: Hierarchical document structure and strong multilingual pretraining are key factors for effective cross-lingual summarization
- Evidence anchors:
  - [abstract] "Our multi-lingual-multi-domain models using HipoRank (extractive) and mBART (abstractive) lead to the best results."
  - [section] "We experiment with two different extractive summarization-based techniques: Salience and HipoRank... For the abstractive stage, we use two state-of-the-art multilingual natural language generation models viz. mBART-large and mT5-base."
  - [corpus] Weak evidence - corpus doesn't directly compare HipoRank vs Salience or mBART vs mT5 performance
- Break condition: If reference documents lack clear hierarchical structure or if target language has significantly different syntax, this combination may underperform

## Architecture Onboarding

- Component map: Extractive stage (Salience/HipoRank) → Abstractive stage (mBART/mT5) → Evaluation (ROUGE-L/METEOR/chrF++)
- Critical path: Reference URLs → Extractive summarization → Abstractive generation → Evaluation
- Design tradeoffs: Extractive stage trades completeness for efficiency; multilingual training trades model complexity for better low-resource performance
- Failure signatures: Repetitive patterns in generated text, hallucination of incorrect entity values, poor performance on certain language-domain combinations
- First 3 experiments:
  1. Test extractive stage alone on sample data to verify it selects relevant sentences
  2. Test abstractive stage with gold extractive input to establish upper bound
  3. Compare multi-lingual vs single-language training on a small subset of data

## Limitations
- The two-stage approach assumes extractive summaries can capture all necessary information for abstractive generation, but no ablation study validates this assumption
- Performance metrics measure surface-level similarity rather than factual correctness or coherence, which are critical for encyclopedic content
- The dataset covers only 8 languages and 5 domains, limiting generalizability to other low-resource languages or domains

## Confidence
- **High Confidence**: The basic two-stage architecture (extractive → abstractive) is sound and technically feasible
- **Medium Confidence**: The superiority of multi-lingual-multi-domain training over other configurations is supported by experimental results
- **Low Confidence**: The claim that HipoRank + mBART specifically provides the best results lacks direct comparison with other method combinations

## Next Checks
1. Conduct an ablation study removing the extractive stage to quantify information loss and validate the necessity of the two-stage approach
2. Implement factual consistency checking to evaluate beyond surface-level metrics
3. Test the model on a held-out subset of truly low-resource languages (e.g., languages with <1000 training examples) to verify transfer learning claims
