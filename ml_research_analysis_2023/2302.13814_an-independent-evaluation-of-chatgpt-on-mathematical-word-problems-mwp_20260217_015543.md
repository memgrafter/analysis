# An Independent Evaluation of ChatGPT on Mathematical Word Problems (MWP)

## Quick Facts
- arXiv ID: 2302.13814
- Source URL: https://arxiv.org/abs/2302.13814
- Reference count: 22
- Key outcome: ChatGPT fails on 20% of problems when showing work versus 84% when only providing final answers

## Executive Summary
This study evaluates ChatGPT's performance on mathematical word problems from the DRAW-1K dataset, revealing dramatic differences in accuracy based on whether the model shows its work. The researchers found that requiring ChatGPT to show its reasoning process reduced failure rates from 84% to 20%. The study identifies key factors affecting performance, including the number of operations and unknowns in problems, and develops baseline machine learning models to predict correct responses. A dataset of ChatGPT responses was released to support further research.

## Method Summary
The researchers collected responses from ChatGPT to 1,000 mathematical word problems from the DRAW-1K dataset across three experimental conditions: January 2023 (no work shown), February 2023 (no work shown), and February 2023 (work shown). They classified responses as correct, partially correct, or incorrect, then analyzed failure probabilities against problem features including number of operations and unknowns. The study also developed baseline machine learning models using ground truth equation features to predict ChatGPT's performance, reporting precision of 0.78-0.94 and recall of 0.69-0.82.

## Key Results
- Failure rate drops from 84% to 20% when ChatGPT is required to show its work
- Probability of failure increases linearly with number of addition/subtraction operations (R²=0.915)
- Number of unknowns increases failure probability when work is not shown, but not when work is shown
- Baseline ML models achieve precision of 0.78-0.94 and recall of 0.69-0.82 in predicting correct responses

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Showing work reduces failure rate by forcing the model to externalize intermediate reasoning steps
- Mechanism: When ChatGPT shows work, it must perform and verify each step sequentially, allowing self-correction of algebraic errors before final answer generation. The work acts as a "reasoning scaffold" that catches mistakes earlier
- Core assumption: The model has internal reasoning capabilities that can be activated through structured output requirements, even if it struggles with implicit multi-step reasoning
- Evidence anchors:
  - [abstract] "failing 20% of the time when it provides work compared with 84% when it does not"
  - [section] "we included the following statement as part of the prompt... Don't provide any work/explanation or any extra text"
- Break condition: If the model's reasoning errors compound faster than it can self-correct, showing work may not help and could even amplify errors through cascading mistakes

### Mechanism 2
- Claim: The probability of failure increases linearly with the number of addition and subtraction operations
- Mechanism: Each arithmetic operation represents a reasoning step where the model can make errors. More operations create more opportunities for mistakes, and these errors accumulate multiplicatively rather than additively
- Core assumption: Each arithmetic operation in the problem template corresponds to a discrete reasoning step that the model must execute correctly
- Evidence anchors:
  - [abstract] "the probability of failure increases linearly with the number of addition and subtraction operations (R²=0.915 when showing work)"
  - [section] "we found a strong linear relationship between the number of addition and subtraction operations with the probability of failure"
- Break condition: If the model can batch operations or use alternative reasoning strategies for certain operation patterns, the linear relationship may break down for specific problem types

### Mechanism 3
- Claim: The number of unknowns in a problem increases failure probability when work is not shown
- Mechanism: Problems with more unknowns require the model to track multiple variables simultaneously. Without showing work, the model must maintain this complexity in its internal state, leading to higher cognitive load and error rates
- Core assumption: Each unknown variable adds cognitive complexity that scales with the number of variables the model must track
- Evidence anchors:
  - [section] "identification of several factors about MWPs relating to the number of unknowns and number of operations that lead to a higher probability of failure"
  - [section] "when the system would be required to show its work, the number of unknowns present no longer seems to increase the probability of failure"
- Break condition: If the model can use pattern recognition to handle multiple unknowns without explicit tracking, or if showing work doesn't actually reduce the cognitive load for complex variable relationships

## Architecture Onboarding

- Component map: Data collection pipeline (MWP dataset → ChatGPT interface → response storage), analysis pipeline (response classification → feature extraction → statistical analysis), prediction pipeline (feature engineering → model training → evaluation)
- Critical path: MWP dataset → ChatGPT prompt generation → response collection → classification → statistical analysis → model development
- Design tradeoffs: API accessibility vs. scale (no API required manual CLI wrapper), ground truth equations vs. model-generated equations (oracle vs. practical), showing work vs. not showing work (accuracy vs. computational cost)
- Failure signatures: High failure rate on problems with many operations, systematic algebraic errors in intermediate steps, incorrect variable tracking across multiple unknowns
- First 3 experiments:
  1. January 2023 experiment: Test baseline performance without work requirement using specific prompt to suppress explanations
  2. February 2023 experiment (no work): Test performance after OpenAI improvements with refined prompt
  3. February 2023 experiment (showing work): Test performance when work is allowed, using ChatGPT Plus for faster response

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Does ChatGPT's performance on mathematical word problems improve when it is explicitly instructed to use a step-by-step reasoning approach rather than just showing its work?
- Basis in paper: [explicit] The paper notes that ChatGPT's performance changes dramatically when required to show its work, with a 20% failure rate compared to 84% when not showing work. However, it does not explore different types of explicit reasoning instructions
- Why unresolved: The study only compared two scenarios - showing work vs not showing work - but did not test different prompting strategies for reasoning
- What evidence would resolve it: A controlled experiment testing ChatGPT with various explicit reasoning prompts (e.g., "break down the problem step by step," "explain your reasoning process") on the same dataset

### Open Question 2
- Question: Can the factors identified (number of unknowns, operations, etc.) be used to create an effective pre-filter that prevents ChatGPT from attempting problems it is likely to fail?
- Basis in paper: [inferred] The paper presents baseline ML models using ground truth equation features to predict ChatGPT's performance, but these models use oracle features rather than features derived from ChatGPT's own outputs
- Why unresolved: The baseline models use ground truth equations as features, which is not practical for real-world applications where the equations must be derived from ChatGPT's responses
- What evidence would resolve it: Developing and testing prediction models that use features extracted from ChatGPT's own problem-solving attempts and evaluating their practical effectiveness

### Open Question 3
- Question: How does ChatGPT's performance on mathematical word problems compare to other large language models when using the same prompting strategies?
- Basis in paper: [explicit] The paper focuses specifically on ChatGPT and does not compare its performance to other LLMs like GPT-3, PaLM, or Claude
- Why unresolved: The study was designed as an independent evaluation of ChatGPT specifically, without benchmarking against other models
- What evidence would resolve it: Running the same experiments with multiple LLMs using identical problem sets and prompting strategies, then comparing failure rates and success factors across models

## Limitations

- Limited generalizability to other problem types beyond the specific DRAW-1K dataset
- Potential influence of ChatGPT's evolving capabilities during the study period
- Lack of human expert verification for all responses, relying on automated classification

## Confidence

- High confidence: The dramatic difference in failure rates between showing work (20%) versus not showing work (84%)
- Medium confidence: The linear relationship between addition/subtraction operations and failure probability (R²=0.915)
- Low confidence: The generalizability of the machine learning prediction models (precision 0.78-0.94, recall 0.69-0.82) to real-world deployment scenarios

## Next Checks

1. Cross-dataset validation: Test the same experimental conditions on additional mathematical word problem datasets to verify whether the showing-work effect and operation-failure relationship hold across different problem types and difficulty levels.

2. Model version sensitivity analysis: Replicate the experiments using multiple versions of ChatGPT (including current models) to assess whether the observed effects persist as the underlying model architecture and training evolve over time.

3. Human expert verification study: Conduct a blind evaluation where human mathematics experts review a sample of ChatGPT responses to verify the accuracy of the classification system and assess whether any systematic patterns in errors were missed by the automated analysis.
