# Boosting Neural Networks to Decompile Optimized Binaries

## Quick Facts
- arXiv ID: 2301.00969
- Source URL: https://arxiv.org/abs/2301.00969
- Reference count: 40
- Primary result: 45.21% higher accuracy than state-of-the-art neural decompilation frameworks on optimized binaries

## Executive Summary
This paper introduces NeurDP, a neural-based decompilation framework specifically designed to handle compiler-optimized binaries. The key innovation is a graph neural network model that translates low-level program language (LPL) into an intermediate representation (IR), effectively bridging the semantic gap between source code and optimized binary. By introducing the Optimized Translation Unit (OTU) approach, which splits functions into smaller code fragments, the framework achieves significantly improved translation performance on optimized code that traditional decompilers struggle with.

## Method Summary
NeurDP employs a graph neural network architecture that operates on program graphs derived from optimized binaries. The framework first parses binary code into LPL, then applies the OTU technique to decompose complex functions into manageable fragments. These fragments are processed through the GNN model, which learns to map low-level operations to higher-level IR constructs. The model is trained on a dataset containing both optimized and unoptimized binaries across various optimization levels, enabling it to recover high-level program structure even when standard decompilation fails due to aggressive compiler optimizations.

## Key Results
- Achieves 45.21% higher accuracy compared to state-of-the-art neural decompilation frameworks
- Successfully handles various types of statements in optimized binaries that defeat traditional decompilers
- Demonstrates improved performance on functions split using the Optimized Translation Unit approach

## Why This Works (Mechanism)
The framework works by leveraging graph neural networks to capture the semantic relationships between low-level instructions and their high-level counterparts. The OTU fragmentation technique breaks down complex optimized code into smaller, more manageable units that preserve local control flow and data dependencies. This enables the GNN to learn translation patterns more effectively, as each fragment contains fewer optimization artifacts that typically confuse traditional decompilation approaches. The intermediate representation serves as a semantic bridge, allowing the model to recover higher-level abstractions that are otherwise lost during compilation.

## Architecture Onboarding

**Component Map:**
Binary Input -> LPL Parser -> OTU Fragmenter -> GNN Translator -> IR Generator -> Output Code

**Critical Path:**
The critical execution path follows: Binary Input → LPL Parser → OTU Fragmenter → GNN Translator → IR Generator. Each stage must complete successfully for the next to function, with the GNN translation being the computational bottleneck.

**Design Tradeoffs:**
- Fragmentation vs. context: Smaller OTU fragments improve translation accuracy but may lose global context
- Model complexity vs. training efficiency: Deeper GNN architectures capture more patterns but require more training data
- Precision vs. generalization: Model can be tuned for specific optimization patterns at the cost of broader applicability

**Failure Signatures:**
- Incorrect control flow reconstruction when optimization eliminates branches
- Variable naming and type inference failures in highly optimized code
- Incomplete translation when OTU fragments break semantic dependencies
- Performance degradation on exotic optimization patterns not seen during training

**First 3 Experiments:**
1. Test translation accuracy on increasingly complex optimization levels (O0 → O3)
2. Evaluate fragment size impact on translation quality and runtime performance
3. Assess model robustness against control flow flattening and other aggressive optimizations
