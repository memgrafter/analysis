# Advancing Direct Convolution using Convolution Slicing Optimization and ISA Extensions

## Quick Facts
- **arXiv ID**: 2303.04739
- **Source URL**: https://arxiv.org/abs/2303.04739
- **Reference count**: 33
- **Primary result**: Eliminates Im2Col transformation; reduces packing time by 2.0x-3.9x (x86) and 3.6x-7.2x (POWER10); achieves end-to-end speedups of 9%-25% (x86) and 10%-42% (POWER10)

## Executive Summary
This paper introduces SConv, a direct convolution algorithm that eliminates the traditional Im2Col transformation used in ML inference. By combining Convolution Slicing Analysis (CSA) for cache-tiled optimization, Convolution Slicing Optimization (CSO) for code generation, and Vector-Based Packing (VBP) for efficient data packing using vector instructions, SConv achieves significant performance improvements over Im2Col+BLAS approaches. The method is evaluated on 393 convolutions from seven ONNX-MLIR models across Intel x86 and IBM POWER10 architectures, demonstrating total convolution speedups of 12%-27% on x86 and 26%-46% on POWER10.

## Method Summary
SConv implements direct convolution by eliminating the Im2Col transformation and using fast packing routines. The method consists of CSA for analyzing convolution parameters and selecting optimal tiling strategies, CSO for generating macro-kernel loop nests and packing routines, and VBP for efficient data packing using vector instructions. The approach leverages architecture-specific micro-kernels (POWER10 MMA or x86 AVX-512) to compute convolution tiles directly from packed input data. The ONNX-MLIR framework integrates these components through compiler passes that analyze models, generate optimized code, and execute convolution operations with reduced memory overhead and improved cache utilization.

## Key Results
- Total packing time reduction of 2.0x-3.9x on Intel x86 and 3.6x-7.2x on IBM POWER10 compared to Im2Col+BLAS
- End-to-end model inference speedups of 9%-25% on Intel x86 and 10%-42% on POWER10
- Total convolution speedups of 12%-27% on Intel x86 and 26%-46% on POWER10
- Outperforms BLAS GEMM in over 83% of pointwise convolutions tested

## Why This Works (Mechanism)

### Mechanism 1
- Claim: SConv eliminates the Im2Col transformation, which reduces data movement and improves cache utilization.
- Mechanism: By packing input tiles directly into the micro-kernel format instead of expanding them into large matrices, SConv avoids creating redundant data copies and leverages Packing on Demand to keep data in cache longer.
- Core assumption: The elimination of Im2Col reduces both memory footprint and cache misses without introducing significant overhead in the packing step itself.
- Evidence anchors:
  - [abstract] "elimination of the Im2Col transformation and the use of fast packing routines result in a total packing time reduction, on full model inference, of 2.0x – 3.9x on Intel x86 and 3.6x – 7.2x on IBM POWER10."
  - [section] "The input must be expanded into windows, which are then reshaped so that the micro-kernel can be used to compute the convolution. Instead of doing this process in two separate steps as done by Im2Col+BLAS, the SConv input-tensor packing routine combines both into a single pass."
  - [corpus] No direct evidence; neighboring papers mention MLIR transform and direct convolution but do not validate this specific claim. Weak evidence.
- Break condition: If packing overhead becomes comparable to Im2Col cost, or if cache hierarchy changes make tile reuse less beneficial, the advantage diminishes.

### Mechanism 2
- Claim: Convolution Slicing Analysis (CSA) optimizes cache tiling to maximize data reuse across memory levels.
- Mechanism: CSA uses symbolic simulation to choose tile sizes and scheduling (Input Stationary vs. Weight Stationary) that fit L1, L2, and L3 caches while minimizing reuse distance. The tile distribution ensures that frequently reused data stays in faster cache levels.
- Core assumption: The CSA cost model accurately predicts cache behavior and guides selection of tile sizes that minimize total memory access cycles.
- Evidence anchors:
  - [section] "CSA uses a symbolic simulation heuristic to find a suitable data tiling and scheduling combination that reduces convolution execution time. It aims to maximize input-tensor and filter data reuse on cache memories by: (a) determining the tile size and distribution through the cache hierarchy that maximize cache usage for every level; and (b) selecting the order in which input-tensor/filter tiles are accessed to reduce data movement between the various levels of the cache hierarchy."
  - [section] "The CSA algorithm selects tile sizes based on the following constraints: the windows in IN T and the filters in FS T are only tiled in their channel dimensions; full 𝐹ℎ × 𝐹𝑤 filters and windows are used in a tile; the maximum number of channels (𝑁𝑐) is chosen for each tile."
  - [section] "CSA decides between IS and WS based on a cost model... using the number of L2, L3, and main memory accesses and estimating the number of cycles for those accesses in each strategy."
  - [corpus] No direct evidence; neighboring papers mention performance characterization but do not validate CSA's cache modeling. Weak evidence.
- Break condition: If the cost model misestimates access costs, or if cache hierarchy is significantly different from assumptions, tile choices may be suboptimal.

### Mechanism 3
- Claim: Vector-Based Packing (VBP) leverages vector shift instructions to reduce redundant loads for unitary stride convolutions.
- Mechanism: In unitary stride convolutions, the next window overlaps most of the previous window, so VBP uses a vector shift operation to obtain the next window's data instead of reloading from memory, reducing memory bandwidth usage.
- Core assumption: Unitary stride is common enough that the shift-based packing yields measurable performance gains.
- Evidence anchors:
  - [section] "This observation enables the use of Vector-Based Packing (VBP), where a vector shift operation reduces loads: the next element of each window in a row is obtained by shifting the current set of elements to the left, which can be done by loading all elements into vector registers."
  - [section] "This operation is available in most architectures, so the technique is general. Both POWER10 and Intel Skylake x86 provide instructions to shift a pair of vector registers together to the left with the second vector register appended to the right of the first."
  - [corpus] No direct evidence; neighboring papers mention SIMD operations but do not validate VBP's specific impact. Weak evidence.
- Break condition: If stride is not unitary, or if vector shift instructions are unavailable or slower than expected, the benefit disappears.

## Architecture Onboarding

- Component map:
  - CSA (Convolution Slicing Analysis) -> CSO (Convolution Slicing Optimization) -> Micro-kernel -> Packing routines -> ONNX-MLIR integration

- Critical path:
  1. Model IR → CSA pass (tile analysis) → CSO pass (codegen) → Filter packing (compile-time) → Executable.
  2. At runtime: Load packed filters → CSO-generated macro-kernel → Input packing on demand → Micro-kernel calls → Output accumulation.

- Design tradeoffs:
  - CSA space exploration is intentionally limited to avoid long compilation times, trading potential optimality for practical usability.
  - Packing on demand avoids precomputing all input tiles but may add runtime overhead; the tradeoff favors models with fewer unique input tiles.
  - The choice of IS vs. WS scheduling is made per convolution; this adds complexity but tailors execution to hardware characteristics.

- Failure signatures:
  - Poor cache performance: High L2/L3 miss rates indicate CSA misestimated tile sizes or scheduling choice was wrong.
  - Unexpected slowdowns vs. baseline: Likely due to packing overhead dominating gains, or micro-kernel not being well-matched to hardware.
  - Compilation failure: CSA or CSO passes may generate invalid IR if tiling constraints are not met (e.g., tile size exceeds cache limits).

- First 3 experiments:
  1. Run a single small convolution (e.g., 3x3 filter, small input) with both SConv and Im2Col+BLAS; measure cache miss rates and execution time to confirm packing overhead is low.
  2. Vary the 𝛼, 𝛽, 𝛾 parameters in CSA (e.g., 0.8, 0.9, 0.95) on a representative convolution; observe impact on tile size, scheduling choice, and performance.
  3. Force CSA to use WS scheduling on POWER10 (where IS is normally chosen) and compare performance; this tests the correctness of the cost model.

## Limitations
- The paper lacks independent validation of the claimed elimination of Im2Col's memory inefficiencies, with packing overhead not independently measured
- CSA's cache modeling assumes specific memory access patterns that may not generalize across different hardware configurations
- VBP's performance benefit is only demonstrated on architectures with specific vector shift instructions, limiting generalizability

## Confidence

- **High confidence**: Empirical speedups on x86 (12%-27%) and POWER10 (26%-46%) architectures; packing time reductions (2.0x-3.9x x86, 3.6x-7.2x POWER10)
- **Medium confidence**: Mechanism claims for CSA cache optimization and VBP vector operations; the theoretical basis is sound but lacks independent validation
- **Low confidence**: Generalizability across different convolution shapes and hardware configurations; no ablation studies isolating individual optimization effects
