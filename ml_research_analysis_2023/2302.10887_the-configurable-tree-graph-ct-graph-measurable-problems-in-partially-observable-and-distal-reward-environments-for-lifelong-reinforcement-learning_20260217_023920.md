# The configurable tree graph (CT-graph): measurable problems in partially observable and distal reward environments for lifelong reinforcement learning

## Quick Facts
- arXiv ID: 2302.10887
- Source URL: https://arxiv.org/abs/2302.10887
- Reference count: 7
- Primary result: Introduces CT-graph, a benchmark for RL that enables precise control over observability, reward sparsity, and task similarity through configurable tree structures

## Executive Summary
The configurable tree graph (CT-graph) provides a novel benchmark for reinforcement learning that offers precise control over problem complexity, partial observability, and reward structures. Based on an expandable tree graph with decision and wait states, the CT-graph enables researchers to create environments with specific properties that are challenging for current RL algorithms. The framework supports lifelong learning scenarios through variable reward functions that create multiple tasks with controllable degrees of similarity, making it a valuable tool for testing transfer learning and adaptation capabilities.

## Method Summary
The CT-graph is implemented as an OpenAI gym environment with configurable parameters including tree depth, branching factor, and observation sets. The environment generates synthetic 1D or 2D observations through a blueprint matrix system that creates unique patterns for each state. The reward function can be placed at arbitrary locations in the graph to create multiple tasks with shared structural features. The implementation is available on GitHub and provides a systematic way to generate POMDPs with measurable properties for RL algorithm evaluation.

## Key Results
- CT-graph enables precise control over partial observability through its tree structure and observation generation system
- The framework supports lifelong learning scenarios by allowing multiple tasks with varying degrees of similarity
- Exponential growth of the state space with increasing depth and branching factor creates challenging complexity levels

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The CT-graph's tree structure with configurable depth and branching factor enables precise control over problem complexity and observability.
- Mechanism: By expanding the tree graph in depth (d) and width (branching factor b), the CT-graph can generate exponentially growing state spaces and distal rewards. This allows researchers to create environments with specific levels of partial observability, reward sparsity, and memory requirements.
- Core assumption: The tree structure can be expanded indefinitely while maintaining computational tractability for testing RL algorithms.
- Evidence anchors:
  - [abstract]: "The CT-graph is based on a tree graph that can be expanded in depth and width to obtain arbitrary levels of complexity."
  - [section]: "Given a CT-graph with parameters ⟨b,d⟩, the size of the underlying MDP can be computed counting all wait states, decision states, end states, plus two states for the home and fail states."
- Break condition: If the tree depth becomes too large, the state space grows exponentially, making the environment computationally intractable for most RL algorithms.

### Mechanism 2
- Claim: The hierarchical state categorization (decision vs. wait states) creates a controllable hierarchy of importance among observations.
- Mechanism: Decision states require specific actions to continue, while wait states only need the default action. This structure allows researchers to test an agent's ability to identify and prioritize important stimuli (decision states) over distractors (wait states).
- Core assumption: The distinction between decision and wait states is clear and learnable by the agent.
- Evidence anchors:
  - [abstract]: "Two categories of states, decision states and wait states, are devised to create a hierarchy of importance among observations."
  - [section]: "Decision state : a state in which the graph forks into b branches, requiring the agent to make a choice out of the b options (or branches) of the graph by selecting one of b different actions in the subset AD = {A1,..,Ab}. The agent will transition to a fail state if it selects A0. Wait state: a state in which only action A0 leads the agent to the next decision state in the graph with probability p−1 and leaves the agent in the same wait state with probability p."
- Break condition: If the number of wait states becomes too large relative to decision states, the agent may struggle to identify the importance hierarchy.

### Mechanism 3
- Claim: Variable reward functions allow for easy creation of multiple tasks with controllable degrees of similarity.
- Mechanism: By changing the location of the reward in the graph, researchers can create multiple tasks that share common structures but require different optimal policies. This enables testing of lifelong learning and transfer learning capabilities.
- Core assumption: Changing the reward location creates meaningfully different tasks while maintaining structural similarities.
- Evidence anchors:
  - [abstract]: "Variable reward functions allow for the easy creation of multiple tasks with controllable degrees of similarities."
  - [section]: "An agent in the CT-graph may apply policies with the following characteristics and effects: Optimal policy : The agent is able to navigate the full graph and applies an optimal policy to maximise the reward by executing the A0 action at wait states and the optimal sequence AD⋆ at decision states."
- Break condition: If the tasks become too dissimilar, the shared structure may not provide meaningful transfer opportunities.

## Foundational Learning

- Concept: Partially Observable Markov Decision Processes (POMDPs)
  - Why needed here: The CT-graph is designed to test RL algorithms in partially observable environments, which are more challenging than fully observable MDPs.
  - Quick check question: How does partial observability affect the state representation and policy learning in RL algorithms?

- Concept: Exploration vs. Exploitation in Sparse Reward Environments
  - Why needed here: The CT-graph features distal and sparse rewards, requiring agents to balance exploration to find rewards with exploitation of known good actions.
  - Quick check question: What strategies can RL algorithms use to efficiently explore in environments with very sparse rewards?

- Concept: Lifelong and Multi-task Learning
  - Why needed here: The CT-graph allows for the creation of multiple tasks with varying degrees of similarity, enabling testing of algorithms' ability to learn continuously and transfer knowledge between tasks.
  - Quick check question: How can RL algorithms efficiently adapt to new tasks while retaining knowledge from previous tasks?

## Architecture Onboarding

- Component map: Tree graph structure (depth d, branching factor b) -> Observation generators (1D/2D patterns) -> Reward functions (variable locations) -> OpenAI gym interface
- Critical path: Configure graph parameters -> Generate environment with specific observation and reward settings -> Run RL algorithm and evaluate performance on measurable properties
- Design tradeoffs: The CT-graph trades off visual appeal for precise control over problem complexity and observability. While it may not be as visually engaging as 3D environments, it offers a more rigorous testing ground for specific RL capabilities.
- Failure signatures: Common failures when using the CT-graph include: RL algorithms failing to solve even simple configurations due to the challenging nature of POMDPs with sparse rewards, inability to detect task changes in lifelong learning scenarios, and poor performance on graphs with high p values (long wait states)
- First 3 experiments:
  1. Test a basic DQN agent on a fully observable CT-graph (MDP D=true, MDP W=true) to establish baseline performance.
  2. Increase the complexity by introducing partial observability (MDP D=false, MDP W=false) and observe the performance drop.
  3. Create a lifelong learning scenario with multiple tasks of varying similarity and test an algorithm's ability to adapt and transfer knowledge.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can the CT-graph be effectively extended to handle continuous action spaces while maintaining its measurable properties?
- Basis in paper: [inferred] The paper notes that the CT-graph has a discrete action space, which is a limitation for testing algorithms designed for continuous outputs.
- Why unresolved: Extending the CT-graph to continuous action spaces would require a fundamentally different approach to action selection and state transitions, potentially altering the graph's structure and the way rewards are calculated.
- What evidence would resolve it: A modified CT-graph implementation with continuous actions that maintains the ability to measure partial observability, reward sparsity, and other key properties, along with empirical results comparing performance on continuous-action problems.

### Open Question 2
- Question: What is the optimal balance between invariant and variant features in lifelong learning scenarios, and how can this balance be quantified and utilized by reinforcement learning algorithms?
- Basis in paper: [explicit] The paper discusses the concept of invariant and variant features in lifelong learning, suggesting that an ideal learner could implement a policy with a fixed part for invariant features and a learnable part for variant features.
- Why unresolved: The paper does not provide a concrete method for quantifying or optimizing this balance, leaving it as a theoretical concept rather than a practical approach.
- What evidence would resolve it: Empirical studies comparing different methods of balancing invariant and variant features in lifelong learning tasks, along with metrics for quantifying the effectiveness of these methods.

### Open Question 3
- Question: How does the performance of reinforcement learning algorithms on the CT-graph correlate with their performance on real-world problems, given the CT-graph's simplified and abstract nature?
- Basis in paper: [explicit] The paper acknowledges that the CT-graph is an abstraction of real-world decision problems and does not use appealing visual inputs like 3D FPV environments.
- Why unresolved: The paper does not provide empirical evidence or theoretical analysis to support the claim that performance on the CT-graph translates to performance on real-world problems.
- What evidence would resolve it: A study comparing the performance of RL algorithms on the CT-graph and a set of real-world problems, with statistical analysis to determine the correlation between performance metrics on the two sets of tasks.

## Limitations

- The paper lacks extensive empirical validation with diverse RL algorithms across different CT-graph configurations
- Claims about CT-graph's superiority over existing benchmarks are not substantiated with comparative experiments
- Performance of state-of-the-art methods on various CT-graph configurations remains unclear

## Confidence

- High confidence: The mathematical formulation of the CT-graph structure and its properties (exponential growth, POMDP characteristics) is well-defined and verifiable
- Medium confidence: The claim that CT-graph can effectively benchmark lifelong learning capabilities is reasonable but requires more empirical validation across diverse algorithms
- Low confidence: Claims about CT-graph's superiority over existing benchmarks are not substantiated with comparative experiments
