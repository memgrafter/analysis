# Better Language Models of Code through Self-Improvement

## Quick Facts
- arXiv ID: 2304.01228
- Source URL: https://arxiv.org/abs/2304.01228
- Reference count: 16
- Key outcome: Simple data augmentation framework improves pre-trained language models for code (PLMCs) by 0.76-0.81 BLEU points on average across code summarization and generation tasks

## Executive Summary
This paper introduces a simple yet effective data augmentation framework to improve pre-trained language models for code (PLMCs) without model compression. The method leverages knowledge gained during pre-training and fine-tuning to generate pseudo data through beam search decoding, then uses this pseudo data as additional training data. Applied to state-of-the-art PLMCs including CodeT5, CodeBERT, and UnixCoder, the approach consistently improves performance on code-related sequence generation tasks in the CodeXGLUE benchmark, with average improvements of 0.76 BLEU points for code summarization and 0.81 BLEU points for code generation.

## Method Summary
The self-improvement framework works by first fine-tuning a pre-trained PLMC on a downstream code task until convergence. Then, using beam search with size K, the model generates K-best predictions for each training example. These predictions are scored against ground truth using BLEU similarity, and the highest-scoring prediction is selected as a pseudo-label. The model is then fine-tuned again on an augmented dataset containing both original and pseudo-labeled examples. This process effectively creates a data augmentation step where the model learns from its own high-quality predictions.

## Key Results
- Improves CodeT5, CodeBERT, and UnixCoder performance on CodeXGLUE benchmark
- Achieves average 0.76 BLEU point improvement on code summarization tasks
- Achieves average 0.81 BLEU point improvement on code generation tasks
- Effectiveness correlates with beam size gap (r1) - larger gaps indicate greater potential for improvement

## Why This Works (Mechanism)

### Mechanism 1
The framework leverages the model's own predictions as pseudo-labels to create a better training distribution. During fine-tuning, the model generates K-best predictions using beam search, evaluates them against ground truth using BLEU similarity, and selects the highest-scoring prediction as a pseudo-label. This pseudo-label is paired with the original input and used to retrain the model, creating a data augmentation step. The core assumption is that the model's own high-scoring predictions are of sufficient quality to serve as training data.

### Mechanism 2
Self-improvement is most effective when there is a large gap between performance at beam size 1 and beam size K. Larger beam sizes allow the model to explore more candidates, increasing the chance of generating a prediction close to the ground truth. When this gap is large, it indicates the model has not fully converged and can benefit from retraining on its own better predictions. The effectiveness correlates with beam size gap (r1).

### Mechanism 3
The approach acts as sequence-level knowledge distillation without model compression. The model's own predictions are used as soft targets, allowing it to learn from its own distribution of outputs rather than just ground truth. This can smooth the learning process and reduce overfitting to the original dataset. The core assumption is that the model's own output distribution contains useful inductive biases that complement the ground truth labels.

## Architecture Onboarding

- Component map: Pre-trained model checkpoint (θpre-trained) -> Fine-tuned model checkpoint (θfine-tuned) -> Pseudo data generator (beam search + BLEU scoring) -> Self-improved model checkpoint (θimproved)
- Critical path: 1) Fine-tune pre-trained model on downstream task 2) Generate pseudo data using beam search and BLEU scoring 3) Fine-tune on pseudo data to obtain θimproved
- Design tradeoffs: Beam size vs. computational cost (larger beams improve pseudo-label quality but increase inference time); pseudo-label quality vs. diversity (selecting only high-BLEU pseudo-labels may reduce diversity in training data)
- Failure signatures: Minimal improvement in BLEU scores after self-improvement; increased variance in model outputs indicating overfitting to pseudo-labels; degraded performance on validation set after self-improvement step
- First 3 experiments: 1) Compare performance of θfine-tuned vs. θimproved on held-out validation set 2) Vary beam size (1, 5, 10) and measure impact on pseudo-label quality and downstream performance 3) Analyze correlation between beam size gap (r1) and performance gain (r2) across different programming languages

## Open Questions the Paper Calls Out

### Open Question 1
How does the self-improvement method perform on encoder-only models for tasks like code completion? The paper mentions the method has only been applied to encoder-decoder models but suggests it's also applicable to encoder-only models used for code completion tasks. Further research is needed to determine effectiveness on these models.

### Open Question 2
What is the impact of varying the beam size on the performance of the self-improvement method? While the paper shows effectiveness across different beam sizes (1, 5, and 10), it doesn't provide detailed analysis of how varying beam size impacts performance. A wider range of beam sizes and analysis of the relationship between beam size and performance improvement would provide insights into the optimal beam size.

### Open Question 3
How does the self-improvement method affect the computational complexity of the model training process? The authors acknowledge increased computational complexity but don't quantify the impact on training time or resource usage. Measuring training time and resource usage compared to baseline models would provide insights into the method's practicality.

### Open Question 4
How does the self-improvement method perform on larger-scale models and other tasks beyond code summarization and code generation? The authors intend to implement the technique in larger-scale models and other tasks in the future. Conducting experiments on larger-scale models and other tasks like code completion or program repair would provide evidence of effectiveness and versatility.

## Limitations
- Pseudo-label quality depends heavily on beam search and BLEU scoring, with limited analysis of quality distributions
- Performance varies across programming languages, with inconsistent improvements across different language paradigms
- Reproducibility is challenging without exact model versions, training configurations, and random seeds

## Confidence

**High Confidence Claims**:
- The self-improvement framework consistently improves baseline PLMC performance on CodeXGLUE tasks
- The correlation between beam size gap (r1) and improvement gain (r2) provides actionable guidance for when to apply self-improvement

**Medium Confidence Claims**:
- The mechanism works through sequence-level knowledge distillation without model compression
- Pseudo-label quality is sufficient to drive meaningful improvements

**Low Confidence Claims**:
- The framework generalizes to unseen programming languages or code domains not represented in CodeXGLUE
- The approach scales effectively to much larger model sizes or different pre-training objectives
