# An Approximate Algorithm for Maximum Inner Product Search over Streaming Sparse Vectors

## Quick Facts
- arXiv ID: 2301.10622
- Source URL: https://arxiv.org/abs/2301.10622
- Reference count: 40
- This paper introduces Sinnamon, a novel approximate algorithm for maximum inner product search (MIPS) over sparse real-valued vectors

## Executive Summary
This paper presents Sinnamon, a novel algorithm for approximate maximum inner product search (MIPS) over streaming sparse vectors. The algorithm uses a lossy sketching technique to compress high-dimensional sparse vectors while maintaining bounded error in inner product approximations. Sinnamon processes queries using coordinate-at-a-time traversal with anytime termination, enabling efficient retrieval with controllable trade-offs between memory, latency, and accuracy. The algorithm is particularly effective for streaming scenarios and can be easily parallelized.

## Method Summary
Sinnamon addresses MIPS for sparse real-valued vectors by combining an inverted index with a sketch matrix that stores upper and lower bounds on coordinate values. The algorithm maps each vector through independent random functions to compress dimensions while preserving similarity relationships. During retrieval, it processes non-zero query coordinates in descending order of absolute value, accumulating upper bounds on inner products. The anytime termination property allows early stopping based on time budgets, and the design enables trivial parallelization across inverted lists without synchronization overhead.

## Key Results
- Sinnamon outperforms existing algorithms on MS MARCO dataset, achieving high recall with reduced latency and memory usage
- The sketching technique provides bounded error in inner product approximations while significantly reducing storage requirements
- Empirical evaluation shows Sinnamon's effectiveness for streaming scenarios with easy parallelization capabilities

## Why This Works (Mechanism)

### Mechanism 1
The lossy sketching technique compresses high-dimensional sparse vectors while preserving inner product approximations within bounded error. Each vector maps through h independent random functions to m coordinates, storing upper and lower bounds on coordinate values in a sketch matrix. During retrieval, coordinate-at-a-time traversal accumulates upper bounds on inner products using these sketches. The core assumption is that non-zero coordinates are uniformly distributed across dimensions and sketching error concentrates around zero as query size grows.

### Mechanism 2
Coordinate-at-a-time traversal enables anytime termination and efficient cache utilization. The algorithm processes non-zero query coordinates in descending order of absolute value, accumulating partial scores and allowing early termination when time budget is exhausted while maintaining upper bounds on inner products. Modern CPUs benefit from predictable memory access patterns and instruction-level parallelism during sequential array traversal.

### Mechanism 3
Parallelization is trivial due to independent computation across inverted lists. The sketch matrix layout and inverted index structure allow concurrent processing of different coordinate lists without synchronization overhead or index sharding. Each inverted list can be processed independently without data dependencies between lists.

## Architecture Onboarding

- Component map:
  - Inverted index: Maps coordinates to lists of document identifiers
  - Sketch matrix: Stores upper/lower bounds for each document (2m × |X| dimensions)
  - Vector storage: Raw document vectors for exact score computation during re-ranking
  - Random mapping functions: h independent mappings from n coordinates to m sketch dimensions

- Critical path:
  1. Document insertion: Update inverted index + compute and store sketch
  2. Query processing: Sort non-zero query coordinates → coordinate-at-a-time scoring → find top-k' candidates → exact re-ranking → return top-k
  3. Deletion: Remove document identifier from inverted lists + mark sketch column as vacant

- Design tradeoffs:
  - Sketch size m vs accuracy: Larger sketches provide tighter bounds but consume more memory
  - Number of random mappings h vs error concentration: More mappings reduce expected error but increase computational cost
  - Time budget T vs accuracy: Tighter budgets reduce latency but may miss relevant documents

- Failure signatures:
  - High memory usage: Sketch size m too large relative to document sparsity
  - Poor accuracy: Insufficient sketch size m or too aggressive time budget T
  - Slow insertions: Inverted index compression/decompression overhead too high

- First 3 experiments:
  1. Insert 100,000 synthetic sparse vectors (100 non-zeros in 10,000 dimensions) and measure insertion throughput
  2. Run queries with varying time budgets (T=5ms, 20ms, ∞) and measure recall vs exact retrieval
  3. Compare memory usage and latency across different sketch sizes (m=30, 60, 90) with fixed time budget

## Open Questions the Paper Calls Out

### Open Question 1
How does the performance of Sinnamon compare to WAND when the query vectors have a large number of non-zero entries (e.g., ψq > 100)? The paper states that WAND fails to prune documents effectively when the distribution of non-zero coordinates deviates from the Zipfian curve, but only provides limited comparison on a few datasets with varying query sparsity.

### Open Question 2
How does the choice of the number of random mappings (h) in Sinnamon affect the trade-off between memory usage and retrieval accuracy? While the paper mentions that using more random mappings may increase error probability but shift the probability mass closer to zero, it does not provide detailed analysis of this impact.

### Open Question 3
Can the theoretical results presented in the paper be used to dynamically adjust the intermediate number of candidates (k') in Sinnamon on a per-query basis to achieve a desired retrieval accuracy? The paper presents theoretical results that could potentially enable this, but does not provide a concrete method or demonstrate its effectiveness in practice.

## Limitations
- The paper lacks complete implementation details for text encoding methods (BM25, SPLADE, Efficient SPLADE, uniCOIL) used to generate sparse vectors
- The sketching error analysis assumes uniform distribution of non-zero coordinates, which may not hold for real-world datasets
- The anytime termination mechanism's effectiveness depends heavily on the distribution of query vector norms and time budget parameter selection

## Confidence

- **High Confidence**: The coordinate-at-a-time traversal mechanism and its cache-friendly properties are well-supported by both theoretical analysis and empirical evidence
- **Medium Confidence**: The sketching technique's error bounds are mathematically sound, but their practical effectiveness depends on unverified distributional assumptions about the input data
- **Medium Confidence**: Parallelization benefits are demonstrated empirically but lack theoretical analysis of scalability limits and load balancing under varying data distributions
