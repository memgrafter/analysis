# PFSL: Personalized & Fair Split Learning with Data & Label Privacy for thin clients

## Quick Facts
- arXiv ID: 2303.10624
- Source URL: https://arxiv.org/abs/2303.10624
- Reference count: 40
- Primary result: PFSL achieves accuracy close to centralized learning while significantly outperforming existing federated and split learning approaches on thin clients

## Executive Summary
PFSL introduces a three-stage split learning architecture that enables thin clients to train deep learning models while preserving data and label privacy. The framework offloads heavy computation to a centralized server, allowing resource-constrained devices to participate in collaborative learning. By combining transfer learning from pre-trained models with a lightweight personalization phase, PFSL optimizes performance across heterogeneous client data distributions while ensuring work fairness regardless of data size variations.

## Method Summary
The framework implements a three-stage split learning approach where clients handle lightweight front and back layers while the server processes central layers. PFSL leverages transfer learning from pre-trained ResNet-18 models and introduces a personalization phase to optimize for client-specific data distributions. The system ensures work fairness across clients with varying data sizes through a constrained optimization approach. Extensive experiments compare PFSL against centralized learning, federated learning, and split learning baselines across multiple datasets including CIFAR-10, MNIST, F-MNIST, APTOS, and EyePACS.

## Key Results
- PFSL achieves test accuracy comparable to centralized learning while significantly outperforming existing federated and split learning approaches
- The framework ensures work fairness across clients with varying data sizes, addressing a critical limitation of traditional federated learning
- PFSL demonstrates strong performance across heterogeneous data distributions through its lightweight personalization phase

## Why This Works (Mechanism)
PFSL works by strategically partitioning neural network layers between thin clients and a powerful centralized server. This architectural division allows clients to handle computationally lightweight operations while offloading heavy matrix multiplications to the server. The transfer learning component provides a strong initialization, reducing the training burden on resource-constrained devices. The personalization phase fine-tunes models for individual client data distributions without requiring full model updates, maintaining privacy while improving accuracy. Work fairness is enforced through optimization constraints that ensure equitable computational effort across clients regardless of their data volume.

## Architecture Onboarding

**Component Map**
Thin Clients -> Front Layers -> Server (Central Layers) -> Back Layers -> Thin Clients

**Critical Path**
Data preprocessing on client → Front layer inference → Server central layer processing → Back layer inference → Client-side personalization → Secure aggregation

**Design Tradeoffs**
- Computational offloading vs. communication overhead
- Model accuracy vs. privacy preservation
- Training speed vs. work fairness constraints
- Resource consumption vs. personalization effectiveness

**Failure Signatures**
- Communication bottlenecks between clients and server
- Imbalanced work distribution across clients
- Convergence issues due to layer partitioning
- Privacy leaks through intermediate activations

**Three First Experiments**
1. Verify layer partitioning correctness by testing forward and backward passes independently
2. Validate secure aggregation by checking that raw client gradients are never exposed
3. Test work fairness enforcement by running with deliberately unbalanced client data sizes

## Open Questions the Paper Calls Out
- How does PFSL's convergence guarantee compare to traditional federated learning in terms of theoretical bounds? The paper focuses on empirical results without providing mathematical proofs or convergence guarantees.
- What is the impact of varying the number of split layers on PFSL's performance and resource consumption? The authors mention configurability but do not systematically analyze this parameter.
- How does PFSL perform under different types of adversarial attacks on the model or data? The paper discusses privacy preservation but does not evaluate security under adversarial conditions.

## Limitations
- Exact hyperparameter values for different algorithms and datasets remain unspecified, potentially affecting reproducibility
- Specific implementation details of secure client model averaging server and offloading server APIs are not fully provided
- The framework requires NVIDIA GPUs with >=12GB memory, creating hardware constraints for reproduction
