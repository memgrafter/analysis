# Slimmable Encoders for Flexible Split DNNs in Bandwidth and Resource Constrained IoT Systems

## Quick Facts
- arXiv ID: 2306.12691
- Source URL: https://arxiv.org/abs/2306.12691
- Reference count: 32
- Primary result: Novel split computing approach with slimmable ensemble encoders for IoT devices, outperforming existing solutions in compression efficacy and execution time

## Executive Summary
This paper addresses the challenge of executing large deep neural networks on resource-constrained mobile edge devices by proposing a novel split computing approach using slimmable ensemble encoders. The approach enables real-time adaptation of computational load and transmitted data size with minimal overhead, making it particularly suitable for bandwidth and resource-constrained IoT systems. The proposed solution demonstrates superior performance compared to existing split computing methods, especially on weak mobile devices without GPUs.

## Method Summary
The proposed approach leverages slimmable neural network architectures to create multiple encoder variants that can be dynamically selected based on current resource constraints. The split computing framework divides the DNN between edge and cloud, with the slimmable encoders at the edge adapting their width to balance computational load and transmission requirements. The ensemble aspect combines multiple encoder variants to improve robustness and performance across varying conditions. The system includes mechanisms for real-time adaptation based on device capabilities and network conditions.

## Key Results
- Demonstrated superior compression efficacy compared to existing split computing solutions
- Achieved better execution time performance on GPU-less devices
- Showed effective real-time adaptation to varying resource constraints
- Validated performance across multiple bandwidth scenarios

## Why This Works (Mechanism)
The effectiveness stems from the combination of slimmable network architectures with split computing principles. By maintaining multiple encoder variants of different widths, the system can dynamically adjust the computational and bandwidth requirements based on current conditions. The ensemble approach provides robustness while the slimmable architecture minimizes overhead associated with switching between different model configurations.

## Architecture Onboarding

**Component Map**: Sensor -> Slimmable Encoder Variants -> Switch Controller -> Edge-Cloud Communication -> Cloud Backend

**Critical Path**: Input data flows through selected encoder variant, with switch controller determining optimal configuration based on current constraints

**Design Tradeoffs**: Width vs accuracy vs computation - wider encoders provide better accuracy but require more resources; switching overhead vs static configuration; ensemble diversity vs model size

**Failure Signatures**: Performance degradation under rapid constraint changes; increased latency during adaptation; accuracy drops when inappropriate encoder variant selected
