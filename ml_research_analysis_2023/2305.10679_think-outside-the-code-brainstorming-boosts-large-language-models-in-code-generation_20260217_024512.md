# Think Outside the Code: Brainstorming Boosts Large Language Models in Code Generation

## Quick Facts
- arXiv ID: 2305.10679
- Source URL: https://arxiv.org/abs/2305.10679
- Reference count: 40
- State-of-the-art performance on CodeContests and APPS benchmarks with over 50% relative improvement in pass@1 and pass@5 metrics

## Executive Summary
This paper introduces the BRAINSTORM framework for competition-level code generation, which employs a brainstorming strategy to generate diverse algorithmic thoughts from problem descriptions. The framework ranks these thoughts using a neural model and uses the best thought to guide code generation by large language models. BRAINSTORM achieves state-of-the-art performance on CodeContests and APPS benchmarks, significantly boosting ChatGPT's pass rates with over 50% relative improvement in pass@1 and pass@5 metrics. The approach demonstrates performance comparable to human programmers on LeetCode contests.

## Method Summary
BRAINSTORM is a two-stage code generation framework that first generates diverse algorithmic thoughts through a brainstorming step, then ranks these thoughts using a neural ranker model before generating code. The framework decomposes the task into three steps: brainstorming (generating 4 diverse thoughts per problem using different instructions), thoughts selection (ranking thoughts with a neural model trained to predict solution correctness), and writing code (using the highest-scoring thought to guide code generation). The approach is evaluated on CodeContests and APPS benchmarks using pass@k metrics with nucleus sampling (p=0.95) and temperature T=0.8.

## Key Results
- Achieves state-of-the-art performance on CodeContests and APPS benchmarks
- Over 50% relative improvement in ChatGPT's pass@1 and pass@5 metrics
- Performance comparable to human programmers on LeetCode contests

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The brainstorming step generates diverse algorithmic thoughts, which increases the probability of correct solutions being sampled.
- Mechanism: By constructing multiple prompts with different instructions, the LLM generates a variety of high-level descriptions of potential solutions for the given problem. This diversity increases the chance of including the correct algorithmic approach.
- Core assumption: Different prompt instructions will lead to sufficiently diverse thought generation, and at least one of these thoughts will capture the correct algorithmic approach.
- Evidence anchors:
  - [abstract] "It leverages a brainstorming step that generates and selects diverse thoughts on the problem to facilitate algorithmic reasoning"
  - [section] "The core of BRAINSTORM framework is to generate diverse thoughts that is potentially helpful for solving the given problem"
  - [corpus] Weak evidence. The corpus shows papers on "thinking outside the box" and "creative humor generation" but lacks direct evidence for brainstorming improving algorithmic reasoning in code generation.
- Break condition: If the prompt diversity is insufficient or the LLM cannot generate correct algorithmic thoughts regardless of prompt variation.

### Mechanism 2
- Claim: The thoughts ranker model effectively selects the most promising thoughts for code generation.
- Mechanism: A neural model is trained to predict the probability that a given thought will lead to a correct solution. During inference, the highest-scoring thoughts are selected for code generation.
- Core assumption: The ranker can be trained to distinguish between thoughts that lead to correct solutions and those that don't, based on execution results.
- Evidence anchors:
  - [section] "a neural model called the thoughts ranker, denoted as R. This model takes problem descriptions and the generated thoughts as input and predicts the probability that these thoughts will lead to correct solutions"
  - [section] "The function r can be learned by minimizing the following objective function"
  - [corpus] Missing direct evidence. No corpus papers specifically address ranking thoughts for code generation success.
- Break condition: If the training data lacks sufficient diversity in correct/incorrect thought examples, or if the ranker overfits to specific problem types.

### Mechanism 3
- Claim: The two-stage generation process (thoughts first, then code) enhances the LLM's reasoning capabilities compared to direct code generation.
- Mechanism: By separating algorithmic reasoning from code implementation, the framework allows the LLM to first determine the solution approach before worrying about syntax and implementation details.
- Core assumption: LLMs have latent reasoning capabilities that can be better exploited through intermediate reasoning steps rather than direct code generation.
- Evidence anchors:
  - [abstract] "We introduce BRAINSTORM framework for code generation. It leverages a brainstorming step that generates and selects diverse thoughts on the problem to facilitate algorithmic reasoning"
  - [section] "BRAINSTORM framework decomposes the generation task into three steps: brainstorming, thoughts selection, and writing code"
  - [corpus] Weak evidence. While "Chain-of-Thought" prompting exists in the corpus, there's no direct evidence for two-stage code generation.
- Break condition: If the LLM's reasoning capabilities are not sufficiently developed to benefit from this separation, or if the overhead of two-stage generation outweighs benefits for simpler problems.

## Architecture Onboarding

- Component map: LLM (for brainstorming and code generation) → Thoughts Ranker → LLM (for code generation) → Execution Sandbox
- Critical path: Problem Description → LLM (Brainstorming) → Thoughts Ranker → Selected Thought → LLM (Code Generation) → Execution Sandbox → Pass/Fail
- Design tradeoffs: The two-stage generation adds complexity but potentially improves reasoning; the ranker requires training data but improves thought selection quality
- Failure signatures: Low diversity in generated thoughts, ranker consistently selecting wrong thoughts, code generation failing despite correct thought selection
- First 3 experiments:
  1. Test brainstorming with a single instruction type and measure thought diversity using clustering metrics
  2. Train ranker on a small dataset and evaluate its ability to distinguish between correct and incorrect thoughts
  3. Compare pass@1 rates with and without the brainstorming step on a small set of problems

## Limitations

- Limited diversity in thought generation: The paper claims to generate 4 diverse thoughts per problem, but doesn't specify the exact instructions used for brainstorming.
- Ranker training data quality: The thoughts ranker is trained on execution results, but the paper doesn't detail how negative examples are collected or whether there's sufficient variety in correct/incorrect thought patterns.
- Execution-only evaluation: The framework relies heavily on execution results to train the ranker and evaluate success, which may miss semantic correctness issues or edge cases.

## Confidence

**High confidence**: The framework's general architecture (brainstorming → ranking → code generation) is sound and follows established principles of decomposition in complex reasoning tasks. The improvement over baseline ChatGPT performance is demonstrated with specific metrics.

**Medium confidence**: The effectiveness of the brainstorming strategy for generating diverse algorithmic thoughts is supported by results but lacks detailed validation of thought diversity metrics or qualitative analysis of generated thoughts.

**Medium confidence**: The claim of "state-of-the-art" performance needs context, as it's compared to specific baselines but doesn't account for all recent approaches in the rapidly evolving field of code generation.

## Next Checks

2. **Ranker robustness test**: Create adversarial thought examples that are semantically correct but syntactically different, and test whether the ranker consistently assigns them high scores. Target: ranker assigns top-2 scores to at least 80% of semantically equivalent correct thoughts.

3. **Human evaluation of thought quality**: Have human experts rate the quality and diversity of generated thoughts on a sample of problems, comparing BRAINSTORM's thoughts against baseline single-prompt approaches.
