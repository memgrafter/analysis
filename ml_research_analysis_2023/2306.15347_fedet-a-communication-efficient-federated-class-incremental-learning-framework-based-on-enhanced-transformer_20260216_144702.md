# FedET: A Communication-Efficient Federated Class-Incremental Learning Framework Based on Enhanced Transformer

## Quick Facts
- arXiv ID: 2306.15347
- Source URL: https://arxiv.org/abs/2306.15347
- Reference count: 22
- Key result: Achieves 14.1% higher average accuracy than state-of-the-art methods on benchmark datasets while reducing communication costs by 90%

## Executive Summary
This paper introduces FedET, a novel federated class-incremental learning framework designed to handle new classes in decentralized environments while maintaining privacy. FedET addresses two major challenges: catastrophic forgetting of old classes and high communication costs in federated learning. The core innovation lies in using an "Enhancer" module—a small, trainable component—that works alongside frozen pre-trained transformers to learn new tasks efficiently. This modular approach allows selective updates, drastically reducing communication overhead. To mitigate forgetting, FedET employs dual distillation techniques and entropy-aware losses, balancing knowledge retention and adaptation. Experimental results demonstrate that FedET achieves 14.1% higher average accuracy than state-of-the-art methods on benchmark datasets, while reducing communication costs by 90%. The framework is validated across both computer vision and natural language processing tasks, showcasing its versatility and effectiveness.

## Method Summary
FedET is a federated class-incremental learning framework that uses frozen pre-trained transformers with trainable Enhancer modules to learn new classes while minimizing communication overhead. The framework employs dual distillation (local and global) to prevent catastrophic forgetting and uses an Enhancer Select Module to route inputs to appropriate Enhancer Groups. The method is tested on five text classification datasets (AGnews, Yelp, Amazon, DBpedia, Yahoo) and ImageNet-Subset/CIFAR-100 for computer vision tasks. Key components include frozen transformer backbones, Enhancer Pool with multiple Enhancer Groups, Sample Memory Module, and server-side distillation coordination.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Selective parameter updates via Enhancers drastically reduce communication cost.
- Mechanism: Only Enhancer parameters (tiny module) are updated and transmitted instead of full transformer backbone.
- Core assumption: Transformer backbone parameters are sufficient for feature extraction; only task-specific adaptation needs to be communicated.
- Evidence anchors:
  - [abstract]: "uses Enhancer, a tiny module, to absorb and communicate new knowledge"
  - [section]: "only the parameters of the chosen Enhancer Group need to be updated, the communication cost is significantly reduced"
  - [corpus]: Weak - no direct comparison papers found in corpus.
- Break condition: If feature extraction quality degrades without backbone updates, or if Enhancer size grows too large relative to backbone.

### Mechanism 2
- Claim: Dual distillation (local + global) mitigates both local and global catastrophic forgetting.
- Mechanism: Local distillation uses sample memory and double distillation loss; global distillation uses entropy-aware multiple distillation across clients.
- Core assumption: Old knowledge can be preserved through distillation while integrating new classes.
- Evidence anchors:
  - [abstract]: "To address local forgetting... and global forgetting... we proposed an Enhancer distillation method"
  - [section]: "double distillation loss... and the difference of average entropy across different clients"
  - [corpus]: Weak - no direct evidence of entropy-aware distillation in corpus.
- Break condition: If entropy weighting fails to properly balance client contributions, or if sample memory becomes insufficient.

### Mechanism 3
- Claim: Enhancer Select Module routes inputs to appropriate Enhancer Group, enabling task specialization.
- Mechanism: Frozen classifier selects which Enhancer Group handles each input based on class similarity.
- Core assumption: Class-to-group mapping can be learned and remains stable across tasks.
- Evidence anchors:
  - [section]: "The Enhancer Select Module is a pre-trained frozen classifier... to select a suitable Enhancer Group"
  - [section]: "In t-th task T t, the Enhancer Select Module will first select an Enhancer Group"
  - [corpus]: Weak - no direct evidence of similar routing mechanisms in corpus.
- Break condition: If class distribution shifts too rapidly, or if classifier accuracy degrades over time.

## Architecture Onboarding

- Component map:
  Pre-trained Transformer Blocks -> Enhancer Pool -> Enhancer Select Module -> Sample Memory Module -> Server-side distillation coordinator

- Critical path:
  1. Input → Enhancer Select Module → Enhancer Group selection
  2. Enhancer Group + frozen backbone → prediction
  3. Local distillation with Sample Memory → updated Enhancer
  4. Server aggregates entropy-weighted updates → global model

- Design tradeoffs:
  - Enhancer size vs. adaptation capacity
  - Sample memory size vs. forgetting prevention
  - Number of Enhancer Groups vs. routing complexity
  - Communication frequency vs. model freshness

- Failure signatures:
  - Accuracy degradation on old classes indicates forgetting
  - Poor performance on new classes suggests insufficient adaptation
  - Communication bottlenecks suggest Enhancer size optimization needed
  - Routing errors indicate Enhancer Select Module issues

- First 3 experiments:
  1. Measure communication savings vs. baseline (full model updates)
  2. Test accuracy retention on old classes after incremental learning
  3. Evaluate routing accuracy of Enhancer Select Module across tasks

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the number of Enhancers (J) impact the trade-off between model accuracy and computational efficiency in FedET across different incremental learning tasks?
- Basis in paper: [explicit] The paper discusses the impact of the number of Enhancers on model performance, noting that increasing J improves initial performance but degrades faster as learning progresses.
- Why unresolved: The paper suggests that the optimal number of Enhancers depends on the specific task and the capability of the Enhancer Select Module, but does not provide a definitive method to determine this optimal number.
- What evidence would resolve it: Empirical studies comparing different values of J across a range of incremental learning tasks, measuring both accuracy and computational efficiency, would help determine the optimal number of Enhancers for various scenarios.

### Open Question 2
- Question: What are the long-term effects of using auxiliary data for global distillation in FedET, particularly in terms of model generalization and privacy?
- Basis in paper: [explicit] The paper mentions the use of auxiliary data to approximate training samples for global distillation, constructed dynamically and discarded after use.
- Why unresolved: While the paper addresses the necessity of auxiliary data for global distillation, it does not explore the long-term implications of this approach on model generalization and potential privacy concerns.
- What evidence would resolve it: Longitudinal studies evaluating the impact of auxiliary data on model performance over multiple learning tasks, alongside privacy assessments, would provide insights into the long-term effects of this approach.

### Open Question 3
- Question: How does FedET's performance scale with the number of clients (K) in federated learning environments, especially in scenarios with highly heterogeneous data distributions?
- Basis in paper: [explicit] The paper discusses the impact of increasing the number of clients on FedET's performance, noting a decline as K increases, particularly when K = 100.
- Why unresolved: The paper suggests that increasing K leads to performance degradation due to the complexity of managing multiple enhancer groups, but does not explore potential strategies to mitigate this issue.
- What evidence would resolve it: Comparative studies of FedET's performance across different numbers of clients with varying degrees of data heterogeneity, coupled with strategies to optimize client-server communication and model convergence, would clarify the scalability of FedET.

## Limitations
- Limited ablation studies on Enhancer size vs. performance tradeoffs
- Entropy-aware multiple distillation mechanism lacks detailed mathematical formulation
- Enhancer Select Module routing accuracy over multiple incremental tasks is not thoroughly evaluated

- Low confidence: Enhancer Select Module routing effectiveness (minimal evidence provided for long-term stability)
