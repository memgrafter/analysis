# GKD: A General Knowledge Distillation Framework for Large-scale Pre-trained Language Model

## Quick Facts
- arXiv ID: 2306.06629
- Source URL: https://arxiv.org/abs/2306.06629
- Authors: 
- Reference count: 40
- GKD is a general knowledge distillation framework for large-scale pre-trained language models that addresses challenges in deploying distillation systems on ultra-large-scale PLMs with limited GPU memory and method switching.

## Executive Summary
GKD is a knowledge distillation framework designed to address the challenges of distilling ultra-large-scale pre-trained language models (PLMs) onto resource-constrained devices. The framework proposes a teacher-student parallel strategy based on model and data parallelism to support distillation of at least 100B-scale PLMs on 8 NVIDIA A100 (40GB) GPUs. It also implements an efficient adaptive architecture compatible with 25 mainstream distillation methods using dynamic hooks and auxiliary models, enabling easy switching and combining of different distillation methods.

## Method Summary
GKD implements a teacher-student parallel strategy that splits model parameters across GPUs using a combination of Megatron-LM (model parallelism) and ZeRO (data parallelism) to reduce memory usage per GPU while maintaining teacher-student interaction. The framework uses a dynamic hook mechanism to extract intermediate features and modify model inference without changing core architecture, with an auxiliary model calculating loss functions based on these hooks. This adaptive architecture enables compatibility with 25 mainstream distillation methods and supports automatic discovery of optimal distillation feature combinations through systematic experimentation.

## Key Results
- Supports distillation of at least 100B-scale PLMs on 8 NVIDIA A100 (40GB) GPUs
- Compatible with 25 mainstream distillation methods through dynamic hook mechanism
- Achieves SOTA results on SuperGLUE benchmark with "BestC" method, outperforming TinyBERT by 1.24% on average

## Why This Works (Mechanism)

### Mechanism 1
- Claim: GKD enables distillation of ultra-large-scale PLMs (>100B parameters) by splitting model parameters across multiple GPUs using teacher-student parallel strategy.
- Mechanism: Teacher-student parallel strategy evenly distributes teacher and student model parameters across GPUs, combining Megatron-LM (model parallelism) and ZeRO (data parallelism) to reduce memory usage per GPU while maintaining teacher-student interaction.
- Core assumption: Splitting transformer parameter matrices across GPUs preserves computation of feature distance between teacher and student models.
- Evidence anchors:
  - [abstract]: "proposes a teacher-student parallel strategy based on model and data parallelism to support distillation of at least 100B-scale PLMs on 8 NVIDIA A100 (40GB) GPUs"
  - [section 3.2]: "We propose a teacher-student parallel strategy that splits the model parameters to different GPUs while preserving the feature distance computation between the teacher and student models"
  - [corpus]: Weak evidence - no direct citations found for teacher-student parallel strategy in related papers
- Break condition: If splitting transformer parameters breaks computation of teacher-student feature distance, the distillation would fail. Also fails if GPU memory cannot accommodate even split parameters for ultra-large models.

### Mechanism 2
- Claim: GKD supports easy switching and combining of different distillation methods through dynamic hook mechanism and auxiliary model.
- Mechanism: Dynamic hook mechanism constructs extraction hooks for model features and operation hooks for modifying inference process during each iteration. Auxiliary model calculates loss functions based on these hooks and returned features.
- Core assumption: Different distillation methods can be implemented through hook-based feature extraction and loss computation without modifying core model architecture.
- Evidence anchors:
  - [abstract]: "implements an efficient adaptive architecture compatible with 25 mainstream distillation methods using dynamic hooks and auxiliary models"
  - [section 3.3]: "It implements the operation of different methods and the calculation of features through a dynamic hook mechanism and an auxiliary model, respectively"
  - [section 3.3]: "GKD can achieve method combination by integrating hooks from different methods"
  - [corpus]: Weak evidence - no direct citations found for dynamic hook mechanism in related papers
- Break condition: If different methods require incompatible feature extraction patterns that cannot be expressed through hooks, method switching would fail. Also fails if auxiliary model cannot handle diverse loss computations.

### Mechanism 3
- Claim: GKD's adaptive architecture enables automatic discovery of optimal distillation feature combinations through systematic experimentation.
- Mechanism: By recording all model features through extraction hooks and saving teacher-student feature distances, GKD enables analysis of correlation between feature distance and task performance, facilitating discovery of optimal distillation strategies.
- Core assumption: Feature distances captured during distillation correlate with downstream task performance, enabling data-driven optimization of distillation methods.
- Evidence anchors:
  - [section A.2]: "GKD can record all model features through extraction hooks and save the distance of teacher and student features in the auxiliary model for later analysis of the correlation between feature distance and task performance in the distillation process"
  - [section A.2]: "We discovered the method BestC which achieves the SOTA, outperforming TinyBERT by 1.24% on average in SuperGLUE"
  - [corpus]: Weak evidence - no direct citations found for automatic discovery of optimal distillation strategies
- Break condition: If feature distances do not correlate with task performance, analysis would not lead to better distillation strategies. Also fails if computational cost of recording all features becomes prohibitive.

## Architecture Onboarding

- Component map:
  - Teacher-student parallel strategy (model building layer) -> Dynamic hook mechanism (training control layer) -> Auxiliary model (loss computation layer) -> Method configuration system (interface layer) -> GPU memory management (infrastructure layer)

- Critical path: User requirements → Model building (parallel strategy) → Model training (adaptive architecture) → Analysis → Deployment

- Design tradeoffs:
  - Memory vs. flexibility: Recording all features for analysis increases memory usage but enables method discovery
  - Speed vs. accuracy: Model parallelism reduces memory but increases communication overhead
  - Generality vs. optimization: Hook-based architecture supports many methods but may be less optimized than method-specific implementations

- Failure signatures:
  - GPU memory overflow during teacher-student parallel strategy
  - Hook conflicts when combining multiple methods
  - Loss divergence when using certain distillation methods
  - Performance degradation when recording too many features

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the maximum scale of PLMs that GKD can effectively distill beyond the demonstrated 100B parameters?
- Basis in paper: [explicit] The paper states GKD can support distillation of "at least 100B-scale PLMs" and discusses memory/time consumption for various scales up to 110B.
- Why unresolved: The paper only provides empirical results up to 100B parameters and mentions GPU memory overflow for 110B parameters with 8 GPUs, but doesn't explore what happens with more GPUs or different hardware configurations.
- What evidence would resolve it: Testing GKD with more than 8 GPUs or different GPU memory configurations to determine the practical upper limit of PLM scale that can be distilled.

### Open Question 2
- Question: How does the performance of distilled models vary when using different combinations of distillation methods versus single-method approaches?
- Basis in paper: [explicit] The paper demonstrates that method combinations are possible through the dynamic hook mechanism and presents "BestC" as a combination achieving SOTA results, but only explores a limited set of combinations.
- Why unresolved: The paper only shows results for a few dozen combinations out of potentially thousands of possible method combinations, and doesn't provide systematic analysis of which feature combinations work best.
- What evidence would resolve it: Comprehensive testing of various method combinations across different tasks and scales to identify optimal feature distillation strategies.

### Open Question 3
- Question: What is the relationship between feature distance during distillation and downstream task performance, and can this be used to guide the distillation process?
- Basis in paper: [explicit] The paper presents analysis showing correlation between feature distance and both training loss and task performance, but notes that pre-training task performance isn't necessarily correlated with downstream task performance.
- Why unresolved: The analysis is limited to one specific distillation setup (TinyBERT), and the paper doesn't establish clear guidelines for using feature distance metrics to optimize distillation.
- What evidence would resolve it: Systematic study across multiple distillation methods and tasks to determine which features' distances correlate most strongly with final task performance and how to use this information during training.

## Limitations

- Limited empirical validation of ultra-large-scale capability: The paper claims GKD can support 100B-scale PLMs on 8 A100 GPUs, but experimental validation is primarily shown on smaller models (3B GLM), with the 100B-scale claim extrapolated from theoretical calculations.
- Dynamic hook mechanism scalability concerns: While theoretically sound, the hook-based feature extraction approach could introduce significant overhead when recording all intermediate features, potentially making it impractical for very large models or real-time applications.
- Method discovery validity issues: The claim of discovering "BestC" method through systematic feature distance analysis is based on limited experimentation without rigorous statistical validation across diverse tasks and model sizes.

## Confidence

- High confidence: The basic premise that knowledge distillation can compress large language models is well-established. The need for distributed training strategies for ultra-large models is clearly demonstrated. The paper's description of combining Megatron-LM and ZeRO is technically sound.
- Medium confidence: The teacher-student parallel strategy for preserving feature distance computation appears plausible based on the description, but lacks rigorous theoretical justification. The dynamic hook mechanism for method combination is a reasonable architectural approach, though scalability concerns exist.
- Low confidence: Claims about automatic discovery of optimal distillation methods through feature distance analysis are speculative without more rigorous validation. The extrapolation from 3B-scale results to 100B-scale capability is particularly uncertain.

## Next Checks

3. **Feature distance correlation analysis**: Conduct controlled experiments varying only the feature matching strategy while keeping all other parameters constant.
