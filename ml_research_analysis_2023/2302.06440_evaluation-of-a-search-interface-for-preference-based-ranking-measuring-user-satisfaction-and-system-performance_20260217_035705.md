# Evaluation of a Search Interface for Preference-Based Ranking -- Measuring User Satisfaction and System Performance

## Quick Facts
- **arXiv ID:** 2302.06440
- **Source URL:** https://arxiv.org/abs/2302.06440
- **Reference count:** 32
- **Primary result:** Preference-based weighting interface led to higher user satisfaction and better precision than standard faceted search for hotel booking

## Executive Summary
This paper presents a controlled lab study comparing two hotel search interfaces: a traditional faceted search and an experimental preference-based ranking system where users can weight different search criteria. The study involved 24 participants who completed multiple hotel search tasks. Results showed that users were significantly more satisfied with hotels found using the weighted interface and saw more relevant options. Interestingly, while satisfaction was higher, there were no significant differences in time or clicks when users fully engaged with the preference system. The study also uncovered a novel finding that users who felt better supported by the system generated search results with higher precision.

## Method Summary
The study employed a within-subjects lab experiment with 24 participants who performed hotel search tasks using both a standard faceted search interface and a preference-based ranking interface. Participants completed search tasks for hotel bookings, with the order of interface presentation counterbalanced. Researchers measured multiple metrics including user satisfaction, perceived system support, relevance of viewed hotels, price of selected options, time spent, and number of clicks. The preference-based interface allowed users to weight different search criteria, while the faceted interface used standard filtering. All tasks were conducted in a controlled lab environment with predefined scenarios.

## Key Results
- Users showed significantly higher satisfaction with hotels found using the preference-based weighted interface compared to faceted search
- Participants using the weighted interface saw more relevant hotels and selected cheaper options overall
- Time and clicks did not differ significantly when users examined all preferences, though those skipping preferences were faster with faceted search
- A novel finding showed that users who felt better supported by the system generated result lists with higher precision

## Why This Works (Mechanism)
The preference-based ranking interface appears to work by allowing users to explicitly communicate their relative priorities for different search criteria, rather than treating all criteria equally. This weighted approach enables the system to generate rankings that better align with individual user preferences, leading to higher satisfaction with results. The mechanism also appears to influence the relevance of hotels users encounter during their search sessions, potentially by surfacing options that better match the weighted criteria.

## Foundational Learning
**Preference-based ranking:** A search interface design where users can assign weights to different search criteria, allowing the system to generate personalized rankings based on relative importance rather than treating all criteria equally.
*Why needed:* Traditional faceted search treats all filters equally, which may not reflect actual user priorities when multiple criteria are involved.
*Quick check:* Verify that the weighting mechanism allows for continuous rather than just binary preference expressions.

**Perceived system support:** Users' subjective assessment of how well the interface helps them accomplish their search goals, measured through post-task questionnaires.
*Why needed:* Understanding user perception is critical for evaluating interface effectiveness beyond just objective metrics.
*Quick check:* Ensure support scales capture both ease of use and confidence in results.

**Search precision in e-commerce:** The proportion of returned results that meet user needs, measured by relevance ratings of viewed items.
*Why needed:* In commercial search, quality of the result set directly impacts conversion and satisfaction.
*Quick check:* Validate that precision measures align with actual user satisfaction and selection behavior.

## Architecture Onboarding
**Component map:** User Interface -> Preference Weighting Engine -> Ranking Algorithm -> Result Display -> User Feedback Collection
**Critical path:** User sets preferences → System weights criteria → Results ranked and displayed → User evaluates and provides feedback
**Design tradeoffs:** The preference weighting interface adds complexity but potentially increases satisfaction and precision; simpler interfaces may be faster but less personalized.
**Failure signatures:** If users skip preference setting, the system may fall back to equal weighting; poor weight assignments may lead to irrelevant results.
**First experiments:** 1) Test whether different weight distributions consistently improve precision for different user segments, 2) Measure if interface support perception correlates with actual search success across different product categories, 3) Evaluate whether the precision-satisfaction relationship holds when controlling for price sensitivity.

## Limitations
- Small sample size of 24 participants limits statistical power and generalizability
- Lab study setting may not reflect real-world usage patterns where users have more time and context
- Study focuses specifically on hotel search, raising questions about transferability to other domains

## Confidence
- User satisfaction and preference for weighted interface: High confidence
- Relevance and price outcomes: Medium confidence
- Time and clicks metrics: Low confidence

## Next Checks
1. Replicate the study with a larger, more diverse participant pool (minimum 50-100 users) across multiple product domains beyond hotels
2. Conduct field studies comparing interfaces in naturalistic settings over extended time periods rather than controlled lab tasks
3. Test the perceived support-precision relationship with controlled experiments varying interface feedback mechanisms while holding other variables constant
