# Even if Explanations: Prior Work, Desiderata & Benchmarks for Semi-Factual XAI

## Quick Facts
- arXiv ID: 2301.11970
- Source URL: https://arxiv.org/abs/2301.11970
- Reference count: 0
- A new benchmark study finds that the MDN method excels at finding distant semi-factual explanations in tabular data.

## Executive Summary
This paper surveys semi-factual explanations (SFs) in explainable AI, defining them as explanations of why certain changes would not alter an AI decision, contrasting them with counterfactual explanations. The authors establish desiderata for SFs including sparsity, plausibility, and psychological impact, then conduct a systematic literature review. Four historical SF algorithms are benchmarked against a newly-proposed "Most Distant Neighbors" (MDN) method using seven tabular datasets. MDN and the Local-Region method performed best overall, with MDN excelling in finding the most distant SFs while maintaining reasonable sparsity.

## Method Summary
The study benchmarks five semi-factual explanation methods (3 KLEOR variants, Local-Region method, and MDN) using seven tabular binary-class datasets with 3-NN models. The MDN method computes, for each feature of the query, two ranked sets (HighSet and LowSet) and scores them using an sfs function that prioritizes sparse explanations while maximizing distance on one key feature. Leave-one-out cross-validation is used to generate SFs for every instance, and five evaluation metrics are computed: Query-to-SF Distance (L2 norm), Query-to-SF kNN (%), SF-to-Q-Class Distance (Mahalanobis), MDN Distance (sfs function), and Sparsity (% of 1-diff, 2-diff, >3-diff feature differences).

## Key Results
- MDN method found semi-factuals that were on average 2.3x more distant than historical methods while maintaining comparable sparsity
- The Local-Region method performed best overall, excelling at finding SFs near decision boundaries
- KLEOR methods showed varied performance, with Sim-Miss variant being most consistent across datasets
- Sparsity results showed MDN producing more 1-diff and 2-diff SFs than >3-diff SFs, indicating good balance between distance and interpretability

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** MDN finds semi-factual explanations that are maximally distant from the query while still being within the same class, making them more convincing to users.
- **Mechanism:** The MDN method computes, for each feature of the query, two ranked sets: instances with higher feature values (HighSet) and instances with lower feature values (LowSet). Each set is scored using the semi-factual score (sfs) function that prioritizes instances with few feature differences while having the largest possible difference on the key feature. The instance with the highest sfs value across all features is chosen as the semi-factual.
- **Core assumption:** A good semi-factual explanation should be as far from the query as possible within the same class while maintaining minimal feature differences elsewhere, which increases its psychological impact.
- **Evidence anchors:** [abstract] "A na¨ıve benchmark algorithm, based on the new idea of Most Distant Neighbors (MDNs)"
- **Break condition:** If the sfs function weights feature difference and similarity equally (or incorrectly), the method may produce explanations with too many feature differences, reducing their plausibility and user acceptance.

### Mechanism 2
- **Claim:** The sfs function effectively balances sparsity and distance by combining counts of identical features with relative differences on the key feature.
- **Mechanism:** The sfs function calculates: (same features / total features) + (key feature difference / max key feature difference). This creates a composite score where high values indicate both high similarity on most features and maximum distance on one key feature.
- **Core assumption:** Users find semi-factuals more convincing when they see minimal changes except for one key feature that appears to have no causal effect on the outcome.
- **Evidence anchors:** [section] "sfs function that prioritises instances that are sparse (few feature differences) while also having the highest valuedifferences on a key-feature"
- **Break condition:** If the feature space is high-dimensional with many correlated features, the same features count may be misleading, causing the method to select semi-factuals that are not truly sparse in interpretable terms.

### Mechanism 3
- **Claim:** Local region methods can identify semi-factuals that are close to the query in the local decision boundary space, making them more relevant to the specific prediction context.
- **Mechanism:** A surrogate model (logistic regression) is built using perturbations of the query instance to capture the local decision boundary. Candidate neighbors are then evaluated using this local model, with the instance having the highest probability closest to the decision boundary being selected as the semi-factual.
- **Core assumption:** The most convincing semi-factuals are those that lie just before the decision boundary in the local region around the query, as they represent the edge of what wouldn't change the outcome.
- **Evidence anchors:** [section] "The intuition here is that good semi -factuals should be close to the query's local decision boundary, while being as far as possible from it in this local space"
- **Break condition:** If the local region is too small or the surrogate model poorly approximates the true decision boundary, the method may select semi-factuals that are not truly on the edge of the class boundary, reducing their explanatory power.

## Architecture Onboarding

- **Component map:**
  Data preprocessing pipeline -> Query instance representation -> Semi-factual search algorithm -> sfs scoring function -> Local surrogate model builder -> Evaluation metrics calculator -> Cross-validation orchestrator -> Result visualization

- **Critical path:**
  1. Load dataset and preprocess features
  2. For each instance as query, run semi-factual search algorithm
  3. Calculate evaluation metrics for each method-dataset combination
  4. Compare results across methods and datasets
  5. Generate benchmark summary and visualizations

- **Design tradeoffs:**
  - MDN vs KLEOR methods: MDN is simpler but may produce less sparse explanations; KLEOR variants are more sophisticated but require careful parameter tuning
  - Local vs global distance metrics: Local methods capture boundary proximity better but are computationally more expensive
  - Sparsity vs distance tradeoff: More distant semi-factuals may be more convincing but less actionable if they require changing too many features

- **Failure signatures:**
  - All methods returning the same instance as semi-factual (indicates poor diversity in search space)
  - Extremely high sparsity (>3 feature differences) across all datasets (suggests sfs function needs weighting adjustment)
  - Local Region method failing to build valid surrogate models (check perturbation strategy and sample size)
  - MDN method returning instances far outside the data manifold (check distance calculations and data normalization)

- **First 3 experiments:**
  1. Implement MDN method with a simple sfs function (equal weights) and test on a small binary classification dataset to verify it finds instances in the same class but far from the query
  2. Compare MDN and Sim-Miss KLEOR variant on one dataset, checking if MDN consistently finds more distant semi-factuals as measured by L2 distance
  3. Implement the sfs function with adjustable weights and run sensitivity analysis to find optimal weights that balance sparsity and distance for a specific dataset

## Open Questions the Paper Calls Out

- **Question:** How do semi-factual explanations impact user trust and acceptance of AI systems compared to counterfactual explanations in real-world applications?
  - Basis in paper: [explicit] The paper identifies a significant limitation in current research: "The paucity of user studies is another severe limitation; until some carefully-controlled studies are carried out, we do not really know how users will respond to these explanations in the AI context."
  - Why unresolved: While the paper references some user studies on semi-factuals, they are limited in scope and don't directly compare semi-factuals to counterfactuals in practical AI applications.
  - What evidence would resolve it: Controlled user studies comparing user trust, understanding, and acceptance of semi-factual vs. counterfactual explanations across different AI application domains (e.g., medical diagnosis, loan applications, autonomous vehicles).

- **Question:** Can the Most Distant Neighbors (MDN) method be effectively extended to handle complex, high-dimensional data like images and time-series data while maintaining computational efficiency?
  - Basis in paper: [explicit] The paper notes: "it is to be noted that in the current benchmark study we have concentrated on tabular data, largely to respect the focus of historical methods. However, the desiderata and evaluation metrics should equally apply to image dataset (and possibly time-series data), albeit relying more on latent features."
  - Why unresolved: The MDN method was only tested on tabular datasets, and its performance on high-dimensional data remains unknown.
  - What evidence would resolve it: Empirical testing of MDN on image datasets using latent features, comparing performance with image-specific semi-factual methods like PIECE and C2C-VAR, while measuring computational complexity.

- **Question:** What are the ethical implications of using semi-factual explanations in sensitive domains, and how can we ensure they are not misused to manipulate user understanding or decisions?
  - Basis in paper: [explicit] The paper warns: "we believe that it is important to reiterate the ethical point about the use of semi-factuals (a point that also applies to counterfactuals). These explanatory methods have significant cognitive impacts on people's understanding of AI systems and domains, they convince and dissuade people. But, they could be misused if certain assumptions are violated."
  - Why unresolved: The paper identifies ethical concerns but doesn't provide concrete guidelines for auditing or regulating semi-factual explanations in practice.
  - What evidence would resolve it: Development of ethical frameworks and audit metrics for semi-factual explanations, including case studies of potential misuse scenarios and corresponding safeguards.

## Limitations
- Experimental setup uses only tabular datasets with binary classification, limiting generalizability to other data types
- Evaluation relies entirely on algorithmic metrics without user studies to validate psychological impact claims
- MDN method's effectiveness depends on specific sfs function formulation that wasn't empirically validated against alternatives

## Confidence
- **High**: MDN method novelty and basic implementation (supported by clear algorithmic description and code availability)
- **Medium**: Relative performance comparisons between methods (based on systematic benchmarking but limited to specific datasets and models)
- **Low**: Claims about psychological impact and user preference (not empirically tested, only theoretically argued)
