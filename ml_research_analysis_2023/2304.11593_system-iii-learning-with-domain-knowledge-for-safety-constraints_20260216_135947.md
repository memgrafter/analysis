# System III: Learning with Domain Knowledge for Safety Constraints

## Quick Facts
- arXiv ID: 2304.11593
- Source URL: https://arxiv.org/abs/2304.11593
- Reference count: 30
- One-line primary result: System III integrates domain expert knowledge expressed as first-order logic constraints into reinforcement learning to achieve safer exploration and improved sample efficiency in safety-critical domains.

## Executive Summary
This paper introduces System III, a novel framework that incorporates domain expert knowledge expressed as first-order logic constraints into reinforcement learning to achieve safer exploration and improved sample efficiency in safety-critical domains. The approach represents constraints as hazards, objects, and regions to avoid during exploration, and evaluates their satisfaction via p-norms in state vector space. The method was evaluated on OpenAI Gym and Safety-Gym environments, showing that System III results in safer exploration and sample efficiency across tasks including classic control and safety games.

## Method Summary
System III is a reinforcement learning framework that integrates domain expert knowledge expressed as first-order logic constraints into the learning process. The system comprises two reciprocating subsystems: a forward dynamics model that predicts next states given current state and action, and a constraint evaluation system that assesses constraint satisfaction using p-norms in state vector space. The framework uses policy gradient methods (A3C) for model-free learning while simultaneously training the forward model for constraint evaluation, combining fast exploration with analytical safety guidance without modifying existing deep learning formulations or adding regularization parameters.

## Key Results
- System III achieves safer exploration by satisfying first-order logic constraints expressed as hazards, objects, and regions to avoid
- The framework demonstrates improved sample efficiency compared to standard RL methods across classic control and safety game tasks
- System III effectively balances safety and performance without requiring domain-specific engineering or modifying deep learning formulations

## Why This Works (Mechanism)

### Mechanism 1
Constraint satisfaction is evaluated using p-norms in state vector space to measure distance from hazards/objects/regions to avoid. The system uses a forward model to predict the next state given current state and action, then evaluates first-order logic constraints using p-norm distance metrics. If constraints are satisfied, reward is given; otherwise, no reward. This works because the forward model can accurately predict next states, and p-norm distance in state space adequately captures constraint satisfaction.

### Mechanism 2
System III combines fast exploration (model-free RL) with analytical constraint evaluation (model-based RL) for improved sample efficiency and safety. The system uses A3C policy gradient for model-free learning while simultaneously training a forward dynamics model to predict next states. Constraint satisfaction is evaluated using the forward model, providing analytical guidance that affects the reward function without modifying existing deep learning formulations. This works because model-based forward dynamics can be learned efficiently and provide accurate predictions for constraint evaluation.

### Mechanism 3
Constraints expressed in first-order logic provide expressive yet intuitive safety specifications that are easily understandable for humans. Domain expert knowledge is encoded as first-order logic formulas, which are evaluated at each time step. This allows for high-level, general constraints rather than hard-coded actions. This works because first-order logic can adequately express most necessary safety constraints for the domain.

## Architecture Onboarding

- Component map: State → Policy Network → Action → Forward Model → Constraint Evaluation → Reward → Policy Update
- Critical path: State → Policy Network → Action → Forward Model → Constraint Evaluation → Reward → Policy Update
- Design tradeoffs: The approach trades computational overhead (running forward model at each step) for improved safety and sample efficiency. The p-norm evaluation is computationally efficient but may not capture all constraint nuances.
- Failure signatures: Poor forward model predictions leading to incorrect constraint evaluation, overly conservative constraints limiting exploration too much, or first-order logic formulas that are too complex to evaluate in real-time.
- First 3 experiments:
  1. CartPole with simple position constraint (lb ≤ x ≤ ub) to verify basic functionality
  2. CartPole with combined position and angle constraints to test multiple constraint handling
  3. Safety-Gym Point agent with static hazards to validate performance in more complex environments

## Open Questions the Paper Calls Out

### Open Question 1
How does System III's performance compare to other safe RL methods on more complex and diverse tasks? The paper evaluates System III on OpenAI Gym and Safety-Gym environments but does not compare its performance to other safe RL methods on more complex and diverse tasks, leaving uncertainty about the generalizability and scalability of System III.

### Open Question 2
How does the choice of constraint representation (e.g., p-norm) affect System III's performance and safety guarantees? The paper mentions that constraints are evaluated via p-norms in state vector space but does not explore the impact of different constraint representations on System III's performance and safety guarantees.

### Open Question 3
How does System III handle partial observability and uncertainty in the environment? The paper assumes that the constraints are fully known and does not explicitly address how System III handles partial observability or uncertainty in the environment, which is a common challenge in real-world applications.

## Limitations

- Forward dynamics model accuracy is critical but not empirically validated, potentially leading to incorrect constraint evaluation
- P-norm distance metrics may not capture complex constraint geometries, risking false positives or negatives
- Computational overhead from dual-system architecture may negate sample efficiency gains in practice
