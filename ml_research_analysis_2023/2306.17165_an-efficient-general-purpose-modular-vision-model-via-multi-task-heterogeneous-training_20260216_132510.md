# An Efficient General-Purpose Modular Vision Model via Multi-Task Heterogeneous Training

## Quick Facts
- arXiv ID: 2306.17165
- Source URL: https://arxiv.org/abs/2306.17165
- Reference count: 40
- Primary result: Multi-task heterogeneous training framework achieves comparable performance to single-task SOTAs while enabling efficient modular adaptation to downstream tasks

## Executive Summary
This paper presents a multi-task heterogeneous training (MTHL) framework that learns a general-purpose vision model capable of classification, detection, and segmentation through simultaneous training on diverse datasets (ImageNet, COCO, ADE20K). The framework leverages Mixture-of-Experts (MoE) vision transformers with dataset-specific routers that learn to select relevant experts, creating an emergent modular structure. This modularity enables efficient adaptation to downstream tasks with fewer training parameters, model parameters, and computation compared to traditional fine-tuning approaches.

## Method Summary
The MTHL framework combines a backbone transformer (Swin or DaViT) with MoE layers, task-specific heads (classification, detection retina head, segmentation UperNet), and dataset-specific routers. During pre-training, the model learns from heterogeneous datasets using weighted sampling and task-specific loss weights, with MoE routers learning dataset-specific expert selection patterns. For downstream adaptation, the framework exploits its modular structure by learning new routers with smaller Top-K values to reduce computation, pruning irrelevant experts, or learning new experts while freezing existing ones. The approach is trained using large batch optimization with Lamb optimizer for 240,000 iterations on 96 Tesla V100 GPUs.

## Key Results
- Achieves comparable performance to single-task state-of-the-art models on classification, detection, and segmentation tasks
- Demonstrates strong generalization on downstream tasks with efficient adaptation requiring fewer training parameters, model parameters, and FLOPs
- Shows the ability to expand for continual learning without catastrophic forgetting by adding new experts while freezing existing ones

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Modularity emerges from MoE routers learning dataset-specific expert selection patterns
- Mechanism: During multi-task heterogeneous training, dataset-specific routers in each MoE module learn to assign different subsets of experts to each dataset. This creates an emergent modular structure where each expert specializes in certain datasets. When adapting to a new downstream task, the router can select the most relevant experts without needing to update the entire model.
- Core assumption: Expert selection patterns learned during heterogeneous training generalize to downstream tasks with similar characteristics
- Evidence anchors:
  - [abstract] "Due to its emergent modularity, this general-purpose model decomposes into high-performing components"
  - [section 3.2] "we use an approximation inspired by the following idea" and description of buffer-based MI loss for heterogeneous training
  - [corpus] Weak - related papers discuss modular approaches but not the specific MoE-based modularity mechanism
- Break condition: If downstream tasks have characteristics very different from pre-training datasets, the learned router patterns may not select appropriate experts

### Mechanism 2
- Claim: Heterogeneous training improves generalization by exposing the model to diverse data distributions
- Mechanism: Training simultaneously on ImageNet (classification), COCO (detection), and ADE20K (segmentation) exposes the model to different data distributions, scales, and task requirements. This diverse training set provides richer semantic representations that generalize better to unseen downstream tasks compared to single-task pre-training.
- Core assumption: Diversity in pre-training data improves downstream generalization
- Evidence anchors:
  - [abstract] "Benefiting from a more diverse training set designed for multiple purposes, the framework generalizes better"
  - [section 4.1] "We observe that: 1) Heterogeneous training performs on par with the state-of-the-art pre-train then fine-tune learning scheme"
  - [corpus] Weak - related papers discuss multi-task learning but not specifically the heterogeneous training approach
- Break condition: If the downstream tasks are very similar to one of the pre-training tasks, the benefits of heterogeneous training may be minimal

### Mechanism 3
- Claim: Conditional computation via Top-K routing enables efficient adaptation by reducing computation
- Mechanism: The Top-K routing mechanism in MoE allows the model to activate only a subset of experts during inference. When adapting to downstream tasks, the router can be trained with a smaller Top-K value, reducing the number of experts activated per forward pass and thus lowering computation cost while maintaining performance.
- Core assumption: A smaller Top-K can maintain performance while reducing computation
- Evidence anchors:
  - [abstract] "Reduce computation cost via learning new routers with a smaller Top-K that makes fewer experts chosen in one forward pass"
  - [section 3.3] "The new router for the downstream dataset can be learned with a smaller Top-K"
  - [corpus] Weak - related papers discuss efficiency but not specifically the Top-K adaptation mechanism
- Break condition: If the downstream task requires diverse expert combinations, reducing Top-K may hurt performance

## Architecture Onboarding

- Component map:
  Backbone -> MoE MLP layers -> Task-specific heads -> Dataset-specific routers
  (ImageNet/COCO/ADE20K) -> (12 experts, Top-K=4) -> (Classification/Detection/Segmentation) -> (Separate routing networks)

- Critical path:
  1. Sample dataset using weighted sampling
  2. Forward pass through backbone with MoE routing
  3. Apply task-specific processing
  4. Compute task losses with dataset-specific weights
  5. Update buffer for MI loss approximation
  6. Backpropagate gradients

- Design tradeoffs:
  - MoE size vs performance: More experts provide better specialization but increase computation
  - Top-K vs accuracy: Larger Top-K improves accuracy but increases latency
  - Router complexity vs adaptation speed: More complex routers may adapt better but train slower

- Failure signatures:
  - Gradient conflicts: One task dominates training, others stagnate
  - Router collapse: All experts get the same weight, losing specialization
  - Buffer drift: MI loss approximation becomes inaccurate over long training

- First 3 experiments:
  1. Reproduce single-task baselines to establish performance floor
  2. Train heterogeneous model with dense backbone (MTHL.D) to compare with sparse version
  3. Test adaptation efficiency by learning new routers on downstream datasets with different Top-K values

## Limitations
- Scalability of MoE routing is not thoroughly validated across heterogeneous datasets
- Performance and modularity demonstrated primarily on COCO, ImageNet, and ADE20K datasets
- Memory footprint of maintaining 12 experts per MoE layer and separate routers may limit deployment

## Confidence
- High confidence: The basic premise that heterogeneous multi-task training can improve generalization
- Medium confidence: The claim about emergent modularity enabling efficient adaptation
- Medium confidence: The catastrophic forgetting prevention claim

## Next Checks
