# All in Tokens: Unifying Output Space of Visual Tasks via Soft Token

## Quick Facts
- arXiv ID: 2301.02229
- Source URL: https://arxiv.org/abs/2301.02229
- Reference count: 40
- Primary result: State-of-the-art 0.279 RMSE on NYUv2 depth estimation using unified AiT framework

## Executive Summary
This paper introduces AiT (All in Tokens), a framework that unifies the output space of diverse visual tasks through a general tokenizer based on VQ-VAE and soft token prediction. The key innovation is encoding visual task outputs as sequences of discrete tokens, enabling a single auto-regressive transformer to handle multiple tasks like instance segmentation and depth estimation. The approach achieves competitive performance on COCO instance segmentation and state-of-the-art results on NYUv2 depth estimation.

## Method Summary
The AiT framework consists of three components: a tokenizer (VQ-VAE encoder) that converts visual outputs to discrete tokens, a detokenizer (VQ-VAE decoder) that reconstructs visual outputs, and a task solver (auto-regressive encoder-decoder) that predicts tokens from images. The method introduces soft tokens, which use weighted averages of codebook embeddings based on probability vectors, enabling continuous interpolation in the codebook space. Mask augmentation is applied during VQ-VAE training for depth estimation to handle corrupted regions. A lightweight VQ-VAE architecture with 128 codebooks is used to keep computational overhead low while maintaining performance.

## Key Results
- Achieves state-of-the-art 0.279 RMSE on NYUv2 depth estimation
- Competitive accuracy on COCO instance segmentation with unified framework
- Soft token technique improves accuracy without additional computational cost
- Lightweight VQ-VAE architecture (2M parameters, 0.06G FLOPs) sufficient for visual task unification

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Soft tokens improve accuracy by allowing continuous interpolation in the codebook space
- Mechanism: Instead of hard one-hot assignments to discrete codebook embeddings, soft tokens use weighted averages of codebook embeddings based on probability vectors. This creates an interpolable continuous space that better represents visual outputs, especially continuous ones like depth maps
- Core assumption: The correlation between tokens in visual tasks means that hard one-hot assignments create suboptimal representations that lose useful information
- Evidence anchors:
  - [abstract]: "Soft token can improve the accuracy of both the next token inference and decoding of the task output"
  - [section 3.3]: "When a soft token is fed to the input of the detokenizer or to the input of the next token prediction network, its input embedding is computed by the weighted average of the codebook embeddings based on the probability values"
  - [corpus]: Weak evidence - related works focus on visual tokenization but don't specifically address soft token interpolation mechanisms
- Break condition: If visual outputs have no correlation between adjacent values, or if the task requires strict discrete boundaries (like categorical labels), soft tokens may add unnecessary complexity

### Mechanism 2
- Claim: Mask augmentation helps VQ-VAE learn to handle corrupted/undefined regions in visual annotations
- Mechanism: By randomly masking regions in training depth maps and providing ground truth for those regions, the VQ-VAE learns to reconstruct missing information. This transfers to better handling of naturally corrupted regions like occlusions in depth estimation
- Core assumption: The ability to reconstruct artificially masked regions generalizes to reconstructing naturally corrupted regions in the same image space
- Evidence anchors:
  - [abstract]: "Many visual tasks have corruption, undefined or invalid values in label annotations, i.e., occluded area of depth maps"
  - [section 3.4]: "We randomly mask some regions in the input depth images and then use their original depth information as supervision"
  - [section 4.3]: "The best performance is achieved by using the mask ratio of 0.5, which is +0.005 better than the baseline"
- Break condition: If corrupted regions are too large relative to valid regions, or if the corruption pattern is too different from natural occlusions, the augmentation may not generalize

### Mechanism 3
- Claim: Lightweight VQ-VAE architecture with small codebook size is sufficient for visual task unification
- Mechanism: A very lightweight VQ-VAE with 5 convolution layers, 2 residual blocks, and 128 codebooks can effectively tokenize both depth estimation and instance segmentation outputs while keeping computational overhead low
- Core assumption: The output space of visual tasks (depth maps, binary masks) is simpler than natural images, requiring less complex tokenization
- Evidence anchors:
  - [section 3.1]: "We find that a very lightweight VQ-V AE can achieve promising results in depth estimation and instance segmentation"
  - [section 3.1]: "The number of parameters and computations can be as small as 2M and 0.06G FLOPs"
  - [section 4.3]: "We note that though larger codebook size consistently improves VQ-V AE reconstruction ability, they show no difference when applied to task-solver"
- Break condition: If visual tasks have more complex output structures (e.g., multi-channel semantic maps with many classes), the small codebook may become insufficient

## Architecture Onboarding

- Component map:
  - Image → Task solver (Swin Transformer) → Predicted tokens → Detokenizer (VQ-VAE decoder) → Visual output
  - Visual output → Tokenizer (VQ-VAE encoder) → Tokens → Task solver → Loss computation

- Critical path:
  1. During training: Visual output → Tokenizer → Tokens → Task solver → Predicted tokens → Detokenizer → Reconstructed output → Loss computation
  2. During inference: Image → Task solver → Predicted tokens → Detokenizer → Visual output

- Design tradeoffs:
  - Small codebook (128) vs large codebook (8192): Smaller codebook reduces memory and computation but may lose fine-grained distinctions
  - Downsample ratio 32 vs 16: Higher ratio reduces sequence length but may lose spatial resolution
  - Soft token vs hard token: Soft token adds interpolation capability but requires probability computation

- Failure signatures:
  - Poor reconstruction quality: Check if VQ-VAE is underfitting or if codebook size is too small
  - Mode collapse in token predictions: Check if task solver is not learning diverse token sequences
  - Artifacts in depth maps: Check mask augmentation effectiveness or if corrupted regions are not being handled

- First 3 experiments:
  1. Train VQ-VAE alone on depth maps with different codebook sizes (64, 128, 256) and measure reconstruction RMSE to find optimal size
  2. Implement soft token inference and compare hard vs soft token performance on a validation set
  3. Test mask augmentation with different masking ratios (0.3, 0.5, 0.7) on depth estimation to find optimal augmentation strength

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal codebook size for VQ-VAE in this framework, and how does it affect performance across different visual tasks?
- Basis in paper: [explicit] The paper mentions that a small codebook size (e.g., 64) can achieve sufficiently good reconstruction performance, and different codebook sizes have little effect on the final performance when applied to the task-solver. However, the paper does not provide a definitive answer on the optimal codebook size.
- Why unresolved: The paper shows that smaller codebooks work well, but does not systematically test the performance impact of larger codebooks (e.g., 512 or 1024) or explore whether task-specific optimal codebook sizes exist.
- What evidence would resolve it: A comprehensive ablation study varying codebook size across multiple visual tasks (depth estimation, instance segmentation, and others) to determine the performance trade-offs and identify task-specific optimal codebook sizes.

### Open Question 2
- Question: How does the soft token technique perform in tasks beyond depth estimation and instance segmentation, such as object detection or semantic segmentation?
- Basis in paper: [explicit] The paper demonstrates the effectiveness of soft token in depth estimation and instance segmentation, showing performance improvements without additional computational cost. However, it does not explore the technique's applicability to other visual tasks.
- Why unresolved: The paper focuses on two specific tasks, leaving open the question of whether soft token is universally beneficial across the broader spectrum of visual tasks.
- What evidence would resolve it: Empirical results showing the impact of soft token on a diverse set of visual tasks, including object detection, semantic segmentation, and optical flow estimation, with quantitative comparisons to baseline methods.

### Open Question 3
- Question: Can the parallel decoder approach achieve better performance than the auto-regressive decoder for tasks other than depth estimation, such as instance segmentation or object detection?
- Basis in paper: [explicit] The paper presents preliminary studies on parallel decoding for depth estimation, showing it performs better than the auto-regressive counterpart. However, it does not explore the effectiveness of parallel decoding for other tasks.
- Why unresolved: The paper only provides initial results for depth estimation, and the potential benefits of parallel decoding for other tasks remain unexplored.
- What evidence would resolve it: A systematic comparison of auto-regressive and parallel decoders across multiple visual tasks, including instance segmentation and object detection, with performance metrics such as accuracy, inference speed, and computational efficiency.

## Limitations

- The soft token mechanism's effectiveness is primarily validated on depth estimation and instance segmentation tasks, with limited evidence for generalization to other visual tasks
- The lightweight VQ-VAE architecture may face limitations when scaling to more complex visual outputs with many classes or channels
- The mask augmentation technique shows modest improvements (+0.005 RMSE) but lacks comprehensive sensitivity analysis across different corruption patterns

## Confidence

**High Confidence**: The core architectural framework (tokenizer-task solver-detokenizer pipeline) is well-specified and the reported numerical results on COCO and NYUv2 datasets appear reproducible based on the provided implementation details.

**Medium Confidence**: The soft token mechanism's theoretical advantages are plausible and partially supported by the evidence, but the magnitude of improvement and its dependence on task-specific properties remain unclear without broader empirical validation.

**Low Confidence**: The claim that this approach provides a general solution for unifying diverse visual task outputs is premature given the limited scope of tasks tested and the lack of comparison with alternative unification strategies.

## Next Checks

1. **Cross-task generalization test**: Apply the AiT framework to semantic segmentation and object detection tasks beyond the tested depth estimation and instance segmentation. Measure whether soft tokens provide consistent improvements across these additional task types, and whether the lightweight VQ-VAE architecture remains sufficient.

2. **Correlation dependency validation**: Design a controlled experiment comparing soft vs hard tokens on visual tasks with varying degrees of output correlation. Use synthetic depth maps with controlled correlation structures or modify instance segmentation outputs to test whether the soft token advantage correlates with output space correlation.

3. **Codebook scaling study**: Systematically vary codebook size beyond the tested 128 embeddings (e.g., 64, 256, 512) and measure both VQ-VAE reconstruction quality and task solver performance. This would clarify whether the task solver bottleneck is real and whether larger codebooks could unlock better performance if the solver architecture were modified.
