# MFBE: Leveraging Multi-Field Information of FAQs for Efficient Dense Retrieval

## Quick Facts
- arXiv ID: 2302.11953
- Source URL: https://arxiv.org/abs/2302.11953
- Authors: 
- Reference count: 32

## Executive Summary
This paper addresses FAQ retrieval challenges in question-answering systems, including lexical gaps, insufficient context, data scarcity, and high latency. The proposed Multi-Field Bi-Encoder (MFBE) model leverages multiple FAQ fields (question, answer, category) during training and inference to capture additional context. By creating pseudo-positive pairs from different field combinations and using contrastive learning, MFBE achieves significant improvements in retrieval accuracy while maintaining efficient inference through pre-computed embeddings.

## Method Summary
MFBE employs a bi-encoder architecture with LaBSE as the text encoder, using contrastive learning with pseudo-positive pairs created from FAQ field combinations (Q, A, QA, QC, AC, CA, QAC). The model trains to pull matching pairs close and push non-matching pairs apart in embedding space. During inference, pre-computed FAQ embeddings enable fast retrieval through cosine similarity ranking. The approach addresses FAQ retrieval challenges by expanding training signal without manual labels, enabling efficient pre-computation, and using in-batch negatives for improved contrastive learning.

## Key Results
- MFBE achieves 27% better top-1 accuracy on internal Japanese datasets compared to best baseline
- MFBE achieves 20% better top-1 accuracy on open English datasets compared to best baseline
- Model demonstrates robustness in cross-domain and multi-domain settings with potential for cold-start scenarios

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Multi-field combinations expand positive training signal without extra manual labels
- Mechanism: By creating pseudo-positive pairs from FAQ field combinations (e.g., QA, QC, AC), the model implicitly learns cross-field semantic similarity, enriching the training space
- Core assumption: Field concatenation preserves or enhances semantic relationships needed for retrieval
- Evidence anchors:
  - [abstract] "leverages multiple combinations of FAQ fields... to create an extended set of pseudo-positive pairs for training"
  - [section] "we consider both the pairs (F Q,F A) and (F QC,F A) from an FAQF as proxy for(q,F m)"
  - [corpus] Weak - no explicit corpus evidence that field concatenation preserves semantics
- Break condition: If field concatenation introduces noise or destroys context, pseudo-positive pairs mislead training

### Mechanism 2
- Claim: Pre-computed embeddings enable fast inference while maintaining accuracy
- Mechanism: Bi-encoder design allows FAQ embeddings to be computed once and indexed, avoiding expensive query-FAQ joint scoring
- Core assumption: Cosine similarity on fixed embeddings is sufficient proxy for relevance
- Evidence anchors:
  - [abstract] "bi-encoder-based query-FAQ matching model"
  - [section] "pre-computation and indexing of sentence embeddings of the FAQs before-hand, which is not possible with cross-encoders"
  - [corpus] None directly, but matches known bi-encoder retrieval trade-offs
- Break condition: If FAQ embeddings drift significantly over time, cached representations degrade

### Mechanism 3
- Claim: Gold in-batch negatives improve contrastive learning efficiency
- Mechanism: Using positives from the same batch as negatives provides diverse, semantically close negatives without external mining
- Core assumption: Mini-batch sampling yields negatives that are hard enough to improve embedding quality
- Evidence anchors:
  - [section] "we make use ofGold FAQs from the same mini-batch as negatives, termed as in-batch negatives"
  - [corpus] None - this is a standard contrastive learning trick not specific to the paper
- Break condition: If batch size is too small or negatives too easy, model fails to learn discriminative embeddings

## Architecture Onboarding

- Component map: Text encoder (LaBSE) → Pooling → Similarity layer → Contrastive loss; Training loop → Pre-compute FAQ embeddings → Inference retrieval
- Critical path: Training: Input → Encoder → Embedding → Loss → Parameter update; Inference: Query embedding → Cosine similarity → Top-k ranking
- Design tradeoffs: Bi-encoder enables fast retrieval via pre-computation but sacrifices fine-grained cross-attention; multi-field increases training signal but adds complexity
- Failure signatures: Poor accuracy indicates bad negatives or field combinations; slow inference suggests embedding pre-computation missing or broken

## Limitations
- Cross-domain robustness claims rely heavily on limited internal dataset splits
- Zero-shot transfer performance on open datasets not evaluated
- Effectiveness of different field combination strategies lacks empirical validation

## Confidence
- **High confidence**: The 27% and 20% accuracy improvements over baselines are well-supported by experimental results across multiple datasets
- **Medium confidence**: The cross-domain and multi-domain robustness claims are supported but limited to internal datasets with specific conditions
- **Low confidence**: The effectiveness of different field combination strategies is not empirically validated, and cold-start scenario potential remains theoretical without experiments
