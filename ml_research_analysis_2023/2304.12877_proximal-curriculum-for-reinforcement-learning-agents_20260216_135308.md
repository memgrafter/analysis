# Proximal Curriculum for Reinforcement Learning Agents

## Quick Facts
- arXiv ID: 2304.12877
- Source URL: https://arxiv.org/abs/2304.12877
- Authors: 
- Reference count: 40
- Key outcome: ProCuRL accelerates RL training by selecting tasks of intermediate difficulty based on ZPD principles, outperforming state-of-the-art baselines in sample efficiency and computational efficiency.

## Executive Summary
This paper introduces ProCuRL, a curriculum strategy for reinforcement learning agents that draws inspiration from the pedagogical concept of Zone of Proximal Development (ZPD). The strategy mathematically derives an intuitive approach to task selection by analyzing simple learning settings, aiming to pick tasks that are neither too hard nor too easy for the learner. ProCuRL is designed to be easily integrated with deep RL frameworks with minimal hyperparameter tuning and demonstrates superior performance across various domains including PointMass navigation, Karel programming, ball catching, and AntGoal tasks.

## Method Summary
ProCuRL is a curriculum strategy for RL agents in contextual multi-task settings that selects tasks based on maximizing learning progress. The method can operate in two variants: ProCuRL-env which uses additional policy rollouts to estimate success probabilities, and ProCuRL-val which leverages critic network values for efficiency. Both variants implement the same core selection principle but differ in computational overhead and sample efficiency. The strategy is integrated with PPO algorithm and requires only minimal hyperparameter tuning, with β controlling the exploration-exploitation trade-off in task selection.

## Key Results
- ProCuRL outperforms state-of-the-art baselines in sample efficiency and computational efficiency across 5 benchmark environments
- ProCuRL-val variant achieves competitive performance while requiring no additional environment steps for task selection
- The method maintains robust performance across diverse task spaces including continuous navigation, discrete programming, and goal-reaching tasks

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Curriculum strategy maximizes learning progress by selecting tasks with intermediate probability of success.
- **Mechanism**: The strategy selects tasks based on maximizing the product of current success probability and the gap to optimal success probability. This balances exploitation (tasks agent can already solve) and exploration (tasks with large improvement potential).
- **Core assumption**: There exists a smooth relationship between parameter updates and performance improvement, allowing the geometric mean to capture optimal learning progress.
- **Evidence anchors**:
  - [abstract]: "ProCuRL captures the intuition that learning progress is maximized when picking tasks that are neither too hard nor too easy for the learner."
  - [section 3.1]: "Building on this idea, we mathematically derive an intuitive curriculum strategy by analyzing two simple learning settings."
  - [corpus]: No direct evidence; related works mention similar strategies but lack theoretical justification.
- **Break condition**: If the relationship between policy parameters and task success is non-smooth or discontinuous, the geometric mean may not capture optimal progress.

### Mechanism 2
- **Claim**: Using value function estimates instead of direct success probability improves sample efficiency.
- **Mechanism**: ProCuRL-val replaces expensive policy rollouts for success probability estimation with critic network values, reducing computational overhead while maintaining selection quality.
- **Core assumption**: Critic values correlate well with actual success probabilities across the task space.
- **Evidence anchors**:
  - [section 3.3]: "To tackle this issue, we replace PoSt(s) with values Vt(s) obtained from the critic network of the RL agent."
  - [section 4.3]: "ProCuRL-val has similar sample complexity as state-of-the-art baselines since it does not require additional environment steps for the teacher component."
  - [corpus]: No direct evidence; assumption needs validation in environments with sparse rewards.
- **Break condition**: If critic values poorly correlate with success probabilities, task selection quality degrades significantly.

### Mechanism 3
- **Claim**: Stochastic task selection via softmax improves robustness to approximation errors.
- **Mechanism**: Replaces arg max with softmax selection, adding exploration and reducing brittleness from estimation errors in PoS values.
- **Core assumption**: Some stochasticity in task selection helps the agent explore the task space more effectively.
- **Evidence anchors**:
  - [section 3.3]: "To tackle this issue, we replace arg max selection in Eq. 1 with softmax selection and sample according to the following distribution."
  - [section 4.3]: Implicit in comparison with IID baseline, showing ProCuRL-val performs better despite added stochasticity.
  - [corpus]: No direct evidence; assumption based on general RL principles.
- **Break condition**: If stochasticity is too high, agent may not focus enough on optimal tasks, slowing convergence.

## Architecture Onboarding

- **Component map**: PPO agent with policy and value networks -> Teacher component implementing ProCuRL selection -> Task pool Sinit -> Critic network providing value estimates Vt(s) -> Rollout buffer for PPO updates

- **Critical path**: Task selection → Policy execution → Value update → Next task selection

- **Design tradeoffs**:
  - ProCuRL-env: Higher sample efficiency for selection but requires additional rollouts
  - ProCuRL-val: Lower sample efficiency but uses existing critic values
  - β parameter: Controls exploration vs exploitation in task selection

- **Failure signatures**:
  - Critic values not correlating with success probabilities → Poor task selection
  - β too high → Random task selection, no learning progress
  - β too low → Stuck on easy tasks, no exploration

- **First 3 experiments**:
  1. Implement ProCuRL-val on PointMass-s with varying β values (10, 20, 30) to find optimal exploration-exploitation balance
  2. Compare ProCuRL-val vs IID baseline on BasicKarel to validate performance improvements

## Limitations

- Theoretical foundation relies on smooth relationship between policy parameters and task success, which may not hold in complex environments
- Empirical evaluation limited in scope, particularly the Karel domain with only 5 tasks
- Does not address generalization to unseen tasks, which is critical for real-world applications
- ProCuRL-env variant has significant computational overhead (4 additional environment steps per PPO iteration)

## Confidence

**High Confidence**: The core mechanism of selecting tasks based on intermediate success probability (Mechanism 1) is well-supported by both theoretical derivation and experimental results across multiple domains. The claim that ProCuRL outperforms baselines in sample efficiency and computational efficiency is directly validated through controlled experiments.

**Medium Confidence**: The effectiveness of using critic values instead of direct rollouts (Mechanism 2) is supported by experimental results, but the assumption that critic values correlate well with success probabilities across diverse environments needs further validation, particularly in environments with sparse rewards or complex value landscapes.

**Low Confidence**: The robustness improvement from stochastic task selection (Mechanism 3) is theoretically sound but lacks direct empirical validation in the paper. The claim that softmax selection provides meaningful benefits over deterministic selection is based on general RL principles rather than specific experiments.
