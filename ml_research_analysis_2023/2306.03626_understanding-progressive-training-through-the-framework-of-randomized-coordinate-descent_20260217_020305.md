# Understanding Progressive Training Through the Framework of Randomized Coordinate Descent

## Quick Facts
- arXiv ID: 2306.03626
- Source URL: https://arxiv.org/abs/2306.03626
- Reference count: 40
- One-line primary result: This paper analyzes the convergence of Randomized Progressive Training (RPT), a stochastic version of Progressive Training (PT), for general smooth objective functions and establishes theoretical convergence guarantees.

## Executive Summary
This paper introduces Randomized Progressive Training (RPT), a stochastic variant of Progressive Training that updates model parameters in a randomized fashion. By casting RPT into the framework of Randomized Coordinate Descent (RCD), the authors develop a novel convergence analysis that encompasses strongly-convex, convex, and nonconvex objectives. The method uses a PT-sketch operator to randomly select coordinate blocks for update based on a carefully designed probability distribution. Theoretical results establish convergence guarantees for RPT and identify regimes where it can outperform vanilla gradient descent in terms of total computation complexity.

## Method Summary
RPT is a stochastic optimization method that updates model parameters in a randomized fashion by selecting coordinate blocks based on a probability distribution proportional to the square root of their smoothness constants divided by their computation costs. The method is cast as an instance of Sketched Gradient Descent (SkGD) with a PT-sketch operator that provides unbiased gradient estimates. The convergence analysis leverages the framework of Randomized Coordinate Descent and introduces the LP quantity to characterize convergence across different regimes. The method is evaluated on synthetic quadratic functions, real-world datasets for ridge regression, and image classification using CIFAR10 with a ResNet18 model.

## Key Results
- RPT achieves faster convergence than vanilla gradient descent in regimes where blocks have heterogeneous smoothness constants and computation costs scale with block sizes.
- The method inherits convergence guarantees from RCD through its unbiased gradient estimation via the PT-sketch operator.
- RPT reduces total computation complexity by updating fewer parameters per iteration while maintaining convergence speed, as demonstrated on synthetic and real-world datasets.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: RPT achieves faster convergence by randomly selecting which blocks to update based on a carefully designed probability distribution.
- Mechanism: The method uses a PT-sketch operator that selects coordinate blocks with probabilities proportional to the square root of their smoothness constants divided by their computation costs. This design ensures that blocks with high curvature (large smoothness constants) are updated more frequently, while blocks with high computational cost are updated less frequently, balancing progress against cost.
- Core assumption: The smoothness constants of different blocks are sufficiently heterogeneous and the computation costs are proportional to block sizes.
- Evidence anchors:
  - [abstract]: "We then identify regimes where it can outperform vanilla gradient descent in terms of total computation complexity."
  - [section]: "Choosing the optimal RPT sketch is equivalent to solving the minimization problem... min LP · Σ(pi · cσi)"
  - [corpus]: Weak - the corpus papers focus on other randomized methods but don't directly address RPT's specific probability design.
- Break condition: If the smoothness constants across blocks are too similar, or if computation costs don't scale with block sizes as assumed, the probability distribution loses its effectiveness.

### Mechanism 2
- Claim: RPT inherits the convergence guarantees of Randomized Coordinate Descent (RCD) through its unbiased gradient estimation.
- Mechanism: By casting RPT as a special case of SkGD (Stochastic Sketched Gradient Descent) with an unbiased PT-sketch, the authors leverage existing RCD convergence theory. The key is that the PT-sketch provides an unbiased estimate of the gradient when scaled by the probability matrix P.
- Core assumption: The PT-sketch operator is properly constructed to ensure unbiased gradient estimation.
- Evidence anchors:
  - [abstract]: "We cast our method into the established framework of Randomized Coordinate Descent (RCD)... to establish a convergence theory for RPT."
  - [section]: "RPT is an instance of SkGD with probability matrix P = Diag((pσ1)d1, ..., (pσB)dB)."
  - [corpus]: Weak - corpus papers discuss RCD and coordinate descent but not specifically the PT-sketch construction.
- Break condition: If the PT-sketch construction fails to provide unbiased gradient estimates (e.g., due to implementation errors in the probability matrix), the convergence guarantees no longer hold.

### Mechanism 3
- Claim: RPT reduces total computation complexity by updating fewer parameters per iteration while maintaining convergence speed.
- Mechanism: Unlike vanilla gradient descent which updates all parameters, RPT updates only a subset of blocks per iteration. The total computation complexity is measured as the product of the number of iterations needed and the expected cost per iteration. By carefully choosing which blocks to update, RPT can achieve the same accuracy with lower total cost.
- Core assumption: The expected cost per iteration can be reduced without significantly increasing the number of iterations needed.
- Evidence anchors:
  - [abstract]: "identify regimes where it can outperform vanilla gradient descent in terms of total computation complexity."
  - [section]: "E [cost(T)] ∝ c(P) = LP · Σ(pi · cσi) regardless of the regime in question."
  - [corpus]: Weak - corpus papers discuss coordinate descent and block methods but don't directly analyze the total computation complexity tradeoff.
- Break condition: If the probability distribution causes the method to frequently update expensive blocks, or if the reduction in per-iteration cost is offset by a large increase in iteration count, the total complexity advantage disappears.

## Architecture Onboarding

- Component map:
  - PT-sketch operator: Generates random block selection matrices based on probability distribution
  - Probability matrix P: Diagonal matrix defining the probability distribution over blocks
  - Smoothness matrix L: Block-diagonal matrix containing smoothness constants for each block
  - Cost vector c: Vector containing computation costs for updating each block
  - Stepsize scheduler: Manages learning rate throughout training
  - Block partitioner: Divides parameters into blocks (typically by network layers)

- Critical path:
  1. Initialize parameters and partition into blocks
  2. Compute smoothness constants and costs for each block
  3. Set up PT-sketch operator with optimal probability distribution
  4. For each iteration: draw PT-sketch, compute gradient estimate, update parameters
  5. Monitor convergence and adjust stepsize if needed

- Design tradeoffs:
  - Block size vs. granularity: Smaller blocks allow more fine-grained updates but increase overhead
  - Probability distribution: More aggressive probabilities speed convergence but may increase variance
  - Stepsize tuning: Larger stepsizes speed convergence but risk instability
  - Block ordering: Different permutations of σ affect which blocks are prioritized

- Failure signatures:
  - Slow convergence: Check if probability distribution is too conservative or if block smoothness constants are too similar
  - High variance: Verify that the PT-sketch is properly normalized and that probability matrix is correctly constructed
  - Memory issues: Ensure block partitioning doesn't create too many small blocks
  - Incorrect gradient estimates: Validate that the PT-sketch provides unbiased estimates

- First 3 experiments:
  1. Simple quadratic test: Implement RPT on a synthetic quadratic function with known smoothness constants to verify convergence rates match theory
  2. Ridge regression benchmark: Test on a standard regression dataset to compare against vanilla GD and cyclic coordinate descent
  3. Neural network training: Apply to a small CNN on MNIST to evaluate practical performance and identify any implementation issues
