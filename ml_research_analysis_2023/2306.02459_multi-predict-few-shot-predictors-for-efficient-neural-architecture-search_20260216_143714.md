# Multi-Predict: Few Shot Predictors For Efficient Neural Architecture Search

## Quick Facts
- arXiv ID: 2306.02459
- Source URL: https://arxiv.org/abs/2306.02459
- Reference count: 40
- Key outcome: Hardware-independent neural network encodings enable knowledge transfer between NAS tasks, reducing required samples by over an order of magnitude

## Executive Summary
Multi-Predict addresses the high sample and measurement costs in hardware-aware neural architecture search by developing transfer-learning-based accuracy and latency predictors that generalize across tasks, search spaces, and hardware devices. The key innovation is using hardware-independent neural network encodings derived from zero-cost proxies or hardware latency measurements instead of traditional topology-based encodings. These encodings enable knowledge transfer between different NAS spaces and tasks, dramatically reducing the number of required samples and measurements compared to state-of-the-art methods.

## Method Summary
The method employs hardware-independent neural network encodings derived from zero-cost proxies (ZCP) or hardware latency measurements (HWL) rather than traditional topology-based encodings. For accuracy prediction, it uses ZCP encodings that capture neural network characteristics independent of specific hardware. For latency prediction, it employs hardware latency measurements with learnable embedding tables. The approach enables cross-search space and cross-task knowledge transfer, allowing predictors trained on one NAS space to be effectively applied to others with minimal additional samples. The method demonstrates superior sample efficiency, requiring only 4 samples for cross-search space latency prediction versus thousands for traditional approaches.

## Key Results
- Cross-search space latency prediction from NASBench-201 to FBNet requires only 4 samples versus thousands for traditional approaches
- Over order of magnitude reduction in required samples and measurements compared to state-of-the-art methods like HELP and BRP-NAS
- Effective multi-task accuracy prediction across 28 NAS search spaces with significantly improved sample efficiency

## Why This Works (Mechanism)
The method works by replacing hardware-dependent topological encodings with hardware-independent neural network characteristics. Zero-cost proxies capture architectural properties that remain consistent across different hardware platforms, enabling knowledge transfer. The learnable embedding tables for latency prediction learn hardware-specific relationships while maintaining the transferable core architecture information. This separation of hardware-independent and hardware-dependent information allows predictors to generalize across search spaces and tasks.

## Foundational Learning
**Zero-Cost Proxies (ZCP)**: Approximate network properties using minimal computation, enabling efficient encoding of neural network characteristics without full training
*Why needed*: Traditional full training is computationally prohibitive for NAS; quick checks enable practical predictor training
*Quick check*: Verify ZCP correlation with actual performance metrics on benchmark architectures

**Hardware Latency Measurements (HWL)**: Direct measurement of inference time on target hardware devices
*Why needed*: Provides ground truth for latency prediction and hardware-specific performance characteristics
*Quick check*: Ensure measurement consistency across multiple runs and devices

**Learnable Embedding Tables**: Neural network components that learn to map architecture encodings to target metrics
*Why needed*: Enables adaptation of predictors to new search spaces and hardware with minimal samples
*Quick check*: Verify embedding table convergence and performance on held-out validation data

## Architecture Onboarding
**Component Map**: Architecture Encoding -> Embedding Table -> Target Metric Prediction (Accuracy/Latency)
**Critical Path**: Zero-cost proxy computation → Hardware-independent encoding → Embedding table mapping → Final prediction
**Design Tradeoffs**: Hardware-independent encodings vs. accuracy, sample efficiency vs. predictor complexity, cross-hardware generalization vs. device-specific optimization
**Failure Signatures**: Poor predictor performance indicates encoding mismatch between source and target search spaces, insufficient training data diversity, or hardware-specific characteristics not captured by encodings
**First Experiments**: 1) Validate ZCP correlation with actual performance on benchmark architectures, 2) Test cross-search space transfer with minimal samples, 3) Evaluate embedding table adaptation on held-out architectures

None

## Limitations
- Reliance on zero-cost proxy encodings may not generalize well to all architecture types or search spaces
- Effectiveness tied to availability of diverse training data across multiple NAS tasks
- Cross-hardware transferability claims primarily validated on CPU-based latency prediction, with less validation for GPU and specialized accelerators

## Confidence
- High Confidence: Effectiveness of hardware-independent encodings for reducing sample complexity within single search spaces
- Medium Confidence: Cross-search space transferability claims demonstrated on specific pairs but generalizability needs more validation
- Medium Confidence: Multi-task accuracy prediction across 28 search spaces shows strong results but robustness to out-of-distribution architectures remains untested

## Next Checks
1. Evaluate cross-hardware transferability by testing GPU latency predictors trained on CPU data and vice versa, measuring performance degradation
2. Test method's robustness on out-of-distribution architectures not represented in training set across the 28 search spaces
3. Conduct ablation studies on embedding table architecture to quantify contribution of different encoding components to overall performance
