# Learning Search-Space Specific Heuristics Using Neural Networks

## Quick Facts
- arXiv ID: 2306.04019
- Source URL: https://arxiv.org/abs/2306.04019
- Reference count: 8
- Primary result: SING learns neural network heuristics from single instances, achieving competitive performance with Fast Forward and landmark count heuristics on shared search-space domains.

## Executive Summary
This paper presents SING, a minimalist approach to learning heuristic evaluation functions for classical planning using neural networks. Unlike previous methods requiring multiple training instances, SING learns from scratch using only a single problem instance by generating training data through backward search. The system improves upon earlier work (LHFCP) by using boolean state representations, depth-first search for data collection, and a relative error loss function. Experimental results show SING achieves competitive performance with established heuristics on shared search-space domains and consistently outperforms blind search on broader IPC benchmarks.

## Method Summary
SING learns heuristics by generating training data through backward search from goal states, either using derived inverse operators or regression. The system uses boolean state representations where each proposition maps to a bit, enabling the neural network to learn relationships between atomic facts directly. A feedforward neural network with ReLU activation is trained using a relative error loss function to predict distances to goal states. The trained model is then used as a heuristic in greedy best-first search (GBFS) to solve the original planning problem.

## Key Results
- SING achieves competitive performance with Fast Forward and landmark count heuristics on shared search-space domains (24-puzzle, blocksworld, logistics, gripper)
- On broader IPC benchmarks, SING consistently outperforms blind search and matches or exceeds standard heuristics on several domains
- Even when including learning time in the total time budget, SING maintains competitive performance

## Why This Works (Mechanism)

### Mechanism 1
Backward search with regression or derived inverse operators generates training data that approximates true distances to goal states. Starting from a goal state, the system explores the state space in reverse, recording states and their estimated distance from the goal based on the depth of DFS or path length in random walk. This backward exploration builds a training set that captures structural patterns in the search space. Core assumption: The number of steps from a goal state in backward search is a reasonable proxy for true distance in the forward search space.

### Mechanism 2
Boolean state representation enables more accurate neural network predictions than SAS+ multivalued representation. Boolean encoding maps each proposition to a bit, allowing the neural network to learn relationships between atomic facts directly. This reduces abstraction and can improve generalization across structurally similar states. Core assumption: Each bit in the input vector corresponds to an independent, learnable feature about the state.

### Mechanism 3
Relative error loss function improves learning efficiency and prediction accuracy compared to MSE. By penalizing predictions proportionally to the true distance, the loss function focuses learning on states where error matters most, especially in early search stages where small distance errors are critical. Core assumption: The relative magnitude of error is more informative than absolute error in planning contexts.

## Architecture Onboarding

- Component map: PDDL parser -> Fast Downward translator -> SAS+ or STRIPS vector -> Training data generator (backward search with DFS/reg/inv ops) -> PyTorch model trainer (feedforward NN, relative error loss) -> ONNX Runtime evaluator (fast inference during GBFS) -> GBFS loop (uses trained hnn as heuristic)

- Critical path: 1. Parse PDDL and generate SAS+ state space. 2. Run backward search to collect (state, distance) pairs. 3. Train neural network on collected data. 4. Use trained model in GBFS to solve the original instance.

- Design tradeoffs: Boolean vs SAS+ input: accuracy vs speed/memory. DFS vs random walk: sample diversity vs speed. Explicit vs regression search: branching factor vs unreachable states. Relative error vs MSE: sensitivity to scale vs numerical stability.

- Failure signatures: Poor coverage in domains with complex action structures (e.g., visitall). High training time if nsamples or nsearches is too large. Low heuristic accuracy if backward search generates many unreachable states. Overfitting if training data is too small or non-representative.

- First 3 experiments: 1. Run SING on a simple domain (e.g., blocksworld) with small state space to validate backward search and training pipeline. 2. Compare boolean vs SAS+ input representations on a domain with known structure to measure accuracy/speed tradeoff. 3. Swap relative error loss for MSE on a small benchmark to observe impact on heuristic accuracy.

## Open Questions the Paper Calls Out

### Open Question 1
How do unreachable states in the training data affect the quality of the learned heuristic and the performance of the (forward) search using the learned heuristic? The paper acknowledges that explicit backward search can generate states which are not reachable from the start state, but does not investigate the specific impact of these states on the learned heuristic's quality or search performance.

### Open Question 2
What is the optimal configuration (hyperparameters) for SING in different domains? The authors mention manual tuning and ongoing work on automated hyperparameter optimization, but do not provide a systematic approach to finding optimal configurations across domains.

### Open Question 3
How does SING's performance compare to other learning-based approaches for heuristic learning in classical planning? While the paper mentions related work, it does not directly compare SING's performance to these approaches on common benchmarks.

## Limitations

- The system's reliance on backward search may fail in domains with complex action structures or limited reversibility
- Performance evaluation is limited to comparison with a single baseline system (LHFCP)
- The 30-minute total time limit includes training time, potentially disadvantaging systems with longer training phases

## Confidence

- Mechanism 1 (backward search data generation): High
- Mechanism 2 (boolean state representation): High  
- Mechanism 3 (relative error loss): Medium
- Overall: Medium

## Next Checks
