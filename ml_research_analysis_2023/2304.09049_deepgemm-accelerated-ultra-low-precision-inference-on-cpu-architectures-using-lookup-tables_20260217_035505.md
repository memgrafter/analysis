# DeepGEMM: Accelerated Ultra Low-Precision Inference on CPU Architectures using Lookup Tables

## Quick Facts
- arXiv ID: 2304.09049
- Source URL: https://arxiv.org/abs/2304.09049
- Reference count: 25
- Primary result: Lookup table approach achieves geomean speedups of 1.57x-1.74x over 8-bit baselines on CPU architectures

## Executive Summary
DeepGEMM introduces a novel lookup table approach for accelerating ultra low-precision inference on CPU architectures with SIMD instructions. The method replaces expensive multiply-accumulate operations in dot products with faster lookups into precomputed tables containing products of weights and activations. This approach targets the deployment of ultra low-bit quantized models on CPUs, offering significant speedups over traditional 8-bit implementations. The technique demonstrates flexibility in supporting various quantization schemes including uniform and non-uniform quantization with signed or unsigned data.

## Method Summary
DeepGEMM leverages SIMD instructions to perform table lookups instead of traditional multiply-accumulate operations in convolutional and fully-connected layers. The method precomputes all possible products of weights and activations and stores them in lookup tables. During inference, these tables are accessed using SIMD instructions, which are faster than performing multiplications. The approach is particularly effective for ultra low-precision quantization schemes (binary, ternary weights with 2-bit activations) where the table sizes remain manageable. The method supports both uniform and non-uniform quantization schemes and can handle signed or unsigned data representations.

## Key Results
- Geomean speedups of 1.74x, 1.64x, 1.67x, and 1.57x on MobileNetV1, ResNet18, ResNet34, and ResNet50 layers respectively
- End-to-end speedups of up to 1.68x demonstrated on ResNet18, ResNet34, and ResNet50 models
- Outperforms optimized 8-bit baselines across all tested models
- Supports various quantization schemes with flexibility for signed/unsigned data

## Why This Works (Mechanism)
The lookup table approach works by exploiting the fact that in ultra low-precision quantization (binary/ternary weights with 2-bit activations), the number of unique multiplication results is limited and predictable. By precomputing all possible products and storing them in lookup tables, the expensive multiply-accumulate operations can be replaced with much faster memory lookups. SIMD instructions can then be used to perform multiple lookups in parallel, further accelerating the computation. This approach is particularly effective when the quantization reduces the effective bit-width to very low values where the table size remains manageable.

## Foundational Learning

**SIMD (Single Instruction, Multiple Data)**: Parallel processing capability that performs the same operation on multiple data points simultaneously. Why needed: Essential for accelerating multiple lookup operations in parallel. Quick check: Verify if target CPU supports SSE/AVX instructions.

**Quantization**: Process of reducing numerical precision of model weights and activations. Why needed: Enables smaller memory footprint and faster computation at the cost of some accuracy. Quick check: Confirm quantization scheme matches model requirements.

**Lookup Tables**: Precomputed data structures that map input values to output values. Why needed: Replace expensive computations with fast memory accesses. Quick check: Ensure table size is manageable for target hardware.

**Dot Product Optimization**: Techniques to accelerate the fundamental operation in neural network inference. Why needed: Dot products are the primary computational bottleneck in inference. Quick check: Verify that lookup-based approach actually reduces computation time.

## Architecture Onboarding

**Component Map**: Input activations -> Lookup tables -> SIMD instructions -> Output dot products

**Critical Path**: Input quantization → Table lookup via SIMD → Result accumulation → Output activation

**Design Tradeoffs**: Memory usage vs. speed - larger tables provide faster lookups but consume more memory. The method favors speed over memory efficiency, which may limit deployment on memory-constrained devices.

**Failure Signatures**: Memory allocation failures for large models, incorrect quantization leading to table mismatches, SIMD instruction incompatibilities on certain CPU architectures.

## Limitations
- Significant memory footprint increase (geomean 5.4x over FP32 baselines) may limit deployment on memory-constrained edge devices
- Restricted applicability primarily to convolutional and fully-connected layers, with unverified performance on other layer types
- Evaluation focuses mainly on binary/ternary weight quantization with 2-bit activations, limiting generalizability to other quantization schemes

## Confidence
- **High Confidence**: Speedups over 8-bit baselines (1.57x-1.74x geomean) and the technical approach of using SIMD-optimized lookup tables are well-supported
- **Medium Confidence**: End-to-end speedups (up to 1.68x) and flexibility across quantization schemes are reasonably supported but need broader evaluation
- **Low Confidence**: Effectiveness on memory-constrained devices and performance on non-convolutional layers are not adequately addressed
