# iSAGE: An Incremental Version of SAGE for Online Explanation on Data Streams

## Quick Facts
- **arXiv ID**: 2303.01181
- **Source URL**: https://arxiv.org/abs/2303.01181
- **Reference count**: 40
- **Key outcome**: iSAGE outperforms sliding window approaches in approximating ground-truth feature importance under concept drift while requiring less computation

## Executive Summary
iSAGE is an incremental version of the SAGE feature importance method designed for online explanation on data streams with concept drift. The method maintains time-weighted average feature importance estimates using exponential smoothing, allowing it to react to changing data distributions while providing unbiased estimation with confidence bounds. Two feature removal strategies are proposed: marginal distribution sampling using geometric reservoir sampling and conditional distribution sampling using incremental decision trees (HATs).

## Method Summary
iSAGE incrementally updates feature importance estimates by maintaining a time-weighted average of marginal contributions to loss when features are removed. For each incoming observation, it computes the change in loss when marginalizing each feature using either marginal or conditional sampling strategies, then updates the importance estimate using exponential smoothing. The marginal strategy uses geometric reservoir sampling to approximate current feature distributions, while the conditional strategy uses HATs to maintain conditional subgroups for sampling.

## Key Results
- iSAGE provides unbiased feature importance estimates under concept drift with theoretical confidence bounds
- iSAGE outperforms sliding window approaches (SW-SAGE) in approximation quality after concept drift events
- iSAGE requires less computation than window-based approaches while maintaining or improving approximation accuracy

## Why This Works (Mechanism)

### Mechanism 1
- Claim: iSAGE provides unbiased feature importance estimates in dynamic environments by using exponential smoothing with time-weighted averaging.
- Mechanism: The iSAGE estimator updates feature importance incrementally using a weighted average: $\hat{\phi}_t(i) = (1 - \alpha) \cdot \hat{\phi}_{t-1}(i) + \alpha \cdot \Delta_t(i)$, where $\Delta_t(i)$ measures the change in loss when feature $i$ is marginalized.
- Core assumption: The model $f_t$ and data-generating process remain stable over sufficiently long periods, or the exponential smoothing parameter $\alpha$ appropriately balances recency and stability.
- Evidence anchors: [abstract] states theoretical analysis shows iSAGE is unbiased with confidence bounds; [section 3.1] confirms efficiency property with respect to time-sensitive loss estimate.

### Mechanism 2
- Claim: Two feature removal strategies (marginal and conditional) allow iSAGE to handle both independent and dependent feature scenarios effectively.
- Mechanism: Marginal distribution sampling uses geometric reservoir sampling to approximate current feature distributions, while conditional distribution sampling uses incremental decision trees (HATs) to maintain conditional subgroups.
- Core assumption: Geometric sampling adequately approximates the marginal distribution, and HATs can maintain accurate conditional distributions in the incremental setting.
- Evidence anchors: [section 3.2] describes geometric sampling maintaining a reservoir of length L and using decision trees for conditional subgroups.

### Mechanism 3
- Claim: The incremental computation reduces computational overhead compared to sliding window approaches while maintaining approximation quality.
- Mechanism: Instead of recomputing SAGE from scratch over a sliding window, iSAGE updates incrementally using the current model and observation, requiring only O(d) operations per time step versus O(w·d) for window-based approaches.
- Core assumption: The incremental update formula accurately approximates the full recomputation that would occur in a sliding window approach.
- Evidence anchors: [section 4.2] shows iSAGE recovers more quickly than SW-SAGE after concept drift; [table 1] demonstrates iSAGE outperforming SW-SAGE with various computational factors.

## Architecture Onboarding

- **Component map**: Data stream processor -> Model updater -> Feature removal module (marginal/conditional) -> Importance estimator -> Variance tracker -> Reservoir manager

- **Critical path**: 
  1. Receive new observation (xt, yt)
  2. Update model with (xt, yt) to get ft+1
  3. Generate random permutation ϕt
  4. For each feature i, compute marginal contribution Δ(i) using chosen feature removal strategy
  5. Update importance estimate φt(i) using exponential smoothing
  6. Update variance estimate for confidence bounds
  7. Output current importance estimates

- **Design tradeoffs**:
  - Smoothing parameter α: Higher values provide faster adaptation to drift but increase variance; lower values provide stability but may lag behind true importance changes
  - Reservoir size L: Larger reservoirs provide better approximation of marginal distributions but increase memory usage and computation time
  - Number of inner samples m: More samples reduce variance in importance estimates but increase computation time per update

- **Failure signatures**:
  - Importance estimates oscillate wildly: Likely α is too high or m is too small
  - Estimates lag behind true importance changes: Likely α is too low or reservoir size is insufficient
  - Confidence bounds are extremely wide: Likely variance estimate is not being updated correctly or m is too small
  - Model performance degrades but importance estimates don't reflect this: Likely feature removal strategy is inappropriate for current feature dependencies

- **First 3 experiments**:
  1. Static data validation: Run iSAGE on pre-trained models with static data to verify it approximates batch SAGE values
  2. Concept drift recovery: Create synthetic streams with known drift points and verify iSAGE adapts faster than sliding window approaches
  3. Feature dependency sensitivity: Test marginal vs conditional removal strategies on datasets with known feature dependencies to observe differences in importance estimates

## Open Questions the Paper Calls Out

- **Open Question 1**: How does the choice between marginal and conditional feature removal strategies affect the interpretability of feature importance scores in iSAGE when applied to real-world datasets with complex feature dependencies?
  - Basis: The paper discusses the difference between strategies and their impact on FI values, particularly with dependent variables, but lacks extensive exploration on real-world datasets.
  - Resolution: Empirical studies comparing both strategies on real-world datasets with known or suspected feature dependencies.

- **Open Question 2**: What are the computational trade-offs between iSAGE and SW-SAGE in terms of approximation quality and resource utilization under different types and magnitudes of concept drift?
  - Basis: The paper demonstrates iSAGE's superiority in approximation quality but doesn't analyze computational efficiency across various drift scenarios.
  - Resolution: Detailed benchmarking measuring computational time, memory usage, and approximation error under different drift scenarios and window sizes.

- **Open Question 3**: How does the choice of the smoothing parameter α in iSAGE affect the balance between responsiveness to concept drift and stability of feature importance estimates?
  - Basis: The paper mentions α affects focus on recent samples but doesn't systematically analyze its impact on the trade-off.
  - Resolution: Empirical studies evaluating iSAGE performance with different α values across various datasets and drift scenarios.

## Limitations

- The theoretical claims about unbiasedness and confidence bounds would benefit from complete proofs, which are not provided in the main text
- The effectiveness of iSAGE critically depends on the quality of the incremental feature removal strategies, which are assumed to provide accurate approximations but not rigorously validated
- The paper doesn't analyze the computational complexity of the feature removal strategies themselves, which could become bottlenecks with high-dimensional data or complex feature dependencies

## Confidence

- **High confidence**: The core incremental update mechanism using exponential smoothing is sound and well-established in online learning literature
- **Medium confidence**: The experimental design comparing against baselines is appropriate, but could be strengthened with additional datasets and drift types
- **Low confidence**: The claim that geometric reservoir sampling adequately approximates marginal distributions for all feature types is not empirically validated
