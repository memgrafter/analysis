# A Prototype-Oriented Clustering for Domain Shift with Source Privacy

## Quick Facts
- arXiv ID: 2302.03807
- Source URL: https://arxiv.org/abs/2302.03807
- Reference count: 28
- Outperforms ACIDS by up to 19.2% on average across multiple datasets

## Executive Summary
This paper addresses unsupervised clustering under domain shift (UCDS) where labeled data is unavailable in both source and target domains, with privacy constraints preventing access to source data and models. The authors propose Prototype-oriented Clustering with Distillation (PCD), a three-stage framework that learns source clustering models using optimal transport, transfers knowledge to target models via distillation, and refines target models on target data alone. PCD achieves state-of-the-art performance across multiple datasets and settings while preserving source privacy.

## Method Summary
PCD operates in three stages: (1) learns a source clustering model using optimal transport to align data and prototype distributions while maximizing mutual information, (2) transfers knowledge to the target model via distillation using cluster labels from the source model with label smoothing and temporal ensemble, and (3) refines the target model on target data alone using transport and mutual information objectives. The method works with pre-trained encoders (ResNet-18/50, ViT-B/16) and requires only the number of clusters K as input.

## Key Results
- Achieves up to 19.2% improvement over ACIDS on average
- Performs consistently well across Office-31, Office-Home, and PACS datasets
- Maintains privacy by never accessing source data or model parameters directly
- Compatible with different model architectures and pre-training schemes

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Optimal transport aligns prototype and data distributions while preserving domain-specific cluster proportions
- Mechanism: Uses entropic regularized optimal transport to compute transport plans between domain-specific data distributions and prototype distributions, then updates encoder and prototypes to minimize transport cost
- Core assumption: The underlying cluster structure is preserved across domains despite distribution shift
- Evidence anchors:
  - [abstract]: "PCD first constructs a source clustering model by aligning the distributions of prototypes and data"
  - [section]: "To align the distributions of prototypes and data, we want to quantify their difference. A principled way to compare two discrete distributions is to consider the optimal transport problem"
  - [corpus]: Weak evidence - no direct mention of optimal transport for clustering in neighbor papers
- Break condition: If cluster proportions vary significantly across domains, the transport alignment becomes ineffective

### Mechanism 2
- Claim: Mutual information maximization ensures tight clustering around prototypes while preventing degenerate solutions
- Mechanism: Maximizes marginal entropy of cluster labels while minimizing conditional entropy given data, encouraging confident predictions without collapsing to single cluster
- Core assumption: Tight clustering around prototypes leads to better feature representations
- Evidence anchors:
  - [abstract]: "It then distills the knowledge to the target model through cluster labels provided by the source model while simultaneously clustering the target data"
  - [section]: "This objective ensures that the feature representations are tightly clustered around each prototype"
  - [corpus]: No direct mention of mutual information for clustering in neighbor papers
- Break condition: If data contains significant noise or outliers, tight clustering may overfit to noisy patterns

### Mechanism 3
- Claim: Knowledge distillation transfers cluster knowledge from source to target while preserving privacy
- Mechanism: Uses hard labels from source model with label smoothing and temporal ensemble to refine target model predictions, then performs self-training on target data alone
- Core assumption: Source model provides useful cluster information despite domain shift
- Evidence anchors:
  - [abstract]: "PCD first constructs a source clustering model... It then distills the knowledge to the target model through cluster labels provided by the source model"
  - [section]: "Given unlabeled target samples, {xt i}nt i=1, we can obtain cluster assignments, Gs(xt i), through the source model"
  - [corpus]: Weak evidence - neighbor papers mention source-free adaptation but not knowledge distillation for clustering
- Break condition: If source model predictions are highly inaccurate due to severe domain shift, distillation becomes counterproductive

## Foundational Learning

- Concept: Optimal transport for distribution alignment
  - Why needed here: Provides principled way to align prototype and data distributions while respecting domain-specific cluster proportions
  - Quick check question: What is the computational complexity of solving optimal transport for each mini-batch?

- Concept: Mutual information maximization for clustering
  - Why needed here: Ensures feature representations cluster tightly around prototypes while preventing degenerate solutions
  - Quick check question: How does maximizing marginal entropy prevent the model from assigning all samples to one cluster?

- Concept: Knowledge distillation with hard labels
  - Why needed here: Transfers clustering knowledge from source to target while preserving privacy constraints
  - Quick check question: Why might label smoothing be important when using hard labels from the source model?

## Architecture Onboarding

- Component map:
  - Feature encoder Fθ -> Linear clustering head Cµ -> Prototype matrix -> Optimal transport solver -> Label smoothing module -> Temporal ensemble tracker

- Critical path: Source model training → Target model clustering → Target model refinement
- Design tradeoffs: 
  - Privacy vs performance: Complete privacy requires using only hard labels
  - Complexity vs accuracy: Optimal transport adds computational overhead
  - Flexibility vs stability: Different architectures between source and target may affect transfer quality

- Failure signatures:
  - High transport cost indicates poor alignment between prototypes and data
  - Uniform cluster predictions suggest mutual information objective is not working
  - Target performance worse than source-only baseline indicates negative transfer

- First 3 experiments:
  1. Verify optimal transport alignment by visualizing prototype-data relationships in feature space
  2. Test mutual information objective by comparing cluster tightness with and without it
  3. Validate knowledge distillation by measuring performance degradation when using raw vs refined labels from source model

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of PCD change when the number of clusters K is set to values different from the number of classes in the dataset?
- Basis in paper: [explicit] The paper states that K is set equal to the number of classes in each dataset for evaluation purposes.
- Why unresolved: The paper does not explore how varying K affects clustering performance or the method's ability to discover meaningful clusters.
- What evidence would resolve it: Experiments varying K and measuring clustering accuracy and cluster coherence would show how sensitive PCD is to the choice of K.

### Open Question 2
- Question: How robust is PCD to varying degrees of domain shift between source and target domains?
- Basis in paper: [inferred] The paper evaluates PCD on standard domain shift scenarios but does not systematically vary the degree of shift or analyze performance degradation.
- Why unresolved: The experiments focus on fixed domain pairs without quantifying the impact of domain dissimilarity on clustering accuracy.
- What evidence would resolve it: Controlled experiments with artificially induced domain shifts (e.g., varying feature distribution discrepancies) would reveal PCD's sensitivity to domain shift magnitude.

### Open Question 3
- Question: How does PCD perform when the target domain contains classes not present in the source domains?
- Basis in paper: [inferred] The paper assumes the target and source domains share similar semantic content and underlying clusters, but this assumption is not tested.
- Why unresolved: The experiments use datasets where all classes are shared between domains, leaving open the question of handling novel target classes.
- What evidence would resolve it: Experiments on datasets with disjoint class sets or with artificially removed classes in the source would show PCD's ability to handle novel target classes.

## Limitations

- Optimal transport alignment may become ineffective when cluster proportions vary significantly across domains
- Mutual information maximization can overfit to noisy patterns when data contains significant outliers
- Knowledge distillation can cause negative transfer when source model predictions are highly inaccurate due to severe domain shift

## Confidence

- **High**: Privacy preservation mechanism, compatibility with different architectures, overall empirical performance gains
- **Medium**: Three-stage framework design, CutMix regularization benefits, label smoothing effectiveness
- **Low**: Optimal transport alignment theoretical guarantees, mutual information maximization under noisy conditions, negative transfer risks

## Next Checks
