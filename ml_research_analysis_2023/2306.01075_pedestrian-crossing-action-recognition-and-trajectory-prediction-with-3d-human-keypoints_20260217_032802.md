# Pedestrian Crossing Action Recognition and Trajectory Prediction with 3D Human Keypoints

## Quick Facts
- arXiv ID: 2306.01075
- Source URL: https://arxiv.org/abs/2306.01075
- Reference count: 40
- Primary result: Achieves 0.980 crossing action recognition accuracy and 0.373 minimum ADE for trajectory prediction on in-house dataset

## Executive Summary
This paper presents a multi-task learning framework for pedestrian crossing action recognition and trajectory prediction in autonomous driving using 3D human keypoints. The authors propose leveraging 3D keypoints to capture pose and activity information while introducing auxiliary tasks to improve keypoints representation learning. The framework achieves state-of-the-art performance on both a large-scale in-house dataset and a public benchmark dataset, demonstrating the effectiveness of using 3D keypoints for this dual task.

## Method Summary
The method employs a multi-task learning framework that jointly trains crossing action recognition and trajectory prediction models using 3D human keypoints. The architecture consists of multiple encoders (context, keypoints, and target track) that share representations through global interaction modules. Auxiliary tasks including keypoints jigsaw puzzle, keypoints prediction, and contrastive learning are introduced to provide additional supervision for learning better keypoints representations. The framework processes road context, agent positions, pedestrian history trajectories, and 3D keypoints sequences to predict crossing actions and future trajectories.

## Key Results
- Achieves 0.980 crossing action recognition accuracy on in-house dataset
- Reaches 0.373 minimum ADE for trajectory prediction on in-house dataset
- Demonstrates 2.0% improvement over SOTA on JAAD benchmark for crossing action recognition
- Efficient inference time of 4.7ms on NVIDIA V100 GPU for batch of 32 pedestrians

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Using 3D human keypoints provides richer, view-invariant appearance information than 2D images or point clouds.
- Mechanism: 3D keypoints encode compact skeleton structure that remains consistent across view angles and can be directly transformed into the same coordinate system as trajectories.
- Core assumption: The pose estimation model can accurately infer 3D keypoints from sensor data.
- Evidence anchors:
  - [abstract] "3D human keypoints contain the appearance information that can be transformed to be invariant of view angle"
  - [section] "3D human keypoints can provide a compact and clean representation for extracting spatio-temporal features of pose and activity"
- Break condition: If pose estimation fails due to occlusion or noise, the keypoints representation becomes unreliable.

### Mechanism 2
- Claim: Joint training of crossing action recognition and trajectory prediction improves both tasks through complementary feature extraction.
- Mechanism: The two tasks share encoder representations but focus on different aspects - action recognition on road context and keypoints, trajectory prediction on motion patterns and interactions. This mutual enhancement occurs through the shared embedding space.
- Core assumption: The tasks are sufficiently correlated that shared representations benefit both.
- Evidence anchors:
  - [section] "training the model on both tasks jointly achieves better performance than learning from an individual task"
  - [section] "action recognition focuses more on learning the road context and keypoints features while trajectory prediction focuses more on learning history motions"
- Break condition: If the tasks become too dissimilar or conflicting, joint training could degrade performance.

### Mechanism 3
- Claim: Auxiliary tasks (keypoints jigsaw puzzle, prediction, and contrastive learning) improve keypoints representation learning by providing additional supervision.
- Mechanism: These self-supervised tasks force the encoder to capture temporal patterns, fine-grained pose dynamics, and high-level temporal similarity that benefit the main tasks.
- Core assumption: The auxiliary tasks are aligned with the primary task objectives and don't introduce conflicting signals.
- Evidence anchors:
  - [section] "two auxiliary tasks and contrastive learning to enable auxiliary supervisions to improve the learned keypoints representation"
  - [section] "the effectiveness of each model component is validated in a detailed ablation study"
- Break condition: If auxiliary task design is poor, they could distract from primary task learning or introduce noise.

## Architecture Onboarding

- Component map: Context encoder (roadgraph + context agents) → Keypoints encoder (3D human keypoints) → Target track encoder (history trajectory) → Global interaction (self-attention) → Decoder heads (AR, TP, auxiliary tasks)
- Critical path: Keypoints encoder → shared embedding → decoder heads, with context encoder providing complementary information
- Design tradeoffs: Using 3D keypoints adds computational overhead but provides richer information; joint training increases complexity but enables mutual enhancement; auxiliary tasks improve representation but require additional supervision
- Failure signatures: Poor performance on one task could indicate issues with keypoints quality, task correlation assumptions, or auxiliary task design
- First 3 experiments:
  1. Compare performance with and without 3D keypoints to verify the core benefit
  2. Test joint training vs separate training of the two main tasks

## Limitations

- Evaluation on only one public benchmark (JAAD) with limited sample size (1.3K) restricts generalizability
- Heavy reliance on accurate 3D pose estimation creates potential failure points with occlusion or sensor noise
- Computational efficiency claims lack clarity on what's included in the 4.7ms measurement
- Method's performance in complex multi-pedestrian interaction scenarios not thoroughly evaluated

## Confidence

- **High Confidence**: The core claim that 3D keypoints provide richer information than 2D representations is well-supported by the literature and ablation studies. The architectural design choices are standard and validated.
- **Medium Confidence**: The effectiveness of auxiliary tasks in improving representation learning is demonstrated but needs more detailed analysis of individual task contributions and generalization testing.
- **Low Confidence**: The computational efficiency claim (4.7ms runtime) lacks sufficient context about measurement scope and scalability across hardware configurations.

## Next Checks

1. **Dataset Generalization Test**: Evaluate the model on multiple public datasets (JAAD, PIE, PIE-L) with varying sizes and conditions to verify robustness across different pedestrian crossing scenarios and cultural contexts.

2. **End-to-end Runtime Analysis**: Measure total system latency including 3D pose estimation time, and test performance across different GPU/CPU configurations to validate the claimed computational efficiency under realistic deployment conditions.

3. **Failure Mode Analysis**: Conduct systematic experiments with artificially degraded pose estimation quality (varying noise levels, occlusion rates) to quantify the model's sensitivity to keypoints quality and identify failure thresholds.
