# Towards Zero-shot Relation Extraction in Web Mining: A Multimodal Approach with Relative XML Path

## Quick Facts
- arXiv ID: 2305.13805
- Source URL: https://arxiv.org/abs/2305.13805
- Reference count: 7
- Primary result: Up to 10.62 F1 score improvement on NBA+Univ⇒Movie task

## Executive Summary
This paper addresses zero-shot relation extraction from semi-structured web pages, where models must infer relations without prior knowledge of page structure. The authors propose ReXMiner, which leverages relative XML paths in the DOM tree to capture local node relationships more effectively than absolute paths alone. The method also incorporates node popularity across pages and uses contrastive learning to mitigate sparse annotations. Experiments on the SWDE dataset show ReXMiner outperforms state-of-the-art baselines, achieving significant performance gains across verticals.

## Method Summary
ReXMiner extends pre-trained language models with three key innovations: (1) relative XML path attention that captures local DOM relationships by encoding shortest paths between text nodes, (2) popularity embedding that counts text node occurrences across pages to identify structural elements, and (3) contrastive learning with controlled negative sampling to address sparsity in relation extraction. The model is pre-trained on MarkupLM and fine-tuned for relation extraction using a Biaffine classifier. Evaluation is performed in zero-shot settings where knowledge is transferred from existing verticals to unseen ones.

## Key Results
- Achieves up to 10.62 F1 score improvement in NBA+Univ⇒Movie task
- Average 5.88 F1 gain across verticals compared to baselines
- Outperforms state-of-the-art models like PickList, BiLSTM, and MarkupLM

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Relative XML paths provide more efficient transfer signals than absolute paths in zero-shot web mining.
- Mechanism: By encoding the shortest path between text nodes in the DOM tree (removing the common prefix), the model captures local node relationships that are more consistent across different page templates. This relative encoding allows the model to generalize better to unseen page structures.
- Core assumption: Related text nodes in semi-structured web pages tend to be close to each other in the DOM tree, creating long common prefixes in their absolute XML paths.
- Evidence anchors:
  - [abstract] "ReXMiner encodes the shortest relative paths in the Document Object Model (DOM) tree which is a more accurate and efficient signal for key-value pair extraction within a web page."
  - [section] "These pre-training approaches extend vanilla language models by embedding the absolute XML Paths but fail to take into account the relative local relationship expressed by the relative XML Paths. The related nodes tend to be close to each other in the DOM tree, which results in a long common prefix in their XML Paths, as shown in Figure 1."

### Mechanism 2
- Claim: Popularity embedding captures meaningful signals about key-value relationships across pages.
- Mechanism: By counting the occurrence of the same text node across different web pages from the same website, the model identifies text nodes that frequently appear as keys (like "Height:" or "Age:") regardless of their surrounding content. This frequency-based signal helps distinguish structural elements from content-specific text.
- Core assumption: Key-value pairs in semi-structured web pages have text nodes that appear frequently across pages with varying content around them.
- Evidence anchors:
  - [abstract] "It also incorporates the popularity of each text node by counting the occurrence of the same text node across different web pages."
  - [section] "Intuitively, a text node is more likely to be a key word if it appears frequently in a collection of web pages and its surrounding words are not fixed."

### Mechanism 3
- Claim: Contrastive learning addresses sparsity in relation extraction by controlling the positive-to-negative ratio.
- Mechanism: By randomly generating negative cases and restricting their ratio to positive ones during training, the model learns to better discriminate related node pairs from unrelated ones, improving its ability to identify true relations in unseen pages.
- Core assumption: The sparsity issue in relation extraction (few positive pairs compared to many possible pairs) can be mitigated by controlled negative sampling during training.
- Evidence anchors:
  - [abstract] "We use the contrastive learning to address the issue of sparsity in relation extraction."
  - [section] "To tackle this issue, we adopt the contrastive learning and conduct negative sampling to control the ratio between the positive cases and negative ones."

## Architecture Onboarding

- Component map:
  - Text node → Popularity embedding + Absolute XML path embedding → Relative XML path attention bias → Transformer layers → Biaffine classifier → Relation prediction

- Critical path: Text node → Popularity embedding + Absolute XML path embedding → Relative XML path attention bias → Transformer layers → Biaffine classifier → Relation prediction

- Design tradeoffs: Using relative XML paths instead of absolute paths trades some absolute position information for better generalization across templates. The popularity embedding adds computational overhead but provides valuable frequency signals.

- Failure signatures: Poor performance on unseen verticals might indicate that relative XML path patterns don't transfer well. High precision but low recall could suggest the popularity embedding is too restrictive.

- First 3 experiments:
  1. Ablation study: Remove relative XML path attention to verify its contribution to performance
  2. Frequency analysis: Examine how text node popularity correlates with extraction accuracy
  3. Negative sampling ratio: Test different positive-to-negative ratios in contrastive learning to find optimal balance

## Limitations
- Evaluation is based on the SWDE dataset, which may not fully represent real-world web page diversity
- Model's performance on highly dynamic or JavaScript-heavy websites remains unclear
- Scalability to very large websites with millions of pages and computational cost of popularity embedding are not addressed

## Confidence
- **High confidence**: The relative XML path mechanism improves transfer performance (supported by ablation study and quantitative results showing up to 10.62 F1 improvement)
- **Medium confidence**: Popularity embedding consistently improves relation extraction across all verticals (supported by results but with some variation in magnitude)
- **Medium confidence**: Contrastive learning effectively addresses sparsity issues (mechanism is sound but quantitative impact could be more precisely measured)

## Next Checks
1. **Cross-domain robustness test**: Evaluate ReXMiner on web pages from entirely different domains (e.g., news sites, product listings) not represented in SWDE to verify the generalizability of relative XML path patterns
2. **Scalability benchmark**: Measure training and inference time on datasets with varying sizes (100 to 1 million pages) to quantify the computational overhead of popularity embedding and determine practical limits
3. **Negative sampling sensitivity analysis**: Systematically vary the positive-to-negative ratio (µ) in contrastive learning across a wider range (0.5 to 10) to identify the optimal balance and confirm the 1:1 ratio is indeed optimal
