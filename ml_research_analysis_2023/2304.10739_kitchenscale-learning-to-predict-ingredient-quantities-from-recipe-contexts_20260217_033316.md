# KitchenScale: Learning to predict ingredient quantities from recipe contexts

## Quick Facts
- arXiv ID: 2304.10739
- Source URL: https://arxiv.org/abs/2304.10739
- Reference count: 19
- Key outcome: KitchenScale achieves 92.33% accuracy on measurement type classification, 73.35% on unit classification, and 1.44% MAPE on quantity prediction using a three-stage BERT model with DExp regression

## Executive Summary
KitchenScale is a three-stage fine-tuned BERT model that predicts ingredient quantities from recipe contexts by first classifying measurement type (weight/volume), then unit, then quantity. The system addresses the challenge of multimodal numerical distributions in recipe data using DExp regression, which decomposes quantity prediction into exponent and mantissa components. Evaluated on over 98,000 recipe instances, KitchenScale demonstrates strong performance across all three prediction stages while providing practical utility through a web demo.

## Method Summary
KitchenScale uses transfer learning from pre-trained BERT models to predict ingredient quantities through a progressive three-stage approach. The model takes recipe context (title, tags, other ingredients, servings) with a masked target ingredient and processes it through three dedicated BERT encoders: first predicting measurement type (weight/volume), then unit classification, and finally quantity prediction using DExp regression. DExp handles multimodal distributions by predicting exponent and mantissa components separately, enabling accurate predictions across the wide range of possible ingredient quantities from fractions to bulk amounts.

## Key Results
- 92.33% accuracy on measurement type classification
- 73.35% accuracy on unit classification
- 1.44% MAPE and 109.93 MAE on quantity prediction

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Three-stage fine-tuned BERT approach enables progressive refinement by first identifying measurement type, then unit, then quantity
- Mechanism: Each stage uses dedicated BERT encoder with specialized input masking to isolate relevant information, with measurement type constraining subsequent predictions
- Core assumption: Measurement type is a reliable precondition that constrains possible units and influences quantity scales
- Evidence anchors:
  - [abstract]: "It first classifies measurement type (weight/volume), then unit, then quantity."
  - [section]: "Our model architecture has three different prediction modules which are the Ingredient Measurement Type, Unit, and Quantity Predictor."
- Break condition: Wrong measurement type classification causes cascading errors in unit and quantity predictions

### Mechanism 2
- Claim: DExp regression effectively handles multimodal numerical distributions with high variance in recipe corpora
- Mechanism: DExp decomposes quantity prediction into exponent and mantissa components using multinomial distribution for exponents and truncated Gaussian for mantissas
- Core assumption: Ingredient quantities follow multimodal distribution where standard regression would fail
- Evidence anchors:
  - [abstract]: "The quantity regression uses DExp to handle multimodal numerical distributions."
  - [section]: "We utilized DExp component for implementing the Ingredient Quantity Predictor module which consists of sub-components exponent (e) and mantissa (m)."
- Break condition: If quantities were actually unimodal and low-variance, DExp's complexity would be unnecessary

### Mechanism 3
- Claim: Transfer learning from pre-trained BERT provides better recipe context understanding than word2vec approaches
- Mechanism: Fine-tuning BERT on recipe data leverages contextual embeddings that capture semantic relationships between ingredients, measurements, and cooking processes
- Core assumption: Recipe text contains sufficient context for BERT to learn meaningful representations
- Evidence anchors:
  - [abstract]: "We utilized transfer learning of cooking knowledge from recipe texts to PLMs."
  - [section]: "Our model architecture has three different prediction modules which are the Ingredient Measurement Type, Unit, and Quantity Predictor. Each prediction module has its own input query composition and consists of a recipe context encoder and a prediction layer for its corresponding numeracy task."
- Break condition: If recipe text is too sparse or lacks context, pre-trained BERT might not provide significant advantages

## Architecture Onboarding

- Component map: Recipe context (title, tags, other ingredients, servings) -> Three BERT encoders (measurement type, unit, quantity) -> DExp regression layer -> Final numeral converter

- Critical path: Input → BERT encoder → Prediction layer → Output conversion
  - The critical path involves all three prediction stages in sequence, with each stage's output feeding into the next

- Design tradeoffs:
  - Three separate BERT models vs. one shared model: Separate models allow task-specific fine-tuning but increase parameter count
  - DExp vs. standard regression: DExp handles multimodal distributions better but is more complex
  - Input composition with masking vs. full context: Masking helps focus learning but may lose some context

- Failure signatures:
  - Poor measurement type classification cascading to wrong units and quantities
  - DExp failing to converge on multimodal distributions
  - BERT encoders not learning meaningful recipe context representations
