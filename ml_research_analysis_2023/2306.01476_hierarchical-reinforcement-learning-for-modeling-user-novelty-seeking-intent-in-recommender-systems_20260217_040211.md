# Hierarchical Reinforcement Learning for Modeling User Novelty-Seeking Intent in Recommender Systems

## Quick Facts
- arXiv ID: 2306.01476
- Source URL: https://arxiv.org/abs/2306.01476
- Authors: 
- Reference count: 40
- Key outcome: Hierarchical RL with session-level DDPG and interaction-level DQN agents improves novelty-seeking modeling in recommender systems

## Executive Summary
This paper introduces a hierarchical reinforcement learning framework to model user novelty-seeking behavior in recommender systems. The approach uses a two-level architecture: a session-level DDPG agent captures abstract, personalized novelty-seeking propensity, while an interaction-level DQN agent handles dynamic, item-specific novelty-seeking at each user-item interaction. The method incorporates novelty and diversity metrics into the reward function to encourage exploration. Experimental results demonstrate significant improvements over state-of-the-art baselines across multiple evaluation metrics including hit rate, diversity, and novelty.

## Method Summary
The proposed method employs a hierarchical reinforcement learning architecture with two distinct agents operating at different temporal scales. The session-level agent uses DDPG to learn abstract novelty-seeking propensities personalized to each user session, while the interaction-level agent uses DQN to make item-specific novelty-seeking decisions at each interaction point. Both agents share a common reward function that balances novelty and diversity objectives. The hierarchical structure allows the system to capture both long-term novelty-seeking intent and short-term item-specific preferences, enabling more nuanced recommendations that balance exploration with relevance.

## Key Results
- HRL model significantly outperforms state-of-the-art baselines in average reward, hit rate, diversity, and novelty metrics
- Performance improvements validated across simulation environment and three real-world datasets (Yelp, MovieLens, Youku)
- Visualization confirms learned session policy successfully captures hierarchical novelty-seeking intent

## Why This Works (Mechanism)
The hierarchical structure enables modeling of novelty-seeking behavior at multiple temporal scales. The session-level DDPG agent learns abstract, personalized novelty propensities that persist throughout a session, capturing users' overall willingness to explore new items. The interaction-level DQN agent responds to immediate context by making item-specific novelty-seeking decisions at each recommendation point. This dual-scale approach allows the system to balance long-term exploration goals with short-term relevance needs, creating recommendations that are both diverse and personally relevant.

## Architecture Onboarding

**Component Map:**
Session-level DDPG Agent -> Interaction-level DQN Agent -> User-Item Interaction Environment

**Critical Path:**
1. Initialize session-level DDPG agent with user context
2. Session agent outputs novelty-seeking propensity for current session
3. Interaction-level DQN agent receives session propensity and current state
4. DQN selects next item recommendation
5. Environment returns reward based on novelty-diversity metrics
6. Both agents update policies through experience replay

**Design Tradeoffs:**
- Computational overhead of dual-agent system vs. improved modeling capability
- Complexity of hierarchical training vs. potential for better generalization
- Reward function design balancing novelty vs. relevance tradeoffs

**Failure Signatures:**
- Poor session-level policy leads to inconsistent novelty-seeking across interactions
- Interaction-level agent fails to adapt to session-level propensity changes
- Reward function overemphasizes novelty at expense of relevance metrics

**First 3 Experiments:**
1. Ablation study: Remove hierarchical structure, use single-agent RL with identical reward function
2. Cross-dataset validation: Test model trained on one domain (e.g., Yelp) on different domain (e.g., MovieLens)
3. Computational benchmarking: Measure inference latency and resource utilization vs. baseline methods
