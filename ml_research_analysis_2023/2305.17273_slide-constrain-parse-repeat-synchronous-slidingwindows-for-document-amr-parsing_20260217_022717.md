# Slide, Constrain, Parse, Repeat: Synchronous SlidingWindows for Document AMR Parsing

## Quick Facts
- arXiv ID: 2305.17273
- Source URL: https://arxiv.org/abs/2305.17273
- Reference count: 6
- Key outcome: 92% retention of cross-sentential links with 300-token window, matching state-of-the-art document-level AMR parsing performance

## Executive Summary
This paper addresses the challenge of document-level AMR parsing for long texts that exceed transformer input limits by proposing synchronous sliding windows over source and target. The approach extends Structured-BART with transition-based parsing to implement overlapping windows where actions from the overlap are copied and force-decoded in the next window. On the Multi-Sentence AMR 3.0 corpus, the method retains 92% of gold cross-sentential links with a 300-token window and 200-token overlap while maintaining sentence-level parsing quality.

## Method Summary
The method uses transition-based parsing with monotonic alignment between source tokens and parsing actions, enabling window boundary management. Overlapping windows copy actions from the overlap region to the next window and force-decode them, maintaining continuity. The transition system is modified to handle document-level AMR structures including coreference chains through SAME-AS relation labels and CLOSE_SENTENCE actions. Constrained decoding ensures consistency between consecutive windows by adjusting pointer values for new positions.

## Key Results
- Oracle retains 92% of gold cross-sentential links with 300-token window and 200-token overlap
- Document-level parser matches state-of-the-art pipeline approach in performance
- Window size as short as 200 tokens loses only 3 points in SMATCH and 12 in coreference subscore

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Synchronous sliding windows preserve cross-window dependencies
- Mechanism: Overlapping windows copy and force-decode actions from overlap regions
- Core assumption: Monotonic alignment enables window boundary management
- Evidence: 92% cross-sentential link retention reported; transition oracle maintains continuity across windows

### Mechanism 2
- Claim: Constrained decoding ensures consistency between consecutive windows
- Mechanism: Actions from overlapping tokens are copied and force-decoded with pointer adjustments
- Core assumption: Transition oracle action sequences can be segmented and reconstructed
- Evidence: Overlapping forced prefixes provide smooth transitions; 3-point SMATCH loss with 200-token windows

### Mechanism 3
- Claim: Modified transition system handles document-level AMR structures
- Mechanism: Introduced SAME-AS relation for coreference and CLOSE_SENTENCE action for sentence-level roots
- Core assumption: Coreference chains can be modeled as pairwise links
- Evidence: Handles documents up to 4277 tokens; pairwise coreference modeling simplifies parsing

## Architecture Onboarding

- Component map: Structured-BART transition-based parser → sliding window manager → oracle → constraint enforcer
- Critical path: Source text → window chunking → transition action generation → constrained decoding → graph construction
- Design tradeoffs: Window size vs. information loss (300 optimal) vs. memory constraints (1024 token limit)
- Failure signatures: Low Smatch scores indicate window boundary issues; inconsistent coreference subscores suggest constraint failures
- First 3 experiments:
  1. Test oracle with varying window sizes (200, 300, 400) on double-annotation dev set to measure cross-sentential link retention
  2. Validate constrained decoding by parsing documents with 300/200 window/overlap configuration and checking consistency across boundaries
  3. Compare document-level performance against pipeline approach using same training data to establish baseline effectiveness

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Maximum document length effectively parsed without significant cross-sentential information loss
- Basis: Paper tests only up to 300-token windows
- Why unresolved: Larger window sizes not evaluated
- Resolution evidence: Testing with 400-600 token windows and measuring degradation

### Open Question 2
- Question: Performance comparison to other long-range Transformer architectures
- Basis: Paper acknowledges existence of Longformer/BigBird but doesn't benchmark
- Why unresolved: No comparison to alternative architectures
- Resolution evidence: Implementing AMR parsing with Longformer/BigBird and comparing results

### Open Question 3
- Question: Applicability to other graph-based parsing tasks beyond AMR
- Basis: Method validated only on AMR parsing
- Why unresolved: Other structured prediction tasks untested
- Resolution evidence: Applying framework to semantic dependency parsing or discourse parsing

## Limitations

- Oracle effectiveness may not fully capture semantic completeness of retained cross-sentential links
- Window-based approach may systematically underrepresent long-range dependencies spanning multiple windows
- Simplified pairwise modeling of coreference chains may miss complex semantic relationships

## Confidence

**High Confidence (90-100%)**
- Synchronous sliding window architecture can be implemented and will parse documents within specified parameters
- Constrained decoding will maintain consistency across overlapping window segments
- Baseline sentence-level parsing performance will match or exceed existing approaches

**Medium Confidence (60-89%)**
- Oracle will retain approximately 92% of cross-sentential links with 300/200 configuration
- Parser will achieve competitive document-level performance against pipeline approaches
- Coreference chains can be adequately modeled using pairwise SAME-AS links

**Low Confidence (Below 60%)**
- Approach will generalize well to documents significantly longer than training corpus average
- Simplified coreference modeling will capture all necessary semantic relationships
- Window-based approach won't introduce systematic biases in parsing certain document structures

## Next Checks

1. **Oracle Fidelity Analysis**: Systematically vary window sizes (200, 250, 300, 350 tokens) on double-annotation development set, measuring not just overall cross-sentential link retention but also semantic completeness and correctness of retained links.

2. **Cross-Window Dependency Stress Test**: Design test documents with critical dependencies spanning window boundaries at various distances, analyzing whether parser correctly resolves dependencies requiring information from multiple non-overlapping windows.

3. **Error Type Classification**: Conduct detailed error analysis comparing document-level parsing outputs against gold annotations, categorizing errors by type (window boundary issues, coreference modeling failures, structural inconsistencies) and source (oracle limitations, constraint enforcement failures, transition system inadequacies).
