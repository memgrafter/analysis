# Self-Supervised Reinforcement Learning that Transfers using Random Features

## Quick Facts
- arXiv ID: 2305.17250
- Source URL: https://arxiv.org/abs/2305.17250
- Reference count: 40
- Key outcome: RaMP enables transfer across tasks with different rewards by modeling long-term random feature evolution without requiring autoregressive state predictions

## Executive Summary
RaMP introduces a self-supervised reinforcement learning method that enables zero-shot transfer across tasks with different rewards by modeling the long-term evolution of random features rather than explicit dynamics. The method trains task-agnostic Q-basis functions on offline data using random features as pseudo-rewards, then adapts to new tasks via simple linear regression. This approach circumvents the compounding error problem of model-based RL while achieving strong transfer performance on manipulation and locomotion domains.

## Method Summary
RaMP pre-trains Q-basis functions for random features using offline trajectories without reward labels, then adapts to new tasks via linear regression on random features combined with MPC planning. The key insight is that random features implicitly capture long-horizon dynamics without explicit autoregressive state prediction, enabling efficient transfer across tasks with different reward functions.

## Key Results
- Transfers across manipulation and locomotion tasks outperforming model-based and model-free baselines
- Scales to high-dimensional observations by avoiding compounding error through direct random feature modeling
- Enables quick adaptation to new tasks via simple linear regression on random features

## Why This Works (Mechanism)

### Mechanism 1
Random features implicitly model long-horizon dynamics without autoregressive sampling by accumulating task-agnostic random features over time, learning a Q-basis that encodes environmental evolution across multiple steps without predicting future states explicitly. The core assumption is that random features are sufficiently expressive to approximate any reward function when combined linearly. This breaks if random features are insufficiently expressive (too few or poorly chosen), preventing accurate reward approximation through linear combinations.

### Mechanism 2
Disentangling dynamics from rewards enables zero-shot transfer across tasks by learning Q-functions for random features rather than specific rewards, creating task-agnostic representations recombinable via linear regression for any new reward function. The core assumption is that the same transition dynamics apply across all tasks in the transfer setting. This breaks if tasks have different dynamics (not just rewards), invalidating the pre-trained Q-basis for transfer.

### Mechanism 3
Offline pre-training without reward labels enables self-supervised learning by using random features as pseudo-rewards that don't require ground truth labels, allowing training on unlabeled exploration data. The core assumption is that unlabeled trajectories contain sufficient coverage of state-action space to learn useful Q-basis functions. This breaks if offline data has poor coverage or is biased toward specific behaviors, causing learned Q-basis functions to not generalize to new tasks.

  - Why needed here: The entire framework operates within the MDP formalism, defining states, actions, transitions, and rewards
  - Quick check question: What distinguishes the transition dynamics T from the reward function R in an MDP?

- Concept: Value function estimation via Monte Carlo methods
  - Why needed here: The method uses Monte Carlo sampling to estimate multi-step Q-functions for random features
  - Quick check question: How does Monte Carlo estimation differ from dynamic programming approaches for value function learning?

- Concept: Linear regression with random features
  - Why needed here: At test time, the method solves a linear regression problem to find weights that express the new reward as a combination of random features
  - Quick check question: Why does using random features make the reward regression problem equivalent to ridge regression?

## Architecture Onboarding

- Component map: Random feature generator -> Q-basis learner -> Linear regressor -> MPC planner
- Critical path: Generate random features → Collect offline trajectories → Train Q-basis functions → Solve linear regression → Plan with MPC
- Design tradeoffs: More random features improve reward approximation but increase computational cost; longer planning horizon improves infinite-horizon Q approximation but increases variance; ensemble Q-basis reduces uncertainty but requires more memory
- Failure signatures: Poor transfer performance indicates insufficient random feature expressiveness or inadequate offline data coverage; high variance in Q estimates suggests needing more trajectories or actor-critic variants; planning instability indicates need for larger ensemble or MPC temperature adjustment
- First 3 experiments: Test Point environment with varying random features (128, 512, 2048); compare Meta-World transfer with/without MPC uncertainty penalty; evaluate Hopper scaling with planning horizons H=8, 16, 32

## Open Questions the Paper Calls Out

### Open Question 1
How does RaMP's performance scale with the dimensionality of the observation space, especially in visual domains? The paper evaluates on visual domains but provides limited quantitative analysis of scaling behavior with observation dimensionality. What's needed: Experiments on environments with systematically varied observation dimensions analyzing the relationship between dimensionality and performance metrics.

### Open Question 2
What is the impact of the number of random features (K) on RaMP's performance and computational efficiency? While the paper discusses theoretical bounds and shows performance degrades with lower K, it doesn't fully characterize the trade-off between K, performance, and computational efficiency. What's needed: Systematic experiments varying K across environments analyzing relationships between K, performance, and computational metrics to identify optimal choices.

### Open Question 3
How does RaMP compare to model-based RL methods in terms of sample efficiency and performance on long-horizon tasks? The paper claims advantages over model-based RL but doesn't include direct comparisons on long-horizon tasks. What's needed: Experiments comparing RaMP to state-of-the-art model-based RL on long-horizon tasks analyzing sample efficiency and final performance to quantify claimed advantages.

## Limitations
- Theoretical expressiveness requirements for random features may be impractical in high-dimensional settings
- Assumes tasks share identical dynamics, which rarely holds in real-world applications
- Computational overhead of maintaining multiple Q-basis functions and ensemble planning may limit scalability

## Confidence
- High confidence in theoretical framework and MDP formulation
- Medium confidence in random feature expressiveness claim (based on ablation studies)
- Medium confidence in transfer capability (supported by experiments but lacking strongest baseline comparisons)
- Low confidence in scalability claims (limited to simple environments despite assertions)

## Next Checks
1. Test transfer performance when tasks have slightly different dynamics (e.g., mass variations) to assess robustness to dynamics mismatch
