# Interpretable Multi Labeled Bengali Toxic Comments Classification using Deep Learning

## Quick Facts
- arXiv ID: 2304.04087
- Source URL: https://arxiv.org/abs/2304.04087
- Reference count: 24
- Primary result: 89.42% accuracy for binary toxic/non-toxic classification; 78.92% accuracy and 0.86 weighted F1-score for multi-label toxic category classification

## Executive Summary
This paper presents a two-stage deep learning pipeline for detecting and categorizing toxic Bengali comments. It first uses an LSTM with BERT embedding to classify comments as toxic or non-toxic (89.42% accuracy), then applies a CNN-BiLSTM with attention model to label toxic comments into six categories (78.92% accuracy, 0.86 weighted F1-score). The model uses LIME to explain predictions and interprets word importance. A new manually labeled dataset of 16,073 comments was created. CNN-BiLSTM with attention performed best due to its ability to focus on important features and understand correlations between labels. The study highlights the importance of contextual embeddings and balanced data distribution for toxicity classification in low-resource languages.

## Method Summary
The proposed approach uses a two-stage pipeline for Bengali toxic comment classification. First, an LSTM classifier with Bangla BERT embeddings performs binary classification to detect toxic comments. For toxic comments, a CNN-BiLSTM with attention mechanism performs multi-label classification into six categories: vulgar, hate, religious, threat, troll, and insult. The CNN extracts local n-gram features through three convolutional layers, Bi-LSTM captures bidirectional context, and attention selectively focuses on important features for each label. LIME provides interpretable explanations by approximating the model with a simpler linear model that highlights important words for each prediction.

## Key Results
- Binary classification accuracy: 89.42% using LSTM with BERT embeddings
- Multi-label classification: 78.92% accuracy and 0.86 weighted F1-score using CNN-BiLSTM with attention
- Dataset: 16,073 manually labeled Bengali comments (8,488 toxic, 7,585 non-toxic)
- Six toxic categories identified: vulgar, hate, religious, threat, troll, and insult

## Why This Works (Mechanism)

### Mechanism 1
LSTM with BERT embeddings performs well for binary classification because BERT provides rich contextual representations while LSTM captures sequential dependencies in Bengali toxic comments. BERT tokenization and embedding convert each token into a 768-dimensional vector, which is then pooled to a 768D sentence embedding. LSTM processes this sequence, learning temporal dependencies between words that signal toxicity. The combination allows the model to leverage both contextual meaning and sequential patterns.

### Mechanism 2
CNN-BiLSTM with attention performs best for multi-label classification because CNN extracts local n-gram features while Bi-LSTM captures bidirectional context, and attention focuses on the most relevant features for each label. Three convolutional layers with different kernel sizes (4, 3, 2) extract local patterns from the BERT embeddings. Bi-LSTM processes these in both directions to capture context from all positions. The attention mechanism computes weights for each time step, allowing the model to emphasize features most relevant to each toxicity category, improving label correlation understanding.

### Mechanism 3
LIME provides interpretable explanations by approximating the complex model with a simpler, locally faithful linear model that highlights important words for each prediction. LIME generates perturbed samples around the instance being explained, obtains predictions from the black-box model, weights samples by similarity to the original, and fits a sparse linear model. The coefficients of this linear model indicate which words contribute most to the prediction, making the model's reasoning transparent.

  - Why needed here: Toxic comments have sequential dependencies where earlier words influence the meaning of later words, requiring models that can capture these temporal relationships
  - Quick check question: How does an LSTM cell differ from a standard RNN cell in handling long-range dependencies in toxic comment sequences?

  - Why needed here: A single toxic comment can belong to multiple categories simultaneously (e.g., both "hate" and "insult"), requiring a classification approach that predicts multiple labels per instance

## Architecture Onboarding

- Component map: Input text → Preprocessing (punctuation, emoticons, links, stop words removal) → Tokenization (Bangla BERT tokenizer) → BERT embedding (300x768) → Pooling (768D) → Binary classifier (LSTM) OR Multi-label classifier (CNN-BiLSTM with attention) → Prediction → LIME explanation (optional)
- Critical path: For toxic comment detection, the critical path is: Tokenization → BERT embedding → Classification. Each step must complete successfully for the next to function.
- Design tradeoffs: The two-stage pipeline (binary then multi-label) trades computational efficiency for potentially better accuracy, as it avoids running the more complex multi-label model on non-toxic comments. However, this introduces a dependency where errors in the first stage affect the second.
- Failure signatures: Binary classifier errors (false positives/negatives) will cascade to the multi-label stage; imbalanced class distributions may cause model bias toward majority classes; missing words in pretrained embeddings may reduce feature quality.
- First 3 experiments:
  1. Train and evaluate only the binary LSTM-BERT classifier on the full dataset to establish baseline toxic/non-toxic detection accuracy
  2. Train and evaluate the multi-label CNN-BiLSTM with attention classifier on the toxic subset only, measuring per-class F1 scores
  3. Compare different embedding strategies (Bangla BERT vs word2vec vs fasttext) for both classifiers to quantify the impact of contextual embeddings on performance

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the model perform on out-of-distribution toxic comments that do not fit into the predefined categories (vulgar, hate, religious, threat, troll, insult)?
- Basis in paper: [explicit] The authors mention their dataset covers six specific toxic categories and evaluate performance on these, but do not test the model's ability to handle comments that might belong to other types of toxicity or new emerging forms of toxic language.
- Why unresolved: The paper does not include any experiments with novel toxic categories or emerging forms of online toxicity that weren't part of the training data.
- What evidence would resolve it: Testing the model on a diverse set of toxic comments from different sources and contexts, including emerging forms of toxicity, and measuring performance across these new categories.

### Open Question 2
- Question: What is the impact of dataset imbalance on the model's performance across different toxic categories?
- Basis in paper: [explicit] The authors acknowledge in their result analysis that "the data distribution per toxic class is not equal which may produce bias towards particular classes" and provide class distribution statistics.
- Why unresolved: While the authors recognize the imbalance issue, they do not explore techniques to address it (such as oversampling, undersampling, or class weighting) or measure how this imbalance affects model performance on minority classes.
- What evidence would resolve it: Conducting experiments with balanced datasets or applying imbalance mitigation techniques and comparing performance metrics across all toxic categories.

### Open Question 3
- Question: How transferable is the model to other low-resource languages with similar linguistic characteristics to Bengali?
- Basis in paper: [inferred] The authors successfully apply deep learning techniques to Bengali, a low-resource language, suggesting potential applicability to other similar languages, but do not test this hypothesis.
- Why unresolved: The paper focuses exclusively on Bengali and does not explore whether the methodology could be adapted to other low-resource languages or whether the same model architecture would work across different linguistic contexts.
- What evidence would resolve it: Applying the same methodology to other low-resource languages with similar characteristics and comparing performance metrics to establish transferability.

## Limitations
- Dataset quality concerns: The newly created dataset's annotation methodology, inter-annotator agreement, and representativeness of Bengali toxic language are not specified
- Generalization uncertainty: No external validation on out-of-domain data or temporal validation to assess performance on evolving toxic language patterns
- Computational efficiency unknown: The paper doesn't discuss inference time, memory requirements, or practical deployment constraints for the two-stage pipeline

## Confidence
- High Confidence: Binary classification results (89.42% accuracy) and multi-label classification results (78.92% accuracy, 0.86 weighted F1-score)
- Medium Confidence: CNN-BiLSTM with attention superiority claim; lacks ablation studies confirming specific architectural contributions
- Low Confidence: Interpretability claims based on LIME; no validation that explanations help human understanding or improve model trustworthiness
