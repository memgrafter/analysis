# MetaAID 2.0: An Extensible Framework for Developing Metaverse Applications via Human-controllable Pre-trained Models

## Quick Facts
- arXiv ID: 2302.13173
- Source URL: https://arxiv.org/abs/2302.13173
- Reference count: 9
- Key outcome: Framework enabling controllable creativity and responsibility in metaverse applications through PM information flows and URI extensions

## Executive Summary
MetaAID 2.0 addresses the challenge of developing metaverse applications with controllable pre-trained models by introducing a framework that combines human creativity control with model output responsibility. The system enables users to define custom PM information flows that sequence different pre-trained models while maintaining control over the generation process. Through URI-extensions, the framework provides semantic-based tracking and retrieval of model outputs, even after modification. The framework supports multimodal data processing including text, image, video, and audio, and experimental results demonstrate its effectiveness in achieving controllable creativity and responsible content generation.

## Method Summary
The framework integrates pre-trained models for text generation (GPT-2), image generation (DALL-E 2, Stable Diffusion), audio processing (speech synthesis), and video generation (Make-A-Video) within a human-controllable PM information flow mechanism. Users can sequence these models to create multimodal pipelines while maintaining control over parameters and generation sequence. The URI-extension system tags each output with a URI, detailed description, and multimodal embeddings (ViT for images, audio fingerprinting for audio) to enable semantic retrieval and responsibility tracking. The framework is implemented as a website interface for experimental testing of multimodal data processing and PM information flow effectiveness.

## Key Results
- PM information flows enable autonomous human control over creativity in metaverse applications
- URI-extensions with multimodal embeddings support fuzzy retrieval of modified model outputs
- Experimental results validate controllable creativity and responsibility through the framework

## Architecture Onboarding

- Component map:
  Input handlers (text, image, video, audio) -> Model modules (Zhongguancun, Houhai, Wudaokou, Gulou) -> URI-extension generator (URI, description, embeddings) -> Output composer (assembles final multimodal product) -> Storage/Retrieval layer (serializes embeddings, supports fuzzy search)

- Critical path:
  1. User defines PM information flow (sequence of modules)
  2. Input is processed through each module in sequence
  3. URI-extension is generated for each output
  4. Final product is assembled and stored with URI metadata

- Design tradeoffs:
  - Flexibility vs. complexity: More modules and flows increase creative potential but also user burden.
  - Embedding quality vs. storage cost: High-dimensional embeddings improve retrieval but increase storage needs.
  - Modality independence vs. integration coherence: Separate modules simplify design but may introduce integration issues.

- Failure signatures:
  - Degraded output quality when chaining models
  - High false-negative rates in fuzzy retrieval
  - Latency spikes when processing complex multimodal flows

- First 3 experiments:
  1. Single-modality flow (text → text) to verify basic module chaining
  2. Two-modality flow (text → image) to test cross-modal integration
  3. URI-extension retrieval test with modified outputs to validate fuzzy search
