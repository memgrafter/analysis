# Hidden Markov Transformer for Simultaneous Machine Translation

## Quick Facts
- arXiv ID: 2303.00257
- Source URL: https://arxiv.org/abs/2303.00257
- Reference count: 40
- Key outcome: HMT outperforms strong baselines and achieves state-of-the-art performance, with improvements in BLEU scores under various latency levels.

## Executive Summary
This paper addresses simultaneous machine translation (SiMT) by introducing the Hidden Markov Transformer (HMT), which treats moments of starting translation as hidden events and the target sequence as observed events. The model explicitly models multiple candidate moments of starting translation as hidden states and selects one to generate each target token. By maximizing the marginal likelihood of the target sequence over these multiple moments, HMT learns to start translating at moments that enable more accurate target token generation. Experiments on multiple SiMT benchmarks demonstrate that HMT outperforms strong baselines and achieves state-of-the-art performance, particularly in balancing translation quality with latency.

## Method Summary
HMT is a Transformer-based SiMT model that extends the standard encoder-decoder architecture by organizing the moments of starting translation and target sequence in the form of a hidden Markov model. During training, HMT produces K states for each target token, each representing starting translation after receiving a different number of source tokens. The model then selects one state to generate the target token based on confidence scores. The training objective is to maximize the marginal likelihood of the target sequence over all possible state selections. HMT also introduces a state loss to encourage each state to generate the correct target token and a latency loss to control the average waiting time. The model is trained on datasets such as IWSLT15 English→Vietnamese and WMT15 German→English, and evaluated using metrics like BLEU score and Average Lagging.

## Key Results
- HMT outperforms strong baselines and achieves state-of-the-art performance on multiple SiMT benchmarks.
- HMT shows improvements in BLEU scores under various latency levels, demonstrating a better trade-off between translation quality and latency.
- The model's effectiveness is attributed to its ability to explicitly model multiple moments of starting translation and learn when to start translating from multiple possible moments.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: HMT explicitly models multiple moments of starting translation as hidden states, which enables the model to learn when to start translating from multiple possible moments.
- Mechanism: The model produces K states for each target token, each representing starting translation after receiving a different number of source tokens. During training, HMT maximizes the marginal likelihood of the target sequence over all possible selection results, encouraging the selection of states that generate more accurate target tokens.
- Core assumption: The moments of starting translation are hidden events that can be effectively modeled as hidden states in a hidden Markov model, and the target sequence can serve as the corresponding observed events.
- Evidence anchors:
  - [abstract]: "HMT explicitly models multiple moments of starting translating as the candidate hidden events, and then selects one to generate the target token. During training, by maximizing the marginal likelihood of the target sequence over multiple moments of starting translating, HMT learns to start translating at the moments that target tokens can be generated more accurately."
  - [section]: "HMT explicitly produces a set of states for each target token, where multiple states represent starting translating the target token at different moments respectively... Then, HMT judges whether to select each state from low latency to high latency."
- Break condition: If the model cannot effectively distinguish between states representing different moments of starting translation, or if the marginal likelihood maximization fails to identify the optimal moments, the mechanism breaks down.

### Mechanism 2
- Claim: Self-attention between states allows HMT to capture comprehensive state representations by considering different moments of starting translation.
- Mechanism: The self-attention mechanism enables each state to pay attention to states of previous target tokens, ensuring that the attention satisfies tj,k' ≤ ti,k to avoid future source information leakage. This allows HMT to capture more comprehensive state representations.
- Core assumption: The self-attention mechanism can effectively capture the dependencies between states representing different moments of starting translation, and the monotonicity constraint tj,k' ≤ ti,k is sufficient to prevent information leakage.
- Evidence anchors:
  - [abstract]: "State Production When translating yi, HMT first produces a set of K states si = {si,1,...,si,K} to represent starting translating yi when receiving different numbers of source tokens respectively."
  - [section]: "For self-attention between states, state si,k can pay attention to the state sj,k′ of all previous target tokens (i.e., j ≤ i), while ensuring that sj,k′ starts translating no later than si,k (i.e., tj,k′ ≤ ti,k) to avoid future source information leaking from sj,k′ to si,k."
- Break condition: If the self-attention mechanism fails to capture the dependencies between states, or if the monotonicity constraint is insufficient to prevent information leakage, the mechanism breaks down.

### Mechanism 3
- Claim: The proposed boundary for translating moments (lower and upper boundaries) effectively prunes unfavorable translating moments and improves training and inference efficiency.
- Mechanism: HMT introduces a wait-L path as the lower boundary and a wait-(L+K-1) path as the upper boundary, considering only those suitable moments of starting translating within this interval. This pre-pruning of unfavorable moments improves training and inference efficiency.
- Core assumption: The boundaries effectively identify and prune unfavorable translating moments, and the remaining moments within the boundaries are suitable for starting translation.
- Evidence anchors:
  - [abstract]: "To set the suitable t for states, we aim to pre-prune those unfavorable translating moments, such as translating y1 after receiving xJ or translating yI after receiving x1."

- Break condition: If the boundaries fail to effectively identify and prune unfavorable translating moments, or if the remaining moments within the boundaries are not suitable for starting translation, the mechanism breaks down.

## Architecture Onboarding

- Component map: Encoder -> Hidden Markov Decoder -> State Production -> Translation -> Selection
- Critical path:
  1. Encoder maps source sequence to source hidden states.
  2. Hidden Markov Decoder produces K states for each target token.
  3. Self-attention between states captures comprehensive state representations.
  4. Cross-attention to source hidden states computes translation probabilities.
  5. Confidence is predicted for each state.
  6. State with confidence ≥ 0.5 is selected to generate the target token.
- Design tradeoffs:
  - Number of states (K): Larger K allows considering more moments of starting translation but increases computational complexity.
  - Lower boundary (L): Smaller L leads to lower latency but may sacrifice translation quality.
  - Upper boundary (L+K-1): Larger upper boundary allows considering more moments of starting translation but increases computational complexity.
- Failure signatures:
  - Poor translation quality: May indicate issues with state production, self-attention, or translation components.
  - High latency: May indicate issues with boundary settings or state selection.
  - Unstable training: May indicate issues with marginal likelihood maximization or loss function design.

  1. Ablation study on the number of states (K): Evaluate the impact of different K values on translation quality and latency.
  2. Ablation study on boundary settings (L and K): Evaluate the impact of different boundary settings on translation quality and latency.
  3. Comparison with baseline methods: Compare HMT's performance with existing SiMT methods on standard benchmarks.
