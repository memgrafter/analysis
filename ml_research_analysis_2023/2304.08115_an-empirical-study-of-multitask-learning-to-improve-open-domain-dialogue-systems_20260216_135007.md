# An Empirical Study of Multitask Learning to Improve Open Domain Dialogue Systems

## Quick Facts
- arXiv ID: 2304.08115
- Source URL: https://arxiv.org/abs/2304.08115
- Reference count: 7
- Auxiliary tasks improve GPT-2 dialogue models by ~2% perplexity and slight BLEU/ROUGE gains

## Executive Summary
This paper investigates the use of auxiliary tasks to improve open-domain dialogue systems based on GPT-2. The authors introduce four auxiliary tasks—utterance permutation detection (binary and non-binary) and utterance masking (binary and non-binary)—and fine-tune GPT-2 small and medium models on PersonaChat and DailyDialog datasets. The results show that binary versions of these tasks outperform non-binary ones, especially when applied to both persona and context components. While the improvements in perplexity and generation metrics are modest, the findings suggest that auxiliary tasks can enhance context understanding in dialogue models.

## Method Summary
The authors fine-tune GPT-2 small and medium models on PersonaChat and DailyDialog datasets using a combination of language modeling and auxiliary tasks. Four auxiliary tasks are implemented: utterance permutation detection (UPD) and utterance masking (UMD) in both binary and non-binary forms. The tasks are applied to persona, context, or both components. Models are trained with AdamW optimizer (5e-5 for DailyDialog, 3e-5 for PersonaChat), weight decay 0.001, 5 warm-up steps, and 5 epochs. Performance is evaluated using perplexity, BLEU, ROUGE-L, BERTScore, MoverScore, Average, Greedy, and Extrema metrics.

## Key Results
- Binary auxiliary tasks (utterance permutation and masking) outperform non-binary versions.
- Applying auxiliary tasks to both persona and context components yields better performance than applying them to only one component.
- Perplexity decreases by ~2% and BLEU/ROUGE scores increase slightly with auxiliary tasks.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Binary auxiliary tasks (utterance permutation and masking) are more effective than non-binary versions in improving dialogue model performance.
- Mechanism: Binary tasks simplify the learning signal by reducing the prediction problem to a classification (correct/incorrect order or masked token), which is easier for the decoder-only model to learn from given its limited context access.
- Core assumption: The decoder-only architecture with masked causal attention only sees left context, so complex reconstruction tasks are harder to learn than binary classification.
- Evidence anchors:
  - [abstract] "The binary version of auxiliary tasks outperforms non-binary."
  - [section] "Determining the exact part of dialogue that will benefit the most from these tasks is challenging, but it can be agreed upon that combining both the Persona and Context components leads to improved outcomes."
  - [corpus] Weak - no direct corpus support found for binary vs non-binary comparison.

### Mechanism 2
- Claim: Applying auxiliary tasks to both persona and context components yields better performance than applying them to only one component.
- Mechanism: Persona and context provide complementary information; jointly training on both ensures the model learns to integrate personal attributes with conversational history for more coherent responses.
- Core assumption: The dialogue model benefits from richer, multi-faceted supervision signals that cover all relevant aspects of the conversation.
- Evidence anchors:
  - [abstract] "Utterance permutation (binary) and utterance masking (binary) perform best, especially when applied to both persona and context components."
  - [section] "Determining the exact part of dialogue that will benefit the most from these tasks is challenging, but it can be agreed upon that combining both the Persona and Context components leads to improved outcomes."
  - [corpus] Weak - no corpus evidence directly supports persona+context combination effect.

### Mechanism 3
- Claim: Auxiliary tasks act as regularization, improving generalization and coherence of generated responses in multi-turn dialogues.
- Mechanism: By forcing the model to solve additional self-supervised tasks (e.g., detecting re-ordered utterances, predicting masked tokens), the model learns more robust representations of utterance-level dependencies.
- Core assumption: The auxiliary tasks introduce inductive biases that encourage the model to capture linguistic structure beyond token-level patterns.
- Evidence anchors:
  - [abstract] "Previous research in open-domain dialogue generation has shown that the use of auxiliary tasks can introduce inductive biases that encourage the model to improve these qualities."
  - [section] "The utilization of auxiliary tasks in decoder-only models is a well-established practice."
  - [corpus] Weak - no direct corpus support for regularization effect.

## Architecture Onboarding

- Component map:
  - Input encoder: GPT-2 tokenizer with special tokens for persona, context, and response.
  - Language modeling head: Standard GPT-2 decoder head for next-token prediction.
  - Auxiliary heads: Binary classification heads for utterance permutation and masking tasks.
  - Loss combiner: Weighted sum of LM and auxiliary losses.

- Critical path:
  1. Tokenize input with persona/context/response markers.
  2. Pass through GPT-2 to get token embeddings.
  3. Compute LM loss on response tokens.
  4. Apply auxiliary heads to relevant positions and compute auxiliary losses.
  5. Backpropagate combined loss.

- Design tradeoffs:
  - Binary vs non-binary auxiliary tasks: Simpler classification vs more complex reconstruction.
  - Task placement: Applying tasks to persona, context, or both.
  - Loss weighting: Balancing LM vs auxiliary objectives.

- Failure signatures:
  - Perplexity plateaus or worsens: Auxiliary loss weight too high or tasks too hard.
  - BLEU/ROUGE scores flat: Tasks not improving generation quality.
  - Training instability: Mismatched task objectives or learning rates.

- First 3 experiments:
  1. Run baseline GPT-2 on PersonaChat with new prompt format; verify perplexity and generation quality.
  2. Add utterance permutation (binary) auxiliary task on context only; compare performance.
  3. Add utterance masking (binary) auxiliary task on both persona and context; compare performance.

## Limitations
- Performance gains are modest (~2% perplexity reduction, marginal BLEU/ROUGE improvements).
- Evaluation relies heavily on automated metrics without human validation.
- Findings are limited to GPT-2 architecture and two specific datasets.

## Confidence

**High Confidence**: The finding that binary auxiliary tasks outperform non-binary versions has strong empirical support from the reported results across both datasets and model sizes.

**Medium Confidence**: The claim that applying auxiliary tasks to both persona and context components yields better performance is supported by the data but has some caveats due to modest improvements.

**Low Confidence**: The assertion that auxiliary tasks act as regularization improving generalization and coherence lacks direct empirical support in the paper.
