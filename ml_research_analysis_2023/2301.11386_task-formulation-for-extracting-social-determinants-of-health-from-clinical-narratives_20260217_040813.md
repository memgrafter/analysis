# Task formulation for Extracting Social Determinants of Health from Clinical Narratives

## Quick Facts
- arXiv ID: 2301.11386
- Source URL: https://arxiv.org/abs/2301.11386
- Reference count: 34
- Three systems for SDOH extraction achieved F1 scores of 0.884, 0.831, and 0.663 respectively

## Executive Summary
This paper presents three distinct approaches to extracting social determinants of health (SDOH) from clinical narratives, developed for the 2022 n2c2 NLP Challenge. The systems vary in their task formulation: one uses independent sentence-level classification, another employs a large language model with few-shot learning, and the third combines machine learning with hand-crafted rules for relation extraction. Each approach demonstrates different trade-offs between performance, explainability, and implementation complexity, with the independent classification approach achieving the highest F1 score of 0.884. The study reveals how the challenge's evaluation metrics, which score triggers and arguments separately, favor certain architectural choices over others.

## Method Summary
The paper describes three systems for extracting SDOH information from clinical narratives. System 1 uses independent sentence-level classification with multi-label text classifiers and BIO sequence labeling, ignoring trigger-argument relations. System 2 employs a fine-tuned large language model (GPT-J) to extract structured outputs through table-formatted prompts and few-shot examples. System 3 uses a pipeline approach with CRF sequence labeling for phrase detection followed by hand-crafted rules for trigger-argument relation linking. All systems were evaluated on the SHAC corpus from the n2c2 challenge, which contains 5 SDOH types (Alcohol, Tobacco, Drug, Employment, Living Status) with triggers and arguments.

## Key Results
- System 1 (independent classification) achieved F1 score of 0.884, ranking 3rd among 15 teams
- System 2 (LLM-based) achieved F1 score of 0.831, ranking 7th among 15 teams
- System 3 (rule-based) achieved F1 score of 0.663, ranking 8th among 15 teams
- Evaluation metric design (counting triggers and arguments separately) favored System 1's approach
- System 1's method avoids complex trigger-argument relation modeling by decomposing the task

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Independent sentence-level classification achieves higher F1 by avoiding complex trigger-argument relation modeling.
- Mechanism: Decomposes SDOH extraction into simple text classification (for triggers and labeled arguments) and sequence labeling (for span-only arguments) per sentence, leveraging forgiving evaluation metrics.
- Core assumption: Most trigger-argument relations are within a single sentence and labeled arguments are scored by inferred labels only.
- Evidence anchors:
  - [abstract]: "The system that extracts information independently, ignoring the annotated relations, achieves the highest F1 score."
  - [section]: "Most of the trigger-argument relations are within a single sentence... Therefore, the trigger span is not required in effect if a long enough span is proposed."
  - [corpus]: Weak/no direct corpus evidence; inference from challenge data characteristics.
- Break condition: If trigger-argument relations frequently span multiple sentences or evaluation requires exact spans, this approach fails.

### Mechanism 2
- Claim: Fine-tuned LLM captures complete structured outputs by modeling all relations simultaneously.
- Mechanism: Uses few-shot examples converted to table format to fine-tune GPT-J, enabling end-to-end extraction of triggers, arguments, and their relations without explicit decomposition.
- Core assumption: LLM's general knowledge and few-shot learning can model diverse SDOH relations better than rule-based or decomposed approaches.
- Evidence anchors:
  - [abstract]: "Meanwhile, LLM with its versatile capability achieves the high F1 score, while respecting the annotated relations."
  - [section]: "The generated text and gold annotation can be seen in Figure 1C. As formulated, the few-shot task is essentially asking the LLM to function as both a question/answer language model (for span extraction) and a few-shot classification model (for categorical assignments)."
  - [corpus]: Weak/no direct corpus evidence; performance claims based on challenge results.
- Break condition: If computing resources are insufficient or model memorization degrades generalization, performance drops.

### Mechanism 3
- Claim: Rule-based relation extraction provides explainability but suffers from low recall due to complex SDOH relations.
- Mechanism: Uses pipeline architecture with CRF for phrase detection and hand-crafted rules for trigger-argument linking based on syntactic and span patterns.
- Core assumption: Human-readable rules can capture SDOH relations if sufficient time is spent analyzing corpus patterns.
- Evidence anchors:
  - [abstract]: "The rule-based system tackling relation extraction obtains the low F1 score, while it is the most explainable approach."
  - [section]: "When a good rule is created, the precision of the extraction can be high... Yet, many rules are needed to boost the recall."
  - [corpus]: Weak/no direct corpus evidence; performance limitations attributed to time constraints.
- Break condition: If SDOH relations are too diverse or time-constrained, rule coverage remains incomplete.

## Architecture Onboarding

- Component map:
  - System 1: Sentence splitter → Multi-label text classifier (triggers/labeled args) → Sequence labelers (span-only args) → Output merger
  - System 2: Prompt generator → GPT-J fine-tuned model → Span mapping heuristics → Output formatter
  - System 3: Tokenizer → CRF phrase detector → Rule-based relation linker → Output generator

- Critical path:
  - System 1: Sentence classification accuracy → Sequence labeling precision → Output merging logic
  - System 2: Few-shot prompt quality → Model fine-tuning effectiveness → Span mapping heuristics
  - System 3: CRF detection performance → Rule coverage completeness → Rule precision/recall balance

- Design tradeoffs:
  - System 1: High performance but no trigger phrases or labeled argument spans extracted; limited to single-sentence relations
  - System 2: Complete structured outputs but requires significant compute resources and offers limited interpretability
  - System 3: Explainable outputs but time-intensive rule development and maintenance; lower overall performance

- Failure signatures:
  - System 1: High false positives from independent predictions; missed multi-sentence relations
  - System 2: Output hallucinations; poor span mapping; overfitting to training data
  - System 3: Low recall from incomplete rule coverage; high maintenance burden

- First 3 experiments:
  1. System 1: Test sentence classification vs. relation-aware baseline on single-sentence SDOH mentions
  2. System 2: Compare few-shot prompt formats and table structures on extraction accuracy
  3. System 3: Analyze rule precision/recall tradeoffs on specific SDOH types (e.g., Alcohol vs. Employment)

## Limitations
- The evaluation metrics' design heavily favors independent classification approaches by counting triggers and arguments separately rather than as complete pairs
- The paper lacks systematic error analysis across systems to determine whether performance differences are fundamental or implementation-specific
- Computational resource requirements for LLM approaches versus rule-based methods create practical adoption barriers not fully explored

## Confidence
- **High Confidence**: The relative performance ranking of the three systems and the observation that independent classification benefits from evaluation metric design
- **Medium Confidence**: Claims about LLM capabilities and rule-based explainability lack detailed validation of underlying mechanisms
- **Low Confidence**: Generalizability to other clinical domains or languages is not addressed, and rule development effort is only qualitatively described

## Next Checks
1. **Error Analysis Validation**: Conduct systematic error analysis comparing all three systems on identical validation sets to identify whether performance differences are due to architecture or implementation choices, focusing on multi-sentence relations and trigger-argument linking failures.

2. **Resource Efficiency Study**: Measure and compare the computational resources (training time, inference latency, memory usage) required for each approach across different hardware configurations to quantify the practical trade-offs beyond F1 scores.

3. **Generalizability Test**: Apply the best-performing approach (System 1) to a different clinical domain or language to assess whether the independent classification strategy generalizes beyond the specific SDOH challenge domain.
