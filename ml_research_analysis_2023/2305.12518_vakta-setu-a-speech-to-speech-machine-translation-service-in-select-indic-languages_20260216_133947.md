# VAKTA-SETU: A Speech-to-Speech Machine Translation Service in Select Indic Languages

## Quick Facts
- arXiv ID: 2305.12518
- Source URL: https://arxiv.org/abs/2305.12518
- Reference count: 33
- Primary result: Deployed speech-to-speech translation system for English-Hindi, English-Marathi, and Hindi-Marathi with high human evaluation scores across translation quality, speech quality, and interpretability.

## Executive Summary
This paper presents VAKTA-SETU, a scalable speech-to-speech machine translation (SSMT) system supporting English-Hindi, English-Marathi, and Hindi-Marathi language pairs. The system uses a cascade architecture combining Automatic Speech Recognition, Disfluency Correction, Machine Translation, and Text-to-Speech Synthesis models. The authors develop a LaBSE-based corpus filtering tool to extract high-quality parallel sentences from noisy data, addressing data scarcity challenges. The deployed system supports multiple concurrent users with low latency and achieves high scores in human evaluations across translation quality, speech quality, and interpretability. A public web service has been created to access the system, with ongoing collection of user feedback for future improvements.

## Method Summary
The VAKTA-SETU system implements a cascaded SSMT pipeline consisting of four main components: Automatic Speech Recognition (ASR) using a wav2vec 2.0 model fine-tuned on noisy data, Disfluency Correction (DC) using a MuRIL transformer for token classification, Machine Translation (MT) using a Transformer architecture with pivot-based transfer learning and LaBSE-based corpus filtering, and Text-to-Speech Synthesis (TTS) using a Forward Tacotron architecture with CARGAN vocoder. The system was trained on various datasets including CommonVoice for ASR, IndicTTS for TTS, and multiple parallel corpora for MT. A LaBSE-based corpus filtering tool was developed to select high-quality parallel sentences from noisy pseudo-parallel corpora, improving translation quality. The system was deployed on 8 A100 GPUs supporting 104 concurrent SSMT pipelines and evaluated through human evaluation with 101 participants across translation quality, speech quality, and interpretability metrics.

## Key Results
- Human evaluation achieved high scores (4.5+ out of 5) across translation quality, speech quality, and interpretability for all three language pairs
- LaBSE-based corpus filtering improved MT model quality by extracting high-quality parallel sentences from noisy data
- System supports 104 concurrent SSMT pipelines across 8 A100 GPUs with low latency
- Public web service deployed with ongoing user feedback collection for improvements

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Using a cascade of ASR, DC, MT, and TTS models provides robust speech-to-speech translation by isolating error sources and allowing modular improvements.
- Mechanism: Each component handles a distinct transformation (speech-to-text, text cleanup, language translation, text-to-speech) so errors are localized and can be corrected independently.
- Core assumption: The cascaded pipeline does not compound errors beyond recoverability at each stage.
- Evidence anchors:
  - [abstract] "We develop the SSMT system by cascading Automatic Speech Recognition (ASR), Disfluency Correction (DC), Machine Translation (MT), and Text-to-Speech Synthesis (TTS) models."
  - [section] "The input speech is passed to the ASR system, which transcribes the input speech in the source language. This transcription may also contain disfluencies from the speech, which are removed using the DC system."
- Break condition: If any component's error rate exceeds a threshold that causes cascading failure in downstream quality.

### Mechanism 2
- Claim: LaBSE-based corpus filtering improves MT model quality by removing noisy or misaligned parallel sentences from training data.
- Mechanism: Sentence embeddings from LaBSE model are used to compute cosine similarity scores between source and target sentences; low-scoring pairs are filtered out before training.
- Core assumption: High-quality parallel sentences have embeddings that are more similar than low-quality or misaligned pairs.
- Evidence anchors:
  - [abstract] "To mitigate data scarcity, we develop a LaBSE-based corpus filtering tool to select high-quality parallel sentences from a noisy pseudo-parallel corpus for training the TTMT system."
  - [section] "We use the LaBSE model to generate sentence embeddings for the source and target sentences. Then, we compute the cosine similarity between the source and target sentence embeddings."
- Break condition: If the LaBSE model's embedding space does not capture semantic equivalence well for the language pair.

### Mechanism 3
- Claim: Noisy data finetuning improves ASR robustness in real-world environments.
- Mechanism: The baseline ASR model is retrained on audio samples with added noise to simulate real-world conditions, improving recognition accuracy under noise.
- Core assumption: Synthetic noise injection approximates the distribution of real environmental noise.
- Evidence anchors:
  - [section] "We further train this model on Signal to Noise Ratio (SNR) modulated audio samples to make the transcription quality more robust in noisy environments."
  - [corpus] Limited - no evaluation on real noisy data provided in the paper.
- Break condition: If synthetic noise patterns differ significantly from real-world noise distributions.

## Architecture Onboarding

- Component map: Speech input -> ASR transcription -> DC cleanup -> MT translation -> TTS synthesis -> audio output
- Critical path: Speech input → ASR transcription → DC cleanup → MT translation → TTS synthesis → audio output
- Design tradeoffs: Cascade architecture trades end-to-end error propagation for modularity and interpretability vs. potential latency increases
- Failure signatures:
  - ASR failures: High WER, transcription errors
  - DC failures: Residual disfluencies in text
  - MT failures: Poor BLEU scores, semantic errors
  - TTS failures: Low audio quality, poor intelligibility
- First 3 experiments:
  1. Test individual component accuracy (WER for ASR, F1 for DC, BLEU for MT, MOS for TTS)
  2. Test pipeline latency with single concurrent user
  3. Test system with known disfluent speech samples to verify DC effectiveness

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the LaBSE-based corpus filtering tool perform when applied to other low-resource language pairs beyond English-Hindi, English-Marathi, and Hindi-Marathi?
- Basis in paper: [explicit] The paper describes developing a LaBSE-based corpus filtering tool for high-quality parallel sentence extraction from noisy pseudo-parallel corpora.
- Why unresolved: The paper only evaluates the corpus filtering tool on the specific language pairs used in the study (English-Hindi, English-Marathi, and Hindi-Marathi).
- What evidence would resolve it: Testing the LaBSE-based corpus filtering tool on a diverse set of low-resource language pairs and comparing its performance with existing corpus filtering methods.

### Open Question 2

## Limitations
- Evaluation relies heavily on subjective human evaluation with 101 participants, which may not be representative of all user groups or real-world usage patterns.
- Corpus filtering approach using LaBSE embeddings assumes semantic similarity correlates with translation quality, but optimal threshold selection is not validated.
- ASR robustness claims are based on synthetic noise injection during training, but lacks evaluation on real-world noisy data to confirm performance in actual environmental conditions.

## Confidence
- High Confidence: The cascade architecture effectively separates error sources and allows modular improvements. The individual component evaluations (ASR WER, MT BLEU scores, TTS MOS) are reported with specific metrics and datasets, providing strong evidence for component-level performance.
- Medium Confidence: The LaBSE-based corpus filtering improves MT model quality. While the methodology is sound and the filtering process is described, the optimal threshold selection and its impact on downstream translation quality could be more thoroughly validated.
- Low Confidence: The system achieves low latency and supports multiple concurrent users in production. The paper mentions deployment on 8 A100 GPUs but provides limited performance benchmarking data under varying load conditions or stress testing results.

## Next Checks
1. Inter-rater reliability analysis: Calculate and report Fleiss' kappa or similar agreement metrics for the human evaluation scores across all three dimensions (TQ, SQ, I) to assess consistency of subjective judgments.

2. Real-world noise evaluation: Test the ASR component on diverse real-world noisy datasets (e.g., CHiME, Librispeech noisy) to validate whether synthetic noise injection during training translates to improved performance on actual environmental noise conditions.

3. A/B testing with alternative architectures: Compare the cascade approach against end-to-end SSMT models on the same evaluation metrics to quantify the tradeoff between modularity and potential latency increases, providing empirical evidence for the architectural choice.
