# Gorilla: Large Language Model Connected with Massive APIs

## Quick Facts
- arXiv ID: 2305.15334
- Source URL: https://arxiv.org/abs/2305.15334
- Reference count: 40
- Key outcome: Finetuned LLaMA model with retriever-aware training significantly outperforms GPT-4 on API call accuracy while reducing hallucination rates

## Executive Summary
This paper introduces Gorilla, a finetuned LLaMA-based model designed to excel at generating accurate API calls. The core innovation is combining LLaMA with a document retriever during both training and inference, enabling the model to adapt to test-time changes in API documentation and significantly reduce hallucination errors. The authors create APIBench, a comprehensive dataset of ML APIs from HuggingFace, TorchHub, and TensorHub, along with synthetic user prompts. Gorilla demonstrates superior performance on API call accuracy while maintaining low hallucination rates, particularly excelling at handling test-time API changes.

## Method Summary
Gorilla uses retriever-aware fine-tuning where the LLaMA model is trained to leverage retrieved API documentation during both training and inference. The approach combines the base LLaMA model with a document retriever that fetches relevant API specifications. During fine-tuning, the model learns to reason about constraints and accurately generate API calls based on retrieved documentation. The training process uses synthetic user prompts generated from API documentation, and the model is evaluated on APIBench, a dataset containing over 1,600 HuggingFace, TorchHub, and TensorHub APIs.

## Key Results
- Gorilla outperforms GPT-4 on API call accuracy while maintaining significantly lower hallucination rates
- The retriever-aware fine-tuning approach enables Gorilla to flexibly handle updates to API documentation at test time
- Synthetic prompt generation combined with retrieval fine-tuning substantially improves performance over zero-shot approaches

## Why This Works (Mechanism)
Gorilla works by integrating a document retriever into the fine-tuning process, allowing the model to access and reason about up-to-date API documentation during inference. Unlike traditional zero-shot approaches where the model relies solely on its pretraining knowledge, Gorilla learns to leverage retrieved information to generate accurate API calls. This retriever-aware training enables the model to adapt to test-time changes in API documentation and better understand API constraints and specifications.

## Foundational Learning

**API Documentation Retrieval**: Understanding how to fetch and parse API documentation from various sources (why needed: essential for the retrieval component; quick check: can the system correctly identify and extract API specifications from documentation sources)

**LLaMA Fine-tuning**: Knowledge of adapting pretrained language models for specific tasks (why needed: core technique for adapting LLaMA to API generation; quick check: can the model effectively learn to generate API calls from examples)

**Synthetic Prompt Generation**: Creating realistic user queries from API documentation (why needed: provides training data for the fine-tuning process; quick check: do the synthetic prompts cover diverse usage patterns and edge cases)

## Architecture Onboarding

**Component Map**: User Query -> Retriever -> API Documentation -> Gorilla Model -> API Call

**Critical Path**: User query is processed by retriever, which fetches relevant API documentation, then passed to Gorilla model which generates the API call

**Design Tradeoffs**: The paper chose retriever-aware fine-tuning over zero-shot approaches to handle dynamic API changes, accepting the complexity of maintaining a retrieval system in exchange for improved accuracy and reduced hallucinations

**Failure Signatures**: Performance degradation occurs when the retriever returns incorrect or incomplete documentation, or when API specifications are ambiguous or conflicting

**First Experiments**:
1. Evaluate baseline LLaMA performance on API call generation without retrieval
2. Test retriever accuracy on API documentation retrieval across different sources
3. Compare hallucination rates between zero-shot and retrieval-aware approaches

## Open Questions the Paper Calls Out
The paper acknowledges that performance is contingent on retriever quality and does not systematically characterize failure modes when the retriever returns incorrect or incomplete documentation. The mechanism for handling conflicting or ambiguous API specifications is not fully explored.

## Limitations
- Limited evaluation scope to ML APIs (HuggingFace, TorchHub, TensorHub) without testing on diverse non-ML or enterprise-specific APIs
- Reliance on synthetic prompt generation may not capture full complexity of real-world API usage patterns
- Controlled evaluation setup may not reflect challenges in dynamic production environments with rapidly evolving APIs

## Confidence
- High confidence: Retriever-aware fine-tuning improves API call accuracy over zero-shot approaches
- Medium confidence: Reduced hallucination rates are demonstrated within evaluation scope but may not generalize to all API domains
- Medium confidence: Claims about flexible handling of test-time API changes are demonstrated but not extensively validated across diverse evolution scenarios

## Next Checks
1. Test Gorilla on diverse non-ML APIs (REST APIs, cloud service APIs) to assess domain generalization
2. Conduct ablation studies quantifying retriever quality impact on performance, including incorrect/incomplete retrieval scenarios
3. Perform user studies with real-world API usage to evaluate practical utility and identify deployment challenges not captured in synthetic evaluations
