# MARLIN: Soft Actor-Critic based Reinforcement Learning for Congestion Control in Real Networks

## Quick Facts
- arXiv ID: 2302.01301
- Source URL: https://arxiv.org/abs/2302.01301
- Reference count: 40
- Primary result: MARLIN, a RL-based congestion control algorithm using Soft Actor-Critic, achieves comparable performance to TCP Cubic in real network file transfers with minimal hyperparameter tuning.

## Executive Summary
This paper presents MARLIN, a reinforcement learning approach to congestion control that uses Soft Actor-Critic (SAC) to maximize both entropy and return in an infinite-horizon task. The key innovation is training MARLIN on a real network with varying background traffic patterns to overcome the common sim-to-real mismatch in applying RL to congestion control. The authors demonstrate that MARLIN can achieve performance comparable to TCP Cubic in file transfer tasks, even when evaluated on tasks significantly different from its training setting.

## Method Summary
MARLIN implements a Soft Actor-Critic agent that continuously adjusts the Congestion Window (CWND) size based on network statistics collected from a custom transport protocol called Mockets. The agent is trained on a real dumbbell network topology with background traffic sources and receivers, routers, and switches. Training uses infinite-horizon tasks with strictly negative rewards to encourage efficient task completion. The agent communicates with the transport protocol via gRPC, receiving network statistics and sending CWND adjustments as continuous actions.

## Key Results
- MARLIN achieves comparable file transfer performance to TCP Cubic with minimal hyperparameter tuning
- Training on real networks successfully addresses sim-to-real mismatch common in RL congestion control
- MARLIN generalizes well to tasks different from its training setting, demonstrating robustness

## Why This Works (Mechanism)

### Mechanism 1
- Claim: MARLIN avoids the "sim-to-real" mismatch by training on a real network with background traffic.
- Mechanism: The agent is exposed to real-world network variability, including packet loss and latency, which are hard to simulate accurately. This real-world exposure prevents overfitting to artificial patterns and helps the agent generalize better to unseen network conditions.
- Core assumption: Real-world network traffic is sufficiently varied and unpredictable that training on it provides better generalization than simulation.
- Evidence anchors:
  - [abstract]: "We trained MARLIN on a real network with varying background traffic patterns to overcome the sim-to-real mismatch that researchers have encountered when applying RL to CC."
  - [section]: "A key design point of MARLIN is to be trained and evaluated on real networks. Utilizing real components allowed us to understand the challenges that the CC domain brings to RL, avoiding the risk of failing a 'sim-to-real' transposition."
- Break condition: If the real network does not provide sufficient variability in traffic patterns, the agent might not learn robust policies.

### Mechanism 2
- Claim: The infinite-horizon training with strictly negative rewards enables MARLIN to handle tasks longer than the partial episodes seen during training.
- Mechanism: By not having terminal states and using a strictly negative reward function, the agent learns to minimize cumulative penalties rather than just completing a fixed-length episode. This allows it to adapt to tasks of varying lengths and complexities.
- Core assumption: The strictly negative reward function effectively encodes the principle that each step is a step too much, encouraging the agent to complete tasks efficiently.
- Evidence anchors:
  - [section]: "Training is based on inﬁnite-horizon tasks, never encountering a terminal state and following the Partial Episode Bootstrapping (PEB) principles for inﬁnite-horizon training presented in [12]."
  - [section]: "We designed a reward function that gives higher rewards to the agent the closer it gets to fully utilizing the available bandwidth... A strictly negative reward function promotes the agent to accumulate the smallest amount of penalties."
- Break condition: If the reward function is not carefully designed, the agent might not learn the desired behavior or might become too conservative.

### Mechanism 3
- Claim: The Soft Actor-Critic (SAC) algorithm with continuous actions allows MARLIN to fine-tune the Congestion Window (CWND) size effectively.
- Mechanism: SAC is an off-policy, entropy-regularized RL algorithm that encourages exploration and can handle continuous action spaces. This allows MARLIN to make precise adjustments to the CWND size, which is crucial for congestion control.
- Core assumption: The continuous action space is necessary for fine-tuning the CWND size, and SAC is well-suited for this type of control problem.
- Evidence anchors:
  - [abstract]: "Our solution, MARLIN, uses the Soft Actor-Critic algorithm to maximize both entropy and return and models the learning process as an infinite-horizon task."
  - [section]: "MARLIN adopts SAC [11], an off-policy actor-critic algorithm based on the maximum entropy RL framework."
- Break condition: If the action space is not continuous or if a different RL algorithm is used, the agent might not be able to make the necessary fine adjustments to the CWND size.

## Foundational Learning

- Concept: Markov Decision Process (MDP)
  - Why needed here: CC can be naturally posed as an MDP, where the agent takes actions (adjusting CWND) based on the current state (network conditions) to maximize a reward (network performance).
  - Quick check question: What are the components of an MDP, and how do they apply to the congestion control problem?

- Concept: Entropy regularization in RL
  - Why needed here: Entropy regularization encourages exploration and helps the agent avoid overfitting to specific trajectories. This is crucial for MARLIN to adapt to different network conditions.
  - Quick check question: How does entropy regularization affect the agent's exploration-exploitation trade-off, and why is it important for congestion control?

- Concept: Continuous control in RL
  - Why needed here: MARLIN needs to make fine adjustments to the CWND size, which requires a continuous action space. Continuous control algorithms like SAC are designed for this type of problem.
  - Quick check question: What are the challenges of continuous control in RL, and how does SAC address them?

## Architecture Onboarding

- Component map: Agent (MARLIN/SAC) -> Transport Protocol (Mockets) -> Network -> Agent
- Critical path: Agent receives network statistics from transport protocol -> Agent processes statistics and forms state -> Agent takes action (adjusts CWND) based on state -> Action affects network, cycle repeats
- Design tradeoffs: Training on real network provides better generalization but is slower and more expensive than simulation; continuous actions allow for fine-tuning but increase learning complexity; infinite-horizon training allows handling tasks of varying lengths but requires careful reward shaping
- Failure signatures: Poor convergence or performance could indicate insufficient exploration, poorly designed reward function, or lack of variability in training environment; network instability could result from overly aggressive actions or failure to adapt to changing conditions
- First 3 experiments: 1) Evaluate MARLIN on simple file transfer with fixed background traffic, 2) Test robustness by varying background traffic during evaluation, 3) Compare performance to TCP Cubic on complex topology with multiple competing flows

## Limitations
- Only compared against TCP Cubic, lacking broader evaluation against other congestion control algorithms
- Evaluation limited to file transfer tasks without testing other network scenarios
- Training setup lacks detailed specifications about network conditions, making reproduction challenging

## Confidence

**High Confidence Claims:**
- MARLIN uses Soft Actor-Critic for congestion control in real networks
- The algorithm employs infinite-horizon training with continuous actions
- MARLIN achieves comparable performance to TCP Cubic in file transfers

**Medium Confidence Claims:**
- Training on real networks effectively addresses sim-to-real mismatches
- The entropy-regularized framework provides robustness across different network conditions
- The strictly negative reward function successfully encourages efficient task completion

**Low Confidence Claims:**
- MARLIN would generalize well to significantly different network topologies
- The algorithm would maintain performance with more diverse traffic patterns
- MARLIN would outperform TCP Cubic in all network scenarios

## Next Checks
1. **Expanded Baseline Comparison**: Evaluate MARLIN against multiple congestion control algorithms (BBR, PCC, DCTCP) across various network scenarios beyond file transfers, including latency-sensitive applications and high-bandwidth scenarios.

2. **Stress Testing Network Variability**: Systematically vary network conditions during evaluation, including packet loss rates from 0-10%, RTT variations of ±50ms, and competing flow patterns, to identify performance boundaries and failure modes.

3. **Hyperparameter Sensitivity Analysis**: Conduct ablation studies on key hyperparameters including learning rate, entropy coefficient schedule, and reward function weights to determine their impact on convergence and final performance.
