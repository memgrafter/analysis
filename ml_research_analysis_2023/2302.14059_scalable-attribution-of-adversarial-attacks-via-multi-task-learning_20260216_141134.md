# Scalable Attribution of Adversarial Attacks via Multi-Task Learning

## Quick Facts
- arXiv ID: 2302.14059
- Source URL: https://arxiv.org/abs/2302.14059
- Authors: 
- Reference count: 29
- Key outcome: MTAA framework achieves 99.88% attack algorithm accuracy and 99.52% victim model accuracy on MNIST, and 97.84% attack algorithm accuracy and 97.82% victim model accuracy on ImageNet for adversarial attribution

## Executive Summary
This paper addresses the problem of attributing adversarial examples to their source by identifying three key signatures: attack algorithm, victim model, and hyperparameter. The authors propose a multi-task learning framework (MTAA) that overcomes scalability limitations of existing single-label classification approaches, which suffer from combinatorial explosion as the number of attack algorithms and victim models increases. MTAA employs perturbation extraction, adversarial-only extraction, and classification/regression modules, using uncertainty-weighted loss to balance the three attribution tasks. The framework demonstrates superior performance on MNIST and ImageNet datasets compared to single-task baselines.

## Method Summary
MTAA is a multi-task learning framework that simultaneously recognizes three signatures of adversarial examples: attack algorithm, victim model, and hyperparameter. The framework consists of a perturbation extraction module (auto-encoder trained on feature map differences), an adversarial-only extraction module (ResNet101 feature extractor with task-specific layers), and classification/regression modules. The uncertainty-weighted loss function dynamically adjusts task contributions based on their homoscedastic uncertainty. The approach treats hyperparameter attribution as regression to preserve continuous information, while attack algorithm and victim model recognition are treated as classification tasks.

## Key Results
- MTAA achieves 99.88% attack algorithm accuracy and 99.52% victim model accuracy on MNIST
- MTAA achieves 97.84% attack algorithm accuracy and 97.82% victim model accuracy on ImageNet
- Lower RMSE for hyperparameter regression compared to single-task baselines
- Superior ∆MTL performance metric indicating better multi-task learning efficiency

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Multi-task learning with uncertainty-weighted loss better balances attribution tasks than single-task approaches
- Mechanism: The uncertainty-weighted loss function dynamically adjusts the contribution of each task's loss based on its uncertainty, preventing dominant tasks from overwhelming others during training
- Core assumption: The homoscedastic uncertainty of each task is independent of input data but reflects task-specific noise characteristics
- Evidence anchors:
  - [abstract]: "uses the uncertainty weighted loss to adjust the weights of three recognition tasks"
  - [section]: "uncertainty weighted losses to overall loss function and following maximum likelihood inference"
  - [corpus]: Weak evidence - only general multi-task learning papers in corpus, no specific adversarial attribution multi-task learning papers
- Break condition: If task uncertainties are highly correlated or if one task's uncertainty is consistently orders of magnitude larger than others

### Mechanism 2
- Claim: Perturbation extraction module improves attribution by learning differences between clean and adversarial examples at feature level
- Mechanism: The auto-encoder learns to reconstruct feature maps of adversarial examples while being trained on the difference between clean and adversarial feature maps, capturing perturbation-specific patterns
- Core assumption: Feature-level differences between clean and adversarial examples contain more discriminative information than raw pixel differences
- Evidence anchors:
  - [section]: "The perturbation extraction module leverages information from both clean and adversarial examples"
  - [section]: "we optimize AE by minimizing the loss function: LMSE 1 = 1/n Σj (xfm′j - G(R(xfm′j)) - xfmj)²"
  - [corpus]: Weak evidence - no corpus papers specifically discuss perturbation extraction for attribution
- Break condition: If the feature extractor used (ResNet101) fails to produce sufficiently different feature maps for clean vs adversarial examples

### Mechanism 3
- Claim: Treating hyperparameter attribution as regression rather than classification preserves continuous nature of attack parameters
- Mechanism: Direct regression on hyperparameter values avoids artificial discretization and enables finer-grained attribution of attack intensity
- Core assumption: Hyperparameter values have meaningful continuous relationships rather than being purely categorical
- Evidence anchors:
  - [section]: "hyperparameter recognition should be regarded as regression task"
  - [section]: "We define hyperparameter attribution as a mixed liner regression task"
  - [corpus]: Weak evidence - corpus contains no papers specifically addressing hyperparameter regression in adversarial attribution
- Break condition: If hyperparameter values are inherently discrete or if regression performance is worse than classification with appropriate binning

## Foundational Learning

- Concept: Multi-task learning and task relationship modeling
  - Why needed here: The paper explicitly states that attack algorithm and hyperparameter have an "owner-member relationship" that single-task learning cannot capture
  - Quick check question: Why can't we just train three separate models for attack algorithm, victim model, and hyperparameter instead of using multi-task learning?

- Concept: Uncertainty quantification in deep learning
  - Why needed here: The uncertainty-weighted loss function relies on modeling homoscedastic uncertainty for each task to balance their contributions
  - Quick check question: What does the uncertainty parameter σ represent in the context of the combined loss function?

- Concept: Feature extraction and representation learning
  - Why needed here: The perturbation extraction module uses a pre-trained feature extractor (ResNet101) to obtain feature maps before applying the auto-encoder
  - Quick check question: Why does the paper use feature maps from a deeper layer rather than raw images as input to the auto-encoder?

## Architecture Onboarding

- Component map: Clean and adversarial examples → Feature extraction → Perturbation extraction (for clean+adversarial) → Adversarial-only extraction (for adversarial only) → Concatenation → Classification/regression layers → Three outputs

- Critical path: Clean and adversarial examples → Feature extraction → Perturbation extraction (for clean+adversarial) → Adversarial-only extraction (for adversarial only) → Concatenation → Classification/regression layers → Three outputs

- Design tradeoffs: Multi-task learning reduces parameters and FLOPS compared to separate models but requires careful balancing of task losses; regression for hyperparameters preserves continuous information but may be harder to train than classification

- Failure signatures: 
  - If attack algorithm classification accuracy is much higher than victim model classification, the task-specific layers may not be adequately distinguishing victim models
  - If hyperparameter RMSE is high, the regression layer may need a stronger feature extractor or the uncertainty weighting may be unbalanced
  - If overall performance is poor, the perturbation extraction module may not be learning useful representations

- First 3 experiments:
  1. Train MTAA on MNIST with only two attack algorithms and two victim models to verify basic functionality before scaling up
  2. Compare single-task baseline (separate models for each task) vs MTAA on the same data to verify the claimed multi-task learning benefits
  3. Test MTAA's scalability by incrementally adding attack algorithms and victim models to verify it handles combination explosion better than single-label approaches

## Limitations
- Limited scope of attack algorithms (FGSM, PGD, C&W) and victim models tested, with no ablation study showing performance degradation when scaling beyond these specific combinations
- No comparison with alternative attribution methods that might handle combinatorial explosion differently
- Uncertainty-weighted loss mechanism, while theoretically sound, lacks ablation studies showing the impact of this specific weighting strategy versus equal weighting or other multi-task balancing approaches

## Confidence
- High confidence in MNIST and ImageNet experimental results and the basic multi-task learning framework effectiveness
- Medium confidence in claims about scalability benefits due to limited ablation studies on combinatorial explosion
- Medium confidence in the perturbation extraction mechanism due to lack of comparison with simpler feature extraction approaches
