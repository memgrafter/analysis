# A Technical Report for Polyglot-Ko: Open-Source Large-Scale Korean Language Models

## Quick Facts
- arXiv ID: 2306.02254
- Source URL: https://arxiv.org/abs/2306.02254
- Reference count: 3
- Key outcome: Polyglot-Ko models achieve state-of-the-art performance on Korean NLP tasks, with the 12.8B model scoring highest on the KOBEST benchmark

## Executive Summary
Polyglot-Ko presents a series of large-scale Korean language models developed to address the gap in non-English language performance among multilingual models. The project involved curating 1.2TB of Korean text data and training four models of varying sizes (1.3B, 3.8B, 5.8B, 12.8B parameters). The models were evaluated on the KOBEST benchmark, demonstrating strong performance across tasks such as COPA, HellaSwag, BoolQ, and SentiNeg, with the 12.8B model achieving the highest scores. Results showed that model performance improves with increasing compute and model size, establishing Polyglot-Ko as a leading resource for Korean natural language processing. Limitations include occasional generation errors and data preprocessing issues, which are being addressed in future iterations. The project also aims to expand into multilingual models for East-Asian and Romance languages.

## Method Summary
Polyglot-Ko was developed by curating 1.2TB of Korean text data from diverse sources including blogs, news articles, patents, and social media. The data was processed into 863GB of text and tokenized using morpheme-aware Byte-Pair Encoding with MeCab for morphological analysis. Four models (1.3B, 3.8B, 5.8B, 12.8B parameters) were trained using EleutherAI's GPT-NeoX codebase on A100 GPUs, with training tokens ranging from 213B to 167B depending on model size. Models were evaluated on the KOBEST benchmark using standard metrics like F1-score and accuracy.

## Key Results
- The 12.8B parameter model achieved the highest performance across all KOBEST tasks
- Model performance scales with both parameter count and training compute
- Strong results on COPA, HellaSwag, BoolQ, and SentiNeg tasks demonstrate robust Korean language understanding

- Core assumption: The observed improvements are not due to random chance or overfitting artifacts.

### Mechanism 2
- Claim: Morpheme-aware tokenization improves Korean language understanding compared to byte-level tokenization alone.
- Mechanism: Morphological segmentation captures Korean agglutinative structure, allowing more efficient subword representations.
- Core assumption: The Korean language's morphological complexity necessitates specialized tokenization.
- Evidence anchors:
  - [section 3] "The tokenizer was trained using morpheme-aware Byte-Level BPE...We performed morpheme analysis using MeCab"
  - [abstract] No explicit mention, but implied by focus on Korean-specific modeling
  - [corpus] No direct corpus evidence; requires external linguistic validation
- Break condition: If downstream tasks do not benefit from morphological awareness, simpler tokenization may suffice.

### Mechanism 3
- Claim: Diverse data sources (blogs, news, patents, etc.) improve model generalization across Korean domains.
- Mechanism: Training on varied text types exposes the model to different registers, styles, and vocabularies.
- Core assumption: Domain diversity in training data translates to robust performance across unseen tasks.
- Evidence anchors:
  - [section 2] "1.2TB of Korean data meticulously curated...blog posts 682.3GB, Korean news dataset 87.0GB, Modu corpus 26.4GB..."

## Architecture Onboarding

- Component map: Data preprocessing → Tokenizer (30,003 vocab, morpheme-aware BPE) → Model layers (24-40 transformer blocks) → Loss computation → Checkpointing
- Critical path: 1. Data preprocessing (cleaning, deduplication, de-identification) 2. Tokenization with MeCab + BPE 3. Model initialization and parallel setup 4. Training loop with loss monitoring 5. Checkpoint evaluation and early stopping
- Design tradeoffs:
  - Larger models → better performance but higher resource cost and risk of broken generation
  - More diverse data → better generalization but more preprocessing complexity
  - Morpheme-aware tokenization → better Korean representation but slower tokenization
- Failure signatures:
  - Sharp loss drop near epoch boundary → potential overtraining or overfitting
  - Broken generation (repeated tokens) → training instability
  - Random WiC task performance → task-specific model limitations
- First 3 experiments:
  1. Train 1.3B model with early stopping before loss drop; evaluate on COPA zero-shot
  2. Compare 5.8B vs 12.8B on HellaSwag with 5-shot; verify scaling trend
  3. Test modified SentiNeg prompt on 3.8B model; measure F1 improvement over original prompt

## Open Questions the Paper Calls Out

- How does the performance of Polyglot-Ko models compare to monolingual Korean models when controlling for model size and training compute?
- What is the impact of document structure preservation on Polyglot-Ko's performance, given the preprocessing error that stripped newlines?
- What is the optimal number of training tokens for different model sizes in the Polyglot-Ko series?

## Limitations

- Data preprocessing error stripped newlines, potentially losing document structure information
- WiC task performance shows random results across all model sizes, suggesting task implementation issues
- Broken generation occurs during training, particularly near epoch boundaries

## Confidence

**High confidence** in technical implementation details (model architectures, training setup, data curation pipeline). **Medium confidence** in scaling performance claims due to reliance on external literature rather than internal scaling experiments. **Medium confidence** in data diversity benefits, as the claim is supported by data source diversity but lacks direct performance attribution studies. **Low confidence** in WiC task results given the consistently random performance across all model sizes.
