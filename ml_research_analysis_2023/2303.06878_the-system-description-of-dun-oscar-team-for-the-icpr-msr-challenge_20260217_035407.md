# The System Description of dun_oscar team for The ICPR MSR Challenge

## Quick Facts
- arXiv ID: 2303.06878
- Source URL: https://arxiv.org/abs/2303.06878
- Reference count: 17
- Key outcome: Multimodal subtitle extraction system achieving CERs of 0.1159, 0.2162, and 0.1319 on validation and test sets

## Executive Summary
This paper presents a multimodal system for subtitle extraction from videos using both visual and audio modalities. The system combines three subsystems: visual subtitle extraction using OCR and text tracking, audio subtitle extraction using ASR, and a fusion subsystem that combines results from both modalities. The approach employs SAST detector with CTC-based recognizer for visual processing and a Conformer-based ASR system for audio processing. The fusion mechanism includes filtering, removing, and padding operations to produce final subtitle output. The system demonstrates competitive performance with CERs of 0.1159, 0.2162, and 0.1319 on validation and test sets.

## Method Summary
The proposed system integrates three complementary subsystems for subtitle extraction. The visual subsystem uses SAST (Shape-Aware Scene Text) detector combined with CTC-based recognizer for OCR tasks, along with a subtitle extractor that distinguishes subtitles from other text elements. The audio subsystem employs a Conformer-based ASR system with decoder and language models for speech recognition. The fusion subsystem combines results from both modalities through a three-stage process: filtering to select high-confidence results, removing to eliminate duplicates or incorrect entries, and padding to ensure complete subtitle coverage. The system processes videos by extracting both visual text and audio speech, then merges these parallel streams into coherent subtitle output.

## Key Results
- Visual subsystem achieves CER of 0.1159 on validation set
- Audio subsystem achieves CER of 0.2162 on test set
- Fusion subsystem achieves CER of 0.1319 on test set
- Multimodal approach outperforms single-modality baselines

## Why This Works (Mechanism)
The multimodal approach leverages complementary strengths of visual and audio information. Visual processing captures on-screen text directly, while audio processing extracts spoken dialogue. This redundancy ensures coverage even when one modality fails - for example, when visual subtitles are obscured or audio quality is poor. The fusion mechanism intelligently combines both sources, using filtering to prioritize high-confidence results and removing to eliminate inconsistencies. The padding operation ensures complete temporal coverage of subtitles, addressing gaps that might exist in either individual stream.

## Architecture Onboarding

**Component Map**: Video -> Visual Subsystem (SAST Detector -> CTC Recognizer -> Subtitle Extractor) + Audio Subsystem (Conformer ASR -> Decoder -> Language Models) -> Fusion Subsystem (Filter -> Remover -> Padder) -> Final Subtitles

**Critical Path**: Visual processing and audio processing run in parallel, both feeding into the fusion subsystem. The fusion subsystem's filter stage is typically the bottleneck as it requires cross-referencing both input streams.

**Design Tradeoffs**: The system trades computational complexity for accuracy by running both visual and audio processing simultaneously. This increases resource requirements but provides redundancy for improved robustness. The fusion mechanism adds latency but improves accuracy through cross-modal verification.

**Failure Signatures**: 
- Visual subsystem fails with low-contrast text or motion blur
- Audio subsystem fails with background noise or overlapping speech
- Fusion subsystem fails when both modalities provide conflicting high-confidence results
- Overall system fails when neither modality can reliably extract subtitles

## Open Questions the Paper Calls Out

The paper does not explicitly call out open questions but raises implicit concerns about the system's generalizability. The lack of detailed validation on diverse datasets, the absence of comparison with state-of-the-art baseline methods, and the limited discussion of failure cases all point to areas requiring further investigation. The paper also does not address how the system handles languages other than the training language or how it performs with specialized vocabulary or domain-specific terminology.

## Limitations
