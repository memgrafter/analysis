# Unfolded Self-Reconstruction LSH: Towards Machine Unlearning in Approximate Nearest Neighbour Search

## Quick Facts
- arXiv ID: 2304.02350
- Source URL: https://arxiv.org/abs/2304.02350
- Reference count: 22
- Key outcome: USR-LSH achieves 28-131% improvement in PR-AUC over state-of-the-art data-independent LSH methods while supporting fast online deletion (1.96s vs 81.22s for Scann) without retraining

## Executive Summary
This paper addresses machine unlearning in approximate nearest neighbor (ANN) search by proposing Unfolded Self-Reconstruction LSH (USR-LSH), a data-dependent hashing method that preserves information through self-reconstruction objectives while supporting fast online data deletion. The method unfolds an iterative optimization process into a network architecture using tanh as a proximal function. Experiments on four datasets demonstrate superior precision and recall compared to data-independent LSH methods, with significantly faster deletion times than learning-based approaches while maintaining competitive query performance.

## Method Summary
USR-LSH is a data-dependent LSH method that preserves data information through self-reconstruction objectives while supporting fast online data deletion without retraining. The method unfolds an iterative optimization update for instance-wise data reconstruction into a network architecture, using tanh as a proximal function. The algorithm iteratively applies this proximal operator to solve a relaxed reconstruction objective, which reduces reconstruction error at each step. After deletion, only a single parameter (α) needs recalculation based on the remaining dataset, avoiding expensive retraining required by other data-dependent methods.

## Key Results
- USR-LSH outperforms state-of-the-art data-independent LSH methods in precision and recall with 28-131% improvement in PR-AUC depending on hash code dimensionality
- Achieves significantly faster deletion times (1.96 seconds) compared to learning-based data-dependent methods like Scann (81.22 seconds) and Annoy (291.51 seconds)
- Maintains competitive query performance while supporting online data deletion and insertion without retraining
- Shows consistent improvements across four datasets: Deep1B, SIFT, GloVe-100, and GloVe-25

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Unfolding iterative self-reconstruction updates into a fixed network preserves more data information than random hyperplanes alone.
- Mechanism: The USR-LSH algorithm iteratively applies a proximal operator (tanh) to solve a relaxed reconstruction objective, which reduces reconstruction error at each step. By fixing this unrolled process as a network, the learned hash codes capture dataset-specific structure rather than relying solely on randomness.
- Core assumption: The tanh-based proximal operator effectively approximates the sign function while enabling gradient-based optimization, and that T unrolled iterations provide sufficient capacity for meaningful reconstruction.
- Evidence anchors:
  - [abstract]: "Our USR-LSH unfolded the optimization update for instance-wise data reconstruction, which is better for preserving data information than data-independent LSH."
  - [section 3.1]: "We empirically we find the best value is: α = √md / (2Ex∈X[|x|²])" and "For the α in Equation (9), we empirically we find the best value is..."
  - [corpus]: No direct corpus support found for tanh proximal optimization in LSH; this appears to be novel to the paper.
- Break condition: If T is too small, the network lacks expressive power; if too large, it may overfit or become computationally prohibitive.

### Mechanism 2
- Claim: Instance-wise reconstruction with orthogonal random projections yields more discriminative hash codes than purely random projections.
- Mechanism: The algorithm uses a stacked random rotation matrix W, initialized with orthogonal rows (via SVD on Gaussian matrices). This ensures that the projection space preserves angular relationships, and the self-reconstruction loss further tunes the codes per data point.
- Core assumption: Orthogonal random projections maintain sufficient randomness while providing better geometric preservation than non-orthogonal projections; the self-reconstruction loss doesn't collapse the code space.
- Evidence anchors:
  - [abstract]: "Our USR-LSH unfolded the optimization update for instance-wise data reconstruction, which is better for preserving data information than data-independent LSH."
  - [section 2.2]: "Ji et al. [12] proposed Super-bits LSH (SB-LSH) to improve the random projection hash (simHash)... provides an unbiased estimate of pairwise angular similarity with a smaller variance."
  - [section 3.1]: "The W can be viewed as a decoder matrix that decodes hash code b back to the original data space."
- Break condition: If the orthogonalization step fails to maintain sufficient randomness, or if the reconstruction objective becomes degenerate.

### Mechanism 3
- Claim: Online deletion without retraining is possible because the hash function is data-independent except for the global norm scaling parameter α.
- Mechanism: α is recalculated from the remaining dataset after deletion; the core network weights (random projections) remain fixed. This avoids the expensive retraining step required by learning-based LSH methods.
- Core assumption: α alone is sufficient to adapt to dataset changes; the random projections are robust to the removal of individual points.
- Evidence anchors:
  - [abstract]: "Moreover, our USR-LSH supports fast online data deletion and insertion without retraining."
  - [section 4.6]: "For our USR-LSH, we recalculate the average Euclidean norm Ex∈X[|x|²] of the dataset for setting coefficient α, after each deletion."
  - [corpus]: No direct corpus support; this is the paper's unique contribution to machine unlearning.
- Break condition: If α recalculation does not adequately reflect the new data distribution, or if deletion of too many points invalidates the random projections.

## Architecture Onboarding

- Component map: Input x → Random projection W → T iterations of tanh(αWᵀx + (I - WᵀW)yt-1) → sign(yT) → binary hash code
- Critical path: x → W → T iterations → sign → hash code; deletion → α recalculation
- Design tradeoffs:
  - T vs. precision: Higher T may improve reconstruction but increases latency
  - Hash code length (m) vs. storage: Longer codes improve accuracy but cost more space
  - Randomness vs. learned structure: USR-LSH balances both; pure random LSH is faster but less accurate
- Failure signatures:
  - Precision drops sharply if T is too low or m too short
  - Deletion becomes slow if α recalculation is not optimized
  - Query speed degrades if hash codes are not packed efficiently
- First 3 experiments:
  1. Vary T from 1 to 20 on Deep1B and measure PR-AUC to find sweet spot
  2. Compare query latency vs. precision@10 across m=2,4,8,16 on SIFT
  3. Measure deletion time for 1,5,10,20 points on GloVe-100 and plot scaling

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of USR-LSH compare to other data-dependent methods like Scann and Annoy when evaluated on precision and recall metrics, rather than just deletion time?
- Basis in paper: [inferred] The paper primarily compares USR-LSH to data-independent methods (simHash, SB-LSH) on precision/recall, and to data-dependent methods (Scann, Annoy, Faiss-IVFPQfs) only on deletion time. A comprehensive comparison across all metrics would be valuable.
- Why unresolved: The paper doesn't provide a complete picture of how USR-LSH performs across all relevant metrics when compared to the full range of competing methods.
- What evidence would resolve it: Experimental results showing precision, recall, and query speed for USR-LSH alongside Scann, Annoy, and Faiss-IVFPQfs on the same datasets and parameter settings.

### Open Question 2
- Question: What is the theoretical guarantee for USR-LSH's approximation quality in terms of the trade-off between hash code dimensionality and approximation error?
- Basis in paper: [inferred] While the paper mentions that [16] proved reconstruction error reduction for the optimization framework, it doesn't provide specific bounds or guarantees for USR-LSH's approximation quality in the context of ANN search.
- Why unresolved: The paper establishes that the optimization framework reduces reconstruction error, but doesn't translate this into concrete bounds on ANN search performance.
- What evidence would resolve it: Mathematical analysis deriving bounds on the approximation error as a function of hash code dimensionality, potentially connecting this to recall/precision guarantees.

### Open Question 3
- Question: How does USR-LSH's performance scale with increasing dataset size and dimensionality beyond the tested datasets?
- Basis in paper: [inferred] The paper tests on four datasets ranging from 25 to 128 dimensions and up to 1 million points, but doesn't explore the algorithm's behavior at truly massive scales or in extremely high dimensions.
- Why unresolved: The experimental evaluation, while comprehensive for the tested range, doesn't address the algorithm's behavior at scales where ANN search becomes most challenging.
- What evidence would resolve it: Experiments on larger datasets (billions of points) and higher dimensional data, measuring performance degradation and identifying potential bottlenecks or limitations.

## Limitations

- The method's scalability to extremely high-dimensional data (beyond 100 dimensions) remains untested, as the largest dataset uses only 96 dimensions
- Lack of theoretical guarantees for the unfolded optimization process - no analysis of convergence rates or bounds on approximation error
- Performance may degrade with very large datasets or when many deletions are performed, as α recalculation may not adequately reflect new data distribution
