# Improving Training Stability for Multitask Ranking Models in Recommender Systems

## Quick Facts
- **arXiv ID:** 2302.09178
- **Source URL:** https://arxiv.org/abs/2302.09178
- **Reference count:** 39
- **Primary result:** Clippy algorithm significantly improves training stability for multitask ranking models while maintaining convergence speed

## Executive Summary
This paper addresses a critical problem in recommender systems: training instability in multitask ranking models. While multitask learning improves model performance, it also increases susceptibility to loss divergence, particularly in ranking models that share bottom layers among tasks. The authors propose Clippy, a new clipping algorithm that uses L∞ norm instead of L2 norm and clips based on parameter updates rather than gradients. Clippy demonstrates significant improvements in training stability across multiple model architectures on YouTube production data, outperforming existing methods like Gradient Clipping and Adaptive Gradient Clipping without compromising convergence speed.

## Method Summary
The authors identify that ranking models with multiple objectives are more susceptible to loss divergence than retrieval models due to complex architectures and shared layers among tasks. They propose Clippy, which uses L∞ norm for greater sensitivity to gradient changes and clips based on parameter updates (𝒓𝑡 = 𝒈𝑡 ·𝑮−1/2𝑡) rather than gradients. This approach is particularly effective because Adagrad accumulators modify the relationship between gradients and actual parameter changes. Clippy combines absolute and relative thresholds to adapt its behavior throughout training, switching from Gradient Clipping-style early on to Adaptive Gradient Clipping-style later. The algorithm is implemented in TensorFlow-2 and has been successfully deployed in production models.

## Key Results
- Clippy prevents loss divergence in multitask ranking models where other methods fail
- Maintains convergence speed while significantly improving training stability
- Outperforms baseline methods (Gradient Clipping, Adaptive Gradient Clipping, LAMB) on YouTube production dataset
- Effective across multiple model architectures including Large+DCN with 68M parameters

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Clippy uses L∞ norm instead of L2 norm to detect large gradient changes in individual coordinates, making it more sensitive to sudden divergence.
- Mechanism: By monitoring the maximum absolute update per coordinate (|𝒓𝑡|∞) and clipping when this exceeds a threshold relative to parameter size, Clippy prevents large individual coordinate updates that cause instability.
- Core assumption: Loss curvature changes are more likely to occur in individual coordinates rather than uniformly across all coordinates in multitask ranking models.
- Evidence anchors:
  - [abstract] "Clippy that uses L∞ norm instead of L2 norm to increase sensitivity to gradient changes"
  - [section 4.2] "Clippy uses 𝐿∞ norm instead of 𝐿2 norm to increase its sensitivity to changes in individual coordinates"
  - [corpus] Weak - related papers focus on ranking optimization but don't discuss L∞ vs L2 sensitivity
- Break condition: If loss curvature changes uniformly across coordinates, L∞ may be less effective than L2 norm.

### Mechanism 2
- Claim: Clipping based on parameter updates (𝒓𝑡) rather than gradients (𝒈𝑡) is more effective because Adagrad accumulators modify the relationship between gradients and actual parameter changes.
- Mechanism: Since Adagrad scales gradients by accumulator values (𝑮−1/2𝑡), the actual parameter update differs from the raw gradient. Clipping updates directly controls the real parameter change.
- Core assumption: The relationship between gradients and updates is non-trivial due to Adagrad's adaptive scaling.
- Evidence anchors:
  - [section 4.2] "clips based on updates 𝒓𝑡 = 𝒈𝑡 ·𝑮−1/2𝑡 instead of gradients𝒈𝑡, since updates are the actual change to model parameters"
  - [section 4.3.1] "Clippy relies on updates instead of gradients"
  - [corpus] Weak - related papers discuss adaptive clipping but not specifically update-based clipping in Adagrad
- Break condition: If using optimizers without adaptive scaling (like SGD), gradient-based clipping may be equally effective.

### Mechanism 3
- Claim: Clippy switches between GC-style and AGC-style clipping during training by using both absolute and relative thresholds.
- Mechanism: Early in training when |𝒘| ≈ 0, the absolute threshold dominates, making Clippy behave like GC. Later, when |𝒘| is large, the relative threshold dominates, making it behave like AGC.
- Core assumption: Different training phases require different clipping strategies - aggressive clipping early, adaptive clipping later.
- Evidence anchors:
  - [section 4.2] "Introducing absolute threshold... avoid aggressive clipping when model parameters are zero"
  - [section 4.3.1] "Clippy switches from GC-style to AGC-style during training"
  - [corpus] Weak - related papers don't discuss threshold switching strategies
- Break condition: If training dynamics don't follow this pattern, the switching may be suboptimal.

## Architecture Onboarding

- Component map: Input features → Shared bottom layers → Task-specific heads
- Critical path: Forward pass → Compute loss for each task → Backpropagate gradients → Adagrad accumulator update → Clippy clipping decision → Parameter update
- Design tradeoffs:
  - Per-layer clipping vs global clipping: local gives finer control but may introduce bias
  - L∞ vs L2 norm: L∞ more sensitive to individual coordinate changes but may overreact to outliers
  - Absolute vs relative threshold: absolute prevents aggressive clipping early, relative adapts to parameter scale
- Failure signatures:
  - Loss divergence despite Clippy: clipping threshold too loose or model too unstable
  - Convergence slowdown: clipping threshold too tight, preventing necessary updates
  - Inconsistent performance across runs: sensitivity to initialization or random seeds
- First 3 experiments:
  1. Run Large+DCN model with 2x learning rate, compare Clippy vs naive training - expect Clippy to prevent divergence
  2. Vary 𝜆rel from 0.1 to 1.0, observe clipping factor magnitude and model stability - expect optimal range around 0.5
  3. Apply Clippy to only shared bottom layers vs all layers, compare stability - expect shared layers benefit most from clipping

- Analysis doesn't fully explore interaction between Clippy and different learning rate schedules
- Open-sourced implementation may not capture all production nuances
