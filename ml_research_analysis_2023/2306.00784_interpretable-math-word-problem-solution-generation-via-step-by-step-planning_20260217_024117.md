# Interpretable Math Word Problem Solution Generation Via Step-by-step Planning

## Quick Facts
- arXiv ID: 2306.00784
- Source URL: https://arxiv.org/abs/2306.00784
- Reference count: 40
- Key outcome: A planning-LM approach that predicts mathematical operations to guide language model generation, significantly improving solve rates and interpretability on GSM8K

## Executive Summary
This paper introduces a planning-LM approach for generating step-by-step solutions to math word problems. The method first predicts the next mathematical operation needed using a small classifier, then uses this prediction to guide a language model via carefully-constructed prompts. Experiments on GSM8K demonstrate significant improvements over chain-of-thought baselines in both solve rates and intermediate step quality, with the added benefit of generating multiple valid solution paths for the same problem.

## Method Summary
The approach uses a hierarchical control structure where a small operation predictor classifies the next mathematical operation based on problem context and previous steps, then generates a prompt that guides a language model to produce the next solution step. The system employs asynchronous optimization, first tuning the language model and prompts for step generation, then iteratively alternating between freezing the LM to tune the operation predictor and vice versa. This creates a controllable generation process that produces interpretable intermediate steps while maintaining high solve accuracy.

## Key Results
- Outperforms chain-of-thought baselines on GSM8K across multiple metrics
- Generates multiple correct solution paths for the same problem through different operation prompts
- Achieves higher step quality and interpretability through explicit operation guidance
- Demonstrates effective asynchronous optimization of planning and generation components

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Planning mathematical operations before generation improves intermediate step quality
- Mechanism: A small classifier predicts the next operation based on problem context, then uses this prediction to guide language model generation via prompts
- Core assumption: Mathematical operations can be accurately predicted and provide useful constraints for generation
- Evidence anchors: Operation predictor uses one-layer network with weight wγ to obtain operation score vector for each valid math operation

### Mechanism 2
- Claim: In-context operation prompts provide stronger guidance than traditional chain-of-thought prompting
- Mechanism: Mathematical operations are encoded as special tokens that guide generation, providing concrete constraints
- Core assumption: Operation tokens are more interpretable and controllable than natural language reasoning steps
- Evidence anchors: Planning-GPT-2 outperforms chain-of-thought-tuning GPT-2 on multiple metrics

### Mechanism 3
- Claim: Asynchronous optimization of planning and generation components yields better performance
- Mechanism: The approach first optimizes LM and prompts, then iteratively alternates between freezing LM to tune operation predictor and vice versa
- Core assumption: Operation prediction and step generation have different learning dynamics that benefit from separate optimization phases
- Evidence anchors: Asynchronous optimization leads to better performance than simultaneous optimization

## Architecture Onboarding

- Component map: Problem text → Operation predictor → Operation prompt → Language model → Next step generation (repeats iteratively)
- Critical path: Problem text → Operation predictor → Operation prompt → Language model → Next step generation
- Design tradeoffs: Trades complexity (separate operation predictor) for improved control and interpretability; fixed operation vocabulary limits expressiveness but provides strong guidance
- Failure signatures: Incorrect operation predictions leading to nonsensical steps, language model ignoring operation prompts, prompt vocabulary being too limited
- First 3 experiments:
  1. Test operation prediction accuracy on held-out data to verify planning component works independently
  2. Evaluate step generation quality using ground-truth operation prompts to isolate generation component's performance
  3. Run full end-to-end generation with both components and compare against baseline chain-of-thought approaches on solve rate and step quality metrics

## Limitations
- Reliance on a fixed operation vocabulary that may not cover all possible mathematical operations, limiting scalability to complex problems
- Human evaluation methodology lacks full detail, making it difficult to assess generalizability of interpretability results
- Asynchronous optimization procedure effectiveness could benefit from more thorough ablation studies

## Confidence
- **High Confidence**: Core mechanism of using operation prediction to guide generation is well-supported by experimental results
- **Medium Confidence**: Claim that multiple correct solution paths can be generated through different operation prompts is demonstrated but could benefit from more exploration
- **Low Confidence**: Scalability claims beyond GSM8K dataset and generalizability of human evaluation results to other domains
