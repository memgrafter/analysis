# Using Foundation Models to Detect Policy Violations with Minimal Supervision

## Quick Facts
- arXiv ID: 2306.06234
- Source URL: https://arxiv.org/abs/2306.06234
- Reference count: 14
- Key outcome: Foundation models can detect policy violations with 50-5000 labeled examples while providing structured explanations

## Executive Summary
This paper introduces a method for detecting policy violations using foundation models with minimal supervision. The approach combines hard prompts with chain-of-thought reasoning and extractive explanations, then applies soft prompt tuning to adapt the model to specific tasks. Experiments on toxicity detection show the method achieves strong performance with very small labeled datasets while maintaining consistent explanations. The work demonstrates that foundation models can effectively handle policy violation detection with interpretable outputs using minimal training data.

## Method Summary
The method uses foundation models (62B-540B parameters) with hard prompts containing XML-structured guidelines, examples, and instructions for policy violation detection. Soft prompt tuning is then applied using 50-5000 labeled examples while keeping the foundation model frozen. The hard prompt structure ensures consistent explanation generation even after tuning, allowing the model to produce classifications with extractive justifications. Training uses Adam optimizer with gradient clipping on the soft prompt tokens only.

## Key Results
- Achieves strong performance on toxicity detection with as few as 50 labeled examples
- Accuracy increases gradually and predictably as more training data is added
- Model scores correlate with human ratings, enabling efficient filtering
- Explanations remain consistent and high-quality even after soft prompt tuning
- XML prompt structure prevents tokenization issues that occur with section headings

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Hard prompts with structured XML tags guide model output format reliably
- Mechanism: XML tags eliminate ambiguity in prompt structure, preventing tokenization issues that occur with section headings
- Core assumption: The model has learned to parse XML-style markup during pretraining
- Evidence anchors:
  - "In addition section headings led to tokenization problems (Section 4.5), which we avoid with XML and proper spacing"
  - "We found it effective to use XML-style markup to demarcate the blocks. This eliminates the fragility as we show in Section 4.1"
  - Weak - no external validation of XML parsing behavior

### Mechanism 2
- Claim: Few-shot exemplars act as behavioral guides rather than decision boundary examples
- Mechanism: Adding examples from a class can paradoxically reduce predictions of that class by shifting the exemplar distribution
- Core assumption: Foundation models interpret few-shot examples as prototypical cases to emulate
- Evidence anchors:
  - "Adding examples from a class could reduce the number of times that class is predicted"
  - "In traditional ML, examples determine where the decision boundary is drawn... In contrast, with foundation models, the few examples that we supply, mimic 'exemplars'"
  - Weak - no comparative studies with traditional ML on this behavior

### Mechanism 3
- Claim: Soft prompt tuning preserves structured explanations while adapting classification
- Mechanism: Hard prompt structure remains during tuning, so explanations stay consistent even when classification behavior changes
- Core assumption: The model's generative capacity for structured output is not degraded by soft prompt optimization
- Evidence anchors:
  - "Though the supervision only acts on the classifications, we find that the modified explanations remain consistent with the (tuned) model's response"
  - "However, we would like the tuned model to produce extractive explanations. We therefore include the hard prompt during tuning and inference"
  - Weak - no ablation comparing explanation consistency with/without hard prompt during tuning

## Foundational Learning

- Concept: Chain-of-thought prompting adaptation
  - Why needed here: Policy violation detection requires multi-step reasoning (identify violation type, extract evidence, justify classification)
  - Quick check question: Can you explain why decomposing reasoning into "Citation + Keywords + Explanation" is more effective than a single reasoning chain for this task?

- Concept: Soft prompt vs. fine-tuning distinction
  - Why needed here: Understanding frozen parameters vs. tunable prompt tokens determines training approach and computational budget
  - Quick check question: What is the key difference in how soft prompt tuning vs. traditional fine-tuning affects model parameters?

- Concept: Tokenization sensitivity
  - Why needed here: Small formatting changes (spaces around XML tags) can drastically affect model output and scoring
  - Quick check question: Why does removing spaces around XML tags cause the "Yes"/"No" probability sum to deviate from 1.0?

## Architecture Onboarding

- Component map: Foundation model (62B-540B parameters) ← Hard prompt (XML-structured guidelines + examples) ← Soft prompt tokens (100 tokens for 62B, 40 for 540B) ← Training dataset (50-5000 examples)
- Critical path: Prompt design → Dataset sampling → Soft prompt initialization → Training with frozen foundation model → Evaluation and iteration
- Design tradeoffs: Larger soft prompts allow more expressive tuning but increase training cost; more training examples improve accuracy but reduce benefit of minimal supervision approach
- Failure signatures: Inconsistent XML output structure, degradation of explanation quality, unexpected class probability shifts when adding exemplars
- First 3 experiments:
  1. Ablation: Remove XML tags, replace with section headings, measure tokenization and output consistency
  2. Scaling: Train with 50, 500, and 5000 examples, plot accuracy vs. training size
  3. Exemplar effect: Add extreme violation example, measure impact on overall violation prediction rate

## Open Questions the Paper Calls Out
The paper explicitly states that the method has only been evaluated for English language text and has not been tested on adversarial behavior or attempts to circumvent the policy detection.

## Limitations
- Evaluated only on toxicity detection from a single dataset, limiting generalizability to other policy violation types
- Results depend on proprietary 62B-540B parameter models that are not publicly available
- No evaluation of explanation quality from human perspective or real-world deployment scenarios

## Confidence

**High Confidence**: The core mechanism that hard prompts with XML tags produce structured outputs more reliably than section headings. This is directly demonstrated with quantitative evidence showing probability distribution failures when XML spacing is removed.

**Medium Confidence**: The claim that soft prompt tuning preserves explanation quality while improving classification accuracy. While demonstrated on the toxicity task, the mechanism's generalizability to other policy violation types needs validation.

**Low Confidence**: The broader claim that this approach enables "minimal supervision" policy violation detection in production settings. The paper provides no evidence about real-world deployment, cost-benefit analysis, or comparison with existing production systems.

## Next Checks
1. Evaluate the method on at least two additional policy violation types (e.g., harassment and spam detection) using the same 50-5000 example training regime. Compare accuracy and explanation quality across tasks to assess generalizability.

2. Implement the approach using a publicly available large language model (e.g., LLaMA-7B or OPT-13B) with equivalent parameter count. Measure whether the XML prompt structure and soft prompt tuning mechanism still produce reliable outputs.

3. Conduct a user study where annotators rate the quality, accuracy, and usefulness of explanations generated by the tuned model versus the few-shot baseline. Include metrics for explanation clarity, relevance to the decision, and actionable insights.
