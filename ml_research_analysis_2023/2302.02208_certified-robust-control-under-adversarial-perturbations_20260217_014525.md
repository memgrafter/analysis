# Certified Robust Control under Adversarial Perturbations

## Quick Facts
- arXiv ID: 2302.02208
- Source URL: https://arxiv.org/abs/2302.02208

## Executive Summary
This paper addresses the critical problem of adversarial attacks on autonomous systems that rely on machine learning for perception. The authors propose a novel framework that composes certified robustness of predictions (via randomized or percentile smoothing) with robust control algorithms to obtain end-to-end robustness guarantees. The key insight is that by obtaining prediction certificates about system parameters under adversarial perturbations, one can leverage robust control algorithms to maintain system stability despite these perturbations. The approach is evaluated on an adaptive vehicle control case study, demonstrating significantly improved stability and efficiency compared to non-robust baselines in malicious attack scenarios.

## Method Summary
The proposed method combines certified prediction robustness with robust control in a three-layer architecture. First, a perception model maps raw inputs to predicted system parameters. Second, a certification layer applies randomized smoothing (for classification) or percentile smoothing (for regression) to obtain prediction certificates - uncertainty intervals around parameter estimates that hold with high probability under adversarial perturbations. Third, a robust control algorithm (L1 adaptive control) uses these uncertainty intervals to compute control signals that maintain system stability despite the bounded parameter uncertainty. The certification layer provides probabilistic bounds on adversarial perturbations that preserve prediction invariance, while the robust control algorithm ensures stability when parameters remain within these certified bounds.

## Key Results
- Demonstrated significant improvement in vehicle stability during adversarial attacks compared to non-robust baseline
- Achieved certified robustness bounds on adversarial perturbation magnitude using randomized/percentile smoothing
- Showed that the composition of prediction certificates with L1 adaptive control maintains system stability in malicious environments
- Validated approach across multiple datasets (Carla, Road Traversing Knowledge, robotCar) with different weather and road surface conditions

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Randomized smoothing can provide probabilistic guarantees about classification invariance under adversarial perturbations.
- Mechanism: By adding isotropic Gaussian noise γ to input x and observing classification changes, we estimate the probability that a perturbed input x+δ stays within a "safe" label set S(l).
- Core assumption: The classification function f is Lipschitz continuous with respect to the ℓ₂ norm of perturbations.

- Break condition: If the Lipschitz constant assumption fails (e.g., neural network has non-smooth activations or architecture), the bound becomes invalid.

### Mechanism 2
- Claim: The combination of certified prediction intervals with robust control algorithms yields end-to-end robustness guarantees.
- Mechanism: Uncertainty about system parameters (y) derived from perturbed inputs is bounded by prediction certificates; robust control algorithms (like L1 adaptive control) use these bounds to maintain stability despite uncertainty.
- Core assumption: The robust control algorithm A is guaranteed to stabilize the system when parameters are within a known bounded interval [C, C].
- Evidence anchors:
  - [abstract] "composing robustness certification of predictions with respect to raw input perturbations with robust control to obtain certified robustness of control"
  - [section] Theorem IV.1 and IV.2 formally show how prediction certificates translate to control robustness
  - [corpus] Weak: corpus neighbors discuss certified robustness but not the composition with control algorithms
- Break condition: If the prediction interval is too loose (large uncertainty), the control algorithm may degrade performance or become conservative (e.g., drive very slowly).

### Mechanism 3
- Claim: The safe set S(l) concept allows relaxing strict prediction invariance to more practical robustness.
- Mechanism: Not all prediction errors are equally consequential; by defining which misclassifications are "safe," we can tolerate certain adversarial perturbations that don't significantly affect system safety.
- Core assumption: There exists a meaningful partition of prediction space into safe and unsafe sets that correlates with control stability.
- Evidence anchors:
  - [abstract] "not all errors are equally consequential (some may destabilize the system, whereas others will not significantly change stability)"
  - [section] Definition of safe sets: "if the true label is that the weather is sunny, predicting that it is rainy is 'safe' in the sense that it would cause the controller to only be more conservative"
  - [corpus] Weak: corpus neighbors don't discuss safe set concepts in control contexts
- Break condition: If the safe set definition is incorrect or incomplete, adversarial perturbations could lead to unsafe control decisions.

## Architecture Onboarding

- Component map: Perception pipeline (x → f → y) → Certification layer (f(x) → g(x)/h*(x) → [C, C]) → Control layer ([C, C] → A([C, C]) → π(t)) → System dynamics (π(t) + uncertainty → s(t) → o(t))
- Critical path: x → g(x)/h*(x) → [C, C] → A([C, C]) → π(t) → system stability
- Design tradeoffs:
  - Noise variance v² in smoothing: Higher variance increases robustness radius but decreases accuracy
  - Adaptation gain Γ in L1 control: Higher gain improves tracking but reduces robustness to unmodeled dynamics
  - Safe set definition: Tighter safe sets increase safety but reduce the effective robustness radius
- Failure signatures:
  - System instability despite certification: Prediction interval too loose or safe set incorrectly defined
  - Overly conservative control (very slow driving): Robustness margin too large relative to actual uncertainty
  - Prediction accuracy degradation: Noise variance in smoothing too high

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Can the proposed framework be extended to handle continuous-time adversarial perturbations, rather than discrete adversarial perturbations?
- Basis in paper: [inferred] The paper focuses on discrete adversarial perturbations, but the system dynamics are described using continuous-time differential equations.
- Why unresolved: The paper does not explore the theoretical or practical implications of continuous-time perturbations, which could be more realistic in certain scenarios.
- What evidence would resolve it: Theoretical analysis of the robustness properties under continuous-time perturbations, and experimental validation on systems with continuous-time dynamics.

### Open Question 2
- Question: How does the performance of the proposed method scale with the dimensionality of the input space (e.g., high-resolution images)?
- Basis in paper: [explicit] The paper mentions that the input space is high-dimensional (e.g., camera frames), but does not provide detailed analysis of how performance scales with dimensionality.
- Why unresolved: The computational complexity and robustness guarantees may degrade as the input space dimensionality increases, but this is not explicitly addressed.
- What evidence would resolve it: Empirical studies on systems with increasingly higher-dimensional inputs, and theoretical bounds on performance degradation with dimensionality.

### Open Question 3
- Question: Can the safe set of labels (S(l)) be learned automatically rather than manually defined, and how would this affect the robustness guarantees?
- Basis in paper: [explicit] The paper manually defines safe sets for labels in the classification setting, but does not explore automated learning of these sets.
- Why unresolved: Manual definition of safe sets may not be scalable or optimal for complex systems, and automated learning could improve adaptability but may introduce new challenges in maintaining robustness.
- What evidence would resolve it: Development and evaluation of algorithms for learning safe sets from data, and analysis of the impact on robustness guarantees and system performance.

## Limitations

- The certified robustness bounds rely on strong Lipschitz continuity assumptions for the perception model, which may not hold for complex neural networks in practice.
- The composition of certified prediction with robust control assumes perfect knowledge of control system dynamics, which is rarely true in real-world autonomous systems.
- The empirical evaluation on Carla simulator provides suggestive evidence but lacks comprehensive benchmarking against alternative robust control approaches.

## Confidence

- High confidence: The theoretical framework connecting randomized smoothing to prediction certificates is well-established in the literature and correctly applied here.
- Medium confidence: The composition of prediction certificates with L1 adaptive control is theoretically sound, but practical implementation challenges may affect real-world performance.
- Low confidence: The empirical evaluation on Carla simulator provides suggestive evidence but lacks comprehensive benchmarking against alternative robust control approaches.
