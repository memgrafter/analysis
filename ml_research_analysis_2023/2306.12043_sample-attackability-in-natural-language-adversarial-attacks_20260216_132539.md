# Sample Attackability in Natural Language Adversarial Attacks

## Quick Facts
- arXiv ID: 2306.12043
- Source URL: https://arxiv.org/abs/2306.12043
- Reference count: 7
- Primary result: Deep learning-based detector outperforms uncertainty-based approaches for identifying attackable samples, but attackability is heavily method-dependent

## Executive Summary
This paper addresses the problem of identifying which natural language samples are most susceptible to adversarial attacks by extending the concept of sample attackability from computer vision to NLP. The authors define attackability as the minimum perturbation size required to change a sample's output prediction, then propose a deep learning-based detector that can identify the most attackable and robust samples for an unseen target model. Experiments on two NLP datasets, four state-of-the-art models, and four different adversarial attack methods demonstrate that the detector significantly outperforms uncertainty-based approaches in identifying attackable samples.

## Method Summary
The paper defines sample attackability in NLP as the minimum perturbation size needed to successfully attack a sample while maintaining imperceptibility constraints. A deep learning-based detector is trained as a binary classifier using encoder embeddings from seen models to predict the probability of a sample being attackable. The detector uses a simple single hidden-layer fully connected network architecture and is evaluated across different settings (matched, specific, vspecific, universal) to assess its ability to identify attackable and robust samples for both known and unknown attack methods.

## Key Results
- Deep learning-based detector significantly outperforms uncertainty-based approaches (conf-u, conf-s) in matched settings
- Attackability detection shows limited portability across different attack methods due to inconsistent imperceptibility constraints
- The detector performs best when attack methods share similar pre-transformation constraints

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Sample attackability is well-defined in NLP by using minimum perturbation size required to change output prediction.
- Mechanism: Uses imperceptibility constraints to define what counts as a valid adversarial example; then measures attackability by finding smallest distance constraint that produces a successful adversarial example.
- Core assumption: NLP imperceptibility constraints (pre-transformation and distance-based) are consistent and meaningful across different attack methods.
- Evidence anchors:
  - [abstract]: "This work formally extends the definition of sample attackability/robustness for NLP attacks."
  - [section 4]: Defines attackability as minimum perturbation size using distance-based proxy function.
  - [corpus]: Weak evidence - only 25 related papers, none directly citing this work yet, FMR average 0.518 suggests moderate relevance.
- Break condition: If different attack methods have non-overlapping available sets of adversarial examples, attackability becomes method-dependent rather than intrinsic to the sample.

### Mechanism 2
- Claim: Deep learning-based detector outperforms uncertainty-based approaches for identifying attackable samples.
- Mechanism: Trains binary classifier using encoder embeddings from seen models to predict probability of sample being universally attackable across those models.
- Core assumption: Encoder embeddings capture features relevant to attackability that correlate across different models.
- Evidence anchors:
  - [abstract]: "Experiments... demonstrate that sample uncertainty is insufficient... and hence a deep learning based detector can perform much better..."
  - [section 6.2]: Shows F1 scores for deep detector significantly higher than conf-u and conf-s in matched setting.
  - [corpus]: No direct support - this is novel contribution not well-established in related work.
- Break condition: If encoder embeddings don't capture attack-relevant features, or if attackability is too method-specific, detector performance degrades.

### Mechanism 3
- Claim: Lack of portability across attack methods stems from differences in imperceptibility constraints.
- Mechanism: Different attack methods have different pre-transformation constraints creating non-overlapping sets of valid adversarial examples for the same sample.
- Core assumption: Pre-transformation constraints fundamentally shape which adversarial examples are possible, making attackability method-dependent.
- Evidence anchors:
  - [section 6.3]: "it can be argued that an inconsistency in sample attackability across nlp adversarial attack methods is a consequence of the differences in the pre-transformation imperceptibility constraints."
  - [table 2]: Shows different attack methods have different pre-transformation constraints.
  - [corpus]: No direct evidence - this explanation is novel inference from experimental observations.
- Break condition: If attack methods shared identical pre-transformation constraints, portability might be achievable.

## Architecture Onboarding

- Component map: Text samples + encoder embeddings from seen models → Binary classification network → Probability of attackability/robustness
- Critical path: Sample → Encoder embedding → Binary classifier → Attackability probability → Thresholded decision
- Design tradeoffs:
  - Simple vs complex classifier architecture (single layer chosen for efficiency)
  - Universal vs model-specific attackability detection (universal preferred for portability)
  - Strict vs lenient thresholds for attackability/robustness (strict for attackable, lenient for robust)
- Failure signatures:
  - Poor performance on unseen attack methods (method-dependence)
  - High false positives/negatives at default thresholds
  - Sensitivity to embedding quality from seen models
- First 3 experiments:
  1. Train and evaluate detector on matched setting (known attack method) to establish baseline performance
  2. Test detector on unseen attack method to assess portability limitations
  3. Analyze correlation of perturbation sizes across different attack methods to understand method-dependence

## Open Questions the Paper Calls Out

## Limitations
- Attackability detection methods fail to port across different attack methods due to inconsistent imperceptibility constraints
- Limited evaluation scope with only two datasets and four specific attack methods
- Method-dependence prevents universal attackability assessment

## Confidence
- **High Confidence**: Deep learning-based detector significantly outperforms uncertainty-based approaches in matched settings
- **Medium Confidence**: Explanation that pre-transformation constraints cause method-dependence is an inference from observed behavior
- **Low Confidence**: Universal applicability of attackability definition across all NLP tasks and attack methods
