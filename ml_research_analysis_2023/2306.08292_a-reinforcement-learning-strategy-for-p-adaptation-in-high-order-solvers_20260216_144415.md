# A reinforcement learning strategy for p-adaptation in high order solvers

## Quick Facts
- arXiv ID: 2306.08292
- Source URL: https://arxiv.org/abs/2306.08292
- Reference count: 35
- Primary result: RL strategy achieves 90% reward accuracy compared to optimal solutions and 3.56s vs 4.76s computational speedup

## Executive Summary
This paper introduces a reinforcement learning approach for p-adaptation in high-order discontinuous Galerkin solvers. The methodology uses Proximal Policy Optimization to train an agent that dynamically adjusts polynomial orders in mesh elements based on solution characteristics. A key innovation is the decoupling of training from simulation, using randomly generated sinusoidal functions instead of solving PDEs during training. The approach introduces a control parameter δ that allows users to prioritize either computational efficiency or solution accuracy, providing flexibility for different application requirements.

## Method Summary
The RL agent is trained using Proximal Policy Optimization (PPO) with an actor-critic architecture. Training uses a random function generator to create sinusoidal-type functions in one element, allowing the agent to learn optimal polynomial order selection without solving PDEs. The state is defined by the current polynomial degree and error estimate between consecutive polynomial orders. The reward function combines accuracy (exponential decay with RMSE) and computational cost (quadratic function of polynomial order) terms. During testing, the trained agent operates on the 1D inviscid Burgers' equation with periodic boundary conditions, dynamically adapting polynomial orders to balance accuracy and computational cost.

## Key Results
- RL strategy achieves 90% reward accuracy compared to optimal solutions
- Computational speedup of 3.56s vs 4.76s for 8-element simulations
- Maintains or improves solution accuracy while reducing computational cost
- Successfully demonstrates flexible control between accuracy and efficiency via parameter δ

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The RL agent learns to balance accuracy and computational cost by optimizing polynomial orders in mesh elements.
- Mechanism: The reward function combines an accuracy term (exponential decay with rmse) and a cost term (quadratic function of polynomial order), allowing the agent to prioritize lower polynomial orders when accuracy permits.
- Core assumption: The error estimation between consecutive polynomial orders provides a reliable proxy for solution accuracy.
- Evidence anchors: [abstract] "The methodology formulates appropriate reward structures that balance accuracy and computational cost", [section 2.2.3] "We define the reward as the objective function that the agent should learn to decide the best course of action based on the current state", [corpus] Weak - no direct comparison to other error estimation methods
- Break condition: If the error estimation method fails to accurately capture solution accuracy, the agent may make suboptimal decisions.

### Mechanism 2
- Claim: The PPO algorithm provides stable training through conservative policy updates.
- Mechanism: PPO uses a surrogate objective function with a clip function to limit policy updates, preventing large deviations from the previous policy and ensuring stability during training.
- Core assumption: The clip function effectively prevents policy divergence while allowing sufficient exploration.
- Evidence anchors: [section 2.2.1] "PPO belongs to the class of policy optimisation algorithms and is designed to strike a balance between exploration and exploitation", [section 2.2.1] "PPO introduces a clip function that limits the policy update to a specified range, preventing large deviations from the previous policy", [corpus] Weak - no comparison to other RL algorithms
- Break condition: If the clip function is too restrictive, it may prevent the agent from finding optimal policies.

### Mechanism 3
- Claim: Decoupling training from simulation improves efficiency and allows use of analytical solutions.
- Mechanism: Training uses randomly generated sinusoidal functions instead of solving PDEs, allowing faster iterations and use of known analytical solutions for reward calculation.
- Core assumption: Randomly generated sinusoidal functions adequately represent the solution characteristics needed for effective training.
- Evidence anchors: [section 2.2.4] "To tackle both problems, in this work we propose to decouple the training process of the RL agent from the simulation", [section 2.2.4] "The training is performed using a random function generator, which provides random sinusoidal-type functions in one element", [corpus] Weak - no validation that this approach transfers well to real PDEs
- Break condition: If the random functions do not adequately represent the solution characteristics of real PDEs, the trained agent may not generalize well.

## Architecture Onboarding

- Component map:
  RL Agent (PPO-based) -> DGSEM Solver -> State Calculator (polynomial order and error estimation) -> Reward Calculator (rmse and polynomial order) -> Random Function Generator (for training)

- Critical path:
  1. Generate random function for training or set up PDE for testing
  2. Initialize polynomial order and compute initial state
  3. Agent selects action based on current state
  4. Apply action and compute new state and reward
  5. Update agent policy (training) or apply adaptation (testing)

- Design tradeoffs:
  - Accuracy vs. computational cost: Controlled by parameter δ
  - Training efficiency vs. generalization: Decoupled training allows faster iterations but may not fully capture PDE-specific characteristics
  - Error estimation complexity vs. reliability: Simple error estimation is fast but may not capture all relevant solution features

- Failure signatures:
  - Agent consistently selects sub-optimal polynomial orders
  - Training does not converge or converges to poor policies
  - Adaptation causes instability in the numerical solver
  - Computational cost increases without corresponding accuracy improvements

- First 3 experiments:
  1. Test the RL agent on the 1D inviscid Burgers' equation with a fixed mesh (8 elements) and compare results with uniform adaptation
  2. Vary the control parameter δ to observe its effect on the accuracy-computational cost tradeoff
  3. Test the RL agent on different mesh resolutions (4 and 16 elements) to evaluate its adaptability to mesh size changes
