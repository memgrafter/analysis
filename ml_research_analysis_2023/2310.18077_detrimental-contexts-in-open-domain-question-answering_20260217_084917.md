# Detrimental Contexts in Open-Domain Question Answering

## Quick Facts
- arXiv ID: 2310.18077
- Source URL: https://arxiv.org/abs/2310.18077
- Reference count: 14
- Primary result: 10% improvement in exact match scores using 20x smaller context

## Executive Summary
This paper investigates the phenomenon of "damaging contexts" in open-domain question answering systems, where adding more relevant passages to the input can actually degrade model performance. The authors analyze how the FiD reader model interacts with retrieved passages and identify cases where additional context leads to incorrect predictions. They propose a method to identify and remove these detrimental passages by incrementally adding passages to the input and tracking changes in the model's output. By filtering out damaging passages, they achieve up to 10% improvement in exact match scores on NQ and TriviaQA datasets using subsets of context that are 20 times smaller.

## Method Summary
The authors propose an incremental filtering approach to identify and remove detrimental passages from retrieved context. The method works by sequentially adding passages to the input and monitoring how the model's output changes with each addition. When a passage causes the model to switch from a correct to an incorrect prediction, it is flagged as damaging and removed. This process continues until all passages have been evaluated. The filtered context, which is typically much smaller than the original retrieved set, is then used for final answer generation. The approach leverages the FiD reader architecture's ability to process multiple passages and track confidence scores at each step.

## Key Results
- 10% improvement in exact match scores on NQ and TriviaQA datasets
- Context reduction by factor of 20x while maintaining or improving performance
- Demonstrated effectiveness across different passage set sizes (3/5/7 passages)

## Why This Works (Mechanism)
The mechanism relies on the FiD reader's ability to maintain and update internal confidence scores as passages are processed sequentially. When a detrimental passage is introduced, it disrupts the model's reasoning process, causing a shift in the predicted answer. By tracking these confidence score changes, the system can identify the precise passages that cause performance degradation. This approach exploits the fact that the FiD architecture processes passages in order and can maintain state throughout the reasoning process, making it sensitive to the introduction of conflicting or confusing information.

## Architecture Onboarding

**Component Map:**
Retriever -> Passage Set -> FiD Reader (incremental processing) -> Confidence Tracking -> Filtered Passages -> Answer Generation

**Critical Path:**
Passage retrieval → Incremental FiD processing → Confidence score monitoring → Detrimental passage identification → Answer generation from filtered context

**Design Tradeoffs:**
- Computational cost vs. accuracy: The method adds processing overhead for incremental evaluation but reduces overall computation by using smaller context
- Precision vs. recall: Aggressive filtering might remove beneficial context along with detrimental passages
- Sequential vs. parallel processing: Incremental approach requires ordered processing but enables fine-grained monitoring

**Failure Signatures:**
- Over-filtering leading to loss of relevant context
- Incorrect identification of damaging passages due to model uncertainty
- Performance degradation when context reduction is too aggressive
- Limited effectiveness on questions requiring multi-hop reasoning

## Limitations
- Analysis is primarily empirical without theoretical explanations for why detrimental contexts occur
- Results may not generalize to other QA architectures beyond FiD
- The 3/5/7 passage set sizes may not capture the full spectrum of detrimental context scenarios
- Limited testing across diverse question types and domains

## Confidence

**Major Claim Clusters:**
- **High confidence**: The existence of detrimental contexts in retrieval-augmented QA systems is clearly demonstrated through controlled experiments
- **High confidence**: The proposed incremental filtering method effectively identifies and removes damaging passages
- **Medium confidence**: The 10% improvement and 20x context reduction represent robust findings within the tested dataset constraints
- **Low confidence**: Generalizability to other QA architectures and domains beyond the specific experimental setup
