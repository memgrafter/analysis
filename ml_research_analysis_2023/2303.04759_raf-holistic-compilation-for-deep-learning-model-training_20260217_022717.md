# RAF: Holistic Compilation for Deep Learning Model Training

## Quick Facts
- arXiv ID: 2303.04759
- Source URL: https://arxiv.org/abs/2303.04759
- Reference count: 40
- RAF is a deep learning compiler designed for efficient training workloads, addressing the gap in existing compilers that primarily target inference.

## Executive Summary
RAF is a novel deep learning compiler specifically designed for training workloads, addressing the gap left by existing compilers that primarily focus on inference. Unlike traditional approaches, RAF generates a complete training graph encompassing forward propagation, loss computation, backward propagation, and optimizer updates, enabling holistic optimizations. Through a three-phase graph optimization strategy and an operator dialect mechanism, RAF achieves significant performance improvements in training throughput and batch size support while maintaining numerical correctness.

## Method Summary
RAF introduces a comprehensive approach to deep learning training compilation through three key phases: graph generation, expression optimization, and execution order optimization. The compiler generates the entire training graph automatically, including forward pass, loss computation, backward pass, and optimizer updates. This holistic view enables cross-stage optimizations that traditional compilers cannot achieve. The three-phase optimization strategy systematically improves performance: first by generating an optimized graph structure, then by fusing and simplifying operations, and finally by optimizing execution order through memory planning and rematerialization. Additionally, RAF's operator dialect mechanism allows seamless integration of diverse kernel libraries and tensor compilers, ensuring optimal performance across different hardware platforms.

## Key Results
- Achieves better training throughput or supports larger batch sizes compared to PyTorch (eager and torchscript modes), XLA, and DeepSpeed
- Maintains numerical correctness while delivering performance improvements
- Demonstrated effectiveness on popular transformer models (BERT, RoBERTa, GPT-2) running on GPUs

## Why This Works (Mechanism)
RAF's effectiveness stems from its holistic approach to training compilation. By generating the complete training graph in one pass, it can perform cross-stage optimizations that are impossible when treating forward and backward passes separately. The three-phase optimization strategy systematically addresses different aspects of performance: graph generation ensures the fundamental structure is optimal, expression optimization reduces computational overhead through fusion and simplification, and execution order optimization minimizes memory usage and maximizes hardware utilization. The operator dialect mechanism further enhances performance by allowing the compiler to select the most appropriate kernel implementations for each operation based on the target hardware.

## Foundational Learning

**Automatic Differentiation**: Needed to automatically generate backward pass from forward computation graph. Quick check: Verify gradients match analytical derivatives for simple functions.

**Operator Fusion**: Needed to combine multiple operations into single kernels, reducing memory transfers and overhead. Quick check: Compare execution time of fused vs. unfused operations.

**Memory Planning**: Needed to efficiently allocate and reuse memory buffers during training. Quick check: Monitor memory usage during different phases of training.

**Rematerialization**: Needed to trade computation for memory by recomputing intermediate values instead of storing them. Quick check: Measure memory savings vs. computational overhead.

**Automatic Mixed Precision**: Needed to leverage lower precision computations where possible for performance gains. Quick check: Verify numerical accuracy is preserved.

## Architecture Onboarding

**Component Map**: User Code -> Graph Generator -> Expression Optimizer -> Execution Optimizer -> Runtime -> Hardware

**Critical Path**: The critical path flows from user code through the three optimization phases to the runtime system, with each phase building upon optimizations from previous stages.

**Design Tradeoffs**: Memory vs. computation trade-offs in rematerialization, precision vs. performance in automatic mixed precision, and optimization complexity vs. compilation time.

**Failure Signatures**: Numerical instability in automatic mixed precision, memory exhaustion during execution order optimization, and incorrect gradient computation from graph generation errors.
