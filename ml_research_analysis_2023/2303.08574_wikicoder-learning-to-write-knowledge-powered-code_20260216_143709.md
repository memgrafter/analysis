# WikiCoder: Learning to Write Knowledge-Powered Code

## Quick Facts
- arXiv ID: 2303.08574
- Source URL: https://arxiv.org/abs/2303.08574
- Reference count: 28
- Introduces knowledge-powered program synthesis that integrates knowledge graphs with machine-learned program synthesizers

## Executive Summary
WikiCoder presents a novel approach to program synthesis that leverages external knowledge graphs to solve tasks that traditional input-output examples cannot address. The system introduces a three-component architecture that compiles domain-specific languages into context-free grammars, preprocesses input to extract entities and generate SPARQL queries, and uses a prediction model to guide program search. Evaluated across 46 tasks spanning different domains, WikiCoder successfully solves 18 tasks by enabling programs to reference external knowledge, outperforming state-of-the-art models like Codex and GPT-3 on knowledge-intensive problems while maintaining competitive performance on classical synthesis tasks.

## Method Summary
WikiCoder extends traditional program synthesis by incorporating knowledge graphs through a three-component architecture. The system first compiles domain-specific languages into context-free grammars to enable systematic program search. It then preprocesses input strings to extract relevant entities and generate SPARQL queries to retrieve supporting facts from knowledge graphs. Finally, a prediction model guides the search through the program space, enabling the synthesis of programs that can reference external knowledge. This approach allows solving tasks where input-output examples alone are insufficient, such as extracting information that requires external knowledge or performing calculations based on known facts.

## Key Results
- Successfully solves 18 out of 46 tasks across diverse domains, demonstrating capability to handle preprocessing and relationship complexity
- Outperforms Codex and GPT-3 on knowledge-powered tasks while maintaining competitive performance on classical FlashFill problems
- Demonstrates that knowledge graphs enable solving previously unsolvable program synthesis tasks

## Why This Works (Mechanism)
WikiCoder works by bridging the gap between traditional program synthesis and external knowledge sources. The system leverages knowledge graphs to provide contextual information that cannot be inferred from input-output examples alone. By preprocessing inputs to identify relevant entities and query knowledge graphs via SPARQL, WikiCoder can synthesize programs that incorporate external facts and relationships. The prediction model guides efficient search through the program space by leveraging patterns learned from training data, while the compilation of domain-specific languages into context-free grammars enables systematic exploration of possible programs.

## Foundational Learning

**Knowledge Graphs** - Structured representations of facts and relationships between entities
*Why needed:* Provide external context and facts that cannot be inferred from examples alone
*Quick check:* Can represent complex relationships like "capital of country" or "author of book"

**SPARQL Queries** - Query language for retrieving data from knowledge graphs
*Why needed:* Enables systematic extraction of relevant facts from knowledge graphs based on entity recognition
*Quick check:* Supports pattern matching and filtering across multiple properties

**Context-Free Grammars** - Formal grammar systems for defining program syntax
*Why needed:* Enables systematic enumeration and search through possible programs in a structured way
*Quick check:* Can be compiled from domain-specific languages to support efficient synthesis

## Architecture Onboarding

**Component Map:** Input Preprocessing -> SPARQL Query Generation -> Prediction Model -> Program Search -> Output

**Critical Path:** Input string → Entity Recognition → SPARQL Query → Knowledge Graph Retrieval → Program Synthesis → Program Execution

**Design Tradeoffs:** 
- Knowledge graph integration enables solving complex tasks but adds dependency on external data quality
- Three-component decomposition enables modularity but introduces potential failure cascades
- SPARQL-based approach provides flexibility but requires well-structured knowledge sources

**Failure Signatures:**
- Preprocessing failures when entity recognition is ambiguous or spans multiple contexts
- SPARQL query failures when knowledge graphs lack required facts or have inconsistent structure
- Prediction model inaccuracies leading to inefficient program space exploration

**3 First Experiments:**
1. Test entity recognition accuracy on diverse input formats to characterize preprocessing robustness
2. Measure SPARQL query performance across different knowledge graph schemas to identify structural dependencies
3. Evaluate prediction model accuracy on synthetic program synthesis tasks to establish baseline performance

## Limitations
- Performance varies significantly across domains, suggesting domain-specific challenges not fully characterized
- Reliance on high-quality knowledge graphs bounds effectiveness to completeness and accuracy of underlying data
- Preprocessing pipeline may struggle with ambiguous entity recognition or multi-context entity spans

**Medium Confidence:** The scalability claims through modern synthesis techniques, as the comparison focuses on specific domains and may not generalize to broader problem spaces

**Medium Confidence:** The architectural decomposition effectiveness, as the paper demonstrates success but doesn't thoroughly analyze failure modes or robustness
