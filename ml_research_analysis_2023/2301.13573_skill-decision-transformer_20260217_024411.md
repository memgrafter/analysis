# Skill Decision Transformer

## Quick Facts
- arXiv ID: 2301.13573
- Source URL: https://arxiv.org/abs/2301.13573
- Reference count: 26
- One-line primary result: Skill DT achieves competitive performance on D4RL benchmarks through pure unsupervised skill discovery, outperforming Decision Transformer on Mujoco tasks and matching or exceeding other offline RL methods.

## Executive Summary
Skill Decision Transformer (Skill DT) addresses the challenge of discovering diverse behaviors in offline reinforcement learning without relying on reward signals. It treats skill discovery as a sequence modeling problem, using a causal transformer to predict actions based on current states, skill embeddings, and future skill distributions. The method employs VQ-VAE to discretize states into discrete skill embeddings, which are then used as conditioning variables for action prediction. Skill DT demonstrates competitive performance on D4RL benchmarks through pure unsupervised skill discovery and can perform zero-shot state-marginal matching by reconstructing target trajectories.

## Method Summary
Skill DT uses a sequence modeling approach that combines VQ-VAE skill embeddings with future skill distributions to learn discrete behaviors in offline RL settings. The method learns discrete skill embeddings via VQ-VAE that capture diverse behavioral patterns, then conditions action prediction on both current skill embeddings and future skill distributions represented as histograms. At each training iteration, the method relabels future skill distributions using the current VQ-VAE encoder to ensure stability. The causal transformer predicts actions autoregressively based on previous states, skills, and future skill distributions, trained using MSE loss with VQ-VAE regularization.

## Key Results
- Achieves competitive performance on D4RL benchmarks through pure unsupervised skill discovery
- Outperforms Decision Transformer on all Mujoco tasks and matches or exceeds other offline RL methods on most environments
- Can reconstruct target trajectories in zero-shot manner for state-marginal matching
- Learned skills are diverse and distinguishable, with Wasserstein distances between skill distributions ranging from 0.007 to 0.036

## Architecture Onboarding

- Component map: State → VQ-VAE encode → Quantize → Skill distribution → Causal transformer → Action prediction
- Critical path: The full pipeline from state observation through skill embedding and distribution generation to action prediction
- Design tradeoffs: Discrete vs continuous skills (discrete enables easy sampling but may limit expressiveness), skill count (more skills = more computation but potentially better coverage), context length (longer context helps but increases computational cost)
- Failure signatures: Poor skill diversity (skills collapse to few patterns), unstable training (requires frequent relabeling), reconstruction failure (cannot match target trajectories)
- First 3 experiments:
  1. Verify VQ-VAE can cluster states into meaningful discrete categories by visualizing t-SNE projections of quantized vs unquantized embeddings
  2. Test causal transformer with fixed, ground-truth skill distributions to isolate whether the issue is in skill discovery or action prediction
  3. Evaluate skill diversity using Wasserstein distance between skill distributions across different environments to ensure learned skills are distinguishable

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal number of skills to learn for different types of tasks?
- Basis in paper: [explicit] The authors mention that increasing the number of skills has less effect on performance in environments with many successful trajectories but improves performance in multimodal datasets like -replay environments
- Why unresolved: The paper only tests a few discrete skill counts (5, 10, 16, 32) and doesn't systematically explore the relationship between task complexity and optimal skill count
- What evidence would resolve it: A comprehensive ablation study varying skill counts across diverse task types, coupled with analysis of task characteristics that predict optimal skill numbers

### Open Question 2
- Question: How does Skill DT's performance compare to other offline RL methods on long-horizon tasks?
- Basis in paper: [inferred] The authors acknowledge that Skill DT struggles on harder exploration problems like antmaze-medium environments, similar to the original Decision Transformer
- Why unresolved: The paper doesn't provide direct comparisons with specialized long-horizon offline RL methods like Trajectory Transformer or hierarchical approaches like OPAL on challenging exploration tasks
- What evidence would resolve it: Head-to-head comparisons of Skill DT against long-horizon RL methods on complex exploration benchmarks

### Open Question 3
- Question: Can Skill DT benefit from incorporating rewards during training?
- Basis in paper: [explicit] The authors state that their approach is "powerful because it is unsupervised" but also "limited because of it"
- Why unresolved: The paper focuses entirely on reward-free skill discovery and doesn't experiment with semi-supervised or supervised variants
- What evidence would resolve it: Comparative experiments showing Skill DT's performance with varying degrees of reward supervision on standard benchmarks

## Limitations
- Performance on AntMaze tasks is notably weaker than on Mujoco environments, suggesting limitations in handling discrete state spaces
- Computational cost of sequence modeling with long context lengths and multiple skill distributions may limit scalability
- The method struggles on harder exploration problems like antmaze-medium environments, similar to the original Decision Transformer

## Confidence
- High Confidence: The sequence modeling approach with causal transformers is technically sound and well-established
- Medium Confidence: The VQ-VAE discretization strategy effectively captures diverse behavioral patterns that correlate with task performance
- Low Confidence: The hindsight relabeling consistently improves stability and performance across all environments and dataset sizes

## Next Checks

3. Test the learned skill embeddings on transfer tasks or multi-task settings to evaluate whether discrete skills capture genuinely transferable behavioral primitives
