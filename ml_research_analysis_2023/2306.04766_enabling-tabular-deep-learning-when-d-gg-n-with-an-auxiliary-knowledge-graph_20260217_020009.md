# Enabling tabular deep learning when $d \gg n$ with an auxiliary knowledge graph

## Quick Facts
- arXiv ID: 2306.04766
- Source URL: https://arxiv.org/abs/2306.04766
- Reference count: 40
- Primary result: PLATO outperforms 13 baselines by up to 10.19% on 6 datasets with d ≫ n

## Executive Summary
This paper addresses the challenge of applying deep learning to tabular datasets where the number of features far exceeds the number of samples (d ≫ n), which leads to overfitting risks. The key insight is that auxiliary domain information about input features can be structured as a heterogeneous knowledge graph (KG). The proposed method, PLATO, uses this KG to regularize a multilayer perceptron (MLP) by inferring the first layer's weights from feature embeddings learned via a trainable message-passing function on the KG. Across 6 datasets with d ≫ n, PLATO outperforms 13 state-of-the-art baselines by up to 10.19%, demonstrating that leveraging structured domain knowledge significantly improves performance in low-data regimes.

## Method Summary
PLATO addresses the d ≫ n problem by using an auxiliary knowledge graph to regularize a multilayer perceptron. The method pretrains feature embeddings using a KG embedding method (ComplEx), then updates them with a trainable message-passing function that incorporates sample values via attention. The first layer's weights are inferred from these updated embeddings, drastically reducing the number of trainable parameters compared to learning them directly. The remaining MLP layers are then trained normally. This approach effectively captures the inductive bias that features with similar relationships in the KG should have similar weights.

## Key Results
- PLATO achieves a mean Pearson correlation of 0.583 on d ≫ n datasets, outperforming the best baseline (TabTransformer) by 0.069
- Performance gains increase with higher d/n ratios, with PLATO outperforming MLP by up to 10.19% on datasets with d/n = 52.2
- PLATO's performance depends on both feature nodes and non-feature nodes in the KG, with the "full KG" configuration (0.583) outperforming "feature-only KG" (0.539)

## Why This Works (Mechanism)

### Mechanism 1
PLATO reduces overfitting in d ≫ n settings by inferring MLP weights from knowledge graph embeddings rather than learning them directly. Instead of learning d × h weights directly (which causes overfitting when d ≫ n), PLATO learns a small number of parameters to map feature embeddings (dimension c) to weight vectors (dimension h). Since c ≪ d, this drastically reduces trainable parameters.

### Mechanism 2
The message-passing function updates feature embeddings to be sample-specific, allowing PLATO to capture feature interactions relevant to each prediction. PLATO uses attention coefficients αijk that depend on the input sample values Xij and Xik. This allows the feature embeddings to be conditioned on the specific input sample, making the weight inference context-aware.

### Mechanism 3
PLATO's performance depends on both feature nodes and non-feature nodes in the KG, with non-feature nodes providing broader domain context. Non-feature nodes in the KG represent domain knowledge (e.g., gene functions, anatomical relationships) that help regularize the feature embeddings by providing additional structural constraints beyond direct feature-feature relationships.

## Architecture Onboarding

- **Component map:** Input features → KG nodes → pre-trained embeddings → message-passing → updated embeddings → weight inference → MLP prediction
- **Critical path:** Feature → KG node → pre-trained embedding → message-passing → updated embedding → weight inference → MLP prediction
- **Design tradeoffs:** Message-passing rounds R vs. expressiveness and computational cost; embedding dimension c vs. representational capacity and parameter count; MLP depth vs. performance and overfitting risk
- **Failure signatures:** Poor performance if KG contains irrelevant or noisy information; overfitting if message-passing is too expressive relative to data size; underfitting if embedding dimension c is too small
- **First 3 experiments:**
  1. Ablation: Remove message-passing function to test if it's essential
  2. Ablation: Use "feature-only KG" to test importance of non-feature nodes
  3. Hyperparameter sweep: Vary embedding dimension c and message-passing rounds R

## Limitations
- PLATO requires a high-quality auxiliary KG that captures meaningful relationships between features, which may not exist for many domains
- Performance gains were demonstrated on specific biomedical datasets, and generalization to other domains with different KG structures remains untested
- The computational overhead of message-passing updates and the need for pretraining KG embeddings may limit scalability

## Confidence
- Core mechanism: High - The weight inference approach directly addresses the d ≫ n overfitting problem with clear theoretical grounding
- Broader applicability: Medium - Limited to domains with available KGs and specific biomedical datasets tested
- Scalability: Low - Computational overhead and pretraining requirements not fully explored for larger datasets
