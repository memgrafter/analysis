# Long-Tailed Partial Label Learning via Dynamic Rebalancing

## Quick Facts
- arXiv ID: 2302.05080
- Source URL: https://arxiv.org/abs/2302.05080
- Reference count: 40
- Primary result: Dynamic rebalancing method RECORDS improves long-tailed partial label learning without requiring prior class distribution knowledge

## Executive Summary
This paper addresses the challenging problem of long-tailed partial label learning (LT-PLL), where label ambiguity and severe class imbalance coexist. The authors identify that standard long-tailed learning techniques fail in this setting because they assume known class distributions, which are unavailable in PLL. To address this, they propose RECORDS, a dynamic rebalancing method that estimates and adapts to the evolving class distribution during training without requiring prior knowledge. RECORDS decomposes the model output and uses a momentum-updated prototype feature to perform dynamic adjustment, which is shown to be both effective and theoretically convergent to the oracle class prior. Extensive experiments on three benchmark datasets demonstrate that RECORDS significantly improves over state-of-the-art PLL methods, achieving up to 32.03% higher accuracy on PASCAL VOC compared to the best baseline. The method is also robust to non-uniform candidate generation and outperforms other dynamic strategies.

## Method Summary
RECORDS is a dynamic rebalancing method for long-tailed partial label learning that estimates class distributions during training without requiring prior knowledge. It maintains a prototype feature vector updated with momentum across batches, which is combined with the current classifier to estimate the class distribution. This estimate replaces the static log Ptrain(y) in logit adjustment, creating debiased logits that are used for confidence weight updates. The method can be easily plugged into existing PLL methods in an end-to-end manner and theoretically converges to the oracle class prior under small ambiguity conditions. RECORDS is trained with standard optimization techniques including SGD with momentum, cosine learning rate decay, batch size 256, and 800 epochs.

## Key Results
- RECORDS achieves up to 32.03% higher accuracy on PASCAL VOC compared to the best baseline PLL method
- The method demonstrates significant improvements on CIFAR-10-LT and CIFAR-100-LT with imbalance ratios ρ=50 and 100
- RECORDS shows robust performance under non-uniform candidate generation scenarios
- Theoretical analysis proves convergence to oracle class prior under small ambiguity degree conditions

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Dynamic rebalancing through momentum-updated prototype features adapts the class distribution estimate during training to match the disambiguating label process.
- Mechanism: The method maintains a prototype feature vector F that is updated with momentum across batches. This F is combined with the current classifier to estimate Ptrain(y|Θ), which replaces the static log Ptrain(y) in logit adjustment. The debiased logits are then used for confidence weight updates.
- Core assumption: The expectation of features across the training set can be approximated incrementally via momentum updates, and this approximation aligns with the evolving label disambiguation.
- Evidence anchors:
  - [abstract]: "we propose a dynamic rebalancing method, termed as RECORDS, without assuming any prior knowledge about the class distribution"
  - [section 4.2]: "we maintain a prototype featureF for the entire training set, using each batch's feature expectation for momentum updates"
  - [corpus]: Weak. No corpus paper explicitly describes momentum-updated prototype features for class distribution estimation in PLL.
- Break condition: If the momentum coefficient m is too small, the estimate becomes unstable; if too large, it lags the true distribution too much.

### Mechanism 2
- Claim: The parametric decomposition Ptrain(y|Θ) converges to the oracle class prior under small ambiguity conditions, ensuring asymptotic unbiasedness.
- Mechanism: Proposition 1 shows that as label disambiguation progresses (ambiguity degree η → 0), the L2 distance between the dynamic estimate Ptrain(y|Θ) and the true Ptrain(y) shrinks, approaching the constant rebalancing solution.
- Core assumption: The small ambiguity degree condition holds, i.e., most samples have low probability of false positive labels in their candidate set.
- Evidence anchors:
  - [section 4.3]: "Proposition 1 yields an important implication that alongside the label disambiguation, the dynamic estimation can progressively approach to the oracle class distribution under small ambiguity degree"
  - [Figure 3(a)]: Visualizes the L2 distance between estimated and oracle class distributions decreasing during training.
  - [corpus]: Weak. No corpus paper provides theoretical convergence bounds for dynamic class distribution estimation in PLL.
- Break condition: If ambiguity degree is high, convergence to the oracle prior may be slow or incomplete.

### Mechanism 3
- Claim: Using the debiased output logits Puni(y|x; Θ) for confidence weight updates improves label disambiguation accuracy, especially for tail classes.
- Mechanism: RECORDS replaces the biased Ptrain(y|x; Θ) output with Puni(y|x; Θ) before weight updates, reducing the over-confidence in head classes and allowing tail classes to be disambiguated more accurately.
- Core assumption: The debiasing step does not overly distort the relative ordering of candidate labels for any sample.
- Evidence anchors:
  - [section 4.2]: "Our RECORDS is lightweight and can be easily plugged into existing PLL methods in an end-to-end manner"
  - [Figure 5]: Shows improved per-class accuracy on CIFAR-10-LT, especially for minority classes, when using RECORDS vs. Oracle-LA.
  - [corpus]: Weak. No corpus paper explicitly describes debiasing outputs for PLL confidence updates.
- Break condition: If the debiasing overcorrects, it may harm disambiguation for ambiguous samples.

## Architecture Onboarding

- Component map:
  Backbone feature extractor f(x;θ) -> Linear classifier g(f(x;θ); W) -> Prototype feature F (momentum-updated) -> Debiasing module: zuni = z - log softmax(g(F; W)) -> Confidence weight updater (method-specific) -> Loss function (method-specific)

- Critical path:
  1. Forward pass through f and g to get z
  2. Update F via momentum from current batch features
  3. Compute debiased logits zuni using F
  4. Update confidence weights using zuni
  5. Compute loss with updated weights
  6. Backward pass to update θ and W

- Design tradeoffs:
  - Momentum coefficient m balances stability vs. responsiveness; m=0.9 is recommended but can be tuned
  - Frequency of F updates (per batch) vs. computational overhead
  - Integration with different PLL methods (PRODEN, LW, CA VL, CORR) requires minimal changes

- Failure signatures:
  - Poor tail class performance: may indicate insufficient debiasing or slow convergence of Ptrain(y|Θ)
  - Degraded head class performance: may indicate over-debiasing or instability in F updates
  - Training instability: check m value and batch size adequacy

- First 3 experiments:
  1. Plug RECORDS into PRODEN on CIFAR-10-LT with ρ=100, q=0.5; compare accuracy to PRODEN + Oracle-LA
  2. Vary m ∈ {0.0, 0.3, 0.6, 0.9, 1.0} on CIFAR-100-LT; plot accuracy vs. m
  3. Test on CIFAR-100-LT-NU to evaluate robustness to non-uniform candidate generation

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does RECORDS' performance change when the ambiguity degree η approaches 1 (high ambiguity)?
- Basis in paper: [inferred] The paper states that Proposition 1 requires a small ambiguity degree condition (η ∈ [0, 1)), and shows that the L2 distance between dynamic and oracle class distributions decreases with lower η. They test on q=0.03, 0.05, 0.07 but don't explore higher ambiguity levels.
- Why unresolved: The paper only tests moderate ambiguity levels (q=0.03-0.07) and doesn't report results for high ambiguity scenarios where η approaches 1.
- What evidence would resolve it: Experiments showing RECORDS performance on datasets with high ambiguity levels (e.g., q > 0.7) would reveal whether the method degrades gracefully or fails catastrophically when the small ambiguity degree condition is violated.

### Open Question 2
- Question: How sensitive is RECORDS to the momentum coefficient m, and is there an optimal way to set it dynamically rather than keeping it constant?
- Basis in paper: [explicit] The paper shows an ablation study on m in Figure 6(b) but only tests static values and doesn't explore adaptive strategies.
- Why unresolved: The authors acknowledge m=0.9 works best but don't investigate whether the optimal m varies during training or with dataset characteristics.
- What evidence would resolve it: Experiments varying m throughout training (e.g., warm-up schedules, adaptive schemes) and correlating m values with dataset properties would determine if dynamic m selection improves performance.

### Open Question 3
- Question: Does RECORDS transfer effectively to other weakly supervised learning scenarios beyond partial label learning?
- Basis in paper: [explicit] The authors state "In the future, the extension of RECORDS to other weakly supervised learning scenarios can be explored in a more general scope."
- Why unresolved: The paper only validates RECORDS on LT-PLL and mentions potential extensions without testing them.
- What evidence would resolve it: Applying RECORDS to other weakly supervised settings (e.g., positive-unlabeled learning, complementary label learning) and comparing performance against specialized methods would demonstrate its generalizability.

## Limitations

- The theoretical convergence to oracle class prior relies on the small ambiguity degree assumption, which may not hold in all real-world scenarios
- The ablation studies could be more comprehensive to isolate the contribution of each component
- The impact of extreme long-tailed distributions (ρ > 100) is not explored
- The method's performance gains may vary depending on the specific PLL method used
