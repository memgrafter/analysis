# Beyond dynamic programming

## Quick Facts
- arXiv ID: 2306.15029
- Source URL: https://arxiv.org/abs/2306.15029
- Reference count: 40
- One-line primary result: Introduces Score-life programming for reinforcement learning that directly computes optimal infinite horizon action sequences without requiring policy functions

## Executive Summary
This paper introduces Score-life programming, a novel approach to reinforcement learning that maps infinite horizon action sequences to real numbers in a bounded interval, enabling direct optimization of non-stationary policies. Unlike classical dynamic programming methods limited to stationary policies, this framework computes optimal action sequences by defining a Score-life function that maps these real-valued encodings to infinite horizon costs. The approach is demonstrated on the cartpole balancing task, where approximate polynomial methods successfully balanced the cartpole for 500 timesteps, outperforming exact fractal methods that struggled with computational difficulties in optimizing fractal functions.

## Method Summary
Score-life programming constructs a surjective mapping from infinite horizon action sequences to real numbers in [0,1) using binary encoding schemes. It defines a Score-life function that recursively relates infinite horizon costs through dynamic programming without requiring explicit policy functions. The method establishes that Score-life functions of different states are related by amplitude and phase transformations, allowing computation from a reference state. Two implementation approaches are presented: exact methods using Faber-Schauder basis functions for fractal function representation (computationally intractable due to O(2^n) evaluations) and approximate methods using polynomial approximations that are easier to optimize but may sacrifice accuracy.

## Key Results
- Score-life functions can be computed for all states via amplitude and phase transformations from a reference state
- Exact methods using Faber-Schauder basis functions performed poorly on cartpole (16 timesteps) due to local minima in fractal optimization
- Approximate polynomial methods successfully balanced cartpole for 500 timesteps
- The framework enables searching over non-stationary policies, unlike classical dynamic programming limited to stationary policies

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Infinite horizon action sequences can be mapped to real numbers in [0,1) using a binary encoding scheme.
- Mechanism: The paper constructs a surjective mapping κ from action set U to binary sequences of length log(M), where M is the cardinality of U. Each infinite action sequence {u₀, u₁, ...} is mapped to a real number l = Σᵢ 2^(-logM·i-1) · κ(uᵢ), which lies in [0,1) due to the convergence of the geometric series.
- Core assumption: The action set U is finite (|U| = M > 1) and the encoding κ is surjective from U to binary sequences of length log(M).
- Evidence anchors:
  - [abstract] "The central idea in our method is the construction of a mapping between infinite horizon action sequences and real numbers in a bounded interval."
  - [section 3.1] "Consider an agent living in an environment with dynamics xk+1 = f (xk) taking a sequence of actions {uk}∞k=0 from the action set U. Each infinite action sequence forms an action trajectory Ax = {u0}{u1}{u2}.....{u∞}. Let A be the set of all possible infinite horizon action trajectories."
  - [corpus] Weak evidence: no direct citation of prior work using similar real-number encodings for RL.

### Mechanism 2
- Claim: The Score-life function recursively relates the infinite horizon cost of a state to the costs of its successor states.
- Mechanism: Theorem 1 states that S(l, x) = g(x, κ⁻¹(⌊2^logM·l⌋)) + γS({2^logM·l}, f(x, κ⁻¹(⌊2^logM·l⌋))). This recursive relationship allows the infinite horizon cost to be computed from the stage cost and the Score-life function of the next state, enabling dynamic programming without an explicit policy function.
- Core assumption: The environment dynamics are deterministic and the stage cost g(x,u) is well-defined for all state-action pairs.
- Evidence anchors:
  - [abstract] "We define a function that maps the real numbered values to infinite horizon costs of specific action sequences."
  - [section 3.3] "Now we can define a new function called 'Score-life' function, which maps the life value 'l' to its corresponding infinite horizon cost J∞(x0)."
  - [corpus] No direct citation of similar recursive cost formulations; likely original to this work.

### Mechanism 3
- Claim: Score-life functions of different states are related by amplitude and phase transformations.
- Mechanism: Theorem 2 provides a closed-form relation S(l, xN) = 1/γ^N (S(l/2^N·logM + φN, x0) - ψN), where φN and ψN are functions of the action and state trajectory from x0 to xN. This allows computing the Score-life function for any state from the function of a single reference state.
- Core assumption: The state trajectory {x₀, x₁, ..., xN} is uniquely determined by the action sequence {u₀, u₁, ..., uN} under deterministic dynamics.
- Evidence anchors:
  - [section 3.3] "Theorem 2 tells us that the Score-life functions of different states xN and x0 are related by coordinated transformations."
  - [section 3.3] "We can apply this result to design algorithms for efficient computation of optimal action sequences."
  - [corpus] No prior work cited for this specific transformation relationship; appears to be a novel contribution.

## Foundational Learning

- Concept: Faber-Schauder basis functions for fractal function representation.
  - Why needed here: The Score-life function is a fractal function that cannot be represented by polynomials or smooth functions. Faber-Schauder basis functions provide a Schauder basis for C⁰([0,1]) and can represent the fractal Score-life function exactly.
  - Quick check question: Why can't we use polynomial approximation for the Score-life function in exact methods?

- Concept: Bellman operators and dynamic programming.
  - Why needed here: The paper contrasts its approach with classical dynamic programming, which computes optimal policies by iterating Bellman operators. Understanding Bellman operators helps appreciate why Score-life programming can search over non-stationary policies.
  - Quick check question: What is the key limitation of classical dynamic programming that Score-life programming overcomes?

- Concept: Reinforcement learning in infinite horizon settings.
  - Why needed here: The paper solves infinite horizon optimal control problems, which are fundamental in RL. Understanding the infinite horizon cost formulation J∞(x₀) = Σₖ γ^k·g(xₖ,uₖ) is crucial for grasping the Score-life function's purpose.
  - Quick check question: How does the infinite horizon cost differ from finite horizon costs in RL?

## Architecture Onboarding

- Component map:
  State encoding -> Action encoding -> Cost evaluation -> Function representation -> Optimization

- Critical path:
  1. Initialize Score-life function for reference state x₀
  2. Apply Theorem 2 to compute Score-life functions for all states in state space
  3. For a given state x, find l* = argmin_l S(l,x)
  4. Extract optimal action sequence from l* via binary decoding

- Design tradeoffs:
  - Exact vs approximate methods: Exact methods use fractal Faber-Schauder representation but are computationally expensive; approximate methods use polynomial representations that are easier to optimize but may not capture the true optimal action sequence
  - Deterministic vs stochastic dynamics: The current framework assumes deterministic dynamics; extending to stochastic settings would require significant modifications

- Failure signatures:
  - Poor performance on exact methods: Likely due to local minima in fractal function optimization (as seen in cartpole experiments)
  - Suboptimal action sequences from approximate methods: Polynomial approximations may not capture the true minima of fractal Score-life functions
  - Computational intractability: Faber-Schauder coefficient computation requires O(2^n) queries to Score-life function

- First 3 experiments:
  1. Implement the mapping κ from actions to binary sequences and verify that action sequences map to [0,1)
  2. Implement Theorem 1 recursion and verify Score-life function computation for a simple deterministic system
  3. Implement Theorem 2 transformations and verify that Score-life functions of different states are related as predicted

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can the computational challenges of optimizing fractal Score-life functions be addressed to make exact methods more practical and effective?
- Basis in paper: [explicit] The paper mentions that "efficiently optimizing fractal functions is a hard computational problem, and most of the time the solver gets trapped in local minima," leading to poor performance of exact methods compared to approximate methods.
- Why unresolved: The paper acknowledges the difficulty but does not provide a specific solution or methodology to overcome this challenge.
- What evidence would resolve it: Demonstrating a practical algorithm or approach that can reliably find global optima of fractal Score-life functions in complex RL problems.

### Open Question 2
- Question: Can the Score-life programming approach be effectively extended to stochastic and model-free reinforcement learning problems?
- Basis in paper: [explicit] The paper concludes by stating that "In future work, we plan to apply the method to model free and stochastic reinforcement learning problems."
- Why unresolved: The current theoretical framework and demonstrations are limited to deterministic, model-based scenarios, leaving open the question of applicability to more general RL settings.
- What evidence would resolve it: Successful application and performance evaluation of Score-life programming on stochastic environments and in model-free settings, with comparisons to state-of-the-art RL algorithms.

### Open Question 3
- Question: What is the optimal polynomial degree for approximating Score-life functions in different types of control problems, and how does it affect the trade-off between approximation accuracy and computational efficiency?
- Basis in paper: [inferred] The paper uses a quadratic approximation for the cartpole task and notes that "we found that quadratic functions are sufficient for cart pole balancing," but does not explore the impact of polynomial degree on performance across different problems.
- Why unresolved: The choice of polynomial degree is presented as a heuristic that worked for one specific task, without systematic analysis of its impact on approximation quality and computational requirements in general.
- What evidence would resolve it: Empirical studies comparing the performance of Score-life programming with different polynomial degrees across a range of control tasks, analyzing the relationship between polynomial complexity, approximation error, and optimization efficiency.

## Limitations
- Exact methods using Faber-Schauder basis functions are computationally intractable due to exponential growth in required evaluations (O(2^n))
- Approximate polynomial methods may not capture true optimal action sequences due to limitations of polynomial approximations for fractal functions
- Framework currently assumes deterministic dynamics and finite action spaces, limiting applicability to stochastic or continuous control problems

## Confidence
- High confidence: The theoretical foundations connecting infinite horizon action sequences to real numbers, and the recursive Score-life function formulation (Theorems 1 and 2)
- Medium confidence: The experimental results on the cartpole task, though limited to one benchmark problem
- Low confidence: The computational feasibility of exact methods and the practical performance of approximate methods on complex, high-dimensional problems
