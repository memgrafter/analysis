# Dynamic Benchmarking of Masked Language Models on Temporal Concept Drift with Multiple Views

## Quick Facts
- arXiv ID: 2302.12297
- Source URL: https://arxiv.org/abs/2302.12297
- Authors: 
- Reference count: 33
- Key outcome: Introduces DYNAMIC TEMP LAMA, a framework that dynamically generates temporal test sets from Wikidata to evaluate MLMs on knowledge preservation and adaptation across time.

## Executive Summary
This paper introduces DYNAMIC TEMP LAMA, a dynamic benchmarking framework for evaluating masked language models (MLMs) on temporal concept drift. The framework generates test sets from Wikidata with fine-grained temporal splits (updated, new, unchanged, deleted facts) and evaluates models using three distinct methods: single-token probing, multi-token generation, and MLM scoring. Experiments on 11 temporal RoBERTa models show that recent models perform better over time, especially in multi-token generation tasks, demonstrating the framework's ability to measure both knowledge preservation and adaptation capabilities.

## Method Summary
The framework dynamically creates temporal test sets from Wikidata, splitting facts by time granularity (monthly, quarterly, yearly) and creating fine-grained subsets (unchanged, updated, new, deleted). It evaluates MLMs using three methods: single-token probing (accuracy, MRR, P@k), multi-token generation (ROUGE, F1-macro, BERT-score), and MLM scoring (pseudo-log-likelihood). The evaluation uses 11 temporal RoBERTa models trained quarterly on Twitter data from 2019-Q4 to 2022-Q2, testing 16 Wikidata relations through manual template-based cloze queries.

## Key Results
- Recent temporal RoBERTa models (2021-2022) outperform older models (2019-2020) on temporal concept drift tasks
- Multi-token generation shows the most significant performance differences between model time periods
- Single-token evaluation loses ~95% of data due to multi-token objects, highlighting the importance of multi-token methods
- Fine-grained temporal splits enable targeted analysis of knowledge preservation versus adaptation capabilities

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Dynamic test set generation from Wikidata captures temporal concept drift more effectively than static benchmarks.
- Mechanism: The framework queries Wikidata to create test sets split by time granularity (monthly, quarterly, yearly) and further divided into fine-grained subsets (updated, new, unchanged, deleted facts). This allows evaluation of model performance across different types of temporal changes.
- Core assumption: Wikidata contains reliable temporal metadata about fact validity periods that can be used to construct meaningful test splits.
- Evidence anchors:
  - [abstract]: "we provide a holistic framework that (1) dynamically creates temporal test sets of any time granularity (e.g. month, quarter, year) of factual data from Wikidata"
  - [section]: "We base our implementation on the TEMP LAMA (Dhingra et al., 2022) code, while we make several changes in terms of accessibility (i.e. option to dynamically update the test set), flexibility (i.e. option to adjust the granularity of the temporal splits) and comprehensiveness (i.e. fine-grained splits and multiple evaluation views)."
- Break condition: If Wikidata's temporal metadata is incomplete or unreliable for the facts being evaluated, the dynamic splits would not accurately represent temporal drift.

### Mechanism 2
- Claim: Multiple evaluation views (single-token probing, multi-token generation, MLM scoring) provide a more comprehensive assessment of temporal robustness than single-method approaches.
- Mechanism: Each evaluation method captures different aspects of model performance - single-token measures exact match accuracy, multi-token generation handles multi-word entities, and MLM scoring evaluates probability distributions over possible answers.
- Core assumption: Different temporal concept drift scenarios require different evaluation approaches to properly assess model capabilities.
- Evidence anchors:
  - [abstract]: "evaluates MLMs in three distinct ways (single-token probing, multi-token generation, MLM scoring)"
  - [section]: "we introduce three distinct evaluation views with multiple metrics (§3.3) to ensure comprehensive results"
- Break condition: If one evaluation method becomes saturated or irrelevant due to changes in model architecture or training approaches, the comprehensive assessment value decreases.

### Mechanism 3
- Claim: Fine-grained temporal splits enable targeted analysis of knowledge preservation versus adaptation capabilities.
- Mechanism: By separating unchanged facts (knowledge preservation) from updated/new/deleted facts (adaptation), the framework can identify whether models maintain existing knowledge while incorporating new information.
- Core assumption: Temporal concept drift involves both maintaining valid knowledge and updating invalid knowledge, which are distinct capabilities requiring separate measurement.
- Evidence anchors:
  - [section]: "we further create comprehensive test sets that contain examples with unchanged, updated, new or deleted facts, denoted by DUNCHANGED_t+1, DUPDATED_t+1, DNEW_t+1 and DDELETED_t+1 respectively"
  - [section]: "First, we can use DUNCHANGED_t+1 to evaluate knowledge preservation (i.e. how well a model can preserve knowledge over time). Second, we can use DUPDATED_t+1, DNEW_t+1 and DDELETED_t+1 to measure adaptation"
- Break condition: If temporal concept drift is primarily one type (e.g., only new facts appear without updates), the fine-grained distinction becomes less valuable.

## Architecture Onboarding

- Component map:
  Data collection module -> Temporal splitter -> Fine-grained splitter -> Evaluation engine -> Model interface

- Critical path:
  1. Collect facts from Wikidata with temporal information
  2. Split facts into temporal granularity (e.g., quarterly)
  3. Create fine-grained subsets within each temporal split
  4. For each temporal model, evaluate across all splits using three methods
  5. Analyze results to identify knowledge preservation vs. adaptation capabilities

- Design tradeoffs:
  - Static vs. dynamic test sets: Dynamic sets capture current temporal drift but require ongoing maintenance
  - Granularity choices: Finer granularity provides more precise evaluation but increases computational cost
  - Template-based vs. learned prompts: Manual templates ensure consistency but may miss optimal prompts

- Failure signatures:
  - Skewed distributions: If unchanged facts dominate (>95%), the evaluation may not capture adaptation capabilities
  - Performance plateaus: If all models perform similarly across time, the temporal evaluation may not be sensitive enough
  - Multi-token evaluation issues: If MLM decoding produces poor results, the multi-token evaluation may not be reliable

- First 3 experiments:
  1. Verify temporal split creation: Run the data collection and splitting pipeline for a small time range and manually inspect the fine-grained subsets
  2. Test single-token evaluation baseline: Evaluate a standard RoBERTa model on the unchanged split to establish baseline performance
  3. Compare evaluation methods: Run the same model through all three evaluation methods on a single temporal split to understand their different outputs

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of MLM models on temporal concept drift tasks vary when using different granularities of temporal splits (e.g., monthly vs. quarterly vs. yearly)?
- Basis in paper: [explicit] The paper mentions that the framework allows for temporal splits of any granularity (monthly, quarterly, yearly) and that this granularity is an important factor in the correct assessment of the model's temporal factual knowledge.
- Why unresolved: The paper does not provide comparative results for different temporal granularities, focusing instead on quarterly splits.
- What evidence would resolve it: Experimental results comparing model performance across different temporal granularities (monthly, quarterly, yearly) would provide insights into how granularity affects the evaluation of temporal concept drift.

### Open Question 2
- Question: What are the limitations of the current MLM decoding methods (multi-token generation and MLM scoring) in accurately evaluating factual knowledge in language models, and how can these methods be improved?
- Basis in paper: [explicit] The paper acknowledges that both multi-token generation and MLM scoring methods provide results that are hard to interpret and that improving MLM decoding and addressing "domain mismatch" are open areas of research.
- Why unresolved: The paper does not provide solutions or improvements to the current MLM decoding methods, leaving these as open challenges.
- What evidence would resolve it: Development and evaluation of new MLM decoding methods that provide more interpretable results and better address the challenges of multi-token generation and MLM scoring would resolve this question.

### Open Question 3
- Question: How does the manual creation of templates for LAMA-style probing affect the consistency and generalizability of the evaluation framework across different types of inputs?
- Basis in paper: [explicit] The paper mentions that manual templates are a limitation in terms of scale and consistency, as LMs do not reason in an abstract manner and are context-dependent.
- Why unresolved: The paper does not explore the impact of manual templates on evaluation consistency and generalizability or provide solutions to incorporate a diverse set of templates.
- What evidence would resolve it: Experiments comparing model performance using different sets of templates for the same evaluation task would provide insights into the impact of template diversity on evaluation consistency and generalizability.

## Limitations
- Framework's effectiveness depends heavily on the quality and completeness of Wikidata's temporal metadata
- Evaluation focuses exclusively on factual knowledge in Wikidata relations, potentially missing other forms of temporal drift
- Multi-token generation evaluation shows significant performance degradation, suggesting limitations in current MLM decoding approaches

## Confidence
- High Confidence: Methodology for dynamic test set generation and observation that recent models perform better on temporal tasks
- Medium Confidence: Claim that multiple evaluation views provide complementary insights requires further validation across different model architectures
- Low Confidence: Assertion that framework can effectively measure both knowledge preservation and adaptation is limited by small number of models and specific focus on Twitter data
