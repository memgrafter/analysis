# Using Knowledge Graphs for Performance Prediction of Modular Optimization Algorithms

## Quick Facts
- arXiv ID: 2301.09876
- Source URL: https://arxiv.org/abs/2301.09876
- Reference count: 22
- Primary result: KG-based classifiers achieve high F1 scores (0.944) for predicting modular algorithm performance on BBOB functions.

## Executive Summary
This paper introduces a knowledge graph (KG) embedding approach for predicting the performance of modular black-box optimization algorithms, specifically modCMA and modDE, on the BBOB benchmark functions. The method extends the OPTION ontology with representations of algorithm configurations, creates KGs incorporating problem landscape and performance data, and applies triple classification to predict whether an algorithm instance can achieve a given target precision. Evaluation shows that the KG-based classifier achieves high F1 scores (e.g., 0.944) when classes are balanced, outperforming baseline methods. For imbalanced cases, incorporating a Random Forest on learned embeddings improves performance. The work demonstrates that KGs and KG embeddings can effectively support performance prediction in evolutionary computation.

## Method Summary
The authors extend the OPTION ontology to represent modular optimization algorithms, create knowledge graphs incorporating problem landscape features and performance data, and train KG embeddings using the ComplEx model. For balanced classification, they use triple classification with ComplEx scoring, while for imbalanced cases, they add a Random Forest classifier trained on the learned embeddings. The approach is evaluated on modCMA and modDE algorithms across BBOB benchmark functions.

## Key Results
- KG-based triple classifier achieves high F1 scores (0.944) on balanced classification tasks.
- Random Forest on KG embeddings improves performance in imbalanced classification scenarios.
- The approach outperforms baseline methods for predicting algorithm performance on BBOB functions.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Knowledge graph embeddings can encode complex relationships between optimization algorithms and problem instances for accurate performance prediction.
- Mechanism: The KG captures algorithm configurations, problem landscape features, and performance data as triples. Embeddings are learned using the ComplEx scoring model, which represents entities and relations in a complex vector space, allowing for the prediction of unseen performance relations (solved/not-solved) between algorithms and problems.
- Core assumption: The structural and feature information encoded in the KG is sufficient to capture the essential characteristics needed for predicting algorithm performance.
- Evidence anchors:
  - [abstract] "The method extends the OPTION ontology with representations of algorithm configurations, creates KGs incorporating problem landscape and performance data, and applies triple classification to predict whether an algorithm instance can achieve a given target precision."
  - [section 3.2] "Our proposed pipeline for predicting algorithm performance is shown in Figure 4. For training the KG embeddings, we use the Ampligraph library [3]..."

### Mechanism 2
- Claim: Random Forest classifiers trained on KG embeddings improve performance prediction in imbalanced classification scenarios.
- Mechanism: After initial KG embedding training, a Random Forest classifier is trained on the concatenated embeddings of algorithm and problem instances. This adds a supervised learning layer that can better handle class imbalance by learning decision boundaries in the embedding space.
- Core assumption: The embedding space contains separable patterns that a Random Forest can exploit for accurate classification, even when performance classes are imbalanced.
- Evidence anchors:
  - [section 5] "To solve the problem that arises in the case of imbalanced classiﬁcation, we modify the pipeline described in Section 3.2. More speciﬁcally, after the KG training phase, we add an additional training layer, where we train a Random Forest (RF) classiﬁer based on the learned embeddings."
  - [section 5] "The results show that training a RF classiﬁer on the learned embeddings improves the performance in terms of F1 score."

### Mechanism 3
- Claim: The OPTION ontology extension provides a unified formal representation that enables systematic construction of KGs for diverse modular optimization algorithms.
- Mechanism: The OPTION ontology is extended to include modular algorithm representations, allowing consistent encoding of algorithm modules, parameters, and their interactions. This structured knowledge base is then converted into a KG, ensuring that all relevant information (algorithm specs, problem features, performance data) is captured in a standardized format.
- Core assumption: A formal, standardized representation of modular optimization algorithms is both possible and beneficial for KG construction and downstream predictive tasks.

## Architecture Onboarding

- Component map:
  - Ontology Layer: OPTION ontology + algorithm extension module (defines classes and relations for modular algorithms, problem landscape, performance data)
  - Knowledge Graph Layer: Constructed KG from ontology data (nodes: problem instances, algorithm configurations; edges: relations like solved/not-solved, has-parameter)
  - Embedding Layer: KG embeddings learned via ComplEx model (low-dimensional vector representations of entities and relations)
  - Classification Layer: Triple classifier (initial) or Random Forest classifier (for imbalanced cases) trained on concatenated embeddings
  - Data Sources: BBOB benchmark problems, modCMA and modDE algorithm configurations, ELA features

- Critical path:
  1. Extend OPTION ontology to represent modular algorithms.
  2. Create KG from ontology knowledge base (include problem landscape features, algorithm specs, performance data).
  3. Train KG embeddings (ComplEx) on the KG.
  4. For balanced classification: Use triple classifier with ComplEx scores.
  5. For imbalanced classification: Train Random Forest on concatenated embeddings.
  6. Perform inference to predict algorithm performance on new problem instances.

- Design tradeoffs:
  - KG vs. Flat Feature Table: KG can capture complex relational structure and allow for more flexible querying, but requires more complex modeling (embeddings) compared to flat feature tables.
  - ComplEx vs. Other Embedding Models: ComplEx handles asymmetric relations well and is suitable for triple classification, but other models (e.g., TransE) might be faster to train.
  - Balanced vs. Imbalanced Handling: Using RF on embeddings for imbalanced cases improves performance but adds complexity and training time.

- Failure signatures:
  - Low F1 scores even on balanced classes: Indicates that the KG structure or embeddings are not capturing the relevant distinguishing features between algorithm-problem pairs.
  - Random Forest does not improve over ComplEx in imbalanced cases: Suggests that the embedding space is not sufficiently separable or that the RF model is not well-suited to the data distribution.
  - High variance in results across runs: May indicate sensitivity to hyperparameter choices or data splits, suggesting a need for more robust training procedures or data augmentation.

- First 3 experiments:
  1. Replicate the leave-random-triplets-out validation on a small subset of the KG (e.g., 5D modCMA with one fixed budget and target precision) to verify the basic pipeline works.
  2. Compare ComplEx embedding performance with a simpler baseline (e.g., logistic regression on concatenated problem + algorithm features) to assess the value added by KG embeddings.
  3. Test the Random Forest on embeddings approach on a deliberately imbalanced subset of the data to confirm it improves over the baseline ComplEx classifier in such scenarios.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can we develop a formal, standard vocabulary to represent algorithm operators, hyperparameters, and interactions outside of modular frameworks?
- Basis in paper: [explicit] The authors state this is a challenging task requiring community collaboration.
- Why unresolved: Representing all existing algorithms outside modular frameworks is time-consuming and complex.
- What evidence would resolve it: A standardized ontology framework that can represent various non-modular algorithms and their components.

### Open Question 2
- Question: How can KG embeddings be made more explainable for algorithm performance prediction?
- Basis in paper: [explicit] The authors plan to test different methods for training KG embeddings and improve their explainability.
- Why unresolved: Current KG embedding methods lack transparency in how they make predictions.
- What evidence would resolve it: Methods that provide clear explanations for why certain algorithm configurations are predicted to perform well or poorly on specific problems.

### Open Question 3
- Question: Can the Random Forest approach on learned embeddings be generalized to other imbalanced classification scenarios in KG-based performance prediction?
- Basis in paper: [explicit] The authors successfully used this approach for imbalanced classification in their experiments.
- Why unresolved: The effectiveness of this approach needs to be validated across different scenarios and datasets.
- What evidence would resolve it: Successful application of the RF approach to various imbalanced classification tasks in KG-based performance prediction across different domains and datasets.

## Limitations
- Performance prediction accuracy may be sensitive to the choice of KG embedding model and hyperparameters.
- The ontology extension may not capture all relevant nuances of complex modular algorithms or problem landscapes.
- The Random Forest classifier on embeddings adds complexity and may not always improve performance in imbalanced cases.

## Confidence
- High confidence: The KG-based approach can achieve high F1 scores for balanced performance prediction tasks.
- Medium confidence: The incorporation of Random Forest on KG embeddings is effective for imbalanced classification scenarios.
- Medium confidence: The ontology extension provides a systematic way to represent modular algorithms, but its scalability and expressiveness for more complex algorithm structures remain to be fully validated.
