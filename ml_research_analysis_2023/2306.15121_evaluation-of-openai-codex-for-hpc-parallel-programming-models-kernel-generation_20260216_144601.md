# Evaluation of OpenAI Codex for HPC Parallel Programming Models Kernel Generation

## Quick Facts
- arXiv ID: 2306.15121
- Source URL: https://arxiv.org/abs/2306.15121
- Reference count: 40
- OpenAI Codex evaluated for HPC kernel generation across multiple languages and parallel programming models

## Executive Summary
This paper benchmarks OpenAI Codex's ability to generate correct HPC kernels across different programming languages and parallel models. The study systematically evaluates Codex using simple prompts for fundamental kernels (AXPY, GEMV, GEMM, SpMV, Jacobi, CG) and measures proficiency based on correctness of the top 10 generated suggestions. Results reveal that Codex performs well for mature parallel programming models like OpenMP and CUDA in C++, but struggles with newer models like HIP and Kokkos. The proficiency varies significantly across languages, with Fortran and Julia showing improvement when model-specific keywords are included, while Python results remain inconsistent, particularly for Numba compared to CUDA-based tools.

## Method Summary
The evaluation employed a systematic approach where Codex was prompted with simple "<kernel> <programming-model>" phrases across four languages (C++, Fortran, Python, Julia). A proficiency metric was defined to measure correctness across the top 10 generated suggestions for each combination. The study focused on fundamental HPC kernels including AXPY, GEMV, GEMM, SpMV, Jacobi, and CG, testing across parallel programming models like OpenMP, CUDA, HIP, Kokkos, and others. The methodology relied on binary correctness checks without iterative refinement or performance benchmarking, using simple prompts to establish baseline capabilities.

## Key Results
- C++ proficiency was high for mature models (OpenMP, CUDA) but poor for newer models (HIP, Kokkos)
- Kernel complexity reduced success rates, with simpler kernels like AXPY yielding better results
- Fortran and Julia responses improved significantly with the inclusion of model-specific keywords
- Python exhibited inconsistent results, with Numba lagging behind CUDA-based tools in performance

## Why This Works (Mechanism)
Codex's performance correlates strongly with the maturity and prevalence of parallel programming models in its training data. Models with extensive documentation and community usage (OpenMP, CUDA) generate more accurate kernels, while newer or less-documented models (HIP, Kokkos) produce lower-quality results. Language-specific conventions, when incorporated through keywords like "function," "subroutine," or "def," enhance output quality by aligning with expected syntax patterns.

## Limitations
- Proficiency metric relies on binary correctness checks that may not capture HPC-specific performance characteristics
- Simple prompts without iterative refinement may underrepresent Codex's practical capabilities
