# ExClaim: Explainable Neural Claim Verification Using Rationalization

## Quick Facts
- arXiv ID: 2301.08914
- Source URL: https://arxiv.org/abs/2301.08914
- Reference count: 40
- Primary result: ExClaim achieves 0.93 F1 score on verdict classification with rationalization explanations

## Executive Summary
ExClaim introduces an explainable neural claim verification system that combines rationale generation with verdict classification. The system treats claim verification as a question-answer problem, using BART for abstractive summarization to generate rationales from evidence, then applying a T5 model for verdict classification. A new foundational dataset with government and international organization sources is introduced. ExClaim outperforms baseline models on verdict classification and provides sub-task explanations evaluated through SHAP, NLI, and manual annotation. The work advances explainable AI in claim verification by ensuring transparency, interpretability, and trustworthiness for non-expert users.

## Method Summary
ExClaim uses a two-stage approach: first, BART generates rationales by summarizing evidence through abstractive summarization (max 120 tokens, min 75), then T5 fine-tunes on the COPA task using claim + rationales as input with verdicts as choices. The system evaluates rationale quality using SHAP for feature importance, NLI for entailment relationships, and manual annotation (3 raters) for plausibility, fluency, and correctness. The foundational dataset contains 4006 articles with government and international organization sources, and the system is compared against LSTM, DistilBERT, and BART zero-shot baselines.

## Key Results
- ExClaim achieves 0.93 F1 score on verdict classification
- System outperforms DistilBERT on plausibility, fluency, and correctness measures
- Abstractive summarization generates higher quality rationales than extractive alternatives

## Why This Works (Mechanism)

### Mechanism 1
- Claim: ExClaim achieves high F1 score by treating verdict classification as a question-answer problem
- Mechanism: Reformulates claim verification into COPA-style QA format where claim is question, rationale is premise, and verdict choices are "Supports" and "Refutes"
- Core assumption: QA reformulation leverages T5's pre-trained language understanding for complex reasoning
- Evidence anchors:
  - [abstract] "ExClaim treats the verdict classification task as a question-answer problem and achieves a performance of 0.93 F1 score"
  - [section] "We frame the ExClaim classification task as a question-answer problem"

### Mechanism 2
- Claim: Abstractive summarization using BART effectively extracts the 20% of evidence most relevant to the claim
- Mechanism: BART summarizes evidence based on Pareto principle hypothesis that only 20% of information is critical for verification
- Core assumption: Most important evidence is concentrated in small portion and abstractive summarization can reliably extract it
- Evidence anchors:
  - [section] "Inspired by the Pareto principle, we hypothesize that on average only 20% of the information in the evidence is important to verify a claim"
  - [section] "We leverage the BART language model which has a maximum sequence length of 1024 tokens and it outperformed previous work on summarization"

### Mechanism 3
- Claim: Rationale generation process is explainable and trustworthy due to SHAP-based evaluation
- Mechanism: SHAP computes marginal contribution of each input feature towards generated rationale, providing visual and quantitative measure of influence
- Core assumption: SHAP values provide reliable and interpretable measure of feature importance for text generation tasks
- Evidence anchors:
  - [section] "We used an explainable technique called SHAP, which leverages game theory to explain the output of any ML model"
  - [section] "Figure 3 shows the output explanation where the explainer provides Shapley values for input features"

## Architecture Onboarding

- Component map: Data pipeline (claims/evidence) → BART (rationale) → T5 (verdict) → NLE → Explainability checks
- Critical path: Claim → Evidence → BART (rationale) → T5 (verdict) → NLE → Explainability checks
- Design tradeoffs:
  - Abstractive vs extractive: Abstractive is more human-like but risks hallucination; extractive is safer but less coherent
  - Transfer learning vs training from scratch: Transfer learning is faster but may not be optimal for specific task
  - Automated vs manual evaluation: Automated methods are scalable but may miss nuances
- Failure signatures:
  - Low F1 score: Poor rationale quality or mismatch between premise and choices
  - Low NLI entailment: Rationale does not logically support the verdict
  - Hallucination in NLE: Abstractive generation introduces false information
  - Biased verdicts: Evidence sources are not neutral or balanced
- First 3 experiments:
  1. Compare abstractive (BART) vs extractive summarization for rationale quality using manual annotation
  2. Test different formulations of the QA input to optimize T5 performance
  3. Evaluate impact of removing biased evidence sources on verdict classification accuracy

## Limitations
- Evaluation methodology relies heavily on automated metrics (SHAP and NLI) that may not fully capture explanation quality
- Dataset construction removes politically biased sources, potentially introducing selection bias
- Abstractive summarization risks introducing hallucinated content that could compromise verification accuracy

## Confidence

**High Confidence**: ExClaim achieves 0.93 F1 score on verdict classification using T5-based COPA formulation; system outperforms DistilBERT on all evaluation measures; abstractive summarization generates higher quality rationales

**Medium Confidence**: SHAP-based evaluation effectively measures rationale quality without ground truth; Pareto principle applies to claim verification tasks; NLE generation successfully combines claim, rationale, and verdict

**Low Confidence**: Manual annotation sample size (100 NLEs) is sufficient for conclusions; removal of politically biased sources does not significantly impact performance; explainability features significantly improve user trust
