## Executive Summary
This paper introduces a novel approach to query rewriting (QR) in conversational AI by leveraging graph-based collaborative filtering and large language models (LLMs). The method addresses the challenge of unseen user interactions by constructing a User Feedback Interaction Graph (FIG) from historical user-entity interactions, then using multi-hop graph traversal to enrich user indexes with rewrite candidates from similar users. To further enhance performance, the approach incorporates LLM-augmented link prediction to boost the FIG's effectiveness. The system shows significant improvements in handling unseen defective queries compared to traditional graph traversal methods alone.

## Method Summary
The approach builds a User Feedback Interaction Graph (FIG) from historical user-entity interactions, where nodes represent users and entities, and edges represent successful interactions. Multi-hop graph traversal enriches each user's index with rewrite candidates from similar users, expanding coverage of future unseen defective queries. To maintain precision with the enlarged index, the system adds transformer layers to the L1 retrieval model and incorporates graph-based and guardrail features into the L2 ranking model. The paper also explores using a fine-tuned Dolly-V2 7B LLM to enhance the FIG for user-entity link prediction, significantly boosting QR performance on unseen queries.

## Key Results
- LLM-augmented FIG significantly outperforms graph traversal-only approach for query rewriting
- Collaborative filtering via multi-hop graph traversal expands coverage of unseen defective queries
- System effectively balances precision and recall through transformer layer additions and feature engineering

## Why This Works (Mechanism)
The approach works by leveraging collective intelligence from user interaction patterns rather than relying solely on individual user history. By building a User Feedback Interaction Graph, the system captures similarities between users based on their successful interactions with entities. Multi-hop traversal allows information to propagate across the graph, enabling users with similar preferences to benefit from each other's successful interactions. The LLM component enhances this process by providing more accurate link predictions, effectively bridging gaps in the graph where direct connections may be missing.

## Foundational Learning
- User Feedback Interaction Graph (FIG): A graph where nodes represent users and entities, and edges represent successful interactions. Needed to capture collective user behavior patterns for collaborative filtering.
- Multi-hop graph traversal: A technique to find indirect connections between nodes through intermediate nodes. Quick check: Can be implemented using breadth-first search or personalized PageRank algorithms.
- Transformer layers for retrieval: Additional transformer layers that process retrieved candidates to improve ranking. Needed to handle the expanded index size while maintaining precision.
- LLM-augmented link prediction: Using fine-tuned LLMs to predict missing links in the interaction graph. Quick check: Can be implemented using fine-tuned language models with graph-specific prompts.

## Architecture Onboarding

Component Map:
User Query -> FIG Construction -> Multi-hop Traversal -> L1 Retrieval (with transformer layers) -> L2 Ranking (with graph features) -> Final Query Rewrite

Critical Path:
1. User submits query
2. FIG retrieves similar users via multi-hop traversal
3. L1 retrieval model processes candidates with transformer layers
4. L2 ranking model applies graph-based and guardrail features
5. Final rewritten query is generated

Design Tradeoffs:
- Graph complexity vs. computational efficiency: More hops improve coverage but increase computation
- Index size vs. precision: Larger indexes capture more patterns but may introduce noise
- LLM integration vs. scalability: LLMs improve accuracy but add computational overhead

Failure Signatures:
- Precision degradation when index size grows too large
- Performance bottlenecks in multi-hop traversal for very large graphs
- LLM inference latency limiting real-time response capabilities

First Experiments:
1. Compare performance with different hop depths (1-hop vs 2-hop vs 3-hop)
2. Measure precision-recall tradeoff at different index expansion ratios
3. Benchmark LLM-augmented vs non-LLM link prediction performance

## Limitations
- Scalability concerns when building and maintaining User Feedback Interaction Graph for large-scale deployments
- Computational overhead from additional transformer layers and multi-hop graph traversal
- Methodology assumes sufficient historical interaction data exists, which may not hold for new applications with sparse user interactions
