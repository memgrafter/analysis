# GETT-QA: Graph Embedding based T2T Transformer for Knowledge Graph Question Answering

## Quick Facts
- arXiv ID: 2303.13284
- Source URL: https://arxiv.org/abs/2303.13284
- Authors: Multiple authors
- Reference count: 40
- Primary result: GETT-QA achieves 0.403 macro precision on LC-QuAD 2.0 (8% improvement) and 0.761 macro F1 on SimpleQuestions-Wikidata (13% improvement)

## Executive Summary
GETT-QA is a knowledge graph question answering system that generates SPARQL queries using T5, a text-to-text transformer. Instead of directly producing entity and relation IDs, it generates corresponding labels and truncated KG embeddings. These embeddings aid in entity disambiguation by enabling finer search. The model learns to produce these embeddings without any change to the loss function. GETT-QA achieves strong results on LC-QuAD 2.0 and SimpleQuestions-Wikidata datasets, outperforming existing methods.

## Method Summary
GETT-QA fine-tunes T5-Base to generate skeleton SPARQL queries containing entity labels and truncated KG embeddings. For inference, it extracts labels and embeddings from T5 output, retrieves entity candidates via Elasticsearch BM-25 search, and re-ranks top candidates using label matching combined with embedding dot product similarity. Relations are matched using BERT embedding similarity. The system executes top candidate SPARQL queries on Wikidata KG until a non-empty result is found.

## Key Results
- Achieves 0.403 macro precision on LC-QuAD 2.0, 8% improvement over baseline
- Achieves 0.761 macro F1 on SimpleQuestions-Wikidata, 13% improvement over nearest competitor
- Outperforms existing methods on both standard KGQA benchmarks

## Why This Works (Mechanism)

### Mechanism 1
T5 learns to generate truncated KG embeddings without explicit embedding training loss by mapping linguistic patterns in questions to both textual tokens and numeric vector strings. The model handles mixed output (text and numeric vectors) while maintaining SPARQL structure coherence.

### Mechanism 2
Truncated KG embeddings improve entity disambiguation by providing semantic similarity information beyond labels. A two-stage candidate ranking uses label-based search followed by truncated embedding similarity re-ranking to handle label collisions.

### Mechanism 3
T5's pre-trained language understanding transfers effectively to semantic parsing of SPARQL queries by casting SPARQL generation as text-to-text transformation, leveraging pre-training to understand question semantics and produce structured query components.

## Architecture Onboarding

- **Component map**: T5 model -> Elasticsearch database -> Candidate ranking and re-ranking components -> KG execution layer

- **Critical path**: Question input → T5 generation of skeleton SPARQL → Extract labels and truncated embeddings → Label-based candidate retrieval (Elasticsearch) → Embedding-based re-ranking → Relation candidate matching → Candidate combination and KG query execution → Answer output

- **Design tradeoffs**: Using truncated vs full embeddings balances dimensionality and semantic information; number of candidates (k=6 entities, k=3 relations) balances accuracy vs computational cost; text-to-text approach simplifies implementation but requires post-processing

- **Failure signatures**: Incorrect entity grounding despite high confidence scores; SPARQL generation failures or syntax errors; slow response times due to large candidate sets; poor performance on questions with rare entities

- **First 3 experiments**: 1) Test T5 generation with varying truncated embedding lengths (10, 20, 30 dimensions); 2) Evaluate candidate ranking by comparing label-only vs label+embedding approaches; 3) Measure impact of different k values on accuracy and response time

## Open Questions the Paper Calls Out

### Open Question 1
How does the performance of GETT-QA change with different truncated KG embedding lengths? The paper only explores a limited range (30, 10, 5, 3) without investigating the optimal length for performance.

### Open Question 2
How does GETT-QA compare to other state-of-the-art KGQA systems on a larger and more diverse set of datasets? The evaluation is limited to LC-QuAD 2.0 and SimpleQuestions-Wikidata without comprehensive comparison to other systems.

### Open Question 3
How does GETT-QA's performance change with different pre-trained language models (PLMs) other than T5? The paper uses T5 exclusively without exploring whether other PLMs could improve performance.

## Limitations

- Truncated KG embeddings mechanism lacks direct corpus validation - effectiveness is assumed rather than proven through ablation studies
- Exact Wikidata KG snapshot and embedding files used are unspecified, creating reproducibility barriers
- Entity disambiguation effectiveness of truncated embeddings is asserted but not empirically verified through embedding quality metrics

## Confidence

- **High confidence**: Overall architecture design is well-established and reported metrics on standard benchmarks appear credible
- **Medium confidence**: Specific mechanism of learning truncated KG embeddings through T5 generation is plausible but lacks direct empirical validation
- **Low confidence**: Assertion that no change to loss function is needed for learning embeddings lacks evidence about what would happen with modified loss

## Next Checks
