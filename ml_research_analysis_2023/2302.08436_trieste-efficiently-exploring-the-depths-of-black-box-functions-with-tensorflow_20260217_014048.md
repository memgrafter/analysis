# Trieste: Efficiently Exploring The Depths of Black-box Functions with TensorFlow

## Quick Facts
- arXiv ID: 2302.08436
- Source URL: https://arxiv.org/abs/2302.08436
- Reference count: 9
- Trieste is an open-source Python package for Bayesian optimization and active learning that integrates with TensorFlow

## Executive Summary
Trieste is an open-source Python package for Bayesian optimization and active learning that leverages TensorFlow's capabilities for scalable probabilistic modeling. The library provides a modular framework that allows users to plug in their own models and acquisition functions while maintaining efficient sequential decision-making loops. It supports both real-world and synthetic optimization scenarios through two distinct interfaces and integrates with popular TensorFlow modeling libraries like GPflow, GPflux, and Keras.

## Method Summary
Trieste implements Bayesian optimization through a modular architecture where acquisition functions, rules, and models operate as independent components communicating through well-defined interfaces. The library avoids TensorFlow graph retracing by carefully managing the computational graph during sequential optimization loops. It provides two main interfaces: AskTellOptimizer for scenarios requiring external control over function evaluations (useful for real-world settings like laboratory experiments or distributed computing), and BayesianOptimizer for direct function calls in synthetic problems. Automatic differentiation is leveraged to provide gradients for acquisition functions without manual specification, while parallelized L-BFGS-B optimization handles the computational complexity.

## Key Results
- Modular architecture enables plug-and-play of TensorFlow models in BO loops while avoiding graph retracing
- Two interface modes support both real-world scenarios (AskTellOptimizer) and synthetic optimization problems (BayesianOptimizer)
- Automatic differentiation eliminates the need for users to manually derive gradients for acquisition functions

## Architecture Onboarding

- Component map: AcquisitionFunction -> AcquisitionRule -> ProbabilisticModel -> Interface (AskTellOptimizer or BayesianOptimizer) -> Evaluation -> Model update
- Critical path: Model → AcquisitionFunction → AcquisitionRule → Interface → Evaluation → Model update. The model and acquisition function must be compatible in their input/output formats.
- Design tradeoffs: Flexibility vs performance (modular design enables customization but adds overhead), TensorFlow compatibility vs algorithmic purity (leveraging TensorFlow features vs implementing from scratch), real-world vs synthetic optimization (AskTell vs direct interface).
- Failure signatures: Poor convergence (acquisition function not matching problem structure), slow iterations (graph retracing not properly handled), memory issues (models not properly releasing resources), interface mismatches (wrong data formats between components).
