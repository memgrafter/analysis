# Language-guided Task Adaptation for Imitation Learning

## Quick Facts
- arXiv ID: 2301.09770
- Source URL: https://arxiv.org/abs/2301.09770
- Authors: 
- Reference count: 22
- Primary result: RETAIL framework achieves 70-90% of oracle success rates on Room Rearrangement and Room Navigation tasks by combining reward and policy adaptation

## Executive Summary
This paper introduces a new problem setting where an agent learns a target task from a demonstration of a related source task, guided by natural language describing the difference between the tasks. The authors create two new benchmarks—Room Rearrangement and Room Navigation—covering various types of task adaptations in both discrete and continuous domains. They propose a relational approach using transformer-based models to reason about entities and their relationships. The RETAIL framework combines two methods: inferring a reward function for the target task and adapting a policy from the source task. Experiments show that the combined approach significantly outperforms using either method alone, achieving success rates around 70-90% of an oracle baseline across both domains.

## Method Summary
The RETAIL framework addresses language-guided task adaptation by combining reward function inference and policy adaptation approaches. The relational model encodes entities (objects and agent) using attribute, noun, and position embeddings, then processes them with a transformer alongside language descriptions. For reward adaptation, it learns a goal prediction module that maps source goals and language to target goals, combined with a distance function to create potential-based rewards. For policy adaptation, it learns a goal-conditioned policy for the source task, then adapts actions using a transformer that reasons about language and entity relationships. The combined approach initializes PPO with knowledge from both methods and fine-tunes using the predicted reward function.

## Key Results
- RETAIL framework achieves success rates of 70-90% compared to oracle baselines across both Room Rearrangement and Room Navigation tasks
- Combining reward and policy adaptation significantly outperforms using either method alone
- CLIP language encoder performs best, with no substantial differences between other encoders due to simple language descriptions
- Goal prediction error is approximately 0.15 for source tasks and 0.25 for target tasks

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The relational reward adaptation approach works because it learns a goal prediction module that maps the source goal and language description to a target goal, then combines this with a learned distance function to create a reward function.
- **Mechanism:** The goal prediction module uses a transformer to encode entities and language, then predicts target goal positions. The distance function learns embeddings that capture state similarity. Together they form a potential-based reward: R(s, s') = φ(s') - φ(s) = -d(s', Adapt(gsrc, l)) + d(s, Adapt(gsrc, l)).
- **Core assumption:** The source demonstration and language description together contain sufficient information to infer the target goal, and a learnable distance function can accurately measure progress toward this goal.

### Mechanism 2
- **Claim:** The relational policy adaptation approach works by learning a goal-conditioned policy for the source task, then adapting it to the target task using language and action information.
- **Mechanism:** First, a goal-conditioned policy π(a|s, g) is learned via behavior cloning on source and target demonstrations. Then, for each state, the source action is predicted, and a transformer-based model adapts this action to the target action using language and entity information.
- **Core assumption:** Actions in related tasks can be mapped through a learnable transformation that depends on the state entities and language description of the difference.

- **Core assumption:** Initializing PPO with predictions from both approaches provides a better starting point than random initialization, leading to faster and more effective learning.

## Foundational Learning

- **Concept:** Transformer-based relational reasoning
  - **Why needed here:** The tasks require reasoning about entities (objects, agent) and their relationships (positions, relative distances) to interpret language descriptions and adapt demonstrations.
  - **Quick check question:** Can you explain how the transformer encodes both entity positions and language tokens together to predict target goals?

- **Concept:** Goal-conditioned policy learning
  - **Why needed here:** The policy adaptation approach requires learning a policy that can operate toward any specified goal, enabling action prediction for both source and target tasks from the same model.
  - **Quick check question:** How does the goal-conditioned policy π(a|s, g) differ from a standard policy, and why is this useful for the adaptation approach?

- **Concept:** Inverse reinforcement learning via potential functions
  - **Why needed here:** The reward adaptation approach learns a potential function that measures progress toward the target goal, enabling RL without explicit reward engineering.
  - **Quick check question:** What is the relationship between the learned potential function and the distance function in the reward adaptation approach?

## Architecture Onboarding

- **Component map:** Entity Encoder → Language Encoder → Transformer reasoning → Goal prediction or Action adaptation → RL training or direct execution
- **Critical path:** Language → Entity Encoder + Language Encoder → Transformer reasoning → Goal prediction or Action adaptation → RL training or direct execution
- **Design tradeoffs:**
  - Language encoder choice: Pretrained models (CLIP, BERT) offer better generalization but less flexibility; learned models (random BERT, GloVe+LSTM) can specialize but may overfit
  - Reward vs Policy Adaptation: Reward adaptation enables RL for complex tasks but requires more computation; Policy adaptation can work without RL but may be less accurate
  - Knowledge distillation entropy: Too low entropy prevents exploration during RL fine-tuning
- **Failure signatures:**
  - Poor goal prediction: High mean absolute error on validation set, agent moves toward wrong locations
  - Poor action adaptation: Low success rates in policy adaptation without RL, actions don't match target task requirements
  - RL training instability: High variance in success rates across seeds, learning curves that plateau early
- **First 3 experiments:**
  1. Train goal prediction module on synthetic language only, evaluate on validation set with mean absolute error
  2. Train distance function on demonstration data, verify it learns monotonic distance relationships
  3. Run policy adaptation without RL on test tasks, measure success rates to establish baseline performance

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the relational model's performance change when using different language encoders, especially in more complex language scenarios?
- Basis in paper: [explicit] The paper mentions experimenting with four different language encoders (CLIP, BERT, random BERT, GloVe+LSTM) but found no substantial difference due to the simplicity of the language descriptions used.
- Why unresolved: The paper explicitly notes that the language descriptions were relatively simple, suggesting that performance differences might emerge with more complex language scenarios.
- What evidence would resolve it: Testing the relational model with more complex and diverse language descriptions to evaluate how different language encoders impact performance.

### Open Question 2
- Question: How would the performance of the relational reward adaptation approach change if the entity extraction process was automated rather than assumed?
- Basis in paper: [inferred] The paper assumes access to a set of entities for each task, with each entity represented using attribute and noun one-hot vectors, but does not explore how automated entity extraction might affect performance.
- Why unresolved: The paper does not address the potential challenges or performance impacts of automating entity extraction, which is a critical step in real-world applications.
- What evidence would resolve it: Implementing and testing the relational reward adaptation approach with an automated entity extraction method to compare its performance against the assumed entity extraction method.

### Open Question 3
- Question: How would the relational policy adaptation approach perform if it incorporated a mechanism to adjust the importance of datapoints based on their proximity to the goal?
- Basis in paper: [inferred] The paper mentions that errors in the relational policy adaptation approach seem to get larger as the agent gets closer to the target goal, suggesting a potential improvement by weighting datapoints differently.
- Why unresolved: The paper acknowledges the issue but does not implement or test a solution, leaving the potential benefits of such an adjustment unexplored.
- What evidence would resolve it: Implementing a modified training algorithm for the relational policy adaptation approach that weights datapoints based on their proximity to the goal and evaluating its performance compared to the current approach.

## Limitations

- The benchmarks focus on relatively simple room rearrangement and navigation tasks that may not capture real-world complexity
- Evaluation relies heavily on success rate metrics without deeper analysis of failure modes or sample efficiency
- Language descriptions are generated synthetically, which may not reflect the ambiguity and variability of natural language instructions

## Confidence

- High confidence in the architectural framework and its ability to combine reward and policy adaptation
- Medium confidence in the benchmark design and its coverage of different adaptation scenarios
- Medium confidence in the experimental results, particularly the comparison with oracle baselines
- Low confidence in the scalability of the approach to more complex, real-world tasks

## Next Checks

1. Test the framework on more complex environments with higher-dimensional state spaces and longer task horizons to evaluate scalability
2. Conduct human studies where real users provide language descriptions to assess robustness to natural language ambiguity and variability
3. Implement ablation studies to quantify the individual contributions of reward adaptation, policy adaptation, and their combination across different task similarity levels
