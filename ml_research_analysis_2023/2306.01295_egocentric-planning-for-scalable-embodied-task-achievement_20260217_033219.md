# Egocentric Planning for Scalable Embodied Task Achievement

## Quick Facts
- **arXiv ID**: 2306.01295
- **Source URL**: https://arxiv.org/abs/2306.01295
- **Reference count**: 40
- **Key outcome**: 36.07% success rate on unseen ALFRED tasks, winning the ALFRED challenge

## Executive Summary
Egocentric Planning combines symbolic planning and Object-oriented POMDPs to solve tasks in complex environments by leveraging visual perception and NLP models. The method alternates between exploration and planning phases, using classical planners to generate action sequences when sufficient information is available and switching to goal-oriented exploration otherwise. Tested on ALFRED, it achieved a 36.07% success rate on unseen tasks, winning the ALFRED challenge and outperforming prior methods by 8.3%. The approach scales to new tasks without additional training, provided the environment supports the required actions and object types.

## Method Summary
The method implements an egocentric planner that alternates between exploration and planning phases. It starts with a 500-step random exploration to build a semantic spatial graph, then uses classical PDDL planners to generate action sequences when sufficient information is available. If planning fails due to incomplete information, the agent switches to goal-oriented exploration to gather missing data about anchor objects. The approach integrates pre-trained FILM vision and language modules for object detection, depth estimation, and task parsing, with a semantic graph serving as persistent memory to bridge grounded objects and the state representation required for planning.

## Key Results
- Achieved 36.07% success rate on unseen ALFRED tasks
- Won the ALFRED challenge, outperforming prior methods by 8.3%
- Demonstrated zero-shot generalization to new tasks without additional training
- Successfully combined symbolic planning with Object-oriented POMDPs for embodied task achievement

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Egocentric planning enables goal-oriented exploration by alternating between full-observability symbolic planning and object-based POMDP reasoning.
- Mechanism: The agent uses a symbolic planner for fully-observable environments to determine if the current state has enough knowledge to achieve the goal. If more information is needed, it switches to goal-oriented exploration to gather missing information about anchor objects.
- Core assumption: A subset of object types (anchor objects) can reveal information about other objects, and exploration actions allow visiting new anchor objects.
- Evidence anchors:
  - [abstract]: "The method alternates between exploration and planning phases, using classical planners to generate action sequences when sufficient information is available and switching to goal-oriented exploration otherwise."
  - [section 5.2]: "Our exploration and sensing strategy hinges on two elements. First, anchor object types Ta are types of objects that reveal the presence of others. Second, exploration actions X enables the discovery of previously unknown objects."
- Break condition: If anchor objects do not reliably reveal information about other objects, or if exploration actions cannot effectively discover new anchor objects.

### Mechanism 2
- Claim: The semantic spatial graph provides a persistent memory structure that bridges grounded objects and the state representation required for planning.
- Mechanism: The graph stores object classes, segmentation masks, and depth information as nodes, with edges representing agent actions. This allows the agent to maintain an incremental egocentric view of the environment and update its mental state with new perceptions.
- Core assumption: Visual perception can reliably extract object information within a reachable distance threshold, and this information can be stored and retrieved from the spatial graph.
- Evidence anchors:
  - [section 6.1]: "The spatial graph, acting as the agent's memory during exploration, bridges grounded objects and the state representation required for our planner."
  - [section 6.1]: "Each node in the graph stores object classes, segmentation masks, and depth information generated by the vision module."
- Break condition: If visual perception fails to extract object information accurately, or if the spatial graph cannot maintain a consistent representation of the environment.

### Mechanism 3
- Claim: The integration of language and vision modules with symbolic planning enables zero-shot generalization to new tasks within the same object types and action signatures.
- Mechanism: The language module converts natural language task descriptions into goal conditions for PDDL, while the vision module grounds visual information into symbolic representations. This allows the planner to autonomously generate action sequences for new tasks without additional training.
- Core assumption: The language module can reliably extract task goals from natural language descriptions, and the vision module can ground visual information into the same object types and action signatures used in the planning domain.
- Evidence anchors:
  - [abstract]: "The approach scales to new tasks without additional training, provided the environment supports the required actions and object types."
  - [section 8.4]: "Our approach allows zero-shot generalization to new tasks within the same set of objects and relationships, offering adaptability to new instructions."
- Break condition: If the language module cannot reliably extract task goals, or if the vision module cannot ground visual information into the required object types and action signatures.

## Architecture Onboarding

- Component map: Language Module → Vision Module → Semantic Spatial Graph → Egocentric Planner → ALFRED Environment
- Critical path: Language Module → Vision Module → Semantic Spatial Graph → Egocentric Planner → ALFRED Environment
- Design tradeoffs:
  - Exploration vs. Planning: Balancing the initial exploration phase with the need for efficient planning
  - Symbolic vs. Neural: Combining the strengths of symbolic planning with neural perception and language modules
  - Generalization vs. Specificity: Enabling zero-shot generalization while maintaining task-specific performance
- Failure signatures:
  - Language processing errors: Incorrect goal conditions leading to suboptimal or failed plans
  - Visual perception errors: Missing or incorrect object information affecting the semantic spatial graph
  - Planning errors: Inability to find a valid plan due to incomplete or incorrect state information
- First 3 experiments:
  1. Test the language module's ability to convert natural language task descriptions into valid PDDL goal conditions
  2. Evaluate the vision module's performance in extracting object information from egocentric images and updating the semantic spatial graph
  3. Assess the egocentric planner's ability to generate valid action sequences for simple tasks with known object locations

## Limitations
- The approach's reliance on pre-trained FILM modules for perception and language processing introduces dependency on external model performance
- The evaluation focuses exclusively on the ALFRED benchmark, limiting generalizability to other embodied environments
- The paper does not provide detailed ablation studies showing the individual contributions of each component to overall performance

## Confidence

- **High Confidence**: The core mechanism of alternating between exploration and planning phases is well-supported by the described architecture and demonstrated through the winning performance in the ALFRED challenge. The integration of symbolic planning with POMDP reasoning is technically sound.

- **Medium Confidence**: The zero-shot generalization capability claim is supported by the method's design but lacks extensive empirical validation across diverse task types beyond ALFRED. The assumption that anchor objects reliably reveal information about other objects needs more rigorous testing.

- **Low Confidence**: The scalability claims to new environments and task types are largely theoretical, based on the method's architecture rather than demonstrated through systematic experimentation with different environments or object-action sets.

## Next Checks
