# Dialog act guided contextual adapter for personalized speech recognition

## Quick Facts
- arXiv ID: 2303.17799
- Source URL: https://arxiv.org/abs/2303.17799
- Reference count: 0
- This paper addresses personalized speech recognition in multi-turn dialogues by leveraging dialog acts and user catalogs to improve rare word recognition.

## Executive Summary
This paper tackles the challenge of recognizing rare, user-specific words (like contact names) in multi-turn dialogues using end-to-end ASR models. The proposed solution introduces a dialog act guided contextual adapter that uses dialog acts to select relevant user catalogs and create better biasing queries. The approach combines dialog act conditioning with audio representation fusion to enhance predictions. The model is trained in two stages: first pre-training a DA-aware RNN-T, then fine-tuning the biasing components through contextual adaptation.

## Method Summary
The method introduces a two-stage training approach for personalized speech recognition. First, a dialog act aware RNN-T model is pre-trained using both audio and dialog act features. Then, a contextual adaptation stage fine-tunes the biasing components. The core innovation is using dialog acts to guide catalog selection and query creation for a contextual biasing network. This allows the model to leverage user-specific information (contact lists, app names, etc.) while maintaining the ability to recognize generic words. The approach fuses dialog act information with audio representations to improve rare word recognition in multi-turn dialogues.

## Key Results
- Achieves 58% relative word error rate reduction (WERR) on user-specific multi-turn dialogues
- Outperforms DA-only baseline (1.49% WERR) and prior contextual adapter (39% WERR)
- Demonstrates effectiveness of dialog act guided catalog selection and audio-fusion approach

## Why This Works (Mechanism)
The approach works by using dialog acts as semantic context to select relevant user catalogs, creating more targeted biasing queries. Dialog acts provide information about the user's intent and conversation state, allowing the model to predict which user-specific entities are most likely to appear. By fusing this contextual information with audio representations, the model can better distinguish between similar-sounding rare words and common vocabulary. The two-stage training ensures the base ASR model learns good dialog act representations before fine-tuning the biasing components.

## Foundational Learning
- **Dialog acts (DA)**: Labels representing speaker intent and conversation function. Needed to provide semantic context for catalog selection. Quick check: Can you identify the dialog act in "I want to call John"?
- **Contextual biasing**: Technique to improve recognition of specific vocabulary based on conversation context. Needed to personalize ASR for user-specific entities. Quick check: How does biasing differ from traditional language model adaptation?
- **RNN-T (Recurrent Neural Network Transducer)**: End-to-end sequence-to-sequence model for speech recognition. Needed as the base architecture for streaming ASR. Quick check: What are the three components of an RNN-T?
- **Catalog-based personalization**: Using user-specific lists of entities (contacts, apps, etc.) to improve recognition. Needed to handle rare words specific to individual users. Quick check: How do catalogs differ from traditional pronunciation dictionaries?
- **Two-stage training**: First pre-train base model, then fine-tune biasing components. Needed to ensure stable learning of both general and personalized recognition capabilities. Quick check: Why not train all components together from scratch?

## Architecture Onboarding

Component map: Audio -> RNN-T Encoder -> DA Encoder -> Catalog Selector -> Biasing Network -> Decoder

Critical path: Audio input flows through RNN-T encoder, dialog act features are encoded separately, both are combined to select relevant catalogs and create biasing queries, which are then used to influence the decoder's predictions.

Design tradeoffs: The approach balances between leveraging user-specific information (catalogs) and maintaining generalization to common vocabulary. Using dialog acts for catalog selection adds computational overhead but improves precision. The two-stage training approach requires more training time but provides better stability.

Failure signatures: Poor dialog act recognition would lead to incorrect catalog selection and degraded performance. If the audio-fusion component fails, the model might ignore valuable contextual information. Overly aggressive biasing could cause the model to hallucinate user-specific entities that weren't actually spoken.

Three first experiments: 1) Test dialog act recognition accuracy on the dataset, 2) Measure catalog selection precision when using perfect dialog acts, 3) Evaluate the impact of removing the audio-fusion component.

## Limitations
- Evaluation limited to a single industrial voice assistant dataset, raising generalization concerns
- 58% WERR improvement highly dependent on specific dialog act and catalog setup
- No analysis of computational overhead or real-time deployment feasibility
- Incomplete ablation studies - individual contributions of dialog act selection versus catalog fusion not isolated

## Confidence
- Dialog act guided contextual adapter improves rare word recognition: High
- Two-stage training approach is effective: Medium
- 58% WERR improvement on industrial dataset: Medium
- DA-only baseline improvement of 1.49% WERR: High
