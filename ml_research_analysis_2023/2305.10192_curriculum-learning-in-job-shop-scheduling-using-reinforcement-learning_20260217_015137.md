# Curriculum Learning in Job Shop Scheduling using Reinforcement Learning

## Quick Facts
- arXiv ID: 2305.10192
- Source URL: https://arxiv.org/abs/2305.10192
- Reference count: 26
- Key outcome: Agents trained on curricula starting with hardest instances achieve 3.2% shorter average makespans compared to agents trained without a curriculum.

## Executive Summary
This paper addresses the job shop scheduling problem (JSSP) using curriculum learning (CL) to improve deep reinforcement learning (DRL) solutions. The authors introduce a "difficulty to solve" (DTS) metric based on priority dispatching rule performance to rank problem instances. By training agents on curricula ordered by difficulty, particularly starting with hardest instances, they achieve significant improvements in makespan reduction compared to randomly ordered training. The work demonstrates CL's effectiveness in JSSP and highlights DTS as a promising difficulty metric.

## Method Summary
The authors propose using curriculum learning for JSSP by ranking problem instances based on how well established priority dispatching rules (PDRs) perform on them. They generate 40,000 random 6x6 JSSP instances and compute DTS values using the MTR rule. Training curricula are created by sorting instances by DTS and splitting them into easy and hard halves, with both original and reversed orderings tested. DRL agents are trained on these curricula and compared against baseline agents trained on randomly ordered data.

## Key Results
- Agents trained on hardest-first curricula achieve 3.2% shorter average makespans than agents trained without curriculum
- Curriculum ordering significantly impacts learning efficiency and final performance
- DTS metric effectively discriminates between problem instance difficulties
- Agents trained on hardest instances first show faster convergence to better strategies

## Why This Works (Mechanism)

### Mechanism 1
Ordering training instances by DTS improves learning efficiency because DTS ranks instances by PDR performance. Training starts with hardest instances so the agent learns robust strategies under challenging conditions early, leading to better generalization and faster convergence. Core assumption: PDR performance is a reliable proxy for instance difficulty, and agents trained first on hard instances can transfer that knowledge to easier ones.

### Mechanism 2
Starting with hardest instances leads to larger negative reward signals, pushing the agent toward effective strategies faster. Harder instances produce larger makespans, hence larger magnitude negative rewards. This stronger signal accelerates learning of strategies that effectively reduce large optimality gaps early in training. Core assumption: Stronger reward signals from harder instances produce more informative gradients for the agent's policy network.

### Mechanism 3
The DTS metric enables curriculum learning within a fixed problem size, a gap not addressed by prior work. By ranking instances of the same size by PDR performance, the method creates sub-goals within the same computational complexity class, allowing fine-grained curriculum design rather than just varying problem sizes. Core assumption: Difficulty variation exists within fixed-size JSSPs and can be meaningfully quantified by PDR performance.

## Architecture Onboarding

- Component map: Training data generator -> PDR solver -> DRL agent -> Curriculum manager -> Evaluation loop

- Critical path:
  1. Generate and solve training instances with MTR → compute DTS
  2. Sort instances by DTS → create curriculum elements (easy/hard, normal/reversed)
  3. Train DRL agent on curriculum-ordered data
  4. Periodically evaluate on test set
  5. Compare performance across curricula

- Design tradeoffs:
  - Using MTR PDR to compute DTS is fast but may not reflect optimal difficulty
  - Curriculum design (hard-first vs easy-first) directly affects learning trajectory
  - Fixed test set ensures comparability but may not capture generalization to unseen distributions

- Failure signatures:
  - Agent performance plateaus early without further improvement
  - Curriculum ordering has no effect on learning curves
  - High variance in results across random seeds
  - DTS values cluster tightly, reducing curriculum granularity

- First 3 experiments:
  1. Train baseline agent on randomly ordered data (no curriculum) to establish performance floor.
  2. Train agent on hardest-first curriculum (h_r) to test hard-start hypothesis.
  3. Train agent on easiest-first curriculum (e_n) to confirm that curriculum ordering matters.

## Open Questions the Paper Calls Out

### Open Question 1
Would using the optimality gap instead of makespan as the difficulty to solve (DTS) metric lead to even better curriculum learning results? The paper suggests that a strategy minimizing large optimality gaps may be incentivized through a curriculum, but notes this requires solving every training instance optimally, which is computationally expensive.

### Open Question 2
How does the proposed curriculum learning approach perform on JSSP instances with more than 6 machines? The paper only tested the approach on 6x6 JSSP instances, and notes that transferring the methodology to other scheduling problems with more challenging objectives and constraints is necessary.

### Open Question 3
Can combining multiple priority dispatching rules as the basis for the DTS metric improve curriculum learning performance? The paper uses a single priority dispatching rule (MTR) for the DTS metric and suggests investigating other metrics that may stem from priority dispatching rules combined for better performance.

## Limitations
- DTS metric effectiveness relies on correlation between PDR performance and true instance difficulty
- Results limited to 6x6 JSSP instances, scalability to larger problems unknown
- Explanation for hardest-first curriculum superiority remains speculative without deeper policy analysis

## Confidence
- DTS metric effectiveness: Medium
- Hardest-first curriculum superiority: Medium
- 3.2% makespan improvement claim: High
- Generalizability to other problem sizes: Low

## Next Checks
1. Conduct ablation studies testing alternative difficulty metrics beyond PDR performance to validate DTS robustness.
2. Analyze learned policies from different curricula to identify specific strategy differences between hard-first and easy-first approaches.
3. Test curriculum learning effectiveness on larger JSSP instances (e.g., 10x10 or 20x20) to assess scalability.
