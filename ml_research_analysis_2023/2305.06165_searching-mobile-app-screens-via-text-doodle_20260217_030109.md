# Searching Mobile App Screens via Text + Doodle

## Quick Facts
- arXiv ID: 2305.06165
- Source URL: https://arxiv.org/abs/2305.06165
- Reference count: 40
- Primary result: TpD achieves 93.13% top-10 accuracy for mobile app screen search using text + sketch input

## Executive Summary
TpD is an interactive system that enables searching mobile app screens through combined text and sketch input. The system leverages a repository of 58k Android app screens and incorporates techniques from PSDoodle for sketch recognition. Users can draw UI elements and add text queries with positional annotations to refine their search results.

The system demonstrates significant performance improvements over state-of-the-art tools, reducing average search time from 246 seconds (Swire) and 107 seconds (PSDoodle) to just 45 seconds while achieving 93.13% top-10 accuracy. The architecture combines a deep neural network for sketch recognition with Elasticsearch for indexing and searching screen contents.

## Method Summary
TpD implements an iterative search system that combines sketch recognition with text-based queries for mobile app screens. The method involves preprocessing screen texts and UI descriptions through lemmatization and synonym expansion, then using a deep neural network for sketch recognition. The system employs Elasticsearch for indexing and searching screen contents, with a ranking algorithm that combines sketch similarity, text relevance, and positional annotations. The evaluation was conducted with third-party software developers using the Rico repository of 58k Android app screens.

## Key Results
- Achieved 93.13% top-10 accuracy in mobile app screen search
- Reduced average search time to 45 seconds (compared to 107s for PSDoodle, 246s for Swire)
- Outperformed state-of-the-art tools Swire and PSDoodle in both accuracy and speed

## Why This Works (Mechanism)
The system works by combining multiple search modalities - sketch recognition and text queries - with positional awareness. The deep neural network accurately recognizes sketched UI elements, while Elasticsearch efficiently indexes and searches preprocessed screen content. The ranking algorithm balances sketch similarity, text relevance, and spatial relationships between query elements. Preprocessing steps like lemmatization and synonym expansion improve text matching accuracy.

## Architecture Onboarding

Component Map:
User Input -> Sketch Recognition -> Text Preprocessing -> Elasticsearch Index -> Ranking Algorithm -> Results Display

Critical Path:
1. User draws sketch and adds text query
2. Sketch recognition produces UI element labels
3. Text preprocessing and synonym expansion
4. Elasticsearch searches indexed screens
5. Ranking algorithm combines results
6. Top results displayed to user

Design Tradeoffs:
- Accuracy vs. search speed (optimized for 45s average)
- Complexity of preprocessing vs. matching quality
- Sketch detail vs. recognition reliability

Failure Signatures:
- Poor sketch recognition leading to irrelevant results
- Incorrect text preprocessing causing missed matches
- Ranking algorithm producing unexpected orderings

First Experiments:
1. Test sketch recognition accuracy with simple UI elements
2. Verify Elasticsearch indexing of preprocessed text
3. Validate ranking algorithm with controlled test queries
