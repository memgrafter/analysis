# Integrating Eye-Gaze Data into CXR DL Approaches: A Preliminary study

## Quick Facts
- arXiv ID: 2302.02940
- Source URL: https://arxiv.org/abs/2302.02940
- Reference count: 35
- Primary result: Multimodal model using eye-tracking data underperformed image-only baseline for CXR abnormality detection

## Executive Summary
This study investigated whether incorporating radiologists' eye-gaze data improves deep learning models for chest X-ray abnormality detection. The authors proposed a multimodal architecture combining chest X-ray images with fixation maps derived from eye-tracking data. Using the REFLACX dataset, they compared a standard Mask-RCNN model (image-only) against a multimodal variant that incorporated fixation maps via element-wise multiplication. Surprisingly, the image-only model outperformed the multimodal approach across all evaluated abnormality classes, suggesting that raw eye-gaze data may introduce noise rather than diagnostic value. The study identified key challenges including noisy eye-tracking data, poor spatial alignment between fixations and lesion annotations, and artifacts from interface interactions during data collection.

## Method Summary
The study implemented a multimodal Mask-RCNN architecture that fused chest X-ray images with fixation heatmaps derived from radiologists' eye-tracking data. The REFLACX dataset provided 3,032 CXR images with corresponding fixation maps and bounding box annotations for five abnormality classes. The multimodal model used element-wise multiplication to combine CXR images with fixation heatmaps, with two backbone options tested (ResNet and MobileNet). The model was pretrained on Microsoft COCO and fine-tuned for abnormality detection using Average Precision at IoBB=0.50 as the primary metric. The baseline comparison used a standard Mask-RCNN trained only on CXR images.

## Key Results
- Image-only Mask-RCNN achieved AP50 scores ranging from 0.122 to 0.291 across five abnormality classes
- Multimodal model incorporating fixation maps performed worse than image-only baseline for all classes
- Average precision at 50% IoBB was 0.149 for image-only model versus 0.246 for multimodal model
- No predictive advantage observed from incorporating eye-gaze data despite theoretical expectations

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Eye-gaze data introduces noise that outweighs potential diagnostic benefit
- Mechanism: Eye-tracking data contains both diagnostic gaze patterns and artifacts from interface interaction (mouse clicks, scrolling), leading to mixed signals that degrade model performance when directly fused with image data
- Core assumption: Fixation maps are not sufficiently clean representations of diagnostic focus areas
- Evidence anchors:
  - "the REFLACX data contains a lot of noise: the eye gaze patterns that were recorded and made available to the public contained gazes resulting from the interaction with the interface and with the CXR assessment"
  - "those fixations mostly do not correlate with the groundtruth annotations"
  - Weak correlation between fixation data and lesion annotations suggests noise dominates signal
- Break condition: If preprocessing can effectively filter interface-related gaze artifacts, this mechanism would no longer hold

### Mechanism 2
- Claim: Fixation maps lack spatial precision needed for abnormality localization
- Mechanism: Fixation maps aggregate gaze data across time, creating low-resolution heatmaps that don't align well with precise bounding box annotations for lesions, especially when lesions are small or scattered
- Core assumption: Spatial resolution of fixation maps is insufficient for the level of detail required in medical diagnosis
- Evidence anchors:
  - "fixation masks consist of the clustering of gaze data, which means that a CXR image will contain a small number of fixations"
  - "those fixations mostly do not correlate with the groundtruth annotations"
  - Related work on gaze-guided attention networks suggests raw gaze data may be insufficient without refinement
- Break condition: If fixation data can be processed to preserve spatial precision or if diagnosis can rely on broader attention regions

### Mechanism 3
- Claim: Desktop eye-trackers introduce data quality limitations
- Mechanism: Traditional desktop eye-tracking systems are sensitive to head movement and lighting conditions, creating gaps and inaccuracies in the gaze data that propagate to the multimodal model
- Core assumption: Data collection hardware significantly impacts data quality
- Evidence anchors:
  - "the desktop eye trackers used to collect data are highly susceptible to noise and head movements"
  - "the data collection process employed in REFLACX utilized traditional desktop eye-trackers, which are known to be highly susceptible to noise and do not permit extreme head movement during data collection"
  - Evidence suggests VR-based collection could reduce these artifacts
- Break condition: If data collection hardware provides more stable tracking or if the model becomes robust to tracking noise

## Architecture Onboarding

- Component map: CXR image + Fixation heatmap → Element-wise multiplication → Backbone → RPN → ROI Pooling → Detection Head → Output
- Critical path: Image → Backbone → RPN → ROI Pooling → Detection Head → Output
- Design tradeoffs: MobileNet vs. ResNet backbone (speed vs. accuracy), element-wise multiplication vs. concatenation for fusion, using raw fixation vs. processed attention maps
- Failure signatures: Poor localization performance despite high classification accuracy, model performs worse than image-only baseline, high variance in predictions across similar inputs
- First 3 experiments:
  1. Train image-only baseline (Mask-RCNN) to establish performance floor
  2. Train multimodal model with fixation maps, compare to baseline
  3. Apply simple preprocessing to fixation maps (smoothing, thresholding) and retrain to test if noise reduction helps

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Does incorporating pupil dilation data into deep learning models for chest X-ray abnormality detection provide superior predictive performance compared to using only image data?
- Basis in paper: The authors state they plan to extend the study to analyze radiologists' pupil dilations while reading a CXR, as literature shows a strong correlation between pupil dilations and cognitive load, which can be a better metric to correlate with abnormal regions in the CXR than fixation maps.
- Why unresolved: This study did not investigate pupil dilation data, focusing instead on fixation maps. The authors explicitly note this as a direction for future research.
- What evidence would resolve it: Conducting experiments comparing deep learning models trained on chest X-rays alone versus those incorporating both fixation maps and pupil dilation data, then evaluating their performance on abnormality detection tasks.

### Open Question 2
- Question: Does collecting eye-tracking data in virtual reality environments reduce noise and improve the quality of data for deep learning models compared to traditional desktop eye-tracking setups?
- Basis in paper: The authors plan to replicate the REFLACX data collection process using VR glasses, noting that in a VR setting, conditions of light and contrast can be easily controlled, the radiologist will not be bounded to restricted head movements, and the data eye gaze data collection is less noisy.
- Why unresolved: The REFLACX dataset used traditional desktop eye-trackers, which the authors identified as highly susceptible to noise and head movements. The potential benefits of VR-based data collection remain untested.
- What evidence would resolve it: Comparing the quality and utility of eye-tracking data collected via VR versus desktop systems by training identical deep learning models on each dataset and measuring their performance differences.

### Open Question 3
- Question: What specific preprocessing or filtering techniques could be applied to eye-tracking data to reduce noise and improve its correlation with lesion annotations in chest X-rays?
- Basis in paper: The authors note that the current approaches using raw eye gaze data without considering the human generation process results in a highly noisy data stream that does not effectively contribute to supervised learning. They also mention that the REFLACX data contains noise from interface interactions.
- Why unresolved: The study used raw fixation maps directly as input without exploring preprocessing methods to clean or filter the data. The authors suggest that more investigation is needed to extract regions of interest from eye gaze data that correlate with lesion annotations.
- What evidence would resolve it: Developing and testing various preprocessing pipelines (e.g., filtering out non-diagnostic fixations, clustering techniques, temporal smoothing) on eye-tracking data and evaluating whether these processed inputs improve deep learning model performance on abnormality detection.

## Limitations
- Multimodal approach underperformed image-only baseline, suggesting eye-tracking data may introduce more noise than diagnostic value
- Fixation maps showed poor spatial correlation with precise lesion annotations, limiting utility for localization tasks
- Traditional desktop eye-tracking hardware introduced significant noise and artifacts that degraded data quality

## Confidence
- Finding that multimodal model underperforms image-only baseline: High
- Attribution of poor performance specifically to noise in fixation maps: Medium
- Confidence in future improvements through VR-based data collection and pupil dilation analysis: Low

## Next Checks
1. Conduct ablation studies testing different fixation map preprocessing techniques (smoothing, thresholding, temporal aggregation) to determine if noise reduction improves multimodal performance.

2. Compare fixation data quality across different eye-tracking hardware platforms (desktop vs. VR) using the same radiologists to quantify the impact of collection methodology on data quality.

3. Test alternative fusion strategies beyond element-wise multiplication, such as attention-based fusion mechanisms or separate processing streams for image and gaze data before combination.
