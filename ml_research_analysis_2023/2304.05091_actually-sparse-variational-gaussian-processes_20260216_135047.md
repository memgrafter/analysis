# Actually Sparse Variational Gaussian Processes

## Quick Facts
- **arXiv ID**: 2304.05091
- **Source URL**: https://arxiv.org/abs/2304.05091
- **Reference count**: 21
- **Primary result**: AS-VGP achieves comparable predictive performance to SVGP and VFF while drastically reducing memory requirements and enabling scalable inference on large datasets with tens of thousands of inducing points.

## Executive Summary
This paper introduces Actually Sparse Variational Gaussian Processes (AS-VGP), a novel method that uses compactly supported B-spline basis functions as inter-domain inducing variables to enable highly efficient Gaussian process inference with tens of thousands of inducing points. The key innovation is projecting the GP onto B-splines, which results in sparse covariance matrices amenable to sparse linear algebra, reducing computational complexity to linear in the number of inducing variables. AS-VGP achieves comparable predictive performance to existing methods like SVGP and VFF while drastically reducing memory requirements and enabling scalable inference on large datasets. Experiments demonstrate AS-VGP's effectiveness on spatial data with low-lengthscale variations, handling millions of datapoints and thousands of inducing variables efficiently.

## Method Summary
AS-VGP introduces inducing variables as RKHS projections of the GP onto compactly supported B-spline basis functions. The B-spline basis functions have local support, creating sparse band-diagonal covariance matrices between inducing variables. This sparsity enables efficient sparse linear algebra operations with linear complexity in the number of inducing points. The method precomputes the KufKfu matrix, which is independent of kernel hyperparameters, reducing computational cost during training. The resulting model can handle tens of thousands of inducing points while maintaining linear scaling in both computation and memory.

## Key Results
- AS-VGP achieves comparable predictive performance to SVGP and VFF on spatial data benchmarks
- Memory requirements scale linearly with the number of inducing points, enabling use of tens of thousands of inducing variables
- Computational complexity scales linearly with the number of inducing points due to sparse band-diagonal covariance matrices
- Successfully handles low-lengthscale variations in spatial data where previous methods struggle

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Using compactly supported B-spline basis functions as inter-domain inducing variables creates sparse covariance structures that enable efficient linear algebra operations.
- **Mechanism**: B-spline basis functions have local support, meaning each basis function only overlaps with a limited number of neighboring basis functions. This results in band-diagonal covariance matrices (Kuu and KufKfu) where most entries are zero, allowing sparse matrix operations instead of dense ones.
- **Core assumption**: The B-spline basis functions can adequately represent the function space of the GP while maintaining compact support.
- **Evidence anchors**:
  - [abstract]: "The key benefit of our approach is that the compact support of the B-spline basis functions admits the use of sparse linear algebra to significantly speed up matrix operations and drastically reduce the memory footprint."
  - [section]: "Due to the local support of the B-spline basis functions, the covariance between inducing variables yields sparse band-diagonal covariance matrices, admitting highly efficient sparse linear algebra at a complexity that scales linearly with the number of inducing variables."
  - [corpus]: Weak evidence - no direct comparisons found in neighbor papers, but the concept of sparsity for efficiency is common in GP literature.
- **Break condition**: If the function being modeled has very high-frequency components that cannot be captured by the B-spline basis functions, or if the number of inducing points becomes so large that even sparse matrices become memory-intensive.

### Mechanism 2
- **Claim**: Precomputing KufKfu is independent of kernel hyperparameters and can be done once, reducing computational complexity.
- **Mechanism**: Since Kuf is simply the evaluation of B-spline basis functions at training inputs, it does not depend on kernel hyperparameters. This allows KufKfu to be precomputed before training begins, saving computation during each ELBO evaluation.
- **Core assumption**: The B-spline basis functions are chosen such that their covariance structure with the GP (Kuf) is independent of kernel hyperparameters.
- **Evidence anchors**:
  - [section]: "Since the B-spline basis functions are piecewise polynomials, we can evaluate the inner product in closed form, allowing for efficient computation during training and testing."
  - [abstract]: "This allows us to very efficiently model fast-varying spatial phenomena with tens of thousands of inducing variables, where previous approaches failed."
  - [corpus]: Weak evidence - the concept of precomputation for efficiency is mentioned in neighbor papers but not specifically for B-splines.
- **Break condition**: If the kernel hyperparameters change during training in a way that affects the B-spline basis functions (e.g., if non-stationary kernels were used).

### Mechanism 3
- **Claim**: The method achieves linear scaling in both computational complexity and memory requirements with respect to the number of inducing points.
- **Mechanism**: By leveraging sparse linear algebra for band-diagonal matrices and precomputing KufKfu, the method reduces the complexity of matrix operations from cubic to linear in the number of inducing points.
- **Core assumption**: The bandwidth of the covariance matrices remains bounded and does not grow with the number of inducing points.
- **Evidence anchors**:
  - [section]: "Overall, this reduces the pre-computation cost for computing the sparse matrix multiplication KufKfu to linear in the number of training datapoints. The resulting matrix can be cached for later use with a memory footprint of O((k + 1)M), owing to its banded structure (Property 2)."
  - [abstract]: "The key benefit of our approach is that the compact support of the B-spline basis functions admits the use of sparse linear algebra to significantly speed up matrix operations and drastically reduce the memory footprint."
  - [corpus]: Weak evidence - while linear scaling is mentioned in neighbor papers for sparse GPs, specific evidence for B-splines is not found.
- **Break condition**: If the function being modeled requires very high-order B-splines, increasing the bandwidth of the covariance matrices and potentially breaking the linear scaling assumption.

## Architecture Onboarding

- **Component map**:
  - B-spline basis function generator -> Sparse matrix builder -> Precomputation module -> ELBO optimizer -> Prediction engine

- **Critical path**:
  1. Generate B-spline basis functions based on input domain and desired number of inducing points
  2. Build sparse representations of Kuu and KufKfu
  3. Precompute and cache KufKfu
  4. Initialize variational parameters and hyperparameters
  5. Iteratively optimize ELBO using sparse linear algebra operations
  6. Use trained model for predictions

- **Design tradeoffs**:
  - Number of inducing points vs. model accuracy: More inducing points generally improve accuracy but increase memory usage
  - Order of B-splines vs. bandwidth: Higher-order B-splines increase the bandwidth of covariance matrices, potentially breaking linear scaling
  - Precomputation time vs. training efficiency: More extensive precomputation can speed up training but requires more initial computation

- **Failure signatures**:
  - Memory errors during KufKfu precomputation: Indicates too many inducing points or too high-order B-splines
  - Slow training despite sparse operations: May indicate numerical issues or improper B-spline basis function selection
  - Poor predictive performance: Could be due to insufficient inducing points or inappropriate B-spline order for the data

- **First 3 experiments**:
  1. **1D regression with synthetic data**: Test the basic functionality with a simple 1D dataset to verify ELBO optimization and prediction accuracy.
  2. **Scalability test with increasing inducing points**: Gradually increase the number of inducing points to verify linear scaling in computation and memory.
  3. **Comparison with standard SVGP on spatial data**: Test on a spatial dataset with low-lengthscale variations to compare performance and efficiency with standard sparse variational GPs.

## Limitations

- **Limited to Matérn kernels**: AS-VGP currently only supports the Matérn class of kernels, limiting its applicability to other kernel types.
- **Low-dimensional assumption**: The method is primarily designed for low-dimensional spatial data and may not scale well to high-dimensional inputs.
- **Input normalization requirement**: The method requires input features to be normalized to a bounded interval [0, M], which may not be suitable for all datasets.

## Confidence

**High confidence**: The core mechanism of using compactly supported B-splines for sparse covariance matrices is well-established and theoretically sound. The computational complexity claims (linear scaling) are supported by the banded matrix properties of B-spline bases.

**Medium confidence**: The practical benefits demonstrated in experiments are promising, but the specific datasets and problem settings may favor AS-VGP. Generalization to arbitrary datasets requires further validation. The memory savings claims are credible but depend on implementation details not fully specified.

**Low confidence**: The relationship between B-spline order and approximation quality is not thoroughly explored. The paper lacks comprehensive comparisons with state-of-the-art sparse GP methods on diverse benchmark datasets.
