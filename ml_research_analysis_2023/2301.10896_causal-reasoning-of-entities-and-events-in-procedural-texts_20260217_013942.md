# Causal Reasoning of Entities and Events in Procedural Texts

## Quick Facts
- arXiv ID: 2301.10896
- Source URL: https://arxiv.org/abs/2301.10896
- Reference count: 18
- Key outcome: This paper introduces CREPE, the first benchmark for causal reasoning of events and entities in procedural texts. It highlights that existing models perform close to chance, while humans achieve high accuracy. The authors propose a novel code-like representation of procedures using Python classes and functions, significantly improving model performance. By incorporating entity state changes as intermediate reasoning steps (chain-of-thought prompting), they further boost results. The work demonstrates the effectiveness of structured code representations and chain-of-thought reasoning for multihop event prediction, setting a new direction for procedural text understanding.

## Executive Summary
This paper introduces CREPE, the first benchmark for causal reasoning of events and entities in procedural texts. The task requires predicting how the likelihood of a hypothetical event changes after each step in a procedure, given the current state of entities. Existing models perform close to chance (around 0.3 F1), while humans achieve high accuracy (0.90 F1). The authors propose representing procedures as Python code classes and functions, which leverages the semantic similarity between procedures and functions to improve model understanding. They also introduce chain-of-thought prompting by incorporating entity state changes as intermediate reasoning steps, further boosting performance. The approach demonstrates significant improvements, with the best model achieving 0.67 F1, and marks the first successful application of chain-of-thought reasoning with code language models.

## Method Summary
The authors propose representing procedural texts as Python code classes and functions, leveraging the semantic similarity between procedures and functions. They use in-context learning with few-shot prompts on large language models (T5, T0, GPT3) and code language models (Codex). The code-like representation allows for structured reasoning about entity state changes and their impact on event likelihood. Chain-of-thought prompting is employed by incorporating predicted or labeled entity state changes as intermediate reasoning steps before predicting event likelihood changes. The approach is evaluated on the CREPE dataset, which contains 183 procedures with 1219 steps and 324 event likelihood changes, annotated with entity state changes.

## Key Results
- Existing models (T5, T0, GPT3) perform close to chance (around 0.3 F1) on the CREPE task
- Human performance on the task is significantly higher (0.90 F1)
- Representing procedures as Python code classes and functions improves performance to 0.59 F1
- Incorporating entity state changes as intermediate reasoning steps (chain-of-thought prompting) further boosts performance to 0.67 F1

## Foundational Learning

  - Quick check question: Can you identify the main goal and steps in a given procedural text?

- Concept: Entity state tracking
  - Why needed here: Entity state changes are the intermediate steps in the causal chain from entity changes to event likelihood changes, and accurate tracking is crucial for effective reasoning
  - Quick check question: Given a procedural text and a list of entities, can you track the changes in their states throughout the procedure?

- Concept: Counterfactual reasoning
  - Why needed here: The task requires predicting the likelihood of hypothetical events based on the current state of the procedure, which is a form of counterfactual reasoning
  - Quick check question: Can you predict the likelihood of a hypothetical event given a procedural text and a specific step in the procedure?

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Does incorporating intermediate entity state changes into the event likelihood prediction model consistently improve performance across diverse procedural domains and event types?
- Basis in paper: [explicit] The paper demonstrates that including predicted or labeled entity state changes as intermediate reasoning steps (chain-of-thought prompting) improves model performance from .585 to .667 F1 on the development set and from .591 to .609 F1 on the test set.
- Why unresolved: While the paper shows improvement on the CREPE dataset, it remains unclear whether this approach generalizes to other procedural domains (e.g., medical procedures, industrial processes) or event types (e.g., complex causal chains, multi-entity interactions) that may exhibit different levels of complexity and require more nuanced reasoning.
- What evidence would resolve it: Experiments on diverse procedural domains and event types, along with a detailed analysis of the model's performance on each, would provide insights into the generalizability and limitations of this approach.

## Limitations

- The approach relies on few-shot in-context learning rather than fine-tuning, which may limit scalability and reproducibility
- The performance gains are evaluated on a single benchmark with limited diversity in procedural domains
- The human evaluation involved only 10 procedures and may not fully capture the difficulty of the task across different domains
- The approach's dependence on code language models like Codex raises questions about accessibility and the ability to reproduce results with other models

## Confidence

**High Confidence**: The claim that existing models perform close to chance on CREPE is well-supported by the experimental results showing T5, T0, and GPT3 baselines achieving F1 scores around 0.3. The observation that human performance is significantly higher (0.90 F1) is also strongly supported.

**Medium Confidence**: The claim that representing procedures as Python code classes and functions improves performance from ~0.3 to ~0.59 F1 is supported by the experimental results, but the mechanism explanation relies on comparisons with prior work and could benefit from more ablation studies on different code representations.

**Medium Confidence**: The claim that injecting causal relations through intermediate variables improves performance to ~0.67 F1 is supported by results, but the effectiveness of different chain-of-thought strategies (questions vs. statements) is not fully explored, and the impact of entity state tracking accuracy on downstream performance is not quantified.

## Next Checks

1. **Ablation Study on Code Representation**: Conduct controlled experiments comparing different code representation strategies (classes vs. nested functions, with vs. without step comments) to isolate the contribution of each design choice to the performance improvement.

2. **Generalization Across Procedural Domains**: Evaluate the approach on CREPE-like datasets from different domains (e.g., cooking, manufacturing, software development) to assess whether the performance gains generalize beyond the initial dataset.

3. **Impact of Entity State Tracking Accuracy**: Measure the sensitivity of downstream event likelihood prediction to entity state tracking errors by systematically varying the accuracy of predicted entity states in the chain-of-thought prompting experiments.
