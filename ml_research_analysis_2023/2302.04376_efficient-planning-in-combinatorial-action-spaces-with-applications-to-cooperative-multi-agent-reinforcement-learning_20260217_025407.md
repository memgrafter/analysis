# Efficient Planning in Combinatorial Action Spaces with Applications to Cooperative Multi-Agent Reinforcement Learning

## Quick Facts
- arXiv ID: 2302.04376
- Source URL: https://arxiv.org/abs/2302.04376
- Reference count: 40
- One-line primary result: Polynomial-time planning algorithms for MDPs with exponentially large combinatorial action spaces, with applications to multi-agent RL

## Executive Summary
This paper addresses the fundamental challenge of efficient planning in Markov Decision Processes (MDPs) with large combinatorial action spaces, motivated by multi-agent reinforcement learning where the action space grows exponentially with the number of agents. The key insight is that by leveraging greedy oracles and exploiting structural assumptions about the Q-function (such as additive feature decomposition), one can design algorithms that achieve polynomial computational and query complexity without enumerating all actions. The authors propose efficient variants of the CONFIDANT MC-LSPI and CONFIDANT MC-POLITEX algorithms, achieving query complexities of O(m²d³/κ²(1-γ)⁸) for LSPI-DAV and O(md/ϵ⁴(1-γ)⁵) for POLITEX-DAV.

## Method Summary
The method involves designing planning algorithms that avoid explicit enumeration of exponentially large action spaces by using a greedy oracle to compute optimal actions for any Q-function in the model class. Two uncertainty check approaches are proposed: EGSS (using Cholesky decomposition with 2d oracle calls) and DAV (exploiting additive feature decomposition to check only ∑|A(i)| actions instead of |A|). Under linear realizability and additive structure assumptions, these algorithms achieve polynomial complexity in the number of agents, feature dimension, and other relevant parameters. Kernelized versions are also provided for infinite-dimensional feature spaces using reproducing kernel Hilbert spaces.

## Key Results
- EGSS uncertainty check achieves polynomial query complexity with 2d calls to the greedy oracle
- DAV uncertainty check exploits additive feature decomposition, reducing oracle calls from |A| to ∑|A(i)|
- Under linear realizability and additive structure, algorithms achieve polynomial computational and query complexity in all relevant parameters
- LSPI-DAV query complexity: O(m²d³/κ²(1-γ)⁸); POLITEX-DAV query complexity: O(md/ϵ⁴(1-γ)⁵)
- Kernelized versions maintain polynomial complexity through critical information gain parameter

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The greedy oracle enables polynomial-time planning in exponentially large action spaces by solving linear optimization over the feature space.
- Mechanism: For any Q-function in the model class, the oracle returns the action maximizing the inner product between the Q-function's weight vector and the state-action feature vector.
- Core assumption: Access to a greedy oracle that can compute arg max over A for any given weight vector and feature map.
- Evidence anchors:
  - [abstract]: "As a minimal requirement, we assume access to an argmax oracle that allows to efficiently compute the greedy policy for any Q-function in the model class."
  - [section 3]: "Assumption 3 (Greedy oracle). We have access to an oracle G which takes as input a vector w ∈ Rd, a state s ∈ S and a feature function φ : S × A → Rd and returns an action that maximizes w⊤φ(s,a)."
- Break condition: If the oracle cannot solve the linear optimization problem efficiently for the given feature map, the polynomial complexity guarantee fails.

### Mechanism 2
- Claim: The uncertainty check with default action vector (DAV) achieves polynomial complexity by exploiting additive feature decomposition.
- Mechanism: Instead of checking uncertainty for all actions, DAV only checks actions that differ from a default action vector in at most one position.
- Core assumption: The Q-function has an additive structure in the features (Assumption 4), where Qπ(s,a(1:m)) ≈ w⊤∑φi(s,a(i)).
- Evidence anchors:
  - [section 4.2]: "Recall that CONFIDENT MC-LSPI sets a default action vector ¯a(1:m) ∈ A as a global. Define a subset of A as ¯A(1:m) = {(a(i), ¯a(−i)) : a(i) ∈ A(i),i ∈ [m]}..."
  - [section 5.1]: "Then, by Assumption 4 for any a(1:m) ∈ A we have w⊤kφ(s,a(1:m)) = w⊤k(∑m j=1 φj(s,a(j)) ± (m − 1)φi(s, ¯a(1:m)))..."
- Break condition: If the Q-function does not have the additive structure, the DAV uncertainty check cannot guarantee polynomial complexity.

### Mechanism 3
- Claim: The kernelized setting extends the algorithm to infinite-dimensional feature spaces while maintaining polynomial complexity.
- Mechanism: Using reproducing kernel Hilbert spaces (RKHS), the algorithm works with kernel evaluations instead of explicit feature vectors.
- Core assumption: The Q-function is approximately contained in an RKHS (Assumption 5) and has an additive structure in the kernel (Assumption 6).
- Evidence anchors:
  - [section 5.2]: "Assumption 5 (Kernel Qπ-realizability). For each policy π there exists a vector ˜Qπ ∈ H, ∥ ˜Qπ∥H ≤ b that satisfies sups∈S,a(1:m)∈A(1:m) |Qπ(s,a(1:m)) − ˜Qπ(s,a(1:m))| ≤ ϵ..."
  - [section 5.2]: "Assumption 6. The kernel k can be written as k(s1,a(1:m)1 ,s 2,a(1:m) 2 ) = ∑m j=1 kj(s1,a(j) 1 ,s 2,a(j) 2 )..."
- Break condition: If the kernel does not have the additive structure or the Q-function is not in the RKHS, the polynomial complexity guarantee fails.

## Foundational Learning

- Concept: Linear function approximation
  - Why needed here: The algorithms rely on Q-functions being linearly realizable in a feature space to enable efficient planning without enumerating all actions.
  - Quick check question: If Qπ(s,a) = w⊤φ(s,a) + ε where ε is small, does this satisfy linear realizability?

- Concept: Markov Decision Process (MDP)
  - Why needed here: The entire framework is built on MDP theory - understanding states, actions, transitions, and policies is fundamental.
  - Quick check question: In an MDP, if we know the optimal Q-function, how do we derive the optimal policy?

- Concept: Policy iteration
  - Why needed here: The algorithms alternate between policy evaluation (estimating Q-values) and policy improvement (finding greedy policy).
  - Quick check question: What is the difference between policy iteration and value iteration in terms of convergence speed?

## Architecture Onboarding

- Component map: MDP Simulator -> Feature Extractor -> Greedy Oracle -> Uncertainty Checker (EGSS/DAV) -> Core Set Manager -> Policy Updater

- Critical path: State → Feature extraction → Greedy oracle → Action selection → Simulator query → Core set update → Uncertainty check → Policy update

- Design tradeoffs:
  - EGSS vs DAV: EGSS uses Cholesky decomposition with 2d oracle calls but works for general features; DAV exploits additive structure with ∑|A(i)| oracle calls but requires feature decomposition.
  - LSPI vs POLITEX: LSPI uses deterministic policies with better query complexity; POLITEX uses stochastic policies with better sub-optimality guarantees but worse query complexity.
  - Finite vs kernel features: Finite features have complexity scaling with d; kernel features scale with critical information gain ˜Γ.

- Failure signatures:
  - EGSS fails when ∥L⊤φ(s,a)∥∞ > τ is too loose an approximation, leading to excessive core set growth
  - DAV fails when the additive assumption is violated, causing incorrect uncertainty estimates
  - Kernel version fails when the critical information gain grows too quickly with problem size
  - All versions fail when the greedy oracle cannot solve the linear optimization efficiently

- First 3 experiments:
  1. Implement EGSS uncertainty check with synthetic linear MDP where oracle is trivial (enumerate all actions)
  2. Test DAV variant on a simple multi-agent problem with additive structure (like the grid world example)
  3. Compare query complexity empirically between EGSS and DAV on problems of increasing dimension m

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What are the exact computational tradeoffs between EGSS and DAV uncertainty check methods in practice?
- Basis in paper: [explicit] The paper compares EGSS and DAV, noting EGSS has an extra factor of sqrt(d) in suboptimality for LSPI while DAV has an extra factor of m (number of agents).
- Why unresolved: The paper provides theoretical bounds but does not present empirical comparisons showing the practical impact of these tradeoffs across different problem parameters.
- What evidence would resolve it: Empirical results showing performance and runtime of both methods across a range of MDPs with varying numbers of agents and feature dimensions.

### Open Question 2
- Question: How well do these planning algorithms scale to problems with very large numbers of agents (e.g., 100+)?
- Basis in paper: [explicit] The algorithms are designed to scale polynomially with the number of agents, and an example with 4 agents is provided.
- Why unresolved: The paper does not present results for very large-scale multi-agent problems to demonstrate the scaling properties.
- What evidence would resolve it: Empirical results showing performance and scalability of the algorithms on MDPs with increasingly large numbers of agents.

### Open Question 3
- Question: What is the impact of the additive feature decomposition assumption (Assumption 4) on the performance of the algorithms?
- Basis in paper: [explicit] The paper states that the additive feature decomposition leads to improved bounds and efficient kernelized versions, but does not provide empirical evidence.
- Why unresolved: The paper does not present empirical results showing the performance of the algorithms with and without the additive feature decomposition assumption.
- What evidence would resolve it: Empirical results comparing the performance of the algorithms on MDPs with and without additive feature decompositions.

## Limitations

- The polynomial complexity guarantees rely on strong assumptions about the availability of an efficient greedy oracle and the additive structure of Q-functions
- The kernelized version's complexity depends on the critical information gain parameter, which can grow quickly with problem complexity
- The DAV variant's efficiency is tied to the additive feature decomposition assumption, which may not hold in many practical multi-agent scenarios
- The paper does not provide empirical validation on large-scale multi-agent problems with many agents

## Confidence

- **High Confidence**: The theoretical framework connecting greedy oracles to polynomial-time planning is well-established and the EGSS uncertainty check mechanism is sound.
- **Medium Confidence**: The DAV variant's complexity analysis assumes strong structural properties that may not hold in practice.
- **Low Confidence**: The kernelized version's polynomial bounds depend on properties of the critical information gain that are difficult to verify in practice.

## Next Checks

1. **Oracle Feasibility**: Construct explicit greedy oracles for common feature maps used in multi-agent reinforcement learning (e.g., factored Q-functions, Fourier basis) to verify that the polynomial oracle complexity is achievable.

2. **Additive Structure Verification**: Test the DAV variant on problems where the additive assumption is approximately but not exactly satisfied to quantify the robustness of the algorithm to structural violations.

3. **Critical Information Gain Bounds**: Compute or bound the critical information gain for kernelized versions on standard multi-agent benchmark problems to verify that the polynomial complexity holds in practice.
