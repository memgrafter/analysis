# GeneGPT: Augmenting Large Language Models with Domain Tools for Improved Access to Biomedical Information

## Quick Facts
- arXiv ID: 2304.09667
- Source URL: https://arxiv.org/abs/2304.09667
- Reference count: 4
- Key outcome: GeneGPT achieves state-of-the-art performance on eight tasks in the GeneTuring benchmark with an average score of 0.83, surpassing retrieval-augmented LLMs (0.44), biomedical LLMs (0.08-0.04), GPT-3 (0.16), and ChatGPT (0.12).

## Executive Summary
GeneGPT is a method that teaches large language models to use NCBI Web APIs through in-context learning with few-shot demonstrations. By prompting Codex to solve genomics questions with URL requests as examples, GeneGPT achieves state-of-the-art performance on the GeneTuring benchmark. The approach combines API call demonstrations with an augmented decoding algorithm that detects and executes API calls, enabling seamless integration of external data into LLM generation.

## Method Summary
GeneGPT teaches LLMs to use NCBI Web APIs through in-context learning with few-shot API demonstrations. The method prompts Codex with genomics questions and API usage examples, using an augmented decoding algorithm that detects special symbols indicating API calls, executes them, and appends results to continue generation. The approach leverages Codex (code-davinci-002) with temperature 0, stopping generation when "->" symbols are detected to execute NCBI E-utils and BLAST API calls.

## Key Results
- Achieves 0.83 average score on GeneTuring benchmark, surpassing Bing (0.44), BioMedLM (0.08), and BioGPT (0.04)
- Demonstrates superior performance on all 8 tasks including gene alias, gene name conversion, gene SNP association, gene location, SNP location, gene disease association, protein-coding genes, and DNA sequence alignment
- Shows good cross-task generalizability of API demonstrations across different genomics tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Few-shot API demonstrations enable GeneGPT to learn NCBI Web API syntax and usage patterns.
- Mechanism: In-context learning with API call demonstrations provides examples of URL structure, parameters, and expected outputs. Codex learns to generate similar URLs for new queries.
- Core assumption: Codex can generalize API usage patterns from few examples to novel queries.
- Evidence anchors: [abstract] "we prompt Codex to solve the GeneTuring tests with few-shot URL requests of NCBI API calls as demonstrations for in-context learning"; [section 2.2] "It is followed by four QA instances as demonstrations of using NCBI Web APIs"

### Mechanism 2
- Claim: Augmented decoding with API call detection allows seamless integration of external data into LLM generation.
- Mechanism: The decoding process detects special symbols ("->") indicating API calls, executes them, appends results, and continues generation. This creates a feedback loop where API outputs inform subsequent text.
- Core assumption: API results can be directly appended to prompt context for continued generation.
- Evidence anchors: [section 2.3] "We discontinue the text generation process when the special '->' symbol is detected, which is the indication for an API call request"; [section 2.3] "The raw execution results will be appended to the generated text, and it will be fed to Codex to continue the generation."

### Mechanism 3
- Claim: Cross-task generalizability of API demonstrations reduces need for task-specific examples.
- Mechanism: The same set of API demonstrations works across multiple genomics tasks, suggesting learned API usage patterns transfer well.
- Core assumption: API usage patterns are task-agnostic and generalizable.
- Evidence anchors: [abstract] "Further analyses suggest that: (1) API demonstrations have good cross-task generalizability"; [section 2.2] "It is followed by four QA instances as demonstrations of using NCBI Web APIs"

## Architecture Onboarding

- Component map: Prompt builder -> Codex interface -> API executor -> Answer extractor
- Critical path: Prompt → Codex generation → API call detection → API execution → Result appending → Continued generation → Answer extraction
- Design tradeoffs:
  - API demonstrations vs. documentation: Demonstrations work better for in-context learning but require more space
  - Real-time API calls vs. caching: Real-time ensures current data but adds latency; caching speeds up inference but risks stale data
  - Strict evaluation vs. fuzzy matching: GeneGPT uses strict exact matching for evaluation, potentially underestimating performance
- Failure signatures:
  - Invalid API URLs: Codex generates syntactically incorrect URLs
  - Missing API results: API calls fail or return empty results
  - Generation loops: API call detection fails, causing infinite loops
  - Context overflow: Too many API results exceed context window
- First 3 experiments:
  1. Test API call generation with known queries to verify URL syntax
  2. Execute generated URLs to verify API access and result parsing
  3. Run end-to-end with sample queries to verify complete generation flow

## Limitations

- Strict exact matching evaluation may underestimate GeneGPT's performance compared to fuzzy matching approaches
- Reliance on proprietary Codex model limits reproducibility and practical deployment
- Limited evaluation of scalability and performance degradation with longer contexts or more complex queries

## Confidence

- High confidence: Superior performance on GeneTuring benchmark (0.83 vs 0.44 for Bing, 0.08 for BioMedLM)
- Medium confidence: Cross-task generalizability of API demonstrations
- Low confidence: Scalability claims and performance with longer contexts

## Next Checks
