# When is an SHM problem a Multi-Task-Learning problem?

## Quick Facts
- arXiv ID: 2305.09425

## Executive Summary
This paper explores when multi-task learning (MTL) frameworks are applicable to structural health monitoring (SHM) problems. The authors identify three distinct problem settings where MTL can provide benefits: learning multiple related tasks simultaneously, using outputs as inputs through auxiliary measurements, and employing multiple loss functions for different insights. The paper demonstrates how these approaches can leverage natural synergies between tasks in SHM contexts, such as using data from similar structures or delayed measurements, to improve model performance and robustness.

## Method Summary
The paper presents a conceptual framework for applying multi-task learning to SHM problems through neural network architectures with shared hidden layers and multiple output nodes. The approach involves identifying related tasks in SHM contexts, designing appropriate network architectures with shared representations, and implementing different loss functions for each task. The methodology emphasizes leveraging natural task relationships (such as data from similar structures) and auxiliary information (like delayed measurements) to improve model generalization and sensitivity to different aspects of the data.

## Key Results
- Three problem settings identified where MTL is relevant to SHM: multiple related tasks, outputs-as-inputs, and multiple loss functions
- Natural task occurrence in SHM includes using data from multiple similar structures for damage detection
- Multiple loss functions can provide different insights by optimizing for different data aspects (e.g., L2 for overall response, L4 for peak detection)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Natural occurrence of multiple related tasks improves generalization in SHM by allowing models to learn synergies across similar structures or damage states.
- Mechanism: When tasks share common underlying patterns (e.g., damage detection across similar structures), the MTL network can leverage shared representations to improve accuracy over independent learners.
- Core assumption: Tasks are sufficiently related that learning them jointly provides better generalization than learning them separately.
- Evidence anchors:
  - [abstract] "Multi-task neural networks learn tasks simultaneously to improve individual task performance."
  - [section] "A example of the natural occurrence of multiple tasks in the context of SHM is the use of data from several nominally-identical structures to obtain information about their damage state..."
  - [corpus] Weak evidence - corpus neighbors focus on balancing and gradient issues, not natural task occurrence in SHM.
- Break condition: If tasks are not sufficiently related (e.g., vastly different structures with unrelated damage modes), MTL may not provide benefits and could even harm performance.

### Mechanism 2
- Claim: Using outputs as inputs allows inclusion of features unavailable during normal operation by leveraging them during training to improve generalization.
- Mechanism: Outputs that are only available during training (like modal analysis results) can influence the network during backpropagation, effectively acting as inputs that improve the model's ability to handle operational data.
- Core assumption: The additional outputs are correlated with the main task and can provide useful regularization during training.
- Evidence anchors:
  - [section] "The second problem setting of MTL is using outputs as inputs... An output influences a NN during back-propagation... by having an impact on the weights within the model."
  - [abstract] "using outputs as inputs (both linked to the recent research in population-based SHM (PBSHM))"
  - [corpus] Weak evidence - corpus focuses on balancing and optimization, not the outputs-as-inputs mechanism.
- Break condition: If the additional outputs are noisy or uncorrelated with the main task, they may introduce bias or confusion rather than improvement.

### Mechanism 3
- Claim: Multiple loss functions provide different insights by optimizing for different aspects of the data, leading to more robust solutions.
- Mechanism: By duplicating outputs with different loss functions (e.g., L2-norm for overall response, L4-norm for peak detection), the network learns to be sensitive to multiple aspects of the problem simultaneously.
- Core assumption: Different loss functions capture different important features of the data that are relevant to the overall task.
- Evidence anchors:
  - [section] "This problem setting of MTL duplicates outputs but uses different loss functions for each... Caruana [23] demonstrates how the rankprop error metric performs poorly at the lower end of a continuous spectrum."
  - [abstract] "using multiple loss functions to gain different insights"
  - [corpus] Weak evidence - corpus neighbors discuss balancing and optimization but not multiple loss functions for different insights.
- Break condition: If the loss functions are too conflicting or represent contradictory objectives, the network may struggle to find a coherent solution.

## Architecture Onboarding

- Component map: Input layer (sensor data) -> Shared hidden layers (common representations) -> Task-specific layers (if any) -> Multiple output nodes (one per task) -> Separate loss functions (one per task) -> Backpropagation with shared gradients

- Critical path: Input → Shared hidden layers → Task-specific layers (if any) → Multiple outputs → Separate loss calculations → Backpropagation with shared gradients

- Design tradeoffs:
  - Shared vs. separate hidden layers: More sharing improves generalization but may limit task-specific optimization
  - Number of tasks: More tasks increase potential benefits but also computational complexity and risk of negative transfer
  - Loss function selection: Different functions emphasize different aspects but may conflict

- Failure signatures:
  - Negative transfer: Performance degrades when tasks are not sufficiently related
  - Task imbalance: Some tasks dominate training, others are neglected
  - Overfitting to shared representation: Model performs well on training tasks but poorly on new data
