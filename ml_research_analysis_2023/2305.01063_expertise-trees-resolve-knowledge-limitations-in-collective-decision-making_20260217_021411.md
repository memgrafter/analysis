# Expertise Trees Resolve Knowledge Limitations in Collective Decision-Making

## Quick Facts
- arXiv ID: 2305.01063
- Source URL: https://arxiv.org/abs/2305.01063
- Reference count: 11
- Primary result: Expertise trees algorithm partitions context space and maintains independent learners for each region, achieving best performance though at increased computational cost

## Executive Summary
This paper addresses collective decision-making when experts' knowledge varies across problem instances. The authors model this by partitioning the problem space into regions of differing expertise and propose new algorithms that explicitly consider and adapt to this relationship. They introduce expertise trees, a novel approach that constructs decision trees to select appropriate models by partitioning the context space and maintaining independent learners for each region.

## Method Summary
The paper models localized expertise in collective decision-making where expert quality varies as a function of problem instance features. The proposed expertise trees algorithm builds a decision tree over expertise context features, creating leaf nodes each containing an independent bandits-with-expert-advice learner. This allows the system to capture localized expertise by maintaining separate models for different regions of the expertise space. The approach outperforms nearest neighbor methods and tree heuristic approaches by learning to partition the expertise context space rather than relying on single-expert selection.

## Key Results
- Expertise trees achieve the best performance among all tested algorithms
- Performance improves significantly as the number of expertise regions increases
- Incremental expertise tree variant provides practical trade-off between performance and computational efficiency

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Expertise trees outperform nearest neighbor and tree heuristic approaches by learning to partition the expertise context space and maintaining independent learners for each region.
- Mechanism: The algorithm builds a decision tree over the expertise context features (#»z), creating leaf nodes each containing an independent bandits-with-expert-advice learner. This allows it to capture localized expertise by maintaining separate models for different regions of the expertise space.
- Core assumption: The expertise context space can be meaningfully partitioned into regions where expert quality is homogeneous within each region but varies between regions.
- Evidence anchors: [abstract] expertise trees method partitions the context space and maintains independent learners for each region; [section] We split the expertise space (i.e., on #»zt) and learn models on the expert advice (i.e., ξt)

### Mechanism 2
- Claim: The expertise tree approach achieves better performance than meta-CMAB by avoiding the single-expert limitation while still maintaining exploration-exploitation balance.
- Mechanism: Instead of selecting a single expert based on context (like tree heuristic), expertise trees maintain policies that can combine advice from multiple experts within each partition, allowing collective intelligence benefits while still adapting to localized expertise.
- Core assumption: Collective intelligence (performance better than best individual expert) can be achieved when the appropriate experts are selected for each region of the expertise space.
- Evidence anchors: [section] When a decision is taken as a function of the advice of multiple experts, an opportunity for collective intelligence emerges

### Mechanism 3
- Claim: The incremental expertise tree variant achieves a practical trade-off between performance and computational efficiency.
- Mechanism: Instead of rebuilding the entire tree at each timestep, incremental updates only modify the path from root to leaf containing the current expertise context, reducing computational complexity from O(2hgκ) to O(hgκ) or even O(gκ) on average.
- Core assumption: The expertise space structure is relatively stable, so splits made early don't need frequent revision.
- Evidence anchors: [section] Updating the expertise tree requires O(hgκ) updates; The trade-off for a possible performance decrease is a significantly more efficient algorithm

## Architecture Onboarding

- Component map:
  Context processor -> Expertise tree builder -> Learner instances -> Split evaluator -> Distance calculator

- Critical path:
  1. Receive context #»x and extract expertise context #»z
  2. Traverse expertise tree to find appropriate leaf
  3. Use leaf's learner to select arm based on expert advice
  4. Observe reward and update both the learner and the tree structure
  5. Evaluate potential splits and update tree if beneficial

- Design tradeoffs:
  - Tree depth vs. overfitting: Deeper trees capture more nuanced expertise regions but risk overfitting with limited data
  - Split threshold sensitivity: Too aggressive splitting leads to unnecessary exploration; too conservative misses beneficial partitions
  - Incremental vs. full rebuild: Incremental is faster but may lock in suboptimal splits
  - Neighbor percentage (for NN variants): Higher percentages reduce overfitting but increase computational cost and may include irrelevant experiences

- Failure signatures:
  - Performance degradation when expertise context dimensionality increases: Suggests distance metric inadequacy or overfitting to spurious correlations
  - Sudden performance drop after tree depth increase: Indicates overfitting to noise in expertise space
  - Suboptimal performance in non-localized settings: Shows algorithm sensitivity to assumption of localized expertise
  - High computational cost with many regions: Reveals need for feature selection or approximation techniques

- First 3 experiments:
  1. Single region test: Run with all experts having uniform quality across all expertise contexts to verify algorithm doesn't degrade performance when no localization exists
  2. Two-region test: Create simple binary expertise patterns (e.g., one expert good for low z values, another for high) to verify tree learns correct splits
  3. Increasing complexity test: Gradually increase number of expertise regions while monitoring performance gap to oracle to understand scalability limits

## Limitations
- Assumes expertise can be meaningfully partitioned into homogeneous regions, which may not hold in real-world scenarios
- Relies on synthetic expertise heatmaps rather than real-world data, raising generalizability concerns
- Computational complexity grows exponentially with tree depth, making it impractical for high-dimensional expertise contexts

## Confidence
- High confidence in theoretical framework: The mathematical formulation of localized expertise and bandits-with-expert-advice setting is well-established
- Medium confidence in empirical results: Experiments show consistent improvements but use synthetic data with controlled expertise patterns
- Low confidence in scalability claims: Acknowledges computational costs but lacks comprehensive analysis of real-world data scaling

## Next Checks
1. Test the expertise trees algorithm on real-world datasets where expert quality is known to vary with problem instances (e.g., medical diagnosis data with different specialist domains)
2. Conduct ablation studies removing the expertise context features to determine how much performance depends on the quality of these extracted features versus the tree structure itself
3. Compare the computational costs of expertise trees against simpler baselines (like nearest neighbor) across varying dataset sizes to validate the claimed practical limitations
