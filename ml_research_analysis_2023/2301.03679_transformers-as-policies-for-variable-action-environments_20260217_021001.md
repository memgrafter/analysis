# Transformers as Policies for Variable Action Environments

## Quick Facts
- arXiv ID: 2301.03679
- Source URL: https://arxiv.org/abs/2301.03679
- Reference count: 8
- A transformer encoder-based policy architecture that achieves 91% win rate on 8x8 maps and 76% on 16x16 maps while using half the computational resources of GridNet

## Executive Summary
This paper introduces a transformer encoder-based policy architecture for handling variable action spaces in the Gym-µRTS real-time strategy game. The key innovation is a feature map that converts observations into entity representations, which are then processed by a transformer encoder to generate action logits for each controllable unit. This approach addresses the scalability issues of existing methods like GridNet by avoiding wasted computation on empty grid cells. The agent is trained using PPO with shaped rewards across multiple maps and achieves higher returns while using significantly fewer computational resources compared to previous RL approaches.

## Method Summary
The method converts the observation tensor (height×width×27) into entity representations using a feature map that extracts entity features and orders them by player ownership. These entity representations are processed by a transformer encoder with 5 layers, 7 attention heads, and 512 neurons. The actor network generates action logits for each controllable unit using a shared feed-forward layer, while the critic computes value estimates using aggregated statistics of per-unit value estimates weighted by player. The architecture is trained using PPO with shaped rewards across 24 parallel environments for 100M steps.

## Key Results
- Achieves 91% win rate on 8x8 map and 76% win rate on 16x16 map against scripted opponents
- Uses half the computational resources of the next-best RL agent (GridNet)
- Demonstrates faster training times and better reward maximization than previous approaches

## Why This Works (Mechanism)

### Mechanism 1
The transformer encoder processes entity representations in parallel without wasting computation on empty grid cells. The feature map converts the observation tensor into entity representations ordered by player ownership, then the transformer encoder applies self-attention across all entities. This avoids the wasted computation of GridNet which processes every grid cell regardless of whether it contains a unit.

### Mechanism 2
The actor network generates variable numbers of action logits corresponding to the number of controllable units. After the transformer encoder processes all entities, the actor takes only the outputs corresponding to the agent's units and applies a shared feed-forward layer to each, producing 78 logits per unit. This allows the policy to scale with the number of units present.

### Mechanism 3
The critic uses aggregated statistics of value estimates rather than raw values to handle variable unit counts. Instead of summing all value estimates directly, the critic computes sum and mean values for each player's units, then applies a feed-forward layer to weight these aggregated statistics. This makes the value estimate invariant to unit count variations.

## Foundational Learning

- **Transformer self-attention mechanism**: The transformer's ability to process sequences of variable length without positional constraints is crucial for handling variable numbers of units. *Quick check*: How does self-attention handle variable-length input sequences differently from convolutional layers?

- **Proximal Policy Optimization (PPO)**: PPO provides stable policy gradient updates with clipping to prevent destructive updates, essential for training with the shaped rewards used in this environment. *Quick check*: What is the purpose of the clip parameter in PPO's objective function?

- **Variable action spaces in reinforcement learning**: Understanding how to handle action spaces that change size based on environment state is fundamental to this approach. *Quick check*: How does the action space change when the number of controllable units changes in this environment?

## Architecture Onboarding

- **Component map**: Feature map → Transformer encoder (5 layers, 7 heads each) → Actor (shared FF layer per unit) → Critic (aggregated statistics → weighted sum)
- **Critical path**: Observation → Feature map → Transformer encoder → Actor/Critic → Action logits
- **Design tradeoffs**: The transformer scales quadratically with entity count (O(n²d)), but avoids wasted computation on empty cells. The feature map uses one-hot encodings that can be made more compact with embeddings.
- **Failure signatures**: Poor performance when entity interactions are highly spatial and require explicit grid structure, or when unit coordination is critical but the independent action assumption fails.
- **First 3 experiments**:
  1. Test the feature map output size and verify it correctly identifies all entities by comparing with ground truth entity counts
  2. Verify the actor produces the correct number of logits (78 per controllable unit) by running inference on states with known unit counts
  3. Test the critic aggregation by creating states with varying unit distributions and checking if value estimates remain reasonable

## Open Questions the Paper Calls Out

**Open Question 1**: How well does the transformer-based policy generalize from self-play training to competing against different types of scripted AI opponents? The paper only evaluates against scripted AIs and notes it has yet to be determined how well it will generalize from self-play.

**Open Question 2**: What is the maximum number of entities (units) that the transformer-based policy can handle effectively before computational complexity becomes prohibitive? The authors state that while 40² comparisons are reasonable, handling 1000+ entities remains to be seen.

**Open Question 3**: How does the transformer-based policy perform in environments with sparse rewards compared to the shaped rewards used in this paper? The authors state it is not yet known how this transformer policy will work with sparse rewards.

## Limitations

- The transformer-based approach may struggle with scenarios requiring explicit spatial coordination between units, as the paper doesn't validate whether spatial relationships are properly learned.
- The evaluation relies heavily on shaped rewards rather than sparse win/loss rewards, making it difficult to assess true strategic capability.
- Computational scaling with entity count is not thoroughly analyzed, though the transformer's O(n²d) complexity could become prohibitive with many units.

## Confidence

- **High Confidence**: The architectural description and training methodology are well-specified with clear implementation details.
- **Medium Confidence**: The claim about superior performance is supported by the methodology, but reliance on shaped rewards introduces uncertainty about real strategic capability.
- **Low Confidence**: The assertion that the transformer captures all necessary spatial relationships without explicit positional encoding is not empirically validated.

## Next Checks

1. Create a scenario requiring coordinated unit movement (e.g., surrounding an enemy) and evaluate whether the transformer-based policy can learn these behaviors compared to a spatially-aware baseline.

2. Train the same architecture with sparse win/loss rewards only and compare performance to the shaped reward version to reveal susceptibility to reward shaping exploitation.

3. Systematically vary the maximum number of entities in the environment and measure both win rate and computational time per step to validate whether the claimed efficiency advantage holds as entity count increases.
