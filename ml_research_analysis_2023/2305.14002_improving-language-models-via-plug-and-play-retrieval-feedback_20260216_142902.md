# Improving Language Models via Plug-and-Play Retrieval Feedback

## Quick Facts
- arXiv ID: 2305.14002
- Source URL: https://arxiv.org/abs/2305.14002
- Reference count: 13
- Improves language model performance by +6.0% (zero-shot) and +2.5% (few-shot) on knowledge-intensive benchmarks

## Executive Summary
REFEED introduces a novel plug-and-play retrieval feedback pipeline that enhances large language models without requiring expensive fine-tuning. The system generates initial outputs, retrieves relevant documents conditioned on both the query and the generated answer, and then refines the output by incorporating retrieved information. This approach directly addresses hallucination by providing grounded evidence specific to the generated content, achieving significant improvements on four knowledge-intensive benchmark datasets.

## Method Summary
REFEED is a three-stage pipeline: (1) Generate initial answers using a language model with either greedy or nucleus sampling, (2) Retrieve documents conditioned on both the query and the initial answer using BM25 or dense retrieval, and (3) Refine the answer by incorporating retrieved information into in-context demonstrations. The system employs two key innovations: diverse answer generation through nucleus sampling of multiple hypotheses, and an ensemble approach that selects between initial and refined answers based on log-likelihood scores.

## Key Results
- Achieves +6.0% improvement in exact match (EM) under zero-shot setting
- Achieves +2.5% improvement in F1 score under few-shot setting
- Outperforms baselines across four knowledge-intensive benchmark datasets
- Effectively reduces hallucination by providing grounded evidence specific to generated content

## Why This Works (Mechanism)

### Mechanism 1
Retrieval feedback addresses hallucination by providing grounded evidence specific to the generated output. The pipeline generates an initial answer, then retrieves documents conditioned on both the query and this answer. This targeted retrieval finds evidence that can confirm or correct the specific content of the answer, rather than just retrieving general information about the query. The core assumption is that retrieved documents contain information semantically related to the specific answer content. If the initial answer contains no lexical or semantic overlap with relevant documents, the retrieval will fail to find corrective evidence.

### Mechanism 2
Diverse answer generation improves retrieval coverage by exploring multiple answer hypotheses. Instead of generating a single answer, the model samples multiple distinct answers using nucleus sampling. Each answer becomes a separate query for document retrieval, resulting in a more diverse set of retrieved documents that better cover the answer space. The core assumption is that different answer hypotheses will retrieve different but relevant documents, providing complementary information. If the answer space is small or different hypotheses retrieve largely overlapping documents, diversity gains will be minimal.

### Mechanism 3
The ensemble method prevents retrieval feedback from degrading correct answers by selecting between initial and refined outputs based on likelihood. The system computes log-likelihood for both the initial answer and the refined answer after retrieval feedback. If the refined answer has lower likelihood, it keeps the initial answer; otherwise, it adopts the refined version. The core assumption is that the language model's likelihood score correlates with answer correctness, and retrieval feedback can sometimes introduce errors. If the likelihood score does not correlate well with correctness, or if the model is overconfident in incorrect answers, the ensemble may make wrong decisions.

## Foundational Learning

- **Dense passage retrieval using contextualized embeddings**: The pipeline relies on retrieval models to find relevant documents. Understanding how dense retrieval works is crucial for optimizing this component. *Quick check*: What is the key difference between dense retrieval (like DPR) and sparse retrieval (like BM25) in terms of how they represent documents?

- **Perplexity and log-likelihood as quality metrics**: The ensemble mechanism uses log-likelihood to decide between initial and refined answers. Understanding how perplexity relates to answer quality is essential for implementing this correctly. *Quick check*: Why might a lower perplexity score not always indicate a better answer in the context of retrieval-augmented generation?

- **In-context learning with demonstrations**: The pipeline incorporates retrieved documents into in-context demonstrations for output refinement. Understanding how in-context learning works with demonstrations is crucial for implementing the refinement step. *Quick check*: How does the order and formatting of demonstrations in the prompt affect the model's output in in-context learning scenarios?

## Architecture Onboarding

- **Component map**: Query → Answer Generator → Document Retriever → Refiner → Ensemble → Output
- **Critical path**: Query → Answer Generator → Document Retriever → Refiner → Ensemble → Output
- **Design tradeoffs**:
  - Number of diverse answers to generate (n): More diversity improves coverage but increases computational cost
  - Number of retrieved documents (k): More documents provide more context but may overwhelm the model
  - Sampling strategy for diverse generation: Temperature, top-k, or nucleus sampling affect diversity vs. coherence
  - Ensemble threshold: Hard cutoff vs. soft weighting between initial and refined answers
- **Failure signatures**:
  - Low improvement in EM/F1 scores despite retrieval feedback: Indicates retrieval may not be finding relevant documents
  - Significant performance degradation: Suggests retrieval feedback is introducing noise or misleading the model
  - Inconsistent results across runs: Points to sampling instability or retriever variability
  - High computational cost with marginal gains: Indicates need to optimize number of diverse answers or retrieved documents
- **First 3 experiments**:
  1. Baseline comparison: Run with and without retrieval feedback using greedy decoding only, measure EM/F1 improvement
  2. Diversity impact: Compare performance with 1, 3, and 5 diverse answers using nucleus sampling, measure retrieval coverage and final performance
  3. Ensemble threshold tuning: Test different log-likelihood thresholds for accepting refined answers vs. keeping initial answers, find optimal tradeoff point

## Limitations
- Evaluation primarily focuses on knowledge-intensive benchmarks, with unclear performance in open-domain or multi-turn dialogue scenarios
- Ensemble mechanism's reliance on log-likelihood as a proxy for correctness remains unvalidated
- Computational overhead of generating multiple diverse answers and performing retrieval for each is not fully characterized

## Confidence
- **High**: Consistent improvements across multiple datasets and settings provide strong empirical support
- **Medium**: Core claims about retrieval feedback mechanisms lack direct validation and ablation studies
- **Medium**: The ensemble decision-making process and its correlation with correctness needs further validation
