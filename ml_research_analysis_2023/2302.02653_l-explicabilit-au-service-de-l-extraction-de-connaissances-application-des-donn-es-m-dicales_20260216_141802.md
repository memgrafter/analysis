# L'explicabilité au service de l'extraction de connaissances : application à des données médicales

## Quick Facts
- arXiv ID: 2302.02653
- Source URL: https://arxiv.org/abs/2302.02653

- Reference count: 6
- Key outcome: Pipeline extracts clinically meaningful patient subgroups from heart disease data using explainable ML, feature selection, and clustering

## Executive Summary
This paper proposes a pipeline for extracting knowledge from medical data using explainable machine learning techniques. The approach combines feature selection, black-box model training, explainability algorithms, and clustering to identify clinically relevant patient subgroups. Applied to a heart disease dataset, the pipeline successfully identifies demographic trends and risk factors, demonstrating how XAI can bridge the gap between complex ML models and medical expertise.

## Method Summary
The pipeline consists of six steps: feature selection to remove noise (e.g., "type-A behavior" variable), training a multilayer perceptron classifier, using AutoXAI to select and optimize Kernel SHAP explanations, generating explanations for individual instances, applying hierarchical clustering to these explanations, and recommending representative instances (medoids) for each cluster. The method extracts interpretable rules describing patient subgroups with distinct cardiovascular risk profiles, enabling both data scientists and medical experts to understand model decisions and identify potential biases.

## Key Results
- Feature selection identifies "type-A behavior" variable as adding noise, improving model performance
- AutoXAI selects Kernel SHAP with optimized hyperparameters (nsamples=581, l1_reg="bic") for robust explanations
- Hierarchical clustering produces clinically meaningful subgroups, such as older patients with high tobacco/obesity vs younger low-risk patients
- Extracted rules achieve high accuracy (73.3% to 96.7%) and reveal demographic trends in cardiovascular risk

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The pipeline extracts actionable medical insights by combining feature selection, explainability, and clustering to identify clinically meaningful patient subgroups.
- Mechanism: The process begins with removing noise (e.g., "type-A behavior" variable) to improve model accuracy, then uses Kernel SHAP explanations to quantify variable influence. Clustering these explanations reveals subgroups with distinct risk profiles (e.g., older patients with high tobacco and obesity vs. younger patients with low risk factors), enabling interpretable rule generation.
- Core assumption: Explanations generated from a trained model retain sufficient information to meaningfully cluster patients into clinically relevant groups.
- Evidence anchors:
  - [abstract] "Feature selection identifies that the 'type-A behavior' variable adds noise to the model" and "Hierarchical clustering is applied to the explanations, producing rules that describe each cluster."
  - [section] "With the explanations thus produced, we can apply the clustering algorithm on the explanations. The obtained clusters are described by rules that delimit the contours of the clusters in the manner of a decision tree."
  - [corpus] Weak evidence - no related papers directly address medical knowledge extraction via XAI clustering.
- Break condition: If explanations fail to preserve critical feature relationships, clustering will produce clinically irrelevant subgroups.

### Mechanism 2
- Claim: AutoXAI optimizes explanation quality by selecting hyperparameters that maximize robustness and minimize infidelity.
- Mechanism: AutoXAI evaluates multiple explanation algorithms and hyperparameters, ranking them by aggregated scores. In this case, Kernel SHAP with specific parameters (nsamples=581, l1_reg="bic") was selected because it provided better robustness and fidelity than alternatives like LIME, ensuring reliable interpretation of model decisions.
- Core assumption: Explanation quality metrics (robustness and infidelity) correlate with the usefulness of explanations for downstream knowledge extraction.
- Evidence anchors:
  - [abstract] "AutoXAI is used to select Kernel SHAP with specific hyperparameters" and "with an optimization of the hyperparameters with regard to the Robustness and the Inadherence."
  - [section] "AutoXAI uses the model and the dataset to propose an explainability algorithm whose hyperparameters are optimized. It then uses evaluation measures of the explanations to optimize the hyperparameters of the explainability algorithms."
  - [corpus] Weak evidence - no related papers discuss AutoXAI hyperparameter optimization for medical data.
- Break condition: If explanation quality metrics don't align with human interpretability needs, selected explanations may mislead rather than inform.

### Mechanism 3
- Claim: Representative instance selection (medoids) provides concrete examples that embody cluster characteristics for stakeholder communication.
- Mechanism: After clustering, the medoid (most central instance) from each cluster is selected as a representative example. These instances are then visualized with their feature contributions, allowing medical experts to understand typical patient profiles within each risk group.
- Core assumption: The medoid adequately represents the cluster's characteristics and can be effectively communicated to non-technical stakeholders.
- Evidence anchors:
  - [abstract] "The pipeline enables extraction of insights for both data scientists and medical experts, identifying model biases and demographic trends related to cardiovascular risk."
  - [section] "With these clusters, it is possible to go further and extract representative instances as in Figure 2. For the instance of cluster 1 on the left, we can see that the 'median' patient is 31 years old..."
  - [corpus] Weak evidence - no related papers discuss medoid-based representative instance selection in medical XAI applications.
- Break condition: If medoids don't capture the full diversity of cluster characteristics, they may present an incomplete or biased view to stakeholders.

## Architecture Onboarding

- Component map: Feature selection -> MLPClassifier -> AutoXAI (Kernel SHAP) -> Hierarchical clustering -> Skope-rules -> Medoid selection
- Critical path: Feature selection → Model training → Explanation generation → Clustering → Rule extraction → Representative instance selection
- Design tradeoffs:
  - Model complexity vs. interpretability: Using a black-box MLP but relying on explanations for transparency
  - Explanation comprehensiveness vs. noise reduction: Feature selection improves both model performance and explanation quality
  - Clustering granularity vs. clinical relevance: Hierarchical clustering allows multi-level exploration of patient subgroups
- Failure signatures:
  - Poor feature selection leading to noisy explanations and irrelevant clusters
  - Explanation algorithm selection that doesn't align with stakeholder needs
  - Clustering that produces subgroups without clear clinical distinctions
  - Representative instances that don't adequately capture cluster characteristics
- First 3 experiments:
  1. Test feature selection impact: Run the pipeline with and without the "type-A behavior" variable to measure changes in model accuracy and explanation quality
  2. Compare explanation algorithms: Run AutoXAI with different evaluation metrics to see how algorithm selection affects cluster interpretability
  3. Validate cluster clinical relevance: Have medical experts review the generated rules and representative instances to assess clinical meaningfulness
