# OpenPI-C: A Better Benchmark and Stronger Baseline for Open-Vocabulary State Tracking

## Quick Facts
- arXiv ID: 2306.00887
- Source URL: https://arxiv.org/abs/2306.00887
- Reference count: 14
- Primary result: Enhanced seq2seq models with entity memory and two-stage prediction improve open-vocabulary state tracking performance on both original and cleaned OpenPI datasets

## Executive Summary
This paper addresses limitations in the OpenPI dataset for open-vocabulary state tracking, including non-procedural documents, out-of-order steps, and ambiguous state changes. The authors propose OpenPI-C, a cleaned dataset using human annotation, and introduce a cluster-based evaluation metric to mitigate the original metric's preference for repetitive outputs. They enhance the seq2seq generation baseline by introducing an entity memory to model temporal dependencies between steps and a two-stage prediction process to increase entity awareness. Empirical results demonstrate significant performance improvements, particularly on the cluster-based metric, while reducing hallucination in model outputs.

## Method Summary
The paper proposes three key enhancements to seq2seq models for open-vocabulary state tracking: (1) an entity memory module that captures temporal dependencies by storing and attending to historical state changes, (2) a two-stage entity-conditioned prediction process that first predicts entities and then predicts their state changes conditioned on the predicted entities, and (3) a cluster-based evaluation metric that enforces one-to-one assignment between predicted and gold state-change clusters to mitigate repetition bias. The method is evaluated on both the original OpenPI dataset and a cleaned version (OpenPI-C) using BART-based models with these enhancements.

## Key Results
- Enhanced seq2seq models with entity memory and two-stage prediction show consistent performance improvements across multiple evaluation metrics
- The cluster-based evaluation metric effectively addresses the original metric's bias toward repetitive outputs
- Dataset cleaning from OpenPI to OpenPI-C yields measurable performance gains for all tested models
- The proposed methods reduce hallucination in model outputs compared to baseline approaches

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: The entity memory module captures temporal dependencies between steps by storing and attending to historical state changes.
- **Mechanism**: For each entity-attribute pair, a memory slot is allocated when it first appears. The memory is updated only when the attribute changes, using a moving average of hidden states. During decoding, the model attends to both the encoder states and the memory slots, allowing it to adaptively select between current input information and historical state change information.
- **Core assumption**: The state of an entity at a given step depends only on its previous states and the current action, not on other entities' states.
- **Evidence anchors**: [section], [abstract]
- **Break condition**: If the entity-attribute pair changes frequently, the memory update rule (moving average) might smooth out important information, leading to loss of recent state changes.

### Mechanism 2
- **Claim**: The two-stage entity-conditioned prediction increases entity awareness by first predicting entities and then predicting their state changes conditioned on the predicted entities.
- **Mechanism**: The model first generates a set of entities from the input. Then, for each predicted entity, the model performs a second prediction step conditioned on that entity, simplifying the task from modeling all state changes jointly to modeling each entity's state changes separately.
- **Core assumption**: The state changes of different entities are conditionally independent given the input and the entity itself.
- **Evidence anchors**: [section], [abstract]
- **Break condition**: If the model fails to accurately predict the involved entities in the first stage, the subsequent state change predictions will be conditioned on incorrect entities, leading to inaccurate outputs.

### Mechanism 3
- **Claim**: The cluster-based evaluation metric mitigates the original metric's preference for repetition by enforcing one-to-one assignment between predicted and gold clusters.
- **Mechanism**: The predicted and gold state changes are clustered using Sentence-BERT embeddings. The clusters are then matched using maximal matching to enforce one-to-one assignment. Precision, recall, and F1 are calculated based on this assignment.
- **Core assumption**: State changes that are semantically similar should be grouped into the same cluster, and each predicted cluster should correspond to exactly one gold cluster.
- **Evidence anchors**: [section], [abstract]
- **Break condition**: If the clustering threshold is set too high, semantically similar but not identical state changes might be placed in different clusters, leading to underestimation of performance. If set too low, dissimilar state changes might be clustered together, leading to overestimation of performance.

## Architecture Onboarding

- **Component map**: Input (goal + previous steps) -> Encoder (BART) -> Decoder (BART with cross-attention to encoder and entity memory) -> Output
- **Critical path**: Input → Encoder → Decoder (with cross-attention to entity memory) → Output
- **Design tradeoffs**:
  - Entity memory vs. concatenating all previous state changes: Entity memory provides a more focused and efficient way to capture temporal dependencies, while concatenation might introduce noise and distract the model.
  - Two-stage prediction vs. direct generation: Two-stage prediction simplifies the task and increases entity awareness, but introduces an additional prediction step and potential error propagation.
- **Failure signatures**:
  - If the model produces repetitive outputs, the cluster-based metric might not penalize it enough.
  - If the entity memory is not updated correctly, the model might lose track of important historical state changes.
  - If the two-stage prediction fails to accurately predict entities, the subsequent state change predictions will be incorrect.
- **First 3 experiments**:
  1. Evaluate the model on the original OpenPI dataset to establish a baseline.
  2. Evaluate the model on the cleaned OpenPI-C dataset to assess the impact of dataset quality.
  3. Ablation study: Compare the performance of the model with and without entity memory and two-stage prediction.

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions, but based on the limitations and potential areas for future work:

- How would the proposed entity memory and two-stage prediction models perform on other open-vocabulary state tracking datasets beyond OpenPI?
- How sensitive is the clustering-based evaluation metric to the choice of threshold for merging predicted state changes?
- How would the performance of the proposed models change if the human-annotated OpenPI-C dataset was further cleaned to remove more low-quality data points?

## Limitations
- The exact criteria for dataset cleaning are not fully specified, creating uncertainty about potential biases introduced during the cleaning process
- The entity memory's effectiveness depends on predictable temporal patterns, with no adequate discussion of handling sporadic or irregularly changing entities
- The cluster-based evaluation metric introduces new uncertainties, particularly regarding the sensitivity of the fixed 0.7 threshold across different domains

## Confidence
- **High Confidence**: The architectural improvements (entity memory and two-stage prediction) are well-implemented and show consistent performance gains
- **Medium Confidence**: The dataset cleaning process and its impact on overall performance
- **Low Confidence**: The cluster-based evaluation metric's generalizability to other domains and its sensitivity to hyperparameters like clustering threshold

## Next Checks
1. Conduct an ablation study where models are evaluated on progressively less-cleaned versions of OpenPI to quantify the exact impact of the cleaning process on performance
2. Test the entity memory module on synthetic datasets with varying temporal patterns (regular vs. irregular state changes) to assess its limitations and failure modes
3. Systematically vary the clustering threshold (e.g., 0.6, 0.7, 0.8) and analyze how this affects performance rankings across different models to understand the metric's sensitivity and reliability
