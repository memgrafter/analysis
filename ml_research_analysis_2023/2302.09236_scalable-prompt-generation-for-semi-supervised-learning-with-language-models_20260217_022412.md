# Scalable Prompt Generation for Semi-supervised Learning with Language Models

## Quick Facts
- arXiv ID: 2302.09236
- Source URL: https://arxiv.org/abs/2302.09236
- Reference count: 14
- Primary result: Automatic prompt generation achieves 73.2% average accuracy, a 2.52% improvement over manual methods

## Executive Summary
This paper addresses the challenge of manual prompt and verbalizer design in semi-supervised learning with language models by proposing two automatic methods for prompt generation. The first method creates diverse prompt models by adding demonstration examples with learnable continuous prompt tokens, while the second varies the number of soft prompt tokens to encourage different learning patterns. The prototypical verbalizer automatically replaces manual verbalizers. Experiments on five NLU datasets show that the proposed methods achieve an average accuracy of 73.2%, representing a 2.52% relative improvement over state-of-the-art SSL methods that use manual prompts and verbalizers.

## Method Summary
The paper proposes two automatic methods for prompt generation in semi-supervised learning settings. The first method (Demo+Soft Tokens PET) creates multiple prompt templates by prepending randomly sampled demonstration examples from the training data, followed by continuous prompt tokens and the input sentence with a MASK token. The second method (Vary Soft Tokens PET) varies the number of continuous prompt tokens across different labeler models while keeping the input sentence and MASK token fixed. Both methods use a prototypical verbalizer that learns prototype vectors for each class label using contrastive learning, mapping MASK token embeddings to class probabilities based on cosine similarity. The approach eliminates the need for manual prompt and verbalizer design while maintaining competitive performance.

## Key Results
- Automatic prompt generation achieves 73.2% average accuracy across five NLU datasets
- 2.52% relative improvement over state-of-the-art SSL methods with manual prompts and verbalizers
- The prototypical verbalizer successfully replaces manual verbalizers without significant performance loss
- Both Demo+Soft Tokens and Vary Soft Tokens methods show consistent improvements across datasets

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Adding demonstration examples with continuous prompt tokens creates diverse prompt models
- Mechanism: The method constructs multiple prompt templates by prepending randomly sampled demonstration examples from the training data, followed by continuous prompt tokens and the input sentence with a MASK token. This creates variation across labeler models since each demonstration example is randomly selected.
- Core assumption: Different demonstration examples will introduce sufficient diversity in the prompts to enable language models to learn different aspects of knowledge from the dataset
- Evidence anchors:
  - [abstract] "The first method uses various demonstration examples with learnable continuous prompt tokens to create diverse prompt models"
  - [section] "We create multiple prompts by adding different demonstration examples with exactly n continuous soft tokens with the input sentence"
  - [corpus] Weak - no direct corpus evidence found
- Break condition: If demonstration examples are too similar or not representative of the dataset, diversity may be insufficient

### Mechanism 2
- Claim: Varying the number of soft prompt tokens encourages language models to learn different prompts
- Mechanism: The method creates multiple prompt templates by keeping the input sentence and MASK token fixed but varying the number of continuous prompt tokens between different labeler models. This variation in token count changes the prompt structure and expected language model output.
- Core assumption: Different numbers of continuous prompt tokens will lead to optimized prompts with different semantic meanings, allowing language models to capture different aspects of the task
- Evidence anchors:
  - [abstract] "The second method varies the number of soft prompt tokens to encourage language models to learn different prompts"
  - [section] "Here, we do not prepend the demonstration example. Our intuition is that given different numbers of continuous prompt tokens, the optimized learned continuous prompts may also be different"
  - [corpus] Weak - no direct corpus evidence found
- Break condition: If the language model cannot effectively utilize the varying token counts, all prompts may converge to similar solutions

### Mechanism 3
- Claim: Prototypical verbalizer can replace manual verbalizers without significant performance loss
- Mechanism: The prototypical verbalizer learns prototype vectors for each class label using contrastive learning, mapping the MASK token embedding to class probabilities based on cosine similarity with these prototypes. This eliminates the need for manually defined word-label mappings.
- Core assumption: The learned prototype vectors can effectively represent the semantic meaning of each class and provide accurate classification without human-defined verbalizer mappings
- Evidence anchors:
  - [abstract] "The prototypical verbalizer is used as an automatic replacement for manual verbalizers"
  - [section] "We empirically show that using the automatic verbalizer with manual prompts can achieve a similar performance to manual verbalizers' performance in the SSL pipeline"
  - [corpus] Weak - only mentions related work but no direct evidence for prototypical verbalizer superiority
- Break condition: If class boundaries are not well-separated in embedding space, the prototypical verbalizer may struggle to distinguish between similar classes

## Foundational Learning

- Concept: Semi-supervised learning with multiple labeler models
  - Why needed here: The SSL pipeline requires training multiple models with different prompts to label unlabeled data, creating diversity in the soft labels used to train the final classifier
  - Quick check question: What is the purpose of training multiple labeler models in the PET SSL framework?

  - Why needed here: Direct optimization of continuous prompt embeddings is unstable, so reparameterization through LSTM and MLP layers enables effective learning of prompt representations
  - Quick check question: Why does the paper use a reparameterization block instead of directly optimizing continuous prompt tokens?

  - Why needed here: The prototypical verbalizer uses instance-instance and instance-prototype contrastive losses to learn class representations that can map MASK token embeddings to class probabilities
  - Quick check question: How does the prototypical verbalizer learn to map MASK token embeddings to class probabilities?

## Limitations
- Limited evaluation scope with only 5 datasets and no variance reporting makes it difficult to assess statistical significance of improvements
- The method still requires hyperparameter selection (number of prompt tokens, demonstration examples) which could offset automation benefits
- Lack of empirical evidence showing that learned prompts capture different aspects of the task rather than converging to similar solutions

## Confidence
- High confidence: The basic SSL framework implementation (PET pipeline with multiple labelers) is well-established and the paper correctly applies standard techniques like reparameterization of continuous prompts and contrastive learning for the prototypical verbalizer
- Medium confidence: The performance claims are plausible given the established effectiveness of semi-supervised learning, but the limited evaluation scope reduces confidence in generalizability
- Low confidence: The claim that varying soft prompt token counts inherently leads to diverse and effective prompts lacks empirical validation
