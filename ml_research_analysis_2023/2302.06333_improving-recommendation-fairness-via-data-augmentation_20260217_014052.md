# Improving Recommendation Fairness via Data Augmentation

## Quick Facts
- arXiv ID: 2302.06333
- Source URL: https://arxiv.org/abs/2302.06333
- Reference count: 40
- Primary result: Proposed FDA framework outperforms fairness-aware baselines in both fairness metrics (DP and EO) and recommendation accuracy on MovieLens and LastFM datasets.

## Executive Summary
This paper addresses fairness issues in recommendation systems by proposing a data augmentation framework (FDA) that generates "fake" interaction data to balance user preferences across demographic groups. The framework operates on two key hypotheses: for each user's interaction (click or non-click) in one group, there should be a similar interaction by a user in the other group with a similar item. Using bi-level optimization, FDA generates balanced fake data and retrains recommendation models without modifying their architectures. Experiments show FDA achieves better trade-offs between fairness and accuracy compared to fairness-aware baselines.

## Method Summary
The FDA framework generates balanced fake interaction data based on two hypotheses to improve recommendation fairness. For positive interactions (clicks), it creates fake click records for users in the opposite demographic group with similar item preferences. For negative interactions (non-clicks), it creates fake non-click records following the same principle. The framework uses bi-level optimization where the inner loop generates fake data through small perturbations in the embedding space, while the outer loop updates recommendation parameters using augmented data. A random masking mechanism controls the proportion of fake data to prevent accuracy degradation. The approach is model-agnostic and can be applied to any embedding-based recommendation system.

## Key Results
- FDA outperforms fairness-aware baselines (FairRec, FLAN, LOF) in both fairness metrics (DP and EO) and recommendation accuracy (HR@K, NDCG@K)
- FDA achieves better fairness-accuracy trade-offs than baselines on both MovieLens and LastFM datasets
- The framework demonstrates effectiveness across multiple recommendation models (BPR, NCF, GCCF) without architectural modifications

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Balancing data distributions between user groups reduces model bias amplification
- Mechanism: By generating "fake" interaction data that mirrors click and non-click behaviors across groups, the training data becomes more balanced. This prevents the recommendation model from amplifying inherent biases present in the original data distribution.
- Core assumption: The recommendation model learns patterns from training data distribution and amplifies any imbalance.
- Evidence anchors: [abstract] "The recommendation model amplifies the inherent unfairness of imbalanced training data. We augment imbalanced training data towards balanced data distribution to improve fairness." [section] "Both of the two recommendation models (i.e., BPR [49] and GCCF [40]) show larger group divergences of recommendation accuracy results compared to the divergence value of the training data."

### Mechanism 2
- Claim: Two hypotheses guide balanced fake data generation
- Mechanism: Hypothesis 1 ensures positive interactions (clicks) are balanced between groups by creating fake click records. Hypothesis 2 ensures negative interactions (non-clicks) are balanced by creating fake non-click records. This covers all interaction types.
- Core assumption: Users in different groups with similar preferences should exhibit similar behavior patterns to similar items.
- Evidence anchors: [section] "for any user's two kinds of preference (a click record or a non-click record) in one group, there is another user in the remaining group (users with opposite sensitive attribute value) that has a similar item preference." [section] "For each user's interaction (click or non-click) in one group, there should be a similar interaction by a user in the other group with a similar item."

### Mechanism 3
- Claim: Bi-level optimization enables controlled augmentation
- Mechanism: The inner loop generates fake data by optimizing small perturbations in embedding space, while the outer loop updates recommendation parameters using augmented data. Random masking limits the proportion of fake data to prevent accuracy degradation.
- Core assumption: Small perturbations in embedding space can generate realistic "similar" items without leaving the original distribution.
- Evidence anchors: [section] "We employ a non-random perturbation δ to generate similar items in continuous embedding E" and "The noise δv is bounded in a small range ε, and the operator ≤ enforces the constraint for each dimension of δv." [section] "Since only part of the fake data is selected for training, the impact on recommendation accuracy can be controlled."

## Architecture Onboarding

- Component map:
  - Data loader -> Original interaction matrix and sensitive attribute information
  - Fake data generator -> Implements two hypotheses to create balanced fake interactions
  - Bi-level optimizer -> Inner loop for fake data generation, outer loop for model training
  - Embedding space -> Continuous representation where similarity is measured
  - Random mask controller -> Limits proportion of fake data in training
  - Base recommendation model -> Any embedding-based model (BPR, NCF, GCCF)

- Critical path:
  1. Load training data and initialize recommendation embeddings
  2. Generate fake data using both hypotheses
  3. Apply random masking to control fake data proportion
  4. Train recommendation model on augmented data
  5. Evaluate fairness and accuracy metrics

- Design tradeoffs:
  - Fake data quantity vs. accuracy: More fake data improves fairness but may hurt accuracy
  - Perturbation size ε vs. realism: Larger perturbations create more diverse fake items but may be less realistic
  - Model complexity vs. generalizability: Simpler models train faster but may capture less nuanced patterns

- Failure signatures:
  - Accuracy drops significantly with no fairness improvement: Fake data generation may be introducing too much noise
  - Fairness metrics improve but accuracy remains poor: Too much fake data or inappropriate perturbation strategy
  - No improvement in either metric: Hypotheses may not be generating appropriate fake interactions or base model may be inadequate

- First 3 experiments:
  1. Baseline test: Run original recommendation model without any augmentation to establish fairness and accuracy metrics
  2. Single hypothesis test: Apply only Hypothesis 1 or only Hypothesis 2 to isolate their individual effects
  3. Perturbation sensitivity: Vary the ε parameter to find optimal balance between fake data realism and diversity

## Limitations

- The framework's effectiveness depends heavily on the quality of similarity metrics used to identify "similar" items across user groups, which is not thoroughly validated in the paper.
- Results are limited to binary sensitive attributes (gender) and may not generalize to multi-category sensitive attributes or different fairness dimensions.
- The computational cost of bi-level optimization for fake data generation may be prohibitive for very large-scale recommendation systems.

## Confidence

**High confidence** in the core observation that recommendation models amplify bias present in training data distributions. The empirical evidence from both MovieLens and LastFM datasets supports this claim convincingly. The fairness metrics (DP and EO) consistently improve across different Top-K values, demonstrating the framework's effectiveness in reducing demographic disparities.

**Medium confidence** in the proposed mechanism of using two hypotheses for balanced fake data generation. While the framework shows improved fairness-accuracy trade-offs compared to baselines, the specific contributions of each hypothesis remain unclear from the ablation studies. The paper would benefit from more granular analysis of how each hypothesis independently affects different fairness metrics.

**Low confidence** in the generalizability of results to other sensitive attributes beyond gender and to different recommendation domains. The experiments are limited to two datasets with binary gender as the sensitive attribute, leaving questions about performance with multi-category sensitive attributes or non-demographic fairness concerns.

## Next Checks

1. **Sensitivity analysis**: Systematically vary the perturbation parameter ε and random masking rate to map out the full fairness-accuracy trade-off landscape and identify optimal operating points.

2. **Cross-attribute validation**: Test the framework with sensitive attributes other than gender (e.g., age groups, geographic regions) to verify generalizability across different fairness dimensions.

3. **Temporal stability test**: Evaluate how the fairness improvements degrade over time as user preferences evolve, and whether periodic re-augmentation is necessary to maintain fairness guarantees.
