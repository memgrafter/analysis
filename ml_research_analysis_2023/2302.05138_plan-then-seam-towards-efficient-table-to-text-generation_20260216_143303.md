# Plan-then-Seam: Towards Efficient Table-to-Text Generation

## Quick Facts
- **arXiv ID**: 2302.05138
- **Source URL**: https://arxiv.org/abs/2302.05138
- **Reference count**: 40
- **Primary result**: PTS achieves 3.0–5.6× speedup and 50% fewer parameters compared to strong two-stage baselines, while maintaining comparable or better generation quality.

## Executive Summary
This paper introduces Plan-then-Seam (PTS), the first totally non-autoregressive (NAR) model for efficient table-to-text generation. PTS decouples content planning and surface realization into two iterative NAR stages: first generating a content plan in parallel using a rethinking pointer predictor, then iteratively seaming plan tokens into fluent text using a shared NAR decoder. The approach achieves significant computational efficiency gains (3.0-5.6× speedup, 50% parameter reduction) while maintaining generation quality on benchmark datasets.

## Method Summary
PTS implements a two-stage NAR framework where a table encoder first linearizes and encodes table records. The NAR-P stage generates a content plan using a rethinking pointer predictor that observes all generated tokens for improved quality. The NAR-S stage then iteratively inserts connective tokens between plan tokens to produce the final description. Parameter sharing between planning and seaming stages reduces model size. The rethinking mechanism allows the model to detect and correct errors or repetitions in the content plan through a second pass of pointer prediction.

## Key Results
- Achieves 3.0–5.6× speedup for inference time compared to strong two-stage baselines
- Reduces 50% parameters through parameter sharing between content planning and seaming stages
- Maintains comparable or better generation quality (BLEU, ROUGE-L, PARENT) on WikiBio and WikiPerson datasets
- Rethinking pointer predictor significantly improves content plan quality by reducing repetition and incoherence

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Plan-then-Seam achieves non-autoregressive table-to-text generation by decoupling content planning and surface realization into two iterative NAR stages.
- **Mechanism**: The model first generates a content plan (tokens to be verbalized) using a non-autoregressive pointer predictor. Then it iteratively inserts connective tokens between plan tokens using a shared NAR decoder. This separation allows parallel token generation while maintaining coherence through iteration.
- **Core assumption**: Content planning tokens can be predicted independently in parallel without sacrificing quality, and surface tokens can be generated conditioned on these plan tokens.
- **Evidence anchors**:
  - [abstract]: "PTS firstly writes and calibrates one plan of the content to be generated with a novel rethinking pointer predictor, and then takes the plan as the context for seaming to decode the description."
  - [section 3.2]: "NAR-P generates content planning sequence in a fully non-autoregressive manner by conditioning on the source table."
- **Break condition**: If content planning quality degrades too much, subsequent seaming will produce incoherent output, reducing overall generation quality.

### Mechanism 2
- **Claim**: Rethinking pointer predictor improves content plan quality by allowing inter-token dependency modeling.
- **Mechanism**: The model first generates a primary plan using a naive NAR pointer predictor, then re-runs a second pointer predictor that can "rethink" the plan by observing all other tokens. This allows the model to detect and correct errors or repetitions.
- **Core assumption**: A second pass with full context can improve content planning without sacrificing the parallel nature of NAR decoding.
- **Evidence anchors**:
  - [section 3.2]: "We believe that the pointer predictor would produce a better plan by partially observing generated plan tokens. Motivated by this intuition, we adapt the naive pointer predictor and propose its variant rethinking pointer predictor."
  - [section 4.4]: "The results also demonstrate the effectiveness of the newly proposed rethinking mechanism, confirming that the inter-dependency between different positions is essential for NAR-P."
- **Break condition**: If the rethinking step introduces new errors or if the computational overhead negates the speedup benefits.

### Mechanism 3
- **Claim**: Parameter sharing between content planning and seaming stages reduces model size while maintaining quality.
- **Mechanism**: The placeholder predictor and token deleter modules are shared between NAR-P (content planning) and NAR-S (seaming). This halves the parameter count compared to separate two-stage models.
- **Core assumption**: These modules can be generalized across both tasks without performance degradation.
- **Evidence anchors**:
  - [abstract]: "PTS achieves 3.0~5.6 times speedup for inference time, reducing 50% parameters."
  - [section 3.3]: "NAR-S share parameters in placeholder predictor πl and token deleter πd with NAR-P."
- **Break condition**: If the shared modules become a bottleneck or if task-specific optimization is needed.

## Open Questions the Paper Calls Out

The paper identifies several limitations and areas for future work:

1. **Pre-trained language models**: The authors note that while PLMs like TAPAS or T5 could potentially improve performance, they were excluded to ensure fair comparison and avoid data leakage concerns. The paper mentions that fine-tuning NAR models initialized with BERT is "very unstable" but doesn't provide empirical evidence for this claim.

2. **Pre-trained table encoders**: The model could benefit from pre-trained table encoders, but this wasn't explored due to concerns about unfair comparison since the datasets are derived from Wikipedia.

3. **Training efficiency**: While the model achieves inference efficiency, the paper acknowledges that training efficiency could be improved through better initialization or optimization strategies.

## Limitations

- **Content planning quality uncertainty**: The rethinking mechanism's effectiveness is demonstrated but lacks detailed ablation studies on error types and domain robustness.
- **Speed-accuracy tradeoff**: The paper reports significant speedup but doesn't provide comprehensive analysis of how iteration count should vary with table complexity.
- **Generalization concerns**: Evaluated only on Wikipedia biography datasets, limiting claims about performance on tables with different structures or reasoning requirements.

## Confidence

**High confidence**: The architectural design and parameter sharing mechanism are well-specified. Speedup measurements (3.0-5.6×) and parameter reduction (50%) are directly measurable and verifiable.

**Medium confidence**: Quality preservation claims are supported by experimental results, but robustness across different table structures and domains is uncertain. Rethinking mechanism effectiveness is demonstrated but could benefit from more granular analysis.

**Low confidence**: Claims about handling tables with complex relationships or varying structures are not directly tested. Performance on tables requiring sophisticated reasoning remains unknown.

## Next Checks

1. **Error analysis validation**: Conduct detailed error analysis comparing rethinking pointer predictor against naive version, categorizing errors to quantify specific contributions to content planning quality.

2. **Cross-domain generalization test**: Evaluate Plan-then-Seam on diverse table-to-text datasets (E2E, WebNLG, ToTTo) with varying table structures to assess robustness beyond Wikipedia biography tables.

3. **Iteration sensitivity analysis**: Systematically vary NAR-S iteration count across different table sizes, measuring quality-speed tradeoff curves to identify optimal settings and quantify diminishing returns.
