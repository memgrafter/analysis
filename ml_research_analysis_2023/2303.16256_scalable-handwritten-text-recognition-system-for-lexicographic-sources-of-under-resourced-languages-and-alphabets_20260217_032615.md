# Scalable handwritten text recognition system for lexicographic sources of under-resourced languages and alphabets

## Quick Facts
- **arXiv ID**: 2303.16256
- **Source URL**: https://arxiv.org/abs/2303.16256
- **Reference count**: 34
- **Primary result**: Word-level accuracy of 0.881 on 2.8 million handwritten Polish index cards

## Executive Summary
This study presents a scalable handwritten text recognition (HTR) system designed to process 2.8 million handwritten index cards from historical dictionaries of under-resourced languages. The system addresses the challenge of deciphering inconsistent handwriting styles across multiple lexicographers by combining synthetic data generation, spatial transformer networks, and constrained lexicon-based post-processing. Trained on a synthetic dataset of 500,000 Polish words, the system achieves 0.881 word-level accuracy, outperforming baseline models and demonstrating potential for broader application to other under-resourced languages and alphabets.

## Method Summary
The system employs a three-step workflow: (1) text detection using Keras OCR Craft model to identify bounding boxes around lemmas, (2) recognition using a spatial transformer network (STN) followed by ResNet backbone, BiLSTM layers, and CTC decoding, and (3) post-processing with constrained Word Beam Search that matches predictions against a dictionary of 86,000 entries while leveraging the alphabetical organization of index cards. The model was trained on synthetic Polish handwriting data generated from a 17th-century corpus and augmented with various transformations to simulate handwriting variability.

## Key Results
- Achieved 0.881 word-level accuracy on 100,000 test cards
- Outperformed baseline RCNN model through transfer learning and constrained post-processing
- Generated manually annotated dataset of 20,000 index cards for future benchmarking
- Demonstrated scalability for processing 2.8 million historical index cards

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Synthetic data generation compensates for lack of large-scale annotated handwritten text datasets in under-resourced languages
- **Mechanism**: System generates 500,000 synthetic Polish words from historical corpus with augmentation (posterization, histogram equalization, solarization, affine transforms)
- **Core assumption**: Synthetic images preserve enough linguistic and visual realism to train robust HTR model
- **Evidence anchors**: Trained using synthetic set of 500,000 generated Polish words; used randomly generated strings containing all characters
- **Break condition**: If synthetic images fail to capture realistic handwriting deformations, model's generalization degrades sharply

### Mechanism 2
- **Claim**: STN + ResNet backbone enables robust feature extraction across diverse handwriting styles
- **Mechanism**: STN rectifies input images using Thin Plate Spline transformation; ResNet extracts hierarchical features for BiLSTM-CTC decoder
- **Core assumption**: Rectified images standardize contrast, saturation, and orientation for reliable feature extraction
- **Evidence anchors**: Designed as STN followed by RCNN; ensures images are consistent in terms of contrast and saturation
- **Break condition**: If STN cannot correct severe perspective distortions or cursive overlaps, feature extraction fails

### Mechanism 3
- **Claim**: Constrained Word Beam Search significantly boosts accuracy by restricting predictions to known dictionary entries and alphabet range
- **Mechanism**: WBS-C matches CTC output against 86,000 dictionary entries and filters predictions to box's alphabetical range
- **Core assumption**: Index cards are stored alphabetically, so out-of-range predictions can be safely discarded
- **Evidence anchors**: Predictions matched against dictionary entries; leveraged alphabetical organization of index cards
- **Break condition**: If cards are mislabeled or misplaced, WBS-C may incorrectly reject valid predictions

## Foundational Learning

- **Concept**: Connectionist Temporal Classification (CTC) decoding
  - **Why needed here**: Allows mapping variable-length input sequences to output labels without requiring pre-segmented characters, essential for cursive handwriting where character boundaries are ambiguous
  - **Quick check question**: What advantage does CTC provide over traditional alignment-based decoding when recognizing connected cursive text?

- **Concept**: Transfer learning from multilingual synthetic datasets
  - **Why needed here**: Pre-trained models lack Polish diacritics and historical vocabulary; transfer learning injects language-specific features while retaining general handwriting recognition capabilities
  - **Quick check question**: How does adding Polish synthetic dataset improve performance over model trained only on English data?

- **Concept**: Post-processing with lexicon-based correction
  - **Why needed here**: Even with high CTC accuracy, recognition errors remain; constrained WBS-C reduces these by enforcing dictionary membership and alphabetical constraints
  - **Quick check question**: Why is constrained search more effective than simple best-path CTC output for this domain?

## Architecture Onboarding

- **Component map**: Detection (Keras OCR Craft) → Recognition (STN-ResNet-BiLSTM-CTC) → Post-processing (Constrained WBS-C) → Transfer learning (MJ+ST → CVIT → PL-500k → PL-30k)
- **Critical path**: Detection → Recognition (STN-ResNet-BiLSTM-CTC) → Constrained WBS-C
- **Design tradeoffs**:
  - Synthetic data avoids costly annotation but risks distribution mismatch
  - WBS-C improves accuracy but may reject valid rare words outside box's alphabetical range
  - STN adds computational overhead but improves robustness to layout variations
- **Failure signatures**:
  - Low detection IoU → missing or misaligned lemmas
  - High edit distance on misclassifications → struggles with unseen handwriting styles
  - Many rejected predictions → dictionary coverage gaps or mis-sorted cards
- **First 3 experiments**:
  1. Run detection on 100 sample cards; verify bounding boxes align with lemmas
  2. Evaluate vanilla RCNN (no transfer, no WBS) on small held-out set to establish baseline
  3. Apply WBS-C to baseline predictions; measure accuracy gain and identify rejected cases

## Open Questions the Paper Calls Out

### Open Question 1
- **Question**: How does constrained WBS perform when applied to languages with more complex morphological structures than Polish?
- **Basis in paper**: System can be "easily extended to other under-resourced languages, including languages with extended Latin alphabets or non-Latin scripts"
- **Why unresolved**: Current evaluation only demonstrates performance on Polish; morphological complexity could affect effectiveness of constrained WBS approach
- **What evidence would resolve it**: Comparative performance metrics across languages with varying morphological complexity (Turkish, Finnish, Arabic)

### Open Question 2
- **Question**: What is the long-term performance degradation rate when applied to index cards written by previously unseen lexicographers?
- **Basis in paper**: Index cards contain handwriting from numerous lexicographers with inconsistent handwriting styles
- **Why unresolved**: Paper evaluates general sample but doesn't analyze degradation over time or with new handwriting styles
- **What evidence would resolve it**: Longitudinal studies tracking recognition accuracy as system encounters new handwriting styles

### Open Question 3
- **Question**: How would HTR system perform if applied to index cards lacking conventional structure?
- **Basis in paper**: Almost all cards followed conventional scheme but acknowledges rare exceptions
- **Why unresolved**: System optimized for conventional structure; performance on non-standard cards remains unknown
- **What evidence would resolve it**: Systematic testing on index cards with non-conventional layouts, including multiple lemmas or missing headers

## Limitations
- Reliance on synthetic data without real-world validation against annotated handwritten samples from target language
- Constrained WBS assumes perfect alphabetical ordering, vulnerable to archival misfiling or historical sorting errors
- 0.881 accuracy reported without confidence intervals or statistical significance testing

## Confidence
- **High confidence**: Architectural components (STN, ResNet, BiLSTM, CTC) are well-established in HTR literature
- **Medium confidence**: Synthetic data generation approach reasonable but lacks empirical validation against real handwritten samples
- **Low confidence**: Superiority claim over baseline RCNN without presenting baseline's actual performance metrics

## Next Checks
1. Conduct pilot test on manually annotated real handwritten Polish index cards to validate synthetic data generalization
2. Perform statistical significance testing between proposed system and baseline RCNN using McNemar's test
3. Evaluate system robustness by intentionally introducing alphabetical misfiling in test samples to measure impact on WBS-C performance
