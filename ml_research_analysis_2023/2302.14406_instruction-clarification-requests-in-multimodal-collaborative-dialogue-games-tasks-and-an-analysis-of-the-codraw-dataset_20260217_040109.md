# Instruction Clarification Requests in Multimodal Collaborative Dialogue Games: Tasks, and an Analysis of the CoDraw Dataset

## Quick Facts
- arXiv ID: 2302.14406
- Source URL: https://arxiv.org/abs/2302.14406
- Reference count: 34
- 8.8k iCRs annotated across 9.9k dialogues in the CoDraw dataset

## Executive Summary
This paper annotates instruction clarification requests (iCRs) in the CoDraw dataset of multimodal collaborative dialogue games, creating a large spontaneous corpus of 8,807 iCRs across 9,993 dialogues. The authors analyze iCRs' lexical diversity, relation to game dynamics, and formalize two tasks: determining when to ask for clarification (Task 1) and detecting iCRs (Task 2). Neural network models are proposed for both tasks. Results show high performance on Task 2 (average precision 0.988, macro F1 0.968) but lower performance on Task 1 (AP 0.347, macro F1 0.645), indicating the latter is more challenging. The corpus analysis reveals iCRs are frequent, diverse, and impact game dynamics, making CoDraw-iCR a valuable resource for studying clarification in dialogue.

## Method Summary
The authors annotated instruction clarification requests in the CoDraw dataset of multimodal collaborative drawing games. They formalized two tasks: (1) determining when to ask for clarification and (2) detecting iCRs. Neural network models were proposed for both tasks, using pretrained embeddings for text (SentenceTransformers) and images (ResNet101). The models were trained using Adam optimizer with weighted binary cross-entropy loss. Evaluation metrics included average precision and macro F1 score on validation and test sets.

## Key Results
- The CoDraw-iCR corpus contains 8,807 iCRs across 9,993 dialogues
- Task 2 (iCR detection) achieved high performance (AP 0.988, macro F1 0.968)
- Task 1 (when to ask for clarification) showed lower performance (AP 0.347, macro F1 0.645)
- iCRs are frequent, diverse, and significantly impact game dynamics

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The neural network architecture effectively distinguishes between iCR and non-iCR utterances through learned embeddings and classification layers.
- Mechanism: The model encodes dialogue context, last utterance, and scene representation separately, concatenates them, and feeds them through a two-layer classifier with sigmoid output for binary classification.
- Core assumption: The pretrained embeddings (SentenceTransformers for text, ResNet101 for images) contain sufficient information about the occurrence of iCRs.
- Evidence anchors:
  - [abstract] "Neural network models are proposed for both tasks" and "Results show high performance on Task 2"
  - [section] "We use the pretrained embeddings for texts are generated with SentenceTransformers... and for images with ResNet101"
  - [corpus] Weak - the corpus analysis shows lexical diversity but doesn't directly validate embedding quality
- Break condition: If the pretrained embeddings don't capture the necessary information about underspecification or ambiguity in instructions, the model will fail to distinguish iCRs effectively.

### Mechanism 2
- Claim: The decision to ask for clarification emerges from patterns in the dialogue context and the drawer's behavior rather than just the current instruction.
- Mechanism: The model uses the dialogue context representation (including previous utterances by both teller and drawer) as input, allowing it to learn patterns that indicate when clarification is needed based on the history of the interaction.
- Core assumption: The drawer's previous behavior contains predictive signals about when clarification is needed, beyond what's in the current instruction alone.
- Evidence anchors:
  - [abstract] "The corpus analysis reveals iCRs are frequent, diverse, and impact game dynamics"
  - [section] "Interestingly, the most relevant signal for Task 1 is the context and not the last utterance"
  - [corpus] Weak - while the corpus shows iCRs impact game dynamics, it doesn't explicitly validate that drawer behavior patterns predict iCR needs
- Break condition: If the context doesn't contain reliable patterns indicating when clarification is needed, or if those patterns are too subtle for the model to learn, the mechanism will fail.

### Mechanism 3
- Claim: The ablation study reveals that the image representation is not fully exploited, suggesting limitations in the off-the-shelf pretrained model for this specific domain.
- Mechanism: The model includes image features from ResNet101, but ablation shows removing them has minimal impact on performance, indicating the model doesn't effectively use visual information for iCR detection.
- Core assumption: The pretrained ResNet101 model, optimized for general image classification, doesn't capture the specific visual features relevant to identifying underspecified instructions in the clipart-based CoDraw scenes.
- Evidence anchors:
  - [section] "The image representation does not seem to be fully exploited by the model" and "preliminary experiments did not lead to better results"
  - [corpus] Weak - the corpus analysis doesn't provide evidence about which visual features would be most relevant for iCR detection
- Break condition: If the visual features that distinguish underspecified from specified instructions are not captured by standard image models, this mechanism cannot improve performance.

## Architecture Onboarding

- Component map: Text encoders for dialogue context and last utterance (768→128 dimensions) -> Image encoder for scene (2048→128 dimensions) -> Concatenation layer (384 dimensions) -> Two-layer classifier (256 hidden units, LeakyReLU, Dropout, BatchNorm) -> Sigmoid output

- Critical path: Context encoding → Concatenation → Classification → Sigmoid output → Binary decision

- Design tradeoffs: 
  - Using pretrained embeddings saves training time but may not capture domain-specific features
  - Ablation shows image features aren't useful, suggesting potential for architectural simplification
  - Context length limited to 200 tokens to manage computational cost

- Failure signatures:
  - High performance on Task 2 but low on Task 1 suggests the model can recognize iCRs but struggles to predict when they should occur
  - Ablation showing context importance but low performance indicates the model finds some patterns but not the right ones
  - If removing image features doesn't hurt performance, the visual encoder is ineffective

- First 3 experiments:
  1. Train with only context and utterance encoders (remove image) to test if visual features add value
  2. Fine-tune the pretrained embeddings on a subset of the data to see if domain adaptation improves performance
  3. Experiment with attention mechanisms over the dialogue history instead of simple concatenation to better capture temporal dependencies

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What are the most effective strategies for an instruction follower (IF) to determine when to ask for clarification in multimodal dialogue games?
- Basis in paper: [explicit] The paper identifies this as a challenging task (Task 1) where neural network models achieved lower performance (AP 0.347, macro F1 0.645) compared to detecting iCRs (Task 2).
- Why unresolved: The paper shows that Task 1 remains difficult even with neural network models and various techniques like downsampling, upsampling, and cost-sensitive loss functions.
- What evidence would resolve it: Further research on integrating iCR decision-making with action-taking models, exploring more sophisticated architectures like Transformers, and investigating how models can better distinguish underspecified instructions from clear ones.

### Open Question 2
- Question: How can instruction giver (IG) models effectively respond to instruction clarification requests (iCRs) in multimodal dialogue games?
- Basis in paper: [inferred] While the paper provides models for detecting iCRs (Task 2 with high performance), it does not explore how IG models should respond to these requests or what constitutes an effective response.
- Why unresolved: The paper focuses on detecting iCRs but does not address the generation of appropriate responses or the impact of different response strategies on task success.
- What evidence would resolve it: Experiments comparing different response strategies (e.g., providing additional details vs. rephrasing instructions), measuring their impact on task completion rates and dialogue efficiency.

### Open Question 3
- Question: How do individual differences among players affect the frequency and nature of instruction clarification requests (iCRs) in multimodal dialogue games?
- Basis in paper: [inferred] The paper notes that meta-data about crowdworker ID is not available, preventing analysis of individual player strategies and their evolution across multiple games.
- Why unresolved: Without player-level data, it's impossible to determine whether certain players are more likely to ask for clarification, how experience affects clarification behavior, or whether players develop personalized strategies over time.
- What evidence would resolve it: Analysis of player-specific iCR patterns across multiple games, examining correlations between experience level and clarification frequency, and investigating how player strategies evolve with practice.

## Limitations

- The pretrained ResNet101 model may not capture domain-specific visual features relevant to iCR detection
- The model struggles with Task 1 (when to ask for clarification) despite success on Task 2 (detecting iCRs)
- Lack of player-level data prevents analysis of individual differences in clarification behavior

- The corpus analysis findings regarding lexical diversity and game dynamics impact are supported by the data
- Task 2 (iCR detection) is significantly easier than Task 1 (when to ask for clarification), as evidenced by the performance gap

**Medium Confidence:**
- The neural network architecture can effectively distinguish iCRs from non-iCRs through learned embeddings
- The context representation captures predictive patterns about when clarification is needed
- The pretrained embeddings contain relevant information for the tasks

**Low Confidence:**
- The specific visual features that distinguish underspecified from specified instructions are captured by the model
- The ablation study definitively explains why image features don't improve performance
- The findings generalize to other multimodal dialogue datasets beyond CoDraw
