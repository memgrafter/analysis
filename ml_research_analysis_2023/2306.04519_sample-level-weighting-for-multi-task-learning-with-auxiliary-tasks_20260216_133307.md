# Sample-Level Weighting for Multi-Task Learning with Auxiliary Tasks

## Quick Facts
- arXiv ID: 2306.04519
- Source URL: https://arxiv.org/abs/2306.04519
- Reference count: 40
- SLGrad outperforms state-of-the-art MTL weighting algorithms, especially on noisy data (CIFAR-10 with 40% label flips: test loss 0.33 vs 0.86 for static weighting)

## Executive Summary
This paper introduces SLGrad, a sample-level weighting algorithm for multi-task learning that dynamically assigns higher weights to samples positively contributing to the main task's generalization. Unlike existing task-level weighting methods, SLGrad computes sample weights based on the cosine similarity between each sample's gradient and the main task's validation metric gradient. The algorithm effectively filters out samples that would harm the main task while leveraging helpful auxiliary task signals. Experiments show significant performance improvements over existing methods, particularly in scenarios with noisy or corrupted data.

## Method Summary
SLGrad operates by computing sample-level weights through cosine similarity between the gradient of each training sample and the gradient of the main task's validation metric. The algorithm performs three passes per batch: one forward-backward pass to compute sample gradients, one forward-backward pass to compute validation metric gradients, and a final weighted update. To improve efficiency, it uses a first-order Taylor approximation to avoid explicit computation of future validation metrics. The weights are normalized and negative values are set to zero, effectively discarding samples that would harm the main task. The method is evaluated on synthetic regression tasks, CIFAR-10, and Multi-MNIST datasets.

## Key Results
- On CIFAR-10 with 40% label flips, SLGrad achieves test loss of 0.33 compared to 0.86 for static weighting
- On Multi-MNIST, SLGrad achieves test loss of 0.77 compared to 1.95 for static weighting
- SLGrad significantly outperforms existing MTL weighting algorithms (OL-AUX, PCGrad, CAGrad, CosSim, GradNorm, Random) across all tested datasets and noise levels

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Sample-level weights computed via cosine similarity between training sample gradients and main task validation metric gradients prioritize helpful samples.
- Mechanism: The algorithm computes `w_ij = cos(∇L_ij, ∇M_val_m)` and sets negative weights to zero, effectively discarding samples whose gradients oppose the direction of main task performance improvement.
- Core assumption: The cosine similarity between sample gradients and validation metric gradients is proportional to the sample's contribution to main task generalization.
- Evidence anchors:
  - [abstract] "SLGrad dynamically assigns higher weights to samples that positively contribute to the generalization performance of the main task"
  - [section] "Equation (4) reflects the cosine similarity between the gradient of a training sample... and the gradient of the main task generalization metric"
  - [corpus] Weak - no direct corpus evidence for cosine similarity weighting in MTL
- Break condition: If validation metric gradients become noisy or unrepresentative of true generalization performance, the weighting mechanism will fail.

### Mechanism 2
- Claim: The meta-objective (validation metric gradient) prevents overfitting by providing an unbiased generalization proxy.
- Mechanism: By using `∇M_val_m` instead of `∇L_train_ij` as the optimization guide, the algorithm avoids overfitting to training noise and focuses on samples that improve validation performance.
- Core assumption: The validation metric provides an unbiased estimate of generalization performance that correlates with true test performance.
- Evidence anchors:
  - [abstract] "Recent work has instantiated hold-out (i.e., validation set) performance on the task of interest as an optimization-based meta-learning objective"
  - [section] "Equation (4) uses the gradient of the validation (minimization) metric ∇θ(t) Mval_m as a meta-objective that provides a proxy for generalization performance"
  - [corpus] Weak - no direct corpus evidence for meta-objective validation metric use in sample weighting
- Break condition: If the validation set is too small or unrepresentative, the meta-objective will be biased and lead to poor generalization.

### Mechanism 3
- Claim: Look-ahead updating via Taylor approximation eliminates the need for explicit future parameter computation while maintaining efficiency.
- Mechanism: The algorithm approximates `M_val_m(θ_{t+1})` using first-order Taylor expansion instead of computing it explicitly, saving one forward and backward pass per training step.
- Core assumption: The first-order Taylor approximation accurately captures the change in validation metric after a parameter update.
- Evidence anchors:
  - [section] "The update rule in equation (4) represents a computationally efficient version of a look-ahead update"
  - [section] "Theorem 2 shows that... no explicit computation of Mm(θ(t+1)) is required"
  - [corpus] Weak - no direct corpus evidence for Taylor approximation in MTL sample weighting
- Break condition: If the loss surface is highly non-linear, the Taylor approximation may break down and lead to inaccurate weight estimates.

## Architecture Onboarding

- Component map: Gradient computation -> Validation metric computation -> Weight calculation/normalization -> Parameter update
- Critical path: The most time-critical part is the computation of sample-level gradients (step 1) and validation metric gradients (step 2), as these involve forward and backward passes. The weight calculation (steps 3-4) is relatively lightweight.
- Design tradeoffs: The algorithm trades computational overhead (one extra forward and two backward passes per batch) for improved generalization. The Taylor approximation reduces this overhead but may introduce approximation error.
- Failure signatures: Poor performance may indicate issues with: (1) validation set quality affecting the meta-objective, (2) gradient computation errors, (3) inappropriate learning rate for the weighted updates, or (4) tasks that are too dissimilar for useful auxiliary signals.
- First 3 experiments:
  1. Run on a simple synthetic dataset with known noise patterns to verify that the algorithm correctly assigns zero weights to noisy samples.
  2. Compare learning curves with and without the Taylor approximation on a medium-sized dataset to verify the approximation doesn't hurt performance.
  3. Test on a standard MTL benchmark (e.g., CIFAR-10) with varying levels of label noise to verify the algorithm's robustness claims.

## Open Questions the Paper Calls Out

The paper does not explicitly call out any open questions. However, several implicit questions emerge from the work, including how the method scales with dataset size and complexity, the impact on model interpretability, comparison to other meta-learning approaches, and theoretical guarantees for convergence in non-convex optimization scenarios.

## Limitations
- The mechanism connecting gradient cosine similarity to generalization benefit lacks theoretical grounding or empirical validation beyond presented experiments
- Computational efficiency claims lack runtime comparisons with existing methods, and the three-pass approach may incur significant overhead
- Limited ablation studies showing which components are essential and lack of comparison against simpler alternatives like task-level weighting with noise-robust losses

## Confidence
- **Main claims (Medium)**: The performance improvements are demonstrated empirically, but the underlying mechanism connecting gradient cosine similarity to generalization benefit is not well-established
- **Computational efficiency (Low)**: The paper claims efficiency improvements through Taylor approximation, but provides no runtime comparisons or analysis of practical overhead
- **Generalizability (Medium)**: Performance is demonstrated on synthetic, semi-synthetic, and real-world datasets, but primarily within image classification tasks

## Next Checks
1. **Ablation of weighting components**: Remove the cosine similarity weighting and instead use simple magnitude-based filtering to determine if the directional alignment is actually necessary for the observed performance gains.
2. **Cross-dataset robustness**: Test the algorithm on datasets with different characteristics (e.g., regression tasks, sequential data) to verify that the benefits extend beyond image classification tasks.
3. **Runtime efficiency measurement**: Conduct head-to-head runtime comparisons between SLGrad and baseline methods across varying batch sizes and model complexities to quantify the practical overhead.
