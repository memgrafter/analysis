# Planning as Theorem Proving with Heuristics

## Quick Facts
- arXiv ID: 2303.13638
- Source URL: https://arxiv.org/abs/2303.13638
- Reference count: 18
- We present a deductive approach to lifted planning based on theorem proving in the situation calculus.

## Executive Summary
This paper introduces TPLH (Theorem Proving Lifted Heuristic), a new deductive planning approach based on theorem proving in the situation calculus. The planner performs A* search over a tree of situations using a domain-independent delete relaxation heuristic. Unlike traditional planners that build explicit state spaces, TPLH computes states incrementally from the initial theory when needed, making it a lifted planner by design. The authors compare TPLH against Fast Downward and Best First Width Search planners on standard benchmarks, finding that while TPLH is slower due to unoptimized heuristics, it typically produces shorter plans and explores fewer states.

## Method Summary
The TPLH planner operates by searching for a plan in a tree of situations using A* search guided by a delete relaxation heuristic. Actions are grounded at runtime by evaluating preconditions against the current situation, avoiding the need to pre-ground the entire action space. The heuristic builds a relaxed planning graph layer by layer and recursively computes reachability scores for goal literals. The planner requires a Basic Action Theory (BAT) in situation calculus as input, along with a goal formula. It uses Domain Closure Assumption and Closed World Assumption throughout. The implementation was done in PROLOG and tested on standard STRIPS benchmarks including Barman, BlocksWorld, ChildSnack, Depot, FreeCell, Grippers, Logistics, Miconic, and PipesWorld domains.

## Key Results
- TPLH computes shorter plans on average than Fast Downward and Best First Width Search planners
- TPLH explores fewer states on average despite slower planning times
- The delete-relaxation heuristic provides admissible guidance for A* search in situation calculus
- Runtime action grounding enables lifted planning without pre-grounding the entire action space

### Mechanism 1
- **Claim:** Theorem proving in situation calculus can be made efficient with domain-independent heuristics.
- **Mechanism:** The TPLH planner performs A* search over a tree of situations rather than a state space, using a delete-relaxation heuristic to guide exploration.
- **Core assumption:** Situation calculus provides a symbolic representation of states that can be incrementally evaluated without materializing the full state space.

- **Break condition:** If the heuristic consistently overestimates costs, A* optimality is lost and the planner may explore unnecessarily many situations.

### Mechanism 2
- **Claim:** Forward search in situation calculus naturally yields lifted planning without pre-grounding.
- **Mechanism:** Actions are grounded at run-time by evaluating preconditions against the current situation, allowing the planner to operate on action schemas directly.
- **Core assumption:** Local-effect basic action theories enable efficient progression of the initial theory without closure assumptions.
- **Evidence anchors:**
  - [abstract] "TPLH is a lifted planner by design"
  - [section 3] "The planner has to search over executable sequences of actions on a situation tree... Since this computation is done at run-time, but not before the planner starts searching..."
  - [section 4] "Only the initial state Init remains in memory, but all other intermediate states are recomputed from Init when needed."
- **Break condition:** If progression becomes too expensive for complex theories, the runtime cost may outweigh memory savings.

### Mechanism 3
- **Claim:** Planning graphs with delete relaxation provide admissible heuristic estimates for situation calculus search.
- **Mechanism:** The heuristic builds a relaxed planning graph layer by layer and recursively computes reachability scores for goal literals.
- **Core assumption:** Delete relaxation preserves enough information to estimate plan cost while remaining computationally tractable.
- **Evidence anchors:**
  - [section 4] "Computing the heuristic function is done in two stages, with usual delete relaxation. First, a planning graph is built from the current state, layer-by-layer..."
  - [section 4] "For each supporting action, a 'reachability' score is recursively computed using its preconditions as the new goal literals."
  - [corpus] Weak - no direct citations for delete relaxation in SC context.
- **Break condition:** If the look-ahead bound is too small, the heuristic becomes uninformative; if too large, computation becomes prohibitive.

## Architecture Onboarding

- **Component map:**
  Input: Basic Action Theory (BAT) in situation calculus + goal formula
  Parser: Converts PDDL to Prolog representation
  State manager: Maintains initial state under DCA/CWA
  Progression engine: Computes current state from situation
  Heuristic engine: Builds planning graph and computes reachability
  A* controller: Manages frontier, selects next situation, checks goals
  Output: Plan as sequence of actions

- **Critical path:**
  1. Parse domain and problem
  2. Initialize state and priority queue
  3. While queue not empty:
     - Pop best situation
     - Progress to current state
     - If goal satisfied, return plan
     - Generate possible actions
     - For each action:
       - Compute next situation and state
       - Compute heuristic value
       - Insert into queue

- **Design tradeoffs:**
  - Memory vs. speed: TPLH trades memory (no state storage) for recomputation cost
  - Completeness vs. efficiency: Upper bound N guarantees termination but may miss optimal plans
  - Heuristic accuracy vs. computation time: Deeper look-ahead gives better estimates but costs more

- **Failure signatures:**
  - Memory exhaustion: Occurs in model-based planners, not TPLH
  - Timeout: TPLH is slower due to recomputation; watch for planner timeouts
  - Incorrect plans: Usually from heuristic overestimation or progression bugs
  - Non-termination: Likely from missing upper bound or infinite action space

- **First 3 experiments:**
  1. Run TPLH on a simple BW problem (e.g., 3 blocks) and verify plan correctness
  2. Compare number of situations visited vs. states visited by FD on the same problem
  3. Measure time spent in heuristic computation vs. total planning time to identify bottlenecks

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can the computational bottleneck of evaluating preconditions at runtime in hard-to-ground domains be mitigated?
- Basis in paper: [explicit] The paper states "Since we ground actions at run-time by evaluating their preconditions, and this is one of the computational bottlenecks, in particular, in the hard-to-ground domains with complex preconditions...we need a better algorithm for finding possible actions."
- Why unresolved: The paper identifies this as a future work item but does not propose specific solutions or evaluate existing approaches for this specific problem.
- What evidence would resolve it: Empirical comparison of different precondition evaluation strategies (e.g., caching, incremental evaluation, constraint propagation) on hard-to-ground domains showing reduced planning time while maintaining completeness.

### Open Question 2
- Question: Can the TPLH planner be extended to work without requiring the Domain Closure Assumption (DCA) for objects?
- Basis in paper: [explicit] The paper states "In addition, we would like to develop an implementation that does not rely on DCA for objects, e.g., an implementation for the planning problems where the actions can create or destroy objects. This is doable within our theorem-proving approach to planning."
- Why unresolved: While the paper claims this is "doable," no implementation or theoretical framework is provided to support this claim.
- What evidence would resolve it: A formal extension of the TPLH planner's semantics to handle object creation/destruction without DCA, along with experimental results demonstrating correct operation on domains with dynamic object populations.

### Open Question 3
- Question: How does the TPLH planner's performance compare to other recent lifted planners on the same benchmarks?
- Basis in paper: [inferred] The paper acknowledges "It happens that deductive planning in SC leads naturally to lifted planning with action schemas at run time. However, in this paper we do not compare our planner with other recent lifted planners. This study remains an interesting and important future work."
- Why unresolved: The paper focuses on comparing TPLH with non-lifted planners (FD and BFWS) but does not evaluate against the growing class of lifted model-based planners.
- What evidence would resolve it: Head-to-head comparison of TPLH against multiple lifted planners (e.g., Corrêa et al. 2021, Corrêa and Seipp 2022) on identical benchmark problems measuring plan quality, search efficiency, and memory usage.

## Limitations

- The evaluation relies on a small number of domains (11) and does not include PDDL domains with negative preconditions or conditional effects.
- The heuristic implementation is not optimized, resulting in slower planning times compared to FD and BFWS.
- The paper does not provide specific performance metrics for individual domains or problem instances, making it difficult to assess the planner's effectiveness on complex domains.

## Confidence

- **High confidence**: The claim that TPLH is a lifted planner by design, based on theorem proving in the situation calculus, is well-supported by the paper's description of the planner's architecture and search algorithm.
- **Medium confidence**: The claim that the delete-relaxation heuristic is admissible and guides the A* search effectively is supported by the paper's description of the heuristic computation and integration with the search algorithm, but the lack of optimization and performance metrics raises concerns.
- **Low confidence**: The claim that TPLH explores fewer states on average than FD and BFWS is based on the paper's average ratio metrics, but the lack of specific performance data and the impact of the unoptimized heuristic implementation on planning times make it difficult to assess the validity of this claim.
