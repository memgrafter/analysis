# UNFUSED: UNsupervised Finetuning Using SElf supervised Distillation

## Executive Summary
This paper proposes UnFuSeD, a novel approach for low-resource audio classification that leverages self-supervised learning (SSL) through a three-step process: (1) SSL pre-training using a modified DECAR algorithm (DECAR-v2) on unlabeled audio data, (2) unsupervised fine-tuning via self-distillation using pseudo-labels generated from clustering representations, and (3) supervised fine-tuning with a task-specific linear head. The method achieves state-of-the-art results on the LAPE Benchmark, outperforming previous approaches by 5.8% on average across all tasks. Additionally, UnFuSeD achieves these results with an encoder that has approximately 40% fewer parameters than the previous state-of-the-art system. The approach addresses the challenge of direct fine-tuning pre-trained SSL models by introducing an intermediate unsupervised fine-tuning step that improves downstream task performance.

## Method Summary
UnFuSeD is a three-step approach for low-resource audio classification. First, it uses a modified DECAR algorithm (DECAR-v2) for SSL pre-training on unlabeled audio data. Second, it performs unsupervised fine-tuning via self-distillation using pseudo-labels generated from clustering representations. Third, it conducts supervised fine-tuning with a task-specific linear head. The method addresses the challenge of direct fine-tuning pre-trained SSL models by introducing an intermediate unsupervised fine-tuning step that improves downstream task performance. The approach is evaluated on the LAPE Benchmark and achieves state-of-the-art results while reducing the number of parameters by approximately 40% compared to the previous state-of-the-art system.

## Key Results
- Achieves state-of-the-art results on LAPE Benchmark, outperforming previous approaches by 5.8% on average across all tasks
- Reduces parameter count by approximately 40% compared to the previous state-of-the-art system
- Demonstrates effective transfer learning from AudioSet to diverse downstream audio tasks through the three-step process

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Self-distillation with pseudo-labels improves generalization beyond direct fine-tuning
- Mechanism: The DECAR-v2 pre-trained encoder generates clusterable embeddings from the target task data. These embeddings are clustered to form pseudo-labels, which supervise the self-distillation process on a randomly initialized student encoder. This unsupervised fine-tuning step bridges the domain gap between pre-training (AudioSet) and fine-tuning (speech/non-speech tasks).
- Core assumption: Clusterable embeddings from DECAR-v2 reliably reflect semantic structure in the target task data, making pseudo-labels meaningful for supervision.
- Evidence anchors:
  - [abstract]: "we use the encoder to generate pseudo-labels for unsupervised fine-tuning before the actual fine-tuning step"
  - [section 3.1]: "DECAR-v2 generates clusterable embeddings, which helps in the Ypseudo generation"
  - [corpus]: Weak - no direct citations in related papers about DECAR-v2 or this specific pseudo-label clustering approach
- Break condition: If DECAR-v2 embeddings are not clusterable or the clustering fails to capture meaningful structure, pseudo-labels become random noise and self-distillation degrades performance.

### Mechanism 2
- Claim: Multi-loss self-distillation (KL-divergence + MSE + Cross-entropy) enables knowledge transfer across encoder blocks
- Mechanism: The student encoder is divided into three blocks, each with its own classifier head. KL-divergence aligns student-teacher classification outputs, MSE aligns intermediate representations, and cross-entropy ensures correct pseudo-label prediction. This multi-task setup transfers both semantic and representational knowledge.
- Core assumption: The student-teacher architecture with shared input can effectively transfer knowledge from the pre-trained encoder through multiple intermediate objectives.
- Evidence anchors:
  - [section 3.2]: "We treat each block bi as a separate classifier and add a linear transform hi_proj to bi to solve three losses parallelly, KL-divergence Lkl, Mean-Square error Lmse and Cross Entorpy Lce"
  - [section 3.2]: Equation 1 shows the weighted combination of all three losses
  - [corpus]: Weak - no direct citations about this specific multi-loss self-distillation configuration
- Break condition: If the loss weighting (α=0.7, β=0.003) is suboptimal or the student architecture cannot learn from the teacher, the self-distillation process may converge to poor local minima.

### Mechanism 3
- Claim: Frozen linear evaluation accurately measures learned representations without overfitting to downstream tasks
- Mechanism: After unsupervised fine-tuning, only a task-specific linear head is trained while keeping the encoder frozen. This setup prevents the encoder from overfitting to the limited labeled data while still allowing task adaptation through the linear layer.
- Core assumption: The representations learned through DECAR-v2 + self-distillation are sufficiently general that a simple linear classifier can achieve strong performance without fine-tuning the encoder.
- Evidence anchors:
  - [section 3.2]: "Finally, for Linear Evaluation, we use the learning rate as 0.001, batch size as 32, and number of epochs as 50"
  - [abstract]: "Finally, the resultant encoder is then fine-tuned on our target task dataset"
  - [section 3.2]: "we don't train all the layers of our model and instead just train a task-specific linear head added to the encoder"
- Break condition: If the representations are not sufficiently general, linear evaluation will show poor performance compared to end-to-end fine-tuning, indicating the need for encoder adaptation.

## Architecture Onboarding

- Component map:
  - Upstream: DECAR-v2 encoder (convnet) → produces clusterable embeddings
  - Midstream: Pseudo-label generator (K-means on embeddings) → creates weak supervision
  - Self-distillation: Student encoder (identical architecture) + teacher encoder → multi-loss training
  - Downstream: Frozen student encoder + task-specific linear head → evaluation

- Critical path: DECAR-v2 pre-training → pseudo-label generation → self-distillation → linear evaluation
  - Each step must complete successfully for the next to function

- Design tradeoffs:
  - Convnet vs. transformer: Convnet chosen for parameter efficiency (40% reduction) and fair comparison with literature
  - Pseudo-label quality vs. computation: K-means clustering is simple but may miss fine-grained structure
  - Multi-loss weighting: Requires careful tuning of α and β to balance objectives

- Failure signatures:
  - Poor pseudo-label quality → student learns incorrect patterns
  - KL-divergence dominates → student mimics teacher without learning from labels
  - MSE dominates → student focuses on representation matching over classification

- First 3 experiments:
  1. Verify DECAR-v2 produces clusterable embeddings by visualizing t-SNE plots on a subset of target data
  2. Test pseudo-label quality by training a linear classifier directly on K-means assignments and measuring accuracy
  3. Validate self-distillation by comparing student performance with and without each loss component (KL, MSE, CE)

## Limitations
- Limited analysis of DECAR-v2 embedding quality across diverse audio domains, with weak evidence that clusterable embeddings reliably capture semantic structure
- Novel multi-loss self-distillation configuration lacks ablation studies showing individual component contributions
- 40% parameter reduction claim may not reflect true representational efficiency given architectural differences between convnet and transformer backbones

## Confidence
- High confidence: The overall three-step framework (SSL pre-training → self-distillation → linear evaluation) is sound and follows established representation learning principles
- Medium confidence: The specific DECAR-v2 modifications and pseudo-label clustering approach will generalize well across diverse audio tasks
- Low confidence: The exact loss weighting (α=0.7, β=0.003) is optimal or that the multi-loss configuration outperforms simpler alternatives
