# Data Selection for Fine-tuning Large Language Models Using Transferred Shapley Values

## Quick Facts
- arXiv ID: 2306.10165
- Source URL: https://arxiv.org/abs/2306.10165
- Reference count: 12
- Primary result: TS-DS HAPLEY achieves up to 3.4% performance gains over full fine-tuning by removing harmful data

## Executive Summary
This paper introduces TS-DS HAPLEY, an algorithm for efficiently computing Shapley-based data values to identify and remove harmful data during fine-tuning of large language models. The method uses a simple linear classifier trained on target LM representations and multi-chain Monte Carlo sampling to estimate data contributions, significantly reducing computational cost compared to exact Shapley computation. Experiments on benchmark NLU datasets demonstrate that TS-DS HAPLEY outperforms baselines and achieves performance gains by removing harmful data, while being robust across various sampling parameters.

## Method Summary
TS-DS HAPLEY computes data importance scores using transferred Shapley values through a two-step approach. First, it trains a linear classifier on frozen LLM representations to learn task-specific patterns. Then, it applies multi-chain Monte Carlo sampling to approximate Shapley values efficiently, avoiding the exponential complexity of exact computation. The method identifies data points with negative contributions (harmful data) and removes them before fine-tuning, reducing training time and potentially improving model performance by eliminating noisy or misleading examples.

## Key Results
- TS-DS HAPLEY reduces computational cost compared to exact Shapley computation methods
- Achieves up to 3.4% performance gains over full fine-tuning by removing harmful data
- Shows robustness across various sampling parameters in benchmark NLU datasets

## Why This Works (Mechanism)
The method works by leveraging the additive property of Shapley values to quantify each data point's contribution to model performance. By training a linear classifier on frozen LLM representations, TS-DS HAPLEY captures task-specific patterns that transfer across similar NLU tasks. The multi-chain Monte Carlo sampling provides unbiased estimates of Shapley values while drastically reducing computation time from exponential to linear in the number of data points. This allows practical identification of harmful data that degrades model performance during fine-tuning.

## Foundational Learning

**Shapley Values**: A game-theoretic concept measuring each player's (data point's) marginal contribution to coalition performance. Why needed: Provides theoretically sound attribution of individual data points' impact on model performance. Quick check: Verify that estimated values satisfy efficiency property (sum equals total model performance).

**Transfer Learning**: Using representations learned from one task to benefit another task. Why needed: Enables computation of data values without full fine-tuning on every task. Quick check: Confirm linear classifier achieves reasonable accuracy on source task before transfer.

**Monte Carlo Sampling**: Statistical method for approximating expectations through repeated random sampling. Why needed: Makes Shapley value computation tractable for large datasets. Quick check: Monitor variance reduction across sampling chains to ensure convergence.

## Architecture Onboarding

**Component Map**: Data -> Frozen LLM Representations -> Linear Classifier -> Monte Carlo Sampling -> Shapley Value Estimation -> Data Selection -> Fine-tuning

**Critical Path**: The core pipeline follows: input data → representation extraction → linear classifier training → sampling-based Shapley computation → harmful data removal → fine-tuning on cleaned dataset. Bottlenecks occur during representation extraction and classifier training.

**Design Tradeoffs**: Accuracy vs. speed tradeoff in Monte Carlo sampling (more samples = better estimates but higher cost). Transferability vs. task specificity tradeoff in using frozen representations. Computational efficiency vs. estimation quality tradeoff in sampling strategy.

**Failure Signatures**: Poor linear classifier performance indicates representation quality issues. High variance in Shapley estimates suggests insufficient sampling. Negative performance after data removal may indicate over-aggressive filtering or incorrect transferability assumptions.

**First Experiments**:
1. Baseline: Run full fine-tuning on original dataset without any data selection
2. Transfer validation: Train linear classifier on source task and evaluate transfer accuracy to target task
3. Sampling sensitivity: Compare performance across different numbers of Monte Carlo samples

## Limitations
- Computational scalability to truly large-scale datasets (millions of examples) remains untested
- Evaluation only on similar NLU tasks, limiting understanding of cross-domain generalization
- Narrow comparison baseline (full fine-tuning) without ablation studies for other fine-tuning strategies

## Confidence
