# Prompt-based Extraction of Social Determinants of Health Using Few-shot Learning

## Quick Facts
- arXiv ID: 2306.07170
- Source URL: https://arxiv.org/abs/2306.07170
- Reference count: 12
- Key outcome: GPT-4 achieves 0.652 F1 score for SDOH extraction using one-shot prompting, comparable to the 7th best system in the n2c2 challenge

## Executive Summary
This paper evaluates prompt-based extraction of social determinants of health (SDOH) using GPT-4 in a one-shot setting. The authors explore two prompting strategies: generating BRAT standoff format and inline annotations, using the SHAC dataset. Results show that GPT-4 achieves an overall 0.652 F1 score, comparable to the 7th best system in the n2c2 challenge. The study demonstrates that GPT-4 can extract SDOH information with limited training examples, suggesting that fine-tuning may be needed for higher performance.

## Method Summary
The study uses GPT-4 to extract SDOH events from clinical text using one-shot prompting without requiring large labeled datasets. Two prompting strategies were tested: generating BRAT standoff format and inline annotations. The SHAC dataset containing de-identified social history sections annotated for SDOH events was used for evaluation. Post-processing was applied to ensure compliance with BRAT standoff format and correct character indices. Performance was evaluated using n2c2/UW SDOH Challenge criteria and a lenient evaluation metric that relaxes trigger alignment requirements.

## Key Results
- GPT-4 achieved an overall 0.652 F1 score for SDOH event extraction using one-shot prompting
- Performance was comparable to the 7th best system in the n2c2 challenge with similar datasets
- Fine-tuned BERT-based models outperformed GPT-4 but with a smaller performance gap under lenient evaluation criteria

## Why This Works (Mechanism)

### Mechanism 1
- Claim: GPT-4 can extract SDOH events from clinical text using one-shot prompting without requiring large labeled datasets.
- Mechanism: The model leverages its pre-trained knowledge and instruction tuning to understand the task schema from a single annotated example, generating predictions in BRAT standoff or inline formats.
- Core assumption: The prompt contains sufficient information about the annotation schema and the example is representative of the data distribution.
- Evidence anchors:
  - [abstract] "Our prompt-based GPT-4 method achieved an overall 0.652 F1 on the SHAC test set, similar to the 7th best-performing system among all teams in the n2c2 challenge with SHAC."
  - [section] "We report an overall performance of 0.861 F1 from the fine-tuned model, evaluated on the withheld test set. The highest-performing one-shot GPT-4 approach achieved an overall 0.652 F1 for SDOH event extraction."
  - [corpus] Weak evidence: No direct corpus-level analysis of how prompt quality affects performance.
- Break condition: The model fails when the prompt example does not cover all event types or when the schema is too complex for one-shot comprehension.

### Mechanism 2
- Claim: The lenient evaluation metric improves GPT-4 performance by relaxing trigger alignment requirements.
- Mechanism: Minimum-distance trigger pairing allows the model to be credited for correct event type identification even when trigger spans don't perfectly match gold annotations.
- Core assumption: Clinical meaning is preserved when any overlapping trigger of the correct type is present.
- Evidence anchors:
  - [section] "In the lenient criteria, trigger equivalence is relaxed to a minimum-distance metric (minimum distance), where gold triggers are paired (aligned) with the closest predicted trigger of the same event type."
  - [section] "Comparing overall performances (last row in the table), mSpERT outperforms both our GPT-4 models. But the performance gap between the fine-tuned model and the one-shot GPT models is smaller from the n2c2 evaluation to the lenient evaluation."
  - [corpus] Weak evidence: No corpus-level comparison of lenient vs strict criteria impact on specific event types.
- Break condition: Lenient evaluation becomes meaningless if the model consistently predicts wrong spans far from gold annotations.

### Mechanism 3
- Claim: Post-processing is necessary to correct GPT-4's structured output format errors.
- Mechanism: The model can extract correct text spans but often generates invalid BRAT standoff format or incorrect character indices, requiring simple rule-based corrections.
- Core assumption: The model's understanding of the task is accurate but its output formatting needs refinement.
- Evidence anchors:
  - [section] "Our preliminary experimentation indicated that though GPT-4 was able to correctly extract relevant text spans, it had some shortcomings: (1) some generated lines did not conform to the BRAT standoff format, and (2) the generated character indices did not correspond with the identified text spans."
  - [section] "We post-processed the generated outputs to ensure compliance with the BRAT standoff format and updated the character indices to correspond with the first occurrence of the generated text span."
  - [corpus] No corpus-level analysis of post-processing impact on final performance.
- Break condition: Post-processing rules become too complex if the model's output errors are frequent and varied.

## Architecture Onboarding

- Component map: Clinical text from SHAC corpus -> Prompt generator -> GPT-4 API -> Post-processor -> Evaluator
- Critical path: Clinical text → Prompt generation → GPT-4 processing → Post-processing → Evaluation
- Design tradeoffs:
  - One-shot vs few-shot: Using only one example reduces data requirements but may limit performance
  - Standoff vs inline: Standoff format is evaluation standard but inline is easier for GPT-4 to generate
  - Lenient vs strict evaluation: Lenient criteria are more forgiving but may not reflect true extraction quality
- Failure signatures:
  - Low trigger F1 scores indicate the model struggles to identify event spans
  - Character index errors suggest issues with text span mapping
  - Missing argument labels reveal difficulties in trigger-argument linking

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does few-shot learning performance of GPT-4 compare to supervised fine-tuning when using more than one training example?
- Basis in paper: [explicit] The paper mentions exploring one-shot prompting and states "More examples (few-shot) may improve performance" in the limitations section.
- Why unresolved: The study only tested one-shot prompting, leaving the impact of additional training examples unexplored.
- What evidence would resolve it: Comparative experiments testing GPT-4 performance with varying numbers of training examples (one-shot, two-shot, three-shot, etc.) against supervised fine-tuning baselines.

### Open Question 2
- Question: What is the impact of different prompt engineering strategies on GPT-4's SDOH extraction performance?
- Basis in paper: [inferred] The paper only tested two prompting styles (standoff and inline) and mentions in limitations that "Future work could explore more prompting methods such as question & answering and chain-of-thought."
- Why unresolved: Only two prompting strategies were tested, and their relative effectiveness remains unknown compared to other potential approaches.
- What evidence would resolve it: Systematic comparison of multiple prompt engineering techniques (chain-of-thought, few-shot examples, different formatting) on extraction accuracy.

### Open Question 3
- Question: How do errors in GPT-4's SDOH extraction differ from those in traditional supervised models?
- Basis in paper: [explicit] The paper states "We compare prompt-based extraction approaches with a high-performing supervised BERT-based model" and mentions "some of them may be eliminated in post-processing."
- Why unresolved: While performance differences are noted, the specific error patterns and types unique to GPT-4 versus supervised models were not analyzed in depth.
- What evidence would resolve it: Detailed error analysis categorizing false positives, false negatives, and incorrect entity relationships for both GPT-4 and supervised models.

## Limitations

- The study only tested one-shot prompting, leaving the impact of additional training examples unexplored
- Post-processing steps are described but not fully specified, making it difficult to assess their true impact on performance
- The lenient evaluation metric may overestimate practical utility by relaxing trigger alignment requirements

## Confidence

- High Confidence: The observation that GPT-4 achieves comparable performance to traditional fine-tuned models using only one example is well-supported by the reported F1 scores and evaluation against the n2c2 challenge benchmark.
- Medium Confidence: The claim that prompt-based approaches can reduce the need for large labeled datasets is supported, but the study only examines one-shot learning.
- Low Confidence: The assertion that GPT-4's output formatting issues are easily corrected through post-processing lacks empirical support.
