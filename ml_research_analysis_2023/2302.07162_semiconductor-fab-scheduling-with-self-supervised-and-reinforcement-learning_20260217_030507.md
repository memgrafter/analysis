# Semiconductor Fab Scheduling with Self-Supervised and Reinforcement Learning

## Quick Facts
- arXiv ID: 2302.07162
- Source URL: https://arxiv.org/abs/2302.07162
- Reference count: 16
- Primary result: RL method achieves up to 26% lower solution costs and 15% cycle time reduction vs. hierarchical heuristics

## Executive Summary
This paper introduces a novel reinforcement learning approach for semiconductor manufacturing scheduling that combines self-supervised learning for tool family embeddings with an attention-based policy network. The method addresses the continuous, stochastic, and dynamic nature of real-world semiconductor production by encoding domain-specific constraints and enabling global comparison of lots. The approach significantly outperforms traditional hierarchical dispatching heuristics in both high-volume/low-mix and low-volume/high-mix scenarios, demonstrating practical improvements in resource utilization and on-time completion rates.

## Method Summary
The method uses self-supervised learning to encode tool family information through a pretext task predicting tool families from lot features, followed by Natural Evolution Strategies (NES) for policy training. The policy network employs a multi-head attention mechanism to compare lots globally and order them for dispatch. The approach handles continuous, stochastic, and dynamic production environments by incorporating WIP considerations into the reward function and using derivative-free optimization to navigate non-differentiable objectives.

## Key Results
- Outperforms hierarchical dispatching strategies by up to 26% lower solution costs
- Reduces average cycle times by up to 15% compared to traditional methods
- Improves on-time completion rates for both hot and regular lots
- Handles both high-volume/low-mix and low-volume/high-mix scenarios effectively

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Learned tool family embedding injects critical domain knowledge for prioritizing lots based on tool-specific constraints
- Mechanism: Self-supervised pretext task predicts required tool family from lot features, training a shared embedding that captures tool-specific patterns
- Core assumption: Tool family is a strong proxy for constraints and processing characteristics that matter for scheduling decisions
- Evidence anchors: Weak support from corpus; paper claims efficient encoding without increasing input dimensionality

### Mechanism 2
- Claim: Attention-based policy network learns to compare lots globally, improving over static heuristics
- Mechanism: Multi-head self-attention layer operates over legal lots at each dispatch time, producing priority scores reflecting relative importance
- Core assumption: Relative ordering of lots matters more than absolute features; attention can capture pairwise interactions
- Evidence anchors: Weak support from corpus; paper claims global comparison capabilities

### Mechanism 3
- Claim: Episodic, WIP-inclusive objective function prevents short-term optimization at expense of future fab health
- Mechanism: Reward combines finished-lot metrics with forecast-based penalty for WIP lots, weighting by priority
- Core assumption: Forecast dl - (ai * el) reasonably proxies expected completion time for WIP lots
- Evidence anchors: Weak support from corpus; paper claims WIP penalty encourages throughput while avoiding backlog

## Foundational Learning

- Concept: Markov Decision Process (MDP) formulation for scheduling
  - Why needed here: Casts scheduling as sequential decision-making under uncertainty requiring states, actions, rewards, and transitions
  - Quick check question: What constitutes the action space at a given timepoint? (Answer: the set of legal lots that can be dispatched)

- Concept: Self-supervised learning for representation learning
  - Why needed here: Tool family embeddings must capture domain constraints without manual feature engineering
  - Quick check question: What pretext task is used to train the tool family embedding? (Answer: predicting the required tool family from lot features)

- Concept: Evolution Strategies (ES) for black-box policy optimization
  - Why needed here: Reward is non-differentiable and episodic; ES estimates gradients via noisy perturbations
  - Quick check question: Why is ES preferred over policy gradient methods? (Answer: non-smooth, episodic objective makes gradient estimation via simulation noisy)

## Architecture Onboarding

- Component map: Lot features + tool family embedding -> Self-attention layer (2 heads, d_head=6) -> Feed-forward network (3-layer MLP, d_FFN=16) -> Priority scores
- Critical path: Embedding pretraining -> policy network forward pass -> attention-based scoring -> lot ordering -> simulator step -> reward computation -> ES gradient estimate -> Adam update
- Design tradeoffs:
  - Attention vs. fixed heuristics: More flexible but O(n²) compute per step
  - Frozen embedding vs. end-to-end training: Reduces variance but may miss fine-tuning benefits
  - ES vs. policy gradients: Handles non-differentiable rewards but requires many simulator calls
- Failure signatures:
  - Uniform attention weights -> no discrimination between lots
  - Large embedding norms -> feature collapse, poor generalization
  - Reward variance spikes -> unreliable ES gradients
  - WIP penalty dominates -> agent avoids taking lots, starving machines
- First 3 experiments:
  1. Verify self-supervised pretraining loss convergence and embedding distinguishes tool families
  2. Test attention layer on small synthetic WIP set for meaningful priority scores
  3. Run short ES training loop on simplified fab to confirm policy improves over random ordering

## Open Questions the Paper Calls Out

- Question: How would performance change if self-supervised task predicted specific tool ID instead of tool family?
  - Basis: Paper only experiments with tool family encoding, leaving open whether finer-grained tool identification would improve performance
  - Resolution: Experiment comparing tool-specific vs. tool-family-only encoding performance

- Question: Would incorporating currently processed lots into state representation improve scheduling performance?
  - Basis: Authors identify this as limitation of current approach due to computational complexity
  - Resolution: Implementation and evaluation of expanded state representation including currently processed lots

- Question: What is optimal balance between training horizon length and training runtime?
  - Basis: Authors chose 6-month horizon as design choice without systematic exploration
  - Resolution: Systematic experiments varying training horizon lengths (3, 6, 9, 12 months) measuring training efficiency and agent performance

## Limitations
- Lack of ablation studies showing individual contributions of each mechanism
- Dependence on accurate simulator models for validation
- Computational overhead of attention-based comparison in real-time dispatch scenarios

## Confidence

- Mechanism 3 (WIP-inclusive objective): Low confidence
