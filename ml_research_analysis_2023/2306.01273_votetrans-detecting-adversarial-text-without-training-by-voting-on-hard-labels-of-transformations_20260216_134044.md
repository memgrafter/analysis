# VoteTRANS: Detecting Adversarial Text without Training by Voting on Transformations

## Quick Facts
- arXiv ID: 2306.01273
- Source URL: https://arxiv.org/abs/2306.01273
- Reference count: 27
- Primary result: Achieves up to 99.6% F1 score and 100% recall for adversarial text detection without training

## Executive Summary
VoteTRANS introduces a novel approach to detect adversarial text in NLP models without requiring training on adversarial examples. The method works by transforming each word in the input text using an auxiliary attack (PWWS), predicting labels for each transformation using the target model and optional support models, and comparing the original label with a majority vote of the transformed labels. If the original label is not in the majority vote set, the text is flagged as adversarial. Experiments demonstrate that VoteTRANS outperforms state-of-the-art detectors across various attacks, models, and datasets, achieving near-perfect detection rates while being flexible enough to handle new attack types without architectural modifications.

## Method Summary
VoteTRANS operates as a black-box adversarial text detector that leverages the instability of adversarial examples under word-level transformations. The method computes word importance scores using an auxiliary attack (typically PWWS), selects top words based on a configurable ratio, and generates transformation sets for each selected word. For each transformation, the method predicts the label using the target model and optional support models, then performs majority voting across all predictions. The original text's label is compared against this majority vote - if they differ, the text is classified as adversarial. The approach requires no training data and works by exploiting the observation that adversarial text tends to be more sensitive to word substitutions than benign text.

## Key Results
- Achieves F1 scores up to 99.6% and 100% recall across multiple datasets and attack types
- Outperforms state-of-the-art detectors FGWS and WDR on AG News, IMDB, YELP, and RTMR datasets
- Maintains strong performance across diverse models (LSTM, CNN, DistilBERT, BERT) and attacks (PWWS, TextFooler, IGA, BAE)
- Runtime analysis shows reasonable efficiency with configurable word ratio parameter

## Why This Works (Mechanism)

### Mechanism 1
- Claim: VoteTRANS detects adversarial text by leveraging the fact that adversarial text is more sensitive to word substitutions than original text.
- Mechanism: The method generates transformations of each word in the input text and compares the original model prediction with the majority vote of predictions on the transformed texts. If the original label is not in the majority or the majority contains multiple classes, the text is flagged as adversarial.
- Core assumption: Adversarial text has higher prediction instability under minor perturbations compared to original text.
- Evidence anchors: [abstract] "VoteTRANS detects adversarial text by comparing the hard labels of input text and its transformation." [section 3] "If we find any difference in the comparison, the adversarial text is identified."
- Break condition: If an attacker crafts text that remains stable under the chosen transformations, or if transformations are too aggressive and change meaning, the mechanism may fail.

### Mechanism 2
- Claim: Using multiple models (support models) improves detection robustness.
- Mechanism: Predictions from both the target model and optional support models are combined via majority voting to determine the transformed text's label, increasing the chance of catching adversarial examples that fool only one model.
- Core assumption: Adversarial examples often exploit specific vulnerabilities of a single model, so consensus across models is harder to fool.
- Evidence anchors: [section 3] "An optional word ratio α can be used to speed up the detection process. Moreover, a support model list F sup is used to improve the performance." [section 4.2] "The use of the RoBERTa model as support boosts the overall performance."
- Break condition: If the attacker crafts examples that fool all used models simultaneously, or if support models are not sufficiently diverse, the benefit diminishes.

### Mechanism 3
- Claim: VoteTRANS works without training by relying on black-box model predictions and transformations.
- Mechanism: The method uses an auxiliary attack to generate synonyms or transformations and relies solely on the target model's predictions, avoiding the need for labeled adversarial data or model modification.
- Core assumption: Transformations that preserve semantic similarity can be generated without training, and model predictions on these are informative.
- Evidence anchors: [abstract] "To the best of our knowledge, VoteTRANS is the first model to detect adversarial text from various attacks without training." [section 4.2] "VoteTRANS efficiently detects adversarial text except with Checklist, which generates independent adversarial text with any model and does not focus on the performance."
- Break condition: If transformations do not preserve semantics or are too limited, the black-box assumption fails.

## Architecture Onboarding

- Component map:
  Input text -> Target model -> Auxiliary attack (PWWS) -> Transformation generator -> Support models (optional) -> Majority voting logic -> Output (adversarial/original flag)

- Critical path:
  1. Compute word importance scores using auxiliary attack
  2. Select top words based on ratio α
  3. For each selected word, generate transformation set
  4. Replace word with each transformation and predict with target (and support) models
  5. Collect predictions, perform majority vote
  6. Compare original label with majority vote to decide

- Design tradeoffs:
  - Speed vs. accuracy: Larger α improves recall but increases runtime
  - Support models: Adding models improves robustness but increases computational cost
  - Transformation scope: Word-level vs. character-level attacks require different transformation strategies

- Failure signatures:
  - High false negatives: Adversarial texts that remain stable under transformations
  - High false positives: Original texts with ambiguous or short content that change prediction under minor edits
  - Slow performance: Large α or many support models

- First 3 experiments:
  1. Run VoteTRANS on a small set of original and adversarial texts using a simple target model and no support; verify detection rates
  2. Introduce a support model (e.g., RoBERTa) and measure improvement in recall/F1
  3. Vary α (word ratio) and plot detection time vs. performance to find optimal balance

## Limitations
- Performance degradation on short texts (RTMR dataset) due to limited word transformations available
- Dependence on quality of transformations generated by auxiliary attack - poor transformations lead to unreliable detection
- Computational cost increases with longer texts and larger word ratio parameter
- May fail against attacks that preserve semantic meaning while evading detection through alternative strategies

## Confidence

**High Confidence**: The claim that VoteTRANS can detect adversarial text without training is well-supported by the experimental results showing F1 scores up to 99.6% and 100% recall on multiple datasets and attack types.

**Medium Confidence**: The claim that using support models improves detection robustness is supported by experiments showing improved performance with RoBERTa, but lacks ablation studies demonstrating the marginal benefit of additional models.

**Low Confidence**: The claim that VoteTRANS works "without training" should be qualified - while it doesn't require training on adversarial examples, it does rely on an auxiliary attack (PWWS) which itself involves training. The training-free claim is somewhat misleading.

## Next Checks

1. **Adversarial Stability Analysis**: Systematically measure prediction instability (variance in model outputs) across transformations for both adversarial and benign examples across all attack types to empirically validate the core assumption about adversarial text sensitivity.

2. **Transformation Ablation Study**: Test VoteTRANS with different transformation generation methods (not just PWWS) and with different levels of transformation aggressiveness to understand how transformation quality affects detection performance and identify failure modes.

3. **Cross-Domain Generalization**: Evaluate VoteTRANS on texts from domains not seen during any auxiliary attack training (e.g., medical or legal texts) to assess whether the method generalizes beyond the tested datasets and whether domain-specific transformations are needed.
