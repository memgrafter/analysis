# Contrastive Hierarchical Clustering

## Quick Facts
- arXiv ID: 2303.03389
- Source URL: https://arxiv.org/abs/2303.03389
- Reference count: 17
- Key outcome: CoHiClust achieves state-of-the-art clustering accuracy on 5 out of 7 image datasets, with NMI scores ranging from 0.584-0.779

## Executive Summary
CoHiClust introduces a novel Contrastive Hierarchical Clustering approach for unsupervised image clustering that builds a binary tree hierarchy without labels. The method uses a contrastive loss and data augmentations to encourage similar images to follow the same path through the tree, while regularization terms prevent degenerate solutions. Experiments demonstrate state-of-the-art performance on multiple image datasets, with the constructed hierarchies reflecting image semantics and grouping visually similar classes together.

## Method Summary
CoHiClust builds a binary tree hierarchy for unsupervised image clustering using a backbone network to generate embeddings, a projection head to parameterize binary tree decisions, and a novel hierarchical contrastive loss. The method operates in two phases: pre-training the base network with contrastive learning, then constructing and fine-tuning the hierarchical tree structure. Regularization terms ensure balanced tree usage and improve representation quality, while pruning adjusts the number of leaves to match the desired cluster count.

## Key Results
- Achieves state-of-the-art clustering accuracy on 5 out of 7 tested datasets
- NMI scores range from 0.584 (CIFAR-10) to 0.779 (ImageNet-Dogs)
- Constructed hierarchies reflect image semantics, grouping visually similar classes together
- Regularization functions significantly boost performance, improving NMI by 0.2 points

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The hierarchical contrastive loss encourages similar images to follow the same path in the binary tree by maximizing the Bhattacharyya coefficient at each level.
- Mechanism: The loss function computes similarity between two data points as the sum of Bhattacharyya coefficients across tree levels. For augmented views of the same image, this similarity is maximized, pushing them to follow identical paths. For different images, similarity is minimized, pushing them to diverge earlier in the tree.
- Core assumption: Self-supervised data augmentations preserve semantic similarity between the original and augmented images.
- Evidence anchors:
  - [abstract] "The hierarchical clustering structure can be used to analyze the relationship between clusters, as well as to measure the similarity between data points."
  - [section] "By minimizing the above loss, we maximize the likelihood that similar data points follow the same path (second term) and minimize the likelihood that dissimilar ones are grouped together."
- Break condition: If augmentations change semantic content or if the similarity measure doesn't correlate with true semantic similarity, the tree structure will reflect augmentation artifacts rather than image semantics.

### Mechanism 2
- Claim: The regularization terms prevent degenerate solutions where all data points converge to a single leaf node.
- Mechanism: R1 encourages balanced tree usage by minimizing cross-entropy between the desired uniform distribution [0.5, 0.5] and actual routing decisions at each node. R2 improves representation quality through NT-Xent loss on projected embeddings, making the base network's output more discriminative.
- Core assumption: Balanced tree usage and high-quality embeddings are necessary for meaningful hierarchical clustering.
- Evidence anchors:
  - [section] "To enable end-to-end training of the base neural network with an arbitrary number of leaves, we consider two regularization strategies."
  - [section] "regularization functions have a significant impact on the results of CoHiClust boosting the NMI score by 0.2"
- Break condition: If regularization weights are set too high, the model may prioritize tree balance over semantic similarity, leading to suboptimal clustering.

### Mechanism 3
- Claim: Pre-training the backbone network with contrastive learning provides better initialization for hierarchical clustering.
- Mechanism: The pre-training phase trains the base network using only R2 regularization (NT-Xent loss), creating a representation that captures semantic similarity before tree construction begins. This allows the subsequent hierarchical contrastive loss to work with higher-quality embeddings.
- Core assumption: Good initial representations lead to better hierarchical clustering results than random initialization.
- Evidence anchors:
  - [section] "We verified that training is even more effective when we introduce a pre-training phase of the base neural network."
  - [section] "pre-trainig is an essential ingredient of CoHiClust, which allows selecting a better starting point for building a clustering tree."
- Break condition: If the pre-training phase overfits to specific augmentations or if the contrastive learning objective doesn't align with clustering goals, the initialization may not be beneficial.

## Architecture Onboarding

- Component map:
  Base neural network (g) -> Projection head π -> Binary tree decisions -> Hierarchical contrastive loss -> Regularization R1 and R2

- Critical path:
  1. Pre-train base network with R2 (NT-Xent)
  2. Initialize tree with random routing
  3. Apply hierarchical contrastive loss with R1 regularization
  4. Perform pruning to reduce leaf count
  5. Fine-tune with final tree structure

- Design tradeoffs:
  - Tree depth vs. optimization difficulty: Deeper trees provide finer granularity but harder optimization
  - Regularization strength vs. semantic preservation: Strong regularization may enforce balance at the cost of semantic structure
  - Pre-training duration vs. final performance: Longer pre-training generally helps but has diminishing returns

- Failure signatures:
  - All data points converge to one leaf: Insufficient regularization or overly strong contrastive loss
  - Poor clustering accuracy: Suboptimal pre-training or inappropriate backbone architecture
  - Degenerate tree structure: Imbalanced regularization or incorrect tree depth

- First 3 experiments:
  1. Train CoHiClust with and without pre-training on CIFAR-10 to verify the importance of initialization
  2. Vary the tree depth (4, 5, 6 levels) on CIFAR-10 to find optimal granularity
  3. Remove R1 regularization to observe its impact on tree balance and clustering performance

## Limitations
- High computational requirements due to deep hierarchical structure and multiple training phases
- Limited evaluation to image datasets, raising questions about generalizability to other data types
- Sensitive to hyperparameter choices, particularly regularization weights that significantly impact performance

## Confidence

The paper presents CoHiClust with several limitations and uncertainties. The main limitation is that the method requires significant computational resources due to its deep hierarchical structure and multiple training phases. The paper reports results only on image datasets, limiting generalizability to other data types like text or tabular data. Another concern is the sensitivity to hyperparameters, particularly the regularization weights β1 and β2, which significantly impact performance but optimal values may vary across datasets.

Confidence in the key claims is **High** for the hierarchical clustering approach itself and the overall methodology, as the mathematical formulation is well-defined and the experimental results are comprehensive. However, confidence in the specific mechanism claims is **Medium**, as the paper provides theoretical justification but limited ablation studies on the individual components. The claim that pre-training is "essential" has **Medium** confidence since the ablation shows improvement but doesn't explore the full space of initialization strategies.

The reported performance gains over state-of-the-art methods are promising but should be interpreted cautiously given that many baseline comparisons are from older literature, and direct comparisons may be affected by implementation differences.
