# Learning Translation Quality Evaluation on Low Resource Languages from Large Language Models

## Quick Facts
- arXiv ID: 2302.03491
- Source URL: https://arxiv.org/abs/2302.03491
- Reference count: 4
- Key outcome: LLM-generated synthetic data improves BLEURT-like model performance on low-resource languages when mixed with existing datasets

## Executive Summary
This paper addresses the challenge of learning translation quality evaluation metrics for low-resource languages where human-annotated data is scarce. The authors propose using large language models (LLMs) to generate synthetic sentence pairs and similarity scores, which can then be used to train or fine-tune learned metrics like BLEURT. By prompting an LLM (PaLM) to create diverse sentence pairs across multiple languages and score their similarity, the approach provides a scalable way to generate high-quality training data without requiring human annotators. The method demonstrates significant improvements on nine low-resource languages compared to models trained only on existing datasets.

## Method Summary
The authors use PaLM to generate synthetic training data for sentence similarity metrics by prompting it to create sentence pairs with specific properties (preserving or changing meaning) and scoring their similarity on a 0-4 scale. They filter sentences from the multilingual C4 corpus, generate modified sentences using carefully crafted prompts, and apply heuristic filtering to remove low-quality pairs. The synthetic data is mixed with existing WMT datasets and used to fine-tune an mT5-XL model to create a BLEURT-like metric. The approach requires only a text corpus in the target language and LLM access, making it scalable across many languages. The authors evaluate their method on an internal test set across multiple low-resource languages, showing consistent improvements over baseline models.

## Key Results
- BLEURT-like models trained with synthetic data outperform baseline models on low-resource languages
- Adding synthetic data from multiple languages leads to further improvements through cross-lingual transfer
- Performance gains are not guaranteed for every language, with some languages showing more improvement than others
- The approach is scalable and requires only a text corpus and LLM access, not human annotators

## Why This Works (Mechanism)

### Mechanism 1
- Claim: LLM-generated synthetic data improves low-resource language metrics
- Mechanism: The LLM can generate diverse, semantically meaningful sentence pairs across many languages, providing training examples that would be expensive to collect manually. This synthetic data is then mixed with existing datasets to train a BLEURT-like model, improving performance on low-resource languages.
- Core assumption: The LLM's knowledge of multiple languages and ability to generate diverse sentence pairs transfers effectively to the downstream metric model.
- Evidence anchors:
  - [abstract] "We show how knowledge can be distilled from Large Language Models (LLMs) to improve upon such learned metrics without requiring human annotators"
  - [section] "We show that the performance of a BLEURT-like model on lower resource languages can be improved in this way"
  - [corpus] Weak evidence - no direct corpus data provided for this mechanism
- Break condition: If the synthetic data quality is too low or the distribution shift between synthetic and real data is too large, performance improvements may not materialize.

### Mechanism 2
- Claim: Prompt engineering influences the quality and diversity of synthetic data
- Mechanism: Carefully crafted prompts guide the LLM to generate sentence pairs with specific properties (e.g., preserving meaning, changing meaning) and provide similarity scores. This control over data generation allows for targeted dataset creation.
- Core assumption: The LLM reliably follows prompt instructions and generates high-quality, diverse data.
- Evidence anchors:
  - [section] "We tested various prompts and based on the number of successfully generated pairs, settled on the following prompts"
  - [section] "Similar to prior works (Brown et al., 2020; Chowdhery et al., 2022), we create a template with a placeholder for the input sentence and use it to query PaLM"
  - [corpus] Weak evidence - no corpus data directly supporting this mechanism
- Break condition: If prompts are not well-designed or the LLM fails to follow instructions, the quality and diversity of generated data may be insufficient.

### Mechanism 3
- Claim: Mixing synthetic data from multiple languages improves cross-lingual transfer
- Mechanism: By generating synthetic data in multiple languages and mixing it with existing datasets, the model learns better cross-lingual representations and improves performance on low-resource languages.
- Core assumption: Knowledge gained from synthetic data in one language can transfer to improve performance in other languages.
- Evidence anchors:
  - [section] "We generate additional datasets in several languages... Depending on the experiment, a combination of these datasets are used as the final training set"
  - [section] "Results show that adding more synthetic data from different languages leads to further improvements"
  - [corpus] Weak evidence - no direct corpus data supporting this mechanism
- Break condition: If the languages are too dissimilar or the synthetic data quality varies significantly between languages, cross-lingual transfer may not occur effectively.

## Architecture Onboarding

- Component map:
  - LLM (PaLM) -> mT5-XL model -> BLEURT-like metric
  - Multilingual C4 dataset -> sentence selection -> synthetic data generation
  - Existing WMT datasets + synthetic data -> combined training data
  - Internal test set -> evaluation of low-resource languages

- Critical path:
  1. Select sentences from multilingual C4 corpus
  2. Generate synthetic sentence pairs using LLM prompts
  3. Score sentence pairs using LLM
  4. Filter and clean generated data
  5. Mix synthetic data with existing datasets
  6. Fine-tune mT5-XL model on combined data
  7. Evaluate on internal low-resource language test set

- Design tradeoffs:
  - Synthetic data quantity vs. quality: More data may improve performance but could introduce noise
  - Prompt specificity vs. diversity: Tighter prompts may yield more consistent data but less variety
  - Language coverage vs. resource allocation: Balancing which low-resource languages to focus on

- Failure signatures:
  - Poor performance on low-resource languages despite synthetic data addition
  - Inconsistent or low-quality synthetic data generation
  - Overfitting to synthetic data distribution

- First 3 experiments:
  1. Generate synthetic data for a single low-resource language and evaluate performance improvement
  2. Compare performance using zero-shot vs. few-shot prompts for data generation
  3. Test the effect of varying amounts of synthetic data mixed with baseline dataset on model performance

## Open Questions the Paper Calls Out
The paper doesn't explicitly call out open questions, but based on the methodology and results, several important questions remain unaddressed regarding the scalability, robustness, and optimization of the approach.

## Limitations
- Reliance on proprietary LLM access (PaLM) without open-sourcing specific prompts
- Evaluation depends on an internal test set with undisclosed composition
- Assumes LLMs possess adequate knowledge of all low-resource languages tested
- Performance gains vary significantly across language pairs

## Confidence
- High Confidence: The core finding that synthetic data generated by LLMs can improve BLEURT-like model performance on low-resource languages is well-supported by experimental results
- Medium Confidence: The claim that mixing synthetic data from multiple languages improves cross-lingual transfer is supported but shows varying effectiveness across languages
- Low Confidence: The assertion that this approach is "scalable to many languages" with minimal resources is somewhat speculative given limited testing

## Next Checks
1. **Prompt Robustness Testing:** Systematically vary the LLM prompts used for data generation to assess sensitivity of results to prompt engineering choices
2. **Distribution Shift Analysis:** Conduct detailed analysis of the synthetic data distribution compared to real human-annotated data to quantify potential label noise and distribution mismatch
3. **Resource Efficiency Evaluation:** Measure the computational and economic costs of generating synthetic data versus the performance gains achieved, particularly comparing few-shot and zero-shot prompting approaches
