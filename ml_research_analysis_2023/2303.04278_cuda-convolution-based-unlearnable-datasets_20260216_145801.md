# CUDA: Convolution-based Unlearnable Datasets

## Quick Facts
- arXiv ID: 2303.04278
- Source URL: https://arxiv.org/abs/2303.04278
- Authors: [Not specified in source]
- Reference count: 40
- Key outcome: Introduces CUDA, a method using class-wise convolution filters to generate unlearnable datasets that protect data privacy by causing models to learn filter-label relations rather than clean data features.

## Executive Summary
CUDA is a novel method for generating unlearnable datasets that protect data privacy by using class-wise convolution filters. These filters, generated with a private key, blur images in a structured, class-specific way that encourages models to learn filter-label shortcuts rather than informative features for clean data classification. The method demonstrates effectiveness across multiple datasets (CIFAR-10, CIFAR-100, ImageNet-100) and architectures (ResNet-18, VGG-16), achieving low clean test accuracies while maintaining high accuracy on the perturbed dataset itself. CUDA shows robustness to adversarial training, data augmentations, and transfer learning.

## Method Summary
CUDA generates unlearnable datasets by applying class-wise convolution filters to clean images. The method uses randomly generated filters (one per class) created via a private key, with each filter having one value set to 1 and the rest initialized from a uniform distribution. These filters blur images in a structured way that encourages models to learn filter-label relations rather than clean data features. The convolved images are then rescaled to maintain valid pixel values. Models trained on CUDA achieve high accuracy on the perturbed dataset but low accuracy on clean test data, demonstrating unlearnability. The method's effectiveness stems from the convolution theorem, which introduces multiplicative noise in the Fourier domain that is harder for adversarial training to suppress.

## Key Results
- CUDA achieves clean test accuracies as low as 8.96% on ImageNet-100 with ERM training
- The method remains effective across multiple architectures (ResNet-18, VGG-16) and datasets (CIFAR-10, CIFAR-100, ImageNet-100)
- CUDA demonstrates robustness to adversarial training with different budgets, maintaining low clean accuracies (51.19% on CIFAR-10, 36.90% on CIFAR-100, 40.08% on ImageNet-100)
- The method is effective even when only 20% of the training data is poisoned

## Why This Works (Mechanism)

### Mechanism 1: Class-wise Convolution Filters
Class-wise convolution filters trained with a private key cause models to learn filter-label shortcuts instead of clean data features. CUDA applies a unique convolutional filter per class during training, blurring images in a structured, class-specific way. The model learns to associate each filter's output with the class label, so when the filter is absent at test time, performance collapses. This mechanism assumes the model cannot easily learn to invert the convolution without access to the original clean images or the private key.

### Mechanism 2: Fourier Domain Noise Robustness
Multiplicative noise in the Fourier domain is more robust to adversarial training than additive noise. Convolution in the spatial domain equals element-wise multiplication in the Fourier domain, creating multiplicative noise patterns that are harder for adversarial training to suppress because they change the underlying frequency structure of the image rather than just adding small perturbations. This mechanism assumes L_p adversarial training budgets are insufficient to remove multiplicative convolution effects.

### Mechanism 3: Bayes Classifier Degradation
The Bayes-optimal classifier's accuracy degrades on Gaussian mixture data when class-wise convolutions are applied. CUDA transforms the clean Gaussian mixture into a new distribution with convolved means, shifting the Bayes boundary from linear to quadratic and increasing classification error on clean test data. This mechanism assumes the theoretical analysis in the Gaussian mixture model setting generalizes to real image data.

## Architecture Onboarding

- **Component map**: Generate private key -> Produce class-wise filters -> Convolve clean images with class filter -> Rescale to [0,1] -> Save perturbed dataset

- **Critical path**: 1. Generate private key → produce class-wise filters 2. Convolve each clean image with its class filter 3. Rescale to valid pixel range 4. Save perturbed dataset

- **Design tradeoffs**: Filter size vs. perceptual similarity (larger filters increase blur but risk detection); Blur parameter pb vs. unlearnability (higher pb increases effectiveness but may destroy semantics); Private key storage vs. security (key must be stored securely to prevent reverse-engineering)

- **Failure signatures**: Clean test accuracy > 50% on CUDA dataset → unlearnability failing; Filters easily learned by DAT → adaptive defense successful; Perceptual artifacts obvious to humans → filter too aggressive

- **First 3 experiments**: 1. Generate CUDA CIFAR-10 with k=3, pb=0.3 and confirm clean accuracy < 20% 2. Train ResNet-18 on CUDA and verify it achieves > 99% accuracy on CUDA test set but < 25% on clean test set 3. Apply random blurring augmentation during training and measure if clean accuracy increases

## Open Questions the Paper Calls Out

### Open Question 1
What is the theoretical limit of CUDA's effectiveness across different image distributions beyond Gaussian mixtures? The paper provides theoretical analysis for Gaussian mixture data but acknowledges it would be interesting to see analysis considering more complex setups. The theoretical framework relies on specific assumptions about Gaussian mixture models that may not capture the complexity of real-world image distributions.

### Open Question 2
How does CUDA perform against adaptive defenses that can reverse the convolution effect without access to clean data? While the paper demonstrates robustness to deconvolution-based adversarial training (DAT), there may be other adaptive defense strategies that could reverse the convolution effect. The paper assumes the defender cannot access clean data, but in practice, there might be ways to estimate the convolution filters from the CUDA dataset alone.

### Open Question 3
What is the minimum amount of CUDA poisoning required to maintain effectiveness while minimizing data loss? The paper shows CUDA remains effective even when only 20% of the training data is poisoned, but the relationship between poisoning percentage and unlearnability effect is not fully characterized. Additionally, the effectiveness with AT is limited, suggesting there may be a threshold below which CUDA becomes vulnerable.

### Open Question 4
Can CUDA be extended to other data modalities like text or tabular data? The current CUDA method relies on convolutional filters which are specific to image data. Other data modalities like text or tabular data have different structures and may require different types of transformations to achieve similar unlearnability effects.

### Open Question 5
What is the relationship between CUDA's blur parameter and its robustness to different types of adversarial training? While the paper demonstrates that CUDA works well with a specific blur parameter (pb = 0.3 for CIFAR-10), it doesn't explore how different blur parameters affect robustness to different types of AT (L-infinity vs L2, different budgets, etc.).

## Limitations
- The theoretical analysis assumes Gaussian mixture data, but generalization to real image data remains unproven
- Robustness to adversarial training is based on empirical observations rather than formal guarantees, particularly regarding Fourier-domain noise advantage
- The method's effectiveness against adaptive defenses like deconvolution-based attacks is not rigorously tested
- Reliance on a private key for filter generation prevents exact reproduction of results

## Confidence
- **High**: CUDA successfully reduces clean test accuracy across multiple datasets and architectures when using the specified parameters
- **Medium**: The claim that multiplicative Fourier-domain noise is more robust than additive noise lacks direct empirical comparison
- **Low**: The theoretical analysis in Gaussian mixture settings may not translate to real image distributions
