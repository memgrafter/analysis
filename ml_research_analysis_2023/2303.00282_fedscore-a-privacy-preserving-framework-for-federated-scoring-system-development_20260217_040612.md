# FedScore: A privacy-preserving framework for federated scoring system development

## Quick Facts
- **arXiv ID:** 2303.00282
- **Source URL:** https://arxiv.org/abs/2303.00282
- **Reference count:** 40
- **Primary result:** FedScore achieves 0.763 AUC with 0.020 SD for 30-day mortality prediction across 10 simulated sites

## Executive Summary
FedScore is a privacy-preserving framework enabling federated development of scoring systems across multiple sites without direct data sharing. The framework integrates federated variable ranking, transformation, score derivation, model selection, and evaluation to ensure generalizability and stability across heterogeneous datasets. Using a 30-day mortality prediction task with simulated data across 10 sites, FedScore demonstrates performance comparable to centralized pooling while preserving data privacy.

The framework addresses critical challenges in healthcare analytics where data sharing is restricted by privacy regulations, institutional policies, or technical barriers. By enabling collaborative model development without raw data exchange, FedScore allows institutions to leverage collective expertise and data diversity while maintaining data sovereignty and patient privacy.

## Method Summary
FedScore employs a federated learning approach where participating sites contribute to model development without sharing raw data. The framework uses a client-server architecture where the server orchestrates the federated learning process while clients perform local computations. Key components include federated variable ranking using gradient-based methods, local model training with privacy-preserving aggregations, and cross-site model evaluation to ensure generalizability.

The methodology involves initializing the federated learning process, performing local training at each site, aggregating model updates using secure protocols, and evaluating the federated model across all sites. The framework specifically targets scoring system development where interpretability and clinical utility are paramount, distinguishing it from traditional black-box machine learning approaches.

## Key Results
- Achieved average AUC of 0.763 with standard deviation of 0.020 for 30-day mortality prediction
- Outperformed local models trained independently at individual sites
- Performance closely matched centralized pooling approach while preserving privacy

## Why This Works (Mechanism)
FedScore leverages federated learning principles to enable collaborative model development without data sharing. The framework uses secure aggregation protocols to combine model updates from multiple sites while preserving data privacy. Local sites perform gradient computations and model updates using their proprietary data, then transmit only aggregated updates to the central server.

The federated averaging algorithm enables consensus model building across heterogeneous datasets by weighting contributions based on local dataset characteristics. This approach preserves data privacy through encryption and secure multi-party computation while maintaining model accuracy through coordinated optimization across all participating sites.

## Architecture Onboarding

**Component Map:** Data Sources -> Local Processing -> Secure Aggregation -> Federated Model -> Evaluation

**Critical Path:** Variable Ranking → Local Model Training → Secure Aggregation → Model Evaluation

**Design Tradeoffs:** Privacy vs. Performance (stronger privacy guarantees may reduce model accuracy), Interpretability vs. Complexity (simple scoring systems may underperform complex models), Communication Overhead vs. Model Quality (more frequent updates improve convergence but increase bandwidth)

**Failure Signatures:** Poor convergence indicates insufficient local data quality, high variance across sites suggests model instability, communication bottlenecks reveal infrastructure limitations

**First 3 Experiments:** 1) Validate federated variable ranking produces consistent feature importance across sites, 2) Test model convergence with varying numbers of participating sites, 3) Measure privacy-utility tradeoff by varying encryption strength
