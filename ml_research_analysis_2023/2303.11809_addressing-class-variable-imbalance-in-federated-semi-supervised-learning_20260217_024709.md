# Addressing Class Variable Imbalance in Federated Semi-supervised Learning

## Quick Facts
- arXiv ID: 2303.11809
- Source URL: https://arxiv.org/abs/2303.11809
- Reference count: 26
- Primary result: FCVI achieves higher accuracy, recall, precision, and F1 scores compared to baseline methods under class variable imbalance scenarios

## Executive Summary
This paper introduces a novel approach to address class variable imbalance in federated semi-supervised learning (FSSL), where the number of classes changes due to devices joining or leaving the training process. The proposed method, Federated Semi-supervised Learning for Class Variable Imbalance (FCVI), leverages gradient information to monitor class changes without transmitting additional data, thereby preserving privacy. FCVI then selectively expands data using unlabeled data and semi-supervised self-training to mitigate imbalance. Experiments on ImageNet with AlexNet demonstrate FCVI's effectiveness in maintaining model performance while adapting to changing class distributions.

## Method Summary
The paper proposes FCVI, a method designed to handle class variable imbalance in federated semi-supervised learning. FCVI monitors class changes using gradient information, avoiding the need to transmit additional data and preserving privacy. It then selectively expands data using unlabeled data and semi-supervised self-training to mitigate imbalance. The approach is evaluated on ImageNet with AlexNet, showing significant improvements in accuracy, recall, precision, and F1 scores compared to baseline methods (FedRL, K-SMOTE, FedAvg) under both class-increasing and class-decreasing imbalance scenarios.

## Key Results
- FCVI achieves higher accuracy compared to baseline methods (FedRL, K-SMOTE, FedAvg) under class variable imbalance scenarios
- FCVI demonstrates improved recall, precision, and F1 scores in maintaining model performance during class changes
- The method effectively adapts to both class-increasing and class-decreasing imbalance scenarios

## Why This Works (Mechanism)
FCVI works by monitoring class changes using gradient information, which allows it to detect imbalances without requiring additional data transmission. This gradient-based monitoring preserves privacy while enabling the system to identify when class distributions are shifting. Once an imbalance is detected, FCVI selectively expands the underrepresented classes using unlabeled data through semi-supervised self-training. This approach ensures that the model can adapt to new or disappearing classes without compromising the privacy of the participating devices.

### Semi-supervised Learning
**Why needed**: Allows leveraging unlabeled data to improve model performance when labeled data is scarce
**Quick check**: Ensure pseudo-labels generated from unlabeled data are sufficiently accurate

### Class Imbalance Handling
**Why needed**: Prevents model bias towards majority classes when class distributions are uneven
**Quick check**: Monitor per-class performance metrics to ensure balanced learning

### Privacy Preservation
**Why needed**: Protects sensitive data on participating devices from being exposed during collaborative learning
**Quick check**: Verify that no raw data is transmitted outside local devices

### Gradient-based Monitoring
**Why needed**: Enables detection of class distribution changes without additional data transmission
**Quick check**: Validate that gradient patterns reliably indicate class changes

## Architecture Onboarding

### Component Map
Client Devices -> Gradient Monitoring -> Imbalance Detection -> Selective Data Expansion -> Model Update

### Critical Path
The critical path involves gradient monitoring to detect class changes, followed by selective data expansion using semi-supervised self-training. This path ensures that the model can adapt to new or disappearing classes while preserving privacy.

### Design Tradeoffs
- **Privacy vs. Monitoring Accuracy**: Using gradient information preserves privacy but may be less precise than direct data inspection
- **Computational Overhead**: Selective data expansion requires additional computation but improves model robustness
- **Communication Efficiency**: Avoiding additional data transmission reduces communication costs but may limit monitoring granularity

### Failure Signatures
- Poor performance on newly added classes may indicate insufficient data expansion
- Degraded overall accuracy could suggest ineffective gradient-based monitoring
- Privacy breaches might occur if gradient information is not properly anonymized
