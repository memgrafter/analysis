# Availability Adversarial Attack and Countermeasures for Deep Learning-based Load Forecasting

## Quick Facts
- arXiv ID: 2301.01832

- Authors: 
- Reference count: 21

## Executive Summary
This paper addresses adversarial attacks on deep learning-based load forecasting models by proposing availability-based attacks as a more practical alternative to integrity-based attacks. The authors formulate availability attacks as a mixed-integer linear programming problem to optimally determine which input features to block, considering operator strategies for imputing missing data. To defend against these attacks, they propose an adversarial training algorithm that minimizes loss on worst-case attack instances while maintaining performance on clean data. Experiments show that availability attacks can achieve comparable performance to integrity attacks with significantly lower implementation cost, while the proposed adversarial training significantly improves model robustness.

## Method Summary
The authors formulate availability attacks as a mixed-integer linear programming (MILP) problem that determines the optimal set of features to block given an attack budget. The MILP reformulation uses the big-M method to handle ReLU constraints in piecewise linear neural networks, guaranteeing global optimality. The attack considers operator imputation strategies (zero or mean imputation) for missing features. To defend against these attacks, the authors propose an adversarial training algorithm that minimizes loss on worst-case attack instances during training while maintaining performance on clean data. The method is evaluated on a realistic load forecasting dataset using a 40-20-10-1 piecewise linear neural network architecture.

## Key Results
- Availability attacks achieve comparable performance to integrity attacks with much lower implementation cost
- The proposed adversarial training significantly improves model robustness, reducing mean percentage error by over 50% on attacked samples
- Adversarial training only increases mean absolute percentage error by 1% on clean samples while providing substantial robustness gains

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Availability attacks can achieve comparable performance to integrity attacks with much lower implementation cost
- Mechanism: By blocking input features rather than manipulating them, availability attacks exploit the model's inability to handle missing data, while integrity attacks require packet manipulation and retransmission
- Core assumption: Operators use simple imputation strategies (zero or mean) for missing features, which the attacker can anticipate
- Evidence anchors:
  - [abstract]: "availability-based adversarial attacks, which can be more easily implemented by attackers"
  - [section]: "the availability attack is much cheaper, as it only requires the attackers to block measurements"
  - [corpus]: "availability attack is much cheaper than integrity attack as the attacker does not need to manipulate the data and repackage the packets"
- Break condition: If operators use sophisticated imputation methods that are difficult to predict, or if missing data detection mechanisms are in place

### Mechanism 2
- Claim: The MILP reformulation guarantees global optimality for availability attacks
- Mechanism: By transforming the ReLU-based piecewise linear neural network into a mixed-integer linear program, the attack can find the globally optimal set of features to block
- Core assumption: The neural network has a piecewise linear structure with ReLU activations that can be reformulated using big-M method
- Evidence anchors:
  - [section]: "The optimality of the attack is guaranteed by reformulating the PLNN into mixed integer linear programming (MILP)"
  - [section]: "The optimization problem (5) is non-convex due to the maximization constraint caused by ReLU. However, it can be easily transformed into an MILP using the big-M method"
  - [corpus]: "the attack is optimally found through MILP subject to certain attack budget"
- Break condition: If the network contains non-linear activation functions that cannot be reformulated into MILP, or if the problem becomes too large to solve efficiently

### Mechanism 3
- Claim: Adversarial training improves robustness against availability attacks while maintaining clean accuracy
- Mechanism: By minimizing loss on worst-case attack instances during training, the model learns to handle missing features more effectively, reducing the attack's effectiveness
- Core assumption: Including both clean and adversarial loss during training prevents overfitting to attack patterns while maintaining generalization
- Evidence anchors:
  - [abstract]: "The proposed adversarial training significantly improves model robustness, reducing mean percentage error by over 50% on attacked samples"
  - [section]: "the loss of the worst-case attack is minimized in each epoch"
  - [corpus]: "adversarial training can effectively reduce MPE by more than 50% on the adversarial samples while only increasing 1% MAPE on the clean samples"
- Break condition: If the attack budget is too large or the imputation strategy is too complex, the adversarial training may not capture the full attack space

## Architecture Onboarding

- Component map: Data preprocessing -> PLNN training -> MILP attack formulation -> Adversarial training -> Performance evaluation
- Critical path: Data → Model Training → Attack Formulation → Defense Evaluation → Performance Metrics
- Design tradeoffs:
  - Attack budget β vs. attack effectiveness: Higher budget allows more features to be blocked but may not linearly increase attack strength
  - Computational time vs. solution quality: Parallel MILP computation reduces training time but may sacrifice some optimization
  - Defense strength vs. clean accuracy: Stronger adversarial training improves robustness but slightly reduces clean performance
- Failure signatures:
  - MILP solver fails to find feasible solutions: Check bounds propagation and big-M parameters
  - Adversarial training doesn't improve robustness: Verify that attack budget matches training budget and check loss balance
  - Clean accuracy drops significantly: Reduce adversarial training strength or adjust loss weighting
- First 3 experiments:
  1. Baseline evaluation: Run availability attacks (β=1,2,3,4,5,6) on clean model and measure MPE vs. integrity attacks
  2. Defense effectiveness: Train adversarial model with c=0 and c=mean, then compare MPE reduction on attacked samples
  3. Computational optimization: Compare sequential vs. parallel MILP computation time and solution quality tradeoff

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can we effectively balance the cost and impact of availability attacks on load forecasting systems?
- Basis in paper: [explicit] The paper concludes by stating that balancing the cost and impact of availability attacks is an unsolved problem that will be left for future work.
- Why unresolved: The paper only demonstrates that availability attacks are cheaper than integrity attacks but does not provide a framework for optimizing this trade-off or determining acceptable thresholds for different operational contexts.
- What evidence would resolve it: A quantitative framework that establishes cost-benefit relationships between attack implementation costs and forecasting accuracy degradation, along with operational thresholds for different grid reliability requirements.

### Open Question 2
- Question: Can adversarial training algorithms be optimized to better handle both maximization and minimization attacks in availability attacks?
- Basis in paper: [explicit] The paper notes that both A V AI(max, c, 6) and A V AI(min,c, 6) attacks contribute equally to the adversarial loss function, which may not be optimal since the A V AI(min, 0, 6) attack is much stronger than A V AI(max, 0, 6).
- Why unresolved: The current adversarial training approach uses equal weighting (βmax = βmin = 1) for both types of attacks, which may not provide optimal robustness against the stronger minimization attacks while maintaining performance on clean data.
- What evidence would resolve it: Experimental results showing improved performance when using different hyperparameters (βmax > 1 > βmin > 0) for the two types of attacks, along with theoretical justification for these weightings.

### Open Question 3
- Question: How can the proposed availability attack and adversarial training methods be extended to convolutional neural networks for load forecasting?
- Basis in paper: [inferred] The paper mentions in Remark 2 that the proposed methods can be extended to other types of piecewise linear layers, such as convolutional layers, but leaves this discussion for future work due to page limitations.
- Why unresolved: The current implementation focuses on feedforward neural networks, and extending to CNNs would require addressing the spatial structure of convolutional layers and potentially different attack strategies for feature maps.
- What evidence would resolve it: Successful implementation and experimental validation of availability attacks and adversarial training on CNN-based load forecasting models, demonstrating comparable or improved robustness relative to the feedforward network results.

## Limitations
- Architecture Specificity: The approach relies on piecewise linear neural networks with ReLU activations, limiting generalization to more complex architectures
- Imputation Strategy Dependency: Attack effectiveness heavily depends on operators using simple imputation strategies
- Computational Scalability: MILP-based attack formulation may face scalability challenges with larger networks or higher-dimensional feature spaces
