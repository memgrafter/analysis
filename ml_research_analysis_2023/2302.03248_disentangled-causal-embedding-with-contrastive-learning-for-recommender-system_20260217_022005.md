# Disentangled Causal Embedding With Contrastive Learning For Recommender System

## Quick Facts
- arXiv ID: 2302.03248
- Source URL: https://arxiv.org/abs/2302.03248
- Authors: 
- Reference count: 35

## Executive Summary
This paper addresses the challenge of disentangling user interest and conformity in recommender systems by proposing DCCL, a contrastive learning framework that uses sample augmentation to learn separate causal embeddings for these two causes of user-item interactions. The framework is model-agnostic and can be applied to any base recommendation model. Experiments on two real-world datasets and online A/B testing on Kuaishou demonstrate significant improvements over state-of-the-art baselines, particularly for long-tail items and in out-of-distribution environments.

## Method Summary
DCCL uses contrastive learning with sample augmentation to disentangle user interest and conformity embeddings. The framework leverages popularity signals to create augmented samples for both causes - inversely weighting popularity for interest embeddings and positively weighting it for conformity embeddings. Two separate contrastive learning tasks are trained alongside the base recommendation model, with the disentangled embeddings integrated through a multi-task loss. The approach is model-agnostic and can be applied to existing recommendation systems like MF and LightGCN without changing inference complexity.

## Key Results
- Outperforms state-of-the-art baselines in Hit Ratio and NDCG metrics
- Shows significant improvements for long-tail items (improving F1 score from 0.0423 to 0.0571)
- Demonstrates robustness in out-of-distribution environments with better generalization
- Online A/B testing shows 7.362% relative improvement in effective-view-through rate and 41.82% improvement in like-through rate compared to MACR baseline

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Contrastive learning with augmented samples enables disentangled embeddings for interest and conformity.
- Mechanism: The framework uses two separate contrastive learning tasks, one for interest and one for conformity, where augmented samples are created by leveraging popularity signals. For interest, popularity weights are inversely applied to push embeddings toward pure interest. For conformity, negative samples with higher popularity than the target item are filtered to ensure conformity is learned as following popular items.
- Core assumption: User-item interactions can be decomposed into distinct interest and conformity causes, and each can be learned separately using augmented samples with appropriate popularity weighting.
- Evidence anchors:
  - [abstract]: "We propose DCCL, a framework that adopts contrastive learning to disentangle these two causes by sample augmentation for interest and conformity respectively."
  - [section]: "To better learn disentangled embeddings, we augment samples for interest and conformity respectively by leveraging the popularity signal."
  - [corpus]: Weak - no direct corpus support for this specific contrastive augmentation mechanism.
- Break condition: If the augmented samples don't reflect the true underlying interest and conformity causes, the embeddings will be incorrectly learned and performance will degrade.

### Mechanism 2
- Claim: Integrating popularity signals into contrastive loss helps learn disentangled embeddings from raw interaction data.
- Mechanism: The framework integrates popularity signals into the contrastive loss function for both interest and conformity tasks. For interest, the popularity weight is exp(-pop) to reduce the influence of popular items. For conformity, the weight is (1 - exp(-pop)) to increase the influence of popular items.
- Core assumption: Popularity can serve as a proxy signal to differentiate between interest and conformity causes in user interactions.
- Evidence anchors:
  - [section]: "Therefore, the user-item pair contrastive loss for interest is defined as follows: L_{ui}^{int} = -1/N sum_{log exp(-pop) x exp(S(Eu_int, Ei_int+)) / (exp(S(Eu_int, Ei_int+)) + sum_{exp(S(Eu_int, Ei_int-))}), where I_pop represents the normalized popularity of the interacted item."
  - [section]: "Similarly, for conformity causal embedding, (Eu_conf, Ei_conf+) is the positive user-item pair... The popularity signal of target item is also integrated into user-item pair contrastive loss for conformity as follows: L_{ui}^{conf} = -1/N sum_{log (1 - exp(-pop)) x exp(S(Eu_conf, Ei_conf+)) / (exp(S(Eu_conf, Ei_conf+)) + sum_{exp(S(Eu_conf, Ei_conf-))}), where 1 - exp(-pop) ensures interaction with higher popularity item is attributed more to conformity."
  - [corpus]: Weak - no direct corpus support for using popularity as a disentanglement signal.
- Break condition: If popularity doesn't correlate with conformity in the target domain, the embeddings won't be properly disentangled.

### Mechanism 3
- Claim: The model-agnostic design allows DCCL to be applied to any base recommendation model.
- Mechanism: DCCL only deals with embeddings and can be applied on top of any specific models, such as MF and LightGCN. It introduces extra costs for calculating contrastive loss in training but doesn't change inference complexity.
- Core assumption: The disentanglement can be learned at the embedding level without modifying the base model architecture.
- Evidence anchors:
  - [abstract]: "Furthermore, DCCL is model-agnostic, which can be easily deployed in any industrial online system."

- Break condition: If the base model's embedding space doesn't support the disentanglement, the approach won't work regardless of the contrastive learning framework.

## Architecture Onboarding

- Component map:
  - Base recommendation model (MF, LightGCN, etc.) -> Embedding generation layer -> Two contrastive learning heads (interest and conformity) -> Popularity signal extraction module -> Multi-task loss combiner -> Output layer for final recommendation

- Critical path:
  1. User-item interaction data → Base model → Base embeddings
  2. Base embeddings + popularity signal → Contrastive heads → Disentangled embeddings
  3. Disentangled embeddings → Multi-task loss → Parameter updates
  4. Updated embeddings → Base model → Final recommendation

- Design tradeoffs:
  - Using popularity as a proxy for conformity vs. collecting explicit conformity labels
  - Augmenting samples for both causes vs. splitting data by popularity thresholds
  - Model-agnostic approach vs. specialized architecture for causal disentanglement

- Failure signatures:
  - Performance degrades significantly on long-tail items
  - Metrics don't improve when switching from single-cause to multi-cause models
  - Online A/B testing shows no improvement over baseline models
  - The disentangled embeddings don't show clear separation in embedding space

- First 3 experiments:
  1. Implement DCCL with MF backbone on a small dataset, verify that HR@20 improves over MF baseline
  2. Test the two auxiliary tasks separately (remove IPCL, then remove CPCL) to understand their individual contributions
  3. Evaluate OOD performance by creating test sets with different popularity distributions and measuring robustness

## Limitations

- The framework relies on popularity signals as a proxy for conformity, which may not hold across all recommendation domains or cultural contexts
- Sample augmentation strategy for contrastive learning is not fully specified, leaving ambiguity about exact implementation
- The choice of hyperparameters (α=0.1, β=0.1) appears arbitrary without sensitivity analysis or justification

## Confidence

- **High confidence**: The model-agnostic design allowing integration with existing recommendation systems
- **Medium confidence**: The contrastive learning framework's ability to disentangle interest and conformity embeddings
- **Low confidence**: The assumption that popularity is a reliable proxy for conformity across all recommendation domains
