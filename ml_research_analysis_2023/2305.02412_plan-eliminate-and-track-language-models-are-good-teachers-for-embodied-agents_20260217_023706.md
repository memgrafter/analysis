# Plan, Eliminate, and Track -- Language Models are Good Teachers for Embodied Agents

## Quick Facts
- arXiv ID: 2305.02412
- Source URL: https://arxiv.org/abs/2305.02412
- Reference count: 9
- Improvement: 15% better task completion on AlfWorld benchmark compared to state-of-the-art methods

## Executive Summary
This paper introduces the Plan, Eliminate, and Track (PET) framework that leverages large language models (LLMs) to assist embodied agents in complex control tasks. The framework breaks down tasks into high-level sub-tasks using LLMs, masks irrelevant objects/receptacles in observations, and tracks progress through zero-shot QA models. PET achieves significant improvements in generalization to human goal specifications on the AlfWorld benchmark, demonstrating that LLMs can effectively simplify complex tasks and provide common-sense knowledge to embodied agents without requiring fine-tuning.

## Method Summary
The PET framework consists of three main modules: Plan, Eliminate, and Track. The Plan module uses a pre-trained LLM to translate task descriptions into high-level sub-tasks. The Eliminate module employs zero-shot QA models to mask irrelevant objects and receptacles from observations based on the current sub-task. The Track module uses another zero-shot QA model to determine when sub-tasks are complete. An Action Attention agent handles the dynamic action space in text environments by embedding actions and using attention mechanisms to select the most relevant action for the current state and sub-task. The framework is trained using behavior cloning on expert trajectories from the AlfWorld environment.

## Key Results
- Achieves 15% improvement over state-of-the-art methods for generalization to human goal specifications
- Improves average completion rate from 34% to 49% on AlfWorld benchmark
- Demonstrates significant contributions from each PET component, with sub-task planning and tracking particularly beneficial for tasks requiring counting procedures

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Breaking down complex tasks into high-level sub-tasks using LLMs improves generalization by simplifying the control problem.
- Mechanism: The Plan module leverages the procedural knowledge in LLMs to translate a complex task description into a sequence of manageable sub-tasks, which can be executed by a low-level trainable actor.
- Core assumption: LLMs have sufficient procedural knowledge to generate accurate sub-tasks for a wide range of tasks without fine-tuning.
- Evidence anchors:
  - [abstract] "The Plan module translates a task description into a list of high-level sub-tasks."
  - [section 3.1] "We propose the Plan, Eliminate, and Track (PET) framework. The Plan module translates a task description into a list of high-level sub-tasks."
- Break condition: The LLM lacks sufficient procedural knowledge for the task, or the generated sub-tasks are not executable by the low-level actor.

### Mechanism 2
- Claim: Masking irrelevant objects and receptacles using zero-shot QA models reduces the complexity of the observation space for the agent.
- Mechanism: The Eliminate module uses a pre-trained QA model to score and mask objects and receptacles that are irrelevant to the current sub-task, reducing the number of objects in the observation by 40% on average.
- Core assumption: The zero-shot QA model can accurately identify irrelevant objects and receptacles based on common-sense knowledge.
- Evidence anchors:
  - [abstract] "The Eliminate module masks out irrelevant objects and receptacles from the observation for the current sub-task."
  - [section 3.2] "We therefore propose to leverage commonsense knowledge captured by large pre-trained QA models to design our Eliminate moduleME to mask out irrelevant receptacles and objects."
- Break condition: The QA model incorrectly masks relevant objects or receptacles, or the decision threshold is set too high or too low.

### Mechanism 3
- Claim: Tracking the completion of sub-tasks using zero-shot QA models enables the agent to progress through the task in a step-by-step manner.
- Mechanism: The Track module uses a zero-shot QA model to determine if the current sub-task is complete, and if so, moves to the next sub-task.
- Core assumption: The zero-shot QA model can accurately detect the completion of sub-tasks based on the agent's actions and observations.
- Evidence anchors:
  - [abstract] "Finally, the Track module determines whether the agent has accomplished each sub-task."
  - [section 3.3] "We use a pre-trained QA model to design the Track moduleMT to perform zero-shot sub-task completion detection."
- Break condition: The QA model fails to detect the completion of a sub-task, or the agent needs to revisit a previously completed sub-task.

## Architecture Onboarding

- Component map: Task description → Plan module → Eliminate module → Action Attention agent → Environment → Track module → Plan module (next sub-task)

- Critical path: Task description → Plan module → Eliminate module → Action Attention agent → Environment → Track module → Plan module (next sub-task)

- Design tradeoffs:
  - Using pre-trained LLMs for planning and filtering reduces the need for task-specific fine-tuning but may introduce biases from the pre-training data.
  - Zero-shot QA models for filtering and tracking are efficient but may not be as accurate as fine-tuned models.
  - The Action Attention agent handles dynamic action spaces but may struggle with very large action spaces.

- Failure signatures:
  - Plan module: Generates irrelevant or incorrect sub-tasks.
  - Eliminate module: Masks relevant objects or receptacles, or fails to mask irrelevant ones.
  - Track module: Fails to detect the completion of a sub-task or incorrectly marks a sub-task as complete.
  - Action Attention agent: Takes incorrect actions or fails to handle the dynamic action space effectively.

- First 3 experiments:
  1. Evaluate the Plan module's sub-task generation accuracy on a held-out set of task descriptions.
  2. Measure the Eliminate module's object and receptacle masking accuracy using a zero-shot QA model.
  3. Test the Action Attention agent's performance on a simple task with a small action space to ensure it can handle dynamic action spaces.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How would PET perform on non-text environments or multimodal tasks?
- Basis in paper: [explicit] The paper discusses PET's compatibility with non-text environments but primarily tests on text-based AlfWorld. It mentions that using LLMs as actors limits generalization to other modalities.
- Why unresolved: The paper does not provide experimental results or analysis for PET's performance in non-text or multimodal environments.
- What evidence would resolve it: Testing PET on multimodal benchmarks or real-world robotic tasks with visual and/or auditory inputs.

### Open Question 2
- Question: What is the optimal way to handle situations where the Track module incorrectly marks a sub-task as complete, leading to potential failure in task completion?
- Basis in paper: [explicit] The paper mentions that the current system design does not allow revisiting finished sub-tasks, which could be problematic if a sub-task is undone.
- Why unresolved: The paper identifies this limitation but does not propose or test solutions for handling such situations.
- What evidence would resolve it: Experiments comparing PET's performance with and without mechanisms for sub-task-level dynamic replanning or error recovery.

### Open Question 3
- Question: How does the performance of PET scale with increasing task complexity and environment size?
- Basis in paper: [inferred] The paper discusses PET's ability to handle dynamic action spaces and long observations, but does not provide analysis on performance degradation with larger, more complex environments.
- Why unresolved: While the paper demonstrates PET's effectiveness on the AlfWorld benchmark, it does not explore how performance changes with increasingly complex tasks or larger environments.
- What evidence would resolve it: Comparative experiments showing PET's performance across environments of varying sizes and task complexities, measuring completion rates and efficiency metrics.

## Limitations
- Reliance on pre-trained LLMs and zero-shot QA models means performance depends heavily on pre-training data quality and coverage
- Framework primarily evaluated on AlfWorld benchmark, which may not represent full complexity of real-world embodied agent challenges
- Does not extensively explore failure cases or edge conditions where the framework might struggle

## Confidence
**High Confidence Claims:**
- The PET framework improves task completion rates by 15% on the AlfWorld benchmark compared to SOTA methods.
- Each component of PET (Plan, Eliminate, Track) contributes to overall performance, with sub-task planning and tracking particularly beneficial for tasks requiring counting procedures.
- Zero-shot QA models can effectively filter irrelevant objects/receptacles without task-specific fine-tuning.

**Medium Confidence Claims:**
- The framework generalizes to human goal specifications containing unseen verbs and nouns.
- LLMs can reliably translate complex task descriptions into executable sub-tasks without fine-tuning.
- The Action Attention agent can handle dynamic action spaces in text environments effectively.

## Next Checks
