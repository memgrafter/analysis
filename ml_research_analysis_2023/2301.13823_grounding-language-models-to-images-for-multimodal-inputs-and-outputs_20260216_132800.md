# Grounding Language Models to Images for Multimodal Inputs and Outputs

## Quick Facts
- arXiv ID: 2301.13823
- Source URL: https://arxiv.org/abs/2301.13823
- Authors: 
- Reference count: 40
- One-line primary result: FROMAGe grounds frozen language models to images using linear layers, enabling zero-shot multimodal tasks while preserving in-context learning abilities.

## Executive Summary
This paper introduces FROMAGe, a method to ground frozen language models to images by training input and output linear layers. The model is trained with a multi-task objective of image captioning and image-text retrieval. FROMAGe can process arbitrarily interleaved image-text inputs and generate coherent text interleaved with retrieved images. The model achieves strong zero-shot performance on grounded tasks such as contextual image retrieval and multimodal dialogue, outperforming baselines like CLIP on retrieval accuracy. It is computationally efficient, trained in 24 hours on a single GPU, and leverages the in-context learning abilities of pretrained language models.

## Method Summary
FROMAGe grounds frozen language models to images by training input and output linear layers while keeping the LLM and visual encoder frozen. The model uses a multi-task training objective combining image captioning and image-text retrieval losses. During training, images are encoded using a frozen CLIP visual encoder, mapped to the text space via a linear layer, and processed alongside tokenized text. A special [RET] token is added to enable image retrieval within generated text. The model is trained on Conceptual Captions dataset for one epoch and evaluated on zero-shot visual dialogue and contextual image retrieval tasks.

## Key Results
- FROMAGe achieves strong zero-shot performance on grounded tasks like contextual image retrieval and multimodal dialogue
- Outperforms baselines like CLIP on retrieval accuracy, particularly for long and complex free-form text
- Preserves in-context learning abilities of frozen language models while enabling multimodal interactions
- Trained efficiently in 24 hours on a single GPU using only image-text pairs from CC3M

## Why This Works (Mechanism)

### Mechanism 1
- Claim: FROMAGe achieves strong zero-shot performance on grounded tasks by leveraging in-context learning abilities of frozen LLMs.
- Mechanism: The model retains the pretrained LLM's in-context learning capabilities by freezing its parameters and only fine-tuning input/output linear layers. This allows the model to rapidly adapt to new multimodal tasks with minimal examples.
- Core assumption: The pretrained LLM's in-context learning abilities are preserved when its parameters are frozen.
- Evidence anchors:
  - [abstract] "We keep the language model frozen, and finetune input and output linear layers to enable cross-modality interactions."
  - [section 5.3] "FROMAGe is capable of learning in-context to perform many different zero-shot and few-shot tasks."
- Break condition: If the frozen LLM loses its in-context learning capabilities during fine-tuning of the linear layers.

### Mechanism 2
- Claim: The special [RET] token enables FROMAGe to generate coherent interleaved image-text outputs.
- Mechanism: The [RET] token is added to the model vocabulary and its embedding is learned during training. This allows the model to perform an extra step of attention over all tokens in the text to produce a stronger text representation for the caption, and to generate [RET] at inference time for seamless interleaving of image retrieval within generated text.
- Core assumption: The [RET] token embedding can be learned without affecting the performance of other tokens.
- Evidence anchors:
  - [section 3.2] "We propose adding a special [RET] token to the model vocabulary and learning its embeddings (keeping all other token embeddings frozen)."
  - [section 4.1] "FROMAGe also effectively conditions on multimodal context (which previous image-text retrieval models are incapable of)."
- Break condition: If learning the [RET] token embedding causes catastrophic forgetting of other token embeddings.

### Mechanism 3
- Claim: FROMAGe outperforms baselines like CLIP on retrieval accuracy due to its sensitivity to input text.
- Mechanism: FROMAGe uses an autoregressive LLM which is trained on free-form text, making it more sensitive to complex language descriptions compared to bidirectional models like CLIP. This allows FROMAGe to better understand and retrieve images based on nuanced text descriptions.
- Core assumption: Autoregressive models trained on free-form text are more sensitive to input text than bidirectional models.
- Evidence anchors:
  - [section 4.1] "FROMAGe is more accurate on long and complex free-form text compared to existing models."
  - [section 5.2] "FROMAGe significantly outperforms CLIP in all settings, and significantly outperforms CLIP when the full set of dialogue is provided."
- Break condition: If the autoregressive nature of FROMAGe's LLM does not contribute to its superior performance on text-based retrieval tasks.

## Architecture Onboarding

- Component map: Frozen LLM (OPT-6.7B) -> Frozen visual encoder (CLIP ViT-L/14) -> Linear mapping layers (Wc, Wt, Wi) -> [RET] token -> Byte-level BPE tokenizer

- Critical path:
  1. Input image and text are processed by the visual encoder and tokenizer, respectively.
  2. Visual embeddings are mapped to text space using Wc.
  3. [RET] token is added to the tokenized text.
  4. LLM processes the interleaved image-text input and generates output.
  5. Output embeddings are mapped to visual space using Wt for image retrieval.

- Design tradeoffs:
  - Freezing the LLM preserves its in-context learning abilities but limits fine-tuning options.
  - Using a frozen visual encoder reduces computational cost but may not be optimal for the specific task.
  - Training on image-text pairs alone enables zero-shot performance but may limit generalization to other datasets.

- Failure signatures:
  - Poor performance on tasks requiring fine-tuning of the LLM parameters.
  - Inability to generate novel images (only retrieves from a fixed set).
  - Sensitivity to biases in the training and retrieval datasets.

- First 3 experiments:
  1. Train FROMAGe on a small subset of the Conceptual Captions dataset and evaluate its performance on a held-out test set.
  2. Ablate the [RET] token and compare performance on image-text retrieval tasks.
  3. Compare FROMAGe's performance to CLIP on the Visual Storytelling dataset with varying amounts of context.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does FROMAGe's performance scale with larger image-text datasets beyond Conceptual Captions (CC3M)?
- Basis in paper: [explicit] The paper states "Scaling FROMAGe with larger and more capable language models, training on larger image-text datasets" as a promising direction for future work.
- Why unresolved: The paper only trains and evaluates FROMAGe on CC3M (3.1M image-text pairs). It does not explore training on larger datasets like LAION-400M (400M image-text pairs) or web-scale datasets used by Flamingo (1.8B image-text pairs).
- What evidence would resolve it: Training FROMAGe on larger image-text datasets and evaluating its performance on downstream tasks like VIST and VisDial to see if performance improves.

### Open Question 2
- Question: Can FROMAGe be extended to generate novel images from scratch, rather than retrieving from a fixed set of images?
- Basis in paper: [explicit] The paper mentions "extending our approach for generation of novel images from scratch are promising directions for future work."
- Why unresolved: FROMAGe currently retrieves images from a fixed set of images from CC3M. It does not have the ability to generate novel images based on the text input.
- What evidence would resolve it: Modifying FROMAGe to incorporate a generative model for images (like DALL-E or Imagen) and evaluating its ability to generate novel images based on text prompts.

### Open Question 3
- Question: How does FROMAGe's performance compare to models that are trained end-to-end on multimodal data (like Flamingo or CM3)?
- Basis in paper: [explicit] The paper compares FROMAGe to CLIP, ESPER, and CM3 on specific tasks, but does not directly compare it to Flamingo or CM3 on their full range of capabilities.
- Why unresolved: FROMAGe is designed to leverage frozen language models, while Flamingo and CM3 are trained end-to-end on multimodal data. It is unclear how FROMAGe's performance would compare to these models on a broader range of tasks.
- What evidence would resolve it: Conducting a comprehensive comparison of FROMAGe, Flamingo, and CM3 on a wide range of multimodal tasks, including image-text retrieval, image generation, and multimodal dialogue.

## Limitations

- Model is constrained to retrieve from a fixed set of images rather than generating novel ones, limiting practical applicability
- Performance heavily depends on quality and diversity of retrieval dataset with no systematic evaluation of this dependency
- Limited evidence that in-context learning capabilities transfer to truly novel tasks versus similar training objective tasks

## Confidence

- **High Confidence**: The core architectural approach of using frozen LLMs with trainable linear layers for multimodal grounding is technically sound and well-implemented
- **Medium Confidence**: The reported performance improvements over baselines like CLIP are credible but evaluation scenarios are somewhat narrow
- **Medium Confidence**: The claim about preserving in-context learning abilities is supported by qualitative examples but lacks comprehensive quantitative validation

## Next Checks

1. **Cross-dataset generalization test**: Evaluate FROMAGe's performance on retrieval tasks using completely disjoint datasets from the training data (e.g., training on CC3M but testing on Flickr30k or OpenImages). This would validate whether the model truly learns generalizable multimodal representations or simply memorizes training distribution patterns.

2. **In-context learning stress test**: Design a systematic evaluation protocol that tests the model's ability to adapt to novel multimodal tasks with varying numbers of examples (1-shot, 5-shot, 10-shot). Include tasks that require reasoning about relationships between images and text that were not present in the training data to verify genuine in-context learning versus pattern matching.

3. **Retrieval quality analysis**: Conduct a detailed ablation study examining how retrieval performance varies with different types of queries: short vs. long descriptions, concrete vs. abstract concepts, and diverse vs. homogeneous image sets. This would help identify the model's strengths and limitations in handling different query characteristics and inform practical deployment considerations.
