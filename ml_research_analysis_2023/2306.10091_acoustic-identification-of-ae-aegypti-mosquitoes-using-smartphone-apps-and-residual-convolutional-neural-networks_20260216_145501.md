# Acoustic Identification of Ae. aegypti Mosquitoes using Smartphone Apps and Residual Convolutional Neural Networks

## Quick Facts
- arXiv ID: 2306.10091
- Source URL: https://arxiv.org/abs/2306.10091
- Reference count: 26
- Key outcome: Residual CNN achieves 98% accuracy on Ae. aegypti detection with 18.5% smaller model size than prior work

## Executive Summary
This paper presents a residual convolutional neural network architecture for classifying Ae. aegypti mosquitoes from wingbeat sounds recorded on smartphones. The authors address challenges of background noise and computational constraints on mobile devices by developing a lightweight residual CNN with dropout layers for noise resilience and efficient inference. They introduce a new dataset of mosquito audio recordings and a training methodology that incorporates environmental noise samples to improve robustness. Evaluation on multiple datasets shows the proposed network achieves up to 98% accuracy, outperforming prior work while being 18.5% smaller in parameter count. A proof-of-concept Android app demonstrates real-time classification on low-cost smartphones, validating the approach's practicality for large-scale mosquito monitoring.

## Method Summary
The method uses spectrograms generated from 8kHz audio recordings as input to a residual CNN architecture. The network consists of multiple residual blocks, each containing two convolutional layers with batch normalization and skip connections, followed by max pooling and dropout layers. The classification block uses dense layers to produce binary output (Ae. aegypti present/absent). Training incorporates ESC-50 environmental noise samples for robustness, with balanced sampling across classes. The model is optimized for mobile deployment using TensorFlow Lite with dynamic quantization and runs on low-cost smartphones in under 320ms.

## Key Results
- Achieves up to 98% accuracy on multiple datasets including lab recordings and semi-controlled environments
- Outperforms prior methods while maintaining 18.5% smaller model size (under 1 million parameters)
- Demonstrates real-time inference capability on entry-level smartphones (Motorola Moto E6 Play)
- Shows improved noise robustness through incorporation of environmental sound samples during training

## Architecture Onboarding

- Component map: Spectrogram (2D matrix, [0,1]) -> Residual blocks (conv layers + skip connections) -> MaxPooling2D -> Dropout (20%) -> Flatten -> Dense(256) -> Dense(2) -> Probability vector [no mosquito, mosquito present]

- Critical path: Spectrogram generation -> Residual blocks (feature extraction) -> Classification block (decision) -> Output

- Design tradeoffs:
  - Depth vs. efficiency: More residual blocks increase accuracy but require more computation
  - Filter size: (5,5) kernels balance spatial coverage with parameter count
  - Dropout rate: 20% prevents overfitting without underfitting
  - Input size: 60-frame segments balance temporal context with real-time constraints

- Failure signatures:
  - High training accuracy but low validation accuracy -> overfitting (increase dropout or augment data)
  - Both training and validation accuracy plateau at low values -> underfitting (add residual blocks or increase filters)
  - Inconsistent predictions on same input -> numerical instability (check normalization and data types)

  2. Add dropout layer and compare training vs. validation curves to confirm regularization effect
  3. Vary filter size (3x3 vs 5x5 vs 7x7) and measure impact on accuracy and inference time
