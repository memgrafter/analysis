# Minigrid & Miniworld: Modular & Customizable Reinforcement Learning Environments for Goal-Oriented Tasks

## Quick Facts
- arXiv ID: 2306.13831
- Source URL: https://arxiv.org/abs/2306.13831
- Reference count: 37
- Over 2400 GitHub stars and 470 citations

## Executive Summary
Minigrid and Miniworld are modular and customizable reinforcement learning environment libraries that provide a unified API for creating goal-oriented tasks in 2D gridworld and 3D environments. The libraries prioritize simplicity and customizability through Python implementations with minimal dependencies, enabling rapid environment creation and transfer learning studies between different observation spaces. The unified API has demonstrated successful policy transfer between Minigrid and Miniworld environments, while human transfer learning experiments showed comparable performance across observation spaces. These libraries have gained significant adoption in the RL research community, supporting studies in safe RL, exploration, and meta-learning.

## Method Summary
The Minigrid and Miniworld libraries provide modular environment creation through _gen_grid() and _gen_world() functions that allow users to construct new environments by placing agents, objects, and walls in grid layouts. The unified API maintains consistent action spaces and reward structures across 2D and 3D environments, enabling direct policy transfer between them. The implementation uses NumPy for Minigrid and Pyglet for Miniworld graphics, with environments designed as partially observable MDPs. The libraries integrate with OpenAI Gym API standards and support popular RL frameworks like Stable-Baselines3. Transfer learning experiments tested 12 different weight transfer configurations, while human experiments involved 8 participants playing matching Minigrid and Miniworld environments with random key mappings.

## Key Results
- Successful policy transfer from Minigrid to Miniworld environments with improved performance when transferring critic network and mission embedding weights only
- Human transfer learning experiments showed equivalent performance between Minigrid and Miniworld observation spaces
- Over 2400 GitHub stars and 470 citations demonstrate widespread community adoption
- Unified API enables rapid creation of new goal-oriented environments with minimal code modifications

## Why This Works (Mechanism)

### Mechanism 1
The unified API enables transfer learning between different observation spaces by maintaining consistent action spaces and reward structures across Minigrid and Miniworld. This allows policies trained in one environment to be directly transferred to the other with minimal modifications, as demonstrated by successful transfer of PPO agent weights from Minigrid to Miniworld environments.

### Mechanism 2
Modular design allows rapid creation of new environments for research-specific needs through the _gen_grid()/_gen_world() functions that provide a minimal yet flexible API for constructing new environments. Users can modify existing environments or create entirely new ones by changing object placement, room configurations, or goal conditions with relatively few lines of code.

### Mechanism 3
Minimal dependencies and Python implementation enable easy installation and customization by avoiding the complexity of external physics engines or game frameworks. This makes installation straightforward and allows users to understand and modify the entire codebase without dealing with C++ or complex build systems.

## Architecture Onboarding

- Component map:
  Environment core (Grid/GridWorld backend) -> API layer (Gym-style interface) -> Generation system (_gen_grid()/_gen_world() functions) -> Extension system (Wrapper classes) -> Integration layer (Compatibility with RL libraries)

- Critical path:
  1. Environment creation: _gen_grid() or _gen_world() defines the layout
  2. Agent placement: place_agent() positions the agent randomly
  3. Object placement: put_obj() or place_entity() adds interactable objects
  4. Observation generation: render() creates the agent's view
  5. Action execution: step() processes actions and returns new observations

- Design tradeoffs:
  - Simplicity vs. Expressiveness: Minimal API makes learning easy but may limit complex environment types
  - Python vs. Performance: Python implementation is accessible but slower than C++ alternatives
  - 2D vs. 3D: Minigrid offers faster execution, Miniworld provides more realistic visual observations

- Failure signatures:
  - Environments run slowly: Too many objects or complex rendering in Miniworld
  - Agent gets stuck: Incorrect object placement or missing goal configurations
  - Transfer learning fails: Too different observation spaces or MDP structures between source and target environments

- First 3 experiments:
  1. Run a pre-built environment: Test the "MiniGrid-BlockedUnlockPickup-v0" environment to verify installation and basic functionality
  2. Create a simple custom environment: Modify the _gen_grid() function to create a new maze layout with different wall configurations
  3. Test policy transfer: Train a PPO agent on a simple Minigrid environment, then transfer the learned weights to a Miniworld environment with similar structure

## Limitations

- The transfer learning case study uses a limited set of environments and weight transfer configurations, making it difficult to generalize the effectiveness of the unified API approach
- The human transfer learning experiment has a small sample size (n=8) and lacks detailed analysis of learning curves or individual differences
- The libraries' simplicity inherently limits their ability to represent more complex environments requiring advanced physics or continuous control

## Confidence

- High confidence: Modular design enabling rapid environment creation, widespread adoption metrics (2400+ GitHub stars, 470+ citations)
- Medium confidence: Unified API enabling transfer learning between observation spaces, minimal dependency approach for accessibility
- Low confidence: Human transfer learning experiment results generalizability, comprehensive evaluation of all possible weight transfer configurations
