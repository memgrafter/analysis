# Domain Generalization for Domain-Linked Classes

## Quick Facts
- arXiv ID: 2306.00879
- Source URL: https://arxiv.org/abs/2306.00879
- Reference count: 14
- Key outcome: FOND achieves +2.9%, +20.3%, and +1.1% improvements on PACS, VLCS, and OfficeHome datasets respectively for domain-linked classes

## Executive Summary
This paper addresses the challenge of domain generalization (DG) when certain classes only appear in specific source domains, leading to poor generalization for those classes. The authors introduce FOND (Fair and cONtrastive feature-space regularization algorithm for Domain-linked DG), which transfers domain-invariant knowledge from domain-shared classes to domain-linked classes through fairness constraints and contrastive learning. FOND achieves state-of-the-art performance on three standard DG benchmark datasets while providing insights into data conditions that improve domain-linked class generalizability.

## Method Summary
FOND addresses domain generalization for domain-linked classes by learning fair representations that yield similar outcomes for both domain-linked and domain-shared classes. The method combines three components: a classification task objective, a fairness objective that minimizes the difference in classification losses between domain-linked and domain-shared classes, and a contrastive learning objective that maximizes similarity between positive inter-domain pairs while minimizing similarity between negative intra-domain pairs. The model uses a ResNet-18 backbone with feature extraction, projection, and classification networks. Training involves minimizing a weighted combination of these objectives to learn domain-invariant representations that transfer knowledge from domain-shared to domain-linked classes.

## Key Results
- FOND achieves +2.9% improvement on PACS dataset for domain-linked classes
- FOND achieves +20.3% improvement on VLCS dataset for domain-linked classes
- FOND achieves +1.1% improvement on OfficeHome dataset for domain-linked classes
- FOND consistently outperforms baselines when sufficient domain-shared classes are available
- Performance degrades significantly when domain-shared class data is limited

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Minimizing the absolute difference in classification losses between domain-linked and domain-shared classes encourages the model to learn domain-invariant features that generalize to both class types.
- Mechanism: The fairness objective `Lf air = |LL_task - LS_task|` penalizes the model when it performs significantly better on one class type over the other. This forces the learned representations to capture domain-invariant patterns that benefit both domain-linked (YL) and domain-shared (YS) classes equally.
- Core assumption: The performance gap between YL and YS classes stems primarily from a lack of domain-invariant features rather than inherent differences in class difficulty.
- Evidence anchors:
  - [abstract]: "We accomplish this by learning fair representations, which we define as representations that yield similar outcomes for domain-linked and domain-shared classes."
  - [section]: "We therefore impose a fairness constraint on the prediction error rate such that the domain-invariant representations learned would result in similar generalizability between YS and YL classes."

### Mechanism 2
- Claim: Maximizing cosine similarity between positive (same-class) inter-domain pairs while increasing the weight of negative (different-class) intra-domain comparisons effectively learns domain-invariant representations.
- Mechanism: The contrastive objective `Lxdom` uses weighted cosine similarity where `α` increases the weight of inter-domain positive pairs and `β` increases the weight of intra-domain negative pairs. This focuses the model on learning features that distinguish classes within domains while being invariant across domains.
- Core assumption: Inter-domain positive pairs provide stronger signals for domain invariance than intra-domain positive pairs, and intra-domain negative pairs are more informative than inter-domain negative pairs for learning class distinctions.
- Evidence anchors:
  - [abstract]: "combined with a contrastive learning objective that maximizes the similarity between positive inter-domain pairs and minimizes the similarity between negative intra-domain pairs."
  - [section]: "we hypothesize that specifically maximizing the mutual information between positive (same-class) inter-domain samples guides domain-invariant learning... we hypothesize that negative (different-class) intra-domain comparisons are more informative than negative inter-domain comparisons for reducing spurious domain and class correlations."

### Mechanism 3
- Claim: The performance of domain-linked classes improves when there is a sufficient number of domain-shared classes to learn from.
- Mechanism: Domain-shared classes provide the training signal for learning domain-invariant features through the contrastive and fairness objectives. With more domain-shared classes, the model has more opportunities to learn generalizable patterns that transfer to domain-linked classes.
- Core assumption: Domain-shared classes contain sufficient information to learn features that are applicable to domain-linked classes.
- Evidence anchors:
  - [abstract]: "We also provide practical insights on data conditions that increase domain-linked class generalizability to tackle real-world data scarcity."
  - [section]: "Our key observation: FOND consistently outperforms baselines given a sufficient number for domain-shared classes to learn from."

## Architecture Onboarding

- Component map: Input → Feature Extraction Network (F) → Projection Network (P) → Contrastive Learning → Classification Network (G) → Fairness Regularization → Output

- Critical path: Input → Feature Extraction → Projection → Contrastive Learning → Classification → Fairness Regularization → Output

- Design tradeoffs:
  - The fairness objective may limit the model's ability to optimize for maximum accuracy if domain-linked classes are inherently more difficult
  - The contrastive objective with weighted pairs requires careful tuning of α and β parameters
  - Using a ResNet-18 backbone provides a good balance between model capacity and computational efficiency

- Failure signatures:
  - If YL performance is significantly lower than YS performance, the fairness objective may not be effective
  - If the model performs well on source domains but poorly on target domains, the contrastive objective may not be learning domain-invariant features
  - If the model's performance degrades significantly with fewer domain-shared classes, the transfer mechanism may be insufficient

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the number of domain-shared classes impact the generalizability of domain-linked classes in domain generalization?
- Basis in paper: [explicit] The authors state that "Increasing the total number of domain-shared classes observed improves domain-linked generalization" and analyze this relationship in their experiments.
- Why unresolved: While the authors demonstrate this relationship empirically, the underlying reasons for why more domain-shared classes lead to better domain-linked generalization are not fully explained. The mechanisms by which domain-invariant knowledge is transferred from shared to linked classes are not fully understood.
- What evidence would resolve it: Further theoretical analysis and experiments to understand the relationship between the number of domain-shared classes and the quality of domain-invariant representations learned for domain-linked classes.

### Open Question 2
- Question: What is the optimal balance between fairness regularization and contrastive learning in FOND for different datasets and domain variation types?
- Basis in paper: [inferred] The authors propose a combination of fairness and contrastive learning objectives in FOND, but the optimal balance between these components may vary depending on the dataset characteristics and domain variations.
- Why unresolved: The paper does not provide a detailed analysis of how the balance between fairness and contrastive learning affects performance across different datasets and domain variation types. The authors only compare different variants of FOND with varying levels of fairness and contrastive learning components.
- What evidence would resolve it: A comprehensive study varying the weights of fairness and contrastive learning components in FOND across multiple datasets and domain variation types to determine the optimal balance for each scenario.

### Open Question 3
- Question: How does FOND perform in scenarios with limited domain-shared data or highly domain-specific classes?
- Basis in paper: [explicit] The authors acknowledge that "One of the key limitations is that our method does not perform well when observing very few domain-shared YL classes is a general lack of domain-shared data, e.g., during the Low share-class distribution setting."
- Why unresolved: While the authors identify this limitation, they do not provide a detailed analysis of FOND's performance in such scenarios or propose potential solutions to address this issue.
- What evidence would resolve it: Experiments evaluating FOND's performance on datasets with limited domain-shared data or highly domain-specific classes, along with proposed modifications to the algorithm to improve its robustness in such scenarios.

## Limitations

- The method's performance significantly degrades when domain-shared class data is limited, as identified by the authors
- The contrastive learning strategy requires careful parameter tuning (α, β) without clear guidance on optimal values
- The approach assumes domain-linked classes can benefit from domain-invariant knowledge transfer, but doesn't fully explore cases where this transfer might fail

## Confidence

- High confidence in experimental results showing performance improvements on benchmark datasets
- Medium confidence in theoretical justification for fairness and contrastive objectives
- Low confidence in generalizability to datasets with significantly different characteristics
