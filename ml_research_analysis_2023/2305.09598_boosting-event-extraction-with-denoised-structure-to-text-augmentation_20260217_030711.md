# Boosting Event Extraction with Denoised Structure-to-Text Augmentation

## Quick Facts
- **arXiv ID**: 2305.09598
- **Source URL**: https://arxiv.org/abs/2305.09598
- **Reference count**: 35
- **Primary result**: Achieves SOTA F1 score of 76.9% on ACE05-E+ using denoised structure-to-text augmentation

## Executive Summary
This paper addresses low-resource event extraction by introducing a denoised structure-to-text augmentation framework (DAEE) that combines knowledge-based generation with reinforcement learning. The approach uses a T5-based model enhanced with argument-aware loss to generate augmented training data from structured event records, then iteratively filters and refines this data using a policy-based RL agent that selects samples based on their impact on event extraction performance. Experimental results demonstrate state-of-the-art performance on ACE05-E+ and competitive results on ERE-EN datasets, with improvements of 1.1% and 0.7% in F1 scores for trigger and argument classification respectively.

## Method Summary
DAEE consists of three iteratively trained models: a generation model that transforms structured event records into natural language text using T5 with argument-aware loss, a policy model that filters generated samples based on their impact on event extraction performance using BERT-based binary classification, and an event extraction model (GTEE-BASE) that learns from the filtered augmented data. The generation model uses an input format [Pg;Dg;Rg;C′] where Pg is the event description, Dg is masked background context, Rg is the event record, and C′ is the template. The RL agent receives state vectors encoding generated text and event descriptions, selecting retain/remove actions based on F1 score improvements from adding samples to training. The framework iteratively retrains all components, using the F1 improvement as reward for the policy model and mixing selected samples with original training data.

## Key Results
- Achieves SOTA F1 score of 76.9% on ACE05-E+ dataset
- Improves trigger classification (Trg-C) by 1.1% and argument classification (Arg-C) by 0.7% over baseline
- Outperforms existing methods on ERE-EN dataset with competitive performance
- Generates more diverse and grammatically correct training samples compared to baselines

## Why This Works (Mechanism)

### Mechanism 1
The policy-based RL agent filters generated samples based on their impact on event extraction performance, reducing semantic drift and structure misalignment. The RL agent receives a state vector encoding both the generated sentence and corresponding event description, then selects actions (retain/remove) based on the F1 score improvement from adding that sample to training. The reward is the difference in argument F1 between epochs.

### Mechanism 2
The argument-aware loss in the generation model ensures generated sentences contain complete event triggers and arguments, addressing structure misalignment. The loss function computes similarity between generated tokens and unmatched event arguments using sliding window distance scoring, then adds this as a weighted component to the overall loss during training.

### Mechanism 3
Iterative retraining of all three components (generation, policy, extraction models) creates a feedback loop that progressively improves sample quality and event extraction performance. After the policy model filters generated data, the event extraction model is retrained on the filtered set. The F1 improvement becomes the reward for retraining the policy model, which then weights the generation model's training data. This cycle repeats.

## Architecture Onboarding

- **Component map**: Event records → Generation Model → Generated Text → Policy Model → Filtered Text → Event Extraction Model → F1 Score → Policy Update → Generation Model Update
- **Critical path**: Event records flow through generation model to create synthetic text, which is filtered by policy model based on F1 improvement, then used to retrain event extraction model, with F1 scores providing feedback for policy and generation model updates
- **Design tradeoffs**: The three-model architecture provides specialized capabilities but increases complexity and training time; using F1 improvement as reward provides task-relevant feedback but may be noisy; argument-aware loss improves structure alignment but adds computational overhead
- **Failure signatures**: Policy model becomes overly conservative (removes too many samples) → Check reward scaling and action probability thresholds; Generated text quality degrades over iterations → Check PLLs trends and generation model weighting; Event extraction performance plateaus → Check if RL agent is stuck in local optima or if generated data distribution shifted too far
- **First 3 experiments**: 1) Run ablation study removing argument-aware loss to quantify its impact on structure alignment; 2) Compare PLLs trends with and without RL filtering to measure text quality improvement; 3) Test policy model precision at different confidence thresholds to find optimal filtering sensitivity

## Open Questions the Paper Calls Out

### Open Question 1
What is the optimal trade-off between generation diversity and semantic alignment in the structure-to-text generation model? The paper discusses balancing diversity through argument-aware loss (La) versus generation quality, noting that "diverse text can enable the model to obtain more information based on similar event records" but also mentions the generation model may "leak" information or produce misaligned triggers/arguments.

### Open Question 2
How does the performance of DAEE vary with different levels of original training data availability? The paper focuses on "low-resource event extraction" but only evaluates on datasets with moderate training sizes (ACE05-E+ has 17k training sentences, ERE-EN has 14k).

### Open Question 3
What is the impact of pronoun-heavy event records on DAEE's generation quality? The paper notes that "ERE-EN contains more pronoun arguments" and observes that "pronoun roles would offer less information for the generation model thus reducing the role of structured text in guiding the generation model."

### Open Question 4
How does the RL agent's selection policy generalize to completely unseen event types? The RL agent learns to select samples based on their impact on F1 scores, but the paper doesn't evaluate whether this policy transfers to new event types not present in the training data.

## Limitations
- Effectiveness of RL filtering depends on stability and reliability of F1 score improvements as reward signal
- Argument-aware loss mechanism implementation details are underspecified
- Iterative retraining introduces risk of model collapse or overfitting to generated data distribution
- Lacks ablation experiments showing individual contributions of each component

## Confidence

- **RL agent effectively filters semantic drift and structure misalignment**: Medium confidence
- **Argument-aware loss ensures complete trigger and argument inclusion**: Medium confidence
- **Iterative retraining creates progressive improvement**: Low confidence
