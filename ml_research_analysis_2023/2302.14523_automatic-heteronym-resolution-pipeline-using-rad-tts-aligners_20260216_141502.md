# Automatic Heteronym Resolution Pipeline Using RAD-TTS Aligners

## Quick Facts
- arXiv ID: 2302.14523
- Source URL: https://arxiv.org/abs/2302.14523
- Reference count: 0
- Primary result: Proposed pipeline achieves 99.07% accuracy on WikiHomograph and 91.04% on hard evaluation set using 0.01% confidence threshold

## Executive Summary
This paper presents an automatic heteronym resolution pipeline that leverages RAD-TTS aligners to disambiguate heteronyms in grapheme-to-phoneme (G2P) systems. The method generates multiple candidate pronunciations for each heteronym, scores them using an Aligner model based on L2 distance between phoneme and audio embeddings, and selects the best pronunciation. The automatically labeled speech data can be used to create training datasets for both multi-stage and end-to-end G2P systems. Experimental results show significant improvements in heteronym disambiguation accuracy compared to baseline approaches.

## Method Summary
The pipeline operates by first replacing known unambiguous words with their phoneme forms from a dictionary, then generating all possible phonemic forms for each heteronym. Each candidate pronunciation is scored using a RAD-TTS Aligner that learns alignments between text tokens and audio frame encodings through L2 distance minimization. The best pronunciation is selected based on the minimum average L2 distance, and a confidence threshold is applied to filter low-quality disambiguations. OOV words are masked with a special token for training. The resulting labeled sentences are used to train both BERT-based classification models and E2E ByT5 G2P models, with non-balanced data augmentation yielding the best performance.

## Key Results
- Achieves 99.07% accuracy on WikiHomograph dataset with 0.01% confidence threshold
- Improves heteronym disambiguation accuracy for both BERT-based classification and E2E ByT5 G2P models
- Best performance achieved with non-balanced data augmentation rather than balanced approach
- Confidence thresholding effectively removes low-quality disambiguations while maintaining sufficient training data

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Aligner-based scoring selects correct heteronym pronunciations by minimizing L2 distance between phoneme and audio embeddings.
- Mechanism: The RAD-TTS Aligner generates soft alignments between phoneme encodings and audio frames; the pronunciation with the smallest average L2 distance across aligned frames is selected.
- Core assumption: The correct pronunciation produces phoneme encodings that are closer to the corresponding audio embeddings than incorrect pronunciations.
- Evidence anchors: Abstract states the best pronunciation is chosen by scoring candidates with an Aligner model; section describes Aligner learning alignments using L2 distance between representations.
- Break condition: Poor audio quality, speaker mispronunciation, or very similar heteronym forms may prevent reliable L2 distance distinction.

### Mechanism 2
- Claim: Confidence thresholding removes low-quality disambiguations, improving downstream model accuracy.
- Mechanism: For each heteronym, the confidence score is computed as the normalized difference between the best and worst candidate L2 distances; samples below a threshold are discarded.
- Core assumption: The difference in L2 distances between correct and incorrect pronunciations correlates with the likelihood of correct disambiguation.
- Evidence anchors: Abstract mentions best performance achieved with 0.01% confidence threshold; section proposes thresholding based on normalized difference between best and worst candidate L2 distances.
- Break condition: Threshold set too high results in insufficient training samples; too low allows noisy samples to degrade performance.

### Mechanism 3
- Claim: Automatic heteronym labeling enables scalable data augmentation for both multi-stage and end-to-end G2P models.
- Mechanism: The pipeline generates candidate pronunciations for each heteronym, uses the Aligner to score and select the best, and replaces OOV words with a masking token; this produces labeled sentences for model training without manual annotation.
- Core assumption: Automatically labeled sentences are sufficiently accurate to train robust G2P models, and masking OOV words forces the model to generate phoneme predictions for unseen words.
- Evidence anchors: Abstract states the method enables automatic labeling of speech data for use in both multi-stage and end-to-end G2P systems; section describes converting sentences to phonemes for G2P training after heteronym disambiguation.
- Break condition: Too many errors in automatically generated labels degrade model performance; improper masking token handling affects OOV word prediction.

## Architecture Onboarding

- Component map: Raw audio + transcript text -> RAD-TTS Aligner -> Dictionary lookup -> Heteronym candidate generation -> Aligner scoring -> Confidence thresholding -> OOV masking -> Labeled sentences for G2P training

- Critical path:
  1. Replace known unambiguous words with phoneme forms from dictionary
  2. For each heteronym, generate all possible phonemic forms
  3. Pass each candidate + audio through Aligner
  4. Select candidate with minimum average L2 distance
  5. Apply confidence threshold; mask OOV words with ⟨unk⟩
  6. Use labeled sentences to train G2P models

- Design tradeoffs:
  - Higher confidence thresholds → higher quality but fewer training samples
  - Balanced vs. non-balanced augmentation → trade-off between model bias and performance on hard evaluation sets
  - Masking OOV words vs. dropping sentences → trade-off between training data size and model robustness

- Failure signatures:
  - Low confidence scores across all candidates → possible audio noise or ambiguous pronunciation
  - High false positive rate on heteronyms with similar-sounding forms → Aligner may struggle with near-homophones
  - Poor downstream model performance despite high-quality Aligner output → possible issues with masking or training data composition

- First 3 experiments:
  1. Run the pipeline on a small, manually verified dataset; check Aligner accuracy and confidence score distribution.
  2. Train a simple BERT-based classifier on the automatically labeled data; evaluate on a held-out test set with known heteronym labels.
  3. Vary the confidence threshold and measure impact on downstream G2P model accuracy and training set size.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal confidence threshold value for balancing data quality and quantity in the automatic heteronym disambiguation pipeline?
- Basis in paper: [explicit] The paper discusses using confidence thresholds (0.00%, 0.01%, 0.02%, 0.03%) to control the quality of disambiguated data, with results showing varying accuracy depending on the threshold value.
- Why unresolved: The paper shows that different threshold values affect both the accuracy and the number of samples generated, but it doesn't definitively state which threshold provides the best overall balance for all use cases.
- What evidence would resolve it: Comprehensive experiments comparing the performance of downstream models (G2P systems) across various confidence thresholds, including analysis of the trade-off between data quantity and quality.

### Open Question 2
- Question: How well does the automatic heteronym disambiguation pipeline generalize to other languages beyond English?
- Basis in paper: [inferred] The paper focuses on English heteronyms and mentions Japanese heteronyms only in passing when discussing related work, suggesting potential for extension to other languages.
- Why unresolved: The paper doesn't test or discuss the pipeline's performance on heteronyms in languages other than English, despite the general applicability of the approach.
- What evidence would resolve it: Implementation and evaluation of the pipeline on datasets containing heteronyms from multiple languages, comparing performance across different linguistic structures and phonetic systems.

### Open Question 3
- Question: Can the automatic heteronym disambiguation pipeline be improved to handle heteronyms with similar pronunciations more effectively?
- Basis in paper: [explicit] The paper notes that the Aligner model performs poorly on heteronyms with similar pronunciations (e.g., "subject" with /s@b"dZEkt/ and /"s@bdZIkt/) but suggests this can be mitigated by confidence thresholding.
- Why unresolved: While confidence thresholding is proposed as a solution, it's not clear if this is the optimal approach or if there are better methods to improve disambiguation for heteronyms with similar pronunciations.
- What evidence would resolve it: Experiments testing alternative approaches (e.g., incorporating additional linguistic features, using different alignment models) and comparing their effectiveness against confidence thresholding for heteronyms with similar pronunciations.

## Limitations
- The approach may struggle with heteronyms that have phonetically similar pronunciations or when audio quality is poor
- The optimal confidence threshold value (0.01%) may be dataset-specific and not generalizable across all heteronym resolution tasks
- The pipeline's effectiveness depends on the availability of high-quality transcribed audio data for Aligner training, which may not be accessible for all languages or domains

## Confidence
- **High Confidence**: The mechanism of using L2 distance between phoneme and audio embeddings for pronunciation selection is well-established in the RAD-TTS literature and directly supported by the paper's experimental results showing 99.07% accuracy on WikiHomograph.
- **Medium Confidence**: The confidence thresholding approach for filtering low-quality disambiguations is theoretically sound, but the optimal threshold value (0.01%) may be dataset-specific and not generalizable across all heteronym resolution tasks.
- **Medium Confidence**: The claim that automatically labeled data enables scalable training for both multi-stage and end-to-end G2P models is supported by experiments, but the long-term impact on model generalization and robustness requires further validation.

## Next Checks
1. **Threshold Sensitivity Analysis**: Systematically vary the confidence threshold from 0.001% to 1.0% and measure the trade-off between downstream G2P model accuracy and training set size. This will reveal whether 0.01% is truly optimal or merely sufficient for the tested datasets.

2. **Cross-Speaker Generalization Test**: Apply the trained Aligner models to audio from speakers not present in the training data (e.g., from different accent regions or recording conditions) to assess whether the L2 distance metric remains reliable across speaker variations.

3. **Hard Case Benchmark**: Create a benchmark dataset containing only heteronyms with phonetically similar pronunciations or minimal contextual cues, then evaluate whether the Aligner can maintain high accuracy or if alternative disambiguation strategies are needed for these challenging cases.
