# Complement Sparsification: Low-Overhead Model Pruning for Federated Learning

## Quick Facts
- arXiv ID: 2303.06237
- Source URL: https://arxiv.org/abs/2303.06237
- Reference count: 4
- Achieves up to 93.2% communication reduction and 49.3% computation reduction while maintaining comparable model accuracy

## Executive Summary
This paper introduces Complement Sparsification (CS), a model pruning method specifically designed for Federated Learning that reduces both communication and computation overhead while maintaining model accuracy. The method works by having the server and clients collaboratively generate and exchange sparse models that complement each other. In each training round, the server prunes the aggregated dense model and sends the global sparse model to clients, who then train on this sparse model, remove weights that were non-zero in the global sparse model, and send their locally sparse models back to the server for aggregation.

The CS method achieves significant reductions in communication (up to 93.2%) and computation (up to 49.3%) compared to vanilla FL, while maintaining comparable model accuracy on two benchmark datasets: Twitter sentiment analysis and FEMNIST image classification. The approach is particularly practical for resource-constrained devices and outperforms baseline pruning methods like PQSU and PruneFL in the federated learning context.

## Method Summary
Complement Sparsification is an iterative pruning method where the server maintains a global sparse model that is pruned based on weight magnitudes. In each round, the server prunes the aggregated dense model and broadcasts the sparse model to participating clients. Clients train on this sparse model and then create a complement-sparsified version by removing weights that were non-zero in the global sparse model. These locally sparse models are sent back to the server, which aggregates them with the global sparse model using an aggregation ratio to produce a new dense model. This dense model then undergoes another round of pruning to create the next global sparse model, continuing the cycle.

## Key Results
- Achieves up to 93.2% reduction in communication overhead compared to vanilla FL
- Reduces computation by up to 49.3% (FLOPs) while maintaining model accuracy
- Outperforms baseline methods (PQSU, PruneFL) on both Twitter sentiment analysis and FEMNIST image classification tasks
- Maintains comparable accuracy to vanilla FL across different server model sparsity levels (50-80%)

## Why This Works (Mechanism)
The method works by exploiting the complementary nature of sparse models between the server and clients. By having clients focus on training weights that were removed from the global model, the approach ensures that important features are preserved across the federated network. The iterative aggregation and pruning process allows the model to maintain accuracy while gradually reducing the number of parameters that need to be communicated and computed.

## Architecture Onboarding

**Component Map:** Server -> Pruning -> Broadcast -> Clients -> Training -> Complement Sparsification -> Upload -> Server -> Aggregation -> Dense Model -> Pruning -> Server

**Critical Path:** Server pruning → Client training → Client complement sparsification → Server aggregation → Server pruning

**Design Tradeoffs:** 
- Higher sparsity reduces communication but may degrade accuracy
- More clients per round improves accuracy but increases communication
- Aggregation ratio controls contribution balance between global and local models

**Failure Signatures:**
- Accuracy degradation indicates excessive pruning or poor aggregation ratio
- Slow convergence suggests insufficient client participation or aggressive sparsity
- Communication bottleneck despite pruning indicates server model too dense
