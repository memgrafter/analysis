# How to Do Things with Deep Learning Code

## Quick Facts
- arXiv ID: 2304.09406
- Source URL: https://arxiv.org/abs/2304.09406
- Authors: 
- Reference count: 40

## Executive Summary
This paper explores how Critical Code Studies (CCS) can be applied to deep learning systems by examining OpenAI's GPT-2 model code. The authors propose a taxonomy that separates deep learning code into core deep learning code (CDLC) that defines the model and ancillary deep learning code (ADLC) that underwrites applications built around the model. Through case studies of AI Dungeon and This Word Does Not Exist, the paper demonstrates how ADLC can be used to structure model output and construct interfaces that mediate between users and language models. The analysis shows that ADLC provides a more accessible entry point for CCS analysis than CDLC, enabling researchers to examine the cultural and political dimensions of AI systems through the code that shapes user interaction.

## Method Summary
The paper applies CCS methodology to deep learning code by analyzing GPT-2's source code from GitHub and two applications built on it. The authors distinguish between CDLC (model.py containing the neural network definition) and ADLC (interface code that handles user input and output processing). They conduct close reading of the code structure and syntax, then examine case studies of AI Dungeon and This Word Does Not Exist to show how ADLC transforms and mediates the language model's behavior. The analysis focuses on how ADLC enables distributed engagement and creative modification of deep learning systems through open-source code availability.

## Key Results
- CCS can be applied to deep learning systems by distinguishing between CDLC (model-defining code) and ADLC (application-supporting code)
- ADLC provides a more accessible entry point for CCS analysis than CDLC due to its closer resemblance to traditional programming
- The open-source nature of GPT-2 enables distributed engagement and creative modification through ADLC
- ADLC can be used to filter and moderate model output, preventing harmful content generation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Critical Code Studies (CCS) can be applied to deep learning systems by distinguishing between core model code and application code
- Mechanism: The paper creates a taxonomy of deep learning code into CDLC (Core Deep Learning Code) that defines the model and ADLC (Ancillary Deep Learning Code) that underwrites applications. This allows CCS to focus on the more accessible and culturally meaningful application code
- Core assumption: Deep learning code is not uniform and homogenous but can be meaningfully separated into model-defining and application-supporting components
- Evidence anchors:
  - [abstract] "we extract a representational map of OpenAI's GPT-2 with what we articulate as two classes of deep learning code, that which pertains to the model and that which underwrites applications built around the model"
  - [section] "we will articulate as a heuristic a practical and conceptual distinction between two classes of code: core deep learning code (CDLC), kernel code that defines the deep learning model, and ancillary deep learning code (ADLC), ancillary or application code that ordinary developers can replace"
  - [corpus] Weak evidence - no related papers directly discuss this CCS taxonomy of deep learning code
- Break condition: If the distinction between CDLC and ADLC becomes blurred or if ADLC cannot meaningfully influence model behavior, the CCS approach loses analytical value

### Mechanism 2
- Claim: ADLC provides a more accessible entry point for CCS analysis than CDLC because it resembles traditional programming and has clearer cultural/political implications
- Mechanism: While CDLC is mathematically complex and difficult to parse, ADLC consists of familiar programming constructs (loops, conditionals, functions) that can be analyzed for their cultural significance, power dynamics, and user interaction patterns
- Core assumption: The complexity of CDLC stems from mathematical operations while ADLC complexity stems from creative manipulation of model outputs and user interaction design
- Evidence anchors:
  - [section] "ADLC, on the other hand, can be used to interpret and manipulate the raw output in seemingly unlimited ways, and it is this creative and ethicopolitical potential that makes it a particularly fertile area for CCS analysis"
  - [section] "ADLC is productive terrain for critical and creative engagement, not least because its structure, logic, and syntactic form is closer to human language than CDLC"
  - [corpus] Weak evidence - no related papers directly discuss the accessibility of ADLC for CCS analysis
- Break condition: If ADLC becomes as mathematically complex as CDLC or if it loses its cultural/political significance through standardization

### Mechanism 3
- Claim: The open-source nature of GPT-2 enables distributed engagement and creative modification of deep learning systems through ADLC
- Mechanism: By making GPT-2's source code available, OpenAI enabled developers to create applications like AI Dungeon and This Word Does Not Exist that transform the language model through ADLC modifications, demonstrating how ordinary users can direct model behavior
- Core assumption: Open-source release of model code enables distributed innovation and democratization of AI development
- Evidence anchors:
  - [section] "Our analysis of GPT-2's code has shown that deep learning's potential for interactivity is embedded within the open-source Python kernel that made widely available the tools for building interfaces that structure user engagement"
  - [section] "The open source code also made it possible for developers to identify and then address unacceptable or otherwise faulty behavior—exercises that arguably contribute to a sense of community and collective responsibility"
  - [corpus] Weak evidence - no related papers directly discuss the distributed innovation enabled by GPT-2's open-source release
- Break condition: If open-source models become rare or if ADLC modifications are restricted by API controls or licensing

## Architecture Onboarding

- Component map:
  - CDLC (model.py): Contains neural network definition, attention mechanisms, tokenization, and core prediction logic
  - ADLC: Interface code that handles user input, calls model.py functions, processes output, and provides application-specific functionality
  - Training data pipeline: Web scrapers and preprocessing code that prepare data for model training
  - Runtime environment: TensorFlow dependencies and execution context

- Critical path: User input → ADLC preprocessing → model.py prediction → ADLC postprocessing → user output
- Design tradeoffs: Open vs. closed systems (GPT-2 open source vs. GPT-3 API), flexibility vs. safety (unrestricted vs. filtered output), simplicity vs. functionality (basic vs. complex interfaces)
- Failure signatures: Model produces nonsensical output, interface crashes during user interaction, content filters block legitimate content, performance degradation with concurrent users
- First 3 experiments:
  1. Run generate_unconditional_samples.py with different temperature settings to observe how randomness affects output
  2. Modify interactive_conditional_samples.py to add custom post-processing filters and observe effects on output quality
  3. Create a simple web interface using Flask that wraps GPT-2's prediction function and implements basic content moderation

## Limitations

- The core CDLC/ADLC taxonomy remains largely theoretical without extensive empirical validation across multiple deep learning architectures
- The case studies focus exclusively on GPT-2 and language models, leaving unclear whether the framework generalizes to other model families
- The paper doesn't address hybrid architectures where CDLC and ADLC boundaries blur, such as when ADLC implements custom attention mechanisms

## Confidence

- High confidence: The distinction between CDLC and ADLC as a practical taxonomy for organizing deep learning code analysis
- Medium confidence: The claim that ADLC is more accessible and culturally meaningful for CCS analysis than CDLC
- Low confidence: The generalizability of the framework beyond GPT-2 and language models to other deep learning domains
