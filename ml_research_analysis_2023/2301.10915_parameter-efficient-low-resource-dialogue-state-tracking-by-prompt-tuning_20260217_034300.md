# Parameter-Efficient Low-Resource Dialogue State Tracking by Prompt Tuning

## Quick Facts
- arXiv ID: 2301.10915
- Source URL: https://arxiv.org/abs/2301.10915
- Reference count: 37
- Key outcome: Achieves SOTA low-resource DST performance on MultiWOZ 2.0 using only 0.08% of parameters compared to fine-tuning baselines, with notably better results on categorical and number slot types.

## Executive Summary
This paper introduces a parameter-efficient approach to dialogue state tracking (DST) by freezing the language model and using soft prompt tokens to encode task-specific information. The method significantly reduces the number of trainable parameters (to less than 0.5% of prior works) while improving low-resource DST performance. Experiments on MultiWOZ 2.0 show state-of-the-art results using only 0.08% of parameters compared to fine-tuning baselines, with notably better performance on categorical and number slot types.

## Method Summary
The method freezes the parameters of a pre-trained GPT-2 model and introduces soft prompt tokens to adapt the model to the DST task. These soft prompts are continuous embeddings learned during training, initialized from the model's token embeddings. The approach uses a generative sequence-to-sequence framework where the input sequence combines prompt segments (domain, slot, type, question, prefix), dialogue history, and questions. The model generates slot values using reiteration in the target sequence and segment embeddings to distinguish different parts of the input. Only the soft prompt tokens and segment embeddings are updated during training, drastically reducing the number of trainable parameters.

## Key Results
- Achieves SOTA performance on MultiWOZ 2.0 in low-resource settings (5%, 10%, 20% of training data)
- Uses only 0.08% of trainable parameters compared to fine-tuning baselines
- Shows significant improvements on categorical and number slot types
- Demonstrates the effectiveness of reiteration and segment embeddings through ablation studies

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Freezing the language model parameters and only updating soft prompt tokens drastically reduces the number of trainable parameters while maintaining performance.
- Mechanism: By keeping the pre-trained language model frozen, the model leverages existing linguistic and commonsense knowledge without needing to retrain these parameters. The soft prompt tokens, which are learned embeddings, encode task-specific information and adapt the frozen model to the dialogue state tracking task.
- Core assumption: The pre-trained language model contains sufficient general knowledge that can be adapted to specific tasks through task-specific prompt embeddings without fine-tuning the entire model.
- Evidence anchors:
  - [abstract]: "Without tuning LM parameters, our method drastically reduces the number of parameters needed to less than 0.5% of prior works while achieves better low-resource DST performance."
  - [section 2.3]: "We use the pre-trained token embeddings to initialize the soft prompt token embeddings... Word-mapping prompt tokens are initialized with the embedding of the mapped word."

### Mechanism 2
- Claim: The reiteration technique in the target sequence improves the model's ability to learn and retain task information.
- Mechanism: By including a verbalized slot information phrase in the expected output sequence, the model is required to explicitly remember and reproduce task information before generating the answer phrase. This reinforces the learning of task boundaries and metadata.
- Core assumption: Explicitly including task information in the generation objective helps the model better understand and retain the task context.
- Evidence anchors:
  - [section 2.2]: "We introduce the reiteration technique in the target sequence... This technique allows the model to optimize upon both the answer and the sentence containing slot metadata, and explicitly learn the task information."
  - [section 4]: "We also observe an almost 2 points JGA drop (and an even larger drop with fewer training dialogues shown in § B.1) without reiteration (L7), which shows the helpfulness of including explicit task information in the learning objective."

### Mechanism 3
- Claim: Segment embeddings help the model distinguish between different parts of the input sequence, improving its understanding of task structure.
- Mechanism: By assigning unique segment IDs to different parts of the input sequence (e.g., task prompts, dialogue history, questions), the model can learn to identify and process each segment appropriately. This is especially important when the input sequence format differs significantly from the pre-training data.
- Core assumption: The model can effectively use segment embeddings to differentiate and process diverse input segments when combined with sequence and positional embeddings.
- Evidence anchors:
  - [section 2.2]: "Segment embeddings, which have the same length as the input sequence, are added with sequence embeddings and positional embeddings. We randomly initialize the embeddings of segment IDs and update them during training."
  - [section 4]: "The model without segment embedding (L6) has on average 7.8 points JGA drop, indicating the effectiveness of the segment embedding."

## Foundational Learning

- Concept: Pre-trained language models and transfer learning
  - Why needed here: The approach relies on leveraging a pre-trained model's existing knowledge and adapting it to a new task (DST) without full fine-tuning.
  - Quick check question: Why is it beneficial to freeze the LM parameters instead of fine-tuning them in low-resource settings?

- Concept: Prompt engineering and soft prompts
  - Why needed here: The method uses soft prompt tokens as continuous embeddings to encode task-specific information, which is a key technique for parameter-efficient adaptation.
  - Quick check question: How do soft prompts differ from traditional discrete text prompts in terms of optimization and expressiveness?

- Concept: Sequence-to-sequence generation and autoregressive decoding
  - Why needed here: The DST task is formulated as a conditional generation problem, requiring the model to generate slot values based on input sequences.
  - Quick check question: What are the advantages of using a generative approach for DST compared to classification-based methods?

## Architecture Onboarding

- Component map:
  GPT-2 (frozen) -> Soft prompt tokens -> Segment embeddings -> Sequence and positional embeddings -> Decoder stack -> Cross-entropy loss with regularization

- Critical path:
  1. Construct input sequence by concatenating prompt segments, dialogue history, and question.
  2. Generate sequence embeddings by combining prompt, dialogue history, and segment embeddings.
  3. Pass embeddings through frozen decoder stack to calculate output probabilities.
  4. Apply cross-entropy loss with regularization on prompt token embeddings.
  5. Update only prompt and segment embeddings during training.

- Design tradeoffs:
  - Parameter efficiency vs. model flexibility: Freezing LM parameters reduces trainable parameters but may limit adaptability.
  - Task specificity vs. generalization: Soft prompts are task-specific, which may affect cross-domain transfer.
  - Complexity of input sequence vs. model understanding: More complex input sequences may require more sophisticated segment embeddings.

- Failure signatures:
  - Poor performance on unseen domains or slot types due to lack of fine-tuning.
  - Overfitting to specific prompt formats if not enough diversity in training data.
  - Failure to generate correct slot values if the model cannot effectively use segment embeddings.

- First 3 experiments:
  1. Compare performance with and without reiteration in the target sequence to validate its impact.
  2. Test different numbers of soft prompt tokens for each segment to find optimal parameter count.
  3. Evaluate the model's sensitivity to learning rate and batch size to determine stable training configurations.

## Open Questions the Paper Calls Out

- Question: How does the performance of prompt tuning-based DST models scale with the size and diversity of the training data, and what is the optimal data size for achieving maximum performance?
- Question: How does the choice of prompt initialization strategy impact the model's performance, and can more advanced initialization methods further improve the results?
- Question: How does the proposed method perform in multi-lingual or code-switching scenarios, and what adaptations are needed to handle these cases?

## Limitations

- Evaluation limited to MultiWOZ 2.0 with 5 fixed domains, unclear if gains hold on newer datasets or more diverse domains
- No exploration of optimal prompt token counts, alternative initialization strategies, or robustness to noisy training data
- Performance measured only with greedy decoding, missing potential gains from beam search
- Cross-domain generalization not tested

## Confidence

- **High confidence**: Parameter efficiency claims (0.08% trainable parameters vs. fine-tuning baselines) and low-resource JGA improvements are directly supported by reported experimental results on MultiWOZ 2.0.
- **Medium confidence**: The effectiveness of the reiteration technique and segment embeddings is well evidenced in ablations, but their contributions are tied to the specific MultiWOZ setup and may not generalize across datasets or prompt formulations.
- **Low confidence**: The assumption that freezing the LM will universally preserve performance across unseen domains is not tested; no cross-domain or out-of-distribution validation is provided.

## Next Checks

1. **Dataset Generalization**: Replicate experiments on MultiWOZ 2.4 and the Schema-Guided Dialogue dataset to verify parameter efficiency and low-resource gains hold across newer or more diverse task-oriented dialogue benchmarks.

2. **Prompt Design Sensitivity**: Systematically vary the number of soft prompt tokens per segment and test different initialization schemes (e.g., random vs. token-mapped) to identify optimal configurations and robustness to prompt design choices.

3. **Decoding Strategy Impact**: Compare greedy decoding to beam search (with multiple beam widths) to assess whether higher quality outputs are achievable without sacrificing parameter efficiency.
