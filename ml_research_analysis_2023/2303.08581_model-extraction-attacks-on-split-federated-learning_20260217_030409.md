# Model Extraction Attacks on Split Federated Learning

## Quick Facts
- arXiv ID: 2303.08581
- Source URL: https://arxiv.org/abs/2303.08581
- Reference count: 40
- Demonstrates SFL vulnerability to model extraction attacks with >90% accuracy under practical threat models

## Executive Summary
This paper reveals that Split Federated Learning (SFL), designed to protect intellectual property by splitting models between client and server, is vulnerable to model extraction attacks. The authors propose five novel attacks that can reconstruct server-side models with high accuracy by exploiting gradient information, even without access to prediction APIs. These attacks demonstrate that the split architecture intended to protect IP can paradoxically enable extraction when adversaries have white-box gradient access. The work establishes a critical trade-off: larger server-side models provide better IP protection but at the cost of client data privacy.

## Method Summary
The authors develop five model extraction attack variants: Craft-ME, GAN-ME, GM-ME, Train-ME, and SoftTrain-ME. These attacks exploit the fact that clients receive gradients from the server during training, which contain information about the server-side model architecture and parameters. By iteratively querying with crafted inputs and analyzing gradient responses, attackers can reconstruct the server model's behavior. The attacks are designed to work under realistic constraints where attackers have white-box gradient access but no knowledge of the server architecture. The authors evaluate these attacks across different server-side model configurations, cut layer positions, and datasets to quantify vulnerability.

## Key Results
- All five attack variants achieve >90% accuracy on extracted models with less than 2% degradation compared to original models
- Attack success correlates with server-side model size - larger server-side models provide better IP protection
- L1 regularization on client-side models effectively defends against ME attacks by restricting feature extraction capabilities
- Complex datasets and certain architectures (e.g., ResNet) show increased resistance to model extraction

## Why This Works (Mechanism)
The attacks work by exploiting the gradient information exchanged during SFL training. When clients compute gradients for the server-side portion of the model, this information reveals structural and parametric details about the server model. By crafting specific inputs and analyzing how gradients change in response, attackers can reverse-engineer the server-side architecture and parameters. The split nature of SFL creates this vulnerability - while it protects IP from direct exposure, the gradient-based training protocol inadvertently leaks sufficient information for reconstruction.

## Foundational Learning
- **Split Federated Learning (SFL)**: A federated learning variant where the model is split between client and server to protect IP. Why needed: Understanding the target system's design principles and security assumptions.
- **Model Extraction (ME) Attacks**: Attacks that reconstruct model functionality from query access. Why needed: Core threat model being evaluated against SFL.
- **Gradient-based Reconstruction**: Using gradient information to infer model parameters. Why needed: The primary attack vector exploiting SFL's training protocol.
- **Threat Model Analysis**: Defining attacker capabilities (white-box gradients, no architecture knowledge). Why needed: Establishing realistic attack boundaries.
- **Defense Mechanisms**: Techniques like L1 regularization to prevent feature extraction. Why needed: Evaluating countermeasures to ME attacks.
- **Privacy-IP Trade-offs**: Balancing server-side model size for IP protection vs. client privacy. Why needed: Understanding fundamental tensions in SFL design.

## Architecture Onboarding

**Component Map**: Client-side model -> Cut layer -> Server-side model -> Aggregation

**Critical Path**: Client trains partial model → Computes gradients for server portion → Sends gradients to server → Server updates parameters → Returns updated gradients

**Design Tradeoffs**: Larger server-side models improve IP protection but reduce client privacy; smaller server-side models improve client privacy but weaken IP protection

**Failure Signatures**: High ME attack success rates (>90%) indicate vulnerability; effective L1 regularization reducing attack success indicates successful defense

## Limitations
- Threat model assumes white-box gradient access but no architecture knowledge, which may not reflect all real scenarios
- Evaluation primarily focuses on VGG-11 and CIFAR-10, limiting generalizability to other architectures
- Defense mechanism using L1 regularization may introduce performance trade-offs requiring further investigation
- Findings based on classification tasks may not transfer to other ML domains

## Confidence
High: Core claims about SFL vulnerability to ME attacks are well-supported with measurable success rates under clearly defined threat models
