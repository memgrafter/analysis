# Taming Resource Heterogeneity In Distributed ML Training With Dynamic Batching

## Quick Facts
- arXiv ID: 2305.12213
- Source URL: https://arxiv.org/abs/2305.12213
- Reference count: 40
- One-line primary result: Dynamic batching technique reduces model training times by more than 4x on heterogeneous clusters compared to uniform-batching

## Executive Summary
This paper addresses resource heterogeneity in distributed machine learning training by proposing dynamic batching, which adjusts mini-batch sizes per worker based on their resource availability and throughput. The method uses proportional control and PID controller concepts to equalize iteration times across workers in a data-parallel setup. Implemented in TensorFlow using the estimator API, the approach is evaluated across popular ML workloads and shows significant performance improvements over traditional uniform batching techniques.

## Method Summary
The method uses proportional control to dynamically adjust per-worker mini-batch sizes based on their throughput and iteration time deviations from the cluster average. Workers send gradients to parameter servers, which apply weighted averaging to maintain convergence properties. The controller uses dead-banding and exponential smoothing to prevent oscillation and stabilize batch sizes. The implementation is built on TensorFlow's estimator API and requires monitoring worker iteration times to make batch size adjustments.

## Key Results
- Reduces model training times by more than 4x on heterogeneous clusters
- Equalizes iteration times across workers with varying resource capacities
- Outperforms existing uniform-batching techniques in data-parallel distributed training

## Why This Works (Mechanism)

### Mechanism 1
Dynamic batching equalizes iteration times across workers by adjusting per-worker mini-batch sizes in proportion to their throughput. Uses a proportional-control loop where the mini-batch size adjustment is computed as Δ(bk) = -Xkτk, with Xk being the worker's throughput and τk the deviation from the cluster average iteration time. This reduces straggler impact in BSP.

### Mechanism 2
Gradient weighting compensates for non-uniform data consumption across workers. When mini-batch sizes differ, gradients are scaled by λk = bk / ∑i bi before averaging, preserving SGD convergence properties.

### Mechanism 3
Dead-banding and exponential smoothing stabilize the controller and prevent oscillation in batch sizes. Updates only occur if batch size change exceeds Δmin(b) and error is computed over an exponentially weighted moving average of recent iteration times.

## Foundational Learning

- Concept: Proportional control in PID controllers
  - Why needed here: The dynamic batching adjustment rule directly uses a proportional control term (-Xkτk) to drive iteration times toward equality
  - Quick check question: In a cluster with one fast worker (X=100) and one slow worker (X=25), if the slow worker's iteration time is 200ms above average, what is the sign of its batch size adjustment?

- Concept: Stochastic gradient descent convergence theory
  - Why needed here: Weighted gradient averaging must preserve SGD convergence despite varying mini-batch sizes
  - Quick check question: If global batch size is fixed, does changing per-worker batch sizes affect the expected value of the gradient estimate?

- Concept: Amdahl's law for intra-worker parallel scaling
  - Why needed here: Throughput does not scale linearly with CPU/GPU count due to serial portions of training; this affects static batch allocation
  - Quick check question: If a worker with 8 cores achieves 70% parallel efficiency, what is the effective throughput relative to a worker with 4 cores at 100% efficiency?

## Architecture Onboarding

- Component map: Master process -> Parameter servers -> Worker processes
- Critical path: Worker computes gradients -> sends to parameter servers -> parameter servers average weighted gradients -> broadcast new model -> worker adjusts batch size if needed
- Design tradeoffs: Static vs dynamic allocation (speed of convergence vs overhead), batch size bounds (stability vs responsiveness), dead-band threshold (sensitivity vs oscillation)
- Failure signatures: Persistent iteration time inequality after multiple adjustments, sudden throughput drop after batch increase (memory exhaustion), oscillations in batch sizes
- First 3 experiments:
  1. Run ResNet-50 BSP on 3 heterogeneous CPU workers with uniform batching; record per-worker iteration times
  2. Enable static variable batching; verify iteration times equalize and training time improves
  3. Enable dynamic batching; check for oscillations and measure final performance vs static

## Limitations
- Lacks implementation details for TensorFlow estimator API integration
- Missing specific parameter values for deadbanding and EWMA smoothing

## Confidence

- Medium: 4x performance improvement claim on heterogeneous clusters
- Low: Theoretical guarantee of SGD convergence with weighted gradient averaging
