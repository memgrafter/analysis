# Action Dynamics Task Graphs for Learning Plannable Representations of Procedural Tasks

## Quick Facts
- arXiv ID: 2302.05330
- Source URL: https://arxiv.org/abs/2302.05330
- Authors: 
- Reference count: 6
- Key outcome: 30.1% improvement in task tracking accuracy and 20.3% accuracy gain in next action prediction over state-of-the-art methods

## Executive Summary
This paper addresses the challenge of learning plannable representations of procedural tasks from video demonstrations. The authors propose Action Dynamics Task Graphs (ADTG), a structured representation centered around actions that captures temporal dependencies between actions. ADTG learns action embeddings by treating actions as transformations between states and uses these embeddings to track task progress, recommend next actions, and generate plans. The method is evaluated on 18 procedural tasks from the CrossTask dataset, showing substantial improvements over existing methods.

## Method Summary
ADTG learns plannable task representations by constructing graphs where actions are nodes and temporal dependencies are edges. The method learns action embeddings through a transformation prediction network that maps pre-condition states to post-condition states. These embeddings are used in two modules: task tracking (localizing current video frames in the graph) and next action recommendation (predicting the next action given history). A history RNN maintains context across actions. Plan generation uses autoregressive beam search with these components.

## Key Results
- 30.1% improvement in task tracking accuracy compared to state-of-the-art methods
- 20.3% accuracy gain in next action prediction
- Significant performance improvements over baseline methods (NTG, CrossTask, CrossTask-supervised)
- Ablation studies confirm importance of action history and action-centric representation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: ADTG's action-centric graph structure enables tractable planning where state-centric approaches fail due to state space explosion
- Mechanism: By representing procedural tasks as graphs with actions as nodes and temporal dependencies as edges, ADTG reduces the representation complexity from potentially infinite state space to the finite action space
- Core assumption: The action space of procedural tasks is significantly smaller than their visual state space, and temporal dependencies between actions can be captured without explicitly modeling intermediate states

### Mechanism 2
- Claim: Action embeddings learned as transformation predictors capture semantic relationships between actions and enable accurate task tracking
- Mechanism: The action embedding network trains action vectors to predict post-conditions from pre-conditions, creating embeddings that encode the semantic transformation each action represents
- Core assumption: Actions can be meaningfully represented as transformations between visual states, and these transformations can be learned from paired video segments without explicit state annotations

### Mechanism 3
- Claim: Incorporating action history through RNN enables context-aware predictions that significantly outperform history-agnostic approaches
- Mechanism: The history RNN maintains a hidden state representing the sequence of past actions, which conditions both the task tracking and next action recommendation modules
- Core assumption: Procedural tasks have sequential dependencies that extend beyond immediate action pairs, and these dependencies can be captured by maintaining a hidden state over the action history

  - Why needed here: This is the core mechanism by which ADTG learns meaningful action representations without explicit state annotations

## Architecture Onboarding

- Component map: Video features → Condition generator → Action embedding network → ADTG construction → Task tracking module → Next action recommendation → Plan generation (if needed)

- Critical path: Video features flow through the condition generator to the action embedding network, which constructs the ADTG. The task tracking and next action recommendation modules use these embeddings along with history RNN to localize and predict actions. Plan generation uses these predictions with beam search.

- Design tradeoffs:
  - Action-centric vs state-centric representation: Simpler graphs but less detailed state information
  - Fixed vs adaptive action embeddings: Fixed embeddings are simpler but may miss task-specific nuances
  - Greedy vs beam search planning: Beam search is more optimal but computationally expensive

- Failure signatures:
  - Task tracking fails when action embeddings don't capture semantic distinctions well enough
  - Next action recommendation fails when temporal dependencies are complex or bidirectional
  - Plan generation fails when initial localization is wrong (error compounds)
  - Overall performance degrades when action space becomes very large

- First 3 experiments:
  1. Train action embeddings on a simple task (like "Make lemonade") and visualize embeddings to check if semantically similar actions cluster together
  2. Compare task tracking accuracy with and without history RNN on a task with clear sequential dependencies
  3. Generate plans for tasks where the ground truth is known and measure accuracy at different beam search widths to find optimal trade-off

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do ADTG embeddings perform on procedural tasks with significant semantic overlap between actions across different tasks?
- Basis in paper: The paper notes that "we believe that this is primarily because the actions in the CrossTask tasks do not have much semantic or hierarchical overlap across tasks, unlike in Wang, Farhadi, and Gupta (2016)."
- Why unresolved: The paper only tests on the CrossTask dataset where actions have minimal semantic overlap. The paper explicitly states this is a limitation and suggests testing on tasks with connected action semantics as future work.

### Open Question 2
- Question: How can the plan generation component be modified to correct errors when the initial action localization is incorrect?
- Basis in paper: The paper discusses in the Discussion section that "The current design of the ADTG pipeline is not able to correct itself in the later steps of plan generation if it localizes itself in the wrong action node at the very beginning."
- Why unresolved: While the paper identifies this as a limitation and suggests incorporating more state information, it doesn't propose a specific solution or demonstrate how such a modification would work in practice.

### Open Question 3
- Question: How would incorporating object and attribute information into the ADTG edges affect task tracking and plan generation performance?
- Basis in paper: The paper suggests in the Discussion that "Interesting future directions would include incorporating more state information (e.g., object or attribute information) on the edges of ADTG graphs."
- Why unresolved: The paper only tests with action-only representations and doesn't explore how adding state information to edges would impact performance metrics.

## Limitations
- Evaluation focuses on video understanding metrics rather than true plan execution or real-world robot deployment
- Action embedding network architecture is underspecified beyond "two-layer feedforward networks"
- Method assumes paired video narrations are available during training, which may not hold in many real-world scenarios

## Confidence

- **High Confidence**: The core mechanism of using action-centric graphs instead of state-centric representations is well-supported by the problem formulation and theoretical arguments. The improvement over baselines (30.1% tracking accuracy, 20.3% next action accuracy) is clearly demonstrated.
- **Medium Confidence**: The action embedding learning through transformation prediction is conceptually sound but relies on assumptions about action pre/post-condition relationships that may not generalize to all procedural tasks. The history RNN's contribution is demonstrated but the ablation study could be more thorough.
- **Low Confidence**: The plan generation evaluation assumes perfect task tracking and doesn't account for compounding errors. The CrossTask dataset limitations (primarily cooking and craft tasks) may restrict generalizability to more complex or safety-critical applications.

## Next Checks

1. Implement a version of ADTG that incorporates visual observations directly into the planning module to test whether history RNN alone is sufficient for accurate plan generation
2. Test ADTG on a dataset with tasks that have non-sequential dependencies or parallelizable actions to evaluate the limits of the history-based approach
3. Conduct a systematic ablation study varying action embedding dimensionality and RNN hidden state size to identify optimal architecture parameters across different task types
