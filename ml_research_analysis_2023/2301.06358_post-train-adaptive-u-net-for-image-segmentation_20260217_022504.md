# Post-Train Adaptive U-Net for Image Segmentation

## Quick Facts
- arXiv ID: 2301.06358
- Source URL: https://arxiv.org/abs/2301.06358
- Reference count: 32
- Primary result: PTA blocks enable runtime configuration of U-Net for adaptive image segmentation, improving Dice scores while enabling speed-quality tradeoffs.

## Executive Summary
This paper introduces the Post-Train Adaptive (PTA) approach to image segmentation using U-Net with a MobileNetV2 backbone. The key innovation is the ability to configure the network at runtime after training, enabling adaptation to different device performance categories. The approach uses PTA blocks with light and heavy computational paths, trained using a PTA-sampling strategy that ensures good performance across all configurations.

## Method Summary
The PTA approach modifies U-Net by inserting adaptive PTA blocks into the encoder (MobileNetV2 backbone). Each PTA block contains two parallel branches - a light branch with one inverted residual block and a heavy branch with two sequential inverted residual blocks. During training, a PTA-sampling strategy randomly selects different configurations of these blocks to ensure the model learns to perform well under all possible runtime settings. The model is evaluated on the CamVid dataset with Dice loss and Dice score metrics.

## Key Results
- All 6 PTA configurations showed better Dice scores than the original U-Net (No PTA) model
- Best improvement: 0.0087 Dice score increase
- Fastest configuration was 3.14% faster than baseline
- PTA approach improved image segmentation quality while enabling post-training network configuration

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Post-Train Adaptive (PTA) blocks allow runtime selection between light and heavy computational paths without retraining.
- Mechanism: Each PTA block contains two parallel branches—one with a single inverted residual block (light) and another with two sequential inverted residual blocks (heavy). During training, the model is sampled across configurations that enable either branch or both averaged. At inference, the appropriate branch is selected based on device performance.
- Core assumption: The dual-branch design enables the model to retain performance when using the heavy branch and gain speed when using the light branch, while maintaining similar representational capacity.
- Evidence anchors:
  - [abstract] "PTA blocks and PTA-sampling training strategy are key components."
  - [section] "A single PTA block has 2 branches: Light branch. Contains a single Inverted Residual block; Heavy branch. Contains two Inverted Residual blocks connected sequentially."
  - [corpus] Weak—no direct neighbor papers discuss PTA or adaptive branches at training time.
- Break condition: If the heavy and light branches diverge significantly in learned representations, runtime selection could cause accuracy drops.

### Mechanism 2
- Claim: PTA-sampling during training teaches the network to perform well under all post-train configurations simultaneously.
- Mechanism: During training, random sampling of PTA block configurations (e.g., Heavy-Heavy-Heavy, Light-Heavy-Heavy, etc.) forces the network to develop shared features robust to branch selection. This prevents overfitting to a single configuration.
- Core assumption: Training on diverse configurations results in a single model that generalizes well across all possible runtime settings.
- Evidence anchors:
  - [abstract] "The two key components of the approach are PTA blocks and PTA-sampling training strategy."
  - [section] "To enable dynamic branch selection in the PTA block without retraining, a special PTA-sampling strategy is applied at training time."
  - [corpus] Weak—neighbors focus on segmentation but not adaptive sampling strategies.
- Break condition: If the sampling distribution does not cover realistic deployment scenarios, the model may perform poorly in untested configurations.

### Mechanism 3
- Claim: Replacing parts of the encoder with PTA blocks improves Dice score while enabling configurable speed-quality tradeoffs.
- Mechanism: By inserting PTA blocks into the U-Net encoder (MobileNetV2 backbone), the model gains adaptive capacity without modifying the decoder. The learned configurations trade operations for accuracy, allowing lighter models to run faster with minimal quality loss.
- Core assumption: The encoder modifications do not harm the decoder's ability to reconstruct accurate segmentation maps.
- Evidence anchors:
  - [abstract] "All of the configurations have better quality than the original U-Net (No PTA) model."
  - [section] "In this work we include PTA blocks only in the U-Net encoder (backbone), leaving the decoder part intact."
  - [corpus] Weak—no neighbor papers evaluate encoder-only adaptive modifications in segmentation.
- Break condition: If the decoder cannot adapt to variable encoder outputs, segmentation quality may degrade for certain PTA configurations.

## Architecture Onboarding

- Component map: CamVid images -> MobileNetV2 backbone with 3 PTA blocks -> U-Net decoder -> Segmentation output
- Critical path:
  1. Load and preprocess CamVid images (resize to 256x256, letterbox)
  2. Sample PTA configurations during training
  3. Forward pass through encoder (with PTA blocks)
  4. Decoder reconstructs segmentation map
  5. Compute Dice loss and update weights
- Design tradeoffs:
  - Adding PTA blocks increases parameter count slightly but enables runtime flexibility
  - Sampling strategy complexity vs. model robustness
  - Encoder-only adaptation keeps decoder simple but may limit full-network adaptivity
- Failure signatures:
  - Training instability if sampling probabilities are poorly chosen
  - Degraded segmentation if PTA block branching is not well balanced
  - Slow inference if heavy branches dominate despite device constraints
- First 3 experiments:
  1. Train baseline U-Net (No PTA) on CamVid and measure Dice score and inference time.
  2. Train U-Net+PTA with default sampling probabilities; evaluate all 6 configurations for quality and speed.
  3. Vary PTA sampling probabilities to bias toward light configurations; measure impact on speed and accuracy.
