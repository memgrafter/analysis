# Hawk: An Industrial-strength Multi-label Document Classifier

## Quick Facts
- arXiv ID: 2301.06057
- Source URL: https://arxiv.org/abs/2301.06057
- Reference count: 6
- Primary result: Achieves 94.45% accuracy on WOS-5763 dataset

## Executive Summary
Hawk is an industrial-strength multi-label document classifier designed to address real-world challenges including imbalanced datasets, catastrophic forgetting, and the need for explainability. The model views documents as sequences of sentences and leverages sentence-level embeddings for input representation. Using a hydranet-like architecture with task-specific heads (Bi-LSTM and transformer-based), Hawk provides granular control over modularity and scalability while being driven by weighted loss functions to handle imbalanced datasets. The architecture demonstrates significant improvements over existing methods, particularly on the Web of Science datasets.

## Method Summary
Hawk processes documents by breaking them into fixed-size character blocks (100 chars), applying Universal Sentence Encoder (DAN variant) to generate 512-dimensional sentence embeddings, and using a hydranet architecture with optional neck layers and task-specific heads. The model employs weighted binary cross-entropy loss to address class imbalance, where weights are inversely proportional to class frequency. Training uses a max document length of 5,000 characters, batch size of 16, and 5 epochs. The architecture supports both Bi-LSTM heads (10-unit bidirectional LSTM layers) and transformer heads (3 multi-head attention heads) for different classification tasks.

## Key Results
- Achieves 94.45% accuracy on WOS-5763 dataset, significantly outperforming existing models
- Demonstrates 92.81% accuracy on WOS-11967 dataset with substantial improvement margins
- Ablation study shows attention mechanisms and weighted loss functions significantly impact performance
- Provides explainability through attention visualization of relevant text portions in predictions

## Why This Works (Mechanism)

### Mechanism 1
The hydranet architecture with task-specific heads solves the catastrophic forgetting problem by allowing selective training of individual branches. By detaching specific heads during online learning and freezing the neck, the model can update with new data without affecting previously learned label representations. This modular design means that adding or removing labels doesn't destabilize the entire model.

### Mechanism 2
Viewing documents as sequences of fixed-length sentences and using sentence-level embeddings reduces computational overhead while maintaining classification accuracy. By breaking long documents into fixed-size blocks and using sentence embeddings (512-dimensional vectors from USE), the model avoids processing individual words while still capturing meaningful semantic information. This significantly reduces the number of features compared to word-level approaches.

### Mechanism 3
Weighted loss functions effectively handle imbalanced datasets by assigning higher importance to underrepresented classes. The model uses weighted binary cross-entropy where weights are inversely proportional to class frequency. This forces the model to pay more attention to minority classes during training.

## Architecture Onboarding

- **Component map**: Text → Sentence blocks → USE embeddings → Stem processing → Neck (optional) → Task-specific heads → Weighted loss → Predictions
- **Critical path**: The processing pipeline moves from raw text through sentence embedding generation to hydranet classification heads
- **Design tradeoffs**: Sentence-level vs word-level processing reduces computational overhead but may lose fine-grained information; fixed block size simplifies processing but requires careful hyperparameter tuning; hydranet modularity enables selective training but adds architectural complexity; weighted loss addresses class imbalance but may cause overfitting on rare classes
- **Failure signatures**: Poor performance on long documents may indicate inadequate block size or insufficient model capacity; catastrophic forgetting during online updates suggests neck wasn't properly frozen or tasks are too interdependent; imbalanced class predictions may indicate weighted loss parameters need adjustment; inability to explain predictions could mean attention mechanisms aren't working or visualization approach needs refinement
- **First 3 experiments**:
  1. Baseline comparison: Train the model on WOS-5763 with default hyperparameters and compare accuracy to published results (94.45% target)
  2. Block size sensitivity: Test different values of sb (50, 100, 200 characters) and measure impact on accuracy and training time
  3. Online learning test: Freeze the neck and train only one head with new data containing missing labels, then measure performance degradation on other labels

## Open Questions the Paper Calls Out

### Open Question 1
How does the block size (sb) hyperparameter affect the model's performance on different types of documents (e.g., scientific papers vs. news articles)? The paper mentions that block size (sb) defines the size of individual blocks that the USE embeds and discusses the trade-off between block size and computational cost, but does not provide experimental results comparing the impact of different block sizes on various document types.

### Open Question 2
How does the proposed architecture handle documents with mixed languages or code-switching within the text? The paper does not explicitly discuss handling mixed languages, but the architecture treats documents as sequences of sentences, which could be relevant for language identification within documents.

### Open Question 3
What is the impact of the attention window (τ) size on the model's performance for different document lengths? The paper discusses the effect of the attention window (τ) on the model's predictions and mentions that the window size controls the width of the attention window, but does not provide a comprehensive analysis of how different attention window sizes affect performance across various document lengths.

## Limitations

- The exact correlation mapping between labels for hydranet heads is not clearly defined, making faithful reproduction challenging
- The evaluation focuses on accuracy and micro-F1 metrics but doesn't explore other relevant measures like macro-F1 or Hamming loss
- While the hydranet architecture is theoretically sound for addressing catastrophic forgetting, the paper provides limited empirical evidence demonstrating this specific benefit
- The explainability approach relies on attention visualization, but the paper doesn't validate whether these visualizations actually help users understand predictions

## Confidence

- **High confidence**: Sentence-level embedding approach and weighted loss function for handling imbalanced data are well-established techniques with clear implementation details
- **Medium confidence**: Hydranet architecture's effectiveness for multi-label classification and catastrophic forgetting prevention, as the theoretical framework is sound but empirical validation is limited
- **Low confidence**: Specific explainability claims regarding attention visualization usefulness, as the paper doesn't provide user studies or validation of the interpretability approach
