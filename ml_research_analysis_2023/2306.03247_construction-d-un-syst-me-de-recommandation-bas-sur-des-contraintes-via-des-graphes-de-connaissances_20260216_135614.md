# Construction d'un système de recommandation basé sur des contraintes via des graphes de connaissances

## Quick Facts
- arXiv ID: 2306.03247
- Source URL: https://arxiv.org/abs/2306.03247
- Authors: 
- Reference count: 0
- Primary result: Constraint-based recommender system using RDF knowledge graphs achieves 88% solution rate for vehicle recommendations

## Executive Summary
This paper presents a constraint-based recommender system that leverages RDF knowledge graphs for the vehicle purchase/sale domain. The system addresses the challenge of providing relevant recommendations for expensive, infrequently purchased items like vehicles by explicitly capturing user preferences and requirements. The core method involves representing user profiles, vehicle descriptions, and their interactions as RDF triples, then separating constraints into domain-specific knowledge (encoded as SWRL rules) and user preferences (expressed as SPARQL queries). Experiments with a dataset of 5,537 vehicles and 367 users demonstrate the approach's effectiveness, with 88% of users finding at least one solution.

## Method Summary
The system represents user profiles and vehicle descriptions as RDF triples within a knowledge graph. Domain-specific constraints are encoded as SWRL rules, while user preferences are expressed as SPARQL queries. The recommendation process involves finding variable assignments that satisfy all constraints simultaneously through CSP formulation. When initial constraint sets yield insufficient solutions, diagnostic constraint sets are used to iteratively relax less critical constraints to increase solution availability while maintaining user satisfaction.

## Key Results
- System achieves 88% solution rate with users finding at least one relevant vehicle recommendation
- Diagnostic constraint sets improve solution availability by expanding recommendation options when initial constraints are too restrictive
- Separation of constraints into SWRL rules (domain knowledge) and SPARQL queries (user preferences) provides effective filtering mechanism

## Architecture Onboarding

- Component map: RDF Knowledge Graph -> SWRL Rule Engine -> SPARQL Query Processor -> Diagnostic Constraint Manager -> Recommendation Engine
- Critical path: User preference input -> SPARQL constraint processing -> SWRL domain rule application -> Solution matching -> Recommendation output
- Design tradeoffs:
  - SPARQL vs. native graph traversal: SPARQL provides powerful filtering but may be slower than custom graph algorithms
  - SWRL vs. procedural constraints: SWRL rules are declarative and reusable but may have performance limitations
  - Diagnostic constraint sets vs. complete constraint satisfaction: Relaxing constraints increases solution availability but may reduce recommendation quality
- Failure signatures:
  - SPARQL query timeout: Indicates overly complex filtering or insufficient indexing
  - Zero solutions found: Suggests constraint mismatch between user preferences and available vehicles
  - Inconsistent SWRL rule application: Points to ontology structure issues or rule conflicts
- First 3 experiments:
  1. Test basic SPARQL filtering with a small vehicle dataset and simple user preferences (e.g., budget constraint only)
  2. Implement and test SWRL rules for domain constraints (e.g., technical inspection requirements)
  3. Build diagnostic constraint sets and measure the tradeoff between constraint relaxation and solution quality across different user profiles

## Limitations
- Proof-of-concept implementation without addressing scalability challenges for larger datasets or real-time recommendation scenarios
- Effectiveness evaluation relies on simulated user data rather than actual user feedback
- 88% success rate metric doesn't capture recommendation quality or user satisfaction beyond solution existence
- Diagnostic constraint set approach lacks systematic evaluation of tradeoff between constraint relaxation and recommendation relevance
