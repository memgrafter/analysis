# LostNet: A smart way for lost and find

## Quick Facts
- arXiv ID: 2301.02277
- Source URL: https://arxiv.org/abs/2301.02277
- Reference count: 0
- Primary result: LostNet achieves 96.8% testing accuracy on lost item identification using MobileNetV2 + CBAM with only 3.5M parameters

## Executive Summary
LostNet presents an intelligent image recognition system for lost and found applications using transfer learning with MobileNetV2 and CBAM attention modules. The system addresses the challenge of efficiently managing lost items in urban public spaces by automating image-based identification. A private dataset of 10,499 images across 10 common categories was constructed and used to train the model. The approach achieved high performance (96.8% accuracy) while maintaining computational efficiency suitable for laptop deployment.

## Method Summary
The LostNet system employs transfer learning with MobileNetV2 as the backbone architecture, enhanced with a Convolutional Block Attention Module (CBAM) to improve feature discrimination. The model was trained on a custom dataset of 10,499 images spanning 10 common lost item categories. The training utilized standard image augmentation techniques and optimization procedures. For deployment efficiency, the model maintains only 3.5M parameters and 665.12M GFLOPs, making it suitable for edge computing scenarios. The system also incorporates perceptual hashing for online image matching and comparison functionality.

## Key Results
- Achieved 96.8% testing accuracy on private dataset of 10,499 images across 10 categories
- Outperformed eight baseline models (EfficientNet, Inception v4, ViT-B.32, DenseNet201, VGGNet19, ShuffleNet v2, ResNet152, MobileNetV3) in comparative experiments
- Maintained minimal computational overhead with only 3.5M parameters and 665.12M GFLOPs
- Demonstrated computational efficiency suitable for laptop deployment

## Why This Works (Mechanism)
The LostNet system leverages the strengths of lightweight CNN architectures combined with attention mechanisms to achieve high performance in lost item recognition. MobileNetV2 provides an efficient feature extraction backbone with depthwise separable convolutions that reduce computational complexity while maintaining representational power. The CBAM attention module enhances this by allowing the network to focus on discriminative regions within lost items, improving classification accuracy without significant computational overhead. The transfer learning approach enables effective learning from limited training data by leveraging pre-trained knowledge from large-scale image datasets. Perceptual hashing integration allows for efficient online matching of similar items, addressing the practical challenge of duplicate reporting in lost and found systems.

## Architecture Onboarding

**Component Map:** Input Images -> Data Augmentation -> MobileNetV2 Backbone -> CBAM Attention Module -> Classification Head -> Output Probabilities

**Critical Path:** Image preprocessing → MobileNetV2 feature extraction → CBAM spatial and channel attention → Global pooling → Fully connected layers → Classification

**Design Tradeoffs:** The system prioritizes computational efficiency (3.5M parameters) over maximum accuracy, choosing MobileNetV2 over larger architectures. The CBAM attention adds minimal overhead while providing significant accuracy gains. The 10-category limitation balances coverage with practical deployment feasibility.

**Failure Signatures:** The system may struggle with items that have similar visual features across categories, variations in lighting conditions, or occlusions. Background clutter and non-standard viewing angles could reduce accuracy. The private dataset may not capture the full diversity of real-world lost items.

## Limitations
- Private dataset prevents independent validation and reproducibility of results
- Limited to 10 common item categories, may not represent full diversity of lost items in urban spaces
- Real-world performance under varying environmental conditions and lighting remains untested
- Integration of perceptual hashing mentioned but not empirically evaluated in comparison scenarios
