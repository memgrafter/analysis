# Fairness-aware Differentially Private Collaborative Filtering

## Quick Facts
- arXiv ID: 2303.09527
- Source URL: https://arxiv.org/abs/2303.09527
- Reference count: 33
- Key outcome: DP-Fair framework reduces unfairness gap (F_U) by 15-20% compared to DP-SGD while improving NDCG and F1 scores for both active and inactive users.

## Executive Summary
This paper addresses the issue of algorithmic fairness in differentially private collaborative filtering, specifically the "poor become poorer" phenomenon where inactive users suffer more from privacy-preserving noise. The authors propose DP-Fair, a two-stage framework that combines differential privacy mechanisms with fairness constraints. The framework first applies separated DP-SGD to user and item embeddings, then uses post-processing re-ranking to enforce user group fairness. Experimental results on Amazon datasets and Etsy logs demonstrate that DP-Fair outperforms vanilla DP-SGD in both recommendation performance and fairness metrics.

## Method Summary
The method employs a two-stage framework: Stage 1 applies separated DP-SGD where user and item gradients are clipped and noised separately to reduce utility loss from uniform noise addition. Stage 2 performs post-processing re-ranking using integer programming to select fair recommendation lists while preserving privacy guarantees. The approach uses implicit feedback datasets, trains BPR-MF and NeuMF models, and evaluates using NDCG@10, F1@10, and F_U fairness metric comparing active vs inactive user groups.

## Key Results
- DP-Fair reduces unfairness gap (F_U) by 15-20% compared to DP-SGD
- Improves NDCG and F1 scores for both active and inactive users
- Maintains differential privacy guarantees through post-processing
- Separated DP-SGD provides better utility than uniform DP-SGD

## Why This Works (Mechanism)

### Mechanism 1
The separated DP-SGD reduces utility loss by tailoring noise addition and gradient clipping to the distinct statistical properties of user vs item gradients, avoiding unnecessary perturbation from uniform clipping bounds.

### Mechanism 2
Post-processing re-ranking enforces fairness by solving an integer program that selects a subset of top-K items for each user, maximizing prediction scores while constraining the unfairness metric F_U between active and inactive user groups.

### Mechanism 3
The two-stage design decouples privacy-utility and fairness-utility tradeoffs, allowing independent optimization of each objective without violating differential privacy guarantees.

## Architecture Onboarding

- **Component map**: User-item interaction data -> Tailored DP-SGD training -> Generate top-K predictions -> Integer programming re-ranking -> Fairness-aware recommendations
- **Critical path**: 1) Data preprocessing to binary implicit feedback 2) Train model with tailored DP-SGD 3) Generate top-K predictions 4) Solve integer program for fairness-aware re-ranking 5) Output top-k fair recommendations
- **Design tradeoffs**: Privacy budget ε vs. model utility; fairness constraint α vs. active user utility; clipping bounds C_u, C_v vs. bias/noise; Ranker K vs. re-ranker k vs. computation
- **Failure signatures**: Very low NDCG/F1 after training (too tight privacy budget); integer program infeasible (fairness constraint too strict); no improvement over DP-SGD (similar gradient scales)
- **First 3 experiments**: 1) Train BPR-MF on Amazon dataset with ε=1, compare NDCG/F1 and F_U between vanilla DP-SGD and DP-Fair 2) Vary clipping bounds C_u, C_v and observe impact on NDCG and F_U gap 3) Fix ε=1, vary fairness threshold α and measure impact on active vs inactive user performance

## Open Questions the Paper Calls Out

## Limitations
- The effectiveness of separated DP-SGD depends on unverified assumptions about gradient scale differences between users and items
- The integer programming solver may fail or produce invalid rankings when fairness constraints are too strict
- Hyperparameter specifications like exact active/inactive user thresholds and regularization values are not clearly defined

## Confidence

- **High**: Differential privacy guarantees preserved through post-processing; integer programming formulation correctly enforces fairness constraints
- **Medium**: Separated DP-SGD provides utility improvements over uniform DP-SGD; two-stage framework allows independent tuning of privacy-utility and fairness-utility tradeoffs
- **Low**: Exact definition of active vs inactive users and optimal hyperparameter values are not clearly specified
