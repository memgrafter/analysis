# STREET: A Multi-Task Structured Reasoning and Explanation Benchmark

## Quick Facts
- arXiv ID: 2302.06729
- Source URL: https://arxiv.org/abs/2302.06729
- Reference count: 40
- Primary result: Current language models can achieve high answer accuracy on multi-step reasoning tasks but struggle to generate coherent structured explanations, performing significantly below human capability.

## Executive Summary
STREET is a multi-task benchmark for natural language reasoning that requires models to generate step-by-step structured explanations alongside answering questions. The benchmark includes five reasoning tasks from quantitative, analytical, and deductive domains, with each question accompanied by a reasoning graph showing how premises lead to intermediate conclusions and final answers. Experiments with T5 and GPT-3 models reveal that while these models can achieve reasonable answer accuracy, they perform significantly worse than humans at generating coherent reasoning graphs, highlighting a gap between problem-solving and explanation capabilities.

## Method Summary
The STREET benchmark evaluates language models on multi-step reasoning tasks by requiring them to generate linearized reasoning graphs that connect premises to conclusions. The evaluation uses three metrics: answer accuracy (exact match), reasoning graph accuracy (strict topological alignment with ground truth), and graph similarity (soft structural match using graph edit distance). Models are evaluated in two settings: fine-tuned T5-large and few-shot GPT-3, with training conducted separately for each task using standard optimization techniques and evaluation performed on held-out test sets.

## Key Results
- Language models achieve high answer accuracy but significantly lower reasoning graph accuracy across all tasks
- T5 fine-tuning generally outperforms GPT-3 few-shot prompting for structured reasoning generation
- Human performance on reasoning graph generation significantly exceeds model performance
- Multi-task evaluation reveals domain-specific challenges in reasoning graph generation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Multi-step reasoning with explicit intermediate conclusions improves model interpretability compared to end-to-end answer prediction.
- Mechanism: By decomposing reasoning into structured steps connected in a directed acyclic graph, models are forced to generate intermediate conclusions that can be traced and verified, creating an inspectable reasoning path.
- Core assumption: Human-readable intermediate conclusions can be generated and connected in a way that preserves logical entailment from premises to final answer.

### Mechanism 2
- Claim: Fine-tuning on structured reasoning data enables better generation of explanation graphs than few-shot prompting alone.
- Mechanism: Supervised training on labeled reasoning graphs provides explicit supervision on both the content and structure of intermediate reasoning steps, whereas few-shot prompting relies on implicit learning from examples.
- Core assumption: The training data contains sufficient examples of valid reasoning graph structures for the model to learn general patterns.

### Mechanism 3
- Claim: Multi-task evaluation across diverse reasoning domains provides better assessment of general reasoning capabilities than single-task benchmarks.
- Mechanism: By requiring models to handle quantitative, analytical, and deductive reasoning tasks with varying complexity, the benchmark exposes weaknesses in domain transfer and generalization that single-task benchmarks might miss.
- Core assumption: The selected tasks sufficiently represent different reasoning paradigms to test general capabilities rather than task-specific patterns.

## Foundational Learning

- Concept: Directed acyclic graph (DAG) representation of reasoning
  - Why needed here: The reasoning graphs are structured as DAGs where premises lead to conclusions through directed edges, and cycles would create logical paradoxes.
  - Quick check question: What would happen if a reasoning graph contained a cycle? Would the model still be able to generate a valid explanation?

- Concept: Topological sorting of reasoning steps
  - Why needed here: The linearization of reasoning graphs requires a topological order to ensure all premises appear before conclusions that depend on them.
  - Quick check question: Why can't we simply sort reasoning steps alphabetically or by length when linearizing the graph for model input?

- Concept: Graph edit distance as similarity metric
  - Why needed here: The evaluation compares generated reasoning graphs to ground truth using graph edit distance, which measures structural differences between graphs.
  - Quick check question: How does the graph edit distance metric handle cases where the generated answer is correct but the reasoning path differs from the ground truth?

## Architecture Onboarding

- Component map:
  - Data processing pipeline: TLU extraction → reasoning graph construction → linearization for model input
  - Model training: T5 fine-tuning → GPT-3 few-shot prompting → evaluation with accuracy metrics
  - Evaluation framework: Answer accuracy → reasoning graph accuracy → graph similarity metrics

- Critical path: Question → TLU extraction → reasoning graph generation → answer extraction → evaluation
  - Each component must process correctly for the final evaluation score to be meaningful.

- Design tradeoffs:
  - Strict vs soft evaluation: Reasoning graph accuracy requires exact matches while graph similarity allows partial credit
  - Task-specific vs unified encoding: Different text similarity functions per task vs single unified approach
  - Human annotation vs programmatic generation: Expert-annotated graphs provide quality but limit scale

- Failure signatures:
  - Low reasoning graph accuracy despite high answer accuracy indicates models can solve problems without understanding the reasoning
  - Inconsistent text similarity function performance across tasks suggests encoding issues
  - Poor generalization from few-shot examples indicates task distribution mismatch

- First 3 experiments:
  1. Run baseline T5 model on ARC task and compare reasoning graph accuracy vs answer accuracy to quantify the gap between solving and explaining
  2. Test different beam sizes for T5 generation to find optimal trade-off between diversity and coherence
  3. Compare few-shot performance with varying numbers of examples to determine optimal prompt size for each task

## Open Questions the Paper Calls Out
- How can we improve the performance of language models on generating coherent and relevant reasoning graphs for complex analytical reasoning tasks like AR-LSAT?
- How does the performance of language models on STREET tasks vary across different domains (e.g., quantitative, analytical, deductive reasoning) and what factors contribute to these differences?
- Can unsupervised or semi-supervised learning approaches be used to improve the performance of language models on STREET tasks, especially when labeled data is limited?

## Limitations
- Data generation scalability: Expert-annotated reasoning graphs limit the diversity and coverage of reasoning patterns that can be evaluated
- Task selection bias: The five selected tasks may not comprehensively capture the space of human reasoning capabilities
- Evaluation metric limitations: The strict exact match requirement for reasoning graph accuracy may underestimate model capabilities by penalizing valid alternative reasoning paths

## Confidence
**High Confidence**
- Core finding that models struggle with structured reasoning generation despite reasonable answer accuracy
- Methodology for linearizing reasoning graphs and basic evaluation framework

**Medium Confidence**
- Relative performance differences between T5 and GPT-3 across tasks
- Claim that multi-task evaluation provides better assessment of general reasoning capabilities

**Low Confidence**
- Absolute values of reasoning graph accuracy across tasks
- Comparison between human performance and model performance

## Next Checks
1. Evaluate models trained on STREET on external reasoning datasets (e.g., DROP, LogiQA) to assess cross-dataset generalization of structured reasoning capabilities.

2. Systematically vary ground truth reasoning graphs by introducing alternative valid reasoning paths and measure how evaluation metrics respond to structurally different but logically equivalent explanations.

3. Conduct detailed error analysis comparing human and model reasoning graphs on the same questions to identify specific types of reasoning steps or structural patterns where models consistently fail.
