# PCR: Proxy-based Contrastive Replay for Online Class-Incremental Continual Learning

## Quick Facts
- arXiv ID: 2304.04408
- Source URL: https://arxiv.org/abs/2304.04408
- Authors: 
- Reference count: 40
- Final accuracy rates: 58.8% on Split CIFAR10, 29.3% on Split CIFAR100, 28.4% on Split MiniImageNet

## Executive Summary
This paper addresses catastrophic forgetting in online class-incremental continual learning by proposing Proxy-based Contrastive Replay (PCR). The method combines proxy-based and contrastive-based replay approaches to leverage their complementary advantages. PCR replaces anchor-to-sample pairs with anchor-to-proxy pairs in contrastive loss, using proxies from classes present in the current batch to effectively address class imbalance issues while maintaining fast convergence. Experiments on three benchmark datasets demonstrate consistent improvements over state-of-the-art methods.

## Method Summary
PCR combines proxy-based and contrastive-based replay mechanisms to address catastrophic forgetting in online class-incremental continual learning. The method uses a Reduced ResNet18 backbone with a proxy-based classifier and memory buffer. During training, samples from the current batch are combined with samples from the memory buffer, and the model computes a contrastive loss using anchor-to-proxy pairs selected from classes present in the current batch. The memory buffer is updated using reservoir sampling, and data augmentation is applied during training. The final prediction uses a combination of proxy-based and contrastive-based probabilities.

## Key Results
- PCR achieves final accuracy rates of 58.8% on Split CIFAR10, significantly outperforming existing approaches
- On Split CIFAR100, PCR reaches 29.3% final accuracy, demonstrating effective knowledge retention
- For Split MiniImageNet, PCR achieves 28.4% final accuracy while maintaining balanced performance across tasks

## Architecture Onboarding

- Component map:
  - Feature extractor (Reduced ResNet18 backbone) -> Proxy-based classifier with trainable proxies -> Memory buffer for storing previous samples -> Batch-based proxy selection mechanism -> Contrastive loss with anchor-to-proxy pairs

- Critical path:
  1. Sample current batch from data stream
  2. Retrieve samples from memory buffer
  3. Combine and augment samples
  4. Compute contrastive loss with selected proxies
  5. Update model parameters
  6. Update memory buffer

- Design tradeoffs:
  - Buffer size vs. performance (larger buffers help but increase memory usage)
  - Batch size vs. proxy selection quality (larger batches provide better class coverage)
  - Proxy update frequency vs. stability (frequent updates may cause instability)

- Failure signatures:
  - Poor performance on new classes: Check if proxy selection is too restrictive
  - Poor performance on old classes: Check if gradient control is insufficient
  - Slow convergence: Check if proxy representation quality is adequate

- First 3 experiments:
  1. Test baseline performance without PCR on Split CIFAR10 with small buffer
  2. Implement basic PCR with proxy selection but without duplication
  3. Add duplication component and compare performance on Split CIFAR100
