# A System for Human-AI collaboration for Online Customer Support

## Quick Facts
- arXiv ID: 2301.12158
- Source URL: https://arxiv.org/abs/2301.12158
- Reference count: 10
- One-line primary result: AI-assisted FAQ retrieval system achieves MRR@10 of 0.42 for no-suggestion and 0.57 for FAQ-related utterances in German customer support

## Executive Summary
This paper presents a system for human-AI collaboration in online customer support, where an AI agent assists human agents by suggesting relevant FAQs from German customer service conversations. The system uses Dense Passage Retrieval (DPR) with fine-tuned German models to rank relevant FAQs for customer queries, achieving balanced performance between suggesting appropriate FAQs and remaining silent when no FAQ is relevant. Human evaluation showed the system was particularly helpful for less experienced agents, saving time and reducing cognitive load.

## Method Summary
The system uses German DPR models fine-tuned on a dataset of 6,219 utterances from 26 customer service conversations, annotated with FAQ IDs. The training process addresses class imbalance (79.1% no-suggestion utterances) through different calibration settings. The AI model concatenates 4 consecutive utterances as queries and FAQ question-answer pairs as context passages. The system displays top-2 FAQ suggestions with accuracy scores to human agents via a web interface, who can copy, discard, or request more information.

## Key Results
- MRR@10 scores of 0.42 for no-suggestion utterances and 0.57 for FAQ-related utterances on test set
- Deepset-German DPR models outperform baseline methods (dumb, random, BM25)
- Human agents found the system helpful, particularly for less experienced agents
- Agents indicated they would continue using the prototype and it saved time

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Class imbalance calibration through different mixture settings achieves balanced performance
- **Mechanism:** By experimenting with mean, highest-freq, sum, and original settings for class imbalance, the model learns appropriate silence when no FAQ is relevant while still suggesting relevant FAQs when needed. The sum setting produces the best balance.
- **Core assumption:** Explicit calibration is needed to prevent the model from always predicting silence due to class imbalance
- **Evidence anchors:** Abstract shows MRR@10 of 0.42 and 0.57; section describes sum setting as producing balanced performance
- **Break condition:** Improper calibration leads to either always predicting silence or always suggesting FAQs

### Mechanism 2
- **Claim:** German DPR models fine-tuned on domain data outperform baseline methods
- **Mechanism:** Deepset-german encoders, pre-trained on GermanQuAD and fine-tuned on internship-related data, achieve best performance due to language-specific understanding and domain knowledge
- **Core assumption:** Language-specific pre-training and domain fine-tuning are necessary for optimal performance
- **Evidence anchors:** Abstract mentions fine-tuned German DPR models; section states deepset-german models perform best
- **Break condition:** Performance degrades without proper German language models and domain fine-tuning

### Mechanism 3
- **Claim:** Human-AI collaboration improves efficiency for less experienced agents
- **Mechanism:** System provides relevant FAQ suggestions that agents can copy to chat or edit, reducing search time and cognitive load
- **Core assumption:** Human agents benefit from having relevant information readily available
- **Evidence anchors:** Abstract mentions helpfulness for less experienced agents; section reports agents would continue using it
- **Break condition:** System fails if suggestions are not sufficiently accurate or relevant

## Architecture Onboarding

- **Component map:** Customer Query -> DPR Model -> Top-2 FAQs -> Web Interface -> Agent Feedback
- **Critical path:** Customer query received → DPR model ranks relevant FAQs → Top 2 FAQs displayed with accuracy scores → Agent can copy, discard, or get more info → Agent sends response to customer
- **Design tradeoffs:** Display only 2 FAQs initially to avoid overwhelming agent vs showing more for better coverage; use accuracy scores to rank vs other relevance metrics; allow agent feedback but not immediate online learning during evaluation
- **Failure signatures:** High no-suggestion MRR but low FAQ-related MRR (model always predicts silence); low no-suggestion MRR (model suggests when none appropriate); consistently wrong FAQ suggestions (DPR not properly fine-tuned)
- **First 3 experiments:** Test baseline models (dumb, random, BM25) on test split; test different calibration settings with deepset-german models; conduct human evaluation with new agents

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can the system be improved to better handle the imbalance between no-suggestion and FAQ-related utterances?
- Basis in paper: 79.1% of utterances belong to no-suggestion class, leading to class imbalance issues
- Why unresolved: Paper experimented with different settings but did not find optimal solution; challenge of balancing performance between classes remains
- What evidence would resolve it: New methods to balance dataset or adjust training process, evaluated on MRR scores for both classes

### Open Question 2
- Question: How can the feedback function be improved to provide immediate learning for the AI agent?
- Basis in paper: Feedback function did not work as expected; agents expected immediate learning from feedback not implemented during evaluation
- Why unresolved: On-line learning from feedback not implemented, leaving potential benefits unexplored
- What evidence would resolve it: Implementing on-line learning mechanism that updates model based on real-time feedback, measuring impact on performance and user satisfaction

### Open Question 3
- Question: How can the system be scaled to handle a larger and more diverse dataset?
- Basis in paper: Intention to collect larger and more balanced dataset for future iterations
- Why unresolved: Current dataset limited in size and may not cover all possible customer queries, limiting generalizability
- What evidence would resolve it: Collecting and annotating larger dataset with more diverse conversations, evaluating AI agent performance on expanded dataset

## Limitations

- Evaluation metrics narrowly focused on MRR@10 without considering response quality, user satisfaction, or business impact
- Human evaluation limited to small sample size and short two-week evaluation period
- Claims about reducing cognitive load and saving time are qualitative without quantitative measurement

## Confidence

- **High confidence:** DPR-based approach outperforms baseline methods for German FAQ retrieval; MRR@10 scores clearly demonstrated and reproducible
- **Medium confidence:** System helpful for less experienced agents supported by human evaluation but limited sample size; class imbalance calibration mechanism theoretically sound but needs more ablation studies
- **Low confidence:** Claims about reducing cognitive load and saving time are qualitative, based on agent feedback rather than objective metrics

## Next Checks

1. **A/B testing with objective metrics:** Conduct controlled experiments comparing agent response times, resolution rates, and customer satisfaction scores between agents using the system versus those working independently

2. **Long-term adoption study:** Deploy the system for an extended period (minimum 3 months) with larger sample of agents to assess sustained usage patterns, learning curves, and potential fatigue or resistance factors

3. **Cross-lingual and cross-domain validation:** Test DPR fine-tuning approach on non-German datasets and different customer support domains to evaluate generalizability beyond internship-related context
