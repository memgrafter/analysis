# Chain-of-Skills: A Configurable Model for Open-domain Question Answering

## Quick Facts
- arXiv ID: 2305.03130
- Source URL: https://arxiv.org/abs/2305.03130
- Reference count: 33
- Modular dense retriever achieving SOTA retrieval performance across NQ, HotpotQA, and OTT-QA

## Executive Summary
Chain-of-Skills (COS) introduces a novel modular dense retriever for open-domain question answering that unifies five retrieval skills into a single multi-task model. Unlike previous dataset-specific approaches, COS can be configured for different query types and domains through its flexible skill combination mechanism. The model achieves state-of-the-art retrieval performance while demonstrating strong zero-shot and cross-dataset generalization capabilities, addressing the long-standing challenge of creating versatile ODQA systems that don't require task-specific retraining.

## Method Summary
COS implements a modular parameterization inspired by sparse Transformer architectures, where skill-specific attention heads are combined with shared model components to reduce task interference. The model incorporates five retrieval skills: single retrieval, expanded query retrieval, entity span proposal, entity linking, and reranking. Pretrained on Wikipedia using self-supervision, COS is then fine-tuned jointly on six ODQA datasets. The modular design allows dynamic configuration of skills based on query characteristics, enabling adaptation to diverse question types without requiring separate models for each task.

## Key Results
- Achieves state-of-the-art retrieval performance on NQ, HotpotQA, and OTT-QA
- Demonstrates significant gains in zero-shot and cross-dataset settings
- Outperforms specialized models when adapted to diverse query types and domains
- Shows strong generalization across multiple ODQA datasets through joint training

## Why This Works (Mechanism)
The modular parameterization effectively reduces task interference by isolating skill-specific transformations while maintaining shared representations for common features. This design allows each skill to develop specialized capabilities without degrading performance on other tasks, similar to how sparse Transformers use different attention patterns for different linguistic phenomena.

## Architecture Onboarding

**Component map**: Wikipedia pretraining -> Skill-specific attention heads + shared encoders -> Multi-task fine-tuning on 6 ODQA datasets -> Configurable skill deployment

**Critical path**: Input query → Skill selector → Skill-specific attention heads → Shared encoder → Retrieval module → Output ranked documents

**Design tradeoffs**: Modular parameterization vs. fully shared parameters (reduced interference vs. parameter efficiency), joint training vs. sequential training (better generalization vs. easier optimization)

**Failure signatures**: Skill interference when attention heads overlap excessively, catastrophic forgetting during multi-task training, configuration mismatch between query type and selected skills

**First experiments**: 1) Ablation study removing skill-specific attention heads to measure interference, 2) Zero-shot evaluation on unseen ODQA datasets, 3) Cross-dataset transfer learning with different skill configurations

## Open Questions the Paper Calls Out

The paper doesn't explicitly call out specific open questions, but several emerge from the limitations section including scalability to truly diverse domains beyond tested ODQA datasets and the effectiveness of the pretraining methodology for different retrieval tasks.

## Limitations

- Generalization claims limited to three ODQA datasets, uncertain performance on truly diverse domains
- Pretraining methodology effectiveness not fully validated across different ODQA retrieval tasks
- Specialized models may still outperform COS in fully supervised scenarios for specific tasks

## Confidence

- **High confidence**: Modular architecture design and practical implementation
- **Medium confidence**: Effectiveness of modular parameterization for reducing task interference
- **Medium confidence**: Pretraining methodology's contribution to downstream performance
- **Low confidence**: Scalability and generalization claims beyond tested ODQA datasets
