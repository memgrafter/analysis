# On Handling Catastrophic Forgetting for Incremental Learning of Human Physical Activity on the Edge

## Quick Facts
- arXiv ID: 2302.09310
- Source URL: https://arxiv.org/abs/2302.09310
- Reference count: 40
- Key outcome: PILOTE achieves over 93% accuracy with less than 200 exemplars per class while preventing catastrophic forgetting in incremental HAR learning on edge devices

## Executive Summary
This paper presents PILOTE, a method for incremental learning of human physical activities on edge devices that addresses catastrophic forgetting. The approach combines supervised contrastive loss and distillation loss within a Siamese network framework, enabling learning from extremely limited data while preserving knowledge of previously learned activities. PILOTE is designed specifically for edge deployment with minimal storage and computing resources, making it suitable for real-time activity recognition on mobile devices.

## Method Summary
PILOTE implements incremental learning for human activity recognition (HAR) on edge devices through a two-phase approach. First, a model is pre-trained on a rich dataset in the cloud using handcrafted statistical features extracted from sensor time series. When new activity classes need to be learned, PILOTE transfers a small support set of exemplars to the edge device and incrementally updates the model using a combined loss function. This loss includes a supervised contrastive component for learning from limited new-class samples and a distillation component that preserves the embedding space learned for existing classes, preventing catastrophic forgetting while maintaining computational efficiency suitable for edge deployment.

## Key Results
- PILOTE achieves over 93% accuracy on HAR tasks with less than 200 exemplars per class
- The method successfully prevents catastrophic forgetting during incremental learning
- Training completes in under 10 seconds on edge devices with minimal storage requirements

## Why This Works (Mechanism)

### Mechanism 1
- Claim: PILOTE prevents catastrophic forgetting by using distillation loss to constrain the embedding space during incremental learning.
- Mechanism: The distillation loss compares embeddings from the new model (Θ𝑛) with the pre-trained model (Θ𝑜) for old-class samples, ensuring that the new model does not deviate significantly from the learned boundaries. This preserves knowledge from previously learned activities while allowing new classes to be integrated.
- Core assumption: The embedding space learned by the pre-trained model captures meaningful and stable representations of old-class activities that should be preserved.
- Evidence anchors:
  - [abstract] "A jointly optimized Distillation Loss prevents the model from forgetting the previously learned knowledge by guiding the embedding space’s building."
  - [section] "we propose a distillation loss which is designed explicitly for conserving the learned knowledge from existing datasets via guiding the representation space’s building."
  - [corpus] Weak - No direct evidence in corpus about distillation loss effectiveness; corpus papers focus on other aspects of edge learning.
- Break condition: If the pre-trained embedding space is not representative or if the new data distribution is vastly different, the distillation loss may fail to preserve relevant knowledge.

### Mechanism 2
- Claim: PILOTE handles limited data by using a Siamese network with supervised contrastive loss to learn from few examples.
- Mechanism: The Siamese network learns a representation space where embeddings of the same class are close together and embeddings of different classes are far apart. The supervised contrastive loss optimizes this separation, allowing the model to learn effectively even with minimal new-class samples.
- Core assumption: The Siamese network architecture with contrastive learning can effectively separate classes in the embedding space with limited data.
- Evidence anchors:
  - [abstract] "The Siamese Network-based model [18] with supervised Contrastive Loss [16] allows learning from extremely limited data with class imbalance."
  - [section] "we adopt the concept of Few-shot Learning: a Siamese Network [18] is applied to learn a robust representation space, for which much less data is required."
  - [corpus] Weak - Corpus papers mention incremental learning but do not specifically discuss Siamese networks or contrastive loss for limited data.
- Break condition: If the new-class samples are too few or too noisy, the contrastive loss may not be able to establish clear boundaries between classes.

## Architecture Onboarding

- Component map:
  Data Preprocessing -> Feature Extraction -> Siamese Network -> Distillation Loss -> NCM Classifier -> Exemplar Management

- Critical path:
  1. Pre-train model on cloud with rich resources
  2. Select exemplars from old-class data and transfer to edge
  3. Collect new-class data on edge device
  4. Build embedding space incrementally using contrastive and distillation losses
  5. Update class prototypes and exemplars
  6. Perform classification using NCM classifier

- Design tradeoffs:
  - Handcrafted vs. learned features: Simplicity and efficiency vs. potentially higher accuracy
  - Contrastive vs. classification loss: Better handling of limited data vs. more complex training
  - Exemplar selection strategy: Representative exemplars vs. random exemplars for balancing accuracy and storage

- Failure signatures:
  - Accuracy drops on old classes after incremental learning (catastrophic forgetting)
  - Poor performance on new classes (insufficient learning from limited data)
  - High computational cost or memory usage (inefficient for edge deployment)

- First 3 experiments:
  1. Evaluate catastrophic forgetting: Train on old classes, incrementally learn new classes, and measure accuracy drop on old classes
  2. Test with limited data: Vary the number of new-class samples and measure performance to find the minimum required for good accuracy
  3. Assess edge efficiency: Measure memory usage and inference time on edge device with different exemplar set sizes

## Limitations
- Limited validation scope - performance tested only on five activity classes
- Potential overfitting to specific dataset characteristics and handcrafted features
- Reliance on idealized sensor conditions without addressing real-world noise or failures

## Confidence

- Catastrophic forgetting prevention: Medium-High confidence based on distillation loss design
- Learning from limited data: Medium confidence with >93% accuracy claim pending broader validation
- Edge efficiency: High confidence given lightweight architecture
