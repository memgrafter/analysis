# Distinguish Before Answer: Generating Contrastive Explanation as Knowledge for Commonsense Question Answering

## Quick Facts
- arXiv ID: 2305.08135
- Source URL: https://arxiv.org/abs/2305.08135
- Reference count: 29
- Key outcome: CPACE achieves 89.8% accuracy on CommonsenseQA, surpassing human performance

## Executive Summary
This paper addresses commonsense question answering by proposing a concept-centric prompt-based contrastive explanation generation model (CPACE) that converts symbolic knowledge into contrastive explanations to distinguish between answer candidates. The approach involves extracting concept-centric knowledge from external knowledge bases, generating contrastive explanations using a fine-tuned generative language model with concept and prompt guidance, and using these explanations to enhance downstream inference models. Experimental results show that CPACE achieves state-of-the-art performance on the CommonsenseQA dataset (89.8% accuracy, surpassing human performance) and demonstrates strong generalization on QASC and OBQA datasets with improvements of 4.2% and 3.5% respectively.

## Method Summary
The CPACE model follows a pipeline approach: first, it identifies key concepts from questions and answer candidates using a concept recognizer (RoBERTa-large with CRF layer); then extracts concept-centric symbolic knowledge from knowledge bases like ConceptNet and Cambridge Dictionary; next, it generates contrastive explanations using a fine-tuned BART-base model guided by concept information and explanation prompts; finally, these generated explanations are used to enhance downstream inference models (ALBERT-xxlarge-v2 or DeBERTaV3) for answer prediction. The model is trained on multiple datasets including CSQA for concept recognition, ECQA and eQASC for explanation generation, and evaluated on CSQA, QASC, and OBQA datasets.

## Key Results
- Achieves 89.8% accuracy on CommonsenseQA, surpassing human performance
- Shows strong generalization with 4.2% improvement on QASC and 3.5% improvement on OBQA
- Human evaluation scores: 0.87 relevance, 0.91 factual correctness, 0.92 distinguishing ability, 0.94 grammaticality

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Contrastive explanation generation converts symbolic knowledge into distinguishing information that directly aids candidate discrimination before prediction.
- Mechanism: The model retrieves concept-centric symbolic knowledge (triples and definitions), then uses a fine-tuned generative language model with concept and prompt guidance to generate contrastive explanations that explicitly highlight differences among answer candidates.
- Core assumption: Generated contrastive explanations provide more relevant and distinguishing information than raw symbolic knowledge for downstream inference models.
- Evidence anchors:
  - [abstract]: "convert obtained symbolic knowledge into a contrastive explanation for better distinguishing the differences among given candidates"
  - [section 3.2]: "we take the retrieved knowledge and a pre-defined explanation prompt as guidance for a fine-tuned generative pre-trained language model to generate contrastive explanation"
  - [corpus]: Weak evidence - no direct citations supporting this specific mechanism, though related works on contrastive explanation exist
- Break condition: If the generative model fails to capture relevant distinguishing features or produces generic explanations that don't help differentiate candidates.

### Mechanism 2
- Claim: Concept recognition ensures retrieved symbolic knowledge is more relevant to the specific question and candidates.
- Mechanism: A concept recognizer identifies key concepts from the question and candidates, which are then used as queries to extract concept-centric knowledge from knowledge bases like ConceptNet and Cambridge Dictionary.
- Core assumption: Concept-centric knowledge extraction produces more relevant and focused knowledge than generic knowledge retrieval methods.
- Evidence anchors:
  - [section 3.1.1]: "we employ a concept recognizer to detect the concepts from given question and candidates, which can ensure the retrieved symbolic knowledge is more concept-centric and relevant to the input"
  - [section 3.1.2]: "we use them as anchors to retrieve relevant external symbolic knowledge"
  - [corpus]: Moderate evidence - concept-centric approaches have shown promise in related NLP tasks
- Break condition: If concept recognition fails to identify the most relevant concepts or retrieves too narrow a set of knowledge.

### Mechanism 3
- Claim: Explanation prompt guidance improves the quality and distinguishing power of generated contrastive explanations.
- Mechanism: Pre-defined explanation prompts are used as constraints during generation to ensure the output provides distinguishing information among candidates rather than generic knowledge.
- Core assumption: Discrete explanation prompts can effectively guide the generative model to produce more useful contrastive explanations.
- Evidence anchors:
  - [section 3.2]: "Different from previous work (Paranjape et al., 2021) constructs Cloze prompt patterns for comparing the differences between two candidates, we consider whole contrastive explanation among all candidates and construct different discrete explanation prompts for guidance"
  - [section 3.2]: "we use a list of templates t1, ..., tp to generate a list of candidate explanations e1, ..., ep for each input during fine-tuning and select the best prompt for generation"
  - [corpus]: Weak evidence - prompt engineering for contrastive explanation is relatively new with limited published evidence
- Break condition: If prompts are too restrictive and limit the model's ability to generate useful explanations, or if they're too generic and don't provide meaningful guidance.

## Architecture Onboarding

- Component map:
  Concept Recognition Module → Symbolic Knowledge Acquisition → Contrastive Explanation Generation → Explanation Enhanced Inference
- Critical path:
  1. Identify concepts from question and candidates
  2. Extract relevant symbolic knowledge using identified concepts
  3. Generate contrastive explanations using fine-tuned generative model
  4. Use generated explanations to enhance downstream inference model
- Design tradeoffs:
  - Complexity vs. performance: Using multiple knowledge bases and complex generation vs. simpler retrieval methods
  - Generality vs. specificity: Concept-centric extraction ensures relevance but may miss some useful knowledge
  - Prompt design: More specific prompts may improve quality but reduce flexibility
- Failure signatures:
  - Poor concept recognition leading to irrelevant knowledge retrieval
  - Generated explanations that are too generic or don't distinguish candidates effectively
  - Downstream model not benefiting from generated explanations despite high-quality generation
- First 3 experiments:
  1. Test concept recognition accuracy on a sample of questions to ensure relevant concepts are being identified
  2. Evaluate symbolic knowledge extraction by checking if retrieved knowledge is relevant to identified concepts
  3. Test contrastive explanation generation quality by comparing generated explanations to ground truth explanations on a validation set
