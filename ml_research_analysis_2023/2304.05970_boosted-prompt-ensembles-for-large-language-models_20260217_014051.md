# Boosted Prompt Ensembles for Large Language Models

## Quick Facts
- arXiv ID: 2304.05970
- Source URL: https://arxiv.org/abs/2304.05970
- Reference count: 40
- Key outcome: Boosted prompting improves few-shot language model performance by iteratively constructing a set of prompts that cover different regions of the problem space.

## Executive Summary
Boosted Prompt Ensembles is a method that improves few-shot language model performance by iteratively constructing an ensemble of prompts. At each step, "hard" examples are selected where the current ensemble is uncertain, and new prompts are generated from these examples to expand coverage. The method outperforms single-prompt and bagged ensembles on datasets like GSM8k and AQuA, especially when the initial prompt is suboptimal. Train-time boosting uses a small labeled dataset, while test-time boosting adapts to problem distribution shifts by leveraging model-generated predictions.

## Method Summary
The method adapts classical boosting to the prompt-based LLM setting, iteratively constructing an ensemble of prompts that cover different regions of the problem space. At each boosting iteration, the current ensemble identifies examples where predictions disagree (uncertainty), indicating these are "hard" examples. These examples are used to form a new prompt, expanding the ensemble's coverage of the problem space. The new prompt is chosen to generalize to regions where the previous ensemble performed poorly. The algorithm consists of an LLM, an initial prompt, a problem set, and functions for generating new prompts and making predictions. The core loop iteratively generates predictions, selects "hard" examples, and creates new prompts.

## Key Results
- Boosted prompting outperforms single-prompt and bagged ensembles on mathematical reasoning datasets
- Test-time boosting effectively adapts to distribution shifts by leveraging model-generated predictions
- Performance gains are most pronounced when the initial prompt is suboptimal

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Iterative selection of "hard" examples improves ensemble coverage of the problem space.
- Mechanism: At each boosting iteration, the current ensemble identifies examples where predictions disagree (uncertainty). These "hard" examples are used to form a new prompt, expanding the ensemble's coverage of the problem space.
- Core assumption: Disagreement among ensemble members indicates example informativeness for expanding coverage.
- Evidence anchors:
  - [abstract] "few shot examples for each prompt are chosen in a stepwise fashion to be 'hard' examples on which the previous step's ensemble is uncertain"
  - [section 3] "As a proxy for informativeness, we propose to use the agreement between several solutions sampled from the model."

### Mechanism 2
- Claim: Test-time adaptation allows the ensemble to adjust to distribution shifts.
- Mechanism: When no training labels are available, the algorithm uses model predictions with "sufficient agreement" as pseudo-labels.
- Core assumption: Model predictions with sufficient agreement are likely correct and can serve as pseudo-labels for adaptation.
- Evidence anchors:
  - [abstract] "test-time boosting adapts to problem distribution shifts by leveraging model-generated predictions"
  - [section 3] "In the absence of training labels, our algorithm can be adapted to the transductive...setting."

### Mechanism 3
- Claim: Choosing complex chain-of-thoughts improves performance.
- Mechanism: When forming boosted prompts, the algorithm selects the chain-of-thought from among the 5 most complex generated chains that led to the correct answer.
- Core assumption: More complex reasoning paths are more informative for improving performance.
- Evidence anchors:
  - [section 3] "Following Fu et al. (2022)'s discovery that longer reasoning paths improve in-context reasoning performance"
  - [section 4] "Table 5 suggest that this choice improves performance"

## Architecture Onboarding

- Component map: LLM -> Initial prompt -> Problem set -> Prediction generation -> Hard example selection -> New prompt creation -> Ensemble update
- Critical path: The main loop: generate predictions → identify hard examples → create new prompt → update ensemble → repeat. Each iteration depends on the previous one's predictions and prompt coverage.
- Design tradeoffs: More ensemble members and samples per member improve performance but increase computational cost. Higher agreement thresholds for pseudo-labels improve accuracy but may limit adaptation.
- Failure signatures: If prompts don't cover the problem space, performance plateaus. If agreement doesn't correlate with correctness, test-time boosting fails. If the initial prompt is too poor, the ensemble may never recover.
- First 3 experiments:
  1. Verify that disagreement correlates with example difficulty on a small labeled dataset
  2. Test whether adding prompts with complex chains improves performance on a simple task
  3. Compare train-time vs test-time boosting on a dataset with known distribution shift

## Limitations
- Effectiveness critically depends on assumptions about disagreement indicating difficulty and pseudo-label quality
- Performance gains may not justify computational overhead for some applications
- Method has only been validated on mathematical and algebraic reasoning tasks

## Confidence
**High Confidence**: The core algorithmic framework and its ability to improve over single-prompt approaches is well-supported.

**Medium Confidence**: The claim that test-time boosting effectively adapts to distribution shifts is supported but relies on assumptions about pseudo-label quality.

**Low Confidence**: The assertion that selecting more complex reasoning paths consistently improves performance lacks strong empirical support.

## Next Checks
1. **Agreement Quality Validation**: Conduct controlled experiments to measure the correlation between ensemble disagreement and actual example difficulty across different problem types, and quantify the accuracy of pseudo-labels generated from agreement-based selection.

2. **Complexity Heuristic Robustness**: Systematically vary the complexity threshold for selecting reasoning paths and measure the trade-off between reasoning length and solution quality to identify when the complexity heuristic breaks down.

3. **Initial Prompt Sensitivity Analysis**: Perform ablation studies varying the quality of the initial prompt to determine the minimum performance threshold required for boosted prompting to be effective, and identify the point at which poor initial prompts prevent recovery.
