# What Are Effective Labels for Augmented Data? Improving Calibration and Robustness with AutoLabel

## Executive Summary
This paper introduces AutoLabel, a novel approach to automatically learn label confidence for augmented data based on transformation distance from clean data. The method builds upon label smoothing and adjusts label confidence dynamically using calibration performance on a hold-out validation set. Experiments demonstrate that AutoLabel significantly improves model calibration and accuracy when used with popular data augmentation techniques like RandAug, AugMix, and adversarial training, particularly under distributional shift conditions.

## Method Summary
AutoLabel automatically learns label confidence for augmented data by measuring the transformation distance from clean data and adjusting labels accordingly. The method discretizes transformation distances into buckets and updates label confidence using a step size parameter α based on calibration performance metrics. AutoLabel can be applied to various data augmentation techniques including RandAug, AugMix, and adversarial training. The approach treats adversarial examples as a special case of data augmentation, differentiating them based on perturbation magnitude. The method maintains or improves accuracy while significantly enhancing calibration, especially under distributional shift.

## Key Results
- AutoLabel reduces calibration error by 30-60% on corrupted datasets compared to one-hot labels
- The method successfully improves calibration and accuracy for RandAug, AugMix, and adversarial training
- AutoLabel helps balance the trade-off between clean accuracy and adversarial robustness

## Why This Works (Mechanism)

### Mechanism 1
- Claim: AutoLabel improves calibration by dynamically adjusting label confidence based on transformation distance from clean data.
- Mechanism: AutoLabel assigns lower confidence to labels of augmented data that are far from the clean distribution, reducing overconfidence on distorted inputs. This is achieved by updating label smoothing parameters using calibration performance on a hold-out validation set.
- Core assumption: The transformation distance between augmented data and clean data is a reliable proxy for label uncertainty.
- Evidence anchors:
  - [abstract] "AutoLabel builds upon label smoothing and adjusts label confidence based on calibration performance on a hold-out validation set."
  - [section] "The key insight is that the confidence in the labels associated with the augmented data likely depends on how distorted the transformation is."
- Break condition: If the transformation distance metric fails to correlate with human-perceived label ambiguity, AutoLabel's confidence adjustments will be ineffective.

### Mechanism 2
- Claim: AutoLabel balances the trade-off between clean accuracy and adversarial robustness by treating adversarial examples as a special case of data augmentation.
- Mechanism: AutoLabel differentiates adversarial examples based on their ℓ∞ norm (perturbation magnitude) and assigns lower confidence to highly perturbed examples. This prevents the model from overfitting to adversarial noise while maintaining robustness.
- Core assumption: The ℓ∞ norm of adversarial perturbations is a valid measure of how far the adversarial example is from the clean data manifold.
- Evidence anchors:
  - [section] "AutoLabel differentiates the adversarial examples according to the distance between the adversarial examples and clean data, which is approximately captured by the ℓ∞ norm of the adversarial perturbation ϵ."
  - [section] "AutoLabel nicely addresses this problem: it improves calibration on both clean and corrupted datasets compared to vanilla model and adversarial training."
- Break condition: If adversarial examples have non-local effects that are not captured by ℓ∞ norm, AutoLabel's distance-based labeling will be suboptimal.

### Mechanism 3
- Claim: AutoLabel is complementary to existing data augmentation techniques, improving their effectiveness without requiring architectural changes.
- Mechanism: AutoLabel can be applied as a wrapper around any data augmentation method (RandAug, AugMix, adversarial training) by adjusting the labels of augmented data based on their transformation distance. This improves calibration and robustness while maintaining or improving accuracy.
- Core assumption: Existing data augmentation techniques generate transformations that can be meaningfully ordered by distance from clean data.
- Evidence anchors:
  - [abstract] "We successfully apply AutoLabel to three different data augmentation techniques: the state-of-the-art RandAug, AugMix, and adversarial training."
  - [section] "AutoLabel can easily slot into existing data augmentation methods, we show how to apply AutoLabel to automatically adjust the confidence in labels over different data augmentation methods."
- Break condition: If the augmentation method produces transformations that are not monotonic in their distance from clean data, AutoLabel's distance-based labeling will be ineffective.

## Architecture Onboarding

- Component map:
  - Data augmentation pipeline (RandAug, AugMix, or adversarial training) -> Transformation distance calculator (based on augmentation type and parameters) -> Validation set calibration module (computes ECE, accuracy, and confidence) -> Label update module (adjusts label confidence using Eqn 1 and 2) -> Training loop integration (applies updated labels during model training)

- Critical path:
  1. Generate augmented data using chosen augmentation method
  2. Compute transformation distance for each augmented example
  3. Construct augmented validation set with same transformation distance
  4. Calculate ECE, accuracy, and confidence on augmented validation set
  5. Update label confidence using Eqn 1 (based on calibration feedback)
  6. Apply updated labels during training with cross-entropy loss

- Design tradeoffs:
  - AutoLabel adds computational overhead for validation set augmentation and calibration computation
  - The choice of distance buckets affects granularity of label adjustments
  - Hyperparameter α controls step size of label updates and requires tuning

- Failure signatures:
  - If AutoLabel causes accuracy to drop significantly, the distance metric may be poorly calibrated
  - If calibration doesn't improve, the validation set may be too small or not representative
  - If the model becomes under-confident, α may be too large or distance buckets too coarse

- First 3 experiments:
  1. Apply AutoLabel to RandAug with CIFAR-10 and measure ECE improvement vs baseline
  2. Apply AutoLabel to AugMix with varying depth parameters and measure calibration under distributional shift
  3. Apply AutoLabel to adversarial training with different perturbation magnitudes and measure trade-off between clean and adversarial accuracy

## Limitations
- AutoLabel's effectiveness may be limited by the quality of the transformation distance metric used to measure how far augmented data is from clean data
- The method requires a hold-out validation set for calibration, which may not always be available or representative
- The hyperparameters (number of distance buckets, step size α) need careful tuning for optimal performance across different datasets and augmentation methods

## Confidence
- **High Confidence**: AutoLabel's general framework of adjusting label confidence based on transformation distance is well-supported by theoretical reasoning and experimental results on image datasets.
- **Medium Confidence**: The specific distance metrics (ℓ∞ norm for adversarial examples, augmentation-specific distances) are reasonable choices but may not be optimal for all scenarios.
- **Low Confidence**: Claims about AutoLabel's effectiveness on extreme distributional shifts or in multi-modal settings are not sufficiently supported by the presented experiments.
