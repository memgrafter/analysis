# LARG, Language-based Automatic Reward and Goal Generation

## Quick Facts
- arXiv ID: 2306.10985
- Source URL: https://arxiv.org/abs/2306.10985
- Reference count: 40
- Primary result: LLM-based automatic generation of reward functions and goal positions from text descriptions for GCRL and MTRL manipulation tasks

## Executive Summary
LARG2 introduces a novel approach for automatically generating reward functions and goal positions from text descriptions using Large Language Models. The method leverages LLM code generation capabilities to parse natural language task descriptions and produce executable Python functions for both Goal-Conditioned Reinforcement Learning (GCRL) and Multi-Task Reinforcement Learning (MTRL) settings. By automating the traditionally manual process of reward function design, LARG2 enables scalable training of RL agents across diverse manipulation tasks while achieving high compliance rates with task descriptions.

## Method Summary
LARG2 uses LLMs (specifically gpt-3.5-turbo) with in-context prompting to generate executable code for goals (GCRL) or reward functions (MTRL) from text descriptions of tabletop manipulation tasks. The approach involves prompt generation with environment and task descriptions, code generation via the LLM, validation through automatic execution-based error correction, and functional testing. For scalability, LARG2 employs LLM-based paraphrasing to generate multiple variants of base task descriptions, enabling diverse training data without manual reward engineering. The generated code is validated through iterative correction loops that catch Python exceptions and prompt for refinements until syntactically and functionally correct.

## Key Results
- Achieves 87.5% compliance for goal position generation aligned with task descriptions in GCRL setting
- Successfully trains policies conditioned on text inputs using automatically generated reward functions in MTRL setting
- Demonstrates scalability through LLM-based paraphrasing to generate semantically equivalent task variants

## Architecture Onboarding

- Component map: Text Description → Prompt Generation → Code Generation → Code Validation → Functional Testing → Policy Training
- Critical path: Text Description → Prompt Generation → Code Generation → Code Validation → Functional Testing → Policy Training
- Design tradeoffs:
  - Flexibility vs. Reliability: Allowing LLMs to generate full reward functions provides flexibility but may reduce reliability compared to generating only task-dependent components.
  - Automation vs. Control: Full automation enables scalability but may require more iterations for error correction compared to guided generation.
- Failure signatures:
  - Code generation errors: Syntax errors, undefined variables, incorrect function signatures
  - Semantic errors: Generated functions produce incorrect rewards/goals despite valid syntax
  - Auto-correction failure: LLM fails to correct errors after multiple iterations
  - Functional test failures: Generated functions fail tests despite passing syntax and execution checks
- First 3 experiments:
  1. Generate a goal function for a simple "move cube to corner" task and validate it produces correct goal positions
  2. Generate a reward function for a "lift cube" task and validate it produces appropriate reward signals
  3. Use LLM paraphrasing to generate multiple variants of a base task and verify generated rewards are semantically equivalent but syntactically distinct

## Limitations
- The approach's effectiveness heavily depends on LLM capabilities and prompt design quality, which may not generalize well beyond the tested manipulation domain
- Auto-correction loop may fail to converge for complex tasks or when semantically incorrect but syntactically valid code is generated
- Significant API calls and computation required for code validation could limit practical scalability
