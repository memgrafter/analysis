# Breeding Machine Translations: Evolutionary approach to survive and thrive in the world of automated evaluation

## Quick Facts
- arXiv ID: 2305.19330
- Source URL: https://arxiv.org/abs/2305.19330
- Reference count: 40
- We propose using genetic algorithms (GA) to improve machine translation (MT) by modifying n-best lists produced by MT systems

## Executive Summary
This paper introduces a novel approach to improving machine translation quality using genetic algorithms applied to n-best lists. The method optimizes translations toward arbitrary MT metrics through common GA operations like mutation and crossover. The work demonstrates that combining multiple MT metrics as fitness functions yields improved translation quality, while also revealing weaknesses in individual metrics through adversarial example generation. The approach serves dual purposes: enhancing translation quality and analyzing the robustness of MT evaluation metrics.

## Method Summary
The paper proposes using genetic algorithms to improve machine translation by optimizing n-best lists generated by MT systems. The GA approach modifies these lists using standard operations like mutation and crossover, with the goal of maximizing an arbitrary MT metric as the fitness function. The method can work with either single metrics or combinations of multiple metrics. When multiple metrics are combined, the resulting translations show improved quality as measured by held-out metrics. The same approach can also be used to generate adversarial examples by optimizing for specific metrics, revealing blind spots and weaknesses in evaluation methods.

## Key Results
- GA-optimized translations combining multiple metrics achieve improved quality as measured by held-out metrics
- Single-metric optimization can reveal blind spots and flaws in evaluation metrics
- Reference-free COMET is substantially less robust than reference-based COMET when subjected to adversarial examples

## Why This Works (Mechanism)
The genetic algorithm approach works by treating translation candidates as evolving populations where fitter candidates (those scoring higher on chosen metrics) are more likely to survive and reproduce. Through iterative mutation and crossover operations on n-best lists, the algorithm explores the space of possible translations more effectively than greedy optimization approaches. The method can escape local optima by maintaining diversity in the population and exploring multiple translation hypotheses simultaneously. When combining multiple metrics, the GA balances different evaluation criteria to find translations that perform well across multiple dimensions rather than optimizing for a single potentially narrow metric.

## Foundational Learning
- Genetic Algorithms: Evolutionary optimization methods inspired by natural selection; needed for systematic exploration of translation space; quick check: understand selection, crossover, and mutation operations
- N-best Lists: Ranked lists of translation hypotheses from MT systems; provide the initial population for GA optimization; quick check: verify n-best lists contain diverse yet plausible translations
- MT Evaluation Metrics: Automated methods for scoring translation quality; serve as fitness functions for GA; quick check: understand reference-based vs reference-free metrics
- Adversarial Examples: Inputs designed to fool evaluation systems; reveal metric weaknesses; quick check: recognize how optimization can expose metric blind spots

## Architecture Onboarding

Component Map: MT System -> N-best List Generator -> Genetic Algorithm -> Optimized Translations -> Evaluation Metrics

Critical Path: The core workflow involves generating n-best lists from MT systems, applying genetic algorithm operations (selection, crossover, mutation) iteratively, and evaluating the evolved translations against target metrics. The fitness function evaluation is the critical computational bottleneck.

Design Tradeoffs: The approach balances exploration vs exploitation through GA parameters. Using multiple metrics as fitness functions trades single-metric optimization purity for robustness. The n-best list size affects both computational cost and solution quality.

Failure Signatures: Poor results may indicate inadequate n-best list diversity, inappropriate GA parameters (mutation rate too high/low), or metric choices that don't align with human judgment. The method may also get stuck in local optima if population diversity isn't maintained.

First Experiments: 1) Run GA optimization on a small n-best list with a single metric to verify basic functionality. 2) Test multiple mutation and crossover rates to find optimal parameters. 3) Compare results using reference-based vs reference-free metrics on the same dataset.

## Limitations
- Limited exploration of which metric combinations work best or why
- Analysis focused primarily on COMET metric without broader investigation of other metrics' vulnerabilities
- Does not conduct human evaluation studies to confirm automated metric improvements reflect genuine translation quality gains

## Confidence
- High confidence: The core methodology of using GA to optimize n-best lists is sound and the implementation details are clear
- Medium confidence: The claim about improved translation quality when combining metrics, though results show promise
- Medium confidence: The adversarial example generation demonstrates metric weaknesses, but the generalizability to other metrics needs more exploration

## Next Checks
1. Test the GA approach with additional MT metrics beyond COMET to verify the robustness analysis applies more broadly
2. Conduct human evaluation studies to confirm that GA-optimized translations are genuinely better, not just higher-scoring by automated metrics
3. Experiment with different GA parameters (population size, mutation rates, crossover methods) to identify optimal configurations for various language pairs and domains
