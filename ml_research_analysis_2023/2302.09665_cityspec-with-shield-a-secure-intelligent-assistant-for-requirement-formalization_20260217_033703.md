# CitySpec with Shield: A Secure Intelligent Assistant for Requirement Formalization

## Quick Facts
- arXiv ID: 2302.09665
- Source URL: https://arxiv.org/abs/2302.09665
- Reference count: 40
- Key outcome: CitySpec increases sentence-level accuracy from 59.02% to 86.64% and achieves 100% defense against certain adversarial attacks

## Executive Summary
CitySpec addresses the challenge of converting ambiguous, incomplete English city requirements into machine-readable formal specifications for smart city monitoring systems. It introduces an intelligent assistant system that extracts city-specific knowledge, synthesizes requirements to enhance learning, and employs online validation with a shield model to ensure security. The system demonstrates significant improvements in translation accuracy and robust protection against adversarial attacks while adapting effectively to new cities and domains.

## Method Summary
CitySpec is an intelligent assistant that translates natural language city requirements into formal specifications using a sequence labeling approach enhanced with city-specific knowledge. The system extracts 3,061 domain-specific words across five categories and uses them to synthesize new training requirements, enriching the model's vocabulary. It implements a two-stage online learning process with a Bayesian CNN validation module to ensure new knowledge is legitimate before integration. A two-layer shield model provides protection against textual adversarial attacks through literal correction and inferential mapping filters.

## Key Results
- Translation accuracy improves from 59.02% to 86.64% sentence-level accuracy
- F1 scores improve significantly across multiple cities, e.g., from 77.6% to 93.75% for Seattle
- Shield model reduces adversarial attack success rates to 0% for certain attacks like DeepWordBug

## Why This Works (Mechanism)

### Mechanism 1
- Claim: CitySpec improves translation accuracy by injecting synthesized city-specific vocabulary into the model.
- Mechanism: The system extracts 3,061 domain-specific words across 5 categories (entity, quantifier, location, time, condition) and uses them to synthesize new training requirements, enriching the model's vocabulary beyond the limited real-world dataset.
- Core assumption: Synthetic requirements generated from city knowledge capture the same semantic patterns as real requirements, allowing the model to generalize better to unseen city requirements.
- Evidence anchors: [abstract] "We extract city-specific knowledge and build a dataset of city vocabulary with 3,061 words in 5 categories." [section 4.3] "We extract city knowledge and build two knowledge datasets, i.e., a vocabulary set and a pattern set."
- Break condition: If the synthesized requirements don't reflect real-world usage patterns, the model may overfit to artificial patterns that don't generalize to actual city requirements.

### Mechanism 2
- Claim: CitySpec achieves robust online learning by validating new knowledge before permanent integration.
- Mechanism: The system implements a two-stage learning process where new terms are first temporarily stored, then validated through a Bayesian CNN model with uncertainty estimation before being permanently incorporated into the model.
- Core assumption: The validation model can accurately distinguish between legitimate new city knowledge and adversarial inputs with high confidence.
- Evidence anchors: [section 4.5] "To keep CitySpec away from the adversarial inputs, we develop a Bayesian CNN-based validation module in CitySpec." [section 5.3] "The accuracy of validation model is very high. When the uncertainty threshold is set to 0.5, CitySpec gives 100% success rate against scenario I among 2,000 malicious inputs."
- Break condition: If the validation model's uncertainty estimation is poorly calibrated, it may either reject legitimate new knowledge or accept adversarial inputs.

### Mechanism 3
- Claim: CitySpec protects against textual adversarial attacks through a two-layer shield model.
- Mechanism: The shield model combines literal correction (detecting character-level manipulations) with inferential mapping (detecting semantic shifts through embedding analysis) to filter out malicious inputs before they reach the validation function.
- Core assumption: Adversarial attacks must manipulate text in detectable ways, either through character-level changes or semantic shifts that can be captured by embedding distance analysis.
- Evidence anchors: [abstract] "After the enhancement from the shield function, CitySpec is now immune to most known textual adversarial inputs (e.g., the attack success rate of DeepWordBug after the shield function is reduced to 0% from 82.73%)." [section 4.7] "We develop a literal correction filter to detect and leave out any literal disinformation provided in the input tokens."
- Break condition: If attackers develop attacks that don't involve detectable text manipulation (e.g., context-aware attacks that maintain semantic similarity), the shield model may fail to detect them.

## Architecture Onboarding

- Component map: User input → translation model → shield model → validation model → online learning cache → final formal specification output
- Critical path: User input → translation model → shield model → validation model → online learning cache → final formal specification output
- Design tradeoffs: The system trades off between strict validation (rejecting potentially valid inputs) and security (accepting adversarial inputs). The two-layer shield model balances these concerns by first applying literal correction (strict) then inferential mapping (more lenient).
- Failure signatures: High false rejection rate indicates overly strict validation; high false acceptance rate indicates insufficient defense; poor accuracy indicates inadequate knowledge injection or model architecture issues.
- First 3 experiments:
  1. Test translation accuracy on a small set of real requirements without any city knowledge injection to establish baseline performance.
  2. Test the shield model's ability to detect a simple character-level attack (e.g., replacing 'o' with '0') on valid inputs.
  3. Test the online learning mechanism by introducing a new city-specific term and verifying it gets correctly classified after validation.

## Limitations
- Evaluation focuses primarily on a specific set of cities (Seattle, Chicago, New York) and domains (transportation, energy, public safety), limiting generalizability
- Shield model's effectiveness against more sophisticated adversarial attacks beyond tested DeepWordBug and character-level manipulations remains unverified
- Requirement synthesis approach depends heavily on the quality and coverage of extracted city knowledge, which may not scale well to cities with limited documentation

## Confidence
- **High Confidence:** The translation accuracy improvements (59.02% to 86.64%) are well-supported by systematic evaluation across multiple cities and domains with clear metrics
- **Medium Confidence:** The online learning mechanism's effectiveness is demonstrated but relies on assumptions about the validation model's uncertainty quantification that aren't fully explored
- **Low Confidence:** The shield model's comprehensive security claims (100% success against certain attacks) need validation against a broader range of attack types and real-world adversarial scenarios
