# OccRob: Efficient SMT-Based Occlusion Robustness Verification of Deep Neural Networks

## Quick Facts
- **arXiv ID**: 2301.11912
- **Source URL**: https://arxiv.org/abs/2301.11912
- **Reference count**: 40
- **Primary result**: Proposed OccRob approach encodes occlusions as neural network layers, achieving up to 30x speedup over naive SMT encoding for verifying DNN occlusion robustness.

## Executive Summary
This paper introduces OccRob, a novel approach for verifying occlusion robustness of deep neural networks using SMT-based techniques. The key innovation is encoding occlusions as neural network layers rather than constraints, allowing existing DNN verification tools to be leveraged efficiently. Two acceleration techniques - input-space splitting and label sorting - are introduced to further improve performance. Experiments demonstrate OccRob's effectiveness on benchmark datasets with various occlusion types and sizes, significantly outperforming naive SMT encoding while scaling to large networks.

## Method Summary
OccRob encodes occlusions as a neural network (ONN) that is concatenated with the original DNN, transforming the occlusion robustness problem into a standard DNN verification problem solvable by existing SMT-based verifiers like Marabou. The ONN construction handles both integer and real-number occlusion positions through interpolation. To improve efficiency, the method employs input-space splitting to divide the occlusion position space into smaller sub-problems and label sorting to prioritize verification queries based on misclassification probability. The approach is theoretically sound and complete, providing definite verification results and generating counterexamples when DNNs are not robust.

## Key Results
- OccRob achieves up to 30x speedup compared to naive SMT encoding on MNIST and GTSRB benchmarks
- The method successfully verifies robustness against various occlusion types (size, position, color) and generates occlusive adversarial examples
- OccRob scales to large networks with hundreds of ReLU activation functions while maintaining efficiency
- Input-space splitting and label sorting significantly accelerate verification, especially for non-robust cases

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Encoding occlusions as neural network layers enables existing SMT solvers to efficiently verify robustness by reducing the problem to standard neural network verification.
- **Mechanism**: Instead of encoding occlusion perturbations as constraints in the SMT formula (which introduces many ReLU activation functions and large search spaces), the approach constructs an "occlusion neural network" (ONN) that directly models all possible occluded images. This ONN is then concatenated to the original network, creating a new network whose verification can be handled by existing SMT-based verifiers like Marabou. This reduces the number of constraints and leverages the verifier's optimizations against network structure.
- **Core assumption**: The constructed ONN accurately represents all possible occluded images of the input, and the concatenation with the original network preserves the semantic relationship between occlusion and classification.
- **Evidence anchors**: [abstract] "devise a novel approach for encoding occlusions as a part of neural networks"; [section 4.2] "construct a neural network O : R4+ct→ Rm×n to encode all the possible occluded images of x"

### Mechanism 2
- **Claim**: Splitting the occlusion space into smaller, orthogonal sub-spaces significantly improves verification efficiency by reducing the search space for each verification query.
- **Mechanism**: The occlusion space (defined by position coordinates) is divided into intervals along both dimensions. Each sub-space represents a subset of possible occlusion positions. The verification problem is then solved independently on each sub-space. This reduces the number of pivot operations in the underlying Simplex method used by SMT solvers, as each sub-problem has fewer constraints and variables.
- **Core assumption**: The occlusion robustness property is monotonic with respect to occlusion position - if the network is robust on all sub-spaces, it is robust on the entire space. Also, solving smaller independent problems is more efficient than solving one large problem.
- **Evidence anchors**: [section 4.4] "we can divide [1, m] (resp. [1, n]) into km∈ Z+ (resp. kn∈ Z+) intervals"; [section 4.4] "This is equivalent to proving ∀x′∈ X.Φ(x′) for all X(i, j) with 0≤ i < km and 0≤ j < kn"

### Mechanism 3
- **Claim**: Sorting labels by their probability of being misclassified (eager falsification) allows the verifier to find counterexamples faster in non-robust cases, terminating verification early.
- **Mechanism**: For each query, labels are sorted in descending order of the probability that the original image is classified to that label. Queries are dispatched to the backend verifier in this order. If a counterexample is found (i.e., the network misclassifies to that label under some occlusion), verification terminates immediately without checking remaining labels.
- **Core assumption**: Labels with higher classification probabilities are more likely to be the target of misclassification under occlusion perturbations. This heuristic effectively prioritizes the most probable failure modes.
- **Evidence anchors**: [section 4.4] "we sort the sub-problems in a descent order according to the probabilities at which the original image is classified to the corresponding labels"; [section 4.4] "Whenever a counterexample is returned, an occluded image is found such that its classiﬁcation result diﬀers from the original one"

## Architecture Onboarding

- **Component map**: Input image -> Occlusion Neural Network (ONN) construction -> Network concatenation -> Occlusion space splitting -> Label sorting -> Parallel verification queries -> Result aggregation
- **Critical path**: Input image → ONN construction → Network concatenation → Occlusion space splitting → Label sorting → Parallel verification queries → Result aggregation
- **Design tradeoffs**: 
  - ONN complexity vs. verification efficiency: More complex ONN encoding provides more accurate occlusion modeling but may increase verification time
  - Space splitting granularity vs. overhead: Finer splitting reduces per-query complexity but increases total number of queries
  - Label sorting heuristic vs. actual failure modes: The probability-based heuristic may not always prioritize the most likely counterexamples
- **Failure signatures**:
  - Verification timeouts: May indicate need for finer occlusion space splitting or better hardware
  - Incorrect counterexamples: Suggests errors in ONN construction or interpolation logic
  - False positives/negatives: Could indicate issues with the encoding correctness proof or solver limitations
- **First 3 experiments**:
  1. Verify a small FNN (70 ReLUs) on MNIST with a 1×1 uniform occlusion using OccRob, comparing runtime to naive SMT encoding
  2. Test occlusion space splitting by verifying the same network with and without splitting, measuring speedup
  3. Evaluate label sorting by running verification with and without sorting on a known non-robust case, measuring time to first counterexample

## Limitations

- **Encoding complexity**: The ONN construction is complex and requires precise implementation of weight matrices and interpolation logic, which are not fully detailed in the paper
- **Scalability limits**: While OccRob scales better than naive encoding, verification timeouts still occur for large networks and complex occlusions, suggesting practical limits
- **Architecture restrictions**: The method is currently evaluated only on fully connected networks with ReLU activations, with generalization to CNNs and RNNs unverified

## Confidence

- **High confidence**: The core mechanism of encoding occlusions as neural network layers and leveraging existing SMT solvers is well-founded and supported by formal proofs and experimental results
- **Medium confidence**: The acceleration techniques (input-space splitting and label sorting) show significant speedups in experiments, but their effectiveness may depend heavily on the specific dataset and network architecture
- **Medium confidence**: The completeness of verification across all occlusion positions and sizes is theoretically guaranteed, but practical limitations (timeouts, solver heuristics) may affect real-world applicability
