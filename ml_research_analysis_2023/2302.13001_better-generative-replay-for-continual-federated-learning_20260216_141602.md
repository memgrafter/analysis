# Better Generative Replay for Continual Federated Learning

## Quick Facts
- arXiv ID: 2302.13001
- Source URL: https://arxiv.org/abs/2302.13001
- Reference count: 24
- Primary result: FedCIL achieves up to 99.13% accuracy on MNIST and 45.27% on CIFAR-10, outperforming baselines like FedAvg and FedLwF-2T in continual federated learning with non-IID data.

## Executive Summary
This paper addresses continual federated learning where clients incrementally learn new tasks without storing past data. The proposed FedCIL framework combines generative replay (using ACGAN) with model consolidation on the server side and consistency enforcement on the client side. These mechanisms address the challenges of catastrophic forgetting and unstable training that arise when applying generative replay to non-IID federated settings. Experiments on MNIST, EMNIST, and CIFAR-10 demonstrate significant performance improvements over standard federated learning and continual learning baselines.

## Method Summary
FedCIL integrates generative replay into federated learning by having each client maintain local ACGAN models while the server performs model consolidation using synthetic data from all clients. The framework includes model consolidation on the server (aggregating client models and training on balanced synthetic data) and consistency enforcement on clients (aligning features and logits across different model states). This approach enables clients to learn new tasks sequentially without forgetting previous tasks, even when raw data cannot be stored and data distributions are non-IID across clients.

## Key Results
- FedCIL achieves 99.13% accuracy on MNIST compared to 87.22% for FedAvg + ACGAN
- On CIFAR-10, FedCIL reaches 45.27% accuracy versus 33.51% for FedLwF-2T
- FedCIL shows superior performance on EMNIST Letters (89.12%) and Balanced (84.63%) datasets
- The method effectively prevents catastrophic forgetting while maintaining high classification accuracy across all tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Model consolidation on the server side stabilizes the global model by training it on synthetic data generated from all client generators, which prevents the global model from being biased toward frequent classes.
- Mechanism: After receiving client models, the server generates balanced synthetic data using all client generators. It then trains the global model using ACGAN loss on this synthetic data, ensuring the global model sees a balanced class distribution.
- Core assumption: Synthetic data generated from diverse client generators represents the true global data distribution better than simple parameter averaging.
- Evidence anchors:
  - [abstract]: "model consolidation and consistency enforcement"
  - [section 4.3]: "Then we generate balanced synthetic data with collected generator parameters from selected clients. Finally the global model is consolidated by the ACGAN loss function Lacgan with generated data"

### Mechanism 2
- Claim: Consistency enforcement aligns features and logits across different model states, reducing gradient explosion during early local training iterations.
- Mechanism: Each client maintains three generators (current, previous task, global). During local training, consistency loss functions (DKL) align the logits of real data and synthetic data from different generators, ensuring smoother optimization.
- Core assumption: Aligning logits across different data sources reduces the instability caused by heterogeneous, non-IID data distributions.
- Evidence anchors:
  - [abstract]: "consistency enforcement on the client side to align features and logits across model states"
  - [section 4.3]: "To learn a better global model, their features are expected be close to each other when their labels are the same... We use consistency loss functions to ensure this"

### Mechanism 3
- Claim: Using ACGAN instead of standard GAN with replay buffer avoids catastrophic forgetting by enabling conditional generation of previous class data.
- Mechanism: The generator in ACGAN is trained to generate synthetic samples conditioned on class labels. These synthetic samples are used for replay during training, allowing the model to "remember" previous classes without storing real data.
- Core assumption: Conditional generation quality is sufficient to approximate the true data distribution of previous tasks.
- Evidence anchors:
  - [abstract]: "Generative replay (GR) based methods are effective for continual learning without storing history data"
  - [section 4.1]: "ACGAN (Odena et al., 2017) is better than DGR in that, it reduces the complexity of the model by integrating the the classiﬁer and the generative model as a single model. Besides, it enables conditional generation, which is crucial for learning an unbiased classiﬁer"

## Architecture Onboarding

- Component map: Server contains global ACGAN model. Each client contains local ACGAN model, copy of previous task generator, and global generator. Communication involves parameter exchange only.
- Critical path: Client trains locally → sends parameters to server → server consolidates with synthetic data → sends updated parameters back to clients → clients apply consistency enforcement.
- Design tradeoffs: Using synthetic data for replay trades data quality for privacy and storage efficiency. Model consolidation adds server-side computation but improves global model stability.
- Failure signatures: High gradient norms during early local training indicate model instability. Poor FID scores indicate generator quality degradation. Large performance gaps between clients suggest non-IID data issues.
- First 3 experiments:
  1. Run FedAvg + ACGAN on MNIST with 5 clients, 2 classes per task, measure catastrophic forgetting.
  2. Add model consolidation to the above setup, compare global accuracy and generator FID.
  3. Add consistency enforcement, measure local client accuracy stability across communication rounds.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does FedCIL perform when clients have significantly different computational resources or participate in training with different frequencies?
- Basis in paper: [inferred] The paper mentions that clients may have different data distributions and that the server aggregates parameters from selected clients, but does not explore heterogeneity in client participation or computational capabilities.
- Why unresolved: The experiments use a fixed setup where all 5 clients participate in every communication round with equal frequency, which does not reflect real-world scenarios where client availability varies.
- What evidence would resolve it: Experiments varying client participation rates, computational capabilities, and communication frequency to assess FedCIL's robustness under these conditions.

### Open Question 2
- Question: What is the impact of varying the number of communication rounds on FedCIL's performance, particularly in terms of convergence speed and final accuracy?
- Basis in paper: [explicit] The paper states that the number of communication rounds should be flexible according to different settings, but does not provide a systematic analysis of how different communication frequencies affect performance.
- Why unresolved: The experiments use a fixed number of communication rounds (R=200), which may not be optimal for all scenarios and does not explore the trade-off between communication efficiency and model performance.
- What evidence would resolve it: Experiments varying the number of communication rounds and analyzing the resulting convergence curves and final accuracies.

### Open Question 3
- Question: How does FedCIL handle scenarios where new tasks introduce classes that are semantically similar to previously learned classes?
- Basis in paper: [inferred] The paper assumes non-overlapping classes across tasks for each client, but does not address the challenge of similar classes being introduced in different tasks, which could lead to confusion and forgetting.
- Why unresolved: The experimental setup ensures no class overlap within a client's task sequence, which simplifies the problem but does not reflect real-world scenarios where similar concepts may be introduced over time.
- What evidence would resolve it: Experiments introducing semantically similar classes in different tasks and measuring the impact on model performance and forgetting.

## Limitations

- Exact CNN architectures, hyperparameter settings, and noise distributions for ACGAN are not provided, making exact reproduction challenging
- Synthetic data quality assessment relies on FID scores without showing generated sample visualizations
- Experiments use fixed number of communication rounds (R=200) without exploring optimal communication frequency

## Confidence

- **High confidence**: The general framework of combining federated learning with generative replay is sound and well-supported by prior work in both fields.
- **Medium confidence**: The specific mechanisms of model consolidation and consistency enforcement are theoretically justified, but their effectiveness depends heavily on implementation details that are not fully specified.
- **Medium confidence**: The experimental results show clear improvements over baselines, but the magnitude of improvements may vary significantly with different hyperparameter choices and dataset characteristics.
