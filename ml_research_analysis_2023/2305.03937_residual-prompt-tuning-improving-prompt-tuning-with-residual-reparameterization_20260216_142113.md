# Residual Prompt Tuning: Improving Prompt Tuning with Residual Reparameterization

## Quick Facts
- **arXiv ID**: 2305.03937
- **Source URL**: https://arxiv.org/abs/2305.03937
- **Reference count**: 18
- **Key outcome**: Improves prompt tuning by introducing residual reparameterization, achieving up to +7 points improvement on SuperGLUE with T5-Base and reducing prompt length by 10x

## Executive Summary
Residual Prompt Tuning introduces a shallow network with residual connections to reparameterize soft prompt embeddings in prompt tuning. This approach significantly outperforms standard prompt tuning across SuperGLUE tasks with T5-Large, T5-Base, and BERT-Base models, achieving up to +7 points improvement with T5-Base. The method is robust to learning rate and prompt initialization choices, converges faster, and performs well in few-shot settings while reducing prompt length by 10x without sacrificing performance.

## Method Summary
Residual Prompt Tuning improves prompt tuning by reparameterizing soft prompt embeddings using a shallow network with a residual connection. The method applies a multi-layer perceptron (MLP) with a bottleneck design to each prompt token independently, allowing the model to choose between using raw embeddings or the transformed representation. The reparameterization network is jointly optimized with the prompt embeddings while keeping the backbone model frozen. This approach provides flexibility in deciding between separate embeddings for each prompt token versus shared representations from the network.

## Key Results
- Outperforms standard prompt tuning by up to +7 points on SuperGLUE with T5-Base
- Reduces prompt length by 10x without sacrificing performance
- Robust to learning rate and prompt initialization choices
- Converges faster than standard prompt tuning
- Performs well in few-shot settings with limited data

## Why This Works (Mechanism)

### Mechanism 1
The residual reparameterization improves soft prompt learning by combining direct embedding use with learned projections. The skip connection in the MLP lets the model choose between raw prompt embeddings and MLP-transformed embeddings at each token position, providing flexibility in representation selection.

### Mechanism 2
Overparameterization of prompt tokens through MLP bottleneck improves learning capacity. The MLP's hidden layer dimension provides additional parameters beyond raw prompt embeddings, allowing richer representations that capture task-specific patterns more effectively.

### Mechanism 3
Shared reparameterization network provides knowledge sharing across prompt tokens, beneficial in low-data regimes. A single MLP processes all prompt tokens, allowing information to flow between tokens through shared weights, preventing overfitting to individual tokens when data is limited.

## Architecture Onboarding

- **Component map**: Frozen pre-trained model -> Soft prompt embeddings -> Reparameterization network (MLP with skip) -> Task-specific head -> Loss

- **Critical path**:
  1. Initialize soft prompt embeddings
  2. Pass each embedding through MLP with skip connection
  3. Concatenate reparameterized prompts with input embeddings
  4. Feed through frozen model
  5. Apply task-specific head
  6. Compute loss and backpropagate only through prompts and MLP

- **Design tradeoffs**:
  - Shared vs separate MLP: Parameter efficiency vs flexibility
  - MLP width: Overparameterization vs computational cost
  - Prompt length: Performance vs memory constraints

- **Failure signatures**:
  - Slow convergence: Likely missing residual connection or insufficient MLP capacity
  - Unstable performance: Learning rate too high or prompt initialization problematic
  - No improvement over baseline: MLP bottleneck too small or shared network not beneficial for task

- **First 3 experiments**:
  1. Compare residual PT vs standard PT on a single SuperGLUE task with T5-Base
  2. Vary MLP hidden dimension (5, 50, 400) to find sweet spot
  3. Test shared vs separate MLP on a small dataset (CB) vs large dataset (WiC)

## Open Questions the Paper Calls Out

- **Open Question 1**: Does residual prompt tuning generalize to decoder-only models like GPT?
  - Basis in paper: The paper only tested on T5 and BERT models, planning to investigate decoder-only methods in future work
  - Why unresolved: Limited evaluation to encoder-decoder and encoder-only architectures
  - What evidence would resolve it: Experiments on GPT or other decoder-only models

- **Open Question 2**: How does residual prompt tuning perform on multilingual or code-switching tasks?
  - Basis in paper: Focus on English SuperGLUE tasks without testing multilingual capabilities
  - Why unresolved: Limited to English-language benchmarks
  - What evidence would resolve it: Experiments on multilingual benchmarks or code-switching datasets

- **Open Question 3**: What is the optimal MLP bottleneck size for different model scales and task complexities?
  - Basis in paper: Performance improves with larger MLP dimensions but saturates around 50 units for T5-Base
  - Why unresolved: Limited study to one model scale without systematic investigation across model sizes
  - What evidence would resolve it: Comprehensive study varying MLP dimensions across different model sizes and task complexities

## Limitations
- Architecture specificity: Improvements mainly demonstrated on T5 and BERT models
- Limited multilingual evaluation: Results only shown on English SuperGLUE tasks
- Few-shot performance claims: Based on limited evaluation with only two datasets

## Confidence
- **High Confidence**: The core mechanism of residual reparameterization through an MLP with skip connection is technically sound
- **Medium Confidence**: Claims about learning rate robustness and faster convergence are supported but need more validation
- **Low Confidence**: Claims about few-shot learning improvements lack sufficient experimental validation across diverse conditions
