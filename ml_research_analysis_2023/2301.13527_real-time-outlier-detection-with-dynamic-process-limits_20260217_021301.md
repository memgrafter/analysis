# Real-Time Outlier Detection with Dynamic Process Limits

## Quick Facts
- arXiv ID: 2301.13527
- Source URL: https://arxiv.org/abs/2301.13527
- Reference count: 20
- Key outcome: Online anomaly detection algorithm using Welford's method and ICDF for dynamic process limits in microgrid operation data

## Executive Summary
This paper introduces an online anomaly detection algorithm that provides dynamic process limits for real-time systems. The method combines Welford's online algorithm for computing streaming data statistics with inverse cumulative distribution function (ICDF) to generate real-valued thresholds. Tested on microgrid operation data, the approach successfully identifies various anomalies including packet loss, sensor failures, and distribution changes while adapting to environmental conditions. The algorithm offers benefits of ease of use, fast computation, and deployability in existing real-time infrastructures without requiring extensive domain knowledge or retraining of operators.

## Method Summary
The proposed method uses Welford's online algorithm to compute mean and variance of streaming data, then applies inverse cumulative distribution function to generate dynamic process limits for anomaly detection. The approach includes adaptive forgetting of old data through an expiration period parameter, and uses a time constant to control how quickly the model adapts to detected anomalies. The system scores anomalies based on z-scores and the three-sigma rule, providing real-valued thresholds that operators can interpret and use in process control. The method was validated on two case studies involving battery energy storage system (BESS) temperature monitoring and power inverter temperature monitoring.

## Key Results
- Successfully identified packet loss, sensor failures, and change points in microgrid operation data
- Dynamic process limits adapted to changing conditions, providing tighter operational constraints than static thresholds
- Method demonstrated ease of use, fast computation, and deployability in existing real-time infrastructures
- Reduced false positives by adapting to environmental changes and device aging

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Online ICDF provides dynamic process limits that adapt to changing conditions without retraining
- Mechanism: Uses Welford's online algorithm to compute mean and variance, then inverts CDF to generate real-valued thresholds
- Core assumption: Streaming data follows Gaussian distribution that can be approximated online
- Evidence anchors:
  - [abstract] "The online inverse cumulative distribution-based approach is introduced to eliminate common problems of offline anomaly detectors"
  - [section II-D] "Using pure statistics to model normal behavior lets us ask the question about the threshold value x which corresponds to the area under the curve of CDF"
- Break condition: If data distribution deviates significantly from Gaussian assumptions

### Mechanism 2
- Claim: Real-time outlier detection with dynamic process limits reduces false positives by adapting to environmental changes
- Mechanism: Uses time constant parameter to control adaptation speed, updating distribution only when anomalies persist beyond this window
- Core assumption: Persistent anomalies represent true changes rather than temporary fluctuations
- Evidence anchors:
  - [abstract] "The main benefits are ease of use, fast computation, and deployability as shown in two case studies"
  - [section III-A] "The time constant of the system determines the speed of change point adaptation"
- Break condition: If time constant is set too short or too long relative to normal fluctuations

### Mechanism 3
- Claim: Method can be deployed in existing process automation infrastructure without requiring operator retraining
- Mechanism: Integrates with existing alerting mechanisms by providing real-valued thresholds instead of binary alerts
- Core assumption: Existing systems can accept continuous threshold values for triggering alerts
- Evidence anchors:
  - [abstract] "The benefit of the proposed method is the ease of use, fast computation, and deployability as shown in two case studies"
  - [section IV] "The case studies were realized using Python 3.10.1 on a MAC with an M1 CPU and 8 GB RAM"
- Break condition: If existing systems cannot handle continuous threshold values

## Architecture Onboarding

- Component map: Data ingestion pipeline → Welford's algorithm → Gaussian distribution fitting → Anomaly scoring → ICDF threshold calculation → Alert generation
- Critical path:
  1. Receive new data point
  2. Update mean and variance using Welford's method
  3. Calculate z-score and CDF probability
  4. Generate anomaly score
  5. If score exceeds threshold, trigger alert
  6. Periodically calculate dynamic process limits using ICDF
- Design tradeoffs:
  - Expiration period vs. sensitivity to concept drifts
  - Time constant vs. false positive/negative balance
  - Computational complexity vs. detection accuracy
  - Memory usage vs. historical data retention
- Failure signatures:
  - High false positive rate: Check expiration period and time constant settings
  - Slow adaptation to changes: Expiration period may be too long
  - High computational load: Optimize ICDF calculation algorithm
  - Memory overflow: Implement proper buffer management for rolling window
- First 3 experiments:
  1. Test with synthetic Gaussian data with known concept drift to validate adaptation speed
  2. Compare false positive rates against static threshold method using BESS temperature data
  3. Stress test with high-frequency data to verify computational efficiency and memory usage

## Limitations
- Gaussian assumption for streaming data may not hold in all operational scenarios
- Expiration period and time constant parameters require careful tuning without clear selection guidance
- Lack of comparative analysis against established real-time anomaly detection methods
- Claims about deployment ease and operator acceptance are anecdotal without empirical validation
