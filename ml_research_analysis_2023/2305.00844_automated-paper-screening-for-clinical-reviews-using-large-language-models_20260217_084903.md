# Automated Paper Screening for Clinical Reviews Using Large Language Models

## Quick Facts
- arXiv ID: 2305.00844
- Source URL: https://arxiv.org/abs/2305.00844
- Authors: 
- Reference count: 27
- Primary result: GPT API achieves 0.91 overall accuracy in screening clinical review papers

## Executive Summary
This study introduces a novel workflow using the OpenAI GPT API for automated screening of titles and abstracts in clinical reviews. A Python script was developed to interface with the GPT API using natural language prompts containing screening criteria. The approach was evaluated on six real-world clinical review datasets comprising over 24,000 papers. Results showed an overall accuracy of 0.91, with sensitivity of 0.91 for excluded papers and 0.76 for included papers compared to human reviewers. The GPT API also demonstrated the ability to explain its decisions and correct incorrect classifications when prompted.

## Method Summary
The study developed a Python script to interface with the OpenAI GPT API, using natural language prompts that incorporate screening criteria for systematic reviews. The system processes titles and abstracts, returning classification decisions (include/exclude) along with optional reasoning explanations. Six real-world clinical review datasets totaling over 24,000 papers were used for evaluation, comparing GPT API decisions against human reviewer classifications.

## Key Results
- Overall accuracy of 0.91 across six clinical review datasets
- Sensitivity of 0.91 for excluded papers and 0.76 for included papers
- GPT API demonstrated ability to explain decisions and correct initial classifications when prompted

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The GPT API achieves high accuracy in title and abstract screening by leveraging pre-trained semantic embeddings that capture nuanced context.
- Mechanism: GPT-4's transformer architecture allows it to map input text into a high-dimensional semantic space where relevance can be judged based on similarity to inclusion criteria prompts.
- Core assumption: The model's general-domain pre-training provides sufficient semantic understanding for specialized medical review tasks without fine-tuning.
- Evidence anchors:
  - [abstract] The study uses natural language prompts with screening criteria and achieves 0.91 overall accuracy.
  - [section] "Recent developments in artificial intelligence and machine learning (ML) have made it possible to semi-automate or fully automate repetitive steps within the systematic review workflow."
  - [corpus] Weak - corpus shows related work but no direct evidence of GPT-4 semantic matching performance.
- Break condition: If inclusion criteria contain domain-specific terminology or logical operators that weren't represented in GPT's training data, performance would degrade significantly.

### Mechanism 2
- Claim: The API can explain and correct its decisions when prompted with reasoning requests.
- Mechanism: Chain-of-thought prompting enables the model to articulate decision rationale and self-correct when contradictions are identified.
- Core assumption: The model's internal reasoning process can be externally surfaced through appropriate prompting techniques.
- Evidence anchors:
  - [abstract] "The GPT API demonstrated the ability to provide reasoning for its decisions and corrected its initial decision upon being asked to explain its reasoning for a subset of incorrect classifications."
  - [section] "Interestingly, upon being asked to explain its reasoning for a subset of incorrect classifications, the GPT API corrected its initial decision."
  - [corpus] Weak - no corpus evidence of reasoning or self-correction capabilities in similar systems.
- Break condition: If the model's reasoning is post-hoc rationalization rather than genuine self-correction, prompting for explanation won't improve accuracy.

### Mechanism 3
- Claim: The system achieves cost-effectiveness through API-based implementation without requiring custom model training.
- Mechanism: Using a pre-trained API eliminates the need for dataset-specific training, reducing both development time and computational resources.
- Core assumption: The API's base capabilities are sufficient for the task without fine-tuning on domain-specific data.
- Evidence anchors:
  - [section] "the API does not require pretraining on the user's end and can provide reasoning for its decision"
  - [section] "cost of 25 USD" for screening 14,771 papers in NOA dataset
  - [corpus] Weak - no corpus evidence comparing API costs to traditional ML approaches.
- Break condition: If the API's token limits or pricing structure make it impractical for very large datasets or if performance requires expensive fine-tuning.

## Architecture Onboarding

- Component map: Python script -> OpenAI GPT API with natural language prompt -> Decision classification and reasoning -> CSV/JSON results
- Critical path: Data collection → Prompt construction → API call → Decision classification → Results storage → Evaluation
- Design tradeoffs:
  - Using API vs. self-hosted model: Lower development cost vs. potential long-term cost and dependency
  - Natural language prompts vs. structured queries: Flexibility vs. potential ambiguity
  - Single pass vs. iterative refinement: Speed vs. potential for self-correction
- Failure signatures:
  - Consistently misclassifying papers with specific terminology patterns
  - API rate limiting or cost overruns with large datasets
  - Inconsistent reasoning outputs across similar inputs
- First 3 experiments:
  1. Test the prompt format with a small validation set to optimize for accuracy
  2. Measure the impact of including vs. excluding reasoning prompts on classification performance
  3. Compare performance across different prompt engineering approaches (zero-shot vs. few-shot)

## Open Questions the Paper Calls Out

## Limitations
- Evaluation relies on existing clinical review datasets without detailed methodology for original human decisions
- Cost analysis only considers API usage, not full workflow costs including potential human verification
- Study focuses solely on English-language papers, limiting generalizability to multilingual contexts

## Confidence

**High confidence**: The overall accuracy of 0.91 and sensitivity metrics are well-supported by systematic evaluation across six datasets.

**Medium confidence**: The self-correction mechanism's effectiveness is demonstrated but only for a subset of cases.

**Low confidence**: The cost-effectiveness claim of "25 USD for 14,771 papers" represents a single data point without accounting for full workflow costs.

## Next Checks

1. **Bias analysis across clinical domains**: Test the system on clinical review datasets from different medical specialties to identify whether performance varies significantly based on domain-specific terminology or study design patterns.

2. **Human-in-the-loop workflow validation**: Conduct a real-world trial where the GPT API screens papers first, then human reviewers examine only those flagged as uncertain, measuring actual time savings and error rates compared to traditional screening.

3. **Longitudinal performance assessment**: Evaluate whether the system's accuracy degrades over time as screening criteria become more complex or when dealing with rapidly evolving research areas where terminology and concepts change quickly.
