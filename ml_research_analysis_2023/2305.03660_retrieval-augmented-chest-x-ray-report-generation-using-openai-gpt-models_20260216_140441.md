# Retrieval Augmented Chest X-Ray Report Generation using OpenAI GPT models

## Quick Facts
- arXiv ID: 2305.03660
- Source URL: https://arxiv.org/abs/2305.03660
- Reference count: 3
- Key outcome: CXR-RePaiR-Gen achieves BERTScore of 0.2865 (25.88% increase) and Semb score of 0.4026 (6.31% increase) over CXR-ReDonE model for retrieval augmented radiology report generation

## Executive Summary
This paper introduces CXR-RePaiR-Gen, a retrieval augmented generation approach for automated radiology report writing that leverages OpenAI GPT models. The system uses ALBEF contrastively pretrained vision-language embeddings to retrieve relevant radiology text for input X-ray images, then generates report impressions using GPT models (text-davinci-003, gpt-3.5-turbo, gpt-4) with the retrieved context. The approach achieves improved clinical metrics including BERTScore of 0.2865 and Semb score of 0.4026, while enabling structured report generation and hallucination-free outputs by grounding generation in retrieved factual content.

## Method Summary
CXR-RePaiR-Gen implements a retrieval-augmented generation pipeline where an input chest X-ray image is encoded using ALBEF to generate contrastively aligned embeddings. These embeddings retrieve top-K relevant radiology reports/sentences from a vector database containing 374,139 reports. The retrieved context is formatted into prompts with instructions for OpenAI GPT models, which generate the radiology report impression. The system supports both zero-shot and few-shot settings with prompt engineering, and can generate structured outputs in specified formats like JSON with pathology, position, severity, and size fields.

## Key Results
- BERTScore of 0.2865 achieved, representing a 25.88% improvement over CXR-ReDonE baseline
- Semb score of 0.4026 achieved, representing a 6.31% improvement over CXR-ReDonE baseline
- Enables hallucination-free generation by grounding outputs in retrieved factual context
- Supports structured report generation through prompt engineering with few-shot examples

## Why This Works (Mechanism)

### Mechanism 1
- Contrastively pretrained vision-language embeddings enable retrieval of semantically relevant radiology text
- ALBEF learns aligned embeddings so dot-product similarity retrieves contextually appropriate reports
- Core assumption: ALBEF contrastive training ensures images and reports have similar embeddings in shared space
- Break condition: If contrastive training fails to align embeddings, retrieved reports may be irrelevant causing hallucinations

### Mechanism 2
- Retrieval augmented generation grounds LLM outputs in factual radiology text, reducing hallucinations
- Providing retrieved reports as context constrains generation to factual content rather than model generalizations
- Core assumption: LLM can effectively use retrieved context to generate coherent, clinically accurate impressions
- Break condition: If retrieved context is too noisy or irrelevant, LLM may still hallucinate or generate incoherent outputs

### Mechanism 3
- Prompt engineering with few-shot examples enables structured radiology report generation in desired formats
- Providing examples of structured output (e.g., JSON with pathology fields) teaches LLM to organize information from retrieved context
- Core assumption: LLM's instruction-following capabilities are strong enough to parse context and generate structured output
- Break condition: If few-shot examples are unrepresentative or prompt unclear, LLM may fail to generate desired structured output

## Architecture Onboarding

- Component map: ALBEF model -> Vector database -> Retrieval module -> OpenAI LLM -> Prompt templates
- Critical path: 1) Input image encoded using ALBEF to generate image embedding, 2) Image embedding retrieves top-K reports/sentences from vector database, 3) Retrieved context formatted into prompt with LLM instructions, 4) LLM generates radiology report impression based on prompt and context
- Design tradeoffs: Retrieval quality vs. context length (more top-K improves relevance but may exceed context limits), free-text vs. structured output (structured more useful but harder to generate), temperature settings (higher temperature increases diversity but may increase hallucinations)
- Failure signatures: Low BERTScore and Semb scores indicate poor semantic similarity, low RadGraph F1 suggests missing/incorrect clinical entities, high hallucination rate measured by low Semb scores between generations and context
- First 3 experiments: 1) Evaluate retrieval quality by checking semantic similarity between retrieved reports and ground truth impressions for small sample, 2) Test impact of different top-K retrieval values on generated impression quality, 3) Assess prompt engineering effectiveness by comparing structured vs. free-text output quality

## Limitations
- Retrieval quality critically depends on ALBEF model's ability to generate semantically aligned embeddings, with no detailed analysis of failure cases
- Hallucination measurement methodology lacks explicit thresholds or qualitative clinical validation of what constitutes acceptable hallucination rates
- Clinical utility of generated reports not validated through radiologist review or downstream diagnostic accuracy studies

## Confidence
- High confidence: Retrieval mechanism using ALBEF embeddings and basic RAG architecture is technically sound and follows established practices
- Medium confidence: Claimed improvements over CXR-ReDonE are supported by reported metrics, though absolute values indicate significant room for improvement
- Low confidence: Clinical utility not validated through expert review or diagnostic accuracy studies
