# Edge Selection and Clustering for Federated Learning in Optical Inter-LEO Satellite Constellation

## Quick Facts
- arXiv ID: 2303.16071
- Source URL: https://arxiv.org/abs/2303.16071
- Reference count: 24
- Primary result: FedLEO achieves ~97% accuracy and 2.36s system delay for on-orbit FL, outperforming centralized (15.67s) and distributed baselines.

## Executive Summary
This paper proposes FedLEO, a federated learning system for mega-constellations of low-Earth orbit (LEO) satellites using optical inter-satellite links. It eliminates reliance on ground gateways by performing all training and aggregation on orbit. An LEO edge selection and clustering (LESC) algorithm chooses an edge server based on ground-satellite link quality and forms a client cluster based on communication thresholds (distance or SNR), with periodic re-clustering to maintain quality. Simulations using a Walker Delta constellation of ~700 satellites and MNIST classification show FedLEO outperforms centralized and distributed baselines in accuracy and latency.

## Method Summary
FedLEO uses a Walker Delta constellation of ~700 LEO satellites at 570km altitude. The system employs a 3-layer MLP model for MNIST classification with FedAvg aggregation. The LESC algorithm selects an edge server based on maximum ground-satellite link SNR, then clusters nearby LEOs using either distance (δd) or SNR (δγ) thresholds. Clients train locally for E=2 epochs, upload model weights via optical ISLs, and the edge server aggregates and broadcasts the global model. Re-clustering occurs every Trc rounds if cluster size drops below threshold ǫK′. The system is compared against centralized and distributed learning baselines.

## Key Results
- FedLEO achieves ~97% classification accuracy on MNIST using on-orbit FL with optical ISLs
- System delay is 2.36s versus 15.67s for centralized learning baseline
- LESC clustering based on distance thresholds provides better accuracy than SNR thresholds under the tested conditions

## Why This Works (Mechanism)

### Mechanism 1
- Claim: FedLEO eliminates ground station dependency by performing all model training and aggregation in orbit using inter-satellite optical links.
- Mechanism: By clustering LEO satellites into a local FL client group and selecting one satellite as a temporary edge server, FedLEO allows clients to train locally and exchange model parameters via high-bandwidth optical ISLs, avoiding the high-latency data upload/download to ground.
- Core assumption: The optical ISL channel provides sufficiently low latency and high throughput to support timely model exchange among LEO satellites.
- Evidence anchors:
  - [abstract] "We allocate the entire process on LEOs with low payload inter-satellite transmissions, whilst the low-delay terrestrial gateway server (GS) only takes care for initial signal controlling."
  - [section II.C] "We consider laser communication for ISL with the received signal power given by PR = PT ηT ηRGT GRLT LRLP S."
  - [corpus] The cited neighbor papers (e.g., "Satellite Federated Edge Learning: Architecture Design and Convergence Analysis") reinforce the design space of on-orbit FL with optical links.
- Break condition: If the pointing error or distance between LEOs becomes too large, optical ISL link quality degrades below the SNR threshold δγ, causing communication failure.

### Mechanism 2
- Claim: LESC algorithm dynamically selects a cluster of LEO satellites as FL clients based on distance or SNR thresholds, with periodic re-clustering to maintain link quality.
- Mechanism: The GS initially selects the best ground-satellite link LEO as edge server. The edge server then forms a client cluster meeting either distance threshold δd or SNR threshold δγ. After Trc aggregation rounds, if cluster size drops below ǫK′ or link quality degrades, the server re-clusters to maintain sufficient participants.
- Core assumption: High mobility of LEOs necessitates periodic re-clustering to avoid expired or low-quality links affecting training convergence.
- Evidence anchors:
  - [section III] "Due to high mobility of LEOs, the connected links of ISL over LEOs might lead to failure after certain session. The LEO edge server will handover the task to the upcoming reachable candidate LEO to the GS, whilst the new LEO edge server will re-cluster the clients to continue the task."
  - [algorithm] "if Ka < ǫK′ and mod ( a, T rc) = 0 then LEO edge server re-clusters LEO clients Ka with size Ka and update K′ = Ka"
  - [corpus] Papers like "Optimizing Federated Learning in LEO Satellite Constellations via Intra-Plane Model Propagation and Sink Satellite Scheduling" discuss similar re-clustering strategies.
- Break condition: If re-clustering frequency Trc is too low, the cluster may shrink too much before re-clustering, causing loss of training progress or divergence.

### Mechanism 3
- Claim: Adaptive edge selection based on ground-satellite link quality ensures the best possible initial channel for controlling the FL task.
- Mechanism: The GS chooses the LEO with the maximum SNR γ∗gsl,k as the initial edge server. This minimizes the initial control overhead and improves the reliability of task initiation.
- Core assumption: Ground-satellite link quality remains relatively stable during the initial control phase, allowing accurate edge server selection.
- Evidence anchors:
  - [section III] "Considering a practical case, a GS on the ground has limited time to contact with the LEOs. Therefore, we consider the GS acts as an initiator for selecting an appropriate edge of the whole training process with the best ground-satellite link (GSL) quality γ∗gsl,k = max γgs,k."
  - [section II.A] "The GS initially selects an LEO satellite with better communication link quality as an FL edge server and transmits the control signal with the assigned training tasks."
  - [corpus] The neighbor corpus includes "Secure and Efficient Federated Learning in LEO Constellations using Decentralized Key Generation and On-Orbit Model Aggregation," which also highlights edge selection importance.
- Break condition: If the best GSL LEO moves out of GS coverage quickly, the initial control phase may fail, requiring fallback selection logic.

## Architecture Onboarding

- Component map:
  - Ground Station (GS) -> LEO Edge Server -> LEO Clients -> Optical ISLs
- Critical path:
  1. GS selects best GSL LEO as edge server
  2. Edge server clusters nearby LEOs based on δd or δγ
  3. Clients train locally for E epochs
  4. Clients upload model weights via ISL
  5. Edge aggregates and broadcasts updated global model
  6. Repeat until re-clustering condition triggers
- Design tradeoffs:
  - δd vs δγ clustering: δd gives predictable cluster size but may include distant clients with poor link quality; δγ ensures good links but yields variable cluster sizes
  - Trc vs ǫ: Frequent re-clustering (small Trc) maintains quality but increases control overhead; conservative re-clustering risks degraded performance
- Failure signatures:
  - High model staleness: cluster size drops below threshold but re-clustering not triggered
  - Divergence: pointing errors too large causing model exchange failure
  - High latency: δd too large leading to long-distance ISL paths
- First 3 experiments:
  1. Simulate clustering under fixed δd to observe cluster size stability and model accuracy
  2. Vary σθ to measure impact on ISL rate and training convergence
  3. Compare total system delay (Ttr,F) against centralized and distributed baselines under same constellation

## Limitations
- The paper's performance claims hinge on ideal optical ISL conditions that may not hold in practice
- The simulation setup does not address potential issues with heterogeneous data distributions across LEO clients
- The assertion that re-clustering every Trc rounds is sufficient for maintaining performance is not empirically validated across different mobility patterns

## Confidence
- High Confidence: The basic architecture of using optical ISLs for on-orbit FL aggregation and the LESC algorithm for edge selection and clustering are well-supported by the literature and simulation results
- Medium Confidence: The claimed latency and accuracy improvements over baselines are reasonable given the simulation setup, but would benefit from validation under more realistic channel conditions and data distributions
- Low Confidence: The paper's assertion that re-clustering every Trc rounds is sufficient for maintaining performance is not empirically validated across different mobility patterns and satellite densities
