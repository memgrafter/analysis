# Exploring the Curious Case of Code Prompts

## Quick Facts
- arXiv ID: 2304.13250
- Source URL: https://arxiv.org/abs/2304.13250
- Reference count: 8
- Primary result: Code prompts do not consistently outperform text prompts across diverse tasks, with some tasks performing worse with code prompts

## Executive Summary
This paper investigates whether code-like representations outperform natural language prompts for language models across diverse tasks. The authors compare text and code prompts on three GPT models (davinci, code-davinci-002, and text-davinci-002) across 12 tasks including question answering, sentiment analysis, and summarization. Their results show that code prompting is not a universal solution, with performance varying significantly by task type and prompt style. Fine-tuning on text instructions surprisingly improves code prompt effectiveness, and the style of code prompt (vanilla, with variable identifiers, with comments, with class structure) affects performance differently across tasks. The findings suggest that while code prompting can be beneficial for certain reasoning tasks, text prompting remains the preferred method for most tasks.

## Method Summary
The study compares code prompts to text prompts using three GPT models (davinci, code-davinci-002, text-davinci-002) across 12 NLP tasks. For each task, they generate both text prompts from PromptSource and four styles of code prompts (vanilla, variable identifier, variable identifier with comments, class structure with variable identifier and comments). The experiments use few-shot prompting with up to 4000 tokens of in-context examples, randomly sampled from the training set. Performance is measured using task-appropriate metrics including accuracy, F1, Pearson correlation, and ROUGE scores. The analysis examines whether code prompts outperform text prompts, which code prompt styles work best for different tasks, and how model pre-training (text-only, text+code, text+code+instruction fine-tuning) affects these relationships.

## Key Results
- Code prompts do not consistently outperform text prompts across all tasks, with some tasks even performing worse with code prompts
- The style of code prompt has a large effect on performance for some but not all tasks
- Fine-tuning on text instructions leads to better relative performance of code prompts
- No single type of code prompt performs significantly better than the others across all tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Code prompts do not consistently outperform text prompts across diverse tasks.
- Mechanism: The effectiveness of code prompting depends on task characteristics, with structured reasoning tasks benefiting more than general language tasks.
- Core assumption: The underlying language model's pre-training data and architecture interact differently with code-like representations based on task structure.
- Evidence anchors:
  - [abstract] "code prompts do not consistently outperform text prompts across all tasks, with some tasks even performing worse with code prompts"
  - [section 3] "we find that prompting PLMs with code leads to substantial increases in performance for certain few reasoning tasks but that this trend does not hold across all tasks"
  - [corpus] Weak evidence - no direct corpus support for this mechanism
- Break condition: If task characteristics do not align with structured reasoning requirements, code prompts will not provide consistent advantages over text prompts.

### Mechanism 2
- Claim: The style of code prompt significantly affects performance on certain tasks but not others.
- Mechanism: Different code prompt styles (vanilla, variable identifiers, comments, class structure) provide varying levels of semantic clarity and structure, which interact differently with model capabilities across tasks.
- Core assumption: Language models can leverage different levels of code structure to understand task requirements, but this ability varies by task complexity and type.
- Evidence anchors:
  - [abstract] "the style of code prompt has a large effect on performance for some but not all tasks"
  - [section 3] "no single type of code prompt performs significantly better than the others across all tasks and that the relative difference in performance between code prompts also varies significantly across tasks"
  - [corpus] Weak evidence - no direct corpus support for this mechanism
- Break condition: When task requirements are straightforward or when models have sufficient context, the style of code prompt becomes less critical to performance.

### Mechanism 3
- Claim: Fine-tuning on text instructions improves the relative performance of code prompts.
- Mechanism: Instruction fine-tuning on text provides additional context about task structure that can be leveraged when interpreting code-like representations, even when those representations are in code format.
- Core assumption: Instruction fine-tuned models develop better task understanding capabilities that transfer across different prompt formats (text and code).
- Evidence anchors:
  - [abstract] "fine-tuning on text instructions leads to better relative performance of code prompts"
  - [section 3] "we observe that code prompts outperform text prompts on more tasks when using text-davinci-002 than when using code-davinci-002 despite the fact that text-davinci-002 received no additional fine-tuning on code instructions"
  - [corpus] Weak evidence - no direct corpus support for this mechanism
- Break condition: If the instruction fine-tuning does not provide relevant task structure information, or if the model's architecture limits cross-format knowledge transfer, the performance improvement may not materialize.

## Architecture Onboarding

- Component map:
  - Data pipeline: Dataset selection (12 tasks across 5 categories), prompt generation (text from PromptSource, code manually written), model API integration (OpenAI API for davinci, code-davinci-002, text-davinci-002)
  - Model layer: Three GPT models with different pre-training strategies, evaluation metrics (accuracy, F1, Pearson correlation, ROUGE scores)
  - Evaluation pipeline: Context window management (4000 tokens), random sampling of in-context examples, multiple runs for variance measurement

- Critical path:
  1. Load and preprocess dataset examples
  2. Generate corresponding text and code prompts
  3. Fill context window with in-context examples (up to 4000 tokens)
  4. Submit prompts to appropriate model via API
  5. Parse and evaluate model outputs
  6. Aggregate results across all tasks and models

- Design tradeoffs:
  - Random vs. static in-context examples: Random sampling reduces bias but may introduce variance; static examples would be more reproducible but potentially biased
  - Context window size: Larger context allows more examples but increases cost and may not improve performance (as shown in results)
  - Prompt style complexity: More structured prompts (class + comments) may provide clarity but could also introduce noise or confusion

- Failure signatures:
  - Unexpected performance drops when increasing in-context examples (contrary to typical few-shot learning expectations)
  - Inconsistent performance across code prompt styles for certain tasks
  - Significant performance differences between models with similar capabilities but different pre-training strategies

- First 3 experiments:
  1. Baseline comparison: Run all three models on text prompts with 4000-token context to establish baseline performance
  2. Code prompt style ablation: Test all four code prompt styles on a subset of tasks to identify which styles work best for which task types
  3. Context length scaling: Vary context window from 2000 to 8000 tokens on selected tasks to confirm the non-monotonic relationship between context size and performance

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Does the effectiveness of code prompting vary depending on the specific programming language used (e.g., Python vs JavaScript)?
- Basis in paper: [inferred] The paper only tests code prompts written in Python syntax, but does not explore other programming languages.
- Why unresolved: The paper's methodology only considers Python-based code prompts, leaving open the question of whether other languages might yield different results.
- What evidence would resolve it: Experiments testing code prompts in various programming languages (e.g., JavaScript, Java, C++) across the same set of tasks and comparing their performance to Python prompts and text prompts.

### Open Question 2
- Question: How does the complexity of the code prompt (e.g., simple variable assignments vs. complex class structures) affect model performance?
- Basis in paper: [explicit] The paper tests four different styles of code prompts (Vanilla, VI, VIC, CVIC) with increasing complexity, but does not systematically vary complexity within each style.
- Why unresolved: While the paper shows that different prompt styles perform differently, it does not isolate the effect of complexity itself on performance.
- What evidence would resolve it: Experiments systematically varying the complexity of code prompts within each style category (e.g., simple vs. complex variable assignments, simple vs. complex class structures) and measuring their impact on performance.

### Open Question 3
- Question: Can the effectiveness of code prompting be predicted based on the semantic similarity between the task and programming concepts?
- Basis in paper: [inferred] The paper observes that code prompting works well for some reasoning tasks but not others, without explaining why certain tasks benefit more than others.
- Why unresolved: The paper does not provide a theoretical framework for understanding which tasks are likely to benefit from code prompting based on their semantic properties.
- What evidence would resolve it: Analysis correlating task performance with code prompting to semantic similarity metrics between task descriptions and programming concepts, potentially using techniques from computational semantics or knowledge representation.

## Limitations
- Narrow focus on GPT models may limit generalizability to other model families
- Small sample size (1000 examples per task) may not capture scale effects
- Manual creation of code prompts introduces potential experimenter bias

## Confidence
- High confidence: The core finding that code prompts do not consistently outperform text prompts across all tasks is well-supported by the comprehensive comparison across 12 diverse tasks and 3 model variants
- Medium confidence: The claim about fine-tuning on text instructions improving code prompt performance relative to other models has some supporting evidence but would benefit from additional experiments with different instruction fine-tuning approaches
- Medium confidence: The observation about non-monotonic performance with increasing context size is supported by results but requires more systematic investigation across different task types and model sizes

## Next Checks
1. **Cross-model validation**: Test the same code prompt styles on other large language models (e.g., Claude, LLaMA) to determine if the observed patterns are model-specific or general principles

2. **Scale sensitivity analysis**: Evaluate whether the code vs text prompt performance gap changes with larger training datasets and model sizes, particularly examining whether smaller models might benefit more from code prompts

3. **Prompt engineering optimization**: Conduct an ablation study varying the complexity and structure of code prompts systematically to identify which specific elements (variable naming, comments, class structure) contribute most to performance differences across task types
