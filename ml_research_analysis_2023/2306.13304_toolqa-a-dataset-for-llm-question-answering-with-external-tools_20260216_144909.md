# ToolQA: A Dataset for LLM Question Answering with External Tools

## Quick Facts
- **arXiv ID**: 2306.13304
- **Source URL**: https://arxiv.org/abs/2306.13304
- **Reference count**: 40
- **Primary result**: ToolQA dataset exposes limitations in LLM tool-use reasoning, with best model achieving 43.13% on easy questions and 8.24% on hard questions.

## Executive Summary
ToolQA is a new benchmark dataset designed to evaluate large language models' ability to use external tools for question answering. The dataset contains 1530 questions across 8 domains, each requiring tool-based reasoning over external reference corpora. Through a three-phase automated curation process, ToolQA ensures questions cannot be answered from pre-training knowledge alone, forcing models to rely on external tools. Experiments show that existing tool-augmented LLMs struggle significantly on this benchmark, with performance degrading from 43.13% on easy questions to only 8.24% on hard questions, highlighting the need for advancements in LLM tool composition reasoning.

## Method Summary
ToolQA employs a three-phase automated process for dataset curation: reference data collection from contemporary sources, human-guided question generation using validated templates, and programmatic answer generation via scripted tool chains. The dataset uses 13 specialized tools for interaction with external knowledge and stratifies questions into easy (single-tool, simple reasoning) and hard (multi-tool, complex reasoning) categories. Evaluation measures success rates by exact match between normalized ground-truth answers and model predictions, with the key premise being that reference corpora minimally overlap with LLM training data.

## Key Results
- Existing tool-augmented LLMs achieve only 43.13% success on easy ToolQA questions and 8.24% on hard questions
- Performance degrades significantly as question complexity increases, revealing limitations in tool composition reasoning
- Major error types include incorrect tool calls, using incorrect data sources, and failure to understand complex task logic

- Core assumption: If reference corpora are sufficiently distinct from LLM pre-training data, the LLM cannot answer questions without using the provided tools.

## Foundational Learning

- Concept: External tool integration in LLMs
  - Why needed here: ToolQA is built to evaluate how well LLMs can use external tools rather than just recall knowledge.
  - Quick check question: What is the difference between retrieval-augmented LLMs and tool-augmented LLMs in terms of interaction with external knowledge?

- Concept: Template-based question generation
  - Why needed here: The dataset uses templates to ensure questions are answerable only with tools and reduce human effort.
  - Quick check question: How does template validation help prevent questions that can be answered from LLM internal knowledge?

- Concept: Programmatic answer generation
  - Why needed here: Ensures that generated questions have correct, verifiable answers via scripted tool chains.
  - Quick check question: Why is programmatic answer generation more reliable than manual annotation in this context?

## Architecture Onboarding

- Component map: Reference Data Collection -> Human-Guided Question Generation -> Programmatic Answer Generation -> LLM Evaluation
- Critical path: Question generation → Tool chain validation → Answer generation → LLM evaluation. The bottleneck is ensuring generated questions truly require tool use and that tool chains produce correct answers.
- Design tradeoffs: Automated curation reduces human effort but may introduce noise if templates are not carefully validated; programmatic answer generation ensures correctness but requires maintaining accurate tool chain implementations; using contemporary data avoids pre-training overlap but limits dataset size.
- Failure signatures: If LLM performance is uniformly high across easy and hard questions, either the distinction is not meaningful or reference data overlaps with training data; if programmatic answers fail, questions may be unanswerable or require debugging tool chains; if templates generate too many easy questions, the dataset may not stress test tool composition.
- First 3 experiments:
  1. Run baseline LLMs (ChatGPT, CoT) on easy questions to confirm they cannot answer without tools.
  2. Execute programmatic answer generation on a sample of hard questions to verify correctness of tool chains.
  3. Evaluate ReAct on both easy and hard questions to establish performance gap and identify error types.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can tool-augmented LLMs be improved to handle complex reasoning tasks that require multiple tools?
- Basis in paper: [explicit] The paper mentions that hard questions in ToolQA require more tool calls and complicated compositions, which current tool-augmented LLMs struggle with.
- Why unresolved: Existing methods like ReAct and Chameleon show limited success on hard questions, suggesting that the models have difficulty understanding complex tool compositions and reasoning about task logic.
- What evidence would resolve it: Experiments showing improved success rates on hard questions after implementing novel techniques for tool composition reasoning, such as better context understanding or hierarchical planning approaches.

### Open Question 2
- Question: What is the optimal way to incorporate tool descriptions and examples in prompts to minimize hallucinations while maximizing innovation?
- Basis in paper: [explicit] The paper discusses how innovations in tool use can lead to hallucinations, and mentions the challenge of including all possible tool compositions in few-shot exemplars due to context length constraints.
- Why unresolved: There's a trade-off between providing enough context for the model to understand tools and not overwhelming it with too much information, which could lead to hallucinations.
- What evidence would resolve it: Comparative studies of different prompt engineering strategies, showing the balance between innovation and hallucination rates across various task complexities.

### Open Question 3
- Question: How can tool-augmented LLMs be trained to better identify the correct data source for a given question?
- Basis in paper: [explicit] The paper identifies "incorrect data source" as a major error type, with models often confused about which reference corpus to query.
- Why unresolved: Current models struggle to differentiate between similar data sources (e.g., temporal vs. general knowledge) and often select the wrong corpus to answer questions.
- What evidence would resolve it: Development and evaluation of models that show improved accuracy in selecting the correct data source, potentially through fine-tuning on source-specific data or using multi-task learning approaches.

## Limitations
- Limited baseline comparison with only three models tested (ChatGPT, Chameleon, ReAct)
- Lack of quantitative validation that reference corpora truly avoid pre-training overlap
- Template-based generation lacks detailed validation documentation, raising concerns about question quality

## Confidence
- **High confidence**: The dataset successfully demonstrates that existing tool-augmented LLMs struggle with tool composition reasoning, as evidenced by the substantial performance gap between easy (43.13%) and hard (8.24%) questions.
- **Medium confidence**: The three-phase automated curation process likely ensures tool-dependent questions, though validation details are sparse and the actual effectiveness of template constraints is unverified.
- **Low confidence**: The claim that ToolQA enables "faithful evaluation" of LLM tool-use reasoning is weakly supported, as quantitative overlap analysis between reference corpora and LLM training data is absent.

## Next Checks
1. **Overlap validation**: Quantitatively measure the overlap between ToolQA's reference corpora and popular LLM training datasets (e.g., C4, Books3) to verify the dataset's core premise that questions cannot be answered from pre-training knowledge alone.
2. **Template validation audit**: Conduct a systematic review of human-guided question generation templates to assess their effectiveness in ensuring tool dependence and preventing questions answerable from LLM internal knowledge.
3. **Baseline expansion**: Test additional state-of-the-art tool-augmented models (e.g., Voyager, Toolformer) on ToolQA to establish whether the observed performance ceiling of ~43% is a general limitation or specific to the tested models.
