# Domain Aligned Prefix Averaging for Domain Generalization in Abstractive Summarization

## Quick Facts
- arXiv ID: 2305.16820
- Source URL: https://arxiv.org/abs/2305.16820
- Reference count: 17
- Key outcome: DAPA achieves comparable or better performance than baselines for domain generalization in abstractive summarization using prefix averaging

## Executive Summary
This paper introduces DAPA (Domain Aligned Prefix Averaging), a lightweight approach to domain generalization for abstractive summarization. DAPA trains separate prefixes for each source domain, then generates summaries for a small number of target domain documents using these prefixes. The similarity between these summaries and their corresponding documents is used to calculate weights for averaging the source prefixes. This averaging scheme enables DAPA to generalize well to target domains while being computationally efficient. Experiments on four summarization domains show that DAPA achieves comparable or better performance than baselines.

## Method Summary
DAPA trains a prefix for each source domain using prefix tuning on a frozen T5 backbone. For target domain adaptation, DAPA generates summaries for a small number of target documents using each source prefix, computes document-summary similarity scores, and uses these scores to calculate weights for averaging the source prefixes. The weighted average prefix is then used to generate target domain summaries. This approach allows DAPA to leverage knowledge from multiple source domains while preserving generalization capabilities.

## Key Results
- DAPA achieves comparable or better performance than baselines on domain generalization for abstractive summarization
- Prefix averaging enables lightweight domain generalization without updating the full model
- Document-summary similarity effectively guides prefix weight calculation for target domain adaptation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Prefix averaging enables lightweight domain generalization by learning domain-specific prefix representations without updating the full model.
- Mechanism: DAPA trains separate prefixes for each source domain, then computes weighted averages based on their similarity to target domain documents. This leverages knowledge from multiple source domains while preserving generalization capabilities.
- Core assumption: Prefix representations capture domain-specific characteristics sufficiently well that averaging them appropriately can generalize to unseen domains.
- Evidence anchors: [abstract] "In DAPA, prefix tuning allows for lightweight finetuning, and weight averaging allows for the computationally efficient addition of new source domains."
- Break condition: If prefix representations do not capture sufficient domain-specific information, averaging them will not generalize well to target domains.

### Mechanism 2
- Claim: Weight averaging of prefixes preserves generalization better than fine-tuning entire models.
- Mechanism: By keeping the backbone model frozen and only averaging learned prefixes, DAPA avoids overfitting to source domains and maintains the ability to adapt to new domains.
- Core assumption: Freezing the backbone model parameters while adapting only prefixes preserves the generalization properties of the pretrained model.
- Evidence anchors: [abstract] "Through our prefix averaging scheme, we can identify source prefixes essential to ensure good performance on the target domain."
- Break condition: If the backbone model needs adaptation to specific domains for optimal performance, freezing it will limit DAPA's effectiveness.

### Mechanism 3
- Claim: Using document-summary similarity scores to weight prefix averaging ensures the most relevant source domains contribute more to target domain adaptation.
- Mechanism: DAPA generates summaries using each source prefix for a small number of target domain documents, then computes similarity scores between these summaries and the original documents to determine prefix weights.
- Core assumption: Document-summary similarity correlates with the relevance of a source domain prefix for the target domain.
- Evidence anchors: [abstract] "The similarity of the generated summaries to their corresponding documents is used for calculating weights required to average source prefixes."
- Break condition: If document-summary similarity does not correlate with domain relevance, the weight calculation will not select appropriate source prefixes.

## Architecture Onboarding

- Component map:
  - Backbone T5 model (frozen) -> Source domain prefixes (learned through prefix tuning) -> Target domain prefix (weighted average of source prefixes) -> Similarity encoder (SentenceBERT) -> Weight calculation module

- Critical path:
  1. Train source domain prefixes
  2. Generate target domain summaries using source prefixes
  3. Compute similarity scores between summaries and documents
  4. Calculate weights for prefix averaging
  5. Generate target domain prefix and use it for summarization

- Design tradeoffs:
  - Using prefixes vs full model fine-tuning: DAPA is more lightweight but may sacrifice some performance
  - Number of target domain documents for weight calculation: More documents improve weight estimation but increase computation
  - Prefix length: Longer prefixes capture more information but increase parameters and computation

- Failure signatures:
  - Poor performance on target domain despite good source domain performance
  - Weight calculation produces nearly equal weights for all source domains
  - Summary quality is low when using the target domain prefix

- First 3 experiments:
  1. Train DAPA with only one source domain and test on the target domain to establish baseline
  2. Train DAPA with all source domains but use equal weights for averaging to test the importance of weighted averaging
  3. Train DAPA with all source domains and varying numbers of target domain documents for weight calculation to find optimal value

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of DAPA scale with larger backbone models?
- Basis in paper: The authors mention computational constraints prevented them from experimenting with larger models, but expect performance to improve with model size based on previous works.
- Why unresolved: The paper does not provide experimental results for larger models due to computational limitations.
- What evidence would resolve it: Experiments with DAPA using larger backbone models like T5-large or T5-3B to measure performance improvements.

### Open Question 2
- Question: What is the optimal prefix length for prefix tuning in DAPA?
- Basis in paper: The authors state that prefix length C = 50 is used, but an analysis shows that performance increases up to C = 50 and then drops or remains constant. They leave further exploration into this for future work.
- Why unresolved: The paper only provides results for a single prefix length of 50 and suggests further investigation is needed.
- What evidence would resolve it: A comprehensive study varying the prefix length C and measuring its impact on DAPA's performance across different domains.

### Open Question 3
- Question: Does DAPA's weight assignment process correlate with document-level source-target domain similarity?
- Basis in paper: The authors train a BERT model for source domain identification and find that DAPA's weight assignment does not always align with the document-level similarity predicted by BERT.
- Why unresolved: The paper concludes that DAPA relies on summary generation capabilities rather than document-level similarities, but further investigation into this aspect is left for future work.
- What evidence would resolve it: A detailed analysis comparing DAPA's weight assignment with document-level similarity measures to understand the relationship between the two.
