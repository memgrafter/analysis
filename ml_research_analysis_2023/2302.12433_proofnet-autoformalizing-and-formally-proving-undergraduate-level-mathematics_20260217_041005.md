# ProofNet: Autoformalizing and Formally Proving Undergraduate-Level Mathematics

## Quick Facts
- arXiv ID: 2302.12433
- Source URL: https://arxiv.org/abs/2302.12433
- Authors: 
- Reference count: 10
- Key outcome: Introduces ProofNet benchmark for autoformalization of undergraduate mathematics, achieving 13.4% accuracy with Codex model and proposing prompt retrieval and distilled backtranslation methods to improve performance.

## Executive Summary
This paper introduces ProofNet, a benchmark for autoformalizing undergraduate-level mathematics into Lean 3 formal theorem statements. The benchmark consists of 371 examples drawn from popular pure mathematics textbooks covering topics like real analysis, linear algebra, and abstract algebra. The authors establish baseline performance using large language models with in-context learning, achieving 13.4% accuracy. They then propose two novel methods—prompt retrieval and distilled backtranslation—to improve autoformalization without requiring parallel training data. These methods significantly boost performance and provide new approaches for scaling autoformalization to larger mathematical corpora.

## Method Summary
The paper addresses autoformalization through a combination of in-context learning, prompt retrieval, and distilled backtranslation. In-context learning uses few-shot prompts with large language models like OpenAI's Code-davinci-002 and PROOF GPT. Prompt retrieval enhances this by finding semantically similar mathlib declarations through nearest-neighbor search against an embedding database, incorporating them into the prompt. Distilled backtranslation is inspired by unsupervised machine translation: a teacher LM generates synthetic NL-to-Lean pairs by translating monolingual Lean statements, then a student model is fine-tuned on these pairs. The approach enables training autoformalization models without parallel data, addressing a key bottleneck in the field.

## Key Results
- 13.4% autoformalization accuracy baseline using OpenAI's Code-davinci-002 model with in-context learning
- Prompt retrieval increases accuracy by 2.7 points and typecheck rate by 21.5 points
- Distilled backtranslation fine-tuning improves PROOF GPT-1.3B performance above in-context learning baselines
- Typecheck rate recommended as development proxy metric when accuracy evaluation is too costly

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Prompt retrieval significantly improves autoformalization by incorporating relevant mathlib declarations into the few-shot prompt.
- Mechanism: Nearest-neighbor search against an embedding database retrieves the k-nearest formal statements to the model's current autoformalization attempt. These retrieved statements provide relevant syntactic and semantic context that guides the model toward correct formalization patterns.
- Core assumption: The semantic similarity between the model's current attempt and relevant mathlib declarations correlates with the quality of the final formalization.
- Evidence anchors:
  - [abstract]: "Prompt retrieval uses nearest-neighbor search against an embedding database to create a prompt consisting of the mathlib declarations most relevant to a particular natural language theorem."
  - [section 4.1.2]: "Prompt retrieval uses nearest-neighbor search against an embedding database to create a prompt consisting of the most relevant mathlib declarations."
  - [corpus]: Weak evidence - only 1 related paper (DRIFT) mentions retrieval augmentation, but not specifically prompt retrieval.
- Break condition: If the embedding space poorly represents semantic similarity, or if retrieved statements are too generic or unrelated, the performance gain disappears.

### Mechanism 2
- Claim: Distilled backtranslation enables large-scale fine-tuning for autoformalization without parallel data.
- Mechanism: A teacher LM (Code-davinci-002) generates synthetic NL-to-Lean pairs by translating monolingual Lean mathlib statements. A student model (proofGPT-1.3B) is then fine-tuned on these synthetic pairs, learning to map informal mathematical language to formal Lean syntax.
- Core assumption: Synthetic backtranslations preserve enough semantic and syntactic information to train a capable autoformalization model.
- Evidence anchors:
  - [abstract]: "Distilled backtranslation is inspired by work in unsupervised machine translation and fine-tunes a language model for autoformalization without the need for parallel data."
  - [section 4.1.3]: "We manually construct a few-shot prompt C consisting of X|Y pairs. Then, we sample synthetic backtranslations Xi ~ PLLM(X|C, Yi). Finally, we fine-tune Pθ(·) on the synthetic pairs to predict P(Y|X)."
  - [corpus]: Moderate evidence - unsupervised MT papers cited, but specific backtranslation for autoformalization is novel here.
- Break condition: If synthetic pairs are too noisy or the teacher model generates inconsistent formalizations, the student model will learn incorrect patterns.

### Mechanism 3
- Claim: Typecheck rate is a reliable proxy metric for autoformalization accuracy during development.
- Mechanism: Since manual accuracy evaluation is costly, typecheck rate (proportion of generated statements that are well-formed in Lean's type theory) serves as a quick indicator of model progress.
- Core assumption: Models that generate more type-correct Lean code are more likely to eventually produce semantically correct formalizations.
- Evidence anchors:
  - [section 5.2]: "We recommend that typecheck rate be used as a predictor of autoformalization performance when evaluating accuracy is too costly."
  - [section 5.1]: "The PROOF GPT models do not formalize any statements correctly, likely owing to their smaller parameter count. However, they demonstrate some signal on the typecheck rate and BLEU metrics."
  - [corpus]: No direct evidence - this is a methodological claim based on internal validation.
- Break condition: If typecheck rate improves but semantic accuracy plateaus, the metric becomes misleading.

## Architecture Onboarding

- Component map:
  - Data pipeline: NL statement → candidate formalization (model) → typecheck → human evaluation
  - Retrieval system: Embedding DB of mathlib → nearest-neighbor search → augmented prompt
  - Training pipeline: Teacher LM → synthetic pairs → student fine-tuning
  - Evaluation: Typecheck rate, BLEU, accuracy, compile rate

- Critical path: NL statement → in-context learning → typecheck → human accuracy check
  - Most time-sensitive: Model inference and typechecking
  - Most resource-intensive: Human evaluation of accuracy

- Design tradeoffs:
  - Few-shot vs. fine-tuning: Few-shot is quick to implement but limited; fine-tuning requires synthetic data but scales better.
  - Retrieval vs. no retrieval: Retrieval improves accuracy but adds latency and complexity.
  - Typecheck as proxy: Fast but may not correlate perfectly with semantic correctness.

- Failure signatures:
  - Low typecheck rate: Model generates invalid Lean syntax.
  - High typecheck but low accuracy: Model generates valid but semantically wrong statements.
  - Repetitive looping: Model gets stuck generating the same phrase (observed in proofGPT models).

- First 3 experiments:
  1. Run in-context learning baseline on 10 random ProofNet examples and measure typecheck rate.
  2. Implement prompt retrieval with k=4 and compare typecheck rate vs. baseline.
  3. Generate synthetic backtranslations using Code-davinci-002 and fine-tune proofGPT-1.3B on them, then evaluate on same 10 examples.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the upper limit of autoformalization accuracy achievable with current large language models on the ProofNet benchmark?
- Basis in paper: [explicit] The authors report a 13.4% accuracy baseline using OpenAI's Code-davinci-002 model and note that performance drops significantly with smaller models like PROOF GPT 1.3B and 6.7B.
- Why unresolved: The paper establishes baseline performance but does not explore the full potential of scaling up model size or using more advanced architectures. The current results suggest room for improvement but do not indicate a ceiling.
- What evidence would resolve it: Systematic evaluation of autoformalization performance across a wide range of model sizes and architectures, particularly focusing on the largest available models and those specifically fine-tuned for mathematical reasoning.

### Open Question 2
- Question: How can the autoformalization process be made more robust to implicit mathematical assumptions and dependencies?
- Basis in paper: [explicit] The authors note in Case Study 3 that Code-davinci-002 fails to infer implicit hypotheses, such as the need for an inner product space structure in certain problems.
- Why unresolved: The paper identifies this as a significant challenge but does not propose or test solutions for automatically detecting and incorporating implicit assumptions during autoformalization.
- What evidence would resolve it: Development and evaluation of methods that can automatically identify and incorporate implicit mathematical assumptions, potentially through enhanced prompting strategies or auxiliary models trained to detect such dependencies.

### Open Question 3
- Question: What is the most effective way to combine prompt retrieval and distilled backtranslation techniques for autoformalization?
- Basis in paper: [explicit] The authors introduce both prompt retrieval and distilled backtranslation as separate methods that improve autoformalization performance, but do not explore their combination.
- Why unresolved: The paper demonstrates that each technique independently improves performance, but does not investigate whether their combination could lead to synergistic effects or diminishing returns.
- What evidence would resolve it: Experiments comparing autoformalization performance using prompt retrieval, distilled backtranslation, and their combination, with analysis of the relative contributions and potential interactions between the two methods.

## Limitations

- Data Representativeness: ProofNet's 371 examples represent a limited sample of undergraduate mathematics, potentially limiting generalizability to broader mathematical domains.
- Metric Validity: Typecheck rate may not perfectly correlate with semantic correctness, raising questions about its reliability as a development proxy.
- Generalizability: Methods are evaluated only on undergraduate pure mathematics and may not transfer to other domains or more advanced mathematics.

## Confidence

**High Confidence**: The basic autoformalization task definition and ProofNet benchmark construction; the general approach of using few-shot learning with large language models; the observation that larger models (Code-davinci-002 vs PROOF GPT) perform better in in-context learning.

**Medium Confidence**: The effectiveness of prompt retrieval in improving autoformalization performance; the distilled backtranslation approach for training autoformalization models without parallel data; the recommendation to use typecheck rate as a development proxy.

**Low Confidence**: The scalability of prompt retrieval to larger, more diverse mathematical corpora; the quality and consistency of synthetic backtranslations for fine-tuning; the generalizability of findings to other mathematical domains beyond undergraduate pure mathematics.

## Next Checks

1. **Correlation Validation**: Systematically measure the correlation between typecheck rate and actual semantic accuracy across different mathematical domains and model architectures. This should include cases where typecheck rate improves but semantic accuracy does not, to establish the limits of typecheck rate as a proxy metric.

2. **Retrieval Quality Analysis**: Evaluate the semantic quality of retrieved examples by measuring how often the k-nearest neighbors from mathlib are actually relevant to the current formalization attempt. This should include analysis of embedding space quality and retrieval parameters (k value, embedding model choice).

3. **Synthetic Data Quality Assessment**: Conduct a detailed error analysis of synthetic backtranslations generated by the teacher model. Measure the consistency of different formalization approaches for the same natural language statement and assess how these inconsistencies affect the student model's learning.
