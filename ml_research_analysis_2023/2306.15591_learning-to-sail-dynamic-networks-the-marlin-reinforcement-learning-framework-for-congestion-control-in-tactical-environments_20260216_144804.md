# Learning to Sail Dynamic Networks: The MARLIN Reinforcement Learning Framework for Congestion Control in Tactical Environments

## Quick Facts
- arXiv ID: 2306.15591
- Source URL: https://arxiv.org/abs/2306.15591
- Reference count: 16
- Key result: RL-based MARLIN outperforms TCP Cubic and Mockets in tactical networks with lower RTT Transition Impact (RTI) and retransmission rates during link transitions

## Executive Summary
This paper addresses the challenge of congestion control in tactical networks, which feature dynamic link transitions between satellite (SATCOM) and UHF radio communications. Traditional TCP-based solutions struggle with these rapidly changing conditions, leading to suboptimal performance. The authors propose MARLIN, a reinforcement learning framework that trains an agent to adapt congestion control policies in emulation environments that accurately model tactical network behaviors. By introducing a custom reward function and the RTT Transition Impact (RTI) metric, MARLIN achieves superior performance in file transfers under link transitions, with significantly lower retransmission rates and better responsiveness to changing network conditions compared to TCP Cubic and Mockets.

## Method Summary
The MARLIN framework trains an RL agent using Soft Actor-Critic algorithm in a containerized emulation environment built with Containernet and Docker. The agent learns to control congestion window size through continuous actions based on a 14-dimensional state representation including statistics like mean, standard deviation, min, max, and EMA of network metrics. The training environment simulates tactical network conditions including SATCOM-to-UHF link transitions, with specific bandwidth (256Kbps), delay (600ms SATCOM, 100ms UHF), and packet loss characteristics. A custom reward function penalizes retransmissions while incentivizing efficient bandwidth utilization. The framework introduces the RTI metric to evaluate agent performance during link transitions, measuring maximum RTT normalized for each link separately.

## Key Results
- MARLIN achieves RTI of 0.25 compared to 0.31 for TCP Cubic and 0.38 for Mockets during SATCOM-to-UHF transitions
- Under 3% packet loss, MARLIN maintains lower retransmission rates (12.22) versus TCP Cubic (53.1) and Mockets (141.93)
- MARLIN shows competitive file transfer completion times while demonstrating superior queue management and responsiveness to link changes

## Why This Works (Mechanism)

### Mechanism 1
- Claim: MARLIN's RL agent generalizes better than TCP Cubic and Mockets by learning from complex, emulated network scenarios.
- Mechanism: The agent is trained in a parallelizable emulation environment that replicates tactical network behaviors, including link transitions between SATCOM and UHF radio links, enabling exposure to dynamic and unpredictable conditions.
- Core assumption: The emulation environment accurately models real tactical network behaviors and link transitions.
- Evidence anchors:
  - [abstract] "proposes an RL framework that leverages an accurate and parallelizable emulation environment to reenact the conditions of a tactical network"
  - [section] "we trained an RL agent in an emulated environment replicating a bottleneck link transition between a SATCOM link and an UHF radio link"
- Break condition: If the emulation environment fails to accurately model real network dynamics, the agent's learned policy may not generalize well to actual tactical networks.

### Mechanism 2
- Claim: MARLIN's custom reward function effectively incentivizes efficient bandwidth utilization and minimizes retransmissions.
- Mechanism: The reward function incorporates penalties for retransmissions and rewards based on efficient link utilization, encouraging the agent to adapt its congestion window size dynamically.
- Core assumption: The reward function accurately captures the trade-offs between throughput and reliability in tactical networks.
- Evidence anchors:
  - [section] "We designed a reward function incorporating penalties based on retransmissions...reward functions can be devised to both confer greater rewards as the agent progressively approaches the optimal utilization of the available bandwidth"
- Break condition: If the reward function does not adequately balance the trade-offs between throughput and reliability, the agent may learn suboptimal policies that prioritize one metric at the expense of the other.

### Mechanism 3
- Claim: The RTT Transition Impact (RTI) metric provides a more accurate assessment of agent performance in dynamic link conditions.
- Mechanism: RTI measures the maximum RTT normalized for each link separately during a communication involving a link transition, capturing the agent's responsiveness to link changes and queue management capabilities.
- Core assumption: RTI effectively captures the agent's ability to adapt to changing link characteristics and manage network queues.
- Evidence anchors:
  - [section] "we designed a novel metric called the RTT Transition Impact (RTI)...By considering individual link measurements, the RTI provides insights into the impact of link changes on the performance of the CC algorithm"
- Break condition: If RTI does not accurately reflect the agent's performance in dynamic link conditions, it may lead to incorrect conclusions about the effectiveness of the congestion control policy.

## Architecture Onboarding

- Component map: Emulation Environment -> RL Agent -> Policy Evaluation (RTI and transfer time metrics)
- Critical path: Emulation environment → RL agent training → Policy evaluation using RTI and transfer time metrics
- Design tradeoffs:
  - Accuracy vs. efficiency: Balancing the fidelity of the emulation environment with the computational cost of training
  - Generalization vs. specialization: Designing a reward function that encourages both efficient bandwidth utilization and adaptability to diverse network conditions
  - Interpretability vs. performance: Choosing performance metrics that accurately capture agent behavior while being easy to understand and compare
- Failure signatures:
  - Poor generalization: Agent performs well in training environment but fails to adapt to real tactical networks
  - Suboptimal policies: Agent learns to prioritize throughput at the expense of reliability, or vice versa
  - Inefficient training: High computational cost or slow convergence of the RL algorithm
- First 3 experiments:
  1. Baseline comparison: Evaluate MARLIN against TCP Cubic and Mockets in a simple emulation environment with static link conditions
  2. Link transition scenario: Assess MARLIN's performance during a simulated transition between SATCOM and UHF radio links, measuring RTI and transfer time
  3. Packet loss variation: Test MARLIN's robustness to varying levels of random packet loss in the UHF link, comparing performance against baseline algorithms

## Open Questions the Paper Calls Out
- How does the MARLIN RL agent perform in tactical network scenarios with multiple bottleneck links and more complex topologies compared to its performance in the current dumbbell topology?
- How does the MARLIN agent adapt to sudden changes in background traffic patterns, such as the introduction of new high-bandwidth UDP flows or the cessation of existing flows, during a communication session?
- How does the MARLIN agent's performance scale with the size of the congestion window (CWND) and the maximum payload size in tactical network environments?

## Limitations
- The emulation environment may not fully capture the complexity and unpredictability of real tactical networks, particularly regarding mobility patterns and dynamic interference conditions
- Evaluation focuses on specific link transition scenarios between SATCOM and UHF links, with limited testing across diverse tactical network topologies
- Comparison with TCP Cubic and Mockets is conducted in simulation rather than real-world tactical network deployments

## Confidence
- High confidence in the RL framework design and implementation details
- Medium confidence in the RTI metric's effectiveness as a performance measure
- Medium confidence in the generalization claims based on emulation results
- Low confidence in real-world tactical network performance without field testing
