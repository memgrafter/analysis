# ASQ-IT: Interactive Explanations for Reinforcement-Learning Agents

## Quick Facts
- arXiv ID: 2301.09941
- Source URL: https://arxiv.org/abs/2301.09941
- Authors: 
- Reference count: 13
- Primary result: Interactive query-based explanations improve user ability to identify faulty agent behaviors compared to static policy summaries

## Executive Summary
This paper introduces ASQ-IT, an interactive tool that enables users to explore reinforcement learning agent behaviors through temporal logic-based queries. The system translates user-friendly menu selections into Linear Temporal Logic over finite traces (LTLf) formulas, processes these queries using automata-based algorithms, and retrieves relevant video clips from a database of agent executions. Two user studies demonstrate that ASQ-IT helps users identify faulty agent behaviors more effectively than static explanations while maintaining user satisfaction and confidence calibration.

## Method Summary
ASQ-IT maps user-friendly drop-down menus to a fragment of LTLf formulas, which are then processed using automata theory. The system constructs deterministic finite automata (DFAs) for both the user's query and "eventually the query," then searches execution traces in both forward and backward directions to locate matching sub-traces. The tool maintains a database of abstract traces (sets of predicates) paired with corresponding video clips, enabling users to iteratively refine queries based on returned results.

## Key Results
- Laypeople successfully understood and used the system to generate meaningful temporal queries
- Users identified faulty agent behaviors more effectively using ASQ-IT compared to static policy summaries
- Users reported higher satisfaction and better confidence calibration with interactive explanations versus static baselines

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Users can express complex temporal behaviors through simplified LTLf fragments without formal logic training
- Core assumption: Constrained menu options map effectively to LTLf formulas
- Evidence: System maps drop-downs to LTLf, but corpus lacks specific evidence about user comprehension results
- Break condition: Users cannot formulate meaningful queries through menu system

### Mechanism 2
- Claim: Automata-based algorithm efficiently retrieves relevant video clips in linear time
- Core assumption: Trace database is comprehensive and automata search is efficient
- Evidence: Algorithm described as linear time, but corpus lacks evidence about specific method's efficiency
- Break condition: Trace length too large for linear processing or automaton construction becomes prohibitive

### Mechanism 3
- Claim: Interactive query refinement improves debugging effectiveness over static explanations
- Core assumption: Users can formulate better queries after seeing initial results
- Evidence: User studies showed improved performance vs static summaries, but small sample sizes limit generalizability
- Break condition: Users cannot formulate meaningful follow-up queries or system cannot handle multiple refinements

## Foundational Learning

- Concept: Linear Temporal Logic over Finite Traces (LTLf)
  - Why needed here: Provides formal foundation for expressing temporal properties of finite agent traces
  - Quick check question: What is the difference between LTLf and standard LTL, and why is LTLf more appropriate for reasoning about finite agent traces?

- Concept: Deterministic Finite Automata (DFA) and language recognition
  - Why needed here: DFAs efficiently process LTLf queries and match against stored traces
  - Quick check question: How does a DFA recognize whether a given trace satisfies an LTLf formula, and what is the relationship between LTLf formulas and DFAs?

- Concept: Reinforcement Learning policy representation and execution traces
  - Why needed here: Understanding how RL agents generate execution traces is essential for constructing the trace database
  - Quick check question: What is the relationship between an RL policy, MDP states, and execution traces, and how are these traces used in the ASQ-IT system?

## Architecture Onboarding

- Component map: Query Interface -> Query Translator -> LTLf Processor -> Query Engine -> Trace Database -> Result Presenter
- Critical path: User query → Query Translator → LTLf Processor → Query Engine → Trace Database → Result Presenter
- Design tradeoffs:
  - Expressivity vs. usability: More complex LTLf fragments provide greater expressivity but may overwhelm users
  - Trace storage vs. query performance: Storing more traces improves coverage but increases search time
  - Video clip length vs. relevance: Longer clips provide more context but may include irrelevant behavior
- Failure signatures:
  - Empty result sets: Query too specific or trace database lacks matching content
  - Slow query response: Trace database too large or automaton construction inefficient
  - User confusion: Menu options unclear or LTLf fragment insufficiently expressive
- First 3 experiments:
  1. Implement basic version with single predicate and test complete query processing pipeline
  2. Add multiple predicates and test query translator's ability to construct correct LTLf formulas
  3. Populate trace database with simulated agent traces and test end-to-end query processing with actual video clips

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal balance between expressivity and usability in interactive XRL interfaces?
- Basis in paper: Paper discusses challenge of balancing expressivity and usability, noting pilot studies guided iterative design
- Why unresolved: No empirical comparison of different interface designs or A/B testing conducted
- What evidence would resolve it: Controlled experiments comparing multiple interface designs with varying levels of expressivity and usability metrics

### Open Question 2
- Question: How can ASQ-IT be extended to support more abstract queries about agent behavior beyond state predicates?
- Basis in paper: Paper mentions future work could explore language for describing more abstract queries (e.g., "risky" behaviors)
- Why unresolved: Current implementation only supports queries based on predefined state predicates
- What evidence would resolve it: Implementing and testing prototype that supports abstract query types, then evaluating user performance and satisfaction

### Open Question 3
- Question: How does ASQ-IT's performance scale with larger state spaces and more complex agents?
- Basis in paper: Paper does not discuss scalability issues
- Why unresolved: User studies focused on simple highway domain, no analysis conducted with more complex agents or larger state spaces
- What evidence would resolve it: Testing ASQ-IT with increasingly complex agents and state spaces, measuring both algorithmic performance and user experience metrics

## Limitations

- Small sample sizes in user studies (11 participants in study 1, 6 in study 2) limit statistical generalizability
- Implementation details of LTLf-to-DFA conversion and automata-based search algorithm are not provided
- Performance and usability with larger state spaces and more complex agents is unexplored

## Confidence

- Core contribution (interactive query-based explanations): Medium
- Specific implementation details: Low
- Comparative advantage over static baselines: Medium
- Scalability to complex domains: Low
