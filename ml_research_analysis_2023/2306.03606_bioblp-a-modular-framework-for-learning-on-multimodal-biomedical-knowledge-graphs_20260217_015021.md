# BioBLP: A Modular Framework for Learning on Multimodal Biomedical Knowledge Graphs

## Quick Facts
- arXiv ID: 2306.03606
- Source URL: https://arxiv.org/abs/2306.03606
- Reference count: 40
- Key outcome: BioBLP framework achieves competitive link prediction performance, particularly for low-degree entities, by incorporating heterogeneous biomedical entity attributes while supporting missing data.

## Executive Summary
This paper introduces BioBLP, a modular framework for learning embeddings in knowledge graphs with heterogeneous entity attributes. The framework addresses limitations of existing methods that assume homogeneous attributes or ignore attribute data entirely. BioBLP incorporates entity attributes of different modalities (protein sequences, molecular graphs, textual descriptions) while supporting entities with missing attributes. The authors propose an efficient pretraining strategy to reduce training runtime. Experiments on a biomedical KG containing approximately 2 million triples show that BioBLP yields competitive performance on link prediction tasks, particularly for low-degree entities, and achieves favorable results in drug-protein interaction prediction.

## Method Summary
BioBLP is a modular framework that learns embeddings for knowledge graphs with heterogeneous entity attributes. The framework uses modality-specific encoders (ProtTrans for proteins, MolTrans for molecules, BioBERT for text) to map attribute data into a shared embedding space, with lookup table embeddings for entities missing attributes. A key innovation is a pretraining strategy that first trains on graph structure alone, then fine-tunes with attribute encoders, reducing training time while improving performance. The framework supports multiple scoring functions (TransE, ComplEx, RotatE) and is evaluated on link prediction and drug-protein interaction prediction tasks using the BioKG dataset.

## Key Results
- BioBLP achieves competitive link prediction performance compared to state-of-the-art baselines
- The framework shows particular strength on low-degree entities where traditional methods struggle
- Pretraining strategy significantly improves performance while reducing required training runtime
- BioBLP achieves favorable results in drug-protein interaction prediction tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Pretraining on the graph structure alone before optimizing attribute encoders improves convergence speed and final performance.
- Mechanism: Pretraining initializes lookup table embeddings with structure-based knowledge, so attribute encoders adapt from a good baseline instead of random embeddings.
- Core assumption: Structure-only embeddings capture useful graph patterns that attribute encoders can refine, and that initialization matters for multimodal optimization.
- Evidence anchors:
  - [section]: "Step 1 is much cheaper to run since it does not make use of any attribute encoders... Once the relevant modules are transferred to BioBLP, less training steps are required and the resulting performance is higher..."
  - [section]: "Our proposed pretraining strategy yields significantly higher performance while reducing the required training runtime."
- Break condition: If pretraining introduces distribution shift between graph-only and multimodal embeddings, or if attribute encoders are too expressive to benefit from coarse graph initialization.

### Mechanism 2
- Claim: Modular encoders for each modality allow the model to handle heterogeneous attribute data without forcing a common representation.
- Mechanism: Each modality has a specialized encoder (ProtTrans for proteins, MolTrans for molecules, BioBERT for text) that maps directly into a shared embedding space.
- Core assumption: Modality-specific architectures extract meaningful features that align in a common space, and that encoders can be optimized independently before integration.
- Evidence anchors:
  - [abstract]: "allows encoding attribute data of different modalities while also supporting entities with missing attributes."
  - [section]: "we define encoders for these three types. Recent works have demonstrated the effect of using pretrained embeddings..."
- Break condition: If modality-specific encoders cannot align well in the shared space, leading to poor multimodal fusion and degraded link prediction.

### Mechanism 3
- Claim: Supporting missing attribute data via lookup table embeddings for such entities maintains coverage across the entire KG.
- Mechanism: Entities without attributes fall back to randomly initialized (or pretrain-initialized) embeddings in the same space as attribute-encoder outputs.
- Core assumption: Missing-attribute entities still benefit from structure-only patterns learned during pretraining, and that uniform embedding space avoids modality mismatches.
- Evidence anchors:
  - [abstract]: "...while also supporting entities with missing attributes."
  - [section]: "For entities that are missing attribute data, we employ a lookup table of embeddings... When attributes are not available at all, BioBLP reduces to lookup table embedding methods..."
- Break condition: If the proportion of missing-attribute entities is too large, lookup table embeddings may dominate learning and limit multimodal benefits.

## Architecture Onboarding

- Component map: BioBLP = (Protein Encoder, Molecule Encoder, Disease Encoder, Lookup Table for Others, Relation Embeddings, Scoring Function, Loss Function). Each encoder processes its modality-specific input into the shared embedding space; missing attributes use lookup table rows.
- Critical path: Input → Modality Encoder Lookup Table → Shared Space → Scoring Function → Loss → Gradient Update → Parameters (encoders + lookup table).
- Design tradeoffs: Encoder expressiveness vs. training cost; pretraining vs. from-scratch; modality alignment vs. representation capacity.
- Failure signatures: Low MRR on low-degree entities → degree bias; sudden MRR drop during training → modality misalignment or exploding gradients; poor pretraining benefit → distribution shift between pretrain and multimodal phases.
- First 3 experiments:
  1. Train RotatE baseline on BioKG to establish link prediction performance without attributes.
  2. Train BioBLP-D (disease encoder only) with and without pretraining; compare MRR and convergence curves.
  3. Train BioBLP-M (molecule encoder only) with pretraining; analyze molecule embedding quality and link prediction drops relative to RotatE baseline.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can we design more expressive and scalable encoders for protein sequences in BioBLP to improve performance compared to the current ProtTrans-based approach?
- Basis in paper: [explicit] The paper notes that BioBLP-P (protein encoder) performs worse than the Structural baseline and other BioBLP variants, suggesting further improvements are needed for protein sequence encoding.
- Why unresolved: The current ProtTrans-based encoder is not optimized due to memory constraints, and the paper does not explore alternative architectures or pretraining strategies for protein encoders.
- What evidence would resolve it: Experiments comparing BioBLP-P performance with different protein encoder architectures (e.g., incorporating attention mechanisms, varying embedding dimensions, or exploring alternative pretraining tasks) and demonstrating improved link prediction and drug-protein interaction prediction results.

### Open Question 2
- Question: Can BioBLP be effectively applied in an inductive setting where new entities are added to the knowledge graph after training?
- Basis in paper: [explicit] The paper mentions that a useful property of BioBLP is its ability to encode arbitrary entities, but the focus is on comparing lookup table embeddings with BioBLP in a transductive setting. The inductive setting is only briefly mentioned as a potential future direction.
- Why unresolved: The paper does not provide experiments or analysis on BioBLP's performance in an inductive setting, leaving the question of its effectiveness in this scenario unanswered.
- What evidence would resolve it: Experiments evaluating BioBLP's link prediction and drug-protein interaction prediction performance on a held-out test set containing entities not seen during training, comparing it to the performance of lookup table embedding methods in the same setting.

### Open Question 3
- Question: How does the choice of scoring function impact BioBLP's performance when incorporating different modalities of entity attributes?
- Basis in paper: [explicit] The paper experiments with three scoring functions (TransE, ComplEx, and RotatE) and observes that RotatE generally performs best, but the impact of the scoring function choice on BioBLP's performance with different attribute encoders (protein, molecule, disease) is not thoroughly analyzed.
- Why unresolved: The paper does not provide a detailed analysis of how the scoring function interacts with the attribute encoders, leaving the question of the optimal scoring function for each modality open.
- What evidence would resolve it: A comprehensive study comparing BioBLP's performance with different scoring functions for each attribute encoder (protein, molecule, disease) on both link prediction and drug-protein interaction prediction tasks, identifying the best scoring function for each modality.

## Limitations
- Evaluation focuses on a single biomedical KG (BioKG), limiting generalizability to other domains
- Paper does not provide comprehensive ablation studies on the importance of each modality encoder or the pretraining strategy
- Performance comparisons are limited to standard link prediction metrics without extensive error analysis or qualitative assessment of learned embeddings

## Confidence
- **High confidence**: The modular framework design and its ability to handle heterogeneous attributes with missing data is well-supported by the architecture description and experimental results.
- **Medium confidence**: The pretraining strategy's effectiveness is demonstrated but lacks detailed analysis of its impact on different entity types or modalities.
- **Low confidence**: Claims about BioBLP's superiority for low-degree entities are based on aggregate metrics without per-entity analysis.
