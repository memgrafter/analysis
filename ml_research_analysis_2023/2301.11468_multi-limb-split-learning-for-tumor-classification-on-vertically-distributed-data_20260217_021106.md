# Multi-limb Split Learning for Tumor Classification on Vertically Distributed Data

## Quick Facts
- arXiv ID: 2301.11468
- Source URL: https://arxiv.org/abs/2301.11468
- Reference count: 28
- Primary result: Achieved 90.688% training accuracy and 70.250% test accuracy on vertically distributed brain tumor classification

## Executive Summary
This paper introduces a multi-limb split learning approach for classifying brain tumors on vertically distributed MRI data. The method splits neural network training between multiple hospitals, with each hospital processing different halves of the same MRI images and only sharing activation outputs with a central server. This preserves patient privacy while enabling collaborative learning across institutions. The approach uses minimal local computation at each hospital site, with the heavy lifting performed by the server.

## Method Summary
The approach uses vertical data partitioning where different hospitals hold different halves of the same MRI images. Each hospital processes their local image half through a simple client-side network (one layer with ReLU activation) up to a defined cut layer, then sends only the activation outputs to a central server. The server completes the forward pass and backpropagation, sending gradients back to update local models. This architecture preserves privacy by ensuring raw images never leave hospital premises while enabling collaborative training. The method was tested on 2000 MRI images (1600 training, 400 testing), achieving 90.688% training accuracy and 70.250% test accuracy.

## Key Results
- Achieved 90.688% training accuracy and 70.250% test accuracy on vertically distributed brain tumor dataset
- Successfully implemented multi-limb split learning architecture across multiple hospitals
- Demonstrated privacy preservation by sharing only activation outputs rather than raw MRI images

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Splitting the neural network into client-side and server-side components reduces computational burden at each hospital while preserving data privacy
- Mechanism: The client-side performs initial processing up to a defined cut layer, sending only the activation (smashed data) to the server. The server completes the forward pass and backpropagation, sending gradients back to the client-side. This divides the computational workload and ensures raw MRI images never leave hospital premises
- Core assumption: The cut layer is chosen such that the smashed data contains sufficient information for the server to complete accurate classification without needing the raw image

## Architecture Onboarding

- Component map: Hospital 1 Client -> Cut layer activation -> Server -> Hospital 2 Client -> Cut layer activation
- Critical path: 1. Hospitals process local image halves to cut layer 2. Hospitals send smashed data to server 3. Server completes forward pass and backpropagation 4. Server sends gradients back to hospitals 5. Hospitals update local models 6. Repeat until convergence
- Design tradeoffs:
  - Computational efficiency vs. model complexity: Using minimal client-side layers reduces hospital burden but may limit feature extraction capability
  - Privacy vs. accuracy: More aggressive data partitioning improves privacy but may reduce classification accuracy
  - Communication overhead vs. synchronization: Frequent gradient exchanges enable faster convergence but increase network communication
- Failure signatures:
  - Training accuracy plateaus early despite continued training
  - Test accuracy significantly lower than training accuracy (overfitting or insufficient feature extraction)
  - Large discrepancy between hospitals' local model performance
  - Communication failures between hospitals and server
- First 3 experiments:
  1. Baseline experiment: Train on complete images with conventional CNN to establish maximum achievable accuracy
  2. Split position experiment: Vary the cut layer position to find optimal balance between local computation and smashed data informativeness
  3. Client architecture experiment: Test different client-side architectures (number of layers, activation functions) to optimize the privacy-accuracy tradeoff

## Limitations
- 70.25% test accuracy is significantly lower than typical single-institution CNN approaches (85-95%)
- Lacks detailed implementation specifics, particularly regarding cut layer position and hyperparameter settings
- Vertical data distribution effectiveness depends heavily on how informative image halves remain after splitting
