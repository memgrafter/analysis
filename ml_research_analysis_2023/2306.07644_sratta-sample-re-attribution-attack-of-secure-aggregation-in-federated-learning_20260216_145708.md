# SRATTA : Sample Re-ATTribution Attack of Secure Aggregation in Federated Learning

## Quick Facts
- arXiv ID: 2306.07644
- Source URL: https://arxiv.org/abs/2306.07644
- Reference count: 40
- SRATTA presents a novel data reconstruction attack that recovers individual samples and groups them by client in federated learning with secure aggregation.

## Executive Summary
SRATTA introduces a novel attack that breaks the privacy guarantees of secure aggregation in federated learning by reconstructing individual training samples and attributing them to specific clients. The attack exploits the structure of fully connected first-layer models, where neurons with small activation sets reveal information about the training data. By analyzing round-level update ratios and activation patterns, the attacker can recover isolated samples, reconstruct small activation sets using orthogonal matching pursuit, and group samples by client. The attack demonstrates high recovery rates (0.476-0.585) across multiple datasets including CIFAR10, FashionMNIST, DNA, and TCGA, while remaining effective under varying data heterogeneity conditions.

## Method Summary
SRATTA operates in three distinct phases to reconstruct and attribute training samples in federated learning systems using secure aggregation. First, the attack analytically recovers isolated samples by exploiting round-level update ratios, where neurons with very small activation sets (typically one sample) can be identified and reconstructed. Second, for neurons with small activation sets, the attack employs orthogonal matching pursuit to reconstruct the samples based on gradient information. Third, the attack groups samples by client by tracking activation patterns across multiple training rounds, leveraging the fact that each client's samples activate the same neurons consistently. The attack assumes the server knows ground truth gradients and that the first layer uses a fully connected architecture with untrained weights, conditions that enable the mathematical reconstruction framework.

## Key Results
- Sample recovery rates of 0.476-0.585 across CIFAR10, FashionMNIST, DNA, and TCGA datasets
- Successful grouping of recovered samples by client with V_normalized scores up to 0.490
- Attack effectiveness maintained under varying data heterogeneity conditions
- Defense mechanism using active censoring of small activation set updates prevents reconstruction while preserving model accuracy

## Why This Works (Mechanism)
The attack exploits the fundamental vulnerability that in fully connected first-layer models, neurons with small activation sets reveal information about the training data. When a neuron is activated by only a few samples across all clients, the gradient updates contain information specific to those samples. By analyzing the ratio of update values across training rounds and leveraging the sparsity of activations, the attacker can isolate and reconstruct individual samples. The grouping capability emerges from tracking which samples consistently activate the same neurons for a given client across multiple rounds, enabling client attribution even under secure aggregation.

## Foundational Learning
- Federated Learning (FL): Distributed machine learning where clients train locally and share model updates - needed to understand the attack surface and privacy assumptions
- Secure Aggregation (SA): Protocol ensuring only aggregated model updates are visible to server - quick check: verify SA prevents gradient-level privacy leakage
- Orthogonal Matching Pursuit (OMP): Greedy algorithm for sparse signal reconstruction - quick check: validate OMP performance on small activation sets
- Gradient Analysis: Mathematical framework for extracting information from model updates - quick check: confirm gradient sparsity assumptions hold in practice
- Activation Patterns: Neuron activation behavior across training samples - quick check: measure activation set sizes in first layer
- Data Heterogeneity: Variation in data distribution across clients - quick check: test attack under different non-IID scenarios

## Architecture Onboarding

Component Map:
Client devices -> Local training -> Gradient computation -> Secure aggregation -> Server aggregation -> Model update -> SRATTA attack phases

Critical Path:
1. Local training with small activation set neurons
2. Gradient aggregation via secure aggregation
3. Update ratio analysis and OMP reconstruction
4. Sample grouping by activation pattern tracking

Design Tradeoffs:
- Attack effectiveness vs. first layer architecture constraints
- Reconstruction accuracy vs. computational complexity of OMP
- Privacy guarantees vs. model accuracy in proposed defense
- Attack scalability vs. dataset size and number of clients

Failure Signatures:
- Low activation set sparsity reduces attack effectiveness
- Convolutional or pre-trained first layers prevent reconstruction
- Large number of clients dilutes update ratio signals
- High data heterogeneity disrupts consistent activation patterns

3 First Experiments:
1. Measure activation set sizes in first layer for different datasets
2. Test OMP reconstruction accuracy on synthetic small activation sets
3. Evaluate update ratio analysis sensitivity to varying client counts

## Limitations
- Assumes server has knowledge of ground truth gradients, requiring additional coordination mechanisms
- Computational complexity of OMP-based reconstruction scales poorly with dataset size
- Effectiveness depends heavily on first layer being fully connected and untrained
- Defense mechanism introduces privacy-utility trade-offs requiring further evaluation

## Confidence
High: Theoretical framework and mathematical derivations
Medium: Experimental results with small-scale datasets
Low: Generalizability to large-scale, heterogeneous FL deployments and practicality of defenses
