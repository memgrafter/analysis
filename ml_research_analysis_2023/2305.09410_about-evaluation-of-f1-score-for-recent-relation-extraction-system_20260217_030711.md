# About Evaluation of F1 Score for RECENT Relation Extraction System

## Quick Facts
- arXiv ID: 2305.09410
- Source URL: https://arxiv.org/abs/2305.09410
- Authors: 
- Reference count: 8
- Primary result: Corrected F1 score dropped from 75.2 to 65.16 after fixing evaluation loophole

## Executive Summary
The RECENT relation extraction system claimed state-of-the-art performance on TACRED dataset by splitting the task into subsets based on entity types, using binary classifiers for simple cases and specialized semantic classifiers for complex ones. However, an evaluation loophole led to artificially inflated F1 scores: samples incorrectly passed to semantic classifiers but not found in pre-computed results were labeled as "no relation" without actual classification. After correcting this flaw, the F1 score dropped significantly from 75.2 to 65.16, revealing the original results were misleading. The method, while conceptually promising, did not yield the expected performance gain, likely due to reduced training data per classifier.

## Method Summary
The RECENT system splits relation extraction into 13 complex subsets based on entity type pairs and simpler subsets for other cases. It uses a binary classifier to filter obvious "no relation" cases, then routes remaining samples to specialized semantic classifiers based on entity type pairs. During evaluation, the system uses pre-computed partial results stored in files to avoid loading all models simultaneously. The approach aims to reduce task complexity per classifier by focusing on homogeneous subsets, but suffers from data efficiency issues when training on smaller subsets.

## Key Results
- Original reported F1 score: 75.2 (inflated due to evaluation loophole)
- Corrected F1 score after fixing evaluation: 65.16
- Performance drop reveals evaluation flaw rather than actual system capability
- Conceptual decomposition strategy shows promise but data efficiency limits gains

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Binary classifier filtering allows semantic classifiers to focus on more complex relation types, improving performance by reducing task complexity per classifier.
- Mechanism: The system first uses a binary classifier to filter out obvious "no relation" cases. For remaining cases, it routes them to specialized semantic classifiers based on entity type pairs. This decomposition reduces the output space for each classifier.
- Core assumption: Specialized classifiers trained on smaller, more homogeneous subsets will perform better than a single general classifier.
- Evidence anchors:
  - [abstract] "The core idea was to split the task into subsets based on entity types, using binary classifiers for simple cases and specialized semantic classifiers for more complex ones."
  - [section 3] "So we can regroup the data into the independent subsets, where each subset contains sentences with just one pair of types of subject and object...we can decompose the whole task of relations extraction to many similar smaller independent tasks and train a specific, separate semantic classifier for each such subset."
- Break condition: If binary classifier error rate is high, it will pass incorrect samples to semantic classifiers, and since semantic classifiers cannot output "no relation," these become false positives.

### Mechanism 2
- Claim: Pre-computed results from semantic classifiers during evaluation phase avoids runtime model loading overhead.
- Mechanism: During evaluation, instead of loading all semantic classifiers into memory simultaneously, the system pre-computes results for each subset and stores them in partial result files. During evaluation, it simply looks up these pre-computed results.
- Core assumption: Pre-computation doesn't introduce evaluation bias and provides equivalent results to on-the-fly classification.
- Evidence anchors:
  - [section 5] "Actually, in the third step, the semantic classifiers are not used. Very likely to avoid a situation where all the models for semantic classifiers are present in the memory at the same time...the results are stored in 'partial final result files', and then, in step 3, the values contained in files are used as final predictions for the more complicated subsets."
- Break condition: If pre-computed files are incomplete or contain errors, evaluation results will be incorrect.

### Mechanism 3
- Claim: The loophole in evaluation artificially inflated F1 scores by treating missing entries in pre-computed files as "no relation" rather than false negatives.
- Mechanism: When a sample classified by the binary classifier as having a relation is not found in the pre-computed results file, the system assigns it "no relation" rather than treating it as a false positive. This happens because samples with actual "no relation" were filtered out during pre-computation.
- Core assumption: Missing entries in pre-computed files should be treated as false positives rather than "no relation."
- Evidence anchors:
  - [section 5] "3.2 otherwise the final answer is set to 'no relation'...It is not mentioned in the article but it is how the code works...Since the binary classifier allowed the sample to pass through, there should be a meaningful answer. How can it be that for samples classified by the binary classifier as the ones that should be associated with a relation...the system is coded to give an answer as no relation?"
  - [section 5.1] "Why it is not found there? It is not there because during preprocessing - as described at the end of paragraph 4.2 - all samples with 'no relation' were filtered out from the test data."

## Architecture Onboarding

- Component map: Binary Classifier → Entity Type Router → Pre-computed Results Lookup → Final Classification
- Critical path: Binary Classifier → Entity Type Router → Pre-computed Results Lookup → Final Classification
- Design tradeoffs:
  - Memory vs. Speed: Pre-computation saves memory but adds preprocessing overhead
  - Model Complexity vs. Data Efficiency: Specialized classifiers are simpler but trained on less data
  - Evaluation Accuracy vs. Implementation Simplicity: The loophole simplified implementation but compromised accuracy
- Failure signatures:
  - Low precision but high recall: Binary classifier is too permissive, passing many "no relation" cases
  - Low recall but high precision: Binary classifier is too strict, filtering out valid relations
  - Inconsistent results between runs: Pre-computation files are not properly synchronized with classifier versions
- First 3 experiments:
  1. Reproduce the original results with the loophole to verify the 75.2 F1 score
  2. Close the loophole by always passing to semantic classifiers and verify the 65.16 F1 score
  3. Test different binary classifier thresholds to find optimal balance between filtering and recall

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Would the RECENT system's performance improve if the binary classifier were made more accurate, reducing false positives that incorrectly pass samples to semantic classifiers?
- Basis in paper: [explicit] The paper notes that the binary classifier is not perfect and allows samples incorrectly classified as having meaningful relations to pass through, which are then labeled as "no relation" based on their absence in pre-computed results
- Why unresolved: The paper does not explore whether improving the binary classifier's accuracy would meaningfully impact overall F1 score, focusing instead on the evaluation loophole
- What evidence would resolve it: Testing the RECENT system with an improved binary classifier (e.g., through better training data, architecture, or hyperparameter tuning) and measuring the resulting F1 score

### Open Question 2
- Question: Could the RECENT system's performance be improved by allowing semantic classifiers to output "no relation" labels, rather than filtering them out during training?
- Basis in paper: [explicit] The paper states that semantic classifiers were trained without "no relation" labels and are incapable of outputting this label, which creates the evaluation loophole
- Why unresolved: The authors did not explore modifying the semantic classifiers to handle "no relation" cases directly, instead focusing on correcting the evaluation methodology
- What evidence would resolve it: Retraining semantic classifiers to include "no relation" as a possible output and measuring the impact on F1 score compared to the corrected evaluation

### Open Question 3
- Question: Would using a single, comprehensive model trained on the entire dataset outperform the RECENT system's approach of splitting the task into subsets?
- Basis in paper: [explicit] The paper concludes that the performance drop (from 75.2 to 65.16 F1) suggests the loss from having less data to learn is greater than the gain from focusing on smaller subsets
- Why unresolved: The paper does not directly compare the RECENT approach against a single model trained on all data, only inferring this based on the performance drop
- What evidence would resolve it: Training a single, state-of-the-art model (e.g., SpanBERT) on the complete TACRED dataset and comparing its F1 score to the corrected RECENT system's 65.16 F1

## Limitations
- The evaluation loophole artificially inflated F1 scores, masking the system's true performance
- Data efficiency issues arise when training specialized classifiers on smaller subsets
- The binary classifier's inherent limitations may contribute to performance issues beyond the evaluation flaw

- Medium: The conceptual decomposition strategy shows promise but data efficiency limits gains
- Low: The exact training configurations and implementation details are not fully specified
