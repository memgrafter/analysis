# A Strong Baseline for Batch Imitation Learning

## Quick Facts
- arXiv ID: 2302.02788
- Source URL: https://arxiv.org/abs/2302.02788
- Reference count: 40
- Key outcome: A simple support matching algorithm with formal sample complexity guarantees that achieves competitive performance with state-of-the-art IL methods in challenging data regimes

## Executive Summary
This paper proposes ILBRL, a straightforward baseline for batch imitation learning that learns a policy by maximizing intrinsic reward (1 for expert data, 0 otherwise). The method is implemented using TD3-BC with the intrinsic reward function and requires no additional hyperparameter tuning beyond standard batch RL. The authors provide formal sample complexity guarantees in the tabular RL setting and develop a novel evaluation protocol that enables fair comparison of offline RL methods using only the provided dataset. Empirically, ILBRL demonstrates competitive performance on D4RL MuJoCo benchmarks, particularly in challenging data regimes with limited expert data.

## Method Summary
ILBRL is a support matching approach that learns a policy by maximizing intrinsic reward, where expert state-action pairs receive reward 1 and others receive 0. The method combines TD3-BC (an offline RL algorithm) with the intrinsic reward function and a novel evaluation protocol. The evaluation protocol uses off-policy evaluation and data partitioning to tune hyperparameters without requiring environment interaction. The algorithm is trained on combined expert and exploratory datasets from D4RL benchmarks, with the policy optimized to match the expert's state-action distribution through the intrinsic reward signal.

## Key Results
- ILBRL achieves competitive performance with state-of-the-art IL methods on D4RL MuJoCo benchmarks
- The algorithm demonstrates strong performance in challenging data regimes with only 3% expert data
- The proposed evaluation protocol enables fair comparison of offline RL methods without environment access
- Formal sample complexity guarantees are provided for the tabular RL setting

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Maximizing intrinsic reward (1 for expert data, 0 otherwise) yields a policy that closely matches expert state-action distribution.
- Mechanism: The intrinsic reward acts as a surrogate reward that implicitly encodes the expert's state-action occupancy. By maximizing this reward, the learned policy is incentivized to visit and act in regions where expert data is present, effectively matching the expert's support without needing the true reward function.
- Core assumption: Expert data provides sufficient coverage of the expert policy's state-action distribution for the learned policy to imitate well.
- Evidence anchors:
  - [abstract]: "Our algorithm requires no additional hyper-parameter tuning beyond any standard batch reinforcement learning (RL) algorithm"
  - [section 3]: "We define the intrinsic reward, which, for discrete MDPs, is given by ˆr(s,a ) = 1DE((s,a ))"
  - [corpus]: Weak - related works focus on trajectory optimization and transport methods, not direct support matching
- Break condition: If expert data is sparse or unrepresentative of the expert's true behavior, the intrinsic reward will not provide sufficient signal for learning.

### Mechanism 2
- Claim: The batch RL algorithm (TD3-BC) with intrinsic reward can learn a good policy without online interaction.
- Mechanism: TD3-BC is an offline RL algorithm that can optimize policies using only a fixed dataset. By combining it with the intrinsic reward, the algorithm learns to imitate expert behavior using only the dataset, without needing to interact with the environment.
- Core assumption: The batch RL algorithm can effectively optimize the policy using only the intrinsic reward and the dataset.
- Evidence anchors:
  - [section 3]: "we make a call to an offline RL algorithm, which in general may not be able to perfectly optimise for our intrinsic reward"
  - [section 6.2]: "We employ the normalised reward: r(s,a ) := maxs′,a′∈DE ..."
  - [corpus]: Weak - related works focus on trajectory optimization and transport methods, not direct support matching
- Break condition: If the batch RL algorithm is not effective at optimizing the policy using only the dataset, or if the intrinsic reward is not a good surrogate for the true reward.

### Mechanism 3
- Claim: The proposed evaluation protocol allows fair comparison of offline RL methods without access to the true environment.
- Mechanism: The protocol uses a held-out dataset and off-policy evaluation to tune hyperparameters and select the best policy. This avoids the need for online interaction with the environment and ensures that all methods are compared on the same footing.
- Core assumption: The held-out dataset is representative of the environment and the off-policy evaluation is accurate enough to select good hyperparameters.
- Evidence anchors:
  - [abstract]: "we develop a practical, robust and principled evaluation protocol for offline RL methods, making use of only the dataset provided for model selection"
  - [section 6.1]: "In order to compare offline RL methods fairly, with explicit data requirements, we develop a novel and pragmatic hyperparameter tuning protocol for offline RL methods, which requires minimal knowledge of the true environment"
  - [corpus]: Weak - related works focus on trajectory optimization and transport methods, not direct support matching
- Break condition: If the held-out dataset is not representative or the off-policy evaluation is inaccurate, the protocol may not select good hyperparameters or policies.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the algorithm's performance scale with the size of the exploratory dataset (DX) compared to the expert dataset (DE)?
- Basis in paper: [explicit] The paper provides formal sample complexity guarantees and empirical evaluation of the algorithm in challenging data regimes with limited expert data.
- Why unresolved: The paper demonstrates effectiveness in a challenging data regime with 3% expert data, but does not explore how performance changes with varying ratios of exploratory to expert data.
- What evidence would resolve it: Conducting experiments with different ratios of exploratory to expert data while keeping the total dataset size constant would provide insights into the algorithm's data efficiency and the importance of exploratory data.

### Open Question 2
- Question: How does the choice of batch RL algorithm (TD3-BC) impact the performance of ILBRL compared to other offline RL algorithms?
- Basis in paper: [explicit] The paper mentions that TD3-BC was chosen for its simplicity and effectiveness, but notes that other algorithms could work as well.
- Why unresolved: The paper does not compare the performance of ILBRL when using different offline RL algorithms as the underlying solver.
- What evidence would resolve it: Implementing ILBRL with different offline RL algorithms (e.g., CQL, BEAR) and comparing their performance on the same benchmarks would reveal the impact of the choice of batch RL algorithm.

### Open Question 3
- Question: Can the evaluation protocol developed in the paper be extended to settings where the true reward function is unknown or non-stationary?
- Basis in paper: [inferred] The paper develops a novel evaluation protocol that requires minimal knowledge of the true environment, but it still assumes access to true rewards for policy evaluation.
- Why unresolved: The protocol is designed for settings where true rewards are known, which may not be applicable in all imitation learning scenarios.
- What evidence would resolve it: Adapting the evaluation protocol to handle unknown or non-stationary reward functions, perhaps by using inverse RL techniques or by developing new evaluation metrics, would demonstrate its broader applicability.

## Limitations

- The soft support reward implementation for continuous states lacks complete specification, particularly the feature mapping φ
- The evaluation protocol's effectiveness depends on the held-out dataset being representative of the environment
- The method may not perform well if expert data is sparse or unrepresentative of the expert's true behavior

## Confidence

High confidence in the main empirical results as the algorithm demonstrates competitive performance against established IL methods across multiple benchmarks. Medium confidence in the evaluation protocol's effectiveness as it relies on the held-out dataset being representative and the off-policy evaluation being accurate. Medium confidence in the novelty claim as the proof is provided for the tabular case but the extension to continuous domains is heuristic.
