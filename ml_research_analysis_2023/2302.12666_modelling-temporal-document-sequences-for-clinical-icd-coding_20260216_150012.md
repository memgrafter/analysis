# Modelling Temporal Document Sequences for Clinical ICD Coding

## Quick Facts
- arXiv ID: 2302.12666
- Source URL: https://arxiv.org/abs/2302.12666
- Reference count: 14
- Key outcome: HTDS achieves state-of-the-art Micro-F1 when using only discharge summaries, with further improvements across all metrics when including all clinical notes on MIMIC-III-50

## Executive Summary
This paper addresses the problem of ICD coding in clinical notes by proposing a hierarchical transformer architecture (HTDS) that leverages all clinical notes from a hospital stay, not just discharge summaries. The model incorporates metadata embeddings (positional, temporal, and category) and uses a diversity-based strategy to select which notes to include as input. To manage the increased computational load, the authors employ superconvergence techniques. When evaluated on the MIMIC-III-50 dataset, HTDS achieves state-of-the-art performance in Micro-F1 when using only discharge summaries, and further improves across all metrics when including all clinical notes, demonstrating the value of incorporating additional clinical documents for ICD coding.

## Method Summary
The Hierarchical Transformer for Document Sequences (HTDS) uses a two-stage transformer approach where clinical notes are first tokenized and chunked, then encoded with a pre-trained RoBERTa language model. A second transformer layer allows cross-chunk interactions, with metadata embeddings (positional, temporal, category) added at the chunk level. The model employs a diversity-based strategy to select which clinical notes to include as input, and uses a 3-phase 1cycle learning rate scheduler for superconvergence to speed up training. For multi-label ICD code prediction, the model uses label attention with learnable label embeddings.

## Key Results
- HTDS achieves state-of-the-art Micro-F1 performance when using only discharge summaries on MIMIC-III-50
- Including all clinical notes improves performance across all metrics (Micro-F1, Micro-AUC, Macro-AUC, Precision@5)
- Superconvergence techniques reduce training time by at least 50% compared to standard approaches
- Performance degrades when increasing the number of chunks, suggesting the note selection strategy may not be optimal

### Mechanism 1
- Claim: Incorporating all clinical notes improves ICD coding performance compared to using discharge summaries alone.
- Mechanism: The model captures additional diagnostic information present in various clinical notes (e.g., radiology reports, nursing notes) that may not be included in discharge summaries, providing a more comprehensive view of the patient's condition.
- Core assumption: Clinical notes beyond discharge summaries contain diagnostically relevant information for ICD coding.

- Break condition: If clinical notes contain redundant information or introduce noise without additional diagnostic value, performance gains may not materialize.

### Mechanism 2
- Claim: The hierarchical transformer architecture with metadata embeddings effectively processes long document sequences for ICD coding.
- Mechanism: The model uses a two-stage transformer approach where chunks are first encoded with a pre-trained language model, then a second transformer allows cross-chunk interactions. Metadata embeddings (positional, temporal, category) provide additional context for classification.
- Core assumption: Metadata about note position, timing, and category provides useful signals for ICD coding.
- Evidence anchors:
  - [abstract] "We propose a hierarchical transformer architecture that uses text across the entire sequence of clinical notes in each hospital stay for ICD coding, and incorporates embeddings for text metadata such as their position, time, and type of note."

- Break condition: If metadata embeddings don't capture meaningful patterns or the second transformer doesn't effectively integrate cross-chunk information, the architecture may not outperform simpler approaches.

- Mechanism: The 3-phase 1cycle learning rate scheduler allows for faster convergence by starting with low LR, increasing to peak LR, then annealing, reducing training time by at least 50% compared to standard approaches.

## Foundational Learning

- Concept: Hierarchical transformer architecture
  - Why needed here: The model needs to process sequences longer than the typical 512-token limit of standard transformers while maintaining cross-document context
  - Quick check question: How does the two-stage transformer approach allow the model to handle sequences longer than 512 tokens while still capturing interactions between chunks?

- Concept: Multi-label classification with label attention
  - Why needed here: ICD coding requires assigning multiple relevant codes to each hospital stay, necessitating a model that can predict multiple labels simultaneously
  - Quick check question: What is the purpose of using learnable label embeddings in the attention mechanism, and how do they help with multi-label classification?

- Concept: Clinical text tokenization and chunking
  - Why needed here: Clinical documents contain long narratives that must be appropriately segmented for transformer processing while preserving meaningful units
  - Quick check question: Why does the model ensure that each new document always starts a new chunk, and how might this affect the model's ability to capture document-level context?

## Architecture Onboarding

- Component map: Input → Tokenizer → Chunker → Pre-trained LM (RoBERTa) → Metadata Embeddings → Second Transformer → Label Attention → Classification Layer → Output
- Critical path: Chunker → Pre-trained LM → Second Transformer → Label Attention
- Design tradeoffs: Using all clinical notes increases information but also computational cost and potential noise; metadata embeddings add context but increase model complexity; superconvergence reduces training time but requires careful hyperparameter tuning
- Failure signatures: Performance degradation when increasing chunk count suggests the note selection strategy isn't optimal; poor generalization on dev set indicates overfitting or insufficient diversity in training data
- First 3 experiments:
  1. Compare performance using only discharge summaries vs. all notes to validate the core hypothesis
  2. Test different note selection strategies (timestamp-based vs. category-based vs. diversity-based) to optimize input selection
  3. Evaluate the impact of removing metadata embeddings to determine their contribution to performance

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do different clinical note selection strategies (beyond diversity-based and timestamp-based) affect ICD coding performance, particularly for hospital stays with large numbers of clinical documents?
- Basis in paper: [explicit] The paper compares different selection strategies (diversity, timestamp, category) and notes that "the effects of note selection strategies would be more pronounced when the maximum number of chunksNc for model input is smaller"
- Why unresolved: The paper only tested a limited set of selection strategies and found marginal differences, suggesting other strategies might yield better results
- What evidence would resolve it: Comprehensive comparison of novel selection strategies (e.g., content-based filtering, attention-weighted selection, or learning-to-rank approaches) on hospital stays with varying numbers of clinical documents

### Open Question 2
- Question: Can incorporating clinical note synonyms and relationships (similar to MSMN's approach for ICD codes) improve HTDS performance on rare ICD codes and overall Macro-F1?
- Basis in paper: [explicit] The authors note that "steps used to improve performance by incorporating synonyms based on UMLS concepts could also be adapted into our model" and MSMN achieved higher Macro-F1 through this approach
- Why unresolved: The paper focused on Micro-F1 and did not implement synonym incorporation for clinical notes
- What evidence would resolve it: Experimental results comparing HTDS with and without clinical note synonym integration on both MIMIC-III-50 and MIMIC-III-Full datasets, measuring impact on rare code performance

### Open Question 3
- Question: What is the optimal balance between computational efficiency and ICD coding performance when extending HTDS to the MIMIC-III-Full problem with 4x more data and ICD codes?
- Basis in paper: [inferred] The authors acknowledge computational limitations prevented testing on MIMIC-III-Full and note that "The computational requirements to train HTDS is not trivial"
- Why unresolved: The paper only tested on the constrained MIMIC-III-50 problem due to computational constraints
- What evidence would resolve it: Systematic evaluation of HTDS on MIMIC-III-Full with different computational optimizations (e.g., chunk size reduction, attention mechanism modifications, distributed training) measuring both performance and training time trade-offs

## Limitations

- The paper lacks implementation details for key components like the diversity-based note selection strategy and specific hyperparameters
- Evaluation is limited to only 50 ICD codes (MIMIC-III-50), which may not generalize to the full 8,921 code set
- No ablation studies are provided to isolate the contribution of individual components to overall performance
- The claim about superconvergence reducing training time by at least 50% lacks specific baseline comparisons and computational metrics

## Confidence

**High Confidence**: The claim that incorporating all clinical notes improves performance compared to using discharge summaries alone is supported by experimental results showing consistent gains across all metrics (Micro-F1, Micro-AUC, Macro-AUC, Precision@5) when including additional notes.

**Medium Confidence**: The effectiveness of the hierarchical transformer architecture with metadata embeddings is supported by performance gains, but the specific contribution of each component is unclear without ablation studies. The mechanism by which metadata embeddings improve performance could be validated through controlled experiments.

**Low Confidence**: The claim about superconvergence reducing training time by at least 50% lacks specific evidence and baseline comparisons. The exact implementation details of the diversity-based note selection strategy are unclear, making it difficult to assess its effectiveness or reproduce the approach.

## Next Checks

1. **Ablation study on metadata embeddings**: Remove positional, temporal, and category embeddings separately and measure their individual contribution to overall performance to determine which metadata types provide the most value for ICD coding.

2. **Diversity-based selection strategy validation**: Implement and compare the diversity-based selection strategy against simple timestamp-based or category-based approaches to verify that it actually improves input quality and model performance.

3. **Full code set evaluation**: Extend evaluation beyond MIMIC-III-50 to assess model performance on the complete ICD code set (8,921 codes) to determine whether performance gains scale to real-world clinical coding scenarios.
