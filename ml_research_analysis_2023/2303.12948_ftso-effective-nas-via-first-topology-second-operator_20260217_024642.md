# FTSO: Effective NAS via First Topology Second Operator

## Quick Facts
- arXiv ID: 2303.12948
- Source URL: https://arxiv.org/abs/2303.12948
- Reference count: 17
- Key result: Achieves 76.4% ImageNet accuracy in 18 seconds, 1.5% higher than previous best

## Executive Summary
This paper introduces FTSO (First Topology Second Operator), a novel neural architecture search (NAS) method that significantly reduces computational cost while maintaining or improving accuracy. The key innovation is a two-phase search process: first finding the optimal network topology using only skip connections, then searching for the best operators for that topology. This approach shrinks the search space dramatically compared to existing one-shot NAS methods. FTSO achieves state-of-the-art results with dramatically reduced search time - for example, reaching 97.77% accuracy on CIFAR-10 with 99.8% less search time than previous methods.

## Method Summary
FTSO divides NAS into two distinct phases. In the first phase, topology search uses a supernet containing only skip connections to find the optimal network structure. This eliminates the Matthew effect seen in DARTS by avoiding parameter-heavy operators during early training. In the second phase, either a gradient-based operator search or direct replacement strategy is used to find the best operators for the discovered topology. The method leverages parameter sharing while avoiding the overfitting issues of traditional supernet approaches by only evaluating the sparse topology found in phase one.

## Key Results
- Achieves 76.4% testing accuracy on ImageNet within 18 seconds
- Reaches 97.77% testing accuracy on CIFAR-10 with 99.8% less search time than previous best
- Reduces NAS search time from days to 0.68 seconds
- Demonstrates 1.5% higher accuracy than previous state-of-the-art methods

## Why This Works (Mechanism)

### Mechanism 1
Dividing architecture search into topology-first then operator search reduces the search space size dramatically. By first searching topology with only skip connections, the algorithm avoids evaluating combinations of operators at each edge during topology discovery. The core assumption is that optimal topology is relatively independent of specific operators chosen.

### Mechanism 2
Using only skip connections during topology search eliminates the Matthew effect in differentiable NAS. Skip connections have no parameters, so simpler operators don't dominate early in training, preventing the bias toward simple operators seen in DARTS. The core assumption is that the Matthew effect occurs because simple operators with fewer parameters converge faster during initial training phase.

### Mechanism 3
Directly replacing topology-found edges with powerful operators avoids overfitting that occurs with supernet-based approaches. Instead of maintaining a large supernet with all operator combinations, FTSO only needs to evaluate a sparse topology with fixed operators, reducing model capacity during search.

## Architecture Onboarding

- **Component map**: Topology search phase (skip connection-only supernet, architecture parameters βi,j, pruning step) -> Operator search phase (fixed topology, operator weights αo_i,j, optional direct replacement strategy) -> Evaluation pipeline (training and validation loops for both phases)

- **Critical path**: Initialize skip connection supernet → Optimize topology parameters β → Prune edges to keep top-2 connections per node → (Optional) Operator search with α parameters → Deploy final architecture

- **Design tradeoffs**: Topology search with skip connections vs. other simple operators (max pooling), gradient-based operator search vs. direct replacement strategy, one iteration vs. one epoch for topology search

- **Failure signatures**: Topology search produces disconnected graph (check pruning threshold), operator search yields poor accuracy (check if topology is too constrained), search time increases unexpectedly (verify skip connections are truly parameter-free)

- **First 3 experiments**: 1) Run topology search for 1 iteration and verify pruned architecture has expected connectivity, 2) Compare accuracy of directly replacing skip connections with 3×3 separable convolutions vs. gradient-based operator search, 3) Measure FLOPs and parameter count reduction compared to DARTS baseline

## Open Questions the Paper Calls Out

### Open Question 1
The paper mentions potential for applying FTSO to other tasks and search spaces beyond image classification, such as language modeling and multi-view stereo. However, it only evaluates FTSO on image classification tasks using CIFAR10, ImageNet, and NATS-Bench datasets. Resolving this would require conducting experiments to compare FTSO's performance to other NAS algorithms on a variety of tasks and datasets beyond image classification.

### Open Question 2
While the authors mention that max pooling can also deliver satisfying results for the topology search, the paper only uses the skip connection operator for the topology search phase. Resolving this would require conducting experiments to compare the performance of FTSO when using different operators for the topology search phase.

### Open Question 3
The paper mentions two strategies for the operator search phase (gradient-based and direct replacement) but only uses the direct replacement strategy. Resolving this would require conducting experiments to compare the performance of FTSO when using different strategies for the operator search phase.

## Limitations

- Limited empirical validation of the independence assumption between topology and operator choices
- Theoretical analysis of Matthew effect elimination lacks rigorous mathematical proof
- Results primarily validated on image classification tasks only

## Confidence

- **High Confidence**: Search time reduction claims (0.68 seconds) - straightforward measurements with clear experimental protocols
- **Medium Confidence**: Accuracy improvements - strong results but CIFAR-10 improvement margin (97.77% vs 97.48%) is relatively small
- **Low Confidence**: Theoretical analysis of why skip connections prevent Matthew effects - plausible mechanism but lacks rigorous proof or ablation studies

## Next Checks

1. **Interdependence test**: Systematically evaluate architectures where known topology-operator interactions exist to verify the independence assumption holds

2. **Operator search ablation**: Compare gradient-based operator search against random operator assignment on the discovered topology to determine if the search phase adds meaningful value beyond topology discovery

3. **Scale sensitivity analysis**: Test FTSO on larger architectures (e.g., 14-node networks) to verify the 0.68-second search time claim scales appropriately and doesn't degrade in larger search spaces
