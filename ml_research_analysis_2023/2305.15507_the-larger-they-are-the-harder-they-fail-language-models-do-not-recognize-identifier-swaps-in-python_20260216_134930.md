# The Larger They Are, the Harder They Fail: Language Models do not Recognize Identifier Swaps in Python

## Quick Facts
- arXiv ID: 2305.15507
- Source URL: https://arxiv.org/abs/2305.15507
- Reference count: 29
- Large language models fail to recognize identifier swaps in Python code, even as model size increases, exhibiting inverse scaling

## Executive Summary
This study reveals a fundamental limitation in large language models: they fail to recognize when built-in function identifiers have been consistently swapped in Python code, even as model size increases. The research tested auto-regressive language models on a binary classification task where correct function bodies must swap built-in function identifiers consistently with a preceding swap statement. All tested models, including GPT-3, OPT, CodeGen, and FLAN-T5, preferred incorrect outputs, with text-based models showing inverse scaling and code-based models showing flat or marginally positive scaling. These findings indicate that LLMs rely on statistical correlations rather than deep semantic understanding, making them unsuitable for tasks deviating from training data distributions.

## Method Summary
The study evaluated language models on a binary classification task using Python code snippets from GitHub repositories with at least 100 stars. Functions were filtered to include only those with docstrings and at least two callable built-ins. For each function, a swap statement was generated that reassigned two built-in function identifiers. The correct continuation swapped all references to these identifiers consistently, while the incorrect continuation left them unchanged. Models were evaluated based on which continuation they preferred using log-likelihood comparisons. The evaluation tested multiple model families including GPT-3, OPT, CodeGen, FLAN-T5, and various chat LLMs, analyzing scaling behavior across different model sizes.

## Key Results
- All tested models achieved zero classification accuracy on identifier swap tasks
- Text-based models showed inverse scaling (worse performance with larger models)
- Code-based models showed flat or marginally positive scaling but still failed at high rates
- Chat LLMs also failed the binary classification task with low accuracy

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Large language models fail to recognize identifier swaps because they rely on statistical correlations rather than deep semantic understanding.
- Mechanism: LLMs learn statistical patterns from training data where identifier swaps are rare, leading them to prefer the statistically common continuation over the correct but unusual one.
- Core assumption: The training data distribution contains predominantly correctly ordered identifier usage, making swapped versions statistically uncommon.
- Evidence anchors:
  - [abstract] "These findings indicate that LLMs rely on statistical correlations rather than deep semantic understanding, making them unsuitable for tasks deviating from training data distributions."
  - [section] "Our findings indicate that, despite their astonishing typical-case performance, LLMs still lack a deep, abstract understanding of the content they manipulate, making them unsuitable for tasks that statistically deviate from their training data."
  - [corpus] Weak corpus evidence - no direct citation anchors found for this specific mechanism.
- Break condition: If training data included significant amounts of identifier-swapped code or if models learned proper semantic representations of code structure.

### Mechanism 2
- Claim: Larger models exhibit inverse scaling because they become more confident in their incorrect predictions.
- Mechanism: As model size increases, models become better at capturing statistical patterns, but this actually worsens their performance on tasks requiring semantic understanding since they become more confident in statistically common but semantically incorrect patterns.
- Core assumption: Model size increases lead to better statistical pattern matching but not necessarily better semantic understanding.
- Evidence anchors:
  - [abstract] "some of them even become more confident in their incorrect predictions as the model size increases, an instance of the recently discovered phenomenon of Inverse Scaling"
  - [section] "All tested models always prefer the incorrect output resulting in zero classification accuracy, the log-likelihood of the incorrect output is always significantly higher than the uniform baseline"
  - [corpus] No direct corpus evidence found for this inverse scaling mechanism.
- Break condition: If models developed mechanisms to distinguish between statistical patterns and semantic correctness, or if identifier swaps became more common in training data.

### Mechanism 3
- Claim: LLMs fail to understand α-equivalence in Python code.
- Mechanism: The models cannot recognize that identifier swaps create semantic equivalence, instead treating swapped identifiers as entirely different functions based on their statistical usage patterns.
- Core assumption: Python identifier swaps should create semantically equivalent code that models should recognize as such.
- Evidence anchors:
  - [abstract] "Typical programming languages have invariances and equivariances in their semantics that human programmers intuitively understand and exploit, such as the (near) invariance to the renaming of identifiers."
  - [section] "We consider code snippets in Python 3. Python allows to redefine builtin functions by reassigning their identifiers."
  - [corpus] No corpus evidence found for α-equivalence understanding in LLMs.
- Break condition: If models learned to perform static analysis of code structure or if training data included sufficient examples of identifier swaps.

## Architecture Onboarding

- Component map: Data collection (GitHub scraping) -> AST parsing -> Swap generation -> Model evaluation (likelihood calculation) -> Statistical analysis
- Critical path: Data collection → swap generation → model evaluation → statistical analysis. The most time-consuming step is typically data collection and processing, followed by running evaluations on multiple model families.
- Design tradeoffs: Using syntactic substitution for generating "correct" outputs is efficient but may miss edge cases involving reflection. The binary classification approach simplifies evaluation but loses information about confidence levels. Focusing on built-in functions provides clean test cases but limits generalizability.
- Failure signatures: Models consistently preferring incorrect outputs indicates failure to understand semantic equivalence. Inverse scaling (worse performance with larger models) suggests the problem isn't simply model capacity but rather the approach to learning. Flat scaling in code-specific models indicates some benefit from code pretraining but still fundamental limitations.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Do larger language models exhibit inverse scaling on identifier swap tasks across all programming languages, or is this phenomenon specific to Python?
- Basis in paper: [inferred] The paper demonstrates inverse scaling specifically for Python code generation tasks involving identifier swaps, but does not test other programming languages.
- Why unresolved: The study only examined Python code, leaving open whether this inverse scaling behavior generalizes to other languages with similar identifier swap capabilities.
- What evidence would resolve it: Testing the same identifier swap task across multiple programming languages (e.g., JavaScript, Ruby, Lisp) with comparable model families would determine if inverse scaling is language-specific or a general phenomenon.

### Open Question 2
- Question: At what model scale, if any, do code-based language models begin to properly handle identifier swaps and overcome inverse scaling?
- Basis in paper: [explicit] The paper notes that while text-based models show inverse scaling, code-based models show flat or marginally positive scaling, but still fail to correctly handle identifier swaps even at the largest tested sizes.
- Why unresolved: The experiments tested models up to 16B parameters for code-based models, but did not explore whether larger models might eventually overcome this limitation.
- What evidence would resolve it: Testing identifier swap tasks on code-based models with 100B+ parameters (similar to GPT-3 scale) would reveal whether there is a critical threshold where models begin to understand identifier semantics correctly.

### Open Question 3
- Question: Would incorporating explicit semantic understanding of identifier relationships during training eliminate inverse scaling on identifier swap tasks?
- Basis in paper: [inferred] The paper suggests models rely on statistical correlations rather than semantic understanding, and inverse scaling indicates this approach fails for identifier swaps.
- Why unresolved: The study did not investigate whether architectural changes or training objectives that explicitly encode identifier semantics would prevent inverse scaling.
- What evidence would resolve it: Training models with semantic annotations or objectives that explicitly track identifier relationships, then testing their performance on identifier swap tasks, would determine if semantic awareness eliminates inverse scaling.

## Limitations

- The study only tests Python code with built-in function identifiers, limiting generalizability to other languages and identifier types
- Binary classification simplifies evaluation but may miss models that produce semantically correct code through alternative means
- The findings reveal limitations of statistical pattern matching but don't establish whether different training approaches could teach models to handle identifier swaps

## Confidence

**High Confidence**:
- LLMs consistently fail to recognize correct identifier swaps (zero accuracy across all tested models)
- Text-based models show inverse scaling on this task
- Code-specific models show flat or marginally positive scaling but still fail at high rates
- This represents a failure of semantic understanding rather than syntactic processing

**Medium Confidence**:
- Inverse scaling indicates larger models become more confident in statistically common but semantically incorrect patterns
- The findings generalize to chat LLMs and other language models beyond the specific autoregressive models tested
- The limitation extends beyond built-in functions to general identifier renaming

**Low Confidence**:
- The exact implications for practical applications and whether this represents a fundamental limitation or a training data issue
- Whether alternative architectures or training approaches could solve this problem
- The extent to which this finding applies to other types of semantic equivalences in code
