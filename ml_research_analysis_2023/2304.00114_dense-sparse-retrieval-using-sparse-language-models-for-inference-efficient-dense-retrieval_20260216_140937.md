# Dense Sparse Retrieval: Using Sparse Language Models for Inference Efficient Dense Retrieval

## Quick Facts
- arXiv ID: 2304.00114
- Source URL: https://arxiv.org/abs/2304.00114
- Reference count: 19
- Primary result: Sparse language models achieve 3-5x speedup with minimal accuracy loss in dense retrieval

## Executive Summary
Dense retrieval systems based on language models provide high accuracy but require expensive GPU resources for inference. This work demonstrates that sparse language models can serve as drop-in replacements for dense models with minimal accuracy degradation while achieving up to 4.3x improvement in queries per second. Using the Tevatron retrieval toolkit and datasets MSMARCO, NQ, and TriviaQA, we find that 90% sparse models provide the best trade-off between efficiency and accuracy, while 80% block-sparse models perform slightly worse. The method requires no architectural changes, making it a simple drop-in replacement for existing retrieval systems.

## Method Summary
The study uses already sparsified oBERT models (90% unstructured, 80% block sparsity) as drop-in replacements for BERT-base in dense retrieval tasks. Using the Tevatron framework, tied and untied bi-encoder models are trained on MSMARCO, NQ, and TriviaQA datasets. The sparse models are evaluated against dense baselines using standard retrieval metrics (Recall@20, Recall@100, Recall@200) and queries per second measurements. Inference speed is benchmarked using both PyTorch and DeepSparse inference engines to quantify the performance gains from sparsity-aware computation.

## Key Results
- Sparse language models achieve up to 4.3x speedup in queries per second
- 90% unstructured sparsity provides optimal accuracy-efficiency trade-off
- oBERT 90% matches BERT-base accuracy on MSMARCO, NQ, and TriviaQA
- 80% block-sparse models show slightly worse performance than unstructured sparsity
- No architectural changes required for integration into existing retrieval systems

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Sparse language models can replace dense models in retrieval with minimal accuracy loss
- Mechanism: By applying unstructured sparsity masks to pretrained language models (like BERT), the model maintains its ability to generate meaningful embeddings while reducing computational complexity
- Core assumption: The sparse model retains sufficient representational capacity to capture semantic relationships between queries and documents
- Evidence anchors:
  - [abstract] "we find that sparse language models can be used as direct replacements with little to no drop in accuracy"
  - [section 3.2] "Using these already sparse models, we explore their usage as drop-in replacements for the uncompressed BERT base"
  - [corpus] Weak - no direct corpus evidence for this specific claim
- Break condition: When sparsity exceeds the model's ability to maintain semantic representation quality, leading to significant accuracy degradation

### Mechanism 2
- Claim: Sparse models provide 3-5x speedup in inference throughput
- Mechanism: Modern GPUs with sparsity-aware inference engines (like DeepSparse) can skip computations on zeroed weights, reducing FLOPs without changing the computational graph
- Core assumption: The hardware and software stack supports efficient sparse matrix operations
- Evidence anchors:
  - [abstract] "up to 4.3x improved inference speeds"
  - [section 3.4] "we benchmark inference speeds of query encoding to evaluate the impact of using sparse language models"
  - [section B] Detailed benchmark results showing 4.28x speedup for oBERT 90%
- Break condition: When the sparsity-aware inference engine cannot fully exploit sparsity due to memory access patterns or when hardware lacks sparsity support

### Mechanism 3
- Claim: Sparse transfer learning works without additional training
- Mechanism: Pre-sparsified models (like oBERT) retain their pruned weight structure when fine-tuned on retrieval tasks, eliminating the need for retraining from scratch
- Core assumption: The sparsity pattern learned during pretraining remains beneficial for the retrieval task
- Evidence anchors:
  - [section 3.2] "we use already sparsified language models and apply them to new domains"
  - [section 4] "we find that simply by changing the inference engine from PyTorch to DeepSparse can lead to a 1.7x speedup"
  - [corpus] Weak - no direct corpus evidence for transfer learning effectiveness
- Break condition: When the downstream task has fundamentally different characteristics that require different sparsity patterns

## Architecture Onboarding

- Component map: Query encoder -> Document encoder -> ANN index -> Inference engine -> Evaluation pipeline

- Critical path:
  1. Load sparse/dense model
  2. Encode query → embedding
  3. ANN search in document index
  4. Return top-k results
  5. Evaluate accuracy and speed

- Design tradeoffs:
  - Model sparsity vs. accuracy retention
  - Hardware acceleration vs. compatibility
  - Training cost vs. inference efficiency
  - Index freshness vs. computational cost

- Failure signatures:
  - Accuracy drops > 2% from baseline
  - QPS improvements less than 1.7x (baseline DeepSparse improvement)
  - Inconsistent results across different sparsity levels
  - Memory allocation errors during inference

- First 3 experiments:
  1. Compare BERT-base vs. oBERT 90% on MSMARCO with DeepSparse inference engine
  2. Measure QPS improvement when switching from PyTorch to DeepSparse for BERT-base
  3. Evaluate recall@100 for tied vs. untied bi-encoders using oBERT 80% (block) model

## Limitations

- Study focuses exclusively on inference efficiency without considering training efficiency or model compression during training phase
- Evaluation constrained to specific retrieval datasets (MSMARCO, NQ, TriviaQA) and may not generalize to other domains or languages
- Assumes access to pre-sparsified models without addressing how sparsity patterns were originally generated

## Confidence

- High confidence: The QPS speedup measurements (3-5x improvement) are well-supported by direct benchmarking results with DeepSparse inference engine
- Medium confidence: The claim of minimal accuracy loss with sparse models is supported but depends heavily on maintaining the specific sparsity patterns
- Low confidence: The transferability of sparsity patterns from pretraining to retrieval tasks is assumed but not empirically validated across diverse domains
