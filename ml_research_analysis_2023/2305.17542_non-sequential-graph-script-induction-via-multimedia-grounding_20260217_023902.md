# Non-Sequential Graph Script Induction via Multimedia Grounding

## Quick Facts
- arXiv ID: 2305.17542
- Source URL: https://arxiv.org/abs/2305.17542
- Reference count: 20
- Primary result: New model outperforms baselines by 17.52% F1@3 and 13.8% Acc@1, with 48.76% higher human evaluation scores for capturing non-sequential step relationships.

## Executive Summary
This paper introduces non-sequential graph script induction for procedural tasks, addressing the limitation of linear scripts that cannot capture optional and interchangeable steps. The authors propose grounding procedural videos to wikiHow textual steps, transforming each video into an observed step path on the latent ground truth graph script. Using a multimodal framework with BART-based seq2seq models and Path-Level Constraint Loss, they learn the distribution of valid step paths and reconstruct explicit graph scripts that better represent real-world task variability.

## Method Summary
The method grounds procedural videos to wikiHow steps through task-level and step-level alignment, creating observed step sequences from videos. A BART-base seq2seq model is trained on these sequences using both Cross-Entropy Loss and Path-Level Constraint Loss with contrastive examples (re-sampled, shuffled, and cut & swapped sequences). Graph scripts are reconstructed via step-constrained beam search (beam size 40) to generate multiple valid sequences, which are used to build an adjacency matrix that captures both sequential and non-sequential step relationships.

## Key Results
- Next Step Prediction: 17.52% improvement in F1@3 and 13.8% improvement in Acc@1 over strong baselines
- Partial Sequence Completion: 13.8% improvement in Acc@1 over baselines
- Human evaluation: 48.76% higher scores for capturing sequential and non-sequential step relationships compared to wikiHow linear baseline

## Why This Works (Mechanism)

### Mechanism 1: Video-to-Text Grounding
Grounding procedural videos to wikiHow textual steps transforms each video into an observed step path on the latent ground truth graph script. By aligning videos with text at both task-level and step-level, the model obtains sequences of steps that reflect real-world variability in task execution. Core assumption: Step sequences observed in videos are valid samples from the latent graph script. Break condition: Noisy alignment or unrepresentative videos lead to poor model performance.

### Mechanism 2: Path-Level Constraint Loss
Path-Level Constraint Loss improves model learning by penalizing global inconsistencies in generated step sequences. The loss compares the generated sequence with the true grounded sequence and carefully designed negative contrastive sequences (re-sampled, shuffled, cut & swapped), encouraging the model to produce globally consistent step orderings rather than just locally correct next steps. Core assumption: Negative contrastive sequences are sufficiently different from valid sequences to serve as effective training signals. Break condition: Ineffective contrastive sequences prevent the model from learning valid path distinctions.

### Mechanism 3: Step-Constrained Graph Reconstruction
Step-constrained beam search with a fixed prefix trie enables reconstruction of explicit graph scripts from learned step sequences. By constraining the model to generate sequences using only steps from the wikiHow step library and recording adjacency information, the method constructs a probabilistic graph that captures both sequential and non-sequential relationships. Core assumption: The learned step sequence distribution accurately reflects the true graph structure. Break condition: Overly aggressive edge filtering removes valid optional or interchangeable steps.

## Architecture Onboarding

- **Component map**: Grounding module -> BART-based seq2seq model -> Path-Level Constraint Loss -> Graph reconstruction module
- **Critical path**: 1) Ground videos to wikiHow steps (task and step alignment), 2) Train seq2seq model with Cross-Entropy Loss + Path-Level Constraint Loss, 3) Generate multiple step sequences via step-constrained beam search, 4) Record adjacency matrix and filter low-frequency edges, 5) Construct explicit graph script
- **Design tradeoffs**: Grounding quality vs. scalability (manual vs. ASR), model complexity vs. training efficiency (contrastive loss), graph expressiveness vs. noise (edge filtering)
- **Failure signatures**: Poor grounding alignment → sequences don't reflect true variability, ineffective contrastive sequences → model fails to learn global consistency, overly aggressive edge filtering → loss of optional/interchangeable steps
- **First 3 experiments**: 1) Evaluate grounding accuracy on labelled dataset by comparing aligned steps to ground truth, 2) Test Path-Level Constraint Loss ablation by training with/without it and comparing next step prediction accuracy, 3) Assess graph reconstruction quality by varying edge frequency threshold and measuring recall of optional/interchangeable steps

## Limitations
- Grounding quality heavily depends on accurate ASR and fine-grained step alignment, but validation of alignment accuracy is not provided
- Path-Level Constraint Loss effectiveness relies on contrastive sequences that lack detailed sampling strategy and ablation study
- Graph reconstruction depends on filtering low-frequency edges, but optimal threshold is not explored, potentially removing valid optional steps
- Reliance on wikiHow as a single source limits generalizability to other domains or languages

## Confidence
- **High confidence**: The core methodology of grounding videos to wikiHow steps and using seq2seq models for sequence generation is well-defined and reproducible
- **Medium confidence**: The contrastive learning approach (Path-Level Constraint Loss) is conceptually sound but lacks detailed implementation specifics and ablation evidence
- **Medium confidence**: The graph reconstruction pipeline (beam search + adjacency filtering) is plausible but sensitive to hyperparameter choices not fully explored
