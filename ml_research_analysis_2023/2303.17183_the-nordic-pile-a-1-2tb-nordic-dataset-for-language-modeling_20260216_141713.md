# The Nordic Pile: A 1.2TB Nordic Dataset for Language Modeling

## Quick Facts
- arXiv ID: 2303.17183
- Source URL: https://arxiv.org/abs/2303.17183
- Reference count: 26
- Key outcome: A 1.2TB multilingual dataset for pre-training large language models in Nordic languages plus English, created via aggressive cleaning and deduplication, with final composition: 40.24% English, 26.02% Swedish, 11.55% Norwegian, 10.8% Danish, 1.59% Icelandic, 9.47% code.

## Executive Summary
The Nordic Pile is a 1.2TB dataset created to address the scarcity of high-quality training data for Nordic language models. The authors aggregate diverse sources including web data, books, articles, code, and conversational forums, then apply a rigorous cleaning pipeline. Through 16 quality filters and both exact and fuzzy deduplication (removing ~20% of initial data), they produce a dataset optimized for training high-quality Nordic language models. The dataset and source code are publicly available.

## Method Summary
The authors collected 1.2TB of text from diverse sources (web data, books, articles, code, conversational forums, math problems, Wikipedia) and processed it through a 7-step pipeline: normalization, metrics addition, quality filtering (16 filters), exact deduplication via MD5, language segmentation, fuzzy deduplication using MinHash LSH with 0.5 Jaccard threshold, and merging. The process removed approximately 20% of initial data to create a cleaned, deduplicated dataset optimized for training Nordic language models.

## Key Results
- Final dataset composition: 40.24% English, 26.02% Swedish, 11.55% Norwegian, 10.8% Danish, 1.59% Icelandic, 9.47% code
- Aggressive quality filtering removed low-value text, improving model generalization
- Exact and fuzzy deduplication significantly reduced redundancy
- Dataset publicly available for training high-quality Nordic language models

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Aggressive quality filtering removes low-value text, improving model generalization.
- Mechanism: Sixteen filter criteria systematically remove documents with undesirable properties (repetition, low language quality, malformed URLs, etc.), ensuring the dataset contains only high-signal text.
- Core assumption: The filters correctly identify and remove noise without discarding too much useful data.
- Evidence anchors:
  - [abstract] "The dataset undergoes aggressive cleaning and quality filtering (16 filters), exact deduplication via MD5 hashing, fuzzy deduplication using MinHash LSH with a 0.5 Jaccard threshold."
  - [section] "Most of these filters are inspired by the data processing work described in Gopher (Rae et al., 2021) and ROOTS (Laurenc ¸on et al., 2022)."
- Break condition: If filter thresholds are too strict, they could remove valuable but atypical text; if too loose, noise remains.

### Mechanism 2
- Claim: Deduplication reduces redundant training signal, improving parameter efficiency.
- Mechanism: Exact deduplication removes identical documents via MD5; fuzzy deduplication using MinHash LSH removes near-duplicates based on a 0.5 Jaccard similarity threshold, grouped by language.
- Core assumption: Redundancy is harmful to model training and can be reliably detected with the chosen thresholds.
- Evidence anchors:
  - [abstract] "exact deduplication via MD5 hashing, fuzzy deduplication using MinHash LSH with a 0.5 Jaccard threshold."
  - [section] "Our implementation differs in that it is word-based whereas the original implementation is token-based."
- Break condition: If similarity threshold is too high, useful variation is lost; if too low, redundancy remains.

### Mechanism 3
- Claim: Language segmentation enables efficient, targeted deduplication per language.
- Mechanism: Documents are grouped by identified language before fuzzy deduplication, reducing computational load and avoiding cross-language false positives.
- Core assumption: Duplicates are unlikely to occur across different languages, making per-language deduplication safe and efficient.
- Evidence anchors:
  - [abstract] "The dataset composition: 40.24% English, 26.02% Swedish, 11.55% Norwegian, 10.8% Danish, 1.59% Icelandic, 9.47% code."
  - [section] "Since fuzzy deduplication is computationally heavy, we separate the supported languages and fuzzily deduplicate them separately."
- Break condition: If cross-language duplication is significant (e.g., code comments), some redundancy may remain.

## Architecture Onboarding

- Component map: Normalization -> Metrics -> Quality Filtering -> Exact Deduplication -> Language Segmentation -> Fuzzy Deduplication -> Merging
- Critical path: Quality filtering and fuzzy deduplication are the most computationally intensive and impactful stages.
- Design tradeoffs: Aggressive filtering risks losing useful data; conservative filtering risks noise; per-language deduplication trades completeness for efficiency.
- Failure signatures: Large portions of data removed may indicate over-filtering; many duplicates slipping through indicates under-deduplication or incorrect thresholds.
- First 3 experiments:
  1. Run the quality filtering pipeline on a small, known-bad subset and verify expected documents are removed.
  2. Apply exact deduplication on a mixed-language sample and confirm identical documents are removed.
  3. Test MinHash LSH fuzzy deduplication on a controlled set of near-duplicates and verify the 0.5 Jaccard threshold behaves as intended.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the aggressive data cleaning and deduplication pipeline affect the downstream performance of Nordic language models compared to less aggressive approaches?
- Basis in paper: [explicit] The paper describes aggressive quality filtering (16 filters) and deduplication (exact and fuzzy) that removed ~20% of initial data, but does not empirically evaluate the impact on model performance.
- Why unresolved: The authors focused on dataset creation methodology rather than training and evaluating models on the resulting dataset to quantify the performance benefits of their aggressive cleaning approach.
- What evidence would resolve it: Training multiple Nordic language models with varying levels of data cleaning (baseline, moderate cleaning, aggressive cleaning as described) and comparing their performance on standard benchmarks would provide empirical evidence.

### Open Question 2
- Question: What is the optimal shard size for fuzzy deduplication when balancing computational efficiency against deduplication accuracy in massive multilingual datasets?
- Basis in paper: [explicit] The authors experimented with 80GB and 40GB shard sizes for fuzzy deduplication, noting that inter-shard deduplication is computationally expensive and requires significant memory resources.
- Why unresolved: The paper does not provide systematic evaluation of how different shard sizes affect the trade-off between computational cost and the completeness of deduplication results.
- What evidence would resolve it: Conducting experiments with varying shard sizes (e.g., 20GB, 40GB, 80GB, 160GB) while measuring both computational resources used and the amount of remaining duplicate content would identify optimal configurations.

### Open Question 3
- Question: How does the heavy English language composition (40.24% of final dataset) impact the performance of Nordic language models on monolingual tasks?
- Basis in paper: [explicit] The final dataset composition shows 40.24% English content, which the authors note could be adjusted through subset weighting during training if desired.
- Why unresolved: The paper does not investigate whether this English-heavy composition helps or hinders Nordic language model performance on tasks specific to Danish, Icelandic, Norwegian, or Swedish.
- What evidence would resolve it: Training separate models with different English-to-Nordic language ratios and evaluating them on monolingual Nordic language benchmarks would reveal the impact of this composition choice.

## Limitations
- The optimal thresholds for quality filters and Jaccard similarity are empirically chosen without systematic evaluation of their impact on model performance.
- The effectiveness of the cleaning pipeline in preserving useful content versus removing noise is not empirically validated.
- The downstream impact of the English-heavy dataset composition on Nordic language model performance remains untested.
