# FMM-X3D: FPGA-based modeling and mapping of X3D for Human Action Recognition

## Quick Facts
- arXiv ID: 2305.18479
- Source URL: https://arxiv.org/abs/2305.18479
- Reference count: 20
- Primary result: 1.52x improvement in latency and throughput compared to state-of-the-art FPGA-based HAR accelerators

## Executive Summary
This work presents FMM-X3D, a fully automated hardware-level interpretation and modeling approach for the X3D architecture used in Human Action Recognition (HAR). The proposed methodology addresses the challenge of accelerating complex deep learning models with over 200 layers and multiple branches on FPGA devices, an area previously unexplored for X3D. By leveraging Synchronous Dataflow (SDF) computation models and directed acyclic graph (DAG) transformations, the authors achieve significant performance improvements through systematic design space exploration and streaming optimizations.

## Method Summary
The methodology builds on Synchronous Dataflow computation models to capture the X3D network topology as a directed acyclic graph (DAG), which is then transformed into an SDF graph for hardware mapping. An analytical SDF performance model guides design space exploration while considering FPGA resource constraints and off-chip memory characteristics. Two key optimizations enhance performance: using prior batch statistics for Global Average Pooling layers and quantizing model weights and feature maps to 16-bit fixed-point arithmetic. The approach is validated on the ZCU102 FPGA board, demonstrating effective acceleration of the X3D model with throughput of 18.72 clips/s.

## Key Results
- Achieves 18.72 clips/s throughput on ZCU102 with 16-bit fixed-point precision
- Demonstrates 1.52x improvement in latency compared to state-of-the-art FPGA-based HAR accelerators
- Demonstrates 1.52x improvement in throughput compared to state-of-the-art FPGA-based HAR accelerators

## Why This Works (Mechanism)
The approach works by systematically transforming the complex X3D network topology into a tractable SDF representation that enables efficient hardware mapping and optimization. The use of prior batch statistics for GAP layers reduces computational overhead, while 16-bit quantization significantly reduces memory bandwidth requirements and computational complexity without sacrificing performance. The analytical SDF performance model enables effective exploration of the design space within the constraints of target FPGA resources and memory characteristics.

## Foundational Learning

**Synchronous Dataflow (SDF) computation model**: A mathematical framework for modeling and analyzing dataflow graphs where each node consumes and produces a fixed number of tokens per execution. Why needed: Provides the theoretical foundation for transforming complex neural network topologies into hardware-mappable representations. Quick check: Verify token production/consumption rates remain consistent across all graph transformations.

**Directed Acyclic Graph (DAG) representation**: A graph structure with directed edges and no cycles, used to represent the X3D network topology. Why needed: Enables systematic analysis and transformation of the complex multi-branch X3D architecture. Quick check: Ensure no cycles exist in the graph representation of the X3D network.

**Global Average Pooling (GAP) layer optimization**: Using prior batch statistics to reduce computational overhead in GAP layers. Why needed: GAP layers can be computationally expensive in streaming architectures; this optimization reduces their impact. Quick check: Verify statistical consistency across batches when using prior batch statistics.

## Architecture Onboarding

**Component map**: Input video frames → Feature extraction layers -> Multiple branches -> GAP layers -> Classification layers -> Output predictions

**Critical path**: The path through the network that determines overall latency, typically involving the deepest branch of the multi-branch X3D architecture and the final classification layers.

**Design tradeoffs**: Fixed-point quantization (16-bit) vs. floating-point precision balances resource utilization and potential accuracy loss; batch size selection affects memory bandwidth and throughput; optimization of GAP layers impacts computational efficiency.

**Failure signatures**: Performance degradation when memory bandwidth is insufficient for streaming operations; accuracy loss when quantization levels are too aggressive; timing violations when critical path exceeds FPGA clock constraints.

**Three first experiments**:
1. Validate SDF graph transformation accuracy by comparing predicted vs. actual throughput
2. Test 16-bit quantization impact on model accuracy across different HAR datasets
3. Measure performance scaling across different batch sizes on the ZCU102 platform

## Limitations
- Evaluation limited to single FPGA platform (ZCU102), limiting generalizability
- Single batch size (batch=1) evaluation restricts understanding of scalability
- No empirical validation of accuracy retention with 16-bit fixed-point quantization provided
