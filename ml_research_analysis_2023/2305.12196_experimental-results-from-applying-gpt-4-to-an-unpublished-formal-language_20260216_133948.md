# Experimental results from applying GPT-4 to an unpublished formal language

## Quick Facts
- arXiv ID: 2305.12196
- Source URL: https://arxiv.org/abs/2305.12196
- Reference count: 0
- Primary result: GPT-4 successfully completed all formal mathematical tasks in an unpublished formal system with only one minor error

## Executive Summary
This study tested GPT-4's ability to work with an unpublished formal mathematical system called Axiotome using only natural language specifications. GPT-4 demonstrated remarkable capability in generating function definitions, proving theorems, verifying proofs, and creating type definitions while inferring syntax and semantics from minimal examples. The model exhibited extensive domain knowledge in mathematical logic and functional programming, invented helpful syntax conventions, and maintained contextual consistency across multiple tasks. With only one minor error observed across all tasks, the results suggest large language models could serve as powerful mathematical assistants for formal system development.

## Method Summary
The study used GPT-4 via OpenAI's ChatGPT interface with turn-by-turn chat modality and natural language prompts. Researchers provided a concise natural language specification of the Axiotome formal system, then issued a series of prompts requesting various formal system tasks including function definitions, theorem proofs, proof verification, and type definitions. The interaction maintained context throughout the session, allowing GPT-4 to reference previously established definitions and conventions.

## Key Results
- GPT-4 successfully completed all requested tasks including function definitions, theorem proofs, and type definitions
- The model correctly inferred syntax rules and semantics from minimal examples, inventing appropriate naming conventions like "or" for disjunction
- Only one minor error was observed across all tasks, demonstrating high accuracy in formal mathematical reasoning
- GPT-4 leveraged extensive background knowledge in mathematical logic and functional programming without explicit instruction

- Core assumption: GPT-4's training corpus includes sufficient examples of similar formal systems and programming language constructs to enable pattern matching

- Mechanism: GPT-4 accesses stored knowledge about mathematical operations, proof techniques, and programming concepts to generate appropriate definitions and proofs without explicit instruction

## Foundational Learning

- Concept: Pattern matching and extrapolation from examples
  - Why needed here: GPT-4 needs to infer syntax rules from limited examples and apply them to novel situations
  - Quick check question: If given a new formal system with three examples of function definitions, can GPT-4 correctly generate a fourth function definition following the same pattern?

- Concept: Mathematical logic and proof techniques
  - Why needed here: GPT-4 must understand concepts like conjunction, disjunction, proof by cases, and quantification to complete the mathematical tasks
  - Quick check question: Can GPT-4 explain why proof by cases is necessary for certain theorems and demonstrate this technique correctly?

- Concept: Type theory and functional programming concepts
  - Why needed here: GPT-4 needs to understand sum types, product types, polymorphism, and inductive definitions to create appropriate type definitions
  - Quick check question: Can GPT-4 explain the difference between sum and product types and correctly implement a polymorphic list type?

## Architecture Onboarding

- Component map: GPT-4 -> Natural language prompt interface -> Axiotome formal system specification
- Critical path: 1) Provide formal system specification, 2) Issue task prompt, 3) Model generates response, 4) Review and validate output, 5) Use output for subsequent tasks
- Design tradeoffs: Flexibility vs. precision (natural language prompts are flexible but may be ambiguous), context window limitations vs. comprehensive formalization, speed vs. verification thoroughness
- Failure signatures: Incorrect syntax generation, missing axioms in proofs, inconsistent naming conventions, inability to handle edge cases
- First 3 experiments:
  1. Test basic syntax generation with simple function definitions
  2. Verify proof verification capabilities with known theorems
  3. Evaluate context retention by chaining multiple related tasks

## Limitations

- The Axiotome formal system specification remains unpublished, preventing independent verification and comparison
- Only one experimental session was conducted, providing no statistical evidence about result reproducibility or variance
- Limited error analysis makes it difficult to establish the boundaries of GPT-4's capabilities or identify systematic failure modes

## Confidence

- **High confidence** in GPT-4's ability to generate syntactically valid code conforming to formal system rules when given clear examples and sufficient context
- **Medium confidence** in GPT-4's mathematical reasoning capabilities for the specific domains tested (basic logic and functional programming concepts)
- **Low confidence** in the generalizability of results to other formal systems or mathematical domains

## Next Checks

1. Reproduce with published formal system: Implement the same experimental protocol using a well-documented formal system like Lean or Coq syntax to enable independent verification and comparison with established theorem provers.

2. Multiple run analysis: Conduct 50+ independent sessions with the same prompts to establish baseline performance metrics, error rates, and variance to determine whether the exceptional results reported are representative or anomalous.

3. Boundary testing: Systematically vary the complexity of theorems, the ambiguity of formal system specifications, and the context window limitations to identify the breaking points where GPT-4's performance degrades.
