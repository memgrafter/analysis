# MACOptions: Multi-Agent Learning with Centralized Controller and Options Framework

## Quick Facts
- arXiv ID: 2302.03800
- Source URL: https://arxiv.org/abs/2302.03800
- Reference count: 3
- One-line primary result: Q-learning with options achieves highest average reward in multi-agent gem collection task

## Executive Summary
MACOptions is a multi-agent reinforcement learning framework that combines a centralized controller with the options framework for task decomposition. The method uses Manhattan distances for task allocation and learns subtasks separately through two options: pickup-gem and drop-gem. Experiments in a bank world environment with 2 agents and 3 gems demonstrate that Q-learning with options outperforms both Q-learning alone and random policy baselines in terms of average reward, while also enabling faster learning of optimal policies.

## Method Summary
The MACOptions framework implements a multi-agent reinforcement learning approach where a centralized controller maintains Q-tables for two options (pickup-gem and drop-gem) that decompose the main task into subtasks. A planner assigns tasks to agents based on Manhattan distances, and agents update the central Q-table corresponding to their active option. The framework was tested in a bank world environment where agents must collect gems and drop them at a central bank, with performance measured through average reward over test runs.

## Key Results
- Q-learning with options achieves the highest average reward in test runs compared to Q-learning alone and random policy
- The planner enables faster learning of optimal policies compared to approaches without planning
- The options framework reduces training time compared to learning the full task directly

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The planner assigns tasks to agents based on Manhattan distances, improving learning efficiency.
- Mechanism: By computing the Manhattan distance from each agent to each unassigned target, the planner assigns the closest target to the nearest free agent, ensuring each agent focuses on one task at a time.
- Core assumption: Manhattan distance is a reasonable heuristic for task allocation in this grid-based environment.
- Evidence anchors:
  - [abstract] "The method, called MACOptions, uses a planner based on Manhattan distances to assign tasks to agents"
  - [section] "Our Multi-Agent RL Framework leverages a planner based on Manhattan Distances. In every step, each agent with an unallocated target calls the planner. The planner assigns the closest target to the agent based on the Manhattan Distance of the agent from unassigned targets."
- Break condition: If the environment includes obstacles or non-grid-aligned movement, Manhattan distance may no longer be a valid heuristic.

### Mechanism 2
- Claim: The options framework decomposes the complex multi-agent task into smaller, independently learnable subtasks.
- Mechanism: Two options are defined—pickup-gem and drop-gem—each with its own D-FOCI statements and Q-table. Agents update only the Q-table corresponding to the option they are executing, reducing the effective state space and training time.
- Core assumption: The overall task can be decomposed into a sequence of subtasks that are independently learnable.
- Evidence anchors:
  - [abstract] "implements the options framework to learn subtasks separately"
  - [section] "We then define 2 options that learn 2 subtasks separately. One option learns the pickup(Ai,Gi) task and the second option learns the drop(Ai,Gj) task."
- Break condition: If subtasks are highly interdependent or require global coordination, independent learning may fail to capture necessary interactions.

### Mechanism 3
- Claim: Centralized Q-table updates by all agents enable efficient coordination without explicit communication.
- Mechanism: A central controller maintains Q-tables for each option. All agents update the same Q-table for their active option, and the controller returns actions based on the optimal policy for the current state representation.
- Core assumption: Agents can safely update a shared Q-table without interfering with each other's learning.
- Evidence anchors:
  - [section] "We define a central controller that optimizes the overall sum of the rewards obtained by each agent... For each option o, all the agents update the value qπo of a single Q-Table of the central controller"
- Break condition: If agents' updates create conflicting gradients or if exploration strategies differ significantly, centralized learning may degrade.

## Architecture Onboarding

- Component map:
  - Environment -> Planner -> Central Controller -> Agents
  - Central Controller maintains Q-tables for pickup-gem and drop-gem options
  - Agents execute actions and receive rewards

- Critical path:
  1. Environment initializes agents, gems, and bank positions
  2. Planner assigns closest gem to each free agent
  3. Agents update the Q-table for their active option
  4. Central controller selects action based on optimal policy
  5. Agents execute actions and receive rewards
  6. Q-tables are updated via TD learning

- Design tradeoffs:
  - Centralized vs. decentralized control: Centralization simplifies coordination but may limit scalability
  - Manhattan distance vs. other heuristics: Simple and fast but may not handle obstacles well
  - Separate Q-tables vs. shared Q-table: Isolation reduces interference but increases memory usage

- Failure signatures:
  - Poor performance with random policy baseline
  - Slower learning or suboptimal policies when planner is removed
  - Instability in Q-table updates if agents' actions conflict

- First 3 experiments:
  1. Compare random policy vs. Q-learning vs. Q-learning with options in terms of average reward
  2. Evaluate the impact of the planner by comparing Q-learning with and without planner
  3. Test scalability by increasing the number of agents and gems, observing learning efficiency and reward outcomes

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the MACOptions framework perform in environments with a larger number of agents and gems compared to the current setup with 2 agents and 3 gems?
- Basis in paper: [explicit] The authors mention that "Currently, the model is independent of the number of agents and gems but is dependent on the grid dimensions."
- Why unresolved: The paper only tests the framework in a specific environment with 2 agents and 3 gems. The performance in more complex scenarios with a larger number of agents and gems is not explored.
- What evidence would resolve it: Experimental results showing the performance of MACOptions in environments with varying numbers of agents and gems, comparing it to other multi-agent learning approaches.

### Open Question 2
- Question: How does the MACOptions framework handle dynamic environments where the positions of gems change randomly at each step?
- Basis in paper: [explicit] The authors suggest "A future direction could be to see how the Q-learning + Options approach performs when the gems are also moving randomly at each step."
- Why unresolved: The current framework assumes static positions for gems, and its performance in dynamic environments is not tested.
- What evidence would resolve it: Experimental results comparing the performance of MACOptions in static and dynamic environments, analyzing its ability to adapt to changing conditions.

### Open Question 3
- Question: How does the use of function approximators to predict Q-values compare to learning them via the Bellman update in the MACOptions framework?
- Basis in paper: [explicit] The authors mention "Further comparisons can be drawn by using a function approximator to predict the Q values instead of learning them via the bellman update."
- Why unresolved: The paper only explores the use of Q-tables for learning Q-values, and the potential benefits of using function approximators are not investigated.
- What evidence would resolve it: Comparative results showing the performance of MACOptions using Q-tables versus function approximators, considering factors such as learning speed and accuracy.

## Limitations

- Grid dimensions are unspecified, making exact environment replication difficult
- State representation via D-FOCI statements lacks implementation details
- Scalability to larger agent counts or more complex environments untested

## Confidence

- Low confidence in performance guarantees when environment dynamics deviate from grid assumptions
