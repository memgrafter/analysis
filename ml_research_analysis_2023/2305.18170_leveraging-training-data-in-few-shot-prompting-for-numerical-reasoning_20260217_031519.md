# Leveraging Training Data in Few-Shot Prompting for Numerical Reasoning

## Executive Summary
This paper addresses the challenge of leveraging large training datasets for few-shot prompting in math word problem (MWP) solving. While chain-of-thought prompting with large language models has proven effective, designing prompts that generalize across diverse problem types remains difficult, especially when CoT annotations are unavailable. The authors propose two approaches: dynamic program prompting, which uses program execution for automatic verification and similarity-based retrieval of annotated exemplars, and program distillation, which adapts smaller models to program-annotated training data. These methods yield substantial improvements over previous baselines on three standard MWP datasets (GSM8K, SVAMP, MathQA), demonstrating that structured program representations and careful data utilization can enhance few-shot reasoning capabilities.

## Method Summary
The paper introduces dynamic program prompting, where training data is annotated by sampling correct programs from a large language model (Codex) with automatic verification through program execution. For new problems, top-M similar annotated exemplars are retrieved using sentence embeddings and used as few-shot prompts. Program distillation involves fine-tuning a smaller model (e.g., CodeGen-6B) on the program-annotated training data to transfer knowledge from large to small models. The approach combines automatic program verification, similarity-based retrieval, and model adaptation to overcome the limitations of traditional few-shot prompting in MWP solving.

## Key Results
- Dynamic program prompting with similarity-based retrieval outperforms standard few-shot prompting by 10-15% accuracy on GSM8K, SVAMP, and MathQA datasets
- Program distillation with CodeGen-6B achieves competitive results compared to large models while being computationally more efficient
- The combination of program execution for verification and similarity-based exemplar retrieval provides robust performance across diverse MWP types

## Architecture Onboarding

- Component map:
  - Data annotation pipeline: LLM (Codex) generates programs for training data with verification
  - Prompt retrieval module: Sentence embedding models (Sentence-T5, SimCSE) compute similarities
  - Program generation model: CodeGen fine-tuned on program-annotated data
  - Execution environment: Python interpreter to validate program outputs
- Critical path:
  1. Annotate training data with programs via LLM sampling and verification
  2. For a new problem, compute embeddings and retrieve top-M similar annotated examples
  3. Generate program using the retrieved examples as context
  4. Execute program to obtain answer and verify against ground truth
- Design tradeoffs:
  - Using programs vs. natural language CoT: Programs allow automatic verification but require code execution; CoT is more interpretable but harder to validate
  - Model size: Large LLMs (175B) perform better but are expensive; smaller models (6B) are cheaper but may underperform
  - Sampling budget: More program samples per training instance increase annotation coverage but raise costs
- Failure signatures:
  - Programs fail to generate correct solutions despite correct retrieval examples
  - Similarity metric retrieves irrelevant examples leading to poor program generation
  - Fine-tuned smaller model fails to generalize beyond the annotated training distribution
- First 3 experiments:
  1. Run annotation pipeline on a small subset of training data and verify annotation success rate
  2. Test prompt retrieval with a fixed set of examples to ensure correct top-M selection
  3. Fine-tune CodeGen on annotated data and evaluate on a validation set to measure initial performance

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal trade-off between the number of program samples (K) and the quality of annotated training data for different MWP datasets?
- Basis in paper: [explicit] The paper mentions that the maximum number of sampling K for each training instance is set to 54, and increasing K may not lead to significant improvements. They also note budget constraints prevented exploring more samples.
- Why unresolved: The paper did not systematically explore different values of K to determine the optimal trade-off between annotation quality and computational cost.
- What evidence would resolve it: Empirical results showing performance improvements on various MWP datasets when varying K from low (e.g., 5) to high (e.g., 40) values, along with computational cost analysis.

### Open Question 2
- Question: Can smaller language models be enhanced through architectural modifications or better pre-training to close the performance gap with large language models in MWP solving?
- Basis in paper: [inferred] The paper notes that despite leveraging training data, smaller models still underperform large language models significantly, suggesting current approaches may not be sufficient.
- Why unresolved: The paper focuses on data augmentation strategies rather than exploring model architecture improvements or alternative pre-training approaches for smaller models.
- What evidence would resolve it: Comparative results showing performance improvements when using different model architectures or pre-training strategies (e.g., Galactica, Code-T5) for smaller models on the same datasets.

### Open Question 3
- Question: How does the performance of similarity-based prompt retrieval compare to more sophisticated retrieval methods (e.g., semantic matching, graph-based retrieval) in few-shot prompting for MWPs?
- Basis in paper: [explicit] The paper experiments with different sentence embeddings (OpenAI, SimCSE, ST5) for similarity-based retrieval but notes that the "least similar exemplars" consistently leads to a drop in performance.
- Why unresolved: The paper only compares different sentence embedding models within the same similarity-based retrieval framework, without exploring alternative retrieval strategies.
- What evidence would resolve it: Performance comparison of various retrieval methods (similarity-based, semantic matching, graph-based) on the same MWP datasets, showing which method provides the best prompts for few-shot prompting.

## Limitations

- The approach relies heavily on program execution for verification, which may not generalize well to MWPs requiring approximate or probabilistic reasoning
- The effectiveness of similarity-based retrieval depends on the quality of sentence embeddings and the assumption that similar wording implies similar reasoning, which may not always hold true for MWPs with diverse problem structures
- The program distillation approach requires careful selection of the smaller model and may face capacity limitations when learning complex program structures

## Confidence

**High Confidence** - The core mechanism of using program execution for verification is well-supported by empirical results across multiple datasets (GSM8K, SVAMP, MathQA). The improvements over baselines are substantial and consistent, with accuracy gains of 10-15% in most cases.

**Medium Confidence** - The effectiveness of dynamic program prompting through similarity-based retrieval is demonstrated, but the dependency on high-quality sentence embeddings and the assumption of semantic similarity being captured by surface-level features introduces uncertainty. The break condition where retrieved examples may be misleading is not extensively explored.

**Low Confidence** - The program distillation approach's ability to transfer knowledge effectively from large to small models is shown through benchmark results, but the paper does not investigate failure modes where the smaller model may lack capacity or where program annotations may be insufficient for learning complex reasoning patterns.
