# LLM-assisted Knowledge Graph Engineering: Experiments with ChatGPT

## Quick Facts
- **arXiv ID:** 2307.06917
- **Source URL:** https://arxiv.org/abs/2307.06917
- **Reference count:** 8
- **Primary result:** ChatGPT can generate SPARQL queries, extract knowledge from semi-structured text, and visualize schemas, but requires validation due to variability and hallucinations.

## Executive Summary
This paper explores using ChatGPT to assist knowledge graph engineering tasks including generating SPARQL queries from natural language, extracting structured knowledge from semi-structured text, and visualizing knowledge graph schemas. Experiments with GPT-3.5-turbo and GPT-4 demonstrate that ChatGPT can produce syntactically correct outputs but with varying accuracy across runs. While promising for automating KG tasks, the results highlight the need for validation due to occasional hallucinations and inconsistent quality. The study identifies key limitations including token constraints and the tendency to invent properties rather than reuse existing ontologies.

## Method Summary
The study conducted experiments using ChatGPT-3.5-turbo and ChatGPT-4 across three main tasks: generating SPARQL queries from natural language questions with RDF schema context, extracting structured knowledge from semi-structured text documents (like 3D printer fact sheets) into JSON-LD format, and visualizing knowledge graph schemas using Mermaid syntax. The experiments used various input data including custom RDF knowledge graphs, the Mondial knowledge graph, DBpedia ontology, and semi-structured documents. Outputs were evaluated for syntactic correctness, accuracy of knowledge extraction, and quality of schema visualization, with token limits identified as a significant constraint for larger schemas.

## Key Results
- ChatGPT can generate syntactically correct SPARQL queries from natural language when provided with explicit RDF schema context
- The model successfully extracts structured knowledge from semi-structured text into JSON-LD format, though accuracy varies across runs
- Knowledge graph schemas can be visualized using Mermaid syntax, but diagrams may be incomplete or inaccurate
- Token limits (4096 for GPT-3.5, 32,768 for GPT-4) constrain the size of knowledge graphs that can be processed
- The model occasionally invents non-existent properties instead of reusing established ontologies

## Architecture Onboarding

- Component map:
  - ChatGPT LLM (GPT-3.5-turbo or GPT-4) -> RDF/OWL schema or knowledge graph data -> Validation tools for SPARQL and JSON-LD -> Mermaid rendering engine

- Critical path:
  1. Provide schema or knowledge graph context to ChatGPT.
  2. Issue natural language prompt for desired task (e.g., query generation, extraction).
  3. Receive LLM output (SPARQL, JSON-LD, or Mermaid diagram).
  4. Validate output using appropriate tools or manual inspection.
  5. Iterate on prompts if necessary to improve accuracy.

- Design tradeoffs:
  - Token limits vs. schema complexity: Larger schemas may require summarization or chunking.
  - Accuracy vs. automation: Manual validation is often necessary due to occasional hallucinations.
  - Vocabulary reuse vs. invention: ChatGPT may invent properties instead of using established ontologies.

- Failure signatures:
  - SPARQL queries that are syntactically correct but return empty or incorrect results.
  - JSON-LD output with non-existent properties or inconsistent modeling.
  - Mermaid diagrams that omit key classes or misrepresent relationships.

- First 3 experiments:
  1. Generate a SPARQL query from a natural language question using a small, well-defined RDF schema.
  2. Extract structured data from a semi-structured text document and convert it to JSON-LD.
  3. Visualize a knowledge graph schema using Mermaid syntax and validate the diagram against the original schema.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can the reliability of ChatGPT-generated knowledge graphs be improved to reduce hallucinations and ensure consistent quality across runs?
- Basis in paper: [explicit] The paper mentions that ChatGPT shows promise to assist KGE but validation is needed due to occasional hallucinations, and that the quality of generated knowledge graphs significantly varies from run to run.
- Why unresolved: The paper only identifies the issue of hallucinations and inconsistent quality, but does not provide concrete solutions or methods to improve reliability.
- What evidence would resolve it: Empirical studies comparing different techniques (e.g., fine-tuning, prompt engineering, post-processing) to improve the reliability and consistency of ChatGPT-generated knowledge graphs.

### Open Question 2
- Question: What metrics can be developed to automatically rate the quality of ChatGPT-generated SPARQL queries and knowledge graphs?
- Basis in paper: [explicit] The paper concludes that metrics are needed to rate generated ChatGPT answers automatically, like the metrics used for SPARQL queries, to extend the number of test cases and generate profound statistical results.
- Why unresolved: The paper identifies the need for such metrics but does not propose or validate any specific metrics for automatic quality assessment.
- What evidence would resolve it: Development and validation of a set of metrics that can automatically assess the syntactic correctness, semantic validity, and execution results of ChatGPT-generated SPARQL queries and knowledge graphs.

### Open Question 3
- Question: How can the token limit of large language models like ChatGPT be addressed to enable the processing of large knowledge graph schemas?
- Basis in paper: [explicit] The paper discusses that the token limit of ChatGPT (4096 for GPT-3.5 and 32,768 for GPT-4) is a significant constraint when working with large knowledge graph schemas like DBpedia.
- Why unresolved: The paper highlights the token limit issue but does not propose solutions to enable the processing of large knowledge graph schemas within the token constraints.
- What evidence would resolve it: Experiments and case studies demonstrating techniques to compress or chunk large knowledge graph schemas to fit within the token limits while preserving essential information for processing by ChatGPT.

## Limitations

- ChatGPT output quality varies significantly across runs, even with identical prompts, requiring validation
- Token limits restrict the size of knowledge graphs that can be processed, particularly challenging for large ontologies like DBpedia
- The model frequently invents non-existent properties rather than reusing established vocabularies from ontologies

## Confidence

- **High Confidence**: ChatGPT can generate syntactically correct SPARQL queries when provided with explicit schema context
- **Medium Confidence**: The model can extract structured knowledge from semi-structured text with variable accuracy
- **Low Confidence**: Visualization of knowledge graph schemas using Mermaid syntax has acknowledged limitations

## Next Checks

1. **Cross-Model Consistency Test**: Run the same set of prompts across multiple instances of ChatGPT (different sessions, temperature settings) to quantify the variability in output quality and identify patterns in inconsistency.

2. **Token Limit Boundary Analysis**: Systematically test the maximum knowledge graph size that can be processed within token limits for different serialization formats (Turtle, N-Triples, JSON-LD) to establish practical boundaries for schema complexity.

3. **Vocabulary Adherence Audit**: Create a benchmark dataset with established ontologies and measure the frequency with which ChatGPT invents new properties versus reusing existing vocabulary terms across multiple extraction tasks.
