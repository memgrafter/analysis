# ColibriUAV: An Ultra-Fast, Energy-Efficient Neuromorphic Edge Processing UAV-Platform with Event-Based and Frame-Based Cameras

## Quick Facts
- arXiv ID: 2305.18371
- Source URL: https://arxiv.org/abs/2305.18371
- Reference count: 38
- Primary result: Achieves 163 ms end-to-end latency and 46.98 mW power consumption for closed-loop control with event-based vision

## Executive Summary
ColibriUAV is a neuromorphic drone platform that integrates an event-based camera with a low-power RISC-V System on Chip called Kraken. The platform achieves ultra-low-latency and energy-efficient autonomous navigation through specialized hardware accelerators for both spiking neural networks and ternary deep neural networks. The design enables closed-loop control with 163 ms latency and 46.98 mW total power consumption, representing significant improvements over traditional USB-based data reading approaches.

## Method Summary
The ColibriUAV platform combines an event-based camera with a custom RISC-V SoC featuring two dedicated neural network accelerators. The system implements a dedicated event camera interface achieving 7200 event-frames per second throughput at only 10.7 mW power consumption. The closed-loop control pipeline integrates spiking neural networks for event data processing and ternary deep neural networks for frame-based data processing, enabling efficient real-time autonomous navigation for nano-drones.

## Key Results
- End-to-end latency of 163 ms for closed-loop control operations
- Total power consumption of 46.98 mW (9.224 mJ energy per loop)
- Event camera interface throughput of 7200 event-frames per second at 10.7 mW power
- Performance improvements of over 6.6 times faster and hundred times less power than USB-based approaches

## Why This Works (Mechanism)
The platform achieves its performance through a combination of event-based sensing, which provides sparse and asynchronous data updates, and specialized hardware accelerators optimized for neuromorphic processing. The event camera interface bypasses traditional USB bottlenecks by implementing direct memory access and parallel processing pipelines. The two accelerators - one for spiking neural networks and one for ternary deep neural networks - allow efficient processing of both event and frame data streams simultaneously, minimizing computational overhead while maintaining high throughput.

## Architecture Onboarding

Component map: Event camera -> DMA interface -> SNN accelerator -> Control system -> Actuators

Critical path: Event capture → DMA transfer → SNN processing → Control decision → Actuator command

Design tradeoffs: The platform trades off computational flexibility for energy efficiency by using specialized accelerators instead of general-purpose processors. The ternary quantization of DNNs reduces accuracy slightly but dramatically improves speed and reduces power consumption.

Failure signatures: System failures typically manifest as increased latency beyond 200 ms, power consumption spikes above 60 mW, or loss of event camera data synchronization. Network accelerator failures may result in processing stalls or incorrect output classifications.
