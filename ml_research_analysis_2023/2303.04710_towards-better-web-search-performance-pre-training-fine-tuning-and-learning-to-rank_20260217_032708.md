# Towards Better Web Search Performance: Pre-training, Fine-tuning and Learning to Rank

## Quick Facts
- arXiv ID: 2303.04710
- Source URL: https://arxiv.org/abs/2303.04710
- Reference count: 22
- Second place in WSDM Cup 2023 Pre-training for Web Search task with DCG@10 score of 10.04097

## Executive Summary
The THUIR team's approach to the WSDM Cup 2023 Pre-training for Web Search task combines pre-training, fine-tuning, and feature engineering to achieve state-of-the-art ranking performance. The method employs pre-trained language models (PLMs) as a backbone, enhanced with statistical, axiomatic, and semantic features, and uses learning-to-rank techniques to merge these features for optimal document ranking. This comprehensive approach successfully ranks relevant documents for search queries and achieved second place in the competition.

## Method Summary
The method involves a multi-stage pipeline: first, query-document pairs from Baidu Search session data are filtered based on similarity to expert queries and click presence. A PLM backbone is pre-trained using masked language modeling (MLM) and click-through rate (CTR) prediction tasks. The pre-trained model is then fine-tuned on expert-annotated data using a cross-encoder architecture. Statistical, axiomatic, and semantic features are extracted from both the PLM and traditional IR methods, and a learning-to-rank model (LightGBM, XGBoost, or LambdaMART) combines these 20 features to produce the final ranking scores.

## Key Results
- Achieved second place in WSDM Cup 2023 Pre-training for Web Search task
- DCG@10 score of 10.04097 on the competition leaderboard
- Demonstrated effectiveness of combining pre-training, fine-tuning, and feature engineering approaches

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The pre-training tasks (MLM and CTR prediction) improve relevance modeling for search queries.
- Mechanism: The MLM task trains the model to understand contextual relationships between query and document tokens, while the CTR task explicitly models user interaction signals, both contributing to better relevance matching.
- Core assumption: Relevance matching in search can be learned from large-scale user interaction data without explicit relevance labels.
- Evidence anchors:
  - [abstract] "We adopt PLMs as our backbone model" and "Two tasks are employed in our method: MLM and CTR tasks."
  - [section] "We use the oﬃcial pre-training code released by Baidu to train a backbone model. Two tasks are employed in our method: MLM and CTR tasks."
  - [corpus] Weak evidence - no direct corpus support found for this specific mechanism
- Break condition: If the pre-training corpus lacks sufficient query-document pairs with meaningful user interactions, the CTR task cannot learn effective relevance patterns.

### Mechanism 2
- Claim: Feature engineering with statistical, axiomatic, and semantic features enhances ranking performance beyond what the PLM alone can achieve.
- Mechanism: By extracting diverse features (BM25, TF-IDF, proximity scores, semantic embeddings), the model captures multiple relevance dimensions that complement each other.
- Core assumption: Different feature types capture orthogonal aspects of relevance that, when combined, outperform any single feature type.
- Evidence anchors:
  - [abstract] "we extract statistical, axiomatic, and semantic features to enhance the ranking performance"
  - [section] "Feature engineering plays an essential role in learning to rank. Except for taking the scores of the above pre-trained language models as features, we also construct statistical features, axiomatic features [2], and semantic features to achieve better ranking performance."
  - [corpus] Weak evidence - no direct corpus support found for this specific mechanism
- Break condition: If feature distributions differ significantly between training and test sets, the learning-to-rank model may overfit to training-specific patterns.

### Mechanism 3
- Claim: Learning-to-rank aggregation of diverse features outperforms individual ranking models.
- Mechanism: The learning-to-rank model learns optimal weighting and combination strategies for the 20 extracted features, leveraging their complementary strengths.
- Core assumption: The relationships between features and relevance are complex and non-linear, requiring learned combination strategies.
- Evidence anchors:
  - [abstract] "diverse learning-to-rank models are employed to merge those features"
  - [section] "Compared to a single model, learning to rank models achieve better performance, which indicates that fusing different information from different combinations of datasets is beneficial for ranking."
  - [corpus] Weak evidence - no direct corpus support found for this specific mechanism
- Break condition: If the learning-to-rank model overfits to the training data or if feature correlations are too strong, performance gains may be minimal.

  - Why needed here: Axiomatic features like PROX and STM capture theoretical properties of relevance that may not be captured by statistical features alone.

## Architecture Onboarding

- Component map: Data preprocessing → Query filtering and stop word selection → Pre-training → MLM + CTR prediction on filtered corpus → Fine-tuning → Cross-encoder re-ranking on expert annotated data → Feature extraction → 20 features (statistical, axiomatic, semantic) → Learning-to-rank → LightGBM/XGBoost/LambdaMART aggregation → Final ranking

- Critical path: Pre-training → Fine-tuning → Feature extraction → Learning-to-rank → Final ranking

- Design tradeoffs: Using pre-trained language models vs. traditional IR methods; complex feature engineering vs. simpler models; computational cost of cross-encoders vs. their effectiveness

- Failure signatures: Poor pre-training data quality (too few relevant query-document pairs); feature leakage between training and validation sets; overfitting in learning-to-rank model

- First 3 experiments:
  1. Train a baseline BM25 model and evaluate DCG@10 to establish a traditional IR baseline
  2. Implement the cross-encoder fine-tuning and compare its performance against the BM25 baseline
  3. Train a simple learning-to-rank model (e.g., XGBoost) using only the top 5 most important features to verify feature utility before adding complexity

## Limitations
- Heavy reliance on feature engineering without sufficient justification for specific feature choices
- Pre-training corpus (Baidu Search session data) is not publicly available, limiting reproducibility
- Lack of ablation studies to demonstrate the individual contribution of each component

## Confidence
- **High confidence**: The general framework of pre-training → fine-tuning → feature extraction → learning-to-rank is well-established in the literature and the competition results (second place) provide strong evidence of effectiveness.
- **Medium confidence**: The specific implementation details of feature extraction and the choice of 20 features are reasonable but not thoroughly validated. The paper claims these features enhance performance but doesn't demonstrate this through ablation studies.
- **Low confidence**: The exact impact of the pre-training tasks (MLM and CTR) on final performance cannot be assessed without access to the training data and full experimental results.
