# DARE-GRAM : Unsupervised Domain Adaptation Regression by Aligning Inverse Gram Matrices

## Quick Facts
- arXiv ID: 2303.13325
- Source URL: https://arxiv.org/abs/2303.13325
- Reference count: 40
- Key result: DARE-GRAM achieves 30.8% MAE improvement on dSprites, 21.9% on MPI3D compared to state-of-the-art

## Executive Summary
DARE-GRAM introduces a novel unsupervised domain adaptation method for regression that aligns the inverse Gram matrix of features rather than the features themselves. By leveraging the closed-form OLS solution to linear regression, the method addresses limitations of previous approaches that directly align features, particularly when batch sizes are smaller than feature dimensions. The approach demonstrates significant performance improvements across three benchmark datasets, achieving up to 30.8% better MAE than competing methods.

## Method Summary
DARE-GRAM performs unsupervised domain adaptation for regression by aligning the pseudo-inverse Gram matrix of features extracted from source and target domains. The method computes the Gram matrix (Z^T Z) from feature embeddings, applies SVD to obtain the pseudo-inverse, and selects k principal components based on eigenvalue thresholds. It then aligns both scale and angle between source and target domains through cosine similarity of the pseudo-inverse Gram matrix columns. The approach is motivated by the OLS closed-form solution, which requires the inverse Gram matrix for optimal linear regression parameter estimation.

## Key Results
- Achieves 30.8% improvement in MAE on dSprites dataset compared to state-of-the-art methods
- Shows 21.9% better performance on MPI3D dataset
- Demonstrates robustness across diverse regression tasks including position estimation and head pose regression

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Aligning the inverse Gram matrix preserves scale and angle information needed for optimal linear regression in domain adaptation.
- Mechanism: The closed-form OLS solution requires the inverse Gram matrix (Z^T Z)^-1. Aligning this inverse matrix ensures that the target features are calibrated to the source linear regressor, avoiding the instability caused by small eigenvalues.
- Core assumption: The Gram matrix captures feature correlations and its inverse is essential for computing the optimal linear regressor parameters.

### Mechanism 2
- Claim: Pseudo-inverse low-rank property enables robust subspace alignment when batch size is smaller than feature dimension.
- Mechanism: When batch size b < p (embedding dimension), the Gram matrix (Z^T Z) is rank-deficient. Using the Moore-Penrose pseudo-inverse allows alignment in a lower-dimensional subspace, avoiding numerical instability.
- Core assumption: The most informative basis vectors are those with highest eigenvalues, so truncating the pseudo-inverse to k principal components preserves essential information.

### Mechanism 3
- Claim: Angle alignment in pseudo-inverse Gram matrix space ensures optimal feature-subspace correspondence.
- Mechanism: Cosine similarity between columns of the pseudo-inverse Gram matrices aligns the principal angles between source and target subspaces, maximizing mutual information.
- Core assumption: The column space of the pseudo-inverse Gram matrix forms a subspace that captures the essential feature relationships for regression.

## Architecture Onboarding

- Component map: Input images -> ResNet-18 backbone -> feature matrix Z -> Gram matrix computation -> Pseudo-inverse Gram matrix computation -> Angle alignment loss module -> Scale alignment loss module -> Total loss aggregation -> Linear regressor

- Critical path:
  1. Input images → feature encoder → feature matrix Z
  2. Compute Gram matrix (Z^T Z) for source and target
  3. Compute pseudo-inverse Gram matrices
  4. Select k principal components based on eigenvalue thresholds
  5. Compute angle alignment loss
  6. Compute scale alignment loss
  7. Combine with source regression loss
  8. Backpropagate through entire network

- Design tradeoffs:
  - Batch size vs. Gram matrix invertibility (must keep b < p)
  - Number of principal components k vs. alignment quality
  - Weight of alignment terms (α_cos, γ_scale) vs. regression performance
  - Computational cost of SVD decomposition vs. accuracy

- Failure signatures:
  - Numerical instability in pseudo-inverse computation (check batch size vs. feature dimension)
  - Poor alignment despite loss minimization (check eigenvalue threshold T)
  - Performance worse than source-only baseline (check alignment weight hyperparameters)

- First 3 experiments:
  1. Verify Gram matrix invertibility with different batch sizes
  2. Test sensitivity to eigenvalue threshold T on validation set
  3. Compare angle alignment vs. scale alignment contributions to overall performance

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal threshold T for cumulative eigenvalue sum selection that maximizes performance across diverse regression tasks?
- Basis in paper: The paper discusses selecting k principal components based on a threshold T controlling the proportion of explained variance, but does not provide empirical guidance on optimal values.
- Why unresolved: The paper only mentions T as a hyperparameter without conducting systematic experiments to determine optimal values across different datasets and tasks.
- What evidence would resolve it: Empirical results showing performance sensitivity to different T values across multiple datasets and regression tasks would establish optimal threshold ranges.

### Open Question 2
- Question: How does DARE-GRAM's performance scale with batch size beyond 256, and what is the theoretical limit?
- Basis in paper: The paper shows performance improvement with larger batch sizes but only tests up to 256, noting that RSD fails beyond 64 due to numerical errors.
- Why unresolved: The paper stops at batch size 256 without exploring whether further improvements continue or if there's a point of diminishing returns.
- What evidence would resolve it: Systematic experiments testing batch sizes beyond 256 with varying embedding dimensions would reveal the scaling relationship and practical limits.

### Open Question 3
- Question: Can DARE-GRAM be extended to handle multi-source domain adaptation scenarios?
- Basis in paper: The current formulation assumes a single source domain, but the methodology could potentially be generalized to multiple sources by combining their inverse Gram matrices.
- Why unresolved: The paper only evaluates single-source adaptation scenarios and doesn't explore how to handle multiple source domains or whether combining their inverse Gram matrices would be beneficial.
- What evidence would resolve it: Experimental results comparing single-source versus multi-source DARE-GRAM implementations across various datasets would demonstrate the approach's effectiveness in multi-source settings.

## Limitations
- The paper lacks ablation studies comparing different subspace alignment methods or analyzing when the Gram matrix approach might fail
- Selection of k principal components using eigenvalue thresholds is heuristic without systematic sensitivity analysis across diverse datasets
- Potential computational overhead from SVD computations and scalability concerns for larger models and datasets

## Confidence

- High Confidence: Experimental results showing DARE-GRAM outperforming baselines on three benchmark datasets
- Medium Confidence: Theoretical motivation linking OLS solutions to Gram matrix alignment is plausible but lacks rigorous mathematical proof
- Low Confidence: Claim that angle alignment in pseudo-inverse Gram matrix space is the primary driver of performance improvements
