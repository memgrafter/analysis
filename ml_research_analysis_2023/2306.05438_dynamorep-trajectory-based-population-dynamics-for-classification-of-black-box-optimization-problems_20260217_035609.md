# DynamoRep: Trajectory-Based Population Dynamics for Classification of Black-box Optimization Problems

## Quick Facts
- arXiv ID: 2306.05438
- Source URL: https://arxiv.org/abs/2306.05438
- Reference count: 35
- Primary result: 95% mean classification accuracy on BBOB problem classes

## Executive Summary
DynamoRep is a novel feature extraction method for black-box optimization problem classification that captures algorithm-problem interactions by analyzing populations generated during optimization trajectories. Rather than using static landscape properties, it extracts min, max, mean, and standard deviation statistics from each iteration's population across all dimensions plus objective values, creating a longitudinal representation. The method demonstrates that simple descriptive statistics from algorithm trajectories contain sufficient information to identify problem classes, offering a lightweight alternative to traditional landscape analysis methods.

## Method Summary
The core approach analyzes optimization algorithm trajectories by computing descriptive statistics (min, max, mean, standard deviation) from populations generated at each iteration across all problem dimensions and objective values. This creates a longitudinal representation that captures how different algorithms interact with various problem classes. The method is computationally simpler than traditional landscape analysis while maintaining high classification accuracy. It was evaluated on classifying 24 BBOB problem classes using trajectories from differential evolution, genetic algorithms, CMA-ES, and evolution strategies, achieving 95% mean classification accuracy across all experiments.

## Key Results
- Achieves 95% mean classification accuracy across 24 BBOB problem classes
- Outperforms trajectory-based ELA features (mean accuracy ~49%)
- Demonstrates that simple descriptive statistics from algorithm trajectories contain sufficient information for problem classification
- Shows computational simplicity compared to traditional landscape analysis methods

## Why This Works (Mechanism)
The method captures dynamic interactions between optimization algorithms and problem landscapes by tracking how populations evolve over iterations. The four descriptive statistics (min, max, mean, std) provide a compact yet informative summary of population distribution changes that are characteristic of different problem structures. This longitudinal view reveals patterns in how algorithms explore and exploit different landscape features that static landscape analysis misses.

## Foundational Learning
- **Population-based optimization algorithms**: Algorithms that maintain and evolve populations of candidate solutions rather than single points. Why needed: DynamoRep analyzes population trajectories rather than single-solution paths. Quick check: Understand the difference between population-based and single-solution optimization methods.
- **BBOB benchmark suite**: Black-Box Optimization Benchmarking collection of synthetic test functions with known properties. Why needed: Standard testbed for evaluating optimization algorithm performance. Quick check: Familiarize with BBOB problem categories and their characteristics.
- **Descriptive statistics in optimization**: Using statistical measures (min, max, mean, std) to characterize solution populations. Why needed: Core feature extraction mechanism in DynamoRep. Quick check: Understand what each statistic reveals about population distribution.
- **Landscape analysis (ELA)**: Exploratory Landscape Analysis extracts static features from problem landscapes. Why needed: Comparison baseline for DynamoRep performance. Quick check: Know key ELA features like ruggedness, global structure, and local optima counts.
- **Algorithm-problem interaction**: How optimization algorithms behave differently on various problem classes. Why needed: Core concept that DynamoRep captures through trajectory analysis. Quick check: Understand why the same algorithm performs differently on different problems.

## Architecture Onboarding

**Component map:** Trajectory generation -> Population statistics extraction -> Feature matrix construction -> Classification model training/testing

**Critical path:** The essential sequence is: run optimization algorithm to generate trajectory → compute statistics at each iteration → build feature vectors → train classifier → predict problem class.

**Design tradeoffs:** Simplicity vs. information content - DynamoRep sacrifices some detailed landscape information for computational efficiency and interpretability. The choice of four statistics represents a minimal sufficient set that balances compression with discriminative power.

**Failure signatures:** Poor classification accuracy likely indicates either: 1) Insufficient trajectory length to capture problem characteristics, 2) Inappropriate algorithm selection for the problem class, or 3) Need for additional statistical features beyond the basic four.

**First experiments:**
1. Generate trajectories using different algorithms on simple BBOB problems and visualize how population statistics evolve
2. Compare classification accuracy when using individual statistics versus the full feature set
3. Test classification performance with varying trajectory lengths to identify minimum sufficient budget

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do DynamoRep features perform on optimization problems with dimensions higher than three?
- Basis in paper: [explicit] The authors state "In this study, due to computational constraints, we limit ourselves to three-dimensional problem instances" and suggest testing higher dimensions as a future direction.
- Why unresolved: The paper only evaluates on 3D problems, so performance on higher-dimensional problems is unknown.
- What evidence would resolve it: Experiments applying DynamoRep to BBOB problems of dimensions 5, 10, 20+ showing classification accuracy and computational efficiency.

### Open Question 2
- Question: What is the minimum budget (function evaluations) required for DynamoRep to achieve reliable problem classification?
- Basis in paper: [explicit] The authors used 900 function evaluations (30 iterations with population size 30) and note "we did not investigate if smaller budgets would suffice."
- Why unresolved: The study fixed the budget at 900 evaluations without exploring the trade-off between classification accuracy and budget size.
- What evidence would resolve it: Systematic experiments varying the iteration count/budget while measuring classification accuracy to identify the minimum sufficient budget.

### Open Question 3
- Question: Do DynamoRep features trained on one population size generalize to optimization algorithms run with different population sizes?
- Basis in paper: [explicit] The authors note "Some of the proposed features are sensitive to the population size, and may cause the model not to generalize to other population sizes."
- Why unresolved: All experiments used a fixed population size of 30, so generalization to other population sizes is untested.
- What evidence would resolve it: Experiments training DynamoRep models on trajectories with one population size and testing on trajectories with different population sizes, measuring classification accuracy degradation.

## Limitations
- Evaluation limited to synthetic BBOB test functions, with uncertain generalizability to real-world problems
- Fixed budget of 900 function evaluations without exploring minimum sufficient budget for classification
- All experiments used population size of 30, leaving population size sensitivity unexplored
- Comparison to a single ELA variant may not represent state-of-the-art landscape analysis methods

## Confidence
- Problem classification accuracy: **High** (95% accuracy on BBOB is robust given multiple algorithms and replicates)
- Computational simplicity claim: **Medium** (needs full pipeline timing analysis)
- Generalizability to real-world problems: **Low** (only tested on synthetic benchmarks)

## Next Checks
1. Test DynamoRep on real-world optimization problems with noise, constraints, and unknown structure to assess generalizability beyond synthetic benchmarks.
2. Compare against modern ELA implementations and other state-of-the-art feature extraction methods to establish true relative performance.
3. Conduct ablation studies removing individual statistics (min, max, mean, std) to identify which features contribute most to classification accuracy and whether all four are necessary.
