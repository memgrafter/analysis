# Teamwork Is Not Always Good: An Empirical Study of Classifier Drift in Class-incremental Information Extraction

## Quick Facts
- arXiv ID: 2305.16559
- Source URL: https://arxiv.org/abs/2305.16559
- Reference count: 28
- This paper studies how classifier drift leads to forgetting in class-incremental learning and proposes four effective solutions to alleviate the drift.

## Executive Summary
This paper investigates classifier drift as a key cause of catastrophic forgetting in class-incremental learning for information extraction tasks. Through systematic experiments, the authors demonstrate that updating classifiers while freezing feature extractors can cause severe forgetting, and propose the Individual Classifiers with Frozen Feature Extractor (ICE) framework to address this issue. The ICE framework trains separate classifiers for each learning session without updating previous ones, achieving significant performance gains over state-of-the-art methods. The paper also introduces ICE-PL, ICE-O, and ICE-PL&O variants that incorporate additional constraints to further improve performance, especially on detection tasks.

## Method Summary
The paper proposes the ICE framework where individual classifiers are trained for each learning session while keeping the feature extractor frozen. This approach prevents classifier drift by maintaining fixed decision boundaries for previously learned classes. The authors also introduce three variants: ICE-PL preserves previous classifiers' logits as constraints, ICE-O introduces a constant logit for an "Other" class to bound all classifiers, and ICE-PL&O combines both approaches. The framework is evaluated on six class-incremental information extraction tasks using datasets including Few-NERD, MA VEN, ACE-05, and TACRED.

## Key Results
- DRIFTED-BERT baseline with only classifier updates causes severe forgetting, validating the classifier drift hypothesis
- ICE framework significantly outperforms previous state-of-the-art methods by up to 44.7% absolute F-score gain
- ICE-O variant is particularly effective for detection tasks, demonstrating the importance of the Other class constraint
- All four proposed variants (ICE, ICE-PL, ICE-O, ICE-PL&O) consistently improve performance across different datasets and tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Classifier drift in class-incremental learning causes catastrophic forgetting by overshadowing old classes with new ones.
- Mechanism: When new classes arrive, the classifier updates to discriminate new classes better, causing logits for new classes to increase relative to old classes. This shift in decision boundaries leads to misclassification of old classes.
- Core assumption: The classifier is the primary source of forgetting, not the feature extractor.
- Evidence anchors:
  - [abstract]: "the drift in the classifier leads to forgetting" and "classifier drift alone causes severe forgetting."
  - [section]: Analysis shows that when new classifiers are added, new class logits increase while old class logits decrease or stay constant, causing overshadowing.
  - [corpus]: No direct corpus evidence; this is based on the paper's own experiments.
- Break condition: If the feature extractor drifts significantly, it may also contribute to forgetting, invalidating the assumption that classifier drift alone is the primary cause.

### Mechanism 2
- Claim: Training classifiers individually for each session prevents classifier drift by keeping old classifiers fixed.
- Mechanism: By training a new classifier for each session without updating old classifiers, the decision boundaries for old classes remain unchanged. This prevents the overshadowing effect caused by updating all classifiers collectively.
- Core assumption: Fixed feature extractor ensures that the encoded features for a given sample remain unchanged across sessions, isolating the effect of classifier drift.
- Evidence anchors:
  - [abstract]: "Individual Classifiers with Frozen Feature Extractor (ICE) framework where we individually train a classifier for each learning session."
  - [section]: "previous classifiers can avoid being drifted to the sub-optimum, and the new classifier is less prone to output larger logits to overshadow old classes."
  - [corpus]: No direct corpus evidence; this is a novel approach proposed in the paper.
- Break condition: If the feature extractor needs to be updated to learn new patterns, freezing it may limit the model's ability to adapt to new classes.

### Mechanism 3
- Claim: The Other class provides a constraint that helps mitigate classifier drift by bounding the logits of all classifiers.
- Mechanism: By setting a constant logit for the Other class, all classifiers are trained under the constraint that their logits must be less than this constant. This provides a weak contrastivity between classifiers, preventing any single classifier from dominating.
- Core assumption: The Other class, despite having different meanings in different sessions, can still serve as a useful constraint.
- Evidence anchors:
  - [abstract]: "ICE-O, and ICE-PL&O, which introduce a constant logit for the Other class and use it to enforce each individual classifier to be bounded by a constraint shared across different learning sessions."
  - [section]: "both classifiers are trained under the constraint that max(ok) < δ and max(oj) < δ , which provides a weak contrastivity between them."
  - [corpus]: No direct corpus evidence; this is a novel approach proposed in the paper.
- Break condition: If the constant logit for Other is not chosen appropriately, it may not effectively constrain the classifiers, leading to continued drift.

## Architecture Onboarding

- Component map:
  - Pre-trained BERT (frozen): Feature extractor
  - Linear classification layer: Classifier, split into individual classifiers for each session
  - Constant logit for Other class: Constraint for detection tasks

- Critical path:
  1. Encode input text using frozen BERT
  2. Compute logits using individual classifiers for each session
  3. Combine logits (including constant logit for Other) to get final prediction
  4. Train new classifier for each session without updating old classifiers

- Design tradeoffs:
  - Freezing the feature extractor simplifies the problem but may limit adaptability to new classes.
  - Training individual classifiers prevents drift but increases model size and complexity.
  - Using a constant logit for Other provides a constraint but may not be optimal for all tasks.

- Failure signatures:
  - Poor performance on old classes: Indicates classifier drift is not adequately addressed.
  - Overfitting to new classes: Suggests the model is not learning generalizable features.
  - Degraded performance on detection tasks: May indicate issues with the constant logit for Other.

- First 3 experiments:
  1. Compare DRIFTED-BERT baseline with ICE to quantify the impact of classifier drift.
  2. Evaluate ICE-O on detection tasks to assess the effectiveness of the constant logit for Other.
  3. Test ICE-PL&O to determine if preserving previous logits improves performance when Other is involved.

## Open Questions the Paper Calls Out
The paper identifies several limitations and future research directions, including the need to investigate how the ICE framework performs under other continual learning settings beyond class-incremental learning, such as task-incremental learning or online learning. The authors also note that their analysis focuses on classifier drift while freezing the feature extractor, which may not generalize to scenarios where feature drift is significant.

## Limitations
- The analysis focuses primarily on classifier drift while freezing the feature extractor, which may not generalize to scenarios where feature drift is significant.
- Experiments are conducted on specific information extraction tasks and datasets, limiting generalizability to other domains.
- The effectiveness of the Other class constraint assumes that a constant logit value works across different semantic contexts, which may not hold for all classification problems.

## Confidence
**High Confidence:** The empirical demonstration that classifier drift causes forgetting (Mechanism 1) is well-supported by controlled experiments comparing DRIFTED-BERT with ICE variants. The ablation studies showing ICE-O's effectiveness on detection tasks (Mechanism 3) are also robust.

**Medium Confidence:** The claim that freezing the feature extractor isolates classifier drift effects (Mechanism 2) is theoretically sound but may not hold if feature extractor updates are necessary for new class adaptation. The assumption that constant logits for Other provide effective constraints across different semantic contexts needs more validation.

**Low Confidence:** The scalability analysis for long task sequences and the assumption that classifier drift is the dominant forgetting mechanism in all CIL scenarios are not thoroughly validated.

## Next Checks
1. Run experiments where both feature extractor and classifier can update to quantify the relative contribution of feature drift versus classifier drift in causing forgetting.
2. Test ICE variants on non-information-extraction tasks (e.g., image classification) to evaluate whether the classifier drift phenomenon and proposed solutions generalize beyond the current domain.
3. Implement a large-scale experiment with 20+ learning sessions to measure how individual classifier storage and computation scale, and test whether the Other class constraint remains effective over many sessions.
