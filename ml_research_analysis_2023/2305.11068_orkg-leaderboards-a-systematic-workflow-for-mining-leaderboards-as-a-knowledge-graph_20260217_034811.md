# ORKG-Leaderboards: A Systematic Workflow for Mining Leaderboards as a Knowledge Graph

## Quick Facts
- arXiv ID: 2305.11068
- Source URL: https://arxiv.org/abs/2305.11068
- Reference count: 40
- Key outcome: Transformer-based system achieves >90% F1 on extracting Task-Dataset-Metric triples from AI papers

## Executive Summary
orkg-Leaderboards is a software system that automatically extracts leaderboards from AI research papers by identifying Task-Dataset-Metric (TDM) triples. The system processes both LaTeX and PDF inputs, using transformer models fine-tuned on the Natural Language Inference task to achieve high extraction accuracy. By integrating with the Open Research Knowledge Graph (ORKG), the extracted leaderboards become FAIR and machine-actionable, enabling transparent tracking of state-of-the-art progress across AI tasks and datasets.

## Method Summary
The system extracts TDM triples by first converting PDF or LaTeX papers into XML TEI format using GROBID or pandoc, respectively. A DocTAET feature extraction script heuristically selects context from titles, abstracts, experimental sections, and tables/captions. Four transformer variants (BERT, SciBERT, XLNet, BigBird) are fine-tuned on the NLI task to predict if a TDM triple is entailed by the paper context. The best-performing XLNet model with 2000-token context achieves over 90% F1 score. Extracted triples are uploaded to ORKG as RDF resources, enabling dynamic leaderboard views and SPARQL queries.

## Key Results
- Best model (orkg-LeaderboardsXLNet2000) achieves over 90% F1 on TDM extraction
- System outperforms existing leaderboard extraction approaches by 20+ F1 points
- Integration with ORKG enables FAIR and machine-actionable leaderboard representation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The system achieves high extraction accuracy by using transformer models pre-trained on scientific text (SciBERT) or general text (BERT) and fine-tuning them for the leaderboard extraction task.
- Mechanism: Transformer models leverage self-attention to capture contextual relationships between task, dataset, and metric mentions within a paper, enabling accurate inference of TDM triples.
- Core assumption: Scientific language patterns in AI research papers are similar enough to the pre-training corpora to benefit from transfer learning.
- Evidence anchors:
  - "Our best model achieves performances above 90% F1 on the leaderboard extraction task"
  - "we investigate three transformer-based model variants for leaderboard extraction in a Natural Language Inference configuration"
  - Weak evidence - the corpus statistics show large variation in context length but don't directly confirm pre-training effectiveness
- Break condition: If scientific terminology or writing styles differ significantly from the pre-training data, transfer learning benefits diminish and extraction accuracy drops.

### Mechanism 2
- Claim: DocTAET context feature extraction improves model performance by focusing on document regions most likely to contain TDM mentions.
- Mechanism: Heuristically selects sentences from document title, abstract, experimental setup, and tables/captions as informative context, reducing noise from irrelevant text.
- Core assumption: TDM mentions are predominantly found in these four document sections.
- Evidence anchors:
  - "DocTAET feature was designed to heuristically select only those parts of an article that are more likely to contain Task-Dataset-Metric mentions"
  - "DocTAET captures sentences from four specific places in the article that are most likely to contain Task-Dataset-Metric mentions"
  - Weak evidence - corpus statistics show variation in DocTAET feature length but don't directly confirm section selection effectiveness
- Break condition: If TDM mentions are frequently found outside these sections or if the heuristic selection misses important context, extraction accuracy suffers.

### Mechanism 3
- Claim: Integrating with ORKG as a knowledge graph enables FAIR and machine-actionable representation of extracted leaderboards.
- Mechanism: RDF/OWL semantic web standards allow leaderboard data to be queryable, interoperable, and reusable across systems and platforms.
- Core assumption: Semantic web technologies are appropriate for representing scholarly knowledge and meet FAIR principles.
- Evidence anchors:
  - "Thus the system output, when integrated within the ORKG's supported Semantic Web infrastructure... enables transparency in empirical research"
  - "Semantic Web technologies such as the W3C recommendations Resource Description Framework (RDF) and Web Ontology Language (OWL) are the most widely-accepted choice for implementing the FAIR guiding principles"
  - No direct corpus evidence for this mechanism
- Break condition: If semantic web standards prove too rigid or incompatible with other systems, integration and reuse of leaderboard data becomes difficult.

## Architecture Onboarding

- Component map:
  PDF/LATEX → GROBID/pandoc → XML TEI → DocTAET → Transformer model → ORKG upload

- Critical path: PDF/LATEX → GROBID/pandoc → XML TEI → DocTAET → Transformer model → ORKG upload

- Design tradeoffs:
  - BERT/SciBERT: 512 token limit vs. XLNet/BigBird: longer contexts but potentially more computationally expensive
  - PDF processing: GROBID provides good parsing but may introduce noise vs. LaTeX processing: cleaner output but limited to papers with available sources
  - Model selection: Balancing accuracy (XLNet best) with computational efficiency and deployment constraints

- Failure signatures:
  - Low precision: Model predicting too many false TDM triples
  - Low recall: Model missing actual TDM triples in papers
  - Integration failures: ORKG upload errors or malformed RDF data
  - Processing failures: GROBID/pandoc crashes on malformed input files

- First 3 experiments:
  1. Run DocTAET feature extraction on a sample paper and verify output contains expected sections
  2. Train a basic BERT model on the training set and evaluate on the test set to establish baseline
  3. Test the full pipeline with a single PDF input through GROBID, feature extraction, prediction, and ORKG upload

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of orkg-LeaderboardsXLNet2000 compare to BigBird2000 on longer context lengths beyond 2000 tokens?
- Basis in paper: The paper states that XLNet2000 outperforms BERT512 and SciBERT512, but BigBird2000 does not outperform BERT512 and SciBERT512 on the TDM extraction task. The authors suspect the attention mechanism in BigBird needs further examination over a larger dataset.
- Why unresolved: The paper only tested up to 2000 tokens. The attention mechanism in BigBird may become more effective with even longer contexts.
- What evidence would resolve it: Experiment with orkg-LeaderboardsXLNet2000 and orkg-LeaderboardsBigBird2000 on context lengths beyond 2000 tokens, e.g. 4000 tokens, to see if BigBird's performance improves relative to XLNet.

### Open Question 2
- Question: How does the performance of orkg-LeaderboardsLATEX compare to orkg-LeaderboardsGrobid on a much larger training dataset?
- Basis in paper: The paper found that orkg-LeaderboardsLATEX has lower performance than orkg-LeaderboardsGrobid, despite LATEX providing cleaner text. The authors hypothesize that transformer models need a much larger training dataset to generalize on longer contexts.
- Why unresolved: The paper only tested on a subset of the data. The performance gap may decrease with a larger training set.
- What evidence would resolve it: Train orkg-LeaderboardsLATEX and orkg-LeaderboardsGrobid on a much larger dataset, e.g. 10x the current size, and compare their performance. If the gap decreases, it supports the hypothesis that a larger dataset is needed for LATEX.

### Open Question 3
- Question: How can the Score element be extracted to complete the Task-Dataset-Metric-Score tuples for Leaderboards?
- Basis in paper: The paper states that Score extraction is particularly hard due to noisy contextual data. Clean table data extraction from PDFs is a challenging problem that needs to be addressed first.
- Why unresolved: The Score element is currently missing from the extracted tuples. Clean table extraction is an open research problem.
- What evidence would resolve it: Develop a robust table extraction system for PDFs that can accurately extract the Score values. Integrate this with orkg-Leaderboards to extract complete Task-Dataset-Metric-Score tuples.

## Limitations

- Limited evaluation on unseen domains: System only tested on papers from same domain as training data
- Dependency on specific document structures: DocTAET heuristics may miss TDM mentions in non-standard papers
- Computational resource requirements: Best models require significant memory for 2000-token contexts

## Confidence

- High confidence: The system achieves >90% F1 score on TDM extraction task
- Medium confidence: DocTAET context selection improves extraction accuracy
- Medium confidence: Integration with ORKG enables FAIR and machine-actionable leaderboard representation
