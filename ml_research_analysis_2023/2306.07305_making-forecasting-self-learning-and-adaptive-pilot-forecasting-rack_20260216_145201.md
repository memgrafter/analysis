# Making forecasting self-learning and adaptive -- Pilot forecasting rack

## Quick Facts
- arXiv ID: 2306.07305
- Source URL: https://arxiv.org/abs/2306.07305
- Reference count: 5
- One-line primary result: Proposed adaptive forecasting model improves demand forecast accuracy by 20% for Knitwear category, achieving 80% overall accuracy

## Executive Summary
This paper presents an adaptive forecasting approach for retail product categories, specifically addressing the Knitwear category where non-AI models achieve only 60% accuracy. The proposed solution uses an algorithmic rack comprising multiple custom AI/ML models, with a decision tree-based dynamic selector choosing the best-fit algorithm based on historical performance for given contexts. Key influencing parameters like seasonality, pricing, lag sales, and weather are incorporated through advanced feature engineering. The approach achieved a 20% improvement in forecast accuracy, bringing overall accuracy to 80%.

## Method Summary
The method employs a rack-based approach using five different regression models (Linear, KNN, XGBoost, Poly2, LSTM) combined with a Decision Tree classifier that dynamically selects the optimal model based on historical feature contexts. Advanced feature engineering incorporates seasonality, pricing, lag sales, and weather data. The selector is trained on historical data to predict which model will minimize absolute percentage error for a given state. This approach allows customization for specific customer contexts and improves upon traditional non-AI forecasting methods.

## Key Results
- Achieved 20% improvement in forecast accuracy, raising overall accuracy from 60% to 80%
- XGBoost Regressor showed smallest RMSE and highest R2 in training and test sets
- Dynamic model selection based on feature contexts proved effective for Knitwear category

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Dynamic model selection from an algorithm rack improves forecast accuracy over static single-model approaches.
- Mechanism: A decision tree classifier uses historical feature vectors (e.g., seasonality, price, lag sales) to predict which regression model will minimize absolute percentage error for the current context.
- Core assumption: Past model performance on similar feature contexts reliably predicts future best-performing model.
- Evidence anchors:
  - [abstract] "our decision model dynamically selects the best algorithm from an algorithm rack based on performance for a given state and context."
  - [section 4] "We implemented a Decision Tree based dynamic model selector to determine the most suitable forecasting algorithm. Historical data is used in the determination of the choice of ML model."
- Break condition: If feature distribution shifts significantly over time, historical model performance becomes a poor guide, degrading selector accuracy.

### Mechanism 2
- Claim: Advanced feature engineering incorporating seasonality, pricing, lag sales, and weather improves forecast signal over time-series methods that ignore these covariates.
- Mechanism: Features such as Month, WeekNo, AvgSellPrice, Lag Sales t-1 and t-2, weather metrics are engineered and fed into multiple regression models, capturing demand drivers missed by univariate time series.
- Core assumption: These engineered features have consistent and measurable influence on demand patterns for Knitwear.
- Evidence anchors:
  - [section 2] "While these models provide adequate accuracy, they do not account for changing patterns in sales of items based on store, price, lag t - 1, t - 2, weather and other demographics."
  - [section 3] "We modeled the seasonality's for the data using the Month, Week of year, Average Price, and Lag Sales t - 1 and t - 2."
- Break condition: If weather or pricing data become noisy or irrelevant due to market changes, engineered features lose predictive power.

### Mechanism 3
- Claim: Using a diverse rack of regression algorithms ensures coverage across different data patterns and scales.
- Mechanism: Each algorithm captures different data characteristics—Linear for global trends, KNN for local similarity, XGBoost for nonlinear interactions, LSTM for temporal dependencies, Poly2 for quadratic effects—allowing the selector to match algorithm strengths to data context.
- Core assumption: The Knitwear dataset contains heterogeneous patterns that no single algorithm can optimally capture.
- Evidence anchors:
  - [section 3] "The XGBoost Regressor produces the smallest RMSE and high R2 in the train and test sets, making it the most suitable for our regression modeling."
  - [section 4] Lists all five models and their evaluation.
- Break condition: If the dataset is homogeneous, a single well-tuned model may outperform a diverse rack with added complexity.

## Architecture Onboarding

- Component map: Data preprocessing -> Feature engineering (seasonality, lag, weather) -> Multiple regression models (Linear, KNN, XGBoost, Poly2, LSTM) -> APE computation per model -> Selector training (DecisionTreeClassifier) -> Runtime prediction (select best model per context) -> Forecast output
- Critical path: Feature engineering -> Model training -> APE calculation -> Selector training -> Dynamic selection at inference
- Design tradeoffs: Model rack increases coverage but adds inference complexity; decision tree selector is lightweight but assumes historical patterns hold
- Failure signatures: High selector misclassification rate; one model consistently dominates or underperforms; feature drift causing selector degradation
- First 3 experiments:
  1. Train and evaluate each regression model individually on a holdout set; compare RMSE/R2 to baseline Lewandowski/AVS Graves
  2. Compute APE for each model per feature pivot; verify that selector training labels (argmin APE) are stable
  3. Train the DecisionTreeClassifier on the APE-derived labels; validate accuracy on a separate test set and measure improvement over single-model baseline

## Limitations

- Dataset specificity: Results are demonstrated only for Knitwear category; generalizability to other product types remains unproven
- Evaluation methodology gaps: Limited details on validation protocol and statistical significance testing of claimed 20% improvement
- Selector generalization: No analysis of performance during concept drift or with previously unseen feature combinations

## Confidence

- High Confidence: The general approach of using a diverse model rack with a dynamic selector is methodologically sound and aligns with established ensemble learning principles
- Medium Confidence: The claimed 20% accuracy improvement is plausible given the use of multiple advanced models and feature engineering, but limited evaluation details prevent full verification
- Low Confidence: Claims about universal applicability to other product categories are not supported by empirical evidence beyond the Knitwear category
