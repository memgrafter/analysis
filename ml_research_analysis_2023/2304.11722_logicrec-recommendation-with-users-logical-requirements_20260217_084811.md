# LogicRec: Recommendation with Users' Logical Requirements

## Quick Facts
- arXiv ID: 2304.11722
- Source URL: https://arxiv.org/abs/2304.11722
- Reference count: 40
- Key outcome: Extends recommendation systems to handle users' logical requirements over knowledge graphs using logical query embedding and multi-task knowledge sharing, outperforming state-of-the-art KG-based methods on hit rate and NDCG metrics.

## Executive Summary
This paper introduces LogicRec, a novel recommendation framework that incorporates users' logical requirements expressed as queries over knowledge graphs. The key challenge is that KGs are incomplete, making direct query answering impossible for many logical requirements. The proposed solution uses logical query embedding to jointly infer missing facts and retrieve items, combined with a multi-task knowledge-sharing framework that leverages different answer sets from user preferences and logical requirements. Experiments on Amazon and Yelp datasets demonstrate significant improvements over state-of-the-art KG-based recommendation methods and other logical query embedding approaches.

## Method Summary
The LogicRec framework extends recommendation systems to handle users' logical requirements by jointly embedding logical queries and missing facts using logical query embedding (LQE) methods like GQE. The method constructs three types of queries: user preference queries (items a user has interacted with), logical requirement queries (items matching specific logical conditions), and LogicRec queries (items matching both user preferences and logical requirements). A multi-task knowledge-sharing framework with a mixture-of-experts architecture shares learned query representations across these tasks. The model uses max operations for union and attention-weighted concatenation for intersection in the embedding space, with binary cross-entropy loss for parameter learning.

## Key Results
- LogicRec outperforms state-of-the-art KG-based recommendation methods and other LQE approaches on hit rate and NDCG metrics
- The multi-task knowledge-sharing framework effectively exploits complementary information from different answer sets
- Jointly embedding logical queries and missing facts enables effective inference beyond observed KG triples

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Jointly embedding logical queries and missing facts enables inference beyond observed KG triples
- Mechanism: Logical query embedding (LQE) methods like GQE embed queries into the same space as entities, allowing approximate answers even when some triples are missing
- Core assumption: The embedding space captures semantic similarity between queries and answers sufficiently for retrieval
- Evidence anchors:
  - [abstract] "We thus resort to logical query embedding (LQE) to jointly infer missing facts and retrieve items based on logical requirements"
  - [section] "We embed the queries into the entity embedding space as q𝑙 following GQE [9]"
- Break condition: Embedding space does not preserve query-answer relationships; missing facts cannot be inferred from proximity

### Mechanism 2
- Claim: Multi-task knowledge-sharing framework leverages answer sets from both user preference and logical requirement retrieval
- Mechanism: A mixture-of-experts architecture with gating networks shares learned query representations across three tasks (user preference, logical requirement, and LogicRec)
- Core assumption: The answer sets A𝑢 and A𝑙 contain complementary information that improves the final LogicRec task
- Evidence anchors:
  - [abstract] "However, the logical requirements and user preferences have different answer sets, offering us richer knowledge about the requirements and preferences by providing requirement-item and preference-item pairs"
  - [section] "We apply binary cross-entropy loss for parameter learning and use p(𝑞[𝑖]), 𝑖 ∈ I for inference"
- Break condition: The gating mechanism fails to properly balance task-specific knowledge; shared parameters degrade task performance

### Mechanism 3
- Claim: Using intersection and union operations in query embedding preserves logical semantics
- Mechanism: Query embeddings are combined using max operations for union and attention-weighted concatenation for intersection
- Core assumption: Simple vector operations approximate the set-theoretic operations needed for logical reasoning
- Evidence anchors:
  - [section] "The intersection of two query embeddings q1 and q2 is resolved by q𝑙 = 𝑎(q1 ⊕ q2; Ω)1 ∗ q1 + 𝑎(q1 ⊕ q2; Ω)2 ∗ q2"
  - [section] "The union of two query embeddings q1 and q2 is resolved by q𝑙 = max(q1, q2)−1"
- Break condition: The approximations fail to capture complex query semantics; performance degrades on queries with nested operations

## Limitations

- The method relies heavily on the quality of KG embedding space to capture query semantics, which may not hold for complex logical expressions
- Evaluation on only two datasets (Amazon-book and Yelp) may not generalize to domains with different KG structures or user behavior patterns
- Computational cost of training a multi-task model with shared representations could be prohibitive for very large KGs

## Confidence

- **High Confidence**: The core contribution of integrating logical requirements into recommendation systems is well-founded and the experimental methodology (using hit rate and NDCG) is standard
