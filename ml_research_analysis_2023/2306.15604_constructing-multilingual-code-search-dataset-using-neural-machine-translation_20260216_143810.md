# Constructing Multilingual Code Search Dataset Using Neural Machine Translation

## Quick Facts
- arXiv ID: 2306.15604
- Source URL: https://arxiv.org/abs/2306.15604
- Reference count: 9
- This paper constructs a multilingual code search dataset by translating English queries from the CodeSearchNet corpus into French, Japanese, and Chinese, then trains a Transformer-based model on it.

## Executive Summary
This paper presents a methodology for constructing a multilingual code search dataset by translating English queries from the CodeSearchNet corpus into French, Japanese, and Chinese using neural machine translation. The authors create a dataset containing four natural languages (English, French, Japanese, Chinese) and four programming languages (Go, Python, Java, PHP). They evaluate a Transformer-based model pre-trained on this data across multiple code search tasks, demonstrating that models pre-trained with all natural and programming languages perform best. The dataset and model are publicly available for research use.

## Method Summary
The authors translate English queries from CodeSearchNet into French, Japanese, and Chinese using M2M-100, creating multilingual query-code pairs. They then pre-train XLM-R with Masked Language Modeling (MLM) on this translated data and fine-tune on monolingual query-code pairs. The model is evaluated using Mean Reciprocal Rank (MRR) on code search tasks across multiple test sets (CoSQA, WQT, and CSN). The study also investigates the impact of back-translation filtering on dataset quality and performance.

## Key Results
- Models pre-trained with all natural and programming languages (All-to-All) achieve best performance in most cases
- Translation quality affects performance to a certain extent, but dataset size matters more
- Back-translation filtering maintains sufficient dataset size (>250K pairs) to preserve performance gains

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Machine translation quality impacts code search performance but dataset size is the dominant factor
- Mechanism: Back-translation filtering removes low-quality translations, but even filtered datasets maintain sufficient size (>250K pairs) to preserve performance gains
- Core assumption: Code search models require sufficient training data, and quality improvements beyond a certain threshold don't significantly improve performance
- Evidence anchors:
  - [abstract] "By applying back-translation data filtering to our dataset, we demonstrate that the translation quality affects the model's performance to a certain extent, but the data size matters more."
  - [section 5.2] "However, the score changes seem insignificant (±0.02) among these thresholds. One possible reason is that the data size remains over 250K even after filtering, which should already be enough for fine-tuning in general."

### Mechanism 2
- Claim: Pre-training with multilingual queries and monolingual codes (All-to-One) performs well, but pre-training with both multilingual queries and codes (All-to-All) achieves best performance
- Mechanism: Exposure to multilingual natural language patterns during pre-training helps the model learn cross-lingual semantic representations that transfer to code search tasks
- Core assumption: The semantic relationships between natural language queries and code are language-agnostic, so multilingual training improves generalization
- Evidence anchors:
  - [abstract] "Our results show that the model pre-trained with all natural and programming language data has performed best in most cases."
  - [section 4.4] "On CoSQA and WQT, there were also cases where model settings other than All-to-All performed better."

### Mechanism 3
- Claim: Transformer-based models can effectively learn semantic similarity between natural language queries and code when trained on translated datasets
- Mechanism: The model learns to map natural language descriptions to code semantics regardless of the source language, leveraging the semantic consistency across translations
- Core assumption: Code semantics are consistent across languages, and translated queries maintain semantic equivalence with their English originals
- Evidence anchors:
  - [abstract] "we create a multilingual code search dataset in four natural and four programming languages using a neural machine translation model"
  - [section 4.2] "As with Feng et al. (2020), we use Mean Reciprocal Rank (MRR) as an evaluation metric."

## Architecture Onboarding

- Component map: CodeSearchNet corpus -> M2M-100 translation -> Multilingual dataset -> XLM-R MLM pre-training -> Fine-tuning -> MRR evaluation
- Critical path: Translation generation -> Dataset construction -> Pre-training -> Fine-tuning -> Evaluation
- Design tradeoffs: Using XLM-R (multilingual) vs CodeBERT (English-only) - multilingual capability vs potential performance on English-only tasks
- Failure signatures: Low MRR scores despite high dataset size -> translation quality issues; High MRR on training but low on test -> overfitting; Poor performance on specific languages -> insufficient language coverage in pre-training
- First 3 experiments:
  1. Train All-to-One model with English queries and Go code, evaluate on English Go test set
  2. Train All-to-All model with all languages, evaluate on English Go test set
  3. Apply back-translation filtering to All-to-One dataset, compare performance across filtering thresholds

## Limitations

- Translation quality impact is only partially explored - the study shows size dominates but doesn't fully map the quality-size interaction space
- Language coverage gaps exist - results may not generalize to programming languages beyond Go, Python, Java, PHP or natural languages beyond the four studied
- Semantic equivalence assumption - the paper assumes translated queries maintain semantic equivalence with English originals without empirical validation

## Confidence

**High Confidence**: The fundamental claim that multilingual pre-training improves code search performance is well-supported by experimental results showing All-to-All consistently outperforming other settings across multiple test sets.

**Medium Confidence**: The claim that dataset size matters more than translation quality is supported by filtering experiments, but the analysis could be more comprehensive and the relationship may not hold at smaller scales.

**Low Confidence**: The generalizability of results to programming languages beyond the four studied and to natural languages beyond the four used remains uncertain without additional validation.

## Next Checks

1. **Cross-Language Transfer Analysis**: Conduct experiments to measure how well models trained on English-French-Japanese-Chinese transfer to code search tasks in other natural languages (e.g., Spanish, German) and programming languages (e.g., JavaScript, C++), using the same translation pipeline to isolate the effect of language coverage.

2. **Semantic Drift Quantification**: Implement human evaluation or automated semantic similarity measures (e.g., SBERT-based comparison) to quantify semantic drift between English queries and their translations, then correlate this drift with performance degradation across different code domains and query types.

3. **Size-Quality Tradeoff at Critical Thresholds**: Systematically vary dataset sizes below the 250K threshold identified in the paper while maintaining different quality levels through back-translation filtering, to precisely map the boundary where translation quality begins to dominate over dataset size in determining code search performance.
