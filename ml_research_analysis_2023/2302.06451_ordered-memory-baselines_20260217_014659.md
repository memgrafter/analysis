# Ordered Memory Baselines

## Quick Facts
- arXiv ID: 2302.06451
- Source URL: https://arxiv.org/abs/2302.06451
- Reference count: 2
- One-line primary result: Reproduced Ordered Memory model achieving 99.93% accuracy on ListOps, matching state-of-the-art performance

## Executive Summary
We reproduced the Ordered Memory model from NeurIPS 2019 and evaluated it alongside several baseline models on the ListOps dataset. Ordered Memory achieved a top accuracy of 99.93%, matching the state-of-the-art. We also tested Latent TreeLSTM with PPO, SPINN, and treeGRU models. On a subset of 20k examples, Ordered Memory reached 61.15% accuracy, outperforming all baselines. Hyperparameter tuning improved Latent TreeLSTM performance, with the best result at 58.75% accuracy using a batch size of 32 and PPO. SPINN performed poorly at 45.6% accuracy. A parameter search on treeGRU found no significant improvements, with a best accuracy of 83.3% on SST, still below Ordered Memory's 90%. Our results confirm Ordered Memory's superior performance in tree-structured language modeling, even with limited data.

## Method Summary
We implemented the Ordered Memory model and several baseline approaches including Latent TreeLSTM with PPO optimization, SPINN, and treeGRU models. The models were trained and evaluated on the ListOps dataset in multiple configurations: full dataset (90k examples), a 20k subset, and an alternate dataset variant (d5c) with more operators. We conducted hyperparameter tuning on Latent TreeLSTM (batch size optimization) and performed a parameter search on treeGRU (regularization, dropout, learning rate, batch size). The implementation followed the original papers' descriptions, with validation and test accuracy recorded for comparison.

## Key Results
- Ordered Memory achieved 99.93% accuracy on full ListOps dataset, matching state-of-the-art performance
- On 20k example subset, Ordered Memory reached 61.15% accuracy, outperforming all baselines
- Hyperparameter tuning improved Latent TreeLSTM to 58.75% accuracy (batch size 32 with PPO)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Ordered Memory (OM) uses a left-to-right parsing strategy that allows the model to look one step ahead in each sequence, improving tree-structure inference accuracy.
- Mechanism: OM incorporates a gated recursive cell that combines inputs into a feed-forward network, enabling the model to capture hierarchical dependencies more effectively than sequential LSTMs.
- Core assumption: Tree-structured language models inherently outperform sequential models for parsing syntactic structure, even if the inferred trees are not perfect.
- Evidence anchors:
  - [abstract]: "Ordered Memory achieved a top accuracy of 99.93%, matching the state-of-the-art."
  - [section]: "Shen et al. (2019) introduced an Ordered Memory model that uses a left-to-right parsing strategy that can look one step ahead in each sequence."
  - [corpus]: Weak—no direct corpus evidence linking OM to syntactic tree parsing accuracy.
- Break condition: If the assumption that tree structures are always superior for natural language semantics is violated (e.g., in highly sequential tasks), OM's advantage may diminish.

### Mechanism 2
- Claim: OM's performance advantage persists even with reduced training data (20k examples) compared to baselines like Latent Tree LSTM and SPINN.
- Mechanism: The model's architecture allows it to learn effectively from fewer examples by leveraging the inherent structure in the data rather than relying solely on large datasets.
- Core assumption: The tree-structured inductive bias provides enough regularization to generalize well with limited data.
- Evidence anchors:
  - [abstract]: "On a subset of 20k examples, Ordered Memory reached 61.15% accuracy, outperforming all baselines."
  - [section]: "With the subset of 20k examples from the originally used dataset, we found an accuracy of 61.15% after 50 epochs."
  - [corpus]: Weak—no corpus evidence quantifying generalization benefits of tree structures over sequential models with limited data.
- Break condition: If the data contains minimal hierarchical structure, the inductive bias may not help and could even hurt performance.

### Mechanism 3
- Claim: Hyperparameter tuning, particularly batch size reduction from 64 to 32, improves Latent Tree LSTM performance with PPO integration.
- Mechanism: Smaller batch sizes allow for more frequent policy updates in PPO, improving the model's ability to explore the action space during tree parsing.
- Core assumption: PPO's effectiveness in tree parsing tasks scales inversely with batch size, unlike standard supervised learning where larger batches often help.
- Evidence anchors:
  - [section]: "Using the superior PPO model, we compared a batch size of 32 and 128 to their default 64 value... decreasing the batch size to 32 increased the final test accuracy the most to 58.75%."
  - [abstract]: "Hyperparameter tuning improved Latent TreeLSTM performance, with the best result at 58.75% accuracy using a batch size of 32 and PPO."
  - [corpus]: Weak—no corpus evidence showing PPO batch size scaling effects in tree-structured RL tasks.
- Break condition: If PPO's exploration-exploitation balance is not the limiting factor, smaller batches may not improve performance.

## Architecture Onboarding

- Component map: Input tokens → Token embedding → Recursive cell composition (with lookahead) → Tree structure inference → Classification head
- Critical path: Input → Token embedding → Recursive cell composition (with lookahead) → Tree structure inference → Classification head
- Design tradeoffs: OM trades increased model complexity and parameter count for better tree-structure inference accuracy. Simpler models like treeGRU are faster to train but less accurate.
- Failure signatures: If OM underperforms on sequential-only tasks, it may indicate over-reliance on tree structure. If it fails to converge, the recursive composition may be too deep for the given data.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the Ordered Memory model's performance scale with varying dataset sizes beyond the tested 20k and 90k examples?
- Basis in paper: [explicit] The paper mentions exploring OM's performance with smaller datasets (20k examples) but doesn't test larger or intermediate sizes
- Why unresolved: The paper only tested two dataset sizes, leaving a gap in understanding OM's data efficiency across a broader range
- What evidence would resolve it: Systematic testing of OM performance across multiple dataset sizes (e.g., 10k, 50k, 100k examples) would reveal its scaling behavior

### Open Question 2
- Question: What specific aspects of the Ordered Memory architecture contribute most to its superior performance compared to simpler baselines?
- Basis in paper: [explicit] The paper compares OM to simpler models like treeGRU but doesn't perform ablation studies to isolate key architectural components
- Why unresolved: While OM outperforms simpler models, the paper doesn't analyze which specific features (e.g., memory ordering, gating mechanisms) drive this improvement
- What evidence would resolve it: Ablation studies systematically removing or modifying OM components while measuring performance changes would identify critical architectural elements

### Open Question 3
- Question: How does the Ordered Memory model generalize to real-world NLP tasks beyond synthetic datasets like ListOps and SST?
- Basis in paper: [explicit] All experiments were conducted on synthetic or sentiment analysis datasets, with no evaluation on practical NLP applications
- Why unresolved: The paper focuses on controlled benchmark datasets without testing OM's effectiveness on tasks like machine translation, question answering, or named entity recognition
- What evidence would resolve it: Testing OM on diverse real-world NLP benchmarks and comparing its performance to state-of-the-art models would demonstrate its practical applicability

## Limitations

- Hyperparameter tuning for Latent TreeLSTM improved performance, but without ablation studies, we cannot determine whether this gain stems from PPO optimization or architectural changes
- SPINN's poor performance (45.6%) suggests either fundamental limitations in the model or implementation issues that weren't fully resolved
- TreeGRU parameter search found no significant improvements, with best SST accuracy at 83.3% compared to OM's 90%, but the search space may have been insufficiently explored

## Confidence

- High confidence: OM's 99.93% accuracy on full ListOps dataset is reproducible
- Medium confidence: OM outperforms baselines on 20k subset (61.15% accuracy)
- Low confidence: Causal claims about why OM outperforms (tree structure advantages, lookahead mechanism)
