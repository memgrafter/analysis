# Optimizing Sparse Linear Algebra Through Automatic Format Selection and Machine Learning

## Quick Facts
- arXiv ID: 2303.05098
- Source URL: https://arxiv.org/abs/2303.05098
- Reference count: 31
- Primary result: ML-based format selection achieves 1.1×-8× speedups across CPUs and GPUs

## Executive Summary
Morpheus-Oracle is a machine learning library for automatic sparse matrix storage format selection that predicts optimal formats across multiple backends without user input. Using over 2000 real matrices from the SuiteSparse collection, the system achieves 92.63% classification accuracy and 80.22% balanced accuracy. The approach delivers significant performance improvements, achieving 1.1× speedup on CPUs and 1.5× to 8× on GPUs, with maximum observed speedups reaching 7× and 1000× respectively.

## Method Summary
The system employs lightweight ML models trained on runtime-extracted features from sparse matrices to predict optimal storage formats. The approach addresses the challenge of format selection in heterogeneous computing environments by learning patterns from a large corpus of real-world matrices. The ML model uses matrix characteristics as input features and outputs format recommendations that can be applied at runtime without requiring manual analysis or tuning.

## Key Results
- 92.63% classification accuracy and 80.22% balanced accuracy on over 2000 matrices
- 1.1× average speedup on CPUs and 1.5× to 8× on GPUs
- Maximum speedups of 7× on CPUs and 1000× on GPUs

## Why This Works (Mechanism)
The system leverages the observation that sparse matrix patterns exhibit predictable relationships with optimal storage formats. By training ML models on runtime features extracted from matrices, the system can automatically identify these patterns without requiring manual analysis. The lightweight nature of the models enables runtime deployment without significant overhead, making format selection practical for real-world applications.

## Architecture Onboarding

**Component Map:** Matrix Features -> ML Model -> Format Recommendation -> Backend Execution

**Critical Path:** Runtime feature extraction → ML prediction → format application → kernel execution

**Design Tradeoffs:** Model accuracy vs inference latency, feature extraction cost vs prediction benefit, generalization vs specialization

**Failure Signatures:** Incorrect format predictions manifest as reduced performance compared to baseline formats, particularly for matrices with unusual sparsity patterns
