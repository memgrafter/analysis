# Learning Perturbations to Explain Time Series Predictions

## Quick Facts
- arXiv ID: 2305.18840
- Source URL: https://arxiv.org/abs/2305.18840
- Reference count: 40
- Primary result: Learned perturbations significantly improve explanation quality for time series predictions compared to baselines

## Executive Summary
This paper addresses the challenge of explaining predictions made by neural networks on multivariate time series data. The core innovation is learning not only masks to identify important features but also associated perturbations to explain the impact of these features on predictions. By training a neural network to generate perturbations that, when combined with a mask, produce minimal changes in the model's predictions, the method significantly improves explanation quality. Experiments on both synthetic HMM data and real-world MIMIC-III data demonstrate superior performance compared to existing methods like DynaMask and DeepLift.

## Method Summary
The method learns a mask and perturbation model jointly to explain time series predictions. It takes time series data as input and generates a mask identifying important features while simultaneously learning a perturbation network (bidirectional GRU) that outputs feature-wise weighted combinations of past time points. The explanation is computed as Φ(x,m) = m×x + (1−m)×NN(x), where NN(x) is the perturbation output. The objective function combines mask sparsity (λ1||m||1), perturbation sparsity (λ2||NN(x)||1), and prediction fidelity (L(f(x), f(Φ(x, m)))), with the preservation game objective ensuring explanations maintain prediction accuracy while highlighting feature importance.

## Key Results
- Significant improvement in explanation quality metrics (AUP, AUR, Information, mask entropy) compared to baselines
- Outperforms DynaMask, DeepLift, and other perturbation-based methods on both synthetic and real-world data
- Demonstrates effectiveness on MIMIC-III dataset with vital signs and lab test results from ICU patients

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Learning perturbations improves explanation quality by allowing the model to adaptively handle temporal dependencies rather than relying on fixed local averages or Gaussian blurs.
- Mechanism: The method replaces fixed perturbations with a trainable neural network that outputs feature-wise weighted combinations of past time points. This allows the perturbation to capture long-term dependencies and patterns that are not captured by local perturbations.
- Core assumption: Temporal data exhibits long-term dependencies and patterns that fixed local perturbations fail to represent, and these can be learned effectively by a neural network.
- Evidence anchors:
  - [abstract] "In this work, we aim to explain predictions by learning not only masks, but also associated perturbations."
  - [section] "We take inspiration from the perturbation operators of Crabbé & Van Der Schaar (2021)... These perturbations are generally defined as m×x+(1 −m)×µ(x), where µ(x) is a function of the input. In this work, we propose to replace these fixed functions with a neural network..."
- Break condition: If the learned perturbations collapse to trivial solutions (e.g., always outputting zero or mimicking the input), the explanation quality degrades.

### Mechanism 2
- Claim: Adding a regularization term on the perturbation network prevents it from collapsing to a trivial solution and ensures the perturbation remains uninformative unless necessary.
- Mechanism: The objective function includes both ||NN(x)||1 and L(f(x), f(Φ(x, m))). The first term encourages NN(x) to be sparse (uninformative), while the second term only allows it to deviate from uninformative when it helps explain the prediction.
- Core assumption: Without explicit regularization on NN(x), the model will simply learn to output x, rendering the explanation meaningless.
- Evidence anchors:
  - [section] "To prevent this behavior, we modify Equation 9 with the following one: arg min m,Θ∈NN λ1||m||1 + λ2||NN(x)||1 + L(f(x), f(Φ(x, m)))"
  - [section] "By keeping m between 0 and 1, we constrain the mask to only learn how important each feature is."
- Break condition: If λ2 is too small, NN(x) may not be sufficiently regularized and could collapse to the identity function.

### Mechanism 3
- Claim: Using a bidirectional GRU for the perturbation network yields better explanations than unidirectional or fixed perturbations because it can incorporate both past and future context.
- Mechanism: The perturbation network is modeled as a bidirectional GRU that produces weighted sums of historical values, allowing it to incorporate both past and future context when generating perturbations.
- Core assumption: Bidirectional context is necessary to capture the full temporal dependencies relevant for explanation.
- Evidence anchors:
  - [section] "We also compare this choice, in the experiment section, with a unidirectional GRU, which would be closer to the µp t,i average in Crabbé & Van Der Schaar (2021)."
  - [section] "As a result, we choose this model to be a bidirectional GRU (Cho et al., 2014)."
- Break condition: If the bidirectional GRU overfits or if future context is not actually informative for the task, a unidirectional or simpler model may perform better.

## Foundational Learning

- Concept: Loss function balancing between mask sparsity, perturbation sparsity, and prediction fidelity
  - Why needed here: The method requires careful balancing between masking uninformative features, keeping perturbations minimal, and maintaining prediction accuracy. The loss function encodes this multi-objective optimization.
  - Quick check question: What happens to the explanation quality if λ2 is set to zero? (Answer: The perturbation network may collapse to identity function, making explanations meaningless.)

- Concept: Temporal data representation and dependencies
  - Why needed here: The method is specifically designed for time series data where temporal ordering and dependencies matter. Understanding how to represent and model these dependencies is crucial.
  - Quick check question: How does a bidirectional GRU differ from a unidirectional one in terms of temporal context? (Answer: Bidirectional GRU can access both past and future context, while unidirectional only sees past.)

- Concept: Mask training objectives (preservation vs deletion game)
  - Why needed here: The method uses a preservation game objective, which differs from deletion game used in some other perturbation-based methods. Understanding this distinction is important for correct implementation.
  - Quick check question: What is the key difference between preservation and deletion game objectives? (Answer: Preservation aims to keep predictions close while masking as much as possible, deletion aims to change predictions as much as possible while masking as little as possible.)

## Architecture Onboarding

- Component map: Input -> Mask generator -> Perturbation network -> Combination -> Target model -> Loss computation -> Backpropagation to both mask and perturbation network
- Critical path: Input → Mask generator → Perturbation network → Combination → Target model → Loss computation → Backpropagation to both mask and perturbation network
- Design tradeoffs:
  - Bidirectional vs unidirectional GRU: Bidirectional captures more context but may overfit; unidirectional is simpler but may miss important dependencies
  - λ1 vs λ2 balance: Higher λ1 forces sparser masks; higher λ2 forces sparser perturbations
  - Preservation vs deletion game: Preservation maintains prediction fidelity; deletion may reveal more about feature importance
- Failure signatures:
  - Mask collapsing to all ones or all zeros: Check λ1 value and training stability
  - Perturbation network outputting identity function: Check λ2 value and regularization
  - Poor explanation quality compared to baselines: Verify implementation matches paper, check data preprocessing
