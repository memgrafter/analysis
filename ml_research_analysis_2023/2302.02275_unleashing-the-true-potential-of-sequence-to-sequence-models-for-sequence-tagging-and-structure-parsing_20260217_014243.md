# Unleashing the True Potential of Sequence-to-Sequence Models for Sequence Tagging and Structure Parsing

## Quick Facts
- arXiv ID: 2302.02275
- Source URL: https://arxiv.org/abs/2302.02275
- Reference count: 27
- Key outcome: S2S models with constrained decoding outperform other S2S approaches and achieve state-of-the-art or comparable performance on POS tagging, NER, constituency parsing, and dependency parsing

## Executive Summary
This paper presents a systematic study of using sequence-to-sequence (S2S) models for structured prediction tasks including POS tagging, NER, constituency parsing, and dependency parsing. The authors propose three novel linearization schemas (Label Sequence, Label with Text, and Prompt) that convert structured outputs into sequences suitable for S2S generation. For each schema, they design constrained decoding algorithms to ensure valid output sequences. Experiments on OntoNotes 5 and Penn Treebank 3 demonstrate that their approach outperforms other S2S methods and achieves competitive results with state-of-the-art specialized models, showcasing the potential of S2S models for structured prediction without requiring specialized decoders or external resources.

## Method Summary
The method fine-tunes BART-large as the underlying S2S model using three linearization schemas (LS, LT, PT) for each of four tasks. The schemas convert structured outputs into sequences: LS uses labels only, LT incorporates text tokens from input, and PT uses prompt-style formatting. For each schema, task-specific constrained decoding algorithms (Algorithms 1-12) ensure valid output generation during inference. The approach is evaluated on OntoNotes 5 and Penn Treebank 3 for POS, NER, CON, and DEP tasks, training three times with different random seeds and reporting average scores with standard deviations.

## Key Results
- S2S models with constrained decoding outperform other S2S approaches using external resources
- Label with Text (LT) and Prompt (PT) schemas generally outperform Label Sequence (LS) due to better language model utilization
- The best models achieve state-of-the-art or comparable performance across all four tasks (POS, NER, CON, DEP)
- Constrained decoding effectively ensures structural validity of generated outputs

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Constraining decoding during inference improves generation quality by preventing invalid token sequences
- Mechanism: The proposed constrained decoding algorithms (Algorithms 1-12) restrict the model to only generate valid sequences that conform to the task-specific schemas (LS, LT, PT). This ensures structural validity of outputs.
- Core assumption: Autoregressive generation will benefit from explicit constraints that prevent it from producing invalid tokens at each step
- Evidence anchors:
  - [abstract]: "Experiments show that although more lexicalized schemas yield longer output sequences that require heavier training, their sequences being closer to natural language makes them easier to learn."
  - [section 4]: Detailed description of constrained decoding algorithms for each task
- Break condition: If the constraints are too restrictive and prevent the model from exploring valid but unconventional sequences, or if the constraint implementation has bugs

### Mechanism 2
- Claim: Using textual tokens in output schemas improves learning by leveraging the model's language modeling capabilities
- Mechanism: The Label with Text (LT) and Prompt (PT) schemas incorporate actual text tokens from the input sentence, making the output more similar to natural language. This allows the BART model to better utilize its pretrained language understanding.
- Core assumption: BART's language modeling capabilities will transfer effectively to tasks when the output resembles natural language
- Evidence anchors:
  - [abstract]: "Moreover, S2S models using our constrained decoding outperform other S2S approaches using external resources."
  - [section 5]: Results showing LT and PT outperforming LS on most tasks
- Break condition: If the additional textual tokens increase complexity too much, causing overfitting or making the task harder to learn

### Mechanism 3
- Claim: Multiple linearization schemas provide flexibility to match task characteristics and improve performance
- Mechanism: The paper proposes three distinct schemas (LS, LT, PT) with different levels of lexicalization. This allows matching the output format to the specific needs of each task, optimizing the balance between structure and natural language.
- Core assumption: Different tasks benefit from different output formats, and providing multiple options allows optimization
- Evidence anchors:
  - [abstract]: "3 lexically diverse linearization schemas and corresponding constrained decoding methods are designed and evaluated."
  - [section 6.3]: Analysis showing different schemas work better for different tasks
- Break condition: If the schema differences are not significant enough to justify the added complexity, or if the wrong schema is chosen for a task

## Architecture Onboarding

- Component map:
  BART-large -> Tokenizer -> Linearization Schema (LS/LT/PT) -> Constrained Decoder -> Post-processor -> Structured Output

- Critical path:
  1. Tokenize input sentence using BART tokenizer
  2. Apply task-specific linearization to create target sequence
  3. Train BART model to generate target sequence from input
  4. During inference, use constrained decoding to generate valid sequences
  5. Post-process generated sequences back to structured format
  6. Evaluate using task-specific metrics

- Design tradeoffs:
  - Schema complexity vs. naturalness: LS is simple but less natural; PT is more natural but complex
  - Lexicalization level: More textual tokens help language model transfer but increase sequence length
  - Constraint strictness: Tighter constraints ensure validity but may limit model flexibility

- Failure signatures:
  - Invalid output sequences (decoder violated constraints)
  - Poor performance on OOV words (language model dependency)
  - Degradation with sentence length (sequence modeling limitations)
  - Inconsistent tagging/labeling across similar contexts

- First 3 experiments:
  1. Implement LS schema for POS tagging with constrained decoding and evaluate on OntoNotes
  2. Add LT schema for POS and compare performance against LS
  3. Implement constrained decoding for NER with LT schema and test on CoNLL'03 dataset

## Limitations
- Limited to English datasets (OntoNotes 5, Penn Treebank 3, CoNLL'03), results may not generalize to other languages
- Substantial computational requirements for fine-tuning BART-large with no detailed training time or memory characterization
- Primary benchmarking against other S2S approaches rather than full range of specialized architectures
- Potential inference latency from constrained decoding algorithms not characterized

## Confidence
- High Confidence (95%): S2S models with constrained decoding consistently outperform other S2S approaches across all four tasks
- Medium Confidence (75%): Improvements over specialized state-of-the-art models are significant enough for production consideration
- Low Confidence (60%): Relative performance differences between LT and PT schemas are robust across different datasets and domains

## Next Checks
1. **Multilingual Evaluation**: Implement and evaluate the proposed approach on non-English datasets to assess cross-lingual generalization and validate whether language modeling advantages extend beyond English.

2. **Efficiency Benchmarking**: Measure inference time and memory usage for each schema with and without constrained decoding, comparing against specialized models to provide practical deployment guidance on computational trade-offs.

3. **Zero-shot and Few-shot Transfer**: Evaluate the models' ability to generalize to new domains or tagging schemes with minimal fine-tuning to test practical advantages for adaptation beyond original training data.
