# AutoSTL: Automated Spatio-Temporal Multi-Task Learning

## Quick Facts
- arXiv ID: 2304.09174
- Source URL: https://arxiv.org/abs/2304.09174
- Reference count: 16
- Key outcome: First automated method for spatio-temporal multi-task learning, achieving state-of-the-art performance on benchmark datasets.

## Executive Summary
This paper introduces AutoSTL, a novel automated method for spatio-temporal multi-task learning. It proposes a scalable architecture that automatically allocates advanced operations (GCN, CNN, RNN, Transformer) and fusion weights to capture complex dependencies between multiple spatio-temporal tasks. The method uses shared modules and a feature fusion mechanism to model intrinsic relationships between tasks, while AutoML optimizes the operation selection and fusion weights. Experiments on NYC Taxi and PEMSD4 datasets demonstrate that AutoSTL achieves superior performance compared to single-task and fixed multi-task baselines.

## Method Summary
AutoSTL is a scalable architecture for automated spatio-temporal multi-task learning. It consists of a shared bottom MLP layer, multiple stacking hidden layers (each with task-specific and shared modules), and task-specific towers. The model uses AutoML with Gumbel-softmax and bi-level optimization to automatically select operations from a set of advanced spatio-temporal operations (GCN, CNN, RNN, Transformer) for each module and optimize fusion weights between task-specific and shared features. The training process involves three phases: pretrain, search, and retrain. The method aims to jointly model multiple spatio-temporal tasks (e.g., traffic flow, speed, OD flow, trip duration) while capturing spatial and temporal dependencies and intrinsic task relationships.

## Key Results
- AutoSTL achieves state-of-the-art performance on benchmark spatio-temporal datasets (NYC Taxi, PEMSD4)
- Automated operation selection and fusion weight optimization improve performance over fixed architectures
- Shared modules and feature fusion capture intrinsic relationships between tasks, leading to performance gains

## Architecture Onboarding

- Component map: Input -> Shared Bottom -> Hidden Layers (task-specific + shared modules with fusion) -> Task-specific Towers -> Output

- Critical path: Input features are transformed by the shared bottom, processed through stacking hidden layers with automated operation selection and fusion, and finally passed through task-specific towers for predictions.

- Design tradeoffs:
  - Flexibility vs. Complexity: The automated approach adds flexibility but increases complexity and training time
  - Shared vs. Task-specific: Balancing shared modules (for knowledge transfer) with task-specific modules (for task-specific patterns)
  - Search Space vs. Efficiency: Larger operation sets provide more flexibility but increase search time

- Failure signatures:
  - Poor performance on individual tasks may indicate insufficient task-specific modeling
  - Inconsistent results across different task combinations may suggest poor generalization of the shared modules
  - Long training times or convergence issues may indicate an overly complex search space

- First 3 experiments:
  1. Compare performance on a single task using AutoSTL versus a single-task baseline (e.g., DCRNN) to verify that the shared modules don't hurt single-task performance
  2. Test different numbers of hidden layers (e.g., 1, 3, 5) on a two-task setting to find the optimal depth
  3. Compare the automated operation selection results with manually designed architectures for the same tasks to validate the AutoML approach

## Limitations

- Lack of ablation studies to isolate the impact of individual components (shared modules, AutoML operation selection, fusion mechanism)
- Scalability to many tasks (>4) has not been demonstrated
- Computational overhead of the three-phase training process is not quantified

## Confidence

- High confidence: The proposed architecture design and multi-task learning formulation are technically sound
- Medium confidence: The AutoML-based operation selection provides benefits over fixed architectures, based on benchmark results
- Low confidence: The claim of being the first automated method for spatio-temporal multi-task learning requires verification against closely related AutoML approaches
