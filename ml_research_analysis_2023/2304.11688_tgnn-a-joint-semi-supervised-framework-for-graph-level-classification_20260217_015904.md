# TGNN: A Joint Semi-supervised Framework for Graph-level Classification

## Quick Facts
- arXiv ID: 2304.11688
- Source URL: https://arxiv.org/abs/2304.11688
- Reference count: 3
- Primary result: State-of-the-art semi-supervised graph classification on seven standard datasets and OGB benchmarks

## Executive Summary
TGNN introduces a novel semi-supervised graph classification framework that combines message passing and graph kernel modules to capture both implicit and explicit graph topology. The method achieves state-of-the-art results by aligning similarity distributions between two complementary graph representations through a consistency loss. This approach effectively leverages unlabeled data by enforcing agreement between learned embeddings from GNN-based and random walk kernel-based modules.

## Method Summary
TGNN employs a twin-module architecture: a message passing module using GNN for implicit topology learning through neighbor aggregation, and a graph kernel module that explicitly captures structural features via random walk kernels on learnable hidden graphs. The framework uses a memory bank of labeled graph embeddings as anchors for computing similarity distributions, which are then aligned between modules using KL divergence. Four graph augmentation strategies (edge dropping, node dropping, attribute masking, subgraph) enhance the consistency training. The model is trained with both supervised cross-entropy loss on labeled data and consistency loss between the two modules.

## Key Results
- Achieves state-of-the-art performance across seven standard graph classification datasets
- Outperforms recent semi-supervised graph learning methods on both labeled and unlabeled data
- On OGB-HIV and OGB-MUV benchmarks, surpasses baselines with ROC-AUC improvements at both 1% and 10% labeling rates

## Why This Works (Mechanism)

### Mechanism 1
The consistency loss enforces alignment between two complementary graph representations, improving generalization on unlabeled data. TGNN computes similarity distributions between unlabeled graphs and labeled anchors in both message passing and graph kernel embedding spaces, using KL divergence to penalize discrepancies.

### Mechanism 2
The graph kernel module explicitly captures high-order substructures like paths that message passing modules struggle to represent. By comparing each graph to learnable hidden graphs using random walk kernels, it directly measures structural similarity at multiple path lengths.

### Mechanism 3
The memory bank of labeled graph embeddings provides stable anchors for similarity comparison, reducing variance in consistency training. A queue-based memory bank stores embeddings of labeled graphs from recent iterations, providing consistent reference points for unlabeled graph comparisons.

## Architecture Onboarding

- **Component map**: Graph → Augmentation → Both modules → Similarity distributions → Consistency loss + Supervised loss → Classification
- **Critical path**: The complete flow from input graph through augmentation, dual module processing, similarity computation, consistency and supervised losses, to final classification output
- **Design tradeoffs**: Using random walk kernels provides explicit structural information but increases computational complexity; the memory bank provides stable references but requires careful management; ensemble approach adds robustness but doubles model complexity
- **Failure signatures**: Poor performance on unlabeled data suggests consistency loss isn't effective; overfitting to labeled data indicates insufficient regularization; inconsistent results across runs suggest instability in the memory bank mechanism
- **First 3 experiments**:
  1. Train message passing module only (MP-Sup variant) to establish baseline
  2. Train graph kernel module only (GK-Sup variant) to assess standalone performance
  3. Train both modules with only supervised loss (no consistency) to measure ensemble effect without consistency regularization

## Open Questions the Paper Calls Out

### Open Question 1
How does the performance of TGNN scale when using more than 16 hidden graphs in the graph kernel module? The paper sets the number of hidden graphs to 16 empirically and shows sensitivity analysis for other hyperparameters, but does not explore the effect of increasing the number of hidden graphs.

### Open Question 2
Can the graph kernel module be adapted to handle directed graphs without losing the ability to capture structural information? The paper parametrizes hidden graphs as undirected to reduce parameters, but does not discuss adaptation for directed graphs.

### Open Question 3
What is the impact of using different graph augmentation strategies on the consistency loss and final classification performance? The paper mentions using four augmentation strategies but does not analyze their individual contributions.

## Limitations
- The framework requires maintaining two separate GNN modules, increasing computational complexity and memory requirements
- Performance heavily depends on the effectiveness of graph augmentations, but specific augmentation strategies and hyperparameters are not fully detailed
- The memory bank mechanism's stability across training iterations needs empirical validation, particularly for very large-scale datasets

## Confidence

- **High Confidence**: The dual-module architecture and consistency loss formulation are clearly specified and theoretically sound
- **Medium Confidence**: The empirical results on standard benchmarks are reproducible, but the OGB results may depend on specific implementation details not fully disclosed
- **Low Confidence**: The long-term stability of the memory bank mechanism and its impact on consistency training is not thoroughly evaluated

## Next Checks

1. **Ablation Study**: Remove the consistency loss and evaluate performance degradation to quantify its contribution
2. **Memory Bank Analysis**: Track embedding drift in the memory bank over training iterations to assess stability
3. **Scalability Test**: Evaluate performance on graphs with varying sizes to identify computational bottlenecks in the random walk kernel module
