# Learning on Graphs under Label Noise

## Quick Facts
- arXiv ID: 2306.08194
- Source URL: https://arxiv.org/abs/2306.08194
- Reference count: 0
- Outperforms state-of-the-art methods on node classification under label noise

## Executive Summary
This paper tackles node classification on graphs in the presence of label noise, a critical challenge in real-world applications. The proposed Consistent Graph Neural Network (CGNN) integrates graph contrastive learning as regularization and a homophily-based sample selection technique to identify and correct noisy labels. Experiments on three benchmark datasets demonstrate significant improvements over existing methods, particularly under uniform and pair noise conditions.

## Method Summary
CGNN combines a standard GNN backbone with graph contrastive learning regularization and neighborhood-based label noise correction. The method generates two augmented graph views through edge dropping and node attribute masking, then enforces consistent node representations across these views via contrastive loss. Simultaneously, it identifies potentially noisy labels by measuring consistency between node labels and their neighbors' majority labels, correcting them based on a homophily assumption. The total loss combines supervised cross-entropy with contrastive regularization.

## Key Results
- Achieves up to 1.9% improvement in accuracy over best baseline on benchmark datasets
- Demonstrates superior robustness to both uniform and pair label noise
- Maintains stable performance across different training scenarios

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Contrastive regularization prevents noisy nodes from dominating the learned representations by enforcing consistent embeddings across augmentations.
- Mechanism: Two graph views are generated through random edge dropping and node attribute masking. The model learns representations that maximize agreement between these views while minimizing agreement with other nodes, as measured by cosine similarity with temperature-scaled softmax.
- Core assumption: The semantic content of nodes remains invariant under the chosen augmentations, so consistent representations indicate robust learning.
- Evidence anchors:
  - [abstract] "we employ graph contrastive learning as a regularization term, which promotes two views of augmented nodes to have consistent representations"
  - [section] "we enforce two node views to have consistent representations compared with other nodes"
  - [corpus] Weak: related papers focus on contrastive learning for graph noise, but none directly cite this specific augmentation scheme.
- Break condition: If augmentations destroy too much signal or if the graph structure itself is highly noisy, the contrastive objective may not align with true semantic consistency.

### Mechanism 2
- Claim: Neighborhood consistency filtering identifies noisy labels by leveraging homophily.
- Mechanism: For each labeled node, the method computes the most frequent label among its neighbors. Nodes whose predicted labels differ from the majority neighbor label are flagged as candidates. A similarity consistency score ensures only nodes whose embeddings align with neighbors are corrected.
- Core assumption: In most cases, linked nodes share the same semantic class (homophily holds), so disagreement indicates label corruption.
- Evidence anchors:
  - [abstract] "we present a sample selection technique based on the homophily assumption, which identifies noisy nodes by measuring the consistency between the labels with their neighbors"
  - [section] "we recall that the homophily assumption requires that linked nodes have consistent semantics"
  - [corpus] Weak: neighboring work addresses noise detection, but specific homophily-based scoring is not widely reported.
- Break condition: In heterophilic graphs or regions where label distribution is multimodal, this method may misclassify clean nodes as noisy.

### Mechanism 3
- Claim: Combining contrastive regularization with supervised loss mitigates overfitting to label noise.
- Mechanism: The total loss is a sum of supervised cross-entropy (on labeled nodes) and contrastive loss (on all nodes). The contrastive term provides a label-agnostic signal, improving generalization even when some labels are wrong.
- Core assumption: The contrastive signal provides useful gradients even in the presence of noisy labels, helping the model avoid memorizing incorrect patterns.
- Evidence anchors:
  - [abstract] "When combined with supervised classification loss, this regularization term can help produce generalized node representations in the face of label noise"
  - [section] "we combine both the supervised learning loss with the contrastive regularization term"
  - [corpus] Weak: broader literature supports contrastive learning as regularization, but not always in the noisy label graph context.
- Break condition: If the supervised loss dominates, noisy labels can still corrupt the model; if contrastive loss dominates, the model may underfit the available label signal.

## Architecture Onboarding

- Component map:
  Graph augmentation module -> GNN encoder -> Contrastive loss module -> Label correction module -> Supervised loss module

- Critical path:
  1. Forward pass through GNN on both augmentations.
  2. Compute contrastive loss.
  3. Compute supervised loss.
  4. Update embeddings and labels if in correction phase.
  5. Backpropagate total loss.

- Design tradeoffs:
  - Contrastive vs. supervised weight: Higher contrastive weight improves robustness but may underfit labeled data.
  - Augmentation strength: Too much masking/dropping destroys signal; too little fails to regularize.
  - Neighborhood consistency threshold: Too low flags too many clean nodes; too high misses noisy ones.

- Failure signatures:
  - Accuracy plateaus early: Possibly contrastive signal too weak or augmentation too aggressive.
  - High variance across runs: Possibly label correction hyperparameters not tuned.
  - Degraded performance on clean graphs: Possibly over-regularization.

- First 3 experiments:
  1. Train on clean graph to confirm baseline GNN performance.
  2. Add uniform noise and verify that CGNN outperforms vanilla GNN.
  3. Vary the contrastive weight λ and plot accuracy to find optimal balance.
