# Parameter-efficient Modularised Bias Mitigation via AdapterFusion

## Quick Facts
- arXiv ID: 2302.06321
- Source URL: https://arxiv.org/abs/2302.06321
- Reference count: 40
- This paper introduces DAM (Debiasing with Adapter Modules), a novel approach to bias mitigation in NLP models that enables on-demand, modular debiasing.

## Executive Summary
This paper introduces DAM (Debiasing with Adapter Modules), a novel approach to bias mitigation in NLP models that enables on-demand, modular debiasing. The method builds on AdapterFusion, encapsulating bias mitigation functionalities into separate adapter modules that can be selectively integrated into a model while keeping the core model untouched. DAM first learns task and debiasing adapters independently, then combines them through a fusion layer with attention mechanism. Experiments on three classification tasks (biography classification, hate speech detection, and mention detection) with gender, race, and age as protected attributes demonstrate that DAM: (1) consistently improves bias mitigation compared to fully fine-tuned models, (2) better avoids catastrophic forgetting in multi-attribute scenarios, and (3) maintains on-par task performance while significantly reducing trainable parameters (up to 60% fewer). The modular architecture allows flexible switching between original and debiased states, offering practical advantages for real-world deployment where different contexts may require different levels of fairness considerations.

## Method Summary
DAM extends AdapterFusion to bias mitigation by treating debiasing each protected attribute as a standalone task learned by independent debiasing adapters. The approach trains task and debiasing adapters separately, then uses an attention-based fusion layer to combine their outputs. This modular design keeps the core model frozen while allowing flexible integration of bias mitigation capabilities. The method employs adversarial training with gradient reversal for debiasing, and the fusion layer learns to optimally combine task and debiasing adapter outputs through attention mechanisms.

## Key Results
- DAM consistently improves bias mitigation compared to fully fine-tuned models across three classification tasks
- Better avoids catastrophic forgetting when handling multiple protected attributes simultaneously
- Maintains on-par task performance while reducing trainable parameters by up to 60% compared to full fine-tuning

## Why This Works (Mechanism)

### Mechanism 1
- Claim: AdapterFusion allows selective integration of debiasing capabilities without altering the core model parameters
- Mechanism: DAM trains separate task and debiasing adapters independently, then uses an attention-based fusion layer to combine their outputs, enabling modular bias mitigation
- Core assumption: Task and debiasing objectives can be learned independently and combined effectively through attention mechanisms
- Evidence anchors:
  - [abstract] "we propose a novel approach to develop stand-alone debiasing functionalities separate from the model, which can be integrated into the model on-demand"
  - [section 2.1] "DAM extends this principle idea to bias mitigation by viewing the objective of 'removing each protected attribute' as a standalone task, learned by an independent debiasing adapter module"
  - [corpus] Weak evidence - related papers discuss adapter-based bias mitigation but don't specifically validate this modular fusion approach
- Break condition: If the fusion layer cannot effectively learn to combine task and debiasing adapters, the modular approach would fail

### Mechanism 2
- Claim: DAM prevents catastrophic forgetting when handling multiple protected attributes
- Mechanism: By learning separate debiasing adapters for each attribute and combining them through fusion, DAM avoids the interference that occurs when training on multiple attributes simultaneously
- Core assumption: Independent adapter learning followed by fusion preserves distinct debiasing capabilities for each attribute
- Evidence anchors:
  - [abstract] "better avoids catastrophic forgetting in multi-attribute scenarios"
  - [section 5] "Looking at the attacker's BAcc, while FT-DEBIAS G+A is not able to debias the age attribute... our DAM G+A provides strongly improved bias mitigation for age"
  - [corpus] Weak evidence - no direct evidence from related work on catastrophic forgetting prevention in multi-attribute debiasing
- Break condition: If the fusion layer gives disproportionate attention to certain adapters, forgetting of other attributes may occur

### Mechanism 3
- Claim: DAM provides parameter efficiency by keeping the core model frozen while training only adapter modules
- Mechanism: The approach requires training only the adapter modules and fusion layer (up to 60% fewer parameters) rather than full model fine-tuning
- Core assumption: Adapter-based learning can achieve comparable performance to full fine-tuning with significantly fewer parameters
- Evidence anchors:
  - [abstract] "maintaining on-par task performance while significantly reducing trainable parameters (up to 60% fewer)"
  - [section 2.1] "Rücklé et al. (2021) show the training efficiency of adapter models in comparison with full model fine-tuning (∼60%)"
  - [table 1] "The adapter-based models contain significantly fewer trainable parameters in comparison with fully fine-tuned models"
- Break condition: If the limited parameter space of adapters cannot capture necessary task and debiasing information

## Architecture Onboarding

- Component map:
  - Transformer block with adapter extensions containing:
    - Task adapter (for main classification objective)
    - Multiple debiasing adapters (one per protected attribute)
    - Fusion layer (attention-based combiner)
    - Frozen core model parameters

- Critical path:
  1. Train task adapter on main task objective
  2. Train each debiasing adapter independently on adversarial objectives
  3. Freeze all adapters and train fusion layer on combined objectives

- Design tradeoffs:
  - Modularity vs. end-to-end optimization: Modular approach provides flexibility but may miss global optimization
  - Parameter efficiency vs. expressiveness: Adapters are efficient but may have limited capacity compared to full fine-tuning
  - Independent learning vs. coordination: Separate adapter training avoids interference but requires effective fusion

- Failure signatures:
  - Fusion layer attention concentrates heavily on task adapter (fusion layer fails to integrate debiasing)
  - Debiasing adapters show negligible impact on protected attribute leakage
  - Task performance degrades significantly when debiasing adapters are added

- First 3 experiments:
  1. Implement DAM with one protected attribute on BIOS dataset and verify parameter efficiency
  2. Compare DAM's bias mitigation effectiveness against FT-DEBIAS baseline
  3. Test DAM's ability to handle two protected attributes simultaneously on PAN16 dataset

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does DAM perform on non-binary gender classification tasks?
- Basis in paper: [explicit] The authors acknowledge the limitations of using binary gender classification in BIOS and PAN16 datasets, and note that DAM can be defined for generic non-binary settings.
- Why unresolved: The paper focuses on binary gender classification due to dataset constraints, leaving the performance on non-binary gender tasks unexplored.
- What evidence would resolve it: Experiments applying DAM to datasets with non-binary gender categories, measuring task performance and bias mitigation effectiveness.

### Open Question 3
- Question: How does DAM handle multiple protected attributes with complex interactions or correlations?
- Basis in paper: [explicit] The authors mention a possible correlation between gender and age in PAN16 dataset, noting that debiasing one attribute can affect the other.
- Why unresolved: The paper does not explore the complex interactions or correlations between multiple protected attributes in depth, nor does it provide a systematic approach to handle such scenarios.
- What evidence would resolve it: Experiments analyzing the interactions between multiple protected attributes in DAM, developing strategies to handle complex correlations, and evaluating the effectiveness of these strategies.

## Limitations

- Limited analysis of fusion layer effectiveness and attention weight distributions
- Lack of exploration of complex, intersectional bias scenarios beyond three simple protected attributes
- No comprehensive runtime efficiency benchmarking beyond parameter count comparison

## Confidence

**High Confidence**: Parameter efficiency claims (supported by explicit parameter counts in Table 1 showing adapter-based models use significantly fewer parameters than fully fine-tuned models), modular architecture design (clearly specified in section 2.1 with distinct components for task adapters, debiasing adapters, and fusion layer).

**Medium Confidence**: Bias mitigation effectiveness (demonstrated across three datasets with consistent improvements in attacker accuracy and balanced accuracy, but lacks ablation studies on fusion layer contribution), catastrophic forgetting prevention (shown in multi-attribute scenarios but without comparison to alternative multi-task learning approaches).

**Low Confidence**: Fusion layer mechanism (attention-based combination is described but not thoroughly validated or analyzed), scalability to more complex bias scenarios (limited to three datasets with single/multiple attributes, no exploration of intersectional biases or complex bias types).

## Next Checks

1. **Fusion Layer Analysis**: Conduct ablation studies removing the fusion layer to quantify its contribution to bias mitigation performance, and analyze attention weight distributions across different protected attributes to verify balanced integration.

2. **Cross-Domain Generalization**: Test DAM on additional datasets with different bias types (e.g., intersectional gender-race bias) and classification tasks (beyond the three studied) to evaluate the approach's generalizability and identify potential limitations.

3. **Runtime Efficiency Benchmarking**: Measure actual inference latency and memory usage for DAM compared to fully fine-tuned and FT-DEBIAS approaches, accounting for the overhead of multiple adapters and fusion layer computation to validate claimed efficiency benefits.
