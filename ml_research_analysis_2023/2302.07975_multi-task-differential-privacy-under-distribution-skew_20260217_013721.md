# Multi-Task Differential Privacy Under Distribution Skew

## Quick Facts
- arXiv ID: 2302.07975
- Source URL: https://arxiv.org/abs/2302.07975
- Reference count: 40
- Primary result: Adaptive privacy budget allocation improves tail task utility in multi-task learning under user-level DP

## Executive Summary
This paper addresses the challenge of multi-task learning under user-level differential privacy when tasks have highly skewed data distributions. The key insight is that traditional uniform privacy budget allocation disadvantages tail tasks (with fewer users) due to their higher sensitivity to noise. The authors propose an adaptive method that allocates larger portions of the privacy budget to smaller tasks based on their user counts, solving an optimization problem that balances privacy constraints with task-specific utility. Experiments on MovieLens and Million Song Data show significant improvements in overall utility, especially for tail tasks, achieving state-of-the-art results while maintaining user-level differential privacy guarantees.

## Method Summary
The method adaptively allocates a user's privacy budget across tasks by assigning larger weights to smaller (tail) tasks based on their user counts. For task i with n_i users, the optimal weight is ω_i ∝ n_i^(-(1+γ)/4) where γ depends on the loss function (0 for convex, 1 for strongly convex). The algorithm solves a constrained optimization problem that minimizes overall noise while respecting per-user privacy budgets. A clipping step ensures exact privacy guarantees by adjusting weights when the constraint ∑_i∈Ω_j ω_i^2 ≤ β is violated. The method applies generically to both Sufficient Statistics Perturbation (SSP) and noisy gradient descent algorithms. When task counts aren't public, the method uses DP estimates to compute weights, with bounded error propagation.

## Key Results
- Adaptive weights improve tail task utility by 20-30% compared to uniform allocation on MovieLens and Million Song Data
- The method achieves state-of-the-art results for multi-task learning under user-level differential privacy
- A single hyperparameter (controlling skew adaptation) allows fine-tuning the trade-off between head and tail task quality
- Weight clipping occurs infrequently when privacy budget is reasonably sized relative to task distribution skew

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Adaptive weights improve tail task utility by allocating larger privacy budget portions to tasks with fewer users.
- Mechanism: The method computes optimal weights ω_i ∝ n_i^(-(1+γ)/4) where n_i is the number of users contributing to task i. This assigns larger weights to smaller tasks, improving their signal-to-noise ratio under the same privacy budget.
- Core assumption: Task-user graph follows Assumption 4.1 where users contribute uniformly to tasks but task sizes vary.
- Evidence anchors:
  - [abstract] "The key idea is to adaptively allocate a user's privacy budget across tasks by assigning larger weights to smaller (tail) tasks"
  - [section 4] "the optimal trade-off is obtained when ω_i ∝ n_i^(-(1+γ)/4), i.e. larger weights are assigned to smaller tasks"
  - [corpus] Weak - corpus papers focus on federated learning heterogeneity but don't directly address this adaptive weight allocation mechanism
- Break condition: When task sizes are uniform (all n_i equal), the mechanism provides no improvement since weights become uniform.

### Mechanism 2
- Claim: Weight clipping ensures exact privacy guarantees while maintaining utility in high-probability events.
- Mechanism: After computing optimal weights ω_i, the algorithm clips weights per user to ensure ∑_i∈Ω_j ω_i^2 ≤ β for each user j, where β is the user RDP budget.
- Core assumption: The unclipped weights satisfy the privacy constraint with high probability (w.h.p.).
- Evidence anchors:
  - [section 4] "we simply add the following clipping step: let w* be the task-user weights defined as w*_ij = ω*_i min(1, β^(1/2)/(∑_i'∈Ω_j ω*_i')^1/2)"
  - [section A.5] "clipping does not occur since the budget constraint is satisfied" under high probability event
  - [corpus] Weak - corpus papers discuss clipping but not in the context of per-user budget allocation with high-probability guarantees
- Break condition: When privacy budget β is too small relative to task distribution skew, clipping becomes necessary and reduces utility.

### Mechanism 3
- Claim: The optimization problem for weights balances privacy budget allocation against task utility under distribution skew.
- Mechanism: The method solves min_ω ∑_i 1/(ω_i^2 n_i^γ) subject to ∑_i∈Ω_j ω_i^2 ≤ β for all users j, where γ=0 for convex losses and γ=1 for strongly convex losses.
- Core assumption: Task sizes n_i are publicly known or can be privately estimated with bounded error.
- Evidence anchors:
  - [section 4] "the problem becomes: min_ω∈R^m_+ ∑_i 1/(ω_i^2 n_i^γ) s.t. c(n) ∑_i n_i/n ω_i^2 ≤ β"
  - [section B] "If the counts n_i are not public, we can use DP estimates ˆn_i, and use them to solve the problem"
  - [corpus] Weak - corpus papers discuss federated learning with non-IID data but don't address this specific constrained optimization for privacy budget allocation
- Break condition: When count estimates ˆn_i have large errors relative to true counts n_i, the solution quality degrades.

## Architecture Onboarding

- Component map:
  - Input: Task-user graph Ω, user features x_ij, labels y_ij, privacy budget β
  - Private count estimator (optional): Estimates task sizes n_i when not public
  - Weight optimizer: Computes optimal weights ω_i ∝ n_i^(-(1+γ)/4) or their private estimates
  - Clipper: Ensures per-user privacy budget constraints are met
  - Algorithm selector: Chooses between SSP (Algorithm 1) or DPSGD (Algorithm 2)
  - Training loop: Applies weighted objective to the selected algorithm

- Critical path:
  1. Estimate task sizes (if not public)
  2. Compute optimal weights based on task sizes
  3. Clip weights to meet privacy constraints
  4. Apply weighted objective to chosen algorithm
  5. Train model and output results

- Design tradeoffs:
  - Accuracy vs privacy: Larger weights improve utility but consume more privacy budget
  - Head vs tail tasks: Weight allocation shifts quality from frequent to rare tasks
  - Exact vs approximate counts: Using private estimates adds noise but enables the method when counts aren't public

- Failure signatures:
  - Poor tail task performance: Indicates weights are too uniform or privacy budget too constrained
  - Large weight clipping: Suggests privacy budget β is too small for the task distribution skew
  - High variance in results: May indicate insufficient count accuracy when using private estimates

- First 3 experiments:
  1. Compare uniform weights vs adaptive weights on synthetic data with known task sizes
  2. Test weight clipping behavior under different privacy budget constraints
  3. Evaluate utility degradation when using private vs exact count estimates

## Limitations
- Privacy accounting gaps exist in the RDP composition analysis for adaptive weights, particularly when weights are clipped
- Count estimation quality impacts tail task performance when task counts must be privately estimated
- Cross-algorithm generality claims need verification as SSP and DPSGD have substantially different implementation details and privacy accounting

## Confidence

- **High Confidence**: The core mathematical derivation of optimal weights ω_i ∝ n_i^(-(1+γ)/4) under the stated assumptions, the experimental methodology using standard benchmarks, and the general improvement in tail task utility compared to uniform allocation baselines.

- **Medium Confidence**: The practical effectiveness of the clipping mechanism for ensuring privacy guarantees under all scenarios, the real-world applicability when task counts must be privately estimated, and the robustness of results across different privacy budgets.

- **Low Confidence**: The exact privacy accounting when combining adaptive weights with noisy gradient descent in practice, the impact of hyperparameter tuning on different datasets, and the method's behavior under extreme skew distributions not represented in the experimental datasets.
