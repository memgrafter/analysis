# AdaPlanner: Adaptive Planning from Feedback with Language Models

## Quick Facts
- **arXiv ID**: 2305.16653
- **Source URL**: https://arxiv.org/abs/2305.16653
- **Reference count**: 40
- **Primary result**: Outperforms SoTA by 3.73% and 4.11% on ALFWorld and MiniWoB++ while using 2x and 600x fewer samples

## Executive Summary
AdaPlanner introduces an adaptive closed-loop planning approach for LLM agents to solve sequential decision-making tasks. It combines in-plan refinement (extracting key information from observations) with out-of-plan refinement (revising entire plans upon unexpected feedback) to adapt to environmental changes. The method uses code-style prompts to reduce hallucination and a skill discovery mechanism to improve sample efficiency. Experiments on ALFWorld and MiniWoB++ show AdaPlanner outperforms state-of-the-art baselines while using significantly fewer samples.

## Method Summary
AdaPlanner implements a closed-loop planning framework that processes environmental feedback to iteratively refine plans. The system distinguishes between in-plan feedback (aligned with predictions) and out-of-plan feedback (deviating from predictions). In-plan refinement extracts key information via ask_LLM() action, while out-of-plan refinement triggers complete plan revision through a refine-then-resume mechanism. Code-style prompts provide formal structure to constrain LLM generation space and reduce hallucination. Successful trajectories are archived in skill memory, serving as few-shot exemplars for future planning when similar tasks are encountered.

## Key Results
- Achieves 3.73% improvement over SoTA on ALFWorld benchmark
- Achieves 4.11% improvement over SoTA on MiniWoB++ benchmark
- Uses 2x fewer samples on ALFWorld and 600x fewer samples on MiniWoB++ compared to training-based methods

## Architecture Onboarding

- Component map:
  Planner -> Refiner -> Skill Memory -> Code Interface -> Environment Interface

- Critical path:
  1. Initial planning using code-style prompts
  2. Environment interaction and observation collection
  3. Feedback categorization (in-plan vs out-of-plan)
  4. Appropriate refinement execution
  5. Skill discovery and storage when successful

- Design tradeoffs:
  - Code vs natural language prompts: Precision vs flexibility
  - In-plan vs out-of-plan refinement: Efficiency vs thoroughness
  - Skill storage criteria: Storage cost vs future utility
  - Refinement frequency: Responsiveness vs computational cost

- Failure signatures:
  - Stuck in infinite refinement loops
  - Failure to extract useful information from feedback
  - Skill memory not providing useful exemplars
  - Hallucination in code generation despite code prompts

- First 3 experiments:
  1. Test AdaPlanner on a simple task with known feedback patterns to verify basic functionality
  2. Compare performance with and without code-style prompts on the same task
  3. Test skill discovery by solving a task, storing the plan, then attempting a similar task with the stored exemplar

## Limitations

- Evaluation claims are based on specific benchmark suites (ALFWorld and MiniWoB++) that may not generalize to broader task domains
- Reported sample efficiency gains lack detailed ablation studies showing whether improvements stem from skill discovery specifically versus the closed-loop architecture itself
- Reliance on code-style prompts as hallucination reduction technique needs empirical validation beyond stated claims

## Confidence

**High Confidence**: The closed-loop planning architecture with in-plan and out-of-plan refinement is technically sound and well-defined. The skill discovery mechanism for storing successful plans as few-shot exemplars is a straightforward and implementable concept.

**Medium Confidence**: The code-style prompt effectiveness for hallucination reduction and the specific performance improvements on ALFWorld and MiniWoB++ are reasonable given the approach, but lack comprehensive ablation studies and generalizability evidence.

**Low Confidence**: Claims about sample efficiency gains being primarily driven by skill discovery versus other architectural components are not well-supported with direct evidence. The categorization of environmental feedback into "in-plan" versus "out-of-plan" types may be oversimplified for complex real-world scenarios.

## Next Checks

1. **Ablation Study on Skill Discovery**: Run AdaPlanner with and without the skill discovery component on a diverse set of tasks to isolate its specific contribution to sample efficiency improvements. Measure whether the 600x sample reduction claim holds when skill memory is disabled.

2. **Cross-Domain Generalization Test**: Evaluate AdaPlanner on a third, previously unseen benchmark environment outside of ALFWorld and MiniWoB++ to assess whether the reported performance improvements generalize beyond the original evaluation domains.

3. **Hallucination Analysis with Code Prompts**: Conduct controlled experiments comparing AdaPlanner's hallucination rates with natural language prompts versus code-style prompts on identical tasks, measuring both hallucination frequency and any reduction in solution diversity or creativity.
