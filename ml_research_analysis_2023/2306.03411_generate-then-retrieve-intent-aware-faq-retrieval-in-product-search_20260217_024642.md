# Generate-then-Retrieve: Intent-Aware FAQ Retrieval in Product Search

## Quick Facts
- arXiv ID: 2306.03411
- Source URL: https://arxiv.org/abs/2306.03411
- Reference count: 23
- Primary result: 13% Hit@1 improvement and 95% latency reduction in FAQ retrieval

## Executive Summary
This paper presents a novel approach to integrating FAQ retrieval into product search systems, addressing the challenge of query ambiguity and the need for efficient, user-friendly retrieval. The proposed system first classifies queries into question and non-question intents, then reformulates question-intent queries into natural language questions for retrieval. This generate-then-retrieve approach achieves significant improvements in retrieval accuracy while dramatically reducing latency, making it suitable for large-scale e-commerce applications.

## Method Summary
The authors propose an intent-aware FAQ retrieval system that employs a two-stage process: intent classification and query reformulation. The system first determines whether a user query is question-intent or non-question-intent using a classification model. For question-intent queries, the system reformulates the query into a natural language question before retrieval. This approach allows the system to leverage specialized FAQ retrieval models while maintaining the efficiency of the existing product search infrastructure. The reformed queries are then used to retrieve relevant FAQs, which are displayed alongside product search results without disrupting the user experience.

## Key Results
- 13% improvement in Hit@1 metric compared to using original queries
- 95% reduction in latency for FAQ retrieval
- 71% of displayed FAQs received positive user feedback in real-world deployment

## Why This Works (Mechanism)
The system works by recognizing that user queries in e-commerce often contain implicit questions that are not in standard question format. By classifying queries and reformulating question-intent queries into natural language questions, the system can better match user intent with relevant FAQ content. This approach leverages the strengths of both traditional search (for non-question intents) and specialized FAQ retrieval (for question intents), creating a hybrid system that maximizes both relevance and efficiency.

## Architecture Onboarding

Component map: User Query -> Intent Classifier -> (Question Intent: Query Reformulator -> FAQ Retriever) OR (Non-Question Intent: Product Search)

Critical path: Intent classification is the first decision point, followed by either query reformulation and FAQ retrieval or direct product search.

Design tradeoffs: The system trades off some latency in query reformulation against improved retrieval accuracy, justified by the 95% overall latency reduction achieved through optimized FAQ retrieval.

Failure signatures: Ambiguous queries may be misclassified, leading to inappropriate retrieval strategies. Poor reformulation can result in irrelevant FAQ retrieval.

## Limitations
- Evaluation conducted on proprietary data from a single e-commerce platform, limiting generalizability
- Lack of detailed information on training data and methodology for intent classification and reformulation models
- Evaluation methodology for user satisfaction metrics not explicitly described
- No discussion of handling ambiguous queries or multilingual support in international marketplaces
