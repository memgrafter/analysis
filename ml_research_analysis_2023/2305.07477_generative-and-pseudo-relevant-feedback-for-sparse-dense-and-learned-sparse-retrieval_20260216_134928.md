# Generative and Pseudo-Relevant Feedback for Sparse, Dense and Learned Sparse Retrieval

## Quick Facts
- arXiv ID: 2305.07477
- Source URL: https://arxiv.org/abs/2305.07477
- Reference count: 40
- Key outcome: GRF improves over PRF by ~10% on precision and recall measures, with combined GRF+PRF significantly increasing recall on 95% of experiments

## Executive Summary
This work extends generative relevance feedback (GRF) to dense and learned sparse retrieval paradigms, using Large Language Models to generate text that contextualizes queries beyond first-pass retrieval results. The approach generates diverse content (chain-of-thought reasoning, facts, news articles) that is encoded into vectors and combined with original query representations. GRF provides external context not present in the corpus, while PRF grounds queries to corpus-specific information. The paper demonstrates that combining these complementary approaches through weighted reciprocal rank fusion significantly improves recall across multiple datasets and search paradigms.

## Method Summary
The method generates LLM content for each query using diverse prompts, then encodes this generated text into dense (TCT-ColBERT-v2-HNP) or learned sparse (SPLADE) vectors. These vectors are combined with original query representations for retrieval. The approach is tested across BM25, dense (TCT), and learned sparse (SPLADE) retrieval paradigms on six document ranking benchmarks. A weighted reciprocal rank fusion method combines GRF and PRF ranking signals, with the fusion weight λ tuned per dataset and search paradigm.

## Key Results
- GRF improves over PRF by approximately 10% on both precision and recall-oriented measures
- Combining GRF and PRF through weighted reciprocal rank fusion significantly increases recall on 95% of experiments
- GRF provides external context not present in first-pass retrieval, while PRF grounds queries to corpus information
- GRF is more effective than PRF on the hardest 75% of first-pass queries

## Why This Works (Mechanism)

### Mechanism 1
- Claim: GRF improves retrieval by providing external context not present in the corpus
- Mechanism: Large Language Models generate diverse text content that is encoded into vectors, contextualizing queries beyond what first-pass retrieval can provide
- Core assumption: LLM-generated text contains relevant information not captured in the corpus that can improve query representation
- Evidence anchors: [abstract] "GRF provides external context not present in first-pass retrieval", [section 5.3] "GRF expansion uses generated content that directly addresses the questions"

### Mechanism 2
- Claim: PRF grounds queries to corpus-specific information while GRF provides general context
- Mechanism: PRF extracts terms from retrieved documents in the corpus, anchoring expansion to corpus content. GRF uses LLM-generated text that may reference information outside the corpus but still relevant to the query
- Core assumption: There is value in both corpus-grounded information (PRF) and external contextual information (GRF)
- Evidence anchors: [abstract] "PRF grounds the query to the information contained within the target corpus", [section 5.3] Analysis of topic 626 shows PRF captures corpus-specific events while GRF expands with general terms

### Mechanism 3
- Claim: GRF and PRF have complementary ranking signals that can be combined for improved recall
- Mechanism: Weighted reciprocal rank fusion combines GRF and PRF document scores, allowing each to contribute where it's strongest
- Core assumption: GRF and PRF help different queries and can be effectively combined
- Evidence anchors: [abstract] "We propose combining generative and pseudo-relevance feedback ranking signals, which significantly increases recall over PRF methods on 95% of experiments"

## Architecture Onboarding

- Component map: LLM generation -> Text encoding (dense/learned sparse) -> Query representation update -> Document retrieval -> Optional: WRRF fusion with PRF
- Critical path: 1) Receive query, 2) Generate LLM content for GRF, 3) Encode generated content, 4) Combine encoded vectors with original query, 5) Retrieve documents, 6) Optionally fuse with PRF results using WRRF
- Design tradeoffs: LLM generation cost vs. retrieval improvement, maximum token limits affecting generated content usage, balancing GRF vs PRF contributions in fusion, choice between zero-shot vs. few-shot LLM prompting
- Failure signatures: LLM generates irrelevant content, generated content exceeds token limits, fusion weighting produces worse results, significant degradation on queries where PRF traditionally performs well
- First 3 experiments: 1) Implement BM25+GRF and compare against BM25+RM3 on Robust04 titles, 2) Implement TCT+GRF and compare against TCT+PRF on DL-19, 3) Implement SPLADE+GRF and compare against SPLADE+RM3 on CODEC

## Limitations
- The approach requires significant computational overhead from LLM generation for each query
- Performance gains may not generalize to highly technical or domain-specific queries requiring specialized terminology
- The method relies on a single LLM (GPT-3) without ablation studies on different models or prompting strategies

## Confidence

**High Confidence**: The core finding that GRF improves recall over PRF methods on 95% of experiments, as this is directly supported by quantitative results across multiple datasets and retrieval paradigms.

**Medium Confidence**: The claim that GRF provides external context not present in the corpus, as this mechanism is primarily supported by qualitative query analysis rather than systematic measurement of information novelty or corpus coverage.

**Low Confidence**: The assertion that GRF is universally beneficial across all query types, as the analysis shows GRF hurts performance on some queries while helping others.

## Next Checks

1. Conduct ablation studies testing GRF with different LLM models and prompting strategies to assess the sensitivity of improvements to generation quality and diversity.

2. Implement a selective GRF mechanism that determines when to apply GRF versus PRF based on first-pass retrieval precision, testing whether this can achieve the benefits of both approaches while avoiding their weaknesses.

3. Measure the computational overhead of GRF relative to PRF across different query loads and test whether the retrieval improvements justify the additional latency in practical deployment scenarios.
