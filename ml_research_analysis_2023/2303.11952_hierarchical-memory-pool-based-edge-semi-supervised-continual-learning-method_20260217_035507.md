# Hierarchical Memory Pool Based Edge Semi-Supervised Continual Learning Method

## Quick Facts
- arXiv ID: 2303.11952
- Source URL: https://arxiv.org/abs/2303.11952
- Authors: 
- Reference count: 0
- Primary result: Achieves up to 16.35% higher accuracy than classic CL methods while reducing training iterations by over 50% on edge devices

## Executive Summary
EdgeHML addresses catastrophic forgetting in edge continual learning under severe resource constraints by using a hierarchical memory pool and progressive learning. The method combines fast-access memory for labeled data and high-confidence pseudo-labeled samples with disk storage for remaining pseudo-labeled samples. By delaying unlabeled data training through progressive learning, EdgeHML reduces unlabeled sample iterations by up to 60% while maintaining competitive accuracy on standard benchmarks.

## Method Summary
EdgeHML operates in edge environments with limited labeled data and compute/memory resources. It implements a hierarchical memory pool with two tiers: fast-access memory storing labeled samples and high-confidence pseudo-labeled samples, and disk storage holding remaining pseudo-labeled samples. The method uses online confidence-based pseudo-label filtering with threshold τ=0.95 and introduces progressive learning that delays unlabeled data training, applying cosine weight scheduling to gradually increase the importance of unsupervised loss from 20% to 30% of total iterations. This architecture enables effective replay-based continual learning while minimizing computational overhead on resource-constrained devices.

## Key Results
- Outperforms classic CL methods by up to 16.35% in accuracy on CIFAR-10, CIFAR-100, and TinyImageNet
- Reduces training iterations by over 50% compared to semi-supervised approaches
- Achieves 90.08% accuracy on Split Semi CIFAR-10-5 with 2000 fast-access pool samples
- Maintains edge device resource limits while delivering strong continual learning performance

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Hierarchical memory pool separates storage tiers to balance access speed and capacity for edge CL
- Mechanism: Fast-access memory pool holds labeled samples and high-confidence pseudo-labeled samples; disk pool stores remaining pseudo-labeled samples and serves as overflow reservoir
- Core assumption: Labeled data scarcity makes high-confidence pseudo-labels valuable enough to replay
- Evidence anchors:
  - [abstract] "hierarchical memory pool combining fast-access memory for labeled data and disk storage for unlabeled samples"
  - [section] "EdgeHML constructs a hierarchical data memory pool... fast-access memory layer... disk layer data memory pool (i.e., disk pool)"
- Break condition: If confidence threshold selection is too low, disk pool becomes dominated by noisy pseudo-labels, hurting performance

### Mechanism 2
- Claim: Progressive learning reduces unlabeled sample iteration cycles by delaying their training
- Mechanism: For each new task, only supervised loss is computed for the first 20% of iterations; cosine-annealed weight ramps up to full unsupervised loss by 21-30% of iterations
- Core assumption: Early task adaptation benefits more from supervised signals; unlabeled samples add noise if introduced too early
- Evidence anchors:
  - [abstract] "delaying unlabeled data training until later iterations, thereby cutting unlabeled sample iterations by up to 60%"
  - [section] "EdgeHML attempts to use multiple function curves to control the weight of unlabeled sample learning objectives...Cosine function"
- Break condition: If task difficulty is low or labeled samples are plentiful, delaying unlabeled learning may underutilize available data

### Mechanism 3
- Claim: Online confidence-based pseudo-label filtering ensures high-quality disk pool samples
- Mechanism: Inference on unlabeled samples; only those with max-class probability > τ (typically 0.95) and correct current-task class are stored as pseudo-labeled candidates, then sampled into disk pool
- Core assumption: Confidence threshold τ can effectively filter out mislabeled pseudo-samples
- Evidence anchors:
  - [section] "EdgeHML first uses the DNN model to perform inference calculations on the received unlabeled samples... When the result's highest probability value is higher than the confidence threshold τ... the model is used as the pseudo-label of the sample"
  - [section] Equation 5 shows ℒ୳ uses indicator 𝟙(max(𝑝𝑖𝑐)≥τ) to gate unsupervised loss
- Break condition: If model confidence is poorly calibrated, high τ will discard useful samples and low τ will flood disk pool with noise

## Architecture Onboarding

- Component map: DNN model (ResNet-18) -> Fast-access memory pool (labeled + high-confidence pseudo-labeled) -> Disk pool (remaining pseudo-labeled) -> Confidence threshold τ -> Cosine weight scheduler for progressive learning
- Critical path:
  1. Receive unlabeled batch → inference → filter by τ → append to disk pool
  2. At task boundary → offline sampling from disk pool → fast-access pool
  3. During training → supervised loss + replayed samples + (after 20%) unsupervised loss
- Design tradeoffs:
  - Larger τ → cleaner disk pool but fewer samples; smaller τ → more samples but noisier
  - Longer delay before unsupervised loss → less compute but slower adaptation
  - Bigger fast-access pool → better replay but higher memory cost on edge device
- Failure signatures:
  - Accuracy plateaus early → likely unsupervised weight never rises high enough
  - Accuracy drops sharply on later tasks → disk pool sampling failing to supply relevant samples
  - High variance in accuracy → confidence threshold too low, introducing noisy pseudo-labels
- First 3 experiments:
  1. Run with τ=0.95 vs τ=0.80 on Split Semi CIFAR-10-5 and compare disk pool size vs accuracy
  2. Vary progressive learning delay (20% vs 60% of iterations) and measure accuracy + iteration time
  3. Test different fast-access pool sizes (200, 500, 2000) on Split Semi CIFAR-100-5 and observe accuracy scaling
