# Global Layers: Non-IID Tabular Federated Learning

## Quick Facts
- arXiv ID: 2305.19290
- Source URL: https://arxiv.org/abs/2305.19290
- Reference count: 40
- Primary result: GL outperforms FedAvg and local training on heterogeneous tabular FL benchmarks

## Executive Summary
Global Layers (GL) introduces a novel partial model personalization approach for federated learning that addresses the challenge of data heterogeneity in tabular datasets. The method federates only global inner layers while maintaining private input and output layers for each client, enabling support for both client-exclusive features and classes without requiring feature/label overlap. GL achieves this by learning invariant transformations within latent-space inner layers across clients with disjoint feature and label spaces, allowing for personalized compositions of these transformations.

## Method Summary
GL implements partial model personalization by federating only global inner layers (ω) while keeping private input (uk) and output (vk) layers local to each client. This architecture enables clients with heterogeneous feature and label spaces to learn shared invariant transformations in the latent space while preserving client-specific dynamics. The method uses BatchAlignedFedAvg for gradient aggregation, specifying a total number of batches per epoch rather than batch size to ensure consistent gradient updates across clients with varying sample sizes.

## Key Results
- GL outperforms FedAvg and local-only training on two new tabular FL benchmarks
- Some clients achieve better performance than their centralized baseline using GL
- Significant improvements in AUROC, accuracy, and AUPRC metrics
- UCI Covertype split by wilderness area and three heart disease datasets demonstrate GL's effectiveness

## Why This Works (Mechanism)

### Mechanism 1
GL learns invariant transformations within inner layer latent spaces across clients with disjoint feature and label spaces. By federating only global inner layers while keeping input/output layers private, GL allows clients to personalize the composition of global invariant transformations. Core assumption: latent-space transformations are shared across clients despite heterogeneity. Break condition: if transformations aren't invariant, performance degrades to FedAvg levels.

### Mechanism 2
GL supports disjoint feature/label spaces by using private input/output layers to transform local client-specific spaces to a consistent global latent space dimension. This enables aggregation despite complete feature/label space differences. Core assumption: private layers can bridge semantic gaps between heterogeneous client spaces. Break condition: if private layers can't adequately transform spaces, performance collapses.

### Mechanism 3
BatchAlignedFedAvg ensures consistent gradient updates across clients by specifying total batches per epoch rather than batch size. This makes ak = 1 and ensures proportional gradient contributions based on empirical loss only. Core assumption: consistent batch count is more important than consistent batch size for FL convergence. Break condition: if batch alignment fails, gradient updates become skewed by sample size differences.

## Architecture Onboarding

- Component map: Private input layers (uk) → Global layers (ω) → Private output layers (vk), with BatchNormalization, Entity Embeddings, Transformers, and MLPs
- Critical path: Data → Entity Embedding → Transformer → MLP (private layers) → Global Layers aggregation → Client-specific output
- Design tradeoffs: More global layers = better transfer learning but less client-specific adaptation; more private layers = better client adaptation but less knowledge sharing
- Failure signatures: Performance drops to FedAvg levels when global layers don't capture invariant relationships; client-specific layers fail when they can't bridge semantic gaps
- First 3 experiments: 1) Single-client GL training to verify model works before federation, 2) Two-client GL with minimal heterogeneity to validate basic mechanism, 3) GL vs FedAvg on UCI Covertype split to validate against baseline

## Open Questions the Paper Calls Out

### Open Question 1
Question: What is the optimal architecture and selection strategy for federated layers in Global Layers to maximize performance across diverse non-IID tabular FL settings?
Basis in paper: The paper states that federated layer choice should be treated as a hyperparameter selected with cross-validation, but leaves this as an open research question.
Why unresolved: The paper only explores one model architecture without comparing different federated layer selection strategies.
What evidence would resolve it: Empirical studies comparing different architectures and federated layer selection strategies across various non-IID tabular FL datasets.

### Open Question 2
Question: How does the performance of Global Layers compare to other model personalization methods in non-IID tabular FL settings?
Basis in paper: The paper explicitly states it does not compare against other model personalization methods.
Why unresolved: Only FedAvg and local-only training are compared, without considering other personalization techniques.
What evidence would resolve it: Experimental comparisons of GL with other personalization methods like meta-learning, proximal methods, and interpolation techniques on the same datasets.

### Open Question 3
Question: What are the theoretical convergence guarantees for Global Layers in the presence of joint distribution shift and mixed input/output spaces?
Basis in paper: The paper mentions it does not provide in-depth theoretical analysis of the proposed method.
Why unresolved: The paper focuses on empirical results without theoretical convergence analysis.
What evidence would resolve it: Mathematical proofs or convergence analysis showing GL behavior under different distribution shifts and heterogeneous settings.

### Open Question 4
Question: How does Global Layers perform in settings with partial overlap in features, labels, or samples across clients compared to cases with complete disjointness?
Basis in paper: The paper mentions that any existing overlap would improve learning outcomes, suggesting this as an area for future exploration.
Why unresolved: Experiments focus on disjoint feature spaces without exploring scenarios with partial overlap.
What evidence would resolve it: Experiments comparing GL's performance on datasets with varying degrees of overlap in features, labels, and samples across clients.

## Limitations
- Limited empirical evidence on how well private input/output layers bridge truly disjoint feature sets
- Computational overhead of maintaining separate private layers per client while aggregating global layers is not thoroughly analyzed
- Statistical validation of outperforming centralized baselines across multiple runs needs strengthening

## Confidence
- **High confidence**: The core mechanism of partial model personalization through global inner layers is well-supported by architecture and experimental design
- **Medium confidence**: Claims about outperforming centralized baselines for some clients need more rigorous statistical validation
- **Low confidence**: The assertion that GL is the first method supporting both client-exclusive features and classes requires verification against broader FL literature

## Next Checks
1. **Sensitivity analysis**: Evaluate GL performance across varying degrees of feature/label overlap between clients to identify minimum shared information required for effective learning
2. **Ablation study**: Compare GL against variants where different combinations of layers are federated (e.g., only input layers, only output layers, different numbers of global inner layers)
3. **Generalization test**: Apply GL to non-tabular domains (e.g., federated learning with vision or text data) to assess broader applicability of invariant transformation learning approach
