# FastFill: Efficient Compatible Model Update

## Quick Facts
- arXiv ID: 2303.04766
- Source URL: https://arxiv.org/abs/2303.04766
- Reference count: 30
- Primary result: FastFill achieves mAP improvements of +4.4% on ImageNet, +2.7% on Places-365, and +1.3% on VGG-Face2 with efficient compatible model updates

## Executive Summary
FastFill introduces an efficient method for updating embedding models in retrieval systems without incurring the high computational costs of full backfilling. The approach combines feature alignment using uncertainty estimation with a policy-based partial backfilling strategy to improve retrieval performance while minimizing resource usage. The method trains a transformation model to align old and new feature spaces, then uses predicted uncertainties to prioritize backfilling of the most incompatible features. FastFill demonstrates significant performance improvements over existing approaches and effectively reduces bias between subgroups with minimal backfilling.

## Method Summary
FastFill addresses the challenge of model updates in retrieval systems by introducing a two-phase approach: feature alignment and partial backfilling. The method first trains a transformation model to align features between old and new model versions using uncertainty estimation. This alignment model learns to map old features to the new feature space, reducing compatibility gaps. The second phase employs a policy-based approach to selectively backfill only the most uncertain or incompatible features, determined by the uncertainty estimates from the alignment model. This partial backfilling strategy significantly reduces computational overhead while maintaining or improving retrieval performance compared to full backfilling approaches.

## Key Results
- Achieves mAP improvements of +4.4% on ImageNet, +2.7% on Places-365, and +1.3% on VGG-Face2
- Effectively reduces bias between subgroups with minimal backfilling
- Outperforms existing approaches while significantly reducing computational costs of model updates

## Why This Works (Mechanism)
FastFill works by addressing the core challenge of feature space incompatibility when updating retrieval models. The transformation model learns to map features from the old model space to the new one, reducing the gap between incompatible feature representations. Uncertainty estimation identifies which features are most affected by the model update, allowing the policy-based backfilling to focus resources on the most critical items. This selective approach ensures that the most valuable updates are prioritized, maximizing performance gains while minimizing computational overhead. The method effectively balances the trade-off between update quality and resource efficiency by focusing on features where the model change has the greatest impact.

## Architecture Onboarding

Component Map:
Transformation Model -> Uncertainty Estimation -> Partial Backfilling Policy -> Retrieval Performance

Critical Path:
The critical path involves training the transformation model to align feature spaces, using uncertainty estimation to identify incompatible features, and applying the partial backfilling policy to update the most critical items. This sequence ensures that computational resources are focused where they will have the greatest impact on retrieval performance.

Design Tradeoffs:
FastFill trades computational efficiency for selective update quality, prioritizing the most uncertain features rather than updating all items. This approach assumes that the most uncertain features are also the most valuable to update, which may not always hold true in cases of complex feature interactions or non-linear dependencies.

Failure Signatures:
- Poor uncertainty estimation leading to incorrect prioritization of backfilling
- Transformation model failing to adequately align feature spaces
- Policy backfilling the wrong features due to misestimated uncertainties
- Insufficient training data for the transformation model, resulting in poor alignment

First Experiments:
1. Evaluate feature alignment accuracy on a validation set with known ground truth
2. Test uncertainty estimation performance by comparing predicted uncertainties with actual retrieval performance degradation
3. Conduct ablation study to measure the contribution of each component (transformation, uncertainty, policy) to overall performance

## Limitations
- Scalability concerns for very large-scale retrieval systems with millions of features
- Potential brittleness of uncertainty estimation in domain-shifted production environments
- Assumption that most uncertain features are most valuable may not hold in all cases
- Computational overhead of transformation model training not fully characterized across hardware setups
