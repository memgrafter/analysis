# QUERT: Continual Pre-training of Language Model for Query Understanding in Travel Domain Search

## Quick Facts
- arXiv ID: 2306.06707
- Source URL: https://arxiv.org/abs/2306.06707
- Reference count: 38
- Key outcome: QUERT achieves SOTA performance on 5 travel domain search tasks with 2.02% average improvement in supervised and 30.93% in unsupervised settings.

## Executive Summary
This paper introduces QUERT, a continual pre-trained language model designed to enhance query understanding in travel domain search. The model addresses the unique challenges of travel queries, which often contain geographical information and exhibit user click behavior patterns. QUERT is jointly trained on four tailored pre-training tasks that capture geography information, model real geographic locations, learn user click behavior, and improve robustness to phrase and token order. The model is evaluated on five downstream tasks and demonstrates significant improvements over baseline models, with successful deployment on the Fliggy APP showing increased click-through rates.

## Method Summary
QUERT is continually pre-trained on 5 million query-clicked item pairs from Fliggy APP, using four specialized tasks: Geography-aware Mask Prediction (prioritizing geographical phrases), Geohash Code Prediction (encoding physical locations), User Click Behavior Learning (contrastive learning on similar queries), and Phrase and Token Order Prediction (robustness to permutations). The model uses BERT or ERNIE as backbone, trains for 386,460 steps with AdamW optimizer, and fine-tunes on five downstream tasks. High-confidence data pairs are selected using weighted scores based on user click and payment hits.

## Key Results
- Achieves 2.02% average improvement over baselines in supervised settings
- Shows 30.93% average improvement in unsupervised settings
- Online deployment increases Unique Click-Through Rate by 0.89% and Page Click-Through Rate by 1.03%

## Why This Works (Mechanism)

### Mechanism 1
- Claim: QUERT's Geography-aware Mask Prediction (Geo-MP) task enables the model to prioritize and better represent geographical information in travel domain queries.
- Mechanism: By assigning a higher mask probability to geographical phrases that appear in both query and item (50%) and moderate probability to those appearing in only one (30%), the model is forced to learn to infer masked geographical tokens using context from the other text, enhancing its ability to recognize and understand geography-related tokens.
- Core assumption: The geographical phrases are critical for understanding travel domain queries and that masking them with different probabilities based on their co-occurrence in query and item will improve the model's geography awareness.
- Evidence anchors:
  - [abstract] The model is jointly trained on four tailored pre-training tasks to the characteristics of query in travel domain search: Geography-aware Mask Prediction, Geohash Code Prediction, User Click Behavior Learning, and Phrase and Token Order Prediction.
  - [section 3.1] We use the NER tool as a detector to identify geography phrases that appear in q and c. We design three mask strategies. First, for geography phrases in both q and c, we set a mask probability of 50% for them.
  - [corpus] Corpus neighbors show related work on continual pre-training for domain-specific models, but none specifically address geography awareness in travel domain search queries.
- Break condition: If the NER tool fails to accurately identify geographical phrases, or if the mask probabilities are set incorrectly, the model may not effectively learn to prioritize geographical information.

### Mechanism 2
- Claim: QUERT's Geohash Code Prediction (Geo-CP) task allows the model to capture real physical geographic information and model the hierarchy and distance relationships between geographical locations.
- Mechanism: By encoding the geographical entities in the click item into geohash codes and training the model to predict these codes, QUERT learns to represent the physical location and hierarchical structure of geographical locations, enabling it to understand the spatial relationships between different places.
- Core assumption: Geohash codes effectively represent real physical geographic information, and the model can learn to map geographical entities to their corresponding geohash codes, thereby gaining an understanding of the spatial relationships between locations.
- Evidence anchors:
  - [abstract] We introduce geohash in Geohash Code Prediction (Geo-CP) task to model real physical geographic information for the language model.
  - [section 3.2] The geohash algorithm divides geographic blocks into several grids and encodes them according to latitude and longitude. The code is represented as a string, with precision controlled by the number of bits in the string.
  - [corpus] Corpus neighbors do not mention geohash code prediction or similar methods for capturing physical geographic information in language models.
- Break condition: If the geohash encoding does not accurately represent the geographical entities, or if the model fails to learn the mapping between entities and geohash codes, the task will not effectively improve the model's understanding of physical geography.

### Mechanism 3
- Claim: QUERT's User Click Behavior Learning (UCBL) task enables the model to learn the implicit similarity between different queries that lead to the same click item, driven by user click behavior.
- Mechanism: By grouping queries that lead to the same click item and using contrastive learning to maximize the similarity between positive pairs (query and a related query from the same group) and minimize similarity between negative pairs (query and a query from a different group), the model learns to understand the underlying user intent that drives click behavior.
- Core assumption: Queries that lead to the same click item share an implicit similarity driven by user click behavior, and this similarity can be captured by contrastive learning using the click item as a pivot.
- Evidence anchors:
  - [abstract] In order to build a connection between the different queries linking to the same click item, we propose User Click Behavior Learning (UCBL) to learn the potential similarity.
  - [section 3.3] We select the top K from the queries linking to c_i and combine them into a group G = {q_i1, q_i2, ..., q_iK}. Then, in order to guarantee the diversity, we randomly choose one from G as the positive example q_pos_i of q_i.
  - [corpus] Corpus neighbors show related work on contrastive learning for query-document matching, but none specifically address learning query similarity driven by user click behavior in travel domain search.
- Break condition: If the grouping of queries based on click items does not accurately reflect the underlying user intent, or if the contrastive learning setup is not effective in capturing the similarity, the model may not effectively learn the click behavior driven similarity.

## Foundational Learning

- Concept: Continual Pre-training
  - Why needed here: Travel domain search queries have specific characteristics (geography awareness, user click behavior, robustness to phrase and token order) that are not captured by general pre-trained language models. Continual pre-training allows the model to adapt to these domain-specific characteristics.
  - Quick check question: What is the main difference between continual pre-training and fine-tuning in the context of adapting a language model to a specific domain?

- Concept: Contrastive Learning
  - Why needed here: User Click Behavior Learning (UCBL) task requires the model to learn the similarity between queries that lead to the same click item. Contrastive learning is a suitable approach for this, as it can learn to maximize the similarity between positive pairs and minimize similarity between negative pairs.
  - Quick check question: How does contrastive learning differ from traditional supervised learning in terms of the training objective and the type of labels used?

- Concept: Geohash Encoding
  - Why needed here: Geohash Code Prediction (Geo-CP) task requires a way to represent real physical geographic information. Geohash encoding provides a way to encode latitude and longitude into a string that captures the hierarchical structure and distance relationships between geographical locations.
  - Quick check question: What are the advantages of using geohash encoding over other methods (e.g., one-hot encoding) for representing geographical locations in a language model?

## Architecture Onboarding

- Component map: Query Encoder -> Geography-aware Mask Prediction -> Geohash Code Prediction -> User Click Behavior Learning -> Phrase and Token Order Prediction -> Loss Function
- Critical path: Input: Query and click item -> Geography-aware Mask Prediction: Apply masking strategy -> Geohash Code Prediction: Predict geohash codes -> User Click Behavior Learning: Apply contrastive learning -> Phrase and Token Order Prediction: Predict original order -> Output: Embeddings that capture geography awareness, user click behavior, and robustness to phrase and token order
- Design tradeoffs:
  - Mask probabilities in Geo-MP: Higher probabilities for geographical phrases may improve geography awareness but could also make the task too difficult.
  - Number of bits in geohash codes: More bits provide finer granularity but increase the complexity of the prediction task.
  - Size of query groups in UCBL: Larger groups provide more diverse positive examples but may also introduce more noise.
- Failure signatures:
  - Poor performance on geography-related downstream tasks: Indicates issues with Geo-MP or Geo-CP.
  - Lack of improvement on query similarity tasks: Suggests problems with UCBL.
  - Sensitivity to phrase and token order in downstream tasks: Points to issues with PTOP.
- First 3 experiments:
  1. Ablation study: Remove each pre-training task individually and evaluate the impact on downstream task performance.
  2. Hyperparameter tuning: Experiment with different mask probabilities in Geo-MP and different numbers of bits in geohash codes to find the optimal settings.
  3. Contrastive learning setup: Try different strategies for selecting positive and negative pairs in UCBL to improve the learning of query similarity.

## Limitations
- Generalizability beyond travel domain is unclear
- Effectiveness depends on quality of NER tool for geography phrase identification
- Assumes queries leading to same click item share meaningful semantic similarity

## Confidence
- High: The core claim that QUERT outperforms baseline models on travel domain search tasks is well-supported by extensive experimental results across five downstream tasks with multiple metrics.
- Medium: The effectiveness of individual pre-training tasks (Geo-MP, Geo-CP, UCBL, PTOP) is demonstrated through ablation studies, but the exact contribution of each task to overall performance could vary with different data distributions or evaluation settings.
- Low: The online deployment results showing improvements in Unique Click-Through Rate and Page Click-Through Rate are promising but lack statistical significance testing and detailed analysis of real-world impact.

## Next Checks
1. Cross-domain validation: Test QUERT's pre-training approach on a different domain (e.g., e-commerce or healthcare) to assess whether the same strategy generalizes or requires domain-specific modifications.
2. NER tool evaluation: Conduct an ablation study where the geography phrase identification is done with different NER tools or with varying levels of accuracy to quantify the impact of NER quality on geography awareness learning.
3. Click behavior analysis: Analyze the distribution of query groups in the UCBL task to understand what percentage of groups contain truly semantically similar queries versus coincidental click patterns, and assess the impact of this distribution on model performance.
