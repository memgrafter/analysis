# Life of PII -- A PII Obfuscation Transformer

## Quick Facts
- arXiv ID: 2305.09550
- Source URL: https://arxiv.org/abs/2305.09550
- Reference count: 2
- Primary result: UPT achieves lowest IL at 6.99%, while combinations provide greater obfuscation

## Executive Summary
The paper addresses the challenge of protecting Personally Identifiable Information (PII) when using Large Language Models (LLMs) like ChatGPT, particularly in sensitive sectors like finance. The proposed "Life of PII" framework transforms PII into faux-PII tokens using User Provided Tokens (UPT), Named Entity Recognition (NER), and Part of Speech (PoS) replacement techniques. A transformer-based model learns mappings between original and obfuscated PII while preserving context and intent. Experiments show UPT achieves the lowest Information Loss (IL) at 6.99%, while combinations like UPT+NER+PoS provide greater obfuscation at the cost of higher IL (~38.44%).

## Method Summary
The approach uses a transformer-based model to learn mappings between original and obfuscated PII tokens through three techniques: User Provided Tokens (UPT) where users supply replacement tokens, Named Entity Recognition (NER) for entity-based replacement, and Part of Speech (PoS) replacement for syntactic transformation. The framework provides an API interface with configuration-based obfuscator that can be applied to text documents. The transformer model learns consistent PII mappings while preserving the original context and intent of the text, making it suitable for queries to LLMs without exposing sensitive information.

## Key Results
- UPT achieves the lowest Information Loss (IL) at 6.99% across tested scenarios
- Combinations like UPT+NER+PoS achieve higher obfuscation but with IL around 38.44%
- Prompt engineering effectively reduces Sensitivity to Transformation Technique (STT) to zero in most cases
- The method outperforms traditional perturbation techniques by balancing privacy protection and data utility

## Why This Works (Mechanism)
The transformer-based approach works by learning consistent mappings between original PII and faux-PII tokens, ensuring that the same entity type is consistently replaced with the same faux token throughout a document. This consistency preserves context and enables the LLM to understand the semantic relationships even when the actual PII is obfuscated. The combination of UPT (for critical PII where context matters), NER (for entity-level generalization), and PoS (for syntactic preservation) provides flexibility in balancing privacy and utility based on sensitivity requirements.

## Foundational Learning
- **PII obfuscation techniques**: Understanding UPT, NER, and PoS replacement methods and their tradeoffs in privacy vs. utility preservation
- **Information loss metrics**: ILM measures meaning loss, ILS measures structural loss, and their weighted combination (0.5*ILM + 0.5*ILS) quantifies overall information degradation
- **STT measurement**: Evaluating LLM sensitivity to transformations by comparing outputs with and without prompt engineering intervention
- **Transformer-based mapping learning**: How the model learns to consistently map specific PII types to their faux counterparts across different contexts
- **Prompt engineering for LLM robustness**: Techniques to reduce sensitivity to input transformations and ensure consistent LLM responses

## Architecture Onboarding

**Component map**: User Input -> Configuration Processor -> Obfuscator (UPT/NER/PoS) -> Transformer Model -> Faux-PII Output

**Critical path**: Text document → Obfuscation transformer → LLM query → Response generation, where the transformer must maintain context preservation while effectively masking PII

**Design tradeoffs**: 
- UPT provides lowest IL but requires manual token provision
- NER+PoS combinations offer better obfuscation but higher IL
- Transformer complexity vs. real-time processing requirements

**Failure signatures**:
- High IL indicating excessive information loss from aggressive transformations
- High STT suggesting LLM sensitivity to the obfuscation approach
- Context breakdown where faux-PII disrupts semantic understanding
