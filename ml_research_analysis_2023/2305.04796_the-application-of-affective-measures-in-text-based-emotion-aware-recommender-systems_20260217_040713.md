# The Application of Affective Measures in Text-based Emotion Aware Recommender Systems

## Quick Facts
- arXiv ID: 2305.04796
- Source URL: https://arxiv.org/abs/2305.04796
- Reference count: 14
- Primary result: GPT-based emotion detection generates an Affective Index {‘happiness’: 0.02571, ‘sadness’: 0.81373, ‘anger’: 0.05563, ‘fear’: 0.09933, ‘surprise’: 0.00486, ‘disgust’: 0.00074} for movie plot content

## Executive Summary
This paper addresses fundamental challenges in Emotion Aware Recommender Systems (EARS) by proposing a privacy-preserving architecture that leverages GPT technology for affective feature detection. The approach eliminates the need for users to build their own emotion detection mechanisms while protecting sensitive emotional profile data through a separation of responsibility model. Service providers can generate real-time Affective Indices without storing personal emotional data, enabling personalized recommendations while maintaining user privacy.

## Method Summary
The proposed method uses Generative Pre-trained Transformer (GPT) technology to detect affective features in subjective passages, creating an Affective Index based on Ekman's basic emotions. Users maintain control over their emotional profiles while service providers compute Affective Indices in volatile memory for recommendation purposes. The system demonstrates this approach using ChatGPT to analyze movie plot content, generating probabilistic emotion values without requiring persistent storage of user emotional data.

## Key Results
- GPT-based emotion detection achieved specific Affective Index values for "The Godfather I" movie plot
- Demonstrated separation of responsibility where providers compute but don't store emotional data
- Eliminated need for users to build their own affective feature detection mechanisms
- Achieved emotion probability distribution across six basic emotions using single content example

## Why This Works (Mechanism)
The approach leverages GPT's natural language understanding capabilities to extract emotional content from text, converting subjective passages into structured affective features. By computing these features in volatile memory and never storing them persistently, the system maintains the benefits of emotion-aware recommendations while protecting user privacy through architectural design rather than trust assumptions.

## Architecture Onboarding
Component Map: User Content -> GPT Emotion Detector -> Affective Index Generator -> Recommendation Engine
Critical Path: Content analysis occurs in real-time, Affective Indices are computed and used immediately for recommendations, then discarded from memory
Design Tradeoffs: Privacy vs. personalization (memory-only storage protects privacy but prevents long-term personalization), accuracy vs. privacy (GPT detection may have biases but doesn't require user data collection)
Failure Signatures: Poor recommendation quality from inaccurate emotion detection, system performance degradation from real-time computation overhead, user trust erosion if privacy promises are perceived as broken

## Limitations
- Memory-only storage approach vulnerable to in-memory attacks and side-channel exploits during processing
- Limited testing to single movie plot example without validation across diverse domains and languages
- Reliance on GPT-based detection introduces model-specific biases and accuracy limitations

Low: Real-world implementation feasibility and user adoption patterns
