# HOP, UNION, GENERATE: Explainable Multi-hop Reasoning without Rationale Supervision

## Quick Facts
- arXiv ID: 2305.14237
- Source URL: https://arxiv.org/abs/2305.14237
- Authors: 
- Reference count: 17
- Key outcome: Multi-hop QA method that explicitly models rationales as sets of sentences across documents, achieving improved rationale selection compared to state-of-the-art unsupervised methods while maintaining comparable answer prediction accuracy

## Executive Summary
This paper introduces HUG, a three-stage generative model for multi-hop QA that performs rationale selection without supervision by modeling rationales as sets of sentences across documents. The approach uses a hierarchical sampling process: first selecting relevant documents, then selecting sentences within those documents, and finally generating answers conditioned on the selected sentences. Experiments on HotpotQA, MuSiQue, FEVER, and MultiRC demonstrate that HUG achieves better rationale selection (sentence F1) than unsupervised baselines while maintaining comparable answer accuracy. The method explicitly captures document dependencies necessary for multi-hop reasoning without requiring annotated rationales during training.

## Method Summary
HUG implements a three-stage generative process where rationales are treated as latent sets of sentences. The model first selects a set of relevant documents given a question using a document set scoring function, then selects sentences within each document using sentence set scoring, and finally generates an answer via a sequence-to-sequence model conditioned on the selected sentences. To make training tractable, HUG uses hierarchical sampling with top-K Viterbi approximation to marginalize over the exponential number of possible rationales. The model employs transformer encoders (distilBERT or RoBERTa-large) for embedding documents and sentences, and uses sequence-to-sequence models (BART-base or BART-large) for answer generation. Long documents are handled by slicing and aggregating representations to stay within transformer input limits.

## Key Results
- HUG achieves 49.4 sentence F1 on HotpotQA (outperforming unsupervised baselines by 1.7 points)
- Maintains comparable answer prediction accuracy (71.6 F1 on HotpotQA) while improving rationale selection
- Shows significant gains on datasets requiring multi-hop reasoning like FEVER (10.7 F1 improvement over strongest baseline)
- Demonstrates that generative answer models provide stronger supervision for rationale selection than classification models

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The three-stage generative process (Hop → Union → Generate) enables principled multi-hop reasoning without rationale supervision.
- Mechanism: The model explicitly models rationales as sets of sentences across documents by first selecting relevant documents (Hop), then selecting sentences within those documents (Union), and finally generating answers conditioned on the selected sentences (Generate).
- Core assumption: Treating rationales as latent variables that can be marginalized through hierarchical sampling makes training tractable while preserving multi-hop reasoning capabilities.
- Evidence anchors:
  - [abstract] "Our approach performs multi-hop reasoning by explicitly modeling rationales as sets, enabling the model to capture interactions between documents and sentences within a document."
  - [section 3.1] "HUG leverages the naturally hierarchical structure of text and proceeds in three stages – it first selects the relevant set of documents given the question (Hop); then, it selects a subset of sentences within each of the relevant documents and collects them together (Union); finally, it generates an answer via a seq2seq model with all the collected sentences (Generate)."
- Break condition: If the assumption that document and sentence sets can be scored independently fails, the model would lose its ability to capture cross-document dependencies essential for multi-hop reasoning.

### Mechanism 2
- Claim: Modeling document selection as a distribution over sets captures dependencies between documents necessary for multi-hop reasoning.
- Mechanism: The document set scoring function f(d, x) computes embeddings for each document independently then combines them with an MLP, allowing the model to learn how documents interact to answer questions.
- Core assumption: Document dependencies can be effectively captured through a scoring function that combines individual document embeddings with learned interaction weights.
- Evidence anchors:
  - [section 3.1] "We select a set of documents d by directly parameterizing a distribution over all valid document sets. We rely on a document set scoring function f(d, x), which captures both the relevance of the document set d to the question x, as well as the dependencies among the documents in the set."
  - [section 6] "HUG explicitly models the dependencies between documents for multi-hop reasoning. We consider independent document selection to see whether this dependency is necessary on the HotpotQA dataset."
- Break condition: If document interactions are too complex to be captured by simple combination of embeddings, the model would fail to select the correct document sets for bridge-based reasoning.

### Mechanism 3
- Claim: Using answer generation models (BART) instead of classification models improves rationale selection by requiring the model to assign high probability to every token in the answer.
- Mechanism: Generative models make better use of answer supervision because they must assign high probability to every token in the answer, which forces the model to rely more heavily on the provided rationales.
- Core assumption: The additional supervision from generative models (assigning probabilities to all answer tokens) provides stronger signal for learning good rationales than classification-based approaches.
- Evidence anchors:
  - [section 6] "Interestingly, Table 5 shows the choice of answer model significantly impacts the ability of HUG to learn a rationale model... On MultiRC, where questions can often be answered without information in accompanying documents, the best Generative model outperforms the best Classification model by over 32 sentence F1 points."
- Break condition: If the dataset structure makes it possible to answer questions without using the provided rationales (as in MultiRC), generative models may not provide the expected advantage.

## Foundational Learning

- Concept: Set distributions and marginalization
  - Why needed here: The model treats rationales as sets and must marginalize over all possible rationales during training, requiring understanding of probabilistic set operations
  - Quick check question: How does the model compute p(d|x) when d is a set of documents rather than a single document?

- Concept: Hierarchical sampling and variational inference
  - Why needed here: The intractable marginalization over all rationales is approximated through hierarchical sampling (first documents, then sentences), requiring understanding of variational inference techniques
  - Quick check question: Why does the model use top-K Viterbi approximation instead of exact marginalization?

- Concept: Transformer-based encoding of long documents
  - Why needed here: The model must encode documents that exceed transformer input limits by slicing and aggregating representations, requiring understanding of efficient long-document encoding
  - Quick check question: How does the model handle documents longer than 512 tokens while maintaining sentence-level representations?

## Architecture Onboarding

- Component map: Document set selector → Sentence set selector → Answer generator
- Critical path: Question → Document set selection → Sentence set selection → Answer generation, with each stage conditioning on previous selections
- Design tradeoffs: 
  - Using set distributions enables multi-hop reasoning but requires hierarchical sampling for tractability
  - Generative answer models provide stronger supervision but increase computational cost
  - Partitioning long documents enables encoding but introduces approximation error
- Failure signatures:
  - Poor document selection indicates issues with set scoring function or document embeddings
  - Poor sentence selection suggests problems with sentence scoring or contextual embeddings
  - Low answer accuracy despite good rationale selection points to issues with answer generation model
- First 3 experiments:
  1. Test document set selection independently by evaluating p(d|x) on a small dataset with known document dependencies
  2. Validate sentence set selection within single documents before adding multi-document complexity
  3. Compare generative vs classification answer models on a dataset where answers cannot be guessed without rationales (like FEVER)

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does HUG perform on truly open-domain multi-hop QA tasks where relevant documents are not pre-specified and must be retrieved from a large corpus?
- Basis in paper: [inferred] The paper focuses on multi-hop QA with pre-specified candidate documents (HotpotQA distractor setting, MuSiQue, FEVER, MultiRC), but does not evaluate on open-domain settings where document retrieval is part of the task.
- Why unresolved: The current experiments use datasets with fixed candidate documents, limiting generalizability to scenarios where document retrieval is required. The paper mentions HUG could be combined with BM25 but does not provide experimental validation.
- What evidence would resolve it: Experiments on open-domain multi-hop QA benchmarks like full HotpotQA open-domain setting or newly proposed open-domain multi-hop datasets would demonstrate HUG's effectiveness when document retrieval is part of the challenge.

### Open Question 2
- Question: What is the impact of using different prompt templates for answer generation on rationale selection quality, and could specialized prompts improve multi-hop reasoning?
- Basis in paper: [explicit] The paper mentions using different prompt templates for different QA formats (extractive, multiple-choice, Boolean) but does not explore how prompt design affects multi-hop reasoning performance or rationale selection.
- Why unresolved: The current approach uses standard templates without optimization for multi-hop reasoning. The answer model parameterization section mentions alternative classification models but does not explore prompt engineering for rationale selection.
- What evidence would resolve it: Systematic ablation studies comparing different prompt templates (e.g., including intermediate reasoning steps in prompts) and their effects on both answer accuracy and rationale selection quality would identify optimal prompt designs for multi-hop reasoning.

### Open Question 3
- Question: How does the performance of HUG scale with the number of reasoning hops, and is there a theoretical limit to the number of hops HUG can effectively handle?
- Basis in paper: [inferred] While HUG explicitly models document and sentence set dependencies for multi-hop reasoning, the paper does not systematically analyze performance degradation as the number of required reasoning hops increases, nor does it establish theoretical bounds on hop scalability.
- Why unresolved: The experiments use datasets with relatively few hops (mostly 2-hop reasoning in HotpotQA), but don't explore scenarios requiring more complex reasoning chains. The paper mentions that HUG benefits more from larger models as reasoning hops increase but doesn't quantify this relationship.
- What evidence would resolve it: Experiments on datasets with varying hop complexity (e.g., datasets specifically designed for 3+ hop reasoning) and analysis of HUG's performance degradation patterns would establish the practical limits of HUG's multi-hop reasoning capabilities.

## Limitations

- The model's reliance on explicit document and sentence selection makes it computationally expensive for large-scale datasets due to exponential set scoring and sampling requirements
- The Viterbi approximation used for tractable training introduces approximation error that could degrade performance, particularly for datasets with complex document dependencies
- Performance heavily depends on the quality of initial document retrieval, as errors in document selection propagate through subsequent stages

## Confidence

- High confidence: The three-stage generative framework is clearly defined and experimentally validated across multiple datasets with strong ablation evidence
- Medium confidence: Improved rationale selection is demonstrated through better sentence F1 scores, though the evaluation is limited to datasets with human-annotated rationales
- Low confidence: Generalizability claims are not well-supported as experiments are primarily conducted on HotpotQA and similar datasets without testing truly open-domain scenarios

## Next Checks

1. **Document selection ablation study**: Remove the document set scoring function entirely and use retrieved documents instead of learned document selection. Compare performance to determine whether the learned document selection genuinely improves reasoning or simply reinforces retrieval results.

2. **Cross-dataset generalization test**: Train the model on HotpotQA and evaluate on a different multi-hop QA dataset (e.g., WikiHop or QASC) without fine-tuning. This would test whether the learned rationale selection generalizes beyond the training distribution.

3. **Human evaluation of reasoning quality**: Conduct a user study where human judges assess whether the selected rationales actually support the multi-hop reasoning process, not just whether they match human annotations. This would validate whether improved sentence F1 corresponds to improved actual reasoning capabilities.
