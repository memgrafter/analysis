# Graph Neural Networks Go Forward-Forward

## Quick Facts
- arXiv ID: 2302.05282
- Source URL: https://arxiv.org/abs/2302.05282
- Reference count: 13
- This paper introduces Graph Forward-Forward (GFF), an extension of the Forward-Forward algorithm to graph neural networks (GNNs), enabling training without backpropagation.

## Executive Summary
This paper introduces Graph Forward-Forward (GFF), an extension of the Forward-Forward algorithm to graph neural networks (GNNs), enabling training without backpropagation. GFF operates by training GNNs greedily layer-by-layer using positive and negative samples, with the "goodness" of each layer determining parameter updates. The method is compatible with any message-passing scheme and offers a more biologically plausible learning process. Experiments on 11 standard graph property prediction tasks demonstrate that GFF achieves comparable performance to backpropagation-trained GNNs, with some datasets showing improved accuracy. Additionally, GFF provides computational advantages, particularly in memory efficiency, and avoids the need for gradient chaining.

## Method Summary
GFF trains graph neural networks greedily layer-by-layer without backpropagation. For each layer, the algorithm computes a "goodness" metric based on the squared activations of node features, aggregated via sum-pooling. Positive samples (graphs with correct label encodings) are used to maximize goodness, while negative samples (graphs with incorrect label encodings) minimize it. Label encodings are embedded either by appending to node features or using a virtual node. Each layer is updated independently using local loss functions comparing goodness to a threshold. During inference, label goodness is computed for each possible class and the highest is selected.

## Key Results
- GFF achieves comparable performance to backpropagation-trained GNNs on 11 standard graph property prediction tasks, with some datasets showing improved accuracy.
- The method is compatible with any message-passing scheme and offers computational advantages, particularly in memory efficiency.
- Ablation studies show robustness to pooling functions, goodness computation methods, and label encoding approaches.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: GFF trains GNNs greedily layer-by-layer without backpropagation, achieving competitive performance.
- Mechanism: Each layer is trained independently to maximize goodness on positive samples and minimize it on negative samples, using only forward passes.
- Core assumption: Layer-wise goodness optimization preserves or enhances downstream task performance.
- Evidence anchors:
  - [abstract]: "GFF achieves comparable performance to backpropagation-trained GNNs, with some datasets showing improved accuracy."
  - [section]: "With GFF, graph neural networks are trained greedily layer by layer, using both positive and negative samples."
  - [corpus]: Weak - no direct neighbor papers discussing layer-wise greedy training in GNNs; only general Forward-Forward extensions.
- Break condition: If layer-wise training disrupts inter-layer dependencies critical for the task.

### Mechanism 2
- Claim: Goodness aggregation via sum-pooling over squared node activations enables effective layer-wise supervision.
- Mechanism: Squared activations are summed across nodes and features, normalized, to yield a scalar goodness per layer.
- Core assumption: This scalar summary preserves enough signal for parameter updates.
- Evidence anchors:
  - [section]: "The goodness g(i) of the i-th layer, when we use sum-pooling as an aggregation function, is defined such that g(i) = 1/d Σ_k Σ_j (a(i)_jk)²."
  - [abstract]: "We run experiments on 11 standard graph property prediction tasks, showing how GFF provides an effective alternative to backpropagation."
  - [corpus]: Weak - no direct neighbors discussing goodness aggregation in GNNs; only general FF goodness definitions.
- Break condition: If pooling discards discriminative information needed for classification.

### Mechanism 3
- Claim: Using positive/negative label encodings embedded in node features or virtual nodes provides contrastive supervision without explicit pairwise comparisons.
- Mechanism: Each graph is duplicated with correct (positive) and incorrect (negative) label encodings; the network learns to associate higher goodness with correct labels.
- Core assumption: Label encoding differences are sufficient to guide learning without comparing representations.
- Evidence anchors:
  - [section]: "We develop and test two approaches... One consists in appending the one-hot encoded label to each node representation... A second approach... is to endow input graphs with an additional virtual node carrying all information about the label."
  - [abstract]: "This shows in particular that this procedure is remarkably efficient in spite of combining the per-layer training with the locality of the processing in a GNN."
  - [corpus]: Weak - no neighbors detailing label encoding in GNN-FF settings; only general FF label encoding in images.
- Break condition: If label encoding does not influence node representations sufficiently.

## Architecture Onboarding

- Component map:
  Input -> Message-passing (e.g., GCN) -> Activation -> Normalization -> Goodness computation -> Local loss -> Parameter update

- Critical path:
  1. Generate positive/negative samples by embedding correct/incorrect label encodings
  2. For each layer: run forward pass, compute goodness, update parameters with local loss
  3. For inference: compute label goodness for each possible label and select argmax

- Design tradeoffs:
  - Greedy layer-wise training vs. end-to-end backpropagation (memory, scalability, dependency capture)
  - Sum-pooling vs. other pooling methods (aggregation bias, sensitivity to graph size)
  - Node feature concatenation vs. virtual node (data redundancy, interpretability)

- Failure signatures:
  - Poor convergence or high variance in training curves
  - Label goodness values too close to distinguish classes
  - Extremely slow or unstable training when using RGCN with virtual nodes

- First 3 experiments:
  1. Train GFF on a small graph dataset (e.g., MUTAG) with sum-pooling and node feature concatenation; compare accuracy to baseline GCN.
  2. Swap sum-pooling for mean-pooling; observe performance changes.
  3. Replace node feature concatenation with virtual node approach; check stability and accuracy.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal goodness function and local loss function for different graph tasks and datasets?
- Basis in paper: [explicit] The paper mentions that "A good question is how to choose the goodness function and the local loss function" and suggests exploring alternative aggregation methods beyond squared activity vectors.
- Why unresolved: The paper uses squared activity vectors summed over nodes and features as the goodness function, but acknowledges that different tasks might benefit from different goodness functions.
- What evidence would resolve it: Systematic experiments comparing various goodness functions (e.g., mean pooling, max pooling, attention-based aggregation) and local loss functions across diverse graph tasks and datasets.

### Open Question 2
- Question: How can the GFF algorithm be extended to graph regression tasks where the number of labels is not finite?
- Basis in paper: [explicit] The paper states "The method could be extended to handle graph regression" but identifies challenges in defining negative datasets and performing predictions when labels are continuous rather than discrete.
- Why unresolved: The current GFF framework relies on computing label goodness for a finite set of possible labels, which doesn't directly translate to regression where the output space is continuous.
- What evidence would resolve it: Development and validation of a GFF-based approach for graph regression, including methods for generating negative samples and performing predictions in continuous output spaces.

### Open Question 3
- Question: How can negative samples be effectively generated by modifying the underlying graph structure rather than just relabeling?
- Basis in paper: [explicit] The paper suggests "Drawing from the contrastive learning literature, it might be possible to generate negative samples by modifying the underlying graph" and notes this could help GFF focus on longer-range correlations.
- Why unresolved: Current negative sample generation simply assigns incorrect labels to existing graphs, which may not capture the full potential of contrastive learning approaches for graph data.
- What evidence would resolve it: Empirical studies comparing graph-based negative sampling methods (e.g., edge perturbation, node feature corruption, subgraph sampling) against simple relabeling approaches across various graph tasks.

## Limitations
- Layer-wise greedy training may disrupt inter-layer dependencies critical for graph property prediction tasks.
- Goodness aggregation via sum-pooling may discard discriminative information needed for classification.
- Label encoding approaches show varying performance across datasets, but reasons for differences remain unclear.

## Confidence
- **High Confidence**: GFF provides a biologically plausible alternative to backpropagation that works in practice. The experimental results on 11 standard datasets are clear and reproducible.
- **Medium Confidence**: The claim that GFF achieves comparable performance to backpropagation-trained GNNs. While the results show competitive accuracy, the variance across datasets and the lack of extensive hyperparameter tuning limit stronger conclusions.
- **Low Confidence**: The claim that GFF's layer-wise training preserves or enhances downstream task performance without disrupting inter-layer dependencies. This is not directly tested and relies on empirical results alone.

## Next Checks
1. **Ablation on Inter-layer Dependencies**: Train GFF with and without allowing parameter updates to propagate across layers (e.g., by fine-tuning all layers together after greedy training) to isolate the impact of layer-wise independence.

2. **Goodness Function Sensitivity**: Systematically compare different goodness aggregation functions (sum-pooling, mean-pooling, max-pooling) on a subset of datasets to determine which preserves the most discriminative information.

3. **Label Encoding Robustness**: Evaluate GFF's performance when label encodings are corrupted or noisy to test the robustness of the contrastive learning mechanism and determine if it's learning meaningful representations or memorizing label associations.
