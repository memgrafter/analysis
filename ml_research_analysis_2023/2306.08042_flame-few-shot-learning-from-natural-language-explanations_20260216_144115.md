# FLamE: Few-shot Learning from Natural Language Explanations

## Quick Facts
- arXiv ID: 2306.08042
- Source URL: https://arxiv.org/abs/2306.08042
- Reference count: 19
- Primary result: Achieves 17.6% higher accuracy than GPT-3 Babbage and 5.7% higher than GPT-3 Davinci on e-SNLI using generated explanations

## Executive Summary
FLamE introduces a two-stage framework for few-shot learning that leverages natural language explanations to improve classification accuracy. The method uses GPT-3 to generate explanations for classification tasks, then fine-tunes a smaller, more interpretable model (like RoBERTa) using these explanations as training data. Evaluated on natural language inference tasks, FLamE demonstrates significant performance improvements over GPT-3 baselines while maintaining interpretability through the smaller classifier. Human evaluation reveals that while most generated explanations are logically invalid, they contain useful label-specific cues that drive the classification performance gains.

## Method Summary
FLamE operates in two stages: first, GPT-3 generates natural language explanations for given examples in a few-shot setting; second, a smaller model (e.g., RoBERTa) is fine-tuned on these generated explanations. The framework is evaluated on e-SNLI and e-HANS datasets for natural language inference tasks. The generated explanations, despite being mostly logically invalid according to human evaluation, contain label-specific cues (e.g., "not know" for neutral label) that the fine-tuned model learns to associate with correct classifications. This approach enables learning from explanations while maintaining interpretability through the smaller classifier.

## Key Results
- FLamE achieves 17.6% higher accuracy than GPT-3 Babbage and 5.7% higher than GPT-3 Davinci on e-SNLI
- Only 2.6% of generated explanations were rated as logically valid by human evaluators
- Perturbation experiments confirm that label-specific cues in explanations are crucial for model predictions

## Why This Works (Mechanism)
FLamE works by leveraging GPT-3's ability to generate explanations that, while often logically invalid, contain label-specific cues that correlate with correct classifications. The smaller classifier learns to recognize these cues during fine-tuning, enabling improved few-shot performance. The method effectively transforms GPT-3's explanatory reasoning (however flawed) into a form that can be distilled into a more efficient, interpretable model. The key insight is that the structure of explanations, rather than their logical validity, provides useful signal for classification tasks.

## Architecture Onboarding

Component Map: GPT-3 explanation generator -> Explanation storage -> RoBERTa fine-tuner -> Classification output

Critical Path: Input examples → GPT-3 explanation generation → Store explanations → Fine-tune RoBERTa on explanations → Make predictions

Design Tradeoffs: Uses GPT-3 for high-quality explanation generation but incurs computational cost; trades off some performance for interpretability by using smaller RoBERTa model; accepts logically invalid explanations for improved cue-based learning.

Failure Signatures: Performance degrades when explanations lack clear label-specific cues; overfitting to spurious patterns in explanations; poor generalization to out-of-distribution examples.

## Limitations
- Most generated explanations are logically invalid (only 2.6% rated valid by humans)
- Limited to narrow domain (natural language inference) and small label spaces (3-class problems)
- Does not compare against alternative explanation-based methods or different generation strategies

## Confidence

High Confidence:
- Experimental results showing FLamE's performance improvements over GPT-3 baselines
- Perturbation experiments demonstrating importance of label-specific cues

Medium Confidence:
- Claim that explanations provide interpretability through smaller classifier
- Generalizability of approach beyond tested NLI tasks

Low Confidence:
- Assertion that method "enables effective learning from explanations" given mostly invalid explanations
- Whether performance gains stem from genuine understanding versus pattern matching

## Next Checks
