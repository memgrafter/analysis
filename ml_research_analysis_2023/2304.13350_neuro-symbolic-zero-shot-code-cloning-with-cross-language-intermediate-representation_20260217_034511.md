# Neuro-symbolic Zero-Shot Code Cloning with Cross-Language Intermediate Representation

## Quick Facts
- arXiv ID: 2304.13350
- Source URL: https://arxiv.org/abs/2304.13350
- Reference count: 8
- Key outcome: Achieves 12.85 MAP@2 improvement over pre-trained UniXCoder for zero-shot COBOL code clone detection using cross-language transfer from C

## Executive Summary
This paper addresses the challenge of code clone detection for COBOL, a low-resource legacy programming language, by proposing a zero-shot approach that transfers knowledge from the high-resource C language. The method involves creating a common meta-model for intermediate representation (IR) in the form of abstract syntax trees (ASTs) for both C and COBOL, linearizing these IRs using Structure Based Traversal (SBT), and fine-tuning the UniXCoder model on C-SBT-IRs. The approach demonstrates significant performance improvements over pre-trained models in detecting code clones in COBOL without requiring any COBOL training data.

## Method Summary
The approach defines a language-agnostic meta-model instantiated as ASTs for both C and COBOL codes. These ASTs are linearized using Structure Based Traversal (SBT) to create sequential inputs compatible with transformer models. The UniXCoder model, pre-trained for cross-programming language code search, is fine-tuned using SBT-IRs of C code-pairs from the CodeNet dataset. This fine-tuning enables the model to learn transferable representations that can detect code clones in COBOL through zero-shot inference, without requiring any COBOL training data.

## Key Results
- Achieves 12.85 MAP@2 improvement over pre-trained UniXCoder model for COBOL code clone detection
- Demonstrates effectiveness of AST-based IR in capturing language-independent semantic representations
- Shows superior performance compared to models trained from scratch or fine-tuned with original C codes
- Validates the approach on CodeNet dataset with C codes for fine-tuning and COBOL codes for zero-shot testing

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The meta-model based IR creates language-independent semantic representations that enable zero-shot transfer from C to COBOL.
- Mechanism: A shared AST-based IR structure captures the syntactic and semantic elements common to both C and COBOL, abstracting away language-specific surface forms. This common representation space allows knowledge learned on C to transfer directly to COBOL without requiring COBOL training data.
- Core assumption: The semantic equivalence between C and COBOL code fragments can be preserved through the IR transformation, and that the structural similarity in their AST representations is sufficient for semantic understanding.
- Evidence anchors:
  - [abstract]: "We define a meta-model that is instantiated to have an Intermediate Representation (IR) in the form of Abstract Syntax Trees (ASTs) common across codes in C and COBOL."
  - [section 4]: "Our meta-model captures different kinds of IR elements as classes... An IR of a program is constructed by instantiating relevant IR elements in the meta-model."
  - [corpus]: Weak evidence - no directly comparable work found in the corpus, but the approach is novel in using IR for cross-language transfer in code cloning.
- Break condition: If the AST-based IR fails to capture semantic differences between C and COBOL (e.g., different control flow patterns or data handling semantics), the transfer will break down.

### Mechanism 2
- Claim: Fine-tuning UniXCoder with C-SBT-IRs enables better generalization to COBOL than fine-tuning with original C code.
- Mechanism: The SBT-IR representation forces the model to learn structural and semantic relationships rather than surface-level patterns. When UniXCoder is fine-tuned on these IR sequences, it learns language-agnostic code representations that transfer better to unseen COBOL codes.
- Core assumption: The linearized SBT-IR representation preserves sufficient semantic information for code clone detection while removing language-specific syntactic details that could hinder transfer.
- Evidence anchors:
  - [abstract]: "With this fine-tuned UniXCoder, we get a performance improvement of 12.85 MAP@2 over the pre-trained UniXCoder model, in a zero-shot setting, on the COBOL test split."
  - [section 4]: "This allows us to learn latent representations for the IRs of the C codes, which are transferable to the IRs of the COBOL codes."
  - [corpus]: No direct evidence in corpus - this specific comparison appears novel.
- Break condition: If the SBT-IR linearization loses critical semantic information or if the model overfits to C-specific patterns in the IR, transfer performance will degrade.

### Mechanism 3
- Claim: Pre-training on a generic set of programming languages provides better downstream performance than training from scratch.
- Mechanism: The pre-trained UniXCoder model has already learned general code understanding capabilities across multiple languages, providing a strong foundation that can be adapted to specific tasks with less task-specific data.
- Core assumption: General code understanding capabilities learned from multiple languages transfer effectively to specialized tasks like code clone detection.
- Evidence anchors:
  - [abstract]: "fine-tune UnixCoder, the best-performing model for zero-shot cross-programming language code search, for the Code Cloning task"
  - [section 5]: "The performance of the pre-trained UniXCoder is significantly better than that of the vanilla transformer trained using C-SBT-IRs... This demonstrates the efficacy of the use of a model pre-trained with a large amount of code data yielding superior performance over a model trained from scratch"
  - [corpus]: Weak evidence - while related work exists on pre-training, the specific comparison between pre-trained vs scratch models for zero-shot COBOL transfer is not directly addressed in the corpus.
- Break condition: If the pre-training data is too dissimilar from the target task/domain, or if the model's learned representations are too generic to capture task-specific patterns, performance gains may be limited.

## Architecture Onboarding

- Component map: Parser → Meta-model instantiation → AST generation → SBT linearization → UniXCoder fine-tuning → Zero-shot inference on COBOL
- Critical path: Parser → Meta-model instantiation → AST generation → SBT linearization → UniXCoder fine-tuning → Zero-shot inference on COBOL
- Design tradeoffs:
  - Using AST-based IR vs. other representations (token sequences, CFGs, etc.): AST provides structural information but may miss some semantic nuances
  - Linearizing AST vs. using graph-based models: Linearization enables use of transformer models but loses explicit graph structure
  - Zero-shot transfer vs. few-shot/fine-tuning on COBOL: Zero-shot requires no COBOL data but may limit performance compared to fine-tuning
- Failure signatures:
  - Poor MAP scores on COBOL test set despite good C performance: suggests IR transformation isn't preserving semantic equivalence
  - Large performance gap between C and COBOL: indicates language-specific patterns aren't being properly abstracted
  - Model overfitting to C patterns: suggests insufficient abstraction in the IR or SBT representation
- First 3 experiments:
  1. Compare MAP@2 scores on COBOL test set between model fine-tuned on C-SBT-IRs vs. original C code (as done in paper)
  2. Test zero-shot transfer from COBOL to C (reverse direction) to validate symmetry of the approach
  3. Ablation study: remove SBT linearization and fine-tune on AST structures directly (if model supports tree inputs) to measure impact of linearization

## Limitations
- The approach's effectiveness depends on sufficient semantic overlap between C and COBOL AST structures, which may not hold for languages with different paradigms
- The SBT linearization process may lose important structural information that could impact clone detection accuracy
- The handling of COBOL-specific constructs through the common IR is not detailed, raising concerns about potential information loss during abstraction

## Confidence
- High confidence: The experimental results showing 12.85 MAP@2 improvement over pre-trained UniXCoder are well-documented and reproducible
- Medium confidence: The claim that the meta-model provides language-independent semantic representations is theoretically sound but lacks empirical validation
- Medium confidence: The assertion that pre-training on multiple languages provides superior performance to training from scratch is supported by the results but limited to one baseline comparison
