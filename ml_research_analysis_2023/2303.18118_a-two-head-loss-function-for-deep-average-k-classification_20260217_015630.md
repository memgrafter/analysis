# A two-head loss function for deep Average-K classification

## Quick Facts
- arXiv ID: 2303.18118
- Source URL: https://arxiv.org/abs/2303.18118
- Authors: 
- Reference count: 37
- One-line primary result: Two-head loss function (AVG-K) outperforms softmax and top-K baselines for average-K classification, especially on ambiguous and few-shot classes.

## Executive Summary
This paper introduces AVG-K, a novel two-head loss function for average-K classification, where the model must return K classes on average while adapting to input ambiguity. The approach uses a softmax head to identify candidate classes and a multi-label head to maximize likelihood for both true and candidate labels. Experiments on CIFAR-100 and Pl@ntNet-300K show AVG-K consistently outperforms cross-entropy and top-K losses, with larger gains for high-uncertainty cases and classes with few samples. The method is particularly effective for K≥3, with average-10 accuracy reaching 98.23% on Pl@ntNet-300K.

## Method Summary
AVG-K is a two-head loss function for average-K classification. It uses a softmax head (SCCP) to generate class probabilities and identify candidate classes via thresholding, and a multi-label head (ML) to maximize likelihood for both true and candidate labels using binary cross-entropy. Candidate classes are selected from the batch to ensure an average of K classes per image. The total loss is a weighted sum of cross-entropy (SCCP) and BCE (ML), with hyperparameter α controlling the trade-off. The method is trained end-to-end and adapts dynamically to ambiguity within each batch.

## Key Results
- AVG-K achieves 98.23% average-10 accuracy on Pl@ntNet-300K, outperforming top-K (97.26%) and cross-entropy (97.11%) baselines.
- Gains are largest for high uncertainty cases and classes with few samples.
- AVG-K outperforms softmax baseline for all K except K=2.

## Why This Works (Mechanism)

### Mechanism 1
The two-head architecture improves average-K classification by dynamically identifying ambiguous classes within each batch and assigning them pseudo-labels for multi-label training. The SCCP head identifies candidate classes via softmax scores (excluding the true label) and selects top candidates across the batch to ensure an average of K classes. The ML head then maximizes likelihood for both the true label and these candidates using binary cross-entropy, improving recognition of ambiguous classes.

Core assumption: Ambiguity can be captured and leveraged within a batch without requiring additional data; candidate selection is informative when averaged over batch.

Evidence anchors:
- [abstract]: "Experiments on two datasets from the literature demonstrate that our approach outperforms the softmax baseline, as well as several other loss functions more generally designed for weakly supervised multi-label classification. The gains are larger the higher the uncertainty, especially for classes with few samples."
- [section]: "In this paper, we propose a new loss function based on a multi-label classification head in addition to the classical softmax... trained using pseudo-labels generated by thresholding the softmax head while guaranteeing that K classes are returned on average."

Break condition: If the batch size is too small, the method cannot capture variability in ambiguity; if α is set too high, pseudo-labels dominate true labels, causing model instability.

### Mechanism 2
By using pseudo-labels generated on the fly, the model can handle label ambiguity better than standard cross-entropy, which assumes single correct labels. The model learns to boost scores for plausible alternative classes alongside the true class, rather than suppressing them. This is achieved by the ML head treating both true and candidate classes as positives.

Core assumption: In real-world datasets, multiple classes are often plausible for a given image, and learning to include them improves overall set accuracy.

Evidence anchors:
- [abstract]: "We show that this approach allows the model to better capture ambiguities between classes and, as a result, to return more consistent sets of possible classes."
- [section]: "The main difficulty is: how to obtain the candidate labels Sc(xi)? To this end, we propose a two-head model..."

Break condition: If the SCCP head consistently selects irrelevant candidates, the ML head will be misled, reducing accuracy.

### Mechanism 3
The dynamic, batch-wise selection of candidate classes ensures that the average number of returned classes matches K without being overly rigid. By selecting top (K-1)|B| candidate classes per batch, the method naturally adapts to varying ambiguity across images, returning more classes for ambiguous images and fewer for clear ones.

Core assumption: Averaging over a batch is sufficient to enforce the K-class average constraint without requiring instance-level control.

Evidence anchors:
- [abstract]: "Controlling the average number of classes returned is useful for many applications... Our method is more effective for all K except when K=2..."
- [section]: "To construct the candidate classes sets SB_c, we then select the top (K-1)|B| values of Σ-∞ to obtain sets of average size K on the batch..."

Break condition: If the batch is too homogeneous (e.g., all images are unambiguous), the method may not return enough classes to meet the average K constraint.

## Architecture Onboarding

- Component map:
  Input layer -> Backbone (e.g., ResNet-18) -> Shared latent space (HB) -> SCCP head (linear layer -> softmax) -> ML head (linear layer) -> Loss computation

- Critical path:
  1. Forward pass through backbone to get HB
  2. SCCP head produces class scores, softmax applied, candidates selected
  3. ML head produces class scores, binary cross-entropy computed with true + candidate labels
  4. Total loss = cross-entropy (SCCP) + weighted BCE (ML)
  5. Backward pass updates both heads and shared backbone

- Design tradeoffs:
  - Adding a second head increases model complexity and memory usage but enables dynamic candidate selection
  - Batch size critically affects candidate selection quality; too small → poor ambiguity capture
  - Hyperparameter α balances influence of true vs. candidate labels; requires tuning

- Failure signatures:
  - Model collapses to returning only the true label (α too low or batch too small)
  - Model returns too many irrelevant classes (SCCP head poorly calibrated)
  - Training instability (α too high, causing pseudo-labels to dominate)

## Limitations
- The method's effectiveness heavily depends on batch size, with no clear guidance on minimum batch size for reliable candidate selection.
- Hyperparameter α requires careful tuning and may not generalize across datasets; poor calibration can lead to instability or collapse to single-label output.
- The approach assumes pseudo-labels from softmax thresholding are reliable indicators of ambiguity, which may not hold for highly imbalanced or noisy datasets.

## Confidence

**High Confidence**: The experimental results showing AVG-K outperforming cross-entropy and top-K losses on CIFAR-100 and Pl@ntNet-300K are well-supported by the reported metrics. The mechanism of using a two-head architecture to capture ambiguity through pseudo-labels is logically sound and consistent with multi-label learning principles.

**Medium Confidence**: The claim that gains are "larger the higher the uncertainty" is supported by the paper's results but relies on the assumption that the SCCP head accurately identifies ambiguous cases. The batch-wise candidate selection mechanism is reasonable but may fail for small or homogeneous batches, as acknowledged in the failure conditions.

**Low Confidence**: The scalability of AVG-K to extremely large datasets or models with many classes remains uncertain, as the paper only tests on two datasets with up to 1,081 classes. The sensitivity of the method to hyperparameter α and batch size is mentioned but not thoroughly explored.
