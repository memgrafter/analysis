# Continual Facial Expression Recognition: A Benchmark

## Quick Facts
- arXiv ID: 2305.06448
- Source URL: https://arxiv.org/abs/2305.06448
- Authors: [Authors not specified in source]
- Reference count: 40
- One-line primary result: Replay-based CL methods achieve state-of-the-art performance across 3 FER datasets under both Task-IL and Class-IL settings

## Executive Summary
This paper presents ConFER, a benchmark for evaluating Continual Learning (CL) techniques in Facial Expression Recognition (FER) tasks. The benchmark addresses the challenge of training FER models that can adapt to individual differences and contextual changes in real-world settings where data is incrementally acquired during interactions. ConFER evaluates 11 CL strategies across Task-Incremental Learning (Task-IL) and Class-Incremental Learning (Class-IL) settings on three popular FER datasets (CK+, RAF-DB, and AffectNet). The results demonstrate that replay-based methods, particularly Latent Generative Replay (LGR), outperform other approaches and achieve state-of-the-art performance across different datasets and learning scenarios.

## Method Summary
ConFER implements 11 CL strategies (regularization-based, replay-based, and generative replay-based) using a LeNet-like CNN architecture trained from scratch. The benchmark evaluates these methods on three FER datasets with 8 expression classes under both Task-IL and Class-IL settings. Data augmentation is applied uniformly across all methods, and experiments are repeated with 3 random seeds. The framework uses Average Accuracy Score (Acc) and Catastrophic Forgetting (CF) metrics to assess performance, with comparisons against Lower Bound (LB) and Upper Bound (UB) baselines.

## Key Results
- Replay-based methods (NR, A-GEM, LR) outperform regularization-based methods under Task-IL settings
- Regularization-based methods (EWC, EWC-Online, SI, LwF) perform better than replay-based methods under Class-IL settings
- Data augmentation improves replay-based method performance under Class-IL by providing more diverse samples
- Latent Generative Replay (LGR) achieves state-of-the-art performance across datasets and learning settings

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Replay-based methods maintain memory buffers to simulate i.i.d. learning conditions, mitigating catastrophic forgetting
- Core assumption: Memory buffers contain representative samples from each task
- Evidence: Replay methods achieve SOTA performance across datasets
- Break condition: Memory buffer becomes too small relative to number of tasks

### Mechanism 2
- Claim: Regularization-based methods learn task-specific parameters that prioritize weight updates based on task relevance
- Core assumption: Model can identify and prioritize task-relevant parameters without explicit labels
- Evidence: Regularization methods perform better under Class-IL settings
- Break condition: Model cannot balance priorities of old vs new task parameters

### Mechanism 3
- Claim: Data augmentation provides diverse samples for each class, enabling more robust feature representations
- Core assumption: Augmented data maintains class semantics while introducing variations
- Evidence: Augmentation improves replay-based method performance
- Break condition: Augmentation transformations are too extreme or break class semantics

## Foundational Learning

- Concept: Catastrophic forgetting
  - Why needed: Primary challenge CL methods address in FER when new classes overwrite previous knowledge
  - Quick check: What happens to model performance on previous tasks when trained on new tasks without forgetting prevention?

- Concept: Task-Incremental Learning (Task-IL) vs Class-Incremental Learning (Class-IL)
  - Why needed: Different learning scenarios requiring distinct solutions and understanding challenges
  - Quick check: What's the key difference between Task-IL and Class-IL regarding information available during training?

- Concept: Replay mechanisms (rehearsal vs pseudo-rehearsal)
  - Why needed: Core strategy for mitigating catastrophic forgetting using actual vs synthetic samples
  - Quick check: What distinguishes rehearsal from pseudo-rehearsal approaches?

## Architecture Onboarding

- Component map: Data preprocessing -> Model architecture -> Learning algorithms -> Evaluation metrics -> Hyperparameter tuning
- Critical path: Preprocess input data → Initialize model → Train on each task/class with replay/regularization → Evaluate on all seen tasks → Store samples in memory buffer
- Design tradeoffs: Memory buffer size vs efficiency; parameters vs capacity; generative model quality vs sample realism
- Failure signatures: Rapid accuracy decrease on previous tasks; no improvement on new tasks; high variance across runs; memory buffer issues
- First 3 experiments: 1) Implement NR on CK+ under Task-IL for baseline; 2) Implement EWC on CK+ under Class-IL for comparison; 3) Implement DGR on AffectNet under Task-IL for scalability assessment

## Open Questions the Paper Calls Out

- How do ConFER's replay-based methods scale when learning beyond 8 basic expressions to larger expression vocabularies?
- How would ConFER perform under task-free settings with blurred task boundaries rather than clear class increments?
- Would pre-training ConFER models on large-scale facial recognition datasets improve catastrophic forgetting mitigation compared to training from scratch?

## Limitations

- Evaluation restricted to small-scale FER datasets (CK+, RAF-DB, AffectNet) with only 8 expression classes
- LeNet-like CNN architecture may not capture full potential of modern deep learning approaches for FER
- Fixed memory buffer sizes and hyperparameters may not be optimal for each dataset's specific characteristics

## Confidence

- High confidence in overall framework and methodology for evaluating CL techniques in FER settings
- Medium confidence in comparative performance rankings between different CL methods due to potential architecture limitations
- Medium confidence in generalizability of results to larger-scale, more diverse FER scenarios
