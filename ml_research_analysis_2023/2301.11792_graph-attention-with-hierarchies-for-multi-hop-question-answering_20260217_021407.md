# Graph Attention with Hierarchies for Multi-hop Question Answering

## Quick Facts
- arXiv ID: 2301.11792
- Source URL: https://arxiv.org/abs/2301.11792
- Reference count: 7
- Primary result: Achieves 71.9 joint F1 on HotpotQA dev set with combined graph completion and GATH

## Executive Summary
This paper extends the Hierarchical Graph Network (HGN) for multi-hop Question Answering on HotpotQA by introducing two key improvements: (1) adding direct edges between the query and sentence nodes to complete the graph structure, and (2) proposing Graph Attention with Hierarchies (GATH) that updates node representations sequentially based on hierarchical levels rather than simultaneously. The authors demonstrate that both extensions improve performance individually, with the combined approach achieving the best results. The final model achieves a joint F1 score of 71.9 on the HotpotQA development set, outperforming the baseline HGN model.

## Method Summary
The authors build upon HGN by first completing the hierarchical graph structure with novel question_sentence edges that connect the question node directly to all sentence nodes in selected paragraphs. They then introduce GATH, which updates node representations in a sequential fashion according to a pre-determined order of hierarchical levels (e.g., paragraphs → sentences → entities) rather than updating all nodes simultaneously. The model is trained using RoBERTa-large as the base encoder with multi-task learning objectives including answer span extraction, supporting fact prediction, and paragraph selection.

## Key Results
- Graph completion (adding question-sentence edges) improves answer span extraction by 1.6-2.4 F1 points
- GATH with sequential hierarchical updates outperforms standard GAT with simultaneous updates
- Combined model achieves 71.9 joint F1 on HotpotQA dev set, outperforming baseline HGN
- Different hierarchical update orders (P/S/E, E/S/P, S/P/E, S/E/P) yield varying performance, with S/E/P being optimal

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Adding edges between question and sentence nodes improves direct question-sentence relationships
- Mechanism: Creates shorter information paths by allowing direct propagation from question to relevant sentences without traversing through paragraph or entity nodes first
- Core assumption: Direct connections provide more efficient information flow than indirect paths
- Evidence anchors: [abstract] introduces question_sentence edges; [section 3.1] describes connecting question node with all sentence nodes; [corpus] weak evidence from neighbors
- Break condition: Additional edges could introduce noise if paragraph selection retrieves irrelevant paragraphs

### Mechanism 2
- Claim: Sequential node updates based on hierarchical levels improve multi-hop reasoning
- Mechanism: Staggered updates allow each level to aggregate information from immediate neighbors before passing refined representations down the hierarchy
- Core assumption: Document hierarchy (paragraphs→sentences→entities) represents meaningful information flow
- Evidence anchors: [abstract] describes sequential updates based on hierarchy; [section 3.2] explains updating nodes according to pre-determined hierarchical order; [section 4.2] shows 1.6-2.4 point improvements
- Break condition: Predetermined order may not match actual information flow needed for specific question types

### Mechanism 3
- Claim: Combination of graph completion and GATH creates synergistic effects
- Mechanism: Graph completion provides complete information pathways while GATH provides effective traversal of those pathways
- Core assumption: Benefits of improved structure and reasoning mechanisms are complementary
- Evidence anchors: [section 4.2] describes combined model performance; [section 4.2] shows slight improvement over individual models; [corpus] weak evidence for synergy
- Break condition: Combined model could become too complex or mechanisms could interfere rather than complement

## Architecture Onboarding

- Component map: Input → Graph Construction → Context Encoding → Graph Reasoning → Multi-task Prediction → Output
- Critical path: Graph Construction → Context Encoding → Graph Reasoning → Multi-task Prediction
- Design tradeoffs:
  - GATH requires predefined hierarchical order, adding complexity but potentially improving performance
  - Query-sentence edges increase graph density, potentially improving information flow but also computational cost
  - RoBERTa large provides strong contextual embeddings but increases computational requirements
- Failure signatures:
  - Poor paragraph selection leads to poor graph foundation
  - Mismatched hierarchical order degrades performance
  - Overfitting to HotpotQA structure limits generalization
- First 3 experiments:
  1. Train HGN with only graph completion (add query-sentence edges)
  2. Train HGN with only GATH (sequential updates) using original graph
  3. Train HGN with both improvements combined, testing different hierarchical update orders

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the order of hierarchical levels in GATH affect performance on different types of multi-hop reasoning questions?
- Basis in paper: [explicit] Different orders (P/S/E, S/E/P, etc.) lead to varying performance; authors note influence on evidence collection ability
- Why unresolved: Paper identifies optimal order for overall performance but doesn't analyze how different orders affect specific reasoning types
- What evidence would resolve it: Performance breakdown across question types (bridge, comp-yn, comp-span) for each GATH ordering

### Open Question 2
- Question: What is the impact of adding question-sentence edges on the model's ability to handle complex inference chains beyond two hops?
- Basis in paper: [explicit] Adds question-sentence edges to complete graph structure; notes this facilitates information transmission
- Why unresolved: Experiments conducted on HotpotQA requiring primarily two-hop reasoning; doesn't explore more complex scenarios
- What evidence would resolve it: Testing on datasets requiring three or more reasoning hops (ComplexWebQuestions, synthetic extensions)

### Open Question 3
- Question: How does GATH's sequential update mechanism compare to attention-weighted hierarchical aggregation methods?
- Basis in paper: [inferred] Positions GATH as novel for NLP but doesn't benchmark against hierarchical attention methods from other domains
- Why unresolved: Paper doesn't compare against methods using weighted aggregation rather than sequential updates
- What evidence would resolve it: Comparative experiments between GATH and hierarchical attention mechanisms with weighted aggregation

## Limitations
- Evaluation limited to HotpotQA distractor setting (10 paragraphs per question)
- Absolute performance gains are modest (1.6-2.4 F1 points for answer span extraction)
- Unclear if improvements transfer to more challenging settings (full wiki, fullwiki) or other multi-hop QA datasets

## Confidence
- **High Confidence**: Core claim that adding query-sentence edges and implementing GATH improve performance over baseline HGN is well-supported
- **Medium Confidence**: Claim that combining improvements yields synergistic effects is supported but marginal (0.1-0.2 F1 points)
- **Low Confidence**: Claim about why sequential hierarchical updates work better than simultaneous updates is primarily intuitive

## Next Checks
1. **Ablation Study**: Remove query-sentence edges and test GATH with original graph structure to quantify exact contribution of each improvement
2. **Generalization Test**: Evaluate combined model on different multi-hop QA dataset (IIRC, ProofWriter) to assess transfer beyond HotpotQA
3. **Efficiency Analysis**: Measure computational overhead of GATH compared to standard GAT to determine if performance gains justify additional complexity
