# Forward-PECVaR Algorithm: Exact Evaluation for CVaR SSPs

## Quick Facts
- arXiv ID: 2303.00672
- Source URL: https://arxiv.org/abs/2303.00672
- Reference count: 18
- Primary result: Exact policy evaluation algorithm for CVaR-SSPs with non-uniform costs

## Executive Summary
This paper introduces Forward-PECVaR (ForPECVaR), an algorithm for exact evaluation of stationary policies in Conditional Value at Risk (CVaR) Stochastic Shortest Path (SSP) problems with non-uniform costs. The method tracks accumulated costs for each trajectory independently from the initial state using a priority queue that expands leaves with the smallest accumulated cost first until reaching goal states. The algorithm enables comparison between approximate solutions from methods like CVaR Value Iteration with Linear Interpolation (CVaRVILI) and CVaR Value Iteration via Quantile Representation (CVaRVIQ), and can also calculate exact VaR values. Experimental results demonstrate that ForPECVaR achieves high accuracy in policy evaluation on Gridworld and River domains, outperforming Monte Carlo simulation within equivalent time constraints.

## Method Summary
ForPECVaR addresses the challenge of exact policy evaluation in CVaR-SSPs by independently tracking all trajectories from the initial state. The algorithm maintains a priority queue of trajectory leaves, expanding those with the smallest accumulated cost first until a goal state is reached. This forward-search approach ensures that the full distribution of accumulated costs is captured for each policy, enabling exact calculation of CVaR and VaR metrics. The method is particularly valuable for validating approximate algorithms like CVaRVILI and CVaRVIQ, providing a ground truth for comparison. By exploring trajectories in order of increasing cost, ForPECVaR efficiently identifies the critical paths that determine CVaR values.

## Key Results
- ForPECVaR achieves exact policy evaluation for CVaR-SSPs with non-uniform costs, outperforming Monte Carlo simulation in accuracy within equivalent time frames
- The algorithm successfully validates approximate solutions from CVaRVILI and CVaRVIQ, showing the importance of appropriate atom selection and alpha0 values smaller than the target alpha
- Experimental results on Gridworld (7x7) and River (5 widths) domains demonstrate the algorithm's effectiveness in calculating both CVaR and exact VaR values for policies

## Why This Works (Mechanism)
ForPECVaR works by exhaustively exploring all possible trajectories from the initial state while maintaining exact cost accumulation for each path. The priority queue ensures that trajectories are expanded in order of increasing cost, which is critical for CVaR computation as it identifies the α-tail of the cost distribution. By tracking each trajectory independently rather than aggregating costs, the algorithm preserves the full distribution needed for exact CVaR calculation. This forward-search approach is particularly effective for SSPs where the cost distribution is non-uniform and the goal is to evaluate the risk-sensitive performance of policies.

Component map: ForPECVaR algorithm with priority queue of trajectory leaves -> cost accumulation tracking -> goal state detection -> CVaR/VaR calculation

Critical path: Initial state -> priority queue initialization -> trajectory expansion (ordered by cost) -> goal state reached -> CVaR/VaR computation

Design tradeoffs: Exact vs. approximate evaluation (exponential complexity vs. bounded error); independent trajectory tracking vs. aggregated approaches; forward-search vs. backward-induction methods

Failure signatures: Incorrect CVaR values when priority queue expansion order is violated; incomplete exploration when queue management fails; inaccurate results with insufficient memory for storing trajectories

## Limitations
- Exponential computational complexity in maximum number of states per trajectory limits scalability to larger problems
- Experimental validation restricted to two domains (7x7 Gridworld and 5-river widths) with limited generalizability
- No runtime comparisons with alternative approximate methods to establish practical efficiency tradeoffs
