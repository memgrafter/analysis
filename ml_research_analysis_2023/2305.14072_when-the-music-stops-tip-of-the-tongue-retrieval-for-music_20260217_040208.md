# When the Music Stops: Tip-of-the-Tongue Retrieval for Music

## Quick Facts
- arXiv ID: 2305.14072
- Source URL: https://arxiv.org/abs/2305.14072
- Reference count: 40
- Primary result: Standard text retrieval performs poorly on tip-of-the-tongue music queries, with LLM reformulations showing limited improvement

## Executive Summary
This study examines the tip-of-the-tongue (ToT) retrieval problem in music, where users struggle to find songs they can't fully recall. The researchers collected a dataset of 2,278 real-world ToT queries from Reddit, each linked to the correct answer in the Wasabi music corpus. They developed a detailed annotation schema revealing that ToT queries often involve uncertainty, multiple modalities (lyrics, audio, video), and false memories. Standard text retrieval approaches performed poorly on these queries, highlighting the difficulty of the task. Experiments with LLM-generated query reformulations showed limited improvement, suggesting the need for novel cross-modal and multi-modal retrieval methods.

## Method Summary
The researchers collected real-world ToT queries from Reddit and linked them to songs in the Wasabi music corpus. They developed a detailed annotation schema to characterize the queries, then tested standard text retrieval using Elasticsearch with BM25 indexing. The study evaluated multiple query formulations including title-only, full text, title+text, keywords extracted with Yake, and LLM-generated reformulations using GPT-3. Retrieval effectiveness was measured using Recall@K metrics on a test set.

## Key Results
- ToT queries are characterized by complexity, verbosity, uncertainty, and possible false memories
- Standard text retrieval approaches perform poorly on these queries
- LLM-generated query reformulations showed limited improvement over baseline methods
- Multi-modal retrieval methods are needed to handle the diverse nature of ToT queries

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Multi-modal retrieval improves performance on tip-of-the-tongue music queries
- Mechanism: Music-ToT queries often reference multiple modalities (lyrics, audio, video). Cross-modal and multi-modal retrieval methods can leverage these complementary signals to improve retrieval accuracy
- Core assumption: The different modalities contain complementary information that, when combined, provides better coverage of the query intent
- Evidence anchors: [abstract] "Music-ToT information needs are characterized by complexity, verbosity, uncertainty, and possible false memories"; [section] "Music-ToT queries are frequently free-form natural language queries...requiring methods that can retrieve audio using text, as well as tags, genre or human-generated descriptions"
- Break condition: If modalities are redundant rather than complementary, or if combining them introduces noise that outweighs benefits

### Mechanism 2
- Claim: Query reformulation can extract more effective search terms from verbose ToT queries
- Mechanism: The LLM reformulates verbose, uncertain queries into more concise versions that focus on musical elements, potentially improving retrieval precision
- Core assumption: LLM reformulations can identify and preserve the most relevant information while removing uncertainty markers and irrelevant details
- Evidence anchors: [abstract] "We investigate the efficacy of query reformulations generated by a large language model (LLM)"; [section] "Lastly, we conduct a preliminary study on reformulating Music-ToT queries using GPT-3...we find that the task remains very challenging"
- Break condition: If the reformulated queries lose critical identifying information or if the LLM introduces hallucinations

### Mechanism 3
- Claim: Specialized indexing of multiple music metadata fields improves retrieval
- Mechanism: Indexing song name, artist name, and lyrics separately using BM25 allows the retrieval system to match different types of query information to appropriate fields
- Core assumption: ToT queries contain different types of information (lyrical content, artist descriptions, song characteristics) that map well to different metadata fields
- Evidence anchors: [section] "We index the Song Name, Artist Name and Lyrics of all songs using Elasticsearch (BM25 with default parameters)"; [section] "Keywords: extracting up to ten keywords from the post text with Yake"
- Break condition: If query patterns don't align with metadata field boundaries or if keyword extraction fails to capture relevant information

## Architecture Onboarding

- Component map: Data collection pipeline: Reddit scraping → post filtering → answer extraction → corpus linking; Annotation pipeline: Schema development → iterative refinement → labeling; Retrieval pipeline: Elasticsearch indexing → query processing → ranking → evaluation; LLM integration: Prompt engineering → generation → evaluation

- Critical path: 1. Data collection and validation (ensure correct answer linking); 2. Annotation and schema validation (ensure high-quality labels); 3. Retrieval pipeline setup (BM25 configuration, indexing); 4. LLM reformulation integration; 5. Evaluation and comparison

- Design tradeoffs: Using open dataset (Wasabi) vs. proprietary (Spotify) for reproducibility; Simple BM25 vs. more complex neural retrieval methods; Manual annotation vs. automated labeling approaches; Single LLM prompt format vs. multiple variants

- Failure signatures: Low recall at K=1000 suggests fundamental retrieval issues; LLM reformulations performing worse than original queries indicates prompt engineering problems; High inter-annotator disagreement (>0.7) suggests unclear schema

- First 3 experiments: 1. Compare BM25 retrieval using title-only vs. title+text vs. keywords on Wasabi corpus; 2. Test different LLM reformulation approaches (varying word limits, different prompts); 3. Evaluate cross-modal retrieval by indexing lyrics separately and testing lyric-only queries

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can cross-modal retrieval methods be effectively integrated to handle Music-ToT queries that reference multiple modalities (audio, lyrics, video, user-created content)?
- Basis in paper: [explicit] The paper identifies that Music-ToT queries frequently involve multiple modalities and cross-modal references, but standard text retrieval approaches perform poorly on these queries
- Why unresolved: Current retrieval methods struggle with the multi-modal nature of Music-ToT queries, and the paper shows that even LLM-generated reformulations have limited success
- What evidence would resolve it: A comparative study of different cross-modal retrieval architectures (e.g., multi-modal embeddings, cross-modal attention mechanisms) on the ToT/Music dataset showing significant improvement over baseline text-only methods

### Open Question 2
- Question: What is the optimal way to handle uncertainty and false memories in Music-ToT queries during the retrieval process?
- Basis in paper: [explicit] The paper highlights that ToT queries are characterized by uncertainty and possible false memories, which make retrieval challenging, but doesn't provide solutions for handling these phenomena
- Why unresolved: The paper demonstrates that uncertainty and false memories are prevalent in Music-ToT queries, but existing retrieval systems don't account for these cognitive phenomena in their ranking or matching algorithms
- What evidence would resolve it: Development and evaluation of retrieval models that explicitly model uncertainty (e.g., probabilistic matching, confidence-weighted scoring) and false memories (e.g., fuzzy matching for misheard lyrics or misremembered details) on the ToT/Music dataset

### Open Question 3
- Question: Can specialized query reformulation techniques outperform general LLM-based reformulations for Music-ToT retrieval?
- Basis in paper: [explicit] The paper investigates LLM-generated query reformulations but finds they are not as effective as using the entire information need as a query, leaving this as an open question
- Why unresolved: While the paper tests generic LLM reformulations, it doesn't explore domain-specific reformulation strategies that could better capture musical elements and handle the unique characteristics of Music-ToT queries
- What evidence would resolve it: Comparative evaluation of domain-specific reformulation approaches (e.g., music-aware keyword extraction, semantic expansion using music knowledge graphs) against the LLM-based methods tested in the paper, showing significant improvement in retrieval effectiveness

## Limitations
- The evaluation relies on a proprietary Reddit-derived dataset with no public release mentioned
- LLM reformulation experiments show limited improvement despite the promise of the approach
- Evaluation only considers exact match retrieval without accounting for semantic similarity

## Confidence
- High confidence: The characterization of ToT queries as complex, verbose, and involving uncertainty is well-supported by the annotation data and qualitative analysis
- Medium confidence: The dataset quality and annotation schema appear robust, though the reliance on Reddit data introduces potential selection bias
- Low confidence: The efficacy of LLM-based query reformulation and the proposed multi-modal retrieval solutions are not well-demonstrated
