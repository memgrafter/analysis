# Do All Languages Cost the Same? Tokenization in the Era of Commercial Language Models

## Quick Facts
- arXiv ID: 2305.13707
- Source URL: https://arxiv.org/abs/2305.13707
- Reference count: 30
- Primary result: Commercial language model APIs exhibit significant cost disparities across languages due to tokenization inefficiencies, with underrepresented language speakers paying more while receiving poorer performance

## Executive Summary
This work investigates fairness in commercial language model API pricing across different languages. The authors find that Byte Pair Encoding tokenization creates language-dependent fragmentation, leading to higher token counts for underrepresented scripts. Through analysis of 22 typologically diverse languages using the FLORES-200 parallel corpus, they demonstrate that languages requiring more tokens to express the same information incur higher API costs and reduced model utility due to limited context windows. The study reveals that these disparities correlate with human development indices, showing that speakers of underrepresented languages often face both higher costs and poorer model performance, raising concerns about equitable access to AI technologies.

## Method Summary
The authors analyze tokenization fairness across 22 languages by computing fragmentation rates using ChatGPT's tokenizer on the FLORES-200 parallel corpus. They evaluate k-shot in-context learning performance across multiple tasks (XNLI, XFACT, XQUAD, CROSSUM, XLSUM) using BLOOMZ API with 1000 token context windows. Cost calculations are based on token counts multiplied by per-token pricing rates. The study examines correlations between fragmentation rates, model performance metrics, and Human Development Index values using statistical analysis. They also conduct controlled experiments with synthetic training data to isolate the effects of language representation versus inherent script properties on tokenization efficiency.

## Key Results
- Latin-script languages require substantially fewer tokens (3-5× less) compared to languages using other scripts like Telugu and Georgian
- Languages with higher fragmentation rates incur up to 5× higher API costs while showing significantly worse model performance
- Fragmentation rates correlate with Human Development Index, indicating socio-economic inequities in AI access
- Limited context windows prevent many languages from fitting sufficient in-context examples, reducing few-shot learning benefits

## Why This Works (Mechanism)

### Mechanism 1
- Claim: BBPE tokenization creates language-dependent fragmentation that increases token counts for underrepresented scripts.
- Mechanism: BBPE builds vocabulary by merging frequent byte pairs; languages with less representation in training data have fewer merged patterns, leading to higher fragmentation.
- Core assumption: Training data distribution directly influences tokenizer efficiency across languages.
- Evidence anchors:
  - [abstract] "What constitutes a token, however, is training data and model dependent with a large variance in the number of tokens required to convey the same information in different languages."
  - [section 4.1] "Latin-script languages are represented with substantially fewer tokens compared to languages in other scripts... languages that have their own script, e.g. Telugu and Georgian, require up to 5× more tokens."
  - [corpus] Weak evidence - neighbor papers don't directly address tokenization variance but discuss API disparities.
- Break condition: When tokenizer vocabulary size is large enough to capture language-specific patterns or when using character-level tokenization.

### Mechanism 2
- Claim: Higher fragmentation leads to increased API costs for underrepresented language speakers.
- Mechanism: APIs charge per token; languages requiring more tokens to express the same information incur higher costs.
- Core assumption: API pricing is uniform across languages regardless of tokenization efficiency.
- Evidence anchors:
  - [abstract] "speakers of a large number of the supported languages are overcharged while obtaining poorer results."
  - [section 4.2] "Languages that are more heavily segmented have predictably higher costs of usage... close to a 5× increase in cost compared to English."
  - [corpus] Weak evidence - no direct corpus support for cost implications.
- Break condition: When APIs implement language-specific pricing or switch to character-based billing.

### Mechanism 3
- Claim: Higher fragmentation reduces model utility by limiting in-context examples.
- Mechanism: Limited context window means fewer in-context examples can fit for highly fragmented languages, reducing performance gains from few-shot learning.
- Core assumption: Model performance improves with more in-context examples.
- Evidence anchors:
  - [abstract] "languages that cost more and perform worse are often associated with populations of speakers for whom the APIs are less affordable."
  - [section 4.3] "Telugu and Amharic struggle to fit even one in-context example for the majority of their test set... we suspect that these languages could also have benefitted from more demonstrations."
  - [corpus] Weak evidence - corpus doesn't directly address in-context learning limitations.
- Break condition: When context windows are expanded or when zero-shot performance is sufficient.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What specific linguistic features or properties of writing scripts beyond data size influence tokenization fragmentation rates?
- Basis in paper: [inferred] The authors demonstrate that even when controlling for content and data size in their BBPE experiments, there remains a disparity in tokenization rates across different scripts, concluding that "uniformity of BBPE tokenizers across languages is not just determined by the proportion of text from language in the pretraining data but also by language/script properties."
- Why unresolved: While the paper identifies that script properties affect fragmentation, it doesn't specify which linguistic features (such as character frequency distributions, morphological complexity, or orthographic conventions) are responsible for the observed disparities.
- What evidence would resolve it: Detailed analysis comparing tokenization rates across scripts while controlling for specific linguistic features like character frequency distributions, morphological complexity, or orthographic conventions would identify which properties drive fragmentation differences.

### Open Question 2
- Question: How does character-based pricing compare to token-based pricing in terms of fairness across languages?
- Basis in paper: [explicit] The authors mention that "A recently released beta of PaLM 2 API, for example, charges the users based on characters" and note that "Prior work has shown evidence that even the number of characters used to express the same information in different languages is variable."
- Why unresolved: The paper acknowledges character-based pricing as a potential alternative but doesn't investigate whether this approach actually reduces cross-linguistic cost disparities compared to token-based pricing.
- What evidence would resolve it: Comparative analysis of API costs across languages using both token-based and character-based pricing models, measuring the reduction in cost disparities and changes in affordability metrics.

### Open Question 3
- Question: How do translationese effects impact the validity of cross-linguistic tokenization comparisons using parallel corpora?
- Basis in paper: [explicit] The authors acknowledge in their limitations section that "translated texts in any language (referred to as translationese) may differ from original written text in many ways" and that they "do not have a way to measure these differences."
- Why unresolved: While the authors use parallel corpora to control for content across languages, they cannot verify whether translationese artifacts introduce systematic differences that confound their tokenization analysis.
- What evidence would resolve it: Comparative analysis of tokenization rates using both parallel (translationese) corpora and original monolingual corpora across the same languages, measuring the extent to which translationese effects influence observed fragmentation patterns.

## Limitations
- Analysis relies on assumptions about ChatGPT's training data distribution being similar to CC100, as OpenAI does not publish tokenizer training details
- Study evaluates only a limited set of commercial APIs (ChatGPT and BLOOMZ) and 22 languages, potentially missing broader patterns
- Socio-economic correlation analysis uses country-level HDI data, which may mask significant within-country disparities in language speaker populations

## Confidence

- **High Confidence**: The mathematical relationship between tokenization, token counts, and API costs is straightforward and well-established. The observation that Latin-script languages generally have lower fragmentation rates than languages using other scripts is empirically robust.
- **Medium Confidence**: The correlation between fragmentation rates and HDI, while statistically significant, may be influenced by confounding factors such as overall internet representation of languages and availability of parallel corpora. The causal mechanism linking fragmentation to reduced in-context learning performance is plausible but requires further experimental validation.
- **Low Confidence**: The extrapolation from current tokenizer behavior to long-term pricing inequities assumes no evolution in commercial API pricing models or tokenizer design practices. The analysis of socio-economic impact depends on multiple intermediate assumptions about adoption rates and economic sensitivity to API costs.

## Next Checks
