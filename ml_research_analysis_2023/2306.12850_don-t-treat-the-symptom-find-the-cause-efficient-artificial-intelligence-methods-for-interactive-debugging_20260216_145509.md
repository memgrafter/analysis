# Don't Treat the Symptom, Find the Cause! Efficient Artificial-Intelligence Methods for (Interactive) Debugging

## Executive Summary
This thesis presents comprehensive research on model-based diagnosis (MBD) and sequential diagnosis, addressing core challenges in fault detection, localization, and repair across various application domains. The work introduces novel methods for optimizing diagnosis computation, including memory-efficient algorithms (RBF-HS, HBF-HS) that reduce memory requirements by up to 99.9% with minimal runtime overhead, and DynamicHS which achieves up to 75% runtime savings in sequential diagnosis by reusing search trees.

## Method Summary
The research develops multiple algorithmic approaches for model-based diagnosis, including RBF-HS and HBF-HS for memory-efficient diagnosis computation, DynamicHS for runtime optimization through search tree reuse, and StaticHS for generalized sequential diagnosis. The work also presents systematic search techniques for query computation, achieving high query optimality while exploring minimal query spaces. User studies validate the effectiveness of query-based debugging approaches, and OntoDebug provides a full-fledged ontology debugging tool with significant adoption.

## Key Results
- Memory-efficient algorithms (RBF-HS, HBF-HS) reduce memory requirements by up to 99.9% with minimal runtime overhead
- DynamicHS achieves up to 75% runtime savings in sequential diagnosis by reusing search trees
- StaticHS demonstrates 20-65% reduction in oracle queries compared to standard approaches

## Why This Works (Mechanism)
The proposed methods work by systematically optimizing the search and computation processes in model-based diagnosis. Memory-efficient algorithms restructure the search space to minimize storage requirements while maintaining solution quality. Runtime optimizations leverage previously computed search trees to avoid redundant computations in sequential diagnosis. Query selection techniques balance exploration and exploitation to achieve near-optimal query sets with minimal search overhead.

## Foundational Learning
- Model-based diagnosis: Why needed - provides formal framework for fault detection; Quick check - can represent system behavior and constraints
- Sequential diagnosis: Why needed - enables iterative refinement of diagnoses; Quick check - can handle partial information queries
- Query optimization: Why needed - reduces user effort in interactive debugging; Quick check - can minimize query count while maintaining diagnostic accuracy
- Search tree reuse: Why needed - eliminates redundant computation; Quick check - can store and reuse partial search results
- Memory-efficient data structures: Why needed - enables handling larger problem instances; Quick check - can maintain solution quality with reduced memory

## Architecture Onboarding

**Component Map**: MBD System -> Diagnosis Engine -> Query Generator -> User Interface -> Feedback Loop

**Critical Path**: User Query -> Diagnosis Engine (RBF-HS/HBF-HS) -> Search Tree Construction -> Query Selection -> User Feedback -> Diagnosis Refinement

**Design Tradeoffs**: Memory vs Runtime (RBF-HS trades memory for speed), Query Optimality vs Search Space (systematic search explores minimal space for high optimality), User Effort vs Diagnostic Accuracy (query-based approaches reduce effort while maintaining quality)

**Failure Signatures**: Memory overflow (insufficient memory-efficient algorithms), Slow response times (inadequate search tree reuse), Suboptimal queries (incomplete search space exploration), User confusion (poor query selection or presentation)

## Limitations
- Evaluation primarily focuses on benchmark problems and controlled user studies, may not capture real-world complexities
- Memory efficiency improvements require validation across diverse problem domains beyond those tested
- User study results may not generalize to all user populations or application contexts

## Confidence
- Memory-efficient algorithms (RBF-HS, HBF-HS): High confidence based on systematic benchmarking
- DynamicHS runtime savings: Medium confidence requiring cross-domain validation
- User study results: Medium confidence limited by sample size and controlled conditions
- Query optimality claims: High confidence for tested problem spaces, uncertain for larger domains
