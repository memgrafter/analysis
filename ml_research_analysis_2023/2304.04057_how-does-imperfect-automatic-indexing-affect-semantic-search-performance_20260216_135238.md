# How Does Imperfect Automatic Indexing Affect Semantic Search Performance?

## Quick Facts
- arXiv ID: 2304.04057
- Source URL: https://arxiv.org/abs/2304.04057
- Reference count: 40
- Key outcome: Probabilistic logic handles imperfect indexing better than Boolean logic; query performance limited by worst-performing terms; hybrid human-machine indexing regains excellent performance

## Executive Summary
This paper investigates how imperfect automatic indexing affects semantic search performance using Medical Subject Heading (MeSH) terms and biomedical literature search as a case study. The authors compare traditional Boolean logic with probabilistic logic for combining term predictions and evaluate multiple indexing approaches including logistic regression and BERT classifiers. Their key finding is that probabilistic logic can better handle inaccurately assigned terms than traditional Boolean logic, and that query-level performance is mostly limited by the lowest-performing terms in a query. The paper demonstrates that mixing a small amount of human indexing with automatic indexing can regain excellent query-level performance while significantly reducing human effort.

## Method Summary
The study uses the BioASQ 2021 Task A dataset (15,559,157 PubMed articles with MeSH annotations) and evaluates multiple indexing approaches including binary (thresholded probabilities) and probabilistic (raw probabilities) methods using both logistic regression and BERT classifiers. The authors train classifiers on document-term relationships and evaluate performance using standard information retrieval metrics including precision, recall, F1-score, MAP, and P@10/P@50/R@1000. They compare automatic indexing results against manual indexing ground truth and analyze which terms limit query performance. The study uses 27 Boolean queries from three sources (CLEF-TAR 2019, Systematic Review Update Dataset, and PubMed COVID-19 article filters) filtered for MeSH-only queries with at least 50 relevant documents.

## Key Results
- Probabilistic logic outperforms Boolean logic in handling term uncertainty by preserving probability information throughout the query evaluation process
- Query-level performance is primarily limited by the worst-performing terms in a query, creating a "bucket effect" where all terms must perform well for high overall performance
- Mixing automatic indexing for high-performing terms (≥80% F1) with human indexing for low-performing rare terms can achieve performance approaching fully manual indexing

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Probabilistic logic outperforms Boolean logic in handling term uncertainty
- Mechanism: When indexing algorithms output probabilities rather than binary labels, the uncertainty of term assignments is preserved. Probabilistic logic (product t-norm) combines these probabilities in a way that better reflects the likelihood of document relevance than Boolean logic's all-or-nothing approach
- Core assumption: Document relevance can be meaningfully represented as a probability that increases monotonically with the probability of individual term matches
- Evidence anchors:
  - [abstract]: "probabilistic logic can handle inaccurately assigned terms better than traditional Boolean logic"
  - [section III-E]: "For a probability indexing algorithm that gives a probability vector p, we can use the probabilistic version of the Boolean function to estimate the probability that d is relevant to q"

### Mechanism 2
- Claim: Query-level performance is limited by the worst-performing terms in the query
- Mechanism: The performance of a Boolean query depends on the logical combination of its constituent terms. When terms are combined with AND, a single low-performing term creates a bottleneck
- Core assumption: Term performance distributions are not uniform, and rare terms tend to have lower performance due to insufficient training data
- Evidence anchors:
  - [abstract]: "query-level performance is mostly limited by lowest-performing terms in a query"
  - [section IV-B]: "the recall on a query is restricted by the worst-performing MeSH term indexers of MeSH terms in the query"
  - [corpus]: Weak - related papers don't explicitly discuss performance bottlenecks from worst-performing terms

### Mechanism 3
- Claim: Mixing human and machine indexing achieves high performance with minimal human effort
- Mechanism: By using automatic indexing for terms with high predictive performance (≥80% F1) and manual indexing only for low-performing rare terms, overall query performance can approach that of fully manual indexing while significantly reducing human workload
- Core assumption: Rare terms that are challenging for machine learning models are also the ones most critical for maintaining high query performance
- Evidence anchors:
  - [abstract]: "mixing a small amount of human indexing with automatic indexing can regain excellent query-level performance"

## Architecture Onboarding

- Component map: Document corpus with manual MeSH annotations -> Two indexing approaches (binary, probabilistic) -> Two base classifiers (Logistic Regression, BERT) -> Evaluation pipeline comparing against ground truth -> Query analysis module correlating term-level and query-level performance

- Critical path:
  1. Train indexing classifiers on document corpus
  2. Apply classifiers to test documents to get term predictions
  3. Combine term predictions using Boolean or probabilistic logic for each query
  4. Compare retrieved documents against ground truth to calculate performance metrics
  5. Analyze which terms limit query performance

- Design tradeoffs:
  - Binary vs probabilistic indexing: binary is simpler but loses uncertainty information; probabilistic preserves uncertainty but requires more complex evaluation logic
  - LR vs BERT classifiers: LR is faster and more interpretable; BERT captures more complex patterns but requires more computational resources
  - End-to-end vs component-wise training: end-to-end optimizes for query performance directly but is less flexible; component-wise allows separate optimization but may not capture query-level interactions

- Failure signatures:
  - Poor precision: automatic indexing is assigning terms too liberally
  - Poor recall: automatic indexing is missing relevant terms, likely rare ones
  - Disproportionate impact of certain queries: those queries contain terms with particularly poor predictive performance
  - No significant difference between binary and probabilistic approaches: term predictions may already be too certain

- First 3 experiments:
  1. Run both binary and probabilistic indexing with the same base classifier on a small query set and compare precision-recall curves
  2. For each query, identify the term with lowest F1 score and test how performance changes when that term is replaced with ground truth
  3. Vary the threshold for automatic vs manual term assignment (e.g., 0.65 vs 0.8 F1) and measure the tradeoff between performance and human effort

## Limitations
- Results may not generalize beyond the biomedical domain and MeSH indexing task
- The computational resources required for BERT-based approaches may limit practical applicability for large-scale indexing tasks
- The study relies on a single dataset (BioASQ 2021 Task A) and specific query types (Boolean queries with MeSH terms)

## Confidence
- High confidence: Probabilistic logic outperforming Boolean logic in handling term uncertainty
- Medium confidence: Query-level performance being limited by worst-performing terms
- Medium confidence: Hybrid human-machine indexing strategy effectiveness

## Next Checks
1. Test the probabilistic vs Boolean logic comparison on a different domain (e.g., legal or news documents) to assess generalizability of the performance improvement
2. Experiment with different query structures (OR combinations, ranked retrieval scenarios) to determine if the "worst term bottleneck" persists across query types
3. Conduct a cost-benefit analysis of the hybrid indexing approach using actual human indexing costs to determine the optimal threshold for automatic vs manual term assignment
