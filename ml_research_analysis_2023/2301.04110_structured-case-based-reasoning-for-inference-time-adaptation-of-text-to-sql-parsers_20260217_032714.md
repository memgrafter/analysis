# Structured Case-based Reasoning for Inference-time Adaptation of Text-to-SQL parsers

## Quick Facts
- arXiv ID: 2301.04110
- Source URL: https://arxiv.org/abs/2301.04110
- Reference count: 15
- Key outcome: StructCBR enables inference-time adaptation of Text-to-SQL models without fine-tuning, achieving up to 6.3 points improvement in Exact Match and Execution Accuracy across five databases.

## Executive Summary
This paper introduces StructCBR, a structured case-based reasoning approach for adapting Text-to-SQL parsers to unseen schemas at inference time without requiring fine-tuning. The method leverages subtree-level similarity between candidate SQL trees and case examples stored in a learned memory to improve parsing accuracy. Compared to baseline methods, StructCBR demonstrates consistent improvements across five different databases while providing up to 500× faster adaptation than traditional fine-tuning approaches.

## Method Summary
StructCBR adapts Text-to-SQL parsers to new schemas by storing subtree representations from case examples in a learned memory. During inference, it computes compositional similarity between candidate SQL sub-trees and case memory entries to boost candidate scores. The method trains a base SmBoP model on the Spider dataset, then trains a StructCBR module (2.53% additional parameters) on the same data. At inference, case examples are used to compute similarity scores that are combined with SmBoP scores to rank and select the best candidate SQL query.

## Key Results
- StructCBR improves Exact Match (EM) by 2.2 points and Execution Accuracy (EX) by 1.9 points on average across five databases
- Achieves up to 6.3 points improvement in both EM and EX metrics compared to baseline methods
- Provides 20% to 83% of the EM gains achieved by fine-tuning for 100 epochs, but at significantly faster speed
- Outperforms baseline methods (ConcatCBR, GTM, SCoRe) in both accuracy and adaptation efficiency

## Why This Works (Mechanism)

### Mechanism 1
- Claim: StructCBR leverages subtree-level similarity between logical forms of cases and candidate outputs to improve parsing accuracy without fine-tuning.
- Mechanism: By comparing sub-trees in candidate SQL outputs with those in the case memory, StructCBR identifies structurally similar and contextually relevant sub-trees. These similarities boost the scores of likely-correct candidates during inference, improving parsing accuracy.
- Core assumption: The structural similarity between sub-trees in the candidate SQL and case examples, when contextualized appropriately, is indicative of the correctness of the candidate SQL.
- Evidence anchors:
  - [abstract] "StructCBR, a structured case-based reasoning approach, which leverages subtree-level similarity between logical forms of cases and candidate outputs, resulting in better decoder decisions."
  - [section 3.3] "Our key idea is to compute the similarity between two trees compositionally as a function of similarity between their left and right children respectively."
- Break condition: If the subtree similarity does not accurately reflect the contextual relevance or structural correctness, the method's effectiveness diminishes.

### Mechanism 2
- Claim: StructCBR provides faster adaptation compared to fine-tuning by avoiding parameter updates.
- Mechanism: Instead of updating model parameters, StructCBR uses a case memory to store subtree representations and computes similarity scores to boost candidate tree scores during inference. This avoids the computational cost of fine-tuning.
- Core assumption: The computational overhead of memory look-ups and similarity computations is significantly lower than the cost of fine-tuning model parameters.
- Evidence anchors:
  - [abstract] "StructCBR enables inference-time adaptation of Text-to-SQL models without fine-tuning... It also provides faster adaptation (up to 500×) compared to fine-tuning."
  - [section 5] "StructCBR instantly obtains 20% to 83% EM gains achieved by fine-tuning for 100 epochs across different schemas."
- Break condition: If the case memory becomes too large or the similarity computations become too complex, the speed advantage may be reduced.

### Mechanism 3
- Claim: StructCBR's compositional subtree similarity function is more efficient than default whole-tree embeddings for scoring large search frontiers.
- Mechanism: By computing tree similarity as a function of the similarity between child sub-trees, StructCBR reduces the computational complexity from O(K^2) to O(K), where K is the beam size.
- Core assumption: The compositional similarity function accurately captures the essential similarities between trees without needing to compute the similarity for every possible pair of sub-trees.
- Evidence anchors:
  - [section 3.3] "Our key idea is to compute the similarity between two trees compositionally as a function of similarity between their left and right children respectively."
  - [section 5] "Efﬁciently scoring the entire frontier provides us better results on 4 out 5 schemas and a micro-averaged gain of 2.2 points in EM."
- Break condition: If the compositional similarity function fails to capture important structural differences between trees, the efficiency gains may come at the cost of accuracy.

## Architecture Onboarding

- Component map:
  - Encoder -> Decoder (SmBoP) -> Case Memory -> Similarity Module -> Score Booster -> Output
- Critical path:
  1. Encode input text and schema
  2. Generate candidate SQL trees using SmBoP
  3. Compute subtree similarities with case memory
  4. Boost candidate scores based on similarities
  5. Output the highest-scoring SQL tree
- Design tradeoffs:
  - Speed vs. Accuracy: Faster adaptation without fine-tuning may sacrifice some accuracy compared to fine-tuning
  - Memory vs. Efficiency: Storing subtree representations requires memory but enables efficient similarity computations
  - Complexity vs. Simplicity: Compositional similarity reduces complexity but may miss some nuanced differences between trees
- Failure signatures:
  - Incorrect SQL output: Indicates issues with subtree similarity computations or case memory relevance
  - Slow inference: Suggests inefficiencies in similarity computations or memory look-ups
  - Inconsistent gains: Points to problems with the compositional similarity function or case selection
- First 3 experiments:
  1. Compare StructCBR's accuracy with and without case memory on a small dataset
  2. Measure inference time with and without compositional similarity to validate efficiency gains
  3. Test StructCBR on a dataset with varying schema complexities to assess generalization

## Limitations
- StructCBR's performance heavily depends on the quality and relevance of case examples in memory
- The paper does not explore scaling to significantly larger and more complex schemas
- The 500× speedup claim is based on fixed epoch comparisons rather than wall-clock time measurements

## Confidence
- Mechanism 1 (Subtree similarity boosting): Medium - supported by compositional similarity design but dependent on case quality
- Mechanism 2 (Faster adaptation): Medium - theoretically sound but practical speedup needs verification
- Mechanism 3 (Efficient scoring): High - efficiency gains are mathematically derived and empirically validated
