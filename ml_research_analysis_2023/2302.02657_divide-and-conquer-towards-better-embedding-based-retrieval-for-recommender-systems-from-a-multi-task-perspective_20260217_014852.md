# Divide and Conquer: Towards Better Embedding-based Retrieval for Recommender Systems From a Multi-task Perspective

## Quick Facts
- **arXiv ID:** 2302.02657
- **Source URL:** https://arxiv.org/abs/2302.02657
- **Reference count:** 27
- **Key outcome:** Embedding-based retrieval (EBR) for recommender systems that improves Recall by up to 40% and significantly boosts user engagement metrics through divide-and-conquer clustering and prompt-based task adaptation

## Executive Summary
This paper addresses critical challenges in embedding-based retrieval (EBR) for recommender systems: distinguishing highly relevant items from both easy negatives (irrelevant items) and hard negatives (somewhat related items), while maintaining diversity and fairness in retrieval results. The authors propose a divide-and-conquer approach that partitions the candidate item set into semantically relevant clusters and performs EBR within each cluster in parallel, then merges results with controllable strategies. Additionally, they introduce an efficient task adaptation technique inspired by prompt-tuning to boost retrieval performance within each cluster with negligible overhead. Extensive experiments show significant improvements in Recall (up to 40%) and online A/B tests demonstrate substantial gains in key user engagement metrics.

## Method Summary
The method employs a divide-and-conquer approach where items are first clustered into semantically relevant groups using K-means or in-house categories. An EBR model is then trained and applied within each cluster, focusing on discriminating positives from mostly hard negatives by eliminating easy negatives from irrelevant clusters. To further enhance performance, the paper introduces a prompt-like multi-task learning adaptation that adds task-specific embeddings for each cluster, which interact with user behavior embeddings via Hadamard product before being fed into the Transformer. The final candidate set is constructed by merging top items from each cluster using a user-intent model that predicts cluster relevance probabilities, with a tunable hyperparameter controlling the fairness vs. relevance tradeoff.

## Key Results
- Significant improvements in Recall metrics, with up to 40% increase in offline experiments
- Online A/B tests demonstrate substantial gains in key user engagement metrics including App Usage Time, Likes, Follows, Shares, and Downloads
- The divide-and-conquer approach enables more efficient fine-tuning on each task with a unified model architecture
- Controllable merging strategies allow customization of retrieval results for different fairness and diversity requirements

- Mechanism: The divide-and-conquer approach clusters the candidate item set (e.g., using K-means or semantic categories). Within each cluster, the EBR model is trained and applied to retrieve items only from that cluster. This removes easy negatives from irrelevant clusters, concentrating the training and retrieval task on harder negatives within the same cluster.
- Core assumption: Items within the same cluster are mostly relevant to each other, so negatives from the same cluster are predominantly hard negatives.

## Architecture Onboarding

- Component map:
  - User encoder: Transformer-based model (e.g., SASRec) that encodes user behavior sequences into embeddings
  - Item encoder: Transformer-based model that encodes item features into embeddings
  - Clustering module: Assigns items to clusters (e.g., using K-means or semantic categories)
  - Prompt-like MTL: Adds task-specific embeddings for each cluster, interacts with user embeddings via Hadamard product
  - ANN index: Pre-computed item embeddings indexed for efficient retrieval
  - Merging strategy: Combines top items from each cluster based on user-intent model predictions

- Critical path:
  1. Cluster items offline
  2. Train user and item encoders with prompt-like MTL
  3. Pre-compute and index item embeddings
  4. At serving, encode user, retrieve top items from each cluster, merge results

- Design tradeoffs:
  - Cluster granularity: More clusters reduce the number of candidates per cluster but increase the number of retrieval runs and merging complexity
  - Prompt embedding size: Larger embeddings may capture more task-specific information but increase computational cost
  - Merging strategy: Tighter control over fairness vs. relevance by tuning the merging hyperparameter

- Failure signatures:
  - Poor retrieval performance: May indicate ineffective clustering or insufficient task adaptation
  - High latency: May indicate too many clusters or inefficient merging
  - Low diversity: May indicate overly aggressive merging or inaccurate user-intent model

- First 3 experiments:
  1. Verify clustering quality: Check if items within clusters are semantically similar
  2. Compare retrieval performance with and without prompt-like MTL: Measure Recall@20, Recall@50
  3. Test merging strategy: Vary the fairness vs. relevance tradeoff hyperparameter and measure diversity metrics

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How should we optimally cluster items for divide-and-conquer EBR? The paper uses K-means clustering of item embeddings and in-house video categories, but these are heuristic choices.
- Basis in paper: [explicit] "Note that clustering criteria can be chosen according to different application scenarios. Our offline experiments show that K-means [17] clustering of item embeddings trained by Word2Vec [19] can be a decent default option. In our production system, we use our in-house video categories..."
- Why unresolved: The paper only demonstrates that certain clustering methods work, but doesn't explore the space of possible clustering criteria or evaluate what makes an optimal clustering for this application.
- What evidence would resolve it: Systematic evaluation of different clustering methods (content-based, collaborative filtering-based, hybrid approaches) and their impact on EBR performance across multiple datasets and domains.

### Open Question 2
- Question: What is the optimal merging strategy for combining results from different clusters, and how should it adapt to different fairness/diversity requirements?
- Basis in paper: [explicit] "Once the top scored items from each cluster are obtained, we can assign adequate quotas to each cluster to meet customized requirements for the final retrieval results... suppose we want to generate a final candidate set of size 𝑀. We can train a user-intent model using the same features as the user encoder and predict the probability 𝑝𝑢𝑘 that the relevant items to user 𝑢 are likely to fall into cluster C𝑘. Then, we combine the top-𝑀𝑘 items from each cluster as the final results..."
- Why unresolved: The paper presents a quota-based merging strategy with tunable hyperparameters, but doesn't explore the design space of merging strategies or analyze their trade-offs in terms of fairness, diversity, and relevance.
- What evidence would resolve it: Comparative analysis of different merging strategies (quota-based, diversity-aware, fairness-constrained) with systematic evaluation of their impact on user engagement metrics and fairness/diversity measures.

### Open Question 3
- Question: How can we scale the divide-and-conquer approach to extremely large numbers of clusters while maintaining efficiency?
- Basis in paper: [inferred] The paper mentions that "Because EBR can be run on different clusters of items in parallel and the search space of each run is approximately 𝐾 times smaller, this divide-and-conquer procedure does not significantly increase the response latency." However, this assumes 𝐾 is moderate.
- Why unresolved: The paper doesn't address the computational and memory challenges that arise when 𝐾 becomes very large (e.g., thousands of clusters), which would be necessary for fine-grained item categorization.
- What evidence would resolve it: Performance analysis of the divide-and-conquer approach with increasing numbers of clusters, including latency measurements, memory usage, and accuracy degradation points, along with proposed solutions for scaling to large 𝐾.

## Limitations

- The clustering mechanism's effectiveness depends heavily on the semantic quality of clusters, but the paper does not specify the clustering algorithm or evaluation criteria used
- The prompt-tuning adaptation, while theoretically sound, lacks detailed implementation specifications that would enable precise replication
- Online A/B test results show significant improvements but the duration and scale of these tests are not disclosed, limiting generalizability

## Confidence

- **High confidence** in the fundamental insight that reducing easy negatives through clustering improves EBR discrimination
- **Medium confidence** in the prompt-based task adaptation technique's efficiency claims
- **Medium confidence** in the merging strategy's ability to balance diversity and relevance
