# In all LikelihoodS: How to Reliably Select Pseudo-Labeled Data for Self-Training in Semi-Supervised Learning

## Quick Facts
- **arXiv ID**: 2303.01117
- **Source URL**: https://arxiv.org/abs/2303.01117

## Executive Summary
This paper addresses the challenge of reliable pseudo-label selection in self-training semi-supervised learning. Traditional methods using single models are sensitive to modeling assumptions and accumulate errors, leading to covariate shift. The authors propose robust selection criteria that account for multiple sources of uncertainty, including model selection, error accumulation, and covariate shift. The methods leverage multi-objective utility functions across multiple models and 𝛼-cut updating rules for credal sets, demonstrating improved accuracy on both simulated and real-world datasets.

## Method Summary
The method involves fitting multiple parametric models to labeled data, computing likelihood utilities for unlabeled data points under each model, and applying robust selection criteria. The robust PLS criteria include multi-model utility functions that aggregate likelihood utilities across models, 𝛼-cut updating rules that dynamically adjust credal sets based on prediction confidence, and nested model hierarchies that prevent overfitting by favoring simpler models. The process iteratively adds selected pseudo-labeled data to the training set, improving model performance while maintaining robustness to uncertainty.

## Key Results
- Multi-model utility selection prevents error accumulation by avoiding overreliance on single model predictions
- 𝛼-cut updating rules provide adaptive robustness by dynamically adjusting credal sets based on pseudo-label confidence
- Reversing Occam's razor through nested model hierarchies prevents overfitting to complex models

## Architecture Onboarding

- Component map: Data preprocessing -> Model fitting -> Utility computation -> Selection criteria -> Output
- Critical path:
  1. Fit multiple models to labeled data
  2. Compute likelihood utilities for each unlabeled data point under each model
  3. Apply 𝛼-cut updating or multi-model thresholding
  4. Select pseudo-labeled data points that pass the criteria
  5. Add selected data to training set and repeat

- Design tradeoffs:
  - Computational cost vs. robustness: Using more models increases robustness but also computation
  - Model complexity vs. overfitting: Simpler models are less likely to overfit but may miss important patterns
  - Threshold sensitivity: The choice of 𝛼 affects the balance between inclusion and exclusion of pseudo-labels

- Failure signatures:
  - Poor performance: Check if all models in the ensemble are similarly misspecified
  - Computational issues: Check if the number of models is too large or if the likelihood computations are intractable
  - Convergence problems: Check if the 𝛼-cut thresholds are too restrictive or too permissive

- First 3 experiments:
  1. Implement the basic multi-model utility function and compare it to single-model selection on a simple synthetic dataset
  2. Add 𝛼-cut updating and test its effect on robustness to noisy pseudo-labels
  3. Implement the nested model hierarchy and test its ability to prevent overfitting to complex models

## Limitations

- Reliance on multiple parametric models assumes at least one model captures relevant data structure, which may not hold for complex real-world datasets
- The 𝛼-cut updating mechanism depends heavily on accurate prediction confidence estimates, which can be problematic with poorly calibrated models
- Computational complexity scales with the number of models and data points, potentially limiting scalability

## Confidence

- **High Confidence**: The theoretical framework for robust PLS using credal sets and decision theory is well-established
- **Medium Confidence**: The effectiveness of multi-model utility selection is supported by experimental results, but the improvements vary significantly across datasets
- **Low Confidence**: The specific parameter choices for 𝛼-cuts and model weights are not fully specified, making exact replication challenging
