# A general-purpose AI assistant embedded in an open-source radiology information system

## Quick Facts
- arXiv ID: 2303.10338
- Source URL: https://arxiv.org/abs/2303.10338
- Reference count: 28
- Primary result: AI model service integrated into LibreHealth RIS enables real-time human-AI collaboration with swarm learning and few-shot retraining

## Executive Summary
This paper presents an architecture for integrating AI model services into the LibreHealth Radiology Information System to enable real-time human-AI collaboration. The system uses DICOM-SR annotations for overlaying AI results on medical images, allows radiologists to correct model outputs, and employs few-shot learning and swarm learning to continuously retrain personalized models. The implementation demonstrates how AI can be seamlessly embedded into clinical workflows while maintaining radiologist control and improving model accuracy through continuous feedback.

## Method Summary
The method involves integrating an AI model service into LibreHealth RIS using REST API communication for inference and training. DICOM-SR annotations are used to overlay AI results on original images without modification, allowing radiologists to enable/disable annotations and provide corrections. Few-shot learning retrains models using radiologist feedback through image triplets, while swarm learning shares model weights across radiologists to reduce bias and maintain personalization. The system was demonstrated using CheXNet for chest X-ray analysis with OHIF viewer for display and Orthanc PACS for image storage.

## Key Results
- Swarm learning enables model personalization while reducing bias through collaborative weight sharing
- Few-shot learning allows rapid model retraining with minimal annotated data from radiologist corrections
- DICOM-SR standard enables seamless human-AI collaboration without modifying original images

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Swarm learning enables model personalization while reducing bias through collaborative weight sharing.
- Mechanism: Each radiologist trains a personalized model on their annotations, then model weights are shared across the swarm network and merged using ensemble techniques to create updated models.
- Core assumption: Weight sharing maintains model performance while averaging out individual radiologist biases.
- Evidence anchors:
  - [abstract] "The weights of these user-specific models are then finally shared between multiple models in a swarm learning approach."
  - [section] "Swarm learning is utilised in the AI Model Service where models are built independently on private data for each individual radiologist."
  - [corpus] Weak - no direct corpus evidence about swarm learning effectiveness in radiology.
- Break condition: If weight sharing introduces systematic errors from dominant model patterns or if radiologist annotations are too heterogeneous to merge effectively.

### Mechanism 2
- Claim: Few-shot learning enables rapid model retraining with minimal annotated data.
- Mechanism: When radiologists correct model outputs, these corrections are batched and used to retrain models using image triplets (false positive/negative, true positive, true negative) with few epochs.
- Core assumption: Limited training samples with proper triplet selection can meaningfully improve model performance without overfitting.
- Evidence anchors:
  - [abstract] "use few-shot learning and swarm learning approaches to retrain the AI models continuously."
  - [section] "we use few-shot learning, a process of using limited newly labeled images or new labels on existing images, to adjust model weights to these new training set."
  - [corpus] Weak - no direct corpus evidence about few-shot learning implementation details.
- Break condition: If the few available correction samples are insufficient to overcome model bias or if triplet selection fails to capture meaningful error patterns.

### Mechanism 3
- Claim: DICOM-SR standard enables seamless human-AI collaboration without modifying original images.
- Mechanism: Annotations are stored as overlay layers on original images, allowing radiologists to enable/disable AI annotations and relabel them while preserving image integrity.
- Core assumption: DICOM-SR annotations can be reliably stored, retrieved, and displayed without data corruption or loss.
- Evidence anchors:
  - [section] "DICOM -SR provides a standard way to annotate findings by radiologists when they interpret studies. These annotations are stored in their own layer that is overlayed over the original image, without any modifications to the original image."
  - [section] "Our custom extension along with core extensions from OHIF that are useful for measurement tasks are installed."
  - [corpus] Weak - no direct corpus evidence about DICOM-SR implementation challenges.
- Break condition: If DICOM-SR storage or retrieval fails, or if overlay rendering causes performance issues in the viewer.

## Architecture Onboarding

- Component map:
  - LibreHealth RIS (OMOD) -> Orthanc PACS -> OHIF Viewer -> AI Model Service -> MySQL Database

- Critical path: Image acquisition → Orthanc PACS → LH-RIS study list → OHIF viewer → AI model service → Display results → Radiologist correction → Few-shot retraining → Swarm weight sharing

- Design tradeoffs: Modular AI service allows multiple model support but adds network latency; swarm learning reduces bias but requires reliable weight sharing; few-shot learning enables rapid updates but risks overfitting with limited data.

- Failure signatures: AI inference delays indicate model service bottlenecks; missing annotations suggest DICOM-SR integration issues; model degradation after corrections points to few-shot learning problems; inconsistent results across radiologists indicate swarm learning failures.

- First 3 experiments:
  1. Deploy single AI model (CheXNet) with basic inference only, verify OHIF viewer displays results correctly.
  2. Enable radiologist annotation correction workflow, test few-shot learning retraining with synthetic corrections.
  3. Implement swarm learning with two radiologist models, verify weight sharing and performance improvement.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal frequency for retraining AI models in real-world clinical settings to balance accuracy and computational resources?
- Basis in paper: [explicit] The paper mentions retraining is planned as a batch procedure and discusses few-shot learning for rapid model retraining, but does not specify optimal retraining frequency.
- Why unresolved: The paper demonstrates the technical feasibility of continuous learning but lacks empirical data on how often retraining should occur in practice.
- What evidence would resolve it: Clinical studies comparing model performance at different retraining intervals (daily, weekly, monthly) in real-world radiology departments.

### Open Question 2
- Question: How does swarm learning affect model performance when radiologists have varying levels of expertise or different diagnostic patterns?
- Basis in paper: [explicit] The paper describes swarm learning to share model weights across radiologists but acknowledges this may aggregate errors made regularly by individual radiologists.
- Why unresolved: The paper presents the concept theoretically but lacks empirical validation of swarm learning's effectiveness across diverse radiologist populations.
- What evidence would resolve it: Comparative studies of swarm-learned models versus individually-trained models across radiologists with different experience levels and subspecialties.

### Open Question 3
- Question: What is the optimal balance between AI assistance and radiologist autonomy to maximize diagnostic accuracy without causing overreliance on AI?
- Basis in paper: [inferred] The paper discusses enabling/disabling AI annotations and building human-AI partnerships, but doesn't address potential overreliance issues.
- Why unresolved: While the system allows customization, the paper doesn't explore the psychological or workflow impacts of varying levels of AI assistance.
- What evidence would resolve it: Randomized controlled trials comparing diagnostic accuracy and radiologist satisfaction at different AI assistance levels in clinical practice.

## Limitations
- Swarm learning implementation details remain underspecified, with no clear explanation of how model weights are aggregated across radiologists
- Few-shot learning relies on potentially sparse radiologist corrections that may be insufficient for meaningful model retraining
- DICOM-SR annotation handling lacks implementation specifics that could impact real-world deployment

## Confidence

**Low Confidence**: The quantitative claims about bias reduction and performance improvement through swarm learning are not supported by empirical results
