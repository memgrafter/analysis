# Recursive Euclidean Distance Based Robust Aggregation Technique For Federated Learning

## Quick Facts
- arXiv ID: 2303.11337
- Source URL: https://arxiv.org/abs/2303.11337
- Reference count: 13
- Achieved 98.27% accuracy and 1.20% attack success rate against label-flipping attacks on MNIST

## Executive Summary
This paper proposes a robust aggregation algorithm for federated learning that defends against label-flipping and backdoor poisoning attacks by assigning weights to local models based on their Euclidean distance from the current global model. Models with larger distances receive lower weights, reducing the influence of potentially poisoned models during aggregation. The approach is evaluated on MNIST with 100 clients and 10 attackers, showing superior performance compared to a residual-based reweighting method in terms of accuracy, attack success rate, and aggregation time.

## Method Summary
The proposed algorithm calculates Euclidean distances between each client's local model parameters and the current global model during each aggregation round. These distances are used to compute inverse-distance weights for each client's model, with more distant models receiving smaller weights. The global model is then updated by weighted averaging of all local models. This recursive approach adapts to evolving model parameters and aims to minimize the impact of data poisoning by downweighting models that deviate significantly from the global consensus.

## Key Results
- Achieved 98.27% accuracy compared to 91.44% for residual-based reweighting method
- Reduced attack success rate to 1.20% from 1.86% for baseline method
- Decreased aggregation time to 0.028s from 0.038s for residual-based approach

## Architecture Onboarding

- Component map:
  Client layer -> Server layer -> Communication layer

- Critical path:
  1. Clients train local models on private data
  2. Clients send model parameters to server
  3. Server calculates Euclidean distances from current global model
  4. Server assigns weights based on inverse distances
  5. Server aggregates weighted models to update global model
  6. Server broadcasts updated global model to clients

- Design tradeoffs:
  - Accuracy vs. computational overhead: The distance calculations add O(n) complexity per round
  - Robustness vs. false positives: Aggressive distance thresholding may downweight legitimate heterogeneous models
  - Communication efficiency vs. security: More frequent aggregation rounds increase security but also communication costs

- Failure signatures:
  - If the algorithm fails to converge or shows oscillating accuracy, it may indicate incorrect distance scaling
  - If benign models are consistently downweighted, it suggests the distance threshold is too sensitive
  - If attack success rates remain high, the distance metric may not effectively distinguish malicious from benign models

- First 3 experiments:
  1. Baseline test: Run FedAvg and proposed algorithm without attacks to verify accuracy parity
  2. Single attacker test: Introduce one label-flipping attacker and measure attack success rate reduction
  3. Scaling test: Increase number of attackers from 1 to 10 and observe algorithm's degradation point
