# Divide and Prompt: Chain of Thought Prompting for Text-to-SQL

## Quick Facts
- arXiv ID: 2304.11556
- Source URL: https://arxiv.org/abs/2304.11556
- Reference count: 5
- Three prompting-based methods (Clause by Clause DnP, Schema Linking DnP, Generate and Refine DnP) improve execution accuracy by 4.3% overall and 10.8% on hard-level tasks

## Executive Summary
This paper introduces Divide-and-Prompt, a novel prompting paradigm for Text-to-SQL tasks that decomposes the complex problem into manageable subtasks approached through chain-of-thought prompting. The framework presents three specific methods that enhance large language models' ability to generate executable SQL queries from natural language questions. Experimental results demonstrate significant improvements in execution accuracy compared to standard prompting approaches, particularly for more complex queries.

## Method Summary
Divide-and-Prompt breaks down Text-to-SQL into subtasks and approaches each through chain-of-thought prompting. The framework introduces three prompting methods: Clause by Clause DnP, which decomposes SQL into individual clauses; Schema Linking DnP, which establishes relationships between natural language questions and database schemas; and Generate and Refine DnP, which iteratively improves SQL generation through refinement steps. These methods guide LLMs to generate more accurate Text-to-SQL outputs by structuring the reasoning process.

## Key Results
- Overall execution accuracy improved by 4.3% compared to standard prompting
- Hard-level Text-to-SQL tasks showed a 10.8% improvement in execution accuracy
- The proposed prompts successfully guided LLMs to generate more accurate SQL queries

## Why This Works (Mechanism)
The Divide-and-Prompt paradigm works by leveraging the natural decomposition of SQL queries into constituent parts, allowing LLMs to focus on smaller, more manageable reasoning tasks. By breaking down complex Text-to-SQL problems into subtasks, the approach reduces cognitive load and enables more systematic problem-solving. The chain-of-thought prompting guides the model through intermediate reasoning steps, improving the quality of the final SQL output. This structured approach helps models better understand the relationships between natural language questions, database schemas, and SQL syntax.

## Architecture Onboarding

**Component Map**
DnP Framework -> Subtask Decomposition -> Chain-of-Thought Reasoning -> SQL Generation

**Critical Path**
Question Analysis → Schema Mapping → SQL Clause Generation → SQL Assembly → Validation

**Design Tradeoffs**
Structured decomposition vs. increased prompting steps; granularity of subtasks vs. prompt complexity; refinement iterations vs. computational overhead

**Failure Signatures**
Incoherent intermediate reasoning steps; schema linking errors propagating to final output; over-decomposition leading to context loss; refinement loops without convergence

**3 First Experiments**
1. Test Clause by Clause DnP on simple SELECT queries to validate basic decomposition
2. Evaluate Schema Linking DnP with single-table schemas to verify mapping accuracy
3. Run Generate and Refine DnP on queries with known error patterns to assess refinement effectiveness

## Limitations
- Experimental evaluation limited to specific LLMs (GPT-3.5, Codex) without broader model diversity
- Improvements show substantial variance across model sizes and task complexities
- Potential overfitting to specific schema patterns or SQL dialects not thoroughly investigated
- Computational overhead of multi-step prompting not explicitly quantified

## Confidence

**High confidence**: The core methodology of dividing Text-to-SQL into subtasks and using chain-of-thought prompting is technically sound and reproducible

**Medium confidence**: The reported accuracy improvements are reliable within the experimental setup but may vary with different model configurations

**Low confidence**: Generalizability to production environments and other SQL dialects or database schemas remains uncertain
