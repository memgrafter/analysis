# SMAClite: A Lightweight Environment for Multi-Agent Reinforcement Learning

## Quick Facts
- arXiv ID: 2305.05566
- Source URL: https://arxiv.org/abs/2305.05566
- Reference count: 40
- Key outcome: Provides open-source, lightweight alternative to SMAC with equivalent performance and improved runtime efficiency

## Executive Summary
SMAClite addresses the computational cost and closed-source limitations of the StarCraft Multi-Agent Challenge (SMAC) by providing an open-source, lightweight MARL environment. Built on a custom engine with JSON-based scenario definitions and a modified ORCA collision avoidance algorithm, SMAClite replicates SMAC's core mechanics while achieving six times better memory efficiency and real-time capability. The environment demonstrates equivalent performance to SMAC across multiple algorithms and scenarios, with improved cross-environment transfer capabilities. The project represents a practical solution for researchers needing accessible, efficient MARL benchmarking tools.

## Method Summary
The research team developed SMAClite as a complete reimplementation of SMAC's core mechanics using a custom-built engine rather than the StarCraft II API. The environment supports easy scenario and unit creation through JSON files and implements collision avoidance using a modified ORCA algorithm. The validation methodology involved training nine different MARL algorithms (IQL, IA2C, IPPO, MADDPG, COMA, MAA2C, MAPPO, VDN, QMIX) across six scenarios (2s_vs_1sc, 3s5z, MMM2, corridor, 3s_vs_5z, bane_vs_bane) for 12 million timesteps each. Performance was compared against SMAC through training curves, final metrics, and zero-shot transfer testing. Runtime and memory usage measurements were conducted using cgroups and system monitoring tools.

## Key Results
- Training agents on SMAClite yields comparable performance to SMAC with similar algorithm rankings
- SMAClite achieves 6x reduction in RAM usage compared to SMAC while maintaining equivalent performance
- Cross-environment transfer from SMAClite to SMAC shows improved performance compared to SMAC-to-SMAC transfer
- Real-time capability achieved through lightweight engine design and efficient collision avoidance

## Why This Works (Mechanism)
The core mechanism relies on replacing the complex StarCraft II engine with a custom-built environment that simulates essential game mechanics without unnecessary overhead. The JSON-based scenario system allows flexible configuration while maintaining compatibility with SMAC's benchmark suite. The modified ORCA algorithm provides efficient collision handling that scales better than SMAC's physics simulation. By eliminating attack animations and projectile simulation, the environment reduces computational complexity while preserving strategic depth through instantaneous combat resolution.

- Collision detection algorithms (ORCA) - essential for understanding the efficiency gains in agent movement

## Architecture Onboarding

**Component Map:**
Custom Engine -> JSON Scenario Parser -> ORCA Collision System -> MARL Interface -> Algorithm Training Loop

**Critical Path:**
Scenario loading → Environment step execution → Collision resolution → State observation generation → Reward calculation → Episode termination check

**Design Tradeoffs:**
The environment trades graphical fidelity and complex animations for computational efficiency. This decision eliminates attack animations and projectile physics but maintains strategic gameplay through instant combat resolution. The JSON-based configuration system sacrifices some type safety for flexibility and ease of modification.

**Failure Signatures:**
- Algorithm ranking mismatches between environments indicate configuration or mechanic discrepancies
- Performance degradation in specific scenarios suggests collision system issues or target selection problems
- Memory usage spikes may indicate inefficient scenario parsing or state representation

**First Experiments:**
1. Run a single algorithm on a simple scenario to verify basic environment functionality
2. Compare training curves between SMAClite and SMAC for a single algorithm-scenario pair
3. Test zero-shot transfer by training on SMAClite and evaluating in SMAC with identical configurations

## Open Questions the Paper Calls Out
- How does the lack of attack animations and projectile simulation in SMAClite impact the relative performance of agents across different scenarios compared to SMAC?
- To what extent does the simplified target selection logic in SMAClite alter the strategic complexity compared to SMAC?
- How does the performance of SMAClite change when scaling to larger or more complex scenarios, such as those with dynamic terrain or procedurally generated maps?

## Limitations
- Missing attack animations and projectile simulation affect gameplay mechanics like kiting
- Simplified target selection logic may reduce strategic depth in certain scenarios
- Limited testing on scenarios beyond the SMAC benchmark suite

## Confidence
- Performance equivalence claims: High
- Runtime and memory efficiency claims: High
- Cross-environment transfer benefits: Medium
