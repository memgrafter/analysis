# Koala: An Index for Quantifying Overlaps with Pre-training Corpora

## Quick Facts
- arXiv ID: 2303.14770
- Source URL: https://arxiv.org/abs/2303.14770
- Reference count: 14
- Primary result: Introduces Koala, a tool for analyzing overlap between test data and pre-training corpora in LLMs using compressed suffix arrays

## Executive Summary
This paper presents Koala, a public tool for analyzing the overlap between test data and pre-training corpora in large language models (LLMs). Using compressed suffix arrays, Koala provides efficient search and query capabilities for large-scale forensic analysis. The first release indexes the public portion of the OPT 175B pre-training data. Koala offers visualizations of n-gram overlap statistics for benchmarks like PIQA and OpenBookQA, highlighting the extent of data leakage and its correlation with model performance. The tool also supports assessing memorization versus creativity in generative models' outputs.

## Method Summary
Koala constructs searchable indexes over large pre-training corpora using compressed suffix arrays (CSA) with Burrows-Wheeler transform and FM-Index. The method involves preprocessing and deduplicating the target pre-training corpus using MinHashLSH with a Jaccard similarity threshold of 0.95, followed by tokenization with the Moses tokenizer. The CSA index is built for the deduplicated corpus, enabling efficient n-gram overlap analysis via querying the index. The tool provides a web-based interface for uploading files or querying text, generating visualizations of overlap statistics for benchmark datasets.

## Key Results
- Koala enables efficient forensic analysis of pre-training data overlap using compressed suffix arrays
- The tool reveals significant overlap between benchmarks like PIQA and OpenBookQA with pre-training corpora, with over 25% of trigrams occurring at least 100 times in the pre-training data
- A positive correlation is observed between the amount of data overlap and task performance ceiling by LLMs trained on the same pre-training corpora

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Compressed suffix arrays (CSA) enable efficient forensic analysis of pre-training data overlap by allowing fast n-gram queries with low memory footprint.
- Mechanism: CSA uses Burrows-Wheeler transform (BWT) to compress text while preserving search functionality. Searching for a sequence is done in reverse order and requires O(|u| log|σ|), where σ is alphabet size. This allows querying large corpora efficiently.
- Core assumption: The BWT transformation preserves the ability to search for substrings while enabling compression.
- Evidence anchors:
  - [abstract]: "a searchable index over large pre-training corpora using compressed suffix arrays with highly efficient compression rate and search support"
  - [section]: "Compressed Suffix Array exploits the compressibility of T while providing the same functionality of SA in space equal to bzip2 compressed T in practice."
- Break condition: If the BWT does not preserve the search functionality or if the compression degrades search performance beyond acceptable limits.

### Mechanism 2
- Claim: Deduplication using MinHashLSH reduces false overlap signals from repeated documents in pre-training corpora.
- Mechanism: Documents are converted to sets of unigram tokens, hashed into minhashes, and then locality-sensitive hashes are calculated to detect duplicates. Pairs with Jaccard similarity above 0.95 are removed.
- Core assumption: Documents with high Jaccard similarity are likely to be near-duplicates that would inflate overlap statistics.
- Evidence anchors:
  - [section]: "We use MinHashLSH... to remove those having Jaccard similarity scores above 0.95 threshold."
  - [section]: "Documents are first converted into a set of unigram tokens (shingling) and then hashed into a short signature, namely minhash, such that the similarity among documents is preserved."
- Break condition: If the 0.95 threshold is too high or low, leading to removal of unique content or retention of duplicates.

### Mechanism 3
- Claim: N-gram overlap statistics reveal the extent of data leakage between benchmarks and pre-training corpora, correlating with model performance.
- Mechanism: For each benchmark instance, the ratio of k-grams present in pre-training data (above frequency thresholds) is calculated. This quantifies how much of the test data was seen during training.
- Core assumption: Higher overlap between test data and pre-training corpora leads to inflated model performance on those benchmarks.
- Evidence anchors:
  - [abstract]: "highlighting the extent of data leakage and its correlation with model performance"
  - [section]: "We observe that above 25% of trigrams occur at least 100 times in the pretraining data."
  - [section]: "Our highlighted findings suggests a positive correlation between the amount of data overlap we highlighted and the task performance ceiling by the LLMs"
- Break condition: If the correlation between overlap and performance is not consistent across different benchmarks or model sizes.

## Architecture Onboarding

- Component map: Data preprocessing pipeline (cleaning → deduplication → tokenization) -> Index construction (CSA building) -> Query interface (web-based) -> Visualization (n-gram overlap statistics)

- Critical path: Corpus preprocessing → CSA index construction → Query processing → Result visualization

- Design tradeoffs:
  - Compression vs. query speed: Higher compression reduces memory usage but may slow down queries.
  - Deduplication threshold: Higher thresholds remove more duplicates but risk removing unique content.
  - Corpus coverage: More corpora provide better analysis but increase index size and construction time.

- Failure signatures:
  - Slow query responses: May indicate issues with CSA construction or query optimization.
  - Inconsistent overlap statistics: Could suggest problems with deduplication or corpus preprocessing.
  - High memory usage: Might indicate inefficient CSA implementation or insufficient compression.

- First 3 experiments:
  1. Test the query interface with small text files to verify n-gram overlap statistics.
  2. Compare overlap statistics for known overlapping and non-overlapping text samples.
  3. Analyze the effect of different frequency thresholds on overlap statistics for a benchmark dataset.

## Limitations
- The correlation between n-gram overlap and model performance may vary across different benchmarks and model sizes.
- The tool's effectiveness depends on the completeness of the indexed corpora and may not generalize to different model architectures.
- The compression and search efficiency of the CSA implementation may vary with different hardware configurations and corpus characteristics.

## Confidence
- High: The mechanism of using compressed suffix arrays for efficient search over large corpora is well-established and theoretically sound.
- Medium: The correlation between n-gram overlap and model performance is supported by empirical evidence but may vary across different benchmarks and model architectures.
- Low: The generalizability of the tool's findings to different model architectures and the impact of data preprocessing choices on the results are not well-established and require further investigation.
