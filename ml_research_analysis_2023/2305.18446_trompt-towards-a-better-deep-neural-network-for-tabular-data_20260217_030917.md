# Trompt: Towards a Better Deep Neural Network for Tabular Data

## Quick Facts
- arXiv ID: 2305.18446
- Source URL: https://arxiv.org/abs/2305.18446
- Authors: 
- Reference count: 18
- Primary result: Trompt achieves state-of-the-art performance among deep learning models and comparable performance to tree-based models on the Grinsztajn45 benchmark

## Executive Summary
Trompt introduces a novel deep learning architecture for tabular data that adapts prompt learning concepts from NLP. The key innovation is separating feature importance learning into intrinsic column information (learned via column embeddings) and sample-specific variations (learned via prompt embeddings). Evaluated on 45 datasets from the Grinsztajn45 benchmark, Trompt outperforms state-of-the-art deep learning models like SAINT and FT-Transformer while achieving comparable performance to tree-based models across both classification and regression tasks.

## Method Summary
Trompt uses multiple Trompt Cells to generate diverse representations of tabular data, with each cell containing column embeddings for intrinsic dataset properties and prompt embeddings for sample-specific feature importance variations. These cells share a common downstream module for prediction. The architecture fuses prompt embeddings with previous cell outputs rather than inputs, allowing the model to generate diverse feature representations conditioned on sample-specific contexts. Feature importances are derived through this complex fusion process, enabling the model to capture both general patterns and sample-specific nuances in tabular data.

## Key Results
- Trompt outperforms state-of-the-art deep learning models (SAINT and FT-Transformer) on the Grinsztajn45 benchmark
- Achieves comparable performance to tree-based models across classification and regression tasks
- Ablation studies show Trompt is robust to hyperparameter choices and that the prompt-based feature importance mechanism is critical to performance
- Feature importance visualizations demonstrate interpretability consistent with domain knowledge

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Trompt achieves superior performance by separating feature importance learning into intrinsic column information and sample-specific variations.
- Mechanism: The architecture uses column embeddings to learn intrinsic dataset properties invariant across samples, while prompt embeddings provide variations in feature importance specific to individual samples.
- Core assumption: Feature importance for tabular data varies significantly between samples and can be effectively modeled using prompt-inspired variations.
- Evidence anchors:
  - [abstract]: "Trompt separates the learning strategy of tabular data into two parts for the intrinsic information of a table and the varied information among samples."
  - [section 3.3]: "In Trompt, prompt is utilized to derive feature importances that vary in different samples."
  - [corpus]: No direct corpus evidence found supporting this specific mechanism - this appears to be a novel architectural contribution.
- Break condition: If feature importance variations between samples are not significant or cannot be effectively captured through prompt-inspired mechanisms, the performance advantage would diminish.

### Mechanism 2
- Claim: The prompt-based feature importance mechanism is critical to Trompt's performance.
- Mechanism: Feature importances are derived through a complex fusion process where prompt embeddings are fused with previous cell outputs rather than inputs, allowing the model to generate diverse feature representations conditioned on sample-specific contexts.
- Core assumption: The specific design choice of fusing prompt embeddings with previous outputs rather than inputs is crucial for generating effective feature importance variations.
- Evidence anchors:
  - [section 3.3]: "In Trompt, prompt embeddings are trainable vectors fused to the previous cell's output to condition invariant column embeddings for varied feature importances."
  - [section 4.3]: "Ablations on expanding feature embeddings by a dense layer. The part three of Figure 3 uses a dense layer to expand feature embeddings to accommodate P prompts. Here we discuss the necessity of the dense layer."
  - [corpus]: No corpus evidence found - this appears to be a unique architectural design not previously explored in the literature.
- Break condition: If the fusion mechanism is simplified or the dense layer expansion is removed, performance degrades significantly as shown in ablation studies.

### Mechanism 3
- Claim: Multiple Trompt Cells with a shared downstream enables diverse representation learning while maintaining computational efficiency.
- Mechanism: Each Trompt Cell independently processes the input to generate diverse representations, which are then aggregated through a shared downstream module for prediction. This design allows for rich feature extraction while sharing computational resources.
- Core assumption: Having multiple independent feature extraction cells followed by a shared prediction layer provides better representation diversity than a single deep network.
- Evidence anchors:
  - [section 3.2]: "A Trompt Downstream makes a prediction based on a Trompt Cell's output, which contains representations corresponding to P prompt embeddings."
  - [section 4.2]: "During inference, on the other hand, predictions through all cells are simply averaged as the final prediction as Equation (9), where L is the number of Trompt Cells."
  - [corpus]: No corpus evidence found - this ensemble-like approach with shared downstream appears to be a novel design choice.
- Break condition: If the number of Trompt Cells is reduced to one or if individual downstreams are used instead of sharing, the model may lose representation diversity or become computationally inefficient.

## Architecture Onboarding

- Component map: Input layer → Multiple Trompt Cells → Shared Trompt Downstream → Prediction
- Critical path: Input → Column embeddings (invariant) → Fusion with prompt embeddings (variant) → Multiple Trompt Cells → Shared downstream → Prediction
- Design tradeoffs:
  - Multiple cells provide diversity but increase computation
  - Shared downstream reduces parameters but may limit individual cell specialization
  - Prompt-based approach adds flexibility but increases hyperparameter complexity
- Failure signatures:
  - Poor performance on heterogeneous features indicates prompt embedding issues
  - Sensitivity to hyperparameter choices suggests architecture instability
  - Inconsistent feature importance visualizations reveal fusion mechanism problems
- First 3 experiments:
  1. Compare single Trompt Cell vs multiple cells on a small dataset to validate representation diversity
  2. Test with and without prompt embeddings to quantify their contribution to performance
  3. Vary the number of prompts (P) to find optimal balance between diversity and overfitting

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does Trompt's performance scale with the number of Trompt Cells (L) beyond the tested range (L=6)?
- Basis in paper: [explicit] The ablation study showed L=1 performed poorly and L=12 improved performance, suggesting larger L may help but was not tested.
- Why unresolved: The study only tested up to L=12 due to computational constraints, leaving the optimal L for large datasets unknown.
- What evidence would resolve it: Testing Trompt with L=20 or higher on large datasets to find the point of diminishing returns.

### Open Question 2
- Question: Can Trompt's prompt-inspired mechanism be adapted for unsupervised or semi-supervised learning tasks?
- Basis in paper: [inferred] The paper focuses on supervised tasks, but the prompt learning concept could theoretically handle unlabeled data by learning feature importance patterns.
- Why unresolved: The architecture and experiments are designed specifically for supervised learning, with no exploration of unsupervised variants.
- What evidence would resolve it: Adapting Trompt to a self-supervised pretraining task and evaluating on downstream tasks.

### Open Question 3
- Question: How does Trompt's interpretability compare to tree-based models in terms of feature importance consistency across different samples?
- Basis in paper: [explicit] The paper shows Trompt's feature importances align with tree-based models on synthetic and real datasets, but doesn't analyze sample-level consistency.
- Why unresolved: The study focuses on average feature importances, not how importances vary across individual samples or how this compares to tree-based models.
- What evidence would resolve it: Analyzing and comparing the variance of feature importances across samples between Trompt and tree-based models.

## Limitations

- Trompt lacks comparison with the most recent tabular deep learning methods like MLP-Mixer and other modern architectures
- The prompt-based approach introduces significant architectural complexity that may be difficult to implement and tune
- Ablation studies don't fully explore the interaction between hyperparameters like the number of Trompt Cells and the number of prompts

## Confidence

*High Confidence:* The experimental methodology using the established Grinsztajn45 benchmark is sound, and the comparison against relevant baselines is appropriate. The core architectural contributions (separating intrinsic and sample-specific feature importance) are well-defined and implemented.

*Medium Confidence:* The performance claims relative to tree-based methods are credible given the benchmark used, but the superiority over other deep learning methods may be dataset-dependent. The interpretability results through feature importance visualizations are promising but could benefit from more rigorous validation.

*Low Confidence:* The claim that prompt-based feature importance is the critical mechanism for Trompt's success is supported by ablation studies but not conclusively proven. Alternative explanations (such as the ensemble-like effect of multiple cells) could also account for the performance gains.
