# MultiTool-CoT: GPT-3 Can Use Multiple External Tools with Chain of Thought Prompting

## Quick Facts
- arXiv ID: 2305.16896
- Source URL: https://arxiv.org/abs/2305.16896
- Reference count: 4
- Primary result: MultiTool-CoT framework achieves state-of-the-art performance on Task 2 of NumGLUE by integrating multiple external tools during chain-of-thought reasoning

## Executive Summary
This paper introduces MultiTool-CoT, a framework that enables large language models to use multiple external tools during reasoning through chain-of-thought prompting. The approach is applied to Task 2 of NumGLUE, a dataset requiring both numerical reasoning and domain-specific knowledge. By allowing GPT-3 to invoke external tools like calculators and knowledge retrievers at appropriate reasoning steps, the framework achieves state-of-the-art performance. The authors also investigate how the number of few-shot examples affects performance and analyze error types, demonstrating strong generalization ability.

## Method Summary
MultiTool-CoT uses few-shot learning with chain-of-thought prompting to teach GPT-3 how to invoke multiple external tools during reasoning. The framework generates reasoning steps with tool triggers, halts generation, executes the tool, and resumes with the tool's output. The prompt consists of an instruction specifying available tools, few-shot examples demonstrating reasoning with tool triggers, and the question to be solved. External tools include a calculator (eval function), chemical reaction predictor, and molar mass list. The approach is evaluated on Task 2 of NumGLUE using 20 few-shot examples from the training split.

## Key Results
- MultiTool-CoT achieves state-of-the-art performance on Task 2 of NumGLUE
- Using multiple external tools together provides greater performance gains than using each tool individually
- Performance improves with more few-shot examples (5, 10, 20 examples tested)
- Strong generalization ability across different error types

## Architecture Onboarding

- Component map:
  GPT-3 (text-davinci-003) -> Prompt generator -> Tool executor -> External tools (Calculator, Chemical Reaction Predictor, Molar Mass List) -> Answer extractor

- Critical path:
  1. Generate prompt with instruction, few-shot examples, and question
  2. GPT-3 generates reasoning with tool triggers
  3. For each tool trigger: extract tool name and input, execute tool, append result
  4. GPT-3 continues generation with tool results
  5. Extract final answer from reasoning conclusion

- Design tradeoffs:
  - Using few-shot learning vs. fine-tuning: few-shot is faster but may be less reliable
  - Tool trigger format: <<Tool Name>> is simple but may conflict with natural text
  - Error handling: fallback to GPT-3 generation vs. stopping execution

- Failure signatures:
  - Incorrect reasoning processes (39% of errors)
  - Invalid tool inputs (35% of errors)
  - Incorrect gold answers (15% of errors)
  - Variations in answer formats (11% of errors)

- First 3 experiments:
  1. Test with single external tool (Calculator only) to establish baseline improvement
  2. Test with all three external tools to measure combined effect
  3. Vary number of few-shot examples (5, 10, 20) to assess learning curve and generalization

## Limitations

- The framework relies on manually annotated few-shot examples (only 20 used), and the quality/representativeness of these examples significantly impacts performance
- Error analysis identifies four error types but lacks quantitative breakdown of their relative contributions and potential correlations
- External tools like chemical reaction predictor and molar mass list implementations are not fully specified, making robustness assessment difficult

## Confidence

**High confidence**: The core claim that MultiTool-CoT outperforms single-tool approaches and achieves state-of-the-art performance on Task 2 of NumGLUE. The methodology is clearly described, and the performance improvements are substantial and consistent across different metrics.

**Medium confidence**: The mechanism explanations for why multiple tools provide greater benefits than individual tools. While the reasoning is logical (combined errors in knowledge and arithmetic), the evidence is primarily observational rather than experimentally validated through controlled studies.

**Low confidence**: The generalizability claims beyond Task 2 of NumGLUE. The paper demonstrates effectiveness on one specific dataset with chemistry-focused questions, but does not provide evidence that the approach transfers to other domains or reasoning tasks without significant modification.

## Next Checks

1. **Controlled error analysis**: Conduct experiments isolating each error type by creating synthetic test cases that trigger only knowledge errors, only calculation errors, or combined errors. This would validate whether the observed performance gains are indeed due to addressing multiple error types simultaneously.

2. **Few-shot sensitivity analysis**: Systematically vary the number and quality of few-shot examples (e.g., 5, 10, 15, 20, 25 examples) and measure the learning curve. Additionally, test whether diverse example selection improves generalization compared to random selection from the training split.

3. **Cross-domain generalization test**: Apply MultiTool-CoT to a different reasoning task that requires both numerical reasoning and domain knowledge (e.g., financial calculations with economic knowledge, or physics problems requiring unit conversions and physical laws) to assess whether the framework's benefits transfer beyond chemistry-focused questions.
