# ED-Batch: Efficient Automatic Batching of Dynamic Neural Networks via Learned Finite State Machines

## Quick Facts
- arXiv ID: 2302.03851
- Source URL: https://arxiv.org/abs/2302.03851
- Reference count: 40
- Key outcome: ED-Batch achieves 1.15x, 1.39x, and 2.45x speedups over state-of-the-art frameworks for chain-based, tree-based, and lattice-based networks respectively across CPU and GPU.

## Executive Summary
This paper introduces ED-Batch, a novel approach to efficiently batch dynamic neural networks by combining reinforcement learning with memory layout optimization. The key innovation is representing the batching policy as a finite state machine (FSM) that is learned via reinforcement learning to minimize the number of batches executed. Additionally, the paper presents a PQ tree-based algorithm for memory planning that is aware of the batching policy, reducing data movement overhead. Experiments demonstrate significant speedups across various network architectures including chain-based, tree-based, and lattice-based networks on both CPU and GPU.

## Method Summary
ED-Batch addresses the challenge of dynamic batching in neural networks by learning an optimal batching policy through reinforcement learning. The method represents batching decisions as states in a finite state machine, encoding the frontier of the dataflow graph. A Q-learning algorithm is used to learn the optimal policy that minimizes the number of batches executed. The paper also introduces a PQ tree-based memory allocation algorithm that finds optimal memory layouts satisfying adjacency and alignment constraints for batched operations. This memory-aware batching reduces data movement overhead during execution. The approach is integrated with the DyNet runtime and evaluated across multiple benchmark models showing substantial performance improvements.

## Key Results
- ED-Batch achieves 1.15x speedup for chain-based networks compared to Vanilla DyNet
- ED-Batch achieves 1.39x speedup for tree-based networks compared to Vanilla DyNet
- ED-Batch achieves 2.45x speedup for lattice-based networks compared to Vanilla DyNet
- Performance improvements are demonstrated on both CPU and GPU platforms
- Memory planning using PQ trees reduces data movement overhead by optimizing operand adjacency and alignment

## Why This Works (Mechanism)

### Mechanism 1: FSM-based Dynamic Batching Policy
The FSM-based approach discovers near-optimal batching by representing batching decisions as states and using RL to learn the best policy. The algorithm encodes the frontier of the dataflow graph into states and uses a learned policy to select the next operation type to batch, enabling decisions based on the full graph structure rather than heuristics. This works because the regularity in network topology for a given input can be captured by FSM states, and the optimal policy can be represented by a finite number of states.

### Mechanism 2: PQ Tree-based Memory Allocation
The PQ tree-based memory allocation algorithm reduces data movement overhead by finding optimal memory layouts that satisfy both adjacency and alignment constraints for batched operations. The algorithm uses PQ trees to represent possible permutations of variables where operands in each batch are adjacent and aligned in memory, then uses union-find structures to resolve ordering constraints. This works because the ideal memory layout exists as a permutation of variables satisfying the adjacency and alignment constraints, and PQ trees can efficiently find this permutation.

### Mechanism 3: RL Reward Function for Minimizing Batches
The RL reward function minimizes the number of batches executed by penalizing each additional batch and prioritizing types where all operations in the subgraph frontier are ready to execute. The reward function combines a constant penalty for each batch with a term that rewards types where the ratio of ready operations to total operations in the subgraph frontier equals 1. This works because the sufficient condition guaranteeing the existence of a shortest batching sequence can be used to guide RL learning.

## Architecture Onboarding

- **Component map:**
  FSM-based dynamic batching module (RL-trained policy, state encoding functions) -> PQ tree-based memory allocator (PQ tree construction, constraint parsing, order decision) -> DyNet runtime integration (graph construction, execution engine, vendor library calls)

- **Critical path:**
  1. Graph construction and static subgraph extraction
  2. RL training for FSM-based batching policy
  3. PQ tree-based memory optimization for static subgraphs
  4. Runtime execution with learned policy and optimized memory layout

- **Design tradeoffs:**
  - FSM expressiveness vs. runtime overhead (simple state encoding vs. complex encoding)
  - Memory optimization complexity vs. execution speed (PQ tree algorithm vs. naive allocation)
  - RL training time vs. inference speedup (longer training for better policies vs. faster deployment)

- **Failure signatures:**
  - Poor batching performance: RL training not converging, FSM states not capturing necessary information
  - Memory allocation issues: PQ tree algorithm failing to find valid permutation, constraints incompatible
  - Runtime overhead: State encoding too complex, memory optimization too time-consuming

- **First 3 experiments:**
  1. Test FSM-based batching with simple state encoding (Ebase) on chain-based networks to verify basic functionality
  2. Implement PQ tree memory allocation on static subgraphs and measure reduction in memory copies
  3. Run end-to-end inference on TreeLSTM model comparing ED-Batch against Vanilla DyNet

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the theoretical lower bound on the number of batches for dynamic neural networks, and how tight is this bound for different network architectures?
- Basis in paper: The paper provides a lower bound formula (Σt∈TDepth(Gt)) for the optimal number of batches.
- Why unresolved: The paper shows ED-Batch achieves significant improvements but does not quantify how close it gets to the theoretical lower bound for each architecture.
- What evidence would resolve it: Experimental comparison of ED-Batch's batch count against the theoretical lower bound across all evaluated architectures and input sizes.

### Open Question 2
- Question: How does the choice of state encoding (Ebase, Emax, Esort) affect ED-Batch's performance in networks with varying levels of dynamism and control flow complexity?
- Basis in paper: The paper mentions three state encoding methods and found Esort performs best empirically.
- Why unresolved: The paper does not provide a detailed analysis of why Esort performs better or how each encoding handles different network complexities.
- What evidence would resolve it: Systematic ablation studies varying network architectures (chain, tree, lattice) and control flow patterns, measuring both batch count and runtime performance for each encoding.

### Open Question 3
- Question: Can the PQ-tree memory allocation algorithm be extended to handle dynamic memory layouts that change during execution, and what would be the trade-offs?
- Basis in paper: The PQ-tree algorithm is applied to static subgraphs where memory layout can be planned ahead.
- Why unresolved: The paper acknowledges this limitation and suggests the algorithm could apply to any batching problem, but doesn't explore dynamic scenarios.
- What evidence would resolve it: Implementation of PQ-tree on truly dynamic networks and measurement of performance impact versus traditional gather/scatter approaches.

## Limitations
- PQ tree memory optimization may become computationally prohibitive for extremely large graphs
- RL training requires careful hyperparameter tuning that is not fully specified
- Performance on more complex, real-world architectures beyond benchmark models remains untested

## Confidence
- FSM-based batching mechanism: **Medium** - While the theoretical framework is sound, the practical effectiveness depends heavily on the quality of RL training and state encoding.
- PQ tree memory optimization: **Medium** - The algorithm is theoretically valid but implementation complexity and scalability concerns exist.
- Overall speedup claims: **High** - Well-supported by experiments on multiple benchmark models across different network types.
