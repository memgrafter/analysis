# Automated Interactive Domain-Specific Conversational Agents that Understand Human Dialogs

## Quick Facts
- arXiv ID: 2303.08941
- Source URL: https://arxiv.org/abs/2303.08941
- Reference count: 7
- One-line primary result: AutoConcierge outperforms Bing AI in proactivity, economy, explainability, correctness, consistency, and efficiency for restaurant recommendations.

## Executive Summary
This paper presents AutoConcierge, a conversational agent for restaurant recommendation that combines Large Language Models (LLMs) and Answer Set Programming (ASP) to understand user utterances and provide recommendations based on user preferences. The system uses GPT-3 for semantic parsing and response generation, while s(CASP) ASP performs commonsense reasoning on extracted predicates. AutoConcierge demonstrates superior performance compared to Bing AI across multiple evaluation criteria and maintains response times within the average human attention span.

## Method Summary
AutoConcierge employs a two-stage LLM-ASP architecture where GPT-3 with in-context learning converts natural language user utterances into structured predicates, which are then processed by the s(CASP) ASP system to perform reasoning and generate recommendations. The system maintains conversation state through predicate-based representations and uses a conversational knowledge template (CKT) to handle missing information and inconsistencies. GPT-3 is used again to convert the computed predicates back into natural language responses. The approach leverages few-shot learning through carefully crafted examples rather than traditional fine-tuning.

## Key Results
- AutoConcierge outperforms Bing AI in proactivity, economy, explainability, correctness, consistency, and efficiency
- The system maintains response times within the average human attention span
- GPT-3 semantic parser achieves 89.33% accuracy on the E2E dataset with in-context learning
- The approach successfully handles complex user preferences and provides explanations for recommendations

## Why This Works (Mechanism)

### Mechanism 1
- Claim: GPT-3 augmented with in-context learning acts as a semantic parser that translates user utterances into structured predicates representing deep meaning.
- Mechanism: In-context learning provides GPT-3 with examples of sentences and their corresponding predicate representations, enabling it to map new sentences to predicates.
- Core assumption: A small number of carefully selected examples are sufficient for GPT-3 to generalize and parse new sentences accurately.
- Evidence anchors:
  - [abstract] "AutoConcierge is based on our STAR framework developed earlier, which uses GPT-3 to convert human dialogs into predicates that capture the deep structure of the dialog's sentence."
  - [section 3.1] "We tested GPT-3 specialized to our in-context learning on the E2E dataset... We obtained an accuracy of 89.33%."
- Break condition: If the domain requires predicates beyond those covered in the examples, GPT-3 may fail to parse accurately.

### Mechanism 2
- Claim: s(CASP) ASP system performs commonsense reasoning on the extracted predicates to identify missing information, check consistency, and generate recommendations.
- Mechanism: The s(CASP) system contains domain knowledge represented as ASP rules and reasons over the predicates to draw conclusions, detect inconsistencies, and compute responses.
- Core assumption: Commonsense knowledge relevant to the domain can be effectively encoded as ASP rules.
- Evidence anchors:
  - [abstract] "AutoConcierge uses GPT-3 to parse user utterances into predicates and s(CASP) ASP to perform reasoning and generate recommendations."
  - [section 2.2] "The s(CASP) system, developed by Arias et al. (2018), is an answer set programming system that supports predicates, constraints over non-ground variables, uninterpreted functions, and, most importantly, a top-down, query-driven execution strategy."
- Break condition: If the domain knowledge cannot be adequately represented as ASP rules, the reasoning may be incomplete or incorrect.

### Mechanism 3
- Claim: GPT-3 with in-context learning generates natural language responses from the predicates computed by the s(CASP) system.
- Mechanism: In-context learning examples map predicates to natural language responses, and GPT-3 generates responses by matching the computed predicates to these examples.
- Core assumption: Natural language responses can be generated by mapping predicates to examples.
- Evidence anchors:
  - [abstract] "AutoConcierge uses GPT-3 to parse user utterances into predicates and s(CASP) ASP to perform reasoning and generate recommendations."
  - [section 3.3] "Once a target restaurant is identified by the reasoner, its detailed information is presented in the form of logical predicates... These predicates are translated into natural language sentences using GPT-3 in a reverse example format."
- Break condition: If the computed predicates do not match any of the provided examples, GPT-3 may fail to generate an appropriate response.

## Architecture Onboarding

- Component map:
  - GPT-3 with in-context learning (semantic parser)
  - Filter (format adapter)
  - s(CASP) ASP system (reasoner)
  - GPT-3 with in-context learning (response generator)
  - Knowledge base (restaurant information)

- Critical path: User utterance → GPT-3 parser → Filter → s(CASP) reasoner → GPT-3 generator → Response

- Design tradeoffs:
  - Using GPT-3 for both parsing and generation simplifies the architecture but may limit flexibility.
  - Representing domain knowledge as ASP rules requires upfront effort but enables powerful reasoning.
  - In-context learning allows for few-shot learning but may be less robust than fine-tuning.

- Failure signatures:
  - Parser fails to generate predicates for a user utterance.
  - Reasoner fails to compute a response due to inconsistent or incomplete information.
  - Generator fails to produce a natural language response for the computed predicates.

- First 3 experiments:
  1. Test the parser on a set of user utterances and evaluate the accuracy of the generated predicates.
  2. Test the reasoner on a set of predicates and evaluate the correctness of the computed responses.
  3. Test the end-to-end system with a set of user conversations and evaluate the quality of the generated responses.
