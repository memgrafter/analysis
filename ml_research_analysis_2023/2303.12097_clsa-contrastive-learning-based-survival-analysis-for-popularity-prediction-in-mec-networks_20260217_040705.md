# CLSA: Contrastive Learning-based Survival Analysis for Popularity Prediction in MEC Networks

## Quick Facts
- arXiv ID: 2303.12097
- Source URL: https://arxiv.org/abs/2303.12097
- Reference count: 40
- Key outcome: Proposed CLSA framework achieves 95.10% classification accuracy and 96.48% cache-hit ratio for MEC popularity prediction

## Executive Summary
This paper proposes CLSA, a deep learning framework for popularity prediction in mobile edge caching (MEC) networks. The key innovation is using contrastive learning to capture spatial correlations between content request patterns without requiring simultaneous input of all content histories. The framework combines contrastive learning, reconstruction, and survival analysis to predict which contents will become popular within a study window. Experiments on MovieLens data show CLSA outperforms state-of-the-art approaches in both classification accuracy and cache-hit ratio.

## Method Summary
CLSA uses a three-block architecture: (1) a shared LSTM encoder that processes historical request sequences, (2) a contrastive learning block that learns discriminative representations through masked and shuffled augmentations, and (3) a survival analysis block that predicts popularity probabilities over time. The model is trained end-to-end using a combination of contrastive loss, reconstruction loss, and survival analysis loss. The framework processes user contextual features along with request patterns, and uses a reconstruction network to improve latent representation quality. The final output is a sorted list of popularity probabilities used to cache the Top-K contents.

## Key Results
- Achieves 95.10% classification accuracy for identifying popular contents
- Reaches 96.48% cache-hit ratio in MEC network simulation
- Outperforms state-of-the-art approaches including TEDGE, MTEC, ViT-CAT, SCARF, and DLCC
- Maintains strong performance across varying numbers of requests per content

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Contrastive Learning enables spatial correlation learning between content request patterns without increasing input size.
- Mechanism: CL contrasts augmented versions of each content's request history (positive pairs) with other contents' histories (negative pairs), forcing the encoder to map similar patterns close and dissimilar ones far apart in the latent space.
- Core assumption: Temporal patterns within a single content's history carry sufficient signal for spatial similarity learning when contrasted with other contents.
- Evidence anchors:
  - [abstract] "no need to simultaneously input the request patterns of all contents to capture the spatial content correlations."
  - [section] "By capitalizing on a unique characteristic of the CL paradigm, i.e., learning common attributes and differences in input samples, there is no need to input multiple historical patterns of contents simultaneously into the CLSA architecture to capture the spatial content correlations."
  - [corpus] Weak: corpus papers focus on general CL in EHRs and embeddings, not MEC spatial correlation; no direct anchor found.
- Break condition: If temporal correlations within a content's history are weak or non-informative, the CL block will fail to distinguish spatial patterns, leading to poor classification.

### Mechanism 2
- Claim: Survival Analysis models the probability that a content becomes popular within a study window based on user contextual features.
- Mechanism: SA takes the final latent representation from the CL block and predicts a cumulative incidence function over time, directly modeling time-to-popularity.
- Core assumption: User contextual features (age, gender, occupation) are predictive of content popularity timing.
- Evidence anchors:
  - [abstract] "Survival Analysis (SA) block to predict the probability of each content's future popularity."
  - [section] "The output of the SA model is the probability that one content gets popular within a time window."
  - [corpus] No direct corpus support for SA in MEC popularity prediction; survival analysis is cited mainly in medical and recommender literature.
- Break condition: If contextual features do not correlate with popularity timing, SA predictions will be noisy, degrading cache-hit ratio.

### Mechanism 3
- Claim: Reconstruction Network improves latent representation quality by forcing the encoder to retain temporal details.
- Mechanism: RN decodes the masked latent representation back to the original user features, minimizing reconstruction loss to preserve temporal fidelity.
- Core assumption: Temporal information in user features is essential for accurate popularity prediction.
- Evidence anchors:
  - [section] "the masked version of xm_k is regenerated from the encoded masked input sample."
  - [section] "To learn a better latent representation, the masked version of xm_k is regenerated from the encoded masked input sample."
  - [corpus] No direct corpus anchor; reconstruction is standard in autoencoders but not explicitly tied to MEC in cited papers.
- Break condition: If reconstruction loss is too low or too high, the encoder either underfits (misses patterns) or overfits (memorizes noise).

## Architecture Onboarding

- Component map:
  User contextual features + ratings + timestamps -> LSTM encoder -> MLP -> latent representation -> CL block (masking/shuffling augmentations) -> contrastive loss -> RN block (Time-LSTM2 decoder) -> reconstruction loss -> SA block (MLP) -> softmax over time -> cumulative incidence -> sorted popularity probabilities

- Critical path:
  1. Encode historical request sequence -> latent representation
  2. Apply CL augmentation and loss to enforce discriminative latent space
  3. Reconstruct masked input to refine latent representation
  4. Feed refined latent to SA to predict popularity probabilities
  5. Sort probabilities and cache Top-K

- Design tradeoffs:
  - Batch size vs. memory: larger batches improve CL but may exceed GPU memory
  - No (number of requests per content) vs. accuracy: more requests improve temporal signal but increase latency
  - Weight balance (ωcl, ωrn, ωsa) vs. task focus: overemphasizing CL hurts SA accuracy, etc.

- Failure signatures:
  - CL dominates: latent space clusters unrelated contents
  - RN dominates: latent representation collapses to mean
  - SA dominates: encoder underfits, latent space lacks discriminative power
  - Imbalanced labels: SA predicts "unpopular" for most contents

- First 3 experiments:
  1. Run with only CL block (ωrn=ωsa=0) to verify spatial correlation learning
  2. Run with only SA block (ωcl=ωrn=0) to establish baseline classification
  3. Run with balanced ωcl, ωrn, ωsa to measure combined effect on accuracy and cache-hit ratio
