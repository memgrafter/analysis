# Translate your gibberish: black-box adversarial attack on machine translation systems

## Quick Facts
- arXiv ID: 2303.10974
- Source URL: https://arxiv.org/abs/2303.10974
- Reference count: 37
- This work presents a black-box adversarial attack method for machine translation systems using "hallucinogens" - nonsensical input sequences that produce meaningful translations.

## Executive Summary
This paper introduces a novel black-box adversarial attack on machine translation systems that generates nonsensical Russian text sequences ("hallucinogens") which produce meaningful English translations. The approach uses a tensor-based optimizer (PROTES) to search for low-probability Russian character combinations that maximize the difference between input and output perplexity. The method successfully demonstrates that major translation systems (DeepL, Google, Yandex) can be fooled into translating gibberish into meaningful text, and that combinations of these hallucinogens can create English phrases that fail to translate back into Russian. This reveals a significant vulnerability in machine translation systems that could be exploited to interfere with language understanding.

## Method Summary
The method employs a tensor-based black-box optimizer called PROTES to search for 7-character Russian sequences that produce meaningful English translations while having high perplexity in Russian. The optimizer uses tensor train decomposition to efficiently explore the high-dimensional discrete search space without requiring gradients from the translation APIs. The loss function maximizes the difference between source text perplexity and translation perplexity, with additional penalties for short or non-alphabetic translations. After finding individual hallucinogens, the method combines them into longer phrases and tests whether these combinations can produce English text that fails to translate back into Russian, creating a one-way translation vulnerability.

## Key Results
- Generated 7-character Russian gibberish strings that translate into meaningful English phrases
- Demonstrated that combinations of hallucinogens can create English phrases that fail to translate back into Russian
- Successfully tested the attack on three major translation systems (DeepL, Google, Yandex) with a query budget of 1000 translations per system
- Showed that machine translation systems can be fooled by exploiting the disconnect between input perplexity and translation quality

- Mechanism: The PROTES optimizer searches for low-likelihood Russian letter combinations that maximize the difference between the perplexity of the input (gibberish) and the output (meaningful English). The optimizer uses tensor train decomposition to efficiently explore the high-dimensional discrete search space without requiring gradients from the black-box translation API.
- Core assumption: Perplexity of gibberish in the source language correlates with the ability to generate unexpected but valid translations in the target language.

### Mechanism 2
- Claim: Combinations of individually translatable gibberish strings can create longer adversarial phrases that break back-translation.
- Mechanism: After finding individual "hallucinogens" (7-letter gibberish strings with meaningful English translations), the system combines multiple hallucinogens into longer phrases. These combinations maintain translation quality forward but fail during back-translation, creating a one-way translation vulnerability.
- Core assumption: The translation system treats each hallucinogen independently during forward translation but fails to reconstruct the original gibberish when translating back.

### Mechanism 3
- Claim: The tensor train decomposition enables efficient black-box optimization of high-dimensional discrete search spaces.

This avoids the curse of dimensionality in the 7-letter Russian alphabet search space.
- Core assumption: The tensor train format provides sufficient representational power while maintaining computational tractability for this specific optimization problem.
- Evidence anchors:
  - [section] "we use the global optimization method PROTES. It is based on the low-rank tensor train (TT) decomposition"

  - Quick check question: If a word has high perplexity according to GPT-2, does that mean it's more or less likely to be a real word?

  - Why needed here: The translation APIs are black-box systems, so traditional gradient-based attacks cannot be applied
  - Quick check question: What optimization strategy would you use if you can only query a function but cannot compute its gradients?

  - Why needed here: The search space for 7-letter Russian combinations is 33^7 ≈ 4.26e10 possible combinations, requiring efficient representation

## Architecture Onboarding

- Component map:
  GPT-2 model -> PROTES optimizer -> Translation API interface -> Result processing pipeline -> Evaluation framework

- Critical path:
  1. Initialize PROTES with random probability distribution over 7-letter combinations
  2. Sample candidates and query translation APIs for their English translations
  3. Compute perplexity scores and update PROTES distribution
  4. After optimization, collect top hallucinogens and test combinations
  5. Verify adversarial properties by testing back-translation

- Design tradeoffs:
  - Query budget vs. optimization quality: Limited to 1000 translations per system
  - Perplexity estimation accuracy vs. computational cost: GPT-2 provides good but not perfect estimates
  - Hallucinogen combination strategy: Manual selection vs. automated composition
  - Back-translation testing: Completeness vs. computational overhead

- Failure signatures:
  - Optimizer gets stuck in local minima with no meaningful translations
  - Translation systems start rejecting gibberish patterns after multiple queries
  - Perplexity estimation becomes unreliable for very unusual character combinations
  - Back-translation succeeds consistently, indicating no adversarial vulnerability

## Open Questions the Paper Calls Out

- Question: Can the proposed method of generating "hallucinogens" be extended to other language pairs beyond Russian-English?
- Basis in paper: [inferred] The paper demonstrates the method on Russian-English translation, but does not explore its applicability to other language pairs.
- Why unresolved: The authors only tested their approach on one language pair, so it's unclear if the method would be equally effective for other language combinations.
- What evidence would resolve it: Applying the method to generate hallucinogens for other language pairs (e.g. Spanish-English, Chinese-English) and evaluating the results would determine its broader applicability.

- What evidence would resolve it: Testing the generated hallucinogens on a variety of machine translation models, including different architectures and updated versions, would assess their robustness to model changes.

## Limitations

- The PROTES optimizer is not fully specified in terms of implementation details, making exact replication challenging
- The study only tests three translation systems and focuses solely on Russian-to-English translation, raising questions about generalizability
- The query budget of 1000 translations per system is relatively small for exploring the vast search space of 33^7 possible combinations
- The back-translation vulnerability is demonstrated but not systematically quantified across different hallucinogen combinations

## Confidence

**High Confidence**: The core finding that machine translation systems can produce meaningful outputs for nonsensical inputs is well-demonstrated. The success of the PROTES optimizer in finding hallucinogens that translate to English phrases is reproducible given the experimental setup.

**Medium Confidence**: The claim that combining hallucinogens creates back-translation vulnerabilities is supported but not systematically quantified. The specific hallucinogens identified may be sensitive to model updates or system changes over time.

**Low Confidence**: The general applicability of this attack method to other language pairs and translation systems is speculative. The long-term robustness of these adversarial examples against translation system updates is unknown.
