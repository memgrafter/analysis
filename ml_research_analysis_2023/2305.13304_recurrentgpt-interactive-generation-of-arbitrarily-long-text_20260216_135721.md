# RecurrentGPT: Interactive Generation of (Arbitrarily) Long Text

## Quick Facts
- arXiv ID: 2305.13304
- Source URL: https://arxiv.org/abs/2305.13304
- Authors: 
- Reference count: 40
- Key outcome: RECURRENT GPT simulates RNN recurrence using natural language prompts, enabling arbitrarily long text generation with large language models while maintaining coherence and enabling human interaction.

## Executive Summary
RECURRENT GPT addresses the fundamental limitation of Transformer models with fixed context windows by simulating the recurrence mechanism of RNNs using natural language building blocks. The system replaces vector-based LSTM components (cell state, hidden state, input, output) with natural language elements (content, plan, short-term memory, long-term memory) and uses prompt engineering to simulate the recurrence computation graph. This approach enables the generation of arbitrarily long texts while maintaining coherence and interpretability.

The method demonstrates significant improvements over baseline approaches, with human evaluations showing RECURRENT GPT produces more interesting and coherent long texts (3000-6000 words) across multiple genres. The natural language-based recurrence mechanism also enables interactive writing assistance by allowing users to observe and edit memories and plans, preventing error propagation and maintaining generation quality through human-AI collaboration.

## Method Summary
RECURRENT GPT simulates the recurrence mechanism of RNNs by replacing vector-based elements with natural language building blocks and using prompt engineering. The system maintains long-short term memory across timesteps, with each timestep generating a paragraph of text, updating short-term memory summarizing recent content, and retrieving relevant long-term memory from a VectorDB using semantic search. The method constructs input prompts by filling a template with the input content/plan and its internal long-short term memory, then generates new contents, plans, and updates the short-term memory. For long-term memory storage, the system embeds generated paragraphs using sentence-transformers and performs semantic search to retrieve relevant memories that fit within the LLM's context window.

## Key Results
- Human evaluation shows RECURRENT GPT significantly outperforms baselines in generating interesting and coherent long texts of 3000-6000 words across multiple genres
- The approach enables interactive writing assistance and personalized interactive fiction by allowing users to edit plans and memories
- RECURRENT GPT demonstrates the ability to generate arbitrarily long text while maintaining coherence, overcoming the fixed context window limitation of Transformer models

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Language-based recurrence simulates LSTM memory updates via natural language prompts, enabling arbitrarily long text generation without architectural changes.
- Mechanism: The system replaces LSTM vector components with natural language building blocks and uses prompt engineering to simulate the recurrence computation graph.
- Core assumption: Large language models can perform coherent memory updates and generation when provided with structured natural language prompts that mimic RNN computation.
- Evidence anchors: [abstract] "RECURRENT GPT replaces the vectorized elements...with natural language...and simulates the recurrence mechanism with prompt engineering." [section 2.1] "Long-Short Term Memory Similar to an LSTM, RECURRENT GPT maintains long-short term memory across timesteps."

### Mechanism 2
- Claim: Interactive human-computer interaction prevents error propagation and maintains generation quality through editable memory and plan components.
- Mechanism: Users can observe and edit the natural language memories and plans, allowing correction of model mistakes before they propagate to subsequent generations.
- Core assumption: Human intervention in editable language-based components can effectively prevent or correct generation errors that would otherwise accumulate in long sequences.
- Evidence anchors: [abstract] "Since human users can easily observe and edit the natural language memories, RECURRENT GPT is interpretable and enables interactive generation of long text." [section 2.3] "RECURRENT GPT enhances the interpretability of the recurrence mechanism in comparison to the vector-based recurrence mechanism employed in RNNs."

### Mechanism 3
- Claim: VectorDB-based long-term memory enables storage of arbitrarily long context by embedding and retrieving relevant paragraphs through semantic search.
- Mechanism: The system uses sentence-transformers to embed each generated paragraph into a vector database, allowing semantic search to retrieve relevant memories that fit within the LLM's context window.
- Core assumption: Semantic search over embedded paragraphs can effectively retrieve contextually relevant memories that maintain narrative coherence across long texts.
- Evidence anchors: [section 2.1] "Since the generated content can be arbitrarily long and cannot fit in the context size of LLMs, we implement the long-term memory in RECURRENT GPT with a VectorDB approach by embedding the content generated in each timestep with sentence-transformers." [section 2.2] "In particular, since the long-term memory cannot fit into the context size, we use the input plan as the query to perform a semantic search over the VectorDB-based long-term memory and fit a few most relevant contents into the prompt."

## Architecture Onboarding

- Component map: LLM backbone (ChatGPT/GPT-4) -> Prompt template engine -> VectorDB for long-term memory -> Short-term memory manager -> Human interaction interface -> Python orchestration code

- Critical path: 1. Receive input content/plan and memories 2. Perform semantic search on VectorDB 3. Construct prompt with all components 4. Generate new content, plan, and updated memories 5. Store updated memories in VectorDB 6. Return output to user

- Design tradeoffs:
  - Language-based vs. vector-based memory: More interpretable but potentially less efficient
  - VectorDB vs. in-context memory: Scales better but adds retrieval complexity
  - Human interaction vs. full automation: Better quality control but reduced efficiency

- Failure signatures:
  - Generation becomes repetitive or incoherent
  - Semantic search returns irrelevant memories
  - Prompt becomes too large for context window
  - Human interaction disrupts narrative flow

- First 3 experiments:
  1. Generate a 1000-word story with and without recurrence mechanism, measuring coherence and repetition
  2. Test VectorDB retrieval accuracy by querying for specific memory types and evaluating relevance
  3. Compare human editing effectiveness by having users correct model-generated errors at different frequencies

## Confidence

**High Confidence**: The core concept of replacing vector-based RNN components with natural language building blocks is well-defined and theoretically sound. The approach to using VectorDB for long-term memory is technically feasible and aligns with established practices in semantic search.

**Medium Confidence**: The human evaluation results showing RECURRENT GPT's superiority over baselines are plausible given the mechanism's design, but the lack of detailed evaluation protocols and baseline implementation details prevents stronger confidence.

**Low Confidence**: The autonomous generation capabilities and the effectiveness of the human simulator cannot be fully assessed without implementation details of the plan generation and revision process.
