# Interpreting Robustness Proofs of Deep Neural Networks

## Quick Facts
- arXiv ID: 2301.13845
- Source URL: https://arxiv.org/abs/2301.13845
- Reference count: 26
- Primary result: SuPFEx extracts ≤10 proof features for COLT-trained MNIST networks vs. original counts of 250-1000

## Executive Summary
This paper introduces SuPFEx, an algorithm that interprets neural network robustness proofs by identifying a small set of "sufficient proof features" that retain essential proof elements while removing spurious ones. The method works by iteratively pruning less important features based on their contribution to verification. Experiments show that standard networks' proofs rely on spurious input features, while adversarially trained networks filter out more spurious features. COLT-trained networks achieve the best results, combining empirical and provable robustness to selectively filter spurious features while retaining human-interpretable ones.

## Method Summary
SuPFEx extracts proof features by analyzing the first (l-1) layers of a neural network combined with abstract-domain verification. It computes intervals for neurons in the penultimate layer, then iteratively prunes features using a priority function based on their impact on the verification lower bound. The algorithm visualizes the most important features through gradient maps with respect to input pixels. The method is evaluated on MNIST and CIFAR-10 datasets across different training methods (standard, PGD, COLT, CROWN-IBP) using L∞-based local robustness properties.

## Key Results
- SuPFEx achieves proof feature set sizes of ≤10 in 100% of cases for COLT-trained MNIST networks
- Standard networks' proofs rely on spurious input features while adversarially trained networks filter them out
- COLT training produces the most effective proofs by selectively filtering spurious features while retaining human-interpretable ones
- The method successfully reduces proof feature counts from 250-1000 to ≤10 features while preserving verification

## Why This Works (Mechanism)

### Mechanism 1
- Claim: SuPFEx iteratively prunes proof features while preserving property verification using a priority function based on impact on verification lower bound
- Mechanism: Computes priority Pub(Fni) for each proof feature as maximum potential impact on verification lower bound Λ(A), then iteratively removes lowest-priority features in batches
- Core assumption: Lower-priority features are less critical for preserving verification when pruned
- Evidence anchors: Priority computation based on global upper bound estimation; concept of pruning based on feature importance is common in neural network interpretation
- Break condition: Inaccurate priority estimation may prune critical features, causing verification to fail

### Mechanism 2
- Claim: Proof features reveal meaningful differences in how training methods use input features to satisfy robustness properties
- Mechanism: Gradient visualization of proof features with respect to input pixels shows which regions are most important for each proof
- Core assumption: Gradients represent feature importance for proofs
- Evidence anchors: Gradient maps calculated over 100 samples; standard networks show non-zero gradients at spurious features
- Break condition: Misleading gradient visualizations or proof features not corresponding to meaningful input regions

### Mechanism 3
- Claim: COLT training produces proofs that selectively filter spurious features while retaining human-interpretable ones
- Mechanism: COLT networks create proofs relying on both semantically meaningful and discriminative features
- Core assumption: COLT training better distinguishes between spurious and meaningful features
- Evidence anchors: COLT proofs provide best of both worlds; experimental results support COLT superiority
- Break condition: COLT training doesn't produce better feature selection or subjective interpretation of "human-interpretable" features

## Architecture Onboarding

- Component map: N + V → Proof features F → SuPFEx (priority computation + iterative pruning) → Sufficiency-checked feature set F_S0 → Gradient visualization → Interpretation
- Critical path: Input network N and verifier V produce proof features F, which are processed by SuPFEx algorithm through priority computation and iterative pruning to yield sufficient feature set F_S0, then visualized through gradient maps for interpretation
- Design tradeoffs: Abstract domains provide scalability but less precision vs. exact methods; batch pruning offers efficiency but may miss optimal solutions; gradient visualization is computationally efficient but potentially misleading
- Failure signatures: Empty feature sets indicate verifier couldn't prove original property; gradient visualizations without clear patterns suggest features don't correspond to meaningful regions; identical top features across methods indicate lack of meaningful differences
- First 3 experiments: 1) Run SuPFEx on small standard MNIST network to verify feature reduction while preserving verification, 2) Compare gradient visualizations of standard vs. PGD-trained networks on same input, 3) Test sensitivity to batch size parameter on small network

## Open Questions the Paper Calls Out

- Open Question 1: How do proof feature interpretations scale to larger, more complex networks and datasets beyond MNIST and CIFAR-10?
  - Basis in paper: Scalability limited by verifier capabilities; currently cannot handle larger datasets like ImageNet
  - Why unresolved: Only evaluated on small networks; scaling requires verifier advances
  - What evidence would resolve it: Experiments on larger networks/datasets (e.g., ResNet on ImageNet) quantifying how interpretations change with size/complexity

- Open Question 2: Can the algorithm be modified to find smaller sufficient proof feature sets by incorporating additional heuristics?
  - Basis in paper: Current greedy heuristic produces approximate (not minimum) sets; suggests exploring additional heuristics
  - Why unresolved: Specific priority function and greedy approach may not be optimal
  - What evidence would resolve it: Comparative experiments evaluating different heuristics (simulated annealing, genetic algorithms) measuring set size and verification time

- Open Question 3: How do proof feature interpretations differ across different types of properties beyond local robustness?
  - Basis in paper: Focuses exclusively on local robustness properties; framework could theoretically apply to other properties
  - Why unresolved: Only examines one property type; different properties might yield different patterns
  - What evidence would resolve it: Applying SuPFEx to networks with different properties (fairness, safety) and comparing interpretations across property types

## Limitations
- Relies on sound but incomplete abstract-domain verifiers, creating asymmetric reliability
- Exclusive focus on L∞-norm robustness properties limits generalizability
- Subjective nature of "human-interpretable" features introduces uncertainty in qualitative assessments

## Confidence

- Mechanism 1: Medium - iterative pruning approach is well-established but specific priority function lacks extensive validation
- Mechanism 2: Low - gradient-based visualization can be misleading and connection to semantic meaning is not rigorously established
- Mechanism 3: Medium - COLT superiority claim supported by experiments but not independently verified
