# Reinforcement Learning in the Wild with Maximum Likelihood-based Model Transfer

## Quick Facts
- **arXiv ID:** 2302.09273
- **Source URL:** https://arxiv.org/abs/2302.09273
- **Reference count:** 40
- **Key outcome:** MLEMTRL achieves faster learning speed and near-optimal performance by transferring knowledge from source MDPs through constrained maximum likelihood estimation, with theoretical regret bounds in both realisable and non-realisable settings.

## Executive Summary
This paper proposes MLEMTRL, a novel approach for model transfer in reinforcement learning that uses constrained maximum likelihood estimation to estimate a target MDP model from a set of known source MDPs. The method leverages the convex hull of source models to construct a more expressive model class, allowing for better estimation of the target dynamics. Theoretically, the paper provides regret bounds for both realisable (target in convex hull) and non-realisable settings, showing that performance depends on both estimation error and realisability gap. Empirically, MLEMTRL demonstrates superior learning speed and near-optimal performance compared to learning from scratch, particularly when the target MDP is similar to the source models.

## Method Summary
MLEMTRL is a two-stage model transfer algorithm for reinforcement learning. In Stage 1, it uses constrained maximum likelihood estimation to estimate the target MDP model as a weighted mixture of source MDPs, with weights constrained to the probability simplex. The optimization is solved using Sequential Least-Squares Quadratic Programming (SLSQP). In Stage 2, it applies model-based planning (ValueIteration for tabular MDPs, RiccatiIteration for LQRs) to the estimated model to derive a policy. The method assumes access to multiple source MDPs and data collected from the target environment, and aims to minimize regret through accurate model estimation and planning.

## Key Results
- MLEMTRL achieves faster learning in new MDPs compared to learning from scratch
- Theoretical regret bounds are proven for both realisable and non-realisable settings
- Empirical results show near-optimal performance, especially when target MDP is similar to source models
- Superior learning speed improvements demonstrated on LQR-based environments compared to baselines

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Constrained maximum likelihood estimation over the convex hull of source MDPs yields an accurate target model when the true target lies within that hull.
- **Mechanism:** MLEMTRL constructs the target model as a weighted mixture of source models. By maximizing the likelihood of observed data under this constrained mixture, the estimator finds the model in the convex hull that best explains the target dynamics. This leverages the expressiveness of the full source model class rather than being limited to individual source models.
- **Core assumption:** The true target MDP is representable as a convex combination of source MDPs (realisable setting).
- **Evidence anchors:**
  - [abstract] "In the first stage, MLEMTRL uses a constrained Maximum Likelihood Estimation (MLE)-based approach to estimate the target MDP model using a set of known MDP models."
  - [section 5] "In this setting, the target MDP µ* is in the convex hull µ* ∈ C(Ms) of the source MDPs. Thus, with respect to Class I, we extend the parameter space considered in MLE to an infinite but compact parameter set."
  - [corpus] Weak - related work focuses on general transfer RL but not specifically on constrained MLE over convex hulls.
- **Break condition:** If the target MDP lies outside the convex hull of source models (non-realisable setting), the estimation error becomes bounded by the realisability gap rather than converging to zero.

### Mechanism 2
- **Claim:** Model-based planning using the estimated target model achieves near-optimal performance with regret bounds that depend on both estimation error and realisability gap.
- **Mechanism:** After estimating the target model via MLE, MLEMTRL applies standard model-based planning algorithms (ValueIteration for tabular MDPs, RiccatiIteration for LQRs) to the estimated model. The resulting policy's performance loss is bounded by a function of both the estimation error and the distance from the true target to the best representable model in the convex hull.
- **Core assumption:** The planning algorithm used (ValueIteration/RiccatiIteration) is optimal for the estimated MDP class and the estimated model is sufficiently accurate.
- **Evidence anchors:**
  - [abstract] "Theoretically, we prove worst-case regret bounds for MLEMTRL both in realisable and non-realisable settings."
  - [section 6] "Theorem 1 (Performance Gap for Non-Realisable Models) Let µ* = (S, A, R, T*, γ) be the true underlying MDP. Further, let µ = (S, A, R, T, γ) be the maximum likelihood estimator..."
  - [corpus] Weak - related work discusses regret bounds in RL but not specifically for model transfer with MLE.
- **Break condition:** If the estimation error or realisability gap is too large relative to the planning horizon and discount factor, the regret bounds may become vacuous, leading to poor performance.

### Mechanism 3
- **Claim:** Transfer learning improves learning speed and jumpstart performance compared to learning from scratch, especially when source and target models are similar.
- **Mechanism:** By leveraging knowledge from source models through MLE-based estimation, MLEMTRL starts with a better initial model of the target environment than a method that learns from scratch. This results in faster convergence to near-optimal policies and better early performance.
- **Core assumption:** The source models contain useful information about the target environment, i.e., the target MDP is sufficiently similar to the source models.
- **Evidence anchors:**
  - [abstract] "We empirically demonstrate that MLEMTRL allows faster learning in new MDPs than learning from scratch and achieves near-optimal performance depending on the similarity of the available MDPs and the target MDP."
  - [section 7] "In the LQR-based environments, we can see a clear superiority of MLEMTRL compared to all baselines in terms of learning speed improvements, and in some cases, asymptotic performance."
  - [corpus] Weak - related work discusses transfer learning benefits but not specifically for MLE-based model transfer in RL.
- **Break condition:** If the source models are very dissimilar to the target environment, the transferred knowledge may be misleading, resulting in worse performance than learning from scratch.

## Architecture Onboarding

- **Component map:**
  Data Collection Module -> Model Estimation Engine -> Planning Module -> Performance Evaluation

- **Critical path:**
  1. Initialize with source MDPs and empty dataset
  2. Collect initial data from target environment
  3. Run MLE optimization to estimate target model
  4. Apply model-based planning to get policy
  5. Execute policy in environment, collect new data
  6. Repeat steps 3-5 until convergence

- **Design tradeoffs:**
  - Source model quality vs. computational complexity: More source models provide better expressiveness but increase MLE optimization time
  - Realisability assumption vs. generality: Realisable setting provides strong guarantees but limits applicability to non-realisable cases
  - Model-based vs. model-free planning: Model-based provides theoretical guarantees but may be less sample efficient than model-free methods in some cases

- **Failure signatures:**
  - Poor performance despite many iterations: Likely indicates non-realisable setting or very dissimilar source/target models
  - MLE optimization failing to converge: May indicate ill-conditioned likelihood function or insufficient data
  - Planning algorithm failing: Could indicate inaccurate model estimation or inappropriate planning algorithm for the MDP class

- **First 3 experiments:**
  1. Implement MLEMTRL on a simple tabular MDP (like Chain) with clearly similar source models to verify basic functionality
  2. Test on a non-realisable setting to observe performance degradation and validate theoretical bounds
  3. Compare learning speed against PSRL baseline on a moderate complexity LQR problem to demonstrate practical benefits

## Limitations
- Theoretical guarantees rely heavily on the realisability assumption, which may not hold in practical scenarios
- Computational complexity scales poorly with the number of source models and state-action space size
- Experimental validation is restricted to relatively simple environments (tabular MDPs and low-dimensional LQRs)

## Confidence
- **High confidence:** The theoretical framework for constrained MLE over convex hulls of MDPs and the regret bounds in realisable settings
- **Medium confidence:** The empirical demonstration of improved learning speed and performance in non-realisable settings
- **Medium confidence:** The comparative performance against baselines, given limited implementation details
