# Gesture Recognition with mmWave Wi-Fi Access Points: Lessons Learned

## Quick Facts
- arXiv ID: 2306.17062
- Source URL: https://arxiv.org/abs/2306.17062
- Reference count: 40
- Primary result: mmWave Wi-Fi beam SNR achieves 96.7% gesture classification accuracy in single environment

## Executive Summary
This paper explores using mmWave (60 GHz) Wi-Fi signals for gesture recognition and pose estimation in extended reality applications. The authors extract spatial beam SNRs from IEEE 802.11ad devices during sector sweep operations and classify 10 XR-related gestures performed by three people in two environments. A custom CNN architecture achieves 96.7% accuracy in controlled settings, though the model requires re-training when environments change, unlike CSI-based approaches which generalize better.

## Method Summary
The authors collect mmWave beam SNR data from 36 sectors using IEEE 802.11ad routers performing periodic sector sweeps, along with CSI data from IEEE 802.11ac routers for comparison. A 7-layer CNN based on GoogLeNet with two inception modules processes raw SNR matrices (y×36) and CSI matrices directly without preprocessing. The model uses 1D convolutions, ReLU activations, and dropout, trained with Adam optimizer (lr=3e-4, batch size 16-64) for 150 epochs with learning rate scheduling.

## Key Results
- Beam SNR-based gesture classification achieves 96.7% accuracy in single environment
- CSI-based classification achieves 100% accuracy in single environment
- CSI features generalize across environments without re-training, while beam SNR features do not

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Beam SNRs capture environment changes caused by gestures, enabling classification
- Mechanism: During sector sweep, routers record SNR for each of 36 sectors. Gesture movements alter the channel between transmitter and receiver, changing received power patterns that are directly captured and fed to DNN
- Core assumption: Gesture movements cause detectable, repeatable changes in beam SNR patterns across sectors
- Evidence anchors:
  - [abstract] "We extract spatial beam signal-to-noise ratios (SNRs) from the periodic beam training employed by IEEE 802.11ad devices."
  - [section] "IEEE 802.11ad devices use a sector sweep algorithm to determine signal strength per sector... The beam SNR is then extracted from the sector sweep frames."
- Break condition: If gesture movements are too subtle or SNR changes fall below noise floor, DNN cannot distinguish gestures reliably

### Mechanism 2
- Claim: DNN extracts discriminative features from beam SNR time series without preprocessing
- Mechanism: GoogLeNet with 1D convolutions and inception modules learns spatial and temporal patterns in SNR matrix. 1×1 bottleneck layers reduce dimensionality while 3×1 and 5×1 kernels capture local and global temporal dependencies
- Core assumption: Temporal evolution of SNR patterns across sectors contains sufficient discriminative information
- Evidence anchors:
  - [section] "We use GoogLeNet with 2 inception modules... The 1×1 convolutions... reduce the number of output channels... These convolutions don't change the size of the data. At the end, the outputs from two 1×1, 3×1, and 5×1 convolutions are concatenated across channels."
  - [abstract] "To extract features from the CSI and the beam SNR, we leverage a deep neural network (DNN)."
- Break condition: If dataset is too small or SNR patterns are too similar across gestures, DNN cannot learn meaningful features

### Mechanism 3
- Claim: CSI generalizes across environments and people without retraining, while beam SNR does not
- Mechanism: CSI captures fine-grained multipath information with high spatial and frequency resolution (256 subcarriers). This rich information contains environment-independent features that DNN can learn and transfer. Beam SNR, being coarser (36 sectors) and more sensitive to direct path changes, captures environment-specific signatures
- Evidence anchors:
  - [abstract] "Our experiments reveal that features from the CSI generalize without additional re-training, while those from beam SNRs do not."
  - [section] "We conclude that the environment impacts the beam SNRs significantly more than the CSI."
- Break condition: If environment changes are small or gesture movements dominate signal, beam SNR might generalize better than expected

## Architecture Onboarding

- Component map: TCP traffic generation -> Beam SNR collection (36 sectors) -> Raw data input to CNN -> Classification
- Critical path: Data collection → DNN feature extraction → classification
- Design tradeoffs:
  - Low sample rate (beam training triggered by traffic) vs. higher accuracy with more data
  - Mid-grained SNR (36 sectors) vs. fine-grained CSI (256 subcarriers) - SNR is simpler but less robust across environments
  - Direct raw data input vs. preprocessing - reduces engineering effort but may limit performance
- Failure signatures:
  - Low accuracy on similar gestures suggests insufficient feature discrimination
  - Poor generalization across environments indicates over-reliance on environment-specific features
  - High variance with different users suggests need for more diverse training data
- First 3 experiments:
  1. Train DNN on beam SNR data from one user in home environment, test on same user in same environment
  2. Train DNN on CSI data from one user, test on different user in same environment to check generalization
  3. Train DNN on CSI data from home environment, test on office environment to validate cross-environment generalization

## Limitations
- Narrow dataset scope: Only three users and two controlled environments tested
- Lack of cross-validation: Results may not generalize to more diverse real-world scenarios
- Incomplete architectural specifications: CNN implementation details lack precision for exact reproduction

## Confidence

- **High confidence**: 96.7% accuracy claim for mmWave beam SNR gesture classification in controlled settings is well-supported
- **Medium confidence**: CSI generalization advantage is demonstrated but not thoroughly mechanistically explained
- **Low confidence**: Scalability to more users, environments, and gesture types remains unproven

## Next Checks

1. **Cross-environment validation with augmented data**: Train on home environment data with data augmentation (rotation, scaling, noise injection) and evaluate on office environment. Compare with models trained on larger, more diverse datasets.

2. **Architecture ablation study**: Systematically vary CNN architecture (different kernel sizes, number of inception modules, preprocessing methods) to identify essential components. Test whether raw SNR/CSI input is truly optimal or if feature engineering could improve results.

3. **Real-world deployment simulation**: Create simulated multi-user, multi-environment scenario with varying distances, occlusions, and interference sources. Measure classification accuracy degradation and identify failure modes not apparent in controlled experimental setup
