# Knowledge Graph Embedding with Electronic Health Records Data via Latent Graphical Block Model

## Quick Facts
- **arXiv ID**: 2305.19997
- **Source URL**: https://arxiv.org/abs/2305.19997
- **Reference count**: 40
- **Primary result**: Proposes a latent graphical block model for knowledge graph embedding from EHR data that enables automatic clustering of synonymous features while preserving conditional dependency structure

## Executive Summary
This paper addresses the challenge of deriving generalizable knowledge from electronic health records (EHR) data, which is fragmented and detailed with a large number of unique features. The authors propose a latent graphical block model (LGBM) that infers the conditional dependency structure among EHR features through a two-layer approach. The first layer provides semantic embedding vector representation for EHR features, while the second layer overlays a graphical block model on these latent vectors, enabling automatic clustering of synonymous features. The method is designed to be computationally efficient by learning from aggregated co-occurrence statistics rather than individual patient records.

The proposed approach demonstrates both statistical and computational efficiency, with theoretical guarantees for estimator rates and perfect recovery of block structure. The LGBM framework is validated through simulations and real EHR data analyses, showing strong performance in finite samples. The model provides a scalable solution for knowledge graph construction from EHR data while maintaining interpretability through its block-structured representation of feature relationships.

## Method Summary
The LGBM method consists of three main steps: (1) Compute a co-occurrence matrix from EHR data using a sliding window approach, then derive a shifted positive PMI matrix; (2) Apply spectral decomposition to the PMI matrix to obtain initial embedding vectors, followed by block clustering using the COD algorithm; (3) Refine the covariance estimate by averaging PMI entries within clusters and apply the CLIME estimator to obtain the precision matrix and knowledge graph. The method uses four categories of EHR codes (ICD, medication prescriptions, laboratory tests, and CPT procedures) with mappings to standardized terminologies (PheCodes, CCS categories, RxNorm, and LOINC codes). Performance is evaluated using Rand index for cluster recovery, average relative error for precision matrix estimation, and F-score for support recovery.

## Key Results
- Establishes statistical rates for PMI matrix estimators and shows perfect recovery of block structure under the model assumptions
- Demonstrates clustering recovery with high Rand index accuracy in both independent and Erdos-Renyi graph structures
- Achieves low average relative error in precision matrix estimation through the block-structured refinement approach
- Shows computational efficiency by learning from aggregated co-occurrence statistics rather than subject-level data

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The LGBM enables efficient knowledge graph embedding from EHR data by avoiding computationally prohibitive subject-level training while preserving conditional dependency structure
- Mechanism: Uses a two-layer structure where the first layer provides semantic embedding vectors (SEVs) for EHR features based on co-occurrence patterns, and the second layer overlays a graphical block model on these latent SEVs, allowing learning from aggregated co-occurrence matrices
- Core assumption: Co-occurrence patterns in EHR data sufficiently capture the conditional dependency structure among features
- Evidence anchors: [abstract] and [section] both state "We propose to infer the conditional dependency structure among EHR features via a latent graphical block model (LGBM)" and propose learning based on the empirical PMI matrix
- Break condition: If co-occurrence patterns fail to capture conditional dependencies due to confounding variables or temporal dynamics not reflected in co-occurrence, embedding quality degrades significantly

### Mechanism 2
- Claim: The block structure enables automatic grouping of near-synonymous EHR features, improving interpretability and reproducibility
- Mechanism: The second layer assumes a block-structured Gaussian graphical model where features within the same cluster share similar behavior in their embedding vectors, allowing automatic identification of clinically meaningful code concepts
- Core assumption: Near-synonymous EHR features exhibit sufficiently similar co-occurrence patterns to be grouped together by the block structure
- Evidence anchors: [abstract] states "The block structures on the graphical model also allows us to cluster synonymous features in EHR" and [section] explains grouping into clinically meaningful code concepts
- Break condition: If clinically distinct features have similar co-occurrence patterns (or vice versa), automatic grouping will produce clinically meaningless or incorrect clusters

### Mechanism 3
- Claim: Statistical properties of the PMI matrix approximation enable consistent estimation of both conditional dependency structure and clustering recovery
- Mechanism: Establishes theoretical rates showing that the empirical PMI matrix converges to the true covariance matrix of embedding vectors, enabling consistent estimation of precision matrix and perfect recovery of block structure
- Core assumption: Concentration properties of the empirical PMI matrix to the true PMI matrix are sufficient to guarantee consistent estimation of underlying graphical model parameters
- Evidence anchors: [abstract] states "We establish the statistical rates of the proposed estimators and show the perfect recovery of the block structure" and [section] discusses statistical rates of PMI matrix and knowledge network
- Break condition: If sample size is insufficient relative to number of features and embedding dimension, concentration bounds fail and estimation consistency is lost

## Architecture Onboarding

- **Component map**: Co-occurrence matrix computation -> PMI matrix estimation and spectral decomposition -> Block clustering algorithm -> Precision matrix estimation using CLIME
- **Critical path**: The most critical computational path is the PMI matrix computation from co-occurrence counts, followed by the clustering algorithm that determines the block structure, as errors here propagate to all downstream estimation
- **Design tradeoffs**: Trades off computational efficiency (learning from aggregated statistics rather than patient-level data) against potential information loss from not using individual patient trajectories, and trades off model complexity (two-layer structure) against estimation accuracy
- **Failure signatures**: Poor clustering recovery (Rand index below 90%), large relative error in precision matrix estimation (>10%), failure to recover the true block structure, or inability to scale to very large numbers of features
- **First 3 experiments**:
  1. Validate PMI matrix concentration bounds on synthetic data with known covariance structure
  2. Test clustering recovery accuracy across different graph structures (independent vs. Erdos-Renyi) and cluster sizes
  3. Evaluate precision matrix estimation accuracy with and without using the block structure information

## Limitations

- **Data requirements**: Heavy reliance on sufficient co-occurrence data to estimate PMI matrix accurately, with performance potentially degrading on sparse clinical datasets
- **Computational scalability**: Quadratic growth in complexity with number of features, with unclear scalability to full EHR code spaces of 10,000+ unique codes
- **Clinical validity assumptions**: Automatic grouping assumes clinical similarity correlates with co-occurrence patterns, which may not hold when clinically distinct codes co-occur frequently

## Confidence

- Block clustering algorithm performance under assumed model conditions
- Computational efficiency advantage of learning from aggregated statistics

**Medium Confidence** (supported by theory but limited empirical validation):
- Perfect recovery of block structure in finite samples under practical conditions
- Clinical interpretability of automatically generated code clusters
- Generalizability of results to real-world EHR datasets with varying characteristics

**Low Confidence** (minimal empirical support):

- Scalability to very large code spaces (10,000+ features)
- Robustness to temporal dynamics and non-stationary code usage patterns
