# Unlocking Context Constraints of LLMs: Enhancing Context Efficiency of LLMs with Self-Information-Based Content Filtering

## Quick Facts
- arXiv ID: 2304.12102
- Source URL: https://arxiv.org/abs/2304.12102
- Reference count: 5
- Key outcome: Selective Context achieves up to 50% context reduction with ROUGE-1 scores above 0.5 and BERT scores around 0.9, maintaining strong performance across summarisation, question answering, and conversation tasks.

## Executive Summary
This paper introduces Selective Context, a novel method for enhancing context efficiency in large language models (LLMs) by filtering out less informative content using self-information. The approach computes self-information for lexical units within a context and retains the most informative ones based on a percentile threshold. Evaluated across Arxiv papers, BBC news, and ShareGPT datasets, Selective Context demonstrates strong performance with up to 50% context reduction, showing only minor performance drops compared to original context while significantly improving computational efficiency.

## Method Summary
Selective Context enhances LLM context efficiency by computing self-information for lexical units (tokens, phrases, or sentences) using a base language model. The method merges tokens into lexical units, calculates self-information for each unit, ranks them, and applies percentile-based filtering to retain only the most informative content. This approach is evaluated on summarization, question answering, context reconstruction, and conversation tasks across three datasets, comparing performance at different context reduction ratios (0.2, 0.35, 0.5, 0.65, 0.8) using BLEU, METEOR, ROUGE, and BERTScore metrics.

## Key Results
- Selective Context achieves up to 50% context reduction while maintaining strong performance across multiple tasks
- At 35% reduction, ROUGE-1 scores remain above 0.5 and BERT scores around 0.9
- The method outperforms random filtering baselines and shows consistent results across Arxiv papers, BBC news, and ShareGPT datasets

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Selective Context reduces context length by filtering out less informative content using self-information, enabling LLMs to process longer documents or extended conversations without significant performance loss.
- Mechanism: Self-information is computed for lexical units (tokens, phrases, or sentences) using a base language model. Lexical units are ranked by self-information and a percentile-based threshold filters out the least informative content, retaining only those with self-information above the percentile.
- Core assumption: Self-information computed by a base language model (e.g., Curie) is an accurate proxy for informativeness of lexical units to LLMs (e.g., ChatGPT).
- Evidence anchors:
  - [abstract]: "Selective Context employs a base language model to compute self-information for lexical units (sentences, phrases, or tokens) in a context and use it to evaluate their informativeness."
  - [section]: "Selective Context employs a base language model to compute self-information for lexical units (sentences, phrases, or tokens) in a context and use it to evaluate their informativeness."
- Break condition: If the base model's self-information computation does not correlate well with the LLM's understanding of informativeness, or if the percentile-based filtering is too aggressive, leading to loss of critical context.

### Mechanism 2
- Claim: The percentile-based filtering approach is more flexible and adaptive than fixed thresholds or top-k selection, allowing Selective Context to retain the most informative content based on the distribution of self-information values in the given context.
- Mechanism: Lexical units are ranked by self-information, and the p-th percentile is computed. Only units with self-information greater than or equal to this percentile are retained, constructing a filtered context.
- Core assumption: The distribution of self-information values in a context is indicative of the informativeness of its lexical units.
- Evidence anchors:
  - [section]: "Instead of using a fixed threshold or retaining a fixed number of topk lexical units, we recommend to use a percentile-based filtering approach to adaptively select the most informative content."
  - [section]: "The percentile-based filtering is a more flexible approach to retain the most informative content depending on the distribution of self-information values in the given context."
- Break condition: If the self-information distribution does not reflect true informativeness, or if the percentile chosen is too high, leading to excessive information loss.

### Mechanism 3
- Claim: LLMs can infer missing information based on contextual clues and prior knowledge acquired from their pre-training, allowing them to answer queries correctly even with less informative content deleted.
- Mechanism: By retaining only the most informative content, LLMs leverage their pre-trained knowledge to fill in gaps, maintaining performance despite reduced context length.
- Core assumption: LLMs have sufficient prior knowledge to infer missing information when provided with a context containing only the most informative content.
- Evidence anchors:
  - [abstract]: "Our results demonstrate that Selective Context significantly enhances the efficiency of LLMs, allowing them to handle long documents and extended conversations with only minor sacrifices in generation quality."
  - [section]: "Fortunately our experiments reveal that LLMs do not need all content in a document or the entire conversation history to answer users’ queries. As shown in Figure 1, LLMs are able to generate the expected answer even with relevant information deleted."
- Break condition: If the retained context lacks sufficient clues for the LLM to infer missing information, or if the task requires specific details that are filtered out.

## Architecture Onboarding

- Component map:
  Input context -> Base language model (Curie) -> Token self-information computation -> Lexical unit merging -> Lexical unit self-information calculation -> Percentile-based filtering -> Filtered context output

- Critical path:
  1. Compute self-information for each token in the context.
  2. Merge tokens into lexical units (phrases/sentences).
  3. Calculate self-information for each lexical unit.
  4. Rank lexical units by self-information.
  5. Compute the p-th percentile of self-information values.
  6. Retain lexical units with self-information ≥ p-th percentile.

- Design tradeoffs:
  - Balancing reduction ratio (p) vs. performance loss.
  - Choosing the appropriate lexical unit level (token, phrase, or sentence) for filtering.
  - Selecting the base language model for self-information computation.

- Failure signatures:
  - Significant performance drop in LLM tasks despite context reduction.
  - Inability to reconstruct original context from filtered context.
  - Inconsistent results across different data sources or tasks.

- First 3 experiments:
  1. Compare Selective Context with different reduction ratios (0.2, 0.35, 0.5) on a summarisation task using the BBC News dataset.
  2. Evaluate the impact of lexical unit level (phrase vs. sentence) on the effectiveness of Selective Context using the Arxiv dataset.
  3. Test Selective Context on a conversation task using the ShareGPT dataset to assess its performance in extended conversations.

## Open Questions the Paper Calls Out

The paper does not explicitly call out open questions, but several areas remain unexplored:
- Cross-linguistic generalization: How does Selective Context perform across different language families?

## Limitations

- The method's reliance on self-information computed by a base language model assumes this metric accurately reflects informativeness to downstream LLMs, but this correlation is not empirically validated.
- Performance degradation is more significant for tasks requiring fine-grained detail (like certain question answering scenarios) compared to summarization tasks.
- The paper does not address computational overhead or latency implications of the additional self-information computation step.

## Confidence

- **High**: The core claim that Selective Context can reduce context length while maintaining reasonable performance is well-supported by the experimental results across multiple datasets and tasks.
- **Medium**: The assertion that percentile-based filtering is more flexible than fixed thresholds is reasonable given the methodology, but lacks direct comparative analysis with alternative filtering approaches.
- **Low**: The claim that LLMs can reliably infer missing information from contextual clues is primarily supported by observed performance rather than theoretical justification or ablation studies.

## Next Checks

1. Conduct ablation studies comparing Selective Context's percentile-based filtering against fixed threshold and top-k approaches to empirically validate the claimed flexibility advantage.
2. Test the method's performance when using different base language models (e.g., GPT-2, LLaMA) for self-information computation to verify the robustness of the approach across model choices.
3. Evaluate Selective Context on tasks requiring precise factual recall (e.g., medical QA, legal document analysis) to determine the method's limitations in domains where information loss is more critical.
