# CEnt: An Entropy-based Model-agnostic Explainability Framework to Contrast Classifiers' Decisions

## Quick Facts
- arXiv ID: 2301.07941
- Source URL: https://arxiv.org/abs/2301.07941
- Reference count: 6
- Key outcome: CEnt achieves better proximity rates than existing methods while maintaining low latency, high attainability, and zero constraint violations.

## Executive Summary
CEnt is a model-agnostic method for generating counterfactual explanations that satisfy immutability, semi-immutability, and attainability constraints. It uses a variational autoencoder to learn a manifold-like distance for local sampling, trains a decision tree to approximate the model locally, and applies graph search to find minimal feature changes that alter predictions while maintaining low entropy. The method generates diverse counterfactuals without requiring gradient access to the black-box model. Experiments on four real-world datasets show CEnt achieves better proximity rates than existing methods while maintaining low latency, high attainability, and zero constraint violations.

## Method Summary
CEnt generates counterfactual explanations by first training a VAE on the dataset to learn a latent representation that reflects data density. For a given input instance, it samples k neighbors in the latent space, trains a decision tree on these neighbors to approximate the black-box model locally, and constructs a weighted graph from the decision tree nodes. The graph encodes feature edit costs, immutability constraints (infinite weight for invalid edits), and custom costs. A one-to-many shortest path search (Dijkstra's algorithm) finds the minimal cost path from the original class to the target class, translating into a set of feature changes that flip the prediction. The method is extended to image and text data through appropriate adaptations of the VAE and sampling strategies.

## Key Results
- CEnt achieves better proximity rates (l0, l2, VAE-distance) than existing methods on four real-world datasets
- The method maintains zero constraint violations for immutability and semi-immutability constraints
- CEnt demonstrates high attainability (yNN) and low latency while generating diverse counterfactuals
- Extension to image data (MNIST, Fashion MNIST) successfully derives visual contrasts
- Application to text data (20 Newsgroups) detects classifier vulnerabilities through adversarial attacks

## Why This Works (Mechanism)

### Mechanism 1
The variational autoencoder learns a manifold-like distance that reflects data density, enabling more realistic local sampling for counterfactual generation. By training a VAE on the dataset, the model learns to encode data points into a latent space where Euclidean distances approximate the underlying data manifold. This latent space is then used to sample k neighbors around the input instance, ensuring that generated counterfactuals are plausible and attainable within the data distribution.

### Mechanism 2
The decision tree approximation captures local decision boundaries while enabling interpretable rule extraction for counterfactual paths. A decision tree is trained on the k sampled neighbors to approximate the black-box model locally. Each internal node represents a feature split, and leaf nodes represent class predictions. The tree structure allows the extraction of minimal feature changes needed to alter the prediction, with edge weights encoding edit costs and constraints.

### Mechanism 3
Graph search on the decision tree with weighted edges finds the minimal edit path from the original class to the target class. A directed weighted graph is constructed from the decision tree nodes. Edges are weighted based on feature edit costs, semi-immutability constraints (infinite weight for invalid edits), and custom costs. A one-to-many shortest path search (Dijkstra's algorithm) is then used to find the minimal cost path from the original class to the target class, translating into a set of feature changes that flip the prediction.

## Architecture Onboarding

- Component map: VAE -> Local sampler -> Decision tree trainer -> Graph constructor -> Graph searcher -> Counterfactual decoder
- Critical path:
  1. Train VAE on the dataset
  2. Encode input instance into latent space
  3. Sample k neighbors in latent space
  4. Train decision tree on sampled neighbors
  5. Construct weighted graph from decision tree
  6. Perform shortest path search to find counterfactuals
  7. Decode counterfactuals from latent space
- Design tradeoffs:
  - VAE architecture: Deeper VAEs may capture more complex data distributions but increase training time and risk overfitting
  - k value: Larger k provides better local approximation but increases computational cost
  - Decision tree depth: Shallower trees are more interpretable but may underfit the local neighborhood
  - Graph edge weights: Balancing feature costs and constraints affects the diversity and plausibility of generated counterfactuals
- Failure signatures:
  - Poor VAE reconstruction: Indicates the VAE is not learning a meaningful latent representation
  - Decision tree accuracy < 90%: Suggests the tree is not capturing the model's behavior well in the local neighborhood
  - No counterfactual found: Implies the graph search failed to find a valid path or the constraints are too restrictive
  - Generated counterfactuals are unrealistic: Indicates the latent space or sampling strategy is not reflecting the true data distribution
- First 3 experiments:
  1. Train VAE on a subset of the Adult dataset and visualize the latent space to assess if it captures meaningful structure
  2. Sample neighbors around an instance from the Adult dataset using the VAE and train a decision tree to check if it accurately approximates the model's predictions
  3. Construct the graph from the decision tree and perform a shortest path search to generate a counterfactual for an instance from the Adult dataset, verifying that it flips the prediction and satisfies constraints

## Open Questions the Paper Calls Out
The paper doesn't explicitly call out open questions, but three important questions emerge from the work:
1. How does CEnt's performance vary with different VAE architectures across various data types?
2. Can CEnt maintain effectiveness when applied to high-dimensional tabular data with hundreds or thousands of features?
3. How does CEnt perform when the underlying data distribution shifts or when the model is retrained on new data?

## Limitations
- VAE architecture and hyperparameters are not fully specified, requiring dataset-specific tuning
- Edge weighting scheme in graph construction is only partially described, particularly for custom costs and semi-immutability
- Performance on high-dimensional data (hundreds/thousands of features) is not evaluated
- The paper relies on empirical validation without theoretical guarantees for constraint satisfaction

## Confidence
- High Confidence: The core mechanism of using VAE for manifold distance approximation and decision tree for local approximation is well-established in the literature
- Medium Confidence: The graph search approach for finding minimal counterfactuals is sound, but implementation details for constraint encoding are incomplete
- Medium Confidence: Experimental results show strong performance metrics, though some metrics (like redundancy) require additional validation procedures not fully detailed
