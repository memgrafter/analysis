# Text-Blueprint: An Interactive Platform for Plan-based Conditional Generation

## Quick Facts
- **arXiv ID**: 2305.00034
- **Source URL**: https://arxiv.org/abs/2305.00034
- **Reference count**: 15
- **Key outcome**: Text-Blueprint is a web-based interactive system for query-focused summarization that uses a sequence of question-answer pairs as a blueprint plan to guide text generation.

## Executive Summary
Text-Blueprint is an interactive web-based platform that addresses challenges in query-focused summarization by using plan-based conditional generation. The system generates summaries guided by blueprint plans consisting of question-answer pairs, allowing users to inspect, edit, and control the output. Three model variants are implemented: end-to-end, iterative, and interactive, with the interactive model enabling users to input custom questions. The approach provides an interpretable intermediate representation that helps reduce hallucinations and irrelevancies while making the summarization process more user-friendly.

## Method Summary
The Text-Blueprint system uses LongT5 models fine-tuned on the AQuaMuSe dataset to implement three variants of blueprint-based summarization. The end-to-end model generates summaries directly from queries, the iterative model generates summaries question by question, and the interactive model allows user input for custom questions. A web interface enables users to modify the blueprint plan and observe the impact on generated summaries. The system includes a document retrieval component to provide relevant context for the summarization task.

## Key Results
- The interactive model allows users to generate multiple summaries by modifying blueprint plans
- The system reduces hallucinations and irrelevancies through interpretable intermediate representations
- Users can directly observe the impact of plan changes on output text quality

## Why This Works (Mechanism)
The system works by decomposing the summarization task into a series of question-answer pairs that serve as a blueprint for text generation. This intermediate representation makes the generation process more interpretable and controllable. By allowing users to modify the blueprint, the system enables iterative refinement of summaries while maintaining relevance to the original query.

## Architecture Onboarding

Component map: User Interface -> Blueprint Model -> LongT5 Encoder-Decoder -> Document Retriever -> Document Corpus

Critical path: User Query → Document Retrieval → Blueprint Generation → Text Generation → User Interface

Design tradeoffs: The system trades model complexity for interpretability by using intermediate blueprint representations. The interactive variant sacrifices some generation efficiency for user control. The document retrieval system adds latency but improves summary relevance.

Failure signatures:
- Hallucinations occur when blueprint questions are too vague or unsupported by documents
- Irrelevancies appear when document retrieval fails to find pertinent information
- Generation failures happen when blueprint sequences exceed model length constraints
- Interface issues arise from slow document retrieval or model inference times

First experiments:
1. Generate blueprint plans from simple queries and documents to verify basic functionality
2. Test end-to-end model on short documents to establish baseline performance
3. Validate interactive model can handle user-input questions and generate corresponding text
