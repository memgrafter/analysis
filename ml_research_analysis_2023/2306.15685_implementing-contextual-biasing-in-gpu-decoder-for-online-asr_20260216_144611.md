# Implementing contextual biasing in GPU decoder for online ASR

## Quick Facts
- arXiv ID: 2306.15685
- Source URL: https://arxiv.org/abs/2306.15685
- Reference count: 0
- Key outcome: Achieved 13.4% relative improvement in EntityWER on Earnings21 dataset

## Executive Summary
This paper presents a method for integrating contextual biasing into GPU-based speech recognition decoders without requiring lattice generation. The approach dynamically adjusts arc weights in the decoding graph based on contextual information, enabling efficient rescoring of partial hypotheses. By storing indices of arcs to be boosted for each context and applying a discounting offset during decoding, the method achieves similar entity recognition improvements compared to lattice composition approaches while maintaining GPU decoding speed advantages.

## Method Summary
The authors propose a GPU-based contextual biasing technique that modifies the decoding graph weights dynamically during inference. Instead of generating lattices and performing offline rescoring, the method stores indices of arcs associated with each context entry. During decoding, these stored indices are used to apply weight boosts to relevant arcs in real-time. A discounting offset parameter controls the magnitude of these adjustments. This approach allows flexible integration of contextual information while preserving the computational efficiency of GPU decoding.

## Key Results
- 13.4% relative improvement in EntityWER on Earnings21 dataset
- Similar performance to lattice composition approaches for contextual biasing
- Maintains GPU decoding speed advantage over lattice-based methods

## Why This Works (Mechanism)
The method works by pre-computing which arcs in the decoding graph correspond to each context entry and storing these indices. During decoding, when a context entry becomes active, the decoder applies weight boosts to the corresponding arcs using a discounting offset. This dynamic adjustment influences the search path without requiring expensive lattice generation and composition steps, making contextual biasing computationally feasible for real-time GPU decoding.

   - Why needed: Balances context influence against overall recognition accuracy
   - Quick check: Test different offset values on held-out data

3. **Partial hypothesis rescoring**: Dynamic weight adjustment during beam search
   - Why needed: Allows real-time integration of contextual information
   - Quick check: Monitor hypothesis changes when contexts activate

4. **GPU memory management**: Storing arc indices for multiple contexts
   - Why needed: Critical for maintaining decoding speed
   - Quick check: Measure memory usage with varying context set sizes

## Architecture Onboarding

**Component Map**: Context Database -> Arc Index Mapping -> GPU Decoder -> Hypothesis Output

**Critical Path**: Context activation detection → Arc index lookup → Weight adjustment → Beam search continuation

**Design Tradeoffs**: Memory vs. Speed (storing more arc indices improves flexibility but increases memory usage), Context Specificity vs. Generalizability (highly specific contexts may not transfer well)

**Failure Signatures**: Poor entity recognition despite context availability (likely indexing errors), Decoding speed degradation (excessive memory operations), Context conflicts (overlapping contexts with contradictory boosts)

**First 3 Experiments**:
1. Validate arc indexing accuracy by comparing boosted arcs against expected context mappings
2. Benchmark memory usage and decoding speed with context sets of increasing size (100, 1000, 10000 entries)
3. Test performance across different context types (short phrases, long entities, common vs. rare words)
