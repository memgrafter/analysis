# Bi-level Multi-objective Evolutionary Learning: A Case Study on Multi-task Graph Neural Topology Search

## Quick Facts
- arXiv ID: 2302.02565
- Source URL: https://arxiv.org/abs/2302.02565
- Reference count: 40
- Key outcome: Proposes BLMOL framework for bi-level multi-objective optimization, applied to multi-task graph neural topology search

## Executive Summary
This paper addresses the computationally expensive problem of bi-level multi-objective optimization in machine learning, where both upper and lower level sub-problems involve multiple conflicting objectives. The proposed BLMOL framework couples the lower-level decision-making process with upper-level optimization by introducing a preference vector, enabling simultaneous search of upper-level variables and preference vectors. A preference surrogate model is constructed to approximate upper-level objectives, reducing computational cost. The framework is applied to multi-task graph neural topology search, demonstrating superior performance on three real-world graph datasets compared to state-of-the-art algorithms.

## Method Summary
The BLMOL framework couples lower-level (LL) decision-making with upper-level (UL) optimization by introducing an LL preference vector. UL variables and preference vectors are simultaneously searched using evolutionary multi-objective algorithms (MOEAs), while the LL weight is trained using gradient-based preference MOEAs like EPO. To reduce computational cost, a preference surrogate model is constructed to approximate UL objectives. The framework is applied to multi-task graph neural topology search (MTGNTS), aiming to find Pareto-optimal topologies and their weights for graph classification, node classification, and link prediction tasks.

## Key Results
- BLMOL outperforms state-of-the-art algorithms on three real-world graph datasets
- The framework generates well-representative UL solutions and LL weights
- Preference surrogate model effectively approximates UL objectives, reducing computational cost

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Coupling the LL decision-making process to the UL optimization by introducing an LL preference vector r enables efficient exploration of the UL Pareto front without evaluating multiple LL Pareto weights for each UL solution.
- **Mechanism:** The framework searches UL variables α and LL preference vectors r simultaneously using a MOEA. For each pair (α, r), a single exact LL Pareto weight w*(α, r) is computed via gradient-based preference algorithms. This reduces the need to maintain multiple high-dimensional LL weights.
- **Core assumption:** The LL Pareto weight set W*(α) can be well-represented by a single weight w*(α, r) that satisfies the preference optimality condition (r1F1(α,w*) = r2F2(α,w*) = ... = rm′Fm′(α,w*)).
- **Evidence anchors:**
  - [abstract]: "This paper proposes a bi-level multi-objective learning framework (BLMOL), coupling the above decision-making process with the optimization process of the UL-MOP by introducing LL preference r."
  - [section III.A]: "We couple the decision-making process of the LL-MOP to the search process of the UL-MOP by introducing the LL preference vector r."
  - [corpus]: Weak evidence; neighboring papers discuss preference-based methods but none explicitly couple LL preference to UL search in bi-level MOPs.
- **Break condition:** If the preference vector r cannot adequately represent the LL Pareto front, the quality of the overall solution degrades significantly.

### Mechanism 2
- **Claim:** The preference surrogate model accurately approximates UL objectives, enabling rapid evaluation of UL solutions without expensive LL training.
- **Mechanism:** A set of (α, r, L(α,w*(α,r))) samples are generated. Multiple surrogate models (SVR, RF, AdaBoost, Bagging, GP, MLP) are fitted to these samples. The best model per UL objective is selected via cross-validation.
- **Core assumption:** The functional relationship between (α, r) and UL objectives L(α,w*(α,r)) is smooth enough to be well-approximated by cheap surrogate models.
- **Evidence anchors:**
  - [abstract]: "the preference surrogate model is constructed to replace the expensive evaluation process of the UL-MOP."
  - [section III.B]: "we adopt a preference surrogate model to fit the functional relationship between UL variables, LL preference vectors, and multiple UL objective functions."
  - [corpus]: No direct evidence; surrogate models are common in expensive optimization but not explicitly for bi-level MOPs in ML.
- **Break condition:** If the surrogate model accuracy drops below acceptable thresholds, the MOEA will search based on inaccurate fitness values, leading to poor convergence.

### Mechanism 3
- **Claim:** Embedding the EPO gradient-based preference algorithm in BLMOL effectively trains the LL weight for each (α, r) pair.
- **Mechanism:** EPO computes a combination coefficient vector μ that balances convergence and diversity. The weight update rule w = w - ξμT∇wF(α,w) finds an exact LL Pareto weight satisfying the preference optimality condition.
- **Core assumption:** The EPO algorithm can find an exact LL Pareto weight for any given preference vector r in the LL objective space.
- **Evidence anchors:**
  - [section III.B]: "After the model is trained, we can easily calculate the UL objective values."
  - [corpus]: EPO is referenced in related work but not validated for bi-level MOPs; neighboring papers focus on multi-objective optimization rather than bi-level settings.
- **Break condition:** If EPO fails to converge or finds a weight far from the preference vector r, the surrogate model training data becomes noisy, degrading overall performance.

## Foundational Learning

- **Concept:** Multi-objective evolutionary algorithms (MOEAs) like NSGA-II and MOEA/D.
  - **Why needed here:** The UL-MOP involves multiple conflicting objectives (e.g., task accuracy rates), requiring a population-based search to approximate the Pareto front.
  - **Quick check question:** What is the primary difference between NSGA-II and MOEA/D in handling multiple objectives?

- **Concept:** Gradient-based multi-objective optimization with preference vectors.
  - **Why needed here:** The LL-MOP is differentiable and involves training neural network weights; gradient methods like EPO can efficiently find exact LL Pareto weights for a given preference vector.
  - **Quick check question:** How does EPO compute the combination coefficient μ for the gradient descent direction?

- **Concept:** Surrogate modeling (e.g., SVR, RF, GP, MLP) and model selection via cross-validation.
  - **Why needed here:** Direct evaluation of UL objectives requires expensive LL training; surrogate models approximate these objectives cheaply during MOEA search.
  - **Quick check question:** What metric is used in the paper to select the best surrogate model for each UL objective?

## Architecture Onboarding

- **Component map:** UL variable α and LL preference vector r → EPO training → LL weight w*(α, r) → UL evaluation → surrogate model → NSGA-II archive
- **Critical path:** α, r → EPO training → w*(α, r) → UL evaluation → surrogate model → NSGA-II archive
- **Design tradeoffs:**
  - Sampling size Ns vs. surrogate accuracy vs. pre-search cost
  - Preference vector granularity (rm) vs. search space size
  - Surrogate model complexity vs. prediction speed
- **Failure signatures:**
  - NSGA-II converges to a small region → surrogate model overfits to sampled data
  - High variance in UL objectives across runs → EPO training instability
  - Archive lacks diversity → preference vectors r not well-distributed
- **First 3 experiments:**
  1. Verify EPO finds exact LL Pareto weights for simple synthetic bi-level problems
  2. Test surrogate model accuracy on a small set of (α, r) pairs before scaling up
  3. Run NSGA-II with ground-truth UL evaluations (no surrogate) to establish baseline Pareto front quality

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of BLMOL scale with the size and complexity of the search space in multi-task graph neural topology search?
- Basis in paper: [inferred] The paper discusses the search space for MTGNTS and the impact of parameters like the number of backbones (Nb) on performance. However, it does not provide a comprehensive analysis of how BLMOL scales with increasingly large and complex search spaces.
- Why unresolved: The paper focuses on a specific search space and limited parameter variations. Scaling behavior in more complex scenarios remains untested.
- What evidence would resolve it: Systematic experiments varying the number of aggregation operations, fusion operations, and backbone layers, and measuring performance and computational cost.

### Open Question 2
- Question: How does BLMOL perform on larger, real-world graph datasets with millions of nodes and edges?
- Basis in paper: [inferred] The paper demonstrates BLMOL on three relatively small datasets (ENZYMES, PROTEINS, DHFR). It does not address the scalability of BLMOL to large-scale graph datasets.
- Why unresolved: The datasets used are limited in size and may not represent the challenges of real-world, large-scale graph problems.
- What evidence would resolve it: Experiments on large-scale graph datasets (e.g., social networks, biological networks) with millions of nodes and edges, comparing BLMOL's performance and efficiency to other methods.

### Open Question 3
- Question: Can BLMOL be extended to handle dynamic graphs where the structure and node/edge features change over time?
- Basis in paper: [inferred] The paper focuses on static graph datasets. It does not discuss the applicability of BLMOL to dynamic graph scenarios.
- Why unresolved: The current BLMOL framework assumes a fixed graph structure and features. Adapting it to dynamic graphs requires additional considerations.
- What evidence would resolve it: A modified BLMOL framework that incorporates mechanisms for handling dynamic graph updates and retraining or adapting the model over time. Experiments on dynamic graph datasets demonstrating the effectiveness of the extended approach.

## Limitations
- The coupling of LL preference vectors to UL search assumes a single LL Pareto weight per UL solution adequately represents the trade-off surface
- Surrogate modeling approach assumes smooth relationships between UL variables and objectives
- Experimental validation is limited to three graph datasets with no ablation studies on surrogate model accuracy

## Confidence

- **Medium:** The overall framework design and integration of preference vectors with evolutionary search
- **Low:** Surrogate model accuracy and its impact on NSGA-II convergence
- **Medium:** EPO algorithm's ability to find exact LL Pareto weights for arbitrary preferences

## Next Checks

1. **Surrogate model ablation:** Compare BLMOL performance with and without surrogate models across different sample sizes (10, 25, 50, 100) to establish minimum requirements for accurate UL objective approximation.

2. **Preference vector sensitivity:** Systematically vary the granularity of preference vectors (rm = 2, 3, 5, 10) and measure the impact on Pareto front diversity and solution quality.

3. **LL Pareto front validation:** For selected UL solutions, compute and visualize the complete LL Pareto front to verify that single preference-based weights adequately represent the trade-off surface.
