# TEDB System Description to a Shared Task on Euphemism Detection 2022

## Quick Facts
- arXiv ID: 2301.06602
- Source URL: https://arxiv.org/abs/2301.06602
- Authors: 
- Reference count: 13
- Primary result: 0.816 F1-score on euphemism detection using a hybrid transformer-KimCNN architecture

## Executive Summary
This paper presents a baseline system for the 2022 shared task on euphemism detection, framing it as a text classification problem. The authors explore Transformer-based models and find that pretraining on related tasks like sentiment analysis and offensiveness detection correlates with higher F1-scores. The best result of 0.816 F1-score is achieved using a euphemism-detection-finetuned TweetEval/TimeLMs-pretrained RoBERTa model as a feature extractor with a KimCNN classifier backend trained end-to-end using a cosine annealing scheduler. The paper also notes that increasing the number of word vector channels does not improve performance.

## Method Summary
The approach uses a hybrid architecture combining a Transformer model (RoBERTa) with a KimCNN classifier. The Transformer is first finetuned on euphemism detection, then used as a feature extractor where hidden states from all layers are concatenated to form word vectors. These word vectors are fed into the KimCNN backend with 100 feature maps and filter sizes 3, 4, and 5. The model is trained end-to-end using a cosine annealing scheduler. The training procedure uses early stopping with zero patience, training until saturation on the full training set rather than using validation splits.

## Key Results
- Best F1-score of 0.816 achieved using a euphemism-detection-finetuned TweetEval/TimeLMs-pretrained RoBERTa model with KimCNN backend
- Pretraining on sentiment analysis and offensiveness detection correlates with higher F1-scores
- Pretraining on sarcasm detection yields lower F1-scores
- Increasing word vector channels does not improve performance

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Finetuning pretrained transformers on euphemism detection yields better performance than training from scratch.
- Mechanism: Pretrained models capture semantic and contextual representations that transfer to euphemism detection, especially when pretrained on related tasks like sentiment and offensiveness.
- Core assumption: Pretraining tasks are semantically related enough to improve euphemism detection performance.
- Evidence anchors:
  - [abstract]: "We observed pretrained models on sentiment analysis and offensiveness detection to correlate with more F1-score while pretraining on other tasks, such as sarcasm detection, produces less F1-scores."
  - [section 3.2.1]: "we tend to confirm the hypothesis... that euphemism relates with sentiment and offensiveness because the top-2 best scores in the table are sentiment analysis and offensiveness detection."
- Break condition: If the pretrained task is too dissimilar from euphemism detection (e.g., sarcasm detection), performance degrades significantly.

### Mechanism 2
- Claim: Using a KimCNN backend with pretrained transformer features improves stability and convergence compared to using only transformer classifiers.
- Mechanism: KimCNN provides a stable, well-understood architecture that regularizes the high-capacity transformer features, leading to faster convergence and more stable hyperparameter sensitivity.
- Core assumption: KimCNN can effectively learn from transformer embeddings without losing the nuanced semantic information.
- Evidence anchors:
  - [abstract]: "Our best result of 0.816 F1-score... consists of a euphemism-detection-finetuned TweetEval/TimeLMs-pretrained RoBERTa model as a feature extractor frontend with a KimCNN classifier backend trained end-to-end..."
  - [section 3.3]: "we got the best result of 0.8158 test F1-score, approximately 0.01 improvement over the previous model, simply using a KimCNN backend."
- Break condition: If the transformer features are too complex for the KimCNN to process effectively, or if the training data is too small for the hybrid model to learn properly.

### Mechanism 3
- Claim: Early stopping with zero patience and training until saturation on the full training set is more effective than traditional validation-based early stopping for small datasets.
- Mechanism: With small datasets, validation splits can lead to high variance in performance estimates, and withholding data reduces model capacity. Training until saturation ensures the model captures all available information.
- Core assumption: The training set is representative enough of the test set that maximizing training performance correlates with test performance.
- Evidence anchors:
  - [section 3.1]: "Training the model just to shatter the whole training data and stop training in a basic train-test setting... We relied solely on our heuristics on the training set instead."
  - [section 3.1]: "it would be weird to withhold some training data from a given small data... and let the model predict them wrongly."
- Break condition: If the training set is not representative of the test set, or if the model overfits the training data without proper regularization.

## Architecture Onboarding

- Component map: Input text -> RoBERTa transformer (finetuned) -> Concatenated hidden states (word vectors) -> KimCNN classifier -> Binary classification output

- Critical path:
  1. Tokenize and preprocess input text
  2. Pass through finetuned RoBERTa model to extract features
  3. Concatenate hidden states from all layers to form word vectors
  4. Feed word vectors into KimCNN backend
  5. Apply softmax to obtain final classification

- Design tradeoffs:
  - Using a hybrid architecture (transformer + KimCNN) provides stability and faster convergence but may limit the model's capacity to learn complex patterns compared to using a pure transformer classifier.
  - Training until saturation on the full training set maximizes the use of limited data but risks overfitting if the training set is not representative of the test set.

- Failure signatures:
  - Low F1-score: The model may not be capturing the semantic nuances of euphemisms, possibly due to inadequate pretraining or insufficient training data.
  - High variance in results: The model may be sensitive to hyperparameter choices or random seeds, indicating instability in the training process.
  - Slow convergence: The KimCNN backend may not be effectively learning from the transformer features, possibly due to mismatched architectures or learning rates.

- First 3 experiments:
  1. Train a vanilla RoBERTa model on euphemism detection without any additional preprocessing or postprocessing.
  2. Fine-tune a pretrained RoBERTa model (e.g., 'cardiffnlp/twitter-roberta-base-sentiment-latest') on euphemism detection and evaluate its performance.

## Limitations
- Small dataset size (1572 training instances) raises concerns about generalizability and overfitting
- Heavy reliance on heuristic training procedures without extensive ablation studies
- Limited exploration of KimCNN architecture parameters and hyperparameter sensitivity

## Confidence

- High confidence: The hybrid transformer-KimCNN architecture design and the observed correlation between related pretraining tasks (sentiment, offensiveness) and euphemism detection performance. The reported F1-score of 0.816 is well-documented and reproducible given the described methodology.
- Medium confidence: The effectiveness of training until saturation without validation splits, as this is an empirical observation specific to this dataset and task. The choice of KimCNN architecture parameters (100 feature maps, filter sizes 3, 4, 5) lacks extensive justification or ablation studies.
- Low confidence: The generalizability of the findings to larger datasets or different euphemism detection scenarios, given the small dataset size and task-specific training procedures.
