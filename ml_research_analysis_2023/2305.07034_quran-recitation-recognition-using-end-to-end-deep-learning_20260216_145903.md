# Quran Recitation Recognition using End-to-End Deep Learning

## Quick Facts
- arXiv ID: 2305.07034
- Source URL: https://arxiv.org/abs/2305.07034
- Reference count: 40
- Primary result: 8.34% word error rate (WER) and 2.42% character error rate (CER) on Quran recitation recognition

## Executive Summary
This paper addresses the challenge of automatic Quran recitation recognition, which is complicated by unique pronunciation rules (Tajweed) not present in normal speech. The authors propose an end-to-end deep learning model using CNN-Bidirectional GRU encoder with CTC loss function and a character-level decoder with beam search. The model is trained and evaluated on the Ar-DAD public dataset containing 37 chapters recited by 30 male reciters. The proposed approach achieves competitive performance (8.34% WER, 2.42% CER) and provides a baseline for future research in this domain, particularly valuable since no end-to-end deep learning approaches have previously been applied to Quran recitation recognition.

## Method Summary
The proposed model uses a CNN-Bidirectional GRU encoder architecture with CTC loss for training and beam search decoding. The input consists of normalized spectrograms extracted from Quran recitation audio (44.1 kHz, 16-bit depth, stereo channels). The model includes two CNN layers (32 filters each with kernel sizes 11x41 and 11x21), followed by five BiGRU layers (512 units each) with dropout=0.5, batch normalization, and ReLU activation. A dense layer with 1024 neurons connects to a 46-class softmax output layer (blank + Arabic alphabet). The model was trained using Adam optimizer (learning rate 1e-4) on Google Colab with NVIDIA Tesla T4 GPU, evaluated on a 10% test split of the Ar-DAD dataset after removing Bismillah verses from transcripts.

## Key Results
- Achieved 8.34% word error rate (WER) on Quran recitation recognition
- Achieved 2.42% character error rate (CER) demonstrating high accuracy
- Outperformed traditional ASR approaches that require phoneme alignment

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: The CNN-BiGRU encoder automatically learns phonetic features without needing phoneme alignment.
- **Mechanism**: CNN layers extract local spectral patterns, then BiGRU layers model temporal dependencies in both directions, capturing context for character prediction.
- **Core assumption**: End-to-end training with CTC loss can infer alignment from data without explicit phoneme labels.
- **Evidence anchors**: Abstract states end-to-end methodology avoids traditional ASR alignment tools; section explains CTC loss eliminates need for phoneme-aligned datasets.
- **Break condition**: If dataset lacks sufficient variability in pronunciation or Tajweed rules, the model cannot learn accurate alignments, leading to high CER/WER.

### Mechanism 2
- **Claim**: Character-level decoding handles rare and out-of-vocabulary words better than word-level decoding.
- **Mechanism**: By predicting individual characters, the decoder can compose any word from the Arabic alphabet, including those not seen during training.
- **Core assumption**: Arabic script is largely phonemic, so character prediction suffices for accurate transcription.
- **Evidence anchors**: Section states character-level decoders have advantages over word-level decoders; abstract mentions character-based decoder.
- **Break condition**: If Arabic orthography is heavily context-dependent (e.g., short vowels not marked), character-level decoding may struggle without explicit diacritics.

### Mechanism 3
- **Claim**: CTC beam search decoder sums probabilities over multiple alignments, improving robustness to timing variations.
- **Mechanism**: Beam search keeps multiple candidate sequences, summing their probabilities to find the best overall output rather than picking most likely character at each step.
- **Core assumption**: Quran recitation varies in speed (Hadr, Tadweer, Tahqeeq), so search-based decoder handles alignment uncertainty.
- **Evidence anchors**: Section explains beam search sums probabilities of each sentence; abstract mentions beam search decoder.
- **Break condition**: If beam width is too narrow, decoder may miss correct alignment; if too wide, decoding becomes computationally expensive.

## Foundational Learning

- **Concept**: Spectrogram extraction parameters (FFT size, hop length)
  - **Why needed here**: Controls time-frequency resolution trade-off; affects how well model captures fast articulation changes in Tajweed.
  - **Quick check question**: What happens to WER if hop size is too large relative to frame length?

- **Concept**: CTC loss function and alignment-free training
  - **Why needed here**: Allows model to learn mappings from audio to text without requiring pre-aligned phoneme labels, critical for Quran datasets.
  - **Quick check question**: How does CTC loss differ from cross-entropy loss in handling variable-length sequences?

- **Concept**: Beam search decoding vs greedy decoding
  - **Why needed here**: Handles multiple possible alignments for same text, crucial for variable recitation speeds.
  - **Quick check question**: Why might greedy decoding fail on Quran recitation but beam search succeed?

## Architecture Onboarding

- **Component map**: Spectrogram → CNN layers → BiGRU layers → Dense layer → Output layer → CTC loss → Beam search decoder
- **Critical path**: Spectrogram → CNN → BiGRU → Dense → CTC loss → Beam search output
- **Design tradeoffs**:
  - CNN vs raw features: CNN learns hierarchical features but adds complexity
  - BiGRU vs unidirectional: BiGRU captures context but doubles parameters
  - Character vs word decoding: More robust to OOV but may struggle with diacritics
  - Beam width: Wider beams improve accuracy but increase latency
- **Failure signatures**:
  - High CER but low WER: Character-level model struggles with diacritics
  - High WER: Alignment errors or insufficient training data variability
  - Slow decoding: Beam width too large or inefficient implementation
- **First 3 experiments**:
  1. Vary spectrogram hop size (256, 400, 512) and measure WER/CER to find optimal time resolution.
  2. Replace BiGRU with LSTM and compare training time and accuracy.
  3. Test greedy vs beam search decoding with different beam widths to balance accuracy and speed.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question**: How would the proposed end-to-end model perform on Quran recitation data from women and children reciters?
- **Basis in paper**: [explicit] Authors note Ar-DAD dataset only includes men reciters, which may limit model's robustness for recognizing recitations by women and children.
- **Why unresolved**: Model was only trained and evaluated on male reciter data, so generalization to other demographics is unknown.
- **What evidence would resolve it**: Testing model on Quran recitation data from women and children reciters and comparing performance to male reciter results.

### Open Question 2
- **Question**: How would the proposed end-to-end model perform on Quran recitation data from different recitation forms (Qira'at) beyond the 'Hafs from Aasim' form used in Ar-DAD dataset?
- **Basis in paper**: [explicit] Authors mention Ar-DAD dataset only contains samples from one recitation form, while there are ten approved forms that differ in pronunciation, prolongation, and intonation.
- **Why unresolved**: Model was only trained and evaluated on one recitation form, so ability to generalize to other forms is unknown.
- **What evidence would resolve it**: Testing model on Quran recitation data from different recitation forms and comparing performance across forms.

### Open Question 3
- **Question**: How would the proposed end-to-end model compare to traditional ASR approaches for Quran recitation recognition in terms of word error rate and character error rate?
- **Basis in paper**: [inferred] Authors claim end-to-end model avoids alignment issues present in traditional ASR, but don't directly compare performance metrics.
- **Why unresolved**: Paper doesn't provide direct comparison of WER and CER between proposed end-to-end model and traditional ASR approaches.
- **What evidence would resolve it**: Implementing and evaluating traditional ASR approaches on same Quran recitation data and comparing their WER and CER to proposed end-to-end model.

## Limitations

- Limited dataset diversity with only 30 male reciters and one recitation form (Hafs from Aasim)
- Unclear handling of Arabic diacritics and short vowels in training data
- Computational efficiency claims lack empirical validation against word-level alternatives

## Confidence

**High Confidence**: The technical implementation of CNN-BiGRU architecture with CTC loss is sound and follows established deep learning practices for speech recognition.

**Medium Confidence**: Reported WER and CER metrics are likely accurate for specific Ar-DAD dataset and test conditions described, but may not generalize well to other Quran recitation datasets.

**Low Confidence**: Claims about computational efficiency advantages of character-level decoding and model's ability to handle out-of-vocabulary words are not empirically validated and remain theoretical assertions.

## Next Checks

1. **Cross-dataset validation**: Test the trained model on an independent Quran recitation dataset (if available) or on different splits of Ar-DAD to assess generalization beyond the reported test set.

2. **Diacritic handling evaluation**: Create test cases with and without Arabic diacritics to quantify the model's performance degradation and determine whether explicit diacritic modeling is necessary.

3. **Ablation study on architectural components**: Systematically remove or modify components (e.g., CNN layers, BiGRU layers, beam search width) to quantify their individual contributions to final WER/CER, validating claimed importance of each design choice.
