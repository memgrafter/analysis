# Example-Based Explainable AI and its Application for Remote Sensing Image Classification

## Quick Facts
- arXiv ID: 2302.01526
- Source URL: https://arxiv.org/abs/2302.01526
- Reference count: 26
- Method achieves 95.7% accuracy on EuroSAT classification

## Executive Summary
This paper introduces "What I Know (WIK)", a data-centric XAI method that explains deep learning model inferences by showing training examples similar to inference targets. Unlike traditional importance analysis methods that highlight relevant pixels, WIK uses model-extracted features from the layer before output to find semantically similar training instances. The approach helps assess whether models are trained on representative data and can detect unreliable inferences by verifying if similar training examples exist.

## Method Summary
WIK works by extracting feature vectors from the layer before the output layer of a trained CNN model, then computing L2-norm similarity between these vectors to identify semantically similar training instances. The method uses a two-step verification process: first ensuring inference classes match between target and training instance, then computing L2-norm similarity on feature vectors. This approach helps verify whether the model's abstraction is reasonable and whether the training dataset is sufficient for each inference.

## Key Results
- WIK successfully selected visually similar examples using L2-norm similarity on EuroSAT dataset
- The method achieved 95.7% accuracy with a LeNet CNN architecture
- WIK outperformed pixel-based similarity methods in identifying semantically comparable examples

## Why This Works (Mechanism)

### Mechanism 1
WIK uses feature similarity from the model's internal representation rather than pixel similarity to select comparable training examples. The method extracts feature vectors from the layer before the output layer, then computes L2-norm similarity between these vectors to identify semantically similar instances. This works because the model has learned to extract meaningful features that capture task-relevant similarities between inputs.

### Mechanism 2
The two-step verification process ensures selected examples are both semantically similar AND belong to the same class. First step verifies inference class matches between target and training instance, second step computes L2-norm similarity on feature vectors. This works because class alignment in feature space correlates with meaningful similarity for the task.

### Mechanism 3
Data-centric XAI complements traditional importance analysis by showing what the model was trained on rather than what inputs matter. Instead of highlighting important pixels/regions, WIK shows entire training examples that share similar feature representations. This works because understanding training data distribution helps assess whether model inferences are reliable.

## Foundational Learning

- Concept: Deep learning feature extraction
  - Why needed here: Understanding how models abstract input data into meaningful representations is crucial for interpreting WIK's approach
  - Quick check question: What happens to the dimensionality and nature of data as it passes through convolutional and pooling layers?

- Concept: Distance metrics in high-dimensional spaces
  - Why needed here: WIK uses L2-norm to measure similarity, but other metrics like cosine similarity were tested and found less effective
  - Quick check question: How do L1-norm, L2-norm, and cosine similarity differ in their sensitivity to feature magnitude versus direction?

- Concept: Model generalization and training data distribution
  - Why needed here: WIK's effectiveness depends on understanding whether test data falls within the training distribution
  - Quick check question: What are the implications if test data lies in regions of feature space poorly represented in training data?

## Architecture Onboarding

- Component map: Input preprocessing layer -> CNN feature extractor (3 conv-pool blocks) -> Feature vector layer (32 nodes) -> Output layer (10 nodes) -> Similarity computation module -> Visualization interface

- Critical path: Input → CNN → Feature vector → L2-norm similarity → Training example selection → Output

- Design tradeoffs:
  - Feature layer selection: Using penultimate layer vs. earlier layers affects granularity of similarity
  - Distance metric choice: L2-norm worked best but may not generalize to all tasks
  - Class verification step: Ensures semantic consistency but adds computational overhead

- Failure signatures:
  - Selected examples appear visually dissimilar despite high similarity scores
  - Model accuracy drops when using feature-based similarity instead of pixel-based
  - Similarity values show no correlation with human perception of similarity

- First 3 experiments:
  1. Implement basic L2-norm similarity on feature vectors and visualize selected examples for random test samples
  2. Compare L2-norm with L1-norm and cosine similarity on the same feature vectors to validate metric choice
  3. Test on a simpler dataset (e.g., MNIST) to verify the method works before scaling to EuroSAT complexity

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of WIK compare to other XAI methods when detecting data distribution shifts between training and test datasets?
- Basis in paper: The paper discusses WIK's ability to detect unreliable inferences and monitor model performance by showing training examples similar to inference targets
- Why unresolved: The paper demonstrates WIK's effectiveness on a single EuroSAT dataset with 95.7% accuracy, but doesn't compare its distribution shift detection capabilities against other XAI methods like LIME or SHAP
- What evidence would resolve it: Direct comparison studies using benchmark datasets with known distribution shifts, measuring WIK's detection accuracy versus other XAI methods

### Open Question 2
- Question: What is the computational complexity of WIK compared to importance analysis methods like SHAP when applied to large-scale remote sensing datasets?
- Basis in paper: The paper describes WIK's two-step similarity evaluation process involving L2-norm calculations across all training instances, but doesn't analyze computational efficiency
- Why unresolved: The paper focuses on WIK's effectiveness but doesn't provide runtime analysis or scalability testing with larger datasets or different model architectures
- What evidence would resolve it: Runtime benchmarks comparing WIK's processing time against SHAP/LIME across datasets of varying sizes and model complexities

### Open Question 3
- Question: How does WIK's performance vary across different remote sensing tasks beyond classification, such as semantic segmentation or object detection?
- Basis in paper: The paper states "This method can be applied to various machine-learning tasks, including classification and regression" but only demonstrates classification
- Why unresolved: The paper only demonstrates WIK on EuroSAT image classification, leaving its effectiveness on other remote sensing tasks unexplored
- What evidence would resolve it: Experimental results applying WIK to semantic segmentation and object detection tasks on multiple remote sensing datasets, with quantitative performance metrics

## Limitations

- The method only demonstrates effectiveness on a single dataset (EuroSAT) and CNN architecture (LeNet)
- Evaluation relies primarily on qualitative visual inspection rather than quantitative metrics for similarity assessment
- Computational complexity of comparing all test instances against the entire training set is not addressed

## Confidence

- High Confidence: The core mechanism of using model-extracted features for similarity computation is well-defined and theoretically sound
- Medium Confidence: The effectiveness of L2-norm over other metrics is demonstrated but may not generalize across all tasks and domains
- Low Confidence: Claims about WIK's superiority over existing methods lack comparative analysis with alternative XAI approaches
