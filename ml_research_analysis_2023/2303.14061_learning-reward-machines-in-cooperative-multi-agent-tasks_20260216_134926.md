# Learning Reward Machines in Cooperative Multi-Agent Tasks

## Quick Facts
- arXiv ID: 2303.14061
- Source URL: https://arxiv.org/abs/2303.14061
- Reference count: 24
- Key outcome: Novel method for learning reward machines in cooperative multi-agent reinforcement learning through task decomposition and decentralized learning

## Executive Summary
This paper introduces a method for learning reward machines (RMs) in cooperative multi-agent reinforcement learning by decomposing complex tasks into sub-tasks, each solved by a separate agent. The approach interleaves reinforcement learning with reward machine induction using inductive logic programming (ILASP), allowing agents to learn both task structure and policies simultaneously in a decentralized manner. Experiments on ThreeButtons and Rendezvous tasks demonstrate that the learned RMs enable successful agent collaboration and convergence to maximum collective reward, addressing the challenge of non-Markovian rewards in multi-agent settings.

## Method Summary
The method decomposes a global cooperative task into sub-tasks, each independently solved by a separate agent. Each agent learns its own reward machine from traces collected during exploration using ILASP, while simultaneously learning Q-functions for policy optimization. The learning process interleaves RM induction with reinforcement learning, allowing agents to discover task structure and optimal behaviors in parallel. Agents synchronize through shared labeling functions and communicate through the environment, with the approach aiming to reduce complexity compared to learning a single global RM.

## Key Results
- Learned reward machines enable agents to successfully collaborate and achieve shared objectives in both ThreeButtons and Rendezvous tasks
- Agents converge to maximum collective reward (1.0) upon task completion in both environments
- The approach effectively handles non-Markovian rewards through the use of reward machines
- Task decomposition reduces complexity compared to learning a global reward machine

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Learning individual reward machines (RMs) per agent simplifies the learning problem compared to learning a global RM.
- Mechanism: By decomposing the task into sub-tasks, each agent learns an RM over a smaller proposition set and state space, reducing the complexity of the learning problem. This decomposition allows agents to learn independently, avoiding the scalability issues of learning a single global RM.
- Core assumption: The global task can be decomposed into sub-tasks, each solvable by a single agent.
- Evidence anchors:
  - [abstract]: "The RMs associated with each sub-task are learnt in a decentralised manner and then used to guide the behaviour of each agent. By doing so, the complexity of a cooperative multi-agent problem is reduced, allowing for more effective learning."
  - [section 3.2]: "We propose to decompose the global task into sub-tasks, each of which can be independently solved by one of the agents... This should be simpler than learning a global RM since the number of constituent states becomes smaller."
- Break condition: If the task cannot be effectively decomposed into sub-tasks, or if agents need to coordinate at a finer granularity than the sub-task decomposition allows.

### Mechanism 2
- Claim: Interleaving reinforcement learning (RL) with reward machine (RM) induction allows agents to learn both task structure and policies simultaneously.
- Mechanism: The algorithm interleaves Q-learning for each agent with the induction of the RM from the traces collected by the agent. This allows the agent to learn the structure of its sub-task (the RM) and the policies to achieve it (the Q-functions) in parallel.
- Core assumption: The traces collected by the agent are sufficient to learn the structure of the sub-task.
- Evidence anchors:
  - [section 3.2]: "We propose an algorithm that interleaves the induction of the RMs from a collection of label traces and the learning of the associated Q-functions... The induction of the RMs is done using a state-of-the-art inductive logic programming system called ILASP."
- Break condition: If the traces collected are insufficient to learn the RM, or if the RL process resets too frequently, preventing the Q-functions from converging.

### Mechanism 3
- Claim: Using inductive logic programming (ILASP) to learn the RM from traces provides a scalable and interpretable way to model the task structure.
- Mechanism: ILASP learns the transition function of the RM as a set of logic rules from the example traces observed by the agent. This provides a symbolic representation of the task structure that is both interpretable and scalable.
- Core assumption: The task structure can be expressed as a set of logic rules.
- Evidence anchors:
  - [section 3.2]: "The induction of the RMs is done using a state-of-the-art inductive logic programming system called ILASP [15], which learns the transition function of an RM as a set of logic rules from example traces observed by the agent."
- Break condition: If the task structure is too complex to be expressed as logic rules, or if ILASP cannot learn the rules within a reasonable time.

## Architecture Onboarding

- Component map:
  - Agents -> RM Learner (ILASP) -> Q-learning -> Environment
  - Each agent has its own RM, Q-functions, and labeling function
  - Environment collects traces and provides rewards

- Critical path:
  1. Initialize each agent with a minimal RM (initial and final states)
  2. Run episodes for each agent, collecting traces
  3. Update Q-functions based on the current RM and observed rewards
  4. Learn new RMs from the collected traces using ILASP
  5. If the RM changes, reset the Q-functions and continue learning

- Design tradeoffs:
  - Learning individual RMs vs. a global RM: Individual RMs are simpler to learn but may not capture all task dependencies
  - Interleaving RM induction and RL vs. sequential learning: Interleaving allows for simultaneous learning but may require more resets
  - Using ILASP vs. other learning methods: ILASP provides symbolic representations but may have scalability issues

- Failure signatures:
  - Agents fail to achieve the global task: May indicate that the task decomposition is incorrect or that the RMs are not learned properly
  - RMs are not learned within the time limit: May indicate that the traces are insufficient or that the task structure is too complex
  - Q-functions do not converge: May indicate that the RL process is resetting too frequently or that the reward signal is not informative enough

- First 3 experiments:
  1. Test the algorithm on a simple grid-world task with known sub-task decomposition
  2. Vary the complexity of the task and observe the impact on RM learning and RL convergence
  3. Compare the performance of the proposed algorithm with a baseline that uses a global RM or no RM at all

- Why unresolved: The paper does not address the issue of noisy labeling functions in multi-agent settings.

## Limitations

- Limited experimental scope to two grid-world environments, unclear scalability to complex, high-dimensional environments
- Potential scalability bottlenecks with ILASP for larger or more complex reward machines
- Assumes effective task decomposition into independent sub-tasks, which may not hold for tightly coupled agent interactions
- Limited analysis of synchronization challenges and impact of labeling function noise

## Confidence

**High confidence**: The core mechanism of interleaving RL with RM induction using ILASP is well-defined and theoretically sound. The experiments demonstrate successful learning of reward machines and convergence to maximum collective reward in the tested environments.

**Medium confidence**: The claim that decomposing tasks into sub-tasks reduces complexity is supported by the experiments, but the extent of this benefit across diverse task types remains to be validated.

**Low confidence**: The scalability of the approach to more complex environments and the impact of labeling function design on synchronization are not thoroughly explored in the current work.
