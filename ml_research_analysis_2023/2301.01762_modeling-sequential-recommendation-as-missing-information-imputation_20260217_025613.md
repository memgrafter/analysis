# Modeling Sequential Recommendation as Missing Information Imputation

## Quick Facts
- arXiv ID: 2301.01762
- Source URL: https://arxiv.org/abs/2301.01762
- Reference count: 40
- This paper proposes a unified framework for handling missing side information in sequential recommendation by formulating it as Missing Information Imputation (MII).

## Executive Summary
This paper addresses the challenge of missing side information in sequential recommendation by introducing a unified framework that treats both missing side information and next item prediction as special cases of a Missing Information Imputation (MII) task. The authors propose MIIR, a model that uses Dense Fusion Self-Attention (DFSA) to capture all pairwise relations between feature fields, enabling effective fusion of side information. Experiments on three real-world datasets demonstrate that MIIR significantly outperforms state-of-the-art sequential recommendation methods, particularly in scenarios with varying levels of missing information.

## Method Summary
The paper proposes MIIR, a model that formulates sequential recommendation as a Missing Information Imputation (MII) task. MIIR randomly masks feature fields in input sequences and trains the model to recover them, treating next item prediction as a special case of imputation. The model employs a Dense Fusion Self-Attention (DFSA) mechanism that uses transformer layers to model relationships between any pair of feature fields. MIIR is first pre-trained using MII loss and then optionally fine-tuned with recommendation loss. The model uses cross-entropy loss for categorical features and MSE for textual features, with a dropout rate of 0.5 and masking probability p of 0.5.

## Key Results
- MIIR significantly outperforms state-of-the-art sequential recommendation methods on three real-world datasets
- DFSA captures all pairwise relations between feature fields, improving information fusion
- The model achieves better performance on datasets with varying levels of missing information, demonstrating robustness

## Why This Works (Mechanism)

### Mechanism 1
- Claim: MIIR effectively handles missing side information by treating both missing side information and next item prediction as special cases of the Missing Information Imputation (MII) task.
- Mechanism: MIIR randomly masks feature fields in input sequences and trains the model to recover them. Since the next item can be viewed as a missing feature field, sequential recommendation becomes a special case of MII.
- Core assumption: The model can learn to infer missing values from context when trained to impute both side information and item IDs simultaneously.
- Evidence anchors:
  - [abstract] "By considering the next item as a missing feature field, sequential recommendation can be formulated as a special case of MII."
  - [section 3.3] "The dense fusion self-attention (DFSA) mechanism employs several transformer layers to model the relation between any pair of feature fields in the sequence and fuse side information into the model for both imputation and recommendation."
- Break condition: If the context provided by available features is insufficient to infer missing values, or if the model overfits to specific patterns in the training data.

### Mechanism 2
- Claim: Dense Fusion Self-Attention (DFSA) improves sequential recommendation by capturing all pairwise relations between feature fields.
- Mechanism: DFSA uses a transformer with L layers where each layer's self-attention mechanism computes attention values between any pair of feature fields, allowing comprehensive information fusion.
- Core assumption: Modeling all possible pairwise relations between feature fields provides richer context for both imputation and recommendation tasks.
- Evidence anchors:
  - [abstract] "We devise a dense fusion self-attention (DFSA) mechanism for MIIR to capture all pairwise relations between items and their side information."
  - [section 3.3] "DFSA captures the relation between any pair of feature fields in the input sequence, allowing it to fully fuse various types of (side) information to impute missing feature values and address the main recommendation challenge."
- Break condition: If the computational cost of modeling all pairwise relations becomes prohibitive for long sequences, or if some relations are noisy and degrade performance.

### Mechanism 3
- Claim: Training with MII provides better supervision for sequential recommendation than training with recommendation loss alone.
- Mechanism: MIIR is first pre-trained using the MII loss that requires imputing masked feature fields, then fine-tuned with recommendation loss. This dual supervision helps the model better handle missing information.
- Core assumption: The imputation task forces the model to learn richer representations that are beneficial for the downstream recommendation task.
- Evidence anchors:
  - [section 5.2] "MIIR achieves better or comparable performance with the baselines on most evaluation metrics of all datasets, even without the help of MII."
  - [section 5.2] "MIIR-R achieves better or comparable performance with the baselines on most evaluation metrics of all datasets, even without the help of MII."
- Break condition: If the MII task introduces too much noise or if the model overfits to the imputation task at the expense of recommendation performance.

## Architecture Onboarding

- Component map: Embedding layer -> Dense Fusion Self-Attention (DFSA) -> Output layer
- Critical path:
  1. Input sequence with potentially missing feature fields
  2. Embedding layer transforms features into unified embeddings
  3. DFSA processes embeddings through transformer layers
  4. Output layer reconstructs feature fields and calculates losses
  5. Model learns to impute missing values and predict next item

- Design tradeoffs:
  - Computational cost vs. modeling capacity: DFSA models all pairwise relations but is computationally expensive
  - Imputation vs. placeholder values: Imputation uses context but may introduce errors; placeholders are simple but uninformative
  - Masking probability: Higher masking helps generalization but may make learning harder

- Failure signatures:
  - Performance degrades significantly when missing rate increases
  - Model overfits to specific patterns in training data
  - Imputation of missing values introduces significant errors

- First 3 experiments:
  1. Compare MIIR performance with different masking probabilities (e.g., 0.3, 0.5, 0.7)
  2. Evaluate impact of DFSA by comparing with sparse attention variant
  3. Test MIIR on datasets with varying levels of missing information

## Open Questions the Paper Calls Out

The paper does not explicitly call out open questions. However, several important questions arise from the work:

1. How does the performance of MIIR change when using different masking probabilities p for the missing information imputation task? The paper sets p=0.5 but does not explore other values.

2. How would MIIR perform on datasets with significantly longer item sequences than the 20-item limit used in this study? The computational constraints of DFSA are not fully explored.

3. Can the dense fusion self-attention mechanism be optimized to reduce redundancy while maintaining or improving performance? The paper observes redundancy in attention patterns but does not implement optimizations.

## Limitations

- The paper assumes uniform random masking of side information during training, but real-world missing data often follows non-random patterns
- DFSA's modeling of all pairwise feature field relations creates quadratic complexity, with unknown computational overhead
- Experiments focus exclusively on Amazon product datasets, leaving generalization to other domains untested

## Confidence

- **High confidence**: The MII formulation as a unified framework for handling missing side information
- **Medium confidence**: The superiority of DFSA over sparse attention variants
- **Low confidence**: Claims about MII pretraining's contribution to performance

## Next Checks

1. Test MIIR on datasets with non-random missing patterns (e.g., items with missing descriptions are systematically different from complete items) to verify the model handles realistic missingness scenarios.

2. Measure training time and memory consumption for MIIR vs baselines on datasets with varying sequence lengths and feature field counts to quantify the practical cost of DFSA.

3. Apply MIIR to non-e-commerce sequential recommendation datasets (e.g., music or video streaming) to test whether the MII framework generalizes beyond the Amazon product domain.
