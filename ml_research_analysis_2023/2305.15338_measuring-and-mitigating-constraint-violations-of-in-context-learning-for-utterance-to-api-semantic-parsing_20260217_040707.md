# Measuring and Mitigating Constraint Violations of In-Context Learning for Utterance-to-API Semantic Parsing

## Quick Facts
- **arXiv ID:** 2305.15338
- **Source URL:** https://arxiv.org/abs/2305.15338
- **Reference count:** 10
- **Primary result:** Proposes fine-grained constraint violation metrics and two mitigation strategies (SRD and API-CD) for improving utterance-to-API semantic parsing with LLMs

## Executive Summary
This paper addresses the challenge of constraint violations in large language models for utterance-to-API semantic parsing. The authors introduce a novel set of fine-grained metrics to measure task-specific constraint violations, including structural, functional, argument, and function-argument association constraints. Through detailed error analysis using these metrics, they identify common failure modes in LLM semantic parsing. The paper then proposes two mitigation strategies: Semantic-Retrieval of Demonstrations (SRD) for better in-context example selection and API-aware Constrained Decoding (API-CD) for constraining token generation based on API information. Results show that SRD reduces constraint violations and improves semantic parsing metrics, while API-CD can completely eliminate constraint violations, with the combination of both approaches yielding the best performance.

## Method Summary
The paper introduces a comprehensive framework for analyzing and mitigating constraint violations in utterance-to-API semantic parsing. The authors define four types of constraint violations: structural (e.g., unmatched brackets), functional (e.g., wrong function usage), argument (e.g., incorrect argument values), and function-argument association (e.g., wrong arguments for functions). They conduct extensive error analysis using these metrics across two datasets (ATIS and a custom dataset). To address these violations, they propose two strategies: Semantic-Retrieval of Demonstrations (SRD), which uses BM25 retrieval to select relevant in-context examples based on utterance and API information, and API-aware Constrained Decoding (API-CD), which constrains the token generation process using API schema information to ensure valid outputs. The combination of both approaches demonstrates significant improvements in constraint satisfaction and overall semantic parsing performance.

## Key Results
- SRD reduces constraint violations and improves semantic parsing metrics (exact match and tree accuracy)
- API-CD can completely eliminate constraint violations when API schema information is available
- Combining SRD and API-CD yields the best results, significantly outperforming baseline in-context learning approaches
- Error analysis reveals common failure modes including misunderstanding task semantics, lack of relevant examples, and inability to handle compositionality

## Why This Works (Mechanism)
The proposed approach works by first providing a fine-grained understanding of constraint violations through detailed metrics, then addressing these specific failure modes with targeted mitigation strategies. SRD improves the quality of in-context examples by retrieving demonstrations that are semantically relevant to both the utterance and the API, reducing cases where the model lacks appropriate guidance. API-CD directly constrains the generation process to ensure outputs conform to API specifications, eliminating invalid structures and function-argument associations. By combining semantic retrieval of demonstrations with API-aware decoding constraints, the system addresses both the knowledge gap (through better examples) and the generation gap (through structural constraints), resulting in more reliable and accurate semantic parsing outputs.

## Foundational Learning

**Constraint Violation Metrics** - Fine-grained evaluation metrics for structural, functional, argument, and function-argument association violations are needed to understand specific failure modes in semantic parsing. Quick check: Verify that metrics can distinguish between different types of constraint violations in sample outputs.

**In-Context Learning Limitations** - Large language models can struggle with task semantics, lack relevant examples, and fail to handle compositionality when relying solely on in-context demonstrations. Quick check: Identify examples where the model fails due to missing or irrelevant demonstrations.

**Semantic Retrieval for Demonstrations** - BM25-based retrieval can select in-context examples that are semantically relevant to both the utterance and API, improving the model's guidance. Quick check: Compare demonstration relevance scores between BM25 and random selection.

**API-aware Constrained Decoding** - Constraining token generation using API schema information can ensure valid output structures and prevent constraint violations. Quick check: Verify that constrained decoding produces outputs that conform to API specifications.

## Architecture Onboarding

**Component Map:** Utterance + API Schema -> BM25 Retrieval -> Demonstration Selection -> LLM with API-CD Constraints -> Constraint-Checked Output

**Critical Path:** The core workflow involves taking the user utterance and API schema as input, retrieving semantically relevant demonstrations using BM25, providing these to the LLM with API-aware constrained decoding, and validating the output against constraint metrics.

**Design Tradeoffs:** SRD trades computational overhead of retrieval against improved demonstration quality, while API-CD trades flexibility for guaranteed constraint satisfaction. The combination provides better accuracy but requires both API schema availability and retrieval infrastructure.

**Failure Signatures:** Common failures include retrieval of irrelevant demonstrations (SRD), API schema mismatches or incompleteness (API-CD), and generation that satisfies constraints but not semantics (both approaches).

**First Experiments:** 1) Run BM25 retrieval on a small test set and manually verify demonstration relevance. 2) Apply API-CD constraints to sample generations and check for complete elimination of structural violations. 3) Combine SRD and API-CD on a held-out dataset and measure constraint violation reduction.

## Limitations
- Evaluation limited to ATIS dataset and one custom semantic parsing dataset, limiting generalizability to other domains
- SRD relies on BM25 retrieval without exploring more advanced semantic retrieval methods
- API-aware Constrained Decoding requires API schema information, which may not always be available in real-world deployment scenarios

## Confidence

**High confidence** in the constraint violation metrics and their utility for error analysis - the metrics provide clear insights into specific failure modes and have been validated across datasets.

**Medium confidence** in the effectiveness of SRD and API-CD - results are promising but limited to specific datasets, and the relative contribution of each component needs further validation.

**Low confidence** in the scalability of these approaches to more complex APIs with larger output spaces or to domains with limited available demonstrations.

## Next Checks

1. Test the constraint violation metrics and mitigation strategies on additional semantic parsing datasets with varying complexity, such as Overnight or complex MultiWOZ-style APIs.

2. Evaluate SRD using semantic retrieval methods (e.g., dense retrieval or re-ranking) instead of BM25 to assess if demonstration quality can be further improved.

3. Investigate the performance of API-CD when API schema information is incomplete or unavailable, simulating more realistic deployment conditions.
