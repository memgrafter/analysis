# A Framework for History-Aware Hyperparameter Optimisation in Reinforcement Learning

## Quick Facts
- arXiv ID: 2303.05186
- Source URL: https://arxiv.org/abs/2303.05186
- Reference count: 33
- Primary result: History-aware framework combining CEP and temporal models significantly improves RL training stability and reward values compared to traditional HPO methods.

## Executive Summary
This paper introduces a novel framework for dynamically optimizing hyperparameters during a reinforcement learning agent's lifetime. The approach combines complex event processing (CEP) for real-time monitoring with temporal models (TMs) to analyze historical performance data. A key innovation is an epsilon-greedy logic that adjusts hyperparameters based on detected stability windows, enabling more efficient exploration of the hyperparameter space. The framework was validated using Deep Q-Networks (DQN) in a 5G mobile communications case study, demonstrating significant improvements over traditional optimization methods like grid search, random search, and Bayesian optimization.

## Method Summary
The framework integrates RL agents with CEP engines (Esper) and temporal graph databases (Greycat TGDB) to monitor performance and trigger hyperparameter updates. RL agents publish decision, observation, and reward traces to an MQTT broker. The CEP engine detects stability patterns in reward signals over defined time windows, while the temporal model stores historical state changes. When stability is detected without improvement, an epsilon-greedy logic probabilistically selects new hyperparameter values for exploration. The system was implemented and tested using DQN agents optimizing the discount factor (gamma) in a 5G communications scenario.

## Key Results
- History-aware framework achieved higher maximum reward values compared to grid search, random search, and Bayesian optimization
- Training stability improved significantly with dynamic hyperparameter adjustment during agent lifetime
- The approach successfully balanced exploration and exploitation of the hyperparameter space through epsilon-greedy logic

## Architecture Onboarding

- Component map: RL Agent (DQN) -> MQTT Broker -> CEP Engine (Esper) -> Temporal Model (Hawk + Greycat TGDB) -> Graph Listener -> Feedback to RL Agent
- Critical path:
  1. RL Agent publishes trace events to MQTT
  2. CEP Engine detects stability patterns
  3. Temporal Model updates TGDB with new state
  4. Graph Listener computes HPO decision
  5. Feedback is sent back to RL Agent
- Design tradeoffs:
  - Real-time CEP vs. batch processing: CEP enables immediate adaptation but adds CPU load.
  - TGDB storage vs. memory: TGDB allows long-term queries but increases persistence overhead.
  - Exploration probability ε vs. exploitation: Higher ε increases hyperparameter search but risks destabilizing training.
- Failure signatures:
  - No feedback messages → CEP pattern never triggered or MQTT disconnect
  - TGDB grows unbounded → missing retention policy or high-frequency updates
  - Reward never stabilizes → too strict stability threshold or noisy environment
- First 3 experiments:
  1. Replace MQTT with in-memory queue to isolate CEP/TM logic from networking.
  2. Hard-code a stable reward window and verify Graph Listener produces expected feedback.
  3. Vary ε in the epsilon-greedy logic and measure hyperparameter update frequency.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can the proposed history-aware framework be extended to optimize multiple hyperparameters simultaneously rather than focusing on a single hyperparameter like the discount factor?
- Basis in paper: [explicit] The paper mentions the limitation of the current approach focusing on a single hyperparameter and suggests future work will involve allowing the tuning of multiple hyperparameters using different threads or timelines.
- Why unresolved: The current implementation and experiments only demonstrate the optimization of the discount factor. Extending the framework to handle multiple hyperparameters simultaneously would require significant architectural changes and validation.
- What evidence would resolve it: Successful implementation and experimental results showing improved performance when optimizing multiple hyperparameters (e.g., learning rate, epsilon, discount factor) simultaneously using the extended framework.

### Open Question 2
- Question: What alternative criteria for stability could be implemented to address the limitations of the current approach when dealing with noisy reward signals?
- Basis in paper: [explicit] The paper discusses the challenge of defining stability and mentions potential issues when the reward signal is noisy, suggesting future work to explore different criteria such as Z-score or absolute deviation around the median.
- Why unresolved: The current stability criterion relies on a fixed threshold and time window, which may not be robust to noisy data. Implementing and evaluating alternative criteria would require extensive experimentation and validation.
- What evidence would resolve it: Comparative analysis of the proposed framework's performance using different stability criteria (e.g., Z-score, absolute deviation) on various RL tasks with noisy reward signals, demonstrating improved stability and performance.

### Open Question 3
- Question: How can the proposed history-aware framework be applied to other RL algorithms beyond DQN, such as policy gradient methods or actor-critic approaches?
- Basis in paper: [inferred] While the paper demonstrates the framework's effectiveness with DQN, it suggests future work to benchmark the approach with other RL methods. The framework's architecture is designed to be reusable for different RL algorithms.
- Why unresolved: The current experiments and implementation are specific to DQN. Adapting the framework to other RL algorithms would require modifications to the event patterns, temporal models, and epsilon-greedy logic to accommodate different algorithmic structures and hyperparameter spaces.
- What evidence would resolve it: Successful implementation and experimental results showing improved performance when applying the history-aware framework to other RL algorithms (e.g., A3C, PPO, TRPO) on various benchmark tasks.

## Limitations

- The stability detection mechanism (Eq. 5) lacks quantitative validation through ablation studies on time-window size or threshold sensitivity
- Storage overhead and performance impact of the TGDB-based temporal model are not characterized
- The framework was only validated on DQN agents optimizing a single hyperparameter, limiting generalizability

## Confidence

- **High confidence** in the basic architectural framework combining CEP and TM for runtime HPO monitoring, as the components are well-established in their respective domains
- **Medium confidence** in the specific stability detection algorithm and epsilon-greedy HPO logic, as the paper provides conceptual descriptions but limited empirical validation
- **Low confidence** in the claimed improvements over traditional HPO methods without access to the full experimental setup, baseline implementations, and statistical significance testing
