# EdgeTran: Co-designing Transformers for Efficient Inference on Mobile Edge Platforms

## Quick Facts
- arXiv ID: 2303.13745
- Source URL: https://arxiv.org/abs/2303.13745
- Reference count: 40
- Key outcome: Framework that co-designs transformer models and edge devices, achieving 15.0% lower latency, 10.0x lower energy, and 10.8x lower peak power compared to server GPUs

## Executive Summary
EdgeTran presents a framework for co-designing transformer models and edge devices to achieve efficient inference. The approach profiles hardware performance across diverse edge platforms and uses this information to search for optimal model-device pairs. By expanding the design space of transformer architectures (FlexiBERT 2.0) and applying block-level grow-and-prune optimization (GPTran), EdgeTran achieves significant improvements in both accuracy and hardware efficiency compared to traditional approaches.

## Method Summary
EdgeTran co-designs transformer models and edge devices through a four-stage process: (1) FlexiBERT 2.0 expands the design space with heterogeneous architectures and attention mechanisms; (2) ProTran profiles latency, energy, and power consumption across diverse edge platforms using active learning and surrogate modeling; (3) BOSHCODE searches for optimal model-device pairs using Bayesian optimization with second-order gradients; (4) GPTran applies block-level grow-and-prune to further optimize the converged model. The framework balances accuracy with hardware constraints through an integrated search process.

## Key Results
- Models 2.8x smaller than BERT-Base with 0.8% higher accuracy
- 15.0% lower latency compared to server GPU baselines
- 10.0x lower energy consumption on edge devices
- 10.8x lower peak power draw on edge devices

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Co-designing transformer models with specific edge devices improves overall efficiency compared to generic model-device pairs.
- Mechanism: By profiling latency, energy, and power consumption for various transformer architectures on diverse edge platforms, EdgeTran can select the optimal model-device combination that minimizes hardware performance metrics while maintaining high accuracy.
- Core assumption: The performance of a transformer model is highly dependent on the specific hardware platform it runs on, and there exists an optimal pairing for each task.

- Claim: The GPTran post-processing step further optimizes the transformer model's accuracy and hardware performance.

## Architecture Onboarding

- Component map:
  FlexiBERT 2.0 -> ProTran -> BOSHCODE -> GPTran

- Critical path:
  1. Expand the design space using FlexiBERT 2.0
  2. Profile hardware performance using ProTran
  3. Run co-design using BOSHCODE
  4. Apply post-processing using GPTran

- Design tradeoffs:
  - Larger design space vs. computational feasibility of search
  - Model accuracy vs. hardware performance (latency, energy, power)
  - Model size vs. inference speed on edge devices

- Failure signatures:
  - Inaccurate hardware performance predictions due to outdated profiling data
  - Suboptimal model-device pairs due to incomplete design space or insufficient profiling
  - Poor model performance due to excessive pruning or growth during GPTran

- First 3 experiments:
  1. Profile hardware performance of a small set of transformer architectures on a target edge device to validate the ProTran framework.
  2. Run co-design using BOSHCODE on a limited design space to ensure the optimization process is working correctly.
  3. Apply GPTran to a converged model and evaluate the impact on accuracy and hardware performance.

## Limitations
- Limited evaluation scope with only three GLUE tasks tested
- Reliance on synthetic inputs rather than real-world application workloads for hardware profiling
- Computational overhead of GPTran's multiple grow-and-prune iterations may offset benefits for certain edge deployment scenarios

## Confidence
- **High Confidence**: The co-design framework's ability to find optimal model-device pairs is well-supported by the methodology.
- **Medium Confidence**: The accuracy improvements from FlexiBERT 2.0's expanded design space and GPTran's post-processing steps are plausible but require more extensive validation.
- **Low Confidence**: The energy and power consumption comparisons between edge devices and server GPUs may be misleading due to differences in workload characteristics and synthetic evaluation inputs.
