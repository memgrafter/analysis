# Collaborative Recommendation Model Based on Multi-modal Multi-view Attention Network: Movie and literature cases

## Quick Facts
- arXiv ID: 2305.15159
- Source URL: https://arxiv.org/abs/2305.15159
- Reference count: 40
- CRMMAN outperforms state-of-the-art methods by 2.08% AUC, 2.20% NDCG@5, and 2.26% NDCG@10 on average.

## Executive Summary
This paper addresses the problem of modeling user dislikes in collaborative recommendation models. Most existing methods focus on user preferences but ignore dislikes, which can lead to incomplete user profiles. The authors propose CRMMAN, a novel model that represents users from both preference and dislike views, extracting semantic and structural information from knowledge graphs to enrich item representations. The model uses a multi-view attention mechanism to generate user embeddings based on positive and negative interactions, achieving significant improvements over state-of-the-art methods on MovieLens-1M and Book-Crossing datasets.

## Method Summary
CRMMAN builds a collaborative recommendation model that captures both user preferences and dislikes using multi-modal information from knowledge graphs. The method encodes items using both semantic information (via BERT on text descriptions) and structural information (via GAT on knowledge graph relationships), then aggregates these modalities. Users are represented using two separate embeddings: one for preferred items and one for disliked items. Multi-head self-attention is applied separately to each view to generate weighted user representations. The final prediction is a weighted sum of dot products between candidate item embedding and each user view embedding, optimized with negative sampling.

## Key Results
- CRMMAN improves AUC, NDCG@5, and NDCG@10 by 2.08%, 2.20%, and 2.26% on average compared to state-of-the-art methods
- Ablation studies demonstrate the effectiveness of the multi-modal and multi-view mechanisms
- The model shows consistent performance gains across both MovieLens-1M and Book-Crossing datasets

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The multi-view user representation mechanism captures both preference and dislike signals, improving model performance.
- Mechanism: Users are represented using two separate embeddings: one for preferred items and one for disliked items. The final prediction is a weighted sum of dot products between candidate item embedding and each user view embedding.
- Core assumption: Users' negative interactions contain meaningful information about their preferences that should be modeled explicitly.
- Evidence anchors:
  - [abstract] "users are represented from both preference and dislike views" and ablation studies show "multi-view mechanism" improves performance
  - [section 4.2] "instead of traditionally set up a separate vector for each user, we use the vector of items that have interacted with the user to represent the user"
  - [corpus] Weak: No direct corpus evidence of multi-view mechanisms in related work, but "Bayes-enhanced Multi-view Attention Networks" suggests multi-view attention is an active area
- Break condition: If negative interactions are not truly disliked items but missing recommendations, the dislike view would capture noise rather than signal.

### Mechanism 2
- Claim: Multi-modal item representations (semantic + structural) provide richer item embeddings than single modality approaches.
- Mechanism: Semantic information is extracted using BERT on text descriptions, while structural information is captured using GAT on knowledge graph relationships. These are aggregated to form final item embeddings.
- Core assumption: Both semantic content and structural relationships between items contain complementary information useful for recommendations.
- Evidence anchors:
  - [abstract] "semantic and structural information extracted from the scene is employed to enrich the item representation"
  - [section 4.1] "We consider two modalities of information: semantic information and structural information" and ablation experiments show multi-modal effects
  - [corpus] Moderate: "Bridging the Cross-modal Semantic Gap for Multi-modal Recommendation" suggests multi-modal approaches are current research focus
- Break condition: If semantic and structural modalities are highly correlated or one modality dominates, the multi-modal approach provides diminishing returns.

### Mechanism 3
- Claim: The attention-based aggregation mechanism effectively weights item contributions to user representations.
- Mechanism: Multi-head self-attention is applied separately to preferred and disliked items, generating weighted user representations that emphasize important items.
- Core assumption: Not all user interaction items contribute equally to understanding user preferences; attention weights can identify the most informative items.
- Evidence anchors:
  - [abstract] "multi-view attention mechanism to generate user embeddings based on positive and negative interactions"
  - [section 4.2] "We apply the multi-head self-attention mechanism to the items in ξpre f er u and ξdislike u, respectively"
  - [corpus] Weak: While attention mechanisms are common in recommender systems, specific evidence for this multi-view attention approach is not in corpus
- Break condition: If attention weights converge to uniform values or if the attention mechanism overfits to training data patterns.

## Architecture Onboarding

- Component map:
  Input layer: User historical interactions (positive and negative) + candidate item
  Item Encoder: Semantic information embedding (BERT) + Structural information embedding (GAT) + Aggregation layer
  Multi-view User Representation: Split items into preferred/disliked → Multi-head self-attention → User preference/dislike embeddings
  Click-through Rate Prediction: Dot products between user views and candidate item + Weighted sum
  Training: Negative sampling strategy with cross-entropy loss

- Critical path: Item Encoder → Multi-view User Representation → Click-through Rate Prediction
  The item encoder must process semantic and structural information efficiently, as downstream components depend on quality embeddings.

- Design tradeoffs:
  - Single vs. multi-modal item representations: Multi-modal provides richer information but increases complexity and computational cost
  - Single vs. multi-view user representations: Multi-view captures dislikes but requires careful weight balancing between preference and dislike views
  - Concatenate vs. average aggregation: Concatenate preserves modality-specific information but increases embedding dimension

- Failure signatures:
  - Performance drops significantly on sparse datasets: May indicate over-reliance on knowledge graph information
  - Preference and dislike view weights become unstable: May indicate insufficient negative samples or noisy dislike signals
  - Attention weights become uniform: May indicate attention mechanism not learning meaningful item importance

- First 3 experiments:
  1. Ablation study: Remove semantic modality → Should observe performance drop, especially on NDCG metrics
  2. Ablation study: Remove multi-view mechanism → Should observe performance drop, particularly on AUC metric
  3. Hyperparameter sensitivity: Vary number of historical records B → Should observe optimal B around 10-15 for most datasets

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does modeling dislikes affect long-tail recommendation performance compared to standard preference-only methods?
- Basis in paper: [explicit] Authors argue that modeling dislikes can improve user profile completeness and recommend performance, and they compare AUC, NDCG@5, and NDCG@10 against baselines that do not model dislikes.
- Why unresolved: The paper shows overall performance gains but does not analyze the impact on long-tail item recommendations, which are often more challenging.
- What evidence would resolve it: A breakdown of performance metrics specifically for long-tail items, showing improvement when dislikes are modeled versus not.

### Open Question 2
- Question: What is the optimal strategy for handling missing modalities (e.g., items without text descriptions) in the multi-modal item encoder?
- Basis in paper: [inferred] The model relies on semantic and structural information from knowledge graphs, but the paper does not discuss how to handle items lacking one or both modalities.
- Why unresolved: Handling incomplete data is critical for real-world deployment, yet the paper assumes all items have both modalities.
- What evidence would resolve it: Experiments comparing performance with and without missing modality imputation strategies, and an analysis of the trade-offs.

### Open Question 3
- Question: How does the choice of knowledge graph construction (e.g., threshold S_m for edge creation) influence recommendation accuracy?
- Basis in paper: [explicit] The authors construct a single-part graph using a threshold S_m, but they do not explore the sensitivity of recommendation performance to different threshold values.
- Why unresolved: The threshold directly affects the structural information extracted, yet its impact on model performance is not quantified.
- What evidence would resolve it: A sensitivity analysis showing recommendation accuracy across a range of S_m values, identifying an optimal threshold.

## Limitations

- The model relies heavily on knowledge graph quality and coverage, with poor KG construction potentially significantly impacting performance
- The negative sampling strategy assumes all non-preferred items are truly disliked, which may not hold in real-world scenarios
- The computational cost of multi-modal encoding (BERT + GAT) and multi-view attention mechanisms may limit scalability to large-scale industrial applications

## Confidence

**High Confidence**: The multi-view mechanism's effectiveness in capturing both preference and dislike signals is well-supported by ablation studies showing consistent performance improvements across both datasets. The mathematical formulation of the attention-based user representation is clearly defined and implementable.

**Medium Confidence**: The multi-modal item representation approach shows performance benefits, but the relative contribution of semantic vs. structural modalities is not clearly quantified. The KG construction methodology (S_m thresholds) lacks detailed justification for parameter choices.

**Low Confidence**: The negative sampling strategy's assumption that all non-liked items represent dislikes may not hold in practice. The model's performance on highly sparse datasets (like Book-Crossing) may be artificially inflated by the KG information rather than true collaborative signal.

## Next Checks

1. **Cross-domain validation**: Test CRMMAN on additional domains (e.g., music, news) to verify the multi-view dislike mechanism generalizes beyond movies and books.

2. **Negative interaction quality analysis**: Conduct user studies to verify whether non-interacted items truly represent dislikes versus unobserved recommendations, and evaluate model performance under different negative sampling strategies.

3. **Scalability benchmarking**: Measure training/inference time and memory usage on progressively larger datasets to assess practical deployment feasibility, particularly focusing on the BERT and GAT components.
