# Multiplexed gradient descent: Fast online training of modern datasets on hardware neural networks without backpropagation

## Quick Facts
- arXiv ID: 2303.03986
- Source URL: https://arxiv.org/abs/2303.03986
- Reference count: 40
- Multiplexed gradient descent (MGD) is a framework for training neural networks in hardware without backpropagation, using zero-order optimization techniques

## Executive Summary
Multiplexed gradient descent (MGD) presents a novel approach to training neural networks on hardware platforms without requiring backpropagation. The method uses zero-order optimization by applying small perturbations to network parameters and globally broadcasting resulting cost changes. Individual parameters then extract partial gradients via homodyne detection using orthogonal perturbations. MGD can implement various optimization algorithms by tuning time constants and perturbation types, making it compatible with analog, digital, or mixed-signal hardware. Simulations demonstrate MGD can train modern datasets like CIFAR-10 and Fashion-MNIST with accuracy comparable to backpropagation while offering potential for significantly faster training on hardware.

## Method Summary
MGD applies small perturbations to each network parameter using unique frequencies or code patterns. The resulting cost changes are globally broadcast to all parameters. Each parameter then performs homodyne detection by integrating the product of its own perturbation signal with the global cost signal, effectively extracting its individual gradient contribution. By adjusting time constants (τp, τθ, τx) and perturbation types, MGD can implement finite-difference gradient descent, coordinate descent, or SPSA. The framework is designed to work with various hardware implementations including analog, digital, or mixed-signal systems, with parameters updated locally using only broadcast cost information.

## Key Results
- MGD achieves similar accuracy to backpropagation when training on CIFAR-10 and Fashion-MNIST datasets
- The method demonstrates robustness to noise and hardware imperfections in simulations
- Under realistic hardware assumptions, MGD can train networks orders of magnitude faster than GPU backpropagation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: MGD approximates gradients without backpropagation by using orthogonal perturbations and homodyne detection
- Mechanism: Each parameter is perturbed at a unique frequency or code pattern. The resulting cost change is broadcast globally. Each parameter then integrates the product of its own perturbation with the global cost change, filtering out contributions from other parameters due to orthogonality
- Core assumption: Perturbations are pairwise orthogonal (deterministic) or statistically uncorrelated (random), allowing clean extraction of individual parameter effects
- Evidence anchors:
  - [abstract]: "It applies small perturbations to network parameters and globally broadcasts the resulting cost changes to all parameters, which then extract partial gradients via homodyne detection"
  - [section]: "To extract a given ∆Ci, all we need to do is integrate the product of the input perturbation ˜θi(t) with ˜C(t). The integration takes the form of a homodyne detection, where unwanted perturbations (frequencies) from other parameters are eliminated via integration"
- Break condition: When perturbation signals are not sufficiently orthogonal, cross-talk increases and gradient approximation degrades

### Mechanism 2
- Claim: MGD can implement different optimization algorithms by adjusting time constants τp, τθ, and τx
- Mechanism: By setting τθ = Pτp (P = number of parameters) and using sequential perturbations, MGD implements finite-difference gradient descent. Setting τθ = τp implements coordinate descent. Using simultaneous random perturbations implements SPSA
- Core assumption: The choice of time constants directly controls which gradient approximation method is used, without changing the underlying perturbation-broadcast-extraction framework
- Evidence anchors:
  - [abstract]: "MGD can implement various optimization algorithms by tuning time constants and perturbation types"
  - [section]: "Using same procedure as above but with the integration time reduced to a single timestep, i.e. τθ = τp. This corresponds exactly to coordinate descent"
- Break condition: When τθ is too short relative to the perturbation timescale, gradient approximation becomes too noisy to be useful

### Mechanism 3
- Claim: MGD achieves faster training than backpropagation on hardware by reducing computational overhead
- Mechanism: MGD avoids the need for backward error propagation through the network. Parameters update locally using only broadcast cost information. This eliminates the synchronization and memory requirements of backpropagation
- Core assumption: Hardware constraints (like slow weight updates or limited bandwidth) make backpropagation more expensive than the perturbation-broadcast approach
- Evidence anchors:
  - [abstract]: "Assuming realistic timescales and hardware parameters, our results indicate that these optimization techniques can train a network on emerging hardware platforms orders of magnitude faster than the wall-clock time of training via backpropagation on a standard GPU"
  - [section]: "Because all the parameters are being perturbed and updated simultaneously, we call the framework multiplexed"
- Break condition: When hardware can efficiently implement backpropagation (e.g., with dedicated analog circuits for error propagation), the advantage diminishes

## Architecture Onboarding

- Component map:
  Perturbation generator -> Parameter array -> Inference engine -> Cost calculator -> Global broadcast -> Homodyne detector -> Parameter updater

- Critical path:
  Input → Parameter perturbation → Inference → Cost calculation → Global broadcast → Homodyne detection → Parameter update

- Design tradeoffs:
  - Perturbation type: Sinusoidal (clean extraction, requires precise frequency control) vs. code-based (robust to timing errors, requires code generation)
  - Time constants: Longer τθ gives better gradient approximation but slower updates; shorter τθ gives faster but noisier updates
  - Integration method: Analog (continuous, requires highpass filtering) vs. digital (discrete, requires sample-and-hold)

- Failure signatures:
  - Gradient approximation diverges: Check perturbation orthogonality and integration time
  - Training stalls: Verify cost calculation accuracy and learning rate appropriateness
  - Oscillations in parameter updates: Reduce learning rate or increase gradient integration time

- First 3 experiments:
  1. Implement MGD on a simple 2-2-1 network solving XOR problem, compare with backpropagation
  2. Test different perturbation types (sinusoidal vs. code-based) on same network and measure training time
  3. Add simulated hardware noise to cost signal and measure robustness of MGD training vs. backpropagation

## Open Questions the Paper Calls Out

- Question: What is the optimal balance between τθ and τx for different batch sizes and network architectures?
  - Basis in paper: [explicit] The paper mentions that varying τθ and τx allows implementation of different optimization algorithms and affects training speed and accuracy. It states that "for a given learning rate, there is a threshold amount of noise below which the training time is minimally changed" and that "waiting a long time for an extremely accurate gradient then taking a large step is less productive than taking a series of short (but less accurate) steps."
  - Why unresolved: The paper only tests a few specific values of τθ and τx for each dataset and network architecture. It does not provide a general formula or guidelines for choosing optimal values based on batch size or other factors.
  - What evidence would resolve it: Systematic experiments varying τθ and τx for different batch sizes, network architectures, and datasets, with analysis of training speed and final accuracy to determine optimal combinations.

- Question: How does MGD performance scale to much larger datasets and deeper networks?
  - Basis in paper: [explicit] The paper states "While in this paper we only examined feed forward networks, it has already been demonstrated that is possible to use perturbative techniques to train recurrent neural networks [56], spiking networks [53] and other non-standard networks at small scale; future work remains to demonstrate their utility on problems of modern interest." It also mentions testing on CIFAR-10 and Fashion-MNIST but not much larger datasets like ImageNet.
  - Why unresolved: The paper only tests MGD on relatively small networks and datasets. It does not investigate how MGD performance scales to very large datasets like ImageNet or very deep networks with hundreds of layers.
  - What evidence would resolve it: Experiments training MGD on much larger datasets and deeper networks, with analysis of training speed, final accuracy, and scaling behavior compared to backpropagation.

- Question: What is the best way to implement MGD in analog hardware with realistic non-idealities?
  - Basis in paper: [explicit] The paper discusses various non-idealities that could affect analog hardware implementations, such as noise, device-to-device variations, and imperfect parameter updates. It mentions that "these non-idealities affected the training speed of the network, but did not prevent the desired problem from being solved" and that "one can compensate for large amounts of cost noise in a system simply by reducing the learning rate."
  - Why unresolved: The paper only simulates the effects of non-idealities, but does not test MGD on actual analog hardware. It also does not provide specific design guidelines or error correction techniques for implementing MGD in analog hardware.
  - What evidence would resolve it: Experiments implementing MGD on analog hardware platforms with realistic non-idealities, with analysis of training performance and comparison to ideal simulations. Development and testing of specific design techniques or error correction methods to improve MGD performance in analog hardware.

## Limitations
- Practical implementation of homodyne detection in real hardware systems remains unproven
- Claims about orders-of-magnitude speed improvements depend heavily on specific hardware characteristics
- Scaling to very large datasets and deep networks has not been experimentally validated

## Confidence
- **High confidence**: The mathematical framework for MGD is sound and the orthogonality principle for gradient extraction is well-established in signal processing
- **Medium confidence**: The simulation results showing competitive performance with backpropagation, though based on idealized assumptions
- **Low confidence**: Claims about orders-of-magnitude speed improvements on actual hardware, as these depend heavily on specific hardware characteristics not fully detailed in the paper
