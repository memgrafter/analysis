# Explainable Multi-Agent Reinforcement Learning for Temporal Queries

## Quick Facts
- arXiv ID: 2305.10378
- Source URL: https://arxiv.org/abs/2305.10378
- Reference count: 10
- Key outcome: Generates policy-level contrastive explanations for multi-agent reinforcement learning to answer temporal user queries via PCTL* encoding and probabilistic model checking

## Executive Summary
This work presents an approach for generating policy-level contrastive explanations for multi-agent reinforcement learning (MARL) to answer temporal user queries. The method encodes queries as PCTL* logic formulas and checks feasibility under a given MARL policy using probabilistic model checking. When queries are infeasible, the approach generates correct and complete explanations to identify failure reasons. The system was successfully applied to four benchmark MARL domains with up to 9 agents, and user studies demonstrated significant improvements in user performance and satisfaction.

## Method Summary
The approach encodes temporal user queries as PCTL* logic formulas and checks feasibility under MARL policies via probabilistic model checking on Markov decision process (MDP) abstractions. When queries are infeasible, guided rollout expands the abstraction through targeted sampling, followed by Quine-McCluskey minimization to generate minimal Boolean formulas that distinguish successful from failed executions. These formulas are translated into natural language explanations that pinpoint specific failure causes.

## Key Results
- Successfully applied to four benchmark MARL domains with up to 9 agents
- Generated explanations that significantly improved user performance and satisfaction
- Verified query feasibility within seconds using probabilistic model checking
- Produced correct and complete explanations for infeasible queries using minimal Boolean formulas

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Encoding temporal user queries as PCTL* logic formulas enables systematic verification of MARL policy feasibility.
- Mechanism: Temporal queries are translated into PCTL* formulas that specify the desired sequence of task completions. Probabilistic model checking then exhaustively explores the MMDP abstraction to determine if any execution path satisfies the formula.
- Core assumption: The MMDP abstraction accurately represents the reachable state space and transition probabilities of the MARL policy.
- Evidence anchors: [abstract]: "encodes the temporal query as a PCTL* logic formula and checks if the query is feasible under a given MARL policy via probabilistic model checking"; [section 4.2]: "We encode a temporal user query ρ = ⟨τ1,τ2,⋯⟩ as a PCTL* logic [Aziz et al., 1995] formula ϕ with a 'sequencing' specification template"
- Break condition: If the MMDP abstraction is incomplete or inaccurate, the model checker may incorrectly report infeasibility or feasibility.

### Mechanism 2
- Claim: Guided rollout expands the MMDP abstraction to capture additional policy behaviors, reducing false infeasibility reports.
- Mechanism: When the initial MMDP fails to satisfy the PCTL* formula, the guided rollout procedure prioritizes exploring states with high query conformance (U values) and low sample counts. This targeted sampling generates new transitions that better approximate the true policy behavior before rechecking feasibility.
- Core assumption: Additional sampling from the policy converges to a representative approximation of all feasible executions.
- Evidence anchors: [section 4.3]: "The search tree stops expanding a node with U=−∞ since the user query is already violated along the path" and "This ordering prioritizes the exploration of states with a higher degree of user query conformance"; [section 5]: "It only took seconds to check the feasibility of a user query and generate explanations when needed"
- Break condition: If RolloutNum or DepthLimit are insufficient, the MMDP may still miss critical behaviors, leading to incorrect infeasibility claims.

### Mechanism 3
- Claim: Quine-McCluskey minimization generates minimal, actionable explanations for task failures.
- Mechanism: When a query is infeasible, the algorithm identifies target states where the failed task is completed and non-target states where it is not. The Quine-McCluskey algorithm then computes a minimal Boolean formula distinguishing these sets, which is translated into natural language explanations that isolate the precise failure cause.
- Core assumption: The target and non-target state sets are correctly identified and sufficiently representative.
- Evidence anchors: [section 4.4]: "we obtain a minimized Boolean formula φ by applying the Quine-McCluskey algorithm [Quine, 1952], which represents the minimal description of the states in the target set V compared to those in the non-target set V"; [section 6.2]: "Participants were able to answer more questions correctly based on explanations generated by our proposed approach"
- Break condition: If the state sets are incomplete or incorrectly labeled, the minimal formula may be misleading or fail to capture the true failure reason.

## Foundational Learning

- Concept: PCTL* temporal logic for multi-agent task sequencing
  - Why needed here: PCTL* provides the formal syntax to express complex temporal dependencies between agent tasks, which is essential for specifying user queries about multi-agent behavior.
  - Quick check question: How would you encode a query asking for task A to be completed before task B using PCTL* syntax?

- Concept: Markov decision process (MDP) abstractions for policy analysis
  - Why needed here: The MMDP abstraction compresses the high-dimensional state space into Boolean predicates about task completion, making formal verification computationally tractable.
  - Quick check question: What information is lost when abstracting a joint state into Boolean task-completion predicates?

- Concept: Contrastive explanation generation via minimal distinguishing formulas
  - Why needed here: Users need to understand not just that a query fails, but why it fails; minimal Boolean formulas isolate the specific conditions causing failure.
  - Quick check question: Why is the Quine-McCluskey algorithm appropriate for finding minimal distinguishing conditions?

## Architecture Onboarding

- Component map: User query → PCTL* encoder → MMDP builder → Model checker → (if infeasible) Guided rollout → (if still infeasible) Quine-McCluskey generator → Natural language translator → Explanation output
- Critical path: Query → PCTL* encoding → MMDP construction → Model checking → (if failed) Guided rollout → Recheck → (if still failed) Explanation generation
- Design tradeoffs:
  - Completeness vs. scalability: More exhaustive sampling improves accuracy but increases runtime
  - Abstraction granularity: Finer predicates capture more detail but explode state space
  - Explanation minimality vs. comprehensiveness: Single minimal explanations are clearer but may miss related failure modes
- Failure signatures:
  - Model checker reports infeasible but policy can actually achieve query → insufficient sampling
  - Generated explanations are too vague → incorrect state set labeling or insufficient target states
  - Runtime too long → overly complex PCTL* formula or large MMDP state space
- First 3 experiments:
  1. Run with a simple SR domain (3 agents, 3 tasks) and a feasible query to verify YES responses
  2. Run with an infeasible query in the same domain to verify explanation generation and correctness
  3. Gradually increase agents/tasks and measure MMDP size growth and runtime scaling

## Limitations
- Scalability constraints due to exponential growth of MMDP state space with increasing agents and task complexity
- Guided rollout completeness depends on heuristic prioritization that may miss critical execution paths
- Explanation quality heavily relies on accurate state set identification, which can be challenging with ambiguous or overlapping task conditions

## Confidence
- **High Confidence**: The core mechanism of encoding temporal queries as PCTL* formulas and verifying feasibility through probabilistic model checking is well-established and theoretically sound.
- **Medium Confidence**: The guided rollout procedure effectively expands the MMDP abstraction, though its completeness guarantees depend on sampling depth and breadth.
- **Medium Confidence**: The Quine-McCluskey-based explanation generation produces minimal distinguishing formulas, but the quality of explanations depends on correct state set labeling.

## Next Checks
1. **Scalability Test**: Evaluate the approach on domains with 10+ agents and measure how MMDP size and verification time scale. Compare against theoretical complexity predictions.
2. **Explanation Completeness**: Systematically generate explanations for a variety of query failures and verify that each explanation correctly identifies at least one necessary condition for the failure. Check if multiple minimal explanations are needed for complete understanding.
3. **Robustness to Policy Variations**: Test the approach across different MARL algorithms (not just shared experience actor-critic) to assess whether the MMDP abstraction and verification process generalize beyond the specific training method used in the paper.
