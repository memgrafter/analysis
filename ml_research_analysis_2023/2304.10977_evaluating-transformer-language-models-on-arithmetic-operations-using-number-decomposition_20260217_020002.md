# Evaluating Transformer Language Models on Arithmetic Operations Using Number Decomposition

## Quick Facts
- **arXiv ID**: 2304.10977
- **Source URL**: https://arxiv.org/abs/2304.10977
- **Reference count**: 0
- **Primary result**: Decomposition pipeline improves 5-digit addition accuracy by 63% over baseline

## Executive Summary
This paper introduces Calculon, a GPT-2 model fine-tuned to perform arithmetic operations using number decomposition. The method breaks numbers into place-value components (units, tens, hundreds, etc.) and trains the model to compute digit-by-digit like children do at school. Experiments demonstrate that this approach dramatically improves accuracy on addition and subtraction tasks, particularly for multi-digit numbers, while revealing fundamental limitations in transformer reasoning for multiplication operations.

## Method Summary
The authors fine-tune GPT-2 Small (117M parameters) on arithmetic datasets generated by randomly sampling number pairs and computing results. Three approaches are compared: baseline (no decomposition), spaced (digits separated by spaces), and decomposition (digits with explicit magnitude labels). Models are trained for 25 epochs with learning rate 10^-4 and batch size 32 using Adam optimizer. Evaluation uses greedy decoding on test sets from Brown et al. (2020), measuring accuracy across addition, subtraction, and multiplication tasks with numbers ranging from 2 to 5 digits.

## Key Results
- Decomposition pipeline achieves 63% accuracy improvement on 5-digit addition versus baseline
- Calculon shows 75% accuracy gain over spaced approach on 5-digit subtraction
- All approaches struggle with multiplication, suggesting transformers lack necessary reasoning capabilities for this operation

## Why This Works (Mechanism)

### Mechanism 1
Decomposing numbers into place-value units enables transformers to learn arithmetic by aligning token sequences with the standard school algorithm. By representing numbers as sequences of digit-magnitude pairs, the model can perform addition/subtraction digit-by-digit in the same order children learn, allowing it to capture the place-value reasoning steps explicitly.

### Mechanism 2
Separating digits with spaces improves tokenization granularity, allowing each digit to be a distinct token. This forces the BPE tokenizer to split numbers into individual digits, making the model treat each digit as an atomic symbol rather than part of a subword unit, which simplifies digit-wise operations.

### Mechanism 3
Providing explicit magnitude labels in the decomposition step significantly improves performance over merely spacing digits. The model can leverage the magnitude tokens to understand place value and apply correct carry/borrow rules, rather than inferring magnitude from position alone.

## Foundational Learning

- **Place-value arithmetic**: The decomposition pipeline relies on the model learning to process each digit with its corresponding magnitude, mirroring manual addition/subtraction. Quick check: What is the sum of 8 units and 5 units in the decomposition framework?
- **Tokenization and subword units**: Understanding how BPE tokenization affects number representation is critical since subword splits can obscure digit-level reasoning. Quick check: If "1234" is tokenized as "1-234" vs "12-34", which is more problematic for digit-wise arithmetic?
- **Autoregressive sequence generation**: The model must generate intermediate decomposed forms and final answers step-by-step, so understanding generation order and dependencies is essential. Quick check: In generating "3 units, 0 tens, 5 hundreds, 2 thousands", which digit is generated first and why?

## Architecture Onboarding

- **Component map**: GPT-2 Small (117M params) -> Fine-tuning on arithmetic datasets -> Tokenization and decomposition pipeline -> Autoregressive generation -> Post-processing output
- **Critical path**: Tokenize input → generate intermediate decomposition → perform digit-wise operation → reconstruct final number → post-process output
- **Design tradeoffs**: Decomposition adds training overhead and longer sequences but yields higher accuracy; spacing reduces sequence length but loses magnitude context; baseline is fastest but fails on multi-digit tasks
- **Failure signatures**: Near-zero accuracy on 4- and 5-digit tasks indicates the model cannot learn place-value reasoning without decomposition; poor performance on multiplication indicates higher reasoning needs
- **First 3 experiments**: 1) Train baseline GPT-2 on non-decomposed 2-digit addition and measure accuracy to confirm minimal reasoning is possible. 2) Train spaced GPT-2 on 2-digit addition to verify digit-level tokenization benefit. 3) Train decomposition GPT-2 on 5-digit addition to confirm the full pipeline's accuracy gains.

## Open Questions the Paper Calls Out
- How do decomposition-based methods perform on arithmetic operations involving more than five digits?
- What are the reasons behind the difficulty of Transformer Language Models in learning to perform multiplication operations?
- How does the number of observations in the training sets affect the performance of fine-tuned GPT-2 models in the studied tasks?

## Limitations
- The decomposition pipeline requires longer sequences and additional training complexity
- Performance gains may not scale to larger numbers or more complex operations
- Multiplication remains fundamentally challenging for transformer-based approaches

## Confidence
- **High confidence**: Transformers can learn basic addition/subtraction with decomposition pipeline; spaced tokenization improves digit-level processing; GPT-2 Small with decomposition achieves state-of-the-art accuracy on 5-digit addition/subtraction
- **Medium confidence**: The decomposition approach mirrors children's learning sufficiently to enable arithmetic reasoning; multiplication requires "higher reasoning" beyond current LMs
- **Low confidence**: The specific magnitude labeling mechanism is necessary versus spacing alone; decomposition will scale to larger numbers or more complex operations

## Next Checks
1. **Tokenization validation**: Test whether BPE consistently tokenizes spaced digits as single tokens across the full range of numbers used in the experiments, and whether this behavior holds for different BPE configurations.
2. **Ablation study on magnitude labels**: Systematically remove magnitude tokens while maintaining spacing to isolate whether magnitude labeling provides additional benefit beyond simple digit separation.
3. **Multiplication reasoning analysis**: Conduct qualitative analysis of multiplication failures to determine whether the limitation is computational (requires multi-step reasoning) or representational (cannot capture multiplicative relationships through addition-based decomposition).
