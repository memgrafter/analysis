# Depth-based 6DoF Object Pose Estimation using Swin Transformer

## Quick Facts
- arXiv ID: 2303.02133
- Source URL: https://arxiv.org/abs/2303.02133
- Authors: 
- Reference count: 40
- 6D object pose estimation using only depth images with Swin Transformer achieves 96.3% and 97.5% ADD(S) accuracy on LineMod and Occlusion LineMod datasets respectively

## Executive Summary
SwinDePose presents a novel approach for 6D object pose estimation using only depth images by generating normal vector angles images that encode geometric information as RGB-like representations. The method leverages Swin Transformer for global context capture and RandLA-Net for point cloud feature extraction, then fuses these representations for semantic segmentation and 3D keypoint localization. The pipeline achieves state-of-the-art performance on standard benchmarks while demonstrating robustness to poor lighting and textureless objects.

## Method Summary
SwinDePose processes depth images by first computing surface normal vectors and converting them into normal vector angles relative to camera coordinate axes, creating RGB-like representations. These images are encoded using Swin Transformer, while the corresponding point clouds are processed with RandLA-Net. The image and point cloud features are concatenated and fed into semantic segmentation and 3D keypoint localization modules. Final pose estimation is performed via least-squares fitting of predicted keypoints to model keypoints. The method is trained on synthetic data (20K depth images per category for LineMod, 40K for Occlusion LineMod) and evaluated using ADD(S) metric with 10% object diameter threshold.

## Key Results
- Achieves 96.3% ADD(S) accuracy on LineMod dataset, outperforming state-of-the-art depth-based methods
- Achieves 97.5% ADD(S) accuracy on Occlusion LineMod dataset, demonstrating robustness to heavy occlusions
- Shows superior performance in challenging scenarios including poor lighting and textureless objects

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Normal vector angles image generation provides richer geometric encoding than raw depth or depth-normal hybrid representations.
- Mechanism: By computing angles between surface normals and camera axes (X, Y, Z), the method captures directional information. Normalizing these angles into RGB channels creates structured representation preserving angular relationships across orientations, enabling better feature learning in image encoder.
- Core assumption: Angular encoding is more informative for pose estimation than grayscale intensity encoding of depth, and RGB-like representation is compatible with pretrained vision backbones.
- Evidence anchors:
  - [abstract]: "SwinDePose first calculates the angles between each normal vector defined in a depth image and the three coordinate axes in the camera coordinate system. The resulting angles are then formed into an image, which is encoded using Swin Transformer."
  - [section III-B]: Detailed explanation of normal vector angle generation and normalization into RGB channels.
- Break condition: If surface normal estimation is noisy or unreliable, angle encoding degrades. If encoder cannot learn angular semantics, representation adds no value over raw depth.

### Mechanism 2
- Claim: Swin Transformer's global attention captures long-range geometric context better than CNNs for depth-based pose estimation.
- Mechanism: Swin-T uses shifted window attention to model dependencies across larger image regions, particularly useful for 6D pose tasks where object parts far apart in image can be related by global pose. Hierarchical structure aligns well with multi-scale nature of depth features.
- Core assumption: Global context is important for accurate 3D keypoint localization and semantic segmentation from depth images.
- Evidence anchors:
  - [abstract]: "We employ Swin Transformer, which leverages a self-attention mechanism to capture global context by attending to all positions in the input."
  - [section III-C]: Explicit mention of Swin-T as encoder and comparison with CNNs' "small local receptive fields, sensitivity to object occlusions, and lack of global context."
- Break condition: If scene is small or mostly local, attention overhead may not be justified. If depth features are already well-localized, global attention might not improve performance.

### Mechanism 3
- Claim: Combining point cloud embeddings (via RandLA-Net) with image embeddings (via Swin-T) provides complementary feature sets that improve keypoint detection and pose regression.
- Mechanism: Point clouds preserve precise 3D coordinates while normal vector angles image encodes angular structure in 2D grid. Fusing them allows network to benefit from both metric 3D geometry and angular pattern recognition, improving robustness in keypoint voting and semantic segmentation.
- Core assumption: Two modalities are aligned (same camera pose, same object) and complementary rather than redundant.
- Evidence anchors:
  - [abstract]: "Additionally, we apply RandLA-Net to learn the representations from point clouds. The resulting image and point clouds embeddings are concatenated and fed into a semantic segmentation module and a 3D keypoints localization module."
  - [section III-D]: Description of point cloud feature extraction with RandLA-Net and concatenation with image embeddings.
- Break condition: If alignment is poor due to calibration error, fusion may hurt performance. If both modalities encode same information, network may overfit or suffer from redundancy.

## Architecture Onboarding

- Component map: Depth → Normal angles → Swin-T → RandLA-Net → Fusion → Keypoint + Segmentation → Least-squares fitting
- Critical path: Depth → Normal vector angles generation → Swin Transformer encoding → RandLA-Net point cloud processing → Feature concatenation → Semantic segmentation and 3D keypoint localization → Least-squares pose fitting
- Design tradeoffs:
  - Swin-T vs CNN: More parameters and compute but better global context capture
  - RandLA-Net vs PointNet: Randomized sampling more robust to noise but less deterministic
  - Normal angles vs raw depth: Better compatibility with pretrained encoders but requires normal estimation quality
- Failure signatures:
  - Poor segmentation → wrong keypoints → bad pose (likely due to weak image encoder or misalignment)
  - Noisy keypoint voting → high variance in pose (likely due to point cloud noise or insufficient training data)
  - Low accuracy on symmetric objects → evaluation metric ADDS not matched by predictions (likely due to local minima in fitting)
- First 3 experiments:
  1. Ablation: Remove Swin-T, replace with 4-layer CNN. Measure accuracy drop and runtime change
  2. Ablation: Remove RandLA-Net, use only image embeddings. Compare ADD(S) on LineMod
  3. Ablation: Replace normal vector angles image with raw depth image. Test if RGB-like encoding is essential

## Limitations

- Synthetic data generation procedures for training not fully described, raising concerns about domain gap
