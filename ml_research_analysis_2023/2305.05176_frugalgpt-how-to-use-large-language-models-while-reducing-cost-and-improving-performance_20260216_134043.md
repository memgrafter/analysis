# FrugalGPT: How to Use Large Language Models While Reducing Cost and Improving Performance

## Quick Facts
- arXiv ID: 2305.05176
- Source URL: https://arxiv.org/abs/2305.05176
- Reference count: 12
- The paper introduces FrugalGPT, a system that can match the performance of expensive LLMs like GPT-4 while reducing costs by up to 98% or improving accuracy by 4% at the same cost.

## Executive Summary
Large language models like GPT-4 offer impressive capabilities but come with prohibitive costs due to heterogeneous pricing across LLM APIs. This paper presents FrugalGPT, a flexible system that learns to adaptively select combinations of LLMs and prompts for different queries to reduce cost while improving accuracy. The authors propose three complementary strategies: prompt adaptation (reducing prompt size through selection and concatenation), LLM approximation (using cheaper models or cached responses), and LLM cascade (sequentially querying multiple LLMs with a scoring function to determine when to stop). Experiments on three datasets demonstrate that FrugalGPT can achieve up to 98% cost reduction while maintaining accuracy or improve accuracy by 4% at the same cost as using a single expensive LLM.

## Method Summary
The paper addresses the challenge of high LLM API costs by proposing three complementary strategies: prompt adaptation, LLM approximation, and LLM cascade. FrugalGPT implements the cascade approach by learning to route queries through a sequence of LLMs, stopping at the first one that provides a sufficiently reliable answer based on a learned scoring function. The system is trained on datasets specific to the target task, optimizing the order of LLM queries and the thresholds for accepting answers. The approach works with black-box APIs without requiring access to model internals, making it broadly applicable across different LLM providers.

## Key Results
- FrugalGPT can reduce costs by up to 98% while matching the performance of the best individual LLM
- The system can improve accuracy by 4% while maintaining the same cost as using a single expensive LLM
- Experiments on three diverse datasets (finance, law, and reading comprehension) demonstrate consistent cost savings and performance improvements

## Why This Works (Mechanism)

### Mechanism 1: Prompt Adaptation
Reducing prompt size through selective example retention or query concatenation lowers token count and cost. The core assumption is that smaller prompts can still effectively guide the LLM to produce accurate responses. Evidence from the paper shows prompt adaptation as a key strategy for cost reduction. This mechanism breaks when reduced prompts lack sufficient context, causing significant performance degradation.

### Mechanism 2: LLM Approximation
Using cheaper models or cached responses can approximate expensive LLM outputs for specific tasks. This relies on the assumption that approximation models or cached responses can sufficiently mimic expensive LLM behavior. The paper identifies completion cache and model fine-tuning as examples of this approach. The mechanism fails when approximations are not accurate enough, degrading overall system performance.

### Mechanism 3: LLM Cascade
Sequentially querying multiple LLMs with a scoring function optimizes the cost-accuracy tradeoff. FrugalGPT learns to route queries through LLMs, stopping at the first sufficiently reliable answer. This assumes the cascade order and scoring thresholds can be optimized for high accuracy at lower cost. The paper provides empirical results showing FrugalGPT's cost savings using this approach. The mechanism breaks when the scoring function is inaccurate or cascade order is poorly optimized.

## Architecture Onboarding

- **Component map**: Query → Prompt Selector → LLM Router → LLM(s) → Scoring Function → Answer Cache → Fine-Tuner
- **Critical path**: Receive query → Select prompt → Route to first LLM → Evaluate answer → If reliable, return; else, proceed to next LLM → Return final answer
- **Design tradeoffs**: Balancing prompt size vs. performance, choosing number of LLMs vs. cost/latency, determining cache size vs. storage requirements
- **Failure signatures**: High cost with low accuracy (inefficient selection), low cost with very low accuracy (inadequate adaptation), high latency (excessive queries)
- **First 3 experiments**: 1) Compare full vs. reduced prompts on sample dataset, 2) Measure cache hit rate and cost savings for repeated queries, 3) Vary LLM order and thresholds to measure cost-accuracy impact

## Limitations

- The effectiveness heavily depends on accurate scoring function training and optimal cascade optimization, but implementation details are not fully specified
- The paper focuses on cost reduction through API selection without addressing potential quality variations between different LLM providers
- Long-term reliability of cached responses and their impact on system performance is not evaluated

## Confidence

- **High confidence**: The general framework combining prompt adaptation, model approximation, and cascading is technically sound and well-grounded in existing literature
- **Medium confidence**: Empirical results showing up to 98% cost reduction are compelling but rely on specific dataset-task combinations that may not generalize
- **Low confidence**: Learning mechanisms for scoring function and cascade optimization lack sufficient detail for independent verification
