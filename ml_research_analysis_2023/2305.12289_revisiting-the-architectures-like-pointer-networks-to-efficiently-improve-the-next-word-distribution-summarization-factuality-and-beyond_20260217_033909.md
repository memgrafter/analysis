# Revisiting the Architectures like Pointer Networks to Efficiently Improve the Next Word Distribution, Summarization Factuality, and Beyond

## Quick Facts
- **arXiv ID**: 2305.12289
- **Source URL**: https://arxiv.org/abs/2305.12289
- **Reference count**: 40
- **Primary result**: Efficient softmax alternatives improve summarization factuality by 2 points and MAUVE scores by 30% on T5-Small

## Executive Summary
Modern transformer language models rely on a softmax layer to compute next-word probabilities, but this can create a "softmax bottleneck" where the model struggles to represent multi-modal word distributions. To overcome this, the authors propose efficient softmax alternatives that dynamically partition the vocabulary and use multiple embeddings to compute next-word probabilities. These methods combine ideas from pointer networks, rerankers, and vocabulary partitioning. In experiments on GPT-2, their best method achieves lower perplexity than mixture of softmax while being faster. For summarization with T5-Small, their method improves factuality by 2 points and MAUVE scores by 30%. Overall, the results demonstrate that softmax alternatives can significantly improve transformer LMs by breaking the softmax bottleneck.

## Method Summary
The authors propose several softmax alternatives that partition the vocabulary and use multiple embeddings to compute next-word probabilities. Their methods include context partition (C), which computes separate dot products for context words versus non-context words; reranker partition (R), which identifies top-k likely next words and uses separate projections for them; and pointer network (P), which uses local decoder embeddings for context words. They also introduce multiple input state enhancement (Mi) for T5 and BART, which concatenates blocks of hidden states. These methods are combined in various configurations (CR, CPR, CRMi) and tested on GPT-2 for next-word prediction and T5-Small for summarization tasks.

## Key Results
- Context partition with reranker (CR:20) achieves 23.6 perplexity on Wiki-2021, outperforming Mixture of Softmax
- CPR:20 achieves 19.5 perplexity on OpenWebText, also outperforming Mixture of Softmax
- T5-Small with CRMi improves summarization factuality by 2 points and MAUVE scores by 30% compared to baseline

## Why This Works (Mechanism)

### Mechanism 1
The softmax bottleneck prevents LMs from outputting multi-modal next word distributions. When predicting next word, softmax requires a single hidden state that is close to all possible next words in embedding space. This creates interference when desired next words have interfering words between them in embedding space. The core assumption is that output word embeddings form a structured space where similar words have similar embeddings, creating linear dependencies. The break condition occurs when the next word distribution is unimodal or when there are no interfering words between candidates in embedding space.

### Mechanism 2
Context partition breaks the bottleneck by computing separate dot products for context words. Instead of using a single hidden state for all words, the model uses different hidden state projections for context words versus non-context words, allowing independent optimization. The core assumption is that the next word is often related to words in the context, making context-based predictions more accurate. The break condition occurs when the next word is not related to context or when context words are not in vocabulary.

### Mechanism 3
Reranker partition breaks bottleneck by dynamically identifying likely next words. Instead of computing scores for all vocabulary words, the model identifies top-k likely words and uses separate hidden state projections for these words, reducing interference. The core assumption is that the next word is among the top-k most probable words most of the time. The break condition occurs when the next word is not in top-k or when k is poorly chosen.

## Architecture Onboarding

- **Component map**: Input layer → Transformer layers → Multiple projection layers (context, reranker, local decoder) → Softmax combination
- **Critical path**:
  - For GPT-2: Input context → Transformer layers → Multiple projections (LfV, LfC, LfPD) → Logit computation (Equation 5) → Softmax → Output
  - For T5/BART: Input context → Encoder → Decoder → Multiple projections (LfV, LfC, LfPD, LfE, LfPE) → Logit computation (Equation 6) → Softmax → Output
- **Design tradeoffs**:
  - Context partition vs. Pointer network: Context partition uses global embeddings (faster, leverages global similarity) while pointer network uses local embeddings (more representational power)
  - Number of reranker partitions: More partitions allow finer discrimination but increase computational cost
  - Block size for multiple input states: Larger blocks provide more information but increase model size
- **Failure signatures**:
  - Poor perplexity when k is too small in reranker partition
  - Degradation in performance when context partition is used on unrelated contexts
  - Training instability when multiple input states are not properly initialized
- **First 3 experiments**:
  1. Implement context partition only (C) and compare perplexity on validation set
  2. Add reranker partition with k=20 (CR:20) and measure improvement
  3. Implement pointer network (CPR) and compare against context partition alone

## Open Questions the Paper Calls Out

### Open Question 1
What is the maximum model size beyond which the softmax bottleneck becomes negligible and our proposed methods no longer improve performance? The paper suggests that the softmax bottleneck is not completely solved even in GPT-3.5 and that improvements tend to be larger in smaller language models. This remains unresolved because the authors did not have access to computational resources to test their methods on larger LMs beyond GPT-3.5. Testing methods on increasingly larger LMs and observing at what model size the performance gains plateau would resolve this question.

### Open Question 2
How does the performance of our proposed methods vary across different languages with varying morphology? The paper mentions that the meaning of tokens is locally defined in many applications, including languages with more morphology. This remains unresolved because the authors did not test their methods on languages other than English. Evaluating methods on summarization and text generation tasks in multiple languages with varying morphology and comparing the performance gains to English would resolve this question.

### Open Question 3
What is the optimal number of words to include in the context partition for a given task and dataset? The authors mention that including more words in a context partition might improve performance at the cost of extra computational overhead. This remains unresolved because the authors did not conduct a systematic analysis of the tradeoff between context partition size and performance. Experimenting with different context partition sizes on various tasks and datasets, measuring both performance and computational overhead, would find the optimal balance.

## Limitations

- Evaluation scope is limited to narrow set of tasks and models, with results based on small T5-Small model
- Method introduces multiple hyperparameters (k values, block sizes) that were only coarsely tuned on one dataset
- Lack of ablation studies showing individual contribution of each component (context partition, reranker, pointer network, Mi)

## Confidence

**High Confidence Claims:**
- The softmax bottleneck is a real phenomenon that can limit next-word distribution modeling in transformers
- Context and reranker partitioning strategies can improve next-word prediction accuracy
- The proposed methods are computationally more efficient than Mixture of Softmax

**Medium Confidence Claims:**
- The specific implementation details of the multiple input state enhancement (Mi) are correct and optimal
- The hyperparameter choices (k values, block sizes) are appropriate across all tasks
- The improvements on T5-Small generalize to larger T5 variants or other architectures

**Low Confidence Claims:**
- The exact mechanisms by which context partition breaks the bottleneck are fully understood
- The method will scale to models 10x larger than those tested
- The improvements are primarily due to breaking the softmax bottleneck rather than increased model capacity
