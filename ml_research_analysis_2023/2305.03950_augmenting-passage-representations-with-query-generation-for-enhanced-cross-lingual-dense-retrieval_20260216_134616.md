# Augmenting Passage Representations with Query Generation for Enhanced Cross-Lingual Dense Retrieval

## Quick Facts
- arXiv ID: 2305.03950
- Source URL: https://arxiv.org/abs/2305.03950
- Reference count: 40
- Key outcome: Up to 4.2% improvement in R@2kt and 3.1% improvement in R@5kt on XOR-TyDi dataset

## Executive Summary
This paper proposes a novel approach to enhance cross-lingual dense retrieval by augmenting passage representations with cross-lingual query generation. The method involves fine-tuning a multilingual T5 model to generate queries in multiple languages for each passage, then encoding both the original passage and generated queries with a cross-lingual dense retrieval encoder. These representations are combined using a Rocchio-like aggregation function to create augmented passage embeddings that are more aligned with the query distribution across target languages. Experiments on the XOR-TyDi dataset demonstrate significant improvements over baseline cross-lingual dense retrieval methods.

## Method Summary
The approach involves three main steps: (1) Fine-tuning mT5 on the XOR-TyDi dataset using language-specific prompts to generate queries in each target language for every passage; (2) Encoding both the original passages and generated queries using a cross-lingual dense retriever (mBERT or XLM-R) to obtain their embeddings; (3) Combining these embeddings using a Rocchio-like function with augmentation ratio α to create augmented passage representations. These augmented embeddings are then used at indexing time for retrieval, improving effectiveness without increasing query-time latency.

## Key Results
- 4.2% improvement in R@2kt on XOR-TyDi dataset
- 3.1% improvement in R@5kt on XOR-TyDi dataset
- Consistent improvements across all 7 target languages (Ar, Bn, Fi, Ja, Ko, Ru, Te)
- Effectiveness gains without increasing query-time latency

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Augmenting passage embeddings with query embeddings encoded in target languages moves passage representations closer to query distribution.
- Mechanism: By generating queries in each target language and encoding them with the same xDR model, then applying a weighted aggregation (Rocchio-like), the augmented passage embedding shifts toward the query embedding subspace in that language.
- Core assumption: The cross-lingual query generator produces queries that are semantically relevant to the passage and that are effectively encoded by the same xDR encoder used for retrieval.
- Evidence anchors: [abstract] "we propose to use cross-lingual query generation to augment passage representations with queries in languages other than the original passage language"; [section] "These augmented representations are used at inference time so that the representation can encode more information across the different target languages"
- Break condition: If generated queries are poor quality or semantically misaligned, the aggregation will push passage embeddings away from relevant queries.

### Mechanism 2
- Claim: The pre-training task similarity between T5 and query generation fine-tuning leads to effective xQG models without additional training data.
- Mechanism: mT5's pre-training on text-to-text tasks aligns closely with the fine-tuning objective of generating queries, enabling effective adaptation using only XOR-TyDi data.
- Core assumption: The seq2seq objective and prompt-based conditioning used in fine-tuning match the capabilities learned during mT5 pre-training.
- Evidence anchors: [abstract] "The query generator training is also effective because the pre-training task for the generator (T5 text-to-text training) is very similar to the fine-tuning task (generation of a query)"; [section] "We use a seq2seq objective akin to docTquery-T5's objective"
- Break condition: If the prompt structure or generation task diverges significantly from pre-training, fine-tuning will fail to produce high-quality queries.

### Mechanism 3
- Claim: Adding query embeddings at indexing time avoids query-time overhead while still improving retrieval.
- Mechanism: Since augmentation is done once during indexing, the retrieval pipeline remains unchanged; at query time only the original query embedding is used.
- Core assumption: The retrieval system supports precomputed augmented embeddings without requiring dynamic query augmentation.
- Evidence anchors: [abstract] "The use of the generator does not increase query latency at inference and can be combined with any cross-lingual dense retrieval method"; [section] "These augmented representations are used at inference time so that the representation can encode more information across the different target languages"
- Break condition: If the indexing system cannot store augmented embeddings or retrieval indices become too large, deployment will fail.

  - Why needed here: The xQG is trained with language-specific prompts; understanding prompt conditioning is crucial for generating appropriate queries.

## Architecture Onboarding

- Component map: XOR-TyDi dataset -> mT5-based xQG fine-tuning -> Generated queries (5 per language) -> xDR encoder (mBERT/XLM-R) -> Rocchio-like aggregation (α=0.01) -> Augmented passage embeddings -> ANN index

- Critical path:
  1. Fine-tune xQG on XOR-TyDi (passages + queries)
  2. Generate queries per passage per target language
  3. Encode passages and all generated queries with xDR encoder
  4. Apply Rocchio aggregation to obtain augmented embeddings
  5. Store augmented embeddings in ANN index for retrieval

- Design tradeoffs:
  - More generated queries → better augmentation but higher indexing cost and storage
  - Higher α → more emphasis on query embeddings, but too high can degrade effectiveness
  - Prompt design → impacts query quality and cross-lingual generation quality

- Failure signatures:
  - Drop in retrieval recall after augmentation → likely poor query generation or wrong α
  - Index size ballooning → too many generated queries per passage
  - Training failure → mismatch between prompt format and model pre-training

- First 3 experiments:
  1. Vary α from 0 to 0.1 and measure R@2kt and R@5kt; identify optimal α.
  2. Vary number of generated queries per language (0-5) and measure effectiveness; check saturation point.
  3. Compare augmentation using queries from same language vs. other languages to assess cross-lingual benefits.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the effectiveness of xQG vary across different cross-lingual dense retrieval architectures beyond DPR?
- Basis in paper: [explicit] The paper notes that the empirical investigation was limited to cross-lingual DPR and suggests future work should extend the investigation to other dense retriever architectures.
- Why unresolved: The current study only evaluates xQG with cross-lingual DPR, leaving open whether the improvements generalize to other dense retrieval methods.
- What evidence would resolve it: Experiments applying xQG to other cross-lingual dense retrieval architectures (e.g., RocketQA, PAIR, or newer models) and comparing their effectiveness gains.

### Open Question 2
- Question: What is the optimal number of generated queries per language to maximize effectiveness without excessive computational cost?
- Basis in paper: [explicit] The paper shows improvements with up to 5 queries per language but notes curves do not plateau, suggesting more could be beneficial. Computational constraints limited the investigation.
- Why unresolved: The study only tested up to 5 queries per language, and the relationship between query count and effectiveness at higher numbers remains unknown.
- What evidence would resolve it: Systematic experiments testing effectiveness with varying numbers of generated queries per language (e.g., 10, 20, 50) while measuring computational overhead.

### Open Question 3
- Question: How can we filter out ineffective generated queries to prevent potential negative impacts on retrieval effectiveness?
- Basis in paper: [explicit] The paper cites recent work showing T5-based query generation can produce poor queries that negatively impact effectiveness, suggesting cross-encoder rankers could filter them, but this adaptation is left for future work.
- Why unresolved: The current approach uses all generated queries without filtering, potentially including ineffective ones that could harm performance.
- What evidence would resolve it: Implementation and evaluation of a filtering mechanism (e.g., cross-encoder ranker) to select only high-quality generated queries before embedding augmentation.

## Limitations

- The study is limited to evaluating xQG with cross-lingual DPR, leaving open whether improvements generalize to other dense retrieval architectures.
- Computational constraints limited investigation to only 5 generated queries per language, without exploring whether more queries could yield further improvements.
- The approach uses all generated queries without filtering, potentially including ineffective queries that could negatively impact retrieval effectiveness.

## Confidence

- **High confidence**: The core claim that augmenting passage embeddings with cross-lingual query embeddings improves retrieval effectiveness is well-supported by the experimental results showing consistent improvements across multiple languages and metrics.
- **Medium confidence**: The claim about pre-training alignment enabling effective fine-tuning without additional data is reasonable given the similar text-to-text nature of both tasks, but lacks direct empirical validation of this mechanism.
- **Medium confidence**: The assertion that augmentation does not increase query latency is technically accurate but requires verification that the indexing system can handle the increased storage requirements for augmented embeddings.

## Next Checks

3. Systematically explore the sensitivity of results to the augmentation ratio α, testing values from 0 to 0.1 in small increments to find the optimal setting.
