# Framework for Certification of AI-Based Systems

## Quick Facts
- arXiv ID: 2302.11049
- Source URL: https://arxiv.org/abs/2302.11049
- Authors: 
- Reference count: 31
- Key outcome: Framework to adapt DO-178 certification for neural networks, achieving 79% AP on object detection model tested across 4 distance ranges

## Executive Summary
The paper proposes a certification framework for AI-based systems in aerospace applications, addressing the limitations of traditional DO-178 processes for neural networks. The framework focuses on traceability through version-controlled datasets and statistical analysis of model performance across operational domains. A practical implementation demonstrates training an SSD-FPN with ResNet-50 on 724 images and testing on 379 images, with sensitivity analysis across distance ranges (0-375m, 375-750m, 750-1115m, 1115-1500m).

## Method Summary
The framework implements a traceable AI development pipeline using Git and DVC for dataset versioning, TensorFlow for deterministic training, and sensitivity analysis across operational partitions. The method tracks training code, hyperparameters, data, and random seeds to ensure reproducibility. Performance is evaluated using average precision metrics and analyzed across distance ranges to demonstrate operational domain coverage. The approach replaces traditional line-by-line code traceability with statistical performance guarantees for neural networks.

## Key Results
- Achieved 79% average precision on object detection test set
- Demonstrated performance degradation with distance, analyzed across 4 range bins
- Successfully implemented traceability framework tracking data, code, and models through version control

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Statistical performance guarantees replace traditional line-by-line code traceability for neural networks.
- Mechanism: By tracking the full training pipeline—code, hyperparameters, data, and random seeds—the framework ensures reproducibility and enables statistical analysis of model behavior across the operational domain.
- Core assumption: Deterministic training and inference allow the model to be treated as a fixed function from inputs to outputs after training.
- Evidence anchors:
  - [abstract] "The precise parameters resulting from training are as important as (or more important than) the code that drives it."
  - [section] "If the code running the model is deterministic and there is no online learning, then the model is a function from input data to labels/annotations which is determined by the weight parameters that are optimized during training."
  - [corpus] Weak evidence: no direct citations on statistical guarantees for DNN certification found in neighbor papers.
- Break condition: Non-deterministic training/inference, or online learning during deployment.

### Mechanism 2
- Claim: Version-controlled datasets enable traceability of data provenance and evolution.
- Mechanism: Datasets, annotations, and images are tracked with hashes and git commits, allowing full reconstruction of any dataset version used during development.
- Core assumption: Data integrity can be guaranteed by hashing and version control, even for large multimedia files.
- Evidence anchors:
  - [section] "We use DVC [2] to ensure data integrity of images/videos while keeping the size of the git repository small."
  - [section] "Data is abstracted into images, annotations, and datasets... The integrity of all components is guaranteed by tracking the hash."
  - [corpus] Weak evidence: no direct citations on dataset versioning in neighbor papers.
- Break condition: Hash collisions, or loss of version control history.

### Mechanism 3
- Claim: Sensitivity analysis across partitions of the operational domain reveals model limitations for certification.
- Mechanism: By dividing test data into bins based on operational parameters (e.g., range to intruder), the framework quantifies how performance metrics (e.g., average precision) vary across conditions.
- Core assumption: Partitioning test data by operational parameters provides meaningful insight into model robustness across the operational domain.
- Evidence anchors:
  - [section] "We built a framework for analyzing the sensitivity of a trained model to the types of attributes that we record with our data."
  - [section] "The data was divided into 4 bins based on range - 0-375m, 375-750m, 750-1115m and 1115-1500m. The average precision was then calculated for each bin."
  - [corpus] Weak evidence: no direct citations on sensitivity analysis for DNN certification found in neighbor papers.
- Break condition: Inadequate coverage of operational domain in partitions, or inappropriate binning.

## Foundational Learning

- Concept: Deterministic training and inference
  - Why needed here: Ensures the trained model is a fixed function from inputs to outputs, enabling reproducibility and statistical analysis.
  - Quick check question: What happens to the framework if training includes non-deterministic operations like dropout during inference?

- Concept: Statistical generalization
  - Why needed here: Since the input space is too large to test exhaustively, statistical methods are used to demonstrate performance across the operational domain.
  - Quick check question: How does the framework ensure that the certification dataset is representative of the operational domain?

- Concept: Version control for datasets
  - Why needed here: Tracks the evolution of data used in training and testing, enabling reconstruction of any dataset version for analysis and audit.
  - Quick check question: What metadata must be tracked for each image to enable meaningful partitioning and sensitivity analysis?

## Architecture Onboarding

- Component map:
  - Data Collection: ADS-B and radar for initial bounding boxes, manual refinement in CVAT
  - Dataset Management: Git + DVC for versioned images, annotations, and datasets
  - Training: TensorFlow with deterministic operations, trace of code, data, and environment versions
  - Evaluation: Performance metrics (mAP) and sensitivity analysis by operational partitions
  - Guardrails: Runtime checks for model behavior (not fully implemented)

- Critical path:
  1. Collect and label training/test data
  2. Version datasets and track metadata
  3. Train model with deterministic setup, trace all components
  4. Evaluate on test set, compute performance metrics
  5. Analyze sensitivity across operational partitions
  6. Implement guardrails and monitoring (future work)

- Design tradeoffs:
  - Deterministic training vs. potential performance gains from non-deterministic methods
  - Comprehensive metadata tracking vs. storage and management overhead
  - Statistical analysis vs. stronger formal verification (future direction)

- Failure signatures:
  - Performance degradation in specific operational partitions
  - Inability to reproduce model from traced components
  - Data integrity issues due to version control problems

- First 3 experiments:
  1. Train SSD-FPN with ResNet-50 on 724 images, evaluate on 379 images, report mAP
  2. Partition test set by range (0-375m, 375-750m, 750-1115m, 1115-1500m), compute mAP for each bin
  3. Add new training data for underperforming partitions, retrain, and re-evaluate

## Limitations

- Applicability to complex real-world scenarios remains uncertain with only 724 training images
- Heavy reliance on statistical analysis rather than formal verification methods
- Assumption that partitioning by operational parameters adequately captures all relevant variations in the operational domain

## Confidence

- High Confidence: The traceability mechanisms using version control and deterministic training are well-established practices with clear implementation paths.
- Medium Confidence: The statistical analysis approach for certification shows promise but lacks extensive validation across diverse operational scenarios and safety-critical domains.
- Low Confidence: The framework's ability to handle non-deterministic elements in training/inference and its scalability to more complex neural network architectures and larger datasets remains largely unproven.

## Next Checks
