# Flocks of Stochastic Parrots: Differentially Private Prompt Learning for Large Language Models

## Quick Facts
- arXiv ID: 2305.15594
- Source URL: https://arxiv.org/abs/2305.15594
- Reference count: 40
- Primary result: Membership inference attacks reveal significant privacy risks in LLM prompting; PromptDPSGD and PromptPATE achieve high utility with strong privacy (ε < 0.3)

## Executive Summary
This paper addresses a critical privacy vulnerability in large language model (LLM) prompting: membership inference attacks can reveal whether specific data points were used to create prompts. The authors propose two solutions: PromptDPSGD, which applies differential privacy to soft prompt training by updating only a small number of parameters, and PromptPATE, which creates private discrete prompts through noisy ensemble voting and knowledge transfer. Both methods achieve strong privacy guarantees (ε < 0.3) while maintaining high utility close to non-private baselines, with PromptPATE being particularly efficient as it requires only black-box API access.

## Method Summary
The paper introduces two differentially private prompt learning approaches. PromptDPSGD applies DPSGD to optimize soft prompts (continuous embeddings) while keeping the LLM frozen, making it computationally efficient. PromptPATE creates an ensemble of discrete prompts from private data, aggregates their predictions with added noise using Confident-GNMax, and transfers the knowledge to a single public student prompt. This allows deployment without exposing private prompts. Both methods address the privacy vulnerability demonstrated by effective membership inference attacks against standard prompting approaches.

## Key Results
- Membership inference attacks achieve high accuracy in detecting whether data points were used in LLM prompts
- PromptDPSGD reaches 92.7% accuracy on sst2 with GPT3 under (ε = 0.147, δ = 10⁻⁶)-DP vs 95.2% non-private baseline
- PromptPATE requires only 100 queries for strong performance and black-box API access only
- Both methods provide strong privacy guarantees (ε < 0.3) while maintaining competitive utility

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Membership inference attacks can reveal whether data points were used in LLM prompts, indicating significant privacy risk.
- Mechanism: The attack exploits the fact that prompted LLMs assign significantly higher prediction probabilities to correct class tokens for data points that were actually used in the prompt compared to random data points. By analyzing the output probability distribution at the correct class token, the attacker can distinguish members from non-members with high accuracy.
- Core assumption: The LLM's output probabilities are sensitive to whether a data point was used in the prompt, and this sensitivity is consistent enough to enable statistical discrimination.
- Evidence anchors:
  - [abstract]: "we instantiate a simple but highly effective membership inference attack against the data used to prompt LLMs"
  - [section 3]: "we analyze the model's output probability at token yi,li that corresponds to the correct target class label of every xi. The intuition to distinguish between members and non-members is that the output probabilities at the correct class li will be significantly higher for demonstrations that were used within the prompt"
  - [corpus]: Weak evidence - the corpus neighbors don't directly address membership inference attacks
- Break condition: If the LLM's prediction probabilities for correct class tokens become uniform regardless of whether data was used in the prompt, or if the attacker cannot access the prediction probabilities.

### Mechanism 2
- Claim: PromptDPSGD enables private soft prompt learning by applying differential privacy to soft prompt training while keeping the LLM frozen.
- Mechanism: PromptDPSGD uses DPSGD to update soft prompt embeddings by computing gradients with respect to these embeddings, clipping them to a maximum norm, adding Gaussian noise, and then updating the embeddings. Since soft prompts have orders of magnitude fewer parameters than LLMs, this approach is computationally efficient while providing privacy guarantees.
- Core assumption: Computing gradients with respect to soft prompt embeddings is feasible and that clipping and noise addition can provide differential privacy for these gradients.
- Evidence anchors:
  - [abstract]: "we propose PromptDPSGD, which applies differential privacy to soft prompt training by updating only a small number of parameters"
  - [section 4.1]: "We call this approach PromptDPSGD. The algorithm yields soft prompts with DP guarantees that can be deployed with the LLM to solve the respective downstream task"
  - [corpus]: Weak evidence - the corpus neighbors discuss privacy-preserving prompt engineering but don't specifically address PromptDPSGD
- Break condition: If computing gradients with respect to soft prompts becomes infeasible due to API restrictions, or if the noise addition degrades utility beyond acceptable levels.

### Mechanism 3
- Claim: PromptPATE creates private discrete prompts by orchestrating a noisy vote among an ensemble of LLMs presented with different prompts, then transferring knowledge to a single public prompt.
- Mechanism: PromptPATE creates multiple teacher prompts from private data, each used with the LLM to generate predictions on public data. These predictions are aggregated with added noise using the Confident-GNMax algorithm to create a differentially private vote. The resulting knowledge is transferred to create a single public student prompt that can replace the private prompts.
- Core assumption: The ensemble voting mechanism with added noise can provide differential privacy while preserving enough information to create a useful student prompt.
- Evidence anchors:
  - [abstract]: "we orchestrate a noisy vote among an ensemble of LLMs presented with different prompts, i.e., a flock of stochastic parrots. The vote privately transfers the flock's knowledge into a single public prompt"
  - [section 4.2]: "By performing a noisy majority vote over all models' token output, we generate a single output that, due to the noise addition, implements differential privacy guarantees while incorporating knowledge from the flock"
  - [corpus]: Weak evidence - the corpus neighbors discuss privacy-preserving approaches but don't specifically address PromptPATE's ensemble voting mechanism
- Break condition: If the noise addition completely obscures the signal needed to create a useful student prompt, or if the consensus among teachers is too low to provide meaningful privacy protection.

## Architecture Onboarding

- Component map:
  - PromptDPSGD: Private data → soft prompt initialization → gradient computation → clipping + noise addition → parameter updates → deployed prompt
  - PromptPATE: Private data → teacher prompt creation → teacher predictions on public data → noisy aggregation → student prompt generation → deployed prompt
  - Membership inference attack: Data point evaluation → probability analysis → membership determination

- Critical path: For PromptDPSGD: private data → soft prompt initialization → gradient computation → clipping + noise addition → parameter updates → deployed prompt. For PromptPATE: private data → teacher prompt creation → teacher predictions on public data → noisy aggregation → student prompt generation → deployed prompt.

- Design tradeoffs: PromptDPSGD requires gradient access but is more efficient; PromptPATE requires only black-box access but needs public data and multiple teacher prompts. Both balance privacy (ε) against utility (accuracy).

- Failure signatures: High membership inference accuracy indicates privacy leakage; low student prompt accuracy indicates poor knowledge transfer; high privacy budget (ε) indicates insufficient privacy protection.

- First 3 experiments:
  1. Implement the membership inference attack on a simple prompted LLM to verify the privacy vulnerability
  2. Test PromptDPSGD on a small dataset with soft prompts to verify the gradient-based approach works
  3. Implement a simplified version of PromptPATE with a small teacher ensemble to verify the noisy voting mechanism provides privacy while maintaining utility

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do soft prompts compare to fine-tuning in terms of privacy-utility trade-offs for complex downstream tasks with large training datasets?
- Basis in paper: [inferred] The paper shows soft prompts achieve competitive results for simpler tasks but notes fine-tuning performs better on more complex tasks. The authors state "the performance of soft prompt or prefix matches the one of fine-tuning" for simple tasks like SST2 and QNLI, but for difficult tasks like QQP and MNLI, "the performance of prefix and soft prompts is also relatively close to fine-tuning."
- Why unresolved: The paper only provides experiments on simpler tasks (SST2, QNLI, QQP, MNLI) with moderate-sized datasets. It doesn't test soft prompts on highly complex tasks or very large datasets where fine-tuning might have a more significant advantage.
- What evidence would resolve it: Experiments comparing soft prompts and fine-tuning on complex downstream tasks (e.g., multi-hop reasoning, long-form generation) with large training datasets would clarify whether soft prompts can maintain competitive privacy-utility trade-offs in these more challenging settings.

### Open Question 2
- Question: How sensitive is PromptPATE's performance to the quality and diversity of the teacher prompts?
- Basis in paper: [inferred] The paper states "Care must be taken during selection: utility cannot be evaluated on the private data anymore given that the prompt will be publicly deployed" and uses validation accuracy on labeled public data to select student prompts. However, it doesn't systematically study how teacher prompt quality affects performance.
- Why unresolved: The paper doesn't provide experiments varying teacher prompt quality or analyzing the relationship between teacher performance and student prompt quality. It only shows results using randomly selected prompts without replacement.
- What evidence would resolve it: Experiments systematically varying teacher prompt quality (e.g., using different prompt templates, example selection strategies, or random vs. curated prompts) and measuring the resulting student prompt performance would reveal the sensitivity to teacher quality.

### Open Question 3
- Question: How does the privacy-utility trade-off of PromptPATE scale with the number of teachers in the ensemble?
- Basis in paper: [inferred] The paper notes "due to cost limitations, we were unable to experiment with the latest and best available model" and "we were not able to incorporate a larger number of teachers in our experiments for PromptPATE." It only uses 200 teachers for GPT3 experiments.
- Why unresolved: The paper doesn't explore how increasing the ensemble size affects either privacy (more teachers means more privacy budget consumption) or utility (potentially better consensus and student prompts). The authors mention that with more teachers, "not only the baseline but also the teacher ensemble's performance would get better."
- What evidence would resolve it: Experiments varying the number of teachers (e.g., 50, 100, 200, 500, 1000) while keeping other parameters constant would show how privacy costs and utility change with ensemble size, revealing optimal trade-offs.

## Limitations

- Attack Generalization: The membership inference attack demonstrated is effective but may not generalize to all LLM architectures or prompting strategies.
- Real-world Deployment Constraints: The proposed methods assume access to either gradient computation or black-box API queries, which may be restricted by LLM providers.
- Private Data Availability: PromptPATE requires both private data for creating teacher prompts and public data for knowledge transfer, which may not always be feasible.

## Confidence

- **High Confidence**: The fundamental observation that MIAs can reveal membership in prompted LLM data is well-supported by the experimental results and aligns with established privacy literature. The core mechanism of PromptDPSGD (differentially private optimization of soft prompts) is theoretically sound and matches standard DP-SGD approaches.

- **Medium Confidence**: The effectiveness of PromptPATE's ensemble voting mechanism and its ability to transfer knowledge to a single public prompt while maintaining privacy guarantees shows promise but may be sensitive to hyperparameters and dataset characteristics.

- **Low Confidence**: The practical deployment considerations, including real-world API restrictions, computational costs for very large models, and the sensitivity to dataset sizes and compositions, require further validation before the methods can be considered production-ready.
