# WikiWeb2M: A Page-Level Multimodal Wikipedia Dataset

## Quick Facts
- arXiv ID: 2305.05432
- Source URL: https://arxiv.org/abs/2305.05432
- Authors: 
- Reference count: 4
- WikiWeb2M is the first large-scale dataset preserving full multimodal webpage content (images, text, HTML structure) from Wikipedia

## Executive Summary
WikiWeb2M addresses a critical gap in multimodal research by providing a dataset that preserves complete webpage content rather than partial subsets. By rescraping over 2 million Wikipedia pages, the dataset enables new tasks including page description generation, section summarization, and contextual image captioning. The preservation of HTML structure, complete text sections, and all images (not just captioned ones) creates opportunities for richer multimodal understanding. Experimental results demonstrate that using full page context significantly improves performance on section summarization (ROUGE-L: 29.43→37.69) and contextual image captioning (CIDEr: 148.53→158.19) compared to target sections alone.

## Method Summary
WikiWeb2M was constructed by rescraping Wikipedia pages to extract complete multimodal content including text, images, and HTML structure. The dataset contains 2M+ pages with preprocessing that removes unwanted sections while preserving all images regardless of caption availability. Task-specific datasets were generated for page descriptions (using Wikipedia-provided summaries), section summarization (using first sentences as pseudo-summaries), and contextual image captioning (using full page context rather than isolated sections). The dataset was split into train/val/test sets, and experiments were conducted using T5 and ViT base models, comparing performance when using full page context versus target sections alone.

## Key Results
- Section summarization performance improved significantly (ROUGE-L: 29.43→37.69) when using full page context versus target sections alone
- Contextual image captioning showed better results (CIDEr: 148.53→158.19) with complete webpage context
- The dataset enables new tasks previously not possible with partial content datasets

## Architecture Onboarding

- Component map: Web scraping -> Data cleaning -> Dataset splitting -> Task-specific processing
- Critical path:
  1. Scrape Wikipedia pages to extract text, images, and HTML structure
  2. Clean and preprocess data, removing unwanted sections and filtering images
  3. Split data into train/val/test sets
  4. Generate task-specific datasets (page descriptions, section summaries, image captions)
  5. Train and evaluate models on each task
- Design tradeoffs:
  - Including all images vs. only captioned images: More data but potentially noisier
  - Using first sentence as pseudo-summary vs. human annotations: Faster but potentially less accurate
  - Preserving HTML structure vs. simplified text: More context but potentially more complex processing
- Failure signatures:
  - Poor performance on tasks may indicate issues with data quality or task formulation
  - Large discrepancy between training and validation performance may indicate overfitting
  - Failure to generate coherent text or captions may indicate issues with model architecture or training
- First 3 experiments:
  1. Evaluate section summarization performance using only target section vs. full page context
  2. Compare contextual image captioning performance using different levels of webpage context
  3. Test page description generation quality using different text generation model architectures

## Limitations
- Limited ablation studies: The paper demonstrates performance improvements but lacks comprehensive ablation studies isolating the impact of individual components
- Model scalability concerns: Experiments use base-size models, but scalability to larger architectures remains unexplored
- Real-world deployment gaps: While assistive technology applications are mentioned, practical validation with target users is not demonstrated

## Confidence
- High confidence: The dataset construction methodology and basic task formulations are well-documented and reproducible
- Medium confidence: The reported performance improvements are credible given the methodology, but could benefit from additional experimental controls
- Low confidence: Claims about real-world impact on assistive technologies lack empirical validation with actual users
