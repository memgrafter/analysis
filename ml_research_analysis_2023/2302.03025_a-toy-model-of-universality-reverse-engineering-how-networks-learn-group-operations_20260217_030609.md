# A Toy Model of Universality: Reverse Engineering How Networks Learn Group Operations

## Quick Facts
- arXiv ID: 2302.03025
- Source URL: https://arxiv.org/abs/2302.03025
- Reference count: 40
- Primary result: Networks learn group composition via representation theory, showing weak but not strong universality

## Executive Summary
This paper investigates whether neural networks consistently learn the same algorithms when trained on group composition tasks. The authors present a novel algorithm based on representation theory that allows networks to compute group compositions by embedding elements as matrices, performing matrix multiplication, and extracting results via character theory. Through extensive experiments across multiple groups and architectures, they find evidence for weak universality - networks consistently implement their algorithm using representation-theoretic features - but not strong universality, as different networks learn different representations and in different orders.

## Method Summary
The authors train small MLPs and Transformers to perform group composition (multiplication) on finite groups, then reverse-engineer the learned algorithms. Models take ordered pairs of group elements as input and predict their product. The key insight is that networks implement a Group Composition via Representations (GCR) algorithm: embeddings map group elements to representation matrices, MLP neurons compute matrix products via ReLU activations, and unembeddings extract outputs using character theory. The authors analyze trained models by projecting embeddings onto representation subspaces and performing ablations to verify algorithm components.

## Key Results
- Networks consistently implement the GCR algorithm using representation-theoretic features across all tested groups
- Different networks learn different specific representations and in different orders, showing weak but not strong universality
- The algorithm achieves constructive interference when multiple representations are learned simultaneously, improving performance
- Transformers consistently learn fewer representations than MLPs despite having more parameters

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Networks learn to compute group composition using representation-theoretic features rather than memorizing lookup tables.
- **Mechanism:** The model embeds group elements as matrices from irreducible representations, uses matrix multiplication to combine them, and applies character theory to extract the output element. This allows the network to generalize across all possible group compositions.
- **Core assumption:** The network can learn to embed elements into representation space and implement matrix multiplication via ReLU activations.
- **Evidence anchors:**
  - [abstract] "We present a novel algorithm by which neural networks may implement composition for any finite group via mathematical representation theory."
  - [section 4] "We are not aware of this algorithm existing in any prior literature."
  - [corpus] Weak - the paper itself introduces the algorithm; no external corpus evidence provided.
- **Break condition:** If the network fails to learn meaningful representation matrices or cannot implement matrix multiplication through ReLU activations.

### Mechanism 2
- **Claim:** Different networks consistently implement the same underlying algorithm but learn different specific representations and in different orders.
- **Mechanism:** While all networks follow the GCR algorithm, they arbitrarily choose which representations to learn from the available set, leading to variation in learned features while maintaining algorithmic consistency.
- **Core assumption:** The algorithm has multiple valid solutions that networks can converge on, and weight initialization determines which solution is chosen.
- **Evidence anchors:**
  - [abstract] "we can completely characterize the family of circuits and features that networks learn on this task, but for a given network the precise circuits learned – as well as the order they develop – are arbitrary."
  - [section 6] "We find evidence for weak universality: our models are all characterized by a family of circuits corresponding to our GCR algorithm across all group representations."
  - [corpus] Moderate - related work on universality (Li et al., 2016) provides context but doesn't specifically address this mechanism.
- **Break condition:** If networks converge on identical representations and learning orders across different runs and architectures.

### Mechanism 3
- **Claim:** The algorithm's effectiveness comes from constructive interference when multiple representations are learned simultaneously.
- **Mechanism:** When multiple representations are present, their character functions constructively interfere at the correct output element, creating a larger logit and improving performance.
- **Core assumption:** Character functions from different representations are orthogonal, allowing clean separation of their contributions.
- **Evidence anchors:**
  - [section 4] "Since each representation has χρ(abc−1) maximized on the correct answers, using multiple representations gives constructive interference at c∗ = ab."
  - [section 5.1] "Theorem C.9 implies these character vectors are orthogonal, so we may approximate the logits with these two directions."
  - [corpus] Moderate - orthogonality in representation theory is well-established, but the specific application to neural network logits is novel.
- **Break condition:** If character functions from different representations do not show orthogonality or fail to constructively interfere at correct outputs.

## Foundational Learning

- **Concept: Group Theory**
  - Why needed here: The task involves composing elements from finite groups, which requires understanding group operations and structure.
  - Quick check question: What property must a binary operation have to be considered a group operation?

- **Concept: Representation Theory**
  - Why needed here: The algorithm relies on representing group elements as matrices and using character theory to extract outputs.
  - Quick check question: What is the relationship between irreducible representations and the dimension of the group?

- **Concept: Neural Network Architecture**
  - Why needed here: Understanding how embeddings, MLPs, and unembeddings work together to implement the algorithm.
  - Quick check question: How do ReLU activations enable matrix multiplication in the MLP layer?

## Architecture Onboarding

- **Component map:** Input → Left embedding → MLP → Right embedding → MLP → Unembedding → Output
- **Critical path:** Input → Left embedding → MLP → Right embedding → MLP → Unembedding → Output
- **Design tradeoffs:** Using separate left/right embeddings allows handling non-abelian groups, but requires the network to learn both input representations independently.
- **Failure signatures:** Poor performance indicates either failure to learn meaningful representation matrices or inability to implement matrix multiplication correctly.
- **First 3 experiments:**
  1. Train on cyclic group C113 and verify logit similarity with character predictions
  2. Extract representation matrices from MLP activations and compare with theoretical values
  3. Ablate key representations and measure performance degradation

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Why do some representations (like 5d_b in S5) take significantly longer to learn than others, even when they're not more complex?
- Basis in paper: [explicit] Section 6 notes that 5d_b is learned later than sign and standard, and shows a second phase of grokking in some runs
- Why unresolved: The paper observes this timing difference but doesn't explain the underlying cause. It could be related to weight decay dynamics, optimization paths, or some other factor affecting learning speed.
- What evidence would resolve it: Ablation studies showing whether learning order correlates with weight norm, experiments with different learning rates/optimizers, or analysis of representation space accessibility during training.

### Open Question 2
- Question: What specific properties of representation-theoretic features make them "natural" for neural networks to express, beyond the ability to implement matrix multiplication?
- Basis in paper: [explicit] Section 7 mentions that our algorithm seems like an "overly complex solution" but is actually natural for networks, and discusses inductive biases
- Why unresolved: The paper identifies linearity as important but doesn't fully explain why representation-theoretic features specifically are natural. There may be deeper structural reasons.
- What evidence would resolve it: Systematic comparison of different algorithmic approaches to group composition, analysis of initialization patterns, or experiments with alternative architectures that can't easily express matrix multiplication.

### Open Question 3
- Question: How do lottery tickets (Frankle & Carbin, 2019) relate to the learned representations - are there pre-existing subnetworks that make certain representations more likely to be learned?
- Basis in paper: [inferred] Section 6 mentions lottery tickets as a potential direction, noting that different representations are learned across seeds with some probabilistic trends
- Why unresolved: The paper raises this as a future direction but doesn't investigate whether initialization patterns predict representation learning outcomes.
- What evidence would resolve it: Iterative magnitude pruning experiments to find lottery tickets, correlation analysis between initialization patterns and final representations, or weight rewinding experiments.

## Limitations

- Limited to small finite groups and simple MLP architectures, unclear if principles extend to larger, more complex structures
- Mechanical interpretability relies on projection methods with known limitations and somewhat arbitrary thresholds
- Claims of universality are carefully qualified as "weak universality" due to arbitrary learning order variations

## Confidence

**High Confidence:** Experimental methodology for training and analyzing small group composition tasks is sound and well-executed. Basic observation that networks learn to compose group elements rather than memorizing lookup tables is well-supported.

**Medium Confidence:** Characterization of GCR algorithm and its implementation through representation-theoretic features is well-reasoned but relies on assumptions about how neural networks implement mathematical operations through ReLU activations.

**Low Confidence:** Claims about algorithm's generality beyond specific groups studied, and extent to which this approach scales to larger, more complex mathematical structures or real-world tasks.

## Next Checks

1. **Cross-group generalization test:** Train models on multiple groups simultaneously (e.g., C113 and S5) and analyze whether they learn shared representation-theoretic features or develop group-specific algorithms. This would test whether the GCR algorithm represents a truly universal approach or is task-specific.

2. **Scaling experiment:** Increase model capacity and group size systematically (e.g., C1000, S6) while monitoring algorithm consistency. Measure how representation orthogonality, logit construction, and constructive interference scale with problem complexity to identify potential break points in the algorithm.

3. **Architecture ablation study:** Replace the MLP with alternative architectures (simple RNNs, attention-only models without MLPs) while maintaining the same task. Compare learned algorithms across architectures to test whether the GCR algorithm is an MLP-specific solution or represents a more fundamental computational principle.
