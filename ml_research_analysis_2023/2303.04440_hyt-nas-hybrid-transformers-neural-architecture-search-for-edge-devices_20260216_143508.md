# HyT-NAS: Hybrid Transformers Neural Architecture Search for Edge Devices

## Quick Facts
- arXiv ID: 2303.04440
- Source URL: https://arxiv.org/abs/2303.04440
- Reference count: 25
- Key outcome: HyT-NAS achieves similar hypervolume with less than 5x training evaluations compared to state-of-the-art

## Executive Summary
HyT-NAS introduces an efficient Hardware-aware Neural Architecture Search (HW-NAS) for hybrid attention and convolution-based models targeting tiny and edge devices. The method enhances the search space and strategy, including multi-objective Bayesian optimization and performance predictors. Results show HyT-NAS achieves similar hypervolume with less than 5x training evaluations compared to state-of-the-art. The resulting architecture outperforms MLPerf MobileNetV1 by 6.3% accuracy improvement with 3.5x fewer parameters on Visual Wake Words. Additionally, HyT-NAS achieves the same mAP as MobileNetV3 with a 7x smaller model on Person Detection.

## Method Summary
HyT-NAS uses a hybrid search space combining MobileNetV2 convolution blocks with Vision Transformer encoder blocks, parameterized for edge deployment. The method employs multi-objective Bayesian optimization with surrogate rank predictors to efficiently approximate Pareto-optimal architectures balancing accuracy and latency. A hardware-aware latency predictor trained on Raspberry Pi measurements guides the search toward real-world deployable models. The approach uses NSGA-II for Pareto front optimization and selects final architectures based on hypervolume improvement (HVI).

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Multi-objective Bayesian Optimization with surrogate rank predictors accelerates convergence to Pareto front with fewer evaluations.
- Mechanism: Replace expensive GP surrogate models with rank predictors trained on accuracy and latency to rapidly approximate architecture rankings, enabling efficient UCB-based exploration-exploitation.
- Core assumption: Rank predictors generalize well from limited training data and accurately capture Pareto front geometry.
- Evidence anchors:
  - [abstract] "Our experiments show that HyT-NAS achieves a similar hypervolume with less than 5x training evaluations."
  - [section] "We replace them with a set of rank predictors... The mean and standard deviation of the networks' predictions are used to approximate the objectives via an acquisition function."
  - [corpus] Weak evidence; no direct comparison of BO variants or rank predictor performance found.
- Break condition: Poor rank predictor generalization causes misranking, leading to suboptimal exploration and loss of hypervolume gains.

### Mechanism 2
- Claim: Hybrid search space including convolution and attention blocks enables competitive accuracy with reduced parameters on tiny devices.
- Mechanism: Interleaving MobileNetV2 blocks with Vision Transformer encoder blocks allows capturing spatial and global features while keeping model size low for edge deployment.
- Core assumption: Hybrid blocks contribute complementary features without exploding parameter count, maintaining edge feasibility.
- Evidence anchors:
  - [abstract] "Our resulting architecture outperforms MLPerf MobileNetV1 by 6.3% accuracy improvement with 3.5x less number of parameters on Visual Wake Words."
  - [section] "Our search space is inspired by the MobileVit architecture... Each block has its own set of hyperparameters described in Table I."
  - [corpus] Weak evidence; related works mention hybrid search but lack direct accuracy/size comparison.
- Break condition: Overfitting or inefficiency in hybrid block combinations inflates parameters or degrades accuracy, breaking edge constraints.

### Mechanism 3
- Claim: Hardware-aware latency predictors trained on edge device measurements guide search toward architectures meeting real deployment constraints.
- Mechanism: Latency dataset collected on Raspberry Pi enables surrogate model to predict hardware performance, ensuring Pareto front respects device limits.
- Core assumption: Latency predictor captures real hardware behavior; predictions correlate with actual execution on target devices.
- Evidence anchors:
  - [section] "The latency dataset is more extensive... a dataset of 1700 models executed each using an image size of 224 on a Raspberry Pi Model 3 B For latency."
  - [section] "XGBoost gives 95% and 93% for latency and accuracy estimation respectively."
  - [corpus] Weak evidence; no latency predictor accuracy evaluation reported in corpus neighbors.
- Break condition: Predictor bias or hardware mismatch causes selected architectures to exceed latency/energy budgets in deployment.

## Architecture Onboarding

- Component map: Hybrid macro-architecture (convolution blocks ↔ attention blocks) → Rank predictors (accuracy, latency) → Multi-objective solver (NSGA-II) → HVI selection → Pareto front.
- Critical path: Search space definition → Predictor training → BO iteration (predict → solve → select) → Evaluate → Update dataset → Converge to Pareto front.
- Design tradeoffs: Larger search space improves solution quality but increases training cost; simpler predictors reduce search time but may misrank architectures; more BO iterations improve Pareto front but delay deployment.
- Failure signatures: Predictor underfitting (misranked architectures), BO stagnation (no hypervolume improvement), latency predictor mismatch (selected architectures fail hardware constraints).
- First 3 experiments:
  1. Train rank predictors on a small random sample of architectures; evaluate Kendall tau ranking correlation.
  2. Run HyT-NAS for 100 iterations; plot hypervolume evolution and compare to Random Search baseline.
  3. Deploy best architecture on target Raspberry Pi; measure actual latency and accuracy vs. predictor estimates.

## Limitations
- The hybrid search space, while innovative, may not fully explore the potential of attention-convolution combinations, limiting the generality of results.
- The rank predictors for accuracy and latency, though showing 93-95% XGBoost accuracy, are evaluated on internal datasets without independent validation.
- Results are validated primarily on Raspberry Pi 3B, raising questions about performance on other edge devices with different compute capabilities.

## Confidence
- **High Confidence**: The methodology framework (hybrid search space + MOBO + hardware-aware predictors) is technically sound and well-documented.
- **Medium Confidence**: The reported accuracy improvements (6.3% over MobileNetV1, 7x smaller than MobileNetV3) are promising but lack direct comparison with recent edge NAS methods.
- **Low Confidence**: The efficiency claim of "less than 5x training evaluations" compared to SOTA is difficult to verify without specific baselines and their evaluation counts.

## Next Checks
1. Deploy the HyT-NAS-discovered architecture on at least two additional edge devices (e.g., NVIDIA Jetson Nano, Coral USB Accelerator) to verify latency predictor generalization across hardware.
2. Generate 100 random architectures outside the training distribution and evaluate the rank predictors' correlation with actual accuracy/latency using Kendall tau or Spearman rank correlation metrics.
3. Run controlled experiments removing either attention or convolution blocks from the search space to quantify their individual contributions to accuracy and parameter efficiency.
