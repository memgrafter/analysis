# Phoenix: Democratizing ChatGPT across Languages

## Quick Facts
- arXiv ID: 2304.10453
- Source URL: https://arxiv.org/abs/2304.10453
- Reference count: 30
- Key outcome: Phoenix achieves state-of-the-art performance among open-source Chinese LLMs and outperforms existing open-source models in many non-Latin languages, while Chimera achieves 96.6% ChatGPT quality in English.

## Executive Summary
This paper introduces Phoenix, a large language model designed to democratize ChatGPT access across multiple languages, with a focus on non-Latin and non-Cyrillic languages. The model is trained using instruction-based and conversation-based tuning on multi-lingual data collected from various sources. Phoenix is built on BLOOMZ-7B, while its Latin counterpart Chimera uses LLaMA-7B. The model achieves strong performance across languages, setting new benchmarks for open-source multilingual LLMs.

## Method Summary
Phoenix and Chimera are fine-tuned on BLOOMZ-7B and LLaMA-7B backbones respectively, using both instruction data and conversation data. The instruction data is multi-lingual, collected from Alpaca and self-generated sources, and translated into 40 languages. Conversation data comes from ShareGPT and Discord. The models are fine-tuned using AdamW optimizer with learning rate 2e-5, weight decay 0, batch size 256, and 3 epochs. Evaluation is performed using GPT-4/GPT-3.5 Turbo API for automated assessment and human evaluation for ranking model responses.

## Key Results
- Phoenix achieves state-of-the-art performance among open-source Chinese LLMs.
- Phoenix outperforms existing open-source models in many non-Latin languages including Arabic, Japanese, and Korean.
- Chimera achieves 96.6% ChatGPT quality in English, setting a new SOTA among open-source LLMs.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Using both instruction data and conversation data together yields better performance than using either alone.
- Mechanism: Instruction data teaches the model to follow explicit instructions and complete tasks, while conversation data teaches it to maintain context and engage in multi-turn dialogue. The two types complement each other.
- Core assumption: Multi-turn conversational skills and instruction-following skills are complementary and can be learned simultaneously without interference.
- Evidence anchors:
  - Experimental results demonstrate the effectiveness of using them simultaneously.
  - In training Phoenix, we exploited both instruction and conversation data during post-training.
- Break condition: If the model suffers from catastrophic forgetting of one skill when learning the other, or if the two data types have conflicting objectives that cannot be reconciled.

### Mechanism 2
- Claim: Translating instructions into multiple languages and generating answers in those languages produces culturally and linguistically appropriate outputs.
- Mechanism: By generating answers in the target language (post-answering translation), the model can leverage the generative capabilities of GPT-4/GPT-3.5 to produce culturally appropriate and linguistically nuanced responses.
- Core assumption: The generative models used (GPT-4/GPT-3.5) can produce high-quality outputs in the target language when prompted with translated instructions.
- Evidence anchors:
  - We believe incorporating both data types is essential for a recipe to achieve a proficient language model.
  - The rationale is that the instruction data helps to tame language models to adhere to human instructions and fulfill their information requirements, while the conversation data facilitates the development of conversational skills in the model.
- Break condition: If the generative models produce poor quality outputs in the target language, or if the translation process introduces significant errors that cannot be mitigated.

### Mechanism 3
- Claim: Using BLOOMZ as the backbone enables strong multilingual performance due to its multilingual pre-training.
- Mechanism: BLOOMZ was pre-trained on a diverse multilingual corpus, giving it a strong foundation in multiple languages. Fine-tuning on multilingual instruction and conversation data builds upon this foundation.
- Core assumption: The multilingual pre-training in BLOOMZ is effective and provides a good starting point for fine-tuning on multilingual downstream tasks.
- Evidence anchors:
  - We start from the multi-lingual pre-trained backbone, BLOOM [15], and fine-tune it in the multi-lingual instruction-following data, without excluding any language.
  - In other non-Latin languages, Phoenix largely outperforms existing LLMs in many languages, including Arabic, Japanese, and Korean.
- Break condition: If the multilingual pre-training in BLOOMZ is found to be ineffective or biased towards certain languages, or if the fine-tuning process causes the model to forget the multilingual capabilities.

## Architecture Onboarding

- Component map: Pre-trained backbone (BLOOMZ-7B for Phoenix, LLaMA-7B for Chimera) -> Instruction data (multi-lingual, post-translated, user-centered) -> Conversation data (ShareGPT, Discord) -> Fine-tuning process (instruction-based and conversation-based tuning) -> Evaluation framework (GPT-4/GPT-3.5 Turbo API for automated assessment)

- Critical path:
  1. Collect and prepare instruction and conversation data in multiple languages.
  2. Fine-tune the pre-trained backbone on the instruction data.
  3. Further fine-tune the model on the conversation data.
  4. Evaluate the model's performance using the automated assessment framework.

- Design tradeoffs:
  - Using BLOOMZ enables multilingual capabilities but may lead to "multilingual tax" on English performance compared to a monolingual model like LLaMA.
  - Translating instructions and generating answers in the target language may introduce errors but allows for culturally appropriate outputs.

- Failure signatures:
  - Poor performance on languages with limited training data.
  - Catastrophic forgetting of one skill (instruction-following or conversation) when learning the other.
  - Generation of inappropriate or nonsensical outputs in the target language.

- First 3 experiments:
  1. Fine-tune BLOOMZ on the instruction data and evaluate performance on a multilingual benchmark.
  2. Fine-tune the model from step 1 on the conversation data and evaluate performance on a conversational benchmark.
  3. Compare the performance of Phoenix and Chimera on English and non-English languages to assess the "multilingual tax."

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do instruction data and conversation data contribute differently to the performance of Phoenix in various languages?
- Basis in paper: The paper mentions that instruction data helps tame language models to follow human instructions, while conversation data facilitates the development of conversational skills. It also states that both types of data are used simultaneously in training Phoenix.
- Why unresolved: The paper does not provide a detailed analysis of the individual contributions of instruction data and conversation data to Phoenix's performance in different languages.
- What evidence would resolve it: Conducting ablation studies by training Phoenix with only instruction data, only conversation data, and a combination of both, and comparing their performance in various languages.

### Open Question 2
- Question: What is the optimal size of the instruction dataset for achieving the best performance in multilingual language models like Phoenix?
- Basis in paper: The paper uses a large instruction dataset for training Phoenix, but does not explore the impact of dataset size on performance.
- Why unresolved: The paper does not investigate the relationship between instruction dataset size and model performance, leaving the optimal dataset size unknown.
- What evidence would resolve it: Conducting experiments with different sizes of instruction datasets and evaluating their impact on Phoenix's performance in various languages.

### Open Question 3
- Question: How does the multilingual nature of Phoenix affect its performance in language-specific tasks compared to monolingual models?
- Basis in paper: The paper mentions that Phoenix achieves state-of-the-art performance among open-source Chinese LLMs and outperforms existing open-source models in many non-Latin languages. However, it lags behind some models in English due to the "multi-lingual tax."
- Why unresolved: The paper does not provide a comprehensive comparison of Phoenix's performance in language-specific tasks against monolingual models.
- What evidence would resolve it: Conducting experiments comparing Phoenix's performance in language-specific tasks against monolingual models trained on the same language.

## Limitations

- Lack of transparency in data collection and translation process, making it difficult to assess true generalizability.
- Reliance on GPT-4/GPT-3.5 Turbo API for automated evaluation introduces potential bias.
- "Multilingual tax" observed in English performance compared to Chimera, suggesting a fundamental trade-off.

## Confidence

- High Confidence: Phoenix's strong performance on Chinese and other non-Latin languages is well-supported by the experimental results.
- Medium Confidence: The assertion that translating instructions and generating answers in the target language produces culturally and linguistically appropriate outputs is plausible but relies on the quality of the translation and generation process.
- Low Confidence: The claim that BLOOMZ's multilingual pre-training is the primary driver of Phoenix's strong multilingual performance is difficult to verify without access to the model's internal representations.
