# Prompted LLMs as Chatbot Modules for Long Open-domain Conversation

## Quick Facts
- arXiv ID: 2305.04533
- Source URL: https://arxiv.org/abs/2305.04533
- Reference count: 18
- Key outcome: MPC achieves long-term consistency in open-domain conversations using prompt-based techniques without fine-tuning

## Executive Summary
This paper introduces MPC (Modular Prompted Chatbot), a system that leverages large language models through prompt engineering to create conversational agents capable of maintaining long-term consistency and flexibility in open-domain dialogues. Unlike traditional approaches that require extensive fine-tuning, MPC uses carefully designed prompts, few-shot examples, chain-of-thought reasoning, and external memory to build individual modules for different aspects of conversation management. The system demonstrates competitive performance against fine-tuned models like Blenderbot in human evaluations across multiple quality dimensions.

## Method Summary
MPC is built around a modular architecture where each module performs a specific function in the conversation pipeline: clarifying user input, retrieving relevant memories from conversation history, processing retrieved information into concise context, and generating appropriate responses. The system employs few-shot prompting with carefully curated examples, chain-of-thought reasoning to improve response quality, and external memory management to maintain conversation context. By avoiding fine-tuning and relying entirely on prompt engineering, MPC offers greater flexibility and reduced computational overhead while maintaining high-quality conversational capabilities.

## Key Results
- MPC achieves human-evaluated performance on par with or exceeding Blenderbot in consistency, sensibleness, and engagingness
- The system successfully maintains long-term conversation context without fine-tuning through prompt-based techniques
- External memory management and chain-of-thought reasoning contribute significantly to improved response quality

## Why This Works (Mechanism)
The approach works by decomposing the complex task of conversation management into specialized modules, each optimized through prompt engineering. By using few-shot examples and chain-of-thought reasoning, the LLM can better understand context and generate more coherent responses. The external memory component allows the system to maintain conversation state across extended interactions, addressing the long-term consistency challenge that plagues many conversational AI systems.

## Architecture Onboarding

**Component Map**: User Input -> Clarification Module -> Memory Retrieval -> Context Processing -> Response Generation

**Critical Path**: The essential flow is User Input → Clarification → Memory Retrieval → Context Processing → Response Generation, with each step building upon the previous to maintain conversation coherence.

**Design Tradeoffs**: The system trades computational efficiency (no fine-tuning) for flexibility and reduced resource requirements. The modular approach allows for easier debugging and optimization but may introduce latency from multiple LLM calls.

**Failure Signatures**: Common failures include memory retrieval errors when conversation context is too sparse, generation inconsistencies when chain-of-thought prompts are inadequate, and clarification failures when user intent is ambiguous.

## Limitations
- Limited comparison to a single fine-tuned baseline (Blenderbot) without broader model evaluation
- Human evaluation focus without extensive automated metrics for comprehensive performance assessment
- Potential scalability challenges with very large conversation histories in external memory management
- Unverified generalizability across different domains and languages

## Confidence
- High confidence in prompt engineering methodology and modular design effectiveness
- Medium confidence in comparative performance claims against Blenderbot
- Low confidence in system behavior with extremely long conversation histories or cross-domain applications

## Next Checks
1. Conduct A/B testing with multiple fine-tuned baselines beyond Blenderbot, including more recent models, to establish broader comparative performance

3. Implement automated evaluation metrics (e.g., coherence scores, factuality checks) alongside human evaluation to provide more comprehensive performance assessment
