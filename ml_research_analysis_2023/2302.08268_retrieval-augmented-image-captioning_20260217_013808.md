# Retrieval-augmented Image Captioning

## Quick Facts
- arXiv ID: 2302.08268
- Source URL: https://arxiv.org/abs/2302.08268
- Reference count: 15
- This paper presents EXTRA, a retrieval-augmented image captioning model that conditions generation on both the input image and a set of captions retrieved from a datastore.

## Executive Summary
This paper introduces EXTRA, a retrieval-augmented image captioning model that leverages semantically similar captions to improve caption quality. The model uses a pretrained vision-and-language BERT (LXMERT) to jointly encode the input image and retrieved captions, allowing the decoder to attend to cross-modal representations. Experiments on COCO demonstrate that retrieving 5 captions provides optimal performance, with the model achieving competitive results against state-of-the-art captioning approaches.

## Method Summary
The model consists of three main components: a retrieval system using FAISS and CLIP embeddings to fetch k similar captions from a datastore, a LXMERT encoder that jointly processes the image and retrieved captions to produce cross-modal representations, and a GPT-2 style decoder with cross-attention layers that generates captions conditioned on these representations. The model is trained in two stages - first with cross-entropy loss using AdamW optimizer, then with Self-Critical Sequence Training (SCST) optimizing CIDEr scores. Evaluation is performed on COCO Karpathy splits using standard captioning metrics (BLEU-4, METEOR, CIDEr, SPICE).

## Key Results
- Retrieving k=5 captions provides optimal performance, with performance degrading when retrieving fewer captions
- The model achieves competitive results with state-of-the-art captioning models on COCO
- Cross-attention analysis shows the decoder shifts from visual to textual features across layers, relying more on retrieved captions for language generation
- The approach demonstrates the potential of using pretrained vision-and-language encoders for generative tasks beyond classification

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Retrieval-augmented captioning improves by encoding both image and semantically similar captions with a V&L encoder.
- Mechanism: The model jointly processes the input image and retrieved captions through a pretrained V&L BERT (LXMERT), producing cross-modal representations that capture both visual and textual context. The decoder then attends to these combined features, allowing it to generate captions informed by both modalities.
- Core assumption: Semantically similar captions provide useful linguistic context that enhances caption quality beyond image-only encoding.
- Evidence anchors:
  - [abstract] "The encoder in our model jointly processes the image and retrieved captions using a pretrained V&L BERT, while the decoder attends to the multimodal encoder representations, benefiting from the extra textual evidence from the retrieved captions."
  - [section 2.1] "The encoder produces a sequence of cross-modal representations of image and the text, which are the inputs to the decoder"
  - [corpus] Weak evidence; related works use retrieval augmentation but rarely with V&L encoders as primary cross-modal fusion mechanism.
- Break condition: If retrieved captions are irrelevant or mismatched, the cross-modal attention degrades and the model relies more heavily on visual features alone.

### Mechanism 2
- Claim: The decoder shifts attention from visual to textual features across layers, leveraging textual semantics for language generation.
- Mechanism: Cross-attention analysis shows the decoder initially attends to both visual and textual outputs, but by later layers attends primarily to textual representations from retrieved captions. This shift allows the decoder to leverage well-formed linguistic context for coherent caption generation.
- Core assumption: Textual context from similar captions is more useful for guiding language generation than purely visual features in later decoding stages.
- Evidence anchors:
  - [section 5.1] "Figure 3 shows that across the layers, the decoder's attention shifts to the textual outputs. In Layer 1, the model attends both to the visual and textual representations, but the model hardly pays attention to the visual outputs by Layer 4, relying more on the textual information from the retrieved captions."
  - [section 2.3] "We add cross-attention layers (Vaswani et al., 2017) subsequent to the masked self-attention sublayers, so the decoder can attend to the encoder outputs."
  - [corpus] Moderate evidence; similar attention shifts observed in VL-T5 but with object tags instead of full captions.
- Break condition: If retrieved captions are poor matches, the textual attention dominates incorrectly, leading to captions that ignore visual details.

### Mechanism 3
- Claim: Retrieving a sufficient number of captions (k=5) is critical for robustness against retrieval errors.
- Mechanism: Multiple retrieved captions provide redundancy; even if some are poor matches, others can compensate. Training with fewer captions (k=1 or k=3) degrades performance because the model lacks this robustness.
- Core assumption: Retrieval systems are imperfect and benefit from redundancy to mitigate individual caption mismatches.
- Evidence anchors:
  - [section 4.1] "Table 2 reports the result of this experiment, showing that performance degrades when retrieving less captions."
  - [section 5.2] "we hypothesise that retrieving more captions makes the model more robust in the presence of mismatches from certain captions"
  - [corpus] Weak evidence; retrieval augmentation literature often uses single retrieved examples, but not always in captioning.
- Break condition: If retrieval quality improves dramatically (near-perfect matches), fewer captions may suffice and reduce computational cost.

## Architecture Onboarding

- Component map: Image → CLIP features → retrieval → k captions → LXMERT encoding → cross-attention → caption generation

- Critical path: Image → CLIP features → retrieval → k captions → LXMERT encoding → cross-attention → caption generation

- Design tradeoffs:
  - Caption redundancy vs. computational cost (k=5 vs. k=1)
  - Retrieval quality vs. datastore size (CLIP-based retrieval vs. Faster R-CNN)
  - Encoder capacity vs. training stability (LXMERT frozen vs. fine-tuned)

- Failure signatures:
  - Low CIDEr/BLEU despite high retrieval accuracy → suggests cross-modal fusion isn't working
  - Attention collapsing to visual or textual only → indicates retrieval captions are mismatched
  - Training instability when encoder is fine-tuned → suggests gradient conflicts between randomly initialized decoder and pretrained encoder

- First 3 experiments:
  1. Vary k (1, 3, 5) to confirm redundancy benefit
  2. Replace LXMERT with OSCAR or VinVL to test encoder generalization
  3. Test retrieval from external dataset (COCO → Flickr30K) to validate zero-shot transfer

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of EXTRA vary when using different vision-and-language encoders beyond LXMERT, such as OSCAR or VinVL?
- Basis in paper: [explicit] The paper mentions that "our approach can be adapted to other V&L encoders besides LXMERT (e.g., OSCAR, VinVL, etc.)" and that these encoders "have mostly been applied to classiﬁcation tasks and have seen limited use for image captioning."
- Why unresolved: The paper only evaluates EXTRA using LXMERT as the vision-and-language encoder, leaving the performance of other encoders unexplored.
- What evidence would resolve it: Empirical results comparing the performance of EXTRA using different vision-and-language encoders on the COCO dataset.

### Open Question 2
- Question: What is the impact of jointly training the retrieval mechanism with the full model to retrieve captions that are more similar to the input image?
- Basis in paper: [explicit] The paper states that they plan to "explore methods that allow us to jointly train the retrieval mechanism with the full model in order to retrieve captions that are more similar to the input image" as future work.
- Why unresolved: The paper does not explore joint training of the retrieval mechanism, focusing instead on using a fixed retrieval system.
- What evidence would resolve it: Experimental results showing the performance improvement of EXTRA when the retrieval mechanism is jointly trained with the full model.

### Open Question 3
- Question: How does the performance of EXTRA change when evaluated on multilingual and geographically diverse captioning datasets, as opposed to the English-centric COCO dataset?
- Basis in paper: [explicit] The paper acknowledges that "Captioning datasets are primarily available in English, and most image captioning models are trained on COCO or other english-centric datasets" and mentions the importance of "multilingual captioning datasets that contain both language-diverse captions and geographically-diverse visual concepts."
- Why unresolved: The paper only evaluates EXTRA on the English-centric COCO dataset, leaving the performance on multilingual and geographically diverse datasets unexplored.
- What evidence would resolve it: Experimental results comparing the performance of EXTRA on multilingual and geographically diverse captioning datasets against the English-centric COCO dataset.

## Limitations

- Limited architectural novelty - the model primarily repurposes existing components (LXMERT encoder, GPT-2 decoder) without significant innovations
- Dataset-specific performance - the model's generalization to other domains or languages remains unexplored
- Computational overhead - the two-stage training process with frozen encoder followed by SCST fine-tuning creates significant computational requirements

## Confidence

**High confidence**:
- The model architecture (LXMERT encoder + GPT-2 decoder with cross-attention) functions as described
- Retrieval augmentation with k=5 captions provides performance benefits over k=1 or k=3
- Cross-attention mechanisms shift from visual to textual features across decoder layers

**Medium confidence**:
- The claimed performance improvement over baselines is statistically significant
- The V&L encoder provides meaningful semantic context beyond image features alone
- The model's robustness to retrieval errors when using multiple captions

**Low confidence**:
- The approach generalizes to non-English captioning tasks
- The model would maintain performance with different V&L encoders (OSCAR, VinVL)
- The retrieval-augmented approach would work with smaller datasets or fewer training examples

## Next Checks

1. **Ablation study with different k values on held-out test set**: Systematically evaluate k=1, 2, 3, 5, 10 to determine optimal number of retrieved captions and establish whether the performance curve plateaus, which would inform computational efficiency decisions.

2. **Cross-dataset generalization test**: Train the model on COCO and evaluate on Flickr30K or other image captioning datasets without fine-tuning to assess whether the retrieval-augmented approach transfers across domains and datasets.

3. **Encoder substitution experiment**: Replace LXMERT with other state-of-the-art V&L encoders (OSCAR, VinVL, BLIP) while keeping all other components identical to determine whether performance gains are primarily from the retrieval strategy or the specific encoder architecture.
