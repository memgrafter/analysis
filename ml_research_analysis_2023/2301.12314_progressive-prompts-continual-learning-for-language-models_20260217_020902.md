# Progressive Prompts: Continual Learning for Language Models

## Quick Facts
- **arXiv ID**: 2301.12314
- **Source URL**: https://arxiv.org/abs/2301.12314
- **Reference count**: 40
- **Key outcome**: Progressive Prompts eliminates catastrophic forgetting in continual learning by learning and freezing task-specific soft prompts, achieving over 20% improvement in average test accuracy compared to previous best methods on T5 models.

## Executive Summary
Progressive Prompts addresses catastrophic forgetting in continual learning for language models by learning a separate soft prompt for each task and sequentially concatenating them while keeping the base model frozen. The method preserves knowledge from previous tasks through frozen prompt parameters while enabling forward transfer by leveraging contextual information from prior prompts. Experiments demonstrate significant improvements over state-of-the-art methods on both standard and extended continual learning benchmarks, with particular success on T5 models where it achieves over 20% improvement in average test accuracy.

## Method Summary
Progressive Prompts learns task-specific soft prompts that are sequentially concatenated and prepended to input embeddings. For each new task, a separate prompt is initialized and trained while the base model remains frozen. After training, the prompt parameters are frozen and appended to the prompt sequence. At inference, all learned prompts are concatenated and prepended to inputs. The method optionally uses residual MLP reparameterization to stabilize prompt tuning by adding a skip connection that prevents the MLP from learning an identity mapping. This approach is parameter-efficient, model-agnostic, and does not require data replay.

## Key Results
- Progressive Prompts achieves over 20% improvement in average test accuracy compared to previous best methods on T5 models
- Significant gains observed on BERT models across long task sequences
- Eliminates catastrophic forgetting by freezing prompt parameters after each task
- Outperforms state-of-the-art methods including finetuning, replay, EWC, A-GEM, MBPA++, and IDBR

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Progressive concatenation of task-specific prompts prevents catastrophic forgetting.
- Mechanism: Each task prompt is frozen after training, so parameters are never updated again. New prompts are appended to the input sequence, leaving previous prompts untouched.
- Core assumption: The base model parameters remain frozen, so the only place task-specific knowledge lives is in the task prompts.
- Evidence anchors:
  - [abstract] "...sequentially concatenates it with previously learned prompts, while keeping the base model frozen."
  - [section] "...parameters θ of the language model are always frozen, and parameters θPk corresponding to prompt Pk are only trainable during learning Tk, and frozen afterwards."
  - [corpus] Weak – related papers focus on prompt isolation but do not describe freezing strategy.
- Break condition: If base model parameters are updated, earlier task knowledge could be overwritten.

### Mechanism 2
- Claim: Forward transfer is achieved by leveraging previously learned prompts as contextual conditioning.
- Mechanism: When learning task Tk, the model receives not only the new prompt Pk but also all prior prompts P1…Pk-1. These act as a form of contextual conditioning that encodes prior task structure.
- Core assumption: Task prompts capture task-specific input-output mappings that can generalize to new tasks.
- Evidence anchors:
  - [abstract] "...allows forward transfer by leveraging knowledge from previous tasks."
  - [section] "In Progressive Prompts, we learn a separate prompt Pk for task Tk, and concatenate it with all previously learned prompts Pi,i < k, before prepending to the input embeddings."
  - [corpus] Weak – no direct evidence of prompt-to-prompt knowledge transfer in the corpus.
- Break condition: If prompt embeddings are randomly initialized and not expressive enough to capture transferable structure.

### Mechanism 3
- Claim: Residual MLP reparameterization stabilizes prompt tuning and improves accuracy.
- Mechanism: Prompt embeddings are passed through an MLP with a skip connection before being fed into the model. The residual connection ensures gradients flow directly to the raw embeddings, preventing the MLP from learning an identity mapping.
- Core assumption: Direct gradient updates on raw prompt embeddings can lead to training instability; MLP with residual mitigates this.
- Evidence anchors:
  - [section] "To solve this issue, we propose adding a residual connection to the MLP reparameterization. This residual connection improves optimization, because it avoids learning an identity mapping by the MLP."
  - [corpus] Weak – no mention of MLP reparameterization in related papers.
- Break condition: If MLP depth or hidden size is too large, overfitting may occur.

## Architecture Onboarding

- **Component map**: Base model (BERT/T5) -> Task prompts (concatenated sequence) -> MLP reparameterization (optional) -> Input embeddings -> Frozen encoder/decoder -> Task-specific classification head
- **Critical path**: 1) Load base model and freeze parameters 2) For each task: initialize new prompt, optionally pass through MLP, concatenate with existing prompts 3) Train prompt with task data; freeze after training 4) At inference: prepend concatenated prompt sequence to input, forward through frozen base model, decode with task-specific head
- **Design tradeoffs**: Longer prompt sequences → more parameters but better task separation; Residual MLP → more stable training but adds compute; Freezing base model → prevents forgetting but limits adaptation capacity
- **Failure signatures**: Degrading accuracy on earlier tasks → prompts not properly frozen or base model updating; Slow convergence or divergence → improper MLP initialization or learning rate; High memory usage → too many long prompts or large MLP hidden size
- **First 3 experiments**: 1) Single-task prompt tuning baseline: verify that prompt tuning alone matches full fine-tuning on one dataset 2) Two-task progressive setup: confirm that adding a second prompt and freezing the first eliminates forgetting 3) MLP reparameterization ablation: compare with and without residual MLP on a few-shot task

## Limitations

- Limited ablation studies to isolate which components (prompt concatenation vs MLP reparameterization) drive performance gains

- Key implementation details missing including exact random seeds and specific MLP hyperparameter configurations

## Confidence

- **High confidence**: Catastrophic forgetting is prevented by prompt freezing mechanism
- **Medium confidence**: Progressive Prompts outperforms baselines on average accuracy
- **Low confidence**: Forward transfer attribution to prompt concatenation specifically
