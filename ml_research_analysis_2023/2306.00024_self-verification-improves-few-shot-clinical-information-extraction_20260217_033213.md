# Self-Verification Improves Few-Shot Clinical Information Extraction

## Quick Facts
- arXiv ID: 2306.00024
- Source URL: https://arxiv.org/abs/2306.00024
- Reference count: 10
- Primary result: Self-verification improves clinical information extraction accuracy by 0.056 F1 on average

## Executive Summary
This work introduces self-verification, a method for improving the reliability of clinical information extraction using large language models. The approach chains four LLM calls—original extraction, omission detection, evidence grounding, and pruning—to iteratively refine extracted information. Experiments across three clinical tasks demonstrate consistent accuracy improvements, with the method showing particular promise for reducing hallucinations and improving interpretability through evidence spans that align with human judgments.

## Method Summary
The self-verification method processes clinical text through a four-stage pipeline using large language models. First, an initial extraction identifies relevant information. Second, an omission step finds missing elements that should have been extracted. Third, an evidence step grounds each extracted element to specific text spans in the source document. Finally, a pruning step removes elements that cannot be adequately grounded or appear inaccurate. This iterative refinement process aims to produce more reliable and interpretable clinical information extraction results while maintaining few-shot learning capabilities.

## Key Results
- Self-verification consistently improves extraction accuracy across different LLMs
- Average F1 improvement of 0.056 across three clinical tasks
- Evidence spans produced by the method match human judgments for interpretability
- Method shows effectiveness for clinical trial arm extraction, medication status extraction, and ICD code extraction

## Why This Works (Mechanism)
The self-verification approach works by leveraging the LLM's own reasoning capabilities to iteratively improve extraction quality. Each stage serves a distinct purpose: the original extraction provides a baseline, omission detection identifies gaps, evidence grounding creates verifiable connections to source text, and pruning removes unreliable outputs. This multi-stage process addresses key LLM limitations like hallucinations and incomplete extractions by forcing the model to justify its outputs with textual evidence and reconsider its initial extractions.

## Architecture Onboarding

Component map: Original extraction -> Omission detection -> Evidence grounding -> Pruning

Critical path: The evidence grounding stage is critical as it provides the interpretability foundation that enables effective pruning. Without verifiable evidence spans, the pruning stage cannot make informed decisions about which elements to remove.

Design tradeoffs: The method trades computational efficiency for accuracy and interpretability, requiring four sequential LLM calls per extraction rather than a single call. This increases latency and cost but provides the iterative refinement needed for reliable clinical extraction.

Failure signatures: The method may fail when evidence spans cannot be found for correct extractions (leading to false positives in pruning), when omission detection misses critical elements, or when the LLM's reasoning chain breaks down across the multiple stages. Clinical text complexity and ambiguity can exacerbate these failures.

First experiments:
1. Run self-verification on a simple clinical text with known extractions to verify each stage produces expected outputs
2. Measure the individual contribution of each verification stage by running ablations (removing one stage at a time)
3. Test the method on non-clinical text to verify the approach generalizes beyond the specific domain

## Limitations
- Computational overhead from four sequential LLM calls may limit practical deployment
- Performance improvements, while consistent, may still be insufficient for critical clinical applications
- Limited evaluation across diverse clinical tasks raises questions about generalizability
