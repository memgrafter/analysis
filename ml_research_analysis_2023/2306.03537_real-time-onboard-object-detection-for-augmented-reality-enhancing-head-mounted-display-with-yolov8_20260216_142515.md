# Real-Time Onboard Object Detection for Augmented Reality: Enhancing Head-Mounted Display with YOLOv8

## Quick Facts
- arXiv ID: 2306.03537
- Source URL: https://arxiv.org/abs/2306.03537
- Reference count: 40
- Primary result: Real-time object detection pipeline for AR using YOLOv8 on Microsoft HoloLens 2, achieving processing times below 100 ms while maintaining satisfactory accuracy.

## Executive Summary
This paper presents a real-time object detection pipeline for augmented reality (AR) using the YOLOv8 model on the Microsoft HoloLens 2. The key contributions include implementing YOLOv8 onboard the HL2 to achieve real-time processing without offloading to external servers, optimizing the YOLOv8 network and image preprocessing to fit within the HL2's computational constraints, and demonstrating the pipeline's effectiveness through experiments on the COCO dataset. The results indicate that the proposed approach can effectively detect objects within a 2.5-meter range, suitable for most AR use cases.

## Method Summary
The method involves exporting a YOLOv8n model from PyTorch to ONNX format, importing it into Unity's Barracuda library on the HoloLens 2, and implementing an optimized image preprocessing pipeline. The approach focuses on reducing computational load by using smaller model sizes (YOLOv8n) and input image resolutions (160×160) while maintaining acceptable accuracy for AR tasks. The pipeline includes image cropping, normalization, YOLOv8 inference, and Non-Maximum Suppression (NMS) for postprocessing.

## Key Results
- Real-time processing achieved with YOLOv8n model and 160×160 input size on HL2, maintaining frame rates below 100 ms.
- Satisfactory mean average precision (mAP) demonstrated on COCO dataset, validating the approach's effectiveness.
- Detailed analysis of processing times provided, with strategies proposed for further optimization using different model sizes and input image resolutions.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: YOLOv8 network inference on HL2 is feasible within real-time constraints by balancing model size and input resolution.
- Mechanism: Smaller YOLOv8 models (e.g., YOLOv8n) paired with reduced input image sizes (160×160) reduce computational load while maintaining acceptable accuracy for AR tasks within a 2.5-meter range.
- Core assumption: The computational power of HL2's Snapdragon 850 and Adreno 630 GPU can handle the reduced model and image size without exceeding the 100 ms frame budget.
- Evidence anchors:
  - [abstract] states "real-time processing without needing offloading tasks to the cloud or any other external servers while retaining satisfactory accuracy"
  - [section V.A] shows processing times scaling with model size and [section V.B] with input image size, indicating trade-offs.
- Break condition: If input image size is further reduced below 160×160, accuracy drops below acceptable levels for AR use cases.

### Mechanism 2
- Claim: The use of ONNX and Barracuda library enables efficient model deployment on HL2.
- Mechanism: Exporting YOLOv8 from PyTorch to ONNX format and loading it into Unity's Barracuda library allows leveraging GPU acceleration for neural network inference.
- Core assumption: Barracuda supports the necessary ONNX opset version and provides efficient GPU inference on HL2's hardware.
- Evidence anchors:
  - [section III.C] mentions Barracuda's support for ONNX and GPU inference engines.
  - [section V.C] tests different backends (Compute, ComputePrecompiled) showing GPU inference is faster than CPU alternatives.
- Break condition: If Barracuda updates remove support for required opset versions or if GPU acceleration is not properly utilized, inference times will exceed real-time limits.

### Mechanism 3
- Claim: Image preprocessing and postprocessing steps are optimized to minimize latency.
- Mechanism: Cropping the center of the image to the network's input size and normalizing pixel values reduces preprocessing time; Non-Maximum Suppression (NMS) filters overlapping boxes efficiently.
- Core assumption: Preprocessing steps (cropping, normalization) and postprocessing (NMS) can be performed quickly enough not to dominate the total processing time.
- Evidence anchors:
  - [section IV] describes the image processing pipeline including preprocessing and NMS.
  - [section VI.A] provides timing analysis showing preprocessing (1.97 ms) and postprocessing (4.06 ms) are minor compared to inference (89.84 ms).
- Break condition: If the image resolution increases or if the number of detected objects grows significantly, preprocessing and postprocessing times could become bottlenecks.

## Architecture Onboarding

### Component Map
RGB Camera -> Image Preprocessing -> YOLOv8 Inference -> Non-Maximum Suppression -> AR Overlay

### Critical Path
Image Preprocessing (Crop, Normalize) -> YOLOv8 Inference -> Non-Maximum Suppression

### Design Tradeoffs
- Model size vs. accuracy: YOLOv8n chosen over larger models to reduce computational load.
- Input resolution vs. processing time: 160×160 resolution selected to balance speed and accuracy.
- Backend selection: ComputePrecompiled backend used for optimal GPU acceleration on HL2.

### Failure Signatures
- Processing time exceeds 100 ms: Check backend selection and image resolution.
- Low mAP despite fast inference: Adjust confidence threshold and NMS parameters; verify proper preprocessing.
- System crashes or freezes: Verify Barracuda support for ONNX opset version and GPU acceleration.

### 3 First Experiments
1. Export YOLOv8n model from PyTorch to ONNX with opset 9.
2. Import ONNX model into Unity Barracuda and set up image preprocessing pipeline (crop, normalize, resize to 160×160).
3. Run real-time inference and measure processing time; ensure ≤100 ms per frame while tracking mAP on COCO val2017.

## Limitations
- The approach is limited to a 2.5-meter range for object detection, with unclear performance in larger environments or complex scenarios.
- Reliance on the COCO dataset for evaluation may not fully represent typical AR use cases or domain-specific objects.
- The paper does not address potential issues with occlusions or varying lighting conditions, which are common challenges in real-world AR applications.

## Confidence

**High Confidence**: The claim that YOLOv8 can be implemented onboard the HL2 for real-time object detection is well-supported by the processing time measurements and mAP results presented in the paper.

**Medium Confidence**: The assertion that the proposed approach maintains satisfactory accuracy within a 2.5-meter range is based on the COCO dataset results, but lacks real-world validation in typical AR scenarios.

**Low Confidence**: The paper's claim about the system's effectiveness for "most AR use cases" is not well-supported, as it doesn't provide evidence beyond the COCO dataset and a 2.5-meter range.
