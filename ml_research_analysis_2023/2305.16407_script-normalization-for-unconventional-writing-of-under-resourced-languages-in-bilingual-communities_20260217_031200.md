# Script Normalization for Unconventional Writing of Under-Resourced Languages in Bilingual Communities

## Quick Facts
- arXiv ID: 2305.16407
- Source URL: https://arxiv.org/abs/2305.16407
- Reference count: 40
- One-line primary result: Transformer-based script normalization significantly improves downstream language identification and machine translation for under-resourced languages written in unconventional scripts.

## Executive Summary
This paper addresses script normalization for languages written in Perso-Arabic script by bilingual communities that also use other scripts (e.g., Persian, Arabic, Urdu). A transformer-based model is trained to normalize noisy text created by synthetically replacing characters based on script mappings and alignment matrices. The method outperforms a naive baseline, especially for lower script similarity ratios, and improves downstream tasks such as language identification and machine translation. Real-world evaluation shows significant BLEU gains over noisy input. The approach is robust across varying noise levels and demonstrates the feasibility of normalizing unconventional writing for under-resourced languages.

## Method Summary
The approach casts script normalization as a translation task, where noisy text in a dominant script is translated to clean text in the source script. Synthetic parallel data is generated by mapping characters between Perso-Arabic scripts and dominant language scripts using orthographic rules and character alignment matrices created via Needleman-Wunsch alignment. Transformer encoder-decoder models are trained at the character level on synthetic data with varying noise levels (20%, 40%, 60%, 80%, 100%, and merged). The models are evaluated using BLEU, chrF, and sequence accuracy metrics, with downstream applications in language identification and machine translation.

## Key Results
- Transformer models outperform naive baselines, particularly when source and dominant scripts have low character overlap (<0.6 script ratio)
- Normalization improves downstream language identification F1 scores by up to 25% and machine translation BLEU scores by up to 8 points
- Models trained on merged synthetic data (all noise levels) show strong generalization to real-world unconventional writing
- Performance varies significantly across language pairs, with high-performing languages like Sorani and lower-performing languages like Kashmiri

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Script normalization succeeds when the source and dominant scripts have low character overlap.
- Mechanism: Transformer encoder-decoder models learn to map characters from the dominant script to the source script when the mapping is not trivial (low script ratio).
- Core assumption: The noise introduced by unconventional writing is harder to resolve when characters from the two scripts are similar, making the task more difficult for the model.
- Evidence anchors:
  - [abstract] "Our experiments indicate that script normalization is also beneficial to improve the performance of downstream tasks such as machine translation and language identification."
  - [section] "Figure 3 shows the BLEU score (left y-axis) of the baseline and our model to normalize the datasets containing 100% noise, e.g. GLK100 FAS →GLK along with the script ratio for each language (right y-axis). This indicates that the normalization model (model100) performs better where the script ratio is relatively low (<0.6, i.e. the two scripts are not that similar)."
  - [corpus] Weak: corpus neighbors do not directly address script ratio impacts on normalization success.
- Break condition: When the script ratio is high (scripts are very similar), the transformer model fails to outperform the naive baseline because the noise is minimal and the model struggles to learn a meaningful mapping.

### Mechanism 2
- Claim: Synthetic data generation with varying noise levels improves model robustness.
- Mechanism: By injecting noise at different levels (20%, 40%, 60%, 80%, 100%), the model learns to handle a range of noise intensities, making it more effective at normalizing real-world unconventional writing.
- Core assumption: Real-world unconventional writing varies in noise level, and a model trained on diverse synthetic noise will generalize better.
- Evidence anchors:
  - [abstract] "Using synthetic data with various levels of noise and a transformer-based model, we demonstrate that the problem can be effectively remediated."
  - [section] "Using this model, our objective is to encode noisy data, i.e. synthetically noisy sentences, and decode normalized ones, i.e. the clean sentences in the collected datasets."
  - [corpus] Weak: corpus neighbors do not provide evidence on synthetic data generation for robustness.
- Break condition: If the noise levels in synthetic data do not reflect the true distribution of noise in real-world data, the model may overfit to synthetic patterns and fail on actual unconventional writing.

### Mechanism 3
- Claim: Framing script normalization as a translation task improves performance.
- Mechanism: By treating the normalization problem as translating from noisy text to clean text, the transformer model leverages its sequence-to-sequence capabilities to learn the mapping between scripts.
- Core assumption: The transformer architecture is well-suited for sequence-to-sequence tasks, and the normalization problem can be effectively modeled as such.
- Evidence anchors:
  - [abstract] "We cast script normalization as a translation task where noisy text is 'translated' into normalized one using synthetic data generated."
  - [section] "Given that these languages are less-resourced, we rely on synthetic data to create parallel datasets by injecting noise based on script mapping. We then train transformer-based encoder-decoders and show that the models can tackle the problem effectively, even for real data, but differently based on the level of noise."
  - [corpus] Weak: corpus neighbors do not provide direct evidence on the effectiveness of framing normalization as translation.
- Break condition: If the normalization problem is not well-suited to a translation framing (e.g., if the mapping is too simple or too complex), the transformer model may not learn an effective solution.

## Architecture Onboarding

- Component map: Data Collection -> Script Mapping -> Synthetic Data Generation -> Model Training -> Evaluation -> Downstream Tasks
- Critical path:
  1. Collect clean data in the source language
  2. Create script mapping rules and character alignment matrices
  3. Generate synthetic noisy data
  4. Train transformer models on synthetic data
  5. Evaluate model performance on test sets
  6. Apply models to downstream tasks

- Design tradeoffs:
  - Synthetic vs. real data: Synthetic data allows for controlled noise injection but may not fully capture real-world complexities
  - Rule-based vs. learned mappings: Rule-based mappings provide interpretability but may miss nuanced mappings that a learned model could capture
  - Character-level vs. subword-level modeling: Character-level modeling captures fine-grained mappings but may struggle with longer sequences

- Failure signatures:
  - Low BLEU/chrF scores on test sets: Indicates the model is not effectively learning the normalization mapping
  - High scores on synthetic data but low scores on real data: Suggests overfitting to synthetic noise patterns
  - Poor performance on downstream tasks: Indicates the normalization is not effective enough for practical use

- First 3 experiments:
  1. Train a baseline model on clean data and evaluate on noisy test sets to establish a performance floor
  2. Train a model on synthetic data with 20% noise and evaluate on test sets with varying noise levels to assess robustness
  3. Train a model on synthetic data with all noise levels merged and evaluate on real-world unconventional writing to test generalization

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Why do transformer models fail to simply learn to copy their input in script normalization tasks with high script similarity ratios?
- Basis in paper: [explicit] The paper notes that transformer models underperform the naive baseline for language pairs with high script similarity ratios (e.g., AZB, GLK, MZN, KAS, HAC), and suggests this is because the two scripts are very similar, leading to less "noise" and simpler copying tasks.
- Why unresolved: The paper does not investigate the underlying reasons why the transformer models fail to learn copying behavior despite the simplicity of the task.
- What evidence would resolve it: Experiments testing model capacity, architecture modifications, or training data augmentation to force copying behavior in high similarity scenarios.

### Open Question 2
- Question: How would performance change if the synthetic data generation included additional types of noise beyond simple character replacement?
- Basis in paper: [inferred] The paper acknowledges that the current noise generation is limited to character replacement and suggests that including other noise types (e.g., word boundary changes, spelling errors) could improve model robustness for morphologically rich languages.
- Why unresolved: The paper only tests one type of synthetic noise, limiting generalizability to real-world scenarios with varied error types.
- What evidence would resolve it: Experiments with synthetic data containing multiple noise types (diacritic removal, word boundary errors, spelling variations) and evaluation on real noisy data.

### Open Question 3
- Question: Would multilingual or transfer learning approaches improve script normalization performance for low-resource language pairs?
- Basis in paper: [inferred] The paper trains separate models for each language pair and shows varying performance. Some languages (e.g., Sorani) perform well while others (e.g., Kashmiri) do not, suggesting potential for knowledge transfer.
- Why unresolved: The paper does not explore multilingual training or transfer learning, missing potential performance gains from shared script normalization patterns across language pairs.
- What evidence would resolve it: Experiments training a single multilingual model on multiple language pairs and evaluating performance gains, particularly for low-resource languages.

## Limitations

- Evaluation relies entirely on synthetic data, with real-world performance demonstrated only for Sorani Kurdish, limiting confidence in practical applicability across all target languages.
- The character-level modeling approach may struggle with subword-level phenomena common in Perso-Arabic scripts, such as ZWNJ usage and word boundary variations.
- The paper does not explore alternative approaches (e.g., sequence labeling or denoising autoencoders) to establish whether the translation framing is optimal.

## Confidence

- **High Confidence**: The effectiveness of transformer-based normalization for low script similarity ratios (<0.6) is well-supported by experimental results across multiple languages and noise levels. The downstream benefits for language identification and machine translation are clearly demonstrated with quantitative metrics.
- **Medium Confidence**: The synthetic data generation methodology is described in sufficient detail for reproduction, but the exact rule-based mappings and character alignment matrices for all language pairs are not fully specified. This creates uncertainty about faithful reproduction across all target languages.
- **Low Confidence**: The claim that framing script normalization as a translation task is optimal is not empirically validated against alternative approaches. The paper does not compare transformer-based translation models to other potential architectures for this specific problem.
