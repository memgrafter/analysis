# Controllable Text-to-Image Generation with GPT-4

## Quick Facts
- arXiv ID: 2305.18583
- Source URL: https://arxiv.org/abs/2305.18583
- Reference count: 40
- Key outcome: Control-GPT achieves 44.2% spatial accuracy on Visor benchmark, nearly doubling Stable Diffusion's 18.8%

## Executive Summary
This paper introduces Control-GPT, a method that uses GPT-4 to generate TikZ sketches from text descriptions, which are then used to guide diffusion-based image generation models like ControlNet for more controllable text-to-image synthesis. The key idea is to leverage GPT-4's strong code generation ability to produce programmatic sketches that serve as spatial references alongside text prompts, helping diffusion models better follow spatial instructions. Since no aligned text-image-sketch dataset exists, the authors construct one by converting instance masks from COCO/LVIS into polygon sketches and fine-tune ControlNet on this data with additional grounding tokens for object names and positions. Evaluations on the Visor spatial benchmark show Control-GPT achieves 44.2% accuracy, nearly doubling the performance of standard Stable Diffusion (18.8%) and outperforming DALL-E 2.

## Method Summary
Control-GPT works by querying GPT-4 to write TikZ code from text prompts, then compiling these sketches into images. The method fine-tunes ControlNet on a dataset of COCO/LVIS images with corresponding polygon sketches and captions, adding grounding tokens that bind object names to positions. At inference, the system combines the GPT-4-generated sketch, text prompt, and grounding tokens to guide image generation. The fine-tuning process addresses the gap between programmatically generated sketches and what ControlNet can interpret, while grounding tokens help reduce ambiguity in object placement and identity.

## Key Results
- Control-GPT achieves 44.2% spatial relation accuracy on Visor benchmark versus 18.8% for Stable Diffusion
- Human evaluations show better handling of multi-object and out-of-distribution prompts
- Improves fine-grained control over object positions and sizes compared to text-only prompting
- GPT-4 successfully generates semantically correct TikZ sketches for 97% of test queries (95/95)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: GPT-4 generates TikZ sketches that follow spatial instructions with high precision, improving controllability over pure text inputs.
- Mechanism: GPT-4 leverages its code generation ability to convert spatial text instructions into programmatic sketches, which are then used as additional conditioning signals for diffusion models.
- Core assumption: GPT-4's code generation quality is high enough to produce semantically and spatially correct sketches that diffusion models can interpret.
- Evidence anchors: [abstract] "Control-GPT works by querying GPT-4 to write TikZ code, and the generated sketches are used as references alongside the text instructions for diffusion models"; [section] "GPT-4 only fails three times out of the 95 queries... giving a roughly 97% in successfully following the text instruction"

### Mechanism 2
- Claim: Fine-tuning ControlNet on polygon-masked data mitigates the gap between GPT-4-generated TikZ sketches and the model's understanding.
- Mechanism: Converting instance masks to polygon sketches and training ControlNet on these triplets (image, caption, sketch) allows the model to learn to interpret sketch-like inputs during inference.
- Core assumption: Polygon sketches are similar enough to GPT-4 TikZ outputs that the learned representations transfer.
- Evidence anchors: [section] "We construct a dataset containing triplets of images, textual captions, and polygon-represented sketches and fine-tune ControlNet"; [section] "We find this approach can mitigate the gap in understanding the GPT-generated sketches"

### Mechanism 3
- Claim: Grounding tokens that bind object names and positions to sketches improve object accuracy and reduce ambiguity.
- Mechanism: Adding grounding tokens in the form {object_name, object_position} alongside sketches and text helps ControlNet disambiguate between objects and enforce correct placement.
- Core assumption: The attention-based fusion of grounding tokens with image tokens can effectively condition the generation on precise object placement.
- Evidence anchors: [section] "We design grounding tokens in the form of {object_name, object_position}" and "Adding additional object grounding tokens to ControlNet is useful to further eliminate ambiguity"; [section] "Without the grounding token, we can see generation errors like the model successfully follows the layout of the provided sketch but generates incorrect objects"

## Architecture Onboarding

- Component map: GPT-4 (TikZ sketch generator) → TikZ compiler → Sketch image; GPT-4 (object name + position extractor) → Grounding token generator; ControlNet (fine-tuned on COCO+LVIS polygons) → Stable Diffusion backbone; Input: Text prompt + sketch image + grounding tokens → Output: Photo-realistic image
- Critical path: 1. Prompt GPT-4 to generate TikZ code and grounding tokens from text; 2. Compile TikZ → sketch image; 3. Feed sketch, text, and grounding tokens into fine-tuned ControlNet; 4. Generate final image
- Design tradeoffs: Fine-tuning vs. zero-shot (fine-tuning ControlNet on polygon data is needed because off-the-shelf ControlNet cannot interpret GPT-4 sketches); Grounding tokens vs. sketch-only (tokens reduce ambiguity but add complexity and may over-constrain generation); Sketch fidelity vs. realism (precise sketches may produce artifacts if the model overfits to layout)
- Failure signatures: Missing objects (indicates grounding token or sketch generation failure); Wrong object placement (indicates poor sketch or token alignment); Unrealistic images (indicates over-constraining by sketches or tokens)
- First 3 experiments: 1. Test GPT-4 sketch generation on a held-out set of spatial prompts; measure sketch accuracy manually; 2. Run ControlNet inference with off-the-shelf weights on GPT-4 sketches; measure object and spatial accuracy; 3. Fine-tune ControlNet on COCO+LVIS polygons; compare accuracy before and after fine-tuning on sketch-following benchmarks

## Open Questions the Paper Calls Out

  - Basis in paper: [explicit] The paper presents quantitative results comparing Control-GPT to GLIDE, DALL-E 2, and other models on the Visor spatial dataset, showing that Control-GPT achieves higher accuracy in following spatial relations, object positions, sizes, and colors.
  - Why unresolved: The paper does not provide a detailed analysis of the qualitative differences in image quality between Control-GPT and other models, which could provide insights into the trade-offs between controllability and photorealism.
  - What evidence would resolve it: A comprehensive qualitative evaluation of generated images from Control-GPT and other models, focusing on the quality of object shapes, textures, and overall scene composition, while also considering the adherence to spatial instructions.

- Question: How does the performance of Control-GPT vary with different types of spatial relationships, such as left/right, above/below, and complex multi-object arrangements?
  - Basis in paper: [explicit] The paper presents results on the Visor spatial dataset, which includes various spatial relationships, but does not provide a detailed breakdown of performance for different types of relationships.
  - Why unresolved: Understanding the strengths and weaknesses of Control-GPT in handling different spatial relationships could provide insights into potential areas for improvement and guide future research directions.
  - What evidence would resolve it: A detailed analysis of Control-GPT's performance on subsets of the Visor dataset, focusing on specific types of spatial relationships, and comparing the results to other models to identify areas where Control-GPT excels or struggles.

- Question: How does the integration of LLMs, such as GPT-4, into text-to-image generation models impact the overall computational efficiency and scalability of the system?
  - Basis in paper: [inferred] The paper discusses the integration of GPT-4 for generating sketches, but does not provide a detailed analysis of the computational overhead and scalability implications of this approach.
  - Why unresolved: Understanding the computational costs and scalability limitations of Control-GPT could provide insights into its practical applicability and guide the development of more efficient and scalable models.

## Limitations

- Core mechanisms rely heavily on GPT-4's sketch generation quality and the transferability of polygon-based fine-tuning to programmatically generated TikZ sketches
- No ablation study demonstrates the individual contribution of grounding tokens versus sketch-only control
- The 97% sketch generation success rate is based on manual inspection of only 95 queries without standardized evaluation criteria

## Confidence

- High confidence: Control-GPT achieves superior spatial accuracy on Visor benchmark (44.2% vs 18.8% for Stable Diffusion baseline)
- Medium confidence: GPT-4 reliably generates semantically correct TikZ sketches from spatial text instructions (based on 95-query manual inspection)
- Medium confidence: Fine-tuning ControlNet on polygon-masked data improves sketch-following capability
- Low confidence: Grounding tokens significantly improve object accuracy and reduce ambiguity (qualitative examples only, no ablation study)

## Next Checks

1. **Sketch generation reliability test**: Systematically evaluate GPT-4's TikZ sketch generation on a held-out test set of 500 diverse spatial prompts with blind human evaluation using standardized spatial accuracy metrics, measuring both semantic correctness and layout fidelity.

2. **Fine-tuning transfer validation**: Conduct an ablation study comparing ControlNet performance on GPT-4 sketches with and without fine-tuning, and test generalization to sketch styles that differ from COCO/LVIS polygons (e.g., hand-drawn sketches, different levels of abstraction).

3. **Grounding token contribution analysis**: Perform controlled experiments removing grounding tokens while keeping sketch inputs constant, measuring the quantitative impact on object accuracy, spatial relation accuracy, and object identity consistency across multiple test sets.
