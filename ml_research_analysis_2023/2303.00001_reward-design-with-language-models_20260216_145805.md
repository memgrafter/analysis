# Reward Design with Language Models

## Quick Facts
- arXiv ID: 2303.00001
- Source URL: https://arxiv.org/abs/2303.00001
- Reference count: 25
- Primary result: Using LLMs as proxy reward functions improves alignment with user objectives in game-theoretic scenarios

## Executive Summary
This paper proposes using large language models (LLMs) as proxy reward functions to train reinforcement learning (RL) agents that are better aligned with user objectives. The key innovation is leveraging LLMs' in-context learning abilities and prior knowledge of human behavior to provide reward signals consistent with user objectives from only a few examples or a description. The approach involves prompting an LLM with a task description, user-provided examples of desired behavior, and a trajectory from an RL episode, then using the LLM's output as a reward signal to train an RL agent. Experiments on the Ultimatum Game, matrix games, and a negotiation task demonstrate that agents trained with LLM rewards are better aligned with user objectives compared to supervised learning baselines or agents trained without explicit objectives.

## Method Summary
The approach uses an LLM as a reward function by prompting it with task descriptions, user-provided examples or descriptions of desired behavior, and agent trajectories from RL episodes. The LLM outputs a reward signal that is then used to train the RL agent. This leverages the LLM's ability to understand natural language specifications and its prior knowledge of human behavior patterns. The method allows for flexible reward specification through natural language rather than requiring manual reward function engineering or extensive demonstrations.

## Key Results
- Agents trained with LLM rewards showed better alignment with user objectives in the Ultimatum Game compared to supervised learning baselines
- The approach generalized to matrix games and a negotiation task, demonstrating its applicability across different game-theoretic scenarios
- A pilot human study found that agents trained with LLM rewards were rated as significantly more aligned with user objectives than other approaches

## Why This Works (Mechanism)
The approach works by leveraging the LLM's ability to understand natural language task descriptions and user-provided examples of desired behavior. The LLM can then evaluate agent trajectories and output rewards that reflect how well the agent's behavior matches the specified objectives. This allows for flexible reward specification without requiring manual reward function engineering or extensive demonstrations. The LLM's prior knowledge of human behavior patterns helps it generate rewards that are aligned with how humans would evaluate the agent's behavior.

## Foundational Learning
- **In-context learning**: Why needed - enables the LLM to adapt to new tasks from few examples; Quick check - verify the LLM can correctly interpret user-provided examples
- **Natural language understanding**: Why needed - allows the LLM to parse task descriptions and behavioral specifications; Quick check - test the LLM's ability to extract key objectives from natural language prompts
- **Reward shaping**: Why needed - transforms LLM outputs into usable reward signals for RL training; Quick check - validate that shaped rewards lead to meaningful policy updates
- **Reinforcement learning fundamentals**: Why needed - necessary for training agents using the LLM-generated rewards; Quick check - ensure RL training converges with LLM rewards

## Architecture Onboarding

### Component Map
LLM Prompt Builder -> LLM Reward Generator -> RL Agent -> Environment -> Trajectory Collector -> LLM Reward Generator (loop)

### Critical Path
User provides task description → Prompt builder formats inputs → LLM generates rewards → RL agent updates policy → Agent interacts with environment → Trajectory collected → Process repeats

### Design Tradeoffs
- LLM size vs. inference cost and speed
- Prompt engineering complexity vs. reward quality
- Number of examples required vs. generalization capability
- Reward signal granularity vs. computational efficiency

### Failure Signatures
- LLM generates inconsistent rewards across similar trajectories
- Rewards don't correlate with actual alignment to user objectives
- RL training fails to converge or produces degenerate policies
- Performance degrades significantly with slight prompt variations

### First 3 Experiments
1. Test LLM reward consistency by evaluating the same trajectory multiple times with different prompts
2. Compare RL performance using LLM rewards vs. manually engineered rewards on a simple gridworld task
3. Measure sensitivity of results to LLM size and number of in-context examples provided

## Open Questions the Paper Calls Out
None

## Limitations
- Evaluation limited to relatively simple game-theoretic scenarios rather than complex real-world environments
- Small sample size in human pilot study with only subjective alignment ratings
- Does not address potential biases in LLM's reward generation or performance across different LLM architectures
- Reliance on few-shot examples or textual descriptions may limit applicability in domains where such specifications are difficult

## Confidence

### High confidence
- Core methodology of using LLMs as proxy reward functions is clearly described and technically sound for demonstrated domains

### Medium confidence
- Empirical results showing improved alignment with user objectives in tested scenarios appear valid but may not generalize broadly

### Low confidence
- Claims about the approach's potential for real-world applications and scalability remain speculative without further validation

## Next Checks

1. Test the LLM reward design approach on environments with continuous state and action spaces, such as robotic control tasks, to assess scalability beyond discrete games.

2. Conduct a larger-scale human study with diverse participants and objective behavioral metrics to validate the subjective alignment ratings.

3. Perform ablation studies varying LLM size, prompting strategies, and the number of examples required to achieve reliable reward signals across different task types.
