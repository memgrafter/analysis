# Safe AI for health and beyond -- Monitoring to transform a health service

## Quick Facts
- arXiv ID: 2303.01513
- Source URL: https://arxiv.org/abs/2303.01513
- Reference count: 17
- Primary result: Introduces "Learning Machines" framework for continuous monitoring and updating of predictive models in healthcare to address performance degradation over time

## Executive Summary
This paper presents the concept of "Learning Machines" to address the challenge of maintaining predictive model performance in healthcare settings where patient demographics, clinical practices, and data distributions evolve over time. The framework proposes continuous monitoring of model outputs and data properties to determine when retraining is necessary, using automated model selection techniques like Auto-Prognosis. Two case studies demonstrate the approach: a breast cancer prognosis model showed unexpected performance changes over time, and an Alzheimer's detection algorithm performed better when trained on one dataset and applied to another, challenging the assumption that retraining with new data is always beneficial.

## Method Summary
The Learning Machines framework combines continuous monitoring of statistical properties of incoming healthcare data with automated model selection and hyperparameter tuning using techniques like Auto-Prognosis with Bayesian optimization. When monitoring detects significant changes in data distributions or model performance degradation, the system triggers retraining using the latest data. The approach incorporates uncertainty estimation and interpretability methods to support clinical decision-making, allowing practitioners to assess model reliability and understand predictions. The framework aims to ensure safe, effective, and transparent deployment of AI in high-stakes healthcare environments.

## Key Results
- A breast cancer prognosis model trained on SEER data showed performance changes over time, highlighting the need for monitoring infrastructure
- An Alzheimer's early detection algorithm trained on ADNI data performed better on Cambridge clinic data than a model trained on Cambridge data alone
- Blindly retraining with new data is not always optimal, demonstrating the importance of systematic monitoring before model updates

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Performance degradation over time is caused by changes in input data distribution, not by model complexity alone.
- Mechanism: The Learning Machines framework uses continuous monitoring of statistical properties of incoming patient data (distributions of features and outcomes) to detect drift. When detected, it triggers retraining or model replacement.
- Core assumption: Data distributions in healthcare are non-stationary due to evolving patient demographics, clinical practices, and treatment advances.
- Evidence anchors:
  - [abstract] "data changes over time, and they also changed when models are transported to new places to be used by new demography"
  - [section 4] "continuous monitoring of the properties of the dataset (distributions of patient features and outcomes) and evaluate the performance of the model on the latest data"
  - [corpus] Weak evidence - no directly comparable studies on drift detection in healthcare ML models found in corpus
- Break condition: If drift detection algorithms fail to capture subtle changes in high-dimensional clinical data, or if retraining pipelines introduce latency that prevents timely updates.

### Mechanism 2
- Claim: AutoML-based model selection can adapt to changing data patterns without manual intervention.
- Mechanism: The framework uses techniques like Auto-Prognosis with Bayesian optimization to automatically select and tune models based on the current dataset characteristics. This allows the system to potentially choose different models when retraining is triggered.
- Core assumption: The search space of ML models and hyperparameters is sufficiently rich to find better-performing alternatives when data distributions change.
- Evidence anchors:
  - [section 3] "Auto-Prognosis is a method proposed in [12], where authors use Bayesian optimization techniques [16] to find the right model and hyperparameters for a given dataset"
  - [section 5] "older models sometimes outperforming models trained on more recent patients or models trained on larger datasets" - demonstrating that blind retraining is not always optimal
  - [corpus] Weak evidence - no corpus papers specifically discussing AutoML for healthcare data drift scenarios
- Break condition: If the optimization process becomes computationally prohibitive for real-time updates, or if the search space doesn't contain suitable models for new data patterns.

### Mechanism 3
- Claim: Uncertainty estimation and interpretability provide necessary safeguards for clinical decision support.
- Mechanism: The framework incorporates uncertainty quantification (e.g., confidence intervals, probability scores) and interpretability methods (instance-wise feature selection, statistical interaction uncovering) to help clinicians assess model reliability and understand predictions.
- Core assumption: Clinicians can effectively use uncertainty and interpretability information to make safer decisions when AI recommendations are uncertain or counterintuitive.
- Evidence anchors:
  - [section 4] "uncertainty estimation can also be used to decide when to trigger retraining the model. When the confidence intervals start to become larger, it is an indication that the distribution of the input has changed"
  - [section 4] "Since the learning machine is going to interact with human experts it is vital that we provide interpretations for the predictions that the model makes"
  - [corpus] Weak evidence - corpus lacks papers on uncertainty estimation in clinical ML deployment scenarios
- Break condition: If uncertainty estimates are systematically miscalibrated, leading to either over-reliance on uncertain predictions or rejection of valid recommendations.

## Architecture Onboarding

- Component map: Data ingestion pipeline → Preprocessing and feature engineering → AutoML model selection → Uncertainty estimation module → Interpretability layer → Performance monitoring → Retraining trigger → Model registry → Clinical interface
- Critical path: New patient data → Feature extraction → Drift detection → Model prediction with uncertainty → Clinical decision support
- Design tradeoffs: Real-time vs. batch processing for drift detection (real-time provides faster updates but higher computational cost), model complexity vs. interpretability (more complex models may be more accurate but harder to explain to clinicians)
- Failure signatures: Performance degradation without drift detection (missed updates), false positive drift detection (unnecessary retraining), uncertainty underestimation (overconfident wrong predictions)
- First 3 experiments:
  1. Implement simple drift detection on a single feature (e.g., age distribution) and measure false positive/negative rates
  2. Test Auto-Prognosis on a fixed dataset with known optimal hyperparameters to verify search effectiveness
  3. Build end-to-end pipeline with synthetic data drift to validate complete retraining workflow

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What are the optimal metrics and thresholds for triggering model retraining in learning machines?
- Basis in paper: [explicit] The paper discusses continuous monitoring of data distributions and model performance but doesn't specify concrete metrics or thresholds for when to trigger retraining.
- Why unresolved: The authors note that simply retraining with new data isn't always optimal, as shown in the Alzheimer's example where the ADNI-trained model performed better on Cambridge data than a Cambridge-trained model. This suggests that naive retraining approaches may not work, but specific criteria are not provided.
- What evidence would resolve it: Empirical studies comparing different monitoring metrics (e.g., KL divergence, Wasserstein distance for data drift; AUROC, Brier score for performance changes) and their effectiveness at predicting when retraining improves vs. degrades performance across diverse datasets and domains.

### Open Question 2
- Question: How can learning machines effectively handle data from heterogeneous sources with different granularities and vocabularies?
- Basis in paper: [explicit] The paper identifies this as a technical challenge, noting that different hospital systems collect different levels of detail and use different vocabularies, which are lost when integrating data.
- Why unresolved: While the paper mentions this challenge, it doesn't propose specific solutions for reconciling heterogeneous data sources beyond general statements about the need for common vocabularies and understanding of hospital practices.
- What evidence would resolve it: Development and validation of automated data harmonization methods that can map between different medical coding systems and integrate data at varying granularities while preserving information content.

### Open Question 3
- Question: What is the optimal balance between transparency (interpretability and uncertainty) and model performance in learning machines?
- Basis in paper: [explicit] The paper emphasizes the importance of interpretability and uncertainty estimation for trust and accountability but doesn't address potential trade-offs with predictive performance.
- Why unresolved: More interpretable models often sacrifice some predictive accuracy, and the paper doesn't discuss how to weigh these competing objectives in high-stakes settings.
- What evidence would resolve it: Empirical comparisons of different interpretability methods and uncertainty quantification techniques across various machine learning architectures, measuring both their impact on model performance and their effectiveness at enabling clinician trust and appropriate use.

## Limitations

- The framework is conceptual rather than a fully implemented system, limiting direct empirical validation
- Key operational parameters (drift detection thresholds, retraining triggers) are not specified
- Case studies are preliminary demonstrations rather than comprehensive evaluations of the full framework

## Confidence

- Learning Machines framework effectiveness: Medium - theoretical framework with preliminary demonstrations but no full system validation
- AutoML performance improvement: Medium - well-established in ML literature but healthcare-specific validation needed
- Uncertainty and interpretability utility: Medium - important for clinical adoption but impact on decision quality unproven
