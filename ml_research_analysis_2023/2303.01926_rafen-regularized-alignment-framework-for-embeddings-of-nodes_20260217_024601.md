# RAFEN -- Regularized Alignment Framework for Embeddings of Nodes

## Quick Facts
- arXiv ID: 2303.01926
- Source URL: https://arxiv.org/abs/2303.01926
- Authors: 
- Reference count: 19
- Key outcome: RAFEN improves link prediction on dynamic graphs by aligning node embeddings across snapshots during training, achieving on-par or better performance than post-hoc alignment methods.

## Executive Summary
RAVEN is a framework that enables learning aligned node embeddings for dynamic graphs by incorporating an alignment regularization term into the loss function of existing node embedding methods. This approach allows embeddings to remain comparable across graph snapshots without requiring post-hoc alignment. The framework offers three variants: RAFEN_ALL (uses all common nodes), RAFEN_Weighted (weights nodes by activity using Edge Jaccard or Temporal Betweenness scores), and RAFEN_REF (selects top active nodes). Experiments on six real-world datasets demonstrate that RAFEN achieves competitive or superior performance compared to existing post-hoc alignment approaches.

## Method Summary
RAVEN enhances existing node embedding methods (Node2Vec, GAE) by adding an alignment regularization term to the loss function, minimizing the distance between embeddings of the same nodes across consecutive graph snapshots. The framework offers three variants: RAFEN_ALL treats all common nodes equally, RAFEN_Weighted assigns weights based on node activity scores (Edge Jaccard or Temporal Betweenness), and RAFEN_REF selects a subset of top active nodes. This end-to-end approach eliminates the need for computationally expensive post-hoc matrix factorization alignment while maintaining or improving link prediction performance on dynamic graphs.

## Key Results
- RAFEN_ALL, RAFEN_Weighted, and RAFEN_REF variants achieve on-par or better link prediction performance compared to existing post-hoc alignment methods
- RAFEN_Weighted using Temporal Betweenness scoring shows particularly strong performance on bitcoin-alpha and bitcoin-otc datasets
- The framework demonstrates flexibility by working with both Node2Vec and GAE embedding methods
- RAFEN eliminates the need for computationally expensive post-hoc matrix factorization alignment steps

## Why This Works (Mechanism)

### Mechanism 1
- Claim: RAFEN improves downstream link prediction by aligning embeddings across consecutive graph snapshots during training.
- Mechanism: The framework adds an alignment loss term to the base node embedding model's loss, minimizing the distance between embeddings of the same nodes in consecutive snapshots. This encourages embeddings to be algebraically comparable over time.
- Core assumption: Node embeddings should remain consistent for the same node across snapshots to preserve temporal relationships for downstream tasks.
- Evidence anchors:
  - [abstract] "we introduce a framework – RAFEN – that allows to enrich any existing node embedding method using the aforementioned alignment term and learning aligned node embedding during training time."
  - [section] "We enhance the loss function of the node embedding model Lmodel by adding an alignment term Lalignment."
- Break condition: If the alignment term overpowers the base model loss, it may distort the embedding space and harm performance.

### Mechanism 2
- Claim: RAFEN offers three variants (ALL, Weighted, REF) to balance alignment across nodes based on activity.
- Mechanism: RAFEN_ALL uses all common nodes equally, RAFEN_Weighted weights nodes by activity scores (e.g., Edge Jaccard or Temporal Betweenness), and RAFEN_REF selects only the top p% most active nodes. This allows tuning the alignment focus.
- Core assumption: Not all nodes change equally between snapshots; active nodes may need more or less emphasis in alignment.
- Evidence anchors:
  - [section] "We propose three different versions of the alignment function, including one that treats all nodes equally and one that utilizes temporal network measures for weighting the alignment process."
  - [section] "RAFEN_Weighted – similarly to the previous case, we use all common nodes, but instead of treating each one of them equally, we assign weights that reflect the change of a particular node between the graph snapshots."
- Break condition: If the scoring function poorly captures node activity, it may introduce noise or bias in the alignment.

### Mechanism 3
- Claim: RAFEN avoids post-hoc alignment by incorporating it into the training process, reducing computational overhead.
- Mechanism: Instead of applying expensive matrix factorization after training, RAFEN integrates alignment into the loss, enabling end-to-end learning of aligned embeddings.
- Core assumption: Embedding alignment during training is more efficient and potentially more effective than post-hoc correction.
- Evidence anchors:
  - [abstract] "RAFEN achieves on-par or better performance than existing approaches without requiring additional processing steps."
  - [section] "contrary to existing post-hoc methods, it does not rely on a time-consuming matrix factorization approach."
- Break condition: If the alignment term is poorly tuned, it could degrade the base embedding quality, negating the benefit of avoiding post-hoc alignment.

## Architecture Onboarding

- Component map: Base node embedding model (Node2Vec or GAE) -> Alignment loss term (MSE between consecutive snapshot embeddings) -> Activity scoring function (for RAFEN_Weighted) -> Reference node selector (for RAFEN_REF) -> Hyperparameter α (balance between base loss and alignment loss)
- Critical path:
  1. Initialize base embedding model on current snapshot
  2. Compute alignment loss with previous snapshot
  3. Combine with base loss using α
  4. Backpropagate and update model
- Design tradeoffs:
  - RAFEN_ALL: Simple but may include noisy nodes
  - RAFEN_Weighted: More nuanced but depends on scoring quality
  - RAFEN_REF: Reduces noise but requires selecting threshold p%
  - α tuning: Requires grid search or domain knowledge
- Failure signatures:
  - Alignment loss dominates → embeddings lose structural information
  - α too low → no alignment benefit
  - Poor scoring function → misaligned active nodes
  - Training instability → check learning rate and batch size
- First 3 experiments:
  1. Baseline: Train Node2Vec on last snapshot only, evaluate link prediction
  2. RAFEN_ALL: Add alignment to Node2Vec with α=0.5, compare to baseline
  3. RAFEN_Weighted with Edge Jaccard: Evaluate impact of weighting on performance

## Limitations

- The effectiveness of RAFEN depends on choosing appropriate scoring functions for node activity, but the paper lacks clear guidance on selecting between Edge Jaccard and Temporal Betweenness measures
- Performance improvements over post-hoc methods may not generalize to all node embedding approaches or dynamic graph scenarios
- The hyperparameter α requires careful tuning, and the paper does not discuss automated methods for finding optimal values
- Computational overhead of incorporating alignment during training versus post-hoc alignment is not explicitly quantified or compared

## Confidence

- High: The mechanism of adding an alignment term to the loss function is well-explained and mathematically sound
- Medium: The effectiveness of RAFEN variants (ALL, Weighted, REF) is supported by experiments, but the specific impact of scoring functions is not thoroughly analyzed
- Low: Claims about RAFEN's superiority over post-hoc methods lack detailed ablation studies or comprehensive comparisons across diverse graph types
