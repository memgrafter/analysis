# Symbolic Discovery of Optimization Algorithms

## Quick Facts
- arXiv ID: 2302.06675
- Source URL: https://arxiv.org/abs/2302.06675
- Reference count: 40
- Key outcome: Symbolic program search discovers Lion optimizer, achieving up to 2% accuracy improvement on ImageNet and state-of-the-art results across diverse tasks

## Executive Summary
This paper presents a symbolic approach to discovering optimization algorithms for deep learning through program search. The authors formulate algorithm discovery as an evolutionary search problem in an infinite and sparse program space, introducing techniques like abstract execution and funnel selection to address generalization gaps between proxy and target tasks. They discover Lion (EvoLved Sign Momentum), a simple yet effective optimizer that tracks only momentum and uses sign operations for updates. Lion demonstrates strong performance across diverse domains including image classification, vision-language tasks, diffusion models, and language modeling, often outperforming or matching AdamW while being more memory-efficient.

## Method Summary
The method formulates optimization algorithm discovery as program search, employing evolutionary search with warm-start and restart techniques to explore the program space. Abstract execution prunes redundant programs and caches semantically duplicate ones. The search uses proxy tasks for efficient evaluation, followed by funnel selection on progressively larger meta-validation tasks. Programs are simplified by removing redundant statements and converting to mathematical form. Lion is discovered through this process, using sign operations on momentum for updates while tracking only momentum parameters.

## Key Results
- Lion achieves up to 2% accuracy improvement on ImageNet classification
- Achieves state-of-the-art zero-shot and fine-tuning results in vision-language contrastive learning
- Improves diffusion model training efficiency by up to 2.3x
- Matches or exceeds AdamW performance on language modeling tasks
- Demonstrates strong out-of-distribution generalization across different architectures, datasets, and domains

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Symbolic program search discovers optimization algorithms by exploring an infinite and sparse program space
- Mechanism: Evolutionary search with warm-start and restart techniques navigates the program space, while abstract execution prunes redundant programs and caches semantically duplicate ones
- Core assumption: The program space contains sparse high-performing algorithms discoverable through evolutionary methods
- Evidence anchors: [abstract] "formulate algorithm discovery as program search, employing evolutionary search techniques to explore an infinite and sparse program space"
- Break condition: If search space is too sparse or evolutionary search fails to find diverse candidates

### Mechanism 2
- Claim: Lion achieves strong generalization due to its simple update rule with sign operation
- Mechanism: Sign operation adds noise acting as regularization, while tracking only momentum provides memory efficiency and uniform update magnitudes
- Core assumption: Simpler algorithms with uniform update magnitudes generalize better than complex adaptive methods
- Evidence anchors: [abstract] "Lion tracks only momentum and uses the sign operation for updates, making it more memory-efficient than Adam"
- Break condition: If noise from sign operation becomes detrimental on tasks requiring precise updates

### Mechanism 3
- Claim: Lion's performance advantage grows with batch size due to sign-based update mechanism
- Mechanism: Larger batch sizes provide more accurate gradient directions, which when combined with sign operation, leads to better optimization trajectories
- Core assumption: Sign operation requires accurate gradient information to be effective, which larger batches provide
- Evidence anchors: [abstract] "Our analysis of Lion reveals that its performance gain grows with the training batch size"
- Break condition: If batch size becomes too small (<64) where noise overwhelms sign operation benefits

## Architecture Onboarding

- Component map: Program search space definition -> Evolutionary search engine -> Abstract execution pipeline -> Funnel selection system -> Program simplification module -> Hyperparameter tuning interface

- Critical path: 1) Generate candidate programs through mutations 2) Abstract execution to filter and deduplicate 3) Evaluate on proxy tasks 4) Funnel selection on meta-validation tasks 5) Simplify and deploy best program

- Design tradeoffs: Search space expressiveness vs tractability, proxy task fidelity vs evaluation cost, algorithm simplicity vs performance, memory efficiency vs optimization quality

- Failure signatures: Early meta-overfitting (search fitness grows but meta-validation metric declines), high percentage of redundant statements (>70%), cache hit rate saturation (>90%), small performance gaps between Lion and AdamW on large datasets

- First 3 experiments: 1) Run basic evolutionary search with AdamW warm-start on proxy task 2) Implement abstract execution and measure pruning effectiveness 3) Test discovered Lion vs AdamW on small-scale ImageNet training

## Open Questions the Paper Calls Out

### Open Question 1
- Question: Can the discovered optimization algorithms generalize to tasks beyond deep learning, such as reinforcement learning or graph neural networks?
- Basis in paper: [explicit] The authors mention their method is generally applicable to other tasks but focus on deep learning optimizers
- Why unresolved: Only evaluated on deep learning tasks, no evidence for other task types
- What evidence would resolve it: Experimental results comparing performance on deep learning, reinforcement learning, and graph neural networks

### Open Question 2
- Question: How does choice of proxy tasks affect quality and generalizability of discovered algorithms?
- Basis in paper: [inferred] Authors discuss bridging generalization gap but don't analyze different proxy task impacts
- Why unresolved: No systematic comparison of different proxy tasks or their impact
- What evidence would resolve it: Comparative study of optimizers using different proxy tasks with analysis of their impact

### Open Question 3
- Question: What is optimal balance between exploration and exploitation in evolutionary search?
- Basis in paper: [explicit] Authors use multiple restarts but don't analyze exploration-exploitation trade-off
- Why unresolved: No systematic study of how restart strategies affect balance
- What evidence would resolve it: Ablation study comparing performance using different restart strategies and search parameters

## Limitations
- Search space exploration heavily depends on warm-starting from AdamW, potentially biasing discoveries
- Evolutionary search parameters (mutation rates, population diversity) are not fully specified
- Abstract execution implementation details remain underspecified, particularly dependency tracking and hash computation
- Performance claims for batch size relationship primarily based on experiments at batch sizes ≥256

## Confidence
- Discovery methodology: Medium-High - Well-established framework but implementation details are sparse
- Lion's generalization mechanism: Medium - Supported by experiments but theoretical justification is limited
- Cross-domain performance: High - Multiple independent task validations provide strong empirical support
- Memory efficiency claims: High - Direct comparison with AdamW implementation shows measurable reduction

## Next Checks
1. Conduct ablation studies varying warm-start conditions (random initialization vs AdamW warm-start) to quantify discovery bias
2. Test Lion on small-batch training (batch size 32-64) to verify claims about robustness across batch scales
3. Implement and compare alternative program search spaces (e.g., excluding momentum tracking entirely) to assess search space design impact
