# Curriculum Learning for Compositional Visual Reasoning

## Quick Facts
- arXiv ID: 2303.15006
- Source URL: https://arxiv.org/abs/2303.15006
- Reference count: 5
- Key outcome: Achieves 68.1% accuracy using only 50% of training data through curriculum learning

## Executive Summary
This paper proposes a curriculum learning method for the GQA visual question answering dataset using a neural module network framework. The approach leverages predefined cross-modal embeddings from LXMERT to warm-start learning and employs difficulty criteria such as number of objects and program length to define the curriculum strategy. By introducing intermediate losses for each module during training, the method reduces both training cost and data requirements while maintaining competitive accuracy.

## Method Summary
The method employs a neural module network architecture that uses frozen LXMERT features as input, with a program generator converting questions into sequences of module operations. The curriculum learning strategy starts with easier samples (single-object questions) and progressively increases difficulty based on object count and program length. Intermediate losses are added for each module's output using ground-truth labels from image graphs, helping individual modules learn their specific subtasks more effectively. The approach achieves comparable accuracy to full training with only 50% of the training data.

## Key Results
- Achieves 68.1% accuracy after 7 training iterations using less than 7M distinct examples
- Matches 70.2% accuracy of full training (14M examples) with only 50% of training data
- Reduces training cost while maintaining accuracy through curriculum learning

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Curriculum Learning with object-count difficulty criterion reduces training cost while maintaining accuracy
- **Mechanism:** Staged learning from single-object to multi-object reasoning allows the model to first learn basic reasoning skills before tackling complex multi-object reasoning
- **Core assumption:** Questions involving fewer objects require simpler reasoning and can be learned faster, providing a foundation for more complex reasoning tasks
- **Evidence anchors:** [abstract] shows CL reduces training cost and data requirements, [section] explains object count as relevant difficulty criterion
- **Break condition:** If the model cannot generalize from single-object to multi-object reasoning, or if object detection fails

### Mechanism 2
- **Claim:** Using predefined cross-modal embeddings from LXMERT "warms up" the learning process
- **Mechanism:** Pre-trained LXMERT features provide rich, aligned visual and textual representations as input to the NMN, rather than learning them from scratch
- **Core assumption:** LXMERT's cross-modal encoder has learned meaningful alignments between visual objects and textual concepts relevant to the GQA task
- **Evidence anchors:** [abstract] mentions predefined cross-modal embeddings to warm-start learning, [section] employs LXMERT as frozen feature extractor
- **Break condition:** If LXMERT's learned representations are not aligned with the specific reasoning patterns required for GQA

### Mechanism 3
- **Claim:** Intermediate module losses stabilize learning and help modules converge to expected behavior
- **Mechanism:** Adding loss terms for each module's output using ground-truth labels from image graphs provides more frequent feedback signals during training
- **Core assumption:** Each module has a well-defined expected behavior that can be evaluated independently using ground-truth information
- **Evidence anchors:** [abstract] introduces intermediate losses during training, [section] adds module loss to output loss using ground truth from image graphs
- **Break condition:** If ground-truth labels for intermediate modules are noisy or incomplete

## Architecture Onboarding

- **Component map:** Image → LXMERT → Object features + word embeddings → Program Generator → Program Executor → Answer prediction
- **Critical path:** Image → LXMERT → Object features + word embeddings → Program Generator → Program Executor → Answer prediction
- **Design tradeoffs:**
  - Frozen LXMERT vs. fine-tuning: Trade computation for adaptation capability
  - Weight sharing between compatible modules: Reduces parameters but may limit specialization
  - CL vs. standard training: Reduced cost and data requirements vs. potential accuracy drop
- **Failure signatures:**
  - High variance in module performance indicates poor grounding or loss weighting
  - Accuracy plateaus early suggest difficulty criteria are not well-calibrated
  - Training instability may indicate learning rate or batch size issues
- **First 3 experiments:**
  1. Train the NMN with random sampling (no CL) to establish baseline performance and identify which modules struggle most
  2. Implement CL with only object-count difficulty criterion (no weighting or pretraining) to isolate the impact of staged difficulty
  3. Add intermediate losses to the CL model to evaluate their impact on module convergence and overall accuracy

## Limitations
- Only evaluated on GQA dataset with program supervision, limiting generalizability
- Specific implementation details of program-to-module mapping and sampling strategy are not fully specified
- Potential for catastrophic forgetting when increasing difficulty levels

## Confidence
- **High confidence:** Core finding that curriculum learning reduces training cost while maintaining accuracy
- **Medium confidence:** Specific mechanisms (object-count difficulty criterion and intermediate losses) based on theoretical justification but limited ablation studies
- **Low confidence:** Generalization potential as method is only evaluated on GQA dataset

## Next Checks
1. **Ablation on difficulty criteria:** Run experiments isolating each difficulty criterion (object count, program length, etc.) to quantify their individual contributions to the CL performance gain

2. **Transfer to other VQA datasets:** Apply the CL method to datasets like VQAv2 or CLEVR without program supervision to test generalizability and identify which components are GQA-specific

3. **Analysis of catastrophic forgetting:** Conduct detailed analysis of accuracy changes between curriculum iterations, particularly focusing on whether questions from earlier difficulty levels are forgotten as training progresses to harder examples
