# An Empirical Comparison of LM-based Question and Answer Generation Methods

## Quick Facts
- arXiv ID: 2305.17002
- Source URL: https://arxiv.org/abs/2305.17002
- Reference count: 16
- Key outcome: End-to-end question-answer generation outperforms pipeline and multitask approaches while being computationally efficient

## Executive Summary
This paper systematically compares three LM-based question and answer generation (QAG) approaches: pipeline QAG (separate answer extraction and question generation models), multitask QAG (shared model with task prefixes), and end-to-end QAG (single model generating question-answer pairs directly). The evaluation uses a multi-domain QA task where QA models are trained on generated question-answer pairs. Results show that end-to-end QAG models generally perform best, with T5 LARGE end-to-end and BART LARGE multitask achieving the highest QA evaluation scores. The study demonstrates that end-to-end QAG is computationally efficient while maintaining high performance across domains.

## Method Summary
The paper evaluates three QAG approaches using encoder-decoder language models (T5 and BART) fine-tuned on SQuAD data. Pipeline QAG uses separate models for answer extraction and question generation, multitask QAG shares parameters across both tasks with task prefixes, and end-to-end QAG directly generates "question:{q}, answer:{a}" sequences from context. QA models are trained on generated data and evaluated on test sets to assess generation quality. The study also includes downsampling experiments comparing generated data to human-labeled gold QA pairs.

## Key Results
- End-to-end QAG models are computationally lighter at both training and inference times while generally outperforming other approaches
- T5 LARGE end-to-end and BART LARGE multitask models achieve the highest QA evaluation scores
- Generated QA pairs are competitive with human-labeled data, with T5 LARGE end-to-end showing the best quality
- Human-annotated gold datasets remain more informationally efficient than generated question-answer pairs

## Why This Works (Mechanism)

### Mechanism 1
- Claim: End-to-end QAG models outperform pipeline and multitask approaches because they generate question-answer pairs directly from context without intermediate decomposition.
- Mechanism: By generating the flattened sequence "question:{q}, answer:{a}" directly from context, the model learns a more coherent joint distribution of questions and answers conditioned on the context.
- Core assumption: The joint generation of question and answer from context captures more contextual dependencies than separate generation steps.
- Evidence anchors:
  - [abstract]: "Experiments show that an end-to-end QAG model, which is computationally light at both training and inference times, is generally robust and outperforms other more convoluted approaches."
  - [section 4.2]: "Among the QAG approaches, T5 consistently works better with the end2end QAG, while BART is not well-suited when used end2end."
  - [corpus]: Weak evidence - no direct comparison of generation quality between approaches in corpus.
- Break condition: If the context is too complex or requires multi-hop reasoning, the direct generation might fail to capture the necessary structure.

### Mechanism 2
- Claim: T5 models perform better with end-to-end QAG because their pre-training includes structured generation tasks.
- Mechanism: T5's pre-training objective involved generating from input-output pairs with structured templates, making it naturally suited for generating structured question-answer pairs directly.
- Core assumption: The pre-training objective shapes the model's ability to handle structured output tasks.
- Evidence anchors:
  - [section 4.2]: "A possible explanation is that T5 has observed sentences with structured information due to its multitask pre-training objective, while BART did not have such training instances."
  - [abstract]: No direct mention, but supports the overall comparison.
  - [corpus]: No direct evidence in corpus - this is an inference based on model architectures.
- Break condition: If using a model without structured pre-training (like BART), the end-to-end approach may underperform compared to pipeline/multitask.

### Mechanism 3
- Claim: Downsampling reveals that human-labeled data is more informationally efficient than generated QA pairs.
- Mechanism: When controlling for dataset size by downsampling, the gold QA baseline outperforms all generated models, indicating that each human-labeled pair contains more discriminative information.
- Core assumption: Information density per QA pair is higher in human-labeled data than in generated data.
- Evidence anchors:
  - [section 4.3]: "In this experiment, no model outperforms the gold QA baseline. This indicates that the human-annotated gold dataset is still more informative and data efficient than the generated question-answer pairs."
  - [abstract]: No direct mention of downsampling analysis.
  - [corpus]: Weak evidence - corpus mentions related work but not this specific finding.
- Break condition: If the generated data quality improves significantly or if the evaluation task is less information-sensitive, this advantage might diminish.

## Architecture Onboarding

- Component map: Base language models (T5/BART) → QAG fine-tuning → QA model training → Evaluation
- Critical path: Fine-tuning QAG models → Generating QA pairs → Training QA models → Evaluation
- Design tradeoffs:
  - Pipeline: Higher computational cost but potentially more control over each sub-task
  - Multitask: Moderate computational cost with shared representation learning
  - End2end: Lowest computational cost but less interpretable intermediate outputs
- Failure signatures:
  - Pipeline: Answer extraction failures cascade to question generation
  - Multitask: Task interference when fine-tuning both subtasks together
  - End2end: Poor handling of complex answer structures or multi-hop reasoning
- First 3 experiments:
  1. Train and evaluate all three QAG approaches on a small subset of SQuAD to verify implementation
  2. Compare computational costs (training time, inference speed, memory usage) across approaches
  3. Perform qualitative analysis of generated QA pairs to identify failure modes

## Open Questions the Paper Calls Out
- How do these QAG approaches perform on more complex domains requiring multi-hop reasoning or open-domain QA?
- Can end-to-end QAG models effectively handle complex answer structures and long-form questions?
- What is the optimal balance between model complexity and generation quality across different QA tasks?

## Limitations

- Domain Generalization: Performance on complex domains (multi-hop reasoning, open-domain QA) remains uncertain
- Evaluation Metric Validity: Using downstream QA performance as proxy for generation quality may be confounded by QA model characteristics
- Model Architecture Bias: Results may be partially attributed to T5 vs BART differences rather than fundamental QAG approach differences

## Confidence

- High Confidence: End-to-end QAG is computationally more efficient than pipeline approaches
- Medium Confidence: End-to-end approaches generally outperform multitask and pipeline approaches
- Medium Confidence: Human-labeled data is more informationally efficient than generated data
