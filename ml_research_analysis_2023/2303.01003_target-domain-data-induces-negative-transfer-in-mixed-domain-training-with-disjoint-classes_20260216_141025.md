# Target Domain Data induces Negative Transfer in Mixed Domain Training with Disjoint Classes

## Quick Facts
- arXiv ID: 2303.01003
- Source URL: https://arxiv.org/abs/2303.01003
- Authors: 
- Reference count: 16
- Primary result: Adding target domain data for in-classes causes models to ignore shape information for out-classes, leading to worse performance than training only on surrogate data

## Executive Summary
This paper reveals a previously unknown source of negative transfer in mixed-domain training with disjoint classes. When training with a mix of target and surrogate domain data, the presence of target domain data for in-classes causes the model to learn a domain-based shortcut that prioritizes domain discrimination over class-relevant features for out-classes. This leads to significantly worse performance on out-classes compared to training only on surrogate domain data. The effect occurs across 25+ domain shifts on real image classification datasets (PACS, VLCS, VisDA2017) and persists even with state-of-the-art domain adaptation methods.

## Method Summary
The paper investigates negative transfer by training models on mixed-domain data where target domain data is only available for in-classes (not out-classes). They compare performance against models trained only on surrogate domain data for out-classes. Experiments use standard image classification architectures (ResNet18, ConvNext, ViT-B) on PACS, VLCS, and VisDA2017 datasets. They systematically vary the proportion of target domain data for out-classes to study the effect. Colored MNIST is used as a toy example to illustrate the mechanism where models learn to use color (domain) as a shortcut instead of shape (class-relevant feature).

## Key Results
- Adding target domain data for in-classes causes significantly worse performance on out-classes compared to training only on surrogate domain data
- Performance degradation can be severe, sometimes dropping to worse than random guessing on out-classes
- State-of-the-art domain adaptation algorithms fail to mitigate this negative transfer
- The negative transfer is specifically induced by target domain data, not by adding any additional surrogate domain data
- The effect diminishes as the proportion of target domain data for out-classes increases (typically 5-20% threshold)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Target domain data in training causes the model to learn a shortcut that prioritizes domain discrimination over class-relevant features for out-classes.
- Mechanism: When both target and surrogate domain data are present in training, the model learns to split the domains first and then decide which class to predict based on the domain label. This shortcut is learned because the model can achieve good performance on in-classes by using domain information alone, and this strategy then incorrectly generalizes to out-classes.
- Core assumption: The model learns to use domain labels as a shortcut feature that is more easily accessible than the true discriminative features (e.g., shape in Colored MNIST).
- Evidence anchors:
  - [abstract] "We hypothesize that this negative transfer is due to an intermediate shortcut that only occurs when multiple source domains are present"
  - [section] "We claim the model has learned the relevant discriminative feature in our setting...But what we instead find is that the network learns a 'lazy' rule first...where it eliminates specific classes based on the digit's color, and then selects the predicted class based on the shape of the digit."
- Break condition: If the model is prevented from learning domain-based shortcuts (e.g., through domain-invariant feature learning), or if sufficient target domain data for out-classes is provided to override the shortcut.

### Mechanism 2
- Claim: The negative transfer effect is specifically induced by adding target domain data, not by adding any additional domain data.
- Mechanism: When target domain data for in-classes is added to training, it creates a situation where the model can achieve good performance on in-classes by using domain information as a shortcut. This shortcut then harms performance on out-classes when tested on the target domain. Adding data from a different surrogate domain does not create this shortcut because it doesn't provide the same domain-based shortcut opportunity.
- Core assumption: The presence of target domain data for in-classes creates a unique opportunity for domain-based shortcut learning that is not present when adding data from other surrogate domains.
- Evidence anchors:
  - [abstract] "We show that this phenomena occurs on over 25 distinct domain shifts...and that even the presence of state-of-the-art domain adaptation algorithms does not significantly address this problem."
  - [section] "Interestingly, some surrogate domains do exhibit some negative transfer, specifically in the cases when S1 = P, S2 = {C, S}, T = A in Figure 7)."
- Break condition: If the surrogate domain is sufficiently similar to the target domain, it may induce similar negative transfer.

### Mechanism 3
- Claim: The degree of negative transfer is related to the proportion of target domain data for out-classes in the training set.
- Mechanism: With very little target domain data for out-classes, the model relies heavily on the domain-based shortcut, leading to poor performance. As more target domain data for out-classes is added, the model learns to use the true discriminative features, reducing the negative transfer effect. However, as the proportion increases further, the benefit of the surrogate data diminishes.
- Core assumption: The model's reliance on the domain-based shortcut decreases as it receives more examples of out-classes in the target domain.
- Evidence anchors:
  - [section] "We find that with very low amounts of target domain data for these classes, negative transfer is still present. However, typically with a proportion of about 5-20% of target domain to surrogate domain, the negative transfer begins to gradually diminish"
- Break condition: If the proportion of target domain data for out-classes becomes very high (e.g., 100%), the problem reduces to standard supervised learning without domain shift.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the degree of negative transfer vary with the similarity between the target and surrogate domains?
- Basis in paper: [explicit] The paper states that "the degree of negative transfer varies between domains, and appears to be more severe when domains are intuitively 'further apart'."
- Why unresolved: While the paper provides anecdotal evidence of this relationship, it does not conduct a systematic study to quantify the relationship between domain similarity and the degree of negative transfer.
- What evidence would resolve it: A quantitative analysis measuring domain similarity (e.g., using feature space distance metrics) and correlating it with the magnitude of performance degradation across multiple domain pairs would provide concrete evidence.

### Open Question 2
- Question: Does the negative transfer phenomenon extend to other computer vision tasks beyond image classification, such as object detection or semantic segmentation?
- Basis in paper: [inferred] The paper explicitly states in the discussion that "determining whether this effect occurs in object detection, segmentation, or other machine vision tasks is outside the scope of this work."
- Why unresolved: The paper only investigates the phenomenon in image classification tasks using ResNet architectures, leaving uncertainty about its generalizability to other tasks and architectures.
- What evidence would resolve it: Conducting experiments on object detection and semantic segmentation benchmarks (e.g., COCO, Pascal VOC) with mixed-domain training scenarios would determine if the negative transfer phenomenon generalizes across computer vision tasks.

### Open Question 3
- Question: What are the underlying mechanisms that cause the model to prioritize domain information over class-specific features when target domain data is present in the training set?
- Basis in paper: [explicit] The paper hypothesizes that "the network learns a 'lazy' rule first... where it eliminates specific classes based on the digit's color, and then selects the predicted class based on the shape of the digit."
- Why unresolved: While the paper provides a hypothesis based on toy examples, it does not provide a comprehensive explanation for why models systematically prioritize domain information over discriminative features when target domain data is present.
- What evidence would resolve it: Detailed analysis of intermediate representations and feature importance through techniques like feature visualization, ablation studies on learned representations, and investigation of gradient flow could elucidate the mechanisms driving this prioritization.

## Limitations
- The exact mechanism of why target domain data for in-classes specifically causes negative transfer is hypothesized but not definitively proven
- The relationship between visual similarity of surrogate domains and degree of negative transfer is mentioned but not thoroughly analyzed
- The experiments focus primarily on image classification; generalization to other domains (text, tabular data) is untested
- No ablation studies examining different model architectures' susceptibility to this effect

## Confidence
- High confidence: The empirical observation that target domain data for in-classes causes worse performance on out-classes (supported by 25+ domain shifts)
- Medium confidence: The hypothesis that this is due to domain-based shortcut learning (mechanism is plausible but not definitively proven)
- Medium confidence: The claim that this is strictly caused by target domain data (interesting finding, but the analysis of surrogate domain similarity effects is limited)
