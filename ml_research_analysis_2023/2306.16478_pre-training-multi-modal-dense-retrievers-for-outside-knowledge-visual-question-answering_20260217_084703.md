# Pre-Training Multi-Modal Dense Retrievers for Outside-Knowledge Visual Question Answering

## Quick Facts
- arXiv ID: 2306.16478
- Source URL: https://arxiv.org/abs/2306.16478
- Reference count: 40
- Key outcome: Pre-training on automatically generated data achieves 40.2% Precision@5 improvement in zero-shot retrieval and 26.9% Precision@5 improvement over state-of-the-art when fine-tuned on supervised data.

## Executive Summary
This paper addresses the challenge of outside-knowledge visual question answering (OK-VQA), where questions about images require external knowledge not present in the image itself. The authors propose an automatic data generation pipeline to pre-train multi-modal dense retrieval models, eliminating the need for large-scale manually labeled training data. By generating question-image pairs from image captions, retrieved passages, and answer phrases, the pipeline creates training data that aligns with the OK-VQA task. Experiments show that this pre-training approach significantly improves retrieval performance and reduces the need for supervised data by 75% while maintaining competitive results.

## Method Summary
The authors develop an automatic pipeline to generate training data for multi-modal dense retrieval in OK-VQA tasks. The pipeline works by first captioning images from datasets like MS COCO, then retrieving relevant passages using BM25 or learned retrievers based on these captions. Answer phrases are extracted from the retrieved passages (primarily noun phrases), and questions are generated using a fine-tuned T5 model. A QA model filters out low-quality questions by checking if the generated question can be answered from the passage. The dense retrieval model uses an asymmetric architecture with LXMERT for queries and BERT for passages, trained using contrastive loss with hard negatives. The pre-trained model is then fine-tuned on limited supervised OK-VQA data.

## Key Results
- 40.2% Precision@5 improvement in zero-shot retrieval over BM25 baselines
- 26.9% Precision@5 improvement over current state-of-the-art asymmetric dense retrieval when fine-tuned on supervised data
- Pre-trained model outperforms model trained on 100% of supervised data when using only 25% of supervised data
- Performance stabilizes after 50% of supervised data, demonstrating reduced need for large-scale manually labeled training sets

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Automatic question generation from retrieved passages ensures questions require external knowledge, aligning pre-training data with OK-VQA task.
- Mechanism: Pipeline retrieves passages based on image captions, extracts answer phrases, and generates questions using fine-tuned T5 model, ensuring questions are grounded in external knowledge sources.
- Core assumption: Retrieved passages contain sufficient external knowledge to answer questions about images when combined with image context.
- Evidence anchors: [abstract] pipeline generates question-image pairs by first using image captions to retrieve relevant passages, then extracting answer phrases; [section 4.1] approximately 80% of answers in OK-VQA dataset are noun phrases.
- Break condition: If retrieved passages lack relevant external knowledge or question generation produces questions answerable without external knowledge, alignment breaks.

### Mechanism 2
- Claim: Filtering generated questions using QA model reduces noise in pre-training data, improving downstream performance.
- Mechanism: After generating questions, pipeline uses QA model to verify generated question can be answered from passage, filtering out questions where answer doesn't match extracted answer phrase.
- Core assumption: QA model can accurately determine whether question can be answered from given passage, and filtering removes questions that would mislead retriever during training.
- Evidence anchors: [section 4.1] design QA model and filter out questions for which model cannot produce close enough answer; [section 5.2] zero-shot retrieval results show pre-trained model significantly outperforms BM25 and other baselines.
- Break condition: If QA model is inaccurate or filters out too many valid questions, pre-training data quality may degrade.

### Mechanism 3
- Claim: Pre-training on automatically generated data reduces need for large-scale supervised training data.
- Mechanism: Pre-trained model learns to retrieve relevant passages for multi-modal queries through automatically generated data, so when fine-tuned on limited supervised data, it already has strong retrieval foundation.
- Core assumption: Automatically generated data captures essential characteristics of OK-VQA task, so pre-training transfers well to supervised task.
- Evidence anchors: [abstract] pre-trained model outperforms model trained on 100% of supervised data when using only 25% of supervised data; [section 5.2] learning curve shows pre-trained model outperforms non-pretrained model trained on 100% of supervised data after seeing only 25% of supervised data.
- Break condition: If automatically generated data poorly represents true distribution of OK-VQA queries, pre-training may not transfer effectively.

## Foundational Learning

- Concept: Multi-modal dense retrieval
  - Why needed here: Task requires retrieving text passages relevant to queries combining images and questions, which is multi-modal retrieval problem.
  - Quick check question: What distinguishes multi-modal retrieval from uni-modal retrieval, and why is this distinction important for OK-VQA?

- Concept: Weak supervision and data augmentation
  - Why needed here: Paper relies on automatically generated data rather than manually labeled data, requiring understanding how weak supervision can be effective.
  - Quick check question: How does weak supervision differ from traditional supervised learning, and what are risks and benefits in context of retrieval?

- Concept: Contrastive learning for retrieval
  - Why needed here: Dense retrieval model trained using contrastive loss that pulls relevant passages closer to query and pushes irrelevant passages away.
  - Quick check question: How does contrastive loss function work in dense retrieval, and why is it effective for learning semantic similarity?

## Architecture Onboarding

- Component map: Image → Caption → Retrieved passages → Answer phrases → Questions → Filtered questions → Training data → Pre-trained retriever
- Critical path: Image → Caption → Retrieved passages → Answer phrases → Questions → Filtered questions → Training data → Pre-trained retriever
- Design tradeoffs:
  - Using BM25 for initial retrieval vs. learned retriever: BM25 is simpler and doesn't require training, but may miss semantically relevant passages
  - Noun phrase extraction for answers: Simple and effective, but may miss answers that aren't noun phrases
  - Question filtering with QA model: Reduces noise but may filter out valid questions if QA model is inaccurate
- Failure signatures:
  - Poor zero-shot performance: Suggests pre-training data generation pipeline producing low-quality data or retriever architecture isn't learning effectively
  - Degradation in supervised fine-tuning: May indicate overfitting to pre-training data or poor alignment between pre-training and target tasks
  - High variance in learning curves: Could suggest instability in training process or sensitivity to initialization
- First 3 experiments:
  1. Generate small sample of pre-training data and manually inspect quality of questions, answers, and retrieved passages to verify pipeline works as intended
  2. Train dense retrieval model on generated data and evaluate zero-shot retrieval performance on held-out set to confirm pre-training is effective
  3. Fine-tune pre-trained model on small subset of OK-VQA data and compare performance to model trained from scratch on same data to verify transfer benefit

## Open Questions the Paper Calls Out
- Extending the proposed pre-training pipeline to other knowledge-intensive vision-language tasks beyond OK-VQA, such as FVQA (Fact-Based Visual Question Answering)
- Investigating the impact of using more diverse image collections beyond MS COCO, particularly for underrepresented OK-VQA categories
- Comparing the proposed pre-training approach to other pre-training tasks like multimodal variants of Inverse Cloze Task (ICT) for OK-VQA

## Limitations
- The effectiveness of automatic pre-training relies heavily on the assumption that generated questions accurately represent true OK-VQA query distribution
- The filtering mechanism using QA model may introduce bias by removing valid but challenging questions
- The study focuses primarily on OK-VQA and doesn't extensively test generalizability to other knowledge-intensive vision-language tasks

## Confidence
- High confidence: Pre-training pipeline implementation and zero-shot retrieval results are well-supported by experimental evidence and methodological clarity
- Medium confidence: Claim about reduced need for supervised data (25% vs 100%) is supported but could benefit from more extensive ablation studies on different data subsets
- Medium confidence: Mechanism explanations are reasonable but rely on several assumptions about alignment between pre-training and target task distributions

## Next Checks
1. Conduct thorough distribution analysis comparing automatically generated questions to actual OK-VQA questions, examining answer types, question patterns, and knowledge domains to verify distributional alignment
2. Perform ablation studies removing question filtering step to quantify how much QA model filtering contributes to performance gains versus potential filtering bias
3. Test pre-trained model on related visual question answering tasks that don't require external knowledge to assess whether model has overfit to OK-VQA domain or developed generalizable retrieval capabilities
