# Event Knowledge Incorporation with Posterior Regularization for Event-Centric Question Answering

## Quick Facts
- arXiv ID: 2305.04522
- Source URL: https://arxiv.org/abs/2305.04522
- Reference count: 11
- Primary result: Achieves up to 4.6% absolute improvement in Exact Match scores on TORQUE and ESTER datasets

## Executive Summary
This work introduces a posterior regularization mechanism to incorporate event knowledge into question-answering (QA) models for event-centric QA tasks. Event knowledge constraints are defined based on event trigger annotations in the training data, and used to regularize the answer probabilities generated by backbone PLMs. For extractive QA, sentence-level event knowledge constraints assess whether a sentence contains answer events, and use this to modify answer span extraction probabilities. For generative QA, token-level event knowledge constraints compare generated tokens to answer events to introduce rewards or penalties, indirectly adjusting answer generation probabilities. Experiments on the TORQUE and ESTER datasets show that the proposed approach effectively injects event knowledge into PLMs and achieves strong performance compared to existing QA models.

## Method Summary
The method incorporates event knowledge into QA models using posterior regularization. Event knowledge constraints are defined based on event trigger annotations in the training data. For extractive QA, sentence-level constraints assess whether sentences contain answer events and modify answer span extraction probabilities accordingly. For generative QA, token-level constraints compare generated tokens with answer events to introduce reward or penalty terms that indirectly adjust answer generation probabilities. The approach is implemented using RoBERTa-large for extractive QA and UnifiedQA-T5-large for generative QA, trained on the TORQUE and ESTER datasets with event trigger annotations.

## Key Results
- Achieves up to 4.6% absolute improvement in Exact Match scores on TORQUE and ESTER datasets
- Effectively incorporates event knowledge into PLMs without requiring annotations during inference
- Demonstrates strong performance compared to existing QA models on event-centric tasks

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Sentence-level event knowledge constraints improve extractive QA by increasing the probability of extracting answer spans from sentences that contain answer events.
- **Mechanism:** The model defines a sentence relevance score based on whether a sentence contains an answer event. This score is used to adjust the answer span extraction probability through a regularization function.
- **Core assumption:** Sentences containing answer events are more likely to contain the correct answer spans.
- **Evidence anchors:**
  - [abstract]: "For extractive QA, the sentence-level event knowledge constraint is defined by assessing if a sentence contains an answer event or not, which is later used to modify the answer span extraction probability."
  - [section 3.2.1]: "Intuitively, if the sentence relevance score is high, then the probability of extracting an answer span from the corresponding sentence will be increased."
- **Break condition:** If the model incorrectly identifies sentences as containing answer events when they do not, the regularization could lead to extracting incorrect spans.

### Mechanism 2
- **Claim:** Token-level event knowledge constraints improve generative QA by rewarding the generation of answer events and penalizing the generation of irrelevant events.
- **Mechanism:** A reward and penalty term is defined based on comparing generated tokens with answer events. This term is used to create an additional loss that indirectly adjusts the answer generation probability.
- **Core assumption:** Generating tokens that match answer events should be encouraged, while generating tokens that match irrelevant events should be discouraged.
- **Evidence anchors:**
  - [abstract]: "For generative QA, the token-level event knowledge constraint is defined by comparing the generated token from the backbone language model with the answer event in order to introduce a reward or penalty term, which essentially adjusts the answer generative probability indirectly."
  - [section 3.2.2]: "We extend this strategy by combining rewards of answer events and penalties of irrelevant events."
- **Break condition:** If the reward and penalty terms are not well-calibrated, the model might generate incorrect answers that happen to contain some answer event tokens.

### Mechanism 3
- **Claim:** Posterior regularization allows for the incorporation of external knowledge constraints without requiring these constraints during inference.
- **Mechanism:** Event knowledge constraints defined using training data annotations are used to regularize the posterior answer probabilities. During inference, only the question and passage are needed.
- **Core assumption:** The regularization learned during training generalizes to unseen data, allowing the model to benefit from the constraints without needing them at test time.
- **Evidence anchors:**
  - [abstract]: "Although our model training relies on event trigger annotations to define event knowledge constraints, such annotations are not necessary during the inference."
  - [section 3.2]: "We propose a simple yet effective strategy to incorporate event semantic knowledge via posterior regularization for both extractive and generative event-centric QA."
- **Break condition:** If the model overfits to the specific event annotations in the training data, the regularization may not generalize well to new data.

## Architecture Onboarding

- **Component map:** Input (Question, Passage) -> Backbone (RoBERTa-large/UnifiedQA-T5-large) -> Event Knowledge Constraints -> Regularization -> Output (Answer Spans/Generated Text)

- **Critical path:**
  1. Encode question and passage using backbone PLM
  2. Define event knowledge constraints based on event triggers
  3. Apply regularization to adjust answer probabilities
  4. Generate final answer

- **Design tradeoffs:**
  - Using sentence-level vs. token-level constraints for extractive QA
  - Direct vs. indirect adjustment of answer probabilities for generative QA
  - Balancing the main QA loss with the regularization loss

- **Failure signatures:**
  - Decreased performance on questions where the event knowledge constraints are incorrect or misleading
  - Overfitting to the specific event annotations in the training data
  - Instability in generative QA due to direct modification of answer probabilities

- **First 3 experiments:**
  1. Implement the basic QA model without any regularization to establish a baseline
  2. Add sentence-level event knowledge constraints for extractive QA and evaluate the impact
  3. Add token-level event knowledge constraints for generative QA and compare with direct probability adjustment approach

## Limitations

- The approach relies heavily on the availability and quality of event trigger annotations in the training data, which may not always be available or accurate.
- Specific implementation details, such as the attention mechanism in sentence-level constraints and exact hyperparameter values, are not fully specified, which could impact reproducibility and performance.
- The method's effectiveness on datasets with more complex event structures or in different domains remains untested.

## Confidence

- **High Confidence:** The general concept of using posterior regularization to incorporate event knowledge into QA models is well-established in the literature. The experimental results demonstrating performance improvements on TORQUE and ESTER datasets are also convincing.
- **Medium Confidence:** The specific mechanisms for defining sentence-level and token-level event knowledge constraints are clearly described, but the lack of detailed implementation details introduces some uncertainty about the exact functioning of these components.
- **Low Confidence:** The claim that the model can effectively incorporate event knowledge without requiring annotations during inference is based on the assumption that the learned regularization generalizes well. However, without further experiments on out-of-domain data or with different event annotation schemes, it's difficult to fully assess the robustness of this claim.
