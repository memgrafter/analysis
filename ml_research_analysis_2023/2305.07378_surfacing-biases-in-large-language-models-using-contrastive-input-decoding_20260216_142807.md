# Surfacing Biases in Large Language Models using Contrastive Input Decoding

## Quick Facts
- arXiv ID: 2305.07378
- Source URL: https://arxiv.org/abs/2305.07378
- Reference count: 30
- Primary result: Contrastive Input Decoding (CID) reveals context-specific biases in LLMs by modifying token distributions based on input perturbations

## Executive Summary
This paper introduces Contrastive Input Decoding (CID), a method for surfacing biases in large language models by generating text that is likely given one input but unlikely given a perturbed "contrastive" version of it. The method uses a hyperparameter λ to control the degree of contrasting during decoding. CID is applied to audit LMs for fairness properties and quantify sensitivity to different input perturbations. The approach reveals biases that are difficult to detect with standard decoding strategies and provides a quantitative measure of perturbation effects.

## Method Summary
CID works by modifying the next-token distribution during decoding based on a contrastive input. Given an original input and a perturbed contrastive input, the method generates text that maximizes the probability under the original input while minimizing it under the contrastive input. The hyperparameter λ controls the trade-off between these two objectives. For bias auditing, specific perturbations like name changes (e.g., male vs female names, different racial names) serve as contrastive inputs to reveal differential model behavior across demographic groups.

## Key Results
- CID reveals context-specific biases that standard decoding strategies miss
- GPT-2 shows more gender/racial bias than T5 when perturbed with name changes
- The minority group is more affected by bias in both models
- T5 shows greater sensitivity to syntactic perturbations (spelling mistakes) than semantic ones (irrelevant information)
- λ values provide quantitative measure of perturbation sensitivity

## Why This Works (Mechanism)
CID works by exploiting the difference in token probabilities between an original input and its perturbed contrastive counterpart. By forcing the model to generate text that is probable under one input but improbable under another, CID surfaces the model's differential treatment of similar but distinct contexts. The λ parameter acts as a knob to control how strongly the model should contrast against the perturbed input, allowing fine-grained exploration of bias sensitivity.

## Foundational Learning
- **Contrastive learning**: Why needed - provides a framework for comparing model behavior across similar inputs; Quick check - can be validated by observing symmetric behavior when swapping contrastive inputs
- **Next-token probability distributions**: Why needed - forms the basis for text generation and bias quantification; Quick check - should sum to 1 and reflect semantic plausibility
- **Perturbation sensitivity**: Why needed - quantifies how model outputs change with input modifications; Quick check - should be measurable and reproducible across multiple runs
- **Bias quantification metrics**: Why needed - enables systematic comparison of model fairness; Quick check - should correlate with human judgments of biased outputs

## Architecture Onboarding

Component map: Input text -> Perturbation generator -> CID decoder (with λ) -> Output text

Critical path: The perturbation generator creates contrastive inputs that are semantically similar but differ in protected attributes (e.g., names indicating gender/race). These contrastive inputs are fed into the CID decoder along with the original input. The decoder uses λ to balance between maximizing likelihood under the original input and minimizing it under the contrastive input, producing outputs that reveal bias patterns.

Design tradeoffs: Higher λ values increase contrast but may produce less coherent text; lower λ values maintain coherence but may miss subtle biases. The choice of perturbation type (syntactic vs semantic) affects which biases are revealed and which models show greater sensitivity.

Failure signatures: If λ is too high, outputs may become incoherent or unrelated to the original prompt. If perturbations are too dissimilar from the original input, the contrastive signal weakens. If the model has been extensively debiased, CID may fail to reveal meaningful differences.

First experiments:
1. Test with simple gender-swapped names on gender-neutral prompts to verify basic functionality
2. Vary λ from 0.0 to 1.0 on the same perturbation to observe sensitivity
3. Apply CID to both biased and debiased versions of the same model to confirm it detects differential behavior

## Limitations
- Effectiveness heavily depends on the choice of contrastive perturbation
- Limited cross-model validation beyond GPT-2 and T5 comparison
- Lacks systematic exploration of optimal λ values for different bias types
- Requires access to model internals, limiting applicability to closed models

## Confidence
- High: CID as a general framework for bias auditing is valid and technically sound
- Medium: Specific claims about GPT-2 being more biased than T5 for gender/racial names are supported but need broader validation
- Medium: Quantitative claims about perturbation sensitivity (λ values) are methodologically reasonable but lack statistical significance testing

## Next Checks
1. Compare CID's bias detection performance against established baseline methods (e.g., conditional probability ratios, prompting with "bias check" questions) on the same datasets
2. Conduct cross-model evaluation with at least 5 different LMs of varying sizes and architectures to assess generalizability of bias detection patterns
3. Perform ablation studies systematically varying λ across a wider range (0.0 to 1.0) and different perturbation types to establish optimal parameter settings for different bias categories
