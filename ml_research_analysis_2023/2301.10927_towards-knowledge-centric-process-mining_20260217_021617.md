# Towards Knowledge-Centric Process Mining

## Quick Facts
- arXiv ID: 2301.10927
- Source URL: https://arxiv.org/abs/2301.10927
- Reference count: 30
- Key outcome: Improves process mining metrics (fitness, precision, F-score) by integrating knowledge graphs with event logs.

## Executive Summary
This paper introduces a knowledge-centric approach to process mining that leverages knowledge graphs to address challenges with noisy, incomplete, or imperfect event logs. The method integrates domain knowledge through rule-based reasoning, context-aware analysis, and temporal knowledge graph completion to improve process discovery outcomes. Applied to a sepsis event log, the approach demonstrates significant improvements in process mining metrics, suggesting that knowledge integration can enhance the utility and reliability of process mining results in domains with complex, unstructured data.

## Method Summary
The method combines three knowledge-centric techniques: (1) constraint-based filtering using closed-path rules mined from knowledge graphs to remove infeasible behavior from dependency graphs, (2) context-aware process variant classification using embedding-based link prediction on annotated traces, and (3) event log augmentation through temporal knowledge graph completion to infer missing events. These techniques work together to address semantic incompleteness, filter noise, and enrich event logs with domain knowledge, ultimately improving process mining metrics.

## Key Results
- Fitness improved from 0.794 to 0.903
- Precision improved from 0.573 to 0.671
- F-score increased from 0.665 to 0.769

- Core assumption: The knowledge graph contains sufficient domain rules to encode valid process behavior constraints.

- Core assumption: Contextual information is available and meaningfully correlates with process variants.

### Mechanism 3
- Claim: Temporal knowledge graphs complete missing events in event logs through box embedding-based prediction.

- Core assumption: Temporal patterns in the event log are sufficiently captured by the knowledge graph to enable accurate prediction of missing events.

## Architecture Onboarding

- Component map:
  - Knowledge graph construction module (domain rules, contextual data)
  - Rule mining component (AMIE+ for closed-path rules)
  - Dependency graph mining with constraint filtering
  - Event log augmentation component (context annotation)
  - Variant classification module (embedding-based link prediction)
  - Event completion module (temporal KG completion with box embeddings)
  - Conformance checking evaluator (fitness, precision, F-score)
- Critical path:
  - Input event log → Knowledge graph integration → Rule mining → Dependency graph filtering → Context annotation → Variant classification → Event completion → Output augmented log and models
- Design tradeoffs:
  - Rule mining vs. manual rule specification: Automated mining is scalable but may produce noisy rules; manual rules are precise but labor-intensive.
  - Embedding dimensionality vs. computational cost: Higher dimensions may capture more nuance but increase training time.
  - Completeness of knowledge graph vs. utility: More complete KGs enable better filtering and completion but require more effort to construct.
- Failure signatures:
  - Low fitness/precision after augmentation: Indicates filtering or completion is removing or adding incorrect behavior.
  - Variant classification accuracy near baseline: Suggests contextual attributes are not predictive.
  - Slow rule mining or embedding training: May indicate scalability issues with large KGs or logs.
- First 3 experiments:
  1. Apply rule-based filtering on a small synthetic event log with known infeasible traces; verify removal.
  2. Augment a simple event log with synthetic contextual attributes; train variant classifier and evaluate accuracy.
  3. Use a small temporal KG to predict missing events in a controlled trace; measure precision of predictions.
