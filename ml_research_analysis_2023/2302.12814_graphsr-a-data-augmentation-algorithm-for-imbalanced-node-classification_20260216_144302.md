# GraphSR: A Data Augmentation Algorithm for Imbalanced Node Classification

## Quick Facts
- arXiv ID: 2302.12814
- Source URL: https://arxiv.org/abs/2302.12814
- Reference count: 29
- Primary result: GraphSR outperforms state-of-the-art baselines on Cora, CiteSeer, and PubMed across metrics with different imbalance ratios and GNN backbones

## Executive Summary
GraphSR addresses the challenge of class-imbalance in semi-supervised node classification by augmenting minority classes with informative unlabelled nodes. The method employs a two-step selection process: a similarity-based module filters nodes close to minority class centers, followed by an RL-based module that adaptively selects reliable samples to optimize classifier performance. GraphSR dynamically determines the over-sampling scale for each minority class, demonstrating superior performance compared to fixed-ratio over-sampling approaches.

## Method Summary
GraphSR introduces a data augmentation algorithm for imbalanced node classification that leverages both labeled and unlabeled data. The method consists of two key modules: a similarity-based module that identifies unlabelled nodes similar to minority class centers, and an RL-based module that adaptively selects the most informative samples for augmentation. This approach dynamically determines the appropriate over-sampling scale for each minority class, optimizing the augmented dataset to improve classifier performance while avoiding overfitting.

## Key Results
- GraphSR outperforms state-of-the-art baselines on Cora, CiteSeer, and PubMed datasets
- Demonstrates consistent improvements across multiple metrics (ACC, F1, AUC-ROC)
- Shows effectiveness with different imbalance ratios and GNN backbones (GCN, GraphSAGE, GAT)
- RL-based module enables better generalization compared to fixed-ratio over-sampling

## Why This Works (Mechanism)
GraphSR's effectiveness stems from its intelligent selection of unlabelled nodes for augmentation. The similarity-based module ensures that selected nodes are structurally similar to minority class centers, preserving class characteristics. The RL-based module then optimizes the selection process by learning which nodes will most improve classifier performance, rather than using a fixed ratio. This adaptive approach prevents overfitting and ensures that the augmented dataset maintains quality while addressing class imbalance.

## Architecture Onboarding

Component map:
Input graph and labels -> Similarity-based module -> Filtered candidate nodes -> RL-based module -> Augmented dataset -> Classifier training

Critical path:
Input graph and labels -> Similarity-based module -> Filtered candidate nodes -> RL-based module -> Augmented dataset

Design tradeoffs:
- Two-step selection vs. single-step approach: Provides more control but increases complexity
- Adaptive sampling vs. fixed ratio: Better performance but requires RL training overhead
- Dynamic scale determination vs. pre-defined ratios: More flexible but harder to tune

Failure signatures:
- Poor minority class performance despite augmentation indicates similarity module issues
- Overfitting on augmented data suggests RL module selecting too aggressively
- Computational bottlenecks during RL training phase
