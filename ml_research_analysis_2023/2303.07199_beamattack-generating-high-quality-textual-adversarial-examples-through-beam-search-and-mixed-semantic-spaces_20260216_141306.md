# BeamAttack: Generating High-quality Textual Adversarial Examples through Beam Search and Mixed Semantic Spaces

## Quick Facts
- arXiv ID: 2303.07199
- Source URL: https://arxiv.org/abs/2303.07199
- Reference count: 26
- Primary result: BeamAttack achieves higher attack success rates while maintaining semantic similarity and reducing model queries compared to baselines.

## Executive Summary
BeamAttack is a black-box adversarial attack algorithm designed for generating high-quality textual adversarial examples. The method combines mixed semantic spaces by searching synonyms from both word embedding spaces and pre-trained language models like BERT, along with an improved beam search to expand the search space and reduce word over-substitution. Experiments on five datasets demonstrate that BeamAttack achieves superior attack success rates while maintaining semantic similarity and reducing the number of model queries compared to baselines. The adversarial examples crafted by BeamAttack are highly transferable and can improve model robustness during adversarial training.

## Method Summary
BeamAttack operates in a black-box setting where only class label probabilities are available. The algorithm first calculates word importance scores by replacing words with [oov] and observing prediction changes. It then generates candidate substitutions from mixed semantic spaces (word embedding and BERT), filters them based on POS tags and semantic similarity threshold, and uses an improved beam search with K=10 to explore multiple substitution paths simultaneously. The improved beam search merges outputs from consecutive iterations to prevent word over-substitution and find optimal combinations with minimal changes.

## Key Results
- Achieves higher attack success rates across five datasets (MR, IMDB, SST-2, SNLI, MultiNLI) compared to baselines
- Maintains high semantic similarity (SIM) while reducing word substitution rate (WSR)
- Reduces model queries compared to other attack algorithms
- Generates adversarial examples with high transferability across different model architectures (CNN, LSTM, BERT)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: BeamAttack achieves higher attack success rate by expanding the search space through mixed semantic spaces and improved beam search.
- Mechanism: The algorithm searches synonyms from both word embedding spaces (e.g., WordNet, counter-fitting vectors) and pre-trained language models (BERT). By combining these sources, it increases the diversity of candidate substitutions. The improved beam search then explores multiple substitution paths simultaneously rather than greedily choosing the single best option at each step.
- Core assumption: A larger and more diverse search space will contain better adversarial examples that are both effective at fooling the model and maintain semantic similarity to the original text.

### Mechanism 2
- Claim: BeamAttack reduces word over-substitution while maintaining high attack success rates.
- Mechanism: The improved beam search merges the output of the last iteration with the current iteration, selecting top K adversarial examples jointly. This approach prevents the algorithm from repeatedly substituting the same words and allows exploration of different substitution combinations that may achieve the attack goal with fewer changes.
- Core assumption: Word over-substitution occurs when greedy search repeatedly modifies the same words; by exploring multiple paths, the algorithm can find solutions with minimal necessary changes.

## Architecture Onboarding

- Component map:
  Input preprocessing: Word importance calculation using [oov] replacement
  Candidate generation: Mixed semantic spaces (word embedding + BERT)
  Filtering: POS filtering and semantic similarity threshold
  Search algorithm: Improved beam search with K=10
  Output: Adversarial example or failure notification

- Critical path: Importance calculation → Candidate generation → Filtering → Beam search → Output
  The most time-consuming steps are candidate generation (especially BERT predictions) and beam search iterations.

- Design tradeoffs:
  - Beam size K vs. query efficiency: Larger K increases success rate but also increases model queries and computation time
  - Semantic similarity threshold L vs. attack success: Higher thresholds maintain quality but may reduce success rate
  - Number of candidates N per word vs. diversity: More candidates provide better options but increase processing time

- Failure signatures:
  - Low attack success rate despite high-quality candidates: Beam search parameters may be too restrictive
  - Poor semantic similarity in generated examples: Threshold L may be too low or filtering insufficient
  - Excessive model queries: Beam size K may be too large for the problem complexity

- First 3 experiments:
  1. Run BeamAttack with K=1 (equivalent to greedy search) on a small dataset to establish baseline performance
  2. Test different beam sizes (K=5, K=10, K=20) on the same dataset to find optimal balance between success rate and efficiency
  3. Compare semantic similarity scores when using only word embedding space vs. only BERT vs. mixed semantic spaces to validate the mixed approach

**Medium Confidence**: The claim that BeamAttack achieves higher attack success rates while maintaining semantic similarity is supported by experimental results, but the lack of detailed hyperparameter specifications and ablation studies creates uncertainty about which specific design choices drive these improvements.
