# Agent-based Collaborative Random Search for Hyper-parameter Tuning and Global Function Optimization

## Quick Facts
- arXiv ID: 2303.03394
- Source URL: https://arxiv.org/abs/2303.03394
- Reference count: 34
- Key outcome: Agent-based method outperforms random and Latin hypercube search in hyperparameter tuning and function optimization, especially with limited resources and high dimensions

## Executive Summary
This paper introduces an agent-based collaborative random search method for hyperparameter optimization and global function optimization. The approach uses a hierarchical agent architecture to distribute search operations across different dimensions, employing adaptive width-based random sampling for locating optima. Empirical results demonstrate superior performance compared to standard random search and Latin hypercube search, particularly in high-dimensional spaces and with limited computational resources.

## Method Summary
The method forms a hierarchical agent-based architecture where agents are organized in a tree structure. Each internal agent recursively splits its objective hyper-parameter set into disjoint subsets and assigns each subset to subordinate agents. Terminal agents perform adaptive width-based random sampling in their assigned single dimension while fixing subsidiary hyper-parameters according to parent agent decisions. Results are aggregated upward through the hierarchy, with the root agent using this information to provide feedback coordinates for the next iteration. The system iteratively refines the search until convergence or budget exhaustion.

## Key Results
- Agent-based method achieves significant performance improvements over standard random search and Latin hypercube search
- Notable gains observed in higher dimensions and when computational resources are limited
- Cooperative searching procedure based on adaptive width-based random sampling effectively locates optima
- Hierarchical architecture enables efficient distribution of searching operations across different dimensions

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Hierarchical agent structure improves exploration efficiency by partitioning search space along hyper-parameter dimensions
- Mechanism: Each internal agent recursively splits its objective hyper-parameter set into disjoint subsets, assigning each subset to a subordinate agent. Terminal agents then explore their single assigned dimension using adaptive width-based sampling while subsidiary hyper-parameters are fixed by parent agents.
- Core assumption: Decomposing the optimization problem into smaller subproblems reduces redundant exploration and improves parallel efficiency

### Mechanism 2
- Claim: Adaptive width-based sampling enables targeted exploration around promising regions
- Mechanism: Terminal agents use slot-based uniform sampling where the width parameter E controls exploration radius around the starting coordinate. E is updated adaptively based on whether the current best candidate matches the previous iteration's best.
- Evidence anchors:
  - [abstract] "employs a cooperative searching procedure based on an adaptive width-based random sampling technique to locate the optima"
  - [section 2.2.2] "The slot width parameter set E is used to control the exploration behavior of the agent around the starting coordinates in the search space"

- Break condition: If the loss landscape is highly multimodal with distant peaks, the adaptive width might get stuck in local optima

### Mechanism 3
- Claim: Inter-agent collaboration through result aggregation improves convergence speed
- Mechanism: Terminal agents find local optima and send results upward through the hierarchy. Internal agents aggregate results from subordinates and propagate combined results upward. The root agent uses this aggregated information to provide feedback coordinates for the next iteration.
- Evidence anchors:
  - [abstract] "employs a cooperative searching procedure"
  - [section 2.2.2] "As soon as a local optimum is found by a terminal agent, it will be sent up to the parent agent"
  - [section 2.2.2] "Having waited for the results to be collected from all of its subordinates, the parent aggregates them together and passes the combined result to its own parent"
- Break condition: If communication overhead becomes significant relative to computation time, or if agent synchronization introduces delays

## Architecture Onboarding

- Component map: Root agent -> Internal agents -> Terminal agents
- Critical path: User query → Root agent formation → Hierarchical structure building → Iterative tuning cycles → Result aggregation → Final report
- Design tradeoffs:
  - Depth vs. width: Deeper hierarchies reduce parallel evaluation but improve search space coverage
  - Exploration vs. exploitation: Width parameter E controls this balance but requires problem-specific tuning
  - Communication overhead vs. aggregation quality: More frequent result sharing improves guidance but increases latency
- Failure signatures:
  - Slow convergence: May indicate poor choice of initial width parameter E or insufficient exploration
  - Degraded performance vs. baseline: Could result from ineffective decomposition strategy or poor coordination
  - High resource utilization without improvement: Suggests inefficient agent allocation or communication bottlenecks
- First 3 experiments:
  1. Implement the hierarchical structure formation with c=2 and test on a simple 2D optimization problem
  2. Add adaptive width-based sampling to terminal agents and compare exploration behavior with fixed-width sampling
  3. Implement result aggregation and feedback mechanisms, then run a complete tuning cycle on a 3-hyperparameter ML problem
