# Angel-PTM: A Scalable and Economical Large-scale Pre-training System in Tencent

## Executive Summary
Angel-PTM is a deep learning system designed to address the challenges of efficient large-scale pre-training and fine-tuning of Transformer models. It introduces a Page-based memory organization and unified scheduling method to manage model states at a fine-grained level, reducing memory fragmentation and improving bandwidth utilization. The system also supports extreme model scaling through SSD storage and a lock-free updating mechanism. Experimental results demonstrate significant performance improvements over existing systems, with strong scalability demonstrated on hundreds of GPUs.

## Method Summary
Angel-PTM implements fine-grained memory management using a Page abstraction, where memory is divided into fixed-size pages (4MB) to reduce fragmentation. The unified scheduler coordinates computations, data movements, and communications by analyzing tensor lifetime information. The system supports hierarchical memory management across GPU, CPU, and SSD storage, and implements a lock-free updating mechanism to improve GPU utilization during extreme-scale training.

## Key Results
- Achieves up to 114.8% improvement in maximum model scale compared to existing systems
- Demonstrates up to 88.9% improvement in training throughput
- Successfully scales to train GPT3-175B and T5-MoE-1.2T models on hundreds of GPUs

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Page-based memory organization reduces memory fragmentation and improves memory usage efficiency during large-scale Transformer training.
- Mechanism: By dividing memory into fixed-size pages (4MB) and managing tensor allocations at the page level, Angel-PTM ensures that memory is allocated and released in consistent chunks, minimizing fragmentation caused by irregular tensor sizes.
- Core assumption: Most model state tensors are larger than the chosen page size, allowing efficient packing of tensors into pages.

### Mechanism 2
- Claim: Unified scheduling method maximizes bandwidth utilization by overlapping communication and computation operations.
- Mechanism: By analyzing tensor lifetime information (first and last access times within an iteration), the scheduler dynamically arranges data movements, computations, and communications to overlap where possible, reducing idle time and improving throughput.
- Core assumption: Tensor access patterns are predictable within each training iteration, allowing effective scheduling.
- Evidence anchors:
  - [abstract] "a unified scheduling method that coordinate the computations, data movements, and communications"
  - [section] "The Unified Scheduler is the crucial component in Angel-PTM, responsible for coordinating the activities of other components"

### Mechanism 3
- Claim: Lock-Free Updating Mechanism decouples GPU computation from CPU optimizer operations, improving GPU utilization and overall training efficiency.
- Mechanism: By using auxiliary buffers in CPU memory to store parameters and gradients, and employing a buffering thread to manage these buffers, Angel-PTM allows GPUs to continue computation without waiting for CPU optimizer updates, reducing synchronization overhead.
- Core assumption: Deep learning model training can tolerate staleness in parameters due to the lock-free mechanism without significantly impacting model quality.

- Break condition: If the staleness introduced by the lock-free mechanism significantly degrades model quality or convergence.

## Architecture Onboarding

- Component map: Tracer → Unified Scheduler → Allocator/Executor/Communicator
- Critical path: Tracer → Unified Scheduler → Allocator/Executor/Communicator during each training iteration
- Design tradeoffs:
  - Fine-grained memory management vs. overhead: Page abstraction reduces fragmentation but adds management overhead
  - Static vs. dynamic partitioning: Angel-PTM uses dynamic memory management for flexibility but requires more complex coordination
  - Lock-free updates vs. staleness: Improves GPU utilization but introduces potential staleness in parameters
- Failure signatures:
  - Out-of-memory errors: Indicate insufficient memory management or incorrect scheduling
  - Degraded throughput: May result from poor overlapping of communication and computation
  - Model quality issues: Could be caused by excessive staleness from lock-free updates
- First 3 experiments:
  1. Single-GPU training: Verify basic functionality and performance with a small model to ensure correct implementation of core components
  2. Multi-GPU training without hierarchical memory: Test data parallelism and parameter sharding to validate distributed training capabilities
