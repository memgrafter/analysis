# ADAPT: Action-aware Driving Caption Transformer

## Quick Facts
- arXiv ID: 2302.00673
- Source URL: https://arxiv.org/abs/2302.00673
- Reference count: 40
- Primary result: State-of-the-art performance on BDD-X dataset with 31.7 CIDEr improvement for action narration and 33.1 for reasoning

## Executive Summary
This paper introduces ADAPT, an end-to-end transformer-based framework for generating action narration and reasoning in self-driving vehicles. The framework uniquely combines driving caption generation with vehicular control prediction through a shared video representation, enabling both descriptive and reasoning capabilities. Experiments on the BDD-X dataset demonstrate significant improvements over existing methods, particularly in CIDEr metrics for both action narration and reasoning tasks.

## Method Summary
ADAPT employs a transformer-based architecture that jointly trains driving caption generation and vehicular control prediction tasks. The framework processes video input through a shared representation that captures both visual and temporal information, then uses separate but connected modules to generate action descriptions and predict control signals. The action-aware component helps the model focus on relevant driving actions while maintaining context for reasoning about driving decisions.

## Key Results
- 31.7 CIDEr score improvement for action narration over previous state-of-the-art
- 33.1 CIDEr score improvement for reasoning capabilities
- Strong performance in control signal prediction tasks alongside captioning

## Why This Works (Mechanism)
The framework's effectiveness stems from its joint training approach that leverages shared video representations for both captioning and control prediction. By training these tasks together, the model develops a more comprehensive understanding of driving scenarios that captures both what actions are occurring and why they're necessary. The transformer architecture enables effective handling of temporal dependencies in driving videos while the action-aware module helps filter irrelevant information.

## Architecture Onboarding

Component Map: Video Encoder -> Action-aware Module -> Shared Representation -> Caption Decoder + Control Predictor

Critical Path: Input video → Video Encoder → Shared Representation → Separate Task Heads (Caption + Control)

Design Tradeoffs: Joint training improves overall performance but increases computational complexity; action-aware module adds specificity but requires additional supervision.

Failure Signatures: Poor captioning when control signals are ambiguous; control prediction errors when visual context is insufficient.
