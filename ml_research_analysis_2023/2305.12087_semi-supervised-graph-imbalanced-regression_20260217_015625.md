# Semi-Supervised Graph Imbalanced Regression

## Quick Facts
- arXiv ID: 2305.12087
- Source URL: https://arxiv.org/abs/2305.12087
- Authors: 
- Reference count: 40
- Key outcome: SGIR significantly reduces prediction error in graph regression on imbalanced data, especially in under-represented label areas

## Executive Summary
This paper tackles the challenge of graph regression on imbalanced data, where certain label values are rare and difficult to obtain. The authors propose SGIR, a semi-supervised framework that progressively balances training data to reduce model bias. SGIR employs three key components: (1) confidently predicted labels with a novel regression confidence measurement, (2) reverse sampling to select more pseudo-labels for under-represented labels, and (3) a label-anchored mixup algorithm to augment graph examples in latent space. Experiments on seven graph regression tasks demonstrate that SGIR significantly reduces prediction error, especially in under-represented label areas, outperforming other semi-supervised learning and imbalanced regression methods.

## Method Summary
SGIR is a self-training framework that iteratively improves graph regression models on imbalanced labeled data by leveraging large unlabeled datasets. The method trains an initial model on limited labeled data, generates pseudo-labels for unlabeled graphs with confidence scores, applies reverse sampling to balance label distribution, and augments remaining under-represented labels via label-anchored mixup. This balanced dataset is then used to retrain the model, repeating the process until convergence. The framework uses GIN for graph encoding and MLP for label prediction, with confidence measured through a novel GRation approach based on rationale-environment subgraphs.

## Key Results
- SGIR significantly reduces MAE and geometric mean error across entire label space
- Performance improvements are most pronounced in few-shot regions (under-represented labels)
- Outperforms existing semi-supervised learning and imbalanced regression methods on seven graph regression benchmarks

## Why This Works (Mechanism)

### Mechanism 1
Iterative self-training progressively reduces model bias by improving training data quality and balance. SGIR starts with an imbalanced labeled dataset and unlabeled graphs. In each iteration, it uses a regression model to generate pseudo-labels for unlabeled data, selects high-confidence predictions, applies reverse sampling to balance label distribution, and augments remaining under-represented labels via label-anchored mixup. The newly balanced dataset is then used to retrain the model, which produces better predictions in the next iteration.

### Mechanism 2
Reverse sampling selectively augments under-represented label ranges to balance the training distribution. After generating confident pseudo-labels, SGIR applies reverse sampling to select more examples from under-represented label ranges. The sampling rate for each interval is inversely proportional to its frequency in the original labeled data, ensuring more pseudo-labels are added where data is scarce.

### Mechanism 3
Label-anchored mixup augments graph representations for remaining under-represented labels to achieve perfect balance. SGIR creates virtual data points anchored at target label values and mixes them with real graph representations in latent space. This generates augmented examples for label ranges still lacking data after pseudo-labeling and reverse sampling, effectively filling gaps in the label distribution.

## Architecture Onboarding

- Component map:
  GNN encoder (graph → representation) -> MLP decoder (representation → label prediction) -> Confidence measurement module (variance-based regression confidence) -> Reverse sampling module (frequency-based selection) -> Label-anchored mixup module (latent space augmentation) -> Iterative training loop (self-training framework)

- Critical path:
  1. Train initial model on Gimb
  2. Generate pseudo-labels for Gunlbl with confidence scores
  3. Apply reverse sampling to select Gconf
  4. Generate Haug via label-anchored mixup
  5. Train next iteration on Gimb ∪ Gconf ∪ Haug
  6. Repeat until convergence

- Design tradeoffs:
  - Confidence threshold 𝜏: Higher values reduce noise but may discard useful pseudo-labels
  - Number of label intervals 𝐶: More intervals enable finer-grained balance but increase complexity
  - Mixup weight 𝜆: Closer to 1 preserves target label anchors but may reduce diversity

- Failure signatures:
  - Stagnant validation performance across iterations
  - Increasing prediction variance in pseudo-labels
  - Label distribution remains imbalanced after multiple iterations
  - Augmented examples degrade model performance

- First 3 experiments:
  1. Verify confidence measurement works by comparing GRation against simple regression confidence methods
  2. Test reverse sampling effectiveness by measuring label distribution balance before/after
  3. Validate label-anchored mixup by checking if augmented examples improve predictions in under-represented ranges

## Open Questions the Paper Calls Out

### Open Question 1
How does the label-anchored mixup algorithm handle the case when the unlabeled graph dataset lacks sufficient diversity in the label ranges targeted for augmentation? The paper mentions that even with hundreds of thousands of unlabeled graphs, the label distribution of quality examples may still be biased, and the augmented examples might not achieve a perfect balance.

### Open Question 2
How does the choice of the hyperparameter 𝛽 in the Beta distribution for the mixup weight λ affect the performance of the label-anchored mixup algorithm? The paper mentions that λ is often closer to 1 because we want the augmented label to be closer to the label anchor, but it does not provide a detailed analysis of how the choice of 𝛽 affects the performance.

### Open Question 3
How does the SGIR framework perform when the labeled dataset is extremely imbalanced, with some label ranges having only a handful of examples? The paper mentions that SGIR aims to improve performance in the few-shot region, but it does not provide a detailed analysis of its performance in extremely imbalanced scenarios.

## Limitations
- Confidence threshold 𝜏pct is not explicitly specified, leaving a critical hyperparameter undefined
- The label-anchored mixup mechanism lacks ablation studies to isolate its contribution from other components
- Reverse sampling approach assumes sufficient diversity in unlabeled data, which may not hold in all domains
