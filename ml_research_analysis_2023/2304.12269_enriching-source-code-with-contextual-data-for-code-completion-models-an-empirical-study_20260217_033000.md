# Enriching Source Code with Contextual Data for Code Completion Models: An Empirical Study

## Quick Facts
- **arXiv ID**: 2304.12269
- **Source URL**: https://arxiv.org/abs/2304.12269
- **Reference count**: 40
- **Primary result**: Removing type annotations and adding multi-line comments can improve code completion model performance

## Executive Summary
This study investigates how contextual information in source code—specifically type annotations and comments—affects the performance of large-scale pre-trained models for code completion. The authors conduct controlled experiments using three models (UniXcoder, CodeGPT, and InCoder) on TypeScript code with varying levels of contextual information. The experiments evaluate both token-level and line-level completion tasks using multiple metrics including Exact Match, Edit Similarity, BLEU-4, ROUGE-L, and METEOR.

The findings reveal that all models perform better on untyped code compared to type-annotated code, while multi-line comments consistently enhance performance across all models. However, the effect sizes are small, suggesting that while statistically significant, the practical impact may be limited. The study recommends considering these factors when selecting models for code completion tasks and highlights the need for better evaluations and multi-modal techniques in future research.

## Method Summary
The authors conducted empirical experiments on TypeScript code using three pre-trained models: UniXcoder, CodeGPT, and InCoder. They systematically varied the amount of type annotations and comments in the code samples to assess their impact on code completion performance. The experiments covered two completion tasks: token completion and line completion. For evaluation, they used multiple metrics including Exact Match (EM), Edit Similarity (ES), BLEU-4, ROUGE-L, and METEOR to provide a comprehensive assessment of model performance across different dimensions of code completion quality.

## Key Results
- All models showed better performance on untyped code compared to type-annotated code
- Multi-line comments consistently improved performance across all models
- Effect sizes were small across all experiments despite statistical significance

## Why This Works (Mechanism)
The mechanism behind these results relates to how contextual information affects the model's ability to predict subsequent code. Type annotations add syntactic constraints that may introduce ambiguity or complexity that models struggle to resolve during completion. Multi-line comments provide semantic context that helps models understand the programmer's intent without the syntactic overhead of type declarations. This suggests that models benefit more from semantic guidance than from syntactic constraints when generating code completions.

## Foundational Learning
- **Contextual embeddings**: These represent how models incorporate surrounding code context into token representations, essential for understanding how different types of context affect predictions
- **Code completion metrics**: Understanding various evaluation metrics (EM, ES, BLEU-4, ROUGE-L, METEOR) is crucial for interpreting model performance and comparing results across studies
- **Multi-modal learning**: The study hints at the importance of integrating different types of information (code and natural language comments), which is fundamental for modern AI systems
- **Type systems in programming languages**: Knowledge of how type annotations work in TypeScript helps understand why they might impact model performance
- **Pre-trained language models**: Understanding the architecture and training of models like UniXcoder, CodeGPT, and InCoder is necessary to contextualize the results
- **Token vs. line completion**: Recognizing the difference between predicting individual tokens versus entire lines helps interpret the varying results across task types

## Architecture Onboarding
- **Component map**: Input code -> Context processor (adds/removes types and comments) -> Pre-trained model (UniXcoder/CodeGPT/InCoder) -> Output predictions -> Evaluation metrics (EM, ES, BLEU-4, ROUGE-L, METEOR)
- **Critical path**: Code input → Context modification → Model inference → Metric calculation
- **Design tradeoffs**: The study balances controlled experimentation (limiting to TypeScript) with generalizability concerns, choosing comprehensive metric coverage over simplicity
- **Failure signatures**: Poor performance on type-annotated code suggests models struggle with syntactic constraints; multi-line comments help but single-line comments do not
- **First experiments**:
  1. Run baseline experiments on pure TypeScript code without any modifications
  2. Systematically remove type annotations and measure performance changes
  3. Add multi-line comments to untyped code and measure the impact on completion accuracy

## Limitations
- Effect sizes were consistently small, raising questions about practical significance
- Study focuses exclusively on TypeScript, limiting generalizability to other languages
- Only three specific models were tested, which may not represent the full range of code completion approaches

## Confidence
- **High confidence**: Models perform better on untyped versus type-annotated code, and multi-line comments provide consistent benefits
- **Medium confidence**: Practical recommendation to remove type annotations for improved performance
- **Low confidence**: Generalizability of findings to other programming languages or untested model architectures

## Next Checks
1. Replicate experiments across multiple programming languages (Python, Java, C++) to assess language-specific effects
2. Conduct user studies with developers to determine if metric improvements translate to real-world productivity gains
3. Investigate the impact of contextual information on model training versus inference separately to understand long-term behavior differences
