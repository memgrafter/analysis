# Towards preserving word order importance through Forced Invalidation

## Quick Facts
- **arXiv ID:** 2304.05221
- **Source URL:** https://arxiv.org/abs/2304.05221
- **Reference count:** 10
- **Key outcome:** Forced Invalidation (FI) significantly improves language models' sensitivity to word order permutations while maintaining performance on well-ordered data

## Executive Summary
Forced Invalidation (FI) is a simple yet effective approach to improve language models' sensitivity to word order. The method augments training data with {1,2,3}-gram permutations of sentences labeled as invalid, and modifies models to identify these as such. Evaluated on various NLU and QA tasks using BERT and attention-based models, FI demonstrates significant improvements in sensitivity to word order permutations while maintaining performance on well-ordered data. For example, on the DROP QA dataset, FI reduced accuracy on permuted questions from near 100% to around 30-40%, while only slightly impacting original accuracy.

## Method Summary
FI improves word order sensitivity by explicitly training models to classify permuted n-gram sequences as invalid. The approach augments training data with {1,2,3}-gram permutations labeled as "invalid" and modifies the model architecture to include an additional class for invalid sequences. During training, the model learns to distinguish between well-ordered and permuted sequences. The method was evaluated on various NLU tasks including QA, NLI, and grammatical acceptability using BERT-based and attention-based models.

## Key Results
- FI significantly improves sensitivity to word order permutations while maintaining performance on well-ordered data
- On DROP QA dataset, FI reduced accuracy on permuted questions from near 100% to around 30-40%
- FI improved robustness to syntactic heuristics in NLI tasks and generalized to other languages like Arabic

## Why This Works (Mechanism)

### Mechanism 1
- Models rely heavily on first-order word co-occurrence statistics rather than understanding syntactic structure
- By forcing the model to reject invalid permutations, it must learn to use word order information
- Break condition: If n-gram permutations do not sufficiently destroy syntactic information

### Mechanism 2
- FI reduces models' reliance on superficial heuristics by making them explicitly handle invalid input patterns
- Adding an "invalid" class and training on permuted samples forces development of more robust representations
- Break condition: If the model can achieve high accuracy on invalid samples without truly understanding why they're invalid

### Mechanism 3
- FI works across different model architectures and languages because it addresses a fundamental limitation in how language models process word order
- The approach is model-agnostic and can be applied to various architectures
- Break condition: If the approach fails to generalize to architectures significantly different from BERT

## Architecture Onboarding

- **Component map**: Input data (original + permuted) -> Model (BERT/attention-based with invalid class) -> Output (task classification + validity)

- **Critical path**: 1. Generate n-gram permutations from training data 2. Augment training set with permuted samples labeled as invalid 3. Modify model architecture to include invalid class 4. Train model on combined dataset 5. Evaluate on original and permuted validation sets

- **Design tradeoffs**: 
  - Pros: Simple to implement, minimal changes to existing architectures, improves robustness to word order perturbations
  - Cons: Increases training data size by 50%, may require careful tuning of class weights if dataset is imbalanced

- **Failure signatures**: 
  - Model still achieves high accuracy on permuted samples
  - Significant performance degradation on well-ordered data
  - Model predicts all samples as invalid

- **First 3 experiments**: 
  1. Implement FI on a simple BERT classifier for CoLA and verify it correctly flags permuted sentences as invalid
  2. Apply FI to an NLI model and test robustness to syntactic heuristics (HANS dataset)
  3. Extend FI to a different language (e.g., Arabic using ArBERT) to verify cross-lingual applicability

## Open Questions the Paper Calls Out

## Limitations

- Experimental scope is constrained to BERT-based and attention-based models
- Cross-lingual effectiveness demonstrated only for English and Arabic
- Paper doesn't extensively test FI's behavior with very long sequences or highly context-dependent tasks

## Confidence

- **High confidence** in the core mechanism: The approach's theoretical foundation is well-established and consistently effective across multiple NLU tasks
- **Medium confidence** in generalization claims: While results show FI works across BERT and attention-based models, the paper doesn't explore edge cases or fundamentally different architectures
- **Low confidence** in long-tail scenarios: The paper doesn't extensively test FI's behavior with very long sequences, highly context-dependent tasks, or languages with free word order

## Next Checks

1. **Architecture stress test**: Apply FI to non-transformer architectures (RNNs, CNNs) to verify if the invalidation mechanism transfers across fundamentally different model types

2. **Cross-linguistic robustness**: Test FI on languages with flexible word order (e.g., Latin, Russian) to determine if the approach generalizes beyond fixed word order languages

3. **Edge case analysis**: Systematically evaluate FI on extremely long sequences and highly context-dependent tasks to identify potential failure modes at scale
