# Predict NAS Multi-Task by Stacking Ensemble Models using GP-NAS

## Quick Facts
- arXiv ID: 2305.01667
- Source URL: https://arxiv.org/abs/2305.01667
- Reference count: 17
- Key outcome: Achieved 0.7991 Kendall-tau score, ranking 1st in CVPR 2022 Track 2 Challenge for NAS multi-task prediction

## Executive Summary
This paper presents a solution to the CVPR 2022 Track 2 Challenge for predicting neural network architecture performance with limited training data. The approach combines data preprocessing techniques (ordinal encoding, inverse sigmoid transformation) with ensemble stacking using GP-NAS as the final estimator. The method achieved a Kendall-tau score of 0.7991, ranking first in the challenge. The key innovation lies in carefully preprocessing the data to reduce complexity and avoid overfitting, then leveraging the strengths of multiple ensemble models through stacking with GP-NAS to handle the small sample size and multi-task prediction challenges.

## Method Summary
The method involves preprocessing ViT-Base search space data through ordinal encoding of depth features, removing uninformative embed-dim parameters, and applying inverse sigmoid transformation to convert uniform rank distributions to Gaussian distributions. Seven gradient boosting models (GBRT, XGBoost, CATGB, LightGB variants) are trained with task-specific hyperparameters on full training data. These base models are then combined using stacking with GP-NAS as the final estimator, employing K-fold cross-validation to prevent overfitting. The GP-NAS model uses modified covariance matrix calculations and is tuned for optimal performance on each task.

## Key Results
- Achieved 0.7991 Kendall-tau correlation score on the challenge leaderboard
- Ranked first place in CVPR 2022 Track 2 Challenge
- Demonstrated effectiveness of data preprocessing in reducing complexity and avoiding overfitting
- Showed that stacking ensemble models with GP-NAS effectively handles small sample sizes and multi-task prediction

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Preprocessing data with ordinal encoding and inverse sigmoid transformation stabilizes model training on small datasets.
- Mechanism: Ordinal encoding preserves ordinal relationships of depth values, reducing dimensionality and enabling learning of monotonic trends. The inverse sigmoid transformation converts uniform rank labels to Gaussian-distributed targets, better suited for gradient boosting models that assume Gaussian residuals.
- Core assumption: Depth has monotonic correlation with performance, and Gaussian-distributed targets improve model learning efficiency.
- Evidence anchors: [section] "Transfer the depth encoding(j,k,l) to integer...we assume depth has some monotonic correlation with predictability...Ordinal encoding...Using inverse sigmoid function as activation function...By inverse sigmoid function we transfer uniform distribution to Gaussian distribution which is best choice for most model."

### Mechanism 2
- Claim: Stacking multiple ensemble models with GP-NAS as final estimator leverages diverse model strengths and reduces overfitting.
- Mechanism: Each base ensemble model captures different aspects of data's non-linear relationships. Stacking these with GP-NAS combines predictions, benefiting from individual model strengths while GP-NAS's Bayesian approach provides robustness to small sample sizes.
- Core assumption: Different ensemble models capture complementary information, and GP-NAS can effectively combine predictions without overfitting.
- Evidence anchors: [section] "we choose to stack several ensemble models by GP-NAS...Stacking allows us to use the strength of each individual estimator...In order to avoid overfitting, we use full training data set only in sub model training, but training our final model with cross validation."

### Mechanism 3
- Claim: Task-specific hyperparameter tuning improves model performance by adapting to different signal-to-noise ratios and feature distributions.
- Mechanism: Different tasks have varying complexity and noise levels. By tuning hyperparameters (learning rate, loss function, model depth) for each task, the model better captures underlying patterns without overfitting.
- Core assumption: Different tasks have distinct signal-to-noise ratios and feature distributions requiring tailored model configurations.
- Evidence anchors: [section] "Depending on the problem, we should find a different variance and bias trade off to predict well but avoid over fitting...we consider select different loss function, learning rate and depth for different task as we assume different data set and task have different signal noise ratio and different features."

## Architecture Onboarding

- Component map: Data Preprocessing -> Base Models (7 GB variants) -> Stacking Layer (GP-NAS) -> Cross-Validation -> Final Predictions

- Critical path:
  1. Preprocess raw data to reduce complexity and avoid overfitting
  2. Train base ensemble models on full training dataset
  3. Use K-fold cross-validation to generate out-of-fold predictions from base models
  4. Train GP-NAS on out-of-fold predictions to combine model strengths
  5. Post-process GP-NAS predictions to obtain final rank predictions

- Design tradeoffs:
  - Using ordinal encoding vs. one-hot encoding for depth features: Ordinal encoding reduces dimensionality but assumes a monotonic relationship
  - Choosing GP-NAS as final estimator vs. other models: GP-NAS is robust to small sample sizes but may be computationally intensive
  - Task-specific hyperparameter tuning vs. uniform parameters: Tuning improves performance but increases complexity and risk of overfitting

- Failure signatures:
  - Poor Kendall-tau scores indicating model not accurately predicting architecture performance
  - Overfitting indicated by high training performance but low validation performance
  - Instability in predictions across different folds in cross-validation

- First 3 experiments:
  1. Implement data preprocessing steps (ordinal encoding, inverse sigmoid transformation) and evaluate their impact on model performance
  2. Train individual gradient boosting models and compare their performance to stacked model to validate benefit of stacking
  3. Perform cross-validation during stacking phase and analyze variance in predictions to ensure model not overfitting
