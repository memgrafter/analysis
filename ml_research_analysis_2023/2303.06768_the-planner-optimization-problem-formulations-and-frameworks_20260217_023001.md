# The Planner Optimization Problem: Formulations and Frameworks

## Quick Facts
- arXiv ID: 2303.06768
- Source URL: https://arxiv.org/abs/2303.06768
- Reference count: 40
- Key outcome: Introduces POP formulation and OPOF framework for learning planners' internal parameters conditioned on problem instances, showing performance gains over traditional algorithm configuration approaches

## Executive Summary
This paper introduces the Planner Optimization Problem (POP) formulation and the Open Planner Optimization Framework (OPOF) for learning planners' internal parameters conditioned on problem instances. POP generalizes algorithm configuration by seeking a generator that maps problem instances to high-quality parameters, rather than finding a single set of parameters that works well on average. The OPOF framework provides a software infrastructure to specify and solve POPs, including implementations of the Generator-Critic algorithm and SMAC. Experiments across various domains show that POP methods like Generator-Critic outperform traditional algorithm configuration approaches by leveraging problem instance information, though conditioning can increase training time.

## Method Summary
The POP formulation frames planner optimization as learning a generator that maps problem instances to high-quality parameter configurations. The Open Planner Optimization Framework (OPOF) provides a modular software framework for implementing POP solvers, supporting various domains including motion planning and POMDPs. The framework includes the Generator-Critic algorithm, which uses a critic network to evaluate parameter-generator pairs, and integrates with SMAC for comparative evaluation. The approach leverages instance features to condition parameter selection, enabling more adaptive planner configuration than traditional algorithm configuration methods.

## Key Results
- POP methods like Generator-Critic outperform traditional algorithm configuration approaches by leveraging problem instance information
- Conditioning on problem instances increases training time but improves solution quality across multiple domains
- The framework demonstrates effectiveness in learning conditional parameters for planners across domains including motion planning and POMDPs

## Why This Works (Mechanism)
POP works by conditioning parameter selection on problem instance features, allowing planners to adapt their configuration based on the specific characteristics of each problem. The Generator-Critic algorithm learns a mapping from instance features to parameters by using a critic network to evaluate the quality of parameter-generator pairs. This approach leverages the rich information available in problem instances that traditional algorithm configuration methods ignore, enabling more nuanced and effective parameter selection.

## Foundational Learning
- **Algorithm Configuration**: Traditional method of finding a single parameter set that works well on average; needed as baseline comparison
- **Instance-Based Algorithm Selection**: Selecting algorithms based on problem instance features; needed to understand the generalization from algorithm selection to parameter optimization
- **Conditional Parameter Generation**: Learning mappings from instance features to parameters; needed as the core innovation of POP
- **Critic Networks**: Neural networks that evaluate parameter-generator pairs; needed for the Generator-Critic algorithm's training procedure
- **Motion Planning Domains**: Planning problems involving pathfinding and obstacle avoidance; needed as primary evaluation domain
- **POMDPs**: Partially Observable Markov Decision Processes; needed to demonstrate framework applicability beyond motion planning

## Architecture Onboarding

**Component Map**: Problem Instances -> Instance Features -> Generator Network -> Parameters -> Planner -> Solution Quality -> Critic Network (feedback)

**Critical Path**: The core training loop involves extracting features from problem instances, generating parameters using the generator network, evaluating planner performance with those parameters, and using the critic network to provide feedback for generator updates.

**Design Tradeoffs**: The framework trades off training time for improved solution quality by conditioning on instance features. Discrete parameter spaces are supported, but scalability to continuous or high-dimensional spaces remains an open question.

**Failure Signatures**: Poor performance may result from insufficient instance feature representation, inadequate generator network capacity, or suboptimal critic network training.

## Limitations
- Focuses on discrete parameter spaces, potentially limiting applicability to planners with continuous or high-dimensional parameter spaces
- POMDP domain experiments are more limited compared to motion planning domains
- Trade-off analysis between increased training time and improved solution quality could be more comprehensive

## Confidence

**Confidence Assessment:**
- POP formulation: High - well-grounded theoretical framing with clear generalization from algorithm configuration
- OPOF framework implementation: Medium - demonstrated across multiple domains but long-term maintainability unclear
- Empirical validation (motion planning): High - significant performance gains observed
- Empirical validation (POMDPs): Medium - more limited experimental scope
