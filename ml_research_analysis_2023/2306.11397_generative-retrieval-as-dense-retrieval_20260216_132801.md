# Generative Retrieval as Dense Retrieval

## Quick Facts
- arXiv ID: 2306.11397
- Source URL: https://arxiv.org/abs/2306.11397
- Reference count: 34
- Primary result: Tied-Atomic generative retrieval matches or exceeds previous methods while enabling scaling to millions of documents

## Executive Summary
Generative retrieval models like DSI and NCI struggle with updating document indices and scaling to large collections. This paper reveals that generative retrieval with atomic identifiers can be mathematically decomposed into dense retrieval operations using dot-product scoring between query and document vectors. This insight leads to Tied-Atomic, a new generative retrieval variant that incorporates dense retrieval techniques like tied document embeddings and contrastive training losses. Experiments on NQ320K and full MSMARCO demonstrate Tied-Atomic achieves 38% improvement over DSI Atomic on MRR@10 while enabling efficient scaling to millions of documents.

## Method Summary
The paper proposes Tied-Atomic, which treats generative retrieval as dense retrieval by tying document identifier embeddings to document texts through the encoder-decoder stack. Unlike previous generative retrieval models that use learned document embeddings, Tied-Atomic freezes document embeddings and uses contrastive loss with BM25 negatives for training. This approach enables the model to handle unseen documents and scale to large collections. The model is implemented using a T5-base architecture trained for 120k steps with batch size 32, and for MSMARCO uses mined hard negatives with MarginMSELoss for distillation training.

## Key Results
- Tied-Atomic achieves MRR@10 of 33.42 on MSMARCO, a 38% improvement over DSI Atomic
- Matches or exceeds previous generative retrieval methods on NQ320K and MSMARCO benchmarks
- Enables efficient scaling to millions of documents without retraining for new documents
- Demonstrates that generative retrieval with atomic identifiers is mathematically equivalent to dense retrieval

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Generative retrieval with atomic identifiers can be decomposed into dense retrieval operations via dot products between query and document vectors.
- Mechanism: The decoding process in generative retrieval produces a probability distribution over document identifiers by computing the dot product between the decoder's last hidden state (representing the query) and the embeddings of document identifier tokens. This is mathematically identical to dense retrieval's dot product similarity scoring.
- Core assumption: The generative model's vocabulary embeddings for document identifiers act as document vectors that can be compared to query vectors via dot product.
- Evidence anchors:
  - [abstract] "we analytically demonstrate that the generative retrieval process can be decomposed into dot products between query and document vectors, similar to dense retrieval"
  - [section] "we can see that each generation step can be decomposed into the dot product of two vectors: the last hidden state emitted by the transformer's encoder-decoder stack and the vocabulary embeddings representing document identifiers"
- Break condition: If the document identifier embeddings are not trained to meaningfully represent document semantics, the dot product will not capture true relevance.

### Mechanism 2
- Claim: Tying document identifier embeddings to encoder-decoder outputs enables generalization to unseen documents and scaling to large collections.
- Mechanism: By making document embeddings a deterministic function of document text through the transformer's encoder-decoder stack (rather than learned parameters), new documents can be represented without retraining the entire model. This ties document texts to their vectors like dense retrieval does.
- Core assumption: The encoder-decoder stack can produce meaningful representations for documents not seen during training.
- Evidence anchors:
  - [section] "With these changes, atomic generative models can theoretically insert new documents or scale to large collections as easily as dense retrieval methods"
  - [abstract] "our model can handle unseen documents and scaled up for large collections, as we demonstrate with the full MSMARCO dataset"
- Break condition: If the encoder-decoder stack cannot generalize to document semantics outside the training distribution, tied embeddings will not work for unseen documents.

### Mechanism 3
- Claim: Contrastive training with BM25 negatives improves generative retrieval effectiveness compared to teacher forcing with cross-entropy loss.
- Mechanism: The contrastive loss explicitly pulls positive documents closer to the query vector and pushes negative documents away, similar to dense retrieval training. This creates better query-document vector alignment than teacher forcing which only pushes away all other documents.
- Core assumption: Hard negatives from BM25 are effective for training the generative retrieval model.
- Evidence anchors:
  - [section] "In contrast, atomic generative retrieval uses teacher forcing with a seq-2-seq cross entropy loss, which increases the likelihood of a chosen positive documents (and thus pushes away all other documents)"
  - [section] "The dense retrieval encoder ties document texts and vectors together in a sense, allowing it to generalize to similar and unseen documents"
- Break condition: If BM25 negatives are not truly negative or too easy, the contrastive loss may not provide effective training signals.

## Architecture Onboarding

- Component map:
  - T5 encoder-decoder model (pretrained) -> Document collection preprocessing pipeline -> BM25 negative sampler -> Training loop with contrastive loss -> Inference pipeline with beam search

- Critical path:
  1. Load and preprocess document collection
  2. Initialize Tied-Atomic model with tied embeddings
  3. Sample BM25 negatives for each query
  4. Compute contrastive loss and update model
  5. At inference, generate document identifiers using beam search

- Design tradeoffs:
  - Tying embeddings vs. learned parameters: Tying enables scalability but may limit model expressiveness compared to learned identifier embeddings.
  - Contrastive loss vs. teacher forcing: Contrastive loss is more computationally expensive but provides better training signals.
  - Atomic vs. hierarchical identifiers: Atomic identifiers are simpler but less efficient for very large collections.

- Failure signatures:
  - Low retrieval effectiveness: May indicate poor embedding tying or ineffective negative sampling.
  - Memory issues during training: Could mean too many negatives are being used or model is too large.
  - Slow inference: May indicate inefficient beam search implementation or too large a document collection.

- First 3 experiments:
  1. Train Tied-Atomic on NQ320K with 50k steps and evaluate R@1
  2. Compare Tied-Atomic effectiveness to DSI and dense retrieval baselines on NQ320K
  3. Scale Tied-Atomic to MSMARCO and evaluate MRR@10

## Limitations
- Mathematical equivalence is proven only for atomic identifiers, not hierarchical identifiers
- Limited analysis of performance degradation at different scaling levels
- Missing specific details about contrastive loss implementation and hyperparameters

## Confidence
- High confidence: The core mathematical insight that generative retrieval with atomic identifiers can be viewed as dense retrieval through dot product scoring is well-supported
- Medium confidence: Effectiveness improvements are convincing but lack detailed hyperparameter information and comprehensive baseline comparisons
- Low confidence: Claims about handling unseen documents and arbitrary scaling are theoretically justified but not empirically validated across diverse document types

## Next Checks
