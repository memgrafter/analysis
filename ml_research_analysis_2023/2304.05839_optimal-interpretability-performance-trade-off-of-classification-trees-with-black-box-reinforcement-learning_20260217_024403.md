# Optimal Interpretability-Performance Trade-off of Classification Trees with Black-Box Reinforcement Learning

## Quick Facts
- arXiv ID: 2304.05839
- Source URL: https://arxiv.org/abs/2304.05839
- Reference count: 40
- Key outcome: This paper proposes using Reinforcement Learning (RL) in an Iterative Bounding Markov Decision Process (IBMDP) framework to learn interpretable decision trees, proving that solving a fully observable MDP (Observation-IBMDP) is sufficient to achieve optimal interpretability-performance trade-off, and showing experimental results where their DQN-based approach (DQNDT) learns better trees than previous methods while avoiding excessively large trees.

## Executive Summary
This paper addresses the challenge of learning interpretable decision trees for classification by formulating the problem as a reinforcement learning task in an Iterative Bounding Markov Decision Process (IBMDP). The key insight is that the partially observable nature of the original IBMDP can be eliminated by proving that a fully observable version (Observation-IBMDP) is sufficient to achieve the same optimal interpretability-performance trade-off. The authors implement this using a DQN-based approach (DQNDT) that learns decision trees by gathering information about feature bounds and making predictions, with experiments on UCI datasets demonstrating superior interpretability-performance trade-offs compared to previous asymmetric RL methods like CUSTARD.

## Method Summary
The authors frame decision tree learning as an MDP where states represent feature bounds and actions either gather information or make predictions. They prove that solving a fully observable MDP (Observation-IBMDP) is sufficient to learn optimal interpretability-performance trade-offs, eliminating the need for complex partially observable RL methods. The DQNDT algorithm uses DQN to learn in this Observation-IBMDP, enforcing a maximum tree depth to prevent excessive growth. The method is evaluated on UCI datasets and compared against CUSTARD, showing better interpretability-performance trade-offs with trees of more diverse sizes.

## Key Results
- DQNDT learns decision trees with better interpretability-performance trade-offs than CUSTARD on UCI datasets
- The approach avoids the problem of CUSTARD producing excessively large trees
- DQNDT achieves a wider range of tree sizes (2-8 decision nodes) compared to CUSTARD's tendency toward very small or very large trees
- The theoretical proof shows solving a fully observable MDP is sufficient for optimal trade-offs

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Solving a fully observable MDP (Observation-IBMDP) is sufficient to learn optimal interpretability-performance trade-off for decision trees.
- Mechanism: The paper proves that any optimal policy for the Observation-IBMDP has the same policy return as the optimal policy for the original IBMDP. This means that instead of dealing with the complexity of partially observable RL (POMDP), we can solve a simpler fully observable MDP and still achieve the same interpretability-performance trade-off.
- Core assumption: The base MDP is a supervised classification task where the next state (training sample) is sampled randomly and independently from the last prediction.
- Evidence anchors:
  - [abstract]: "The main contribution of this paper is to prove that it is sufficient to solve a fully observable problem to learn a DT optimizing the interpretability-performance trade-off."
  - [section 5.1]: The proof shows that reactive policies have the same policy return in the IBMDP and the OIBMDP.
  - [corpus]: No direct evidence, but the claim aligns with the general principle that fully observable MDPs can be easier to solve than POMDPs.
- Break condition: If the base MDP is not a supervised classification task where the next state is sampled independently, the proof may not hold.

### Mechanism 2
- Claim: DQNDT avoids learning excessively large trees by enforcing a maximum tree depth.
- Mechanism: The paper proposes learning an Observation-IBMDP with a maximum tree depth Mmax. When the agent observes a state where the current depth is greater than or equal to Mmax, it takes a base action (making a prediction), effectively adding a leaf node to the learned decision tree. This prevents the tree from growing indefinitely.
- Core assumption: A maximum tree depth Mmax is specified and the agent can track the current depth based on the feature bounds.
- Evidence anchors:
  - [section 5.2]: "To avoid this problem, we learn an OIBMDPs with a maximum tree depth Mmax and with p a prime number to leverage Proposition 1."
  - [section 6.2]: The paper specifies Mmax values for different datasets (e.g., Mmax = 4 for Wine).
  - [corpus]: No direct evidence, but this is a common technique in decision tree learning to prevent overfitting.
- Break condition: If the maximum tree depth is set too low, the learned tree may not achieve good performance. If it's set too high, the tree may still become too large.

### Mechanism 3
- Claim: DQNDT outperforms CUSTARD in learning decision trees with better interpretability-performance trade-offs.
- Mechanism: The paper compares DQNDT with CUSTARD on UCI datasets. DQNDT is able to learn trees with a wider range of interpretability-performance trade-offs (i.e., trees with different numbers of decision nodes) compared to CUSTARD, which tends to learn either very small or very large trees. DQNDT also avoids the problem of CUSTARD where it repeats information-gathering actions indefinitely for ζ ≥ 0.6.
- Core assumption: The experiments are conducted fairly and the results are representative.
- Evidence anchors:
  - [section 6.3]: The paper shows plots comparing the interpretability-performance trade-offs of DTs learned using CUSTARD, DQNDT, and CART. It states that "DQNDT is able to return DTs with a wider range of interpretability-performance trade-offs (DTs with 2, 4, 6, 7, 8 decision nodes)."
  - [section 5.3]: The paper mentions that DQNDT outperforms CUSTARD on a simple binary classification benchmark.
  - [corpus]: No direct evidence, but the claim is supported by the experimental results presented in the paper.

## Architecture Onboarding

- Component map:
  - Base MDP: The supervised classification task
  - IBMDP: The MDP augmented with feature bounds and information-gathering actions
  - Observation-IBMDP (OIBMDP): The fully observable MDP derived from the IBMDP
  - DQNDT: The DQN-based algorithm for learning decision trees in the OIBMDP
  - CUSTARD: The asymmetric RL algorithm for learning decision trees in the IBMDP

- Critical path:
  1. Define the base MDP (supervised classification task)
  2. Convert the base MDP to an IBMDP by adding feature bounds and information-gathering actions
  3. Convert the IBMDP to an Observation-IBMDP (fully observable MDP)
  4. Use DQNDT to learn the optimal policy in the Observation-IBMDP
  5. Extract the learned decision tree from the optimal policy

- Design tradeoffs:
  - Maximum tree depth (Mmax): Affects the size and interpretability of the learned tree
  - Cost of information-gathering actions (ζ): Affects the balance between interpretability and performance
  - RL algorithm: DQNDT vs. CUSTARD (DQNDT is simpler and avoids the POMDP complexity)

- Failure signatures:
  - Tree is too large: Mmax is set too high or ζ is set too low
  - Tree is too small: Mmax is set too low or ζ is set too high
  - Poor performance: RL algorithm fails to learn a good policy or the feature representation is inadequate

- First 3 experiments:
  1. Run DQNDT on a simple binary classification task (like the one in Section 4.1) and verify that it learns a better tree than CUSTARD.
  2. Vary the maximum tree depth (Mmax) and observe its effect on the learned tree's size and performance.
  3. Vary the cost of information-gathering actions (ζ) and observe its effect on the interpretability-performance trade-off.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of DQNDT scale with increasing numbers of features and maximum tree depths compared to CUSTARD?
- Basis in paper: [explicit] The paper states that Policy Iteration becomes intractable as the number of features d and Mmax grow, and that Q-learning and SARSA failed on the simple benchmark, motivating the use of DQN.
- Why unresolved: The experiments only tested DQNDT on UCI datasets with relatively small numbers of features (4-16) and small maximum depths (4-5). Scaling to larger problems is left for future work.
- What evidence would resolve it: Systematic experiments comparing DQNDT and CUSTARD on synthetic datasets with increasing d and Mmax, measuring both accuracy and tree size, and analyzing computational complexity.

### Open Question 2
- Question: Can the OIBMDP framework be extended to learn decision trees with multi-feature splits or other complex decision nodes?
- Basis in paper: [explicit] The authors mention that generalizing to "test nodes that also test if a feature value is within closed intervals [v1,v2] or for example could consider combinations of more than one feature" is possible as long as the transition function can be written.
- Why unresolved: The paper only considers simple threshold splits on individual features. The theoretical extension to more complex nodes is suggested but not demonstrated.
- What evidence would resolve it: Implementation and experiments showing DQNDT or a similar algorithm learning optimal trees with multi-feature splits on benchmark datasets, comparing performance to single-feature splits.

### Open Question 3
- Question: Does the IBMDP/OIBMDP framework generalize to reinforcement learning tasks beyond supervised classification?
- Basis in paper: [explicit] The authors state that "provably convergent algorithms for finding an optimal IBMDP policy when the base task is a sequential decision making problem remains an open question" and suggest imitation learning as an intermediate step.
- Why unresolved: The paper focuses entirely on supervised classification tasks. The connection to general RL is theoretical and unexplored.
- What evidence would resolve it: Applying the OIBMDP framework to a standard RL benchmark (e.g., Atari games or continuous control tasks) where the goal is to learn a policy that can be represented as a decision tree, and comparing its performance and interpretability to standard RL methods.

## Limitations
- The theoretical framework assumes the base MDP has random, independent state transitions, which may not hold for all classification problems
- Experiments only compare against one prior method (CUSTARD), limiting generalizability
- The hyperparameter sensitivity (Mmax, ζ) is not thoroughly explored

## Confidence
- Theoretical claims: Medium - The proof that Observation-IBMDP optimality implies IBMDP optimality is well-grounded but relies on specific assumptions about state transitions
- Empirical claims: Medium - Results are promising but limited to small UCI datasets and lack statistical significance testing
- Implementation claims: Medium - The DQNDT approach is described clearly but implementation details are not fully specified
