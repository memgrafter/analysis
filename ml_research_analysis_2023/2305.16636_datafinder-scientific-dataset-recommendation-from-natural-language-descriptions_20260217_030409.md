# DataFinder: Scientific Dataset Recommendation from Natural Language Descriptions

## Quick Facts
- arXiv ID: 2305.16636
- Source URL: https://arxiv.org/abs/2305.16636
- Reference count: 20
- One-line primary result: A neural bi-encoder model trained on the DataFinder Dataset significantly outperforms term-based retrieval and k-nearest-neighbor retrieval methods on dataset recommendation tasks.

## Executive Summary
This paper addresses the challenge of recommending relevant datasets for machine learning research given a natural language description of a research idea. The key insight is that dataset recommendation poses unique challenges as an information retrieval problem, as datasets are hard to directly index for search and there are no corpora readily available for this task. To operationalize this task, the authors build the DataFinder Dataset consisting of a larger automatically-constructed training set (17.5K queries) and a smaller expert-annotated evaluation set (392 queries). They compare various information retrieval algorithms on their test set and present a superior bi-encoder retriever for text-based dataset recommendation. The system, trained on the DataFinder Dataset, finds more relevant search results than existing third-party dataset search engines.

## Method Summary
The authors operationalize dataset recommendation by constructing the DataFinder Dataset, which includes a large automatically-constructed training set (17.5K queries) and a smaller expert-annotated evaluation set (392 queries). They compare various information retrieval algorithms, including BM25, nearest neighbor retrieval, and dense retrieval with neural bi-encoders. The bi-encoder retriever model is trained on the DataFinder Dataset and evaluated against existing third-party dataset search engines. The method involves building a dataset, comparing information retrieval algorithms, and presenting a bi-encoder retriever model trained on the DataFinder Dataset to find more relevant datasets than existing search engines.

## Key Results
- The neural bi-encoder model outperforms traditional IR methods (BM25 and kNN) on dataset recommendation tasks
- Task information in queries is critical for effective dataset retrieval (removing task keywords reduces MAP from 23.5 to 7.5)
- The bi-encoder retriever finds more relevant search results than existing third-party dataset search engines

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Full-sentence queries contain implicit constraints that keyword queries make explicit
- Mechanism: When a researcher states "I want to use adversarial learning to perform domain adaptation for semantic segmentation of images," they implicitly require datasets that support domain adaptation, not just semantic segmentation
- Core assumption: Researchers can articulate their needs in natural language with implicit requirements
- Evidence anchors:
  - [abstract] states "researchers tend to rely on recent datasets" and mentions implicit constraints in queries
  - [section 2] explains how full-sentence queries can "implicitly specify constraints based on what a researcher wants to study"
  - [corpus] shows keyword search struggles with ambiguous terms like "semantic segmentation"

### Mechanism 2
- Claim: Neural bi-encoder models outperform traditional IR methods for dataset recommendation
- Mechanism: The bi-encoder learns semantic similarity between queries and datasets through contrastive learning, capturing relationships beyond term matching
- Core assumption: Dataset recommendation requires understanding semantic similarity, not just keyword overlap
- Evidence anchors:
  - [section 4.2] describes the bi-encoder architecture using BERT embeddings and contrastive loss
  - [section 5.2] shows bi-encoder outperforms BM25 and kNN methods on all metrics (P@5: 16.0 vs 4.7 for BM25)
  - [corpus] indicates off-the-shelf SciBERT fails without task-specific finetuning

### Mechanism 3
- Claim: Task information in queries is most critical for effective dataset retrieval
- Mechanism: The task type (e.g., "question generation," "optical flow estimation") directly maps to specific dataset requirements and constraints
- Core assumption: Task keywords are the primary differentiator between dataset needs
- Evidence anchors:
  - [section 5.4] shows removing task keywords reduces MAP from 23.5 to 7.5 (statistically significant)
  - [section 3.3] details the annotation process where task extraction is the first keyphrase type
  - [corpus] demonstrates that task information appears in nearly all queries and correlates with dataset selection

## Architecture Onboarding

- Component map: Query encoder -> Dataset encoder -> Similarity scoring -> Ranking -> Evaluation metrics
- Critical path: Query -> Bi-encoder -> Dataset ranking -> Top-k results
- Design tradeoffs: Full-sentence vs keyword queries (flexibility vs precision), automatic vs manual annotation (scalability vs quality)
- Failure signatures: Poor performance on queries with ambiguous terms, inability to generalize to unseen dataset types, over-reliance on recent popular datasets
- First 3 experiments:
  1. Compare BM25 baseline vs bi-encoder on small subset of test queries
  2. Test query understanding by removing task keywords and measuring performance drop
  3. Evaluate impact of adding structured metadata to dataset representations

## Limitations
- The use of Galactica for automatic query generation may introduce artifacts that don't reflect genuine researcher needs
- The evaluation set's small size (392 queries) and focus on machine learning datasets limits generalizability to other domains
- The bi-encoder's reliance on semantic similarity may struggle with highly technical or domain-specific terminology not well-represented in the training data

## Confidence
- High: The superiority of neural bi-encoder models over traditional IR methods for dataset recommendation (supported by consistent performance improvements across multiple metrics)
- Medium: The importance of task information in queries (based on ablation studies, but potentially domain-dependent)
- Medium: The scalability of automatic query generation (practical but quality concerns remain)
