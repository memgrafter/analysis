# Fused Depthwise Tiling for Memory Optimization in TinyML Deep Neural Network Inference

## Quick Facts
- arXiv ID: 2303.17878
- Source URL: https://arxiv.org/abs/2303.17878
- Reference count: 32
- The paper introduces Fused Depthwise Tiling (FDT) for memory optimization of Deep Neural Networks (DNNs) on TinyML devices

## Executive Summary
This paper introduces Fused Depthwise Tiling (FDT), a novel memory optimization technique for Deep Neural Networks (DNNs) on TinyML devices. FDT reduces memory usage by splitting intermediate buffers along the channel dimension rather than spatial dimensions, avoiding the runtime overhead that occurs in existing methods when dealing with larger kernel sizes. The authors propose an automated end-to-end flow that combines path discovery, memory-aware scheduling, and layout planning to find optimal tiling configurations. Evaluation on seven models shows that FDT achieved significant memory reduction for two models (76.2% and 18.1%) where existing methods could not be applied, and provided alternative design points with no overhead for two other models that had high run time overhead using existing methods.

## Method Summary
The paper presents Fused Depthwise Tiling (FDT), a memory optimization technique that splits intermediate buffers along the channel dimension to avoid runtime overhead. The method works by avoiding spatial overlap that occurs in existing Fused Feature Map Tiling (FFMT) when dealing with larger kernel sizes. FDT can be applied to a wider range of layer types than existing methods, including dense operations and embedding lookup-axis reduction pairs. The authors propose an automated end-to-end flow with path discovery to identify tiling opportunities, memory-aware scheduling to order operations, and layout planning formulated as a Mixed Integer Linear Program (MILP) to map buffers to memory locations. The approach is evaluated on seven quantized 8-bit DNN models targeting RISC-V RV32GC architecture.

## Key Results
- FDT achieved 76.2% memory reduction for one model where existing methods were inapplicable
- FDT achieved 18.1% memory reduction for another model where existing methods were inapplicable
- For two models with high runtime overhead using existing methods, FDT provided alternative design points with no overhead but reduced memory savings

## Why This Works (Mechanism)

### Mechanism 1
- Claim: FDT reduces memory usage without inducing runtime overhead by splitting intermediate buffers along the channel dimension instead of spatial dimensions
- Mechanism: By splitting along channels, FDT avoids the additive overlap that occurs in FFMT when splitting spatial dimensions with larger kernel sizes. Each output feature map is the result of summing all input feature maps after applying a convolutional filter, so FDT requires the input and output buffers to be fully available to every partition, but avoids the redundant computations that cause runtime overhead in FFMT
- Core assumption: Operations being tiled have all output elements depend on all input elements, but no interdependence among output elements themselves
- Evidence anchors:
  - [abstract] "FDT reduces memory usage without inducing any run time overhead"
  - [section] "Switching to the depthwise dimension avoids any overlap in the intermediate buffer and makes the method independent of the kernel size because the two dimensional convolutions are not split"
- Break condition: If operations have interdependencies among output elements or if splitting along channels would require partial computation of outputs, FDT would fail

### Mechanism 2
- Claim: FDT can be applied to a wider range of layer types than existing methods that focus solely on convolutions
- Mechanism: FDT works on any operation where all output elements depend on all input elements and there's no interdependence among outputs. This includes dense operations and pairs of embedding lookup followed by axis reduction, which cannot be tiled by FFMT
- Core assumption: The operation can be expressed as a sum of products where partial values can be recombined by summing element-wise and applying the activation function
- Evidence anchors:
  - [abstract] "FDT can be applied to more layer types than existing methods that focus solely on convolutions"
  - [section] "Examples of operations that can only be tiled by FDT are dense operations and pairs of embedding lookup (e.g. TensorFlow gather function) and axis reduction (e.g. by taking the mean)"
- Break condition: If the operation cannot be decomposed into independent partial computations that can be recombined, FDT would not work

### Mechanism 3
- Claim: The automated end-to-end flow with path discovery, memory-aware scheduling, and layout planning efficiently finds optimal tiling configurations
- Mechanism: The flow uses a block-based path discovery approach that identifies critical buffers, proposes tiling configurations for each, and evaluates them using memory-aware scheduling and layout planning to minimize peak memory usage
- Core assumption: The memory layout planning can be formulated as a Mixed Integer Linear Program (MILP) that finds the optimal buffer placement
- Evidence anchors:
  - [abstract] "In order to identify the best tiling configuration, an end-to-end flow with a new path discovery method is proposed"
  - [section] "The following MILP is formulated to perform optimal memory layout planning"
- Break condition: If the MILP becomes intractable for very large models or if the path discovery search space becomes too large to explore efficiently

## Foundational Learning

- Concept: DNN operation dependencies and buffer lifetimes
  - Why needed here: Understanding when intermediate buffers can be overlapped in memory requires knowing which operations depend on which buffers and when those buffers are no longer needed
  - Quick check question: Can you identify which buffers in a DNN graph have overlapping lifetimes and which can be safely overlapped?

- Concept: Memory layout planning as a graph coloring problem
  - Why needed here: The problem of mapping intermediate buffers to memory locations while avoiding conflicts is analogous to graph coloring where buffers are nodes and conflicts are edges
  - Quick check question: How would you formulate the buffer layout problem as a graph coloring problem and what would be the objective function?

- Concept: Series-parallel graphs and optimal scheduling
  - Why needed here: Tiled DNN graphs often have series-parallel structure, and optimal memory-aware scheduling for such graphs can be done in polynomial time
  - Quick check question: Can you identify which parts of a DNN graph are series-parallel and which require more complex scheduling approaches?

## Architecture Onboarding

- Component map: Path Discovery Module -> Memory-Aware Scheduler -> Layout Planner -> Graph Transformer
- Critical path: Identify critical buffers → Path discovery to propose configurations → Memory-aware scheduling → Layout planning → Graph transformation → Iterate until no further improvements
- Design tradeoffs: The main tradeoff is between memory savings and runtime overhead. FDT avoids runtime overhead but may achieve lower memory savings than FFMT. The automated flow trades exploration time for finding the optimal configuration
- Failure signatures: The system fails when no tiling configuration reduces memory usage, when the MILP for layout planning becomes intractable, or when the path discovery search space becomes too large to explore efficiently

## Open Questions the Paper Calls Out

The paper does not explicitly call out open questions, but several areas remain unexplored based on the limitations of the current work. The evaluation is limited to quantized 8-bit DNNs on RISC-V RV32GC architecture, which may not generalize to other architectures or precision formats. The claimed "no runtime overhead" for FDT is estimated via MAC operations rather than actual runtime measurements, which may not capture all overheads. The memory-aware scheduling and layout planning rely on MILP solvers that could become intractable for larger models, though the paper doesn't discuss fallback mechanisms. The automated flow's effectiveness depends on the completeness of the path discovery search space, which isn't fully characterized.

## Limitations

- The evaluation is limited to quantized 8-bit DNNs on RISC-V RV32GC architecture, which may not generalize to other architectures or precision formats
- The claimed "no runtime overhead" for FDT is estimated via MAC operations rather than actual runtime measurements
- The memory-aware scheduling and layout planning rely on MILP solvers that could become intractable for larger models, though fallback mechanisms are not discussed

## Confidence

- High confidence: FDT's fundamental mechanism of avoiding spatial overlap by splitting along channels is sound and the mathematical reasoning is clear
- Medium confidence: The claim that FDT works on a wider range of layer types than FFMT, as the examples provided are limited and the generalization to arbitrary operations needs more validation
- Medium confidence: The automated flow's ability to find optimal configurations, as the evaluation shows success on seven models but doesn't characterize failure modes or scalability limits
