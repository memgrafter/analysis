# DeepFire2: A Convolutional Spiking Neural Network Accelerator on FPGAs

## Quick Facts
- arXiv ID: 2305.05187
- Source URL: https://arxiv.org/abs/2305.05187
- Reference count: 40
- Key outcome: Achieves nearly 10× improvement over previous FPGA implementations with 1500+ FPS throughput on ImageNet models and 10.26 kFPS/Watt energy efficiency

## Executive Summary
DeepFire2 addresses scalability challenges in FPGA-based spiking neural network accelerators by introducing a novel split-kernel mapping technique that distributes large neural network layers across multiple super logic regions (SLRs) in multi-die FPGAs. The approach uses fine-grained resource allocation to balance memory and compute resources across SLRs, enabling efficient deployment of large ImageNet-scale models. Key innovations include a novel AND operation implementation using FPGA registers instead of lookup tables, reducing LUT usage and enabling higher clock frequencies up to 600 MHz. DeepFire2 achieves excellent scalability from small MNIST networks to large ImageNet models while maintaining high resource utilization and performance across multiple SLRs.

## Method Summary
DeepFire2 implements a systolic array architecture with split-kernel mapping to distribute large neural network layers across multiple SLRs in Xilinx VU9P FPGAs. The system uses a novel AND operation implementation with FPGA registers instead of LUTs, enabling deep pipelining up to 600 MHz. The architecture alternates between neuron cores (processing units) and feature buffers (data storage), with controllers managing data flow and bridges enabling SLR communication. SNN models are trained using TensorFlow with batch normalization, leaky ReLU/tanh activations, and 8-bit quantization, then mapped to the FPGA fabric using the DeepFire2 compilation flow.

## Key Results
- Nearly 10× improvement over previous FPGA implementations
- 1500+ frames per second throughput on ImageNet models
- 10.26 kFPS/Watt energy efficiency on MNIST
- Scales efficiently from MNIST to ImageNet across multiple SLRs
- Achieves 600 MHz clock frequency through register-based AND operations

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Split-kernel mapping distributes large layers across multiple SLRs, preventing memory bottlenecks.
- Mechanism: The mapping technique divides each convolutional layer into multiple kernel units, each with its own weight and threshold storage. By adjusting the number of parallel units, layers can be split across SLRs to balance memory and compute resources.
- Core assumption: Memory resources are the limiting factor for large layers, not compute resources.
- Evidence anchors:
  - [abstract] "introducing a novel split-kernel mapping technique that distributes large neural network layers across multiple super logic regions (SLRs) in multi-die FPGAs"
  - [section] "The limitation of this strategy is that layers can no longer be mapped into a single SLR, if they have too many parameters"
  - [corpus] Weak - corpus papers focus on general FPGA acceleration but don't discuss SLR-specific split-kernel techniques
- Break condition: If compute resources become the bottleneck instead of memory, or if inter-SLR communication overhead exceeds benefits.

### Mechanism 2
- Claim: Using FPGA registers instead of LUTs for AND operations reduces resource utilization and increases clock frequency.
- Mechanism: The neuron core design routes weights directly to register inputs and uses inverted input spikes to control the synchronous reset. This implements the AND operation without using LUTs, saving resources and improving timing.
- Core assumption: Registers are more abundant and efficient than LUTs for implementing AND operations in FPGA fabric.
- Evidence anchors:
  - [abstract] "A novel implementation of the logical AND operation of spiking neurons, which makes use of FPGA registers, to reduce the utilization of lookup tables"
  - [section] "Registers are also more abundant in Xilinx UltraScale+ devices, since each configurable logic block (CLB) contains eight 6-input LUTs, but 16 flip-flops"
  - [corpus] Weak - corpus papers don't discuss this specific optimization technique
- Break condition: If the specific FPGA architecture changes to make registers less abundant, or if AND operations become more complex than simple binary operations.

### Mechanism 3
- Claim: Deep pipelining enables high clock frequencies up to 600 MHz.
- Mechanism: The architecture implements multiple pipeline stages in the neuron core, including AND operations, addition, accumulation, and firing decisions. Retiming registers between stages enable timing closure at high frequencies.
- Core assumption: Pipeline depth can be increased without introducing excessive latency or resource overhead.
- Evidence anchors:
  - [abstract] "A deep pipeline does not only lead to an increased clock speed of up to 600 MHz"
  - [section] "The adder tree consists of three stages, where the first stage is embedded in DSP blocks in SIMD configuration and the remaining two-stages are implemented in CLBs"
  - [corpus] Weak - corpus papers don't provide specific details about pipeline depth optimization
- Break condition: If pipeline registers consume too much area or if the latency penalty from deep pipelining becomes prohibitive for real-time applications.

## Architecture Onboarding

- Component map: Neuron cores -> Feature buffers -> Controllers -> Bridges -> SLRs. Each layer alternates between neuron cores and feature buffers, with controllers managing data flow and bridges enabling SLR communication.
- Critical path: Image input -> Transduction layer -> Convolution layers -> Fully connected layers -> Output. The longest delay typically occurs in the convolution layers due to large feature maps and weight storage requirements.
- Design tradeoffs: Split-kernel mapping trades off some latency (less than ten cycles) for improved resource utilization and scalability. Using registers for AND operations trades off register usage for LUT savings and higher clock frequency.
- Failure signatures: Resource imbalance across SLRs causing underutilization, inter-SLR communication bottlenecks, timing closure failures at high clock frequencies, or backpressure in the feature buffer pipeline.
- First 3 experiments:
  1. Implement a single convolution layer with split-kernel mapping on two SLRs, varying the split ratio to observe resource utilization and timing
  2. Compare neuron core implementations using LUT-based AND versus register-based AND operations to measure resource usage and maximum frequency
  3. Implement a small SNN (e.g., MNIST) with different pipeline depths to find the optimal balance between clock frequency and resource usage

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the AND operation implementation using FPGA registers instead of LUTs scale to different FPGA architectures beyond Xilinx UltraScale+?
- Basis in paper: [explicit] The paper mentions this technique reduces LUT usage and enables higher clock frequencies up to 600 MHz on Xilinx UltraScale+ devices, but doesn't explore other FPGA architectures
- Why unresolved: The implementation was only tested on Xilinx UltraScale+ devices, and different FPGA architectures may have different register and LUT distributions
- What evidence would resolve it: Testing the AND operation implementation on other FPGA architectures (Intel, Lattice, etc.) to verify if similar resource savings and clock frequency improvements can be achieved

### Open Question 2
- Question: What is the optimal number of SLRs for deploying ImageNet models that balances resource utilization and performance?
- Basis in paper: [inferred] The paper mentions DeepFire2 can scale to unlimited SLRs in theory but only up to 4 are commercially available, and the ImageNet implementation uses all 3 SLRs while depleting most resources
- Why unresolved: The paper only tested ImageNet on 3 SLRs and didn't explore if using 4 SLRs or a different SLR allocation strategy could improve accuracy or performance
- What evidence would resolve it: Testing DeepFire2 with ImageNet on 4 SLRs and comparing accuracy, performance, and resource utilization against the 3 SLR implementation

### Open Question 3
- Question: How does the split-kernel mapping technique compare to other layer mapping strategies for balancing resource utilization across SLRs?
- Basis in paper: [explicit] The paper introduces split-kernel mapping as a novel technique for distributing large neural network layers across multiple SLRs while maintaining resource balance
- Why unresolved: The paper doesn't compare split-kernel mapping to other mapping strategies like traditional layer-wise mapping or more sophisticated partitioning algorithms
- What evidence would resolve it: Implementing alternative mapping strategies on the same datasets and comparing throughput, energy efficiency, and resource utilization against the split-kernel approach

## Limitations

- The architectural optimizations are highly dependent on the specific Xilinx UltraScale+ FPGA fabric, raising questions about portability to other FPGA families
- The paper claims 10× improvement over previous FPGA implementations but does not provide direct comparisons with baseline implementations
- Lack of publicly available implementation details for the split-kernel mapping algorithm and the specific register-based AND operation implementation
