# If the Sources Could Talk: Evaluating Large Language Models for Research Assistance in History

## Quick Facts
- arXiv ID: 2310.10808
- Source URL: https://arxiv.org/abs/2310.10808
- Reference count: 40
- Primary result: LLMs augmented with vector embeddings achieve 57.5-92.5% accuracy on historical question-answering and can extract genealogical data with high precision

## Executive Summary
This paper evaluates large language models as research assistants for historical research, focusing on question-answering and data extraction tasks. The authors demonstrate that by augmenting LLMs with vector embeddings from specialized academic sources, they can provide more accurate and contextually relevant responses to historical queries. The study shows that LLMs can assist researchers in examining customized corpora of documents and can be queried privately, with performance varying significantly based on the model and task complexity.

## Method Summary
The researchers evaluated LLMs by augmenting them with vector embeddings from a corpus of 86 academic books covering Irish Migration Studies, Cuban Studies, Migration Theory, and histories of Slavery. They used Chroma vector database with embeddings from sentence-transformers and integrated LangChain with local models (Falcon, XGen, Beluga) and API models (GPT3, ChatGPT). The evaluation involved 40 questions across different types (factual, argumentative, descriptive, integrative) with binary pass/fail grading, plus data extraction from genealogical sources.

## Key Results
- ChatGPT achieved the highest accuracy rates, ranging from 57.5% to 92.5% depending on model and task complexity
- LLMs can extract tabular data from genealogical sources with high accuracy when prompted with specific column formats
- Vector retrieval significantly improves answer accuracy by providing relevant document chunks as context
- Temperature settings near zero reduce hallucination by encouraging factual responses based on provided context

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Vector database retrieval provides LLMs with relevant document chunks that improve accuracy of answers beyond what the LLM knows from training data.
- Mechanism: Document text is split into overlapping chunks, each embedded into a vector. During a query, semantically similar chunks are retrieved and presented to the LLM as context, allowing it to base answers on specific academic sources rather than general web knowledge.
- Core assumption: Embedding similarity in vector space correlates with semantic relevance to the query.
- Evidence anchors:
  - [abstract] "We show that by augmenting such LLMs with vector embeddings from highly specialized academic sources, a conversational methodology can be made accessible to historians"
  - [section 2.1] "While executing a query, the database refers to its index to find those documents located in proximity to the embedding that matches the text of the query"
- Break condition: If embeddings do not capture the relevant semantics of the chunks, retrieved chunks will not help the LLM answer correctly.

### Mechanism 2
- Claim: Setting LLM temperature near zero encourages factual correctness over creativity, reducing hallucination.
- Mechanism: Temperature controls randomness in token selection; near-zero temperature makes the LLM pick the most likely next token, favoring responses grounded in provided context rather than invented content.
- Core assumption: Deterministic generation improves factuality when context is available.
- Evidence anchors:
  - [section 2.2] "A zero temperature corresponds to picking the most likely answer in each step and encourages factual correctness over creativity"
  - [section 4.1] Results show improved accuracy when corpus chunks are provided, suggesting reduced hallucination.
- Break condition: If context is insufficient or misleading, deterministic generation will still produce incorrect answers.

### Mechanism 3
- Claim: LLMs can extract structured data from genealogical texts by prompting them to output in tabular format.
- Mechanism: The LLM is given a full text excerpt and a prompt specifying column names and desired format; it parses the text and populates the table accordingly, inferring missing fields like gender from name conventions.
- Core assumption: The LLM's pre-trained knowledge includes patterns for genealogical language and can infer gender from Spanish names.
- Evidence anchors:
  - [section 4.2] "ChatGPT is able to extract data from Historia de Familias Cubanas... into a structured tabular format by simply prompting it to create a table"
  - [section 4.2] "The gender information was not in the original text. We asked ChatGPT to infer it automatically based on its pre-trained knowledge about Spanish name conventions"
- Break condition: If the text structure varies significantly or the LLM lacks sufficient cultural knowledge, extraction will miss or misattribute data.

## Foundational Learning

- Vector embeddings and similarity search
  - Why needed here: Core to retrieving relevant document chunks for the LLM.
  - Quick check question: How does an embedding represent a text chunk numerically?
- Prompt engineering and temperature settings
  - Why needed here: Controls LLM output style and reduces hallucination.
  - Quick check question: What happens to token selection when temperature is set to zero?
- Tabular data extraction with LLMs
  - Why needed here: Enables automation of genealogical data compilation.
  - Quick check question: How can you instruct an LLM to format output as a table with specific columns?

## Architecture Onboarding

- Component map:
  - PDF corpus → OCR/text extraction → chunking → Chroma vector DB → LangChain integration → LLM interface → CSV report
- Critical path:
  1. Load and clean PDFs
  2. Chunk text and generate embeddings
  3. Store chunks in vector DB
  4. Query DB with question → retrieve relevant chunks
  5. Prompt LLM with question + chunks
  6. Collect and format answers
- Design tradeoffs:
  - Larger chunk size → more context but fewer matches and higher DB cost
  - Lower temperature → more factual but less creative
  - Local models → privacy, offline use, but lower performance than ChatGPT
- Failure signatures:
  - No sources retrieved → query too broad or embeddings poorly aligned
  - LLM outputs hallucinated facts → temperature too high or context missing
  - Extraction misses data → prompt format unclear or text structure unexpected
- First 3 experiments:
  1. Run a small set of factual questions without any corpus to confirm baseline LLM capability.
  2. Load a single monograph, chunk it, and test question-answering to verify retrieval works.
  3. Attempt data extraction from a short genealogical excerpt to confirm prompt format works.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of open-source LLMs compare to ChatGPT on complex historical research tasks when both are provided with the same curated academic corpus?
- Basis in paper: [explicit] The paper states that "ChatGPT performed best even without any sources and remarkably we found that there is a big gap to GPT3 accessed through the OpenAI API" and that "XGen and Beluga consistently outperform GPT3 and both are competitive with ChatGPT."
- Why unresolved: The paper only compares performance on a limited set of 40 questions and doesn't provide a comprehensive evaluation across different types of historical research tasks or with larger datasets.
- What evidence would resolve it: A comprehensive study comparing multiple open-source and proprietary LLMs on a wide range of historical research tasks using the same curated academic corpus and evaluation metrics.

### Open Question 2
- Question: Can the hallucination problem in LLMs be effectively mitigated by providing them with curated academic corpora, or will it persist as a fundamental limitation?
- Basis in paper: [explicit] The paper acknowledges that "problems such as hallucination...will also probably be significantly reduced in the near future" but doesn't provide conclusive evidence on whether this approach can fully solve the issue.
- Why unresolved: The paper only provides preliminary evidence that providing sources can reduce hallucination, but doesn't explore whether this is a complete solution or if LLMs will continue to fabricate information even with curated corpora.
- What evidence would resolve it: A systematic study comparing the hallucination rates of LLMs with and without curated academic corpora across various types of historical research questions and tasks.

### Open Question 3
- Question: How can LLMs be effectively integrated into the historical research process to augment rather than replace human researchers?
- Basis in paper: [inferred] The paper discusses how LLMs can assist with tasks like question-answering and data extraction, but doesn't provide a comprehensive framework for how these tools should be integrated into the broader research process.
- Why unresolved: The paper focuses on demonstrating the capabilities of LLMs for specific tasks, but doesn't explore the broader implications for historical methodology or how these tools might change the nature of historical research.
- What evidence would resolve it: Case studies of historians using LLMs in their research process, along with surveys or interviews to understand how these tools are changing research practices and what new methodologies are emerging.

## Limitations

- The evaluation is limited to a narrow corpus of academic sources and specific question types, making it difficult to generalize performance to broader historical research contexts.
- Binary pass/fail grading may not capture nuanced accuracy levels in historical research where partial correctness matters.
- The study does not address long-term consistency or the potential for model drift as LLMs are updated.

## Confidence

- Question-answering claims: Medium (controlled experimental setup with clear metrics)
- Data extraction claims: Low (demonstrated on single source type only)
- Vector retrieval mechanism: High (well-supported by evidence)
- Temperature setting impact: Medium (needs more rigorous testing)

## Next Checks

1. Test the system with a more diverse corpus of historical sources, including primary sources in multiple languages and varying formats, to assess generalizability beyond the current academic monographs.
2. Implement a multi-level grading rubric for answers instead of binary pass/fail to capture partial correctness and identify specific failure modes in LLM responses.
3. Conduct a longitudinal study tracking the system's performance over time as both the vector database grows and LLM models are updated, to assess stability and evolving accuracy.
