# Network Anomaly Detection Using Federated Learning

## Quick Facts
- arXiv ID: 2303.07452
- Source URL: https://arxiv.org/abs/2303.07452
- Reference count: 20
- Primary result: 97.21% accuracy on UNSW-NB15 dataset using hierarchical federated learning

## Executive Summary
This paper presents a hierarchical federated learning framework for network anomaly detection that addresses scalability and efficiency challenges in centralized systems. The approach leverages edge servers to reduce computational load on global servers while preserving data privacy by keeping training data local. The model uses deep neural networks trained in a distributed manner across multiple clients, each handling network traffic from different devices.

The hierarchical architecture enables efficient anomaly detection by analyzing request features and IP addresses to identify malicious activity. Experimental results on the UNSW-NB15 dataset demonstrate superior performance compared to traditional centralized approaches, achieving 97.21% accuracy while reducing training time overhead. The framework shows promise for real-world deployment in distributed network environments.

## Method Summary
The proposed hierarchical federated learning framework consists of edge servers and clients working collaboratively to detect network anomalies. Edge servers act as intermediaries between clients and the global server, reducing computational burden while maintaining data privacy. Each client handles network traffic from different devices and performs local model training using deep neural networks (ANN). The trained models are then aggregated at the edge servers and global server through federated learning protocols. The system analyzes network request features and IP addresses to identify malicious activity, with the hierarchical structure enabling efficient computation and improved detection performance compared to centralized approaches.

## Key Results
- Achieved 97.21% accuracy on UNSW-NB15 dataset
- Outperformed centralized ML models: SVM (90.01%) and Random Forest (89.01%)
- Reduced training time overhead compared to traditional centralized approaches
- Demonstrated improved performance and faster computation through hierarchical architecture

## Why This Works (Mechanism)
The hierarchical federated learning framework works by distributing the computational load across multiple edge servers and clients while maintaining data privacy. Local data remains on client devices, and only model updates are shared, preventing sensitive information exposure. The edge servers aggregate local model updates before forwarding them to the global server, reducing communication overhead and improving efficiency. This distributed approach allows for parallel processing of network traffic data while maintaining a unified detection model, resulting in faster computation and improved accuracy compared to centralized systems.

## Foundational Learning
- Federated Learning: Distributed machine learning approach that trains models across multiple decentralized devices without sharing raw data; needed for privacy preservation and scalability
- Deep Neural Networks (ANN): Multi-layer neural networks capable of learning complex patterns in network traffic data; required for accurate anomaly detection
- Hierarchical Architecture: Multi-level system design with edge servers and global server; essential for balancing computational load and communication efficiency
- Network Traffic Analysis: Process of examining network packets and request features to identify normal vs. anomalous behavior; fundamental to the detection task
- Model Aggregation: Combining multiple local model updates into a unified global model; critical for maintaining consistent detection capabilities across the distributed system

## Architecture Onboarding

Component Map:
Clients (network devices) -> Edge Servers -> Global Server -> Detection Model

Critical Path:
1. Network data collected at client devices
2. Local model training on client devices
3. Model updates sent to edge servers
4. Edge servers aggregate local updates
5. Aggregated updates sent to global server
6. Global server performs final aggregation
7. Updated global model deployed back to edge servers and clients

Design Tradeoffs:
- Privacy vs. Performance: Local data stays on devices (privacy) but may limit training data diversity
- Communication Efficiency vs. Model Accuracy: Edge server aggregation reduces communication but may introduce approximation errors
- Hierarchical vs. Flat Architecture: Hierarchical reduces global server load but adds complexity and potential bottlenecks at edge servers

Failure Signatures:
- Edge server failure: Reduced model update aggregation efficiency, potential data loss from affected clients
- Client communication failure: Delayed model updates, potential staleness in detection capabilities
- Global server failure: Complete system halt in model aggregation and update distribution

First Experiments:
1. Single client with synthetic network traffic to verify basic model training and aggregation
2. Multiple clients with varied network patterns to test distributed training coordination
3. Edge server failure simulation to evaluate system resilience and recovery mechanisms
