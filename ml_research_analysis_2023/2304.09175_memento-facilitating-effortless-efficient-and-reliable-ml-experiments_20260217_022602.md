# Memento: Facilitating Effortless, Efficient, and Reliable ML Experiments

## Quick Facts
- arXiv ID: 2304.09175

## Executive Summary
Memento is a framework designed to streamline the management of complex machine learning experiments by automating parallelization, checkpointing, and caching. The system uses a user-defined configuration matrix to specify experimental parameters, which Memento automatically translates into parallelizable tasks. This approach significantly reduces the time and coding complexity required for running large-scale experimental workflows while providing fault tolerance and exception handling capabilities.

## Method Summary
Memento addresses ML experiment management challenges through a configuration matrix that defines parameter combinations for experimental tasks. The framework automatically distributes these tasks across multiple threads, caches outputs to prevent redundant computations, and creates checkpoints for fault tolerance. Users implement an experiment function that processes each task's context and configuration, while Memento handles the parallelization, error recovery, and notification systems. The approach requires minimal boilerplate code and provides automated restoration capabilities when errors occur.

## Key Results
- Enables parallel execution of ML experiments across multiple threads
- Provides automated checkpointing and error recovery mechanisms
- Reduces coding complexity through declarative configuration matrix specification

## Architecture Onboarding

- Component map:
  - Configuration Matrix Parser -> Task Generator -> Parallel Executor -> Checkpoint Manager -> Cache Manager -> Notification Provider

- Critical path:
  1. User defines configuration matrix
  2. Memento generates task list with hash identifiers
  3. Parallel execution distributes tasks across threads
  4. Each task runs experiment function, checkpoints results
  5. Cache manager prevents duplicate computations
  6. Notification provider alerts user upon completion

- Design tradeoffs:
  - Parallelization vs memory usage: More threads increase speed but require more memory
  - Checkpoint frequency vs overhead: More frequent checkpoints reduce lost work but increase I/O
  - Cache size vs speed: Larger caches prevent recomputation but consume storage

- Failure signatures:
  - Task hash collision: Duplicate hash values causing incorrect checkpoint restoration
  - Thread contention: Multiple threads competing for shared resources
  - Cache corruption: Invalidated or corrupted cache entries causing incorrect results

- First 3 experiments:
  1. Simple configuration with 2-3 parameters and small value sets to verify basic functionality
  2. Parallel execution test with dummy tasks to verify thread distribution and checkpointing
  3. Error recovery test where a task fails and Memento restores from checkpoint correctly
