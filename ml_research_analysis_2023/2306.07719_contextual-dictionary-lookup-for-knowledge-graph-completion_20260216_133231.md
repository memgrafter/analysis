# Contextual Dictionary Lookup for Knowledge Graph Completion

## Quick Facts
- arXiv ID: 2306.07719
- Source URL: https://arxiv.org/abs/2306.07719
- Reference count: 40
- Key outcome: CoDLR improves KGE models (TransE, DistMult, ConvE) on FB15k-237 and WN18RR with up to 53.53% improvement in H@1 metric

## Executive Summary
This paper introduces a contextual dictionary lookup method (CoDLR) for knowledge graph completion that represents relations as dictionaries containing multiple latent semantics. For each entity-relation pair, the method generates a context vector by composing the entity embedding with central relation semantics, then uses this context to lookup appropriate fine-grained semantics from the dictionary. The approach extends three KGE models (TransE, DistMult, ConvE) and demonstrates substantial performance improvements on standard benchmarks.

## Method Summary
CoDLR represents each relation as a dictionary containing multiple latent semantics. During training, it generates a context vector by composing the head entity embedding with the central semantics of the relation dictionary. This context is processed through an MLP to produce a lookup vector that acts as attention weights over the dictionary. The fine-grained semantics is computed as the weighted sum of dictionary elements, and two score functions (using central and fine-grained semantics) are optimized simultaneously. The method introduces two metrics, SOL (sparseness of lookup) and DAE (dictionary alignment entity), to validate the quality of the dictionary lookup operation.

## Key Results
- CoDLR achieves up to 53.53% improvement in H@1 metric over baseline KGE models
- The method shows consistent improvements across multiple KGE architectures (TransE, DistMult, ConvE)
- Dictionary sizes between 2-10 provide optimal performance trade-offs

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The dictionary lookup adaptively selects fine-grained relation semantics based on entity context
- Mechanism: CoDLR uses a dictionary `Dr` of size n containing multiple latent relation semantics. For each triple (h,r,t), it generates a context vector `Ch_r` by composing the head entity embedding `h` with the central semantics `Dc_r` of the dictionary. This context vector is passed through an MLP to produce a lookup vector `Lh_r`, which acts as attention weights over the dictionary. The fine-grained semantics `Dh_r` is then computed as the weighted sum `Lh_r Dr`, allowing adaptive selection of relation meaning based on the specific head entity.
- Core assumption: The composition of entity embedding and central semantics captures sufficient information to distinguish which fine-grained relation meaning is appropriate
- Evidence anchors:
  - [abstract] "The composition of a given entity and the dictionary's central semantics serves as the context for generating a lookup"
  - [section 4.2] "we consider the composition of the relation-connected entity and the central semantics of the dictionary as the context associated with the current fine-grained semantics"

### Mechanism 2
- Claim: Dual optimization of central and fine-grained semantics ensures semantic consistency while preserving model expressiveness
- Mechanism: CoDLR optimizes two score functions in parallel: one using central semantics `Dc_r` (S_c) and one using fine-grained semantics `Dh_r` (S_f). The loss function `L = L_f + λLc` where λ < 1 maintains consistency between the two while allowing them to diverge enough to capture distinct semantics. This prevents the fine-grained semantics from collapsing to the central semantics while ensuring they remain semantically related.
- Core assumption: The central semantics provide a meaningful anchor point that constrains but doesn't overly restrict the fine-grained semantics
- Evidence anchors:
  - [section 4.3] "we optimize two loss functions containing them respectively in parallel during the training process"
  - [section 4.4] "To maintain the consistency between the central semantics and fine-grained semantics of the dictionary"

### Mechanism 3
- Claim: SOL and DAE metrics provide orthogonal validation of lookup quality and dictionary-entity alignment
- Mechanism: SOL measures lookup vector sparsity - a sparse vector indicates the lookup focused on a specific fine-grained meaning. DAE measures alignment between the diversity of dictionary semantics and the diversity of entities connected to each relation. Low DAE indicates the dictionary captures the same diversity present in real entity distributions.
- Core assumption: A valid dictionary lookup should be sparse (focus on one meaning) and the dictionary diversity should match entity diversity
- Evidence anchors:
  - [section 4.4] "To determine whether a dictionary lookup is valid, we observe the sparseness of lookup (SOL)"
  - [section 4.5] "DAE inspects whether corresponding entity embeddings are aligned to the dictionary"

## Architecture Onboarding

- Component map: Entity embeddings → Central semantics (mean pooling) → Context generation (composition operator) → MLP → Lookup vector → Dictionary multiplication → Fine-grained semantics → Score function (with both central and fine-grained semantics)
- Critical path: The forward pass goes through context generation to produce the fine-grained semantics used for scoring, while the backward pass optimizes both semantics through the dual loss
- Design tradeoffs: Larger dictionary size increases model capacity but risks overfitting; different composition operators trade off expressiveness and parameter efficiency
- Failure signatures: Poor SOL values indicate lookup vectors aren't sparse enough; poor DAE values indicate dictionary doesn't match entity diversity; performance degradation compared to baseline indicates fine-grained semantics aren't being learned effectively
- First 3 experiments:
  1. Run CoDLR-TransE with varying dictionary sizes (2, 4, 6, 8) on FB15k-237 to find optimal capacity
  2. Compare different composition operators (sum, concat, mult, corr) on the same dataset to identify best context generation
  3. Train with λ = 0 (only fine-grained semantics) vs λ > 0 to validate the importance of semantic consistency constraint

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the choice of composition operator ϕ affect the performance of CoDLR across different KGE models and datasets?
- Basis in paper: [explicit] The paper states "the composition operator ϕ can be selected from four implementations" and provides results showing different performance for sum, concat, mult, and corr operators across models.
- Why unresolved: The paper shows performance differences but doesn't provide a theoretical explanation for why certain operators work better for specific models/datasets combinations.
- What evidence would resolve it: Systematic theoretical analysis of how each composition operator affects the embedding space and downstream task performance.

### Open Question 2
- Question: What is the optimal dictionary size n for different types of relations and datasets, and how does it scale with graph complexity?
- Basis in paper: [explicit] The paper states "the dictionary size n ranges from 2 to 10" and shows performance varies with n, but doesn't provide guidance on how to choose optimal size.
- Why unresolved: The paper only tests limited range of dictionary sizes and doesn't provide a principled approach for determining optimal size based on relation characteristics or graph properties.
- What evidence would resolve it: Empirical study correlating dictionary size with relation ambiguity, graph statistics, and performance across multiple datasets.

### Open Question 3
- Question: How can the SOL and DAE metrics be integrated into the training objective to improve dictionary lookup quality?
- Basis in paper: [explicit] The paper suggests "SOL and DAE, the two metrics can be added to the loss function as optimized terms to smooth the training" in the conclusion.
- Why unresolved: This integration was proposed but not implemented or evaluated in the paper.
- What evidence would resolve it: Experimental results comparing models with and without SOL/DAE as regularizers in the loss function, showing impact on dictionary quality and overall performance.

## Limitations
- Scalability concerns: The method maintains multiple semantics per relation, potentially increasing computational overhead for large knowledge graphs
- Limited evaluation scope: The paper focuses on standard benchmarks without testing on more complex or real-world knowledge graphs
- Hyperparameter sensitivity: Performance depends on careful tuning of dictionary size and composition operator selection
