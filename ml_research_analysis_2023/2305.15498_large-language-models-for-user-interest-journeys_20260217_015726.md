# Large Language Models for User Interest Journeys

## Quick Facts
- arXiv ID: 2305.15498
- Source URL: https://arxiv.org/abs/2305.15498
- Reference count: 40
- Key outcome: LLM-based journey extraction and naming doubles journey-serving rates compared to traditional systems

## Executive Summary
This paper presents a framework for extracting and naming user interest journeys on recommendation platforms using large language models. The approach combines personalized clustering (ICPC algorithm) to extract coherent user journeys from interaction logs with LLM-based naming using prompt-tuning. The authors demonstrate that prompt-tuning on small, high-quality datasets outperforms fine-tuning on large, noisy datasets for generating meaningful journey names. Their evaluation shows significant improvements in journey-serving rates and semantic accuracy when using journey-aware recommendations.

## Method Summary
The framework consists of two main components: personalized journey extraction using the Infinite Concept Personalized Clustering (ICPC) algorithm, and journey naming using prompt-tuned large language models. The ICPC algorithm groups items into user-specific journeys based on salient term similarity, creating new clusters only when similarity falls below a threshold. For naming, the authors compare few-shot prompting, prompt-tuning, and fine-tuning approaches, finding that prompt-tuning on expert-curated collections provides the best generalization. The system was validated on YouTube Music data and shows promise for enabling novel user experiences with more control over recommendations.

## Key Results
- ICPC personalized clustering produces coherent user journeys with 100% precision and 73% recall on 300 user histories
- Prompt-tuning outperforms fine-tuning in-domain and shows better generalization capability
- Journey-aware recommendations double the fraction of journeys being served (0.102 → 0.253)
- Journey names generated using all items outperform those using only last 5 items, but using last 11 items shows minimal drop in quality

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Personalized clustering via infinite concepts outperforms non-personalized global clustering for journey extraction
- Mechanism: ICPC algorithm assigns items to existing journey clusters based on salient term similarity, creating new clusters only when similarity falls below a threshold
- Core assumption: User journeys are personalized and cannot be effectively captured by global clustering approaches
- Evidence anchors: Abstract states "personalized extraction of interest journeys" and section 4 hypothesizes that "personalized view of journeys is more appropriate than assuming space of journeys is global"
- Break condition: When journeys are not personalized and global patterns dominate, or when similarity threshold is poorly calibrated

### Mechanism 2
- Claim: Prompt-tuning on small, high-quality datasets provides better generalization than fine-tuning on large, noisy datasets
- Mechanism: Prompt-tuning learns soft prompt embeddings that condition the LLM on domain-specific examples, while fine-tuning updates all model parameters
- Core assumption: Small, high-quality datasets contain more representative examples than large, noisy datasets for the target domain
- Evidence anchors: Section 5 shows "prompt-tuning outperforms fine-tuning in-domain, but prompt-tuning has better generalization capability" and section 5.4 emphasizes "quality of data used to learn prompt embedding plays a key role"
- Break condition: When large amounts of high-quality data become available, or when domain requires learning parameters not captured in prompt embeddings

### Mechanism 3
- Claim: Journey-aware recommendations improve relevance compared to traditional collaborative filtering
- Mechanism: Journey names provide semantic signals for content discovery rather than relying solely on collaborative filtering patterns
- Core assumption: Journey names provide better semantic signals for content discovery than collaborative filtering patterns
- Evidence anchors: Section 5.7 shows journey-serving rate improvement from 0.102 to 0.253, and section 3 mentions enabling users to interact with extracted journeys
- Break condition: When journey extraction becomes inaccurate or when user-item interaction patterns provide stronger signals than journey semantics

## Foundational Learning

- Concept: Salient term extraction and cosine similarity
  - Why needed here: Forms the basis of the infinite concept clustering algorithm for grouping items into coherent journeys
  - Quick check question: How does cosine similarity between salient term vectors determine whether two items belong to the same journey?

- Concept: Prompt engineering and few-shot learning
  - Why needed here: Required to understand how different prompting techniques (zero-shot, few-shot, prompt-tuning) affect LLM performance on journey naming
  - Quick check question: What's the difference between hard prompts in few-shot examples and soft prompts in prompt-tuning?

- Concept: BLEURT and SacreBLEU evaluation metrics
  - Why needed here: Essential for understanding how the paper quantitatively compares journey naming quality against ground truth
  - Quick check question: When would BLEURT score be more appropriate than SacreBLEU for evaluating generated journey names?

## Architecture Onboarding

- Component map: User interaction logs → Salient term extraction → ICPC clustering → LLM prompt generation → Journey names
- Critical path: User interaction history → ICPC clustering → LLM prompt generation → journey name output. Any bottleneck in clustering or LLM inference directly impacts user experience
- Design tradeoffs: Personalized clustering vs. computational cost, small high-quality datasets vs. large noisy datasets for prompt tuning, journey granularity vs. coherence
- Failure signatures: Poor journey extraction shows as either too many singleton clusters or overly broad clusters mixing different interests. Poor journey naming shows as generic, repetitive, or semantically unrelated names
- First 3 experiments:
  1. Run ICPC with varying similarity thresholds (0.05, 0.1, 0.15) on sample user histories to observe granularity effects
  2. Compare few-shot vs. prompt-tuning performance using the expert-curated collections dataset
  3. Test journey-aware recommendation by manually matching generated journey names to content search results

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the quality of generated journey names vary with different journey lengths (number of items)?
- Basis in paper: The paper states that generating names from only the last five items results in significantly lower SacreBLEU scores compared to using all items, but using the last eleven items shows minimal drop in quality
- Why unresolved: The paper provides initial insights but doesn't fully explore the relationship between journey length and name quality across different user cohorts or content types
- What evidence would resolve it: A comprehensive study varying journey lengths and measuring quality using multiple metrics across diverse user groups and content domains

### Open Question 2
- Question: How does the proposed journey service impact user engagement and satisfaction compared to traditional recommendation systems?
- Basis in paper: The paper mentions that A/B user-facing experiments to measure value added to users will be part of future work
- Why unresolved: While the technical aspects are well-explored, empirical evidence of impact on user behavior or satisfaction is lacking
- What evidence would resolve it: Results from A/B testing comparing user engagement and satisfaction between journey service and traditional recommendation systems over extended periods

### Open Question 3
- Question: How can the journey service be extended to handle multi-modal content (e.g., images, videos) in addition to text-based items?
- Basis in paper: The paper focuses on text-based items and their metadata, mentioning "salient terms" but not exploring multi-modal content incorporation
- Why unresolved: As recommendation platforms increasingly incorporate diverse content types, understanding how to adapt the journey service to handle multi-modal data is crucial
- What evidence would resolve it: A study demonstrating adaptation to handle multi-modal content, comparing journeys and names generated from text-only vs. multi-modal inputs

## Limitations
- Evaluation relies heavily on automated metrics rather than human judgment, which may not fully capture semantic quality
- ICPC algorithm performance depends critically on similarity threshold parameter, but optimal values across populations remain unclear
- Prompt-tuning requires high-quality curated datasets that may not be readily available in all domains or languages

## Confidence
- High Confidence: Personalized clustering outperforming global clustering for journey extraction, supported by strong empirical evidence (0.102 → 0.253 improvement)
- Medium Confidence: Prompt-tuning advantage over fine-tuning on small high-quality datasets, but generalizability across domains needs validation
- Low Confidence: Journey-aware recommendations significantly improving relevance compared to collaborative filtering, lacking direct comparative experiments
