# AutoMLP: Automated MLP for Sequential Recommendations

## Quick Facts
- arXiv ID: 2303.06337
- Source URL: https://arxiv.org/abs/2303.06337
- Reference count: 40
- This paper proposes AutoMLP, an MLP-based model for sequential recommendation that achieves competitive performance against state-of-the-art methods while maintaining linear computational complexity.

## Executive Summary
AutoMLP addresses the challenge of modeling users' long-term and short-term interests in sequential recommendation through a simple yet effective MLP-based architecture. The key innovation is an automated and adaptive search algorithm that determines the optimal short-term interest length via end-to-end optimization using DARTS. Experiments on public datasets show that AutoMLP achieves significant improvements over strong baselines in terms of HR, NDCG, and MRR metrics, with lower space complexity and higher training efficiency compared to transformer-based methods.

## Method Summary
AutoMLP is an MLP-based model that distinguishes between long-term and short-term user interests through separate modules. The long-term module processes the entire interaction sequence using sequence-mixer and channel-mixer MLP blocks, while the short-term module focuses on recent interactions with parallel SRSMLP layers. An automated search algorithm using DARTS determines the optimal short-term sequence length through differentiable architecture search. The model is trained with cross-entropy loss and evaluated using HR@10, NDCG@10, and MRR@10 metrics on MovieLens-1M and Amazon Beauty datasets.

## Key Results
- AutoMLP achieves significant improvements over strong baselines in HR, NDCG, and MRR metrics
- The model maintains linear computational complexity compared to quadratic complexity of transformer-based methods
- AutoMLP demonstrates higher training efficiency and lower space complexity than transformer alternatives

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The automated short-term interest length search replaces exhaustive enumeration by making the architecture search differentiable
- Mechanism: DARTS-based continuous relaxation converts discrete candidate sequence lengths into a weighted combination of outputs, where weights are learnable and optimized via gradient descent
- Core assumption: The effect of short-term sequence length on model performance is approximately smooth in the continuous relaxation space
- Evidence anchors:
  - [abstract] "automated and adaptive search algorithm for preferable short-term interest length via end-to-end optimization"
  - [section] "leverage continuous relaxation to convert the discrete sequence length to a continuous and differentiable representation via AutoML techniques"
- Break condition: If the effect of length is highly discontinuous or multimodal, gradient descent may get stuck in a poor local optimum

### Mechanism 2
- Claim: Replacing transformers with MLP blocks reduces computational complexity from quadratic to linear in sequence length
- Mechanism: The sequence-mixer block applies a position-independent MLP across the sequence dimension, avoiding self-attention matrix computation
- Core assumption: Position-independent processing suffices because the model can learn sequential order from input data patterns
- Evidence anchors:
  - [abstract] "maintains linear computational complexity"
  - [section] "AutoMLP only consists of MLP blocks, therefore maintaining linear time and space complexity"
- Break condition: If sequential order information is essential and cannot be recovered from data patterns, model performance may degrade

### Mechanism 3
- Claim: Joint modeling of long- and short-term interests via separate modules captures both static and dynamic user preferences
- Mechanism: The long-term module processes entire sequence learning stable preferences; short-term module focuses on recent interactions capturing volatile interests
- Core assumption: Users' next-item preferences are influenced by both stable long-term tastes and recent short-term trends
- Evidence anchors:
  - [abstract] "long-standing issue is how to distinguish between users' long/short-term interests"
  - [section] "long-term user sequential dependency... describes the users' most recent interest"
- Break condition: If separation of interests doesn't align with how users actually make choices, model may not improve over single-module approaches

## Architecture Onboarding

- Component map: Embedding layer → Long-term module (sequence-mixer → channel-mixer) → Short-term module (parallel SRSMLP layers + softmax weighting) → Output layer (concatenation + linear projection)
- Critical path: Embedding → Long-term module → Short-term module (selected by NAS) → Fusion → Prediction
- Design tradeoffs:
  - Simplicity and efficiency vs. potential loss of order-awareness compared to transformers
  - Joint training of modules vs. separate pretraining
  - Number of candidate lengths vs. search efficiency
- Failure signatures:
  - If short-term length search consistently picks maximum candidate, NAS may not be effective
  - If performance worse than single MLP baseline, module separation may be unnecessary
  - If training is unstable, bilevel optimization may need adjustment
- First 3 experiments:
  1. Ablation: Remove short-term module and compare performance to full AutoMLP
  2. Sensitivity: Vary number of candidate short-term lengths and measure search time and accuracy
  3. Efficiency: Compare training time and memory usage of AutoMLP vs. transformer-based baseline on same dataset

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does AutoMLP's performance scale with very long user interaction sequences compared to transformer-based methods?
- Basis in paper: [explicit] The paper claims AutoMLP maintains linear computational complexity while transformers have quadratic complexity to sequence length
- Why unresolved: Experiments only used datasets with sequences up to 999 interactions; real-world sequences can be much longer
- What evidence would resolve it: Benchmarking AutoMLP against transformer methods on datasets with sequences containing 10,000+ interactions

### Open Question 2
- Question: How does AutoMLP's automated short-term interest length selection perform on domains with different temporal patterns compared to domain-specific handcrafted approaches?
- Basis in paper: [explicit] The paper claims AutoMLP automatically adapts short-term interest length via end-to-end optimization rather than using predefined lengths
- Why unresolved: Experiments only tested on movie and beauty product domains; different domains may have very different temporal patterns
- What evidence would resolve it: Testing AutoMLP on diverse domains like music streaming, travel planning, and news consumption

### Open Question 3
- Question: How does AutoMLP's performance change when incorporating different types of item features beyond those used in experiments?
- Basis in paper: [explicit] The paper notes that feature-level methods like FDSA performed better than those without features, and mentions AutoMLP could incorporate item features
- Why unresolved: Experiments only used basic item features; real-world recommendation systems often have rich feature sets
- What evidence would resolve it: Evaluating AutoMLP with various feature combinations (text, image, social, temporal features)

## Limitations

- The DARTS-based approach assumes smoothness in the optimization landscape which may not hold for all datasets
- Reliance on position-independent processing in MLP blocks could limit ability to capture complex sequential dependencies
- Separation of long-term and short-term interests may not always align with actual user decision-making processes

## Confidence

**High Confidence**: Theoretical foundation of using MLP blocks for linear complexity and general framework of distinguishing long-term vs. short-term interests. Empirical results showing competitive performance against strong baselines.

**Medium Confidence**: Effectiveness of automated short-term length search in finding optimal architecture configurations across diverse datasets. Claim that MLP blocks can fully replace transformers without significant performance loss.

**Low Confidence**: Generalizability of results to datasets with different characteristics (very short/long sequences, different item types, or different user behavior patterns). Potential impact of bilevel optimization on training stability.
