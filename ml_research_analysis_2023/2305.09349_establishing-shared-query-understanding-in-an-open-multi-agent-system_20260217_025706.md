# Establishing Shared Query Understanding in an Open Multi-Agent System

## Quick Facts
- arXiv ID: 2305.09349
- Source URL: https://arxiv.org/abs/2305.09349
- Reference count: 20
- One-line primary result: Agents can achieve over 80% precision and 90% recall in query understanding through exchanging grounded examples within few interactions

## Executive Summary
This paper introduces a framework for evaluating shared understanding in open multi-agent systems, particularly for task-oriented communication involving human participants. The framework defines restrictions for grounded interaction, cooperation requirements, and efficiency metrics to ensure reliable task performance evaluation. A use case on cooperative query answering demonstrates the framework, where agents exchange examples of common instances to establish shared understanding. Experiments using an ontology alignment dataset show that agents can achieve over 80% precision and 90% recall within few interactions, with the framework providing guidelines for designing communication experiments with human-machine interaction applications.

## Method Summary
The framework establishes shared query understanding through iterative exchange of grounded examples between Teacher and Student agents. The Teacher selects examples from a pool of common instances, each containing one relevant and one irrelevant instance to refine the interpretation space. The Student updates its property-score representation based on received examples. Task performance serves as an indirect measure of communication success, with the Environment evaluating the Student's answers and providing feedback to the Teacher. Efficiency is measured by number of examples exchanged and memory demands. The framework uses ontology alignment datasets with common instances to test various Teacher and Student policy combinations.

## Key Results
- Agents achieved over 80% precision and 90% recall in query understanding tasks
- Robust query understanding methods performed better with incomplete knowledge
- More informative examples were more likely to be interpreted differently by agents
- The framework successfully demonstrated shared understanding through grounded communication

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Shared understanding can be incrementally built by exchanging concise, grounded examples between agents operating under different ontologies.
- Mechanism: Agents communicate via common world objects using examples with one relevant and one irrelevant instance to refine the interpretation space. The Teacher selects examples to maximize exclusion of non-relevant properties, while the Student updates its property-score representation.
- Core assumption: Both agents share some overlapping knowledge about the environment, allowing them to refer to common instances, even if their ontologies differ.
- Evidence anchors:
  - [abstract]: "Grounded interaction here has the form of examples that consists of common instances, for which the agents are expected to have similar knowledge."
  - [section 4.3]: Describes the Property-Based Teacher Policy that scores examples based on properties to exclude from interpretation candidates.
- Break condition: If agents have no common instances or the Teacher cannot provide examples with a positive property set for the Student, understanding cannot be built.

### Mechanism 2
- Claim: Task performance serves as an indirect measure of communication success when formal ontology alignment is infeasible.
- Mechanism: Agents cooperate on a query-answering task; the Environment evaluates the Student's answers, and this evaluation is relayed only to the Teacher. High task performance implies successful communication.
- Core assumption: The task cannot be solved by either agent alone, ensuring that cooperation and thus communication are necessary.
- Evidence anchors:
  - [abstract]: "We suggest the evaluation to be indirectly reflected on the performance of a task that requires agent collaboration."
  - [section 4.2]: "Successful communication and cooperation is required in our example. The student cannot find senior researchers alone... The database agent alone cannot automatically be updated about new roles."
- Break condition: If either agent can solve the task independently, task performance no longer reliably reflects communication quality.

### Mechanism 3
- Claim: Efficient communication in human-in-the-loop scenarios requires minimizing interaction time and cognitive load.
- Mechanism: Efficiency is measured by number of examples exchanged (interaction time) and memory demands (Episodic and Working memory), approximated by number of examples memorized and variables tracked.
- Core assumption: Human agents have cognitive limitations that must be respected; thus, communication must be concise and memory-efficient.
- Evidence anchors:
  - [abstract]: "the communicated examples should be concise so that their comprehension is not very laborsome."
  - [section 4.2]: Defines Episodic and Working memory in terms of number of memorized episodes and variables.
- Break condition: If communication becomes too verbose or memory-intensive, human agents cannot sustain the interaction.

## Foundational Learning

- Concept: Ontology Alignment
  - Why needed here: Understanding how different formal representations of knowledge can be mapped is crucial for grasping why direct comparison of agent interpretations is not feasible.
  - Quick check question: What is the main challenge in applying traditional ontology alignment methods in this framework?
  - Answer: Traditional methods require complete access to both ontologies and are too complex for real-time use, making them unsuitable when some agents are humans with incomplete knowledge.

- Concept: Grounded Communication
  - Why needed here: Grounded communication via common world objects is the foundation for how agents can interact without a shared formal language.
  - Quick check question: How do agents communicate in this framework when they don't share a common language?
  - Answer: They refer to common world objects (e.g., researchers) that both agents are aware of, using these as examples to convey meaning.

- Concept: Information Retrieval Metrics
  - Why needed here: Task performance is evaluated using precision and recall, which are standard metrics for assessing how well the Student's answers match the Environment's expectations.
  - Quick check question: Why are precision and recall used to evaluate communication success?
  - Answer: Because the agents' task is query-answering, and precision/recall measure how accurately the Student retrieves relevant information, which indirectly reflects its understanding of the Teacher's query.

## Architecture Onboarding

- Component map: Teacher -> Student -> Environment -> Teacher (feedback loop)

- Critical path:
  1. Teacher receives task from Environment.
  2. Teacher selects example from pool based on policy.
  3. Teacher sends example to Student.
  4. Student updates its property-score representation based on policy.
  5. Student performs task (e.g., answers query).
  6. Student sends results to Environment.
  7. Environment evaluates results, sends feedback to Teacher.
  8. Loop until task is performed satisfactorily or communication limit is reached.

- Design tradeoffs:
  - Example selection vs. exploration: Teacher must balance selecting informative examples against exploring the space of possible interpretations.
  - Memory vs. efficiency: Student must decide whether to memorize examples (Logic-based) or just update scores (Frequency-based), trading off memory usage for potential accuracy.
  - Conciseness vs. informativeness: Examples must be concise to respect human cognitive limits but informative enough to effectively communicate the query.

- Failure signatures:
  - Low precision/recall despite many interactions: Possible issues with example selection policy or Student's interpretation method.
  - Rapid decline in recall after few examples (Logic-based Student): Indicates the policy is not robust to incomplete knowledge.
  - High number of unclear examples: Suggests poor overlap between agent ontologies or ineffective example selection.

- First 3 experiments:
  1. Implement a baseline with Random Teacher and Random Student policies to establish a performance floor.
  2. Implement Property-Based Teacher with Frequency-Based Student to test if targeted example selection improves efficiency.
  3. Implement Logic-Based Student with Property-Based Teacher to evaluate the impact of example memorization on performance with incomplete knowledge.

## Limitations

- The framework's effectiveness relies heavily on the assumption that agents share sufficient common world knowledge and instances
- Experimental validation uses synthetic ontology alignment datasets which may not fully capture real-world human-agent communication complexity
- Cognitive load metrics are simplified to counts of memorized examples and tracked variables, potentially not accurately representing human cognitive limitations

## Confidence

**High Confidence**: The theoretical framework for establishing shared query understanding through grounded communication is well-defined and internally consistent.

**Medium Confidence**: The experimental results showing 80% precision and 90% recall are promising but based on synthetic datasets.

**Low Confidence**: The cognitive load approximations and their impact on human-agent interaction efficiency have not been empirically validated with human subjects.

## Next Checks

1. **Human Subject Study**: Conduct a small-scale experiment where human participants act as either Teacher or Student to validate the cognitive load assumptions and assess the framework's effectiveness in real human-agent communication scenarios.

2. **Cross-Domain Evaluation**: Apply the framework to a different domain (e.g., image classification or natural language instruction following) to test its generalizability beyond query answering.

3. **Scalability Analysis**: Evaluate the framework's performance as the number of properties and instances increases, and analyze how the number of required interactions scales with problem complexity.
