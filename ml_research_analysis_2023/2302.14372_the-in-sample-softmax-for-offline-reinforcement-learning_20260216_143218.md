# The In-Sample Softmax for Offline Reinforcement Learning

## Quick Facts
- arXiv ID: 2302.14372
- Source URL: https://arxiv.org/abs/2302.14372
- Authors: 40
- Reference count: 40
- One-line result: In-Sample Actor-Critic (InAC) consistently outperforms or matches existing offline RL methods by using an in-sample softmax operator that avoids overestimation from out-of-distribution actions.

## Executive Summary
This paper addresses the fundamental problem in offline reinforcement learning where the standard max operator may select actions not present in the dataset, leading to overestimation and poor performance. The authors introduce the in-sample softmax operator that only considers actions in the dataset during value updates, ensuring bootstrapping only from supported actions. They prove convergence properties showing that policy iteration with this operator converges and approaches the in-sample max as temperature decreases. The resulting In-Sample Actor-Critic (InAC) algorithm demonstrates strong performance across tabular and continuous control tasks, particularly when datasets contain suboptimal or incomplete action coverage.

## Method Summary
The core method introduces an in-sample softmax operator that computes τ log Σ(exp(q(s',a')/τ)) over only actions with positive probability under the dataset's action distribution πD. This operator ensures that value updates only consider actions actually observed in the dataset, preventing overestimation from out-of-distribution actions. The In-Sample Actor-Critic algorithm learns a behavior policy πω to approximate πD, uses the in-sample softmax in the critic qθ, estimates a normalizer Z with value function vφ, and updates the actor πψ via KL divergence to the in-sample soft greedy policy while sampling from the dataset. The method proves convergence to the in-sample max as temperature τ→0 and demonstrates consistent performance improvements across multiple offline RL benchmarks.

## Key Results
- InAC consistently outperforms or matches state-of-the-art offline RL methods (IQL, TD3+BC, CQL) on D4RL Mujoco benchmarks
- InAC performs well in both pure offline training and online fine-tuning scenarios
- The method shows particular effectiveness when datasets contain suboptimal or incomplete action coverage

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The in-sample softmax operator mitigates overestimation by restricting bootstrapping to actions present in the dataset.
- Mechanism: By computing τ log Σ_{a':πD(a'|s')>0} exp(˜q*(s',a')/τ) instead of the full max over all actions, the operator ensures only supported actions contribute to the value update.
- Core assumption: The dataset's action distribution πD adequately covers the support of the optimal policy.
- Break condition: If πD has near-zero probability for a high-value action in some state, the in-sample softmax will never select it, leading to suboptimal policies.

### Mechanism 2
- Claim: The in-sample softmax converges to the in-sample max as temperature τ→0.
- Mechanism: For decreasing τ, τ log Σ_{a'} exp(q(a')/τ) approaches max_{a'} q(a'), so restricting the sum to dataset-supported actions yields the in-sample max.
- Core assumption: The dataset covers the support of the optimal policy and τ can be decreased without numerical instability.
- Break condition: Numerical precision limits prevent τ from approaching zero; or dataset lacks support for optimal actions.

### Mechanism 3
- Claim: Sampling the actor update from the dataset (via πD) is equivalent to sampling from the in-sample soft greedy policy.
- Mechanism: The KL divergence loss can be rewritten as an expectation over actions sampled from πD, eliminating the need to sample from an approximate πD.
- Core assumption: πω approximates πD well enough for the actor update to remain in-sample.
- Break condition: If πω poorly approximates πD, the actor may update towards out-of-distribution actions.

## Architecture Onboarding

- Component map: πω (behavior policy) -> qθ (critic with in-sample softmax) -> vφ (value for normalizer) -> πψ (actor updated via KL divergence)

- Critical path:
  1. Sample batch from dataset
  2. Update πω to approximate πD
  3. Update qθ with in-sample softmax backup
  4. Update vφ to estimate Z
  5. Update πψ via KL divergence using dataset samples

- Design tradeoffs:
  - Using πω to approximate πD vs. exact support constraints
  - Temperature τ balancing exploration vs. overestimation risk
  - Learning vφ to estimate Z vs. computing Z directly (computational cost)

- Failure signatures:
  - Poor performance on datasets with highly suboptimal policies (IQL-like failure)
  - Instability when τ is too small (numerical issues)
  - Overestimation if πω poorly approximates πD

- First 3 experiments:
  1. Run on Four Rooms with Expert, Random, and Missing-Action datasets to verify convergence to Oracle-Max
  2. Compare InAC vs. IQL on Medium-Expert dataset to test performance on suboptimal data
  3. Test online fine-tuning from Medium-Replay dataset to evaluate robustness to poor offline data

## Limitations
- The method assumes the dataset adequately covers the support of the optimal policy, which is not proven and could fail when true optimal actions are missing from the dataset.
- Numerical stability of decreasing temperature τ is not fully addressed, with no guidance on practical lower bounds.
- The performance gain over existing methods is not substantial in all tested scenarios, particularly for some D4RL datasets.

## Confidence
- High confidence: The convergence proof for the in-sample softmax operator and its relationship to the in-sample max (supported by mathematical derivations)
- Medium confidence: Experimental results showing performance improvements across multiple datasets (though some baselines show limited improvement)
- Low confidence: The claim that this method generalizes well to all offline RL scenarios, particularly those with highly suboptimal or incomplete datasets
