# Language Variety Identification with True Labels

## Quick Facts
- arXiv ID: 2303.01490
- Source URL: https://arxiv.org/abs/2303.01490
- Reference count: 12
- This paper introduces DSL-TL, the first human-annotated dataset for language variety identification, addressing the limitation of previous datasets that rely on document source for labels.

## Executive Summary
This paper addresses the critical limitation in language variety identification where existing datasets rely on document source metadata (e.g., country domain) rather than true linguistic labels. The authors introduce DSL-TL, a human-annotated dataset with 12,900 instances across Portuguese, Spanish, and English national varieties. The dataset features true labels derived from multiple human annotators, including an explicit "both/neither" class for ambiguous cases. Experimental results show that traditional machine learning models, particularly Naive Bayes variants, outperform deep learning approaches like mBERT and XLM-R on this task, achieving up to 0.803 average F1 score.

## Method Summary
The study introduces DSL-TL, a human-annotated dataset for language variety identification containing 12,900 instances across three language pairs (pt-PT/pt-BR, es-ES/es-AR, en-GB/en-US). Annotators labeled sentences as variety X, variety Y, or both/neither based on linguistic features. Models evaluated include Naive Bayes, Adaptive Naive Bayes, mBERT, XLM-R, and XLM-R-LD, using character n-grams and standard fine-tuning approaches. The dataset uses a 70/20/10 train/dev/test split, with macro-averaged F1-score as the primary evaluation metric.

## Key Results
- Naive Bayes variants outperform deep learning models, with open Naive Bayes achieving highest average F1 of 0.803 in variety-only classification
- The "both/neither" class remains challenging, showing significantly lower performance than variety-specific classes
- Character n-gram based models perform well, suggesting language variety identification is primarily a pattern-matching task

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Human-annotated labels with multiple annotators per instance improve label reliability compared to document-source proxies.
- Mechanism: Multiple human judgments allow aggregation to produce a consensus label that better reflects actual linguistic features rather than metadata (country domain).
- Core assumption: Annotators can reliably identify language variety markers in text, and majority voting reduces noise from individual disagreement.
- Evidence anchors:
  - [abstract] "The annotators were displayed with sentences from the dataset, and they were asked to assign one of the following three labels..."
  - [section] "We considered the gold label correct in cases in which the three annotators agreed on the same label or when two annotators agreed with the original gold label..."
  - [corpus] Weak - corpus shows no direct evidence of annotation process reliability.
- Break condition: If annotators are not native speakers or lack training, labels may not reflect true variety distinctions.

### Mechanism 2
- Claim: Including a "both/neither" class captures cases where texts contain features from multiple varieties or no distinctive markers.
- Mechanism: This explicit class prevents forced misclassification of ambiguous instances and reduces error propagation in downstream models.
- Core assumption: Some sentences genuinely cannot be assigned to a single variety due to mixed or neutral features.
- Evidence anchors:
  - [abstract] "The 'both/neither' class remains challenging, indicating room for improvement in modeling mixed or neutral language variety instances."
  - [section] "they were asked to assign one of the following three labels... variety X, variety Y, or both/neither..."
  - [corpus] Weak - no direct evidence on frequency or nature of "both/neither" cases.
- Break condition: If "both/neither" class becomes too large, it may indicate unclear annotation guidelines or insufficient variety distinction.

### Mechanism 3
- Claim: Traditional machine learning models (Naive Bayes) perform comparably or better than deep learning models on this task.
- Mechanism: Character n-gram based Naive Bayes captures fine-grained linguistic patterns effectively without requiring large training data or complex embeddings.
- Core assumption: Language variety identification is primarily a pattern matching task rather than semantic understanding, favoring simpler models.
- Evidence anchors:
  - [abstract] "Results show Naive Bayes variants outperform deep learning models in this task, with open Naive Bayes achieving the highest average F1 of 0.803..."
  - [section] "Language identification is essentially a pattern-matching task rather than a semantic understanding one. We believe that this often favors relatively simpler character n-gram models..."
  - [corpus] Weak - no corpus evidence comparing model performances.
- Break condition: If task complexity increases (e.g., more varieties), deep learning may outperform due to better generalization.

## Foundational Learning

- Concept: Character n-grams as text representation
  - Why needed here: Language variety identification relies on subtle orthographic and lexical differences that are best captured at character level.
  - Quick check question: Why might character n-grams be more effective than word embeddings for distinguishing Brazilian vs European Portuguese?

- Concept: Multi-annotator consensus for ground truth
  - Why needed here: Single annotator labels based on document source are unreliable for similar varieties; consensus improves label quality.
  - Quick check question: What is the minimum number of annotator agreements used to establish a gold label in this dataset?

- Concept: Class imbalance handling
  - Why needed here: The "both/neither" class is challenging and may be underrepresented, affecting model performance.
  - Quick check question: How does the model performance on "both/neither" class compare to variety-specific classes?

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the optimal method for modeling the 'both or neither' class in language variety identification?
- Basis in paper: [explicit] The paper notes that models performed poorly on the 'both or neither' class, achieving much lower scores compared to individual language varieties, and states this class remains challenging to model.
- Why unresolved: The authors do not provide a solution or experimental approach to improve modeling of this class, and existing language identification datasets lack this category, making it difficult to establish best practices.
- What evidence would resolve it: Experimental results showing improved F1-scores for the 'both or neither' class using novel modeling techniques such as multi-label classification, threshold-based approaches, or incorporating contextual information.

### Open Question 2
- Question: How does dataset size impact the performance of language variety identification models?
- Basis in paper: [explicit] The authors state they would like to expand the dataset size in future work to investigate the impact of dataset size on performance.
- Why unresolved: The current dataset (12,900 instances) is relatively small, and the authors acknowledge the need to study how increasing dataset size affects model performance, but no experiments were conducted.
- What evidence would resolve it: Performance comparisons between models trained on datasets of varying sizes, showing how accuracy, F1-scores, and model training time scale with increased data.

### Open Question 3
- Question: How can language variety identification systems be made more robust to code-switching and code-mixing phenomena?
- Basis in paper: [inferred] The paper discusses the challenges of discriminating between similar languages and varieties, and mentions code-mixing as a linguistic phenomenon that challenges language identification systems.
- Why unresolved: While the paper focuses on identifying single language varieties, it does not address the complexities introduced by mixed-language texts, which are common in real-world applications.
- What evidence would resolve it: Experiments evaluating model performance on datasets containing code-switched texts, and results showing improvements using techniques like code-switching detection, multi-task learning, or specialized tokenization strategies.

## Limitations
- Limited dataset size (12,900 instances) may constrain generalizability to other language varieties
- Annotation process relies on crowdworkers without explicit verification of linguistic expertise
- Performance gap between Naive Bayes and deep learning may reflect task-specific characteristics rather than general superiority

## Confidence

**High Confidence**: The core finding that human-annotated labels improve upon document-source proxies is well-supported by the methodological approach and aligns with established annotation principles. The comparative performance of Naive Bayes versus deep learning models is empirically demonstrated with clear metrics.

**Medium Confidence**: The claim about the "both/neither" class being inherently challenging requires more analysis of annotation patterns and inter-annotator agreement to determine whether this reflects genuine linguistic ambiguity or annotation guideline issues.

**Low Confidence**: The generalizability of results to other language pairs, particularly those with less distinct orthographic features or more complex dialect continua, remains untested and speculative.

## Next Checks

2. **Cross-linguistic Generalization Test**: Apply the best-performing models to a different set of language varieties (e.g., French Canadian vs European French) to test whether Naive Bayes superiority extends beyond the current language pairs.

3. **Annotation Guideline Refinement**: Conduct error analysis on "both/neither" class predictions to determine if specific linguistic features consistently trigger this label, and revise guidelines accordingly for future annotation rounds.
