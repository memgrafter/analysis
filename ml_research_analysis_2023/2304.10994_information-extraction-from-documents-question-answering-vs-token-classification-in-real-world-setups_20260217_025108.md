# Information Extraction from Documents: Question Answering vs Token Classification in real-world setups

## Quick Facts
- arXiv ID: 2304.10994
- Source URL: https://arxiv.org/abs/2304.10994
- Reference count: 36
- Primary result: Token classification outperforms QA on clean, short entities; QA shows greater robustness in noisy environments and with long entities

## Executive Summary
This paper compares two approaches for document key information extraction: token classification and question answering (QA). Using LayoutLM as a backbone model, the study evaluates both methods across five experimental setups including raw performance, robustness to noise, long entity extraction, few-shot learning, and zero-shot learning. The research finds that token classification excels with clean, short entities while QA demonstrates superior robustness in noisy environments and with long entities. The study concludes that method selection should depend on specific use case requirements and data characteristics.

## Method Summary
The study uses LayoutLMv2 with style-based embeddings as the backbone architecture, implementing both token classification and QA heads. For token classification, the model uses IOB tagging with batch size 2 and early stopping based on F1 score improvements. The QA approach employs span prediction with batch size 4 and gradient accumulation. Both methods use Adam optimizer with learning rate 2e-5. The researchers convert token classification datasets to QA format by generating questions like "What is the <LABEL>?" and evaluate performance across multiple document types including receipts, forms, contracts, and legal documents.

## Key Results
- Token classification achieved 94.86% F1 on clean SROIE dataset while QA scored 93.83%
- QA maintained 83.09% F1 with 10% missing tags while token classification dropped to 40.66%
- For long entities from CUAD dataset, QA achieved 37.51% weighted F1 while token classification scored 0%
- In few-shot learning with 100 examples, QA achieved 71.11% F1 while token classification scored 68.74%

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Token classification is more effective than QA for extracting clean, short entities from structured documents.
- Mechanism: Token classification directly assigns labels to each token, allowing the model to leverage contextual information within a fixed sequence. For short, well-defined entities, this direct labeling is more precise and efficient than extracting spans based on question-answer pairs.
- Core assumption: The entity boundaries are clear and the text is relatively noise-free, allowing the model to accurately classify each token.
- Evidence anchors:
  - [abstract] states "when dealing with clean and relatively short entities, it is still best to use token classification-based approach"
  - [section 6.3] shows token classification achieved higher F1-scores on clean datasets like SROIE and Trade Confirmations
- Break condition: When entity boundaries are ambiguous or the text contains significant noise, token classification performance degrades due to increased false positives/negatives.

### Mechanism 2
- Claim: QA approach is more robust to noisy environments with missing or incorrect annotations.
- Mechanism: QA models are trained on positive samples only (correct entity spans), so they are less affected by missing or incorrect annotations compared to token classification models that must classify every token, including those without labels.
- Core assumption: The noise primarily consists of missing or incorrect entity annotations rather than fundamental issues with the document structure or content.
- Evidence anchors:
  - [section 6.4] shows QA approach maintained F1-score with 10% missing tags (83.09%) while token classification dropped significantly (40.66%)
  - [abstract] mentions "QA approach could be a good alternative for noisy environment"
- Break condition: If noise is structural (e.g., document layout issues, OCR errors affecting entire regions) rather than annotation errors, QA performance may also degrade.

### Mechanism 3
- Claim: QA approach performs better on long entities due to reduced dependency on contiguous context.
- Mechanism: QA models only need to identify start and end positions of entities, making them less sensitive to entity length and better able to handle entities that span multiple chunks when documents are divided for processing.
- Core assumption: The entity length exceeds the model's maximum input capacity, requiring document chunking for processing.
- Evidence anchors:
  - [section 6.5] shows QA achieved 37.51% weighted average F1-score on long entities from CUAD while token classification achieved 0%
  - [abstract] states "QA approach could be a good alternative for noisy environment or long entities use-cases"
- Break condition: If the model's input capacity is sufficient to process entire documents without chunking, or if entities are consistently short, the advantage of QA for long entities diminishes.

## Architecture Onboarding

- Component map: Input document → LayoutLM encoding → Token classification layer OR QA layer → Entity labels or start/end positions
- Critical path: For token classification: Input document → LayoutLM encoding → Token classification layer → Entity labels. For QA: Input document and question → LayoutLM encoding → QA layer → Start/end positions of answer spans
- Design tradeoffs: Token classification is more precise for clean, short entities but struggles with noise and long entities. QA is more robust to noise and handles long entities better but may underperform on clean, short entities and has challenges with multiple entities of the same type.
- Failure signatures: Token classification fails with high noise (increased false positives/negatives), long entities (cannot capture full entity), or ambiguous boundaries. QA fails with clean, short entities (lower precision), multiple entities of same type (ambiguity in span selection), or unseen labels (zero-shot learning).

## Open Questions the Paper Calls Out

- Question: How do the token classification and QA approaches compare in extracting entities with nested structures (e.g., nested named entities or tables)?
  - Basis in paper: [explicit] The paper mentions "additional experimental settings with nested entities" as a potential future work direction, indicating this has not been explored yet.
  - Why unresolved: The paper's experiments did not include nested entity structures, focusing instead on flat entity extraction tasks.
  - What evidence would resolve it: Experiments comparing token classification and QA performance on datasets with nested entities, measuring precision, recall, and F1-score for each approach.

- Question: What is the impact of using image features alongside text and layout information on the performance of QA and token classification approaches?
  - Basis in paper: [explicit] The paper mentions that "further works" could include "more model architectures that could include image features as shown in the document visual question answering task," suggesting this is unexplored.
  - Why unresolved: The experiments in the paper only used LayoutLM models, which primarily focus on text and layout, without incorporating image features.
  - What evidence would resolve it: Comparative experiments using models that incorporate image features (e.g., LayoutLMv2) for both QA and token classification, showing improvements in accuracy or robustness.

- Question: How does the robustness of QA and token classification approaches compare in environments with varying levels of annotation errors (e.g., typos, missing tags, incorrect tags)?
  - Basis in paper: [explicit] The paper explored noisy environments with partial missing tags but did not extensively test other types of annotation errors.
  - Why unresolved: The experiments only simulated missing tags, not other error types like typos or incorrect annotations.
  - What evidence would resolve it: Experiments introducing different types of annotation errors (typos, incorrect tags, missing tags) into datasets and measuring the performance degradation of both approaches.

## Limitations

- The conclusions about approach superiority depend heavily on specific data characteristics, potentially oversimplifying real-world deployment decisions
- The noise injection experiments use controlled, synthetic noise that may not reflect real-world annotation errors or OCR failures
- Zero-shot learning performance remains poor for both approaches, but the paper doesn't explore hybrid approaches or curriculum learning strategies

## Confidence

**High Confidence**: The claim that token classification outperforms QA on clean, short entities is well-supported by the empirical results across multiple datasets (SROIE, Trade Confirmations) with statistically significant differences in F1 scores.

**Medium Confidence**: The assertion that QA is more robust to noisy environments has strong experimental support but relies on the specific noise model (missing annotations) used in the study.

**Medium Confidence**: The performance advantage of QA for long entities is demonstrated but the absolute performance levels (37.51% F1 on CUAD) suggest this is more of a "less bad" solution than a truly effective approach.

## Next Checks

1. **Hybrid Approach Validation**: Implement and test a hybrid model that dynamically switches between token classification and QA based on entity characteristics (length, position, surrounding context). Measure whether this outperforms either approach alone on datasets with mixed entity types, particularly examining the 15-25 character sweet spot where current approaches show similar performance.

2. **Real-World Noise Validation**: Replace the synthetic annotation noise with realistic OCR errors and document quality variations on the same datasets. Compare approach robustness using metrics like character error rate and bounding box accuracy alongside F1 scores to determine if conclusions about noise robustness hold under more authentic degradation patterns.

3. **Zero-Shot Transfer Enhancement**: Test few-shot adaptation techniques (e.g., prompt tuning, adapter layers) starting from pre-trained models on related document types. Evaluate whether these techniques can bridge the performance gap between few-shot and fully supervised settings, particularly for the NDA and legal document datasets where zero-shot performance was poorest.
