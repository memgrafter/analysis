# Beyond Universal Transformer: block reusing with adaptor in Transformer for automatic speech recognition

## Quick Facts
- arXiv ID: 2303.13072
- Source URL: https://arxiv.org/abs/2303.13072
- Authors: 
- Reference count: 0
- Primary result: Achieves 9.3% CER with 7.6M parameters using block-reusing strategy

## Executive Summary
This paper introduces a block-reusing strategy for Transformer-based automatic speech recognition (ASR) to dramatically reduce model size for edge devices. The approach reuses a single Transformer block multiple times instead of using multiple independent blocks, theoretically reducing parameters to 1/M of the original model. An adapter module (ADM) is introduced to enhance representation diversity and prevent local optimization. Experiments on AISHELL-1 show that the method achieves competitive performance with significantly fewer parameters (7.6M vs 29M in baseline).

## Method Summary
The method reuses a single Transformer block multiple times in both encoder and decoder instead of using independent blocks. An adapter module (ADM) with linear and ReLU layers is inserted between repeated blocks to improve representation diversity and prevent local deterioration. The model uses CTC-ATT hybrid architecture with SpecAugment and speed perturbation. Training employs Adam optimizer with 0.002 learning rate and 25,000 warm-up steps.

## Key Results
- Block-reusing (BR) achieves 9.3% CER with only 7.6M parameters on AISHELL-1
- Adding adapter modules (BRA) improves performance to 6.63% CER with 8.3M parameters
- Pure block-reusing without ADMs leads to linear deterioration and local optimization
- The method enables extremely low-footprint ASR models suitable for resource-constrained devices

## Why This Works (Mechanism)

### Mechanism 1
Block-reusing strategy reduces parameters by sharing a single block across multiple positions in the encoder/decoder. Instead of having M independent blocks, one block is repeated M times during forward propagation, theoretically reducing total parameters to 1/M of the original model. The core assumption is that repeated blocks can effectively capture diverse representations across different positions.

### Mechanism 2
Adapter modules (ADM) inserted between repeated blocks improve representation diversity and prevent local optimization. ADMs are additional trainable parameters that modify the output of each block repetition, creating non-linear transformations that help the model escape local minima. The core assumption is that ADMs can effectively transform representations to maintain diversity across repetitions.

### Mechanism 3
Linear deterioration occurs when pure block-reusing loses non-linear representation ability. Without ADMs, repeated blocks become increasingly similar (linear) in their transformations, reducing the model's capacity to capture complex patterns. The core assumption is that the first block captures most non-linearity, and subsequent repetitions without ADMs become progressively more linear.

## Architecture Onboarding

- **Component map**: Input speech features → Encoder block 1 → ADM 1 → Encoder block 2 → ... → Encoder block M → CTC decoder + Attention decoder → Attention decoder output → ADM (if used) → Decoder block 1 → ... → Decoder block N

- **Critical path**: 1) Input features through repeated encoder blocks with ADMs 2) Encoder output to CTC and attention decoders 3) Attention decoder output through repeated decoder blocks with optional ADMs

- **Design tradeoffs**: Fewer parameters vs. potential loss of representation diversity, simpler architecture vs. need for ADMs to maintain performance, training complexity (fewer parameters) vs. potential for local minima

- **Failure signatures**: Performance degradation compared to baseline when using block-reusing without ADMs, similar representations across repeated blocks (checkable via similarity metrics), increased CER/WER despite parameter reduction

- **First 3 experiments**: 1) Implement basic block-reusing without ADMs and measure CER/WER 2) Add ADMs only to encoder and compare performance 3) Add ADMs to both encoder and decoder, measure parameter count and performance

## Open Questions the Paper Calls Out

### Open Question 1
What is the theoretical limit of parameter reduction achievable through block-reusing strategies in Transformer-based ASR models without significant performance degradation? The paper only tests one level of block-reusing (12 repeats). The trade-off curve between parameter reduction and performance degradation at different reuse factors remains unexplored.

### Open Question 2
Why does the adapter module (ADM) improve performance in block-reusing but not when added to the decoder alone? The paper shows BRA-E (ADM only in encoder) performs similarly to BRA-ED, while BRA-D (ADM only in decoder) performs worse than BR, but doesn't explain the fundamental architectural reason for this asymmetry.

### Open Question 3
What is the relationship between the "linear deterioration" phenomenon and the degradation in block-reusing models? The paper observes this phenomenon but doesn't establish whether linear deterioration is the cause, effect, or correlated with other factors in performance degradation.

## Limitations

- Implementation details are missing (position encoding, layer normalization placement, dropout rates, exact ADM implementation)
- Limited comparative analysis - no comparison with other compression techniques like pruning or quantization
- Results only on AISHELL-1 Mandarin dataset, limiting generalizability to other languages and domains

## Confidence

- **High Confidence**: The basic premise that block-reusing reduces parameters (Claim 1) is mathematically sound and trivially verifiable
- **Medium Confidence**: The CER/WER results on AISHELL-1 appear reasonable given the parameter reduction
- **Low Confidence**: The explanation of "linear deterioration" and specific mechanisms by which ADMs prevent local optimization are asserted but not rigorously proven
