# Large Language Models (GPT) Struggle to Answer Multiple-Choice Questions about Code
## Quick Facts
- arXiv ID: 2303.08033
- Source URL: https://arxiv.org/abs/2303.08033
- Reference count: 4
- Major finding: GPT models perform poorly on MCQs containing code snippets compared to natural language questions

## Executive Summary
This study evaluates the performance of GPT models on multiple-choice questions containing code snippets from programming courses. A dataset of 530 MCQs was collected from three Python courses and categorized by question type. The results demonstrate that while GPT models handle straightforward fill-in-the-blank and natural language questions reasonably well, they struggle significantly with questions requiring code analysis and reasoning. The findings suggest that current language models are not yet reliable tools for automated assessment of programming concepts, particularly for questions that test deeper understanding of code behavior.

## Method Summary
The researchers collected 530 multiple-choice questions from three Python programming courses covering introductory and intermediate topics. Questions were categorized into types including true/false, output prediction, and code completion. Three GPT models (text-davinci-001, text-davinci-002, and text-davinci-003) were evaluated on these questions using standardized prompts. Performance was measured by accuracy across different question categories to identify which types of programming questions the models could handle effectively.

## Key Results
- MCQs containing code snippets show significantly lower accuracy rates compared to natural language-only questions
- Fill-in-the-blank and code completion questions achieve the highest success rates among code-containing questions
- Questions requiring code analysis and reasoning demonstrate the poorest performance across all GPT models tested
- The performance gap between code-containing and natural language questions suggests fundamental limitations in how language models process programming constructs

## Why This Works (Mechanism)
The fundamental limitation stems from how language models process programming constructs. LLMs are trained on statistical patterns in text rather than executing or reasoning about code logic. When presented with code snippets, models rely on pattern matching from their training data rather than simulating execution or understanding the semantic meaning of programming constructs. This explains why questions requiring step-by-step analysis or output prediction perform poorly, while those with familiar syntactic patterns (like fill-in-the-blank) show better results.

## Open Questions the Paper Calls Out
The paper raises questions about whether more advanced prompt engineering techniques or larger context windows could improve performance on code-related questions. It also questions whether the fundamental architecture of current language models is inherently limited for programming tasks, or if specific training approaches could bridge this gap. The researchers suggest that understanding the specific types of reasoning failures could inform better model design for programming education applications.

## Limitations
- Limited dataset size (530 MCQs) may not capture full diversity of programming assessments
- Focus on Python programming restricts generalizability to other languages
- Only three GPT models evaluated, missing potential performance variations across architectures
- No exploration of prompt engineering techniques that might improve performance
- Does not investigate whether fine-tuning on programming-specific data could improve results

## Confidence
- High confidence: Code-containing MCQs are more challenging than natural language questions
- Medium confidence: Specific categorization of question difficulty types
- Low confidence: Generalizability to other programming languages or advanced concepts
- Low confidence: Potential for improvement through prompt engineering
