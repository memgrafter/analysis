# Benchmark of Data Preprocessing Methods for Imbalanced Classification

## Quick Facts
- arXiv ID: 2303.03094
- Source URL: https://arxiv.org/abs/2303.03094
- Reference count: 40
- Primary result: Oversampling methods generally outperform undersampling methods, with SMOTE providing the most significant gains

## Executive Summary
This paper benchmarks 16 data preprocessing methods for imbalanced classification across 23 datasets, including six cybersecurity datasets. The study systematically compares oversampling and undersampling techniques, with particular focus on SMOTE and its variants. Using Auto-Sklearn for classifier selection and multiple performance metrics, the researchers found that most preprocessing methods improve classification performance, though the baseline approach of doing nothing outperformed many methods. Oversampling methods showed consistent advantages over undersampling approaches, with SMOTE demonstrating the largest performance gains.

## Method Summary
The study evaluated 16 preprocessing methods on 23 datasets using Auto-Sklearn for classifier selection with 5-fold cross-validation. Researchers tested 82 hyperparameter configurations across oversampling (Random Oversampling, SMOTE, ADASYN, Borderline-SMOTE variants, SVM SMOTE, etc.) and undersampling methods (Random Undersampling, Tomek Links, NearMiss variants, Edited Nearest Neighbours, etc.). Performance was measured using PR AUC, ROC AUC, and P-ROC AUC, along with traditional metrics like F1 and Matthews Correlation Coefficient. Each run applied preprocessing to training data, trained classifiers via Auto-Sklearn, and evaluated on test sets.

## Key Results
- Oversampling methods generally outperformed undersampling methods in improving classification performance
- The standard SMOTE algorithm provided the most significant performance gains among all preprocessing methods
- The baseline approach of doing nothing outperformed many preprocessing methods, suggesting AutoML can handle imbalance effectively

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Oversampling methods improve classification performance more consistently than undersampling methods in imbalanced datasets.
- Mechanism: Oversampling increases the number of minority class samples, allowing classifiers to learn better decision boundaries without losing majority class information.
- Core assumption: The minority class contains useful patterns that are under-represented in the original dataset.
- Evidence anchors:
  - [abstract] "Oversampling methods generally outperform undersampling methods"
  - [section] "SMOTE, however, considers all of the minority samples to have the same importance. It does not consider prior sample density and does not care about the neighbourhood of a minority sample."
  - [corpus] Weak: Related papers focus on imbalanced learning but do not directly compare oversampling vs undersampling performance.
- Break condition: If the minority class samples are mostly noise or outliers, oversampling may amplify these errors rather than improve learning.

### Mechanism 2
- Claim: SMOTE algorithm provides the most significant performance gains among oversampling methods.
- Mechanism: SMOTE generates synthetic minority samples by interpolating between existing minority samples and their nearest neighbors, creating a more representative decision boundary.
- Core assumption: The minority class decision boundary can be approximated by linear interpolation between existing samples.
- Evidence anchors:
  - [abstract] "The most significant performance gains are brought by the standard SMOTE algorithm"
  - [section] "SMOTE [16]. It creates new synthetic examples on the line segments between existing examples from the minority class."
  - [corpus] Weak: Related papers discuss SMOTE variants but don't provide comparative performance data.
- Break condition: If the minority class has complex, non-linear boundaries, simple interpolation may not capture the true decision boundary.

### Mechanism 3
- Claim: Baseline approach of doing nothing outperformed many preprocessing methods.
- Mechanism: AutoML with appropriate performance metrics (ROC AUC, PR AUC) can learn effectively even from imbalanced data without preprocessing.
- Core assumption: The classifier's ability to optimize for imbalanced performance metrics compensates for class imbalance.
- Evidence anchors:
  - [abstract] "Baseline approach of doing nothing outperformed a large portion of methods in the benchmark"
  - [section] "We use a state-of-the-art AutoML framework Auto-Sklearn [23] for selecting, training and tuning a classifier suitable for a given dataset."
  - [corpus] Weak: Related papers focus on preprocessing methods but don't evaluate baseline performance.
- Break condition: If the dataset is extremely imbalanced or contains many noisy features, the baseline may fail to learn meaningful patterns.

## Architecture Onboarding

- Component map:
  - Datasets (23 total) -> Preprocessing methods (16 techniques) -> AutoML classifier selection -> Performance evaluation (PR AUC, ROC AUC, P-ROC AUC)

- Critical path:
  1. Load dataset
  2. Apply preprocessing method with hyperparameter configuration
  3. Train classifier using AutoML with 5-fold cross-validation
  4. Evaluate performance on test set
  5. Record results

- Design tradeoffs:
  - Using AutoML provides unbiased classifier selection but increases computational cost
  - Multiple hyperparameter configurations per method increase coverage but multiply runtime
  - Including cybersecurity datasets adds domain relevance but may limit sample size

- Failure signatures:
  - Extremely long runtime (methods taking >48 hours) indicates computational infeasibility
  - No successful runs for certain method-dataset combinations suggest method limitations
  - Baseline outperforming most methods suggests preprocessing may be unnecessary

- First 3 experiments:
  1. Run SMOTE with default parameters on a small public dataset to verify basic functionality
  2. Compare Random Oversampling vs SMOTE on a cybersecurity dataset to observe performance difference
  3. Test Random Undersampling on a dataset with moderate imbalance to understand its limitations

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do preprocessing methods perform on multi-class imbalanced classification problems compared to binary classification?
- Basis in paper: [explicit] The paper focuses exclusively on binary classification and mentions that multi-class extension is possible via one-vs-one or one-vs-rest schemes
- Why unresolved: The study only evaluates methods on binary classification datasets and doesn't provide empirical evidence for multi-class scenarios
- What evidence would resolve it: Benchmarking the same 16 preprocessing methods on multi-class imbalanced datasets using appropriate averaging strategies (micro/macro)

### Open Question 2
- Question: What is the optimal combination of preprocessing method and classifier algorithm for different types of cybersecurity datasets?
- Basis in paper: [inferred] The paper uses AutoML to automatically select classifiers, but doesn't analyze which specific classifier-preprocessing combinations work best for different cybersecurity domains
- Why unresolved: The analysis focuses on preprocessing methods independently without examining optimal classifier pairings for different cybersecurity problem types
- What evidence would resolve it: Systematic comparison of classifier-preprocessing combinations across different cybersecurity domains (network intrusion, malware, phishing, etc.)

### Open Question 3
- Question: How do preprocessing methods perform under extreme class imbalance ratios (e.g., 1:10^6) that are common in practical cybersecurity systems?
- Basis in paper: [explicit] The paper acknowledges that real-world cybersecurity systems face several orders of magnitude higher imbalance than their experimental datasets, and had to subsample datasets to create reasonable imbalance ratios
- Why unresolved: The experiment used subsampled datasets that still had much lower imbalance ratios than real systems, and the paper explicitly states they couldn't achieve more realistic imbalances due to insufficient data
- What evidence would resolve it: Testing preprocessing methods on datasets with realistic cybersecurity imbalance ratios (10^-5 to 10^-6) using large-scale production data

## Limitations

- Computational constraints prevented complete runs for all method-dataset combinations, particularly for resource-intensive methods like CNN
- Limited evaluation of preprocessing method hyperparameters beyond default settings may have missed optimal configurations
- The study's exclusive focus on tabular datasets limits generalizability to other data types like text or images

## Confidence

- High confidence: Oversampling methods generally outperform undersampling methods
- Medium confidence: SMOTE provides the most significant performance gains
- Medium confidence: Baseline approach outperforming many preprocessing methods
