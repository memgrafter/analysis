# V2X-Seq: A Large-Scale Sequential Dataset for Vehicle-Infrastructure Cooperative Perception and Forecasting

## Quick Facts
- arXiv ID: 2305.05938
- Source URL: https://arxiv.org/abs/2305.05938
- Reference count: 40
- First large-scale sequential V2X dataset for vehicle-infrastructure cooperative perception and forecasting

## Executive Summary
V2X-Seq is the first large-scale sequential dataset designed for vehicle-infrastructure cooperative perception and forecasting in autonomous driving. It contains over 15,000 frames from 95 scenarios for sequential perception and approximately 210,000 scenarios covering 672 hours of data for trajectory forecasting. The dataset enables three new tasks: VIC3D Tracking (cooperative 3D object tracking), Online-VIC Forecasting (real-time trajectory prediction), and Offline-VIC Forecasting (pre-trained trajectory prediction). A middle fusion framework called FF-Tracking is proposed to address latency challenges in cooperative perception, demonstrating superior performance compared to early and late fusion methods.

## Method Summary
The paper introduces V2X-Seq dataset and three new cooperative perception and forecasting tasks. For VIC3D Tracking, the authors propose FF-Tracking, a middle fusion framework that transmits compressed features and feature flows from infrastructure to ego-vehicle. This approach predicts future infrastructure features to align with ego-vehicle timestamps using linear estimation, effectively addressing fusion errors caused by communication delays. For trajectory forecasting, the paper introduces Online-VIC and Offline-VIC Forecasting tasks, with the latter leveraging knowledge extracted from infrastructure trajectories to improve ego-vehicle trajectory prediction.

## Key Results
- Infrastructure data significantly enhances 3D tracking performance by providing complementary views and reducing occlusions
- FF-Tracking framework demonstrates robustness to communication delays and outperforms early/late fusion methods
- Knowledge extracted from infrastructure trajectories improves trajectory forecasting performance by up to 7.65 minADE
- All fusion methods outperform no-fusion strategies when using point clouds as input, even with communication delays

## Why This Works (Mechanism)

### Mechanism 1
Infrastructure sensors positioned at elevated positions offer broader perception range and encounter fewer occlusions compared to vehicle-mounted sensors, allowing better tracking of partially or fully occluded objects.

### Mechanism 2
FF-Tracking transmits compressed features and feature flows from infrastructure to ego-vehicle, predicting future infrastructure features to align with ego-vehicle timestamp using linear estimation (Ff uture(t) = F0 + t ∗ F1).

### Mechanism 3
Offline-VIC Forecasting pre-trains models on infrastructure-view trajectories and fine-tunes on cooperative-view data, allowing the model to learn general patterns and behaviors from infrastructure data.

## Foundational Learning

- **Multi-object tracking (MOT) metrics (MOTA, MOTP, IDS)**: Used to evaluate VIC3D Tracking performance - MOTA measures overall tracking accuracy, MOTP measures object localization precision, and IDS counts identity switches
- **Feature flow prediction**: Core mechanism of FF-Tracking framework - works by transmitting feature flows to predict future infrastructure features and align with ego-vehicle timestamps
- **Trajectory forecasting metrics (minADE, minFDE, MR)**: Used to evaluate Online-VIC and Offline-VIC Forecasting - minADE measures average displacement error, minFDE measures final displacement error, and MR measures miss rate

## Architecture Onboarding

- **Component map**: V2X-Seq dataset -> VIC3D Tracking task -> Online-VIC Forecasting task -> Offline-VIC Forecasting task -> FF-Tracking framework -> Trajectory forecasting models (TNT, HiVT)
- **Critical path**: Collect and preprocess V2X-Seq dataset → Implement VIC3D Tracking task → Implement Online-VIC and Offline-VIC Forecasting tasks → Train and evaluate FF-Tracking framework → Train and evaluate trajectory forecasting models
- **Design tradeoffs**: Early fusion vs. middle fusion vs. late fusion in VIC3D Tracking; Transmission cost vs. tracking performance in FF-Tracking; Online vs. offline infrastructure data usage in trajectory forecasting
- **Failure signatures**: High latency leading to fusion errors in VIC3D Tracking; Poor infrastructure data quality; Inaccurate vector map encoding; Insufficient infrastructure data
- **First 3 experiments**: 1) Implement and evaluate early fusion, middle fusion, and late fusion methods for VIC3D Tracking; 2) Implement and evaluate FF-Tracking framework with different latency settings; 3) Implement and evaluate Online-VIC Forecasting using only ego-vehicle data, then incrementally add infrastructure data

## Limitations

- FF-Tracking's linear feature flow prediction may not generalize well to highly dynamic scenes or extreme communication delays
- Knowledge transfer in Offline-VIC Forecasting assumes similar distributions between infrastructure and ego-vehicle scenarios
- Geographic coverage and weather/lighting condition specifications are not provided, potentially limiting generalization

## Confidence

- VIC3D Tracking performance claims: Medium
- FF-Tracking latency compensation: Medium
- Offline-VIC Forecasting benefits: Low-Medium
