# Strengthening structural baselines for graph classification using Local Topological Profile

## Quick Facts
- arXiv ID: 2305.00724
- Source URL: https://arxiv.org/abs/2305.00724
- Reference count: 35
- Primary result: LTP achieves state-of-the-art results on 4 out of 9 graph classification benchmarks while being 1-3 orders of magnitude faster than LDP baseline

## Executive Summary
This paper introduces Local Topological Profile (LTP), an extension of the Local Degree Profile (LDP) baseline that incorporates additional topological descriptors including edge betweenness centrality, Jaccard index, and local degree score. The method aggregates these features into histograms to create fixed-length graph representations that are invariant to node ordering. Evaluated on 9 benchmark datasets using Random Forest classifiers, LTP matches or exceeds the performance of recent Graph Neural Networks while offering significant computational advantages. The authors provide open-source implementation and demonstrate that proper baseline methods can be competitive with more complex deep learning approaches.

## Method Summary
LTP extends LDP by computing histograms of degree statistics, edge betweenness centrality, Jaccard index, and local degree score for each graph. For each node, degree statistics (min, max, mean, std of neighbor degrees) are calculated and aggregated into histograms. Edge betweenness centrality identifies important edges, Jaccard index measures neighborhood overlap, and local degree score captures hub relationships. These histograms serve as fixed-length feature vectors for Random Forest classification. The method uses Networkit library for efficient parallel computation of topological descriptors, achieving 1-3 orders of magnitude speedup compared to NetworkX-based LDP implementation.

## Key Results
- LTP outperforms or closely matches latest GNNs on 4 out of 9 benchmark datasets
- Achieves state-of-the-art results on DD, NCI1, PROTEINS, and REDDIT-B datasets
- Runs 1-3 orders of magnitude faster than the original LDP approach
- Random Forest classifier outperforms SVM for LTP features in terms of both accuracy and speed
- Provides competitive performance on topology-only graph classification tasks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: LTP improves classification accuracy by combining multiple topological descriptors into a single histogram-based representation.
- Mechanism: LDP uses degree statistics for each node, then adds edge betweenness centrality, Jaccard Index, and Local Degree Score. Each descriptor captures different aspects of graph structure (local connectivity, edge importance, neighborhood overlap, hub relationships). Aggregating these into histograms preserves distributional information while maintaining computational efficiency.
- Core assumption: Histograms of these descriptors are sufficient to capture discriminative graph structure for classification tasks.
- Evidence anchors:
  - [abstract]: "LTP uses histograms of degree statistics, edge betweenness centrality, Jaccard index, and local degree score to capture local and global topological features of graphs."
  - [section]: "For each node, we calculate the following statistics: degree(v), min(DN), max(DN), mean(DN), std(DN). They are then aggregated for the whole graph by calculating a histogram or empirical distribution function (EDF) over each feature."
- Break condition: If the histograms become too high-dimensional relative to dataset size, or if the selected descriptors fail to capture class-specific structural patterns.

### Mechanism 2
- Claim: Random Forest classifier outperforms SVM for LDP-based features due to better handling of high-dimensional, non-linear feature spaces.
- Mechanism: RF uses multiple decision trees trained in parallel, each using a random subset of features. This reduces overfitting risk from high-dimensional histograms and avoids expensive kernel computations required by SVM.
- Core assumption: Decision trees can effectively split on histogram features without requiring kernel transformations.
- Evidence anchors:
  - [abstract]: "LTP is also 1-3 orders of magnitude faster than the original LDP approach, while being more accurate and scalable."
  - [section]: "We propose to change SVM to a Random Forest (RF) classier. It is bagging ensemble of decision trees, which means that each tree can be trained independently in parallel, increasing scalability."
- Break condition: If dataset contains too few samples relative to feature dimensions, leading to overfitting despite RF's ensemble approach.

### Mechanism 3
- Claim: Networkit library implementation provides 1-2 orders of magnitude speedup over NetworkX for descriptor computation.
- Mechanism: Networkit uses parallel C++ implementations with optimized algorithms, while NetworkX uses sequential Python code. Parallel computation across CPU cores dramatically reduces time for expensive graph algorithms like edge betweenness centrality.
- Core assumption: Modern multi-core processors can effectively parallelize descriptor computation without significant overhead.
- Evidence anchors:
  - [abstract]: "LTP is also 1-3 orders of magnitude faster than the original LDP approach"
  - [section]: "Instead, we propose to use Networkit [25], a parallelized C++ library. This way, we are able to utilize modern CPUs with multiple cores and compute descriptors in parallel."
- Break condition: If graph sizes become extremely large or dense, causing memory bottlenecks that negate parallelization benefits.

## Foundational Learning

- Concept: Graph isomorphism invariance
  - Why needed here: LDP and LTP features must be invariant to node relabeling to be meaningful graph representations
  - Quick check question: Why can we compare degree histograms across graphs with different node orderings?

- Concept: Histogram aggregation as graph embedding
  - Why needed here: Converting graph structure to fixed-length vectors requires aggregating node/edge features across the entire graph
  - Quick check question: How does histogram binning affect the discriminative power of the final feature vector?

- Concept: Centrality measures and their interpretations
  - Why needed here: Understanding what edge betweenness, Jaccard Index, and Local Degree Score capture is crucial for feature selection
  - Quick check question: What structural property does high edge betweenness indicate in a graph?

## Architecture Onboarding

- Component map: Graph loading (PyTorch Geometric) → Descriptor computation (Networkit) → Histogram aggregation → Random Forest training (Scikit-learn)
- Critical path: Feature extraction time dominates for large graphs; optimization should focus on parallel descriptor computation
- Design tradeoffs:
  - More descriptors → higher accuracy but increased computation and potential overfitting
  - More histogram bins → better resolution but higher dimensionality
  - Networkit vs NetworkX → massive speedup but requires C++ library
- Failure signatures:
  - Runtime errors: Networkit not installed or incompatible graph format
  - Memory errors: Very large graphs exceeding available RAM during descriptor computation
  - Poor accuracy: Selected descriptors don't capture discriminative features for specific dataset
- First 3 experiments:
  1. Run LTP on DD dataset with default parameters to verify basic functionality
  2. Compare RF vs SVM on NCI1 dataset to confirm speedup and accuracy improvement
  3. Test single descriptor addition (EBC only) on PROTEINS to measure impact of individual features

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do additional topological descriptors beyond the three currently used (EBC, JI, LDS) affect the discriminative power and scalability of LTP?
- Basis in paper: [explicit] The authors mention plans to extend the number of vertex/edge descriptors and enrich LTP towards more global features such as eccentricity.
- Why unresolved: The paper only evaluated three specific descriptors and did not explore the full space of possible descriptors.
- What evidence would resolve it: Systematic experiments adding different combinations of additional descriptors and measuring their impact on accuracy, computational time, and scalability across various graph datasets.

### Open Question 2
- Question: Can LTP be effectively extended to handle attributed graphs with node/edge features, or is it inherently limited to topology-only classification?
- Basis in paper: [inferred] The paper notes that LTP achieves strong results on topology-only tasks but acknowledges that on bioinformatics datasets with node features, purely feature-based baselines outperform it.
- Why unresolved: The current LTP implementation and evaluation only considers graph topology, not node/edge attributes that are common in many real-world datasets.
- What evidence would resolve it: Experiments comparing LTP variants that incorporate node/edge features against state-of-the-art attributed GNNs on attributed graph datasets.

### Open Question 3
- Question: What is the theoretical relationship between LTP's discriminative power and the Weisfeiler-Lehman test of graph isomorphism?
- Basis in paper: [explicit] The authors reference that GIN was designed to be as powerful as the Weisfeiler-Lehman test, and they compare LTP to GIN.
- Why unresolved: While empirical comparisons are provided, there is no theoretical analysis of LTP's ability to distinguish non-isomorphic graphs compared to the WL test.
- What evidence would resolve it: Formal proof or counterexample showing whether LTP can distinguish all graph pairs that the WL test can, or identification of specific graph structures that differentiate the two approaches.

## Limitations
- Histogram aggregation may lose fine-grained structural information compared to more sophisticated graph representations
- Computational advantage heavily depends on Networkit library's parallel implementation, which may not scale optimally for extremely large or dense graphs
- Assumes distributional statistics of local features are sufficient for classification, potentially missing global graph properties

## Confidence
- State-of-the-art performance claims (4/9 datasets): **High confidence** - Supported by rigorous 10-fold cross-validation and fair evaluation framework
- Speed improvement claims (1-3 orders of magnitude): **Medium confidence** - Based on single implementation comparison; depends on hardware and graph characteristics
- Feature effectiveness claims: **Medium confidence** - Limited ablation studies; doesn't test all possible descriptor combinations
