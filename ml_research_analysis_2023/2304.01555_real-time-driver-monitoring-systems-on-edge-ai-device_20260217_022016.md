# Real-time Driver Monitoring Systems on Edge AI Device

## Quick Facts
- arXiv ID: 2304.01555
- Source URL: https://arxiv.org/abs/2304.01555
- Reference count: 8
- Primary result: Edge AI-based DMS achieves 63 FPS on TI-TDA4VM, exceeding 30 FPS target

## Executive Summary
This paper presents a real-time Driver Monitoring System (DMS) deployed on the TI-TDA4VM edge AI device. The system uses infrared camera input processed by deep learning models for face detection and facial landmark localization to monitor driver attention. The key innovation is "model surgery" - adapting deep learning models to run entirely on the device's hardware accelerator, eliminating CPU offloading and data transfer overhead. This optimization achieved significant speed improvements, with face detection increasing from 121.55 to 259.84 FPS and landmark detection from 163.60 to 500.97 FPS, enabling the final system to run at 63 FPS.

## Method Summary
The DMS system processes infrared camera input using two deep learning models: YOLOX-tiny for face detection and PFLD for facial landmark detection. Model surgery was performed to ensure all model layers could run on the device's hardware accelerator, replacing unsupported operators like channel-wise padding with equivalent operations and removing dequantization steps. Both models were quantized to 8-bit integer precision to optimize inference speed. The architecture was designed to maximize throughput while maintaining accuracy, with careful attention to minimizing data transfer between the accelerator and CPU.

## Key Results
- Face detection model achieved 259.84 FPS after model surgery (up from 121.55 FPS)
- Facial landmark model achieved 500.97 FPS after model surgery (up from 163.60 FPS)
- Complete DMS system runs at 63 FPS, exceeding the 30 FPS target
- All processing occurs on-device using 8-bit quantized models on TI-TDA4VM hardware accelerator

## Why This Works (Mechanism)
The system achieves real-time performance through comprehensive model surgery that ensures all operations run on the hardware accelerator without CPU offloading. By replacing unsupported operators and removing unnecessary dequantization steps, the models maintain full compatibility with the accelerator while maximizing throughput. Quantization to 8-bit integer precision further reduces computational requirements without significant accuracy loss. This approach eliminates data transfer bottlenecks between CPU and accelerator, enabling the system to process video frames at rates well above the required 30 FPS threshold.

- **Hardware accelerator optimization**: Ensures all model operations are compatible with accelerator capabilities - needed to avoid CPU offloading; quick check: profile execution time per layer
- **Operator substitution**: Replaces unsupported operations (e.g., channel-wise padding) with equivalent supported ones - needed for full accelerator compatibility; quick check: verify numerical equivalence of substituted operations
- **Inference pipeline optimization**: Minimizes data movement between memory and processing units - needed to reduce latency; quick check: measure data transfer overhead with and without optimization

- **Edge AI deployment constraints**: Limited computational resources and power budget compared to cloud systems - needed to guide optimization decisions; quick check: monitor power consumption during operation

## Architecture Onboarding

**Component map:** Infrared camera -> Preprocessing -> YOLOX-tiny face detection -> PFLD landmark detection -> Attention analysis

**Critical path:** Camera capture → preprocessing → accelerator inference → result aggregation → driver attention classification

**Design tradeoffs:** The system prioritizes speed over marginal accuracy gains, accepting quantized 8-bit models to achieve 63 FPS. This choice favors real-time responsiveness essential for driver safety over potential improvements from higher precision or larger models. The architecture also trades model complexity for on-device execution, avoiding cloud connectivity for privacy and latency reasons.

**Failure signatures:** Performance degradation may occur under low-light conditions (despite IR camera), partial face occlusions, extreme head angles, or when multiple faces are present. Hardware-specific failures could arise from unsupported operators in models not properly adapted for the accelerator, resulting in CPU fallback and reduced FPS.

## Limitations
- No detailed ablation studies quantifying individual impact of optimization steps on performance and accuracy
- Quantized model accuracy retention not validated against full-precision baselines with standard metrics
- System robustness not evaluated across diverse real-world conditions (lighting, occlusions, camera angles)
- Performance claims lack validation of detection accuracy under typical driving scenarios

## Confidence
**High confidence** in core FPS measurements and model surgery methodology, as these are straightforward technical achievements with reproducible benchmarks. **Medium confidence** in real-world effectiveness due to limited scenario testing and absence of accuracy validation under typical driving conditions. The technical approach is sound but generalizability to other hardware platforms and model architectures remains untested.
