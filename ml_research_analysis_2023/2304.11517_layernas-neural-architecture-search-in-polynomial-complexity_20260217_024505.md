# LayerNAS: Neural Architecture Search in Polynomial Complexity

## Quick Facts
- arXiv ID: 2304.11517
- Source URL: https://arxiv.org/abs/2304.11517
- Authors: 
- Reference count: 40
- Key outcome: LayerNAS reduces neural architecture search complexity from exponential to polynomial by performing layerwise search with cost grouping

## Executive Summary
LayerNAS is a novel neural architecture search method that transforms multi-objective NAS into a combinatorial optimization problem, achieving polynomial complexity O(H·|S|·L) instead of exponential complexity. The method performs layerwise search, selecting from a set of options for each layer, and groups model candidates by one objective (e.g., size or latency) while searching for optimal models based on another. LayerNAS consistently discovers superior models across various search spaces, including MobileNetV2 and MobileNetV3, achieving 69.0% top-1 accuracy on ImageNet for 61M MAdds, a 1.6% improvement over MobileNetV3-Small.

## Method Summary
LayerNAS addresses the computational intractability of neural architecture search by transforming it into a polynomial-complexity problem through layerwise search and cost grouping. The algorithm performs sequential search from the first layer to the last, storing model candidates by their cost metric value and searching for optimal models under different constraints in each subsequent layer. This approach splits the cost and reward elements of the search, reducing complexity from exponential to polynomial while maintaining the ability to discover high-quality models. The method is validated across multiple search spaces and shows consistent improvements over strong baselines.

## Key Results
- Achieves 69.0% top-1 accuracy on ImageNet for 61M MAdds, a 1.6% improvement over MobileNetV3-Small
- Reduces search complexity from exponential to polynomial (O(H·|S|·L)) while maintaining or improving model quality
- Outperforms other NAS algorithms on NATS-Bench in terms of best model quality, stability, and efficiency

## Why This Works (Mechanism)

### Mechanism 1
- Claim: LayerNAS reduces search complexity from exponential to polynomial by transforming multi-objective NAS into a combinatorial optimization problem.
- Mechanism: By grouping model candidates based on one objective (e.g., model size or latency) and searching for optimal models based on another objective, LayerNAS splits the cost and reward elements of the search, limiting complexity to O(H·|S|·L).
- Core assumption: Optimal models when searching for layer i can be constructed from one of the models in layer i-1 (Assumption 4.1).
- Evidence anchors:
  - [abstract]: "LayerNAS groups model candidates by one objective (e.g., size or latency) and searches for optimal models based on another, limiting search complexity to O(H·|S|·L) where H is a constant."
  - [section]: "For a model architecture with L layers, we perform layerwise-search for each layer, selecting from a set of search options S."
- Break condition: If the assumption that optimal models can be constructed from previous layer models is violated, the sequential search order and polynomial complexity guarantee fail.

### Mechanism 2
- Claim: LayerNAS effectively handles multi-objective NAS problems by treating model constraints and model quality as separate metrics.
- Mechanism: Instead of using a single objective function that combines multiple objectives, LayerNAS stores model candidates by their constraint metric value and searches for optimal models under different constraints in the next layer.
- Core assumption: The optimal model Mi with cost = C when searching for layer i can be constructed from the optimal model Mi-1 with cost = C - Cost(si) from Mi-1 (Assumption 4.2).
- Evidence anchors:
  - [abstract]: "LayerNAS groups model candidates based on one objective, such as model size or latency, and searches for the optimal model based on another objective, thereby splitting the cost and reward elements of the search."
  - [section]: "LayerNAS stores model candidates by their constraint metric value. Let Mi,h be the best model candidate for layer i with cost = h."
- Break condition: If the accuracy varies significantly across training trials, the stored model candidates may not represent the true optimal models, reducing search effectiveness.

### Mechanism 3
- Claim: LayerNAS achieves consistent discovery of superior models across various search spaces by leveraging layerwise attributes.
- Mechanism: The algorithm enforces a directional search process from the first layer to the last layer, using a priori knowledge about the search space structure to reduce the number of candidates that need to be searched.
- Core assumption: Search spaces constructed in a layerwise manner can usually meet the assumption that optimal models on layer i can be constructed from models on layer i-1.
- Evidence anchors:
  - [abstract]: "Our experiments show that LayerNAS is able to consistently discover superior models across a variety of search spaces in comparison to strong baselines, including search spaces derived from NATS-Bench, MobileNetV2 and MobileNetV3."
  - [section]: "Search spaces that are constructed in a layerwise manner, such as those in size search problems discussed in Section 3, can usually meet this assumption."
- Break condition: If the search space cannot be transformed to satisfy the layerwise assumption (e.g., in scale search problems where hyper-parameters are interdependent), LayerNAS may not be applicable.

## Architecture Onboarding

- Component map:
  Layerwise Search Engine -> Cost Grouping Module -> Dynamic Programming Table -> Search Space Constructor

- Critical path:
  1. Initialize M1 with all possible models for layer 1.
  2. For each layer l from 1 to L-1:
     a. Select a model candidate from Ml.
     b. Apply search options from Sl+1 to generate Ml+1.
     c. Calculate the cost of each generated model and map it to a bucket h using Equation (4).
     d. Update Ml+1,h with the best model candidate for each cost bucket.
  3. Return the best model candidate from ML.

- Design tradeoffs:
  - Number of cost buckets (H): A larger H allows for more precise cost grouping but increases memory usage. A smaller H reduces memory usage but may group models with significantly different costs together.
  - Number of model candidates to store per cost bucket: Storing more candidates increases the likelihood of keeping the better model architecture but also increases memory usage and search time.

- Failure signatures:
  - If the search space cannot be transformed to satisfy LayerNAS assumptions, the algorithm may not find optimal models or may fail to converge.
  - If the cost grouping is too coarse (small H), the algorithm may miss models with optimal cost-quality tradeoffs.
  - If the number of candidates to store per cost bucket is too small, the algorithm may not capture the variability in model quality due to training noise.

- First 3 experiments:
  1. Implement LayerNAS on a simple search space (e.g., 3 layers with 2 search options each) and verify that it finds the optimal model with lower search complexity than exhaustive search.
  2. Apply LayerNAS to a search space derived from MobileNetV2 and compare the discovered models' performance against baseline models and other NAS algorithms.
  3. Evaluate LayerNAS on NATS-Bench size search task, measuring the quality of the best candidate found, the stability of the search process, and the efficiency of the algorithm.

## Limitations
- The algorithm relies on specific search space assumptions (layerwise construction) that may not generalize to all NAS problems
- Short 5-epoch search training period may not reliably identify high-quality models due to training noise
- Performance on scale search problems with interdependent hyperparameters remains unexplored and potentially problematic

## Confidence
- **High confidence**: The theoretical framework for reducing NAS complexity from exponential to polynomial through layerwise search is well-founded and mathematically sound
- **Medium confidence**: The experimental results showing LayerNAS outperforming baselines on ImageNet and NATS-Bench are promising but limited by the short search training duration
- **Low confidence**: The claim that LayerNAS can be universally applied across all search space types without modification requires further validation
