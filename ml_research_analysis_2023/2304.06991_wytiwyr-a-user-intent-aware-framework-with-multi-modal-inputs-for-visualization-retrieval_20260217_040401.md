# WYTIWYR: A User Intent-Aware Framework with Multi-modal Inputs for Visualization Retrieval

## Quick Facts
- arXiv ID: 2304.06991
- Source URL: https://arxiv.org/abs/2304.06991
- Reference count: 17
- Outperforms existing methods in F1-scores for retrieval with significant improvements in top-K rankings

## Executive Summary
WYTIWYR introduces a novel user intent-aware framework for visualization retrieval that addresses the limitation of existing methods focusing solely on visual similarity. The framework consists of two stages: Annotation, which disentangles visual attributes in the query chart, and Retrieval, which embeds user intent with customized text prompts to retrieve targeted results. By leveraging a contrastive language-image pre-training (CLIP) model for zero-shot classification and multi-modal input encoding, WYTIWYR demonstrated superior performance in quantitative experiments, case studies, and qualitative interviews. The framework enables flexible combination of attributes and incorporation of user intent, allowing for more diverse and relevant retrieval results.

## Method Summary
WYTIWYR is a two-stage framework for chart retrieval. The first stage (Annotation) uses ResNet50 classifiers with Focal Loss for primary attributes (Type, Color, Trend, Layout) and CLIP-based zero-shot classification for extended attributes. The second stage (Retrieval) implements an intent-aware filter that removes charts lacking selected attributes, followed by multi-modal encoding of the query chart and user intent text prompt using CLIP's image and text encoders. The framework computes cosine similarity between the joint representation and candidate chart features to produce ranked results. The method was evaluated on a corpus of 33,260 bitmap charts from Beagle and Pinterest.

## Key Results
- Outperforms existing methods in F1-scores for retrieval with significant improvements in top-K rankings
- Enables flexible combination of visual attributes through disentanglement into primary and extended categories
- Allows incorporation of user intent via text prompts, improving retrieval relevance beyond visual similarity

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Disentangling visual attributes into primary and extended categories enables flexible combination of attributes in retrieval.
- Mechanism: By training separate classifiers for primary attributes (Type, Color, Trend, Layout) and using CLIP for zero-shot classification of extended attributes, the framework can extract both explicit and implicit visual features independently. This allows users to select any subset of attributes for retrieval, conditioning the search on their specific intent.
- Core assumption: Visual attributes can be meaningfully separated and independently classified without loss of semantic coherence.
- Evidence anchors:

  - [section] "To better understand user intents, we conducted a comprehensive study to categorize chart attributes."

### Mechanism 2
- Claim: Multi-modal encoding of query chart and user intent text prompt improves retrieval relevance compared to image-only methods.
- Mechanism: The framework uses CLIP's image and text encoders to create a joint representation that combines visual features from the query chart with semantic intent from text prompts. This multi-modal feature is then compared with candidate chart features using cosine similarity.
- Core assumption: Visual and textual information can be meaningfully combined in a shared embedding space to capture user intent.
- Evidence anchors:
  - [abstract] "The Retrieval stage digests both query chart and user intent as multi-modal inputs to get target retrieval results."
  - [section] "The multi-modal encoder integrates Q and IP as a joint representation."

### Mechanism 3
- Claim: Intent-aware filtering based on selected attributes narrows the search space and improves retrieval precision.
- Mechanism: After attribute disentanglement, users select intent attributes (IA) which condition an intent-aware filter that removes charts lacking these attributes from the database. This reduces the candidate set before similarity computation.
- Core assumption: Filtering based on explicit attributes significantly reduces irrelevant candidates without removing relevant ones.

  - [section] "The intent-aware filter rules out irrelevant charts in the database and forms the candidate feature."

## Foundational Learning

- Concept: Contrastive Language-Image Pre-training (CLIP)
  - Why needed here: CLIP provides the foundation for both zero-shot attribute classification and multi-modal encoding of chart images with text prompts.
  - Quick check question: How does CLIP align visual and textual representations in a shared embedding space?

- Concept: Zero-shot classification
  - Why needed here: Allows the framework to classify extended attributes that weren't seen during training by using natural language labels.
  - Quick check question: What enables CLIP to classify categories it wasn't explicitly trained on?

- Concept: Cosine similarity for feature matching
  - Why needed here: Provides a normalized metric for comparing multi-modal features and ensuring consistent similarity scoring.
  - Quick check question: Why is cosine similarity preferred over Euclidean distance for high-dimensional embeddings?

## Architecture Onboarding

- Component map:
  Query chart -> Redundant information removal -> Primary attribute classification -> Extended attribute classification -> User attribute selection -> Intent-aware filtering -> Multi-modal encoding -> Similarity computation -> Ranked results

- Critical path:
  Query chart → Redundant information removal → Primary attribute classification → Extended attribute classification → User attribute selection → Intent-aware filtering → Multi-modal encoding → Similarity computation → Ranked results

- Design tradeoffs:
  - Flexibility vs. complexity: Allowing arbitrary attribute combinations increases flexibility but complicates the retrieval pipeline
  - Pre-trained vs. fine-tuned models: Using CLIP avoids training costs but may have domain misalignment
  - Real-world vs. synthetic data: Real charts are more diverse but noisier than synthetic alternatives

- Failure signatures:
  - Poor attribute classification accuracy (misidentifying chart types or visual properties)
  - Intent-aware filter removing too many or too few candidates
  - Multi-modal encoding failing to capture the relationship between text prompts and visual features
  - Similarity scores not correlating with human judgment of relevance

- First 3 experiments:
  1. Test attribute classification accuracy on a held-out set of charts with known attributes
  2. Compare retrieval results with and without intent filtering to measure precision improvement
  3. Evaluate the impact of different text prompt formulations on retrieval relevance using user studies

### Open Question 2
- Question: How can the effectiveness of text prompts be improved in the context of visualization retrieval, given the limitations of the CLIP model trained primarily on natural images?
- Basis in paper: [explicit] The paper discusses the challenges of prompt design and the limitations of the CLIP model in interpreting expert expressions for the visualization domain, using a case study to illustrate the impact of different prompts on retrieval results.
- Why unresolved: While the paper acknowledges these limitations and suggests potential solutions like fine-tuning the CLIP model or using advanced language-image models, it does not provide a concrete implementation or evaluation of these approaches.
- What evidence would resolve it: An evaluation comparing the effectiveness of different prompt design strategies, fine-tuned CLIP models, or alternative language-image models on visualization retrieval tasks, demonstrating improved performance in handling domain-specific expressions and concepts.

## Limitations

- Effectiveness depends on quality of attribute classification, which may not generalize to charts with complex layouts or novel visualization types
- Reliance on CLIP introduces potential domain misalignment as it was trained on general web images rather than specialized visualization content
- User study sample size (n=8) and lack of accessibility testing represent significant limitations for usability claims

## Confidence

- **High confidence** in the core retrieval mechanism: The two-stage architecture (Annotation + Retrieval) is well-defined and the use of established models (ResNet50, CLIP) provides a solid foundation. The quantitative results showing improved F1-scores over baselines are compelling.

- **Medium confidence** in attribute disentanglement effectiveness: While the framework separates primary and extended attributes systematically, the evidence for whether this separation meaningfully improves retrieval relevance compared to unified approaches is limited. The paper demonstrates that disentanglement is possible but doesn't conclusively show it's necessary or superior.

- **Low confidence** in generalization claims: The evaluation corpus, while large, comes from specific sources (Beagle, Pinterest) and may not represent the full diversity of visualization designs. Claims about handling "diverse" queries are supported by case studies but lack systematic testing across varied chart types and domains.

## Next Checks

1. **Cross-domain robustness test**: Evaluate the framework on charts from different domains (scientific publications, business dashboards, academic presentations) to assess generalization beyond the training corpus.

2. **Attribute classification stress test**: Systematically evaluate classifier performance on edge cases including charts with multiple overlapping attributes, unconventional color schemes, and novel chart types not present in the original dataset.

3. **Ablation study on intent filtering**: Compare retrieval results with intent-aware filtering disabled versus enabled across different user query types to quantify the actual contribution of the filtering mechanism to retrieval precision.
