# ContrastNER: Contrastive-based Prompt Tuning for Few-shot NER

## Quick Facts
- arXiv ID: 2305.17951
- Source URL: https://arxiv.org/abs/2305.17951
- Reference count: 40
- Key outcome: ContrastNER achieves competitive performance to SOTA NER methods in high-resource settings and outperforms existing models in low-resource scenarios across multiple datasets.

## Executive Summary
This paper presents ContrastNER, a prompt-based model for named entity recognition (NER) in few-shot learning scenarios. The key innovation is the use of a soft-hard prompt tuning technique that combines continuous and discrete prompts, eliminating the need for manual prompt engineering. Additionally, ContrastNER employs contrastive learning to unify the learning of the soft-hard prompt and the prediction of entity types without requiring a verbalizer. Experimental results demonstrate that ContrastNER achieves competitive performance to state-of-the-art NER methods in high-resource settings and outperforms existing models in low-resource scenarios across multiple datasets, including CoNLL03, MIT Restaurant Review, MIT Movie Review, and Airline Travel Information Systems.

## Method Summary
ContrastNER reformulates NER as a prompt-based masked language modeling task using soft-hard prompts (combining continuous and discrete tokens) and contrastive learning for label prediction. The model transforms input sentences by appending soft tokens and a masked hard prompt "[candidate_entity] is a [MASK] entity", then optimizes both soft tokens and label embeddings jointly using a weighted combination of contrastive loss and cross-entropy loss.

## Key Results
- ContrastNER achieves competitive performance to SOTA NER methods in high-resource settings
- Outperforms existing models in low-resource scenarios across multiple datasets
- Eliminates need for manual prompt engineering and verbalizer design

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Soft-hard prompt tuning combines continuous soft prompts with discrete hard prompts to automatically search for optimal prompt templates without manual engineering.
- Mechanism: The model transforms each input word into a sentence containing the original word, a sequence of continuous soft tokens, and a masked hard prompt "[candidate_entity] is a [MASK] entity". During training, the soft tokens and the masked hard token are jointly optimized, with the soft tokens providing flexibility and the hard tokens maintaining semantic structure.
- Core assumption: Continuous tokens can be learned to complement discrete templates effectively, and the combination improves over either approach alone.
- Evidence anchors:
  - [abstract]: "employs both discrete and continuous tokens in prompts"
  - [section]: "we propose the soft-hard prompt, where we use both soft (continuous) and hard (discrete) prompts in the fine-tuning paradigm"
  - [corpus]: Weak - no direct corpus evidence comparing soft-hard vs pure soft or pure hard.
- Break condition: If the continuous tokens fail to align with the semantic intent of the discrete template, or if the discrete template is too restrictive, the joint optimization may diverge or produce poor prompts.

### Mechanism 2
- Claim: Contrastive learning unifies prompt learning and entity type prediction without requiring a verbalizer.
- Mechanism: Instead of mapping a predicted token through a verbalizer to a label, the model learns to predict an embedding for the label directly. Positive examples share the same label, negative examples have different labels. The contrastive loss pulls embeddings of same-label examples together and pushes different-label examples apart.
- Core assumption: Label embeddings can be learned directly in the embedding space and that semantic similarity in this space aligns with label equivalence.
- Evidence anchors:
  - [abstract]: "uses a contrastive learning approach to learn the continuous prompts and forecast entity types"
  - [section]: "we employ contrastive learning to combine learning the soft-hard prompt and predicting the entity type without explicitly designing a verbalizer"
  - [corpus]: Weak - no corpus evidence on contrastive vs verbalizer-based mapping performance.
- Break condition: If the label embedding space becomes collapsed or if the number of labels is very large, the contrastive objective may fail to separate classes effectively.

### Mechanism 3
- Claim: The overall loss combines contrastive loss for label prediction with cross-entropy loss for soft prompt tuning, weighted by hyperparameter λ.
- Mechanism: During training, the model optimizes both the label embedding (via contrastive loss) and the soft prompt parameters (via cross-entropy). The weighted sum balances learning entity type discrimination with prompt optimization.
- Core assumption: Both objectives are compatible and jointly optimizing them does not cause interference or instability.
- Evidence anchors:
  - [section]: "we define the overall loss function L as the weighted average of LC and LS"
  - [section]: "L = λLC + (1 − λ)LSP"
  - [corpus]: No direct corpus evidence on the effect of varying λ or ablation of one loss component.
- Break condition: If λ is set too high, prompt tuning may be neglected; if too low, label discrimination may suffer. Imbalance could lead to degraded performance on either objective.

## Architecture Onboarding

- Component map: Input sentence -> Template transformation (soft-hard prompt) -> PLM backbone -> Contrastive loss (label embedding) + Cross-entropy loss (soft prompt) -> Updated soft tokens and PLM parameters
- Critical path: Template creation -> Soft token optimization -> Label embedding via contrastive loss -> Entity type prediction
- Design tradeoffs: Soft tokens add learnable parameters but avoid manual prompt engineering; contrastive loss removes verbalizer but requires careful label embedding space design; combining both objectives may complicate optimization.
- Failure signatures: Poor entity recognition despite high training accuracy may indicate label embedding collapse; unstable soft token updates may suggest template mismatch; high variance across random seeds may indicate sensitivity to initialization.
- First 3 experiments:
  1. Ablation: Remove soft tokens (pure hard prompt) and compare performance to verify soft-hard benefit.
  2. Ablation: Replace contrastive loss with verbalizer mapping and compare to confirm removal of verbalizer is effective.
  3. Hyperparameter sweep: Vary λ (weight between contrastive and cross-entropy loss) and τ (temperature in contrastive loss) to find stable settings.

### Open Question 2
- Question: How does ContrastNER perform on extremely low-resource settings (e.g., 1-5 examples per entity type)?
- Basis in paper: [inferred] The paper tests up to 10 examples per entity type but doesn't explore scenarios with fewer examples.
- Why unresolved: The paper's evaluation focuses on settings with at least 10 examples per entity type, leaving the extremely few-shot regime unexplored.
- What evidence would resolve it: Experiments testing ContrastNER with 1, 3, and 5 examples per entity type across multiple datasets to determine its lower bound performance.

### Open Question 3
- Question: What is the impact of different temperature values (τ) in the contrastive loss function on ContrastNER's performance?
- Basis in paper: [explicit] The paper sets τ = 2 but acknowledges it as a hyperparameter without exploring its sensitivity.
- Why unresolved: The paper uses a fixed temperature value without investigating how different values affect model performance.
- What evidence would resolve it: Systematic ablation studies varying τ (e.g., 0.1, 0.5, 1, 2, 5) and measuring the resulting performance changes across different datasets and few-shot scenarios.

## Limitations

- Limited error analysis and comparison with strong baselines like generative LLMs
