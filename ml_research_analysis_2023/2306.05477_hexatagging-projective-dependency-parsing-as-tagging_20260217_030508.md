# Hexatagging: Projective Dependency Parsing as Tagging

## Quick Facts
- arXiv ID: 2306.05477
- Source URL: https://arxiv.org/abs/2306.05477
- Reference count: 34
- Primary result: Hexatagging achieves state-of-the-art performance on the Penn Treebank test set with 10x decoding speedup

## Executive Summary
This paper introduces hexatagging, a novel approach to projective dependency parsing that frames the task as a tagging problem using only six distinct tag types. The method represents dependency trees as binary head trees (BHTs) which are then linearized into hexatag sequences. A probabilistic parser predicts these hexatags using a linear model with features from a pretrained language model. Despite its simplicity, hexatagging achieves state-of-the-art performance on English Penn Treebank while offering significant efficiency gains, running approximately 10 times faster than previous state-of-the-art models during decoding.

## Method Summary
Hexatagging converts dependency parsing into a sequence labeling task by representing dependency trees as binary head trees. The method linearizes these trees into sequences of hexatags (six distinct tag types) that encode head-dependent relationships. A probabilistic dependency parser predicts hexatags using a linear model that leverages features from a pretrained language model. This approach enables fully parallelizable training and decoding while maintaining competitive accuracy. The parser's linear time complexity and efficient parallelization contribute to its significant speed advantages over traditional parsing approaches.

## Key Results
- Achieves state-of-the-art performance on the English Penn Treebank test set
- Provides approximately 10x speed-up during decoding compared to previous state-of-the-art models
- Outperforms parsers with more complex architectures and extra annotations despite using a simpler linear model
- Demonstrates the effectiveness of representing dependency trees as binary head trees for tagging-based parsing

## Why This Works (Mechanism)
Hexatagging works by transforming the structured prediction problem of dependency parsing into a simpler sequence labeling task. The binary head tree representation provides a canonical form that can be efficiently linearized into hexatag sequences. The six-tag vocabulary is sufficient to encode all necessary head-dependent relationships in projective trees while maintaining a constant tag space. The pretrained language model features provide rich contextual information that compensates for the simplicity of the linear prediction model. This combination of efficient representation and strong feature extraction enables both high accuracy and fast inference.

## Foundational Learning
- Binary Head Trees (BHT): A tree representation where each node has at most two children, used to canonicalize dependency structures - needed for efficient linearization into tag sequences; quick check: verify BHT construction preserves all dependency relationships
- Hexatag vocabulary: Six distinct tags that encode head-dependent relationships - needed to maintain constant tag space while representing all projective dependencies; quick check: ensure all possible head directions are covered by the six tags
- Linear model with PLM features: Simple prediction model using pretrained language model embeddings - needed to balance model complexity with performance; quick check: verify feature extraction captures sufficient syntactic information

## Architecture Onboarding

Component map:
Input sentence -> PLM feature extraction -> Hexatag prediction (linear model) -> Binary head tree reconstruction -> Dependency tree output

Critical path:
Sentence -> PLM -> Linear classifier -> Hexatag sequence -> BHT reconstruction

Design tradeoffs:
- Simplicity vs. expressiveness: Hexatag uses only 6 tags for efficiency but cannot handle non-projective structures
- Linear model vs. complex architectures: Simpler model provides speed gains but may miss some syntactic nuances
- Parallelization vs. global context: Fully parallelizable training sacrifices explicit modeling of long-range dependencies

Failure signatures:
- Non-projective dependencies cause parsing failures due to representation limitations
- Low-resource languages may show degraded performance due to reliance on PLM features
- Ambiguous constructions may be misparsed due to lack of explicit syntactic structure modeling

First experiments:
1. Run hexatagging on a small projective treebank to verify basic functionality
2. Test decoding speed on sentences of increasing length to measure scalability
3. Evaluate performance degradation on sentences with non-projective dependencies

## Limitations
- Restricted to projective dependency trees, cannot handle non-projective structures common in many languages
- Performance on typologically diverse languages and noisy web text remains untested
- Does not explicitly model long-range dependencies or syntactic hierarchies beyond local tag predictions
- Relies heavily on pretrained language model features which may not generalize well to low-resource settings

## Confidence
High: English Penn Treebank results, efficiency gains, ablation studies
Medium: Generality across languages and domains, comparison with non-projective parsers
Low: Potential extensions to handle non-projective parsing, ability to capture complex syntactic phenomena
