# QAID: Question Answering Inspired Few-shot Intent Detection

## Quick Facts
- arXiv ID: 2303.01593
- Source URL: https://arxiv.org/abs/2303.01593
- Reference count: 17
- Key outcome: QAID achieves state-of-the-art few-shot intent detection performance with 4.39 points accuracy improvement over previous best on BANKING77 in 5-shot setting

## Executive Summary
QAID presents a novel approach to few-shot intent detection by reformulating it as a question-answering retrieval task. The method treats utterances as queries and intent names as answers, using a two-stage training approach with batch contrastive loss. In the pre-training stage, self-supervised contrastive learning improves query representations, while the fine-tuning stage increases similarity scores between queries and answers from the same intent. The system demonstrates state-of-the-art performance on three intent detection benchmarks (CLINC150, BANKING77, HWU64), particularly excelling when training data is limited.

## Method Summary
QAID reformulates few-shot intent detection as a retrieval problem where utterances are queries and intent names are answers. The approach employs a two-stage training pipeline: first, self-supervised contrastive pre-training on external intent detection datasets using data augmentation (masking and dropout) to improve query representations; second, supervised contrastive fine-tuning on target datasets using intent names as answers. The method uses token-level late interaction scoring (Khattab & Zaharia, 2020) and Faiss indexing for efficient inference. The contrastive loss function encourages higher similarity between queries and their corresponding intent names while pushing apart unrelated pairs, enabling effective few-shot learning.

## Key Results
- Achieves state-of-the-art performance on three intent detection benchmarks (CLINC150, BANKING77, HWU64)
- Demonstrates 4.39 points accuracy improvement over previous best method on BANKING77 in 5-shot setting
- Shows particular effectiveness in low-resource scenarios with limited training data
- Validates the value of incorporating intent names as additional semantic signal in the learning process

## Why This Works (Mechanism)
The effectiveness of QAID stems from leveraging intent names as semantic anchors during training. By treating intent detection as a retrieval task, the model learns to map utterances to their corresponding intent names through contrastive learning. The two-stage training approach first builds robust query representations through self-supervised learning on external data, then fine-tunes these representations to specifically align with intent names. This framework naturally handles the few-shot setting by focusing on semantic similarity rather than classification boundaries, making it more robust when training examples are scarce.

## Foundational Learning
- **Contrastive Learning**: Learning by comparing similar and dissimilar pairs - needed for creating discriminative representations with limited data; quick check: verify loss decreases during training
- **Token-level Late Interaction**: Computing similarity scores at token level rather than representation level - needed for capturing fine-grained semantic relationships; quick check: compare with simple dot-product similarity
- **Self-supervised Pre-training**: Training on unlabeled data to build general representations - needed to compensate for few-shot target data; quick check: ensure pre-training improves downstream performance
- **Faiss Indexing**: Efficient similarity search in high-dimensional space - needed for scalable inference across many intent classes; quick check: verify search latency meets requirements

## Architecture Onboarding
- **Component Map**: External ID datasets -> RoBERTa pre-training -> Contrastive fine-tuning -> Faiss index -> Inference
- **Critical Path**: Utterance encoding -> Token similarity scoring -> Faiss retrieval -> Intent prediction
- **Design Tradeoffs**: Using intent names as anchors provides semantic supervision but assumes names are representative; token-level scoring is more precise but computationally heavier than representation-level
- **Failure Signatures**: Poor pre-training leads to weak query representations; ambiguous intent names cause confusion; computational cost scales with number of intents
- **First Experiments**: 1) Verify contrastive loss improves during pre-training, 2) Test query-to-answer similarity scores, 3) Measure inference latency with different Faiss configurations

## Limitations
- Reliance on intent names assumes they are consistently representative and discriminative across domains
- Pre-training requires access to external intent detection datasets, limiting applicability in truly novel domains
- Token-level late interaction introduces computational overhead that scales linearly with number of intents
