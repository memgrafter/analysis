# Using Z3 for Formal Modeling and Verification of FNN Global Robustness

## Quick Facts
- **arXiv ID**: 2304.10558
- **Source URL**: https://arxiv.org/abs/2304.10558
- **Reference count**: 37
- **Primary result**: Complete formal specification and implementation of DeepGlobal framework using Z3 SMT solver for global robustness verification of feedforward neural networks

## Executive Summary
This paper presents a formal verification framework for global robustness of feedforward neural networks (FNNs) using the Z3 SMT solver. The authors introduce Sliding Door Activation (SDA) functions to reduce the exponential explosion of activation patterns, enabling tractable verification. By leveraging prototypes generated through autoencoders, the framework focuses on semantically meaningful samples rather than arbitrary points near decision boundaries. Experiments on MNIST and FashionMNIST demonstrate the framework's ability to efficiently verify global robustness and generate adversarial examples with formal guarantees.

## Method Summary
The authors formalize the DeepGlobal framework by modeling FNNs with Sliding Door Activation functions and constraints in Z3. The approach involves training SDNs and autoencoders on benchmark datasets, generating class prototypes via encoding training samples, enumerating activation patterns using BFS, and solving constraint satisfaction problems with customized Z3 tactics. The framework verifies global robustness by checking that perturbations remain within specified radius of prototypes across all activation patterns, generating both boundary samples and adversarial examples.

## Key Results
- SDA functions reduce activation pattern complexity from O(∏ 2^n_i) to O(∏ n²_i) compared to ReLU networks
- Z3 solver with customized tactics efficiently handles constraint satisfaction for global robustness verification
- Prototype-based approach generates semantically meaningful adversarial examples and boundary samples
- Framework successfully verifies global robustness on MNIST and FashionMNIST datasets

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Z3-based formal modeling enables complete enumeration of activation patterns in Sliding Door Networks (SDNs) with significantly fewer patterns than ReLU-based FNNs.
- **Mechanism**: By dividing neurons into groups and using Sliding Door Activation (SDA) functions, each layer has at most (n_i/k + 1)² activation patterns instead of 2^n_i patterns for ReLU networks.
- **Core assumption**: The reduction in activation patterns directly translates to computational tractability for formal verification.
- **Evidence anchors**:
  - [abstract] "They propose using Sliding Door Activation (SDA) functions to reduce the number of activation patterns that need to be considered"
  - [section] "From the perspective of activation pattern number SDNs demonstrate superiority than classic FNNs... O(∏n²_i) possible activation patterns... significantly fewer than... O(∏ 2^n_i)"
  - [corpus] Weak evidence - corpus contains related verification work but no direct comparison of pattern enumeration complexity
- **Break condition**: When network depth increases such that even reduced pattern count becomes intractable, or when k becomes too small reducing the pattern reduction benefit.

### Mechanism 2
- **Claim**: Using autoencoders to generate prototypes enables meaningful global robustness verification by focusing on semantically valid samples rather than arbitrary points near decision boundaries.
- **Mechanism**: Prototypes are created as averages of encoded training samples per class, and verification checks that perturbations stay within r of these prototypes rather than arbitrary bounds.
- **Core assumption**: Samples close to class prototypes are more likely to be semantically meaningful than random samples near decision boundaries.
- **Evidence anchors**:
  - [abstract] "We leverage prototypes crafted by autoencoder to improve the verification framework by searching for meaningful solutions"
  - [section] "we use autoencoders as surrogate models... any meaningful sample y with F~(y) = i should not be significantly different from the prototype P_i"
  - [corpus] Weak evidence - corpus mentions related verification but no specific work on prototype-based meaningful sample verification
- **Break condition**: When autoencoder reconstruction quality is poor, making prototypes unreliable, or when meaningful samples exist outside the prototype radius.

### Mechanism 3
- **Claim**: The Z3 solver with customized tactics ("simplify", "normalize-bounds", "solve-eqs", "smt") efficiently handles the constraint satisfaction problems for generating boundary and adversarial examples.
- **Mechanism**: Specific solver tactics are selected to optimize the solving process for this particular verification task, improving computational efficiency.
- **Core assumption**: The chosen tactics are well-suited for the specific structure of the verification constraints in this framework.
- **Evidence anchors**:
  - [abstract] "We leverage prototypes crafted by autoencoder to improve the verification framework by searching for meaningful solutions"
  - [section] "To improve the efficiency of generating adversarial examples, we use specific tactics during initialization, including 'simplify', 'normalize-bounds', and 'solve-eqs'"
  - [corpus] Weak evidence - corpus contains verification work but no specific details on Z3 tactic optimization
- **Break condition**: When the constraint structure changes significantly, making the customized tactics less effective, or when problem scale exceeds solver capabilities.

## Architecture Onboarding

- **Component map**: Input preprocessing -> Core verification engine -> Pattern enumeration -> Output processing
- **Critical path**: 1. Train SDN and autoencoder 2. Generate prototypes for each class 3. Enumerate activation patterns using BFS 4. For each pattern, solve constraints in Z3 5. Extract boundary samples and generate adversarial examples 6. Identify Adversarial Dangerous Regions (ADRs)
- **Design tradeoffs**:
  - Pattern reduction vs. model expressiveness: Smaller k reduces patterns but may limit network capacity
  - Prototype radius r vs. verification completeness: Larger r captures more meaningful samples but may include less robust regions
  - Z3 customization vs. generality: Tailored tactics improve performance but may not generalize to other verification tasks
- **Failure signatures**:
  - Solver timeout or unsatisfiable results despite known solutions
  - Generated adversarial examples that appear semantically invalid
  - Inconsistent results across different activation patterns for the same region
- **First 3 experiments**:
  1. Verify a simple 2-layer SDN on MNIST with k=2 and compare pattern enumeration count to equivalent ReLU network
  2. Test prototype generation quality by reconstructing samples and measuring reconstruction error
  3. Generate boundary samples for a single class pair and visually inspect for semantic validity

- Why unresolved: The paper does not provide theoretical bounds or empirical studies on how the number of prototypes affects the coverage of ADRs or the probability of missing vulnerabilities.
- What evidence would resolve it: Theoretical analysis of the trade-off between prototype count and verification completeness, or empirical studies showing diminishing returns as prototype count increases.

### Open Question 3

- What evidence would resolve it: Sensitivity analysis showing how verification time, success rate, and robustness guarantees vary with α and r across different network architectures and datasets.

### Open Question 4
- Question: How does the Z3-based approach compare to other formal verification methods (like Reluplex or abstract interpretation) for global robustness verification?

## Limitations
- Relies heavily on autoencoder quality for prototype generation, which may not generalize across diverse datasets
- Pattern enumeration complexity may still become intractable for deeper networks despite SDA reduction
- Assumes samples near prototypes are more meaningful than those near decision boundaries without comprehensive validation
- Framework performance on datasets beyond MNIST and FashionMNIST remains untested

## Confidence
- **High Confidence**: The mathematical formulation of pattern enumeration reduction using SDA functions is sound and clearly derived.
- **Medium Confidence**: The Z3 implementation and constraint modeling approach is methodologically sound, though solver performance may vary with problem scale.
- **Medium Confidence**: Prototype-based verification approach shows promise but lacks comprehensive validation across diverse scenarios.
