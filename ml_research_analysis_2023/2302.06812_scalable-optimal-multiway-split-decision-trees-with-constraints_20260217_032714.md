# Scalable Optimal Multiway-Split Decision Trees with Constraints

## Quick Facts
- arXiv ID: 2302.06812
- Source URL: https://arxiv.org/abs/2302.06812
- Reference count: 8
- Primary result: Path-based MIP framework learns optimal multiway-split trees 24X faster than arc-based methods on datasets up to 1M samples

## Executive Summary
This paper introduces a scalable mixed-integer programming (MIP) framework for learning optimal multiway-split decision trees. The key innovation is a path-based formulation that models decision rules as paths in a feature graph, dramatically reducing the number of binary variables from O(2^d N) to a value independent of dataset size N. A column generation algorithm dynamically generates high-quality paths, enabling the framework to handle large datasets (up to 1,008,372 samples) that were previously intractable. The method supports nonlinear metrics like F1-score, path-level constraints, and attribute-level constraints, and naturally produces more interpretable multiway-split trees.

## Method Summary
The framework constructs a feature graph with SKIP nodes and enumerates all possible decision paths. It formulates tree learning as a set partitioning problem where each path is represented by a single binary variable. Column generation dynamically generates promising paths by solving a K-shortest path subproblem to find candidates with negative reduced cost. The algorithm iteratively solves the restricted master program and adds new paths until convergence, then solves a final MIP with integrality constraints to obtain the optimal tree.

## Key Results
- Achieves up to 24X runtime reduction compared to state-of-the-art MIP-based methods
- Handles datasets up to 1,008,372 samples (an order of magnitude larger than prior work)
- Competitive or superior accuracy on tested datasets with nonlinear metrics
- Naturally produces more interpretable multiway-split trees with shorter rules

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The path-based MIP formulation reduces binary decision variables from O(2^d N) to a value independent of dataset size N.
- Mechanism: By modeling decision rules as paths in a feature graph, each path is represented by a single binary variable rather than assigning each sample to a node. The feature graph structure allows enumeration of all possible feature combinations upfront, eliminating the need for per-sample binary assignments.
- Core assumption: The feature graph accurately captures all possible decision rules without redundancy, and the set partitioning constraint (1) ensures each sample is assigned to exactly one rule.
- Evidence anchors:
  - [abstract]: "the number of binary variables is independent of N"
  - [section]: "the number of binary decision variables in our formulation is independent of N"
- Break condition: If the feature graph contains redundant paths or fails to capture all valid decision rules, the formulation loses its advantage.

### Mechanism 2
- Claim: Column generation dynamically generates only high-quality paths, making the method scalable to large datasets.
- Mechanism: The restricted master program (RMP) starts with no candidate rules and iteratively adds paths with negative reduced cost identified by solving the subproblem (KSP). This focuses computational effort on paths that can improve the current solution rather than enumerating all possible paths.
- Core assumption: The KSP heuristic can efficiently find high-quality paths that maximally violate the dual constraints, and the reduced costs accurately guide path selection.
- Evidence anchors:
  - [section]: "we employ column generation (CG) to dynamically generate a relatively small number of candidates"
  - [section]: "identify up to K candidate rules having the most negative reduced cost"
- Break condition: If the KSP heuristic fails to find relevant paths or the reduced costs poorly guide path selection, column generation becomes ineffective.

### Mechanism 3
- Claim: The multiway-split tree structure naturally produces more interpretable trees than binary-split trees.
- Mechanism: Multiway-split trees allow nodes to have more than two children, reducing tree depth and the number of rules needed. Since features seldom appear more than once in any root-to-leaf path, the resulting rules are shorter and more intuitive.
- Core assumption: Shorter rules with fewer feature repetitions are inherently more interpretable to users, and the cardinality constraint (2) effectively limits tree complexity.
- Evidence anchors:
  - [abstract]: "Our framework produces a multiway-split tree which is more interpretable than the typical binary-split trees due to its shorter rules"
  - [section]: "multiway-split trees are easier to comprehend than their binary counterparts"
- Break condition: If the cardinality constraint fails to prevent overly complex trees or users don't find shorter rules more interpretable, this advantage diminishes.

## Architecture Onboarding

- Component map: Feature graph builder -> Path enumerator (KSP solver) -> Master MIP solver -> Constraint handler -> Model validator

- Critical path:
  1. Build feature graph from input features
  2. Initialize empty candidate path set
  3. Solve RMP with current paths
  4. Solve KSP subproblem to find negative reduced cost paths
  5. Add new paths to candidate set
  6. Repeat 3-5 until convergence
  7. Solve final Master-MIP with integrality constraints

- Design tradeoffs:
  - Path enumeration vs. on-demand generation: Complete enumeration guarantees optimality but is intractable; column generation is scalable but may miss some paths
  - Tree depth vs. interpretability: Deeper trees can capture more complex patterns but reduce interpretability
  - KSP size (K) vs. runtime: Larger K finds better paths but increases computation time

- Failure signatures:
  - Slow convergence: KSP subproblem repeatedly finds no negative reduced cost paths
  - Memory issues: Candidate path set grows too large for available RAM
  - Poor solution quality: Final tree performs worse than CART on validation set

- First 3 experiments:
  1. Small synthetic dataset (100 samples, 3 features) to verify basic functionality
  2. Medium UCI dataset (breast-cancer, 277 samples) to test constraint handling
  3. Large numerical dataset (pendigits, 7494 samples) to evaluate scalability with column generation

## Limitations
- Scalability relies heavily on column generation heuristic effectiveness, which may not generalize to all problem types
- Feature graph construction assumes feature independence, which may not hold with correlated features
- Interpretability claims lack empirical user validation through studies or quantitative metrics
- Solution quality depends on KSP subproblem's ability to find relevant paths

## Confidence
- High Confidence: The path-based MIP formulation's mathematical correctness and reduction in binary variables from O(2^d N) to a value independent of N
- Medium Confidence: Scalability claims and runtime improvements, as column generation effectiveness may vary with different problem characteristics
- Low Confidence: Interpretability claims, as they are based on structural arguments rather than empirical user studies

## Next Checks
1. **Heuristic Sensitivity Analysis**: Systematically vary the KSP heuristic parameters (K value, path selection criteria) and measure the impact on solution quality and runtime to understand the robustness of the column generation approach.

2. **Feature Correlation Testing**: Evaluate the framework's performance on datasets with high feature correlations to assess whether the independence assumption in feature graph construction affects solution quality or causes failures.

3. **Interpretability Validation**: Conduct user studies comparing binary-split and multiway-split trees generated by the framework, measuring both quantitative metrics (rule length, tree depth) and qualitative assessments of interpretability from human evaluators.
