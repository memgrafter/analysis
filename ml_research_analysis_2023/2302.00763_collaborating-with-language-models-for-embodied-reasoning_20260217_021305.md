# Collaborating with language models for embodied reasoning

## Quick Facts
- arXiv ID: 2302.00763
- Source URL: https://arxiv.org/abs/2302.00763
- Authors:
- Reference count: 16
- Primary result: Zero-shot performance of Planner-Actor-Reporter system using LLMs for embodied reasoning tasks

## Executive Summary
This paper presents a system for combining the reasoning abilities of large language models with embodied agents for tasks requiring exploration and information gathering. The key idea is a Planner-Actor-Reporter architecture where a pre-trained language model (Planner) issues commands to a simple embodied agent (Actor), with a Reporter translating environment feedback back to the Planner. The authors introduce tasks requiring logical reasoning and information gathering, showing zero-shot performance with language models as Planners. They demonstrate that larger language models (70B vs 7B parameters) perform significantly better and show robustness to Actor and Reporter errors.

## Method Summary
The paper proposes a Planner-Actor-Reporter architecture that combines large language models (LLMs) with embodied agents for tasks requiring exploration and information gathering. The system uses a pre-trained LLM as the Planner, which issues commands to a simple embodied agent (Actor) based on few-shot examples in the prompt. The Actor executes these commands in a 2D grid-world environment and reports back through a Reporter module that translates visual observations into language the Planner can understand. The authors demonstrate zero-shot performance on tasks requiring logical reasoning and information gathering, showing that larger language models (70B vs 7B parameters) perform significantly better. They also present a proof-of-concept for training the Reporter module with reinforcement learning to improve collaboration between Planner and Actor.

## Key Results
- Larger language models (70B vs 7B parameters) perform significantly better on embodied reasoning tasks, with 70B models achieving 96% success rate versus 58% for 7B models
- The system shows robustness to Actor and Reporter errors, with the Planner able to handle irrelevant reports and continue planning effectively
- Zero-shot performance is demonstrated across multiple reasoning and information gathering tasks without any fine-tuning of the language model components

- Claim: Language models can function as planners that issue interpretable, step-by-step instructions to embodied agents
- Mechanism: The Planner module uses in-context learning with few-shot examples to decompose complex tasks into simple, actionable commands that the Actor can execute
- Core assumption: The language model has sufficient reasoning capacity to understand task requirements and generate appropriate instructions

- Mechanism: The Reporter takes pixel observations and action sequences from the Actor and produces textual reports that capture relevant environmental information
- Core assumption: There exists a learnable mapping between visual/environmental states and language descriptions that are useful for planning
- Evidence anchors:
  - [abstract] "the Reporter communicates with the Planner to inform its next command"
  - [section] "The Reporter translates from the Actor's action+observation space to the Planner's"

### Mechanism 3
- Claim: Larger language models (70B vs 7B parameters) show significantly better performance in embodied reasoning tasks

## Foundational Learning

- Concept: Few-shot in-context learning
  - Why needed here: Enables the Planner to handle new tasks without fine-tuning by learning from examples in the prompt
  - Quick check question: How many examples are provided in the prompt for each task?
- Concept: Hierarchical decision-making
  - Why needed here: Separates high-level planning (Planner) from low-level execution (Actor) to handle complex tasks
  - Quick check question: What are the three components of the Planner-Actor-Reporter architecture?
- Concept: Embodied perception-action loops
  - Why needed here: The Reporter bridges the gap between the Actor's visual observations and the Planner's language-based reasoning
  - Quick check question: What special actions can the Actor perform when on top of an object?

## Architecture Onboarding

- Component map: Planner (LLM) → Actor (RL agent) → Environment → Reporter → Planner (feedback loop)
- Critical path: Planner issues instructions → Actor executes in environment → Reporter translates observations → Planner incorporates feedback
- Design tradeoffs:
  - Large vs small language models: better reasoning vs faster inference
  - Hard-coded vs learned Reporter: reliability vs flexibility
  - Pre-trained vs trained-from-scratch components: zero-shot performance vs task-specific optimization
- Failure signatures:
  - Planner failures: incorrect task decomposition, inability to incorporate feedback
  - Actor failures: inability to execute instructions, distribution shift
  - Reporter failures: inaccurate reporting, inability to identify relevant information
- First 3 experiments:
  1. Implement secret property conditional task with 7B Planner to verify basic Planner-Actor interaction
  2. Test 70B Planner on same task to measure performance difference
  3. Introduce irrelevant reports to test Planner robustness and observe failure modes

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can the Planner-Actor-Reporter framework be extended to handle more complex, real-world tasks beyond the current grid-world environment?
- Basis in paper: [explicit] The authors discuss expanding to more complex/realistic tasks as an exciting direction for future work.
- Why unresolved: The current tasks are limited to a simple 2D grid-world with abstract object properties. Real-world tasks would involve more complex environments, object interactions, and potentially continuous action spaces.
- What evidence would resolve it: Successful demonstrations of the framework on increasingly complex simulated environments (e.g., 3D navigation, object manipulation) or real-world robotic tasks.

### Open Question 2
- Question: How can the Reporter module be improved to handle noisy or irrelevant information more effectively?
- Basis in paper: [explicit] The authors demonstrate some robustness to irrelevant reports but note that inference time with large Planners is expensive, suggesting a need for more efficient Reporters.
- Why unresolved: While the paper shows some strategies for handling irrelevant reports, there's no systematic exploration of how to make the Reporter more selective or how to train it to ignore noise.
- What evidence would resolve it: Development of a Reporter that can dynamically filter relevant information or experiments showing improved performance with a trained Reporter that can ignore irrelevant events.

### Open Question 3
- Question: What is the optimal balance between using pre-trained components and learning from scratch in the Reporter module?
- Basis in paper: [explicit] The authors propose combining pre-trained modules with reinforcement learning for the Reporter but don't explore this systematically.
- Why unresolved: The paper only provides a proof-of-concept for training the Reporter with RL and doesn't compare different approaches or investigate the trade-offs between pre-training and learning from scratch.
- What evidence would resolve it: Systematic comparisons of Reporter performance using different combinations of pre-trained components and learned modules, or ablation studies showing the impact of pre-training on Reporter effectiveness.

### Open Question 4
- Question: How can the inference time bottleneck of large language models be addressed in the Planner module?
- Basis in paper: [explicit] The authors note that inference time through a large Planner is expensive, suggesting a need for more efficient approaches.
- Why unresolved: The paper doesn't explore techniques to reduce inference time or alternative architectures that could maintain performance while being more computationally efficient.
- What evidence would resolve it: Experiments demonstrating improved efficiency through model distillation, knowledge distillation, or alternative architectures that maintain performance while reducing inference time.

## Limitations

- Inference speed bottleneck: The paper acknowledges that inference time for large language models remains prohibitive for real-time deployment
- Limited task complexity: Tasks remain relatively simple compared to real-world scenarios requiring continuous adaptation
- Simulation-only validation: All experiments are conducted in a controlled 2D grid-world environment

## Confidence

- High confidence: Basic feasibility of using LLMs as Planners with zero-shot performance on simple tasks
- Medium confidence: Robustness claims regarding tolerance to Actor and Reporter errors
- Low confidence: Effectiveness of training the Reporter module with reinforcement learning

## Next Checks

1. **Scale test in realistic environment**: Implement the same architecture in a 3D simulation environment like Habitat or AI2-THOR to verify if the performance gains from larger language models translate to more realistic settings.

2. **Continuous task evaluation**: Design a benchmark with tasks requiring multiple rounds of planning and execution (beyond the simple two-stage tasks in the paper) to test the system's ability to handle more complex, extended reasoning chains.

3. **Real-world deployment stress test**: Test the system's robustness to sensor noise and actuator uncertainty by introducing realistic physical simulation parameters or testing on a real robot platform to evaluate how well the architecture handles the messiness of real-world environments.
