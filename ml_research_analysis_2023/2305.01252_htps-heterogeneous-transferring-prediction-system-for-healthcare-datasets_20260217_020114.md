# HTPS: Heterogeneous Transferring Prediction System for Healthcare Datasets

## Quick Facts

## Executive Summary
This paper introduces the Heterogeneous Transferring Prediction System (HTPS), a framework designed to address the challenges of high sparsity and heterogeneity in healthcare data. HTPS employs feature engineering to transform data into sparse and dense matrices, and utilizes embedding networks with autoencoders to embed features and transfer knowledge from heterogeneous datasets. The system demonstrates superior performance on various prediction tasks, outperforming benchmark systems significantly on both homogeneous and heterogeneous data.

## Method Summary
HTPS transforms healthcare data into sparse and dense feature matrices through feature engineering. It employs N autoencoders in the dense embedding network to embed each feature separately, enabling knowledge transfer between heterogeneous datasets based on reconstruction error matching. The sparse embedding network captures temporal patterns from the last W measurements. These embeddings are then combined in a prediction network to produce final outputs. The heterogeneous transfer learning mechanism transfers weights from source to target models by matching features with similar reconstruction errors.

## Key Results
- HTPS achieves up to 78.6% reduction in MSE compared to MLP baseline
- HTPS shows 30.2% MSE improvement over BIBE system
- Ablation studies confirm the effectiveness of each designed mechanism in HTPS
- HTPS demonstrates stable convergence and excellent performance on heterogeneous data where benchmark systems struggle

## Architecture Onboarding

- Component map:
  - Feature Engineering Layer: Converts raw healthcare records into sparse and dense feature matrices
  - Dense Embedding Network: N autoencoders for individual feature embedding and transfer learning
  - Sparse Embedding Network: Fully connected layers for temporal pattern extraction
  - Prediction Network: Combines embeddings to produce final predictions
  - Transfer Learning Module: Matches and transfers weights between heterogeneous datasets

- Critical path: Raw data → Feature Engineering → Dense/Sparse Embedding → Prediction → Output
- Design tradeoffs:
  - Window size W: Larger windows capture more temporal context but increase computational cost and may introduce noise
  - Number of autoencoders: More features allow more detailed embeddings but increase model complexity
  - Transfer learning matching: Strict matching preserves model integrity but may miss useful cross-dataset patterns

- Failure signatures:
  - Extremely large MSE spikes during training: Likely indicates poor feature matching in transfer learning
  - Stable but poor performance: May indicate insufficient window size or inadequate embedding dimensions
  - Memory errors: Window size or feature count may be too large for available resources

- First 3 experiments:
  1. Baseline MLP comparison: Train MLP on dense features only to establish baseline performance
  2. Dense embedding ablation: Add dense autoencoders without transfer learning to measure their impact
  3. Sparse embedding addition: Include sparse embeddings to evaluate temporal information contribution

## Limitations
- Evaluation is limited to MIMIC-III data, which may not represent diverse real-world healthcare data distributions
- Window size parameter W is fixed at 50 records without systematic exploration of optimal values across different clinical scenarios
- Heterogeneous transfer learning relies on reconstruction error matching, which may not capture all relevant feature relationships when datasets have vastly different feature distributions

## Confidence
- High confidence: The core feature engineering mechanism that transforms data into sparse and dense matrices is well-specified and technically sound
- Medium confidence: The heterogeneous transfer learning approach shows promise but requires more extensive validation across diverse dataset pairs
- Low confidence: The optimal configuration parameters (W size, embedding dimensions) are not thoroughly explored
