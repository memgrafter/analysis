# A Common Misassumption in Online Experiments with Machine Learning Models

## Quick Facts
- **arXiv ID**: 2304.10900
- **Source URL**: https://arxiv.org/abs/2304.10900
- **Reference count**: 7
- **Primary result**: SUTVA violations in ML A/B tests cause biased estimates when competing models learn from pooled data

## Executive Summary
This paper identifies a critical but overlooked assumption violation in online experiments for machine learning models. The Stable Unit Treatment Value Assumption (SUTVA), which underpins standard A/B testing methodology, is routinely violated when ML models update using pooled data from competing variants. Through a synthetic bandit experiment, the authors demonstrate that this violation systematically biases results, causing greedy exploration methods to appear superior in pooled-data settings but inferior when deployed independently. The work highlights the need for greater awareness of this issue and calls for research to quantify its impact and develop solutions.

## Method Summary
The authors conducted a synthetic bandit experiment to demonstrate SUTVA violations in online ML testing. They created a controlled environment where competing policies (exploration-heavy vs. greedy) learned from data collected under different variants. By comparing results from pooled data versus siloed data scenarios, they measured how the violation affects model ranking and performance estimates. The synthetic setting allowed precise control over the violation mechanism while maintaining analytical tractability.

## Key Results
- SUTVA violations occur when ML models learn from pooled data collected under different policies
- Greedy exploration methods appear superior in pooled-data online tests despite being inferior in independent deployment
- The ranking of exploration methods reverses when using siloed data instead of pooled data
- SUTVA violations systematically bias causal effect estimates in ML A/B tests

## Why This Works (Mechanism)
When multiple ML variants update their parameters using data from a shared pool, each variant's performance depends on the actions of others. This creates interference between units, violating the SUTVA assumption that each unit's outcome depends only on its own treatment. The violation is particularly acute in bandit-style personalization where models continuously adapt based on collected data, but the paper suggests it extends to other adaptive ML systems.

## Foundational Learning
- **SUTVA (Stable Unit Treatment Value Assumption)**: The assumption that an individual's outcome depends only on their own treatment, not on others' treatments. Critical for valid causal inference in A/B tests.
- **Interference in ML systems**: When units (users, items) affect each other's outcomes through shared learning mechanisms, violating SUTVA.
- **Pooled vs. siloed data**: Pooled data aggregates observations across variants, enabling cross-contamination; siloed data keeps variant-specific data separate to prevent interference.
- **Greedy vs. exploration policies**: Greedy policies exploit known information while exploration policies seek new information; their relative performance depends on data collection mechanisms.
- **Causal effect estimation**: The process of inferring the effect of a treatment (model variant) on an outcome, which requires valid assumptions like SUTVA.

## Architecture Onboarding
**Component map**: Competing ML variants -> Shared data pool -> Joint parameter updates -> Performance metrics
**Critical path**: Data collection → Model update → Performance evaluation → Decision making
**Design tradeoffs**: Pooled data enables efficient learning but violates SUTVA; siloed data prevents interference but may reduce statistical power
**Failure signatures**: Unexpected performance reversals between pooled and independent deployment; consistent ranking changes across exploration strategies
**First experiments**: 1) Measure interference magnitude in real A/B test data, 2) Test variance reduction techniques on pooled data, 3) Compare siloed vs. pooled results across multiple ML systems

## Open Questions the Paper Calls Out
The paper identifies several key open questions: how to quantify the magnitude of bias caused by SUTVA violations in practical settings, what alternative experimental designs can mitigate these violations without sacrificing statistical power, and how severely SUTVA is violated in non-bandit ML systems like batch-trained recommendation models.

## Limitations
- Controlled synthetic setting may not capture all real-world complexities
- Practical solutions remain underdeveloped beyond suggesting siloed data
- Limited analysis of SUTVA violations in non-bandit ML systems
- No empirical validation on actual production A/B test data
