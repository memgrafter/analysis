# Hierarchical confusion matrix for classification performance evaluation

## Quick Facts
- arXiv ID: 2306.09461
- Source URL: https://arxiv.org/abs/2306.09461
- Reference count: 27
- A novel hierarchical confusion matrix extends binary classification evaluation to hierarchical problems while maintaining intuitive interpretation

## Executive Summary
This paper proposes a hierarchical confusion matrix that extends traditional binary classification evaluation to hierarchical classification problems. The core innovation redefines confusion matrix elements (TP, TN, FP, FN) as hierarchical versions (TPH, TNH, FPH, FNH) that count nodes along prediction paths, allowing standard binary metrics to be applied while preserving hierarchical structure. The method handles various hierarchical problem types including trees, DAGs, multi-label classification, and non-mandatory leaf node prediction through a "benevolent" two-step approach. Evaluation on three real-world datasets demonstrates consistent rankings compared to established measures while offering more intuitive interpretation aligned with familiar binary classification metrics.

## Method Summary
The hierarchical confusion matrix redefines traditional confusion matrix elements in terms of nodes along prediction paths rather than final class assignments. For tree structures, it counts correct and incorrect node decisions along the predicted path. For DAGs, it selects the true path most similar to the predicted path. For multi-label problems, it decomposes the problem into single-label evaluations. For non-mandatory leaf prediction, it evaluates all paths without requiring leaf nodes. The method then applies standard binary classification metrics (accuracy, precision, recall, F1-score) to the hierarchical confusion matrix values, providing intuitive evaluation while capturing hierarchical relationships.

## Key Results
- Hierarchical confusion matrix measures produce consistent rankings compared to established evaluation methods across three real-world datasets
- The approach offers more intuitive interpretation aligned with binary classification metrics while preserving hierarchical structure
- Implementation successfully handles various hierarchical problem types including trees, DAGs, multi-label, and non-mandatory leaf prediction

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The hierarchical confusion matrix extends binary classification evaluation to hierarchical problems by redefining confusion matrix elements in terms of nodes along the prediction path.
- Mechanism: Traditional confusion matrix elements (TP, TN, FP, FN) are redefined as hierarchical confusion matrix elements (TPH, TNH, FPH, FNH) that count nodes along the predicted path and its relationship to the true path. This allows standard binary metrics like accuracy, precision, recall, and F1-score to be directly applicable while preserving hierarchical structure.
- Core assumption: The hierarchical structure can be evaluated by considering individual node decisions along the prediction path rather than just final class assignment.
- Evidence anchors:
  - [abstract] "This work proposes a novel hierarchical confusion matrix for evaluating hierarchical classification models. The core idea extends the traditional binary classification confusion matrix to handle hierarchical structures"
  - [section] "The concept of the hierarchical confusion matrix defines the four fields of the confusion matrix with a connotation to decisions that are done along the prediction path(s)"
- Break condition: The method breaks down when hierarchical relationships are non-tree structures where paths are not well-defined or when multiple inheritance makes node-level evaluation ambiguous.

### Mechanism 2
- Claim: The method handles different hierarchical classification problem types (trees vs DAGs, single vs multi-label, mandatory vs non-mandatory leaf prediction) through a two-step "benevolent" approach.
- Mechanism: For DAG problems, the approach selects the true path most similar to the predicted path. For multi-label problems, predictions are mapped to true classes and evaluated as a series of single-label problems. This decomposition allows the same hierarchical confusion matrix definition to work across all problem types.
- Core assumption: Complex hierarchical problems can be decomposed into simpler subproblems that can be evaluated using the same framework.
- Evidence anchors:
  - [section] "we propose a two step 'benevolent' approach" for DAG problems and "we can decompose the MPL problem to SPL problems" for multi-label problems
  - [section] "The discussed approach in the previous subsection is also suitable in this case, as the confusion matrix element definitions consider paths and their intersection" for non-mandatory leaf prediction
- Break condition: The method may fail when the decomposition creates significant information loss or when the "benevolent" selection doesn't align with actual evaluation goals.

### Mechanism 3
- Claim: The hierarchical confusion matrix provides consistent rankings compared to established evaluation measures while offering more intuitive interpretation aligned with binary classification metrics.
- Mechanism: By using familiar binary classification metrics on the hierarchical confusion matrix, practitioners can evaluate hierarchical models using measures they already understand, while the method still captures hierarchical relationships. This reduces the learning curve and makes results more interpretable.
- Core assumption: Consistency with established measures combined with intuitive interpretation will make the method practically useful for model comparison.
- Evidence anchors:
  - [abstract] "Results showed that measures based on the hierarchical confusion matrix produce consistent rankings compared to established evaluation methods, while offering a more intuitive interpretation aligned with binary classification metrics"
  - [section] Tables III, IV, and V show the hierarchical confusion matrix measures produce similar rankings to established measures in three real-world experiments
- Break condition: The method may not be useful if the rankings diverge significantly from established measures in practice or if the intuitive interpretation doesn't match domain expert expectations.

## Architecture Onboarding

- Component map: Hierarchical confusion matrix calculator -> Standard binary metric calculators (accuracy, precision, recall, F1-score)
- Critical path: For each data point: parse input to extract predicted and true paths → select appropriate true path(s) for DAG/multi-label cases → calculate TPH, TNH, FPH, FNH for each prediction → sum across all data points → calculate binary metrics from summed confusion matrix values
- Design tradeoffs: The "benevolent" approach for DAG and multi-label problems prioritizes best-case evaluation but may overestimate performance. Alternative approaches could use worst-case or average-case selection. The method trades completeness of evaluation for simplicity and interpretability.
- Failure signatures: Inconsistent rankings between hierarchical confusion matrix measures and established measures, unexpected behavior with complex DAG structures, performance degradation when number of paths grows large, incorrect handling of overlapping true paths in multi-label problems.
- First 3 experiments:
  1. Implement and test on a simple tree structure with known ground truth to verify basic metric calculations match expectations
  2. Test on a DAG structure to verify the path selection mechanism correctly identifies the most similar true path
  3. Test on a multi-label problem to verify the mapping and decomposition mechanism correctly handles multiple true paths and predictions

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can hierarchical confusion matrix measures be effectively extended to handle more complex hierarchical structures like polyhierarchies (where a node can have multiple parents)?
- Basis in paper: [explicit] The paper mentions the extension to DAGs but doesn't fully explore polyhierarchies where nodes can have multiple parent relationships.
- Why unresolved: The current framework handles directed acyclic graphs but doesn't specifically address the additional complexity introduced by multiple parent-child relationships in polyhierarchies.
- What evidence would resolve it: A formal extension of the hierarchical confusion matrix to handle polyhierarchies, including new mathematical definitions and experimental validation showing improved performance over current approaches.

### Open Question 2
- Question: What are the optimal weighting strategies for different levels of hierarchy when calculating hierarchical confusion matrix measures?
- Basis in paper: [inferred] The paper discusses depth-based measures and weighting but doesn't provide specific guidance on optimal weighting schemes.
- Why unresolved: The paper mentions that weighting structural edges is challenging but doesn't provide concrete recommendations or experimental validation of different weighting strategies.
- What evidence would resolve it: Empirical studies comparing different weighting schemes across multiple hierarchical classification tasks, demonstrating which approaches consistently outperform others.

### Open Question 3
- Question: How does the hierarchical confusion matrix perform when applied to extremely large-scale hierarchical classification problems with thousands of classes?
- Basis in paper: [inferred] The experiments use datasets with relatively small hierarchies (343 categories maximum), leaving scalability concerns unaddressed.
- Why unresolved: The current implementation and experiments don't test the approach on very large hierarchies, which is increasingly common in real-world applications.
- What evidence would resolve it: Benchmarking the hierarchical confusion matrix approach on large-scale problems, measuring computational efficiency and evaluating whether performance degrades or maintains consistency with smaller hierarchies.

## Limitations
- The "benevolent" approach for DAG and multi-label problems may overestimate performance by selecting the most favorable true path
- Scalability with very large hierarchical structures (thousands of classes) remains untested
- The method requires independent verification of the implementation available on GitHub
