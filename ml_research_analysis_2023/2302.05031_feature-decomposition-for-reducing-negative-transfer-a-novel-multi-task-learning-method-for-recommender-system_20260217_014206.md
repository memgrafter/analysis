# Feature Decomposition for Reducing Negative Transfer: A Novel Multi-task Learning Method for Recommender System

## Quick Facts
- arXiv ID: 2302.05031
- Source URL: https://arxiv.org/abs/2302.05031
- Reference count: 23
- Key outcome: FDN achieves 0.6252 AUC for CTR and 0.6783 for CVR on Ali-CCP dataset, outperforming other methods while using fewer parameters

## Executive Summary
This paper addresses negative transfer in multi-task learning for recommender systems by proposing the Feature Decomposition Network (FDN). The key innovation is decomposing features into task-specific and task-shared components using a DeComposition Pair (DCP) module with three carefully designed constraints. Experimental results on synthetic and real-world Ali-CCP datasets demonstrate that FDN outperforms state-of-the-art methods while using fewer parameters, showing improved ability to decouple task-specific and task-shared features.

## Method Summary
FDN introduces DeComposition Pairs (DCPs) consisting of task-specific and task-shared experts. Each DCP uses three constraints: an orthogonal constraint to ensure task-specific features don't interfere with task-shared features, an auxiliary task constraint where each task-specific expert learns its own prediction head, and a task-shared feature fusion constraint. The method explicitly decomposes features into orthogonal task-specific and task-shared components, reducing feature redundancy that causes negative transfer in multi-task learning.

## Key Results
- On Ali-CCP dataset: FDN achieves 0.6252 AUC for CTR and 0.6783 for CVR
- FDN uses 5.11×10^9 parameters vs PLE's 7.03×10^9 parameters
- Performance improvements of 0.0076 AUC for CTR and 0.0045 for CVR over PLE
- Outperforms MMoE, CGC, and PLE on both synthetic and real-world datasets

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Feature redundancy causes negative transfer in MTL for recommender systems
- Mechanism: When experts in an MTL model extract mixed features (both task-specific and task-shared), the interference degrades performance
- Core assumption: Task-specific and task-shared features should be orthogonal for optimal MTL performance
- Evidence anchors:
  - [abstract] "the root cause of negative transfer is feature redundancy that features learned for different tasks interfere with each other"
  - [section] "Due to the above phenomena, there will be task-specific features in the task-shared feature space or task-specific features of other tasks in the current task-specific feature space"
  - [corpus] Weak evidence - corpus papers discuss negative transfer but don't specifically address feature redundancy as the root cause
- Break condition: If the orthogonal constraint doesn't sufficiently separate features, the model will still suffer from negative transfer

### Mechanism 2
- Claim: Decomposing features into task-specific and task-shared components improves MTL performance
- Mechanism: The DeComposition Pair (DCP) module uses three constraints to explicitly separate features, allowing each expert to focus on its designated feature type
- Core assumption: Task-specific experts should learn task-specific features while task-shared experts should learn shared features
- Evidence anchors:
  - [section] "The key idea of the proposed FDN is reducing the phenomenon of feature redundancy by explicitly decomposing features into task-specific features and task-shared features with carefully designed constraints"
  - [section] "The DCP module has a pair of experts, a task-specific expert and a task-shared expert"
  - [corpus] Weak evidence - corpus papers discuss feature decomposition but don't specifically address the DCP approach
- Break condition: If the constraints don't work as intended, features may remain mixed and performance won't improve

### Mechanism 3
- Claim: The auxiliary task constraint helps task-specific experts extract the most salient task-specific features
- Mechanism: Each task-specific expert is treated as a single-task network with its own prediction head, inducing it to extract the most relevant features for that task
- Core assumption: Adding an auxiliary task with the same objective as the main task will guide the expert to focus on task-specific features
- Evidence anchors:
  - [section] "we introduce an auxiliary task to each task-specific expert as a regularizer. Specifically, we treat each task-specific expert as a single-task network and directly use its extracted feature for the prediction of a specific task"
  - [section] "Such design can induce the task-specific expert to extract the most salient task-specific feature for the current task"
  - [corpus] Weak evidence - corpus papers discuss auxiliary tasks but don't specifically address this approach in the context of feature decomposition
- Break condition: If the auxiliary task doesn't provide enough guidance, the task-specific expert may still extract mixed features

## Architecture Onboarding

- Component map: Input layer -> DCPs (task-specific expert + task-shared expert) -> Feature fusion module -> Prediction layer for each task

- Critical path: Input features → DCPs → Feature decomposition → Feature fusion → Predictions

- Design tradeoffs:
  - Using fewer parameters than competing methods (FDN uses 5.11×10^9 parameters vs PLE's 7.03×10^9)
  - Potential complexity in training due to multiple constraints

- Failure signatures:
  - Performance degradation if constraints don't work as intended
  - Convergence issues due to the complexity of the loss function

- First 3 experiments:
  1. Implement a single DCP with both orthogonal and auxiliary constraints, test on synthetic data
  2. Add the task-shared feature fusion constraint, compare performance with and without it
  3. Scale up to multiple DCPs, evaluate on Ali-CCP dataset against baseline methods

## Limitations
- The paper's claims about feature redundancy being the "root cause" of negative transfer lack extensive empirical validation across diverse datasets
- Performance improvements on Ali-CCP dataset are modest (0.0076 AUC gain for CTR, 0.0045 for CVR over PLE)
- Computational complexity of training with multiple orthogonal constraints and auxiliary tasks is acknowledged but not thoroughly analyzed

## Confidence
- **High Confidence**: The mathematical formulation of the DCP module and its three constraints is well-defined and reproducible
- **Medium Confidence**: The experimental results on the Ali-CCP dataset are valid but show incremental improvements over existing methods
- **Low Confidence**: The claim that feature redundancy is the fundamental cause of negative transfer across all MTL scenarios in recommender systems

## Next Checks
