# Adaptive Federated Pruning in Hierarchical Wireless Networks

## Quick Facts
- arXiv ID: 2305.09042
- Source URL: https://arxiv.org/abs/2305.09042
- Reference count: 39
- Primary result: Adaptive federated pruning scheme achieves similar learning accuracy to HFL without pruning while reducing communication cost by ~50%

## Executive Summary
This paper proposes an adaptive federated pruning scheme for hierarchical wireless networks that jointly optimizes pruning ratio and wireless resource allocation to minimize the upper bound of the l2-norm of gradients under latency and bandwidth constraints. The method derives closed-form solutions for pruning ratios and bandwidth allocation using KKT conditions, achieving similar learning accuracy to hierarchical federated learning without pruning while reducing communication cost by approximately 50%. The scheme addresses the challenges of increasing model size and communication overhead in federated learning by strategically pruning model weights based on their importance and allocating wireless resources optimally across devices and edge servers.

## Method Summary
The proposed method implements hierarchical federated learning with adaptive model pruning across device-edge-cloud architecture. It derives closed-form solutions for optimal pruning ratios that satisfy latency constraints while maximizing learning performance, and uses KKT conditions to solve the wireless resource allocation problem. The approach performs importance-based pruning where weights are pruned based on their difference from updated weights, then optimizes bandwidth allocation given the pruning ratio. The method is validated through simulations using MNIST and Fashion MNIST datasets with CNN models, comparing adaptive pruning against baseline schemes across various network configurations.

## Key Results
- Achieves similar learning accuracy compared to HFL without model pruning
- Reduces communication cost by approximately 50%
- Provides closed-form solutions for both pruning ratio and wireless resource allocation
- Maintains convergence performance under latency and bandwidth constraints

## Architecture Onboarding

- Component map: Cloud server -> Edge servers -> Devices
- Critical path:
  1. Cloud broadcasts global model to edge servers
  2. Edge servers broadcast to devices
  3. Devices train local models with pruning
  4. Devices upload pruned models to edge servers
  5. Edge servers aggregate and upload to cloud
  6. Cloud aggregates global model

- Design tradeoffs:
  - Pruning ratio vs. accuracy: Higher pruning reduces latency but may hurt accuracy
  - Bandwidth allocation vs. fairness: More bandwidth to some devices may improve convergence but reduce fairness
  - Edge vs. cloud aggregation: More edge aggregation reduces cloud load but may increase edge complexity

- Failure signatures:
  - High communication latency despite pruning: Indicates pruning ratio too low or bandwidth allocation suboptimal
  - Poor convergence: May indicate pruning too aggressive or wireless resource allocation causing bottleneck
  - High computation load on devices: May indicate pruning ratio too conservative

- First 3 experiments:
  1. Vary pruning ratio ρₙ,ₑ from 0 to 1 and measure accuracy/latency tradeoff
  2. Test bandwidth allocation strategies: equal vs. optimal under different channel conditions
  3. Compare convergence rates with and without edge aggregation for same total pruning level

## Limitations
- Closed-form solutions rely on strict assumptions about latency constraints and convex optimization that may not hold in highly dynamic wireless environments
- Importance-based pruning method lacks detailed specification of threshold selection, potentially affecting reproducibility
- Edge aggregation complexity is not fully addressed, particularly for large-scale models or high device counts
