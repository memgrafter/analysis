# PALI: A Language Identification Benchmark for Perso-Arabic Scripts

## Quick Facts
- arXiv ID: 2304.01322
- Source URL: https://arxiv.org/abs/2304.01322
- Reference count: 15
- Key outcome: PALI dataset achieves F1 scores 0.88-0.95 across noise levels using hierarchical fastText models

## Executive Summary
This paper introduces PALI, a benchmark dataset for language identification of Perso-Arabic script languages. The dataset addresses the challenge of identifying low-resource languages in bilingual communities where unconventional writing is practiced. The authors create a dataset by collecting text from Wikipedia and news sources, then generate synthetic noisy data by mapping characters between scripts. They propose a hierarchical fastText model that resolves confusion between similar languages, achieving F1 scores ranging from 0.88 to 0.95 across various noise levels, significantly outperforming state-of-the-art LID systems.

## Method Summary
The authors collected text from Wikipedia dumps and local news websites for 19 Perso-Arabic script languages. They generated synthetic noisy data by mapping characters between scripts using manually defined visual similarity rules. A hierarchical fastText model was trained with a root classifier and three cluster-specific classifiers for frequently confused language groups. The system was evaluated at multiple noise levels (0-100%) using macro-average F1 scores.

## Key Results
- Hierarchical model achieves F1 scores 0.88-0.95 across all noise levels
- Significant improvements over baseline fastText lid.176 model
- Script mapping generates realistic synthetic noisy data
- Character n-gram features effectively capture script-based patterns

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Synthetic data generation via script mapping effectively simulates unconventional writing scenarios.
- Mechanism: Random character substitution using visual similarity mappings between Perso-Arabic script variants
- Core assumption: Visual similarity captures real-world unconventional writing patterns
- Evidence anchors: [abstract], [section 2.2], [corpus]
- Break condition: Character mappings fail to reflect phonetic/orographic conventions

### Mechanism 2
- Claim: Hierarchical modeling resolves confusion between closely related languages better than flat classification.
- Mechanism: Cluster-specific classifiers for frequently confused language groups identified from confusion matrix
- Core assumption: Language clusters generalize from training to test data
- Evidence anchors: [abstract], [section 2.5], [section 3.2]
- Break condition: Cluster boundaries not well-defined or relationships change between datasets

### Mechanism 3
- Claim: Character n-gram features capture script-based language patterns effectively.
- Mechanism: fastText models use character n-grams (size 2-6) to detect orthographic patterns
- Core assumption: Character-level patterns distinguish languages sharing script family
- Evidence anchors: [section 2.4], [section 3], [corpus]
- Break condition: Languages share too many character patterns or noise overwhelms signals

## Limitations

- Synthetic data generation may not fully capture real-world unconventional writing patterns
- Dataset construction relies heavily on Wikipedia and news sources, introducing potential domain bias
- Complete script mapping tables and confusion matrices not provided for exact reproduction
