# A Deep Neural Network Based Approach to Building Budget-Constrained Models for Big Data Analysis

## Quick Facts
- arXiv ID: 2302.11707
- Source URL: https://arxiv.org/abs/2302.11707
- Reference count: 15
- The paper proposes a method for building budget-constrained deep learning models by iteratively removing the least important features based on link weights in a fully connected deep neural network.

## Executive Summary
This paper presents a novel approach to building budget-constrained deep learning models by iteratively removing the least important features based on link weights in a fully connected deep neural network. Starting with all available features, the method identifies weak links and neurons by comparing link weights against neuron-specific thresholds, then removes the least impactful feature to meet budget constraints while preserving accuracy. The approach is evaluated on two medical datasets (diabetes and heart disease) and shows superior performance compared to cost-based and random selection approaches in maintaining predictive accuracy across varying budget levels.

## Method Summary
The method builds budget-constrained deep learning models by starting with a fully connected deep neural network (FF-DNN) trained on all available features. It identifies weak links and neurons by comparing link weights to neuron-specific thresholds, marking those below threshold as weak. Beginning from the output layer and working backward, the algorithm marks weak neurons and their connecting links. The least important feature (highest cost among weak input neurons) is iteratively removed, with the model retrained after each removal, until the total model cost falls within the specified budget. This process generates multiple models across different budget levels, allowing users to select the optimal trade-off between accuracy and cost.

## Key Results
- The proposed approach outperforms cost-based and random selection approaches in maintaining predictive accuracy across varying budget levels
- Best trade-off between cost and accuracy observed when moderately reducing feature sets
- Successfully handles both datasets with different characteristics (520 instances with 13 features for diabetes, 76 instances with 14 features for heart disease)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Weak links are identified by comparing link weights to neuron-specific thresholds
- Mechanism: The algorithm sets a threshold for each neuron based on the weights of its input links. Links with weights below this threshold are marked as weak. If all outgoing links from a neuron are weak, the neuron itself is marked as weak, indicating minimal impact on model output.
- Core assumption: Link weights directly correlate with feature importance in a trained DNN
- Evidence anchors:
  - [section] "the absolute weight value of a link in a neural network represents the impact of the source neuron to the target neuron"
  - [section] "We can identify the weak links by setting a threshold for each target neuron of a link"
- Break condition: If features are highly correlated or if the model has learned redundant representations, weight-based importance may not reflect true feature contribution

### Mechanism 2
- Claim: Budget constraints are met by iteratively removing least important features
- Mechanism: Starting with all features, the algorithm repeatedly identifies and removes the least important feature (highest cost among weak neurons) until the model cost falls within budget. Each removal triggers retraining of the model with remaining features.
- Core assumption: Removing features incrementally allows controlled accuracy degradation
- Evidence anchors:
  - [section] "We gradually remove the least important input features until the model costs are within the budgets"
  - [section] "Each time when the least important feature is removed, we build a new FF-DNN model and train it using the same datasets"
- Break condition: If feature interactions are non-linear or if budget constraints require removing multiple important features simultaneously, this sequential approach may fail

### Mechanism 3
- Claim: Backward propagation through layers identifies weak neurons effectively
- Mechanism: The algorithm starts from the last hidden layer (closest to output) and works backward through layers, marking weak links and neurons. This ensures that importance is evaluated based on final impact on predictions.
- Core assumption: Importance propagates backward through network layers in a meaningful way
- Evidence anchors:
  - [section] "Our approach starts with the last hidden layer that most directly affects the output neurons, and then works backward"
  - [section] "starting from the last hidden layer lL-1, all the weak neurons and weak links are marked in a backward manner"
- Break condition: If earlier layers have critical but indirect effects on output, or if the network has skip connections that bypass this evaluation path

## Architecture Onboarding

- Component map:
  - Data preprocessing -> Base model training -> Weak link/neuron identification -> Feature removal loop -> Budget validation -> Accuracy calculation

- Critical path: Data preprocessing → Base model training → Weak feature identification → Feature removal and retraining → Budget validation → Accuracy calculation

- Design tradeoffs:
  - Single feature removal vs. batch removal: Sequential removal allows controlled accuracy degradation but may be slower
  - Fixed vs. adaptive thresholds: Fixed thresholds are simpler but may not adapt well to different model scales
  - Training from scratch vs. fine-tuning: Training new models each time ensures clean starts but is computationally expensive

- Failure signatures:
  - Sharp accuracy drops at specific budget levels may indicate critical feature removal
  - Inconsistent results across runs suggest insufficient training or unstable threshold selection
  - Budget-constrained models performing worse than cost-based or random selection approaches indicate flawed importance identification

- First 3 experiments:
  1. Verify weak link identification by manually checking weight-threshold comparisons on a small network
  2. Test feature removal on a simple dataset with known feature importance to validate the algorithm's selection
  3. Compare model accuracy degradation curves across budget levels to establish baseline performance

## Limitations

- The method relies heavily on the assumption that link weights directly correlate with feature importance, which may not hold for complex feature interactions or correlated features
- The iterative removal approach may be computationally expensive as it requires retraining the model after each feature removal
- The paper only compares against two baseline methods (cost-based and random selection) without exploring more sophisticated feature selection techniques

## Confidence

The paper's claims about weight-based feature importance have **Low confidence** due to the lack of empirical validation for the threshold-setting mechanism and the assumption that link weights directly correlate with feature importance. The method's effectiveness relies heavily on the relationship between weight magnitudes and actual feature contribution, which may not hold for complex feature interactions or correlated features.

The iterative removal approach has **Medium confidence** based on the reported experimental results, but the absence of statistical significance testing and the limited dataset sizes (particularly the heart disease dataset with only 76 instances) reduce confidence in the generalizability of findings.

The budget-constrained optimization claims have **Medium confidence** as the method shows competitive performance against cost-based and random selection approaches, but the experiments only compare against two baseline methods without exploring more sophisticated feature selection techniques.
