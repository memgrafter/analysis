# Easy-to-Hard Learning for Information Extraction

## Quick Facts
- arXiv ID: 2305.09193
- Source URL: https://arxiv.org/abs/2305.09193
- Reference count: 28
- Key outcome: E2H achieves state-of-the-art results on 13 out of 17 datasets across four IE tasks, outperforming one-stage learning by 0.38-2.96 absolute points.

## Executive Summary
Easy-to-Hard Learning for Information Extraction (E2H) is a novel framework that mimics human learning by breaking down the training process into three progressive stages: easy, hard, and main. The framework introduces substructure learning in the easy stage, followed by harder instance construction in the hard stage, and culminates in mastering the full target task. E2H demonstrates consistent improvements across four IE tasks (NER, RE, EE, ABSA) on 17 datasets, achieving state-of-the-art results on 13 datasets.

## Method Summary
E2H employs a three-stage learning approach using pre-trained T5 models. In the easy stage, the model learns basic substructures by modifying input prompts and decomposing target structures. The hard stage constructs more complex training instances by combining two training examples to expose the model to more entities, relations, and contexts. Finally, the main stage focuses on the full target task. The framework uses a unified text-to-structure formulation with prompts containing hints, constraints, and schema information across all stages.

## Key Results
- E2H achieves state-of-the-art results on 13 out of 17 datasets
- Average improvement over one-stage learning: 0.38 (NER), 2.96 (RE), 1.33 (EE), 1.39 (ABSA)
- Consistent performance gains across all four IE tasks
- Effective in low-resource scenarios

- Core assumption: Learning substructures first helps the model build a foundation for understanding the full structure.

## Architecture Onboarding

- Component map: T5 encoder-decoder model -> Three-stage learning (easy, hard, main) -> Prompt with Hint, Constraint, Schema
- Critical path: Easy stage → Hard stage → Main stage
- Design tradeoffs:
  - Using a unified framework simplifies the overall architecture but may require more complex prompt design.
  - Constructing harder instances by combining two instances increases training data diversity but may introduce noise.
- Failure signatures:
  - Poor performance on the main task despite good performance on the easy and hard stages may indicate that the substructures learned are not representative of the full task.
  - If the model struggles with the hard stage, it may suggest that the combined instances are too complex or not representative.
- First 3 experiments:
  1. Train the model only on the easy stage and evaluate its performance on the main task to assess the importance of substructure learning.
  2. Train the model on the main stage only and compare its performance with the full easy-to-hard framework to quantify the benefits of staged learning.
  3. Vary the number of combined instances (M) in the hard stage to find the optimal balance between complexity and diversity.

## Limitations

- The paper lacks detailed implementation specifics for constructing harder instances in the hard stage and prompt engineering techniques.
- The claim of consistent improvement across all tasks needs validation, as gains vary significantly between tasks.
- The framework's dependence on pre-trained T5 models raises questions about generalizability to other architectures.

## Confidence

- **High Confidence:** The core three-stage learning framework and its general methodology are well-articulated and empirically validated across 17 datasets.
- **Medium Confidence:** The mechanism claims about substructure learning and curriculum progression are supported by results but lack detailed ablation studies isolating each stage's contribution.
- **Low Confidence:** The specific implementation details for prompt construction and instance combination in the hard stage are insufficient for exact reproduction without additional clarification.
