# Finspector: A Human-Centered Visual Inspection Tool for Exploring and Comparing Biases among Foundation Models

## Quick Facts
- arXiv ID: 2305.16937
- Source URL: https://arxiv.org/abs/2305.16937
- Reference count: 10
- Key outcome: Human-centered visual inspection tool for detecting biases in foundation models using log-likelihood scores

## Executive Summary
Finspector is a visual analytics tool designed to detect and compare biases across foundation language models. The tool leverages log-likelihood scoring of sentence pairs with stereotypical versus non-stereotypical content to reveal model biases. Through four interactive visualization views—distribution of log-likelihoods, sentence table, sentence embeddings, and customization panel—researchers can explore how different models treat biased content. A case study with the CrowS-Pairs dataset demonstrates the tool's ability to uncover systematic differences in how models handle various bias categories.

## Method Summary
Finspector computes pseudo-log-likelihood scores for sentence pairs where stereotypical and non-stereotypical variants differ only in bias-related terms. These scores are generated using multiple foundation models (BERT, RoBERTa, ALBERT) and visualized through interactive parallel coordinates, density plots, and 2D embeddings. The tool is implemented as a Python package with a Jupyter notebook interface, allowing users to load custom datasets, compute scores in real-time, and explore results through coordinated views. The method relies on masking tokens iteratively to compute sentence likelihoods and uses dimensionality reduction to project high-dimensional score vectors into interpretable 2D spaces.

## Key Results
- Successfully detected differences in log probabilities between stereotypical and non-stereotypical sentences across multiple bias categories
- Demonstrated that different foundation models exhibit varying bias profiles when compared side-by-side
- Showed that interactive visual analytics enable researchers to identify bias patterns that might be missed by automated metrics alone

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Log-likelihood scoring can expose model biases by comparing stereotypical vs non-stereotypical sentence pairs
- Mechanism: The tool computes pseudo-log-likelihood scores for sentence pairs where only stereotype-related terms differ. Lower/higher scores for stereotypical variants reveal model preference, indicating bias.
- Core assumption: Log-likelihood differences reliably correlate with human-perceived bias severity and are comparable across models.
- Evidence anchors: [abstract] "detect biases in different categories through log-likelihood scores generated by language models"; [section] "computing the pseudo-log-likelihood scores of paraphrased sentences using different foundation models can be used to test the consistency and robustness of the models"

### Mechanism 2
- Claim: Interactive visual analytics enable humans to detect subtle bias patterns missed by automated metrics
- Mechanism: Parallel coordinates, density plots, and sentence embeddings let users filter, compare, and cluster log-likelihood scores across models and bias categories, revealing systematic differences.
- Core assumption: Human pattern recognition outperforms purely statistical detection in complex, multi-dimensional bias landscapes.
- Evidence anchors: [abstract] "enable researchers to easily identify potential biases using visual analytics"; [section] "interactive data visualization techniques can help users to form and test their hypotheses about underlying models"

### Mechanism 3
- Claim: Comparing multiple foundation models side-by-side reveals inconsistent bias profiles
- Mechanism: Displaying log-likelihood distributions from BERT, RoBERTa, ALBERT, etc., in coordinated views highlights where models diverge on stereotype detection.
- Core assumption: Different training corpora or architectures lead to distinct bias patterns; side-by-side comparison makes these differences actionable.
- Evidence anchors: [abstract] "detect biases in different categories through log-likelihood scores generated by language models"; [section] "users can use Finspector to generate and visually compare the log probability scores on user-provided sentences"

## Architecture Onboarding

- Component map: User interface (Jupyter notebook) -> Finspector Python package -> Hugging Face model loader -> Log-likelihood computation engine -> Embedding generator -> Visualization views
- Critical path: User loads dataset → models are loaded → log-likelihoods computed → views rendered → interactive exploration
- Design tradeoffs:
  - Real-time log-likelihood computation vs precomputed scores (latency vs freshness)
  - Rich interactivity vs computational cost (especially for large datasets)
  - Model flexibility vs standardization (accept any Hugging Face model vs curated set)
- Failure signatures:
  - Empty views or missing distributions → model loading or computation failure
  - Slow interaction → large dataset or expensive log-likelihood computation
  - Misaligned axes or garbled text → data formatting or embedding projection issues
- First 3 experiments:
  1. Load built-in CrowS-Pairs dataset with default models and verify all four views populate correctly
  2. Apply a simple filter on one model axis and confirm linked views update
  3. Add a custom sentence and check its log-likelihood appears as a distinct polyline across models

## Limitations
- Evaluation relies primarily on a single case study using the CrowS-Pairs dataset, limiting generalizability
- Log-likelihood scoring mechanism lacks direct validation against human-annotated bias severity scores
- Paper does not address potential confounds such as dataset size effects on log-likelihood distributions

## Confidence

- **High Confidence**: The visualization architecture and interactive design principles are well-established in the XAI literature, with clear alignment to human-centered AI evaluation practices.
- **Medium Confidence**: The core claim that log-likelihood differences reveal model biases is plausible but requires broader validation across diverse datasets and bias types beyond the presented case study.
- **Low Confidence**: The assertion that human visual inspection outperforms automated bias detection methods lacks comparative evaluation or empirical evidence from user studies.
