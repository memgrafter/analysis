# Towards More Robust NLP System Evaluation: Handling Missing Scores in Benchmarks

## Quick Facts
- arXiv ID: 2305.10284
- Source URL: https://arxiv.org/abs/2305.10284
- Authors: 
- Reference count: 40

## Executive Summary
This paper addresses the challenge of evaluating NLP systems when some systems are not assessed on certain tasks due to computational or cost constraints. The authors propose a ranking-based approach that imputes missing data using compatible partial rankings and aggregates results using the Borda count method. The method is robust to missing data and outperforms traditional mean aggregation approaches on both synthetic and real benchmarks.

## Method Summary
The method handles missing task-level or instance-level scores by first constructing a matrix representation for each partial ranking that encodes pairwise win probabilities between systems. These matrices are then combined across tasks or instances, and the Borda count is applied to produce a final system ranking. The approach is designed to be robust to missing data and provides confidence intervals for statistical interpretation of the results.

## Key Results
- The method outperforms mean aggregation on both synthetic and real benchmarks with over 131 million scores
- Confidence intervals are provided for statistical interpretation of rankings
- The approach is robust to missing data at both task and instance levels

- Claim: The approach robustly handles missing data by imputing missing task-level or instance-level scores using compatible partial rankings
- Mechanism: Constructs a matrix representation for each partial ranking that encodes pairwise win probabilities, then combines matrices and applies Borda count
- Core assumption: Pairwise comparison information is sufficient to infer system rankings even with incomplete task-level scores

- Break condition: If pairwise win probabilities cannot be accurately estimated (very few system comparisons), the imputation fails

### Mechanism 2
- Claim: Matrix representations enable efficient computation of pairwise win probabilities
- Mechanism: Matrix Mπ encodes proportion of compatible permutations where system i outperforms system j, computed via combinatorial formulas
- Core assumption: Uniform distribution over compatible permutations is a valid model for missing data
- Evidence anchors: [section] provides closed-form expressions and proof of uniformity
- Break condition: If uniformity assumption doesn't hold (systematic bias in missing systems), matrix becomes biased

### Mechanism 3
- Claim: Borda count aggregation produces stable and interpretable final ranking
- Mechanism: Sums column-wise and sorts totals from combined matrix to produce final system ranking
- Core assumption: Borda count is robust to noise and provides fair aggregation of partial rankings

- Break condition: If combined matrix has many entries close to 0.5, ranking becomes arbitrary

## Architecture Onboarding

- Component map: Input -> Matrix builder -> Combiner -> Borda aggregator -> Output
- Critical path: Input → Matrix builder → Combiner → Borda aggregator → Output
  Most computationally intensive step is generating compatible permutations for matrix builder, optimized using combinatorial formulas
- Design tradeoffs:
  - Pairwise matrices vs. direct score aggregation: Matrices handle missing data better but lose magnitude information
  - Borda count vs. other rank aggregation methods: Borda is simple and efficient but may not always produce optimal ranking under certain noise models
  - Uniform vs. weighted compatible permutations: Uniform is simpler but may not reflect true system performance distributions
- Failure signatures:
  - Many matrix entries close to 0.5 → low confidence in pairwise comparisons
  - Rankings change drastically with small changes in input → instability
  - Confidence intervals very wide → insufficient data for reliable ranking
- First 3 experiments:
  1. Generate synthetic data with known ground truth rankings and varying levels of missing data. Verify method recovers correct ranking as missingness decreases.
  2. Apply method to small real benchmark (e.g., GLUE) with artificially removed scores. Compare recovered ranking to full-data ranking.
  3. Measure runtime and memory usage on benchmarks of increasing size to identify scalability limits.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the method's performance scale with extremely large numbers of systems and tasks (beyond 131 million scores)?
- Basis in paper: [inferred] Paper validates method on dataset of over 131 million scores, but scalability to much larger benchmarks not explicitly tested
- Why unresolved: Paper doesn't explore performance or robustness at scales significantly larger than presented dataset
- What evidence would resolve it: Empirical tests showing method's runtime, accuracy, and robustness on datasets with orders of magnitude more systems, tasks, or instances

### Open Question 2
- Question: How sensitive is the ranking method to choice of aggregation function beyond Borda count?
- Basis in paper: [explicit] Paper uses Borda count for aggregation and mentions advantages, but doesn't compare or analyze impact of using other ranking aggregation methods
- Why unresolved: Unclear whether Borda count is optimal or if alternative methods (e.g., Kemeny-Young, Copeland) would yield more accurate or robust rankings under missing data
- What evidence would resolve it: Comparative experiments testing multiple aggregation functions on same datasets and measuring differences in rankings and robustness

### Open Question 3
- Question: How does the method perform when missing data is not random but systematically biased (e.g., certain system types or tasks are consistently excluded)?
- Basis in paper: [inferred] Method designed to handle missing data, but experiments use random missingness; no analysis of systematic bias provided
- Why unresolved: Real-world scenarios may involve systematic missingness due to resource or capability constraints, which could affect validity of rankings
- What evidence would resolve it: Experiments introducing systematic missingness patterns and measuring impact on final rankings and confidence intervals

### Open Question 4
- Question: Can the confidence interval approach be extended to provide statistical significance tests for overall system rankings, not just pairwise comparisons?
- Basis in paper: [explicit] Paper derives confidence intervals for pairwise comparisons but doesn't extend this to full ranking significance
- Why unresolved: Pairwise confidence intervals inform which systems are better, but don't directly indicate if overall ranking order is statistically significant
- What evidence would resolve it: Framework for testing statistical significance of entire rankings, possibly using bootstrapping or permutation tests

## Limitations
- Method assumes uniformity over compatible permutations when imputing missing data, which may not hold if missing systems are systematically worse or better
- Performance depends heavily on having sufficient overlap between systems across tasks - sparse evaluation data leads to wide confidence intervals and unstable rankings
- While outperforming mean aggregation, the magnitude of improvement varies with data characteristics

## Confidence
- High confidence: Mathematical framework for constructing pairwise probability matrices is well-defined and provably correct under uniformity assumption
- Medium confidence: Borda count aggregation produces stable rankings in practice, but may not always be optimal for noisy data
- Medium confidence: Method outperforms mean aggregation on benchmarks, though improvement magnitude varies with data characteristics
