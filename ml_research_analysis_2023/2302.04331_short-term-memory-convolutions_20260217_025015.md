# Short-Term Memory Convolutions

## Quick Facts
- arXiv ID: 2302.04331
- Source URL: https://arxiv.org/abs/2302.04331
- Reference count: 25
- Primary result: 5-fold inference time reduction and 2-fold latency reduction for speech separation using STMC

## Executive Summary
This paper introduces Short-Term Memory Convolutions (STMC), a method for reducing inference latency and memory consumption in convolutional neural networks processing time series signals. STMC caches intermediate outputs of convolutional layers and reuses them in subsequent model calls, allowing arbitrary-sized data chunks to be processed without redundant computations. The approach is demonstrated on U-Net for speech separation and GhostNet for acoustic scene classification tasks, achieving significant improvements in inference speed while preserving output quality. The method is model-agnostic and can be applied to any convolutional architecture, with causal convolutions recommended for near real-time processing.

## Method Summary
STMC modifies convolutional layers by adding cache buffers (shift registers) sized to each layer's receptive field. During online processing, these buffers store intermediate feature maps that would otherwise be recomputed when processing overlapping input chunks. For architectures like U-Net with skip connections, transposed STMC adds similar caching for upsampling layers. The approach fundamentally changes the computational complexity from O(KM²) to O(KM) for K layers with kernel size M, by eliminating redundant computation across multiple convolutional layers. Causal convolutions are used to ensure near real-time processing, and special handling is required for transposed convolutions to maintain causality.

## Key Results
- Speech separation: 5-fold reduction in inference time and 2-fold reduction in latency without affecting output quality
- Acoustic scene classification: Up to 4 times faster inference while preserving accuracy
- Model-agnostic approach applicable to any convolutional architecture

## Why This Works (Mechanism)

### Mechanism 1
STMC caches intermediate convolutional outputs to avoid redundant computation on overlapping input chunks. During online processing, each convolutional layer saves its output feature maps into shift registers sized to its receptive field. When a new chunk arrives, only the newest frames are processed, and cached past outputs are concatenated to form the complete output without recomputing the overlap. Core assumption: The input data chunks are processed in a streaming fashion with overlap equal to the receptive field minus one.

### Mechanism 2
STMC reduces inference latency by a factor of up to 5 compared to incremental inference for speech separation tasks. By caching intermediate feature maps instead of just the input, STMC eliminates redundant computation across multiple convolutional layers. This reduces the computational complexity from O(KM²) to O(KM), where K is the number of layers and M is the kernel size. Core assumption: The reduction in computation time directly translates to lower latency in real-world deployment.

### Mechanism 3
Causal convolutions are necessary for near real-time processing, and STMC preserves causality by proper input shifting. Causal convolutions ensure that each output depends only on current and past inputs. STMC maintains this property by shifting inputs relative to outputs and properly adjusting skip connections in architectures like U-Net. Transposed STMC requires special handling to prevent "anti-causality." Core assumption: Human perception of audio-visual synchronization tolerates up to 40ms delay, making causality critical for real-time applications.

## Architecture Onboarding

- **Component map**: Input → Convolution → Cache intermediate output → Concatenate with cached past outputs → Output. The cache update and concatenation happen in every inference step.

- **Critical path**: Input → Convolution → Cache intermediate output → Concatenate with cached past outputs → Output. The cache update and concatenation happen in every inference step.

- **Design tradeoffs**: STMC trades increased memory usage for reduced computation time. The memory overhead is proportional to the sum of receptive fields across all layers. Causal convolutions reduce memory but may slightly impact accuracy.

- **Failure signatures**: Increased latency despite STMC implementation suggests improper cache sizing or incorrect input shifting. Output quality degradation indicates causality violations in skip connections or transposed convolutions.

## Open Questions the Paper Calls Out

### Open Question 1
How does STMC performance scale with increasingly deep convolutional networks? While the paper demonstrates STMC effectiveness on a specific U-Net depth, it does not provide systematic scaling analysis for much deeper networks or compare performance across different depths. What evidence would resolve it: Comprehensive experiments testing STMC on networks of varying depths (e.g., 3, 7, 15, 25 layers) showing how latency reduction and memory savings change with network depth.

### Open Question 2
How does STMC perform on non-audio time series domains like financial data or sensor networks? The paper claims STMC is "model-agnostic" and applicable to any convolutional architecture processing time series, but all experiments are limited to audio domains. What evidence would resolve it: Application of STMC to at least two non-audio time series tasks (e.g., financial forecasting and sensor data classification) demonstrating similar latency and memory benefits.

### Open Question 3
What is the impact of STMC on model convergence and training stability compared to standard convolutions? The paper states that "the training of STMC-based models is faster and more stable" but provides no empirical comparison of training dynamics. What evidence would resolve it: Direct comparison of training curves, convergence rates, and final validation performance between equivalent models trained with and without STMC across multiple tasks.

## Limitations

- Performance claims are limited to specific tasks and hardware configurations without exploring architectural variations
- Lack of ablation studies showing how STMC performance scales with different receptive field sizes and model depths
- No validation of STMC behavior with non-causal convolutions or irregular input patterns

## Confidence

- **High Confidence**: The mathematical foundation of STMC (Toeplitz matrix representation and shift register implementation) is well-established and correctly applied
- **Medium Confidence**: The empirical results showing latency reduction are convincing but limited to specific tasks and hardware configurations
- **Low Confidence**: The scalability claims across different model architectures and input patterns are not sufficiently validated
