# Disagreement amongst counterfactual explanations: How transparency can be deceptive

## Quick Facts
- **arXiv ID:** 2304.12667
- **Source URL:** https://arxiv.org/abs/2304.12667
- **Reference count:** 40
- **Primary result:** High disagreement among counterfactual explanation methods allows malicious users to manipulate feature inclusion/exclusion in explanations

## Executive Summary
This paper investigates the "disagreement problem" among counterfactual explanation methods, where different algorithms can produce varying explanations for the same model prediction. Using 40 datasets and 12 explanation methods, the authors empirically analyze over 192,000 explanations to quantify this disagreement. They find alarmingly high levels of disagreement, with malicious users easily able to exclude or include specific features in explanations by choosing different methods. The disagreement is primarily driven by dataset characteristics and the type of counterfactual algorithm used, with algorithms optimizing for plausibility showing significantly more disagreement than those optimizing for proximity.

## Method Summary
The authors conduct a large-scale empirical analysis using 40 tabular binary classification datasets. They train Random Forest and ANN classifiers on each dataset, then generate counterfactual explanations for 200 test instances using 12 methods (10 counterfactual algorithms plus SHAP and Anchors). The study calculates three disagreement metrics: relative feature exclusion, relative feature span, and scaled L0 distance between explanations. Results are aggregated across all dataset-model-method combinations to quantify the extent and drivers of disagreement.

## Key Results
- Average relative feature exclusion exceeds 99.6% across all counterfactual methods
- Relative feature span varies from 20-100% depending on the dataset
- Algorithms optimizing for plausibility show significantly more disagreement than proximity-optimized methods
- Dataset characteristics and algorithm type are the primary drivers of disagreement, not the classifier used

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Different counterfactual explanation algorithms can produce mutually exclusive feature sets for the same instance and model prediction.
- Mechanism: Algorithms optimize for different evaluation metrics (plausibility vs proximity) leading to fundamentally different search spaces and solution criteria.
- Core assumption: The optimization objective directly determines which features are included in the explanation.
- Evidence anchors:
  - [abstract] "This disagreement seems to be driven mainly by the dataset characteristics and the type of counterfactual algorithm."
  - [section 3.3.2] "The first six algorithms optimize for plausibility and the last four do not. The second group is only interested in providing counterfactual instances that are close to the original instance and thus called Prox2."
  - [corpus] Weak - corpus papers discuss disagreement generally but don't provide specific empirical evidence about plausibility vs proximity optimization.

### Mechanism 2
- Claim: Malicious users can exploit algorithmic diversity to manipulate feature inclusion/exclusion in explanations.
- Mechanism: By selecting different explanation methods, users can control which features appear in explanations without modifying the underlying model.
- Core assumption: Users have knowledge of which algorithms include/exclude specific features.
- Evidence anchors:
  - [section 3.1] "A malicious user is able to both exclude and include desired features when multiple counterfactual explanations are available."
  - [section 3.3.1] "The average relative feature exclusion is over 99.6% for both classiﬁers over all counterfactual methods, and 99.8% if we include Anchors and SHAP."
  - [corpus] Weak - corpus papers mention deceptive explanations but don't provide concrete evidence about malicious feature manipulation through algorithm selection.

### Mechanism 3
- Claim: Dataset characteristics significantly influence the degree of disagreement between explanation methods.
- Mechanism: Feature distributions, class imbalance, and data manifold structure affect which features are considered important by different algorithms.
- Core assumption: Algorithms interpret feature importance differently based on local data structure.
- Evidence anchors:
  - [abstract] "This disagreement seems to be driven mainly by the dataset characteristics and the type of counterfactual algorithm."
  - [section 3.3.2] "The size of the disagreement problem is highly dependent on the dataset and counterfactual methods used and not so much on the classiﬁer used."
  - [corpus] Weak - corpus papers discuss dataset influence but lack specific quantitative evidence about how dataset characteristics drive counterfactual disagreement.

## Architecture Onboarding

- **Component map:** Data preprocessing pipeline (40 datasets → train/test splits) → Model training (RF and ANN classifiers) → Explanation generation (12 methods producing ~192,000 explanations) → Disagreement quantification (feature exclusion, feature span, pairwise distances) → Analysis engine (aggregating results across datasets and algorithms)

- **Critical path:** Dataset → Model training → Explanation generation → Disagreement metrics → Analysis

- **Design tradeoffs:** Large-scale empirical analysis vs. deeper qualitative understanding of specific algorithm behaviors

- **Failure signatures:**
  - Dataset preprocessing errors causing invalid train/test splits
  - Explanation methods failing to generate valid counterfactuals
  - Numerical instability in distance calculations

- **First 3 experiments:**
