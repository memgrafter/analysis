# Study of Distractors in Neural Models of Code

## Quick Facts
- arXiv ID: 2303.01739
- Source URL: https://arxiv.org/abs/2303.01739
- Reference count: 40
- One-line primary result: Neural code models are significantly influenced by distractor tokens that affect model confidence across multiple tasks and architectures.

## Executive Summary
This study investigates how distractor tokens affect the confidence of neural models in code intelligence tasks. Using a reduction-based approach with Delta Debugging, the authors identify tokens whose removal significantly changes prediction probabilities while preserving the model's prediction. Experiments across four tasks, seven models, and four datasets reveal that models are significantly influenced by distractors, with Code2Vec being particularly susceptible while CodeBERT shows higher reliance on individual tokens. Control structures, data types, and operators emerge as top distractor tokens, providing insights for improving model transparency and reliability.

## Method Summary
The study employs Delta Debugging to systematically remove tokens from source code while monitoring changes in model confidence. When a token's removal causes a confidence change of at least 10%, it is identified as a distractor. The approach is applied across multiple models (RNN, CNN, Code2Vec, Code2Seq, Transformer, CodeBERT) and tasks (vulnerability detection, method naming, variable misuse, code search) using four datasets (s-bAbI, Java-Large, Py150-Great, CSN-Java). The analysis categorizes distractor tokens by type and measures their impact on model confidence.

## Key Results
- Code2Vec model shows highest susceptibility to distractor tokens, while CodeBERT relies more heavily on individual tokens
- Control structures, data types, and operators are consistently identified as top distractor tokens across different tasks
- Removing distractor tokens causes significant changes in model confidence (minimum 10% threshold) while preserving predictions
- Models show varying patterns of token dependency, suggesting architectural differences in how they process code

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Removing distractor tokens systematically changes the model's confidence while preserving its prediction, revealing which tokens affect model certainty.
- Mechanism: The Delta Debugging algorithm iteratively removes tokens from input programs, checking at each step whether the model's prediction remains the same but its confidence (probability score) changes significantly. Tokens whose removal causes a confidence change of at least 10% are identified as distractors.
- Core assumption: The Delta Debugging reduction preserves the model's prediction while removing irrelevant tokens, allowing isolation of confidence-affecting tokens.
- Evidence anchors:
  - [abstract] "Using a reduction-based approach, the authors identify tokens whose removal significantly changes prediction probabilities."
  - [section] "Using Delta Debugging to enhance the transparency of neural code intelligence models by finding the most relevant features to the model's prediction."
- Break condition: If the Delta Debugging reduction changes the model's prediction label, the reduction is invalid and cannot identify distractors for that sample.

### Mechanism 2
- Claim: Different neural models show varying susceptibility to distractors, with Code2Vec being most affected and CodeBERT relying heavily on individual tokens.
- Mechanism: By applying the same reduction-based approach across multiple models and tasks, the study measures how different architectures respond to token removal in terms of confidence changes, revealing architectural differences in token dependency.
- Core assumption: The reduction process and confidence measurement are consistent across different model architectures, allowing valid comparison of distractor susceptibility.
- Evidence anchors:
  - [abstract] "The Code2Vec model is particularly susceptible, while CodeBERT shows higher reliance on individual tokens."
  - [section] "We use the default base configurations given by the authors in their paper or repository, to which we only make minor modifications."
- Break condition: If models use fundamentally different input representations or architectures that make confidence scores incomparable, the comparative analysis breaks down.

### Mechanism 3
- Claim: Tokens from specific categories (control structures, data types, operators) consistently act as distractors across different tasks and programming languages.
- Mechanism: By analyzing the categories of tokens that cause significant confidence changes, the study identifies patterns in which syntactic elements affect model certainty regardless of the specific task or language.
- Core assumption: Token categories have consistent semantic meanings across different programming contexts, making category-based analysis meaningful.
- Evidence anchors:
  - [abstract] "Control structures, data types, and operators are among the top distractor tokens, highlighting their impact on model confidence."
  - [section] "From Table II, we can observe the distractor tokens to be from the following categories: control-flow, datatypes, digits, operators, end-of-statement syntax, and other identifiers and keywords."
- Break condition: If token categorization is inconsistent or if different programming languages use the same tokens for fundamentally different purposes, the cross-task pattern breaks down.

## Architecture Onboarding

- Component map: Delta Debugging reduction engine -> model prediction interface -> confidence change analyzer -> distractor categorization module
- Critical path: input program -> Delta Debugging reduction -> model prediction -> confidence comparison -> distractor identification
- Design tradeoffs: The study uses publicly available pre-trained models with default configurations rather than fine-tuning, prioritizing reproducibility over potentially higher performance. The 10% confidence change threshold balances sensitivity to distractors with avoiding false positives from noise.
- Failure signatures: Common failures include: Delta Debugging reducing the program to the point where the prediction changes (invalidating the sample), confidence scores being too stable to detect distractors, or token categorization being ambiguous for certain syntax elements.
- First 3 experiments:
  1. Run the reduction process on a simple C program from the s-bAbI dataset with the RNN vulnerability detection model to verify the basic pipeline works.
  2. Test the confidence change calculation on a known distractor case from the motivation example (removing "throw" and "new" tokens) to validate the 10% threshold.
  3. Run the complete analysis pipeline on a small subset of 50 samples from one task to check that all components integrate correctly before scaling up.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do different categories of distractor tokens (e.g., control structures, data types, operators) specifically impact the confidence of neural models in their predictions?
- Basis in paper: [explicit] The paper identifies control structures, data types, and operators as top distractor tokens and highlights their impact on model confidence.
- Why unresolved: While the paper identifies these categories, it does not provide a detailed analysis of how each category specifically affects model confidence or why certain categories are more impactful than others.
- What evidence would resolve it: A detailed study analyzing the impact of each category of distractor tokens on model confidence, possibly through controlled experiments isolating the effect of each category.

### Open Question 2
- Question: To what extent do distractor tokens affect the generalizability of neural models of code across different tasks and datasets?
- Basis in paper: [inferred] The paper suggests that models may rely on irrelevant features or noise, which could hinder generalizability, but does not explicitly explore this aspect in the context of distractor tokens.
- Why unresolved: The study focuses on the impact of distractor tokens on model confidence but does not investigate how these tokens might affect the model's ability to generalize to new, unseen data.
- What evidence would resolve it: Experiments testing the performance of models with and without distractor tokens on unseen datasets to assess changes in generalizability.

### Open Question 3
- Question: Can the identification and removal of distractor tokens improve the transparency and reliability of neural models in code intelligence tasks?
- Basis in paper: [explicit] The paper aims to enhance model transparency by emphasizing tokens that significantly influence model confidence, implying that removing distractors could improve reliability.
- Why unresolved: The paper introduces the concept of distractors and their impact but does not provide evidence on whether removing these tokens leads to improved model transparency or reliability.
- What evidence would resolve it: Comparative studies showing the performance and interpretability of models before and after the removal of identified distractor tokens.

## Limitations
- The 10% probability change threshold for identifying distractors may exclude subtle but meaningful confidence shifts
- The reduction process may introduce artifacts that artificially affect confidence beyond the specific token's influence
- The study focuses on four datasets, limiting broader generalizability across different programming languages and domains

## Confidence
- **High Confidence**: Different models show varying susceptibility to distractors (Code2Vec vs. CodeBERT) is well-supported by systematic experimentation across multiple models and tasks
- **Medium Confidence**: Specific token categories (control structures, data types, operators) consistently act as distractors across tasks and languages is supported by categorical analysis but may reflect dataset-specific patterns
- **Medium Confidence**: Models are "significantly influenced" by distractors is well-demonstrated statistically, but practical significance for real-world deployment remains unclear

## Next Checks
1. Implement cross-validation on the 10% threshold by testing multiple thresholds (5%, 10%, 15%) and analyzing how the number and type of identified distractors changes, establishing sensitivity analysis for this critical parameter
2. Conduct ablation studies where syntactically invalid reduced programs are filtered out, ensuring that confidence changes are attributable to the removed token rather than code validity issues introduced by the reduction process
3. Test whether identified distractors maintain their confidence-impacting properties when the same code is processed by different models (e.g., verifying that tokens identified as distractors for Code2Vec also affect CodeBERT's confidence), establishing cross-model consistency
