# Fair multilingual vandalism detection system for Wikipedia

## Quick Facts
- arXiv ID: 2306.01650
- Source URL: https://arxiv.org/abs/2306.01650
- Reference count: 30
- This paper introduces a new system for detecting vandalism on Wikipedia that improves upon the current state-of-the-art ORES system

## Executive Summary
This paper presents a vandalism detection system that uses multilingual BERT fine-tuning and metadata features to detect vandalism across 47 Wikipedia languages. The system outperforms the current ORES system in accuracy metrics while reducing bias against anonymous users. By training on anonymous-only revisions and combining semantic embeddings with metadata features, the model achieves better fairness metrics (DIR of 9.54 vs ORES's 20.02) while maintaining competitive accuracy across all languages.

## Method Summary
The authors collected a large dataset from Wikimedia dumps spanning 47 languages, filtered to remove bots and edit wars, and split into training (6 months) and hold-out test sets (1 week). They fine-tuned four multilingual BERT models to predict whether revisions would be reverted, using text changes, inserts, removes, and page titles as inputs. These MLM features were aggregated with mean/max pooling and combined with metadata features in a CatBoost classifier. The model was evaluated against ORES using AUC, precision, and fairness metrics including Disparate Impact Ratio.

## Key Results
- Model outperforms ORES in accuracy metrics while covering 60% more languages (47 vs 11)
- Shows significantly less bias against anonymous users (DIR reduced from 20.02 to 9.54)
- Anonymous-only training model achieves higher AUC for anonymous edits (0.757 vs 0.732) while maintaining overall accuracy
- Covers 47 Wikipedia languages compared to ORES's 11 languages

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Multilingual BERT fine-tuning extracts cross-linguistic semantic features that improve vandalism detection accuracy beyond fixed dictionaries.
- **Mechanism:** The system uses a pretrained multilingual BERT model to encode semantic changes in text inserts, removals, and edits. These embeddings capture context-dependent meaning, which is then aggregated (mean/max pooling) and combined with metadata features in a final CatBoost classifier. This approach generalizes better across 47 languages compared to language-specific word lists.
- **Core assumption:** Semantic embeddings from mBERT capture vandalism-relevant signals better than static keyword lists, and the model generalizes across languages without catastrophic forgetting.
- **Evidence anchors:**
  - [abstract] "applied advanced filtering and feature engineering techniques, including multilingual masked language modeling to build the training dataset from human-generated data"
  - [section 3.1.1] "We apply the fine-tuned MLMs that were trained to predict the event of revision to be reverted"
  - [corpus] Weak. Corpus shows related vandalism detection work but no direct mBERT comparison.
- **Break condition:** If the mBERT model fails to generalize across languages or if vandalism patterns are highly language-specific, performance drops.

### Mechanism 2
- **Claim:** Training on anonymous-only revisions reduces bias against anonymous users while maintaining or improving detection accuracy.
- **Mechanism:** By constructing separate training datasets—one for anonymous users only, another for all users—the model learns patterns specific to anonymous editing behavior. The anonymous-trained model shows higher AUC for anonymous edits (0.757 vs 0.732) while still performing competitively on all edits.
- **Core assumption:** Anonymous edits have distinct linguistic and behavioral patterns that can be learned without harming overall accuracy.
- **Evidence anchors:**
  - [abstract] "Our model outperforms ORES, ensuring that the results provided are not only more accurate but also less biased against certain groups of contributors"
  - [section 5.2] "We observe a significant improvement in performance for anonymous users"
  - [corpus] Weak. Corpus includes vandalism detection but no direct bias mitigation comparison.
- **Break condition:** If anonymous and registered user patterns overlap significantly, separate training provides no benefit and may reduce overall accuracy.

### Mechanism 3
- **Claim:** Combining mBERT-derived features with metadata and edit-type features improves fairness metrics (DIR) and accuracy simultaneously.
- **Mechanism:** The system extracts four types of mBERT features (changes, inserts, removes, page titles) and combines them with metadata (user type, bytes changed) and mwedittypes features. This hybrid approach achieves DIR of 9.54 vs ORES's 20.02, indicating significantly reduced bias against anonymous users.
- **Core assumption:** Metadata features introduce bias but also provide useful signals; mBERT features can compensate for bias while maintaining predictive power.
- **Evidence anchors:**
  - [abstract] "ensuring that the results provided are not only more accurate but also less biased against certain groups of contributors"
  - [section 5.4] "The best-performing configuration of our solution shows a DIR value of 9.54, which is much closer to the base value"
  - [corpus] Weak. Corpus mentions fairness but lacks direct DIR comparison.
- **Break condition:** If mBERT features fail to capture vandalism signals, adding them only increases complexity without improving fairness or accuracy.

## Foundational Learning

- **Concept: Multilingual masked language modeling**
  - Why needed here: To extract language-agnostic semantic features from text changes across 47 Wikipedia languages without relying on language-specific dictionaries.
  - Quick check question: How does mBERT handle languages with different scripts or word orders during fine-tuning?

- **Concept: Group fairness metrics (Disparate Impact Ratio)**
  - Why needed here: To quantify and reduce algorithmic bias against anonymous users, who are a protected group in Wikipedia's context.
  - Quick check question: What is the relationship between DIR and the base rate ratio in an unbalanced dataset?

- **Concept: Time-based train-test split**
  - Why needed here: To prevent data leakage and ensure evaluation reflects real-world performance on future edits.
  - Quick check question: Why is random splitting problematic when evaluating vandalism detection models?

## Architecture Onboarding

- **Component map:** Data ingestion → Text preprocessing → Feature extraction → Classification → Deployment
- **Critical path:** Revision ingestion → Text change extraction → mBERT feature computation → Feature aggregation → CatBoost prediction → API response
- **Design tradeoffs:**
  - mBERT vs. language-specific models: Better coverage vs. potential performance loss
  - Anonymous-only training vs. mixed training: Reduced bias vs. possible accuracy trade-off
  - Real-time inference vs. batch processing: Lower latency vs. higher resource usage
- **Failure signatures:**
  - High latency: Large text changes causing mBERT processing delays
  - Low AUC for specific languages: mBERT model not generalizing well
  - Increased bias metrics: Metadata features overpowering mBERT signals
- **First 3 experiments:**
  1. Compare AUC of mBERT features vs. baseline ORES on holdout test set
  2. Measure DIR improvement when adding mBERT features to metadata-only model
  3. Test inference latency with varying text change sizes on CPU-only instances

## Limitations
- Coverage claims based on comparison with ORES's 11 languages, but ORES's actual supported languages aren't independently verified
- Fairness improvements demonstrated primarily through DIR reduction, but intersectional bias not explored
- Real-world deployment claims lack operational metrics like sustained performance over time or false positive rates

## Confidence
- **High confidence**: mBERT feature extraction methodology and its integration with CatBoost classifier
- **Medium confidence**: Claims about accuracy improvements over ORES (based on controlled experiments but limited comparison framework)
- **Medium confidence**: Fairness improvements for anonymous users (DIR reduction demonstrated but real-world bias impact not fully characterized)
