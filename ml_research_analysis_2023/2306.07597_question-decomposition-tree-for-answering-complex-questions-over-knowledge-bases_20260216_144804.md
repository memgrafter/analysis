# Question Decomposition Tree for Answering Complex Questions over Knowledge Bases

## Quick Facts
- arXiv ID: 2306.07597
- Source URL: https://arxiv.org/abs/2306.07597
- Reference count: 10
- Key outcome: Question Decomposition Trees (QDT) improve complex KBQA performance by 12% on LC-QuAD 1.0 and outperform previous methods on ComplexWebQuestions

## Executive Summary
This paper introduces Question Decomposition Trees (QDT) to address the limitations of existing question decomposition methods for complex KBQA tasks. The authors propose a two-staged Clue-Decipher method that generates QDTs while preserving original question semantics. They implement a KBQA system called QDTQA that leverages QDTs to guide query generation. Experimental results show that QDTQA outperforms state-of-the-art methods on ComplexWebQuestions and achieves a new state-of-the-art on LC-QuAD 1.0 with a 12% improvement.

## Method Summary
The authors propose a two-staged decomposition method called Clue-Decipher. First, ClueNet (a T5-based model) generates a corrupted clue with separators representing compositionality types. Then, DecipherNet (a BERT-based multi-choice model) positions these separators in the original question to produce the QDT. The QDT is then used by QDTQA, which incorporates entity linking (using ELQ and FACC1) and a T5-based query generation model to produce executable SPARQL queries. The system normalizes questions into S-expressions before query generation.

## Key Results
- QDTQA outperforms previous state-of-the-art methods on ComplexWebQuestions dataset
- QDTQA improves an existing KBQA system by 12% on LC-QuAD 1.0, setting a new state-of-the-art
- QDT provides structural guidance that improves query structure (7.31% more correct queries) and relation linking (10.53% better results)

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Tree-based decomposition better models complex question structure than sequence-based splitting
- Mechanism: QDT captures nested compositionality by allowing inner questions as subtrees rather than just binary splits
- Core assumption: Complex questions often contain multiple compositionality types (conjunction + composition)
- Evidence anchors:
  - [abstract] "Existing decomposition methods split the question into sub-questions according to a single compositionality type, which is not sufficient for questions involving multiple compositionality types"
  - [section] "We find that 39% and 31% of the questions in ComplexWebQuestions (CWQ) (Talmor and Berant 2018) and LC-QuAD 1.0 (LC) (Trivedi et al. 2017), contain more than one compositionality type"
- Break condition: If questions rarely contain multiple compositionality types, the added complexity of tree structure provides minimal benefit

### Mechanism 2
- Claim: Clue-Decipher preserves original question semantics while leveraging NLG strength
- Mechanism: First generates a corrupted clue with separators, then uses DecipherNet to insert separators into original question
- Core assumption: Separators can be accurately positioned based on semantic similarity between clue and original question
- Evidence anchors:
  - [section] "It leverages the strong generation ability of NLG models and simultaneously ensures that the original question remains unchanged"
  - [section] "none of the example become worse after the incorporation of DecipherNet"
- Break condition: If NLG models cannot reliably preserve question semantics in corrupted clues, downstream KBQA performance degrades

### Mechanism 3
- Claim: QDT provides structural guidance that improves both query structure and relation linking
- Mechanism: QDT constrains search space by encoding decomposition structure into query generation input
- Core assumption: Query generation model can effectively utilize QDT as implicit structural guidance
- Evidence anchors:
  - [section] "additional 7.31% questions derive correct query structures" after using QDT
  - [section] "10.53% questions get better relation linking results after the incorporation of QDT"
- Break condition: If query generation model cannot effectively interpret QDT structure, the benefit disappears

## Architecture Onboarding

- Component map: Question → ClueNet → DecipherNet → QDT → Entity Linker → Query Generator → SPARQL
- Critical path: Question → ClueNet → DecipherNet → QDT → Query Generator → SPARQL
- Design tradeoffs:
  - Two-stage decomposition adds complexity but improves semantic preservation
  - Tree structure captures complexity but requires more annotation effort
  - S-expression normalization simplifies model input but requires conversion logic

- Failure signatures:
  - ClueNet produces clues missing key entities or relations
  - DecipherNet selects wrong separator positions, breaking original question
  - Entity linker fails to correctly identify entities
  - Query generator produces invalid S-expressions

- First 3 experiments:
  1. Evaluate ClueNet alone on QDTrees to measure semantic preservation
  2. Test DecipherNet's separator positioning accuracy on held-out data
  3. Run QDTQA without QDT to measure decomposition contribution to QA performance

## Limitations
- Requires significant annotation effort for training data generation
- Evaluation limited to two specific datasets (ComplexWebQuestions and LC-QuAD)
- Two-stage decomposition introduces additional complexity compared to direct methods
