# Zero-Shot Next-Item Recommendation using Large Pretrained Language Models

## Quick Facts
- arXiv ID: 2304.03153
- Source URL: https://arxiv.org/abs/2304.03153
- Reference count: 32
- Zero-shot NIR achieves 11.87% HR@10 and 5.46% NDCG@10 on MovieLens 100K

## Executive Summary
This paper introduces Zero-Shot NIR (Next-Item Recommendation), a prompting approach that enables LLMs to perform next-item recommendation without any training data. The method addresses two key challenges: the extremely large recommendation space and the lack of user preference modeling in LLMs. By constructing focused candidate item sets and using a 3-step prompting strategy, NIR captures user preferences and makes recommendations directly through prompting. Experiments on MovieLens 100K demonstrate that NIR achieves strong zero-shot performance, outperforming some fully trained sequential recommendation models.

## Method Summary
The method involves three key components: candidate set construction using user filtering or item filtering to create a manageable set of 19 movies per user, a 3-step prompting strategy that captures user preferences, selects representative movies, and recommends from the candidate set, and formatting hints to facilitate answer extraction. The approach uses GPT-3 text-davinci-003 with temperature=0 and evaluates performance using HR@10 and NDCG@10 metrics on the MovieLens 100K dataset.

## Key Results
- NIR-Multi-UF variant achieves 11.87% HR@10 and 5.46% NDCG@10 on MovieLens 100K
- Zero-shot NIR outperforms some fully trained sequential recommendation models
- Candidate set construction significantly improves LLM recommendation performance
- Three-step prompting provides better results than single-step approaches

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Zero-shot NIR prompting works because it reduces the recommendation space by using external candidate set construction before prompting.
- Mechanism: By applying user filtering or item filtering, the method constructs a focused candidate set of items that are more likely to be relevant to the target user, thereby reducing the combinatorial complexity that LLMs face with large recommendation spaces.
- Core assumption: LLMs perform better when the candidate space is constrained to items that are contextually relevant to the user, rather than being exposed to the full universe of items.
- Evidence anchors:
  - [abstract] "First, the recommendation space can be extremely large for LLMs, and LLMs do not know about the target user's past interacted items and preferences."
  - [section 3.2] "the recommendation space can be extremely large for LLMs... We therefore propose to first construct the candidate movie set for each target user using a principled approach."
  - [corpus] No direct evidence about candidate set impact on LLM performance; this is assumed from NLP prompting literature.
- Break condition: If the candidate set is too small, it restricts the diversity of recommendations; if too large, it overwhelms the LLM's reasoning capacity and performance degrades.

### Mechanism 2
- Claim: The three-step prompting strategy improves performance by progressively building context and narrowing the recommendation focus.
- Mechanism: Step 1 captures user preferences from past interactions; Step 2 uses those preferences to rank representative movies; Step 3 uses both to recommend from the candidate set. This staged approach mirrors how humans reason about recommendations.
- Core assumption: LLMs can simulate multi-step reasoning when given clear, structured prompts that build upon each other, and that intermediate outputs can be reliably incorporated into subsequent prompts.
- Evidence anchors:
  - [abstract] "Our strategy incorporates a 3-step prompting that guides GPT-3 to carry subtasks that capture the user's preferences, select representative previously watched movies, and recommend a ranked list of 10 movies."
  - [section 3.3] "three instruction prompts corresponding to three subtasks... capture the target user's preferences, ranking previously interacted movies by user's preferences, and recommending 10 similar movies from the candidate set."
  - [corpus] No direct evidence about multi-step prompting effectiveness in recommendation; assumed from zero-shot reasoning literature.
- Break condition: If intermediate steps produce incorrect or irrelevant outputs, the final recommendation quality will degrade significantly.

### Mechanism 3
- Claim: Formatting hints in prompts improve answer extraction reliability from LLM outputs.
- Mechanism: By instructing GPT-3 to output recommendations in a specific format (e.g., "a watched movie: <- a candidate movie ->"), the method enables rule-based extraction of recommendations from free-form text.
- Core assumption: LLMs will follow explicit formatting instructions when prompted, and that the format can be parsed reliably to extract structured recommendation data.
- Evidence anchors:
  - [section 3.4] "We add the hint... to generate answers in the desired format for easy extraction. Our study has shown that such a hint has worked very well."
  - [abstract] "Finally, Zero-Shot NIR introduces a formatting technique in Step 3 to facilitate the extraction of movie items from the answer text generated by GPT-3"
  - [corpus] No direct evidence about formatting hints in LLM outputs; this is an empirical claim from the paper.
- Break condition: If the LLM ignores formatting instructions or produces unexpected variations, extraction will fail or require complex parsing.

## Architecture Onboarding

- Component map:
  Candidate Set Construction -> Three-Step Prompting Engine -> Answer Extraction Module -> GPT-3 API Interface

- Critical path:
  1. Pre-compute candidate sets for all users
  2. For each recommendation request: execute Step 1 prompt → parse output → execute Step 2 prompt with intermediate result → parse output → execute Step 3 prompt with both intermediate results → parse final recommendations

- Design tradeoffs:
  - Candidate set size: Larger sets provide more options but reduce LLM performance; smaller sets are more manageable but limit recommendation diversity
  - Prompt granularity: More detailed prompts improve quality but increase API costs and latency
  - Format reliance: Structured outputs enable easy extraction but may fail if LLM ignores formatting instructions

- Failure signatures:
  - Poor HR@10/NDCG@10 scores indicating LLM is not effectively narrowing recommendations
  - Extraction errors when parsing LLM outputs due to format deviations
  - High variance in recommendations across repeated prompts with same input

- First 3 experiments:
  1. Test candidate set construction with varying sizes (15-22 items) to find optimal performance point
  2. Compare single-prompt vs. three-step prompting to quantify the benefit of intermediate context
  3. Test user filtering vs. item filtering to determine which yields better candidate sets for the dataset

## Open Questions the Paper Calls Out

- Why unresolved: The paper only evaluates on the MovieLens 100K dataset, limiting generalizability to other recommendation domains.
- What evidence would resolve it: Experiments applying the NIR prompting strategy to other domains like music, books, or products, comparing performance to domain-specific baselines.

### Open Question 2
- Question: How does the performance of zero-shot LLM-based recommendation compare to few-shot and fine-tuned approaches?
- Basis in paper: [explicit] The authors mention that their work can be extended to the few-shot setting as a future direction.
- Why unresolved: The paper only evaluates zero-shot performance, not comparing to few-shot or fully fine-tuned models.
- What evidence would resolve it: Comparative experiments measuring HR@10 and NDCG@10 for zero-shot, few-shot, and fully fine-tuned versions of the NIR approach and baselines.

### Open Question 3
- Question: What is the impact of LLM model size and architecture on zero-shot recommendation performance?
- Basis in paper: [inferred] The paper uses GPT-3 text-davinci-003 (175B) but doesn't explore how different model sizes or architectures affect results.
- Why unresolved: Only one LLM variant is tested, leaving questions about scalability and efficiency unanswered.
- What evidence would resolve it: Experiments comparing NIR performance across different GPT-3 variants (Ada, Babbage, Curie, Davinci) and other LLM architectures like PaLM or OPT.

## Limitations

- Evaluation limited to a single dataset (MovieLens 100K) with relatively small user base, raising questions about scalability
- Critical prompt templates and exact candidate set construction parameters are not publicly available
- Performance claims rely on formatting-based answer extraction that may not generalize across different LLM models or prompt variations

## Confidence

- **High Confidence**: The core observation that candidate set construction improves LLM recommendation performance by reducing the search space is well-supported by the experimental results showing consistent improvement across different filtering methods.
- **Medium Confidence**: The claim that 3-step prompting significantly outperforms single-step approaches is supported by the results, but without access to the actual prompts, it's difficult to assess whether the improvement stems from the specific prompt design or the general principle of staged reasoning.
- **Low Confidence**: The assertion that formatting hints reliably enable answer extraction across different LLM versions and prompting scenarios is based on internal testing without public validation, making it the most fragile component of the approach.

## Next Checks

1. **Prompt Template Verification**: Request and test the exact prompt templates used in each step to determine whether the performance gains are reproducible with the stated prompts or if they depend on specific phrasing choices that weren't documented.

2. **Scalability Testing**: Evaluate the approach on a larger recommendation dataset (e.g., MovieLens 20M or Netflix Prize data) to verify whether the candidate set construction and 3-step prompting strategies maintain their effectiveness as the number of users and items scales up by orders of magnitude.

3. **Format Robustness Testing**: Systematically test the answer extraction mechanism by intentionally introducing minor variations in LLM outputs (e.g., different phrasing, added punctuation, reordered elements) to quantify how sensitive the formatting-based extraction is to output variations and whether more robust parsing methods are needed.
