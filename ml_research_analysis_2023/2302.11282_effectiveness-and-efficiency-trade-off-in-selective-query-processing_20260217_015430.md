# Effectiveness and Efficiency Trade-off in Selective Query Processing

## Quick Facts
- arXiv ID: 2302.11282
- Source URL: https://arxiv.org/abs/2302.11282
- Reference count: 31
- One-line primary result: Selective query processing method using machine learning achieves superior effectiveness and efficiency compared to baselines by choosing optimal processing threads per query

## Executive Summary
This paper addresses the challenge of optimizing both effectiveness and efficiency in information retrieval systems through selective query processing. The authors propose a method that selects the best query processing thread on a query-by-query basis using machine learning, considering factors like term weighting functions and query expansion models. Experiments on three TREC collections demonstrate that their selective approach significantly outperforms traditional baselines in both effectiveness and efficiency metrics. The study finds that the optimal trade-off is achieved when using the best trained processing thread and its query expansion counterpart, suggesting that query expansion optimization is key for real-world search engines.

## Method Summary
The approach involves creating a grid of over 20,000 query processing threads that vary term weighting models, query expansion models, and hyperparameters (#expansion documents/terms). Candidate threads are selected using a risk-reward function, then a model is trained using SVM-rank with LETOR features extracted from BM25 top-K results. The selective model chooses between two candidate processing threads per query based on extracted features. The method is evaluated on three TREC collections (TREC78, GOV2, WT10g) with effectiveness metrics (AP, nDCG@10, P@10) and efficiency metrics (elapsed time for data generation, model training, and runtime processing).

## Key Results
- Selective query processing outperforms traditional BM25 baseline and data fusion approaches (CombSum) in both effectiveness and efficiency
- The best trade-off between effectiveness and efficiency is achieved using the best trained processing thread and its query expansion counterpart
- Selective approach demonstrates significant improvements in AP, nDCG@10, and P@10 metrics while maintaining efficient runtime performance

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The selective query processing method achieves superior effectiveness by optimizing both the term weighting function and query expansion model per query rather than using a one-size-fits-all approach.
- Mechanism: By training a model to select between two candidate processing threads (one with and one without query expansion) based on query features, the system can choose the most appropriate thread for each query. The method uses a risk-based function to select candidates and SVM-rank for the final decision.
- Core assumption: Query features can reliably predict which processing thread will be most effective for a given query.
- Evidence anchors: [abstract] "The choice is based on query features." [section] "The selective model is trained using a supervised approach that considers query features."

### Mechanism 2
- Claim: The best trade-off between effectiveness and efficiency is achieved when using the best trained processing thread and its query expansion counterpart.
- Mechanism: This approach leverages the fact that the core engine (term weighting function) remains the same between the two threads, while only the query expansion component varies. This reduces computational overhead while maintaining effectiveness gains from selective expansion.
- Core assumption: The term weighting function is the primary determinant of effectiveness, and query expansion provides complementary gains when appropriately applied.
- Evidence anchors: [abstract] "This seems to be also the most natural for a real-word engine since the two threads use the same core engine (e.g., same term weighting function)." [section] "we found that the best trade-off between effectiveness and efficiency is obtained when using the best trained processing thread and its query expansion counter part."

### Mechanism 3
- Claim: Selective query processing outperforms data fusion approaches in both effectiveness and efficiency.
- Mechanism: By selecting the optimal thread per query rather than fusing results from multiple threads, the system avoids the computational cost of redundant processing and merging while achieving comparable or better effectiveness.
- Core assumption: The computational overhead of data fusion (running multiple threads and merging results) is not offset by effectiveness gains.
- Evidence anchors: [section] "Our results contradict the intuition that data fusion was more effective although less efficient (CombSum baseline)." [section] "we found that selective approach is both more effective and efficient than data fusion."

## Foundational Learning

- Concept: Term weighting functions (e.g., BM25, DFRee, DirichletLM)
  - Why needed here: The paper compares different term weighting functions as part of the processing threads. Understanding how these functions work is essential to grasp why certain combinations perform better.
  - Quick check question: How does BM25 differ from DFRee in terms of document length normalization and term frequency saturation?

- Concept: Query expansion techniques (e.g., KL, Bo1, Bo2)
  - Why needed here: Query expansion is a key component of the selective processing threads. Understanding different expansion models helps explain why some threads are more effective than others.
  - Quick check question: What is the difference between KL and Bo1 query expansion in terms of how they select additional terms?

- Concept: Learning to rank (L2R) with SVM-rank
  - Why needed here: The paper uses SVM-rank to learn which processing thread to select for each query. Understanding L2R principles is crucial for implementing the selective approach.
  - Quick check question: How does SVM-rank differ from traditional ranking methods in terms of feature usage and training objectives?

## Architecture Onboarding

- Component map: Query → Feature extraction → Thread selection (SVM-rank) → Process with selected thread → Return results
- Critical path: Query → Feature extraction → Thread selection (SVM-rank) → Process with selected thread → Return results
- Design tradeoffs: The method trades increased training complexity and memory usage (storing multiple threads) for improved query-level effectiveness and runtime efficiency compared to data fusion approaches.
- Failure signatures: Poor performance on queries where features don't correlate with thread effectiveness, increased latency if thread selection model is slow, or degraded results if risk-based candidate selection fails to identify complementary threads.
- First 3 experiments:
  1. Implement BM25 baseline and measure effectiveness on a small query set to establish baseline performance.
  2. Implement a simple selective query expansion (SQE) system with two threads and SVM-rank selection, measure effectiveness gains over BM25.
  3. Extend to full selective query processing (SQP) with two threads varying both weighting and expansion, compare effectiveness and efficiency against SQE and baselines.

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions, but based on the discussion section, several important questions emerge:

- How would the selective query processing approach scale to handle more than two query processing threads?
- What is the impact of different query types (e.g., ambiguous, entity-specific, broad) on the effectiveness of selective query processing?
- How does the performance of selective query processing compare to other meta-search approaches, such as the combination of multiple retrieval models?

## Limitations
- Dependency on query features being predictive of processing thread effectiveness
- Evaluation limited to title-only queries from TREC collections
- Computational overhead of training and maintaining multiple processing threads not fully characterized
- Risk-based candidate selection mechanism not fully specified

## Confidence
- Mechanism 1 (Query feature-based selection): Medium confidence - well-described but depends on feature predictability
- Mechanism 2 (Same-core optimization): High confidence - clearly demonstrated and intuitive
- Mechanism 3 (Selective vs data fusion): High confidence - results are consistent and well-supported
- Overall approach effectiveness: High confidence - multiple metrics and collections show consistent improvements
