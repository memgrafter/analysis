# Modular Domain Adaptation for Conformer-Based Streaming ASR

## Quick Facts
- **arXiv ID**: 2305.13408
- **Source URL**: https://arxiv.org/abs/2305.13408
- **Reference count**: 0
- **Primary result**: MDA achieved similar performance to multidomain models with 0.2-0.4% absolute WER degradation across voice search and dictation domains.

## Executive Summary
Modular Domain Adaptation (MDA) is proposed as a method to enable a single Conformer transducer to process multidomain speech data while keeping all parameters domain-specific. The approach introduces per-domain components or adapters into a backbone model trained only on video caption data. By adding per-domain adapters and feed-forward networks in the Conformer encoder, MDA achieves similar performance to multidomain models across voice search and dictation domains, with only 22% of the backbone model's parameters being domain-specific.

## Method Summary
The MDA framework uses a YT-only Conformer transducer as the backbone model, with per-domain adapters and feed-forward networks added to the non-causal encoder. The backbone remains frozen while per-domain parameters are fine-tuned using MWER training on combined data from all domains. The model uses domain routing to process multidomain data through either the backbone or domain-specific parameters. Training is conducted on 8x8 TPUs with batch size 4096 for 300k steps.

## Key Results
- MDA achieved similar performance to multidomain models across voice search and dictation domains
- Per-domain parameters represented only 22% of the backbone model's parameters
- Non-causal encoder blocks with future context were more effective for cross-domain adaptation than causal blocks
- WER degradation was minimal (0.2-0.4% absolute) after MWER training

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Per-domain adapters can efficiently adapt a backbone model to new domains without retraining all parameters.
- Mechanism: Adapters insert lightweight modules (via weight matrices W_down and W_up) that transform intermediate representations from the backbone model, allowing domain-specific adjustments while keeping the backbone frozen.
- Core assumption: Domain-specific variations in speech data can be captured by modifying intermediate representations rather than the entire model.
- Evidence anchors:
  - [abstract] "adding per-domain adapters and per-domain feed-forward networks in the Conformer encoder"
  - [section] "adapters are commonly used as efficient modules to adapt large foundation models for particular tasks without finetuning all model parameters"
- Break condition: If the domain shift is too large or the backbone model is too domain-specific, adapters may not capture necessary variations.

### Mechanism 2
- Claim: Per-domain Conformer modules in the non-causal encoder are more effective than those in the causal encoder for cross-domain adaptation.
- Mechanism: Non-causal encoder blocks use future context, allowing them to better learn domain-invariant patterns that help recognition in target domains.
- Core assumption: Future context in non-causal blocks provides additional modeling capacity for domain adaptation.
- Evidence anchors:
  - [section] "with the help of future context, the WERs drop to around 6% for all non-causal Conformer blocks"
  - [section] "non-causal blocks hold much more significance than causal blocks in terms of the recognition quality on the target domain"
- Break condition: If streaming latency constraints prevent using non-causal blocks, the adaptation effectiveness may decrease.

### Mechanism 3
- Claim: Modular domain adaptation allows selective updating of domain-specific parameters while keeping the backbone fixed.
- Mechanism: By routing traffic through per-domain parameters only when available, the model can process multidomain data with domain-specific parameter usage.
- Core assumption: Different domains can be effectively separated by routing through specific parameter sets without affecting other domains.
- Evidence anchors:
  - [abstract] "enables a single model to process multidomain data while keeping all parameters domain-specific"
  - [section] "all traffic passes through the common backbone model except certain parts of the model where the traffic is split and routed through the per-domain parameters"
- Break condition: If domains have significant overlap in acoustic/linguistic characteristics, separate parameter sets may be redundant.

## Architecture Onboarding

- **Component map**: Input features → Backbone Conformer (causal + non-causal blocks) → Per-domain adapters/FFN → Decoder (HAT) → Joint Network → Wordpiece tokens

- **Critical path**: Encoder → Decoder (HAT) → Joint Network → Output vocabulary

- **Design tradeoffs**:
  - Parameter efficiency vs. quality: Per-domain adapters use fewer parameters but may achieve slightly worse WER
  - Computation cost: Per-domain components don't increase computation but require more storage
  - Modularity: MDA allows adding new domains without retraining the backbone

- **Failure signatures**:
  - High deletion/insertion error rates in target domains
  - WER degradation when adding new domains
  - Inconsistency between causal and non-causal encoder performance

- **First 3 experiments**:
  1. Implement per-domain adapters on FFN modules in non-causal encoder and measure WER on target domain
  2. Compare sequential vs parallel adapter configurations with different bottleneck dimensions
  3. Test combination of per-domain components and adapters for optimal parameter efficiency

## Limitations
- The paper doesn't fully address how to determine which components should be made domain-specific versus shared
- MDA's effectiveness on truly unseen domains remains untested
- Computational overhead analysis during inference is lacking

## Confidence
- **High confidence**: The core mechanism of using per-domain adapters in non-causal encoder blocks is well-supported by empirical evidence
- **Medium confidence**: The parameter efficiency claim (22% of backbone) is mathematically sound but may not translate directly to practical deployment scenarios
- **Low confidence**: The claim about achieving "similar performance as the multidomain model" across all domains needs more rigorous statistical validation

## Next Checks
1. Evaluate MDA performance on a held-out domain (e.g., telephony speech or accented speech) that was completely excluded from training
2. Implement and measure actual inference latency and memory access patterns when using domain-specific parameters
3. Systematically vary which components are made domain-specific to identify the minimum viable configuration for each domain type
