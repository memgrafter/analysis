# Adaptive Weight Assignment Scheme For Multi-task Learning

## Quick Facts
- arXiv ID: 2303.07278
- Source URL: https://arxiv.org/abs/2303.07278
- Reference count: 30
- Key outcome: Simple adaptive weight assignment method outperforms uncertainty-based and dynamic weight average methods on CIFAR-100 (3/5 tasks) and AGNews (1/2 tasks)

## Executive Summary
This paper addresses the challenge of assigning appropriate loss weights to different tasks in multi-task learning, where tasks have varying difficulty levels. The authors propose a straightforward adaptive weighting scheme that assigns weights based on the ratio of each task's loss to the total loss across all tasks, scaled by the number of tasks. This approach emphasizes more difficult tasks by giving them proportionally higher weights during training. The method was evaluated on both image (CIFAR-100) and text (AGNews) domains, demonstrating competitive performance against state-of-the-art baseline methods while maintaining computational efficiency.

## Method Summary
The proposed method assigns adaptive weights to each task in multi-task learning based on the relative magnitude of task losses. Specifically, the weight for task i is computed as (L_i / sum(L)) × n, where L_i is the loss for task i, sum(L) is the total loss across all tasks, and n is the number of tasks. This weighting scheme dynamically adjusts during training, recalculating weights each epoch based on current task performance. The method emphasizes more difficult tasks by assigning higher weights to tasks with larger loss values, under the assumption that loss magnitude correlates with task difficulty.

## Key Results
- Outperforms baseline methods in 3 out of 5 tasks on CIFAR-100 dataset
- Achieves best performance in 1 out of 2 tasks on AGNews dataset
- Demonstrates computational efficiency with minimal overhead compared to fastest baseline method
- Effective across both image and text domains with different neural network architectures

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Tasks with larger individual loss values are considered more difficult and receive proportionally higher weights during training.
- Mechanism: The algorithm computes each task's weight as (task loss / total loss) × n, where n is the number of tasks. This scales the relative contribution of each task's loss to the total loss sum.
- Core assumption: Loss magnitude is a valid proxy for task difficulty, and weighting by relative loss improves overall performance.
- Evidence anchors:
  - [abstract] "This approach emphasizes more difficult tasks by assigning higher weights to tasks with larger loss values."
  - [section] "What we do is take the sum of the loss values for each tasks and use it to figure out the ratio of how much a single tasks loss value contributes to the total loss."
  - [corpus] Weak evidence; corpus papers focus on different MTL strategies (federated learning, context switching, etc.) and do not discuss this specific weighting mechanism.
- Break condition: If tasks have inherently different loss scales or if loss magnitude does not correlate with task difficulty, this weighting scheme could misrepresent task importance.

### Mechanism 2
- Claim: Weight updates occur dynamically in each training epoch based on current task performance.
- Mechanism: At each epoch, the algorithm recalculates weights using the latest loss values from all tasks, ensuring that the model adaptively prioritizes tasks that are currently underperforming.
- Core assumption: Dynamic weight adjustment based on epoch-level loss statistics improves convergence and final performance compared to static or pre-defined weights.
- Evidence anchors:
  - [abstract] "This method outperforms the baseline methods in three out of five tasks on CIFAR-100 and achieves the best performance in one task on AGNews."
  - [section] "Our algorithm is based on the simple concept that difficult tasks will have more loss values than the easier ones."
  - [corpus] No direct evidence; corpus papers discuss adaptive methods but focus on task switching, federated learning, and model merging rather than per-epoch weight recomputation.
- Break condition: If task loss values fluctuate significantly between epochs, the weights may become unstable, leading to noisy gradients or oscillatory training behavior.

### Mechanism 3
- Claim: The proposed method achieves computational efficiency by requiring only simple arithmetic operations per epoch.
- Mechanism: The weight computation involves summing losses, calculating ratios, and a single multiplication by the number of tasks—operations that are O(n) and negligible compared to forward/backward passes.
- Core assumption: The overhead of weight calculation is minimal compared to the overall training time, making it practical for large-scale MTL.
- Evidence anchors:
  - [section] "Table 1 provides a chart about the time required to execute these schemes including our method. From the table we can see that though our method is not the fastest method to compute weights but it certainly is not the slowest."
  - [section] "Also, the time difference between the quickest method and our method is very small."
  - [corpus] No evidence; corpus does not compare computational costs of weight assignment methods.
- Break condition: If the number of tasks becomes very large (n >> 10), the per-epoch weight recalculation could contribute non-trivial overhead, especially on hardware with limited compute resources.

- Component map: Data → Backbone → Heads → Per-task loss → Weighting → Total loss → Backpropagation
- Critical path: Data → Backbone → Heads → Per-task loss → Weighting → Total loss → Backpropagation
- Design tradeoffs:
  - Simplicity vs. adaptability: The method is easy to implement but may not capture complex task relationships.
  - Uniform architecture vs. task-specific tuning: All tasks share the same network structure, which may limit performance if tasks have very different requirements.
  - Computational overhead: Minimal compared to training but increases linearly with number of tasks.
- Failure signatures:
  - Degraded performance on some tasks when others dominate the weighted loss.
  - Training instability if task losses have high variance or are poorly scaled.
  - Slower convergence if weights do not align with actual task importance.

## Limitations

- The method assumes loss magnitude is a reliable proxy for task difficulty, which may not hold when tasks have inherently different loss scales or when loss does not correlate with true task importance.
- Experimental validation is restricted to two datasets with artificial task splits, limiting generalizability to real-world multi-task scenarios.
- The computational efficiency claim is based on limited comparison and may not scale well with a large number of tasks.
