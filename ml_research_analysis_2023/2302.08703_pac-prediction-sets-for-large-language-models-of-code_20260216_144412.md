# PAC Prediction Sets for Large Language Models of Code

## Quick Facts
- arXiv ID: 2302.08703
- Source URL: https://arxiv.org/abs/2302.08703
- Authors: 
- Reference count: 12
- Key outcome: Method constructs PAC prediction sets for code generation models by representing them as partial programs with AST-based hole placement

## Executive Summary
This paper addresses the challenge of constructing PAC prediction sets for large language models of code. The key insight is to represent prediction sets as partial programs - programs with certain subtrees replaced by holes. By leveraging the abstract syntax tree structure, the algorithm identifies which subtrees to replace while maintaining PAC guarantees. The approach is evaluated on SQL semantic parsing and Python code completion tasks, showing significant improvements over baseline methods in terms of prediction set compactness while maintaining high coverage rates.

## Method Summary
The algorithm constructs PAC prediction sets for code generation by first parsing the model's top prediction into an AST, then using an integer linear program to generate a monotonic chain of partial programs with varying numbers of holes. This chain satisfies the monotonicity constraint required for PAC guarantees. The algorithm then applies an existing PAC prediction set algorithm to select the optimal threshold, producing a partial program that contains the ground truth with high probability. The optimization minimizes the average number of leaf nodes removed while ensuring probability mass constraints are satisfied.

## Key Results
- The method generates prediction sets containing ground truth with high probability (ε=0.15)
- On SQL task, removes only 45% of nodes versus 55% for baseline
- Significantly outperforms greedy heuristic baseline in prediction set compactness
- Maintains PAC guarantees through monotonic partial program chain construction

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The algorithm achieves PAC guarantees by leveraging monotonicity in the space of partial programs to construct a valid scoring function.
- Mechanism: By restricting prediction sets to partial programs and ensuring that if τ ≤ τ′ then the AST of the prediction set for τ contains the AST of the prediction set for τ′, the algorithm creates a 1D search space that can be handled by existing PAC prediction set methods.
- Core assumption: The space of partial programs forms a chain under the subset relation, which is ensured by the ILP constraints on subtree removal.
- Evidence anchors:
  - [abstract]: "Our approach is to design a modified scoring function f̃ whose level sets have the form {y′ | f̃(x,y′) ≥ τ} = π(y) for some partial program y."
  - [section]: "To achieve this goal, we first note that for a single input x, if our goal is to obtain a prediction set of the form π(y) for some partial program y, we need f̃(x,y′) > τ for all y′ ∈ π(y) and f̃(x,y′) < τ otherwise."
  - [corpus]: Weak evidence - the related papers mention PAC prediction sets and conformal prediction but don't specifically address the monotonicity constraint for partial programs.
- Break condition: If the ILP fails to find a monotonic chain of partial programs, the algorithm cannot construct a valid scoring function and the PAC guarantee is lost.

### Mechanism 2
- Claim: The optimization-based approach for selecting which AST subtrees to replace with holes outperforms greedy heuristics by considering the global structure of the prediction set space.
- Mechanism: The ILP minimizes the total number of leaf nodes removed across all candidate partial programs while satisfying probability mass constraints, ensuring compact prediction sets.
- Core assumption: The negative log probability of remaining leaves in the AST is a good proxy for the quality of the partial program as a prediction set.
- Evidence anchors:
  - [section]: "Overall, our goal is to minimize the leaf nodes removed on average across yi" and the description of constraints (3-8).
  - [section]: "We use this objective to prioritize partial programs" regarding the negative log probability of AST leaves.
  - [corpus]: No direct evidence in the corpus about optimization-based selection for partial programs.
- Break condition: If the probability mass constraint (Eq. 8) cannot be satisfied for any partial program, the optimization fails and the algorithm must fall back to a less optimal solution.

### Mechanism 3
- Claim: Using AST structure to constrain the space of partial programs ensures that the resulting prediction sets are human-interpretable and syntactically valid.
- Mechanism: By only allowing removal of complete AST subtrees (not arbitrary subsequences), the algorithm guarantees that holes are inserted at semantically meaningful locations in the code.
- Core assumption: The AST provided by the user accurately represents the syntactic structure of the programming language and that removing entire subtrees preserves syntactic validity.
- Evidence anchors:
  - [abstract]: "We propose a solution that considers a restricted set of prediction sets that can compactly be represented as partial programs, which are programs with portions replaced with holes."
  - [section]: "Instead, we may want to require the algorithm to either remove only the elements of the array to obtain print([??]); or remove the full array to obtain print(??)."
  - [corpus]: No direct evidence in the corpus about AST-based constraints for prediction sets.
- Break condition: If the AST does not accurately capture the semantic structure of the code (e.g., for languages with complex metaprogramming features), the human-interpretability guarantee may not hold.

## Architecture Onboarding

- Component map:
  Input -> AST Parser -> ILP Solver -> PAC Algorithm -> Output
  (Trained model, validation data) -> (AST generation) -> (Monotonic partial programs) -> (Threshold selection) -> (Partial program)

- Critical path:
  1. Parse AST of model's top prediction
  2. Solve ILP to generate monotonic chain of partial programs
  3. Compute prediction set threshold using existing PAC algorithm
  4. Output partial program corresponding to threshold

- Design tradeoffs:
  - m (max holes): Larger m allows more flexible prediction sets but may reduce interpretability
  - AST granularity: Finer-grained ASTs allow more precise hole placement but increase computational complexity
  - ILP vs. greedy: ILP guarantees optimality but is computationally expensive; greedy is faster but suboptimal

- Failure signatures:
  - ILP infeasible: Check AST parsing and probability mass constraints
  - Coverage below target: Model uncertainty may be underestimated; consider increasing m
  - Excessive node removal: Model predictions may be too uncertain; consider model calibration

- First 3 experiments:
  1. Verify AST parsing produces expected structure for simple code examples
  2. Test ILP with synthetic ASTs to ensure monotonicity constraint is enforced
  3. Validate coverage rate on a small validation set before scaling up

## Limitations

- The algorithm's effectiveness depends heavily on accurate AST representations, which may not capture semantic structure for languages with complex metaprogramming features
- Computational complexity of solving the ILP could become prohibitive for large ASTs or when generating prediction sets for many threshold values
- The paper does not provide runtime analysis or discuss scalability concerns for large-scale applications

## Confidence

- **High Confidence**: The PAC guarantee mechanism (Mechanism 1) is theoretically sound and well-supported by the literature on conformal prediction. The monotonicity constraint is a novel but logical extension to the partial program space.
- **Medium Confidence**: The optimization-based selection (Mechanism 2) shows empirical improvements over greedy heuristics, but the quality of the negative log probability proxy is not rigorously evaluated. The claim that this approach "significantly outperforms" baselines needs more quantitative comparison.
- **Medium Confidence**: The AST-based constraint for human-interpretability (Mechanism 3) is intuitive but lacks empirical validation. The paper does not provide user studies or qualitative assessment of whether the generated partial programs are indeed more interpretable than alternatives.
