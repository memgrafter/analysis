# Domain Incremental Lifelong Learning in an Open World

## Quick Facts
- arXiv ID: 2305.06555
- Source URL: https://arxiv.org/abs/2305.06555
- Reference count: 40
- Outperforms state-of-the-art baselines with 6.15% and 9.49% relative improvements in average performance on seen and unseen tasks

## Executive Summary
This paper proposes Diana, a dynamic architecture-based lifelong learning model that uses hierarchically organized prompts to capture knowledge at different granularities for domain incremental learning in an open world. Diana combines four types of prompts—general, format, task, and meta—shared across different scopes and dynamically combined based on key vectors. It introduces dedicated components to model unseen tasks and optimizes key vectors with regularization terms. Experiments on two task sets show Diana outperforms state-of-the-art baselines in both seen and unseen task handling, achieving relative improvements of 6.15% and 9.49% in average performance over strong baselines. Diana also maintains high task identity detection accuracy and balanced meta prompt key distributions.

## Method Summary
Diana is a dynamic architecture-based lifelong learning model that uses hierarchically organized prompts to capture knowledge at different granularities. It employs four types of prompts (general, format, task, meta) that are dynamically combined based on key vectors. The model introduces dedicated prompts to model unseen tasks and uses a memory buffer with negative sampling to optimize key vectors. During training, scheduled sampling and adaptive decision boundaries are used, while inference relies on distance-based prompt selection. The model is trained on a fixed T5-base backbone with specific hyperparameters including learning rate 1e-4, batch size 64, and various regularization terms.

## Key Results
- Achieves 6.15% relative improvement in average performance on seen tasks compared to strong baselines
- Achieves 9.49% relative improvement in average performance on unseen tasks
- Maintains high task identity detection accuracy while balancing meta prompt key distributions

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Diana uses hierarchically organized prompts to capture knowledge at different granularities.
- Mechanism: Four types of prompts (general, format, task, meta) are organized in a hierarchy where knowledge becomes more localized at lower levels. The general prompt Pg captures global knowledge across all tasks, format prompts Pf capture knowledge shared within task formats, task prompts Pt capture task-specific knowledge, and meta prompts Pm capture instance-level knowledge shared between similar inputs.
- Core assumption: Different scopes of knowledge sharing require different prompt organizations, and a hierarchical structure can effectively capture this multi-granular knowledge.
- Evidence anchors:
  - [abstract] "Four types of hierarchically organized prompts are used in Diana to capture knowledge from different granularities."
  - [section] "These four types of prompts present a hierarchical structure with a decreasing knowledge granularity, i.e., Pg captures global knowledge between all tasks, while Pm captures local knowledge that is shared between instances."
  - [corpus] Weak - only 5 related papers found, none specifically discussing hierarchical prompt organization in lifelong learning.
- Break condition: If the hierarchical organization fails to properly separate knowledge at different granularities, catastrophic forgetting may occur between tasks of different formats or within the same format.

### Mechanism 2
- Claim: Diana uses dynamic prompt combination based on key vectors to facilitate knowledge sharing.
- Mechanism: Each task prompt Pt and meta prompt Pm has an associated key vector. For each input (C,Q), a query vector is computed and the closest key vectors determine which prompts to combine. This creates a dynamic architecture that can share knowledge between similar tasks while maintaining task-specific components.
- Core assumption: Task and instance similarities can be effectively captured in a vector space where distances reflect meaningful relationships between prompts.
- Evidence anchors:
  - [abstract] "We dedicate separate prompts to explicitly model unseen tasks and introduce a set of prompt key vectors to facilitate knowledge sharing between tasks."
  - [section] "We allocate a key vector kt(Ti) and kj m to each task prompt Pt(Ti) and meta prompt Pj m, respectively, and build a fixed text encoder h to map a context-question pair (C,Q) to a query vector q = h(C,Q)."

- Break condition: If the key vector space doesn't properly cluster similar tasks and instances, the wrong prompts may be combined, leading to poor performance or forgetting.

## Architecture Onboarding

- Component map:
  - T5-base encoder-decoder model (fixed backbone)
  - Four prompt types: Pg (general, length 20), Pf (format, length 40), Pt (task, length 40), Pm (meta, length 20)
  - M=30 meta prompts with associated key vectors
  - N task prompts with associated key vectors
  - L extra prompts for unseen tasks
  - Memory buffer M for negative sampling
  - Query vector encoder h (fixed T5-base encoder with average pooling)

- Critical path:
  1. For each input (C,Q), compute query vector q = h(C,Q)
  2. Determine task prompt Pt using either scheduled sampling (training) or distance-based selection (inference)
  3. Select M'=5 closest meta prompt keys and concatenate corresponding meta prompts
  4. Construct full prompt P(C,Q) = [Pg;Pf(Fj);Pt;Pm(C,Q)]
  5. Generate answer A = gθ([P(C,Q);C;Q])

- Design tradeoffs:
  - Fixed vs. trainable backbone: Fixed T5 encoder for query vectors ensures consistent prompt selection, but limits adaptability
  - Number of meta prompts (M=30): More prompts allow finer-grained knowledge sharing but increase computational cost
  - Scheduled sampling probability: Balances exposure bias vs. using correct task IDs during training

- Failure signatures:
  - Poor task identity detection accuracy (<60%) indicates key vectors not properly learned
  - Large performance gap between seen and unseen tasks suggests unseen task prompts ineffective
  - High forgetting scores (>10%) despite dedicated task prompts indicates architectural separation insufficient

- First 3 experiments:
  1. Verify prompt construction works correctly by checking output lengths and content for a simple input
  2. Test key vector learning by visualizing t-SNE plots of query vectors and key vectors for a small task set
  3. Validate task identity detection by measuring accuracy on a held-out validation set before full training

## Limitations

- The paper's claims about hierarchical prompt organization and dynamic knowledge sharing through key vectors rest on several critical assumptions that lack strong empirical validation.
- The evaluation setup uses relatively small task sets (decaNLP and QA), and the paper doesn't address how Diana would scale to hundreds or thousands of tasks.
- The claim of "open world" learning is somewhat constrained since the number of unseen tasks per format is fixed and known during training.

## Confidence

- **High Confidence**: The basic architectural design and implementation details (prompt lengths, training procedure, loss functions) are well-specified and reproducible. The experimental methodology and metric definitions are clear and follow established practices.
- **Medium Confidence**: The performance improvements over baselines are demonstrated, but the magnitude of improvement (6.15% and 9.49%) needs to be interpreted cautiously given the limited task diversity and the specific nature of the datasets.
- **Low Confidence**: The claims about knowledge sharing mechanisms and the effectiveness of hierarchical prompt organization are largely theoretical. The paper provides minimal empirical evidence for why the specific hierarchical structure works better than alternative prompt organizations.

## Next Checks

1. **Ablation Study on Prompt Hierarchy**: Remove the hierarchical structure by using a single prompt type or random prompt combinations, and measure the impact on performance and forgetting. This would directly test whether the hierarchical organization is actually necessary for the claimed benefits.

2. **Key Vector Space Analysis**: Visualize the learned key vector space using t-SNE or UMAP for multiple task sets, and measure whether cosine distance correlates with actual task similarity. Compute nearest neighbor accuracy and check if semantically similar tasks cluster together in the key vector space.

3. **Scalability Experiment**: Test Diana on a larger and more diverse set of tasks (e.g., combining multiple datasets or using a broader task collection) to evaluate how performance scales with the number of tasks and whether the memory buffer and key vector mechanisms remain effective.
