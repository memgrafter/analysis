# Chinese Open Instruction Generalist: A Preliminary Release

## Quick Facts
- arXiv ID: 2304.07987
- Source URL: https://arxiv.org/abs/2304.07987
- Reference count: 10
- Key outcome: 200k Chinese instruction-tuning samples manually verified for high quality across diverse domains

## Executive Summary
The Chinese Open Instruction Generalist (COIG) project presents a comprehensive Chinese instruction dataset for training large language models. The dataset comprises approximately 200k high-quality instruction samples spanning multiple domains including common sense reasoning, code generation, and human value alignment. COIG distinguishes itself through manual quality verification and domain adaptation features. The dataset is publicly available on HuggingFace and GitHub with plans for continuous updates.

## Method Summary
COIG was constructed through a data pipeline involving collection of diverse instruction-tuning samples across multiple domains, followed by manual verification processes to ensure quality. The dataset emphasizes domain adaptation, diversity, and human-verified content to enhance Chinese LLM instruction-following capabilities. While specific construction methodologies are not detailed in the paper, the authors emphasize their empirical approach to dataset curation and quality assurance.

## Key Results
- Dataset contains approximately 200k Chinese instruction-tuning samples
- Manual verification process ensures high data quality
- Covers diverse tasks including common sense reasoning, code generation, and human value alignment

## Why This Works (Mechanism)
The dataset's effectiveness stems from its comprehensive coverage of diverse instruction types combined with rigorous manual quality verification. By focusing on domain adaptation and including tasks like hallucination correction, COIG addresses critical gaps in Chinese LLM instruction capabilities. The manual verification process ensures that each instruction sample meets quality standards, reducing noise in the training data and improving model performance.

Component map: Data Collection -> Manual Verification -> Domain Classification -> Quality Assurance -> Dataset Release

Critical path: The dataset creation follows a linear process from initial collection through multiple verification stages to final release, with manual verification serving as the quality bottleneck.

Design tradeoffs: Prioritized quality over quantity through manual verification, potentially limiting dataset size but ensuring higher reliability compared to fully automated approaches.

Failure signatures: Poor quality instructions would manifest as degraded model performance on downstream tasks, particularly in specialized domains like code generation or hallucination correction.
