# RePAST: Relative Pose Attention Scene Representation Transformer

## Quick Facts
- arXiv ID: 2304.00947
- Source URL: https://arxiv.org/abs/2304.00947
- Reference count: 17
- Primary result: RePAST achieves reference-frame invariance while maintaining comparable or slightly better performance than SRT on novel view synthesis tasks.

## Executive Summary
RePAST (Relative Pose Attention SRT) addresses a fundamental limitation in the Scene Representation Transformer (SRT) by incorporating reference-point invariant relative pose information into the attention mechanism. The method achieves invariance to changes in coordinate systems without compromising quality by using pairwise-relative coordinate systems in both encoder and decoder layers. Experimental results demonstrate that RePAST produces comparable or slightly better results than SRT in terms of PSNR, SSIM, and LPIPS, while gaining the crucial ability to handle large-scale scenes without being tied to a specific global reference frame.

## Method Summary
RePAST modifies the SRT architecture by injecting pairwise relative camera pose information directly into the attention mechanism of transformers. Instead of fixing a reference frame at the input, query and key embeddings are augmented with pose information relative to the key's camera coordinate system. In the decoder, each query ray is represented N times (once per input image) in the coordinate system of each input camera, allowing flexible cross-attention between the query and scene representation. The method uses the MultiShapeNet-Hard dataset for training and evaluation, maintaining the same training procedure as SRT while achieving reference frame invariance.

## Key Results
- RePAST achieves reference-frame invariance while maintaining comparable or slightly better performance than SRT
- The method produces results with similar PSNR, SSIM, and LPIPS scores to SRT on the MultiShapeNet-Hard dataset
- RePAST's design allows handling large-scale scenes where the reference frame would need to be changed regularly

## Why This Works (Mechanism)

### Mechanism 1
- Claim: RePAST achieves invariance to reference camera choice by encoding camera rays in a pairwise-relative coordinate system within the attention mechanism.
- Mechanism: Query and key embeddings are augmented with pose information relative to the key's camera coordinate system, ensuring consistent comparisons regardless of the global reference frame.
- Core assumption: The model's attention mechanism can learn the full 3D geometry from pairwise-relative information alone.
- Evidence anchors:
  - [abstract] "Instead of fixing a reference frame at the input, we inject pairwise relative camera pose information directly into the attention mechanism of the Transformers."
  - [section 2.2] "The key idea behind RePAST is the use of pairwise-relative coordinate systems."

### Mechanism 2
- Claim: Representing each query ray N times in the decoder allows for more flexible and robust cross-attention.
- Mechanism: Each query ray is represented in the coordinate system of each input camera, allowing it to attend to the scene representation from multiple perspectives.
- Core assumption: The decoder's cross-attention mechanism can effectively integrate information from multiple coordinate systems.
- Evidence anchors:
  - [section 2.2] "Unlike the encoder, the decoder operates as a form of cross attention between a query ray and the SLSR."
  - [section 2.2] "In the first decoder block, N local query vectors vi are initialized, one per input image."

### Mechanism 3
- Claim: RePAST's design allows it to handle large-scale scenes where the reference frame would need to be changed regularly.
- Mechanism: By using only pairwise-relative information, RePAST is not tied to a specific global reference frame and can adapt as new input views are added.
- Core assumption: The pairwise-relative information is sufficient to capture the global structure of the scene even as the reference frame changes.
- Evidence anchors:
  - [abstract] "RePAST's ability to handle large-scale scenes and its potential for further applications make it a significant step towards fully latent transformer-based rendering methods."
  - [section 1] "As a result, SRT is not directly applicable to large-scale scenes where the reference frame would need to be changed regularly."

## Architecture Onboarding

- Component map: CNN backbone -> Feature extraction -> Patch tokenization -> Transformer blocks with RePA -> SLSR -> Decoder cross-attention -> MLP -> Novel view rendering

- Critical path:
  1. Posed RGB images are fed into the CNN backbone to extract feature maps.
  2. Feature maps are converted to patch tokens and associated with camera rays.
  3. Patch tokens and camera rays are processed by the Transformer blocks with RePA to produce the SLSR.
  4. SLSR and target view camera rays are fed into the decoder's cross-attention layers.
  5. Decoder outputs are processed by an MLP to produce the final novel view rendering.

- Design tradeoffs: RePAST trades the simplicity of a single global reference frame (used in SRT) for the flexibility and invariance of pairwise-relative coordinate systems, allowing it to handle large-scale scenes but requiring more complex attention mechanisms.

- Failure signatures: If RePAST fails to learn the geometry from pairwise-relative information alone, it may produce blurry or inconsistent novel views. If the model struggles to integrate information from multiple coordinate systems in the decoder, it may exhibit artifacts or inconsistencies in rendered views.

- First 3 experiments:
  1. Implement a minimal RePAST with a single Transformer block and small CNN backbone, training on a simple synthetic dataset and evaluating novel view production from different reference frames.
  2. Compare RePAST with SRT on a medium-scale dataset (ShapeNet) in terms of novel view synthesis quality and invariance to reference frame changes, analyzing attention patterns.
  3. Scale up RePAST and dataset to larger scale using MegaScene subset, evaluating ability to handle more input views and complex scenes, and analyzing impact of pairwise-relative coordinate system.

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions, but based on the methodology and results, several natural questions arise regarding generalization to arbitrary camera configurations, scalability with increasing numbers of input views, and applicability to other transformer-based 3D representation methods.

## Limitations
- The evaluation is limited to a single synthetic dataset with controlled camera configurations, leaving performance on truly large-scale scenes unproven
- Computational overhead from incorporating pairwise relative poses into attention mechanisms increases memory and compute requirements
- The method's behavior and quality degradation with many views or complex scenes remain unknown due to limited testing

## Confidence
- High confidence: The mathematical formulation of relative pose attention and its implementation in encoder/decoder layers is well-specified and theoretically sound.
- Medium confidence: The claim of achieving reference frame invariance is supported by the proposed mechanism but lacks extensive empirical validation across diverse datasets and camera configurations.
- Medium confidence: The assertion that results are "comparable or slightly better" than SRT is supported by reported metrics but could benefit from more extensive ablations and comparisons.

## Next Checks
