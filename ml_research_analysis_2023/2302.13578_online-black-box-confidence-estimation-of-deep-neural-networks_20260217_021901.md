# Online Black-Box Confidence Estimation of Deep Neural Networks

## Quick Facts
- arXiv ID: 2302.13578
- Source URL: https://arxiv.org/abs/2302.13578
- Reference count: 28
- Primary result: NHC is a black-box method for estimating DNN classification reliability using only top-1 labels, performing on par with or better than white-box methods in low-data and out-of-domain scenarios.

## Executive Summary
This paper introduces Neighborhood Confidence (NHC), a black-box method for estimating the reliability of deep neural network (DNN) classifications, especially for autonomous driving systems. NHC measures classification robustness by adding noise perturbations and computing the fraction of perturbed inputs that maintain the original class label, requiring only the top-1 class output. Evaluated on traffic sign recognition, NHC performs on par with or better than gradient-based white-box methods in low-data regimes, across distribution shifts, out-of-domain data, and adversarial attacks. The method is efficient and scalable, meeting real-time constraints needed for ADAS deployment.

## Method Summary
NHC estimates classification reliability by perturbing inputs with noise (e.g., Rademacher) and measuring how often the classifier's top-1 output remains unchanged. The method only requires the classifier's top-1 label, making it suitable for black-box systems like externally supplied ADAS components. NHC's performance depends on the strength λ of perturbations, which controls the range of neighborhood sampling to check for nearby decision boundaries. The method is efficient and scalable, with the number of noise samples N balancing quantization of NHC and latency.

## Key Results
- NHC matches or exceeds white-box methods like Attribution-based Confidence (ABC) in low-data and out-of-domain scenarios.
- Rademacher noise outperforms Gaussian noise for boundary detection in classification.
- NHC's computational efficiency allows real-time deployment in ADAS, with batch processing of perturbed inputs.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: NHC detects proximity to decision boundaries by measuring classification stability under input perturbations.
- Mechanism: By adding noise to an input and measuring how often the classifier returns the same top-1 class, NHC estimates how "deep" inside a decision region the point lies. Deep inside, perturbations don't flip the class; near boundaries, they do.
- Core assumption: Classification outputs are stable in the interior of a decision region and unstable near boundaries, and this behavior is preserved under the types of noise perturbations used.
- Break condition: If the decision boundary is extremely jagged or the classifier is adversarially trained, noise might flip classes even far from the boundary, breaking the stability signal.

### Mechanism 2
- Claim: NHC works as a black-box method because it only requires the top-1 class label, not gradients or internal activations.
- Mechanism: NHC treats the classifier as a pure input-output function, generating noisy inputs, collecting outputs, and computing the stability fraction—no access to internals needed.
- Core assumption: The top-1 class output alone is sufficient to infer the stability of the classifier around the input.
- Break condition: If the classifier internally uses randomness or ensembles that affect top-1 output beyond input perturbations, the stability signal could be confounded.

### Mechanism 3
- Claim: NHC performance improves with optimal perturbation strength λ that balances exploration of nearby decision boundaries without jumping across them.
- Mechanism: Small λ explores the immediate neighborhood; too large λ risks crossing boundaries and losing the stability signal. Optimal λ adapts to the scale of decision regions.
- Core assumption: Decision regions have a characteristic spatial scale that can be probed effectively by tuning λ.
- Break condition: If decision regions are highly irregular or overlapping, a single λ may be insufficient to capture the true boundary structure.

## Architecture Onboarding

- Component map:
  - Input preprocessor -> Noise generator (Rademacher) -> Classifier (black-box) -> Output stability counter -> NHC value

- Critical path:
  1. Generate N perturbed inputs (parallelizable).
  2. Batch classify all N+1 inputs in one forward pass.
  3. Compare outputs to original top-1 class.
  4. Compute fraction stable -> NHC.
  - Bottleneck: Batch size N limited by GPU memory and real-time constraints.

- Design tradeoffs:
  - More noise samples (N) -> finer quantization of NHC but higher latency.
  - Larger λ -> broader boundary detection but risk of crossing boundaries.
  - Rademacher vs Gaussian noise -> impact on detection sensitivity and computational cost.

- Failure signatures:
  - NHC stuck near 0 or 1 regardless of input -> likely λ mismatch or classifier over/under-confidence.
  - High variance in NHC across repeated runs -> classifier nondeterminism or batch effects.
  - NHC drops sharply under adversarial attack -> correct behavior; sharp drops without attack -> over-sensitivity to benign perturbations.

- First 3 experiments:
  1. Run NHC on clean, in-distribution data with varying λ; plot NHC histogram and compare to ground-truth accuracy.
  2. Introduce small synthetic corruptions; measure how NHC changes relative to clean baseline.
  3. Apply PGD attack with increasing ε; record NHC degradation curve and compare to white-box ABC.

## Limitations
- NHC's robustness to classifier architectures beyond CNNs (e.g., transformers, hybrid vision-language models) remains untested.
- The optimal choice of λ across diverse real-world datasets and tasks is not fully characterized.
- Interaction effects between NHC and model ensembling or stochastic inference are unexplored.

## Confidence
- **High confidence**: NHC is effective in black-box mode using only top-1 labels, as shown by consistent performance in traffic sign benchmarks across multiple shift scenarios.
- **Medium confidence**: NHC performance matches or exceeds white-box methods like ABC in low-data settings, but broader architecture and dataset diversity is needed for generalization.
- **Low confidence**: Claims about computational efficiency meeting real-time ADAS constraints are based on a single model (GTSRB with DeepGTSRB); scaling to larger, more complex models is unverified.

## Next Checks
1. **Architecture Generalization Test**: Apply NHC to a non-CNN model (e.g., Swin Transformer) on a standard vision benchmark (ImageNet) and compare confidence estimation accuracy and computational overhead.
2. **Hyperparameter Transferability**: Fix λ to values optimized on GTSRB and evaluate NHC performance on unseen datasets (e.g., CIFAR-10, STL-10) without per-dataset tuning; report degradation in reliability detection.
3. **Real-Time Scalability**: Measure NHC's runtime on a modern, larger model (e.g., ResNet-50 or ConvNext) under batch size constraints typical of embedded ADAS hardware; compare latency to safety thresholds (e.g., 100ms decision cycle).
