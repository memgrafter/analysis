# TwinExplainer: Explaining Predictions of an Automotive Digital Twin

## Executive Summary
This paper addresses the lack of explainability in Digital Twin (DT) systems used for automotive predictive maintenance, which can hinder user trust and decision-making. The authors propose TwinExplainer, a three-layered system that generates both global and local explanations for DT predictions using SHAP (SHapley Additive exPlanations). TwinExplainer processes sensor data from vehicle subsystems (engine, transmission, fuel, brakes), employs a Temporal Convolutional Network (TCN) for anomaly detection, and visualizes feature attributions through bar charts, summary plots, dependence plots, and force plots. The system enables stakeholders to understand which sensor channels most influence normal and abnormal predictions, thereby improving interpretability and supporting maintenance decisions.

## Method Summary
TwinExplainer is a three-layered system that explains automotive Digital Twin predictions through SHAP-based feature attribution. The method involves preprocessing sensor data from engine, transmission, fuel, and brake subsystems, training a Temporal Convolutional Network (TCN) for anomaly detection using sliding window sequences, and applying SHAP to generate feature importance scores. The system produces global explanations (feature importance rankings, summary plots, dependence plots) and local explanations (force plots) to visualize how individual sensor channels contribute to both normal and abnormal predictions. TwinExplainer functions as a post-hoc explainer that receives predictions from the TCN model and generates interpretable visualizations without modifying the underlying model architecture.

## Key Results
- TwinExplainer successfully generates interpretable explanations for both normal and abnormal DT predictions using SHAP values
- The system visualizes feature importance through multiple plot types including bar charts, summary plots, dependence plots, and force plots
- Explanations help automotive stakeholders understand which sensor channels most influence prediction outcomes, supporting maintenance decision-making

## Architecture Onboarding

- Component map:
  Physical Asset (sensor data collection) -> Virtual Asset (data preprocessing + TCN anomaly detection) -> TwinExplainer (SHAP-based explanation generation + visualization)
- Critical path:
  1. Collect and preprocess sensor data
  2. Feed preprocessed data into TCN model for anomaly prediction
  3. Pass predictions to TwinExplainer
  4. Generate and visualize SHAP explanations
- Design tradeoffs:
  - Accuracy vs. interpretability: Adding TwinExplainer does not change prediction accuracy but provides interpretability
  - Real-time vs. batch: Explanations can be generated in real-time or as a batch process after predictions
- Failure signatures:
  - If SHAP values do not align with expected feature importance, the explanation may be misleading
  - If visualizations are not intuitive, stakeholders may misinterpret the explanations
- First 3 experiments:
  1. Validate SHAP values by comparing with known feature importance in synthetic datasets
  2. Test visualization clarity by conducting user studies with automotive stakeholders
  3. Measure the impact of explanations on decision-making by comparing maintenance actions with and without explanations
