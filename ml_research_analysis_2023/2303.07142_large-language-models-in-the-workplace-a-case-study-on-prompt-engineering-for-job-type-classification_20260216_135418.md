# Large Language Models in the Workplace: A Case Study on Prompt Engineering for Job Type Classification

## Quick Facts
- arXiv ID: 2303.07142
- Source URL: https://arxiv.org/abs/2303.07142
- Reference count: 28
- Key result: Zero-shot gpt-3.5-turbo with prompt engineering achieves 86.9% precision at 97% recall for job classification

## Executive Summary
This case study evaluates Large Language Models (LLMs) for job classification in a real-world setting, specifically determining if job postings are suitable for graduates or entry-level positions. The study compares traditional models (SVM), deep learning (DeBERTa), and LLMs (text-davinci-003 and gpt-3.5-turbo) in few-shot and zero-shot settings using prompt engineering techniques. Results show that with proper prompt engineering, a zero-shot gpt-3.5-turbo classifier achieved a 6% increase in Precision@95% Recall compared to the best supervised approach, reaching 86.9% precision and 97% recall. The study highlights that prompt wording and structure significantly impact LLM performance, with minor changes affecting results.

## Method Summary
The study evaluates job posting classification using multiple approaches: traditional machine learning (SVM with tf-idf), deep learning (DeBERTa-V3), and LLMs (text-davinci-003 and gpt-3.5-turbo). The dataset consists of 10,000 manually labeled English-language job postings from the UK, split into 7,000 training and 3,000 test samples. Models are evaluated using Precision@95% Recall (P@95%R) and Precision@85% Recall (P@85%R) metrics. Prompt engineering techniques including Chain-of-Thought reasoning, instruction formatting, and answer templates are systematically tested across zero-shot and few-shot settings.

## Key Results
- Zero-shot gpt-3.5-turbo with optimized prompt engineering achieved 86.9% precision at 97% recall
- Performance represents a 6% improvement over the best supervised approach (DeBERTa)
- Few-shot Chain-of-Thought prompting performed worse than zero-shot, suggesting examples may bias the model's reasoning

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Prompt engineering significantly improves LLM classification performance over traditional and supervised models.
- Mechanism: The LLM leverages its vast pre-training knowledge to perform classification without task-specific fine-tuning, guided by carefully crafted prompts that elicit reasoning and enforce task-specific constraints.
- Core assumption: The LLM's pre-training data contains sufficient implicit knowledge about job posting structures and graduate-level requirements to enable effective zero-shot classification.
- Evidence anchors:
  - [abstract] "with a well-designed prompt, a zero-shot gpt-3.5-turbo classifier outperforms all other models, achieving a 6% increase in Precision@95% Recall compared to the best supervised approach"
  - [section] "our results show that, with a well-designed prompt, a zero-shot gpt-3.5-turbo classifier outperforms all other models"

### Mechanism 2
- Claim: Specific prompt wording and structure elements (CoT, instructions, reinforcement) dramatically affect classification accuracy.
- Mechanism: Prompt modifications guide the LLM's reasoning process, reduce hallucinations, and enforce task constraints, with small changes producing large performance swings.
- Core assumption: The LLM's instruction-following fine-tuning makes it sensitive to prompt phrasing, and its reasoning capabilities can be reliably elicited through structured prompting.
- Evidence anchors:
  - [abstract] "the wording of the prompt is a critical factor in eliciting the appropriate 'reasoning' in the model, and that seemingly minor aspects of the prompt significantly affect the model's performance"
  - [section] "we find that these results highlights just how prompt-sensitive downstream results are"

### Mechanism 3
- Claim: Zero-shot CoT prompting outperforms few-shot prompting for this classification task.
- Mechanism: The LLM's internal knowledge is sufficient for classification, and few-shot examples may bias reasoning away from optimal decision boundaries.
- Core assumption: The classification task relies more on implicit knowledge than learned patterns from examples, and the LLM can generate reliable reasoning chains without examples.
- Evidence anchors:
  - [section] "Interestingly, few-shot CoT prompting the model with examples performs noticeably worse than a zero-shot approach. We speculate that this is due to the examples biasing the model reasoning too much"

  - Data ingestion pipeline: Job postings collection and preprocessing
  - Classification engine: LLM API integration with prompt management
  - Evaluation framework: P@95%R and P@85%R metric calculation
  - Prompt management system: Template storage and modification tracking

- Critical path:
  1. Input job posting → 2. Apply prompt template → 3. LLM API call → 4. Parse response → 5. Calculate metrics → 6. Store results

- Design tradeoffs:
  - Zero-shot vs few-shot: Zero-shot avoids token limits and example bias but may be less reliable for novel tasks
  - Prompt complexity vs performance: More elaborate prompts improve accuracy but increase latency and cost
  - Template rigidity vs flexibility: Strict templates improve consistency but may reduce LLM's ability to handle edge cases

- Failure signatures:
  - Performance degradation: Sudden drops in P@95%R indicating prompt effectiveness decline
  - Template stickiness issues: LLM deviating from expected output format
  - API reliability: LLM service outages or rate limiting affecting throughput

- First 3 experiments:
  1. Baseline zero-shot prompt vs baseline with simple CoT instruction
  2. Instruction inclusion (system vs user message) vs no instructions
  3. Strict answer template vs loose answer template

## Open Questions the Paper Calls Out

### Open Question 1
- Question: What is the precise mechanism by which specific wording in prompts affects LLM performance in job classification tasks?
- Basis in paper: [explicit] The paper notes that "seemingly minor aspects of the prompt significantly affect the model's performance" and observes variations in outcomes based on wording.
- Why unresolved: While the paper shows that wording matters, it does not explain the underlying mechanism or cognitive processes in LLMs that lead to these performance changes.
- What evidence would resolve it: Controlled experiments isolating specific linguistic features (e.g., word choice, syntax, semantics) with systematic variation, combined with interpretability analysis of model attention patterns during prompt processing.

### Open Question 2
- Question: How generalizable are the prompt engineering techniques discovered for this job classification task to other domains and classification problems?
- Basis in paper: [inferred] The study focuses on a specific domain (job classification) and observes prompt sensitivity, but doesn't test transferability to other classification tasks.
- Why unresolved: The paper demonstrates domain-specific prompt effectiveness but doesn't establish whether these techniques would work similarly for other text classification problems.
- What evidence would resolve it: Systematic testing of the discovered prompt engineering techniques across diverse classification tasks (sentiment analysis, topic classification, intent detection) with comparative performance analysis.

### Open Question 3
- Question: What is the optimal balance between providing instructions and allowing the model to use its pre-existing knowledge in few-shot/zero-shot settings?
- Basis in paper: [explicit] The paper shows that few-shot CoT prompting performs worse than zero-shot CoT, suggesting that examples may bias the model too much when it already contains sufficient knowledge.
- Why unresolved: The paper observes this phenomenon but doesn't determine the optimal amount of guidance versus knowledge leverage across different task complexities.
- What evidence would resolve it: Empirical studies varying the amount and type of instruction versus examples across tasks of varying complexity, measuring performance trade-offs and identifying patterns in optimal instruction-to-knowledge ratios.

## Limitations
- Limited generalizability due to evaluation on only UK job postings
- Specific prompt templates and few-shot examples not fully disclosed
- No cost-benefit analysis or production deployment considerations

## Confidence
- High confidence in the core finding that prompt engineering significantly improves LLM performance over traditional models
- Medium confidence in the superiority of zero-shot over few-shot prompting, given limited comparative data
- Medium confidence in the specific prompt elements that drive performance, as minor wording changes show sensitivity but optimal configurations remain unclear
