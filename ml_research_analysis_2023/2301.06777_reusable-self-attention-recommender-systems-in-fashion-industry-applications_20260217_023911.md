# Reusable Self-Attention Recommender Systems in Fashion Industry Applications

## Quick Facts
- arXiv ID: 2301.06777
- Source URL: https://arxiv.org/abs/2301.06777
- Reference count: 15
- One-line primary result: Single Transformer model trained on diverse interactions achieves up to 30% improvement in user retention across fashion recommendation use cases

## Executive Summary
This work presents a Transformer-based recommender system that handles multiple fashion industry use cases through a unified architecture. The system processes diverse interaction types (clicks, purchases, wishlists) with various entities (items, outfits, creators) using session-based modeling with temporal features. Live experiments demonstrate significant improvements in user engagement and retention, outperforming existing approaches like LTR, CNN-based kNN, and Siamese Networks. The architecture is designed for scalability and practical deployment, featuring configurable filtering and re-ranking logic with optimized serving infrastructure.

## Method Summary
The system uses a Transformer encoder-decoder architecture trained on diverse interaction sequences from multiple sources. User interactions are modeled as sessions with temporal features (recency) concatenated to entity embeddings. Outfits are represented as averaged item embeddings, while creators are treated as sets of outfits. The model employs casual language modeling with target boolean masking to train on heterogeneous interactions while predicting specific entity types. The trained model serves multiple use cases including outfit ranking, recommendation, and real-time personalized outfit generation through configurable filtering and re-ranking logic.

## Key Results
- 30% improvement in user retention across different use cases
- Single model outperforms specialized approaches on multiple metrics
- Effective handling of both cold-start and existing users
- Optimized serving infrastructure reduces latency and improves scalability

## Why This Works (Mechanism)

### Mechanism 1
A single Transformer model can effectively serve multiple use cases in fashion recommendation by training on diverse interaction types. The model treats all interaction entities as sequences with heterogeneous features, using masking to focus predictions on specific target types. This allows one model to handle both cold-start and existing users by leveraging session-based modeling with temporal features.

### Mechanism 2
Session-based modeling with temporal features improves recommendation performance by capturing short-term interests. Interactions are grouped into sessions based on time frames, with recency features concatenated to embeddings. This allows the attention mechanism to weigh recent interactions more heavily.

### Mechanism 3
Embedding fashion items in outfits as averaged item features, combined with creator embeddings as outfit sets, enables effective outfit recommendation. Outfits are represented as averaged embeddings of constituent items, while creators are treated as sets of outfits, creating consistent embedding dimensions across entity types.

## Architecture Onboarding

- **Component map**: Input processing → Entity embeddings (averaged items, creator sets) → Temporal feature concatenation → Transformer encoder/decoder → Scoring layer → Configurable filtering/re-ranking → Serving endpoint
- **Critical path**: User interaction sequence → Feature transformation → Model inference → Filtering → Re-ranking → Output recommendations
- **Design tradeoffs**: Single model for multiple use cases vs. specialized models (trade accuracy for simplicity and scalability); in-memory entity data vs. external database calls (trade memory for latency)
- **Failure signatures**: High latency from external entity lookups; poor cold-start performance from insufficient non-outfit interactions; feedback loops from training on same carousel data
- **First 3 experiments**:
  1. Test baseline Transformer on outfit-only interactions vs. diverse interaction types to verify multi-entity training benefit
  2. Compare session-based modeling with temporal features against sequential modeling without sessions
  3. Validate outfit averaging representation by testing against alternative outfit encoding methods

## Limitations

- Missing architectural details (layer count, attention heads, embedding dimensions) prevent precise reproduction
- Averaging approach for outfit representations may lose critical compatibility information
- Potential feedback loops from training on the same carousel data used for recommendations
- No quantitative comparison of serving infrastructure performance gains against baselines
