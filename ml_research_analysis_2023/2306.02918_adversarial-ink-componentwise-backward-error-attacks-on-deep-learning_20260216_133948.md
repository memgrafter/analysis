# Adversarial Ink: Componentwise Backward Error Attacks on Deep Learning

## Quick Facts
- arXiv ID: 2306.02918
- Source URL: https://arxiv.org/abs/2306.02918
- Reference count: 40
- Primary result: Componentwise adversarial attacks preserve image backgrounds while perturbing ink content, creating natural-looking perturbations that successfully fool classifiers.

## Executive Summary
This paper introduces "adversarial ink" attacks that use componentwise relative perturbations to preserve background content while modifying only the ink levels in images. The approach builds on backward error analysis and extends normwise attack algorithms to the componentwise setting. Experiments on MNIST demonstrate that these attacks produce visually natural perturbations that mimic inconsistent handwriting pressure or blotchy pen strokes while successfully changing classifier outputs. The componentwise condition number is proposed as a measure of vulnerability to such attacks.

## Method Summary
The method extends existing normwise adversarial attack algorithms (Beuzeville et al., 2021) to the componentwise setting by allowing each pixel to be perturbed by a small percentage of its original value. The tolerance vector f is set equal to the original image x, which preserves zero-valued background pixels while allowing non-zero ink pixels to be perturbed. Four algorithms are developed: two normwise (Algorithms 1-2) and two componentwise (Algorithms 3-4), with the componentwise versions minimizing either infinity-norm or 2-norm of the perturbations. The attacks are tested on MNIST using three neural network architectures and compared against DeepFool and PGD baselines.

## Key Results
- Componentwise untargeted attacks achieve smaller ∞-norm perturbations (0.0077) than normwise attacks (0.0090)
- Componentwise perturbations preserve background pixels while creating natural-looking variations in ink consistency
- The componentwise condition number μ∞ provides theoretical insight but shows weaker correlation with actual attack success for larger perturbations
- Black-box attacks using finite differences maintain effectiveness despite increased computational cost

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Componentwise perturbations preserve background while perturbing ink content, creating "adversarial ink" that appears natural to humans.
- Mechanism: By setting the tolerance vector f equal to the original image values (f = x), zero-valued background pixels remain fixed at zero while non-zero ink pixels can be perturbed by a small relative amount. This creates variations in ink consistency that mimic natural writing imperfections.
- Core assumption: Zero-valued background pixels correspond to areas that should remain unchanged, and small relative perturbations to non-zero pixels are visually imperceptible as adversarial manipulation.
- Evidence anchors: Abstract and section statements about preserving background while perturbing ink levels.
- Break condition: If background pixels have non-zero values (e.g., greyscale images with non-black backgrounds), this mechanism would no longer preserve the background as intended.

### Mechanism 2
- Claim: The componentwise condition number (μ∞) indicates vulnerability to adversarial ink attacks.
- Mechanism: The condition number measures the worst-case sensitivity of output changes to input perturbations. For componentwise perturbations, μ∞ ≈ ∥|A|f∥∞/∥F(x)∥∞ where f is the tolerance vector, providing a measure of how easily small relative changes to the input can alter classification.
- Core assumption: The relationship between forward error and backward error holds approximately in the linearized regime, allowing condition numbers to predict attack success.
- Evidence anchors: Abstract and section statements about using componentwise condition number to quantify vulnerability.
- Break condition: When perturbations are large enough that the linear approximation breaks down, the condition number becomes a poor predictor of actual attack success.

### Mechanism 3
- Claim: Iterative algorithms with infinity-norm optimization (Algorithm 3) produce larger but more noticeable perturbations than 2-norm optimization (Algorithm 4).
- Mechanism: Algorithm 3 minimizes ∥v∥∞ which encourages all components of v to reach the maximum value, creating large uniform changes across many pixels. Algorithm 4 minimizes ∥Dv∥2 which distributes changes more evenly, producing less visually obvious perturbations.
- Core assumption: Infinity-norm minimization creates uniform changes across all perturbed components, while 2-norm minimization creates more distributed changes.
- Evidence anchors: Section statements comparing visual appearance of infinity-norm vs 2-norm perturbations.
- Break condition: When the tolerance vector f has many zeros (sparse), both algorithms may produce similar results since only a subset of pixels are perturbable.

## Foundational Learning

- Concept: Backward error analysis
  - Why needed here: The attack algorithms are formulated as finding the smallest perturbation to the input that achieves a desired output change, which is the definition of backward error.
  - Quick check question: In backward error analysis, are we measuring the error in the input or the output of a computation?

- Concept: Condition numbers
  - Why needed here: Condition numbers provide a theoretical framework for understanding when small input changes can cause large output changes, which is essential for adversarial attack vulnerability.
  - Quick check question: What does a high condition number indicate about a system's sensitivity to perturbations?

- Concept: Componentwise vs normwise perturbations
  - Why needed here: The paper contrasts componentwise relative perturbations (which preserve the background) with normwise perturbations (which affect all pixels equally), making this distinction fundamental to understanding the approach.
  - Quick check question: How does a componentwise perturbation differ from a normwise perturbation in terms of which pixels are affected?

## Architecture Onboarding

- Component map:
  Image preprocessing -> Neural network -> Jacobian computation -> Optimization -> Attack algorithms -> Evaluation

- Critical path:
  1. Load image and compute network output
  2. Compute Jacobian at current image
  3. Formulate constrained optimization problem based on attack algorithm
  4. Solve optimization to get perturbation direction
  5. Scale perturbation to achieve target classification
  6. Evaluate success and measure perturbation size

- Design tradeoffs:
  - Exact Jacobian vs finite differences: Exact is faster and more accurate but requires white-box access; finite differences works in black-box but is slower
  - Infinity-norm vs 2-norm optimization: Infinity-norm creates more uniform but noticeable changes; 2-norm creates less noticeable but potentially larger norm perturbations
  - Componentwise vs normwise: Componentwise preserves background but may be less effective; normwise affects all pixels but doesn't preserve background

- Failure signatures:
  - Attack fails to change classification: Check if Jacobian is singular or if perturbation is being overly constrained by pixel bounds
  - Background is being perturbed in componentwise attack: Verify tolerance vector f is correctly set to original image values
  - Perturbations are too large: Reduce step size α or number of iterations
  - Condition number predictions don't match actual attack success: Likely because perturbations exceed linear regime

- First 3 experiments:
  1. Test Algorithm 2 on a simple 2-layer network with a single MNIST image, targeting a different class, verify background is perturbed
  2. Test Algorithm 4 on the same setup, verify background remains unchanged and perturbation appears natural
  3. Compare condition number μ∞ with actual perturbation size for 10 random images to validate correlation

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How effective are componentwise adversarial ink attacks on signatures, postcodes, dates, cheques, or entire documents compared to standard normwise attacks?
- Basis in paper: The authors suggest this as a direction for future work, noting that such attacks are "highly relevant in the case of handwritten documents or printed texts where, for example, the classification of signatures, postcodes, dates or numerical quantities may be altered by changing only the ink consistency and not the background."
- Why unresolved: The paper only tests on the MNIST dataset of handwritten digits, which is a simplified case compared to real-world documents with varying backgrounds, textures, and ink patterns.
- What evidence would resolve it: Experiments comparing componentwise attacks to normwise attacks on real-world document images (signatures, cheques, forms, etc.) showing relative perturbation sizes, attack success rates, and visual quality of the perturbations.

### Open Question 2
- Question: Can universal componentwise adversarial ink attacks be constructed that affect multiple images with shared non-background locations?
- Basis in paper: The authors propose investigating "the construction of universal componentwise attacks, where the same perturbation changes the classification of many images that have shared 'non-background' locations."
- Why unresolved: The paper only considers targeted attacks on individual images, not universal attacks that would work across multiple images.
- What evidence would resolve it: Development and testing of a perturbation that, when applied to multiple images with similar ink/non-background patterns, consistently changes their classifications in the desired manner.

### Open Question 3
- Question: How can object recognition be used to automatically identify background pixels to enable automated componentwise tolerance vector selection in complex images?
- Basis in paper: The authors suggest "the use of object recognition to identify background pixels so that the choice of componentwise tolerance vector can be automated in complex images."
- Why unresolved: The paper manually sets the tolerance vector f = x for MNIST images with simple black backgrounds, but this approach would not work for complex images with varied backgrounds.
- What evidence would resolve it: An algorithm that uses object recognition to segment foreground ink from background, then applies componentwise attacks only to the foreground pixels while preserving the background.

## Limitations
- The approach is primarily validated on MNIST, a simplified dataset that may not generalize to complex real-world documents
- The condition number's predictive power diminishes for larger perturbations where linear approximations break down
- Visual assessment of perturbation naturalness is qualitative rather than rigorously quantified
