# Silver Syntax Pre-training for Cross-Domain Relation Extraction

## Quick Facts
- arXiv ID: 2305.11016
- Source URL: https://arxiv.org/abs/2305.11016
- Reference count: 21
- Key outcome: Silver syntax pre-training improves cross-domain RE performance by 0.71 Macro-F1 on average across 5 of 6 domains without additional annotated data.

## Executive Summary
This paper introduces a cost-effective method for cross-domain relation extraction that uses automatically parsed syntactic dependencies as silver training data. Rather than requiring additional manually annotated RE data, the approach leverages the structural affinity between syntactic dependencies and semantic relations by pre-training on dependency labels frequently found on shortest paths between entities. Using silver syntax data from unlabeled corpora, the method achieves consistent improvements across five domains while maintaining efficiency, demonstrating that syntactic structure can effectively support RE across domains.

## Method Summary
The method uses a two-phase training approach: first, pre-training on silver syntax data generated by automatically parsing unlabeled corpora, then fine-tuning on target RE datasets. The syntactic parser (MaChAmp with XLM-R large) generates dependency trees, from which instances containing only five UD labels (nsubj, obj, obl, nmod, appos) on shortest paths between entities are extracted and converted into RE-formatted training instances. The RE model architecture consists of a BERT-base-cased encoder with entity markers and a single-layer feed-forward classification head. The pre-training phase uses 8.4K-20.4K silver instances before fine-tuning on each of six CrossRE domains separately.

## Key Results
- The syntax pre-training approach outperforms the baseline in five out of six cross-domain settings on the CrossRE dataset
- Average Macro-F1 improvement of 0.71 compared to the baseline model
- Performance gains are consistent across multiple pre-training data quantities (8.4K-20.4K instances)
- The method achieves these improvements without requiring any additional manually annotated RE data

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Syntactic dependencies on shortest paths between entities capture semantic relation structure effectively.
- Mechanism: Pre-training on dependency labels (nsubj, obj, obl, nmod, appos) that frequently appear on shortest dependency paths teaches the model structural patterns that transfer to semantic relation extraction.
- Core assumption: High affinity exists between syntactic dependency structure and semantic relation structure, making path dependencies semantically informative.
- Evidence anchors: [abstract] identifies syntactic relations on shortest paths as closely related to RE; [section] observes high frequency of specific UD labels on shortest paths.
- Break condition: If parser accuracy drops significantly or semantic relation patterns differ substantially from syntactic patterns in target domains.

### Mechanism 2
- Claim: Silver syntax data from automatically parsed corpora provides sufficient quality for effective pre-training.
- Mechanism: High-accuracy syntactic parsers generate large-scale dependency-annotated data enabling cost-effective pre-training that improves cross-domain RE performance.
- Core assumption: Current syntactic parsers have sufficiently high accuracy that their output serves as reliable training signals for RE models.
- Evidence anchors: [abstract] and [section] both state exploitation of high accuracy of current syntax parsers for obtaining low-cost pre-training data.
- Break condition: If parser accuracy falls below threshold where silver data introduces too much noise, degrading RE performance.

### Mechanism 3
- Claim: Intermediate pre-training on syntactic relations bridges the gap between general language model pre-training and domain-specific RE fine-tuning.
- Mechanism: Inserting syntax pre-training between BERT pre-training and RE fine-tuning enables the model to learn domain-agnostic structural patterns that transfer across domains.
- Core assumption: Intermediate task training provides benefits across domains even when the intermediate task (syntax) differs from the target task (RE).
- Evidence anchors: [abstract] notes intermediate training on related tasks is beneficial across NLP tasks; [section] investigates dependency information as efficient silver data in intermediate training.
- Break condition: If syntactic patterns learned don't generalize across domains, or if intermediate task creates interference rather than helpful inductive bias.

## Architecture Onboarding

- Component map: Unlabeled corpus -> Syntactic parser (MaChAmp + XLM-R) -> Filter UD labels (nsubj, obj, obl, nmod, appos) on shortest paths -> Convert to RE instances -> Pre-train RE model -> Fine-tune on CrossRE domains -> Evaluate cross-domain performance

- Critical path: The critical path is: parse unlabeled corpus → filter relevant UD labels → convert to RE instances → pre-train RE model → fine-tune on target RE dataset → evaluate cross-domain performance. Each step must complete successfully for the method to work.

- Design tradeoffs: The method trades off between data quantity and quality (using silver vs gold syntax), between generality and specificity (five UD labels vs more comprehensive sets), and between computational cost and performance gains (pre-training data quantity optimization).

- Failure signatures: Poor performance indicates either parser accuracy issues (silver data too noisy), wrong UD label selection (missing relevant syntactic patterns), insufficient pre-training data quantity, or domain mismatch between syntax patterns and semantic relations.

- First 3 experiments:
  1. Verify syntactic parser accuracy on a sample of the unlabeled corpus to ensure silver data quality.
  2. Analyze shortest dependency path UD label distribution on a small sample of CrossRE to confirm label selection.
  3. Test pre-training with varying amounts of syntactic instances (e.g., 5K, 10K, 15K) on the dev set to find optimal quantity before full training.

## Open Questions the Paper Calls Out

- Question: What is the optimal quantity of syntactic dependencies to pre-train on for maximizing cross-domain relation extraction performance?
- Basis in paper: The paper discusses pre-training data quantity analysis and mentions that performance stabilizes above the baseline starting from 8.4K instances onward, with a selected peak at 20.4K instances.
- Why unresolved: The paper breaks inspection of optimal pre-training data amount at 24K instances due to computational cost constraints, and mentions that more pre-training instances might be even more beneficial.
- What evidence would resolve it: Systematic experiments varying the amount of pre-training data beyond 24K instances and measuring the impact on cross-domain relation extraction performance would provide a definitive answer.

- Question: How would the inclusion of additional UD labels such as acl and compound affect the performance of the syntax pre-training approach for relation extraction?
- Basis in paper: The paper mentions that while they test their approach over one set of UD labels, different sets could be investigated, including acl and compound, which present a considerable amount of instances.
- Why unresolved: The paper does not explore the impact of including additional UD labels beyond the initial set of nsubj, obj, obl, nmod, and appos.
- What evidence would resolve it: Conducting experiments with expanded sets of UD labels and comparing the performance of relation extraction across domains would clarify the potential benefits of including additional labels.

- Question: How does the proposed syntax pre-training approach perform on end-to-end relation extraction tasks, where gold entities are not assumed?
- Basis in paper: The paper acknowledges that while assuming gold entities is common in relation extraction research, the inspection of the proposed method over end-to-end relation extraction is left for future work.
- Why unresolved: The current study focuses on relation extraction with assumed gold entities, leaving the performance on end-to-end tasks unexplored.
- What evidence would resolve it: Applying the syntax pre-training approach to end-to-end relation extraction tasks and evaluating its effectiveness in identifying both entities and relations would provide insights into its broader applicability.

## Limitations

- Performance improvements are modest (0.71 average Macro-F1) and not consistent across all domains, with one domain showing no improvement.
- The quality of silver syntax data depends entirely on parser accuracy, which is not explicitly measured or validated in the study.
- The method assumes syntactic patterns generalize across domains, but this transfer may break down for domains with substantially different linguistic characteristics.

## Confidence

- **High Confidence**: The syntactic affinity hypothesis - that dependencies on shortest paths between entities are semantically informative - is well-supported by linguistic theory and empirical observation.
- **Medium Confidence**: The silver syntax pre-training approach works because parser accuracy is sufficiently high - while parsers are known to be accurate, the specific impact on downstream RE performance through silver data is not directly measured.
- **Medium Confidence**: The performance improvements are real but domain-dependent - the 0.71 average improvement is statistically meaningful, but the lack of improvement on one domain suggests limitations in cross-domain generalization.

## Next Checks

1. **Parser Quality Assessment**: Measure the accuracy of the syntactic parser on a held-out sample of sentences from the unlabeled corpus to quantify silver data quality and establish correlation between parser accuracy and RE performance gains.

2. **Label Coverage Analysis**: Analyze whether the five selected UD labels capture the majority of semantically relevant syntactic patterns across all six domains, particularly focusing on the Wiki domain where the method failed to improve performance.

3. **Data Quantity Optimization**: Systematically vary the amount of pre-training data (below and above the 8.4K-20.4K range) on the development set to determine the optimal quantity that maximizes cross-domain RE performance while minimizing computational cost.
