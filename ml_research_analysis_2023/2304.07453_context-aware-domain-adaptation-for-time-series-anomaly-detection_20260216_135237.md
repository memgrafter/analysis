# Context-aware Domain Adaptation for Time Series Anomaly Detection

## Quick Facts
- arXiv ID: 2304.07453
- Source URL: https://arxiv.org/abs/2304.07453
- Reference count: 40
- Outperforms state-of-the-art domain adaptation methods, achieving 63% vs 56% Macro-F1 on SMD dataset

## Executive Summary
This paper addresses the challenge of transferring knowledge between time series domains for anomaly detection. Traditional domain adaptation methods often struggle with negative transfer when domains have different temporal characteristics. The proposed ContexTDA framework solves this by adaptively sampling context window sizes for both source and target domains using deep reinforcement learning. By formulating context sampling as a Markov Decision Process and combining it with anomaly detection in a joint learning procedure, the method achieves superior performance on three public datasets.

## Method Summary
ContexTDA combines context sampling and anomaly detection into a joint learning framework. The method formulates context window selection as a Markov Decision Process, where a Deep Q-learning agent selects window sizes for both source and target domains. The framework uses an LSTM autoencoder with an encoder, decoder, classifier, and domain discriminator. A tailored reward function combines classification loss, reconstruction loss, and domain alignment/discrimination losses to guide the DQN agent. This allows the system to learn domain-invariant features while adapting to optimal temporal contexts for each domain.

## Key Results
- Achieves 63% Macro-F1 score on SMD dataset compared to 56% for previous best method
- Shows consistent improvement across three public datasets (SMD, Boiler, SMAP, MSL)
- Demonstrates effectiveness of adaptive context sampling over fixed window sizes

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Aligning context window sizes between source and target domains improves anomaly detection performance.
- Mechanism: The method samples different context window sizes for each domain using a Markov Decision Process, allowing it to capture the optimal temporal dependencies for each domain separately.
- Core assumption: Anomalies in different domains require different context window sizes to be properly detected.
- Evidence anchors:
  - [abstract]: "we aim to transfer knowledge between two domains via adaptively sampling context information for two domains"
  - [section]: "Figure 2 illustrates the preliminary experiment that reports the detected ratio of 20 outliers with different context alignment settings for 20 runs"
  - [corpus]: Weak - no corpus evidence for this specific claim
- Break condition: If anomalies in both domains have identical temporal patterns and optimal context window size, adaptive sampling would provide no benefit over fixed window size.

### Mechanism 2
- Claim: Combining context sampling with domain adaptation through reinforcement learning improves knowledge transfer.
- Mechanism: The framework uses Deep Q-learning to optimize context window selection while simultaneously training anomaly detection and domain adaptation objectives.
- Core assumption: The reward function can effectively guide the context sampler to select window sizes that improve anomaly detection.
- Evidence anchors:
  - [abstract]: "We formulate context sampling into the Markov decision process and exploit deep reinforcement learning to optimize the time series domain adaptation process"
  - [section]: "We define the reward rt at timestep t as a combinatorial signal of source domain classification loss, source and target domain reconstruction loss, domain alignment and discrimination loss"
  - [corpus]: Weak - no corpus evidence for this specific mechanism
- Break condition: If the reward function doesn't correlate with actual anomaly detection performance, the RL agent won't learn useful context sampling policies.

### Mechanism 3
- Claim: Personalized contextual information for individual time points enables better anomaly detection than global alignment methods.
- Mechanism: Instead of using fixed context windows for all time points, the method samples context windows individually based on learned policies.
- Core assumption: Different time points require different amounts of context to properly detect anomalies.
- Evidence anchors:
  - [section]: "we observe that setting target domain windows at 6 and 8 leads to generally better performance than making them the same as the source domain"
  - [section]: "anomalies 1 and 6 can always be detected when the window size is 6, whereas anomalies 2 and 7 can be better detected when the window size is set to 8"
  - [corpus]: Weak - no corpus evidence for this specific mechanism
- Break condition: If all time points in both domains benefit from the same context window size, the added complexity of adaptive sampling would be unnecessary.

## Foundational Learning

- Concept: Markov Decision Process
  - Why needed here: The context sampling problem is framed as an MDP where states are feature vectors, actions are window sizes, and rewards are anomaly detection performance.
  - Quick check question: In an MDP, what determines the next state and reward given a current state and action?

- Concept: Deep Q-learning
  - Why needed here: Used to solve the MDP by approximating the Q-function that maps state-action pairs to expected rewards.
  - Quick check question: What are the two key techniques introduced by DQN to stabilize training?

- Concept: Domain adaptation objectives
  - Why needed here: The reward function combines classification loss, reconstruction loss, and domain alignment/discrimination losses to guide context sampling.
  - Quick check question: What is the purpose of including both domain alignment and domain discrimination losses in the reward function?

## Architecture Onboarding

- Component map:
  Context Sampler (DQN) -> State Generator -> Anomaly Detector (LSTM autoencoder) -> Reward Calculator -> Context Sampler

- Critical path:
  1. Sample window sizes → 2. Generate feature vectors → 3. Compute losses → 4. Calculate reward → 5. Update DQN → 6. Update anomaly detector

- Design tradeoffs:
  - Fixed vs adaptive window sizes: Adaptive provides flexibility but adds complexity
  - Reward function composition: Balancing different objectives affects learning stability
  - State representation: Using concatenated feature vectors vs separate representations

- Failure signatures:
  - DQN not converging: Check reward signal scaling and epsilon decay
  - Poor anomaly detection: Verify window size ranges and state feature quality
  - Negative transfer: Ensure proper weighting of domain adaptation losses

- First 3 experiments:
  1. Run with random context sampling (RandContexTDA) to establish baseline performance
  2. Test with single fixed window size to determine if adaptive sampling provides benefit
  3. Evaluate different reward function weightings to find optimal balance for the specific dataset

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does ContexTDA's performance vary with different maximum context window sizes?
- Basis in paper: [explicit] The paper mentions using a maximum context window size K but doesn't provide systematic ablation studies on its impact.
- Why unresolved: The paper only mentions that "For fixed window sized baseline...we empirically select context window size as 30 for SMD dataset, 10 for Boiler dataset and 40 for MSL and SMAP datasets" but doesn't explore how different maximum window sizes affect performance.
- What evidence would resolve it: Experiments showing ContexTDA's performance across a range of maximum context window sizes (e.g., 10, 20, 30, 40, 50) for each dataset.

### Open Question 2
- Question: Can ContexTDA handle more than two domains simultaneously?
- Basis in paper: [inferred] The paper focuses on transferring knowledge between two domains but mentions that "recent efforts have been devoted to time series domain adaptation to leverage knowledge from similar domains" (plural), suggesting potential for multi-domain scenarios.
- Why unresolved: The methodology and experiments are all designed for two-domain adaptation, with no exploration of multi-domain scenarios.
- What evidence would resolve it: Experiments showing ContexTDA's performance when simultaneously adapting from multiple source domains to a single target domain.

### Open Question 3
- Question: How does the proposed reward function compare to alternative formulations?
- Basis in paper: [explicit] The paper designs a specific reward function (Eq. 3.5) but mentions that "each objective plays a unique role during the training process and may affect the performance for each setting differently."
- Why unresolved: The ablation study only removes individual components of the reward function but doesn't compare against fundamentally different reward formulations.
- What evidence would resolve it: Experiments comparing ContexTDA with alternative reward functions, such as those based on different combinations of losses or different weighting schemes.

## Limitations
- Computational overhead from running DQN alongside anomaly detector may limit scalability
- Performance depends on similarity between source and target domains - may degrade with dissimilar temporal patterns
- Requires careful hyperparameter tuning, particularly for reward function coefficients

## Confidence

**High confidence**: The experimental results showing improved Macro-F1 scores over baseline methods are well-supported by the presented data.

**Medium confidence**: The mechanism by which adaptive context sampling improves anomaly detection is theoretically sound but lacks extensive ablation studies to isolate its contribution.

**Low confidence**: The claim that this approach generalizes well to arbitrary domain pairs without additional domain-specific tuning remains unproven.

## Next Checks
