# Path to Medical AGI: Unify Domain-specific Medical LLMs with the Lowest Cost

## Quick Facts
- arXiv ID: 2306.10765
- Source URL: https://arxiv.org/abs/2306.10765
- Reference count: 40
- One-line primary result: Proposes MedAGI, a paradigm to unify domain-specific medical LLMs with lowest cost through adaptive expert selection, achieving exceptional performance across dermatology, X-ray, and pathology domains.

## Executive Summary
This paper introduces Medical AGI (MedAGI), a novel paradigm designed to unify domain-specific medical large language models (LLMs) with minimal cost and maximum scalability. MedAGI automatically selects the most appropriate expert model for a given medical query by analyzing the user's question with an adaptive expert selection algorithm. By leveraging lightweight expert alignment layers instead of full model fine-tuning, MedAGI offers a cost-effective and future-proof solution that can easily integrate new models without retraining. The system was evaluated across three medical domains—dermatology, X-ray diagnosis, and pathology—demonstrating remarkable versatility and scalability.

## Method Summary
MedAGI is built on a vision encoder (ViT), Q-Transformer, and an adaptive expert selection algorithm. When a user uploads an image and asks a question, the system encodes the question and model descriptions using a BERT encoder, then computes cosine similarity to select the most suitable domain-specific model. Instead of fine-tuning entire models, MedAGI uses lightweight expert alignment layers for each domain, keeping the base vision encoder and LLM frozen. This approach enables cost-effective scalability and easy integration of new models. The system was evaluated using datasets from dermatology, X-ray, and pathology domains, with performance measured across these diverse medical specialties.

## Key Results
- MedAGI achieved exceptional performance across three distinct medical domains: dermatology diagnosis, X-ray diagnosis, and pathology picture analysis.
- The system demonstrated remarkable versatility and scalability, successfully handling cross-domain queries that individual models could not address.
- By using lightweight expert alignment layers instead of full model fine-tuning, MedAGI offers a cost-effective and future-proof solution for integrating new medical models.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The system achieves domain-generic performance by automatically selecting the most suitable expert alignment layer for a given user query.
- Mechanism: When a user uploads an image and asks a question, the system first encodes the question and the descriptions of available domain-specific models using a BERT encoder. It then computes cosine similarity between the question embedding and each model description embedding. The model with the highest similarity score is selected to process the image.
- Core assumption: The textual description of a domain-specific model's capabilities accurately captures the types of queries it can handle best, and cosine similarity in the BERT embedding space is a reliable proxy for task-model alignment.
- Evidence anchors:
  - [abstract] "MedAGI is designed to automatically select appropriate medical models by analyzing users’ questions with our novel adaptive expert selection algorithm."
  - [section] "Our expert alignment layer selection considers both the user question and different model instructions. ... The model that obtains the highest s score will be selected as the answering model."
  - [corpus] Found related work (BLADE, OpenAGI) that also explores selecting or combining domain-specific models with LLMs, supporting the general idea that such selection mechanisms are being actively researched.
- Break condition: If the model descriptions are vague, incomplete, or do not capture the nuances of the types of queries each model handles, the selection may become inaccurate. Also, if the BERT encoder does not produce meaningful embeddings for this task, similarity scores will be unreliable.

### Mechanism 2
- Claim: The use of lightweight expert alignment layers instead of full model fine-tuning enables cost-effective scalability.
- Mechanism: Instead of retraining entire multimodal models for new domains, the system keeps the base vision encoder and LLM frozen and only fine-tunes a small adapter (alignment layer) for each new domain. These adapters are then selected at inference time based on the query.
- Core assumption: A small number of parameters in the alignment layer is sufficient to adapt the frozen backbone to a new domain's task, and storing/loading these adapters is much cheaper than storing/loading full models.
- Evidence anchors:
  - [abstract] "It offers a unified approach to existing LLMs in the medical field, eliminating the need for retraining regardless of the introduction of new models."
  - [section] "This method, as employed in models such as SkinGPT-4 [40], ProteinChat [41], XrayGPT [42] and XrayChat [43], is more feasible due to the requirement of fewer instances to fine-tune fewer parameters."
  - [corpus] The paper explicitly contrasts this adapter-based approach with end-to-end training of large multimodal models, noting that the latter requires diverse data across domains which is hard to obtain in medicine.
- Break condition: If the domain gap is too large, a small adapter may not capture the necessary adaptation, leading to poor performance. Also, if many domains are added, the number of adapters could grow large, potentially offsetting storage benefits.

### Mechanism 3
- Claim: By integrating multiple specialized models, the system can handle cross-domain queries that individual models cannot.
- Mechanism: Since the system can select among models trained on different domains (dermatology, X-ray, pathology), it can route a query to the most appropriate one even if the user does not explicitly specify the domain. This allows it to answer questions that span multiple domains or are ambiguous.
- Core assumption: The query contains enough information for the selection algorithm to correctly identify the most relevant domain-specific model, and each model's capabilities overlap sufficiently to cover realistic cross-domain queries.
- Evidence anchors:
  - [section] "In contrast, MedAGI proved capable of providing accurate and appropriate answers to user queries, even in cross-domain situations."
  - [section] "MedAGI offers a unified interface that eliminates the need for users to worry about the specific domain to which a particular task belongs."
  - [corpus] Related work (BLADE) also focuses on enhancing black-box LLMs with small domain-specific models, suggesting this is a recognized strategy for cross-domain handling.
- Break condition: If a query is genuinely cross-domain in a way that no single model is well-suited for (e.g., combining dermatology and X-ray insights), the system may still fail. Also, if the selection algorithm misclassifies the intent, the wrong model will be used.

## Architecture Onboarding

- Component map:
  - Input: User-uploaded image + text question
  - ViT encoder: Splits image into patches, extracts visual features
  - Q-Transformer: Generates image embedding using transformer architecture
  - BERT encoder: Encodes user question and model descriptions
  - Similarity module: Computes cosine similarity between question and model descriptions
  - Expert alignment layer selector: Picks the model with highest similarity
  - Selected expert alignment layer: Aligns visual embedding with question
  - LLM: Generates final text-based diagnosis/answer
  - Output: Text response to user

- Critical path:
  1. Image → ViT patches → visual features
  2. Q-Transformer → image embedding
  3. BERT → question embedding + model description embeddings
  4. Cosine similarity → best model selection
  5. Alignment layer → aligned visual + text representation
  6. LLM → final answer

- Design tradeoffs:
  - Storing many small adapters vs. one large unified model: Adapters save space and allow independent updates, but require selection logic and may have redundancy.
  - Using BERT for similarity vs. learned matching: BERT is pre-trained and generalizable, but may not be optimal for this specific task compared to a learned classifier.
  - Freezing backbones vs. fine-tuning: Freezing saves compute and storage, but may limit adaptation potential.

- Failure signatures:
  - Wrong model selected → user gets irrelevant or incorrect answer
  - Similarity scores too close → system may be unstable in selection
  - Adapter too small → poor performance on its target domain
  - ViT/Q-Transformer mismatch → visual features not well aligned with text

- First 3 experiments:
  1. Unit test the similarity module: Given a set of question and model description pairs, verify that the highest similarity score matches the expected model.
  2. Integration test the full pipeline on a single domain: Use a dermatology image and question, ensure the dermatology adapter is selected and produces a reasonable answer.
  3. Cross-domain test: Use an X-ray image but ask a question that could be interpreted as dermatology-related; verify that the system either selects the correct model or gracefully handles ambiguity.

## Limitations

- The evaluation is limited to only three medical domains, making it difficult to assess scalability to a larger number of medical specialties.
- Performance metrics are not fully specified, particularly for cross-domain scenarios where the system must select between multiple potential expert models.
- The adaptive expert selection algorithm's behavior when similarity scores are very close or when queries are genuinely ambiguous across domains is not well characterized.

## Confidence

- High confidence in the core mechanism of using adapter-based expert alignment layers for cost-effective scalability
- Medium confidence in the similarity-based model selection approach, given that it relies on BERT embeddings without domain-specific fine-tuning
- Medium confidence in cross-domain capability claims, as the evaluation scenarios appear somewhat limited
- Low confidence in the system's performance with a larger number of medical domains due to limited empirical evidence

## Next Checks

1. **Similarity Score Distribution Analysis**: Test the adaptive selection algorithm with intentionally ambiguous queries and measure how often it selects the correct domain, particularly when similarity scores are close. This will reveal the robustness of the selection mechanism.

2. **Scalability Benchmark**: Implement the system with 10+ medical domain adapters (beyond the three tested) and measure both storage requirements and selection accuracy degradation as the number of domains increases.

3. **Cross-Domain Query Stress Test**: Design queries that explicitly require knowledge from multiple medical domains (e.g., "Could this skin lesion be related to the lung condition shown in this X-ray?") and evaluate whether the system can handle such cases or if it defaults to a single domain prediction.
