# Noisy Parallel Data Alignment

## Quick Facts
- arXiv ID: 2301.09685
- Source URL: https://arxiv.org/abs/2301.09685
- Reference count: 25
- Primary result: Synthetic OCR noise injection reduces alignment error rate up to 59.6% for low-resource languages

## Executive Summary
This work addresses the challenge of aligning noisy OCR text for low-resource and endangered languages, where modern NLP models perform poorly due to noise. The authors create synthetic OCR-like noisy data by modeling real OCR errors (substitutions, deletions, insertions) based on character-level edit distances. They apply this synthetic data to train or fine-tune word alignment models, particularly the state-of-the-art neural model awesome-align. Their approach significantly reduces alignment error rate (AER) on multiple language pairs by incorporating structural diagonal bias for low-resource settings.

## Method Summary
The method involves building probabilistic models that capture OCR errors using Levenshtein distance to compute edit probabilities, then generating synthetic noisy data by applying these error models to clean parallel text. Word alignment models (especially awesome-align) are fine-tuned or trained on this synthetic noisy data, optionally with diagonal bias for low-resource settings. The approach is evaluated on clean-clean, clean-noisy, noisy-clean, and noisy-noisy test sets using alignment error rate as the primary metric.

## Key Results
- Synthetic noise injection reduces AER up to 59.6% on state-of-the-art neural alignment models
- Diagonal bias improves alignment quality for low-resource languages by emphasizing near-diagonal alignments
- Supervised fine-tuning with silver alignments from clean data outperforms unsupervised fine-tuning on noisy data

## Why This Works (Mechanism)

### Mechanism 1
Synthetic OCR noise injection during training makes alignment models more robust to real OCR errors. The method captures real OCR error distributions using edit distance statistics, then synthesizes parallel data with similar noise patterns. Fine-tuning on this noisy synthetic data exposes the alignment model to perturbations it will encounter in real OCR output. Core assumption: synthetic error distribution matches real OCR errors. Evidence: up to 59.6% AER reduction. Break condition: if real OCR error distribution changes.

### Mechanism 2
Diagonal bias improves alignment quality for low-resource languages by incorporating prior structural knowledge. A bias matrix emphasizes alignments near the diagonal of the attention matrix, reflecting common monotone alignment patterns. Core assumption: low-resource language pairs tend to have monotone alignment structures. Evidence: AER reduction with diagonal bias. Break condition: if language pair has highly non-monotone alignment.

### Mechanism 3
Supervised fine-tuning with silver alignments derived from clean data improves performance on noisy data more than unsupervised fine-tuning. Clean parallel data generates silver alignments with an out-of-the-box model, which then supervise fine-tuning on synthetic noisy data. Core assumption: silver alignments from clean data are accurate enough for supervision. Evidence: improved performance over unsupervised fine-tuning. Break condition: if silver alignments contain many errors.

## Foundational Learning

- Concept: Edit distance and Levenshtein distance
  - Why needed here: Used to compute frequency of OCR errors between clean and noisy text, forming basis for synthetic noise generation
  - Quick check question: What are the three operations that Levenshtein distance counts between two strings?

- Concept: Word alignment error rate (AER)
  - Why needed here: Primary evaluation metric; lower AER indicates better alignment quality
  - Quick check question: If an alignment model predicts 50 alignments and 40 match gold standard, what is its precision?

- Concept: Fine-tuning vs. training from scratch
  - Why needed here: Method uses fine-tuning of pre-trained models on synthetic data
  - Quick check question: When would you choose fine-tuning over training a new model from scratch?

## Architecture Onboarding

- Component map: Input pipeline (clean and noisy parallel sentences) → Error model (compute substitution/insertion probabilities) → Synthetic data generator (apply noise to clean data) → Alignment model (awesome-align, optionally with diagonal bias) → Evaluation (AER against gold alignments)
- Critical path: Error modeling → Synthetic data generation → Fine-tuning alignment model
- Design tradeoffs: More synthetic data improves robustness but increases compute cost; stronger diagonal bias helps monotone alignments but may hurt non-monotone ones; supervised fine-tuning requires silver alignments, adding preprocessing steps
- Failure signatures: High AER on both clean and noisy test sets indicates synthetic data mismatch; large gap between clean and noisy performance suggests insufficient fine-tuning; worse performance after fine-tuning indicates poor quality silver alignments or over-regularization from bias
- First 3 experiments:
  1. Generate synthetic data with varying CER levels and evaluate impact on AER for clean-clean, clean-noisy, noisy-clean, and noisy-noisy test sets
  2. Compare unsupervised vs. supervised fine-tuning with synthetic data on a low-resource pair to quantify benefit of silver alignments
  3. Apply diagonal bias to alignment model and measure improvement in low-resource versus high-resource settings

## Open Questions the Paper Calls Out

The paper does not explicitly call out open questions, but several important research directions emerge from the work:

- How does diagonal bias matrix scale to very long sentences in terms of computational efficiency and effectiveness?
- Is there an optimal synthetic data size for fine-tuning that balances performance gains against computational costs?
- How do OCR error distributions vary across different types of documents and how should this affect synthetic data generation?
- Can the approach be adapted to handle OCR noise in languages with non-Latin scripts?

## Limitations

- Synthetic data quality depends on accurate modeling of real OCR error distributions, which may vary across OCR engines and document types
- Diagonal bias implementation details are not fully specified, making exact reproduction difficult
- Method relies on availability of clean parallel data to generate silver alignments for supervised fine-tuning

## Confidence

- High Confidence: Overall approach of using synthetic noisy data to improve robustness is sound and well-supported by significant AER reductions reported (up to 59.6%)
- Medium Confidence: Effectiveness of diagonal bias for low-resource languages is supported by experimental results, but implementation details are lacking
- Low Confidence: Assumption that silver alignments are accurate enough for effective supervised fine-tuning is reasonable but not directly validated
