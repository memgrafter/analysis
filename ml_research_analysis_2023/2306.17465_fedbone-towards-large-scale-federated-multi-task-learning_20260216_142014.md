# FedBone: Towards Large-Scale Federated Multi-Task Learning

## Quick Facts
- **arXiv ID**: 2306.17465
- **Source URL**: https://arxiv.org/abs/2306.17465
- **Reference count**: 15
- **Key outcome**: FedBone achieves better performance than existing FL algorithms on dense prediction and classification tasks while requiring significantly less computational resources on edge clients.

## Executive Summary
FedBone is a federated multi-task learning framework that addresses two key challenges in FL: insufficient computing power on edge clients and gradient conflicts during federated aggregation. The framework splits the model into a large-scale general model on the cloud server and task-specific models on edge clients, enabling efficient training with limited client resources. It introduces a gradient projection-based aggregation method to reduce negative impacts of conflicting gradients and improve generalization. Experiments on public datasets (NYUDv2, PASCAL-Context) and a real ophthalmic dataset demonstrate FedBone's superior performance compared to existing federated learning algorithms while requiring significantly less computational resources on the client side.

## Method Summary
FedBone implements a split learning paradigm where clients compute patch embeddings locally, send them to a cloud server for feature extraction using a large-scale general model (Swin Transformer), then perform task-specific adaptation locally. The framework uses GPAggregation with gradient projection to handle conflicting gradients between tasks - when gradients have negative cosine similarity, one gradient is projected onto the normal plane of the other to remove the conflicting component. Historical gradient attention prevents clients converging to sharp minima from dominating aggregation by rescaling current gradients based on cosine similarity with historical aggregated gradients. Task adaptation modules with deformable convolutions and self-attention enable efficient task-specific processing on resource-constrained clients.

## Key Results
- FedBone outperforms existing federated learning algorithms on dense prediction tasks (semantic segmentation, depth estimation, normal estimation) and classification tasks
- Achieves better generalization through gradient projection-based aggregation that resolves conflicting gradients between heterogeneous tasks
- Requires significantly less computational resources on edge clients by offloading large-scale feature extraction to cloud server
- Successfully handles 13 tasks in ophthalmic dataset including disease classification, grading, and segmentation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Gradient conflicts between clients are resolved by projecting conflicting gradients onto orthogonal planes.
- Mechanism: When two gradients have a negative cosine similarity (cos ωij < 0), one gradient is projected onto the normal plane of the other, removing the conflicting component.
- Core assumption: The conflicting gradient component is the primary source of negative transfer between tasks.
- Evidence anchors:
  - [abstract] "The conflicting gradient projection technique is used to enhance the generalization of the large-scale general model between different tasks."
  - [section 3.4] "To eliminate the opposite component, as shown in Figure 3(b)."
  - [corpus] Weak evidence - only 1 paper mentions gradient projection in FL context, others focus on different aggregation methods.
- Break condition: If the projection removes too much information, causing underfitting or slow convergence.

### Mechanism 2
- Claim: Historical gradient attention prevents clients converging to sharp minima from dominating aggregation.
- Mechanism: Current client gradients are rescaled by attention weights calculated from cosine similarity with historical aggregated gradients, reducing influence of clients with conflicting optimization trajectories.
- Core assumption: Historical gradients capture long-term optimization direction better than single-step gradients.
- Evidence anchors:
  - [section 3.4] "To dampen the influence of clients which converge towards sharp minima, we propose a novel gradients aggregation method GPAggregation by the use of historical aggregated gradients."
  - [section 3.4] "The gradient projection method is described in Algorithm 2. The task gradients ∇k are scaled by attention mechanism with historical aggregated gradients ∇′."
  - [corpus] No direct evidence - gradient attention in FL is rarely discussed in literature.
- Break condition: If historical gradients become stale or represent outdated optimization directions.

### Mechanism 3
- Claim: Split learning enables large-scale model training on resource-constrained clients by offloading computation to cloud server.
- Mechanism: Clients only perform lightweight patch embedding and task-specific operations, while the cloud server handles feature extraction using the large-scale general model.
- Core assumption: Bandwidth and latency for sending embeddings is acceptable compared to full model training overhead.
- Evidence anchors:
  - [abstract] "We split the entire model into two components: a large-scale general model (referred to as the general model) on the cloud server and multiple task-specific models (referred to as the client model) on edge clients, solving the problem of insufficient computing power on edge clients."
  - [section 3.2] "All clients perform patch embedding computations in parallel and then send the local results to the cloud server for feature extraction using a large-scale general model."
  - [corpus] Strong evidence - split learning is well-established in FL literature for reducing client computational burden.
- Break condition: If communication overhead exceeds benefits of reduced local computation.

## Architecture Onboarding

- **Component map**:
  - Edge clients: Patch embedding module → Task adaptation module (deformable conv + self-attention) → Task-specific heads
  - Cloud server: Large-scale general model (Swin Transformer) → Gradient aggregation logic
  - Communication: Embedding exchange → Gradient exchange → Intermediate results exchange

- **Critical path**:
  1. Client embeds data locally
  2. Client sends embeddings to server
  3. Server extracts features using general model
  4. Server sends features back to client
  5. Client computes task loss and gradients
  6. Client sends gradients to server
  7. Server aggregates gradients via GPAggregation
  8. Server updates general model parameters

- **Design tradeoffs**:
  - Split learning vs full model training: Communication overhead vs local resource requirements
  - GPAggregation vs FedAvg: Complexity vs potential for better generalization
  - Task adaptation module: Added parameters vs improved task-specific performance

- **Failure signatures**:
  - Communication bottlenecks: High latency in embedding/gradient exchange
  - Model degradation: Poor performance on individual tasks despite aggregation
  - Resource imbalance: Cloud server becomes bottleneck while clients idle

- **First 3 experiments**:
  1. Baseline FedAvg with same architecture but no split learning - measure communication vs computation tradeoff
  2. FedBone without GPAggregation but with split learning - isolate impact of gradient projection
  3. FedBone without task adaptation module - measure contribution of deformable conv + self-attention

## Limitations

- Limited evaluation to specific datasets without testing on tasks with more severe gradient conflicts
- No comparison against other multi-task FL approaches that don't use split learning
- Missing analysis of communication costs relative to computational savings
- No ablation study isolating GPAggregation impact from split learning benefits

## Confidence

**Confidence: Medium** - The gradient projection mechanism relies on assumptions about conflicting gradient identification that aren't fully validated. The claim that projecting gradients onto orthogonal planes resolves negative transfer is based on geometric intuition but lacks empirical validation showing which components are truly harmful versus beneficial.

**Confidence: Medium** - Historical gradient attention assumes that past aggregated gradients represent optimal optimization direction, but this may not hold when task distributions shift or when clients have heterogeneous data. The decay mechanism for historical gradients isn't specified.

**Confidence: Medium** - The split learning architecture assumes communication overhead for embeddings is acceptable, but no quantitative analysis of bandwidth requirements vs computational savings is provided. Large-scale general model parameters (Swin-S) could create significant communication burden.
