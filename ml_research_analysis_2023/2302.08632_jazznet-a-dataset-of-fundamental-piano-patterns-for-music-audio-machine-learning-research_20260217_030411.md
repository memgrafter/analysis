# jazznet: A Dataset of Fundamental Piano Patterns for Music Audio Machine Learning Research

## Quick Facts
- arXiv ID: 2302.08632
- Source URL: https://arxiv.org/abs/2302.08632
- Reference count: 0
- Primary result: Dataset of 162,520 labeled piano patterns for music information retrieval research

## Executive Summary
This paper introduces jazznet, a comprehensive dataset of fundamental jazz piano patterns designed to advance machine learning research in music information retrieval. The dataset contains over 162,000 labeled piano patterns including chords, arpeggios, scales, and chord progressions with all inversions, totaling more than 26,000 hours of audio. The authors present a novel Distance-Based Pattern Structures (DBPS) method that allows researchers to easily generate new piano patterns by defining intervallic distances, along with baseline models demonstrating the dataset's utility for benchmarking MIR tasks.

## Method Summary
The jazznet dataset was created using a Distance-Based Pattern Structures (DBPS) method that generates piano patterns by defining intervallic distances from a root note. The Pattern Generator iterates through all 88 piano keys and applies these distance patterns to automatically create all possible variations and inversions. MIDI files are generated and converted to 16kHz/24-bit WAV audio using Timidity synthesizer with standardized parameters (60 bpm, 2-beat decay, consistent durations per pattern type). The dataset includes four pattern types: chords (3 seconds), arpeggios (4-6 seconds), scales (7-9 seconds), and progressions (7-10 seconds), organized in directories with corresponding metadata CSV files for train/validation/test splits.

## Key Results
- 162,520 labeled piano patterns covering chords, arpeggios, scales, and chord progressions
- 95GB dataset with more than 26,000 hours of 16kHz/24-bit WAV audio
- Multi-class labeling enables hierarchical benchmarking of model performance
- Baseline models (CRNN and M5) demonstrate dataset utility for mode prediction tasks
- Open-source Pattern Generator allows easy expansion and generation of new patterns

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Distance-Based Pattern Structures (DBPS) enable scalable generation of piano patterns by encoding musical intervals as numerical distances.
- Mechanism: Each piano pattern (chord, arpeggio, scale, progression) is defined by a sequence of MIDI pitch distances from the root note. The algorithm iterates through all piano keys and applies these distances to generate all possible patterns and inversions automatically.
- Core assumption: Musical patterns can be fully described by their intervallic structure, independent of absolute pitch.
- Evidence anchors:
  - [abstract] "Pattern Generator using a method called Distance-Based Pattern Structures (DBPS), which allows researchers to easily generate new piano patterns simply by defining the distances between pitches within the musical patterns."
  - [section] "We use a method called distance-based pattern structures (DBPS) to automatically generate piano patterns in a flexible and intuitive way. Thanks to the formulaic structure of most piano music patterns, the patterns can be generated based on the distance between the pitches within the patterns."
- Break condition: If patterns require context-dependent modifications (e.g., voice leading, harmonic tension) that cannot be reduced to intervallic distances, the DBPS method would fail to generate musically valid patterns.

### Mechanism 2
- Claim: Multi-class labeling (chords, arpeggios, scales, progressions) enables hierarchical MIR benchmarking that mirrors human learning difficulty.
- Mechanism: The dataset is structured to allow models to first distinguish between pattern types (easier), then modes within types (harder), and finally specific keys (hardest), creating a natural progression for model development and evaluation.
- Core assumption: Human difficulty in recognizing musical patterns correlates with model difficulty, making the dataset useful for progressive model training.
- Evidence anchors:
  - [abstract] "The multi-class characteristic of the dataset also aims to model the hierarchy of difficulty humans experience in learning jazz music."
  - [section] "The dataset is based on the notes of a standard 8-octave (88-key) piano... The dataset consists of four types of piano patterns: chords, arpeggios, scales and chord progressions."
- Break condition: If model performance does not correlate with the stated difficulty hierarchy, the multi-class structure may not provide the intended benchmarking utility.

### Mechanism 3
- Claim: Wav audio format with consistent tempo and decay enables direct comparison between different pattern types and inversion variants.
- Mechanism: All patterns are recorded at 60 bpm with standardized 2-beat decay and consistent duration per type (chords: 3s, arpeggios: 4-6s, scales: 7-9s, progressions: 7-10s), creating uniform input for audio-based models.
- Core assumption: Consistent recording parameters eliminate confounding variables when comparing model performance across pattern types.
- Evidence anchors:
  - [section] "The patterns are all recorded at a speed of 60 beats per minute (bpm), with two beats of decay at the end. The chord recordings are all 3 seconds long. The arpeggios and scales are recorded with one note played per beat... Progressions are recorded with two chords played per measure and range from 7 to 10 seconds long."
- Break condition: If musical patterns require variable tempos or decay times to be properly recognized, the standardized approach would limit model effectiveness.

## Foundational Learning

- Concept: MIDI pitch numbering system (0-127) with semitone intervals
  - Why needed here: Understanding how musical distances are encoded as numbers is essential for using and extending the DBPS method
  - Quick check question: What MIDI pitch numbers represent C4 and the next C above it?

- Concept: Musical inversion and its relationship to pitch reordering
  - Why needed here: The dataset includes all inversions for each pattern, so understanding how inversions work is necessary for pattern generation and analysis
  - Quick check question: How many inversions does a 4-note chord have, and what determines each inversion?

- Concept: Basic chord construction and Roman numeral analysis
  - Why needed here: Chord progressions use Roman numerals, and understanding this notation is essential for generating and interpreting progression patterns
  - Quick check question: What Roman numeral represents a C major chord in the key of C major?

## Architecture Onboarding

- Component map:
  - Pattern Generator (Python scripts implementing DBPS) -> MIDI files (intermediate representation) -> WAV conversion (Timidity synthesizer) -> Dataset directories (organized by pattern type) -> Metadata CSV files (labels and splits)

- Critical path: Pattern Generator → MIDI files → WAV conversion → Dataset assembly → Model training

- Design tradeoffs: 
  - WAV format provides consistency but larger file size vs. MIDI's compactness
  - Fixed tempo and decay simplifies comparison but may not capture musical nuance
  - Multi-class structure enables hierarchical benchmarking but creates imbalance (progressions dominate)

- Failure signatures:
  - Pattern Generator produces incorrect MIDI files → check distance calculations in DBPS implementation
  - Audio files have timing issues → verify Timidity synthesizer settings
  - Models perform poorly on specific pattern types → check if those patterns were correctly generated and labeled

- First 3 experiments:
  1. Generate and verify a simple chord (e.g., C major triad) using the Pattern Generator to confirm DBPS implementation
  2. Train a basic classifier to distinguish between chord and arpeggio patterns using the small subset
  3. Test model performance on mode recognition within a single pattern type (e.g., distinguishing major vs minor chords)

## Open Questions the Paper Calls Out

- How do performance differences between CRNN and M5 models change when trained on subsets of the jazznet dataset with varying degrees of class imbalance?
- Can the DBPS method be extended to generate patterns for instruments other than piano while maintaining the same intuitive distance-based approach?
- How does the inclusion of more complex patterns (such as 5-note chords or longer chord progressions) affect the difficulty of MIR tasks for current ML models?

## Limitations
- Heavy class imbalance with chord progressions dominating other pattern types
- Fixed recording parameters may limit real-world applicability
- DBPS method validation limited to jazz piano patterns

## Confidence
- High: Dataset creation methodology and DBPS algorithm implementation are clearly specified and reproducible
- Medium: Benchmarking utility of multi-class structure is theoretically sound but requires empirical validation
- Medium: Scalability claims depend on assumption that intervallic distances fully capture musical patterns

## Next Checks
