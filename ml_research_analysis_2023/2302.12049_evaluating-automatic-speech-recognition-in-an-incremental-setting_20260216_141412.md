# Evaluating Automatic Speech Recognition in an Incremental Setting

## Quick Facts
- **arXiv ID**: 2302.12049
- **Source URL**: https://arxiv.org/abs/2302.12049
- **Reference count**: 0
- **Key outcome**: Local ASR models are faster and more stable than cloud-based models; Meta's Wav2Vec is fastest, Mozilla's DeepSpeech is most stable; Concatenation method is more accurate but computationally expensive.

## Executive Summary
This paper evaluates six automatic speech recognition (ASR) models on English test data using metrics like word error rate (WER), latency, and stability. The authors propose two methods for streaming audio into recognizers for incremental recognition and introduce a new metric called Revokes per Second. Their findings show that local recognizers generally outperform cloud-based ones in speed and stability, with Meta's Wav2Vec being the fastest and Mozilla's DeepSpeech the most stable. The Concatenation method for combining sub-word output is more accurate but computationally more expensive than the Sliding Window method.

## Method Summary
The authors evaluate six ASR models (Google Cloud Speech-to-Text, Microsoft Azure Speech SDK, Meta's Wav2Vec, Mozilla's DeepSpeech, CMU Sphinx, and Vosk) on two datasets: LibriSpeech test-clean and a medical conversation dataset. They use the ReTiCo framework to implement incremental recognition with two streaming methods: Sliding Window and Concatenation. The evaluation measures WER, latency, Edit Overhead, and introduces Revokes per Second as a new metric. The test data was filtered to 17 utterances that could be processed by all models.

## Key Results
- Local ASR models (Meta's Wav2Vec, Mozilla's DeepSpeech, CMU Sphinx, Vosk) are faster and more stable than cloud-based models (Google Cloud, Microsoft Azure)
- Meta's Wav2Vec model is the fastest among all tested models
- Mozilla's DeepSpeech model is the most stable in its predictions
- The Concatenation method produces more accurate results but is computationally more expensive than the Sliding Window method

- Core assumption: Network latency dominates cloud-based model response time, and local GPU processing is faster than cloud inference for the same model architecture.

## Foundational Learning

- **Word Error Rate (WER)**: Primary metric for evaluating ASR accuracy, measuring the edit distance between reference and hypothesis transcriptions. Needed to compare model accuracy across different approaches.
- **Edit Operations (Add, Revoke, Commit)**: Core operations in incremental ASR that track how predictions change over time. Understanding these is crucial for interpreting IU framework metrics.
- **Streaming vs. Batch Processing**: Fundamental distinction in how audio is fed to ASR models. Streaming is essential for real-time incremental recognition in dialogue systems.

## Architecture Onboarding

- **Component map**: Audio input buffer → Streaming method (Sliding Window/Concatenation) → ASR model → IU framework processing → Output with add/revoke/commit operations
- **Critical path**: Audio input → Buffer management → ASR inference → Edit operation determination → Output generation
- **Design tradeoffs**:
  - Sliding Window: Lower computational cost but requires dictionary-based joining and may lose context
  - Concatenation: Higher accuracy and no joining required but more computationally expensive and memory-intensive
  - Local vs Cloud: Local offers lower latency and better privacy but limited scalability; Cloud offers better scalability but higher latency and privacy concerns
- **Failure signatures**:
  - High RPS with low WER: Model is frequently changing predictions but getting them right eventually
  - Low RPS with high WER: Model is stable but consistently wrong
  - High latency across all models: Potential system bottleneck or resource constraint
  - Inconsistent results between Sliding Window and Concatenation: Indicates context sensitivity issues
- **First 3 experiments**:
  1. Run each ASR model with both Sliding Window and Concatenation methods on the same test audio to compare WER and RPS
  2. Measure latency for each model under varying network conditions to confirm local vs cloud latency differences
  3. Test model stability by introducing controlled audio variations and measuring revoke frequency

## Limitations

- The evaluation is limited to only 17 utterances that could be processed by all six ASR models, potentially limiting generalizability
- The study focuses exclusively on English language data, which may not translate to other languages with different phonetic structures
- The Concatenation method's computational expense raises questions about its practical applicability in real-time systems with limited resources
- The Revokes per Second metric has not been validated across diverse ASR tasks or compared to established metrics in the broader research community

## Confidence

- **High Confidence**: Local ASR models achieve lower latency than cloud-based models; Meta's Wav2Vec is the fastest model
- **Medium Confidence**: Concatenation method is more accurate than Sliding Window; RPS metric shows promise but needs broader validation
- **Low Confidence**: Mozilla DeepSpeech being the most stable model is based on limited data (17 utterances)
