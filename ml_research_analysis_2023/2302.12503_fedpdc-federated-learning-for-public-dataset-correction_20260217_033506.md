# FedPDC:Federated Learning for Public Dataset Correction

## Quick Facts
- arXiv ID: 2302.12503
- Source URL: https://arxiv.org/abs/2302.12503
- Reference count: 37
- Improves model accuracy in non-IID federated learning by using server-side public data for model correction

## Executive Summary
This paper introduces FedPDC, a federated learning algorithm that addresses the challenge of non-IID data distribution across clients by leveraging server-side public datasets. The method improves model accuracy without additional communication costs by using public data to correct local models during aggregation and training. FedPDC demonstrates consistent performance improvements over traditional federated learning methods across multiple image classification benchmarks.

## Method Summary
FedPDC introduces a novel approach to federated learning by incorporating server-side public datasets into the model aggregation and training process. The algorithm weights local model updates based on their accuracy on public data during aggregation, and adds a regularization term to the local loss function that penalizes poor performance on public data. This mechanism helps align local models with a common objective while maintaining the benefits of federated learning's privacy-preserving architecture.

## Key Results
- Achieves 2-4% accuracy improvements over FedAvg and FedProx across CIFAR-10, CIFAR-100, and Tiny-Imagenet datasets
- Maintains robustness in highly non-IID data scenarios
- No additional communication costs compared to standard federated learning approaches

## Why This Works (Mechanism)
FedPDC works by using server-side public data as a reference point to correct model drift that occurs in federated learning with non-IID data. During aggregation, models that perform better on public data are given higher weights, ensuring that the global model is biased toward solutions that generalize better. The local regularization term encourages each client to maintain model parameters that perform well on public data, creating a shared objective across all participants.

## Architecture Onboarding

**Component Map:** Clients -> Local Training (with regularization) -> Server Aggregation (weighted by public accuracy) -> Global Model Update

**Critical Path:** The key workflow involves each client training locally with the public data regularization term, sending updated weights to the server, where aggregation weights are determined by public data accuracy, then distributing the updated global model.

**Design Tradeoffs:** Uses public data instead of private client data for regularization (privacy-preserving but requires representative public data); adds computation to local training but no communication overhead; requires public data that matches federated task domain.

**Failure Signatures:** If public data is not representative of federated data distribution, the regularization may push models in wrong directions; if public data is too small, accuracy weights may be unreliable; if communication is unstable, the weighted aggregation may not converge properly.

**First Experiments:** 1) Compare FedPDC vs FedAvg on CIFAR-10 with increasing degrees of non-IIDness; 2) Test FedPDC with different sizes of public datasets to find optimal scale; 3) Evaluate FedPDC with different regularization strengths to find optimal balance.

## Limitations
- Limited testing to image classification tasks on CIFAR and Tiny-Imagenet datasets
- Does not address privacy concerns regarding model inversion attacks through public data
- Assumes server-side public data is representative of federated data distribution
