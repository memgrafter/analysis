# PESCO: Prompt-enhanced Self Contrastive Learning for Zero-shot Text Classification

## Quick Facts
- arXiv ID: 2305.14963
- Source URL: https://arxiv.org/abs/2305.14963
- Authors: 
- Reference count: 16
- Key result: Achieves 98.5% accuracy on DBpedia zero-shot classification

## Executive Summary
This paper introduces PESCO, a self-training framework for zero-shot text classification that combines prompt-enhanced label descriptions with contrastive learning. The method treats text classification as a neural text matching problem, mapping documents and label-prompts into a shared embedding space where similarity determines classification. PESCO iteratively improves performance through a self-training loop that generates pseudo-labels and refines the model using a novel Prompt-aware Label-aware Cloze Test (PLCT) loss. The framework achieves state-of-the-art results on four benchmark datasets, demonstrating the effectiveness of integrating prompts with contrastive learning for zero-shot scenarios.

## Method Summary
PESCO reformulates zero-shot text classification as a neural text matching problem using a pre-trained sentence encoder (SimCSE). The method operates in two main phases: first, documents and enhanced label-prompts are encoded into embeddings, and labels are predicted based on cosine similarity. Second, a self-training loop iteratively generates pseudo-labels and updates the encoder using PLCT loss, which combines Label-aware Cloze Test (LCT) and Prompt Contrastive Loss (PCL). Key sentence selection identifies the most salient sentence in each document based on similarity to the predicted label-prompt, serving as positive examples in contrastive learning. The training pairs are sampled based on confidence scores, with the number of pairs gradually increasing across iterations to maintain label balance.

## Key Results
- Achieves 98.5% accuracy on DBpedia zero-shot classification
- State-of-the-art performance across four benchmark datasets (AG News, DBpedia, Yahoo Answers, Amazon)
- Demonstrates all components of PESCO are necessary for optimal performance
- Shows effectiveness of prompt-enhanced label descriptions in improving matching quality

## Why This Works (Mechanism)

### Mechanism 1
- Claim: The key sentence selection based on similarity to the pseudo-label prompt provides an effective augmentation signal.
- Mechanism: For each document, the algorithm identifies the most salient sentence that best matches the predicted label's prompt embedding. This sentence serves as a positive example during contrastive training, effectively bridging the gap between the full document context and the condensed label representation.
- Core assumption: The most semantically relevant sentence to a document's predicted label will also be the most informative for training the text encoder to align documents with their correct labels.
- Evidence anchors:
  - [section] "As illustrated in Figure 2-(A), given an input document xi = {s1i, s2i, · · · , sni} consists of n sentences and its predicted pseudo label ŷi, its key sentence ki is sj, where: j = arg maxn g(sni, pŷi)."
  - [section] "We use the supervised contrastive loss (Khosla et al., 2020) to optimize LCT, which extends the SimCLR (Chen et al., 2020) to allow multiple positive keys for a query in a supervised setting."
  - [corpus] Weak - no direct comparison studies on key sentence selection versus random sampling in contrastive learning for text classification found in corpus.
- Break condition: If the pseudo-label predictions are noisy or the sentence-level semantics don't align well with the label descriptions, the selected key sentences could mislead the contrastive learning process rather than enhance it.

### Mechanism 2
- Claim: Combining label-prompt matching (PCL) with key sentence matching (LCT) in a single batch creates a more challenging and effective contrastive task.
- Mechanism: By placing both pseudo-label prompts and key sentences from documents with the same pseudo-label into the same contrastive batch, the model must distinguish between these semantically similar positive examples while pushing away negative examples. This dual positive setup forces the encoder to learn finer-grained distinctions.
- Core assumption: The model benefits from having multiple semantically related positive examples (both the prompt and the key sentence) rather than just one, and these examples serve as challenging negative examples for each other.
- Evidence anchors:
  - [section] "By doing so, pseudo keys k and pseudo prompt p can serve as mutually challenging negative samples, thus enhancing the representative power through more difficult contrastive tasks."
  - [section] "In our experiment, this simple solution significantly improves the performance."
  - [corpus] Weak - no explicit ablation studies found in corpus comparing single versus dual positive contrastive setups for text classification.
- Break condition: If the key sentences and prompts are too dissimilar or the batch size is too small to provide meaningful negative samples, the contrastive signal could become diluted or confusing.

### Mechanism 3
- Claim: The self-training loop with gradually increasing training pair sampling creates a stable learning trajectory.
- Mechanism: The algorithm starts with a pre-trained sentence encoder to generate initial pseudo-labels, then iteratively refines the encoder using contrastive loss on these pseudo-labels. The sampling probability is proportional to prediction confidence, and the number of training pairs increases over iterations, allowing the model to focus on high-confidence examples early and gradually incorporate more challenging cases.
- Core assumption: Starting with a strong pre-trained model and gradually incorporating more training data based on confidence scores prevents the model from being overwhelmed by noisy pseudo-labels in early stages.
- Evidence anchors:
  - [section] "We use fθ(·) from the last iteration as our final model. In the algorithm, we set Tt = d · Tt−1 that gradually increases T until a threshold T ′."
  - [section] "When sampling pseudo training pairs, we found that it is important to keep the ratio of all the labels balanced."
  - [corpus] Weak - no direct comparison found in corpus of gradual versus immediate full sampling strategies in self-training for zero-shot text classification.
- Break condition: If the initial pseudo-label quality is poor or the confidence threshold is set too low, the model could reinforce incorrect predictions and degrade performance over iterations.

## Foundational Learning

- Concept: Contrastive learning with supervised positive pairs
  - Why needed here: PESCO relies on supervised contrastive loss (Khosla et al., 2020) to train the text encoder using pseudo-labels as supervision. Understanding how positive pairs are constructed and how the loss function operates is fundamental to implementing the LCT and PCL components.
  - Quick check question: In supervised contrastive learning, how are positive pairs defined differently from unsupervised contrastive learning like SimCLR?

- Concept: Text matching and embedding similarity
  - Why needed here: The core classification task is reformulated as a matching problem where documents and label-prompts are mapped to a shared embedding space. The system predicts labels based on cosine similarity between these embeddings, requiring understanding of how text encoders produce comparable representations.
  - Quick check question: What properties should a text encoder have to ensure that semantically similar texts (documents and their correct labels) have high cosine similarity in the embedding space?

- Concept: Prompt-based learning and template engineering
  - Why needed here: PESCO uses prompts to enhance label descriptions, converting short label names into more informative label-prompts. Understanding how different prompt templates affect model comprehension is crucial for implementing and tuning this component.
  - Quick check question: How does adding context through prompts (e.g., "Category: [desc]" vs just "[desc]") affect a pre-trained language model's ability to understand and match label semantics?

## Architecture Onboarding

- Component map: Text Encoder (fθ) -> Prompt Generator -> Key Sentence Selector -> Pseudo-label Generator -> Contrastive Trainer (PLCT) -> Updated Text Encoder

- Critical path: Unlabeled documents → Text Encoder → Pseudo-labels → Key Sentence Selection → Contrastive Training (PLCT) → Updated Text Encoder → Repeat until convergence

- Design tradeoffs:
  - Batch size vs. training stability: Larger batches provide more negative samples but require more memory
  - Prompt variety vs. computational cost: More prompt templates improve robustness but increase inference time
  - Self-training iterations vs. overfitting: More iterations can improve performance but risk reinforcing errors
  - Key sentence selection vs. document-level context: Focusing on single sentences may lose broader context

- Failure signatures:
  - Performance plateaus early: Indicates the model may be stuck with poor pseudo-labels or the contrastive task is too easy
  - Accuracy drops after iterations: Suggests error propagation in self-training or poor confidence-based sampling
  - High variance across runs: Could indicate sensitivity to random initialization or batch composition
  - Disproportionate performance on certain classes: May reveal bias in pseudo-label generation or imbalanced sampling

- First 3 experiments:
  1. Baseline matching without self-training: Implement the document-to-label-prompt matching using SimCSE embeddings and measure zero-shot accuracy to establish the initial performance ceiling
  2. Key sentence selection ablation: Compare performance using randomly selected sentences versus the most salient sentences in the LCT component to validate the importance of intelligent key selection
  3. PLCT loss composition: Test different combinations of LCT and PCL (separate, summed, or combined in single batch) to identify which configuration yields the best performance gain

## Limitations
- Weak empirical validation of individual mechanisms: Limited ablation studies showing the isolated impact of key sentence selection versus random sampling or dual-positive versus single-positive contrastive setups
- Dataset and domain specificity: Evaluation only on four well-established benchmark datasets; effectiveness on specialized domains or non-English languages unverified
- Reproducibility constraints: Critical implementation details underspecified, including exact prompt templates, sampling strategy, threshold T', and stopping criteria

## Confidence
- **High confidence**: The overall self-training framework architecture is clearly defined and logically sound
- **Medium confidence**: The claim that PESCO achieves state-of-the-art performance on the four benchmark datasets
- **Low confidence**: The specific mechanisms by which individual components (key sentence selection, dual-positive contrastive setup, confidence-based sampling) contribute to performance gains

## Next Checks
1. **Ablation study of key sentence selection**: Implement the contrastive learning component with randomly selected sentences versus the proposed similarity-based key sentence selection. Measure the performance difference on a subset of the benchmark datasets to validate whether intelligent key selection provides statistically significant improvement over simpler alternatives.

2. **Dual-positive versus single-positive contrastive comparison**: Modify the PLCT loss to use only label prompts (PCL-only) or only key sentences (LCT-only) as positive examples in contrastive learning. Compare the performance of these variants against the full PLCT to quantify the marginal benefit of the dual-positive setup.

3. **Confidence threshold sensitivity analysis**: Systematically vary the confidence threshold for pseudo-label sampling across multiple self-training iterations. Measure how different threshold values affect performance stability and final accuracy to identify optimal confidence-based sampling strategies and potential overfitting risks.
