# ChatGPT and Other Large Language Models as Evolutionary Engines for Online Interactive Collaborative Game Design

## Quick Facts
- arXiv ID: 2303.02155
- Source URL: https://arxiv.org/abs/2303.02155
- Authors: 
- Reference count: 40
- Key outcome: An online collaborative design framework that combines interactive evolution with large language models to simulate the typical human design process, evaluated on three game design tasks with remote human designers.

## Executive Summary
This paper presents a novel framework for online interactive collaborative game design that leverages large language models (LLMs) as evolutionary engines. The system combines interactive evolution with LLMs to simulate human design processes, allowing users to collaborate remotely by providing feedback that guides the evolutionary algorithm. The framework was evaluated on three game design tasks, demonstrating its ability to generate novel and diverse game designs while enabling users to steer the design process through their feedback.

## Method Summary
The framework implements an interactive genetic algorithm where large language models serve as the evolutionary engine. The process begins with a design brief and initial candidate designs, either generated by LLMs or provided by users. Users collaborate remotely by providing feedback through polls or web interfaces, which an interactive genetic algorithm uses to select, recombine, and mutate the most promising designs. The evolutionary operators are implemented using LLM prompts, with steady-state selection (tournament size 2), recombination (probability 0.7), and mutation operators. The system uses a database to store designs and evaluations, an interaction agent to manage communication (via Telegram or web interface), and LLM APIs to implement the genetic operators.

## Key Results
- The framework successfully generated novel and diverse game designs across three different design tasks
- Remote human designers were able to effectively collaborate on the design process through feedback mechanisms
- The combination of interactive evolution and LLMs proved effective for complex creative tasks like game design recombination and variation

## Architecture Onboarding

- Component map: Database -> Evolutionary Engine -> Interaction Agent -> LLM API -> Telegram/Web Interface
- Critical path: User feedback → Selection → LLM-based recombination/mutation → New population → Publication of new ideas
- Design tradeoffs:
  - Population size vs. evaluation effort: Smaller populations reduce evaluation burden but may limit diversity
  - Publication frequency vs. user engagement: More frequent publications keep users engaged but may lead to fatigue
  - LLM choice vs. cost/performance: More powerful LLMs may generate better ideas but are more expensive
- Failure signatures:
  - Stale or repetitive design ideas: May indicate issues with LLM-based operators or lack of diversity in initial population
  - Low user engagement: Could be due to interface issues, notification fatigue, or lack of interesting ideas
  - Semantic incoherence in generated ideas: Suggests the LLM is not maintaining semantic coherence as expected
- First 3 experiments:
  1. Test basic functionality with a small population and simple design task to verify all components work together
  2. Experiment with different LLM prompts and parameters to optimize idea generation quality
  3. Conduct a user study with a small group to gather feedback on the interface and evaluation process before scaling up
