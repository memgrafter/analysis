# LUKE-Graph: A Transformer-based Approach with Gated Relational Graph Attention for Cloze-style Reading Comprehension

## Quick Facts
- arXiv ID: 2303.06675
- Source URL: https://arxiv.org/abs/2303.06675
- Reference count: 40
- Primary result: State-of-the-art 91.36 F1 and 90.95 EM on ReCoRD dev set

## Executive Summary
This paper addresses the challenge of incorporating prior knowledge into transformer-based models for cloze-style machine reading comprehension, specifically targeting commonsense reasoning tasks. The authors propose LUKE-Graph, a method that constructs a heterogeneous graph based on intuitive relationships between entities in a document, without relying on external knowledge graphs. The approach leverages the pre-trained LUKE model to obtain entity-aware representations and employs a Relational Graph Attention Network (RGAT) to capture relation-aware representations. To enhance the model's reasoning capability, the authors introduce Gated-RGAT, which incorporates a question-aware gating mechanism to regulate the influence of question information during graph convolution.

## Method Summary
LUKE-Graph constructs a heterogeneous graph from document entities using three edge types (SENT-BASED, MATCH, PLC) and processes it with a two-layer RGAT network augmented with question-aware gating. The model uses pre-trained LUKE to obtain entity-aware contextual representations, then applies Gated-RGAT to fuse graph reasoning with contextual information. A linear classifier scores candidate entities for the cloze-style task. The model is trained with binary cross-entropy loss using AdamW optimizer (learning rate 1e-5, warmup ratio 0.06, weight decay 0.01) for 2 epochs with batch size 32.

## Key Results
- Achieves state-of-the-art performance with 91.36 F1 and 90.95 EM on ReCoRD development set
- Outperforms existing transformer-based and graph-based models on commonsense reasoning tasks
- Demonstrates effectiveness of combining entity-aware representations with graph-based reasoning

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Using LUKE as base model provides entity-aware representations that capture entity relationships better than standard BERT
- Mechanism: LUKE extends RoBERTa by treating entities as independent tokens alongside words, using entity-aware self-attention to explicitly model relationships between entities. This allows the model to distinguish between entities with the same strings and those that are unrelated
- Core assumption: Entity-aware self-attention is more effective than standard self-attention for capturing entity relationships in text
- Evidence anchors: The paper states LUKE has archived impressive performance compared other transformer-based models, and the entity-aware self-attention mechanism allows distinguishing between entities with the same strings

### Mechanism 2
- Claim: Gated-RGAT enhances RGAT by incorporating question information to regulate graph convolution, improving reasoning capability
- Mechanism: Gated-RGAT adds a question-aware gating mechanism to RGAT that adjusts the update message based on question information. This gating mechanism is similar to human reasoning processing, where people choose the best entity candidate based on question information
- Core assumption: Incorporating question information during graph reasoning improves the model's ability to select the most relevant entities
- Evidence anchors: The paper explains that the gating mechanism, like human reasoning processing, considers the question when choosing the entity information

### Mechanism 3
- Claim: Constructing a heterogeneous graph based on intuitive relationships between entities in the document improves performance over using external knowledge graphs
- Mechanism: The model builds a graph where nodes are entities and edges represent relationships (same sentence, matching entities, placeholder connections). This avoids the challenge of selecting relevant entities from external KGs and extracting the best subgraphs
- Core assumption: The relationships between entities within a document are sufficient for commonsense reasoning tasks without requiring external knowledge
- Evidence anchors: The paper states that selecting the most relevant ambiguous entities in KG and extracting the best subgraph remains a challenge, and constructs a heterogeneous graph that relates entities within a sentence and the same entities in different sentences

## Architecture Onboarding

- Component map: Input → LUKE → Graph construction → Gated-RGAT → Linear classifier → Output
- Critical path: Input → LUKE → Graph construction → Gated-RGAT → Linear classifier → Output
- Design tradeoffs:
  - Using LUKE vs other transformers: LUKE provides better entity representations but may be more computationally expensive
  - Graph-based vs graph-free approach: Graph approach captures entity relationships but adds complexity and may not generalize well to documents with sparse entities
  - Gated vs non-gated RGAT: Gating incorporates question information but adds parameters and may over-regularize
- Failure signatures:
  - Poor performance on documents with few entities or weak entity relationships
  - Overfitting to specific entity types or relationship patterns
  - Sensitivity to entity recognition errors in the input
- First 3 experiments:
  1. Compare LUKE-Graph performance with and without the graph module on ReCoRD development set
  2. Test different graph neural network architectures (GAT, GCN, RGCN) in place of RGAT
  3. Evaluate the impact of removing the question-aware gating mechanism from Gated-RGAT

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of LUKE-Graph change when using different knowledge graphs (e.g., WordNet, ConceptNet, NELL) instead of constructing the heterogeneous graph from the document?
- Basis in paper: The paper states that LUKE-Graph does not use any additional knowledge graph and constructs a heterogeneous graph based on the intuitive relationships between entities in a document. It also compares LUKE-Graph to models like SKG-BERT, KT-NET, and KELM that use external knowledge graphs
- Why unresolved: The paper does not provide experimental results comparing LUKE-Graph with external knowledge graphs to its current approach of constructing a heterogeneous graph from the document
- What evidence would resolve it: Conducting experiments using LUKE-Graph with different external knowledge graphs and comparing the results to the current approach would provide evidence to answer this question

### Open Question 2
- Question: How does the performance of LUKE-Graph vary with different graph neural network architectures, such as GraphSAGE or Graph Isomorphism Networks (GIN)?
- Basis in paper: The paper investigates the impact of different graph neural networks (RGAT, GATv2, GAT, RGCN, and GCN) on the performance of LUKE-Graph
- Why unresolved: The paper does not explore the performance of LUKE-Graph using other popular graph neural network architectures like GraphSAGE or GIN
- What evidence would resolve it: Conducting experiments using LUKE-Graph with different graph neural network architectures and comparing the results would provide evidence to answer this question

### Open Question 3
- Question: How does the performance of LUKE-Graph change when incorporating the importance of relationships between entities directly into the transformer model instead of using a separate graph module?
- Basis in paper: The paper mentions that as future work, they would like to incorporate the importance of relationships between entities directly into the transformer model instead of using a separate graph module
- Why unresolved: The paper does not provide any experimental results or analysis on this proposed future work
- What evidence would resolve it: Developing a modified version of LUKE-Graph that incorporates the importance of relationships between entities directly into the transformer model and comparing its performance to the current approach would provide evidence to answer this question

## Limitations

- The exact implementation details of the question-aware gating mechanism are not specified, particularly the architecture of the MLP used for computing gate values
- The evaluation is limited to a single dataset (ReCoRD), which may constrain generalizability to other commonsense reasoning tasks or domains with different entity distributions
- The computational complexity of constructing heterogeneous graphs for each document is not addressed, raising questions about scalability to longer documents or larger datasets

## Confidence

- LUKE entity-aware representations: Medium confidence - strong performance on ReCoRD but lacking ablation studies comparing with standard BERT
- Question-aware gating mechanism: Medium confidence - paper asserts similarity to human reasoning but provides limited quantitative evidence of specific contribution
- Document-based graph sufficiency: Low confidence - absence of comparisons with approaches using external knowledge graphs
