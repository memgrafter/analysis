# Adaptive Decision-Making with Constraints and Dependent Losses: Performance Guarantees and Applications to Online and Nonlinear Identification

## Executive Summary
This paper presents a novel algorithm for adaptive decision-making that improves upon classical multiplicative weights by incorporating constraints on losses. The method solves a linear program at each iteration to determine optimal probability distributions over options, allowing exploitation of suboptimal environment behavior. The algorithm provides instance-dependent regret bounds that outperform standard multiplicative weights when the environment plays suboptimally, and includes closed-form solutions for the case of two options. Applications to nonlinear and online system identification demonstrate competitive performance.

## Method Summary
The algorithm extends classical multiplicative weights by parameterizing the probability distribution as `p_t = w_t-1 / φ_t-1 - ε_t-1 * Q_t-1 * q_t / 2`, where q_t is computed by solving a linear program that minimizes the worst-case second-order term. For m=2 options, closed-form solutions are provided based on interval relationships. The step-size ε_t is adaptively tuned based on accumulated second-order terms. The method handles general dependencies between losses through flexible constraint sets X_t that can also account for loss budgets.

## Key Results
- Regret bound scales with √(∑ max second-order terms) rather than worst-case L²/4 bound used in classical MW
- For m=2, three distinct cases with closed-form optimal strategies based on interval relationships
- Numerical examples on nonlinear system identification show competitive performance against standard MW
- Algorithm exploits suboptimal environment choices, reflected in instance-dependent regret bounds

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The algorithm improves upon classical multiplicative weights by exploiting second-order terms in the Taylor expansion when the environment plays suboptimally.
- **Mechanism:** By parameterizing the probability distribution as `p_t = w_t-1 / φ_t-1 - ε_t-1 * Q_t-1 * q_t / 2`, the algorithm can actively control the second-order term in the regret bound, which becomes `max_{l_t ∈ X_t} l_t^T * Q_t-1 * (l_t - q_t)`. When the environment plays suboptimally, this term can be made smaller than the worst-case L²/4 bound used in classical MW.
- **Core assumption:** The environment's loss constraints X_t are known and can be exploited to reduce the second-order term.
- **Evidence anchors:**
  - [abstract] "Our algorithm and our analysis is instance dependent, that is, suboptimal choices of the environment are exploited and reflected in our regret bounds."
  - [section] "The constraints handle general dependencies between losses (even across time), and are flexible enough to also account for a loss budget, which the environment is not allowed to exceed."
- **Break condition:** If the constraints X_t are vacuous or the environment plays optimally, the algorithm reduces to standard multiplicative weights and loses its advantage.

### Mechanism 2
- **Claim:** The linear programming formulation for two options provides optimal closed-form solutions that exploit interval structure.
- **Mechanism:** For m=2, the minmax problem in (6) reduces to a linear program with only 5 constraints. The optimal solution depends on the relative positions of the intervals [l1_t, ¯l1_t] and [l2_t, ¯l2_t], leading to three distinct cases (A, B, C) with different optimal strategies.
- **Core assumption:** The loss constraints are intervals, which allows the maximization over l_t to be restricted to interval corners.
- **Evidence anchors:**
  - [section] "Let q_t ∈ R^m be an arbitrary vector, and X_t = [l1_t, ¯l1_t] × ··· × [lm_t, ¯lm_t]. Then l_t^T * Q_t-1 * (l_t - q_t) achieves its maximum for l_t ∈ X_t on the corners of X_t."
  - [section] "Depending on the values of ¯l1_t - l2_t and ¯l2_t - l1_t we distinguish three different cases, as summarized in Fig. 1."
- **Break condition:** If m > 2, the problem becomes a more complex linear program with 2m + m + 1 constraints, requiring approximation methods.

### Mechanism 3
- **Claim:** Adaptive step-size tuning (ε_t) balances exploration and exploitation based on accumulated information.
- **Mechanism:** The algorithm sets ε_t = √(2 log(m) / c2 + ∑_{j=0}^{t-1} r̃_j*), where r̃_j* is the maximum second-order term at iteration j. This makes the step-size smaller as more information is gathered, focusing on exploiting the environment's suboptimal behavior.
- **Core assumption:** The accumulated second-order terms r̃_j* provide a reliable measure of the environment's suboptimality.
- **Evidence anchors:**
  - [section] "Alg. 3 adapts the parameter ε_t-1 on the go."
  - [section] "By choosing the parameter ε to be √(2 log(m) / ∑_{j=0}^{T-1} r_j*), we finally arrive at the following bound for the regret"
- **Break condition:** If the environment is adversarial and plays optimally, r̃_j* remains large and the algorithm cannot reduce ε_t below the standard multiplicative weights value.

## Architecture Onboarding

- **Component map:** Weight update module -> Constraint handler -> Linear program solver/Approximation module -> Step-size tuner -> Probability distribution generator -> Action sampler
- **Critical path:** 1. Receive X_t constraints 2. Compute weights w_t-1 from past losses 3. Solve (or approximate) the linear program for q_t 4. Compute step-size ε_t 5. Generate probability distribution p_t 6. Sample action a_t and observe loss l_t 7. Update weights for next iteration
- **Design tradeoffs:**
  - Exact vs. approximate LP solution: Exact solutions are optimal but computationally expensive for large m; approximations are faster but may sacrifice some performance
  - Adaptive vs. fixed step-size: Adaptive step-sizes can exploit suboptimality but add complexity; fixed step-sizes are simpler but may be suboptimal
  - Memory vs. computation: Storing all past losses allows for exact weight updates but increases memory usage
- **Failure signatures:**
  - Weights becoming numerically unstable: Check for overflow in exponential weight updates
  - LP solver failing to find feasible solution: Verify constraint consistency and that X_t is non-empty
  - Poor performance compared to standard MW: Check if environment is truly suboptimal or if constraints are too loose
  - Step-size becoming too small: Monitor if accumulated second-order terms r̃_j* are growing too quickly
- **First 3 experiments:**
  1. Implement the algorithm for m=2 with exact LP solutions and test on randomly generated interval constraints to verify the three-case behavior
  2. Compare performance against standard multiplicative weights on synthetic data where the environment plays suboptimally (e.g., losses concentrated in smaller regions)
  3. Test the approximation method for larger m on nonlinear system identification tasks to evaluate the tradeoff between computation time and performance
