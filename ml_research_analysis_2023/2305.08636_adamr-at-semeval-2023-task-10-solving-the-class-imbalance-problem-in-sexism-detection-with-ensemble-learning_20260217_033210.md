# AdamR at SemEval-2023 Task 10: Solving the Class Imbalance Problem in Sexism Detection with Ensemble Learning

## Quick Facts
- arXiv ID: 2305.08636
- Source URL: https://arxiv.org/abs/2305.08636
- Reference count: 9
- Key outcome: Ranked in top 40% across all three EDOS 2023 subtasks—36th in binary sexism detection (Macro-F1 0.838), 29th in category classification (Macro-F1 0.623), and 25th in fine-grained vector classification (Macro-F1 0.457).

## Executive Summary
This paper addresses the EDOS 2023 challenge for explainable sexism detection on social media texts, focusing on the class imbalance problem where only 24.3% of examples are sexist. The authors employ ensemble learning with Transformer models trained on diverse datasets, combining official EDOS data with external sources like EXIST and HatEval. Their approach includes preprocessing strategies, weighted loss functions, and focal loss to improve minority class performance, achieving competitive results across all three task variants.

## Method Summary
The approach uses ensembles of Transformer models (BERT, RoBERTa, BERTweet variants) trained on different datasets to address class imbalance in sexism detection. The EDOS dataset is augmented with external sources, and models are fine-tuned with weighted loss and focal loss functions to improve minority class detection. Ensembles are created via soft voting of validated models. The method addresses three subtasks: binary sexism detection (Task A), category classification (Task B), and fine-grained vector classification (Task C).

## Key Results
- Achieved top 40% ranking across all three EDOS 2023 subtasks
- Task A (binary detection): Ranked 36th with Macro-F1 0.838
- Task B (category classification): Ranked 29th with Macro-F1 0.623
- Task C (fine-grained classification): Ranked 25th with Macro-F1 0.457

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Ensemble models improve overall performance compared to individual models
- Mechanism: Combining multiple models trained on different datasets and architectures reduces individual model biases and errors, leading to better generalization
- Core assumption: Model errors are diverse and not perfectly correlated across ensemble members
- Evidence anchors:

  - [corpus]: Weak - the corpus neighbors don't directly discuss ensemble performance mechanisms
- Break condition: If all ensemble members make similar errors on the same instances, the ensemble won't improve over the best individual model

### Mechanism 2
- Claim: Using focal loss improves performance on minority classes
- Mechanism: Focal loss reduces the contribution of easy examples and focuses training on hard examples, which helps models learn better representations for minority classes
- Core assumption: The difficulty of classifying minority class examples is the main bottleneck for improving their detection
- Evidence anchors:
  - [section]: "A different loss function was tested, allowing the model to focus on the most challenging entries. Focal loss modifies the weights for each sample by increasing them for the most difficult cases and reducing them for the easy ones"
  - [section]: "For task B, the group of models decided upon was BERTweet base, RoBERTa base, and RoBERTa large, which were trained on datasets B1 and B2. As the problem of vast class imbalance was still present in dataset B1, a different loss function was tested"
  - [corpus]: Weak - corpus doesn't discuss focal loss specifically for sexism detection
- Break condition: If the minority class examples aren't inherently more difficult to classify, focal loss won't provide benefits

### Mechanism 3
- Claim: Data augmentation with external datasets improves minority class representation
- Mechanism: Adding balanced external datasets increases the number of minority class examples, helping models learn better decision boundaries for underrepresented classes
- Core assumption: External datasets contain relevant patterns that generalize to the target domain
- Evidence anchors:
  - [section]: "Multiple additional datasets have been used concerning similar or identical tasks to extend the available training data and enhance predictive capabilities... The provided EDOS datasets have been extended by data points from various sources concerning past research on the topic"

- Break condition: If external datasets have different data distributions or introduce label noise, performance may degrade

## Architecture Onboarding

- Component map:
  - Data preprocessing pipeline (text normalization, special token replacement)
  - Multiple Transformer model trainers (BERT, RoBERTa, BERTweet variants)
  - Loss function modules (standard, weighted, focal)
  - Ensemble combiner (soft voting aggregator)
  - Evaluation metrics calculator (macro-F1 scores)

- Critical path:
  1. Preprocess and normalize all datasets
  2. Train individual Transformer models with different architectures and loss functions
  3. Validate each model on held-out data
  4. Create ensembles by combining validated models
  5. Evaluate ensemble performance on test data

- Design tradeoffs:
  - More models in ensemble → better performance but higher computational cost
  - External data augmentation → better minority class representation but potential distribution mismatch
  - Focal loss → better minority class focus but may hurt overall accuracy

- Failure signatures:
  - Ensemble performance worse than best individual model → models are making correlated errors
  - Minority class performance doesn't improve with focal loss → minority class examples aren't harder to classify
  - Performance degrades with external data → distribution mismatch or label noise in external datasets

- First 3 experiments:
  1. Train a single BERT model on the base EDOS dataset with standard loss function
  2. Train the same BERT model with weighted loss to penalize minority class errors
  3. Create a two-model ensemble of BERT and RoBERTa trained on different datasets using soft voting

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do different ensemble voting strategies (e.g., weighted voting vs. soft voting) impact performance in hierarchical sexism detection tasks?
- Basis in paper: [explicit] The paper mentions that weighted scoring for models was tested in Task A, resulting in marginal improvements but was not used due to overfitting concerns. It also compares hard and soft voting in Task B, showing hard voting sometimes outperformed soft voting.
- Why unresolved: The paper only briefly tested weighted voting and did not fully explore ensemble weighting strategies or other voting mechanisms (e.g., stacked generalization). The trade-off between performance gains and overfitting was not deeply analyzed.
- What evidence would resolve it: Systematic experiments comparing various ensemble voting strategies (e.g., weighted voting, stacked ensembles, dynamic weighting) across all three tasks, with ablation studies to quantify overfitting risks.

### Open Question 2
- Question: What is the optimal balance between model diversity and performance in ensembles for sexism detection?
- Basis in paper: [explicit] The paper notes that the best-performing ensembles did not always include the top individual models, suggesting that model diversity plays a role. However, the criteria for selecting diverse models were not explicitly defined or optimized.
- Why unresolved: The paper does not provide a systematic method for selecting diverse models or quantify the impact of diversity on ensemble performance. It also does not explore whether certain model combinations consistently outperform others.
- What evidence would resolve it: Experiments that systematically vary model diversity (e.g., using models with different architectures, training data, or hyperparameters) and measure the impact on ensemble performance across tasks.

### Open Question 3
- Question: How does the inclusion of translated data (e.g., Spanish texts) affect model performance and fairness in sexism detection?
- Basis in paper: [explicit] The paper tested models with and without translated Spanish data, finding that including translated data degraded performance in Task A but did not explore the reasons or potential mitigation strategies.
- Why unresolved: The paper does not analyze whether the performance drop is due to translation quality, domain mismatch, or class imbalance in the translated data. It also does not assess the fairness implications of excluding non-English data.
- What evidence would resolve it: Detailed analysis of translation quality, domain adaptation techniques, and fairness metrics (e.g., performance across languages and demographics) to determine the impact of multilingual data on model performance and bias.
