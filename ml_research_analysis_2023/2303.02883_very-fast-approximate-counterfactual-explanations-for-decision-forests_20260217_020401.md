# Very fast, approximate counterfactual explanations for decision forests

## Quick Facts
- arXiv ID: 2303.02883
- Source URL: https://arxiv.org/abs/2303.02883
- Reference count: 38
- One-line primary result: LIRE is extremely fast, scales to large forests and high-dimensional data, and produces counterfactual explanations that are both accurate and practical.

## Executive Summary
This paper introduces LIRE (Live Region Search), a method for finding counterfactual explanations for decision forests that addresses the computational challenge of exponential search space. By restricting the search to regions containing actual data points ("live" regions), LIRE dramatically reduces computation while producing realistic counterfactuals. The approach is particularly effective for axis-aligned forests where the problem reduces to a nearest-neighbor search, and it leverages the observation that oblique forests naturally have fewer live regions. Experimental results show LIRE outperforms existing methods in both runtime and solution quality.

## Method Summary
LIRE (Live Region Search) finds counterfactual explanations by searching only over input space regions defined by the forest that contain actual data points. For each training instance, the algorithm tracks which leaf it reaches in each tree to identify live regions. In axis-aligned forests, this reduces to computing distances to axis-aligned boxes using a closed-form median-based formula per dimension, enabling vectorization. For oblique forests, live regions are defined by linear constraints and require solving quadratic or linear programs per region. The method filters live regions to those producing the target prediction and selects the minimum distance solution.

## Key Results
- LIRE achieves runtime improvements of orders of magnitude compared to exhaustive search
- The method produces counterfactual explanations that are both faster to compute and more realistic than competing approaches
- LIRE scales effectively to large forests and high-dimensional datasets while maintaining solution quality

## Why This Works (Mechanism)

### Mechanism 1
Restricting counterfactual search to "live" regions (those containing training data) drastically reduces the search space while improving solution realism. The forest partitions input space into regions; only a small fraction contain actual data points. By limiting search to these regions, the algorithm avoids exponential explosion and biases solutions toward high-density areas. Core assumption: Regions containing training data are more likely to produce realistic counterfactuals than arbitrary regions. Evidence: [abstract] "constrains the optimization to only those input space regions defined by the forest that are populated by actual data points" and [section 4] "restrict the search to only those regions containing at least one actual data point... intuitive... retrieve realistic CEs". Break condition: If the dataset is too sparse or the decision boundaries are highly irregular, live regions might miss optimal counterfactuals.

### Mechanism 2
For axis-aligned forests, the search reduces to a nearest-neighbor problem using a custom distance-to-box function. Each live region is a box defined by lower/upper bounds per dimension. The optimal counterfactual in a box can be computed in closed form per dimension, enabling vectorization over all boxes. Core assumption: The distance function is separable (e.g., ℓ2, ℓ1) so per-dimension optimization is valid. Evidence: [section 5.3] "the solution to 'x* = arg min d(x,x) s.t. a≤x≤b' can be given in closed form as x* = median(a,b,x)" and [section 5.3] "This shows that, in effect, the problem reduces to a form of nearest-neighbor search". Break condition: If using non-separable distances (e.g., Mahalanobis), this optimization no longer applies.

### Mechanism 3
Oblique forests have fewer live regions than axis-aligned forests, making the approach more scalable. Oblique trees use fewer, shallower trees to achieve comparable accuracy, resulting in exponentially fewer regions to search. Core assumption: Oblique trees are more efficient in partitioning space for the same predictive accuracy. Evidence: [section 3.2] "oblique forests... achieve state-of-the-art accuracy using fewer and shallower trees" and [section 4.1] "For oblique forests, it takes well over 10 trees to approach N regions". Break condition: If oblique trees are forced to be deep (e.g., for highly non-linear boundaries), the region count advantage diminishes.

## Architecture Onboarding

- Component map: Forest traversal -> Region construction -> Target filtering -> Distance computation -> Minimum selection
- Critical path: Forest traversal → Region construction → Target filtering → Distance computation → Minimum selection
- Design tradeoffs:
  - Axis-aligned vs oblique: Axis-aligned is faster but needs more trees; oblique is slower per region but needs fewer trees
  - Exhaustive vs approximate: Exhaustive guarantees optimality but is exponential; approximate is fast but suboptimal
  - Distance metrics: ℓ2 is smooth but ℓ1 is more robust to outliers
- Failure signatures:
  - Runtime explosion: Indicates too many live regions (likely with axis-aligned forests on large datasets)
  - Suboptimal solutions: May occur if target regions are sparse or decision boundaries are irregular
  - Memory issues: Suggests too many regions being stored simultaneously
- First 3 experiments:
  1. Run LIRE on a small axis-aligned forest (e.g., 10 trees, depth 5) with a binary classification dataset and verify runtime vs exhaustive search
  2. Compare LIRE solutions to dataset search on a moderate-sized problem (e.g., 100 trees) to measure approximation quality
  3. Test oblique forest variant on a high-dimensional problem to validate the region count advantage claim

## Open Questions the Paper Calls Out

### Open Question 1
How does the LIRE algorithm's performance scale with dataset size beyond the tested cases, particularly for datasets with billions of instances? The paper mentions that for very large datasets, LIRE's exhaustive search becomes slow, suggesting potential methods like parallelization, search trees, or approximate nearest-neighbor techniques, but does not explore these. The paper only tests LIRE on datasets up to 55k instances and mentions potential solutions for scaling without implementing or testing them.

### Open Question 2
Can the LIRE algorithm be adapted to handle categorical features or mixed-type data more effectively than current approaches? The paper mentions that datasets like Adult have mixed-type attributes, which are converted to one-hot encoding, but does not explore how LIRE handles categorical features natively or more efficiently. The paper focuses on numerical features and does not discuss or test LIRE's performance on categorical or mixed-type data.

### Open Question 3
How does the quality of counterfactual explanations generated by LIRE compare to those generated by human experts in real-world applications? The paper discusses the realism of CEs generated by LIRE, noting that they are guided towards high-density areas of input space, but does not compare them to human-generated CEs. The paper evaluates CEs based on distance metrics and feasibility but does not include qualitative assessments or comparisons to human judgments.

## Limitations
- The paper's claim about oblique forests having fewer live regions than axis-aligned forests relies on theoretical reasoning but lacks direct empirical validation
- The assumption that live regions correspond to realistic counterfactuals, while intuitive, lacks rigorous validation against human judgment or downstream task performance
- The relationship between forest architecture and live region count requires more systematic study

## Confidence

- Mechanism 1 (live region restriction): High confidence - directly supported by algorithmic description and basic complexity analysis
- Mechanism 2 (nearest-neighbor reduction for axis-aligned): High confidence - mathematical derivation is clear and verifiable
- Mechanism 3 (oblique efficiency): Medium confidence - theoretically sound but under-supported by direct evidence
