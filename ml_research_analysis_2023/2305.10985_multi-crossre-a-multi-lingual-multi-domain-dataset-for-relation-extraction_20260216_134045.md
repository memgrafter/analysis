# Multi-CrossRE A Multi-Lingual Multi-Domain Dataset for Relation Extraction

## Quick Facts
- arXiv ID: 2305.10985
- Source URL: https://arxiv.org/abs/2305.10985
- Reference count: 11
- Multi-lingual relation extraction dataset covering 27 languages and 6 domains with baseline results showing high translation quality

## Executive Summary
This paper introduces Multi-CrossRE, a multilingual dataset for relation extraction spanning 27 languages across 6 domains. The dataset is created by machine translating the English CrossRE dataset using DeepL's document markup translation capability, which preserves colored entity spans. A baseline relation classification model is trained and evaluated on the dataset, with results showing high quality of the translation. The authors provide a comprehensive analysis including manual checks on 210 sentences across 7 languages and back-translation validation to English.

## Method Summary
The authors create Multi-CrossRE by machine translating the English CrossRE dataset to 26 additional languages using DeepL's document markup translation capability. Entity spans are preserved through colored text formatting, with only trailing punctuation stripped during post-processing. A relation classification model using XLM-R large is trained on each translated dataset with 5 random seeds. Model performance is evaluated on test sets and back-translations to English, with manual quality checks performed on 210 sentences across 7 languages.

## Key Results
- Multi-CrossRE covers 27 languages and 6 domains, enabling multilingual relation extraction research
- Manual checks on 210 sentences across 7 languages show high translation quality with preserved entity boundaries
- Back-translation to English yields consistent performance with original CrossRE, validating translation quality
- Japanese shows the lowest performance due to significant entity boundary errors in translation

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Machine translation with preserved entity markup yields high-quality relation extraction datasets across languages
- Mechanism: DeepL's document markup translation capability allows direct transfer of colored entity spans from source to target text, avoiding complex span-mapping algorithms
- Core assumption: Entity spans do not overlap and entity boundaries remain stable enough during translation
- Evidence anchors:
  - [abstract]: "high quality of the translation and the resulting dataset"
  - [section]: "capitalizes on the fact that DeepL... is capable of translating document markup"
  - [corpus]: Found 25 related papers with average FMR 0.491, indicating moderate relatedness but limited direct replication evidence
- Break condition: If entity spans overlap or translation alters entity boundaries significantly, the approach fails

### Mechanism 2
- Claim: Back-translation to English serves as effective quality control for multilingual datasets
- Mechanism: Training and evaluating models on back-translated data and comparing results with original English data reveals translation quality
- Core assumption: Performance consistency between back-translated and original data indicates translation quality
- Evidence anchors:
  - [abstract]: "Results on the back-translated data are consistent with the ones on the original English CrossRE"
  - [section]: "As a sanity check, we back-translated the data... train and evaluate new models on this data"
  - [corpus]: Moderate corpus relatedness (FMR 0.491) suggests this approach is novel but not widely validated
- Break condition: Large performance gaps between back-translated and original evaluations indicate translation issues

### Mechanism 3
- Claim: Simple post-processing (stripping trailing punctuation) suffices for entity boundary correction
- Mechanism: Removing punctuation not present in original entity boundaries corrects most translation artifacts
- Core assumption: Translation primarily adds punctuation to entity boundaries rather than restructuring them
- Evidence anchors:
  - [section]: "the only post-processing we apply is to strip from each translated entity any trailing punctuation"
  - [section]: "Japanese is the one suffering the most by the translation process"
  - [corpus]: Limited corpus evidence on punctuation-specific translation artifacts
- Break condition: If translation fundamentally restructures entity boundaries beyond punctuation, post-processing fails

## Foundational Learning

- Concept: Span-based annotation transfer
  - Why needed here: The dataset contains annotated entity spans that must be preserved across translation
  - Quick check question: What happens to entity boundaries when text is machine translated?

- Concept: Back-translation as quality validation
  - Why needed here: Provides objective measure of translation quality by comparing model performance on back-translated vs original data
  - Quick check question: How does performance on back-translated English compare to original English data?

- Concept: Language distance metrics
  - Why needed here: Helps understand expected performance differences across languages based on linguistic similarity to English
  - Quick check question: What is the lang2vec distance between English and the target language?

## Architecture Onboarding

- Component map:
  Source dataset (CrossRE) → Machine translation (DeepL) → Target datasets (26 languages) → Model training → Evaluation
  Quality control loop: Target datasets → Back-translation → Model training → Comparison with original

- Critical path:
  1. Translate source dataset with entity markup preservation
  2. Apply post-processing (punctuation stripping)
  3. Train baseline model on translated data
  4. Back-translate to English
  5. Train and evaluate model on back-translated data
  6. Compare performance with original English baseline

- Design tradeoffs:
  - Simplicity vs accuracy: Using DeepL's built-in markup translation vs complex span-mapping algorithms
  - Cost vs quality: Manual vs machine translation
  - Evaluation complexity: Single-language vs multilingual evaluation

- Failure signatures:
  - Large performance gaps between back-translated and original evaluations
  - High entity boundary error rates in manual analysis
  - Languages with significantly lower scores than expected based on lang2vec distance

- First 3 experiments:
  1. Translate 100 sentences from CrossRE to a target language and verify entity preservation
  2. Train baseline model on translated data and evaluate on held-out translated test set
  3. Back-translate translated test set and evaluate model trained on back-translated data

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the quality of relation extraction performance vary across different language families and linguistic distances from English?
- Basis in paper: [explicit] The paper reports that the lang2vec distance is not informative of the quality of individual translations (Pearson's correlation −0.59) and that Japanese, which has the largest lang2vec distance with respect to English (0.41), suffers the most in translation quality.
- Why unresolved: The paper only reports overall performance trends and does not provide a detailed analysis of how performance varies across different language families or specific linguistic features.
- What evidence would resolve it: Detailed performance analysis of relation extraction across different language families, correlation analysis between performance and specific linguistic features (e.g., morphological complexity, syntactic structure), and comparison of performance across languages with similar lang2vec distances but different linguistic characteristics.

### Open Question 2
- Question: What are the limitations of using machine translation for relation extraction datasets with span-based annotations, and how can these limitations be addressed?
- Basis in paper: [explicit] The paper discusses the challenges of transferring entity boundaries during translation and mentions that the Relation Classification model is not much influenced by this type of error due to the injected entity markers.
- Why unresolved: The paper does not provide a comprehensive analysis of the limitations of using machine translation for relation extraction datasets with span-based annotations or propose solutions to address these limitations.
- What evidence would resolve it: Detailed analysis of the types of errors that occur during machine translation of span-based annotations, evaluation of the impact of these errors on relation extraction performance, and exploration of post-processing techniques or alternative approaches to improve the quality of machine-translated datasets.

### Open Question 3
- Question: How does the performance of relation extraction models trained on machine-translated data compare to models trained on manually translated data?
- Basis in paper: [explicit] The paper presents baseline results on the machine-translated MULTI-CROSSRE dataset and compares them to the original CrossRE dataset, but does not include a comparison with manually translated data.
- Why unresolved: The paper does not provide a direct comparison between the performance of relation extraction models trained on machine-translated data and those trained on manually translated data.
- What evidence would resolve it: Training and evaluating relation extraction models on a manually translated version of the CrossRE dataset and comparing their performance to models trained on the machine-translated MULTI-CROSSRE dataset.

## Limitations
- Limited manual quality verification covering only 210 sentences across 7 languages, insufficient for comprehensive validation
- No detailed analysis of domain-specific translation challenges across the 6 domains in CrossRE
- Assumes entity boundaries remain stable during translation without comprehensive boundary error analysis

## Confidence
- **High Confidence**: The basic translation methodology using DeepL's document markup preservation is technically sound and the manual verification process is clearly described.
- **Medium Confidence**: The claim about "high quality" of the resulting dataset is supported by limited manual checks (7 languages) and back-translation performance, but lacks comprehensive validation across all target languages.
- **Low Confidence**: The assertion that this approach can be "applied to other similar cases" without modification is not empirically validated beyond the specific CrossRE dataset and may not generalize to datasets with different annotation schemes or entity types.

## Next Checks
1. **Comprehensive Entity Boundary Validation**: Manually verify entity boundary preservation across all 26 target languages using a stratified sample of sentences from each domain, focusing on languages with reported difficulties (Japanese, Chinese, Korean).

2. **Domain-Specific Translation Quality Analysis**: Evaluate translation quality separately for each of the 6 domains in CrossRE to identify whether certain domains (e.g., scientific vs. general) exhibit systematically different translation quality patterns.

3. **Cross-Dataset Generalization Test**: Apply the same translation methodology to a different relation extraction dataset with varying entity types and annotation schemes to assess the approach's generalizability beyond CrossRE.
