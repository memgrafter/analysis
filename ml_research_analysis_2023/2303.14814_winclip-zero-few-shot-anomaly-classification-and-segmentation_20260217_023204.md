# WinCLIP: Zero-/Few-Shot Anomaly Classification and Segmentation

## Quick Facts
- arXiv ID: 2303.14814
- Source URL: https://arxiv.org/abs/2303.14814
- Reference count: 40
- Zero-shot classification AUROC: 91.8% on MVTec-AD, 85.1% on VisA

## Executive Summary
This paper introduces WinCLIP and WinCLIP+, methods for zero-/few-shot anomaly classification and segmentation in industrial quality inspection. WinCLIP uses a compositional prompt ensemble and efficient multi-scale feature extraction from CLIP for zero-shot anomaly segmentation. WinCLIP+ extends this by incorporating reference normal images for few-shot settings. Experiments on MVTec-AD and VisA benchmarks show WinCLIP achieves 91.8%/85.1% AUROC for zero-shot classification/segmentation, and WinCLIP+ achieves 93.1%/95.2% AUROC for 1-shot classification/segmentation, outperforming prior methods.

## Method Summary
WinCLIP addresses zero-shot anomaly detection through two key innovations: a compositional prompt ensemble (CPE) that combines state words and prompt templates to create rich textual descriptions of normal and anomalous states, and window-based feature extraction that obtains dense, language-aligned visual features suitable for pixel-level segmentation. WinCLIP+ extends this framework for few-shot settings by adding a reference association module that constructs memory banks from multi-scale features of normal images and retrieves the closest feature at each spatial location to score anomaly likelihood, which is then fused with the language-driven WinCLIP score via harmonic averaging.

## Key Results
- WinCLIP achieves 91.8% AUROC for zero-shot classification and 85.1% AUROC for zero-shot segmentation on MVTec-AD
- WinCLIP+ achieves 93.1% AUROC for 1-shot classification and 95.2% AUROC for 1-shot segmentation on MVTec-AD
- Outperforms prior methods including CLIP-AC, patch-token, and image tiling approaches across both benchmarks

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Compositional prompt ensemble improves anomaly classification by explicitly defining both normal and anomalous states with diverse state words and task-specific templates.
- Mechanism: The CPE constructs a comprehensive textual description of the two states by combining generic and task-specific descriptors. This ensemble of prompts captures a richer semantic space in CLIP's joint embedding, allowing better discrimination between normal and anomalous instances compared to simple two-class or one-class setups.
- Core assumption: CLIP's pre-trained vision-language alignment is sufficiently expressive to differentiate subtle semantic distinctions when provided with detailed state descriptions.
- Evidence anchors:
  - [abstract] states WinCLIP uses "a compositional ensemble on state words and prompt templates" and shows improved performance.
  - [section 4.1] explains the two-class design and demonstrates via Table 3 that adding state and prompt ensembles yields gains over naïve CLIP-AC.
  - [corpus] neighbors show follow-up works on CLIP-based zero-shot anomaly segmentation, indicating the prompt engineering direction is promising.
- Break condition: If CLIP's embedding space does not encode the semantic distinctions captured by the ensemble, or if prompts become too generic and lose specificity, performance degrades.

### Mechanism 2
- Claim: WinCLIP's window-based feature extraction provides dense, language-aligned visual features suitable for pixel-level anomaly segmentation.
- Mechanism: By applying sliding windows and extracting class-token embeddings from CLIP's image encoder, WinCLIP obtains local features that retain global context yet emphasize fine-grained details. These features are directly aligned with language due to the class-token supervision in CLIP pre-training, unlike penultimate patch features.
- Core assumption: The class token in CLIP's transformer architecture preserves rich local information while being aligned to text, enabling effective dense prediction.
- Evidence anchors:
  - [abstract] describes WinCLIP as extracting "efficient multi-scale feature extraction from CLIP" for segmentation.
  - [section 4.2] details the window-based extraction and explicitly compares it to penultimate features, noting better alignment.
  - [section 5.4 Table 8] confirms WinCLIP outperforms patch-token and image tiling baselines in accuracy and efficiency.
- Break condition: If the class token's representation collapses local detail or if window extraction is too coarse, segmentation quality suffers.

### Mechanism 3
- Claim: WinCLIP+ leverages few normal reference images through reference association, combining visual memory with language guidance for improved few-shot performance.
- Mechanism: WinCLIP+ constructs memory banks from multi-scale features of normal images and retrieves the closest feature at each spatial location to score anomaly likelihood. This visual-only component is then fused with the language-driven WinCLIP score via harmonic averaging, capturing both semantic context and reference-based normality.
- Core assumption: Normal images provide complementary visual cues that language alone cannot capture, especially for relative or context-dependent defects.
- Evidence anchors:
  - [abstract] states WinCLIP+ "uses complementary information from normal images" and shows large gains in 1-shot metrics.
  - [section 4.3] explains the reference association module and the aggregation of multi-scale predictions.
  - [section 5.4 Table 5] shows the combined ascore0 + maxMW improves over either alone, confirming complementarity.
- Break condition: If normal images are not representative or if the association fails to retrieve relevant features, the benefit diminishes.

## Foundational Learning

- Concept: Contrastive learning for vision-language models
  - Why needed here: CLIP's pre-training via contrastive loss aligns image and text embeddings, enabling zero-shot classification by similarity in joint space.
  - Quick check question: How does CLIP's contrastive loss ensure that "normal [object]" and images of normal objects are close in embedding space?

- Concept: Prompt engineering and ensemble methods
  - Why needed here: Crafting diverse textual prompts expands the semantic coverage of classes, allowing CLIP to better recognize varied manifestations of normal and anomalous states.
  - Quick check question: Why does a compositional ensemble of state words and templates outperform a single handcrafted prompt?

- Concept: Sliding window feature extraction for dense prediction
  - Why needed here: Standard CLIP outputs global features; WinCLIP adapts it for pixel-level tasks by extracting local embeddings that preserve spatial context.
  - Quick check question: How does the window size trade off between local detail and global context in anomaly segmentation?

## Architecture Onboarding

- Component map:
  - Prompt ensemble generator → Text encoder → Class embeddings (normal/anomalous)
  - Image encoder (CLIP backbone) + window extraction → Multi-scale dense features
  - Reference association module (for WinCLIP+) → Memory features from normal images
  - Scoring: similarity between image features and class embeddings
  - Aggregation: harmonic averaging across scales and (for WinCLIP+) language + visual scores

- Critical path:
  1. Generate compositional prompts → encode to text embeddings
  2. For each window/patch, extract image embedding from CLIP
  3. Compute similarity to text embeddings → anomaly score map
  4. (WinCLIP+) Retrieve nearest normal reference features → visual score map
  5. Fuse scores (harmonic averaging) → final classification/segmentation

- Design tradeoffs:
  - Window stride vs. computational cost: smaller stride increases accuracy but slows inference.
  - Scale selection: too few scales miss defect sizes; too many add overhead.
  - Prompt diversity vs. noise: more prompts can capture edge cases but may dilute signal.

- Failure signatures:
  - Low AUROC with high variance: prompts not aligned to task or window features not discriminative.
  - Segmentation maps too coarse: window size too large or stride too big.
  - Few-shot gains absent: reference association not retrieving relevant features or memory too sparse.

- First 3 experiments:
  1. Compare CLIP-AC with/without prompt ensemble on MVTec-AD zero-shot classification.
  2. Test WinCLIP vs. patch-token baseline on a simple anomaly segmentation task.
  3. Evaluate WinCLIP+ with 1-shot references vs. 0-shot WinCLIP on a defect type requiring visual context.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How does the performance of WinCLIP and WinCLIP+ scale with increasing numbers of normal reference images beyond 4-shots?
- Basis in paper: [inferred] The paper shows performance improvement from 0-shot to 4-shot settings but does not explore beyond 4-shots.
- Why unresolved: The paper only evaluates up to 4-shot settings and does not provide analysis on whether performance plateaus or continues to improve.
- What evidence would resolve it: Additional experiments testing WinCLIP+ with 8, 16, or 32 normal reference images to determine the optimal number of shots and potential performance saturation points.

### Open Question 2
- Question: Can the compositional prompt ensemble be automatically learned rather than manually curated?
- Basis in paper: [explicit] The paper mentions that CPE is manually constructed by combining state words and templates, but suggests future work could explore automatic learning.
- Why unresolved: The paper uses a fixed set of manually defined state words and templates without exploring data-driven or learned approaches to prompt generation.
- What evidence would resolve it: Development and evaluation of an automated system that learns optimal prompt combinations from data, comparing its performance against the manual CPE approach.

### Open Question 3
- Question: How does WinCLIP+ perform on industrial datasets with significantly different characteristics than MVTec-AD and VisA?
- Basis in paper: [inferred] The paper only evaluates on two specific industrial datasets without testing generalization to other industrial contexts.
- Why unresolved: The paper's experiments are limited to MVTec-AD and VisA benchmarks, which may not represent all types of industrial anomaly detection scenarios.
- What evidence would resolve it: Testing WinCLIP+ on additional industrial datasets with different object types, defect characteristics, and image resolutions to validate robustness across diverse manufacturing domains.

### Open Question 4
- Question: What is the computational efficiency trade-off between WinCLIP and other segmentation methods in real-time industrial applications?
- Basis in paper: [explicit] The paper mentions inference time measurements but doesn't provide comprehensive analysis of real-time deployment constraints.
- Why unresolved: While the paper compares inference times with some methods, it doesn't analyze how these methods perform under real-time industrial constraints like varying image resolutions and processing speeds.
- What evidence would resolve it: Detailed benchmarking of WinCLIP's performance under different hardware configurations, image resolutions, and processing speed requirements typical of industrial inspection systems.

## Limitations

- Prompt Ensemble Specificity: The exact composition of state words and templates in the compositional prompt ensemble is not fully specified, introducing variability in reproducing results.
- Reference Association Effectiveness: WinCLIP+ relies on representative normal images, but the paper does not extensively validate whether reference images are representative across all defect types.
- Scalability and Efficiency: While WinCLIP claims efficient multi-scale feature extraction, the computational overhead of window-based extraction and multi-scale aggregation is not fully quantified.

## Confidence

- **High Confidence**: The zero-shot classification performance of WinCLIP on MVTec-AD and VisA benchmarks (91.8% and 85.1% AUROC) is well-supported by the ablation studies and comparisons to CLIP-AC.
- **Medium Confidence**: The few-shot segmentation performance of WinCLIP+ (93.1% and 95.2% AUROC) is promising, but the reliance on representative normal images introduces uncertainty.
- **Low Confidence**: The claim of superior efficiency over patch-token and image tiling baselines is based on a single comparison table without comprehensive computational analysis.

## Next Checks

1. **Prompt Ensemble Sensitivity**: Conduct an ablation study varying the number and diversity of prompts in the compositional ensemble to quantify their impact on classification accuracy.

2. **Reference Image Representativeness**: Evaluate WinCLIP+ performance with varying numbers of normal reference images and across defect types that require visual context.

3. **Computational Efficiency Benchmarking**: Measure inference time and memory usage of WinCLIP and WinCLIP+ across different window sizes, strides, and scale settings to assess real-time viability.
