# GlowQ: Group-Shared LOw-Rank Approximation for Quantized LLMs
## Quick Facts
- **arXiv ID:** 2603.25385  
- **Source URL:** https://arxiv.org/abs/2603.25385  
- **Reference count:** 40  
- **Primary result:** GlowQ improves accuracy and cuts latency for low-bit quantized LLMs via group‑shared low‑rank correction and optional selective restoration.

## Executive Summary
GlowQ tackles the dual challenges of accuracy loss and computational overhead in low‑bit quantization of large language models. It introduces a group‑shared low‑rank correction that caches a single right projection matrix per input‑sharing group (e.g., Q, K, V or MLP), while each layer within the group learns a left factor. This reduces redundant matrix‑vector multiplications during inference. The method also employs a covariance‑aligned (whitened) objective to align the shared subspace with high‑variance input directions, mitigating quantization errors. An optional selective variant, GlowQ‑S, further optimizes latency and memory by restoring only the most beneficial groups under a given budget. Experiments show that GlowQ outperforms strong layer‑wise baselines, achieving lower perplexity (e.g., –0.17% on WikiText‑2) and better zero‑shot task accuracy (+0.42%), along with reduced time‑to‑first‑byte (5.6%) and higher throughput (9.6%). GlowQ‑S pushes efficiency further, cutting TTFB by 23.4% and boosting throughput by 37.4% with minimal accuracy drop (≤0.2 percentage points).

## Method Summary
GlowQ is a post‑training quantization (PTQ) technique that corrects errors introduced by low‑bit weight quantization via a low‑rank approximation that shares computation across modules. First, the model is quantized (e.g., to 4‑bit) using an existing PTQ method like GPTQ. During an offline calibration phase, activation statistics are collected to estimate the input covariance. Linear layers that share the same input tensor (e.g., the three projection matrices in an attention head) are grouped together. For each group (and for solo layers like output projections), the error matrix between full‑precision and quantized weights is computed. These errors are then approximated by a product of two factors: a group‑shared right factor \(B_{\text{shared}}\) and per‑layer left factors \(A_i\). The factorization is obtained by solving a weighted least‑squares problem where the weight is the input covariance (raised to 1/2), a formulation that steers the shared right subspace toward high‑variance directions. Specifically, the stacked error matrix is multiplied by \(\Sigma_x^{1/2}\) to produce a whitened matrix, whose top singular vectors yield the balanced factors; these are then split into the per‑layer left and group‑shared right factors. At inference, the shared right projection \(R = B_{\text{shared}} x\) is computed once per group, and each layer in the group adds its correction \(A_i R\) to the quantized output. Optional selective restoration (GlowQ‑S) ranks groups by importance (e.g., using GSVD energy or normalized error ratio) and applies the correction only to the top‑k groups under a budget, trading a small accuracy loss for significant latency and memory reductions.

## Key Results
- GlowQ improves accuracy over layer‑wise low‑rank baselines: perplexity reduced by 0.17% on WikiText‑2 and average zero‑shot task accuracy increased by 0.42%.
- Efficiency gains: time‑to‑first‑byte (TTFB) reduced by 5.6% and throughput increased by 9.6%.
- Selective variant GlowQ‑S achieves larger efficiency improvements: TTFB down 23.4%, throughput up 37.4%, with accuracy degradation ≤0.2 percentage points.

## Why This Works (Mechanism)
### Mechanism 1: Group‑shared projection reduces redundant matrix‑vector multiplications
Modules that share the same input (e.g., Q, K, V projections) compute separate projections \(W_i x\). GlowQ approximates each error \(E_i = W_i^{(fp)} - W_i^{(q)}\) as \(A_i B_{\text{shared}}\). Instead of computing each \(B_i x\) individually, the shared right projection \(R = B_{\text{shared}} x\) is computed once per group, and each module uses \(A_i R\). This eliminates repeated multiplications with the (typically tall) input dimension, replacing \(G\) separate \(d \times r\) matrix‑vector products with a single \(d \times r\) product and \(G\) smaller \(o \times r\) products. The core assumption is that modules within a group receive identical input tensors; this holds for standard transformer blocks where Q, K, V are computed from the same hidden state. The claim is supported by the paper’s description of caching the right factor and by the implementation details (Section 3.3). A break condition would be architectures where inputs to grouped modules are not identical, e.g., cross‑attention or conditional computation graphs.

### Mechanism 2: Covariance‑aligned (whitened) objective steers the shared subspace toward high‑variance directions
LLM activations are anisotropic, with heavy‑tailed eigenvalue spectra. Minimizing \(\|E - AB\|_F^2\) treats all input directions equally, but errors along high‑variance axes have larger impact on the output. GlowQ instead minimizes \(\mathbb{E}[\|(E - AB)x\|_2^2] = \|(E - AB)\Sigma_x^{1/2}\|_F^2\), where \(\Sigma_x\) is the centered input covariance. This right‑weighted formulation ensures the shared right factor \(B_{\text{shared}}\) aligns with the principal components of the input distribution. Concretely, the optimal \(B_{\text{shared}}\) is derived from the top right singular vectors of the whitened error matrix \(E \Sigma_x^{1/2}\). The paper’s theoretical derivation (Section 3.1.2) and empirical evidence (ablation in Section 4.7) anchors this mechanism. It depends on accurate estimation of \(\Sigma_x\) from a representative calibration set; if the covariance is poorly estimated (few samples or distribution shift) or nearly isotropic, the whitening adds little benefit and may even hurt.

### Mechanism 3: Selective restoration picks high‑payoff groups under a budget
GlowQ‑S further reduces latency and memory by applying the low‑rank correction only to a subset of groups. Groups are ranked by an importance metric—such as the GSVD energy (the squared singular values from the group’s factorization) or the normalized error ratio (frobenius norm of error divided by that of the quantized weight). Under a given budget (e.g., a maximum number of groups or a latency target), only the top‑k groups receive the correction; the rest rely solely on the quantized weights. The paper shows that a small fraction of groups already recovers most of the accuracy gain, yielding large efficiency wins (Section 4.6). The assumption is that not all groups contribute equally to quantization error. Break conditions include a poorly chosen metric or budget that discards critical groups, causing disproportionate accuracy degradation. The paper notes that different model families (LLaMA vs. Qwen) exhibit different selection patterns, requiring model‑specific tuning.

## Foundational Learning
### Post‑training quantization (PTQ)
**Why needed:** GlowQ operates on models that have already been quantized to low bit‑widths (e.g., 4‑bit) without retraining. Understanding PTQ explains the baseline that GlowQ improves upon and the nature of the quantization errors it corrects.

### Low‑rank approximation & SVD
**Why needed:** GlowQ models the weight error as \(E \approx AB\), where \(A\) and \(B\) are low‑rank factors. The optimal rank‑\(r\) approximation under Frobenius norm is given by the truncated SVD (Eckart–Young theorem), which underlies GlowQ’s factorization.  
**Quick check:** According to the Eckart‑Young theorem, what is the best rank‑\(r\) approximation of a matrix?

### Input covariance & whitening
**Why needed:** The covariance‑aligned objective weights the reconstruction error by the input covariance \(\Sigma_x\). Without this weighting, the shared right subspace might not align with directions that matter most for the model’s outputs. Understanding whitening clarifies why GlowQ multiplies by \(\Sigma_x^{1/2}\) before applying SVD.

## Architecture Onboarding
### Component map
Offline calibration: calibration sequences → activation capture per layer → covariance Σₓ estimation → group‑wise error stacking E_cat → whitening (E_cat Σₓ^{1/2}) → randomized SVD → balanced factors → split into per‑layer A_i and shared B_shared → factor storage.  
Runtime forward pass: input x → for each group g compute R = B_shared^{(g)} x → for each module i in group g compute corrected output = W_i^{(q)} x + A_i R → aggregate outputs → logits.

### Critical path
1. Load a calibration set (e.g., 64 sequences of length 2048) and run the quantized model to capture input activations X at target layers.  
2. Group linear layers that share the same input (e.g., q_proj/k_proj/v_proj; gate_proj/up_proj); solo layers (o_proj, down_proj) are treated individually.  
3. For each group/solo: center X, compute Σ = (1/|X|) XᵀX; add ridge εI for regularization; compute Σ^{1/2} via eigen‑decomposition.  
4. Stack error matrices E_i (full‑precision minus quantized) vertically for modules in a group → E_cat. Compute whitened matrix E_wh = E_cat · Σ^{1/2}.  
5. Apply QR‑reduced randomized SVD to E_wh to obtain top‑r right singular vectors V_r and singular values Σ_r. Form balanced factors: bA = U_r √Σ_r, bB = √Σ_r V_rᵀ. For groups, split bA into per‑module blocks; set B_shared = bB · Σ^{-1/2}. For solos, B_i = bB · Σ^{-1/2} directly.  
6. At inference initialization, load B_shared (or B_i) and A_i into device memory.  
7. During generation: for each group g, compute R = x · B_shared^{(g)ᵀ}. For each module i in that group, add correction A_i · Rᵀ to the quantized output W_i^{(q)} x. For solo layers, compute R = x · B_iᵀ and add A_i · Rᵀ.

### Design tradeoffs
- **Rank r**: Larger r improves accuracy (closer to full‑rank correction) but increases storage (∑ O_i r + r d) and compute (A_i R cost). Typically r ∈ {32, 64}.  
- **Calibration size N**: More samples stabilize Σₓ and E_cat; N = 32‑64 often suffices. Larger N increases offline time linearly.  
- **Selective restoration**: Choice of budget (fraction of groups restored) trades accuracy for latency/memory. Model‑specific curves (e.g., LLaMA vs. Qwen) guide selection; improper budget can cause steep accuracy drops.  
- **Randomized SVD parameters**: Oversampling p and power iterations q improve approximation quality but add setup cost; common defaults p ≈ r, q = 1.

### Failure signatures
- Sudden perplexity spike on validation: likely rank r too low, unrepresentative calibration data, or incorrect grouping (e.g., modules not truly sharing input).  
- No speedup vs. baseline: selective restoration disabled, or caching not implemented correctly (B_shared X recomputed per module instead of once).  
- Excessive memory usage: verify that group sharing actually reduces total factor count; check that B_shared is not duplicated per module.  
- Poor accuracy on specific downstream tasks: inspect per‑group importance scores; critical groups might have been deprioritized.

## Open Questions the Paper Calls Out
1. **Integration with rotation‑based PTQ and KV‑cache compression**: The authors suggest GlowQ is complementary to methods like ROSAQ, GuidedQuant, and CommVQ but leave empirical validation for future work. The interaction (potential conflicts) is unknown.  
2. **Automatic budget selection for selective restoration**: The paper uses model‑specific heuristics (elbow for LLaMA, fixed 50% for Qwen). A data‑driven method to choose the restoration fraction without exhaustive curve tracing is missing.  
3. **Relation between covariance‑aligned objective and downstream task performance**: The whitening objective is derived from an expected squared error loss, but downstream tasks may have different sensitivities. It is unclear whether weighting by input covariance always correlates with better task accuracy across diverse tasks.  
4. **Extension to dynamic computation graphs**: GlowQ assumes static grouping (e.g., Q, K, V always computed from same input). For models with variable sequence lengths, sparse attention, or conditional layer skipping, the caching strategy may need adaptation; this is not addressed.  
5. **Robustness to out‑of‑distribution calibration data**: The paper shows saturation with N≥64 samples on a single corpus (SlimPajama). Stability under domain‑shifted calibration (e.g., code data for text models) and theoretical justification for small calibration size require further study.

## Limitations
- **Calibration details unspecified**: The paper does not disclose the exact calibration dataset (C4 vs. WikiText), ridge regularization strength, or GPTQ hyperparameters, which may hinder exact reproduction and optimal performance.  
- **Covariance estimation for large layers**: The handling of massive solo‑layer covariances (e.g., `down_proj` with 4d input) is vague; approximations (diagonal vs. full) could affect the whitening objective and thus accuracy.  
- **Selective‑restore metric selection**: The importance metric (GSVD energy vs. normalized error ratio) appears to be chosen per model family without a clear rule, making automatic budget selection ambiguous.
