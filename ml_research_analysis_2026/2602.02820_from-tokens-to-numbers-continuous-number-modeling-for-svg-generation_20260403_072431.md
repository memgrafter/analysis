# From Tokens to Numbers: Continuous Number Modeling for SVG Generation

## Quick Facts
- arXiv ID: 2602.02820
- Source URL: https://arxiv.org/abs/2602.02820
- Reference count: 15
- Primary result: CNM reduces test sequence length by 54% and training time by 32% while improving SSIM (54.1% vs 48.5%) and DINOv2 similarity (42.5% vs 42.0%) over StarVector baseline.

## Executive Summary
The paper tackles the inefficiency of tokenizing numeric parameters in SVG generation, which inflates sequence length and harms model performance. It introduces Continuous Number Modeling (CNM), which separates SVG data into a token stream with `<NUM>` placeholders and a parallel continuous float sequence. A Fourier feature-based encoder/decoder within a multimodal transformer processes the two streams. After supervised pre-training, reinforcement learning with a composite perceptual reward (SSIM, LPIPS', DINOv2) fine-tunes the model. On the SVG-Stack dataset, CNM achieves a 54% reduction in test sequence length and a 32% reduction in training time compared to the StarVector baseline, while delivering higher visual fidelity (SSIM 54.1% vs 48.5%, DINOv2 42.5% vs 42.0%). Additionally, the proposed SVGFloat binary format shrinks file size by up to 42% relative to raw SVG with minimal fidelity loss.

## Method Summary
Preprocessing converts each SVG into two sequences: tokens with `<NUM>` placeholders and the corresponding numeric literals as floats. All floats are normalized to \([-1,1]\) using \(M=512\) after affine scaling to fit the canvas \([-512,512]^2\); SVGs that deviate after scaling (SSIM < 0.99) are filtered out. The model builds on Qwen2-VL-2B-Instruct. The NumberEncoder adds Gaussian noise during training, applies Fourier feature mapping \(\gamma(v) = [\sin(2^i\pi v), \cos(2^i\pi v)]_{i=0}^{k-1}\) with \(k=16\), then a two-layer MLP produces \(d\)-dimensional embeddings. The NumberDecoder is a symmetric MLP mapping hidden states at `<NUM>` positions back to de‑normalized floats. During fusion, image patch embeddings, token embeddings, and number embeddings are interleaved into a single sequence processed by the decoder backbone. Supervised fine‑tuning optimizes combined loss: cross‑entropy for tokens plus \(\lambda \cdot \text{MSE}\) for numbers (\(\lambda=10^{-5}\)) with noise scale \(\sigma=0.2/512\). Reinforcement learning (GRPO) then samples eight outputs per image, renders them, computes reward \(R = \alpha\!\cdot\!\text{DINOv2} + \beta\!\cdot\!\text{SSIM} + \gamma\!\cdot\!\text{LPIPS'}\) (\(\alpha=0.4,\beta=0.3,\gamma=0.3\)), and updates the policy with a KL constraint (target KL=0.001) relative to the SFT model. Inference proceeds autoregressively; when `<NUM>` is predicted, the NumberDecoder produces a float, which is clipped, rounded, and inserted. SVGFloat stores numerical values in binary rather than decimal text, yielding substantial compression.

## Key Results
- Test sequence length reduced by **54%** and training time by **32%** versus StarVector on SVG‑Stack.
- Visual quality improved: **SSIM 54.1%** (vs. 48.5%) and **DINOv2 similarity 42.5%** (vs. 42.0%).
- **SVGFloat** binary format cuts file size by up to **42%** with negligible fidelity loss.

## Why This Works (Mechanism)
1. **Digit-level tokenization inflates sequences**  
   Standard tokenizers (e.g., Qwen) break each number into multiple tokens (e.g., `123.456` → 7 tokens). This fragmentation increases memory usage and modeling difficulty without adding semantic value for geometric parameters. Continuous numerical representation preserves mathematical relationships and drastically reduces token count (4.67× compression per Table 1).  

2. **Disentangling symbolic structure from continuous numbers**  
   CNM processes the token stream (with `<NUM>` placeholders) and the float sequence in parallel. The transformer handles syntax while a Fourier‑enhanced MLP regresses numbers. Fourier feature mapping expands a single scalar into a high‑frequency space, making tiny differences (e.g., 123.45 vs 123.46) linearly separable; this improves geometric precision. Ablation (Table 5) shows Fourier mapping (0.53 SSIM) outperforms a simple linear projection (0.44 SSIM).  

3. **RL with a composite perceptual reward**  
   Supervised losses (CE, MSE) do not guarantee high perceptual similarity between rendered SVG and target image. RL fine‑tuning uses GRPO to maximize a reward that combines SSIM (low‑level structure), LPIPS' (learned perceptual similarity), and DINOv2 (high‑level semantics). The composite prevents over‑optimization of any single metric; full reward yields SSIM 0.54, better than SFT‑only (0.53) or individual components (Table 5).  

## Foundational Learning
- **Fourier Feature Mapping** – Maps a continuous scalar to a high‑dimensional sinusoidal basis. Simple linear layers lack frequency sensitivity, which is crucial for distinguishing fine geometric variations; the sinusoidal expansion makes small changes linearly separable. *Quick check: Why is a linear layer insufficient for embedding continuous numbers in SVG generation?*  
- **Multimodal Sequence Fusion** – Unifies three modalities (image patches, discrete tokens, continuous numbers) into one sequence for a transformer decoder. The order between `<NUM>` placeholders and their floats must be preserved exactly for correct generation. *Quick check: How does the model keep `<NUM>` tokens aligned with their corresponding float embeddings?*  
- **Reinforcement Learning from Non‑Differentiable Metrics** – Metrics like SSIM and DINOv2 are not differentiable w.r.t. SVG code. GRPO provides gradient estimates via policy gradients while a KL‑divergence constraint prevents the policy from drifting too far from the supervised model. *Quick check: What is the role of the KL‑divergence constraint in GRPO?*

## Architecture Onboarding
**Component map**  
1. SVG Pre‑processor – extracts numeric literals, replaces them with `<NUM>`, outputs parallel token/float sequences.  
2. Number Encoder – normalizes floats → (training only) adds Gaussian noise → Fourier mapping → two‑layer MLP → \(d\)‑dim embedding.  
3. Image Encoder – patch‑based vision encoder (from Qwen2‑VL) produces image embeddings.  
4. Fusion & Transformer – interleaves image, token, and number embeddings into one sequence processed by the decoder backbone.  
5. Number Decoder – at each `<NUM>` position, MLP transforms the hidden state to a de‑normalized float.  
6. SVG Consolidator – merges the generated token stream with decoded floats into a final SVG string.  
7. RL Reward Module – renders the predicted SVG, computes composite reward (SSIM, LPIPS', DINOv2) against the target image.

**Critical path**  
Training: `SVG → Pre‑processor → (tokens, floats) → Embeddings → Fusion → Transformer → (CE loss on tokens, MSE loss on <NUM> positions)`.  
RL: `Image → Generator (SFT model) → Sample SVGs → Render → Reward → GRPO update`.

**Design tradeoffs**  
- Fourier bandwidth \(k\): higher \(k\) increases sensitivity but also compute and dimensionality.  
- Loss weight \(\lambda\): balances CE and MSE; improper values destabilize training.  
- Precision: use `bfloat16` for backbone, `float32` for number modules to maintain numerical accuracy.

**Failure signatures**  
- Invalid SVGs: mismatched `<NUM>` count or syntax errors → check consolidation logic.  
- Numerical drift: predicted floats outside \([-M,M]\) → enforce clipping/rounding.  
- RL mode collapse: one reward component dominates → monitor all three during training.

**First 3 experiments**  
1. **Sequence compression verification** – Process SVG‑Stack samples; confirm average token reduction of ~4.67× vs default tokenizer.  
2. **Fourier ablation** – Replace Fourier mapping with a linear layer; train briefly; expect SSIM drop of ~0.09 (Section 3.4).  
3. **Reward isolation** – After SFT, run RL with only DINOv2, only SSIM, and only LPIPS' rewards; compare against full composite to observe synergy.

## Open Questions the Paper Calls Out
- **Optimality of Fourier features**: Only compared against a linear projection; not evaluated against other continuous encodings (e.g., learned embeddings, RBF networks). Systematic comparison is needed.  
- **Synergy of composite reward**: The weighted sum works best, but interactions among SSIM, LPIPS', and DINOv2 are unexplored; correlation and Pareto‑front analyses could clarify trade‑offs.  
- **Normalization constant \(M\)**: Fixed \(M=512\) may not generalize to datasets with different coordinate distributions; adaptive per‑SVG or dataset‑specific scaling might improve performance.  
- **Scalability to larger backbones**: All experiments use Qwen2‑VL‑2B; it is unclear whether gains hold for larger models (e.g., 7B) or different architectures (decoder‑only vs encoder‑decoder).  
- **Adoption of SVGFloat binary format**: Practical barriers (browser support, editor compatibility, conversion overhead) are not addressed; integration studies are required to assess real‑world feasibility.

## Limitations
- Reproducibility gaps: key details (Fourier mapping scaling/bias, GRPO KL penalty coefficient, reward normalization) are missing, hindering exact replication.  
- Baseline scope: only StarVector is compared; newer SVG generators (e.g., SVGBuilder, SVGFusion) are not evaluated, so relative standing is unclear.  
- Generalization: Experiments are limited to SVG‑Stack; performance on SVGs with gradients, filters, or text remains unknown.  
- Reward design: Fixed weights (\(\alpha=0.4,\beta=0.3,\gamma=0.3\)) lack sensitivity analysis, and how each metric is scaled to \([0,1]\) is unspecified.  
- Efficiency attribution: It is unclear how much of the 32% training speedup stems from shorter sequences versus overhead of the number modules.

## Confidence
- **54% sequence reduction & 32% training time reduction**: *Medium* (depends on implementation details and hardware).  
- **Improved SSIM (54.1% vs 48.5%) and DINOv2 (42.5% vs 42.0%)**: *Medium* (modest gains reported without statistical tests).  
- **Mechanistic explanations (Fourier mapping separation, RL reward synergy)**: *Medium* (ablations support components but alternative explanations not ruled out).  
- **SVGFloat binary format up to 42% compression**: *High* (arithmetic directly validated in experiments).

## Next Checks
- **Preprocessing verification** – Randomly sample 1,000 SVGs from SVG‑Stack; ensure every numeric literal is replaced by exactly one `<NUM>` and extract the correct corresponding floats; measure average token reduction (expect ~4.67× vs default tokenizer).  
- **Fourier mapping ablation** – Train two models on a fixed subset (e.g., 10k samples) for equal steps: one with Fourier encoder (k=16) and one with only a linear projection; compare SSIM and DINOv2; expect SSIM drop ~0.09 for the linear model.  
- **Reward weighting robustness** – From the same SFT checkpoint, run RL fine‑tuning with alternative weightings: (0.6,0.2,0.2), (0.2,0.4,0.4), and uniform (1/3,1/3,1/3). Evaluate final metrics to confirm optimality of (0.4,0.3,0.3) and monitor for dominance of any single component.
