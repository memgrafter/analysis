# Paper Reconstruction Evaluation: Evaluating Presentation and Hallucination in AI-written Papers

## Quick Facts
- **arXiv ID:** 2604.01128
- **Source URL:** https://arxiv.org/abs/2604.01128
- **Reference count:** 40
- **Primary result:** PaperRecon disentangles presentation quality and hallucination in AI-written papers, revealing a trade-off: ClaudeCode achieves higher presentation scores but more hallucinations than Codex.

## Executive Summary
This paper introduces Paper Reconstruction Evaluation (PaperRecon), the first systematic framework for evaluating the writing capability of AI agents on scientific papers. The core task is reconstruction: given a compressed overview and minimal resources (figures, tables, references, code) from an original paper, an agent generates a full paper. Evaluation separates two orthogonal dimensions—Presentation (rubric-based scoring of section content, figures, tables) and Hallucination (agentic extraction and verification of factual claims against the original). The PaperWrite-Bench benchmark contains 51 recent papers from top-tier venues. Experiments on Claude Code (Sonnet 4.6) and Codex (GPT-5.4) show a clear trade-off: ClaudeCode produces higher-quality writing but with over 10 hallucinations per paper, while Codex produces fewer hallucinations (~3) but lower presentation quality. The framework effectively tracks advances in AI writing ability.

## Method Summary
The pipeline begins with preprocessing an original paper into a structured `overview.md` (summarizing motivation, method, results) and minimal resources (extracted figures/tables, references with abstracts, code). An agent (Claude Code or Codex) then generates a full LaTeX paper from these inputs, with iterative compilation fixes. The generated paper is aligned with the original via section classification (7 categories) and matching. Evaluation proceeds in parallel: (1) rubric-based scoring uses GPT-5.4 to judge coverage of per-section key elements (1–5 scale); (2) hallucination detection first extracts all verifiable claims via LLM, classifying them as supported/neutral/contradictory, then a coding agent re-verifies contradictory claims against original resources; (3) citation metrics compare reference keys. Aggregation yields average rubric scores, hallucination counts, and citation scores.

## Key Results
- PaperWrite-Bench provides a standardized benchmark with 51 papers across ML, CV, NLP, and MM domains.
- Evaluation reveals a trade-off: ClaudeCode (Sonnet 4.6) achieves higher presentation quality (avg rubric score 3.86) but produces over 10 hallucinations per paper; Codex (GPT-5.4) produces fewer hallucinations (~3) but lower presentation quality (avg 3.59).
- Both models improve with newer versions (Sonnet 4 → 4.6, GPT-5 → 5.4), demonstrating the framework’s sensitivity to capability advances.

## Why This Works (Mechanism)
The framework isolates writing ability by removing research execution: the `overview.md` and minimal resources provide all necessary information, so failures in reconstruction reflect the agent’s generative and organizational skills. Evaluation disentangles presentation (how well content is articulated) from hallucination (factual consistency) via complementary methods: rubrics with concrete elements enable fine-grained scoring, while a two-stage claim extraction and verification process catches factual errors with high precision. Standardization via fixed section templates and controlled inputs ensures consistent, reproducible comparisons across agents and paper types, making the benchmark a reliable testbed.

## Foundational Learning
- **Orthogonal Evaluation Dimensions:** Separating presentation and hallucination avoids misleading conclusions—e.g., a paper can be well-written but factually wrong. Without this, a single metric might reward fluency over truthfulness.
  - *Quick check:* If an AI-generated paper scores high on clarity but contains fabricated results, is it high-quality? A single metric could conflate style with substance.
- **Rubric-Based vs. Holistic Assessment:** Concrete, element-wise rubrics (vs. a single score) reduce bias and detect subtle omissions by requiring explicit coverage of non-negotiable components like benchmark details or ablation studies.
  - *Quick check:* How does scoring specific elements (e.g., “experiment setup”) improve detection of missing or inaccurate information compared to an overall score?
- **Two-Stage Hallucination Detection:** Extracting all claims first ensures high recall; re-verification by an agent with ground-truth access improves precision by resolving false positives (e.g., neutral statements misclassified as contradictory).
  - *Quick check:* Why not let an LLM directly judge contradictions? Providing the original paper’s resources during re-verification allows evidence-based resolution of ambiguous cases.
- **Benchmark Construction for Writing Ability:** Unlike result-reproduction benchmarks, PaperWrite-Bench isolates the writing task via compressed inputs and fixed templates, enabling fair comparison across diverse paper structures.
  - *Quick check:* How does fixing the section structure (via `template.tex`) allow meaningful comparison when original papers have different organizations?
- **Trade-off Analysis in Capability Metrics:** Measuring both dimensions reveals that improving one may worsen the other—a crucial insight for developing balanced AI writers.
  - *Quick check:* If only presentation were measured, ClaudeCode might seem superior; if only hallucination, Codex might seem better. The trade-off shows neither is universally better.

## Architecture Onboarding
- **Component map:**  
  Preprocessing -> Agent Writing -> Section Matching -> Parallel Rubric Evaluation & Hallucination Detection -> Aggregation  
  (Rubric generation runs offline during benchmark construction.)
- **Critical path:** Preprocessing creates inputs; agent writes paper; sections are matched; rubrics are scored and hallucinations detected in parallel; results aggregated.
- **Design tradeoffs:**  
  - Resources are provided to isolate writing, but this assumes agents can use them effectively (real-world writing may require retrieval).  
  - Rubric generation combines automatic extraction (GPT-5.4) with author review to balance scalability and quality.  
  - Two-stage hallucination detection uses one agent invocation for efficiency, trading some thoroughness for cost.  
  - Fixed `template.tex` enables direct comparison but may force unnatural structures.
- **Failure signatures:**  
  - Low rubric scores across sections: check overview sufficiency and prompt adherence.  
  - High major contradictions in Method/Experiment: agent inventing details not in overview.  
  - Discrepancy between rubric and human scores: rubric may overweight coverage over readability.  
  - Section misclassification: unconventional section names may confuse classifier.  
  - Citation hallucination with low overall hallucinations: agent misusing citation keys.  
  - Persistent LaTeX errors: improve error parsing or feedback iterations.
- **First 3 experiments:**  
  1. Single-paper end-to-end run with ClaudeCode Sonnet4.6: verify section matching, rubric scoring, hallucination count (~10), and compilation success.  
  2. Overview length ablation: for 3–5 papers, compare default (~463 words) vs. long (~1492 words) overviews; expect longer overviews improve presentation and reduce hallucinations.  
  3. Trade-off confirmation: run 5 papers with both ClaudeCode and Codex; confirm ClaudeCode higher presentation (≥3.8) but more hallucinations (≥10), Codex lower presentation (≤3.6) but fewer hallucinations (≤3).

## Open Questions the Paper Calls Out
- **Question:** How does evaluation change when agents must retrieve resources instead of being given them?  
  *Basis:* Explicitly noted as future work. Current setup isolates writing; retrieval could introduce errors affecting both dimensions.  
  *Why unresolved:* Real-world writing often involves retrieval; testing this requires modifying the pipeline to include search, then comparing results.
- **Question:** Can rubric-based evaluation handle diverse writing styles across domains without losing discriminative power?  
  *Basis:* Acknowledged limitation; rubrics derived from specific papers may penalize valid stylistic variations.  
  *Why unresolved:* Different fields have different conventions; applying the rubric broadly and correlating with expert judgments would test its generality.
- **Question:** What explains the trade-off between presentation quality and hallucination rate?  
  *Basis:* Inferred from consistent experimental results: ClaudeCode high presentation/high hallucinations, Codex opposite.  
  *Why unresolved:* The paper does not analyze whether this stems from model architecture, training, decoding, or uncertainty calibration; understanding could guide balanced system design.
- **Question:** How reliable are LLM-based evaluators across all domains?  
  *Basis:* Human validation covered only small subsets (72 paper pairs for presentation, 97 claims for hallucinations). Full benchmark relies on LLM judges without extensive verification.  
  *Why unresolved:* Domain biases or inconsistent scoring by LLM judges could skew overall results; full-scale human evaluation is needed to confirm precision/recall.

## Limitations
- Agent configuration details (API endpoints, model names, hyperparameters) are unspecified, hindering exact replication.
- Prompt engineering specifics are only exemplified, not fully documented, introducing potential variance.
- Manual verification of `overview.md` sufficiency for each paper is a scalability bottleneck.

## Confidence
- **Claim: PaperRecon isolates writing ability from research execution.** Confidence: High  
  *Basis:* Design explicitly removes data/experiment requirements; fixed inputs focus evaluation on generation.
- **Claim: Presentation and Hallucination are orthogonal dimensions.** Confidence: Medium  
  *Basis:* Human validation shows moderate correlation for rubrics and high precision for hallucination detection, but rubric elements might inadvertently capture factual accuracy.
- **Claim: ClaudeCode trades higher presentation for more hallucinations vs. Codex.** Confidence: High  
  *Basis:* Direct experimental finding across multiple papers and model versions; effect size is substantial and consistent.
- **Claim: Two-stage hallucination detection is effective.** Confidence: Medium  
  *Basis:* 96% precision from human validation; however, recall is unmeasured, and Stage 2 agent might miss subtle contradictions.

## Next Checks

2. **Quantify prompt sensitivity:** For 3–5 papers, vary the writing agent’s system prompt (e.g., instructions on figure placement); measure changes in rubric scores and hallucination counts to assess stability.
3. **Audit section matching accuracy:** Manually inspect classification for 10 random papers; compute error rate for misaligned sections; if >5%, refine keyword/LLM rules and re-evaluate.
