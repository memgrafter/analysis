# ORBIT: Scalable and Verifiable Data Generation for Search Agents on a Tight Budget
## Quick Facts
- **arXiv ID**: 2604.01195
- **Source URL**: https://arxiv.org/abs/2604.01195
- **Reference count**: 40
- **Primary result**: ORBIT-4B (Qwen3-4B with GRPO) achieves state-of-the-art among sub-4B models, averaging 49.1 exact match across 7 Wikipedia QA benchmarks (up to 9.0 points above baselines) and scores 24.2 EM on FRAMES.

## Executive Summary
Training search agents for deep research requires multi-step retrieval and reasoning, but existing approaches rely on costly human annotation or restrictive synthetic data pipelines. ORBIT introduces a frugal, prerequisite-free framework that generates 20K reasoning-intensive QA pairs across 15 domains using only free tools and without paid APIs. The four-stage process leverages Wikipedia categories for seeds, a search-enabled DeepSeek-V3.1 to produce inverted questions and answers, self-verification, and cascading external verification via LLM judges with scraped web content. Training Qwen3-4B with GRPO on this data yields strong performance, demonstrating that high-quality synthetic data for search agents can be produced at minimal cost.

## Method Summary
ORBIT constructs a synthetic training dataset via four sequential stages. First, broad domains are expanded into Wikipedia category lists using Deep Research; linked page titles from these categories serve as seed entities. Second, a search-enabled DeepSeek-V3.1 generates inverted questions (where the answer is known but the question is crafted to require multi-hop reasoning) and concise answers, along with a verification checklist and evidence URLs. Third, the same model re-searches each pair and discards those where any atomic fact cannot be verified. Fourth, external validation uses two independent LLM judges (Qwen3-4B-Instruct and gpt-oss-120b) that answer the question using only scraped content from the provided URLs; only pairs agreeing with the gold answer in both rounds survive. The final dataset is mixed with single-hop examples (NQ, HotpotQA) and a Qwen3-4B agent is trained with Group Relative Policy Optimization (GRPO) using a verifiable exact-match reward and a search tool (DDGS).

## Key Results
- ORBIT-4B averages 49.1 EM across 7 Wikipedia QA benchmarks, improving up to 9.0 points over prior sub-4B models.
- On the out-of-distribution FRAMES benchmark, ORBIT-4B achieves 24.2 EM.
- The pipeline generates 20K high-quality pairs without paid APIs, enabling scalable data creation on a tight budget.

## Why This Works (Mechanism)
### Mechanism 1: Wikipedia category seeds enable scalable and diverse question generation
The pipeline uses OpenAI’s Deep Research to enumerate Wikipedia categories for chosen domains, then queries the MediaWiki API to harvest linked page titles as seeds. These seeds act as factual anchors for generating inverted questions that require chaining multiple facts. The core assumption is that Wikipedia’s category graph covers both popular and long-tail topics adequately. Break condition: If Wikipedia’s coverage is biased or incomplete in a domain, seed diversity suffers, leading to homogeneous or shallow questions.

### Mechanism 2: Self-verification filters low-quality pairs cheaply
The same search-enabled DeepSeek-V3.1 that generated the QA pair re-evaluates it by conducting fresh searches (up to 50 documents) and checking whether the answer satisfies every atomic fact. Pairs with unverified or weakly supported answers are discarded, retaining 61.5% of the original set. Core assumption: The model can accurately introspect on factual sufficiency when given new search results. Break condition: Model overconfidence or systematic blind spots (e.g., failing to find contradictory evidence) may allow incorrect pairs to pass.

### Mechanism 3: Cascading external verification reduces self-bias and ensures ground-truth alignment
After self-verification, the evidence URLs are scraped. Two independent LLM judges (Qwen3-4B-Instruct and gpt-oss-120b) each generate an answer using only the scraped content and compare it to the gold answer. Only pairs that pass both judges are kept. Core assumption: The judges’ error modes are uncorrelated, so consensus improves reliability. Break condition: Shared systematic biases across judges or poor scraping quality (paywalls, dynamic content) can still let incorrect pairs through.

## Foundational Learning
- **Reinforcement Learning with Verifiable Rewards (GRPO)**: Why needed? ORBIT-4B is trained with GRPO where the reward is exact match against the gold answer. This incentivizes the model to produce correct final answers after multi-hop search, rather than merely plausible reasoning. Quick check: How does a verifiable reward shape an agent’s exploration during rollouts compared to a learned reward model?
- **Multi-hop Reasoning**: Why needed? ORBIT questions require 4–6 reasoning steps; the agent must chain multiple search calls and synthesize evidence. Quick check: What distinguishes a multi-hop question from a single-hop one in terms of evidence dependencies?
- **Search-Augmented LLMs (Tool Use)**: Why needed? The agent interleaves `search>` actions. The framework assumes the search tool returns relevant snippets that the model can reason over. Quick check: How does the prompt template enforce a plan-search-answer loop rather than a monolithic generation?

## Architecture Onboarding
- **Component map**: Seed Pipeline → Q&A Generator (DeepSeek-V3.1 with search) → Self-Verifier (same model) → External Verifier (web scraper → Qwen3-4B-Instruct → gpt-oss-120b cascade) → Dataset Mixing (with NQ/HotpotQA) → GRPO Training (Qwen3-4B + DDGS) → Evaluation (BGE-M3 retrieval + EM)
- **Critical path**: Seed creation → Q&A generation → self-verification → external verification → dataset mixing → GRPO training → evaluation. The two verification stages are quality gates; failure at either reduces final dataset size and quality.
- **Design tradeoffs**: 
  - Cost vs. quality: No paid APIs → reliance on free but less stable DDGS and manual Selenium scripting; slower generation but accessible.
  - Openness vs. reproducibility: Using transient model versions (DeepSeek-V3.1) and free search introduces variability; mitigated by releasing intermediate artifacts.
  - Bias vs. efficiency: Self-verification is cheap but risks self-approval; external verification with two judges is costlier but reduces bias.
- **Failure signatures**: 
  - High drop rate after self-verification (<50%) indicates generation quality issues or overstrict verification prompt.
  - Verification URLs dominated by a single source (e.g., >90% Wikipedia) suggests questions lack multi-source diversity.
  - Training EM plateaus early or diverges could signal reward hacking (e.g., gaming EM without real search) or dataset mixing imbalance.
- **First 3 experiments**:
  1. **Seed diversity ablation**: Sample seeds from only high-traffic Wikipedia categories vs. long-tail categories; measure resulting question complexity and domain coverage.
  2. **Verification stage swap**: Replace cascading external judges with a single judge (either Qwen3-4B or gpt-oss-120b) and compare final dataset accuracy on a held-out verification set.
  3. **Dataset mixing sensitivity**: Train with ORBIT-only vs. ORBIT+NQ+HotpotQA at varying ratios (1:0:0, 1:1:1, 1:2:4) to validate the claim that single-hop pairs are necessary "learning steps" for small models.

## Open Questions the Paper Calls Out
- **Question**: Does using paid search APIs instead of free aggregators improve synthetic data quality and downstream agent performance?  
  *Basis*: Section 6 identifies "access to paid search APIs" as a necessary extension.  
  *Unresolved*: ORBIT exclusively uses free DDGS; the impact of paid APIs remains unevaluated.  
  *Resolution*: Compare agents trained on datasets from free vs. paid search APIs on deep search benchmarks.

- **Question**: Does incorporating a get_document tool (full page retrieval) enhance synthetic data quality and agent performance?  
  *Basis*: Section 6 lists "an additional get_document tool" as needed.  
  *Unresolved*: The current pipeline uses snippets only; benefits of full documents are unknown.  
  *Resolution*: Compare ORBIT variants with and without full document retrieval, measuring agent performance.

- **Question**: For ≥30B models, does supervised fine-tuning before reinforcement learning improve search agents trained on synthetic data?  
  *Basis*: Section 6 proposes "a larger base model combined with SFT warm-up followed by RL fine-tuning".  
  *Unresolved*: The 4B model used RL-only; scalability to larger models is untested.  
  *Resolution*: Train a >30B model on ORBIT with RL-only vs. SFT+RL and compare results.

## Limitations
- Wikipedia category seeds may omit niche or emerging domains, limiting question diversity.
- Self-verification can miss subtle factual errors, allowing incorrect pairs to persist.
- Cascading external verification may still be affected by correlated judge biases and unstable web scraping (paywalls, dynamic content).
