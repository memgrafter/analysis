# O-Researcher: An Open Ended Deep Research Model via Multi-Agent Distillation and Agentic RL

## Quick Facts
- **arXiv ID:** 2601.03743
- **Source URL:** https://arxiv.org/abs/2601.03743
- **Reference count:** 40
- **Primary result:** O-Researcher-RL achieves SOTA on DeepResearch Bench among open-source models with a RACE score of 48.48, surpassing proprietary agents like Perplexity Deep Research.

## Executive Summary
O-Researcher is an open-source deep research model that bridges the performance gap with closed-source systems. It automatically synthesizes high-quality training data through a multi-agent parallel workflow that decomposes queries into tool-integrated subtasks and aggregates reports. A two-stage training strategy—supervised fine-tuning followed by reinforcement learning with a composite reward—then optimizes the model for balanced report quality, tool usage, and formatting. Starting from Qwen-2.5-72B-Instruct, the final RL model attains state-of-the-art results on deep research benchmarks, demonstrating strong capabilities in comprehensiveness, insight, and citation accuracy.

## Method Summary
The method comprises two core phases. First, a multi-agent parallel workflow synthesizes training trajectories: a planner decomposes a query into orthogonal subtasks; independent agents perform multiple rounds of think-plan-tool-observation for each subtask; a summarizer aggregates sub-reports. This produces end-to-end, tool-integrated reasoning data. Second, the base model undergoes supervised fine-tuning on these trajectories to internalize the workflow, followed by reinforcement learning with GRPO. The RL reward combines an LLM-as-a-Judge score (RACE dimensions), a tool-usage incentive (2–8 calls), and a formatting reward (XML closure, `<suggested_answer>` tag), balancing comprehensiveness with factual rigor.

## Key Results
- Achieves a RACE score of 48.48 on DeepResearch Bench (vs. 33.38 for the base model), surpassing Perplexity Deep Research and rivaling leading closed-source systems.
- Attains perfect clarity (100.00) and near-perfect insight (99.3) on DeepResearchGym.
- Records the highest citation precision (51.45); RL improves citation accuracy (29.13%→31.99%) and effective citations (22.63→26.01).

## Why This Works (Mechanism)
### Mechanism 1: Multi-Agent Parallel Trajectory Synthesis
Parallel decomposition and multi-agent execution produce high-fidelity, diverse training trajectories that capture complex tool-integrated reasoning. A planner decomposes queries into orthogonal subtasks; independent agents conduct multiple rounds of think-plan-tool-observation; a summarizer aggregates sub-reports, simulating peer-review. This mitigates context window limits and avoids sequential dependency issues.  
*Evidence:* Abstract and section describe the parallel workflow; Chain-of-Agents (arXiv:2508.13167) supports multi-agent efficacy.  
*Break condition:* Non-orthogonal subtasks cause context competition; poor summarization degrades coherence.

### Mechanism 2: Two-Stage Training with Composite Reward
SFT initializes the model with the research workflow from synthetic trajectories. RL with GRPO then optimizes using a composite reward: *R* = 0.6·*R*<sub>base</sub> + 0.2·*R*<sub>tool</sub> + 0.2·*R*<sub>format</sub>, where *R*<sub>base</sub> is an LLM-as-a-Judge score on RACE dimensions, *R*<sub>tool</sub> incentivizes 2–8 tool calls, and *R*<sub>format</sub> enforces XML structure. This balances comprehensiveness, factual rigor, and behavior constraints.  
*Evidence:* Abstract and reward design section specify weights and components.  
*Break condition:* Mis-specified weights cause extreme tool spam or reward hacking; LLM judge misalignment leads to poor optimization.

### Mechanism 3: Quality Assurance and Structured Representation
A multi-stage rejective sampling pipeline (diverse generation, rule-based filter, LLM-as-judge semantic filter, human spot-checking) ensures high data fidelity. Trajectories are serialized with an XML-style schema (`<subtask_list>`, `<think>`, `<plan>`, `<web_search>`, `<crawl_page>`, `<observation>`, `<subtask_answer>`, `<suggested_answer>`), inducing the desired behavior during SFT.  
*Evidence:* Abstract mentions rigorous pipeline; section details tags and filtering steps.  
*Break condition:* Overly strict filtering reduces dataset diversity; inconsistent tag usage confuses the model.

## Architecture Onboarding
**Component map:**  
Data Synthesis: Planner -> Parallel Subtask Agents (with tools) -> Summarizer -> Trajectory Collector -> QA Pipeline (diversity generation, rule filter, model filter, human verification)  
Training: Base LLM -> SFT Trainer -> RL Trainer (GRPO + Reward Calculator: LLM-as-a-Judge for RACE, citation metrics, tool counter, format validator) -> Final Model  
Inference: Model with structured decoding to produce XML-tagged responses and invoke tools.

**Critical path:**  
1. *Data generation:* Query → Planner → Orthogonal subtasks → Parallel agents (multiple think-plan-tool-observation cycles) → Sub-reports → Summarizer → Trajectory & report → Quality assurance → SFT dataset.  
2. *Model training:* Base LLM → SFT on dataset → RL with GRPO (rollouts, reward calculation, policy update) → Final model.

**Design tradeoffs:**  
- Parallelism vs. cost: More agents reduce wall-clock time but increase compute and risk inconsistency across sub-reports.  
- Reasoning steps: More steps (e.g., 20 vs. 10) improve depth but increase context length and token costs; paper found 10 optimal.  
- Reward weights: Adjusting *w*<sub>1</sub>, *w*<sub>2</sub>, *w*<sub>3</sub> changes emphasis; higher *w*<sub>2</sub> may cause tool spam.  
- Filtering thresholds: Stricter rules yield higher quality but smaller dataset; balance needed.

**Failure signatures:**  
- SFT: Model fails to generate required XML tags or tool calls; outputs incoherent.  
- RL: Reward collapse, excessive tool calls, or degenerate long outputs with low substance.  
- Data pipeline: Human verification bottleneck; high rejection rate leading to insufficient training data.

**First 3 experiments:**  
1. *Parallel vs. Sequential:* Compare agent workflows on a fixed query set; measure RACE comprehensiveness and insight. Expect parallel to outperform.  
2. *SFT vs. SFT+RL:* Train ablations; compare citation accuracy (FACT) and effective citations. Expect RL to improve factual metrics while maintaining quality.  
3. *Reward Ablation:* Vary *w*<sub>1</sub> (quality) and *w*<sub>2</sub> (tool usage); observe tool call counts and RACE scores. Expect balanced weights to yield best overall.

## Limitations
- **Generalizability:** Performance validated only on DeepResearch Bench/Gym; unknown if methods transfer to other domains or tool ecosystems.
- **Reward Design:** Reliance on LLM-as-a-Judge and fixed linear weighting risks misalignment; no ablation showing robustness to weight perturbations.
- **Data Pipeline:** Human spot-checking scale/extent unclear; potential bottleneck limits dataset diversity. Cost of parallel synthesis high but not quantified.

## Confidence
- **SOTA claims (RACE 48.48, surpassing Perplexity):** High — benchmark scores specific but limited to cited test sets.
- **Multi-agent parallel workflow efficacy:** Medium — supported by internal results and Chain-of-Agents analogy; break conditions (subtask dependencies) not tested.
- **Composite reward balancing:** Medium-Low — ablations on reward components absent; LLM judge consistency unknown.
- **Quality assurance pipeline:** Medium — process described but trade-offs (filter strictness vs. diversity) lack empirical analysis.

## Next Checks
1. **Orthogonality Stress Test:** Intentionally introduce dependencies across subtasks (shared entities/contexts) and measure degradation in RACE comprehensiveness/insight vs. orthogonal baseline.
2. **Reward Ablation Study:** Systematically vary \(w_1, w_2, w_3\) (including extreme values) and track tool call frequency, citation accuracy, and report coherence to identify failure modes.
3. **Out-of-Domain Generalization:** Evaluate O-Researcher-RL on a held-out research domain (e.g., biomedical or legal queries) with different tool suites to measure cross-domain transfer and tool-agnostic reasoning.
