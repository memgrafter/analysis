# LEA: Label Enumeration Attack in Vertical Federated Learning

## Quick Facts
- arXiv ID: 2603.03777
- Source URL: https://arxiv.org/abs/2603.03777
- Reference count: 37
- Primary result: LEA achieves 50%-90% higher attack accuracy than prior state-of-the-art, works with logistic regression and neural networks, and remains effective against gradient noise and compression defenses.

## Executive Summary
This paper introduces the Label Enumeration Attack (LEA), a novel threat to label privacy in Vertical Federated Learning (VFL). Unlike prior attacks, LEA enables a passive party to infer the active party’s labels without any auxiliary data, applicable to both aggregated VFL (AggVFL) and split VFL (SplitVFL). The attack leverages unsupervised clustering on the adversary’s local features to generate candidate label mappings, then simulates models for each mapping and identifies the true one by comparing cosine similarity of first-round loss gradients with those from benign VFL training. A binary variant, Binary-LEA, reduces computational complexity from factorial to cubic, making the attack feasible for many-class scenarios. Empirical results on real datasets demonstrate significant improvements in attack success rate over existing methods and resilience to common gradient-based defenses.

## Method Summary
LEA proceeds in four main stages: First, the passive party clusters its local feature matrix into *n* clusters (where *n* is the number of classes), creating candidate label-to-cluster assignments. Second, it enumerates all *n!* permutations of these assignments (or uses Binary-LEA’s pairwise approach for *O(n³)* complexity) to construct simulated labeled datasets. Third, for each permutation, a duplicate of the local model (and a simulated top model for SplitVFL) is trained for one epoch; the first-round loss gradient is recorded. Fourth, cosine similarity between each simulated gradient and the benign gradient captured during normal VFL training is computed; the permutation yielding the highest similarity corresponds to the correct label mapping. The associated model is then retrained to convergence and used to predict labels on new samples. For SplitVFL, the simulated top model must be initialized with positive weights to align gradient signs.

## Key Results
- LEA outperforms prior state-of-the-art attacks by 50%-90% in Top-1 attack accuracy across multiple datasets and model architectures.
- The attack is effective for both logistic regression and neural network models in AggVFL and SplitVFL settings.
- LEA remains successful under gradient noise and compression defenses, though its efficacy depends critically on the clustering accuracy of the adversary’s local features.

## Why This Works (Mechanism)
### Mechanism 1: Clustering Generates Candidate Mappings
The passive party applies unsupervised clustering to its local feature matrix, partitioning samples into *n* clusters. Under the assumption that local features are predictive of true labels, each cluster predominantly corresponds to a single class. Enumerating all *n!* permutations of label assignments to these clusters yields candidate labeled datasets. The core assumption is that clustering accuracy exceeds random chance; if cluster purity is low (e.g., <70%), the correct mapping may be omitted, causing attack failure. Evidence: The paper’s abstraction and Section III.A emphasize that classifiable local data are prerequisite for VFL participation, and experiments show attack success strongly correlates with clustering accuracy.

### Mechanism 2: First-Round Gradient Similarity Identifies Truth
For each simulated model trained on a permuted label set, the first-round loss gradient is recorded. The model whose gradient has the highest cosine similarity to the benign model’s first-round gradient (obtained during actual VFL training) corresponds to the correct label permutation. This works because the initial gradient direction is heavily influenced by the true label assignment. In SplitVFL, the top model’s weights must have consistent sign (all positive) with the benign top model to ensure alignment. Evidence: Theoretical justification in Section III.B and empirical results (Table III) show gradient similarity succeeds where parameter similarity fails. The break condition is mixed-sign top weights or excessive gradient noise/compression that distorts similarity rankings.

### Mechanism 3: Binary-LEA Reduces Complexity
Binary-LEA avoids full *n!* enumeration by decomposing the multi-class problem into pairwise binary tasks. For each pair among remaining classes, it trains *O(n²)* binary models and selects the most similar one. After ⌊*n*/2⌋ such steps, the binary classifiers are combined for final multi-class prediction. This reduces complexity to *O(n³)* while preserving accuracy, provided pairwise decisions are correct and can be aggregated. Evidence: Algorithm 2 and Table IV demonstrate dramatic speedups (e.g., ~19,000× for MNIST-10) with minimal accuracy loss. Break conditions include highly imbalanced label distributions where pairwise assignments may not uniquely determine the global mapping.

## Architecture Onboarding
- Component map: Input (local features *X_a*, benign first-round gradient ∇_benign) → Clustering module (outputs *C* clusters) → Permutation generator (full *n!* or Binary-LEA’s ∑*N*(*N*‑1)) → Simulated trainer (trains each model 1 epoch, records ∇_sim) → Similarity engine (computes cosine similarity) → Selector (picks top‑k candidates) → Predictor (final attack model or combined binary models)
- Critical path: 1. Capture benign gradient during VFL round‑1. 2. Cluster local data → *C*; estimate cluster accuracy. 3. For each candidate mapping: initialize simulated model, train 1 epoch, record ∇_sim. 4. Compute cosine similarities; select model with max score. 5. Retrain selected model to convergence. 6. Deploy attack model for label prediction.
- Design tradeoffs: Clustering quality vs speed (deep clustering vs k‑means); full vs Binary enumeration (accuracy vs feasibility); first‑round vs full training (efficiency vs robustness); initialization constraints (positive top-model weights in SplitVFL).
- Failure signatures: Cluster accuracy <70% → ASR near random; top similarity score barely above median → low confidence; defenses altering gradient ranking → wrong model selected; extreme label imbalance in binary tasks → ambiguous mapping; mixed-sign top model in SplitVFL → gradient similarity breaks.
- First 3 experiments: 1. **Baseline replication**: Breast Cancer (2 classes), AggVFL, logistic regression; target >90% ASR; measure CA vs ASR correlation. 2. **Binary‑LEA scaling**: MNIST‑10 (10 classes), SplitVFL, ResNet18; compare time/accuracy of full LEA (infeasible) vs Binary‑LEA; verify *O(n³)* scaling. 3. **Defense validation**: Apply Laplace noise and gradient compression; measure ASR degradation; test label mapping table defense with varying auxiliary data ratio.

## Open Questions the Paper Calls Out
- **Open Question 1**: How can clustering accuracy be improved when the passive party has limited or low-quality features? *Basis*: Paper shows with 10% features on Give-me-some-credit, CA drops to 48.7%, ASR to 50.8%. *Why unresolved*: No remedies for low-feature scenarios are addressed. *Evidence needed*: Evaluate enhanced clustering (e.g., deep clustering) on reduced feature subsets, correlating metrics with ASR.
- **Open Question 2**: What robust defenses can counter LEA across all VFL scenarios, especially with auxiliary data or label imbalance? *Basis*: Gradient noise/compression defenses fail; label mapping table defense fails with auxiliary data or skewed ratios. *Why unresolved*: Critical gaps remain; no generalized solution proposed. *Evidence needed*: Design adaptive defenses (e.g., randomized label encoding) and test under controlled auxiliary data/balance conditions.
- **Open Question 3**: Can LEA be adapted to non-differentiable VFL models like decision trees or gradient boosting? *Basis*: Paper evaluates only LR and neural networks; tree-based models are common in industry. *Why unresolved*: Gradient similarity may not transfer to non-differentiable models. *Evidence needed*: Reformulate LEA using alternative similarities (e.g., prediction consistency) and validate on tree-based VFL.
- **Open Question 4**: How can computational cost be reduced for high-class tasks (*n* > 10)? *Basis*: Binary-LEA’s *O(n³)* remains prohibitive; MNIST-10 already takes ~4924s. *Why unresolved*: No approximations beyond binary decomposition explored. *Evidence needed*: Develop heuristic/sampling approaches (e.g., clustering-guided pruning) and test accuracy vs. cost on synthetic/real multi-class data.

## Limitations
- Clustering algorithm and hyperparameters are unspecified; attack success strongly depends on clustering accuracy, which may be low in practice.
- SplitVFL assumption of all-positive top-model weights is likely unrealistic; gradient similarity may fail with mixed-sign initializations.
- Binary-LEA’s pairwise decomposition risks error propagation under label imbalance, potentially yielding incorrect global mappings.
- Defense evaluation is limited; no assessment against strong differential privacy or adaptive mapping defenses.

## Confidence
- Core attack mechanism (clustering + gradient similarity): Medium
- Binary-LEA complexity reduction: High
