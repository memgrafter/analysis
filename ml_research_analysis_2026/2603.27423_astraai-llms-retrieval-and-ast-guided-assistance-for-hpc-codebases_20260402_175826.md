# AstraAI: LLMs, Retrieval, and AST-Guided Assistance for HPC Codebases

## Quick Facts
- **arXiv ID**: 2603.27423
- **Source URL**: https://arxiv.org/abs/2603.27423
- **Reference count**: 28
- **Primary result**: Integrating RAG and AST-guided prompting with LLMs measurably improves code correctness for HPC tasks, with CodeLlama-13B similarity scores increasing by >0.4 on AMReX benchmarks.

## Executive Summary
AstraAI is a framework designed to generate correct, context-aware code modifications for complex high-performance computing (HPC) codebases. It combines large language models (LLMs) with Retrieval-Augmented Generation (RAG) and Abstract Syntax Tree (AST) analysis to produce structurally consistent code changes. The system constructs high-fidelity prompts that fuse user requests, retrieved relevant code snippets, and AST-extracted structural details (e.g., class members, function signatures). Evaluated on AMReX tasks, AstraAI shows improved code correctness via cosine similarity against verified benchmarks, with notable gains for smaller models like CodeLlama-13B. Frontier models also benefit, though less dramatically, suggesting the approach especially enhances models lacking extensive HPC pretraining.

## Method Summary
The method involves a pipeline where user queries are augmented through two main mechanisms: (1) RAG retrieves semantically relevant code snippets from the codebase, and (2) AST analysis extracts precise structural information (e.g., class members, function signatures). These elements are combined into a detailed prompt for an LLM, which then generates code modifications. The prompt’s high fidelity aims to ground the LLM’s output in both semantic and syntactic context of the target HPC project.

## Key Results
- CodeLlama-13B similarity scores rose from 0.32 to 0.78 on task 1 and from 0.60 to 0.87 on task 2 (AMReX benchmarks).
- Frontier models (Claude-Sonnet-4.6-High, GPT-OSS-120B) also saw improvements on several tasks, though gains were less pronounced.
- RAG+AST augmentation enhances structural consistency and correctness, particularly for smaller models with limited HPC pretraining.

## Why This Works (Mechanism)
Assumption: The improvements stem from the synergistic effect of augmenting LLM prompts with both semantic and syntactic context. RAG retrieves relevant code snippets from the codebase, providing examples of correct usage and patterns. AST analysis extracts structural details (e.g., class definitions, function signatures), ensuring that generated modifications conform to the codebase's architecture. This dual grounding reduces hallucinations and improves structural consistency, particularly for smaller models that lack extensive HPC pretraining.

## Foundational Learning
The work integrates several foundational concepts in machine learning for code:
- Large Language Models (LLMs): Pretrained models that generate code conditioned on prompts.
- Retrieval-Augmented Generation (RAG): Enhances generation by retrieving relevant documents from a knowledge source (here, the codebase) and incorporating them into the prompt.
- Abstract Syntax Trees (ASTs): Tree representations of code structure that enable precise extraction of syntactic elements like variable declarations and function signatures.
These elements address key challenges in HPC codebases, which often involve complex, performance-critical, and tightly coupled components that require modifications to respect existing interfaces and patterns.

## Architecture Onboarding
Based on the description, the AstraAI architecture likely consists of the following components:
- Query interpreter: Parses user requests.
- Code retriever: Searches the codebase for semantically relevant snippets (using embeddings or other methods).
- AST extractor: Parses the target code files to extract structural information (e.g., class members, function signatures).
- Prompt builder: Combines the user request, retrieved snippets, and AST details into a structured prompt.
- LLM generator: Sends the prompt to an LLM (e.g., CodeLlama, Claude, GPT) to produce code modifications.
The critical path flows from query reception through retrieval and AST extraction, prompt assembly, and finally generation. Design tradeoffs include balancing retrieval precision with recall and determining the granularity of AST information to avoid excessively long prompts. Failure signatures might involve irrelevant retrievals, AST parsing errors (e.g., for malformed code), or LLM outputs that ignore the provided context. Initial experiments focused on AMReX tasks to validate the approach, comparing cosine similarity of generated code to reference implementations.

## Open Questions the Paper Calls Out
The paper does not explicitly enumerate open questions; however, the limitations and suggested future work point to several:
- How generalizable is the approach to other HPC codebases beyond AMReX?
- Do cosine similarity scores correlate with actual functional correctness when code is executed?
- What are the individual contributions of RAG and AST components, and how do they interact?
- How does the quality of the retrieval mechanism (e.g., embedding model, indexing) impact overall performance?

## Limitations
- Evaluation is restricted to AMReX tasks; generalizability to other HPC codebases is unknown.
- Cosine similarity against benchmarks may not directly correlate with functional correctness or real-world usability.
- Individual contribution of RAG vs. AST-guided prompting is not isolated; retrieval quality and AST detail depth are unclear.
