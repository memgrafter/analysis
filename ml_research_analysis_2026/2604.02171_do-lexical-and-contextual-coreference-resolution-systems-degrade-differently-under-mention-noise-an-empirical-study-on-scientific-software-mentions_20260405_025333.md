# Do Lexical and Contextual Coreference Resolution Systems Degrade Differently under Mention Noise? An Empirical Study on Scientific Software Mentions

## Quick Facts
- **arXiv ID:** 2604.02171
- **Source URL:** https://arxiv.org/abs/2604.02171
- **Reference count:** 0
- **Primary result:** Context Aware Representations (CAR) is more robust to boundary noise (0.07 F1 drop vs. Fuzzy Matching's 0.20) and more efficient at scale (linear vs. superlinear scaling), while Fuzzy Matching (FM) degrades more gracefully under mention substitution (0.52 F1 drop vs. CAR's 0.63).

## Executive Summary
This study compares two unsupervised coreference resolution systems—Fuzzy Matching (FM), based on lexical string similarity, and Context Aware Representations (CAR), which combines mention and document embeddings—for linking software mentions across scientific papers. Both systems achieve high performance (CoNLL F1 0.94–0.96) on the SOMD 2026 shared task, with CAR consistently outperforming FM by about one F1 point. Under controlled noise injection simulating mention detection errors, CAR proves significantly more robust to boundary noise (perturbations to mention span edges), while FM degrades more gracefully under mention substitution (replacing the mention string). Inference-time analysis reveals FM scales superlinearly with corpus size due to pairwise comparisons, whereas CAR scales approximately linearly, making CAR more suitable for large corpora.

## Method Summary
The evaluation uses the SOMD 2026 dataset for cross-document software mention resolution. FM applies a tuned threshold to Ratcliff/Obershelp character-level similarity scores between normalized mention strings, linking mentions via transitive closure. CAR encodes each mention using a weighted combination of a mention-level embedding (the normalized name string) and a document-level embedding (aggregated from up to ten sentences containing the mention) via the `all-MiniLM-L6-v2` model, then clusters using agglomerative clustering on cosine distance. Both systems are unsupervised and require no fine-tuning. Robustness is tested by injecting two noise types—boundary modification (random span truncation/extensions) and mention substitution (replacing the string with a random software name)—at increasing rates, with FM's similarity threshold retuned at each noise level.

## Key Results
- Both systems achieve high absolute performance (CoNLL F1 0.94–0.96), with CAR consistently ~1 point higher than FM.
- Under boundary noise, CAR degrades far less (0.07 F1 drop at 100% noise) compared to FM (0.20 drop). Under mention substitution, FM degrades more gracefully (0.52 drop) than CAR (0.63 drop).
- FM's inference time scales superlinearly with corpus size; CAR scales approximately linearly, making CAR more efficient for large corpora (e.g., at ~21.5k mentions, FM time increases 78× while CAR increases 10×).

## Why This Works (Mechanism)

### Mechanism 1: Lexical Similarity Thresholding in Fuzzy Matching
- **Claim:** FM clusters mentions by applying a fixed threshold to a character-level string similarity score, effectively grouping near-identical software name variants.
- **Mechanism:** For each pair of mention strings, the Ratcliff/Obershelp algorithm computes a similarity score based on recursively matching common substrings. Mentions are linked if their score exceeds a tuned threshold θ, and transitive closure forms final clusters. The system operates solely on surface form, ignoring context.
- **Evidence anchors:** Average intra-cluster lexical similarities of 0.881 and 0.887 are substantially higher than in general coreference corpora, supporting the assumption that coreferent software mentions are near-identical strings.
- **Break condition:** If mention strings are heavily corrupted (e.g., substitution noise >25%), lexical similarity drops below threshold, causing rapid cluster fragmentation (∆F1 = 0.52 drop at 100% substitution).

### Mechanism 2: Combined Mention-and-Document Embedding in CAR
- **Claim:** CAR encodes each mention using a weighted combination of a mention-level embedding (software name string) and a document-level embedding (context from up to 10 mention-bearing sentences), then clusters via agglomerative clustering on cosine distance.
- **Mechanism:** The `all-MiniLM-L6-v2` model produces dense vectors for (a) the normalized mention string (em) and (b) an aggregated string of up to 10 sentences containing that mention (ed). The final representation is e = α·em + (1-α)·ed (α=0.6). Clustering uses a precomputed distance matrix with average linkage.
- **Evidence anchors:** CAR loses only 0.07 F1 under boundary noise versus FM’s 0.20, indicating embedding tolerance to minor string perturbations. The design reflects the intuition that software names are surface-regular, making the mention string primary while context disambiguates ambiguous cases.
- **Break condition:** When mention content is substituted, both mention and document embeddings are simultaneously corrupted because document context is built from *mention-bearing* sentences, eliminating any compensatory signal (∆F1 = 0.63 at 100% substitution).

### Mechanism 3: Scaling Divergence via Computational Complexity
- **Claim:** FM’s pairwise similarity computation leads to superlinear scaling with corpus size, while CAR’s independent mention encoding yields approximately linear scaling, reversing the efficiency advantage at large scale.
- **Mechanism:** FM must compute s(mi, mj) for every unique mention string pair (complexity ≈ O(n²) in unique strings). CAR encodes each mention independently (O(n) in mentions) and uses a matrix-based clustering step (O(n² log n) but dominated by encoding). At small n, FM’s lower per-operation cost wins; at large n, FM’s quadratic term dominates.
- **Evidence anchors:** For Subtask 1 (n=743 mentions), FM is 7.4× faster (0.60s vs 4.45s). For Subtask 2 (n≈21,500 mentions, 29× larger), FM time increases 78× (47s) while CAR increases only 10× (45s).
- **Break condition:** If corpus size grows beyond the point where pairwise O(n²) becomes computationally infeasible (memory or time constraints), FM fails regardless of accuracy.

## Architecture Onboarding
- **Component map:** Input (mention spans + sentences) -> FM: String Normalization -> Pairwise Similarity Matrix (Ratcliff/Obershelp) -> Thresholding (θ) -> Transitive Closure -> Clusters. CAR: Mention Encoding (all-MiniLM-L6-v2) + Document Context Encoding (aggregated mention-bearing sentences) -> Weighted Combination (α=0.6) -> Cosine Distance Matrix -> Agglomerative Clustering (average linkage, δ) -> Clusters.
- **Critical path:** 1. Obtain mention strings (and document sentences for CAR). 2. Generate pairwise similarity/distance matrix. 3. Apply threshold/clustering to produce coreference chains. 4. *For FM only:* Tune θ via grid search on training CoNLL F1.
- **Design tradeoffs:** 
  - **FM:** Simple, deterministic, superlinear scaling. Fast at small scale, brittle to string corruption. No context, so cannot disambiguate same surface form in different contexts.
  - **CAR:** More complex per-mention cost (neural encoding), linear scaling. Embeds context, but context is contaminated by mention string (see break condition). Fixed δ may not generalize.
  - **Common:** Both unsupervised, no fine-tuning. Both assume coreference chains are not extremely long (max chain 367).
- **Failure signatures:**
  - **FM:** Performance drops sharply with mention substitution noise (0.52 F1 loss at 100%). Also sensitive to boundary noise (0.20 loss) because character alignment is disrupted.
  - **CAR:** Moderate drop with substitution (0.63 loss), but resistant to boundary noise (0.07 loss) due to embedding smoothness. High variance in CPU inference times (±5s on large set).
  - **Both:** Collapse under severe mention content corruption (>50% substitution). Performance plateau at high noise levels (~0.18–0.19 F1) indicates a fundamental limit when mention identity is randomized.
- **First 3 experiments:**
  1. **Baseline replication:** Run FM (θ=0.84) and CAR (δ=0.4) on the official SOMD 2026 training set. Verify FM CoNLL ~0.95, CAR ~0.96. Confirm superlinear vs. linear scaling by measuring time at n=100, 1000, 5000 mentions (sample subsets).
  2. **Noise injection protocol:** Implement boundary modification (randomly extend/truncate spans by 1 token) and mention substitution (replace string with random training-set software name) at 0%, 25%, 50%, 75%, 100% rates. For each noise level, retune FM’s θ via grid search and report degradation curves (as in Table 4).
  3. **Context contamination test for CAR:** Modify CAR to build document context from *non-mention-bearing* sentences only (e.g., title + abstract + other sentences). Compare performance under mention substitution noise to original CAR. *Assumption:* This should improve robustness to substitution if document context truly provides independent signal.

## Limitations
- **Corpus generalizability:** Findings rely on SOMD 2026's high surface regularity (avg intra-cluster similarity >0.88), which may not hold for software mentions in other corpora (e.g., general web text).
- **Noise simulation realism:** Synthetic boundary and substitution noise are simplistic proxies for actual mention detector errors (e.g., partial matches, OCR errors, aliases); extreme substitution (100%) likely exceeds real-world error distributions.
- **CAR's context assumption:** Using mention-bearing sentences for document context contaminates the signal during substitution noise experiments, potentially understating CAR's true robustness.

## Confidence
- **Surface regularity enables FM:** High (strong empirical evidence: intra-cluster similarity >0.88).
- **Robustness divergence (boundary vs. substitution):** Medium (consistent results but unrealistic noise and contaminated context weaken substitution comparison).
- **Scalability reversal:** Medium (timing at two scales supports trend but lacks theoretical O(n²) verification and ignores clustering overhead).

## Next Checks
1. **Independent replication with real detector noise:** Run FM and CAR end-to-end using outputs from a state-of-the-art mention detector (e.g., a fine-tuned NER model) on a held-out scientific corpus. Compare robustness to naturally occurring boundary errors and misidentifications.
2. **Context-isolated CAR variant:** Modify CAR to build document context from *all sentences except the mention-bearing ones* (e.g., title, abstract, introduction, conclusion). Re-run the substitution noise experiment; if degradation lessens (F1 drop <0.63), it confirms contaminated context was the primary weakness.
3. **Cross-dataset validation:** Apply both systems to a *different* cross-document coreference corpus with diverse entity types (e.g., news events, products) where surface regularity is lower. Test whether CAR's contextual advantage generalizes beyond the high-regularity software domain.
