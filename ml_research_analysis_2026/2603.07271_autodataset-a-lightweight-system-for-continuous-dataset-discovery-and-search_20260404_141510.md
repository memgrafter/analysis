# AutoDataset: A Lightweight System for Continuous Dataset Discovery and Search

## Quick Facts
- **arXiv ID:** 2603.07271
- **Source URL:** https://arxiv.org/abs/2603.07271
- **Reference count:** 24
- **Primary result:** A lightweight, two‑stage BERT pipeline identifies dataset‑introducing papers with high accuracy (F1=0.94) and low latency (11 ms), enabling near‑real‑time discovery and reducing researchers’ time‑to‑find new datasets by up to 80%.

## Executive Summary
AutoDataset addresses the lag in discovering newly released machine learning datasets by shifting from slow manual curation to an automated, paper‑first strategy. It continuously monitors arXiv submissions, using a fast binary classifier (BERT‑GATE) to filter titles and abstracts for dataset mentions, then a second BERT model (BERT‑DESC) to extract concise descriptions from full texts. URLs are reliably extracted via a hybrid PDF/LaTeX parsing and rule‑based scoring system, and records are indexed with a dense semantic retriever for natural‑language search. Deployed as a live web service, the system achieves high throughput and near‑zero latency, significantly accelerating access to new datasets.

## Method Summary
The pipeline ingests new arXiv papers via RSS/API and first applies BERT‑GATE, a fine‑tuned `bert-base-uncased` classifier on concatenated title and abstract, to quickly identify dataset‑introducing papers (F1=0.94, 11 ms). Positive papers are passed to a PDF processor (GROBID) that converts the full text into sentence‑level XML. BERT‑DESC then classifies each sentence using a class‑conditional sliding window (different stride for positive/negative contexts) to extract contiguous description snippets, outperforming long‑document and LLM baselines. In parallel, a hybrid URL extractor parses both the PDF and the original LaTeX source, scoring candidates via rule‑based features and optional LLM verification to reliably pinpoint the primary dataset hosting link. Finally, descriptions are encoded with `gte-large-en-v1.5` and indexed in a vector database (FAISS) for low‑latency semantic search.

## Key Results
- **Filtering:** BERT‑GATE achieves F1=0.94 with 11 ms latency per paper.
- **Description extraction:** BERT‑DESC reaches F1=0.858 at 9.39 ms, surpassing Longformer (0.747) and Qwen‑Plus (0.757) while being far more efficient.
- **Impact:** User studies show up to 80% reduction in time‑to‑find new datasets; the system demonstrates strong data efficiency, nearing saturation performance with minimal annotated sentences (~3,560).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** A lightweight binary classifier on titles/abstracts enables high‑throughput initial filtering of dataset‑introducing papers with minimal latency.
- **Mechanism:** Fine‑tuned `bert-base-uncased` (BERT‑GATE) classifies concatenated title and abstract of each arXiv submission, exploiting strong semantic cues in these condensed sections while avoiding full‑text processing costs.
- **Core assumption:** Titles and abstracts contain sufficient signals to distinguish dataset papers from general research with high precision.
- **Evidence anchors:** Reported F1=0.94 and 11 ms latency; system design reasoning from section 3.
- **Break condition:** If dataset releases are routinely omitted from titles/abstracts (e.g., buried in full text), recall degrades, increasing downstream load.

### Mechanism 2
- **Claim:** A sentence‑level classifier with a class‑conditional sliding window context achieves accurate, low‑latency extraction of concise dataset descriptions from full‑text PDFs.
- **Mechanism:** After GROBID conversion to sentence‑level XML, BERT‑DESC classifies each sentence. A symmetric window of surrounding sentences expands around the target, with stride size conditioned on the predicted label (smaller stride around positives). Positively classified sentences are concatenated in document order.
- **Core assumption:** Dataset descriptions reside in contiguous or near‑contiguous sentence spans; enriched local context is more beneficial than full‑document processing.
- **Evidence anchors:** BERT‑DESC F1=0.858 at 9.39 ms, outperforming long‑document and LLM baselines (Table 3, Figure 2); strong data efficiency with modest annotation.
- **Break condition:** Highly fragmented descriptions across disjoint sections cause incomplete extraction.

### Mechanism 3
- **Claim:** A hybrid URL extraction pipeline (PDF parsing + LaTeX source fallback + rule‑based/LLM scoring) reliably identifies the primary dataset hosting link despite inconsistent paper formatting.
- **Mechanism:** Extract hyperlinks from parsed PDF and LaTeX source (preserving semantic anchors). Candidates are scored via interpretable integer‑weighted features (host, path, lexical cues). Selection uses rule‑only thresholds, LLM verification, or hybrid fallback.
- **Core assumption:** The canonical dataset URL appears explicitly in the paper’s text and can be distinguished from peripheral links by hosting platform, path hints, and anchor text.
- **Evidence anchors:** Robustness against inconsistent formatting; case study success (e.g., MMDocIR); detailed feature design in Appendix B.
- **Break condition:** Authors host datasets on personal sites without dataset‑centric signals or omit links entirely, causing rule scores to drop and forcing less precise LLM fallback or missing links.

## Foundational Learning
- **Fine‑tuning BERT for short‑text classification:** Both BERT modules rely on fine‑tuning `bert-base-uncased`. Critical decisions include input formatting (e.g., title+abstract concatenation), handling class imbalance, and optimizing for latency (small max length, efficient batching). *Quick check:* How would you adjust BERT‑GATE if the positive class became much rarer?
- **GROBID for PDF‑to‑structured text conversion:** GROBID parses PDFs into sentence‑level XML with structural hints, enabling the sliding‑window approach. Understanding its failure modes (e.g., poor OCR) helps diagnose downstream issues. *Quick check:* If GROBID mis‑segments a paragraph where a description spans a boundary, how does this impact BERT‑DESC?
- **Dense semantic retrieval with pre‑computed index:** Search requires embedding queries and descriptions (e.g., with `gte-large-en-v1.5`) and performing approximate nearest neighbor search (FAISS) for low‑latency response. *Quick check:* What are the trade‑offs between a sentence‑transformer and a general‑purpose embedding model for indexing these snippets?

## Architecture Onboarding
- **Component map:** Ingestor -> BERT‑GATE -> PDF Processor (GROBID) -> BERT‑DESC + Link Extractor (concurrent) -> JSON record -> Vector index (FAISS) -> Web Interface (Flask)
- **Critical path:** New arXiv ID -> Ingestor -> BERT‑GATE (if positive) -> PDF download & GROBID -> BERT‑DESC + Link Extraction (concurrent) -> JSON -> Vector index → searchable. Latency dominated by PDF download/parse and BERT‑DESC.
- **Design tradeoffs:**
  - Speed vs. accuracy: BERT‑GATE uses 512‑token limit for 11 ms, sacrificing some full‑context understanding; BERT‑DESC’s windowed approach is faster than long‑document models but may miss long dependencies.
  - Rule‑based vs. LLM for URLs: Rule‑only is deterministic/fast but brittle; LLM‑Only is semantic but slow/expensive; Hybrid balances cost and robustness.
  - Modularity: Independent modules allow separate updates but introduce inter‑module failure points (e.g., BERT‑GATE false positives waste resources).
- **Failure signatures:**
  - High false positive rate from BERT‑GATE: Overloads downstream; monitor precision on a validation sample.
  - Empty BERT‑DESC output: Likely false positive or GROBID failure; reclassify as negative and inspect GROBID.
  - URL extraction failure: All candidate scores below threshold; inspect rule scores for unconventional hosting patterns.
  - Indexing lag: Vector DB update slower than ingestion; monitor queue depth.
- **First 3 experiments:**
  1. Standalone BERT‑GATE evaluation on temporally held‑out arXiv papers to verify F1 generalizability.
  2. Ablate BERT‑DESC’s class‑conditional stride vs. fixed‑stride and full‑document baselines to confirm design.
  3. Compare URL extraction modes (Rule‑Only, LLM‑Only, Hybrid) on 100 papers; measure success rate, latency, and cost.

## Open Questions the Paper Calls Out
- **Fine‑grained metadata extraction:** How to automatically extract task, modality, and language tags from dataset‑introducing papers? The current system only provides plain descriptions and URLs.
- **Cross‑paper deduplication:** How to implement robust deduplication of datasets across different papers (versions, names) to avoid clutter?
- **Integration with community repositories:** What strategies enable tight two‑way synchronization with Hugging Face or Papers with Code to enrich records and reduce redundancy?

## Limitations
- **Pipeline performance generalizability:** High confidence in reported metrics from internal evaluation, but external validation (e.g., non‑arXiv venues, evolving publication norms) is lacking.
- **URL extraction robustness:** Medium confidence; heuristic rules may fail on novel hosting patterns (personal domains, non‑standard paths), and the hybrid LLM fallback’s trade‑offs are not fully quantified.
- **Impact claim verifiability:** Low confidence in the “80% time‑to‑find reduction” due to sparse user study details (sample size, baseline, metrics).

## Confidence
- **High confidence:** BERT‑GATE/BERT‑DESC F1 and latency metrics (internal, well‑specified experiments).
- **Medium confidence:** URL extraction success (heuristic‑based, limited external validation).
- **Low confidence:** System impact on user workflow (user study under‑specified); long‑term operational costs and failure rates on noisy arXiv feed (undisclosed).

## Next Checks
1. **External BERT‑GATE evaluation:** Test the released model on a held‑out arXiv sample from 6 months post‑training cut‑off to measure recall drift and identify new title/abstract patterns.
2. **URL extraction stress test:** Run the hybrid pipeline on 200 dataset papers hosted on diverse platforms (GitHub Pages, institutional repos, OSF) to quantify per‑mode success rates and common failure patterns.
3. **BERT‑DESC sliding window ablation:** Replicate the class‑conditional stride design and compare against fixed‑stride and Longformer baselines on a test set with deliberately fragmented descriptions to confirm robustness.
