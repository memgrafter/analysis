# ChartEditBench: Evaluating Grounded Multi-Turn Chart Editing in Multimodal Language Models

## Quick Facts
- **arXiv ID:** 2602.15758
- **Source URL:** https://arxiv.org/abs/2602.15758
- **Reference Count:** 23
- **Primary Result:** ChartEditBench reveals a 20–33% performance drop across conversation turns for top MLLMs, with the best model scoring only 2.187 out of 5.

## Executive Summary
Multimodal large language models (MLLMs) are increasingly used for data analysis tasks, yet evaluating their ability to perform iterative, multi-turn chart editing remains an open challenge. This paper introduces ChartEditBench, a benchmark comprising 5,000 difficulty-controlled modification chains and a hybrid evaluation framework that combines code execution validity, pixel-level visual similarity, and logical assertions. Testing on mainstream MLLMs shows substantial performance degradation across conversation turns (20–33% drop for top models), strong results on stylistic edits but frequent failures on data-centric operations like rolling averages. The best model, Claude Haiku 4.5, achieves an overall score of 2.187 on a 5-point scale, while smaller models such as InternVL3-1B reach only 1.345, highlighting scalability challenges and the need for improved state tracking in multimodal tasks.

## Method Summary
ChartEditBench is constructed by generating 5,000 chains of chart modifications, each with a controlled difficulty level. The modifications include both stylistic changes (e.g., color updates) and data-centric operations (e.g., adding rolling averages). For each turn, a model receives the current chart image and a textual instruction, then outputs an edited chart. The evaluation is hybrid: (1) code execution validity checks whether the model’s output can be rendered without errors; (2) pixel-level visual similarity compares the output against a gold-standard edit; (3) logical assertions verify that semantic constraints (e.g., “the trend line should follow the data”) hold. This multi-metric approach aims to capture correctness along multiple dimensions. The benchmark is designed to assess how well models maintain state and context over multiple turns.

## Key Results
- Top MLLMs exhibit a 20–33% performance drop as conversation turns increase, indicating error accumulation.
- Models perform well on stylistic edits but struggle with data-centric operations such as rolling averages.
- Claude Haiku 4.5 leads with a score of 2.187/5, while InternVL3-1B scores 1.345, revealing a significant gap for smaller models.

## Why This Works (Mechanism)
The hybrid evaluation framework works because it jointly assesses syntactic correctness (via code execution), visual fidelity (via pixel similarity), and semantic integrity (via logical assertions). This multi-faceted scoring reduces the risk of false positives that could arise from a single metric. Additionally, the difficulty-controlled modification chains allow systematic isolation of failure modes, particularly state tracking across turns. The benchmark’s design ensures that models must not only execute isolated edits but also maintain a consistent internal representation of the chart’s data and appearance, which is essential for real-world analysis.

## Foundational Learning
- **Multimodal Reasoning**  
  *Why needed:* To integrate visual chart information with textual editing instructions.  
  *Quick check:* Can the model correctly interpret “highlight the peak bar” and apply a distinct color to the highest data point?

- **Iterative State Tracking**  
  *Why needed:* To preserve chart context across multiple turns and prevent error propagation.  
  *Quick check:* After applying two successive transformations (e.g., change axis labels then add a regression line), does the final chart reflect both edits without contradictions?

- **Hybrid Evaluation Metrics**  
  *Why needed:* A single metric cannot fully capture the quality of an edited chart; combining code validity, pixel similarity, and logical assertions yields a more robust assessment.  
  *Quick check:* Would a model receive a high score if it produces an image that looks correct but contains a subtle data misalignment detectable only by inspecting the underlying code?

- **Difficulty-Controlled Benchmark Design**  
  *Why needed:* To systematically probe model capabilities across a spectrum of challenges.  
  *Quick check:* Do longer modification chains (more turns) consistently lead to lower scores, thereby confirming the benchmark’s ability to test state maintenance?

## Architecture Onboarding
**Component Map (plain text)**  
Modification Chain Generator → Chart Renderer → Model Input Formatter → MLLM (Vision Encoder + LLM) → Output Parser → Evaluation Engine → Score

**Critical Path**  
The process begins with a base chart and a sequence of natural language edit instructions. Each instruction is paired with the current chart image and fed to the MLLM. The model generates an output that should be a valid chart representation (e.g., code or image). The Output Parser extracts the chart code, which is executed by the Chart Renderer to produce a new image. The Evaluation Engine then compares this image against the gold-standard edit using the three metrics and aggregates a final score.

**Design Tradeoffs**  
- *Hybrid evaluation*: Increases computational overhead but improves reliability by capturing multiple quality dimensions.  
- *Automatic chain generation*: Scales to thousands of examples but may miss subtle real-world intents that human users would express.  
- *Fixed set of chart types*: Ensures controlled experiments but limits generalizability to more exotic chart forms.

**Failure Signatures**  
- Error accumulation: Performance degrades steadily with more turns.  
- State forgetting: Model ignores earlier edits or reverts changes.  
- Overfitting to style: Excels at superficial changes but fails on data transformations.  
- Code hallucinations: Produces syntactically invalid rendering code.

**First Experiments**  
1. Baseline Evaluation: Run Claude Haiku 4.5 on the full benchmark to establish performance baselines across difficulty levels and edit types.  
2. Human Alignment: Collect human annotations for a random subset of model outputs and correlate with the hybrid score to validate metric consistency.  
3. Ablation Study: Disable one evaluation component at a time (e.g., drop logical assertions) to measure its contribution to overall score stability.

## Limitations
- Generalizability of the 5,000 modification chains to all real-world chart types (e.g., geospatial, 3D) is unclear.
- The hybrid evaluation’s logical assertions may not capture all semantic errors, especially subtle misrepresentations.
- Models tested are limited to a small set of mainstream MLLMs, potentially overlooking niche architectures that might perform differently.

## Confidence
- **Benchmark construction & evaluation framework:** High  
- **Performance degradation across turns:** Medium  
- **Scalability challenges for small models:** Low  

## Next Checks
1. Expand chart diversity: Run ChartEditBench on additional chart subtypes (e.g., heatmaps, funnel charts) to test benchmark coverage.
2. Human alignment study: Correlate the hybrid evaluation scores with human judgments on a sampled subset of edits.
3. Architecture ablation: Test error accumulation trends in models with explicit state-tracking modules vs. standard transformers.
