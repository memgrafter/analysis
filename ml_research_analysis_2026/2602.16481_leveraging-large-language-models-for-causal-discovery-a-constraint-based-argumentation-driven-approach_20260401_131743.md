# Leveraging Large Language Models for Causal Discovery: a Constraint-based, Argumentation-driven Approach
## Quick Facts
- **arXiv ID:** 2602.16481
- **Source URL:** https://arxiv.org/abs/2602.16481
- **Reference count:** 40
- **Primary result:** ABAPC-LLM achieves state-of-the-art structural accuracy (lowest SHD, highest F1) on standard and memorization-robust benchmarks by integrating high-precision LLM constraints with data-driven conditional independence tests via Causal ABA.

## Executive Summary
Causal discovery from observational data relies on conditional independence tests but often requires expert knowledge to guide structure learning. This work proposes using Large Language Models (LLMs) as a defeasible source of such knowledge. The authors design a pipeline that queries an LLM multiple times to generate candidate causal direction constraints (required/forbidden arrows), filters them via strict consensus to ensure high precision, and integrates them with statistical evidence within a Causal Assumption-Based Argumentation (ABA) framework. This symbolic integration resolves conflicts between LLM priors and data while maintaining transparency. Evaluations on standard benchmarks and a novel synthetic protocol that embeds random DAGs in CauseNet to avoid memorization show that the LLM-augmented ABA (ABAPC-LLM) significantly outperforms purely data-driven methods.

## Method Summary
The method consists of three main stages. First, LLM-derived constraints are elicited: a primary LLM is queried five times with variable names/descriptions to produce sets of required and forbidden causal directions; a secondary LLM parses free-text responses into structured constraints using a schema; only arrows appearing in all five responses (intersection) are retained as high-precision consensus constraints. Second, a data-driven skeleton is learned: Majority-PC (MPC) runs conditional independence tests to generate CI facts, and a one-off skeleton reduction hard-removes edges supported by high-confidence independence tests. Third, integration via Causal ABA: the remaining CI facts (weighted) and consensus constraints (as hard arrow facts) are encoded as assumptions in an ABA framework. An ASP solver (clingo) iteratively relaxes low-weight CI facts to find a stable extension that corresponds to a valid DAG, thereby defeasibly reconciling LLM priors with statistical evidence.

## Key Results
- **Problem:** Eliciting precise causal constraints from experts is labor-intensive; LLMs offer automation but suffer from hallucinations and memorization.
- **Core idea:** Treat LLMs as defeasible experts: use multi-query consensus for high-precision constraints and integrate them with CI evidence via Causal ABA, which resolves conflicts transparently.
- **Primary results:** On bnlearn benchmarks and a novel CauseNet synthetic evaluation (with random DAGs to avoid memorization), ABAPC-LLM achieves state-of-the-art structural accuracy (lowest normalised SHD, highest F1) across graph sizes (5, 10, 15 nodes), with statistically significant improvements over data-only baselines (MPC, FGS, NOTEARS).

## Why This Works (Mechanism)
**Mechanism 1: Consensus filtering yields high-precision LLM constraints.** The system queries the same LLM five times independently and retains only causal relationships proposed in all five responses (intersection). This variance-reduction exploits that spurious or hallucinated outputs are stochastic and unlikely to recur identically, while stable semantic priors (e.g., temporal precedence) are consistently retrieved. If the intersection is empty, no LLM constraints are used. Evidence: The pipeline explicitly uses a 5-way intersection; the paper notes empty consensus leads to pure ABAPC fallback. Break condition: Frequent empty consensus occurs when LLM outputs are inconsistent due to ambiguous semantics or insufficient knowledge.

**Mechanism 2: Causal ABA enables principled, transparent reconciliation.** LLM constraints are encoded as defeasible assumptions (required/forbidden arrows) in ABA. CI facts from data are also assumptions. The ABA solver seeks a stable extension—a conflict-free set of assumptions implying a DAG. If an LLM constraint contradicts a high-confidence CI fact, the solver may reject (defeat) the LLM constraint to maintain global consistency. This preserves statistical rigor while leveraging semantic guidance where no conflict exists. Evidence: The abstract states ABA resolves conflicts while preserving transparency; Section 4.2 details how required/forbidden arrows interact with skeleton edges. Break condition: If LLM constraints and CI facts are fundamentally incompatible (no stable extension), the solver may produce a graph discarding most LLM guidance or fail.

**Mechanism 3: CauseNet embedding mitigates memorization bias.** The evaluation protocol generates a random abstract DAG scaffold (via ER, SF, LT) and searches CauseNet for an induced subgraph isomorphism—a set of real-world causal concepts whose known links exactly match the scaffold’s topology. A heuristic selects a thematically coherent match. The LLM is queried only on these novel, semantically grounded variable names, forcing reasoning about unseen causal configurations rather than memorizing benchmark graphs. Evidence: The abstract introduces this protocol to avoid memorization; Section 5 describes the isomorphism search. Break condition: Isomorphism search may fail to find a match; if the heuristic picks overly generic “hub” concepts, graphs may remain too ambiguous.

## Foundational Learning
- **Concept:** Causal Assumption-Based Argumentation (ABA)
  - **Why needed:** The entire integration framework uses ABA to represent LLM constraints and CI facts as assumptions, define attacks via d-separation rules, and compute stable extensions that correspond to valid DAGs.
  - **Quick check:** If ABA contains assumptions `A→B` and `B→C`, and a rule that `A→B` and `B→C` imply `A→C`, what happens if `¬(A→C)` is also an assumption? Can a stable extension include both `A→B` and `B→C`? (Answer: No, because `A→B`, `B→C` together attack `¬(A→C)`; if `¬(A→C)` is accepted, it attacks the rule or one premise, so both originals may not coexist stably.)

- **Concept:** Conditional Independence (CI) Testing & d-separation
  - **Why needed:** Data-driven evidence enters as CI test results; ABA rules encode d-separation to check consistency between CI facts and arrow assumptions, enabling conflict resolution.
  - **Quick check:** In a DAG with `A→B←C`, what is the d-separation between A and C when conditioning on B? Without conditioning? (Answer: Conditioning on B opens the collider, so A and C are d-connected (dependent). Without conditioning, they are d-separated (independent).)

- **Concept:** Defeasible Reasoning & Consensus Filtering
  - **Why needed:** The LLM is treated as a defeasible (not infallible) expert; consensus filtering (intersection of multiple queries) is a practical form of defeasible reasoning that only retains universally agreed outputs as strong constraints.
  - **Quick check:** How does taking the intersection of five LLM query outputs differ from taking a majority vote in terms of precision and recall? (Answer: Intersection maximises precision (fewer false positives) but reduces recall; majority vote increases recall but admits more false positives.)

## Architecture Onboarding
- **Component map:** Metadata Input -> LLM Query Module -> Schema-Guided Parser -> Consensus Filter -> Data Engine (MPC) -> Skeleton Reducer -> Causal ABA Solver -> Output
- **Critical path:** Variable metadata triggers LLM queries; parsed constraints are consensus-filtered; MPC provides CI facts; skeleton reduction prunes edges; ABA solver combines retained CI facts and consensus constraints to produce final DAG.
- **Design tradeoffs:**
  - **Precision vs. Recall:** 5-way intersection maximises constraint precision at the cost of recall; this trades off coverage for safety given ABA’s sensitivity to false positives.
  - **Scalability vs. Transparency:** One-off skeleton reduction (hard edge removal before ABA) bounds search space for larger graphs (~15 nodes) but prevents later reconsideration if a CI test was false.
  - **LLM Cost vs. Coverage:** A single comprehensive prompt is efficient but may miss nuanced pairwise interactions; multiple pair-wise queries could improve recall but increase cost and complexity.
- **Failure signatures:**
  - **Empty consensus:** No constraints survive 5-way intersection; pipeline defaults to pure ABAPC. Diagnose by checking raw LLM output variability.
  - **Solver failure/no extension:** ABA program admits no stable extension, often due to irreconcilable conflict between hard LLM constraints and initial skeleton. Diagnose by relaxing consensus threshold or CI significance level.
  - **Degraded LLM constraint quality on CauseNet:** Low precision/recall of LLM constraints on synthetic benchmarks suggests the semantic grounding produced too abstract concepts or LLM lacks required knowledge.
  - **Prompt parsing failures:** Schema-guided extraction mis-parses LLM responses if formatting varies. Check extraction success rate and raw output compliance.
- **First 3 experiments:**
  1. Replicate main result on CauseNet synthetic data: For |V|∈{5,10,15}, run ABAPC-LLM vs. ABAPC, MPC, FGS, etc.; confirm significant SHD/F1 improvement (Table 2).
  2. Ablate consensus mechanism: Compare ABAPC-LLM using 5-way intersection vs. union (average of single runs); measure constraint precision/recall and final DAG F1 (Table 3); expect intersection yields better final F1.
  3. Ablate variable descriptions: Run pipeline with/without optional metadata enrichment; quantify impact on LLM constraint quality (F1 vs. ground truth) and final DAG accuracy.

## Open Questions the Paper Calls Out
- **How can LLM-derived prior knowledge be integrated into causal discovery without sacrificing rigorous and transparent reasoning?** The proposed ABA framework provides symbolic, defeasible integration but does not fully characterise the transparency of argumentation explanations or formal guarantees under LLM errors. Resolution needs formal analysis linking ABA semantics to probabilistic guarantees, user studies on interpretability, and comparisons with alternative hybrids.
- **How can we robustly certify that LLM-augmented causal graphs do not merely reflect memorised benchmark structures?** The CauseNet protocol grounds random DAGs in real concepts to reduce memorisation, but LLMs may still have encountered similar subgraphs; proving genuine generalisation is elusive. Evidence needed: evaluation on never-before-published causal graphs, membership inference tests, adversarial perturbations that break memorised cues.
- **What is the optimal design of the LLM constraint elicitation pipeline—including query count, consensus mechanism, and prompt structure—to maximise downstream causal discovery accuracy?** The pipeline uses heuristics (5 queries, intersection consensus) without theoretical justification; the conclusion calls for exploring alternative models and prompts. Resolution requires large-scale sensitivity studies varying consensus thresholds and query counts, ablating prompt components, and cross-LLM benchmarking.

## Limitations
- LLM model versions and generation parameters (temperature, top_p) are unspecified, hindering exact replication.
- ABA solver implementation details (ASP encoding, CI relaxation schedule) are omitted, requiring assumptions or reuse of cited code.
- The 5-way consensus filter often yields empty constraint sets, forcing fallback to data-only mode and potentially nullifying LLM benefits.
- Evaluation is restricted to small graphs (≤15 nodes); scalability to larger, real-world graphs remains unproven.
- The CauseNet embedding likely reduces but does not eliminate memorisation bias; no direct evidence confirms prior results were inflated.
- The one-off skeleton reduction cannot later reverse false CI removals, possibly propagating errors.

## Confidence
- **SOTA accuracy on benchmarks:** Medium (strong empirical results but limited scale and potential overfitting to synthetic protocol)
- **Consensus filtering yields high-precision constraints:** Medium (precision is demonstrated, but recall suffers; trade-off justified by ABA sensitivity)
- **ABA integration resolves conflicts transparently:** Medium (theoretically sound; practical behaviour hinges on solver heuristics)
- **CauseNet protocol mitigates memorisation:** Low (preventative but lacks direct evidence that prior results were inflated by memorisation)
