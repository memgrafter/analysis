# Aligning Text, Code, and Vision: A Multi-Objective Reinforcement Learning Framework for Text-to-Visualization
## Quick Facts
- **arXiv ID:** 2601.04582
- **Source URL:** https://arxiv.org/abs/2601.04582
- **Reference Count:** 21
- **Primary Result:** RL-Text2Vis with GRPO improves code execution success to 97% and achieves a 22% relative improvement in chart quality over GPT-4o on the Text2Vis benchmark.

## Executive Summary
This paper introduces RL-Text2Vis, a reinforcement learning framework that addresses the failure of supervised fine-tuning to optimize semantic alignment and clarity in text-to-visualization generation. By employing Group Relative Policy Optimization (GRPO) and a multi-objective reward derived from post-execution feedback (textual accuracy, code executability, and visualization quality), the system enables large language models to learn from the final rendered output. Training Qwen2.5 models yields state-of-the-art results, significantly boosting code execution rates and chart quality metrics while generalizing to multiple benchmarks.

## Method Summary
RL-Text2Vis formulates Text2Vis as a reinforcement learning problem where a policy model (e.g., Qwen2.5) generates JSON-structured outputs containing an answer and Matplotlib code. For each prompt, the framework generates a group of candidate outputs, executes the code to render a chart, and evaluates all three modalities using separate reward models: an LLM for answer accuracy, a combination of execution success and code-intent matching, and a VLM for the rendered image's readability and correctness. The composite reward is weighted (0.5, 0.25, 0.25). Advantages are computed as group-relative standardized scores, and the policy is updated via a clipped surrogate objective with a KL penalty to a frozen reference model, avoiding the need for a learned value function.

## Key Results
- Code execution success increased from a 78% zero-shot baseline to 97% after RL.
- The 14B model achieved a 22% relative improvement in chart quality over GPT-4o.
- Readability (4.10) and Correctness (4.03) scores surpassed GPT-4o's (3.32 and 3.30) on the Text2Vis test set.
- Strong generalization was demonstrated on VIS-Eval and NVBench benchmarks.

## Why This Works (Mechanism)
### Mechanism 1: Group Relative Policy Optimization (GRPO)
GRPO enables efficient optimization for long, structured outputs by replacing a learned value function (critic) with group-based relative advantages. For each prompt, the policy generates `G` candidates; rewards are standardized within the group (`(r_i - mean)/std`) to compute advantages. This critic-free approach provides a stable, low-variance learning signal suited to tasks where quality is only observable after full generation (e.g., rendering a chart). Evidence shows GRPO outperformed PPO in efficiency and effectiveness. The method destabilizes if the group size `G` is too small or the reward signal is excessively noisy.

### Mechanism 2: Multi-Objective Post-Execution Reward
The composite reward `R = αR_text + βR_code + γR_vis` (weights 0.5, 0.25, 0.25) is necessary because Text2Vis has three distinct, measurable quality dimensions. `R_text` (LLM judge) assesses answer correctness against ground truth. `R_code` combines binary executability (`I_exec`) and intent match (`I_intent`). `R_vis` (VLM) scores rendered chart readability and correctness. Ablation experiments confirm that removing any component significantly degrades performance, validating the need for joint optimization. The fixed weighted sum assumes objectives are not fundamentally conflicting and that each sub-reward is well-calibrated.

### Mechanism 3: Closed-Loop Execution and Visual Feedback
Semantic alignment and clarity are emergent properties of the final rendered image, not inferable from code tokens alone. The framework closes the loop: generate code → execute → render → evaluate image → compute reward. Post-execution feedback from the VLM provides the crucial signal for improving chart quality, which static code analysis or token-level SFT loss cannot capture. The signal quality depends on a faithful execution environment and an accurate VLM evaluator.

## Foundational Learning
- **Concept: Group Relative Policy Optimization (GRPO)**
  - **Why needed here:** Optimizing long, structured outputs (JSON with multi-line code) with standard PPO is computationally expensive due to the critic. GRPO's critic-free, group-relative advantage offers a scalable alternative.
  - **Quick check:** How does GRPO compute advantages without a value network, and why is this particularly suited for tasks where quality is only measurable after full generation?

- **Concept: Multi-Objective Reinforcement Learning**
  - **Why needed here:** The task has three distinct quality dimensions (text, code, vision). A single scalar reward must balance these, requiring careful weighted-sum design and awareness of trade-offs.
  - **Quick check:** What are the risks of setting `α=1.0, β=γ=0` (text-only) versus `α=β=γ=1/3` during training?

- **Concept: Post-Execution Evaluation as Reward**
  - **Why needed here:** Code execution success and chart quality are not deducible from code tokens. The system must generate code, execute it, render the image, and then evaluate to obtain a meaningful learning signal.
  - **Quick check:** Why can't a standard code-generation reward (e.g., unit test pass) suffice? What specific quality dimensions require the rendered image?

## Architecture Onboarding
**Component map:**
Policy Model -> [Generate G outputs] -> Execution Environment -> [Render images] -> Reward Models (Text LLM, Code Exec+Intent LLM, Vision VLM) -> [Compute R] -> GRPO Trainer -> [Update Policy]; Reference Model (frozen) -> [KL penalty]

**Critical path:**
1. Receive (query, table).
2. Policy generates G candidate (answer, code) outputs per prompt.
3. For each output: validate JSON format; execute code to get image and `I_exec`; evaluate answer (`R_text`), code intent (`I_intent`), and rendered chart (`R_vis`).
4. Combine reward: `R = 0.5*R_text + 0.25*(0.5*I_exec + 0.5*I_intent) + 0.25*R_vis` (0 if format fails).
5. Standardize rewards within the G-sized group to compute advantages.
6. Perform clipped PPO update with KL penalty against reference model.

**Design tradeoffs:**
- **Reward weighting (α,β,γ):** Tuned on a dev set; imbalance risks degrading one objective (e.g., high γ may hurt answer correctness).
- **Group size (G):** Larger G (e.g., 8 vs. 4) improves ranking signal but increases rollout cost.
- **Judge model choice:** Using different model sizes for policy and judges (e.g., 7B policy, 32B VLM judge) mitigates reward hacking but introduces dependency on judge quality.
- **KL penalty (β):** Must be high enough to prevent mode collapse/language drift but low enough to allow learning.

**Failure signatures:**
- **Training instability:** KL spikes or reward plateaus. Diagnose: β too low, LR too high, or noisy rewards.
- **Mode collapse:** Diversity of G outputs collapses. Diagnose: β too high or G too small.
- **Poor generalization:** High in-domain scores but low on VIS-Eval/NVBench indicates overfitting to training chart types.
- **Degraded text accuracy:** `Answer Match` drops as `R_vis` rises, suggesting reward weighting imbalance.

**First 3 experiments:**
1. **Reward Ablation:** Train with `R_code + R_vis` only (no `R_text`) to verify textual correctness requires explicit signal.
2. **Group Size Sensitivity:** Compare `G=4`, `G=8`, `G=16` on a subset to measure impact on reward variance and convergence.
3. **Cross-Architecture Transfer:** Apply the same GRPO recipe to a different base model (e.g., Llama-3.1-8B) to test framework portability.

## Open Questions the Paper Calls Out
1. How does RL-Text2Vis scale with significantly larger model sizes (e.g., 32B or 72B)?
2. How robust is the fixed reward weighting (0.5, 0.25, 0.25) to different data distributions or task complexities?
3. Can the framework handle highly specialized domains (e.g., medical, financial) without adaptation, and is the VLM reward signal reliable there?
4. What are the long-term training dynamics with a multi-objective reward? Does the policy converge to a balanced optimum or exhibit goal-switching/reward hacking?
5. How do VLM-based in-loop judges propagate biases, and can a more objective, programmatic reward component be integrated?

## Limitations
- **Incomplete documentation:** Missing details on reward-model prompts, code sandbox parameters, and reference model initialization hinder exact replication.
- **Judge model dependency:** Performance relies on specific VLMs/LLMs as reward models; their biases or inaccuracies may distort optimization.
- **Benchmark scope:** Evaluation is limited to three datasets; transfer to other chart types, libraries, or real-world data distributions is unproven.

## Confidence
- **GRPO effectiveness:** **High** (ablations show clear advantage over PPO).
- **Multi‑objective reward necessity:** **High** (ablations show significant drop when any component is removed).
- **Post‑execution feedback importance:** **High** (removing `R_vis` hurts readability/correctness by >0.5 points).
- **Generalization to out-of-domain benchmarks:** **Medium** (results on VIS-Eval/NVBench are positive but limited to general domains).
- **Scalability to larger models:** **Low** (not tested; an open question).
