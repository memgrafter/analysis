# CiteLLM: An Agentic Platform for Trustworthy Scientific Reference Discovery
## Quick Facts
*   **arXiv ID:** 2602.23075
*   **Source URL:** https://arxiv.org/abs/2602.23075
*   **Reference Count:** 8
*   **Primary Result:** A local LaTeX editor plugin that retrieves 100% valid, real references from trusted repositories by using LLMs only for query/ranking, never for creation.

## Executive Summary
CiteLLM is a local agentic platform embedded within LaTeX editors to combat AI-generated fake references. It ensures privacy by keeping all manuscript data on the user's machine and guarantees reference validity by sourcing candidates exclusively from trusted academic repositories (arXiv, bioRxiv, medRxiv). The system uses LLMs solely for generating queries, ranking results, and performing semantic validation via full-text analysis. Evaluated on 40 sentences, it achieved 100% reference validity, 87.5% human-assessed precision, and 92.5% usability, outperforming Google Scholar and ChatGPT.

## Method Summary
The system is built as a local plugin for LaTeX editors. It captures user-selected text and document context, uses a lightweight local LLM to generate search queries and classify the discipline for routing. Queries are sent only to arXiv, bioRxiv, or medRxiv APIs. Retrieved papers are fetched, their full PDFs are parsed with GROBID, and an LLM judge performs paragraph-level semantic matching against the user's claim to validate relevance and rank results. The final output presents verified BibTeX entries and matched evidence paragraphs.

## Key Results
*   **100% Validity:** All returned references were real and accessible.
*   **87.5% Precision:** Human evaluators agreed on the relevance of suggested citations.
*   **92.5% Usability:** Users found the integrated workflow effective for academic writing.

## Why This Works (Mechanism)
### Mechanism 1: Local-Only Execution for Privacy
*   **Claim:** Embedding within the LaTeX editor eliminates external data transmission, preventing pre-publication leakage.
*   **Mechanism:** All processing (context extraction, query generation, result rendering) occurs on the user's machine. No manuscript text or intermediates are sent to external servers or cloud APIs.
*   **Core Assumption:** A local environment can host LLM inference, GROBID, and repository access with acceptable performance.
*   **Evidence Anchors:** Abstract states "no data transmission outside the local system"; Section 2.1 confirms content remains local.
*   **Break Condition:** Any network call for core processing (e.g., to a commercial LLM API) violates the guarantee.

### Mechanism 2: Repository Routing to Prevent Hallucinations
*   **Claim:** Querying only trusted, curated repositories (arXiv, bioRxiv, medRxiv) guarantees real, accessible references from appropriate scholarly domains.
*   **Mechanism:** A discipline-aware classifier routes queries to a primary repository (with fallback). BibTeX entries are pulled directly from repository metadata (via paper ID or DOI), never generated by an LLM.
*   **Core Assumption:** These repositories contain vetted content accessible via stable APIs/DOIs.
*   **Evidence Anchors:** Abstract: "retrieve candidates exclusively from trusted... never for reference creation." Section 2.2 details repository-specific metadata acquisition.
*   **Break Condition:** Accepting a candidate whose metadata (title, authors, DOI) was LLM-generated, not repository-sourced.

### Mechanism 3: Full-Text Semantic Validation for Relevance
*   **Claim:** Paragraph-level semantic matching using GROBID-parsed full-texts ensures retrieved papers genuinely support the specific claim.
*   **Mechanism:** The system downloads/open-access PDFs, parses them with GROBID, and uses an LLM to score alignment between parsed paragraphs and the user's selected sentence.
*   **Core Assumption:** Granular paragraph matching is a reliable proxy for claim support; GROBID provides sufficiently accurate parsing.
*   **Evidence Anchors:** Section 2.3 describes "two-layer mechanism" and "fine-grained semantic matching." Abstract highlights "paragraph-level semantic matching."
*   **Break Condition:** Skipping full-text download/parse and relying only on title/abstract for final ranking.

## Foundational Learning
*   **Concept: Constrained RAG**
    *   **Why needed:** CiteLLM is a RAG system where "generation" (queries, rankings) is strictly bounded by verifiable retrieved sources. The engineer must design prompts/workflows that never let the LLM invent source material.
    *   **Quick Check:** At which pipeline point could an LLM hallucinate a reference, and what guardrails prevent it?
*   **Concept: IDE/Editor Integration**
    *   **Why needed:** Usability and privacy depend on seamless embedding within a LaTeX editor. An engineer must understand editor extension APIs, context capture, and local resource management.
    *   **Quick Check:** What editor events (e.g., text selection, command) trigger the workflow, and how is the BibTeX entry injected?
*   **Concept: Scholarly Infrastructure**
    *   **Why needed:** Effective routing and metadata extraction require knowledge of arXiv's API, bioRxiv/medRxiv's DOI negotiation, and BibTeX structure.
    *   **Quick Check:** How is a BibTeX obtained for a medRxiv paper (no arXiv-style ID), and what is the DOI fallback if negotiation fails?

## Architecture Onboarding
*   **Component Map:** Analyzer -> Retriever -> Reranker -> Informer
*   **Critical Path:** User selects sentence S -> Analyzer extracts context & classifies discipline -> Retriever fetches candidates from primary repo -> Reranker parses PDFs & validates semantic match -> Informer displays ranked, validated results with one-click BibTeX insertion.
*   **Design Tradeoffs:**
    *   Latency vs. Validation Depth: Full-text download/GROBID parsing adds seconds but is necessary for the hallucination-free guarantee.
    *   Repository Coverage vs. Complexity: Limiting to 3 open repos simplifies integration but restricts niche field coverage.
    *   Local LLM Size vs. Performance: A small local LLM preserves privacy/cost but may degrade query/ranking quality versus a larger cloud model.
*   **Failure Signatures:**
    *   Invalid references: Retriever accepts malformed record or Reranker skips full-text validation.
    *   Zero results: Analyzer misclassifies discipline, repository API outage, or all PDFs inaccessible/un-parseable.
    *   High latency (>30s): Slow repository APIs or GROBID parsing bottleneck.
    *   Irrelevant top rank: Reranker's LLM judge scores incorrectly, possibly due to poor context window management.
*   **First 3 Experiments:**
    1.  **Discipline Router Accuracy:** Feed 100 discipline-diverse text samples to Analyzer. Log classifier output, chosen repository, and fallback triggers vs. ground-truth domain.
    2.  **End-to-End Validity & Latency:** Run full pipeline on 20 representative sentences. Measure per-stage time, success rate (≥1 valid ref), and BibTeX resolvability.
    3.  **Reranker Sanity Check:** For 50 retrieved paper-claim pairs, verify full-text was downloaded/parsed, matched paragraphs are non-trivial, and scores correlate with human judgment on a sample.

## Open Questions the Paper Calls Out
*   **Open Question 1:** How can CiteLLM's architecture be optimized to reduce real-time processing latency while maintaining verification rigor?
    *   **Basis:** Conclusion states future work should focus on "optimizing their integration to reduce latency and costs."
    *   **Why Unresolved:** No specific architectural/algorithmic modifications to address latency are proposed.
    *   **Resolution Evidence:** A structured ablation study measuring per-component latency and user studies defining acceptable thresholds.
*   **Open Question 2:** To what extent does reliance on arXiv, bioRxiv, and medRxiv limit effectiveness for disciplines with limited preprint coverage or for citing non-preprint literature?
    *   **Basis:** Inferred; system routes exclusively to these repos and notes architecture "naturally extends to restricted... corpora," implying current limitation.
    *   **Why Unresolved:** Evaluation doesn't specify disciplines or test performance when target references are outside these repositories (e.g., humanities, paywalled journals).
    *   **Resolution Evidence:** A multi-domain benchmark with ground-truth references from diverse venues, measuring validity/precision when sources are absent from used repos.
*   **Open Question 3:** What factors cause misalignment between LLM-based (GPT-5) and human evaluation of citation precision, and how can the LLM-as-a-judge metric be calibrated?
    *   **Basis:** Explicit; paper notes "a consistent trend where GPT-5 ratings exceed those of human evaluators" and highlights caution with autonomous agents.
    *   **Why Unresolved:** Discrepancy is noted but not investigated; root cause and remedy are not proposed.
    *   **Resolution Evidence:** Comparative error analysis identifying GPT-5's systematic biases (e.g., surface similarity preference), followed by a calibrated LLM evaluation rubric validated against human-annotated gold standards.
*   **Open Question 4:** How does the pipeline perform when the most relevant reference is paywalled or in a non-open-access repository, and what fallback strategies exist without compromising the guarantee?
    *   **Basis:** Inferred; "Full-Text Acquisition" prioritizes open-access, but paywall scenarios aren't discussed.
    *   **Why Unresolved:** 100% validity depends on accessible references; system's open-access assumption may not hold for all fields, creating a silent utility limitation.
    *   **Resolution Evidence:** A controlled experiment where ground-truth reference is paywalled, measuring if CiteLLM can identify it via metadata/abstract (without full-text) and how its rankings degrade.

## Limitations
*   **Unverified Local Feasibility:** The core assumption that typical academic hardware can host the full pipeline (LLM + GROBID) with acceptable performance is not empirically validated.
*   **Implementation Opacity:** Exact LLM models, prompts, classifier training data, and API error-handling logic are unspecified, blocking faithful reproduction.
*   **Evaluation Scale:** Results are based on a small test set (n=40), with limited neighboring paper citations, indicating minimal independent validation of the approach.
