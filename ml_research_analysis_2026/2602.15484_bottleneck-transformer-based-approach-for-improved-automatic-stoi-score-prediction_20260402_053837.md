# Bottleneck Transformer-Based Approach for Improved Automatic STOI Score Prediction

## Quick Facts
- **arXiv ID:** 2602.15484
- **Source URL:** https://arxiv.org/abs/2602.15484
- **Reference count:** 32
- **Primary result:** Proposed bottleneck transformer model yields LCC 94.63%, SRCC 95.88%, MSE 0.0059 on seen test set with HuBERT features, outperforms STOI-Net with fewer parameters.

## Executive Summary
The paper introduces a bottleneck transformer-based architecture for non-intrusive prediction of Short-Time Objective Intelligibility (STOI) scores, eliminating the need for a clean reference speech signal. The model combines convolutional blocks for local pattern extraction and a multi-head self-attention mechanism for global context, operating on both self-supervised learning (SSL) features (e.g., wav2vec 2.0, HuBERT) and spectral features. Evaluated on multiple datasets including Indic TIMIT, Librispeech, RESPIN, and Bhashini under diverse distortions, the method achieves high correlation and low error on both seen and unseen language tests, while using significantly fewer trainable parameters than the STOI-Net baseline.

## Method Summary
The task is to predict utterance-level STOI without reference speech. Inputs consist of three feature families: SSL embeddings (wav2vec 2.0 small: 768-D; HuBERT base: 1024-D), and spectral features (STFT-based 257-D, or 512-D from STOI-Net/QUAL-Net conv layers). The model architecture comprises: a Conv Block (two 1D convolutions with batch normalization and GELU activation) → Bottleneck Transformer (a 1×1 convolution, multi-head self-attention with 8 heads, adaptive average pooling, residual connection) → Dense Block‑1 (linear layer with layer normalization) → Global average pooling → Dense Block‑2 (linear layer with sigmoid output). Training uses 5‑fold cross‑validation on the 12‑hour Indic TIMIT subset (four parts for training, one for validation per fold) with Adam optimizer (learning rate 1e‑4) for 50 epochs, minimizing mean squared error. Evaluation metrics include linear correlation coefficient (LCC), Spearman rank correlation (SRCC), and MSE. Results show that using HuBERT features, the model attains LCC 94.63%, SRCC 95.88%, and MSE 0.0059 on the held‑out seen test set, surpassing the STOI‑Net baseline and demonstrating improved generalization to unseen languages.

## Key Results
- Achieves LCC 94.63%, SRCC 95.88%, and MSE 0.0059 on seen test data with HuBERT features.
- Outperforms STOI‑Net baseline on both seen and unseen language test sets, showing higher correlations and lower errors.
- Uses substantially fewer trainable parameters than STOI‑Net while maintaining superior performance.

## Why This Works (Mechanism)
The proposed architecture effectively integrates local and global speech representations. The initial convolutional block captures fine‑grained temporal patterns, while the bottleneck transformer with multi‑head self‑attention efficiently models long‑range dependencies across the sequence. The bottleneck design reduces computational complexity compared to a full transformer. SSL features provide rich, pre‑trained speech representations that encode phonetic and prosodic information, and spectral features contribute complementary acoustic details. The residual connection around the transformer stabilizes training. Together, these elements enable the model to map distorted speech features directly to STOI scores without requiring a clean reference.

## Foundational Learning
- **STOI (Short‑Time Objective Intelligibility):** Standard intrusive metric for speech intelligibility; ground‑truth for training. *Quick check:* Use `pystoi` to compute STOI between clean and degraded signals; typical range 0‑1.
- **Self‑Supervised Learning (SSL) features:** Pre‑trained representations (e.g., wav2vec 2.0, HuBERT) that capture high‑level speech content. *Quick check:* Load a pretrained model and verify output dimension (768 for wav2vec2‑small, 1024 for HuBERT‑base).
- **Bottleneck Transformer:** Transformer variant where self‑attention is preceded by a low‑rank projection, reducing parameters and computation. *Quick check:* Ensure the 1×1 convolution output dimension matches the attention head dimension (e.g., 64).
- **Multi‑Head Self‑Attention (MHSA):** Allows the model to jointly attend to different representation subspaces. *Quick check:* Set `num_heads` and confirm final output dimension equals input dimension (or hidden dim × heads).
- **5‑Fold Cross‑Validation:** Splits data into five parts to assess model stability and generalize performance. *Quick check:* For each fold, verify that training and validation sets have no speaker overlap and metrics are averaged over folds.

## Architecture Onboarding
**Component map:**  
Input feature (T, D) → Conv Block (→ 128‑D) → Bottleneck Transformer (1×1 conv → MHSA → pooling + residual) → Dense Block‑1 (128→32) → Global Avg Pool → Dense Block‑2 (32→1 with sigmoid) → Predicted STOI

**Critical path:**  
- Feature dimension must match first conv’s `in_channels`.  
- Conv Block output channels fixed to 128 to interface with bottleneck.  
- Bottleneck’s attention requires sequence length preservation or appropriate pooling; residual addition demands matching dims.  
- Global average pooling reduces temporal dimension before final dense layer.  
- Sigmoid ensures output in [0,1], matching STOI range.

**Design tradeoffs:**  
- *Local vs global context:* Convs capture local patterns; MHSA captures long-range dependencies but is computationally heavier; bottleneck balances this.  
- *Feature choice:* SSL features provide rich representations but are large; spectral features are compact but may lack high‑level information. Combining both could improve robustness but increases complexity.  
- *Parameter efficiency:* Bottleneck transformer reduces parameters relative to full transformer, enabling faster training and less overfitting, at the cost of some expressive power.

**Failure signatures:**  
- Shape mismatches (e.g., conv block output ≠ 128).  
- Attention producing NaNs due to improper dropout or scaling.  
- Poor convergence: suggests learning rate too high or data leakage.  
- Overfitting to seen languages: performance drops on unseen test; may need more data or regularization.  
- Inconsistent STOI ground truth: if evaluation metric implementation differs (e.g., frame length).

**First experiments (3):**  
1. **Feature extraction validation:** For each feature type, extract a small batch and assert tensor shapes: SSL (batch, T, 768/1024), spectral (batch, T, 257/512).  
2. **End‑to‑end overfitting:** Train on a tiny synthetic dataset (e.g., 10 samples) for many epochs; loss should approach zero, confirming model capacity and gradient flow.  
3. **Single‑fold training:** Run one fold of the 5‑fold cross‑validation on Indic TIMIT; after 50 epochs, compute LCC, SRCC, MSE on the validation split and verify they are reasonably high (e.g., LCC > 0.8).

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Does adapter-based fine-tuning of SSL features improve STOI prediction performance?
- **Basis in paper:** The authors propose future work on "adapter-based fine-tuning of SSL features" (Conclusion).
- **Why unresolved:** The study uses fixed SSL features; it is unknown whether task-specific adaptation yields gains.
- **What evidence would resolve:** Implement adapter modules in SSL encoder, fine-tune on STOI dataset, compare LCC/SRCC/MSE to the proposed model with frozen features.

### Open Question 2
- **Question:** Can Whisper or Conformer encoders improve STOI prediction when integrated into the bottleneck transformer?
- **Basis in paper:** The authors mention exploring "more recent models like Whisper or Conformer-based models" (Conclusion).
- **Why unresolved:** These models have not been tested; their representations may better capture speech characteristics for intelligibility.
- **What evidence would resolve:** Replace the SSL feature extractor with Whisper/Conformer encoders, re-run experiments on seen/unseen test sets, and report metric comparisons.

### Open Question 3
- **Question:** Is multi-task learning feasible to predict multiple metrics (STOI, PESQ, MOS) with the bottleneck transformer without accuracy loss?
- **Basis in paper:** The authors suggest "predictions that include a combination of metrics" (Conclusion).
- **Why unresolved:** The current model is single-task; joint training could cause interference or require careful loss balancing.
- **What evidence would resolve:** Design a shared backbone with metric-specific heads, train with combined losses, evaluate each metric's performance against single-task baselines.
