# Per-Domain Generalizing Policies: On Learning Efficient and Robust Q-Value Functions (Extended Version with Technical Appendix)

## Quick Facts
- arXiv ID: 2603.17544
- Source URL: https://arxiv.org/abs/2603.17544
- Reference count: 19
- Primary result: Regularized Q-value policies achieve 4–18 times lower runtime than state-value policies on larger instances, with better scaling and coverage.

## Executive Summary
Classical planning policies are often learned via supervised training on optimal plans using state-value functions, which are inefficient because they require evaluating all successor states. This work replaces state-values with Q-values, which are cheaper to evaluate. However, standard supervised learning of Q-values fails because the loss only considers the optimal action, leading to uniform Q-value predictions. To fix this, the authors introduce regularization terms that enforce lower bounds on Q-values for non-optimal actions, using either optimal heuristic values or admissible heuristics. Across ten planning domains and three graph neural network architectures, regularized Q-value policies run 4–18 times faster than state-value policies on larger instances. They also scale to significantly larger problem instances and achieve higher coverage sums. On standard IPC'23 test sets, they attain higher coverage than state-value policies and produce competitive plan lengths compared to the LAMA-first planner.

## Method Summary
The method trains a graph neural network (GNN) to predict Q-values for planning actions. Data is generated by sampling small instances of a domain, solving them optimally with Fast Downward, and extracting state–action pairs from optimal trajectories. For each training state, the optimal action \(a^*\) and optimal heuristic value \(h^*(s)\) are recorded; additionally, for every non-optimal action \(a_i\), the heuristic value \(h_{\text{LMcut}}(s'_i)\) of its successor state is computed. The GNN processes the planning state as a graph: objects as nodes and relational facts as edges. After message passing, the network produces either a state-value \(V(s)\) or, after augmenting the graph with action-specific information, Q-values \(Q(s,a)\) for all applicable actions. Training minimizes mean absolute error between predicted and target \(h^*(s)\) for the optimal action, optionally adding a regularization term \(\Omega\) that penalizes Q-values of non-optimal actions falling below a lower bound. Two choices: \(\Omega_{\text{Exp.}}\) uses bound \(B_{\text{Exp.}} = h^*(s) + 1\); \(\Omega_{\text{Heu.}}\) uses \(B_{\text{Heu.}} = \max\{h^*(s) + 1, \text{cost}(a_i) + h_{\text{LMcut}}(s'_i)\}\). Models are trained with Adam (learning rate 0.0002 for unregularized, 0.002 for regularized), batch size 256, gradient clipping, and up to 100 epochs. The best checkpoint is selected via dynamic coverage validation. At test time, the policy repeatedly selects the action with minimal predicted Q-value, avoiding state revisits.

## Key Results
- Runtime efficiency: Regularized Q-value policies are 4–18× faster per instance than state-value policies on large instances.
- Generalization scaling: Achieve significantly larger maximum instance size (Scale) and higher total coverage (SCov) in dynamic generation evaluations.
- IPC'23 performance: Higher coverage than state-value policies and plan lengths comparable to LAMA-first.

## Why This Works (Mechanism)
Vanilla supervised learning of Q-values fails because the loss only penalizes error on the optimal action in each state. The model can minimize loss by predicting nearly identical Q-values for all actions, as long as the optimal one is accurate. This leads to random action selection during planning because there is no discrimination. The first regularization term, \(\Omega_{\text{Exp.}}\), directly penalizes non-optimal actions whose Q-value does not exceed \(h^*(s) + 1\). This forces a separation margin; non-optimal actions must have Q-values at least one higher than the target, encouraging the network to assign lower values to them. The second, tighter regularizer \(\Omega_{\text{Heu.}}\) uses an admissible heuristic (LM-cut) to compute a lower bound \(\text{cost}(a_i) + h_{\text{LMcut}}(s'_i)\) for each non-optimal action's true Q-value, combined with \(h^*(s)+1\). This bound is much larger for actions leading to dead-ends or poor successors, creating stronger discrimination. Consequently, the learned Q-value function reliably ranks the optimal action first, yielding effective policies. Both regularizers assume availability of optimal heuristic values (and LM-cut for the second). Evidence shows that regularized models exhibit much larger differences between optimal and non-optimal Q-values (Diff metric) while maintaining low error on optimal actions (Err). Over-regularization can cause overly high Q-values for all non-optimal actions, but this typically does not harm policy performance because the minimal Q-value is still selected.

## Foundational Learning
**Concept: Supervised Learning for Planning Policies**  
Why needed here: The entire approach trains neural networks on labeled data consisting of optimal state–action pairs, forming the basis for learning a policy.  
Quick check: If the training loss only considers the Q-value of the expert action, why does this not teach the model about the values of other actions?

**Concept: State-Value vs. Q-Value Functions**  
Why needed here: The core efficiency gain comes from using Q-values, which require evaluating only the current state rather than all successor states as state-values do.  
Quick check: What is the computational bottleneck when using a state-value policy on a large instance with high branching factor?

**Concept: Admissible Heuristics and Dead-Ends**  
Why needed here: The heuristic regularizer relies on an admissible heuristic to compute meaningful lower bounds for non-optimal actions; dead-end states (heuristic = ∞) yield extremely high bounds that enforce strong penalties.  
Quick check: Why does an action leading to a dead-end state receive an extremely high lower bound in \(\Omega_{\text{Heu.}}\), and how does this help discrimination?

## Architecture Onboarding
Component map:  
State (set of ground atoms) -> Graph Construction (objects/atoms as nodes, predicates as edges) -> GNN Layers (message passing) -> Object Embeddings -> State Embedding (sum) -> MLP -> (for V) scalar value; or (for Q) extend graph with action atoms -> Action-specific node embeddings -> Concatenation with state embedding -> MLP -> Q-values for all actions.

Critical path:  
1. Generate small planning instances via domain-specific generators.  
2. Solve each instance optimally using Fast Downward (seq-opt-merge-and-shrink) to obtain optimal trajectories.  
3. For each state on trajectories, store: state representation, \(h^*(s)\), optimal action \(a^*\), list of applicable actions \(\{a_i\}\), and for each \(a_i\) compute \(h_{\text{LMcut}}(s'_i)\).  
4. Train GNN with MAE loss \(\mathcal{L} = |h^*(s) - Q(s,a^*)| + \lambda \cdot \Omega(s)\), using \(\lambda=1.0\) for regularized models; optimize with Adam, dynamic coverage validation to select checkpoint.  
5. At test time, given a state, run GNN to obtain Q-values, select \(\arg\min Q(s,a)\), execute action, and forbid revisits.

Design tradeoffs:  
- Regularizer choice: \(\Omega_{\text{Exp.}}\) requires only \(h^*(s)\) and is simpler; \(\Omega_{\text{Heu.}}\) yields tighter bounds and better performance at the cost of computing LM-cut for all successors during data generation.  
- GNN architecture: R-GNN uses predicate-specific message passing and often generalizes best; OE/OAE use standard RGCN but are more general but slightly weaker.  
- Learning rate: Regularized Q-models use higher LR (0.002) as they are less prone to overfitting; unregularized Q and V models use 0.0002.

Failure signatures:  
- Vanilla Q-policy: On training states, Diff metric (average \(Q(s,a^*)-Q(s,a_i)\)) remains low (∼0.7–0.96) while Err is modest; policy coverage collapses due to near-random action selection.  
- Over-regularized Q-policy: Extremely high Diff (e.g., >100) combined with rising Err on validation; policy may become overly conservative, rejecting valid actions and leading to failures.  
- State-value policy: Runtime per state grows linearly with branching factor; scaling evaluations show sharp drop in coverage as instance size increases.

Compute Err and Diff on held-out training trajectories. Expect vanilla Q to have low Err but very low Diff; regularized models to have much higher Diff (especially \(\Omega_{\text{Heu.}}\)).

Evaluate on dynamically generated instances of increasing size, record Scale (max size before coverage <30%) and SCov (sum of coverages). Expect Q-value policy to outperform in both metrics.

## Open Questions the Paper Calls Out
1. **Integration of reinforcement learning:** How can RL be used to fine-tune the supervised Q-value policies on dynamically generated instances to further improve generalization? The paper suggests gradually increasing instance size during RL training as a promising direction.
2. **R-GNN's advantage:** What specific properties of the relational GNN (R-GNN) enable its consistently superior generalization compared to object-encoding architectures (OE, OAE)? Understanding this could guide better architecture designs.
3. **Heuristic regularizer efficiency:** How does the choice of admissible heuristic affect the performance of \(\Omega_{\text{Heu.}}\), and can we design more efficient lower bounds that avoid costly heuristic computations while maintaining discrimination? The current use of LM-cut and a fixed large value for dead-ends may be improved.

## Limitations
- Key architectural details are missing, notably the exact MLP structure for the value prediction heads.
- The handling of infinite heuristic values in \(\Omega_{\text{Heu.}}\) (using a fixed constant 1120) is not explained or justified.
- The dynamic coverage validation procedure used for model selection is not described, hindering full replication.
- Training data distribution (exact number of instances per size) is not reported, which may affect reproducibility.
- The approach relies on an optimal teacher and admissible heuristics, which may become expensive or unavailable for larger, more complex domains.

## Confidence
- Vanilla supervised Q-learning fails to discriminate actions: **High** (Table 2 shows low Diff despite low Err).
- Regularization explicitly increases Q-value separation: **High** (Diff rises sharply with Ω, especially Ω_Heu).
- Regularized Q-policies scale better than state-value policies: **Medium–High** (Tables 3–4 show consistent improvements, but dependent on hyperparameters).
- Ω_Heu outperforms Ω_Exp: **Medium** (improvement varies across domains; not uniform).
- Q-policies achieve lower runtime per state: **High** (empirical measurement in Table 1).
- IPC'23 results comparable to LAMA-first: **Medium** (coverage higher than state-value but not directly compared to LAMA in all domains; plan lengths competitive).
