# AutoNumerics: An Autonomous, PDE-Agnostic Multi-Agent Pipeline for Scientific Computing

## Quick Facts
- **ArXiv ID:** 2602.17607  
- **Source URL:** https://arxiv.org/abs/2602.17607  
- **Reference count:** 14  
- **Primary result:** AutoNumerics achieves a geometric mean normalized root mean square error (nRMSE) of 9.00×10⁻⁹ on 24 benchmark PDEs, outperforming neural network and LLM-based baselines by approximately six orders of magnitude.

## Executive Summary
AutoNumerics is a multi-agent framework that automatically generates classical numerical PDE solvers (e.g., finite difference, spectral) from natural language descriptions. It employs a coarse-to-fine debugging strategy and residual-based self-verification to ensure accuracy without requiring analytical solutions. On 24 benchmark PDEs spanning 1D to 5D and various boundary conditions, it attains near-machine precision (geometric mean nRMSE 9.00×10⁻⁹), far surpassing neural and LLM baselines. The system also demonstrates scheme selection aligned with numerical analysis principles, such as spectral methods for periodic boundaries.

## Method Summary
The pipeline orchestrates eight specialized agents: Dispatcher, Formulator (converts natural language to structured PDE spec), Planner (generates ~10 candidate discretization schemes), Feature (extracts numerical features), Selector (ranks and filters schemes), Coder (implements solver code), Critic (debugs logic errors on coarse grids), and Reasoning (provides theoretical analysis). Key innovations include a coarse-to-fine execution strategy (solver runs on low-resolution grids for logic debugging, then on high-resolution grids for stability assessment), residual-based self-verification (computes relative PDE residuals as correctness proxy), and Fresh Restart (regenerates code after repeated failures). This enables fully automated generation of accurate, interpretable solvers for a broad range of PDEs.

## Key Results
- Geometric mean nRMSE of 9.00×10⁻⁹ on 24 PDE benchmarks, achieving ~10⁶× lower error than neural (9.52×10⁻³) and CodePDE (5.08×10⁻³) baselines.
- Correctly selects discretization schemes matching PDE structural properties (e.g., spectral Fourier for periodic boundaries).
- Residual verification allows assessment of solver correctness even when analytical solutions are unavailable.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** AutoNumerics employs a coarse-to-fine execution strategy to efficiently debug LLM-generated solver code by decoupling logic error correction from numerical stability validation.
- **Mechanism:** The solver first runs on a low-resolution grid where runtime is minimal; the Critic Agent identifies and fixes logic errors (e.g., syntax, shape mismatches). After passing logic checks, the solver is promoted to a high-resolution grid to assess stability, with time step adjustments if needed. If retry limits are exceeded, a Fresh Restart discards the code and regenerates from scratch.
- **Core assumption:** Logic errors are resolution-independent and can be reliably detected on coarse grids without interfering with stability assessment on finer grids.
- **Evidence anchors:**  
  - [abstract] Explicitly mentions "coarse-to-fine execution strategy" for debugging logic errors before high-resolution runs.  
  - [section 2.2] Details the two-phase execution, Fresh Restart logic, and memory decimation for large simulations.  
  - [corpus] Neighbor papers focus on neural operators or library-based PDE solving; none describe this specific coarse-to-fine debugging paradigm, indicating it is a novel contribution.
- **Break condition:** If logic errors persist after maximum retries or if stability issues cannot be resolved by time step tuning (e.g., for extremely stiff PDEs), the pipeline may fail to produce a valid solver, particularly for high-order or high-dimensional problems.

### Mechanism 2
- **Claim:** Residual-based self-verification enables AutoNumerics to evaluate solver correctness in the absence of analytical solutions by computing norms of the PDE residual.
- **Mechanism:** For problems without analytic solutions, the system computes relative residual errors (e.g., \(e_{res} = \|L(u) - f\|_{L2(\Omega)} / \|f\|_{L2(\Omega)} + \varepsilon\)), where \(L\) is the PDE operator and \(u\) is the numerical solution. Low residual values indicate the solution satisfies the PDE closely.
- **Core assumption:** Minimizing the residual is a sufficient proxy for solution accuracy when ground truth is unavailable, leveraging the PDE itself as a verification criterion.
- **Evidence anchors:**  
  - [abstract] Highlights "residual-based self-verification mechanism" for assessing solver quality without analytical solutions.  
  - [section 2.3] Defines \(e_{res}\), \(e_{L2}\), and \(e_{impl}\) metrics and mandates that solvers compute and return residuals for validity checks.  
  - [corpus] Related work on neural PDE solvers often relies on data-driven or loss-based validation; corpus does not evidence residual-based self-verification in an autonomous multi-agent context.
- **Break condition:** Residuals may be misleading for chaotic dynamics, discretization-induced artifacts, or when the PDE operator implementation is incorrect; also, computing residuals adds computational overhead and may require symbolic manipulation of the PDE.

### Mechanism 3
- **Claim:** The multi-agent planning and selection process embeds numerical reasoning to choose discretization schemes aligned with PDE structural properties (e.g., boundary conditions, type), while filtering ill-designed configurations.
- **Mechanism:** The Planner Agent generates candidate schemes (e.g., spectral for periodic boundaries, finite difference for Dirichlet parabolic), the Feature Agent extracts problem and scheme features, and the Selector Agent scores candidates based on expected accuracy, stability, and cost, discarding those violating fundamental principles like CFL conditions.
- **Core assumption:** LLMs can be prompted to internalize expert heuristics from numerical analysis, enabling automated assessment of scheme suitability for given PDE characteristics.
- **Evidence anchors:**  
  - [abstract] States that AutoNumerics "correctly selects numerical schemes aligned with PDE structural properties, such as spectral methods for periodic boundaries."  
  - [section 2.1] Describes the Planner, Feature, and Selector agents' roles in generating, scoring, and filtering plans to avoid instability or invalid solutions.  
  - [Table 5] Shows consistent scheme selection patterns across benchmarks (e.g., spectral Fourier for periodic hyperbolic/parabolic PDEs, Chebyshev for Dirichlet elliptic).
- **Break condition:** For PDEs with atypical properties (e.g., high-order derivatives like Biharmonic, high-dimensional >5D), the LLM's numerical reasoning may be insufficient, leading to suboptimal selections and higher errors, as evidenced by failure cases in Table 2.

## Architecture Onboarding
**Component map:**  
Dispatcher (orchestrates) → Formulator (extracts PDE spec) → Planner (generates ~10 candidates) → Feature (extracts features) → Selector (scores and filters, selects top‑k) → Coder (implements solvers) → Critic (debugs on coarse grid) → Reasoning (analysis).  
Data flow: Input → Formulated spec → Candidate plans → Feature extraction → Scoring/selection → Coded solvers → Coarse‑to‑fine execution with Critic → Residual verification → Best scheme output with analysis.

**Critical path:**  
Natural language description → Formulator produces structured specification → Planner generates plan candidates → Selector ranks and selects top‑k → Coder implements each plan → Coarse‑grid execution with Critic debugging → If logic passes, high‑resolution execution for stability → Residuals computed and evaluated → Selector chooses best plan based on residuals and runtime → Reasoning Agent provides analysis → Final solver and metrics output.

**Design tradeoffs:**  
- Number of candidate plans: higher improves diversity but increases computational cost.  
- Coarse‑grid resolution: lower saves debugging time but may miss resolution‑specific logic bugs.  
- Residual threshold for acceptance: stricter ensures accuracy but may reject valid solvers on stiff problems.  
- Memory vs. storage trade‑off in history decimation for large temporal simulations.

**Failure signatures:**  
- Residual errors (e_L2, e_res) exceeding problem‑specific tolerances (e.g., >10⁻⁶ for analytic cases).  
- Repeated triggers of Fresh Restart (code regeneration from scratch) indicating persistent logic or stability issues.  
- Scheme selection mismatches (e.g., finite difference for periodic PDEs yielding high residuals).  
- Runtime exceeding per‑phase limits (120 s) causing termination.  
- Memory exhaustion in temporal simulations if snapshot decimation fails.

**First 3 experiments:**  
1. Validate on 1D Advection (periodic BCs): Confirm spectral Fourier scheme selection and near‑machine precision residuals (e_res ~10⁻¹³) as in Table 2; debug any logic errors via coarse‑grid phase.  
2. Test on 2D Poisson (Dirichlet BCs): Verify Chebyshev spectral method selection and low e_L2 (<10⁻¹⁵); assess handling of elliptic problems and implicit residual if needed.  
3. Evaluate on viscous Burgers (nonlinear, stiff): Check for implicit finite difference scheme selection, residual accuracy (e_res ~10⁻¹⁴ in Table 2), and stability adjustments via time step reduction during high‑resolution phase.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can AutoNumerics be extended to maintain high accuracy (e.g., nRMSE ~10⁻⁹) when solving high‑dimensional (≥5D) and high‑order (e.g., fourth‑order or higher) PDEs?  
- **Basis in paper:** [explicit] "The framework still exhibits limited accuracy on high‑dimensional (≥5D) and high‑order PDEs" (Conclusion).  
- **Why unresolved:** Current discretization choices and scaling strategies likely suffer from the curse of dimensionality and instability with high‑order derivatives; the planner’s candidate pool may not include suitable schemes for such cases.  
- **What evidence would resolve:** Systematic benchmarking on a diverse set of high‑dimensional and high‑order PDEs, error decomposition to identify failure modes, and modifications (e.g., tensor decompositions, specialized high‑order stencils) validated by improved results.

### Open Question 2
- **Question:** How can AutoNumerics effectively solve PDEs on irregular domains (e.g., complex geometries) while preserving accuracy and stability?  
- **Basis in paper:** [explicit] "our evaluation covers only regular domains" (Conclusion).  
- **Why unresolved:** The pipeline presently assumes structured grids (finite differences/spectral) which are ill‑suited for irregular boundaries; handling such domains requires mesh generation or mapping not currently integrated.  
- **What evidence would resolve:** Extending the planner to generate mesh‑based or immersed‑boundary methods, incorporating automatic mesh generation tools, and demonstrating success on benchmark PDEs with irregular geometries (e.g., L‑shaped domains).

### Open Question 3
- **Question:** What theoretical frameworks can be incorporated to provide formal convergence and stability guarantees for the automatically generated numerical solvers?  
- **Basis in paper:** [explicit] "the generated code lacks formal convergence or stability guarantees" (Conclusion).  
- **Why unresolved:** Verification relies on empirical residual checks and coarse‑to‑fine execution, which do not constitute mathematical proofs; this limits trust and applicability to critical scenarios.  
- **What evidence would resolve:** Integration of formal methods (e.g., theorem proving, static analysis) to verify properties like consistency, Lax equivalence, or CFL compliance; or a meta‑theory linking the planner’s selection rules to known sufficient conditions.

### Open Question 4
- **Question:** To what extent does the performance of AutoNumerics depend on the specific large language model used (e.g., GPT‑4.1), and can the framework be adapted to work effectively with other LLMs (open‑source or smaller models)?  
- **Basis in paper:** [inferred] Noted as a limitation: "The system is also coupled to a single LLM (GPT‑4.1)" (Conclusion).  
- **Why unresolved:** All experiments use GPT‑4.1; different LLMs vary in coding ability, numerical knowledge, and reasoning, potentially affecting reliability, cost, and accessibility.  
- **What evidence would resolve:** Replicating the full pipeline with multiple LLMs (e.g., Claude, Llama, Mistral) and comparing metrics (success rate, accuracy, debugging iterations); identifying which agents are most model‑sensitive and designing robustification strategies.

### Open Question 5
- **Question:** For problems without analytic solutions, how reliable is the relative PDE residual as a metric for assessing solution accuracy, and how should residual thresholds be determined to ensure solver correctness?  
- **Basis in paper:** [inferred] The paper employs residual‑based self‑verification but does not analyze its limitations or justify the fixed ε = 10⁻¹² beyond numerical stability.  
- **Why unresolved:** A small residual only indicates the PDE is approximately satisfied, not that the solution is close to the true one (non‑uniqueness, instability, or aliasing could produce low residuals with large errors); threshold choice appears ad hoc.  
- **What evidence would resolve:** Theoretical bounds linking residual norms to solution error for different PDE classes; empirical studies comparing residual to ground‑truth error where available; development of adaptive or multi‑criteria verification (e.g., residual decay, mesh convergence).

## Limitations
- Undisclosed implementation details (agent prompts, hyperparameters) hinder precise replication.
- Limited accuracy on high‑dimensional (≥5D) and high‑order PDEs; break conditions may cause failures.
- Residual‑based verification may be unreliable for chaotic dynamics and depends on an ad‑hoc threshold.
- Benchmark set is small (24 PDEs) with no statistical significance tests reported.
- Performance tightly coupled to GPT‑4.1; unknown for other LLMs.
