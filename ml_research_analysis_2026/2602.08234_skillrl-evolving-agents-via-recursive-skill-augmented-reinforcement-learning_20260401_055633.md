# SkillRL: Evolving Agents via Recursive Skill-Augmented Reinforcement Learning
## Quick Facts
- **arXiv ID:** 2602.08234  
- **Source:** https://arxiv.org/abs/2602.08234  
- **References:** 34  
- **Primary result:** SkillRL reduces token usage by 10–20× while achieving 89.9% success on ALFWorld (41.9% above GPT‑4o) and 72.7% on WebShop, and sets a new SOTA of 47.1% average across seven search‑augmented QA tasks.

## Executive Summary
SkillRL introduces a hierarchical skill library (SkillBank) to compress LLM agent experiences into reusable abstractions. By distilling successful and failed trajectories with a teacher model, it separates general and task‑specific skills. During reinforcement learning with GRPO, the agent retrieves relevant skills to augment its context, dramatically cutting token consumption while enhancing reasoning. A recursive co‑evolution loop updates the library from validation failures, ensuring continual adaptation. The method yields substantial improvements on ALFWorld, WebShop, and multiple QA benchmarks.

## Method Summary
SkillRL constructs a hierarchical SkillBank: general skills (Sg) capture cross‑task patterns, while task‑specific skills (Sk) reflect fine‑grained strategies. First, experiences (successes τ⁺ and failures τ⁻) are distilled using a teacher model to extract skill representations. Cold‑start SFT fine‑tunes the base policy on synthetic trajectories demonstrating skill application, yielding πₛ𝒻𝓉. Then GRPO‑based RL trains the policy πθ with skill‑augmented prompts. At each step, the top‑K skills most similar to the current description are retrieved and injected into the context. Every few iterations, if a task’s validation success rate falls below a threshold, failures are sampled, new skills are distilled from them, and the SkillBank is updated. This recursive loop enables the library to evolve alongside the policy.

## Key Results
- Token usage reduced by 10–20× versus raw trajectory memory.
- Success rates: 89.9% (ALFWorld), 72.7% (WebShop); average improvement over baselines 15.3%, and 41.9% above GPT‑4o on ALFWorld.
- State‑of‑the‑art average score of 47.1% across seven search‑augmented QA tasks.

## Why This Works (Mechanism)
Experience‑based distillation converts raw trajectories into compact skills, eliminating redundant information. Hierarchical organization allows a small set of general skills to cover many tasks while specialized skills handle edge cases. Skill retrieval ensures the policy always has relevant priors, reducing the need to relearn from scratch. GRPO reinforcement learning optimizes behavior within this scaffold, balancing reward improvement with deviation from the reference policy. Recursive co‑evolution prevents library stagnation by continuously harvesting insights from failures, leading to sustained gains.

## Foundational Learning
- **Hierarchical Skill Abstraction**  
  *Why needed:* Raw trajectories are token‑heavy; skills provide reusable, composable units.  
  *Quick check:* Verify skills can be invoked across multiple episodes to cut context length.

- **Experience‑Based Distillation**  
  *Why needed:* Teacher model extracts high‑level insights from successes and failures.  
  *Quick check:* Ensure distilled skills are coherent and cover both positive and negative patterns.

- **Retrieval‑Augmented Policy**  
  *Why needed:* Dynamic injection of relevant skills guides decision‑making.  
  *Quick check:* Log retrieved skills and confirm semantic similarity to current task description.

- **GRPO Reinforcement Learning**  
  *Why needed:* Optimizes policy while maintaining proximity to a reference.  
  *Quick check:* Monitor KL divergence and reward curves; GRPO should improve success without collapse.

- **Recursive Co‑Evolution**  
  *Why needed:* Keeps skill library aligned with evolving policy and environment.  
  *Quick check:* Track library growth and correlate with validation performance after updates.

## Architecture Onboarding
**Component map:** Teacher model → (distillation) → SkillBank (Sg, Sk) → Retrieval (TopK by similarity) → Policy πθ (SFT → GRPO) ↔ Environment → Validation → (failure collection) → Teacher model → SkillBank update.

**Critical path:** 1) Collect trajectories with base agent. 2) Distill skills into hierarchical SkillBank. 3) Generate synthetic SFT data from teacher; fine‑tune policy. 4) Run GRPO with skill‑augmented context. 5) Periodically validate; if task success < threshold, sample failures, distill new skills, and merge into SkillBank.

**Design tradeoffs:**  
- General vs. task‑specific skill granularity: finer skills increase relevance but risk library bloat.  
- Retrieval threshold δ: higher precision vs. recall; unseen δ may cause irrelevant or missing skills.  
- Teacher dependency: using o3 ensures quality but limits reproducibility; self‑distillation trades cost for potential noise.  
- Library growth: larger libraries improve coverage but increase context length and retrieval latency.  
- KL coefficient in GRPO: stronger regularization stabilizes training but may slow convergence.

**Failure signatures:**  
- Low skill retrieval relevance (similarity scores near threshold).  
- Skill library not expanding during evolution.  
- Sudden drop in success rate after SFT or RL steps.  
- GRPO divergence (KL blow‑up or reward stagnation).  
- Token usage remains high despite skills.

**First experiments:**  
1. **Baseline SFT:** Train policy without skills; measure token usage and success to quantify skill contribution.  
2. **Evolution ablation:** Disable recursive updates; compare skill library size and performance over time to isolate evolution benefits.  
3. **Threshold sweep:** Vary similarity threshold δ (e.g., 0.3, 0.5, 0.7); evaluate retrieval precision, token compression, and task success.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Can skill distillation be done without an external teacher model?
- **Basis in paper:** [explicit] Section 3.1 relies on a teacher MT for distillation.
- **Why unresolved:** The paper never tests self‑supervised alternatives, which are key for autonomy.
- **What evidence would resolve it:** Replace MT with the agent’s own policy iteratively improving skills; benchmark on ALFWorld/WebShop.

### Open Question 2
- **Question:** How does skill library growth affect inference speed and success rates?
- **Basis in paper:** [inferred] Figure 3 shows the library expanding to 100 skills, but no analysis of retrieval overhead.
- **Why unresolved:** Larger libraries increase context length and may introduce redundant or conflicting skills.
- **What evidence would resolve it:** Measure latency, token usage, and performance while varying library size; apply pruning (e.g., clustering) and test.

### Open Question 3
- **Question:** Do the learned skills transfer to out‑of‑distribution tasks or different domains?
- **Basis in paper:** [explicit] Experiments are limited to ALFWorld, WebShop, and seven QA datasets (Sec. 4.1), all similar text‑based settings.
- **Why unresolved:** It remains unknown whether skills capture abstract principles or only domain‑specific heuristics.
- **What evidence would resolve it:** Test on a novel text‑based environment (e.g., ScienceWorld) or continuous control task; measure zero‑shot performance and adaptation speed.

## Limitations
- Missing hyperparameters (similarity threshold δ, teacher generation settings) hinder exact replication.
- Reliance on proprietary teacher model (o3) limits reproducibility and raises cost barriers.
- Vague “diversity‑aware stratified sampling” for validation failures may introduce bias in skill updates.
- Evolution trigger (validation accuracy < 0.4) risks overfitting to validation set; no held‑out analysis provided.

## Confidence
- **Token compression (10–20×):** Medium  
- **ALFWorld/WebShop success rates:** Medium  
- **QA tasks SOTA (47.1%):** Low  

## Next Checks
1. **δ sensitivity:** Evaluate performance across δ ∈ {0.3, 0.5, 0.7} and report token reduction vs. success rate.  
2. **Teacher‑free ablation:** Replace o3 with self‑distillation (e.g., Qwen2.5‑72B); compare success rates, token usage, and cost.
