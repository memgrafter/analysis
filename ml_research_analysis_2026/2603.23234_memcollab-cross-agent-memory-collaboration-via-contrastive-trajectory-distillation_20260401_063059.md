# MemCollab: Cross-Agent Memory Collaboration via Contrastive Trajectory Distillation

## Quick Facts
- **arXiv ID:** 2603.23234
- **Source URL:** https://arxiv.org/abs/2603.23234
- **Reference count:** 35
- **Primary result:** By contrasting reasoning trajectories from heterogeneous agents, MemCollab builds a transferable memory bank that boosts accuracy across model sizes/architectures (e.g., Qwen2.5-7B: 52.2%→67.0% on MATH500) and reduces reasoning turns.

## Executive Summary
MemCollab tackles the challenge of creating a memory system that works across heterogeneous LLM agents. It constructs a shared, agent‑agnostic memory bank by contrasting correct and flawed reasoning trajectories from different agents on the same tasks, distilling abstract invariants while suppressing model‑specific biases. A task‑aware retrieval mechanism filters memories by predicted category, ensuring relevance. Evaluations on MATH500, GSM8K, MBPP, and HumanEval show consistent accuracy gains and improved inference efficiency for a wide range of models. The approach demonstrates that collaborative memory can serve as a reusable reasoning resource, generalizing across model families.

## Method Summary
The method consists of two phases: memory construction and memory‑augmented inference. During construction, a set of training tasks is solved by two heterogeneous agents producing trajectories \( \tau^+ \) (correct) and \( \tau^- \) (incorrect). A contrastive summarizer (the stronger agent’s LLM) extracts up to \( K \) abstract constraints from each pair, each pairing a required invariant (“enforce …”) with a forbidden pattern (“avoid …”). These constraints are stored in a memory bank together with task‑category labels predicted by an LLM classifier. At inference time, the target agent classifies a query into a category, retrieves the top‑\( p \) matching memories by TF‑IDF similarity, and conditions its multi‑step reasoning on those constraints.

## Key Results
- Significant accuracy improvements on four benchmarks: e.g., Qwen2.5‑7B on MATH500 (52.2% → 67.0%), Llama3‑8B on GSM8K (27.4% → 42.4%).
- Memory built from heterogeneous agents transfers well across model families, whereas single‑source memory degrades performance on out‑of‑family agents.
- Memory‑augmented agents reach correct solutions in fewer reasoning turns, indicating improved efficiency.

## Why This Works (Mechanism)
- **Contrastive distillation of agent‑agnostic invariants:** Contrasting correct vs. flawed trajectories from different agents isolates reasoning structure \( s \) from agent‑specific biases \( b \). This distills constraints that are reusable across architectures under the assumption that successful reasoning on a task shares common structure. *Break condition:* If agents employ fundamentally divergent strategies, contrast yields no transferable guidance.
- **Task‑aware retrieval ensures relevance:** By organizing memory by task category and filtering retrieval accordingly, irrelevant constraints are excluded. This leverages the observation that error patterns and invariants cluster by task type. *Break condition:* Systematic misclassification by the task classifier introduces noise that can outweigh gains.
- **Cross‑agent contrast promotes generalization:** Heterogeneous agents have independent biases; contrasting them cancels out idiosyncrasies while preserving shared reasoning principles. This produces an agent‑agnostic memory that transfers across model families. *Break condition:* If agents share a common bias (e.g., from similar training data), contrast fails to remove it, limiting transferability.

## Foundational Learning
- **Contrastive Learning (InfoNCE):** Provides theoretical grounding for extracting shared, transferable features from positive/negative pairs. The contrastive objective encourages representations that bring positive trajectories together while pushing negatives apart. *Quick check:* How does InfoNCE encourage capturing shared structure rather than superficial patterns?
- **Task Categorization & Retrieval Conditioning:** Underpins the mechanism that filters memories by predicted category. Understanding that reasoning errors are category‑specific (empirically shown via Jensen–Shannon divergence) justifies conditioning retrieval. *Quick check:* Why might category‑conditioned retrieval be more effective for reasoning than pure embedding similarity?
- **Trajectory Decomposition (s vs. b):** Models reasoning as a combination of task‑level structure \( s \) (transferable) and agent‑specific bias \( b \) (non‑transferable). Contrast aims to distill \( s \) by canceling independent \( b \). *Quick check:* Provide an example of a model‑specific bias in code generation that does not belong to the underlying reasoning structure.

## Architecture Onboarding
- **Component map:**  
  Training: Trajectory Generator (heterogeneous agents) → Contrastive Summarizer (LLM) → Task Classifier (LLM) → Memory Bank (stores constraint + category).  
  Inference: Query → Task Classifier (target agent’s LLM) → Retriever (TF‑IDF filter + similarity) → Inference Agent (solves with retrieved constraints).
- **Critical path:** Generate paired trajectories per task → Extract abstract constraints → Assign categories → Store. At test time: classify query → retrieve matching memories → condition agent reasoning.
- **Design tradeoffs:**  
  - \( K \) (max constraints per task): larger \( K \) increases coverage but risks noise; paper finds \( K=3 \) effective.  
  - \( p \) (retrieval size): more memories broaden guidance but beyond a task‑specific threshold degrade performance.  
  - Classifier fidelity: using the agent’s own LLM is cheap but misclassifications directly harm retrieval.
- **Failure signatures:**  
  - Noisy memory (constraints are vague or task‑specific).  
  - Category mismatch (classifier error includes irrelevant memories).  
  - Cross‑architecture collapse (contrast fails to suppress shared biases, offering no transfer gain).
- **First 3 experiments:**  
  1. Inspect sampled memory entries to verify abstractness and lack of task‑specific details.  
  2. For a held‑out task, manually check top‑retrieved memories for category match and applicability.  
  3. Train memory on one model pair (e.g., Qwen‑7B + 32B) and test on another (Llama3‑8B); compare against self‑memory and vanilla baselines.

## Open Questions the Paper Calls Out
1. **Multi‑agent contrast:** How to extend the binary contrast formulation to more than two agents when the preferred trajectory is ambiguous? Aggregation strategies (majority voting, weighting) need empirical and theoretical study.
2. **Lifelong updates:** How can the memory bank be incrementally updated as new tasks and agents emerge without catastrophic forgetting of previously distilled constraints? Requires principled update policies (replay, consolidation, selective overwriting).
3. **Generalization beyond structured domains:** Does contrastive memory construction work in open‑ended domains (e.g., creative writing) where reasoning invariants are less explicit and multiple valid strategies exist? Human‑evaluated quality metrics would be needed.

## Limitations
- Implementation details (prompts for self‑contrast, exact handling of task classification, constraint formatting) are not fully specified, complicating faithful reproduction.
- The accuracy of the LLM‑based task classifier is not reported; misclassifications could significantly degrade retrieval quality.
- The core assumption that heterogeneous agents share reasoning invariants may fail if they adopt fundamentally different solution strategies.
- Evaluation is limited to two model families (Qwen, Llama); broader cross‑architecture generalization remains unproven.

## Confidence
- Contrastive distillation extracts agent‑agnostic invariants: **Medium**
- Task‑aware retrieval improves relevance: **Medium**
- Cross‑architecture memory transfer works: **Medium**
