# Accelerating Diffusion-based Video Editing via Heterogeneous Caching: Beyond Full Computing at Sampled Denoising Timestep

## Quick Facts
- arXiv ID: 2603.24260
- Source URL: https://arxiv.org/abs/2603.24260
- Reference count: 37
- Primary result: Up to 2.67× latency speedup and FLOPs reduction from 145.21P to 23.60P with negligible quality loss.

## Executive Summary
The paper tackles computational inefficiency in Diffusion Transformer (DiT)-based video editing, where redundant operations occur across denoising timesteps and within spatio-temporal token attention. Existing caching methods fail to leverage architectural heterogeneity, especially in masked video-to-video editing where unmasked context tokens provide varying semantic guidance. The proposed HetCache is a training-free framework that exploits two-dimensional heterogeneity: it dynamically classifies timesteps into full, partial, or reuse regimes based on accumulated input change, and within full steps partitions tokens into generative, margin, and context groups using the editing mask. For partial steps, it selectively caches a representative subset of context tokens via K-Means clustering and sparse attention scores. Evaluations on V ACE-Benchmark and VPBench with Wan2.1-V ACE show up to 2.67× speedup and FLOPs reduction from 145.21P to 23.60P, with negligible degradation in PSNR, SSIM, VFID, and VBench scores.

## Method Summary
HetCache is a training-free acceleration method for DiT-based video editing. It dynamically schedules denoising timesteps into three regimes (reuse, partial, full) by accumulating relative L1 change in modulated inputs (timestep embedding multiplied by latent). In full steps, tokens are partitioned using the editing mask into generative, margin, and context groups. For partial steps, context tokens are reduced by K-Means clustering (K=16) and selection based on cached attention scores to generative tokens (top 70% per cluster). The model is then run on the reduced token set (generative, margin, and selected context). Cached outputs are updated via EMA after partial steps. This reduces redundant computations both across timesteps and within attention.

## Key Results
- Latency speedup: up to 2.67×.
- FLOPs reduced from 145.21P to 23.60P.
- Negligible quality degradation on PSNR, SSIM, VFID, VBench.

## Why This Works (Mechanism)

### Dynamic Timestep Regime Scheduling
HetCache reduces computation by adaptively scheduling denoising timesteps into full, partial, or reuse regimes based on accumulated input change. It computes a relative L1 distance between modulated inputs (timestep embedding * noise latent) of consecutive timesteps and accumulates it over a window. A threshold Δ classifies the current step: if accumulated distance D ≤ Δ, it’s a Reuse step (cache output); if Δ < D ≤ 1.5Δ, it’s a Partial step (refresh subset of tokens); if D > 1.5Δ, it’s a Full step (recompute all). This exploits temporal redundancy in the diffusion trajectory. The core assumption is that modulated input change correlates with output variation; small changes imply local stability, so cached outputs are valid. Evidence includes similar ideas in TeaCache and token-wise caching, though HetCache’s thresholds are heuristic. A break condition occurs if the correlation fails in high-noise early steps.

### ROI-guided Token Partitioning
Within full-compute steps, HetCache reduces attention cost by partitioning spatio-temporal tokens into Generative, Margin, and Context groups using the editing mask. The mask defines: Generative tokens (inside mask), Margin tokens (adjacent boundary), and Context tokens (unmasked far). This spatial prior ensures critical interactions: Generative↔Margin for boundary smoothness and Generative↔Context for semantic guidance, while making Context↔Context attention selectively cacheable. The core assumption is that Context tokens have uneven relevance to the masked region, making many Context↔Context interactions redundant. No direct corpus evidence; effectiveness is shown by ablations. Risk: if mask boundaries are ambiguous or global changes are needed, misclassification may harm consistency.

### Representative Context Token Selection
For partial-compute steps, HetCache selects a small, representative subset of Context tokens using K-Means clustering for semantic diversity and cached sparse attention scores for relevance to Generative tokens. The full set of Context tokens X_ctx is clustered into K semantic groups (K=16). Within each cluster, tokens are ranked by their average cached attention weight to Generative tokens (α_i). The top r_ctx (0.7) per cluster is selected (X*_ctx). This subset, with all Margin and Generative tokens, forms a reduced token set, lowering attention complexity. The core assumption: semantic clustering approximates token diversity, and cached attention scores are valid proxies for future relevance. Evidence from ablations shows disabling either clustering or correlation harms metrics. Break conditions: poor K choice or stale attention scores can cause semantic drift.

## Foundational Learning

### Diffusion Denoising Process
**Why needed here:** HetCache’s timestep scheduling and feature caching operate within the iterative reverse diffusion process. Understanding how noise is progressively removed, the role of timestep embeddings, and how model outputs change across timesteps is essential to grasp why input change estimates output variation and how caching affects the trajectory.
**Quick check question:** If the accumulated input change between timesteps t and t+1 is very small, what does that imply about the model’s output at t+1 relative to t, and why is it safe to reuse the cached output?

### Diffusion Transformer (DiT) Architecture
**Why needed here:** HetCache targets DiTs, not U-Net denoisers. DiTs reshape latents into spatio-temporal tokens and use self-attention across all tokens. This token-based structure enables the token-level heterogeneity analysis and caching (e.g., partitioning tokens, reducing attention set). Knowing DiT’s tokenization and attention pattern is key to understanding the quadratic cost and the token-group interactions.
**Quick check question:** In a DiT processing a video, how does the number of attention FLOPs scale with the number of spatio-temporal tokens, and why does this make token-level caching impactful?

### Attention Mechanism in Transformers
**Why needed here:** The core computational burden HetCache reduces is the self-attention operation. Understanding that attention computes pairwise token interactions (QK^T) and aggregates values (softmax·V) is necessary to see why reducing the token set (especially Context tokens) lowers cost. Also, the concept of attention scores as a measure of token relevance underpins the correlation-based selection.
**Quick check question:** If you reduce the number of Context tokens participating in attention from N to M (keeping all Generative and Margin tokens), how does the attention FLOPs change approximately, and which attention sub-matrices are most affected?

## Architecture Onboarding

### Component Map
HetCache consists of the following interconnected components:
- **Input Modulation Unit**: Computes modulated input \(F_t = T_t \otimes x_t\).
- **Cumulative Distance Tracker**: Maintains accumulated relative L1 change \(D\) between consecutive \(F_t\).
- **Regime Scheduler**: Uses \(D\) and thresholds \(\Delta\) to classify timesteps as Reuse, Partial, or Full.
- **Spatial Token Partitioner**: (Only in Full steps) Uses editing mask \(M\) to split tokens into Generative, Margin, Context.
- **Context Token Selector**: (Only in Partial steps) Clusters Context tokens via K-Means and selects top \(r_{ctx}\) per cluster based on importance \(\alpha_i\) from cached attention.
- **Cache Manager**: Holds \(O_{\text{cache}}\); updates via EMA after Partial steps; overwrites after Full steps; provides output on Reuse steps.
- **Denoising Step Executor**: Orchestrates the above per timestep and updates the latent.

### Critical Path
For each timestep \(t\):
1. Compute \(F_t\) and update \(D\).
2. If \(D \leq \tau_{\text{reuse}}\) and cache exists, **Reuse**: output = \(O_{\text{cache}}\).
3. Else if \(D \leq \tau_{\text{partial}}\), **Partial**:
   a. Partition tokens (X_gen, X_mar, X_ctx) via mask \(M\).
   b. Cluster X_ctx; compute \(\alpha_i\) from last Full step’s cached attention; select X*_ctx.
   c. Run model on X_gen ∪ X_mar ∪ X*_ctx → O_t.
   d. Update O_cache only at computed positions: \(O_{\text{cache}}[pos] = (1-\gamma)O_{\text{cache}}[pos] + \gamma O_t[pos]\) (EMA).
   e. Reset \(D\).
4. Else, **Full**:
   a. Partition tokens (same as above, but all tokens used).
   b. Run model on all tokens → O_t.
   c. O_cache = O_t; reset \(D\).
5. Use O_t to update noise latent \(x_{t-1}\).

### Design Tradeoffs
- **Speed vs. Quality**: Lower \(r_{\text{ctx}}\) and smaller \(K\) increase speed but risk losing semantic diversity/relevance. Paper finds \(r_{\text{ctx}}=0.7\), \(K=16\) as sweet spot.
- **Aggressiveness vs. Stability**: Smaller \(\Delta\) triggers more Reuse/Partial steps → higher speed but may accumulate error; larger \(\Delta\) → fewer but safer.
- **Overhead vs. Gain**: K-Means clustering adds overhead; for very small X_ctx, it may outweigh attention savings. Assumed negligible.
- **Cache Update Strategy**: EMA factor \(\gamma\) smooths cache; Full steps reset completely.

### Failure Signatures
- **Semantic drift in masked region**: Generative tokens lack coherent context guidance → inconsistent textures/objects. Likely cause: \(X^*_{\text{ctx}}\) too small (low \(r_{\text{ctx}}\)) or poor clustering.
- **Boundary artifacts**: Sharp edges/ghosting at mask boundary. Likely cause: Margin tokens misdefined or incorrectly pruned (but HetCache preserves all Margin, so mask inaccuracies).
- **Temporal flickering**: Inconsistent semantics across frames. Likely cause: cached attention becomes stale; or overuse of Reuse steps.
- **No speedup**: FLOPs/latency near baseline. Likely cause: \(\Delta\) too conservative (always Full) or \(r_{\text{ctx}}\) too high.

## Open Questions the Paper Calls Out
- **Generalization to maskless tasks**: HetCache relies on an explicit editing mask; it's unclear if it can be applied to text-to-video generation where token roles are not predefined.
- **Non-monotonic K effect**: The optimal cluster count K does not improve quality monotonically; the underlying reason is not analyzed.
- **Adaptive thresholds**: Fixed thresholds (τ_reuse, τ_partial, Δ) may be suboptimal across different videos or layers; dynamic adaptation could improve trade-offs.
- **Layer-specific caching**: Token relevance likely varies by DiT depth, but HetCache uses uniform caching across layers; layer-adaptive strategies might yield better results.

## Limitations
- **Hyperparameter gaps**: Margin width, attention source layer, clustering feature space, and EMA factor are not specified, requiring educated guesses.
- **Generalization scope**: Evaluated only on masked video editing (MV2V) with Wan2.1-V ACE; performance on other DiT architectures or un-masked tasks is unknown.
- **Assumption fragility**: The correlation between modulated input change and output stability might not hold in early high-noise steps or for videos with large motion, risking quality degradation.

## Confidence
- **Efficiency gains (speedup, FLOPs reduction):** Medium – results are benchmark-specific and depend on thresholds.
- **Quality preservation (metrics):** Medium – some degradation observed in ablations; "negligible" may not hold universally.
- **Synergy of mechanisms:** Medium-High – supported by Table 3 ablations.
- **General applicability to other tasks/models:** Low – only Wan2.1-V ACE on MV2V evaluated.
