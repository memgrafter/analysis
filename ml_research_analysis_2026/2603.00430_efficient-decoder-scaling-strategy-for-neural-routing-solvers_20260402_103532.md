# Efficient Decoder Scaling Strategy for Neural Routing Solvers

## Quick Facts
- **arXiv ID**: 2603.00430
- **Source URL**: https://arxiv.org/abs/2603.00430
- **Reference count**: 40
- **Primary result**: Deep-narrow decoder architectures (high depth, low width) achieve superior parameter and data efficiency for TSP solving, with near-linear scaling from depth versus diminishing returns from width.

## Executive Summary
This paper investigates scaling decoder-only transformers for constructive neural routing solvers on the Traveling Salesman Problem. Through systematic experiments across 12 model configurations ranging from 1M to 150M parameters, the authors reveal that parameter count alone is insufficient to predict performance; instead, depth and width obey distinct scaling laws. Depth scaling yields near-linear improvements in optimality gap (exponent α_n ≈ 0.98–1.05), while width scaling shows diminishing returns (α_n ≈ 0.24–0.40). Consequently, deep-narrow models outperform wide-shallow counterparts in parameter and data efficiency, generalizing better to larger problem instances. The study derives practical design principles: prioritize depth in parameter allocation, use deep models when data is scarce, and scale depth with compute budget.

## Method Summary
The study trains decoder-only transformers with Gated Attention and ReZero normalization via supervised learning on 60 million TSP100 instances. Models vary depth (L=6,12,24,42) and width (d=128,256,512). Node embeddings are linear projections of 2D coordinates. Training uses AdamW (lr=1.25e-4, weight decay=0.01), batch size 1024, and exponential learning rate decay for 60,000 steps. A critical inference correction scales attention scores by log(n_tr/n_te) to generalize to larger test sizes. Evaluation uses greedy or beam search, measuring optimality gap against LKH3 solutions. Results are analyzed via power-law exponents for parameter, data, and compute scaling.

## Key Results
- Depth scaling yields near-linear performance gains (α_n ≈ 0.98–1.05); width scaling exhibits diminishing returns (α_n ≈ 0.24–0.40).
- Deep-narrow models achieve better parameter and data efficiency: on TSP1000, a 9M-parameter deep model attains 0.869% gap versus 1.291% for a 21M wide model.
- Design principles: allocate parameters to depth over width; use deep models with limited data; scale depth with compute budget.

## Why This Works (Mechanism)
The distinct scaling laws arise because increasing depth enhances the model’s ability to iteratively refine tours through multiple transformer layers, effectively capturing complex dependencies in the routing process. In contrast, increasing width expands the embedding space but yields diminishing returns as additional dimensions do not translate linearly to expressive power for this task. The `log(n)` correction mitigates distribution shift between training and test sizes by normalizing attention scores, enabling cross-size generalization. Deep-narrow architectures thus optimize parameter efficiency by maximizing computational steps per parameter while maintaining manageable memory.

## Architecture Onboarding
Component map: Input Coordinates -> Linear Embedding -> Transformer Decoder (L layers with Gated Attention + ReZero) -> Output Projection -> Masking (prevent duplicate visits) -> Greedy/Beam Decoding -> Tour

Critical path: Generate TSP100 dataset with Concorde -> Initialize model (depth L, width d) -> Forward pass with masking -> Compute cross-entropy loss -> Backpropagate with AdamW -> Periodically evaluate on validation set -> After 60k steps, test on TSP100/200/500/1000 with `log(n)` correction.

Design tradeoffs: Depth vs width: depth improves efficiency but increases memory and may destabilize training; width increases memory linearly but yields less gain. Data size: more samples improve convergence but require longer training. Inference method: greedy is fast but beam search may improve quality at cost of time.

Failure signatures:
- Training loss spikes/NaNs for deep models (L≥24) → likely ReZero or LR misconfiguration.
- Large gaps on TSP500/1000 without `log(n)` → correction not applied.
- Convergence to high gap with small dataset → insufficient training data (<10M).
- Out-of-memory on large models → need gradient checkpointing or multi-GPU.
- Beam outputs identical → missing deduplication in beam search.

First experiments:

## Open Questions the Paper Calls Out
The paper does not explicitly list open questions. However, based on the limitations and implications, potential open questions include:
- How do the scaling laws generalize to other routing problems such as CVRP or VRPTW?
- Do the findings hold for reinforcement learning settings instead of supervised learning?
- What are the depth limits beyond which training becomes unstable or performance gains saturate?

## Limitations
- Implementation details (Gated Attention, ReZero, beam search) are under-specified, potentially affecting reproducibility.
- Findings are limited to TSP with 2D uniform coordinates and supervised learning; generalization to other routing problems or RL settings is unknown.
- Models only scale up to 150M parameters; behavior beyond this regime is unexplored.

## Confidence
- **Depth scaling near-linear (α≈0.98–1.05)**: Medium – observed trend but sensitive to architecture stability.
- **Width scaling diminishing returns (α≈0.24–0.40)**: Medium – consistent within tested range, may shift with larger widths.
- **Deep-narrow models superior in parameter/data efficiency**: High – robustly validated across multiple test sizes.
- **Design principles (prioritize depth, deep models with scarce data, scale depth with compute)**: Medium – empirically derived, needs cross-domain verification.
