# According to Me: Long-Term Personalized Referential Memory QA
## Quick Facts
- arXiv ID: 2603.01990
- Source URL: https://arxiv.org/abs/2603.01990
- Reference count: 40
- Primary result: Schema-Guided Memory (SGM) improves QA scores by up to 20% on the hard set over Descriptive Memory, achieving 47.3% vs 25.6% under oracle retrieval.

## Executive Summary
This paper addresses long-term personalized memory question answering across multimodal sources (images, videos, emails). It introduces ATM-Bench, a benchmark containing approximately four years of privacy-preserved personal data and 1,038 human-annotated QA pairs, along with Schema-Guided Memory (SGM) for structured representation of memories. Evaluation of five state-of-the-art memory systems and RAG baselines reveals poor performance on the hard subset, with the best end-to-end accuracy below 20%. Notably, SGM consistently outperforms Descriptive Memory, delivering up to 20% higher QA scores in oracle retrieval settings (47.3% vs 25.6% on ATM-Bench-Hard) and improving retrieval metrics across systems. Additionally, the study finds that a simple flat vector index (Piled Memory) often surpasses more complex graph-based Linked Memory while being dramatically more efficient.

## Method Summary
The authors formalize Memory QA into three modular stages: (1) **Memory Ingestion** – raw multimodal data is converted into either Descriptive Memory (free text) or Schema-Guided Memory (structured key-value pairs), with optional organization via Piled (flat index) or Linked (graph) structures; (2) **Retrieval** – dense vector maximum inner product search (MIPS) fetches the top-k relevant memory items; (3) **Answer Generation** – a multimodal LLM produces answers in required formats (exact match, list recall, or open-ended). Experiments are conducted on ATM-Bench, which provides ~12k memory items (emails, images, videos) spanning four years and 1,038 human-annotated QA pairs with ground-truth evidence. The hard subset requires multi-evidence reasoning across long temporal spans. Evaluation uses Question Type Score (type-specific metrics), Recall@10, Joint@10, and memory encoding time.

## Key Results
- Best accuracy on ATM-Bench-Hard without oracle retrieval is below 20% for all systems.
- SGM yields up to 20% higher QA scores in oracle conditions (47.3% vs 25.6%).
- Piled Memory outperforms or matches Linked Memory while reducing encoding time by an order of magnitude.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: Schema‑Guided Memory (SGM) yields higher QA accuracy than Descriptive Memory (DM) because its structured fields better align with retrieval embeddings.
- **Mechanism**: SGM normalizes each memory item into fixed key‑value pairs (time, location, entities, OCR, tags). This explicit structure emphasizes semantically salient tokens that embedding models can match precisely, improving recall of relevant evidence. Under oracle retrieval, SGM lifts QA scores by ~20% on the hard set; with real retrievers, it consistently improves both recall and joint metrics across systems.
- **Core assumption**: The predefined schema covers all attributes critical for referential reasoning (e.g., temporal, spatial, entity cues). If queries rely on information outside the schema (e.g., visual style, emotional tone), SGM’s benefit may vanish.
- **Evidence anchors**:
  - Abstract: "SGM consistently improves over Descriptive Memory, achieving up to 20% higher QA scores in oracle conditions (47.3% vs 25.6% on ATM‑Bench‑Hard) and better retrieval metrics across systems."
  - Section 4.2: Formal definitions of DM and SGM with concrete examples.
  - Corpus: Related benchmarks (PerLTQA, LifeBench) use unstructured text, underscoring SGM’s novelty as a schema‑driven approach.
- **Break condition**: Queries requiring attributes not encoded in the schema (e.g., "How did the atmosphere feel?") would prevent SGM from retrieving relevant evidence, degrading performance.

### Mechanism 2
- **Claim**: Piled Memory (flat index) often outperforms Linked Memory (graph‑based links) for personal memory QA while being dramatically more efficient.
- **Mechanism**: Linked Memory builds a graph of memory items via LLM‑inferred relations and expands retrieval through traversal. This adds computational overhead and may introduce spurious links that distract from direct attribute matching. Piled Memory uses a simple vector index; retrieval returns the most similar items directly. For the majority of queries on ATM‑Bench—even those needing multi‑evidence composition—this simplicity suffices, as shown by improved or comparable QA scores and far lower encoding times.
- **Core assumption**: Personal memory queries are primarily satisfied by retrieving individually relevant items, not by multi‑hop reasoning over a graph. If a query explicitly demands relational chains (e.g., "Who did I meet after the conference?"), Linked Memory might become necessary.
- **Evidence anchors**:
  - Section 5.2: "We modified A‑Mem to use Piled Memory organization and find performance improves compared to its original Linked Memory setting. This is achieved with substantially reduced encoding time (12.6h → 1.6h)."
  - Table 3, Rows 4 vs 5: A‑Mem DM Piled QS 46.1 vs Linked 44.8; encoding time 1.2h vs 12.6h.
  - Corpus: HippoRAG2 (Gutiérrez et al., 2025) employs Linked Memory (graph traversal) and scores lower than SGM‑based Piled systems (e.g., ATM‑RAG SGM Piled 51.0 QS vs HippoRAG2 SGM Linked 47.7) in our experiments.
- **Break condition**: Queries requiring evidence that is only connected via inferred links (e.g., following a sequence of events) would expose Piled Memory’s limitation.

### Mechanism 3
- **Claim**: The three‑stage decomposition (Memory Ingestion, Retrieval, Answer Generation) provides a modular framework that isolates component effects, enabling clear causal analysis of design choices.
- **Mechanism**: By treating ingestion, retrieval, and answering as separate stages, researchers can vary one factor (e.g., memory representation) while holding others constant. The paper’s experiments use this decomposition to demonstrate that SGM improves retrieval and QA, that Piled memory is efficient, and that agentic answering does not consistently help on hard queries. Without modularity, attributing performance differences to specific design decisions would be difficult.
- **Core assumption**: The three stages are sufficiently decoupled; gains in one stage (e.g., better memory representation) will reliably propagate to end‑to‑end performance. Strong interdependencies could break this assumption.
- **Evidence anchors**:
  - Abstract: "We formulate the Memory QA task into three steps... This formalism well describes current Memory QA approaches and provides a framework for comparing system designs."
  - Section 4.1: Presents the pipeline (Figure 2) and formal equations (Eqs. 5–7).
  - Section 5: Results are organized by stage (e.g., representation in Table 3, retrieval in Table 5), showing the decomposition’s utility.
- **Break condition**: If future systems merge stages into an end‑to‑end model (e.g., an LLM that directly processes raw assets without a distinct retrieval step), the decomposition may lose analytical clarity, though it remains conceptually useful.

## Foundational Learning
- **Multi-modal Retrieval**  
  *Why needed here*: The memory corpus contains images, videos, and emails; retrieval must operate across modalities. The paper typically converts non‑text data into textual fields (OCR, tags, captions) or uses multimodal embeddings.  
  *Quick check*: "When using SGM, which fields from an image are used for retrieval, and how are they combined?"

- **Structured vs Unstructured Data Representation**  
  *Why needed here*: The core innovation (SGM) contrasts with DM; understanding the trade‑offs between key‑value schemas and free‑form text is essential to grasp why SGM works.  
  *Quick check*: "List two advantages of SGM over DM and one scenario where DM might be preferable."

- **Evaluation of Personal Memory QA**  
  *Why needed here*: The paper introduces Question Type Score (QS) and Joint@k to handle diverse answer formats and ensure evidence usage. These metrics are crucial for interpreting results.  
  *Quick check*: "Why does the paper use Jaccard similarity for list‑recall answers instead of exact match?"

- **Privacy‑Preserving Data Processing**  
  *Why needed here*: The benchmark derives from real personal data; all released content underwent anonymization (face blurring, LLM rewriting, synthetic PII injection). Any reproduction must follow similar safeguards.  
  *Quick check*: "Describe the three‑stage pipeline for anonymizing images before release."

## Architecture Onboarding
**Component map**:  
Offline: Raw data → preprocessing (DM/SGM conversion) → optional linking (graph construction) → embedding generation → vector index.  
Online: Query → query embedding → top‑k retrieval (vector search) → retrieved items (including raw images/videos) → answer generation (multimodal LLM) → answer.

**Critical path**:  
1. Ingest each memory item into a normalized representation (DM or SGM).  
2. Encode items into vectors and build a FAISS‑like index.  
3. At query time, encode the query with the same embedding model.  
4. Retrieve top‑k items by inner‑product similarity.  
5. Feed query and retrieved items (with raw visuals) to the answerer LLM.  
6. Output answer in the expected format.

**Design tradeoffs**:  
- DM vs SGM: DM is faster to generate but may bury key details; SGM requires schema design but improves alignment.  
- Piled vs Linked: Piled is extremely fast to build and often more accurate; Linked adds graph traversal that can support multi‑hop but increases encoding cost (12× slower) and may add noise.  
- Embedding size: Larger models boost recall but raise indexing and retrieval latency; MiniLM is cheap but less expressive.  
- Single-pass vs agentic answerer: Agentic loops (e.g., Mem0) can refine retrieval but on the hard set show no consistent gain and add latency.  
- Raw visual inputs vs text‑only: Supplying raw images to the answerer may capture details missing from SGM fields but increases context length and compute.

**Failure signatures**:  
- Temporal update failure: Model picks outdated evidence when newer, contradictory records exist (e.g., using a booking confirmation instead of a final invoice).  
- Location aliasing: Model trusts erroneous GPS coordinates, selecting the wrong venue despite visual cues indicating the correct one.  
- Inadequate multi‑evidence aggregation: Questions requiring several pieces across sources yield low Joint@k, indicating the retriever missed some needed items.  
- Over‑reliance on textual fields: When SGM fields are sparse (e.g., missing OCR), retrieval fails to find relevant images.

**First 3 experiments**:  
1. **SGM vs DM replication**: Implement ATM‑RAG with both representations and evaluate on the full test set; expect ~5% absolute QS improvement with SGM (Table 3, rows 8 vs 9).  
2. **Memory organization ablation**: Compare A‑Mem in Piled and Linked modes; measure encoding time and QS. Piled should be >10× faster and at least as accurate (Table 3, rows 4 vs 5).  
3. **Retriever ablation**: Systematically vary embedding models (MiniLM‑L6, Qwen3‑0.6B, Qwen3‑4B) and optionally add a reranker; record R@10 and QS to observe the tight correlation between retrieval quality and end‑to‑end performance (Table 5).

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: Why do state-of-the-art memory systems, even with oracle retrieval, still fail to achieve high accuracy on ATM-Bench-Hard, and what specific architectural or reasoning improvements are needed to handle long-term, multi-evidence aggregation?
- **Basis in paper**: [explicit] The authors state that "even state-of-the-art models operating under gold-evidence conditions consistently fail to answer correctly" on hard queries requiring memory updates and multi-source reasoning (Sec. 5.3, Appendix F). The best oracle accuracy is 74.7% on ATM-Bench-Hard, indicating answer-generation bottlenecks beyond retrieval.
- **Why unresolved**: The paper identifies poor Hard-set performance (<20% without oracle) but does not isolate whether the failure stems from inability to reason over many retrieved items, reconcile conflicting evidence, or track temporal updates.
- **What evidence would resolve it**: Controlled experiments varying evidence count, conflict types, and temporal spans with oracle retrieval; error analysis categorizing specific reasoning failures (e.g., numerical aggregation, temporal ordering, entity disambiguation).

### Open Question 2
- **Question**: What specific properties of Schema-Guided Memory (SGM) enable its consistent improvement over Descriptive Memory (DM) across systems—is it better retrieval precision, more structured grounding for answer generation, or both?
- **Basis in paper**: [explicit] SGM yields "substantially improved" retrieval metrics and up to 20% higher QA scores in oracle conditions (Abstract, Sec. 5.2). However, the paper does not disentangle whether gains come primarily from retrieval (better embedding similarity due to structured fields) or from answer generation (LLM can parse key-value pairs more reliably than free text).
- **Why unresolved**: The ablation compares DM vs. SGM end-to-end but does not hold retrieval constant to isolate the answer-generation effect, nor does it analyze which schema fields are most beneficial.
- **What evidence would resolve it**: Experiments with fixed retrieval (e.g., same retrieved set) but different memory representations (DM vs. SGM) fed to the answerer; probing which schema fields (time, location, entities) correlate most with correct answers; studying failure cases where SGM still fails.

### Open Question 3
- **Question**: How can memory systems better leverage video content, given that videos are a significant but underperforming modality in ATM-Bench?
- **Basis in paper**: [inferred] The corpus includes 533 videos (Table 2), but the retriever baseline using Qwen3-VL-Embedding performs worse than text-only embedders (Table 5). The authors note that high-resolution visual tokens "dilute the critical metadata signals." Videos are sampled to ≤8 frames, likely losing temporal dynamics. No system explicitly models video temporal structure or audio.
- **Why unresolved**: The paper does not evaluate video-specific architectures (e.g., video-language models) or study how video retrieval differs from image retrieval. The poor VL-embedder performance suggests current methods cannot effectively index video content for personalized queries.
- **What evidence would resolve it**: dedicated video-encoder baselines (e.g., TimeSformer, VideoLLaMA) vs. frame-averaging; evaluation of video-only vs. multimodal queries; analysis of video-related question performance breakdown.

### Open Question 4
- **Question**: Can memory agents learn to perform temporal memory updates (MUT) robustly, and what inductive biases or training signals are needed to prioritize newer evidence over outdated records?
- **Basis in paper**: [explicit] MUT is a core challenge (Sec. 3.2, Figure 1b). Error analysis (Appendix F.1) shows GPT-5 with oracle retrieval picks outdated booking confirmations over updated invoices. The authors note "memory evolution over time in a more realistic manner" is not solved.
- **Why unresolved**: No memory system in the paper explicitly models time (e.g., timestamp confidence, recency weighting, versioning). The retrieval is similarity-based without temporal reasoning; answer generation is not instructed to resolve conflicts by time.
- **What evidence would resolve it**: Augmenting SGM with explicit "last updated" timestamps and training/ prompting to prefer newer records; evaluating on a held-out MUT subset with controlled conflicts; measuring performance decay as time gap between evidence items increases.

### Open Question 5
- **Question**: Does the human annotation process introduce distributional biases that make the benchmark easier for systems mimicking human query patterns but not necessarily more capable in deployment?
- **Basis in paper**: [inferred] The authors rejected agentic auto-annotation because generated questions were "analytical" rather than "human-likely" (Appendix B.1). Annotators were instructed to write "realistic, experience-driven user queries" with "partial or fuzzy recall." Thus, the benchmark favors questions that align with human memory recall behavior (entity/event-driven) over precise analytical queries.
- **Why unresolved**: It is unclear whether systems optimized for ATM-Bench's human-like query distribution would generalize to arbitrary user queries (including analytical ones). The benchmark may underrepresent queries requiring precise computation or temporal offset reasoning.
- **What evidence would resolve it**: Analyzing question-type distribution vs. real user logs from deployed assistants; creating a parallel analytical query split and comparing system performance; user studies to validate if benchmark questions match real needs.

## Limitations
- **Dataset availability**: ATM-Bench is not yet publicly released; exact test/hard splits and evidence mappings are unknown, blocking full reproducibility.
- **Schema coverage**: SGM relies on fixed fields (time, location, entities, OCR, tags); queries requiring unsupported attributes (e.g., emotional tone, visual aesthetics) may nullify its benefit.
- **Graph vs. flat generality**: Piled Memory's superiority may fail on queries requiring explicit multi-hop relational reasoning (e.g., sequential event chains).
