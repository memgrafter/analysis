# ROOFS: RObust biOmarker Feature Selection

## Quick Facts
- arXiv ID: 2601.05151
- Source URL: https://arxiv.org/abs/2601.05151
- Reference count: 40
- Primary result: A filter using the union of Benjamini-Hochberg adjusted p-values from t-test and logistic regression (0.05 threshold) achieved optimal stability (S=0.39) and optimism-corrected AUC (0.72) on the PIONeeR immunotherapy resistance dataset, with a 22-feature signature showing high selection consistency.

## Executive Summary
ROOFS is a comprehensive framework for benchmarking feature selection (FS) methods in high-dimensional biomedical data. It evaluates FS methods based on three key criteria: stability (consistency of selected features across bootstraps), optimism-corrected predictive performance (using .632+ bootstrap), and true/false discovery rates (via semi-synthetic outcomes). Applied to the PIONeeR dataset (435 patients, 214 features after VIF filtering), ROOFS tested 23 FS methods combined with 11 classifiers (253 models). The optimal method was a filter combining t-test and logistic regression p-values with Benjamini-Hochberg adjustment (threshold 0.05), yielding a stable 22-feature signature and an optimism-corrected AUC of 0.72. Filters generally outperformed embedded and ensemble methods in stability, while achieving comparable predictive power. ROOFS automates rigorous FS evaluation to enhance reproducibility and translational potential of biomarker discoveries.

## Method Summary
ROOFS implements a bootstrap-based evaluation pipeline. For each FS method, it generates B=100 bootstrap resamples of the data. Within each bootstrap, preprocessing (imputation, normalization) and FS are applied, then a classifier is trained on the selected features. Performance is estimated on the original dataset using optimism correction (Harrell’s method, .632, or .632+). Stability is computed via Nogueira’s frequency-based measure, which quantifies the consistency of feature selection across bootstraps. Additionally, semi-synthetic outcomes are simulated from a known subset of true predictors to compute true positive rate (TPR) and false positive rate (FPR). The framework produces detailed reports summarizing metrics, selection frequencies, and runtime, enabling comparative analysis of FS methods.

## Key Results
- Optimal FS method: union of BH-adjusted p-values from t-test and logistic regression (0.05 threshold) achieved stability S=0.39 and optimism-corrected AUC=0.72 on the PIONeeR dataset.
- The resulting 22-feature biomarker signature showed high selection consistency (>50% of bootstraps).
- Filters outperformed embedded/ensemble methods in stability and predictive power; the optimal filter also achieved high TPR (0.93±0.06) and low FPR (0.10±0.03) on semi-synthetic data.

## Why This Works (Mechanism)
### Mechanism 1: Bootstrap-Based Stability Assessment via Feature Frequency
ROOFS quantifies feature selection stability by measuring the consistency of selected features across bootstrap resamples. For each FS method, it generates B bootstrap samples (default B=100) and applies the identical FS pipeline, recording whether each feature is selected. Stability S is computed using Nogueira's frequency-based measure: S = 1 - (1/p) Σ_{f=1}^{p} (s_f^2)/(k(1 - k/p)), where s_f^2 is the unbiased variance of selection frequency for feature f, p is total features, and k is average subset size. S=1 indicates perfect consistency; S=0 indicates random selection. The core assumption is that stability across resamples approximates reproducibility on external datasets. High selection frequency for a feature indicates signal strength and robustness to sampling variation.

Evidence: [section 2.2.4] defines stability calculation and selection frequency as a signal strength indicator; [section 3.2] shows iterative VIF pre-filtering increases stability; [section 3.3] reports stability values (e.g., S=0.39 for p.adjust) and notes filters generally outperformed embedded methods.

Break condition: Insufficient bootstraps (B < 50) leads to unreliable variance estimates; methods with high intrinsic randomness may have stability near zero regardless of true signal.

### Mechanism 2: Optimism-Corrected Predictive Performance Estimation
ROOFS estimates downstream predictive performance of an FS + classifier pipeline without a separate hold-out test set, using bootstrap-based optimism correction (OC). For each FS-classifier combination, it trains the model on the full dataset (apparent performance θ_app) and on each bootstrap sample. For each bootstrap b, it computes performance (e.g., AUC) on (i) the bootstrap training data (θ_boot^{(b)}) and (ii) the original dataset (θ_orig^{(b)}). Optimism O = (1/B) Σ_b (θ_boot^{(b)} - θ_orig^{(b)}) is subtracted from θ_app to yield Harrell’s OC. The package also implements .632 and .632+ rules, with .632+ preferred for lowest bias in overfitting scenarios, adjusting weights based on an overfitting ratio R.

Core assumption: The difference between bootstrap training performance and performance on the original dataset estimates the optimism (overfitting) inherent in using the full dataset for both FS and training. The .632+ rule further corrects for the proportion of overlap between bootstrap and original samples.

Evidence: [section 2.2.3] details the three OC methods and formulas; [section 3.3] reports optimism-corrected AUC values and compares them to full-data performance; [Table 2] lists AUC as the primary performance metric derived via OC.

Break condition: If FS is highly unstable or the classifier is extremely misspecified, the optimism estimate may be biased because bootstrap model variations are not solely due to overfitting. Also, OC assumes the same data-generating process across bootstraps; if bootstrapping induces artificial clusters, optimism may be underestimated.

### Mechanism 3: Semi-Synthetic Outcome Simulation for True/False Discovery Trade-off
ROOFS evaluates FS methods' ability to identify true predictors (TPR) and control false discoveries (FPR) by simulating outcomes from a known subset of real features. It creates a semi-synthetic dataset by keeping the original feature matrix X but generating a synthetic outcome 𝑦̃ via a logistic model: score_i = 1/(1+exp(-Σ_{j∈S} β_j X_{ij} + ε_i)), 𝑦̃_i = 1 if score_i ≥ 0.5 else 0. Here, S is a pre-selected set of "true" features (e.g., 19 features from PIONeeR chosen via BH-adjusted p-values), and coefficients β_j are either randomly sampled (𝒩(2,0.5)) or estimated from real outcome regression. Each FS method is applied to X, 𝑦̃; TPR = proportion of features in S that are selected; FPR = proportion of features not in S that are selected.

Core assumption: The linear logistic model with added Gaussian noise, using real features from the dataset, provides a realistic yet controllable signal structure to benchmark discovery capability. Methods that recover S well are likely to identify true biomarkers.

Evidence: [section 2.1.3] describes the semi-synthetic generation process and coefficient derivation approaches; [section 3.4] presents TPR/FPR results (e.g., p.adjust TPR=0.93±0.06, FPR=0.10±0.03); [Table 2] includes FPR and TPR metrics.

Break condition: If true signal is strongly non-linear or involves complex interactions, the linear simulation may overestimate TPR for simple filters. Also, if the pre-selected true set S is itself unstable or incorrect, TPR/FPR evaluation may be misleading.

## Foundational Learning
### Concept: Feature Selection Algorithm Families (Filter, Embedded, Wrapper, Ensemble)
**Why needed here:** ROOFS benchmarks methods across all four families. Understanding their core principles explains why their stability and performance differ. Filters use statistical scores independent of models; embedded methods incorporate FS during training; wrappers use model performance as evaluation; ensembles aggregate multiple selections.
**Quick check:** Why might an embedded method like LASSO be less stable than a filter method like a t-test, especially in correlated data?

### Concept: Stability Metrics for Feature Selection
**Why needed here:** ROOFS centers its evaluation on stability (S) and selection frequency. Without understanding that stability measures agreement across resamples, one cannot interpret why p.adjust (S=0.39) is considered "stable" compared to LASSO (S=0.34).
**Quick check:** What does a stability score of 0.25 imply about the consistency of a feature selection method?

### Concept: Optimism Correction in Model Evaluation
**Why needed here:** ROOFS uses OC (especially .632+) to estimate predictive performance without sacrificing data to a test set, crucial for biomarker discovery with limited samples. One must grasp why apparent performance is optimistically biased and how OC adjusts for it.
**Quick check:** How does the .632+ rule differ from simple cross-validation in estimating generalization performance for a model that includes an FS step?

## Architecture Onboarding
### Component map
Data Input & Preprocessing -> FS Method Registry -> Classifier Registry -> Bootstrap Engine -> Metrics Aggregator -> Report Generator

### Critical path
Input Data → (Optional VIF) → For each FS method: For each bootstrap: [Impute → Normalize → FS → Train Classifier → Evaluate] → Aggregate metrics → Generate report

### Design tradeoffs
- **Computation vs. Coverage:** Benchmarking 23 FS methods × 11 classifiers × 100 bootstraps is computationally heavy (hours to days). The tradeoff is methodological comprehensiveness vs. runtime. Users can limit classifiers or exclude wrapper/ensemble methods for large p.
- **Stability vs. Performance:** The pipeline does not automatically choose the "best" method because the optimal trade-off (e.g., high stability vs. high AUC) is user/context-dependent. The report enables manual inspection.
- **Simplicity vs. Realism:** Semi-synthetic outcomes use a linear logistic model for TPR/FPR assessment. This simplifies interpretation but may not capture complex non-linear biomarker relationships present in real data.

### Failure signatures
- **High variance in stability across bootstraps for a single method:** Indicates insufficient bootstraps (B too low) or that the FS method is inherently unstable on this data structure.
- **All methods show very low stability (<0.1):** Suggests the dataset may have extremely high noise, very low sample size relative to feature dimensionality, or that the outcome is nearly independent of all features.
- **Optimism-corrected AUC > 0.95 for many methods:** Possible data leakage (e.g., outcome information used in preprocessing) or that the full dataset performance is already near-perfect and correction is inadequate.
- **Semi-synthetic TPR near 1 for all methods:** The simulated signal may be too strong or the "true" set S includes features highly correlated with others, making them easy to rediscover indirectly.

### First 3 experiments
1. **Baseline & VIF impact:** Run ROOFS on the PIONeeR dataset with full features (p=374) and then after iterative VIF (p=214). Compare stability distributions. Expected: Most methods show increased stability post-VIF, confirming multicollinearity reduction.
2. **Method family comparison:** Focus on representative methods: LASSO (embedded), p.adjust (filter), RF-RFE (wrapper), Stabl LASSO (ensemble). Compare their stability, AUC, and TPR/FPR. Expected: Filters (p.adjust) show best stability–AUC balance; ensemble methods show low FPR but also low TPR.
3. **Subset size investigation:** For p.adjust, inspect bootstrap distribution of selected subset sizes (Fig 5C). Then repeat with subsampling (80% without replacement). Expected: Bootstrapping inflates subset size due to sample-specific signals; subsampling yields tighter, smaller sets with higher stability, validating that observed sparsity instability is a bootstrap artifact.

## Open Questions the Paper Calls Out
### Open Question 1: Extension to regression and survival tasks
ROOFS currently only handles binary classification. Extending it to regression and survival prediction tasks would require different evaluation metrics (e.g., mean squared error, concordance index) and possibly tailored feature selection methods. The paper explicitly states this as future work but provides no implementation details. Evidence to resolve: a revised ROOFS version that integrates regression and survival models, validated on relevant datasets, with reliable optimism-corrected performance estimates.

### Open Question 2: Instability of resampling-based ensemble methods
The benchmark showed that ensemble feature selection methods (e.g., Bolasso, stability selection, Stabl LASSO, RENT) did not improve stability over standard LASSO, despite being designed to enhance consistency. The authors speculate that variability behind resampling procedures may be the cause, but this requires further investigation. Evidence to resolve: systematic experiments varying resampling schemes, sample sizes, and correlation structures; quantifying sources of instability; and modifying ensemble aggregation rules.

### Open Question 3: Impact of VIF threshold on false positive rate
The study used a fixed VIF threshold of 5. The authors note that the high FPR of p.adjust may be due to residual correlations and suggest investigating stricter VIF thresholds. It remains unknown whether more stringent thresholds (e.g., 2.5) would reduce false positives without compromising other metrics. Evidence to resolve: benchmark with a range of VIF thresholds, comparing FPR, TPR, stability, and AUC across FS methods.

### Open Question 4: Automated selection of optimal feature selection algorithm
ROOFS generates comprehensive reports but relies on manual choice of the best method. An automated recommendation system that selects the optimal FS algorithm based on dataset characteristics and user goals would improve usability and reproducibility. Evidence to resolve: a meta-analysis of benchmark results across diverse datasets to identify patterns linking data descriptors and performance metrics, and building a predictive model for method recommendation.

## Limitations
- Unknown hyperparameters: Exact settings (e.g., LASSO λ, ReliefF k) for all 23 FS methods are unreported, blocking exact replication.
- Semi-synthetic "true" set: The 19-feature predictor set used for TPR/FPR simulation was derived from PIONeeR-specific models; its composition is not public, limiting external validation.
- Generalizability: Findings are based on a single immunotherapy dataset; performance on other biomedical domains (e.g., genomics, imaging) remains unknown.

## Confidence
- **High**: ROOFS’s bootstrap-based evaluation framework (stability, optimism-corrected AUC) is rigorously defined and internally consistent.
- **Medium**: Claim that the p.adjust filter is optimal (S=0.39, AUC=0.72) is dataset-specific; relative performance may shift with different data characteristics.
- **Low**: Assertion that filters are universally more stable than embedded/ensemble methods lacks external validation and may not hold under varied correlation structures or sample sizes.

## Next Checks
1. **Independent dataset replication**: Apply ROOFS to a publicly available high-dimensional biomarker dataset (e.g., TCGA) to test generalizability of the p.adjust filter’s superiority.
2. **Hyperparameter sensitivity analysis**: For key FS methods (LASSO, RF-RFE), systematically sweep tuning parameters (λ, number of trees) to quantify robustness of stability and AUC rankings.
3. **Semi-synthetic realism check**: Compare TPR/FPR from ROOFS’s linear simulation against results using non-linear outcome models (e.g., random forest) on the same feature matrix to assess simulation bias.
