# SToRM: Supervised Token Reduction for Multi-modal LLMs toward efficient end-to-end autonomous driving

## Quick Facts
- **arXiv ID:** 2602.11656
- **Source URL:** https://arxiv.org/abs/2602.11656
- **Reference count:** 21
- **Primary result:** Achieves up to 30× FLOP reduction (from 30.8 to 1.02 TFLOPs with LLaVA) while matching or exceeding all-token driving performance, enabling real-time inference (>25 FPS) on a single GPU.

## Executive Summary
The paper presents SToRM, a framework that dramatically lowers the computational cost of multi-modal large language models (MLLMs) for end-to-end autonomous driving by reducing the number of visual tokens. SToRM introduces a supervised token reduction approach that leverages pseudo-supervision from all-token LLM attention scores to train a lightweight importance predictor. An anchor-context merging module then consolidates less important tokens into high-importance anchors. On the LangAuto benchmark, SToRM reduces FLOPs by up to 30× and achieves >25 FPS on a single GPU, while matching or surpassing the driving scores of models that use all visual tokens. Under a fixed token budget of 120 tokens, it also outperforms prior token reduction methods across multiple metrics and LLM scales.

## Method Summary
SToRM builds on the LMDrive architecture, which fuses multi-view RGB images, a BEV map, and language instructions via a frozen vision encoder and a frozen LLM backbone (LLaVA or TinyLLaVA). The core contributions are a lightweight importance predictor and an anchor-context merging (ACM) module. The predictor, an MLP-Mixer with short-term sliding windows, scores each visual token. During training, an auxiliary path processes all tokens through the LLM to extract column-wise mean attention scores from the last decoder layer; these serve as pseudo-supervision for the predictor (L1 loss). The ACM selects the top-K tokens as anchors per frame and merges the remaining context tokens into these anchors using a cross-attention mechanism with Gumbel-Softmax and Straight-Through Estimator (STE) to approximate hard assignments. The merged tokens (T×K) are concatenated with text tokens and fed to the LLM, whose outputs drive a two-layer MLP that predicts future waypoints, later converted to control commands via PID. Only the predictor and ACM parameters are trained, using loss L = L_wp + λ·L_score (λ=50). This design compresses the token sequence from T×N ≈ 3000 to T×K ≈ 120, drastically reducing FLOPs while preserving driving performance.

## Key Results
- Matches or exceeds driving performance (DS, RC, IS) of the all-token baseline while reducing computational cost by up to 30× (30.8 → 1.02 TFLOPs with LLaVA).
- Enables real-time inference (>25 FPS) on a single NVIDIA RTX 4090.
- Under a fixed budget of 120 tokens, SToRM significantly outperforms LMDrive and other heuristic token reduction methods across metrics and LLM scales.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Visual token importance for driving can be supervised by attention scores from an all-token MLLM pass, enabling learned reduction without heuristic rules.
- **Mechanism:** An auxiliary path processes all visual tokens through the frozen LLM. From the last decoder layer, column-wise mean attention scores across all queries are extracted as pseudo-importance labels. These supervise a lightweight predictor trained via L1 loss.
- **Core assumption:** Tokens that receive higher average attention from the LLM's final self-attention layer are more critical for the downstream driving task.
- **Evidence anchors:**
  - [abstract] "supervised token reduction using... pseudo-supervision signals derived from all-token LLM attention scores"
  - [section III-C] "we extract the attention score matrix... take the column-wise mean... pseudo importance scores"
  - [corpus] *Weak corpus evidence*: Neighbor papers discuss E2E driving but not attention-based pseudo-supervision for token reduction.
- **Break condition:** If the correlation between attention scores and task-critical visual features (e.g., pedestrians, traffic signs) is weak, the pseudo-supervision becomes misaligned, potentially degrading driving performance. Evidence: The paper assumes alignment but does not validate it directly (e.g., via ablation with shuffled attention).

### Mechanism 2
- **Claim:** A lightweight predictor using short-term spatio-temporal mixing within sliding windows can approximate full-context importance prediction at lower compute.
- **Mechanism:** The predictor uses MLP-Mixer blocks. Spatial mixing occurs within a frame. Temporal mixing is restricted to a sliding window (size `2ℓ+1`) across adjacent frames, avoiding full `T×N` interaction. Channel mixing operates per token.
- **Core assumption:** Driving-relevant importance signals are captured by local temporal contexts (a few frames) rather than long-range dependencies across all `T` frames.
- **Evidence anchors:**
  - [abstract] "lightweight importance predictor with short-term sliding windows"
  - [section III-B1] Eq. (2)-(3) define windowed token mixing; Table I shows reduced complexity `O(D·(2ℓ+1)²·(T/κ)·N²)` vs `O(D·(TN)²)`
  - [corpus] *Weak corpus evidence*: Neighbors focus on E2E benchmarks or self-supervised learning, not efficient token importance modeling.
- **Break condition:** If critical driving cues require integrating information across non-adjacent or distant frames (e.g., sequential traffic light states), the sliding window may miss long-term dependencies, harming performance. Evidence: The paper does not test varying `ℓ` on scenarios requiring long memory.

### Mechanism 3
- **Claim:** Merging context tokens into high-importance anchors via hard assignments reduces token count while preserving decision-critical information better than soft merging or anchor-only schemes.
- **Mechanism:** Top-K tokens by predicted importance become anchors. Remaining context tokens are assigned to a single anchor via Gumbel-Softmax approximation with Straight-Through Estimator (STE). Anchor features are updated with a weighted sum of assigned context values.
- **Core assumption:** A hard, many-to-one merging preserves the integrity of anchor representations (which encode salient cues) while absorbing complementary context, whereas soft merging dilutes anchor signals.
- **Evidence anchors:**
  - [abstract] "anchor-context merging module that consolidates less important tokens into high-importance anchors"
  - [section III-B2] Fig. 3(c) and Eq. (7)-(9) describe hard assignment via STE vs. soft merging baseline
  - [section IV-E] Table VI shows hard merging (44.2 DS) outperforms soft (40.1 DS) and anchor-only (41.8 DS)
  - [corpus] *No direct evidence*: Neighbors use different merging/pruning strategies (e.g., ToMe, VisionZip) but not this anchor-context hard merge.
- **Break condition:** If important information is distributed across multiple context tokens that should augment *different* anchors, forcing many-to-one merges may lose nuanced details. Evidence: The paper does not analyze per-sceme merging quality; success is measured only by aggregate driving metrics.

## Foundational Learning
- **Concept: Multi-modal LLMs for autonomous driving**
  - *Why needed here:* SToRM builds on LMDrive-like architectures that fuse camera/LiDAR tokens and language instructions via an LLM. Understanding modality encoding, token concatenation, and LLM-based control prediction is prerequisite.
  - *Quick check question:* Why does feeding visual tokens from multiple frames into an LLM cause quadratic compute growth, and why is this problematic for real-time driving?
- **Concept: Token reduction in transformer-based models**
  - *Why needed here:* The core problem is excessive visual tokens (`T×N=3000`) causing prohibitive FLOPs. Grasping the trade-off between token budget and information retention is key to evaluating SToRM's design.
  - *Quick check question:* What is the computational complexity of self-attention with respect to sequence length, and how does reducing tokens from 3000 to 120 affect it?
- **Concept: Attention as a proxy for feature importance**
  - *Why needed here:* SToRM's pseudo-supervision relies on the assumption that LLM attention scores reflect token importance. This requires understanding how attention distributions emerge from autoregressive decoding.
  - *Quick check question:* In a frozen LLM's final layer, what does a high column-wise mean attention score for a visual token indicate about its role in the output generation?
- **Concept: Differentiable approximation for discrete assignments**
  - *Why needed here:* The ACM module uses Gumbel-Softmax and STE to approximate one-hot assignments for merging. This is a standard technique for making discrete selection differentiable.
  - *Quick check question:* Why can't we use `argmax` directly in the forward pass for assigning context tokens to anchors while maintaining end-to-end trainability?

## Architecture Onboarding
### Component Map
Component map: Modality encoders (frozen CNN + fusion transformer, SentencePiece tokenizer) -> Importance predictor (MLP-Mixer) -> ACM module -> LLM backbone (frozen) -> Control head (two-layer MLP + PID). Auxiliary path (training only): Modality encoders -> LLM backbone (all visual tokens) -> attention extraction.

### Critical Path (Inference)
1. Encode current & past `T` frames → `Z_t` (size `T×N×D`).
2. Importance predictor → `s` (size `T×N`).
3. ACM per frame → `Ã` (size `T×K×D`).
4. Concatenate `Ã` + text tokens → LLM → output tokens.
5. MLP waypoint predictor → control commands.

### Design Tradeoffs
- **Sliding window (`ℓ`, `κ`) vs. full temporal context:** Smaller windows reduce predictor FLOPs but may miss long-range cues. The paper uses ℓ=1, κ=2 (window size 3, stride 2), achieving a GFLOP reduction from 11.3 to 2.1 with minimal DS drop (44.2 vs 46.1).
- **Anchor count `K` vs. information loss:** Higher `K` preserves more tokens but reduces compression; the paper fixes `K=4` per frame. If `K` is too low, anchors may not cover all critical objects (e.g., multiple pedestrians).
- **Hard vs. soft merging:** Hard merging (STE) achieves higher DS (44.2) than soft merging (40.1) by avoiding over-smoothing, though it introduces gradient discretization error.

### Failure Signatures
- Sudden DS drop >5% vs. all-token baseline: check predictor scores misalignment or ACM merging critical tokens.
- High FPS but low RC/IS: over-compression (`K` too small) losing navigational info.
- Training instability (`L_score` not decreasing): pseudo-supervision may be noisy; try increasing `λ` or adjusting predictor capacity.

### First 3 Experiments
1. **Replicate Table II (LLaVA backbone):** Run SToRM vs. all-token LMDrive and LMDrive (Q-Former) on LangAuto-Long. Verify ≥30× FLOP reduction with comparable DS.
2. **Ablate predictor architecture (Table V):** Compare MLP-Mixer with/without sliding window vs. Transformer predictor. Confirm sliding window cuts GFLOPs with minimal DS loss.
3. **Test ACM merging schemes (Table VI):** Ablate hard merging vs. soft vs. anchor-only. Validate hard merging's superiority. Also try varying `K` (e.g., 2, 4, 8) to see DS/FPS tradeoff.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How robust is the token importance prediction to the choice of LLM layer from which attention scores are extracted as pseudo-supervision signals?
- **Basis in paper:** [inferred] The paper uses attention scores from the last decoder layer of the frozen LLM to generate pseudo-supervision signals (Sec. III-C) but does not consider alternative layers.
- **Why unresolved:** The paper does not investigate whether attention from earlier or middle layers might produce more accurate or transferable importance cues, leaving the layer selection as an arbitrary design choice.
- **What evidence would resolve it:** Train the importance predictor using pseudo-supervision derived from various layers (e.g., first, middle, last decoder layers) while keeping all other settings fixed. Compare driving performance (DS, RC, IS) and analyze the correlation between layer-wise attention patterns and ground-truth token importance (if available).

### Open Question 2
- **Question:** To what extent does the sliding window size (ℓ) and dilation factor (κ) affect the trade-off between importance prediction accuracy and computational cost in the lightweight predictor?
- **Basis in paper:** [inferred] The paper proposes a sliding window mechanism (Sec. III-B.1) and sets ℓ = 1, κ = 2 based on computational considerations, but does not explore other values.
- **Why unresolved:** No ablation study is provided on how varying ℓ and κ influences the predictor’s effectiveness or efficiency; the choice is not justified by empirical evidence.
- **What evidence would resolve it:** Systematically sweep ℓ and κ (e.g., ℓ ∈ {1, 2, 3}, κ ∈ {1, 2, ℓ+1}), measure the predictor’s FLOPs, the score loss (L_score), and downstream driving metrics. Plot performance vs. cost to identify optimal operating points.

### Open Question 3
- **Question:** Does SToRM maintain its performance advantage when transferred from the synthetic CARLA environment to real-world driving datasets?
- **Basis in paper:** [inferred] All experiments are conducted on the LangAuto benchmark, which is generated in the CARLA simulator (Sec. IV-A.1). No real-world data is used.
- **Why unresolved:** The synthetic domain may not capture the full complexity, noise, and distribution of real-world driving scenes; thus, generalization remains unproven.
- **What evidence would resolve it:** Apply the trained SToRM model (without retraining or with minimal fine-tuning) to real-world multimodal driving datasets that include camera images, LiDAR, and language instructions (e.g., nuScenes, Waymo Open Dataset). Evaluate driving performance using analogous metrics or through human-in-the-loop testing.

### Open Question 4
- **Question:** Would an adaptive token reduction mechanism, where the number of anchors per frame (K) varies based on scene complexity or token importance distribution, improve performance beyond the fixed K = 4 used?
- **Basis in paper:** [inferred] The ACM module uses a constant K per frame across all timesteps (Sec. III-B.2), and experiments fix K = 4. No dynamic allocation is explored.
- **Why unresolved:** A fixed budget may under-utilize tokens in complex scenarios (e.g., heavy traffic) and over-reduce in simple ones, potentially limiting performance.
- **What evidence would resolve it:** Implement a policy that determines K per frame (e.g., thresholding importance score variance, or a learned network). Evaluate under the same average token budget and compare driving metrics against the fixed-K baseline to assess benefits of adaptivity.

## Limitations
- **Pseudo-supervision validity** – The assumption that LLM attention scores reflect token importance is not directly validated; misalignment could degrade driving performance.
- **Temporal scope limitations** – The predictor’s sliding window (ℓ=1, κ=2) may miss long-range dependencies, but the paper does not test on scenarios requiring extended memory.
- **Merging quality analysis** – No qualitative inspection of which tokens are merged; potential loss of critical details in complex scenes is not examined.
