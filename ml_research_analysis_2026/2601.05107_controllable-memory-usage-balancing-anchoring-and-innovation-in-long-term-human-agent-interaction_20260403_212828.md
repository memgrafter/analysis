# Controllable Memory Usage: Balancing Anchoring and Innovation in Long-Term Human-Agent Interaction

## Quick Facts
- **arXiv ID:** 2601.05107
- **Source URL:** https://arxiv.org/abs/2601.05107
- **Reference count:** 23
- **Primary result:** SteeM framework enables user-controllable memory reliance on a 1–5 scale via rubric-aligned supervised fine-tuning and GRPO reinforcement learning, significantly reducing alignment error (δalign) while maintaining response quality comparable to baselines.

## Executive Summary
The paper addresses "Memory Anchoring"—the tendency of LLM agents to over- or under-use past interactions regardless of user intent. They introduce SteeM, a framework that lets users specify desired memory reliance via a 1–5 scale. SteeM measures dependence with a rubric-based MD-Score, generates preference-aligned training data, and fine-tunes models using both supervised fine-tuning (SFT) and GRPO reinforcement learning. Experiments on Qwen3 models show SteeM reduces alignment error substantially across tasks without degrading response quality, outperforming direct memory masking.

## Method Summary
SteeM begins with a synthetic long-term interaction dataset (Research and Tutoring scenarios) where each query is paired with structured memory (user profile, cross-session, intra-session). A rubric-trained LLM judge assigns a Memory Dependence Score (MD-Score) from 1 to 5 based on Content, Pattern, and Style cues. To train models to follow user-specified dependence levels, the authors use a user simulator to rewrite queries into preference-indicative forms that match the target MD-Score of chosen high-quality responses. This decouples the dependence preference from the query content. A base model (Qwen3-4B/8B) is first fine-tuned on 7k such triples via cross-entropy (SFT). Then GRPO reinforcement learning further refines the policy using a multi-component reward: R = R_align (negative deviation from target MD-Score) + R_task (task-specific rubric score) + R_general (general reward model). This process yields models that reliably produce outputs with the requested level of memory reliance.

## Key Results
- SteeM (SFT+RL) reduces alignment error δalign from ~1.59 to ~1.01 on Research tasks (Qwen3-4B), and similarly on Tutoring.
- Realized MD-Score distributions closely match target preference distributions, unlike baselines that cluster at high reliance.
- Response quality (AlpacaEval, Skywork-Reward) remains comparable to baselines; pairwise evaluations favor SteeM over simpler memory masking approaches.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The rubric-based MD-Score provides a reliable, human-aligned measurement of how much a response relies on given memory.
- **Mechanism:** An LLM judge scores responses on a 1–5 scale using rubrics that observe Content, Pattern, and Style cues. Human validation confirms strong agreement (Figure 3 left), creating a consistent supervision signal for alignment.
- **Core assumption:** The rubrics capture human intuition about memory reliance; the judge generalizes across tasks without re-calibration.
- **Evidence anchors:** [abstract], [section 3.2] Rubric definitions (Table 7) and scoring protocol; [section 3.3] human–rubric agreement analysis.
- **Break condition:** Judge produces biased scores on out-of-distribution domains (e.g., artistic or highly speculative tasks), causing noisy alignment signals.

### Mechanism 2
- **Claim:** Preference-aligned data generation isolates the memory-dependence preference from original queries and creates diverse training triples spanning the 1–5 spectrum.
- **Mechanism:** A user simulator rewrites each original query into a preference-indicative variant `q_align` whose implied dependence level matches the realized MD-Score of a selected high-quality response `y`. This decouples the preference from the content-agnostic original query.
- **Core assumption:** The simulator can generate natural language cues that reliably communicate target dependence without altering the underlying task semantics.
- **Evidence anchors:** [abstract], [section 4.2] Full pipeline (Figure 2(C)); quality filtering using task rubrics and a reward model; dataset statistics.
- **Break condition:** Simulator rewrites introduce ambiguities (e.g., conflicting instructions) that cause distribution shift between `q_align` and natural queries, reducing test-time transfer.

### Mechanism 3
- **Claim:** GRPO with a multi-component reward refines the policy to match target dependence while preserving response quality.
- **Mechanism:** Reward `R = R_align + R_task + R_general`, where `R_align = -δ_align` directly penalizes MD-Score deviation from the preference. GRPO’s group-based clipped objective updates the policy using on-policy rollouts, balancing alignment and utility.
- **Core assumption:** The weighted combination creates a gradient that improves dependence alignment without degrading task performance.
- **Evidence anchors:** [abstract], [section 4.3] Reward design; [section 5.1] Results: SteeM(SFT+RL) lowers δalign further than SFT alone while matching quality (Figure 6).
- **Break condition:** Reward weights mis-specified, leading to overfitting to δalign (e.g., responses become overly generic to avoid anchoring) or quality collapse due to `R_general` model bias.

## Foundational Learning
- **Preference-Tuning (SFT/RL):** Needed because SteeM learns to follow a numeric preference (target memory dependence); understanding how preference data shapes loss functions is key. *Quick check:* When would you choose direct policy optimization (e.g., GRPO) over plain supervised fine-tuning on preference-aligned demonstrations?
- **Retrieval-Augmented Generation (RAG):** Needed because memory is provided as retrieved context; anchoring arises from RAG’s standard context-injection pattern; understanding RAG pitfalls (e.g., context over-reliance) is essential. *Quick check:* What architectural modifications could reduce a model’s tendency to parrot retrieved passages while still using them?
- **Behavioral Metrics for LLM Outputs:** Needed because MD-Score is a behavioral proxy; constructing such metrics requires defining observable rubrics and validating them with humans. *Quick check:* How would you design a rubric to measure ‘conciseness’ of an answer, and what are common validity threats?

## Architecture Onboarding
- **Component map:** Data Synthesis -> Rubric & Judge -> Preference-Aligned Data Generator -> SFT Trainer -> RL Trainer (GRPO) -> Evaluator.
- **Critical path:** Build synthetic dataset and define rubrics; validate MD-Score with human annotation; generate preference-aligned SFT dataset (7k samples); train SFT model; prepare RL samples (2k); apply GRPO; run ablations and case studies.
- **Design tradeoffs:** Natural vs. tag-cued queries: tags improve δalign but hurt AlpacaEval; SFT vs. RL: RL reduces δalign further but costs more; memory masking simpler but less flexible.
- **Failure signatures:** High mean δalign (>1.0) after training; AlpacaEval drop >0.3 vs. base; reward divergence during RL; MD-Score distribution not shifting toward diagonal; inconsistent alignment across tasks.
- **First 3 experiments:** 1. Replicate Memory Anchoring baseline to confirm high MD-Scores; 2. Evaluate SteeM SFT reduction in δalign; 3. Evaluate SteeM SFT+RL further δalign reduction.

## Open Questions the Paper Calls Out
1. **Generalization to authentic long-term interactions:** The synthetic dataset may not capture real human unpredictability and emotional nuance; longitudinal user studies needed.
2. **Sufficiency of a discrete 1–5 scale:** Users may have richer or continuous preferences; user elicitation studies required to determine optimal granularity.
3. **Robustness across model architectures:** Results are limited to Qwen3; testing on other architectures (e.g., Llama, Mistral) and scales is necessary.
4. **Memory structure universality:** The three-component memory (user profile, inter-session, intra-session) may not suit domains requiring different schemas (e.g., emotion-centric, graph-based).
5. **Computational cost for deployment:** Real-time rubric judging and GRPO rollouts may be prohibitive for resource-constrained settings; profiling and lightweight alternatives are needed.

## Limitations
- Synthetic dataset may not reflect real human interaction dynamics, limiting external validity.
- MD-Score rubric validation was conducted only on Research and Tutoring domains; performance may degrade on out-of-distribution tasks (e.g., artistic, speculative).
- Exact judge prompts/models and reward component details are not fully specified, hampering exact replication.

## Confidence
- SteeM reduces δalign while preserving quality: **High**
- Rubric-based MD-Score aligns with human intuition: **Medium**
- Preference-aligned data generation decouples dependence from content: **Low**
- GRPO with multi-component reward balances alignment and utility: **Medium**

## Next Checks
1. **Rubric Generalization:** Test MD-Score judge on out-of-distribution tasks (e.g., creative writing) with human annotation; measure agreement drift.
2. **Reward Component Balance:** Ablate `R_align` vs. `R_general` weights during GRPO; monitor δalign and Skywork-Reward for collapse or overfitting.
