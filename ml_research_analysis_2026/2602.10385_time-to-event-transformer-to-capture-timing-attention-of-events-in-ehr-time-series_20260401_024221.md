# Time-to-Event Transformer to Capture Timing Attention of Events in EHR Time Series

## Quick Facts
- **arXiv ID**: 2602.10385  
- **Source URL**: https://arxiv.org/abs/2602.10385  
- **Reference count**: 39  
- **Primary result**: LITT reduces RMSE by ~50 days and improves AUC/F1 by >0.3 for cardiotoxicity prediction in breast cancer patients, and achieves C-index of 0.669/0.673 on survival datasets.

## Executive Summary
Electronic Health Record (EHR) time series data are inherently irregular and asynchronous, making it difficult to capture precise event timing. Existing transformer-based models for EHR often ignore timing information, limiting causal reasoning and personalized trajectory discovery. This paper introduces LITT, a Timing-Transformer that integrates a Time-Transformation Gate within an LSTM backbone to align events onto a virtual relative timeline. The model computes "timing attention" as the excess kurtosis of relative timestamps across patients, emphasizing events with concentrated timing patterns. On a cohort of 3,276 breast cancer patients, LITT significantly outperforms LSTM and GRU baselines, reducing root mean squared error (RMSE) by about 50 days and improving AUC/F1 by over 0.3 for predicting cardiotoxicity onset. On public survival datasets SUPPORT and METABRIC, LITT achieves concordance indices (C-index) of 0.669 and 0.673, respectively, surpassing most state-of-the-art survival models. Additionally, the model uncovers clinically intuitive treatment trajectories, demonstrating its potential for interpretable decision support.

## Why This Works (Mechanism)
LITT ensures that all patient events are expressed relative to a common reference point (e.g., diagnosis) via the Time-Transformation Gate. This alignment removes patient-specific temporal offsets and allows the LSTM to learn patterns consistent across individuals. The timing attention mechanism then examines the distribution of relative timestamps for each event type across the cohort. Excess kurtosis, which measures distribution peakedness, is high when an event consistently occurs within a narrow window—indicating strong timing relevance. By scaling the LSTM’s hidden representations with these attention weights, the model highlights time-critical events, improving predictive accuracy and enabling extraction of common temporal trajectories. The synergy of alignment and data‑driven weighting yields a temporally aware and interpretable model.

## Foundational Learning
1. **Time-Transformation Gate**  
   *Why needed*: Converts absolute timestamps into a common reference frame (relative timeline) to enable cross‑patient comparison.  
   *Quick check*: Apply the gate to two sequences with identical ordering but different absolute start times; outputs should be nearly identical after scaling.

2. **Virtual Relative Timeline**  
   *Why needed*: Eliminates patient‑specific offsets (e.g., enrollment dates) and focuses on event ordering relative to an index event.  
   *Quick check*: Shift all timestamps by a constant; the relative timeline should remain unchanged.

3. **Excess Kurtosis as Timing Attention**  
   *Why needed*: Quantifies concentration of event timestamps across the cohort; high kurtosis indicates that an event occurs within a narrow window, suggesting predictive timing.  
   *Quick check*: Compute excess kurtosis on a uniform distribution (near 0) and on a peaked distribution (>0).

4. **LSTM Backbone with Modified Input**  
   *Why needed*: LSTM naturally handles irregular intervals and captures long‑term dependencies essential for modeling multi‑year patient trajectories.  
   *Quick check*: Train a standard LSTM on a synthetic task requiring memory over long intervals; it should outperform a vanilla RNN.

## Architecture Onboarding
#### Component map
Event features + absolute timestamps → Time-Transformation Gate → relative timeline encoding → LSTM encoder → cohort‑wise aggregation of relative timestamps per event type → excess kurtosis computation → timing attention weights → weighted LSTM outputs → prediction head.

#### Critical path
1. Transform absolute times to relative times using the gate.  
2. Process each patient’s sequence through the LSTM.  
3. Pool relative timestamps for each event type across the training cohort (or batch) to form distributions.  
4. Compute excess kurtosis for each event type to obtain scalar attention weights.  
5. Multiply the LSTM’s final hidden state (or event representations) by these weights.  
6. Feed the weighted features into a task‑specific output layer (regression or classification).

#### Design tradeoffs
- **Interpretability vs. flexibility**: Using a simple statistic (kurtosis) yields an interpretable timing signal but may be less expressive than learned attention mechanisms.
- **Cohort‑level computation**: Timing attention requires aggregating data across patients, which increases memory demands and raises privacy concerns for decentralized training.
- **Backbone choice**: The gate is designed for LSTM’s cell state; moving to a Transformer could improve parallelization but might sacrifice the natural handling of irregular intervals.

#### Failure signatures
- Poor calibration of the relative timeline (e.g., incorrect reference point) makes timing attention noisy and degrades performance.
- Small training cohorts lead to unstable excess kurtosis estimates, especially for rare events, causing erratic weighting.
- Overfitting to dataset‑specific timing artifacts (e.g., system‑level scheduling) results in poor generalization to external populations.

## Open Questions the Paper Calls Out
1. **Question:** Can the time‑transformation gate be used with non‑LSTM backbones (e.g., Transformers)?  
   **Basis in paper:** [inferred] LITT relies on LSTM’s cell state for timing; authors claim Transformers ignore timing.

   **What evidence would resolve it:** Implement gate in Transformer, compare performance on EHR tasks.

2. **Question:** Is excess kurtosis the best measure for timing attention, or would alternatives (variance, entropy) be better?  
   **Basis in paper:** [explicit] Timing attention is defined as excess kurtosis of relative timestamps.  
   **Why unresolved:** No comparison with other statistics; unclear if optimal.  
   **What evidence would resolve it:** Ablate attention metric, correlate with clinical validity or prediction accuracy.

3. **Question:** How can LITT handle right‑censoring and competing risks natively for survival analysis?  
   **Basis in paper:** [inferred] LITT predicts event days and thresholds for binary outcomes; authors admit it’s not designed for survival.  
   **Why unresolved:** Thresholding discards censoring information; limits applicability.  
   **What evidence would resolve it:** Modify loss to incorporate censoring (e.g., Cox partial likelihood), produce survival curves, evaluate with proper metrics on public datasets.

## Limitations

- The claim of discovering “clinically intuitive” treatment trajectories is anecdotal, without structured clinical evaluation or inter‑rater reliability.
