# Let the Agent Search: Autonomous Exploration Beats Rigid Workflows in Temporal Question Answering

## Quick Facts
- **arXiv ID**: 2603.01853
- **Source URL**: https://arxiv.org/abs/2603.01853
- **Reference count**: 28
- **Primary result**: AT2QA achieves state-of-the-art zero-shot Hits@1 of 88.7% (MultiTQ), 75.4% (Timeline-CronQuestion), and 75.4% (Timeline-ICEWS-Actor), surpassing prior bests by 10.7, 4.9, and 11.2 absolute points respectively.

## Executive Summary
Temporal Knowledge Graph Question Answering (TKGQA) requires complex multi-hop reasoning over temporal facts with intricate time constraints. Existing LLM-based approaches rely on rigid, predefined workflows or costly fine-tuning, limiting adaptability to diverse queries. This paper introduces AT2QA, a training-free autonomous agent that enables an off-the-shelf LLM to interactively explore a TKG via a generic search tool. The agent dynamically formulates and executes search queries, iteratively refining its reasoning based on retrieved evidence. A novel experience mining mechanism distills a compact few-shot demonstration library from successful self-generated trajectories, eliciting latent reasoning capabilities without model updates. Extensive evaluation on three challenging TKGQA benchmarks shows AT2QA dramatically outperforms prior methods, establishing autonomy and experience mining as effective principles for temporal reasoning.

## Method Summary
AT2QA treats the LLM as an autonomous agent that operates in a closed loop with a structured search tool over a temporal knowledge graph. Given a question, the agent produces a thought and a structured search call (specifying entity, relation, and time window constraints). The search tool first filters the TKG symbolically, then retrieves semantically relevant facts via dense embeddings, and finally ranks them by relevance or chronology. The agent incorporates the returned facts as observations, revises its plan, and repeats until it emits an answer. No model parameters are updated; instead, a training-free experience mining phase samples multiple trajectories for training questions, rewards those yielding exact-match answers, ranks them by "marginal instructional value" using an LLM, and selects a small set (K=3) of high-quality demonstrations. These demos are injected into the agent's prompt at test time, guiding it toward successful reasoning patterns without fine-tuning. The entire system is zero-shot with respect to the target datasets.

## Key Results
- On MultiTQ, AT2QA reaches **88.7% Hits@1**, a **+10.7** absolute improvement over the previous state-of-the-art.
- On Timeline-CronQuestion, it achieves **75.4% Hits@1**, **+4.9** points ahead of prior work.
- On Timeline-ICEWS-Actor, it also obtains **75.4% Hits@1**, **+11.2** points higher.
All results are obtained without any dataset-specific training.

## Why This Works (Mechanism)
### Mechanism 1: Autonomous Exploration
Allowing the LLM to decide its next action mitigates the cascade of errors inherent in rigid workflows. The agent iteratively interacts with the TKG, generating thoughts and tool calls based on accumulated observations. This closed-loop enables dynamic reformulation of temporal constraints (e.g., adjusting time windows) when evidence is insufficient or contradictory. Modern off-the-shelf LLMs possess sufficient planning and meta-cognitive abilities to navigate complex temporal reasoning without prescribed steps. Evidence: The paper’s ablation shows that replacing the autonomous agent with a fixed decomposition pipeline (e.g., RTQA) causes a large performance drop (~7.7 points on MultiTQ), confirming that autonomy is the primary driver. However, if the LLM fails to generate meaningful search constraints or enters repetitive loops, autonomy may become inefficient.

### Mechanism 2: Training-Free Experience Mining
Distilling successful self-generated trajectories into a compact few-shot library elicits latent reasoning capabilities without parameter updates. The mining process samples many interaction traces, uses exact-match rewards to select correct ones, and then employs an LLM to rank them by marginal instructional value, ultimately selecting a small set of "advantage experiences" that are validated on a held-out set. The assumption is that the correct reasoning path already exists within the LLM’s latent space and can be triggered by in-context examples of successful *processes* (including tool-interaction patterns). Evidence: Pass@k analysis shows >84% Pass@1 and ~96% Pass@10 on a hard subset, indicating correct paths are present but need appropriate prompting to surface deterministically. A limitation arises if the distribution of successful trajectories is sparse or lacks diversity, potentially leading to overfitting to narrow patterns.

### Mechanism 3: Structured Temporal Search Tool
A hybrid search tool provides a reliable, grounded interface for the agent to query the TKG. It accepts a query string along with structured constraints (time window, entity/relation filters). The tool first performs structural filtering on the TKG, then dense semantic retrieval, and finally supports hybrid sorting (by relevance or chronologically). This design grounds the LLM’s semantically ambiguous queries in symbolic, timestamped facts, balancing precision (avoiding temporal hallucination) and recall (handling linguistic variation). Ablations attribute large gains to the temporal modules (time limit and time-aware sorting), with stability across different embedding backbones suggesting the structural filter reduces dependence on exact semantic matching. If the TKG is extremely sparse or queries require complex temporal logic beyond simple filters, the tool may return no relevant candidates, causing failure unless a recovery mechanism exists.

## Foundational Learning
- **Concept: ReAct/Agentic Tool-Use Paradigm**
  - *Why needed*: AT2QA’s core loop (thought → action → observation) follows ReAct; engineers must design actionable tools and prompt the LLM to interleave reasoning with tool calls.
  - *Quick check*: How would you design a system prompt to make an LLM generate a `<think>` block followed by a structured `<search>` call with JSON arguments?
- **Concept: Few-Shot Learning with Process Trajectories**
  - *Why needed*: The experience miner selects full interaction traces, not just final answers. The model learns *procedural* patterns (how to search, verify, correct) from these.
  - *Quick check*: What’s the difference between providing a few-shot example of a correct final answer versus a correct multi-step reasoning *trajectory* with tool interactions? Which is more likely to teach the model self-correction?
- **Concept: Temporal Knowledge Graph Semantics**
  - *Why needed*: The TKG consists of (subject, relation, object, timestamp) quadruples; engineers must understand how temporal constraints (“after”, “last”, “same month”) map to operations on timestamps and why multi-hop reasoning is often required.
  - *Quick check*: For the query “Who visited France *after* the 2020-05-01 conference?”, what are the minimal required hops over the TKG? What role does the timestamp play in each hop?

## Architecture Onboarding
- **Component map**:
  LLM Agent ↔ Controller ↔ Search Tool ↔ Environment (TKG + embedding index)
  Experience Miner (offline) → produces Ddemo → Controller injects into LLM Agent
- **Critical path**:
  1. Controller provides question and Ddemo to LLM Agent.
  2. Agent generates thought and structured search action.
  3. Search tool queries TKG, returns filtered and ranked facts as observation.
  4. Agent incorporates observation; repeats steps 2–3 until it emits an answer or reaches Tmax.
  Mining path: sample N×G trajectories for training questions → filter by exact-match reward → LLM ranks successes → select top K → validate on held-out → update Ddemo.
- **Design tradeoffs**:
  - *Autonomy vs. Efficiency*: More interaction rounds improve robustness but increase latency/cost; gains diminish after ~8 rounds.
  - *Tool Generality vs. Performance*: A generic single-relation search tool is easier to integrate than specialized temporal tools but requires the LLM to do more query structuring.
  - *Library Size vs. Stability*: Larger few-shot libraries cover more patterns but risk contradictions; K=3 is chosen for stability.
- **Failure signatures**:
  - *Infinite Loop*: Agent repeats similar searches without answering (Tmax reached, no new gold facts).
  - *Retrieval Dead End*: Tool returns empty or irrelevant facts for all queries (low recall/gold fact absence).
  - *Hallucinated Answer Premature Termination*: Agent answers early without verifying all required entities, especially for “Multiple” questions.
- **First 3 experiments**:
  1. **Autonomy Ablation**: Replace the autonomous agent with a rigid decomposition workflow (e.g., RTQA’s fixed subquestion pipeline) while keeping the advanced search tool.
  2. **Mining Ablation**: Disable experience mining (use zero-shot with no demos, or random demos from the training set).
  3. **Tool Component Sweep**: In the zero-shot autonomous setting, systematically disable: (a) time window filter, (b) time-aware sorting, (c) entity/relation filters.

## Limitations
- **Implementation gaps**: The search tool’s exact filtering logic (time window inclusivity, entity/relation scope) and the prompts for agent/mining are under-specified, hindering faithful replication.
- **Mining diversity risk**: Selecting successful trajectories via LLM ranking may yield a narrow few-shot library if sampled paths lack diversity, potentially overfitting to limited patterns.
- **Model dependency**: Reliance on proprietary models (DeepSeek-V3.2, GLM-Embedding-3) raises accessibility and cost concerns; performance with open alternatives is uncertain.

## Confidence
- Autonomy-driven exploration (primary mechanism): High
- Training-free experience mining (benefit): Medium
- Structured temporal search tool (effectiveness): Medium

## Next Checks
1. **Tool audit**: Compute gold fact recall@10 and precision for the search tool on validation data; systematically ablate each temporal component to quantify their marginal contributions.
2. **Mining sensitivity**: Sweep key hyperparameters (group size G, library size K, training questions N, ranking prompts) and measure performance variance alongside demonstration diversity metrics.
3. **Cross-dataset transfer**: Evaluate AT2QA on at least two additional TKGQA benchmarks (e.g., TemporalQuestions, ComplexQuestions) to test robustness to different temporal constraint types and KG schemas.
