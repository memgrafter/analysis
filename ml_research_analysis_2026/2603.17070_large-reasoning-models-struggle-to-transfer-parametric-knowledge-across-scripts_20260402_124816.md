# Large Reasoning Models Struggle to Transfer Parametric Knowledge Across Scripts

## Quick Facts
- **arXiv ID:** 2603.17070  
- **Source URL:** https://arxiv.org/abs/2603.17070  
- **Reference count:** 30  
- **Primary result:** Script mismatch between query and knowledge source causes a ~13% accuracy drop in cross-script QA; targeted SFT teaching explicit transliteration reasoning yields modest but consistent improvements, especially for low-resource and cross-script questions.

## Executive Summary
This paper investigates why large reasoning LLMs fail to answer questions about entities when the query script differs from the script in which the entity's knowledge was memorized (e.g., English query about a Serbian entity). Through analysis of two local knowledge QA datasets, the authors identify script mismatch—not language family or identity—as the primary predictor of failure. Interventions that provide the entity in its source script as a thinking prefix disproportionately improve cross-script performance, implicating faulty entity mapping as a key bottleneck. A synthetic data pipeline teaches models to reason explicitly about transliteration ambiguities, and fine-tuning two models with this data yields small but consistent accuracy gains. The findings suggest that a significant portion of the cross-script gap stems from suboptimal test-time reasoning behavior, which can be mitigated via targeted post-training.

## Method Summary
The study combines observational analysis with intervention experiments. First, models are evaluated on ECleKTic (12 languages) and MultiLoKo (31 languages) QA datasets. Feature vectors capturing script match, language family, and model capability (via Belebele scores) are extracted per question, and OLS regression isolates script mismatch as the dominant failure predictor. Second, a prefixing experiment prepends the source-script entity to the prompt, measuring its disproportionate benefit for cross-script questions. Third, a synthetic data pipeline generates question–reasoning–answer triples that explicitly reflect on transliteration ambiguities (using Gemini as a teacher), then reformats them to match the target model's style. Finally, LoRA-based supervised fine-tuning (SFT) on this data is applied to GPT-OSS-120B and Qwen3-30B-A3B, with evaluation on the original test sets to measure cross-script performance changes.

## Key Results
- Script mismatch is the primary predictor of QA failure, with a regression coefficient of ~+12% accuracy after controlling for model capability and question difficulty.
- Providing the source-script entity as a thinking prefix yields a +2.1% average gain on cross-script questions vs. +0.5% on same-script questions.
- SFT on synthetic transliteration-reasoning data produces modest but consistent absolute accuracy improvements (e.g., +1.0% on ECleKTic, +0.4% on MultiLoKo for GPT-OSS-120B), with larger gains on low-resource and cross-script subsets.

## Why This Works (Mechanism)
### Mechanism 1: Script-Sensitive Entity Mapping
- **Claim:** Script mismatch causes specific failures in mapping the query entity to its memorized form.
- **Mechanism:** When a query uses a different script than the memorized knowledge (e.g., English query about a Cyrillic entity), the model must perform a brittle transliteration or semantic mapping. A failure here prevents correct activation of the parametric knowledge.
- **Core assumption:** The model's retrieval system is sensitive to surface script form and does not robustly abstract to a script-agnostic entity representation.
- **Evidence anchors:**  
  - Regression shows script match is significant (~+12% accuracy), while language family/identity are not.  
  - Prefixing the source entity disproportionately helps cross-script questions (+2.1% vs. +0.5%).  
- **Break condition:** Models develop script-agnostic entity representations (e.g., via alignment training), closing the gap even with script mismatch.

### Mechanism 2: Suboptimal Test-Time Reasoning Policy
- **Claim:** Reasoning LLMs often possess the latent knowledge but fail to access it due to a mis-specified reasoning chain that skips explicit transliteration checks.
- **Mechanism:** The default reasoning process does not systematically consider potential origin scripts of a named entity, leading to retrieval of incorrect memory traces. Teaching an explicit “transliteration check” step modifies the inference-time search to better access correct knowledge.
- **Core assumption:** The bottleneck is the reasoning *policy*, not the stored *knowledge*.
- **Evidence anchors:**  
  - SFT on synthetic data that encourages reflection about transliteration yields consistent accuracy gains, especially on cross-script questions.  
  - The paper states: “LLMs sometimes possess the requisite parametric knowledge but fail to access it during reasoning.”  
- **Break condition:** If parametric knowledge is genuinely absent/modified, SFT would not improve accuracy.

### Mechanism 3: Token Overlap Signal Loss
- **Claim:** Token-level overlap between query and memorized knowledge provides a cheap retrieval cue that vanishes in cross-script scenarios.
- **Mechanism:** Same-script transfer benefits from shared subword tokens as direct retrieval signals. Cross-script transfer has disjoint token sequences, forcing reliance on noisier, higher-level semantic representations.
- **Core assumption:** The model’s retrieval/attention favors token overlap as a primary low-effort signal.
- **Evidence anchors:**  
  - Prefixing the source script entity (restoring token overlap) gives a large boost, while a control prefix (additional English text) does not.  
  - Neighbor paper “Beyond Literal Token Overlap” supports the idea that token overlap metrics fail across scripts.  
- **Break condition:** Models develop internal script-invariant alignment mechanisms that reduce dependence on token overlap.

## Foundational Learning
- **Concept: Cross-lingual vs. Cross-script Transfer**  
  *Why needed:* The core finding is that the barrier is *script* (e.g., Latin vs. Cyrillic), not language (e.g., English vs. Spanish). Distinguishing these is critical for diagnosing transfer failures.  
  *Quick check:* A French query about a Japanese historical figure written in Katakana is cross-script (Latin vs. phonetic Japanese) and cross-lingual; if the name is in Kanji, it is cross-script (Latin vs. logographic) and cross-lingual.

- **Concept: Entity Mapping & Transliteration Ambiguity**  
  *Why needed:* The bottleneck involves mapping the query’s surface form of an entity to its memorized source-script form, handling ambiguous transliterations (e.g., “Beijing” vs. “Peking”).  
  *Quick check:* For “Where is Moscou?” (French), the model must consider source forms like “Moscow” (English) or “Москва” (Cyrillic).

- **Concept: Test-Time Reasoning vs. Parametric Knowledge**  
  *Why needed:* The paper’s intervention (SFT) changes *how the model thinks* (reasoning chain), not the stored facts. This separates reasoning *policy* from knowledge *base*.  
  *Quick check:* To distinguish missing knowledge from reasoning failure, test whether providing the source-script entity as a hint (prefix) recovers accuracy—if it does, the knowledge likely exists but was not retrieved.

## Architecture Onboarding
### Component map
Evaluation Datasets (ECleKTic, MultiLoKo) and Models (GPT-OSS-120B, Qwen3-30B-A3B) feed into:
- Feature Extraction → Statistical Model (OLS regression)
- Prefixing Intervention → Evaluation
Independent: Synthetic Data Pipeline (Gemini generation → style-transfer) → Training (LoRA SFT) → Evaluation

### Critical path
1. Run base models on evaluation datasets to collect (model, question, score) results.  
2. Compute Belebele scores for all model-language pairs.  
3. Assemble feature vectors per (model, question) and run OLS regression.  
4. Implement prefixing logic; re-run inference with modified prompts.  
5. Build synthetic data generation prompts; generate & filter data.  
6. Perform style-transfer step to align with target model formatting.  
7. Configure LoRA hyperparameters and run SFT.  
8. Evaluate SFT checkpoints on original test sets; analyze subset deltas.

### Design tradeoffs
- **Belebele as capability proxy:** Measures reading comprehension, not pure factual recall; chosen for granularity but may conflate language understanding with knowledge retrieval.  
- **SFT vs. RL:** Used SFT for stability and resource efficiency; RL might yield larger gains by more effectively shaping reasoning behavior.  
- **Synthetic data source:** Used a powerful teacher model (Gemini) to generate ideal reasoning; risks distribution mismatch, partially mitigated by style-transfer.

### Failure signatures
- **Data-level:** High variance in individual question scores for low-resource languages.  
- **Model-level:** SFT improves only the synthetic distribution but not general cross-script performance, indicating data diversity or overfitting issues.  
- **Analysis-level:** OLS regression shows script match insignificant, possibly due to dataset imbalance or already strong cross-script representations.

### First 3 experiments
1. **Replicate OLS regression:** Reproduce Table 1, verify script-match coefficient is positive/significant while language family/identity are not; test sensitivity to feature scaling.  
2. **Prefixing ablation:** For held-out cross-script questions, run three prefix conditions (Original, Prefix-Control, Prefix+SrcEntity); expect larger delta for cross-script vs. same-script.  
3. **SFT qualitative check:** Manually inspect 10–20 style-transferred reasoning traces for target model; confirm explicit transliteration ambiguity reflection before answering.

## Open Questions the Paper Calls Out
- **Open Question 1:** Why does the script barrier persist in large reasoning LLMs despite scaling and expectations of language-agnostic representations?  
  *Basis:* The persistence is surprising and contrasts with prior literature on robust knowledge representations.  
  *Resolution evidence:* Controlled analyses of internal representations (probing, activation patching) across model scales and training objectives to see if script-specific subspaces persist.

- **Open Question 2:** Can reinforcement learning (RL) more effectively reduce the cross-script transfer gap than SFT?  
  *Basis:* The paper hypothesizes RL could more effectively elicit reasoning behaviors but used SFT due to resource constraints.  
  *Resolution evidence:* Direct comparison of RL-based fine-tuning (with rewards for correct transliteration reasoning) vs. SFT on same models and synthetic task.

- **Open Question 3:* To what extent do transliteration ambiguities in the evaluation datasets confound the measured script barrier?  
  *Basis:* Limitations note that cross-script translations may have higher ambiguity/errors for rare entities.  
  *Resolution evidence:* Re-evaluate on a curated subset of cross-script questions with unambiguous, consensus-based transliterations, or on synthetically controlled test sets varying transliteration ambiguity.

- **Open Question 4:** Does the language of the model's reasoning chain (e.g., English vs. source script) impact cross-script knowledge retrieval?  
  *Basis:* Models primarily reason in English (except Qwen/GLM sometimes in Chinese); the interaction is unexplored.  
  *Resolution evidence:* Ablate by prompting models to reason in the source script or a neutral interlingua, then measure cross-script performance.

- **Open Question 5:** Can fundamental changes to knowledge representations eliminate the script barrier?  
  *Basis:* The discussion asserts improvements must ensure knowledge representations are more distant from token-level forms.  
  *Resolution evidence:* Develop models with script-invariant representation learning (e.g., multilingual bottlenecks, contrastive learning across scripts) and test on cross-script QA.

## Limitations
- Synthetic dataset not released; quality, diversity, and overfitting risks are unknown.  
- Auto-rater tuning details are sparse, especially for low-resource languages, possibly adding evaluation noise.  
- Reported SFT gains are modest (+1% absolute) and may not generalize beyond the specific local QA datasets.

## Confidence
- **Script mismatch as primary predictor:** High (strong statistical significance and large prefixing effect).  
- **Faulty entity mapping bottleneck:** Medium-High (prefixing yields clear improvements, but alternative explanations like surface cue remain plausible).  
- **Reasoning behavior modification via SFT:** Medium (gains are consistent but small; latent knowledge presence is inferred but not directly proven).

## Next Checks
1. Replicate the OLS regression with additional controls (entity frequency, language resource level) to test robustness against omitted variable bias.  
2. Perform human evaluation of reasoning traces from SFT models on cross-script questions to verify explicit transliteration reasoning.  
3. Evaluate the SFT approach on a separate multilingual QA benchmark (e.g., XQuAD, MLQA) to check generalizability beyond local knowledge tasks.
