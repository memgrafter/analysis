# In-context Pre-trained Time-Series Foundation Models adapt to Unseen Tasks
## Quick Facts
- **arXiv ID:** 2602.20307  
- **Source URL:** https://arxiv.org/abs/2602.20307  
- **Reference count:** 33  
- **Primary result:** In-context Time-series Pre-training (ICTP) equips time-series foundation models with in-context learning, enabling adaptation to unseen tasks without fine-tuning and yielding an average 11.4% reduction in MSE/MAE.

## Executive Summary
The paper introduces In-Context Time-series Pre-training (ICTP), a method that restructures standard time-series pre-training data into multi-task context sequences to imbue foundation models with in-context learning capabilities. By concatenating multiple input-output demonstrations from a single task and training the model to predict the output for a new input within the same sequence, ICTP forces the model to infer the task from context rather than relying on task-specific parameters. Evaluations across three backbone models (MOMENT, TimesFM, LPTM) and six diverse datasets show that ICTP improves performance on unseen tasks by an average of 11.4% in terms of MSE and MAE, without any fine-tuning. This demonstrates a promising path toward more versatile time-series foundation models that can generalize across tasks through context alone.

## Method Summary
ICTP transforms each raw time-series sample into a composite sequence. For a chosen task `k`, the method constructs an input-output pair `(x, y_k)` from the sample. It then samples `m` other samples (non-overlapping in time) that are also transformed into `(x_i, y_k_i)` for the same task `k`. These `m` pairs are concatenated to form a context `C_x`. The final training sequence is `C_x` followed by the test input `x`, and the model is trained to predict `y_k` only for this last segment. At inference, for an unseen task, a similar context is built from examples of that task, and the model generates the output for a novel input based on the context. This approach ensures no temporal leakage and requires careful partitioning of the time series.

## Key Results
- Average improvement of 11.4% on unseen tasks (forecasting, imputation, backtracing) across six datasets when using ICTP versus standard pre-training.
- Gains are observed consistently across three different backbone architectures (MOMENT, TimesFM, LPTM), with notable improvements on tasks that were not part of the pre-training mixture.
- Ablation studies show that using `m=4` context examples yields the strongest performance, and that the non-overlapping constraint is critical for genuine in-context reasoning.

## Why This Works (Mechanism)
1. **ICL acquisition via multi-task context sequences**: ICTP restructures pre-training data by concatenating multiple input-output examples from a single task, followed by a test input. This formulation forces the model to infer the task from the context rather than learning task-specific parameters, thereby inducing in-context learning capabilities that are absent in standard single-task pre-training. The chronological nature of time-series data normally restricts exposure to diverse tasks, but ICTP explicitly exposes the model to multiple task types within each sequence.
2. **Shared representation with dynamic routing**: By mixing tasks within a sequence, the model learns a shared representation that dynamically maps inputs to appropriate output structures based on contextual cues. The transformer attention mechanism can then parse the context to identify patterns such as masked segments (imputation) or future windows (forecasting), enabling the same parameters to serve multiple tasks without fine-tuning.
3. **Non-overlapping constraint prevents data leakage**: ICTP explicitly ensures that context examples do not temporally overlap with the test input. This prevents the model from simply retrieving the answer from the context and instead requires it to extract the underlying task rule (e.g., "predict next values") and apply it to a novel input. The constraint is essential for evaluating true in-context reasoning.

## Foundational Learning
- **In-Context Learning (ICL)**: The capability of a model to perform a task based on demonstrations provided in the input context, without parameter updates. *Why needed*: ICTP aims to instill ICL in TSFMs, which do not naturally exhibit this property. *Quick check*: Given a context with several masked imputation examples, can the model correctly fill a new masked segment?
- **Task Candidate Definition**: The set of tasks (e.g., forecasting, imputation, backtracing) used during ICTP to generate context mixtures. *Why needed*: The choice of tasks determines the breadth of ICL capabilities the model acquires. *Quick check*: How would you formulate an anomaly detection task as an input-output pair for ICTP?
- **Temporal Data Partitioning**: The process of splitting time-series data into training/validation/test windows while ensuring no temporal overlap between context examples and the target sample. *Why needed*: Time-series data have strict chronological ordering; overlap would lead to leakage. *Quick check*: Given a series of length 1000, context length 192, and a test window of length 96, how would you sample pairs to guarantee non-overlap?

## Architecture Onboarding
**Component map**  
TaskSpec -> ContextSampler -> ContextAssembler -> ICLPreTrainer

**Critical path**  
Raw dataset is processed by iterating over each sample: sample a task `k`, compute `y_k = f_k(x)`, sample `m` non-overlapping context examples from same task, assemble `C_x` by concatenating the context pairs, then train the backbone TSFM to predict `y_k` from the combined sequence `(C_x ⊕ x)`.

**Design tradeoffs**  
- Context size `m`: Larger `m` provides richer task signals but increases sequence length and computational cost; paper uses `m=4`.
- Task diversity: Including more candidate tasks may broaden ICL but risks interference if tasks conflict.
- Backbone compatibility: Encoder-only models (e.g., MOMENT) handle imputation formatting differently from decoder-only models (TimesFM, LPTM), requiring task-specific input transformations.

**Failure signatures**  
- No improvement on unseen tasks (MSE/MAE similar to baseline).
- Performance collapse on seen tasks (forgetting original skills).
- High variance across random seeds due to unstable context sampling.

**First 3 experiments**  
1. **Single unseen task evaluation**: Pre-train with ICTP on two tasks (e.g., forecasting and imputation), then evaluate on the third task (backtracing). Compare MSE/MAE against naive reprogramming baseline.
2. **Ablate context count**: Train with varying `m` (1, 2, 4, 8) and measure impact on ICL performance to determine sensitivity.
3. **Task conflict test**: Pre-train with two conflicting tasks (e.g., forecasting and backtracing on same data direction) to see if the model can disambiguate via context or fails.

## Open Questions the Paper Calls Out
- What factors determine the variability in ICTP's effectiveness across different TSFM architectures and datasets? The paper speculates about dataset simplicity and architectural biases but lacks controlled isolation.
- How does the design of context sequences (number of demonstrations, task mixture) affect ICL performance? The paper uses fixed `m=4` and multi-task concatenation without exploring alternatives.
- Can ICTP be extended to other time-series tasks (e.g., anomaly detection, classification) and what modifications are required? The current formulation is specific to sequence-to-sequence tasks.
- What are the precise mechanistic reasons why multi-task pre-training induces ICL in TSFMs, and how does this compare to ICL emergence in LLMs? The paper offers limited interpretability; attention analyses are absent.

## Limitations
- Context sampling strategy (random vs. similarity-based) is unspecified, potentially affecting reproducibility.
- Imputation masking pattern (contiguous time blocks vs. random channels) is ambiguous, risking inconsistent baseline implementations.
- Training hyperparameters (learning rate, batch size, epochs) are omitted, hindering exact replication.

## Confidence
- ICTP induces in-context learning in TSFMs: **Medium**
- ICTP yields ~11.4% average improvement on unseen tasks: **Medium**
- Gains generalize across backbone models and tasks: **Medium**

## Next Checks
1. **Clarify context selection**: Request authors to specify the context example sampling method (e.g., random, k-NN on embeddings) and, if unavailable, compare random vs. embedding-based selection in reimplementation.
2. **Masking pattern ablation**: Systematically vary the imputation mask (contiguous vs. channel-random) and measure performance; ensure alignment with the paper’s assumed protocol.
3. **Hyperparameter sensitivity**: Train ICTP across a range of learning rates and batch sizes (using backbone defaults) to confirm robustness of the reported improvement and document exact settings.
