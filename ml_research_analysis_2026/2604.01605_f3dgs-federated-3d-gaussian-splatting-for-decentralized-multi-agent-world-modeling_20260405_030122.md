# F3DGS: Federated 3D Gaussian Splatting for Decentralized Multi-Agent World Modeling

## Quick Facts
- **arXiv ID:** 2604.01605
- **Source URL:** https://arxiv.org/abs/2604.01605
- **Reference Count:** 30
- **Primary Result:** Federated training with frozen LiDAR geometry and visibility-weighted appearance aggregation reaches global PSNR within ~2 dB of per-client local models on the MeanGreen indoor dataset.

## Executive Summary
F3DGS addresses multi‑agent 3D reconstruction when raw images cannot be pooled centrally. It merges 3D Gaussian Splatting with federated learning: a shared geometric scaffold from globally aligned LiDAR point clouds is frozen to avoid drift; each agent locally updates only appearance attributes (covariance, opacity, spherical harmonics) using its own images; the server then aggregates these updates with visibility‑aware weighting. On nine indoor sequences from the MeanGreen dataset, the global model attains PSNR within 2 dB of each agent’s locally trained model, and performance increases with more frequent communication rounds. The approach offers a practical, privacy‑preserving solution for decentralized world modeling.

## Method Summary
The pipeline begins with metric‑scale pose estimation for each agent (via LiDAR or monocular depth). A global alignment (Umeyama) stitches trajectories into a common frame. All LiDAR point clouds are fused in that frame and converted to Gaussians; only the positions are kept fixed. In each federated round, the server broadcasts the global appearance parameters; each client optimizes its local appearance parameters by minimizing the rendering loss while freezing positions, and counts per‑Gaussian visibility during rasterization. The server aggregates updates using weights `α_k,i = v_k,i / (∑_j v_j,i + ε)`, handling quaternion sign flips and normalization. After several rounds, the global appearance model is ready. By decoupling geometry (shared, immutable) from appearance (locally adapted), the method prevents misalignment and respects data privacy.

## Key Results
- Global PSNR falls within ~2 dB of local per‑client PSNR (local ~22–25 dB, global ~18–24 dB depending on sequence).
- More communication rounds consistently improve global reconstruction metrics.
- Federated degradation is not uniform; it concentrates in specific temporal segments rather than across the whole scene.

## Why This Works (Mechanism)

### Frozen Geometric Scaffold
- **Claim:** Fixing Gaussian positions from a shared, globally aligned LiDAR point cloud eliminates geometric drift.
- **Mechanism:** The fused LiDAR provides metric‑scale, consistent geometry. Freezing positions forces all clients to optimize appearance relative to the same anchor, preventing divergent spatial layouts.
- **Evidence:** The authors explicitly state this prevents drift by construction; local PSNR remains high, showing that appearance can be effectively refined with fixed geometry.
- **Break condition:** If the initial LiDAR registration fails (e.g., loop closure errors), systematic geometry errors propagate and cannot be corrected later.

### Visibility‑Aware Aggregation
- **Claim:** Weighting each client’s update by its observation frequency for each Gaussian mitigates partial observability.
- **Mechanism:** Each client tracks a per‑Gaussian visibility count `v_k,i` during rasterization. The server computes weight `α_k,i = v_k,i / (∑_j v_j,i + ε)` and aggregates the attribute as a weighted average. Clients that see a Gaussian more often have greater influence.
- **Evidence:** The weighting is clearly defined; ablation shows that increasing communication rounds improves global quality, implying the aggregation successfully combines complementary views.
- **Break condition:** High visibility does not guarantee high‑quality data; a client viewing a Gaussian under poor conditions (motion blur, extreme angle) could inject noise with high weight.

### Decoupling Geometry and Appearance
- **Claim:** Updating only appearance parameters while positions remain fixed makes the federated problem amenable to standard averaging without misalignment.
- **Mechanism:** Federated averaging is applied exclusively to appearance attributes (scale, rotation, opacity, SH). The frozen positions act as an immutable reference, ensuring all local optima lie in the same coordinate space.
- **Evidence:** The method restricts gradients to appearance; local training achieves strong results, and global aggregation yields a coherent model.
- **Break condition:** Systematic biases in the initial geometry (e.g., scale errors) force appearance to over‑compensate, potentially baking parallax into view‑dependent terms.

**Concept: Federated Learning (FedAvg)**  
*Why needed:* The entire framework is federated, introducing challenges like statistical heterogeneity (non‑IID data) and communication constraints. Knowledge of FedAvg’s broadcast‑train‑aggregate loop is key.  
*Quick check:* In classic FedAvg for neural networks, what does “non‑IID” mean, and why would simply averaging model weights from clients with disjoint image sets fail? How does F3DGS’s design change this equation?  

**Concept: Metric‑Scale Multi‑View Geometry & Pose Estimation**  
*Why needed:* F3DGS requires globally consistent, metric‑scale camera poses to initialize the scaffold and for rendering. This relies on fusing LiDAR odometry (metric scale) with visual data (texture). Understanding Umeyama alignment and trajectory smoothing is important.  
*Quick check:* Why is a LiDAR‑based scaffold used instead of a purely visual SfM point cloud? What does “metric‑scale” mean, and why is it critical for the frozen geometry to be valid?

## Architecture Onboarding

### Component Map
Raw Data (per‑agent) → Pose Construction (LiDAR/visual odometry) → Global Pose Alignment (Umeyama) → Geometric Scaffold Initialization (fixed µ) → Federated Loop: Server broadcasts global appearance → Client Local Optimization (update appearance, count visibility) → Server Visibility‑Aware Aggregation → (repeat for R rounds) → Final Global Model.

### Critical Path
1. Collect per‑agent RGB frames and metric poses.
2. Align all trajectories into a common world frame via Umeyama (optionally smooth boundaries).
3. Fuse all LiDAR point clouds using global poses; convert to Gaussians with fixed positions.
4. For each communication round: broadcast global appearance; each client locally refines appearance only while freezing positions, tracking per‑Gaussian visibility; send updates and visibility counts to server.
5. Server computes visibility weights and aggregates appearance; quaternions are sign‑aligned and normalized.
6. After R rounds, the global model is ready for evaluation.

### Design Tradeoffs
- **Frozen Geometry vs. Correctability:** Guarantees coherence but cannot fix errors from inaccurate LiDAR registration.
- **Visibility Weight Simplicity vs. Robustness:** Count‑based weighting is cheap but may overvalue frequent but low‑quality observations; more sophisticated weights could be better.
- **LiDAR Dependency:** Provides accurate metric geometry but limits the system to agents equipped with depth sensors.

### Failure Signatures
- **Local training instability** (high loss, diverging appearance) → likely poor initial scaffold geometry.
- **Global PSNR drop concentrated in 1–2 clients** → misaligned poses or domain shift for those agents.
- **No improvement with more rounds** → aggregation saturated or visibility weights failing to resolve conflicts.
- **Quaternion sign flips** → must perform sign alignment before averaging to avoid visual artifacts.

### First Experiments
1. **Reproduce Local Optimization:** Run a single client’s local step with provided global µ. Confirm PSNR matches standard 3DGS on that subset, proving µ freeze does not hinder fitting.
2. **Aggregation Sanity Check:** Split one sequence into two temporal clients. Perform one federated round. Verify global PSNR on both clients’ validation sets exceeds each local model alone, showing aggregation benefit.
3. **Communication Frequency Ablation:** For a 2‑client sequence, vary rounds R=1,3,5,7 (fixed total steps). Plot global PSNR vs. R; expect increasing trend, validating visibility‑weighted aggregation.

## Open Questions the Paper Calls Out
1. **Boundary Degradation:** What factors at temporal partitioning boundaries cause the most significant global degradation? The paper notes degradation is concentrated in a small subset of clients but does not isolate whether this stems from abrupt appearance changes, residual pose misalignments, or visibility discontinuities.
2. **Comparison to Alternatives:** How does F3DGS compare to other decentralized multi‑agent 3D reconstruction paradigms (e.g., collaborative SLAM, partitioned NeRF) under comparable privacy and communication constraints? Current evaluations are limited to FedNeRF and Fed3DGS.
3. **Scaffold Robustness:** To what extent can F3DGS tolerate residual errors in the initial LiDAR geometric scaffold (e.g., from imperfect pose stitching or sparse sampling)? The method cannot correct such errors after initialization.
4. **Generalization to Outdoor/Dynamic Scenes:** How well does F3DGS generalize to outdoor or highly dynamic scenes with lighting variations, moving objects, and larger scale? Evaluation so far is restricted to indoor sequences.

## Limitations
- **Depth Source Ambiguity:** The exact source of dense depth for scaffold creation (raw LiDAR vs. predicted depth) is unspecified, affecting scaffold density and accuracy.
- **Hyperparameter Gaps:** Precise local optimization settings (learning rates, Adam parameters, any implicit regularization beyond disabled densification) are not fully detailed, hindering exact replication.
- **Pose Alignment Underspecification:** The procedure for building the global LiDAR map (SLAM backend, loop closure handling) is not described, which critically impacts scaffold quality.

## Confidence
- **Frozen geometry prevents drift:** High (mechanism explicit; local PSNR evidence supports effectiveness).
- **Visibility‑weighted aggregation resolves partial observability:** Medium (weighting clear; ablation shows improvement but no alternative weighting baselines).
- **Global PSNR within ~2 dB of local models:** Medium (holds on MeanGreen with specific splits; generalizability unverified).

## Next Checks
1. **Depth Source Ablation:** Train F3DGS on a sequence using (a) raw sparse LiDAR points only, (b) LiDAR + monocular dense depth (e.g., Depth Anything v2), (c) LiDAR + predicted dense depth. Compare scaffold density, local PSNR, and global PSNR.
2. **Hyperparameter Sensitivity Sweep:** Vary local optimization hyperparameters (learning rates for scale/rotation/opacity/SH, loss λ) around reported values. Measure stability of local PSNR and impact on global aggregation.
3. **Pose Alignment Robustness Test:** Intentionally degrade global alignment for one client’s trajectory (add SE(3) drift). Quantify PSNR drop for that client vs. others, validating the break condition of frozen geometry.
