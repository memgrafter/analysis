# Automatic feature identification in least-squares policy iteration using the Koopman operator framework

## Quick Facts
- **arXiv ID:** 2603.26464  
- **Source URL:** https://arxiv.org/abs/2603.26464  
- **Reference count:** 21  
- **Primary result:** KAE‑LSPI automatically learns features via a Koopman autoencoder, removing manual basis selection and achieving performance comparable to LSPI/KLSPI on chain walk and inverted pendulum benchmarks.

## Executive Summary
The paper addresses the long‑standing challenge of manual feature design in linear reinforcement learning methods like least‑squares policy iteration (LSPI). It proposes Koopman autoencoder‑based LSPI (KAE‑LSPI), which reformulates the LSPI fixed‑point approximation within the Koopman operator framework. This reformulation permits a neural network—the Koopman autoencoder—to learn a feature mapping from state‑action pairs to a latent space where dynamics are approximately linear. The learned features replace hand‑crafted bases or kernels, enabling fully automatic feature discovery.  
KAE‑LSPI operates in two phases: first, a random policy generates a dataset of transitions; second, a Koopman autoencoder trains to learn feature functions and a linear Koopman matrix. The frozen encoder then serves as the feature map in the LSPI loop for policy evaluation and improvement. Experiments on stochastic chain walk (20 and 50 states) and an inverted pendulum show that KAE‑LSPI learns a modest number of features (15–46), converges to optimal or near‑optimal policies in a comparable number of iterations to LSPI/KLSPI, and matches LSPI’s performance on the pendulum task.

## Method Summary
KAE‑LSPI consists of an offline training phase and an iterative policy improvement phase. In the offline phase, a random policy collects transitions \((s, a, r, s')\). For each transition, state‑action pairs \(x = (s,a)\) and \(x' = (s', \pi_{\text{rand}}(s'))\) are constructed. A Koopman autoencoder—comprising an encoder \(\Phi\), decoder \(\Psi\), and a linear matrix \(K\)—is trained to minimize a composite loss: reconstruction error \(L_{\text{rec}}\), prediction error \(L_{\text{pred}}\), and a dynamics loss \(L_{\text{dyn}} = \|\Phi(x') - \Phi(x)K\|^2\). The dynamics loss enforces linear evolution in the latent space: latent features \(z = \Phi(x)\) should satisfy \(z' \approx zK\). After training, \(\Phi\) (with predefined latent dimension \(k\)) becomes the automatic feature map \(\phi(s,a)\).  
In the online LSPI phase, the encoder is frozen. Starting from an initial policy \(\pi_0\), the algorithm iterates: (i) policy evaluation: compute feature matrices \(\Phi\) (for all \(x\) in the dataset) and \(\Phi'_{\pi_j}\) (for \(x' = (s', \pi_j(s'))\)) and reward vector \(R\); solve the linear system \(\Phi^T(\Phi - \gamma \Phi'_{\pi_j}) w = \Phi^T R\) for weights \(w\); (ii) policy improvement: set \(\pi_{j+1}(s) = \argmax_a \phi(s,a) w\). Iteration stops when the policy stabilizes or a maximum number of iterations is reached. The method assumes that features learned from random‑policy data remain suitable for policies encountered during iteration.

## Key Results
- KAE‑LSPI automatically determines feature counts: 15 for the 20‑state chain, 45 for the 50‑state chain, and 46 for the pendulum task.  
- The algorithm converges to an optimal or near‑optimal policy within a number of LSPI iterations comparable to that of standard LSPI and KLSPI.  
- On the inverted pendulum benchmark, the final policy performance matches that of LSPI, demonstrating the effectiveness of the learned features.

## Why This Works (Mechanism)

**Mechanism 1: Koopman reformulation decouples features from policy evaluation**  
The core of LSPI is solving a least‑squares fixed‑point equation: \(\Phi^T(\Phi - \gamma \Phi'_\pi) w = \Phi^T R\), where \(\Phi\) and \(\Phi'_\pi\) are feature matrices for current and next‑state actions. By substituting the Koopman operator approximation \(\Phi'_\pi \approx K^\pi \Phi\) (where \(K^\pi\) approximates the Bellman operator in the feature space), the equation becomes \(\Phi^T(\Phi - \gamma K^\pi \Phi) w = \Phi^T R\). This reformulation separates the unknown weight vector \(w\) from the feature map \(\phi\); the features no longer need to be fixed a priori. The Bellman operator is now represented by a finite matrix \(K^\pi\) acting on the learned features. The key assumption is that a nonlinear feature map exists such that the Koopman approximation \(\phi(s',\pi(s')) \approx \phi(s,a) K^\pi\) is accurate enough for the linear value approximation \(Q^\pi(s,a)=\phi(s,a)w\) to converge to \(Q^*\). Evidence: Section II.3 and III derive Eq. (12) showing this substitution; the abstract explicitly states the reformulation enables automatic feature learning. If the learned features do not span a subspace where the Bellman operator is well approximated by a finite linear operator, the linear system becomes ill‑conditioned and convergence fails.

**Mechanism 2: Koopman Autoencoder enforces linear latent dynamics**  
The Koopman autoencoder (KAE) jointly learns an encoder \(\Phi: x \to z\), a decoder \(\Psi: z \to x\), and a linear matrix \(K\). Training minimizes \(L = \lambda_{\text{rec}} L_{\text{rec}} + \lambda_{\text{pred}} L_{\text{pred}} + \lambda_{\text{dyn}} L_{\text{dyn}}\), where \(L_{\text{dyn}} = \|\Phi(x') - \Phi(x)K\|^2\). This dynamics loss forces the latent representation to evolve linearly: \(z' \approx zK\). After training, \(\phi(s,a) = \Phi(s,a)\). The architecture assumes the neural network class is expressive enough to achieve low \(L_{\text{dyn}}\) while maintaining good reconstruction; the latent dimension \(k\) must be chosen beforehand. Evidence: Section III and Fig. 1 detail the architecture and losses; the abstract cites the KAE framework. Neighboring works like KOROL and KEEC validate Koopman autoencoders for dynamics learning. Failure occurs if training converges to a solution with high \(L_{\text{dyn}}\), if \(k\) is too small/large, or if the network gets stuck in a poor local minimum.

**Mechanism 3: Off‑policy feature transfer from random to optimal policies**  
KAE‑LSPI is a two‑phase, off‑policy algorithm. Phase 1 uses data from a random policy \(\pi\) to train the KAE, learning features \(\phi\) and the *on‑policy* Koopman matrix \(K^\pi\) for that random policy. Phase 2 freezes \(\phi\) and runs standard LSPI, repeatedly solving the linear system with the current policy \(\pi_j\) (which requires evaluating \(\Phi'\) for \(\pi_j\)) and improving the policy. This design assumes that the features learned under the random policy are sufficiently rich and approximately Koopman‑invariant so that they remain effective for the improved policies \(\pi_j\) during iteration. Evidence: Algorithm 1 in Section III clearly separates the KAE learning step (using random \(\pi\) data) from the LSPI loop; Section IV reports successful convergence on chain and pendulum tasks, supporting the transfer assumption. If the random‑policy features are not generalizable to the optimal policy’s state‑action space, the linear approximation in LSPI will be limited regardless of iteration, causing a performance ceiling.

## Architecture Onboarding
**Component Map**  
Data Generator → Koopman Autoencoder (KAE) → Feature Extractor (frozen encoder) → LSPI Solver

**Critical Path**  
1. Collect dataset with random policy.  
2. Train KAE to learn encoder \(\Phi\), decoder \(\Psi\), and Koopman matrix \(K\).  
3. Freeze \(\Phi\) as the feature function \(\phi(s,a)\).  
4. Run LSPI iterations: for current policy \(\pi_j\), compute feature matrices \(\Phi\) and \(\Phi'_{\pi_j}\), solve linear system for \(w\), improve policy to \(\pi_{j+1}\). Stop when stable or max iterations reached.

**Design Tradeoffs**  
- *Feature count \(k\)*: Must be set manually; too small limits expressivity, too large may cause overfitting and ill‑conditioned linear systems (paper uses 15–46).  
- *Off‑policy vs On‑policy*: Current KAE‑LSPI uses a fixed dataset from a random policy for all iterations, which is efficient but assumes feature transferability. An on‑policy variant (regenerating data after each improvement) could adapt features but at higher computational cost.  
- *Loss weights (\(\lambda_{\text{rec}}, \lambda_{\text{pred}}, \lambda_{\text{dyn}}}\))*: Balance reconstruction, prediction, and dynamics linearity. The paper sets \(\lambda_{\text{dyn}}=0.1\), subordinating exact reconstruction to linear dynamics; tuning these affects feature quality.

**Failure Signatures**  
- *KAE training*: Divergence or persistently high \(L_{\text{dyn}}\) indicates the latent space does not satisfy linear dynamics; may require increasing \(\lambda_{\text{dyn}}\), network capacity, or adjusting data scaling.  
- *LSPI linear system*: Matrix \(A = \Phi^T(\Phi - \gamma \Phi'_\pi)\) becomes near‑singular, signaled by a large condition number; remedy by adding ridge regularization or reducing feature dimension.  
- *Policy performance*: Plateaus below optimal suggest the learned features are insufficiently expressive or not transferable to improved policies.

**First 3 Experiments for Validation**  
1. *KAE dynamics validation*: Train KAE on random data, verify \(L_{\text{rec}}\) and \(L_{\text{dyn}}\) decrease; check that latent trajectories follow \(z_{t+1} \approx K z_t\) on held‑out pairs.  
2. *Feature transfer test on minimal MDP*: On a 3‑state chain, compare LSPI using handcrafted sufficient features vs. features from a pre‑trained KAE (random policy). If KAE fails to reach the optimal policy, the transfer assumption is flawed even in a simple setting.  
3. *Sensitivity to feature count \(k\)*: On the 20‑state chain, run KAE‑LSPI with \(k \in \{5, 15, 50\}\). Plot performance (e.g., iterations to convergence, average return) vs. \(k\); expect a U‑curve indicating an optimal middle ground.

## Open Questions the Paper Calls Out
1. **Automatic selection of feature count \(k\)** – The paper manually sets \(k\); a method to automatically determine \(k\) (e.g., via pruning or growing the autoencoder bottleneck) remains an open direction.  
2. **Online, on‑policy extension** – Could KAE‑LSPI be modified to update features incrementally after each policy improvement, reducing computational overhead compared to KLSPI?  
3. **Convergence guarantees** – What are the theoretical convergence properties of the two‑phase algorithm, and how do errors in the Koopman autoencoder approximation affect overall policy iteration convergence?  
4. **Finite‑sample regret bounds** – Can we derive regret bounds for KAE‑LSPI by leveraging existing Koopman operator error bounds? Such bounds would provide performance guarantees and guide sample complexity.

## Limitations
- Experiments limited to small chain (≤50 states) and simple pendulum; scalability to high‑dimensional tasks is unproven.  
- Feature dimensionality \(k\) must be chosen manually; the algorithm lacks an automatic mechanism and may suffer performance degradation if \(k\) is poorly set.  
- The off‑policy feature transfer assumption (using random‑policy data for all iterations) is not theoretically justified and may not hold for diverse MDPs.  
- Implementation details (e.g., exact activation placement, LSPI regularization) are insufficiently specified, hindering reproducibility.  
- No convergence analysis or regret bounds are provided, leaving the theoretical foundations open.
