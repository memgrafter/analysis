# Decoupling Geometric Planning and Execution in Scalable Multi-Agent Path Finding

## Quick Facts
- **arXiv ID**: 2603.26684  
- **Source URL**: https://arxiv.org/abs/2603.26684  
- **Reference count**: 12  
- **Primary result**: Achieves near-linear runtime scaling, 100% success on geometrically feasible instances, and reduces sum-of-costs by up to 23.1% in bottleneck-heavy maps by cutting waiting actions by 70%, outperforming prioritized and bounded-suboptimal baselines in dense scenarios.

## Executive Summary
This paper introduces a hybrid two-stage framework for Multi-Agent Path Finding (MAPF) that decouples geometric planning from execution-time conflict resolution. The first stage, Geometric Conflict Preemption (GCP), sequentially plans each agent’s geometric path using A* on the original graph with cost inflation to avoid higher-priority footprints. The second stage, Decentralized Local Controller (DLC), executes these paths using per-vertex FIFO queues that serialize vertex access and implicitly prevent edge-swap conflicts. Evaluated on up to 1000 agents, the approach achieves near-linear runtime scaling and perfect success on geometrically feasible instances, while significantly reducing sum-of-costs in bottleneck-heavy maps compared to state-of-the-art baselines.

## Method Summary
The framework operates in two phases. In the geometric planning phase (GCP), agents are planned in a fixed priority order. For each agent, a residual graph is constructed by removing goals of higher-priority agents. Edge costs are inflated by adding a penalty based on the first-visit index of the target vertex in each higher-priority path, encouraging detours that avoid contested areas. A* then computes a shortest path on this inflated graph. In the execution phase (DLC), per-vertex FIFO queues are built offline by listing agents in global priority order for every vertex they visit. During online simulation, an agent may move to its next vertex only if it heads that vertex’s queue; otherwise it waits. This simple rule guarantees collision-free execution with minimal extra waiting, assuming agents strictly follow their geometric paths.

## Key Results
- Near-linear runtime scaling with agent count, enabling solution of instances with up to 1000 agents.
- 100% success rate on geometrically feasible instances across benchmark maps.
- Sum-of-costs reduced by up to 23.1% in bottleneck-heavy maps (room-64-64-8) due to 70% fewer waiting actions versus prioritized baselines.

## Why This Works (Mechanism)
### Mechanism 1
Cost inflation in GCP reduces downstream contention by encouraging geometric detours that avoid vertices heavily used by higher-priority agents. For agent *i*, edge costs entering vertex *v* are inflated by a penalty equal to the first-visit index of *v* in each higher-priority path. This makes A* prefer routes that minimize early overlap with those footprints. The first-visit index approximates how long a vertex is occupied. If higher-priority agents have long, pervasive footprints, inflation may force later agents into excessively long detours, increasing spatial cost without reducing conflicts.

### Mechanism 2
Per-vertex FIFO authorization queues in DLC guarantee collision-free execution with minimal extra waiting by serializing vertex access and implicitly preventing edge-swaps. Queues are built offline by appending agents in global priority order for every vertex visit. During execution, an agent moves to a vertex only if it heads that vertex’s queue; otherwise it waits. Consistent ordering across edge endpoints blocks opposite traversals. This mechanism requires the queue ordering to be consistent across shared vertices and assumes agents follow their geometric paths exactly.

### Mechanism 3
Decoupling geometric planning from execution avoids time-expanded state explosion, enabling near-linear scalability. GCP solves independent shortest-path problems on the original graph (with inflation), avoiding a joint space–time model. DLC then resolves residual conflicts locally via queues, sidestepping centralized conflict searches over time. The approach assumes geometric feasibility (Assumption 3.1) and that local queuing suffices to prevent all conflicts during asynchronous execution.

## Architecture Onboarding
- **Component map**: GCP -> DLC (two-stage pipeline).  
- **Critical path**: GCP must finish sequentially for all agents (sum of A* runtimes). DLC offline construction is linear in total path length; online execution time equals makespan. Planning time dominates GCP.  
- **Design tradeoffs**: Priority ordering (e.g., CL vs. SPF) greatly affects SOC in bottleneck maps; cost inflation trades spatial detours for temporal waiting; decoupling sacrifices optimality for linear scaling.  
- **Failure signatures**: GCP fails if an agent’s start/goal is excluded from its residual graph (violates Assumption 3.1) or if A* finds no path. DLC cannot deadlock under the assumption but may produce high SOC if inflation is mis-set.

## Limitations
- Cost inflation proxy may misestimate vertex occupation if lower-priority agents incur waiting, leading to suboptimal detours or failures in long-horizon dense scenarios.
- Fixed priority order: DLC requires precomputed queues; any replanning or path alteration invalidates them.
- Geometric feasibility (Assumption 3.1) may break on many realistic maps with high agent counts, causing planner aborts.

## Confidence
