# Taxonomy-Aligned Risk Extraction from 10-K Filings with Autonomous Improvement Using LLMs

## Quick Facts
- arXiv ID: 2601.15247
- Source URL: https://arxiv.org/abs/2601.15247
- Reference count: 28
- Primary result: Extracted 10,688 validated risk factors from S&P 500 filings; same-industry risk profile similarity 63% higher than cross-industry (Cohen's d=1.06, AUC 0.733–0.822, p<0.001); autonomous refinement improved embedding separation by 104.7% for one category.

## Executive Summary
This paper introduces a three-stage pipeline for mapping free-form risk factors extracted from 10-K filings to a predefined taxonomy without spurious assignments. It combines LLM extraction with supporting quotes, embedding-based semantic matching, and LLM-as-a-judge validation to ensure high precision. A feedback loop enables autonomous taxonomy refinement. Evaluated on S&P 500 filings, the method yields a large corpus of validated risks and demonstrates strong industry-specific clustering. A case study shows significant improvement in category separation through automated refinement.

## Method Summary
The pipeline first uses an LLM (Claude 4.5 Sonnet) to extract risk factors and verbatim supporting quotes from the Item 1A section, keeping the taxonomy withheld to avoid forced fits. Each quote is embedded using Qwen3-Embedding-0.6B with a task-specific instruction, and nearest-neighbor matching assigns it to the most similar taxonomy category description. A separate LLM then validates each mapping with a 1–5 quality score; only mappings scoring ≥4 are retained. Low-score mappings are logged and periodically analyzed by an agent that proposes refined category descriptions, which are adopted if they improve embedding separation.

## Key Results
- 10,688 validated risk factors extracted across S&P 500 10-K filings.
- External validation: same-industry companies exhibit 63% higher risk profile similarity than cross-industry pairs (Cohen's d=1.06, AUC 0.733–0.822, p<0.001).
- Autonomous refinement case study: 104.7% improvement in embedding separation for a problematic tertiary category.

## Why This Works (Mechanism)
The approach succeeds by decoupling risk identification from classification, using verifiable quotes to ground mappings. Instruction-tuned embeddings capture semantic similarity between quotes and category descriptions, while an LLM judge provides nuanced quality filtering. The feedback loop turns validation failures into signals for taxonomy improvement, creating a self-correcting system. This avoids spurious assignments that plague purely embedding-based or LLM-only methods.

## Foundational Learning
1. **Supporting Quote Extraction**  
   Why needed: Ensures each extracted risk is anchored in the source text, preventing hallucination and providing a concrete snippet for semantic matching.  
   Quick check: Does the extraction stage require a verbatim quote from the source document for every risk tag?

2. **Instruction‑Tuned Dense Embeddings**  
   Why needed: Aligns the vector space to the specific task of risk classification, improving matching accuracy over generic embeddings.  
   Quick check: Are both taxonomy descriptions and extracted quotes embedded with the same instruction (“Classify risk factor text from an annual report into the most appropriate taxonomy category”)?

3. **LLM‑as‑a‑Judge with Feedback Loop**  
   Why needed: Provides reliable quality scoring to filter low-confidence mappings and aggregates failure patterns for autonomous taxonomy updates.  
   Quick check: Does the system retain only mappings with a judge score ≥4 and log lower scores for later analysis?

## Architecture Onboarding
- Component map:  
  LLM Extractor → Embedding Module → Similarity Matcher → LLM Judge → Quality Filter → Feedback Logger → Taxonomy Refinement Agent → Taxonomy Store  
  (Feedback loop: Feedback Logger → Taxonomy Refinement Agent → Taxonomy Store update)

- Critical path:  
  1. Item 1A text → LLM Extractor → list of (risk tag, supporting quote).  
  2. Each quote → embedding → dot-product with precomputed taxonomy embeddings → best category.  
  3. (quote, category, description) → LLM Judge → quality score & reasoning.  
  4. Score ≥4 → final output; else → Feedback Logger.  
  5. Periodic: Feedback Logger → Taxonomy Refinement Agent → analyze low-score patterns → propose refined descriptions → test via embedding separation → update Taxonomy Store if improvement threshold met.

- Design tradeoffs:  
  - Extraction LLM capability vs. cost/latency.  
  - Validation threshold (≥4) precision-recall balance.  
  - Refinement frequency vs. risk of overfitting.  
  - Embedding model size vs. compute/semantic granularity.

- Failure signatures:  
  - Industry clustering AUC drops below 0.7.  
  - Single taxonomy category accumulates >100 low-score mappings.  
  - LLM judge score distribution becomes highly polarized (mostly 1s and 5s).  
  - Refinement reduces embedding separation on a validation set.  
  - Extraction returns empty risk list for a filing.

- First 3 experiments:  
  1. Baseline without LLM validation: run embedding-only mapping, measure spurious assignment rate on a human-labeled sample.  
  2. Threshold sensitivity: vary quality score cutoff (e.g., 3, 4, 5) on a held-out set with human-validated mappings; plot precision/recall.  
  3. Autonomous refinement efficacy: select a problematic category, let the agent propose a description, compute embedding separation before/after, and measure impact on industry clustering.

## Open Questions the Paper Calls Out
1. Does the three-stage pipeline generalize to non-financial domains, achieving comparable taxonomy-aligned extraction quality?  
   Basis: Abstract claims generalization but evaluation is only on 10-K risk factors.  
   Why unresolved: No empirical tests in other domains.  
   Resolution: Replicate on a different domain (e.g., medical reports) and report precision/recall against human annotations.

2. How consistently does the autonomous taxonomy refinement agent improve embedding separation across all 140 categories, and what proportion require human oversight?  
   Basis: Case study shows 104.7% improvement for one category; no aggregate results.  
   Why unresolved: Scalability and variability across the full taxonomy unaddressed.  
   Resolution: Run the agent on all categories using accumulated low-quality mappings; analyze distribution of improvements and degradation cases.

3. What cost-precision trade-offs exist in the LLM-as-a-judge stage, and can embedding similarity thresholds reduce validation costs while maintaining high mapping quality?  
   Basis: Conclusion notes cost/latency; fixed threshold used without optimization analysis.  
   Why unresolved: Threshold selection arbitrary; no exploration of hybrid cost-saving strategies.  
   Resolution: Ablate quality threshold on a validation set, measure precision/recall/cost, and test using embedding scores to pre-filter mappings.

4. How robust is the pipeline to initial taxonomy design flaws (e.g., ambiguous descriptions, category overlap), and can autonomous refinement fully compensate for these?  
   Basis: Assumes reasonable starting taxonomy; no tests on recovery from poor designs.  
   Why unresolved: Resilience to common taxonomy flaws unknown.  
   Resolution: Intentionally degrade taxonomy with flaws (vagueness, redundancy), run pipeline with refinement, and measure recovery via embedding separation and industry clustering.

## Limitations
- The full 140-category taxonomy with descriptions is not released, hindering faithful reproduction.
- LLM judge prompt details, rubric specifics, and model configuration are unspecified, risking variability in validation performance.
- Evidence for autonomous refinement is limited to a single category; scalability and consistency across the taxonomy are unproven.

## Confidence
- Pipeline design & extraction mechanism: High
- Embedding-based mapping efficacy: Medium
- LLM-as-a-judge filtering: Medium
- Autonomous taxonomy improvement: Low
- External validation (industry clustering): High

## Next Checks
1. **Manual audit of low-score mappings**: Randomly sample 100 mappings with judge score <4. Verify whether the judge’s reasoning correctly identifies true mismatches vs. valid risks lacking clear category fits.
2. **Threshold sensitivity analysis**: On a held-out set with human-validated mappings, vary the quality score cutoff (e.g., 3, 4, 5) and compute precision/recall curves to validate the ≥4 threshold.
3. **Independent replication of embedding separation test**: For the case study category, re-implement the proposed refinement using the initial and new descriptions; confirm the 104.7% improvement in the separation metric.
