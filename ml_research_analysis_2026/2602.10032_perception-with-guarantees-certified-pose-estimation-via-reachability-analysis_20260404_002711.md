# Perception with Guarantees: Certified Pose Estimation via Reachability Analysis

## Quick Facts

- **arXiv ID:** 2602.10032  
- **Source URL:** https://arxiv.org/abs/2602.10032  
- **Reference count:** 40  
- **Primary result:** A certified 3D pose estimation method that guarantees containment of the true pose using only a single camera image and known target geometry, achieving ~50× volume reduction on synthetic landing planes and final pose volume as low as 1.17% on real event-camera data.

## Executive Summary

This paper introduces a certified pose estimation technique for safety-critical cyber-physical systems. Given a single camera image and a known 3D target, the method computes a set that provably contains the true 6D pose even under bounded image noise. It combines reachability analysis (via polynomial zonotopes) with formal neural network verification to propagate pose uncertainty through the camera model and refine candidate poses using constraints derived from image vertices. Evaluations on synthetic and real-world data show substantial uncertainty reduction while maintaining formal guarantees, with online computation on the order of seconds.

## Method Summary

The approach operates in two phases: offline partitioning and online refinement. Initially, the pose space is recursively divided into axis-aligned boxes (candidates) based on the tightness of their image enclosures. For each candidate, the offline precomputation uses polynomial zonotopes to compute a sound outer-approximative binary image set (`bIE`) that contains all possible images from any pose in the candidate, along with vertex zonotopes for each target polygon. During online operation, an observed noisy binary image `I*` is checked against each candidate’s `bIE`; candidates where `I*` is not fully contained are discarded as impossible. For surviving candidates, witness pixels (turned-on pixels in `I*` that lie within the precomputed vertex sets) are identified. Pre-image enclosure applied to the pose-to-vertex mapping yields linear constraints on the latent pose space; intersecting these with the candidate’s box gives a tightened certified subset. The final certified pose estimate is the union of all constrained subsets, guaranteeing inclusion of the true pose with significantly reduced volume.

## Key Results

- Synthetic landing plane experiments (200×200 images): the true pose was always contained; pose volume reduced by ~50× beyond initial filtering; online time 2.81 s.
- Real event-camera data (640×480, 138 images): true pose localized within 2.14 s, achieving a final volume of 1.17% of the initial space.
- Standalone image enclosures achieved an average linearization error ratio of 18.6%, confirming tight outer-approximations.

## Why This Works (Mechanism)

### Mechanism 1: Sound Image Enclosure

**Claim:** Sound outer-approximations of all possible images from any pose within an uncertain candidate set are computable.  
**Mechanism:** The uncertain 6D pose is represented as a matrix polynomial zonotope. Propagation through the analytical pinhole camera model (rotation, translation, projection) uses set operations (Minkowski sum, linear map, convex hull). The nonlinear division in the projection is enclosed via polynomial zonotope over-approximation, yielding a binary image zonotope `bIE` guaranteed to contain the image of any concrete pose in the set.  
**Break condition:** If the polynomial zonotope enclosure of the division becomes excessively loose due to large pose uncertainty or extreme perspective, `bIE` may degrade to a trivial bound, failing to filter candidates effectively.

### Mechanism 2: Candidate Filtering

**Claim:** Pose candidates inconsistent with the observed image can be decisively eliminated.  
**Mechanism:** For each precomputed candidate box `Ec`, a sound image enclosure `bIEc` is available. Given the observed noisy image `I*`, the containment check `I* ⊆ bIEc` discards any candidate `Ec` for which the check fails. Soundness from Mechanism 1 ensures that if `I*` is not contained in `bIEc`, the true pose cannot lie in `Ec`.  
**Break condition:** If `bIEc` is too conservative (e.g., due to loose zonotope operations), candidates containing the true pose might be incorrectly discarded (`I* ⊄ bIEc` despite `ξ* ∈ Ec`).

### Mechanism 3: Latent Space Constraint Synthesis

**Claim:** For surviving candidates, constraints on the shared latent space (the original pose uncertainty box) can be derived from the observed vertex positions in the image.  
**Mechanism:** The uncertain image vertex sets `V_PCFc,i(·,k)` computed in Mechanism 1 are affine projections of the pose candidate’s latent hypercube. Using pre-image enclosure, it is enforced that the true vertex `V*i(·,k)` must lie within a set derived from `I*` (the witness pixels `Q*c,i,k` expanded by pixel size `D`). This yields linear constraints `Cc,i,k ≤ dc,i,k` on the latent space. Intersecting constraints from all vertices/polygons produces a tightened certified set `Ec | Cc ≤ dc`.  
**Break condition:** If vertices overlap (violating the standalone assumption) and witness pixels are ambiguous, constraints may become too loose or incorrectly applied; excessive noise forces the use of all turned-on pixels, weakening tightening.

## Foundational Learning

- **Set-based computing with polynomial zonotopes**  
  *Why needed:* Provides a representation for propagating pose uncertainty through the camera model with guaranteed outer-approximations, enabling sound but tractable enclosures of nonlinear functions. Polynomial zonotopes combine interval and polynomial approximations to balance tightness and complexity.

- **Formal neural network verification (pre-image computation)**  
  *Why needed:* The image enclosure `bIE` relies on function enclosure for nonlinearities (`sin`, `cos`, `1/x`) encountered when propagating pose uncertainty. Constraint tightening directly uses pre-image enclosure to map image constraints back to the pose space, which is the inverse of the usual forward reachability.  
  *Quick check:* Explain the difference between output set enclosure (`Y ⊇ f(X)`) and pre-image enclosure (`f^{-1}_X(U) ⊆ X|C≤d`). Why is the latter crucial for certified pose estimation?

- **Camera geometry and projection models**  
  *Why needed:* The entire forward model (pinhole projection with rotation, translation, intrinsic parameters) is the function whose inverse must be bounded. Understanding the coordinate frames (TCF, CCF, PCF) and the effect of the perspective division is essential to grasp the transformation being enclosed.

## Architecture Onboarding

**Component map (plain text):**  
Pose Space Partitioning (offline) → Candidate Pre-computation (offline) → Online Filtering → Witness Pixel Extraction → Constraint Synthesis → Certified Pose Set Union.

**Critical path:** Offline pre-computation (computing `bIEc` and `V_PCFc` for all candidates) is the heaviest computational load. Online performance is dominated by batch containment checks (`I* ⊆ bIEc`) and the application of linear constraints derived from witness pixels.

**Design tradeoffs:**  
- *Tightness vs. speed:* More support function directions in convex hull (Alg. 3) tighten `bPPCF` but increase cost; larger candidate set `ζ` improves coverage but hurts online time.  
- *Noise handling:* Basic denoising drastically reduces candidates; more sophisticated filtering could help but adds complexity.  
- *Vertex ambiguity:* The strict standalone condition (Eq. 18) ensures soundness but discards data from overlapping vertices (e.g., inner corners); relaxing it risks unsound constraints.

**Failure signatures:**  
- High candidate retention after filtering indicates loose `bIEc` envelopes.  
- Large final certified volume suggests witness pixel sets are too numerous (ineffective geometric pruning).  
- Empty certified set `E*` means the true pose was filtered out erroneously (soundness breach or underestimated noise budget).

**First 3 experiments:**  
1. *Validate Mechanism 1 (Soundness):* Sample concrete poses from a candidate, compute images, and verify they lie inside `bIE`; measure linearization error ratio.  
2. *Validate Mechanism 2 (Filtering):* For a fixed pose space, ensure the true pose is never discarded across diverse `I*`; measure discard rate vs. noise budget `τ`.  
3. *Validate Mechanism 3 (Constraining):* For surviving candidates, compute `E*` and measure volume reduction; systematically vary witness pixel heuristics to gauge impact on volume and containment.

## Open Questions the Paper Calls Out

- **Robustness to degraded visibility:** The method assumes the target is fully visible. Weather, occlusions, or adversarial attacks could break this assumption, and it is unclear how to maintain certification under partial visibility.
- **Optimizing witness pixel selection for noisy images:** Noisy pixels inflate witness sets, leading to conservative pose bounds. Better algorithms for selecting a minimal set of reliable witness pixels are needed.
- **Incorporating multiple targets:** The current work considers a single object. Combining multiple targets could improve accuracy, but challenges like overlapping images, occlusions, and uncertain relative positions remain unresolved.

## Limitations

- Polynomial approximations (for `sin`, `cos`, reciprocal) and partitioning thresholds (`δ`) are not fully specified; these affect tightness and computational trade-offs.
- Dataset specifics (exact 3D models, event-camera denoising parameters, noise budget calibration) are missing, hindering faithful reproduction and real-world guarantee.
- Edge cases such as overlapping polygon vertices or extremely large initial pose uncertainty can degrade the image enclosure (trivial bounds) or invalidate the witness-pixel heuristics.

## Confidence

- **Mechanism 1 (Image enclosure):** High – formal guarantee supported by an average linearization error ratio of 18.6%.  
- **Mechanism 2 (Filtering):** High – soundness directly inherited from Mechanism 1; synthetic experiments showed 0% false dismissals.  
- **Mechanism 3 (Constraint tightening):** Medium – depends on correct witness pixel extraction; vulnerable to vertex overlap and image noise; soundness is conditional on geometric heuristics.
