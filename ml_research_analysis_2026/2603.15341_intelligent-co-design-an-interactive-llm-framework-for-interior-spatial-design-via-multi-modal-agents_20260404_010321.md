# Intelligent Co-Design: An Interactive LLM Framework for Interior Spatial Design via Multi-Modal Agents

## Quick Facts
- **arXiv ID:** 2603.15341
- **Source URL:** https://arxiv.org/abs/2603.15341
- **Reference count:** 40
- **Primary result:** An interactive LLM multi-agent framework enables non-designers to co-create 3D interior layouts via natural language, with user satisfaction at 77% and 51% preferring it over traditional tools like SketchUp.

## Executive Summary
This paper introduces an interactive framework that bridges communication gaps in interior design by allowing non-designers to collaboratively generate 3D spatial layouts using natural language and reference images. The system employs a multi-agent LLM architecture (Reference, Spatial, Interactive, Grader) where a specialized Spatial Agent converts user intent into structured spatial constraints via Retrieval-Augmented Generation (RAG). These constraints are optimized into 3D scenes through iterative feedback loops—either via human user refinement or automated grading. Evaluations demonstrate that interactive designs significantly outperform non-interactive baselines, with average scores across intent alignment, aesthetics, functionality, and circulation improving by 0.75–1.25 points per test case. A user study (n=53) further reports high satisfaction (77%) and a clear preference (51%) over conventional design software.

## Method Summary
The framework orchestrates four specialized LLM agents without model fine-tuning. The Reference Agent processes reference images into textual descriptions using a vision-language model (LLaVa). The Spatial Agent, the core component, executes a three-stage chain-of-thought pipeline (object selection, constraint generation, score term formulation) augmented by RAG from a local design-rule repository to produce machine-parseable `{object, constraint, parameters}` tuples. Users then interact via the Interactive Agent, which paraphrases the technical rules into plain language for acceptance or revision; rejected items trigger regeneration. In automatic mode, a lightweight Grader Agent (LLaVa) scores proposed layouts against reference images to guide refinement. Accepted rules are fed to a simulated annealing optimizer (Infinigen) to produce the final 3D scene. This decomposition and iterative refinement are the key methodological innovations.

## Key Results
- Interactive refinement loops increased design quality metrics by 0.75–1.25 points over non-interactive baselines across user intent, aesthetics, functionality, and circulation.
- User survey reported 77% satisfaction with the framework.
- 51% of users preferred the framework over traditional design software like SketchUp.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The framework converts non-designer intent into computable spatial rules via a specialized Spatial Agent using Retrieval-Augmented Generation (RAG) and chain-of-thought prompting.
- **Mechanism:** The Spatial Agent receives room specifications and reference descriptions, then executes a three-stage LLM pipeline (object selection, constraint generation, score terms) with RAG context from a local design-rule repository. This decomposes vague user requests into structured `{object, constraint, parameters}` tuples that a downstream optimization solver can consume.
- **Evidence anchors:** 
  - Abstract: "Specialized agents... collaboratively address core challenges: the agent system enables real-time user interaction for iterative spatial refinement, while Retrieval-Augmented Generation (RAG) reduces data dependency without requiring task-specific model training."
  - Section 3.4: Details the three-stage pipeline, RAG integration, and output format (`O_object`, `O_constraint`, `O_scoreterms`).
- **Break condition:** If the Spatial Agent's output fails syntax/parsing checks or violates RAG guidelines consistently across iterations, the rule-generation loop breaks or defaults to auto-mode Grader evaluation.

### Mechanism 2
- **Claim:** Interactive refinement via the Interactive Agent and user feedback loops increases alignment with user intent and design quality metrics.
- **Mechanism:** The Interactive Agent translates the Spatial Agent's technical output into plain language for user review. Users accept/reject each stage (object, constraint, score terms). Rejection triggers the Spatial Agent to regenerate based on feedback, iteratively aligning rules with user preferences.
- **Evidence anchors:**
  - Abstract: "The agent system enables real-time user interaction for iterative spatial refinement."
  - Section 3.1: Describes the three decision stages with accept/reject gates and manual vs. auto modes.
  - Section 4: Evaluation shows interactive designs scored 0.75–1.25 points higher per test case across four criteria vs. non-interactive baselines.
- **Break condition:** If user feedback is inconsistent, contradictory, or leads to unresolved constraint violations, the loop may terminate with a suboptimal layout or default to Grader-mode.

### Mechanism 3
- **Claim:** An independent Grader Agent (using a lightweight vision-language model) provides cost-effective automated quality control, enabling the auto-mode fallback and supplementing human evaluation.
- **Mechanism:** The Grader Agent (LLaVa-1.5-7B-hf) scores the Spatial Agent's proposed rules against reference images, returning a 0–100 score to guide regeneration in auto-mode, avoiding the token cost of querying large proprietary VLMs.
- **Evidence anchors:**
  - Section 3.6: "Leveraging the multimodal LLaVa-1.5-7B-hf... compares these rules with reference images, and returns a score between 0 and 100... Its lightweight, data-efficient, open-source model removes token costs in the iterative Spatial Agent to Grader Agent loop."
  - Section 4: Main evaluation used ChatGPT-o3 for grading, but the framework uses LLaVa for real-time auto-mode.
- **Break condition:** If the Grader's score does not improve over N iterations or remains below a threshold, auto-mode may yield a layout or prompt human intervention.

## Foundational Learning
- **Concept: Multi-Agent Systems with Specialized Roles**
  - **Why needed here:** Decomposes a complex design task into subtasks (image interpretation, rule generation, user translation, quality scoring) handled by distinct agents to avoid overloading a single LLM and to manage different modalities.
  - **Quick check:** Why might a single LLM performing all four roles fail compared to the specialized agent pipeline?
- **Concept: Retrieval-Augmented Generation (RAG)**
  - **Why needed here:** RAG supplies domain-specific design guidelines from a local repository, improving the Spatial Agent's accuracy without retraining, addressing the "data dependency" limitation of prior data-driven methods.
  - **Quick check:** How does RAG differ from fine-tuning, and why is it crucial for this framework's claim of resilience across diverse floor plans?
- **Concept: Prompt Engineering for Structured Output**
  - **Why needed here:** Strict templates and example-driven prompts ensure the Spatial Agent's outputs are parsable by the optimization solver, preventing runtime failures.

## Architecture Onboarding
- **Component map:** 
  Frontend UI -> Interactive Agent -> Spatial Agent -> (Reference Agent & Shared Memory) & (Grader Agent in auto-mode) -> Optimization Backend -> 3D Output
  Shared Memory connects Reference Agent, Spatial Agent, and Interactive Agent.
- **Critical path:** User input -> Reference Agent (if image provided) -> Spatial Agent (initial rules) -> **if manual mode** -> Interactive Agent -> User accept/reject loop -> back to Spatial Agent. **If auto mode** -> Grader Agent -> back to Spatial Agent. After acceptance -> Optimization -> 3D output.
- **Design tradeoffs:** 
  - Cost vs. Accessibility: Uses Claude + LLaVa to balance capability and cost vs. prohibitively expensive proprietary VLMs.
  - Automation vs. Control: Auto-mode reduces user burden but may miss subtle intent; manual-mode increases control but requires user engagement.
  - Generality vs. Precision: RAG provides guidelines without training but may not cover all edge-case layouts; hard-coded constraints ensure feasibility.
- **Failure signatures:**
  - Parsing errors from Spatial Agent output not matching expected templates.
  - Circular/contradictory user feedback causing infinite regeneration loops.
  - Grader Agent scoring low on all layouts despite user satisfaction (misalignment).
  - Optimization failing to place objects without constraint violations, especially in very small rooms.
- **First 3 experiments:**
  1. Unit test each agent's I/O: Feed fixed inputs and verify Spatial Agent produces syntactically valid rule dictionaries; verify Interactive Agent produces coherent plain language; verify Grader returns a numeric score.
  2. End-to-end run in auto-mode: With a simple room (e.g., 15m² studio), run full pipeline without user input. Check if final 3D scene respects all accepted constraints.
  3. Manual-mode interaction loop: Simulate a user rejecting the first object list (e.g., "remove armchair, add plants"). Verify Spatial Agent incorporates feedback and produces a new valid list that lacks the armchair and includes plants.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can the framework integrate drag-and-drop and real-time 3D preview capabilities to enhance user spatial reasoning and reduce iteration time?
  - **Basis in paper:** "user feedback highlighted needs for enhanced visual interaction (e.g., drag-and-drop interaction, real-time 3D previews)" (Conclusion).
  - **Why unresolved:** The existing text-only interface requires users to mentally visualize placements, which may impede non-designers and slow down the refinement process.
  - **What evidence would resolve it:** A between-subjects user study comparing the current system with an augmented version featuring interactive 2D/3D previews, evaluating metrics like design quality, completion time, and satisfaction.
- **Open Question 2:** What approach should be taken to implement multilingual support for the LLM agents while maintaining accuracy in spatial rule generation?
  - **Basis in paper:** "multilingual support to broaden accessibility" (Conclusion).
  - **Why unresolved:** The system's prompts and outputs are English-only, potentially excluding non-English speakers and risking translation errors of spatial concepts.
  - **What evidence would resolve it:** Develop localized prompt templates and conduct user testing with speakers of target languages, comparing rule accuracy and user experience against the English baseline.
- **Open Question 3:** Can alternative optimization algorithms (e.g., reinforcement learning, evolutionary methods) overcome the limitations of simulated annealing for unconventional spatial requirements?
  - **Basis in paper:** "depending on simulated annealing optimization restricts adaptability to unconventional spatial requirements" (Conclusion).
  - **Why unresolved:** Simulated annealing is a generic optimizer that may not efficiently explore complex, non-convex solution spaces or incorporate domain-specific heuristics for irregular layouts.
  - **What evidence would resolve it:** Replace the SA module with candidate optimizers and test on a dataset of non-standard floor plans and furniture arrangements, assessing layout validity, constraint satisfaction rates, and computational efficiency.
- **Open Question 4:** How can the multi-agent architecture be scaled to handle whole-building or urban-level design challenges, and what new agent roles or knowledge structures are necessary?
  - **Basis in paper:** "extend the framework to broader architectural scenarios such as urban planning and architecture design" (Conclusion).
  - **Why unresolved:** The current design targets single-room layouts with a limited object set; scaling up introduces multi-scale hierarchies, regulatory constraints, and coordination across larger spatial networks.
  - **What evidence would resolve it:** A pilot study applying the framework to a small urban district, introducing agents for parcel division, road network generation, and building massing, and evaluating the coherence and compliance of results with expert evaluations.

## Limitations
- The exact content and structure of the "local design-rule repository" used for RAG are unspecified, critically affecting the Spatial Agent's constraint quality and claims about generalizability.
- The Grader Agent's alignment with human preference in auto-mode is not directly validated, as the main human evaluation used a different model (ChatGPT-o3).
- Details of the simulated annealing solver (e.g., cost function weights, convergence criteria) are minimal, hindering exact reproduction of optimization behavior.

## Confidence
- **Multi-Agent Decomposition Mechanism:** High (well-specified in text and diagrams).
- **Interactive Feedback Improvement:** High (supported by comparative evaluation metrics).
- **Grader-Driven Auto-Mode Viability:** Medium (uses open-source model, but human alignment unproven).
- **Framework Generalizability Across Layouts:** Low (hinges on unrevealed RAG repository scope).

3. **Constraint Parsing Failure Rate:** Implement the exact Spatial Agent prompts. Over 100 diverse room inputs, log the percentage of LLM responses that fail to parse into the required `{object, constraint, parameters}` dictionary format on the first try.
