# Scaling Small Agents Through Strategy Auctions
## Quick Facts
- arXiv ID: 2602.02751
- Source URL: https://arxiv.org/abs/2602.02751
- Reference count: 40
- Primary result: SALE reduces reliance on the largest agent by 53%, lowers overall inference cost by 35%, and achieves higher pass@1 than the best single agent while advancing the accuracy–cost Pareto frontier over established routers.

## Executive Summary
This paper investigates whether small language model agents can cost-effectively handle complex, long-horizon tasks and how to optimally route tasks across agents of varying capabilities. It introduces Strategy Auctions for Workload Efficiency (SALE), a framework where agents submit short strategic plans as bids; a cost–value mechanism—combining price, plan length, entropy, and peer assessments—scores bids, and cheaper agents refine their bids using a shared auction memory. Across deep search and coding tasks, SALE significantly reduces dependence on the largest model, cuts overall inference costs, and surpasses the accuracy of any single agent and the state-of-the-art routers.

## Method Summary
SALE orchestrates a heterogeneous pool of LLM agents (e.g., Qwen3 4B–32B) with known per-token costs. For each task, every agent generates a concise strategic plan (`st,i`). A scoring function computes cost (`Ct,i`) as the product of the agent’s price and plan length, and value (`Vt,i`) as a weighted sum of plan entropy and peer-assessed quality (all agents score each plan on a 0–5 scale). Weights are learned on a development set by minimizing the worst-case `Ct,i − Vt,i` via a mixed-integer linear program. The provisional winner is the agent with the lowest cost–value score. Agents cheaper than this provisional winner then retrieve similar past tasks from a shared memory and use contrastive prompting to refine their strategies. If any refined bid improves the cost–value score, that agent becomes the final winner and executes its trace. After execution, the task, bids, and outcome are stored in memory for future refinement.

## Key Results
- SALE reduces reliance on the largest (32B) agent by 53% compared to a baseline that always uses the best single agent.
- Overall inference cost is lowered by 35% versus using the largest agent for all tasks.
- SALE achieves higher pass@1 than any single agent in the pool and consistently advances the accuracy–cost Pareto frontier over routers like WTP, CARROT, TO-Router, and FrugalGPT.
- The cumulative share of tasks handled by the smallest (4B) agent increases over time due to memory-guided refinement.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Short strategic plans predict downstream execution success better than task descriptions alone.
- **Mechanism:** Agents generate concise solution intents (`st,i`) before execution. These plans encode decomposition, tool choices, and anticipated challenges, providing an early, low-cost signal of execution viability.
- **Core assumption:** Plan quality correlates with trace quality.
- **Evidence anchors:** [abstract] agents bid with short strategic plans; bids are scored by a cost–value mechanism. [section 5] strategies are interpreted as bids used to compute both cost and value.
- **Break condition:** If strategies become divorced from execution outcomes (e.g., agents propose plausible but un-executable plans), routing accuracy degrades.

### Mechanism 2
- **Claim:** A learned cost–value scoring function optimally balances compute cost against expected performance across heterogeneous agents.
- **Mechanism:** Cost (`Ct,i`) combines price and plan length; value (`Vt,i`) combines normalized plan entropy and peer-assessed quality. Weights are tuned to minimize worst-case cost-minus-value on a training set.
- **Core assumption:** A unified, linear scoring rule can approximate the complex cost-performance trade-off across agents and tasks.
- **Evidence anchors:** [section 5] cost estimate formula; [section D.2] optimization objective; [section 6] reported reductions in cost and largest-agent reliance.
- **Break condition:** If the linear form cannot capture non-linear interactions (e.g., synergy effects between agent size and task complexity), routing may misallocate tasks.

### Mechanism 3
- **Claim:** Shared auction memory enables continuous self-improvement of smaller agents, dynamically expanding their effective capability.
- **Mechanism:** After each auction, all bids and outcomes are stored. When a cheaper agent loses initially, it retrieves similar past winning/losing strategy pairs and refines its bid via contrastive prompting. Refined bids can usurp the provisional winner.
- **Core assumption:** Smaller agents can learn to improve their strategies from examples of past wins by cost-efficient peers, without changing model weights.
- **Evidence anchors:** [section 5] memory retrieval and contrastive prompting; [section 7.3] cumulative share of tasks routed to the smallest agent increases over time; [section 7.4] memory-guided refinement grounds strategies.
- **Break condition:** If memory grows too large or retrieval becomes noisy, refinement may degrade rather than improve bids.

## Foundational Learning
- **Concept: LLM Agent Scaling Laws**  
  Why needed: The paper’s premise is that small agents fail to scale with task complexity. Understanding this non-linear relationship explains why routing is necessary.  
  Quick check: On a deep search task with τ(t)=12.5 minutes, what relative pass@1 does the 4B agent achieve vs. the 32B agent? (~25% from Figure 1a)

- **Concept: Test-Time Compute vs. Training**  
  Why needed: SALE is a test-time orchestration mechanism. Distinguishing inference-time routing/refinement from model training is key to understanding its "no separate router" advantage.  
  Quick check: Does SALE update the agent models’ weights? (No, it optimizes routing weights and uses memory for prompting only.)

- **Concept: Market-Based Mechanism Design**  
  Why needed: The auction metaphor structures coordination. Grasping cost–value minimization as a "profit" analog clarifies the objective.  
  Quick check: What does minimizing (Ct,i − Vt,i) encourage? (High value, low cost; akin to maximizing net utility.)

## Architecture Onboarding
- **Component map:**  
  Agent Pool (A): Heterogeneous LLM agents with known per-token cost π(ai)  
  Auction Memory (M): Stores (task, all bids, outcome) tuples for retrieval  
  Jury: All agents score each bid’s value via a Likert prompt  
  Router: Learns scoring weights by solving a min–max MILP on a dev set  
  Execution Environment: ARE with tools (search, Python, final_answer)  
  Critical path: For each task t: (1) All agents generate st,i. (2) Compute Ct,i and Vt,i. (3) Select provisional winner argmin_i(C−V). (4) Agents cheaper than provisional winner retrieve k=8 similar past tasks from M and refine bids via contrastive prompting. (5) Re-score refined bids; select final winner i*(t). (6) Execute a_i*(t) with its winning strategy. (7) Store (t, {st,i}, outcome) in M.

- **Design tradeoffs:**  
  Cost vs. accuracy: Weights balance these; ablations show all terms contribute.  
  Jury size vs. overhead: Full jury (all agents) gives best accuracy; single-judge ablations hurt performance.  
  Memory scale: Retrieval k fixed at 8; memory grows linearly—future work may need summarization.

- **Failure signatures:**  
  Over-escalation: SALE selects larger agent than oracle (common on easy tasks).  
  Under-escalation: SALE selects smaller agent that fails (rare).  
  Jury dominance: If one judge’s weight dominates, diversity benefit may reduce.

- **First 3 experiments:**  
  1. Replicate scaling validation: Plot pass@1 vs. τ(t) for single agents (Figure 1a) to confirm performance divergence.  
  2. Baseline comparison: Run WTP, CARROT, TO-Router, FrugalGPT on same test set; verify SALE advances Pareto frontier (Table 1, Figure 6).  
  3. Memory ablation: Disable refinement; measure drop in pass@1 and increase in cost (compare “SALE w/o memory” vs. “SALE” in Table 1).

## Open Questions the Paper Calls Out
1. How does SALE’s performance–cost trade-off change with agent pools that include significantly larger frontier models (e.g., 70B+ or closed-source APIs), given current evaluation used Qwen3 capped at 32B?
2. How can SALE’s memory mechanism be managed effectively over long deployments (thousands of tasks) without degradation, and which strategies (summarization, importance sampling, sliding windows) best preserve the self-improvement effect?
3. Does SALE’s strategy-based routing remain effective in domains where tool costs dominate LM token costs, and how must the cost function be adapted to capture such resource constraints?
4. Can the observed complementary failure modes (e.g., large agents overconfidently skipping tools, small agents using simpler strategies) be exploited more aggressively to improve routing accuracy, perhaps by enriching the decision signal beyond initial strategy text?
5. For tasks with clear substructure (e.g., planning followed by coding), does splitting the task and routing subtasks to different agents yield better cost–accuracy trade-offs than SALE’s single-agent allocation?

## Limitations
- Jury prompt wording and scoring rubric are undocumented; variations could bias weight learning and selections.
- Dev/test splits and random seeds are not specified, hindering exact replication of reported metrics.
- Memory grows unbounded; long-term retrieval noise might degrade performance.

## Confidence
- Plan-based routing (Mechanism 1): Medium. Supported by ablations but relies on a correlation that may not generalize.
- Cost–value optimization (Mechanism 2): Medium. Linear scoring works empirically yet may overlook non-linear agent–task interactions.
- Memory refinement (Mechanism 3): High. Consistent gains across experiments align with memory-augmented agent research.

## Next Checks
