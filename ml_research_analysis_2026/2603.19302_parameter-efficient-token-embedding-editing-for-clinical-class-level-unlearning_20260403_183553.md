# Parameter-Efficient Token Embedding Editing for Clinical Class-Level Unlearning

## Quick Facts
- **arXiv ID:** 2603.19302
- **Source URL:** https://arxiv.org/abs/2603.19302
- **Reference count:** 20
- **Primary result:** STEU achieves near-complete forgetting (forget F1 ≈ 0.0004) while editing only ~0.19% of model parameters, preserving high retained utility (retain F1 ≈ 0.4766).

## Executive Summary
This paper tackles machine unlearning in clinical text classification, aiming to remove a target disease class's predictive behavior from a trained model without full retraining. The proposed Sparse Token Embedding Unlearning (STEU) method identifies a small set of class-discriminative tokens via pointwise mutual information (PMI). It then updates only the embeddings for these tokens and the final classifier head, freezing all encoder layers. This targeted approach induces strong behavioral forgetting with minimal parameter changes. Experiments across multiple clinical datasets and encoder architectures show STEU significantly outperforms encoder-level unlearning baselines in parameter efficiency while maintaining utility on remaining classes.

## Method Summary
STEU operates in two phases. First, it computes a frequency-weighted PMI score for all tokens, comparing their occurrence in forget-class documents against retain-class documents. The top-k tokens (e.g., k=256) are selected as a sparse “forget signal” set. Second, the model is trained briefly with a constrained update surface: all encoder parameters and non-selected embedding rows are frozen. Only the embedding rows for the selected tokens and the final linear classification layer receive gradient updates. The training objective combines a forget loss (binary cross-entropy against zero labels for the forget class) and a utility loss (divergence between updated and original model predictions on the retain set). A gradient mask ensures only the designated embedding rows are modified.

## Key Results
- STEU on MIMIC-IV with BioClinicalBERT achieves forget F1 = 0.0004 and retain average F1 = 0.4766 after modifying only 0.19% of parameters.
- Performance is consistent across datasets (MIMIC-III, eICU) and encoders (BERT-base, DistilBERT), with forget F1 near zero and minimal retain utility drop.
- Encoder-level unlearning baselines require updating >19% of parameters to achieve comparable forgetting, making STEU vastly more parameter-efficient.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** PMI selects a sparse set of tokens whose embeddings encode most of the forget-class signal.
- **Mechanism:** Compute frequency-weighted PMI between tokens and the forget class; keep top-*k* tokens. Only these embeddings are updated.
- **Core assumption:** A disease class is largely triggered by a limited lexical vocabulary.
- **Evidence anchors:** 
  - [abstract] "identifies a small set of class-discriminative tokens via pointwise mutual information (PMI)"
  - [section] "Token Selection via PMI" details the scoring formula and rationale for frequency weighting.
- **Break condition:** If the class is defined by contextual patterns rather than specific tokens, PMI may miss critical cues, leaving residual predictiveness.

### Mechanism 2
- **Claim:** Freezing the encoder preserves representations for retain classes while allowing localized embedding edits.
- **Mechanism:** All encoder layers and non-selected embeddings are frozen; only chosen token embeddings and the classifier head receive gradients.
- **Core assumption:** Class-specific information for the target class is concentrated in a small subset of token embeddings, not distributed across encoder layers.
- **Evidence anchors:**
  - [abstract] "updates only PMI-selected token embeddings ... while keeping all encoder layers frozen"
  - [section] "Constrained Update Surface" explicitly describes the frozen encoder and masked embedding gradients.
- **Break condition:** If the encoder has already composed the target class signal from common tokens, freezing may block complete forgetting.

### Mechanism 3
- **Claim:** Dual loss balancing forget suppression and retain anchoring prevents utility collapse while driving forget F1 near zero.
- **Mechanism:** Minimize BCE on forget batch with zero labels (*L*<sub>forget</sub>) and minimize divergence between updated and original model predictions on retain batch (*L*<utility>).
- **Core assumption:** The retain loss regularizes updates to avoid over-suppression that could harm correlated classes.
- **Evidence anchors:**
  - [section] Equation (2) and surrounding text define the combined objective.
  - [results] Table 3 shows STEU achieves forget F1 = 0.0004 with retain F1 = 0.4766, outperforming encoder-level methods in parameter efficiency while maintaining utility.
- **Break condition:** If forget and retain classes share many features, the retain constraint may impede full forgetting; improper loss weighting (λ<sub>u</sub>, λ<sub>k</sub>) can also cause imbalance.

## Foundational Learning
### Concept: Behavioral Class-Level Unlearning
- **Why needed here:** Defines the problem—suppressing an entire disease category’s predictions, not removing individual records. Sets evaluation metrics (forget F1, retain F1) and success criteria.
- **Quick check:** What distinguishes behavioral unlearning from certified sample-level removal, and why is the former more practical in clinical deployments?

### Concept: Pointwise Mutual Information (PMI)
- **Why needed here:** Drives token selection; its label-awareness and frequency weighting produce a sparse, interpretable set of class-discriminative tokens.
- **Quick check:** How does the frequency term in PMI prevent rare, noisy tokens from dominating the selection?

### Concept: Gradient Masking
- **Why needed here:** Enables parameter efficiency by zeroing gradients for non-selected embedding rows, ensuring only a tiny fraction of parameters change.
- **Quick check:** Besides the selected token embeddings, which other parameters are trainable in STEU, and why are they necessary?

### Concept: Dual Loss Regularization
- **Why needed here:** Balances the competing goals of forgetting and utility preservation; the retain loss anchors non-target predictions to prevent overfitting to the forget set.
- **Quick check:** Why match predictions on the retain set to the original model instead of simply continuing standard classification training?

## Architecture Onboarding
### Component map
Token Selector (PMI scores) -> Selected Token IDs -> Embedding Layer (gradient mask applied) -> Frozen Encoder -> Trainable Classifier Head -> Output logits

### Critical path
1. Precompute PMI token selection offline from forget/retain token frequencies.
2. Per training step: sample one forget batch and one retain batch.
3. Forward pass: masked embedding lookup -> frozen encoder -> classifier head.
4. Compute loss: *L*<sub>forget</sub> (forget batch vs. zero labels) + *L*<utility> (retain batch predictions vs. original model predictions).
5. Backward pass: apply gradient mask to embedding matrix so only selected rows receive gradients.
6. Optimizer step updates selected embeddings and classifier head.

### Design tradeoffs
- **Token budget (*k*):** Larger *k* may improve forgetting but increases parameter change and risk to utility.
- **Head inclusion:** Adding head updates is critical for complete forgetting with negligible overhead.
- **PMI vs other selectors:** PMI is simple and deterministic but may miss context-sensitive signals; gradient-based attribution could be an alternative.
- **Freezing encoder:** Assumes class signal is in embeddings; may fail for abstract or compositional classes.

### Failure signatures
- **Forget F1 remains high (>0.1):** Check PMI scores and token relevance; verify classifier head is being updated.
- **Large retain F1 drop (Δ < -0.05):** Likely token budget too high or classes semantically overlapping; reduce *k* or adjust loss weighting.
- **Parameter count exceeds 0.2%:** Verify gradient mask implementation; ensure position/segment embeddings and non-selected embedding rows remain frozen.
- **Training instability:** Adjust loss weighting (λ<sub>u</sub>, λ<sub>k</sub>) or lower learning rate; track separate loss components.

### First 3 experiments
1. Replicate primary result: STEU on MIMIC-IV/BioClinicalBERT (k=256, with head). Expect forget F1 ~0.0004, retain F1 ~0.4766, params ~0.19%.
2. Ablation: Compare “emb only” vs. “emb+head” configurations. Expect forget F1 to drop significantly (from ~0.276 to ~0.0004) when head is included.
3. Cross-encoder validation: Apply STEU to BERT-base and DistilBERT on MIMIC-IV. Expect similarly low forget F1 and small retain delta, confirming architecture agnosticism.

## Open Questions the Paper Calls Out
1. **Generalization across datasets/seeds:** How does STEU perform on more EHR datasets with multiple random seeds? Current evaluation uses three datasets and single-seed runs.
2. **Token selector sensitivity:** How does PMI compare to gradient- or Fisher-based token importance selectors? Only PMI is evaluated.
3. **Privacy guarantees:** What are the formal privacy properties of STEU? Does it leak information about the forgotten class? No membership inference or influence analysis is provided.
4. **Extension to generative models:** Can STEU be applied to generative language models without degrading fluency while removing class-specific behavior? Only classification tasks are evaluated.
5. **Comparison to partitioned retraining:** How does STEU compare to methods like SISA in unlearning quality and computational cost? Such comparisons are not fully explored.

## Limitations
- Missing critical hyperparameters (λ_u, λ_k, minimum token frequency threshold, learning rate) hinders exact replication.
- PMI-based token selection may fail for classes defined by contextual or compositional patterns rather than specific lexical items.
- Ambiguity in the utility loss formulation (whether to match logits or probabilities) risks implementation drift.
- Evaluation is limited to three clinical datasets and single-seed runs, restricting claims about robustness.

## Confidence
- **High:** Empirical success of STEU in achieving strong forgetting with minimal parameter changes is supported by consistent results across multiple datasets and architectures.
- **Medium:** The mechanism that class signal is concentrated in a sparse set of token embeddings (via PMI) is plausible but not formally proven; sensitivity to token selection heuristic is unknown.
- **Medium:** The design of freezing the encoder and using a dual loss is logically sound for the clinical domain but its generalizability to other text domains or model architectures is not established.
- **Low:** Claims about broader applicability (e.g., to generative models) or privacy guarantees are speculative without evidence.

## Next Checks
1. **Hyperparameter sensitivity sweep:** Systematically vary λ_u, λ_k, token selection threshold (min frequency), top-k, and learning rate; report forgetting/retain F1 distributions and optimal ranges.
2. **Alternative token selector benchmark:** Implement gradient-based attribution and Fisher information-based selectors; compare unlearning effectiveness and required token budget on both lexical and contextual disease classes.
3. **Cross-domain and scale validation:** Test STEU on non-clinical multi-label tasks (e.g., topic classification) and larger models (e.g., RoBERTa-large) to assess generalizability beyond the paper’s clinical, base-model setting.
