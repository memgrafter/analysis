# Enhancing Instruction Following of LLMs via Activation Steering with Dynamic Rejection

## Quick Facts
- **arXiv ID:** 2603.06745
- **Source URL:** https://arxiv.org/abs/2603.06745
- **Reference count:** 40
- **Primary result:** DIRECTER improves average instruction-following accuracy by up to 6.5% over strong baselines while preserving output quality, with only a ~16% throughput reduction.

## Executive Summary
Large language models (LLMs) often fail to follow complex instructions due to oversteering in existing activation steering methods. This paper introduces DIRECTER (Dynamic Rejection Steering), a test-time intervention that dynamically modulates steering strength by scaling the KV cache of instruction-related tokens. It employs a plausibility-guided decoding loop that compares the steered output distribution to the model's raw distribution at each generation step; if the steered output is implausible, steering strength is progressively reduced by halving the set of steered layers. Layer selection is guided by a one-time attention sensitivity analysis that ranks layers by their influence. Evaluations on IFEval, LIFBench, and GSM8K-Format show significant gains in instruction-following accuracy with minimal impact on text quality and throughput.

## Method Summary
DIRECTER operates in two phases. First, a one-time sensitivity analysis ranks model layers by their influence on the output distribution when keys are scaled; layers are ordered by the average cosine-distance disturbance they cause to all layers' attention states. Second, during decoding, for each token the method checks if the model's raw top-2 token probabilities are too close (using a fixed threshold β=0.5). If so, it starts with the full ranked layer set, applies key scaling (α=100) to those layers' KV caches for instruction tokens, and computes a steered distribution. The steered token is accepted only if its raw probability is not less than β times the raw top-1 token's probability. If rejected, the lowest-ranked half of layers are removed and the check repeats. If no candidate set passes, the raw distribution decodes. This dynamic loop prevents oversteering while maintaining steering efficacy.

## Key Results
- Improves average instruction-following accuracy by up to 6.5% on IFEval, LIFBench, and GSM8K-Format versus baselines like PASTA and SpotLight.
- Preserves text quality and task fidelity as judged by an LLM, with negligible impact on language modeling perplexity.
- Incurs only a ~16% throughput reduction due to the plausibility gate skipping many decoding steps.
- The plausibility-guided mechanism also mitigates oversteering when used as a safety wrapper around other steering methods.

## Why This Works (Mechanism)

### Mechanism 1: Plausibility-Guided Steering Adaptation
- **Claim:** Steering strength is dynamically reduced when the steered output distribution deviates unacceptably from the model's raw distribution, preventing oversteering.
- **Mechanism:** At each token step, DIRECTER compares a candidate steered distribution to the raw distribution. A token is accepted only if its steered probability meets \(p_t(i) \geq \beta \cdot p_t(i^*)\), where \(i^*\) is the raw top-1 token. If not, the candidate layer set is halved (removing lowest sensitivity layers) and the check repeats. If no set passes, raw decoding is used.
- **Core assumption:** A plausible output aligns with the raw model's high-probability tokens; large divergence indicates oversteering that harms quality or task fidelity.
- **Evidence anchors:** [abstract] describes the dynamic weakening; [section 3.2] details the iterative halving and probability threshold; [section 4.3] ablation shows the gate's necessity.

### Mechanism 2: Sensitivity-Guided Layer Ranking
- **Claim:** Layers most influential for steering are ranked once via attention sensitivity, enabling effective "strength tuning" by halving the ranked list.
- **Mechanism:** For each layer ℓ, its sensitivity is the average cosine-distance disturbance it causes to all layers' pre/post attention states when keys are scaled. Layers are ranked descending by this score; top-ranked layers are used first in the adaptive loop.
- **Core assumption:** Disturbance in cosine distance captures directional shifts in attention outputs; summing over all layers isolates the global impact of perturbing ℓ.
- **Evidence anchors:** [section 3.2] defines \(D_j(\ell)\) and sensitivity aggregation; [section 4.3] ablation reversing ranking degrades performance (79.0 vs. 81.8), validating ranking necessity.

### Mechanism 3: KV Cache Scaling as Steering Primitive
- **Claim:** Scaling instruction token keys in the KV cache modifies attention distributions with minimal overhead and without renormalization.
- **Mechanism:** For steered layer ℓ and instruction token position i, \(k'_i = \alpha \cdot k_i\) (with \(\alpha \gg 1\)). Softmax renormalizes, amplifying attention to instruction tokens indirectly via score shifts. Values remain unscaled.
- **Core assumption:** Key scaling alters attention logits; subsequent softmax renormalizes, avoiding extra computation needed for explicit value scaling.
- **Evidence anchors:** [section 3.1] explains efficiency and renormalization; [section 4.3] Figure 3b shows robustness over α orders; Figure 10 shows key scaling outperforms value scaling.

## Architecture Onboarding
- **Component map:**
  KV Cache Manager -> Sensitivity Analyzer -> Plausibility Gate -> Layer Halver -> Gating Optimizer
  (Sensitivity Analyzer runs once pre-decoding; Plausibility Gate, Layer Halver, Gating Optimizer operate per token)
- **Critical path:**
  1. Prefill prompt → raw KV cache.
  2. Run sensitivity analysis → rank layers \(L_{\text{ranked}}\).
  3. For each decode step \(t\):
     a. Forward raw → \(p_t\).
     b. If \(p_t^{(2)} < \beta \cdot p_t^{(1)}\), use raw and skip.
     c. Else init \(L_{\text{cand}} \gets L_{\text{ranked}}\).
     d. While \(|L_{\text{cand}}| > 0\): steer \(L_{\text{cand}}\) → \(\tilde{p}_t\); if \(\tilde{p}_t(\text{top}) \geq \beta \cdot p_t(\text{raw top-1})\), accept; else \(L_{\text{cand}} \gets \text{top-half}\).
     e. Accept first passing \(\tilde{p}_t\) or fallback to \(p_t\).
     f. Decode token; update KV cache.
- **Design tradeoffs:**
  - *Latency vs. robustness:* The dynamic loop adds overhead but prevents overcorrection; gating mitigates by skipping many steps.
  - *One-time ranking vs. per-step adaptation:* Sensitivity analysis is static but effective; avoids costly per-step recomputation.
  - *Key vs. value scaling:* Key scaling chosen for efficiency and better results, but loses some control granularity versus value scaling.
- **Failure signatures:**
  - *Plausibility gate rejects all:* May indicate instruction span misidentification or overly strict β.
  - *Ranking reversed:* Leads to performance drop (Table 3).
  - *No top-2 gating skip:* High raw certainty still incurs loop cost (Figure 13); could optimize further.
- **First 3 experiments:**
  1. *Gating effectiveness:* Compare token change rate & throughput with/without top-2 skip to confirm skip logic reduces trials.
  2. *Sensitivity ranking ablation:* Test random layer ordering and reversed ranking to isolate ranking importance.
  3. *Span robustness:* Apply self-extracted instruction spans on IFEval (Table 16) to test robustness to imperfect span detection.

## Open Questions the Paper Calls Out
- **Question:** Can the attention sensitivity metric be grounded in a formal theoretical framework beyond empirical effectiveness?
  - *Basis:* The paper acknowledges its sensitivity metric is "not based on a formal theoretical framework" and suggests developing "more principled metrics" as a future direction.
  - *Why unresolved:* A theory could improve performance, enable more efficient ranking, and provide guarantees about steering effects versus decomposition assumptions.
  - *Evidence to resolve:* Derive and validate a theory (e.g., using influence functions or mechanistic interpretability) that predicts layer influence on output distribution shifts, then compare its ranking against the current empirical metric on multiple benchmarks.
- **Question:** How effective are advanced instruction span detection methods compared to the simple LLM self-extraction used for interleaved prompts?
  - *Basis:* The paper notes real-world instructions are "often embedded within tasks" but only tested with a "simple automatic span detection method" and suggests "more sophisticated method such as (Zhang et al., 2024) could be beneficial."
  - *Why unresolved:* Poor span detection could misapply steering, harming performance. A robust detector is needed for deployment on natural user queries where tasks and constraints are mixed.
  - *Evidence to resolve:* Integrate state-of-the-art span detectors into DIRECTER's pipeline, evaluate on a benchmark of naturally interleaved prompts, and measure accuracy and robustness versus the simple method.
- **Question:** Is the fixed plausibility threshold β=0.5 universally optimal across model architectures, scales, and task domains, or does it require task-specific tuning?
  - *Basis:* The paper sets β=0.5 "across all tasks without any task-specific tuning" and reports robustness across some scales, but shows variance. The hyperparameter is described as "fixed" without justification for universality.
  - *Why unresolved:* Different models may have varying output distribution characteristics; a universal β may over- or under-reject for certain tasks, limiting practical adoption without tuning.
  - *Evidence to resolve:* Systematically sweep β across a wide range of models and diverse task types, analyzing the trade-off between instruction fidelity and text quality to determine if a single β suffices or if adaptive calibration is needed.
- **Question:** Does the focus on key scaling (versus value scaling or combined scaling) limit the potential of DIRECTER's dynamic control for other model architectures or activation spaces?
  - *Basis:* The paper empirically favors key scaling due to efficiency and observed performance but does not explore whether value scaling could be equally effective with proper gating. Also, the method is tied to Transformer attention mechanics; it may not apply to non-transformer models or alternative activation spaces.
  - *Why unresolved:* Key scaling might be suboptimal for architectures with different attention implementations or for interventions targeting other model components. Understanding the boundary conditions of KV cache steering versus other activation spaces is crucial for generalization.
  - *Evidence to resolve:* Conduct experiments comparing key vs. value vs. combined scaling on diverse architectures (e.g., Mamba, RWKV) and evaluate whether the plausibility-guided loop remains effective. Also, test DIRECTER's principle on non-attention activations (e.g., MLP output steering) to prove its mechanism is broadly applicable beyond KV cache.

## Limitations
- **Span extraction dependency:** Performance hinges on accurate instruction span indices; automatic extraction using GPT-4o-mini may vary across runs, and real-world interleaved prompts are not fully addressed.
- **Baseline configuration ambiguity:** Exact exemplars for PASTA/SpotLight profiling and other baseline details are not published, risking configuration mismatches in replication.
- **Evaluation stringency:** Exact formatting instructions for GSM8K-Format and LIFBench subsampling parameters are unspecified, which could affect reproducibility of reported numbers.

## Confidence
- **High:** Sensitivity-guided layer ranking is validated by ablation (reversed ranking degrades performance).
- **Medium:** Plausibility-guided adaptation depends on the fixed β=0.5 and the top-2 skip assumption; effectiveness across diverse model distributions is not fully explored.
- **Medium:** KV cache key scaling as steering primitive is empirically supported but memory bandwidth costs of repeated scaled copies in the loop are not quantified.
