# From Pixels to BFS: High Maze Accuracy Does Not Imply Visual Planning

## Quick Facts
- arXiv ID: 2603.26839
- Source URL: https://arxiv.org/abs/2603.26839
- Reference count: 8
- Primary result: High maze accuracy in multimodal models stems from costly brute-force token search (simulating BFS) rather than genuine spatial planning, with vision-to-grid extraction as the key bottleneck.

## Executive Summary
This paper examines whether multimodal large language models (MLLMs) solve visual mazes through genuine spatial reasoning or by brute-force enumeration in token space. Using the new MazeBench benchmark of 110 procedurally generated mazes, the authors evaluate 16 model configurations. They find that high-accuracy models (e.g., GPT-5.4 at 91%) first convert images to text grids and then exhaustively enumerate paths, effectively performing breadth-first search (BFS) via natural language tokens. Without reasoning budgets, all models score only 2–12%. Ablations reveal that Claude Sonnet’s accuracy jumps from 6% to 80% when given the correct grid, isolating failed visual extraction as the primary bottleneck. On larger, harder mazes, even top models fail due to token limits. The study concludes that high maze accuracy does not indicate human-like spatial planning but rather resource-intensive brute-force search.

## Method Summary
The authors introduce MazeBench, a benchmark of 110 pixel-art maze images varying in size (5×5 to 20×20), wall density, and features like traps. Sixteen model configurations from OpenAI, Anthropic, Google, and Alibaba are evaluated via API calls with a fixed JSON-output prompt that forbids external tools. The key independent variable is the reasoning budget (e.g., OpenAI’s `reasoning_effort`, Anthropic’s `thinking`), which controls the number of internal tokens allocated for step-by-step reasoning. Models are queried without training; outputs are parsed for correctness (reachability, shortest path length, exact path match). To diagnose strategies, the authors analyze model traces qualitatively and conduct an ablation where some models receive correct text grids instead of images. Token counts (thinking + output) are aggregated per provider’s API reporting.

## Key Results
- High-accuracy models (e.g., GPT-5.4 at 91%) consume 1,710–22,818 tokens per solve by translating images to text grids and exhaustively enumerating paths—a brute-force BFS simulation.
- Without added reasoning budgets, all configurations achieve only 2–12% solve rates; increasing budgets improves performance (GPT-5.4: 12% → 85% → 91%).
- A text-grid ablation shows Claude Sonnet’s accuracy jumps from 6% to 80% when provided the correct grid, isolating visual extraction as the bottleneck.
- On 20×20 ultra-hard mazes, even top models with medium reasoning budgets fail entirely, indicating token exhaustion limits exhaustive search.

## Why This Works (Mechanism)
### Mechanism 1: Vision-to-Grid Translation Bottleneck
- **Claim:** The fidelity of the image-to-text-grid translation determines downstream search success; low visual extraction accuracy causes incorrect brute-force enumeration on a hallucinated grid.
- **Mechanism:** The vision encoder converts pixel data into a discrete token-based grid representation (rows/columns with symbols). If this translation misidentifies walls, open paths, or grid dimensions, all subsequent path enumeration operates on a corrupted state space.
- **Core assumption:** Grid extraction must be accurate for token-level BFS to yield a valid path; the reasoning strategy itself is invariant across models.
- **Evidence anchors:** Claude Sonnet’s accuracy jumps from 6% to 80% when given the correct grid (abstract, Section 6); Claude models misidentify grid dimensions (e.g., 10×10 vs. 8×8) leading to hallucinated grids (Section 6).
- **Break condition:** Providing a ground-truth text grid bypasses the vision encoder, eliminating the bottleneck (Section 6 text-grid ablation).

### Mechanism 2: Serial Token Enumeration (BFS Simulation)
- **Claim:** Models solve mazes via serial token enumeration (simulating BFS) rather than spatial planning; token consumption scales with path length.
- **Mechanism:** After grid extraction, the model iteratively proposes path steps in natural language, backtracks on wall collisions, and compares path lengths—executing a breadth-first search through prose tokens.
- **Core assumption:** No internal spatial map or heuristic exists; the only available computation is sequential token generation constrained by the context window.
- **Evidence anchors:** Models typically translate images into text grids and then exhaustively enumerate paths (abstract); all models follow the same two-stage strategy: image-to-grid translation then serial path enumeration (Section 6).
- **Break condition:** Hitting the maximum output token limit terminates enumeration, causing failure on longer paths (Section 5.6 ultra-hard results).

### Mechanism 3: Reasoning Budget Scaling
- **Claim:** Solve rate scales monotonically with reasoning token budget because additional tokens permit longer brute-force search chains.
- **Mechanism:** API-controlled reasoning effort parameters allocate more internal tokens, allowing the model to explore more path branches before truncation.
- **Core assumption:** The underlying strategy is exhaustive search; more tokens directly correlate with more path trials.
- **Evidence anchors:** Without added reasoning budgets, all configurations score only 2–12% (abstract); GPT-5.4 improves from 12% to 85% to 91% as reasoning effort increases (Section 5.2); token per solve varies by 9× across providers (Section 5.5).
- **Break condition:** Diminishing returns and absolute failure on ultra-hard mazes despite medium budgets indicate path length exceeds even expanded token budgets (Section 5.6).

## Architecture Onboarding
**Component map:**  
Base64 image -> Vision encoder -> Text grid (implicit) -> Reasoning engine (token enumeration) -> JSON output; Control layer: API parameters (reasoning_effort, thinking) bound token generation.

**Critical path:** Image must be translated into an accurate text grid; if corrupted, downstream brute-force search fails regardless of token budget.

**Design tradeoffs:**  
- Accuracy vs. token cost: Higher reasoning budgets improve solves but with superlinear token growth.  
- Speed vs. correctness: Low-latency configurations (no thinking) sacrifice nearly all maze-solving ability.  
- Prompt compliance vs. capability: Models ignore instructions to avoid grid enumeration, indicating hardwired strategy.

**Failure signatures:**  
- Hallucinated grid: Wrong dimensions or wall placements visible in reasoning traces.  
- Token limit exhaustion: Model terminates with partial output or false "unreachable" on long paths.  
- High verbosity with low solve rate: E.g., Claude spending ~22k tokens per solve but solving only 4%.

**First 3 experiments:**  
1. Replicate text-grid ablation: Feed Sonnet 4.6 the correct grid (as text) instead of the image; expect solve rate to jump from ~6% to ~80%.  
2. Reasoning effort sweep: Run GPT-5.4 on identical mazes with `reasoning_effort=none/low/medium`; record solve rate and total tokens; expect 12% → 85% → 91% with token increase.  
3. Strategy compliance probe: Use the "visual-intuition" prompt that forbids grid construction; inspect output traces for hidden grid enumeration; expect violation and reversion to brute-force.

## Open Questions the Paper Calls Out
- **Open Question 1:** Do open-source MLLMs and humans solve mazes efficiently, or also use brute-force token search?  
  Basis: Limitations state the study only covers proprietary models; human and open-model performance unknown.  
  Resolution: Evaluate open-source MLLMs and human solvers on MazeBench; compare solve rates, token counts, reasoning traces.

- **Open Question 2:** Can models be prompted or fine-tuned to perform genuine spatial planning without constructing a textual grid?  
  Basis: Models revert to enumeration even when explicitly prohibited.  
  Resolution: Train on spatially-reasoning tasks that disallow grid output; test if models solve without enumeration; analyze traces.

- **Open Question 3:** What vision encoder failures cause inaccurate grid extraction in Claude models?  
  Basis: Text-grid ablation lifts accuracy from 6% to 80%, pinpointing vision bottleneck, but lacks diagnostic of extraction errors.  
  Resolution: Error analysis of grid transcriptions; experiment with alternative encoders; correlate extraction accuracy with solve success.

- **Open Question 4:** How should we quantify reasoning strategy to distinguish brute-force from efficient spatial planning?  
  Basis: Conclusion notes need to track "strategy, efficiency, failure mode" beyond correctness; token count is coarse.  
  Resolution: Define trace-based metrics (e.g., backtracking frequency, heuristic use); validate against human reasoning; correlate with maze complexity.

## Limitations
- Exact API parameters (reasoning_effort, adaptive thinking) and token counting scopes are incompletely documented, hindering faithful reproduction.
- Model versions may have drifted since the March 2026 experiments, potentially altering performance.
- Trace analyses infer strategy from surface patterns, which cannot fully exclude alternative heuristics that mimic BFS without true enumeration.

## Confidence
- **Brute-force BFS execution** (serial token enumeration simulating breadth-first search): Medium. Consistent token scales and strategy probes support it, but internal mechanisms remain opaque.
- **Vision-to-grid extraction bottleneck**: High. The ablation jump from ~6% to ~80% solve rate when providing the correct grid strongly isolates visual perception as the limiting factor.
- **Token budget scaling**: Medium‑High. Solve rates improve with larger reasoning budgets (e.g., GPT‑5.4: 12% → 85% → 91%), yet diminishing returns and token variability suggest additional constraints.
- **Ultra‑hard failure due to token limits**: High. All models fail on 20×20 mazes despite medium reasoning budgets, aligning with BFS exhaustion beyond context capacity.
