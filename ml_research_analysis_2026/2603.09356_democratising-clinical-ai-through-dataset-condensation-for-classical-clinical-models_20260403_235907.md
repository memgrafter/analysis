# Democratising Clinical AI through Dataset Condensation for Classical Clinical Models

## Quick Facts
- **arXiv ID**: 2603.09356
- **Source URL**: https://arxiv.org/abs/2603.09356
- **Reference count**: 40
- **Primary result**: Condensed datasets with as few as 100 samples per class achieve performance within 0.7% AUROC (or 0.003 C-index) of models trained on full data, with ε ≈ 1.8–3.8 differential privacy.

## Executive Summary
This paper extends dataset condensation to non-differentiable classical clinical models (e.g., decision trees, Cox regression) via a differentially private, zero‑order optimisation framework. The method optimises a tiny synthetic dataset by querying a pretrained reference model, making it suitable for privacy‑preserving data sharing. Across six clinical datasets, synthetic data with 100 instances per class matched full‑data model performance within 0.7% AUROC (classification) and 0.003 C-index (survival), while providing formal (ε, δ)‑DP guarantees. The condensed data also generalised to external cohorts and other model types, with feature attribution (SHAP, hazard ratios) closely aligned with real‑data models.

## Method Summary
The framework first trains a reference model (e.g., XGBoost) on the full real dataset. It then optimises a synthetic dataset (X_syn, y_syn) to minimise a composite loss that combines label‑consistent prediction (binary cross‑entropy or survival loss) and a distribution‑matching term that aligns the reference model’s average predictions on synthetic and real data within each class or risk stratum. Because the reference model is non‑differentiable, gradients with respect to X_syn are estimated by symmetric finite differences: the model is queried on perturbed copies of X_syn. For differential privacy, these per‑example gradients are clipped to a fixed norm and contaminated with adaptive Gaussian noise; privacy loss is accumulated via Rényi DP with Poisson subsampling. The noised gradients update X_syn using Adam. After optimisation, models trained on the condensed data achieve near‑identical performance to models trained on the full dataset, and the process yields formal DP guarantees.

## Key Results
- Condensed datasets with 100 samples per class achieve within 0.7% AUROC (classification) and 0.003 C-index (survival) of full‑data models.
- Differential privacy guarantees: ε ≈ 1.8–3.8 for δ = 10⁻⁵.
- Synthetic data generalises to external cohorts and other model types; SHAP values and hazard ratios from condensed‑data models closely match those from real‑data models.

## Why This Works (Mechanism)

### Mechanism 1: Zero‑order gradient estimation
**Claim**: Zero‑order gradient estimation enables dataset condensation for non‑differentiable classical clinical models (e.g., decision trees, Cox regression) by approximating gradients using only model function evaluations.  
**Mechanism**: The framework queries a pretrained reference model (e.g., XGBoost) with perturbed synthetic inputs via symmetric finite differences to estimate the gradient of a composite loss with respect to the synthetic data. This gradient then updates the synthetic samples using a first‑order optimizer (Adam), despite the model’s non‑differentiability.  
**Core assumption**: Finite differences provide a sufficiently accurate gradient estimate for optimizing synthetic data in the input space, even for piecewise‑constant models like decision trees.  
**Evidence anchors**:  
- [abstract]: “extends DC to non‑differentiable models using only model function evaluations.”  
- [section 4.2]: Detailed equations for symmetric finite differences (Equation 7) and gradient‑based update (Equation 8).  
- [corpus]: Weak evidence; neighboring papers focus on neural‑network‑based DC or GANs, not zero‑order for classical models.  
**Break condition**: Gradient estimates become too noisy or unstable if perturbation scales are poorly tuned relative to feature magnitudes or model decision boundaries, causing synthetic data optimization to diverge.

### Mechanism 2: Differential privacy via gradient perturbation
**Claim**: Differential privacy is achieved by adding calibrated Gaussian noise to the per‑example gradient estimates during synthetic data optimization, formally bounding the influence of any single real training record.  
**Mechanism**: Each estimated gradient is ℓ₂‑clipped to a norm C, then Gaussian noise with variance adapted to maintain signal‑to‑noise ratio ≥1 is added. Privacy loss is tracked via Rényi Differential Privacy (RDP) with Poisson subsampling, converted to (ε, δ)‑DP.  
**Core assumption**: Clipping and Gaussian noise injection on gradient estimates, combined with RDP accounting for subsampled gradient queries, yields a valid DP guarantee for the condensation process.  
**Evidence anchors**:  
- [abstract]: “providing formal differential privacy guarantees (ε ≈ 1.8–3.8).”  
- [section 4.4]: Describes clipping (Equation 12), adaptive noise (Equation 13), and RDP accounting.  
- [corpus]: Neighbors discuss DP in generative models or FL, but not this specific gradient‑perturbation approach for DC.  
**Break condition**: If clipping norm C is too small, signal is destroyed; if too large, sensitivity increases, requiring more noise and degrading utility. Privacy budget ε may exceed acceptable thresholds if T is too high.

### Mechanism 3: Composite loss for model‑agnostic behaviour
**Claim**: A composite loss combining label‑consistent prediction and class‑conditional output distribution matching preserves the predictive behaviour of the full‑data model in the condensed dataset.  
**Mechanism**: Loss ℓ = ℓ_pred + α·ℓ_match. ℓ_pred encourages synthetic samples to yield correct labels under the reference model. ℓ_match aligns the average model predictions on synthetic vs. real data within each class (for classification) or risk strata (for survival). α is adaptively weighted to balance the two terms.  
**Core assumption**: Aligning model outputs (not feature distributions) on synthetic and real data is sufficient for downstream models to learn similar decision boundaries, even when the downstream model differs from the reference.  
**Evidence anchors**:  
- [abstract]: “condensed datasets … achieved model performance within 0.7% (AUROC) … of models trained on full data.”  
- [section 4.2/4.3]: Equations 2–5 for classification; Equation 11 for survival stratification.  
- [section 2.4]: Cross‑model and cross‑site generalisation results (Tables 4, Figure 3) support this claim.  
**Break condition**: If α is poorly scheduled or the matching loss dominates, synthetic data may overfit to the reference model’s quirks, harming generalisation to other models or external cohorts.

## Foundational Learning
1. **Zero‑order (derivative‑free) optimisation**  
   - *Why needed*: The reference model (e.g., XGBoost, Cox) is non‑differentiable; gradients w.r.t. inputs cannot be computed via backpropagation, so we must estimate them via function queries.  
   - *Quick check*: How does symmetric finite difference approximation estimate the gradient of a black‑box model’s output with respect to its input?

2. **Differential privacy (DP) via gradient perturbation**  
   - *Why needed*: Condensed data must not leak individual patient information; DP provides formal, composable privacy guarantees for the condensation process itself.  
   - *Quick check*: Why does clipping gradients before adding noise help bound the sensitivity of the condensation algorithm?

3. **Dataset condensation (matching‑based trajectory)**  
   - *Why needed*: The goal is to produce a tiny synthetic dataset that induces similar training trajectories (in model parameter space or output space) as the full dataset, not to replicate the full data distribution.  
   - *Quick check*: What is the key difference between dataset condensation and generative modelling (e.g., GANs) in terms of objective?

## Architecture Onboarding

### Component map
The pipeline consists of:  
Pretrained reference model (non‑differentiable, e.g., XGBoost, Cox) → provides function evaluations → Composite loss module → computes ℓ_pred + α·ℓ_match → Zero‑order gradient estimator → approximates ∇_{X_syn}ℓ via finite differences → DP noise injector → clips and adds Gaussian noise to per‑example gradients → Optimizer (Adam) → updates X_syn → Privacy accountant (RDP) → tracks cumulative ε, δ.  

### Critical path
1. Train reference model f_real on real dataset (X_real, y_real).  
2. Initialise synthetic dataset (X_syn, y_syn) (balanced classes or stratified for survival).  
3. For T iterations:  
   a. Sample minibatch of real data for matching loss.  
   b. Compute loss ℓ on (X_syn, y_syn) with f_real.  
   c. Estimate ∇_{X_syn}ℓ via symmetric finite differences (query f_real on perturbed X_syn).  
   d. Clip per‑example gradients; add adaptive Gaussian noise.  
   e. Update X_syn via Adam step.  
   f. Update RDP accountant.  
4. Select best X_syn (lowest validation loss) with final ε, δ.

### Design tradeoffs
- **Privacy vs. utility**: Smaller ε requires more noise, degrading synthetic data quality; IPC also trades off with privacy budget.  
- **Model‑agnosticism vs. performance**: Condensation using one model (e.g., XGBoost) generalises well to similar models (Random Forest) but less so to dissimilar ones (linear models), as seen in proteomics results.  
- **Stability vs. fidelity**: Finite‑difference step size must be large enough to overcome model output noise but small enough for accurate gradient approximation; requires tuning per dataset/model.

### Failure signatures
- Collapsed synthetic data: all X_syn converge to near‑identical points (check t‑SNE or nearest‑neighbor distances).  
- Diverging loss: ℓ increases or oscillates, indicating poor gradient estimates (likely due to too large perturbation or high model stochasticity).  
- Privacy leakage: Membership inference attack AUROC > 0.6 (Figure 5 shows near‑chance here), suggesting synthetic data memorises real points.  
- Poor cross‑model generalisation: Performance drop when downstream model differs from reference (e.g., SVM on proteomics in Figure 3).

### First 3 experiments
1. **Gradient estimation sanity check**: On a small, differentiable proxy model (e.g., logistic regression), compare finite‑difference gradients to analytical gradients. Goal: low relative error (<5%) across input range.  
2. **DP utility Pareto sweep**: Vary IPC (50, 100, 500, 1000) and clipping norm C; record AUROC/C‑index vs. ε. Goal: identify operating points where utility loss <1% relative to full data at ε < 3.  
3. **Cross‑model generalisation**: Condense using XGBoost; train Logistic Regression, SVM, and Random Forest on synthetic data. Evaluate AUROC relative to models trained on full data. Goal: quantify drop for linear vs. tree‑based models.

## Open Questions the Paper Calls Out
1. **How can dataset condensation be made more model‑agnostic?**  
   *Basis*: Explicit statement in paper: “performance was strongest when the downstream models shared inductive biases with the pre‑trained model used during condensation, suggesting an opportunity to improve model‑agnosticity.”  
   *Why unresolved*: Current method shows dependency on model family—e.g., tree‑based models work well but linear models struggle with high‑dimensional proteomics data.  
   *What evidence would resolve*: Systematic evaluation across diverse model families (linear, kernel‑based, tree‑based, neural networks) on multiple datasets, with metrics comparing performance gaps; develop regularization techniques or multi‑model condensation objectives that encourage broader compatibility.

2. **How does the choice of reference model affect the quality and generalizability of condensed datasets?**  
   *Basis*: Inferred; authors consistently use XGBoost as reference without investigating alternatives.  
   *Why unresolved*: Reference model guides condensation via its predictions; different models may capture different data aspects, possibly biasing synthetic data. Without understanding sensitivity, practitioners cannot make informed choices.  
   *What evidence would resolve*: Comparative studies using various reference models (different tree configurations, linear models, neural networks) on the same dataset, evaluating downstream performance across multiple model types; analyse synthetic sample characteristics and feature attribution alignment relative to reference model family.

3. **Can the proposed DP dataset condensation framework be extended to deep neural networks?**  
   *Basis*: Explicit note: “while the proposed framework is model‑agnostic and readily compatible with neural networks, we focused exclusively on classical models … Extending the method to deep models is technically straightforward and represents a natural next step.”  
   *Why unresolved*: Deep models are increasingly used in clinical AI (e.g., imaging, time‑series). Extension may face challenges due to high dimensionality, non‑convexity, and different optimisation landscapes.  
   *What evidence would resolve*: Implementation and evaluation of the zero‑order DP optimisation for neural network architectures on clinical datasets, comparing performance and privacy‑utility trade‑offs against full‑data training and alternative privacy‑preserving methods.

4. **How robust are the privacy guarantees of condensed datasets against more advanced inference attacks?**  
   *Basis*: Authors acknowledge: “although our empirical evaluations used strong white‑box attacks and revealed minimal leakage, future work should assess robustness to more adversarial conditions such as adaptive attacks, repeated querying, and integration with auxiliary information.”  
   *Why unresolved*: Current evaluation uses a specific distance‑based attack. Adaptive attackers might exploit the condensation process’s optimisation trajectory or query repeatedly; real‑world adversaries may have auxiliary data.  
   *What evidence would resolve*: Design and test adaptive membership/attribute inference attacks that exploit knowledge of the condensation algorithm, simulate repeated release scenarios, and evaluate attacks with realistic auxiliary information; formal privacy analysis under broader threat models.

5. **Can the condensation process be made more sample‑efficient by learning optimal synthetic dataset sizes adaptively?**  
   *Basis*: Inferred; paper evaluates fixed IPC values (50, 100, 500, 1000) but does not investigate variable sizing.  
   *Why unresolved*: Fixed IPC may be suboptimal—some datasets/tasks might require more synthetic samples for minority classes or complex boundaries, while others need fewer; adaptive sizing could improve storage efficiency and privacy.  
   *What evidence would resolve*: Develop algorithms that terminate condensation when validation performance plateaus or allocate synthetic samples per class based on learning difficulty metrics; empirical studies showing adaptive sizing achieves better utility‑privacy‑storage trade‑offs than fixed IPC.

## Limitations
- **Hyperparameter gaps**: Critical DP parameters (gradient clipping norm C, base noise σ_base) and early‑stopping criteria are unspecified, blocking faithful replication.
- **Generalisation boundaries**: Condensation overfits to reference model inductive biases; performance drops notably for linear models vs. tree‑based downstream models (e.g., SVM on proteomics).
- **Scalability unexplored**: Experiments limited to ≤6 datasets with moderate feature dimensions (≤181); applicability to high‑dimensional EHR or imaging data is unknown.

## Confidence
- **Zero‑order DC for non‑differentiable models**: Medium  
- **Differential privacy guarantees**: Medium  
- **Cross‑model/cross‑site generalisation**: Medium‑Low  

## Next Checks
1. **Gradient estimation validation**: On a small, differentiable proxy dataset (e.g., logistic regression), compute analytical gradients and compare to symmetric finite‑difference estimates across input regions. Target: relative error <5% in 90% of samples; if error >20%, condensation may optimise noise.
2. **DP–utility Pareto sweep**: Systematically vary IPC (50–500) and clipping norm C (log‑scale) on 1–2 datasets. Re‑measure AUROC/C‑index vs. final ε. Verify whether reported operating points (e.g., IPC=100, ε≈2.5) lie on the true Pareto frontier; identify if better utility is possible at same ε.
3. **Failure‑mode stress test**: Intentionally mis‑set finite‑difference step size (e.g., 10× too large/small) and α‑schedule (overweight matching loss). Monitor synthetic data collapse (via t‑SNE) and downstream model degradation (especially linear models). Quantify tolerance margins for stable condensation.
