# CODE-SHARP: Continuous Open-ended Discovery and Evolution of Skills as Hierarchical Reward Programs

## Quick Facts
- **arXiv ID**: 2602.10085
- **Source URL**: https://arxiv.org/abs/2602.10085
- **Reference count**: 40
- **Primary result**: CODE-SHARP discovers approximately 90 diverse skills and composes them to solve complex long-horizon benchmark tasks, outperforming pretrained agents and task-specific experts by more than 134% on average; mutation refinement increases the success rate of elite skills by 68.80 percentage points.

## Executive Summary
CODE-SHARP introduces a framework for open-ended skill discovery in reinforcement learning without manual reward engineering. It employs foundation models to generate, implement, and evaluate hierarchical reward programs called SHARPs, which are executable Python codes specifying success conditions and prerequisite skills. These skills form a directed acyclic graph archive that serves as a learnable curriculum. A goal-conditioned agent trained on SHARP-generated rewards masters a wide range of abilities, from basic foraging to deep navigation. When a high-level FM planner composes these skills into policies-in-code, the agent solves complex, long-horizon tasks in the Craftax environment, achieving >134% average improvement over strong baselines. Additionally, a mutation-based refinement loop boosts the success rate of elite skills by 68.80 percentage points. These results demonstrate that foundation models can autonomously design reward functions and hierarchical skill structures, enabling agents to acquire increasingly sophisticated behaviors.

## Method Summary
The method operates through two iterative loops. In skill discovery, a propose-implement-judge pipeline uses foundation models to create SHARP proposals (pseudo-code), translate them into executable JAX-compatible Python, and select two candidates per iteration based on correctness, feasibility (learnability by the current agent), and novelty. A copy of the agent briefly trains on each candidate’s reward; if success exceeds a threshold, the skill is added to a DAG archive. In skill refinement, skills are sampled inversely to their success rate; the FM proposes mutations (reordering conditions, swapping prerequisites, hyperparameter adjustments), which are implemented and zero-shot evaluated with the current agent. Better mutations replace parents. The main agent—a goal-conditioned Transformer-XL trained via PPO—trains on all archive rewards, using prerequisite-aware importance sampling and adaptive scaling. At deployment, a high-level FM planner composes archive skills into executable policies for benchmark tasks, leveraging the hierarchical traversal operator to dynamically select active skills based on environment state.

## Key Results
- An average of ∼90 diverse SHARP skills are discovered, forming a natural curriculum from basic (e.g., FindTree) to advanced (e.g., multi-level mine navigation).
- Composed policies achieve a geometric mean success rate >134% higher than pretrained PPO agents and task-specific experts across four Craftax benchmarks.
- Mutation refinement raises the success rate of elite skills by 68.80 percentage points (absolute), from 24.30% to 41.02%.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Foundation models autonomously generate and evaluate novel, hierarchically-composed reward programs that form a learnable curriculum.
- **Mechanism**: An FM-based propose-implement-judge pipeline creates SHARP skills as executable Python code with success conditions and prerequisite dependencies. The judge filters for correctness, feasibility (learnable by current agent), and novelty relative to existing skills. Accepted skills are added to a directed acyclic graph archive.
- **Core assumption**: FMs can reason about environment code to propose semantically meaningful and executable skill decompositions that a goal-conditioned agent can learn.
- **Evidence anchors**: 
  - [section 2.3] Describes the three-stage pipeline: proposal generator, implementor, and judge that selects two candidates for evaluation.
  - [section 3.1] Shows the archive grows to ~90 diverse skills following a natural curriculum from Overworld to Mines.
- **Break condition**: If FMs consistently generate non-executable code or skills that are never learnable (low success rates), the archive fails to expand meaningfully.

### Mechanism 2
- **Claim**: Hierarchical graph traversal enables dynamic, state-sensitive skill selection without retraining.
- **Mechanism**: Given a high-level target skill, the transition operator T recursively checks environment conditions in order, activating the first unmet condition's prerequisite skill. This allows the active skill to change stochastically as environment state varies, without policy modification.
- **Core assumption**: A fixed goal-conditioned policy can master complex temporally-extended tasks when conditioned on the dynamically-selected terminal skill from the hierarchy.
- **Evidence anchors**: 
  - [section 2.2] Equation 2 formally defines the transition operator T that maps target to prerequisite skills based on condition satisfaction.
  - [section 2.5] Describes how at each environment step, T is applied to determine the active skill for the policy and reward.
- **Break condition**: If prerequisite chains become too deep or conditions brittle, the traversal may cycle or stall, preventing progress on long-horizon tasks.

### Mechanism 3
- **Claim**: Mutation-driven refinement improves existing SHARP skills by reordering conditions and substituting more suitable prerequisites, directly boosting agent success rates.
- **Mechanism**: Skills are sampled inversely to their success rate. FMs propose mutations (e.g., "Efficiency", "Simplicity", "Crossover" heuristics). Mutations are evaluated zero-shot using the current policy; if success rate improves, the elite version replaces the base skill.
- **Core assumption**: SHARP skills can be locally optimized via structural modifications (condition ordering, prerequisite swaps) without requiring full policy retraining for evaluation.
- **Evidence anchors**:
  - [section 2.4] Describes mutation proposal generation, zero-shot filtering, and replacement if ρ_mut > ρ_k.
  - [section 3.4] Reports a 68.80 percentage point absolute increase in success rate (24.30% → 41.02%) from elite mutations.
- **Break condition**: If mutation space is exhausted or changes degrade performance, refinement halts; also, if evaluation noise exceeds improvement signal, false positives may replace functional skills.

## Foundational Learning

- **Goal-Conditioned Reinforcement Learning**
  - *Why needed*: The framework trains a single universal policy to execute any discovered skill, enabling composition without retraining for new tasks.
  - *Quick check*: Can the policy generalize to novel skill combinations it has never seen sequentially during training?

- **Hierarchical Reinforcement Learning (Options Framework)**
  - *Why needed*: SHARP skills are temporal abstractions with initiation sets and internal policies, building on the options framework.
  - *Quick check*: Does the hierarchical decomposition actually reduce effective horizon compared to flat reward shaping?

- **Programmatically Defined Rewards**
  - *Why needed*: Rewards are executable Python code accessing environment state, allowing complex logical conditions impossible to hand-design.
  - *Quick check*: Are the generated reward programs semantically aligned with their natural language descriptions, or do they exploit implementation quirks?

- **Quality Diversity and Open-Endedness**
  - *Why needed*: The judge's novelty criterion and mutation loop push the archive toward unexplored regions of the skill space without external task definitions.
  - *Quick check*: Does the archive truly explore diverse skill types, or does it converge on a few high-performing templates?

## Architecture Onboarding
- **Component map**: FM pipeline: Proposal Generator → Implementor → Judge → [Environment Evaluation]; Mutation loop: Sample Skill → Mutation Generator → Implementor → Zero-shot Eval → Archive update; Agent: Goal-conditioned PPO with TransformerXL; Graph: Archive Λ = (V, E) where V are SHARP classes; edges implicit in prerequisite lists.
- **Critical path**:
  1. Initialize archive with elementary skills (FindTree, FindLake, FindCow).
  2. Loop: Generate n proposals, implement, judge selects two → evaluate learnability → add if τ_learn exceeded.
  3. With probability P(k) ∝ (1-ρ_k), sample skill for mutation → generate m mutations → zero-shot eval → replace if better.
  4. Train agent for fixed steps on current archive with importance sampling and adaptive rewards.
- **Design tradeoffs**:
  - Executable code vs. natural language reward: code enables precise conditions but requires environment code access.
  - Graph traversal depth vs. policy capacity: deeper hierarchies risk semantic dilution; agent must learn long chains.
  - Proposal batch size vs. cost: more proposals increase discovery chance but multiply FM calls.
  - Mutation frequency vs. stability: frequent mutations may disrupt learning; sampling by (1-ρ) focuses on weak skills.
- **Failure signatures**:
  - Judge accepts non-executable code → training crashes or silent failures.
  - Prerequisite cycles in graph → infinite recursion in transition operator T.
  - Reward sparsity: many skills have low success rates → agent receives little learning signal.
  - Over-specialization: archive fills with parametric variants rather than novel types.
- **First 3 experiments**:
  1. **Skill discovery rate**: Track number of accepted skills per iteration; should grow sublinearly, not saturate quickly.
  2. **Archive complexity**: Compute C(σ) = 1 + Σ C(prerequisites); should increase gradually, showing hierarchical composition.
  3. **Zero-shot policy composition**: Use FM policy planner to generate BenchmarkSolver from current archive; track geometric mean of milestone success rates across iterations to see if performance improves with archive growth.

## Open Questions the Paper Calls Out
- **Open Question 1**: *How can CODE-SHARP be applied to environments without source code (e.g., real robotics)?*  
  Basis: The authors identify environment code requirement as a major limitation and propose extending to non-code environments via learned reward models or natural-language feedback. Unresolved because current pipeline parses environment code directly. Resolution would require a version that replaces code inspection with a learned reward model or language feedback, successfully discovering skills in a black-box simulator.
- **Open Question 2**: *What is the long-term trajectory of the open-ended discovery process? Does it eventually saturate or keep generating useful skills?*  
  Basis: The authors halted after 100 iterations due to compute limits, not convergence, and hypothesize continued improvement from non-saturating performance curves. Unresolved because performance beyond 100 iterations unknown. Resolution would be running CODE-SHARP for many additional iterations (e.g., 500) and measuring skill archive growth and performance trends.
- **Open Question 3**: *How dependent is CODE-SHARP on using a large foundation model? Could smaller or different models be effective?*  
  Basis: The method exclusively uses Qwen3-235B-A22B-Thinking; no ablation on model size or family. Unresolved because practicality and generalizability are unclear. Resolution would be systematic experiments varying model size (7B, 70B) and provider (GPT-4, Claude) to assess impact on skill quality and downstream task success.

## Limitations
- Prompt specifications are incomplete (missing system messages, temperature, exact formatting), preventing exact replication of the FM pipeline.
- The learnability evaluation protocol is unclear: the τ_learn threshold, number of training episodes per candidate, and details of the agent copy are not specified.
- Initial SHARP skill implementations for the seed skills (FindTree, FindLake, FindCow) are not provided; only pseudo-code descriptions are given, and necessary environment helper functions are undefined.

## Confidence
- **Skill Discovery (~90 skills)**: Medium confidence (archive growth documented but missing parameters raise sensitivity concerns).
- **Hierarchical Composition (>134% benchmark improvement)**: Low-Medium confidence (no ablation on hierarchy depth; unlimited depth safety untested).
- **Mutation Refinement (+68.80 pp success)**: High confidence (well-defined procedure, large effect size; mutation space not fully characterized but effect robust).

## Next Checks
1. **Prompt reconstruction test**: Using appendix snippets, build full prompts (system messages, temperature). Run 10 trials to generate initial SHARP skills; record success rate (syntactically correct, JIT-compatible). Expect >80% within 5 attempts.
2. **Learnability threshold sensitivity**: Vary τ_learn across plausible range (0.1, 0.3, 0.5) and candidate training steps (100 vs. 500). Compare resulting archive size, depth, and downstream benchmark performance. Large variations indicate fragility.
3. **Depth stress test**: Impose maximum prerequisite chain length (1, 2, 3, unlimited). Train agent on same set of skills (e.g., top 50) and evaluate all benchmarks. If performance drops significantly with depth, the hierarchical composition claim is weakened.
