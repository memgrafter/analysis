# An Efficient Unsupervised Federated Learning Approach for Anomaly Detection in Heterogeneous IoT Networks

## Quick Facts
- **arXiv ID**: 2602.24209
- **Source URL**: https://arxiv.org/abs/2602.24209
- **Reference count**: 33
- **Primary result**: F1-score improved by ~15% (0.795 to 0.957) on CICIoT-DIAD 2024; CICIoT2022 saw gain (0.116 to 0.306); matched baseline on CICIoT2023; stable convergence over 21 rounds; SHAP confirmed shared features dominance.

## Executive Summary
IoT anomaly detection must handle data privacy and feature heterogeneity across devices. This paper introduces an unsupervised federated learning framework using autoencoders that aggregates only common hidden layers while keeping client-specific input/output layers local. After server-side averaging, clients fine-tune their full models on validation data to align weights. Evaluated on three CIC IoT datasets, the method improves F1-score by about 15% on CICIoT-DIAD 2024 (0.795→0.957) and significantly on CICIoT2022 (0.116→0.306), while matching the centralized baseline on CICIoT2023. The model converges stably over 21 rounds, and SHAP analysis verifies that the most influential features belong to the manually identified shared subset, providing both performance and interpretability.

## Method Summary
The approach trains autoencoders in a federated manner without requiring labels. Each client holds a dataset with a distinct feature set and constructs a symmetric autoencoder; the input and output layer dimensions match the local feature count, while all hidden layers have identical dimensions across clients. Clients train locally for two epochs using MSE reconstruction loss. Only the weights of these common hidden layers are sent to the server, which aggregates them via weighted averaging (by client test size). Clients then rebuild their full model by combining their unique input/output layers with the averaged common layers. To resolve mismatched interfaces, each client fine-tunes the entire model for two epochs on its local validation set. For inference, the encoder maps test samples to latent vectors, which are clustered with K-means. Cluster labels are aligned to true classes (binary inversion for two-class, frequency mapping for multi-class) to compute metrics. This pipeline runs for 21 communication rounds, with per-client best models selected based on validation performance. Finally, SHAP analysis is applied to the final client models to provide feature-level explanations, confirming the dominance of the shared feature subset.

## Key Results
- Achieved ~15% F1 improvement on CICIoT-DIAD2024 (0.795→0.957) and large gain on CICIoT2022 (0.116→0.306); matched baseline on CICIoT2023; convergence stable over 21 rounds.
- SHAP analysis confirmed that the most influential features for anomaly detection belong to the shared feature subset across datasets.

## Why This Works (Mechanism)
### Mechanism 1: Selective Common-Layer Aggregation
**Claim:** Selective aggregation of only common-dimension autoencoder layers enables effective federated learning across clients with differing input features.  
**Mechanism:** Clients train identical autoencoder architectures except for input/output layer dimensions (set by local feature count). Only weights from fully connected hidden layers with matching dimensions are transmitted to the server for averaging. Client-specific first/last layer weights remain local. After aggregation, clients reintegrate the averaged common weights with their unique layers and perform brief validation-based fine-tuning to resolve weight misalignment.  
**Core assumption:** The intermediate latent representations learned by common layers capture transferable, dataset-agnostic patterns sufficient for global model utility, while client-specific layers preserve local data structure.  
**Evidence anchors:** Abstract mentions aggregation of only common layers; Section IV.B.1 describes sending only weights of common dimensions; paper notes fine-tuning with validation data.  
**Break condition:** If the proportion of shared common layers becomes too small, the global model may fail to learn a coherent shared representation, leading to performance collapse or instability.

### Mechanism 2: Dynamic Weight Alignment via Lightweight Fine-Tuning
**Claim:** Validation-based fine-tuning reconciles mismatched layer interfaces after aggregation, enabling functional reconstruction across heterogeneous clients.  
**Mechanism:** After receiving averaged common-layer weights, each client inserts them between its locally unique input and output layers. Because the weight matrices now have incompatible shapes, the full autoencoder is briefly retrained on the client's local validation set to adjust the surrounding unique-layer weights to interpret the new shared weights correctly.  
**Core assumption:** A small amount of local validation data is sufficient to adapt client-specific layers without overwriting the collaborative knowledge.  
**Evidence anchors:** Section IV.B.1: "Repair the model weights by training with validation data"; Algorithm 1 lines 11-12.  
**Break condition:** If the distribution shift between the client's validation data and its training data is large, or if the validation set is too small, the fine-tuning may either fail to align weights properly or catastrophically forget the aggregated shared knowledge.

### Mechanism 3: SHAP-Based Validation of Shared Feature Dominance
**Claim:** SHAP-based explainability confirms that the global model's anomaly detection decisions are driven primarily by the shared feature subset, validating the efficacy of cross-dataset knowledge transfer.  
**Mechanism:** After training, SHAP values are computed on local client models (e.g., at Round 12). The distribution of feature contributions is analyzed to determine whether the most influential features correspond to the manually identified shared feature space across datasets.  
**Core assumption:** Features with high absolute SHAP values are causally relevant; if shared features dominate, it indicates successful leveraging of the common feature subspace.  
**Evidence anchors:** Abstract mentions SHAP-based interpretability; Section V.E discusses feature importance; Figures 13-15 show SHAP summary plots.  
**Break condition:** If SHAP analysis shows feature importance is scattered or dominated by client-unique features, the global model failed to integrate shared knowledge meaningfully.

## Foundational Learning
- **Unsupervised Federated Learning**: Needed because IoT anomaly detection often lacks labels and requires privacy-preserving collaborative training. *Quick check:* How can you aggregate model updates in FL when no loss labels exist to weight client contributions?  
- **Feature Heterogeneity Handling**: Needed because IoT clients have different feature vectors, violating standard FL homogeneity assumptions. *Quick check:* If Client A has 46 features and Client B has 48, what architectural modifications allow them to contribute to the same global model?  
- **Latent Space Clustering for Anomaly Detection**: Needed because autoencoders learn compressed representations; anomalies are better detected by clustering latent vectors than using raw reconstruction error alone. *Quick check:* Why apply K-means to the bottleneck layer output rather than the raw input or reconstruction error?

## Architecture Onboarding
**Component map:** Local data → asymmetric autoencoder (unique input/output + common hidden layers) → extract common layer weights → server (weighted averaging) → broadcast common weights → client reassembles full model (unique + averaged common) → validation fine-tuning → encoder → latent vectors → K-means clustering → label alignment → metrics → SHAP.

**Critical path:**
1. Preprocess local data (normalize, balance).
2. Train local autoencoder for 2 epochs (MSE loss).
3. Extract weights of common layers → send to server.
4. Server aggregates common weights (weighted by client test size) → broadcast to clients.
5. Clients rebuild model: unique layers + averaged common layers.
6. Fine-tune entire model on validation set (2 epochs) to align weights.
7. Encode test data via encoder → cluster latent vectors with K-means.
8. Align cluster labels to true labels → compute metrics.
9. Repeat for 21 rounds; save best-round model per client.

**Design tradeoffs:**
- **Shared vs. unique features:** Aggregating only common layers protects local structure but discards unique feature interactions from collaboration.
- **Communication efficiency:** Sending only common layers reduces payload, but requires local reconstruction/fine-tuning overhead.
- **Clustering simplicity vs. temporal dynamics:** K-means is lightweight but ignores sequential patterns in IoT flows.
- **Label alignment heuristics:** Binary inversion is exact; multi-class frequency mapping is approximate and may fail with highly imbalanced clusters.

**Failure signatures:**
- **Convergence failure:** Global metrics do not improve over rounds → likely insufficient common feature overlap or problematic aggregation.
- **Misaligned clusters:** Post-alignment accuracy remains low → K-means failed to recover true classes; consider increasing k or changing initialization.
- **SHAP incoherence:** Shared features show low SHAP magnitude → model may be using noise or client-specific artifacts.
- **Weight mismatch errors:** Shape mismatch during reconstruction → indicates incorrect identification of "common" layers; verify layer dimensions match across all clients.

**First 3 experiments:**
1. **Common layer ablation:** On CICIoT-DIAD2024, train with only the first *k* common layers (e.g., 1, 2, …) and measure F1-score drop to quantify criticality of shared depth.
2. **Aggregation strategy comparison:** Compare the proposed selective aggregation with (a) aggregating all layers after zero-padding unique dimensions, and (b) ignoring heterogeneity and training only on the shared feature subset. Evaluate on CICIoT-DIAD2024.
3. **SHAP stability check:** Compute SHAP for the same client model across rounds 5, 12, and 18; calculate rank correlation of feature importance. Low correlation indicates unstable explanations.

## Open Questions the Paper Calls Out
1. To what extent can heterogeneous and partially overlapping feature spaces be effectively integrated within a federated learning framework to construct an accurate and robust global model for device behavior modeling?
2. How effectively can the learned global federated model detect device-level anomalies, and to what extent can SHAP-based explainability provide meaningful insights into the key features driving these detection decisions?
3. What is the minimum required overlap of common features across heterogeneous IoT clients to maintain acceptable anomaly detection performance in the proposed federated framework?
4. Can incorporating temporal sequence modeling (e.g., via LSTM or Transformer-based autoencoders) improve anomaly detection performance over the current feedforward autoencoder + K-means pipeline, especially for detecting sophisticated, stateful attacks?

## Limitations
- The method relies on exact identification of shared features across datasets, but the paper does not provide the complete list, blocking faithful replication.
- The weight repair procedure after aggregation is underspecified (number of epochs, optimizer, scope), leaving critical implementation gaps.
- The validity of SHAP in unsupervised reconstruction anomaly detection is questionable, as SHAP's assumptions may not hold in this context, weakening the interpretability claim.

## Next Checks
1. **Common layer ablation:** On CICIoT-DIAD2024, train models with only the first *k* common layers (e.g., 1, 2, …) and measure F1-score drop. A monotonic decline would confirm that all shared layers contribute and none are superfluous.
2. **Aggregation strategy comparison:** Replace selective aggregation with (a) zero-padding unique dimensions and aggregating all layers, and (b) training solely on the shared feature subset. Compare F1 to isolate the benefit of layer-wise selection.
3. **SHAP stability check:** Compute SHAP values for a fixed client model across multiple random seeds or K-means initializations; compute rank correlation of feature importance. Low correlation indicates unstable explanations, challenging the claim that shared features consistently dominate.
