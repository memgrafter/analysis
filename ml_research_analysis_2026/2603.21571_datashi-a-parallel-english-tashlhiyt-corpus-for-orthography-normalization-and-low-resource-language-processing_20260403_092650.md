# DATASHI: A Parallel English-Tashlhiyt Corpus for Orthography Normalization and Low-Resource Language Processing
## Quick Facts
- **ArXiv ID**: 2603.21571
- **Source URL**: https://arxiv.org/abs/2603.21571
- **Reference count**: 0
- **Primary result**: Gemini-2.5-Pro attains WER 35.5% and LD 3.65 in few-shot orthography normalization of Tashlhiyt.

## Executive Summary
The DATASHI corpus addresses the scarcity of resources for Tashlhiyt, a low-resource Amazigh language, by providing 5,000 parallel English-Tashlhiyt sentence pairs. A subset of 1,500 sentences includes non-standard user-generated text alongside expert-standardized references, enabling orthographic normalization research.

The authors evaluate five large language models (GPT-5, Claude-Sonnet-4.5, Gemini-2.5-Pro, Mistral Large, Qwen3-Max) using zero-shot and few-shot prompting. Gemini-2.5-Pro attains the lowest error rates (WER 35.5%, LD 3.65) in the few-shot setting. Fine-grained analysis reveals that all models struggle most with gemination and emphatic consonants, though Gemini demonstrates relatively better handling of these features.

## Method Summary
The study benchmarks orthographic normalization of non-standard Tashlhiyt text to a standardized form. The evaluation dataset comprises 1,500 parallel sentences, each with a non-standard input and a gold-standard reference. Performance is measured via Word Error Rate (WER) and Levenshtein Distance (LD), supplemented by error-type breakdowns (deletions, substitutions, insertions) across phonological categories such as gemination and emphatic consonants. The researchers test five large language models under zero-shot and few-shot conditions. The prompt template includes an instruction to normalize, an explicit Berber Latin character inventory, and IRCAM-based orthographic rules. For few-shot runs, a curated set of 30 input-output pairs (excluded from the test set) is provided as demonstrations. All prompts and the full corpus are intended to be publicly released.

## Key Results
- Gemini-2.5-Pro leads in few-shot normalization: WER 35.5%, LD 3.65.
- All models exhibit highest error counts on gemination and emphatic consonants.
- Gemini shows the most robust performance on these marked phonological features, with comparatively lower delete/substitute rates.

## Why This Works (Mechanism)
Large language models can perform orthographic normalization through in-context learning, where the prompt provides explicit rules and examples that guide the model to map non-standard spellings to a standardized orthography. The inclusion of IRCAM-based rules and a defined character set helps constrain the output to the target script. Gemini-2.5-Pro’s superior handling of gemination and emphatic consonants suggests it better captures the phonological constraints of Tashlhiyt, possibly due to more effective representation of these marked features in its training data or architectural inductive biases.

## Foundational Learning
- **Orthographic normalization**: Converts diverse non-standard spellings to a canonical form, essential for consistent NLP processing. *Quick check*: Model output matches gold standard string exactly.
- **In-context learning**: Adapts LLMs to new tasks via examples in the prompt without weight updates. *Quick check*: Compare zero-shot vs few-shot performance improvement.
- **Tashlhiyt phonology**: Gemination (e.g., “tt”) and emphatic consonants (e.g., “t.”) are distinctive features challenging for models. *Quick check*: Measure error rates on sentences containing these features.
- **Low-resource language processing**: Overcomes data scarcity through transfer learning and curated corpora. *Quick check*: Ability to train or adapt models with limited parallel data (e.g., 1,500 pairs).
- **IRCAM orthographic standard**: Official writing conventions for Amazigh languages define character inventory and spelling rules. *Quick check*: Compliance of model output with the specified character set and rules.

## Architecture Onboarding
The reproduction pipeline consists of sequential components: Raw_Input (non-standard Tashlhiyt sentence) -> Prompt_Assembly (instruction, character set, rules, optional demonstrations) -> LLM_Inference (API call to target model) -> Output_Cleanup (strip extraneous text, enforce character set) -> Metric_Computation (WER, LD, error breakdown). The critical path runs from loading the test set through prompt generation, model inference, output cleaning, and metric calculation. Design tradeoffs include zero-shot vs few-shot (simplicity vs accuracy), model choice (performance vs accessibility), and strict output constraints (precision vs recall of valid characters). Failure signatures manifest as: output containing disallowed characters (e.g., “č”), high WER on geminated/emphatic words, inclusion of explanatory text, and incorrect clitic segmentation. The three first experiments are: (1) replicate zero-shot and few-shot results for Gemini-2.5-Pro using the released artifacts; (2) vary the number of few-shot examples (5, 15, 30) to assess sensitivity; (3) compute category-specific error rates for gemination and emphatics to validate reported patterns.

## Open Questions the Paper Calls Out
1. Does fine-tuning multilingual LLMs on the DATASHI normalization subset significantly reduce error rates beyond few-shot prompting for Tashlhiyt orthography normalization?  
2. Are the observed high deletion and substitution errors for gemination and emphatic consonants primarily due to insufficient representation in pre-training data or architectural limitations?  
3. To what extent does orthographic normalization using DATASHI improve downstream NLP tasks (e.g., tokenization, machine translation) for Tashlhiyt?  
4. Can the parallel structure of DATASHI be extended to create a multimodal speech-text corpus, and does normalized text improve forced alignment and pronunciation modeling for Tashlhiyt ASR?

## Limitations
- Unreleased artifacts (exact 30-shot demonstration set and full prompt template) block exact replication.
- Results depend on specific model versions accessible via APIs, which may change over time.
- Token-based metrics (WER, LD) may not fully capture linguistic normalization quality for morphophonological phenomena.

## Confidence
