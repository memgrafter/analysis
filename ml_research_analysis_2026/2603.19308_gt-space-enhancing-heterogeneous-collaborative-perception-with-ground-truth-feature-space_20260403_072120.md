# GT-Space: Enhancing Heterogeneous Collaborative Perception with Ground Truth Feature Space

## Quick Facts
- **arXiv ID:** 2603.19308
- **Source URL:** https://arxiv.org/abs/2603.19308
- **Reference count:** 18
- **Primary result:** GT-Space constructs a common ground-truth BEV feature space, enabling plug-and-play heterogeneous fusion; it achieves state-of-the-art 3D detection (AP@50 up to 0.891, AP@70 up to 0.810 on OPV2V) and shows robustness under agent degradation and communication latency.

## Executive Summary
Heterogeneous collaborative perception in autonomous driving—where agents with different sensors (e.g., LiDAR, camera) or models produce misaligned features—has been inefficient and unscalable due to the need for pairwise retraining or interpreters. GT-Space addresses this by constructing a common feature space directly from ground-truth bounding box labels in bird’s-eye view (BEV), providing a unified reference. Each agent uses a lightweight projector to map its local BEV features into this space; a transformer-based fusion network, trained with combinatorial contrastive losses across all modality pairs, then aggregates the projected features to handle arbitrary agent combinations. On standard datasets (OPV2V, V2XSet) GT-Space consistently outperforms prior methods, achieving AP@50 up to 0.891 and AP@70 up to 0.810 with Agent 1. The approach also generalizes to the real-world RCooper dataset and maintains robust performance when agents underperform or communication latency occurs. By freezing encoders and detection heads during fusion training, GT-Space supports plug-and-play addition of new agents with minimal cost.

## Method Summary
GT-Space introduces a ground-truth (GT) BEV space as a canonical representation for heterogeneous agent features. The pipeline comprises: (1) Pre-trained, frozen encoders for each agent type produce local BEV feature maps. (2) A GT encoder transforms 3D bounding box annotations into object-centric BEV features via fully-connected layers and positional embeddings, trained with an IoU loss to ensure decodability. (3) Each agent is equipped with a lightweight MLP projector that aligns its local BEV features to the GT-BEV space, trained with an L2 similarity loss while keeping the encoder frozen. (4) A fusion transformer aggregates all projected features and is trained with a combinatorial contrastive loss that maximizes similarity between fused features and GT features for the same object across all possible modality pairs, thus learning modality-agnostic representations. The final collaborative detection head produces detections. During training, only projectors and the fusion network are optimized; encoders and detection heads remain fixed. For a new agent at deployment, only its projector needs training on a few samples, enabling plug-and-play scalability.

## Key Results
- State-of-the-art performance on OPV2V and V2XSet: with Agent 1 collaborating others, AP@50 reaches 0.891 and AP@70 reaches 0.810, surpassing prior best (~0.887/0.801).
- Improved results on the real-world RCooper dataset, demonstrating practical applicability.
- Robustness to under-performing agents and moderate communication latency, with controlled performance degradation.

## Why This Works (Mechanism)

### Mechanism 1: Common Ground-Truth BEV as Unified Reference
A feature space derived directly from ground-truth bounding boxes provides a shared semantic and spatial anchor for aligning heterogeneous agent features, eliminating the need for pairwise retraining. The GT encoder converts 3D box parameters (center, dimensions, yaw, category) into BEV feature maps using FC layers and position embeddings; these features act as object-centric prototypes. Each agent’s lightweight projector (MLP) then maps its local BEV features into this space via an L2 similarity loss. This mechanism assumes that GT annotations are accurate and that a common BEV grid can serve as a canonical layout across modalities. Evidence includes the abstract’s statement, Section 3.3’s encoding equations, and the fact that prior heterogeneous works do not challenge GT-derived alignment. The approach fails if GT annotations are sparse, noisy, or lack spatial coverage, as the common space would then misrepresent objects.

### Mechanism 2: Combinatorial Contrastive Learning for Modality-Agnostic Fusion
The fusion network is trained with contrastive losses across all possible modality pairs, forcing it to produce representations that are consistent regardless of the sensor combination. Specifically, similarity between fused feature grid cells and averaged GT features for the same object is maximized, while similarity across different objects is minimized. Computing this loss over every pair (e.g., LiDAR–camera, LiDAR–LiDAR) encourages the network to learn object-level features that are invariant to the originating modality. The core assumption is that object-level alignment in the GT space can be supervised directly on features, bypassing detection head gradients. The abstract mentions contrastive losses, Section 3.5 defines the combinatorial loss, and related works like HM-ViT use end-to-end training, making GT-Space’s explicit feature-level contrast distinctive. If the number of modalities becomes very large, the pairwise loss may become computationally intractable or cause overfitting to frequent pairs.

### Mechanism 3: Lightweight Projectors for Plug-and-Play Scalability
Each agent is equipped with a single adapter module (a small MLP) that projects its local BEV features into the GT-BEV space. During training, the agent’s encoder and detection head remain frozen; only its projector is optimized with the L2 alignment loss. At inference, adding a new agent requires training only its projector while keeping the fusion network fixed. This design eliminates pairwise interactions among agents, allowing arbitrary numbers and types of agents to join the collaboration without retraining the fusion core. The underlying assumption is that despite heterogeneity, a simple MLP suffices to bridge the feature gap. Supporting evidence: the abstract highlights the single adapter, Section 3.4 details projector training and plug-and-play, and Table 4 shows that removing projectors causes the largest performance drop. However, if an agent’s feature space is fundamentally incompatible (e.g., drastically different resolution or semantics), a lightweight projector may be inadequate.

## Foundational Learning

- **Bird’s-Eye View (BEV) Representation**
  - Why needed: BEV offers a consistent top-down spatial grid, aligning features from sensors with different viewpoints and enabling spatial indexing for communication and fusion.
  - Quick check: Why is BEV preferred over perspective view for multi-agent fusion?

- **Contrastive Learning for Feature Alignment**
  - Why needed: Contrastive losses provide direct supervision on feature similarity, ensuring object-level consistency across modalities without relying on detection head gradients.
  - Quick check: How does the temperature parameter in the contrastive loss affect feature discrimination?

- **Heterogeneous Feature Spaces**
  - Why needed: Different sensors (e.g., LiDAR vs. camera) yield BEV features with varying semantics, scales, and channel dimensions; understanding these discrepancies is essential for designing effective projectors and fusion mechanisms.

## Architecture Onboarding
- **Component map:** Pre-trained encoders (per agent) → Local BEV features; Ground-truth encoder → GT-BEV space; Agent-specific projectors → Features aligned to GT-BEV; Fusion transformer → Aggregated features; Collaborative detection head → Final detections.
- **Critical path:**
  - *Training:* (1) Pre-train each agent’s encoder and detection head. (2) Train the GT encoder with IoU loss. (3) Freeze encoders and detection heads; train projectors and fusion transformer using combinatorial contrastive loss over all modality pairs.
  - *Inference for new agent:* Freeze fusion and detection; train the new agent’s projector with GT-BEV alignment loss; deploy.
- **Design tradeoffs:**
  - GT-BEV offers explicit supervision but requires ground-truth at training and high-quality boxes.
  - Lightweight projectors reduce deployment cost but may limit alignment for strongly divergent modalities.
  - Combinatorial contrastive loss ensures modality-agnostic fusion but scales quadratically with modality count.
- **Failure signatures:**
  - Performance declines when agents have weaker local encoders.
  - Sensitivity to pose errors and communication latency (performance drops under high noise/delay).
  - Ablation: Removing projectors or contrastive loss yields significant AP decrease.
- **First 3 experiments:**
  1. Benchmark heterogeneous modality pairs (e.g., LiDAR–camera) against prior baselines to validate cross-modality gains.
  2. Intentionally degrade local agent performance to assess system resilience.
  3. Conduct ablation study disabling GT space, projectors, or contrastive loss to isolate each component’s contribution.

## Open Questions the Paper Calls Out
1. **Eliminating ground-truth dependency:** How can GT-Space be adapted to train without ground-truth bounding boxes, perhaps via weakly-supervised or self-supervised methods? The authors note this as future work.
2. **Scalability to many modalities:** Does the combinatorial contrastive loss remain effective and efficient when the number of heterogeneous agents grows beyond the tested four? The pairwise loss scales quadratically, raising computational concerns.
3. **Sensitivity to projector and encoder design:** What is the impact of projector architecture (depth, width) and ground-truth encoding hyperparameters on performance? The paper does not explore these ablations.
4. **Robustness to extreme communication and pose errors:** Can GT-Space tolerate latency or pose errors beyond the tested ranges (e.g., >500 ms, >0.2 m)? Real-world conditions may exceed these bounds.

## Limitations
- Architectural details (network depths, channel sizes, training schedules) are not fully described, hindering exact replication.
- GT-BEV construction requires accurate, complete bounding box annotations; performance under sparse, noisy, or missing labels is unverified.
- Simple MLP projectors may be insufficient to align features from drastically different modalities (e.g., very low-resolution LiDAR vs. high-dimensional camera).
- Combinatorial contrastive loss may become computationally prohibitive and risk overfitting as the number of modalities increases.
