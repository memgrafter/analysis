# RAG without Forgetting: Continual Query-Infused Key Memory

## Quick Facts
- **arXiv ID**: 2602.05152  
- **Source URL**: https://arxiv.org/abs/2602.05152  
- **Reference count**: 40  
- **Primary result**: ERM transforms transient query expansions into persistent key updates, improving retrieval nDCG@1 by up to +46% (BM25) and QA generation by +2–6% across 13 BEIR/BRIGHT datasets, with especially large gains on reasoning-intensive tasks.

## Executive Summary
Retrieval-Augmented Generation (RAG) systems often rely on query expansion and iterative retrieval to improve robustness, but these adaptations are stateless—computations are discarded after each query, preventing cumulative learning and incurring repeated inference costs. Index-side key expansion exists but typically requires offline preprocessing or heuristic updates, risking semantic drift and noise accumulation. This paper introduces Evolving Retrieval Memory (ERM), a training-free framework that converts ephemeral query expansions into persistent, selectively updated document keys. ERM leverages correctness-gated feedback from the generator to filter expansion signals and attributes only beneficial units to document keys via norm-bounded updates, ensuring stable convergence. Evaluated on 13 datasets, ERM delivers consistent retrieval and end-to-end QA improvements while maintaining native retrieval speeds, particularly excelling on reasoning-heavy benchmarks like LeetCode and TheoremQA.

## Method Summary
ERM operates as a lightweight augmentation on existing RAG pipelines without retraining. For each query, it generates expansion units (e.g., via HyDE) and retrieves documents using the expanded query. A correctness signal—combining retrieval recall and generation quality (e.g., ROUGE or LLM judge)—gates whether the expansion units are retained. Only gated expansions are then attributed to retrieved documents based on a positive marginal similarity gain (Δ>0) between the expanded query and the document’s key. Each document maintains an expansion memory storing these attributed units and their weights. When a saturation criterion is met, the top-weighted units are selected and used to augment the document’s key via a norm-bounded update, ensuring convergence. This process evolves the retrieval index incrementally, turning transient query improvements into lasting key enhancements.

## Key Results
- Retrieval nDCG@1 gains: +46% over BM25 baseline, +13–15% for dense retrievers (e.g., BGE).
- End-to-end QA generation accuracy improves by +2–6% across retrievers.
- Particularly strong performance on reasoning-intensive datasets: LeetCode, AoPS, TheoremQA.

## Why This Works (Mechanism)

### Mechanism 1: Correctness-Gated Feedback
**Claim**: Filtering expansion units based on downstream task success prevents noisy key updates.  
**Mechanism**: For each expanded query \(q'\), a binary success signal is computed as \(\text{success}(q', K) := \mathbf{1}[ V_r(R_K(q')) + V_g(Y_K(q')) \ge 1 ]\), where \(V_r\) is a retrieval verifier (e.g., recall@K) and \(V_g\) is a generation verifier (e.g., ROUGE or LLM judge). Only if success=1, the expansion units are cached for memory evolution.  
**Core assumption**: Downstream task correctness signals reliably indicate useful query expansions.  
**Evidence anchors**: Abstract states "ERM updates the retrieval index through correctness-gated feedback"; Section 4.1 Equation (4) defines the unified success indicator.  
**Break condition**: If verifiers are sparse or biased (e.g., inconsistent LLM judge), gating may filter valid expansions or retain noisy ones, causing drift or missed improvements.

### Mechanism 2: Selective Expansion Attribution
**Claim**: Attributing expansion units only to documents where they yield positive marginal similarity gain bridges query expansion and key building.  
**Mechanism**: For each retrieved document \(d_i\) and expansion unit \(e_j\), compute \(\Delta_{i,j}(q) = \text{sim}(f(q), k_i \oplus f(e_j)) - \text{sim}(f(q), k_i)\). Only if \(\Delta>0\), \(e_j\) is attributed to \(d_i\)'s key. This relies on query-key equivalence (Proposition 4.1) under additive similarity.  
**Core assumption**: The similarity function satisfies query-key equivalence (e.g., inner product with additive augmentation).  
**Evidence anchors**: Abstract notes "selectively attributes atomic expansion signals to the document keys they benefit"; Section 4.2 Proposition 4.1 and equation (5) formalize marginal gain and equivalence.  
**Break condition**: Equivalence fails for non-additive similarity (e.g., normalized cosine) or sparse/late-interaction retrievers, leading to misattribution and key corruption.

### Mechanism 3: Progressive Key Evolution
**Claim**: Accumulating attributions in a bounded memory and updating keys via norm-bounded augmentation ensures convergence and avoids drift.  
**Mechanism**: Each document maintains an expansion memory \(u_i\). For each query batch, compute attribution weights \(w_{i,j}(q) = \text{softmax}_{e_j \in c(q)}(\Delta_{i,j}(q))\). Accumulate scores \(s_{i,j}\) across queries. When saturation criterion triggers, select top-\(x\) units \(\tau_x(u_i)\) and augment: \(k_i^{(t+1)} = k_i^{(t)} \oplus f(\tau_x(u_i))\). Norm bounds on \(f(e_j)\) guarantee stability.  
**Core assumption**: Norm-bounded updates and finite memory capacity lead to stable convergence.  
**Evidence anchors**: Abstract mentions "progressively evolves keys via stable, norm-bounded updates"; Section 4.3 Theorem 4.3 proves convergence; Proposition 4.5 shows amortized cost.  
**Break condition**: Unbounded expansion embeddings or mis-set saturation parameters cause divergence or premature stopping; significant query distribution shift misaligns converged keys.

## Architecture Onboarding
- **Component map**:  
  Retriever -> Query Expansion Module -> Correctness Gater -> Attribution Module -> Per-document Expansion Memory -> Key Evolution Engine -> Index Updater
- **Critical path**:  
  1. Receive query \(q\).  
  2. Generate expansion units \(c(q)\).  
  3. Form expanded query \(q' = \{q\} \cup c(q)\); retrieve top-\(N\) documents \(R_K(q')\).  
  4. Generate answer \(Y_K(q')\).  
  5. Compute \(\text{success}(q', K)\). If 0, discard expansions.  
  6. For each retrieved \(d_i\) and \(e_j\), compute \(\Delta_{i,j}(q)\); if \(\Delta>0\), update \(d_i\)'s memory with weighted contribution.  
  7. After a batch, evaluate saturation (Eq. 10). If saturated, trigger key evolution: for each document, select top-\(x\) units from \(u_i\) and augment \(k_i\).  
  8. Continue with next batch.
- **Design tradeoffs**:  
  - Training-free vs. expressiveness: avoids retraining but depends on fixed retriever/expansion quality.  
  - Selectivity vs. coverage: only positive gains accumulate, preventing drift but possibly missing beneficial multi-unit interactions.  
  - Batch vs. online updates: batched evolution stabilizes but adds latency; online updates are responsive but risk instability.  
  - Norm-bounding: ensures convergence but may limit specialisation if bound \(M\) is too tight.
- **Failure signatures**:  
  - Retrieval nDCG declines on a held-out set after updates.  
  - Expansion memory size grows without bound (capacity not enforced).  
  - Saturation criterion never triggers (\(\rho\) too high) or triggers prematurely (\(\rho\) too low).  
  - High variance in \(\Delta_{i,j}\) scores across batches indicates noisy attributions.  
  - Inconsistent generation verifier (e.g., LLM judge) leads to incorrect gating.
- **First 3 experiments**:  
  1. **Sanity check**: Run ERM on a small dataset (e.g., NFCorpus) with GTE-base retriever and HyDE expansion. Measure nDCG@1 improvement vs. naive retrieval; expect consistent gain.  
  2. **Ablation - gating**: Disable correctness gating (accept all expansions) and compare. Expect degradation due to noise.  
  3. **Attribution validation**: Log distribution of \(\Delta_{i,j}\) values; verify only positives are stored and softmax weights are meaningful. Check diversity of top-\(x\) selected units.

## Limitations
- Verifier quality critical: biased LLM judges misgate updates.
- Additive similarity assumption may not hold for all retrievers (e.g., cosine, ColBERT).
- Saturation heuristic (\(\rho\), top-\(x\)) can cause premature stop or unbounded growth.
- Corpus comparison weak; novelty overlap possible.

## Confidence
- **High**: Reported gains on 13 datasets (BEIR/BRIGHT) are robust.
- **Medium**: Theory proofs assume idealized conditions; real-world adherence uncertain.
- **Low**: Long-term drift and cross-domain generalization not evaluated.
