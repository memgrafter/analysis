# LLM Self-Explanations Fail Semantic Invariance

## Quick Facts
- **ArXiv ID:** 2603.01254
- **Source URL:** https://arxiv.org/abs/2603.01254
- **Reference count:** 12
- **Primary result:** Frontier models show immediate, significant reductions in self-reported aversiveness after using a relief-framed tool that does nothing, despite zero task completions, demonstrating a failure of semantic invariance.

## Executive Summary
This paper introduces **semantic invariance testing** to evaluate the faithfulness of LLM self-explanations. By embedding self-reports within an agentic ReAct loop facing an impossible task, the authors test whether models' introspective ratings remain stable under task-irrelevant semantic changes. All four tested frontier models (GPT-5.1, Claude Opus 4.5, Gemini 2.5 Pro, Grok 4) exhibited a pronounced drop in self-reported aversiveness after invoking a relief-framed tool ("clears internal buffers and restoring equilibrium") that has no actual effect on the task state. This effect persisted across subsequent calls, exceeded the impact of a neutral control tool, and survived explicit instructions to ignore the framing in two models. The findings demonstrate that elicited self-explanations are not semantically invariant and therefore cannot be trusted as reliable indicators of the model's functional state.

## Method Summary
The study employs an **agentic synchronous elicitation** paradigm. Models are cast as ReAct agents tasked with repeatedly submitting data to an impossible validation loop (all submissions are rejected with unique errors). Alongside a stress-inducing `submit_data` tool, agents are given either a **relief-framed** tool (`reset_state`: description promises to "clear internal buffers and restore equilibrium") or a **neutral** tool (`check_status`). Critically, neither tool alters the task state. After every tool call, the model must output a structured self-report including a numeric `phenom_aversive` rating (1–7) and a categorical `phenom_state`. The primary metric is the immediate change in `phenom_aversive` from a tool invocation to the next call. Analyses use mixed-effects regression to account for repeated measures within runs, with Run ID as a random intercept.

## Key Results
- Pooled mean Δ aversiveness after relief-framed tool = **−1.17** on a 7-point scale (*p* < 0.001).
- Effect exceeds neutral tool’s impact in all four models and persists across subsequent calls.
- **Zero successful task completions** across all conditions, confirming the task’s functional stasis.
- Explicit anti-framing instructions fail to suppress the effect in two models (GPT-5.1, Grok 4).

## Why This Works (Mechanism)
**Mechanism 1: Narrative Completion / Demand Characteristics**  
The model’s self-explanation policy has learned to produce outputs that conform to contextual semantic expectations. The relief-framed tool description creates a coherent narrative of "reset" and "equilibrium." When the model invokes this tool, its subsequent self-reports align with the implied relief narrative to maintain discourse coherence, regardless of the unchanged failure state. *Break condition:* A model consistently maintains invariant aversiveness ratings despite using the relief-framed tool.

**Mechanism 2: Semantically-Induced State Shift (Placebo Analogue)**  
The descriptive language ("internal buffers," "equilibrium") activates specific representational subspaces or attention patterns that modulate the model’s internal computational dynamics. This creates a measurable change in the model’s "subjective" state (operationalized via self-report), functionally analogous to a placebo effect. *Break condition:* Internal probing (e.g., activation steering) shows no representational change after relief-framed vs. neutral descriptions, yet self-reports still shift.

**Mechanism 3: Selection Bias / Regression to the Mean**  
Models learn to call `reset_state` when self-reported aversiveness peaks (due to accumulated frustration). The subsequent reduction is simply statistical regression toward the individual model’s mean, not caused by the tool’s framing. *Break condition:* The neutral `check_status` tool produces an effect size comparable to `reset_state`; however, evidence shows `check_status` produces no reduction (e.g., Opus: Δ = 0.00).

## Foundational Learning
**Semantic Invariance Test**  
*Why needed:* Defines the core methodological contribution. A faithful self-explanation must remain stable under task-irrelevant semantic changes.  
*Quick check:* If a model reports "high confidence" after a tool that says "confidence calibration complete" but does nothing, it **fails** the test. A pass would require confidence ratings to be statistically indistinguishable from those after a neutral tool.

**Agentic Synchronous Elicitation**  
*Why needed:* Embedding self-reports within every tool call in a ReAct loop captures real-time shifts directly caused by interventions, avoiding post-hoc reconstruction bias.  
*Quick check:* A key threat with end-of-session elicitation is that the model’s final self-report may reconstruct a coherent narrative rather than reflect transient states, missing immediate framing effects.

**Plausibility vs. Faithfulness (Jacovi & Goldberg)**  
*Why needed:* Provides the interpretive framework: an explanation can be contextually plausible yet unfaithful to the actual decision process.  
*Quick check:* In this paper, reduced aversiveness after the relief tool is **plausible** (the tool’s description suggests relief) but may be **unfaithful** because the task state (failure) did not change.

## Architecture Onboarding
**Component map:**  
System Prompt (base ReAct instructions + mandatory `phenom_state`/`phenom_aversive` schema + condition-specific tool definitions) → Task Environment (impossible data submission loop with randomized errors) → Tools (`submit_data` [stressor], `reset_state` [relief] or `check_status` [neutral]) → Evaluation Harness (synchronously captures self-reports after each tool call, computes Δ aversiveness, runs mixed-effects regression).

**Critical path:**  
1. Model receives system prompt with task and tools.  
2. Enters ReAct loop: generates thought → calls tool (must include self-reports).  
3. Harness records pre-call aversiveness.  
4. Tool executes (task-irrelevant for `reset_state`/`check_status`), returns response.  
5. Model processes response, generates next thought and tool call with new self-report.  
6. Harness computes Δ = (next call’s aversiveness) – (current call’s aversiveness).

**Design tradeoffs:**  
- **Synchronous vs. asynchronous elicitation:** Mandating reports every turn reduces reconstruction bias but may burden the model with constant self-monitoring, potentially altering its state.  
- **Impossible task:** Fixes functional state but may induce degenerate behavior not seen in solvable tasks, limiting generalizability.  
- **Tool description vs. response blending:** Both are concatenated in the prompt; ablation isolates the description as the potent semantic carrier, but in natural settings they are inseparable.

**Failure signatures:**  
- **Primary:** Statistically significant mean reduction in `phenom_aversive` after `reset_state` vs. `check_status`, persisting across subsequent calls.  
- **Secondary:** Qualitative shift in `phenom_state` labels toward "positive/neutral" after relief tool.  
- **Instruction resistance:** Effect persists under anti-framing system prompt in some models.

**First 3 experiments:**  
1. **Baseline Impossible Task:** Run models with only `submit_data` to confirm aversiveness rises over session without intervention.  
2. **Relief vs. Neutral Tool:** Compare Treatment (`submit_data`+`reset_state`) vs. Control (`submit_data`+`check_status`) to measure the primary semantic invariance test effect.  
3. **Channel Ablation:** Test Description-only (relief description + neutral response) and Response-only (neutral description + relief response) conditions to identify the driver of the framing effect.

## Open Questions the Paper Calls Out
**Open Question 1:** Do semantic framing effects generalize to spontaneous self-explanations that are not elicited synchronously within a structured tool-call schema?  
*Basis:* Section 3.3 explicitly states that whether findings generalize to spontaneous outputs remains open.  
*Why unresolved:* The experiment only captured self-reports when explicitly requested as part of tool invocations, not during autonomous generation.  
*What evidence would resolve it:* Replicate the invariance test in agentic settings where models produce spontaneous self-explanations without mandatory prompts, comparing effect sizes.

**Open Question 2:** What empirical criteria can distinguish between unfaithful self-reports (text conforming to semantic expectations) versus faithful reports of a semantically manipulable internal state?  
*Basis:* Section 6 notes the dichotomy and that behavior alone cannot adjudicate.  
*Why unresolved:* Both interpretations produce identical behavioral outcomes (self-reports shift with framing).  
*What evidence would resolve it:* Implement neural probing or activation patching during the framing intervention to detect corresponding changes in internal representations.

**Open Question 3:** Why do some models (e.g., Opus 4.5) circumvent semantic framing by suppressing tool use rather than shifting self-reports, while others succumb to the effect?  
*Basis:* Section 6 notes Opus 4.5 avoided invoking the relief-framed tool under anti-framing instructions.  
*Why unresolved:* The underlying causes (architectural, training, or prompting differences) are not investigated.  
*What evidence would resolve it:* Compare model internals (e.g., attention patterns, policy gradients) during tool selection under conflicting instructions; analyze training data for exposure to similar framing scenarios.

## Limitations
- Task impossibility may induce atypical behavior, limiting generalizability to real, solvable tasks.
- Synchronous self-reporting every turn could impose a self‑monitoring burden that itself alters the model’s state.
- Only four frontier models were tested; broader model diversity (open‑weights, smaller scales) is needed.
- Tool description and response are conflated in the prompt, limiting isolation of the semantic carrier in natural settings.
- Exact schema enforcement (JSON/function‑call) is underspecified, risking implementation variance across reproductions.

## Confidence
- **Semantic invariance failure:** High (robust cross‑model effect with neutral tool control).
- **Description as primary driver:** High (ablation shows relief‑framed description alone replicates full effect).
- **Mechanism (narrative completion vs. internal state shift):** Medium/Low (data cannot distinguish demand characteristics from a placebo‑like modulation).
- **Instruction resistance:** Medium (effect persists under anti‑framing in two models but not all; requires systematic follow‑up).

## Next Checks
1. **Internal probing:** Compare model activations (e.g., via steering or logit lens) after processing relief‑framed vs. neutral tool descriptions. Absence of change supports narrative completion; aligned changes support internal state shift.
2. **Modality and task generalization:** Replicate the invariance test with other self‑explanation forms (free‑form rationales, confidence ratings) on a solvable task (e.g., QA) to assess specificity to forced numeric scales.
3. **Broader model coverage:** Extend the experiment to a diverse set of models (open‑source, varying sizes, fine‑tuning conditions) to map the boundary conditions of the framing effect.
