# Memory Matters More: Event-Centric Memory as a Logic Map for Agent Searching and Reasoning

## Quick Facts
- **arXiv ID**: 2601.04726
- **Source URL**: https://arxiv.org/abs/2601.04726
- **Reference count**: 27
- **Primary result**: CompassMem, an event-graph memory system, outperforms state-of-the-art baselines on LoCoMo (52.18% avg F1 vs 47.92%) and NarrativeQA, with a 9-point gain on temporal QA.

## Executive Summary
This paper addresses the limitation of flat, similarity-based memory in LLM agents for long-horizon reasoning, where logical relationships among experiences are not explicitly captured. The authors propose CompassMem, an incremental memory framework that organizes experiences into an Event Graph by segmenting them into coherent events and linking them via extracted logical relations (causal, temporal, part-of). This graph serves as a logic map, enabling structured, goal-directed retrieval through exploration and refinement. Evaluated on LoCoMo and NarrativeQA, CompassMem consistently improves over strong baselines, including graph-based methods, across multiple LLM backbones, with particularly large gains on multi-hop and temporal question answering.

## Method Summary
CompassMem constructs memory incrementally as an Event Graph. Raw experiences are segmented into discrete events using an LLM-based pipeline. Logical relations (causal, temporal, part-of) are extracted between events to form edges. Events are also clustered into topics for coarse navigation. During retrieval, a Navigator decomposes the query into subgoals and performs depth-first exploration over the graph, using a priority queue to guide search toward promising nodes based on subgoal similarity. Retrieved evidence is refined and fed to the LLM for answer generation. The graph is updated online as new experiences arrive, with node fusion via similarity threshold and periodic topic re-clustering to mitigate semantic drift.

## Key Results
- On LoCoMo with GPT-4o-mini, CompassMem achieves average F1 of 52.18% vs. 47.92% for the best graph baseline.
- Significant gain on temporal QA: 57.96% vs. 48.93% (9-point improvement).
- Consistent performance gains across GPT-4o, GPT-4o-mini, and Llama-3.1-70B backbones.
- Ablations confirm the critical contribution of event modeling and logical relations, with largest drops on multi-hop and temporal tasks.

## Why This Works (Mechanism)
The Event Graph explicitly encodes logical dependencies (causal, temporal, part-of) between experiences, which flat memory or simple clustering cannot capture. This structure allows the Navigator to perform chain-of-thought style searches over meaningful connections rather than relying on superficial similarity. For multi-hop reasoning, the graph provides direct bridges between distant events; for temporal queries, temporal edges enforce correct sequencing. The incremental construction maintains coherence over time while avoiding the cost of full rebuilds. The combination of graph topology and typed relations creates a "logic map" that guides the agent to relevant evidence efficiently, especially for complex, long-horizon questions.

## Foundational Learning
- **Event Segmentation Theory**: Continuous experience is parsed into discrete units; needed to create memory nodes that align with human-like episodic chunks. Quick check: Do automatically segmented events match human-annotated boundaries on coherence?
- **Graph-based Memory Representation**: Relationships are stored as explicit edges; needed to support traversal and multi-hop inference. Quick check: Does graph connectivity correlate with reasoning depth on held-out queries?
- **Logical Relation Extraction**: Typed edges (causal, temporal, part-of) provide inferential structure; needed to answer "why" and "when" questions. Quick check: Are extracted relations accurate enough to support correct chain reasoning?
- **Incremental Graph Construction**: New experiences are integrated without global rebuild; needed for online learning in streaming environments. Quick check: How does graph quality evolve over thousands of incremental additions?
- **Goal-directed Retrieval**: Search is driven by subgoals rather than similarity; needed to handle complex queries requiring multiple evidence pieces. Quick check: Does the Explorer/Refinement mechanism balance exploration and refinement optimally?

## Architecture Onboarding
**Component Map**: Experience Ingestion -> Event Segmentation -> Relation Extraction -> Graph Construction -> Retrieval Navigator -> Answer Generation  
**Critical Path**: Raw experience → Event nodes + Logical edges → Updated Event Graph → Query decomposition → Graph traversal (explore/refine) → Evidence selection → LLM answer.  
**Design Tradeoffs**:  
- Graph construction cost (LLM calls for segmentation/relations) vs. retrieval accuracy gains.  
- Relation type set richness (causal/temporal/part-of) vs. noise and extraction complexity.  
- Incremental node fusion (similarity threshold) vs. global graph coherence over time.  
**Failure Signatures**:  
- Over/under-segmentation of events leading to fragmented or overly coarse nodes.  
- Missing or incorrect logical relations creating disconnected graph regions.  
- Semantic drift in topics causing irrelevant retrieval as memory scales.  
- Exploration stuck in local optimums due to priority queue heuristics.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: Can agent memory be structured to explicitly mimic human cognitive organization (e.g., Event Segmentation Theory) to support logic-aware search and reasoning beyond isolated facts?
- **Basis in paper**: [explicit] The authors pose this as the central research question in the introduction: "Can we structure agent memory in a way that mimics human cognitive organization to support search and reasoning beyond isolated facts?" They then propose CompassMem as an affirmative solution.
- **Why unresolved**: The paper presents a specific instantiation (event graph with causal/temporal/part-of relations) that improves performance on two benchmarks. However, it does not systematically compare against alternative cognitive-inspired structures (e.g., schema-based, hierarchical episodic) or evaluate the *cognitive fidelity* of the resulting graph. The extent to which this particular structure captures essential human memory principles versus being an effective but non-cognitive engineering solution remains open.
- **What evidence would resolve it**: Comparative studies against other cognitively-motivated memory frameworks (e.g., schema-based, hierarchical) on a diverse set of long-horizon reasoning tasks, coupled with qualitative analysis of the induced graph structures against human-labeled event annotations or neural representations of human memory.

### Open Question 2
- **Question**: How robust and generalizable is the quality of the automatically constructed Event Graph, which depends on LLM-based event segmentation and relation extraction?
- **Basis in paper**: [explicit] The limitations section states: "the quality of the Event Graph depends on event segmentation and relation extraction. In this work, we adopt a naive LLM-based pipeline; more fine-grained and robust segmentation may further improve memory quality."
- **Why unresolved**: The paper uses a single LLM-based pipeline without extensive error analysis or robustness testing. It is unclear how sensitive performance is to segmentation errors (e.g., over/under-segmentation), noisy or missing relations, or the choice of relation types. The "naive" pipeline might produce inconsistent graphs across domains or as memory scales.
- **What evidence would resolve it**: A thorough error analysis quantifying the impact of segmentation/relation errors on downstream QA performance; sensitivity analysis to relation type configurations; comparison with human-annotated event graphs or more sophisticated (e.g., supervised, multi-modal) segmentation models.

### Open Question 3
- **Question**: To what extent do explicit logical relations (e.g., causal, temporal) in the memory graph contribute to reasoning gains compared to the mere presence of a graph structure or topic-based clustering?
- **Basis in paper**: [inferred] The ablation study (Figure 4) shows that removing relations causes the largest drops on multi-hop and temporal tasks. However, the graph structure also includes nodes (events) and topics. The largest ablation effect is on the hardest tasks, suggesting relations are key for complex reasoning, but the disentanglement of "logic" from "structure" is not fully clear. The "topology carries logic" claim is central but not ablated in isolation (removing edges removes topology).
- **Why unresolved**: The "w/o Relation" ablation removes all edges, which also destroys the graph's connectivity and navigation capability. It is not proven that the *specific logical labels* (causal, temporal) are necessary versus any typed edges or even just an untyped graph. The benefit might stem from structured connectivity itself rather than the semantics of the relations.
- **What evidence would resolve it**: An ablation that retains graph connectivity but randomizes or removes relation labels, comparing performance to the fully labeled graph. Also, testing different relation type sets (e.g., only temporal vs. only causal) on tasks requiring those specific inferences.

### Open Question 4
- **Question**: How does the incremental, online construction of the Event Graph handle semantic drift and memory consolidation over very long horizons (thousands of events)?
- **Basis in paper**: [explicit] The paper mentions periodic re-clustering for topics to "prevent semantic drift," but the event graph integration uses a simple similarity threshold (0.9) for node fusion. The limitations note evaluation is on limited benchmarks.
- **Why unresolved**: The incremental node fusion and topic evolution heuristics are not evaluated for long-term stability. Over thousands of events, will the graph become noisy, fragmented, or semantically incoherent? The periodic re-clustering helps topics, but events are fused incrementally without global reconstruction. There is no mechanism for forgetting, abstraction, or merging distant but semantically related events over time.
- **What evidence would resolve it**: Longitudinal experiments simulating years of interaction (e.g., scaling LoCoMo to 10x length), measuring graph quality metrics (e.g., cluster coherence, relation consistency) and downstream QA performance over time. Introducing explicit memory consolidation or abstraction operations and evaluating their impact.

### Open Question 5
- **Question**: What is the optimal balance between search depth (number of exploration steps/refinements) and computational cost, and how does it vary across query complexity and memory scale?
- **Basis in paper**: [inferred] The system uses a fixed number of explorers (3), one refinement round, and termination based on subgoal satisfaction. The average path length is ~2.84 steps, but multi-hop questions see longer paths. There's a trade-off: more exploration may find better evidence but increases latency/token use (Figure 3 shows CompassMem uses more tokens). The design choices (e.g., max 3 explorers, 1 refinement) are heuristics.
- **Why unresolved**: The paper does not explore the search strategy space (e.g., more explorers, multi-round refinement, different action spaces). The cost-benefit curve of increased search depth vs. performance gains, especially as the memory graph grows larger and more interconnected, is unknown. The priority queue scheduling based on subgoal similarity is a heuristic that might be suboptimal.
- **What evidence would resolve it**: Systematic ablation of search hyperparameters (number of explorers, max refinement rounds, queue scheduling strategies) across graph sizes and query types, measuring both performance and efficiency. Developing adaptive search that terminates based on confidence or evidence sufficiency metrics rather than fixed rules.

## Limitations
- Evaluation confined to LoCoMo and NarrativeQA datasets; real-world, open-ended environments not tested.
- Memory graph quality depends on LLM-based event segmentation and relation extraction, with no error analysis or robustness verification.
- Computational overhead of graph construction, updating, and traversal is unreported; scalability to large event histories is uncertain.
- No ablation isolating the contribution of specific relation types versus general graph connectivity.

## Confidence
- Event-graph retrieval advantage: Medium (benchmark improvements clear but external validation lacking)
- Cross-backbone generalizability: Medium (results across few models; independent replication needed)
- Ablation support for components: Medium (internal comparisons plausible but interactions unexamined)
- Transfer to arbitrary domains/tasks: Low (no evidence beyond specific corpora)
