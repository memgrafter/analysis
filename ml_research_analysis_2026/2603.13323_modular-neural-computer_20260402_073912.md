# Modular Neural Computer

## Quick Facts
- **arXiv ID**: 2603.13323
- **Source URL**: https://arxiv.org/abs/2603.13323
- **Reference count**: 10
- **Primary result**: The Modular Neural Computer (MNC) achieves deterministic, exact execution of algorithms (array minimum, in-place bubble sort, A* search) on variable-length inputs by compiling known algorithms analytically rather than learning from data.

## Executive Summary
Memory-augmented neural networks often fail to generalize algorithmic computations to inputs of unseen lengths. The Modular Neural Computer (MNC) addresses this unreliability by combining an external associative memory, a controller multilayer perceptron (MLP), and a fixed set of homogeneous functional MLP modules. Computation proceeds via a predetermined graph: at each step, the controller emits a one-hot gate signal that activates exactly one module, which then performs an exact, specified transformation on memory state read via dedicated addresses. The weights of all networks are analytically specified—not learned—so the system executes algorithms deterministically and invariants are preserved. Three case studies demonstrate the approach: computing an array minimum, in-place bubble sorting, and executing A* search on a fixed graph. Sorting correctly reorders any array in exactly n(n+1)/2 steps, and A* finds the optimal path (cost 8) on a 7-node graph without approximation.

## Method Summary
MNC employs an external associative memory implemented as a bank of scalar cells. Addressing is performed via a softmax with a very low temperature (τ=10⁻⁴), making reads and writes effectively discrete and integer-indexed, while remaining differentiable. A controller MLP reads the current control variables (e.g., current index i, array length n, pass limit p) and outputs two signals: a one-hot gate vector that selects which functional module will run this step, and a set of integer addresses that specify which memory cells to read or write. The architecture includes a fixed, homogeneous set of K functional MLP modules; only the module whose gate is high receives a nonzero input and thus updates memory. Each module implements an exact primitive operation (e.g., compute minimum of two values, increment a counter, swap two cells) by using analytically derived weight matrices and biases. The computational graph—the order in which modules are activated—is fixed for each algorithm and loops over steps until a termination condition stored in memory is met. All weights are hand-specified, eliminating training and guaranteeing deterministic behavior that exactly matches the textbook algorithm.

## Key Results
- Exact array minimum: For any input length, MNC returns the correct minimum value.
- In-place bubble sort: MNC sorts any array in exactly n(n+1)/2 steps, preserving the invariant of a partially sorted array after each pass.
- A* search: On a 7-node graph, MNC finds the optimal path with total cost 8, matching classic A* without approximation.

## Why This Works (Mechanism)
MNC’s reliability stems from its analytic construction: every weight is chosen so that each functional module performs its assigned transformation exactly (e.g., a min module outputs the smaller of two inputs using linear combinations followed by a ReLU that only passes the smaller value). The controller’s outputs are deterministic given the current memory state; because the computational graph is fixed and the gating is one-hot, exactly one module executes per step, avoiding conflicting writes. Low-temperature softmax addressing ensures that reads and writes target the intended integer addresses, making the overall state transition deterministic. By avoiding gradient-based learning, the system does not suffer from approximation errors or failure to generalize seen in learned neural computers. The combination of discrete addressing, exact arithmetic modules, and a fixed schedule yields behavior that is mathematically equivalent to a conventional program implementing the same algorithm, thus guaranteeing invariance preservation and correct termination.

## Foundational Learning
- **External Associative Memory**: Provides a flexible, addressable store for state of arbitrary size. Needed because algorithms require persistent state that changes over time. *Quick check*: verify that memory read/write operations produce near one-hot weight distributions, resulting in integer addresses and no interference between cells.
- **One-Hot Gating**: Selects a single functional module each step, preventing simultaneous updates that could corrupt state. Needed to enforce a sequential, deterministic execution model. *Quick check*: inspect the gate vector; it should contain exactly one component close to 1 (e.g., >0.99) and the rest near 0.
- **Controller MLP**: Interprets control variables (loop counters, flags) and decides the next action (which module to run and which memory locations to access). Needed to translate algorithmic control flow into neural signals. *Quick check*: for a known memory snapshot (e.g., i=3, n=5), the controller should output the expected gate (e.g., “increment”) and the correct addresses.
- **Homogeneous Functional Modules**: Each module implements a basic operation (min, max, increment, compare) exactly via handcrafted weights. Needed because complex algorithms are decomposed into such primitives. *Quick check*: test each module in isolation; it must compute the exact mathematical function (e.g., min(7,2)=2) for all possible inputs.

## Architecture Onboarding
**Component map**: Memory -> Controller -> Gate/Addresses -> Selected Functional Module -> Memory (cycle repeats each step).

**Critical path**: For a given algorithm (e.g., bubble sort), at each time step: (1) controller reads loop control variables from memory; (2) controller outputs a one-hot gate and integer addresses; (3) the chosen module reads the specified memory cells, performs its exact operation (e.g., compare-and-swap), and writes the results back; (4) memory updates, possibly modifying control variables; (5) loop until termination condition is true.

**Design tradeoffs**:
- External memory enables variable-length data but requires careful soft-addressing to stay near-discrete.
- Homogeneous modules are simple and reusable but may necessitate many steps for complex logic.
- One-hot gating ensures determinism but relies on precisely tuned weights; small deviations can break exactness.
- Fixed computational graph trades flexibility for correctness; changing algorithm requires redesigning the graph and possibly adding modules.

**Failure signatures**:
- Gates not one-hot: multiple modules fire, leading to memory corruption.
- Addresses non-integer: softmax not sharp enough; reads/writes hit wrong cells.
- Approximate arithmetic: ReLU thresholds or weight inaccuracies cause outputs to deviate from expected min/max/increment.
