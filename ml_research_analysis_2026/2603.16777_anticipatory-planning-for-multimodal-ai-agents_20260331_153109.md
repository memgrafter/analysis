# Anticipatory Planning for Multimodal AI Agents

## Quick Facts
- **arXiv ID:** 2603.16777
- **Source URL:** https://arxiv.org/abs/2603.16777
- **Reference count:** 40
- **Primary result:** A two-stage reinforcement learning framework (TraceR1) substantially improves long-horizon task success rates on GUI and tool-use benchmarks, with Stage 2 execution grounding providing consistent ~6% absolute gains.

## Executive Summary
Multimodal AI agents typically fail at long-horizon tasks due to reactive, myopic decision-making. TraceR1 introduces a two-stage reinforcement learning framework that first trains the model to generate globally coherent, anticipatory trajectories using discounted alignment rewards against reference plans, and then refines step-level executability using binary success signals from frozen tool agents. Across seven benchmarks, this approach raises task success rates (e.g., AndroidWorld +3.5pp, OSWorld-Verified +5.6pp) and achieves performance comparable to proprietary systems, demonstrating that separating trajectory-level coherence from step-level grounding yields more robust planning.

## Method Summary
TraceR1 employs sequential reinforcement learning with Group-Relative Policy Optimization (GRPO). In Stage 1, the planner predicts a short-horizon trajectory (T≈10 steps) and is rewarded for alignment with a ground-truth reference trajectory, using temporal discounting (γ=0.8) and a repetition penalty to encourage global coherence without execution. Stage 2 then fine-tunes the same planner using binary rewards derived from executing only the first predicted step with a frozen tool agent (e.g., UI-TARS), which provides ground-truth success signals for feasibility and precision. During inference, the agent runs a plan-act loop: predict T steps, execute the first, observe the new state, and replan.

## Key Results
- Improved success rates on AndroidWorld (e.g., UI-TARS-1.5-7B: 27.4% → 30.9%) and OSWorld-Verified (Qwen3-VL-32B: 35.6% → 41.2%).
- Outperformed open-source baselines across seven GUI/tool benchmarks and matched proprietary systems.
- Ablations confirm Stage 2 contributes a consistent ~6% absolute gain; performance peaks at a moderate prediction horizon T≈10.

## Why This Works (Mechanism)

**Mechanism 1:** Stage 1 trains globally coherent multi-step plans by optimizing a discounted trajectory-level reward against a reference plan. The model predicts a short-horizon future trajectory (action types and instructions). A reward function computes alignment (accuracy of action types) with the ground-truth trajectory, applies temporal discounting (γ=0.8) to prioritize near-future correctness, and penalizes repetitive sequences, optimized via GRPO. This induces long-term dependencies purely from trajectory data. Evidence: Section 3.1 defines R(τ) = Σ γ^(t-1) r_t with alignment and repetition terms; ablations show Stage 1 alone underperforms the full method. Break condition: Removing the repetition penalty or setting γ=1.0 causes reward hacking (cyclic actions) or overfitting to unstable distant predictions.

**Mechanism 2:** Stage 2 refines step-level executability and precision using binary success signals from frozen tool agents. For each rollout, the first predicted step is executed by a separate, frozen tool model (e.g., UI executor). The outcome (e.g., click coordinates) is compared to ground truth to produce a binary reward. This grounded signal fine-tunes the planner to output instructions that lead to feasible low-level execution, without altering the high-level anticipatory structure from Stage 1. Evidence: Section 3.2 describes r_G_t as binary match; ablations show w/o Stage 2 drops ~6% on average. Break condition: Removing Stage 2 entirely yields infeasible steps despite coherent plans.

**Mechanism 3:** The two-stage decoupling separates learning of long-horizon coherence from low-level precision, yielding a planner robust to both planning drift and execution errors. Stage 1 establishes a prior for multi-step consistency across abstract action types; Stage 2 then conditions this prior on concrete executability without contaminating the global objective with step-level noise. Evidence: Figure 3 shows full method outperforms ablations; the design avoids interference seen in joint training. Break condition: Merging stages into a single mixed reward degrades performance due to conflicting gradients during early learning.

## Foundational Learning
- **Anticipatory Trajectory Reasoning:** The paper’s core proposed capability—forecasting a sequence of future actions rather than reacting step-by-step. Why needed: It shifts the agent from myopic to deliberative planning. Quick check: How does predicting a fixed-length 5-step trajectory during training differ from supervised next-step prediction with a long context window?
- **Grounded Reinforcement Learning (with frozen tools):** Using the actual outcome of an action (via a separate tool model) as a reward signal, without updating the tool itself. Why needed: Stage 2 relies on this to provide executable precision. Quick check: Why use a frozen tool agent for execution feedback instead of training the policy to directly output precise coordinates?
- **Group-Relative Policy Optimization (GRPO):** The RL algorithm used in both stages; it computes advantages from a group of rollouts (no value network). Why needed: It enables stable policy updates for multi-step trajectory rewards. Quick check: What is the main computational advantage of GRPO over PPO for this kind of trajectory optimization?

## Architecture Onboarding
- **Component map:** Planner (TraceR1 model) -> Frozen Tool Agents -> Reward Modules -> GRPO Trainer
- **Critical path:** Pre-collected trajectory dataset -> Stage 1 RL (trajectory rewards, no execution) -> Stage 2 RL (execute first step per rollout, compute step reward) -> Inference (plan → execute first step → replan loop)
- **Design tradeoffs:** 
  - Prediction horizon (T): Short (T=1) loses anticipatory benefit; long (T>10) introduces noise from uncertain distant predictions; optimal range T≈10.
  - Two-stage vs. joint: Sequential training avoids interference but requires two passes; joint training risks catastrophic forgetting.
  - Frozen tools: Using powerful proprietary tools (e.g., GPT-4.1) ensures high-quality execution feedback but limits open-source reproducibility.
- **Failure signatures:**
  - Stage 1 only: Coherent plans but individual steps infeasible (e.g., "click Settings" when not visible); manifests as low step success rates.
  - Stage 2 only: Steps executable but myopic; agent gets stuck in local loops on long-horizon tasks.
  - Excessive T (T>>10): Plans become speculative and unravel during execution; success rate drops.
  - Missing repetition penalty: Agent repeats the same action type (e.g., multiple "click") to game alignment reward without state change.
- **First 3 experiments:**
  1. Ablate Stage 2: Train with only Stage 1 RL. Expect ~6% absolute drop on AndroidWorld/OSWorld/GTA, confirming need for execution grounding.
  2. Horizon sweep: Train with T ∈ {1,3,5,10,15,20}. Expect peak performance around T=10, validating the design choice of "short-horizon foresight."
  3. Reward component ablation: Remove λ_rep or set γ=1.0. Expect significant degradation, proving necessity of temporal discounting and loop prevention.

## Open Questions the Paper Calls Out
- **Extending to embodied/hybrid environments:** Can the paradigm be applied to domains requiring coordination of perception, reasoning, and action over longer time scales? Current evaluations are on discrete GUI/tool tasks; embodied settings involve continuous control and physical dynamics, likely requiring modifications.
- **Improving long-range trajectory rewards:** Why does performance peak at T≈10 and degrade for longer horizons? The paper attributes this to uncertainty accumulation and noisy rewards but offers no solution. Improved reward design (e.g., adaptive discounting, hierarchical decomposition) is needed.
- **Removing dependence on reference trajectories:** How can anticipatory planning be rewarded without ground-truth multi-step demonstrations? The current Stage 1 reward requires reference trajectories, limiting applicability to tasks without detailed demonstrations and possibly stifling creative planning.
- **Enhancing Stage 2 for long-term plan revision:** Can short-horizon execution updates be used to revise long-term plans? Stage 2 provides only local corrections and cannot reshape understanding of long-term feasibility; hierarchical planning or world models may be needed.

## Limitations
- Data preprocessing details (history truncation, trajectory splitting) and reward implementation nuances (normalization, clipping) are unspecified, hindering faithful reproduction.
- Heavy reliance on proprietary frozen tools (e.g., GPT-4.1) for Stage 2 grounding limits open-source reproducibility and introduces external API dependencies.
- Evaluations are confined to GUI/tool benchmarks; generalization to other long-horizon domains (e.g., robotics, embodied AI) remains unverified.

## Confidence
- **High:** Reported performance gains (e.g., +3.5pp on AndroidWorld, +5.6pp on OSWorld) and consistent ~6% contribution from Stage 2 are robust across multiple benchmarks.
- **Medium:** Optimal prediction horizon T≈10 is empirically validated but may not generalize beyond GUI tasks; two-stage decoupling is inferred from ablations but lacks direct comparison to joint training.
- **Low:** Accuracy of frozen tool agents as execution oracles is unverified; potential noise in Stage 2 rewards could affect results. Scalability and computational cost of two-stage RL are not analyzed.

## Next Checks
