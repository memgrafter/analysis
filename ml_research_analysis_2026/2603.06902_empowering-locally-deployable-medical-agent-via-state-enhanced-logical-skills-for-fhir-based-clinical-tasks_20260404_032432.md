# Empowering Locally Deployable Medical Agent via State Enhanced Logical Skills for FHIR-based Clinical Tasks

## Quick Facts
- **arXiv ID**: 2603.06902
- **Source URL**: https://arxiv.org/abs/2603.06902
- **Reference Count**: 0
- **Primary Result**: A training-free framework using entity-agnostic logical skills and query-anchored two-stage retrieval achieved 71.33% overall success on MedAgentBench with Qwen3-30B-A3B, a 22.67% absolute gain.

## Executive Summary
SELSM (State Enhanced Logical Skills for Medical agents) is a training-free, memory-augmented framework designed to deploy large language models (LLMs) locally for FHIR-based clinical tasks. It addresses data scarcity and privacy constraints by distilling simulated clinical interaction trajectories into reusable, entity-agnostic logical skills. At inference, a two-stage retrieval mechanism selects relevant skills based on the current query and state, guiding step-by-step reasoning and resolving polysemy in clinical states. Evaluated on MedAgentBench with 30B–32B models, SELSM significantly improved action success rates and overall task completion, demonstrating a path for efficient, privacy-preserving local clinical AI deployment without model fine-tuning.

## Method Summary
SELSM operates in two phases. First, a skill distillation phase uses simulated FHIR interaction trajectories (generated from seed queries via an LLM "actor" and a "judge" LLM) to extract abstract, entity-agnostic logical skills (e.g., "search patient by identifier then create condition"). These skills are stored in a memory. Second, during inference on a new task, a query-anchored two-stage retrieval first fetches skills relevant to the query intent, then re-ranks them based on semantic similarity to the current state representation (which condenses the agent's history and observation). The top-k retrieved skills condition the agent's step-by-step generation, grounding its actions in previously successful logical patterns.

## Key Results
- Achieved a 100% task completion rate and 71.33% overall success on Qwen3-30B-A3B, a 22.67% absolute improvement over baseline.
- Lifted action success on GLM4-32B from 16.7% to 60.7% (+44 points).
- Averaged 60.89% success across tested 30B–32B models, outperforming memory-augmented baselines.
- Reduced token cost per correctly completed task, indicating higher inference efficiency.

## Why This Works (Mechanism)
SELSM mitigates two core challenges for local medical agents: 1) **Data Scarcity & Privacy**: By using synthetic, simulator-generated trajectories for distillation, it avoids needing large-scale, sensitive real-world clinical data for training. 2) **State Polysemy**: Clinical states (e.g., "search results") can have ambiguous meanings depending on prior actions. The two-stage retrieval anchors skill selection first in task intent (query), then in precise operational context (current state), ensuring retrieved skills match the dynamic workflow stage. The entity-agnostic nature of skills allows generalization across patient-specific data without retraining.

## Foundational Learning
* **FHIR (Fast Healthcare Interoperability Resources)**: A standard for exchanging healthcare information via RESTful APIs. *Why needed*: Provides the structured, text-based interaction interface (resources, searches, operations) that the agent must navigate. *Quick check*: Verify the agent can formulate valid FHIR search parameters (e.g., `GET /Condition?patient=123`) from natural language.
* **Entity-Agnostic Skill Abstraction**: Representing clinical procedures as generalized logical templates (e.g., "find <resource> by <field> then update <field>") instead of concrete, patient-bound sequences. *Why needed*: Enables reuse of procedural knowledge across different patients and data values, which is essential for broad coverage from limited simulation. *Quick check*: Sample skills should contain placeholders (e.g., `<Patient_ID>`) and be applicable to multiple synthetic patient scenarios.
* **Two-Stage Retrieval**: First, retrieve skills by query similarity (task intent); second, re-rank by state similarity (current context). *Why needed*: Prevents retrieval of skills that match the high-level goal but are inappropriate for the precise workflow state (e.g., a "create" skill when the current state indicates a "search" has already failed). *Quick check*: Ablate the second stage and measure drop in success rate on tasks requiring sequential context awareness.
* **Simulated Clinical Trajectories**: Synthetic interaction histories (query → state sequence → action) generated by an LLM actor within a FHIR simulator. *Why needed*: Provides the raw material for skill distillation without real patient data. *Quick check*: Validate a sample trajectory against FHIR API specifications; actions should be syntactically valid and states should reflect API response semantics.
* **LLM-as-Judge for Skill Abstraction**: A separate LLM is prompted to extract the core logical pattern from a complete trajectory, producing the generalized skill. *Why needed*: Automates the abstraction from concrete examples to reusable templates. *Quick check*: Judge outputs should consistently omit patient-specific values (names, IDs) while preserving the logical operator sequence (Search → Read → Create).
* **Memory-Augmented Agent**: An LLM actor that conditions its generation on a retrieved prompt containing relevant skills. *Why needed*: Injects external procedural knowledge to compensate for the base model's lack of clinical workflow training. *Quick check*: With an empty memory, the agent should exhibit high failure rates on multi-step tasks; with a correct skill retrieved, it should execute the sequence accurately.

## Architecture Onboarding
**Component Map**
Seed Queries -> Trajectory Generator (Simulator + Actor LLM) -> Raw Trajectories -> Skill Distiller (Judge LLM) -> Skill Memory (Vector DB of abstract skills) -> Inference: New Query & State -> Two-Stage Retriever -> Relevant Skills -> Actor LLM (Conditioned) -> Next Action -> State Update -> (repeat)

**Critical Path**
1. **Distillation Phase**: Generate diverse seed queries → simulate full trajectories → distill into abstract skills → index skills in vector store.
2. **Inference Phase**: For a new task, generate initial state from query → retrieve top-k skills via two-stage similarity → prepend skills to actor prompt → actor generates first action → simulator returns new state → loop until task completion.

**Design Tradeoffs**
- **Memory Size vs. Retrieval Cost**: Larger skill libraries improve coverage but increase retrieval latency and prompt length. The paper uses top-k=5, a tradeoff between context window limits and relevance.
- **Judge LLM Capability vs. Skill Quality**: Using a stronger judge (e.g., GPT-4) likely produces more accurate abstractions but raises cost and environmental footprint during distillation; the tradeoff is not explored.
- **Generalization vs. Specificity**: Entity-agnostic skills generalize well but may omit crucial, concrete constraints (e.g., "must use SNOMED CT codes"). The framework prioritizes logical flow over terminological precision.

**Failure Signatures**
- **Retrieval Misalignment**: Top-retrieved skills do not match the current workflow state (e.g., retrieving a "create" skill for a "search" state). Manually inspect retrieved skill templates vs. current state description.
- **Skill Library Gaps**: Agent fails with "cannot find relevant skill" or repeatedly attempts invalid actions. Indicates missing procedural templates for a sub-task.
- **Judge Abstraction Error**: Distilled skills are nonsensical or contain residual concrete values. Sample and validate a subset of stored skills for placeholder usage and logical coherence.
- **State Representation Failure**: The state encoding does not capture critical context (e.g., previous search results), causing the second-stage retrieval to fail. Compare state embeddings for different points in the same trajectory.

**First Three Experiments**
1. **Seed Query Coverage Test**: Measure agent success on a held-out set of 100 MedAgentBench tasks while varying the diversity of seed queries used to build the skill memory (e.g., clinical vs. IT-focused, common vs. rare operations). Expect success to correlate with seed diversity.
2. **Judge Consistency Audit**: Run the skill distillation pipeline with three different LLMs as judges (e.g., GPT-4, Claude-3, Qwen-72B). Compute agreement (e.g., Jaccard similarity) on distilled skills for the same input trajectories and correlate with downstream agent performance.
3. **Two-Stage Retrieval Ablation**: On MedAgentBench, compare full SELSM against variants: (a) single-stage retrieval (only query-based), (b) random skill selection, and (c) perfect oracle retrieval. Isolate the contribution of the state-aware re-ranking.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: Does SELSM generalize to clinical task types or domains beyond theFHIR-based EHR interactions evaluated on MedAgentBench?
- **Basis in paper**: [explicit] The authors identify "Single-benchmark evaluation" as a principal limitation, noting all experiments were conducted solely on MedAgentBench.
- **Why unresolved**: Relying on a single benchmark, even a rigorous one, constrains claims about the framework's applicability to other clinical workflows (e.g., administrative, imaging, or laboratory tasks) or alternative data standards.
- **What evidence would resolve it**: A replication study evaluating SELSM on additional benchmarks, such as FHIR-AgentBench (read-only) or novel benchmarks covering other clinical domains (e.g., scheduling, billing, or multimodal imaging workflows).

### Open Question 2
- **Question**: Can the entity-agnostic skill abstraction of SELSM enable effective cross-institutional deployment across heterogeneous hospital IT infrastructures (e.g., distinct FHIR endpoints, custom formularies, legacy systems)?
- **Basis in paper**: [explicit] The authors highlight the "Absence of real cross-institutional validation" as a key limitation, stating the claimed generalization pathway "remains a hypothesis awaiting empirical confirmation through multi-site studies."
- **Why unresolved**: The evaluation occurred within a single simulated FHIR environment. Real-world heterogeneity in data dictionaries, API implementations, and clinical protocols could break the assumption that distilled skills transfer seamlessly.
- **What evidence would resolve it**: A multi-site study where each participating hospital generates skills from its own local simulator (emulating its specific EHR configuration) and deploys them on a common set of evaluation tasks, measuring performance retention or adaptation needs.

### Open Question 3
- **Question**: To what extent do systematic biases in the LLM-as-Judge (e.g., preference for verbose rules, specific syntactic structures) propagate into the distilled skill library and affect downstream agent performance?
- **Basis in paper**: [explicit] The authors note the "LLM-as-Judge quality ceiling," stating that "systematic biases in the judge... may propagate to the skill memory undetected, and the current framework provides no independent calibration mechanism."
- **Why unresolved**: The skill quality is entirely contingent on the judge's abstraction fidelity, which is uncalibrated and could introduce subtle, consistent errors into the logical skill space that degrade retrieval or reasoning.
- **What evidence would resolve it**: (a) A meta-evaluation where skills distilled by different LLM judges (e.g., GPT-4, Claude, DeepSeek) are compared for consistency and impact on agent performance; (b) Human expert audits of a sample of distilled skills to identify systematic omissions or distortions relative to ground-truth operational logic.

### Open Question 4
- **Question**: How dependent is the comprehensiveness of the SELSM skill library on the expertise and effort invested in generating the initial seed queries for trajectory collection?
- **Basis in paper**: [explicit] The authors cite "Seed query dependency" as a limitation, noting that generating "effective and diverse seed queries requires clinicians or clinical informatics specialists with substantial domain expertise, representing a non-trivial human investment."
- **Why unresolved**: The framework's zero-shot capability ultimately relies on having a pre-populated, high-quality skill memory. If achieving broad coverage requires prohibitively expert-heavy query engineering, the practicality for widespread local deployment is undermined.
- **What evidence would resolve it**: Experiments varying the seed query source (e.g., clinician-generated vs. LLM-generated vs. ontology-derived) and measuring the impact on (a) skill library diversity, (b) coverage of held-out tasks, and (c) agent success rates, to quantify the "expertise threshold" needed for viable deployment.

### Open Question 5
- **Question**: Can the SELSM paradigm be extended beyond text-based FHIR API interactions to multimodal clinical workflows involving other data types (e.g., DICOM images, HL7 messages, physiological time-series)?
- **Basis in paper**: [explicit] The authors identify "Text-only interaction assumption" as a limitation and state that extension to "multimodal clinical settings... would necessitate fundamentally new abstraction mechanisms."
- **Why unresolved**: The entity-agnostic skill space is designed for textual state representations. Clinical environments often involve non-textual data (images, waveforms) where operational logic (e.g., "measure left ventricular ejection fraction from this MRI slice") requires different abstraction and skill representation.
- **What evidence would resolve it**: A proof-of-concept extension of SELSM where (a) state representations integrate multimodal features (e.g., image embeddings, signal segments), (b) the logical skill generator produces skills with multimodal reasoning patterns, and (c) evaluation on a simulated multimodal task (e.g., radiology report generation followed by order placement) demonstrates maintained or improved performance.

## Limitations
- Evaluation is confined to MedAgentBench, a single synthetic benchmark; performance on real-world, diverse clinical workflows remains unknown.
- Claims of "locally deployable" efficiency are validated only on 30B–32B models; feasibility on smaller, consumer-grade hardware (e.g., 7B–13B models) is unverified.
- The "privacy-preserving" assertion relies on synthetic data; no empirical audit of residual memorization risks or data leakage is provided.

## Next Checks
1. **Cross-Benchmark Replication**: Re-run SELSM on at least two other clinical agent benchmarks using 30B–32B and smaller (7B–13B) models to test generalizability and hardware constraints.
2. **Privacy Stress Test**: Quantify potential data leakage by prompting the memory-augmented system to reproduce exact phrases from the synthetic training simulations and measuring memorization rates.
3. **Ablation of Retrieval Design**: Isolate the contribution of the query-anchored two-stage retrieval by comparing against single-stage retrieval and random skill selection on MedAgentBench, controlling for memory size.
