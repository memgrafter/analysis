# Multi-Scenario User Profile Construction via Recommendation Lists

## Quick Facts
- **arXiv ID:** 2603.15357
- **Source URL:** https://arxiv.org/abs/2603.15357
- **Reference count:** 40
- **Primary result:** RAPI framework achieves attribute inference accuracies up to 0.764 (gender, MovieLens-1m) and 0.6477 (gender, LastFM-1k), consistently outperforming baselines across four scenarios and showing only a 2–3% accuracy drop against a fairness-aware recommendation model.

## Executive Summary
This paper introduces RAPI, a framework for inferring user attributes (e.g., gender, age) from recommendation lists under four distinct information-access scenarios. RAPI constructs a white-box surrogate recommender that mimics a black-box target model, augments user recommendation lists by aligning BERT-based content embeddings with the surrogate’s item embeddings, and employs an adaptive-weight classifier for attribute prediction. Experiments on multiple datasets demonstrate state-of-the-art inference accuracy and robustness against fairness-aware recommendation defenses, highlighting persistent privacy risks even when only limited list data is exposed.

## Method Summary
RAPI operates in three stages. First, it selects a white-box surrogate recommendation model (e.g., MF, NGCF) by measuring recommendation list similarity (rls) between candidate models and the target black-box model on a contributor set. The chosen surrogate provides accessible item embeddings. Second, it augments each user’s short recommendation list by aligning BERT content embeddings to the surrogate’s embedding space using an MLP trained on interacted items; then it appends the most similar candidate items to create a longer, richer list. Third, it predicts user attributes using a neural network that dynamically weights each item’s embedding based on its learned informativeness, aggregating them into a user representation. The framework is evaluated across four scenarios varying available data (item IDs, embeddings, content, contributor interactions) and shows consistent improvements over baseline methods.

## Key Results
- RAPI achieves attribute inference accuracies up to 0.764 (gender, MovieLens-1m) and 0.6477 (gender, LastFM-1k), significantly outperforming baselines like DT, KNN, DNN, and PeterRec.
- The framework remains effective across all four information-access scenarios, with performance steadily improving as more auxiliary data (α, β) becomes available.
- When tested against a fairness-aware recommendation model (FairMI), RAPI’s accuracy drops by only 2–3%, demonstrating notable robustness to adversarial defenses.

## Why This Works (Mechanism)
**Mechanism 1: Surrogate Model Selection via List Similarity**
- **Claim:** A white-box surrogate recommendation model can be selected that mimics the black-box original model’s output, enabling the analyst to access item embeddings.
- **Mechanism:** The analyst computes the recommendation list similarity (rls) between the original model’s top‑K lists and those generated by candidate models (e.g., MF, NeuMF, NGCF) on a contributor set. The model with the highest rls is selected as the spurious model (F_spu). This model’s internal item embeddings (E_S) can then be extracted for items in V_L (items interacted with by contributors).
- **Core assumption:** Different recommendation algorithms exhibit structurally similar collaborative filtering behavior on the same user‑item interaction graph, leading to overlapping top‑N recommendation lists.
- **Evidence anchors:** Section 4.1 formalizes rls; Section 5.3.1 shows MF achieves highest rls (~0.62–0.69) against LightGCN; the paper’s reference corpus focuses on graph‑based/CF models supporting the premise.

**Mechanism 2: Augmentation via Content‑Embedding Alignment (RLDA)**
- **Claim:** Augmenting a target user’s short recommendation list with items similar to their historical interactions (using an aligned embedding space) provides a richer user preference signal for attribute inference.
- **Mechanism:** Using the surrogate F_spu, the analyst obtains E_S for items in V_L. For items not in V_L (V_V), BERT provides content embeddings (E_C). An alignment model (MLP) is trained on V_L to map E_C to the recommendation space (bE_C), minimizing distance to E_S. For a target user’s original list, similarity (res) between list items (in E_S) and all candidate items (using aligned embeddings) is computed; the top‑K₂ most similar items are appended to form an augmented list.
- **Core assumption:** An item’s semantic/content features (from BERT) are predictive of its preference in the collaborative filtering embedding space, and this relationship can be aligned.
- **Evidence anchors:** Section 4.2 details RLDA; Section 5.3.2 reports res values (~4 for MovieLens) indicating feasible alignment; Section 5.6 shows accuracy improves with longer augmented lists.

**Mechanism 3: Adaptive‑Weight Classification**
- **Claim:** Dynamically weighting items within an augmented recommendation list based on their learned contribution to attribute prediction, rather than fixed or equal weighting, improves inference accuracy.
- **Mechanism:** For an augmented list z_i, item embeddings (e_j from E_S) are aggregated via a weighted sum (u_i = Σ w_j * e_j). Weights w_j are computed by a softmax over a learned projection (W_a * e_j + b_a), making them position‑agnostic but content‑aware. The aggregated vector u_i is fed to a classification MLP to predict the attribute.
- **Core assumption:** Informativeness of items about a sensitive attribute is a function of their latent features and relation to the attribute, not just their rank in the list.
- **Evidence anchors:** Section 4.3 defines the mechanism; Section 5.3.3 (Figure 5) shows adaptive weighting outperforms static/sum aggregation; Section 5.2 (Tables 2–7) shows RAPI consistently outperforms DNN baselines.

## Foundational Learning
- **Collaborative Filtering & Recommendation Models**  
  Understanding matrix factorization, GCNs (e.g., LightGCN), and how they generate user/item embeddings and top‑N lists is essential to grasp surrogate model selection and embedding usage.  
  *Quick check:* Why might MF (a linear model) have higher recommendation list similarity (rls) with LightGCN (a graph model) than NeuMF (a non‑linear neural model) on a given dataset?
- **Pre‑trained Language Models & Embedding Alignment**  
  RAPI bridges semantic item content (BERT) and collaborative filtering embeddings via an alignment model, critical for augmenting lists when the surrogate model lacks embeddings for some items.  
  *Quick check:* What are the risks of using BERT embeddings (trained on general text) for movie/music item titles in the alignment task?
- **Supervised Classification with Imbalanced Data**  
  Attribute inference often involves binary/multi‑class classification with inherent class imbalance; the adaptive‑weight classifier must learn under these conditions, and evaluation uses accuracy/F1.  
  *Quick check:* Why does the paper report both accuracy and F1‑score, and when might F1 be more informative?

## Architecture Onboarding
**Component map:**  
Contributor interaction histories & original recommendation lists → Spurious model confirmation (candidate models trained, rls computed, best surrogate selected) → Extraction of surrogate item embeddings (E_S) for interacted items → RLDA (alignment model trained on E_S vs BERT E_C; BERT embeddings aligned for all items; target user lists augmented via similarity) → Adaptive‑weight classifier (item embeddings dynamically weighted, aggregated, passed to MLP) → Predicted user attributes.

**Critical path:** For Scenarios 3/4 (with content/contributor data), the pipeline is: Confirmation → Alignment → Augmentation → Weighted Classification. Failure at any stage (e.g., poor surrogate, bad alignment) propagates downstream.

**Design tradeoffs:**
- *Surrogate model selection:* Simple models (MF) are faster and may generalize better (higher rls) but have less expressive embeddings than complex models (NGCF).
- *Alignment complexity:* MLP vs. AE; MLP performed better but more complex aligners might help if semantic gap is large.
- *Augmentation size:* Longer lists (K₂) provide more data but also more noise; paper uses K₂=50 for original length 20.
- *Weighting mechanism:* Adaptive weights add parameters and training complexity versus static/sum, but yield clear gains.

**Failure signatures:**
- Low rls (<0.4): Surrogate model too dissimilar; abort or try different candidates.
- High alignment error (res) on validation items: Alignment model failed; adjust capacity or pretrained model.
- Classifier training loss stagnates or validation accuracy low (< random): Augmentation may add noise; reduce K₂.
- Inference accuracy drops significantly vs. baselines in Scenario 1/2: Augmentation may harm signal; verify item relevance.

**First 3 experiments:**
1. **RQ1 (Overall Performance):** Test RAPI against DT/KNN/DNN/PeterRec across four datasets and scenarios with varying α, β. Confirm RAPI (Scenario 4) achieves highest accuracy (e.g., 0.764 gender in MovieLens-1m) and improves with more α, β.
2. **RQ2 (Module Impact – Augmentation):** Ablate RLDA by comparing RAPI with/without augmentation. Measure accuracy drop to quantify value of alignment and similarity‑based augmentation.
3. **RQ3 (Robustness against FairMI):** Run RAPI against a fairness‑aware recommendation model (FairMI) instead of LightGCN. Observe the accuracy drop (2–3%) to test framework resilience.

## Open Questions the Paper Calls Out
- **What perturbation strategies on recommendation lists best balance robustness against user attribute inference and recommendation utility?** The conclusion mentions future work on refinement mechanisms for an optimal trade‑off, but only preliminary category‑based replacement was tested without systematic exploration.
- **How does the accuracy of RAPI degrade when the spurious recommendation model significantly differs from the original model?** The framework selects a surrogate based on rls but only tests three standard models against LightGCN, without considering broader model mismatches or error bounds.
- **Does joint modeling of multiple sensitive attributes improve inference accuracy compared to treating attributes independently?** The evaluation treats each attribute separately; potential correlations between attributes are ignored, and joint inference could yield more accurate holistic profiling.

## Limitations
- Exact hyperparameter configurations for candidate recommender models (MF, NeuMF, NGCF) are unspecified, impeding faithful reproduction.
- The operational definition of α and β relative to the fixed data split is unclear, affecting result comparability.
- Robustness is evaluated only against a single fairness‑aware model; vulnerability to other defenses and lack of cold‑start user evaluation leave broader claims unverified.

## Next Checks
1. **Hyperparameter Audit:** Re‑run spurious model confirmation with full disclosure and variation of hyperparameters (embedding dim, layers, regularization) to reproduce reported rls values exactly.
2. **Alignment Robustness Test:** Replace BERT with alternative content encoders (e.g., different language models or item‑specific metadata encoders) and re‑evaluate RLDA’s augmentation quality (res metric) and final inference accuracy.
3. **Cold‑Start User Evaluation:** Isolate target users with zero interaction history in the contributor set (strict Scenario 1). Apply RAPI and all baselines to directly test inference from short/empty lists and expose potential overfitting.
