# Correct, Concise and Complete: Multi-stage Training For Adaptive Reasoning

## Quick Facts
- **arXiv ID**: 2601.02972
- **Source URL**: https://arxiv.org/abs/2601.02972
- **Reference count**: 20
- **Primary result**: Multi-stage training reduces LLM reasoning length by 28–40% with minimal accuracy loss, achieving state-of-the-art accuracy‑efficiency trade‑off (AUCOAA +5 over base).

## Executive Summary
Large language models often exhibit “overthinking” in chain‑of‑thought reasoning, producing unnecessarily long outputs that increase computational cost and can even degrade performance. This paper introduces a multi‑stage framework to mitigate overthinking while preserving accuracy. The approach first curates a supervised fine‑tuning dataset by selecting the shortest correct reasoning trace per problem (rejection sampling) or by removing redundant summary statements (trace reformatting). It then applies reinforcement learning with a verifiable reward that combines correctness and an adaptive length penalty, which discourages generation beyond the first correct answer. Evaluated on seven diverse benchmarks, the method slashes response length by 28% for 8B models and 40% for 32B models, with only small accuracy drops of 1.6 and 2.5 points respectively. The resulting models achieve a new best score (76.6) on the Overthinking‑Adjusted Accuracy curve, outperforming both the base model and prior work.

## Method Summary
The training pipeline consists of two sequential stages. Stage 1 (SFT) builds a high‑quality dataset: either by rejection sampling from multiple model‑generated traces (keeping only the shortest correct trace for each problem) or by parsing existing traces to strip intermediate summaries while retaining the final answer. This dataset is used to fine‑tune a base model for 2 epochs with a learning rate of 1e‑5 and batch size 256. Stage 2 employs reinforcement learning via the GRPO algorithm. For each prompt, K=8 responses are sampled; each receives a reward R = RC − λ·RL, where RC is 1 if the final answer matches the reference and 0 otherwise, and RL counts tokens generated after the first correct answer (detected by normalized matching). RL penalizes superfluous tokens, encouraging the model to stop as soon as it reaches correctness. Training runs for 50 iterations with a global batch of 256, learning rate 1e‑6, KL penalty β=0.001, and λ fixed at 1. The final policy yields reasoning that is both accurate and concise.

## Key Results
- **Length reduction**: Average response length decreased by 28% for 8B models and 40% for 32B models across seven benchmarks.
- **Accuracy trade‑off**: Only modest accuracy drops of 1.6 points (8B) and 2.5 points (32B) relative to the base model.
- **AUCOAA improvement**: Achieved a score of 76.6, surpassing the base model by 5 points and the previous state‑of‑the‑art by 2.5 points.

## Why This Works (Mechanism)
The method works because it cleanly separates the learning of correctness from the optimization for conciseness. The SFT stage establishes a strong prior for producing correct answers by training on traces that are already correct and minimal (rejection sampling) or denoised (reformatting). This gives the model a good starting point where it can solve problems without unnecessary elaboration. The subsequent RL stage then directly tunes the model’s output length using an adaptive penalty that activates only after the model has already generated a correct answer. This penalty is computed per token after the first correct answer, so the model has no incentive to continue once correctness is achieved. The use of a verifiable reward (binary correctness) ensures the penalty is applied only when the model has actually solved the problem, preventing premature truncation. Together, these stages yield a model that can reliably reach the correct solution and stop promptly, thereby reducing overthinking while maintaining accuracy.

## Foundational Learning
- **Chain‑of‑Thought (CoT) Reasoning**  
  - *Why needed*: Standard prompting technique for complex reasoning that generates intermediate steps; however, it can become verbose.  
  - *Quick check*: Prompt the model with “Let’s think step by step” and verify it produces multiple reasoning lines before the final answer.

- **Overthinking Problem**  
  - *Why needed*: Excessive reasoning tokens waste compute and may introduce errors; recognizing this problem motivates the need for efficiency.  
  - *Quick check*: Generate multiple CoT traces for the same problem and plot accuracy vs. token length; observe diminishing or negative returns after a certain length.

- **Rejection Sampling for SFT Data Curation**  
  - *Why needed*: Allows automatic assembly of a dataset that demonstrates minimal correct reasoning, guiding the model toward brevity.  
  - *Quick check*: For a set of problems, sample N traces from a model, check correctness, and confirm the selected shortest correct trace is indeed shorter than the average correct trace.

- **Group Relative Policy Optimization (GRPO)**  
  - *Why needed*: A reinforcement learning algorithm that uses relative rewards within a group of sampled responses, offering stable policy updates with a verifiable reward.  
  - *Quick check*: Implement a toy task (e.g., bandit) and compare GRPO’s sample efficiency and stability to REINFORCE or PPO.

- **Adaptive Length Penalty via First Correct Answer Detection**  
  - *Why needed*: Directly penalizes superfluous tokens after correctness is reached, driving the model to stop early without harming solution correctness.  
  - *Quick check*: Given a trace and a reference answer, use normalized string matching to locate the earliest point where the answer appears; ensure tokens beyond that point are counted in the penalty.

## Architecture Onboarding
**Component Map**  
Base Model → SFT Module (dataset via rejection sampling/trace reformatting) → RL Module (GRPO with adaptive reward) → Final Efficient Model.

**Critical Path**  
1. Prepare base model and sample 13K problems from DeepScaleR.  
2. Construct SFT data: either generate multiple traces per problem and pick the shortest correct one, or parse existing traces to remove summary text.  
3. Fine‑tune base model on SFT data for 2 epochs (LR=1e‑5).  
4. Initialize RL: define reward R = RC − λ·RL (λ=1).  
5. Run GRPO for 50 iterations, sampling 8 responses per prompt, updating policy with Adam (LR=1e‑6) and KL regularization (β=0.001).  
6. Output final model.

**Design Tradeoffs**  
- Rejection sampling yields model‑specific minimal traces but requires multiple forward passes per problem; trace reformatting is cheaper but may leave residual redundancy.  
- Fixed λ=1 simplifies training but may not be optimal across tasks; tuning could improve the accuracy‑efficiency balance.  
- Two‑stage decoupling avoids corrupting correctness learning with length penalties but introduces additional training complexity and compute.

**Failure Signatures**  
- Accuracy drops >5 points: likely λ too high or first‑correct‑answer detector flawed (e.g., false positives causing over‑penalization).  
- No meaningful length reduction: RL stage failing to learn (e.g., reward signal too weak, insufficient iterations).  
- Inconsistent length reduction across benchmarks: overfitting to the SFT/RL training distribution (DeepScaleR sample limits generalization).

**First Experiments**  
1. Verify SFT data pipeline: on a 100‑problem subset, manually confirm that the selected shortest correct traces are indeed correct and shorter than alternatives.  
2. Test RL reward function: compute RC and RL for a few hundred model outputs; ensure RL is nonzero only when the correct answer appears and that tokens after that point are counted accurately.  
3. Evaluate SFT‑only model on a held‑out set: compare length and accuracy to the base model to establish the baseline improvement before RL.

## Limitations
- The DeepScaleR dataset composition and licensing are undisclosed, hindering full reproducibility.  
- The adaptive length penalty coefficient (λ) is fixed at 1; its sensitivity and impact on training stability are unexplored.  
- Evaluation is restricted to seven benchmarks; generalization to other domains (e.g., code, multilingual) or model architectures remains uncertain.

## Confidence
- **Length reduction claim** (28% for 8B, 40% for 32B): Medium (reproducible numerically but may vary with λ and random seed).  
- **Accuracy preservation claim** (minor drop): Medium (no statistical variance reported).  
- **AUCOAA superiority** (+5 over base, +2.5 over SOTA): Medium (depends on metric definition and benchmark set).  
- **Generalization across benchmarks**: Low (evaluation scope limited to seven tasks).  
- **RL stage contribution**: Low (no ablation isolating RL’s effect).

## Next Checks
- Replicate the full SFT+RL pipeline with the same hyperparameters; report mean and standard deviation over multiple random seeds for length and accuracy on all seven benchmarks.  
- Perform ablations: (a) train without RL; (b) vary λ ∈ {0.5, 1.0, 2.0} to quantify each component’s impact on the accuracy‑efficiency trade‑off.  
- Test the final models on at least two out‑of‑distribution benchmarks (e.g., GSM8K, MBPP) to assess cross‑dataset generalization.
