# Instruction Set and Language for Symbolic Regression

## Quick Facts
- arXiv ID: 2603.21836
- Source URL: https://arxiv.org/abs/2603.21836
- Reference count: 2
- Primary result: ISALSR achieves >99.97% round-trip fidelity and canonical invariance on benchmark DAGs, with 100% acyclicity and evaluation preservation; it collapses up to k! equivalent numberings to one canonical string.

## Executive Summary
ISALSR introduces a novel representation for symbolic regression that eliminates structural redundancy by encoding expressions as strings over a two‑tier alphabet where every string maps to a valid labeled DAG. The method uses a commutative encoding (NEG/INV for subtraction/division) to reduce non‑commutative operators to POW only, and a pruned backtracking algorithm to compute a canonical string that is a complete labeled‑DAG isomorphism invariant. On Nguyen and AI Feynman benchmarks, ISALSR yields >99.97% round‑trip fidelity and canonical invariance, and analyses show a 71.2% redundancy rate among valid perturbations, demonstrating dramatic search‑space compression.

## Method Summary
ISALSR defines a deterministic state machine (S2D) that translates any string over a 31‑token alphabet into a labeled DAG while guaranteeing acyclicity and proper edge creation. The inverse D2S algorithm greedily traverses a DAG to produce a string. The core contribution is the pruned canonicalization algorithm, which explores all valid insertion orders (Vℓ/vℓ) with label‑aware τ‑pruning and a POW‑eligibility filter to find the lexicographically smallest string representing the DAG. A preprocessing step (Normalize_const_creation) redirects all constant‑creation edges to a fixed variable, ensuring a unique canonical form. This representation provides a unique identifier for expression equivalence, drastically reducing redundancy in symbolic regression search.

## Key Results
- >99.97% round‑trip fidelity (S2D→D2S preserves DAG structure and evaluation).
- >99.97% canonical invariance across 961 DAG permutations (all numberings yield identical canonical string).
- 71.2% redundancy rate among valid perturbations, confirming substantial search‑space compression; for k=8, >40,000 equivalent numberings collapse to one.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The two‑tier instruction alphabet guarantees every string decodes to a valid labeled DAG, eliminating invalid‑expression rejection.
- **Mechanism:** Tokens move a pointer, create edges (with cycle check), or insert new operation/variable nodes with an edge from the current pointer. New nodes get strictly increasing IDs; S2D rules (Table 2) are total and enforce arity and type constraints.
- **Core assumption:** Strictly increasing node IDs and edge‑insertion‑order tracking ensure operand‑order semantics for POW and prevent cycles.
- **Evidence anchors:** Abstract states “every string over the alphabet represents a valid DAG”; Section 2.2 details S2D and the acyclicity invariant.

### Mechanism 2
- **Claim:** Commutative encoding (NEG/INV) reduces the set of non‑commutative binary operations to POW only, simplifying labeled‑DAG isomorphism.
- **Mechanism:** Subtraction and division are decomposed into ADD/MUL with NEG/INV; ADD/MUL are commutative, so only POW requires preserving operand order via edge‑insertion order.
- **Core assumption:** Decomposition preserves semantic equivalence (confirmed by 100% evaluation preservation).
- **Evidence anchors:** Abstract mentions commutative encoding; Section 2.1 defines NEG/INV; Section 4.1 reports 100% evaluation preservation.

### Mechanism 3
- **Claim:** The pruned canonical string (label‑aware τ‑pruning + exhaustive Vℓ/vℓ search) computes a complete labeled‑DAG isomorphism invariant, collapsing Θ(k!) numberings to one.
- **Mechanism:** The search explores all valid insertion orders but prunes using (1) POW first‑operand eligibility and (2) τ‑tuples (hop counts to depth 3). It seeks the lexicographically smallest string among shortest encodings.
- **Core assumption:** τ‑tuple comparison is safe for pruning; i.e., a candidate with a strictly larger tuple can be kept without missing a lexicographically smaller canonical string.
- **Evidence anchors:** Abstract states the collapse; Conjecture 2.11; Section 4.2 shows 100% canonical invariance on 961 DAGs (with three P3 failures outside intended domain).

## Foundational Learning
- **Labeled DAG isomorphism**  
  Why needed: The goal is to identify when two instruction strings (node numberings) represent the same mathematical expression. Requires a precise equivalence (Def 2.9) respecting operator semantics and operand order for POW.  
  Quick check: If you permute the two child nodes of an ADD node, are the DAGs equivalent? What about swapping children of a POW node?

- **Backtracking search with pruning heuristics**  
  Why needed: Canonicalization requires exploring all Vℓ/vℓ orders, which is exponential. τ‑tuple pruning reduces the search space while (conjecturally) preserving the lexmin result. Understanding branch‑and‑bound and safe heuristics is key.  
  Quick check: What structural information does the τ‑tuple capture, and why might comparing τ‑tuples allow discarding Vℓ/vℓ branches without affecting the final canonical string?

- **Commutative vs. non‑commutative operator semantics in graph representations**  
  Why needed: Redundancy interacts with operator symmetry. ADD/MUL are commutative, so many numberings are truly equivalent; POW is non‑commutative, so some numberings are distinct. Decomposing subtraction/division shrinks the non‑commutative set to POW only, simplifying isomorphism and search.  
  Quick check: After decomposing x‑y into ADD(x, NEG(y)), how many distinct DAGs encode this expression if ADD’s children were ordered? Why does the decomposition reduce that number?

## Architecture Onboarding
### Component Map
Normalize_const_creation → PrunedCanonical → D2S → canonical string; S2D and D2S provide bidirectional conversion between strings and DAGs.

### Critical Path
Input DAG → Normalize_const_creation (redirect all CONST edges to x1) → PrunedCanonical (backtracking search) → canonical string. For round‑trip evaluation: canonical string → S2D → DAG.

### Design Tradeoffs
- Pruning heuristic vs. completeness: τ‑tuple pruning sacrifices theoretical completeness for speed; empirical >99.97% agreement with exhaustive, but three P3 failures (edges into VAR) reveal domain limits.
- Commutative simplification vs. operator expressivity: Decomposing − and / removes operator‑specific isomorphism rules but adds unary nodes, increasing DAG size slightly.
- Two‑tier alphabet vs. grammar complexity: Guarantees every string yields a valid DAG, avoiding rejection sampling, but requires a stateful parser with cycle checks and pointer management.

### Failure Signatures
1. P3 failure: canonical(D) ≠ canonical(permutation(D)) when DAG has edges into VAR nodes (e.g., CONST → variable). This breaks D2S’s insertion assumption.
2. Timeout in canonicalization: For large DAGs (k > 12), exponential backtracking may become infeasible; monitor recursion depth and candidate set size.
3. Round‑trip fidelity failure: Rare; indicates bugs in S2D’s cycle checks or D2S’s reconstruction of POW operand order.

### First 3 Experiments
1. Round‑trip test: Generate random ISALSR strings, run S2D → D2S, verify DAG isomorphism and evaluation identity.
2. Canonical invariance on benchmarks: Take known expressions (Nguyen/AI Feynman), create two DAGs with different internal numberings (e.g., swap commutative ADD children), verify canonical strings match.
3. Search‑space collapse quantification: For small DAGs (k=3,4), enumerate all k! internal node permutations, compute canonical strings, confirm they collapse to one string; compare pruned vs exhaustive for k=6–8.

## Open Questions the Paper Calls Out
1. **Can the central conjectures (round‑trip fidelity and pruned canonical completeness) be formally proven for all valid labeled DAGs?**  
   *Basis:* Conjectures stated in Sections 2.5 and 3; proofs left as future work.  
   *Unresolved:* Requires rigorous analysis of backtracking exhaustiveness and isomorphism adequacy for all DAG topologies, including edges into VAR nodes.

2. **How does runtime scale with DAG size, and what is the quantitative speedup from τ‑tuple pruning over exhaustive search for larger expressions?**  
   *Basis:* Scalability study under analysis; to be reported in a subsequent revision (Section 4.3).  
   *Unresolved:* No empirical data for k>8; theoretical worst‑case complexity is exponential.

3. **To what extent does canonicalization reduce effective search space and improve convergence when integrated into state‑of‑the‑art SR algorithms?**  
   *Basis:* Integration experiments with specific SR algorithms deferred to future work (Section 5).  
   *Unresolved:* No measurement of impact on evaluation count, population diversity, or model quality.

4. **Does Levenshtein distance on canonical strings provide a useful, semantically meaningful metric for guiding search across a wide range of expression sizes, or does it degenerate for larger DAGs?**  
   *Basis:* Metric proposed and illustrated only on small, hand‑picked examples (Section 4.4).  
   *Unresolved:* Correlation between string distance and expression similarity not validated at scale; neighbourhood redundancy quantified only for one expression.

5. **Can ISALSR be generalized beyond its fixed instruction set to support user‑defined operators, conditionals, multi‑output DAGs, while preserving completeness and efficiency?**  
   *Basis:* Limitations section states the alphabet is fixed; extension requires further investigation.  
   *Unresolved:* Need formal extension of the DAG model and canonicalization algorithm, plus empirical validation for custom functions or conditional structures.

## Limitations
- τ‑pruning may be incomplete; three P3 failures (edges into VAR nodes) show canonicalization not invariant for all DAGs.
- `Normalize_const_creation` isomorphism‑preservation not formally proven.
- Scalability of canonicalization to large DAGs (k > 12) remains unknown; exponential worst‑case behaviour may limit practical use.

## Confidence
- Validity‑by‑construction: **High**
- Commutative encoding: **High**
- Canonical string uniqueness: **Medium** (empirical >99.97% but heuristic lacks proof; P3 failures exist)
- Benchmark metrics (Nguyen/AI Feynman): **High**
- Generalizability to other expression spaces: **Low**

## Next Checks
1. Generate DAGs where a VAR node has ≥2 incoming edges (variable reuse). Test that all permutations of commutative child orderings yield identical canonical strings; expect failures if current method cannot handle such edges.
2. For k=6,8,10, compare pruned canonicalization runtime and results against exhaustive search (feasible up to k=8). Measure any deviation in canonical strings for k=10 to assess pruning completeness at scale.
3. Extend alphabet with a non‑decomposed non‑commutative binary operator (e.g., SUB). Check whether isomorphic DAGs (differing only in operand order) still map to the same canonical string; if not, the method’s reliance on commutative simplification is essential.
