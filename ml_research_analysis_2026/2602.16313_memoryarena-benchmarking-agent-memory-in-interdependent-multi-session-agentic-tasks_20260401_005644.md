# MemoryArena: Benchmarking Agent Memory in Interdependent Multi-Session Agentic Tasks

## Quick Facts
- **arXiv ID**: 2602.16313
- **Source URL**: https://arxiv.org/abs/2602.16313
- **Reference count**: 40
- **Primary result**: State-of-the-art agents with near-saturated performance on existing long-context memory benchmarks achieve low success rates (SR) and progress scores (PS) in MemoryArena, revealing limitations in maintaining and reusing state for long-horizon interdependent tasks.

## Executive Summary
MemoryArena is a new benchmark designed to evaluate agent memory in multi-session tasks where subtasks are interdependent. The benchmark spans four domains—web shopping, group travel planning, progressive web search, and formal reasoning—each requiring agents to distill experiences from earlier sessions into memory to guide later actions. Evaluation of current agents, including large language models with long-context capabilities and external memory/RAG systems, shows consistently low task success rates and a decay in performance as subtask depth increases. External memory provides benefits only in specific domains and at the cost of higher latency. The benchmark highlights a critical gap in current memory mechanisms for long-horizon, interdependent decision-making.

## Method Summary
The benchmark comprises 766 human-curated tasks across four environments. Each task is a sequence of subtasks with explicit causal dependencies (e.g., product compatibility constraints, shared itinerary references). Agents operate within a Memory-Agent-Environment loop: at the start of each subtask they retrieve relevant memories from a store M; they then interact with the environment until the subtask completes; finally, they update M with the trajectory. Memory backends tested include verbatim long-context (using different LLMs), external memory systems (Letta, Mem0, ReasoningBank), and retrieval-augmented generation (BM25, embedding-based, GraphRAG). The primary metrics are Success Rate (SR), Progress Score (PS), SR@k (success after k subtasks to measure decay), and subtask latency. The base agent across all configurations is GPT-5.1-mini.

## Key Results
- SOTA agents perform poorly: average SR remains low (near zero in Group Travel Planning) and decays with subtask depth (SR@k).
- External memory and RAG do not universally beat simple long-context agents; they only improve results in domains with exceptionally long traces (Progressive Web Search, Formal Reasoning) but incur higher latency.
- The benchmark reveals that current memory mechanisms fail to reliably maintain and reuse state for long-horizon interdependent tasks.

## Why This Works (Mechanism)
### Mechanism 1: Interdependent Subtask Design
The design forces agents to use memory across sessions, exposing limitations of current memory mechanisms. Each task consists of ordered subtasks where later steps depend on earlier outcomes (e.g., buying a camera body before selecting a compatible lens). The agent must store information from previous sessions and retrieve it to satisfy constraints. **Core assumption**: Real-world agent tasks often have latent dependencies that persist across sessions; isolating memorization from action fails to test this. **Evidence**: The paper constructs tasks with explicit causal links across four domains; prior work (e.g., TReMu, Mem-Gallery) focuses on conversational recall, not cross-task causal dependence.

### Mechanism 2: Memory-Agent-Environment Loop
This operationalizes memory as a dynamic component integrated with action and environment feedback. For each subtask, the agent retrieves relevant memories, acts, and after completion updates the memory store. This loop repeats across sessions, mimicking persistent memory systems. **Core assumption**: Memory should be evaluated within full interaction cycles, not via static recall tests. **Evidence**: The loop is formalized with RETRIEVE and UPDATE functions; benchmarks like LoCoMo and LongMemEval treat memory as post-hoc QA without environment dynamics, whereas MemoryArena couples memorization and action.

### Mechanism 3: Domain Diversity
Spanning four environments—(1) bundled web shopping (technical compatibility), (2) group travel planning (preference chaining), (3) progressive web search (accumulating constraints), and (4) sequential formal reasoning (dependency chains in proofs)—ensures that memory challenges are general, not domain-specific artifacts. Each domain stresses different memory facets. **Core assumption**: Memory capabilities must generalize; a single domain may miss important failure modes. **Evidence**: MemoryArena provides a multi-domain suite, contrasting with existing single-domain agent benchmarks like WebArena and SWE-Bench.

## Architecture Onboarding
**Component map**: Task Generator → Environment Simulator → Agent Interface → Memory Backend → Evaluator

**Critical path**:
1. Instantiate a task and reset the environment.
2. For each subtask in order:
   a. Retrieve relevant memories → prepend to prompt.
   b. Agent generates actions; environment steps until subtask completion.
   c. Extract trajectory and final state → update memory.
3. After all subtasks, compare final state to ground truth → compute SR/PS.

**Design tradeoffs**:
- Verbatim vs. summarized memory: Verbatim avoids distillation error but scales poorly; external memory adds latency but can compress.
- Retrieval vs. consolidation: RAG offers precise lookup but may miss implicit relations; external memory may abstract away details.
- Latency vs. accuracy: Structured memory (e.g., GraphRAG) often slower; balance needed for real-time use.

**Failure signatures**:
- Low SR with high PS: Agent makes partial progress but fails global integration.
- SR@k decays monotonically: Inability to maintain state across many sessions (belief drift).
- High latency variance: Memory operations become a bottleneck, especially with external systems.
- Near-zero SR in Group Travel Planning: Failure in precise constraint satisfaction over long horizons.

**First 3 experiments**:
1. Baseline replication: Run GPT-5.1-mini + long-context on all four domains to reproduce Table 3 results and verify implementation.
2. Memory mechanism comparison: Test BM25 RAG vs. long-context on Progressive Web Search; expect improved SR and slower decay due to better retrieval of early constraints.
3. Latency profiling: Measure subtask completion time across memory backends; verify external memory incurs higher overhead as in Table 4.

## Open Questions the Paper Calls Out
The paper does not explicitly list open questions. It focuses on introducing the MemoryArena benchmark and evaluating current memory mechanisms. However, the findings and limitations point to several research directions, such as designing memory systems that maintain state over long horizons without drift and reducing the latency overhead of external memory approaches.

## Limitations
- Proprietary model access (GPT-5.1-mini) and underspecified implementations of external memory systems (Mem0, ReasoningBank) may hinder exact replication and affect performance rankings.
- Potential limited public release of the full 766-task suite restricts comprehensive external validation.
- High API costs and rate limits may constrain extensive testing, especially for latency measurements.

## Confidence
- Benchmark design (interdependent multi-session tasks across four domains): High
- SOTA agents perform poorly (low SR, SR@k decay): High
- External memory/RAG not universally superior: Medium
- Current memory mechanisms fail long-horizon tasks: High

## Next Checks
1. Replication: Run the benchmark with released code using a publicly available model (e.g., GPT-4o) to confirm trends of low SR and monotonic decay.
2. Ablation study: Remove interdependencies in one domain to demonstrate the benchmark’s sensitivity to memory requirements.
3. Broadening memory systems: Test newer memory architectures (e.g., MemGPT with different chunking, graph-based) to see if any can achieve SR > 50%, challenging the failure claim.
