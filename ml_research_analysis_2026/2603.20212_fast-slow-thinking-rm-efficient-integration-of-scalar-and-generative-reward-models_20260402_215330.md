# Fast-Slow Thinking RM: Efficient Integration of Scalar and Generative Reward Models

## Quick Facts
- **arXiv ID:** 2603.20212  
- **Source URL:** https://arxiv.org/abs/2603.20212  
- **Reference count:** 21  
- **Primary result:** F/S-RM achieves a 1.2% relative improvement over state-of-the-art reward models while reducing token consumption by 20.8% on RewardBench, RM-Bench, and JudgeBench.

## Executive Summary
Reward models for reinforcement learning from human feedback (RLHF) face a fundamental trade‑off: scalar reward models (SRMs) are computationally efficient but lack nuanced judgment, while generative reward models (GRMs) produce accurate, chain‑of‑thought (CoT) critiques at high computational cost. This paper introduces Fast‑Slow Thinking Reward Models (F/S‑RM), a hybrid architecture that unifies both paradigms in a single model. The system produces an immediate scalar decision via first‑token prediction and conditionally engages in slow, generative reasoning when a dual‑confidence mechanism indicates uncertainty. Trained in two stages—supervised fine‑tuning for fast thinking and reinforcement learning for slow thinking—F/S‑RM attains a 1.2% relative accuracy gain over prior art while cutting token usage by 20.8% across three major benchmarks.

## Method Summary
F/S‑RM is trained on a merged dataset of 20 K preference pairs drawn from skywork‑single, Code‑Preference‑Pairs, and Math‑DPO‑10K. The training pipeline has two stages. First, a supervised fine‑tuning (SFT) phase teaches the model fast thinking: given a prompt and two responses, it predicts the preferred choice (A or B) from the first generated token. The loss combines a Bradley‑Terry pairwise loss with an action‑space constraint penalty that forces probability mass onto {A, B}. Second, a reinforcement learning (RL) stage (GRPO) refines slow thinking. The model is prompted with an additional “tie” token and generates a CoT before outputting a final label. Rewards consist of a format penalty (−1 for invalid format) and a binary outcome reward (+1 for correct final label). At inference, the model computes two confidence metrics: intuition confidence (CI = |P(A)−P(B)|) and token confidence (CT = mean(−log P(v)) for non‑A/B tokens v). If both fall below thresholds (set to the mean of correctly predicted training samples), slow mode is triggered; otherwise, the first token is used directly.

## Key Results
- 1.2% relative accuracy improvement over state‑of‑the‑art reward models on RewardBench, RM‑Bench, and JudgeBench.
- 20.8% reduction in average token consumption per query via conditional slow‑mode activation.
- The hybrid approach maintains competitive accuracy while significantly lowering inference cost.

## Why This Works (Mechanism)
The hybrid design exploits the observation that many preference queries can be resolved from the model’s initial “intuition” encoded in the first token. Fast mode thus offers extreme efficiency. Slow mode is reserved for ambiguous cases where both the intuition confidence (CI) and token confidence (CT) are low—signaling that the model’s immediate judgment is unreliable and that the distribution over other tokens is diffuse. By training fast mode with a constrained Bradley‑Terry loss, the model learns to project its decision onto the first token reliably. RL then enhances slow‑mode reasoning using outcome‑based rewards, ensuring that when CoT is generated, it leads to correct final labels. The dual‑confidence trigger dynamically balances speed and accuracy, avoiding unnecessary CoT generation while summoning it when needed.

## Architecture Onboarding
**Component map:**  
Input → Base Model (shared) → Confidence Metrics (CI, CT) → Threshold Check → [Fast Path: first token → Label] / [Slow Path: generate “tie” + CoT → Label]

**Critical path:**  
1. Forward pass through base model yields logits over vocabulary.  
2. Compute CI = |P(A)−P(B)| from first‑token probabilities.  
3. Compute CT = mean(−log P(v)) for v in vocabulary \ {A, B}.  
4. If CI < τI and CT < τT, engage slow mode: append “tie” token, autoregressively generate CoT until a valid final label (A/B) appears.  
5. Else, read the first generated token (A or B) as the decision.

**Design tradeoffs:**  
- *Speed vs. accuracy:* Fast mode is O(1) token; slow mode is O(N) tokens. Thresholds directly control this trade‑off.  
- *Threshold calibration:* Fixed thresholds (means from correct samples) risk overfitting; domain‑specific tuning may be necessary.  
- *Training complexity:* Two‑stage pipeline (SFT then RL) avoids action‑space collapse but increases implementation overhead.  
- *Parameter sharing:* Efficient but may cause catastrophic forgetting of fast mode during RL.

**Failure signatures:**  
- *Action space collapse:* Model drifts from outputting A/B in fast mode; monitor π(A)+π(B) < 0.95.  
- *Slow‑mode reward hacking:* Model emits “tie” without meaningful CoT or violates format; track format reward violations.  
- *Catastrophic forgetting:* Fast‑mode accuracy degrades after RL; compare pre‑ and post‑RL fast performance.  
- *Threshold mismatch:* Excessive slow activations (token savings <10%) or accuracy drop >2% indicate poorly set thresholds.

**First three experiments:**  
1. *Baseline fast mode:* Train only SFT stage; evaluate accuracy and token usage without slow mode. Confirm first‑token reliability.  
2. *Slow mode isolation:* Initialize from fast checkpoint, force slow mode on all inputs, measure accuracy and average CoT length. Validate RL improvement.  
3. *Threshold sweep:* Run hybrid with varying τI and τI on a validation split; plot accuracy vs. token savings. Compare to paper’s mean thresholds and identify optimal settings.

## Open Questions the Paper Calls Out
1. **Scaling to larger models**  
   *Basis:* Limitations explicitly note validation on larger models (e.g., 32B, 70B) as future work.  
   *Why unresolved:* Confidence thresholds and inference dynamics may differ at scale.  
   *Evidence needed:* Train and evaluate F/S‑RM on Qwen3‑32B and Llama3.3‑70B across standard benchmarks, measuring accuracy and token savings.

2. **Less biased benchmarks**  
   *Basis:* Limitations state current benchmarks involve LLM participation, introducing model‑specific biases.  
   *Why unresolved:* LLM‑biased benchmarks may not reflect true human preferences, leading to misleading rankings.  
   *Evidence needed:* Conduct large‑scale human evaluations, develop new human‑annotated benchmarks, and test whether performance correlations shift.

3. **Adaptive or learned thresholds**  
   *Basis:* Paper sets static thresholds (means of CI/CT on correct samples) without exploring alternatives.  
   *Why unresolved:* Fixed thresholds may be suboptimal across domains and model scales.  
   *Evidence needed:* Optimize thresholds on a validation set or train a lightweight classifier to predict slow‑thinking need; compare hybrid results against baseline at matched token budgets.

4. **Two‑stage training necessity**  
   *Basis:* Paper justifies SFT+RL to avoid action‑space collapse on length‑imbalanced data.  
   *Why unresolved:* End‑to‑end training might simplify the pipeline if stability can be maintained.  
   *Evidence needed:* Implement joint training with multi‑task losses or KL regularization; measure training stability, final accuracy, and token savings vs. staged approach.

## Limitations
- Ambiguous data sampling: exact parent dataset sizes, merging strategy, and random‑sampling process are not described.  
- Unspecified prompt differences between SFT and RL stages (e.g., inclusion of CoT examples, format specifications).  
- Token confidence (CT) computation details unclear: vocabulary definition, handling of special tokens, and pre/post‑softmax application.

## Confidence
- Hybrid fast‑slow architecture: **High**  
- Dual‑confidence activation mechanism: **Medium**  
- Two‑stage training (SFT + RL): **Medium**  
- Reported performance improvements (1.2% gain, 20.8% token reduction): **Medium**
