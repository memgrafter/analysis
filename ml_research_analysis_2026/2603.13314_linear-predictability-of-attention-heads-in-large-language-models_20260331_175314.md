# Linear Predictability of Attention Heads in Large Language Models
## Quick Facts
- arXiv ID: 2603.13314
- Source URL: https://arxiv.org/abs/2603.13314
- Reference count: 40
- Primary result: Attention head activations (Q/K/V) are linearly predictable from a small set of peer heads; this enables 2× KV cache compression with modest accuracy trade-offs (4.5–5.5 pp drop on Falcon3-10B and Qwen3-32B, larger on Llama3.1-8B).

## Executive Summary
Large language models face a memory bottleneck during inference due to the key‑value (KV) cache. This paper discovers that attention head activations exhibit strong linear predictability: a target head’s queries, keys, or values can be accurately reconstructed from just a few (2–5) reference heads using simple linear maps. Across multiple models, the mean coefficient of determination (R²) for key reconstruction reaches ~0.76 on C4 and >0.85 on GSM8K. Keys are far more predictable than values, and the predictability emerges during pretraining alongside increasing alignment of key projection subspaces within layers. By caching only reference‑head states and reconstructing others on the fly, the authors achieve 2× memory reduction with predictable accuracy drops (e.g., 4.5–5.5 percentage points on Falcon3-10B and Qwen3-32B, but 9.9 pp on Llama3.1-8B).

## Method Summary
The authors first collect K/V activations from all attention heads across layers on a calibration set (a 1–5% slice of C4). For every feasible head pair (target, reference), they fit an ordinary least squares (OLS) regression (no intercept) and compute the R² of reconstruction. From these pairwise scores they build a directed graph and apply a threshold‑based greedy selection (Algorithm 1) to designate a minimal set of reference heads such that each target has at least *m* (e.g., 5) high‑predictability references. Then, for each target, they train a multivariate linear map using activations from its selected references. During inference, the KV cache stores states only for reference heads; for any target head, its KV is reconstructed on‑the‑fly by applying the learned linear map to the cached reference KV states of the current token. The approach is evaluated on several pretrained models (Llama, Falcon, Qwen, OLMo) and multiple downstream tasks, measuring both memory reduction and accuracy.

## Key Results
- Linear predictability is high: using 2–5 reference heads yields mean R² ≈ 0.76 for keys on C4 and > 0.85 on GSM8K; values are less predictable.
- KV cache compression of 2× memory reduction incurs an average accuracy drop of 4.5–5.5 percentage points on Falcon3-10B and Qwen3-32B, but a larger drop (9.9 pp) on Llama3.1-8B.
- Reconstructing keys is substantially less harmful than reconstructing values (e.g., ~2 pp vs. ~4.3 pp drop), indicating asymmetric alignment of projection subspaces.

## Why This Works (Mechanism)
### Mechanism 1: Subspace Alignment during Pretraining
Claim: Linear predictability emerges because pretraining aligns the column subspaces of Key projection matrices within each layer, creating a shared low‑rank manifold. Gradient updates drive the Key projection matrices of different heads toward overlapping column spaces, reducing principal angles between subspaces. As a result, one head’s Key activations become a low‑error linear combination of others. Core assumption: Optimization implicitly regularizes toward redundancy to improve generalization or efficiency. Evidence: Overlap dimension (ODH) increases monotonically during training, paralleling the rise in intra‑layer linear predictability; the paper’s abstract notes that predictability is learned and largely absent at initialization. Break condition: If subspace alignment plateaus or reverses, predictability gains would stagnate or degrade; this is observed only in inter‑layer links, not intra‑layer.

### Mechanism 2: Orthogonality at Random Initialization
Claim: Random initialization yields near‑zero linear predictability because independently drawn projection matrices have nearly orthogonal column spaces with high probability. Mechanism: Theorem 3.1 provides a lower bound on mean‑squared error for linear prediction when projection matrices have i.i.d. Gaussian (or sub‑Gaussian) entries; the bound scales as Ω(d_hm), showing inherently large reconstruction error without learned alignment. Core assumption: Standard initialization schemes (e.g., Xavier) are effectively sub‑Gaussian. Evidence: At initialization, average R² is < 0.05 and only < 5% of head pairs exceed R²=0.10; the theoretical lower bound matches this empirical level. Break condition: If initialization schemes deliberately correlate projection matrices, the bound would fail, but current standards do not.

### Mechanism 3: Asymmetric Subspace Growth (Keys vs. Values)
Claim: Key projection subspaces align substantially during pretraining, while Value subspaces remain largely orthogonal. This asymmetry explains why reconstructing Keys hurts accuracy far less than reconstructing Values. Mechanism: Linear maps between aligned subspaces are well‑conditioned and generalize across tasks, whereas orthogonal Value subspaces retain task‑specific structure that a single linear map cannot capture without large error. Core assumption: Aligned Key subspaces encode domain‑agnostic patterns; Values are more task‑specific. Evidence: Overlap dimension rises steeply for Keys but stays near zero for Values; empirical results show Key‑only compression drops accuracy by ~2 pp vs. ~4.3 pp for Value‑only. Break condition: If Value subspaces became as aligned as Keys in some models, Value compression would become less harmful – not observed across Llama, Falcon, Qwen, OLMo.

## Foundational Learning
- **Subspace alignment and overlap dimension (ODH)**: Quantifies the intersection of column spaces of projection matrices. Needed because higher ODH indicates more shared basis directions, enabling linear predictability. Quick check: If two projection matrices have nearly identical column spaces, their pseudoinverse product *A†B* should be well‑conditioned with small singular values.
- **R² from multivariate OLS regression**: Measures the fraction of variance in a target head’s activations explained by reference heads. Needed to guide reference selection and assess compression fidelity. Quick check: If adding more reference heads yields diminishing R² increases, the intrinsic dimensionality of the target’s activation span is being saturated.
- **KV cache and autoregressive decoding memory bottleneck**: The KV cache stores past key/value states for all attention heads to enable efficient attention during generation; its size grows linearly with sequence length and number of heads, becoming a memory bottleneck. Needed because the paper’s compression strategy directly targets this component. Quick check: In autoregressive decoding, why must all previous KV states be retained? (Answer: Each new token attends to all prior tokens; recomputing is prohibitively expensive.)

## Architecture Onboarding
**Component map**:  
Pretrained LLM → Calibration dataset → activation collection → Pairwise regression module → Graph construction → Reference selection (Algorithm 1) → Linear projector storage → Modified inference engine (cache reference KV only; on‑the‑fly reconstruction for targets).

**Critical path**:
1. Calibration: Run forward passes on a held‑out dataset (e.g., C4 slice) to log all head K/V activations.
2. Pairwise analysis: For every ordered head pair (target, reference) with layer(target) ≥ layer(reference), fit OLS regression (no intercept) and compute R².
3. Reference selection: Perform binary search on a threshold τ to ensure each target has at least *m* candidate references; then greedily select a minimal set of targets to become references such that remaining targets have ≥ *m* non‑target parents.
4. Train final linear maps: For each target head, fit a multivariate OLS model using its top‑*m* references from the pruned graph.
5. Deploy: Replace KV cache storage for target heads with stored reference KV states plus the linear weights; during generation, reconstruct target KV via matrix multiplication with the weights.

**Design tradeoffs**:
- Reference count per target (*m*): Smaller *m* reduces stored weight size but may lead to underdetermined systems; the paper uses *m*=5.
- Calibration data diversity: Must cover the task distribution; narrow calibration leads to overfitted projectors and poor generalization.
- Head partitioning: Algorithm 1 aims to maximize the fraction of predictable heads while minimizing references; the greedy choice may not be globally optimal.
- Key vs. Value reconstruction: The asymmetry allows more aggressive Key compression; hybrid schemes might compress both but with tighter budgets on Values.

**Failure signatures**:
- Low pairwise R² (< 0.3) for a target with all potential references → that head will likely reconstruct poorly; it should be kept as a reference.
- High condition number of reference activation covariance matrix → numerical instability in OLS; consider regularization.
- Large drop in R² between calibration and held‑out validation set → overfitting; may require more diverse calibration or ridge regression.
- Disproportionate accuracy drop on certain models (e.g., Llama3.1-8B) suggests model‑specific predictability distribution; verify coverage per layer.

**First 3 experiments** (reproduction sanity checks):
1. **Baseline predictability profiling**: On a small calibration set (e.g., 1% C4), compute pairwise R² across head pairs. Confirm that ~75% of pairs have R² > 0.5 as reported; otherwise compression will be ineffective.
2. **Random initialization sanity check**: Load model checkpoints at initialization and after minimal training; measure average R². It should jump from ~0.05 to >0.5, verifying that predictability is learned, not present at start.
3. **Single‑head ablation test**: For a chosen target head, reconstruct using its top‑3 references token‑wise. Compute reconstruction error distribution; it should be approximately zero‑mean Gaussian with moderate variance. Large bias or heavy tails indicate poor linear fit.

## Open Questions the Paper Calls Out
- What specific pretraining dynamics and architectural factors drive the alignment of key projection subspaces across heads? (The paper establishes a correlation but not causality.)
- Can nonlinear or adaptive reconstruction methods (e.g., MLPs, dynamic reference selection) improve KV cache compression fidelity, especially for models with larger accuracy drops?
- What are the exact causal mechanisms by which linear predictability emerges from random initialization during pretraining? (No explanation of why gradient updates induce alignment.)
- Does the theoretical lower bound on prediction error extend to deeper layers, and how does it relate to the observed dominance of intra‑layer over inter‑layer links? (Current proof only for first layer under Gaussian inputs.)

## Limitations
- Algorithmic details for reference selection (threshold τ convergence, minimum incoming edges *m*) are not fully specified, hindering exact replication.
- Calibration protocol (exact token count, sequence truncation, preprocessing) is ambiguous, risking mismatched activation distributions and reproducibility issues.
- The causal link between subspace alignment and linear predictability is inferential; no intervention experiments confirm that alignment drives predictability rather than co‑occurring.

## Confidence
- Subspace alignment emergence: Medium
- Initialization orthogonality: High
- Key/Value asymmetry: Medium

## Next Checks
1. **Causal subspace intervention**: During pretraining, add a regularization term that penalizes subspace alignment between Key projections. Predictability (R²) should fail to rise if alignment is causal.
2. **Initialization robustness test**: Initialize a model with correlated Gaussian projection matrices (e.g., shared column space) and measure R² at step 0. A higher baseline would confirm the orthogonality hypothesis.
3. **Cross‑model transfer test**: Train reference sets and linear projectors on one model (e.g., Falcon3‑10B) using C4, then apply them directly to a different model (e.g., Llama3.1‑8B) without recalibration. Failure to reconstruct would indicate model‑specific learned structure and limited generalizability.
