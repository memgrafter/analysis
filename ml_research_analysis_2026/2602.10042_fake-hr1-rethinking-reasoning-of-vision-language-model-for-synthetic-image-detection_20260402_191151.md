# Fake-HR1: Rethinking Reasoning of Vision Language Model for Synthetic Image Detection

## Quick Facts
- **ArXiv ID**: 2602.10042
- **Source URL**: https://arxiv.org/abs/2602.10042
- **Reference count**: 0
- **Primary result**: First hybrid‑reasoning model that *adaptively* decides whether to generate reasoning chains; on FakeClue it achieves ~86% accuracy on both easy and hard queries and reduces token length by ~30× on easy cases.

## Executive Summary
Synthetic image detection benefits from interpretable step‑by‑step reasoning, but always requiring such reasoning is inefficient for simple queries. Fake‑HR1 introduces a hybrid reasoning framework that learns when to reason and when to answer directly. The two‑stage pipeline first performs Hybrid Fine‑Tuning (HFT) on dual‑mode data (reasoning vs. non‑reasoning) to initialize both capabilities. Then Hybrid‑Reasoning Grouped Policy Optimization (HGRPO), a reinforcement learning method with a composite reward, teaches the model to select the appropriate output mode. On the FakeClue benchmark, Fake‑HR1 attains 86.92% accuracy (87.12 F1) on easy queries and 85.96% accuracy (86.71 F1) on hard queries, far surpassing several strong baseline models. For easy queries the average output length is only ~23 tokens versus ~700 tokens for always‑reasoning models.

## Method Summary
Fake‑HR1 builds on a vision‑language architecture: an image is processed by a visual encoder (from Qwen2.5‑VL‑7B), its features are aligned to the LLM embedding space via an MLP adapter, and the LLM backbone generates text. Training proceeds in two phases.  
**HFT** constructs a mixed dataset: GenImage samples paired with *simple* seed questions yield non‑reasoning examples (format `answer`); FakeClue samples paired with *hard* seed questions yield reasoning examples (format `thinkanswer`). The model is fine‑tuned (AdamW, 1 epoch, lr=1e‑6) to produce both formats.  
**HGRPO** then refines the policy using reinforcement learning. For each training sample, G responses are sampled. A composite reward `R = 0.8·R_acc + 0.1·R_format + 0.1·R_hyb` is computed, where `R_acc` rewards correct answer (after stripping think tags), `R_format` rewards strict structural compliance, and `R_hyb` rewards mode alignment with difficulty (simple → no reasoning; hard → reasoning). Group‑relative advantages (mean/std across the G samples) drive a PPO‑style update with a KL penalty against the SFT model. After 3 epochs (batch 32, lr 1e‑6) the policy adaptively selects the output mode per input.

## Key Results
- **Easy queries**: 86.92% accuracy, 87.12 F1; ~23 tokens/output.
- **Hard queries**: 85.96% accuracy, 86.71 F1.
- Outperforms GPT‑4o (47.40/42.00), Qwen2.5‑VL‑7B (35.40/29.50), and InternVL3‑8B (55.84/59.24).

## Why This Works (Mechanism)

### Dual‑Mode Cold‑Start via Hybrid Fine‑Tuning (HFT)
- **Claim**: HFT equips the model with competent reasoning and non‑reasoning capabilities *without* manual annotation.
- **Mechanism**: Existing datasets are partitioned using (i) a data‑oriented heuristic (e.g., FakeClue already contains reasoning outputs) and (ii) a query‑oriented heuristic: two seed question banks (simple vs. complex) label samples from GenImage (non‑reasoning) and FakeClue (reasoning). The resulting dual‑mode data is used for supervised fine‑tuning.
- **Evidence**: [abstract] “dual‑mode data strategy… avoiding the need for costly manual annotation.” [§2.1] “systematically partitions existing datasets into reasoning and non‑reasoning subsets… based on query complexity, we construct two seed question banks.”

### Adaptive Reasoning via Hybrid‑Thinking Reward in HGRPO
- **Claim**: The hybrid‑thinking reward incentivizes correct mode selection, balancing accuracy and efficiency.
- **Mechanism**: During RL, each sample’s reward includes `R_hyb` (1 if mode matches difficulty, else 0). The composite reward `R = 0.8·R_acc + 0.1·R_format + 0.1·R_hyb` is computed for multiple responses; group‑relative advantages encourage exploring both modes while aligning with the hybrid objective.
- **Evidence**: [§2.2] “Hybrid‑Thinking Reward: When the input comes from the simple seed bank, omitting reasoning yields a reward of 1… combine the three rewards: R = 0.8·R_acc + 0.1·R_format + 0.1·R_hyb.”

### Mode Stabilization via Group‑Based Advantage Estimation
- **Claim**: GRPO stabilizes hybrid‑reasoning learning by normalizing advantages within sampled groups, preventing mode collapse.
- **Mechanism**: For each input, G responses are sampled; advantage `A_i = (r_i - mean({r_j})) / std({r_j})` creates a baseline that compares responses across modes, encouraging the policy to favor the mode with higher relative reward within the group.
- **Evidence**: [abstract] “online reinforcement learning with Hybrid‑Reasoning Grouped Policy Optimization (HGRPO)… implicitly learn when to select an appropriate reasoning mode.” [§2.2] Equation 2 defines group‑normalized advantage; “GRPO eliminates the critic network and instead estimates the baseline through group averaging.”

## Foundational Learning
- **Chain‑of‑Thought (CoT) Reasoning**  
  *Why needed*: CoT provides interpretable step‑by‑step justifications, crucial when artifacts are subtle.  
  *Quick check*: What is the primary risk of always using CoT for synthetic image detection?

- **Reinforcement Learning from Group Relative Advantages (GRPO)**  
  *Why needed*: Supervised fine‑tuning cannot teach *when* to reason. GRPO uses outcome‑based rewards to implicitly learn adaptive mode selection without a critic.  
  *Quick check*: How does GRPO’s group‑normalized advantage differ from a standard PPO clipped objective in encouraging mode exploration?

- **Dual‑Mode Data Curation via Seed Banks**  
  *Why needed*: To bootstrap both reasoning and non‑reasoning capabilities without manual annotation, the paper uses the assumption that query complexity predicts reasoning necessity.  
  *Quick check*: Why might using a fixed seed question bank for labeling data introduce bias into the model’s learning of adaptive reasoning?

## Architecture Onboarding
- **Component map**:  
  Visual Encoder → MLP adapter → LLM backbone.

- **Critical path**: Input (image + query) → Visual Encoder → Visual features → MLP → LLM generates response with optional `think` block.  
  **Training**: HFT (supervised on dual‑mode data) → HGRPO (RL with group‑relative rewards and KL penalty).

- **Design tradeoffs**:  
  – Reward weights (0.8/0.1/0.1) prioritize accuracy; stronger `R_hyb` may improve adaptation but could hurt accuracy.  
  – Fixed seed banks simplify labeling but limit difficulty coverage; online generation could increase adaptability.

- **Failure signatures**:  
  – *Reasoning degeneration*: Model defaults to non‑reasoning on hard queries.  
  – *Mode collapse*: Model always produces reasoning.  
  – *Poor generalization*: High accuracy on training distribution but low on new generative models.

- **First three experiments**:  
  1. **HFT replication**: Train on combined GenImage (simple queries) and FakeClue (hard queries); verify dual‑mode capability (≈23 tokens for simple, ≈700 for hard).  
  2. **HGRPO ablation**: Vary `R_hyb` weight (0, 0.05, 0.1, 0.2); measure reasoning proportion on simple vs. hard queries; expect adaptive switching only at non‑zero weight.  
  3. **Efficiency‑accuracy tradeoff**: Compare Fake‑HR1 against always‑reasoning baseline on FakeClue test; plot token length vs. accuracy per difficulty; expect cluster at low‑token/high‑accuracy for easy queries and high‑token/high‑accuracy for hard queries.

## Open Questions the Paper Calls Out
1. What learning objective best balances accuracy, interpretability, and efficiency for large reasoning models in synthetic content detection?
2. Can the hybrid reasoning framework be effectively extended to synthetic text and video detection tasks?
3. Does using an online, large‑model‑generated seed question set improve the adaptability of hybrid reasoning models compared to a fixed seed set?
4. How well does Fake‑HR1 generalize to synthetic images from unseen generative models?

## Limitations
- HGRPO hyperparameters (group size G, KL coefficient β, clip range ε) are not specified.
- The method for assigning test queries to “easy” vs. “hard” subsets is ambiguous; only seed question banks are described.
- Generalization is evaluated only on FakeClue; cross‑generator robustness remains untested.

## Confidence
- **Hybrid adaptive reasoning** – *Medium* (novel but builds on existing hybrid‑reasoning ideas).  
- **Reported performance numbers** – *Medium* (details missing, replication plausible but not guaranteed).  
- **Efficiency gains** – *Medium* (token reduction mechanically straightforward, exact magnitude implementation‑dependent).
