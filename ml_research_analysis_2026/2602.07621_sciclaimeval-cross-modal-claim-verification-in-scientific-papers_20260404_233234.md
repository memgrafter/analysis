# SciClaimEval: Cross-modal Claim Verification in Scientific Papers
## Quick Facts
- arXiv ID: 2602.07621
- Source URL: https://arxiv.org/abs/2602.07621
- Reference count: 0
- Primary result: Introduces a scientific claim verification dataset with authentic claims and refuted examples created by modifying evidence; best model (o4-mini) achieves 79.1 macro-F1 on figure verification, trailing human baseline of 89.6.

## Executive Summary
SciClaimEval addresses the task of cross-modal scientific claim verification. It presents a dataset derived from published papers where claims are paired with supporting evidence (figures or tables) and refuted counterparts generated by altering the evidence while preserving the claim. The evaluation of eleven multimodal models reveals that figure-based verification is particularly challenging, with top model performance significantly below human levels. Table verification is somewhat easier, yet still shows a gap. The study also introduces Pair Accuracy as a stricter metric that uncovers brittleness in model predictions.

## Method Summary
The task is binary classification: given a claim and associated evidence (figure image or table in various formats), determine if the evidence *Supports* or *Refutes* the claim. Each sample includes the evidence caption and optional context (preceding sentences or full paper). The dataset spans three domains (NLP, ML, Medicine) from ~180 papers. The authors evaluate eleven multimodal foundation models in a zero-shot setting using Chain-of-Thought prompting. Two conditions are tested: without context (claim+evidence only) and with context as required. Primary metric is macro-F1; a secondary stricter metric is Pair Accuracy, which requires both a supported and its corresponding refuted sample (created by modifying the same evidence) to be classified correctly. No fine-tuning is performed; all models are used as pre-trained.

## Key Results
- Figure verification: top model o4-mini scores 79.1 macro-F1; human baseline 89.6.
- Table verification: o4-mini achieves 82.9 macro-F1; human baseline 87.9.
- Pair Accuracy is consistently lower than macro-F1, indicating models struggle to correctly label both samples in a claim-evidence pair simultaneously.

## Why This Works (Mechanism)
The design of SciClaimEval effectively probes multimodal models' cross-modal reasoning abilities in scientific contexts through:
- **Authentic claims and evidence**: Using real claims from published papers and generating refuted examples by minimally modifying the evidence (e.g., swapping graph elements, altering table values) ensures the task reflects genuine scientific verification while maintaining controlled experimental conditions.
- **Zero-shot Chain-of-Thought prompting**: This elicits step-by-step reasoning without task-specific fine-tuning, allowing assessment of the model's inherent capabilities and providing interpretable outputs.
- **Rigorous evaluation metrics**: Macro-F1 measures overall performance, while Pair Accuracy evaluates consistency across minimally perturbed claim-evidence pairs, exposing model brittleness.
Together, these elements create a challenging benchmark that reveals significant gaps between current models and human performance, highlighting areas for future improvement.

## Foundational Learning
- **Multimodal Fusion**: Needed to integrate information from images/figures and text (claims, captions). *Quick check*: Can the model answer a claim that requires reading a table image and its caption?
- **Zero-shot Chain-of-Thought (CoT)**: Enables reasoning without training on the task, probing the model's innate problem-solving. *Quick check*: Does explicit step-by-step prompting improve consistency on scientific claims?
- **Cross-modal Alignment**: Aligning visual and textual embeddings is crucial for matching claim semantics to evidence. *Quick check*: Are image and text features mapped into a shared space where similarity reflects relevance?
- **Pair Accuracy**: A stricter metric that measures robustness to minimal evidence changes. *Quick check*: If a claim and its refuted pair are both misclassified, does the model show sensitivity to small perturbations?
- **Scientific Claim Verification**: Evaluates real-world applicability in high-stakes research contexts. *Quick check*: Can models detect subtle statistical distortions in published figures?

## Architecture Onboarding
Component map: Claim + Evidence + Caption + Context -> Zero-shot CoT Prompt -> Multimodal LLM -> Predicted Label -> Evaluation (macro-F1, Pair Accuracy)

Critical path: 1) Obtain test samples from the dataset; 2) For each sample, format the evidence (convert table to appropriate representation if needed); 3) Construct the prompt according to context usage flag; 4) Run inference with the multimodal model; 5) Parse output to obtain label; 6) Group predictions by claim ID; 7) Compute macro-F1 and Pair Accuracy.

Design tradeoffs: 
- Image vs text representation for tables: PNG preserves visual layout but loses structural semantics; LaTeX/HTML/JSON provide structure but may be poorly rendered by text-only models and include conversion errors.
- Including context may provide necessary background but risks noise and length exceeding model limits.
- Zero-shot evaluation ensures generality but may underperform compared to fine-tuned models; the paper prioritizes assessing base capabilities.

Failure signatures: 
- Low macro-F1 on figure samples, especially for operations like `Graph Swap` and `Category Swap`.
- Significant drop in Pair Accuracy relative to macro-F1, indicating instability to minor evidence changes.
- Performance variance across table formats, with JSON (error-prone) often underperforming.

## Limitations
- The exact zero-shot CoT prompt template and the mapping of context usage per sample are not released, making exact replication impossible.
- The dataset contains JSON table conversions with 19 major errors per 100 samples, and these errors are not corrected in the provided data.
- Critical model inference details (e.g., resolution, API specifics, rate limits for o4-mini; handling of different table formats for open-source models) are omitted.
