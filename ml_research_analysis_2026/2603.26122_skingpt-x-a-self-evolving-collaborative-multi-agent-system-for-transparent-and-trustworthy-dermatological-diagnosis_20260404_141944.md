# SkinGPT-X: A Self-Evolving Collaborative Multi-Agent System for Transparent and Trustworthy Dermatological Diagnosis

## Quick Facts
- **arXiv ID:** 2603.26122  
- **Source URL:** https://arxiv.org/abs/2603.26122  
- **Reference count:** 40  
- **Primary result:** SkinGPT-X achieves state-of-the-art performance, with +9.6% accuracy improvement on DDI31 and +13% weighted F1 gain on Dermnet versus prior models.

## Executive Summary
SkinGPT-X introduces a collaborative multi-agent system with a self-evolving memory mechanism (EvoDerma-Mem) to address limitations of monolithic LLMs in fine-grained and rare skin disease diagnosis. The system simulates clinical workflows, combining visual analysis, evidence-based RAG, and cross-verification against dynamically updated historical cases and diagnostic guidelines. Evaluated on multiple public datasets and new benchmarks (Dermnet498, RSDD), SkinGPT-X shows substantial improvements over prior models, demonstrating the value of modular, transparent, and continuously learning AI in dermatology.

## Method Summary
SkinGPT-X employs a multi-agent architecture where specialized agents handle distinct diagnostic subtasks: a Vision Agent (Qwen3‑VL) extracts visual findings from the input image; a Disease Diagnosis Agent (fine‑tuned PanDerm) proposes a ranked list of candidate diseases; a RAG module retrieves canonical textbook criteria from the Skin Handbook for each candidate; an EvoDerma‑Mem graph database stores historical cases and evolves disease-specific guidelines via a Summarization Agent; and a Case‑Review Agent (Qwen3‑A30) synthesizes all evidence through a five-stage cross‑verification protocol to produce a final diagnosis and report. The self‑evolving memory mechanism allows continuous knowledge accumulation without full model retraining, adapting to rare or fine‑grained diseases by integrating new cases and updating guidelines when a threshold of new data is reached.

## Key Results
- On DDI31, SkinGPT‑X achieves a +9.6% accuracy improvement over prior models.  
- On Dermnet, it achieves a +13% weighted F1 gain.  
- On the fine‑grained Dermnet498 benchmark (498 classes), it outperforms the fine‑tuned PanDerm baseline by +5.4% in accuracy.  
- On the Rare Skin Disease Dataset (RSDD, 8 classes), it shows a +9.8% accuracy improvement.  
- Ablation studies confirm that removing the EvoDerma‑Mem mechanism causes significant drops across accuracy, weighted F1, MCC, and Cohen’s Kappa on all datasets.

## Why This Works (Mechanism)
### Mechanism 1: Collaborative Multi‑Agent Diagnostic Pipeline
The system distributes the diagnostic task across specialized agents, each handling a distinct subproblem: Vision Agent extracts objective morphological descriptors; Disease Diagnosis Agent produces a ranked candidate list; RAG module retrieves canonical textbook standards; Case‑Review Agent synthesizes evidence and produces the final report; Summarization Agent updates memory. This decomposition reduces error propagation and allows each component to be optimized independently. Evidence: [abstract] and [section 2.1] describe the multi‑agent collaboration. Break condition: If the Vision Agent omits a critical feature or the Disease Diagnosis Agent’s top‑5 list excludes the ground‑truth label, downstream recovery may fail.

### Mechanism 2: Self‑Evolving Memory (EvoDerma‑Mem)
Historical cases are stored as (embedding, key findings, diagnosis) triplets in a graph database. When the number of newly added cases exceeds a threshold, the Summarization Agent synthesizes updated diagnostic guidelines by integrating new findings with existing ones. During inference, the system retrieves visually similar cases and the latest guidelines to augment reasoning. This enables continuous improvement without retraining, especially for rare or fine‑grained diseases. Evidence: [abstract] and [section 4.3] detail the case representation and knowledge synthesis. Ablation studies [section 2.5] show that removing EvoDerma‑Mem causes statistically significant drops (e.g., ACC –10.1% on Dermnet498). Break condition: Poor embedding similarity or summarization errors could degrade guidelines.

### Mechanism 3: Knowledge‑Guided Cross‑Verification
For each candidate disease, the system anchors predictions in static textbook knowledge (RAG) and cross‑references with dynamically evolved guidelines and historical cases. The Case‑Review Agent executes a five‑stage protocol (visual validation, canonical cross‑check, empirical alignment, conflict resolution, final determination) to produce the output. This combination of static standards and adaptive experience yields robust consensus and reduces hallucination. Evidence: [section 4.4.2] and [section 4.4.3] describe the RAG and cross‑check stages. Ablation (Figure 5a) shows that using only RAG (no memory) reduces metrics significantly. Break condition: Outdated textbooks or overfitted guidelines could lead to erroneous decisions if conflicts cannot be adjudicated.

## Architecture Onboarding
### Component map
Vision Agent (Qwen3‑VL) -> Disease Diagnosis Agent (PanDerm fine‑tuned) -> RAG module (Skin Handbook) -> Case‑Review Agent (Qwen3‑A30) + EvoDerma‑Mem -> final diagnosis. Summarization Agent (offline) updates EvoDerma‑Mem.

### Critical path (inference)
1. Input image I -> Vision Agent -> P_vis.  
2. I -> Disease Diagnosis Agent -> D_pre (top‑5 candidates).  
3. For each candidate in D_pre: Retrieve from Skin Handbook -> K_prior.  
4. Compute image embedding; query EvoDerma‑Mem -> K_hist (top‑5 similar cases) and retrieve G_evo for candidates.  
5. Case‑Review Agent synthesizes P_vis, D_pre, K_prior, K_hist, G_evo -> final diagnosis D* and report R*.  
6. Summarization Agent periodically updates guidelines in EvoDerma‑Mem.

### Design tradeoffs
- **Accuracy vs. latency:** Multi‑agent orchestration increases inference time; parallelization mitigates but not eliminate overhead.  
- **Memory size vs. retrieval quality:** More cases improve rare disease coverage but increase cost and risk of irrelevant retrieval.  
- **Static vs. dynamic knowledge:** RAG provides reliable baselines but may become outdated; EvoDerma‑Mem adapts but can accumulate noise.  
- **Model choice:** Proprietary Qwen models ensure capability but hinder reproducibility and increase cost; smaller models reduce resource usage but may lose nuanced reasoning.

### Failure signatures
- **Low final confidence:** Case‑Review Agent outputs probability far below typical thresholds (e.g., <0.7), indicating unresolved conflicts.  
- **High variance on similar images:** For visually similar inputs, wildly different diagnoses suggest inconsistent retrieval or agent randomness.  
- **Missing or contradictory guidelines:** Evolved guidelines diverging significantly from standards cause vacillation; monitor via divergence metric.  
- **Poor retrieval recall:** Top‑5 retrieved cases have low cosine similarity or none share ground‑truth diagnosis.

### First 3 experiments
1. **Unit test: Vision Agent consistency** – Feed 10 known images and verify extracted visual findings contain expected descriptors for malignant lesions; compare against human annotations.  
2. **Ablation of EvoDerma‑Mem** – Run with and without memory retrieval on Dermnet498 subset; measure drop in accuracy, MCC, Kappa to confirm contribution.  
3. **Memory retrieval sanity check** – For a query image, manually inspect top‑5 retrieved historical cases to ensure visual/diagnostic relevance; compute embedding similarities and check that top‑1 retrieved case shares ground‑truth diagnosis in >80% of common disease samples.

## Open Questions the Paper Calls Out
### Open Question 1
**Question:** How can the computational overhead of the multi‑agent orchestration be reduced for real‑time clinical deployment without sacrificing diagnostic depth?  
**Basis:** The Discussion states that orchestration results in prolonged processing times, challenging high‑throughput settings.  
**Why unresolved:** Complexity trades speed for traceability and robustness; no optimization strategies explored.  
**Evidence needed:** Profiling to identify bottlenecks; development and benchmarking of optimized variants (e.g., pruned pipelines, asynchronous retrieval).

### Open Question 2
**Question:** To what extent does EvoDerma‑Mem depend on the knowledge accumulation threshold (N_thresh), and what is the optimal strategy for setting it across disease categories?  
**Basis:** Methods define evolution trigger when new samples ≥ N_thresh, but threshold not specified or analyzed.  
**Why unresolved:** Inappropriate threshold could cause unstable updates (low) or stale guidelines (high), especially for rare diseases; no validation.  
**Evidence needed:** Systematic sensitivity analysis measuring guideline stability and diagnostic performance across N_thresh values on longitudinal data.

### Open Question 3
**Question:** Does the Rare Skin Disease Dataset (RSDD) with only 8 conditions and 564 samples adequately capture the diversity of rare dermatological diseases, or does its construction introduce selection bias?  
**Basis:** RSDD constructed from Chinese guidelines, selecting 12 initial conditions, ending with 8 classes; acknowledged modest scale.  
**Why unresolved:** May not represent the long‑tail of hundreds of rare conditions; source may bias toward conditions prevalent in China; gains may not generalize.  
**Evidence needed:** External validation on independently curated rare disease datasets from other regions; comparative analysis of feature space coverage.

### Open Question 4
**Question:** Is the fixed specialization of agents the optimal collaborative structure, or could alternative role distributions yield better accuracy or efficiency?  
**Basis:** Architecture presented as fixed design mimicking clinical workflows; no ablation comparing variants.  
**Why unresolved:** Multi‑agent overhead; simpler or adaptive structures might achieve similar accuracy with lower cost; current design may create bottlenecks.  
**Evidence needed:** Controlled experiments varying number and function of agents (e.g., removing Summarize Agent, merging vision and diagnosis) measuring accuracy, reasoning trace quality, and cost.

### Open Question 5
**Question:** To what degree do the evolved guidelines from EvoDerma‑Mem memorize rare‑case features versus learn generalizable causal principles for unseen rare presentations?  
**Basis:** Paper shows guideline evolution (e.g., Lichen Planus expanding from "6 P's") and claims it transcends pattern matching, but does not test causal generalization.  
**Why unresolved:** Guidelines could overfit to spurious correlations; no tests for out‑of‑distribution generalization or causal interventions.  
**Evidence needed:** Expert evaluation of guideline edits for causal validity; testing on new, deliberately challenging rare cases with atypical morphologies.

## Limitations
- **Undisclosed checkpoints and hyperparameters:** The fine‑tuned PanDerm model weights and exact training details for each dataset are not provided, obstructing baseline replication.  
- **EvoDerma‑Mem design specifics hidden:** The Summarization Agent’s prompt, contradiction‑resolution strategy, and evolution threshold (N_thresh) are not disclosed, raising concerns about stability and safety.  
- **Proprietary model dependency:** The system relies on Qwen models (Qwen3‑VL, Qwen3‑A30), which may limit reproducibility and increase cost; performance transfer to open‑source alternatives is unclear.

## Confidence
- Reproducing PanDerm baseline results: **Medium**  
- Long‑term reliability of EvoDerma‑Mem: **Low**  
- Generalizability of architectural claims beyond Qwen models: **Medium**
