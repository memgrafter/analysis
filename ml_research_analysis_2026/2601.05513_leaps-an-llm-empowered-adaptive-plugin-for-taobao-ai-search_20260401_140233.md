# LEAPS: An LLM-Empowered Adaptive Plugin for Taobao AI Search

## Quick Facts
- **arXiv ID:** 2601.05513
- **Source URL:** https://arxiv.org/abs/2601.05513
- **Reference count:** 32
- **Primary result:** Deployed on Taobao AI Search since August 2025, it reduces the Low-Result Rate by 31.7% and increases CTR by 16.4% for conversational queries while preserving legacy search performance and serving hundreds of millions monthly.

## Executive Summary
LEAPS is a non-invasive plugin that resolves the “zero-result or decision overload” dilemma in e-commerce conversational search. It employs a two-stage “Broaden-and-Refine” architecture: an upstream Query Expander uses a novel three-stage RL training pipeline to generate complementary query rewrites that maximize recall of relevant products from a black-box search engine, while a downstream Relevance Verifier filters noisy results via chain-of-thought reasoning over multi-source context (OCR, reviews, etc.). Live A/B testing on Taobao confirms significant business impact—cutting low-result occurrences by nearly a third and boosting click-through rates—demonstrating a scalable, low-cost way to endow traditional search engines with conversational understanding.

## Method Summary
LEAPS treats the existing search engine as an immutable black box. For a user query, the Query Expander (an LLM) produces multiple complementary rewrites through a three-stage training process: (1) Inverse Data Augmentation SFT learns basic rewrite patterns from synthesized pairs, (2) Posterior-Knowledge SFT aligns rewrites with the search engine’s actual output by scoring them with a Relevance Verifier, and (3) Diversity-aware RL optimizes set-level rewards (Hybrid/Global/Effective Relevance) to encourage non-redundant results. The aggregated candidate pool is then filtered by the Relevance Verifier, an LLM fine-tuned with chain-of-thought supervision on multi-instruction data that synthesizes item text, OCR, reviews, and user context to make binary relevance judgments. The final ranked list is returned to the user.

## Key Results
- Online A/B test on Taobao AI Search: Low-Result Rate reduced from 24.88% to 16.98% (-31.7%), CTR increased from 9.39% to 10.93% (+16.4%).
- Offline relevance gains: Hybrid Relevance up to 0.555, outperforming baselines.
- System deployed at scale since August 2025, handling hundreds of millions of monthly users without degrading performance on non-conversational queries.

## Why This Works (Mechanism)
### Mechanism 1: Query Expander mitigates zero-result failures
The Expander generates system-friendly query rewrites that maximize recall of relevant candidates. Its three-stage training (inverse augmentation → posterior-knowledge SFT → diversity-aware RL) aligns an LLM to optimize for the search engine’s actual retrieval behavior, not just semantic similarity. The core assumption is that the engine’s output (items returned) provides a learnable feedback signal for query utility. Break condition: Expander redundancy collapse, detectable via low unique result rate or high rewrite similarity.

### Mechanism 2: Relevance Verifier prevents decision overload
The Verifier acts as a semantic gatekeeper, precisely filtering broadened results using multi-source context and chain-of-thought reasoning. It distills human-like constraint modeling (e.g., “no pure black”, price ranges) into an LLM via CoT supervision. The assumption is that such reasoning generalizes when provided rich item/user context. Break condition: Verifier precision/recall drop on held-out items, especially for constrained attributes.

### Mechanism 3: Non-invasive plugin preserves legacy performance
LEAPS interacts solely via standard query submission and result ingestion APIs, leaving the underlying index and ranking models untouched. It intervenes only for conversational queries, thus maintaining optimized performance for short-keyword queries. Break condition: Degraded metrics (e.g., CTR) for short, high-frequency queries or increased P99 latency beyond threshold.

## Foundational Learning
- **Broaden-and-Refine Paradigm:** Separates recall and precision into two dedicated modules instead of tuning a single ranker. *Quick check:* Why is using only a rewriter OR only a reranker insufficient? (Rewriter alone may still produce noisy results; reranker alone cannot rescue zero-result queries.)
- **Posterior-Knowledge SFT:** Bridges user language and system matching by training on rewrites scored by actual search output (via Verifier). *Quick check:* In Algorithm 1, why is relevance ratio `s = |I_rel|/|I|` computed after Verifier filtering, not just by result count `|I|`? (Count alone ignores result quality; Verifier provides a quality signal.)
- **Diversity-Aware RL Reward:** Prevents the Expander from converging to a single high-reward rewrite by penalizing result overlap. *Quick check:* How does `Hybrid Relevance`’s `P_ic` (independent contribution rate) enforce diversity? (It measures the marginal gain of each rewrite to the overall candidate pool, rewarding non-overlapping coverage.)

## Architecture Onboarding
**Component map:** User Query → Query Expander (E) → Set of Rewrites Q' → Black-Box Search Engine (S) → Item Lists per Rewrite → Aggregator → Candidate Pool I_b → Relevance Verifier (V) + Multi-Source Context → Filtered List I_r → Final Ranked Results

**Critical path:** Expander generates 4-8 rewrites (~190ms) → parallel search calls → result aggregation → Verifier applies context and CoT reasoning (~150ms batch) → final list. Latency budget sensitive to search QPS and Verifier GPU throughput.

**Design tradeoffs:**
- Expander diversity vs. search quota: More rewrites improve coverage but increase search QPS and latency; fixed budget (4-8) is a heuristic.
- Verifier reasoning depth vs. throughput: CoT improves accuracy but increases token count; solution is ultra-concise rationale training and sequential batching.
- Context freshness vs. cost: Asynchronous updates for OCR/reviews reduce pipeline complexity but risk stale context.

**Failure signatures:**
- Expander: High Low-Result Rate for conversational queries; offline low `|I_b|` or high semantic similarity among rewrites.
- Verifier: Low CTR despite low LRR (irrelevant results); offline F1 drop on tail queries; false-negative filtering on constrained attributes.
- Integration: Degraded metrics for short queries; P99 latency >500ms.

**First 3 experiments:**
1. **Expander Isolation Test:** For 1k conversational queries, run Expander → S → compare `|I'_b|` and diversity metrics against a baseline rewriter (synonym expansion). Verify offline HR/GR/ER gains without Verifier.
2. **Verifier Stress Test:** Take 10k items from high-LRR queries’ `I_b`. Run Verifier with/without multi-source context (ablating OCR, reviews). Expect >15% F1 drop when removing reviews/OCR.
3. **Latency & Throughput Dry Run:** Simulate peak QPS (10k RPS). Tune Verifier batch size and concurrent search calls. Identify bottlenecks (search saturation, GPU memory). Validate P99 <400ms with sequential batching.

## Open Questions the Paper Calls Out
- **Question 1:** How can reinforcement learning dynamically allocate search budgets based on confidence weights for query rewrites, moving beyond equal-weight allocation? *Basis:* Future Work explicitly states current equal-weight mechanism is a limitation.
- **Question 2:** What are the trade-offs in accuracy, robustness, and cost when replacing OCR-based multimodal integration with a native VLM for direct product image perception? *Basis:* Future Work proposes upgrading to a VLM to avoid OCR error accumulation.
- **Question 3:** Which knowledge distillation techniques optimally compress the Verifier into a lightweight model for high-concurrency scenarios? *Basis:* Future Work notes intent to distill to reduce computational costs while preserving performance.

## Limitations
- **Simulator Dependency:** Expander training relies on a high-fidelity search engine simulator; its construction and validation against live Taobao search are not detailed.
- **Context Provenance:** Verifier’s multi-source data (OCR, reviews) integration lacks documentation on preprocessing, coverage, and freshness, limiting robustness assessment.
- **Corpus Validation Gap:** Neighboring papers support general RL/CoT trends but do not directly validate LEAPS’s specific architecture or hybrid reward design.

## Confidence
- **Online Performance Gains (LRR -31.7%, CTR +16.4%):** High (live A/B test from major deployment).
- **Mechanism 1 (Expander’s Three-Stage Training):** Medium (logically sound but gated by unverified simulator fidelity).
- **Mechanism 2 (Verifier’s Contextual CoT):** Medium (architecture specified; full context dependencies opaque).
- **Mechanism 3 (Non-Invasive Plugin):** Medium-High (well-defined API interaction; confidence hinges on legacy engine stability assumption).
