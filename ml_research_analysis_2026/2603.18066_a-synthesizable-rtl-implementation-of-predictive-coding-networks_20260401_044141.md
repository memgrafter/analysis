# A Synthesizable RTL Implementation of Predictive Coding Networks

## Quick Facts
- **arXiv ID:** 2603.18066
- **Source URL:** https://arxiv.org/abs/2603.18066
- **Reference count:** 14
- **Primary result:** A deterministic, synthesizable RTL substrate implements predictive coding networks with strictly local neuron updates and a uniform clamping interface, demonstrating rapid supervised learning on small regression tasks without backpropagation.

## Executive Summary
This paper presents a hardware-friendly implementation of predictive coding networks (PCNs) that avoids backpropagation by using local, adjacent-layer communication. Each neural core executes a fixed finite-state machine schedule to compute prediction errors and update its state and weights. Supervised learning is enabled via a per-neuron clamping interface that sets boundary conditions while leaving the internal update schedule unchanged. Experiments on small feedforward networks (ReLU and tanh activations) show fast convergence, and architectural scaling tests confirm the substrate's generality across widths without RTL modification.

## Method Summary
The method translates the continuous-time predictive coding energy minimization into a discrete-time, tick-based digital hardware schedule. Each neural core implements a 6-stage FSM (PRED, ERR, BACKSUM, BACKVEC, WUP, STATE) per clock tick, using sequential MAC accumulation for weighted sums. All arithmetic is IEEE-754 single precision. Inference and learning share the same microarchitecture; the mode is determined by external clamping signals (for inputs/targets) and learning-rate parameters. Communication is strictly between adjacent layers, ensuring locality. The design is synthesizable and verified via SystemVerilog testbenches on synthetic regression tasks defined by teacher networks.

## Key Results
- Avoids backpropagation's hardware infeasibility by using local prediction-error updates between adjacent layers.
- Demonstrated rapid supervised learning: in a 2→4→3 ReLU network, MSE dropped from 0.341 to 0.006 over 25 epochs; in a 2→2→1 tanh network, MSE dropped from 1.107 to 0.004.
- Architectural scaling (up to 8→16→8) showed consistent learning without RTL modifications, confirming the substrate's generality and deterministic local update rules.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Learning and inference emerge from strictly local prediction-error updates between adjacent layers, avoiding global error propagation.
- **Mechanism:** Each neural core computes its prediction (µ) from presynaptic activities (via weighted sum after activation), forms its prediction error (ε) against its own state, and uses locally received backpropagated error products (b) to update both its state (x) and outgoing weights (θ). All computations depend only on the neuron's own state/parameters, adjacent-layer presynaptic activities, and adjacent-layer error products.
- **Core assumption:** The predictive coding energy decomposition yields gradients that are implementable with only adjacent-layer communication under the specific discrete-time, Euler-style schedule described.
- **Evidence anchors:** [abstract] "each neural core executes local prediction-error updates... communicating solely with adjacent layers." [Section 4.1] Component-wise equations show each neuron's update (Δx_i, Δθ_ij) depends only on ε_i, f(x_{i,eff}), f(x^ℓ+1_j), and ∑_k θ^{ℓ−1}_{ki} ε^{ℓ−1}_k. [corpus] Weak; neighboring papers focus on FPGA training, LLM for RTL, or spiking neuromorphic systems, not predictive coding locality.
- **Break condition:** If a task requires error signals that cannot be expressed as a sum of products from immediate presynaptic partners and immediate postsynaptic error (e.g., certain attention mechanisms), the locality constraint may prevent learning.

### Mechanism 2
- **Claim:** Supervised learning and inference are unified under a single hardware schedule via a per-neuron clamping primitive that modifies the effective state used in local computations.
- **Mechanism:** An external `x_set_en` signal and `x_obs` value define an "effective state" x_eff for the current tick. This x_eff is used to compute the local error (ε = x_eff - µ) and the derivative gate (f'(x_eff)) in the state update equation. The stored state register is then overwritten if hard clamping is asserted, otherwise updated via the equation. The same finite-state machine (FSM) executes for both learning (α > 0) and inference (α = 0); clamping dictates boundary conditions.
- **Core assumption:** The clamping mechanism correctly implements the boundary conditions for both supervised learning (output layer clamped to targets) and inference (input layer clamped to observed data) without requiring a separate mode switch in the core's micro-architecture.
- **Evidence anchors:** [abstract] "supervised learning is enabled through a uniform per-neuron clamping interface... leaving the internal update schedule unchanged." [Section 5.4] Explicitly defines x_eff and the final state update logic with `CLAMP_HARD`. [corpus] No direct anchor; neighboring papers do not discuss this specific clamping interface.
- **Break condition:** If clamping interferes with the natural convergence of internal layers by imposing excessively rigid constraints, or if the fixed schedule cannot accommodate the necessary tick budget for a given task under clamping, performance may degrade or fail to learn.

### Mechanism 3
- **Claim:** A deterministic, tick-based execution model with a fixed per-neuron FSM schedule makes the entire learning substrate synthesizable and verifiable, mapping predictive coding dynamics directly to hardware stages.
- **Mechanism:** Each neural core runs an identical 6-stage FSM (PRED → ERR → BACKSUM → BACKVEC → WUP → STATE) per clock tick. Stages perform the sequential operations: accumulate prediction, compute error, sum backpropagated products, emit back products, update weights, update state. A global tick coordinator synchronizes layer completion. No dynamic scheduling or instruction fetch occurs; the algorithm is the hardware wiring.
- **Core assumption:** A fixed Euler-style discretization with finite-precision IEEE-754 arithmetic, combined with simultaneous activity and weight updates under a constant tick budget, yields a stable and convergent dynamical system for the tested network sizes and step sizes.
- **Evidence anchors:** [abstract] "deterministic, synthesizable RTL substrate built around a sequential MAC datapath and a fixed finite-state schedule." [Section 5.3] Lists the exact FSM stages and their correspondence to equations. [Section 7] "stability properties... do not automatically transfer... we treat stability... as an empirical property."
- **Break condition:** Instability may arise from aggressive step sizes (α, γ), insufficient tick budget for approximate inference convergence between weight updates, or finite-precision rounding errors accumulating in the iterative schedule. The paper reports empirical success but no formal stability guarantees.

## Foundational Learning
- **Concept:** Predictive Coding Gradient Dynamics (Eqs. 1-5 in Section 4.3)
  - *Why needed:* The entire hardware implementation is a direct translation of these discrete-time update equations. Understanding the derivation from the continuous-time energy minimization (Section 4) and the component-wise locality is essential to grasp why the hardware can be local.
  - *Quick check:* For a hidden neuron, list all sources of information required to compute its state update Δx_i in one tick. Which of these come from adjacent layers?

- **Concept:** Synchronous Digital Design & Finite-State Machines (Section 5.5, 6.1)
  - *Why needed:* The substrate's determinism and synthesizability rely on a tick-based, globally synchronized model where each core executes a fixed FSM. This contrasts with asynchronous or event-driven neuromorphic designs.
  - *Quick check:* Why does the design use a sequential MAC datapath that iterates over presynaptic indices, and what is the primary cost of this choice?

- **Concept:** Boundary Value Problems & Clamping (Section 5.4)
  - *Why needed:* Supervised learning is framed as solving an inference problem with clamped boundary conditions (inputs and targets). The hardware implements this via the clamping interface. The distinction between inference and learning phases is not a hardware mode but a parameter/boundary condition change.
  - *Quick check:* How does the `x_set_en` signal affect the computation during a tick versus the final stored state value?

## Architecture Onboarding
- **Component map:** Network Module → Layer Module → Neural Core. The Network broadcasts `start_tick` when idle; each Layer collects `done` from its cores and asserts layer `done` when all cores finish; each Neural Core runs the 6-stage FSM using presynaptic states from the next layer and back products from the previous layer.
- **Critical path:** Tick start propagates Network → Layer → Core. Core latency = Σ (sequential MAC stages) for its fan-in/out. Layer `done` = max(core latencies). Network `done` = max(layer latencies). Next tick begins after network `done`.
- **Design tradeoffs:**
  - Sequential MAC minimizes area per neuron but makes per-tick latency O(N+M) with fan-in N and back-fan M.
  - IEEE-754 single precision ensures numerical robustness but consumes significant area/power; fixed-point or lower precision would require stability re-tuning.
  - Fixed FSM schedule simplifies control but may waste cycles on near-converged neurons; adaptive early termination would add complexity.
- **Failure signatures:**
  - Diverging MSE: likely step sizes (α, γ) too large, severe rounding error, or clamping misconfiguration (e.g., output layer not clamped).
  - Plateau at high residual: likely insufficient tick budget per example, mismatched α/γ ratio, or inadequate network capacity.
  - Tick completion stall: likely synthesis/implementation timing failure or simulation bug in accumulation loops.
- **First 3 experiments:**
  1. Teacher–Student Regression (2→4→3 ReLU): Validates basic supervised learning on a known teacher network; rapid initial MSE drop followed by slow plateau.
  2. Nonlinear Regression (2→2→1 tanh): Tests with smaller network and smooth activation; faster convergence, confirming generality across activation functions.
  3. Architectural Scaling (2→4→3, 4→8→4, 8→16→8): Compiles same RTL with different dimensions; no RTL changes needed. Confirms local, composable design scales in width, though residual floor increases with size.

## Open Questions the Paper Calls Out
- **Open Question 1:** Can predictive coding dynamics be usefully combined with spiking event-driven computation to merge the bio-plausibility and energy efficiency of SNNs with the local gradient-based learning of predictive coding?
  - *Basis in paper:* [explicit] "Whether predictive-coding dynamics and spiking event-driven computation can be usefully combined is an open question for future work."
  - *Why unresolved:* The current architecture is a synchronous deterministic RTL design using scalar floating-point state updates, fundamentally different from the asynchronous, event-based, integrate-and-fire dynamics of SNN platforms like Loihi or BrainScaleS.
  - *What evidence would resolve it:* A hybrid hardware substrate that integrates spike-based communication with predictive-coding local update rules, followed by empirical benchmarks comparing learning performance, energy efficiency, and hardware resource utilization against both pure SNN and the presented RTL substrate.

- **Open Question 2:** Would extending this digital substrate toward analog "mortal computation"—embracing device-specific parameter variations and non-ideal hardware characteristics—improve energy efficiency or learning fidelity for predictive coding?
  - *Basis in paper:* [explicit] "Whether extending this further toward true analog mortal computation — accepting hardware-specific parameter fidelity in exchange for energy efficiency — would benefit predictive-coding substrates is an open question."
  - *Why unresolved:* The current design uses precise IEEE-754 arithmetic and assumes ideal, repeatable hardware behavior, sidestepping the analog variability that mortal computation embraces. The trade-offs between noise-induced regularization, learning stability, and energy gains in an analog predictive coding system are unknown.
  - *What evidence would resolve it:* Fabrication and measurement of an analog/digital mixed-signal predictive coding chip with characterized transistor-level mismatch, comparing its learning curves, power consumption, and tolerance to parameter drift against the synthesized digital RTL baseline.

- **Open Question 3:** What are the theoretical stability and convergence guarantees for the specific discrete-time, finite-precision, tick-based predictive coding implementation with simultaneous activity and weight updates under clamping?
  - *Basis in paper:* [inferred] The paper states that continuous-time stability "does not automatically transfer to a tick-based explicit Euler discretization in floating-point arithmetic" and that stability is treated empirically. It also notes that incremental predictive coding analyses [12, 9, 6] "do not directly guarantee stability for a particular hardware discretization."
  - *Why unresolved:* The system's coupled state-weight updates, fixed Euler step size (γ), finite precision, and periodic clamping create a complex dynamical system without a derived stability region. The empirical success in experiments does not provide general conditions for avoiding divergence or oscillation.
  - *What evidence would resolve it:* A mathematical analysis deriving sufficient (or necessary-and-sufficient) conditions on the step size γ, learning rate α, number of ticks per phase, and floating-point precision that ensure local contraction properties or convergence to a fixed point for a given network topology and activation function, validated by extensive simulation across parameter sweeps.

- **Open Question 4:** What is the optimal architectural trade-off between per-neuron area/power and tick latency for predictive coding substrates when scaling to large fan-in, and does a partially parallel datapath yield a net benefit?
  - *Basis in paper:* [inferred] The design uses a sequential MAC datapath, leading to linear per-tick cycle count with fan-in (Ctick ≈ 3N+M+4). The paper identifies this as a limitation: "higher-throughput implementations could introduce parallel MAC units or vectorized datapaths" but does not explore the cost-benefit.
  - *Why unresolved:* While sequential reuse minimizes area per neuron, linear latency may bottleneck performance in wide layers. The break-even point where additional parallel units improve throughput-per-watt or throughput-per-area under realistic synthesis constraints is unknown.
  - *What evidence would resolve it:* Synthesizing and comparing RTL variants with 1, 2, 4, and 8 parallel MAC lanes across a range of fan-in values (N) and technology nodes, reporting metrics like maximum clock frequency, total silicon area, dynamic power, and effective updates-per-second-per-mm².

- **Open Question 5:** What hardware-friendly approximations of nonlinear activation functions (f(·) and f′(·)) maintain learning performance in predictive coding without prohibitive synthesis cost?
  - *Basis in paper:* [inferred] The paper uses IEEE-754 single precision for all arithmetic and notes that "synthesizable implementations of nonlinear activations and their derivatives require careful numerical design." It does not evaluate alternatives like piecewise linear, lookup tables, or low-bit quantized approximations.
  - *Why unresolved:* Exact floating-point nonlinear functions (ReLU, tanh) are area- and power-intensive in ASIC/FPGA flows. The sensitivity of predictive coding's local error minimization dynamics to approximation error in f and f′—particularly for state gating in the update—is not characterized.
  - *What evidence would resolve it:* Systematically replacing exact floating-point f/f′ with various approximators (e.g., piecewise linear segments, fixed-point rational approximations, small neural network emulators) in the RTL, then measuring the impact on final MSE, convergence speed, and hardware resource usage (LUTs/FFs/DSPs) compared to the precise baseline.

## Limitations
- Hyperparameters (α, γ, tick budget) are undisclosed, blocking exact reproduction and full stability characterization.
- Stability relies on empirical observation; no analysis of Euler discretization or finite-precision effects for the coupled state-weight update system.
- Resource metrics (area, power, timing) are missing, weakening the hardware feasibility claim.
- Generality is limited to small feedforward nets; non-local architectures (e.g., with attention) may break locality.

## Confidence
- Local update design: Medium (matches equations but scalability unproven beyond 8→16→8).
- Clamping interface: High (clearly specified and integrated into FSM).
- Deterministic FSM schedule: High (synthesizable by construction).
- Reported learning results: High (MSE decreases as claimed in provided experiments).
- General scalability to large/deep networks: Low (only up to 8→16→8 tested).
