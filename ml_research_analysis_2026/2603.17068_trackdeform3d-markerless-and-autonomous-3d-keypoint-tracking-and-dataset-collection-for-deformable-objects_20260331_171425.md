# TrackDeform3D: Markerless and Autonomous 3D Keypoint Tracking and Dataset Collection for Deformable Objects

## Quick Facts
- **arXiv ID**: 2603.17068
- **Source URL**: https://arxiv.org/abs/2603.17068
- **Reference count**: 32
- **Primary result**: TrackDeform3D reduces absolute edge length error to 2.99–3.83 mm (25–67% vs. baselines), achieves frame success rates (E<5mm) of 63–98% across rope, branched rope, and fabric, and enables collection of a large-scale dataset with 6 deformable objects and 110 minutes of high-quality 3D trajectories.

## Executive Summary
TrackDeform3D introduces a markerless system for robust 3D keypoint tracking of deformable objects using only a single RGB-D camera. It formulates both initialization and tracking as a constrained optimization that enforces anchor point fixation, consistent edge lengths between keypoints, and projection onto the segmented object point cloud, ensuring geometric and temporal consistency. The method autonomously segments the object via point cloud differencing, detects anchors based on inferred topology (1D chain/tree or 2D grid), and tracks with warm-started iterative projection. Evaluated against state-of-the-art baselines, it significantly improves geometric accuracy and facilitates the collection of a large-scale, high-quality dataset that exceeds prior benchmarks in duration and object diversity.

## Method Summary
The pipeline processes synchronized RGB-D streams by converting depth images to point clouds and segmenting the deformable object through differencing between the first two frames, filtering robot arm points via known kinematics, and clustering the largest coherent cluster with DBSCAN. Object type (1D vs. 2D) is classified from point cloud eigenvalue ratios. For 1D objects (e.g., ropes), anchors are detected as leaf/junction points via skeletonization and minimum spanning tree (MST) degree analysis; for 2D fabrics, anchors are evenly distributed contour points via farthest point sampling (FPS). Topology is inferred as a chain (DLO), tree (BDLO), or grid (rectangular cloth). Initial keypoints are placed by FPS from anchors. Tracking per frame solves a constrained optimization (minimizing squared edge length deviation, subject to anchor fixation and point cloud projection) via iterative Gauss-Seidel projections, warm-started from the previous frame’s solution. A symmetric temporal moving-average filter smooths the final trajectories. The output is a set of consistent 3D keypoint trajectories with fixed indexing and topology.

## Key Results
- **Geometric accuracy**: Absolute edge length error reduced to 2.99–3.83 mm, representing a 25–67% improvement over state-of-the-art baselines (CoTracker3, CDCPD2, SpatialTrackerV2).
- **Frame success rates**: Percentage of frames with error below 5 mm increased to 63–98% across rope, branched rope, and fabric categories.
- **Dataset scale**: Enabled collection of 110 minutes of high-quality 3D keypoint trajectories for 6 diverse deformable objects, significantly exceeding prior benchmarks in total time and object variety.

## Why This Works (Mechanism)

### Mechanism 1
**Claim**: Enforcing geometric constraints (anchor fixation, edge length, point cloud projection) in a unified optimization yields geometrically consistent and temporally smooth keypoint trajectories.  
**Mechanism**: The core problem (Eq. 1) minimizes deviations from target edge lengths while projecting solutions onto manifolds defined by anchor positions and the segmented point cloud. Anchor constraints fix keypoints at geometrically significant positions (detected per frame), providing stable references and preventing drift. Edge length terms maintain inferred topology by encouraging uniform spacing. Point cloud projection forces non-anchor keypoints onto the observed object surface, ensuring fidelity to observations. Iterative solving (Alg. 1) with warm-start from the previous frame propagates consistency through time.  
**Core assumption**: Object topology (graph connectivity `E`) and keypoint count `N` are fixed after initialization; detected anchors are accurate and correspond to repeatable features.  
**Evidence**: Abstract states the formulation enforces constraints for consistency; Section III-B defines Eq. 1 and its components; Section III-E details the warm-start tracking procedure (Alg. 2).  
**Break condition**: Anchor detection failure (e.g., due to occlusion or shape ambiguity) removes stabilizing references, causing drift or collapse; incorrect topology `E` enforces invalid geometry.

### Mechanism 2
**Claim**: Anchor point detection from the segmented point cloud provides boundary conditions that ensure initialization and trajectory consistency across collection sessions.  
**Mechanism**: For 1D objects, anchors are leaf/junction points found via skeletonization of the 2D mask and MST degree analysis, lifted to 3D. For 2D cloth, anchors are evenly distributed contour points via FPS. These anchors are fixed during optimization, anchoring the solution in object geometry (e.g., rope ends, fabric corners). This makes the final keypoint configuration repeatable despite different initializations or noise, satisfying initialization consistency.  
**Core assumption**: Object type (1D vs. 2D) is correctly classified from local point cloud geometry; anchor features are reliably detectable from a single segmented point cloud.  
**Evidence**: Abstract mentions anchor fixation; Section III-D covers classification (eigenvalue ratios) and anchor detection for 1D (skeleton+MST) and 2D (contour+FPS); Section III-B includes anchor constraint `xt,k = at,k` in Eq. 1.  
**Break condition**: Anchor detection failure (e.g., skeletonization breaks on thick/noisy objects, contour extraction fails on self-occluded cloth) leads to variable keypoint layouts across sessions and potential drift.

### Mechanism 3
**Claim**: Autonomous point cloud differencing segmentation enables robust, markerless object isolation from a static background, a prerequisite for constraint-based tracking.  
**Mechanism**: Two point clouds are captured with robot arms in different configurations. Differencing (`P1 - P0`) filters static background, leaving points from the moving object (appearing with opposite sign depth changes). Robot arm points are removed using a known kinematic model and calibration. The largest coherent cluster (via DBSCAN) from the remainder is taken as the segmented object point cloud `P_seg_t`, providing the surface constraint for optimization.  
**Core assumption**: Background is static between captures; robot arms’ point clouds can be accurately simulated and subtracted; the object is the largest coherent moving cluster and remains unoccluded.  
**Evidence**: Abstract notes use of only RGB-D cameras; Section III-C details the segmentation procedure; Section III-A states the unoccluded object assumption.  
**Break condition**: Partial occlusion during one capture fragments clusters; inaccurate robot simulation contaminates object cluster; non-static background includes noise points.

## Foundational Learning

### Constrained Optimization (Projective Dynamics)
**Why needed**: The tracking core solves Eq. 1 iteratively via alternating projections (Alg. 1). Understanding how constraints (edge length, point cloud, anchor) are projected onto the solution manifold explains stability and warm-start efficacy.  
**Quick check**: What happens to the edge length constraint projection (Line 4 in Alg. 1) if two keypoints are currently much closer than `d_ij`? How does this differ from a simple repulsion force?  
*Answer*: The projection rescales the vector between keypoints to match the target length, preserving direction—a hard constraint enforcement—whereas a repulsion force would push them apart but not guarantee exact length.

### Point Cloud Processing & Segmentation
**Why needed**: The pipeline operates on segmented point clouds `P_seg_t`; keypoints must lie on this cloud (projection constraint). Operations like clustering, differencing, and FPS are fundamental.  
**Quick check**: Why use DBSCAN after point cloud differencing instead of just taking all remaining points? What property of the object makes it the "largest coherent cluster"?  
*Answer*: DBSCAN groups spatially coherent points, filtering scattered noise. The object is assumed to be the largest connected moving component, so its cluster size dominates.

### Topology Inference for Deformable Objects
**Why needed**: The edge set `E` defines which keypoints are connected. For 1D objects, this is a chain/tree found by ordering skeleton points; for 2D cloth, it’s a grid derived from contours. Wrong topology implies wrong physical constraints.  
**Quick check**: For a branched rope (BDLO), how does the MST on the skeleton help determine both the anchor points (junctions) and the ordering of keypoints along each branch?  
*Answer*: MST connects skeleton points with minimal total length; high-degree nodes in the MST correspond to junctions (anchors), and MST paths from anchors to leaves define keypoint ordering along each branch.

## Architecture Onboarding

### Component Map
RGB-D input -> Preprocessing (depth to point cloud, calibration) -> Segmentation (point cloud differencing, robot arm simulation/subtraction, DBSCAN clustering) -> Initialization (object classification, anchor detection, topology inference, warm-start via FPS, solver) -> Tracking Loop (anchor re-detection, solver warm-started from previous frame) -> Post-processing (symmetric temporal moving-average filter) -> Output (3D keypoint trajectories, topology `E`, grasp indices)

### Critical Path
Segmentation (`P_seg_t`) -> Anchor Detection (`a_t,k`) -> Solver (uses `P_seg_t`, `E`, `A`, warm-start) -> Filter. The solver cannot run without `P_seg_t` and anchors; filter is last.

### Design Tradeoffs
- **Anchor sensitivity vs robustness**: More anchors (denser contour) provide more constraints but require more accurate detection. Fewer anchors (just ends/junctions) are robust but may not constrain interior keypoints enough on complex shapes.
- **Point cloud projection vs geometric validity**: Strict projection (`x_l = nearest(P_seg)`) ensures keypoints lie on observed surface but can jitter with sensor noise. Relaxing it might smooth trajectories but cause keys to drift off-object.
- **Single camera vs occlusion**: Single RGB-D is cheap but fails under occlusion. Multi-camera would require more calibration and fusion, increasing complexity.

### Failure Signatures
- **High absolute edge length error (Abs.)**: Either anchor detection failed (no fixed points), edge length term was weakened, or point cloud projection is not pulling keypoints onto the correct surface.
- **Keypoint drift across sessions (init. inconsistency)**: Anchor detection is unstable or anchors are not geometrically significant enough to define a unique configuration.
- **Sudden jumps/loss of track**: The solver diverges, often because warm-start (`X_{t-1}`) is too far from the feasible set defined by new `P_seg_t` and anchors, or because anchor detection completely fails for a frame.

### First 3 Experiments
1. **Segmentation validation**: Isolate Section III-C. Manually place a known object, move robot arms, run differencing. Quantify: % of object points correctly clustered vs. arm point contamination vs. missing fragments. Sweep DBSCAN parameters (eps, minPts).
2. **Anchor detection robustness**: For a fixed object shape (e.g., rope loop), apply minor synthetic deformations/noise to `P_seg_1`. Run anchor detection (skeleton+MST). Measure variance in detected anchor 3D positions and MST degree mismatches across runs.
3. **Full pipeline tracking under perturbation**: Run on a standard sequence (slow rope manipulation). Introduce controlled perturbations: a) skip anchor detection for one frame (force solver to use previous anchors), b) add Gaussian noise to depth (affects `P_seg_t`), c) change object color to match table (makes differencing harder). Track metrics (Abs., E<5) degradation versus baseline.

## Open Questions the Paper Calls Out
- How can TrackDeform3D be extended to handle deformable objects with complex or unknown topologies that do not conform to predefined chain, tree, or grid structures?
- Can TrackDeform3D's segmentation and tracking be made robust to partial occlusions without relying on the assumption that the object remains fully visible?
- Does the reliance on a single RGB-D camera limit scalability to larger workspaces or scenes with complex geometry, and how much does a multi-camera setup improve accuracy?
- How well does the anchor point detection generalize to 2D deformable objects beyond rectangular fabrics, such as irregularly shaped cloths or garments with complex boundaries?

## Limitations
- Segmentation parameters (DBSCAN eps/minPts, differencing radius) are unspecified and sensitive to tuning.
- Anchor detection heuristics (skeletonization, MST) may fail on complex or noisy geometries.
- Core assumptions (static background, accurate robot model, unoccluded object, fixed topology) are fragile in real-world conditions.
- Single RGB-D camera limits field of view and is prone to occlusion, restricting workspace size and scene complexity.

## Confidence
- Constrained optimization formulation (Eq. 1): Medium (effective if anchors and point cloud are reliable).
- Anchor detection pipeline (Section III-D): Medium (heuristic; lacks robustness validation on diverse shapes).
- Autonomous segmentation (Section III-C): Medium (assumes ideal static background/unoccluded object; not benchmarked).
- Dataset scale claim (110 min, 6 objects): High (plausible given setup).
- Overall system robustness: Medium due to multiple tuned assumptions and sensitivity to parameters.
