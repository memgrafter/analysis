# Optimization Instability in Autonomous Agentic Workflows for Clinical Symptom Detection

## Quick Facts
*   arXiv ID: 2602.16037
*   Source URL: https://arxiv.org/abs/2602.16037
*   Reference count: 16
*   Primary result: Autonomous prompt optimization (Pythia) exhibits prevalence-dependent instability and F1 degradation, but a retrospective selector agent prevents catastrophic failure and outperforms expert-curated lexicons on low-prevalence tasks.

## Executive Summary
This study investigates the reliability of autonomous, multi-agent workflows for optimizing clinical symptom detection prompts. The core system, Pythia, uses error-driven feedback from specialist and critic agents to iteratively refine a natural-language prompt. The authors find that this process is inherently unstable, particularly on rare symptoms (3% prevalence), where validation sensitivity oscillates between perfect and zero and F1 scores collapse. Actively intervening to guide the optimization worsens overfitting. However, a simple design change—selecting the best development iteration only after all optimization completes—robustly prevents failure and significantly improves performance over static expert lexicons.

## Method Summary
The paper evaluates the Pythia framework, a multi-agent system using Llama 3.1 70B to autonomously improve a binary classification prompt for detecting symptoms (brain fog, chest pain, shortness of breath) in EHR notes. The process starts with a single symptom term. In each iteration, a Specialist Agent classifies the development set. Error Analysis Agents (Specificity/Sensitivity Improvers) critique false positives or false negatives. Synthesis Agents (Summarizers) integrate these critiques to rewrite the prompt for the next iteration, with a rollback mechanism to avoid immediate degradation. The loop runs for up to 7 iterations. The key intervention is comparing an active "guiding agent" that redirects stalled optimization against a retrospective "selector agent" that simply picks the best development-set F1 score from the completed trajectory. Performance is measured on a held-out validation set (200 notes per symptom, prevalences 3–23%).

## Key Results
*   The autonomous optimization loop exhibits prevalence-dependent instability: validation sensitivity oscillates between 0.0 and 1.0, and F1 degrades, with the most extreme failure at 3% prevalence where a prompt achieved 95% accuracy but zero positive detections.
*   An actively intervening guiding agent, which redirected optimization when progress stalled, amplified overfitting to the development set, increasing the development-validation F1 gap.
*   A retrospective selector agent, which chose the best development iteration post-hoc, prevented catastrophic failure. With this oversight, Pythia outperformed expert-curated lexicons on brain fog detection (+331% F1) and chest pain (+7%), starting from a single symptom term.

## Why This Works (Mechanism)
### Mechanism 1: Optimization Spiral from Sparse Signal Overfitting
*   **Claim:** Optimization instability manifests as oscillations in sensitivity/specificity because the autonomous multi-agent workflow overfits to sparse positive signals in the development set during iterative refinement.
*   **Mechanism:** At low prevalence (e.g., 3% for brain fog), each false negative critique triggers the Sensitivity Summarizer to expand detection patterns. Because positive cases are rare, small linguistic changes in the prompt can disproportionately shift the decision boundary. The system alternately overcorrects for false positives (raising specificity, lowering sensitivity) and then for the new false negatives (lowering specificity, raising sensitivity), creating a destructive feedback loop. The natural-language prompt space lacks smooth gradient properties, allowing discrete jumps.
*   **Core assumption:** Error-driven synthesis from sparse critiques introduces high-variance modifications poorly regularized by limited positive examples.
*   **Evidence anchors:** [abstract]: validation sensitivity oscillated between 1.0 and 0.0; [section 4.1]: spiral pattern described; [corpus]: neighboring papers on agentic fragility support general instability concerns.
*   **Break condition:** Oscillation amplitude grows until sensitivity collapses to zero, typically at low prevalence when prompts exploit noise or learn overly broad exclusion rules.

### Mechanism 2: Guiding Agent Introduces an Exploitable Objective
*   **Claim:** An actively intervening guiding agent that monitors stagnation and redirects optimization amplifies overfitting by giving the system an additional, poorly constrained objective (satisfying the guide) that it can exploit via prompt modifications fitting development-set idiosyncrasies.
*   **Mechanism:** The guiding agent issues a meta-instruction (e.g., "explore an alternative direction") after detecting no F1 improvement. Summarizer Agents can incorporate this as a new constraint. Since the guide's feedback is based on development-set metrics, the system learns to generate prompts that *appear* to satisfy the guide's request (e.g., via large, complex changes) while further specializing to `D_dev` patterns that do not generalize. The guide adds an indirect optimization target that the prompt synthesis mechanism can "game."
*   **Core assumption:** The guiding agent's intervention criterion (e.g., "no F1 improvement") is a noisy signal exploitable by the natural-language synthesis process, which lacks inherent generalization pressure.
*   **Evidence anchors:** [abstract]: guiding agent amplified overfitting; [section 4.2]: intervention reduced oscillation on `D_dev` but did not improve `D_val` and exacerbated overfitting; [section 5 discussion]: active intervention may be counterproductive vs. retrospective selection.
*   **Break condition:** The gap between development and validation F1 becomes large (e.g., 0.47 gap for brain fog), indicating learning of `D_dev`-specific artifacts.

### Mechanism 3: Retrospective Selection Avoids Steering Bias
*   **Claim:** A retrospective selector agent that chooses the best development iteration *after* all optimization completes prevents catastrophic failure by avoiding the introduction of a selection-pressure signal during the optimization loop itself.
*   **Mechanism:** By allowing the full, unguided optimization trajectory to unfold and *then* applying a selection criterion (best `F1_Ddev`), the selector does not influence the *content* of the generated prompts. The optimization process remains "blind" to the eventual selection mechanism, preventing the system from learning to produce prompts that specifically exploit the selection criterion. This preserves diversity in the explored prompt space and increases the chance that at least one iteration represents a robust, generalizable solution. The selector acts as a filter, not a steering wheel.
*   **Core assumption:** The development set contains at least one iteration that generalizes reasonably well, and its `D_dev` performance is sufficiently correlated with its `D_val` performance to be identified post-hoc, even at very low prevalence.
*   **Evidence anchors:** [abstract]: retrospective selector successfully prevented catastrophic failure; [section 4.3]: selector-aided Pythia outperformed lexicon baselines; [section 5 discussion]: retrospective selection outperforms active intervention by avoiding exploitable degrees of freedom.
*   **Break condition:** If *all* iterations collapse to the same poor local minimum (e.g., all zero sensitivity), the selector cannot recover a viable model, more likely at extremely low prevalence with very few `D_dev` positives.

## Foundational Learning
*   **Concept: Class Imbalance and Evaluation Metric Pathology**
    *   **Why needed here:** The core failure mode (95% accuracy with zero detections) is only visible when looking at sensitivity/recall, not overall accuracy. Understanding how prevalence distorts common metrics is essential to diagnosing the instability.
    *   **Quick check:** If a classifier on a 3% prevalence task always predicts "negative," what are its accuracy, sensitivity, and F1 score? Why is accuracy misleading?
*   **Concept: Empirical Risk Minimization (ERM) and Decision Boundary Instability**
    *   **Why needed here:** The oscillation suggests the optimization process is navigating a high-variance loss landscape where small prompt changes cause large swings in sensitivity. This connects to classic ML instability under class imbalance where the model's decision boundary is poorly anchored by few positive examples.
    *   **Quick check:** In a linearly separable binary classification task with 100 negative points and 3 positive points, why might adding a single new positive example (via a data augmentation critique) cause a large shift in the decision boundary of a simple linear model?
*   **Concept: Prompt Engineering as a Discrete, Interpretable Search Problem**
    *   **Why needed here:** Pythia treats prompts as mutable natural language strings, not continuous embeddings. This design enables interpretability but may cause non-monotonic, unstable optimization because a small wording change can have a discontinuous effect on the LLM's behavior.
    *   **Quick check:** How might changing a prompt from "Detect mentions of chest pain" to "Detect *explicit* mentions of chest pain, ignoring vague descriptions" cause the classifier's behavior to change in a non-linear way on a case with "patient complains of discomfort in his chest"?

## Architecture Onboarding
*   **Component map:**
    Specialist Agent -> [Development Workflow Controller] -> Error Analysis Agents (Specificity/Sensitivity Improver) -> Synthesis Agents (Summarizer) -> [back to Specialist with new prompt P_t+1]
    [Selector Agent] -> [Validation Workflow] (post-hoc selection)
*   **Critical path:** The core optimization cycle is: `P_t` -> [Specialist on `D_dev`] -> metrics (`σ_t`, `τ_t`) -> convergence check? -> No -> identify limiting metric (σ or τ) -> [Corresponding Improver on errors] -> critiques `C` -> [Corresponding Summarizer] -> `P_{t+1}` -> repeat (max 7 iterations). The selector acts *after* this loop.
*   **Design tradeoffs:**
    *   Interpretability vs. Stability: Natural-language prompt modifications are human-readable but create a discrete, non-smooth search space prone to instability vs. embedding-based optimization which might be more stable but opaque.
    *   Autonomy vs. Control: Fully autonomous error-driven synthesis maximizes adaptability but risks spiral; active guidance adds control but introduces a new, gameable objective; retrospective selection sacrifices some peak optimality for robustness.
    *   Development vs. Validation fidelity: The system optimizes for `D_dev` metrics. The rollback mechanism tries to prevent degradation *on `D_dev`*, but `D_dev` performance can be a poor proxy for `D_val` generalization at low prevalence.
*   **Failure signatures:**
    1.  **Oscillation**: Validation sensitivity (`σ_val`) swings dramatically between 0.0 and 1.0 across iterations, while accuracy remains high.
    2.  **Catastrophic collapse**: `σ_val` reaches 0.0 for one or more iterations, meaning zero positive cases are detected.
    3.  **Development-validation divergence**: High `F1_Ddev` (e.g., 0.47) with near-zero `F1_Dval` (e.g., 0.00), indicating severe overfitting to `D_dev`.
    4.  **Metric myopia**: System stabilizes on a prompt with high accuracy but zero sensitivity (detects nothing), a failure invisible to accuracy alone.
*   **First 3 experiments:**
    1.  **Baseline instability characterization**: Run the core Pythia loop (T_max=7) on all three symptoms (SOB 23%, Chest Pain 12%, Brain Fog 3%) with minimal initialization (single symptom term). Plot `σ_dev` and `σ_val` per iteration. Confirm prevalence-dependent oscillation/collapse.
    2.  **Guiding agent intervention test**: Integrate a guiding agent that, after iteration *t*, checks if `F1(P_t) < F1(P_{t-1})` and, if true, instructs the Summarizer to "generate a *radically different* prompt exploring a new direction." Compare development-validation F1 gaps vs. baseline.
    3.  **Selector agent validation**: Allow all 7 iterations to complete. Post-hoc, select `P* = argmax F1_Ddev(P_t)`. Evaluate `P*` on `D_val` and compare F1 to the expert lexicon baseline. Verify that the selected iteration is not always the final one.

## Open Questions the Paper Calls Out
*   **Open Question 1:** Why does the guiding agent amplify overfitting while the selector agent prevents catastrophic failure in low prevalence tasks?
    *   *Basis in paper:* [explicit] The guiding agent increased the development-validation performance gap, whereas the retrospective selector succeeded.
    *   *Why unresolved:* The paper speculates active intervention introduces exploitable degrees of freedom but lacks analysis of how guidance alters the optimization trajectory or error feedback.
    *   *What evidence would resolve it:* Comparative analysis of prompts generated under each condition, focusing on how guidance changes error critique utilization and whether it encourages memorization of development set idiosyncrasies.
*   **Open Question 2:** What mechanistic factors link class prevalence to the amplitude of sensitivity oscillations during autonomous prompt optimization?
    *   *Basis in paper:* [inferred] The paper shows oscillations are more severe at 3% prevalence but does not explain the underlying process in the optimization loop.
    *   *Why unresolved:* Without understanding how sparse positives affect error critique generation or prompt synthesis stability, interventions cannot be principled.
    *   *What evidence would resolve it:* Controlled experiments varying positive sample counts in the development set, measuring error critique diversity and prompt step changes; possibly formalizing the optimization as a stochastic process sensitive to sample size.
*   **Open Question 3:** Does evaluating multiple clinical notes per patient mitigate optimization instability and improve detection performance for low-prevalence symptoms?
    *   *Basis in paper:* [explicit] The authors note their study used single notes per patient and suggest longitudinal records may improve detection, especially for subtle symptoms.
    *   *Why unresolved:* It is unknown whether aggregating notes reduces sparsity of positive signals or introduces noise that could worsen instability.
    *   *What evidence would resolve it:* Replicate the study with patient-level note aggregation, comparing instability patterns and validation F1 across prevalence levels against the single-note baseline.

## Limitations
*   Exact convergence thresholds (θσ, θτ) used in experiments are not disclosed.
*   Full agent system prompts, SOPs, and the "performance monitoring mechanism" details are missing; the original code repository link is absent.
*   The dataset source, annotation guidelines, and precise lexicon construction method for baselines are unspecified, hindering faithful replication.
*   The strength of the development-validation correlation at very low prevalence, which underpins the selector's effectiveness, remains unknown.

## Confidence
*   **Instability & prevalence-dependent oscillation:** Medium – supported by abstract and Section 4.1, but limited external validation.
*   **Guiding agent amplifies overfitting:** Medium – evidence from Section 4.2, but no alternative guide designs were tested.
*   **Retrospective selector prevents failure & improves performance:** High – consistent F1 gains across symptoms (+331% brain fog, +7% chest pain) and robust in experiments.
