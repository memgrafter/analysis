# Learning From Design Procedure To Generate CAD Programs for Data Augmentation
## Quick Facts
- **arXiv ID**: 2603.06894
- **Source URL**: https://arxiv.org/abs/2603.06894
- **Reference count**: 31
- **Primary result**: Proposed data augmentation yields CAD models with 77% B‑Spline faces (0% in baselines), 89% B‑Spline curves (1% in baselines), and B‑Spline Ratio 0.2217, approaching the 0.5352 ratio of commercial designs. Ablation confirms reference surface is essential (ratio drops to 0.0085).

## Executive Summary
The paper tackles the scarcity of organic B‑Spline shapes in LLM‑generated CAD programs. The authors introduce a data augmentation approach that conditions an LLM on both a textual design description and a reference surface program—a CadQuery script defining an organic B‑Spline surface. The LLM iteratively generates CadQuery programs, which are executed and validated for correctness (watertight solid). The resulting dataset exhibits a dramatic increase in B‑Spline content, with 77% of samples containing B‑Spline faces and an overall B‑Spline Ratio of 0.2217, compared to near‑zero in existing datasets. An ablation study shows the reference surface is critical, as removing it reduces the ratio to 0.0085. The method mimics industrial design workflows and brings synthesized data closer to real‑world complexity.

## Method Summary
The method operates in two stages: prompt assembly and iterative generation‑validation. First, for each design description (taken from DeepCAD bracket labels), a random reference surface program is chosen among four organic B‑Spline types (Gaussian, saddle, wave, ripple) with parameter variations. The prompt includes a system prefix, the design description, a context instructing the LLM to “conform to the reference surface … remove it”, and a postfix requesting a watertight solid and STEP export. The LLM (o3‑2025‑04‑16 snapshot, high reasoning effort) outputs a CadQuery script. The script is executed; if it fails or produces an invalid/non‑watertight STEP, the error message is fed back into the prompt for self‑correction (up to a limit). Successful programs are retained, and their STEP files are parsed to compute B‑Spline metrics. This pipeline enriches geometric diversity by explicitly steering the model toward organic shapes.

## Key Results
- B‑Spline faces appear in 77% of generated samples (baselines: 0%); B‑Spline curves in 89% (baselines: 1%).
- B‑Spline Ratio rises to 0.2217, while baseline datasets score near zero; commercial industry designs achieve 0.5352.
- Ablating the reference surface drops the B‑Spline Ratio to 0.0085, underscoring its necessity.

## Why This Works (Mechanism)
The reference surface program acts as a concrete geometric template that the LLM can emulate within the constraints of the design description. By instructing the model to “conform to the reference surface” and then remove it, the prompt encourages the incorporation of the underlying B‑Spline structure while allowing adaptation to the target object. The iterative validation loop ensures that only geometrically valid, watertight solids are accepted, raising overall quality. This combination of explicit conditioning on a high‑quality organic shape and rigorous self‑correction effectively bridges the gap between simple LLM defaults and the organic forms prevalent in industrial CAD.

## Foundational Learning
- **B‑Spline surfaces/curves in CAD**: *Why needed*: Represent smooth, organic shapes essential for consumer products and aerospace components. *Quick check*: Does the STEP file contain `B_SPLINE_SURFACE` or `B_SPLINE_CURVE` entities?
- **LLM‑based code generation**: *Why needed*: Automates the synthesis of complex geometry scripts. *Quick check*: Can the LLM produce syntactically correct CadQuery programs that run without errors?
- **Data augmentation via conditioning**: *Why needed*: Expands training data diversity without collecting new examples. *Quick check*: Does adding a reference surface increase the variety of B‑Spline usage compared to text‑only conditioning?
- **Iterative self‑correction**: *Why needed*: Handles execution and validation failures automatically. *Quick check*: Does feeding error messages back to the LLM improve the success rate across multiple attempts?
- **Watertight solid validation**: *Why needed*: Guarantees manufacturability and simulation readiness. *Quick check*: After STEP import, does `isValid()` and `isClosed()` return true?
- **Reference surface program**: *Why needed*: Provides a reusable, parameterized example of organic geometry. *Quick check*: Do variations in surface parameters yield distinct B‑Spline shapes while remaining watertight?

## Architecture Onboarding
**Component map**: Design description → Prompt Assembler → LLM → Code Executor → STEP Validator → Metric Analyzer; Reference Surface Generator feeds into Prompt Assembler.  
**Critical path**: 1) Assembler combines description, reference script, and system prompts; 2) LLM generates CadQuery code; 3) Executor runs code and captures STEP/errors; 4) If failure, error is fed back to LLM (up to N iterations); 5) Upon success, Validator checks watertightness; 6) If valid, program is stored; 7) Analyzer computes B‑Spline metrics.  
**Design tradeoffs**:
- LLM reasoning effort vs cost: Higher effort improves code quality but increases API expense.
- Iteration limit vs throughput: More retries yield higher success rates but slower generation.
- Reference surface diversity vs prompt complexity: More surface types increase variety but may dilute conditioning if not carefully chosen.
- Validation strictness vs false negatives: Stricter watertight checks ensure quality but may reject marginal but acceptable designs.  
**Failure signatures**:
- Execution error (e.g., CadQuery API misuse) appears in traceback.
- Non‑watertight shape: `isValid()` or `isClosed()` returns false.
- B‑Spline absence: Generated code shows only primitive operations (extrude, revolve).
- Excessive iterations: Average retries > threshold (e.g., 5) indicates prompt or validation issues.

## Limitations
- The exact DeepCAD bracket subset and extracted text descriptions are not released, preventing precise replication of baseline comparisons.
- Reference surface parameter ranges and randomization schedule are unspecified, requiring arbitrary choices.
- The watertight validation relies on the authors’ internal DTGBrepGen implementation; external approximations may differ in strictness.

## Confidence
- Main claim (significant B‑Spline increase): **Medium**
- Ablation result (reference surface essential): **High**
- Baseline comparisons: **Low**
