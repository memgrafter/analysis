# Constraint-Rectified Training for Efficient Chain-of-Thought
## Quick Facts
- arXiv ID: 2602.12526
- Source URL: https://arxiv.org/abs/2602.12526
- Reference count: 40
- Primary result: CRT reduces token count by ~37% (1172 vs 1869) while improving accuracy (84.64% vs 84.43%) on DeepSeek-1.5B/GSM8K, and achieves the highest AES (0.29 in-domain).

## Executive Summary
Overthinking in large language model chain-of-thought reasoning generates excessive token usage and higher inference costs. Existing heuristic shortening methods often degrade accuracy and require careful tuning. Constraint-Rectified Training (CRT) addresses this by framing efficient reasoning as a reference-guarded constrained optimization problem. Using a frozen reference policy, CRT alternately minimizes normalized response length when accuracy meets a threshold, otherwise rectifies accuracy. A two-stage extension first discovers the shortest reliable reasoning patterns, then refines accuracy under the learned length budget. Results on DeepSeek-1.5B with GSM8K show a 37% token reduction while slightly improving accuracy, the highest AES scores, and lower internal redundancy. Intermediate checkpoints also enable inference-time verbosity control without retraining.

## Method Summary
CRT initializes a trainable model alongside a frozen reference policy (either an earlier checkpoint or a separate model). For each training batch, the trainable model produces a response, which is evaluated against the reference answer to compute accuracy. Normalized response length (e.g., token count relative to reference length) is also measured. A constraint controller monitors the batch accuracy: if it meets or exceeds a predefined threshold (e.g., 95% of reference accuracy), the loss switches to length minimization (e.g., a penalty proportional to length); otherwise, the loss is standard cross-entropy to improve accuracy. This alternating optimization prevents the model from collapsing to overly terse but incorrect reasoning. The two-stage variant first runs only length minimization until the model consistently meets the threshold with minimal length, thereby discovering a length budget; stage two then freezes that budget (or uses a Lagrange multiplier) and focuses on accuracy maximization under the constraint. Throughout training, intermediate checkpoints capture different points on the efficiency-accuracy trade-off, allowing post-hoc selection of desired verbosity.

## Key Results
- Token reduction with maintained/improved accuracy: DeepSeek-1.5B on GSM8K – accuracy 84.64% (vs 84.43% baseline) with 1172 tokens (vs 1869 baseline), a 37% reduction.
- Highest AES scores among compared methods (0.29 in-domain).
- Lower internal language redundancy (compression ratio 0.423 vs. baseline 0.356) and fine-grained verbosity control via intermediate checkpoints.

## Why This Works (Mechanism)
CRT uses the reference policy as a guardrail: the accuracy threshold ensures that length minimization only occurs when the model already produces sufficiently correct reasoning, preventing a drop in performance. Alternating optimization separates the conflicting objectives, avoiding interference between gradient signals for length and accuracy. The two-stage approach further decouples the discovery of a minimal viable length from the refinement of accuracy within that constraint, yielding a Pareto-optimal balance. Intermediate checkpoints naturally capture this progression, enabling inference-time verbosity adjustment.

## Foundational Learning
- **Constrained Optimization**: CRT frames the problem as minimizing length subject to an accuracy constraint. *Why needed*: Balances efficiency with correctness. *Quick check*: Verify that the constraint (accuracy threshold) is enforced before applying length loss.
- **Reference Policy**: A frozen model that provides baseline outputs and accuracy. *Why needed*: Supplies a stable target for the constraint and prevents degenerate shortcuts. *Quick check*: Ensure reference accuracy is measured on a held-out set and does not drift.
- **Normalized Response Length**: Token count scaled by a reference (e.g., reference output length). *Why needed*: Allows fair comparison across examples of different inherent lengths. *Quick check*: Confirm normalization uses a consistent denominator (e.g., median reference length per dataset).
- **Accuracy Threshold**: The minimum acceptable accuracy relative to the reference. *Why needed*: Acts as a guardrail to avoid over-shortening that harms correctness. *Quick check*: Set threshold slightly below reference accuracy and monitor model's ability to exceed it.
- **Two-Stage Training**: Separately discovers minimal length patterns and then refines accuracy under a fixed length budget. *Why needed*: Prevents conflict between minimizing length and maximizing accuracy in a single phase. *Quick check*: Track that length decreases in stage 1 and accuracy improves in stage 2.
- **Alternating Optimization**: Switches between length loss and accuracy loss based on current accuracy relative to threshold. *Why needed*: Allows each objective to be optimized without interference. *Quick check*: Log phase activations and ensure they correlate with accuracy relative to threshold.

## Architecture Onboarding
**Component map**: Reference Policy -> Accuracy Evaluator & Length Calculator -> Constraint Controller -> Loss Selector -> Optimizer -> Trainable Model. Outputs from Trainable Model loop back to Accuracy Evaluator & Length Calculator.
**Critical path**: (1) Trainable Model generates response. (2) Accuracy Evaluator compares response to reference (from Reference Policy) to compute batch accuracy; Length Calculator computes normalized token count. (3) Constraint Controller checks if accuracy ≥ threshold; if true, Loss Selector chooses length loss; else, chooses accuracy loss (e.g., cross-entropy). (4) Optimizer updates model parameters. In two-stage mode, Constraint Controller also monitors length budget: stage 1 forces length minimization until convergence; stage 2 applies a hard constraint while maximizing accuracy.
**Design tradeoffs**: 
- Reference policy size vs. compute cost; larger reference gives higher threshold but is slower.
- Threshold value: trade-off between allowed shortening and accuracy preservation.
- Alternating frequency (per step vs. per epoch) affects stability.
- Two-stage simplifies optimization but requires careful handoff; joint training is simpler but may suffer gradient conflict.
- Normalization choice (reference length vs. fixed constant) influences fairness across tasks.
**Failure signatures**: 
- Accuracy never exceeds threshold → length loss never applied → no token reduction.
- Length plateau in stage 1 → check loss weight or learning rate.
- Accuracy drop in stage 2 → length constraint too strict; reduce penalty or increase budget.
- Persistent phase oscillations → threshold too tight or learning rates mismatched.
- Degenerate outputs (e.g., loops) → model exploiting length metric without meaningful content.
**Exactly 3 first experiments**:
1. Threshold Sensitivity: Train CRT with thresholds at 90%, 95%, and 98% of reference accuracy. Evaluate token reduction and accuracy to find a robust operating point.
2. Two-Stage Ablation: Compare full CRT (two-stage) against ablations: (a) length-only training, (b) accuracy-only training with fixed length penalty, and (c) alternating without explicit stages. Measure convergence and final performance.
3. Reference Policy Scale: Use reference policies of different sizes (1.5B vs. 7B) while keeping the trainable model fixed. Assess impact on training stability, token reduction, and final accuracy.

## Limitations
- Generalizability uncertain: results only on DeepSeek-1.5B and GSM8K; may not hold for larger models or other reasoning tasks.
- Training overhead and hyperparameter sensitivity not fully explored; missing cost-benefit metrics.
- Potential overfitting to GSM8K benchmark; performance on diverse datasets unknown.

## Confidence
- Token reduction with maintained accuracy: High (specific experiment), Medium (generalization)
- Highest AES scores: Medium
- Reduced internal redundancy (compression ratio): High
- Fine-grained verbosity control via intermediate checkpoints: Medium

## Next Checks
1. Replicate CRT on at least two additional model families (e.g., Llama-2, Mistral) and two diverse reasoning datasets (e.g., MATH, CommonsenseQA) to test transferability.
