# One Language, Two Scripts: Probing Script-Invariance in LLM Concept Representations

## Quick Facts
- **arXiv ID**: 2603.08869
- **Source URL**: https://arxiv.org/abs/2603.08869
- **Reference count**: 8
- **Primary result**: Sparse Autoencoder features in Gemma models exhibit script-invariant semantic alignment, with average Jaccard similarity of 0.58 across Latin and Cyrillic scripts, rising to 0.65 in the 27B parameter model.

## Executive Summary
This paper investigates whether Sparse Autoencoder (SAE) features in large language models encode abstract semantic concepts or remain tied to surface-level, script-specific tokenization. By exploiting Serbian digraphia—where the same language can be written in Latin or Cyrillic scripts with completely disjoint tokenizations—the authors conduct a controlled study across the Gemma model family (270M to 27B parameters). They measure the overlap of active SAE features for identical sentences rendered in the two scripts, finding substantial similarity (average Jaccard 0.58) far above random baselines (~0.28). Script switching induces less representational divergence than paraphrasing within the same script, and even cross-script paraphrases of rare sentences maintain high overlap (~0.47), arguing against memorization as the sole cause. Notably, script invariance strengthens with model scale, reaching 0.65 for the 27B model while random baselines fall. These results suggest that SAE features capture meaning at an abstraction level that transcends orthographic tokenization.

## Method Summary
The authors use Serbian digraphia as a natural experiment: for a set of sentences, they generate both Latin-script and Cyrillic-script versions, which are tokenized with disjoint vocabularies. They extract activations from a fixed layer of various Gemma models, then apply a sparse autoencoder trained on those activations to obtain a high-dimensional feature representation. For each sentence, they identify the top‑k most active SAE features, producing a binary feature set. The Jaccard similarity (intersection over union) between the feature sets of the two script versions is computed as a measure of script invariance. This process is repeated across model scales and for paraphrased sentences to probe the robustness of invariance. Random baselines are constructed by pairing unrelated sentences across scripts to account for chance overlap.

## Key Results
- Average cross‑script Jaccard similarity of active SAE features: **0.58** (vs random baseline ~0.28).
- Cross‑script cross‑paraphrase similarity remains high (~0.47) even for low‑frequency sentences, challenging memorization explanations.
- Invariance increases with model size: **0.65** for the 27B parameter model, while random baselines decrease, indicating improved semantic abstraction at scale.

## Why This Works (Mechanism)
SAE features are trained to efficiently reconstruct model activations, which themselves encode contextual meaning. Because the model’s forward pass yields similar activation patterns for semantically equivalent inputs irrespective of script, the SAE learns to capture these shared patterns. The high Jaccard overlap thus reflects an underlying representation that is largely independent of orthographic form. The scaling trend further suggests that larger models develop a more abstract, script‑agnostic semantic space, possibly by integrating richer multilingual knowledge and by refining token embeddings to collapse script‑specific variations.

## Foundational Learning
- **Sparse Autoencoder (SAE)**: Learns a sparse code to reconstruct activations, yielding interpretable features. *Why needed*: To translate continuous activations into discrete, human‑interpretable concepts. *Quick check*: Does the encoder achieve low reconstruction error with <10% active features per sample?
- **Script Invariance**: The property that representations remain consistent across different writing systems. *Why needed*: To test whether concepts are truly semantic rather than surface‑form bound. *Quick check*: Do feature correlations exceed those between unrelated sentences in the same script?
- **Jaccard Similarity**: Set overlap metric (|A∩B|/|A∪B|). *Why needed*: Quantifies similarity between active feature sets. *Quick check*: Compute on two small integer sets to verify formula.
- **Digraphia**: A single language expressed in multiple scripts (e.g., Serbian in Latin and Cyrillic). *Why needed*: Provides a natural control with identical semantics but disjoint tokenizations. *Quick check*: Confirm direct word‑to‑word mapping between the two Serbian scripts.

## Architecture Onboarding
**Component map** (plain text flow):
Raw Text (Latin/Cyrillic) -> Script‑specific Tokenizer -> Gemma Model -> Activation Hook -> Sparse Autoencoder -> Sparse Feature Vector -> Top‑k Threshold -> Active Feature Set -> Jaccard Similarity Calculator

**Critical path**:
1. Align parallel Latin/Cyrillic sentence pairs.
2. Tokenize each sentence with its corresponding tokenizer.
3. Perform a forward pass through the Gemma model and extract activations from a predetermined layer.
4. Encode activations via the SAE to obtain feature logits.
5. Apply a top‑k selection to derive a binary feature presence vector.
6. Compute Jaccard similarity for each pair.
7. Aggregate results across the dataset and model scales.

**Design tradeoffs**:
- *SAE vs raw activations*: SAE enhances interpretability but introduces reconstruction error and requires training.
- *Layer choice*: Deeper layers carry more semantic information but may be noisier for feature extraction.
- *Top‑k size*: Smaller k focuses on the most salient features but risks missing finer overlaps; larger k increases coverage but adds noise.

**Failure signatures**:
- Cross‑script Jaccard near random baseline → no script invariance detected.
- High variance in Jaccard across sentences → instability in the invariance property.
- Absence of scaling trend (no increase with model size) → contradicts the abstraction‑improvement hypothesis.

**First three experiments**:
1. Reproduce random baseline Jaccard by shuffling script‑pairings.
2. Measure script invariance across all Gemma scales on a held‑out test set.
3. Compare within‑script paraphrases to cross‑script paraphrases to quantify relative divergence.

## Limitations
- Generalizability is limited to Serbian digraphia; other script pairs (e.g., Hindi‑Urdu, Chinese scripts) may exhibit different behavior due to deeper linguistic or cultural divergences.
- SAE features are partially opaque; high overlap could reflect shared syntactic or surface patterns rather than pure semantics, despite controlled baselines.
- Potential dataset contamination (e.g., parallel Latin/Cyrillic texts in training data) might artificially inflate invariance, though the authors implement controls to mitigate this.

## Confidence
- **Empirical findings (script‑invariance metrics)**: High confidence.
- **Interpretation as semantic abstraction**: Medium confidence.
- **Scaling hypothesis (larger models → more invariance)**: Medium confidence.

## Next Checks
1. **Cross‑linguistic replication**: Test script invariance on additional language pairs with disjoint scripts and minimal mutual intelligibility (e.g., Kazakh Latin vs. Cyrillic, Malay Latin vs. Jawi).
2. **Controlled memorization test**: Generate *nonce* sentences (syntactically valid but semantically nonsensical) in both scripts and measure SAE overlap; minimal overlap would strengthen the non‑memorization claim.
3. **Feature‑level probing**: For a subset of high‑overlap features, conduct interpretability audits (e.g., activation maximization, human evaluation) to verify whether they encode semantic concepts versus script‑agnostic lexical/grammatical features.
