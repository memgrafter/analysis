# QP-OneModel: A Unified Generative LLM for Multi-Task Query Understanding in Xiaohongshu Search

## Quick Facts
- arXiv ID: 2602.09901
- Source URL: https://arxiv.org/abs/2602.09901
- Reference count: 40
- Primary result: Unified generative LLM for query parsing yields 7.35% offline gain over BERT, +0.21% DCG and +0.044% retention online at Xiaohongshu.

## Executive Summary
QP-OneModel tackles fragmentation in query parsing pipelines for social network search by collapsing multiple discriminative sub‑tasks into a single generative large language model. It employs a domain‑specific backbone adapted to the linguistic characteristics of Xiaohongshu queries and a progressive three‑stage alignment strategy to mitigate error propagation and domain mismatch. The approach demonstrates strong offline improvements (7.35% overall, with NER and Term Weighting F1 up ~9%) and generalizes effectively, outperforming a 32B model on unseen tasks by 7.60% accuracy. In online deployment, it delivers modest but measurable gains in retrieval relevance and user retention. The paper thus offers a compelling unified alternative to traditional cascaded QP systems in SNS search.

## Method Summary
The proposed architecture integrates all query parsing tasks (named entity recognition, term weighting, etc.) into a single generative LLM. A domain‑specific backbone is first pre‑trained on large‑scale SNS query data to capture colloquial expressions and abbreviations. Then a progressive three‑stage alignment—comprising continued pre‑training, supervised fine‑tuning, and reinforcement learning from task rewards—gradually steers the model toward the target tasks while preserving its linguistic adaptability. This unified design eliminates error accumulation from separate classifiers and aligns the model closely with the target domain.

## Key Results
- Offline evaluation: 7.35% overall improvement over BERT baselines; NER F1 +9.01%; Term Weighting F1 +9.31%.
- Generalization test: Outperforms a 32B model by 7.60% accuracy on previously unseen query parsing tasks.
- Online deployment at Xiaohongshu: DCG (retrieval relevance) +0.21%, user retention +0.044%.

## Why This Works (Mechanism)
The unified generative LLM eliminates cascaded error propagation by producing all QP outputs simultaneously. The domain‑specific backbone ensures the model understands the informal language and entity variations typical of SNS queries. The progressive three‑stage alignment first grounds the model in the domain (continued pre‑training), then teaches task‑specific structures (SFT), and finally refines outputs based on task rewards (RL), collectively reducing domain mismatch and boosting performance.

## Foundational Learning
- **Generative LLMs for Structured Prediction**: Enables flexible generation of multiple structured outputs in one pass. *Why needed?* Avoids separate models and allows joint learning. *Quick check:* Are predicted structures syntactically valid and constraint‑compliant?
- **Progressive Alignment**: Gradually adapts a pre‑trained model to downstream tasks, mitigating catastrophic forgetting. *Why needed?* Maintains general language knowledge while specializing. *Quick check:* Does performance on intermediate checkpoints show steady improvement?
- **Domain‑Specific Backbone**: Pre‑trains on in‑domain data to capture niche terminology and slang. *Why needed?* General LLMs may mis‑handle SNS‑specific expressions. *Quick check:* Does the backbone show higher perplexity on in‑domain vs. out‑of‑domain queries?
- **Unified Multi‑Task Learning**: Shares a single model across tasks, promoting common representations. *Why needed?* Reduces computational overhead and simplifies deployment. *Quick check:* Are gradients from different tasks balanced without one dominating?
- **Error Propagation Mitigation**: By generating all outputs jointly, mistakes in one task don’t cascade to others. *Why needed?* Cascaded discriminative pipelines compound errors. *Quick check:* Compare end‑to‑end error rates with pipeline approaches on identical data.

## Architecture Onboarding
- **Component map**: Input Query -> Domain‑Specific LLM Backbone -> Stage 1: Continued Pre‑training -> Stage 2: Supervised Fine‑tuning -> Stage 3: Reinforcement Learning -> Unified Generative Head -> Structured Outputs (NER, Term Weight, etc.)
- **Critical path**: The data flow from raw query through the backbone, through the three alignment stages that shape the model’s behavior, finally to the generative head that emits all required QP fields in a single forward pass.
- **Design tradeoffs**: A single generative model simplifies serving and eliminates pipeline errors but may increase inference latency and require careful output formatting. The domain backbone improves relevance but adds pre‑training cost. Progressive alignment needs substantial task‑specific data and compute for RL.
- **Failure signatures**: Sudden drops in specific task F1 (e.g., NER) may indicate mis‑scaled loss weights during alignment. Inconsistent output format (missing fields, invalid JSON) suggests insufficient constraint enforcement. Unchanged performance after alignment stages could reflect stage interference or poor reward shaping.
- **First three experiments**: 1) Offline comparison against the existing discriminative BERT pipeline on a held‑out test set. 2) Ablation study removing each alignment stage to quantify its contribution. 3) Zero‑shot generalization evaluation on a set of previously unseen query parsing tasks to test adaptability.
