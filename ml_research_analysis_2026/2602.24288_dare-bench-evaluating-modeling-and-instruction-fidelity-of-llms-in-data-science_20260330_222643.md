# DARE-bench: Evaluating Modeling and Instruction Fidelity of LLMs in Data Science

## Quick Facts
- **arXiv ID:** 2602.24288
- **Source URL:** https://arxiv.org/abs/2602.24288
- **Reference count:** 40
- **Primary result:** Training-focused benchmark for data science agent evaluation with verifiable ground truth and substantial performance gains from fine-tuning

## Executive Summary
DARE-bench addresses the need for standardized evaluation and training data in data science agent development. The benchmark provides 6,300 verifiable tasks derived from Kaggle datasets across classification, regression, and time-series forecasting domains. Unlike existing benchmarks that rely on human judges, DARE-bench uses ground truth outcomes from executing reference solutions, enabling reproducible evaluation of both instruction-following fidelity and predictive performance. The benchmark demonstrates that strong general-purpose models struggle on these tasks, but fine-tuning on DARE-bench training data yields substantial improvements—up to 1.83× for supervised fine-tuning and over 8× for reinforcement learning.

## Method Summary
DARE-bench creates a comprehensive evaluation framework for data science agents by generating verifiable tasks from real-world datasets and providing training data through rejection sampling. The approach combines controlled execution environments with ground truth comparison to enable reproducible assessment of both instruction-following and machine learning modeling capabilities. Training data is generated by filtering successful trajectories, supporting both supervised fine-tuning and reinforcement learning applications. The benchmark covers diverse domains including health, finance, and education, with evaluation metrics designed to handle the specific characteristics of each task type.

## Key Results
- Strong general-purpose models struggle on DARE-bench tasks despite excelling on other benchmarks
- Supervised fine-tuning on DARE-bench training data improves performance by up to 1.83×
- Reinforcement learning on DARE-bench training data yields over 8× improvement in instruction-following and predictive performance
- The benchmark enables reproducible evaluation through controlled execution and verifiable ground truth

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Using verifiable ground truth instead of human judges enables reproducible, scalable evaluation and training.
- **Mechanism:** Verifiable ground truth provides an objective outcome that can be automatically checked without human intervention, removing variability and cost from evaluation.
- **Core assumption:** Ground truth outcomes exist and are deterministic for the task domain.

### Mechanism 2
- **Claim:** Rejection sampling creates high-quality training data by selecting only successful, diverse trajectories.
- **Mechanism:** By sampling multiple attempts and filtering for valid, diverse outcomes, the method ensures training data represents both successful strategies and varied problem-solving approaches.
- **Core assumption:** Multiple valid solution paths exist and can be efficiently sampled.
- **Evidence anchors:**
  - [abstract] "Using DARE-bench training tasks for fine-tuning can substantially improve model performance"
  - [section] "We generate data for supervised fine-tuning through rejection sampling using task-independent filters"

### Mechanism 3
- **Claim:** Controlled randomness and deterministic execution enable process-aware evaluation.
- **Mechanism:** By fixing seeds and controlling environmental factors, the same instruction-following process produces identical outcomes, making process fidelity measurable through final results.
- **Core assumption:** Data science workflows can be made deterministic through controlled execution.

## Architecture Onboarding

- **Component map:** Data curation pipeline (web crawling + LLM task formulation) -> Sandbox execution environment (code execution with time limits) -> Evaluation harness (metric calculation and ground truth comparison) -> Training data generation (rejection sampling + filtering) -> Model fine-tuning/RL training modules

- **Critical path:** Task generation → Execution in sandbox → Ground truth comparison → Performance metrics → Training data filtering

- **Design tradeoffs:**
  - Verifiability vs. coverage (restrictive licenses limit open-source subset)
  - Reproducibility vs. real-world complexity (controlled randomness vs. natural variation)
  - Evaluation cost vs. accuracy (multiple runs vs. single evaluation)

- **Failure signatures:**
  - Non-deterministic outcomes breaking reproducibility
  - Insufficient valid trajectories for training data generation
  - Sandbox execution failures due to resource constraints

- **First 3 experiments:**
  1. Run single task through full pipeline to verify sandbox execution and ground truth comparison
  2. Test rejection sampling with different validity thresholds on small task set
  3. Evaluate model fine-tuning with varying amounts of training data to establish performance scaling

## Limitations
- Reliance on verifiable ground truth assumes all data science tasks have deterministic outcomes
- Controlled randomness may not capture real-world non-deterministic elements in data science workflows
- Effectiveness depends on quality of reference solutions representing valid approaches across diverse domains
