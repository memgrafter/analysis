# Offline Decision Transformers for Neural Combinatorial Optimization: Surpassing Heuristics on the Traveling Salesman Problem

## Quick Facts
- **arXiv ID:** 2603.25241  
- **Source URL:** https://arxiv.org/abs/2603.25241  
- **Reference count:** 31  
- **Primary result:** The method consistently outperforms all four training heuristics (Nearest Neighbor, Nearest Insertion, Farthest Insertion, Simulated Annealing) on TSP instances of sizes N=20, 50, and 100, with optimality gaps reduced e.g., from 12.36% to 6.07% on SA-trained data for N=100.

## Executive Summary
This paper introduces an offline Decision Transformer framework for solving the Traveling Salesman Problem, shifting from online reinforcement learning to learning from static heuristic solution datasets. By integrating a Pointer Network to manage instance-dependent action spaces and employing expectile regression for optimistic Return-to-Go (RTG) conditioning, the model synthesizes superior tour construction strategies. It achieves lower optimality gaps than the heuristics it was trained on across multiple problem sizes, demonstrating the potential of offline RL for combinatorial optimization without environment interaction.

## Method Summary
The approach trains a Decision Transformer on TSP solution trajectories generated by four heuristics (NN, NI, FI, SA). Architecture-wise, a transformer encoder produces node embeddings from city coordinates and predicts a scalar RTG. A causal decoder, conditioned on the RTG and current node embedding, uses a Pointer Network head to select the next unvisited node via attention over all node embeddings. Training uses a multi-task loss: cross-entropy for action prediction and expectile loss (α=0.99) for optimistic RTG prediction. During inference, the encoder-predicted RTG guides the decoder autoregressively, often with a positive offset to counteract conservative RTG estimates.

## Key Results
- Outperforms all four training heuristics (NN, NI, FI, SA) on TSP instances of sizes N=20, 50, 100.
- For SA-trained data at N=100, optimality gap reduced from 12.36% (heuristic) to 6.07%.
- Ablation studies confirm optimistic RTG prediction via expectile regression is critical, and RTG conditioning is essential beyond simple behavior cloning.

## Why This Works (Mechanism)

**Mechanism 1: Pointer Network for Variable Action Spaces**  
- **Claim:** Integrating a Pointer Network allows the Decision Transformer to handle the instance-dependent, variable action space of node selection in the TSP.  
- **Mechanism:** The Pointer Network replaces the fixed action head with an attention mechanism over input node embeddings, generating a probability distribution dynamically over valid, unvisited nodes.  
- **Core assumption:** The model can learn a constructive policy by mapping from the current partial tour state to a distribution over the same set of input nodes.  
- **Evidence anchors:** Abstract and Section 2.3 describe the pointer mechanism; analogous architectures are used in other TSP solvers like Graph Neural Networks are Heuristics.  
- **Break condition:** If node embeddings lack discriminative power, the pointer attention fails to produce meaningful probabilities, leading to random tour construction.

**Mechanism 2: Optimistic RTG Conditioning via Expectile Regression**  
- **Claim:** Using expectile regression to predict an optimistic Return-to-Go enables the model to synthesize trajectories with better returns than present in the training data.  
- **Mechanism:** The RTG predictor is trained with expectile loss (α>0.5) to overestimate the true RTG; this optimistic value then conditions the policy during inference to seek higher rewards.  
- **Core assumption:** The dataset contains high-quality trajectory fragments that can be recombined into superior full solutions; an optimistic RTG acts as a target for such recombination.  
- **Evidence anchors:** Abstract and Section 2.4 define expectile loss; Section 3.4 shows α=0.99 outperforms α=0.5; Section 3.5 shows adding a positive offset to predicted RTG improves performance, indicating native conservatism.  
- **Break condition:** If the dataset is low-quality, an optimistic RTG may condition the policy to seek unachievable returns, causing invalid tours or collapse.

**Mechanism 3: Multi-Task Learning over Behavior Cloning**  
- **Claim:** The combined loss (cross-entropy for actions + expectile loss for RTG) enables goal-conditioned policy learning beyond simple imitation.  
- **Mechanism:** The RTG prediction task forces the model to learn an approximate value function for partial tours; under optimistic RTG conditioning, this shapes action selection toward higher-reward trajectories.  
- **Core assumption:** Predicting final outcomes from partial sequences provides a useful signal for solution quality, aligning policy with return maximization.  
- **Evidence anchors:** Section 2.5 defines total loss; Table 1 shows DT outperforms BC (fixed RTG=0); ablations in Section 3.4 support predicted RTG over fixed targets.  
- **Break condition:** Loss weighting imbalance (e.g., too high RTG loss weight) can degrade action prediction accuracy, harming tour construction.

## Foundational Learning
- **Pointer Networks**: Needed to handle variable-sized action spaces where valid next nodes are instance-specific. Quick check: How does the attention mechanism ensure only unvisited nodes receive probability mass? (via masking visited nodes during softmax).
- **Decision Transformer**: Provides an offline RL framework where a transformer generates trajectories conditioned on desired return using static demonstrations, avoiding online interaction. Quick check: What is the key difference in training data format between behavioral cloning and Decision Transformer? (DT uses sequences of states, actions, and RTGs; BC uses state-action pairs only).
- **Expectile Regression**: Used to train the RTG predictor to be optimistic by assigning asymmetric weight to prediction errors. Quick check: For loss `|α-1(ˆRt < R̃t)| · (ˆRt − R̃t)^2` with α=0.99, is over-prediction (R̃t > ˆRt) or under-prediction (R̃t < ˆRt) penalized more? (under-prediction, since α>0.5 emphasizes cases where predicted < true).

## Architecture Onboarding
- **Component map**: Encoder processes graph into node embeddings and predicts RTG; Decoder (causal transformer) uses RTG and current node embedding to compute hidden state; Pointer Head attends to node embeddings to output action distribution; RTG Head outputs scalar from encoder. Flow: Graph -> Encoder -> Node Embeddings & RTG -> Decoder + Pointer Head (autoregressive steps) -> Tour.
- **Critical path**:
  1. Input graph G -> Encoder -> Node embeddings f_e_i.
  2. Initialize with start node (depot) embedding f_e_1 and RTG token (predicted or true).
  3. For t=1 to N-1:
     a. Decoder attends to sequence (RTG_t, f_e_t) and all f_e_i -> h_a_t.
     b. Pointer: Compute u_{t+1,i} = (h_a_t · f_e_i) / sqrt(d) -> softmax (mask visited) -> select σ_{t+1}.
     c. RTG Predict: Predict ˜R_{t+1} from decoder state.
     d. Append f_e_{t+1} (selected node) and ˜R_{t+1} to sequence.
  4. Output tour (σ_1, ..., σ_N).
- **Design tradeoffs**:
  - Fixed vs. Predicted RTG: Predicted RTG enables instance-specific conditioning but adds complexity; fixed targets (e.g., 0) fail to adapt to instance difficulty.
  - Optimism (α): Higher α (e.g., 0.99) encourages optimism and better solutions but may cause training instability.
  - Pointer Network: Essential for variable actions but incurs O(N) computation per step.
- **Failure signatures**:
  1. No improvement over behavior cloning, especially on NN data, indicating ineffective RTG conditioning or low dataset diversity.
  2. Degenerate tours with fixed RTG=0, showing inability to extrapolate RTG scale from uninformative conditioning.
  3. Performance drop with increasing problem size (N=100), suggesting RTG prediction struggles with scaling.
- **First 3 experiments**:
  1. Reproduce Table 1: Train on each heuristic dataset (NN, NI, FI, SA) for N=20/50/100; compute optimality gaps; compare to heuristics and include BC baseline.
  2. Ablation on RTG Conditioning: Train with RTG fixed to 0 (BC) vs. predicted RTG (DT); measure gap difference to isolate RTG contribution.
  3. RTG Offset Sensitivity Test: For a trained model (e.g., SA, N=100), add constant offset k to predicted RTG during inference; sweep k ∈ [−2.0, 2.0] to find optimal positive k confirming conservative RTG estimation.

## Open Questions the Paper Calls Out
1. How can RTG prediction be improved to avoid underestimation for larger TSP instances? (The paper notes conservism worsens with size.)
2. Does training on diverse heuristic datasets or expert solutions yield policies that outperform single-heuristic training and generalize better?
3. Why does the method fail to surpass behavior cloning on Nearest Neighbor data, and how can this be addressed? (Attributed to low action diversity.)
4. Do the results generalize to non-uniform or constrained real-world TSP instances? (Evaluation limited to uniform synthetic data.)
5. Would scaling up the transformer architecture improve RTG prediction and solution quality for larger problems? (No capacity ablation performed.)

## Limitations
- Evaluation restricted to uniform Euclidean TSP instances; generalizability to clustered or constrained real-world distributions is unknown.
- Performance on Nearest Neighbor data shows minimal improvement, likely due to low diversity in action patterns, limiting the DT's ability to synthesize better solutions.
- Optimality gaps remain above 6% for N=100, indicating scalability challenges and room for improvement in solution quality.

## Confidence
- Pointer Network integration for variable action spaces: **High** (standard architectural solution).
- Optimistic RTG via expectile regression: **Medium** (ablations positive but robustness and stability unproven).
- Multi-task learning over behavior cloning: **Medium** (BC consistently worse, but possible overfitting on limited data).
- Overall TSP performance surpassing heuristics: **Medium** (strong results on uniform instances, but gaps and generalizability issues persist).
