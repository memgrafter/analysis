# GOT-JEPA: Generic Object Tracking with Model Adaptation and Occlusion Handling using Joint-Embedding Predictive Architecture

## Quick Facts
- **arXiv ID:** 2602.14771
- **Source URL:** https://arxiv.org/abs/2602.14771
- **Reference Count:** 40
- **Primary Result:** Achieves state-of-the-art performance on seven benchmarks, with top robustness on VOT2022 and superior success on out-of-distribution datasets like A VisT (63.7% SUC).

## Executive Summary
Current generic object trackers struggle to generalize to unseen targets and handle occlusions effectively. GOT-JEPA addresses these issues through a two-part design. First, it extends the Joint-Embedding Predictive Architecture (JEPA) for pre-training a robust model predictor: a frozen teacher generates pseudo-tracking models from clean frames, while a student predictor learns to replicate them from corrupted inputs, building invariance to occlusions and distractors. Second, OccuSolver integrates a point tracker, conditioned on object priors from the GOT tracker, to produce fine-grained, pixel-level visibility states. This visibility signal refines the tracker’s features and labels, creating a feedback loop that progressively improves adaptation. On multiple benchmarks, the combined system sets new standards for accuracy and robustness, particularly on challenging out-of-distribution data.

## Method Summary
GOT-JEPA’s core innovation is a pre-training strategy for the model predictor within a tracking-by-detection framework. A frozen teacher predictor (from a pretrained ToMP) generates a target tracking model from a clean current frame, given historical context. A student predictor must match this model when given a corrupted version of the same frame (via feature-space copy-paste augmentation). This enforces invariance (via L_inv) and output decorrelation (via L_cov). After pre-training, the student predictor is attached to classification and regression decoders for end-to-end tracking fine-tuning.

OccuSolver is a parallel branch that adapts a frozen CoTracker point tracker. It conditions the point tracker on object priors (reference bounding boxes and masks) from the main tracker using a Prior Encoder. The point tracker’s iterative transformer is fine-tuned with lightweight adapters (light-Trans, ScaleNet) to align its features with the tracker’s space. The sparse point trajectories and visibility scores are converted into a dense "energy map" via a mapping function and fused with the tracker’s current-frame feature through an Ensemble Network. This visibility-augmented feature refines localization. The tracker and OccuSolver are trained end-to-end with a dual-supervision loss that uses both point-tracker and GOT labels.

## Key Results
- Out-of-distribution robustness: A VisT (63.7% SUC), NfS (70.8% SUC), OTB-100 (73.2% SUC).
- In-distribution accuracy: LaSOT (85.3% NPr), TrackingNet (90.6% NPr).
- VOT2022: Top robustness (0.898) and AUC (0.728).

## Why This Works (Mechanism)

### Mechanism 1: Invariant Model Prediction via JEPA Pre-training
**Claim:** GOT-JEPA pre-training improves the model predictor’s generalization to unseen targets and adverse observations (occlusions, distractors) by forcing it to reconstruct a stable tracking model from corrupted inputs, using a clean-teacher pseudo-model as the target.
**Mechanism:** The frozen teacher predictor generates a pseudo-tracking model (ω̂) from a clean current frame conditioned on historical context. The identically conditioned student predictor must match ω̂ when its current frame is corrupted via feature-space copy-paste. The invariance loss (L_inv, Eq. 3) aligns student and teacher outputs; the covariance loss (L_cov, Eq. 4) regularizes the student’s output space. This explicitly trains robustness.
**Break Condition:** Teacher models become unstable or corruptions are unrealistic, causing the student to mimic noise instead of learning invariance.

### Mechanism 2: Fine-Grained Occlusion Awareness via Adapted Point Tracker
**Claim:** OccuSolver provides pixel-level, object-aware visibility states by adapting a point tracker with high-level priors from the GOT tracker, enabling detailed occlusion pattern capture.
**Mechanism:** A pretrained CoTracker is conditioned on object priors (reference labels *p_a, p_b*) via a Prior Encoder added to frame features. Its iterative transformer is fine-tuned (light-Trans, ScaleNet) using a Ladder Side Network. A mapping function (Gaussian kernel) converts sparse point coordinates and visibility scores into a dense energy map (E), which modulates the tracker’s current feature (z_cur → ż_cur).
**Break Condition:** Tracker’s initial object priors are Highly inaccurate (e.g., during complete failure), misaligning the point tracker and propagating errors.

### Mechanism 3: Positive Feedback Loop for Progressive Refinement
**Claim:** Tight coupling between GOT-JEPA and OccuSolver creates a loop: the tracker provides better object priors to OccuSolver, which generates better visibility-aware reference labels, improving subsequent model predictions.
**Mechanism:** OccuSolver’s visibility state is integrated into the tracker’s feature space (ż_cur) via the Ensemble Network, yielding more accurate localization. This improved bounding box becomes a higher-quality reference label for the next frame’s model predictor. The dual-supervision loss (Eq. 9) trains this integration end-to-end.
**Break Condition:** Visibility signal is noisy or overconfident (e.g., false negatives on visible regions), causing ż_cur to discard useful cues and amplifying errors over time.

## Foundational Learning

### Concept: Joint-Embedding Predictive Architecture (JEPA)
**Why needed:** GOT-JEPA extends JEPA from predicting image features to predicting *tracking models* (adaptive filters). This shift requires a general skill—model generation for any target—and JEPA’s frozen-teacher prediction in representation space provides stable pseudo-supervision for this.
**Quick check:** Why is a frozen teacher used in JEPA for tracking instead of a jointly trained student-teacher pair?

### Concept: Tracking-by-Detection Paradigm
**Why needed:** The baseline and proposed tracker follow this paradigm. It defines the architecture: a model predictor dynamically generates a discriminative model (filter) from historical context, and a localization head uses it to detect the current object. Understanding this flow reveals where GOT-JEPA (predictor pre-training) and OccuSolver (feature refinement) intervene.
**Quick check:** In tracking-by-detection, what is the role of the online-predicted "model," and why is its accuracy critical?

### Concept: Point Tracking (e.g., CoTracker)
**Why needed:** OccuSolver leverages a point tracker to obtain fine-grained physical trajectories and visibility. The core challenge is adapting this class-agnostic, point-centric method to be object-aware for generic tracking, requiring understanding of its iterative transformer architecture and query-point interface.
**Quick check:** Why is a standard point tracker not directly suitable for generic object tracking, and what two modifications does OccuSolver apply to adapt it?

## Architecture Onboarding

- **Component map:** Backbone (ViT-L, frozen) -> Historical Encoder -> Student Model Predictor (ProjNet + Expander) -> Tracking Head (RegDec/ClsDec). Parallel branch: Backbone -> Point Tracker Core (frozen CoTracker) + Light-Trans/ScaleNet (adapters) -> Point/Vis Heads -> Mapping Function -> Ensemble Network -> Modulates tracker’s z_cur -> ż_cur -> Tracking Head.
- **Critical path (inference):** 1) Input streaming frames and initial box. 2) For frame *t*, encode reference frames/labels. 3) Track Path: extract z_cur, student predictor outputs ω. 4) OccuSolver Path: extract frames, encode object priors, fine-tune point tracker, output point visibility map. 5) Ensemble Network fuses z_cur and point map -> ż_cur. 6) Tracking Head uses ω and ż_cur to predict box/score. 7) New label becomes historical context for *t+1*.
- **Design tradeoffs:**
  - *JEPA Teacher Fidelity vs. Student Flexibility:* Frozen teacher (from ToMP) offers stable targets but cannot adapt; a trainable teacher might drift. Tradeoff: stability vs. potential for better targets.
  - *Point Tracker Granularity vs. Cost:* More query points yield finer visibility maps but increase latency (~22.8% of cost). Fixed 128 points balances detail and efficiency.
  - *Corruption Realism vs. Stability:* Feature-space copy-paste efficiently simulates distractors but may create unrealistic patterns; simpler masking removes too much semantics.
  - *OccuSolver Integration Overhead:* Adapters and Ensemble Network add parameters (7.7M) and latency (~3.4%) for robustness gains.
- **Failure signatures:**
  - JEPA collapse: L_inv stagnates/increases; Tab. V(3) worse than (1).
  - OccuSolver misalignment: Low visibility on clean objects or high on background; degradation on occlusion attributes (Tab. VII).
  - Feedback loop amplification: Tracker fails to recover after occlusion; degraded performance over time.
- **First 3 experiments:**
  1. Isolate JEPA pre-training: Train only student predictor on corrupted/clean pairs (L_inv + L_cov) with frozen teacher. Freeze all else. Evaluate on A VisT/LaSOT using standard ToMP localization. Expect gain over baseline (Tab. V row (3) > (1)).
  2. Validate OccuSolver integration: With JEPA-pretrained predictor (frozen), train only OccuSolver adapters (light-Trans, ScaleNet, Ensemble Net) via dual-supervision loss. Expect gain over tracker without OccuSolver (Tab. V row (5) > (4)); ablation in Tab. XIII.
  3. End-to-end fine-tuning & corruption ablation: Jointly train all trainable components (predictor ProjNet/Expander, OccuSolver adapters, Reg/ClsDec) with copy-paste corruption in student branch. Ablate corruption type (Tab. VIII). Expect final SOTA (Tab. I) and lower validation loss (Fig. 7).

## Limitations
- Detailed architectures for light-Trans, ScaleNet, and Ensemble Network are underspecified, hindering exact reproduction.
- Historical conditioning details (reference frame count/selection) and corruption hyperparameters (feature-grid patch size) are missing.
- The frozen teacher assumption may be fragile; unstable teacher models or unrealistic corruptions could degrade invariance learning.
- OccuSolver relies on accurate tracker priors; under heavy occlusion, misaligned priors could propagate errors through the feedback loop.

## Confidence
- **JEPA pre-training improves robustness:** Medium. Supported by ablations (Tab. V, VI) but teacher stability and corruption realism are open.
- **OccuSolver enables fine-grained occlusion handling:** Medium. Gains on occlusion attributes (Tab. VII) are promising, but point-tracker adaptation specifics are underspecified.
- **Positive feedback loop between components:** Low. Theoretically plausible (Sec. III-C) but direct evidence is scarce; break conditions not thoroughly tested.

## Next Checks
1. **Teacher stability ablation:** Compare performance with frozen teacher vs. jointly trained teacher (EMA) to quantify stable target importance.
2. **Visibility map validation:** On a pixel-level occlusion subset (e.g., A VisT), evaluate OccuSolver’s energy map against true occlusion masks.
3. **Feedback loop stress test:** Inject noise into OccuSolver’s visibility estimates (e.g., random flips) and measure tracking accuracy over time to assess error amplification risk.
