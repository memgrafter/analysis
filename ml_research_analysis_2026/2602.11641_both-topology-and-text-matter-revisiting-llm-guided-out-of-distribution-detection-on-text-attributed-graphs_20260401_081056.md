# Both Topology and Text Matter: Revisiting LLM-guided Out-of-Distribution Detection on Text-attributed Graphs

## Quick Facts
- **arXiv ID:** 2602.11641
- **Source URL:** https://arxiv.org/abs/2602.11641
- **Reference count:** 40
- **Primary result:** LG-Plug reduces FPR95 by at least 7% over topology-driven detectors and by at least 5% over LLM-based baselines, while drastically cutting LLM query costs via cluster-based sampling.

## Executive Summary
Out-of-distribution (OOD) detection on text-attributed graphs (TAGs) is challenged by a gap between topology-driven GNN methods—which underutilize textual semantics—and recent LLM-based approaches that suffer from unreliable OOD priors and high query costs. This paper introduces LG-Plug, a plug-and-play strategy that first aligns graph and text encoders to produce fine-grained node embeddings, then employs clustered iterative LLM prompting with intra-cluster filtering to generate reliable OOD exposures. These exposures are incorporated as a regularization term into existing topology-driven detectors without architectural changes. Experiments on six TAG benchmarks show consistent improvements in FPR95 and AUROC, along with substantial efficiency gains.

## Method Summary
LG-Plug consists of three stages. (1) **Topology-Text Representation Alignment**: A 2-layer GCN and a 12-layer Transformer are jointly trained with node-level contrastive and edge-level alignment losses to produce embeddings that fuse graph structure and textual content. (2) **Consensus-driven OOD Exposure**: Unlabeled node embeddings are clustered (K‑means). For each cluster, near‑centroid nodes are selected as prompts. An LLM is queried iteratively with a dynamic category codebook; if a batch reaches consensus on a category that does not intersect known ID classes, those nodes are added to the OOD exposure set. (3) **Score Regularization**: The exposure set is fed to any topology‑driven detector (e.g., GNNSafe, GRASP) as a margin‑based regularization term, pushing ID scores up and OOD scores down during fine‑tuning. The approach is architecture‑agnostic and requires no changes to the base detector.

## Key Results
- LG‑Plug consistently enhances topology‑driven detectors, reducing FPR95 by at least 7% across six TAG benchmarks.
- It surpasses LLM‑based baselines by at least 5% FPR95 reduction.
- LLM query costs are significantly lowered by orders of magnitude due to cluster‑based sampling, with runtime around 70 seconds on Cora.

## Why This Works (Mechanism)
LG‑Plug successfully bridges the gap between topology‑driven GNNs and LLM‑based semantics by first aligning graph and text modalities at a fine‑grained node level, ensuring that embeddings capture both structural and textual nuances. Clustering these embeddings groups semantically similar nodes, allowing focused LLM queries on representative near‑centroid examples. Iterative prompting with a dynamic codebook aggregates consensus, filtering noise and preventing ID category contamination. The resulting OOD exposures serve as reliable negative examples, enabling a simple margin‑based regularization that cleanly separates ID and OOD score distributions. This synergy yields stronger detectors while drastically curbing LLM usage.

## Architecture Onboarding
**Component map:**  
GCN encoder → Node embeddings (Z) → Text encoder (Transformer) → Node embeddings (H) → Alignment losses (L_node, L_edge) → Aligned embeddings → K‑means clustering → Cluster centroids → Near‑centroid selection (ρ) → LLM prompting with dynamic codebook (B_m) → Consensus check → OOD exposure set (V_exp) → Existing detector (e.g., GNNSafe) → Base scores (s_i) → Margin‑based regularization (L_reg) → Fine‑tuned detector.

**Critical path:**  
1. Train alignment (GCN + Transformer) until convergence.  
2. Cluster unlabeled nodes, pick representative samples.  
3. Run iterative LLM queries per cluster, update codebook.  
4. If batch consensus yields non‑ID categories, add those nodes to V_exp.  
5. Integrate V_exp into detector via L_reg and fine‑tune.

**Design tradeoffs:**  
- **Cluster count (M):** More clusters ↑ purity but ↑ LLM batches (cost). Fewer clusters ↓ cost but risk semantic mixing.  
- **Trials (T) / batch size (b):** More trials or smaller batches improve consensus accuracy but increase API calls.  
- **Regularization weight (β):** Stronger separation helps OOD detection but can distort the detector’s native scoring if excessive.

**Failure signatures:**  
- High ID nodes in V_exp (false OOD): Check B_m ID ratio; increase ρ or decrease batch size.  
- Empty V_exp: Increase M or revisit embedding quality (node classification accuracy).  
- Detector performance drops after L_reg: Lower β; verify margins Δ1, Δ2 relative to ID/OOD energy percentiles.  
- LLM costs sky‑high: Reduce M and/or b; ensure near‑centroid filter (ρ) is not too permissive.

**First experiments (must‑run):**  
1. Measure alignment quality by training a simple classifier on ID nodes; expect >90% accuracy on standard TAGs.  
2. Sweep cluster count M (e.g., 5, 10, 20, 50) and plot FPR95 vs. LLM queries to observe trade‑off.  
3. Perform a small‑scale hyperparameter search for β and margins Δ1, Δ2 on a validation split; record best combination.

## Limitations
- Implementation details (LLM prompt template, margin values, β, stopping criteria) are underspecified, risking reproduction drift.  
- OOD exposure reliability hinges on clustering quality and LLM consensus; false positives or missed OOD types may occur.  
- Evaluation is restricted to six TAG datasets and two base detectors; generalizability to larger graphs or alternative OOD definitions remains unverified.
