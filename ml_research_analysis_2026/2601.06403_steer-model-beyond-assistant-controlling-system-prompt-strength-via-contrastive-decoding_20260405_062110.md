# Steer Model beyond Assistant: Controlling System Prompt Strength via Contrastive Decoding

## Quick Facts
- **ArXiv ID:** 2601.06403
- **Source URL:** https://arxiv.org/abs/2601.06403
- **Reference count:** 40
- **Primary result:** Training-free contrastive decoding scales system prompt influence, yielding up to +8.5 points on IFEval strict accuracy, +45 percentage points on OffTopicEval out-of-domain refusal, and +13% steerability boost on Prompt-Steering.

## Executive Summary
Large language models exhibit a strong prior toward a helpful assistant persona, making it difficult to deviate from this behavior via system prompts alone. This paper introduces "system prompt strength," a training-free method that uses contrastive decoding: at each generation step, logits from a target system prompt are contrasted with those from a default assistant prompt, and the resulting "persona delta" is scaled by a hyperparameter α. Increasing α amplifies the target persona's signal, overriding the default prior. Evaluated across five benchmarks and five model families, the approach substantially improves instruction following, refusal behavior, and persona steering, particularly for tasks conflicting with the assistant prior. The method also reduces sensitivity to prompt wording, offering continuous, retraining-free control over model behavior.

## Method Summary
Given a target system prompt *s* and a default system prompt *d* (e.g., "You are a helpful assistant"), the method modifies next-token logits during autoregressive decoding. For each step *t*, it computes *z_sys_t* (logits conditioned on *s*) and *z_def_t* (logits conditioned on *d*), then combines them as *z_final = z_sys_t + α·(z_sys_t - z_def_t)*. The hyperparameter α controls amplification: α=0 is standard prompting under *s*; higher α upweights tokens more probable under the target persona than the default. This contrast isolates the behavioral signal unique to the target persona and overcomes the strong assistant prior. An alternative uses an explicit negative system prompt instead of *d* for finer-grained control.

## Key Results
- Up to +8.5 points improvement on IFEval strict accuracy by scaling α.
- +45 percentage point increase in out-of-domain refusal on OffTopicEval for high-conflict tasks (e.g., medical assistant).
- +13% boost in steerability on Prompt-Steering; α=1 reduces accuracy variance across five prompt paraphrases by ~70%.

## Why This Works (Mechanism)

### Mechanism 1: Persona Delta Isolation
**Claim:** Contrasting logits between target and default system prompts isolates the unique behavioral "persona delta" that captures instructions conflicting with the default prior.  
**Mechanism:** At each step, compute Δ = *z_sys_t - z_def_t*. This delta suppresses tokens favored by the default assistant and amplifies those promoted by the target persona.  
**Core assumption:** The logit-space difference meaningfully separates persona-specific signal from the base model's helpful-assistant prior, assuming linear and early-captured instruction representations.  
**Evidence anchors:** Formal definition in Equations (3)–(4); related work on contrastive decoding for reasoning (e.g., DoLLa).  
**Break condition:** If the target persona is not encoded in logits (e.g., extreme out-of-distribution), the delta may be noisy or zero.

### Mechanism 2: Amplification via α
**Claim:** Scaling the persona delta by α > 0 amplifies the target persona's influence, allowing the model to overcome its post-training prior.  
**Mechanism:** The final logits *z_final = z_sys_t + αΔ* direct the distribution toward tokens more probable under the target than the default.  
**Core assumption:** The default assistant prior acts as an additive bias in logit space, linearly separable from persona signals.  
**Evidence anchors:** Optimal α correlates with conflict level (Figure 2); improvements across benchmarks with increasing α for counter-prior tasks.  
**Break condition:** Excessive α degrades coherence and capabilities; linear scaling may break for very large α.

### Mechanism 3: Robustness to Prompt Phrasing
**Claim:** Amplifying the delta makes steering more robust to variations in prompt wording.  
**Mechanism:** The contrastive step focuses on what is unique to the target persona relative to the default, stabilizing the signal across paraphrases.  
**Core assumption:** The persona delta is invariant to superficial linguistic changes when semantic equivalence holds.  
**Evidence anchors:** On IFEval, α=1 reduces accuracy variance across five paraphrases compared to α=0 (Table 5.1).  
**Break condition:** If paraphrases change the persona meaning, the delta becomes inconsistent.

## Foundational Learning
- **Concept:** Autoregressive decoding with logit access  
  - **Why needed:** The method modifies next-token logits during generation, requiring understanding of the decoding loop and logit interception.  
  - **Quick check:** In an autoregressive model, at which point in the generation loop are the logits available for modification, and what changes when you alter them?
- **Concept:** Contrastive learning in decoding  
  - **Why needed:** The core innovation uses logit contrast between two prompts to isolate a directional signal.  
  - **Quick check:** Why does (*z_sys_t - z_def_t*) theoretically suppress tokens that are probable under the default assistant but not the target persona?
- **Concept:** System prompts and instruction following  
  - **Why needed:** The method assumes system prompts encode personas; crafting effective *s* and *d* is crucial.  
  - **Quick check:** What makes a "good" default system prompt *d* for this method, and how might its design affect the persona delta?

## Architecture Onboarding
- **Component map:**  
  Base LLM -> Dual prompt processor -> Logit differencer -> Amplifier -> Sampler
- **Critical path:**
  1. Load model and tokenizer with logit output.
  2. For each generation step, construct two contexts: [*d*, user, gen_so_far] and [*s*, user, gen_so_far].
  3. Forward pass both to get *z_def_t* and *z_sys_t*.
  4. Compute *z_steered = z_sys_t + α · (z_sys_t - z_def_t)*.
  5. Sample next token and append; repeat.
- **Design tradeoffs:**
  - Latency: Dual forward passes double compute per step; mitigate via KV-cache sharing for shared prefixes but require careful duplication.
  - α selection: Start with α∈[0.5,1] for most tasks; α>1 for strong counter-prior behaviors but risks coherence.
  - Prompt design: *d* must accurately represent the default prior; a poor *d* yields a noisy delta.
- **Failure signatures:**
  - Over-steering (α too high): Incoherent text, capability drops (e.g., Inverse Capability Acc.High).
  - Under-steering (α too low or bad prompts): Model reverts to default assistant behavior.
  - Cache invalidation: Forgetting to separate KV caches for the two contexts leads to incorrect conditioning.
- **First 3 experiments:**
  1. Baseline sanity check: With α=0 and target prompt *s*, does the model follow *s* at all? If not, prompt may be poor.
  2. Simple constraint task: Use IFEval with a single constraint (e.g., "no commas"). Sweep α∈{0,0.5,1,2} and measure constraint adherence. Expect improvement at α=1, degradation at α=2.
  3. Counter-prior task: Use OffTopicEval (medical assistant refusing off-topic queries). Sweep α and plot refusal rate vs. in-domain acceptance. Expect refusal rate to rise with α while ARID stays stable until high α.

## Open Questions the Paper Calls Out
1. How can the computational overhead (roughly double FLOPs) be reduced without compromising steerability gains?
2. What systematic principles govern the design of effective negative system prompts, and can they be generated automatically for arbitrary target personas?
3. Can a theoretical framework predict the optimal α based on the divergence between target and default model distributions?
4. Does combining system prompt strength with activation steering produce synergistic effects, and if so, how should they be integrated?

## Limitations
- Exact prompt decompositions for IFEval (500+ test items) and full negative prompts for OffTopicEval are unreleased, hindering exact replication.
- Computational overhead and caching optimizations are not explored, leaving a barrier for latency-sensitive applications.
- Generalization beyond the five evaluated benchmarks and model families remains unknown.

## Confidence
- **Persona delta isolation:** Medium confidence (theoretically plausible but relies on strong linearity assumptions not fully validated).
- **Amplification via α:** High confidence (consistently supported across benchmarks with clear empirical trends).
- **Robustness to prompt phrasing:** Medium confidence (evidence limited to IFEval paraphrases; not tested more broadly).
