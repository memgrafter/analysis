# SE-Search: Self-Evolving Search Agent via Memory and Dense Reward
## Quick Facts
- arXiv ID: 2603.03293
- Source URL: https://arxiv.org/abs/2603.03293
- Reference count: 29
- Primary result: SE-Search-3B achieves state-of-the-art average exact match of 0.420 on seven QA benchmarks, a 10.8-point absolute improvement and 33.8% relative gain over Search-R1.

## Executive Summary
Retrieval-augmented generation (RAG) search agents often suffer from noisy document accumulation, limited query diversity, and sparse reinforcement learning feedback, which impede effective information seeking. SE-Search addresses these challenges through three self-evolving mechanisms: memory purification, which distills retrieved documents into concise, relevant memories; atomic query training, which enforces short and diverse search queries; and dense rewards, which provide fine-grained RL signals across query, memory, answer, and format dimensions. The agent operates in a Think-Search-Memorize loop, progressively building a distilled memory while interacting with a retriever (E5-base-v2) and a Wikipedia corpus.

Evaluated on seven question-answering benchmarks (NQ, TriviaQA, PopQA, HotpotQA, 2WikiMultihopQA, Musique, Bamboogle), SE-Search-3B attains an average exact match of 0.420, surpassing the previous state-of-the-art Search-R1 by 10.8 points (33.8% relative gain) and achieving up to 8-point improvements on multi-hop tasks like Bamboogle. Ablations confirm the contribution of each component: memory purification alone boosts performance on Musique by 5 points. Larger model scales (7B, 14B) further improve results, while analysis shows the agent makes fewer search calls (14% reduction) with higher accuracy (14% increase), emits shorter queries, and stores more relevant memory. These findings demonstrate the effectiveness of self-evolving mechanisms for training robust search agents.

## Method Summary
SE-Search is trained on a merged dataset of Natural Questions (NQ) and HotpotQA, comprising 169,615 training samples. The backbone language model is Qwen2.5-3B (with 7B and 14B variants), and the retriever is E5-base-v2, which returns the top-3 Wikipedia documents for each search query. The agent follows a structured prompt template requiring`, `<search>`, `<documents>`, `<memory>`, and `<answer>`. At each step, the policy LLM decides whether to think, search, update memory, or answer; after a `<search>`, the environment injects the retrieved documents into the `<documents>` block. The memory is updated incrementally via a Think-Search-Memorize loop that extracts salient facts from the latest documents and prior memory. Training uses the Group Relative Policy Optimization (GRPO) algorithm with a group size of 10, without a separate value network. The dense reward combines: (1) answer reward R_ans (token-level F1 between predicted and ground-truth answer), (2) memory reward R_mem (Cover Exact Match, which checks if all answer tokens appear in the final memory), (3) query reward R_query based on the number of atomic queries (Algorithm 1), and (4) format reward R_format that penalizes rule violations (exceeding max search turns of 5, invalid actions, or tag mismatches). The query reward coefficient μ decays cosine-wise over 150 steps. Hyperparameters include learning rate 1e-6, KL penalty 0.001, clip 0.2, batch size 256, and training for 320 steps.

## Key Results
- SE-Search-3B achieves average EM 0.420 across all seven benchmarks, a 10.8-point absolute gain over Search-R1.
- Multi-hop tasks see up to 8-point improvement (e.g., Bamboogle); memory purification alone adds 5 points on Musique.
- Scaling to larger models (7B, 14B) further boosts performance. The agent reduces search calls by 14% while increasing accuracy by 14%, uses shorter queries, and stores more relevant memory.

## Why This Works (Mechanism)
### Mechanism 1: Memory Purification
Memory purification filters retrieved documents into a distilled memory using a Think-Search-Memorize template. After each search, the LLM extracts only salient evidence from retrieved documents and updates a dedicated `<memory>` block, discarding irrelevant details. A memory reward based on Cover Exact Match (CEM) encourages the stored content to overlap with the ground-truth answer. The core assumption is that the LLM can reliably identify answer-relevant facts, and a concise memory improves subsequent reasoning compared to raw document streams. Evidence includes the abstract’s mention of the template, Section 3.2’s formalization (Eqs. 7–8), and the self-contained design without external LLMs. A break condition occurs if extraction consistently omits critical information or introduces hallucinations, causing memory to fail in supporting accurate answers.

### Mechanism 2: Atomic Query Training
Atomic query training enforces short, diverse queries via a similarity-threshold counting method (Algorithm 1). Queries are filtered by length bounds (Lmin=10, Lmax=120 characters) and a similarity threshold T=0.3; overly long or too-similar queries are considered invalid. The query reward penalizes excessive searches when the final answer is correct (R_query = -max(1, N_query)) and encourages more searches when incorrect (R_query = min(T_max, N_query)). This shapes both query quality and search frequency. The underlying assumption is that shorter, less similar queries yield more diverse and informative retrieval results, benefiting multi-hop reasoning. Evidence spans the abstract, Section 3.3, and the related Atom-Searcher work. Inappropriate thresholds could suppress useful queries or permit redundancy, impairing evidence coverage.

### Mechanism 3: Dense Rewards
Dense rewards provide fine-grained RL signals across four components: query (R_query), memory (R_mem), answer (R_ans as F1), and format (R_format). The combined reward R_dense = R_ans + α R_mem + γ μ R_query + γ R_format yields richer supervision than sparse outcome-only signals, stabilizing and accelerating training. A cosine decay on μ gradually reduces the influence of the query reward, shifting the agent from exploration to exploitation. The assumption is that graded feedback (F1) and behavioral constraints enable more efficient policy updates. Evidence includes the abstract, Section 3.4’s definitions, and Section 4.4’s analysis showing faster convergence and higher early memory accuracy. Mis-weighted reward terms (e.g., overly strong format penalty) could destabilize learning or suppress exploratory behavior.

## Foundational Learning
- **Group Relative Policy Optimization (GRPO)**: This is the RL algorithm used to optimize the policy without a separate value network and with within-group advantage normalization. It is needed to understand how dense rewards shape the agent’s behavior during updates. Quick check: What are the key differences between GRPO and PPO, and why might GRPO be more suitable for search agents?  
  Answer: GRPO differs from PPO by eliminating the separate value network and normalizing advantages within each trajectory group (size 10). This may be beneficial for search agents because the dense, multi-dimensional rewards (query, memory, answer, format) can be effectively normalized per group, stabilizing training without the need for a value function that might struggle with sparse and heterogeneous rewards.
- **Retrieval-Augmented Generation (RAG)**: The base paradigm of conditioning generation on retrieved documents. SE-Search extends RAG with iterative search and memory, so grasping the single-step RAG pipeline is foundational. Quick check: How does SE-Search’s multi-turn retrieval differ from a single-step RAG pipeline?  
  Answer: Unlike single-step RAG, which retrieves documents once and generates an answer directly, SE-Search performs multiple retrieval iterations interleaved with thinking and memory updates. The agent can dynamically decide when to search, refine queries based on previous results, and maintain a distilled memory that accumulates evidence across turns, enabling complex multi-hop reasoning.
- **Evaluation Metrics: Exact Match vs. F1**: The reward design uses F1 instead of exact match to provide denser, token-level supervision. Understanding the trade-offs clarifies the choice. Quick check: In what ways does F1 offer more graded supervision than exact match for answer generation?  
  Answer: F1 measures the overlap between predicted and ground-truth answer tokens, providing a continuous score between 0 and 1 that reflects partial correctness. Exact match is binary (0 or 1) and gives no credit for near misses. The graded nature of F1 yields denser reinforcement signals, allowing the policy to learn from partially correct answers and accelerate convergence.

## Architecture Onboarding
Component map: Question -> Policy LLM (Qwen2.5-3B) -> actions (think, search, memory, answer) -> Retriever (E5-base-v2) -> Documents -> Memory Buffer (distilled facts) -> Reward Calculator (computes R_dense) -> GRPO Optimizer (updates policy). Reference policy π_ref (fixed) provides KL regularization.

Critical path: For a new question, the agent enters a loop: <think> (decide next action) -> if search emitted, <search> with query, then environment returns top-k documents in <documents>, then <memory> updates distilled facts from documents and previous memory. The loop repeats until an <answer> is produced. The full trajectory (thoughts, queries, documents, memory states, final answer) is stored. After rollout, dense reward is computed for each trajectory. Advantages are normalized within a group of G trajectories (G=10). The policy is updated using the GRPO objective (clipped surrogate with KL penalty). This process repeats over 320 training steps.

Design tradeoffs:
- Memory capacity vs. noise: Larger memory retains more facts but risks including irrelevant information; distilled memory attempts to balance.
- Query diversity vs. length: Very short queries may be ambiguous; overly long ones cause redundancy. The length bounds (10–120 characters) and similarity threshold (T=0.3) are tunable.
- Reward weighting: α (memory weight) and γ (query weight) control signal influence; the decay schedule µ for query reward shifts emphasis over time.
- Group size G: Larger groups stabilize advantage normalization but increase memory consumption.

Failure signatures:
- Low memory Cover EM (<0.3) indicates extraction failures or poor distillation.
- High pairwise query similarity (>0.7) suggests redundancy; the agent may be stuck in a pattern.
- Frequent format violations (e.g., >1 per trajectory) point to decoding or prompt issues.
- Training instability (large KL divergence or high reward variance across the group) may require adjusting β or clip ϵ.
- Degraded multi-hop performance relative to single-hop tasks implies ineffective evidence chaining.

First 3 experiments:
1. **Memory ablation**: Train two agents, one with memory reward (α>0) and one without (α=0). Evaluate memory CEM and final EM on Musique; expect the memory reward to improve both metrics.
2. **Query diversity sweep**: At inference, vary atomic similarity threshold T (0.2, 0.3, 0.5). Measure average query similarity and accuracy on Bamboogle; the default T=0.3 should yield the best trade-off.
3. **Dense reward components**: Replace the F1 answer reward with exact match (binary) and remove format penalty. Compare convergence speed (reward vs. training step) and final F1 on a validation set; the full dense reward combination should converge faster and achieve higher performance.

## Limitations
- SequenceMatch implementation unspecified (e.g., longest common substring, token Jaccard), which directly impacts atomic query counting and thus the query reward.
- Memory update procedure is ambiguous (append vs. overwrite, tokenization for Cover EM), potentially affecting memory quality and training signal.
- Hyperparameter sensitivity (α, γ, decay steps) is not explored; robustness across different settings remains unknown.

## Confidence
- Memory purification (+5 Musique): High
- Atomic query training (shorter queries, fewer searches): Medium
- Dense rewards (explicit ablation vs. sparse): High
- Overall SOTA EM 0.420: Medium
