# ADEPT: Adaptive Dynamic Early-Exit Process for Transformers

## Quick Facts
- **arXiv ID:** 2601.03700
- **Source URL:** https://arxiv.org/abs/2601.03700
- **Reference count:** 40
- **Primary result:** Enables token-level dynamic early exit in both prefill and generation phases, reducing computation by up to 25% in language modeling while matching base model perplexity and achieving a 4× speed-up in classification tasks.

## Executive Summary
ADEPT introduces a method to perform early exit on a per-token basis throughout the entire Transformer forward pass, overcoming the sequential Key-Value (KV) cache dependency that previously restricted early-exit techniques to the prompt or first generation token. It uses a lightweight similarity metric based on the inner product of normalized hidden states to decide when a token’s representation has converged and can exit. For tokens that exit, a shared Hidden State Mapper (HSM) predicts the final hidden state and generates the necessary KV representations for all subsequent skipped layers in parallel. This avoids the costly query, attention, and feedforward operations in those layers, significantly improving inference efficiency without sacrificing accuracy.

## Method Summary
ADEPT modifies the Transformer inference流程 by adding an early-exit decision after each layer for every token. The decision uses a similarity score between the token’s current normalized hidden state and a cumulative “inertia” state (the sum of its previous normalized states). If the score exceeds a threshold δ, the token exits. Upon exit, a shared, lightweight Hidden State Mapper (HSM) takes the token’s current and previous hidden states plus the inertia state and outputs a prediction of the final hidden state (as if processed by all remaining layers). This predicted state is then used to compute the KV projections for all skipped layers via a simple linear projection with the layer’s original KV weight matrices. These KV values are inserted into the cache, allowing subsequent layers and tokens to attend as usual. The HSM is trained while the base model is frozen, using task-specific losses (e.g., cross-entropy for language modeling, MSE for classification).

## Key Results
- Reduces computation by up to 25% in language modeling (GPT-2 XL on WikiText-103) with no increase in perplexity.
- Achieves up to a 4× speed-up in classification tasks (BERT on GLUE) while matching accuracy.
- Improves performance over state-of-the-art early-exit baselines (e.g., DeeBERT, PABEE) by up to 45%.
- Uses 6–20× fewer trainable parameters than per-layer early-exit alternatives.

## Why This Works (Mechanism)

### Mechanism 1: Token-Level Dynamic Exit via Representation Convergence
ADEPT enables dynamic early termination per token in both prefill and generation by evaluating a lightweight similarity metric. For token j at layer i, it computes the inner product between the normalized current hidden state (ˆsh<sub>i,j</sub>) and the cumulative inertia state (sh<sub>inertia,j</sub> = Σ<sub>d=1</sub><sup>i-1</sup> ˆsh<sub>d,j</sub>). A token exits when this similarity exceeds a threshold δ. This works because Transformer representations often stabilize across layers; the inertia state accumulates sufficient information to approximate the final representation. Evidence is provided in the paper’s formal definition (Section 4.1) and contrast with prior work limited to prompt or first-token exits (Section 2). A break condition occurs if token complexity distributions are skewed or convergence is unstable, causing premature or delayed exits.

### Mechanism 2: Shared Hidden State Mapper (HSM) for State Prediction
The HSM is a single lightweight module shared across all layers and tokens that predicts the final hidden state from an early-exited intermediate state. It takes the concatenated current hidden state (sh<sub>i,j</sub>), previous state (sh<sub>i-1,j</sub>), and inertia state (sh<sub>inertia,j</sub>), applies RMS normalization, a 3×3 convolution, and an MLP with skip connections to output ˜sh<sub>N,j</sub>. The core assumption is that one module can generalize across layers and tokens to accurately map intermediate to final states. Evidence includes the architecture description (Section 4.2, Table S1) and parameter efficiency (Table 2: 184M vs. 3782M for per-layer baselines). A break condition is insufficient coverage of the training distribution (e.g., extreme token complexities), leading to mapping errors.

### Mechanism 3: Decoupled Parallel KV Generation
KV representations for skipped layers are generated independently of sequential computation, avoiding attention/feedforward operations in those layers. For a token exiting at layer i*, KV for any later layer r > i* is computed as s<sub>kv</sub><sub>r,j</sub> = ˜sh<sub>N,j</sub> · W<sub>kv</sub><sub>r</sub>, using the predicted final state and the base model’s layer-specific KV projection matrices. This decoupling is valid because attention weights depend on the compatibility between the final mapped state and layer-specific projections. Evidence includes the reconstruction formula (Section 4.3, Equation 9) and the minor additional KV cost (Section 6: ~8.5% for GPT-2 XL). A break condition arises in very deep networks where intermediate representations are highly specialized; parallel KV generation may fail to capture layer-specific features, causing attention misalignment.

## Architecture Onboarding

### Component map
Similarity Calculator -> Exit Controller -> Hidden State Mapper (HSM) -> KV Generator -> Task-Specific Head

### Critical path
**Prefill phase:** Process all tokens in parallel through layers. After each layer, compute per-token similarity; tokens exiting are removed from the batch (dynamic shrinkage). For each exited token, HSM predicts final state; KV Generator computes KV for all remaining layers in parallel and fills the cache. Non-exited tokens continue to the next layer.
**Generation phase:** Tokens arrive sequentially. After generating the next token’s hidden state at a layer, compute its similarity; if it exits, HSM and KV Generator compute its final state and KV for all future layers, which are then used for attending by later tokens.

### Design tradeoffs
- **Threshold δ:** Lower values increase exits but risk quality drop; higher values reduce savings. Calibrated against a target computation reduction C<sub>threshold</sub>.
- **HSM capacity:** Deeper MLPs improve mapping accuracy but add overhead; the paper found 3-layer MLP + conv optimal (Table S4).
- **Shared vs. per-layer HSM:** Sharing drastically reduces parameters (6–20×) but may limit layer-specific adaptation.
- **Training data:** HSM is trained for a specific δ; changing the target reduction requires retraining (Section H.1).

### Failure signatures
1. **Perplexity spike at target reduction:** HSM not trained adequately for that exit rate; check exit layer distribution (Figure S3) if concentrated at extremes.
2. **No token exits:** δ too high or similarity metric broken; verify inertia accumulation and normalization.
3. **KV cache inconsistency:** Outputs diverge from base model even without exits; likely ˜sh<sub>N,j</sub> misprediction—inspect HSM outputs.
4. **Inference slowdown:** Parallel KV overhead outweighs savings if exit rates too low; ensure exits occur in earlier layers.
5. **Parameter count mismatch:** HSM size differs from reported (e.g., ~184M for GPT-2 XL); revisit convolution and MLP shapes.
6. **Inertia accumulation bug:** Including states from layers not processed by the token; add assertions to track per-token layer history.

### First 3 experiments
1. **Baseline replication:** Run base model, DeeBERT, and PABEE on PTB/WikiText103 to establish expected perplexity/reduction trade-off curves.
2. **Similarity metric validation:** With the base model, plot per-token normalized inner product ⟨ˆsh<sub>i,j</sub>, sh<sub>inertia,j</sub>⟩ against layer index; verify convergence pattern and select initial δ from the distribution.
3. **HSM smoke test:** Train HSM at a fixed δ (e.g., 20% reduction), evaluate cosine similarity between HSM’s predicted final states and true final states from the base model; confirm mapping quality before full integration.

## Open Questions the Paper Calls Out
### Open Question 1
**Question:** How can we automatically adjust the early-exit threshold δ per input to maintain consistent performance across domains without manual tuning?
**Basis:** The Impact Statement explicitly calls for “future work should focus on developing algorithms capable of dynamically adjusting thresholds based on input characteristics.”
**Why unresolved:** ADEPT uses a fixed threshold heuristically set for a given computational budget, which may not generalize to new tasks or data distributions.

### Open Question 2
**Question:** Does ADEPT deliver its promised efficiency gains during the autoregressive generation phase for open-ended text generation?
**Basis:** The paper claims token-level exit in both prefill and generation, but experiments only evaluate prefill on language modeling and classification; generation results are absent.
**Why unresolved:** Autoregressive decoding introduces sequential KV reuse; the overhead of parallel KV generation might diminish returns or affect output coherence, which remains untested.

### Open Question 3
**Question:** Could per-token adaptive thresholds improve the efficiency-performance trade-off compared to ADEPT’s uniform global threshold?
**Basis:** ADEPT uses a single threshold for all tokens and does not explore personalized thresholds per token or layer.
**Why unresolved:** Token complexities vary; a global threshold forces easy tokens to process extra layers and hard tokens to exit prematurely, potentially limiting optimal resource allocation.

## Limitations
- ADEPT assumes universal representation convergence and that a shared HSM generalizes across all tokens and layers; these assumptions may break for rare/complex tokens or deeper networks.
- Requires manual calibration of the threshold δ for each target reduction rate; no automatic input-adaptive mechanism is provided.
- KV decoupling might cause attention misalignment in very deep models where intermediate representations are highly specialized.
- Efficiency gains are demonstrated on specific models (GPT-2 XL, BERT) and tasks; scalability to modern large language models is uncertain.

## Confidence
- **Token-level dynamic exit:** Medium (evidence from experiments but limited to tested models).
- **Shared HSM mapping:** Medium (parameter-efficient but mapping accuracy depends on training).
- **KV reconstruction:** Medium (minor overhead in experiments but untested in very deep architectures).
- **Efficiency numbers (25% reduction, 4× speed-up):** High on evaluated setups, Low for broader LLM use cases.
