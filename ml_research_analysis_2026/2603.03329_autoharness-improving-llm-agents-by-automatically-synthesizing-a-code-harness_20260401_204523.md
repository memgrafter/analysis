# AutoHarness: improving LLM agents by automatically synthesizing a code harness

## Quick Facts
- **arXiv ID:** 2603.03329
- **Source URL:** https://arxiv.org/abs/2603.03329
- **Reference count:** 40
- **Primary result:** Automatically synthesized code harnesses prevent 100% of illegal moves across 145 TextArena games and enable a smaller model (Gemini-2.5-Flash) to outperform larger ones (Gemini-2.5-Pro, GPT-5.2-High) in specific game settings.

## Executive Summary
The paper tackles the pervasive problem of LLM agents performing invalid actions in interactive environments, such as game rules violations. It introduces AutoHarness, a system that uses a small LLM (Gemini-2.5-Flash) to automatically synthesize a Python code harness via tree search and iterative refinement, guided by feedback from the game environment. The harness can act either as an action verifier filter that blocks illegal proposals or as a complete policy where the LLM is not needed during test-time execution. Evaluations across hundreds of TextArena games show the verifier eliminates all illegal moves, and the harness-augmented agent outperforms larger models in both 1-player and 2-player settings. The full code-only policy achieves state-of-the-art average reward on 1-player games at near-zero test-time cost.

## Method Summary
AutoHarness employs a tree search over candidate Python programs that implement two functions: `propose_action(board_state)` and `is_legal_action(board_state, action)`. The search begins with a simple seed harness. In each iteration, a node (a specific code version) is selected via Thompson sampling based on its heuristic value (fraction of legal moves for the verifier, or a reward-weighted score for the full policy). The node is evaluated by rolling it out in parallel game environments. Failures (illegal moves, execution errors, low rewards) are aggregated by a Critic into a textual summary. A separate Refiner LLM (the same Gemini-2.5-Flash model) mutates the current code given this feedback, creating a new child node. This loop continues until the heuristic reaches a target (e.g., 1.0 for perfect legality) or a timeout. The final harness is deployed either as a filter (requiring one LLM call per step) or as a standalone policy (no LLM calls).

## Key Results
- The synthesized **action verifier** prevented 100% of illegal moves across 145 TextArena games.
- In 16 tested 2-player games, **Gemini-2.5-Flash with the harness** achieved a 56.3% win rate, outperforming **Gemini-2.5-Pro** (38.2%).
- In 1-player games, the harness-augmented agent (0.745 avg reward) beat both **Gemini-2.5-Pro** (0.707) and **Flash alone** (0.673).
- The **full code-only policy (harness-as-policy)** on 16 1-player games achieved a higher average reward (0.870) than **GPT-5.2-High** (0.844) and **Gemini-2.5-Pro** (0.707).
- Training required an average of 14.5 iterations to synthesize the verifier and 89.4 iterations for the full policy.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Tree search with environment feedback iteratively refines code to eliminate illegal actions.
- **Mechanism:** The system maintains a tree of code hypotheses. A base LLM acts as a mutation operator, proposing code changes based on Critic feedback (e.g., illegal move errors, reward signals). Thompson sampling selects which node to refine next, balancing exploration of new logic structures with exploitation of partially working harnesses. The heuristic value (average legal move accuracy) guides search convergence.
- **Core assumption:** Environment feedback (legal/illegal action labels, sparse rewards) is a sufficiently rich and reliable training signal for code synthesis.
- **Evidence anchors:** [abstract] "automatically synthesize such a code harness, using a small number of rounds of iterative code refinement given feedback from the (game) environment." [section 3] "Our approach maintains multiple code hypotheses in a tree structure, and uses Thompson sampling to choose which node to refine next... The refinement is done with a base LLM, given feedback from the environment (Critic)..."
- **Break condition:** Search terminates when heuristic reaches 1.0 (perfect legality) or a timeout occurs. A break would occur if the code space cannot represent a valid solution for a given game (e.g., if the game rules are too complex for the fixed function signatures).

### Mechanism 2
- **Claim:** A learned action verifier harness (filter) enables a smaller model to outperform a larger one by removing illegal proposals, while a learned full policy harness eliminates LLM inference cost entirely.
- **Mechanism:** Two harness instantiations: (1) *Action Verifier*: `propose_action` generates candidate moves, `is_legal_action` filters them; if rejected, the LLM reprompts with a warning. (2) *Harness-as-Policy*: `propose_action` contains the complete decision logic in code, with no LLM call at test time. The latter is trained with a heuristic combining legality and end-of-episode reward.
- **Core assumption:** The `propose_action` and `is_legal_action` function signatures are expressive enough to implement strategies that achieve high performance across diverse games. For 2-player games, this assumption may be weaker as the full policy would likely need a search component (e.g., MCTS) not easily encoded in simple Python functions.
- **Evidence anchors:** [abstract] "The resulting harness prevents all illegal moves... enabling the smaller Gemini-2.5-Flash to outperform larger models... Pushing our technique to the limit, we can get... to generate the entire policy in code, thus eliminating the need to use the LLM at decision making time." [section 4.2] Results show Flash+Harness (verifier) beats Pro (56.3% vs 38.2% win rate in 2P). [section 4.3] Harness-as-Policy achieves 0.870 avg reward vs GPT-5.2-High's 0.844 on 1P games.
- **Break condition:** For the verifier, failure occurs if `is_legal_action` returns `False` negatives (blocks legal moves) or `True` positives (lets illegal moves pass). For the full policy, failure occurs if the synthesized code cannot achieve a non-trivial reward (heuristic stuck << 1.0) or generalizes poorly.

### Mechanism 3
- **Claim:** Using a smaller, more efficient model (Gemini-2.5-Flash) for the *code synthesis* phase, and a specialized harness for *deployment*, is more cost-effective than using a larger model (Gemini-2.5-Pro, GPT-5.2-High) for direct decision-making.
- **Mechanism:** The "training" phase (code synthesis) uses the smaller model with tree search, incurring LLM costs for a limited number of iterations (avg 14.5 for verifier, 89.4 for full policy). The resulting harness is a static Python program. During "test" (gameplay), execution cost is near-zero for the full policy, and only one LLM call per step for the verifier (to generate the initial proposal). This contrasts with using a large model for every decision step.
- **Core assumption:** The quality gap between the small model's synthesized code-harness and the large model's direct policy is smaller than the quality gap between the large model and the small model acting directly. The synthesis process effectively "distills" the large model's strategic reasoning into precise, verifiable code.
- **Evidence anchors:** [abstract] "Our results show that using a smaller model to synthesize a custom code harness... can outperform a much larger model, while also being more cost effective." [section 4.3] "test time cost is nearly zero, while the GPT-5.2 and GPT-5.2-High experiments cost approximately $640."
- **Break condition:** The cost advantage disappears if the synthesis phase requires prohibitively many iterations (e.g., >1000) for complex games, or if the harness's performance degrades significantly on distribution shifts not seen during synthesis.

## Foundational Learning
- **Concept: LLM-based Code Synthesis & Iterative Refinement**
  - Why needed here: The core of AutoHarness is using an LLM not as a direct policy, but as a *code optimizer* that receives execution feedback (legal/illegal actions, rewards) to mutate a program. The engineer must understand how to prompt for robust code that handles edge cases and incorporates numeric/logical feedback.
  - **Quick check:** How would you design the Critic's feedback message to maximize the chances the Refiner produces a correct `is_legal_action` function for a game with complex move rules like Chess?
- **Concept: Tree Search for Program Space (Thompson Sampling)**
  - Why needed here: The search over syntactically valid Python programs is discrete and high-dimensional. Thompson sampling (a Bayesian bandit technique) is used to allocate limited LLM "mutations" to the most promising code nodes in the tree, balancing trying new approaches vs. fixing current best. The engineer needs to grasp the exploration-exploitation trade-off in this context.
  - **Quick check:** If a particular code hypothesis produces 95% legal moves but gets stuck in a loop, how might Thompson sampling's probabilistic node selection help escape this local optimum?
- **Concept: Action Applicability & Verifiers in Agent Systems**
  - Why needed here: The paper targets the fundamental "action applicability" problem—knowing which actions are valid in a given state. The engineer must recognize that separating *action proposal* (creative, strategic) from *action validation* (deterministic, rule-based) is a key architectural pattern. The harness formalizes this separation.
  - **Quick check:** Why is it generally harder for an LLM to generate a correct `is_legal_action(board, action)` function than to simply propose an action from a list of provided valid moves? What does this imply about prompt design?

## Architecture Onboarding
- **Component map:**
  - Refiner LLM -> (proposes new code) -> Tree Manager (updates Beta stats, selects node)
  - Tree Manager -> (selects node) -> Environment Wrapper (runs rollouts)
  - Environment Wrapper -> (returns trajectories) -> Critic (aggregates failures)
  - Critic -> (feedback summary) -> Refiner LLM
  - Execution Sandbox (runs harness code) is invoked by Environment Wrapper during rollouts.
- **Critical path:**
  1. Initialize: Create a seed harness (e.g., random move in `propose_action`, stub `is_legal_action` returning `False`).
  2. Rollout: For N parallel envs, run current harness to max steps or until illegality/error. Record trajectories.
  3. Evaluate: Critic analyzes failures, computes heuristic (legal move rate or reward-based) for the node.
  4. Sample & Refine: Tree manager uses Thompson sampling to select a node. Refiner LLM generates new code variant.
  5. Repeat from step 2 until heuristic target met or iteration limit.
  6. Deployment: Freeze final harness. For action-verifier: at test time, call `propose_action` -> if `is_legal_action` returns False, reprompt LLM with warning. For full policy: call `propose_action` directly.
- **Design tradeoffs:**
  - *Harness-as-Verifier*: Simpler to synthesize, retains LLM's strategic proposal ability, but incurs 1+ LLM calls per step.
  - *Harness-as-Policy*: Zero inference cost, but requires synthesizing full strategy in code (harder, avg 89.4 iterations), likely infeasible for complex 2P games needing opponent modeling.
  - *Tree Search Depth*: More iterations improve robustness but increase synthesis cost. The 14.5 (verifier) vs 89.4 (policy) iteration gap highlights the difficulty jump.
  - *Feedback Granularity*: Critic provides final error summary. More granular, per-step feedback might speed learning but increase prompt complexity.
- **Failure signatures:**
  - **Infinite Loop in Code**: Harness's `propose_action` enters an unending state. *Detect*: Rollout exceeds max steps. *Fix*: Ensure loop-breaking logic in prompt/refinement.
  - **Parsing Failure**: `propose_action` or `is_legal_action` cannot parse the board string (e.g., unexpected format). *Detect*: Execution exception. *Fix*: Refine with robust parsing examples; include board format in prompt.
  - **Overly Conservative Verifier**: `is_legal_action` returns `False` for many legal moves. *Detect*: Low legal action rate despite many "valid move" errors from env. *Fix*: Critic must distinguish "illegal move" errors from other failures.
  - **Strategy Collapse**: Synthesized policy only performs safe, low-reward actions (e.g., always passes). *Detect*: Reward heuristic stuck at low plateau. *Fix*: Adjust heuristic weighting (e.g., more emphasis on reward for policy), or add diversity to mutation.
- **First 3 experiments:**
  1. **Smoke Test on Bandit-v0**: Use the simplest 1-player game (likely a multi-armed bandit). Goal: Achieve 100% legal action rate in <5 iterations. Validates the basic code generation and feedback loop.
  2. **Scaling Test on 2048-v0**: A moderate-complexity 1-player puzzle. Goal: Compare synthesis iterations and final legal rate against Table 1 (expect ~27 steps, 1.0 rate). Tests the harness's ability to handle deterministic state transitions.
  3. **Strategic Test on Chess-v0 (Blind)**: A complex 2-player game with "Available Moves" removed (per A.4). Goal: Achieve 100% legal move rate (paper reports 64 iterations). Probes the hardest constraint—rule understanding without hints. Monitor for code that correctly encodes piece movement and check detection.

## Open Questions the Paper Calls Out
- **Can the AutoHarness framework be effectively extended to multimodal game environments (e.g., Craftax, Terra Nova) that require processing visual inputs beyond text observations?** The current implementation and evaluations are limited to text-based TextArena games. Multimodal environments introduce additional complexities such as image parsing, state representation, and action spaces that may not be directly amenable to code synthesis from textual descriptions.
- **Does distilling the synthesized domain-specific harnesses or policies back into the base LLM (Gemini-2.5-Flash) improve its general game-playing capabilities on unseen tasks without requiring additional per-game synthesis?** The paper shows that synthesizing a harness for a specific game improves performance on that game, but it remains unknown whether the knowledge encoded in the harness (e.g., rule-following logic) can transfer to the LLM’s parameters. Such transfer could reduce the need for per-game synthesis and yield a more generally capable agent.
- **Can a library of reusable harnesses be constructed from synthesized code for families of similar games (e.g., different variants of 2048 or Chess) to reduce synthesis cost and improve sample efficiency?** The current approach synthesizes a separate harness for each game independently. However, many TextArena games share common mechanics (e.g., grid-based movement, turn-based play). Reusing harness components across variants could dramatically cut the number of required iterations and LLM calls, but the paper does not explore transferability.
- **Can the harness-as-policy approach be extended to two-player adversarial games by synthesizing code policies that incorporate opponent modeling or search (e.g., minimax, MCTS) without relying on an LLM at test time?** The current harness-as-policy succeeds only for 1-player games because they lack the need to anticipate an opponent. For 2-player games, the synthesized code must not only follow rules but also plan strategically against an adversary, which may require search over a world model—a capability not yet demonstrated.

## Limitations
- **Prompt and parameter fidelity:** Exact LLM prompts, decoding parameters (temperature, top-p), and message formatting for both policy and refinement are unspecified; minor variations could significantly affect synthesis efficiency and final code quality.
- **Search dynamics unclear:** Thompson sampling implementation details (Beta prior initialization, update frequency per step vs. per rollout, branching factor) are unclear; these critically control exploration/exploitation balance and iteration counts.
- **Critic design ambiguous:** How multiple rollout failures are consolidated into a single feedback string for the Refiner LLM is not described; aggregation strategy impacts refinement efficacy.
- **Generalizability bounds:** Performance gains are demonstrated on limited subsets (16 games each for 2P/1P). Claim generalizability across all 145+ games is not fully supported; confidence lowered by potential dataset selection bias and incomplete game splitting information.

## Confidence
- **Illegal Move Prevention (100% rate)**: High – Result is binary, measured across 145 games, with clear failure signature (illegal move error). Methodology is well-specified despite prompt unknowns.
- **Performance Gains (vs. Larger Models)**: Medium – Results are strong but based on limited subsets (16 games each for 2P/1P). Claim generalizability across all 145+ games is not fully supported.
- **Cost-Effectiveness**: Medium – Zero test-time cost for harness-as-policy is definitive, but synthesis cost (average iterations) has high variance (14.5 vs. 89.4). Confidence reduced by unclear scaling to more complex games and unstated synthesis wall-clock time.
- **Extension to Multimodal/2P Games**: Low – The paper explicitly identifies these as open challenges with no evidence provided.
