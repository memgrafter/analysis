# Towards Intelligent Geospatial Data Discovery: a knowledge graph-driven multi-agent framework powered by large language models

## Quick Facts
- **ArXiv ID:** 2603.20670  
- **Source URL:** https://arxiv.org/abs/2603.20670  
- **Reference count:** 40  
- **Primary result:** Achieved 99.27% intent match accuracy, NDCG@10 of 85.22%, and Recall@20 of 66.54% across 100 diverse queries, significantly outperforming baseline systems like Data.gov.

## Executive Summary
This paper addresses the inefficiencies of keyword-based geospatial data discovery caused by semantic heterogeneity across metadata standards. The authors propose a knowledge graph-driven multi-agent framework powered by large language models (LLMs). A unified geospatial metadata ontology acts as a semantic mediation layer, aligning standards such as STAC, FGDC CSDGM, and CKAN into a common model. A knowledge graph representing over 260,000 datasets enables relational and semantic queries. A three-agent pipeline—comprising an intent parser, a graph retriever, and an answer synthesizer—processes natural language queries, retrieves relevant datasets, and generates explanations. Evaluations demonstrate substantial improvements in ranking and recall over existing systems, with the answer synthesis agent alone contributing a 16%+ gain. The work moves geospatial discovery toward a semantic, intent-aware paradigm while highlighting challenges in ontology coverage, LLM reliability, and resolution awareness.

## Method Summary
The method integrates a unified ontology, a knowledge graph, and an LLM-powered multi-agent architecture. The ontology defines core entities (Dataset, Topic, Space, Time, etc.) and maps elements from multiple metadata standards to ensure semantic compatibility. The knowledge graph stores dataset instances and relationships in Neo4j, with hybrid indexes for vector, spatial, and temporal search. The multi-agent pipeline first uses an LLM to parse user queries into structured GeoIntent; a second agent then queries the graph via embedding similarity, hard filtering (e.g., spatial overlap), and relevance scoring; a third agent reranks results using LLM-based synthesis with evidence chains and generates natural language explanations. The system orchestrates these steps via a central module with memory for multi-turn context and interfaces with a frontend UI.

## Key Results
- **99.27%** intent match accuracy on 100 diverse user queries, demonstrating robust natural language understanding.
- **NDCG@10 of 85.22%** vs. 43.65% for Data.gov; **Recall@20 of 66.54%** vs. 34.61%, showing major gains in ranking quality and coverage.
- **16.82%** improvement in NDCG@10 from the answer synthesis agent in ablation studies, confirming its critical role.

## Why This Works (Mechanism)

### Mechanism 1: Semantic Alignment via Unified Ontology
- **Claim:** The unified geospatial metadata ontology enables semantic alignment across heterogeneous metadata standards.
- **Mechanism:** By mapping elements from STAC, FGDC CSDGM, and CKAN to a shared ontology with entities like Dataset, Topic, Space, etc., it creates a common semantic layer that allows consistent querying and integration.
- **Core assumption:** Metadata heterogeneity is a primary barrier to effective discovery; a mediation layer can reconcile differences without replacing standards.
- **Evidence anchors:**  
  [abstract] "introduces a unified geospatial metadata ontology as a semantic mediation layer to align heterogeneous metadata standards"  
  [section] 3.1.1: "The ontology design follows two principles: standard compatibility and semantic abstraction with minimal sufficiency."  
  [corpus] Neighbor papers such as "ReSearch" and "GeoEvolve" focus on discovery frameworks but do not directly address metadata standard alignment, indicating limited direct corpus evidence for this specific mechanism.
- **Break condition:** If mapping rules fail to capture key standard-specific nuances, semantic loss may occur, leading to inaccurate retrieval.

### Mechanism 2: Multi-Agent Pipeline for Robust and Transparent Discovery
- **Claim:** The multi-agent collaborative architecture decomposes discovery into interpretable stages, improving robustness and transparency.
- **Mechanism:** Intent parsing agent uses LLM to extract structured GeoIntent; graph retrieval agent uses embeddings and graph queries to find candidates; answer synthesis agent uses LLM to rerank and explain based on evidence.
- **Core assumption:** Complex discovery tasks can be broken down into specialized subtasks, each handled by an optimized agent, reducing errors and providing traceability.
- **Evidence anchors:**  
  [abstract] "adopts a multi-agent collaborative architecture to perform intent parsing, knowledge graph retrieval, and answer synthesis"  
  [section] 3.2: Detailed workflows for each agent, e.g., Figs. 3, 4, 5.  
  [corpus] "From Questions to Queries: An AI-powered Multi-Agent Framework for Spatial Text-to-SQL" (arxiv:2510.21045) presents a similar multi-agent approach for spatial queries, suggesting that multi-agent designs are a viable trend in geospatial AI, though not directly for data discovery.
- **Break condition:** If agents miscommunicate or state management fails, the pipeline may produce inconsistent results, especially in multi-turn conversations.

### Mechanism 3: LLM-Powered Answer Synthesis for Enhanced Ranking
- **Claim:** The answer synthesis agent, powered by LLMs, significantly enhances ranking quality by reranking candidates with contextual explanations.
- **Mechanism:** After graph retrieval produces Top K, synthesis agent collects evidence, constructs prompts with GeoIntent and history, and uses LLM to rerank to Top N, improving NDCG@10 by 16.82% in ablation.
- **Core assumption:** LLMs can effectively integrate structured evidence and natural language context to make better ranking decisions than pure similarity scores.
- **Evidence anchors:**  
  [abstract] "ablation studies confirming the answer synthesis agent's critical role, improving ranking by over 16%."  
  [section] 3.2.4: "The synthesis process begins with the Top K datasets... the agent performs reranking... generates explanatory output."  
  [corpus] "DeepEvidence: Empowering Biomedical Discovery with Deep Knowledge Graph Research" (arxiv:2601.11560) combines knowledge graphs and LLMs for biomedical discovery, with high fmr_score 0.658, indicating some support for knowledge graph-LLM integration in discovery tasks.
- **Break condition:** If LLM outputs are inconsistent or biased towards certain patterns, reranking may degrade performance, especially for niche or complex queries.

## Architecture Onboarding
**Component map:**  
Geospatial Metadata Knowledge Graph -> Multi-Agent Pipeline (Intent Parsing Agent -> Graph Retrieval Agent -> Answer Synthesis Agent) <- Orchestration and Memory Module -> Frontend UI

**Critical path:**  
User query submitted -> Orchestrator triggers Intent Parsing Agent -> GeoIntent extracted and stored in memory -> Graph Retrieval Agent queries knowledge graph via entity matching, hard filtering, and relevance scoring -> Answer Synthesis Agent reranks Top K and generates explanations with subgraphs -> Results returned to user. Memory supports multi-turn context.

**Design tradeoffs:**  
- Ontology minimalism vs. expressiveness: Simpler ontology eases mapping and maintenance but may lose standard-specific metadata richness affecting precision.  
- Agent specialization: Modular agents allow independent scaling and updates but introduce coordination overhead and potential error propagation across stages.  
- LLM reliance: High flexibility in natural language understanding but incurs cost, latency, and non-determinism; balance with rule-based fallbacks.  
- Hybrid retrieval: Graph queries enforce relational constraints (e.g., spatial overlap) while vector search handles semantic similarity; tuning weights (e.g., W_Topic=0.3) trades off precision vs. recall.

**Failure signatures:**  
- Intent parsing: Low confidence scores (<0.5) trigger human-in-the-loop, but high thresholds may reject valid queries; ambiguous terms like "South" cause spatial misinterpretation.  
- Entity matching: Embedding similarity threshold (default 0.7) may miss semantically relevant entities with lower scores or include noisy matches from polysemy.  
- Hard filtering: Incomplete spatiotemporal metadata in source catalogs leads to false negatives; enrichment via LLM inference may introduce errors.  
- Answer synthesis: LLM reranking may favor datasets with verbose metadata or generate incorrect explanations if evidence is conflicting or insufficient.

**First 3 experiments:**  
1. **Intent parsing robustness test:** Evaluate EIMR across varying confidence thresholds (e.g., 0.3 to 0.9) on ambiguous queries, measuring human-in-the-loop rate and final accuracy.  
2. **Retrieval weighting sensitivity:** Systematically vary dimension weights (e.g., W_Topic, W_Space) in relevance scoring and assess impact on NDCG@10 and Recall@20 across query complexity levels.  
3. **Agent ablation with alternative LLMs:** Replace GPT-5.2 with smaller or open-source LLMs in answer synthesis to measure cost-latency vs. ranking performance tradeoffs, including error analysis on reranking decisions.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can the framework be extended from data discovery to a complete pipeline that includes automated data preprocessing and generation of analysis-ready datasets?  
  **Basis in paper:** [explicit] "...this study focuses mainly on the data discovery stage. In practical scientific research and decision-making workflows, however, data preprocessing and the generation of analysis-ready data are equally important. Future work could extend the framework beyond discovery to encompass a complete pipeline from data discovery to data preprocessing."  
  **Why unresolved:** The current system stops at dataset retrieval and does not address downstream steps like data cleaning, format conversion, reprojection, or subsetting, which are critical for actual analysis workflows.  
  **What evidence would resolve it:** A prototype extension that integrates preprocessing modules (e.g., automated CRS alignment, resolution matching, quality checks) and is evaluated via user studies measuring end-to-end task completion time and data usability.

- **Open Question 2:** How can the framework incorporate spatial and temporal resolution awareness to ensure retrieved datasets are compatible with the user's analytical scale and precision requirements?  
  **Basis in paper:** [explicit] "Geospatial datasets exhibit substantial variation in spatial and temporal resolution. The current framework does not fully address issues related to resolution matching and scale compatibility. Future research could introduce hierarchical resolution modeling mechanisms to support scale-aware data discovery."  
  **Why unresolved:** The relevance scoring currently uses coverage overlap (F1) but does not penalize or rank based on resolution suitability, potentially returning datasets too coarse or fine for the intended analysis.  
  **What evidence would resolve it:** Implementation of a resolution compatibility metric (e.g., based on user-stated or inferred analysis scale) and ablation studies showing improved user satisfaction or analytical accuracy when resolution is considered.

- **Open Question 3:** To what extent do LLM-generated intents, semantic validations, and answer synthesis introduce hallucinations or biases that could degrade discovery reliability in geospatial contexts?  
  **Basis in paper:** [inferred] The framework relies on LLMs for core reasoning tasks (intent parsing, validation, synthesis) but does not report systematic analysis of LLM error modes (e.g., spatial/temporal misinterpretation, false positives in semantic validation). The "confidence assessment" mechanism assumes LLM self-evaluation is reliable.  
  **Why unresolved:** LLMs are known to hallucinate or exhibit positional biases; without quantifying these risks in the geospatial domain, the system's robustness to ambiguous or complex queries remains uncertain.  
  **What evidence would resolve it:** A controlled error analysis using adversarial or edge-case queries, comparing LLM outputs against expert annotations to measure hallucination rates, and perturbation studies on prompt design.

## Limitations
- **Ontology coverage:** The unified ontology's ability to fully capture nuanced differences across all geospatial standards (e.g., ISO 19115's detailed lineage) remains unvalidated, risking semantic loss.
- **Generalization:** Evaluations used 100 curated queries over 260k datasets from six catalogs; performance on unseen domains, languages, or highly ambiguous natural language is unknown.
- **LLM dependency:** The framework's effectiveness is tightly coupled to specific LLM capabilities (e.g., GPT-5.2). Cost, latency, and non-determinism are not addressed for operational deployment.

## Confidence
- **Semantic alignment via ontology:** Medium (theoretical foundation clear, but empirical validation across broader standards missing)
- **Multi-agent architecture:** Medium (pipeline well-documented, but coordination overhead and multi-turn robustness require further evidence)
- **Answer synthesis impact:** High (ablation shows ~16% improvement, though dependent on specific LLM and prompts)
