# E2Former-V2: On-the-Fly Equivariant Attention with Linear Activation Memory

## Quick Facts
- **arXiv ID:** 2601.16622  
- **Source URL:** https://arxiv.org/abs/2601.16622  
- **Reference count:** 28  
- **Primary result:** Scales to 100,000 atoms (others OOM beyond 50k) with 19.5× less memory, 20× TFLOPS improvement, and SOTA accuracy on SPICE/OMol25.

## Executive Summary
E2Former-V2 tackles the O(|E|) memory bottleneck in equivariant graph neural networks for 3D atomistic systems by introducing two synergistic innovations. First, Equivariant Axis-Aligned Sparsification (EAAS) leverages an SO(3)→SO(2) change of basis to collapse dense Clebsch–Gordan tensor products into deterministic, sparse parity re-indexing operations, yielding ~6× speedup. Second, On-the-Fly Equivariant Attention fuses attention score computation, online softmax, and value aggregation into a single Triton kernel that streams over neighbor lists without ever materializing edge tensors, achieving 20× TFLOPS improvement. Together, these enable linear memory scaling in the number of nodes, allowing the model to process systems with 100,000 atoms while matching state-of-the-art accuracy on chemical benchmarks.

## Method Summary
E2Former-V2 is built on the node-centric factorization from its predecessor E2Former, which uses a Binomial Local Expansion and Wigner-6j recoupling to separate edge interactions into source-node–local terms and target-node–local terms. This factorization ensures that only scalar attention weights depend on edges, while geometric coupling is precomputed per node. The first innovation, EAAS, aligns each edge’s relative position vector to the z-axis via a differentiable rotation, exploiting “pole sparsity” in spherical harmonics to reduce the dense tensor product to a fixed parity-based re-indexing rule; the result is inverse-rotated to the global frame. The second, On-the-Fly Equivariant Attention, implements the remaining scalar attention and aggregation in a fused kernel that streams neighbor indices and pre-coupled source features from HBM into SRAM, performing online softmax and accumulation entirely on-chip. This eliminates the O(|E|) edge tensor allocation and reduces memory traffic.

## Key Results
- Scales to 100,000 atoms while competitors OOM beyond 50,000; uses 19.5× less memory than MACE-Large.
- Achieves 140 steps/s at 1,000 atoms (10× faster than competitors) and 20× TFLOPS improvement in attention.
- Matches SOTA accuracy: best MAE on SPICE dataset, 1.27 meV/atom on OMol25.

## Why This Works (Mechanism)

### Mechanism 1: Equivariant Axis-Aligned Sparsification (EAAS)
- **Claim:** EAAS reduces the arithmetic complexity of SO(3)-equivariant tensor products by transforming dense Clebsch–Gordan contractions into deterministic, sparse re-indexing operations.
- **Mechanism:** For each edge, compute a rotation *R* that aligns the relative position **r** to the z-axis. In this aligned frame, the geometric spherical harmonic *R<sup>(ℓ<sub>f</sub>)</sup>(R**r*)* contains only the *m<sub>f</sub>=0* component (Lemma 4.1). The Clebsch–Gordan coupling then collapses to a fixed re-indexing rule (Eq. 13) that maps each output order *m<sub>o</sub>* to at most one input order *m<sub>i</sub>*, based on the parity of the total angular momentum sum *L<sub>Σ</sub>=ℓ<sub>i</sub>+ℓ<sub>f</sub>+ℓ<sub>o</sub>*. After re-indexing, the result is inverse-rotated back to the global frame.
- **Core assumption:** The alignment rotation *R* can be computed per edge without breaking differentiability, and the parity-dependent re-indexing pattern is correct for all degrees *ℓ* up to the model’s *L<sub>max</sub>*.
- **Evidence anchors:**  
  [abstract] “EAAS … exploiting an SO(3)→SO(2) change of basis to transform computationally expensive dense tensor contractions into efficient, sparse parity re-indexing operations.”  
  [section 4.3] Lemma 4.1 (pole sparsity) and Definition 4.2 (EAAS re-indexing operator) explicitly define the sparse rule.
- **Break condition:** If **r** is zero or misaligned (e.g., numerical instability), pole sparsity fails and dense summation returns. An incorrect parity sign convention in Eq. 13 violates equivariance.

### Mechanism 2: On-the-Fly Equivariant Attention
- **Claim:** On-the-Fly Equivariant Attention eliminates the O(|E|) memory bottleneck by fusing attention score computation and value aggregation into a single kernel that streams over neighbors without materializing edge tensors.
- **Mechanism:** For each target node *i*, the kernel iterates through its neighbor list *N(i)* given by index tensor **I**. It computes the scalar attention score *s<sub>ij</sub>* (Eq. 18) on the fly, applies an online softmax update (Eqs. 15–17), and immediately accumulates the weighted source-term feature *ϕ(r<sub>ij</sub>)h'<sub>j</sub>* into an output accumulator *A<sub>i</sub>*. Keys, values, and **I** are streamed from HBM, while *µ<sub>i</sub>*, *z<sub>i</sub>*, and *A<sub>i</sub>* reside in SRAM.
- **Core assumption:** The neighbor list is static during the forward pass and fits within the GPU’s memory hierarchy for streaming; online softmax is numerically stable.
- **Evidence anchors:**  
  [abstract] “On-the-Fly Equivariant Attention … eliminating edge tensors … achieves 20× improvement in TFLOPS.”  
  [section 4.4] Algorithm 1 details the fused kernel logic; states “eliminates the dominant sources of intermediate memory allocation and HBM traffic.”
- **Break condition:** Highly irregular neighbor degrees cause warp divergence; if neighbor count *K* exceeds on-chip accumulator capacity, the kernel falls back to suboptimal access patterns.

### Mechanism 3: Node-Centric Factorization
- **Claim:** The node-centric factorization (Eq. 5, from E2Former) decouples edge interactions into node-local computations, providing the theoretical foundation for linear memory scaling.
- **Mechanism:** Uses the Binomial Local Expansion and Wigner-6j recoupling to rewrite the edge message *h<sub>j</sub>⊗R(ℓ)(r<sub>ij</sub>)* as a sum of terms where the dependence on the source node *j* (via *h<sub>j</sub>⊗R(ℓ−u)(r<sub>j</sub>)*) is separated from the target node *i* (via *R<sup>(u)</sup>(r<sub>i</sub>)*). The scalar attention weight *α<sub>ij</sub>* remains the only edge-dependent term.
- **Core assumption:** The factorization is mathematically exact for all *ℓ* and the source-term pre-computation *h'<sub>j</sub> = h<sub>j</sub>⊗R(r<sub>j</sub>)* can be done once per node before attention.
- **Evidence anchors:**  
  [abstract] Implicit: “fully node-centric mechanism” and “linear activation memory” rely on this.  
  [section 3] Equation (5) is the central factorization theorem from E2Former.
- **Break condition:** Incorrect Wigner-6j approximation or truncation for higher *ℓ* breaks decoupling; if *α<sub>ij</sub>* depends on angular features, edge tensors reappear.

## Foundational Learning
- **Irreducible Representations (irreps) of SO(3)**  
  *Why needed:* Node features *h* are direct sums of irreps *h<sup>(ℓ)</sup> ∈ ℝ<sup>C<sub>ℓ</sub>×(2ℓ+1)</sup>*; all operations must commute with the Wigner-D matrix *D<sup>(ℓ)</sup>(R)* to maintain equivariance.  
  *Quick check:* Given a vector feature (ℓ=1) rotated by *R*, how does its component index *m* transform, and why is this block structure critical for parameter sharing?
- **Clebsch–Gordan Tensor Product**  
  *Why needed:* The fundamental operation combining two irreps (e.g., node feature × geometric encoding); its density O(*L<sup>6</sup>*) is the primary bottleneck EAAS addresses.  
  *Quick check:* For ℓ<sub>i</sub>=1, ℓ<sub>f</sub>=1, ℓ<sub>o</sub>=0, how many *(m<sub>i</sub>, m<sub>f</sub>, m<sub>o</sub>)* triples yield non-zero CG coefficients, and what does this imply about summation cost?
- **Hardware-Aware Kernel Fusion (SRAM Tiling)**  
  *Why needed:* The fused Triton kernel relies on keeping intermediate sums in fast SRAM while streaming data from HBM; understanding the roofline model is key to the 20× TFLOPS gain.  
  *Quick check:* If per-head feature dimension *d* is very small, what becomes the dominant cost in standard attention, and how does on-the-fly computation change this tradeoff?

## Architecture Onboarding
- **Component map:** Input Encoder -> EAAS Layer -> On-the-Fly Attention Kernel (with Neighbor Indexer)
- **Critical path:** Block-diagonal projections → pre-couple source terms *h'<sub>j</sub>* (node-wise, O(|V|)) → invoke fused attention kernel with **I**, *q*, *k*, *h'* → output equivariant *ŷ<sub>i</sub>*.
- **Design tradeoffs:**  
  *Sparsity vs. expressivity:* EAAS sparsity is exact but fixed by parity; higher *L<sub>max</sub>* increases channel count but sparsity per block remains O(1).  
  *Kernel fusion vs. flexibility:* Assumes fixed neighbor budget *K* and scalar *α<sub>ij</sub>*; adding per-head gates or dynamic *K* requires kernel redesign.  
  *Memory vs. recomputation:* Source terms *h'<sub>j</sub>* precomputed once per layer (memory O(|V|)) rather than recomputed per edge (compute O(|E|)).
- **Failure signatures:**  
  *Memory spike:* If *h'<sub>j</sub>* is accidentally materialized per edge, O(|E|) memory returns.  
  *Low TFLOPS:* Separate QK and V reductions saturate HBM traffic.  
  *Equivariance violation:* Incorrect rotation alignment or parity sign error detectable via random rotation tests.
- **First 3 experiments:**  
  1. EAAS microbenchmark: Reproduce Figure 3; time tensor products (ℓ<sub>i</sub>,ℓ<sub>f</sub>,ℓ<sub>o</sub>) using EAAS vs. e3nn dense SO(3) TP; expect ~6× speedup.  
  2. Attention kernel scaling: Profile fused kernel memory (should scale O(N)) and TFLOPS vs. *N* and *K*; verify peak memory does not grow with *K*.  
  3. Full-model scalability: Train tiny E2Former-V2 on SPICE 1k-atom subset; measure steps/s for *N* = 1k, 10k, 50k using synthetic FCC carbon; confirm >10× speedup over MACE-Large and no OOM at 100k atoms.

## Open Questions the Paper Calls Out
1. **Backward pass efficiency:** How efficient is the backward pass of the fused on-the-fly equivariant attention kernel during training? The paper describes only the forward kernel and asserts training efficiency without evidence; backward may require recomputation, increasing memory/time.
2. **Rotation overhead:** What is the overhead of per-node rotation computations in EAAS, and how does it scale with ℓ<sub>max</sub> and system size? For large *N* or high ℓ, rotation overhead may dominate, offsetting sparse gains.
3. **Large neighbor counts:** Can linear scaling hold when neighbor count *K* is large (e.g., metals, long-range), and how to extend to all-to-all? Method assumes bounded *K* (~50); large *K* breaks O(*N*) and hurts performance.

## Limitations
- EAAS sparsity is exact but fragile; zero edges or parity errors reintroduce dense sums.
- On-the-Fly Attention assumes uniform *K*; irregular graphs cause warp divergence, reducing speedup.
- Scalability experiments use only synthetic FCC carbon; real heterogeneous systems (>50k atoms) unproven.

## Confidence
- **EAAS:** Medium — theory sound but no external verification.
- **On-the-Fly Attention:** Medium — clear design, no profiling on irregular graphs.
- **Scalability:** Low — synthetic benchmarks only; real-world generalization uncertain.
- **Accuracy:** Medium — matches SOTA on SPICE/OMol25 but no variance/stats reported.
