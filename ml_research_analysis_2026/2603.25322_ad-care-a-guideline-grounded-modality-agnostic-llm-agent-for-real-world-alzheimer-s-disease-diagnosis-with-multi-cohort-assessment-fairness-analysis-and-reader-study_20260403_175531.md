# AD-CARE: A Guideline-grounded, Modality-agnostic LLM Agent for Real-world Alzheimer's Disease Diagnosis with Multi-cohort Assessment, Fairness Analysis, and Reader Study

## Quick Facts
- **arXiv ID**: 2603.25322
- **Source URL**: https://arxiv.org/abs/2603.25322
- **Reference count**: 40
- **Primary result**: AD-CARE achieved 84.9% diagnostic accuracy with 4.2%–13.7% relative improvement over baselines, reduced fairness dispersion by 21%–68% (race) and 28%–51% (age), improved clinician accuracy by 6%–11% and halved decision time, and converged performance across eight LLM backbones.

## Executive Summary
AD-CARE is a guideline-grounded, modality-agnostic LLM agent designed for real-world Alzheimer's disease diagnosis. It dynamically orchestrates specialized diagnostic tools based solely on available patient data without imputation, addressing the challenge of incomplete, heterogeneous multimodal inputs. The system embeds clinical guidelines into its aggregation process to produce transparent, structured reports aligned with clinical workflows. Evaluated on 10,303 cases across six diverse cohorts, AD-CARE achieved 84.9% diagnostic accuracy, significantly outperforming baseline methods. It also reduced performance disparities across racial and age subgroups, enhanced neurologist and radiologist accuracy by 6%–11% while halving decision time in a reader study, and maintained robust performance across eight different LLM backbones, demonstrating scalability for varied resource settings.

## Method Summary
AD-CARE operates as an agentic framework where an LLM-based reasoning engine (planner) parses a user query and available multimodal data to decompose the diagnostic task and select appropriate specialized tools (e.g., hippocampal analyzer, cognitive score calculator). Each tool executes independently on its required input (e.g., MRI scans, text scores), and the outputs are passed to an outcome aggregator—another LLM—that synthesizes the results conditionally on formal diagnostic guidelines (e.g., NIA-AA) and curated exemplars. This aggregation resolves any conflicts, explicitly maps evidence to criteria, and generates a structured report with diagnosis, confidence, and rationale. The entire process avoids data imputation by only invoking tools for modalities that are present. The system was evaluated retrospectively on six public and private cohorts totaling 10,303 cases, with metrics including accuracy, fairness dispersion, and clinician utility measured via a reader study.

## Key Results
- Diagnostic accuracy reached 84.9%, representing a 4.2%–13.7% relative improvement over baseline methods.
- Fairness dispersion (std. dev. across subgroups) decreased by 21%–68% for racial groups and 28%–51% for age groups.
- In a reader study, AD-CARE improved neurologist and radiologist accuracy by 6%–11% and reduced decision time by more than half.
- Across eight LLM backbones, the framework delivered absolute gains of 2.29%–10.66% and converged performance within a narrow range (78.73%–80.40%).

## Why This Works (Mechanism)
- **Dynamic tool orchestration**: The reasoning engine analyzes available data modalities and selectively invokes only the relevant diagnostic tools (e.g., MRI analyzer if MRI is present, cognitive scorer if tests are available), avoiding imputation and mimicking clinician adaptability to incomplete information. This ensures that partial multimodal data suffices for reliable staging without introducing synthetic data bias.
- **Guideline-embedded aggregation**: The outcome aggregator uses an LLM to synthesize tool outputs against explicit diagnostic criteria (e.g., NIA-AA, IWG) and curated exemplars, listing supporting and contradictory evidence, and resolving conflicts before report generation. This produces transparent, guideline-concordant outputs that enhance clinical trust.
- **Tool-augmented convergence**: By offloading specialty tasks (e.g., hippocampal segmentation) to dedicated executors, AD-CARE standardizes intermediate outputs and reduces reliance on the LLM's raw knowledge. This stabilizes predictions across diverse LLM backbones, narrowing accuracy differences and enabling cost-effective deployment.

## Architecture Onboarding
- **Component map**: Web Interface (captures user query and data) → Reasoning Engine (Planner) → Specialized Executors (Tools) → Outcome Aggregator (Coordinator) → Web Interface (displays report)
- **Critical path**: 1. Observation: Parse query and extract available multimodal data (demographics, tests, imaging files). 2. Thought: Planner generates task list and selects tools from registry based on data availability and diagnostic intent. 3. Action: Each tool executes on its input; outputs verified for validity; retries if needed. 4. Aggregation: Coordinator merges tool results, applies guidelines, resolves conflicts, and produces final report with diagnosis, confidence, and rationale.
- **Design tradeoffs**: 
  - Modality coverage vs. complexity: Adding more tools increases versatility but complicates orchestration.
  - Guideline rigidity vs. clinical nuance: Strict adherence ensures consistency but may limit flexibility for atypical cases; managed via few-shot exemplars.
  - Backbone cost vs. accuracy: Smaller LLMs reduce cost but may impair planning; tool augmentation mitigates this.
- **Failure signatures**:
  - Tool invocation failures: Invalid outputs from executors (e.g., MRI processing error) detected by verification step.
  - Evidence inconsistency: Conflicting tool results not reconciled in report; check for unresolved conflicts.
  - Guideline deviation: Report omits required criteria elements; validate against a guideline-derived checklist.
  - Cohort-specific performance drops: Significant accuracy decline on certain demographics/sites indicates domain shift or bias.
- **First 3 experiments**:
  1. Modality ablation test: Systematically remove modalities (e.g., no MRI, no CSF) on a held-out cohort to measure accuracy degradation and identify critical dependencies.
  2. Guideline compliance audit: Sample 50 reports and have clinicians rate alignment with NIA-AA criteria; expect >90% compliance with clear evidence mapping.
  3. Backbone convergence benchmark: Instantiate AD-CARE with eight LLMs on ADNI subset; plot accuracy vs. cost to confirm narrow accuracy range (78–80%) across backbones.

## Open Questions the Paper Calls Out
- **Expansion to non-Alzheimer dementias**: Authors recommend extending the label space to include non-AD dementias and mixed pathologies. Unresolved because current system only distinguishes NC, MCI, AD. Requires evaluation on multi-diagnosis cohorts (e.g., FTD, VaD, LBD).
- **EHR integration and prospective validation**: Future work includes integrating with electronic health records and conducting prospective multi-center studies. Unresolved due to retrospective research-cohort evaluation only. Needs live clinical deployment across diverse EHR systems.
- **Prognostic capability with additional modalities and longitudinal data**: Authors propose incorporating tau PET, digital biomarkers, and longitudinal trajectories. Unresolved as the system provides only cross-sectional diagnosis. Requires longitudinal cohorts with new modalities to assess conversion prediction.
- **Open-source/on-premise LLM backbones**: Limitation noted: reliance on proprietary APIs; future work should explore open-source or locally deployable models. Unresolved because backbone benchmarking used only cloud-based proprietary models. Requires benchmarking with open-source LLMs (e.g., Llama, Meditron) across all cohorts.

## Limitations
- Missing supplementary materials (exact LLM prompts, guideline text, exemplar cases) blocks exact replication and may affect aggregation behavior.
- Undetailed MRI predictor training (data splits, harmonization) risks performance variance on external scanners and sites.
- Unclear error-handling and retry policies in the Action module could affect robustness in noisy real-world deployments.

- Fairness improvement (21%-68% dispersion reduction): Medium-High
