# PONTE: Personalized Orchestration for Natural Language Trustworthy Explanations

## Quick Facts
- **arXiv ID:** 2603.06485
- **Source URL:** https://arxiv.org/abs/2603.06485
- **Reference count:** 40
- **Primary result:** PONTE achieves perfect faithfulness (1.00) and significantly improves completeness (0.97–0.99) and stylistic alignment (0.94–0.99) over single-pass generation via a verification-refinement loop, with minimal iterations (1.1–1.8 average).

## Executive Summary
PONTE is a human-in-the-loop orchestration framework designed to generate personalized, trustworthy natural language explanations from structured XAI artifacts (e.g., SHAP values, counterfactuals). It addresses two key challenges: the lack of personalization in explainable AI and hallucination risks inherent in LLM-based generation. By modeling user preferences as a 4-dimensional vector and combining a preference-conditioned generator with deterministic verifiers, PONTE enforces numerical faithfulness, informational completeness, and stylistic alignment through an iterative refinement loop. Evaluations on diabetes risk and loan default datasets demonstrate substantial improvements in automatic metrics, and human studies (N=17) confirm strong alignment between target preferences and perceived style, along with robust positive quality assessments across diverse user personas.

## Method Summary
PONTE takes as input a predictive model's local explanation artifacts and an initial user preference vector `s ∈ [0,1]^4` encoding technicality, verbosity, depth, and actionability. A conditional LLM generator produces a narrative conditioned on the artifact and `s`. This narrative is then verified by three components: a Faithfulness Verifier that parses mandatory tags to extract numerical claims and matches them against the source artifact under a tolerance (0.05); a Completeness Verifier that ensures all modified features from counterfactuals are mentioned; and a Style Alignment Verifier that uses an LLM-as-judge to score stylistic deviation from `s`. If any verifier fails, structured corrective feedback is injected for regeneration (up to 10 iterations). After delivery, user feedback in natural language is parsed by an LLM-based translator into a bounded delta vector `∆t`, which updates `s` via `s_{t+1} = clip(s_t + η∆t)` with `η=0.2`. An optional retrieval-grounded argumentation (RAG) module queries a certified domain knowledge base to ground claims beyond the core XAI artifact. The system thus implements a closed-loop personalization cycle that balances fidelity to the underlying model explanation with adaptation to user stylistic preferences.

## Key Results
- Completeness improved from 0.80–0.95 (single-pass baseline) to 0.97–0.99 with PONTE's verification-refinement loop.
- Stylistic alignment improved from 0.39–0.97 to 0.94–0.99.
- Achieved perfect faithfulness (1.00) across evaluated datasets.
- Average iterations to convergence were low (1.1–1.8), indicating efficient preference alignment.
- Human studies (N=17) showed strong correlation (0.75–0.78) between target preference vectors and perceived style, with consistently positive quality ratings across personas.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Explicit low-dimensional preference modeling (4D vector) enables efficient personalization of XAI narratives by distilling complex user needs into a manipulable control state.
- **Mechanism:** The Contextual Preference Model (CPM) encodes user requirements as a bounded vector `s∈[0,1]^4`. This vector conditions the LLM generator and serves as the target for the Style Alignment Verifier. User feedback is translated into a delta vector `∆t` via an LLM-based translator, updating `s` with step size `η=0.2`.
- **Core assumption:** Four dimensions sufficiently capture primary stylistic variance across heterogeneous users (e.g., patient vs. clinician).
- **Evidence anchors:** [abstract] models user preferences via a 4-dimensional vector; [section 3] details the bounded vector formulation.
- **Break condition:** Preference vector fails to converge within 10 iterations for a majority of sessions, indicating insufficient dimensionality or inconsistent feedback translation.

### Mechanism 2
- **Claim:** Deterministic verification with a closed-loop refinement process enforces faithfulness and completeness, mitigating LLM hallucinations more effectively than single-pass generation.
- **Mechanism:** The Faithfulness Verifier parses generated narratives using mandatory tags for numerical claims and performs deterministic value matching against the source XAI artifact under fixed tolerances (0.05). The Completeness check ensures all counterfactual features are mentioned. Violations trigger structured corrective feedback for regeneration.
- **Core assumption:** LLM output can be reliably parsed via controlled tags to extract concrete claims for automated verification.
- **Evidence anchors:** [abstract] combines verifiers for numerical faithfulness and completeness; [table 1] shows faithfulness pass rate 1.00 and completeness gains with verification.
- **Break condition:** Parsing failures or numerical mismatches persist after maximum refinement steps, indicating generator non-compliance or unreliable source artifacts.

### Mechanism 3
- **Claim:** Retrieval-grounded argumentation (RAG) over curated domain literature mitigates plausibility-masked hallucinations in supporting claims that extend beyond the core XAI artifact.
- **Mechanism:** For narrative segments requiring domain justification, a RAG component queries a certified knowledge base (peer-reviewed literature, regulatory docs) and injects relevant passages into the generation context, constraining the LLM's parametric knowledge.
- **Core assumption:** High-quality domain-specific knowledge bases exist and retrieved passages reduce unsupported claims without degrading fluency.
- **Evidence anchors:** [abstract] mentions optional RAG support; [section 3] describes RAG as a safeguard against plausibility-masked hallucinations.
- **Break condition:** Human evaluators rate clarity/logical consistency low when RAG is enabled, or retrieval precision is low in offline tests.

## Foundational Learning
- **Low-Dimensional Preference Manifold**  
  *Why needed:* Personalizing for every user trait is combinatorially infeasible; a 4D vector provides a tractable, continuous space for optimization and feedback integration, enabling quick adaptation (1.1–1.8 iterations).  
  *Quick check:* How would you extend the model if user studies showed "depth" and "actionability" are strongly correlated, violating independence?

- **Deterministic Verification as Rejection Sampling**  
  *Why needed:* LLMs are prone to factual drift; deterministic parsing and value matching create model-agnostic hard constraints that ensure narrative alignment with the verified XAI substrate.  
  *Quick check:* What are the limitations of mandatory tags for numerical extraction if a user requests a purely qualitative narrative?

- **Closed-Loop Personalization via Feedback Translation**  
  *Why needed:* User feedback is naturally unstructured; an LLM translator maps free-text corrections to a structured preference delta, allowing learning without manual sliders.  
  *Quick check:* What risks arise from using an LLM to interpret feedback, and how might errors in `∆t` compound over iterations?

## Architecture Onboarding
**Component map:**  
XAI Backbone -> CPM & Narrative Generator -> Verifiers (Faithfulness, Completeness, Style Alignment) -> [if fail: loop back with feedback] -> User -> Feedback Integrator -> CPM update

**Critical path:** The feedback loop (Verifiers -> Feedback Integrator -> CPM update) is the key differentiator from single-pass generation.

**Design tradeoffs:**  
- Verification latency vs. reliability: Each refinement adds LLM overhead; trade-off between iteration budget (10 max) and pass rate.  
- RAG scope vs. relevance: Broad queries increase coverage but risk noise; domain KB curation is costly.  
- Vector simplicity vs. expressiveness: 4D may miss nuanced preferences but enables robust optimization.

**Failure signatures:**  
- High completeness failure rate: Verifier detects missing counterfactual features.  
- Persistent style deviation: Style Alignment Verifier reports `||s_target - s_current|| > threshold` after max iterations.  
- Feedback instability: `∆t` vectors show high variance, preventing convergence.  
- RAG degradation: User studies show lower clarity/logical consistency when RAG is active.

**First 3 experiments:**  
1. **Baseline replication:** Run Single-Pass Baseline on 50 high-risk instances (Diabetes/LendingClub) using both generator models (Kimi, GPT-OSS). Record initial faithfulness, completeness, style alignment pass rates.  
2. **Ablation - Verifiers:** Disable Style Alignment Verifier only. Measure change in alignment scores vs. full PONTE; expect style alignment to drop to baseline.  
3. **Convergence stress test:** For a fixed target persona, run 20 Monte Carlo simulations of the feedback loop (using LLM-as-judge for feedback) and record iteration distribution; check if efficiency score `η` matches reported values (~1.9–4.7).

## Open Questions the Paper Calls Out
**Open Question 1**  
*Question:* How does retrieval quality and source attribution impact user trust in PONTE's explanations?  
*Basis:* Conclusion states future work may strengthen guarantees for retrieval quality.  
*Why unresolved:* RAG is integrated but not evaluated; no causal link between grounding quality and trust is examined.

**Open Question 2**  
*Question:* Why does personalization efficiency (`η`) vary between professional and layperson personas, and how can iteration counts be reduced for lay users?  
*Basis:* Automatic evaluation shows professional `η≈1.9–2.8`, layperson `η≈4.3–4.7`.  
*Why unresolved:* Gap observed but not analyzed; no ablation isolates causes like feedback noisiness or initial archetype suboptimality.

**Open Question 3**  
*Question:* How reliable is the LLM-based style alignment verifier against human assessments, especially for abstract dimensions like depth and actionability?  
*Basis:* Human alignment scores: depth=0.688, actionability=0.732.  
*Why unresolved:* Verifier's agreement with human judges is unreported; lower scores suggest rubric or LLM misinterpretation.

**Open Question 4**  
*Question:* To what extent does natural language feedback parsing via the LLM-based integrator introduce errors that hinder long-term preference convergence?  
*Basis:* Feedback integrator maps free-text to `∆t`; no error analysis provided.  
*Why unresolved:* Assumes accurate translation; ambiguous/contradictory input could degrade alignment over time.

**Open Question 5**  
*Question:* Are the four preference dimensions sufficient to capture all user-specific narrative needs, or are additional dimensions required?  
*Basis:* Lower alignment for depth/actionability; Economics/Finance participants rated actionable insights lower.  
*Why unresolved:* CPM derived from literature but not validated as exhaustive; potential gaps (e.g., empathy, uncertainty communication) untested.

## Limitations
- The 4D preference model assumes orthogonal dimensions capture all stylistic variance but lacks validation (e.g., correlation analysis or user study on dimensionality).
- Verifier implementation details (prompts, rubrics, parsing rules) are undisclosed, hindering exact replication.
- RAG integration lacks quantitative evaluation of hallucination reduction or trust impact; claims remain architectural.

## Confidence
- Preference modeling & feedback loop: **Medium** – Architecture clear and iteration efficiency supported, but 4D assumption and feedback translation accuracy unvalidated.
- Deterministic verification gains: **Medium-High** – Strong automatic metrics (faithfulness=1.00, completeness/style gains) support effectiveness, but verifier component ablations are missing.
- RAG for grounding: **Low** – Primarily architectural; no quantitative evidence linking RAG to reduced hallucinations or improved user scores.

## Next Checks
1. **Dimensionality validation:** Run a user study measuring perceived preferences across 10+ candidate dimensions; perform factor analysis to test if the 4D space explains >85% of variance.
2. **Verifier ablation study:** Disable individual verifiers (Faithfulness, Completeness, Style) in isolated runs; measure degradation in automatic and human scores to quantify each component's contribution.
3. **RAG hallucination audit:** For a fixed set of narratives, compute hallucination rate (unsupported claims) with RAG on vs. off using a standardized fact-checking dataset; correlate with human clarity/logical consistency scores.
