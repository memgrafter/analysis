# Fine-grained Motion Retrieval via Joint-Angle Motion Images and Token-Patch Late Interaction

## Quick Facts
*   **arXiv ID:** 2603.09930
*   **Source URL:** https://arxiv.org/abs/2603.09930
*   **Reference count:** 33
*   **Primary result:** Achieves state-of-the-art fine-grained text-motion retrieval on HumanML3D and KIT-ML by using a joint-angle motion image representation and a token-patch late interaction mechanism.

## Executive Summary
This paper addresses the limitation of global embedding methods in text-to-motion retrieval, which discard fine-grained correspondences and lack interpretability. The proposed solution transforms 3D human motion into a structured "Motion Image" using joint-angle kinematics, making it compatible with pre-trained Vision Transformers (ViTs). Instead of pooling embeddings, it employs a late interaction mechanism (MaxSim) that matches individual text tokens to motion patches. This is enhanced by Masked Language Modeling (MLM) regularization to produce context-rich text token embeddings. The framework yields state-of-the-art retrieval accuracy and provides interpretable alignment maps between specific text phrases and body joint movements over time.

## Method Summary
The method processes a 3D skeleton sequence through inverse kinematics to extract translation-invariant joint angles per frame. These are projected into a 224x224 "Motion Image" where each horizontal band corresponds to a specific joint. A pre-trained ViT processes this image to produce a set of 196 patch embeddings. Separately, a text encoder (e.g., DistilBERT) produces token embeddings for the input description. For retrieval, the similarity score is computed via MaxSim: for each text token, the maximum cosine similarity to any motion patch is found, and these maxima are averaged. The model is trained with a symmetric in-batch contrastive loss using this MaxSim score, plus an auxiliary MLM loss on the text encoder to enrich token representations with context.

## Key Results
*   On HumanML3D text-to-motion retrieval, the base model achieves 43.80% R@10 and 14.00 MedR, while a scaled version improves to 48.08% R@10.
*   The approach outperforms prior state-of-the-art methods on both HumanML3D and KIT-ML datasets.
*   The framework generates interpretable token-to-patch correspondence maps that visually align specific text tokens with relevant body joints and temporal phases.

## Why This Works (Mechanism)
### Mechanism 1: Joint-Angle Motion Representation
The claim is that decoupling joint movements from global trajectories via joint angles clarifies the kinematic signal for retrieval and creates a spatially structured image compatible with ViTs. Raw 3D positions are transformed into anatomically defined angles (e.g., hip flexion) which are translation-invariant. These are arranged into horizontal bands in a fixed-size image, ensuring each band encodes one joint's behavior. Ablations show this structured angle-based representation significantly outperforms using raw positions with the same late interaction mechanism, confirming that disentangling global drift improves the fine-grained matching signal.

### Mechanism 2: Token-Patch Late Interaction (MaxSim)
Replacing global pooling with per-token/patch matching enables fine-grained alignment. MaxSim computes a similarity matrix between all text tokens and all motion patches. The final score averages the maximum similarity found for each text token across all patches. This allows a word like "kicking" to score highly with patches representing the right leg during a kick phase, without requiring the entire motion embedding to be similar. This mechanism draws strong parallel success from video-text retrieval (e.g., Video-ColBERT). Its effectiveness is evidenced by ablations showing MaxSim with a global-pooling baseline (Pos+Global) performs worse than the full system, and by the emergence of interpretable alignment maps.

### Mechanism 3: MLM Regularization for Token Enrichment
MaxSim relies on individual token embeddings being semantically discriminative. MLM regularization, added as an auxiliary loss during training, forces the text encoder to produce token embeddings rich in contextual information from surrounding words. This stabilizes the fragile token-level matching by preventing embeddings from being purely lexical. Ablations demonstrate consistent performance gains from adding MLM, particularly in motion-to-text (M2T) direction where gallery token quality is critical, supporting the claim that context-aware tokens are more reliable for fine-grained matching.

## Architecture Onboarding
*   **Component map:**
    Raw Motion (SMPL) → Inverse Kinematics → Joint Angle Features (29-D/frame) → Per-Joint Linear Projection → Repeated-Channel Motion Image (224x224) → ViT → Patch Embeddings (N=196, gallery).
    Text → Tokenization → Text Encoder (Transformer) → Token Embeddings (M, query).
    Token Embeddings + Gallery Patch Embeddings → MaxSim → Similarity Score → Ranking.
    Text Encoder Outputs → MLM Head → MLM Loss.
    Combined Loss (Contrastive + λ·MLM) → Backpropagation.
*   **Critical path (T2M retrieval):** `Raw Motion` → `Joint Angles` → `Motion Image` → `ViT` → `Pre-computed Patch Embeddings` (gallery). `Text` → `Text Encoder` → `Query Token Embeddings`. `Query Token Embeddings` + `All Gallery Patch Embeddings` → `MaxSim` → `Ranked List`.
*   **Design tradeoffs:**
    *   **Storage vs. Granularity:** Retaining all patch embeddings (~837MB for N=196, D=256) vs. a single global vector (~4MB). The paper proposes post-hoc quantization (PQ, binary) with minor accuracy loss to mitigate this.
    *   **Late Interaction Direction:** MaxSim is unidirectional (text→motion). Applying it bidirectionally (motion→text) is avoided because motion patches are numerous and often contain uninformative static/transitional frames, which would introduce noise into the final score.
    *   **Representation Choice:** Using joint angles instead of positions sacrifices some intuitive interpretability but provides cleaner, decoupled features. The image format sacrifices temporal continuity for spatial structure that meshes with pre-trained ViTs.
*   **Failure signatures:**
    *   **Ablation - Positions + MaxSim:** If replacing angles with raw positions and using MaxSim causes a performance drop versus a global baseline, it indicates MaxSim is sensitive to representation quality and entangled features cause spurious matches.
    *   **Poor Interpretability:** If visualized MaxSim score maps (e.g., Fig. 4) are flat, noisy, or show activation on incorrect joints/times, it suggests the model failed to learn fine-grained correspondences. Potential causes include failed MLM regularization or poor joint-angle extraction.
    *   **M2T vs. T2M Gap:** If motion-to-text retrieval performs disproportionately worse than text-to-motion in ablations, it may indicate that the token embeddings stored in the motion gallery (used as queries in M2T) are not sufficiently contextualized. This is plausible since MLM regularization only acts during training, and gallery token embeddings are frozen after extraction.
*   **First 3 experiments (from paper):**
    1.  **Ablation Study (Table 3):** Systematically removes proposed components (joint angles, MaxSim, MLM) to validate their individual and combined contributions. The key comparison is the full model (`Angle + MaxSim + MLM`) against a strong baseline using raw positions and global matching (`Pos + Global`).
    2.  **Efficiency & Compression Analysis (Table 4):** Measures the storage footprint and retrieval latency of the patch-indexed gallery versus a global-embedding baseline. It also tests product quantization (PQ) and binary hashing to quantify the accuracy-storage trade-off for practical deployment.
    3.  **Qualitative Map Inspection (Figure 4):** Visualizes the MaxSim interaction score maps (token vs. time) for specific query-motion pairs. This checks the core interpretability claim: does the activation localize to semantically correct joints and temporal phases (e.g., "high kick" activates the leg band during the kick phase)?

## Limitations
*   **Representation fidelity:** The inverse kinematics pipeline for extracting joint angles is not exhaustively detailed; implementation variations could alter Motion Image statistics and affect the "clean band" assumption.
*   **Scalability trade-off:** The storage cost of pre-computed patch embeddings (≈837MB) is significantly higher than global vectors (~4MB), posing practical challenges for large-scale deployment even with proposed compression.
*   **Directional MaxSim asymmetry:** Applying late interaction only in the text→motion direction is a design choice based on the assumption that motion patches are noisier than text tokens. This asymmetry is not formally validated or compared to a bidirectional variant.

## Confidence
*   **Joint-angle motion representation:** **Medium.** The conceptual decoupling is well-motivated and supported by ablations vs. raw positions, but evidence relies heavily on the paper's own implementation without external biomechanical validation.
*   **Token-patch late interaction (MaxSim):** **High.** The mechanism is clearly described, has strong parallels in established video-text retrieval work (Video-ColBERT, ColPali), and ablations confirm its contribution over global pooling.
*   **MLM regularization for token enrichment:** **Medium.** Ablations show consistent gains, especially in M2T. However, the specific break condition (context overwhelming action semantics) is not stress-tested, and corpus support for this exact application is weak.

## Next Checks

2.  **Benchmark storage/latency at scale:** Compare end-to-end retrieval latency and GPU memory footprint of the patch-indexed gallery against a global-embedding baseline on a large-scale subset (e.g., 10K motions). Quantify the accuracy drop from applying the proposed PQ (8-bit) and binary hashing.
3.  **Probe MaxSim asymmetry:** Run an experiment where MaxSim is applied bidirectionally (both T2M and M2T) with identical embedding architectures. Measure changes in R@10. If M2T degrades, analyze per-patch MaxSim scores in the M2T direction to confirm if noisy/uninformative patches are being selected.
