# Large Language Models for Designing Participatory Budgeting Rules
## Quick Facts
- **arXiv ID**: 2602.09349
- **Source URL**: https://arxiv.org/abs/2602.09349
- **Reference count**: 40
- **Primary result**: LLM-generated PB rules achieve higher utility than existing handcrafted proportional rules while maintaining comparable fairness on 600+ real-world instances.

## Executive Summary
Participatory budgeting (PB) involves allocating a limited budget to public projects based on voter preferences, balancing utilitarian welfare and fairness. This paper introduces LLMRule, an automated framework that uses large language models (LLMs) within an evolutionary search to design heuristic PB rules. The framework evaluates rules on a fitness function combining normalized utilitarian welfare and a penalty based on a tractable approximation of Strong-EJR fairness, using precomputed maximal cohesive groups to accelerate evaluation. Trained and tested on over 600 real-world PB instances from the US, Canada, Poland, and the Netherlands, LLMRule produces rules that significantly improve utilitarian welfare compared to existing proportional rules while achieving comparable fairness, for both approval and cardinal ballots. The results demonstrate the potential of LLM-driven automated rule design to address longstanding trade-offs in PB without requiring deep domain expertise.

## Method Summary
LLMRule maintains a population of heuristic rules represented as natural language descriptions and executable Python code implementing a greedy prioritization function. In each generation, rules are evaluated on a dataset of PB instances; fitness combines the normalized utilitarian welfare (relative to the optimal allocation) and a penalty if the rule’s Strong-EJR approximation score falls below a threshold ε. Parent rules are selected with probability proportional to their fitness rank, and offspring are generated via LLM prompts—either exploring new combinations of ideas or modifying existing parameters. Prompt strategies are refined when progress stalls. A key computational innovation is the precomputation of all maximal cohesive groups for each instance using frequent itemset mining (Apriori), which reduces the cost of computing the Strong-EJR approximation from exponential to near-linear in the number of agents for the top σ groups. This enables efficient multi-objective optimization across hundreds of real-world instances.

## Key Results
- For approval ballots, LLMRule attains out-of-distribution utilitarian welfare up to 0.814 and Strong-EJR approximation 0.901, outperforming SeqPhrag (0.695, 0.956) and MaximinSupp (0.691, 0.960).
- For cardinal ballots, LLMRule reaches welfare 0.972 and fairness 0.993, surpassing GreedUtil (0.961, 1.0).
- LLM-generated rules achieve higher utility than existing handcrafted proportional rules while maintaining comparable fairness across diverse real-world datasets.

## Why This Works (Mechanism)
### Mechanism 1: Evolutionary Search with LLM-Generated Heuristics
- **Claim**: An evolutionary loop, where an LLM generates and refines heuristic PB rules guided by fitness-based selection, efficiently explores the space of greedy allocation strategies to optimize the utility-fairness trade-off.
- **Mechanism**: A population of `h` heuristic rules (represented as natural language descriptions + Python code) is maintained. Rules are evaluated on a dataset of PB instances; fitness `q(f)` combines normalized utilitarian welfare and a penalty if Strong-EJR approximation `φ` falls below a threshold `ε`. Parent rule(s) are selected with probability proportional to fitness rank, and new offspring are generated via LLM prompts: *exploration* prompts (crossover-like combination of parent ideas) and *modification* prompts (parameter tuning, simplification). Stagnation detection triggers prompt refinement, where new prompt strategies are designed to be qualitatively different.
- **Core assumption**: LLMs can generate meaningful, diverse heuristic variations when conditioned on existing high-fitness examples and explicit strategic prompts, and these heuristics can be empirically evaluated on real PB instances to guide search.
- **Evidence anchors**:
  - [abstract]: "incorporating LLMs into an evolutionary search procedure for automating the design of PB rules."
  - [section 3.4]: Details population management, prompt strategies (E1, M1), fitness function Equation 6, and stagnation-driven prompt refinement.
  - [corpus]: Neighbors discuss LLMs for algorithmic design (e.g., EoH, FunSearch) but not specifically for PB rule design; evidence for the broader paradigm is strong, but direct application to this multi-objective PB context is novel.
- **Break condition**: If LLM-generated offspring rules consistently fail to produce valid executable code or if fitness improvements plateau despite prompt diversification, indicating the LLM cannot generate novel, beneficial heuristic structures within the constrained representation.

### Mechanism 2: Strong-EJR Approximation as a Tractable Fairness Objective
- **Claim**: By redefining Strong-EJR verification to consider only *maximal* cohesive groups, a computable approximation objective `φ` (Equations 3,4) is derived that correlates with fairness and is feasible for use as a penalty term in fitness evaluation.
- **Mechanism**: Standard Strong-EJR requires checking *all* cohesive groups `N` for all project subsets `P`, which is intractable (coNP-complete). Theorem 1 proves that if a maximal `P`-cohesive group `N_max` (i.e., not properly contained in any other `P`-cohesive group) satisfies the fairness condition, then all smaller cohesive groups for the same `P` automatically do. Thus, verification and the approximation objective `φ` only need to consider maximal groups. `φ` computes the minimum satisfaction ratio across agents in `N_max` for each maximal group, averaging over the top-σ groups sorted by "deservingness" `γ = (|N|/n * b) / c(P)`.
- **Core assumption**: Satisfaction of Strong-EJR for maximal cohesive groups is sufficient to imply satisfaction for all smaller cohesive groups for the same `P`, and the `φ` score computed from these maximal groups serves as a meaningful, differentiable proxy for overall fairness.
- **Evidence anchors**:
  - [section 3.1]: Theorem 1 and the updated Definitions 8,9 establishing the equivalence for maximal groups.
  - [section 3.2]: Definition of `φ` based on maximal groups and justification for using `γ` for prioritization.
  - [corpus]: Weak direct evidence; corpus discusses fairness notions (EJR, PJR) but not this specific tractable approximation. The paper's theoretical derivation is the primary evidence.
- **Break condition**: If maximal cohesive groups are extremely numerous (2^m) and the top-σ truncation (with small σ) leads to `φ` scores that no longer correlate with actual fairness violations on held-out instances, the objective becomes misleading.

### Mechanism 3: Accelerated Computation via Maximal Cohesive Group Mining
- **Claim**: By precomputing and sorting all maximal cohesive groups using frequent itemset mining (Apriori algorithm) based on support `supp(P) = |N_max|/n`, the per-rule evaluation cost of `φ` is reduced from exponential in `m` to linear in the number of agents `n` (for a fixed, limited number of top groups `σ`).
- **Mechanism**: Step (i) (finding all maximal `P`-cohesive groups `N_max`) is instance-specific and independent of the rule `f`. It uses Apriori with minimum support `min_p c(p)/b` to generate candidate `P` and their `supp(P)`. For each candidate, finding `N_max` (checking agents approving all `p∈P`) is O(mn). The list is sorted by descending `γ`. Step (ii) (computing satisfaction ratios for `f`) is then O(σ * n) after `f` is run. This avoids recomputing cohesive groups for every evaluated rule.
- **Core assumption**: The set of maximal cohesive groups is static for a given PB instance profile and can be precomputed once; also, limiting to top-σ groups by `γ` retains the most "critical" groups for fairness assessment.
- **Evidence anchors**:
  - [section 3.3]: Complexity analysis splitting computation into (i) and (ii); use of Apriori; final complexity O(s*n) with `s ≤ σ`.
  - [section 4.1]: Implementation caps `σ` at 100 for large `m` to manage runtime.
  - [corpus]: Weak; corpus includes references to frequent pattern mining but not this specific application to PB fairness evaluation.
- **Break condition**: If the number of maximal cohesive groups `s` is huge (close to 2^m) even after pruning, precomputation becomes infeasible, or if the top-σ groups by `γ` miss crucial fairness violations (e.g., a large group with lower `γ` but high dissatisfaction), the approximation becomes unreliable.

## Architecture Onboarding
- **Component map**: LLM Interface → Rule Representation (description, code, fitness) → Fitness Evaluator (uses precomputed maximal cohesive groups) → Evolutionary Loop (selection, offspring generation) → Prompt Strategy Manager (assigns scores, triggers refinement) ↺ (loops) and Strong-EJR Precomputation Module (runs per instance before evolution)
- **Critical path**: Instance precomputation (cohesive groups) → rule generation (LLM) → rule evaluation (run `f`, compute `ω'` and `φ` using precomputed groups) → selection → prompt strategy update → repeat.
- **Design tradeoffs**:
  - Greedy rule representation: flexible for completion methods but may miss globally optimal allocations. Trade-off: simplicity and speed vs. optimality.
  - Strong-EJR approximation threshold `ε`: Higher `ε` enforces stricter fairness (fewer rules pass) but may discard high-utility rules. Lower `ε` allows more utility but weaker guarantees. Set to best baseline's average `φ` on training set.
  - Top-`σ` cohesive groups: Smaller `σ` speeds up evaluation but risks missing representative groups. Larger `σ` is more thorough but closer to exponential in worst-case.
- **Failure signatures**:
  1. High invalid rule rate: LLM generates code with syntax errors or not following `priority()` template. Mitigation: stricter prompt engineering, code validation step.
  2. Fitness stagnation: No improvement in top-`l` rules for `t` generations. Mitigation: prompt refinement module should add novel strategies.
  3. Precomputation blowup: For instances with many projects (`m` large), Apriori generates too many candidate `P`. Mitigation: use more efficient maximal itemset mining (e.g., LCM) or increase minimum support.
- **First 3 experiments**:
  1. Baseline comparison: Train LLMRule on small approval/cardinal PB instances. Evaluate on ID and OOD test sets. Compare `ω'` and `φ` against MaxUtil, GreedUtil, MES variants, SeqPhrag, MaximinSupp. Expected: LLMRule rules achieve higher `ω'` than proportional rules with comparable `φ`.
  2. Ablation on prompt strategies: Run LLMRule with only exploration prompts, only modification prompts, and both. Measure convergence speed and final Pareto front quality. Expected: combination yields best trade-off; modification improves utility; exploration improves diversity.
  3. Sensitivity to `ε` and `σ`: Vary `ε` (e.g., 0.9, 0.95, 0.99) and `σ` (e.g., 50, 100, all). Monitor changes in average `ω'` and `φ` on a validation set. Expected: higher `ε` reduces `ω'`; lower `σ` slightly reduces `φ` but speeds up training.

## Open Questions the Paper Calls Out
1. **How can LLMRule be extended to generate PB rules with provable fairness guarantees (e.g., satisfying EJR or PJR) while maintaining high utilitarian welfare?**
   - **Basis in paper**: The conclusion and Appendix H explicitly state that generating PB rules with provable fairness guarantees is a promising extension, noting that current LLM-generated rules are only empirically fair.
   - **Why unresolved**: The framework uses a penalty term based on Strong-EJR approximation, but this does not ensure theoretical satisfaction of fairness properties. Provable guarantees would increase trust and adoption.
   - **What evidence would resolve it**: Integrate formal verification (e.g., SMT solvers) into the evolutionary loop to certify fairness, or design LLM prompts that encode known sufficient conditions for EJR/PJR satisfaction, then empirically test on diverse instances.

2. **What is the scalability limit of LLMRule regarding the number of projects, and can more efficient algorithms (beyond Apriori) compute Strong-EJR approximation for larger instances?**
   - **Basis in paper**: Appendix H notes that the current O(2^m) complexity from Apriori may not scale for m > 25, which limits applicability to larger real-world PB instances.
   - **Why unresolved**: Many practical PB problems have more than 25 projects; the exponential dependence could make LLMRule infeasible without improved computation.
   - **What evidence would resolve it**: Benchmark LLMRule with alternative frequent pattern mining (e.g., FP-growth) or sampling-based approximations on instances with m = 30–100, measuring runtime and rule quality trade-offs.

3. **Beyond greedy heuristics, can LLMRule discover and evolve non-greedy PB rule structures (e.g., dynamic programming, integer programming) that achieve superior utility-fairness trade-offs?**
   - **Basis in paper**: The paper restricts rules to greedy prioritization due to flexibility and practicality, but does not justify why other paradigms are excluded or whether they might perform better.
   - **Why unresolved**: Greedy rules are widely used but may be suboptimal; exploring a broader space of algorithmic templates could yield novel, higher-performing rules.
   - **What evidence would resolve it**: Modify LLMRule’s code template to allow arbitrary decision procedures (not just greedy), then analyze generated rules for non‑greedy patterns and compare their utility‑fairness performance against greedy baselines.

4. **Does the penalty-based fitness function in LLMRule effectively capture the utility-fairness trade-off, or would a dedicated multi-objective evolutionary algorithm (e.g., NSGA-II) produce a more diverse and Pareto-optimal set of rules?**
   - **Basis in paper**: The authors acknowledge Challenge I (multi-objective optimization) and use a simple penalty term, but note that existing LLM‑based methods have not addressed multi‑objective problems, suggesting a gap.
   - **Why unresolved**: The penalty approach may force a single threshold and miss intermediate trade‑offs; a true multi‑objective method could better explore the frontier.
   - **What evidence would resolve it**: Replace the fitness function with NSGA‑II selection within LLMRule, compare the spread and convergence of the resulting rule populations on the Pareto front, and assess whether more diverse trade‑offs are found.

5. **How robust is LLMRule’s performance to hyperparameters (population size, ε threshold, prompt strategies) and the choice of LLM model (e.g., GPT-4o vs. GPT-4)?**
   - **Basis in paper**: The paper fixes many hyperparameters and uses GPT‑4o mini without justification; sensitivity is not studied, leaving uncertainty about generalizability and reproducibility.
   - **Why unresolved**: Hyperparameter choices can significantly affect evolutionary search outcomes; model capabilities vary, impacting rule quality.
   - **What evidence would resolve it**: Conduct extensive ablation studies varying each hyperparameter and testing multiple LLM models (e.g., GPT‑4, Claude 3), measuring consistency in utility and fairness across runs and datasets.

## Limitations
- Limited geographic and dataset diversity: Evaluation covers only four countries (US, Canada, Poland, Netherlands) with 600+ instances; performance on other regions or larger, more complex PB elections remains unknown.
- Scalability concerns: The Apriori-based precomputation may become infeasible for instances with many projects (m > 50), and the top‑σ truncation might miss critical fairness violations, potentially compromising the Strong-EJR approximation's fidelity.
- LLM dependency: The framework relies on a specific commercial model (GPT-4o mini); smaller or open‑source LLMs may yield lower-quality heuristics, and prompt engineering may overfit to the chosen model.

## Confidence
- LLMRule effectiveness: **High** on evaluated datasets; **Medium** for broader generalization due to limited geographic coverage and reliance on a specific LLM.
- Strong-EJR approximation: **High** theoretical soundness; **Medium** empirical validity because top‑σ truncation may miss relevant groups in some instances.
- Evolutionary search efficiency: **Medium** – convergence demonstrated, but LLM randomness, stagnation, and sensitivity to prompt strategies remain concerns.

## Next Checks
1. **Scalability testing**: Run LLMRule on synthetic PB instances with m = 100–500 projects and n = 10,000–100,000 voters. Measure runtime, validity rate of generated rules, and stability of utility/fairness scores.
2. **Approximation fidelity**: On small instances (m ≤ 20), compute exact Strong-EJR satisfaction for the generated rules and correlate with the φ score to validate the approximation's accuracy.
3. **Model robustness**: Replace GPT‑4o mini with two alternative LLMs (e.g., Llama‑3‑70B, Mistral‑Large) and compare fitness trajectories, final rule quality, and invalid rule rates to assess dependence on the base model.
