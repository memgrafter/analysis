# Towards Orthographically-Informed Evaluation of Speech Recognition Systems for Indian Languages

## Quick Facts
- **arXiv ID:** 2603.00941
- **Source URL:** https://arxiv.org/abs/2603.00941
- **Reference count:** 0
- **Primary result:** OIWER reduces average error rates by 6.3 points, narrows inflated model gaps (e.g., Gemini-Canary from 18.1 to 11.5), and aligns 4.9 points closer to human-perceived error than prior normalization methods.

## Executive Summary
Speech recognition evaluation for Indian languages suffers from over-penalization due to legitimate orthographic variations (e.g., spelling differences, word splitting, code-mixing). This paper introduces Orthographically-Informed WER (OIWER), which expands the gold transcript with permissible variants generated by an LLM and refined by humans. The modified alignment algorithm then treats any match to a variant as correct, eliminating false substitution errors. Across 22 Indian languages, OIWER lowers average error by 6.3 points, compresses exaggerated performance gaps between models, and aligns much more closely with human judgments of error. Crucially, the LLM-generated variants correlate highly (R²=0.89) with human-curated ones, enabling scalable benchmark creation for orthographically diverse languages.

## Method Summary
The study builds on the IndicVoices benchmark and uses outputs from multiple ASR systems (Canary, Gemini, Azure). Linguists define seven categories of orthographic variation (e.g., matra, loanwords, splitting/merging). For each utterance transcript, a large language model (Gemini-2.5-Pro) is prompted to produce context‑aware variants for every word/subsequence according to these categories. Human experts then post‑edit these suggestions via a LabelStudio interface, yielding a final set of permissible forms per reference position. The OIWER score is computed by a dynamic programming alignment between the ASR prediction and the sequence of variant sets, where a prediction incurs zero substitution cost if it appears in the corresponding set. This pipeline produces a robust metric that respects linguistic flexibility while preserving sensitivity to true errors.

## Key Results
- OIWER reduces average error rates by 6.3 points compared to standard WER across IndicVoices.
- The performance gap between Gemini and Canary shrinks from 18.1 to 11.5 WER points, indicating narrowed exaggeration.
- OIWER aligns 4.9 points closer to human‑perceived error than prior normalization (WER‑SN), and LLM‑generated variants achieve a 0.89 correlation with human‑corrected ones.

## Why This Works (Mechanism)
**1. Expansion of reference variants reduces false substitutions.** Standard WER aligns a single gold transcript to ASR output; OIWER supplies a set of permissible orthographic variants for each gold word (via LLM + human review). During alignment, matching any variant avoids a substitution penalty, directly eliminating over‑penalization. Evidence: average error drops by 6.3 points and substitution counts fall by 28.5K summed across languages. Break condition: incomplete or noisy variant sets could re‑introduce errors.

**2. Narrowing of exaggerated performance gaps.** Different ASR systems may output different but valid orthographic forms (e.g., standardized vs. colloquial). Standard WER punishes any deviation from the single gold form, unfairly favoring one style. OIWER accepts any variant, so model differences reflect linguistic accuracy rather than arbitrary spelling. Evidence: the Gemini–Canary WER gap contracts from 18.1 to 11.5 points. Break condition: bias in variant sets toward one model’s output could artificially narrow gaps.

**3. LLM‑generated variants as a scalable proxy for human curation.** Prompting an LLM with variation categories generates candidate forms quickly; brief human post‑editing (1.2 min/utterance) corrects major issues. A strong correlation (R²=0.89) between OIWER computed with LLM‑only vs. human‑corrected variants shows the LLM captures the core variation distribution. Evidence: correlation holds across languages despite variant counts ranging from 1.3× to 3.2× per word. Break condition: poor LLM quality (many invalid or missing variants) would degrade the proxy.

## Foundational Learning
### Orthographic Permissibility & Morphological Richness
- **Why needed:** Indian languages often lack rigid spelling standards; valid forms arise from agglutination, dialectal matra use, loanword transliteration, and code‑mixing. Understanding this prevents misinterpreting such outputs as ASR errors.
- **Quick check:** For the word "पुस्तकालय" (library), list at least two other valid orthographic forms based on splitting/merging rules and explain why they are permissible.

### Minimum Edit Distance & Dynamic Programming Alignment
- **Why needed:** WER and OIWER are computed via Levenshtein distance. OIWER modifies the DP recurrence to allow matches against a set of tokens per reference position instead of a single token.
- **Quick check:** In standard WER DP, what does `dp[i][j] = min(dp[i-1][j] + 1, dp[i][j-1] + 1, dp[i-1][j-1] + cost)` represent? How would you change `cost` to incorporate word‑variation sets?

### Human‑in‑the‑Loop Data Curation for Low‑Resource Languages
- **Why needed:** Creating gold variants manually for thousands of utterances is prohibitive. The paper’s framework uses LLM generation followed by efficient human verification (1.2 min/utterance vs. 2.4 min for full transcription).
- **Quick check:** Why is post‑editing LLM‑generated variations faster than de novo transcription? What risks does this hybrid approach mitigate compared to fully automated or fully manual creation?

## Architecture Onboarding
**Component map:** LLM Variation Generator -> Human Post-Editing Interface (LabelStudio) -> OIWER Scorer -> Evaluation Pipeline

**Critical path:** LLM Generation → Human Review → DP Alignment → Metric Calculation. A break in LLM generation quality propagates to human review load and final metric stability.

**Design tradeoffs:**  
- LLM choice vs. cost/quality (larger models give better variants but are slower/expensive).  
- Variant set granularity (allowing merged subsequences increases coverage but complicates alignment).  
- Human review depth (light review maximizes speed but risks accepting LLM hallucinations).

**Failure signatures:**  
- High WER‑OIWER delta per language (variant set too small or missing local forms).  
- Low LLM‑Human correlation (LLM fails to capture variation distribution).  
- Post‑editing high reject rate (LLM generates too much noise).  
- DP alignment time explosion (variant sets become very large).

**First 3 experiments:**  
1. Variant Coverage Sanity Check – manually enumerate known variants for a sample and compare recall against final sets; expect >90% coverage.  
2. WER vs. OIWER Gap Analysis – run a strong baseline ASR and measure delta across languages; larger drops expected for languages with known orthographic flexibility.  
3. LLM‑Only Variant Stress Test – compute OIWER using only LLM‑generated variants; a small delta (<1.0 WER) from the primary OIWER validates the proxy claim.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can OIWER be extended to account for inherent audio ambiguities that produce multiple valid transcriptions without additional context, which currently contribute to a 6.9 WER gap from human perception?
- **Basis in paper:** [explicit] In Section 6.2, the authors state that the remaining gap between OIWER and perceived WER is due to "inherent ambiguities in the audio that cannot be resolved without further context."
- **Why unresolved:** OIWER currently focuses solely on orthographic variations and does not incorporate acoustic or discourse context to resolve such ambiguities.
- **What evidence would resolve it:** Evaluating the integration of contextual features (e.g., prosody, surrounding turns) into the variation generation or alignment process to reduce this gap.

### Open Question 2
- **Question:** Why do Telugu and Konkani exhibit a significantly larger gap between OIWER and perceived WER compared to other languages, as noted in Section 6.2?
- **Basis in paper:** [explicit] Section 6.2 reports that the gap is "particularly high for Telugu and Konkani" despite using OIWER.
- **Why unresolved:** The paper attributes this to audio ambiguities but does not analyze whether language‑specific orthographic features, data quality, or other factors drive this disparity.
- **What evidence would resolve it:** A detailed per‑language analysis correlating gap size with linguistic properties (e.g., morphological complexity, script consistency), dataset characteristics (audio noise, speaker diversity), or variation coverage metrics.

### Open Question 3
- **Question:** Does the effectiveness of LLM‑generated orthographic variations as a proxy for human‑corrected variations generalize uniformly across all 22 Indian languages in IndicVoices?
- **Basis in paper:** [inferred] While the paper reports a strong overall correlation (0.89) between LLM and human variations (Section 6.4), it acknowledges substantial variation in the number of generated variants per language (1.3 to 3.2) and does not provide per‑language correlation breakdowns.
- **Why unresolved:** High variation counts for low‑resource languages (e.g., Kashmiri) suggest LLM may struggle or overgenerate in some contexts, but the impact on OIWER accuracy per language is unknown.
- **What evidence would resolve it:** Computing per‑language correlations between OIWER\_LLM and OIWER\_Human, and analyzing error cases where LLM variations fail to match human corrections, especially for languages with higher variation counts.

## Limitations
- The exact LLM prompt and few‑shot examples used for variation generation are not disclosed, making reproduction sensitive to prompt engineering.
- The dynamic programming recurrence for handling merged subsequences is incompletely specified, risking implementation errors.
- LLM variant quality is validated only on a small sample (R²=0.89) and lacks cross‑LLM or per‑language robustness tests.
- Evidence relies on internal IndicVoices data; external replication is missing.
- Generalizability to non‑Indian orthographically diverse languages remains unknown.

## Confidence
- **OIWER reduces over‑penalization:** High – internal results show large substitution reductions and a consistent 6.3‑point WER drop.
- **OIWER narrows model gaps:** Medium – effect may be influenced by variant set bias; independent cross‑model verification is needed.
- **LLM‑generated variants are a scalable proxy:** Medium – correlation is moderate and limited to one LLM; robustness across languages and models is unproven.

## Next Checks
1. **Cross‑LLM variant generation:** Run the same prompt on at least two other LLMs (e.g., GPT‑4, Llama‑3) for a shared subset. Compare variant set overlap, average set size, and resulting OIWER stability.
2. **Blind human alignment study:** For 200 utterances across five languages, compute standard WER, OIWER (LLM+human), and have expert judges rate perceived error. Verify that OIWER’s correlation with human perception significantly exceeds that of standard WER and prior normalization methods.
3. **Synthetic DP correctness test:** Create a controlled test suite with known reference variant sets and ASR predictions, including cases with merged words. Confirm that the OIWER implementation returns the exact minimum edit distance (via brute‑force enumeration) for all test cases.
