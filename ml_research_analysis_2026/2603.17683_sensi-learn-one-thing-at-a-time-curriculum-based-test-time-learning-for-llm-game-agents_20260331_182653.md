# Sensi: Learn One Thing at a Time -- Curriculum-Based Test-Time Learning for LLM Game Agents

## Quick Facts
- **arXiv ID:** 2603.17683  
- **Source URL:** https://arxiv.org/abs/2603.17683  
- **Reference count:** 40  
- **Primary result:** Completed test-time learning curriculum in ~32 actions (50–94× sample efficiency vs. baselines) but solved 0 game levels due to perception errors.

## Executive Summary
Sensi is a framework for test-time curriculum learning in LLM-based game agents. It introduces a two-player architecture that separates perception (Observer) from action (Actor), a database-as-control-plane to make agent context programmatically steerable, and an LLM-as-judge with dynamically generated rubrics to sequence and evaluate learning goals. The system follows a predefined curriculum of learning items, advancing only when the judge scores mastery above a threshold, and accumulates verified facts for subsequent learning.

On the ARC-AGI-3 benchmark, Sensi completed its entire learning curriculum in approximately 32 action attempts, representing a 50–94× improvement in sample efficiency over baselines requiring 1,600–3,000 attempts. However, the agent solved zero game levels. The failure was traced to a self-consistent hallucination cascade originating in the perception layer, which corrupted the learning process and shifted the bottleneck from learning efficiency to perceptual grounding.

## Method Summary
Sensi employs an external state machine to manage a curriculum of learning items stored in a SQLite database. Each turn, a five-LLM pipeline processes the new game frame: FrameDiff generates a structured description of changes; MetricGen (if a new item starts) creates an evaluation rubric; SenseScore rates progress on the active item; Observer updates hypothesis lists; Actor selects the next action. All prompts are constructed by querying the database, which serves as the central control plane, enabling modularity and debuggability. Curriculum items advance when the SenseScore exceeds a threshold, and completed items' hypotheses are promoted to facts, building a knowledge base for later learning.

## Key Results
- Completed full learning curriculum in ~32 action attempts.  
- Achieved 50–94× sample efficiency compared to 1,600–3,000 attempts baseline.  
- Solved 0 game levels; failure traced to self-consistent hallucination cascade in perception.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Separating perception from action via a two-player architecture enables structured hypothesis accumulation and reduces stochastic degradation in learning.  
**Mechanism:** The Observer (Player1) interprets frame diffs and updates `guesses`/`figured_out`; the Actor (Player2) selects actions based on these. This factorization prevents a single LLM call from conflating perception, reasoning, and decision-making.  
**Core assumption:** LLMs can maintain persistent state across turns with consistent interfaces; role specialization improves reliability.  
**Evidence:** Described in the abstract and Section 3.1; neighboring work on multi-agent adaptation provides weak support.  
**Break condition:** Inconsistent hypothesis updates or misinterpreted list semantics cause the separation to fail, reverting to monolithic inefficiency.

### Mechanism 2
**Claim:** A curriculum-based learning system managed by an external state machine sequences learning goals, preventing hypothesis space explosion and enabling focused sample-efficient exploration.  
**Mechanism:** A predefined ordered queue of learning items is advanced only when an LLM-as-judge scores mastery above a threshold. Completed items' `figured_out` entries are promoted to `facts`, creating a knowledge accumulation chain where later learning builds on verified prior knowledge.  
**Core assumption:** The environment's mechanics have a natural sequential dependency (e.g., understanding actions precedes understanding energy), and a hand-designed curriculum approximates this dependency.  
**Evidence:** The abstract and Section 4.2 discuss the sequential dependency; curriculum learning is well-supported in deep RL literature, though test-time application is novel.  
**Break condition:** If the curriculum order is suboptimal or the judge's threshold is mis-calibrated, the agent may stall or learn incorrect foundations.

### Mechanism 3
**Claim:** A database-as-control-plane makes the LLM's context window externally programmable, enabling modular, steerable, and debuggable agent behavior by externalizing all cognitive state.  
**Mechanism:** All agent state (learning queue, facts, guesses, history) resides in SQLite tables. Prompts are constructed by querying this database, and LLM outputs update it. This separates control logic from inference, allowing runtime behavior modification via database operations.  
**Core assumption:** LLM performance can be steered by precise, structured context injection, and complex agent behavior can be decomposed into database state transitions plus prompt generation.  
**Evidence:** The abstract and Section 4.4 describe this as a form of neuro-symbolic programming. Direct analogs are limited.  
**Break condition:** Poor database schema design, query performance bottlenecks, or information loss due to query limits can undermine steerability and latency.

## Foundational Learning
### POMDP with Dual Discovery
- **Why needed:** ARC-AGI-3 requires an agent to learn both transition dynamics *and* the reward function from scratch; standard POMDP solvers assume known dynamics/reward.  
- **Quick check:** Explain why learning the win condition is a reward discovery problem separate from learning action effects (transition dynamics).

### In-Context Knowledge Accumulation with Persistent Structured State
- **Why needed:** Unlike pure chain-of-thought or test-time training, Sensi stores learned facts in a database that persists across context windows, enabling multi-hundred-turn learning without context length limits.  
- **Quick check:** How does Sensi's approach differ from simply including all past interactions in the prompt? What failure mode does the database prevent?

### Self-Consistent Hallucination Cascade
- **Why needed:** A single perception error (frame diff) can propagate through hypothesis formation, get validated by an internal-consistency judge, become a "fact," and contaminate all subsequent learning.  
- **Quick check:** Trace the cascade: starting from a wrong frame diff, list each component that fails to correct the error and how it compounds.

## Architecture Onboarding
**Component Map:**  
The pipeline consists of: FrameDiff (LLM1) → MetricGen (LLM2) → SenseScore (LLM3) → Observer/Player1 (LLM4) → Actor/Player2 (LLM5). The central state is a SQLite DB with 6 tables (`items_to_learn`, `inputs`, `game`, `guesses`, `figured_outs`, `losing_action_seqs`). An external state machine controls the curriculum.

**Critical Path:**  
Each game turn runs the 5-LLM pipeline, reading from and writing to the DB. The active learning item advances when SenseScore ≥ τ=8, at which point `figured_out` hypotheses are promoted to `facts`. The entire curriculum completes in ~32 turns.

**Design Tradeoffs:**  
- Sample efficiency vs. perceptual grounding: curriculum achieves efficiency but fails if perception is faulty.  
- External state vs. latency: DB queries add I/O but enable steerability and debuggability.  
- Hand-designed curriculum vs. generality: current sequence is game-specific; automatic generation is future work.

**Failure Signatures:**  
1. Self-consistent hallucination cascade (high SenseScore despite incorrect facts).  
2. State machine stall (SenseScore never reaches threshold).  
3. Database injection errors (prompts not reflecting DB state).  
4. LLM1 pattern drift (FrameDiff output format deviation).

**First 3 Experiments:**  
1. **Isolate Perception:** Run FrameDiff on known frame pairs with ground-truth diffs; measure accuracy; expect >90% for reliable learning.  
2. **Validate Judge:** Inject a mix of correct/incorrect `figured_out` lists into SenseScore prompts; check correlation between score and factual correctness; expect low correlation, indicating vulnerability.  
3. **Curriculum Sanity Check:** Replace FrameDiff with ground-truth diffs; run full pipeline; verify sequential item transitions and correct fact accumulation; if still fails, curriculum or judge is flawed.

## Open Questions the Paper Calls Out
- **Hybrid frame differencing:** Can combining programmatic and neural differencing eliminate the hallucination cascade while preserving sample efficiency? (Currently untested)  
- **Automatic curriculum generation:** Does an autonomous curriculum improve adaptability across games without sacrificing efficiency? (Hand-designed curriculum limits generality)  
- **Multi-agent fact validation:** Could multiple agents with a shared database cross‑validate facts to prevent cascades? (Single‑agent sense scorer vulnerable)  
- **Model capability confounds:** Are differences between ChatGPT 5.1 and Gemini 3.1 Pro responsible for v2's failure to solve levels? (Unclear)  
- **Robust LLM-as-judge:** Can the sense scorer be grounded to avoid rewarding coherent but false hypotheses? (Dynamic rubrics lack grounding)

## Limitations
- Missing prompt templates, model parameters, and curriculum specifics block faithful reproduction.  
- No ablation isolating the perception bottleneck; the hallucination cascade diagnosis is indirect.  
- Evaluation limited to a single game (ARC-AGI-3); generalizability unproven.

## Confidence
- **Sample efficiency:** High  
- **Perception as root cause:** Medium  
- **Architectural mechanisms:** Low to Medium

## Next Checks
1. **Perception accuracy test:** Evaluate FrameDiff on a large set of frame pairs with ground-truth diffs; if accuracy <90%, perception is the bottleneck.  
2. **Judge integrity test:** Inject controlled `figured_out` lists (correct/incorrect) into SenseScore; measure correlation between score and factual correctness; expect low correlation if cascade vulnerability exists.  
3. **Curriculum isolation test:** Replace FrameDiff with ground-truth diffs; if pipeline still fails, curriculum order or judge calibration is flawed; if succeeds, perception is the sole issue.
