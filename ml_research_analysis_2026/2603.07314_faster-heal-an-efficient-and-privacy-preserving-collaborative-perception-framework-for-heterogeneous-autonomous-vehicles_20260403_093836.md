# Faster-HEAL: An Efficient and Privacy-Preserving Collaborative Perception Framework for Heterogeneous Autonomous Vehicles

## Quick Facts
- arXiv ID: 2603.07314
- Source URL: https://arxiv.org/abs/2603.07314
- Reference count: 31
- Primary result: Improves detection Average Precision (AP) by 2% over state-of-the-art on OPV2V-H, reduces trainable parameters by 94%, and achieves 1.16× higher training throughput with 38.6% lower peak GPU memory.

## Executive Summary
Faster-HEAL tackles the challenge of feature domain gaps in heterogeneous collaborative perception, where different autonomous vehicles employ varied sensors and models. By fine-tuning low-rank visual prompts (LIFT) on a frozen unified feature space, it aligns new agents' features without exposing raw data or full model parameters, thus preserving privacy. Evaluated on the OPV2V-H dataset, it yields a 2% AP improvement over prior art while drastically cutting trainable parameters (94% reduction) and computational overhead (1.16× throughput, 38.6% less GPU memory). The two-stage training paradigm—first establishing a homogeneous base, then adapting each new agent type with lightweight modules—enables efficient and scalable deployment in diverse vehicle fleets.

## Method Summary
Faster-HEAL operates in two stages. Stage 1 trains a homogeneous base model (ego agent m1 with 64-channel LiDAR and homogeneous neighbors) using pyramid fusion across three scales and a detection loss (focal, smooth-L1, direction) plus foreground estimation losses. This establishes a unified feature space. Stage 2 introduces a new heterogeneous agent type (e.g., camera-based m2, LiDAR-based m3, or camera-based m4). The ego’s fusion and detection modules and the new agent’s encoder are frozen. A lightweight ConvNeXt-based aligner projects the agent’s features to match the ego’s expected dimensions, and a low-rank LIFT prompt (PARAFAC decomposition with rank R=8) further aligns the feature distribution. Only the aligner and LIFT are trained via the same detection loss. After training, each agent type stores only its {aligner, LIFT} pair, enabling modular integration without sharing raw data or full models.

## Key Results
- Detects objects with 2% higher AP (at IoU 0.5/0.7) than state-of-the-art on OPV2V-H.
- Reduces trainable parameters by 94% compared to collaborative fine-tuning baselines.
- Achieves 1.16× higher training throughput and 38.6% lower peak GPU memory usage.

## Why This Works (Mechanism)
Faster-HEAL succeeds by decoupling the stable, privacy-sensitive perception backbone from the adaptable alignment modules. The frozen unified feature space ensures that all agents’ representations are compatible, while the low-rank LIFT prompts efficiently capture domain shifts without overfitting. Intermediate feature sharing (aligned BEV features) rather than raw sensor data or full gradients preserves privacy and limits communication bandwidth. The two-stage design allows the base model to learn robust fusion first, then tailors the interface for each new agent type with minimal additional parameters. This modularity yields both performance gains and substantial computational savings.

## Architecture Onboarding
**Component Map** (plain text flow):
Heterogeneous agent: Sensor -> Encoder (frozen) -> ConvNeXt Aligner (trainable) -> PARAFAC LIFT (trainable) -> Aligned BEV features -> Ego
Ego: Aligned BEV features from all agents -> Pyramid Fusion (frozen) -> Detection Head (frozen) -> 3D bounding boxes

**Critical Path**: Raw sensor input is encoded to a feature map; the aligner reshapes channels/spatial dimensions; LIFT applies a low-rank transformation to match the unified feature distribution; aligned features are transmitted to the ego; the ego fuses multi-agent features pyramidally; the detection head outputs final boxes.

**Design Tradeoffs**:
- Frozen vs. trainable backbone: Freezing preserves privacy and speeds up training but limits adaptation to new sensor characteristics.
- Low-rank vs. full-rank prompts: Low-rank drastically cuts parameters (94% reduction) but may not capture complex domain shifts; rank R is a tunable hyperparameter.
- Intermediate features vs. raw data/gradients: Features offer privacy and bandwidth benefits but may still leak information if not properly aligned.

**Failure Signatures**:
- Dimension mismatch: Aligner output shape does not match expected (C, H, W) for fusion → runtime error.
- LIFT instability: Reconstruction error high or NaNs during training → try adjusting rank R or initialization.
- Poor convergence: Detection/foreground losses plateau early → increase learning rate or check that encoders are fully frozen.

**First Experiments**:
1. Train Stage 1 homogeneous base model for 25 epochs; verify that loss converges and AP on validation reaches baseline (≈92% AP@0.5 for m1 alone).
2. For a new agent type (e.g., m2), train Stage 2 aligner & LIFT for 25 epochs; monitor detection loss and compute AP; expect ~2% gain over SOTA.
3. Quantify feature alignment: compute mean cosine similarity between aligned features (after LIFT) and ego’s expected features on a held-out batch; target >0.8.

## Open Questions the Paper Calls Out
1. **Generalization to other datasets and configurations**: The paper only evaluates on OPV2V-H with limited sensor/model types. Extending to more diverse CP datasets (e.g., V2X-Sim, DAIR-V2X) and sensor modalities (radar, multimodal) remains future work.
2. **Intra-type variation robustness**: Using one LIFT per agent type may not handle minor architectural changes within a type (e.g., different backbone depths). Performance may degrade if new agents deviate from the training distribution.
3. **Privacy guarantees**: The claim of privacy via intermediate feature sharing lacks formal analysis. It is unknown whether shared BEV features could be reverse-engineered to reveal sensitive sensor data or model details.
4. **Resilience to real-world nuisances**: The method’s performance under concurrent challenges like communication latency, pose errors, and sensor noise is not evaluated. These factors often co-occur in practice and could interact negatively with feature alignment.

## Limitations
- **Implementation gaps**: Missing specifics for PARAFAC decomposition (e.g., initialization, optimizer integration) and ConvNeXt aligner architecture (layer counts, kernel sizes) hinder exact replication.
- **Environment variance**: Hardware/software details (CUDA, cuDNN, PyTorch versions, precision) affect throughput/memory measurements; reported numbers may not hold under different setups.
- **Evaluation subtlety**: Unclear whether SOTA baselines were re-implemented or original codes used; potential dataset split or augmentation differences could skew comparisons.

## Confidence
- Performance (AP ~2% gain): Medium – plausible but sensitive to implementation details and baseline setup.
- Method (LIFT with frozen models): Medium – conceptually sound, but PARAFAC integration and prompt initialization lack depth.
- Efficiency (94% fewer params, 1.16× throughput, 38.6% memory reduction): Low – numbers highly dependent on exact codebase, profiling, and hardware; likely optimistic without identical conditions.

## Next Checks
1. **PARAFAC stability test**: Train a standalone low-rank prompt on synthetic data to verify reconstruction error convergence and stable gradients; adjust rank R if necessary.
2. **Feature alignment quantification**: After Stage 2, compute mean cosine similarity between aligned heterogeneous features and ego’s unified features on a validation batch; aim for >0.8.
3. **SOTA baseline reimplementation**: Replicate a recent baseline (e.g., STAMP) in the same codebase with identical hardware and batch size to ensure fair comparison of AP, throughput, and memory.
