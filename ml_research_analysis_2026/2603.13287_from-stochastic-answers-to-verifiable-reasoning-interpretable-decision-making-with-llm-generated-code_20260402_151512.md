# From Stochastic Answers to Verifiable Reasoning: Interpretable Decision-Making with LLM-Generated Code

## Quick Facts
- **ArXiv ID:** 2603.13287
- **Source URL:** https://arxiv.org/abs/2603.13287
- **Reference count:** 17
- **Primary result:** Achieves 37.5% precision and F0.5 25.0% on VCBench founder screening, outperforming GPT-4o while reducing API costs by >99% and ensuring deterministic, debuggable predictions.

## Executive Summary
The paper tackles the tension between scalability, interpretability, and reproducibility in LLM-based high-stakes decisions. It proposes reframing LLMs as one-time code generators that produce executable Python predicates over structured data, eliminating costly, stochastic per-sample evaluation. These rules are validated automatically via statistical metrics and refined iteratively using cluster-based gap analysis. Applied to venture capital founder screening, the method yields higher precision than GPT-4o with full transparency and dramatic cost savings.

## Method Summary
The framework iteratively builds a rule-based classifier. First, an LLM generates 30 human-readable Python lambda predicates from a stratified sample of founder profiles. These rules are compiled and executed deterministically on the full dataset. Each rule is filtered by statistical validation: precision lift >1.0, binomial p-value <0.05, and coverage between 1%–50%. Validated rules activate a binary matrix used for K-means clustering; clusters with low or mixed success rates identify coverage gaps. Feedback summarizing these gaps guides the next LLM generation round. After iterations, a logistic regression on rule activations is threshold-tuned for F0.5.

## Key Results
- Precision 37.5% and F0.5 25.0% on VCBench, exceeding GPT-4o’s 30.0% precision (F0.5 25.7%).
- >99% reduction in API costs versus per-sample LLM evaluation.
- Fully deterministic, debuggable predictions with human-readable logic.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Reframing LLMs as one-time code generators decouples cost from dataset size and ensures deterministic, debuggable outputs.
- **Mechanism:** The LLM produces executable Python predicates over structured founder attributes. These run locally on all data via standard code execution, eliminating stochastic per-sample queries.
- **Core assumption:** Founder screening signals are expressible as deterministic logic over structured fields (education, jobs, exits).
- **Evidence anchors:** Abstract states “a single LLM call generates executable… logic that runs deterministically.” Section 3.3 describes the LLM as rule generator, not evaluator. Section 3.4 highlights reproducibility and debugging benefits.
- **Break condition:** If structured data cannot capture predictive signals (e.g., nuanced job descriptions requiring NLP), generated rules may have low validation pass rates.

### Mechanism 2
- **Claim:** Automated statistical validation filters low-quality rules without human annotation.
- **Mechanism:** Rules are evaluated on precision lift (vs. baseline), binomial significance (p<0.05), and coverage (1%–50%). Only passing rules proceed.
- **Core assumption:** These heuristics jointly identify predictive, reliable, non-generic rules.
- **Evidence anchors:** Section 3.5 defines thresholds. Table 7 shows mean lift for significant rules increased from 1.70× to 2.58× after validation and feedback.
- **Break condition:** With very small datasets or ultra-sparse successes (<1%), coverage thresholds may discard rare-pattern rules, or binomial approximations may fail.

### Mechanism 3
- **Claim:** Cluster-based gap analysis over rule activations identifies subpopulations where rules fail, enabling targeted refinement.
- **Mechanism:** Founders are clustered (K-means) on their rule activation patterns. Clusters are classified by success rate (high/low/mixed). Underperforming clusters feed back to the LLM for new rule generation.
- **Core assumption:** Similar activation patterns with divergent outcomes represent coherent subgroups with distinct success drivers.
- **Evidence anchors:** Section 3.6 details clustering and classification. Section 4.4 notes 68% of founders in mixed clusters and 57% of successes uncovered by top rules. Table 5 shows Iteration 2 rules with high lift but low coverage, targeting specialized gaps.
- **Break condition:** Noisy or small rule sets may yield clusters that don’t represent meaningful subgroups; elbow method for k-selection is heuristic.

## Foundational Learning
- **Binary classification metrics (Precision, Recall, F0.5):** Needed to optimize for high-confidence shortlists in rare-event contexts (9% base rate). F0.5 weights precision more heavily than recall, matching VC screening goals. *Quick check:* Why is F0.5 preferred over F1 here, and how would you tune a logistic regression threshold to maximize it?
- **Statistical significance testing (binomial test):** Needed to probabilistically filter rules where observed lift could arise by chance. The p<0.05 threshold controls false discoveries amid multiple rule generations. *Quick check:* For a rule covering 100 founders with 20 successes (baseline 9%), approximate the z-score for the one-sided binomial test. Is it significant at α=0.05?
- **Clustering for pattern discovery (K-means):** Needed to group founders by rule activations and diagnose where current rules fail to discriminate. This turns global validation into targeted subpopulation refinement. *Quick check:* What are the risks of using K-means on a high-dimensional binary matrix (rules × founders), and how does the elbow method help choose k?

## Architecture Onboarding
- **Component map:** Data Loader -> LLM Generator -> Deterministic Evaluator -> Statistical Validator -> Cluster Analyzer -> Feedback Generator -> Logistic Regression Classifier
- **Critical path:** Rule generation (LLM call) → Deterministic evaluation → Validation → Clustering → Feedback → Next generation. First iteration has no feedback; later iterations close the loop.
- **Design tradeoffs:**
  - Cost vs. coverage: 30 rules per iteration balance novelty and redundancy; fewer rules lower cost but risk missing patterns.
  - Precision vs. recall: Validation thresholds (lift>1.0) are permissive; logistic regression prioritizes strong rules. Cluster feedback targets recall gaps but may yield low-coverage specialized rules.
  - Complexity vs. interpretability: Rules are simple predicates over flat fields; cannot encode complex temporal sequences or text semantics.
- **Failure signatures:**
  - Low validation pass rate (<40% of generated rules significant) indicates poor LLM generation or data representation issues.
  - High multicollinearity in rule matrix (many rules covering similar founders) may degrade classifier stability despite coverage max (50%).
  - Cluster silhouette scores near zero suggest rule activations don’t form meaningful subgroups—gap analysis unreliable.
- **First experiments:**
  1. Sanity-check deterministic evaluation: Manually compute lift for a known rule (e.g., `prior_exit`) on a 100-founder sample, compare to pipeline output.
  2. Validate statistical thresholds: Generate 1,000 dummy random rules; confirm <5% pass p<0.05 under null.
  3. Test clustering stability: Run K-means on Iteration 1 rule activations with 50 random seeds; check if gap clusters (mixed/low-success) persist via variation of information.

## Open Questions the Paper Calls Out
- **Reinforcement learning from verifiable rewards:** Can fine-tuning LLMs using precision lift, significance, etc., as rewards improve rule quality and reduce iterations compared to prompt-only iteration? (Section 5.4)
- **Cross-domain generalization:** Does the framework generalize to other high-stakes tabular tasks with different schemas and rare-event rates (e.g., medical diagnosis, loan default)? (Section 5.4)
- **Extending rule expressiveness:** Can rules handle unstructured/semi-structured data (e.g., job descriptions) without sacrificing determinism and interpretability? (Section 5.3)
- **Automated gap detection:** How does the cluster-based heuristic compare to theoretically grounded methods for identifying rule coverage gaps and optimizing diversity? (Section 5.3)

## Limitations
- Dataset access: VCBench is cited but not publicly released, blocking direct replication.
- LLM generation specifics: Exact prompt templates, GPT-5.2 parameters, and stratified sampling method are under-specified.
- Generalizability: Evaluation is confined to one domain (VC screening); performance on other tasks is unknown.
- Representation limits: Assumes success signals are expressible as deterministic logic over flat structured fields; complex temporal/textual cues may be lost.

## Confidence
- **High:** Cost reduction & deterministic execution mechanism (clearly described, mathematically sound).
- **Medium:** Statistical validation effectiveness (thresholds specified, but sensitivity to base-rate shifts not explored).
- **Low:** Cluster-based gap analysis for iterative refinement (novel heuristic; stability and actionability depend on unstated clustering parameters and rule diversity).
