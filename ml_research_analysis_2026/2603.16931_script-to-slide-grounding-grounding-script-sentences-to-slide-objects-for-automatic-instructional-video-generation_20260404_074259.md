# Script-to-Slide Grounding: Grounding Script Sentences to Slide Objects for Automatic Instructional Video Generation

## Quick Facts
- **arXiv ID:** 2603.16931
- **Source URL:** https://arxiv.org/abs/2603.16931
- **Reference Count:** 12
- **Primary Result:** Achieved a micro-averaged F1-score of 0.924 on a test set of 19 text-only slides and 94 script sentences using a zero-shot LLM approach.

## Executive Summary
This paper introduces Script-to-Slide Grounding (S2SG) to automate the addition of visual effects in slide-based instructional videos by automatically linking narration script sentences to corresponding slide objects. As an initial solution for slides containing only text, the proposed Text-S2SG method uses a large language model (LLM) with hierarchical and contextual prompts. The approach processes slide text by decomposing the non-semantic DOM tree into a logical hierarchy based on indentation, then grounds script sentences to these structured text elements. The system achieved strong performance (F1=0.924) and demonstrated robustness to the presence or absence of stylistic and hierarchical metadata, indicating its reliance on deep semantic matching rather than superficial layout cues.

## Method Summary
The Text-S2SG system follows a three-module pipeline. First, a **Data Processing Module** extracts text from a `.pptx` file using `python-pptx`, assigns unique `shape_ID`s, splits multi-sentence text objects by newlines, and infers a parent-child hierarchy from indentation levels to create a logical `ContentList`. Second, an **LLM Module** (Gemini 2.5 Flash, temperature=0) takes this hierarchical slide data and the script sentences, following an instruction prompt to output, for each sentence, a JSON list of corresponding `shape_ID`s. Third, a **Video Generation Module** uses the grounding results to render visual effects (e.g., pointers, highlights) on slide images by looking up `shape_ID` positions and concatenating clips. The problem is confined to a single slide at a time, and no model training is performed.

## Key Results
- Micro-averaged F1-score of **0.924** on a test set of 19 text-only slides with 94 script sentences.
- Performance was robust across four data format conditions (with/without hierarchical metadata, with/without stylistic metadata), showing no substantial differences.
- The method successfully handles script sentences that paraphrase or elaborate on concise slide text without relying on visual layout cues like coordinates or font size.

## Why This Works (Mechanism)

### Hierarchical Decomposition Resolves DOM Limitations
- **Claim:** Parsing the slide's XML DOM tree into a hierarchy based on indentation resolves its lack of semantic structure and problematic object granularity.
- **Mechanism:** The system splits multi-sentence text shapes by newline and infers parent-child relationships from indentation levels, creating a logically structured `ContentList` instead of a flat, order-dependent XML dump.
- **Evidence:** [section II-B] identifies the DOM's core problems; [section IV-A] describes the hierarchy-building solution; neighbor literature supports hierarchical slide analysis.
- **Break condition:** Inconsistent or absent indentation to denote grouping would produce erroneous hierarchies.

### LLM Relies on Semantic Content, Not Visual Layout
- **Claim:** The LLM performs grounding primarily through deep semantic matching between script and slide text, not by using coordinates or font size.
- **Mechanism:** Ablation study shows nearly identical performance whether hierarchical or stylistic metadata is provided, indicating the model uses textual meaning.
- **Evidence:** [abstract] and [section V-B] report robustness across metadata conditions; [section VI] notes that shuffling script sentences had no effect, confirming content-based reasoning.
- **Break condition:** Script sentences with heavy deictic references ("this", "it") without concrete lexical overlap with slide text would fail without additional context.

### Per-Slide Context Confinement Simplifies the Task
- **Claim:** Processing each slide independently eliminates cross-slide dependencies, which are rare in typical presentations.
- **Mechanism:** The LLM is called on a per-slide basis, confining the correspondence search to objects on that single slide.
- **Evidence:** [section III-A] defines the confined setting; [section IV-B] describes per-slide processing; [section VI] suggests the approach may handle non-linear structures in principle.
- **Break condition:** Script sentences referring to objects on a different slide (e.g., "as shown previously") would be grounded incorrectly.

## Foundational Learning
- **Concept: DOM Tree & Slide Object Model**
  - **Why needed:** The slide's XML export is a non-semantic DOM tree; understanding this explains why preprocessing (hierarchical decomposition) is necessary before any meaningful reasoning.
  - **Quick check:** *Why can't we simply use the XML node order from the slide file as the reading order for grounding?*
- **Concept: Grounding as a Correspondence Matrix Estimation**
  - **Why needed:** Formalizing S2SG as estimating a binary matrix `M` (script sentence `s_i` vs. slide object `v_j`) clarifies the output goal and distinguishes it from generation/captioning tasks.
  - **Quick check:** *In matrix `M`, what would a row of all zeros represent, and why is that a valid output?*
- **Concept: Phased Approach for Complex Multimodal Problems**
  - **Why needed:** The authors propose solving text-only S2SG first to create a high-confidence foundation before tackling harder visual grounding (figures/tables), reducing overall complexity.
  - **Quick check:** *What is the primary risk of attempting the full multimodal S2SG problem in one step with a VLM?*

## Architecture Onboarding
- **Component map:** Data Processing Module (extract text, assign shape_ID, build hierarchy) → LLM Module (prompt with hierarchical data + script, output JSON mapping) → Video Generation Module (lookup positions, render effects, concatenate clips).
- **Critical path:** `.pptx` file → Data Processing (hierarchy build) → LLM (grounding) → Video Gen (effect rendering) → Final video. Hierarchy construction is a key enabling step before the LLM call.
- **Design tradeoffs:** Text-only vs. multimodal (sacrifices figures/tables for high accuracy); per-slide vs. presentation-context (fast but fails on cross-slide references); rule-based hierarchy (deterministic, fast) vs. learned layout understanding (more flexible but complex).
- **Failure signatures:** Hierarchy error (nonsensical parent-child links) → diagnosis: check indentation parsing; Semantic mismatch (selects conceptually wrong object) → diagnosis: review prompt clarity, check pronoun use; Empty/over-assignment → diagnosis: prompt needs better rules or examples.
- **First 3 experiments:** 1. Run baseline Text-S2SG with only raw text lists (no hierarchy/style) to establish performance ceiling. 2. Conduct metadata ablation study (4 conditions) to confirm "semantics-only" finding on a new dataset. 3. Manually audit automatically built `ContentList` hierarchies to measure parent-child assignment error rate.

## Limitations
- **Generalizability:** Evaluation on only 19 slides/94 sentences limits confidence in broader performance; dataset diversity is unknown.
- **Scope:** Method is limited to text objects; figures, tables, and charts are not supported, requiring a future phased multimodal extension.
- **Break Conditions:** Per-slide confinement fails for cross-slide references; indentation-based hierarchy fails on slides with complex, manually placed text boxes; deictic references without lexical overlap are problematic.
- **Implementation Gaps:** Exact "grounding rules" in the prompt and precise indent-level derivation algorithm are underspecified, blocking exact replication.

## Confidence
- **Hierarchical Decomposition Mechanism:** High (clearly defined, logically sound, supported by literature).
- **Semantic-Only Grounding Mechanism:** Medium (ablation study strongly supports, but subtle biases from omitted metadata cannot be fully ruled out).
- **Reported Performance (F1=0.924):** Medium (well-documented on a narrow test set; replicability on larger, diverse datasets is uncertain).

## Next Checks
1.  **Cross-Slide Reference Test:** Measure performance drop on script sentences that explicitly refer to objects on previous/next slides when processed with per-slide confinement.
2.  **Hierarchy Error Quantification:** Audit `ContentList` hierarchies on diverse `.pptx` files to measure error rates in parent-child assignment and correlate with grounding failures.
3.  **Pronoun/Anaphora Stress Test:** Evaluate on a controlled set with heavy deictic/anaphoric references to assess if the LLM can resolve them using only the provided slide hierarchy.
