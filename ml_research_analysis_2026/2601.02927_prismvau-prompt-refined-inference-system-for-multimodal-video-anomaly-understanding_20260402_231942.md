# PrismVAU: Prompt-Refined Inference System for Multimodal Video Anomaly Understanding

## Quick Facts
- **arXiv ID:** 2601.02927
- **Source URL:** https://arxiv.org/abs/2601.02927
- **Reference Count:** 40
- **Primary Result:** Achieves ROC AUC 87.82% on UCF-Crime and AP 78.68% on XD-Violence without instruction tuning or frame annotations; inference at 241 FPS.

## Executive Summary
Video Anomaly Understanding (VAU) extends traditional video anomaly detection by providing explanatory insights for detected anomalies. Existing VAU methods rely on fine-tuned multi-modal large language models (MLLMs), external modules, or dense frame processing, leading to high computational cost and inference overhead. This paper introduces PrismVAU, a prompt-refined inference system that achieves fine-tuned performance without any weight updates, using only a single off-the-shelf MLLM (VideoLLaMA-3).

PrismVAU operates in two stages. First, it computes coarse anomaly scores by comparing video frame embeddings to optimized textual anchors ("normal"/"abnormal") derived via weakly supervised Automatic Prompt Engineering (APE) that uses only video-level labels. Second, the MLLM processes video segments with a prompt augmented by the coarse scores as priors, producing step-like anomaly curves and natural language explanations. The two outputs are fused using Gaussian smoothing and Fourier upsampling. On UCF-Crime and XD-Violence, PrismVAU matches or surpasses state-of-the-art fine-tuned VAU methods. Notably, it runs at 241 FPS (at 1 FPS input) and generates explanations with moderate semantic similarity to human references.

## Method Summary
PrismVAU is a two-stage pipeline that leverages a single pre-trained MLLM (VideoLLaMA-3) without any fine-tuning. The coarse stage encodes video frames and two optimized text prompts ("normal", "abnormal") into a shared embedding space and produces per-frame anomaly probabilities via a softmax over cosine similarities. The text prompts are automatically optimized through an APE loop: the MLLM generates candidate prompts and selects those that maximize video-level AUC on the training set. The refinement stage feeds each video segment (≤30 s) to the same MLLM with a system prompt optimized by APE, along with a user prompt that includes a JSON summary of coarse predictions (overall video label, segment score, temporal region, frame statistics). The MLLM is instructed to reason step-by-step and output a sparse temporal curve (start/end times, score) plus a textual explanation. Finally, the coarse and MLLM curves are smoothed with different Gaussian kernels, averaged, and upsampled to the original frame rate via a Fourier method. The approach requires no frame-level annotations, no external detectors, and no gradient updates.

## Key Results
- UCF-Crime: ROC-AUC 87.82%, F1 41.52%
- XD-Violence: AP 78.68%, F1 70.23%
- Inference speed: 241 FPS (input at 1 FPS)
- Explanation quality: 0.56 semantic similarity (cosine) to HIVA U-70k references

## Why This Works (Mechanism)

**Mechanism 1: Coarse anomaly scores via optimized textual anchors.**  
Coarse frame-level anomaly scores are computed as a softmax over cosine similarities between frame embeddings and optimized text anchors ("normal"/"abnormal"). The anchors are automatically refined via weakly supervised APE using only video-level labels: the MLLM generates and scores candidates based on video-level AUC. This yields dataset-aligned textual representations that discriminate normal from abnormal video. The core assumption is that the MLLM's vision-text alignment allows optimizing text to improve frame separability. Evidence includes the ablation in Table 2 showing a jump from near-random (41% AUC) to 70%+ when using optimized anchors. If the MLLM's alignment is poor for a domain, anchor optimization fails (low training AUC), and the coarse module breaks.

**Mechanism 2: MLLM refinement with coarse priors.**  
The MLLM processes each video segment with a prompt that includes a JSON summary of coarse predictions (e.g., segment score, temporal region). This conditioning steers the MLLM's temporal reasoning to produce a step-like anomaly curve (start/end, score) and a textual explanation. The core assumption is that VideoLLaMA-3 possesses inherent capabilities for video understanding and instruction following, which can be tapped without weight updates. Ablation in Table 3 shows progressive improvement as more coarse features are injected, confirming the value of explicit priors. The MLLM's global context corrects the noisy per-frame coarse signal, yielding higher precision and interpretable outputs. Failure can occur if coarse priors are highly misleading or if the MLLM cannot handle long sequences.

**Mechanism 3: Fusion of complementary signals.**  
The coarse curve (smooth, high ROC AUC) and the MLLM curve (precise boundaries, high F1) are combined by applying different Gaussian smoothings (σ=2 for coarse, σ=4 for MLLM) and averaging. Fourier upsampling then resamples the 1 FPS signal to the original video frame rate without interpolation lag. The two modules exhibit low error correlation (r=0.28), indicating complementary error patterns. Simple averaging after appropriate smoothing effectively merges their strengths. If the modules' errors become correlated, or if smoothing parameters are mis-set (too small or too large), fusion performance degrades.

## Foundational Learning
- **Weakly Supervised Automatic Prompt Engineering (APE)**  
  *Why needed:* PrismVAU must optimize textual anchors and MLLM prompts using only video-level labels (no frame annotations). APE uses the MLLM itself as an optimizer to iteratively generate and evaluate prompt candidates based on video-level AUC, eliminating manual prompt design and aligning prompts with dataset-specific anomaly semantics.  
  *Quick check:* How does the APE loop prevent overfitting to the training set while searching for generalizable prompts? (The paper uses the training set for optimization but reports test results; potential overfitting risk is not explicitly mitigated by a held-out validation.)

- **Contrastive Vision-Language Embedding Alignment (CLIP-style)**  
  *Why needed:* The coarse scoring module relies on a shared embedding space where visual frames and text anchors are comparable via cosine similarity. This requires pre-trained alignment between the MLLM's vision and text encoders, inherited from models like CLIP.  
  *Quick check:* Why use a softmax over similarity scores (Eq. 1) instead of a simple threshold on (s_abn - s_norm)? (Answer: The softmax with temperature τ provides calibrated 0-1 probabilities suitable for aggregation and thresholding.)

- **MLLM as a Zero/Few-Shot Reasoner for Temporal Localization**  
  *Why needed:* The refinement module requires the MLLM to output structured temporal data (start/end times) and a score from video input. This hinges on the MLLM's pre-trained capacity for temporal understanding and instruction following, which is activated via optimized prompts without weight updates.  
  *Quick check:* What inherent capability of VideoLLaMA-3 makes it suitable for this task beyond static image captioning? (Answer: Its design for long-video understanding and temporal reasoning, including a token pruning mechanism for efficiency on surveillance footage.)

## Architecture Onboarding
- **Component Map:**  
  Input Preprocessor → Coarse Scorer → MLLM Refiner → Signal Fusion → Output  
  (APE Optimizer runs offline to generate optimized prompts for anchors and MLLM.)

- **Critical Path:**  
  1. Video is sampled into non-overlapping segments (≤30 s) at 1 FPS.  
  2. Coarse Scorer encodes frames and anchor texts, computes per-frame anomaly scores via Eq 1.  
  3. For each segment, the coarse curve is summarized into a JSON (video label, segment score, temporal region, frame stats).  
  4. MLLM Refiner processes the segment video + JSON + optimized system/user prompts, producing a sparse temporal curve (start/end, score) and a textual explanation.  
  5. Signal Fusion smooths the coarse (σ=2) and MLLM (σ=4) curves, averages them, and applies Fourier upsampling to match the original frame rate.  
  6. Final anomaly curve and explanation are returned.

- **Design Tradeoffs:**  
  - *Efficiency vs Precision:* Coarse module is encoder-only and fast but temporally imprecise; MLLM is slower but captures context. Fusion balances speed and accuracy.  
  - *Generalization vs Optimization:* APE optimizes prompts on the training distribution; prompts may overfit. Reusing MLLM prompts across datasets (UCF→XD) works but anchors need re-optimization.  
  - *Interpretability vs Performance:* MLLM natural language outputs enhance interpretability at the cost of step-function artifacts; fusion smooths these but can dilute explanation fidelity.

- **Failure Signatures:**  
  - Anchor optimization yields low video-level AUC → coarse scores uninformative.  
  - MLLM prompt failure → incorrect JSON format or empty outputs.  
  - High correlation between coarse and MLLM errors → limited fusion gains.  
  - Inappropriate Gaussian σ parameters → over-smoothing (missing short anomalies) or under-smoothing (noisy final curve).

- **First 3 Experiments:**  
  1. **Baseline anchor evaluation:** Run coarse scorer with initial unoptimized prompts on validation set; expect near-random performance (ROC AUC ~41%) confirming need for APE.  
  2. **MLLM prompt ablation:** Test MLLM with initial vs. optimized prompts (no coarse injection); measure improvement (e.g., UCF ROC AUC 58.72% → 70.78%) validating APE for MLLM prompts.  
  3. **Coarse injection test:** With optimized MLLM prompts, progressively add coarse prior features (L, S, T, F) and measure ROC AUC gain (70.78% → 76.97% in Table 3) confirming value of conditioning.

## Open Questions the Paper Calls Out
1. **Standardized benchmarks for explanation quality**  
   - *Question:* How can standardized benchmarks and metrics be established to evaluate the quality of textual explanations in video anomaly understanding?  
   - *Basis:* The authors explicitly state in the Summary and Future Work that current fine-tuned methods rely on custom datasets and ad hoc criteria, calling for standardized benchmarks and metrics.  
   - *Why unresolved:* Existing evaluations (e.g., HIVA-U-70k) use heterogeneous datasets and metrics (cosine similarity), making cross-method comparison difficult.  
   - *Resolving evidence:* A consensus benchmark with human-annotated textual explanations across diverse scenarios, along with a validated automatic metric adopted by the community.

2. **Generalization of PrismVAU to other MLLMs**  
   - *Question:* Does the two-stage pipeline maintain competitive performance with multimodal large language models other than VideoLLaMA-3?  
   - *Basis:* The paper claims model agnosticism but only evaluates VideoLLaMA-3 (Sec 4.2), chosen for efficiency and temporal reasoning.  
   - *Why unresolved:* It is unknown whether alternative MLLM architectures (different vision encoders, language backbones, token pruning) would produce comparable accuracy and speed.  
   - *Resolving evidence:* Re-implementation with other MLLMs (e.g., LLaVA, GPT-4V) and direct comparison of frame-level ROC-AUC/F1 on standard datasets.

3. **Dataset specificity of optimized textual anchors**  
   - *Question:* Can textual anchors optimized for one anomaly dataset transfer to another without re-optimization, or are they inherently dataset-specific?  
   - *Basis:* In Sec 4.4, new anchors are distilled for XD-Violence while MLLM prompts are reused from UCF-Crime, suggesting anchors may not generalize directly.  
   - *Why unresolved:* No explicit test of anchor transferability; APE may produce anchors overfitted to dataset-specific semantics (e.g., criminal vs. violent contexts).  
   - *Resolving evidence:* Evaluate anchors optimized on UCF-Crime on XD-Violence without re-optimization, measure performance drop, and analyze semantic differences between anchor sets.

## Limitations
- Generalization of APE optimization: weakly supervised prompt search may overfit to the training distribution without held-out validation.
- Comparison scope: only compared against fine-tuned VAU methods; zero-shot MLLM VAD baselines not evaluated, limiting claims about matching fine-tuned without tuning.
- Inference cost transparency: 241 FPS likely reflects coarse module only; end-to-end latency with MLLM refinement is not fully reported.

## Confidence
- Coarse Prior via Optimized Anchors: High
- MLLM Refinement with Coarse Priors: High
- APE Prompt Generalization: Medium
- Complementary Fusion Assumption: Medium
- Efficiency Advantage: Medium

## Next Checks
1. **Zero-Shot Comparative Benchmark:** Re-run PrismVAU using its APE-optimized prompts on the same splits as recent zero-shot MLLM VAD methods (e.g., "No Need For Real Anomaly") and compare ROC-AUC/F1.
2. **APE Validation Set Overfitting Test:** Split training data into train/validation folds, run APE on training fold, evaluate optimized anchors on held-out validation fold, measure degradation to quantify overfitting.
3. **End-to-End Latency Profiling:** Instrument the full pipeline (sampling, coarse scoring, MLLM inference for all segments, fusion, upsampling) on standard hardware (e.g., single V100), report mean FPS and memory usage for videos of varying lengths to verify the 241 FPS claim.
