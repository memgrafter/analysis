# Transformers are Bayesian Networks
## Quick Facts
- arXiv ID: 2603.17063
- Source URL: https://arxiv.org/abs/2603.17063
- Reference count: 23
- Primary result: Proves that any sigmoid transformer forward pass exactly implements one round of weighted loopy belief propagation on an implicit factor graph; exact posteriors uniquely determine BP-specific weights.

## Executive Summary
The paper addresses the fundamental question of why transformers are effective by establishing a rigorous link to Bayesian inference. It proves that a transformer with sigmoid activation performs exactly one round of weighted loopy belief propagation (BP) per forward pass on an implicit factor graph defined by its weights, and this holds for any weight configuration. Furthermore, the authors construct explicit weights that allow a transformer to implement exact BP on any pairwise factor graph, and they show that producing exact Bayesian posteriors uniquely forces the transformer's weights to match this BP pattern. Empirical experiments on synthetic Bayesian inference tasks confirm that gradient descent discovers these BP weights, achieving near-zero error (validation MAE 0.000752) and near-perfect convergence on loopy graphs (average KL < 0.0002). The theory also indicates that verifiable inference requires a finite concept space, which grounding provides, making hallucination structurally impossible on grounded trees.

## Method Summary
The empirical validation employs the 'bayes-learner' experiment, where transformers are trained to perform exact Bayesian inference on small synthetic factor graphs. Each graph consists of two variable nodes and one factor node, with factor table entries sampled uniformly. Graphs are encoded into a sequence of three 8-dimensional tokens: dimension 0 holds the node's belief (initialized 0.5), dimensions 1–4 store factor table entries (for factor nodes), dimension 5 indicates node type (0=variable, 1=factor), and dimensions 6–7 contain normalized node indices for routing. A transformer encoder (2 layers, 2 heads, d_model=32, ReLU activation) is trained to predict the exact posterior probabilities of the variable nodes, using mean squared error loss and Adam optimizer (learning rate 1e-3) for 50 epochs on 20,000 graphs. The model achieves a validation mean absolute error of approximately 0.000752, demonstrating successful learning of exact belief propagation. The reproduction notes detail a replication plan using the provided bayes-learner codebase or a manual implementation, and they include diagnostics such as inspecting attention patterns for sparse one-hot routing and checking FFN weights for BP-specific values (w0≈w1≈1, b≈0).

## Key Results
- Theoretically, the paper proves (via mechanized Lean 4) that every sigmoid transformer implements exactly one round of weighted loopy belief propagation per forward pass on an implicit factor graph; it also provides a constructive proof that transformers can implement exact BP on any pairwise factor graph, and a uniqueness theorem showing that exact posteriors force BP-specific weights.
- Empirically, gradient descent on the bayes-learner task discovers these BP weights, yielding near-exact posteriors (validation MAE 0.000752) and near-perfect convergence on loopy QBBN graphs (500 trials, average KL < 0.0002).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: A sigmoid transformer with any weights implements weighted loopy belief propagation (BP) on an implicit factor graph, with one forward pass equal to one BP round.
- **Mechanism**: Attention heads act as the BP gather step, routing neighbor beliefs into fixed "scratch slots" in the residual stream (dimensional indices 4 and 5 for the two parents). The sigmoid FFN then executes `σ(logit(m0) + logit(m1) + b)`, which is the BP update step combining independent evidence. The residual stream enforces simultaneity of the two parent beliefs before the FFN computes, satisfying BP's requirement that messages arrive from independent subtrees.
- **Core assumption**: The transformer uses sigmoid activation and strictly alternates attention and FFN layers with residual connections that allow both parent values to be present simultaneously in the same token’s representation.
- **Evidence anchors**:
  - [abstract] "every sigmoid transformer... implements weighted loopy belief propagation on its implicit factor graph. One layer is one round of BP."
  - [section] Section 6.2 defines the implicit factor graph; Theorem 6.1 is the formal Lean 4 proof.
  - [corpus] Jung et al. [9] derive a formal equivalence between softmax attention and BP on a latent graphical model, supporting the general link between attention and message passing. However, this paper's result is stronger: it holds for any sigmoid weights and uses an explicit factor graph.
- **Break condition**: If the sigmoid activation is replaced with a non-invertible activation like ReLU, the formal equivalence to BP breaks because the log-odds algebra no longer holds exactly. The empirical results (Section 10.4) show ReLU can approximate BP but does not preserve the exact internal correspondence.

### Mechanism 2
- **Claim**: Explicitly constructed transformer weights can implement exact BP on any declared pairwise factor graph, yielding provably correct marginals on tree-structured graphs after sufficient passes.
- **Mechanism**: Each node is encoded as a token with dedicated dimensions: one for current belief, four for its factor table entries (if it is a factor node), two for the neighbor indices (routing key), and one for node type. Two attention heads per layer use `projectDim` Q/K to match neighbor indices (ensuring each head attends to exactly one parent) and `crossProject` V to copy that parent's belief into a specific slot. The FFN with weights `w0 = w1 = 1, b = 0` computes `σ(logit(m0) + logit(m1))`, exactly the BP update. Binarization of k-ary factors via associativity of AND and additivity of log-odds allows any factor graph to be reduced to pairwise form without approximation.
- **Core assumption**: The factor graph is fully grounded (no universal quantification remains) and uses only pairwise factors; the transformer has at least two attention heads per layer and depth at least equal to the graph diameter for tree graphs.
- **Evidence anchors**:
  - [abstract] "a transformer with explicitly constructed weights implements one round of exact belief propagation per forward pass on any pairwise factor graph."
  - [section] Section 7.2 details the weight construction and token encoding; Theorem 7.1 is the formal proof; Corollary 7.4 gives the exactness on trees.
  - [corpus] Scarselli et al. [14] proved GNNs implement BP on explicit graphs, but require the graph structure to be hardwired into the adjacency matrix. This transformer construction uses self-attention and token features to encode topology, which is a different architectural instantiation.
- **Break condition**: If the factor graph contains cycles (loops), exactness is not guaranteed because BP on loopy graphs may not converge to the true marginals; the transformer then inherits BP's approximate behavior. The construction also assumes a grounded node for each proposition; ungrounded symbols break the routing alignment.

### Mechanism 3
- **Claim**: If a sigmoid transformer produces exact Bayesian posteriors on a grounded factor graph, its weights must necessarily be the BP-specific ones (`w0=w1=1, b=0` in FFN; `projectDim/crossProject` structure in attention).
- **Mechanism**: The sigmoid FFN computes a sigmoid of a linear combination of logits. Exact Bayesian posteriors require that the update be `updateBelief(m0,m1)`. Because sigmoid is injective, the linear combination inside must equal `logit(m0) + logit(m1)`, forcing `w0=w1=1, b=0`. Attention weights must implement perfect routing: each head must attend uniquely to one specific neighbor. This requires the Q·K dot product to peak uniquely at the correct neighbor token, which forces the `projectDim` structure (rank-1, single 1 at query=neighbor index). The V weights must copy that neighbor's belief into the correct scratch slot, forcing `crossProject`.
- **Core assumption**: The transformer is required to produce exact posteriors for all possible factor graph instantiations and all possible input beliefs; the factor graph is grounded and pairwise.
- **Evidence anchors**:
  - [abstract] "a sigmoid transformer that produces exact posteriors necessarily has BP weights. There is no other path through the sigmoid architecture to exact posteriors."
  - [section] Section 6.5 states Theorem 1.4; subsections FFNUniqueness.lean and AttentionUniqueness.lean provide the detailed proofs.
  - [corpus] No direct prior work establishes this uniqueness; the closest are mechanistic interpretability efforts (e.g., Olsson et al. [11] showing induction heads) that find specific circuits but not a uniqueness proof. The corpus is silent on this.
- **Break condition**: If the outputs are only approximately correct (e.g., due to finite training or ReLU activation), many weight configurations can achieve low error; uniqueness holds only for exact posteriors.

## Foundational Learning
- **Concept: Factor Graphs and Belief Propagation**
  - **Why needed here**: The paper's core claim identifies transformers as performing BP on a factor graph. Understanding variable nodes, factor nodes, message passing (gather/update), and the `updateBelief` function is essential to follow the mechanism.
  - **Quick check question**: What are the two steps of a single BP round on a pairwise factor graph, and what algebraic operation combines messages in the update step?

- **Concept: Log-Odds Algebra and Sigmoid**
  - **Why needed here**: The sigmoid FFN computes `σ(w0·logit(m0) + w1·logit(m1) + b)`. The isomorphism between probability and log-odds via `logit`/`σ` is why sigmoid is the correct activation for exact Bayesian updates. The paper roots this in Turing and Good's weight-of-evidence tradition.
  - **Quick check question**: Why is `updateBelief(m0, m1) = σ(logit(m0) + logit(m1))` the correct formula for combining two independent pieces of binary evidence?

- **Concept: Transformer Internals as Routing and Computation**
  - **Why needed here**: To map the architectural components (multi-head attention, FFN, residual stream) to BP steps (gather vs. update). The paper's construction assigns specific dimensional roles (scratch slots, routing keys) that must be understood.
  - **Quick check question**: In the BP transformer construction, what do dimensions 4 and 5 of the residual stream store, and which component writes to them?

## Architecture Onboarding
- **Component map**:
  - Token encoding (8 dimensions): dim 0 = current belief; dims 1–4 = factor table entries (if factor node); dim 5 = node type (0=variable, 1=factor); dim 6 = own index/(n–1); dim 7 = neighbor index/(n–1).
  - Attention (two heads): Head 0 uses `projectDim(1)` for Q/K and `crossProject(0,4)` for V — it queries for neighbor 0 and writes its belief to dim 4. Head 1 is symmetric for neighbor 1 and dim 5.
  - FFN: Takes dims 4 and 5 (the two parent beliefs), computes `σ(w0·logit(m0) + w1·logit(m1) + b)`, writes result to dim 0 (new belief).
  - Residual stream: Shared workspace that holds both parent beliefs simultaneously before FFN computation; enables the AND-gate behavior.

- **Critical path** (single layer, pairwise factor graph):
  1. Input tokens arrive with current beliefs and routing keys.
  2. Attention gather: Each token's two heads compute Q·K scores with all others. The softmax concentrates on the tokens whose neighbor index matches the query's own index. The V projection copies those neighbors' beliefs into dims 4 and 5.
  3. FFN update: Reads dims 4 and 5, computes new probability via sigmoid of their logit sum, writes to dim 0.
  4. Output token has updated belief in dim 0; other dimensions unchanged (or passed through residual).
  - Depth correlates with reasoning steps: for a tree, `L ≥ diameter` rounds yield exact marginals.

- **Design tradeoffs**:
  - **Depth vs. Breadth**: More complex factor graphs (deeper reasoning chains, higher arity) require more layers, not more heads per layer. Two heads suffice for pairwise factors; k-ary factors require `⌈log₂k⌉` extra layers due to binarization.
  - **Token dimensionality**: The construction uses 8 dimensions to separate belief, factor data, and routing keys. This is minimal for the proof; practical systems may merge roles.
  - **Exact vs. Loopy**: Exactness guaranteed only on trees. Loopy graphs may converge to approximate Bethe free energy minima; the transformer inherits this behavior.

- **Failure signatures** (debug checklist for a trained model):
  - **Attention misrouting**: Q/K matrices not rank-1 with a single peak in each row; or peaks not aligning with the intended neighbor index. Check attention patterns: should be sparse (one-hot per head) on grounded data.
  - **FFN incorrect combination**: Learned `w0, w1, b` far from `(1,1,0)`. Check via linear probe on FFN inputs/outputs: does `sigmoid(w0·logit(m0) + w1·logit(m1) + b)` match `updateBelief`? Deviations indicate non-BP weights.
  - **Grounding mismatch**: Token routing keys (dims 6–7) do not correspond to any node in the declared factor graph; unknown keys lead to undefined inference.
  - **Loopy divergence**: On graphs with short loops, BP may oscillate or fail to converge; monitor belief changes across passes.

- **First 3 experiments** (to validate the implementation):
  1. **Two-node factor graph**: Train a 2-layer, 2-head transformer from random initialization to match exact BP posteriors on a single-factor, two-variable graph. Expect val MAE < 0.001 (as in bayes-learner). Verify that the learned weights match the BP pattern (check `w0≈w1≈1, b≈0`; Q/K have `projectDim` pattern).
  2. **Attention pattern inspection**: On a small grounded factor graph, run a forward pass and visualize attention matrices for each head. Each head should attend to exactly one neighbor token (sparse pattern). The attended token index should match the neighbor index stored in the query token's dim 7.
  3. **Tree exactness test**: Build a tree-structured factor graph (e.g., a chain of 5 variable nodes connected by factors). Run the trained transformer for ≥ diameter passes. Compare final beliefs against brute-force exact marginals. Expect exact match (within numerical tolerance). Also test a loopy variant (e.g., add one edge to create a cycle); expect small but non-zero KL divergence, confirming loopy BP behavior.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: For a trained transformer that approximates Bayesian inference, what is the actual set of distinct routing keys (concepts) used in its attention mechanism, and how does this compare to the theoretical maximum of 2n² for pairwise factor graphs?
- Basis in paper: [inferred] The paper defines concepts via routing keys (node type, own index, neighbor index) and proves the routing class set size is 2n² for pairwise BP (Theorem 9.2, Section 9.3). However, this assumes perfect BP weights and explicit grounding. In a trained model without explicit grounding, the actual attention patterns may not perfectly align with these keys, and the concept space may be smaller or structured differently.
- Why unresolved: The formal result applies to the constructed BP transformer with explicit routing keys. For a trained model, attention patterns are learned and may not cleanly partition into discrete routing classes; continuous weight effects and training dynamics could blur or merge concepts. No experimental analysis extracts the actual routing classes from a trained model.
- What evidence would resolve it: Empirically analyze attention patterns in a transformer trained on BP tasks (e.g., from bayes-learner). Cluster tokens by their attention distributions to identify distinct routing behaviors. Compare the number of clusters to 2n² and to the graph size. If clusters correspond to theoretical routing keys, it validates the concept space; if not, revise the theory to account for learned approximations.

### Open Question 2
- Question: Do ReLU-activated transformers that achieve low error on Bayesian inference tasks internally approximate the log-odds algebra (e.g., maintain linearity in logit space), or does the ReLU non-linearity force fundamentally different internal computations despite compatible outputs?
- Basis in paper: [explicit] Section 10.4 states that sigmoid is required for the exact proof because it bijects with logit space, while ReLU only ensures non-negativity. The bayes-learner experiment uses a ReLU transformer and achieves val MAE 0.000752, but the internal states are not verified to satisfy BP quantities. The paper explicitly notes: "the internal representations do not necessarily correspond to named quantities in the BP proof."
- Why unresolved: The formal guarantee (transformer implements bp) holds only for sigmoid activations, where the FFN output is constrained to (0,1) and the computation is exactly σ(logit sum). ReLU outputs are unbounded and require external normalization. The experiment shows outputs match, but the internal trajectory (scratch slot values, logits) is unverified. It is unknown whether ReLU networks learn to simulate log-odds (e.g., by keeping activations positive and approximately linear) or rely on different mechanisms.
- What evidence would resolve it: Train a ReLU transformer on BP tasks, then probe internal layers: (1) Compute logits of FFN inputs (dims 4,5) and check if their sum predicts the output logit linearly. (2) Test if internal representations remain in the positive regime (since log-odds of probabilities in (0,1) can be any real, but ReLU floors at 0—this could distort). (3) Compare the learned weight matrices to the BP construction; if they approximate w0 ≈ w1 ≈ 1 and b ≈ 0 in a transformed space, it suggests approximate log-odds. If not, identify the actual computational invariant.

### Open Question 3
- Question: For loopy factor graphs, what structural properties (e.g., loop density, factor potential magnitudes) guarantee that belief propagation—as implemented by a transformer with BP weights—converges to a fixed point, and does that fixed point approximate the true marginals with bounded error?
- Basis in paper: [inferred] Section 10.5 reports empirical convergence on five loopy QBBN-structured graphs, with average KL < 0.0002. However, the paper notes: "BP itself is not guaranteed to converge or be exact" on loopy graphs, and "the theoretical gap between trees and loopy graphs is smaller in practice than in the worst case." No convergence theorem is provided for the implicit factor graphs defined by transformer weights.
- Why unresolved: Classical BP convergence theory depends on graph structure (e.g., how loops interact) and factor potentials (e.g., strong potentials aid convergence). The transformer defines an implicit loopy graph via attention patterns, which may have different properties than hand-designed loopy graphs. The empirical results are limited to specific small graphs; the conditions under which convergence holds in general—especially for large, dense, or high-potential loops—are unknown.
- What evidence would resolve it: Conduct a systematic study varying graph parameters (number of variables, loop count, factor potential ranges). For each, run iterative BP (simulated by multiple transformer forward passes) and measure convergence rate and fixed-point accuracy against exact marginals (via brute force for small graphs). Identify thresholds (e.g., maximum loop length, potential magnitude) that ensure convergence and bound the Bethe approximation error. Formalize these as sufficient conditions for transformer-based loopy BP.

### Open Question 4
- Question: For a transformer trained to approximate Bayesian inference on factor graphs, are the learned weights necessarily close to the BP weight construction (projectDim/crossProject for attention, w0=w1=1,b=0 for FFN), or can distinct weight configurations yield similar performance via alternative computational mechanisms?
- Basis in paper: [inferred] The uniqueness theorem (Theorem 1.4/6.2) shows that exact posteriors force BP weights. But in practice, transformers are trained on data to approximate posteriors, not achieve exactness. The bayes-learner experiment finds weights that yield near-exact posteriors (MAE 0.000752), but it is not shown that these weights match the BP construction in structure; only the outputs are measured. The paper states: "gradient descent finds BP weights from scratch," but this is an empirical observation, not a necessity proof.
- Why unresolved: The training objective (MSE on posteriors) may have multiple optima. The BP weights are one solution, but non-BP weights could produce similar outputs via different internal computations (e.g., canceling errors). Without probing the internal alignment to BP quantities (scratch slots, logit sums), we cannot confirm that the mechanism is BP. The empirical result is consistent with BP but does not prove it.
- What evidence would resolve it: After training on BP tasks, extract the learned Q/K and V matrices and FFN weights. Test for the projectDim/crossProject pattern: Q/K should show rank-1, single-dimension peaks; V should show off-diagonal rank-1 structure. Test FFN: compute effective w0,w1 from weight magnitudes and verify w0≈w1 and b≈0. If these hold, it supports that gradient descent finds BP weights. If not, analyze how alternative weights produce correct outputs (e.g., via distributed representations or cancellation).

## Limitations
- **Sigmoid dependency**: Exact BP requires sigmoid activation; common activations like ReLU or GELU break the algebraic equivalence.
- **Grounding requirement**: The implicit factor graph relies on explicit node indices in the residual stream; natural language data lacks such grounding, limiting applicability.
- **Scalability and loops**: Exact marginals are guaranteed only on trees; loopy graphs yield approximate BP with no convergence guarantees. Experiments are limited to tiny graphs (≤3 nodes), so scalability remains unproven.

## Confidence
- Formal theorems (any sigmoid transformer = BP, explicit construction, uniqueness): **High** (mechanized Lean 4 proofs).
- Empirical claim that SGD discovers BP weights: **Medium** (validated only on tiny synthetic graphs).
- Extension to standard transformers (softmax, GELU): **Low** (exact equivalence fails; only approximation observed).

## Next Checks
1. Activation ablation: Train transformers with sigmoid, ReLU, and GELU activations on the two-variable factor graph. Expect sigmoid to match BP template (FFN weights near (1,1,0), attention one-hot). ReLU/GELU should deviate.
2. Tree depth scalability: Test trees with diameters 5, 10, 15 using a 2-head transformer with depth ≥ diameter. Expect MAE < 1e-4, confirming exactness independent of depth.
3. Generalization to unseen structures: Train on random trees (5–10 nodes), test on larger trees (15–20 nodes). Success criterion: MAE < 0.001, indicating learning a general BP algorithm.
