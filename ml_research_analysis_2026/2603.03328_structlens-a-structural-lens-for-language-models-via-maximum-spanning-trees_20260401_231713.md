# StructLens: A Structural Lens for Language Models via Maximum Spanning Trees

## Quick Facts
- **arXiv ID**: 2603.03328  
- **Source URL**: https://arxiv.org/abs/2603.03328  
- **Reference count**: 40  
- **Primary result**: TreeBI pruning achieves 66.2% MMLU accuracy on Llama3.1 8B at 12.5% pruning ratio, significantly outperforming cosine-based methods (p < 0.05).

## Executive Summary
Existing analyses of language models focus on local token interactions (e.g., attention patterns), overlooking global inter-layer relationships. StructLens addresses this gap by introducing a framework that constructs Maximum Spanning Trees (MSTs) from residual stream representations, capturing holistic inter-token structures within each layer. Structure-aware similarity metrics—Tree Edit Distance and Edge Edit Distance—are then used to quantify similarity between layers. Applied to Llama3.1 8B and Qwen2.5 7B, StructLens reveals distinct “island” clustering in inter-layer similarity heatmaps, differing from conventional cosine similarity. When used for layer pruning via Block Influence scoring, the approach improves downstream performance (e.g., MMLU) and provides insights into structural evolution during pre‑training, such as increasing contiguous token clustering in middle layers of later checkpoints.

## Method Summary
For a given text input, the forward pass yields residual stream activations \(H^{(\ell)} \in \mathbb{R}^{n \times d}\) for each layer \(\ell\). For every layer, a directed MST is built: tokens are nodes; for each ordered pair \(i < j\), an edge \(i \rightarrow j\) is added with weight \(1 / (1 + \|h_i - h_j\|)\). The Chu‑Liu/Edmonds algorithm (Tarjan implementation) selects a single-root spanning tree \(T_\ell\) with maximum total weight. Inter‑layer similarity is then computed via structure‑aware metrics: Edge Edit Distance is the negative symmetric difference of edge sets, while Tree Edit Distance accounts for node re‑attachments. For pruning, Block Influence (BI) for layer \(\ell\) is defined as \(1 - \text{similarity}(T_\ell, T_{\ell-1})\), normalized per sample using theoretical bounds (e.g., \(n-1\) for Edge‑Edit). BI scores are averaged over a calibration set; layers with the smallest BI are removed.

## Key Results
- **Island clustering**: Edge‑Edit similarity heatmaps show clear “island” patterns, contrasting with the smooth gradients of cosine similarity, indicating discrete functional phases across layers.
- **Improved pruning**: TreeBI yields 66.2% MMLU accuracy on Llama3.1 8B at 12.5% pruning, statistically significant over cosine‑based methods (p < 0.05).
- **Pre‑training dynamics**: Later checkpoints exhibit higher contiguous token clustering (subtree ratio) in middle layers, suggesting evolving position‑aware chunking during training.

## Why This Works (Mechanism)
The MST aggregates the strongest pairwise token affinities (small distances yield large weights) into a single-rooted hierarchy, analogous to a dependency parse. This global structure reflects how information flows and aggregates across tokens within a layer, making it more informative than pointwise cosine similarity. Edge‑Edit compares these hierarchical graphs directly, sensitive to changes in parent‑child relationships that may indicate a shift in computational focus. The Block Influence metric assumes that layers whose MSTs are highly similar to the previous one contribute redundancy; removing such layers minimally disrupts the representational progression, thus preserving performance while reducing size.

## Foundational Learning
- **Residual Stream**: The sequence of token representations after each transformer layer; needed because StructLens operates on \(H^{(\ell)}\).  
  *Quick check*: Can you extract \(H^{(\ell)}\) from a HuggingFace model by setting `output_hidden_states=True`?  
- **Maximum Spanning Tree (MST)**: A directed tree connecting all nodes with maximum total edge weight; captures the strongest connections.  
  *Why needed*: Provides a global, hierarchical view of token relationships per layer.  
  *Quick check*: Given a weighted directed graph, does the Chu‑Liu/Edmonds algorithm produce a single‑root MST?  
- **Dependency Parsing Analogy**: Interpreting the MST as a dependency structure helps relate token influences to linguistic parse trees.  
  *Why needed*: Offers intuition for the hierarchical organization of representations.  
  *Quick check*: How would you interpret an edge \(i \rightarrow j\) in terms of information flow?  
- **Tree/Edge Edit Distance**: Measures structural dissimilarity between trees; Edge‑Edit simplifies to set difference.  
  *Why needed*: Quantifies how much layer structures change.  
  *Quick check*: Compute Edge‑Edit between two small trees; ensure normalization to \([0,1]\).  
- **Block Influence (BI)**: A redundancy score derived from inter‑layer similarity; used for pruning.  
  *Why needed*: Identifies layers that are least critical to model function.  
  *Quick check*: Given similarity scores for adjacent layers, how is BI computed?  
- **Layer Pruning**: Removing entire transformer layers to compress models.  
  *Why needed*: Validates the practical utility of StructLens metrics.  
  *Quick check*: What are the trade‑offs when pruning based on BI vs. random removal?

## Architecture Onboarding
**Component map**: Tokenization → Residual Stream Extraction → MST Construction → Similarity Computation (Edge‑Edit/Tree‑Edit) → Block Influence Scoring → Pruning Decision → Evaluation.

**Critical path**: (1) Extract residual streams for all layers; (2) Build an MST per layer; (3) Compute pairwise similarity; (4) Average BI across calibration samples; (5) Rank and prune layers. Any failure in these steps breaks the pipeline.

**Design tradeoffs**:  
- Forward constraint (\(i < j\)) ensures acyclicity but introduces directionality; undirected MSTs would lose temporal order.  
- Edge weight \(1/(1+\|h_i-h_j\|)\) maps distances to \((0,1]\); alternative transforms could affect sparsity.  
- Normalization of BI: Edge‑Edit has a simple bound \(n-1\); Tree‑Edit’s bound depends on tree shape and edit costs, complicating comparisons.  
- Calibration data: Using only 10 Wikipedia passages may not represent diverse inputs, risking biased BI estimates.  
- Complexity \(O(n^2)\) per layer limits scalability to very long sequences.

**Failure signatures**:  
- MST output has cycles or fewer than \(n-1\) edges → bug in MST algorithm.  
- BI scores are nearly constant across layers → similarity metric fails to distinguish representations.  
- Pruning degrades accuracy drastically → BI does not correlate with redundancy for this model/task.  
- Heatmaps lack island structure → possible root token mismatch or incorrect normalization.

**First experiments**:  
1. Validate MST builder on random vectors: confirm single‑root tree with \(n-1\) edges and no cycles.  
2. Compute Edge‑Edit similarity between consecutive layers for a few samples; check that values are in \([0,1]\) and vary meaningfully.  
3. Apply TreeBI pruning to a small model (e.g., GPT‑2 small) on a toy dataset (e.g., a few sentences); verify that pruning improves or maintains performance and that removed layers align with expectations.

## Open Questions the Paper Calls Out
1. **Metric variability**: Why do structure‑aware pruning metrics (TreeBI, EdgeBI) perform inconsistently across models and tasks, whereas cosine‑based methods are more uniform? The paper notes this limitation but does not investigate causes (e.g., architectural nuances, task‑specific representations, MST sensitivity).  
2. **Island causality**: Do the “island” clusters in Edge‑Edit similarity directly correspond to functional phases in model computation, or are they merely epiphenomena of representation similarity? Current alignment with logit lens transitions is correlational.  
3. **Position‑aware chunking**: What mechanisms cause contiguous token clustering to peak in middle layers later in pre‑training? The paper observes the pattern but does not link it to representational changes, training dynamics, or linguistic processing.

## Limitations
- Root token for the single‑root forward MST is unspecified (likely BOS, but not confirmed).  
- Normalization for TreeBI/EdgeBI beyond “theoretical bounds” is ambiguous, especially for Tree Edit Distance.  
- Calibration data details (token count, truncation) for pruning are missing; may affect BI scores and pruning order.  
- Evaluation is limited to two autoregressive models; no evidence for encoder‑decoder or other architectures.

## Confidence
- MST captures holistic token structure: **High** (equations and deterministic construction).  
- Island clustering in inter‑layer similarity maps: **Medium** (supported by clustering metrics but pattern depends on root/normalization).  
- Structure‑aware pruning improves performance: **Medium** (statistically significant results but replication hinges on calibration and BI computation).  
- Structural evolution during pre‑training: **Low** (limited checkpoint analysis; may not generalize).

## Next Checks
1. **Root sensitivity test**: Vary the root token (BOS, first content, last) on a fixed sample; recompute Edge‑Edit heatmaps and BI rankings to assess impact on island patterns and pruning order.  
2. **Normalization audit**: Derive the exact maximum Tree Edit Distance for given tree sizes and unit costs; recalc BI and compare pruning rankings to the paper’s; verify whether results hold under precise normalization.  
3. **Cross‑architecture evaluation**: Apply StructLens to an encoder‑decoder model (e.g., T5) and a non‑transformer (e.g., LSTM); check for island patterns and test TreeBI pruning to probe generality.
