# Overview of the TREC 2025 Tip-of-the-Tongue track

## Quick Facts
- **arXiv ID:** 2601.20671
- **Source URL:** https://arxiv.org/abs/2601.20671
- **Reference count:** 19
- **Primary result:** Top system (SRCB) achieved NDCG@1000 of 0.6824, significantly outperforming the best baseline (PyTerrier BM25, 0.1700).

## Executive Summary
The TREC 2025 Tip-of-the-Tongue (ToT) track tackled ad-hoc retrieval for verbose, complex information needs where users recall partial details about an entity. The track introduced a general-domain test set with 622 queries across 53 entity types, sourced from a movie dataset, human elicitations, and LLM-generated synthetic queries, using a 6.4M-article Wikipedia corpus. Nine teams submitted 32 runs, with the best system more than quadrupling the baseline BM25 NDCG@1000. Performance varied by query source, with synthetic and human-elicited queries being easier than movie queries, and top systems leveraged hybrid retrieval and external knowledge.

## Method Summary
The TREC 2025 ToT track used a filtered 2023 Wikipedia dump (6,407,814 articles) as the corpus. The test set comprised 622 queries: 172 from the MS-ToT movie dataset, 150 human-elicited by NIST assessors across three domains, and 300 synthetically generated using Llama-3.1-8B-Instruct and GPT-4o. A training set of 143 MS-ToT queries and development sets were provided. Relevance was binary (correct Wikipedia page). Primary metric was NDCG@1000, with supplementary metrics (NDCG@10, MRR@1000, Recall@1000). Participants (nine groups, 32 runs) could use provided data and external resources (e.g., Wikidata). Baselines included BM25 (Anserini, PyTerrier) and a dense retriever (Lightning IR). Top runs typically combined provided and external training data, used hybrid first-stage retrieval (sparse + dense), and employed learned rerankers, often integrating structured knowledge.

## Key Results
- SRCB's top run achieved NDCG@1000 of 0.6824, far surpassing the best baseline (PyTerrier BM25, 0.1700).
- Performance was higher on synthetic and NIST human-elicited queries than on MS-ToT movie queries.
- Wide score spread and strong correlations (Kendall's τ ≥ 0.703) across query types supported the use of diverse query generation for robust ToT evaluation.

## Why This Works (Mechanism)
### Mechanism 1: Diverse Query Training for Robustness
**Claim:** Systems exposed to a mixture of query sources (synthetic LLM, human-elicited, legacy dataset) develop more robust representations for ToT needs than those trained on a single source.  
**Mechanism:** Different sources introduce varying distributions of linguistic complexity (false memories, uncertainty markers, contextual vs. semantic details). A model exposed to this mixture learns to disentangle overlapping memory phenomena, avoiding overfitting to one source's idiosyncrasies.  
**Evidence:** [abstract] "The wide score spread and query-type correlations support using diverse query generation..."; [section 4.2] "This finding supports the use of diverse query generation approaches..."; Figure 6 shows correlation. Corpus examples illustrate source-specific patterns (MS-ToT: movie plot/actor names; NIST: celebrity visual cues; Synthetic: general-domain descriptive metaphors).

### Mechanism 2: Hybrid Retrieval with External Knowledge
**Claim:** Top systems leverage hybrid retrieval (sparse + dense) supplemented by external knowledge (e.g., Wikidata) and a learned reranker to resolve ambiguity.  
**Mechanism:** Verbose ToT queries contain partial, noisy, multi-faceted clues. Hybrid first-stage retrieval casts a wider net; external structured data provides disambiguating signals (entity type, properties); a learned reranker re-weights candidates based on complex feature interactions.  
**Evidence:** [section 4.1] top runs used provided and other data; participants allowed external resources like Wikidata; [Table 1] top runs marked as using "Official and other" data; corpus examples require external property matches (e.g., actor's commercial work, talk show appearances).

### Mechanism 3: Explicit Memory Modeling
**Claim:** Resolving ToT queries requires distinguishing between semantic memories (target facts) and episodic memories (last engagement context), and handling negation/exclusion.  
**Mechanism:** Queries mix these elements; a robust system must weight semantic anchors more heavily than fallible episodic context while respecting negations. Could be achieved via query understanding that tags spans, retrieval that boosts semantic fields, or a reranker that down-weights episodic-only matches.  
**Evidence:** [section 2] lists seven ToT phenomena including semantic/episodic memories and uncertainty; [section 2] explicitly distinguishes semantic vs. episodic; corpus examples illustrate mixes (e.g., plot details + "saw clip on Facebook" + "not the one with blue poster").

## Foundational Learning
### Concept: Verbose Query Decomposition
**Why needed:** ToT queries are long and interleave multiple information types (target facts, personal context, uncertainties). Naive processing loses signal.  
**Quick check:** Given "It's a book about a wizard, I read it in a cabin in the woods, but it's not the one with the lightning scar...", identify the semantic memory, episodic memory, and exclusion criterion.

### Concept: Multi-hop/Implied Relation Reasoning
**Why needed:** Correct answers often require connecting disparate clues (e.g., "actor in casino commercials" + "talk show panelist" → celebrity). This goes beyond keyword matching to intermediate inference, possibly using external KB relations.  
**Quick check:** For "The scientist who co-authored that book with the physicist who wrote 'A Brief History of Time'", what are the necessary hops to identify the target entity?

### Concept: Negative Evidence and False Memory Modeling
**Why needed:** Queries state what the target is not ("it's not the Tom Cruise one") or contain incorrect memories. Systems must treat these as constraints to eliminate candidates, not as content to match.  
**Quick check:** How should a retrieval system's scoring function change when encountering "not the one starring [X]" compared to "starring [X]"?

## Architecture Onboarding
**Component map:**  
Query Parser & Feature Extractor → [Sparse Retriever (BM25), Dense Retriever (e.g., BGE-M3), External KB Lookup] → Candidate Merger & Deduplication → Feature Extractor for Reranking → Learned Reranker (e.g., LambdaMART, Cross-Encoder) → Final Ranked List

**Critical path:** Input Query → Parser → Ensemble Retrieval → Merge → Feature Extraction → Reranker → Output. Parser quality and feature extraction are latent bottlenecks.

**Design tradeoffs:**
- **Sparse vs. Dense:** Sparse precise for named entities/plot points; dense handles paraphrasing. Hybrid is essential.
- **External Data:** Wikidata adds latency/complexity but provides structured disambiguation (e.g., "born in," "occupation"). Must align Wikipedia IDs to Wikidata Q-ids.
- **Reranker Complexity:** Linear model on handcrafted features is interpretable but limited; cross-encoder powerful but slow; two-stage approach (light filter then heavy rerank on top-100) common.

**Failure signatures:**
- High Recall@1000 but low NDCG@10: weak reranker (correct entity buried deep).
- Performance collapse on MS-ToT vs. synthetic: overfitting to synthetic query style.
- Systematic failures on queries with strong negation: reranker ignores "not" constraints.

**First 3 experiments:**
1. **Query Type Sensitivity:** Run baseline (e.g., BM25 + BGE-M3 + simple reranker) on each query subset (MS-ToT, NIST, Synthetic) separately. Report NDCG@1000 for each. Expect large variance if system is fragile.
2. **External Data Ablation:** Re-run best configuration with and without Wikidata during first-stage retrieval or feature extraction. Measure NDCG@1000 delta. Hypothesis: top systems show significant positive delta.
3. **Error Analysis:** Manually sample 50 failed queries (correct answer not in top-100). Categorize primary reason: (a) missed semantic clue, (b) failed negation, (c) over-relied on episodic detail, (d) entity too obscure. Guides parser/feature improvements.

## Open Questions the Paper Calls Out
1. **Why are MS-ToT movie queries more difficult?** Paper notes they were harder but provides no analysis of underlying query differences (length, complexity, domain specificity, memory characteristics).
2. **Which external data sources and integration methods contribute to top performance?** Top runs used external data but did not disclose specifics (e.g., Wikidata usage details, ablation results).
3. **Do LLM-generated synthetic queries accurately reflect real human ToT complexity?** No empirical comparison of synthetic vs. real queries regarding ToT phenomena frequencies or human-rated realism.
4. **Which of the 53 entity types are most challenging?** Results aggregated; no per-entity analysis or correlation with entity attributes (Wikipedia coverage, popularity).

## Limitations
- Exact architecture and training details of top system (SRCB) undisclosed, preventing full replication.
- Synthetic query generation methodology (prompts, domain sampling, filtering) lacks granular description, risking irreproducibility.
- No ablation studies isolating component contributions; causal claims about mechanisms remain inferential.

## Confidence
- **Diverse query generation improves robustness:** High (supported by strong inter-query-type correlations τ ≥ 0.703).
- **Hybrid retrieval + external KB is necessary:** Medium (top runs used external data, but no controlled ablation proves necessity).
- **Explicit modeling of semantic/episodic memory:** Low (plausible task interpretation, but no system analysis confirms implementation).

## Next Checks
1. **Query-source ablations:** Train only on synthetic vs. human-elicited data; evaluate on all three sources; measure performance deltas to test shared-skill assumption.
2. **External knowledge ablation:** For best open-source system (e.g., DS@GT), remove all Wikidata/knowledge-graph features; assess NDCG@1000 change.
3. **Phenomenon-specific error audit:** Categorize 100 failures from top system into: missed semantic clue, failed negation, over-relied on episodic, obscure entity; quantify distribution to validate memory-modeling hypothesis.
