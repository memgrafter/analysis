# SUN: Shared Use of Next-token Prediction for Efficient Multi-LLM Disaggregated Serving
## Quick Facts
- **arXiv ID:** 2603.02599
- **Source URL:** https://arxiv.org/abs/2603.02599
- **Reference count:** 40
- **Primary result:** SUN improves throughput per GPU by up to 2.0× over conventional disaggregated serving while matching full fine-tuning accuracy, and QSUN achieves a 45% speedup with quantization.

## Executive Summary
SUN addresses inefficient GPU utilization in multi-LLM serving caused by model-specific resource partitioning. It decomposes decoder-only Transformers into task-specific prefill modules and a single shared frozen decode module, trained via prefill-only tuning to ensure KV cache compatibility. This enables cross-model decode sharing and model-agnostic routing that balances load across workers. Experiments show SUN matches full fine-tuning accuracy across tasks and model families, improves throughput per GPU by up to 2.0×, and keeps time-per-output-token (TPOT) within 5% of full fine-tuning. Quantized SUN (QSUN) applies weight-only quantization to the shared decoder and recovers accuracy via prefill re-tuning, achieving a 45% speedup while preserving shared decoding benefits.

## Method Summary
SUN’s core idea is to separate the prefill and decode phases at the model level rather than per-model instance. Each task (fine-tuned variant) has its own prefill module, responsible for processing the input prompt and generating the initial KV cache. A single frozen decode module, shared across all tasks, then performs autoregressive generation using the KV cache. The prefill modules are trained with a loss that backpropagates through the KV cache but stops at the frozen decoder, forcing them to produce KV representations compatible with the shared decoder. During serving, requests are first sent to task-specific prefill workers; after prefill, the KV cache is transferred to a shared decode pool. A model-agnostic router balances decode load across the pool by aggregating all decode requests regardless of task, enabling cross-model batching and high GPU utilization. For quantization, QSUN applies weight-only quantization to the shared decoder and then re-tunes the prefill modules with the quantized decoder frozen, aligning their KV outputs to the low-precision decoder.

## Key Results
- **Accuracy parity:** SUN achieves comparable performance to full fine-tuning across tasks (math, coding, tool calling) and model families (LLaMA, Qwen).
- **Throughput gain:** Up to 2.0× improvement in throughput per GPU over conventional disaggregated serving, with TPOT within 5% of full fine-tuning.
- **Quantization speedup:** QSUN delivers a 45% decode speedup while maintaining accuracy through prefill re-tuning.

## Why This Works (Mechanism)
### Mechanism 1: Prefill-only Tuning for Decoder-Compatible KV Caches
SUN preserves fine-tuning accuracy by adaptively shaping KV caches during prefill to be directly consumable by a frozen shared decode module. The prefill-only tuning loss (Eq. 6) backpropagates through the prompt KV cache but stops at the frozen decoder, forcing the prefill module to produce KV representations that the base decoder expects. This eliminates train-inference mismatch and ensures that a single decoder can serve multiple tasks without accuracy loss, as demonstrated by the significant drop in accuracy for a naive sharing baseline (Fig. 2).

### Mechanism 2: Model-Agnostic Decode Routing for Load Balancing
By decoupling decode routing from task identity, SUN aggregates all decode requests into a common queue and processes them on a shared pool of decode workers. This cross-model batching balances the memory-bound decode workload across workers, preventing underutilization under skewed traffic. The model-agnostic policy works because decode computation is largely uniform across tasks (same architecture, only parameters differ), allowing heterogeneous batching without excessive per-task latency variance (Fig. 3, 4).

### Mechanism 3: Prefill Re-tuning for Quantization Compatibility
QSUN recovers accuracy lost from weight-only decoder quantization by re-tuning the prefill modules with the quantized decoder frozen. This aligns the prefill’s KV production to the effective weight distribution of the low-precision decoder. As shown in Table 2 and 3, without re-tuning (SUN+AWQ-d) accuracy collapses, but with prefill re-tuning QSUN nearly matches full-precision SUN.

## Architecture Onboarding
**Component map:** Task-specific prefill modules → KV cache transfer → Shared decode pool (with frozen decoder) → Model-agnostic decode router → Clients

**Critical path:**
1. Request arrives and is routed to the task-specific prefill worker.
2. Prefill worker computes the full prompt KV cache using its task-specific parameters.
3. KV cache is transferred to the shared decode pool; a decode request is enqueued.
4. Shared decode workers batch requests across tasks and run the frozen decoder step-by-step using the KV cache.
5. Generated tokens are streamed back; per-task context is maintained via KV cache pointers.

**Design tradeoffs:**
- Prefill-only tuning reduces training cost and enables sharing but limits prefill adaptability (cannot modify decoder layers).
- Decode pool size trades off utilization vs. bottleneck risk; too small increases queuing, too large wastes resources.
- Quantization placement: decoder-only quantization avoids prefill overhead but requires careful re-tuning to avoid accuracy loss.

**Failure signatures:**
- Accuracy collapse when prefill KV is incompatible with shared decoder (e.g., without re-tuning for quantization).
- Throughput saturation at lower concurrency than expected: indicates decode pool too small for workload skew.
- Increased TTFT under quantization without re-tuning due to KV mismatch.

**First 3 experiments:**
1. Accuracy validation: Compare SUN with full fine-tuning on multiple model/task pairs (e.g., LLaMA3.1-8B, Qwen3-Base) to confirm <5% gap.
2. Throughput under consolidation: Vary shared decode worker count (e.g., 4D→1D) under uniform and skewed (Zipf α=1.5) workloads; measure total throughput and TPOT.
3. QSUN ablation: Compare SUN+AWQ-d (no re-tuning) vs. QSUN (with re-tuning) on accuracy and TPOT to show recovery.

## Open Questions the Paper Calls Out
1. Does prefill-only tuning maintain comparable accuracy to full fine-tuning across a broader range of NLP tasks beyond the three evaluated domains (math, coding, tool calling)?
2. What decode routing policy minimizes tail latency (e.g., p99 TPOT) in a shared decode pool under highly skewed and dynamic workloads?
3. Can prefill-only re-tuning in QSUN recover accuracy universally across different weight-only quantization methods, or is it specific to AWQ?

## Limitations
- SUN’s decoder generalization may fail for highly divergent model architectures (e.g., mixture-of-experts) or aggressive fine-tuning.
- Heterogeneous decode parameters (sampling, generation lengths) could increase tail latency in the shared pool.
- Quantization recovery may not extend to very low bit-widths (e.g., 3-bit) or other quantization schemes (e.g., GPTQ).
