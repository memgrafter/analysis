# KGHaluBench: A Knowledge Graph-Based Hallucination Benchmark for Evaluating the Breadth and Depth of LLM Knowledge

## Quick Facts
- arXiv ID: 2602.19643
- Source URL: https://arxiv.org/abs/2602.19643
- Reference count: 35
- Primary result: Proprietary models achieve higher weighted accuracy (55.94% average for large models) than open-source (48.32%); smaller models show high HaluBOK (54.75%) indicating poor entity recognition, while larger models still exhibit significant HaluDOK (~30%), revealing persistent struggles with factual depth.

## Executive Summary
KGHaluBench introduces a dynamic, knowledge graph-based benchmark to evaluate LLM hallucinations across knowledge breadth and depth. By generating compound questions from Wikidata and employing a two-layer verification pipeline, it classifies errors into entity-level misalignment (breadth) and fact-level inaccuracies (depth). Evaluation of 25 LLMs reveals that proprietary models outperform open-source ones in weighted accuracy, with smaller models struggling primarily with entity recognition and larger models still showing substantial depth-related hallucinations. The benchmark provides novel metrics—HaluBOK, HaluDOK, and W_a—to enable fairer comparisons.

## Method Summary
The method comprises three stages: (1) **Question Generation**: A focal entity is sampled from Wikidata; three distinct relations are selected; a compound question template is populated with the entity's name, disambiguating context (e.g., lifespan), and the three relations, requiring a comprehensive response. (2) **Difficulty Estimation**: Each question's difficulty score (Qd) combines normalized entity popularity and relation complexity via a sigmoid function. (3) **Response Verification**: A two-layer pipeline first detects abstentions and checks entity-level alignment using semantic and lexical similarity; then, for aligned responses, each fact is verified through an NLI model, an LLM judge, and an expert arbitration. Metrics include weighted accuracy (W_a), breadth hallucination rate (HaluBOK), and depth hallucination rate (HaluDOK).

## Key Results
- Proprietary large models achieve higher weighted accuracy (55.94% avg) than open-source models (48.32% avg).
- Smaller models exhibit high HaluBOK (54.75%), indicating severe entity recognition issues.
- Larger models still show significant HaluDOK (~30%), demonstrating ongoing challenges with factual depth despite better conceptual alignment.

## Why This Works (Mechanism)
**Mechanism 1: Dynamic compound questioning via KG probes breadth and depth.**  
The KG's relational structure allows sampling a focal entity and selecting three distinct relations to form a compound question demanding a unified response covering the entity's identity and multiple factual details. This forces models to recall both core entity identity and varied specifics. The KG's comprehensive coverage provides an updatable ground truth, while random sampling and relation weighting prevent topic overrepresentation. *Break condition*: Wikidata's Western/English biases may limit global knowledge breadth representation.

**Mechanism 2: Two-layer verification pipeline classifies hallucination types.**  
First, an entity-level filter uses semantic (cosine similarity) and lexical (token ratio) comparisons to classify responses as aligned, hallucinated, or abstained. Second, fact-level verification independently checks each required relation via an NLI model, an LLM judge, and an expert arbitration. This separates conceptual misalignment from factual errors. *Break condition*: Subtle, pervasive factual errors in semantically aligned responses may evade detection, undercounting fact-level hallucinations.

**Mechanism 3: Decomposed metrics and difficulty scaling enable fair comparisons.**  
HaluBOK measures entity-level failure rate (breadth), HaluDOK measures fact-level error rate among aligned responses (depth), and W_a scales accuracy by Qd (entity popularity + relation complexity) to neutralize question difficulty bias. *Break condition*: If Qd poorly correlates with actual model success (paper reports moderate ρ = -0.403), W_a may misrepresent capability.

## Foundational Learning
- **Knowledge Graph Structure & Querying**: Understanding KG as triples (subject-predicate-object) is fundamental for entity/relation retrieval and question generation. *Quick check*: How would you retrieve all 'occupation' relations for 'Marie Curie' from Wikidata, and why is this relation set used in question generation?
- **Semantic vs. Lexical Similarity Metrics**: The entity-level filter combines semantic similarity (cosine of embeddings) and lexical overlap (token ratio) to detect entity misalignment. *Quick check*: Why might an LLM's response about 'Barack Obama' achieve high token overlap with the correct description if it confuses key facts? How does semantic similarity help?
- **Item Response Theory (IRT) Inspiration**: W_a's Qd uses a sigmoid function to non-linearly aggregate entity popularity and relation complexity, inspired by IRT's item difficulty modeling. *Quick check*: If a question has high entity popularity (easy) but three very low-complexity relations (hard facts), what would Qd be relative to average, and why?

## Architecture Onboarding
**Component map**:  
KG Interface -> Entity Selector & Sampler -> Question Generator -> Difficulty Scorer -> LLM Inference -> Response Verification Pipeline (Abstention Classifier -> Entity-Level Filter -> Fact Verification Pipeline) -> Metrics Calculator

**Critical path**:  
KG Query -> Entity Sampling -> Triple Selection -> Question Formulation -> LLM Inference -> Entity Filter (branch: Abstain/Hallucinate/Align) -> **IF Align** -> Fact Verification (per relation) -> Scoring & Metrics

**Design tradeoffs**:  
- Verification accuracy vs. cost: Uses cheap NLI first, then expensive LLM, rarely invoking expert.
- Randomness vs. control: Entity type prioritization and relation weighting maintain difficulty distribution while ensuring breadth.
- Automation vs. ground truth: Fully automated pipeline calibrated on human validation; accepts residual error for scalability.

**Failure signatures**:  
- High abstention rate across models: questions too obscure or disambiguation ineffective.
- Low human agreement in validation (<75%): entity-level filter threshold misaligned.
- W_a standard deviation increases vs. accuracy: Qd instability across random draws.
- HaluBOK ~0% but HaluDOK very high for large models: entity filter too lenient.

**First 3 experiments**:  
1. Validate entity-level filter: Human study on 900 questions to tune similarity threshold (test 0.65, 0.70, 0.75) for optimal F1-score, prioritizing recall.
2. Check difficulty correlation: Compute Spearman's ρ between Qd and actual success rate on calibration set; if |ρ| < 0.3, revise weightings.
3. End-to-end pipeline sanity: Generate 10 assessments; ensure entity type distribution matches Table 2 and Qd variance low.

## Open Questions the Paper Calls Out
- How can KGHaluBench be extended to incorporate domain-specific knowledge graphs and improve coverage of underrepresented languages and topics?
- What enhancements can be made to the automated fact verification pipeline to reduce errors in hallucination detection?
- Why do larger language models exhibit significant depth-of-knowledge hallucinations (high HaluDOK) despite low breadth-of-knowledge hallucinations (low HaluBOK)?
- How can abstention mechanisms in LLMs be optimized to reduce over-abstention while maintaining low hallucination rates?
- Is the weighted accuracy metric (W_a) effective in neutralizing entity popularity bias across diverse question sets?

## Limitations
- Reliance on Wikidata introduces Western/English biases, limiting global knowledge breadth representation.
- Automated verification pipeline (87.74% human agreement) may miss subtle factual errors, risking undercounting hallucinations.
- Weighted accuracy's difficulty estimator shows only moderate correlation (ρ = -0.403) with actual model performance, questioning its robustness.
- Calibration dataset and derived weights (entity relevance, relation complexity, α parameter) are undisclosed, hindering faithful reproduction.

## Confidence
- **Claim 1 (KG-driven questions probe breadth/depth)**: Medium. Evidence: KG structure enables compound queries, but Wikidata biases limit global generality.
- **Claim 2 (Two-layer verification accuracy)**: Medium. Evidence: Human validation shows 79.19% (entity) and 87.74% (fact) agreement, but may miss pervasive errors.
- **Claim 3 (W_a and split metrics fairness)**: Low-Medium. Evidence: W_a reduces variance slightly, but difficulty correlation modest; depends on unreleased calibration.
