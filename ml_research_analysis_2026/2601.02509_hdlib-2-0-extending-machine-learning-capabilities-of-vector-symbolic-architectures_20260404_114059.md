# hdlib 2.0: Extending Machine Learning Capabilities of Vector-Symbolic Architectures
## Quick Facts
- **ArXiv ID:** 2601.02509
- **Source URL:** https://arxiv.org/abs/2601.02509
- **Reference count:** 0
- **Primary result:** hdlib 2.0 provides a unified open-source VSA toolkit integrating supervised, unsupervised, graph-based, and quantum machine learning models.

## Executive Summary
The hdlib 2.0 library extends the foundational Vector-Symbolic Architecture (VSA) framework with advanced machine learning capabilities. It introduces supervised models (classification with feature selection and hyperparameter tuning, multi-model regression), unsupervised clustering, graph learning (encoding entire graphs into single vectors), and the first implementation of Quantum Hyperdimensional Computing. The library is available under an MIT license and offers a consistent API for both classical and quantum operations, enabling researchers to apply VSA to a wider range of data-driven problems.

## Method Summary
The work extends the hdlib Python library by implementing several new models that leverage VSA operations (binding, bundling, permutation) to encode data into high-dimensional hypervectors. The classification model enhances the prior version with stepwise feature selection and automatic hyperparameter tuning. The regression model uses a multi-cluster strategy: inputs are assigned soft cluster memberships, and predictions are confidence-weighted sums of cluster-specific regressors. The clustering model adapts k-means to the VSA space using cosine similarity and bundling for centroid updates. The graph model encodes nodes and weighted edges as random hypervectors, bundling them into a single graph vector that supports edge existence and weight prediction via algebraic queries. For quantum computing, the library implements VSA arithmetic (binding, bundling, permutation, similarity) using Qiskit circuits, based on phase encoding, LCU/OAA, QFT, and the Hadamard test. A quantum classification model uses these primitives to store class states and classify by similarity. All models follow a similar scikit-learn-like interface (fit, predict).

## Key Results
- Provides a unified toolkit for VSA-based machine learning, including enhanced classification, multi-model regression, VSA k-means clustering, and single-vector graph encoding.
- Introduces the first Quantum Hyperdimensional Computing implementation with quantum arithmetic operations (binding, bundling, etc.) and a quantum classification model via Qiskit.

## Why This Works (Mechanism)
### Mechanism 1: Multi-model Regression
- **Claim**: The multi-model regression strategy accurately predicts continuous variables by combining outputs from multiple cluster-specific regressors, each weighted by the input's membership confidence.
- **Mechanism**: Input features are nonlinearly encoded into a hypervector using random base vectors and biases. The encoded vector is compared to k cluster centroid hypervectors via cosine similarity; a softmax converts these similarities to confidence scores. The final prediction is the confidence-weighted sum of all regression models' outputs. During training, all regressors update proportionally to their confidence, while only the most confident cluster (highest softmax) refines its centroid and regressor toward the target. This adaptively partitions the input space and learns non-linear relationships.
- **Core assumption**: The data can be segmented into k regions where a linear model in the hyperdimensional space is effective; confidence weighting provides robustness near cluster boundaries.
- **Evidence anchors**: 
  - Abstract: "a new regression model for predicting continuous variables..."
  - Section: "The RegressionModel employs a sophisticated multi-model strategy, maintaining a set of k parallel cluster models and regression models. During the iterative fit process, an encoded input vector is compared against all cluster models to compute a set of confidence scores via a softmax function. A final prediction is produced by a confidence-weighted sum of the outputs from all regression models. The prediction error is then used to update the models: all regression models are adjusted based on their confidence score, while only the most similar cluster model is refined."
  - Corpus: Builds on prior work by Hernández‑Cano et al. (2021).
- **Break condition**: If the data lacks clear cluster structure, confidence weights become diffuse, causing unstable learning. Low dimensionality leads to unreliable similarity estimates, preventing accurate prediction.

### Mechanism 2: Graph Encoding
- **Claim**: GraphModel encodes an entire directed/undirected weighted graph into a single hypervector, enabling direct edge existence checks and weight prediction via algebraic operations without reconstructing the explicit adjacency structure.
- **Mechanism**: Each node and edge weight receives a random hypervector. For a node, its memory vector is created by bundling the hypervectors of its neighbors, each multiplied by the corresponding weight vector; directed edges apply a permutation to the neighbor's vector to encode direction. The global graph vector results from bundling all node identifiers bound to their memory vectors. Querying `edge_exists(u, v)` binds the graph vector with the inverse of u's identifier to retrieve a noisy memory, then binds with v and measures similarity; a threshold decides presence. Weight prediction compares the noisy memory against stored weight vectors.
- **Core assumption**: The superposition encoded by bundling preserves relational information so that similarity between a probe and stored patterns reliably indicates connectivity; interference noise remains below the decision threshold.
- **Evidence anchors**: 
  - Abstract: "a graph model encoding entire directed/undirected weighted graphs into single vectors for edge queries and weight prediction."
  - Section: "Graph Model: ... encodes an entire directed and undirected weighted graph into a single hyperdimensional vector. The edge_exists method uses binding operations to probe the graph vector, retrieve a noisy version of a node’s memory, and check its similarity to a potential neighbor."
  - Corpus: Method originates from Poduval et al. (2022).
- **Break condition**: For large or dense graphs, binding interference overwhelms the signal, causing high false positive/negative rates. Collisions in random vectors also degrade performance.

### Mechanism 3: Quantum Hyperdimensional Computing
- **Claim**: Quantum Hyperdimensional Computing (QHDC) implements VSA arithmetic operations (binding, bundling, permutation, similarity) on quantum hardware, providing a foundation for quantum machine learning models that operate on hyperdimensional vectors.
- **Mechanism**: Classical hypervectors are mapped to quantum states via phase encoding: each element of a bipolar hypervector corresponds to a relative phase in a uniform superposition. Binding is realized by sequentially applying phase rotations derived from the two vectors. Bundling (summation) uses Linear Combination of Unitaries (LCU) followed by Oblivious Amplitude Amplification (OAA) to produce a normalized superposition representing the average. Permutation is achieved by applying the Quantum Fourier Transform (QFT) to induce cyclic shifts. Similarity (inner product) is estimated via the Hadamard Test, yielding the cosine similarity. The QuantumClassificationModel leverages these primitives to store class states and classify by measuring similarity.
- **Core assumption**: Quantum circuits can accurately simulate VSA algebra; errors from noise and decoherence do not dominate; the number of qubits scales with hypervector dimensionality.
- **Evidence anchors**: 
  - Abstract: "the first implementation ever of Quantum Hyperdimensional Computing with quantum-powered arithmetic operations (binding, bundling, etc.) via Qiskit and a corresponding quantum classification model."
  - Section: "Quantum Hyperdimensional Computing: Encoding: we employ a phase encoding strategy... Binding: realized via quantum phase oracles... Bundling: implemented as a quantum-native averaging process using LCU followed by OAA... Permutation: achieved using the QFT... Similarity: computed via the Hadamard Test."
  - Corpus: No prior papers on quantum hyperdimensional computing; this is a novel contribution.
- **Break condition**: Current quantum hardware suffers from high error rates and limited qubit counts; circuits for high-dimensional vectors (>1000) often exceed coherence times or require too many qubits. Simulation on classical hardware loses any quantum advantage and may be memory‑limited.

## Foundational Learning
- **Vector-Symbolic Architectures (VSA) and core operations**
  - *Why needed*: All hdlib models rely on these operations to encode and manipulate information in high-dimensional spaces. Understanding binding (composition), bundling (superposition), and permutation (order) is essential to design effective data representations.
  - *Quick check*: What is the mathematical difference between binding (typically element-wise multiplication) and bundling (element-wise addition followed by normalization) in VSA, and how does each operation contribute to representing symbols and their relationships?

- **Machine learning paradigms (classification, regression, clustering, graph learning)**
  - *Why needed*: The library provides distinct modules for each task; one must know whether the goal is to predict discrete labels, continuous values, discover groupings, or answer graph queries to select the correct model and interpret its outputs.
  - *Quick check*: In hdlib, how does the formation of class hypervectors differ between supervised classification and unsupervised clustering?

- **Quantum computing basics (qubits, superposition, gates) as used in QHDC**
  - *Why needed*: The quantum module runs VSA operations as quantum circuits; grasping qubits, unitary evolution, and measurement is necessary to understand the encoding process and the practical limitations of the QuantumClassificationModel.
  - *Quick check*: How does phase encoding map a classical hypervector to a quantum state, and why is this representation suitable for implementing binding via sequential phase rotations?

## Architecture Onboarding
- **Component map**:
  hdlib.space.Space -> hdlib.vector.Vector -> hdlib.arithmetic (classical: multiply, add, roll, cosine; quantum: QuantumBinder, QuantumBundler, QuantumPermuter, QuantumSimilarity) -> models (ClassificationModel, RegressionModel, ClusteringModel, GraphModel, QuantumClassificationModel). RegressionEncoder supports RegressionModel; stepwise_regression/auto_tune are methods of ClassificationModel.

- **Critical path (classical classification)**:
  1. Create space: `space = Space(d=10000, vtype='binary')`.
  2. Build item memory: random vectors for each feature symbol/value.
  3. Encode training data: bind feature vectors and bundle to produce a composite hypervector.
  4. Train: `clf = ClassificationModel(space); clf.fit(X_encoded, y)`.
  5. (Optional) Feature selection: `clf.stepwise_regression(X_original, y)` to identify important features and rebuild encoded vectors.
  6. (Optional) Hyperparameter tuning: `clf.auto_tune(X_encoded, y, param_grid)`.
  7. Predict: encode test samples; `pred = clf.predict(X_test_encoded)`.

- **Design tradeoffs**:
  - *Dimensionality*: Larger `d` increases capacity and reduces interference but uses more memory and CPU. Common choices: 5,000–100,000.
  - *Vector type*: Binary (`±1`) allows fast Hamming distance; continuous vectors preserve magnitude but are slower.
  - *Regression*: `k` (number of clusters) balances bias/variance; too few underfit, too many overfit. `quantized_prediction` mode uses Hamming for speed at potential accuracy loss.
  - *Graph*: Interference grows with density; for large graphs, increase `d` or use permutation for directionality.
  - *Quantum*: Simulation feasible only for small `d` (<~500); real hardware limited by qubit count and noise; circuits may require many measurement shots.

- **Failure signatures**:
  - `ValueError: All vectors must have the same dimension.` – check vector dimensions.
  - `RuntimeError: Vectors must be normalized before similarity.` – call `normalize()` after bundling.
  - Classification accuracy near chance: insufficient dimensionality or poor encoding; try higher `d` or better item memory.
  - Regression predictions constant or NaN: confidence under/overflow; reduce learning rate or adjust `k`.
  - Graph `edge_exists` returns all `True`/`False`: threshold inappropriate; adjust threshold or increase `d`.
  - Quantum circuit errors: `QiskitError: Too many qubits` – reduce `d`; `Circuit too deep` – simplify or transpile; high variance – increase shots.

- **First 3 experiments**:
  1. **Classification**: Two-moon dataset with ~500 samples, `d=10000`. Expect >95% accuracy.
  2. **Regression**: Synthetic 1D function `y = 0.5*x + noise` with 10 level vectors, `k=5`. Expect MSE <0.05.
  3. **Graph**: Directed ring graph with 6 nodes and random weights (3 levels). Fit and check `edge_exists` for all 36 ordered pairs; expected recall >90% for existing edges, precision >90% for non-edges. Predict held-out edge weight with >80% accuracy within one level.

## Open Questions the Paper Calls Out
1. How do the enhanced feature selection and hyperparameter tuning methods in the classification model scale with extremely high-dimensional feature spaces or massive datasets?
2. What are the performance trade-offs between full-precision and binarized representations in the regression model, particularly regarding prediction accuracy versus inference speed?
3. What are the theoretical and practical limits of the graph encoding method in terms of maximum graph size, edge density, or structural complexity before representation fidelity degrades?
4. How do current quantum hardware limitations, such as noise and decoherence, affect the reliability and accuracy of quantum arithmetic operations in Quantum Hyperdimensional Computing and the quantum classification model?

## Limitations
- No quantitative benchmarks or baseline comparisons are provided for any model.
- Quantum Hyperdimensional Computing is currently simulated only; real‑hardware noise and qubit constraints are not evaluated.
- Graph model interference for large or dense graphs remains untested; scalability thresholds are unknown.
