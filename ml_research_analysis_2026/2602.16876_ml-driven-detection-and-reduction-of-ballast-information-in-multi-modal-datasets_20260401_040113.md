# ML-driven detection and reduction of ballast information in multi-modal datasets
## Quick Facts
- arXiv ID: 2602.16876
- Source URL: https://arxiv.org/abs/2602.16876
- Reference count: 37
- Primary result: Unified Ballast Score achieves >70% feature reduction across modalities while preserving or improving model performance.

## Executive Summary
The proliferation of multi-modal datasets often includes “ballast”—features that are redundant, noisy, or of low analytical utility—leading to inflated storage and computational costs. This paper introduces a unified framework to detect and eliminate such ballast information across structured, semi-structured, unstructured, and sparse data. Central to the approach is the Ballast Score, which aggregates multiple indicators including entropy, mutual information, Lasso coefficients, SHAP values, PCA loadings, and topic modeling metrics. Evaluated on four diverse datasets—IEEE-CIS fraud detection, Amazon Fashion reviews, CORD-19/PubLayNet, and Ireland Census 2022—the method removes over 70% of features in sparse and semi-structured cases, achieves up to 95.68% storage savings via sparse matrices, reduces training time by more than 60%, and in some instances slightly improves predictive performance. The work demonstrates a practical pathway to efficient, high‑utility data representations.

## Method Summary
To identify ballast features, the authors apply a suite of statistical, model‑aware, and semantic techniques tailored to each data modality. For structured and sparse datasets, they compute feature‑wise entropy and mutual information to capture randomness and target relevance, fit Lasso to obtain sparse coefficients, and train a LightGBM model to derive SHAP values that quantify each feature's contribution. For semi‑structured JSON data (e.g., Amazon reviews), they flatten the structure, generate TF‑IDF vectors, and use BERT embeddings to measure semantic similarity and redundancy. For unstructured text and layout (CORD-19, PubLayNet), they employ LDA topic modeling with coherence scores, TextRank summarization, and intersection‑over‑union of bounding boxes. All indicators are normalized to [0,1] and combined—either by averaging or weighted sum—into a Ballast Score. A threshold τ, chosen by analyzing model performance as features are incrementally removed, determines which features are pruned. The pruned dataset is then used to train a classifier (LightGBM or CatBoost), and performance, training time, and storage requirements are compared against the full feature set.

## Key Results
- Over 70% of features are removable in sparse and semi‑structured datasets, with storage savings reaching 95.68% using compressed sparse row (CSR) format.
- On the IEEE‑CIS fraud detection dataset, SHAP‑guided pruning retains only 69 features yet improves AUC from 0.9131 to 0.9147 and cuts training time by more than 60%.
- Across all modalities, predictive metrics (AUC, F1‑score, accuracy, recall) remain stable or show marginal gains, confirming that ballast removal does not sacrifice analytical value.

## Why This Works (Mechanism)
The Ballast Score succeeds because it synthesizes multiple, complementary perspectives on feature utility, thereby reducing the chance of wrongly discarding informative signals. Statistical measures (entropy, mutual information) quickly flag constant or uncorrelated features; model‑based methods (Lasso, SHAP) capture relevance within predictive algorithms, including nonlinear interactions; semantic analysis (topic modeling, BERT) identifies redundancy in textual content; and PCA highlights directions of maximal variance. By requiring low scores across several of these dimensions, a feature is likely to be truly superfluous. Moreover, threshold selection is driven by empirical performance curves: pruning proceeds only until a point where additional removal would degrade metrics, ensuring that essential information is retained. The final use of sparse matrix formats magnifies storage savings without altering the data itself.

## Foundational Learning
- **Entropy**: Measures randomness of a feature's distribution; low entropy indicates a feature carries little information. Quick check: Compute histogram of feature values; if one value dominates (entropy < 0.5), consider removal.
- **Mutual Information**: Quantifies dependence between feature and target; low MI suggests irrelevance. Quick check: Estimate MI using k‑nearest neighbors; if MI < 0.01, candidate for ballast.
- **Lasso (L1 Regularization)**: Embeds feature selection by shrinking coefficients to zero; zero coefficients indicate the feature is not needed in a linear model. Quick check: Fit LassoCV; drop features with coefficient exactly zero.
- **SHAP Values**: Post‑hoc explanation for tree models; average absolute SHAP per feature reflects its impact on predictions. Quick check: Train LightGBM, compute SHAP; prune features with mean |SHAP| below a threshold (e.g., 1e‑4).
- **Topic Modeling (LDA)**: For text, assigns words to topics; low‑contributing words to coherent topics are likely ballast. Quick check: Compute topic coherence; remove words that never appear in top‑N words of any topic.
- **Sparse Matrix Storage (CSR)**: Compresses matrices with many zeros; essential for high‑dimensional sparse data like TF‑IDF. Quick check: Check sparsity (>90% zeros); converting to CSR should reduce memory by ~90% or more.

## Architecture Onboarding
**Component map**  
Raw Data → Preprocessing (modality‑specific) → Feature Matrix → Ballast Indicator Computation (Entropy, MI, Lasso, SHAP, PCA, LDA) → Score Aggregation (Normalization + Thresholding) → Pruned Dataset → Classifier Training (LightGBM/CatBoost) → Evaluation (Performance, Time, Storage)

**Critical path**  
1. Load and clean raw data (handle missing values, standardize).  
2. Perform feature extraction appropriate to modality (e.g., flatten JSON, TF‑IDF, OCR extraction).  
3. Compute all ballast indicators in parallel where possible.  
4. Normalize each indicator to [0,1] and combine into a single Ballast Score.  
5. Apply threshold τ (determined from a validation sweep) to mark ballast features.  
6. Remove marked features to obtain the pruned feature matrix.  
7. Train the target model on both full and pruned matrices for comparison.  
8. Report AUC/F1, training time, and storage metrics.

**Design tradeoffs**  
- *Robustness vs. compute*: Using many indicators improves detection accuracy but requires extra model training (Lasso, SHAP) and topic modeling, increasing runtime.  
- *Pruning aggressiveness vs. risk*: Higher thresholds yield greater reduction but risk discarding useful features; the paper mitigates this by selecting τ where performance plateaus.  
- *Modality‑specific tuning vs. generality*: Tailoring preprocessing and indicators to each data type enhances effectiveness but complicates the pipeline; the unified Ballast Score offers a common interface at the cost of some specialization.

**Failure signatures**  
- *Performance degradation*: If the pruned model's AUC declines drastically, over‑pruning occurred; reduce threshold or inspect indicator contributions.  
- *Mismatched feature counts*: Preprocessing should yield expected dimensions (e.g., IEEE‑CIS 432 features); discrepancies indicate encoding flaws or leakage.  
- *Unexpected memory usage*: CSR format should drastically reduce memory for sparse data; if not, the matrix may not be sufficiently sparse or conversion was not applied correctly.  
- *SHAP/Lasso errors*: Convergence failures or all‑zero coefficients may signal poor scaling or inappropriate hyperparameters.

## Limitations
- Dataset‑specific threshold values (e.g., entropy < 0.5, MI < 0.01) are not provided, requiring empirical re‑tuning for new data.
- Hyperparameters for LightGBM, CatBoost, LDA, BERT, and random seeds are omitted, making exact replication difficult and results sensitive to these choices.
- Implementation details (e.g., handling of categorical variables, JSON flattening rules) are only partially described, risking inconsistent feature engineering across reproductions.
