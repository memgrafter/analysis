# RoPE-LIME: RoPE-Space Locality + Sparse-K Sampling for Efficient LLM Attribution

## Quick Facts
- **arXiv ID:** 2602.06275
- **Source URL:** https://arxiv.org/abs/2602.06275
- **Reference count:** 29
- **Primary result:** A decoupled perturbation-attribution method using a surrogate model with a RoPE-space locality kernel and Sparse-K sampling reduces closed-model API calls while achieving higher feature attribution quality (IoU, F1, AUROC) than baseline LIME variants on QA and MMLU tasks.

## Executive Summary
RoPE-LIME addresses the challenge of explaining black-box LLM outputs without requiring gradient access or repeated expensive queries to the target model. It does so by decoupling the reasoning and explanation phases: a closed-source model produces a fixed output once, and then a smaller, open-source surrogate model is used to compute token-level attributions via perturbation-based regression. The method introduces two key innovations: (1) a locality kernel based on Relaxed Word Mover's Distance computed in Rotary Positional Embedding (RoPE) space, which provides stable similarity measures under input masking, and (2) Sparse-K sampling, an efficient strategy that explores feature interactions with a sublinear number of queries. Evaluated on HotpotQA (sentence features) and a hand-labeled MMLU subset (word features), RoPE-LIME significantly outperforms leave-one-out sampling and a prior state-of-the-art method (gSMILE) while drastically reducing the number of calls to the closed model.

## Method Summary
RoPE-LIME follows the LIME framework but modifies the kernel and sampling. Given a prompt with interpretable features (e.g., sentences, words), it first queries the closed model once to obtain a fixed output text. Then, using an open-source surrogate model, it generates perturbed versions of the input by masking subsets of features according to the Sparse-K strategy, which samples masks with a fixed number of active features `k` (typically scaling with √M) and uses a total sample count `N` that scales logarithmically with the number of features `M`. For each perturbation, the surrogate model produces token logits conditioned on the fixed output; regression targets are derived from the negative log-likelihood and KL divergence relative to the unperturbed baseline. The locality kernel weights perturbations based on the Relaxed Word Mover's Distance between the original and perturbed inputs, computed in the RoPE embedding space of the surrogate model. Finally, a weighted linear regression fits the attribution coefficients.

## Key Results
- On a 50-query MMLU subset, open-source RoPE-LIME (Qwen-8B) outperformed closed-source gSMILE (gpt-4o-mini) on IoU (0.364 vs 0.248), F1 (0.508 vs 0.368), and AUROC (0.563 vs 0.431).
- On HotpotQA, Sparse-K sampling consistently beat leave-one-out (LOO): for 3-feature cases (96 samples) IoU 0.903 vs 0.797; for 13-feature cases (24 samples) IoU 0.632 vs 0.246 and AUROC 0.815 vs 0.566.
- The method drastically reduces the number of closed-model API calls compared to methods that require regeneration for each perturbation.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Using RWMD computed in RoPE embedding space yields a stable locality kernel for text perturbations that is robust to index shifts introduced by masking.
**Mechanism:** Standard token pooling in Euclidean space is sensitive to absolute position. RoPE encodes relative positions via complex rotations. The method aggregates span embeddings by averaging magnitudes (`¯r_k`) and using the circular mean for phases (`¯θ_k`), then defines `polarL2` distance. This kernel weights perturbations based on semantic/positional similarity in a space aligned with the model's attention.
**Core assumption:** Semantic and positional similarity for attribution is best captured in a space that respects the relative rotational structure inherent to the model's architecture (RoPE), rather than absolute Euclidean token positions.
**Evidence anchors:**
- [abstract] "locality kernel based on Relaxed Word Mover's Distance computed in RoPE embedding space for stable similarity under masking"
- [section 3.1/3.2] Formalizes polar domain aggregation and `polarL2` to preserve relative phase structure invariant to global index shifts.
- [corpus] Corpus shows related work on geometric metrics (e.g., WMD variants) and attribution, but no direct prior work combining RWMD with RoPE-space for LLM attribution. The novelty assumption stands.
**Break condition:** If the surrogate model does not use RoPE positional embeddings, the kernel's alignment with its attention mechanism is lost. Also, if features are syntactically identical but semantically unrelated, the kernel may over-weight based on positional similarity alone.

### Mechanism 2
**Claim:** Sparse-K sampling efficiently explores the combinatorial perturbation space, capturing feature interactions under a logarithmic sample budget (`N = c * log K`) compared to linear-cost leave-one-out (LOO).
**Mechanism:** Instead of perturbing one feature at a time (LOO) or all subsets (exponential), Sparse-K randomly masks `k` features per sample, where `k` scales with `√M`. This exploits contextual dependence in natural language: perturbing small, correlated groups reveals interactions without needing all combinations. Total sample count `N` scales sublinearly with `M`.
**Core assumption:** Natural language features exhibit local contextual dependence such that meaningful interactions occur within small, bounded groups (`k ≈ √M`), allowing a sublinear sample budget to approximate the full combinatorial space.
**Evidence anchors:**
- [abstract] "Sparse-K sampling, an efficient perturbation strategy that scales logarithmically with feature count and improves interaction coverage."
- [section 3.3] Explicitly contrasts with LOO's linear scaling and defines `N = c * log K`. Empirical results in Tables 2-3 show Sparse-K (e.g., M=13, IoU 0.632) dramatically outperforming LOO (IoU 0.246) with far fewer samples (24 vs 960).
- [corpus] Neighbors include "Context Attribution with Multi-Armed Bandit Optimization" and "AttriBoT", indicating a recognized need for efficient sampling. Sparse-K's specific logarithmic scaling and `k≈√M` are novel here.
**Break condition:** If features are entirely independent, perturbing groups of `k` features adds noise without revealing interactions. Also, if `k` is set too large relative to `M`, samples become too dense and lose locality.

### Mechanism 3
**Claim:** Decoupling reasoning (closed-model generation) from explanation (open-source surrogate attribution) eliminates the high cost and noise of closed-model regeneration during perturbation, enabling probability-based regression targets.
**Mechanism:** The closed-source model `f_L` is queried **once** to generate the fixed output text `y`. All subsequent perturbations `x ⊙ z_j` are fed to a smaller open-source surrogate `f_S`, which attends over `y` and outputs token probability distributions. Attribution regression uses distributional targets (KL divergence from baseline `L_0`) instead of discrete text overlap. This avoids repeated expensive API calls and stabilizes objectives against generation stochasticity.
**Core assumption:** A smaller, open-source model `f_S` can serve as a sufficiently faithful surrogate for the closed model `f_L`'s **input-output sensitivity** (i.e., how output token distributions change with input masking), even if `f_S` has different raw capabilities. The key is matching the *gradient* of output likelihoods with respect to input features, not generating identical text.
**Evidence anchors:**
- [abstract] "decouples reasoning from explanation: given a fixed output from a closed model, a smaller open-source surrogate computes token-level attributions from probability-based objectives... drastically reducing closed-model API calls."
- [section 3.4] Details the pipeline: `y = f_L(x)` is fixed; `f_S(x⊙z_j; y)` produces logits for regression targets `y_reg_j = KL(L_0 || L_j)`.
- [section 4.1] Reports that open-source RoPE-LIME (Qwen-8B) outperforms closed-source gSMILE (gpt-4o-mini) on MMLU attribution (e.g., IoU 0.364 vs 0.248), suggesting the surrogate can exceed the original method's quality without any closed-model calls during explanation.
- [corpus] Neighbors like "SAEMark" also use surrogates for watermarking, supporting the paradigm. However, direct evidence for this specific decoupling in attribution is primarily from the paper's own experiments.
**Break condition:** If the surrogate model `f_S` is misaligned (e.g., different architecture, tokenizer, or training data) such that its sensitivity to input perturbations does not correlate with `f_L`'s, attributions become unfaithful. The paper shows success with Qwen-8B vs gpt-4o-mini, but this may not generalize to all model pairs.

## Foundational Learning
- **Concept: Rotary Positional Embeddings (RoPE)**
  - **Why needed:** RoPE defines the embedding space where the locality kernel computes distance. Its rotational, relative-position nature is key to why polar aggregation (`¯r_k`, `¯θ_k`) and `polarL2` are used instead of Euclidean pooling.
  - **Quick check:** Explain why averaging token embeddings in Euclidean space would break under masking-induced index shifts, and how RoPE's phase aggregation preserves relative positional information.

- **Concept: Relaxed Word Mover's Distance (RWMD)**
  - **Why needed:** RWMD is the base distance metric, modified for token-level spans and RoPE space. It provides a semantically meaningful, quadratic-cost alternative to exact WMD, enabling the kernel's weighting of perturbations.
  - **Quick check:** What is the computational complexity difference between WMD and RWMD, and why is RWMD's simplification acceptable for attribution where exact optimal transport isn't critical?

- **Concept: Surrogate-based Local Explanation (LIME framework)**
  - **Why needed:** RoPE-LIME is a LIME variant. Core understanding: fitting a weighted linear surrogate on perturbed samples to approximate the local behavior of a complex model. The paper's innovation is in the kernel (RWMD+RoPE) and sampling (Sparse-K) within this framework, plus the decoupling.
  - **Quick check:** In standard LIME, what are the roles of the perturbation matrix `Z`, the kernel weights `w_j`, and the regression target? How does RoPE-LIME change the definition of the target and the kernel?

## Architecture Onboarding
- **Component map:**
  Input `x` with features `F_1..F_n` -> one-time closed-model query `f_L(x)` -> output `y` -> Sparse-K sampler generates masks `Z` -> for each mask `z_j`, surrogate `f_S(x⊙z_j; y)` produces logits `ℓ_j` -> compute `L_j = NLL(ℓ_j)`, `y_reg_j = KL(L_0 || L_j)` -> compute `d_j = RWMD_RoPE(x, x⊙z_j)`, `σ = median(d_j)`, `w_j = exp(-d_j²/σ²)` -> weighted linear regression `min_β ||W^{1/2}(y_reg - Zβ)||^2` -> coefficients `β` -> normalized absolute `a_i` as attributions.

- **Critical path:** `x, F` → (one-time `f_L`→ `y`) → (Sparse-K → `Z`) → (`f_S` + `y` → `L_j` → `y_reg`) → (RWMD_RoPE → `d_j` → `w_j` → `W`) → weighted regression → `a_i`.

- **Design tradeoffs:**
  - **Sparse-K parameters (`k`, `c`):** Higher `k` increases interaction coverage but risks losing locality; higher `c` increases budget for stability. Performance peaks around `k ≈ 2-4√M` and `c ≈ min(M, 16k)` or `0.5M`.
  - **Surrogate choice:** Smaller models are cheaper but may be less aligned; larger surrogates cost more but may better approximate `f_L`'s sensitivities.
  - **Kernel bandwidth (σ):** Median heuristic is standard but may be suboptimal if distance distribution is skewed.

- **Failure signatures:**
  1. High variance in `a_i` across different random seeds of Sparse-K: insufficient samples (`N` too small) or `k` poorly matched to feature dependence.
  2. Surrogate log-likelihoods `L_j` show erratic, non-smooth changes with `z_j`: `f_S` is untrustworthy or features are too coarse/fine for its tokenization.
  3. Kernel weights `w_j` all near-identical: `RWMD_RoPE` distances are too uniform (features semantically homogenous), making locality ineffective.
  4. Attributions concentrate on a few features across all examples: `k` too large or regression under-regularized.

- **First 3 experiments:**
  1. **Sanity check with synthetic data:** Create a prompt with known influential features. Verify RoPE-LIME attributes highly to that feature with small `M` and reasonable `N`. Compare against random attributions.
  2. **Sparse-K parameter sweep on a validation slice:** For fixed `M` (e.g., 8), sweep `k` and `c`. Plot IoU/F1 vs. `N`. Identify stable region, not just peak.
  3. **Surrogate sensitivity test:** Run attribution with two surrogate models of different sizes (e.g., Qwen-1.5B vs Qwen-8B). Compute correlation of `a_i` vectors. Low correlation indicates high sensitivity to surrogate choice.

## Open Questions the Paper Calls Out
- **Question 1:** How does the capacity and architecture of the open-source surrogate model affect the quality and reliability of RoPE-LIME attributions when explaining a closed-source model's outputs?
  - **Basis:** The method decouples reasoning and explanation by using a smaller open-source model as a surrogate, but the evaluation only varies the model type (Qwen-8B vs. gpt-4o-mini), not the surrogate's scale or architecture. This leaves open how sensitive attributions are to the surrogate's inherent capabilities.
  - **Why unresolved:** The surrogate's probability distribution directly shapes the regression targets. A mismatched or weak surrogate may misrepresent the closed model's behavior, but the paper provides no systematic study of this trade-off.
  - **What evidence would resolve it:** A comprehensive study comparing attributions obtained with surrogates of different sizes (e.g., 1B, 8B, 70B) and architectures (decoder-only, encoder-decoder) against a known ground truth, perhaps via human evaluation or an oracle model.

- **Question 2:** What is the theoretical foundation for the Sparse-K sampling strategy's sample budget \(N = c \log K\), and how can hyperparameters \(k\) (sparsity) and \(c\) (budget multiplier) be optimally set across different feature distributions?
  - **Basis:** The budget formula is introduced as a heuristic motivated by computational constraints, and the paper explicitly admits that "these choices are motivated by computational constraints, rather than theoretical optimality" (Appendix A.1). No generalization bounds or sample complexity analysis are provided.
  - **Why unresolved:** Without a theoretical model linking perturbation design, feature interactions, and attribution error, practitioners must rely on expensive sweeps. This limits the method's applicability to novel domains or extreme budget constraints.
  - **What evidence would resolve it:** A derivation of sample complexity bounds for LIME-style regression under sparse perturbations, showing how \(k\) and \(c\) should scale with the number of features \(M\), feature correlation structure, and desired confidence. Empirical validation would compare theoretical recommendations to results on diverse tasks.

- **Question 3:** Does computing the locality kernel in RoPE embedding space provide a statistically significant improvement in attribution stability compared to alternative positional encodings or simpler distance metrics (e.g., cosine similarity on token embeddings)?
  - **Basis:** The authors motivate RoPE by stating it "aligns with the model’s native attention mechanism" and yields "stable similarity under masking" (Section 3.1), but they do not compare against other kernels such as absolute-positional WMD or Euclidean distances.
  - **Why unresolved:** The claimed advantage remains unverified experimentally. The surrogate model may use a different positional encoding than the closed model, so the benefit of RoPE is not guaranteed. A direct ablation is necessary to confirm that the added complexity of polar L2 is warranted.
  - **What evidence would resolve it:** Controlled experiments isolating the kernel variable: keep the surrogate model, sampling, and regression fixed; evaluate RoPE-RWMD against alternatives like absolute-WMD, mean-pooled Euclidean, and cosine similarity on contextual embeddings across multiple datasets. Use paired statistical tests to compare attribution metrics (IoU, F1, AUROC).

- **Question 4:** How well does RoPE-LIME transfer to generative tasks beyond extractive question answering, such as abstractive summarization, machine translation, or multi-turn dialogue, where outputs are longer and the input-output relationship is less direct?
  - **Basis:** Evaluation is restricted to HotpotQA (sentence-level features) and a word-level MMLU subset, both short-answer QA tasks. The method has not been tested on tasks requiring free-form generation, longer outputs, or more complex reasoning patterns.
  - **Why unresolved:** The linear surrogate and probability-based targets assume a stable mapping from input perturbations to output token likelihoods. In generative tasks with diverse outputs or novel phrasing, this assumption may break, and the attribution quality could degrade. Scalability with output length is also unknown.
  - **What evidence would resolve it:** Apply RoPE-LIME to standard benchmarks for summarization (e.g., CNN/DailyMail), translation (e.g., WMT), and dialogue (e.g., MultiWOZ), using appropriate feature granularities. Compare against baselines (LOO, SHAP) using human-annotated rationales or internal model saliency (where possible). Measure accuracy, computational cost, and robustness to output length.

## Limitations
- Implementation specifics for multi-span RWMD aggregation and Sparse-K budget mapping from feature count `M` are underspecified, hindering faithful reproduction.
- The surrogate model's ability to faithfully mimic the closed model's input sensitivity is not theoretically guaranteed; results shown only for Qwen-8B vs gpt-4o-mini may not generalize.
- Regression target definition (KL between scalar NLLs) is ambiguous; likely intended as KL between token probability distributions, but details are missing.
