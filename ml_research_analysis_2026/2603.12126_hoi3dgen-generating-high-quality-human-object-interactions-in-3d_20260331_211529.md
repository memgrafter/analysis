# Hoi3DGen: Generating High-Quality Human-Object-Interactions in 3D

## Quick Facts
- **arXiv ID:** 2603.12126
- **Source URL:** https://arxiv.org/abs/2603.12126
- **Reference count:** 40
- **Primary result:** Surpasses baselines by 4-15x in text consistency (GPT score 0.81) and 3-7x in 3D model quality; achieves 90% contact accuracy.

## Executive Summary
Hoi3DGen tackles the challenge of generating high-quality 3D human-object interactions (HOI) from text. It first automatically curates detailed interaction captions by decomposing the task into appearance, action, and contact subtasks using multimodal LLMs. Then it fine-tunes a view-conditioned SANA model on this data for 2D image generation, lifts images to textured 3D meshes via Hunyuan3D, segments them with GSAM2, and registers SMPL models for semantic contacts. The framework significantly outperforms prior work in text fidelity and geometric accuracy, demonstrating strong generalization across diverse interactions.

## Method Summary
The pipeline consists of three stages:

1. **Data curation:** From the ProciGen dataset, select 750k HOI meshes. For each mesh, render four orthogonal views. Use InternVL to label human appearance (clothing, hair, footwear), object attributes, and interaction type (from a predefined list). Compute contact body parts via geometric distance (<4 cm). Fuse all labels with LLaMA 3.1 into a natural caption. Filter for clean contacts, no interpenetration, and action-contact consistency to obtain 400 high-quality samples.

2. **Fine-tuning:** Train a view-conditioned SANA diffusion model on the curated set. For each sample, append a view token (front, left diagonal, right diagonal) to the caption. Use standard diffusion loss; training uses 4× H100 GPUs for ~24 h, batch size 16, resolution 1024×1024. Optionally retexturize generated images with Flux at inference.

3. **Inference pipeline:** Given a text prompt, generate three images with the three view conditions. Lift each image to a textured 3D mesh using Hunyuan3D (geometry and texture networks). For each mesh, render a 120‑view spherical trajectory and apply GSAM2 with prompts “person” and the object category to obtain temporally consistent masks. Perform per‑vertex majority voting to split the mesh into human (Hm) and object (O). Use CameraHMR on the front‑view render to obtain a full SMPL mesh (Hs). Align Hs to Hm via a 7‑DoF (scale, translation, rotation) Chamfer optimization, optionally masking SMPL vertices with the front‑view human mask for robustness. Select the view/mesh with the best contact quality as the final output: a segmented human mesh, an object mesh, and an aligned animatable SMPL model.

## Key Results
- GPT score of 0.81 for text‑to‑3D consistency, surpassing baselines by 4–15×.
- 90% contact accuracy on generated HOI meshes.
- 91.09% user preference for text fidelity over prior methods.
- 3–7× improvement in 3D model quality relative to TRELLIS and InterFusion.

## Why This Works (Mechanism)

### Mechanism 1: Decomposed Multimodal Annotation for High-Quality Captions
- **Claim:** Decomposing caption generation into appearance, action, and contact sub‑tasks using multimodal LLMs yields detailed, consistent training data for HOI generation.
- **Mechanism:** Render 4 orthogonal views of a 3D HOI mesh. Use InternVL to label human clothing/hairstyle/footwear and object attributes/color. Use InternVL with a constrained action list to label interaction type. Compute geometric contacts (<4 cm) to identify body parts. Fuse all labels with LLaMA 3.1 into a natural caption. Filter for clean contacts, no interpenetration, and action‑contact consistency to select 400 diverse samples.
- **Core assumption:** Multimodal LLMs can reliably perform these sub‑tasks with structured prompts and renderings; a small curated set suffices to fine‑tune a generative model without forgetting.
- **Evidence anchors:** [abstract] mentions decomposition; [section 3.1] details the process; neighbors like InterDiff and InterDreamer use different data strategies, highlighting novelty.
- **Break condition:** If any sub‑task fails (e.g., hallucination, contact mis‑identification, unnatural fusion), the fine‑tuning signal becomes noisy, limiting interaction fidelity.

### Mechanism 2: View‑Conditioned Fine‑Tuning for Stable 2D Interaction Generation
- **Claim:** Conditioning a pre‑trained text‑to‑image model (SANA) on camera view (front/left/right diagonal) during fine‑tuning produces 2D images with visible contacts that lift reliably to 3D.
- **Mechanism:** Append a view token to the interaction prompt. Fine‑tune SANA with standard diffusion loss on the curated 400 (text, multi‑view) pairs. At inference, sample 3 views per prompt. Use Hunyuan3D to lift each image to a 3D mesh; select the mesh with the most accurate contacts.
- **Core assumption:** A pre‑trained model retains general human/object knowledge; fine‑tuning on a small focused set adjusts its representation to compose interactions correctly without losing diversity. View conditioning prevents occlusion of contact regions, which is essential for faithful image‑to‑3D reconstruction.
- **Evidence anchors:** [section 3.2] describes the approach; [section 4.4, Table 4] shows contact accuracy rises from ~79% (single view) to >90% with 3‑view conditioning.
- **Break condition:** If view descriptions are ignored or the curated data overfits to specific views/contacts, generated images may still have occlusions, leading to poor 3D lifting (Janus artifacts, missing parts).

### Mechanism 3: Semantic Segmentation and SMPL Registration for Animatable Output
- **Claim:** Multi‑view video segmentation (GSAM2) and robust partial SMPL alignment enable segmentation of a monolithic mesh into human/object parts and registration of an animatable SMPL model, even for incomplete generated humans.
- **Mechanism:** Render the combined 3D mesh on a smooth spherical trajectory (120 views). Run GSAM2 with prompts “person” and object category to get temporally consistent 2D masks. Perform per‑vertex majority voting across visible views to split the mesh. Register SMPL: use CameraHMR on a front view to get a full SMPL mesh, then align it to the segmented human mesh via a 7‑DoF Chamfer optimization. If the human mesh is partial, mask SMPL vertices using the GSAM2 front‑view human mask before alignment.
- **Core assumption:** Multi‑view video segmentation with majority voting can reliably separate a monolithic mesh into semantic parts despite self‑occlusion. Partial SMPL alignment (masking to visible regions) makes registration robust to incomplete generated humans, which full‑body methods fail on.
- **Evidence anchors:** [section 3.3] details the pipeline; [supplementary Sec 7.2] explains partial masking; [section 4.4] comparison with ETCH shows lower alignment error (1.60 cm vs. 4.30 cm).
- **Break condition:** If GSAM2 segmentation fails (poor rendering quality, category mismatch) vertex voting yields incorrect splits. If the generated human is extremely incomplete (e.g., only hands visible), masked SMPL has no correspondence, alignment fails, and contact computation becomes invalid.

## Foundational Learning
- **Multimodal LLM (e.g., InternVL) for structured scene annotation.**  
  *Why needed:* To automatically generate detailed, consistent captions for 3D HOI data by decomposing a complex task into simpler vision‑language sub‑tasks (attribute labeling, action selection, contact reasoning).  
  *Quick check:* How would you design the prompt for InternVL to minimize hallucination when describing the interaction type from a set of possible actions?

- **View‑conditioned diffusion for 3D‑stable generation.**  
  *Why needed:* To ensure the 2D image used for lifting contains an unobstructed view of the human‑object contact region, avoiding occlusions that cause Janus problems or missing parts in the 3D mesh.  
  *Quick check:* Why is generating a single random view insufficient for reliable 3D contact reconstruction, even if the 2D image looks plausible?

- **Image‑to‑3D lifting (e.g., Hunyuan3D) and its failure modes.**  
  *Why needed:* The final 3D mesh is obtained by lifting a generated 2D image; understanding that this step is sensitive to completeness and multi‑view consistency is crucial for the overall pipeline design.  
  *Quick check:* Given a 2D image where the object is partially behind the human, what specific artifact might the image‑to‑3D model produce?

- **SMPL model and semantic contact evaluation.**  
  *Why needed:* The framework outputs an aligned SMPL model to provide animatable semantics and a standardized way to evaluate contact accuracy via point‑to‑mesh distance thresholds.  
  *Quick check:* How do you compute “contact accuracy” for a generated HOI using the registered SMPL and object mesh?

## Architecture Onboarding

### Component Map (high‑level modules)
Data Curation Module → 2D Generation Module → 3D Lifting Module → Semantic Processing Module → Registration Module

### Critical Path
During inference, the flow is: text prompt → view‑conditioned SANA generates 3 images → each image lifted to 3D mesh via Hunyuan3D → best mesh selected via contact quality → multi‑view segmentation (GSAM2 + vertex voting) splits mesh → SMPL registration (CameraHMR + alignment) produces final animatable HOI pair.

### Design Tradeoffs
- **Data filtering vs. diversity:** Filtering 750k ProciGen pairs to 400 ensures quality but risks limited generalization to unseen contact patterns or object categories. Mitigation: filters based on geometric plausibility (no interpenetration) and semantic consistency (action‑contact match), not visual style.
- **View conditioning vs. inference cost:** Generating 3 views per prompt improves stability but triples lifting computations. Tradeoff: Could use a learned confidence predictor to stop early if a good view is found, or reduce to 2 views with minor accuracy drop.
- **Re‑texturing vs. texture fidelity:** Using Flux to retexture Hunyuan3D outputs improves GPT scores but may alter fine details. It is a non‑gradient post‑processing fix for texture quality.

### Failure Signatures
- **Janus artifacts / multi‑faced meshes:** Indicates Hunyuan3D failure due to occluded contact region in the 2D input. Sign: multiple faces or symmetric body parts.
- **Incomplete human mesh:** Human mesh missing limbs/torso. Sign: SMPL registration produces high Chamfer error (>4 cm). Cause: SANA generated partial human; GSAM2 segmentation also fails.
- **Incorrect contact segmentation:** Contact accuracy <70%. Sign: SMPL‑object distance threshold not met for claimed body parts. Causes: 1) view‑conditioning failed (wrong view selected), 2) GSAM2 mis‑segmented parts, 3) contact threshold mismatch.
- **Poor texture quality:** Blurry, nonsensical textures. Sign: high CLIP similarity but low GPT score for text consistency. Mitigation: Re‑texturing step.

### First 3 Experiments
1. **Validate data curation:** Manually inspect 100 generated captions and renderings. Metrics: % with correct action‑contact match; % with plausible appearance descriptions. Target: >95% plausible.
2. **Ablate view conditioning:** For 50 held‑out prompts, generate 1, 2, 3 conditioned views. Lift all to 3D. Measure contact accuracy. Expected: 3 views >90%, 1 view ~78%. Confirms Table 4.
3. **Test SMPL registration robustness:** Take 20 generated HOI meshes with challenging poses (sitting, bending, kneeling). Compute one‑directional Chamfer distance from segmented human mesh to registered SMPL. Target: <2.0 cm average. Compare against ETCH if available.

## Open Questions the Paper Calls Out
The paper does not explicitly discuss open questions or future work. However, based on the limitations identified, several open questions arise:
- How can the data curation process be scaled to larger numbers of samples without compromising quality, given the current filtering yields only 400 samples?
- Can the pipeline be adapted to use open-source image-to-3D models to improve reproducibility and allow deeper failure analysis?
- What are the specific failure modes of the lifting model (Hunyuan3D) for HOI scenes, and how can they be systematically addressed?
- How robust is the SMPL registration when the generated human mesh is extremely incomplete (e.g., only hands visible)? Are there alternative alignment strategies?

## Limitations
- Automatic captioning without human validation may propagate noise into the small curated set (400 samples), limiting generalization.
- Fine‑tuning on such a small dataset risks catastrophic forgetting or overfitting to a narrow distribution.
- Final 3D quality is bottlenecked by Hunyuan3D’s ability to lift from a single 2D image; failure modes (Janus artifacts, missing parts) are not deeply analyzed.
- Dependence on proprietary models (Hunyuan3D, Flux) hinders reproducibility and detailed failure analysis.

## Confidence
- Decomposed multimodal annotation: Medium
- View‑conditioned 2D generation: High
- Semantic segmentation & SMPL registration: Medium‑High
- Overall pipeline superiority: Medium

## Next Checks
1. **Caption fidelity audit:** Manually inspect 100 randomly sampled curated (text, multi‑view image) pairs. Quantify rates of action‑contact semantic mismatch and appearance hallucination. Target >95% plausible.
2. **Diversity stress test:** Generate HOI outputs for 50 prompts with unseen combinations (novel objects, actions, human appearances). Measure failure rate (missing limbs, incorrect contact, object failure). Probe overfitting.
3. **Lifting artifact quantification:** For the 3 generated views per prompt, lift each with Hunyuan3D without selection. Catalog failure modes: Janus faces, non‑manifold edges, missing contacts. Correlate with 2D image quality metrics (CLIP similarity to prompt, visible contact area). Isolate the lifting bottleneck.
