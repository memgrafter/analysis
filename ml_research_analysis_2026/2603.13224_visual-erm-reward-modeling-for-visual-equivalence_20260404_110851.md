# Visual-ERM: Reward Modeling for Visual Equivalence

## Quick Facts
- arXiv ID: 2603.13224
- Source URL: https://arxiv.org/abs/2603.13224
- Reference count: 40
- Primary result: Visual-ERM introduces a multimodal generative reward model for visual equivalence, improving vision-to-code generation across tasks (e.g., +8.4 points on ChartMimic) and test-time reflection, outperforming larger models.

## Executive Summary
Vision-to-code generation requires high visual fidelity when rendering code outputs, but existing reward signals (text-based metrics or coarse vision embeddings) often miss fine-grained discrepancies and can be gamed. Visual-ERM addresses these issues by introducing a multimodal generative reward model that directly compares the original and rendered images, producing structured error annotations (category, location, severity). Trained on a curated dataset of over 340,000 image pairs with distilled discrepancy labels, Visual-ERM serves as a unified supervisor for reinforcement learning (GRPO) and test-time scaling. On ChartMimic, it improves the base Qwen3-VL-8B-Instruct model by +8.4 points overall, significantly surpassing DINO-based rewards. Consistent improvements are seen on table parsing (+2.7) and SVG generation (+4.1). Moreover, on VC-RewardBench, Visual-ERM (8B) outperforms Qwen3-VL-235B-Instruct by +36.8 F1-hard and rivals proprietary models, highlighting the power of fine-grained visual supervision. The same feedback mechanism also enhances test-time reflection, yielding an additional +3.1 gain on charts.

## Method Summary
Visual-ERM is a reward model built upon a multimodal LLM (Qwen3-VL-8B) and fine-tuned via supervised learning to predict fine-grained discrepancies between a ground-truth image and a rendered output from generated code. The training data is created by first corrupting ground-truth visual outputs (charts, tables, SVGs) using a strong LVLM to induce realistic errors, then rendering the corrupted code, and finally annotating the image pairs with GPT-5-mini or a similar model to produce structured error lists (category, location, severity, description). This yields 104k chart, 125k table, and 111k SVG instances.

At inference, Visual-ERM processes the image pair and outputs a JSON-like structure of errors. The reward score is computed as `r = clip(1 - S_verm / max_task_S, 0, 1) + r_rsr`, where `S_verm` is the sum of severity scores, `max_task_S` is a task-specific normalization constant, and `r_rsr` is a binary render-success indicator (1 if rendering succeeded, else 0). This dense, normalized reward avoids sparsity and provides interpretable feedback.

For policy optimization, the reward is used in the GRPO algorithm to update a base model (e.g., Qwen3-VL-8B-Instruct) with a KL penalty towards the reference policy. At test time, the same Visual-ERM feedback can be fed back to the policy for iterative refinement (test-time scaling), allowing the model to revise its output based on the pointed errors without additional training.

## Key Results
- ChartMimic: Overall improvement of +8.4 points over base Qwen3-VL-8B-Instruct, significantly outperforming DINO-based rewards.
- Table parsing (OmniDocBench): +2.7 points gain.
- SVG generation (UniSVG): +4.1 points gain.
- VC-RewardBench (hard F1): Visual-ERM (8B) exceeds Qwen3-VL-235B-Instruct by +36.8 and approaches proprietary models.
- Test-time reflection on charts: Additional +3.1 improvement beyond RL.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Visual-ERM provides fine-grained, interpretable visual supervision that captures pixel- and layout-level discrepancies missed by text-based or coarse embedding rewards.
- **Mechanism:** It jointly processes the original and rendered image pair in a unified multimodal space, generating structured error annotations (category, location, severity) rather than a single scalar. This decomposes the reward into actionable dimensions (structure, data, text, style) that align with human evaluation of visual fidelity.
- **Core assumption:** Direct visual-space comparison, grounded in rendered outputs, is necessary and sufficient for accurate vision-to-code supervision because text metrics ignore layout/color/alignment and embedding similarity is semantically biased.
- **Evidence anchors:**
  - [abstract] "Visual-ERM addresses this by introducing a multimodal generative reward model that directly compares the original and rendered images, producing fine-grained, interpretable feedback."
  - [section 1] "Text-based metrics ... fail to capture fine-grained visual discrepancies ... vision-encoder rewards (e.g., DINO) are coarse-grained and semantically-biased."
  - [corpus] Neighbors like ViGoR and RewardMap focus on fine-grained reward modeling, supporting the principle that granular feedback improves alignment, but do not directly address vision-to-code visual equivalence.
- **Break condition:** If the rendering pipeline introduces non-deterministic artifacts or if the reward model's generative head becomes biased toward certain error types during training, the fine-grained feedback may misalign with true visual fidelity.

### Mechanism 2
- **Claim:** Multi-task training on chart, table, and SVG data yields a generalizable reward model that transfers cross-domain error patterns (e.g., layout, text recognition) without negative transfer.
- **Mechanism:** Shared visual reasoning backbones (e.g., Qwen3-VL) learn common failure modes across structured visuals (misalignment, OCR errors, shape distortions). Joint optimization forces the model to abstract task-agnostic discrepancy detection skills, improving robustness on each individual task.
- **Core assumption:** Error taxonomies across tasks overlap sufficiently (e.g., `text_error` in tables and charts) that knowledge distills across domains, and that catastrophic interference is avoided by balanced data mixing.
- **Evidence anchors:**
  - [section B.2.1] Mixing chart, table, and SVG data yields best average VC-RewardBench performance; single-task models show strong task bias and poor cross-task generalization.
  - [section B.2.2] Mixed-data RM improves RL gains on Table-to-Markdown beyond a table-only RM.
  - [corpus] StructVRM proposes structured reward models for multimodal reasoning, aligning with the idea of decomposable, cross-modal supervision, but does not evaluate multi-task transfer.
- **Break condition:** If tasks exhibit conflicting optimal representations (e.g., SVG geometry vs. table layout), joint training could induce negative transfer, degrading performance on one or more tasks.

### Mechanism 3
- **Claim:** Visual-ERM's structured output (error list with severity) enables stable RL optimization via GRPO and effective test-time scaling (TTS) through iterative reflection and revision.
- **Mechanism:** The error decomposition allows reward shaping: total severity sum is normalized and clipped to a [0,1] reward, providing dense signals that avoid the binary sparsity of execution-only rewards. For TTS, the free-form descriptions condition the policy to revise specific failure modes.
- **Core assumption:** A well-calibrated severity score correlates with overall visual fidelity, and providing the policy with the raw error descriptions (not just the scalar) is sufficient to guide correction without external tools.
- **Evidence anchors:**
  - [section 3.2.1] Reward design: `r_verm = clip(1 - normalized_severity_sum, 0, 1)` plus render-success reward.
  - [section 4.4] TTS with Visual-ERM feedback yields +8.0 gain over base model and +3.1 over RL-only model on charts; similar gains on SVG.
  - [corpus] RewardMap uses multi-stage RL for fine-grained reasoning, supporting the decomposition principle, but does not integrate generative feedback into TTS.
- **Break condition:** If severity scores are poorly calibrated (e.g., under-penalizing critical structure errors), RL may optimize the wrong objective; if error descriptions are incomplete or hallucinated, TTS revision could degrade outputs.

## Foundational Learning
### Concept: Multimodal Generative Reward Modeling
- **Why needed here:** Vision-to-code tasks require judging rendered image fidelity, which demands cross-modal alignment between text (code) and visual pixels. Conventional scalar RMs do not output interpretable diagnostics.
- **Quick check question:** How does training a reward model to generate structured error annotations (vs. predicting a scalar) improve its utility for RL and test-time scaling?

### Concept: Reinforcement Learning from Visual Feedback (RLVF)
- **Why needed here:** Standard RL for code generation uses execution success or text similarity; here the reward comes from a visual judge (Visual-ERM) that evaluates the rendered output, forming a closed loop between code generation and visual assessment.
- **Quick check question:** What are the key differences between using a DINO-based similarity reward and a generative visual equivalence reward in terms of hackability and gradient informativeness?

### Concept: Test-Time Scaling with Iterative Refinement
- **Why needed here:** The same reward model used in RL can provide feedback at inference to enable self-correction, leveraging its fine-grained output to guide multiple revision rounds without additional training.
- **Quick check question:** Why might a generative RM (producing error descriptions) be more suitable for TTS than a scalar RM?

## Architecture Onboarding
### Component map
Render Engine -> Visual-ERM -> Reward Scorer -> RL Trainer (GRPO) ; TTS Loop: Policy + Visual-ERM feedback
### Critical path
Data construction → Visual-ERM SFT → RL/TTS integration.
### Design tradeoffs
- Fine-grained vs. scalar reward: JSON output provides interpretability and TTS utility but requires parsing and normalization for RL; scalar-only would be simpler but less informative.
- Multi-task vs. specialized RM: Single multi-task RM reduces deployment complexity but risks cross-task interference; specialized RMs may be higher fidelity per task.
- Generative judge vs. discriminative: Generative (text output) enables natural language feedback for TTS but is slower and more variable than a classification head; discriminative (pairwise ranking) could be more stable but less expressive.
### Failure signatures
- Reward hacking: Model learns to tweak non-critical style features to minimize severity sum while preserving data errors (if severity calibration is off).
- Render failures: Many outputs fail to render (`r_rsr=0`), causing sparse rewards; requires carefully balancing `r_rsr` and `r_verm`.
- Error description hallucination: Visual-ERM reports errors where none exist (false positives), leading TTS to "fix" correct outputs incorrectly.
- Task conflating: Multi-task RM confuses chart axes with table headers, leading to incorrect category assignments.
### First 3 experiments
1. Sanity check reward model: Run Visual-ERM on a small set of known matching and mismatching image pairs (from VC-RewardBench). Verify that severity sums correlate with human judgment and that error categories align with expected failure modes.
2. Single-task RL ablation: Apply Visual-ERM-guided RL to Chart-to-Code only. Compare against DINO-based RL and text-based (TEDS) RL on ChartMimic to confirm the +8.4 overall gain is reproducible and not due to random initialization.
3. TTS zero-shot test: Without any RL, take the base Qwen3-VL-8B-Instruct and run 3-round reflection with Visual-ERM on ChartMimic. Measure if standalone TTS yields a meaningful gain over base (expect ~+8.0 as in paper). This isolates the value of the feedback loop from RL optimization.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Is fine-grained visual supervision via a reward model *sufficient* for all vision-to-code reinforcement learning, or are there task-specific failure modes where it remains inadequate?
- **Basis in paper:** [explicit] The conclusion states Visual-ERM's supervision is "both necessary and sufficient for vision-to-code RL, regardless of task specificity."
- **Why unresolved:** The claim is based on three tasks (charts, tables, SVGs); no counterexamples or boundary conditions are explored. Tasks with different visual priors (e.g., 3D renderings, complex layouts) may require additional supervision signals.
- **What evidence would resolve it:** Systematically evaluate Visual-ERM-guided RL on a diverse set of vision-to-code tasks beyond the three studied, particularly those with abstract or non-standard visual grammars. Identify any tasks where performance does not improve or degrades despite Visual-ERM rewards, and analyze whether the failures stem from the reward model's perception limitations or from inherent task characteristics (e.g., ambiguity in ground-truth rendering).

### Open Question 2
- **Question:** To what extent can Visual-ERM's multi-task training on chart, table, and SVG data transfer to *unseen* structured visual domains (e.g., flowcharts, UI mockups, scientific diagrams) without further fine-tuning?
- **Basis in paper:** [explicit] Section B.2 shows multi-task mixing yields a more generalizable reward model on the evaluated tasks. No explicit test on held-out domains.
- **Why unresolved:** The cross-task transfer observed is within a cluster of "structured tabular/graphic" data. Generalization to domains with different visual primitives (e.g., nodes/edges in flowcharts) is not assessed. The paper does not define the scope of "task-agnostic" beyond the three tasks.
- **What evidence would resolve it:** Evaluate a Visual-ERM trained only on chart/table/SVG data on a new held-out domain (e.g., a flowchart-to-code benchmark). Measure both reward discrimination quality (via a domain-specific VC-RewardBench variant) and downstream RL performance when using the same reward model without adaptation.

### Open Question 3
- **Question:** Is GRPO the optimal RL algorithm for vision-to-code when using a fine-grained generative reward model like Visual-ERM, or would other objectives (e.g., DPO, KTO) yield better efficiency or final performance?
- **Basis in paper:** [inferred] The RL experiments exclusively use GRPO. The design of the reward (sum of severity scores normalized per task) is tailored to that framework. No comparison to other RL or preference-based methods is provided.
- **Why unresolved:** GRPO was chosen for stability and sample efficiency, but the unique structure of Visual-ERM's output (a list of errors with severities) might be better exploited by a different optimization scheme that directly consumes the structured feedback, rather than collapsing it into a single scalar. The paper does not justify the algorithmic choice beyond convention.
- **What evidence would resolve it:** Implement alternative RLHF/DPO pipelines that use Visual-ERM's structured output (e.g., by treating each error as a negative preference or using the error list for a more fine-grained advantage calculation). Compare sample efficiency, final accuracy, and training stability against GRPO on the same tasks and model backbones.

### Open Question 4
- **Question:** What is the scalability limit of Visual-ERM's architecture (Qwen3-VL-8B) in capturing ultra-fine-grained discrepancies (e.g., sub-pixel rendering differences, anti-aliasing artifacts) and does increasing model scale systematically improve reward fidelity?
- **Basis in paper:** [explicit] Visual-ERM is built on an 8B parameter model and outperforms a 235B model on VC-RewardBench. However, the benchmark's hardest examples (𝐹1 ℎ) still only reach ~40% for Visual-ERM.
- **Why unresolved:** The paper demonstrates that targeted training outperforms scale for this task, but it does not explore a spectrum of model sizes. The remaining 60% hard errors suggest either dataset limitations or capability ceilings. It is unclear whether a larger, more capable base model with the same training recipe would close this gap, or if the bottleneck is data (annotations of subtle discrepancies) rather than model size.
- **What evidence would resolve it:** Train Visual-ERM models of varying scales (e.g., 2B, 8B, 70B) on the identical reward-modeling dataset. Evaluate them on the hardest subset of VC-RewardBench (low 𝐹1 ℎ) and on a manually curated set of "extremely subtle" discrepancies. Analyze scaling curves for error detection accuracy and whether larger models better distinguish true visual equivalence from imperceptible differences.

### Open Question 5
- **Question:** Does Visual-ERM's feedback引入 (introduce) any subtle biases during RL that harm *general multimodal understanding* on non-code tasks, and can these be mitigated?
- **Basis in paper:** [explicit] Appendix B.1 evaluates on chart/document VQA benchmarks and finds no significant degradation. However, the tested benchmarks are closely related to the training domains.
- **Why unresolved:** The VQA benchmarks (ChartQA, DocVQA) still involve structured visuals similar to charts/tables. The paper does not test on *diverse* multimodal tasks (e.g., natural scene understanding, complex reasoning, open-domain VQA). The RL optimization objective is narrowly tied to rendering fidelity, which could inadvertently distort the model's internal representations for other types of visual-text alignment.
- **What evidence would resolve it:** Run a broader evaluation suite (e.g., MMBench, MME, SEED-Bench) on RL-trained policies. Perform a deeper analysis of embedding spaces (e.g., linear probing on frozen features for other VQA tasks) to detect any representation drift. If negative transfer exists, experiment with auxiliary losses or constrained RL updates to preserve prior multimodal capabilities.

## Limitations
- Data availability/quality: The exact composition and construction pipeline of the 340K+ reward training dataset remain unreleased; dependence on proprietary models (GPT-5-mini) for annotation distillation limits faithful replication.
- Evaluation stability: VC-RewardBench relies on LLM-as-judge with unspecified configurations; score variability and consistency across different judges or seeds are unclear.
- Failure mode understanding: While reward hacking and task interference are noted as risks, the paper lacks systematic stress tests quantifying how often these occur in practice or their impact on end-task performance.

## Confidence
- Fine-grained visual supervision mechanism: High
- Multi-task transferability: Medium
- Scalability via TTS & RL: Low to Medium

## Next Checks
1. Independent reward model replication: Re-train Visual-ERM using an alternative data construction pipeline (e.g., error injection via open-source LVLMs like LLaVA-NeXT, human-verified subsets) and compare VC-RewardBench scores to assess robustness to annotation source.
2. Adversarial reward hacking analysis: Generate outputs optimized to minimize Visual-ERM severity while maximally diverging from ground-truth (e.g., via gradient-based attacks on the renderer or policy). Quantify correlation between Visual-ERM scores and human judgments in these failure cases.
3. Cross-dataset RL generalization: Apply Visual-ERM-guided RL trained on ChartMimic to out-of-distribution chart datasets (e.g., PlotQA, ChartQA) without further tuning. Measure drop in performance to evaluate overfitting versus true visual reasoning transfer.
