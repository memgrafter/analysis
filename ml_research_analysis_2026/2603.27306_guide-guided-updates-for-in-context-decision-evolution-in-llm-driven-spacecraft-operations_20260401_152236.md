# GUIDE: Guided Updates for In-context Decision Evolution in LLM-Driven Spacecraft Operations

## Quick Facts
- **arXiv ID:** 2603.27306  
- **Source URL:** https://arxiv.org/abs/2603.27306  
- **Reference count:** 23  
- **Primary result:** Achieves 82–99% composite score reduction vs. static LLM baseline by evolving state‑conditioned playbooks without model weight updates.

## Executive Summary
GUIDE addresses the inability of static LLM prompts to improve across repeated executions in spacecraft supervisory roles. It introduces a framework where a fixed‑capacity acting model executes real‑time control using a state‑conditioned playbook of natural‑language decision rules, while an offline reflector analyzes prior trajectories and proposes rule modifications. Multiple playbook versions are maintained and selected via an Upper Confidence Bound (UCB) algorithm to balance exploration and exploitation. Evaluated on adversarial orbital interception tasks (LBG scenarios in KSPDG), GUIDE’s evolved versions drastically outperform both static LLM and classical baselines, demonstrating that structured in‑context evolution serves as an effective policy search mechanism for closed‑loop dynamical systems.

## Method Summary
GUIDE employs a two‑model, decoupled architecture. An online **acting model** (resource‑constrained LLM) generates control actions within strict latency bounds by conditioning on a filtered subset of the current **playbook**—a set of state‑tagged natural‑language rules. Between episode batches, an offline **reflector** (frontier LLM) analyzes selected trajectories (via ϵ‑biased sampling) and suggests rule edits (add/update/remove). A **curator** transforms these proposals into structured operations, spawning a new playbook version. A **UCB selector** then chooses which version the acting model uses next, based on historical composite scores. This separation allows continuous policy improvement without altering the acting model’s weights, treating the evolving playbook as the primary locus of learning.

## Key Results
- **LG4:** Composite score reduced from 4.15e5 to 7.22e4 (82.6% improvement).  
- **LG6:** From 2.28e7 to 5.07e4 (99.8% improvement).  
- **LG7:** From 1.95e7 to 3.49e4 (99.8% improvement).  
Improvements stem from learned guard‑avoidance and approach‑braking rules that reduce lady‑bandit distance while increasing guard separation.

## Why This Works (Mechanism)

### Mechanism 1: Playbook as the Policy Locus
**Claim:** Cross‑episode performance improvement arises from iteratively refining a state‑conditioned playbook of natural‑language rules, without updating the acting model’s weights.  
**Mechanism:** The offline reflector analyzes failure/success trajectories and proposes corrections; the curator formalizes these into structured playbook bullets with symbolic conditions. The fixed acting model then conditions its decisions on the active subset of bullets, effectively executing a modified policy π(a|s, P).  
**Core assumption:** A fixed‑capacity LLM can sufficiently differentiate and act upon distinct, state‑tagged behavioral rules provided in‑context.  
**Evidence anchors:** [abstract] "evolving a state‑conditioned playbook... without weight updates"; [section 3.2] "The learned object... is the evolving playbook P."  
**Break condition:** If the reflector/curator pipeline generates syntactically invalid or semantically incoherent rules, or if the acting model’s context window cannot effectively discriminate a complex rule set, evolution degrades.

### Mechanism 2: Decoupled Online/Offline Processing
**Claim:** Real‑time closed‑loop control is decoupled from episodic reflection, satisfying latency constraints while enabling adaptation.  
**Mechanism:** A lightweight, bounded‑reasoning acting model executes within control‑cycle deadlines using the current playbook. Separately, a frontier reflector performs deep analysis of completed trajectories between episode batches, proposing updates. This teacher‑student separation prevents online deliberation from violating real‑time dynamics.  
**Core assumption:** High‑level, state‑conditioned rules can be reliably executed within a short token budget, and the reflector can correctly identify necessary modifications from telemetry and reasoning traces.  
**Evidence anchors:** [section 1] "control actions must be generated within strict latency bounds... learning must be separated"; [section 3.3] "bounded reasoning agent... This separation bounds reasoning latency."  
**Break condition:** If the acting model’s bounded reasoning cannot integrate active bullets into a coherent intent, or if the reflector misattributes failure causes, updates worsen performance.

### Mechanism 3: UCB‑Driven Version Selection
**Claim:** Maintaining and selecting among multiple playbook versions via UCB1 balances exploitation of known good rules with exploration of new combinations, preventing premature convergence.  
**Mechanism:** After reflection, a new playbook version Pₖ is created. All versions are scored over episodes. UCB1: scoreₖ + c√(log(N)/nₖ) selects the next version, encouraging evaluation of less‑tried versions even if their average score is slightly worse.  
**Core assumption:** The composite score S is a stable, informative metric, and noise in its estimation can be managed by the UCB bonus.  
**Evidence anchors:** [section 3.4] "Selection among playbooks uses an Upper Confidence Bound (UCB1) rule"; [section 4, Fig. 2] Shows performance evolution across versions.  
**Break condition:** If S is excessively noisy or multi‑modal, UCB could repeatedly select poor new versions; poor tuning of c could cause too much or too little exploration.

## Foundational Learning
- **In‑Context Learning (ICL):** GUIDE’s acting model learns entirely via context; its behavior is determined by the evolving playbook P. Understanding that LLMs modify output distribution based on structured context is fundamental.  
  *Quick check:* If a new, contradictory rule activates in a state where an old rule also activates, order and specificity determine which dominates—introducing non‑trivial compositionality challenges.
- **Closed‑Loop Dynamical Systems with Delayed Consequences:** Spacecraft control involves irreversible, delayed effects. A rule like "pursue the lady" can lead to guard capture if it causes entry into a dangerous region. The playbook must encode state‑conditioned trade‑offs.  
  *Quick check:* Why is "always avoid the guard" insufficient? It may prevent capture but also prevent interception, failing the primary objective; conditional rules are necessary.
- **Non‑Parametric Policy Search:** GUIDE treats the structured playbook P as the policy parameterization. "Search" occurs over rule‑sets via reflection/curation and UCB selection, not gradient descent, framing the problem as memory/context optimization.  
  *Quick check:* How does GUIDE’s search differ from RL? Policy representation is discrete symbolic rules; updates are symbolic edits proposed by an LLM, not gradient steps on a value function.

## Architecture Onboarding
**Component Map:**  
Acting Model → (uses) Playbook Store → Action output  
Reflector → Curator → New Playbook Version → UCB Selector → Acting Model  
Metrics Calculator → UCB Selector

**Critical Path:**  
1. *Online:* Acting model receives current state → filters active bullets from current playbook → generates action → environment steps → trajectory recorded.  
2. *Offline (after B episodes):* ϵ‑selector picks trajectory windows → Reflector analyzes → Curator creates P_new → UCB Selector evaluates all versions → P_current ← argmax(UCB).

**Design Tradeoffs:**  
- **Token budget vs. expressiveness:** Bounded reasoning limit (e.g., 128 tokens) constrains number of active bullets that can be integrated; verbose rules risk truncation.  
- **Rule granularity:** Fine‑grained rules are precise but brittle; coarse rules are robust but may miss nuances. Evidence blocks aim to ground rules in failure cases.  
- **Separation of concerns:** Online/offline split is rigid; any online latency violation is fatal. Cannot adapt within an episode.

**Failure Signatures:**  
- **Degradation after update:** Composite score worsens immediately after new Pₖ selected → indicates malformed rule (incorrect condition/contradiction).  
- **UCB stagnation:** Same 1–2 versions always selected → poor exploration (c too low) or consistently bad new versions.  
- **Rule conflict/overrides:** Active bullets with overlapping conditions produce inconsistent instructions → erratic behavior or default to last bullet.

**First 3 Experiments:**  
1. **Baseline Validation:** Run static LLM (v0) with empty playbook across LG4–LG7. Confirm high composite scores and guard‑capture failures.  
2. **Single‑Step Reflection:** Run GUIDE for one reflection cycle (v0 → v1). Isolate first new bullet’s effect (e.g., guard‑avoidance). Verify intended trajectory change and score improvement.  
3. **UCB Exploration Sanity Check:** Inject two divergent playbook versions (aggressive pursuit vs. extreme evasion). Run UCB for 10+ episodes. Confirm both get evaluated (nₖ increases) and poorer version isn’t discarded after one bad trial.

## Open Questions the Paper Calls Out
1. **Component contribution:** What is the individual contribution of UCB‑based selection, ϵ‑biased sampling, and state‑conditioned rule structure to overall improvement?  
   *Basis:* Conclusions mention future ablation studies. *Why unresolved:* Full system evaluated monolithically; no disentanglement of mechanisms.
2. **GNC integration:** How does GUIDE’s rule evolution integrate with traditional low‑level Guidance, Navigation, and Control systems?  
   *Basis:* Conclusions list "tighter low‑level control integration" as future work. *Why unresolved:* Actor LLM is final authority; mapping to deterministic GNC unstudied.
3. **Non‑language policy evolution:** Can evolving algorithmic candidates (e.g., parametric controllers, symbolic planners) yield superior or more sample‑efficient adaptation?  
   *Basis:* Conclusions propose exploring "algorithmic candidate evolution alongside language policies." *Why unresolved:* Playbook is purely natural‑language bullets; hybrid approaches unexplored.
4. **Long‑term dynamics:** Do performance and playbook structure converge, oscillate, or degrade after many iterations? What patterns (specialization, abstraction, bloat) emerge?  
   *Basis:* Conclusions call for "larger‑scale playbook evolution." *Why unresolved:* Only up to five versions evaluated; supplementary hints at later degradation (e.g., LG7 v5 worse than v4).

## Limitations
- **Unknown model specifics & prompts:** Exact LLM variants (actor/reflector), baseline prompt wording, and reflection/curation prompts are unreported, hindering direct replication.  
- **Hyperparameter values:** Critical thresholds (UCB constant c, batch size B, ϵ rate, condition logic details like `guard approaching`) are not fully specified, requiring tuning assumptions.  
- **Correlation vs. causation:** While composite score improvements are large, the precise contribution of UCB vs. rule quality vs. environment stochasticity is not fully disentangled.

## Confidence
- **Performance claims (82–99% improvement):** High confidence. Results are numerically specific and internally consistent across scenarios.  
- **Mechanism 1 (playbook evolution without weight updates):** Medium confidence. Architecture is coherent, but external validation of symbolic rule sufficiency is limited.  
- **Mechanism 2 (decoupled online/offline for latency):** Medium confidence. Design is logical and motivated, but real‑time bounds under varied hardware are untested.  
- **Mechanism 3 (UCB balancing exploration/exploitation):** Low confidence. UCB works empirically, but without exact hyperparameters and sensitivity analysis, robustness is uncertain.  
- **Generalization beyond LBG scenarios:** Low confidence. Evaluation restricted to three KSPDG scenarios; transfer unproven.

## Next Checks
1. **Baseline replication audit:** Run `LLM (static v0)` with plausible baseline prompt. Confirm composite scores ~4e5 for LG4 and guard‑capture failures.  
2. **Single‑step causal isolation:** Execute only v0 → v1 reflection cycle. Verify first added rule’s condition fires on intended failure mode (e.g., `guard_distance` threshold). Replay subsequent episode to confirm rule’s direct effect on trajectory and score.  
3. **UCB exploration sanity test:** Inject two divergent playbook versions (aggressive pursuit vs. extreme evasion). Run UCB selector for 10+ episodes. Confirm both versions receive ≥2–3 evaluations (`nₖ` increases) and poorer version isn’t permanently discarded after one bad trial.
