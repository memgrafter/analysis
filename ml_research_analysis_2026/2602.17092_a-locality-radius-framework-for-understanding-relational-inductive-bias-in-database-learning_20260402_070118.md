# A Locality Radius Framework for Understanding Relational Inductive Bias in Database Learning

## Quick Facts
- **arXiv ID**: 2602.17092
- **Source URL**: https://arxiv.org/abs/2602.17092
- **Reference count**: 0
- **Primary result**: Graph neural networks (GNNs) only outperform multi-layer perceptrons (MLPs) on database schema learning tasks when the GNN's aggregation depth matches or exceeds the task's minimal locality radius; performance degrades when depth exceeds necessity due to over-smoothing.

## Executive Summary
This paper challenges the widespread assumption that relational inductive bias via graph neural networks (GNNs) is universally beneficial for database schema learning. It introduces "locality radius" as a formal measure of the minimal structural neighborhood required for correct prediction on a given task. Through controlled experiments on tasks like foreign key prediction, join cost estimation, and cascade impact classification, the authors show that model performance is determined by the alignment between a task's locality radius and the GNN's aggregation depth. For column-local tasks (radius 0), simpler MLPs significantly outperform GNNs. For multi-hop tasks (radius ≥2), GNNs achieve substantial gains, with performance peaking when depth matches the radius and declining thereafter due to over-smoothing.

## Method Summary
The study employs a synthetic database benchmark suite where tasks are explicitly constructed with known locality radii. For each task (e.g., predicting a foreign key, estimating join cost, simulating blast radius), the ground-truth minimal neighborhood size is determined by design. Models compared include MLPs and GNNs (e.g., GraphSAGE) with varying aggregation depths (k=1..5). Performance is measured via metrics like F1-score and R². The locality radius for each task is estimated based on its definition, and the relationship between this radius, model depth, and performance is analyzed statistically (e.g., Spearman correlation).

## Key Results
- For column-local tasks (locality radius r* = 0), MLPs significantly outperform GNNs (ΔF1=0.276, p=0.0002) despite having fewer parameters.
- For multi-hop tasks (r* ≥ 2), GNNs achieve substantial improvements; e.g., R² on blast radius regression increases from 0.51 (MLP) to 0.83 (GNN with matching depth), p<0.001.
- GNN advantage increases monotonically with locality radius (Spearman ρ=0.69), and performance peaks when aggregation depth matches the task radius, degrading when depth exceeds r* due to over-smoothing.

## Why This Works (Mechanism)
The benefit of relational inductive bias is governed by the precise alignment between a GNN's aggregation depth (k) and a task's locality radius (r*). This alignment dictates whether the model's receptive field is sufficient, excessive, or insufficient for the information needs of the prediction.

*   **Insufficient depth (k < r*)**: The model's k-hop neighborhood is smaller than the minimal required neighborhood. Information from nodes at distance r* cannot propagate to the target node. The GNN behaves similarly to a shallower model, lacking the contextual information needed for correct prediction, leading to underfitting on multi-hop tasks.

*   **Optimal alignment (k ≈ r*)**: The receptive field exactly encompasses the minimal necessary structural context. The GNN can aggregate all relevant information without introducing extraneous signals from beyond the task's dependency boundary. Node representations remain discriminative and task-specific, yielding peak performance.

*   **Excessive depth (k > r*)**: Aggregation continues beyond the point where all necessary information has been incorporated. Repeated message passing causes **over-smoothing**: node embeddings from different parts of the graph converge toward a similar, indistinguishable global representation. Discriminative features originating from the node's own attributes or its immediate task-relevant neighborhood are eroded. This homogenization is particularly detrimental for tasks with r* = 0, where *any* neighborhood aggregation introduces noise and harms performance.

Thus, the locality radius framework explains the non-monotonic performance curve: a threshold effect (need k ≥ r*) followed by a degradation effect (over-smoothing when k ≫ r*). The optimal k is task-dependent and must be chosen with respect to r*.

## Foundational Learning
- **Locality radius (r*)**: The minimal k-hop neighborhood required for a perfect predictor. *Why needed*: Quantifies task complexity; guides model selection. *Quick check*: Can you define a task where r*=2? e.g., predicting a cascade effect that propagates two steps.
- **GNN aggregation depth (k)**: Number of message-passing layers, determining maximum neighborhood size. *Why needed*: Controls model's receptive field. *Quick check*: If k=1, what is the maximum hop distance considered? One-hop neighbors.
- **Over-smoothing**: Phenomenon where repeated aggregation makes node representations indistinguishable. *Why needed*: Explains performance degradation when k > r*. *Quick check*: What happens to node embeddings after many GNN layers? They converge to a uniform vector.
- **Relational inductive bias**: Prior built into GNNs that nodes are connected in a graph and information flows along edges. *Why needed*: Enables leveraging database schema structure. *Quick check*: Does an MLP have relational inductive bias? No, it treats inputs as independent.
- **Foreign key prediction**: Task to predict if a column references another table. *Why needed*: Example of a database learning task. *Quick check*: Is this typically column-local (r*=0)? Yes, depends only on column values.
- **Blast radius regression**: Estimating the size of a cascade effect from a database change. *Why needed*: Example of a multi-hop task. *Quick check*: Would this require r*≥2? Yes, cascades propagate multiple steps.

## Architecture Onboarding
**Component map**: Schema input -> Graph construction (tables as nodes, foreign keys as edges) -> Node feature initialization (column statistics) -> GNN layers (k iterations of neighbor aggregation) -> Prediction head (task-specific output layer). For MLP baseline: same input features -> MLP layers -> prediction head, ignoring graph structure.

**Critical path**: The graph construction step defines the relational structure. For GNNs, the number of layers (k) directly controls the size of the neighborhood each node aggregates from. The prediction head then uses the final node representations (and possibly graph-level pooling) to make predictions.

**Design tradeoffs**:
- Depth vs. over-smoothing: Increasing k expands receptive field but risks losing node-specific information.
- Parameter efficiency: GNNs share parameters across neighbors, often requiring more parameters than MLPs for the same feature dimension, but exploit relational structure.
- Task alignment: A fixed k must be chosen; mismatch with r* leads to suboptimal performance.

**Failure signatures**:
- k < r*: Model fails to capture necessary long-range dependencies, leading to poor performance on multi-hop tasks.
- k > r*: Over-smoothing causes performance drop, especially on column-local tasks where any aggregation is harmful.
- Schema noise: Missing or incorrect foreign keys can disrupt message passing, causing GNNs to aggregate irrelevant information.

**First three experiments**:
1. Baseline comparison: Train and test MLP vs. GNN (k=2) on a column-local task (e.g., foreign key prediction). Expect MLP to outperform.
2. Depth sweep: For a multi-hop task (e.g., blast radius with r*=3), vary GNN depth k from 1 to 5. Expect performance to improve until k≈3, then degrade.
3. Transfer test: Train a GNN on a task with r*=2 and evaluate on a task with r*=0 without retraining. Expect poor performance due to over-smoothing from unnecessary depth.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: What is the precise relationship between a relational learning task's locality radius and the optimal GNN aggregation depth for maximum performance?
- Basis in paper: [explicit] The core hypothesis is stated in Section 3.5: "If k ≈ r*, performance is maximized." The paper empirically shows a monotonic relationship (Spearman ρ=0.69) and peak performance at matching depth, but the underlying theoretical form (e.g., linear, thresholded) and universality across architectures remain open.
- Why unresolved: The study evaluates fixed depths (k∈{1..5}) against estimated radii for a limited set of tasks. The exact functional form of the alignment curve (e.g., is there a sharp cutoff or gradual decay beyond r*?) and whether it holds for all GNN variants (GCN, GAT, GraphSAGE) equally is not formally derived or exhaustively tested.
- What evidence would resolve it: A theoretical analysis deriving the bias-variance tradeoff curve as a function of (k - r*), supported by extensive experiments varying k continuously over a wider range (e.g., k=0 to 10) across a larger, more diverse suite of synthetic and real-world schema tasks with known ground-truth radii.

### Open Question 2
- Question: How can the locality radius (r*) of an arbitrary, real-world database schema learning task be automatically estimated without requiring hand-crafted synthetic benchmarks or prior knowledge of the task's structural dependencies?
- Basis in paper: [explicit] Section 6.5 (Limitations) states: "Radius Estimation - We approximate locality radius based on task construction. Real-world tasks may exhibit mixed locality components." Section 6.6 (Future Directions) lists "Adaptive Radius Estimation" as a key direction, calling for methods to "estimate task locality automatically using probing networks or influence analysis."
- Why unresolved: The current framework relies on the analyst to manually determine or design a task's radius based on its definition (e.g., blast radius simulation implies r=3). There is no general, automated procedure to probe a trained model or the data distribution to infer the minimal sufficient neighborhood for a given prediction target.
- What evidence would resolve it: The development and validation of a principled probing or intervention-based algorithm (e.g., masking k-hop neighborhoods and measuring prediction drop, or using influence functions) that can output a reliable r* estimate for unseen tasks, validated against known radii on synthetic benchmarks and showing consistency across multiple model architectures.

### Open Question 3
- Question: Can hybrid architectures be designed that dynamically route information based on the local per-example (or per-task) effective locality radius, thereby achieving near-optimal performance across tasks with varying r* without manual depth selection?
- Basis in paper: [explicit] Section 6.6 proposes: "Hybrid Architectures - Design architectures that interpolate between MLP and GNN via learnable message gating." The paper's core finding—that performance degrades when k ≫ r* due to over-smoothing—motivates the need for models that can adaptively use shallow or deep propagation.
- Why unresolved: While the paper advocates for choosing a fixed depth matching r*, this requires knowing r* a priori. A model that could learn to ignore or suppress deeper message passing when it is not beneficial (i.e., for local subgraphs) would resolve the trade-off. No such adaptive mechanism is implemented or evaluated.
- What evidence would resolve it: Proposal and empirical evaluation of a GNN layer with a learned, example-wise gating mechanism (e.g., attention over layers, early stopping within the forward pass) that maintains high performance on both low-radius (r=0) and high-radius (r≥2) tasks within a single model, measured against the best fixed-depth baseline for each task.

## Limitations
- External validity limited to controlled synthetic/benchmark databases; unclear generalizability to complex real-world schemas with noise, missing keys, or cyclic dependencies.
- Locality radius operationalization may not capture all relational nuances (e.g., soft constraints, implicit joins).
- Corpus signals show zero citations, indicating lack of independent replication or critique; neighbor FMR (0.48) suggests moderate but not strong community convergence.

## Confidence
- **Radius-alignment hypothesis**: Medium (supported by internal experiments but needs cross-dataset verification).
- **Task-specific model superiority (radius 0 vs ≥2)**: High (consistent, statistically significant results across multiple tasks).
- **Monotonic GNN advantage (ρ=0.69)**: Medium (correlational; causality not fully established).
- **Over-smoothing degradation**: Low (observed but not systematically isolated or quantified).
