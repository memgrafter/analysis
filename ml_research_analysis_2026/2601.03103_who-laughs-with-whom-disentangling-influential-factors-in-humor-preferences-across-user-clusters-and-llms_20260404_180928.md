# Who Laughs with Whom? Disentangling Influential Factors in Humor Preferences across User Clusters and LLMs

## Quick Facts
- **ArXiv ID**: 2601.03103
- **Source URL**: https://arxiv.org/abs/2601.03103
- **Reference count**: 32
- **Primary result**: Clustering reveals heterogeneous humor preferences; LLM alignment varies by model and can be tuned via personas.

## Executive Summary
This study tackles the heterogeneity in human humor preferences by identifying distinct user clusters and analyzing the factors that drive their laughter preferences. Using data from the Oogiri platform, 276 active users were clustered into seven groups based on their interactions. For each cluster, a Bradley‑Terry‑Luce (BTL) model estimated the influence of 45 linguistic features and 11 humor‑strategy labels. Three large language models (Gemini‑3‑Pro, GPT‑5.1, Claude‑Sonnet‑4.5) were prompted to judge which of two responses was funnier; their BTL scores were correlated with the cluster‑specific weights. Persona prompting (e.g., “female_45”) was also tested to adjust LLM alignment. Results show that clusters differ markedly in preferred features (e.g., Cluster 0 favors long, dialogic responses; Cluster 5 prefers slang). LLM preferences align moderately with some clusters but negatively with the aggregated baseline, and persona tuning can substantially improve alignment for a given cluster. This indicates that LLM humor evaluation is not monolithic and can be steered toward specific user segments.

## Method Summary
The research leveraged the Oogiri platform’s interaction logs to select 276 active users. Responses were annotated with 45 linguistic features (e.g., length, lexical diversity) and 11 humor‑strategy labels (e.g., slapstick, wordplay). Clustering (method unspecified) grouped users into seven segments. For each cluster, a Bradley‑Terry‑Luce model was fitted to infer preference weights for each feature/strategy based on pairwise user choices. LLMs were instructed to act as judges and select the funnier response from pairs; their selections were also analyzed with BTL to produce a score vector. Correlations between LLM and cluster BTL scores quantified alignment. The impact of persona prompting was examined by instructing Gemini‑3‑Pro to adopt a “female_45” persona and measuring changes in correlation with Cluster 0.

## Key Results
- Clustering identified seven user groups with divergent humor preference factor weights (e.g., Cluster 0 favored long responses and dialogue; Cluster 5 preferred slang).
- LLM BTL scores showed moderate positive correlations with some clusters (e.g., GPT‑5.1 vs. Cluster 0: r = 0.57) but a negative correlation with the aggregated user baseline (r = ‑0.22).
- Persona prompting shifted alignment: for Gemini‑3‑Pro, the female_45 persona increased correlation with Cluster 0 from 0.39 to 0.63.

## Why This Works (Mechanism)
Bradley‑Terry‑Luce models effectively translate pairwise preference judgments (from users or LLMs) into continuous weight vectors over features, enabling direct comparison. Clustering captures latent heterogeneity, revealing that different user segments value distinct humor dimensions. The moderate correlations indicate that LLMs partially encode human humor biases but also deviate systematically; the negative baseline correlation arises because aggregating across clusters masks these segment‑specific patterns. Persona prompting likely modifies the LLM’s internal decision boundary, nudging its preference vector toward that of a target cluster. Together, these mechanisms explain how LLM humor preferences can be both variable and tunable.

## Architecture Onboarding
Component map:  
Raw Data -> Feature Extraction -> Clustering -> BTL Estimation (per cluster) -> LLM Prompting (with/without persona) -> BTL Scoring -> Correlation Analysis

**Critical path**: User interaction data are first transformed into linguistic and strategy features. These features drive the clustering step, which partitions users into segments. For each segment, a BTL model learns the segment’s preference weights. LLMs are then prompted to judge response funniness; their choices are also modeled with BTL to obtain a model preference vector. Finally, these vectors are correlated across clusters to assess alignment, and persona variations are introduced at the LLM prompting stage.

**Design tradeoffs**:  
- Number of clusters: more clusters increase specificity but reduce statistical power; fewer may mask heterogeneity.  
- Feature set richness vs. overfitting: 45 features capture nuance but risk noise; curation is crucial.  
- LLM selection: different models vary in capability and cost; Gemini, GPT, and Claude provide coverage but miss others.  
- Persona simplicity: using coarse personas (e.g., “female_45”) is easy to implement but may not reflect real user multidimensionality.

**Failure signatures**:  
- Low silhouette scores or unstable cluster assignments across runs.  
- Poor BTL model fit (e.g., high residual deviance) indicating mis‑specification.  
- Correlation values that swing dramatically with small data perturbations.  
- Persona prompts failing to produce measurable changes in LLM BTL scores.  
- LLM outputs showing minimal variance, suggesting the judgment task is not being engaged.

**First experiments**:  
1. **Clustering robustness**: Re‑cluster using alternative algorithms (e.g., DBSCAN, spectral clustering) and compare cluster stability and BTL weight consistency.  
2. **LLM diversity**: Expand evaluation to additional open‑ and closed‑source models (e.g., Llama‑3, PaLM‑2) to map the boundaries of alignment variation.  
3. **Persona granularity**: Test personas of varying specificity (e.g., only age, age + gender, full demographic profile) to quantify how fidelity affects alignment improvement.

## Limitations
- **Sample & Platform Bias**: Clustering relies on 276 Oogiri users, a niche group that may not represent general humor preferences.  
- **Feature Set Completeness**: The 45 linguistic features and 11 strategy labels may miss important factors such as cultural context or visual cues.  
- **Persona Prompt Fidelity**: The “female_45” persona is a crude proxy; real user personas are multidimensional and dynamic.

## Confidence
- **User Clustering & Distinct Weights**: Medium  
- **LLM‑Human Alignment Variation**: High  
- **Persona Prompt Tuning Effect**: Low

## Next Checks
1. **External Replication**: Apply the identical pipeline to a larger, demographically diverse humor dataset (e.g., social media, cross‑cultural) to test cluster robustness.  
2. **LLM & Prompt Breadth**: Test 5+ additional LLMs (open/closed) with varied persona prompting strategies (e.g., inferred vs. explicit traits) to map alignment boundaries.  
3. **Longitudinal Stability**: Re‑cluster users after 6+ months to assess whether humor preference clusters are stable traits or context‑dependent states.
