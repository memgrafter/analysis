# FinCARDS: Card-Based Analyst Reranking for Financial Document Question Answering

## Quick Facts
- **arXiv ID:** 2601.06992
- **Source URL:** https://arxiv.org/abs/2601.06992
- **Reference count:** 17
- **Primary result:** A three-stage tournament reranking pipeline using structured "Card" representations improves early-precision retrieval on financial QA (nDCG@10 from 44.26 to 71.58) while progressively reducing candidate set size from ~100 to <25.

## Executive Summary
Financial question answering over long documents demands evidence that satisfies strict numeric, temporal, and entity constraints. Standard LLM rerankers optimized for semantic relevance yield unstable rankings and opaque decisions. FinCards introduces a structured representation called "Cards" that abstracts document chunks into schematized fields (entities, metrics, periods, numeric spans). A multi-stage tournament reranking process then uses these Cards for deterministic field-level alignment, followed by stability-aware aggregation via bootstrap Borda scoring. This approach yields substantial gains in early-rank precision without any fine-tuning, demonstrating that constraint-aware structuring and ordinal stabilization are key to reliable financial evidence retrieval.

## Method Summary
The pipeline operates in three stages after initial lexical retrieval. First, a BM25 retriever selects a length-adaptive top-N (~60–150) of raw text chunks. Second, each chunk is converted offline into a structured "ChunkCard" with core alignment fields (topic, entities, metrics, numeric spans, normalized period, section, derived triple, evidence spans) and auxiliary cues (scope, table signature, boilerplate flag). The query is similarly mapped to a "QueryIntent." Stage 2 groups the BM25 candidates and uses an LLM to select a filtered set (~40) based on Card-intent field alignment. Third, Stage 3 repeatedly randomizes the filtered set into groups, performs listwise LLM ranking on each group, and aggregates the results via normalized Borda scores across up to 5 bootstrap rounds, stopping early if top-k set Jaccard similarity exceeds 0.9. The final output is a stable top-k ranking of chunk indices with an audit trail of alignment decisions.

## Key Results
- nDCG@10 rises from 44.26 (BM25) and 55.80 (zero-shot LLM) to 71.58 with the full FinCards pipeline.
- Candidate set size is progressively reduced: ~100 (Stage 1) → ~40 (Stage 2) → <25 (Stage 3).
- Ablations confirm the necessity of both Card-based filtering (Stage 2) and bootstrap stabilization (Stage 3) for the observed gains.
- Results are robust across multiple LLM backbones (GPT-4, Claude, Llama) without any task-specific fine-tuning.

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** Structured Card representations replace monolithic semantic ranking with deterministic field-level alignment, mitigating numeric, temporal, and entity mismatch.
**Mechanism:** Raw document chunks are abstracted into typed records (Cards) with schematized fields (metrics, periods, entities, numeric spans). Queries are mapped to the same schema. Alignment is performed via explicit field matching (e.g., metric overlap, temporal compatibility) rather than free-text similarity, enforcing constraint satisfaction.
**Core assumption:** Financial evidence relevance can be operationalized by a finite set of domain-specific fields that, when aligned, reliably indicate evidential fitness.
**Evidence anchors:** Abstract states Cards use "aligned schema fields (entities, metrics, periods, and numeric spans)"; Section 3.2 defines the Card schema (Ti, Ei, Mi, Ni, Pi, Si, Di, Ξi).
**Break condition:** If a query’s constraint cannot be expressed within the Card schema (e.g., implicit causal reasoning, cross-sectional synthesis), alignment fails regardless of field matching precision. Error analysis shows schema coverage gaps as a primary failure mode.

### Mechanism 2
**Claim:** Multi-stage tournament reranking with bootstrap aggregation stabilizes ordinal judgments by exposing candidates to diverse comparison contexts, reducing variance from single-pass LLM assessments.
**Mechanism:** Stage 2 performs group-wise selection using Cards; Stage 3 repeatedly randomizes candidate groups, produces listwise rankings, and aggregates via normalized Borda scores. Random regrouping mitigates context-dependent bias; Borda preserves fine-grained ordering across variable group sizes.
**Core assumption:** A candidate’s true relevance is reflected in its relative performance across multiple, randomized comparison sets, not a single ranking pass.
**Evidence anchors:** Abstract mentions "multi-stage tournament reranking with stability-aware aggregation"; Section 3.4.4 details bootstrap rounds, shuffling, normalization, and early stopping based on Jaccard similarity; Table 3 shows single-round or fixed-grouping variants increase rank variance and reduce nDCG@10.
**Break condition:** If Stage 2 candidate set is systematically misaligned (e.g., due to Card schema gaps), bootstrap aggregation will stabilize an incorrect ranking, amplifying rather than correcting error.

### Mechanism 3
**Claim:** Progressive candidate set reduction maintains computational feasibility while concentrating LLM attention on increasingly precise subsets, improving early-rank precision without fine-tuning.
**Mechanism:** Stage 1 (BM25) provides high-recall (~100 chunks). Stage 2 filters via Cards, reducing to ~40. Stage 3 stabilizes ranking within this smaller set, finally outputting <25. Each stage uses LLM calls only on manageable groups, avoiding monolithic long-context processing.
**Core assumption:** Early-stage filters can tolerate some noise because later stages operate on smaller, higher-quality sets; the cost of multiple LLM calls is offset by reduced per-call complexity.
**Evidence anchors:** Abstract notes "progressively reducing candidate set size from ~100 to fewer than 25"; Table 1 shows candidate sizes and concurrent nDCG@10 improvement; Section 3.4 outlines length-adaptive N and group size g.
**Break condition:** If Stage 1 recall is too low (BM25 misses all gold), subsequent stages cannot recover evidence. Error analysis demonstrates complete failure when lexical retrieval yields no gold candidates.

## Foundational Learning
- **Concept:** Financial constraint satisfaction in retrieval  
  **Why needed:** Financial QA requires simultaneous matching of metric, period, entity, and often numeric values—unlike generic semantic relevance. Misalignment on any dimension yields incorrect evidence.  
  **Quick check:** Given a query "What was Q4 2023 net income for Segment A?", list the Card fields that must align with evidence chunks.

- **Concept:** Structured intermediate representations  
  **Why needed:** Raw text chunks are noisy and uninterpretable for automated alignment. Cards make evidential attributes explicit, auditable, and comparable via field-level operations.  
  **Quick check:** What is the purpose of the `alignment core` (`ccore_i`) vs. `auxiliary fields` (`caux_i`) in a Chunk Card?

- **Concept:** Stability-aware rank aggregation  
  **Why needed:** Single-pass LLM rankings are order-sensitive and high-variance. Tournament-style multi-round aggregation produces consistent top-k results despite LLM stochasticity.  
  **Quick check:** How does normalized Borda scoring in Stage 3 differ from simple majority voting, and why is it preferred?

## Architecture Onboarding
- **Component map:** Chunker -> Card Abstraction -> Query Intent Mapper -> Stage 1 Retriever (BM25) -> Stage 2 Screener (Card filtering) -> Stage 3 Stabilizer (Bootstrap aggregation) -> Audit Logger
- **Critical path:** Input filing -> Chunking -> Card creation (offline) -> Query -> Intent mapping -> BM25 -> Stage 2 filtering -> Stage 3 aggregation -> Top-k output. Stage 2 and 3 are online; Cards can be cached per filing.
- **Design tradeoffs:**  
  - Zero-shot vs. fine-tuning: Avoids task-specific training but relies on prompt engineering and LLM reasoning ability.  
  - Cost vs. stability: More bootstrap rounds improve stability but increase LLM calls; early stopping mitigates this.  
  - Schema expressivity vs. coverage: Fixed schema enables deterministic matching but cannot capture implicit reasoning (e.g., strategic impact queries).  
  - Group size (g): Smaller groups increase comparison diversity but may miss global ordering; larger groups risk context limits and reduced diversity. Default g=25 balances.
- **Failure signatures:**  
  - **Lexical recall failure:** No gold chunks in Stage 1 Top-N → pipeline cannot recover (nDCG@10 = 0).  
  - **Schema gap:** Gold evidence requires an unmapped attribute → Stage 2 filters it out (Stage 2 nDCG drops vs. raw chunks).  
  - **Bootstrap instability:** High rank variance across rounds despite Card alignment → inconsistent LLM judgments (rank variance >0.06).  
  - **Over-filtering:** Stage 2 retention below threshold triggers reshuffling; persistent low retention suggests overly strict Card criteria.
- **First 3 experiments:**  
  1. Run Stage 1 (BM25) vs. Full Pipeline on FinAgentBench; expect nDCG@10 gain ~27 points and candidate reduction to <25.  
  2. Remove one Card field (e.g., `temporal_anchor`) and re-run Stage 2; expect largest drop when temporal data is removed.  
  3. For a sample query, run Stage 3 with R=5 and record top-5 Jaccard between consecutive rounds; expect convergence by round 3–4.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can the tournament reranking pipeline be extended to handle cross-document evidence selection, given that the current study is limited to intra-document retrieval within a single SEC filing?
- **Open Question 2:** Can the structured Card schema be enriched to handle implicit reasoning and causal queries (e.g., "How will interest rate hikes affect profitability?"), which currently cause systematic failures?
- **Open Question 3:** What is the sensitivity of FinCards to prompt design and schema specification choices, given that the method avoids fine-tuning but still relies on LLM interpretation of structured prompts?
- **Open Question 4:** Can the tournament-style stabilization mechanism (Stage 3) be made computationally more efficient without sacrificing the observed gains in ranking stability and early precision?
- **Open Question 5:** Do the gains from FinCards primarily stem from the structured Card representation itself or from the stability-aware aggregation (Stage 3), and how do these components interact across different query types?

## Limitations
- Evaluation restricted to FinAgentBench; generalizability to other financial datasets is unproven.
- The Card schema may not capture implicit constraints (e.g., causality), causing filtering failures.
- Stage 1 lexical recall is a single point of failure; missing gold chunks cannot be recovered.

## Confidence
- **Card-based alignment:** Medium – Ablations show benefits but schema gaps limit certainty.
- **Tournament stabilization:** High – Rank variance drops and nDCG improves across backbones.
- **Progressive reduction:** High – Directly observed candidate shrinking and nDCG gains.

## Next Checks
