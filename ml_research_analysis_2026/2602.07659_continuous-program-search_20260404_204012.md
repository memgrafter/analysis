# Continuous Program Search

## Quick Facts
* **arXiv ID:** 2602.07659
* **Source URL:** https://arxiv.org/abs/2602.07659
* **Reference Count:** 33
* **Primary Result:** Geometry-compiled mutation discovers strong trading strategies using only 13.7% of the evaluation budget (7.3× speedup over isotropic mutation) and achieves the highest median out-of-sample Sharpe ratio under a fixed evolutionary optimizer.

## Executive Summary
Genetic Programming (GP) suffers from poor behavioral locality, where small syntactic changes cause large, unpredictable shifts in program behavior, harming sample efficiency. This paper reframes the problem as an operator-design challenge: first, learn a continuous latent space where distance correlates with behavioral similarity; second, design a mutation operator that exploits this structure without changing the underlying evolutionary algorithm. Using a trading DSL with four semantically distinct signals (long/short entry/exit), the authors train a block-factorized VAE to embed programs. They empirically define a "trust region" for valid latent perturbations where decoding is stable and behavioral changes are gradual. A flow-based mutation model is then trained on historical isotropic traces to propose direction vectors within this region, but only applied to semantically paired subspaces (e.g., long entry/exit together). In comparative (μ+λ)-ES experiments across five assets, this geometry-compiled mutation (GCM) reaches strong strategies dramatically faster and more reliably than isotropic or subspace-only baselines, proving that semantically aligned, behavior-aware mutation substantially improves search efficiency.

## Method Summary
The method constructs a continuous GP search pipeline. A domain-specific language (GPTL) decomposes trading strategies into four Boolean signals. A VAE with a block-factorized latent space (four 32-dimensional blocks) is trained on randomly synthesized valid programs. Latent diagnostics identify a perturbation scale (ϵ ≤ 0.1) where small changes yield executable programs with low behavioral divergence (action-sequence distance)—this defines a trust region. Disentanglement tests confirm that perturbing one latent block affects only its corresponding signal with negligible cross-talk. An evolutionary loop using a fixed (μ+λ)-ES evaluates decoded programs via walk-forward backtesting. Three mutation kernels are compared: (1) isotropic Gaussian noise over the full latent vector, (2) "dual-block" Gaussian restricted to paired entry/exit subspaces, and (3) geometry-compiled mutation (GCM). GCM uses a flow-matching model trained on traces from baseline isotropic runs; at search time, it conditions on a parent's latent code and its behavioral embedding (derived from in-sample performance) to predict a mutation direction, which is then masked to the active semantic subspace and applied. All methods share identical selection, evaluation, and total evaluation budgets.

## Key Results
* GCM achieved the highest median out-of-sample Sharpe ratio (1.152) while consuming only 13.7% of the evaluation budget, compared to 88.5% for isotropic mutation.
* GCM discovered strong solutions 7.3× faster than isotropic mutation and was more reliable across seeds, though isotropic occasionally reached higher peaks.
* Subspace-restricted mutation (dual-block) outperformed isotropic but was surpassed by GCM, indicating value in both semantic masking and learned direction proposals.

## Why This Works (Mechanism)
### Mechanism 1: Behavioral Locality via Trust Region
Small isotropic perturbations to the latent code produce predictable behavioral shifts only within an empirically identified scale (ϵ ≤ 0.1). Outside this "trust region", decode validity drops and behavioral divergence spikes, making mutations unreliable. This quantifies and bounds the locality gap, enabling safe continuous mutation.

### Mechanism 2: Semantic Disentanglement via Block-Factorization
The VAE's architecture mirrors the DSL's four-signal decomposition, yielding a latent vector of four independent blocks. Single-block perturbations change almost exclusively the corresponding signal (near-zero cross-talk), allowing mutation to target coherent semantic units (e.g., long entry/exit together) without introducing incoherent edits.

### Mechanism 3: Learned Proposal Within Subspaces
A flow-matching model is trained on historical mutation traces (parent latent, child latent, behavioral embedding, fitness delta) from isotropic runs. During search, it conditions on a parent's state and behavior to propose a mutation direction biased toward historically fitness-improving moves. Combined with the semantic mask, this yields targeted, high-quality proposals within the trust region, accelerating evolution under a fixed optimizer.

## Foundational Learning
* **Behavioral Locality in GP:** Small syntactic edits can cause large behavioral changes (e.g., flipping an entry condition to an exit), making search inefficient. Measuring this gap requires controlled latent-space experiments.
* **VAEs for Structured Programs:** A continuous latent space enables gradient-free continuous mutation. Architectural inductive biases (e.g., block-factorization) can align the representation with domain semantics.
* **Operational Disentanglement:** Disentanglement is validated not by proxy metrics but by direct perturbation tests: altering one latent factor should change only the corresponding program component, enabling controlled mutation.
* **Flow Matching for Mutation Learning:** Conditional flow models can learn to propose mutation directions from historical evolutionary traces, biasing search toward beneficial regions without altering the evolutionary algorithm's selection mechanism.
* **Trust Region in Latent Space:** There exists a perturbation magnitude where decoding remains stable and behavioral change is approximately linear; this region defines valid steps for continuous search.
* **Semantic Subspace Mutation:** When program semantics decompose cleanly (e.g., entry vs. exit), restricting mutations to paired subspaces prevents incoherent offspring and improves sample efficiency.

## Architecture Onboarding
* **Component map:**
  GPTL grammar -> Dataset generator (random valid programs) -> Block-factorized Transformer VAE (latent z = [z_le, z_se, z_lx, z_sx]) -> Latent diagnostics (trust region, disentanglement tests) -> Behavioral embedding φ (from execution trace) -> Flow model Fθ(z, φ) (trained on isotropic traces) -> (μ+λ)-ES loop: population in ℝ^128 -> Mutation: [Isotropic | Dual-block Gaussian | GCM (masked Fθ output)] -> Decode -> Backtest (Sharpe) -> Selection -> repeat.

* **Critical path:**
  1. Define a semantically decomposable DSL (GPTL) and generate a dataset of valid programs.
  2. Train a block-factorized VAE to embed programs into a continuous space.
  3. Determine a trust region (ϵ ≤ 0.1) via latent perturbation diagnostics.
  4. Validate disentanglement via single-block perturbation tests (expect near-zero cross-talk).
  5. Collect mutation traces from baseline (isotropic) ES runs.
  6. Train flow model Fθ to predict mutation direction δ given (z, φ).
  7. Run comparative ES experiments, swapping only the mutation kernel.
  8. Evaluate out-of-sample Sharpe and budget efficiency.

* **Design tradeoffs:**
  - Semantic alignment (subspace masks) reduces incoherent edits but may miss beneficial cross-subspace changes.
  - Trust region size trades off exploration scale vs. stability of decoded programs.
  - Learned proposals require upfront data collection cost but aim for per-generation efficiency.
  - GCM directions are latent, not symbolic edit scripts, reducing human interpretability of mutations.

* **Failure signatures:**
  - VAE validity low (<90%) or reconstruction poor → latent space unusable.
  - High cross-talk in disentanglement tests (>5-10%) → subspace restriction ineffective.
  - GCM underperforms dual-block baseline → flow model failed to learn beneficial directions (overfit/underfit).
  - High decode invalidity in ES runs → trust region violated (step size too large).

* **First 3 experiments:**
  1. Train block-factorized VAE (dim=128) on GPTL dataset. Report reconstruction accuracy and validity. Confirm latent dimension 128 balances capacity and validity.
  2. Perform single-block perturbation test (ϵ=0.1) on 100 held-out programs. Compute heatmap of per-signal edit distance; expect strongly diagonal with ~0% off-diagonal.
  3. Compare dual-block Gaussian vs. isotropic mutation in short ES runs (e.g., 300 evaluations) on one asset. Track best Sharpe vs. evaluations; expect dual-block to progress faster despite isotropic's potentially higher final peak.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Can geometry-compiled mutation generalize to program synthesis domains lacking clear semantic decompositions into independent components?
- **Basis in paper:** The authors state in the Discussion: "Extending these ideas to domains without obvious semantic partitions remains an important direction for future work."
- **Why unresolved:** The method relies on a block-factorized latent space aligned with four trading-specific semantic components. Other domains (e.g., general code generation) may not offer similarly clean, separable substructures, making it unclear how to define meaningful subspaces for mutation.
- **What evidence would resolve it:** Apply the GCM pipeline to diverse DSLs with varying semantic modularity (e.g., arithmetic expressions, control-flow programs) and measure whether subspace-restricted mutation still yields efficiency gains over isotropic baselines. Success would require consistent relative improvement despite the absence of obvious part boundaries.

### Open Question 2
- **Question:** Does the quality of training traces (collected under isotropic mutation) limit the effectiveness of the learned flow-based mutation model?
- **Basis in paper:** The flow model is trained offline on mutation traces gathered using isotropic Gaussian mutation within the same (μ+λ) ES (Section 7.4). The paper does not explore whether base operator choice affects the learned proposals.
- **Why unresolved:** If training traces predominantly contain ineffective or high-divergence mutations from isotropic search, the flow model might learn to avoid directions that could be beneficial under a different exploration prior. This dependency could constrain GCM's performance ceiling.
- **What evidence would resolve it:** Train multiple flow models on traces from different base operators (e.g., isotropic, dual-block Gaussian, random walk) and compare the resulting GCM operators in identical evolutionary runs. Significant performance differences would confirm that training data quality impacts the learned mutation policy.

### Open Question 3
- **Question:** Is the performance gain from geometry-compiled mutation primarily driven by restricting updates to semantically paired subspaces or by the learned direction proposals within those subspaces?
- **Basis in paper:** The paper compares isotropic mutation, dual-block Gaussian (subspace restriction only), and GCM (subspace restriction + learned directions). GCM outperforms both, but the relative contribution of each design choice is not isolated.
- **Why unresolved:** Disentangling these factors is critical for future operator design. If subspace restriction is the main driver, simpler geometric constraints may suffice; if learned directions are key, then investment in more sophisticated generative models is justified.
- **What evidence would resolve it:** Perform ablations: (a) apply GCM’s flow-predicted directions without subspace masking (full-latent flow), and (b) use isotropic noise within dual-block subspaces but conditioned on the behavioral embedding. Comparing these against the full GCM and baselines would quantify each component’s marginal benefit.

### Open Question 4
- **Question:** How robust is GCM to the design of the behavioral embedding Φ used to condition the flow model?
- **Basis in paper:** The flow model conditions on an 8-dimensional handcrafted feature vector derived from execution traces (Appendix D.1). The paper does not validate whether this specific representation is optimal or necessary.
- **Why unresolved:** Φ captures only coarse regime exposure and trade statistics. It may omit subtle behavioral cues that could improve proposal quality. Conversely, a simpler or alternative Φ might work equally well, reducing implementation complexity.
- **What evidence would resolve it:** Systematically replace Φ with alternatives (e.g., raw trade logs, learned embeddings from a separate model, ablated feature sets), retrain the flow model, and evaluate GCM performance. Consistent results across diverse Φ designs would indicate robustness; significant variance would highlight the need for careful feature engineering.

## Limitations
* Hyperparameters for isotropic mutation scale (σ) and the "strong solution" threshold for budget metrics are unspecified, hindering exact replication.
* The reported generation count ("100 generations") conflicts with the total evaluation budget (1320 offspring with λ=66 implies ~20 generations), creating ambiguity.
* Evaluation is restricted to five futures assets, limiting generalizability to other domains or data regimes.
* Flow model architecture and training details (e.g., filtering of improving mutations) are underspecified.

## Confidence
* **Behavioral Locality & Trust Region (Mechanism 1): High** – Directly validated via controlled perturbation experiments on held-out data.
* **Semantic Disentanglement (Mechanism 2): High** – Single-block perturbation tests show near-zero cross-talk, confirming operational control.
* **Geometry-Compiled Mutation Efficacy (Mechanism 3): Medium** – Strong comparative results but dependent on unspecified hyperparameters and quality of training traces.
* **Generalization to Other Domains: Low** – Unresolved; method seems tightly coupled to the semantically decomposable DSL.

## Next Checks
1. **Trust Region Consistency:** For each of the five assets, recompute behavioral divergence vs. ϵ on a held-out program set. Confirm the transition point (ϵ ≤ 0.1) is stable across assets; significant variation would challenge the universal trust region assumption.
2. **Cross-Asset Flow Transfer:** Train the flow model on isotropic traces from four assets only, then run GCM on the held-out fifth asset. Measure degradation in budget efficiency (fraction to reach target Sharpe). Minimal degradation would support generalization across assets.
3. **Ablation: Masking vs. Learned Direction:** Implement two variants: (a) GCM flow direction without subspace masking (apply full δ), and (b) isotropic Gaussian within dual-block subspaces (same σ) but *without* the flow model. Compare both to full GCM and dual-block baseline. The performance drop from (a) vs. full GCM would isolate the value of masking; from (b) vs. full GCM would isolate the value of learned directions.
