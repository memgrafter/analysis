# Bias in the Shadows: Explore Shortcuts in Encrypted Network Traffic Classification

## Quick Facts
- **arXiv ID:** 2601.10180
- **Source URL:** [https://arxiv.org/abs/2601.10180](https://arxiv.org/abs/2601.10180)
- **Reference Count:** 34
- **Primary Result:** BiasSeeker addresses shortcut learning in encrypted network traffic classification by detecting dataset-specific spurious features through model-agnostic, data-driven Adjusted Mutual Information analysis on raw bytes.

## Executive Summary
Encrypted network traffic classification often suffers from shortcut learning, where models exploit spurious correlations present in the training data but not causally related to the target class, leading to poor generalization. This paper introduces BiasSeeker, a model-agnostic framework that detects such shortcuts by analyzing raw packet fields using Adjusted Mutual Information (AMI) to rank feature-label dependence. High-AMI features are manually categorized into three types—Data-Leakage Identifiers, Relative Artifacts, and Task-Agnostic Fields—and validated with category-specific tests. Evaluated on 19 public datasets across VPN, malware, and app classification tasks, BiasSeeker shows that removing Data-Leakage features consistently degrades accuracy (e.g., up to 2.6% drop for NetMamba), confirming their role as non-causal shortcuts. In contrast, mitigation of other categories yields variable effects, indicating that shortcut harmfulness is context-dependent. The work highlights the need for careful dataset construction and standardized benchmarks to foster robust, generalizable traffic classifiers.

## Method Summary
BiasSeeker operates in a pipeline: First, raw network traffic (PCAPs) is parsed using tshark to extract per-packet fields (e.g., IP addresses, ports, timestamps). These fields are normalized to uniform numeric representations (integers for categorical values, floats for timestamps, etc.). Next, for each feature, Adjusted Mutual Information (AMI) between the feature values and the class label is computed, producing a ranking of features by statistical dependence. The top-ranked features are then manually categorized based on domain knowledge into Data-Leakage Identifiers (features that directly reveal labels due to collection artifacts, e.g., SNI), Relative Artifacts (features that encode absolute session state, e.g., TCP sequence numbers), or Task-Agnostic Fields (environmental factors like TTL). Each category is subjected to a tailored validation: occlusion (zero or random masking) for Data-Leakage, ΔAMI (difference between raw and relative AMI) for Relative Artifacts, and cross-dataset KL divergence for Task-Agnostic Fields. Based on validation outcomes, mitigation strategies such as feature zeroing, relative transformation, or normalization are applied before model training/evaluation. The process is model-agnostic; the study uses NetMamba and decision trees.

## Key Results
- BiasSeeker identified high-AMI features across 19 datasets, with Data-Leakage fields like IP addresses and SNI consistently ranking at the top.
- Mitigation experiments revealed that removing Data-Leakage features caused significant accuracy drops (e.g., NetMamba accuracy decreased by up to 2.6% on CrossNet2021 and 1.58% on ISCXVPN2016), confirming models’ reliance on non-causal shortcuts.
- The impact of mitigating Relative Artifacts and Task-Agnostic Fields varied across datasets, demonstrating that not all shortcuts are equally harmful and that context plays a critical role.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** BiasSeeker detects dataset-specific shortcut features by identifying those with disproportionately high statistical dependence on classification labels, using Adjusted Mutual Information (AMI) as a model-agnostic ranking metric.
- **Mechanism:** For each raw packet field, AMI between the field's values and class labels is computed. Fields are ranked by AMI; top-ranked candidates are hypothesized as shortcuts because shortcuts must exhibit some predictive correlation (high I(X;Y)) to be exploited.
- **Core assumption:** Shortcut features will manifest as statistically dependent on the label in the training data, even if the dependence is spurious.
- **Evidence anchors:**
  - [abstract] "By performing statistical correlation analysis directly on raw binary traffic, BiasSeeker identifies spurious or environment-entangled features... independent of any classifier."
  - [section IV.C] "If a feature X_j is exploited as a shortcut by a model f, then X_j must exhibit non-trivial dependence with the label Y, i.e., I(X_j;Y) > 0. Therefore, shortcut features are expected to appear in the top-ranked AMI list."
  - [corpus] Corpus neighbors focus on shortcut learning broadly but lack direct evidence for AMI's efficacy in NTC; anchors rely primarily on paper's self-contained justification.
- **Break condition:** A feature with high AMI but proven semantic relevance to the task (e.g., packet length for VoIP detection) would violate the shortcut hypothesis; AMI alone cannot distinguish causal from spurious correlation without further categorization.

### Mechanism 2
- **Claim:** BiasSeeker categorizes high-AMI features into three types (Data-Leakage Identifiers, Relative Artifacts, Task-Agnostic Fields) to enable tailored validation, recognizing that shortcut manifests and mitigation needs differ fundamentally.
- **Mechanism:** Domain knowledge (protocol specs, labeling processes) interprets the semantics of top-AMI features. This human-in-the-loop step assigns each to a category with characteristic failure modes (e.g., Data-Leakage Identifiers directly correlate with labels due to collection artifacts; Relative Artifacts encode absolute session state; Task-Agnostic Fields reflect environmental conditions).
- **Core assumption:** Protocol and data-collection domain knowledge can reliably group shortcut mechanisms into a finite set of behavioral patterns, each requiring different intervention.
- **Evidence anchors:**
  - [abstract] "To address the diverse nature of shortcut features, we introduce a systematic categorization and apply category-specific validation strategies..."
  - [section IV.D] Defines the three categories explicitly with examples: "Data-Leakage Identifiers: Features that reveal label-relevant information due to data collection or labeling artifacts."
  - [corpus] Neighbor papers (e.g., "SoK: Decoding the Enigma of Encrypted Network Traffic Classifiers") discuss field-level biases but do not provide evidence for this specific tripartite taxonomy.
- **Break condition:** Discovery of a frequent high-AMI shortcut that does not fit any proposed category would require taxonomy expansion; the categorization is heuristic, not exhaustive.

### Mechanism 3
- **Claim:** Category-specific validation (occlusion for Data-Leakage, AMI delta for Relative Artifacts, cross-dataset KL divergence for Task-Agnostic) quantifies each feature's shortcut impact and guides mitigation, moving beyond blanket removal.
- **Mechanism:** For each category, a targeted test measures sensitivity to bias. Data-Leakage: zero/random masking should hurt accuracy if relied upon. Relative Artifacts: `ΔAMI = AMI(raw) - AMI(relative)`; high Δ indicates absolute values encode non-semantic bias. Task-Agnostic: high `KLavg` across datasets shows environmental entanglement, suggesting normalization.
- **Core assumption:** The behavioral signature of each shortcut type is captured by its respective validation metric, and model performance shifts under these interventions reflect shortcut reliance.
- **Evidence anchors:**
  - [section IV.E] Details each validation: "For Relative Artifacts: We measure the change in feature-label dependence before and after relative transformation using Adjusted Mutual Information (AMI): ΔAMI = AMI(X_j, Y) - AMI(X_j^rel, Y)."
  - [section V.C] Presents results: "Data leakage constitutes a stable shortcut category: Across all six datasets, removing SII or SNI consistently results in noticeable accuracy drops."
  - [corpus] No direct corpus evidence; validation strategies are paper-original designs inspired by domain properties.
- **Break condition:** A validation metric shows no signal (e.g., ΔAMI ~0) yet post-mitigation accuracy drops significantly, indicating the metric failed to capture the shortcut mechanism for that feature.

## Foundational Learning
- **Concept: Adjusted Mutual Information (AMI)**
  - **Why needed here:** It is the core, model-agnostic statistic for ranking feature-label dependence, normalized against chance to allow cross-feature comparison in imbalanced traffic datasets.
  - **Quick check question:** Why use AMI instead of raw Mutual Information or correlation for ranking features in highly imbalanced classification tasks?
- **Concept: Shortcut Learning (in NTC context)**
  - **Why needed here:** The entire framework targets this specific failure mode where models exploit spurious correlations (e.g., IP addresses, fixed timestamps) that do not generalize beyond the training distribution.
  - **Quick check question:** What is a canonical example of a shortcut in encrypted traffic classification, and why does it break generalization?
- **Concept: Causal vs. Spurious Correlation**
  - **Why needed here:** The paper's goal is to distinguish features that causally relate to the traffic class (e.g., protocol semantics) from those that spuriously correlate due to collection artifacts. This underpins the entire detection and categorization logic.
  - **Quick check question:** How might a feature like TCP Window Size be a *spurious* correlation for app classification, and what environmental factor drives this?

## Architecture Onboarding
- **Component map:**
  1. **Raw Field Extractor** (`tshark`): Parses PCAPs into structured per-packet fields.
  2. **Normalizer & Encoder**: Converts fields to uniform numerical format (IP→int, hex→int, floats preserved, domain→index).
  3. **AMI Scorer**: Computes `AMI(field, label)` for all fields; ranks and selects top-k.
  4. **Categorizer** (human+heuristics): Assigns top-k fields to Data-Leakage, Relative Artifact, Task-Agnostic.
  5. **Validator**: Applies category-specific test (occlusion, ΔAMI, KLdiv).
  6. **Mitigator** (optional): Applies transformation (zeroing, relative calc, normalization) based on category.
- **Critical path:** `PCAP → Fields → Normalize → AMI Rank → Categorize → Validate → [Mitigate]`. The categorization step is the main branch point determining the validation path.
- **Design tradeoffs:**
  - **AMI speed vs. depth:** AMI is fast and model-agnostic but only captures linear/marginal dependence; may miss complex shortcuts requiring model-based analysis.
  - **Automation vs. expertise:** Field categorization requires domain knowledge (protocols, labeling); fully automating this is an open challenge noted in the paper.
  - **Granularity:** Packet-level analysis captures fine-grained shortcuts but may miss flow-level patterns; flow-level aggregation was rejected due to bias from variable lengths.
- **Failure signatures:**
  - **High AMI, no accuracy drop on occlusion:** Feature is likely *causal* (legitimate signal), not a shortcut.
  - **Low ΔAMI for a Relative Artifact:** Absolute value may be stable/semantic in this dataset; relative transform unnecessary.
  - **Inconsistent category effects across datasets:** Example: SNI removal helps in one dataset but hurts in another, indicating context-dependence (Takeaway 2).
- **First 3 experiments:**
  1. **Replicate AMI ranking on one dataset (e.g., ISCXVPN2016):** Verify top-10 features match paper's expectations (IP/port, SNI high). Confirm preprocessing steps (discretization, filtering constants) yield stable rankings.
  2. **Validate categorization on a known shortcut:** Take `tcp.srcport` (Data-Leakage). Apply zero padding. Expect: significant accuracy drop (e.g., >1% on NetMamba) as in Table III for SII.
  3. **Test Relative Artifact ΔAMI:** For `tcp.options.timestamp.tsval` on a malware dataset, compute `AMI(raw, label)` and `AMI(tsval - tsecr, label)`. Expect large Δ (>0.1) per Figure 3(R), indicating raw timestamp is a shortcut.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can shortcut detection be fully automated, removing the need for human interpretation of feature semantics?
- **Basis in paper:** [explicit] The authors state in Section VI.A: "Building an automatic shortcut detector is a challenging open problem. We hope our framework provides a structured first step..." and note that BiasSeeker still requires human inspection for feature categorization.
- **Why unresolved:** BiasSeeker relies on domain knowledge to interpret high-AMI features and categorize them. A fully automated system must replicate this semantic assessment without expert input, which is difficult in high-dimensional traffic data where feature semantics are often opaque.
- **What evidence would resolve it:** An end-to-end system that ingests raw traffic, automatically ranks and clusters features by behavioral patterns (e.g., stability across environments, causal plausibility), and outputs a ranked list of suspected shortcuts validated against known dataset artifacts, without requiring manual labeling of feature types.

### Open Question 2
- **Question:** What dataset and model properties predict whether a high-AMI feature will act as a harmful shortcut versus a valid signal?
- **Basis in paper:** [inferred] The paper finds that shortcut impact is context-dependent (Section VI.B), with Data-Leakage Identifiers consistently harmful but Relative Artifacts and Task-Agnostic Fields showing variable effects across datasets. The authors do not provide a predictive framework.
- **Why unresolved:** The paper demonstrates empirical variability but does not isolate the underlying factors (e.g., labeling methodology, network topology stability, application behavior diversity) that determine harmfulness. This limits proactive mitigation.
- **What evidence would resolve it:** A controlled study varying dataset characteristics (e.g., collection environment, label source, traffic diversity) and measuring the correlation between feature stability metrics (e.g., cross-dataset AMI variance) and downstream model robustness metrics (e.g., OOD accuracy drop).

### Open Question 3
- **Question:** Can neural models be trained to learn semantic, protocol-invariant representations of encrypted traffic that are inherently resistant to shortcut learning?
- **Question:** What evidence would resolve it: A traffic classification model pre-trained on diverse, multi-domain datasets with an explicit objective (e.g., contrastive learning) to minimize reliance on known shortcut-prone fields (like SII or timestamps), evaluated for both in-distribution accuracy and robust OOD generalization across unseen network conditions and labeling schemes.

### Open Question 4
- **Question:** How should standardized benchmarks for encrypted network traffic classification be designed to adequately stress-test for shortcut reliance and promote generalizable models?
- **Basis in paper:** [inferred] The authors call for "realistic and diverse benchmarks" (Section VI.C), criticizing current datasets for potentially embedding hidden biases. Existing public datasets may not reflect deployment heterogeneity.
- **Why unresolved:** The paper uses 19 public datasets but does not propose benchmark design principles. Without such standards, shortcut detection remains dataset-specific and may not transfer to real-world scenarios.
- **What evidence would resolve it:** A proposal for benchmark suites that deliberately include controlled distribution shifts (e.g., varied capture environments, labeling strategies, protocol implementations) paired with canonical shortcut feature annotations, enabling consistent evaluation of model resilience beyond simple accuracy.

## Limitations
- NetMamba implementation details (pre-training hyperparameters, fine-tuning procedures) are unspecified, hindering exact replication of experiments.
- The heuristic categorization of high-AMI features requires manual domain knowledge and may miss novel shortcut types or misclassify ambiguous fields.
- AMI captures only marginal (linear) dependence and may overlook complex, nonlinear shortcuts that also generalize poorly.
