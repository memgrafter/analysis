# Emulating Clinician Cognition via Self-Evolving Deep Clinical Research

## Quick Facts
*   **arXiv ID:** 2603.10677
*   **Source URL:** https://arxiv.org/abs/2603.10677
*   **Reference count:** 40
*   **Primary result:** A self-evolving diagnostic agent (DxEvolve) improved diagnostic accuracy by 11.2% over backbone models on MIMIC-CDM, reached 90.4% on a subset (surpassing 88.8% clinician reference), and generalized with gains to an external Chinese hospital cohort.

## Executive Summary
Clinical AI systems are misaligned with how clinicians think, treating diagnosis as a static prediction from a full record rather than an interactive process of evidence gathering. This paper introduces DxEvolve, an agent that emulates clinician cognition through an interactive "deep clinical research" (DCR) workflow. It autonomously requests examinations, refines hypotheses, and after each case, distills the experience into a reusable, inspectable artifact called a Diagnostic Cognition Primitive (DCP). These DCPs are stored in a retrievable repository and used to guide future cases without updating model parameters, enabling governed, continuous improvement. On a benchmark of acute abdominal cases, DxEvolve showed significant accuracy gains over its base models and outperformed clinicians in a reader study. External validation demonstrated cross-institutional generalizability, and performance scaled with accumulated experience, with later DCPs proving more clinically useful. The work provides a pathway for accountable, evolving clinical AI.

## Method Summary
DxEvolve operates via a prompt-based agentic system around a frozen base LLM. It uses a structured DCR workflow where the agent iteratively outputs a "Thought" and a structured "Action" (e.g., ordering a specific lab or imaging study, searching its experience repository). The environment executes the action and returns only the solicited findings, mimicking real-world cue acquisition. After an encounter, a post-hoc consolidation module distills the full trajectory into a DCP containing an experience pattern for retrieval, test-ordering guidance, and a linked diagnostic rule. For new cases, the agent can perform an `Experience Search` action to retrieve relevant past DCPs via dense vector similarity, using the retrieved heuristics to inform its subsequent reasoning and action choices. This creates a closed loop of interactive diagnosis, experience distillation, and retrieval-augmented future performance without any parameter updates.

## Key Results
*   On the MIMIC-CDM benchmark, DxEvolve improved average diagnostic accuracy by 11.2% over the backbone model baseline and achieved 90.4% accuracy on a reader-study subset, exceeding the 88.8% clinician reference.
*   In external validation at a Chinese hospital, it achieved a 10.2% gain on categories overlapping the source MIMIC cohort and a 17.1% gain on entirely new categories, demonstrating generalization.
*   Performance scaled with the number of accrued DCPs; later DCPs were rated as more clinically useful in blinded assessment, and retrievals in improvement cases were enriched for DCPs from prior *failures*, indicating an error-correction dynamic.

## Why This Works (Mechanism)
### Mechanism 1: Workflow-Aligned Evidence Acquisition (DCR)
Replaces static, full-record diagnosis with an interactive, stepwise investigation. The agent must explicitly request physical exams, labs, and imaging, receiving only the solicited findings. This mimics the clinician's dynamic cue-acquisition process, creates traceable encounter states, and forces the model to operate within realistic clinical constraints.
*Break Condition:* Fails if the backbone model cannot comply with the structured action-call protocol or if the clinical environment does not support discrete, requestable evidence items.

### Mechanism 2: Experience Distillation into Diagnostic Cognition Primitives (DCPs)
After each encounter, the trajectory is post-hoc distilled into a structured primitive containing: (1) an *Experience Pattern* (salient presentation summary for retrieval), (2) *Test-Ordering Experience* (actionable workup guidance), and (3) *Diagnostic Decision Experience* (evidence-linked reasoning rule). This externalizes learning into an inspectable repository, enabling reuse without parameter updates.
*Break Condition:* Fails if the reflection/consolidation prompt generates low-quality, non-actionable, or incorrect DCPs, corrupting the repository.

### Mechanism 3: Exposure-Dependent, Error-Driven Self-Evolution
Performance scales with the number of accrued DCPs. Critically, retrievals in *improvement cases* (where DxEvolve succeeded but the no-DCP ablation failed) are enriched for DCPs sourced from *incorrect* prior encounters. This suggests a "corrective" learning dynamic where failures generate high-value heuristics forfuture cases.
*Break Condition:* Stagnation occurs if the DCP repository becomes saturated with low-diversity or low-quality artifacts, or if retrieval fails to surface relevant DCPs for novel presentations.

## Architecture Onboarding
### Component map
DCR Workflow Engine -> State Manager -> Base LLM Backend
DCR Workflow Engine <- External Knowledge Tools (Guideline Search, PubMed Search)
State Manager <- DCP Repository & Retriever (via FAISS index on Experience Patterns)
Post-episode: DCR Workflow Engine -> DCP Consolidator -> DCP Repository & Retriever

### Critical path
1.  **Initialization**: Load base LLM, empty/pre-filled DCP repository, external knowledge indices.
2.  **Diagnostic Encounter**:
    a. Receive `Patient History`. Initialize state.
    b. **Loop**: Generate `Thought` & `Action` from state. If `Action` is a search, query appropriate index; if a medical evaluation, call tool.
    c. Receive `Observation`, update state.
    d. Continue until `Final Diagnosis` or step limit.
3.  **Post-Episode**: If in accrual pool, trigger **DCP Consolidator** to create and index a new DCP.
4.  **Evaluation**: For a held-out case, the loop (2b-2d) queries the *growing* DCP repository.

### Design tradeoffs
*   **Retrieval vs. Computation**: Dense retrieval is fast but depends on embedding quality. Tradeoff between richer DCPs (harder to retrieve precisely) and focused ones (less generalizable).
*   **DCP Granularity**: Mid-level (e.g., disease workup) vs. specific decision points. Too broad: noisy retrieval. Too narrow: limited utility.
*   **External Tool Reliance**: Guideline/PubMed search adds authoritative knowledge but introduces latency, API failures, and potential for irrelevant results.
*   **Non-Parametric vs. Parametric Learning**: Avoiding fine-tuning preserves auditability but may cap performance if the base LLM's reasoning is insufficient.

### Failure signatures
*   **Poor Retrieval Precision**: Agent retrieves clinically irrelevant DCPs, visible in logs where `Experience Search` is followed by reasoning that ignores or conflicts with the DCP.
*   **Guideline/PubMed Over-reliance or Misinterpretation**: Agent defers to retrieved guidelines even when they conflict with patient-specific findings, or mis-parses nuanced criteria.
*   **Workflow Violation**: Agent fails to execute required action types or outputs malformed JSON, causing the DCR engine to stall.
*   **DCP Repository Corruption**: Early incorrect/unsafe DCPs get indexed, potentially degrading performance initially or causing a permanent ceiling.

### First 3 experiments
1.  **Primary Benchmark (MIMIC-CDM)**: Compare `DxEvolve` vs. `CDM baseline` and `DxEvolve w/o DCP` across multiple LLM backbones on the 400-case held-out set. *Purpose:* Isolate contribution of full DCR+DCP mechanism.
2.  **Ablation of External Knowledge**: Run `DxEvolve` with `Guideline Search` and `PubMed Search` disabled. *Purpose:* Quantify marginal contribution of real-time external knowledge vs. experiential learning from DCPs.
3.  **External Validation (Chinese Hospital Cohort)**: Apply the DCP repository built from MIMIC-CDM to a new institutional cohort (translated English and native Chinese records). *Purpose:* Test portability and generalizability of distilled experience across language, documentation style, and practice patterns.

## Limitations
*   **DCP Quality Dependency:** Efficacy hinges on the reflection prompt generating clinically accurate, reusable DCPs. No robust validation of DCP correctness beyond downstream performance; risk of compounding errors.
*   **Retrieval Configuration:** Critical hyperparameters (top-k, embedding model choices) are unspecified; reported gains may be sensitive.
*   **Generalizability Evidence:** External validation uses a single non-Western cohort; claims about broad portability lack multi-institution testing.

## Confidence
*   **Diagnostic Accuracy Gains (MIMIC-CDM):** High. Rigorous within-cohort evaluation with multiple backbones and key ablations.
*   **External Generalization (Chinese Cohort):** Medium. Positive result on a distinct cohort, but single-site with translation/normalization confounders.
*   **Auditable Self-Evolution Mechanism:** Low-Medium. Plausible mechanism supported by correlation, but lacks causal proof that retrieval itself drives improvement.

## Next Checks
1.  **Hyperparameter Sensitivity Analysis:** Systematically vary retrieval top-k, embedding models, and DCP filtering thresholds on a fixed split to quantify performance stability.
2.  **Multi-Site, Multi-Dataset Stress Test:** Evaluate a DCP repository built on MIMIC-CDM against *at least two* additional held-out cohorts from distinct institutions (e.g., MIMIC-IV, a European EHR).
3.  **DCP Content Audit & Failure Mode Correlation:** Manually annotate a sample of retrieved "high-impact" vs. "low-impact" DCPs for accuracy, relevance, actionability; correlate with case outcomes to verify error-correlation dynamic.
