# Integrating Machine Learning Ensembles and Large Language Models for Heart Disease Prediction Using Voting Fusion
## Quick Facts
- arXiv ID: 2602.22280
- Source URL: https://arxiv.org/abs/2602.22280
- Reference count: 35
- Primary result: Hybrid ML-LLM system achieved 96.62% accuracy and 0.97 ROC-AUC, a modest improvement over ML ensemble alone.

## Executive Summary
This study presents a hybrid framework that combines traditional machine learning ensembles with large language models (LLMs) for cardiovascular disease prediction. Using a merged dataset of 1,190 patient records, the authors first train a suite of gradient boosting and tree-based models (Random Forest, XGBoost, LightGBM, CatBoost, Gradient Boosting) that individually achieve high accuracy (95.78%) and ROC-AUC (0.96). In contrast, zero-shot LLMs perform poorly (78.9% accuracy). The proposed system then uses Gemini 2.5 Flash to provide meta-reasoning via a weighted voting mechanism, which marginally improves performance to 96.62% accuracy and 0.97 ROC-AUC. The authors argue that the LLM contributes by aiding in uncertain or borderline cases, though the exact mechanism and generalizability remain uncertain due to dataset limitations and proprietary model use.

## Method Summary
The hybrid fusion approach involves two parallel pathways: (1) a traditional ML ensemble that outputs predictions from multiple models, and (2) a large language model (Gemini 2.5 Flash) that receives a textual serialization of the patient's tabular data and produces a prediction or confidence scores. The final decision is made by a weighted voting scheme that combines the ensemble's predictions with the LLM's output. The weighting may be fixed or dynamically adjusted based on the LLM's assessment of case difficulty, though this is not fully specified. The ML models are trained on the merged dataset, while the LLM is used in a zero- or few-shot manner without fine-tuning. The textual conversion of tabular data is highlighted as a crucial factor for LLM performance.

## Key Results
- ML ensemble alone: 95.78% accuracy, 0.96 ROC-AUC.
- LLM alone (zero-shot): 78.9% accuracy.
- Hybrid ML-LLM system (Gemini 2.5 Flash): 96.62% accuracy, 0.97 ROC-AUC.

## Why This Works (Mechanism)
The hybrid system leverages complementary strengths: the ML ensemble provides robust, high-performance predictions from structured features, while the LLM adds contextual reasoning for cases where the ensemble's predictions are uncertain. By converting tabular data into natural language narratives, the LLM can interpret complex feature interactions, potential contradictions, and clinical context that may not be captured by conventional models. This meta-reasoning allows the LLM to effectively reweight or correct ensemble predictions on borderline cases, leading to a small but measurable improvement in overall accuracy and AUC.

## Foundational Learning
- **Ensemble Learning**: Combining multiple models to reduce variance and bias. *Why needed*: Achieves state-of-the-art performance on tabular data. *Quick check*: Train three different models on the same dataset and verify that voting or averaging improves accuracy over any single model.
- **Large Language Models (LLMs)**: Transformer-based models trained on vast text corpora, capable of few-shot reasoning. *Why needed*: Provides flexible, context-aware interpretation of patient data when expressed as text. *Quick check*: Use an open-source LLM (e.g., Llama 3) to generate a diagnosis from a textual description of symptoms and compare to ground truth.
- **Voting Fusion**: Aggregating predictions from multiple sources via weighted averaging or majority vote. *Why needed*: Merges heterogeneous model outputs (ensemble and LLM) into a single decision. *Quick check*: Implement a simple weighted sum of two model probabilities and evaluate on a validation set to see if weights can be optimized.
- **Meta-Reasoning**: Using a higher-level model to evaluate and adjust base model predictions. *Why needed*: Enables the LLM to identify uncertain cases and adjust contributions accordingly. *Quick check*: Compute prediction entropy from the ML ensemble; have an LLM re-predict only when entropy exceeds a threshold.
- **Tabular Data Textualization**: Converting structured data into natural language sentences. *Why needed*: Allows LLMs, which are trained on text, to process clinical features. *Quick check*: Convert a few patient records into "The patient is a 55-year-old male with chest pain, blood pressure 130/80..." and verify an LLM can extract key values.
- **Uncertainty Quantification**: Measuring confidence in model predictions. *Why needed*: To define "borderline cases" where LLM intervention is beneficial. *Quick check*: Use the softmax probability from an ensemble model; flag cases where the top two class probabilities are within 0.1 as uncertain.

## Architecture Onboarding
**Component Map**: Raw Patient Data -> Feature Preprocessing -> ML Ensemble (RF, XGBoost, LightGBM, CatBoost, GB) -> Ensemble Predictions; Raw Patient Data -> Textual Serialization -> LLM (Gemini 2.5 Flash) -> LLM Prediction; Ensemble Predictions + LLM Prediction -> Weighted Voting -> Final Diagnosis.

**Critical Path**: Data ingestion must succeed; textual conversion must produce valid prompt; LLM API must respond without error; ensemble models must load and predict; voting mechanism must execute; final output must be returned.

**Design Tradeoffs**: 
- Accuracy vs. cost: Adding LLM improves accuracy slightly but introduces API costs and latency.
- Transparency vs. performance: Proprietary Gemini model yields gains but hinders reproducibility; open-source LLMs may be less capable.
- Complexity vs. maintainability: Hybrid system is more complex than pure ML, requiring careful integration and monitoring of LLM failures.
- Generality vs. specificity: Textual serialization choices affect LLM performance; no standardized approach for medical tabular data.

**Failure Signatures**:
- LLM API returns error or timeout.
- LLM output is malformed or not parseable into a probability.
- Ensemble models fail to load (e.g., version mismatch).
- Voting weights sum to zero or produce NaN.
- Textual serialization loses critical numerical precision (e.g., rounding lab values).

**First Three Experiments**:
1. **Baseline replication**: Train the ML ensemble on the provided merged dataset and confirm the reported 95.78% accuracy and 0.96 ROC-AUC using identical cross-validation splits.
2. **LLM sensitivity analysis**: Vary prompt templates (zero-shot vs. few-shot) and textual serialization formats (e.g., JSON vs. narrative) to measure LLM accuracy alone; identify the best-performing prompt.
3. **Hybrid voting evaluation**: Implement weighted voting with different schemes (equal weight, ensemble weight 0.5/LLM 0.5, entropy-based dynamic weight). Compare hybrid performance to ensemble baseline on the test set; compute statistical significance.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: What specific characteristics of "uncertain or borderline" cases make LLM meta-reasoning more effective than the ML ensemble alone, and can these characteristics be formally defined?
- Basis in paper: [inferred] The authors state the hybrid system improved performance by aiding in "uncertain or borderline cases" (Abstract, Key Outcome) but do not define these cases or analyze *why* the LLM's reasoning was beneficial for them.
- Why unresolved: Understanding the precise nature of these cases is critical for trusting and deploying the hybrid system. Without this, the improvement is a black-box observation.
- What evidence would resolve it: A detailed error analysis comparing ML-only vs. hybrid predictions on a held-out set, identifying patient subgroups or feature patterns where the LLM corrected the ML, and quantifying the LLM's contribution (e.g., via ablation studies or SHAP/LIME analysis of the LLM's "reasoning").

### Open Question 2
- Question: Does the hybrid ML-LLM fusion framework maintain its performance advantage (0.86% accuracy gain) on larger, more diverse, and temporally modern cardiovascular datasets, and is it clinically safe/equitable across demographics?
- Basis in paper: [explicit] The "Limitations and Future Work" section explicitly states the main limitation is the "small harmonized cohort (1,190 records)" and calls for scaling to "bigger and more multifarious datasets" and "clinical incorporation towards safety and equity."
- Why unresolved: The single, old, merged dataset (1988-~2018) raises serious concerns about dataset shift, generalizability, and potential biases that could invalidate the modest reported gain or cause harm in practice.
- What evidence would resolve it: Rigorous external validation on at least 2-3 large, independent, and contemporary cardiac datasets (e.g., from national registries or modern EHRs). This must include subgroup analyses by age, sex, ethnicity, and comorbidity to assess fairness and calibration plots/reliability diagrams to assess clinical trustworthiness.

### Open Question 3
- Question: To what extent does the performance of the LLM ensemble (and thus the hybrid system) depend on the specific prompt engineering and the textual representation of the tabular data, and can this process be automated or optimized?
- Basis in paper: [explicit] The authors note LLM performance is "prompt-dependent" (Intro) and that "the input form is a crucial factor" with better accuracy when tabular data is "converted to the textual forms" (Discussion). They used manually crafted prompts for zero/few-shot settings.
- Why unresolved: The hybrid system's reliability is threatened by the known instability of LLM outputs to prompt variations. The process of "converting to textual forms" is not described or automated, making replication and systematic improvement difficult.
- What evidence would resolve it: A systematic sensitivity analysis varying prompt wording, structure, and few-shot example selection. Development and testing of an automated, consistent textual serialization protocol for tabular medical data. Benchmarking this protocol across multiple LLM families to see if the hybrid gain persists.

### Open Question 4
- Question: Is the observed minor improvement (96.62% vs. 95.78%) from adding the LLM layer statistically significant and clinically meaningful, given the known variability and cost of LLM inference?
- Basis in paper: [inferred] The paper highlights a "minor but measurable improvement" (Key Outcome) but provides no statistical tests (e.g., p-values, confidence intervals) for the accuracy/AUC difference between the ML ensemble and the hybrid. The LLM layer (Gemini 2.5 Flash) introduces API costs, latency, and non-determinism not present in the pure ML ensemble.
- Why unresolved: A small absolute gain may not be statistically significant on a single dataset. Even if significant, it may not justify the added financial cost, computational overhead, and operational complexity of integrating live LLM calls into a clinical decision support workflow.
- What evidence would resolve it: Reporting statistical significance (e.g., DeLong test for AUC, McNemar's test for accuracy) on the test set. A cost-benefit analysis comparing the marginal performance gain against LLM API costs, inference time, and failure modes (e.g., rate limits, hallucinations). A prospective simulation study estimating the hybrid's impact on clinical outcomes (e.g., true positive rate increase).

### Open Question 5
- Question: Does merging multiple historic datasets (Cleveland, Hungary, etc.) into a single cohort introduce hidden biases or distributional shifts that inflate ensemble model performance and threaten the validity of the hybrid framework's evaluation?
- Basis in paper: [explicit] The method states they used a "merged dataset" from five sources from 1988. The "Limitations" section notes this "small harmonized cohort... limits the extrapolation of the results."
- Why unresolved: Merging datasets from different geographies and eras can create batch effects where the model learns to predict the *source* of the data rather than the true disease signal. This could lead to over-optimistic performance estimates that collapse on new data from a single, modern source.
- What evidence would resolve it: Analysis of data source as a potential covariate. Evaluating model performance *within* each original dataset (Cleveland, Hungary, etc.) separately after training on the merged set to check for source-specific overfitting. A domain adaptation or batch effect correction study before merging. Training and testing on data from a single, modern source to establish a new baseline.

## Limitations
- Dataset constraints: small size (n=1,190), merged from multiple historic sources with potential batch effects, limited demographic and clinical diversity.
- Lack of transparency: The LLM's meta-reasoning process and the exact mechanism for identifying "uncertain cases" are not detailed; prompt engineering and textual serialization are not standardized.
- Proprietary dependency: Use of Gemini 2.5 Flash hinders reproducibility and independent verification; performance may not generalize to other LLMs.

## Confidence
- **Hybrid system superiority (96.62% vs 95.78%)**: Medium confidence (modest gain, no statistical tests, small dataset).
- **LLM contribution via uncertain cases**: Low confidence (not directly quantified or explained).
- **ML ensemble performance (95.78% accuracy, 0.96 ROC-AUC)**: High confidence (consistent with literature on similar datasets).

## Next Checks
1. Independent replication with open-source LLMs: Re-run the entire pipeline using a transparent, open-weight LLM (e.g., Llama 3.1) with the same dataset and voting protocol to verify if the performance gain persists without proprietary model black-box effects.
2. Ablation study on "borderline case" definition: Implement a formal uncertainty quantification method (e.g., prediction entropy from the ML ensemble) to systematically define borderline cases. Then, compare hybrid vs. ensemble performance *only* on this subset to isolate the LLM's contributory value.
3. External validation on a publicly available, larger cardiovascular dataset (e.g., UCI Heart Disease, Framingham Heart Study) to assess generalizability and rule out dataset-specific artifacts. Report performance with 95% confidence intervals from repeated stratified cross-validation.
