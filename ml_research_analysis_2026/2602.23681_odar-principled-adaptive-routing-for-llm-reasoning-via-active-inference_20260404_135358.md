# ODAR: Principled Adaptive Routing for LLM Reasoning via Active Inference

## Quick Facts
- **ArXiv ID:** 2602.23681  
- **Source URL:** https://arxiv.org/abs/2602.23681  
- **Reference count:** 40  
- **Primary result:** Adaptive routing with a lightweight difficulty estimator and free‑energy fusion yields 89.6% average accuracy (+6.0%) across 23 benchmarks and reduces compute by 82% versus Self‑Consistency in open‑source replication.

## Executive Summary
ODAR tackles the problem of inefficient test‑time compute scaling in LLM reasoning, where fixed best‑of‑N sampling wastes resources on easy queries and still over‑thinks hard ones. The system introduces a two‑agent architecture (fast heuristic + slow deliberative) and dynamically routes each query via a Difficulty Estimator (DE) that predicts computational demand from input features. For routed queries, a free‑energy‑principled fusion combines candidates by balancing likelihood with epistemic uncertainty (varentropy). Evaluated on 23 benchmarks, ODAR achieves 89.6% average accuracy—a 6.0% gain over strong baselines—and in a fully open‑source replication matches Self‑Consistency performance at 82% lower cost.

## Method Summary
ODAR’s core loop begins by extracting 24 lexical, structural, and semantic features from the input query. A lightweight linear DE, trained on a calibration set to predict a normalized difficulty score, estimates whether the query is Simple (fast agent only), Medium (fast agent followed by slow verification), or Hard (fast agent plus slow best‑of‑5). The fast agent (GPT‑5.1) always generates an initial response; the slow agent (Claude‑4.5) is invoked only for Medium and Hard paths. For fusion, candidate answers are scored by a variational free‑energy objective: character‑normalized negative log‑likelihood plus a λ‑weighted varentropy term. Per‑model statistics (mean, std) from a calibration set align scores across differing model distributions, and the answer minimizing free energy is selected.

## Key Results
- **Average accuracy:** 89.6% on 23 benchmarks (+6.0% over baselines).  
- **Peak performance:** 98.2% on MATH, 54.8% on HLE.  
- **Efficiency:** Matches Self‑Consistency with only 18% of the compute in a Llama 4 + DeepSeek replication (82% cost reduction).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** ODAR reduces unnecessary compute by dynamically routing queries based on predicted difficulty, avoiding uniform brute‑force sampling.  
- **Mechanism:** A lightweight Difficulty Estimator (DE) predicts a difficulty score `d(x) ∈ [0,1]` from input features. This score approximates the Expected Free Energy (EFE) of potential reasoning policies, bypassing costly simulation. Based on thresholds `τ1=0.3` and `τ2=0.7`, the query is routed to one of three paths: Simple (Fast Agent only), Medium (Fast generation + Slow verification), or Hard (Fast generation + Slow Best‑of‑N with FEP fusion).  
- **Core assumption:** The DE can reliably estimate the relative computational demand (epistemic value and pragmatic risk) of a query from surface and structural features, and this estimate correlates with the accuracy gains from additional compute.  
- **Evidence anchors:**  
  - [abstract] “ODAR uses a difficulty estimator grounded in amortized active inference to dynamically route queries between a heuristic Fast Agent and a deliberative Slow Agent.”  
  - [section 2.1] The DE is trained to predict `d*`, a proxy for EFE, using human time and Fast Agent accuracy as targets (Eq. 6).  
  - [section 3.2] The routing thresholds produce a weighted average of 2.55 calls per query vs. 5.0 for Self‑Consistency.  
- **Break condition:** The DE’s feature set may fail to capture novel reasoning patterns in out‑of‑distribution domains, leading to mis‑routing (e.g., routing a hard query to the Simple path). The ablation in [section 4.5] shows that removing the DE causes a 135% cost explosion on saturated tasks.

### Mechanism 2
- **Claim:** FEP‑Fusion selects more reliable answers by balancing model confidence (accuracy) with reasoning stability (varentropy), avoiding ad‑hoc voting over heterogeneous candidates.  
- **Mechanism:** Candidate answers from different models are scored by a variational free energy objective `F(y|x) ≈ -log‑likelihood + λ·varentropy`. To enable cross‑model comparison, energy is character‑normalized and Z‑score aligned using calibration statistics. The answer with minimum `F` is selected.  
- **Core assumption:** The variance of token‑level surprisal within a reasoning chain is a proxy for epistemic uncertainty (hallucination risk). Minimizing this variance filters unstable, high‑volatility generations.  
- **Evidence anchors:**  
  - [abstract] “a free‑energy‑principled, risk‑sensitive fusion mechanism that selects answers by minimizing a variational free energy objective, balancing log‑likelihood with epistemic uncertainty (varentropy).”  
  - [section 2] Derivation from Risk‑Sensitive Control (Appendix D) shows the variance term emerges from a second‑order Taylor expansion of the entropic risk measure.  
  - [section 3.5] Character‑level normalization and Z‑score alignment enable principled comparison across GPT‑5.1 and Claude‑4.5.  
- **Break condition:** The ergodicity assumption (temporal variance approximates ensemble variance) may fail for very short or highly structured outputs (e.g., code snippets with repetitive syntax), where aleatoric variance could dominate. [section D.3] notes excluding formatting tokens to mitigate this.

### Mechanism 3
- **Claim:** The Fast/Slow agent dichotomy, inspired by theta‑gamma coupling, enables efficient specialization where only high‑difficulty queries trigger expensive, deliberative processing.  
- **Mechanism:** The Fast Agent (`A_θ`, GPT‑5.1, low temperature) provides rapid pattern‑matching. The Slow Agent (`A_γ`, Claude‑4.5, higher temperature) performs extended verification or exploration. The DE’s output gates whether the Slow Agent is invoked at all, mimicking biological conditional computation.  
- **Core assumption:** There exists a functional dichotomy between heuristic (fast) and deliberative (slow) reasoning modes such that most queries can be correctly answered by the fast mode, and the slow mode’s benefit is highly non‑uniform across queries.  
- **Evidence anchors:**  
  - [abstract] “dual‑agent architecture… inspired by a functional neuro‑computational motif: under high cognitive demand, slower control rhythms can gate burst‑like recruitment of higher‑cost processing.”  
  - [section 3.3] Ablation shows homogeneous configurations degrade performance: using GPT‑5.1 for both agents reduces accuracy by 1.8%, while using Claude‑4.5 for both increases cost by 47%.  
  - [section 4.6] 41% of queries are handled by the Simple Path (instant response), confirming the prevalence of low‑difficulty tasks.  
- **Break condition:** The analogy is purely functional; if a task domain requires deep reasoning but exhibits surface simplicity (e.g., a deceptively simple math puzzle), the DE may misclassify it as Simple, triggering underthinking.

## Foundational Learning

- **Concept: Active Inference & Expected Free Energy (EFE)**  
  *Why needed here:* ODAR’s DE approximates the EFE (Eq. 4) to select reasoning policies. Understanding EFE as a trade‑off between pragmatic (goal achievement) and epistemic (uncertainty reduction) value explains why difficulty prediction is necessary.  
  *Quick check question:* How does minimizing Expected Free Energy differ from maximizing expected reward in standard reinforcement learning?

- **Concept: Variational Free Energy (FEP) & Risk‑Sensitive Control**  
  *Why needed here:* The FEP‑Fusion mechanism (Eq. 3) is derived from a risk‑sensitive objective. This justifies the inclusion of the varentropy penalty term as a principled way to penalize reasoning paths with high epistemic uncertainty.  
  *Quick check question:* Why does a Taylor expansion of the exponential utility (entropic risk measure) yield a mean‑variance objective, and what does the variance term represent in the context of LLM reasoning?

- **Concept: Amortized Inference**  
  *Why needed here:* Direct EFE computation is intractable. ODAR uses amortized inference—training a DE to predict EFE directly from inputs—to achieve test‑time efficiency. This is a core design choice for scalable routing.  
  *Quick check question:* What is the key difference between amortized inference and performing explicit planning/search at test time? What are the trade‑offs?

## Architecture Onboarding
- **Component map:**  
  Input Analyzer → Difficulty Estimator (DE) → Strategy Selector (SS) → {Fast Agent (Aθ)} → (if Simple) output; (if Medium) Slow Agent (Aγ) → FEP Fusion → output; (if Hard) Slow Agent (BoN=5) → FEP Fusion → output.

- **Critical path:**  
  1. Query `x` arrives.  
  2. Feature extraction `ϕ(x)` → DE → `d(x)`.  
  3. `d(x)` → SS → selects path `π*`.  
  4. If `π* = Simple`: `Aθ(x)` → output.  
  5. If `π* = Medium`: `Aθ(x)` → `yθ`; `Aγ(x, yθ)` → `yγ`; FEP‑Fusion({`yθ`, `yγ`}) → output.  
  6. If `π* = Hard`: `Aθ(x)` → `yθ`; `Aγ^i(x)` for `i=1..5` → `Yγ`; FEP‑Fusion({`yθ`} ∪ `Yγ`) → output.

- **Design tradeoffs:**  
  - **Latency vs. Accuracy:** Simple path gives instant answers (1.8 s) but is prone to underthinking on hard tasks. Hard path (median 12.4 s with parallelism) achieves highest accuracy but increases tail latency. Tradeoff managed by DE calibration.  
  - **Routing Complexity:** A single scalar `d` is interpretable and low‑overhead but may be less expressive than a full policy network (e.g., PPO in HierRouter). Forgone training complexity for inference simplicity.  
  - **Fusion Generality:** Character‑level + Z‑score alignment works across models but requires a calibration set. If a new model family has radically different logit scaling, calibration must be redone.

- **Failure signatures:**  
  - **DE misclassification (E1):** Hard query routed to Simple path → incorrect answer, low latency.  
  - **Verification failure (E3):** In Medium path, Slow Agent fails to catch Fast Agent’s error → incorrect answer, 4.2× cost.  
  - **FEP selection miss (E4):** Correct candidate exists but has higher free energy due to variance → incorrect answer, high cost in Hard path.  
  - **Model capability limit (E5/E6):** All agents fail due to knowledge/logic gaps → incorrect answer regardless of routing.

- **First 3 experiments:**  
  1. **DE Calibration Check:** On a held‑out set, verify that path labels (from `d*`) match human annotations of difficulty. Check distribution: ~41% Simple, 35% Medium, 24% Hard. Tune `τ1, τ2` to target desired cost‑accuracy tradeoff.  
  2. **Path‑Specific Accuracy Profiling:** Run ODAR on a diverse subset and compute accuracy per path. Expect: Simple path accuracy should be high on factual/commonsense tasks; Hard path should show largest gains on MATH/IMO/HLE. If Simple path accuracy is low on supposedly easy tasks, DE is under‑routing.  
  3. **Fusion Sanity Test:** Construct a synthetic candidate set with one clearly correct answer and one with high confidence but a subtle error (e.g., off‑by‑one). Validate that FEP‑Fusion selects the correct one. If not, inspect character‑normalized energies and Z‑score alignments for the involved models.

## Open Questions the Paper Calls Out
- **When does varentropy fail to capture epistemic uncertainty?** The paper’s Appendix D.2 assumes epistemic variance dominates for rigorous reasoning, but this assumption isn’t validated across diverse task domains. Controlled experiments where reasoning complexity and lexical variability are independently manipulated are needed to measure alignment between varentropy and actual error modes.
- **Can adaptive sampling reduce Hard Path compute while maintaining accuracy?** The Hard Path uses fixed Best‑of‑N with n=5; Figure 9 shows diminishing returns but no per‑query sample‑size optimization. An oracle analysis of optimal sample size stratified by difficulty could demonstrate that many queries achieve confidence thresholds with fewer than 5 samples.
- **Can FEP fusion work without token‑level log‑probabilities?** The current implementation requires per‑token log‑probs, which are unavailable for black‑box models and many APIs. Development of alternative uncertainty metrics from final outputs only (e.g., consistency across diverse prompts) validated to correlate with FEP selection quality remains future work.

## Limitations
- **Non‑reproducible calibration:** The calibration dataset `D_cal` (N=2,000) and exact human‑time mapping for targets `d*` are not released, preventing faithful DE training and threshold tuning.
- **Incomplete feature specification:** The extraction of 24 features ϕ(x) lacks implementation details (e.g., LaTeX handling, SBAR counting, domain classifier training), leading to potential drift.
- **Missing cross‑model calibration:** Model‑specific statistics (`µ_m, σ_m`) for FEP fusion are omitted, blocking verifiable scoring across heterogeneous LLMs.
- **Potential data leakage:** DE targets use human solution times from datasets that overlap with evaluation benchmarks (ARC, MATH), which may inflate results.
- **Fixed thresholds:** The thresholds `τ1=0.3, τ2=0.7` are not robustly validated beyond the GPT‑5.1/Claude‑4.5 pair and may overfit.

## Confidence
