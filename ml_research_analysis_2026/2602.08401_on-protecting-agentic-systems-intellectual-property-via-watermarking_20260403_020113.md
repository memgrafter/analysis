# On Protecting Agentic Systems' Intellectual Property via Watermarking

## Quick Facts
- **arXiv ID:** 2602.08401
- **Source URL:** https://arxiv.org/abs/2602.08401
- **Reference count:** 40
- **Primary result:** AGENTWM achieves perfect imitation attack detection (F1=1.0) and high user localization (0.92–1.0) with negligible service quality impact (≤3% degradation) via watermarking functionally equivalent action segments in grey-box agent deployments.

## Executive Summary
Agentic systems deployed in grey-box settings (only action sequences visible) are vulnerable to imitation attacks where adversaries replicate capabilities by training on victim outputs. Existing LLM watermarking fails here. AGENTWM introduces a novel approach that embeds watermarks by subtly biasing the distribution of functionally equivalent action segments—different tool paths achieving the same outcome—without altering final results. An offline pipeline automatically generates and validates watermark passes. During deployment, a user-specific subset of passes activates, subtly altering the agent's chosen action paths. Verification uses Jensen-Shannon Divergence on a suspect model's action distribution to detect theft and localize the source user. Across three domains, AGENTWM achieves perfect detection, high localization accuracy, maintains trajectory quality, and remains robust against removal attempts.

## Method Summary
AGENTWM operates in two phases. Offline, a generator identifies semantically equivalent action segments (e.g., different tool calls with identical effects) using embeddings and LLM analysis; a verifier executes these in a sandbox to confirm functional equivalence. Validated equivalence sets become "watermark passes," each defining a target distribution that over-represents one segment via exponential scaling. Online, each registered user receives a unique binary UID that activates a specific subset of passes. When the agent generates a trajectory, the inserter replaces any segment belonging to an active pass with a sample from that pass's biased distribution. For verification, a private dataset queries the suspect model; its empirical action distribution per pass is compared to the target via JSD. If enough passes exceed a detection threshold, the model is flagged as stolen. The set of detected passes forms a fingerprint matched against UIDs to identify the leaking user.

## Key Results
- Perfect detection performance (F1=1.0) on stolen models across three domains.
- High user localization accuracy (0.92–1.0) even with large user pools (50k).
- Negligible impact on service quality: trajectory success rate, reasoning score, and task score degrade by ≤3%.
- Minimal runtime overhead (0.28% latency increase).
- Robustness: attackers cannot remove the watermark without causing severe utility loss (~36% drop in trajectory quality).
- Stealthiness: watermarked trajectories are statistically indistinguishable from clean ones in terms of perplexity.

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** AGENTWM embeds a verifiable watermark into the action trajectory by subtly biasing the selection among functionally equivalent action segments, without perceptibly degrading service utility.
**Mechanism:** The defender precomputes equivalence sets of action segments. For each set, a target distribution over segments is constructed that over-represents a designated “target” segment via exponential scaling. During inference, when a segment from the set appears in the agent’s raw action sequence, it is replaced by a sample from the biased distribution. The rest of the trajectory remains unchanged, preserving functionality.
**Core assumption:** Many agentic tasks admit multiple semantically equivalent action sequences, and the grey-box setting provides a stable channel for watermark injection.
**Evidence anchors:** Abstract and Section 4.1 define watermark passes as biased distributions over equivalence sets. Related work shows watermarking IP is possible but does not address the grey-box agentic challenge.
**Break condition:** If a trajectory contains no segments from any active equivalence set, no watermark is inserted. Overly strong bias (high δ) degrades trajectory quality and may alert adversaries.

### Mechanism 2
**Claim:** Statistical verification via Jensen–Shannon Divergence (JSD) thresholding can reliably detect whether a suspect model was trained on watermarked outputs.
**Mechanism:** The verifier queries the suspect model with a private dataset and computes the empirical distribution of corresponding action segments. The JSD between this distribution and the target watermarked distribution is calculated. A pass is “detected” if its JSD is below a threshold θ_J. If the total number of detected passes ≥ θ_N, the model is classified as an imitation.
**Core assumption:** The imitation model will faithfully reproduce the watermarked distribution because it was trained on watermarked trajectories. The JSD metric provides a consistent signal given enough samples.
**Evidence anchors:** Abstract mentions an automated pipeline and hypothesis testing. Section 5.2 details the two-level thresholding (θ_J and θ_N). Prior text watermarking (e.g., KGW) uses similar testing; AGENTWM adapts it to the distribution-level action space.
**Break condition:** If the attacker’s fine-tuning data is too small or low-quality, the model may not converge to the watermarked distribution, causing false negatives. Natural distributions already matching the target could cause false positives; the two-level threshold mitigates this.

### Mechanism 3
**Claim:** By assigning each user a unique subset of watermark passes (via a random UID), AGENTWM can localize the source of a stolen model to a specific user with high accuracy.
**Mechanism:** Upon registration, each user receives an N‑bit UID. The i‑th bit determines whether pass P_i+1 is activated. When a suspicious model is verified, the set of detected passes forms a binary fingerprint. The verifier compares this fingerprint against stored UID‑to‑pass mappings using a similarity metric (cosine similarity). The user with the highest similarity is identified as the attacker.
**Core assumption:** Watermark passes are sufficiently numerous and independent to yield unique fingerprints, and detection recovers activated passes with low noise.
**Evidence anchors:** Abstract reports high user localization (0.92–1.0). Section 4.2 describes UID generation and pass assignment; Section 5.2 explains localization via similarity matching.
**Break condition:** Too few passes per user cause fingerprint collisions. If the attacker sees too few watermarked trajectories, some assigned passes may not be detected, leading to incomplete fingerprints and mis-matches.

## Foundational Learning
- **Concept:** Imitation Attack (Model Extraction)
  - *Why needed here:* The threat model assumes an adversary queries the victim agent to collect trajectories and fine-tunes a public model to replicate its capabilities. Understanding this attack explains why watermarking is necessary.
  - *Quick check question:* What data does an attacker collect from a grey‑box agentic system, and how is it used to clone the model?
- **Concept:** Grey‑box Deployment Constraint
  - *Why needed here:* AGENTWM is designed for settings where only the action sequence (and final response) is visible, not the full reasoning chain. This constraint invalidates prior LLM watermarking and motivates the action‑level approach.
  - *Quick check question:* Why do many commercial agentic platforms adopt a grey‑box visibility model, and what does this imply for IP protection?
- **Concept:** Trajectory Equivalence
  - *Why needed here:* The core insight is that multiple distinct action sequences can be functionally equivalent, providing a space to bias distributions without affecting outcomes. This enables watermarking despite grey‑box constraints.
  - *Quick check question:* Give an example of two action sequences that are semantically equivalent in an agentic system (e.g., from the CE or VR schemes).

## Architecture Onboarding
- **Component map:** Tool Library -> Embedding + LLM Analysis -> Candidate Pairs -> Execution Sandbox (Verifier) -> Validated Equivalence Sets -> Watermark Passes (with target distributions) -> User Management (UID assignment) -> Online Inserter (mutates agent trajectories) -> Served Grey‑box Outputs. Verification Service: Suspect Model + Private Dataset -> Empirical Distributions -> JSD Computation -> Detection Thresholding (θ_J, θ_N) -> Localization (similarity matching) -> Attacker UID.
- **Critical path:**
  1. Offline: Tool library → (embedding + LLM analysis) → candidate pairs → (execution sandbox) → validated equivalence sets → watermark passes (with target distributions).
  2. Online: User request → agent generates trajectory → inserter mutates actions per user’s active passes → serve grey‑box trajectory.
  3. IP theft check: Obtain suspect model → query with private dataset → compute empirical distributions → JSD test → count detections → if ≥ θ_N, perform localization → output attacker UID.
- **Design tradeoffs:**
  - *Watermark strength (δ) vs. fidelity:* Larger δ increases detectability (higher KLD) but degrades trajectory quality (TS). δ=2–3 recommended.
  - *Number of active passes per user vs. capacity:* More passes improve detection confidence but reduce total unique UIDs. Hamming weight constraint 5–20 balances.
  - *JSD threshold (θ_J) and count threshold (θ_N):* Lower θ_J yields more sensitive per‑pass detection but risks false positives; θ_N controls overall false positive rate. θ_N=3 default.
  - *Automated pipeline recall vs. precision:* Generator prunes with embeddings (high recall) but may include false positives; verifier eliminates them (precision). This separation ensures scalability without sacrificing reliability.
- **Failure signatures:**
  - High degradation in PR/RS/TS for watermarked models → watermark insertion too aggressive or poor equivalence set selection.
  - Low F1 detection on known stolen models → thresholds mis‑configured (e.g., θ_N too high) or insufficient pass coverage.
  - Poor localization accuracy with large user pools → too few distinguishing passes per domain or collisions due to Hamming weight too low.
  - Perplexity gap between watermarked and clean trajectories → watermarks not stealthy; distribution shifts too large.
  - High variance in robustness tests → attackers still able to remove watermarks with limited quality loss; δ too low or schemes insufficiently diverse.
- **First 3 experiments:**
  1. **Fidelity baseline:** Fine‑tune Mvic on Dft and evaluate Mvic vs. Mimi (trained on watermarked data) across PR, RS, TS, ARC, ACPBench. Ensure ≤3% degradation.
  2. **Detection validation:** Train positive (watermarked) and negative (clean) imitation models. Vary θ_J and θ_N, compute F1‑score for stolen model detection. Confirm near‑perfect F1 (≥0.95) with recommended thresholds.
  3. **Localization scalability:** Simulate a pool of users (e.g., 12 malicious + 50K benign). Run verification on each stolen model, compute top‑1 accuracy of UID matching. Target ≥0.92.

## Open Questions the Paper Calls Out
Can AGENTWM be extended to agentic systems with highly deterministic or low-redundancy action spaces where functionally equivalent segments are rare? How does the approach scale to domains requiring long-horizon planning with many interdependent actions? Are there theoretical guarantees on the minimum number of watermark passes needed for a given false positive/negative rate? Could adversaries develop adaptive attacks that selectively alter only the watermarked segments while preserving overall utility more effectively than simple fine-tuning?

## Limitations
- Equivalence set generation may fail for deterministic or highly constrained action spaces where functionally equivalent alternatives are scarce.
- The verification process requires a held-out private dataset from the defender, which may not be accessible in all deployment scenarios.
- Watermark strength (δ) and threshold parameters (θ_J, θ_N) require per-domain tuning; inappropriate values either degrade utility or reduce detection reliability.
- No theoretical bounds on unremovability under worst-case adaptive attacks; empirical robustness tests use standard fine-tuning only.

## Confidence
- **Detection performance:** High (near-perfect F1 in controlled experiments on three domains).
- **Localization accuracy:** Medium (0.92–1.0 for user pools up to 50k; collision risk grows with larger pools).
- **Quality impact:** High (≤3% degradation demonstrated; likely generalizable to moderately redundant domains).
- **Robustness:** Medium (resists basic fine‑tuning attacks; untested against sophisticated adaptive removal).
- **Stealthiness:** Medium (perplexity indistinguishable; other statistical anomalies not fully explored).
