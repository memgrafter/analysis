# LLM Router: Prefill is All You Need

## Quick Facts
- arXiv ID: 2603.20895
- Source URL: https://arxiv.org/abs/2603.20895
- Reference count: 9
- Primary result: Closes 45.58% of the accuracy gap between the best standalone model and the Oracle while achieving 74.31% cost savings; consistently outperforms all evaluated semantic routers.

## Executive Summary
Large language model (LLM) routing aims to assign queries to the most suitable model from a pool, balancing accuracy and cost. Existing routers rely on semantic signals that are fragile and fail to capture intrinsic task difficulty. This paper introduces a novel approach called Encoder-Target Decoupling, which uses prefill activations from a separate encoder model to predict the correctness of target models. Layer selection is guided by Fisher Separability, and a SharedTrunkNet architecture enables joint multi-target confidence estimation. On a mixed-tier model pool, the method closes 45.58% of the accuracy gap to the Oracle and saves 74.31% cost compared to the most expensive model, outperforming all semantic routers.

## Method Summary
The proposed router operates in three stages. First, a frozen encoder model processes the query in a prefill pass, and hidden states from a carefully selected layer (identified by high Fisher Separability) are extracted. Second, for each target model, these activations are pooled and reduced via pre-fitted PCA to produce a feature vector. All target-specific feature vectors are concatenated into a joint representation. Third, a multi-output neural network (SharedTrunkNet) with a shared hidden trunk and per-target output heads consumes this joint representation to estimate the probability that each target model would answer correctly. The final routing decision combines these confidence estimates with normalized cost metrics. This design decouples the signal source from the target, enabling prediction even for closed-source models, and leverages cross-model context to improve confidence calibration.

## Key Results
- Closes 45.58% of the accuracy gap between the best standalone model and the theoretical Oracle.
- Achieves 74.31% cost savings versus the highest-cost model in the pool.
- Consistently outperforms all evaluated semantic routers across standardized routing efficacy metrics.

## Why This Works (Mechanism)
### Mechanism 1: Encoder-Target Decoupling
- **Claim:** Using internal prefill activations from a separate, possibly open-source "Encoder" model can predict the correctness of a different "Target" model (including closed-source) more effectively than using the Target's own states.
- **Mechanism:** The router extracts hidden-state activations from the upper layers of the Encoder during the prefill phase. These activation vectors are treated as a high-fidelity signal of the query's intrinsic complexity. A classifier (probe) is then trained to map this signal to the binary correctness label of the Target model on that query. This decoupling allows the optimal pairing of any Encoder to any Target, bypassing the need for Target-specific access.
- **Core assumption:** The activation geometry of a sufficiently capable Encoder model during prefill encodes information about task difficulty that is predictive of a diverse set of Target models' performance, regardless of architectural differences.
- **Evidence anchors:**  
  [abstract] "Encoder-Target Decoupling—a functional separation between the model providing the predictive signal (the Encoder) and the model whose performance is being estimated (the Target)."  
  [section 4.3] "...we evaluate three operational modes: per model (fixed assignments), single (one encoder for all targets), and auto (optimal encoder per target)."  
  [corpus] Neighboring papers (e.g., TensorOpera Router) focus on semantic or cost-based routing; none explicitly evaluate cross-model activation decoupling for closed-source prediction, so direct corpus support is weak.
- **Break condition:** The predictive advantage disappears if the Encoder is significantly less capable than the Target pool or if the activation spaces of Encoder and Target are fundamentally misaligned (e.g., drastically different tokenization or architecture families).

### Mechanism 2: Fisher Separability-Guided Layer Selection
- **Claim:** Optimal predictive power is not found in the final layer but in a specific intermediate layer identified by high Fisher Separability (J) and substantial Effective Dimensionality (d_eff).
- **Mechanism:** For each Encoder-Target pair, the router sweeps across transformer layers. It computes J (the ratio of between-class to within-class variance in PCA-reduced activations, using correctness labels) and d_eff (a measure of information distribution across PCA components). The layer with the highest J is selected as the signal source, under the assumption that high linear separability of correct/incorrect responses indicates a crystallized "correctness direction."
- **Core assumption:** A layer where correct and incorrect responses form linearly separable clusters in activation space is the most informative for a linear probe. d_eff ensures this separability exists in a sufficiently rich subspace to avoid PCA information loss.
- **Evidence anchors:**  
  [section 7] "Fisher J-based layer selection perfectly conforms to empirical probe sweeps, providing an explainable foundation for our results."  
  [section 4.3] "Layer selection is determined by a grid search validated with 5-fold stratified cross-validation using L2-regularized logistic regression." (Implies the J-guided selection replaces brute-force search).  
  [corpus] The corpus contains no direct references to using Fisher J for layer selection in LLM routing; this appears to be a novel probe from this work.
- **Break condition:** The J metric becomes unstable or uninformative if the task distribution has very few "incorrect" samples (low variance in one class) or if the PCA dimensionality reduction critically distorts the cluster geometry.

### Mechanism 3: SharedTrunkNet for Cross-Model Context
- **Claim:** A single multi-output neural network ("SharedTrunkNet") that takes concatenated activation features from all Encoder-Target pairs and outputs simultaneous confidence estimates for all Targets outperforms independent per-model probes.
- **Mechanism:** The input feature vector `x` (Eq. 1) concatenates PCA-reduced activations from the *same* Encoder layer but for *all* Target models. The SharedTrunkNet has a shared hidden trunk that processes this joint representation before branching into per-Target output heads. This allows the shared layers to learn representations that capture relative query difficulty (e.g., "this query is hard for Model A but easy for Model B") by comparing the activation patterns across the embedded Target-specific subspaces.
- **Core assumption:** The relative pattern of activation magnitudes/directions across different Target models' projected spaces encodes a signal about comparative model strengths that is lost when each Target is probed in isolation.
- **Evidence anchors:**  
  [section 4.3] "Joint optimization provides two advantages over independent probes: Cross-model context: features from one encoder supply complementary evidence about query difficulty for other models."  
  [table 3] SharedTrunkNet achieves the highest mean per-model AUC and lowest Brier across all pools compared to semantic multi-task baselines.  
  [corpus] Related work (e.g., Stripelis et al.) uses a unified multi-task network but for semantic features, not cross-encoder activation concatenation; the specific architecture is novel.
- **Break condition:** The benefit vanishes if the Target models are nearly identical (no complementary strengths to model) or if the shared trunk introduces harmful interference between the learning signals of very dissimilar Targets.

## Foundational Learning
- **Concept: Transformer Prefill Activations & Residual Stream**  
  **Why needed here:** The entire mechanism hinges on extracting and interpreting the hidden state vectors (`hidden_states`) from specific layers *before* any decoding begins. Understanding that these vectors form a continuous, high-dimensional representation of the prompt's processed meaning is essential.  
  **Quick check question:** Why might the activation geometry at layer *L/2* contain different information about task solvability than the final layer's output?

- **Concept: Fisher's Linear Discriminant & PCA for Signal Probing**  
  **Why needed here:** The paper's layer selection criterion (J) and dimensionality reduction (PCA) are core to identifying a separable, information-rich signal. The learner must grasp that J measures class separation *after* PCA, not in the raw high-D space.  
  **Quick check question:** If a layer's raw activations have high d_eff but low J after PCA, what does that suggest about the nature of the "correctness" signal at that layer?

- **Concept: Multi-Task Learning & Shared Trunk Architectures**  
  **Why needed here:** SharedTrunkNet is a specific multi-task design. The learner needs to understand the trade-off: a shared trunk can learn common, cross-Target representations (helpful for context) but risks task interference if objectives conflict.  
  **Quick check question:** In the SharedTrunkNet loss function (BCE per head), what would be a symptom that the shared trunk is failing to provide useful cross-Target context?

## Architecture Onboarding
- **Component map:**  
  Query Input -> Encoder Model (frozen, prefill only) -> Activation Extractor (per Target, selected layer) -> Pooling & PCA (per Target) -> Feature Concat (all Targets) -> SharedTrunkNet (MLP with shared trunk + K heads) -> Confidence & Cost Calcs -> Routing Policy (score_k,q = λ * P(correct_k) - (1-λ) * norm_cost_k,q) -> argmax selects model

- **Critical path:** Query → Encoder Prefill → Targeted Layer Extraction → PCA per Target → Concatenation → SharedTrunkNet forward pass → K confidence scores → Routing policy decision. *Note: PCA transforms and layer selections are pre-determined hyperparameters from the training sweep.*

- **Design tradeoffs:**  
  - **Encoder size vs. latency:** Larger encoders (Qwen-122B) yield better AUC (Table 2) but increase prefill latency. The paper assumes router overhead can be amortized by caching.
  - **Layer selection heuristic:** Fisher J is cheap and model-free but assumes separability in PCA space is the ideal proxy. A grid search over layers is still required during *training* to find the peak-J layer.
  - **Joint vs. Independent probes:** SharedTrunkNet risks negative transfer if one Target's signal corrupts another's representation. The consistent gains (Table 3) suggest cross-model context is net positive in heterogeneous pools.
  - **Cost normalization:** Normalizing cost to `[0,1]` using *training-set* min/max (Eq. 4) makes the router's cost sensitivity a stable, zero-shot property. A break occurs if test-set costs fall outside the training range.

- **Failure signatures:**  
  - Low per-model AUC (<0.7) on validation for a specific Target: Indicates a bad Encoder-Target pairing or wrong layer selected for that Target.
  - High Brier score (>0.2) for SharedTrunkNet: Indicates poor calibration, possibly due to distribution shift in test-set difficulty or insufficient joint training data.
  - Router accuracy barely above "Model-only Pareto": SharedTrunkNet is not learning useful cross-Target context; the pool may have insufficient performance variance or the activation features are not discriminative.
  - Cost savings negative or low: The `λ` sweep curve is flat or the router defaults to expensive models. Confidence predictions are not correlating with actual cost-effectiveness.

- **First 3 experiments:**  
  1. **Encoder-Target Pair Validation:** For a fixed pool, train independent logistic regression probes on PCA features from the *final layer* of a single encoder for all targets. Compute per-target AUC. Identify if any Target has AUC near 0.5 (random). If so, that pairing fails; try a different encoder or layer.
  2. **Layer Sweep & J Correlation:** For the best encoder from Exp 1, extract activations from *every layer* (L/2 to L) for a small calibration set. For each layer, compute PCA-reduced features, train a quick probe, and record validation AUC. Separately, compute `J` and `d_eff` for that layer's activations. Plot AUC vs. J. Expect a strong positive correlation. If not, the J-based selection assumption may not hold for this Encoder-Target pair.
  3. **Shared vs. Independent Probe Test:** Train three models on the same `x` feature set: (a) Independent MLPs (one per Target), (b) SharedTrunkNet, (c) A single "unified" head predicting correctness for *any* model (ignoring model ID). Compare mean per-model AUC and Brier. SharedTrunkNet should beat (a) and (c). If (a) wins, the pool may be too homogeneous for cross-context benefits.

## Limitations
- Encoder capability gap: The core assumption that any sufficiently capable Encoder predicts any Target fails if the Encoder is significantly weaker; break condition not stress-tested across diverse model families.
- PCA dependency: Pre-fitted PCA transforms per Encoder-Target pair are hyperparameters; distribution shift in test activations could distort the reduced subspace, breaking the linear separability assumption.
- Cost normalization fragility: Normalizing costs using training-set min/max makes the router's cost-sensitive scoring unstable if test-set costs fall outside the training range.

## Confidence
- Encoder-Target Decoupling: Medium
- Fisher J-guided layer selection: Medium-High
- SharedTrunkNet gains: Medium

## Next Checks
1. **Encoder capability boundary test:** Systematically degrade Encoder size (e.g., Qwen-122B → 7B) and measure AUC drop for a fixed Target pool; identify the minimal capability ratio where prediction fails.
2. **PCA robustness stress test:** Apply distribution-shifted activation sets (e.g., novel task domains) to pre-fitted PCA transforms; monitor per-target AUC decay and re-calibrate PCA online to quantify sensitivity.
3. **SharedTrunkNet negative transfer probe:** Construct a homogeneous pool (e.g., three Llama-2 variants) and compare SharedTrunkNet vs. independent probes; a performance drop would confirm interference risks.
