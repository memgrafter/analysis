# Crab$^{+}$: A Scalable and Unified Audio-Visual Scene Understanding Model with Explicit Cooperation

## Quick Facts
- arXiv ID: 2603.04128
- Source URL: https://arxiv.org/abs/2603.04128
- Reference count: 40
- Primary result: Reverses negative transfer (from 55% degradation to 88% positive transfer) and matches/surpasses specialized models on benchmarks (e.g., 81.09% on AVQA, 79.62% on ARIG).

## Executive Summary
Crab+ addresses the problem of severe negative transfer in multi-task audio-visual large language model training, caused by heterogeneity in task granularity and capability demands. The authors construct a large-scale instruction-tuning dataset, AV-UIE v2, containing 222K samples with explicit step-by-step reasoning processes to bridge gaps between low-level perception and high-level reasoning tasks. They also propose a unified input-output interface mapping all tasks to sequence generation, and an Interaction-aware LoRA (I-LoRA) module that uses token-level dynamic routing to decouple conflicting audio-visual interaction patterns. This combination reverses negative transfer, achieving positive multi-task transfer in 88% of evaluated tasks across 7 diverse audio-visual tasks. Crab+ covers a broader task range than prior unified models and attains performance comparable to or better than specialized models on key benchmarks such as AVQA (81.09%) and ARIG (79.62%).

## Method Summary
Crab+ employs a unified architecture where audio and video inputs are processed by pre-trained encoders (Whisper for audio, Qwen2.5-VL for vision). Their features are projected by connectors (e.g., Q-Former for video, MLP for audio) into the hidden dimension of a frozen large language model backbone (e.g., Qwen2.5-Omni). All tasks are formulated as sequence generation: the model outputs textual answers, captions, timestamps, or spatial prompts (bounding boxes, points). For segmentation, the predicted spatial prompts are fed to a frozen SAM2 module to produce masks, decoupling grounding from mask generation. The core innovation is Interaction-aware LoRA (I-LoRA), which injects trainable low-rank updates into the LLM layers. I-LoRA uses a shared low-rank matrix **A** and multiple **B**-head matrices specialized for different interaction patterns. A router computes token-wise weights to softly combine the heads’ contributions, reducing parameter interference among tasks. Training proceeds in two stages: first, pre-train the connectors on single-task data; second, multi-task instruction tuning on AV-UIE v2, optimizing only I-LoRA (and optionally connectors) via next-token prediction.

## Key Results
- Positive transfer achieved in 88% of tasks, reversing the typical 55% negative transfer observed in naive multi-task training.
- Matches or surpasses specialized models on benchmarks: AVQA (81.09%), ARIG (79.62%), and others.
- Covers 7 tasks across 17 datasets, a broader spectrum than prior unified audio-visual models.

## Why This Works (Mechanism)
**1. Explicit Reasoning Chains Bridge Granularity Mismatch**  
AV-UIE v2 converts original task labels into step-by-step textual reasoning chains, forcing the model to generate intermediate semantic content reusable across tasks. This intermediate representation connects low-level perception (e.g., pixel-level localization) and high-level reasoning (e.g., question answering). Dataset construction uses Gemini 1.5 Pro with consistency checks to ensure quality. If reasoning chains become noisy, they could harm performance; a two-step verification (consistency + human review) mitigates this risk.

**2. Unified Input-Output Interface Eliminates Architectural Bottlenecks**  
All tasks are mapped to sequence generation, avoiding disjoint module training. Outputs not naturally sequential (e.g., dense masks) are handled by predicting spatial prompts that are passed to a frozen SAM2, effectively decoupling grounding from mask generation. This interface assumes a single autoregressive objective can accommodate all required output formats.

**3. Interaction-aware LoRA (I-LoRA) Decouples Conflicting Updates**  
I-LoRA learns a shared low-rank matrix **A** capturing common audio-visual representations and multiple **B**-head matrices that specialize for different interaction patterns. A router assigns token-wise weights to softly combine the heads’ contributions, preventing interference between tasks with divergent capability demands. The router’s design assumes task differences can be modeled by distinct linear subspaces. Ablation and visualizations show heads cluster by task and dropping any head degrades performance, confirming complementary specializations. If the router produces uniform weights, interference may reappear; using multiple heads helps maintain separation.

## Architecture Onboarding
**Component map**  
Input encoders (Whisper audio encoder, Qwen2.5-VL visual encoder) extract features, which are processed by connectors (Q-Former for video, MLP for audio) to produce token sequences. These tokens are concatenated with text instruction tokens and fed into a frozen LLM backbone (e.g., Qwen2.5-Omni) that contains I-LoRA modules inserted into its linear layers. A router attached to each I-LoRA module computes token-level routing weights. For segmentation tasks, the LLM outputs spatial prompts which are passed to a frozen SAM2 module to generate masks.

**Critical path**  
1. Preprocess video into frames and audio into segments.  
2. Encode frames and audio to obtain visual tokens H_v and audio tokens H_a.  
3. Fuse: concatenate H = [H_v; H_a; H_t] where H_t are instruction text tokens.  
4. Process the sequence through the LLM: each transformer layer applies I-LoRA by multiplying features with shared A, routing to multiple B heads via router R, aggregating the weighted updates, and adding them to the original outputs.  
5. Autoregressively decode the output token sequence.  
6. If the task requires spatial segmentation, parse bounding boxes or points from the output and run SAM2 to produce the final mask.

**Design tradeoffs**  
- *Unified interface vs. task-specific heads:* The unified approach enables single-stage training on all tasks but may not optimally handle highly specialized outputs; SAM2 decoupling mitigates this for segmentation.  
- *Dynamic routing vs. static LoRA:* Routing adds minimal parameters but introduces routing computation and a hyperparameter (number of heads). Too few heads may not separate tasks; too many may overfit.  
- *Explicit reasoning in data:* Reasoning chains improve cross-task transfer but increase data construction cost and may add irrelevant verbosity for simple tasks.

**Failure signatures**  
- *Negative transfer persists:* Some tasks still degrade in multi-task settings, indicating insufficient router separation or head capacity.  
- *Router weights uninformative:* Visualization shows near-uniform weights; the router is not differentiating tasks. Remedy: increase head count or adjust temperature.  
- *Poor spatial grounding:* SAM2 fails despite correct prompts, possibly due to prompt format errors or connector issues.  
- *Overfitting on reasoning:* Model generates excessively verbose or incorrect reasoning for simple classification tasks, suggesting mismatched reasoning granularity in the dataset.

**First 3 experiments**  
1. **Baseline negative transfer reproduction:** Train a multi-task model with standard (non-interaction-aware) LoRA on AV-UIE v2. Expect ~55% of tasks to degrade compared to single-task baselines, confirming the problem.  
2. **I-LoRA vs. LoRA comparison:** Replace standard LoRA with I-LoRA under identical multi-task training. Expect positive transfer on ~88% of tasks and overall performance gains, validating the mechanism.  
3. **Head ablation:** Systematically drop each B-head in I-LoRA and evaluate all tasks. Expect consistent degradation across tasks, confirming that heads learn complementary specializations.

## Limitations
- Auto-generated reasoning chains may contain noise or irrelevant details, potentially harming tasks that require concise answers.
- The reliance on a frozen SAM2 for segmentation limits end-to-end optimization and may propagate SAM2’s failures.
- The router’s scalability to larger task sets remains uncertain; it has only been validated on 7 tasks.

## Confidence
- Negative transfer reversal (55% → 88% positive transfer): **High** (extensive ablations).  
- Explicit reasoning chains bridging granularity mismatch: **Medium** (indirect evidence; no robustness test for chain noise).  
- Unified interface with SAM2: **Medium-High** (effective but contingent on external module).  
- I-LoRA dynamic routing decoupling tasks: **High** (ablation and visualizations confirm).  
- Broader task coverage than prior unified models: **High** (covers 7 tasks).  
- Benchmark performance parity/superiority: **High** (numbers match or exceed specialized models).

## Next Checks
1. **Reasoning chain ablation:** Train Crab+ on AV-UIE v2 without explicit reasoning (using original labels only). A significant drop in multi-task transfer would confirm the chains’ bridging role.  
2. **Router head scaling:** Vary the number of B-heads in I-LoRA (e.g., 1, 3, 6, 12). Analyze routing entropy, task clustering, and performance to determine optimal capacity and overfitting thresholds.  
3. **SAM2 replacement with end-to-end mask head:** Substitute the two-stage segmentation with a lightweight decoder trained on the same prompts. Compare IoU on spatial tasks; improvement would indicate SAM2 as a bottleneck.
