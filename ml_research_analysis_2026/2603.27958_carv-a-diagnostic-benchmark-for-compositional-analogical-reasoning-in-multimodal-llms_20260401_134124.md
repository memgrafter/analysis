# CARV: A Diagnostic Benchmark for Compositional Analogical Reasoning in Multimodal LLMs
## Quick Facts
- **arXiv ID:** 2603.27958
- **Source URL:** https://arxiv.org/abs/2603.27958
- **Reference count:** 27
- **Primary result:** Introduces CARV, a 5,500-sample benchmark revealing large performance gaps in MLLMs (best: 64.6% shared-source, 40.4% different-source) vs. human (100%), with decomposition and scaling as key failure modes.

## Executive Summary
The paper presents CARV, a novel diagnostic benchmark designed to test compositional analogical reasoning in multimodal large language models (MLLMs). The task requires models to extract symbolic transformation rules from multiple image pairs, compose them via set operations (union, intersection, difference), and apply the composed rule to a query image. Evaluation across state-of-the-art MLLMs shows a substantial performance gap, with the best model achieving only 64.6% on the simpler shared-source setting and 40.4% on the more challenging different-source setting, far below the human ceiling of 100%. Diagnostic analysis identifies two primary failure modes: (1) decomposing perceived visual changes into correct atomic symbolic rules, and (2) maintaining accuracy as the number of atomic transformations or contextual divergence increases.

## Method Summary
CARV constructs a controlled visual domain with five fixed properties (subject, object, color, number, spatial relation) and limited value sets to isolate reasoning from open-world perception variability. Images are generated by editing a base set (from Kamath et al., 2023) using Gemini-2.5 Flash Image, creating pairs that embody one or more atomic transformations. For each sample, the model receives 2–4 source image pairs and a query image, then outputs a caption describing the resulting image after applying a set operation over the transformation rules. Accuracy is evaluated by comparing the model’s caption to a ground-truth caption using GPT-4o as an automated judge. An optional diagnosis prompt forces stepwise reasoning (perception, decomposition, composition, application) to pinpoint failure stages.

## Key Results
- **Benchmark scale and design:** 5,500 samples covering set operations, two settings (shared-source, different-source), and varying numbers of atomic transformations (|T| = 1–4).
- **Performance gap:** SOTA MLLMs (GPT-5.1, Gemini-2.5 Pro) achieve ≤64.6% (shared-source) and ≤40.4% (different-source) versus a human ceiling of 100%.
- **Failure modes:** Decomposition of visual changes into atomic symbolic rules is the earliest and most frequent error for closed-source models; performance degrades significantly as |T| increases and in the different-source setting.

## Why This Works (Mechanism)
**Mechanism 1: Symbolic decomposition failure**
Models often correctly perceive visual differences but fail to abstract them into discrete, manipulable symbolic rules (e.g., `(color, wood, red)`). Their internal representations remain at a descriptive level (e.g., “the table became red”), preventing logical composition. Evidence: Section 5.3 shows decomposition is the dominant failure stage for closed-source models. Ablation providing ground-truth rules yields 94–99% accuracy on subsequent steps, confirming rule inference is the bottleneck.

**Mechanism 2: Scaling with multiple transformations**
As the number of concurrent atomic changes per image pair increases, models struggle to disentangle and identify all rules, leading to missed or incorrectly bundled transformations. Evidence: Section 5.4 shows decomposition failure rates rise with |T| while perception errors remain stable or decrease. Figure 6 depicts consistent accuracy drops when moving from |T|=2 to |T|=3/4.

**Mechanism 3: Different-source setting difficulty**
When the query image differs from source images, models cannot rely on shallow visual matching or memorization, forcing true rule abstraction and generalization. The consistent accuracy drop from shared-source to different-source (e.g., Gemini-2.5 Pro Union: 51.6% → 40.4%) reveals a reliance on superficial cues in the easier setting.

## Foundational Learning
- **Symbolic Rule Extraction**: Converting a visual change into a structured `(property, from_value, to_value)` tuple. *Why needed*: Enables set operations over transformations. *Quick check*: Given “blue cup → red cup”, the atomic rule is `(color, blue, red)`.
- **Set Operations as Logical Composition**: Applying Union, Intersection, Difference to rule sets. *Why needed*: Core task requires combining rules from multiple pairs. *Quick check*: If `T1 = {color: wood→red}` and `T2 = {color: wood→blue}`, then `T1 ∩ T2 = ∅`.
- **Controlled Visual Domain Taxonomy**: Fixed property set and value lists. *Why needed*: Isolates reasoning from noisy perception. *Quick check*: The five properties are subject, object, color, number, spatial relation.
- **Error Stage Diagnosis Pipeline**: Breaking reasoning into perception → decomposition → composition → application. *Why needed*: Locates bottlenecks for targeted improvement. *Quick check*: Correct image descriptions but wrong final caption suggest failure in composition or application.
- **Contextual Divergence**: Varying object identities across source and query images. *Why needed*: Tests abstraction beyond superficial matching. *Quick check*: In shared-source, `I_q = I₁`; in different-source, all images are distinct.

## Architecture Onboarding
**Component map:**  
Data Generator → Task Formulator → Model Executor → Evaluator → Diagnosis Annotator

**Critical path:**  
Base image creation → Sample `(T1, T2, O, setting)` → Generate `(I₁, I₁'), (I₂, I₂'), (I_q, I_a)` → Build prompt → Query MLLM → Evaluate caption → (Optional) Parse stepwise response → Aggregate accuracy and error distributions.

**Design tradeoffs:**  
- *Controlled domain vs. ecological validity*: Synthetic, noise-free images isolate reasoning but limit real-world generalizability.  
- *Caption output vs. image generation*: Avoiding generative tasks prevents compounding errors from imperfect image models.  
- *Direct vs. diagnosis prompting*: Diagnosis pipeline pinpoints failures but may alter natural model behavior.

**Failure signatures:**  
- *Perception*: Incorrect property value (e.g., “blue” instead of “red”), wrong count, or spatial relation.  
- *Decomposition*: Non-atomic rules (bundling properties) or incorrect `from`/`to` values.  
- *Composition*: Wrong set operation result (e.g., missing a rule unique to one set).  
- *Application*: Rule correctly composed but misapplied to query image.

**First three experiments:**  
1. **Baseline replication**: Re-run Table 2 for 2–3 models (e.g., GPT-5.1, Gemini-2.5 Pro, Qwen3VL-8B-Thinking) to confirm reported accuracy gaps and human ceiling.  
2. **Error stage profiling**: Use diagnosis prompts on a stratified subset (e.g., 200 samples) to compute per-stage failure rates and replicate Figure 3a,b.  
3. **Complexity scaling**: Train a logistic regression on model correctness vs. property combinations to replicate Figure 4’s finding that subject+position and number+position are hardest.

## Open Questions the Paper Calls Out
**Open Question 1**: What underlying architectural or training deficiencies cause MLLMs to fail at decomposing multiple concurrent visual transformations into discrete symbolic rules?  
*Basis*: Diagnostic pipeline shows decomposition is the earliest and most frequent failure for closed-source models; oracle ablation yields near-perfect later steps, pointing to decomposition as the core bottleneck.  
*Why unresolved*: No probe into internal causes (e.g., representation disentanglement, supervision, vision-language fusion).  
*What evidence would resolve*: Compare architectures with explicit rule extraction training; analyze attention/activations during multi-transformation processing.

**Open Question 2**: Why do MLLMs exhibit a larger performance drop in the different-source composition setting compared to the shared-source setting, and what specific cognitive or representational challenges does it reveal?  
*Basis*: Consistent accuracy drop from shared-source to different-source (e.g., Gemini-2.5 Pro Union: 51.6% → 40.4%) suggests reliance on shallow matching in the easier setting.  
*Why unresolved*: No experimental isolation of factors (object identity interference, rule generalization difficulty).  
*What evidence would resolve*: Systematically vary object identity/shape/background while fixing transformations; test explicit abstract rule output.

**Open Question 3**: How does increasing the number of atomic transformations per input pair affect the scalability of compositional reasoning in MLLMs, and what is the breaking point where performance collapses?  
*Basis*: All models show clear performance decline as |T| grows from 2 to 3/4; decomposition failures rise with |T|.  
*Why unresolved*: Study stops at |T|=4; unknown if degradation is gradual or catastrophic; interaction with set operations unexplored.  
*What evidence would resolve*: Extend experiments to |T|=5,6; probe iterative vs. parallel processing; compare with models having explicit working memory.

**Open Question 4**: Why do certain property combinations (e.g., subject+position, number+position) cause disproportionately high failure rates, and does this point to specific weaknesses in spatial or numerical understanding?  
*Basis*: Logistic regression weights (Figure 4) show high positive contributions for subject+position and number+position; error breakdown (Figure 5) shows subject+position fails mainly at decomposition, number+position also at perception.  
*Why unresolved*: No isolation of whether issues stem from vision encoder spatial reasoning, number mapping, or property interference.  
*What evidence would resolve*: Test on separate spatial/number benchmarks; causal interventions swapping property values; analyze free-form captioning biases.

## Limitations
- Dataset generation details (source images, Gemini editing prompts, quality heuristics) are not fully disclosed, hindering faithful replication.
- The GPT-4o judge prompt for overall accuracy evaluation is not published; minor variations could affect reported numbers.
- The synthetic, constrained domain limits ecological validity and generalizability to real-world scenes.
- Diagnosis prompting forces stepwise reasoning, potentially altering natural model behavior and error attribution.

## Confidence
- **Benchmark isolates compositional analogical reasoning**: Medium (rigorous design but lacks independent replication).
- **Large performance gap**: High (empirical numbers, human ceiling).
- **Decomposition is primary failure mode**: High (oracle ablation and systematic error analysis).
- **Accuracy degrades with increased transformations/contextual divergence**: High (consistent trends across settings).

## Next Checks
1. Recreate the dataset using a deterministic renderer or alternative image-editing model to confirm failure modes are not artifacts of Gemini-based generation.
2. Conduct human annotation on model outputs to validate the diagnosis pipeline’s error stage assignments and compute inter-annotator agreement.
3. Test whether fine-tuning MLLMs for explicit symbolic rule extraction improves CARV performance and transfers to other composition tasks (e.g., VOILA, KiVA).
