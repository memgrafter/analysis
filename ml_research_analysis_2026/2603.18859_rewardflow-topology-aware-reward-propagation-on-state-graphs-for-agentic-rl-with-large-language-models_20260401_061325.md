# RewardFlow: Topology-Aware Reward Propagation on State Graphs for Agentic RL with Large Language Models

## Quick Facts
- **arXiv ID**: 2603.18859
- **Source URL**: https://arxiv.org/abs/2603.18859
- **Reference count**: 40
- **Primary result**: RewardFlow significantly improves success rates on multiple agentic RL benchmarks (e.g., ALFWorld +7.0% absolute, Sokoban +28.0%) with negligible runtime overhead (≤2.4 s per step).

## Executive Summary
RewardFlow tackles the challenge of sparse rewards in agentic reinforcement learning with large language models by constructing a state graph from sampled trajectories and propagating terminal success backward via multi-source inverse BFS. This yields dense, topology-aware process rewards without training a separate reward model. The system transforms these state rewards into action-level gains and combines them with trajectory-level advantages to update the policy via a PPO-style objective. Experiments on ALFWorld, WebShop, Sokoban, and DeepResearch demonstrate consistent improvements over strong baselines (RLOO, GRPO, GiGPO). For instance, with Qwen2.5-7B-Instruct, RewardFlow achieves 89.8% success on ALFWorld (+7.0% over GiGPO) and 62.4% on Sokoban (+28.0%), while adding minimal computational overhead.

## Method Summary
During training, RewardFlow collects multiple trajectories from the current policy. It normalizes states to merge equivalent representations and prunes invalid transitions, then builds a directed graph where nodes are distinct states and edges are valid transitions. A multi-source inverse BFS from successful terminal states computes each state’s shortest-hop distance to success; state rewards are decayed exponentially by this distance (R(s) = γ^d(s)). These state rewards are projected back to transitions to compute action-level gains as differences between consecutive state rewards. Advantages combine action-level gains (normalized per normalized state) with trajectory-level advantages derived from terminal success. The policy is updated with a PPO-style clipped objective using per-token importance ratios and a KL penalty. This approach provides dense supervision without separate reward modeling and shows strong empirical performance.

## Key Results
- Consistent improvements: ALFWorld 89.8% (+7.0%), Sokoban 62.4% (+28.0%), DeepResearch 49.1% (+1.9%) over GiGPO/GRPO.
- Runtime overhead: ≤2.4 seconds per training step.

## Why This Works (Mechanism)
### Mechanism 1: State Graph Construction
**Claim:** RewardFlow constructs a unified state graph from multiple trajectories that captures the intrinsic topological relationships among states, enabling analysis of state-wise contributions to success.

**Mechanism:** It normalizes states (canonicalization for equivalence, feature enrichment for ambiguity) and prunes invalid/noisy transitions. It aggregates states and observed valid actions across trajectories to build a directed graph where nodes represent distinct states and edges represent valid transitions. This graph approximates the underlying Markov chain of the environment.

**Core assumption:** Equivalent states across trajectories can be reliably merged, and the graph structure meaningfully reflects task difficulty and success pathways.

**Evidence anchors:** [abstract], section 3.2; related work includes graph reasoning paradigms but RewardFlow’s graph is specifically derived from on-policy rollouts without external knowledge.

**Break condition:** If state normalization fails to merge semantically equivalent states, the graph becomes fragmented, reducing connectivity and impairing BFS. If invalid actions are not properly pruned, spurious edges distort distances.

### Mechanism 2: Backward BFS Propagation
**Claim:** By performing backward BFS from all successful terminal states, RewardFlow assigns each reachable state a propagated reward that decreases monotonically with graph distance to success, yielding dense supervision.

**Mechanism:** Compute shortest-hop distance d(s) to nearest success node via inverse BFS. Set R(s) = γ^d(s) with γ ∈ (0,1]. This creates a smooth decay: states closer to success get higher values.

**Core assumption:** Shortest graph distance to success correlates with the state's inherent potential to lead to task completion; in deterministic or clustered stochastic settings, this metric approximates state quality.

**Evidence anchors:** [abstract], section 4.1 (Equation 3 and description: "propagated reward measures the promise of a state to solve the agentic task successfully"); related work like transductive reward inference uses graph propagation but RewardFlow's BFS is simpler and tailored to agentic graphs from LLM rollouts.

**Break condition:** Graph may have disconnected components; states not reachable from any success node receive R(s)=0 (or ∞). In highly stochastic environments like DeepResearch, state clustering is needed to avoid contradictions; without it, repeated contradictory rewards could destabilize training.

### Mechanism 3: Action-Level Advantages
**Claim:** Transforming state rewards into action-level gains (potential differences) and combining with trajectory-level advantages yields dense, robust credit assignment even in data-poor states.

**Mechanism:** For transition (s,a,s'), define ˜r = R(s') - R(s). Then compute state-wise baseline μ(ˆs) and scale σ(ˆs) from all actions observed in that state to get Aaction = (˜r - μ)/σ. Combine with Atraj from terminal success via A = α_action*Aaction + α_traj*Atraj.

**Core assumption:** The difference R(s')-R(s) accurately reflects the action's contribution; combining local and global signals preserves advantages of both: fine-grained discrimination where multiple actions exist, and coverage where only single path is seen.

**Evidence anchors:** [abstract], section 4.2 (Equations 4–9 and explanation of synergistic advantages); related work like "Enhancing Agentic RL with Progressive Reward Shaping" uses dense rewards but RewardFlow's are derived from topology rather than hand-crafted shaping.

**Break condition:** In states with only one observed action (Group(ˆs) size=1), Aaction is undefined so Atraj solely determines advantage. If α_traj is small, advantage may become zero, providing no learning signal. Also, if μ and σ are poorly estimated due to very few samples, Aaction can be high-variance.

## Architecture Onboarding
### Component Map
TrajectoryCollector → StateNormalizer → GraphBuilder → BFSPropagator → RewardMapper → AdvantageComputer → PolicyUpdater

### Critical Path
Trajectories → normalize → graph → BFS → state rewards → action rewards → advantages → policy gradient → updated πθ. Note: Graph construction and BFS are batch-level; they require all G trajectories before computing advantages.

### Design Tradeoffs
- **Group size G**: Larger G yields denser graphs but more memory/time; diminishing returns after ~8 (Tab 4).
- **γ decay**: Controls reward spread; lower γ makes distant states near-zero faster. Paper uses 0.9.
- **α_action, α_traj**: Balance local vs global signal. Default 1,1 but could be tuned for specific task structure.
- **State normalization**: Embedding threshold (DeepResearch) vs string matching; more aggressive clustering reduces fragmentation but risks over-merging distinct states.
- **Invalid action filtering**: Must align with environment’s validity check; overly strict removes meaningful diversity, too lenient injects noise.

### Failure Signatures
- Extremely sparse graph (<10 nodes for a typical task) → likely state normalization/merging broken or policy producing repetitive trajectories. Check merge thresholds.
- Large fraction of nodes with R(s)=0 (unreachable) → batch contained no successful trajectory; increase G or adjust temperature.
- High variance in Aaction across timesteps in same state → insufficient samples per state; increase G or smooth σ with larger ε.
- Training instability (exploding loss) after reward propagation → verify BFS distances are finite; check for cycles or incorrect ∞ handling; consider scaling advantages.

### First Three Experiments
1. **Toy deterministic MDP validation**: Build a 5-node chain with clear success at node 5. Sample one trajectory from start to success. Run RewardFlow; verify R decays exponentially from node 5, and ˜r is positive along the chain, negative on backward edges. Inspect graph matches expected.
2. **Ablation of state normalization**: On ALFWorld with Qwen2.5-1.5B, run with/without state enrichment (e.g., not appending transformation features). Compare graph size (nodes/edges) and validation success rate; expect ~25% drop without normalization (Tab 5). Also check fragmentation: more duplicate nodes.
3. **Limited rollout robustness**: Train on ALFWorld with fixed total trajectories but varying G (batch size 256, G = 4, 6, 8). Compare success rates and graph statistics. Expect monotonic improvement with larger G, but also measure time overhead; evaluate efficiency tradeoff.

## Open Questions the Paper Calls Out
1. **How does RewardFlow perform in environments where state representations are not inherently informative (e.g., high-dimensional visual inputs or highly ambiguous text)?**  
   Basis: [explicit] "A current limitation is its dependence on informative states for effective graph construction, which presents challenges in environments where state representations lack rich problem-solving information."  
   Why unresolved: The paper evaluates only on simple text-based and visual tasks (ALFWorld, WebShop, Sokoban, DeepResearch). It remains unclear whether graph construction yields meaningful topological signals when states are raw pixels or otherwise noisy/dense.  
   What evidence would resolve it: Test RewardFlow on complex domains like Atari games or robotic manipulation where states are images; measure graph connectivity and final success rates, perhaps augmenting with representation learning to improve state clustering.

2. **Can graph neural networks (GNNs) be integrated into RewardFlow’s propagation to improve reward estimation in semantically rich environments while maintaining efficiency?**  
   Basis: [inferred] Appendix C.3 discusses potential benefits of GNNs for incorporating node/edge features, but notes current challenges (data collection, training overhead, online graph dynamics) that limit application in on-policy RL.  
   Why unresolved: No GNN variant is implemented or evaluated; the trade-off between richer propagation and computational cost remains unknown.  
   What evidence would resolve it: Design a hybrid where a lightweight GNN is pre-trained on collected graphs (e.g., from StarCraft replays) to predict state values, then compare performance and runtime against the hand-crafted BFS propagation in a fixed-task environment with abundant offline data.

3. **What is the theoretical justification for using minimum hop distance in propagation, and could adaptive strategies (e.g., uncertainty-weighted distances) further improve credit assignment?**  
   Basis: [inferred] Table 11 shows min-distance propagation outperforms mean-distance in Sokoban; the authors argue that distant routes dilute the signal, but no formal analysis is provided.  
   Why unresolved: The choice is heuristic; properties like monotonicity, robustness to graph noise, and effects on convergence are not studied.  
   What evidence would resolve it: Derive bounds on variance/accuracy of state values under different aggregation rules; conduct systematic experiments varying graph sparsity/structure to measure sample efficiency and final performance across multiple benchmarks.

4. **How does RewardFlow scale to extremely large state-action spaces (e.g., open-world web interaction) in terms of graph construction and propagation time?**  
   Basis: [inferred] Figure 7 and Table 9 report ≤2.4 s overhead for small graphs (max 42 nodes, 77 edges). The claim of “negligible runtime overhead” is based on these small scales; scaling behavior for larger graphs is not addressed.  
   Why unresolved: As trajectory diversity and length increase, graph size could grow substantially, potentially making BFS and storage costly; no analysis of asymptotic complexity or incremental update mechanisms is given.  
   What evidence would resolve it: Measure time/memory as a function of group size and horizon; extrapolate to larger scales; experiment with approximate BFS or incremental graph updates to maintain efficiency.

## Limitations
- State normalization may over‑merge or under‑merge states, distorting graph topology; no analysis of graph accuracy.
- BFS propagation assumes graph distance ≈ state quality; fails under stochasticity or disconnected components.
- Advantage computation uses per‑state statistics that are high‑variance with few samples; risk of noisy gradients.
