# The Agentic Researcher: A Practical Guide to AI-Assisted Research in Mathematics and Machine Learning

## Quick Facts
- **arXiv ID:** 2603.15914
- **Source URL:** https://arxiv.org/abs/2603.15914
- **Reference count:** 27
- **Primary result:** The framework enables autonomous, long-running research sessions and has produced a 5% improvement in validation perplexity over the Muon optimizer for LLM pretraining, an 18–50% perplexity reduction for LLM pruning, and a tight theoretical lower bound for the Frank-Wolfe algorithm.

## Executive Summary
This paper presents a practical framework for integrating AI into everyday mathematical and machine learning research. It introduces a five-level taxonomy of AI integration and an open-source system that uses CLI coding agents (e.g., Claude Code) guided by ten methodological “commandments” within a sandboxed container. The framework supports autonomous, long-running research sessions by maintaining structured artifacts (report.tex, TODO.md) and using Git for version control. Case studies demonstrate concrete gains: improved LLM pretraining, effective pruning, and a new theoretical bound. The system scales from a single laptop to multi-node clusters and is publicly available.

## Method Summary
The framework operates inside a sandboxed container (e.g., Docker) that contains all necessary dependencies (Python, Julia, LaTeX, Git). A CLI coding agent, instructed by a persistent INSTRUCTIONS.md file, follows an eight-step loop: Explore → Plan → Implement → Evaluate → Analyze → Record → Commit → Iterate. The agent documents every experiment in a structured LaTeX report (report.tex) with required fields (Goal, Hypothesis, Method, Implementation, Results, Analysis, Next Steps) and updates a TODO.md checklist. Git commits encapsulate each experiment, creating an external memory that survives context resets. The agent also adheres to ten “commandments” that enforce scientific rigor (e.g., change only one variable per experiment, verify before claiming, bound expectations). The researcher periodically inspects the artifacts and steers the investigation. The container can dispatch experiments to local or Slurm-based compute nodes, enabling scalable execution.

## Key Results
- 5% improvement in validation perplexity over the Muon optimizer for LLM pretraining.
- Weight reconstruction method for LLM pruning reduces perplexity by 18–50% across model scales.
- Mathematical proof of a tight lower bound $\Omega(1/T^{p/(p-1)})$ for the Frank-Wolfe algorithm on uniformly convex sets for $p\ge3$.
- Autonomous sessions have run over 20 hours, dispatching experiments across multiple nodes.

## Why This Works (Mechanism)

### Mechanism 1: Methodological Commandments Enforce Rigor
- **Claim:** The ten commandments prevent common failure modes (e.g., cherry-picking, unreproducible results, hallucinated citations), thereby increasing trustworthiness.
- **Mechanism:** Each commandment is a falsifiable, explicit rule embedded in the agent’s persistent instruction file. They govern the experiment loop (e.g., “Change exactly one thing per experiment”, “Verify before claiming”) and force the agent to document failures, run verification scripts, and produce structured reports.
- **Core assumption:** Language models will follow literal, well‑specified instructions consistently and the addressed failure modes are indeed the most prevalent in autonomous research.
- **Evidence anchors:** The abstract mentions “methodological rules formulated as agent prompts” and “ten methodological ‘commandments’”. Section 3.2 details each commandment and the specific failure mode it mitigates. The corpus includes similar agentic frameworks that emphasize guardrails.
- **Break condition:** If the agent circumvents the commandments (e.g., due to context window compression or ambiguous prompts), the protective effect collapses, leading to unverified claims or invalid experiments.

### Mechanism 2: Persistent Artifact Structure and Versioning Provide Continuity
- **Claim:** The structured artifacts (report.tex, TODO.md) and Git versioning create an external memory that outlives the agent’s context window, enabling inspectability, reproducibility, and human re‑entry.
- **Mechanism:** The agent is required to record every experiment in a LaTeX subsection and update the TODO list after each iteration. Git commits encapsulate each experiment, allowing the researcher to review progress, restart from any commit, and trace the full experimental history. After context resets, the agent re‑reads these files to restore continuity.
- **Core assumption:** The agent will reliably update the artifacts and the researcher will periodically review them to steer the investigation.
- **Evidence anchors:** The abstract states that all progress is recorded in a single LATEX file complemented by a TODO.md checklist. Section 3.1 describes the eight‑step loop and the re‑reading requirement. Section 4.1 notes “each of the more than 40 experiments was documented in the agent’s report.tex”.
- **Break condition:** If the agent fails to update the artifacts (e.g., due to a crash or forgetting) or the artifacts become too large to manage, continuity and reproducibility are lost.

### Mechanism 3: Sandboxed Container Provides Safety and Reproducibility
- **Claim:** Running the framework inside a sandboxed container isolates the agent’s actions from the host system and ensures a reproducible software stack, enabling safe, long‑running sessions across diverse compute environments.
- **Mechanism:** The container (e.g., Docker) contains all dependencies (Python, Julia, LaTeX, Git) and confines the agent’s operations. This prevents accidental host damage and makes experiments portable. The same image can be launched on a laptop or scaled to multi‑node Slurm clusters.
- **Core assumption:** The container image is correctly configured and the agent’s actions are indeed confined within it.
- **Evidence anchors:** The abstract mentions “sandboxed container… scales from personal‑laptop prototyping to multi‑node, multi‑GPU experimentation”. Section 3.1 explains confinement. Section 4.1 describes the multi‑node launcher that dispatches experiments to remote Slurm nodes.
- **Break condition:** Misconfigured container permissions or an agent escape (e.g., via a shell exploit) would compromise security and reproducibility.

## Foundational Learning
- **Concept:** Five‑level taxonomy of AI integration  
  **Why needed here:** The framework corresponds to Level 4 (“AI as Research Associate”), where the agent operates autonomously within a structured plan. Understanding the taxonomy helps researchers choose the appropriate level and recognize that the system still requires human steering.  
  **Quick check question:** What distinguishes Level 3 (“AI as Collaborator”) from Level 4 in terms of human involvement and agent autonomy?

- **Concept:** The ten commandments  
  **Why needed here:** These are the core operational rules that convert a generic CLI agent into a disciplined research assistant. Without grasping them, a user cannot effectively instruct the agent or interpret its behavior.  
  **Quick check question:** What is the rationale behind Commandment VIII (“Bound Your Expectations”) and how does it prevent wasted effort?

- **Concept:** Structured experiment recording (report.tex fields)  
  **Why needed here:** The agent’s output is only as useful as its documentation. The required fields (Goal, Hypothesis, Method, Implementation, Results, Analysis, Next Steps) ensure every experiment is self‑contained and reviewable.  
  **Quick check question:** Why is it critical to include failures in the report, as mandated by Commandment IX?

## Architecture Onboarding

**Component map:**  
Researcher prepares project directory → Launches sandbox container → CLI Agent (guided by INSTRUCTIONS.md) reads/writes report.tex and TODO.md, makes Git commits, and dispatches experiments to a compute layer (local machine or Slurm cluster). All components (instruction file, artifacts, version control, domain tools) reside inside the container.

**Critical path:**  
1. Researcher prepares project directory with a clear research question, codebase, and data.  
2. Researcher launches the sandbox and starts the CLI agent.  
3. Agent asks clarifying questions, then writes project‑specific INSTRUCTIONS.md.  
4. Agent initializes report.tex and TODO.md, proposes an initial plan.  
5. Researcher approves the plan; agent enters the autonomous eight‑step loop (Explore → Plan → Implement → Evaluate → Analyze → Record → Commit → Iterate).  
6. Researcher periodically inspects report.tex and TODO.md to steer or adjust the plan.

**Design tradeoffs:**  
- *Inspectability vs. automation:* Prioritizing human‑readable artifacts requires more researcher review time but builds trust.  
- *Generality vs. specialization:* Using generic CLI agents makes the framework model‑agnostic but limits expressiveness to shell commands; domain‑specific tasks may need custom integrations.  
- *Autonomy vs. control:* Level 4 grants long‑running autonomy with strict guardrails; too many rules could stifle creativity, too few risk invalid results.

**Failure signatures:**  
- Agent repeatedly skips steps (violates Commandment I) → report missing experiments.  
- Agent changes multiple variables → results cannot be attributed (violates Commandment VI).  
- Agent claims improvements without theoretical bounds (violates Commandment VIII) → likely overfitting.  
- Context loss due to compaction → agent forgets prior results or repeats failed approaches.  
- Hallucinated citations appear in report → unverifiable references.

**First 3 experiments:**  
1. **Baseline replication:** Run the existing baseline (e.g., Muon optimizer) to establish a reference metric and confirm environment setup.  
2. **Single‑variable modification:** Implement a simple, isolated change (e.g., add weight decay) to test the agent’s ability to execute the experiment loop and document properly.  
3. **Tiered evaluation validation:** Verify the agent correctly uses Tier 1 (does it run?), Tier 2 (quick sanity check on a small subset), and Tier 3 (full benchmark) before drawing conclusions.

## Limitations
- Practical reproducibility is hindered because the exact container setup (runtime, image tag, volume mounts) and sample researcher instruction templates are not detailed in the provided excerpt.
- The framework hinges on the agent reliably following the ten commandments; context window compression, ambiguous prompts, or “laziness” could silently break this.
- It remains unclear whether the commandments and artifact structure can maintain scientific rigor over hundreds or thousands of autonomous experiments.

## Confidence
- Case study results (5% Muon improvement, 18–50% pruning gain, proof bound): **Medium**
- Five‑level taxonomy and ten commandments as effective guardrails: **Medium**
- Containerized sandbox and artifact‑driven continuity: **High**

## Next Checks
1. **Git Commit Audit:** Run a single experiment and verify every commit message follows the pattern `exp(EXXX): <desc> -- metric=value`.  
2. **Single‑Variable Enforcement:** After three consecutive experiments, inspect report.tex to confirm each “Method” section declares exactly one independent variable changed from the prior entry.  
3. **Context Restoration Test:** Halt the agent after 10 experiments, clear its context, and restart. Query the agent for the last experiment’s hypothesis and result; it should correctly read report.tex and TODO.md to recover state.
