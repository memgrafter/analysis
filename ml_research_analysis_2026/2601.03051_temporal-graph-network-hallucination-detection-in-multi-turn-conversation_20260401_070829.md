# Temporal Graph Network: Hallucination Detection in Multi-Turn Conversation

## Quick Facts
- **arXiv ID:** 2601.03051
- **Source URL:** https://arxiv.org/abs/2601.03051
- **Reference Count:** 9
- **Primary Result:** TGN[ET] achieves 0.5468±0.0332 multiclass accuracy on DiaHalu, outperforming the GCA baseline (0.4343).

## Executive Summary
This paper tackles the problem of detecting hallucinations in multi-turn dialogues, where a model's response may contain six distinct types of inconsistencies. The authors propose a Temporal Graph Network (TGN) that represents each dialogue turn as a node in a graph, connected by temporal edges (sequential turns) and shared-entity edges (common named entities). Graph Neural Networks propagate contextual information across this structure, and an attention pooling mechanism aggregates node embeddings into a dialogue-level representation for classification. On the DiaHalu benchmark, the TGN[ET] variant yields a multiclass accuracy of 0.5468±0.0332, significantly surpassing prior baselines. Ablations confirm the value of shared-entity edges, and attention weights offer a rationale for model decisions.

## Method Summary
The method builds on three pillars: encoding, graph construction, and classification. First, each dialogue turn is encoded into a fixed-dimensional vector using the `All-MiniLM-L6-v2` sentence transformer, while named entities are extracted per turn using Gemini 2.5 Flash Lite. These components feed into a graph builder that creates two edge types: directed temporal edges between consecutive turns and undirected shared-entity edges linking turns that share at least one entity (exact matching details unspecified). A relational GNN (RGCN-style) performs message passing to update node embeddings, considering edge types. Updated embeddings are pooled into a dialogue-level embedding via attention, where each turn’s contribution is weighted. Finally, a linear classifier predicts one of six hallucination types. Training uses cross-entropy loss and a `WeightedRandomSampler` to mitigate severe class imbalance. Evaluation is averaged over 25 random splits (80:20 train/validation).

## Key Results
- TGN[ET] reaches 0.5468±0.0332 multiclass accuracy on DiaHalu, beating the prior GCA baseline (0.4343).
- Ablation studies show that removing shared-entity edges degrades performance markedly, highlighting their importance.
- The attention mechanism produces turn-level importance scores, which the authors claim provide decision justification.

## Why This Works (Mechanism)
The TGN mechanism operates by representing dialogue turns as nodes in a graph with two edge types: temporal edges for sequential flow and shared-entity edges for entity-based consistency. A relational graph convolutional network (RGCN) performs message passing across these edges, updating each turn's embedding by aggregating information from neighboring turns while respecting edge semantics. This allows context from any turn to influence others, enabling detection of inconsistencies that span the conversation. An attention-based pooling mechanism then computes a dialogue-level embedding by weighting turns according to their relevance to the classification task. The authors claim this yields interpretability via attention weights, though this is not quantitatively validated (see Confidence). Ablation studies confirm that removing shared-entity edges significantly reduces performance, highlighting the importance of entity coherence tracking.

## Architecture Onboarding
**Component Map:**  
Sentence Encoder (All-MiniLM-L6-v2) → Turn Embeddings  
Entity Extractor (Gemini 2.5 Flash Lite) → Entity Sets per Turn  
Graph Builder → Graph with Temporal & Shared-Entity Edges  
GNN (RGCN) → Updated Turn Embeddings  
Attention Pooling → Dialogue Embedding  
Classifier → Hallucination Type  

**Critical Path:**  
Raw dialogue → turn encoding & entity extraction → graph construction → GNN message passing → attention pooling → classification.

**Design Tradeoffs:**  
- Simplicity of two edge types vs. richer relations (e.g., coreference): simpler graphs reduce complexity but may miss subtle links.  
- Offline static graph vs. dynamic updates: static construction is straightforward; dynamic updates could capture emerging contradictions but need online processing.  
- Entity matching threshold: using ≥1 shared entity creates dense graphs (high recall, more compute) but may introduce noise; a stricter threshold would sparsify graphs.

**Failure Signatures:**  
- Minority-class performance remains poor even with sampling.  
- Attention weights concentrate on irrelevant turns (e.g., opening/closing turns).  
- Graph construction failures: turns with no extracted entities yield isolated nodes or empty shared-entity edges.  
- Discrepancy between high training and low validation accuracy indicates overfitting.

**First Three Experiments:**  
1. **Baseline Reproduction**: Run TGN[ET] with repository defaults on DiaHalu to verify reported 0.5468±0.0332 multiclass accuracy.  
2. **Edge Ablation**: Construct graphs using only temporal edges to quantify the drop in performance, confirming the contribution of shared-entity edges.  
3. **Attention Visualization**: Sample dialogues and plot attention weights; manually check if high-weight turns correspond to those containing or resolving hallucinations.

## Open Questions the Paper Calls Out
- What additional relational edge types (e.g., semantic role or discourse relations) beyond temporal and shared-entity connections can be incorporated into the TGN to improve hallucination detection accuracy, and how should they be encoded?
- How can external knowledge graphs (KGs) be integrated into the TGN framework to enhance detection of subtle factual inconsistencies without introducing prohibitive computational overhead or requiring full KG alignment?
- Does a dynamic graph construction that incrementally updates node and edge representations as each dialogue turn arrives improve detection of emergent, context-dependent hallucinations compared to the current static post-hoc graph?
- To what extent does the TGN framework generalize to non-open-domain conversations (e.g., task-oriented or multimodal dialogues), and what architectural adaptations are necessary for such domains?

## Limitations
- The exact GNN architecture (layers, hidden dimensions, dropout) and entity extraction prompt are underspecified, hindering exact replication.
- The attention justification claim lacks quantitative validation (e.g., agreement with human rationales).
- Performance on minority hallucination classes remains low despite class weighting, suggesting persistent imbalance issues.

## Confidence

- Ablation claim (shared-entity edges provide strong signal): Medium
