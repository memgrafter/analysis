# Benchmarking Multi-Agent LLM Architectures for Financial Document Processing: A Comparative Study of Orchestration Patterns, Cost-Accuracy Tradeoffs and Production Scaling Strategies

## Quick Facts
- **arXiv ID**: 2603.22651
- **Source URL**: https://arxiv.org/abs/2603.22651
- **Reference count**: 28
- **Primary result**: Reflexive architecture achieved highest field-level F1 (0.943) at 2.3× sequential cost; hierarchical provided optimal cost-accuracy tradeoff (F1 0.921 at 1.4× cost).

## Executive Summary
This paper benchmarks four multi-agent LLM orchestration patterns—sequential, parallel, hierarchical, and reflexive—for structured extraction from financial documents. Using 10,000 SEC filings and five frontier models, the study compares accuracy, cost, latency, and token efficiency. The reflexive architecture attains the highest field-level F1 (0.943) through iterative verification but at 2.3× the cost of sequential baselines. Hierarchical supervision yields the best cost-accuracy tradeoff on the Pareto frontier (F1 0.921, 1.4× cost). A hybrid hierarchical system with semantic caching, model routing, and adaptive retries recovers 89% of reflexive's accuracy gains at only 1.15× sequential cost (F1 0.924, $0.148/document). Scaling analysis shows reflexive accuracy degrades sharply beyond 25,000 daily documents due to timeout truncation, while sequential remains robust.

## Method Summary
The task extracts 25 field types (financial metrics, governance, compensation) from SEC filings (10-K, 10-Q, 8-K). Five LLMs are evaluated: GPT-4o, Claude 3.5 Sonnet, Gemini 1.5 Pro, Llama3 70B, Mixtral 8x22B. Each architecture is implemented as a LangGraph workflow using shared atomic agents (Document Parser, Field Extractor, Table Analyzer, Cross-Ref Resolver, Confidence Scorer, Output Formatter). Metrics include field-level micro-F1 (exact for categoricals, ±2% for numericals), document accuracy, end-to-end latency (p50, p95), cost per document, and token efficiency. Experiments run on a fixed 8‑node A100 cluster; scaling tests vary daily volume from 1K to 100K documents. Ablations examine semantic caching (embedding similarity threshold 0.95), model routing by difficulty, and adaptive retry policies.

## Key Results
- Reflexive architecture achieves the highest field-level F1 (0.943) but at 2.3× the cost of sequential baselines; its accuracy sharply degrades beyond 25,000 daily documents due to timeout truncation.
- Hierarchical architecture provides the optimal cost-accuracy tradeoff on the Pareto frontier (F1 0.921 at 1.4× cost).
- A hybrid hierarchical configuration (semantic caching, model routing, adaptive retries) recovers 89% of reflexive's accuracy gains at only 1.15× sequential cost (F1 0.924, $0.148/doc).

## Why This Works (Mechanism)
### Reflexive Iteration for Accuracy
Reflexive architectures employ a verifier agent to apply domain-specific consistency rules (e.g., balance sheet identity checks) and source grounding. Critiques from the verifier trigger a correction agent, with up to three iterations allowed. This iterative refinement resolves complex, interdependent errors that single‑pass systems miss, yielding the highest accuracy. The mechanism assumes that the additional inference cost is offset by reduced residual errors. However, under high‑throughput scaling, timeout truncation cuts iterations short, causing accuracy to collapse beyond 25K docs/day.

### Hierarchical Selective Re‑extraction
A supervisor agent dynamically assigns extraction tasks to specialized workers using a confidence threshold (0.85) to identify low‑confidence fields. Those fields are selectively re‑extracted (up to two iterations), possibly with a different model. By avoiding full‑document re‑processing, this approach reduces cost relative to reflexive while still improving accuracy over sequential. It achieves the best cost‑accuracy Pareto tradeoff. Effectiveness depends on well‑calibrated confidence scoring; coordination failures account for 12.4% of its errors.

### Scaling Degradation via Coordination Overhead
On a fixed compute cluster, increasing document volume leads to queuing delays. Architectures with more inter‑agent communication (reflexive, hierarchical) consume more tokens per document, resulting in longer queue times and greater susceptibility to timeout policies that truncate their loops. Sequential, with minimal coordination, degrades gracefully. This mechanism explains the observed non‑linear accuracy drop for multi‑agent systems beyond a throughput threshold.

## Foundational Learning
- **Token Efficiency**: Defined as output tokens / total tokens consumed. Key for cost modeling: hierarchical and reflexive have identical efficiency (2.78%) despite different total tokens, revealing that overhead scales proportionally with useful output. - **Pareto Frontier in Cost‑Accuracy Space**: The set of configurations where accuracy cannot be improved without increasing cost. The paper identifies the hierarchical optimum as a "knee point" offering maximal accuracy gain per unit cost. ## Architecture Onboarding
### Component Map
Atomic agents: Document Parser, Field Extractor, Table Analyzer, Cross‑Ref Resolver, Confidence Scorer, Output Formatter. Orchestration graphs: Sequential (linear chain: Parser -> Extractor -> Analyzer -> Resolver -> Formatter); Parallel (Dispatcher -> domain branches -> Merge Agent -> Formatter); Hierarchical (Supervisor -> Worker Pool -> conditional feedback -> Formatter); Reflexive (Extractor -> Verifier -> Critique -> Correction loop [≤3] -> Formatter). Optimization adapters: Semantic Cache (embedding similarity on inputs), Model Router (task‑based model assignment), Adaptive Retry Controller (adjusts thresholds/escalation).

### Critical Path
1. Orchestrator initiates workflow for a new document.
2. Document Parser converts raw filing (HTML/XBRL) into structured text with table preservation.
3. Dispatcher/Supervisor selects which agent(s) to activate for each field/group.
4. Field Extractor(s) invoke the assigned LLM with context.
5. (Reflexive/Hierarchical only) Confidence scores trigger optional re‑extraction via verifier/correction or supervisor reassignment.
6. (Parallel only) Merge/Reconcile Agent resolves conflicts from independent branches.
7. Output Formatter assembles final structured JSON.
8. Optimization layer checks cache before steps 4/5 and may route to different models.

### Design Tradeoffs
- **Accuracy vs. Cost/Latency**: Reflexive maximizes accuracy at high cost/latency/variance; sequential minimizes cost/latency but sacrifices accuracy on complex docs; hierarchical aims for the "knee point" on the Pareto frontier.
- **Complexity vs. Resilience**: More coordination (Parallel → Hierarchical → Reflexive) increases failure surface (coordination errors, deadlocks) but provides more error recovery pathways; sequential has zero inter‑agent failure but propagates all upstream errors.
- **Token Efficiency**: Parallel often has lower efficiency due to context window overlap across branches; hierarchical/reflexive have similar efficiency because their overhead (supervisor decisions / critique tokens) scales with useful output.

### Failure Signatures
- **Sequential**: High rate of "cross‑table reference failure" (28.4% of errors). Symptom: extracted values in one table do not match summed totals in another.
- **Parallel**: Spikes in "agent coordination failure" (8.1%) and "context window truncation" (14.7%). Symptom: merge agent reports conflicting values or missing fields.
- **Hierarchical**: Surge in "agent coordination failure" (12.4%) and "ambiguous disclosure resolution" (15.4%). Symptom: supervisor reassignment loops or conflicting interpretations in output.
- **Reflexive**: Dominance of "ambiguous disclosure resolution" (39.3%) and high latency tail (p99/p50 = 3.34×). Symptom: correction iterations oscillate between values, or timeout warnings.

### First Three Experiments
1. **Replicate Sequential Baseline**: Implement the exact 5‑agent sequential chain (Parser→Extractor→Analyzer→Resolver→Formatter) using Claude 3.5 Sonnet on a 1K‑doc subset. Verify F1 ~0.903 and cost ~$0.187/doc.
2. **Add Semantic Caching Ablation**: Integrate a Redis cache with `text‑embedding‑3‑small` (cosine >0.95) at field‑level input. Measure hit rate, cost reduction, and F1 delta vs. baseline. Target: 38% hit rate, 34.5% cost reduction, -0.005 F1.
3. **Implement 2‑Tier Model Routing**: In a Hierarchical setup, route simple fields (binary metrics, standard financials) → Mixtral 8x22B; complex fields (compensation, governance) → Claude 3.5 Sonnet. Measure cost reduction and retained F1 vs. all‑Claude. Target: 51% cost reduction, retain ~98% F1.

## Open Questions the Paper Calls Out
1. **Dynamic architecture switching**: How can we develop a robust, automated complexity estimator for financial documents to dynamically route between sequential, hierarchical, and reflexive architectures based on per‑document characteristics?
2. **Specialist models via fine‑tuning**: To what extent can fine‑tuned specialist models (e.g., distilled from frontier LLMs) replace expensive models in hierarchical architectures for specific extraction domains while maintaining accuracy and reducing cost?
3. **Cross‑document context**: Does incorporating prior SEC filings for a company reduce temporal confusion errors (e.g., FY vs. QTR mix‑ups) and enable consistent time‑series extraction?
4. **Formal verification integration**: Can formal verification of financial identity constraints (e.g., total assets = liabilities + equity) be integrated as a post‑processing step to provide provable correctness guarantees, and what are the tradeoffs?

## Limitations
- No publicly released ground truth annotations, preventing exact F1 replication.
- Incomplete specification of agent prompts, verification rules, and critical hyperparameters (confidence thresholds, iteration limits).
- Underspecified scaling infrastructure (timeout thresholds, queueing logic) and limited corpus (SEC filings only) restrict reproducibility and generalizability.
