# PHMForge: A Scenario-Driven Agentic Benchmark for Industrial Asset Lifecycle Maintenance

## Quick Facts
*   **arXiv ID:** 2604.01532
*   **Source URL:** https://arxiv.org/abs/2604.01532
*   **Reference Count:** 39
*   **Primary Result:** PHMForge establishes a challenging benchmark where state-of-the-art agentic frameworks achieve a peak task completion rate of 68%, with systematic failures in tool orchestration (23%), multi-asset reasoning (−14.9 pp), and cross-equipment generalization (42.7% success).

## Executive Summary
PHMForge is a novel benchmark designed to evaluate the capability of large language model (LLM) agents in the high-stakes domain of industrial prognostics and health management (PHM). It addresses the absence of robust, realistic benchmarks by providing 75 expert-curated scenarios spanning seven asset classes and five core maintenance tasks. The benchmark forces agents to orchestrate 65 specialized tools via the Model Context Protocol (MCP) and employs a strict, execution-based evaluation that requires verified outputs. Testing reveals that even frontier models struggle with fundamental challenges like correct tool sequencing, fleet-level reasoning, and zero-shot transfer across equipment types, highlighting significant gaps before agentic AI can be reliably deployed in industrial maintenance settings.

## Method Summary
The benchmark comprises 75 natural language scenarios derived from 18 public PHM datasets (e.g., CMAPSS, CWRU). Each scenario is paired with a ground truth validation template. Agents interact with two MCP servers exposing 65 domain-specific tools (e.g., `train_rul_model`, `assess_compliance`). Agent frameworks (ReAct, Cursor Agent, Claude Code) using LLM backbones (Claude Sonnet 4.0, GPT-4o, Granite-3.0-8B) must infer the required tool sequence from the vague query, execute the workflow, and produce a final output that embeds computed verification metrics (e.g., MAE). Success is determined by an execution-based evaluator that checks the output structure and validates it against the ground truth criteria.

## Key Results
*   Peak task completion is 68% (Claude Code + Sonnet 4.0), with smaller models (Granite-3.0-8B) failing on complex model training tasks.
*   Agents exhibit a 23% failure rate due to incorrect tool sequencing, such as predicting before model training.
*   Multi-asset reasoning (e.g., fleet prioritization) causes a 14.9 percentage-point performance degradation compared to single-asset tasks.
*   Cross-equipment zero-shot generalization success is only 42.7%, indicating poor transfer of PHM knowledge across asset types like bearings and motors.

## Why This Works (Mechanism)
### Mechanism 1
*   **Claim:** Expert-vetted, scenario-driven curation ensures industrial authenticity and operational relevance.
*   **Mechanism:** Subject Matter Experts (SMEs) manually transform raw PHM datasets into natural language queries that mirror real stakeholder requests, embedding domain terminology, urgency, and contextual nuance. This human-in-the-loop process filters out synthetic artifacts, aligning scenarios with genuine maintenance workflows.
*   **Core assumption:** Human expertise is necessary to capture the tacit knowledge and decision-making patterns of industrial practitioners that automated query generation would miss.
*   **Evidence anchors:** [abstract] "expert-curated scenarios" and "progressive SME-driven curation (396 person-hours across domain experts)." [section 3.3] "Experts drafted the queries... to capture operational context and business urgency" and "no LLM was used during the generation of the scenarios."
*   **Break condition:** If SME time investment is reduced or automated, scenario realism degrades, leading to inflated agent performance on non-authentic tasks.

### Mechanism 2
*   **Claim:** Specialized MCP-server tooling forces agents to demonstrate domain-specific orchestration rather than general API use.
*   **Mechanism:** PHMForge constructs 65 tools across two MCP servers (Prognostics, Maintenance) that encode PHM domain logic (e.g., `train_rul_model`, `assess_component_health`). Agents must discover, sequence, and execute these tools without explicit tool names, mimicking real deployment where specialized PHM functions are not off-the-shelf.
*   **Core assumption:** Existing generic tool-use benchmarks fail to stress the technical depth and regulatory constraints of industrial maintenance, where tools must interface with sensor data, failure modes, and safety standards.
*   **Evidence anchors:** [abstract] "65 specialized tools via two MCP servers" and "unknown-tools challenge." [section 2.4] "Standardized Tooling: The first deployment of 65 specialized tools via the Model Context Protocol (MCP)."
*   **Break condition:** If tools are coarsened or generalized (e.g., a single `analyze_data` tool), the benchmark loses granularity in measuring orchestration skill specific to PHM sub-tasks.

### Mechanism 3
*   **Claim:** Execution-based evaluation with deterministic ground truth verification exposes failure modes hidden in passive QA benchmarks.
*   **Mechanism:** Each scenario specifies a ground truth object with validation criteria (error thresholds, categorical mappings). Agents must not only produce outputs but also compute and verify metrics (e.g., `calculate_mae`), enforcing best-practice validation. Success requires both task completeness and passing ground truth checks.
*   **Core assumption:** Industrial AI demands validated outputs; an agent that predicts RUL without error assessment is unsafe. Passive evaluation can be gamed by LLMs without real analytical execution.
*   **Evidence anchors:** [abstract] "execution-based evaluators" and "systematic failures... underscore the challenge of deploying reliable agentic AI." [section 4] `validate(ˆ𝑦, G)` function and "Success is determined through execution-based evaluation."
*   **Break condition:** If verification steps are removed or made optional, completion rates artificially inflate (ablation shows +18.7%) and false positives rise (31% false positive rate).

## Architecture Onboarding
### Component map
Scenarios -> Data (18 PHM Datasets) -> MCP Servers (Prognostics Server: 65 Tools; Maintenance Server) -> Agent Frameworks (ReAct, Cursor Agent, Claude Code) -> LLM Backbones (Claude Sonnet 4.0, GPT-4o, Granite-3.0-8B) -> Output -> Execution-based Evaluator (validate(ˆ𝑦, G))

### Critical path
1.  **Scenario ingestion:** Agent receives natural language query (e.g., "Which engines are nearing critical limits?").
2.  **Tool discovery & sequencing:** Agent must infer required tools (e.g., `load_dataset` → `predict_rul` → `calculate_mae`) without explicit tool names.
3.  **Execution loop:** Agent calls MCP tools, receives observations, updates state, and iterates until output generation.
4.  **Output validation:** Agent must embed verification (e.g., compute MAE and compare to threshold) in its final structured response.
5.  **Scoring:** Evaluator runs `validate(ˆ𝑦, G)`; success requires correct output format + passing metric thresholds.

### Design tradeoffs
*   **Scenario count vs. depth:** 75 scenarios cover breadth (7 asset classes) but limit depth per asset. Tradeoff: comprehensive generalization assessment vs. exhaustive coverage of any single failure mode.
*   **Tool granularity:** 65 specialized tools increase evaluation sensitivity but raise orchestration complexity. A coarser toolset (e.g., unified `analyze` function) would simplify agent design but obscure failure modes in sub-task sequencing.
*   **Unknown-tools challenge:** Vague queries ("nearing critical limits") force multi-hop intent extraction. This increases realism but may penalize agents that overfit to keyword matching in simpler benchmarks.

### Failure signatures
*   **Tool sequencing errors (23%):** Attempting `predict_rul` before `train_rul_model`; invoking distraction tools (e.g., `web_search` on embedded-data queries).
*   **Multi-asset degradation (−14.9 pp):** Agents fail on fleet-level ranking/prioritization, often processing assets individually without aggregation.
*   **Cross-equipment generalization (42.7%):** Zero-shot transfer from bearing to motor diagnostics collapses due to overfitting to dataset-specific patterns rather than PHM task structure.
*   **Verification omission:** Agents produce predictions without computing MAE/RMSE, violating output template requirements.

### First 3 experiments
1.  **Single-asset RUL prediction:** Run a CMAPSS FD001 scenario with `train_rul_model` and `predict_rul`. Verify agent produces RUL values *and* calculates MAE within ±20% threshold. Expected: Frontier models succeed ~73%; Granite fails on model training.
2.  **Unknown-tools query:** Use a vague query like "Assess health of our turbofan fleet." Agent must discover `load_dataset`, `analyze_engine_signals`, and `assess_component_health` without tool names. Expected: Claude Code’s native MCP integration yields higher tool discovery (4.2 tools vs. 2.8 for ReAct).
3.  **Cross-asset transfer:** Evaluate a motor fault classification scenario after only bearing scenarios in training history. Measure F1-score drop from in-distribution (~84%) to cross-equipment (~43%). Expected: All frameworks show large degradation, confirming lack of architectural generalization.

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** What architectural modifications to agent frameworks can address the 23% incorrect tool sequencing rate and the 14.9 percentage-point degradation in multi-asset reasoning observed in PHMForge?
*   **Basis in paper:** [explicit] "systematic failures in tool orchestration (23% incorrect sequencing), multi-asset reasoning (14.9 percentage point degradation)"
*   **Why unresolved:** Current frameworks (ReAct, Cursor Agent, Claude Code) fail to correctly order tools or reason across multiple assets, limiting reliability in complex industrial workflows.
*   **What evidence would resolve it:** A modified agent achieving ≤5% sequencing errors and ≤5 percentage-point multi-asset degradation on PHMForge, with ablation showing which components (planning, memory) contribute.

### Open Question 2
*   **Question:** What causes the 42.7% cross-equipment generalization failure rate, and how can agent designs leverage shared PHM structures to transfer knowledge across asset classes (e.g., bearings to motors)?
*   **Basis in paper:** [explicit] "only 42.7% success on cross-equipment generalization" and "zero-shot transfer from bearing diagnostics to motor diagnostics collapsed to 42.7%"
*   **Why unresolved:** Agents fail to generalize despite common task patterns (RUL, fault classification), suggesting limited transfer learning in current architectures.
*   **What evidence would resolve it:** An agent achieving ≥80% of in-distribution performance on held-out equipment, with analysis of transferred representations (e.g., tool usage patterns, feature abstractions).

### Open Question 3
*   **Question:** How can LLM agents autonomously retrieve and sequence tools from large libraries when given vague, stakeholder-style queries (the "unknown-tools challenge") without explicit function names?
*   **Basis in paper:** [explicit] "agents must retrieve appropriate functions from vague industrial queries... mirroring real deployment scenarios" and "unknown-tools challenge" introduced but not solved.
*   **Why unresolved:** Agents struggle with intent extraction from ambiguous queries (e.g., "Which engines are nearing critical limits?"), leading to tool selection errors.
*   **What evidence would resolve it:** A system achieving ≥90% accuracy on unknown-tools scenarios via improved query disambiguation and tool matching, validated by success rates and human SME assessments.

### Open Question 4
*   **Question:** How can regulatory and safety knowledge (e.g., OSHA, FAA, IEC standards) be effectively embedded into agent workflows to reduce errors in safety/policy evaluation (15–21% failure)?
*   **Basis in paper:** [explicit] "systematic failures in regulatory threshold lookup (15%), multi-framework compliance checking (21%)"
*   **Why unresolved:** Agents lack comprehensive, multi-standard reasoning, causing incomplete compliance checks and unsafe recommendations.
*   **What evidence would resolve it:** An agent verifying all relevant standards with ≥95% accuracy, generating auditable compliance reports, and reducing safety risk misclassifications by ≥50% on PHMForge safety scenarios.

## Limitations
*   The benchmark’s 75 scenarios may not fully capture rare failure modes, long-term planning, or complex fleet interactions despite covering 7 asset classes.
*   Cross-equipment degradation (42.7% success) could partly reflect dataset biases (e.g., CMAPSS) rather than inherent agent limitations; generalization to truly unseen industrial data remains untested.
*   Repository-specific setup details (URL, hardware requirements) are not provided in the summary, posing barriers to faithful replication.

## Confidence
*   **Expert curation ensures authenticity:** High. Supported by 396 SME person-hours, manual query drafting without LLMs, and alignment with similar benchmarks.
*   **Specialized MCP tooling drives orchestration:** High. The 65 tools and measured failure signatures (23% sequencing errors, −14.9 pp multi-asset drop) directly link tool granularity to performance.
*   **Execution-based evaluation is necessary:** Medium-High. Ablation results (+18.7% inflated completion, 31% false positives) confirm benefits, though strictness may penalize semantically correct minor deviations.
