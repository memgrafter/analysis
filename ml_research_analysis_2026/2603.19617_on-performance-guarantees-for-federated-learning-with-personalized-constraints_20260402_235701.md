# On Performance Guarantees for Federated Learning with Personalized Constraints

## Quick Facts
- arXiv ID: 2603.19617
- Source URL: https://arxiv.org/abs/2603.19617
- Reference count: 20
- Primary result: PC-FedAvg achieves O(ε⁻²) communication complexity for suboptimality and O(ε⁻¹) for feasibility; empirically yields comparable global loss to baselines but with lower constraint infeasibility under heterogeneous ℓ1 constraints.

## Executive Summary
Personalized constrained federated learning (FL) addresses scenarios where each participating agent has its own private convex constraint set, contrasting with standard FL that imposes a global model to satisfy all constraints uniformly. This paper presents PC-FedAvg, a novel algorithm that decouples constraint handling from model aggregation through a multi-block representation of each agent’s decision variables. Specifically, every agent maintains m blocks approximating the variables of all agents, updates all blocks via stochastic gradients, and penalizes infeasibility only on the block corresponding to itself. The server aggregates the blocks separately, ensuring that cross-agent information flows without forcing consensus on the full decision vector. The analysis proves that PC-FedAvg requires O(ε⁻²) communication rounds to achieve ε‑suboptimality and O(ε⁻¹) rounds to satisfy feasibility within ε. Experiments on MNIST and CIFAR‑10 with heterogeneous ℓ₁ constraints confirm that PC-FedAvg matches the global loss of baselines while yielding substantially lower constraint violations, supporting the theoretical predictions.

## Method Summary
PC-FedAvg extends FedAvg by having each agent store a full vector comprising m blocks, each representing an estimate of one agent’s optimal variable. During a communication round, the server broadcasts the current block‑wise averages; agents set their entire vector to these values. Then, over H local steps, each agent computes the intra‑agent average of its blocks and takes a stochastic gradient step on all blocks simultaneously. The update includes a coupling regularizer that pulls each block toward the intra‑agent average, but an additional penalty ρ (·) is applied only to the self‑block to encourage feasibility with respect to the agent’s private constraint set X_i (using the projection Π_{X_i}). After local updates, agents upload their full vectors, and the server recomputes the block‑wise averages. This mechanism preserves personalization because the self‑block is driven toward feasibility while cross‑blocks remain free to carry information about other agents without being burdened by their constraints.

## Key Results
- Theoretically, PC-FedAvg attains communication complexity O(ε⁻²) for suboptimality ε and O(ε⁻¹) for feasibility violation ε under convex objectives and constraint sets (Theorem 3.4).
- On MNIST and CIFAR-10 with heterogeneous ℓ1 constraints, PC-FedAvg achieves global loss comparable to constrained baselines (FedAvg with projection, FedProx, SCAFFOLD) but with significantly lower average infeasibility across agents.
- The number of local steps H influences performance; larger H reduces communication and can improve results on these datasets, though the theoretical bounds include an H‑dependent factor.

## Why This Works (Mechanism)
### Mechanism 1: Multi‑block cross‑estimates eliminate constraint sharing
- **Claim:** The multi‑block local decision vector with cross‑estimates allows agents to keep their private constraint sets X_i secret while still achieving personalization under heterogeneous constraints.
- **Mechanism:** Each agent i holds a vector x_i ∈ ℝ^{mn} composed of m blocks. Block j approximates agent j’s variable. For its local updates (H steps), the agent uses the same stochastic gradient ∇f_i(¯x_i) on every block (where ¯x_i is the average of its own blocks). However, only the self‑block (j=i) incurs an additional penalty ρ (x_i^{(i)} - Π_{X_i}[x_i^{(i)}]) that pushes it toward feasibility; cross‑blocks (j≠i) lack this penalty and thus serve only to propagate information.
- **Core assumption:** X_i is convex, closed, and the projection Π_{X_i} can be computed locally; local objectives f_i are L‑smooth and convex.
- **Evidence anchors:** Algorithm 1 (line 8) explicitly applies the penalty only when j=i; the abstract describes the cross‑estimate mechanism; related work (e.g., SCAFFOLD) does not use multi‑block splitting for private constraints, underscoring novelty.
- **Break condition:** If X_i is non‑convex, the projection may not be well‑behaved (non‑expansiveness fails), breaking convergence. If an agent cannot compute Π_{X_i}, the penalty cannot be implemented.

### Mechanism 2: Asymmetric penalty enforces feasibility without consensus
- **Claim:** Applying the constraint penalty solely to the self‑block lets each agent satisfy its own constraints while cross‑blocks remain unconstrained, thereby avoiding explicit consensus on decision variables.
- **Mechanism:** In the update rule, the self‑block receives both the feasibility penalty ρ (x_i^{(i)} - Π_{X_i}[x_i^{(i)}]) and a coupling term σ_i·c_i·(x_i^{(i)} - ¯x_i) with c_i = (m‑1)/m; cross‑blocks receive only the coupling term σ_i·c_j·(x_i^{(j)} - ¯x_i) with c_j = –1/m. Thus self‑block is pulled toward the intra‑agent average while being nudged into X_i; cross‑blocks float, carrying estimates of others without constraints.
- **Core assumption:** Tuning parameters satisfy γ ≤ min{1/(6 L_{Gρ}), 1/(5 L_{Gρ}(H‑1))} where L_{Gρ} = L_f + σ(m‑1)/m + ρ; the distance penalty h_i(x)=½‖x - Π_{X_i}(x)‖² is convex with 1‑Lipschitz gradient.
- **Evidence anchors:** Section 4’s penalized objective G_ρ(x) adds ρ h_i(B_i x) only for the agent’s own block (via B_i); the asymmetric coefficients c_j appear in Algorithm 1 line 8; no existing constrained FL method uses such block‑wise asymmetric penalization.
- **Break condition:** ρ too small → infeasibility bound degrades (O(1/ρ)); ρ too large → L_{Gρ} grows, forcing smaller γ and potentially worsening suboptimality. Excessively large σ_i can over‑couple blocks, reducing personalization benefits.

### Mechanism 3: Block‑wise aggregation preserves personalization
- **Claim:** The server’s block‑wise averaging (instead of full aggregation) maintains cross‑estimation across rounds and prevents the system from converging to a consensus model, thus enabling personalization.
- **Mechanism:** After each agent’s local updates, the server computes for each block j the average ¯x^{(j)} = (1/m) ∑_i x_i^{(j)} and broadcasts these m averages. All agents then set their entire multi‑block vector to these averages at the start of the next round. Consequently, at the beginning of every round all agents share identical block‑wise averages, but during the H local steps they diverge because each agent applies its own gradient and self‑block penalty. The j‑th block of every agent always carries information about agent j’s variable, yet the full vector never becomes identical, avoiding full consensus.
- **Core assumption:** The number of local steps H is bounded (max_r |T_{r+1} - T_r| ≤ H); stepsize γ respects the bound above; server aggregation is linear and unbiased.
- **Evidence anchors:** Abstract states block‑wise aggregation “enabling personalization without requiring consensus or sharing constraint information”; Algorithm 1 line 10 implements block‑wise averaging; Theorem 3.4 shows communication complexity O(ε⁻²), matching unconstrained FedAvg, indicating block‑wise aggregation does not increase asymptotic rounds.
- **Break condition:** Full averaging (concatenating vectors) would force identical vectors each round, erasing personalization. Unbounded H would make the drift terms in the analysis uncontrollable, potentially causing instability.

## Foundational Learning
**Concept:** Constrained convex optimization and projection methods  
**Why needed here:** The problem involves private convex sets X_i. The algorithm uses the squared distance h_i(x)=½‖x - Π_{X_i}(x)‖² as a penalty; convergence relies on projection’s firm non‑expansiveness and convexity.  
**Quick check:** For a closed convex set X, what is the first‑order optimality condition for the projection Π_X(x)?  
**Answer:** Π_X(x) is the unique y∈X satisfying ⟨x - y, z - y⟩ ≤ 0 for all z∈X.

**Concept:** Federated averaging (FedAvg) and communication‑complexity trade‑offs  
**Why needed here:** PC‑FedAvg builds on FedAvg by altering aggregation and local updates. Understanding FedAvg’s alternation between local updates and global averaging is essential to see why PC‑FedAvg retains O(ε⁻²) communication complexity despite added constraints.  
**Quick check:** In FedAvg, what is the effect of increasing the number of local steps H on the bound’s dependency on H?  
**Answer:** More local steps reduce communication rounds but typically worsen the constant factor involving H (e.g., drift terms ∝ H²).

**Concept:** Multi‑block (variable splitting) methods in distributed optimization  
**Why needed here:** Each agent holds a multi‑block vector with distinct roles for self vs. cross blocks. Analyzing such systems requires tools for multi‑block gradient methods, handling coupled averages and block‑wise Lipschitz constants.  
**Quick check:** In a multi‑block method, why might one introduce identical copies of a variable across blocks?  
**Answer:** To allow different treatment (e.g., penalty on one copy) while maintaining a shared average that couples the blocks.

## Architecture Onboarding

#### Component Map
- **Server**: Stores m block vectors {¯x^{(j)}}_{j=1}^m. Broadcasts them to all agents at round start. Receives full vectors x_i from agents, computes new block averages: ¯x^{(j)} ← (1/m)∑_i x_i^{(j)} for each j.
- **Agent i**: Holds local data D_i, private constraint set X_i, hyperparameters σ_i, γ, ρ, H. State: full vector x_i ∈ ℝ^{mn} (blocks x_i^{(1)},…,x_i^{(m)}). Operations:  
  a. On receive, set x_i^{(j)} ← ¯x^{(j)} ∀j.  
  b. For t = 1..H:  
     - Compute ¯x_i = (1/m)∑_j x_i^{(j)}.  
     - Sample mini‑batch, compute ∇˜f_i(¯x_i, ξ).  
     - For each block j:  
       *Base step:* (1/m)∇˜f_i.  
       *Regularization:* add σ_i·c_j·(x_i^{(j)} - ¯x_i) with c_j = (m‑1)/m if j=i else –1/m.  
       *Penalty (j=i only):* add ρ (x_i^{(i)} - Π_{X_i}(x_i^{(i)})).  
       *Update:* x_i^{(j)} ← x_i^{(j)} - γ·(total).  
  c. After H steps, send x_i to server.
- **Communication links**: Server→agents (broadcast of m blocks); agents→server (unicast of full vectors).

#### Critical Path (per communication round)
1. Server broadcasts current block averages.
2. Agents initialize their full vectors to these averages.
3. Agents perform H local updates as described.
4. Agents upload updated full vectors.
5. Server aggregates block‑wise to form new averages.
6. Increment round counter.

#### Design Tradeoffs
- ρ (penalty): Larger ρ improves feasibility but increases LGρ, forcing smaller γ; trade‑off balanced by ρ = √R (Theorem 3.6).  
- γ (stepsize): Must satisfy γ ≤ min{1/(6 LGρ), 1/(5 LGρ(H‑1))}; too large causes divergence, too small slows convergence.  
- σ_i (regularization): Larger σ_i increases block coupling within an agent; heterogeneous σ_i allowed. Excessive σ_i may cause numerical stiffness.  
- H (local steps): Larger H reduces communication frequency but worsens drift constants (∝ H²) in theory; empirically larger H improved results on MNIST/CIFAR‑10.  
- m (agents): Affects smoothness constants; more agents change constants but not asymptotic order.

#### Failure Signatures
- **Divergence**: Gradient norms explode → γ too large relative to LGρ.  
- **Persistent infeasibility**: ‖x_i^{(i)} - Π_{X_i}(x_i^{(i)})‖ remains large → ρ too small or rounds insufficient.  
- **Loss of personalization**: Very large σ_i makes blocks nearly identical, collapsing the multi‑block structure.  
- **Slow convergence**: Excessive H with high data heterogeneity can cause the averaged block to drift, requiring more rounds.

#### First 3 Experiments
1. **Toy quadratic validation**: Construct two agents with strongly convex quadratics and different ℓ₂‑ball constraints. Run PC-FedAvg with known optimal solution. Verify expected suboptimality decays as O(1/√R) and infeasibility as O(1/√R).  
2. **MNIST/CIFAR‑10 replication**: Use paper’s hyperparameters on each dataset with heterogeneous ℓ₁ constraints. Reproduce figures showing global loss comparable to baselines but strictly lower infeasibility.  
3. **Ablation on local steps H**: Fix R=100, vary H ∈ {1,10,20,50,100}. Measure final global loss and average infeasibility to confirm larger H benefits.

## Open Questions the Paper Calls Out
1. **Non‑convex objectives**: Can the O(ε⁻²) and O(ε⁻¹) communication guarantees be extended to non‑convex losses, common in deep learning? The current analysis relies on convexity; non‑convex landscapes introduce saddles and local minima not addressed.  
2. **ρ trade‑off automation**: How does the choice of penalty parameter ρ empirically trade off between global loss and feasibility? The paper sets ρ = √R analytically, but finite‑iteration optimality may differ; no systematic study of ρ sensitivity or adaptive selection is provided.  
3. **Privacy leakage**: Does block‑wise aggregation leak information about agents’ private constraint sets X_i? The method avoids sharing X_i, but the server’s aggregated blocks could correlate with feasible regions; no formal privacy analysis is given.  
4. **Comparison to meta‑learning personalization**: How does PC-FedAvg compare to modern personalized FL methods (e.g., pFedHN, PerFedAvg) under personalization + constraints? Baselines are penalized FedAvg variants, not algorithms designed for personalization via local components.  
5. **Partial participation and variable H**: Can PC-FedAvg handle partial agent participation (random client selection) and time‑varying number of local steps H_r? The current analysis assumes all agents participate each round and a uniform bound H; partial participation and variable H could break the convergence proof.

## Limitations
- Theoretical guarantees require convex objectives and convex constraint sets with easy projection, while practical FL often uses non‑convex deep networks and complex constraints.  
- The stepsize and penalty schedule depend on unknown problem constants (smoothness, gradient bounds), making practical deployment sensitive to hyperparameter tuning.  
- Experiments are limited to two vision datasets (MNIST, CIFAR‑10) with simple ℓ₁ constraints; generalization to other domains, models, and constraint types remains unverified.

## Confidence
- **Mechanism correctness (multi‑block cross‑estimates)**: High – algorithm design is explicit and proof under convexity.  
- **Theoretical communication complexity (O(ε⁻²)/O(ε⁻¹))**: High – rigorous theorem under stated assumptions.  
- **Empirical infeasibility reduction**: Medium – promising but limited evaluation scope (only two datasets, simple constraints).
