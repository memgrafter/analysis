# Quality Over Clicks: Intrinsic Quality-Driven Iterative Reinforcement Learning for Cold-Start E-Commerce Query Suggestion

## Quick Facts
- **arXiv ID:** 2603.22922
- **Source URL:** https://arxiv.org/abs/2603.22922
- **Reference count:** 22
- **Primary result:** Cold-EQS achieves 86.1% Strict Accuracy and 90.6% Valid Rate offline, and a +6.81% improvement in chatUV online for cold-start e-commerce query suggestion without relying on click data.

## Executive Summary
This paper tackles the cold-start problem in e-commerce query suggestion, where traditional click-through rate (CTR) based methods fail due to sparse user interaction data. The authors propose Cold-EQS, a framework that optimizes query quality using reinforcement learning with intrinsic rewards—answerability, factuality, and information gain—computed by an LLM-as-judge. An uncertainty-aware sampling strategy selects hard, ambiguous queries from unclicked online data to iteratively refine the model. A new benchmark, EQS-Benchmark (16,949 queries), validates the approach. Cold-EQS significantly outperforms baselines like Qwen-flash offline and shows strong online user engagement gains during cold-start deployment.

## Method Summary
Cold-EQS employs a multi-phase iterative training loop. Starting from a small set of click-positive queries (`D_click`), the base model (Qwen3-4B) undergoes supervised fine-tuning (SFT). This is followed by reinforcement learning (via GRPO) where a composite intrinsic reward—product of answerability, factuality, and information_gain scores from a Qwen-30B-A3B judge—optimizes the policy. To scale beyond the limited `D_click`, the refined policy generates suggestions on a large corpus of unclicked online queries (`D_unclick`). Queries with high variance in reward scores across multiple rollouts (indicating model uncertainty) are sampled into a hard set `D_hard`. The RL training then repeats for several rounds, each time using a mixture of `D_click` and the latest `D_hard`, continuously improving the policy on challenging cases identified from live traffic.

## Key Results
- **Offline:** 86.1% Strict Accuracy and 90.6% Valid Rate on EQS-Benchmark, surpassing Qwen-flash by +10.7% and +9.3% respectively.
- **Online:** +6.81% improvement in chatUV (unique users engaging in chat) during cold-start deployment.
- **Ablation:** Removing uncertainty-aware sampling reduces Strict Accuracy by 4.5%; performance improves over 3 iterations before converging.

## Why This Works (Mechanism)

### Mechanism 1: Intrinsic Rewards Replace Clicks
- **Claim:** Using answerability, factuality, and information gain as reward dimensions in RL can optimize query suggestion quality in cold-start scenarios without click data.
- **Mechanism:** The RL policy (GRPO) is updated using a reward signal computed by an LLM-as-judge (Qwen-30B-A3B) that scores each candidate suggestion on the three intrinsic criteria. The aggregated reward per rollout directly maximizes query utility as defined by these quality dimensions, bypassing the need for CTR.
- **Core assumption:** These intrinsic dimensions are sufficient proxies for long-term user engagement and multi-turn conversation quality when clicks are unavailable.
- **Evidence anchors:** [abstract] states use of intrinsic rewards; [section 3.2] details reward composition and GRPO objective.
- **Break condition:** If judged quality dimensions fail to correlate with real engagement or if the reward model introduces bias that the policy overfits to.

### Mechanism 2: Uncertainty Sampling Identifies Hard Queries
- **Claim:** Sampling unclicked online queries with high variance in intrinsic reward scores across multiple suggestions selects informative "hard" cases that improve model robustness and generalization.
- **Mechanism:** For each query `q` without clicks, the current model generates `k` suggestions; the variance `u_q` of their reward scores measures uncertainty. High `u_q` indicates ambiguity in what constitutes a high-quality suggestion. These high-uncertainty queries are added to `D_hard` for subsequent RL training.
- **Core assumption:** High variance in the model's own quality assessment for a given input correlates with queries where the model's knowledge is weak, and training on these yields the greatest performance gains.
- **Evidence anchors:** [section 3.3] defines `u_q`; [section 4.3, Table 2] shows ablation drop of 4.5% without uncertainty sampling.
- **Break condition:** If variance fails to identify truly difficult queries (e.g., selecting cases where the reward model is inconsistent rather than the policy uncertain).

### Mechanism 3: Iterative RL Loop from Sparse to Abundant Data
- **Claim:** A cyclic process (SFT → RL → uncertainty sampling on unclicked data → repeat) bootstraps performance from minimal warm-up clicks and systematically refines the policy using scalable online data.
- **Mechanism:** Cycle: (1) Warm-up SFT on small `D_click`. (2) RL on `D_click` with intrinsic rewards. (3) Generate on `D_unclick`, compute `u_q`, sample `D_hard`. (4) Repeat RL on mixed `D_click + D_hard`. This addresses the policy's weaknesses identified in live traffic.
- **Core assumption:** Policy uncertainty on unclicked data is a valid signal for selecting valuable training examples in the absence of clicks, and iterative refinement converges to a robust policy.
- **Evidence anchors:** [section 3.4, Algorithm 1] defines the loop; [section 4.3, Figure 4] shows convergence at K=3.
- **Break condition:** If `D_hard` distribution shifts catastrophically across iterations (e.g., reward hacking) or uncertainty signal degrades.

## Foundational Learning
- **Concept:** Reinforcement Learning from Intrinsic/LLM-as-Judge Rewards.
  - **Why needed:** Standard RLHF requires human preference data. Here, clicks are sparse, so an LLM directly scores outputs on predefined dimensions to provide a dense reward for policy optimization.
  - **Quick check:** How does using an LLM as a reward model differ from a learned reward from human preferences, and what failure modes are specific to each?
- **Concept:** Uncertainty Estimation for Active/Iterative Learning in NLP.
  - **Why needed:** To select informative unlabeled data (`D_unclick`) when ground-truth rewards (clicks) are absent. The method uses output-space variance as a proxy for input-level uncertainty.
  - **Quick check:** Why is output variance across `k` generations a plausible but not definitive measure of input uncertainty? What alternatives exist for autoregressive models?
- **Concept:** Cold-Start Problems in Recommendation/Dialogue Systems.
  - **Why needed:** The core problem. New items/users or new deployments lack interaction history, rendering click-dependent models ineffective. Requires alternative supervision.
  - **Quick check:** What are the two main facets of cold-start (user vs. item), and which does this paper primarily address?

## Architecture Onboarding
**Component map:** Base Model (Qwen3-4B) -> SFT Module -> RL Trainer (GRPO) -> Policy; Reward Evaluator (Qwen-30B-A3B) provides scores to RL Trainer; Policy generates for Uncertainty Sampler; Data Mixer combines `D_click` and `D_hard` to feed RL Trainer.

**Critical path:** Warm-up: `D_click` -> SFT -> Initial RL on `D_click` -> Inference Loop: Policy on `D_unclick` -> Uncertainty -> `D_hard` -> Iterative RL Loop (K rounds): Mix `D_click + D_hard` -> GRPO -> Re-sample `D_hard`.

**Design tradeoffs:** 
- Reward model latency vs. quality: 30B judge adds cost but improves reward signal.
- Uncertainty simplicity vs. efficacy: Variance is cheap but may not capture true epistemic uncertainty.
- Data mix ratio: Balances exploitation of known patterns vs. exploration of hard cases; empirically tuned.

**Failure signatures:**
- Reward hacking: Policy generates queries that exploit LLM judge heuristics but fail in real dialogue; monitor via human evaluation.
- Mode collapse on hard samples: Over-training on `D_hard` degrades general performance; track validation on `D_click`.
- Uncertainty degradation: Overconfidence reduces variance, making sampling uninformative; monitor `u_q` distribution over time.

**First 3 experiments:**
1. **Reward Component Ablation:** Train with only 1 or 2 of the 3 reward components to measure each contribution to Strict Accuracy.
2. **Uncertainty Sampler Sanity Check:** Compare variance-based `D_hard` selection vs. random sampling in early RL iterations; expect >2% lift if mechanism holds.
3. **Online/Offline Correlation Pilot:** Deploy offline-optimal model in a small A/B test slice; verify chatUV improvement matches paper’s +6.81%.

## Open Questions the Paper Calls Out
- Can we replace the external LLM-based reward evaluator with a more efficient, lightweight model or a learned reward function that maintains comparable performance?
- Is it possible to eliminate the need for any warm-up click data entirely by designing a purely intrinsic quality-driven training process that learns from unlabeled online queries from scratch?
- How generalizable is the observed positive correlation between offline intrinsic quality metrics (Strict Accuracy, Valid Rate) and online user engagement (chatUV) across different product categories, user segments, and languages?
- Are the three intrinsic quality reward dimensions (answerability, factuality, information gain) equally important for maximizing user engagement, or can performance be improved by adaptively weighting them per intent type?

## Limitations
- Dependency on an external LLM (Qwen-30B-A3B) for reward scoring introduces latency and potential coverage gaps in dynamic or long-tail domains.
- The method still requires a minimal stream of click-positive data (`D_click`) for warm-up, which may be unavailable in extremely cold-start scenarios.
- The iterative RL loop’s long-term stability is not guaranteed; risks include reward hacking or degradation of the uncertainty signal over time.

## Confidence
- **High:** Core mechanism efficacy—strong ablations (Table 2, Figure 4) support gains from intrinsic RL and uncertainty sampling.
- **Medium:** Generalizability beyond e-commerce query suggestion—benchmark is domain-specific; no cross-domain validation.
- **Low:** Claims of broad novelty—neighboring papers address cold-start via different methods (e.g., multimodal features, semantic alignment); incremental contribution not proven.
