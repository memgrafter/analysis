# Trace2Skill: Distill Trajectory-Local Lessons into Transferable Agent Skills

## Quick Facts
- **arXiv ID:** 2603.25158
- **Source URL:** https://arxiv.org/abs/2603.25158
- **Reference count:** 25
- **Primary result:** Trace2Skill enables transferable declarative skill creation without parameter updates, improving Qwen3.5-122B by up to 57.65 absolute percentage points on WikiTableQuestions.

## Executive Summary
Trace2Skill introduces a novel framework for automatically evolving reusable agent skills by analyzing large pools of execution trajectories in parallel. Instead of manually authoring skills or sequentially overfitting to trajectory-specific lessons, it employs specialized sub-agents (error and success analysts) to propose patches, which are then hierarchically consolidated into a conflict-free skill directory via inductive reasoning. This approach mirrors human expert behavior and yields skills that transfer across model scales and domains. Evaluations on spreadsheet, math, and visual QA benchmarks demonstrate substantial gains, including up to a 57.65 percentage point improvement on WikiTableQuestions and human-parity skill creation on SpreadsheetBench. The method requires no parameter updates or retrieval modules, making it efficient and scalable.

## Method Summary
Trace2Skill processes a broad set of agent execution trajectories using dedicated sub-agents that analyze errors and successes in parallel. Each sub-agent proposes localized patches—small modifications to the skill directory—to address specific failures or reinforce effective behaviors. After all patches are generated, a hierarchical consolidation phase combines them simultaneously, resolving conflicts through inductive reasoning to produce a unified, conflict-free set of skills. This parallel design avoids the sequential overfitting pitfalls of prior automated methods and eliminates the need for manual intervention. The resulting skills are declarative (e.g., logical rules or code snippets) and can be directly applied by various agent architectures without further training or retrieval.

## Key Results
- Improves Qwen3.5-122B by up to 57.65 absolute percentage points on WikiTableQuestions.
- On SpreadsheetBench, deepening human-written skills yields up to +21.5 pp in verification accuracy; skills created from scratch match or exceed human quality.
- Skills transfer across model scales and generalize out-of-distribution, using only open-source 35B models for evolution.

## Why This Works (Mechanism)
Trace2Skill works by decoupling analysis from consolidation. Parallel trajectory analysis allows a diverse set of lessons to be extracted without getting trapped in local optima that occur with sequential editing. By having separate error and success analysts, the system captures both corrective and reinforcing insights. The hierarchical consolidation step uses inductive reasoning to merge patches into a coherent skill set, ensuring interoperability and avoiding conflicts that would arise if patches were applied naively. This mirrors how human experts review many examples at once to form generalized principles, leading to transferable skills rather than brittle, task-specific tweaks.

## Foundational Learning
Key concepts underpinning Trace2Skill:

- **Trajectory-Local vs. Global Lessons**: Distinguishes between fixes for a single execution and generalizable improvements.
  - *Why needed*: Prevents overfitting to specific failures.
  - *Quick check*: Does the patch improve performance on multiple trajectories?

- **Parallel Analysis**: Running multiple sub-agents concurrently over the same pool of trajectories.
  - *Why needed*: Increases coverage of potential lessons and reduces analysis time.
  - *Quick check*: Do different analysts propose complementary patches?

- **Patch Proposal**: A small, targeted modification to the skill directory.
  - *Why needed*: Enables incremental, composable improvements.
  - *Quick check*: Is the patch syntactically and semantically valid?

- **Hierarchical Consolidation**: A top-down merging process that resolves conflicts among patches.
  - *Why needed*: Ensures the final skill set is coherent and interoperable.
  - *Quick check*: Are all patches integrated without contradictions?

- **Inductive Reasoning**: The logic used to generalize from patches to broader rules.
  - *Why needed*: Transforms specific patches into reusable skills.
  - *Quick check*: Does the consolidated skill set generalize to unseen tasks?

- **Declarative Skills**: Skills represented as interpretable rules or code, not as network weights.
  - *Why needed*: Enables portability across models and no additional training.
  - *Quick check*: Can the skill be directly invoked by different agents?

## Architecture Onboarding
- **Component map:** Trajectory Pool -> Parallel Sub-Agents (Error Analyst, Success Analyst) -> Patch Proposals -> Hierarchical Consolidation -> Conflict-Free Skill Directory.
- **Critical path:** 1) Collect diverse trajectories; 2) Sub-agents analyze in parallel; 3) Consolidation merges patches; 4) Skill directory is deployed.
- **Design tradeoffs:**
  - Parallelism vs. computational cost: More sub-agents increase coverage but require more resources.
  - Patch granularity: Finer patches are easier to merge but may be less impactful; coarser patches risk conflicts.
  - Consolidation complexity: More patches increase consolidation difficulty but yield richer skills.
  - Declarative vs. learned skills: Declarative skills are portable but may be less expressive than fine-tuned parameters.
- **Failure signatures:**
  - High conflict rate during consolidation indicates overlapping patches with incompatible assumptions.
  - Poor performance on OOD tasks suggests overfitting to the trajectory pool or insufficient generalization.
  - Low diversity of proposed patches points to inadequate analysis coverage.
- **First three experiments:**
  1. Run Trace2Skill on a small synthetic dataset and inspect the patch proposals and consolidation logs to understand merging behavior.
  2. Replace the consolidation module with a naive sequential applier and compare skill utility and conflict rates.
  3. Evaluate evolved skills on a held-out domain (e.g., different table types) to measure transferability early.

## Limitations
- Computational costs (training/inference time, hardware) are not reported.
- Statistical significance of gains (e.g., error bars on 57.65 pp improvement) is unclear.
- Domain diversity is limited to three areas (spreadsheets, math, VQA); generalization to other agent tasks remains untested.
- The "conflict-free" claim lacks explicit verification of skill interoperability.
- Human-parity skill creation is subjective without a clear evaluation protocol.

## Confidence
- Performance improvements on WikiTableQuestions/SpreadsheetBench: Medium (specific absolute gains reported but without replication or variance estimates).
- Cross-model transfer and OOD generalization: Medium (mentioned but not extensively validated across diverse unseen domains).
- Human-parity skill creation from scratch: Low (subjective "matches/exceeds" without clear human evaluation protocol).
- Architectural claims (no parameter updates, parallel consolidation): High (methodology clearly described and differentiated from baselines).

## Next Checks
1. **Independent replication:** Reproduce WikiTableQuestions and SpreadsheetBench results using the same Qwen models and report mean/std over multiple seeds; verify if gains hold with statistical tests.
2. **Ablation of consolidation strategy:** Run controlled experiments comparing Trace2Skill's parallel patch consolidation against sequential editing on identical trajectory pools, measuring final skill utility and conflict rates.
3. **OOD transfer stress-test:** Apply skills evolved on spreadsheet/math tasks to at least two novel domains (e.g., scientific literature QA, geometric reasoning) using different base models (e.g., Llama 3.1 70B) to probe true generalization.
