# Evaluating Ill-Defined Tasks in Large Language Models

## Quick Facts
- **arXiv ID:** 2603.17067  
- **Source URL:** https://arxiv.org/abs/2603.17067  
- **Reference Count:** 20  
- **Primary Result:** Current evaluations for ill-defined tasks (e.g., complex instruction following, diagram generation) produce unstable, non-diagnostic scores by conflating distinct failure modes; hybrid, decomposed evaluations combining deterministic checks with constrained LLM-judge assessments yield actionable, criterion-level insights.

## Executive Summary
This paper identifies a critical flaw in evaluating Large Language Models (LLMs) on **ill-defined tasks**—those with ambiguous success criteria, such as complex multi-constraint instruction following or generating structured diagrams from natural language. Through two case studies (Complex Instruction Following and Natural Language to Mermaid diagram generation), it demonstrates that common benchmarks yield unstable, aggregated scores that obscure underlying trade-offs between different capability dimensions (e.g., syntax vs. logic). The core finding is that single-number metrics are non-diagnostic: they hide whether a model’s failure stems from formatting errors, logical inconsistencies, or incomplete coverage. To address this, the authors advocate for **hybrid, decomposed evaluation designs**. These combine deterministic, code-based checks (e.g., parser validation) with narrowly scoped LLM-as-Judge assessments to isolate failure modes. This approach produces fine-grained performance profiles that reveal actionable insights—for instance, showing how a targeted prompt can improve logical reasoning while harming completeness, an effect hidden by the aggregate score.

## Method Summary
The paper’s analysis relies on re-evaluating existing benchmarks and proposing a new evaluation protocol. For **Complex Instruction Following (CIF)**, it examines benchmarks like IFEval, highlighting their vulnerability to degenerate strategies (e.g., a fixed-output baseline achieving non-trivial scores) and sensitivity to prompt phrasing. For **Natural Language to Mermaid (NL2Mermaid)**, it implements a hybrid pipeline on the MermaidSeqBench dataset: first, a deterministic Mermaid parser validates syntax; second, LLM-as-Judge modules (using DeepSeek-V3 and GPT-OSS-120B) score semantic and logical criteria (Logic, Completeness, Error Handling) using constrained prompts. The key method is **decomposition**—splitting a holistic task into independently verifiable criteria—and **hybridization**—assigning each criterion to the most reliable evaluation type (rule-based vs. subjective). Results are compared both as an aggregate score and as a per-criterion diagnostic profile to expose trade-offs.

## Key Results
- Aggregate evaluation scores for ill-defined tasks are **non-diagnostic**, conflating distinct failure modes like syntactic errors and logical flaws.
- Benchmarks like IFEval are **vulnerable to degenerate strategies**, with a fixed-output baseline scoring ~17–20%, indicating over-reliance on surface-form matching.
- Decomposed evaluation in NL2Mermaid revealed **hidden trade-offs**: targeted prompting improved Logic scores by 12+ points for two models, yet overall scores decreased due to declines in other criteria.
- **LLM-as-Judge instability** (variance across seeds, model choice, and prompt phrasing) introduces significant noise, but can be mitigated by constraining judges to narrow criteria and isolating deterministic checks.

## Why This Works (Mechanism)

### Mechanism 1
Aggregate scores for ill-defined tasks conflate multiple, potentially competing capability dimensions (e.g., syntax, logic, completeness). When these dimensions are averaged or summed, improvements in one dimension can be masked by declines in another, resulting in a stable aggregate that obscures behavioral shifts. This makes the score non-diagnostic for targeted model improvement. The paper shows this via the NL2Mermaid case: a prompting intervention raised Logic scores but lowered the overall metric, a trade-off invisible without decomposition. The mechanism assumes that model performance on such tasks lies on a multi-dimensional Pareto frontier, where no single scalar can capture the full profile. Break condition: if all criteria are perfectly correlated, aggregation suffices; the paper finds trade-offs are common.

### Mechanism 2
Hybrid evaluation designs partition criteria into **deterministic** (checkable by code/parser, e.g., syntax, format) and **subjective** (requiring judgment, e.g., logical coherence). This isolation prevents LLM-judge variance from contaminating structural metrics and confines stochastic noise to the narrowest possible scope. Rule-based checks provide objective, reproducible scores for decidable properties; LLM-as-Judge is reserved for nuanced semantic assessments using constrained prompts. The core assumption is that failure modes can be cleanly separated into these two categories and that judge instability predominantly affects the latter. Evidence: IFEval’s rule-based format checks are stable but inadequate alone; NL2Mermaid’s syntax validation via parser clarifies that semantic flaws, not parsing errors, cause failures. Break condition: if a task’s “subjective” aspects become decidable with better rules, the hybrid benefit diminishes; if judge variance remains high even within narrow criteria, stabilization fails.

### Mechanism 3
Decomposed, multi-criteria benchmarks produce **actionable diagnostic feedback** by scoring outputs against atomic, independently defined criteria (e.g., “keyword adherence,” “logical consistency”). This yields a failure-mode profile (e.g., a heatmap) instead of a single number, enabling developers to pinpoint specific capability gaps (e.g., “model mishandles error-handling logic but correctly implements activation sequences”). The assumption is that teams will use these profiles to direct training or data interventions, and that such interventions will causally improve the identified weak criteria. Evidence: The NL2Mermaid decomposition revealed that custom prompting boosted Logic scores, directly informing the intervention. Break condition: if all criteria are perfectly correlated, decomposition adds no value; if criterion-level scores are too noisy (e.g., due to judge variance), they may misdirect efforts.

## Foundational Learning
- **Ill-defined vs. Well-defined Tasks:** Tasks with ambiguous or multi-faceted success criteria (ill-defined) contrast with those having a single correct answer (well-defined). Misclassifying a task leads to inappropriate metrics.  
  *Quick check:* Can you list multiple, substantially different outputs that experts would all deem successful? If yes, the task is likely ill-defined.
- **Metrics Decomposition (vs. Aggregation):** Splitting a holistic judgment into orthogonal, measurable sub-criteria prevents obscuring trade-offs.  
  *Quick check:* If you had to explain *why* an output failed, could you name one specific aspect (e.g., “missing constraint X”)? If not, the metric is likely aggregated.
- **Hybrid Evaluation Design:** Combining deterministic (rule-based) checks with constrained LLM-as-Judge assessments isolates error sources.  
  *Quick check:* For a given failure, can you determine whether it should have been caught by a deterministic rule (e.g., parser error) or requires subjective judgment? If uncertain, the evaluation design is flawed.
- **Degenerate Baseline Vulnerability:** A benchmark is vulnerable if trivial strategies (e.g., fixed output, repetition) achieve non-trivial scores, indicating it measures superficial pattern matching rather than genuine capability.
- **LLM-as-Judge Instability:** Scores from LLM judges vary with seed, model choice, and prompt phrasing, introducing noise that can overwhelm subtle performance differences.
- **Criterion-Level Diagnosticity:** Evaluation criteria must be defined atomically and independently so that scores for each can inform specific interventions without conflating distinct model behaviors.

## Architecture Onboarding
- **Component map:**  
  Input Parser & Decomposer -> Rule-Based Evaluator Module -> LLM-as-Judge Module -> Judge Calibration & Variance Logger -> Score Aggregator & Diagnostic Reporter  
  Parallel paths: Rule-Based Evaluator and LLM-as-Judge Module operate in parallel after decomposition; outputs converge at Score Aggregator.
- **Critical path:** Instruction input -> Decomposition into atomic constraints -> Parallel evaluation (rule-based for deterministic criteria, LLM-judge for subjective criteria) -> Per-criterion scoring -> Diagnostic profile generation (e.g., heatmap). The decomposition step is pivotal; errors here cascade.
- **Design tradeoffs:**  
  - *Deterministic checks* are reproducible and fast but cannot assess semantic nuance.  
  - *LLM-as-Judge* covers nuance but introduces variance, cost, and prompt-sensitivity.  
  - *Fine-grained decomposition* increases diagnostic clarity but multiplies evaluation cost and may overfit criterion definitions.  
  - *Aggregate score simplicity* vs. *profile interpretability:* Teams often desire a single leaderboard number, but the profile is more valuable for development.
- **Failure signatures:**  
  - High variance in LLM-judge scores for the same output across random seeds.  
  - A degenerate baseline (e.g., fixed string) scores >15% on a benchmark.  
  - Overall score remains unchanged after a targeted intervention known to improve a specific capability.  
  - Prompt rephrasing (e.g., instruction reordering) causes >10% score swing.
- **First 3 experiments:**  
  1. Replicate NL2Mermaid decomposition: Implement syntax validator (Mermaid parser) + two independent LLM judges on 100 NL2Mermaid samples. Confirm that aggregated scores hide Logic/Completeness trade-offs as in the paper.  
  2. Test IFEval vulnerability: Run fixed-output baselines (short string, long repetition, empty) on IFEval. Expect ~17–20% scores, confirming reliance on surface constraints.  
  3. Judge calibration study: For 50 CIF outputs, have one LLM judge score each output 5× with different seeds. Report per-criterion standard deviation; if >1.0 point on a 10-point scale, LLM-judge instability undermines reliability.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can benchmarks for complex instruction following be designed to minimize vulnerability to degenerate strategies while covering realistic constraint diversity and compositionality?  
  *Basis:* The paper shows IFEval scores are vulnerable to trivial baselines and have limited real-world constraint coverage.  
  *Why unresolved:* Current benchmarks conflate semantic understanding with superficial compliance, allowing high scores without genuine capability.  
  *Resolving evidence:* Develop new CIF benchmarks with diverse, natural multi-constraint tasks; show poor performance of degenerate baselines; test generalization to unseen constraint types and paraphrased prompts.
- **Open Question 2:* What principles should guide the decomposition of evaluation criteria for ill-defined tasks to isolate failure modes without sacrificing practical usability?  
  *Basis:* NL2Mermaid shows aggregated scores hide trade-offs (e.g., Logic ↑, Overall ↓), while decomposed criteria yield insights.  
  *Why unresolved:* No systematic framework exists for deciding which dimensions to separate, how to weight them, or optimal criterion count. Over-decomposition may overwhelm; under-decomposition reconflates issues.  
  *Resolving evidence:* Comparative analysis across multiple ill-defined tasks (CIF, diagram generation, creative writing) to derive a taxonomy of common failure dimensions; user studies with developers on diagnosticity vs. complexity of decomposed scores.
- **Open Question 3:** How can LLM-as-Judge instability and bias be mitigated for ill-defined tasks in a standardized, reproducible manner?  
  *Basis:* Judge variance (seed sensitivity, translation effects) and lack of transparency in prompts/model versions are pervasive.  
  *Why unresolved:* Current LLM-judge pipelines lack calibration protocols, inter-judge agreement reporting, and standardized prompting.  
  *Resolving evidence:* Benchmarks reporting judge agreement metrics (e.g., Cohen’s κ), confidence intervals, and full judge prompts; development of constrained judge templates scoped to specific criteria; systematic studies of judge model choice and temperature effects.
- **Open Question 4:** Can hybrid evaluation designs (rule-based + LLM-as-Judge) be formalized into scalable, reusable protocols that reliably attribute failures to specific causes across diverse ill-defined tasks?  
  *Basis:* Authors advocate hybrid approaches (e.g., syntax validation before LLM-judge) but note ad hoc implementations; they call for designs that isolate judge noise from genuine errors.  
  *Why unresolved:* No common standards exist for what should be rule-checked vs. judge-scored, score integration, or edge-case handling. Implementation remains fragmented.  
  *Resolving evidence:* Creation of open-source toolkits with modular components (parsers, constraint checkers, judge wrappers); case studies applying the same protocol to multiple tasks, measuring failure attribution clarity and implementation effort; community adoption metrics.

## Limitations
- **External Validity:** Claims are derived from two specific case studies (CIF/IFEval and NL2Mermaid); generalizability to other ill-defined tasks (e.g., creative writing, strategic planning) is uncertain.
- **Implementation Details:** Missing specifications—such as exact LLM-as-Judge prompts, rubrics, and scoring scales for NL2Mermaid—hinder faithful replication and consistent application.
- **Actionability Assumption:** The link between decomposed diagnostic feedback and actual model improvement (i.e., that developers can correctly interpret criterion-level failures and that interventions will improve isolated criteria without negative side-effects) is assumed but not empirically validated.

## Confidence
- **High Confidence:** Aggregate scores obscure intra-task trade-offs (e.g., Logic ↑, Overall ↓). Directly evidenced by NL2Mermaid case study.
- **Medium Confidence:** LLM-as-Judge instability is a primary noise source. Supported by cited literature and sensitivity analyses, but magnitude varies by criterion and judge model.
- **Low Confidence:** A hybrid, decomposed design is a *sufficient* and *generalizable* solution for all ill-defined tasks. This prescriptive claim rests on two positive case studies; its limits and costs across a broader task spectrum are unknown.
