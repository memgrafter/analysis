# VisBrowse-Bench: Benchmarking Visual-Native Search for Multimodal Browsing Agents

## Quick Facts
- **arXiv ID:** 2603.16289
- **Source URL:** https://arxiv.org/abs/2603.16289
- **Reference count:** 40
- **Primary result:** The best model (Claude-4.6-Opus) achieves only 47.6% accuracy under the proposed agentic workflow, while even specialized deep research models reach 41.1%, revealing a substantial capability gap for visual-native search.

## Executive Summary
VisBrowse-Bench introduces a benchmark to evaluate multimodal browsing agents on visual-native search tasks, where answers require active reasoning with visual information that cannot be adequately paraphrased in text. The dataset contains 169 expert-constructed instances, each demanding multi-hop reasoning with at least two distinct visual evidence blocks. Critical details are spatially grounded and non-paraphrasable, preventing text-only shortcuts. An agentic workflow with five tools (text/image/reverse search, cropping, page visit) drives dynamic evidence gathering. Evaluation shows state-of-the-art models perform poorly, with top accuracy at 47.6%, and all models improve significantly when image search tools are enabled. This highlights a major weakness in current systems for tasks that genuinely require visual understanding during browsing.

## Method Summary
The benchmark construction enforces visual-native search by curating questions where key discriminators exist only in pixel-level details (e.g., spatial positions, fine-grained attributes). Each instance requires cross-validating textual context with at least two separate visual evidence blocks across a minimum of three hops, ensuring that visual reasoning cannot be collapsed into a single lookup. The agentic framework provides tools for textual search, image retrieval, reverse image lookup, image cropping, and webpage visits. The agent must iteratively diagnose information gaps, select appropriate tools, integrate multimodal outputs, and synthesize answers with citations. This design forces a closed-loop process where visual evidence actively guides the search trajectory rather than being passively retrieved.

## Key Results
- Best model (Claude-4.6-Opus) achieves 47.6% accuracy; o3-Deep-Research reaches 41.1%.
- All models show significant improvement when image search tools are enabled, confirming the benchmark’s success in making visual reasoning essential.
- Open-source models lag substantially, with at most 14.2% accuracy, revealing a large performance disparity.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Visual reasoning is enforced by making visual evidence non-paraphrasable and spatially grounded.
- **Mechanism:** Questions are constructed so that critical information (e.g., "the person at the top right," "the fourth man from the left") can only be obtained through pixel-level analysis of provided or discovered images. Textual descriptions of these spatial or attribute details are insufficient or ambiguous, preventing models from relying solely on text search or internal knowledge.
- **Core assumption:** If visual information can be accurately paraphrased in text, models will bypass genuine visual reasoning.
- **Evidence anchors:** The dataset explicitly uses spatial descriptions and perceptual attributes missing from text; related benchmarks (MMSearch, BrowseComp-VL) fail this test because they allow textual shortcuts.
- **Break condition:** A model successfully answers using only text-based retrieval and reasoning, with no need to process image pixels beyond initial identification.

### Mechanism 2
- **Claim:** Multi-hop chains with interleaved visual evidence blocks force sustained multimodal reasoning across the search trajectory.
- **Mechanism:** Each question requires at least three hops and two distinct visual evidence blocks. The solution path includes "visual retrieval, event bridging, and cross-modal entity transition," where one visual element leads to a textual context that then requires locating and reasoning over a different visual element. This prevents the trajectory from collapsing into a single visual lookup followed by text-only deep search.
- **Core assumption:** Real-world visual-native search requires alternating between visual grounding and textual contextualization.
- **Evidence anchors:** Dataset construction rules mandate that visual information must implicate a distinct related entity from the previous hop; cross-image reasoning necessitates visual alignment rather than text matching.
- **Break condition:** All required visual evidence is contained within the initial query image(s), or all subsequent hops can be completed with text-only information after the first visual entity is identified.

### Mechanism 3
- **Claim:** The agentic workflow toolset actively drives the collection and integration of visual evidence through strategic tool orchestration.
- **Mechanism:** Providing five complementary tools and prompting the model to reason step-by-step encourages a closed-loop process where identified information gaps trigger specific tool calls. The workflow design makes image_search and image_crop necessary for resolving visual ambiguities that text_search cannot address, as shown by the performance gain when these tools are enabled.
- **Core assumption:** Current MLLMs will not spontaneously prioritize visual evidence gathering unless the tool-access paradigm and prompting explicitly incentivize it.
- **Evidence anchors:** The framework is designed to "drive the agent to actively collect and reason over visual information"; models like Kimi-K2.5 show large gains correlated with high image_search usage.
- **Break condition:** The model consistently fails to invoke image-related tools or invokes them but does not use their outputs to update reasoning (e.g., calls image_search but answers based only on snippet text from webpage_visit).

## Foundational Learning
- **Multimodal Evidence Integration**: The entire benchmark is built on the premise that answers require fusing information from different modalities (pixel data + text) where neither is sufficient alone. An engineer must understand how to design questions where visual attributes (color, spatial layout, object instances) are the *key discriminators*.
  - **Quick check:** Design a question where two textually identical entities (e.g., two "Blue Bird" brands) are distinguished only by a visual detail in their logo (e.g., shade of blue, orientation).
- **Tool Orchestration for Visual Gaps**: The agent workflow's success depends on correctly diagnosing *why* information is missing and selecting the right tool. A "visual gap" might require image_search (find an image of X), image_crop (isolate a region to see detail Y), or reverse_image_search (find source of a known image). Misdiagnosis leads to inefficient trajectories.
  - **Quick check:** Given a failure where a model searches text for "the color of the hat in the poster" but never uses an image tool, what is the likely visual gap in its reasoning?
- **Multi-Hop Reasoning with Visual Grounding**: Hops are not just textual connections (Entity A → Event B → Date C). They can be Visual A → (textual context) → Visual B. The engineer must trace how visual evidence from one hop becomes the query for the next (e.g., "the person identified in the cropped image" becomes the subject of a text search for their publication).
  - **Quick check:** Map the hops for the Einstein/Dirac question: starting from the group photo visual, what are the intermediate representations (entities/events) and which modality provides the critical evidence at each hop?

## Architecture Onboarding
**Component map:**
Query Analyzer → Tool Selector → Evidence Integrator → Reasoning Engine → (loop back to Tool Selector until ready) → Answer Synthesizer.
- Query Analyzer parses input to identify required visual facts.
- Tool Selector decides next tool call based on current knowledge and missing facts.
- Evidence Integrator processes tool outputs and updates working memory with (modality, content, source_url) tuples.
- Reasoning Engine checks if evidence satisfies requirements and formulates next sub-question.
- Answer Synthesizer composes final answer with citations.

**Critical path:**
Initial analysis of image identifies ambiguous entity (e.g., "the athlete in the red shirt") → use image_search or text_search to resolve entity identity → new visual gap emerges (e.g., "the girl to his right" requires finding a different image) → use webpage_visit on linked article → find new image → use image_crop to isolate group → repeat until all spatial/attribute facts are answered.

**Design tradeoffs:**
- Tool Granularity: More tools (crop, reverse) offer precision but increase decision complexity and potential for invalid calls.
- Prompting Strategy: Must balance between encouraging decomposition and avoiding over-prompting that biases toward excessive tool use.
- Evidence Storage: Deciding what constitutes a persistent "evidence block" (only cropped regions? all visited pages?) impacts state size and relevance.

**Failure signatures:**
- Text Shortcut Reliance: Model answers early sub-questions correctly with text but never initiates search for next visual evidence block (0% image_crop after initial steps).
- Tool Misinvocation: High reverse_image_search usage without subsequent webpage_visit, indicating failure to extract new contextual information from source pages.
- Visual Detail Ignorance: Model visits page with target image but answer synthesizer fails to reference visual attributes (e.g., describes "dark shirt" when ground truth is "black tie" only visible in image).
- Premature Termination: Model declares answer before all visual facts are satisfied, often when parametric knowledge feels "confident".

**First 3 experiments:**
1. **Baseline Capability Check:** Run 5 random instances with `Direct Answer` only. Expect ~20% accuracy, confirming parametric knowledge is insufficient. Log which questions were guessed correctly—these may have text-only shortcuts.
2. **Tool Ablation:** For the same 5 instances, run with `+TS` (text tools only). Measure drop vs. `+IS`. Significant drop (>10pp) on instance indicates visual evidence is truly necessary.
3. **Trajectory Clustering:** Run full `+IS` on a sample of 20 instances. Cluster successful vs. failed trajectories by tool sequence patterns. Expect successful ones to show patterns like [crop → image_search] or [text_search → image_crop → webpage_visit], while failed ones may show long text_search chains without image_crop.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** Why do certain MLLMs (e.g., Claude-4.6-Sonnet) fail to correctly utilize image search tools within the agentic workflow, leading to performance degradation?
- **Basis in paper:** "Claude-4.6-Sonnet cannot use image search tools correctly, which causes the framework to fail and results in lower accuracy." (Section 4.2)
- **Why unresolved:** The paper identifies this failure but does not investigate its underlying cause, whether due to prompting, training data, or inherent model limitations.
- **What evidence would resolve it:** Detailed error analysis of tool invocation sequences, ablation studies on prompt variations, or qualitative inspection of failed trajectories to pinpoint the breakdown point.

### Open Question 2
- **Question:** What architectural or training modifications are necessary to close the significant performance gap between open-source and closed-source MLLMs on visual-native search tasks?
- **Basis in paper:** Open-source models achieve at most 14.2% accuracy, while closed-source models reach 47.6% (Table 2, Section 4.2).
- **Why unresolved:** The paper reports this disparity but does not analyze contributing factors such as training data diversity, tool-integration fine-tuning, or model scale.
- **What evidence would resolve it:** Comparative studies controlling for model size, training corpora analysis, or experiments introducing tool-use distillation to open-source models to assess impact.

### Open Question 3
- **Question:** How can the agentic workflow be optimized to enhance multimodal evidence integration and cross-image reasoning beyond the current 47.6% accuracy ceiling?
- **Basis in paper:** The best model achieves only 47.6% accuracy despite using the proposed workflow, indicating suboptimal reasoning or tool-use strategies.
- **Why unresolved:** The workflow is presented as a fixed framework without systematic exploration of alternative designs, tool chaining, or reasoning prompting.
- **What evidence would resolve it:** Ablation experiments varying tool availability, ordering constraints, or prompting strategies; user studies to identify effective human-like search patterns; or reinforcement learning approaches to learn optimal workflows.

## Limitations
- The "non-paraphrasable visual evidence" claim relies on curated instances; it is difficult to guarantee no latent text-only shortcuts exist across the entire web corpus a browsing agent might access.
- The requirement for "two distinct visual evidence blocks" assumes models cannot bridge hops via textual inference from a single visual grounding; this may not hold for all constructed chains.
- The specific 5-tool set and prompting strategy are presented as sufficient, but the optimal granularity for visual-native search (e.g., separate vs. combined crop/search tools) is not explored.

## Confidence
- **Visual reasoning enforcement (Mechanism 1):** Medium. Dataset construction logic is sound and audited, but quantifying the "non-paraphrasable" property across all possible reasoning paths is inherently subjective.
- **Multi-hop chain validity (Mechanism 2):** Medium. Design explicitly blocks textual shortcuts, but external validation of whether each chain *strictly* requires interleaved visual evidence is limited to expert review.
- **Tool orchestration necessity (Mechanism 3):** Medium-Low. Ablation shows benefit, but experimental design does not isolate which *type* of visual gap (spatial, attribute, identity) each tool critically resolves; correlation between tool usage and success is observational.

## Next Checks
1. **Text Shortcut Audit:** Manually annotate 50 failed trajectories from Claude-4.6-Opus for evidence of successful textual reasoning later undermined by a missed visual detail.
2. **Cross-Benchmark Control:** Run top 3 models on a similar multimodal browsing benchmark (e.g., MMSearch-Plus) with identical tool access. A significant performance drop *unique* to VisBrowse-Bench would strengthen the claim of its uniquely visual-native difficulty.
3. **Tool-Gap Correlation Analysis:** Categorize all instances by primary "visual gap" type (spatial layout, fine-grained attribute, instance disambiguation). For each gap type, compute success rate conditional on specific tool call sequences (e.g., `image_crop` followed by `text_search`). This tests if the toolset adequately covers all necessary gap resolutions.
