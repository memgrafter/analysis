# Can VLMs Reason Robustly? A Neuro-Symbolic Investigation

## Quick Facts
- arXiv ID: 2603.23867
- Source URL: https://arxiv.org/abs/2603.23867
- Reference count: 26
- Primary result: VLC, a neuro-symbolic framework that decouples perception (VLM) from reasoning (Boolean circuit), achieves robust visual reasoning under covariate shift (e.g., 52.06% accuracy on 7-digit addition vs ≤1.35% for fine-tuned VLMs and 30.69% for Prism).

## Executive Summary
Vision-language models (VLMs) often struggle to generalize when visual inputs change but underlying logical rules stay constant—a case of covariate shift. This paper evaluates VLM reasoning robustness on three synthetic tasks (MNAdd, MNLogic, KandLogic) where the number of objects varies (3→5→7). Fine-tuning VLMs yields high accuracy on training distribution but collapses on test distributions; black-box neuro-symbolic approaches (Prism, ViperGPT) show inconsistent gains. The authors introduce VLC, which separates perception (VLM-based concept recognition) from reasoning (exact Boolean circuit). The circuit is compiled from the symbolic rule and applied to binary concept bits. Across all tasks, VLC dramatically outperforms baselines on the hardest cases (e.g., 52.06% vs ≤1.35% and 30.69% on 7-digit addition). The strong correlation between concept recognition and task accuracy confirms that exact rule execution yields robust reasoning once perception is adequate.

## Method Summary
The study uses visual deductive reasoning tasks generated via the rsbench framework. Each task presents images containing objects (handwritten digits or geometric primitives) and a natural‑language query; the underlying rule (e.g., addition, XOR, relational check) must be applied to the objects to produce a binary answer. Training and validation sets contain images with 3 objects, while test sets contain 5 or 7 objects, introducing covariate shift.

The proposed VLC pipeline operates in two stages. First, a VLM (Qwen2.5‑VL‑7B‑Instruct) takes an image and a few‑shot prompt to recognize and output the presence or numeric value of concepts (e.g., each digit). The VLM’s textual responses are parsed into binary bits representing those concepts. Second, a Boolean circuit implementing the task’s symbolic rule is compiled from the rule specification into an SDD (using pySDD). The binary bits are fed into the circuit, which deterministically computes the answer. No end‑to‑end training occurs.

Baselines include: (1) end‑to‑end zero‑shot prompting with the same VLM, (2) fine‑tuned VLM (5 epochs, AdamW, learning rate 2e‑4, batch size 4, gradient accumulation 8, warmup 0.03, gradient clipping 0.3), (3) Prism (VLM for concept extraction followed by LLM reasoning), and (4) ViperGPT (GPT‑4o generates a program that uses GroundingDINO and a VLM). All models are evaluated on the test sets; results averaged over 5 random seeds.

## Key Results
- On MNAdd‑7dgt (7‑digit addition), VLC achieves 52.06% accuracy; fine‑tuned VLM scores 1.35% and Prism 30.69%.
- On MNLogic‑7dgt (logical XOR with 7 elements), VLC reaches 60.31% versus 51.95% (fine‑tuned) and 50.53% (Prism).
- On KandLogic‑7obj (relational check with 7 geometric objects), VLC obtains 92.21% compared to 57.76% (fine‑tuned) and 56.35% (ViperGPT).
- VLC’s task accuracy is strongly correlated with its concept recognition accuracy, indicating that reasoning failures arise only from perception errors.

## Why This Works (Mechanism)
VLC’s robustness stems from its decoupled architecture. The perception module (VLM) is responsible for mapping raw visual inputs to discrete symbolic concepts; its errors are the sole source of inaccuracy. The reasoning module is a compiled Boolean circuit that exactly implements the logical rule, guaranteeing correct deduction given perfect concept inputs. Because the circuit’s operation is independent of perceptual variations, it remains invariant under covariate shifts (e.g., changes in object count, style, or layout). Fine‑tuned VLMs, by contrast, internalize both perception and reasoning in a monolithic black box; they overfit to spurious correlations in the training distribution and fail to generalize. Black‑box neuro‑symbolic methods like Prism and ViperGPT rely on an LLM to reason over VLM outputs, introducing nondeterminism and sensitivity to distribution shifts in the reasoning step. VLC replaces the LLM with a precise symbolic executor, eliminating this vulnerability.

## Foundational Learning
- **Vision‑Language Model (VLM)**: A neural model that processes images and text jointly (e.g., Qwen2.5‑VL). *Why needed*: Provides the interface from raw pixels to symbolic concepts (digits, shapes). *Quick check*: Can the VLM accurately identify individual handwritten digits in a multi‑digit image using a few‑shot prompt?
- **Neuro‑Symbolic Integration**: Combining neural perception with symbolic reasoning. *Why needed*: Leverages pattern recognition of neural networks and the reliability of logic‑based inference. *Quick check*: Does the system clearly separate concept extraction from rule application?
- **Boolean Circuit (SDD)**: A deterministic, compiled representation of a Boolean function (e.g., using pySDD). *Why needed*: Enables exact, efficient computation of answers without stochasticity. *Quick check*: Does the circuit return the correct logical output for all possible binary input combinations?
- **Covariate Shift**: Change in the distribution of input features while the conditional label distribution stays fixed. *Why needed*: Tests whether reasoning generalizes beyond superficial visual changes. *Quick check*: Does model performance drop when object count exceeds training?
- **Concept Recognition Accuracy**: Fraction of correctly recognized symbolic values. *Why needed*: Upper bounds task accuracy in decoupled systems. *Quick check*: Is there a linear relationship between concept accuracy and final task accuracy?

## Architecture Onboarding
**Component Map**:
Image -> VLM (few‑shot concept extraction) -> Binary Concept Bits -> Boolean Circuit (SDD) -> Answer -> Output. Additionally, Symbolic Rule -> Circuit Compiler (offline) produces the SDD.

**Critical Path**:
1. Input image is fed to the VLM with a structured prompt containing few‑shot examples.
2. VLM generates text responses for each target concept; a parser converts them to binary bits.
3. Bits are supplied to the precompiled SDD circuit.
4. The circuit evaluates in deterministic log‑space and outputs a binary decision.
5. The decision is mapped to the final answer (e.g., a number or yes/no).

**Design Tradeoffs**:
- Decoupling perception and reasoning provides exact inference and interpretability but makes the system dependent on VLM accuracy; no end‑to‑end training can optimize perception for the downstream task.
- Using a few‑shot VLM avoids costly fine‑tuning and allows quick adaptation to new tasks via prompt engineering, but may yield lower concept accuracy than a fine‑tuned specialist.
- Compiling a circuit from the symbolic rule ensures correctness but requires the rule to be expressible as a Boolean function; more complex relational reasoning may need richer representations.
- The SDD provides efficient, exact inference but incurs compilation overhead and depends on a random vtree; alternative representations (e.g., BDDs) could be used.

**Failure Signatures**:
- VLM outputs do not match expected parse format (e.g., extra text, missing values) → parsing error.
- Concept bits incorrect due to misrecognized digits/objects → task answer wrong.
- Circuit compiled with wrong variable ordering or encoding (e.g., bit width mismatch) → systematic answer bias.
- In baseline Prism/ViperGPT: LLM reasoning inconsistencies or detector failures (e.g., missing objects) cause poor generalization.

**First Experiments (3 steps)**:
1. **Data Generation**: Clone rsbench and generate MNAdd, MNLogic, KandLogic datasets for 3/5/7 object settings with default splits (train 10k, val 2k, test 3k). Verify image and label integrity.
2. **VLC Pipeline**: Using Qwen2.5‑VL‑7B‑Instruct, implement the few‑shot recognition prompt (as in paper’s Figure 6). Compile each task’s Boolean rule into an SDD (pySDD). Run inference on the test sets, parse VLM outputs, evaluate circuit, and compute task accuracy.
3. **Baseline Replication**: (a) End‑to‑end prompting with reasoning prompt (Figure 5). (b) Fine‑tune VLM on 3‑object training data using provided hyperparameters. (c) Implement Prism (VLM recognition + LLM reasoning) and ViperGPT (program generation with GPT‑4o and GroundingDINO). Compare all methods on 5‑ and 7‑object test sets.

## Limitations
- Dataset generation and evaluation specifics (rsbench usage, random seeds, splits) are not fully documented, hindering exact replication.
- Few‑shot prompt examples are omitted; custom prompts may introduce variability in concept recognition.
- Binary encoding details (bit width, ordering) and mapping from VLM outputs to circuit inputs are unspecified, potentially leading to implementation mismatches.
- ViperGPT’s detection thresholds and post‑processing are not described, likely contributing to its poor performance on MNAdd.
- Evaluation is confined to synthetic tasks; robustness in real‑world, natural images remains an open question.
