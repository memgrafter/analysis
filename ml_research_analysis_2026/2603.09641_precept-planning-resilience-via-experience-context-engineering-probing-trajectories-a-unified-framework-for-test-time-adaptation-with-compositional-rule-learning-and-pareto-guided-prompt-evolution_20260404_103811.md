# PRECEPT: Planning Resilience via Experience, Context Engineering & Probing Trajectories A Unified Framework for Test-Time Adaptation with Compositional Rule Learning and Pareto-Guided Prompt Evolution

## Quick Facts
- **arXiv ID**: 2603.09641
- **Source URL**: https://arxiv.org/abs/2603.09641
- **Reference count**: 23
- **Primary result**: PRECEPT achieves +41.1pp first-try advantage over Full Reflexion and 61% fewer steps, with strong robustness to adversarial knowledge and drift.

## Executive Summary
LLM agents that store knowledge as natural language suffer exponential retrieval degradation as condition count grows, struggle to compose rules reliably, and lack mechanisms for stale or adversarial knowledge. PRECEPT addresses these limitations through three integrated components: deterministic O(1) exact-match retrieval over structured condition keys, conflict-aware memory with Bayesian source reliability and threshold-based rule invalidation, and COMPASS—a Pareto-guided, dual-frequency prompt evolution outer loop. Across synthetic logistics, booking, and integration domains, PRECEPT yields substantial gains: +41.1 percentage points in first-try success over state-of-the-art reflexion methods, +33.3pp in compositional generalization (including 100% P1 on 2-way logistics), +55.0pp in drift recovery, and 61% fewer execution steps, while maintaining resilience under adversarial static knowledge.

## Method Summary
PRECEPT unifies three innovations: (1) structured rule storage with exact-match hashing enables deterministic, scalable retrieval and compositional stacking via a semantic tier hierarchy; (2) Evo-Memory employs an ensemble detector (threshold θ=0.30) to identify static–dynamic conflicts and resolves them using Bayesian source reliability (Beta posteriors with Thompson Sampling), while drift adaptation halves confidence per failure and invalidates after θ=2 consecutive failures; (3) COMPASS uses dual-frequency control—high-frequency O(1) per-step monitoring and low-frequency event-triggered prompt evolution with Pareto selection (success rate weight 0.7, step efficiency weight 0.3) and MAP-Elites diversity. Training exposes agents to atomic precepts (β=3 per condition key); at test time, tasks are parsed, complexity-evaluated, rules retrieved (exact/semantic/compositional), solutions derived via tier-sorted precedence, executed via MCP tools, and outcomes update knowledge.

## Key Results
- First-try success improved by +41.1pp over Full Reflexion (Cohen’s d>1.9, often p<0.001).
- Compositional generalization gain of +33.3pp, achieving 100% P1 on 2-way logistics compositions (d=2.64).
- Drift recovery enhanced by +55.0pp (d=0.95, p=0.031) and 61% fewer execution steps.

## Why This Works (Mechanism)

### Mechanism 1: Exact-match retrieval for deterministic composition
PRECEPT eliminates partial-match interpretation errors by storing learned rules in a hash table keyed by structured condition strings, enabling O(1) exact retrieval. This deterministic substrate supports compositional stacking via a semantic tier hierarchy, theoretically providing conditional 2^N−1 coverage from N atomic precepts. The core assumption is that condition keys are discrete and canonicalizable, and the environment’s solution mapping is deterministic given the key. Evidence: The abstract states exact retrieval eliminates partial-match errors (0% by construction vs 94.4% under Theorem B.6 at N=10). Section 2.5 defines Tier 1 O(1) lookup; Section 3.2 details the tier hierarchy and Algorithm 1 for deterministic composition. Break condition: fails if condition keys are not discretizable (e.g., continuous features without binning) or if hash collisions occur; incorrect rules may still be retrieved but are handled by conflict resolution.

### Mechanism 2: Conflict resolution for static–dynamic and drift
PRECEPT resolves conflicts between static and dynamic knowledge (Type I) and adapts to rule drift (Type II) using a six-method ensemble detector (threshold θ=0.30) to identify conflicts. Resolution applies Bayesian source reliability (static Beta(5,5), dynamic Beta(5,3)) with Thompson Sampling. For drift, each failure halves rule confidence; after θ=2 consecutive failures, the rule is invalidated. Core assumption: source reliability is approximately stationary within segments; failures are detectable and attributable; invalid rules can be overwritten. Evidence: Abstract mentions conflict-aware memory resolves static–dynamic disagreements and supports drift adaptation. Section 4.1 defines Bayesian model and ensemble weights; Section 4.3 specifies invalidation; Experiments 6 and 7 validate adversarial knowledge recovery and drift adaptation. Corpus: Neighbor works like XSkill address continual learning but not per-rule Bayesian conflict resolution. Break condition: local stationary segment assumption may lag under rapidly non-stationary environments; fixed θ=2 risks premature deletion from transient failures; ensemble detector may miss conflicts with sparse evidence.

### Mechanism 3: COMPASS Pareto-guided prompt evolution
COMPASS optimizes system prompts through end-to-end execution evaluation via dual-frequency control: high-frequency O(1) constraint checks each step and low-frequency event-triggered prompt evolution. Low-frequency path allocates rollouts based on complexity, performs bi-objective Pareto selection (success rate weight 0.7, step efficiency weight 0.3), maintains diversity via MAP-Elites, and verifies evolution through actual execution signals. Core assumption: prompt variations significantly affect performance; bi-objective trade-off captures desired behavior; evolutionary search discovers better prompts. Evidence: Abstract notes COMPASS evaluates prompts through the same execution pipeline. Section 5.1–5.7 details architecture, rollout strategy, Pareto selection, dual-frequency loop. Experiment 9 shows Outer Loop Enabled +10.66pp P1 (p≈0.06) and −0.51 steps vs Disabled in OOD semantic tests. Corpus: Neighbor prompt evolution methods lack Pareto selection and dual-frequency integration. Break condition: low-frequency evolution is computationally costly and may not converge with limited rollouts or noisy evaluation; gains are regime-dependent (stronger in OOD semantic); high-frequency monitor adds per-step overhead (though O(1)).

## Foundational Learning
- **Exact-match retrieval**: Needed to avoid exponential partial-match errors in multi-condition scenarios. Quick check: According to Theorem B.6, what is the partial-match error probability at N=10 with per-condition accuracy p=0.75? (Answer: 94.4%)
- **Bayesian source reliability**: Needed to decide between conflicting static (potentially adversarial) and dynamic (first-hand) knowledge without global retraining. Quick check: What are the prior Beta parameters for static and dynamic sources? (Answer: static Beta(5,5), dynamic Beta(5,3))
- **Pareto optimality in multi-objective optimization**: Needed to balance task success and step efficiency, preventing greedy convergence collapse and maintaining diversity. Quick check: If candidate A has success_rate=0.8, step_efficiency=0.6 and candidate B has 0.7 and 0.8, which dominates which? (Answer: neither; both lie on the Pareto front)

## Architecture Onboarding
### Component Map
PRECEPTAgent (client) orchestrates parsing, retrieval, execution, learning; it communicates with precept_mcp_server (server) which handles MCP dispatch, conflict resolution, low-frequency COMPASS, domain executors, and persistent stores. Internal modules: RefineInterceptor (deterministic pruning), ConflictManager (ensemble detection and Bayesian resolution), PRECEPTComplexityAnalyzer, SmartRolloutStrategy, Pareto selector, GEPAEvolutionEngine. Knowledge tiers: static KB (vector DB), dynamic experience (vector DB), episodic memory (trajectory store), learned rules (hash table).

### Critical Path
Seven-phase execution: (1) Task parsing (hybrid rule+LLM), (2) COMPASS complexity analysis (block/proceed/fast-path), (3) Retrieval (exact O(1) | semantic | compositional), (4) Derivation (tier-sort; max tier wins), (5) Execute (domain tool calls via MCP), (6) Outcome (success: confidence+0.25; failure: confidence×0.5; invalidate if failure count ≥ θ=2), (7) Knowledge update (extract atomic precepts, store experience).

### Design Tradeoffs
Exact-match vs. semantic generalization: requires discrete keys but gains determinism; loses fuzzy matching. Bayesian conflict resolution assumes local stationarity; fast adaptation in stable segments but may lag in volatile settings. COMPASS dual-frequency: prompt evolution benefits vs. computational overhead; gains regime-dependent. Rule invalidation θ=2: quick drift detection vs. risk of premature deletion from transient failures.

### Failure Signatures
Repeated failures on same condition key despite prior success → possible drift or retrieval mismatch (check rule confidence, conflict logs). High ensemble conflict rate (weighted_conflict ≥0.30) → static vs dynamic knowledge clash (inspect detector votes). Low step efficiency (many retries) → poor prompt or retrieval mode; should trigger COMPASS evolution. P1 much lower than Pt → first-try penalty (adversarial SK or LLM prior bias); check retrieval path. COMPASS evolution not improving → low diversity score or insufficient rollouts; check MAP-Elites grid.

### First 3 Experiments
1. **Experiment 1** (Main domain comparison): Across Integration, Booking, Logistics, PRECEPT achieves +41.1pp first-try advantage over Full Reflexion and 61% fewer steps.
2. **Experiment 2** (Compositional generalization): Train on atomics, test 2-/3-way compositions. PRECEPT gains +33.3pp compositional generalization and 100% P1 on 2-way logistics.
3. **Experiment 3** (Training size ablation): Vary β∈{1..5}. PRECEPT reaches 100% P1 on Integration at β≥3 and maintains 87.5–92.5% on Logistics; baselines stagnate.

## Open Questions the Paper Calls Out
### Open Question 1
How does PRECEPT scale to high-cardinality condition spaces (E ≫ 100) and large composite condition counts (N > 5), especially with mixed discrete-continuous representations? Basis: Future work F5 calls for evaluation of large-E and larger N regimes, and mixed representations. Why unresolved: Experiments only covered E ≤ 17 and N ≤ 5; theoretical analysis does not address computational or accuracy scaling. What evidence would resolve: Systematic benchmarks varying E and N, measuring retrieval latency, compositional coverage, and error patterns; extending theoretical model to predict scaling behavior.

### Open Question 2
How does PRECEPT handle gradual, cyclical, or adversarial drift compared to the abrupt shift tested in Experiment 7? Basis: Scope limitation S4 restricts drift experiments to a single change-point; theoretical bounds assume local stationary segments. Why unresolved: Only abrupt, piecewise-stationary drift was evaluated. Interaction of threshold-based invalidation with continuous or adaptive drift is unknown. What evidence would resolve: Simulations with controlled drift profiles (linear trends, periodic shifts, adaptive adversaries) tracking adaptation speed, rule invalidation rates, and final performance.

### Open Question 3
Do the theoretical guarantees (e.g., zero partial-match errors, drift resilience ratio) hold when modeling assumptions (independent condition retrieval, stationary source reliability) are violated? Basis: Notes T1 (dependence) and T4 (non-stationarity) acknowledge reliance on simplifying assumptions. Why unresolved: Real-world data may exhibit correlated retrieval errors or time-varying source reliability, which could degrade predicted bounds. What evidence would resolve: Controlled experiments that artificially induce correlation or non-stationarity, measuring deviations from predicted error/resilience ratios; developing relaxed theoretical models.

### Open Question 4
Under what task and environment conditions does low-frequency COMPASS prompt evolution yield significant performance gains, and can its effectiveness be predicted a priori? Basis: COMPASS ablations show regime-dependent effects: marginal gains in matched-key settings and borderline benefits in OOD semantic tests. Why unresolved: Factors determining when prompt evolution adds value are not identified; mechanism behind borderline statistical significance unclear. What evidence would resolve: Correlational analysis between evolved prompt characteristics, task properties (e.g., semantic ambiguity, retrieval difficulty), and outcome metrics; building a meta-predictor to forecast when low-frequency evolution is worthwhile.

## Limitations
- Baseline implementations (Enhanced Full Reflexion/ExpeL) are incompletely specified, risking comparison validity.
- Synthetic domain generation details (condition templates, MD5 salt, option ordering) are partially abstracted, requiring reverse-engineering.
- COMPASS trigger conditions (e.g., “phase change,” diversity_score thresholds) are conceptual; precise hyperparameters may differ from reported values.
- Seed synchronization across client-server processes and LLM sampling is ambiguous, potentially affecting statistical significance claims.

## Confidence
- Deterministic retrieval advantage: High (Theorem B.6 quantifies partial-match error; experiments consistently show exponential gains in multi-condition scenarios).
- Conflict resolution robustness: Medium (adversarial/drift tests support efficacy, but stationarity assumption may lag under rapid non-stationarity; fixed θ=2 risks premature invalidation).
- COMPASS prompt evolution: Medium (OOD semantic gains demonstrated, but computational overhead and convergence with limited rollouts are regime-dependent; low-frequency trigger guards are opaque).

## Next Checks
1. Test exact-match retrieval failure on continuous/binned features—measure retrieval success when condition keys require non-discretizable transformations.
2. Profile conflict detector false negatives under accelerating drift (e.g., hourly rule changes) to quantify θ=2 invalidation lag versus transient noise.
3. Run COMPASS with constrained rollout budgets (e.g., 5 vs. 20 rollouts) to map Pareto front of prompt quality gains against wall-clock overhead.
