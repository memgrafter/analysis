# Overview of TREC 2025 Biomedical Generative Retrieval (BioGen) Track

## Quick Facts
- **arXiv ID**: 2603.21582
- **Source URL**: https://arxiv.org/abs/2603.21582
- **Reference count**: 15
- **Primary result**: Systems achieved >90% answer accuracy but struggled to identify contradictory citations, with Task A contradiction F1 max 15.67% and Task B contradiction rates <5%.

## Executive Summary
The TREC 2025 Biomedical Generative Retrieval (BioGen) track targeted the problem of LLM hallucinations in biomedical question answering by requiring systems to ground responses in verifiable PubMed citations. Two tasks were defined: Task A, where systems assign supporting and contradictory citations to provided answer sentences, and Task B, where systems generate answers with inline sentence-level citations. Results showed that while supporting citation identification was relatively successful (Task A support F1 up to 67.74%) and answer generation accuracy exceeded 90%, contradictory citation identification remained a significant weakness (Task A contradiction F1 max 15.67%; Task B contradiction rates <5%). Automated evaluation using the BioACE framework aligned with expert judgments, but the gap in reliably grounding output with counter-evidence persists.

## Method Summary
Participants predominantly adopted a two-stage retrieval-augmented generation (RAG) pipeline. For Task B, a lexical retriever (BM25) fetched thousands of PubMed documents, which were re-ranked (e.g., cross-encoder) to select a top‑k subset. These documents were processed (often with extractive summarization) and fed to an LLM (commonly a fine‑tuned LLaMA2‑7B) to generate cited answers. Task A relied on natural language inference (NLI) models (e.g., SciFive fine‑tuned on MedNLI) to classify whether a retrieved document contradicts a given answer sentence. Performance was measured via F1 for citation assignment (Task A) and a suite of metrics for answer and citation quality (Task B). The BioACE framework used an LLM‑as‑judge to automate citation quality assessment.

## Key Results
- Task A: Supporting citation identification reached 67.74% F1 (relaxed), but contradictory citation identification peaked at only 15.67% F1.
- Task B: Most systems achieved >90% answer accuracy; best runs attained 97.8% citation support rate, yet contradiction rates remained below 5%.
- Automated (BioACE) and expert evaluations showed consistent alignment across multiple criteria.

## Why This Works (Mechanism)
### Mechanism 1: Retrieval-Augmented Generation (RAG) Pipeline
Most participants used a two‑stage RAG: a lexical retriever (BM25) fetched a broad set of PubMed documents, which were then re‑ranked (cross‑encoder) to a top‑k subset. This subset was prepared (e.g., extractive summaries) and provided to an LLM that generated answer sentences with inline citations. The core assumption is that high‑quality retrieval is prerequisite; the LLM can reliably synthesize and cite from the given contexts. Evidence: The paper states “most runs used a two‑stage retrieval-augmented generation (RAG) approach” and the baseline follows this design. Break condition: If retrieved documents lack evidence for key claims, the LLM may hallucinate or omit citations.

### Mechanism 2: NLI-Based Contradiction Detection (Task A)
Systems applied an NLI model (e.g., SciFive fine‑tuned on MedNLI) to classify document‑sentence pairs as entails/supports, contradicts, or neutral. Contradictory classifications populated the “contradicting PMIDs” list. The core assumption is that biomedical NLI models transfer to abstract‑sentence grounding. Evidence: Task A description expects contradictory PMIDs; baseline uses SciFive. However, contradiction F1 max 15.67% shows failure, likely due to scope/negation complexities or data imbalance.

### Mechanism 3: Nugget-Based Automated Citation Evaluation
The BioACE framework uses an LLM (LLama‑3.3) prompted to judge whether a cited document supports, contradicts, or is neutral toward an answer sentence, enabling scalable metric computation. The core assumption is that a powerful LLM can proxy human judgment on fine‑grained semantic alignment. Evidence: Section 7.1.2 describes this method. The authors note future correlation analysis, implying the LLM judge’s validity is not yet proven. Break condition: LLM biases (e.g., favoring lexical overlap) could misalign automated metrics with human evaluation.

## Foundational Learning
1. **Biomedical Information Retrieval (IR)**
   - *Why needed*: All systems must retrieve relevant PubMed documents from ~26.8M abstracts; mastery of BM25, vector search, and re‑ranking is fundamental to the RAG first stage.
   - *Quick check*: How would you modify BM25 for “Can dogs help lower cortisol?” to include synonyms (“canine”, “stress hormone”) and medical contexts?

2. **Natural Language Inference (NLI) in the Medical Domain**
   - *Why needed*: Task A’s contradiction detection requires understanding entailment/contradiction beyond keywords, especially with hedging, negations, and conditionals common in biomedical text.
   - *Quick check*: Why might an NLI model trained on MedNLI (premise‑hypothesis pairs) fail when the premise is a full PubMed abstract and the hypothesis is a single answer sentence?

3. **Citation Grounding & Evidence Semantics**
   - *Why needed*: The core challenge is mapping generated text to verifiable sources; distinguishing *support*, *partial support*, and *contradiction* in scientific contexts is essential.
   - *Quick check*: For “Melatonin might help lower cortisol,” is a study reporting “Melatonin supplementation did not significantly change cortisol levels” a *contradiction* or *neutral*? What context would flip the label?

## Architecture Onboarding
- **Component map**: Query Processor -> Retriever (BM25/Dense) -> Re‑ranker (Cross‑encoder) -> Context Preparator -> Generator (LLM) -> [Citation Assigner]. For Task A: Answer Sentence + Retrieved Docs -> NLI Classifier (per pair) -> Contradicting/Supporting PMIDs.
- **Critical path**: Question -> Retriever -> Re‑ranker -> Context Prep -> Generator (Task B).
- **Design tradeoffs**:
  - Retrieval recall vs. precision: High recall captures evidence but adds noise; re‑ranker trades recall for precision.
  - Citation granularity: One PMID per sentence (strict) vs. up to three (flexible); more citations risk irrelevant/contradictory sources.
  - Generative freedom vs. constraint: Paraphrasing improves fluency but may drift from sources, hurting citation accuracy; extract‑only avoids drift but lacks synthesis.
- **Failure signatures**:
  - Task B: High answer accuracy (>90%) but low citation support (<50%) → correct answers with poor citation.
  - Task A: High support F1 but contradict F1 <20% → failure to find counter‑evidence, a safety gap.
  - Consistently high redundancy/harmfulness scores → poor length control or inappropriate content.
- **First 3 experiments**:
  1. Baseline replication: Implement BM25+SciFive (Task A) and BM25+rerank+LLaMA2 (Task B) to verify reported baseline scores.
  2. Component isolation: For Task B, replace re‑ranker with random selection from BM25 top‑1000; measure drop in citation support rate.
  3. Contradiction probe: Manually identify contradictory abstracts for 20 answer sentences; run the NLI system; if >50% missed, redesign contradiction module.

## Open Questions the Paper Calls Out
1. Why do current systems consistently fail to identify contradictory citations, and what architectural or training modifications could significantly improve contradiction identification performance?
2. How can answer generation systems be optimized to produce citations that include a meaningful proportion of contradictory evidence without sacrificing answer quality or support rate?
3. To what extent do the automated evaluation metrics (BioACE with LLM‑as‑judge) correlate with expert human judgments across the multifaceted criteria (answer quality, citation quality, document relevance)?
4. Would a unified, multi‑task model that jointly performs answer generation and citation grounding yield superior performance compared to the predominant two‑stage RAG pipeline?

## Limitations
- The precise reasons for poor contradiction detection (NLI model bias, data imbalance, task formulation mismatch) remain unclear.
- BioACE’s LLM‑based evaluation lacks published correlation with human judgments, risking metric misalignment.
- Reproduction is hindered by missing implementation details: bottom‑line extractor algorithm, reranker model, SciFive checkpoint.
- The RAG pipeline’s component contributions (retrieval vs. generation) were not ablated, limiting architectural insights.

## Confidence
- RAG pipeline used by most participants: High
- NLI-based contradiction detection performed poorly (max F1 15.67%): High
- Answer generation achieved >90% accuracy: High
- BioACE evaluation framework validity (vs. human): Medium
- Retrieval quality is prerequisite for grounded generation: Medium

## Next Checks
1. Reproduce baseline scores: Implement the described BM25+SciFive pipeline for Task A and BM25+rerank+LLaMA2 for Task B to verify reported metrics.
2. Human correlation study: Conduct a small‑scale human evaluation of BioACE labels on 100 sentence–citation pairs to measure agreement (e.g., Cohen’s κ).
3. Contradiction-focused retrieval experiment: Modify the retriever to explicitly include negated terms (e.g., “no effect”, “not significant”) and measure impact on contradiction F1 in Task A.
