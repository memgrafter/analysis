# When Career Data Runs Out: Structured Feature Engineering and Signal Limits for Founder Success Prediction

## Quick Facts
- **arXiv ID:** 2604.00339
- **Source URL:** https://arxiv.org/abs/2604.00339
- **Reference count:** 4
- **Primary result:** Predicting startup success from founder career data hits an information ceiling (~CV 0.25, Val 0.30) due to weak signals and rare positives (9%), with a deterministic prior exit rule and structured JSON parsing providing the only meaningful gains over a zero-shot LLM baseline.

## Executive Summary
This paper studies the limits of predicting startup success using only founder career histories from the VCBench dataset. The authors find that raw prose summaries (`anonymised_prose`) are a lossy re-encoding of structured JSON fields (`jobs_json`, `educations_json`), making LLM-based feature extraction from text unrewarding. By engineering 28 structured features directly from the JSON and adding a deterministic rule for founders with prior exits, they achieve a validation F0.5 of 0.3030—a +17.7 pp improvement over a zero-shot LLM. However, extensive modeling converges on a performance ceiling (CV ~0.25), indicating that for 84% of successful founders (those without prior exits), career data alone contains insufficient discriminatory signal. The work concludes that breaking this ceiling requires fundamentally richer covariates like idea quality or market timing.

## Method Summary
The authors parse raw JSON fields for jobs, education, IPOs, and acquisitions to engineer 28 structured features across four tiers (prior exits, "sacrifice" signals, education relevance, career trajectory). They apply a deterministic pre-classifier rule: any founder with `exit_count > 0` is predicted as successful. For the remaining founders, an XGBoost model with decision stumps (`max_depth=1`) is trained to predict binary success, optimized for the imbalanced F0.5 metric. The pipeline is evaluated via 5-fold cross-validation and a held-out validation set, with a separate experiment showing that LLM-extracted features from the `anonymised_prose` field add no predictive signal.

## Key Results
- Validation F0.5 = 0.3030 (Precision = 0.3333, Recall = 0.2222), improving over zero-shot LLM baseline by +17.7 percentage points.
- The deterministic prior exit rule alone achieves Val F0.5 = 0.2889, capturing a high-precision subset (2.7× base rate).
- Cross-validation and validation results converge on an information ceiling of CV ≈ 0.25, Val ≈ 0.30, beyond which no model or feature engineering improves performance.
- LLM-based feature extraction from `anonymised_prose` yields a negligible CV delta of -0.05 percentage points, confirming the prose field's redundancy.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Direct JSON parsing extracts higher-fidelity career signals than LLM-based extraction from `anonymised_prose`.
- **Mechanism:** The `anonymised_prose` is a deterministic, lossy re-encoding of the structured JSON fields. Parsing the source JSON recovers exact numerical values (e.g., company size buckets, role seniority codes) and preserves nulls and field interactions degraded or omitted in natural language summaries. LLM extraction cannot recover information already lost in the re-encoding.
- **Evidence anchors:** [abstract] states prose is a lossy re-encoding; [section III.A & VI] details poor preservation of ordinal buckets and nulls; LLM feature experiment shows zero CV signal gain at 100% coverage.

### Mechanism 2
- **Claim:** A deterministic rule layer based on prior exits (`exit_count > 0`) captures a high-precision, low-recall subset with a strong, non-linear success signal.
- **Mechanism:** Prior exits are rare (106 training rows) but have a dramatically higher base success rate (22.8–60% vs. 8.5% overall). The simple rule fires on this subgroup, providing an immediate, stable precision boost (16.2 pp over zero-shot) that acts as a reliable prior for the downstream model.
- **Evidence anchors:** [section III.C] reports rule precision = 24.5% (2.7× base rate); [section V.table II] shows rule-only achieves Val F0.5=0.2889.

### Mechanism 3
- **Claim:** The performance ceiling (~CV 0.25, Val 0.30) is an information ceiling driven by dataset composition, not model capacity, because ~84% of positive cases (non-exit founders) are statistically indistinguishable from failures on all available career features.
- **Mechanism:** The dataset exhibits a two-population structure: a small, high-signal "exit" group (16% of positives) and a large, low-signal "non-exit" group (84% of positives). All engineered features and models only reliably identify the exit group. For the non-exit majority, no feature provides a success rate ratio >1.38×, too weak to overcome the 9% base rate under F0.5.
- **Evidence anchors:** [section VI] states 84% of successes are non-exit and indistinguishable; [section VI.table IV] confusion matrix shows 332/405 false negatives are structurally hard; [abstract] attributes ceiling to dataset information content.

## Foundational Learning
- **Concept: Imbalanced Classification with Asymmetric Metric (F0.5)**
  - **Why needed here:** The 9% positive rate and F0.5 metric (precision weighted twice recall) force design choices toward high precision. The rule layer's value is its high precision; a model with 18% recall but 3.6× base-rate precision is a significant win. Understanding this metric explains why predicting all "failure" scores 0 and why recall-heavy models are penalized.
  - **Quick check question:** Why does a model that predicts all "failure" achieve an F0.5 score of 0? How would a model that predicts all "success" score, and why is it useless?
- **Concept: Information-Theoretic Limits vs. Modeling Limits**
  - **Why needed here:** The paper's core conclusion is about a *dataset* ceiling, not a *modeling* ceiling. This requires distinguishing the maximum achievable performance given the features/labels (information ceiling) from the ceiling of a specific model class (modeling ceiling). Their evidence: multiple model families and HPO all converge to the same CV/val range.
  - **Quick check question:** If you achieved a much higher validation F0.5 (e.g., 0.40) with a deep neural network, would that disprove the information ceiling claim? What would you check first?
- **Concept: Causal Feature Design vs. Correlational Feature Extraction**
  - **Why needed here:** The engineered features (Tiers 2–4) are *causal/mechanistic* hypotheses: "sacrifice signals" (e.g., leaving a large company) are theorized to *cause* higher success probability via demonstrated conviction. LLM feature extraction from prose is *correlational*: it identifies text patterns *associated* with success but, in this dataset, those patterns are just noisy re-statements of the same causal facts in the JSON. The failure of LLM features tests whether the JSON fields are a complete causal summary.
  - **Quick check question:** Give an example of a "sacrifice signal" feature from the paper and explain the implied causal story behind it.

## Architecture Onboarding
- **Component map:** Data Loader & Parser -> Feature Engineering Module -> Deterministic Rule Layer -> ML Model Wrapper -> Evaluation & CV Orchestrator
- **Critical path:** Parser must be 100% faithful to the JSON schema. A single parsing bug corrupts all 28 features and invalidates the experiment. Rule layer application must be documented as affecting only the subset with `exit_count>0` (~2.4% of rows). Evaluation must ensure no data leakage (e.g., features like `max_company_size_before_founding` must use only pre-founding jobs).
- **Design tradeoffs:**
  - **Stumps vs. Deep Trees:** Stumps are forced by data sparsity (few positives). This is a *diagnostic signal* of information ceiling, not a "best model" choice. Resist the urge to increase depth without more data or new features.
  - **Feature Coverage vs. Signal:** `repeat_founding_gap` was dropped due to 73.8% nulls. The tradeoff is between a potentially powerful signal for a tiny subset (serial founders) vs. model simplicity and stability. The chosen path favors universal features.
  - **LLM Feature Cost vs. Return:** The 100% coverage experiment proved LLM features are redundant here. For similar datasets, treat LLM extraction as a *comparative experiment*, not a default component.
- **Failure signatures:**
  - **Parsing failure:** Feature distributions do not match paper statistics (e.g., `exit_count` mean should be ~0.09). Check JSON schema compliance.
  - **Metric mismatch:** Validation F0.5 significantly higher/lower than 0.30±0.03. Could indicate data leakage (using future info) or wrong `scale_pos_weight`.
  - **LLM feature "improvement":** Any CV gain from LLM features >1pp is likely spurious given the -0.05pp null result at full coverage. Statistically, it should be within ±0.05pp.
  - **Model variance:** High standard deviation (>0.05) across CV folds suggests overfitting—often from too many features or insufficient `min_child_weight`/`gamma`.
- **First 3 experiments:**
  1. **Replication of Structured Features Core:** Implement all 28 features from Table I, *without* the rule layer. Train a stump on 5-fold CV. Target: CV F0.5 ~0.22 (matching "Structured v1"). This validates feature extraction.
  2. **Rule Layer Integration:** Add the `exit_count > 0` deterministic rule. Expect CV F0.5 to jump to ~0.29. This validates the rule's standalone impact and its combination with the stump model.
  3. **LLM Feature Null Test:** Extract the 9 prose-based features from the paper (using a consistent LLM prompt) on a 500-row subset. Train two models: (a) structured-only, (b) structured+LLM. Compare CV F0.5. Expect delta ~0.00 (±0.05). If delta >0.5pp, investigate for data leakage or prompt-induced correlation with JSON fields.

## Open Questions the Paper Calls Out
- **Open Question 1:** What specific, non-career data dimensions (e.g., idea quality, market timing, team dynamics) would most effectively break the identified ~0.30 F0.5 informational ceiling for founder success prediction?
  - **Basis in paper:** [explicit] The conclusion states that pushing past the ceiling "requires signals that do not exist in this dataset: idea quality, market timing, team composition, investor network effects, macroeconomic context at founding."
  - **Why unresolved:** The paper demonstrates that all modeling and feature engineering on the available career data converges to a hard limit. The next research frontier is identifying which of these missing signal classes has the highest marginal predictive value.
  - **What evidence would resolve it:** A controlled experiment augmenting VCBench with one new data dimension (e.g., parsed pitch deck text for idea novelty, or market TAM/SAM figures at founding) and measuring the delta in cross-validation F0.5.
- **Open Question 2:** For the 84% of successful founders with no prior exit, what latent, unobserved factors—beyond the 28 engineered features—differentiate them from the failure cohort?
  - **Basis in paper:** [explicit] The "two-population structure" analysis shows 84% of positives have no exits and are "statistically indistinguishable from failures" on all structured metrics. The authors call this the "structurally hard population."
  - **Why unresolved:** The model's near-zero recall for this subgroup indicates a complete absence of extractable signal from the provided JSON schema. The nature of the missing signal is uncharacterized.
  - **What evidence would resolve it:** A qualitative analysis (e.g., manual review of the anonymized_prose for the true positive, non-exit founders) to identify recurring themes or patterns not captured by the JSON fields, which could then be operationalized into new features.
- **Open Question 3:** In datasets where founder prose is authored by humans (e.g., LinkedIn summaries, pitch decks) rather than being a machine-generated lossy re-encoding of structured JSON, does LLM-based feature extraction yield a statistically significant positive delta over structured parsing alone?
  - **Basis in paper:** [explicit] The third limitation explicitly states: "In datasets where prose is written by humans... LLM extraction may surface signals genuinely absent from structured fields." Their own experiment on machine-generated prose showed zero delta.
  - **Why unresolved:** The core finding of redundancy is tied to the specific VCBench data generation pipeline. The hypothesis that human-authored text contains orthogonal information is plausible but untested.
  - **What evidence would resolve it:** An ablation study on a new founder dataset with both rich structured fields (like education/jobs) and independently written narrative bios, comparing model performance with (1) structured features only, (2) LLM-extracted features from bios only, and (3) both combined.
- **Open Question 4:** Can advanced techniques for handling extreme class imbalance and small-signal regimes (e.g., synthetic minority oversampling, metric learning, few-shot meta-learning) enable the use of deeper, more complex model architectures (beyond decision stumps) without overfitting, and would they modestly surpass the current ceiling?
  - **Basis in paper:** [inferred] The authors found that all models, including ensembles, converged on decision stumps (`max_depth=1`). They rationalize this as an information limit: "With 405 positives, deeper decision boundaries cannot be estimated reliably." This assumes the modeling limitation is purely a consequence of data sparsity.
  - **Why unresolved:** While convincing, the conclusion that the ceiling is purely data-theoretic rests on the failure of standard ML. It leaves open whether more sophisticated regularization or paradigm shifts (e.g., representation learning) could eke out marginal gains by better utilizing the weak, diffuse signal.
  - **What evidence would resolve it:** A dedicated experiment applying state-of-the-art imbalanced-learning and few-shot learning techniques to the VCBench feature set, rigorously evaluating whether any configuration achieves a CV F0.5 > 0.26 with statistically significant improvement over the reported 0.2539±0.035.
- **Open Question 5:** Does the ~0.30 validation ceiling generalize to other founder success prediction tasks with different outcome definitions (e.g., fund-level returns, survival at 5-years vs. 10-years) or different data collection pipelines?
  - **Basis in paper:** [explicit] The first limitation states: "The information ceiling characterization (CV≈0.25) is dataset-specific. We have not validated whether structured career features show similar limits on other founder success datasets; different labeling criteria, time horizons, or data collection pipelines may yield different ceilings."
  - **Why unresolved:** VCBench defines success narrowly (likely an exit). The ceiling is a property of that specific label and the JSON schema used. It is an open question if the "weak signal" conclusion holds for alternative success metrics or richer, less anonymized data sources.
  - **What evidence would resolve it:** Replicating the full structured feature engineering and ceiling analysis pipeline on a different, publicly available founder dataset (e.g., a Crunchbase-derived cohort with different success labels) and reporting the achieved performance plateau.

## Limitations
- Feature definitions lack precise formulas (e.g., `comfort_index`, `industry_prestige_penalty`), risking replication divergence.
- The deterministic rule layer's integration (hard override vs. added feature) is unspecified, affecting performance attribution.
- Corpus support is weak: neighboring works do not address the specific lossy re-encoding mechanism, limiting external validation.

## Confidence
- **Structured JSON vs. prose signal:** High (LLM feature experiment showed zero CV gain at 100% coverage).
- **Prior exit deterministic rule:** High (standalone rule achieves Val F0.5=0.2889, 2.7× base-rate precision).
- **Information ceiling (~CV 0.25, Val 0.30):** Medium (convergence across models suggests a dataset limit, but no cross-dataset validation).

## Next Checks
1. **Feature distribution audit:** Compare summary statistics (means, success-rate ratios) of implemented features against paper benchmarks (e.g., exit founders' success rate 22.8–60%). Significant deviations indicate implementation errors.
2. **Rule layer isolation:** Measure validation F0.5 with the rule enforced (hard override) vs. disabled; expect ~0.2889 for rule-only, confirming correct integration.
3. **Ceiling stress test:** Train deeper XGBoost models or neural nets with extensive hyperparameter optimization and 10-fold CV. If performance does not exceed CV ~0.25, the information ceiling holds; if it does, investigate data leakage or overfitting.
