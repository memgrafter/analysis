# OpenNovelty: An LLM-powered Agentic System for Verifiable Scholarly Novelty Assessment

## Quick Facts
*   **arXiv ID:** 2601.01576
*   **Source URL:** https://arxiv.org/abs/2601.01576
*   **Reference Count:** 40
*   **Primary Result:** Solves scalable novelty verification in peer review by using an LLM-powered agent that grounds all judgments in retrieved real papers, ensuring transparent, verifiable assessments without hallucinations.

## Executive Summary
OpenNovelty is an agentic system designed to automate and improve the scholarly peer review process by performing verifiable novelty assessments. It addresses the scalability and consistency challenges of manual review by extracting a submission's core contributions, retrieving relevant prior work, and conducting contribution-level comparisons where every judgment is explicitly tied to evidence from real papers. Deployed on over 500 ICLR 2026 submissions, the system successfully identifies relevant prior work, including papers authors may have missed, and produces public reports that allow reviewers to audit its reasoning.

## Method Summary
The system implements a four-phase pipeline. **Phase I** extracts a paper's core task and contributions, generating semantic search queries. **Phase II** uses the Wispaper search engine to retrieve candidate prior work, applying multi-layer filtering (quality, deduplication, temporal constraints) to yield a final set of 60-80 papers. **Phase III** builds a hierarchical taxonomy of related work, performs textual similarity checks, and executes LLM-driven, contribution-level comparisons with a mandatory evidence verification step that requires verbatim quote alignment. **Phase IV** renders the structured analysis into a standardized Markdown/PDF report. A core design principle is that all novelty judgments must be grounded in retrieved full-text evidence, with unverified refutations automatically downgraded.

## Key Results
*   Successfully identifies relevant prior work, including closely related papers authors may have missed.
*   Ensures transparent and verifiable novelty assessments by grounding all judgments in retrieved real papers.
*   Eliminates hallucinations by enforcing a hard evidence verification constraint on every `can_refute` judgment.

## Why This Works (Mechanism)

### Mechanism 1: Verifiable Grounding
**Claim:** OpenNovelty ensures novelty judgments are verifiable by grounding all assessments in retrieved real papers rather than LLM parametric knowledge. The system extracts contributions, generates semantic queries, retrieves candidates, and performs full-text comparisons where each judgment must cite explicit verbatim evidence.  
**Core Assumption:** Sufficiently relevant prior work can be retrieved through semantic search, and full-text comparison can determine novelty refutability at the contribution level.  
**Evidence Anchors:** Neighbor FMR scores (0.443–0.594) indicate semantically relevant retrievals; the pipeline explicitly links judgments to retrieved full texts (Section 2.2, 2.3.3).  
**Break Condition:** Critical prior work absent from the search index (e.g., very recent preprints) or filtered out by aggressive quality thresholds may lead to false `cannot_refute` judgments.

### Mechanism 2: Hierarchical Taxonomy Construction
**Claim:** LLM-driven hierarchical taxonomy construction organizes retrieved work into structured context that reveals the target paper's research positioning. Given Top-50 core task papers, the LLM builds a MECE-constrained hierarchy to cluster papers by methodological or thematic similarity.  
**Core Assumption:** LLMs can generate coherent, mutually exclusive category hierarchies from paper metadata that meaningfully represent the research field's structure.  
**Evidence Anchors:** System description of taxonomy construction with MECE validation and automatic repair (Section 2.3.1).  
**Break Condition:** Taxonomy may be unstable across LLM runs, create overlapping categories, or misclassify papers; invalid taxonomies are flagged `needs_review` but still proceed, risking misleading distinctions.

### Mechanism 3: Evidence Verification as Hard Constraint
**Claim:** Evidence verification prevents hallucinated or unsupported refutation claims by requiring verbatim quotes and token-level validation. For every `can_refute` judgment, the system extracts quotes, verifies them against source texts via a token-level anchor alignment algorithm (confidence > 0.6), and automatically downgrades unverified refutations to `cannot_refute`.  
**Core Assumption:** LLM-extracted quotes can be reliably matched to source texts using fuzzy string alignment, and precise quote verification is necessary for trustworthiness.  
**Evidence Anchors:** Abstract guarantees "grounded in evidence"; algorithm details in Appendix C.4; downgrade policy in Section 2.3.3.  
**Break Condition:** Noisy PDF text extraction (e.g., formulas) or LLM paraphrasing can cause verification failure, losing valid refutations; the algorithm may miss matches with high semantic similarity but low lexical overlap.

## Foundational Learning
*   **Concept:** Retrieval-Augmented Generation (RAG)  
    *Why needed:* Verifiability hinges on retrieving real papers instead of relying on LLM memory; this explains the system's emphasis on semantic search and full-text comparison.  
    *Quick check:* "In the context of novelty assessment, what is the key advantage of using retrieved papers over the LLM's internal knowledge?"

*   **Concept:** Contribution-Level Granularity  
    *Why needed:* Decomposing a paper into discrete contributions enables precise, claim-specific verification rather than holistic similarity scoring, which is more actionable for reviewers.  
    *Quick check:* "Why does OpenNovelty extract contributions instead of comparing entire papers end-to-end?"

*   **Concept:** Evidence Verification as Hard Constraint  
    *Why needed:* Prevents the system from making unsupported refutation claims, which would undermine trust; the trade-off is lower recall for refutations to maintain high precision.  
    *Quick check:* "What happens to a `can_refute` judgment if the supporting quotes cannot be verified against the source texts?"

## Architecture Onboarding
**Component map:** Phase I (Extraction) -> Phase II (Retrieval) -> Phase III (Analysis) -> Phase IV (Rendering). Phase I outputs queries; Phase II produces candidate sets; Phase III performs taxonomy, comparison, and verification; Phase IV assembles the final report. Each phase depends on the previous phase's structured output.

**Critical path:** Core task and contribution extraction -> Semantic retrieval and filtering -> Hierarchical taxonomy construction -> Contribution-level full-text comparison with evidence verification -> Overall novelty assessment -> Report rendering.

**Design tradeoffs:**
*   Broad recall in retrieval increases recall but costs more API calls and processing time.
*   Zero-shot extraction avoids few-shot bias but may miss nuances in unconventional paper structures.
*   Contribution-level comparisons isolates claims for precision but overlooks cross-contribution interactions and requires many pairwise LLM calls.
*   Hard evidence verification ensures verifiability but increases false negatives when extraction or text alignment fails.

**Failure signatures:**
*   Phase I: Empty contribution list, overly specific queries (e.g., containing model names), or date inference failures.
*   Phase II: Quality-flag filtering removes >90% of candidates; cross-scope deduplication drops needed papers due to ID mismatches.
*   Phase III: Taxonomy validation fails (missing papers, duplicate assignments) even after repair; high proportion of unverified evidence in `can_refute` judgments; extremely long processing time due to large candidate sets.
*   Phase IV: Missing citations, malformed JSON from Phase III, or template errors causing layout issues.

**First 3 experiments:**
1.  **Single-paper trace:** Run one submission with detailed logging to inspect Phase I extraction outputs, Phase II candidate counts per filter, and Phase III comparison statistics.
2.  **Taxonomy stability test:** Run the same target paper through Phase III multiple times with identical settings and compare taxonomy structures (node names, assignments) to quantify LLM stochasticity.
3.  **Evidence verification ablation:** Disable the verification step and compare the number of `can_refute` judgments before vs. after downgrade to measure the constraint's impact on precision/recall.

## Open Questions the Paper Calls Out
*   **How does varying input scope (abstract-only vs full text) affect the quality and completeness of core task and contribution extraction?** The hypothesis that abstracts suffice for core tasks while contributions need broader context is untested. An ablation study across input granularities is needed.
*   **How do different academic search engines compare in retrieving relevant prior work for novelty assessment?** No comparative evaluation exists; recall, MRR, and coverage of reviewer-cited papers across Semantic Scholar, Google Scholar, OpenAlex, and Wispaper are unknown.
*   **What is the most effective approach for constructing hierarchical taxonomies of related work?** Pure LLM, embedding-based clustering, or hybrid methods have not been compared; trade-offs between automation, stability, and human-aligned coherence are unclear.
*   **How can mathematical formulas and symbolic expressions be reliably analyzed?** Current text extraction fails for equations, symbols, and matrices, preventing assessment of claims hinging on mathematical innovations. LaTeX-aware parsing and semantic formula matching are required.
*   **To what extent does systemic bias toward well-indexed venues and English-language publications affect fairness?** Traceability reveals bias but does not correct it; the magnitude of bias and effective mitigation strategies (e.g., diversified retrieval, multilingual models) remain unquantified.

## Limitations
*   Wispaper search index coverage, API behavior, and quality flag definitions are opaque, making exact reproduction of retrieval results difficult.
*   Exact LLM (claude-sonnet-4-5-20250929) tokenization, stochasticity, and prompt formatting details are undisclosed, causing potential output variance.
*   Evidence verification thresholds (e.g., 300-token gap) lack empirical justification and may affect precision/recall trade-offs.

## Confidence
*   **Mechanism 1 (Verifiable grounding):** High. Neighbor FMR scores and pipeline design strongly support that retrieved papers provide relevant context for grounding.
*   **Mechanism 2 (Taxonomy construction):** Medium. LLM-driven MECE taxonomy lacks direct corpus validation; stability and accuracy are unmeasured.
*   **Mechanism 3 (Evidence verification):** Medium. Algorithm is specified but not empirically evaluated; no precision/recall metrics for quote matching are reported.

## Next Checks
1.  **Retrieval coverage benchmark:** Run OpenNovelty on a paper subset with a gold-standard prior-work set (e.g., from NoveltyBench) to measure recall of known relevant papers and identify index gaps.
2.  **Taxonomy stability test:** Generate taxonomies for 50 papers with 5 repeats each; compute variation in node structure/assignments to quantify LLM-induced inconsistency.
3.  **Evidence verification audit:** Sample 200 `can_refute` cases pre- and post-verification; have human reviewers judge if downgraded cases were actually valid refutations, estimating precision loss from the hard constraint.
