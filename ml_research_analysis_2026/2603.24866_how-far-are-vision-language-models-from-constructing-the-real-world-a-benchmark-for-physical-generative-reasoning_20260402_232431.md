# How Far Are Vision-Language Models from Constructing the Real World? A Benchmark for Physical Generative Reasoning
## Quick Facts
- arXiv ID: 2603.24866
- Source URL: https://arxiv.org/abs/2603.24866
- Reference count: 40
- Primary result: Structural validity and visual fidelity are orthogonal; best joint pass rate only 7.1% on DreamHouse.

## Executive Summary
Vision-language models (VLMs) are increasingly capable of generating images or code from textual and visual inputs, but evaluating their ability to perform *physical generative reasoning*—creating structures that satisfy geometric, structural, and code constraints—remains an open challenge. This paper introduces DreamHouse, a benchmark of over 26,000 timber-frame constructions, each represented by five orthographic renders and metadata. The benchmark employs a deterministic 10-test validator based on the International Residential Code (IRC) and an agentic evaluation loop where the VLM iteratively refines Blender Python code. Key findings reveal that structural validity and visual fidelity are largely independent; the highest joint pass rate (both criteria met) is only 7.1%. Performance is heavily influenced by the evaluation protocol, with Gemini’s structural pass rate varying by 33 points between Planner-Atomic and Planner-Managed, underscoring that scaffold design can outweigh model choice. Moreover, frontier models (Claude, Gemini) show some capability, while open-source VLMs (Qwen, Kimi) fail entirely. DreamHouse thus highlights a significant gap in VLM physical reasoning and provides a rigorous, open framework for future progress.

## Method Summary
The task requires a VLM to generate executable Blender Python code that reconstructs a target timber-frame structure from multi-view renders while satisfying ten deterministic structural tests. The dataset comprises 26,543 structurally verified designs across 13 architectural styles at LOD 350, each described by front, back, left, right, and front-right diagonal images plus metadata (lot size, stories, roof type, complexity). Evaluation follows an agentic loop: the VLM receives the renders and prior validation feedback, then outputs a JSON plan and Blender code. The Executor runs this code in a headless Blender 4.5.4 session to produce a scene graph; the Validator checks the graph against the 10 IRC-based tests (e.g., load path connectivity, span limits, deflection, cantilever limits). Three protocols differ in scaffolding: Planner-Atomic (single-shot generation), Planner-Reactive (model-driven phased refinement with rollback), and Planner-Managed (external controller enforces phase completion). The loop repeats up to a global retry budget until all tests pass or the budget exhausts. Primary metrics are Structural Pass Rate (all tests passed), Visual Fidelity (alpha-weighted MSE between rendered and target views), and Joint Pass Rate (structural pass with S≥0.6).

## Key Results
- Structural validity and visual fidelity are orthogonal; the best observed joint pass rate is a mere 7.1%.
- Scaffold design decisively influences performance; Gemini’s structural pass rate differs by 33 points between Planner-Atomic and Planner-Managed, indicating that protocol choice can matter more than model selection.
- Open-source VLMs (Qwen, Kimi) achieve zero structural validity, while frontier models (Claude, Gemini) attain non-zero scores, pointing to a frontier-only capability gap.

## Why This Works (Mechanism)
DreamHouse provides a rigorous testbed for physical generative reasoning by coupling visual reconstruction with explicit, deterministic engineering constraints. The use of IRC-based tests ensures that generated structures must satisfy real-world building codes, not just look plausible. The iterative feedback loop allows the VLM to refine its code based on concrete failure signals, mimicking a design-verify-redo cycle. The orthogonality of structural and visual metrics exposes a fundamental limitation: VLMs can produce visually accurate outputs that ignore physics, or structurally sound ones that diverge visually. This separation validates the benchmark’s design—by demanding both, it forces models to integrate visual understanding with physical priors, something current systems lack. The protocol-dependence results further show that the way the task is scaffolded (e.g., phased construction) can unlock latent reasoning abilities, suggesting that future improvements may come from both model architecture and interaction design.

## Foundational Learning
- **Physical generative reasoning**: The ability to generate designs that satisfy both visual and physical constraints. *Why needed*: It is the core capability under evaluation. *Quick check*: Given a beam length and load, can you determine if it meets deflection limits?  
- **Timber-frame construction**: A traditional building method using wooden members (posts, beams, joists) connected via joinery. *Why needed*: Defines the domain and constraint vocabulary (e.g., spans, connections). *Quick check*: Identify the primary load-bearing members in a simple gable roof.  
- **International Residential Code (IRC)**: U.S. building standards governing structural safety (span tables, deflection ratios, connection requirements). *Why needed*: Source of the validator’s ten tests. *Quick check*: What is the maximum allowed joist span for a given lumber size and spacing?  
- **Blender Python API**: Scripting interface to programmatically create 3D meshes, assign materials, and define object hierarchies. *Why needed*: The VLM’s output must be executable in Blender. *Quick check*: Write a minimal script to place a cube at (0,0,0).  
- **Agentic evaluation loop**: A process where the model interacts with an environment, receives feedback, and iteratively improves. *Why needed*: Central to the benchmark’s methodology. *Quick check*: Describe how feedback from the validator is used in the next iteration.  
- **Orthogonality of metrics**: The finding that structural pass rate and visual fidelity are uncorrelated. *Why needed*: A key insight about current VLM limitations. *Quick check*: Can a structure look identical to the target yet fail a load-path test?  

## Architecture Onboarding
- **Component map**:  
  Multi-view renders + metadata -> VLM -> JSON plan + Blender code -> Blender Executor -> Scene graph -> Validator -> Test results -> (feedback) -> VLM.  
  Controller layer (for Planner-Managed) inserts phase gates; Planner-Reactive embeds phase logic inside VLM; Planner-Atomic has no explicit phases.  
- **Critical path**: The end-to-end flow from input images to final validation outcome. The primary bottleneck is the VLM’s reasoning and code generation; Blender execution and validation are fast but must be sandboxed.  
- **Design tradeoffs**: Deterministic validator ensures reproducibility but may miss subtle real-world physics. Iterative refinement improves success rates at the cost of increased inference budget. Protocol scaffolding (especially Planner-Managed) yields better structural validity but adds complexity and may not generalize across models.  
- **Failure signatures**:  
  *Syntax/API errors*: Blender console shows tracebacks → invalid code.  
  *Coordinate confusion*: Rendered output is rotated or mirrored relative to target → wrong view mapping.  
  *Dimensional violations*: High visual fidelity but fails Span Limits (T2) or Deflection (T5) → inaccurate member sizes/spacing.  
  *Topological errors*: Load Path (T1) failure → missing connections or wrong construction order.  
  *Phase mismatches*: In Planner-Managed, adding roof members before walls complete → dependency violation.  
- **First experiments**:  
  1. Baseline run: Execute Planner-Atomic on 10 random structures; record initial structural and visual pass rates; inspect failure logs for common error patterns.  
  2. Scaffold sensitivity: Keep model fixed (e.g., Claude) and compare all three protocols on the same 10 structures; quantify improvement and retry budget usage.  
  3. Error correlation: For Planner-Atomic results, plot per-sample structural pass vs. visual fidelity; test statistical independence to confirm orthogonality.

## Open Questions the Paper Calls Out
1. **How can DreamHouse be extended to other construction materials (e.g., concrete, steel) and multi-material assemblies?**  
   *Basis*: The paper explicitly suggests future work to expand the physical constraint vocabulary. It remains unknown whether VLMs can generalize to different material properties, connection types, and engineering standards. *What evidence would resolve*: Build a dataset and validator for at least one additional material (e.g., concrete framing), then evaluate frontier VLMs to measure transferability and uncover new failure modes.  

2. **What input representations or pretraining objectives enable VLMs to internalize structural grammar and reduce reliance on iterative feedback?**  
   *Basis*: The paper notes the importance of exploring the input end to identify representations or objectives that let models proactively internalize structural grammar. Current models appear to lack inherent physical priors, requiring expensive retries. *What evidence would resolve*: Compare different pretraining regimes (e.g., synthetic structural data, physics-based augmentations) on a held-out DreamHouse subset, measuring sample efficiency and one-shot structural pass rates.  

3. **How does scaffold design (phase granularity, feedback timing) impact success, and what scaffold optimizes performance across models?**  
   *Basis*: The paper shows protocol choice changes rankings and pass rates by up to 33 points (e.g., Gemini), suggesting scaffold design is critical. No systematic study of scaffold parameters is provided. *What evidence would resolve*: Conduct a grid search over scaffold configurations (number of phases, feedback detail, retry limits) on a subset of models and tasks; analyze which factors correlate with higher pass rates and whether interactions exist.  

4. **Why do visual fidelity and structural validity remain orthogonal, and how can architectures be modified to improve joint pass rates above the current 7.1% ceiling?**  
   *Basis*: The paper demonstrates low joint pass rates and notes that models often satisfy one criterion at the other's expense, with topological fidelity not predicting structural validity. The underlying cause is unclear. *What evidence would resolve*: Perform error analysis correlating failure modes with model internals (attention, representations) on passed vs. failed structures; test whether joint training objectives (e.g., multi-task loss combining structural validation and visual similarity) can lift joint pass rates without harming individual metrics.

## Limitations
- **Reproducibility gaps**: Full system prompts for Planner-Reactive and Planner-Managed are omitted; dataset download/loader scripts and exact model versions/hyperparameters are not provided, hindering independent verification.
- **Scope constraints**: The benchmark is limited to timber-frame construction (single material, fixed architectural styles), so generalizability to other materials or construction methods is unknown.
- **Evaluation orthogonality**: While structural and visual metrics are shown to be dissociated, the root cause (e.g., spatial reasoning vs. code generation) is not dissected; the validator, though deterministic, may not capture all real-world physics nuances.

## Confidence
- Benchmark design & validator: High
- Joint pass rate (7.1%): Medium
- Protocol dependence > model choice: Medium
- Frontier-only capability: High (for the tested models Qwen/Kimi)
- Generalization to all open VLMs: Low (only a few open models were evaluated)

## Next Checks
1. **Prompt replication study**: Obtain/release the complete system prompts for all three protocols, then run identical queries on a fixed 100-structure subset to confirm the reported protocol-performance gaps (especially Gemini’s 33-point swing).
2. **Open-model expansion**: Evaluate current open-source VLMs (LLaVA-1.6, BLIP-3, InternVL2) under the Planner-Managed protocol to test the claim that only frontier models can achieve structural validity.
3. **Failure mode ablation**: For Planner-Atomic runs, log per-test failure rates and correlate with visual fidelity scores. Perform error analysis to determine whether orthogonality stems from dimensional reasoning, topological errors, or phase-order mistakes.
