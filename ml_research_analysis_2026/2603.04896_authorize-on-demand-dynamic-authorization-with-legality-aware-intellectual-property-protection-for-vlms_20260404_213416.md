# Authorize-on-Demand: Dynamic Authorization with Legality-Aware Intellectual Property Protection for VLMs
## Quick Facts
*   **arXiv ID:** 2603.04896
*   **Source URL:** https://arxiv.org/abs/2603.04896
*   **Reference Count:** 40
*   **Primary Result:** AoD-IP enables dynamic, user-controlled domain authorization for VLMs, maintaining high authorized accuracy (e.g., 0.13% drop on Office-Home-65) while reliably suppressing unauthorized domains (e.g., 74.57% drop) and achieving high legality discrimination (81.9%-100%).

## Executive Summary
Vision-language models (VLMs) face significant intellectual property (IP) protection challenges due to their static, training-time domain isolation. This paper introduces Authorize-on-Demand IP (AoD-IP), a framework that decouples domain identity from model weights via credential tokens. These tokens allow on-demand, user-controlled switching between authorized domains without retraining. AoD-IP employs a lightweight dynamic authorization module and a dual-path inference mechanism that jointly outputs task predictions and an explicit legality signal. By simulating extended domains through style perturbations during training, the model enforces robust boundaries against unseen unauthorized usage. Evaluated on standard domain adaptation benchmarks, AoD-IP achieves a superior trade-off between preserving performance on authorized domains and suppressing accuracy on unauthorized ones, offering a practical solution for dynamic deployment environments.

## Method Summary
AoD-IP builds upon a frozen CLIP backbone (visual encoder `E_v`, text encoder `E_t`). It introduces three lightweight, trainable projectors: `P_img` maps multi-scale visual features to image-content tokens (`τ_g`); `P_dom` maps them to domain-identity tokens (`τ_d`); and `P_enc` (used only on authorized data during training) maps deep features to a unique credential token (`τ_c^a`). During inference for an authorized domain, the input image produces `τ_g` and `τ_d`, while the user-provided `τ_c^a` is prepended to form a prompt `T_a = [τ_c^a, τ_g^a, τ_d^a]` for `E_t`. A dual-path output head computes cosine similarities between the image feature and textual feature for each class prompt (including a dedicated "unauthorized" class), producing an `N+1`-dimensional prediction vector. The legality signal `r_i` is a binary flag derived from the argmax of this vector. Training uses a composite loss that maintains accuracy on authorized data (`L_ce^a`), explicitly forces authorized samples toward the "unauthorized" class with a small weight (`λ₁·L_ce^{a→u}`), forces extended and unauthorized samples into the "unauthorized" class (`L_ce^e`, `L_ce^u`), and uses KL divergence (`L_kl`) between textual features of authorized and extended domains to enhance separability. Extended domains are synthesised from authorized data via `RandAugment` style perturbations.

## Key Results
*   AoD-IP maintains near-perfect authorized performance, with minimal accuracy drops (e.g., 0.13% on Office-Home-65, 0.32% on Office-31) compared to the standard CLIP baseline.
*   It reliably suppresses unauthorized domain performance, achieving large drops (e.g., 74.57% on Office-Home-65, 62.72% on Mini-DomainNet) and significantly outperforming prior static IP protection methods in weighted drop difference (W_u-a) and accuracy cross drop (D_u-a).
*   The legality-aware output achieves high discrimination accuracy: 100% on Office-31, 81.9% on Office-Home-65, and 89.9% on Mini-DomainNet, reliably flagging unauthorized inputs.

## Why This Works (Mechanism)
### Mechanism 1
*   **Claim:** User-controlled, post-training domain authorization is enabled by a credential token that acts as a domain-specific key, decoupling domain identity from model weights.
*   **Mechanism:** A lightweight, trainable `encryption projector (P_enc)` generates a unique `credential token (τ_c^a)` from deep visual features of the authorized domain (`f_v^a`). During inference, this token must be concatenated with domain-specific image and domain tokens (`τ_g^a`, `τ_d^a`) to form a valid prompt (`T_a`) for the frozen text encoder (`E_t`). A mismatch between the credential token and input domain tokens results in an invalid prompt, leading to an "unauthorized" legality signal.
*   **Evidence anchors:**
    *   [abstract]: "...introduces a lightweight dynamic authorization module that uses credential tokens as domain keys, allowing on-demand domain switching without retraining..."
    *   [section 3.4]: "The encryption projector `P_enc` receives the deep feature representation `f_v^a` from the authorized domain and outputs its unique credential token `τ_c^a`, which serves as a domain key to activate the corresponding authorized domain."
    *   [section 3.4, inference]: "Each inference input consists of a data sample and its credential token. If the credential matches the data, the model outputs both the task prediction and the legality-aware output; otherwise, the result is flagged as 'unauthorized.'"
*   **Break condition:** If an adversary can successfully generate or steal a valid `τ_c^a` for an unauthorized domain (e.g., via feature inversion or model extraction attacks on `P_enc`), the authorization barrier fails.

### Mechanism 2
*   **Claim:** A dual-path inference mechanism jointly produces a task prediction and a legality-aware signal, enabling the model to self-identify whether an input is from an authorized context.
*   **Mechanism:** For any input, the model computes a similarity-based prediction vector `p_i` with `N+1` entries (N task classes + 1 "unauthorized" class). The legality-aware output `r_i` is a binary flag: `r_i=0` if `argmax(p_i) = C_unauth`, else `r_i=1`. The training loss explicitly guides samples from authorized, extended, and unauthorized domains toward their respective correct "authorized" or "unauthorized" classification.
*   **Evidence anchors:**
    *   [abstract]: "...incorporates a dual-path inference mechanism that jointly outputs task predictions and a legality signal."
    *   [section 3.5]: "AoD-IP adopts a dual-path output mechanism that jointly produces task predictions and legality-aware output... The legality-aware output `r_i` is then defined as..."
    *   [section 3.6, training loss]: Loss terms `L_u^ce` and `L_e^ce` "guide the model to classify samples into the 'unauthorized' category," while `L_a^ce` ensures accuracy on authorized data.
*   **Break condition:** If feature spaces of authorized and unauthorized domains overlap significantly (e.g., due to insufficient extended-domain diversity), the model may misclassify unauthorized inputs as authorized (`r_i=1`), causing false negatives.

### Mechanism 3
*   **Claim:** Robust authorization boundaries are enforced by simulating a diverse set of "extended domains" via style perturbations, which proactively model potential future, unseen unauthorized domains during training.
*   **Mechanism:** Extended domain data (`x_e`) is created by applying random style perturbations (e.g., from `RandAugment`) to authorized domain data (`x_a`). The model is trained to correctly classify `x_e` as a valid "extended-authorized" domain (with its own tokens) while simultaneously being forced to distinguish `x_e` features from `x_u` (unauthorized) features, enforced by `L_kl` between `f_t^a` and `f_t^e`.
*   **Evidence anchors:**
    *   [section 3.3]: "In practice, `x_e` is generated by applying random style perturbations [10] to the authorized domain, enriching domain diversity without introducing external data... This approach enforces a robust authorization boundary using only existing data."
    *   [section 3.6, loss]: `L_kl = KL(f_t^a ∥ f_t^e)` is used to "enhance inter-domain feature separability and prevent feature overlap between the authorized and extended domains."
    *   [Tables 1-3, `X_e` columns]: The model maintains high accuracy on `X_e` (e.g., >90% on Office-Home-65) while suppressing `X_u`.
*   **Break condition:** If real-world unauthorized domains are not well-approximated by style perturbations (e.g., involve semantic shifts or new sensor modalities), the model's boundary may fail.

## Foundational Learning
*   **Concept: Contrastive Vision-Language Pre-training (e.g., CLIP)**
    *   **Why needed here:** AoD-IP is built on a frozen CLIP backbone. Its dual-encoder (image `E_v`, text `E_t`) structure and shared embedding space are fundamental. The projectors manipulate visual features into tokens that are fed as prepended textual prompts. The legality decision hinges on similarity scores in this pre-aligned space.
    *   **Quick check:** How does standard CLIP inference (image-to-text classification) differ from AoD-IP's token-augmented prompt engineering for the text encoder?
*   **Concept: Domain Adaptation / Domain Generalization**
    *   **Why needed here:** The core problem is domain-specific IP protection. The model must learn representations that are invariant for the task within the authorized domain but variant across domains to block transfer. Concepts like domain discrepancy, feature alignment/separation, and style/content shifts are directly relevant, especially in the design of extended domains via style perturbation.
    *   **Quick check:** Why is minimizing KL divergence between `f_t^a` and `f_t^e` (`L_kl`) a reasonable way to encourage separation from `f_t^u`, given that `x_e` is a perturbed version of `x_a`?
*   **Concept: Parameter-Efficient Fine-Tuning (PEFT) for VLMs**
    *   **Why needed here:** AoD-IP adds only lightweight projectors (`P_img`, `P_dom`, `P_enc`) while freezing the massive CLIP backbone. This PEFT paradigm is key to the design's practicality and efficiency for deployment.
    *   **Quick check:** What is the risk of fine-tuning only small, added modules (like the projectors) compared to full fine-tuning in the context of IP protection, and how does AoD-IP mitigate it?

## Architecture Onboarding
*   **Component map:**
    Frozen CLIP Backbone (`E_v`, `E_t`) -> `P_img` (-> `τ_g`) & `P_dom` (-> `τ_d`) & `P_enc` (-> `τ_c`) -> Token Composition (`[τ_c, τ_g, τ_d]`) -> Text Encoder (`E_t`) -> Dual-Path Output Head (`p_i`, `r_i`)
*   **Critical path (Authorized Inference):**
    1.  User provides image `x_a` and credential token `τ_c^a`.
    2.  `x_a` -> `E_v` -> `f_v^a`.
    3.  `f_v^a` -> `P_img` -> `τ_g^a`; `f_v^a` -> `P_dom` -> `τ_d^a`.
    4.  Construct prompt `T_a = [τ_c^a, τ_g^a, τ_d^a]`.
    5.  `T_a` -> `E_t` -> `f_t^a`.
    6.  `cos_sim(f_v^a, f_t^a)` -> prediction vector `p_a`.
    7.  `argmax(p_a) != C_unauth`? -> `r_a = 1` (Legal) : `r_a = 0` (Illegal). Output `(p_a, r_a)`.
*   **Design tradeoffs:**
    *   **Flexibility vs. Security:** Credential tokens enable dynamic switching but create a new attack surface (token theft/copying). Security now depends on secret parameter management.
    *   **Performance vs. Protection:** The `N+1`-class output and `L_kl` loss trade off pure task accuracy for stronger unauthorized suppression. Hyperparameter `λ₁` balances preventing false "unauthorized" flags.
    *   **Generality vs. Simulation:** Using style perturbations to simulate all future unauthorized domains is computationally cheap but may not cover semantic or sensor-level shifts.
*   **Failure signatures:**
    1.  **High `A_u` with high confidence:** Unauthorized samples achieve high accuracy on main task classes and `r_i=1`, indicating feature space leakage.
    2.  **Low `R_a`:** Authorized samples frequently trigger `r_i=0`, indicating `P_enc` incompatibility or excessive `λ₁`.
    3.  **Failure to switch:** A valid `τ_c^a` for a novel extended domain yields low task accuracy or `r_i=0`, indicating an overly narrow boundary.
*   **First 3 experiments:**
    1.  **Token Switch Validation:** After training, obtain new `τ_c^a` from owner. Feed `X_e` data with `τ_c^a`. Verify (a) high task accuracy, (b) `r=1` for most samples. Confirms dynamic authorization for a simulated extended domain.
    2.  **Legality Discrimination Under Attack:** For an `X_u` sample, construct invalid prompt `T_u_wrong = [τ_c^a, τ_g^u, τ_d^u]`. Verify (a) `argmax(p_u)` is often `C_unauth`, (b) `r_u=0`. Also test "token missing" case.
    3.  **Boundary Stress Test with Novel Perturbations:** Apply a *different* set of style augmentations to `X_a` (not used in `x_e` generation). Feed with `τ_c^a`. Goal: `r=1` with good accuracy. Failure indicates insufficient robustness in extended-domain simulation.

## Open Questions the Paper Calls Out
*   **Question:** Does AoD-IP generalize to tasks beyond image classification, such as VQA and image generation?
*   **Basis:** [explicit] The conclusion states future work will extend AoD-IP to broader tasks (e.g., VQA and image generation).
*   **Why unresolved:** The framework's components are designed for classification and may need adaptation.
*   **Resolution evidence:** Implement AoD-IP for VQA and image generation, measure IP protection effectiveness on relevant datasets.
*   **Question:** How faithful is the use of style perturbations to model real-world domain shifts compared to actual distinct domains?
*   **Basis:** [inferred] Section 3.3 creates extended domains by "applying random style perturbations to the authorized domain" without external data.
*   **Why unresolved:** It is unclear whether perturbed samples represent diverse unseen domains or are easier/harder variants, affecting boundary robustness.
*   **Resolution evidence:** Compare AoD-IP performance when extended domains are (a) style-perturbed authorized data and (b) naturally different domains (e.g., from other datasets), analyzing Drop_u, Drop_a, and legality discrimination.
*   **Question:** How vulnerable is the legality-aware output to adversarial attacks that aim to produce false authorized predictions on unauthorized inputs?
*   **Basis:** [inferred] The dual-path inference produces a legality signal, but the paper does not evaluate adversarial robustness.
*   **Why unresolved:** Adversarial examples could cross the authorization boundary, leading to undetected unauthorized usage.
*   **Resolution evidence:** Generate adversarial samples from unauthorized domains using standard attacks (e.g., PGD) and measure the rate of misclassification as authorized with high task accuracy.

## Limitations
*   **Security of `P_enc` token generation:** The assumption that the mapping from `f_v^a` to `τ_c^a` is non-invertible and tokens cannot be derived for unauthorized domains is not formally proven; resilience to inversion or extraction attacks is unknown.
*   **Coverage of "extended domains":** The reliance on style-space perturbations to simulate all possible future unauthorized domains is a strong inductive bias. Real-world covariate shifts (e.g., sensor changes, semantic drifts) may fall outside this simulated buffer, leading to protection failure.
*   **Deployment practicality & token management:** The framework requires owners to securely generate, distribute, and manage credential tokens (`τ_c^a`) per authorized domain. Issues like token revocation, rotation, and scalability to many clients are unaddressed.

## Confidence
*   **Dynamic authorization via credential tokens (Mechanism 1):** High. The architectural description is clear and internally consistent; the break condition (token theft) is explicitly identified.
*   **Dual-path legality detection (Mechanism 2):** High. The output design and associated loss functions are well-specified. The break condition (feature overlap) is logically sound.
*   **Extended-domain simulation for robust boundaries (Mechanism 3):** Medium. The use of style perturbations is described and results on `X_e` support efficacy. However, the core assumption—that style augmentations adequately proxy unknown future domains—is not validated against non-style shifts (e.g., new object categories, different imaging modalities).

## Next Checks
1.  **Token Replication Attack Test:** Attempt to generate a valid `τ_c^a` for an unauthorized domain `D_u` by (a) querying `P_enc` with `D_u` samples, and (b) using optimization-based inversion to find an input `x'` such that `P_enc(f_v(x')) ≈ τ_c^a`. Success would break Mechanism 1.
2.  **Perturbation Gap Analysis:** Evaluate AoD-IP on *non-style* shifted unauthorized domains (e.g., semantic shifts like new classes, cross-sensor data, or geometric corruptions beyond rotation/shear). Compare `A_u` suppression against the style-perturbed `X_e` baseline to test the generality of Mechanism 3's simulation.
3.  **Zero-Day Domain Deployment:** After training on `(X_a, X_e, X_u)`, deploy the model to a *completely unseen* real-world domain `D_new` (not in training). Provide the correct `τ_c^a`. Measure: (a) task accuracy on `D_new`, (b) legality flag `r_i`. Failure (low accuracy or `r=0`) would indicate the authorization boundary is too narrow.
