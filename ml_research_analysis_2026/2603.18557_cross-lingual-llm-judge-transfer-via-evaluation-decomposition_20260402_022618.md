# Cross-Lingual LLM-Judge Transfer via Evaluation Decomposition

## Quick Facts
*   **arXiv ID:** 2603.18557
*   **Source URL:** https://arxiv.org/abs/2603.18557
*   **Reference Count:** 40
*   **Primary Result:** A decomposition-based evaluation framework (UCS) trained only on English data achieves average balanced accuracy gains of 3.5-2.9 points over strong baselines across 12 non-English languages, with consistent performance in 11 of 12.

## Executive Summary
This paper addresses the scarcity of human annotations for evaluating large language models (LLMs) in non-English languages. It proposes decomposing the evaluation task into a set of universal, language-agnostic criteria (UCS). An LLM first answers these targeted questions to produce an intermediate representation. A lightweight transfer module, trained exclusively on English-labeled data, then maps this representation to a final judgment and can be applied zero-shot to other languages. Evaluated on two multilingual benchmarks (MEMERAG, mFACE) using the Qwen-235B model, the method achieves state-of-the-art or competitive performance across 11 of 12 languages, demonstrating significant data efficiency (performance stabilizes with only 20–30% of English training data) and robust cross-lingual transfer. The main outlier is Burmese, where a simple zero-shot baseline performs best, suggesting potential language-specific limitations.

## Method Summary
The approach, termed **Evaluation Decomposition**, operates in two phases. First, a **Universal Criteria Set (UCS)**—a list of targeted, yes/no questions—is generated from the task description (e.g., "Is this summary factually consistent?"). This set is intended to capture semantic evaluation dimensions common across languages. Second, for a given input-output pair in any language, the LLM is prompted to answer each UCS question. These answers form a binary criterion vector. A lightweight neural transfer module (a simple feed-forward network) is trained on English data to map this criterion vector to the final human-like judgment (e.g., accept/reject). Once trained, this module can be applied to criterion vectors from any language without further adaptation, enabling zero-shot cross-lingual transfer.

## Key Results
*   On MEMERAG, UCS (trained on English) achieves 81.6% average balanced accuracy vs. RocketEval's 78.1%.
*   On mFACE, UCS achieves 74.9% vs. the strongest zero-shot baseline's 72.0%.
*   UCS delivers best or tied-best performance in 11 of 12 evaluated languages, with gains holding across diverse language families (e.g., Germanic, Romance, Slavic, Arabic).
*   Performance stabilizes with only 20–30% of the available English training data, indicating high data efficiency.

## Why This Works (Mechanism)
The method works by **separating language-agnostic semantic assessment from language-specific judgment mapping**. The LLM acts as a multilingual scorer for the predefined criteria, producing an intermediate representation (`s(x)`) that abstracts away surface language form. The transfer module learns the relationship between this abstract representation and the final evaluation label using high-resource English data. The core assumption is that the criteria space (`UCS`) is stable and meaningful across languages, allowing the same `s(x)` vector to predict judgments in a new language. This bypasses the need for non-English training labels and reduces the LLM's role from end-to-end judgment (which can be culturally biased) to answering concrete, presumably objective sub-questions.

## Foundational Learning
*   **Evaluation Decomposition:** Breaking a complex judgment task into smaller, targeted sub-questions. *Why needed:* Reduces ambiguity and leverages LLMs' strength at answering specific queries over holistic evaluation. *Quick check:* Can the sub-questions be answered reliably by humans in the target language without full context?
*   **Cross-Lingual Transfer:** Applying a model trained on one language to others without retraining. *Why needed:* Solves the annotation scarcity problem for low-resource languages. *Quick check:* Does the intermediate representation (`s(x)`) correlate with quality similarly across languages?
*   **Universal Criteria Set (UCS):** A fixed set of questions meant to capture evaluation dimensions common to all languages. *Why needed:* Provides a shared, language-agnostic scaffold for the decomposition. *Quick check:* Are the generated criteria interpretable and relevant across a diverse typological sample?
*   **Lightweight Transfer Module:** A small neural network (e.g., MLP) trained to map criterion vectors to final labels. *Why needed:* Learns the final decision boundary using cheap English labels, avoiding costly LLM fine-tuning. *Quick check:* Is the mapping function sufficiently simple to avoid overfitting to English-specific patterns?
*   **Zero-Shot Generalization:** Applying the trained transfer module to new languages without any target-language training. *Why needed:* Enables evaluation for languages with no labeled data. *Quick check:* Does performance degrade gracefully with increasing linguistic distance from English?
*   **Balanced Accuracy:** Metric that accounts for class imbalance, crucial for benchmarks with skewed label distributions. *Why needed:* Prevents misleadingly high scores from majority-class baselines. *Quick check:* Is the drop in balanced accuracy from English to other languages smaller than for simple accuracy?

## Architecture Onboarding
**Component Map:**
Task Description → UCS Generator (LLM) → Fixed Universal Criteria Set (UCS) → For each sample: Input-Output Pair (any language) → Criteria Scorer (LLM) → Binary Criterion Vector `s(x)` → Transfer Module (Trained NN) → Final Judgment

**Critical Path:**
1.  **Offline (English Data):** Train Transfer Module `f_θ` to predict human label `y` from `s(x)`.
2.  **Online (Any Language):** For new sample, compute `s(x)` using fixed UCS, then apply `f_θ(s(x))` to get prediction.

**Design Tradeoffs:**
*   **Decomposition Granularity:** Finer-grained criteria (more questions) can capture nuances but increase cost and risk of noise. Coarser criteria are cheaper but may lose signal.
*   **UCS Generation:** Using an LLM to generate criteria from a task description is cheap and flexible but may produce questions that are not truly universal or optimal for transfer.
*   **Training Data Reliance:** Training `f_θ` only on English labels is efficient but risks encoding English-centric evaluation norms into the final mapping.

**Failure Signatures:**
*   **High `s(x)` variance for same-quality samples across languages:** Indicates UCS questions are not answered consistently, breaking the language-agnostic assumption.
*   **Poor performance on linguistically distant languages (except Burmese outlier):** Suggests UCS may not be fully universal or LLM scoring is script/tokenization-biased.
*   **Burmese zero-shot baseline > UCS:** Specific failure of the decomposition pipeline for Burmese, possibly due to script complexity, tokenization, or pretraining data gaps affecting either criteria scoring or transfer.

**First Three Experiments:**
1.  **Replication on Qwen-235B with MEMERAG/mFACE:** Strictly follow paper's training/validation splits for the transfer module and evaluate all baselines to confirm reported numbers.
2.  **Cross-Model Test:** Evaluate the same UCS (generated for the task) using a different model family (e.g., GPT-4, Llama-3-70B) as the Criteria Scorer to test model-independence of the decomposition advantage.
3.  **Component Ablation:** Ablate the transfer module (use `s(x)` directly via simple rule or English-trained linear probe) and ablate the UCS (use zero-shot CoT) to quantify the contribution of each component.

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** What explains the anomalous performance of the zero-shot baseline on Burmese (MY), where it significantly outperforms the proposed UCS framework and all other baselines?
*   **Basis in paper:** [explicit] The paper explicitly notes in Section 5.1 that "One notable exception is observed on Burmese (MY), where the zero-shot baseline achieves the highest performance... This suggests that Burmese may exhibit language-specific properties, such as script complexity or limited LLM pretraining coverage, that are not well captured by the shared criteria space."
*   **Why unresolved:** The specific linguistic or pretraining-related factor(s) causing the criteria-based decomposition to fail for Burmese are not identified. Understanding this is critical for assessing the generalizability of the language-agnostic criteria assumption.
*   **What evidence would resolve it:** A detailed analysis comparing the LLM's internal representations (e.g., attention patterns, hidden states) when processing Burmese versus other languages in both zero-shot and criteria-evaluation modes. Error analysis of criterion-level responses for Burmese samples to see which questions are most problematic. Investigation of the Burmese script's tokenization efficiency and frequency in the pretraining corpus.

### Open Question 2
*   **Question:** To what extent are the learned "language-agnostic" evaluation criteria actually stable across languages with different cultural norms, pragmatic contexts, or evaluation conventions, rather than just different surface forms?
*   **Basis in paper:** [inferred] The core assumption of the method is that a Universal Criteria Set (UCS) captures "stable semantic dimensions shared across languages" (Section 3.3). However, the analysis in Section 5.3 shows that "the relative importance of evaluation criteria is not universally shared across languages" and that importance profiles vary. The Limitations section (§7) acknowledges that "the assumption of language-agnostic evaluation criteria may overlook culturally specific norms, stylistic preferences, or context-dependent interpretations of quality."
*   **Why unresolved:** The paper demonstrates *performance* transfer but does not deeply probe *semantic* or *conceptual* alignment of what "faithfulness" or "factual accuracy" means in different linguistic and cultural contexts. A criterion like "correct attribution" or "certainty calibration" may have different practical interpretations.
*   **What evidence would resolve it:** A human evaluation study where annotators from different language/cultural backgrounds judge whether the generated criteria questions themselves are valid, meaningful, and culturally appropriate probes for the target language. A fine-grained analysis of per-criterion performance breakdowns across languages to identify which concepts consistently transfer and which diverge. Qualitative analysis of failure cases where the criteria scores are high but the final judgment is wrong, or vice-versa, in specific languages.

### Open Question 3
*   **Question:** What is the optimal strategy for constructing the Universal Criteria Set (UCS) to maximize cross-lingual transfer efficiency and robustness, given observed variations in criterion importance across languages?
*   **Basis in paper:** [inferred] The UCS is generated from the task description in English (Section 3.1). Section 5.3 shows that restricting the model to the "top-10 criteria selected according to English importance" harms performance for languages with different importance profiles. This implies that a criteria set optimized for English (via its importance) is suboptimal for other languages. The Future Work section (§7) states: "Future work could focus on selecting or learning criteria that provide the strongest signal across languages."
*   **Why unresolved:** The current UCS generation process (prompting an LLM with the task description) is not systematically evaluated against alternative construction methods (e.g., multilingual generation, multi-objective optimization for cross-lingual alignment, iterative refinement using low-resource language feedback). It's unclear if the current set is near-optimal or if a better, more transferable set exists.
*   **What evidence would resolve it:** Experiments comparing different UCS generation protocols (e.g., generate criteria in multiple languages and intersect; generate criteria and then filter for high cross-lingual importance alignment; use a multilingual model to generate criteria). Systematic evaluation of the impact of the *number* of criteria and the *diversity* of concepts on transfer performance across a wider range of language families.

### Open Question 4
*   **Question:** What is the precise cost-benefit trade-off of the decomposition approach in terms of inference latency, computational resources, and marginal accuracy gains over powerful zero-shot or chain-of-thought baselines for high-resource languages?
*   **Basis in paper:** [inferred] Section 5.6 acknowledges the "inference cost" due to multiple LLM calls for criteria generation and scoring. Table 4 shows performance improves with finer decomposition (per-concept), but the associated cost increase is not quantified. For high-resource languages where strong zero-shot baselines already perform well (e.g., French/Spanish in mFACE), the absolute gain from UCS may be smaller. The practical viability depends on whether these gains justify the significant increase in API calls/tokens.
*   **Why unresolved:** The paper reports accuracy but not wall-clock time, token counts, or monetary cost for each method. Without quantifying these costs, the practical adoption of the method for high-resource languages remains unclear, especially when strong zero-shot baselines already achieve high performance.
*   **What evidence would resolve it:** Profiling experiments measuring average latency, total tokens, and estimated API costs for UCS versus zero-shot and CoT baselines across languages. Cost-sensitive evaluation showing at what point marginal accuracy gains no longer justify additional inference burden.

## Limitations
- **Assumption of Universal Criteria:** The method relies on UCS being semantically stable across languages, but this may overlook culturally specific norms, pragmatic variations, or differing interpretations of quality (Open Question 2). The paper does not validate whether the criteria themselves are understood equivalently by speakers of different languages.
- **Ad Hoc UCS Construction:** The UCS is generated from an English task description using a single LLM, which may produce criteria that are not optimally transferable. No systematic comparison to alternative generation strategies is provided (Open Question 3).
- **Burmese Outlier:** The complete failure for Burmese indicates that for certain scripts or typologically distant languages, the decomposition pipeline breaks down. The root cause remains unknown (Open Question 1).
- **Inference Cost:** The approach requires multiple LLM calls (criteria generation + scoring per sample), increasing latency and expense compared to single-pass zero-shot evaluation. This cost is not quantified (Open Question 4).
- **English-Centric Transfer Module:** The lightweight module is trained solely on English labels, potentially embedding English-specific evaluation biases into the final mapping, which may harm performance for languages with different quality conventions.

## Confidence
We have high confidence in the core empirical findings: UCS achieves state-of-the-art or competitive balanced accuracy on two multilingual benchmarks across 11 of 12 languages, with statistically significant gains over strong baselines. The experiments are well-controlled, using standard splits and multiple baselines. The data efficiency claim (performance stabilizes with 20–30% of English data) is supported by ablation results. However, confidence is moderated by the unexplained Burmese outlier and the lack of direct evidence that the UCS criteria are semantically universal rather than merely surface-transferable. The absolute gains, while consistent, are modest (2-3 points) for some languages, and the practical utility is uncertain without cost measurements. Overall, the method appears robust but not fully understood.
