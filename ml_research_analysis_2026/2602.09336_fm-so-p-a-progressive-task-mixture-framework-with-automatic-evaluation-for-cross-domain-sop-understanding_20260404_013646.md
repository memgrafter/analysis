# FM SO.P: A Progressive Task Mixture Framework with Automatic Evaluation for Cross-Domain SOP Understanding

## Quick Facts
- arXiv ID: 2602.09336
- Source URL: https://arxiv.org/abs/2602.09336
- Reference count: 40
- Primary result: FM SO.P achieves parameter-efficient cross-domain SOP understanding, with a 7B model matching a 72B baseline on SOPBench and a 32B variant exceeding it by 13.86%.

## Executive Summary
FM SO.P introduces a progressive task mixture framework to address poor cross-domain Standard Operating Procedure (SOP) understanding in large language models. The approach trains models through three cumulative stages—concept disambiguation, action sequence understanding, and scenario-aware graph reasoning—using contrastive learning with task-specific negative samples. An automatic multi-agent evaluation system generates domain-adaptive rubrics, stratified test sets, and scores. On the SOPBench benchmark spanning seven domains, FM SO.P (7B) achieves a 34.33% pass rate, matching a 72B parameter baseline (34.44%) with ten times fewer parameters; the 32B variant reaches 48.30%, exceeding the baseline by 13.86%. Ablation studies confirm additive gains from each stage, with overall improvement from 11.30% to 34.33%.

## Method Summary
Training proceeds via progressive task mixtures. Stage 1 builds terminology precision using term substitution contrastive pairs. Stage 2 adds sequential error injection (reorder, omit, insert) while retaining Stage 1 data. Stage 3 introduces graph constraint violations (cycles, missing preconditions, invalid edges) and retains all previous data. A unified contrastive loss optimizes across all stages. Evaluation employs three agents: Agent 1 analyzes the SOP corpus to produce a domain-specific rubric; Agent 2 creates a stratified test set; Agent 3 scores model outputs against LLM-generated reference answers using the rubric.

## Key Results
- FM SO.P (7B) matches a 72B baseline on SOPBench (34.33% vs 34.44% pass rate) with 10× fewer parameters.
- FM SO.P (32B) exceeds the 72B baseline by +13.86%, achieving 48.30% pass rate.
- Ablation shows cumulative gains: adding Stage 2 improves from 11.30% to 25.67%, and adding Stage 3 further to 34.33% (+23.03% total).

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** Progressive task mixture training builds SOP understanding hierarchically by staging concept disambiguation, action sequence understanding, and scenario-aware graph reasoning with cumulative data.  
**Mechanism:** Stage 1 trains on term substitution contrastive pairs to establish terminology precision. Stage 2 adds sequential error injection (reorder, omit, insert) while retaining Stage 1 data. Stage 3 introduces graph constraint violations (cycles, missing preconditions, invalid edges) and retains all previous data. Each stage optimizes a contrastive loss, and the final model parameters result from jointly minimizing the weighted sum of all stage losses.  
**Core assumption:** The three reasoning capabilities (terminology, sequencing, conditional logic) are hierarchical and do not conflict when trained cumulatively; explicit negative samples at each stage prevent shortcut learning.  
**Evidence anchors:** [abstract] "progressive task mixtures that build capabilities by stages across three task types with cumulative data"; [section 2.2] formal definitions and cumulative data formulation `D_train^(k) = ∪_{i=1}^k D_i`.  
**Break condition:** If capabilities are not truly hierarchical, Stage 3 may overwrite earlier learning or cause interference; if negative samples do not cover the full error distribution, the model may learn spurious correlations.

### Mechanism 2
**Claim:** Contrastive pair generation with task-specific negative operators provides explicit signals to learn subtle procedural constraints rather than surface-level pattern matching.  
**Mechanism:** Negatives are constructed by minimally perturbing correct examples: Stage 1 substitutes semantically similar terms, Stage 2 applies error injection operators to workflows, Stage 3 modifies graph structure. The model optimizes a contrastive loss that scores correct instances higher than negatives.  
**Core assumption:** Procedural understanding requires distinguishing correct from nearly correct procedures; without such signals, models rely on shallow heuristics.  
**Evidence anchors:** [abstract] "contrastive pairs are generated at every stage with cumulative data"; [section 2.2] equations defining positive-negative pair construction and contrastive loss.  
**Break condition:** If negative samples are not diverse enough or are too easy/hard, the model may not learn the decision boundary; if positives are insufficiently representative, overfitting to the contrastive objective may occur.

### Mechanism 3
**Claim:** The automatic multi-agent evaluation system adapts to domain-specific requirements by generating rubrics, stratified test sets, and scoring dynamically.  
**Mechanism:** Agent 1 analyses the SOP corpus to produce a rubric `R(D)` with dimensions and weights (e.g., "temporal constraint validation" for DMV). Agent 2 creates a test set stratified by complexity, question type, and rubric coverage. Agent 3 scores model outputs against reference answers using the rubric, yielding a weighted final score.  
**Core assumption:** Different domains impose distinct evaluation criteria; a fixed metric cannot capture this variance.  
**Evidence anchors:** [abstract] "automatic multi-agent evaluation system consisting of three agents that adaptively generate rubrics, stratified test sets, and rubric scoring"; [section 2.3] detailed prompts and scoring aggregation.  
**Break condition:** If generated rubrics misalign with human judgment (missing critical dimensions or misweighting), evaluation may be misleading; reference answers are LLM-generated, introducing potential bias.

  *Why needed:* FM SO.P targets cross-domain SOP understanding; SOPs involve multi-step workflows, conditional logic, and domain-specific constraints.  
  *Quick check:* What are the three interconnected dimensions of SOP challenges identified in Section 2.1.1? (Answer: Concept Disambiguation, Sequential Dependency Understanding, Contextual Constraint Reasoning.)

  *Why needed:* The paper positions its progressive mixture against curriculum learning to clarify novelty.  
  *Quick check:* How does FM SO.P's progressive mixture differ from traditional curriculum learning? (Answer: Curriculum orders samples by difficulty within a single task type; progressive mixture introduces new task types at each stage while retaining all previous data.)
- **Concept:** Contrastive learning for procedural reasoning  
  *Why needed:* The training objective is contrastive; grasping positive/negative construction is key to reproducing the method.  
  *Quick check:* What are the three negative generation operators for action sequences in Stage 2? (Answer: reorder, omit step, insert spurious.)

## Architecture Onboarding

### Component Map
Raw SOPs → Data Processor → Structured scenarios → Contrastive Pair Generator (Stages 1–3, cumulative) → Trainer (unified contrastive loss) → Trained model → Evaluation Suite (Agent 1: rubric, Agent 2: test set, Agent 3: scoring) → Domain-specific scores

### Critical Path
1. Preprocess SOPBench into JSON scenarios with required fields.
2. Generate Stage 1 contrastive pairs (term substitution).
3. Generate Stage 2 pairs (workflow error injection) and append to Stage 1 data.
4. Generate Stage 3 pairs (graph constraint violations) and append to create full cumulative dataset.
5. Train base model with loss `min_θ [α1L1 + α2L2 + α3L3]` using AdamW.
6. For evaluation, feed domain corpus to Agent 1 to get `R(D)`, then Agent 2 creates test set `B`, then Agent 3 scores model outputs on `B`.

### Design Tradeoffs
- Cumulative data vs. catastrophic forgetting: Keeping all previous data avoids forgetting but increases memory; mitigated with moderate dataset sizes.
- Negative sample ratio: Found task-dependent optima (1:4 for Stages 1–2, 1:8 for Stage 3); universal ratios underperform.
- Automatic evaluation vs. human labels: LLM-generated rubrics enable scalability but may drift from human judgment; compensated by validation on SOPBench.
- Model size: Parameter efficiency shown (7B ≈ 72B) but training cost still scales; progressive mixture mainly helps smaller models.

### Failure Signatures
- Training: Ablation shows no additive gains when adding stages → negative generation inadequate or stages not properly separated; check negative diversity.
- Evaluation: Rubrics nearly identical across domains → Agent 1 prompt too generic; inspect generated rubrics per domain.
- Overall: FM SO.P underperforms baselines → verify contrastive loss implementation (temperature `τ`, scoring function) and DAG extraction accuracy.

### First 3 Experiments
1. **Ablation – joint training:** Train baseline with all contrastive pairs mixed without staging; expect significant drop (paper: joint training fails to differentiate reasoning capabilities).
2. **Negative ratio sweep:** Test ratios 1:4, 1:8, 1:20 for each stage separately; expect Stage 3 to peak at 1:8, Stages 1–2 at 1:4.
3. **Fixed vs. adaptive rubric evaluation:** Evaluate FM SO.P with uniform rubric (same dimensions/weights for all domains) vs. adaptive multi-agent system; expect adaptive rubrics to better reflect domain-specific performance.

## Open Questions the Paper Calls Out
- **Open Question 1:** How reliable is the automatic multi-agent evaluation system that uses LLM-generated pseudo ground truth, and how do its scores correlate with human expert judgments across the seven SOPBench domains?  
  *Basis:* Authors acknowledge relying on pseudo ground truth without human annotation (Section 2.3.3); no human evaluation provided.
- **Open Question 2:** What determines the optimal positive-to-negative sampling ratio for each stage of the progressive task mixture, and can we predict this ratio from properties of the task or model without exhaustive grid search?  
  *Basis:* Ablation shows varying optimal ratios (Stage 1/2: 1:4, Stage 3: 1:8) but no theoretical guidance (Section 3.3.2).
- **Open Question 3:** Is the prescribed order of training stages (concept disambiguation → action sequence understanding → graph reasoning) critical for achieving the observed gains, or could alternative schedules (e.g., reversed order or interleaved) work equally well?  
  *Basis:* Stages are added cumulatively but not tested in permutations; cumulative ablation shows each stage contributes positively but does not establish causality for ordering.
- **Open Question 4:** To what extent does FM SO.P learn truly domain-agnostic SOP reasoning skills versus domain-specific shortcuts, and how well does it transfer to completely novel domains (e.g., scientific laboratory protocols) not represented in SOPBench?  
  *Basis:* Evaluation limited to seven business/administrative domains; no out-of-distribution experiments; generalization to qualitatively new procedural paradigms untested.

## Limitations
- Major uncertainties block full replication: (1) SOPBench data schema and complete negative sample generation algorithms (especially Stage 3's 64 diverse graph violations) are undisclosed. (2) Implementation details of scoring functions `sθ`, `Sθ`, `Rθ` and evaluation agents' internal models are vague. (3) Algorithm for rubric weight determination in Agent 1 is unspecified.
- Automatic evaluation relies on LLM-generated references and rubrics, introducing potential bias despite validation on SOPBench.

## Next Checks
1. **Negative sample diversity audit:** Generate Stage 3 negatives for 50 SOPBench scenarios using described operators. Measure coverage against a hand-curated list of 30 violation patterns; acceptance requires >85% inclusion.
2. **Rubric-human alignment test:** Run Agent 1 to produce rubrics for 3 domains (e.g., banking, DMV, healthcare). Have domain experts rank rubric dimensions by importance. Compute Krippendorff’s α between LLM weights and expert consensus; target α > 0.7.
3. **Catastrophic forgetting diagnostic:** After full progressive training, evaluate the 7B model on Stage 1 and Stage 2 held-out sets. Pass rate drop >5% on either stage indicates interference; mitigate with gradient-normalization (PCGrad).
