# Talk, Evaluate, Diagnose: User-aware Agent Evaluation with Automated Error Analysis

## Quick Facts
- **ArXiv ID**: 2603.15483
- **Source URL**: https://arxiv.org/abs/2603.15483
- **Reference count**: 40
- **Primary result**: The TED framework systematically evaluates LLM agents across user personas and domains, and fixing diagnosed errors improves performance by up to 8–10%.

## Executive Summary
This paper introduces the TED (Talk, Evaluate, Diagnose) framework for user-aware evaluation of LLM agents. It decouples user personas from task instructions, enabling systematic testing with both expert and non‑expert templates. During evaluation, an LLM‑as‑a‑judge uses natural language grading notes to score subgoal completion, and new metrics combine turn efficiency (AUC, PPT) with progress rates. The diagnosis stage automatically clusters judge‑agent inconsistencies to identify error types. Experiments on τ2‑bench and ToolSandbox show that TED reveals nuanced performance differences across models and user expertise levels, and incorporating the identified error fixes yields gains of 8‑10% on key metrics.

## Method Summary
TED comprises three stages:

- **Talk**: For each task, a persona template (expert or non‑expert) is combined with the task instruction to generate a user proxy prompt. The proxy engages in a dynamic conversation with the agent, simulating realistic user behavior.
- **Evaluate**: The agent’s trajectory (actions, tool calls, responses) is judged by an LLM against a set of natural language subgoals (grading notes). For each subgoal, the judge provides a binary completion score per turn. These scores are aggregated to compute progress metrics, and turn‑efficiency is captured via Area Under the Curve (AUC) and Progress Per Turn (PPT). Multiple judge votes (Q) are collected to reduce noise.
- **Diagnose**: Subgoals with inconsistent or failing outcomes are selected. A prompting routine extracts low‑level error explanations from the trajectory, and a clustering algorithm groups similar errors across samples. The resulting error clusters guide targeted improvements.

The pipeline is instantiated on τ2‑bench (airline easy/hard, retail) and ToolSandbox, using `gpt-4.1` as judge and user proxy, with `n=k=20` trials per τ2‑bench sample and `k=8` for ToolSandbox.

## Key Results
- TED enables dual‑persona evaluation, exposing how agents perform for users of varying expertise.
- New metrics (MeanProgress@k, MaxAUC@k, MaxPPT@k) effectively quantify both task completion and efficiency.
- Automated diagnosis identifies common failure modes; fixing these errors improves agent scores by 8‑10%.

## Why This Works (Mechanism)
The Talk stage produces realistic, persona‑specific dialogues by merging persona traits with task goals, forcing agents to adapt to diverse user expectations. The Evaluate stage leverages a powerful LLM judge to provide granular, turn‑level assessments against natural language subgoals; aggregating these scores over time yields a continuous progress curve, from which AUC and PPT succinctly capture efficiency and consistency. The Diagnose stage treats inconsistent subgoal outcomes as signals of potential errors; by prompting the judge to explain failures and clustering those explanations, TED automatically surfaces systematic weaknesses without manual annotation. This combination offers fine‑grained, user‑centric, and actionable evaluation.

## Foundational Learning
- **LLM‑as‑a‑judge**: Scales evaluation by using an LLM to score agent behavior. Needed: Provides consistent, automated assessment; Quick check: Measure judge agreement with human judgments on a held‑out sample.
- **Natural language grading notes**: Express subgoals in free text rather than rigid assertions. Needed: Allows flexible evaluation across diverse domains; Quick check: Verify that grading notes cover all critical success criteria for a task.
- **Turn‑efficiency metrics (AUC, PPT)**: Summary statistics over the progress curve. Needed: Distinguish agents that reach goals quickly from those that struggle; Quick check: Ensure metrics correlate with human efficiency ratings.
- **User persona templates**: Structured descriptions of expert vs. non‑expert users. Needed: Simulate varied user expectations and knowledge levels; Quick check: Inspect simulated dialogues for persona‑specific language and misconceptions.
- **Automated error identification and clustering**: Prompts to extract error reasons followed by clustering. Needed: Aggregate isolated failures into actionable categories; Quick check: Manually review clusters for semantic coherence.

## Architecture Onboarding

**Component map (plain text):**  
`PersonaTemplate + TaskInstruction -> UserProxy -> Agent -> Judge -> Metrics (Progress, AUC, PPT) -> Diagnosis (ErrorIdentifier -> Clusterer)`

**Critical path:** The end‑to‑end flow is: (1) generate user prompt from persona and task, (2) run interactive dialogue between user proxy and agent, (3) evaluate each agent turn with LLM judge against subgoals, (4) aggregate scores to compute metrics, (5) detect inconsistent subgoals and extract errors, (6) cluster errors for diagnosis.

**Design tradeoffs:** Using `gpt-4.1` ensures high‑quality judgment and user proxy but limits reproducibility. Majority vote across Q judges stabilizes scores at extra cost. Dynamic user simulation introduces small persona confusion (6‑12%) that may affect results, but it scales far better than recruiting real humans.

**Failure signatures:** High variance in judge votes for the same subgoal; user proxy messages that deviate from the assigned persona; diagnosis output that is either too fragmented (many tiny clusters) or overly coarse (few generic clusters); metrics that diverge significantly from manual evaluation on a sample.

**Exactly 3 first experiments:**
1. **Smoke test on τ2‑bench easy**: Run the full TED pipeline with expert persona, n=5 samples, k=1, Q=3 to verify data flow and metric outputs.
2. **Model comparison**: Evaluate two agent models (e.g., GPT‑4 and Claude‑3) on the same dataset using TED’s MaxAUC@k and MaxPPT@k to confirm expected performance gaps.
3. **Diagnosis validation**: For a subset of failing trajectories, manually inspect the error explanations and clusters produced by TED to assess semantic meaningfulness.

## Limitations
- **Proprietary judge**: Heavy reliance on `gpt-4.1` hinders independent replication and raises cost barriers.
- **Underspecified implementation details**: Trajectory parsing, exact prompt templates, and dataset splits are not fully described, requiring trust in the provided repository.
- **User proxy errors and judge noise**: Persona role confusion (6‑12%) and judge inconsistency can bias results; majority vote mitigates but does not eliminate these issues.

## Confidence
- Framework reveals cross‑domain insights: **Medium**
- Metrics (AUC, PPT, Progress) are meaningful: **Medium**
- Automated error diagnosis identifies useful clusters: **Low–Medium**
- Fixing identified errors yields +8‑10% gains: **Medium**

## Next Checks
1. Replicate the experiments using an open‑source judge (e.g., Llama‑3‑70B) and publish full prompt templates to assess robustness and reduce dependency on proprietary models.
2. Conduct a human study of the user proxy dialogues for both personas to quantify persona fidelity and its impact on evaluation outcomes.
3. Manually annotate a stratified sample of Diagnose‑stage error clusters to measure precision/recall and refine the clustering logic.
