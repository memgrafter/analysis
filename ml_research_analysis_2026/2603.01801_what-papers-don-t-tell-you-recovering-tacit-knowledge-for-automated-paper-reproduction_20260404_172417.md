# What Papers Don't Tell You: Recovering Tacit Knowledge for Automated Paper Reproduction

## Quick Facts
- **ArXiv ID:** 2603.01801  
- **Source URL:** https://arxiv.org/abs/2603.01801  
- **Reference count:** 40  
- **Primary result:** PaperRepro achieves an average performance gap of 10.04% from official implementations, improves over the strongest baseline by 24.68%, and attains sub‑10% gaps on 7 out of 10 tasks in ReproduceBench.

## Executive Summary
Automated paper reproduction from academic texts is hampered by three types of tacit knowledge: relational (reuse/adaptation relationships between implementations), somatic (experience‑driven refinements), and collective (community‑wide practices). This paper presents PaperRepro, a graph‑based agent framework that progressively recovers these knowledge types. It operates on a pruned citation graph of papers with code, using node‑level relation‑aware aggregation to scaffold initial implementations, execution‑feedback refinement to fix runtime issues, and graph‑level knowledge induction to distill community practices. Evaluated on an extended ReproduceBench covering 3 domains and 40 recent papers, PaperRepro reduces the average gap to official implementations to 10.04% and outperforms the strongest baseline by 24.68%, with consistent cross‑domain gains and superior human evaluation scores.

## Method Summary
PaperRepro constructs a Semantic Scientific Graph (SSG) from a corpus of papers with code and citations. For a target paper, it first prunes irrelevant citation neighbors via an ensemble LLM ranking (SSGP). Then it recovers tacit knowledge in three stages:  
1. **Node‑level relation‑aware aggregation:** The agent compares the target’s implementation units against pruned neighbors’ code, classifying units as reusable, adaptable, or new. It selects the best candidate per unit using a priority score that combines SSGP edge weight and a reuse bias, and encapsulates APIs with dependency resolution.  
2. **Execution‑feedback refinement:** The initial code is iteratively run in a sandbox; execution logs and metrics drive an LLM‑based diagnosis and repair plan until performance converges or a budget is exhausted.  
3. **Graph‑level knowledge induction:** The full SSG is partitioned into subgraphs via Louvain clustering. Within each subgraph, the agent reproduces all member papers, collects execution outcomes, and induces recurring patterns (e.g., hyperparameter choices) that exceed a frequency threshold and yield stable gains. At inference, the target’s affinity to subgraphs retrieves top‑K knowledge bases, which are injected into the reproduction agent for final synthesis.

## Key Results
- Average performance gap: **10.04%** from official implementations across 40 papers.  
- Relative improvement: **24.68%** over the strongest baseline (Codex or RepoQA).  
- Success rate: Sub‑10% gap on **7 out of 10** tasks; consistent gains across 3 domains.  
- Human evaluation: PaperRepro scores higher than baselines on method fidelity, experimental config consistency, and code completeness.

## Why This Works (Mechanism)

### Mechanism 1: Node‑Level Relation‑Aware Aggregation (Relational Tacit Knowledge)
**Claim:** Recovers relational tacit knowledge (implementation reuse/adaptation relationships omitted in papers) by analyzing citation neighbors at the unit level.  
**Mechanism:** For each pruned neighbor, an LLM compares the target’s implementation needs against the neighbor’s code, classifying units as directly reusable (`Ureuse`), adaptable (`Uadapt` with diff instructions), or new (`Unew`). A priority score `p = w(v_t, v_i) + β·I[reuse]` selects the best candidate per unit from competing neighbors, where `w` is the SSGP edge weight and `β` biases toward reuse.  
**Core assumption:** Implementation‑unit relationships are discernible from paper text and neighbor code, and the most relevant neighbor (by SSGP weight) provides the best starting point unless adaptation is necessary.  
**Evidence anchors:** Abstract and Section 4.2.1 describe the process; Fleiss’ κ=0.82 for neighbor relevance (Appendix C.1) supports SSGP quality. The cited corpus discusses tacit knowledge conceptually but does not directly validate this mechanism.  
**Break condition:** If SSGP pruning discards all neighbors containing a critical implementation unit (i.e., `Unew` dominates for a core module), the initial scaffold will be incomplete and likely fail execution.

### Mechanism 2: Execution‑Feedback Refinement (Somatic Tacit Knowledge)
**Claim:** Recovers somatic tacit knowledge (experience‑driven, hard‑to‑articulate decisions) through iterative code execution and feedback‑driven debugging.  
**Mechanism:** Starting from the initial implementation `C_(init)`, the agent runs the code in a sandbox, captures execution logs, errors, and performance metrics `O_vt`. In a ReAct‑style loop, an LLM diagnoses failures (e.g., dimension mismatches, numerical instability), generates a repair plan `Plan(k)` with specific file edits `δ_u,(k)`, and iterates until performance converges or a budget is exhausted.  
**Core assumption:** Runtime behavior provides a reliable signal for identifying incorrect implicit decisions not specified in the paper.  
**Evidence anchors:** Abstract and Section 4.2.2 formalize the loop. Ablation (Table 3) shows the largest drop when this component is removed, confirming its critical role. The corpus does not directly validate execution‑feedback for code debugging.  
**Break condition:** If execution feedback is too sparse/noisy or the agent misdiagnoses repeatedly, refinement may diverge or stall.

### Mechanism 3: Graph‑Level Knowledge Induction (Collective Tacit Knowledge)
**Claim:** Recovers collective tacit knowledge (community‑wide conventions and tricks) by inducing patterns from clusters of similar papers within the citation graph.  
**Mechanism:** Using SSGP edge weights, the full paper graph is partitioned into subgraphs `G_j^(t)` via Louvain clustering. Within each subgraph, the agent reproduces all member papers, collects `(C_ref, O)` pairs, and an LLM induces recurring patterns (e.g., “use AdamW with weight decay 1e‑4”) that exceed a frequency threshold `η` and show stable validation gains. At inference, the target paper’s affinity to subgraphs selects the top‑K knowledge bases `K_col(v_t)` for injection.  
**Core assumption:** Papers in the same implementation paradigm cluster together via SSGP weights, and cross‑paper induction within these clusters reveals generalizable practices.  
**Evidence anchors:** Abstract and Section 4.2.3 detail the process. Figure 5 shows random partitioning underperforms edge‑weight partitioning, suggesting SSGP weights capture paradigm similarity. The corpus is only weakly related.  
**Break condition:** If subgraph partition groups heterogeneous papers, induced patterns may be conflicting or irrelevant; insufficient training papers in a paradigm causes induction failure.

## Foundational Learning
1. **Scientific Graph Construction & Pruning**  
   - **Why needed:** PaperRepro’s reasoning operates on a citation graph; understanding node/edge creation and pruning (to filter semantic noise) is foundational.  
   - **Quick check:** What distinguishes `N_cand(v_t)` from `N_prune(v_t)`, and why does edge weight `w(v_t, u)` depend on a composite score of mean rank and rank std?

2. **Multi‑Scale Graph Reasoning (Node vs. Graph Level)**  
   - **Why needed:** The system’s innovation is progressive recovery across scales: node‑level for direct relationships, graph‑level for community patterns; skipping either leaves a tacit knowledge type unrecovered.  
   - **Quick check:** Why can’t collective knowledge `K_col` be recovered from just the target’s neighbor set `N_prune(v_t)`? What is the restricted receptive field problem?

3. **Execution‑Feedback Loop (Act‑Observe‑Reason)**  
   - **Why needed:** Somatic knowledge requires environment interaction; this ReAct‑inspired loop is the only way to surface runtime‑specific issues like shape mismatches or numerical instability.  
   - **Quick check:** How does the agent’s repair plan `Plan(k)` differ from the initial build? What specific signals in `O(k)` trigger a change?

## Architecture Onboarding
**Component map:**  
Semantic Scientific Graph Pruning (SSGP) → Node‑Level Relation‑Aware Aggregation → Execution‑Feedback Refinement → Graph‑Level Knowledge Induction → Knowledge Injection & Final Synthesis

**Critical path:** For a new target paper `v_t`: (1) SSGP on its neighbors; (2) Node‑level aggregation over `N_prune`; (3) Execution refinement loops; (4) (Concurrently, full graph partitioned & knowledge bases trained); (5) Subgraph affinity calculation; (6) Knowledge injection into `C_(ref)`; (7) Final output `C_*`.

**Design tradeoffs:**  
- **Pruning depth (`K_keep`) vs. recall:** Tighter pruning reduces noise but risks losing crucial neighbors; looser pruning adds noise. Sensitivity varies by task.  
- **Reuse bias (`β`) vs. adaptation:** Higher `β` favors stability but may perpetuate incorrect patterns if a neighbor’s implementation is flawed for the target.  
- **Subgraph coherence vs. size:** Louvain clustering balances intra‑subgraph similarity (for good induction) against having enough papers per subgraph to extract patterns.

**Failure signatures:**  
- **High performance gap >30%:** Likely indicates early failure: SSGP missed key neighbors or node‑level aggregation produced an unscaffoldable `C_(init)`.  
- **Ablation: Removing Execution‑Feedback Refinement causes largest degradation (Table 3):** Confirms somatic knowledge is the most frequent bottleneck.  
- **Random partitioning underperforms edge‑weight partitioning (Figure 5):** Signals SSGP weights are meaningful for paradigm similarity.

**First three experiments:**  
1. **Validate SSGP neighbor selection:** Manually inspect `N_prune` for 10 target papers; measure expert agreement (Fleiss’ κ).  
2. **Measure code‑source breakdown:** Categorize lines in `C_(init)` as reused/adapted/new; expect >70% derived from neighbors if relation analysis works.  
3. **Test knowledge transferability:** Train `K_j` using a small LLM (e.g., Qwen‑80B) and apply to a larger one (Claude‑Opus); cross‑model gains confirm induced knowledge is model‑agnostic.

## Limitations
- **Prompt robustness:** Minor template variations may destabilize relation analysis and knowledge induction.  
- **Hyperparameter generalization:** Defaults (e.g., `K_keep`, `β`, `η`) may not transfer across domains without task‑specific tuning.  
- **Graph construction and API conflicts:** Sourcing consistent paper‑code pairs, handling missing implementations, and resolving incompatible neighbor APIs are underspecified practical bottlenecks.

## Confidence
- **Relational knowledge recovery:** High (Fleiss’ κ=0.82, detailed unit‑level analysis).  
- **Somatic knowledge:** Medium‑High (ablation shows largest drop without execution‑feedback, but loop convergence depends on noisy signals).  
- **Collective knowledge:** Medium (subgraph partitioning improves over random, but limited direct validation of pattern generalizability).

## Next Checks
1. **Cross‑domain SSGP validation:** Annotate neighbor relevance for 20 unseen‑domain papers (e.g., robotics) with domain experts; measure precision@K to test pruning generalizability.  
2. **Priority scoring ablation:** Remove reuse bias (`β`) in node‑level aggregation; compare initial scaffold success rate (executability without refinement) against default across 10 tasks.  
3. **Subgraph pattern conflict analysis:** On the training graph, compute pairwise disagreement scores between induced patterns within each Louvain cluster; high disagreement indicates unreliable collective induction.
