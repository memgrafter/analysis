# Development of a European Union Time-Indexed Reference Dataset for Assessing the Performance of Signal Detection Methods in Pharmacovigilance using a Large Language Model
## Quick Facts
- arXiv ID: 2603.26544
- Source URL: https://arxiv.org/abs/2603.26544
- Reference count: 0
- Primary result: Constructed a time-indexed reference dataset with 110,823 drug-AE pairs from 17,763 historical SmPCs (1995-2025), achieving 95.1% extraction accuracy and 95.7% MedDRA mapping success, enabling benchmarking of signal detection methods on pre-confirmation data.

## Executive Summary
The study addresses the lack of temporally indexed reference datasets for evaluating early signal detection in pharmacovigilance. By extracting adverse events from all historical Summaries of Product Characteristics (SmPCs) for EU centrally authorized products (1995–2025) and anchoring each drug-AE pair to the regulatory inclusion date, the authors create a gold-standard benchmark. Using DeepSeek V3 to parse Section 4.8 text and a two-pass MedDRA mapping strategy, they produce a curated dataset of 110,823 associations across 1,479 active medicines. Manual validation confirms high accuracy, enabling assessment of signal detection algorithms on data preceding regulatory confirmation.

## Method Summary
The pipeline scraped the EU Union Register to obtain URLs for all historical SmPC PDFs of 1,513 centrally authorized products (17,763 versions). Text from Section 4.8 (“Undesirable effects”) was extracted using `pdfplumber`. Adverse event expressions were parsed by prompting DeepSeek-V3 (temperature=0.0) to output a CSV list. A two-pass MedDRA v28 mapping first attempted exact string matching to Preferred Terms; unmatched terms were processed by an LLM to predict likely System Organ Classes (SOCs), after which the candidate PT space was restricted and the best PT selected. The extracted AEs were merged with scraped metadata (procedure dates, ATC codes) and filtered for active products, yielding a time-indexed dataset where each association is timestamped by the SmPC inclusion date.

## Key Results
- Final dataset: 110,823 drug-adverse event pairs covering 1,479 active medicinal products.
- Manual validation of extraction: 95.1% accuracy.
- MedDRA mapping success: 95.7% overall (73.5% exact match, 22.2% SOC-filtered match).

## Why This Works (Mechanism)
### Mechanism 1: Temporal Indexing via SmPC Inclusion Date
- **Claim:** Temporal indexing to the SmPC inclusion date enables evaluation of signal detection methods on data preceding regulatory confirmation.
- **Mechanism:** The `Date Added` variable is derived from the regulatory procedure closing date for each SmPC version. Any spontaneous report data after this date is considered post-inclusion and excluded from the pre-confirmation analysis, preventing circularity.
- **Core assumption:** The SmPC update date is a valid, discrete proxy for the moment of regulatory acceptance of a safety signal.
- **Evidence anchors:** Abstract states the dataset enables benchmarking using only pre-confirmation data; Section 2.2.1 describes time indexing based on AE inclusion date and lists `Date Added` and `Union_register_close_date` variables.
- **Break condition:** If signal-to-label latency is highly variable, the pre-confirmation window defined by the SmPC date may inconsistently truncate available observational data, potentially biasing performance estimates.

### Mechanism 2: Deterministic LLM Extraction from SmPC Text
- **Claim:** Using DeepSeek V3 with temperature=0.0 can accurately extract AE terms from semi-structured SmPC Section 4.8 text.
- **Mechanism:** The LLM is prompted to parse the free-text narrative and tabular data within PDF SmPCs, outputting a structured list of AE expressions. Temperature 0.0 forces deterministic, reproducible extraction from identical input.
- **Core assumption:** The LLM, when constrained deterministically and given a precise extraction task, can reliably identify AE mentions without significant hallucinations or omissions.
- **Evidence anchors:** Section 2.2.3 describes automated extraction using DeepSeek-V3 with temperature 0.0; Section 3.3 reports 95.1% manual validation accuracy.
- **Break condition:** The 5% error rate, primarily missing events, could be non-random; systematic omissions associated with specific linguistic patterns or drug classes would bias coverage and underestimate true signal detection rates.

### Mechanism 3: Two-Pass MedDRA Mapping for High Standardization
- **Claim:** A two-pass MedDRA mapping strategy (exact match → SOC-filtered LLM match) achieves high terminological standardization (95.7% success) needed for consistent signal detection.
- **Mechanism:** First, extracted AE strings are matched case-insensitively to MedDRA v28 Preferred Terms. For unmatched terms, an LLM predicts 1–3 likely SOCs; the candidate PT space is then restricted to those SOCs and the LLM is re-prompted to select the single best-matching PT. This leverages LLM semantics while drastically reducing the search space.
- **Core assumption:** Predicting a plausible SOC is semantically easier than direct PT selection, and SOC prediction accuracy is sufficient to make the subsequent PT search tractable and correct.
- **Evidence anchors:** Section 2.2.3 details the two-pass procedure; Section 3.3 reports 95.7% success (73.5% exact, 22.2% SOC-filtered).
- **Break condition:** The SOC prediction step is unvalidated; if its error rate is non-trivial, the final PT selection for the 22.2% of terms mapped via this route may be incorrect. Assumption: LLM SOC prediction accuracy >~90%, which is not measured.

## Foundational Learning
- **Concept:** Pharmacovigilance Signal Detection & Reference Standards  
  - **Why needed:** To understand why a time-indexed reference dataset is the gold standard for evaluation; the goal is to test if an algorithm can detect a new safety signal using only data available *before* regulators formally confirm it.  
  - **Quick check:** If a drug-AE pair was added to the SmPC on January 1, 2020, what data should be used to test a signal detection method's "early warning" capability? (Answer: Only reports before that date.)

- **Concept:** Summary of Product Characteristics (SmPC) Structure & Regulatory Process  
  - **Why needed:** Section 4.8 is the target data source; understanding its structure (tables, narrative, frequency categories) and the regulatory procedures causing updates (Type I/II variations, PRAC recommendations) is essential to interpret metadata variables.  
  - **Quick check:** What does a `Source` value of "Post-Approval Discovery" versus "Clinical Trial (Baseline)" indicate about the regulatory procedure and evidence supporting that AE's inclusion?

- **Concept:** MedDRA Hierarchy & Multi-Axial Structure  
  - **Why needed:** The dataset maps each AE to a single PT and its SOC, HLT, HLGT. Analysts must know that a PT can map to multiple SOCs (multi-axial) and that the study's method selects one path, which could affect SOC-level analyses.  
  - **Quick check:** If an AE (e.g., "Pancreatitis") is mapped to PT `Pancreatitis`, how many SOCs could it theoretically belong to in MedDRA, and what might this imply for comparing SOC distributions between drug classes? (Answer: Multiple; distributions may be sensitive to SOC assignment.)

## Architecture Onboarding
**Component map:**  
PDF Ingestion → LLM Extraction → MedDRA Mapper → Metadata Enricher → Time-Indexer → Validator

**Critical path:**  
PDF Download → Section 4.8 Text Extraction → LLM AE List → MedDRA PT/SOC Mapping → Join with Regulatory Metadata → Apply Date & Active Filter → Final Time-Indexed Dataset

**Design tradeoffs:**
- LLM vs. Rule-based Extraction: LLM offers flexibility but introduces non-determinism (mitigated by temp=0) and "missing" errors. Rule-based is reproducible but brittle to format changes.
- MedDRA Mapping: Exact match is precise but limited; SOC-filtered LLM match improves coverage but adds potential error; retaining one SOC per PT simplifies analysis but ignores multi-axial design.
- Temporal Anchor: Using SmPC procedure closing date is objective and available, but is an administrative date, not the epistemic date of first signal suspicion/validation.

**Failure signatures:**
- Extraction failures: Logged PDFs where Section 4.8 text could not be identified or extracted (`pdfplumber` errors), leading to missing entire drug profiles.
- Mapping failures: `MedDRA_Match_Method` = `Unmatched` (0.5% of terms), requiring manual intervention and risking non-standard AE terms in the final dataset.
- Temporal inconsistency: Missing or malformed `Union_register_close_date` for a procedure makes `Date Added` impossible to assign.

**First 3 experiments:**
1. Reproduce Validation Metrics: Run the full pipeline on the 20 most recent SmPCs and perform a manual spot-check (n=100 AEs) to confirm the reported 95.1% extraction accuracy and 95.7% mapping rate.
2. Temporal Consistency Check: For 10 drugs with multiple updates, plot the `Date Added` for the same AE across versions; verify the date is non-decreasing (decrease indicates data integration error).
3. SOC Distribution Sanity Check: Compute top 5 SOCs for the whole dataset and separately for pre- vs. post-marketing AEs; verify relative distributions are similar as reported (large divergence suggests systematic bias).

## Open Questions the Paper Calls Out
1. **How does the implicit resolution of MedDRA's multi-axial structure affect the accuracy of SOC-level signal detection analyses?**  
   *Basis:* The pipeline uses `dict(zip(...))` which retains only the last mapping for PTs with multiple SOCs, not the primary SOC.  
   *Why unresolved:* Dataset SOC assignments are determined by file order, potentially causing systematic misclassification.  
   *What would resolve:* Comparative analyses using both the dataset's SOC assignments and a version with explicit primary SOC selections.

2. **To what extent does the lag between actual safety signal detection and SmPC update (signal-to-label latency) compromise the validity of using SmPC dates as temporal anchors?**  
   *Basis:* Discussion notes SmPC closing date is the formal update, not the first signal identification; latency can be "up to several months".  
   *Why unresolved:* Benchmark may include post-detection data, inflating performance estimates.  
   *What would resolve:* Quantification of average latency via historical logs and sensitivity analyses under different latency assumptions.

3. **Do hybrid LLM-rule-based extraction frameworks yield higher accuracy and terminological precision than pure LLM approaches?**  
   *Basis:* Discussion suggests hybrid frameworks as future work.  
   *Why unresolved:* Current study uses pure LLM; hybrid benefits are untested.  
   *What would resolve:* Controlled experiment comparing LLM-only vs. hybrid (LLM + rule-based) on a held-out validation set.

4. **How generalizable is this dataset to non-centrally authorized medicinal products in the EU?**  
   *Basis:* Coverage limited to centrally authorized products (CAPs); nationally authorized products are not included.  
   *Why unresolved:* Different safety profiles and regulatory processes may limit applicability.  
   *What would resolve:* Extending the pipeline to national SmPC archives and performing comparative analyses between CAPs and nationally authorized products.

## Limitations
- Temporal proxy validity: The assumption that SmPC update dates are a consistent proxy for regulatory confirmation is untested; variable signal-to-label latency could bias pre-confirmation window definitions.
- Extraction & mapping error bias: Residual errors (~5% missing events, 4.3% unmapped terms) may not be random; systematic omissions could bias dataset coverage and affect signal detection rates.
- Unvalidated SOC heuristic: The SOC prediction step for terms mapped via the SOC-filtered path lacks independent accuracy assessment, introducing an unquantified error source.
