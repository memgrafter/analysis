# PIRA-Bench: A Transition from Reactive GUI Agents to GUI-based Proactive Intent Recommendation Agents

## Quick Facts
- arXiv ID: 2603.08013
- Source URL: https://arxiv.org/abs/2603.08013
- Reference count: 23
- Primary result: PIRF improves F1avg (40.75% → 54.68%) and FPSnorm (31.31% → 43.90%) over naive baselines, but trails human (Sfinal 90.35 vs 28.05).

## Executive Summary
Current GUI agents are reactive, requiring explicit user instructions before acting. This paper proposes a shift toward proactive intent recommendation, where the agent infers user goals from continuous visual streams and initiates assistance. To support this transition, the authors introduce PIRA-Bench, the first benchmark for proactive intent recommendation, and present PIRF, a baseline framework with a dynamic memory module and reflection-based auto-deletion. PIRA-Bench consists of 100 multi-step trajectories featuring interleaved tasks, user profiles, and synthetic noise, mimicking realistic challenges. Experiments across multiple language models show that PIRF consistently outperforms naive baselines on key metrics, demonstrating improved robustness to noise. However, the best model’s final score remains substantially below human performance, revealing a significant gap for future work.

## Method Summary
PIRA-Bench is constructed from curated trajectories that simulate users performing multiple, often interleaved, tasks while their interactions are interrupted by noise (e.g., pop-ups). Agents must process a continuous stream of GUI observations and proactively recommend actions aligned with the user’s underlying intent. The PIRF framework operates in a loop: a visual encoder extracts features from the current screen; a dynamic memory updates representations of ongoing task threads; an intent predictor generates candidate intents conditioned on memory; a reflection module evaluates these intents and auto-deletes those inconsistent with recent context; an action selector chooses the next GUI action from the filtered intents; and an executor carries out the action. The design is model‑agnostic and was evaluated with several LLMs, including GPT‑based models.

## Key Results
- PIRF yields significant gains in F1avg and FPSnorm over naive baselines (e.g., GPT‑5.2: F1avg 40.75% → 54.68%, FPSnorm 31.31% → 43.90%).
- The dynamic memory and reflection components reduce hallucinations caused by noise, leading to higher final task scores.
- Despite improvements, the best model’s final score (28.05) remains far below human performance (90.35), indicating a substantial performance gap.

## Why This Works (Mechanism)
Dynamic memory enables the agent to retain context across many steps and maintain multiple concurrent task threads, which is essential for handling interleaved activities. The reflection module acts as a noise filter: it periodically compares stored intents with the most recent observations and prunes those that show inconsistency, thereby discarding distractors. This combination addresses two core challenges—context retention and noise robustness—and explains the observed reduction in hallucinations and the performance boost on noisy trajectories. The synergy allows PIRF to stay focused on true user goals despite interruptions.

  - *Why needed*: To anticipate user goals without explicit commands, enabling assistance in continuous interaction.

  - *Why needed*: Real‑world interactive streams contain irrelevant events that can mislead agents.

## Architecture Onboarding
Component map: Visual Encoder -> Dynamic Memory -> Intent Predictor -> Reflection Module -> Action Selector -> Executor

Critical path:
1. Encode current GUI screen.
2. Update dynamic memory with new observation.
3. Generate candidate intents conditioned on memory.
4. Filter intents via reflection (auto‑deletion of noise‑induced ones).
5. Select action from the remaining intents.
6. Execute the action.
7. Repeat.

Design tradeoffs:
- Memory capacity vs. computational overhead: larger memory retains more threads but costs more and may introduce interference.
- Reflection threshold: a higher threshold avoids deleting valid intents but may let noise through; lower threshold risks over‑deletion.
- Modularity: separating memory and reflection aids debuggability but adds latency compared to end‑to‑end training.

Failure signatures:
- Hallucinations: actions unrelated to the true goal due to undetected noise.
- Task forgetting: critical context overwritten, leading to incomplete multi‑step tasks.
- Over‑deletion: reflection removes legitimate intents, causing task abandonment.
- Slowdown: memory growth increases inference time, breaching real‑time constraints.

First experiments:
1. Ablation: Replace dynamic memory with a fixed‑size sliding window and compare performance to isolate memory benefits.
2. Reflection sensitivity: Vary the confidence threshold for auto‑deletion and measure F1avg on trajectories with low, medium, and high noise levels.
3. Generalization: Run PIRF without fine‑tuning on a different benchmark (e.g., WebArena) to assess cross‑domain adaptability.

## Limitations
- **Benchmark scope & realism:** Only 100 curated trajectories with synthetic noise; may not capture full diversity of real‑world proactive scenarios.
- **Baseline comparisons:** Naive baselines might not represent state‑of‑the‑art reactive agents, potentially overstating the improvement magnitude.
- **Performance gap:** Large discrepancy between model (best Sfinal 28.05) and human (90.35) performance indicates unresolved challenges in long‑term intent modeling.

## Next Checks
1. **Cross‑benchmark generalization:** Evaluate PIRF on other multi‑step, interleaved task benchmarks (e.g., AndroidEnv, WebArena) to test transferability.
2. **State‑of‑the‑art baselines:** Re‑run experiments including recent proactive GUI agents (e.g., PersonalAlign, ProAct) to contextualize improvement magnitude.
3. **Ablation with controlled noise:** Isolate the effect of reflection by comparing against a static memory variant on noise‑free vs. noisy trajectory subsets.
