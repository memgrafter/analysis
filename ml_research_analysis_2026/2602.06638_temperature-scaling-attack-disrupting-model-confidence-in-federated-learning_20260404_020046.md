# Temperature Scaling Attack Disrupting Model Confidence in Federated Learning

## Quick Facts
- arXiv ID: 2602.06638
- Source URL: https://arxiv.org/abs/2602.06638
- Reference count: 40
- Primary result: TSA increases calibration error (e.g., CIFAR-10 ECE from 1.56% to 13.46%) with minimal accuracy change (<2%), evades detection and robust defenses.

## Executive Summary
The Temperature Scaling Attack (TSA) is a novel training-time attack in federated learning where malicious clients poison the model’s confidence calibration without noticeably harming accuracy. By using a temperature-scaled softmax during local training and coupling the local learning rate to the temperature (η = βτ), the attacker produces updates that mimic benign optimization trajectories. This distortion yields severely mis‑calibrated models (e.g., ECE jumps by up to 145%) while remaining stealthy (update cosine similarity >0.93) and surviving standard robust aggregators and post‑hoc calibration. Case studies in healthcare and autonomous driving show up to 7.2× more missed critical cases or false alarms, highlighting severe safety risks.

## Method Summary
TSA targets predictive confidence calibration in FL. Malicious clients modify their local training loop: they compute the cross‑entropy loss with a softmax temperature τ ≠ 1, and set their local learning rate to η = βτ, where β is a fixed base step size (matched to benign training). This η–τ coupling ensures the effective update scale and curvature remain comparable to benign updates (τ = 1), preserving convergence and accuracy. The server, unaware of the attack, aggregates these updates normally (e.g., FedAvg). At test time, the model is evaluated with τ = 1, revealing distorted confidence: τ > 1 causes over‑confidence, τ < 1 under‑confidence. The attack requires no test‑time manipulation and evades detection that relies on update geometry or post‑hoc calibration.

## Key Results
- CIFAR-100: calibration error ↑145% with <2% accuracy change.
- CIFAR-10: ECE ↑ from 1.56% to 13.46% (τ=5) with minimal accuracy shift.
- Evasion: update cosine similarity >0.93; robust aggregation and post‑hoc calibration fail; case studies show up to 7.2× increase in safety‑critical errors.

## Why This Works (Mechanism)

**Mechanism 1: Distorting confidence via training‑time temperature scaling**  
Training with τ≠1 while evaluating with τ=1 alters gradient magnitudes (∝1/τ) and loss curvature (∝1/τ²), pushing logits into regions that yield over‑ or under‑confident predictions without changing decision boundaries. The attacker sets η∝τ (β=η/τ) to preserve a benign effective step size, avoiding accuracy loss. Evidence: On CIFAR‑100, TSA increased ECE by 145% with <2% accuracy change; updates remain stealthy (cosine similarity >0.93).

**Mechanism 2: Stealth through η–τ coupling**  
By setting η = βτ, the attacker cancels the temperature’s effect on update magnitude. Lemma 1 shows loss curvature scales as Lᵗ≈C/τ², so ηLᵗ≈βC, matching benign scale (τ=1). This keeps updates within the noise bounds of standard non‑convex FL, yielding high cosine similarity (>0.93) to benign updates and evading similarity‑based detectors. Ablation without coupling drastically reduces similarity.

**Mechanism 3: Evasion of robust aggregation and post‑hoc calibration**  
Robust aggregators (e.g., FLTrust, MultiKrum) filter outliers based on directional similarity; TSA maintains high similarity (≥0.85) so it survives aggregation. Post‑hoc calibrators (temperature scaling, isotonic regression) fit a mapping on test scores, but TSA distorts the training‑time distribution that produced those scores. The underlying logit‑to‑confidence mapping is altered at train time; a post‑hoc fit on the already corrupted model cannot fully reverse it.

## Architecture Onboarding

### Component Map
Global server → broadcasts model, aggregates client updates (FedAvg or robust rule)  
Malicious clients → run local SGD with temperature τ ≠ 1 and learning rate η = β·τ (η–τ coupling)  
Benign clients → standard local SGD (τ = 1, η = β)  
Evaluation → compute accuracy, ECE, sECE, etc., on a held‑out global test set

### Critical Path
1. Server initializes global model θ and sends to all clients.
2. Each communication round, server samples a subset of clients (e.g., M=10% of K).
3. Malicious clients perform E local SGD steps using loss ℓ_τ (softmax with temperature τ) and learning rate η = βτ; benign clients use ℓ₁ and η = β.
4. All clients send model updates Δθ = θ_local – θ_global to server.
5. Server aggregates updates (e.g., weighted average) and updates global model.
6. Repeat for R rounds until convergence or max rounds.

### Design Tradeoffs
- **τ vs. stealth:** Larger |τ−1| amplifies calibration distortion but risks accuracy loss if τ≫10; smaller |τ−1| is subtler but yields weaker impact.
- **β selection:** β must match the benign training regime; improper β causes convergence issues and may affect both accuracy and calibration.
- **Attack direction:** τ>1 induces over‑confidence; τ<1 induces under‑confidence. Choice depends on adversarial goal (e.g., suppressing safety fallbacks vs. flooding verification).

### Failure Signatures
- Accuracy drop >2% indicates τ too extreme or β mismatched.
- Update cosine similarity to benign updates falls below 0.9 suggests broken η–τ coupling or unstable local dynamics.
- Post‑hoc calibration (e.g., temperature scaling) significantly reduces ECE may indicate mitigation, though paper shows inconsistency.

### First 3 Experiments
1. **Calibration sweep:** Train FL with various τ (e.g., 0.2, 0.33, 1, 3, 5) and fixed β. Log accuracy, ECE, sECE on global test set. Confirm large ECE shift with minimal accuracy change.
2. **Stealth check:** Compute per‑round cosine similarity between malicious and benign updates, and representation similarity (logit cosine, penultimate CKA). Validate similarity ≥0.85 for τ in [0.2,5].
3. **Defense test:** Run TSA under robust aggregators (FLTrust, MultiKrum, FoolsGold) and apply post‑hoc calibration with varying calibration set sizes. Record sECE to verify attack persists.

## Open Questions the Paper Calls Out
1. How can we design calibration-aware auditing and monitoring mechanisms for FL that detect temperature scaling attacks without relying on held-out validation data?
2. Can weaker adversaries that only manipulate data or labels (without modifying local training code) induce calibration distortions comparable to temperature scaling attacks?
3. How can temperature scaling be extended to class-targeted calibration attacks, distorting confidence for specific classes while preserving others?
4. How does temperature scaling affect calibration integrity in downstream tasks with fine-grained confidence consumption, such as object detection (per-box confidence) or language generation (token-level probabilities)?

## Limitations
- Exact β values for each benchmark and precise τ integration details are only in the appendix, creating replication ambiguity.
- Evaluation limited to small models/datasets (MNIST, CIFAR, WikiText2); scalability to larger architectures (e.g., ViTs) untested.
- Attack effectiveness at very low attacker ratios (<10%) and extreme non‑IID settings (Dirichlet α≪1) remains unclear, leaving gaps in the real‑world threat model.
