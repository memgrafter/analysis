# GPU-Accelerated INT8 Quantization for KV Cache Compression in Large Language Models

## Quick Facts
* **arXiv ID:** 2601.04719
* **Source URL:** https://arxiv.org/abs/2601.04719
* **Reference count:** 10
* **Primary result:** GPU-accelerated INT8 quantization of KV cache achieves 4× memory reduction with up to 1,694× speedup over CPU baselines and negligible accuracy impact (reconstruction error <0.004, attention error <0.1).

## Executive Summary
The KV cache in large language models creates a significant memory bottleneck during inference. This work implements GPU-accelerated INT8 quantization for KV cache compression using per-channel scaling. Four CUDA kernel variants (naive, tiled, coarsened, vectorized) were developed and benchmarked. The vectorized kernel achieved up to 1,694× speedup over CPU baselines for workloads up to 1 billion elements. Quantization provides a 4× memory reduction. Reconstruction error was consistently below 0.004 and attention score error remained under 0.1 even for 8K-dimensional heads. For realistic LLM workloads, the total quantization overhead was only 6–58 ms, demonstrating a practical solution with negligible impact on model behavior.

## Method Summary
The method applies per-channel INT8 quantization to FP32 KV cache matrices (shape T×D). For each column (head dimension), a scale factor is computed as half the maximum absolute value divided by 127, enabling use of the full INT8 range. Four CUDA kernel variants implement the quantization: naive (element-wise), tiled (shared memory), coarsened (thread coarsening), and vectorized (float4/char4 vector operations). Correctness is validated against a CPU baseline. Performance is benchmarked across eight configurations varying sequence length (T) and head dimension (D). Reconstruction error and attention score error are measured to assess accuracy impact. Overhead is evaluated in the context of LLM inference.

## Key Results
* 4× memory reduction from FP32 to INT8 storage.
* Vectorized kernel achieves up to 1,694× speedup over CPU for large workloads (T=131,072, D=8,192).
* Reconstruction error ≤ 0.00394 (theoretical bound) and mean attention error ≤ 0.095 even for D=8,192.
* Quantization overhead for realistic LLM workloads is only 6–58 ms.

## Why This Works (Mechanism)
### Mechanism 1
* **Claim:** INT8 quantization reduces KV cache memory by 4× compared to FP32.
* **Mechanism:** Each element is stored in 8 bits instead of 32 bits, directly quartering the storage requirement.
* **Core assumption:** The model’s attention mechanism can tolerate the quantization error without significant degradation in output quality.
* **Evidence anchors:** Abstract: “achieving 4× memory reduction with minimal accuracy degradation”; Section 4.3: error bounded by s/2; neighboring papers (KIVI [7], KVQuant [8]) pursue similar quantization.
* **Break condition:** If reconstruction error propagates to alter softmax outputs, perplexity or accuracy may drop.

### Mechanism 2
* **Claim:** Vectorized memory access (float4/char4) maximizes memory bandwidth utilization, yielding orders-of-magnitude speedup.
* **Mechanism:** Loading/storing 4 elements per memory transaction reduces instruction count, increasing effective throughput for a memory-bound operation.
* **Core assumption:** GPU memory subsystem handles wider transactions efficiently and data layout allows contiguous vector loads.
* **Evidence anchors:** Section 5.3.4 describes vector load/store instructions; Section 7.4 explains reduced memory transactions.
* **Break condition:** If D is not a multiple of 4 and edge cases are unhandled, performance degrades or out-of-bounds accesses occur.

### Mechanism 3
* **Claim:** Per-channel scaling preserves precision across dimensions by adapting to each column’s value range, keeping errors low.
* **Mechanism:** Each dimension d gets scale s_d = max_t |K[t,d]|/127, utilizing full INT8 range per column independently.
* **Core assumption:** Value ranges vary across dimensions; a global scale wastes precision on some.
* **Evidence anchors:** Section 4.2 defines per-channel quantization; Section 7.2 shows max error constant at 0.00394; Section 7.3 shows mean attention error only 0.095 for D=8192; SmoothQuant [6] uses similar scaling.
* **Break condition:** Outliers inflate scale, degrading effective precision for most values; storing scales adds D floats overhead (negligible typically).

## Architecture Onboarding
* **Component map:**  
  FP32 KV cache matrix (T×D) -> Scale computation module (D scales) -> Quantization kernels (4 variants) -> INT8 KV cache + scales -> Dequantization on-read for attention -> Attention computation
* **Critical path:** Quantization kernel execution for long sequences; scale computation once per cache fill; incremental overhead for new rows during token generation.
* **Design tradeoffs:**  
  Memory reduction (4×) vs compute overhead (6–58 ms); kernel simplicity (naive) vs performance (vectorized); per-channel precision vs scale storage (D floats); accuracy vs bit-width (INT8 vs lower).
* **Failure signatures:**  
  Reconstruction error >0.004 suggests incorrect scale computation/rounding; attention error >0.1 indicates inappropriate scaling; vectorized kernel no speedup implies D not multiple of 4 or misaligned accesses; crashes/NaNs from division by zero (all-zero column) – clamp scale to epsilon.
* **First 3 experiments:**  
  1. **Correctness validation:** Run all kernel variants on small deterministic matrix (e.g., all ones) vs CPU reference; check element-wise equality within ±1 INT8 tolerance.  
  2. **Performance profiling:** Benchmark vectorized kernel on large workload (T=131072, D=8192); verify ≥1000× speedup over CPU and sublinear scaling.  
  3. **Error characterization:** Measure reconstruction/attention errors across D=128–8192; confirm within bounds (0.004, 0.1); test with outliers for error sensitivity.

## Limitations
* Kernel launch parameters (block/grid sizes) undocumented; performance may vary with tuning.
* Edge-case handling for vectorized kernel when D not multiple of 4 unspecified; potential out-of-bounds or speedup loss.
* Experiments likely on LLaMA-style decoders; generalizability to other architectures unknown.
* Overhead measurements may omit dequantization/synchronization costs in full pipeline.
* Per-channel scale storage overhead for many layers unquantified; could affect effective memory reduction in extreme memory-constrained scenarios.

## Confidence
* **Memory reduction (4×):** High – inherent to INT8 representation.
* **Speedup (up to 1694×):** Medium – depends on hardware, kernel tuning, problem size; some parameters missing.
* **Error bounds (reconstruction <0.004, attention <0.1):** Medium – validated on limited models; outlier sensitivity not fully explored.
* **Overhead (6–58 ms):** Medium – based on specific configurations; integration costs beyond quantization not deeply analyzed.
