## Warm Starting State-Space Models with Automata Learning
### Quick Facts
- arXiv ID: 2603.05694  
- Source URL: https://arxiv.org/abs/2603.05694  
- Reference count: 40  
- Primary result: Symbolic warm-starting of SSMs with learned automata accelerates convergence 2–5× and improves accuracy on infinite-memory tasks, while gradient-trained SSMs alone require far more samples and fail to recover discrete state structure.

### Executive Summary
The paper establishes an exact equivalence between finite-state Moore machines and linear state-space models (SSMs), enabling direct initialization of SSM parameters from a learned automaton. This warm-start drastically reduces sample complexity on regular language benchmarks (SYNTCOMP) and speeds up convergence on dynamic arbitration tasks that require unbounded memory. However, the initialization inflates model dimensionality, causing memory issues for large alphabets or state spaces, and pure gradient learning fails to recover the underlying discrete state partition.

### Method Summary
The authors first prove that any deterministic Moore machine can be realized as an SSM by encoding states as one-hot vectors and constructing matrices A (identity), B (differences between target and source state one-hots for each state-input pair), and C (output one-hots). This mapping uses a Kronecker product over the state-input space to linearize transitions. In practice, one learns a Moore machine (e.g., via L* or RPNI) from a modest number of traces, then uses it to initialize an SSM with small Gaussian noise. The SSM is trained on a richer task that extends the base policy with an additive history-dependent constraint. Experiments compare warm-started SSMs against random-initialized SSMs and classical automata learners on sample efficiency, convergence speed, and state-structure recovery.

### Key Results
- SSMs require millions of samples to learn regular languages that L* and RPNI acquire with thousands; perfect emulation rates are 33.3% for SSMs versus 77.3% (L*) and 56.0% (RPNI).  
- Warm-started SSMs converge 2–5× faster (243 epochs earlier, p=0.0122) and achieve higher accuracy on dynamic arbitration (e.g., 100% vs 60% for large alphabets).  
- Discretely trained SSMs exhibit poor state separation (ARI=0.414, NMI=0.600), confirming they do not recover the underlying automaton’s state partition.

### Why This Works (Mechanism)
The paper provides three key insights:

1. **Exact Moore-to-SSM Realization**: A finite Moore machine maps to an SSM by representing the state as a one-hot vector and setting A=I, B columns to e<sub>T(i,j)</sub> - e<sub>i</sub>, and C rows to output one-hots. This decouples state updates from input, making dynamics linear in the Kronecker-encoded input.
2. **Sample Inefficiency of Pure Gradient SSMs**: End-to-end training optimizes only trace-level accuracy and lacks an inductive bias for discrete state separation. The continuous state space collapses distinct symbolic states, so SSMs need many samples to approximate the input-output function but cannot recover the automaton.
3. **Warm-Start Inductive Bias**: Initializing with Moore machine matrices gives a strong starting point: the base policy is already implemented, and gradient descent only adjusts parameters needed to handle the additional memory-intensive constraint (e.g., tracking deviation history). This yields faster convergence and better accuracy, barring memory limits.

### Foundational Learning
- **Concept: Deterministic Finite Automaton (DFA) / Moore Machine**  
  Why needed: The target systems have a finite-state core policy; understanding states, transitions, and outputs is essential to grasp the symbolic structure being warm-started.  
  Quick check: Given a Moore machine’s transition table, can you write its state update function F(s<sub>i</sub>, σ<sub>j</sub>) and output function G(s<sub>i</sub>)?  

- **Concept: State-Space Model (SSM) Linear Dynamics**  
  Why needed: The neural architecture is an SSM; understanding x(t+1)=Ax(t)+Bµ(t), y(t)=Cx(t) is necessary to see how symbolic matrices are injected.  
  Quick check: If x(t) is one-hot for state s<sub>i</sub> and B has column (i,j)=e<sub>k</sub> - e<sub>i</sub>, what does x(t+1)=x(t)+Bµ(t) compute when input symbol σ<sub>j</sub> is active?  

- **Concept: Kronecker Product Encoding for Joint State-Input**  
  Why needed: The proof uses µ(t) ∈ ℝ<sup>|S|·|Σ|</sup> as a one-hot over (state, input) pairs to make Moore’s joint transition linear in µ(t).  
  Quick check: Why can’t we use a simple one-hot for the input symbol alone? What does the Kronecker product buy us?

### Architecture Onboarding
**Component map** (plain text)  
Moore machine → Algorithm 1 → SSM matrices (A=I, B=e<sub>T(i,j)</sub>-e<sub>i</sub>, C=output one-hots) → SSM layer with tanh nonlinearity → readout → predictions.

**Critical path**  
1. Learn/obtain a Moore machine for the base policy (e.g., via L* or RPNI on clean traces).  
2. Construct A, B, C using Algorithm 1; add small Gaussian noise ε to zero entries.  
3. Initialize SSM layer with these matrices; keep all parameters trainable.  
4. Train on extended task traces (e.g., dynamic arbitration) with Adam (lr=0.001), max 1000 epochs, binary cross-entropy loss.

**Design tradeoffs**  
- Memory: B scales as O(|S|²·|Σ|); large alphabets/states may cause OOM. Mitigation: state merging or spectral compression (future work).  
- Noise ε: Too small → optimization may not escape symbolic basin; too large → washes inductive bias. Typical ε≈0.1.  
- Input embedding: Warm-start uses identity (no embedding) to preserve one-hot; random init often uses ReLU+linear. Trade-off between symbolic fidelity and flexibility for noisy/continuous inputs.

**Failure signatures**  
- OOM during B allocation → reduce problem size or compress state space.  
- Loss plateaus at ~50% → verify µ = state⊗input encoding; incorrect Kronecker implementation leads to ineffective signal.  
- Perfect base accuracy before training → warm-start misapplied to unchanged task (no deviation handling needed).

**First 3 experiments**  
1. Verify Lemma 1: Build a 2-state, 2-input Moore machine; use Algorithm 1 to get A,B,C; simulate an SSM step and confirm output matches the Moore table.  
2. Sample complexity comparison: On the `arbiter` SYNTCOMP benchmark, train a random-init SSM and a warm-start SSM; record epochs to reach ≥90% test trace accuracy.  
3. Memory scaling stress test: For dynamic arbitration tasks, increase parameter n (2→6); log GPU memory for B matrix and note the largest n before OOM failure.

### Open Questions the Paper Calls Out
1. Can spectral learning reduce SSM dimensionality while preserving functionality, mitigating memory overhead?  
2. What theoretical mechanisms explain the sample complexity improvement from symbolic warm-starting and what are necessary/sufficient conditions?  
3. How robust is warm-starting to imperfections in the symbolic model (e.g., noisy or incomplete automata learning)?  
4. Do benefits generalize beyond linear SSMs and SYNTCOMP arbitration tasks to other architectures (LSTMs, Transformers, Mamba) and domains?  
5. Can efficiency gains be achieved without increasing model dimensionality, e.g., via losses that encourage discrete state representations?

### Limitations
- Warm-start memory overhead can cause failures on large alphabets/state spaces (B matrix size O(|S|²·|Σ|)).  
- Approach relies on a finite-state base policy; for systems without such a core, warm-started SSMs only approximate.  
- Symbolic initialization requires a learned Moore machine; imperfect automata learning may degrade benefits (not evaluated).

### Confidence
- **Exact Moore-to-SSM equivalence**: High (constructive proof for finite machines).  
- **SSMs are sample-inefficient vs automata learning**: High (consistent empirical results).  
- **Warm-start accelerates convergence and improves accuracy**: Medium-High (statistically significant on tested tasks, but limited by memory constraints and task assumptions).  
- **Poor state structure recovery by SSMs**: High (low ARI/NMI across experiments).
