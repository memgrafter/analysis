# BEACONS: Bounded-Error, Algebraically-Composable Neural Solvers for Partial Differential Equations

## Quick Facts
- **arXiv ID:** 2602.14853  
- **Source URL:** https://arxiv.org/abs/2602.14853  
- **Reference count:** 40  
- **Primary result:** Provably bounded L∞ errors for neural PDE solvers via method-of-characteristics smoothness analysis and algebraic composition; BEACONS outperforms PINNs on Burgers’ (L∞ 0.986979 vs 1.208962) and Euler (0.198093 vs 0.546258), with all errors below theoretical bounds.

## Executive Summary
BEACONS introduces a framework for constructing neural partial differential equation (PDE) solvers with formal error guarantees, overcoming the inability of conventional neural networks to generalize beyond the convex hull of their training data. It combines the method of characteristics—to determine solution smoothness a priori—with approximation theory for shallow networks and an algebraic composition strategy to suppress errors in discontinuous regions. An automated theorem prover generates machine-checkable certificates of worst‑case L∞ error, while a code generator produces verified C implementations. Applied to hyperbolic systems (linear advection, Burgers’, Euler) in 1D/2D, BEACONS networks achieve significantly lower L∞ and conservation errors than equivalent PINN baselines, and all observed empirical errors remain below their certified bounds. The open‑source framework integrates with the GKEYLL simulation toolkit.

## Method Summary
The BEACONS workflow begins by specifying the PDE, initial/boundary data, and target architecture in a Racket‑based domain‑specific language (DSL). An automated theorem prover analyzes the PDE via the method of characteristics to compute smoothness classes (order n) for the solution, even in extrapolation regimes. It then proves worst‑case L∞ bounds for shallow networks using Mhaskar‑Poggio theory and searches for algebraic decompositions (u = f ∘ g) that minimize the composed error bound, selecting smooth functions f with controllably small Lipschitz constants to suppress errors from the discontinuous component g. A code generator produces a C program that (a) generates training data from verified or high‑resolution numerical solvers (only early time frames), (b) trains the BEACONS network layer‑by‑layer (full‑batch gradient descent), and (c) evaluates L∞, L2, and conservation metrics against reference solutions. Finally, the theorem prover issues a machine‑checkable certificate confirming that observed errors stay within the certified bound.

## Key Results
- BEACONS achieves provably bounded L∞ errors in extrapolatory regimes, unlike conventional PINNs.
- On 1D Burgers’ (top‑hat, 8‑layer, 128 neurons), L∞ error: BEACONS 0.986979 vs NN 1.208962.
- On 2D Euler quadrants (8‑layer), L∞ error: BEACONS 0.198093 vs NN 0.546258.
- All observed BEACONS errors fall below their worst‑case theoretical bounds.
- Framework is open‑source and integrated with GKEYLL.

## Why This Works (Mechanism)
BEACONS relies on three synergistic mechanisms:

1. **Extrapolatory error bounds via method of characteristics**  
   For smooth PDE solutions, the method of characteristics determines the solution’s smoothness class (order n) from the initial data and flux Jacobian, even outside the training domain. Combined with Mhaskar’s approximation theory (error O(N^{−n/d}) for shallow networks), this yields provable L∞ bounds for hyperbolic PDEs up to the blow‑up time t∞ where characteristics intersect.

2. **Error suppression via algebraic composition**  
   Discontinuous solutions are expressed as a composition u = f ∘ g, where g approximates the discontinuous part and f is smooth with a small Lipschitz constant L. The composition error satisfies ∥f∘g − f̂∘ĝ̂∥∞ ≤ e_f + L·e_g. By choosing f to make L arbitrarily small (e.g., f(x)=arcsinh(x/C)), the large error e_g from approximating g is suppressed, enabling deeper networks to achieve tighter overall bounds.

3. **Machine‑checkable certificates**  
   A Racket‑based theorem prover verifies the smoothness analysis and composition bounds using strictly correctness‑preserving algebraic transformations (respecting IEEE‑754). It generates formal certificates and drives code generation, ensuring that the implemented solver adheres to the proven error guarantees.

## Foundational Learning
- **Method of characteristics for hyperbolic PDEs**  
  Traces characteristic curves from initial data to determine where/when solutions become non‑smooth. *Why needed*: Provides a priori smoothness exponent n for Mhaskar bounds, even in extrapolation. *Quick check*: For Burgers’ u_t + u u_x = 0 with convex flux, shock time t∞ = −1/min(∂_x u0) if ∂_x u0 < 0 somewhere; smoothness drops at t∞.

- **Mhaskar‑Poggio approximation theory**  
  For shallow networks with C∞, non‑polynomial activation, approximating a C^n function yields L∞ error O(N^{−n/d}). *Why needed*: Quantifies approximation error for smooth PDE components. *Quick check*: With ReLU (piecewise linear), the bound loses explicit dependence on n; tanh retains O(N^{−n/d}).

- **Lipschitz continuity and modulus of continuity**  
  If f is L‑Lipschitz on the range of g, then ∥f∘g − f∘ĝ∥∞ ≤ L·∥g − ĝ∥∞. *Why needed*: Allows error suppression by choosing f with arbitrarily small L. *Quick check*: For f(x)=arcsinh(x/C), L = 1/C; increasing C reduces L.

## Architecture Onboarding
- **Component map**: DSL (PDE spec) → Theorem Prover (smoothness analysis, decomposition search) → Code Generator (C code) → Training Loop (per‑layer full‑batch GD) → Validation (error metrics, prover certificate). The prover also outputs certified worst‑case L∞ bound.

- **Critical path**:
  1. Specify PDE, initial/boundary conditions, and target depth/width in Racket DSL.
  2. Run theorem prover: compute smoothness classes, prove bound for architecture, select decomposition (f functions).
  3. Generate C code; execute to produce training data (early frames from verified solver) and train networks.
  4. Validate: compute L∞, L2, conservation errors; confirm observed ≤ certified bound.

- **Design tradeoffs**:
  - Depth vs width: Deeper networks better suppress discontinuities but may increase L2 diffusion.
  - Candidate f functions: Non‑linear functions (e.g., arcsinh) needed; balance Lipschitz reduction with coverage of g’s range.
  - Training data horizon: Only early frames used; extrapolation quality depends on stability of characteristics beyond horizon.

- **Failure signatures**:
  - Observed L∞ > certified bound → decomposition invalid or proof assumption violated.
  - Large conservation errors → network missed conservative structure.
  - Wave speed misprediction (e.g., 2D Euler) → insufficient depth or poor decomposition.
  - Unprovable non‑smooth bounds (e.g., 2D Burgers’ disk) → asymptotic smoothing prevents finite‑time bound.

- **First 3 experiments**:
  1. 1D linear advection Riemann: Verify basic extrapolation; check shock overshoot, advection speed, conservation.
  2. 1D Burgers’ top‑hat: Test shock + rarefaction; verify both wave speeds; compare 8‑layer vs 6‑layer BEACONS.
  3. 2D Euler quadrants: Test multi‑wave interaction; check qualitative shape preservation (no pointy artifacts); verify L∞ error ≤ mixed bound (1.259921 for 8‑layer).

## Open Questions the Paper Calls Out
- **Open Question 1**: How can BEACONS be extended to provide fully unconditionally verified bounds for systems like the Euler equations, where current proofs rely on an unverified underlying solver? The authors note a formally‑verified Euler solver is needed to eliminate conditional assumptions.
- **Open Question 2**: Why does the automated prover fail to prove non‑smooth error bounds for the 2D inviscid Burgers’ disk problem, and can the methodology be generalized to handle asymptotically smoothing cases automatically? The prover runs 221 steps before concluding no bound can be proven.
- **Open Question 3**: What is the optimal algorithmic strategy for decomposing a discontinuous PDE solution into a composition of smooth functions to minimize the L∞ error bound? The paper trials ad‑hoc functions (arcsinh/sinh) but offers no general principle.
- **Open Question 4**: Do the favorable extrapolation and bounded‑error properties of BEACONS extend to three or more spatial dimensions? All experiments are 1D/2D; the theory’s O(N^{−n/d}) bound and characteristic geometry may degrade in higher dimensions.

## Limitations
- Exact command‑line workflows, random seeds, and solver integration details are unspecified, risking non‑identical training data and network initialization.
- For 2D Euler, training data uses an *unverified* solver; any reference error invalidates the bound comparison.
- The automated decomposition selection (e.g., arcsinh) is a black box; its robustness to alternative choices is unclear.
- Asymptotic smoothing limits certification for problems like 2D Burgers’ (no finite‑time bound).
