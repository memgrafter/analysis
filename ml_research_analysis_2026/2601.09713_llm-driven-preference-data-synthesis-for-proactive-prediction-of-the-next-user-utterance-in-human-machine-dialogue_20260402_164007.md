# LLM-Driven Preference Data Synthesis for Proactive Prediction of the Next User Utterance in Human-Machine Dialogue

## Quick Facts

- **arXiv ID:** 2601.09713  
- **Source URL:** https://arxiv.org/abs/2601.09713  
- **Reference count:** 40  
- **Primary result:** ProUtt fine-tuned on Qwen3-8B consistently outperforms commercial APIs and other baselines, achieving relative gains of 4.88% to 5.12% under LLM-judge pointwise evaluation across four benchmark datasets.

## Executive Summary

This paper tackles the challenge of proactively predicting a user's next utterance in human-machine dialogue. Large commercial LLMs raise privacy concerns and local deployment is expensive, while existing user simulators fail to capture evolving user intents. The authors propose ProUtt, an LLM-driven preference data synthesis method that converts dialogue history into a hierarchical intent tree and models next-utterance reasoning through exploitation (refining existing topics) and exploration (introducing new topics). Preference pairs are constructed by revising or perturbing intent paths using future-turn information, avoiding ground-truth leakage. Experiments on four datasets (LMSYS, ShareGPT, WildChat, CrossWOZ) show that a Qwen3-8B model fine-tuned on ProUtt data surpasses commercial APIs, user simulators, and other synthesis methods. The code and synthesized datasets are publicly released.

## Method Summary

ProUtt synthesizes preference data for training small task-specific models. First, it prompts an LLM to extract a hierarchical user intent tree from multi-turn dialogue, representing high-level goals and subgoals. Second, conditioned on the tree and the predicted sentence type, it generates candidate reasoning paths from exploitation and exploration perspectives, each verbalized as a predicted user utterance. Third, it scores candidates against the ground truth using embedding similarity; based on thresholds, it constructs preference pairs: high-scoring reasoning becomes preferred and is perturbed with a future intent path to create the rejected example; low-scoring reasoning becomes rejected and is revised with the immediate next path to create the preferred example. This avoids leakage because future paths are not the gold answer. The resulting dataset (dialogue context, intent tree, chosen/rejected reasoning and utterances) is used to first supervise fine-tune a backbone LLM (e.g., Qwen3-8B) via SFT and then perform preference alignment (DPO/ORPO/SimPO).

## Key Results

- ProUtt (Qwen3-8B) consistently outperforms commercial API solutions, user simulators, and other synthesis methods on four benchmark datasets, with relative gains of 4.88% to 5.12% under LLM-as-a-judge pointwise evaluation.
- Ablation studies confirm the contribution of each core component, and the method remains robust across different LLM backbones used for synthesis.
- The code and two synthesized datasets (LMSYS-ProUtt-10K, CrossWOZ-ProUtt-5K) are publicly released.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Converting dialogue history into a hierarchical intent tree explicitly models the user's evolving semantic focus and goal structure, providing a structural prior for reasoning about the next utterance.
- **Mechanism:** An LLM extracts a goal–subgoal tree from multi-turn dialogue, where top-level nodes represent high-level topics and child nodes specify attributes. This tree captures dependencies and progression of user intents.
- **Core assumption:** User intent in dialogue follows a decomposable, hierarchical structure that can be represented as a tree and is predictive of future intent shifts.
- **Evidence anchors:** Abstract: "ProUtt converts dialogue history into a hierarchical intent tree..."; Section III.B discusses how the tree captures semantic focus shifts; Ablation (Table III) shows performance drops when removing the tree.
- **Break condition:** If the tree extraction fails to capture coherent topic-attribute relationships (e.g., due to ambiguity), downstream reasoning lacks a reliable scaffold. Performance degrades especially on open-domain datasets where intent is implicit.

### Mechanism 2
- **Claim:** Predicting the next intent path from both exploitation (refining existing topics) and exploration (introducing new topics) perspectives generates diverse, plausible candidate trajectories covering different ways a user might advance the conversation.
- **Mechanism:** Conditioned on the intent tree and sentence type, the LLM proposes Q candidate next paths from exploitation (extending current topic) and exploration (new but related topics), then verbalizes each into an utterance.
- **Core assumption:** Human information-seeking alternates between exploiting known sources and exploring new ones (information foraging theory); this pattern applies to intent evolution in dialogue.
- **Evidence anchors:** Abstract mentions dual perspectives; Section III.D.1 cites information foraging; Section V.F shows performance improves with up to 4 candidates (2 per perspective) but saturates or degrades beyond, indicating diversity matters.
- **Break condition:** If one perspective dominates or prompts fail to elicit distinct perspectives, candidate diversity collapses, reducing preference pair quality.

### Mechanism 3
- **Claim:** Constructing preference pairs by revising or perturbing intent paths using *future-turn* intent information (beyond the immediate next turn) avoids ground-truth leakage and teaches the model to distinguish intent-level quality rather than surface form.
- **Mechanism:** If a candidate's similarity to gold is high (≥τ_high), its reasoning becomes preferred and a non-preferred example is created by replacing it with a path from a later turn (t+ε, ε≥2). If similarity is low (≤τ_low), the candidate is non-preferred and is revised with the immediate next path (t+1) to create the preferred example. This ensures negatives are plausible but incorrect at the intent level.
- **Core assumption:** Robust preference learning requires negative examples that are plausible but semantically incorrect; using future paths provides such negatives without exposing the gold utterance directly.
- **Evidence anchors:** Abstract states avoidance of leakage; Section III.A explains the revision/perturbation with future intent; Ablation "w/o Future-Path Negatives" (Table V-A) shows significant performance drop.
- **Break condition:** If future paths are semantically identical to the next path, or if revision introduces incoherence, the preference signal becomes noisy. Threshold sensitivity (Table VII) indicates inappropriate τ_high/τ_low blurs the distinction.

## Foundational Learning

- **Preference Learning (DPO/ORPO/SimPO)**  
  *Why needed:* ProUtt synthesizes (chosen, rejected) reasoning trajectory pairs; alignment algorithms like DPO use these to update the policy directly without a separate reward model.  
  *Quick check:* Given a preference pair (r⁺, Ū⁺) and (r⁻, Ū⁻), what does the DPO objective optimize for? (Answer: It maximizes the log-likelihood of the chosen over rejected, conditioned on the context, typically via a logistic loss on the reward model logits.)

- **Hierarchical Intent Modeling**  
  *Why needed:* The intent tree is the core scaffold for reasoning; understanding goal decomposition (e.g., "Plan Trip" → "Select Attraction" → "Check Hours") is essential to follow ProUtt's path prediction.  
  *Quick check:* In the intent tree example, why is "Restaurant" a sibling of "Attraction" rather than a child? (Answer: Both are top-level subtopics under the same overarching goal like "Plan Trip", indicating they are parallel branches.)

- **Information Foraging Theory**  
  *Why needed:* It theoretically justifies the exploitation/exploration dichotomy: exploitation deepens current topic exploration, exploration broadens to adjacent topics, mirroring user decisions in dialogues.  
  *Quick check:* Give an example of exploitation vs. exploration in a restaurant-planning dialogue. (Example: exploitation: "What are the hours of that Italian restaurant?" (refining existing topic); exploration: "Are there any Thai restaurants nearby?" (introducing new topic).)

## Architecture Onboarding

**Component map:**  
Intent Tree Builder -> Sentence Type Reasoner -> Dual-Path Reasoner -> Preference Constructor -> Trainer

**Critical path:**  
Dialogue -> Intent Tree -> Sentence Type -> Dual-Path Candidates -> Judge Scoring -> Preference Labeling -> Pair Assembly -> Training (SFT then Alignment)

**Design tradeoffs:**  
- *Candidate quantity (Q):* More candidates increase diversity but add noise and cost; paper finds Q=2 (per perspective) optimal.  
- *Thresholds (τ_high, τ_low):* Wider gap creates cleaner preference boundaries but may exclude borderline examples; narrower gap increases noise.  
- *LLM backbone for synthesis:* Stronger synthesis LLM yields better data, but method is robust across models (Table IV).

**Failure signatures:**  
- Low LLM-human agreement in pairwise evaluation (<70%).  
- Ablation of intent tree causes major drop on open-domain datasets.  
- Embedding similarity drops if model overfits to exact phrasing (see CrossWOZ discussion).

**First 3 experiments:**  
1. Ablation - Remove Intent Tree: Replace tree with raw dialogue context in prompts; measure performance drop (Table III).  
2. Sensitivity - Vary τ_high and τ_low: Test threshold pairs (0.7,0.4), (0.8,0.3), (0.9,0.2), (1.0,0.1); observe DPO performance (Table VII).  
3. Backbone Robustness - Swap Synthesis LLM: Use Qwen3-Plus, DeepSeek-V3.2-Exp, GLM-4.5-Air instead of Doubao-1.5-Pro; evaluate final model (Table IV).

## Open Questions the Paper Calls Out

1. **Cross-domain generalization**  
   - *Question:* How can ProUtt's intent tree be generalized to improve cross-domain transfer?  
   - *Basis in paper:* Conclusion notes higher win rates on training vs unseen datasets (LMSYS/CrossWOZ vs ShareGPT/WildChat).  
   - *Why unresolved:* No analysis of why tree modeling fails to transfer; unclear if due to tree construction, exploitation/exploration balance, or data diversity.  
   - *What evidence would resolve it:* Error analysis comparing tree coverage, topic diversity, reasoning alignment across domains; domain-adversarial training or data augmentation experiments.

2. **Graph-based intent representation**  
   - *Question:* Would replacing the hierarchical tree with a graph capture richer relational patterns and further improve performance?  
   - *Basis in paper:* Conclusion explicitly suggests exploring graph-based representations.  
   - *Why unresolved:* No empirical comparison; added complexity may yield gains or noise.  
   - *What evidence would resolve it:* Implement a graph variant, construct intent graphs, and test against tree-based ProUtt on benchmarks.

3. **Hyperparameter interactions**  
   - *Question:* What are optimal values for τ_high, τ_low, and Q, and how do they interact with alignment objective (DPO/ORPO/SimPO) and model scale?  
   - *Basis in paper:* Sensitivity analyses show non-monotonic, dataset-dependent effects.  
   - *Why unresolved:* No principled method for setting hyperparameters; interactions with alignment losses and model sizes not disentangled.  
   - *What evidence would resolve it:* Large-scale hyperparameter sweep across multiple model sizes and alignment methods, with separate metrics for reasoning fidelity and output quality.

4. **Multi-session user history**  
   - *Question:* Can incorporating multi-turn user-specific interaction history (beyond a single session) improve personalization and long-term modeling?  
   - *Basis in paper:* Conclusion notes potential of user-specific preference signals if multiple historical dialogues are available.  
   - *Why unresolved:* ProUtt processes each dialogue independently; no mechanism to aggregate or condition on past sessions.  
   - *What evidence would resolve it:* Extend ProUtt to condition intent tree construction on a user's dialogue history (e.g., prepend a summary), evaluate on datasets with user IDs or simulate multi-session users.

5. **Hybrid synthesis LLMs**  
   - *Question:* How does synthesis LLM quality affect trajectory diversity/validity, and can hybrid synthesis (mixing multiple LLMs) yield higher-quality data?  
   - *Basis in paper:* Appendix Table IV shows minor performance fluctuations when swapping synthesis LLMs; paper hints at hybrid as promising.  
   - *Why unresolved:* No analysis of per-LLM contributions (e.g., stylistic vs structural correctness) or how to combine them.  
   - *What evidence would resolve it:* Analyze trajectory characteristics per LLM; design hybrid strategies (ensemble voting, cross-LLM perturbation) and compare downstream performance against single-LLM baselines.

## Limitations

- Undisclosed implementation details (prompt templates, tree serialization format, judge configuration, fine‑tuning hyperparameters) hinder exact replication.
- The method relies on a high‑quality synthesis LLM (Doubao‑1.5‑Pro), which may be computationally expensive and could limit applicability when using weaker or open‑source models.
- Fixed confidence thresholds (τ_high=0.8, τ_low=0.3) are used universally, but sensitivity analysis shows they may not be optimal across all datasets.
