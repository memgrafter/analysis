# Agent psychometrics: Task-level performance prediction in agentic coding benchmarks

## Quick Facts
- **ArXiv ID**: 2604.00594
- **Source URL**: https://arxiv.org/abs/2604.00594
- **Reference count**: 40
- **Primary result**: Extending IRT with task features and additive LLM-scaffold decomposition enables accurate task-level success prediction, difficulty calibration, and cross-benchmark agent evaluation.

## Executive Summary
Predicting the success of coding agents on individual tasks within multi-step benchmarks is challenging due to high evaluation costs and the obscuring effect of aggregate scores. This paper augments Item Response Theory (IRT) with rich task features (issue statements, repository state, tests, solutions) and decomposes agent ability into additive LLM and scaffold components. The resulting framework supports cross-benchmark aggregation and accurate prediction for unseen tasks and novel LLM-scaffold combinations. Empirical results show substantial improvements in difficulty prediction and robust generalization, enabling cheap task difficulty calibration and adaptive selection for efficient agent evaluation.

## Method Summary
The method extends standard IRT (1PL: success probability = σ(θ − β)) by incorporating auxiliary information. For tasks, the authors first fit a standard IRT to obtain difficulty parameters β. Then they extract heterogeneous feature vectors (embeddings, LLM-as-a-judge scores, environment metrics) and train a ridge regression to predict β from these features. For agents, they parameterize ability as the sum of separate LLM and scaffold parameters (θ_agent = θ_LLM + θ_scaffold) and train across multiple benchmarks with shared LLM and scaffold terms. At inference, for a new task the predicted β is used; for a new agent with previously seen components, the summed ability is used; for a new benchmark the same feature and ability estimates are applied. The approach is evaluated by holding out tasks, agents, or entire benchmarks and measuring AUC-ROC on response prediction.

## Key Results
- Task features substantially improve difficulty prediction on SWE-bench Verified: AUC-ROC rises from 0.718 (problem-statement-only) to 0.842 (combined features).
- The additive LLM-scaffold decomposition matches standard IRT accuracy (AUC 0.939 vs 0.941) while enabling multi-benchmark training and aggregation.
- Predictors achieve high AUC (0.936) on held-out agents and generalize to new benchmarks (e.g., SWE-bench Pro AUC 0.696 vs baseline 0.571).

## Why This Works (Mechanism)
### Mechanism 1  
**Claim:** Task features (issue statements, repository state, tests, solutions) improve prediction of task difficulty beyond the problem statement alone.  
**Mechanism:** Extract heterogeneous feature vectors (embeddings, LLM-as-a-judge scores, environment metrics) from each task; fit ridge regression to predict frozen IRT difficulty parameters.  
**Core assumption:** Agentic task artifacts encode latent difficulty signals not present in the textual problem description.  
**Evidence:** On SWE-bench Verified, AUC-ROC rises from 0.718 (baseline) to 0.842 (combined features). Feature ablation (Table 3) shows incremental gains when adding repository state, tests, and solution to prompt-based features.  
**Break condition:** Feature ablation shows no improvement over problem‑statement‑only features; ridge regression coefficients near zero for non‑text features.

### Mechanism 2  
**Claim:** Agent ability decomposes additively into LLM and scaffold components, enabling multi‑benchmark aggregation despite sparse agent overlap.  
**Mechanism:** Parameterize agent ability as θ_agent = θ_LLM + θ_scaffold; train IRT across benchmarks with shared LLM/scaffold parameters.  
**Core assumption:** LLM and scaffold contributions are independent and additive (no interaction terms).  
**Evidence:** IRT with agent features matches standard IRT AUC (0.939 vs 0.941); Figure 2 shows strong correlation (r = 0.974) between fixed‑scaffold agent abilities and decomposed LLM abilities.  
**Break condition:** Functional form ablation shows additive outperforms max/min/product; multi‑benchmark training fails when benchmarks use incompatible scaffold definitions.

### Mechanism 3  
**Claim:** The predictor generalizes to held‑out agents (new LLM‑scaffold combos with seen components) and held‑out benchmarks.  
**Mechanism:** Combine task‑feature difficulty predictor with multi‑benchmark IRT; at inference, sum LLM/scaffold abilities for new combos and use predicted difficulties for new tasks.  
**Core assumption:** Feature representations (embeddings, LLM‑as‑judge scores) are transferable across benchmarks.  
**Evidence:** Predictors achieve AUC 0.936 on held‑out agents and generalize to new benchmarks (SWE‑bench Pro AUC 0.696 vs baseline 0.571); Table 5 and Figure 3 show adaptive selection works.  
**Break condition:** Significant AUC drop on held‑out benchmarks; failure when new benchmark contains task types absent from training (e.g., entirely different repo structures).

## Foundational Learning
### Item Response Theory (IRT)
Why needed: Provides a probabilistic model of agent‑task success (logistic of ability–difficulty); the base method that is extended with features and decomposition.  
Quick check: In 1PL IRT, what does the difficulty parameter β represent and how does it interact with ability θ?  
*(Answer: β shifts the success curve; higher β means task harder; P(success) = σ(θ − β).)*

### LLM‑Scaffold Decomposition
Why needed: Allows combining evaluation data across heterogeneous leaderboards where agents differ in scaffolds but share underlying LLMs.  
Quick check: If an agent uses LLM "Claude‑4" and scaffold "OpenHands", what is its predicted ability in the additive model?  
*(Answer: θ_Claude‑4 + θ_OpenHands.)*

### Task Feature Engineering for Agentic Coding
Why needed: Captures multi‑step task aspects (test patches, repository state, gold solutions) that influence difficulty beyond the issue statement.  
Quick check: Name two non‑textual feature sources used for difficulty prediction.  
*(Answer: Repository state (from auditor agent) and test patch structure.)*

## Architecture Onboarding
**Component map:**  
IRT core (logistic success probability) → Task feature extractors → Difficulty predictor (ridge regression) → Agent ability decomposer → Multi‑benchmark aggregator.

**Critical path:**  
a. For each task: extract feature vectors (embedding + judge features + optional auditor features).  
b. Train standard IRT on the training split to get β and θ.  
c. Freeze β; train ridge regression (lambda tuned by 5‑fold CV) to predict β from task features.  
d. For agent decomposition: replace each agent’s θ with θ_LLM + θ_scaffold and train those parameters via SVI across all response data.  
e. Inference: for a new task, predict β from features; for a new agent with seen LLM/scaffold, sum abilities; compute P(success).

**Design tradeoffs:**  
- Ridge regression vs joint training: ridge gave better held‑out AUC (Appendix D.4).  
- Additive vs multiplicative LLM‑scaffold: additive best (Table 8).  
- Feature concatenation: embedding + judge features improved performance but increased dimensionality; selected top 15 features via ridge coefficients.

**Failure signatures:**  
- Sharp AUC drop on held‑out benchmarks → distribution shift beyond feature coverage.  
- Inability to score agents with novel LLMs/scaffolds (by design).  
- High variance in scaffold abilities for rare scaffolds.  
- LLM‑as‑judge extraction failures (e.g., missing features) → poor difficulty prediction.

**First 3 experiments:**  
1. **New Tasks:** 5‑fold CV hold out random tasks; evaluate difficulty prediction AUC.  
2. **New Responses:** 5‑fold CV hold out random response entries; compare IRT‑with‑agent‑features vs standard IRT.  
3. **New Agents:** 5‑fold CV hold out agents whose LLM and scaffold appear separately in train; evaluate response prediction AUC.

## Open Questions the Paper Calls Out
1. **Causal role of task artifacts** – Do repository state or test patches inherently affect difficulty, or do they merely reveal latent information already present in the problem statement? Controlled experiments that vary specific artifact features while holding the problem statement constant are needed.  
2. **Zero‑shot agent prediction** – Can performance be predicted for entirely novel agents (unseen LLM or scaffold)? The current decomposition requires both components to have appeared separately in training. Developing semantic or quantitative agent features (e.g., from API specs, dynamic analysis) could enable zero‑shot evaluation.  
3. **Benchmark generalization gap** – Why does performance drop on held‑out benchmarks (e.g., SWE‑bench Pro AUC 0.696 vs oracle 0.909)? Understanding benchmark‑specific idiosyncrasies and developing domain‑adaptation techniques for IRT or invariant feature learning would improve out‑of‑distribution transfer.  
4. **Validity of additive decomposition** – As scaffolds become more specialized and co‑adapted with specific LLMs, the assumption of independent additive contributions may break. Longitudinal studies or statistical tests for interaction effects across a wider range of scaffold‑LLM pairings are needed to monitor the validity of the additive model.

## Limitations
- **Reproduction challenges**: Benchmark versions, preprocessing choices, and IRT hyperparameters are not fully specified, limiting faithful replication.  
- **Scope constraints**: Method cannot evaluate agents with unseen LLMs/scaffolds and assumes linear additivity and linear feature‑difficulty mapping.  
- **Generalization limits**: Moderate transfer to new benchmarks (e.g., SWE‑bench Pro) suggests limited robustness to distribution shifts.

## Confidence
- Task features boost difficulty prediction: **High** (clear AUC improvement with ablation support).  
- Additive LLM‑scaffold decomposition: **High** (matches standard IRT accuracy and enables cross‑benchmark aggregation).  
- Generalization to held‑out agents/benchmarks: **Medium** (strong held‑out agent AUC but modest benchmark transfer; limited stress tests).

## Next Checks
1. **Open‑source replication**: Replace Claude Opus with Llama‑3‑70B and sentence embeddings; verify that feature predictive stability holds.  
2. **Ablate additivity**: Introduce LLM‑scaffold interaction terms in the IRT model; compare held‑out log‑likelihood against the additive baseline.  
3. **Stress‑test on a novel benchmark**: Evaluate on a recent coding suite with different repository structures (e.g., AppAgent) to quantify the generalization gap.
