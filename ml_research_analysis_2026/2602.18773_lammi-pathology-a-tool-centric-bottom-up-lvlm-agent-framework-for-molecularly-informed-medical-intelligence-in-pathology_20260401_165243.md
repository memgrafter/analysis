# LAMMI-Pathology: A Tool-Centric Bottom-Up LVLM-Agent Framework for Molecularly Informed Medical Intelligence in Pathology

## Quick Facts
- arXiv ID: 2602.18773
- Source URL: https://arxiv.org/abs/2602.18773
- Reference count: 40
- Primary result: LAMMI with InternVL3.5-8B attains 0.809 answer consistency on PathSpatial-DocQA, exceeding GPT-5 by 0.070.

## Executive Summary
LAMMI-Pathology introduces a scalable agent framework that integrates molecular tools into large vision-language models for pathology diagnosis, addressing the evidence gap in prior LVLM approaches. Its bottom‑up architecture groups tools by domain style into component agents (e.g., GeneAgent, ImageAgent) that are coordinated by a trajectory‑aware planner, avoiding excessive context lengths. By constructing semi‑simulated reasoning trajectories from atomic execution nodes and fine‑tuning the planner with a parameter‑efficient adapter, LAMMI achieves state‑of‑the‑art results on multiple benchmarks while drastically reducing GPU memory consumption. The approach not only improves multi‑step tool‑calling success but also generalizes to novel molecular tools with minimal redundancy, paving the way for molecularly informed medical intelligence in computational pathology.

## Method Summary
LAMMI proceeds in four interconnected stages. First, tools (e.g., gene APIs, image captioning models) are clustered by domain style into component agents through bottom‑up analysis of co‑occurrence patterns, forming groups like GeneAgent and ImageAgent. Second, atomic execution nodes (AENs) are generated: each AEN records a triple (query, tool action, observation) from actual tool executions. An LLM then links AENs into semi‑simulated meta‑trajectories, inserting reasoning thoughts between steps to create coherent multi‑step reasoning chains. Third, a trajectory‑aware adapter is injected into the feed‑forward layers of an LVLM backbone (e.g., InternVL3.5-8B). Using segment‑mask guidance, the adapter applies distinct per‑channel scaling vectors to Thought, Action, and Action Input segments during fine‑tuning, aligning the model’s output with the thought‑action‑observation structure without altering base weights. Finally, a top‑level planner orchestrates the component agents: given a user query, it delegates sub‑tasks to the appropriate agents, each iterating through thought, action, and observation cycles until summaries are returned; the planner synthesizes these into a final answer. The system yields significant memory savings (~35% vs. conventional multi‑agent setups) and robust performance across pathology benchmarks.

## Key Results
- **Frontier QA**: On PathSpatial-DocQA, LAMMI+InternVL3.5-8B achieves 0.809 answer consistency, beating GPT‑5 by 0.070.
- **Trajectory quality**: On ST‑Traj, it obtains 0.817 trajectory success and 0.275 tool consistency F1, far outperforming ReACT (0.381 TSS).
- **Clinical generalization**: On PathMMU, LAMMI+Qwen3‑VL‑8B records 0.582 ACS and 0.503 F1, and demonstrates robust adaptation to novel tools with low redundancy while cutting GPU memory to ~35% of baseline multi‑agent systems.

## Why This Works (Mechanism)
### Hierarchical Tool Clustering
- **Claim:** Hierarchical tool clustering reduces context length while maintaining specialized problem-solving.
- **Mechanism:** Tools are grouped by domain style into component agents; a top-level planner coordinates these agents instead of invoking all tools directly. Each agent handles a limited, relevant subset.
- **Core assumption:** Tool functionalities can be meaningfully clustered so that a component agent’s local toolset covers its delegated sub‑tasks without needing global tool access. (Query decomposition aligns with cluster boundaries.)
- **Evidence anchors:** Abstract: “These tools are clustered by domain style to form component agents, which are then coordinated through a top-level planner hierarchically, avoiding excessively long context lengths that could induce task drift.”
- **Break condition:** If a query spans multiple clusters and requires iterative cross‑agent calls, context savings diminish; poor clustering may omit necessary tools and cause task failure.

### Atomic Execution Nodes (AENs)
- **Claim:** Atomic Execution Nodes (AENs) provide reliable, composable units for building semi‑simulated trajectories that capture real tool interactions.
- **Mechanism:** Each AEN is a triple (query, tool input, tool output) generated by executing a real tool. An LLM links these nodes into coherent meta‑trajectories, inserting reasoning thoughts between steps.
- **Core assumption:** Tool executions produce accurate observations; the LLM can correctly judge semantic compatibility to create valid chains. (LLM’s relevance judgments preserve causal consistency.)
- **Evidence anchors:** Abstract: “Atomic Execution Nodes (AENs) generate semi‑simulated reasoning trajectories.” Section 3.1 defines AENs and the concatenation algorithm.
- **Break condition:** Noisy tool outputs or incorrect LLM linking introduce invalid steps, degrading fine‑tuning and causing planner hallucinations.

### Trajectory‑Aware Adapter
- **Claim:** A trajectory‑aware adapter enables parameter‑efficient fine‑tuning of the LVLM planner to align its decision‑making with multi‑step tool‑calling patterns.
- **Mechanism:** The adapter injects segment‑mask‑guided modulation into FFN layers, applying distinct per‑channel scaling vectors (γ_thought, γ_action, γ_input) to Thought, Action, and Action Input segments.
- **Core assumption:** Formatting patterns of tool calls are learnable with small parametric changes; preserving base model weights avoids catastrophic forgetting.
- **Evidence anchors:** Abstract: “trajectory‑aware adapter fine‑tuning aligns the planner with these multi‑step traces.” Section 3.2 details the segment‑mask mechanism and zero‑initialization.
- **Break condition:** Over‑modulation may distort base knowledge; insufficient fine‑tuning leaves structural misalignment, causing invalid tool call syntax.

## Architecture Onboarding
**Component map:** Planner (LVLM backbone + trajectory‑aware adapter) → Component Agents (e.g., GeneAgent, ImageAgent) → Tools (molecular APIs, captioning models, knowledge bases). A separate pipeline constructs AENs and meta‑trajectories for training.  
**Critical path (inference):** User query → Planner decides delegation → Component Agent iterates (Thought/Action/Action Input → Tool execution → Observation) → returns summary → Planner synthesizes final answer. Training: collect tool executions → generate AENs → link into trajectories → fine‑tune adapter (shared weights).  
**Design tradeoffs:** 
- *Bottom‑up clustering* cuts memory usage but requires careful tool grouping; misalignment forces extra agent calls. 
- *Adapter* uses ~0.006% of parameters vs. full fine‑tuning, yet may have limited capacity. 
- *Semi‑simulated trajectories* scale without human annotation but depend on LLM quality for linking.  
**Failure signatures:** 
- High Tool Redundancy Rate (TRR) – repeated similar tool calls. 
- Low Trajectory Success Score (TSS) – incomplete tool chains. 
- High Hallucination Rate (HR) – outputs ungrounded in observations. 
- Performance drop as Newly Incorporated Tools Ratio (NITR) increases – poor generalization to novel tools.  
**First 3 experiments:** 
1. **PathSpatial‑DocQA** – frontier Q&A; LAMMI+InternVL3.5‑8B achieves 0.809 ACS (Tab 1). 
2. **ST‑Traj** – trajectory quality; LAMMI+InternVL3.5‑8B attains 0.817 TSS and 0.275 TCF1 (Tab 2). 
3. **PathMMU** – clinical benchmark; LAMMI+Qwen3‑VL‑8B reaches 0.582 ACS and 0.503 F1 (Tab 3).

## Open Questions the Paper Calls Out
**Open Question 1:** How does style‑informed clustering determine cluster count and semantic quality?  
Basis in paper: Tools are “clustered by domain style” with “adaptive cluster numbers” based on co‑occurrence during AEN construction, but no evaluation of cluster semantics or selection criteria.  
Why unresolved: Without verified semantic coherence, component agent grouping may be arbitrary and harm planner coordination.  
What evidence would resolve it: Expert assessment of cluster contents; ablation varying cluster number; comparison with functionally‑defined clusters and impact on TSS/TCF1.

**Open Question 2:** Why does the trajectory‑aware adapter generalize to novel tools better than LoRA, and what patterns does it capture?  
Basis in paper: TA+PE maintains stable TSS under increasing NITR while LoRA+PE shows rising TRR without gains. The adapter uses segment masks for distinct scaling vectors.  
Why unresolved: The mechanism behind TA's generalization is not explained; it is claimed to capture “tool‑agnostic structural regularities” but this is not substantiated.  
What evidence would resolve it: Probing learned scaling vectors for segment‑specific patterns; comparing gradient dynamics between TA and LoRA; testing on synthetic tool sets with controlled syntactic variations.

**Open Question 3:** How reliable are LLM‑scored AEN connections, and how does their quality affect trajectory learning?  
Basis in paper: LLMs score semantic/temporal compatibility of AEN pairs and filter invalid connections. The scalability analysis assumes i.i.d. scores, but no validation of LLM judgments is provided.  
Why unresolved: Semi‑simulated trajectories are training data; noisy LLM scoring could introduce incoherent sequences, harming performance.  
What evidence would resolve it: Human evaluation of connection validity; measuring agreement between multiple LLMs; correlation of connection scores with trajectory success; sensitivity analysis on threshold θ.

**Open Question 4:** Can LAMMI generalize to broader medical imaging domains beyond pathology, and what adaptations are required?  
Basis in paper: Conclusion states that future directions include generalizing this framework to broader medical imaging applications. The framework is domain‑adaptive but only evaluated on pathology with spatial transcriptomics tools.  
Why unresolved: The molecular evidence paradigm, tool set, and trajectory construction may be specific to pathology; other domains (e.g., radiology, ophthalmology) involve different evidence types and tools.  
What evidence would resolve it: Porting LAMMI to another domain (e.g., chest X‑ray diagnosis with segmentation and signal tools) and evaluating performance; identifying domain‑general vs. domain‑specific components via cross‑domain transfer experiments.

## Limitations
- Hyperparameter opacity: Exact adapter training settings (learning rate, batch size, epochs) are not specified, hindering exact replication.
- Clustering algorithm details: The precise method for tool co‑occurrence analysis and adaptive cluster determination is underspecified, limiting assessment of scalability to other domains.
- Semi‑simulated trajectory quality: AEN linking relies on an LLM’s judgment of semantic compatibility; noise could propagate errors, but its impact is unquantified.

## Confidence
- Hierarchical tool clustering context reduction: High
- AEN-based trajectory construction: High
- Trajectory-aware adapter parameter efficiency: High
- Generalization to novel tools (low redundancy): Medium
- Superiority over frontier models (e.g., GPT-5): Medium
- End-to-end clinical utility: Low
