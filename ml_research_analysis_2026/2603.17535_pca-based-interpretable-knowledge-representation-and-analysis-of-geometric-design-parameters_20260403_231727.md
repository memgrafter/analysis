# PCA-Based Interpretable Knowledge Representation and Analysis of Geometric Design Parameters

## Quick Facts
- **arXiv ID:** 2603.17535
- **Source URL:** https://arxiv.org/abs/2603.17535
- **Reference count:** 23
- **Primary result:** Proves a "joint PCA" method for parameter recovery is mathematically identical to standard PCA with post-hoc estimation, and discovers that PCA centering can alter the underlying geometry class, causing accurate parameter recovery only when the class is preserved.

## Executive Summary
This paper investigates recovering CAD design parameters from PCA-reduced representations of 3D geometries. It first mathematically proves that a recently proposed "joint PCA" extension for parameter recovery is equivalent to performing standard PCA followed by a specific linear post-hoc estimation. Through controlled experiments on synthetic geometries, it reveals a critical, previously overlooked effect: the centering step in standard PCA can fundamentally change the geometric class of the data (e.g., a helix may no longer be a helix after subtracting the mean shape). Consequently, accurate parameter estimation is only achieved for geometry families invariant under this centering operation (e.g., rectangles), with mean absolute errors on the order of 10⁻¹¹ to 10⁻¹³. For classes where centering alters the geometry (e.g., helixes, fan blades), estimation fails with errors around 10¹ to 10². The number of principal components needed for accurate reconstruction correlates with the number of generating parameters exclusively when the geometry class remains unchanged.

## Method Summary
The study uses synthetic datasets of 3D point clouds, each generated from a known set of design parameters. Geometeries are vectorized (`vec()`) into high-dimensional vectors. Standard PCA is applied to the centered training data to obtain eigenvectors and eigenvalues. A linear mapping from the PCA projection to the centered parameters is learned via a pseudoinverse solution (`H = P_μ X_μ^T (X_μ X_μ^T)^+ V`). For a test geometry, its vector is centered, projected onto the principal components, and the parameters are estimated as `p̂ = μ_P + H^T (x - μ_X)`. The core analysis compares parameter recovery accuracy across different geometry families and links success or failure to whether the PCA centering step preserves the original geometric class of the data.

## Key Results
- "Joint PCA" for parameter recovery is mathematically identical to standard PCA plus a specific post-hoc linear estimator.
- PCA centering can change the geometric class of the data (e.g., a helix becomes a non-helix), which is a critical failure mode for parameter recovery.
- For classes invariant under centering (rectangles, cuboids, simplified helix), parameter estimation is extremely accurate (MAE ~10⁻¹¹–10⁻¹³); for changed classes (helix, fan blade, tube), it fails (MAE ~10¹–10²).
- The number of eigenvectors required to capture a fixed proportion of variance (e.g., 95%) matches the number of generating parameters only when the geometry class is preserved.

## Why This Works (Mechanism)
### Mechanism 1: Equivalence of Joint PCA and Standard PCA
**Claim:** A recent "joint PCA" extension is mathematically identical to standard PCA followed by post-hoc parameter estimation.
**Mechanism:** Joint PCA introduces mass (`M`) and weight (`W`) matrices and an augmented data matrix combining geometries (`X`) and parameters (`P`). Due to the block-diagonal structure of `M` and `W`, the non-zero eigenvalues of the joint covariance match those of standard PCA's covariance. The eigenvectors for the geometry portion are identical, and the parameter-linked eigenvectors (`H`) simplify to `H = P X^T (X X^T)^-1` under standard PCA, showing equivalence.
**Core assumption:** `M` and `W` are block-diagonal and the data is centered.
**Evidence:** Full algebraic derivation in Section 2.5 (Eq. 18-34) proving the eigenvectors and eigenvalues align.
**Break condition:** Non-block-diagonal `M/W` or uncentered data breaks the cancellation.

### Mechanism 2: Centering Can Alter Geometry Class
**Claim:** Subtracting the mean vector during PCA can change the fundamental geometric class of the data.
**Mechanism:** PCA centers by subtracting the mean of the vectorized geometries (`vec(G)`). This mean is itself a vectorized 3D shape. Subtracting it corresponds to a point-wise difference between each sample geometry and this average shape. For some parameterized families (e.g., a helix with variable turns), this operation yields point clouds that no longer conform to the original generative model.
**Core assumption:** Geometries are represented as vectorized point clouds (`vec()`), and centering is element-wise.
**Evidence:** Visual experiments (Figures 1-3) showing centered helixes and complex shapes (fan blade, tube) visually depart from their original class, while rectangles do not.
**Break condition:** The family is closed under affine transformations applied to a fixed reference shape; it fails for families with non-linear dependencies affecting the centroid.

### Mechanism 3: Parameter Recovery Requires Class Preservation
**Claim:** Accurate parameter recovery from PCA components occurs only when the geometry class is invariant under centering; the component count vs. parameter count correlation holds only in this case.
**Mechanism:** Parameter estimation solves `P_μ = H Z` with `Z = V^T X_μ`. This assumes a linear relationship in the *centered* geometry space. If centering changes the class, the PCA eigenvectors span a space of *new* (centered) shapes that cannot linearly reconstruct the original class. Thus, `H` fails. When the class is preserved, dominant eigenvectors directly encode independent parameters (e.g., width, height), so ~k eigenvectors suffice for k parameters.
**Core assumption:** The mapping `P → G` allows linear modeling in the centered space only if the class is closed under centering.
**Evidence:** Table 1 and Figure 5 show low error and `t ≈ k` for first-set classes (preserved), but high error and `t` uncorrelated with `k` for second-set classes (changed).
**Break condition:** Centering changes the class (diagnosed in Mechanism 2). Then, no number of standard PCA eigenvectors yields accurate recovery for the original generative model.

## Foundational Learning
- **Concept: Principal Component Analysis (PCA) theory.**
  - **Why needed:** Understanding PCA's steps—centering, covariance computation, eigen-decomposition, projection—is essential to grasp what the eigenvectors represent and the impact of centering.
  - **Quick check:** If you subtract the mean from already centered data, what changes about the first eigenvector? (Answer: Its direction (variance) is unchanged; only the mean becomes zero, which was already zero.)

- **Concept: Representing 3D geometries as high-dimensional vectors (`vec()`).**
  - **Why needed:** The paper's insight about class change via centering depends on treating a point cloud as a single vector. This dictates what "subtracting the mean geometry" does to the shape.
  - **Quick check:** For a dataset of squares with random sizes, all centered at the origin, what is the mean of their vectorized forms? (Answer: A square of average side length, centered at the origin.)

- **Concept: Linear parameter estimation via pseudoinverse.**
  - **Why needed:** The core equation `p̂ = μ_P + H^T (x - μ_X)` relies on `H = P_μ X_μ^T (X_μ X_μ^T)^+ V`. Knowing when this linear system is well-posed (stable, unique) is key to interpreting results.
  - **Quick check:** What condition on `X_μ X_μ^T` makes the pseudoinverse numerically unstable? (Answer: Near-singularity, i.e., eigenvalues near zero, indicating directions with very little variance.)

## Architecture Onboarding
- **Component map:**
  GeometryPointClouds, ParameterVectors → [vec → Matrix X, P] → Split(Train/Test) → CenterTrain(X_μ) → PCA(X_μ) → [V, Λ, μ_X] → ComputeZ, ComputeH(P_μ, X_μ, V) → For test x: center(x_μ) → Project(V^T x_μ) → ParameterEstimator(H, μ_P) → p̂ → CompareError(p̂, p_true).
  DiagnosticVisualizer runs after centering to inspect `vec⁻¹(x_μ)`.

- **Critical path:** `vec(G) → center → PCA → learn H → test: center new x → project → apply H → get p̂`. The diagnostic (visualizing centered geometries) must precede trusting `H`.

- **Design tradeoffs:**
  - **Number of eigenvectors (r):** For class-preserving families, `r ≈ k` is optimal; `r > k` adds noise and increases error. For class-changing families, more `r` may reduce error but never reaches low levels.
  - **Vectorization:** Simple `vec()` is used but may not preserve local structure. An injective encoder (e.g., neural network) is suggested as future work.
  - **Covariance estimator:** Sample covariance (`1/(m-1)`) is used; with high dimension `l=3n` and `m=1800`, it may be sensitive to noise.

- **Failure signatures:**
  - **Visual:** Centered test geometries visibly do not belong to original class (e.g., helix becomes tangled).
  - **Eigenvalue spectrum:** For changed classes, many small eigenvalues beyond `k`, or very slow decay, indicating higher effective dimensionality of the centered class.
  - **Error plot:** MAE ≳ 10⁰ and does not decrease monotonically with `r` (or only decreases when `r ≫ k`).
  - **Eigengeometry interpretation:** Top eigenvectors (reshaped to 3D) do not visually resemble the target shape family.

- **First 3 experiments:**
  1. **Class Preservation Check:** For each family, compute `g_centered = vec⁻¹(x - μ_X)` for several training samples. Visually confirm if `g_centered` still fits the original parameterized family. Flag as "class change" if not.
  2. **CRV vs. k Analysis:** Compute Cumulative Relative Variance (CRV) for `t=1..min(l,200)`. Find `t` where CRV ≥ 0.95. Compare `t` to `k`. If `t ≈ k`, class likely preserved; if `t ≪ k` or `t ≫ k`, class likely changed.
  3. **Parameter Sweep:** Train on 1800 samples. For test set, compute MAE for `r = [k, t_0.95, 200]`. If MAE at `r=k` is very low (~10⁻¹²) and increases with `r`, class preserved. If MAE is high (~10¹) and decreases with `r`, class changed.

## Open Questions the Paper Calls Out
### Open Question 1
How to learn an injective encoder from geometry to a latent vector where each dimension corresponds to a design parameter, enabling parameter recovery?
- **Basis:** Conclusion suggests future work on "creating an injective mapping" via decoder-encoder networks.
- **Why unresolved:** No concrete method or analysis proposed.
- **Resolution evidence:** A demonstrated encoder-decoder that outputs ground-truth parameters with high test accuracy.

### Open Question 2
What necessary/sufficient conditions on a parametric geometry class guarantee that PCA centering does not change the class?
- **Basis:** Experiments show preservation for rectangles/simplified helix, change for helix/fan blade/tube. Characterized as "difficult to make quantitative."
- **Why unresolved:** No theoretical characterization; observation based on visual inspection of few examples.
- **Resolution evidence:** A mathematical theorem identifying such conditions (e.g., affine closure) validated across many shape families.

### Open Question 3
Why does the number of principal components for a fixed variance proportion (e.g., 95%) equal the number of generating parameters only for classes invariant under centering?
- **Basis:** Table 1 shows `t` matches `k` only for first-set classes; authors state correlation holds only when class unchanged.
- **Why unresolved:** No explanation linking covariance spectrum rank to parameter count.
- **Resolution evidence:** Analytical derivation linking covariance rank to independent parameters, and empirical confirmation that non-linear parameterizations yield higher effective dimensionality.

### Open Question 4
Can we modify the PCA pipeline (e.g., vectorization, centering, weighted PCA) to ensure principal components are interpretable in terms of design parameters, even for problematic classes?
- **Basis:** For second-set classes, eigenvectors are not visually interpretable and estimation fails. Authors suggest exploring "another way of transforming a 3-D geometry into a vector."
- **Why unresolved:** Only standard PCA and equivalent joint PCA tested; no alternatives evaluated.
- **Resolution evidence:** Comparative experiments showing a specific modification (e.g., Procrustes-aligned vectorization, nonlinear DR) yields parameter-aligned eigenvectors and accurate recovery for changed classes.

## Limitations
- **Reproducibility:** Sampling methods for complex shapes (fan blade, tube) and random seeds are unspecified, hindering exact replication.
- **Generality:** Evaluation limited to six geometry classes; the boundary of class-altering centering is unknown.
- **Vectorization:** The exact `vec()` ordering (interleaved vs. block) is not defined, potentially influencing PCA results.

## Confidence
- **Joint PCA equivalence:** High – proof is self-contained and algebraically sound.
- **Centering changes geometry class:** High – strong empirical evidence (visual and quantitative) across multiple classes.
- **Estimation accuracy depends on class preservation:** Medium – consistent pattern observed, but theoretical foundation (e.g., affine closure) is informal and limited to tested cases.

## Next Checks

2. **Analytical class test:** For families with closed-form means (rectangle, ellipse), derive the centered shape analytically and check if it fits the original parameterization; confirm against paper's empirical classification.
