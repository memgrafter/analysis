# AutoFigure: Generating and Refining Publication-Ready Scientific Illustrations

## Quick Facts
- **arXiv ID**: 2602.03828
- **Source URL**: https://arxiv.org/abs/2602.03828
- **Reference count**: 40
- **Primary result**: AutoFigure achieves 66.7% publication-ready rate in human expert evaluation and 83.3% win-rate against other AI systems on the FigureBench benchmark, demonstrating superior structural and aesthetic quality.

## Executive Summary
AutoFigure tackles the bottleneck of manually creating publication-quality scientific illustrations by introducing a "Reasoned Rendering" framework. This framework decouples the process into three stages: extracting a symbolic layout from long-form text via LLM, iteratively refining through a designer-critic loop for structural coherence, and finally rendering with an erase-and-correct module for text legibility. Evaluated on the new FigureBench benchmark (3,300 text-figure pairs), AutoFigure consistently outperforms baselines (GPT-Image, code-generation, Diagram Agent). Human expert evaluation shows 66.7% of outputs are publication-ready and an 83.3% win-rate, highlighting its ability to balance structural accuracy and aesthetic quality.

## Method Summary
AutoFigure is an inference-only pipeline with three stages:
1. **Concept Extraction & Layout Generation**: A Gemini-2.5-Pro model processes long-form scientific text (average >10k tokens) to extract core methodology, entities, and relations, then produces a symbolic layout (SVG/HTML) and a style descriptor. The layout is rasterized to create an image conditioning.
2. **Critique-and-Refine**: An iterative loop simulates a designer-critic dialogue. A critic agent evaluates the current layout for alignment, overlap, and balance, providing feedback. A generator re-interprets the methodology using this feedback to produce candidate layouts, which replace the current best if they score higher. The loop runs up to 5 iterations or until convergence.
3. **Aesthetic Rendering & Text Post-Processing**: The final symbolic layout is converted into a detailed image prompt and structural graph, rendered by GPT-Image to produce a polished image. An erase-and-correct module removes blurry text via background erasure (ClipDrop), extracted text via OCR (EasyOCR) is verified and corrected using a multimodal verifier against ground-truth labels, and vector-accurate text is overlaid to yield the final figure.
The system uses no training; all components rely on large pretrained models. Code and the FigureBench dataset are released.

## Key Results
- FigureBench benchmark: 3,300 text-figure pairs from diverse sources, with a curated test set of 300 high-inter-rater-reliability samples.
- AutoFigure outperforms existing baselines (GPT-Image, code-generation, Diagram Agent) on automated VLM-as-a-judge metrics across Visual Design, Communication Effectiveness, and Content Fidelity.
- Human expert evaluation: 66.7% of outputs rated as publication-ready; AutoFigure achieves 83.3% win-rate in pairwise comparisons against other AI systems.

## Why This Works (Mechanism)
The framework's success stems from three key mechanisms:

### Symbolic Layout Extraction
- **Claim**: Converting long-form scientific text into a structured symbolic layout (SVG/HTML) decouples structural reasoning from visual rendering, ensuring layout coherence.
- **Mechanism**: A Concept-Extraction agent distills core methodology and entities/relations into a directed graph, serialized as a machine-readable blueprint (S0) specifying 2D geometry and topology.
- **Core assumption**: LLMs can reliably parse complex, long-context scientific prose (>10k tokens) into a consistent symbolic representation capturing essential spatial and logical relationships.
- **Evidence anchors**: Abstract; Section 4.1 (Concept Extraction and Symbolic Construction); neighboring papers confirm decoupling paradigm.
- **Break condition**: Source text is highly underspecified, contradictory, or uses domain-specific notation outside LLM training distribution, leading to incomplete/erroneous extraction.

### Iterative Critique-and-Refine Loop
- **Claim**: Simulating a designer-critic dialogue via iterative self-refinement optimizes layout for structural coherence and aesthetic balance before rendering.
- **Mechanism**: Critic evaluates current best layout for alignment, overlap, balance, producing feedback. Generator re-interprets methodology using feedback to produce candidate layouts; if candidate scores higher, it replaces current best. Loop continues until convergence or iteration limit.
- **Core assumption**: Each critique provides meaningful, non-redundant guidance enabling escape from local optima to globally superior layout.
- **Evidence anchors**: Section 4.2 (self-refinement loop description); Section 5.3 (test-time scaling experiment showing score rise from 6.28 to 7.14 after five iterations).
- **Break condition**: Feedback becomes repetitive/adversarial, causing cycling without improvement; performance plateaus (Fig 5c).

### Erase-and-Correct Text Post-Processing
- **Claim**: Separating text rendering into an erase-and-correct pipeline guarantees pixel-perfect textual accuracy.
- **Mechanism**: After rendering, OCR extracts text and bounding boxes from the generated image. A verifier aligns these strings with ground-truth labels from the symbolic layout, correcting errors. Corrected text is re-rendered as vector overlays on a clean, erased background.
- **Core assumption**: OCR errors and generative artifacts can be systematically identified and corrected by cross-referencing with the symbolic layout (S_final), and vector overlay produces flawless legibility.
- **Evidence anchors**: Section 4.2 (erase-and-correct process); Appendix I (ablation shows Aesthetic +0.10 and Polish +0.10).
- **Break condition**: OCR fails on extremely small fonts, complex backgrounds, or distorted glyphs; vector overlay misalignment if bounding boxes inaccurate.

## Architecture Onboarding
**Component map**:  
Input Parser -> Concept-Extraction Agent -> Layout Generator -> {Critic Agent -> Refinement Loop Controller -> Layout Generator}* -> Rendering Prompt Engineer -> Image Generator -> Text Eraser -> OCR Engine -> Text Verifier -> Final Composer

**Critical path**:  
Text input -> Stage 1 (Concept Extraction & Initial Layout) -> Stage 2 (Iterative Critique-and-Refine loop) -> Stage 3 (Rendering Prompting -> Image Generation -> Erase -> OCR -> Verify -> Overlay) -> Final output.

**Design tradeoffs**:
- *Decoupling vs. End-to-End*: Decoupling trades architectural complexity for better control; end-to-end is simpler but fails on structural fidelity.
- *Symbolic Format*: SVG vs. HTML choice affects rendering flexibility and agent generation ease; SVG slightly outperforms HTML (Appendix Fig 5d).
- *Refinement Iterations*: More iterations improve quality (Fig 5c) but increase cost/time; system uses score-based early exit.

**Failure signatures**:
- Text rendering: Blurry, misspelled, misaligned text in final output despite erase-and-correct.
- Structural collapse: Oversimplification (merged nodes) or clutter (excessive overlap) from poor Stage 1/2.
- Aesthetic-structural tension: Overly stylized output sacrificing clarity or omitting key elements.

**First 3 experiments**:
1. **Benchmark Sanity Check**: Run pipeline on 5 manual FigureBench test samples; verify stage outputs (S0, S_final, I_final) match paper examples (Figs 6, 3) for implementation fidelity.
2. **Ablation: No Refinement Loop**: Set Stage 2 iteration count to 0; compare overall quality against full pipeline using VLM scores; expect significant drop in Communication Effectiveness and Content Fidelity.
3. **Text Post-Processing Audit**: For 20 generated figures, manually compare OCR-extracted text vs. ground truth before and after Verifier step; quantify correction rate and remaining error types (character-level, word-level).

## Open Questions the Paper Calls Out
1. **How can AutoFigure's "Reasoned Rendering" framework be adapted to generate high-quality illustrations for scientific domains outside computer science (e.g., biology, chemistry)?**  
   Basis: Conclusion and Appendix C identify extension to other disciplines as key future direction, noting need for domain-specific knowledge. Why unresolved: Requires new benchmarks, fine-tuning components with domain ontologies, possibly modifying symbolic layout representation. Evidence required: Follow-up study showing cross-domain transfer via new benchmark (e.g., BioFigure), pipeline modifications, and quantitative/qualitative results matching CS performance.

2. **What architectural modifications are necessary to eliminate fine-grained text-rendering errors?**  
   Basis: Limitations section lists fine-grained text-rendering accuracy as bottleneck, citing failure case ("ravity" for "gravity"). Why unresolved: Erase-and-correct VLM verification fails on small fonts, complex backgrounds, severe artifacts. Evidence required: Integrated module (e.g., specialized OCR, constrained rendering engine) achieving near-zero character error rate on text-heavy FigureBench samples, confirmed by human evaluation of legibility.

3. **Can the critique-and-refine loop's efficiency be improved without sacrificing quality?**  
   Basis: Performance scales with iterations (Fig 5c) but Stage 2 is most time/cost-intensive (Appendix J). Why unresolved: Current critique is rule-based, not learned; search is local. Evidence required: Replacement with learned reward model or advanced search (e.g., MCTS) achieving same/better layout scores with significantly fewer iterations, reducing generation time.

4. **To what extent does AutoFigure rely on explicit text vs. inferring implied structure for underspecified concepts?**  
   Basis: Limitations mention concretization drift when source text underspecified. Why unresolved: Gap-filling risks inaccuracies; trade-off not quantified. Evidence required: Controlled analysis on FigureBench subset with systematically removed/abstracted details; measure drop in Content Fidelity and hallucination rate; possible RAG augmentation test.

5. **How can ethical risks of misuse (generating plausible but incorrect schematics) be mitigated beyond policy?**  
   Basis: Ethics Statement acknowledges risk, proposes disclaimer and attribution but no technical safeguards. Why unresolved: No internal fact-checking or confidence estimation for layout accuracy. Evidence required: Technical verification module (e.g., cross-referencing key entities/relations with trusted knowledge base) evaluated for catching injected errors/hallucinations, providing practical barrier.

## Limitations
- Undisclosed LLM prompts and agent configurations introduce replication variance.
- Ambiguous model specifications (e.g., GPT-Image variant, VLM judge) hinder precise benchmarking.
- Generalizability beyond FigureBench to highly technical domains, non-English text, or underspecified methods remains unverified.
