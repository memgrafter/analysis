# LLM-as-a-Judge for Time Series Explanations

## Quick Facts
- **arXiv ID:** 2604.02118
- **Source URL:** https://arxiv.org/abs/2604.02118
- **Reference count:** 18
- **Primary result:** A rubric-guided LLM-as-a-Judge framework enables stable, reference-free evaluation of time series explanation correctness by verifying claims directly against raw data, even when models fail to generate accurate explanations themselves.

## Executive Summary
The paper tackles the absence of general-purpose, reference-free methods to assess the factual correctness of LLM-generated explanations grounded in time series data. It introduces a synthetic benchmark, TSQueryBench, with 350 instances across seven query types and proposes a rubric-guided "LLM-as-a-Judge" approach. An evaluator model directly checks a candidate explanation against the raw time series, assigning a ternary label based on pattern identification, numeric accuracy, and faithfulness. Results reveal a clear asymmetry: generation performance is highly pattern-dependent (0% to 96% accuracy), while evaluation tasks (ranking and independent scoring) are substantially more stable. Models like Qwen-3 8B can reliably evaluate explanations even for query types where they cannot generate correct ones, demonstrating that structured prompting unlocks reliable data-grounded verification despite generative shortcomings.

## Method Summary
The authors construct TSQueryBench, a synthetic benchmark of 350 univariate time series (lengths 100, 200, 300, 500) covering seven query types (e.g., Structural Break, Volatility Shift). For each series, a rule-based pipeline generates three candidate explanations: correct, partially correct (with controlled numeric perturbations), and incorrect. The core evaluation uses zero-shot prompting of instruction-tuned LLMs (Qwen-3 8B, LLaMA-3.1 8B, Gemma-2 9B IT) with a structured rubric. The prompt instructs the model to verify all claims against the raw time series values—not the explanation text—across dimensions like data faithfulness and numeric accuracy, outputting a ternary label (`0=Incorrect`, `1=Partially Correct`, `2=Fully Correct`) or a ranking. Performance is measured on four tasks: generation, relative ranking, independent scoring, and multi-anomaly detection (count accuracy & F1).

## Key Results
- Generation accuracy is highly pattern-dependent, ranging from 0% (Volatility Shift) to 96% (Structural Break).
- Evaluation tasks (ranking and scoring) are substantially more stable across query types; models correctly rank and score explanations even when generation fails for the same pattern.
- Multi-anomaly detection shows moderate F1 but near-zero count accuracy, indicating over-sensitive detection with many false positives.

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** Structuring the evaluation with an explicit rubric transforms the LLM into a focused verifier, enabling reliable data-grounded reasoning.
**Mechanism:** The prompt decomposes correctness into verifiable sub-dimensions (faithfulness, numeric accuracy, etc.), forcing stepwise checks against raw time series values rather than relying on the explanation's text.
**Evidence:** Instructions explicitly forbid using explanation values; evaluation performance is significantly more uniform than generation, indicating the scaffold enables reliable verification.
**Break condition:** Fails if the time series exceeds the model's context window or requires nuanced statistical reasoning (e.g., volatility shift) beyond the model's calculation capabilities.

### Mechanism 2
**Claim:** A synthetic benchmark with controlled, known errors isolates the model's verification capability from real-world noise and ambiguity.
**Mechanism:** Rule-based generation of candidate explanations (e.g., perturbing a ground-truth statistic) ensures deterministic labels and precise error typology (e.g., "index off by 2"), creating a clean signal for measuring sensitivity to specific discrepancies.
**Evidence:** Partially correct explanations introduce numeric perturbations; evaluators correctly rank candidates differentiated only by such perturbations.
**Break condition:** Validity is confined to the synthetic error patterns; performance may degrade on qualitatively different real-world errors (e.g., logical fallacies).

### Mechanism 3
**Claim:** The observed asymmetry (strong evaluation, weak generation) arises because evaluation is a constrained discriminative task, while generation requires novel numeric synthesis.
**Mechanism:** Ranking/scoring involves comparing a given claim to the data—a discriminative process aligning with LLM strengths—whereas generation demands precise de novo numeric assertions, which suffer from token sampling variance and symbolic reasoning limits.
**Evidence:** Models achieve high ranking accuracy on Volatility Shift despite 0% generation accuracy; the rubric scaffolds the discriminative process.
**Break condition:** Asymmetry collapses if evaluation itself becomes generative (e.g., "explain why this is wrong").

## Foundational Learning
- **Concept: Reference-Free, Data-Grounded Evaluation**
  - **Why needed:** The evaluator must verify textual claims against raw numerical data without a gold explanation.
  - **Quick check:** If an explanation says "there was a 50% increase at time 50," what three specific actions must the evaluator LLM take using only the list of time series values?
- **Concept: Rubric as a Structured Prompting Scaffold**
  - **Why needed:** The ternary label maps to composable reasoning dimensions; deconstructing the rubric is essential for prompt design and error interpretation.
  - **Quick check:** For the "Partially Correct" label (1), what is one concrete reason an explanation might receive this score instead of "Fully Correct" (2) or "Incorrect" (0)?
- **Concept: Synthetic Benchmark Construction with Error Typology**
  - **Why needed:** Controlled error injection provides a reliable evaluation set with perfect labels and known failure modes.
  - **Quick check:** How would you generate a "partially correct" candidate for a "Mean Shift" query? Give one valid perturbation.

## Architecture Onboarding
**Component map:**  
Time Series Encoder/Formatter → Question Parser → Candidate Explanation Ingestion → Rubric-Guided Evaluator (LLM) → Post-Processor

**Critical path:**  
Raw TS → Formatted TS → (Formatted TS + Question + Explanation) → Rubric-Prompted LLM → Label

**Design tradeoffs:**  
- Synthetic vs. Real Data: Synthetic data offers perfect labels and error control but lacks real-world complexity; real data requires expensive human labeling and introduces ambiguity.
- Granularity of TS Representation: All points ensure fidelity but risk context limits; summary statistics are efficient but may hide local patterns referenced by explanations.
- Rubric Specificity: Detailed rubrics yield interpretable traces but increase prompt complexity; simple prompts are robust but provide no error insight.
- Zero-shot vs. Few-shot: Zero-shot generalizes but may underperform on complex queries; few-shot improves type-specific performance but harms cross-type generalization.

**Failure signatures:**  
1. **Volatility/Statistical Shift Blindness:** Low scores on Volatility Shift and Seasonal Drop, indicating inability to reason about variance or higher-order statistics.
2. **Over-Sensitive Anomaly Detection:** Moderate F1 but very low count accuracy, with many false positives on minor fluctuations.
3. **Context Window Collapse:** Performance drops sharply for series >200–300 steps for smaller-context models (e.g., Gemma-2 9B).
4. **Rubric Hallucination:** Model ignores the time series and critiques wording alone, causing high score variance and low self-agreement.

**First 3 experiments:**  
1. Replicate generation asymmetry: Run generation on all 7 query types with Qwen-3 8B; expect >90% on Structural Break/Mean Shift but ~0% on Volatility Shift.
2. Probe evaluation stability: Run independent scoring on the same Volatility Shift instances where generation failed; verify Qwen-3 8B achieves >70% accuracy.
3. Test rubric dependency: Ablate the rubric—compare full rubric-guided scoring against a generic "Is this correct?" prompt; expect significant accuracy drop.

## Open Questions the Paper Calls Out
1. How does the framework generalize to real-world, noisy time series datasets beyond the synthetic TSQueryBench?
2. Can accuracy be improved for query types involving higher-order statistical properties like volatility shifts?
3. Do hybrid systems combining LLM-based reasoning with symbolic/statistical verification improve correctness assessment?
4. What explains the asymmetry where LLMs can evaluate explanations even when they fail to generate them?
5. How reliable and human-aligned is the rubric-guided approach, given the lack of human validation for evaluation decisions?

## Limitations
- Exact prompt templates (rubric wording, JSON schema, TS formatting) are undisclosed, hindering precise replication.
- The synthetic data generation pipeline (distributions, noise models, thresholds) is underspecified, making TSQueryBench reconstruction difficult.
- Human annotation protocol for generation labels (annotator count, adjudication, agreement) is unreported, compromising the gold standard.
- Ecological validity is limited; rule-based perturbations may not capture real-world error patterns.
- Context-window constraints and implicit anomaly-detection thresholds introduce undocumented performance variations.

## Confidence
- **Asymmetry (evaluation > generation):** Medium – results are robust across models but depend on opaque rubric-guided prompting details.
- **Rubric-guided evaluator effectiveness:** Medium – structured approach improves stability, but specific prompt phrasing impact is unknown.
- **Synthetic benchmark generalizability:** Low – construction details and narrow error typology restrict confidence in transfer to real data.
