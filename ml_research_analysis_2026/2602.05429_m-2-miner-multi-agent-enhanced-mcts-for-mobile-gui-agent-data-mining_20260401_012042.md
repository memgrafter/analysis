# M$^2$-Miner: Multi-Agent Enhanced MCTS for Mobile GUI Agent Data Mining

## Quick Facts
- **ArXiv ID:** 2602.05429
- **Source URL:** https://arxiv.org/abs/2602.05429
- **Reference count:** 25
- **Primary result:** M²-Miner automates high-quality GUI agent data mining using multi-agent MCTS, achieving up to 64× efficiency gains and state-of-the-art performance on multiple benchmarks.

## Executive Summary
Constructing capable GUI agents requires large-scale intent-trajectory data, but manual annotation is costly and existing automated mining methods suffer from low quality and richness. M²-Miner introduces an automated framework based on Monte Carlo Tree Search (MCTS) enhanced by a collaborative multi-agent system. InferAgent proposes actions for tree expansion, OrchestraAgent deduplicates and ranks them, and JudgeAgent supplies process-based rewards to stabilize simulation. An intent recycling strategy extracts additional trajectories from non-primary search paths, enriching diversity. A progressive model-in-the-loop training curriculum iteratively refines agent capabilities. Extensive experiments show that agents fine-tuned on M²-Miner data achieve state-of-the-art results (e.g., 97.5% type accuracy on AndroidControl-Low), outperform prior mining methods by large margins, and reduce data construction cost by ~18× per image while boosting mining efficiency up to 64×.

## Method Summary
M²-Miner employs a tree-structured MCTS where each node represents a GUI state. The search is guided by three specialized agents: InferAgent generates candidate actions during expansion; OrchestraAgent merges equivalent actions and ranks them to prioritize promising branches; JudgeAgent evaluates intermediate states with process-based rewards, avoiding costly full rollouts. After mining an intent, an intent recycling filter repurposes non-primary paths by reassigning coherent intents via a multimodal LLM, thus extracting extra high-quality trajectories without re-mining. The framework adopts a progressive training strategy: agents are initially warmed up on public datasets, then the system cycles through mining basic intents, complex/composite intents, and recycled intents, retraining InferAgent and JudgeAgent after each stage to create a positive feedback loop that enhances mining success on unseen environments.

## Key Results
- GUI agents fine-tuned with M²-Miner data achieve state-of-the-art performance (e.g., 97.5% type accuracy, 93.5% step success on AndroidControl-Low with M²-Miner-7B).
- Outperforms prior automated mining methods by large margins.
- Reduces construction cost by ~18× per image and boosts mining efficiency up to 64×.

## Why This Works (Mechanism)
**Mechanism 1**: Collaborative multi-agent MCTS.  
Claim: Specializing distinct models for expansion, action prioritization, and state evaluation overcomes vanilla MCTS bottlenecks in GUI spaces.  
Mechanism: InferAgent increases valid action hit rate; OrchestraAgent guides search via ranked actions; JudgeAgent provides frequent process rewards, stabilizing learning.  
Break condition: Degradation in any agent (e.g., invalid proposals, misjudged states) collapses efficiency gains and data quality.  
Evidence: Ablation shows exponential efficiency gains (up to 64×) when agents are added incrementally.

**Mechanism 2**: Intent recycling.  
Claim: Non-primary branches in MCTS trees contain latent coherent sequences that can be repurposed for new intents.  
Mechanism: After primary intent mining, all root-to-node paths are filtered; valid ones are reassigned new intents via an MLLM and validated by JudgeAgent, converting "failures" into additional data.  
Break condition: Overly lenient filter adds noise; overly strict discards valuable paths.  
Evidence: t-SNE shows more diverse intent distributions; DQA scores confirm high quality of recycled data.

**Mechanism 3**: Progressive model-in-the-loop training.  
Claim: Alternating mining and agent retraining iteratively improves capabilities, especially on unseen environments.  
Mechanism: A three-stage curriculum (basic intents → complex/composite intents → recycling) uses newly mined data to retrain InferAgent and JudgeAgent, creating a positive feedback loop.  
Break condition: Accumulation of systematic errors in mined data could cause overfitting and reduced generalization.  
Evidence: Steady TP/SR improvements on CAGUI (unseen domain) across stages; increasing JudgeAgent accuracy.

## Architecture Onboarding
**Component map**  
MCTS Controller → Selection → Expansion (InferAgent + OrchestraAgent) → Simulation (JudgeAgent) → Backpropagation  
Data Structures: Intent-Trajectory Tree (nodes store screenshot, action meta, Q-value, visit count, status)  
Training Pipeline: Model-in-the-loop controller cycles through intent generation → mining → retraining  
Execution Layer: Action Parser → adb commands; Android VM provides screenshots

**Critical path**  
1. Initialize root node for intent *I₀* and start state *s₀*.  
2. Select: Traverse tree using UCT until expandable node *v*.  
3. Expand: InferAgent generates *K* actions; OrchestraAgent merges/ranks; execute top action, create child node *v'*.  
4. Simulate: JudgeAgent evaluates *v'*; set reward 0/1 if terminal, else process reward *r*.  
5. Backpropagate: Update *Q* and *N* for all nodes on path from *v'* to root.  
6. Termination check: If node status terminal, extract trajectory(s); if success for *I₀*, stop; else repeat from step 2.  
7. Recycling: For all root-to-node paths, apply filter, generate new intents, validate with JudgeAgent, add valid pairs to dataset.

**Design tradeoffs**  
- Agent cost vs. efficiency: 7B models balance cost/performance; 72B for OrchestraAgent/recycling improves quality but increases latency.  
- Tree depth vs. exploration: Deeper trees capture longer trajectories but risk explosion; intent recycling mitigates by extracting value from shallow branches.  
- Reward specificity: Process rewards accelerate learning but rely on a well-trained JudgeAgent; poor initial rewards misguide search.

**Failure signatures**  
- High simulation failure rate: JudgeAgent misclassifies intermediates; check calibration.  
- Redundant expansion actions: OrchestraAgent merging failed; monitor post-ranking diversity.  
- Recycling noise: Recycled trajectories show low DQA; sample to adjust filter strictness.

**First 3 experiments**  
1. **Ablate Single Agent**: Run mining with only InferAgent (random expansion, rollout-based simulation). Compare MSR and steps-per-trajectory vs. full M²-Miner. Expect dramatic slowdown and lower success.  
2. **Recycling Impact**: Mine fixed initial intents with/without recycling. Compare total trajectories, intent embedding diversity (t-SNE), and downstream agent SR. Expect ~2×+ trajectories and more diverse intents.  
3. **Progressive Training Validation**: On CAGUI (unseen apps), train agents with only warm-up data vs. full 3-stage curriculum. Evaluate final agent TP/SR. Expect significant gains from stages 2 & 3.

## Limitations
- Hyperparameters (*K*, depth limit *L*, UCT initialization) are not specified, critically affecting search efficiency.
- JudgeAgent training data may lack negative/intermediate failure samples, risking biased rewards.
- Recycling and progressive training stability require further validation on truly unseen domains.

## Confidence
- Mechanism 1 (multi-agent MCTS): High
- Mechanism 2 (intent recycling): Medium
- Mechanism 3 (progressive training): Medium
