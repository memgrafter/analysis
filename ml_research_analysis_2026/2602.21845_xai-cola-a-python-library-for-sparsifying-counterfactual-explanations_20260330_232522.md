# xai-cola: A Python library for sparsifying counterfactual explanations

## Quick Facts
- arXiv ID: 2602.21845
- Source URL: https://arxiv.org/abs/2602.21845
- Reference count: 3
- Counterfactual explanations (CEs) from existing generators are often redundant, changing too many features to be actionable.

## Executive Summary
xai-cola is an open-source Python library that addresses the redundancy problem in counterfactual explanations by sparsifying them—removing superfluous feature modifications while preserving validity. The library implements a configurable sparsification algorithm (COLA) with matcher and attributor policies, providing a unified, model-agnostic pipeline for tabular data. It accepts scikit-learn or PyTorch models and arbitrary CE generators, and includes visualization tools to support the explanation process.

## Method Summary
The library uses a COLA algorithm that identifies and removes unnecessary feature modifications from counterfactual explanations. It employs configurable matcher and attributor policies to determine which features can be sparsified while maintaining the validity of the counterfactual. The pipeline is designed to be model-agnostic, supporting both scikit-learn and PyTorch models with tabular data, and integrates with various counterfactual explanation generators.

## Key Results
- Experiments across multiple generators (Wachter, DiCE, GLOBE-CE, DisCount) show consistent sparsity improvements
- Reduces the number of modified features by up to 50% across datasets
- Achieves 45.3% reduction for DisCount (PyTorch) on COMPAS and 24.9% for DiCE (sklearn) on German Credit

## Why This Works (Mechanism)
The COLA algorithm works by analyzing counterfactual explanations and identifying features whose modification is superfluous to achieving the desired counterfactual outcome. By removing these redundant feature changes, the algorithm creates sparser explanations that are more actionable for end-users while maintaining the validity of the counterfactual—ensuring that the modified instance still produces the desired prediction from the model.

- Model validity: "Why needed" - ensure sparsified CEs still achieve counterfactual goal; "Quick check" - test if modified instance produces desired prediction

## Architecture Onboarding

**Component Map:** COLA Algorithm -> Matcher Policy -> Attributor Policy -> Visualization Tools

**Critical Path:** CE Generator → COLA Sparsification → Validity Check → Output

**Design Tradeoffs:** Model-agnostic design supports broad adoption but requires gradient information, limiting non-differentiable model support; configurable policies offer flexibility but increase complexity

**Failure Signatures:** Invalid counterfactuals (don't achieve target prediction), excessive computation time for complex attributions, incompatibility with tree-based models

**First Experiments:**
1. Generate counterfactual with standard method, apply COLA sparsification, verify validity preservation
2. Compare feature count reduction across different matcher/attributor configurations
3. Test visualization tools with sample counterfactuals to assess usability

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How do different matcher and attributor configurations within COLA affect the trade-off between sparsity, validity, and plausibility of counterfactual explanations?
- Basis in paper: [inferred] The library implements configurable policies, but the experimental evaluation uses fixed, unreported policy settings without comparing policy variants.
- Why unresolved: Without isolating policy contributions, it is unclear which combinations optimally balance reduced feature changes with explanation quality metrics beyond validity.
- What evidence would resolve it: Systematic ablation studies across multiple policies, measuring sparsity, validity rates, plausibility (e.g., via data density or realism scores), and computational overhead on standard benchmarks.

### Open Question 2
- Question: To what extent can xai-cola sparsify counterfactuals for non-differentiable or gradient-free models (e.g., tree ensembles), which are prevalent in practice?
- Basis in paper: [explicit] The paper explicitly notes that gradient-based generators (Wachter, DisCount) are incompatible with sklearn models, and all experiments use only logistic regression or neural networks.
- Why unresolved: The reliance on gradient information for attributions may exclude widely used models like random forests or XGBoost, limiting the library's applicability in real-world pipelines.
- What evidence would resolve it: Integrating gradient-free attribution methods (e.g., SHAP for tree models) into COLA and evaluating sparsification performance and validity preservation on non-differentiable models.

### Open Question 3
- Question: Does sparsification via xai-cola improve the practical utility of counterfactual explanations for end-users, such as through enhanced comprehension, trust, or likelihood of action?
- Basis in paper: [inferred] The evaluation is purely quantitative (feature reduction percentages); no user studies or real-world impact assessments are conducted.
- Why unresolved: Actionability inferred from fewer features may not translate to human-centric outcomes without considering cognitive load, domain constraints, or user decision-making processes.
- What evidence would resolve it: Controlled experiments with target users (e.g., loan applicants, clinicians) comparing raw vs. sparsified counterfactuals on metrics like understanding, satisfaction, feasibility perception, and behavioral changes.

## Limitations
- No evaluation of whether sparser explanations remain faithful to the original model's decision boundary
- Absence of user studies on whether sparser explanations improve actionability
- Lack of comparison against alternative sparsification methods

## Confidence
**High**: Core claim that xai-cola consistently reduces feature modifications across multiple CE generators
**Medium**: "Model-agnostic" claim since library explicitly supports only scikit-learn and PyTorch models with tabular data
**Low**: "Preserving validity" assertion due to lack of defined validity metrics or quantitative validation
