# ANCHOR: Branch-Point Data Generation for GUI Agents

## Quick Facts
- **ArXiv ID**: 2602.07153
- **Source URL**: https://arxiv.org/abs/2602.07153
- **Reference count**: 40
- **Primary result**: Fine-tuning on ANCHOR data raised Qwen3-VL-8B success by 3.74% (OSWorld) and 3.29% (WindowsAgentArena) over zero-shot baselines.

## Executive Summary
ANCHOR is a scalable data generation pipeline for desktop GUI agents. It starts from a small set of verified seed demonstrations, identifies *branch points* (meaningful UI state changes) to propose diverse tasks, executes them with an agent, and applies a verifier with step-level filtering and denoising to ensure high-quality trajectories. The pipeline produced 1,777 successful trajectories (average 17.24 steps). Models fine-tuned on this data consistently outperformed zero-shot and task-driven synthesis baselines on OSWorld and WindowsAgentArena, demonstrating the value of automatically generated, state‑grounded demonstrations.

## Method Summary
The ANCHOR pipeline comprises four stages: (1) collection of seed demonstrations; (2) branch point detection, where UI state changes that enable multiple actions are identified; (3) task proposal and execution using an agent; and (4) verification with step‑level filtering and denoising to prune erroneous steps. By iterating over branch points, the system expands a tiny seed set into a large corpus of reliable trajectories suitable for fine‑tuning GUI agents.

## Key Results
- Generated 1,777 successful trajectories averaging 17.24 steps each.
- Fine‑tuned Qwen3‑VL‑8B improved success rates on OSWorld from 16.82% to 20.56% and on WindowsAgentArena from 27.47% to 30.76%.
- Ablations confirm the importance of step‑level quality controls.

## Why This Works (Mechanism)
Branch points capture UI transitions that naturally give rise to a variety of valid actions, ensuring task diversity grounded in real interface states. The step‑level verifier removes individual erroneous steps and denoises the remaining sequence, producing clean, reliable demonstrations. This combination of diversity‑focused generation and rigorous quality filtering yields trajectories that effectively teach agents to navigate desktop environments, explaining the observed performance gains.

## Foundational Learning
- **Branch Point Identification**  
  - *Why needed*: To locate UI states that offer multiple plausible actions, enabling diverse task generation.  
  - *Quick check*: Does the detected point correspond to a meaningful UI change (e.g., menu opening, new panel appearing)?
- **Task Proposal**  
  - *Why needed*: To automatically generate a wide range of executable tasks from branch points without manual scripting.  
  - *Quick check*: Are proposed tasks grounded in the current UI state and executable by the agent?
- **Step‑Level Filtering**  
  - *Why needed*: To remove individual erroneous steps that could propagate failures in the trajectory.  
  - *Quick check*: Does the verifier correctly identify steps that violate UI constraints or lead to dead ends?
- **Denoising**  
  - *Why needed*: To clean up trajectories by correcting minor mistakes, improving overall quality while preserving intent.  
  - *Quick check*: Does denoising fix execution errors without altering the task’s semantic goal?
- **Agent Execution**  
  - *Why needed*: To carry out proposed tasks in the real environment, generating concrete interactions.  
  - *Quick check*: Does the agent follow the proposed task and produce valid UI actions?

## Architecture Onboarding
**Component map**: Seed Demonstrations → Branch Point Detector → Task Proposer → Agent Executor → Verifier (Step Filter + Denoiser) → Clean Trajectories

**Critical path**: Starting from a seed, branch points are identified; for each, tasks are proposed and executed; the resulting trajectory passes through the verifier; successful trajectories are stored.

**Design tradeoffs**:  
- Diversity vs. quality: too many branch points produce noisy tasks; too few limit coverage.  
- Verifier aggressiveness vs. coverage: strict filtering may discard recoverable trajectories.  
- Seed quality dependence: low‑quality seeds may propagate errors despite verification.

**Failure signatures**:  
- Verifier rejects a high proportion of steps, indicating poor execution or over‑strict rules.  
- Agent repeatedly fails on specific UI element types (e.g., dropdowns).  
- Branch point detector outputs either too few (limited diversity) or too many (exponential explosion) candidates.

## Limitations
- Evaluation restricted to OSWorld and WindowsAgentArena; generalizability to other desktop OS or application domains is unknown.
- Heavy dependence on a small seed set may limit task and step diversity; no diversity metrics are reported.
- Verifier implementation details are omitted, hindering reproducibility assessment and raising overfitting concerns.
