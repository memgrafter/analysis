# Anagent For Enhancing Scientific Table & Figure Analysis

## Quick Facts
- arXiv ID: 2602.10081
- Source URL: https://arxiv.org/abs/2602.10081
- Reference count: 40
- Primary result: ANAGENT achieves up to 13.43% relative improvement in zero-shot and 42.12% with finetuning on scientific table & figure analysis.

## Executive Summary
Scientific table and figure analysis demands interpreting multimodal data, integrating cross-source evidence, and domain-specific reasoning—capabilities where current AI systems underperform. This paper introduces ANABENCH, a large-scale benchmark with 63,178 instances spanning nine scientific domains and seven complexity dimensions, and ANAGENT, a modular multi-agent framework. ANAGENT decomposes analysis into four specialized roles—PLANNER, EXPERT, SOLVER, and CRITIC—and uses supervised finetuning followed by reinforcement learning to optimize each agent while preserving collaboration. Evaluated across 170 subdomains, ANAGENT shows substantial gains, demonstrating that task-oriented decomposition and context-aware problem-solving are essential for high-quality scientific analysis.

## Method Summary
The task is to generate coherent analysis of scientific tables/figures, requiring interpretation of multimodal data, integration of cross-source evidence, and domain reasoning. Inputs include tables/figures (x), source paper info (s), and analysis query (q). Performance is measured via rule-based metrics (ROUGE-L, BLEU, SciBERT-Score) and a five-dimensional MLLM-as-Judge protocol. The proposed ANAGENT framework employs four agents: PLANNER decomposes queries into subtasks; EXPERT retrieves task-specific knowledge using 16 specialized tools across five toolkits; SOLVER synthesizes analysis grounded in retrieved knowledge; CRITIC provides iterative five-dimensional feedback. Training proceeds in two phases: supervised finetuning (SFT) on ~31K instances initializes all agents, then agent-specific reinforcement learning (GRPO) with tailored rewards refines each role.

## Key Results
- ANAGENT achieves up to 13.43% relative improvement in zero-shot settings compared to single-agent baselines.
- With finetuning, relative improvement reaches 42.12%; e.g., finetuned Qwen3-VL-4B scores 38.03% overall (SAVG) vs. baseline 26.76%.
- Gains are consistent across 170 subdomains and seven complexity dimensions, validating robustness.

## Why This Works (Mechanism)

**Mechanism 1: Task Decomposition**  
Claim: Breaking complex analysis into actionable subtasks improves accuracy and completeness.  
Mechanism: PLANNER analyzes input and decomposes the query into a structured subtask list before generation, guiding downstream agents and preventing incomplete or misaligned outputs.  
Evidence anchors: PLANNER mitigates common failures (§3.1); decomposition formalized as separate agent role distinguishes from related work.  
Break condition: Subtasks are too vague, unbalanced, or misaligned with query objectives.

**Mechanism 2: Task-Oriented Knowledge Retrieval**  
Claim: Iterative, tool-based retrieval targeted to subtasks reduces domain-specific and contextual errors.  
Mechanism: EXPERT executes specialized tools per subtask, incrementally building knowledge Kₑ = K_{e-1} ∪ EXPERT(τₑ, K_{e-1}), ensuring purpose-driven context gathering.  
Evidence anchors: EXPERT focuses on task-oriented exploration (§D.3); tool utilization analysis shows increased use of abstract collector and information localizer after finetuning (§page 32-33).  
Break condition: Tool calls are hallucinated, return irrelevant results, or fail to adapt to subtask specifics.

**Mechanism 3: Context-Aware Synthesis with Iterative Refinement**  
Claim: Coupling a context-grounded SOLVER with a CRITIC that provides five-dimensional feedback enables coherent, accurate analysis.  
Mechanism: SOLVER generates candidate yᵢ; CRITIC evaluates across content accuracy, completeness, format, clarity, and faithfulness; loop repeats until convergence. Synthesis constrained to retrieved knowledge Kₙ.  
Evidence anchors: Five-dimensional protocol (§2.4, Fig. 44); finetuned CRITIC improves performance (§5.3); SFT+RL yields highest scores (Table 2).  
Break condition: CRITIC feedback is superficial or incorrect; Kₙ is incomplete/noisy.

## Foundational Learning
- **Multimodal Long-Context Reasoning**: Needed to interpret tables (structured text) and figures (visual+text) with lengthy surrounding contexts (captions, sections). Quick check: How would you integrate a table of experimental results and a figure of model architecture while citing MethodSection 3.2 and Table 4?
- **Domain-Specific Knowledge Integration**: Required for correct terminology, prior work references, and reasoning within subdomain conventions (e.g., precision-recall curves in ML vs. Kaplan-Meier curves in medicine). Quick check: How does analysis differ for a hyperparameters table (methodology) vs. an accuracy scores table (experiment)?
- **Iterative Refinement with Structured Feedback**: First drafts often contain subtle interpretation errors or formatting issues needing systematic review. Quick check: What are the five evaluation dimensions and how would you use them to critique a draft analysis?

## Architecture Onboarding
Input (x, s, q) -> PLANNER -> subtask list τ -> EXPERT (loop per subtask with 16 tools across Document, Knowledge, Search, Vision, Sandbox) -> accumulated knowledge Kₙ -> SOLVER (loop with CRITIC) -> final analysis y.
- Critical path: 1. PLANNER decomposes query. 2. EXPERT executes tools for each subtask, building Kₙ. 3. SOLVER generates initial analysis. 4. CRITIC evaluates and gives feedback. 5. SOLVER revises (repeat 4-5).
- Design tradeoffs: Modular training preserves specialization but costs compute; end-to-end risks role collapse. Tool count must balance utility vs. burden. Iteration depth vs. latency. Training-free vs. finetuned tradeoff.
- Failure signatures: PLANNER: vague/misaligned subtasks. EXPERT: tool hallucination, extraction errors. SOLVER: source mixing, shallow analysis, unfaithfulness. CRITIC: superficial feedback, incorrect format scoring.
- First 3 experiments: 1. Baseline vs. Training-Free ANAGENT (isolate architectural gains). 2. SFT Only vs. SFT+RL (quantify RL benefit). 3. Ablation on Agent Variants (validate components; expect Omnion < Symnion < ANAGENT).

## Open Questions the Paper Calls Out
1. How can the computational overhead of multi-agent systems for scientific table & figure analysis be reduced while maintaining high-quality outputs?
2. To what extent does ANAGENT generalize to emerging scientific domains, non‑English literature, and alternative publication platforms beyond arXiv and PubMed?
3. How can tool utilization be made more reliable and strategic to minimize failures and misalignments with task objectives?
4. Can we develop a low‑cost yet accurate automatic evaluation protocol that scales to large‑scale scientific analysis assessment without relying on expensive MLLM‑as‑a‑judge or human experts?

## Limitations
- Tool implementation details (e.g., d-depth hierarchical context retrieval, API access, rate limits) are underspecified, hindering faithful reproduction.
- Hyperparameters for GRPO (group size, reward weights) and SFT initialization checkpoints are incompletely documented.
- Evaluation relies on MLLM-as-Judge (Gemini/GPT), which may introduce model-specific biases.
- ANABENCH, while large, is novel with low citation signals, raising questions about external validity and adoption.

## Confidence
- Task Decomposition (PLANNER): High (well-defined in prompts/papers; ablation supports necessity).
- Task-Oriented Retrieval (EXPERT): Medium (tool gains noted; success rates not quantified in main paper).
- Iterative Refinement (SOLVER+CRITIC): Medium (finetuned CRITIC helps; training-free harms small models).
- Overall Gains (42.12% rel. improvement): Medium (benchmark-specific; cross-benchmark generalizability unproven).

## Next Checks
1. Reproduce tool execution fidelity: Instrument ANAGENT to log all tool calls during EXPERT phase; compute success rates (valid parameters, error-free responses) per tool and domain; compare against reported utilization trends.
2. Ablate CRITIC across model scales: Run training-free ANAGENT with/without CRITIC for Qwen3-VL-4B, 7B, and 14B backbones; measure delta in SAVG to validate "CRITIC hurts small models" claim.
3. External benchmark transfer: Evaluate finetuned ANAGENT on related scientific benchmarks (e.g., SciCap+ for figure captioning, MSEarth for multimodal reasoning) to test generalizability beyond ANABENCH's task distribution.
