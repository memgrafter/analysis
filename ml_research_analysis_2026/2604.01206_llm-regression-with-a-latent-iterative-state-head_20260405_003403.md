# LLM REgression with a Latent Iterative State Head

## Quick Facts
- **arXiv ID:** 2604.01206
- **Source URL:** https://arxiv.org/abs/2604.01206
- **Reference count:** 40
- **Primary result:** A lightweight iterative latent state head attached to frozen LLMs consistently outperforms all prior baselines for numeric regression, achieving macro-averaged Pearson 76.3% with only ~3.4–3.7M trainable parameters (0.01–0.04% overhead).

## Executive Summary
Large language models (LLMs) struggle with numeric regression due to the verbalization gap during token generation and summarization bottlenecks in static pooling heads. This paper introduces RELISH, a method that bypasses token generation entirely and instead iteratively refines a learned latent state via cross-attention over frozen LLM token representations. A lightweight linear regressor then produces the final scalar. Across five datasets and four LLM backbones (8–32B parameters), RELISH significantly exceeds the performance of autoregressive decoding, regression-aware inference, and existing predictive heads, while being far more parameter-efficient than LoRA-based approaches.

## Method Summary
RELISH attaches a small, trainable head to a frozen LLM backbone. For an input `x`, the LLM produces token hidden states `H(x)`. These are optionally projected to a lower dimension `X(x)`. A learned initial latent vector `r(0)` is iteratively refined over `L` steps. Each step applies multi-head cross-attention (query=`r(i-1)`, key/value=`X(x)`), followed by a layer norm, a feed-forward network, and another layer norm. After `L` iterations, the final latent `r(L)` is passed to a linear layer to predict a standardized target `ẑ`. The prediction is denormalized using training set statistics to yield the final scalar `ŷ`. The LLM weights remain frozen; only the projection, iterative refinement stack, and linear head are trained, typically totaling ~3.4M parameters.

## Key Results
- RELISH macro-averages Pearson 76.3%, Spearman 74.0%, and range-normalized RMSE 13.3% across five datasets, beating all baselines.
- It uses only ~3.4–3.7M trainable parameters (0.01–0.04% of an 8B model), far less than LoRA (0.26–0.42%).
- Performance is consistent across four diverse LLM backbones: Llama 3.1 8B, Qwen3 8B, Qwen3 32B, and Gemma 3 27B Instruct.
- Optimal iteration depth `L` varies by backbone (e.g., `L=1` for Qwen3-8B, `L=3` default, `L=5` for Gemma3-27B).

## Why This Works (Mechanism)
### Mechanism 1: Verbalization Gap
- **Claim:** Autoregressive decoding introduces a verbalization gap that decouples token probabilities from numerical proximity, harming regression accuracy.
- **Mechanism:** Language modeling loss penalizes token mismatches equally regardless of numeric closeness (e.g., predicting “0.1” vs “0.9” for target 1.0 both incur high token-level cross-entropy), optimizing for linguistic likelihood rather than minimizing mean squared error.
- **Core assumption:** LLM internal states encode continuous numeric estimates, but the discrete generation process corrupts this signal.
- **Evidence anchors:** [abstract] "LLM-based regression suffers from the verbalization gap when generating numeric tokens"; [section 2.2] "decoding is based on token probabilities rather than numerical proximity".

### Mechanism 2: Summarization Bottleneck
- **Claim:** Static pooling (mean, [CLS]) collapses distributed token-level information, creating a summarization bottleneck.
- **Mechanism:** Uniform averaging washes out localized, high-salience features (e.g., error markers, magnitude cues) crucial for precise regression; the fixed vector cannot selectively emphasize task-relevant tokens.
- **Core assumption:** Regression signals are unevenly distributed across tokens; a simple reductionist summary loses discriminative details.
- **Evidence anchors:** [abstract] "summarization bottlenecks in predictive heads using static pooling"; [section 2.2, 2.4] critiques vector-based heads for reliance on "basic pooling heuristics"; [section C.3.2] calls this "information collapse".

### Mechanism 3: Iterative Latent Refinement
- **Claim:** Iterative latent refinement via cross-attention progressively distills regression-relevant information that single-pass summarization misses.
- **Mechanism:** A learned latent state `r(0)` repeatedly attends to frozen token representations `H(x)`; each round refines the summary, allowing multi-grained context accumulation and selective focus on salient patterns. The final state `r(L)` encodes a more robust regression cue.
- **Core assumption:** One attention pass is insufficient to extract complex, distributed features; iterative updates enable higher-level abstraction.
- **Evidence anchors:** [abstract] "iteratively refining a learned latent state through cross-attention over token-level representations"; [section 3.2] details the loop: `r(i) = LN(r(i-1) + MHA(r(i-1), X, X)) → FFN → LN`; [section E.2] shows `L=1` underperforms `L≥2` with diminishing returns after `L=3` (except Gemma3-27B).

## Foundational Learning
- **Concept: Frozen LLM Backbones**
  - Why needed: RELISH updates only the lightweight head while keeping LLM weights fixed; understanding gradient flow and representation quality is key.
  - Quick check: "During training, which components receive gradients? What does it mean for the LLM to be 'frozen'?"
- **Concept: Cross-Attention**
  - Why needed: The refinement process hinges on MHA where latent state queries token memories; must distinguish from self-attention.
  - Quick check: "In MHA(r(i-1), X(x), X(x)), what are Query, Key, Value? Why reuse X(x) for Key and Value?"
- **Concept: Regression Losses & Normalization**
  - Why needed: Training uses Huber loss on standardized targets; y-normalization prevents collapse to the mean.
  - Quick check: "Why standardize y*? What happens if you train without normalization?"

## Architecture Onboarding
- **Component map:**
  LLM backbone (frozen) → penultimate H(x) → projection X(x)=H(x)W (optional) → initial latent r(0) → iterative refinement blocks (L×[MHA + residual + LN + FFN + residual + LN]) → r(L) → linear head (wᵀr(L)+b) → denormalize → ŷ.
- **Critical path:**
  Forward: `x` → tokenize → LLM → `H` → `[X=HW]` → `r(0)` → loop `i=1..L`: `r(i)=Refine(r(i-1),X)` → `ẑ = wᵀr(L)+b`. Backward: `L(ŷ, y*)` → gradients for `w,b,r(0),FFN,MHA,W`. LLM frozen.
- **Design tradeoffs:**
  - `d_h` (latent dim): Smaller (256) yields extreme efficiency (<0.04% of backbone); larger increases capacity but blows up params if `L>1`.
  - `L` (iterations): `L=3` default; `L≥2` beats `L=1`; optimal `L` backbone-dependent (e.g., Qwen3-8B peaks at `L=1`, Gemma3-27B gains up to `L=5`).
  - Projection: MUST include; omitting (`d_h=d`) causes O(`L d²`) parameter explosion, making RELISH less efficient than LoRA.
  - Loss: Huber (δ=1.0) preferred; after normalization, MSE nearly equivalent but Huber slightly better in most cases.
- **Failure signatures:**
  - Collapsed training (loss ≈ constant): missing y-normalization or latent not trainable.
  - No gain over zero-shot: `L=0`? or attention weights unchanged; check initialization.
  - Degradation as `L` increases: likely overfitting; reduce capacity (`d_h`), add dropout, or lower LR.
  - Unexpectedly high parameter count: projection omitted or `d_h ≈ d`.
- **First 3 experiments:**
  1. Sanity: Train RELISH on STS-B with Llama3.1-8B; expect Pearson >70% (zero-shot ~71.7%).
  2. Ablate `L`: Test `L=1,2,3,5`; confirm `L=3` beats `L=1`. If `L=1` matches `L=3`, backbone already encodes regression well (unusual).
  3. Parameter audit: Print trainable count; should be ~3.4M for 8B models. If >20M, projection likely skipped.

## Open Questions the Paper Calls Out
- **Open Question 1:** How does RELISH perform on single-input regression tasks (e.g., sentiment intensity, product price prediction) compared to its success on pairwise tasks?
  - **Basis:** Evaluation focuses exclusively on pairwise STS and MT quality estimation; future work could include single-input tasks.
  - **Why unresolved:** No results exist for single-input scenarios; iterative summarization might behave differently without a reference text.
  - **What evidence would resolve it:** Benchmark RELISH on single-input regression datasets (e.g., sentiment scoring) and compare to baselines.
- **Open Question 2:** Can RELISH generate full predictive distributions (e.g., quantiles) using quantile heads and pinball loss, and does this improve calibration?
  - **Basis:** The paper suggests RELISH could yield distributions by replacing the linear regressor with quantile heads trained with pinball loss.
  - **Why unresolved:** Only point predictions with Huber/MSE loss were evaluated; quantile extension remains theoretical.
  - **What evidence would resolve it:** Implement quantile regression heads, train on existing datasets, and assess distributional metrics (e.g., interval coverage, CRPS).
- **Open Question 3:** Does fine-tuning the LLM backbone (e.g., via LoRA) with RELISH enhance performance on out-of-distribution regression tasks?
  - **Basis:** Limitations state RELISH is bounded by frozen LLM representations; backbone fine-tuning may be necessary for novel domains.
  - **Why unresolved:** All experiments used a frozen backbone; no combination with LoRA or fine-tuning was evaluated.
  - **What evidence would resolve it:** Train RELISH with LoRA adapters on domain-shifted data (e.g., biomedical STS) and compare against frozen-backbone RELISH and LoRA-only.
- **Open Question 4:** How does RELISH's computational cost scale with input sequence length, and can modifications mitigate bottlenecks for long documents?
  - **Basis:** Attention-based pooling scales linearly with sequence length; for long inputs (e.g., whole papers), cross-attention could become a bottleneck.
  - **Why unresolved:** No empirical scaling experiments were conducted; impact on runtime/memory for long inputs is unknown.
  - **What evidence would resolve it:** Measure latency/memory across sequence lengths (512, 2048, 8192) and test whether sparse attention or token reduction maintain accuracy.

## Limitations
- Evaluation restricted to 5 English‑centric datasets and 4 specific LLMs; generalizability to other languages, domains, or architectures is unknown.
- Mechanistic explanations (verbalization gap, summarization bottleneck) are inferred from empirical results, not directly measured; alternate explanations remain.
- Optimal iteration depth `L` varies by backbone, introducing a tuning burden.

## Confidence
- **Verbalization gap:** Medium. Supported by decoding comparisons and prior work, but gap magnitude not quantified.
- **Summarization bottleneck:** Medium. Static pooling ablations show weakness, but could reflect capacity limits.
- **Iterative refinement:** Medium‑High. Consistent gains for `L≥2` across datasets/backbones; effect persists after capacity matching.
- **Overall superiority:** High within evaluated baselines; external validity uncertain.
- **Parameter efficiency:** High. Trainable parameter calculations are explicit and orders of magnitude lower than LoRA.

## Next Checks
1. **Internal numeric probe:** Extract frozen LLM last‑hidden‑states for regression examples; train a simple linear regressor (no iteration) to predict standardized targets. Compare accuracy to autoregressive generation. If the probe significantly outperforms, it confirms the verbalization gap.
2. **Capacity‑matched non‑iterative head:** Construct an attention‑pooling head with increased heads/FFN width to match RELISH’s ∼3.5M trainable parameters. Evaluate on STS‑B. If iterative refinement still wins, it isolates the benefit of iteration beyond raw capacity.
3. **Cross‑lingual generalization:** Apply RELISH to a non‑English regression task (e.g., German STS) using a multilingual LLM (e.g., Qwen3‑32B) with English prompts. Failure would indicate language‑specific effects; success would strengthen portability claims.
