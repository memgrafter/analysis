# Why Does It Look There? Structured Explanations for Image Classification

## Quick Facts
- arXiv ID: 2603.10234
- Source URL: https://arxiv.org/abs/2603.10234
- Reference count: 38
- Primary result: I2X provides structured explanations by tracking prototype evolution, enabling guided fine-tuning that reduces class confusion (e.g., 2↔7 on MNIST decreased from 14.80±6.31 to 9.80±2.93) and improves accuracy to 84.02% on CIFAR-10.

## Executive Summary
This paper introduces I2X, a framework for generating structured, faithful explanations of image classifier decisions. Unlike typical saliency-based XAI methods that produce only unstructured heatmaps, I2X clusters model features into abstract prototypes and tracks their intensity changes across training checkpoints, correlating these changes with model confidence variations. The resulting structured explanations reveal how models progressively learn to distinguish classes, identify uncertain prototypes that cause confusion (e.g., specific stroke patterns in digits), and demonstrate that training data order influences learned strategies. Guided fine-tuning by removing samples containing uncertain prototypes reduces class confusion and improves accuracy on MNIST and CIFAR-10, and the approach generalizes to InceptionV3.

## Method Summary
I2X consists of two phases: explanation generation and guided fine-tuning. First, using a random 10% subset of training data, hidden features from the final model are reduced by PCA and clustered via K-Means to define K abstract prototypes. For each training checkpoint, GradCAM saliency maps are computed; prototype intensities are derived by averaging saliency values over spatial regions assigned to each prototype. Confidence changes between consecutive checkpoints are computed and clustered with HDBSCAN; a ridge regression then maps prototype intensity changes to confidence changes for each cluster, quantifying each prototype’s influence. Over time, prototypes are categorized as shared, specialized, or uncertain (those alternately supporting conflicting classes). Second, a curated training set is created by excluding samples that activate uncertain prototypes; the model is fine-tuned on this set to reduce reliance on confusing cues and lower inter-class confusion.

## Key Results
- Confusion reduction: on MNIST (ResNet-50), 2↔7 confusion decreased from 14.80±6.31 to 9.80±2.93; on CIFAR-10, cat↔dog confusion dropped from 261.20±30.77 to 238.60±21.90.
- Accuracy gain: fine-tuning on curated sets achieved up to 84.02% accuracy on CIFAR-10.
- Generalization: the framework successfully applied to InceptionV3, confirming its utility for faithful explanation and performance optimization.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Abstract prototypes summarize recurring visual patterns learned by the model, enabling structured analysis.
- **Mechanism:** Hidden features from the final model are dimensionality-reduced via PCA and clustered using K-Means. The resulting centroids become "abstract prototypes," each representing a group of similar feature vectors. For a given input, the spatial feature map is segmented by these prototypes, linking image regions to abstract patterns.
- **Core assumption:** Similar visual features cluster into semantically meaningful patterns; the model’s decision-making can be understood via a finite set of these prototypes.
- **Evidence anchors:** [section 2.2] describes applying PCA and K-Means to all hidden features to derive K centroids; [abstract] mentions "prototypes extracted from post-hoc XAI methods"; neighboring papers focus on saliency or concepts, so I2X’s prototype clustering is a distinct structuring step.
- **Break condition:** If PCA/K-Means fails to capture semantically coherent patterns (e.g., prototypes mix unrelated visual features), the structural explanation becomes invalid.

### Mechanism 2
- **Claim:** Changes in model confidence across training checkpoints can be systematically attributed to changes in prototype activation intensity.
- **Mechanism:** For consecutive training checkpoints, compute (a) the change in per-class confidence (`∆ˆy`) for all samples, and (b) the change in prototype intensity (`∆P`) aggregated over samples. Cluster the confidence changes using HDBSCAN to group samples with similar confidence evolution. For each cluster, compute the mean confidence change and the mean filtered prototype intensity change (`ReLU(∆P - σ)`). A ridge regression (`β = (πᵀπ + λI)⁻¹πᵀC`) then estimates how prototype intensity changes drive confidence changes.
- **Core assumption:** Confidence evolution can be modeled as a linear combination of prototype intensity changes at a checkpoint; samples with similar confidence shifts share common prototype drivers.
- **Evidence anchors:** [section 2.5] details `C_t`, `˜P_t`, and ridge regression in Eq. (8); [abstract] notes "tracking the evolution of abstract prototypes... correlating their intensity changes... with model confidence changes"; neighboring works emphasize saliency or textual explanations, making this temporal mapping novel.
- **Break condition:** If the relationship between prototype intensity and confidence is highly non-linear or if HDBSCAN clusters are not meaningful (e.g., excessive noise points), the attribution model fails.

### Mechanism 3
- **Claim:** Structured explanations identify "uncertain prototypes" that confuse the model; removing samples containing these prototypes during fine-tuning reduces class confusion and improves accuracy.
- **Mechanism:** From the structured explanation, identify prototypes that alternately support conflicting classes across checkpoints (e.g., contributing to both digit 7 and digit 2 confidence). These are "uncertain." Curate a training subset excluding samples where such prototypes are active. Fine-tune the model on this curated set (or perturbed full set) to reduce reliance on the uncertain cue.
- **Core assumption:** Uncertain prototypes are causal sources of confusion; their removal leads to more robust feature learning for the ambiguous classes.
- **Evidence anchors:** [section 3.5] explicitly describes identifying uncertain prototype P-17 and fine-tuning on curated data, showing reduced 2↔7 confusion (14.80→9.80); [table 1] quantifies accuracy and confusion reduction for MNIST; [table 2] shows similar gains for CIFAR10 and InceptionV3; neighbors explore counterfactuals or concept-based fixes but not prototype-driven curation.
- **Break condition:** If uncertain prototypes are not the root cause of confusion (e.g., confusion stems from other features), curation may harm performance or create new biases.

## Foundational Learning
- **Concept: Post-hoc saliency map generation (e.g., GradCAM)**
  - *Why needed here:* I2X uses saliency maps as the raw "unstructured interpretability" from which prototype intensity is aggregated. Without a method to produce spatial relevance maps, the pipeline cannot start.
  - *Quick check question:* What spatial resolution does GradCAM produce for a ResNet-50, and how is it aligned with the feature map dimensions?
- **Concept: Unsupervised clustering (K-Means, HDBSCAN)**
  - *Why needed here:* K-Means defines prototypes from features; HDBSCAN groups samples by similar confidence evolution. Both are essential for reducing dimensionality and finding common patterns.
  - *Quick check question:* How does the choice of `K` in K-Means affect the specificity/generality of the resulting prototypes? What HDBSCAN parameter controls cluster stability versus noise?
- **Concept: Training dynamics (checkpoint sampling, confidence delta)**
  - *Why needed here:* I2X tracks evolution across checkpoints; it uses `∆ˆy` and `∆P` to correlate changes, not static values. Understanding optimization trajectories is central.
  - *Quick check question:* Why compare deltas between checkpoints instead of absolute prototype intensities and confidences? What would be lost by using static snapshots?

## Architecture Onboarding
- **Component map:** Feature Extractor → Prototype Clustering → Saliency & Intensity Extraction → Confidence Change Clustering → Cluster-level Aggregation → Ridge Regression → Explanation Assembly → Curation & Fine-tuning.
- **Critical path:** Feature extraction → Prototype clustering → (for each checkpoint pair) Saliency/intensity → Confidence delta → Cluster → Regression → Aggregation → Identify uncertain → Curate → Fine-tune.
- **Design tradeoffs:**
  - *Post-hoc vs. Faithful:* Uses GradCAM (post-hoc) for saliency; may not perfectly reflect model’s internal reasoning. Tradeoff: accessibility vs. faithfulness.
  - *Clustering parameters:* `K` (prototype count) and `σ` (intensity threshold) control granularity. Too few `K` oversimplifies; too many adds noise.
  - *Checkpoint frequency:* More checkpoints capture finer dynamics but increase compute; fewer may miss key transitions.
- **Failure signatures:**
  - Prototypes do not correspond to coherent visual patterns (inspect via upsampled activation maps).
  - Ridge regression coefficients (`β_t`) are noisy or non-persistent across checkpoints.
  - Fine-tuning on curated set reduces accuracy instead of improving it.
  - HDBSCAN produces mostly noise label `-1` or very few clusters.
- **First 3 experiments:**
  1. Replicate MNIST ResNet-50 analysis for digit ‘7’ (Fig. 3, Fig. 4) to verify prototype visualization and confidence mapping.
  2. Vary `K` (e.g., 16, 32, 64) and observe impact on number of shared/specialized prototypes and regression stability.
  3. Compare fine-tuning on “full explanation set” (10% data) vs. “curated set” (without uncertain prototype) vs. sequential fine-tuning (curated→full) to reproduce Tab. 1 results.

## Limitations
- Critical hyperparameters (HDBSCAN `min_cluster_size`, intensity threshold `σ`, ridge `λ`) are not specified, hindering reproducibility.
- The framework depends on post-hoc GradCAM saliency, which may not faithfully represent the model’s internal decision process.
- Evaluation is limited to MNIST and CIFAR-10; performance on more complex datasets (e.g., ImageNet) remains unproven.

## Confidence

- Confidence-prototype mapping: Low
