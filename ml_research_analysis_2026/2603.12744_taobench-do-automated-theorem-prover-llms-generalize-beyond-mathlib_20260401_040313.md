# TaoBench: Do Automated Theorem Prover LLMs Generalize Beyond MathLib?

## Quick Facts
- **arXiv ID**: 2603.12744
- **Source URL**: https://arxiv.org/abs/2603.12744
- **Reference count**: 40
- **Primary result**: State-of-the-art ATP LLMs exhibit an average 26% drop in pass@128 on TaoBench (22–49%) versus TaoBench-MathLib (50–73%), with the gap exceeding 50 percentage points for contexts containing ≥10 local definitions, revealing severe sensitivity to definitional shifts.

## Executive Summary
This paper introduces TaoBench, a novel Lean 4 benchmark consisting of 150 undergraduate analysis exercises from Terence Tao's *Analysis I*, each provided in two mathematically equivalent forms: one using Tao's bespoke definitions (TaoBench) and another translated to standard MathLib syntax (TaoBench-MathLib). The core problem is quantifying whether automated theorem prover (ATP) large language models generalize beyond the MathLib definitional framework they are accustomed to. Through a rigorous agentic extraction and translation pipeline—validated by manual checks and GPT-5.1-based equivalence verification—the authors evaluate several state-of-the-art ATP models. The results demonstrate a substantial and consistent performance degradation on the bespoke framework, indicating that current ATP models are highly biased toward the specific definitional choices of MathLib and struggle to adapt to alternative, albeit equivalent, formulations.

## Method Summary
The study constructs TaoBench via an agentic pipeline that recursively extracts self-contained, compilable Lean contexts for each exercise from Tao's repository using the JiXia static analysis tool and a file-lookup utility, iterating with a Lean compiler until successful. Each context is then translated to MathLib syntax using GPT-5.1 with web search; compilation errors are fixed iteratively, and mathematical equivalence is verified by comparing proof states extracted via JiXia and judged by GPT-5.1. Expert manual verification ensures fidelity of both the extracted bespoke contexts and the translated MathLib versions. Finally, four SOTA ATP models (DeepSeek-Prover-V2-7B, Goedel-Prover-V2-8B/32B, Kimina-Prover-8B) are evaluated on both benchmarks, generating up to 128 proof attempts per problem with temperature 1.0 and an 8192-token limit.

## Key Results
- All evaluated ATP models show an average 26% drop in pass@128 on TaoBench (22–49%) compared to TaoBench-MathLib (50–73%).
- The performance gap widens dramatically with more local definitions: exceeding 50 percentage points for contexts with ≥10 definitions.
- TaoBench pass@128 plummets from 67% (0 local definitions) to 6% (≥10 local definitions), while the MathLib version remains stable, highlighting extreme sensitivity to definitional shifts.

## Why This Works (Mechanism)
The observed generalization gap arises because ATP models are trained predominantly on MathLib-based formalizations, leading to overfitting to its specific definitional choices, naming conventions, and proof idioms. When presented with mathematically equivalent but syntactically and structurally distinct bespoke definitions, models fail to recognize underlying mathematical concepts, indicating a lack of robust abstract reasoning. The paper does not deeply analyze the internal mechanism (e.g., attention patterns, representation learning) behind this sensitivity, focusing instead on the empirical gap and its implications for real-world deployment.

## Foundational Learning
- **Definitional framework**: A set of foundational definitions and axioms in a formal library; models must recognize mathematical equivalence across frameworks.
  - *Why needed*: Benchmarks test generalization beyond a single framework.
  - *Quick check*: Can the model prove the same theorem when key definitions (e.g., `Limit`) are renamed or restructured?
- **Generalization in ATP**: Ability of models to solve theorems formalized in styles or libraries different from training data.
  - *Why needed*: Real mathematics uses diverse notations and foundations; models must be robust.
  - *Quick check*: Evaluate model on a dataset with mixed formalization styles; measure performance variance.
- **Lean 4 formalization**: The specific proof assistant language and ecosystem (MathLib vs custom developments).
  - *Why needed*: Syntax and library usage directly impact model performance.
  - *Quick check*: Translate a MathLib proof to a bespoke style; does the model still succeed?
- **Equivalence checking**: Verifying that two formal statements represent the same mathematical content.
  - *Why needed*: Ensures paired benchmarks are truly comparable.
  - *Quick check*: Use a trusted verifier (e.g., proof irrelevance check) to confirm bidirectional implication.
- **Agentic extraction pipeline**: Automated process to isolate minimal compilable contexts from large repositories.
  - *Why needed*: Scales benchmark creation while preserving fidelity.
  - *Quick check*: Does extracted context compile in isolation and retain the original theorem statement?
- **Pass@k metric**: Standard evaluation for code/ theorem generation, measuring success within *k* attempts.
  - *Why needed*: Accounts for stochastic generation; robust performance measure.
  - *Quick check*: Compare multiple runs; is variance consistent with reported confidence intervals?

## Architecture Onboarding
**Component map**:
Repository clone -> JiXia analysis -> File-lookup tool -> Lean compiler (sandbox) -> Self-contained snippet (TaoBench) -> GPT-5.1 + web search -> Compiler iteration -> GPT-5.1 + JiXia equivalence check -> Verified snippet (TaoBench-MathLib) -> ATP model evaluation -> pass@128

**Critical path**: Extraction (JiXia → file-lookup → compiler) → Translation (GPT-5.1 → compiler → equivalence check) → Evaluation (model inference → Lean verification).

**Design tradeoffs**: 
- Minimal context retrieval reduces noise but risks missing notational/instance dependencies, causing compilation failures.
- Automated LLM translation scales but introduces semantic drift; manual correction is used sparingly (33 cases).
- Full-context provisioning avoids truncation but may overwhelm models with long contexts; the paper reports no truncation, implying models handle up to ~8k tokens.

**Failure signatures**:
- Extraction: Lean compilation errors (missing declaration, notation, instance).
- Translation: Compilation errors or equivalence-check failures (logical mismatch despite syntactic similarity).
- Evaluation: Model generates syntactically invalid Lean or proofs that do not close the goal.

**Exactly 3 first experiments**:
1. **Extraction replication**: Run the agentic pipeline on 5 exercises from *Analysis I*; measure compilation success rate and context size.
2. **Equivalence validation**: For 10 translated pairs, manually inspect goal states and attempt bidirectional proofs to assess GPT-5.1 equivalence judgments.
3. **Model baseline**: Evaluate one ATP model (e.g., DeepSeek-Prover-V2-7B) on both benchmarks for a subset of 20 problems; confirm the performance gap direction and magnitude.

## Open Questions the Paper Calls Out
- **Open Question 1**: How can we automatically identify all context needed for faithful formalization beyond minimal transitive dependencies?
- **Open Question 2**: What training data or objectives can enable ATP models to generalize across definitional frameworks?
- **Open Question 3**: Why does ATP performance sharply degrade as the number of local definitions in context increases?
- **Open Question 4**: How can we reliably automate translation of mathematical statements between different definitional frameworks with provable equivalence?

## Limitations
- The precise list of 150 exercises is undisclosed; only chapter-wise counts are provided, hindering exact replication.
- The orchestrating agent's LLM, prompts, and file-lookup tool details are unspecified, leaving extraction behavior ambiguous.
- ATP model evaluation parameters (decoding hyperparameters, seeds, inference code) are not fully documented, risking implementation variance.
- Automatic equivalence checking relies on GPT-5.1 and JiXia; subtle semantic mismatches may persist despite manual spot-checks.

## Confidence
- **Performance gap observed** (26% average drop): **Medium** – supported by systematic evaluation but dependent on undisclosed exercise selection.
- **Extraction correctness** (self-contained contexts): **Medium** – described procedure with manual verification, yet agent behavior uncertain.
- **Translation equivalence** (TaoBench vs TaoBench-MathLib): **Low** – automated verification may miss nuanced drift; manual correction used non-trivially.
- **Evaluation reproducibility** (ATP models' pass@128): **Low** – insufficient details on inference setup and exact problem set.
