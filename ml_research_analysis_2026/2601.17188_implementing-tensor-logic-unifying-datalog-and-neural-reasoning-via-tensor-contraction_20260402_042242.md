# Implementing Tensor Logic: Unifying Datalog and Neural Reasoning via Tensor Contraction

## Quick Facts
*   **arXiv ID:** 2601.17188
*   **Source URL:** https://arxiv.org/abs/2601.17188
*   **Reference Count:** 12
*   **Primary Result:** Empirical validation that Datalog rule evaluation and Einstein summation are mathematically equivalent, demonstrated via symbolic transitive closure, zero-shot compositional inference, and the Domingos superposition construction on FB15k-237.

## Executive Summary
This paper introduces Tensor Logic, a framework that unifies symbolic (Datalog) and neural reasoning by proving their computational equivalence through tensor contraction. The core mechanism maps recursive Datalog rules to iterative matrix multiplication followed by a non-linear threshold. Three experiments validate this: a symbolic computation of a biblical genealogy transitive closure; a neural model with learned relation matrices achieving perfect zero-shot compositional generalization; and an implementation of Domingos's superposition construction (`R_r = E^⊤ A_r E`) on FB15k-237, achieving competitive link prediction results and demonstrating multi-hop reasoning when direct edges are removed. The work provides a formal bridge between logical inference and differentiable tensor operations.

## Method Summary
The methodology centers on representing relational data as tensors (adjacency matrices) and logical rules as tensor contractions (Einstein summation). For symbolic reasoning (Experiment 1), a Boolean adjacency matrix is iteratively multiplied by itself, with a Heaviside step function thresholding counts to truth values, converging to a transitive closure. For neural reasoning (Experiments 2 & 3), entities are embedded as vectors and relations as matrices. Compositional inference is performed by chaining matrix multiplications. Experiment 2 uses directly learned relation parameters, while Experiment 3 computes relation matrices on-the-fly via the superposition construction, which sums outer products of head and tail embeddings over all training triples for a given relation.

## Key Results
*   Transitive closure of a 1,972-node biblical genealogy graph converged in 74 iterations, yielding 33,945 ancestor edges and passing full logical verification (containment, closure, acyclicity).
*   A model with learned relation matrices achieved 100% zero-shot accuracy on capital→continent compositional queries using geographic data.
*   The superposition construction on FB15k-237 yielded an MRR of 0.3068 on standard link prediction and 0.3346 on a compositional benchmark where direct edges were withheld during training.

## Why This Works (Mechanism)
**Mechanism 1 (Symbolic Rules ↔ Tensor Contraction):** Recursive Datalog rules (e.g., for transitive closure) are equivalent to iterative tensor contraction (matrix multiplication) with a non-linear threshold (Heaviside step). The product counts path instances; the step function thresholds counts to Boolean truth. Evidence: Experiment 1 explicitly implements `A_new = H(A + A × P)` to compute ancestry. Break condition: cycles in the input graph cause non-termination or incorrect self-ancestry, violating acyclicity.

**Mechanism 2 (Learned Matrices for Composition):** Learnable relation matrices (`M_r`) transform subject embeddings into predicted object embeddings. A chain of relations (e.g., `capital → country → continent`) is a product of matrices. Compositionality holds if linear transformations in embedding space preserve relational semantics. Evidence: Experiment 2's perfect zero-shot inference on geographic queries. Break condition: failure if matrices do not compose linearly due to poor optimization, embedding collapse, or insufficient training data for primitive relations.

**Mechanism 3 (Superposition Construction):** Domingos's construction `R_r = E^⊤ A_r E` creates a relation matrix as a sum of outer products `e_h^⊤ e_t` over training triples. This makes `R_r` a linear operator whose dot product with embeddings scores triples. Composition uses `e_a · R_r1 · R_r2`. Evidence: Experiment 3's strong results on FB15k-237 and its compositional benchmark. Break condition: generalization failure if superposition is noisy, embedding dimension `d` is insufficient, or relation composition is inherently non-linear.

## Foundational Learning
*   **Concept: Datalog rule evaluation (bottom-up fixpoint computation):** Needed to map iterative rule application to tensor steps. Quick check: For `Ancestor(x,z) :- Ancestor(x,y), Parent(y,z)`, one iteration of `A × P` computes all paths of length 2 (grandparent relationships).
*   **Concept: Einstein summation (einsum) and matrix multiplication as generalized join/projection:** The computational core. Quick check: In `np.einsum('xy,yz->xz', A, P)`, index `y` is summed over (join variable), while `x` and `z` remain (head variables).
*   **Concept: Gradient-based learning of embedding transformations:** Needed for Experiments 2 and 3. Quick check: In Experiment 2, the loss function (cross-entropy) trains `M_r` to rank true objects high; if `M_r` were random/frozen, the model could not learn any relational transformations and accuracy would be random.

## Architecture Onboarding
*   **Component map:** Data loader (facts → sparse matrices/batches) -> Entity embedding matrix E -> Relation parameterization (learnable M_r **or** computed R_r = E^⊤ A_r E) -> Tensor contraction engine (einsum/batch matmul) -> Scoring & loss (dot product + cross-entropy) -> Evaluation module (filtered ranking metrics).
*   **Critical path:** Input facts -> Build E and/or A_r -> Compute relation matrix (M_r or R_r) -> Contract (single or chain) -> Score all entities -> Compute loss -> Update E and/or M parameters.
*   **Design tradeoffs:** Boolean tensors (Exp 1) ensure exact logic but no learning; real-valued embeddings (Exps 2,3) trade exactness for generalization. Fixed `R_r` from superposition (Exp 3) ties relations directly to graph structure, while free `M_r` (Exp 2) allows learning from less structured data. Sparse `A_r` vs. dense `R_r` trades memory for composition speed.
*   **Failure signatures:** Exp 1: non-convergence or low edge count → cycle in input graph or incorrect einsum/threshold. Exp 2: training loss stuck or zero-shot failure → unnormalized embeddings, wrong composition order, or insufficient capacity/dimension. Exp 3: low standard MRR → poor embeddings; low compositional MRR → `R_r` not compositional or removed edges not properly excluded from training.
*   **First 3 experiments to implement:**
    1.  **Exp 1 (Transitive Closure):** Build Boolean parent matrix `P` from BibleData. Iterate `A = H(A + einsum('xy,yz->xz', A, P))` until fixpoint. Verify edge count, containment, and acyclicity.
    2.  **Exp 2 (Geographic Zero-Shot):** Train E (489x64) and M (2x64x64) on capital-country and country-region triples. Normalize E after each step. After training, for test capitals, compute `v_city @ M_capital @ M_located` and check top-1 is correct continent.
    3.  **Exp 3 (FB15k-237 Superposition):** Train E (14541x256) with unit norm. For each relation, compute `R_r = E.T @ A_r @ E` on-the-fly. Use bidirectional loss. First reproduce standard MRR ~0.30. Then, train on modified splits with 2000 direct edges removed and evaluate on the withheld paths using `e_a @ R_r1 @ R_r2`.

## Open Questions the Paper Calls Out
1.  Can Tensor Logic be extended to formalisms beyond Datalog, such as first-order logic with quantification, modal logics, or probabilistic reasoning?
2.  Can architectural enhancements (e.g., attention, history encoding) be integrated into Tensor Logic to achieve state-of-the-art performance on knowledge graph benchmarks while preserving logical interpretability?
3.  How can Tensor Logic be scaled to efficiently handle web-scale knowledge graphs with millions of entities?
4.  Does Tensor Logic support compositional reasoning with branching, negation, or aggregation in queries?

## Limitations
*   The exact set of 2,000 direct edges removed for the compositional benchmark in Experiment 3 is unreported, making that specific MRR irreproducible.
*   Random seeds for weight initialization and data shuffling are not provided, introducing uncontrolled variance in reported metrics.
*   The full list of capital cities evaluated in Experiment 2 is not given; only seven are shown, risking cherry-picking of the 100% zero-shot claim.

## Confidence
*   **Exp 1 (Datalog ↔ Tensor Contraction):** High – deterministic, symbolic experiment with verifiable logical properties.
*   **Exp 2 (Learned Matrix Composition):** Medium – perfect accuracy on a tiny subset is plausible but unconfirmed on the full capital set; normalization specifics could affect outcome.
*   **Exp 3 (Superposition on FB15k-237):** Medium – standard link prediction MRR is credible, but compositional benchmark depends on unreleased edge removal list and unknown seed sensitivity.
