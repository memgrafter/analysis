# SAE as a Crystal Ball: Interpretable Features Predict Cross-domain Transferability of LLMs without Training

## Quick Facts
*   **ArXiv ID:** 2603.02908
*   **Source URL:** https://arxiv.org/abs/2603.02908
*   **Reference Count:** 27
*   **Primary Result:** An SAE-based Transferability Score (STS), computed on a pre-trained model using in-context learning to estimate feature shifts, strongly correlates (Pearson ρ > 0.7) with actual supervised fine-tuning (SFT) performance gains across domains, enabling prediction without training.

## Executive Summary
This paper introduces a method to predict how much a large language model will improve on a new domain after supervised fine-tuning (SFT) on a specific training set, *without actually performing the fine-tuning*. The core technique uses a pre-trained model and its associated sparse autoencoder (SAE) to identify a small set of feature dimensions that are most affected by the SFT task. This set is estimated inexpensively via in-context learning (ICL) with the training examples. For any downstream domain, a transferability score (STS) is computed by measuring the activation magnitude of these pre-identified "shifted" dimensions. Experiments across multiple model architectures and MMLU-Pro domains show a high correlation between STS and the true post-SFT performance change, suggesting STS is an effective, training-free predictor of cross-domain transferability. The approach is extended preliminarily to reinforcement learning settings.

## Method Summary
The method uses a pre-trained LLM and a corresponding SAE (trained on the same model's residual stream) to estimate which feature dimensions are most likely to change ("shift") after SFT on a source dataset (e.g., LIMO for math). First, for a set of source samples, the SAE feature activations are computed both normally and when the samples are presented as in-context learning (ICL) demonstrations. The dimensions with the largest average activation difference between these two conditions are identified as the "estimated shifted dimensions." For a target downstream domain (e.g., a MMLU-Pro subject), the SAE-based Transferability Score (STS) is then calculated as either the average activation magnitude of these estimated dimensions on domain samples (`STS_act`) or the change in their activation when using domain examples as ICL prompts (`STS_ICL`). This score, computed entirely before any SFT, is correlated against the actual performance delta measured after training the model on the full source dataset.

## Key Results
*   STS correlates strongly with actual SFT performance changes across MMLU-Pro domains, achieving Pearson coefficients above 0.7 for multiple model families (Qwen2.5, Llama3, Gemma2).
*   The ICL-based estimation of shifted dimensions shows a significant overlap (e.g., >50% for top-100) with the dimensions that *actually* shift after SFT, validating ICL as a proxy for training-induced feature changes.
*   Ablation studies indicate STS performance is sensitive to the choice of SAE layer, hidden dimension size, and sparsity, with optimal results found at specific depths (e.g., middle layers) and with sufficiently monosemantic features.

## Why This Works (Mechanism)
The underlying assumption is that the feature space learned by a SAE provides a meaningful, approximately linear decomposition of the model's internal representations. Supervised fine-tuning (SFT) on a specific task (e.g., mathematical reasoning) induces a targeted update in the model's weights. This update primarily affects a sparse subset of features in the SAE basis—the "shifted dimensions"—which become more active for inputs related to the trained skill. In-context learning (ICL), by priming the model with the same training examples, temporarily activates a similar pattern of features without weight changes. Therefore, the dimensions most perturbed by ICL serve as a reliable proxy for the dimensions that will be permanently shifted by actual SFT. The STS then measures how naturally a new domain engages this pre-identified feature set, predicting the potential for beneficial transfer.

## Foundational Learning
*   **Sparse Autoencoders (SAEs):** A neural network trained to reconstruct model activations with a sparsity penalty, producing a higher-dimensional, interpretable feature basis where each dimension is intended to be monosemantic. *Why needed:* To decompose dense, entangled activations into a set of human-understandable, approximately linear features for analysis and scoring. *Quick check:* Can you explain why a sparsity constraint might lead to more interpretable features than a standard autoencoder?
*   **In-Context Learning (ICL):** The ability of LLMs to adapt behavior based on examples provided in the prompt, without parameter updates. *Why needed:* To simulate the effect of training (feature shifts) in a zero-cost, differentiable way on the pre-trained model. *Quick check:* How does the internal representation of a model differ when processing a query with relevant few-shot examples versus without?
*   **Transferability:** The degree to which knowledge or capabilities gained from training on one task (source) improve performance on a different, but related, task (target). *Why needed:* The core problem being predicted; a successful method identifies features that are common to both source and target. *Quick check:* What are two distinct mechanisms by which fine-tuning on a math dataset might improve performance on a science QA dataset?
*   **Feature Activation Magnitude:** The norm or average value of a specific feature's activation across samples. *Why needed:* The operational measure for STS; a domain that strongly activates the "shifted" features is predicted to transfer well. *Quick check:* If a feature is designed to detect logical reasoning, would you expect its activation magnitude to be higher on math problems or historical narratives?
*   **Residual Stream:** The hidden state vector connecting transformer layers, often used for mechanistic analysis. *Why needed:* The paper's SAEs are trained on residual stream activations, a central highway for information flow. *Quick check:* Where in a transformer block would you attach an SAE to capture the effect of an entire layer's computation?
*   **Pearson Correlation (ρ):** A statistical measure of linear correlation between two variables. *Why needed:* The primary evaluation metric linking the predicted STS score to the actual observed performance delta. *Quick check:* What does a Pearson ρ of 0.7 imply about the strength and direction of the relationship?

## Architecture Onboarding
*   **Component Map:**
    Pre-trained LLM + Pre-trained SAE -> ICL with Source Data (LIMO) -> Identify Top-N Shifted Dimensions -> For each Target Domain (MMLU-Pro) -> Compute STS (Activation Magnitude / ICL Change) -> Score
*   **Critical Path:** The most direct sequence involves: 1) Loading the model and its SAE. 2) Processing source dataset samples to compute feature activations both normally and within ICL prompts. 3) Ranking dimensions by activation difference to select the "shifted" set. 4) Applying this fixed set to all target domains to compute the final STS value. 5) Correlating the computed STS vector (over domains) with the vector of actual SFT performance changes (obtained from separate training runs).
*   **Design Tradeoffs:**
    *   **SAE Quality vs. Generalizability:** More monosemantic, higher-dimensional SAEs may provide a finer-grained signal but are harder to train and may overfit to specific data distributions. The paper uses a fixed set of published SAEs.
    *   **ICL Approximation Fidelity:** Using a small number of ICL demonstrations (2) is computationally cheap but may imperfectly capture the full, distributed weight change of SFT. This is a necessary approximation to avoid training.
    *   **Layer Selection:** Features from different layers capture different abstraction levels. The paper finds specific layers (e.g., 25 for Qwen/Llama) work best, suggesting a trade-off between high-level semantics and task-specific details.
*   **Failure Signatures:**
    *   **Low Correlation (ρ < 0.5):** Indicates the ICL-proxied shifted dimensions do not predict SFT shifts. Causes: Poor SAE quality (non-monosemantic, high reconstruction error), wrong layer chosen, or ICL prompt format/demonstration count mismatch.
    *   **High Variance in STS:** Unstable scores across different random seeds for ICL demonstrations or domain sample selections. Suggests the top-N shifted dimension set is not robust or the domain samples are not representative.
    *   **Mismatched Feature Distributions:** The raw (non-SAEs) feature shift distribution should be more uniform (as in Fig 1a), while SAE shifts should be sparse. If this pattern is not replicated, the SAE may not be properly aligned.
*   **First Three Experiments to Replicate:**
    1.  **Replicate Figure 1a (Distribution of Feature Shifts):** For a held-out LIMO sample, compute the raw activation change (layer norm) and SAE feature change (using the provided SAE) between normal and ICL (with 2 LIMO demos) conditions. Verify the raw shift is broadly distributed while the SAE shift is sparse.
    2.  **Compute STS for a Single Domain:** For a specific MMLU-Pro domain (e.g., "physics"), using the top-100 estimated shifted dimensions from step 1, compute `STS_act` and `STS_ICL` on 100 domain samples. Record the value.
    3.  **Measure ICL vs. SFT Shift Overlap:** Perform a minimal SFT run on a small LIMO subset (e.g., 10%). On a held-out math sample, compute the actual SFT-induced feature shift (difference between pre-SFT and post-SFT SAE activations). Calculate the percentage overlap (e.g., Jaccard) between the top-100 dimensions from this actual shift and the top-100 from the ICL estimation. Target: >50% as claimed.

## Open Questions the Paper Calls Out
*   **Open Question 1:** How can the shifted dimensions for RL post-training be accurately estimated before training in the absence of ground-truth answers, and what alternative demonstration strategies (e.g., synthetic rollouts, model-generated trajectories) could improve the overlap with actual shifted dimensions?
    *   **Basis in paper:** [explicit] The paper explicitly states that RL lacks ground-truth answers for ICL demonstrations, leading to poor overlap between estimated and actual shifted dimensions (Section 6, Figure 6a), and identifies accurate estimation of shifted dimensions in RL as the "future direction."
    *   **Why unresolved:** The current method for RL uses the same SFT procedure (ground-truth CoTs), which is inapplicable. The core mechanism of RL-induced feature shifts (policy gradients, reward modeling) likely differs fundamentally from SFT, making SFT-based dimension estimators inadequate.
    *   **What evidence would resolve it:** A study comparing different RL-specific demonstration sources (e.g., best-response rollouts from reward model, trajectories from a pre-trained policy) against actual post-RL shifted dimensions across multiple RL algorithms (PPO, GRPO) and tasks, measuring both overlap and downstream STS correlation.

*   **Open Question 2:** To what extent does the predictive power of STS depend on the specific choice of SAE (architecture, training data, sparsity, layer), and can a theoretically grounded principle for SAE selection be established to maximize transferability prediction robustness across diverse models and tasks?
    *   **Basis in paper:** [inferred] The ablation studies (Section 4.3) show STS performance varies with SAE hidden dimensions, sparsity (L0 norm), and layer choice, but these are limited to three models. The paper assumes the enhanced monosemanticity from SAEs is crucial but does not systematically define "good" SAEs for STS.
    *   **Why unresolved:** The experiments use a handful of existing SAEs (mostly from prior work) without a controlled study optimizing SAE hyperparameters for the STS objective. The relationship between monosemanticity metrics and STS correlation is not established, leaving the "why" of SAE dependence open.
    *   **What evidence would resolve it:** A large-scale evaluation training multiple SAEs per layer with varied hyperparameters for a single model family, measuring both monosemanticity scores (e.g., automated feature interpretability) and the Pearson correlation between STS and actual performance shifts across domains. Correlating these metrics would yield a selection principle.

*   **Open Question 3:** Are the SAE dimensions identified as "shifted" by the ICL estimator truly causal for the performance change, or are they merely correlated proxies? Could intervening on these dimensions (e.g., via activation patching or steering vectors) alter the actual transferability outcome, confirming a causal role?
    *   **Basis in paper:** [inferred] The method identifies statistical overlap between ICL-induced and SFT-induced shifts (Section 3.2, Figure 2a). The zeroing experiment (Figure 1b) shows removed shifted dimensions hurt task performance, but this is post-SFT and does not prove causality for the *transfer* phenomenon. The link between correlation in feature space and mechanistic change is assumed.
    *   **Why unresolved:** The evidence is correlational: STS predicts performance shifts but does not demonstrate that modifying the identified dimensions controls the shift. It remains possible that shifted dimensions are epiphenomena—correlated with but not driving the capacity transfer.
    *   **What evidence would resolve it:** An intervention study: 1) Use activation patching to *preserve* the shifted dimensions during SFT (e.g., clamp their activations to pre-SFT values). 2) Conversely, *inject* the shifted dimension pattern of a beneficial domain into a model SFT on a detrimental domain. If performance shifts are mitigated or reversed respectively, it would strongly support a causal role of these dimensions in transfer.

## Limitations
*   **Implementation Details Opaque:** Exact SAE checkpoints (training data, layer, context length, sparsity penalty) and precise ICL prompt formatting are not fully specified, making exact replication dependent on matching unpublished configurations.
*   **Reliance on SAE Quality:** The entire method assumes the provided SAEs are sufficiently monosemantic and aligned with the model's internal computations. Invalid or low-quality SAEs would produce meaningless STS values.
*   **ICL as Imperfect Proxy:** The core assumption that ICL-induced feature shifts perfectly predict SFT-induced shifts is validated only by correlation (overlap), not by mechanistic equivalence. The method may fail for domains or models where ICL dynamics diverge significantly from gradient-based learning.

## Confidence
*   **STS correlation claim (ρ > 0.7):** **Medium** – Depends on faithful replication of SAEs, ICL procedure, and domain-matched data splits. The signal is strong in the paper but vulnerable to implementation drift.
*   **ICL as proxy for SFT feature shifts:** **Low** – The paper shows significant overlap (>50%) but does not establish a theoretical bound or test across diverse architectures/tasks. The RL failure highlights its fragility.
*   **Preliminary RL extension:** **Low** – Anecdotal results with a different demonstration strategy; no systematic experiments or strong correlation shown.
