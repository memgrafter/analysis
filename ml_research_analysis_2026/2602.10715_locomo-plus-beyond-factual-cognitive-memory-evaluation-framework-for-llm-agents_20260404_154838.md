# Locomo-Plus: Beyond-Factual Cognitive Memory Evaluation Framework for LLM Agents

## Quick Facts
- **arXiv ID:** 2602.10715
- **Source URL:** https://arxiv.org/abs/2602.10715
- **Reference count:** 25
- **Primary result:** Cognitive memory performance drops up to ~26 points compared to factual memory and collapses rapidly as dialogue length increases, revealing a persistent challenge unaddressed by current benchmarks.

## Executive Summary
LoCoMo-Plus is a new benchmark designed to evaluate cognitive memory in LLM agents—the ability to retain and apply implicit constraints like user state, goals, or values—beyond explicit factual recall. It introduces cue-trigger pairs where a later query semantically differs from an earlier cue but requires applying the latent constraint it encodes. The benchmark replaces task-disclosed prompts and string-matching metrics with a unified constraint-consistency evaluation framework. Experiments across diverse models and memory systems reveal a substantial and consistent performance gap between factual and cognitive tasks, with cognitive memory degrading far more severely as dialogue grows longer.

## Method Summary
LoCoMo-Plus extends the LoCoMo benchmark by constructing dialogues containing implicit cues that encode persistent cognitive constraints (state, goal, value, causal). A trigger query, semantically disconnected from the cue, is inserted later in a long dialogue. Correct resolution requires applying the constraint. The evaluation pipeline uses unified conversational queries (no task instructions) and judges responses via constraint consistency—whether the output lies within the valid response space defined by the latent constraint—using an LLM-as-a-judge approach. Benchmark construction involves automated generation (LLM prompts), semantic filtering (BM25 + MPNet), and human validation for memory-worthiness and genuine elicitation.

## Key Results
- Models show a consistent performance gap of up to ~26 points between factual (LoCoMo) and cognitive (LoCoMo-Plus) tasks.
- Cognitive memory exhibits rapid collapse as dialogue length increases, while factual (episodic/object) memory degrades more linearly or remains robust.
- The gap persists across model families (open/closed-source) and memory systems (RAG, A-Mem, Mem0, SeCom), indicating a fundamental unresolved challenge.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** LoCoMo-Plus evaluates cognitive memory by requiring models to retain and apply implicit constraints (state, goal, value, causal) under cue-trigger semantic disconnect.
- **Mechanism:** The benchmark constructs dialogues where a "cue" implicitly conveys a latent constraint. A later "trigger" query does not semantically resemble the cue but whose correct resolution depends on applying that constraint. The model must preserve the constraint across long-context interference and generate a response consistent with it.
- **Core assumption:** Appropriate conversational behavior in realistic settings often depends on inferred, persistent internal states or goals rather than explicit factual recall. Performance can be measured by whether a response lies within the valid output space defined by that latent constraint.
- **Evidence anchors:**
  - [abstract]: Introduces LoCoMo-Plus for "cognitive memory under cue–trigger semantic disconnect, where models must retain and apply latent constraints across long conversational contexts."
  - [section 3]: Defines Level-2 Cognitive Memory as retaining "implicit constraints such as user state, goals, preferences, values, or causal context" and formulates correctness as membership in a constraint-induced valid response space \(A_c\).
  - [section 4]: Details the construction pipeline (implicit cue dialogue generation, semantic filtering to ensure disconnect, insertion into long dialogues) to create cue-trigger pairs.
  - [corpus]: Weak direct evidence; neighboring papers (e.g., EvolMem, MMAG) also explore multi-dimensional memory but LoCoMo-Plus uniquely operationalizes *semantic disconnect* for *implicit constraints*.
- **Break condition:** If the semantic filtering (BM25 + MPNet) fails to sufficiently decouple cue and trigger lexically/semantically, models could use shallow pattern matching instead of constraint application.

### Mechanism 2
- **Claim:** The proposed constraint-consistency evaluation framework yields more reliable and comparable assessment of memory capabilities than task-disclosed prompts and string-matching metrics.
- **Mechanism:** By removing explicit task-type instructions from the input (unified conversational query) and judging output based on whether it satisfies the implicit constraint (rather than n-gram overlap with a single reference), the evaluation decouples memory fidelity from prompt adaptation and generation style. This reduces biases that distort cross-task and cross-model comparisons.
- **Core assumption:** Standard evaluation metrics (EM, F1, BLEU, ROUGE) are misaligned with assessing the semantic validity of open-ended responses constrained by prior context, as they penalize stylistic variation and reward length matching over conceptual correctness.
- **Evidence anchors:**
  - [abstract]: States that "conventional string-matching metrics and explicit task-type prompting are misaligned" and proposes a "unified evaluation framework based on constraint consistency."
  - [section 5]: Systematically analyzes input-side (task disclosure) and output-side (generation metrics) biases. Figure 5 shows task disclosure distorts performance distribution across task types. Figure 6 demonstrates clear length bias in traditional metrics.
  - [section 6.4]: Shows LLM-as-a-judge for constraint consistency has high human agreement (Table 2) and stability across judge backbones (Table 3), supporting its reliability for this judgment task.
  - [corpus]: Weak; related work (e.g., "LLMs-as-judge" surveys) supports using LLM judges for semantic evaluation, but LoCoMo-Plus specifically applies it to *constraint satisfaction*.
- **Break condition:** If constraint-consistency judgments themselves prove inconsistent across different judge models/human annotators for cognitive cases, or if the judge prompts fail to capture the nuanced valid response space \(A_c\).

### Mechanism 3
- **Claim:** Cognitive memory exhibits a fundamentally different and more severe length-sensitivity profile than factual (object/episodic) memory, revealing a persistent challenge not captured by existing benchmarks.
- **Mechanism:** As dialogue length increases, interference from intervening turns disproportionately disrupts the retention and application of latent, behaviorally constraining signals (goals, values, states) compared to the recall of localized, explicit facts. This leads to a rapid collapse in performance on cognitive tasks, whereas factual memory degrades more linearly (episodic) or remains robust (object).
- **Core assumption:** The cognitive memory components (goal, value, state, causal) are less salient, more abstract, and more susceptible to contextual interference than concrete episodic facts. Existing benchmarks, focusing on explicit recall, do not stress this vulnerability.
- **Evidence anchors:**
  - [abstract]: Notes "Cognitive memory exhibits rapid collapse as dialogue length increases, revealing a persistent, unresolved challenge."
  - [section 6.5]: Figure 7 quantitatively contrasts length sensitivity: Object memory PDR/RTR remains high (~93%/96%), episodic memory decays linearly (PDR/RTR ~67%/72%), but cognitive memory collapses (PDR/RTR ~6%/18%) as context grows.
  - [section 6.2]: Observes that "cognitive memory remains challenging" across all model families and memory systems, with a "substantial and consistent" performance gap (up to ~26 points) from factual memory.
  - [corpus]: Supporting evidence from neighbors like *EvolMem* (multi-session memory challenges) and *Mem-Gallery* (long-term multimodal memory) also find long-context memory difficult, but LoCoMo-Plus isolates the *implicit constraint* aspect as the key differentiator.
- **Break condition:** If the rapid collapse found in Figure 7 is an artifact of the specific LoCoMo-Plus instance distribution (e.g., cue/trigger placement) rather than a general property of cognitive memory, or if other benchmark designs with implicit constraints show similar sensitivity.

## Foundational Learning
- **Concept: Cue-Trigger Semantic Disconnect**
  - *Why needed:* This is the core design principle of LoCoMo-Plus. It prevents models from relying on surface-level matching between query and memory content. The trigger must be answered using the cue, yet they should share minimal lexical/semantic overlap.
  - *Quick check:* If a model correctly answers a trigger query by retrieving a sentence containing words from the query itself (not the earlier cue), does that demonstrate cognitive memory? Why or why not?
- **Concept: Constraint-Consistency vs. String-Matching Evaluation**
  - *Why needed:* The paper's central methodological contribution. Understanding this shift is key to interpreting results. It moves from a single "correct answer" to a space of "valid answers" defined by an implicit constraint.
  - *Quick check:* For a user who earlier stated "I'm saving for a house down payment," is the response "I'll skip the concert to save money" more or less correct than "I bought the concert tickets"? What is the underlying constraint?
- **Concept: Decomposition of Cognitive Memory (Causal, State, Goal, Value)**
  - *Why needed:* Provides the taxonomy for building and analyzing the benchmark. Each component represents a different type of latent, persistent information that can constrain behavior.
  - *Quick check:* Classify this trigger: Cue: "After my panic attack, I've been practicing mindfulness daily." Trigger (months later): "I canceled my crowded weekend plans." Is this primarily State, Goal, Causal, or Value memory?

## Architecture Onboarding
- **Component map:**
  Cue Dialogue Generator -> Trigger Query Generator -> Semantic Filter -> Human Validator -> Dialogue Embedder -> Evaluation Engine
- **Critical path:** Cue Generation → Trigger Generation → Semantic Filtering → Human Validation → Embedding into Long Dialogue → Model Inference → Constraint-Consistency Judgment.
- **Design tradeoffs:**
  - *Scale vs. Diagnostic Depth:* LoCoMo-Plus prioritizes high-quality, validated instances (~hundreds) over large-scale automatic generation (thousands) to ensure genuine cognitive memory testing. This limits its use for training but maximizes diagnostic value.
  - *Automation vs. Human Judgment:* Heavy reliance on LLMs for generation and judging, with human validation only at key filtering points. This enables scale but introduces potential biases from the generator/judge models themselves.
  - *Constraint Definition:* Choosing a coarse 4-component taxonomy (causal/state/goal/value) improves clarity but may not capture all nuanced forms of implicit memory (e.g., relational dynamics, emotional valence).
- **Failure signatures:**
  - *Benchmark Construction:* Low inter-annotator agreement during human validation; high failure rate of generated cues/triggers passing filters.
  - *Model Evaluation:* High variance in judge scores across different judge backbones for the same model responses; models performing similarly on factual and cognitive tasks (indicating benchmark may not be discriminating).
  - *System Behavior:* RAG/retrieval systems returning highly relevant *but semantically similar* snippets, accidentally satisfying the cue-trigger connection via shallow matching.
- **First 3 experiments:**
  1.  **Bias Quantification:** Replicate Section 6.3. For a fixed model (e.g., GPT-4o), run evaluation on LoCoMo-Plus cognitive instances with (a) unified query vs. task-disclosed query, and (b) constraint-consistency judge vs. EM/F1. Measure performance delta to confirm prompt and metric biases.
  2.  **Length Sensitivity Replication:** Replicate Figure 7 for your own model/system. Select 100 cognitive, 100 episodic, 100 object instances. Truncate the embedding dialogues at varying turn counts (e.g., 5, 10, 15, 20, 25). Plot performance decay curves. A steep drop for cognitive tasks confirms the core finding.
  3.  **Judge Reliability Spot-Check:** Sample 50 cognitive instances. Have two human annotators label them using the constraint-consistency protocol (binary: correct/wrong). Have one LLM judge (e.g., Gemini-2.5-Flash) label the same set. Compute pairwise agreement. If agreement is low (<0.8), the judge prompt or constraint definition may need refinement for your specific subset.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can LoCoMo-Plus be systematically extended to evaluate long-term belief revision, emotional dynamics, and multi-agent memory interactions, given its current focus on single-agent, state-goal-value-causal constraints?
  - *Basis in paper:* [explicit] The Limitations section explicitly states that LoCoMo-Plus "does not model long-term belief revision, emotional dynamics, or multi-agent memory interactions."
  - *Why unresolved:* These aspects are central to human memory and realistic conversational agents but are omitted to maintain diagnostic focus. Incorporating them requires new data construction pipelines and validation criteria that can capture evolving internal states and interactive memory.
  - *What evidence would resolve it:* Development of new cue-trigger paradigms that simulate belief updates, emotional carryover, or shared memory across agents, followed by human validation that these instances genuinely require the targeted cognitive processes. Performance drop patterns on such extensions would also clarify their distinct difficulty.
- **Open Question 2:** What methods can scale LoCoMo-Plus from a small, diagnostic benchmark to a larger dataset suitable for training or fine-tuning models, without compromising the quality and memory-specificity of its cognitive instances?
  - *Basis in paper:* [explicit] The Limitations note that LoCoMo-Plus "prioritizes diagnostic value over scale" and is "smaller than large-scale factual QA benchmarks and unsuitable for training."
  - *Why unresolved:* Current construction relies heavily on human verification for memory-worthiness and cue-trigger validity, making scaling costly. Automated alternatives risk introducing noise or shortcuts that degrade the benchmark's purpose.
  - *What evidence would resolve it:* A scalable semi-automated pipeline where LLM-generated candidates are filtered by robust classifiers trained on human-annotated quality signals, with a small human-validated subset used to calibrate and verify the automated process. Correlation between model performance on scaled vs. original sets would indicate success.
- **Open Question 3:** How can the constraint-consistency evaluation framework be stabilized against variability in LLM judge choice and prompt design, given the acknowledged sensitivity?
  - *Basis in paper:* [explicit] The Limitations state that evaluation "may remain sensitive to the choice of judge model and prompt design," and the Reliability section tests only two judge backbones.
  - *Why unresolved:* While judge agreement with humans is high, different judges or prompt formulations could yield score distributions that affect conclusions, especially near decision boundaries. This threatens reproducibility and cross-study comparability.
  - *What evidence would resolve it:* A large-scale study measuring score variance across a diverse set of judge models (open/closed, varied sizes) and multiple prompt templates, using a fixed set of responses. Development of a standardized, validated judge prompt or an ensemble judging protocol that minimizes variance would provide a robust solution.
- **Open Question 4:** What fundamental mechanisms in current LLMs cause the rapid collapse of cognitive memory performance as dialogue length increases, compared to the robustness of object and episodic memory?
  - *Basis in paper:* [inferred] The Length Sensitivity Analysis (Figure 7) shows cognitive memory (PDR=5.88%, RTR=18%) decays much faster than episodic memory (PDR=67.39%, RTR=72%) and object memory (PDR=92.85%, RTR=96%) as turns grow.
  - *Why unresolved:* The paper demonstrates the phenomenon but does not analyze its root cause. Possibilities include attention dilution, inability to maintain latent representations over time, or training objectives that favor surface recall. Identifying the cause is key to architectural improvements.
  - *What evidence would resolve it:* Controlled experiments isolating factors like context window management, retrieval-augmented vs. full-context modeling, and probing hidden states for latent constraint representations. Success would be a consistent predictor (e.g., attention entropy, memory index accuracy) that correlates with the collapse rate across model families.
- **Open Question 5:** Are the four latent constraint types (causal, state, goal, value) exhaustive for cognitive memory in conversation, or are there other implicit dimensions (e.g., trust, relational dynamics, identity) that should be included?
  - *Basis in paper:* [inferred] The paper defines cognitive memory as decomposed into these four components (Section 3, Figure 2) but does not claim exhaustiveness. The examples in Appendix C focus on these types, leaving room for other psychological or social constraints.
  - *Why unresolved:* Human conversations encode many subtle, persistent signals beyond individual goals or values. Missing categories could lead to blind spots in evaluation and model development.
  - *What evidence would resolve it:* A user study or corpus analysis of real-world long-term dialogues to identify recurring implicit constraints that influence responses but are not captured by the current taxonomy. Extending LoCoMo-Plus with instances representing new categories and measuring model performance gaps would validate their relevance.

## Limitations
- Exact dataset construction parameters (splits, instance counts) and full judge prompt specifications are undisclosed, preventing exact replication.
- Heavy reliance on LLM-driven generation and judging introduces potential hidden biases; human validation is limited to selective filtering steps.
- Benchmark size (hundreds of instances) may lack statistical robustness for fine-grained analysis and limit generalizability across domains.

## Confidence
- **C1 (LoCoMo-Plus tests implicit constraint retention via semantic disconnect):** Medium – Conceptually sound and human-validated, but depends on unreported construction details and possible residual surface overlap.
- **C2 (Constraint-consistency evaluation mitigates prompt/metric bias):** Medium – Bias analysis and judge agreement data are compelling, yet judge prompt nuances and cross-model stability remain partially unknown.
- **C3 (Cognitive memory collapses sharply with dialogue length):** Medium – Pattern is clear in reported results, but could be an artifact of specific instance distribution; independent replications with varied dialogues are needed.
