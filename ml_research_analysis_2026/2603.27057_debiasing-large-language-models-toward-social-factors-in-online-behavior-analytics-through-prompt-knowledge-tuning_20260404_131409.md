# Debiasing Large Language Models toward Social Factors in Online Behavior Analytics through Prompt Knowledge Tuning

## Quick Facts
* **ArXiv ID**: 2603.27057  
* **Source URL**: https://arxiv.org/abs/2603.27057  
* **Reference Count**: 25  
* **Primary Result**: A self‑generated knowledge prompt technique consistently improves macro‑F1 scores (e.g., Llama3 on intent detection: 80.8 → 88.7) by mitigating social‑attribution bias in zero‑shot social media classification.

## Executive Summary
The paper tackles *social‑attribution bias* in instruction‑following LLMs, where models unevenly weight dispositional (user goal) versus situational (context) causes, harming zero‑shot classification of social media content. The proposed solution is a scalable prompt engineering method: the LLM automatically generates instance‑specific knowledge aids (user goal for intent, message context for theme) and reasons with them before predicting. Evaluated on mono‑ and multi‑lingual disaster‑domain datasets, the three‑step pipeline yields robust macro‑F1 improvements over strong baselines (Zero‑CoT, Self‑Debias) across Llama3, Mistral, and Gemma, with high faithfulness of the generated knowledge confirmed by human evaluation.

## Method Summary
The approach introduces a three‑stage pipeline applied at inference time without external resources or fine‑tuning.  
1. **Knowledge Generation**: For a given input text, the LLM is prompted to produce a concise statement of the user’s underlying goal (dispositional factor) and a summary of the situational context.  
2. **Reasoning**: The generated knowledge is inserted into a follow‑up prompt that asks the model to reason about the classification task, explicitly considering both factors.  
3. **Prediction**: The final label is produced based on the reasoning trace. This enrichment mitigates the model’s default reliance on a single causal perspective, thus debiasing the decision-making process.

## Key Results
* Macro‑F1 scores improve consistently across all three model families; e.g., intent detection (Lilac) with Llama3: 80.8 → 88.7.
* Gains hold for both mono‑ and multi‑lingual disaster datasets and are robust to temperature and label order permutations.
* Human evaluation indicates the self‑generated knowledge is highly faithful and helpful in supporting predictions.

## Why This Works (Mechanism)
Social‑attribution bias occurs when the model defaults to either dispositional or situational explanations, skewing predictions. By explicitly generating and presenting both the user’s goal (dispositional) and the surrounding context (situational) as part of the prompt, the model is forced to reconcile the two perspectives during reasoning. This balanced grounding reduces over‑reliance on a single causal lens and leads to more accurate, nuanced classifications, especially in ambiguous social media posts.

## Foundational Learning
1. **Social‑attribution bias** – The tendency to over‑weight either internal (dispositional) or external (situational) causes when explaining behavior. *Why needed?* It defines the core problem the method addresses. *Quick check?* Measure performance disparity on test sets where dispositional and situational cues are artificially balanced.
2. **Prompt engineering** – Crafting input text to steer LLM behavior without parameter changes. *Why needed?* The technique relies on carefully designed prompts to generate and use knowledge. *Quick check?* Validate that a simple prompt template yields the intended structured output on a few examples.
3. **Zero‑shot classification** – Making predictions without task‑specific fine‑tuning. *Why needed?* The evaluation setting; the method must work in this resource‑constrained regime. *Quick check?* Compare zero‑shot predictions to a random or majority baseline on a held‑out set.
4. **Self‑generated knowledge** – Using the LLM itself to produce explanatory or intermediate content. *Why needed?* It provides the instance‑specific cues that debias the model. *Quick check?* Assess relevance and conciseness of generated knowledge via spot checks or automated metrics (e.g., BLEU against gold explanations).

## Architecture Onboarding
**Component Map**: Knowledge Generation → Reasoning → Prediction  
**Critical Path**: Accurate knowledge generation → effective incorporation during reasoning → correct final label.  
**Design Tradeoffs**: Using the same LLM for all stages simplifies the pipeline but risks error propagation; the additional generation step increases latency but avoids external data dependencies.  
**Failure Signatures**: (i) Generated knowledge is irrelevant or hallucinated; (ii) reasoning stage ignored the knowledge; (iii) prediction remains biased despite knowledge injection.  
**First Experiments**:  
1. Replicate the Lilac intent detection experiment with Llama3 using the published prompts.  
2. Extend evaluation to Mistral and Gemma models, comparing against Zero‑CoT and Self‑Debias.  
3. Test robustness by varying temperature values (0.1–0.9) and permuting label order in the prompt.

## Limitations
* Domain generalizability is unproven beyond disaster‑related social media (e.g., e‑commerce, political discourse).  
* Cascading errors may occur if the LLM’s self‑generated knowledge is inaccurate or irrelevant.  
* Human evaluation details (annotator demographics, sample size, rubric) are lacking, limiting confidence in the faithfulness claim.

## Confidence
- **High**: Performance gains on disaster‑domain datasets across three model families (consistent macro‑F1 improvements).  
- **Medium**: Robustness to temperature and label ordering variations (tested but not exhaustive).  
- **Low**: Generalizability to other domains; thoroughness of the human evaluation process.

## Next Checks
1. **Cross‑Domain Replication**: Apply the pipeline to at least two non‑disaster social media datasets (e.g., product reviews, political hashtags) to test domain portability.  
2. **Error Mode Analysis**: Manually inspect 200+ generated knowledge instances across models to quantify hallucination rates and correlation with prediction errors.  
3. **Blind Human Evaluation**: Conduct a rigorous study with diverse annotators (≥5 per instance) to re‑evaluate knowledge faithfulness and helpfulness using a standardized rubric, reporting inter‑annotator agreement.
