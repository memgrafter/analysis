# Deep Learning-based Method for Expressing Knowledge Boundary of Black-Box LLM

## Quick Facts
- **ArXiv ID:** 2602.10801
- **Source URL:** https://arxiv.org/abs/2602.10801
- **Reference count:** 36
- **Primary result:** LSCL significantly outperforms baseline models, achieving up to 0.699 F1-score and 0.691 recall rate on MMedBench and CFLUE; a variant without token probabilities also surpasses baselines.

## Executive Summary
Large language models (LLMs) often hallucinate because they cannot express their knowledge boundaries. This paper introduces LSCL, a deep learning method that uses a question, the LLM’s answer, and the token probability to predict a calibrated confidence score (CATP). An adaptive thresholding module then classifies the LLM’s knowledge state into “Know”, “Sciolism” (uncertain), or “Unknow”. Evaluated on Chinese medical (MMedBench) and finance (CFLUE) benchmarks with three black-box LLMs, LSCL yields substantial improvements over baselines, with F1-scores up to 0.699 and recall up to 0.691. A prompt-guided variant for models without token probabilities also performs strongly, demonstrating robustness.

## Method Summary
LSCL comprises two components. (1) **Confidence Learning Module**: a deep network that ingests the question text, the LLM-generated answer, and the maximum token probability from greedy decoding (p_Â). BERT encodes the question and answer separately; 1D convolutions extract local patterns; multi-head attention models interactions between question and answer features. Additional features include cosine similarity between embeddings and an embedding of p_Â. These are concatenated and processed by self-attention to regress a confidence score ĉ. The training loss combines Huber loss (to match true CATP), an MSE term pulling ĉ toward a trust-weighted combination of p_Â and its complement, and a penalty to encourage conservative predictions near 0/1 boundaries. SMOTE oversampling balances confidence bins. (2) **Adaptive Thresholding Module**: after training, a grid search over predicted confidences on the training set finds thresholds t1 and t2 that maximize Macro-F1 for the three-class decision: “Know” if ĉ ≥ t1, “Sciolism” if t2 < ĉ < t1, “Unknow” if ĉ ≤ t2.

## Key Results
- LSCL achieves up to 0.699 F1-score and 0.691 recall, significantly outperforming baseline methods on MMedBench and CFLUE.
- The prompt-guided variant (for models without token probabilities) performs close to the token-based version and still surpasses all baselines.
- The method is effective across multiple black-box LLMs (Qwen2-7B, Qwen-flash, Doubao-flash) and Chinese medical/finance domains.

## Why This Works (Mechanism)
LSCL works by learning to map the semantic content of a question-answer pair and the LLM’s token-level uncertainty (p_Â) to a calibrated confidence that correlates with correctness. Token probability provides a direct but often miscalibrated signal of the model’s internal certainty. The deep network integrates this signal with contextual features from the question and answer, enabling it to correct for miscalibration and capture patterns that indicate overconfidence or uncertainty. The adaptive thresholding then translates the continuous confidence into discrete knowledge states based on empirical accuracy, effectively separating “knowing” (high accuracy), “sciolism” (moderate accuracy), and “unknowing” (low accuracy). This decoupling of confidence estimation and decision boundaries allows flexible adaptation to different datasets and models.

## Foundational Learning
- **Token Probability (p_Â)**  
  *Why needed:* Provides a raw, model-specific uncertainty estimate from the LLM’s output distribution; serves as a base signal for confidence calibration.  
  *Quick check:* Verify that p_̂ values cluster near 1 for correct answers and near 0 for incorrect ones in a small labeled subset.
- **Calibrated Confidence Score (CATP)**  
  *Why needed:* Serves as the regression target during training; defined as p_Â if answer correct else 1−p_Â, ensuring the model learns to predict a score aligned with actual correctness.  
  *Quick check:* Plot histogram of CATP values; should show two modes near 0 and 1 with a mixture in between.
- **Confidence Learning Module (Deep Network)**  
  *Why needed:* Learns a mapping from (question, answer, p_Â) to a well-calibrated confidence, correcting for the limitations of using raw token probability alone.  
  *Quick check:* On a validation set, compute correlation between predicted confidence and accuracy; should be strongly positive (e.g., >0.8).
- **Adaptive Thresholding**  
  *Why needed:* Converts continuous confidence into interpretable knowledge states (“Know”, “Sciolism”, “Unknow”) with thresholds optimized for Macro-F1.  
  *Quick check:* After training, run grid search on training confidences; ensure found thresholds separate classes with clear accuracy gaps.
- **SMOTE Oversampling**  
  *Why needed:* Mitigates extreme class imbalance in confidence bins, preventing the model from ignoring low-confidence (“Unknow”) samples.  
  *Quick check:* Compare class distribution before and after SMOTE; minority class samples should be significantly increased.

## Architecture Onboarding
Component map:  
Input (q, Â, p_Â) -> BERT Encoder (e_q, e_A) -> 1D Convolution (x_q, x_A) -> Multi-head Attention (x_related) + Cosine Similarity (x_diff) -> Concatenation with x_p (p_Â embedding) -> Self-Attention -> Confidence Prediction (ĉ). Parallel: p_Â -> selection gate (w0) for loss modulation. Training: Loss (Huber + MSE + penalty) with SMOTE. Post-training: Grid search on ĉ_train -> thresholds (t1, t2). Inference: ĉ -> thresholds -> class.

Critical path: The core learning flow is encoding → local feature extraction (conv, attention) → global integration (self-attention) → confidence regression. Thresholding is a separate post-processing step that depends on training set predictions.

Design tradeoffs:
- Using token probability alone is simple but poorly calibrated; combining with semantic features improves calibration at the cost of model complexity.
- SMOTE oversampling helps with imbalance but may introduce synthetic samples that are not representative, potentially harming generalization.
- Grid search for thresholds is straightforward and data-driven but risks overfitting to the training distribution and is computationally heavy for large confidence ranges.

Failure signatures:
- Incorrect p_Â aggregation (e.g., product instead of average) distorts CATP distribution and prevents meaningful learning.
- Severe class imbalance persists if SMOTE parameters are poorly chosen, leading to near-zero recall for “Unknow”.
- Threshold overfitting manifests as a large gap between training Macro-F1 and test Macro-F1; thresholds may be too aggressive or conservative on new data.
- Architectural mismatches (e.g., wrong BERT dimension or conv parameters) cause shape errors or loss of information, detectable by debugging tensor shapes.

First three experiments:
1. **Token Probability Aggregation Test**: Implement multiple plausible definitions for p_Â (average max token probability, geometric mean, product). Compute CATP distributions and select the definition that yields a distribution with modes near 0 and 1, as described in the paper.
2. **Confidence-Accuracy Correlation Check**: Train a minimal version of the Confidence Learning Module on a small subset. Evaluate on a held-out set: plot predicted confidence vs. empirical accuracy. Expect a strong positive correlation (>0.8) if the module learns properly.
3. **SMOTE Impact Validation**: Train LSCL with and without SMOTE. Compare per-class recall (especially “Unknow”) on a validation set. If “Unknow” recall remains below 0.1, SMOTE is ineffective; test alternative oversampling strategies or class weighting.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can the classification performance for the “Unknow” knowledge state be substantially improved, given its persistently low accuracy and high misclassification rates across all LLMs and datasets? Extreme data imbalance and diversity of low-confidence cases cause bias toward high-confidence predictions; current SMOTE augmentation is insufficient.
- **Open Question 2:** For black-box LLMs lacking token probability outputs, how can Prompt-guided LSCL be made reliably consistent with the original token-based LSCL’s performance, eliminating observed instability and gaps? Self-reported confidences via prompts are inherently noisy and uncalibrated; current calibration may not fully compensate.
- **Open Question 3:** Can the adaptive thresholding module’s grid search be replaced with a dynamic, data-driven method that efficiently determines optimal thresholds (t1, t2) without overfitting to the training distribution, enhancing generalization? Grid search is computationally intensive and may yield thresholds overly tailored to the training set.

## Limitations
- **Implementation ambiguities:** Critical details like BERT variant, 1D convolution parameters, and attention head count are underspecified, forcing assumptions that may diverge from the authors’ exact design.
- **Token probability definition ambiguity:** The scalar p_Â derivation (e.g., average max probability vs. sequence probability) is unclear; incorrect aggregation distorts the core CATP target and degrades performance.
- **Threshold selection protocol:** Thresholds are derived solely from training set predictions, risking overfitting and poor generalization to new data or different LLMs.

2. **Held-Out Threshold Validation:** After determining thresholds (t1, t2) via grid search on the training set, evaluate Macro-F1 on a separate held-out validation set. A significant drop (>5-10%) indicates threshold overfitting; consider using a validation set for threshold selection instead.
