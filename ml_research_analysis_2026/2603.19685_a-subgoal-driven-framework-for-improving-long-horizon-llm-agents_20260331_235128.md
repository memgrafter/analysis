# A Subgoal-driven Framework for Improving Long-Horizon LLM Agents

## Quick Facts
- **arXiv ID**: 2603.19685
- **Source URL**: https://arxiv.org/abs/2603.19685
- **Reference count**: 40
- **Primary result**: On WebArena-Lite, the subgoal-driven framework improves Gemini-2.5-pro by 9.1 percentage points (23.0% → 32.1%) and MiRA training boosts Gemma3-12B from 6.4% to 43.0%, surpassing GPT-4 models and reducing the "Get Stuck Midway" failure from ~33% to ~21%.

## Executive Summary
Long-horizon planning remains a major challenge for LLM-based web agents. This paper introduces a two-pronged framework: (1) a dynamic online planning mechanism that breaks tasks into subgoals and verifies progress at each step using an LLM-as-judge (AutoRater), and (2) MiRA, an offline RL algorithm that densifies sparse terminal rewards via a learned potential function derived from subgoal completions. Evaluated on the WebArena-Lite benchmark, the approach yields substantial improvements. The real-time planning component raises the success rate of Gemini-2.5-pro by 9.1 percentage points, while MiRA applied to Gemma3-12B increases success from 6.4% to 43.0%, outperforming GPT-4-Turbo and GPT-4o. Moreover, the dominant "Get Stuck Midway" failure mode is reduced from approximately 33% to 21%, demonstrating more robust long-horizon reasoning.

## Method Summary
The method consists of an online subgoal-driven planner and a reinforcement learning training pipeline (MiRA). During inference, a teacher model (Gemini-2.5-pro) generates a fixed set of subgoals from the initial task description. At every time step, the agent undergoes a reflection loop: its past trajectory is analyzed, and an AutoRater (another Gemini-2.5-pro instance) labels which subgoals are already satisfied. The current binary subgoal completion vector is incorporated into the agent’s prompt, conditioning its next action. This dynamic re-planning prevents error propagation and helps recover from deviations.

For training, MiRA operates in an offline RL setting. The agent’s replay buffer contains trajectories annotated with computed progress labels based on subgoal completions (linear interpolation between milestones, anchored to the trajectory end). Two critics are maintained: a value critic \(V_\phi\) trained on binary success labels via cross-entropy, and a potential critic \(P_\psi\) trained by regression to predict the dense progress scores. The auxiliary reward \(r' = r + \alpha (P_\psi(s_{t+1}) - P_\psi(s_t))\) (with \(\alpha=0.3\)) is added to the sparse outcome reward \(r\). The actor \(\pi_\theta\) is updated by minimizing a squared loss between its log-ratio to a reference policy \(\pi_{\text{ref}}\) and a doubly-robust advantage estimate that combines TD and Monte-Carlo returns. To continuously improve the agent, an iterative curriculum is employed: after each RL phase, a failure analyzer categorizes errors (e.g., Stuck Midway, Wrong Termination) and identifies key decision steps; the task generator then either resamples semantically similar tasks from a pool or synthesizes new instructions targeting underrepresented failures. The replay buffer is filtered by trajectory perplexity under \(\pi_{\text{ref}}\), retaining a ranked band (0.5–0.9) to ensure high-quality transitions. This closed-loop curriculum progressively patches the agent’s weak spots, leading to substantial gains in long-horizon success.

## Key Results
- Real-time subgoal planning improves Gemini-2.5-pro success by 9.1 pp (23.0% → 32.1%) on WebArena-Lite.
- MiRA training raises Gemma3-12B success from 6.4% to 43.0%, exceeding GPT-4-Turbo (17.6%) and GPT-4o (13.9%).
- The "Get Stuck Midway" failure rate drops from ~33% to ~21% after applying the framework.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Dynamic subgoal verification during inference prevents error propagation in long-horizon web navigation by forcing the agent to explicitly assess progress against semantically meaningful checkpoints before each action.
- **Mechanism:** At each timestep, the agent performs retrospective reflection on its history, queries an AutoRater (LLM-as-Judge) to determine which subgoals are complete, and uses this verified state vector to condition its next action. This transforms opaque execution into structured state tracking, allowing the agent to detect stagnation or deviation and re-plan accordingly.
- **Core assumption:** Subgoals generated by a capable teacher model (Gemini-2.5-pro) serve as reliable, monotonic progress indicators that correlate with final success. The agent’s internal reflection can accurately ground these subgoals against observed states.
- **Evidence anchors:**
  - [abstract] "the real-time planning mechanism improves Gemini-2.5-pro by 9.1 percentage points (23.0%→32.1%)"
  - [section 5.2] "forces the agent to 'think' before acting... The AutoRater determines that a required milestone is not yet satisfied, this enhanced context prevents the agent from hallucinating progress"
  - [corpus] Neighbors like *WebAnchor* and *Why Do LLM-based Web Agents Fail?* independently identify planning instability and lack of subgoal coherence as primary failure modes, confirming the mechanism's relevance.
- **Break condition:** If subgoal generation becomes unreliable for new website structures (violating assumption of monotonic correlation), the verification signal becomes misleading and may actively harm performance by penalizing valid alternative paths.

### Mechanism 2
- **Claim:** Potential-based reward shaping using a learned progress model (Potential Critic) densifies sparse terminal rewards, enabling effective credit assignment over long horizons without altering the optimal policy.
- **Mechanism:** MiRA trains a separate network \(P_\psi(s,g)\) to regress onto continuous progress labels derived from subgoal completion vectors. During RL, the shaping reward \(r_{\text{aux}} = \alpha(P_\psi(s_{t+1},g) - P_\psi(s,g))\) is added to the sparse outcome reward. The main value critic \(V_\phi\) is trained only on final success, ensuring the auxiliary signal accelerates learning but does not bias the final objective.
- **Core assumption:** Subgoal completion vectors provide a valid, dense supervision signal that correlates with proximity to the true goal across successful trajectories. Training the potential critic exclusively on positive traces ensures the learned landscape reflects efficient procedural paths.
- **Evidence anchors:**
  - [abstract] "MiRA applied to Gemma3-12B boosts success from 6.4% to 43.0%"
  - [section 5.3] "progress labels \(p^*_t \in [0,1]\) through linear interpolation between key steps... The potential critic fills this gap by estimating the 'distance' to the next subgoal"
  - [corpus] *WebRL* and *WebATLAS* papers confirm that sparse rewards and credit assignment are fundamental bottlenecks; MiRA’s shaped auxiliary reward directly addresses this.
- **Break condition:** If the subgoal-to-success correlation degrades (e.g., subset of tasks where subgoals are not sequentially necessary), the potential critic may learn a misleading landscape that reinforces suboptimal intermediate behaviors.

### Mechanism 3
- **Claim:** An iterative curriculum that automatically generates harder tasks from failure analysis progressively patches the agent’s weak spots, transforming static overfitting into continual capability expansion.
- **Mechanism:** After each RL phase, trajectories are analyzed to identify failure modes and key decision steps. The task generator then samples semantically similar tasks from a pool or synthesizes new instructions targeting rare failure types. This creates a closed loop where weaknesses directly inform the next training distribution.
- **Core assumption:** Failures are informative and classifiable; the set of human-selected tasks (1,573) and synthetic generation can effectively cover the distributional shift needed to address identified weaknesses without requiring manual intervention.
- **Evidence anchors:**
  - [section 4] "automated failure analyzer that systematically uncovers the dominant failure modes"
  - [section 5.4] "transform the training process into an online curriculum of offline RL phases, where each iteration learns from the agent’s most recent failures"
  - [section 6.2.2] "MiRA steadily improves from an initial SR of ~31% to 43%, while the baseline RL model without subgoal shaping saturates near 35%"
- **Break condition:** If failure analysis becomes inaccurate (e.g., cannot correctly identify key decision steps), the curriculum may address non-critical errors and waste training budget, leading to diminishing returns or performance plateaus.

## Foundational Learning
### Potential-Based Reward Shaping
- **Why needed here:** MiRA’s auxiliary reward builds on PBRS theory to ensure that dense intermediate rewards do not alter the optimal policy. The paper assumes familiarity with how potential functions preserve optimality when differences are added to rewards.
- **Quick check:** If you add a shaping reward \(r_{\text{aux}} = \gamma\Phi(s') - \Phi(s)\) to the environment reward, what condition on \(\Phi\) guarantees the optimal policy remains unchanged?

### Goal-Conditioned RL
- **Why needed here:** Web navigation is formulated as a goal-conditioned POMDP where each episode has a distinct instruction. The value critic \(V(s,g)\) estimates probability of success for a specific goal, not environment visitation alone.
- **Quick check:** In WebArena, why is it necessary to condition value functions on the task instruction \(I\) rather than just the state \(s\)?

### Hierarchical Planning & Subgoal Decomposition
- **Why needed here:** The core innovation is breaking long tasks into milestones. Understanding how subgoals differ from full trajectories (semantic vs. concrete) and how they enable re-planning is essential.
- **Quick check:** What is the difference between a subgoal (milestone) used for planning versus an action in the agent’s primitive action space?

## Architecture Onboarding
#### Component map
1. Subgoal Generator: Gemini-2.5-pro prompted with task intent + initial screenshot → 4 explicit milestones (fixed granularity).
2. Online Agent: Base LLM (Gemini for SGO, Gemma for MiRA) that takes (instruction, history, HTML) and emits actions.
3. AutoRater / SubGoal Checker: LLM-as-Judge (Gemini-2.5-pro) that verifies at step t which milestones are complete given the trace.
4. Potential Critic \(P_\psi\): Pretrained on successful trajectories with interpolated progress labels; outputs dense progress [0,1].
5. Value Critic \(V_\phi\): Trained on binary success labels; predicts final goal probability.
6. Experience Buffer: Stores trajectories with (s,a,r,r_aux, progress label). Filtered by perplexity to keep high-quality transitions.
7. Failure Analyzer: Categorizes errors (Stuck Midway, Wrong Termination, etc.) and identifies key divergence steps.
8. Task Generator: Resamples from pool based on semantic similarity to failures or synthesizes new tasks for underrepresented failure types.

#### Critical path
1. Inference (SGO): For each step, run reflection loop → get subgoal status → condition next action. (Latency-critical: reflection quality and AutoRater trust directly impact runtime)
2. Training (MiRA): Offline RL loop: sample batch → compute shaped rewards using \(P_\psi\) → estimate advantages with doubly-robust estimator → regress actor log-ratios → update critics.
3. Curriculum: After K phases, run Auto Analyzer on failures → generate next phase task set → redeploy actor → repeat.

#### Design tradeoffs
- Exact vs. graded subgoals: Paper finds exact equivalence low (F1=0.68) but monotonic grading strong (AUROC=0.84). Treat subgoals as continuous progress signals, not hard constraints.
- Static vs. dynamic thinking budget: Fixed token budgets (e.g., 8192) improve accuracy but add ~19s/step; dynamic allocation achieves similar SR with lower latency. Implement reactive compute: only deepen reflection if AutoRater confidence is low.
- Offline vs. online RL: MiRA uses offline RL for stability and to leverage replay buffers. Pure online (e.g., PPO) may adapt faster but risks instability from noisy reward signals.

#### Failure signatures
- Potential Critic collapse: If \(P_\psi\) predictions are non-monotonic or decrease mid-trajectory, shaping is harmful. Monitor Kendall’s τ during warmup training; should be >0.4.
- Perplexity filter mis-set: Too restrictive (only very low PPL) yields boring, uninformative transitions; too permissive (high PPL tail) includes noise. Use [0.5, 0.9] rank score band (1/PPL) as validated in Appendix A.8.
- Subgoal checker mismatches: Disagreement between AutoRater and true progress causes wrong shaping. Ensure the same model (Gemini-2.5-pro) used for training and inference consistency.

#### First 3 experiments
1. Reproduce Figure 4: Validate subgoal quality on a held-out set of 100 WebArena-Lite tasks. Compute AUROC and Kendall’s τ for completion vector vs. success. If AUROC <0.8, revisit subgoal prompt.
2. Ablation: Remove potential critic: Train MiRA with α=0 (only sparse reward). Expect SR to plateau at ~35% on Gemma3-12B, confirming shaping necessity.
3. Ablation: KL vs. MSE policy update: Implement the KL objective (Eq. 19) and compare to MSE (Eq. 8). Expect KL to underperform by ~10% because it cannot downweight bad actions and requires on-policy data.

## Limitations
- Exact subgoal generation prompt and RL hyperparameters (β, λ) are unspecified; critic architectures, SFT data provenance, perplexity threshold derivation, and task resampling details are missing.
- Reliance on proprietary Gemini-2.5-pro for subgoals and AutoRater limits reproducibility.
- Core assumptions (monotonic subgoal correlation, accurate failure analysis) lack exhaustive validation.
