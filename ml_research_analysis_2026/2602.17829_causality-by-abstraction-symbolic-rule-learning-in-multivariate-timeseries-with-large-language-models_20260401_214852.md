# Causality by Abstraction: Symbolic Rule Learning in Multivariate Timeseries with Large Language Models

## Quick Facts
*   **arXiv ID:** 2602.17829
*   **Source URL:** https://arxiv.org/abs/2602.17829
*   **Reference Count:** 35
*   **Primary Result:** A framework (ruleXplain) uses an LLM and diverse counterfactuals from a simulator to extract interpretable temporal causal rules, achieving accurate output reconstruction and generalization to unseen patterns without domain-specific priors.

## Executive Summary
This paper introduces **ruleXplain**, a framework for learning interpretable symbolic causal rules from black-box simulators of multivariate timeseries with delayed effects. The core idea is to generate a diverse set of counterfactual input trajectories that produce the same target output, cluster these examples, and use a large language model (LLM) to abstract them into formal rules with temporal operators (e.g., `□[t1,t2]Trend → ♢[t3,t4]Phase`). A closed-loop refinement process iteratively tests and improves the rules by feeding their generated inputs back into the simulator. The approach is validated on epidemic (PySIRTEM) and building energy (EnergyPlus) simulators, showing that the learned ruleset can reconstruct baseline outputs and generalize to new output patterns, effectively encoding causal dynamics without requiring predefined domain knowledge.

## Method Summary
The `ruleXplain` pipeline operates in a closed loop. First, an optimization module (`PLEARN`) uses a black-box optimizer (TPE) to generate multiple diverse input timeseries `X^p` that, when fed into the simulator, produce outputs `Y_sim^p` closely matching a provided baseline `Y_base`. Diversity is enforced to explore the space of equivalent causes. These input trajectories are then dimensionality-reduced (UMAP) and clustered (K-Means). Cluster centroids, paired with `Y_base`, serve as a concise context for an LLM, which is prompted with a constrained symbolic grammar to synthesize an initial rule set `R`. The LLM then uses `R` to generate a novel input `X'`, which is simulated to produce `Y'`. The deviation `L_out(Y', Y_base)` is fed back to the LLM, which diagnoses mismatches and refines `R`. This cycle repeats until reconstruction error converges or a threshold is met.

## Key Results
*   The closed-loop refinement process consistently decreases the reconstruction loss `L_out` between simulated and baseline outputs over iterations for both application domains.
*   The final extracted ruleset generalizes to generate inputs that produce new, unseen output patterns (e.g., different epidemic curves, altered energy peaks), demonstrating that the rules encode abstract causal structure rather than memorizing a specific trajectory.
*   Validation shows the framework successfully encodes causal dynamics without any injected domain-specific priors, relying solely on the simulator's input-output behavior and the LLM's in-context learning.

## Why This Works (Mechanism)

### Mechanism 1: Counterfactual Generation for Functional Equivalence
- **Claim:** The framework discovers causal rules by analyzing *diverse counterfactual input trajectories* that yield the same target output.
- **Mechanism:** The `PLEARN` optimization module generates multiple input timeseries `X^p` that minimize output deviation `L_out` from `Y_base` while enforcing a diversity penalty `D_arch` against previously found solutions. This creates a set of inputs that produce functionally equivalent outputs, highlighting the *space of possible causes* for the observed effect.
- **Core assumption:** A black-box simulator exists that maps inputs to outputs and is amenable to black-box optimization. The system has sufficient input degrees of freedom to produce the same output via different trajectories.
- **Evidence anchors:** [abstract] mentions generating diverse counterfactuals; [section 2.1] details the `PLEARN` optimization objective.
- **Break condition:** The optimizer fails to find a diverse set of inputs that reconstruct `Y_base` (high `L_out` persists), indicating the simulator's output is overly sensitive to inputs or input space constraints are too restrictive.

### Mechanism 2: LLM Synthesis from Clustered Context
- **Claim:** An LLM synthesizes interpretable, temporally-grounded causal rules from clustered examples of these counterfactual inputs.
- **Mechanism:** Counterfactual inputs are reduced (UMAP) and clustered (K-Means). Cluster centroids provide a *diverse but non-redundant* context for the LLM. The LLM is prompted with a *constrained symbolic language* (temporal operators □, ♢, delay semantics) to abstract common input trend patterns (e.g., `SlowRise`) and their delayed link to output phases (e.g., `PeakFormation`).
- **Core assumption:** The LLM possesses sufficient *in-context learning* and *symbolic reasoning* capability to generalize from a small set of examples to a formal ruleset. The predefined trend and phase vocabularies are expressive enough for the dynamics.
- **Evidence anchors:** [abstract] cites structured prompting with LLM; [section 2.3] details the prompting strategy, vocabulary, and logical form `□[t1,t2](Trends)→♢[t3,t4]Phase`.
- **Break condition:** The LLM generates syntactically invalid rules, rules that do not cover the timeline, or rules that fail to capture the delay relationship, leading to poor reconstruction in the next loop.

### Mechanism 3: Closed-Loop Simulation-Based Refinement
- **Claim:** A *closed-loop simulation-based refinement* iteratively improves rule validity by testing rule-generated inputs against the simulator.
- **Mechanism:** The LLM uses the current ruleset `R_i` to generate a novel input `X'`. The simulator produces `Y'`. The deviation `L_out(Y', Y_base)` is fed back to the LLM, which diagnoses mismatches (e.g., timing, magnitude) and refines `R_i` to `R_{i+1}`. This grounds symbolic rules in empirical simulator feedback.
- **Core assumption:** The *ruleset itself is the primary carrier of causal knowledge*. Rule modifications can systematically correct for observed simulator output discrepancies. The LLM can correctly attribute output errors to specific rule flaws.
- **Evidence anchors:** [abstract] mentions closed-loop refinement; [section 2.3] details the Generate, Simulate & Evaluate, and Update Rules steps; [section 3.2/Fig 8] shows decreasing loss across iterations.
- **Break condition:** The refinement loop diverges (error increases) or stagnates (no improvement), indicating the ruleset's structure or the LLM's refinement reasoning is insufficient, or the simulator introduces noise/unmodeled effects.

## Foundational Learning
- **Concept: Symbolic Temporal Logic with Delay**
  *Why needed here:* The framework translates continuous timeseries dynamics into discrete, human-interpretable rules with explicit temporal windows and delays. This abstraction is the core "explanation" output.
  *Quick check:* Given a rule `□[10,20](SlowRise(X1)∧High(X2))→♢[25,35]PeakFormation(Y)`, what is the minimum delay between the end of the input window and the start of the output phase?

- **Concept: Counterfactual Generation for Functional Equivalence**
  *Why needed here:* Multiple inputs can produce the same output in complex dynamical systems. Generating a *diverse set* of such inputs is crucial for the LLM to learn the *invariant* causal patterns rather than spurious correlations.
  *Quick check:* Why is the diversity term `D_arch` in `PLEARN` necessary? What would happen if only `L_out` was minimized?

- **Concept: In-Context Learning (ICL) for Structured Generation**
  *Why needed here:* The LLM is not fine-tuned. It must generate syntactically strict, table-formatted rules from context examples. This relies on the LLM's pre-trained ability to follow complex, structured prompts and adhere to a specified grammar.
  *Quick check:* What are the risks of providing *too many* clustered examples as context to the LLM for rule generation?

## Architecture Onboarding
- **Component map:**
  Baseline & Simulator -> PLEARN -> Clustering (UMAP + K-Means) -> LLM Rule Engine (Generate R, Generate X', Refine R) -> Validation Harness (L_out, Convergence) --(feedback)--> LLM Rule Engine

- **Critical path:** `Y_base` -> `PLEARN` (find diverse `X^p`) -> `Clustering` (select centroids) -> `LLM` (generate `R_0`) -> `LLM` (generate `X'` from `R_i`) -> `Simulator` (`Y'`) -> `Validation` (`L_out`) -> `LLM` (refine to `R_{i+1}`) -> repeat until convergence -> `R_final`. The path is *closed-loop*: rule quality is validated by feeding it back through the simulator.

- **Design tradeoffs:**
  - **Simulator Access vs. Black-Box:** Requires full forward simulator access (`Y = f(X)`). Cannot work with offline observational data alone.
  - **Abstraction Power vs. Fidelity:** The constrained vocabulary `T`, `P` limits expressiveness but ensures interpretability and verifiability. May miss nuances if the vocab is too coarse.
  - **LLM Prior vs. Ground Truth:** Relies on LLM's pretrained knowledge of temporal patterns and logical structures. Performance may degrade for highly novel system dynamics not represented in its training corpus.
  - **Computational Cost:** `PLEARN` + multiple LLM calls per iteration + simulator runs is expensive. Clustering reduces but does not eliminate LLM context size issues.

- **Failure signatures:**
  1.  **High & Stagnant `L_out`:** `PLEARN` cannot find diverse solutions, or LLM-generated `X'` is consistently invalid (out of bounds, rule-violating).
  2.  **LLM Produces Invalid Rules:** Syntax errors, non-unique output phases, windows not covering full timeline, or ignoring delay semantics.
  3.  **Rule Refinement Divergence:** `L_out` increases after refinement, suggesting the LLM misdiagnoses mismatches or makes harmful rule edits.
  4.  **Poor Generalization:** `R_final` fails to generate inputs for a new `Y'_base`, indicating overfitting to the specific `Y_base`/context or capturing simulator artifacts, not causal structure.

- **First 3 experiments:**
  1.  **Reconstruction Efficacy (Q1):** Run full pipeline. Verify `L_out(Y_final, Y_base)` decreases iteratively and final `Y_final` visually aligns. Validates the closed-loop mechanism.
  2.  **Ablation: Ruleset vs. Context (Q2):** Test three conditions: (S1) LLM with only `Y_base` (no rules/context), (S2) LLM with `R_final` only, (S3) LLM with `R_final` + cluster context. Compare `L_out`. Isolates the ruleset's causal encoding power.
  3.  **Generalization to Unseen Dynamics (Q3):** Apply `R_final` (from original `Y_base`) to a new `Y'_base` with different phase patterns (prominent vs. non-prominent). Also test with a deliberately corrupted `R_incorrect`. Measure if `Y'_final` aligns with `Y'_base`. Tests abstraction vs. memorization.

## Open Questions the Paper Calls Out
- **Open Question 1:** Can ruleXplain recover the true causal mechanisms of simulators with known dynamics, or does it merely approximate input-output mappings without capturing underlying generative rules?
  *Basis:* The paper explicitly states the framework "does not aim to recover the 'ground-truth' generative rules" (Discussion). Validation is limited to reconstruction accuracy; no comparison to known simulator equations/parameters.
  *What would resolve:* Test on simulators with transparent dynamics (e.g., PySIRTEM's DDEs), extract rules, and quantitatively compare to ground-truth logical formulas (precision/recall).

- **Open Question 2:** How does ruleXplain's fidelity, interpretability, and robustness compare to established symbolic rule learners or interpretable time-series methods (e.g., shapelet-based classifiers, symbolic regression) on the same black-box simulator tasks?
  *Basis:* Authors acknowledge they "do not benchmark against existing symbolic rule learners or interpretable predictors" (Discussion). Evaluation is internal reconstruction loss and qualitative phase alignment.
  *What would resolve:* Apply competing methods (e.g., greedy shapelet discovery, sparse regression with temporal operators) to PySIRTEM/EnergyPlus, comparing rule complexity, interpretability scores, and generalization to unseen outputs.

- **Open Question 3:** Can the closed-loop refinement process be fully automated—removing manual specification of qualitative constraints—while maintaining or improving rule quality and convergence?
  *Basis:* Future work proposes exploring "agentic approaches to autonomously introduce logical constraints scalably and systematically" (Section 4). Current refinement requires human analysts to add constraints based on observed mismatches.
  *What would resolve:* Implement an LLM-based agent that automatically diagnoses output deviations and generates constraint modifications, then evaluate convergence speed, final error, and rule consistency against manual refinement baseline.

## Limitations
- The framework requires a perfect, noise-free simulator for counterfactual generation and loop validation; real-world simulator stochasticity or unmodeled dynamics could break the process.
- Success hinges on the LLM's ability to strictly adhere to a constrained symbolic grammar and correctly abstract trends; performance may degrade for dynamics poorly represented in the LLM's training corpus.
- Predefined trend/phase vocabularies may be too coarse to capture nuanced real-world behaviors, limiting fidelity even with low reconstruction error.
- Validation is limited to two curated simulators; generalization to more complex, high-dimensional, or noisy real-world systems remains unproven.

## Confidence
- **Reconstruction efficacy (closed-loop refinement reduces `L_out`):** *Medium*. Demonstrated on two simulators, but hyperparameter tuning is not fully explored.
- **Symbolic rule abstraction as causal encoding:** *High*. The grammar and process are well-specified and validated via reconstruction, though "causal" is inferred from simulator equivalence, not interventional data.
- **Generalization to unseen output patterns:** *Low*. Generalization tests are narrow (different phase prominence, one incorrect rule); no stress tests on entirely novel dynamics.

## Next Checks
1.  **Noise robustness test:** Inject Gaussian/process noise into `Y_base` and/or simulator outputs. Measure degradation in `L_out` convergence and rule validity. Checks tolerance to imperfect observability.
2.  **Vocabulary stress test:** Manually augment `T/P` vocabularies with finer descriptors (e.g., `Oscillate`, `Decay`) and re-run. Compare reconstruction error and rule complexity to assess expressiveness limits.
3.  **Cross-simulator generalization:** Apply ruleset learned from PySIRTEM to a novel epidemiological simulator (e.g., SEIR-based) with identical output shapes. Measure if `X'` from `R` produces comparable `Y'`. Tests abstraction beyond one simulator's idiosyncrasies.
