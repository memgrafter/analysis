# StackPlanner: A Centralized Hierarchical Multi-Agent System with Task-Experience Memory Management

## Quick Facts
- **arXiv ID**: 2601.05890
- **Source URL**: https://arxiv.org/abs/2601.05890
- **Reference count**: 38
- **Primary result**: Hierarchical multi-agent system with task-experience memory management achieves state-of-the-art F1 scores (32.92%, 16.48%, 7.71%, 16.23%) on 2Wiki, MusiQue, GAIA, and FRAMES benchmarks

## Executive Summary
StackPlanner addresses long-horizon coordination instability in centralized multi-agent systems by introducing a hierarchical architecture with explicit task memory and experience memory management. The system decouples high-level coordination from sub-agent execution, employing active memory operations like condensation and pruning to reduce context noise. A structured experience memory enables retrieval and reuse of past coordination patterns, enhancing cross-task generalization. Experimental results demonstrate state-of-the-art performance across multiple benchmarks, with ablation studies confirming the essential role of both memory modules.

## Method Summary
StackPlanner is a hierarchical multi-agent framework centered around a centralized coordinator that manages task memory (update, condense, prune operations) and experience memory (user profiles, semantic memory, procedural memory). The system employs specialized sub-agents (Search Agent, Report Agent) for execution while the coordinator handles high-level planning through actions like PLAN, DELEGATE, and REVISE. Training occurs via reinforcement learning with Group Relative Policy Optimization (GRPO) on curated datasets, particularly 2WikiMultiHopQA. The framework explicitly addresses context bloat and error accumulation through active memory management strategies.

## Key Results
- Achieves state-of-the-art F1 scores of 32.92% on 2Wiki benchmark
- Demonstrates strong performance with 16.48% on MusiQue, 7.71% on GAIA, and 16.23% on FRAMES datasets
- Ablation studies confirm both task memory and experience memory are essential for robust performance

## Why This Works (Mechanism)
StackPlanner works by explicitly managing memory at two levels: task memory handles the immediate context of ongoing coordination, while experience memory stores reusable patterns from past interactions. The centralized coordinator can actively condense and prune task memory to prevent context bloat, while structured experience memory enables retrieval of relevant past patterns. This dual-memory approach addresses the fundamental challenge of long-horizon coordination instability by maintaining focused context and leveraging accumulated experience.

## Architecture Onboarding

**Component Map**: Central Coordinator -> Task Memory Stack (update/condense/prune) -> Sub-Agents (Search Agent, Report Agent) -> Experience Memory (user profiles, semantic memory, procedural memory)

**Critical Path**: User Query → Central Coordinator (PLAN) → Task Memory Update → Sub-Agent Delegation → Task Execution → Memory Condensation → Experience Storage/Retrieval → Final Output

**Design Tradeoffs**: Centralized coordination provides stability but introduces potential bottlenecks; memory management adds overhead but prevents context collapse; hierarchical structure simplifies complexity at the cost of some flexibility.

**Failure Signatures**: Context bloat manifests as degraded coordination stability; ineffective memory retrieval shows as poor cross-task generalization; reward signal issues appear as unstable RL training.
