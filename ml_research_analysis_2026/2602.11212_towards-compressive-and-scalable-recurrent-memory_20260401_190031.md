# Towards Compressive and Scalable Recurrent Memory

## Quick Facts
- **arXiv ID:** 2602.11212
- **Source URL:** https://arxiv.org/abs/2602.11212
- **Reference count:** 39
- **Primary result:** Elastic Memory achieves lower perplexity (PPL) and long-context PPL (LongPPL) than baselines on three 32k+ token datasets while using significantly less memory and scaling efficiently with model size.

## Executive Summary
Transformers suffer from quadratic attention costs for long contexts, and existing memory methods often trade theoretical soundness for scalability. This paper introduces Elastic Memory, a novel approach grounded in the HiPPO framework for optimal online compression of historical key/value sequences into a fixed-size state. The compressed state evolves via a linear recurrence derived from discretizing a continuous-time ODE. For retrieval, polynomial sampling—a flexible mechanism that reconstructs a history summary by evaluating Legendre polynomials at chosen sample points—allows the model to control temporal bias at test time without retraining. Experiments on long-document datasets (PG-19, Proof-Pile, FineWeb-Edu) with sequences exceeding 32k tokens show that Elastic Memory consistently outperforms baselines (Memorizing Transformer, Infini-Transformer, Melodi) in both standard and long-context perplexity. With equal parameters, it matches Memorizing Transformer’s performance using 16× less memory and surpasses Melodi even when Melodi has 30% more parameters. The method scales efficiently with model size, maintains a speed advantage at larger scales, and its decoupled design enables practical test-time adjustments, offering a principled and scalable solution to the long-context challenge.

## Method Summary
Elastic Memory augments a Transformer layer with a recurrent memory module. Two fixed-size buffers per layer store the HiPPO state—coefficients of a Legendre polynomial approximation of the incoming key and value streams. As each token block (e.g., 2048 tokens) is processed, the state updates linearly: `C_i = P_i C_{i-1} + ¯K_i K_raw`, where `P_i` and `¯K_i` are precomputed position-dependent matrices derived from the HiPPO-LegS recurrence via zero-order hold discretization. These matrices are computed offline for all block indices and stored in a bank.

During the forward pass, for block `i>0`, the previous memory state is retrieved by applying a reconstruction matrix `R_{i-1}` to `C_{i-1}`. `R_{i-1}` encodes a polynomial sampling strategy (uniform or exponential) and produces `L_mem` memory tokens, which are prepended to the current block’s keys/values. Attention then uses a trapezoidal causal mask: queries attend fully to memory tokens and causally within the current block. Memory tokens are not positionally encoded (no RoPE), while current keys/queries use standard RoPE. The separation between state update (HiPPO) and retrieval (sampling) allows the sampling strategy to be swapped at test time without retraining. The approach adds no learned parameters; memory overhead per layer is `2·N·d_model` (N = HiPPO dimension). In practice, memory is injected at a single intermediate layer (layer 9) to balance compression and detail.

## Key Results
- **Lower perplexity on long contexts:** Elastic Memory achieves reduced PPL and LongPPL compared to baselines on three datasets with sequences >32k tokens.
- **Memory efficiency:** With equal parameters, it matches Memorizing Transformer’s performance using 16× less memory and outperforms Melodi even when Melodi has 30% more parameters.
- **Scalability and flexibility:** The method scales efficiently with model size, remains faster than Melodi at 4× scale, and its decoupled design allows test-time bias injection via sampling strategy changes.

## Why This Works (Mechanism)

### Mechanism 1: HiPPO-LegS provides optimal online compression
- **Claim:** HiPPO-LegS provides an optimal, incremental compression of historical key/value sequences into a fixed-size state by treating them as samples from continuous signals.
- **Mechanism:** The method projects the evolving 1D signal (per feature dimension) onto an orthonormal Legendre polynomial basis. The coefficients become the memory state. The state evolves via a linear ODE (Eq. 3), discretized into a recurrence (Eq. 4), enabling constant-time updates. This minimizes the L2 error of the polynomial approximation over the uniform measure on the expanding interval [0, t].
- **Core assumption:** The discrete key/value sequences are samples from underlying continuous, smooth (low-frequency) signals, and uniform weighting of history is appropriate.
- **Evidence anchors:** The abstract states the method is "grounded in the HiPPO framework for online function approximation... applying optimal online compression." Section 2.1 formalizes the optimization problem (Eqs. 1-2) and explains the core idea: reframing memory as online function approximation. The corpus shows limited prior work applying HiPPO to KV compression, highlighting novelty.
- **Break condition:** Compression fails for non-smooth signals (e.g., high-frequency noise). Appendix B.1 shows reconstruction MSE remains high (~0.9+) for random noise regardless of HiPPO dimension N, indicating the basis cannot compress incompressible signals.

### Mechanism 2: Polynomial sampling enables flexible, position-aware retrieval
- **Claim:** Polynomial sampling enables flexible, position-aware retrieval from the compressed HiPPO state, allowing control of temporal bias without retraining.
- **Mechanism:** Precomputed reconstruction matrices (Eq. 7) are built by evaluating Legendre basis functions at chosen sample points. The sample points (uniform or exponential) determine which history parts are emphasized during reconstruction (Eq. 8). This linear reconstruction inherently encodes temporal position via non-linear basis evaluations.
- **Core assumption:** Retrieval quality depends primarily on the set of temporal coordinates at which the signal is reconstructed, not on external positional embeddings. The learned HiPPO state generalizes to different sampling grids.
- **Evidence anchors:** The abstract mentions a "flexible polynomial sampling mechanism that reconstructs a history summary." Section 2.3 defines the reconstruction bank, sampling strategies, and notes that "the position information is mathematically intrinsic to each reconstructed vector." Section 3.5 empirically validates: test-time injection of a different sampling strategy changes performance, proving decoupling.
- **Break condition:** Retrieval fails if sample points misalign with task information needs. Section 3.5 shows uniform sampling best for LongPPL (long-range keys) while exponential best for PPL (average tokens). Using a mismatched strategy degrades performance relative to the matched one.

### Mechanism 3: Decoupled design enables test-time bias injection and efficient scaling
- **Claim:** The decoupling of the compressed state representation (HiPPO update) from the retrieval mechanism (polynomial sampling) allows test-time injection of inductive biases and efficient scaling.
- **Mechanism:** The HiPPO update (Eq. 6) produces a state C that is a complete history representation. The retrieval step (Eq. 8) is a separate linear operation using a precomputed matrix R derived from the desired sampling strategy. This separation means R can be changed at test time without altering C or the update rule.
- **Core assumption:** The HiPPO state is sufficiently rich that different linear projections can extract summaries tuned for different temporal biases.
- **Evidence anchors:** The abstract notes the "decoupled design allows for injecting inductive biases at test-time." Sections 2.3 and 3.5 describe the precomputed bank and test-time swap experiment: "We test the flexibility... by training a model with one sampling strategy and evaluating it with another, without any retraining." Tables 5 and 6 show performance shifts when swapping strategies, confirming decoupling.
- **Break condition:** The state lacks information for certain biases. However, switching strategies does not cause catastrophic failure (e.g., `uni-exp` vs `exp`), indicating the state retains a general representation. A break would occur if a radically different sampling grid (e.g., only distant past) yielded no useful information.

## Foundational Learning
- **Concept: HiPPO Framework (Optimal Polynomial Projection)**
  - **Why needed:** The entire memory update mechanism is derived from HiPPO-LegS. Understanding that memory is a coefficient vector of an optimal polynomial approximation (minimizing L2 error) is key to understanding why the update rule (Eq. 6) is mathematically principled and not heuristic.
  - **Quick check:** "What does the HiPPO state vector `c(t)` represent, and what optimization problem does its evolution solve?"
- **Concept: Discretization of Continuous Dynamics (Zero-Order Hold)**
  - **Why needed:** The theoretical ODE (Eq. 3) must be converted into a discrete recurrence (Eq. 4) for implementation. The ZOH method and its resulting matrices (`A_k`, `B_k`) are non-trivial and explain the position-dependence of the block matrices (`P_i`, `K_i`).
  - **Quick check:** "Why do the discrete state transition matrix `P_i` and kernel `K_i` depend on the absolute block index `i`?"
- **Concept: Polynomial Approximation and Sampling**
  - **Why needed:** Retrieval is not a simple look-up but a reconstruction of a continuous function from its polynomial coefficients. The choice of sample points is a form of multi-resolution or biased sampling from this reconstructed function.
  - **Quick check:** "How does the reconstruction matrix `R_i` (Eq. 7) encode temporal position, and why is this different from adding RoPE?"

## Architecture Onboarding

**Component map:**
1. **HiPPO State (`C_i^K`, `C_i^V`):** Fixed-size (N) buffers per layer storing Legendre polynomial coefficients for K and V streams. Updated recurrently.
2. **Precomputation Bank:** Offline-calculated libraries of position-dependent matrices: (a) `P_i` (state transition) and `K_i` (HiPPO kernel) for updates; (b) `R_i` (reconstruction) for retrieval. Indexed by block index `i`.
3. **Polynomial Sampler:** Logic to select the reconstruction matrix `R_{i-1}` from the bank based on the desired sampling strategy (uniform/exponential). This is the test-time configurable knob.
4. **Trapezoidal Attention:** Standard attention modified to prepend retrieved `K_mem`, `V_mem` to current block `K_curr`, `V_curr` and apply a causal mask only on the current block, allowing full attention from queries to memory.

**Critical path:** For each memory-augmented layer during forward pass on block `i`:
- (1) Retrieve `R_{i-1}`, compute `K_mem = R_{i-1} C_{K,i-1}`, `V_mem = R_{i-1} C_{V,i-1}`.
- (2) Augment keys/values: `K_aug = [K_mem, K_curr]`, `V_aug = [V_mem, V_curr]`.
- (3) Compute attention `O_att = softmax(Q_curr K_aug^T / sqrt(D) + M) V_aug`.
- (4) Update state: Retrieve `P_i`, `K_i`, compute `C_i^K = P_i C_{i-1}^K + K_i K_raw^T`, analogous for V.
- (5) Return `O_att` projected.

**Design tradeoffs:**
- **Memory Size (N) vs. Fidelity:** Larger N improves reconstruction but linearly increases memory footprint and retrieval computation. Results show steady gains, suggesting efficient use of capacity.
- **Uniform vs. Exponential Sampling:** A fundamental trade-off between preserving full history (uniform, better for LongPPL) and emphasizing recent context (exponential, better for PPL). This is a test-time choice, not a training one.
- **Theoretical Soundness vs. Implementation Complexity:** HiPPO provides a principled foundation but requires precomputation of time-varying matrices and careful handling of time-scaling in Legendre basis evaluation.

**Failure signatures:**
- **High Reconstruction MSE:** If `||K_curr - R_{i-1} C_{i-1}^K||_F^2` is high on validation, the compressed state is losing signal. Check N scaling and signal smoothness assumptions.
- **No Benefit from Memory:** If PPL/LongPPL do not improve over Transformer++ baseline, memory may be incorrectly injected or precomputed matrices misaligned.
- **Training Instability:** Training can spike; the paper suggests doubling warmup steps. Monitor loss curves at initialization; the recurrent state update may cause gradient issues.

**First 3 experiments:**
1. **Reconstruction Quality Probe (Appendix B):** Implement synthetic signal and real KV reconstruction tests. Verify that increasing N lowers MSE monotonically and that smooth signals reconstruct well while noise does not. Validates core compression assumption.
2. **Sampling Strategy Swap (Section 3.5):** Train a model with uniform sampling. At eval, run with uniform, exponential, and cross strategies. Confirm PPL/LongPPL shift as reported, proving decoupled design.
3. **Local Context Corruption (Section 3.6):** Implement noise injection in the memory-augmented layer (and all layers for "Hardly"). Compare degradation curves. Elastic Memory should degrade less than baselines, confirming use of long-term compressed state.

## Open Questions the Paper Calls Out
- **Impact of injection layer depth:** The paper only injects memory at layer 9; the effect of different depths is unexplored. Resolving this requires evaluating performance across all injection layers.
- **Learnable polynomial sampling:** Fixed uniform/exponential samplers are used; a learnable sampler might better capture data-specific retrieval patterns. This could be addressed by parameterizing the sampler (e.g., attention over positions) and training end-to-end.
- **Scalability beyond 32k tokens:** All experiments use ≤32k context; effectiveness on longer sequences (64k, 128k) remains unknown and could reveal limits of polynomial approximation or computational overhead.

## Limitations
- **Memory size scaling ambiguity:** The exact formula relating total memory (0.8M) to per-layer HiPPO dimension N given model dimensions is unclear.
- **Retrieval configuration unspecified:** The number of retrieved tokens (L_mem) and exponential decay hyperparameter (α) are not detailed.
- **Baseline implementation vagueness:** Details of Memorizing Transformer’s differentiable dense cross-attention and Melodi’s intra-layer propagation are ambiguous, affecting fair comparison.

## Confidence
- HiPPO-based compression (Mechanism 1): Medium
- Polynomial sampling flexibility (Mechanism 2): High
- Decoupled design for test-time bias (Mechanism 3): High
