# FedMomentum: Preserving LoRA Training Momentum in Federated Fine-Tuning

## Quick Facts
- **ArXiv ID**: 2603.08014
- **Source URL**: https://arxiv.org/abs/2603.08014
- **Reference Count**: 25
- **Primary Result**: FedMomentum achieves 34.22% accuracy on GSM8K, improving 18.0% over FLoRA and 219.3% over FedIT on LLaMA2-7B.

## Executive Summary
FedMomentum introduces a method for federated fine-tuning of large language models with LoRA that preserves training momentum lost in standard aggregation. It uses Singular Value Decomposition (SVD) to correctly combine client updates, extract dominant singular components for LoRA reconstruction with preserved rank, and merge residual components into the backbone. Evaluations on LLaMA2-7B across math, commonsense, and code tasks show superior convergence and accuracy, consistently outperforming baselines like FLoRA and FedIT.

## Method Summary
In FedMomentum, clients locally train LoRA adapters. The server aggregates these updates via SVD, decomposing the combined matrix into singular vectors and values. The top singular components, representing dominant update directions, are used to reconstruct LoRA matrices at the original rank. Residual components are merged into the backbone model's weights. This process maintains the structural integrity of LoRA updates, prevents momentum dilution, and ensures efficient communication.

## Key Results
- On GSM8K, FedMomentum reaches 34.22% accuracy, a 18.0% increase over FLoRA (29.06%) and 219.3% over FedIT (10.72%).
- Across math, commonsense, and code benchmarks, it consistently achieves higher final performance than all baselines.
- Learning curves indicate faster and more stable convergence compared to existing federated LoRA methods.

## Why This Works (Mechanism)
SVD aggregation captures the principal directions of client updates, which are most aligned with the training momentum. By reconstructing LoRA adapters from these dominant components, the method preserves the low-rank structure's effectiveness and update coherence. Merging residuals into the backbone prevents parameter explosion and incorporates minor adjustments without corrupting the core LoRA trajectories. This combination mitigates the loss of directionality that occurs with naive averaging, leading to more synchronized and purposeful global updates.

## Architecture Onboarding
- **Component Map**: Client LoRA Training -> SVD Aggregation on Server -> Dominant Component Extraction -> LoRA Reconstruction -> Residual Merge into Backbone
- **Critical Path**: 1. Clients compute local LoRA updates. 2. Server aggregates updates via SVD. 3. Top singular vectors form new LoRA matrices. 4. Residuals are added to backbone weights. 5. Updated models are redistributed to clients.
- **Design Tradeoffs**:
  - Rank selection: Higher rank improves expressiveness but increases communication; lower rank is efficient but risks underfitting.
  - Aggregation complexity: SVD is computationally heavier than averaging but preserves momentum; tradeoff in server load vs. performance.
  - Residual integration: Merging avoids parameter growth but may alter backbone behavior if residuals are significant.
- **Failure Signatures**:
  - stalled or divergent learning curves if SVD rank is insufficient to capture update variance.
  - performance degradation if residual merge introduces noise or destabilizes backbone weights.
  - high server latency if SVD computation becomes a bottleneck with many clients or large matrices.
- **First Three Experiments**:

  2. Comparative evaluation: Test against FLoRA and FedIT under identical client and communication settings.
  3. Ablation study: Remove SVD aggregation or residual merging to quantify each component's impact.

## Limitations
- Methodological opacity: Insufficient details on SVD implementation (e.g., layer-wise vs. global, rank heuristics) impede reproducibility.
- Limited evaluation scope: Experiments confined to LLaMA2-7B and three datasets; no tests on larger models, multilingual, or safety-sensitive tasks.
- Statistical concerns: Reported gains lack error bars or significance tests, raising risks of overfitting or selection bias; missing ablations prevent isolating contributions.
