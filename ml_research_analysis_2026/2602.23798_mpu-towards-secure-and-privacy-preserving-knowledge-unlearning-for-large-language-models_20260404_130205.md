# MPU: Towards Secure and Privacy-Preserving Knowledge Unlearning for Large Language Models

## Quick Facts
- arXiv ID: 2602.23798
- Source URL: https://arxiv.org/abs/2602.23798
- Reference count: 40
- Primary result: MPU enables server-client LLM unlearning under dual non-disclosure (server parameters and client forget set), matching noise-free baselines with average degradation below 1% under 10% noise and requiring only m=2 copies for stable performance.

## Executive Summary
Machine unlearning for large language models in a server-client setting faces a dual non-disclosure problem: the server’s model parameters and the client’s forget set must both remain private. MPU addresses this by publishing multiple perturbed and reparameterized copies of the server’s model to the client. The perturbations use structured zero-sum noise scaled per parameter block, and reparameterization exploits Transformer symmetries to obscure the original parameters. The client performs any standard unlearning algorithm locally on its private forget set without knowing the true server model. The server then inverts the reparameterizations and aggregates the updates via harmonic weighting, which cancels first-order noise effects under a local linearization assumption. Experiments across seven unlearning algorithms on Llama and Qwen models show MPU achieves near noise-free performance even with low noise levels, is algorithm-agnostic, memory-efficient (streaming O(d)), and requires only two copies for stability.

## Method Summary
MPU operates in communication rounds. In each round, the server generates m copies of its current model. For each copy k: it adds structured zero-sum noise εₖ = αₖ ε₀ₖ (block-wise, with ∑ₖ ε₀ₖ = 0) scaled by factor αₖ and a noise level κ, then applies a function-preserving reparameterization Tₖ,ᵣ (e.g., hidden-channel permutations for FFNs, per-head orthogonal rotations commuting with RoPE). The published copy θᵖᵘᵇₖ,ᵣ = Tₖ,ᵣ(θ + εₖ) is sent to the client. The client runs its chosen unlearning algorithm (e.g., NPO, DPO, GradAscent) on its private forget set Dᶠ starting from θᵖᵘᵇₖ,ᵣ, producing an update Δ(k,r). The server receives Δ(k,r), inverts the transform (bΔ(k,r) = Tₖ,ᵣ⁻¹(Δ(k,r))), and aggregates via harmonic weights wₖ ∝ αₖ⁻¹: ¯Δ = (∑ₖ wₖ bΔ(k,r)) / (∑ₖ wₖ). The global model updates as θ ← θ + η_srv ¯Δ. Streaming accumulators S0 (∑ αₖ⁻¹) and S1 (∑ αₖ⁻¹ bΔ) keep memory linear in model size. Key hyperparameters: κ=0.01, m=2, η_srv=1.0, algorithm-specific rounds R and local epochs E.

## Key Results
- MPU achieves average degradation below 1% compared to noise-free baselines under 10% noise, and even surpasses them for some methods under 1% noise.
- The approach requires as few as two perturbed copies for stable performance across seven unlearning algorithms.
- It is algorithm-agnostic, supporting gradient ascent, NPO, DPO, etc., without modification.

## Why This Works (Mechanism)
### Mechanism 1: Dual non-disclosure via perturbed copies
- **Claim:** Publishing multiple perturbed and reparameterized model copies hides server parameters while enabling noise cancellation.
- **Mechanism:** For each round, server creates m copies by adding structured zero-sum noise εₖ = αₖ ε₀ₖ (∑ₖ ε₀ₖ = 0 block-wise) and applying invertible reparameterization Tₖ,ᵣ from a symmetry group (e.g., channel permutations, RoPE-commuting orthogonal transforms). Zero-sum noise lies in a (m-1)-dimensional subspace; scaling αₖ introduces heterogeneity.
- **Core assumption:** Tₖ,ᵣ is invertible and function-preserving; unlearning displacement Δ(θ) is locally smooth; updates are mappable via T⁻¹.
- **Evidence anchors:** [abstract] "distributes multiple perturbed and reparameterized model instances… perturbations use structured zero-sum noise… reparameterization exploits Transformer symmetries"; [section 3.2] details noise (Eq. 2) and reparameterization; corpus shows novelty in dual non-disclosure.
- **Break condition:** Zero-sum property fails; symmetries insufficient to obscure; unlearning highly non-linear → second-order errors dominate.

### Mechanism 2: Client unlearning independence
- **Claim:** Client can run any standard unlearning algorithm locally without knowing server’s true parameters.
- **Mechanism:** Client receives θᵖᵘᵇ = T(θ+ε). Since T preserves function, model outputs are unchanged. Client applies algorithm to Dᶠ, yielding update Δ in transformed coordinates.
- **Core assumption:** Unlearning objective depends only on outputs; reparameterization leaves induced function invariant; optimization trajectories commute with T.
- **Evidence anchors:** [abstract] "client to execute unlearning locally… without accessing the server’s exact original parameters"; [section 3.3] "algorithm-agnostic"; [appx A.4] trajectory invariance proof for gradient methods.
- **Break condition:** Unlearning uses internal statistics altered by T; invariance relies on Euclidean geometry and local smoothness.

### Mechanism 3: Harmonic noise cancellation
- **Claim:** Harmonic aggregation of inversed updates cancels first-order noise error.
- **Mechanism:** Server computes bΔ = T⁻¹(Δ). Under local linearization, bΔ(k,r) ≈ Δ⋆ + J εₖ. Aggregating with weights wₖ ∝ αₖ⁻¹ gives ¯Δ = (∑ wₖ bΔ)/(∑ wₖ). Since εₖ = αₖ ε₀ₖ and ∑ wₖ αₖ ε₀ₖ ∝ ∑ ε₀ₖ = 0, first-order noise vanishes.
- **Core assumption:** Δ(θ) smooth enough for first-order Taylor; client updates independent across copies; exact harmonic weights.
- **Evidence anchors:** [abstract] "harmonic denoising procedure"; [section 3.4] derivation (Eqs. 14–15); [appx A.2] remainder bound.
- **Break condition:** Noise scale large relative to smoothness radius → second-order remainder significant; correlated updates reduce benefit; incorrect weights break cancellation.

## Foundational Learning
- **Concept: Parameter symmetries of neural networks (function-preserving transformations).**
  - Why needed: MPU exploits known invariances of Transformer architectures (e.g., permuting FFN hidden channels, orthogonal head basis changes that commute with RoPE) to create multiple equivalent-looking model copies without altering behavior.
  - Quick check: What are two types of symmetries exploited in MPU for Llama-style models? Answer: hidden-channel permutations in FFNs; per-head orthogonal rotations that commute with RoPE.

- **Concept: Local linearization of an update map.**
  - Why needed: Harmonic denoising assumes unlearning displacement Δ(θ) is approximately linear near the current iterate, enabling first-order error cancellation.
  - Quick check: Given Δ(θ) and perturbation u, write the first-order expansion of Δ(θ+u) and identify the term causing first-order noise error. Answer: Δ(θ) + J·u, where J = ∇Δ|_θ; J·u is the first-order error.

- **Concept: Subspace and linear combination cancellation.**
  - Why needed: Zero-sum noise construction forces vectors into a subspace where a weighted sum vanishes, key to exact cancellation.
  - Quick check: If εₖ = αₖ ε₀ₖ with ∑ₖ ε₀ₖ = 0, and weights wₖ satisfy wₖ αₖ = constant, show ∑ wₖ εₖ = 0. Answer: wₖ αₖ = c ⇒ ∑ wₖ εₖ = c ∑ ε₀ₖ = 0.

## Architecture Onboarding
- **Component map:** Pre-Process Module (server) -> Client Unlearning Module -> Post-Process Module (server). Server’s Pre-Process generates m perturbed/reparameterized copies per round and sends them to client. Client runs unlearning on each and returns updates. Server’s Post-Process inverts transforms, aggregates with harmonic weights, updates global model. Streaming accumulators S0 (∑ αₖ⁻¹) and S1 (∑ αₖ⁻¹ bΔ) keep memory O(d).

- **Critical path:**
  1. Initialize global model θ⁰ from fine-tuned checkpoint.
  2. For each round r = 1 to R:
     a. Server generates m copies: add zero-sum noise εₖ, apply Tₖ,ᵣ, publish θᵖᵘᵇₖ,ᵣ.
     b. Client receives each copy, runs local unlearning on Dᶠ, returns Δ(k,r).
     c. Server inverts: bΔ(k,r) = Tₖ,ᵣ⁻¹(Δ(k,r)); accumulate S0 += αₖ⁻¹, S1 += αₖ⁻¹ bΔ(k,r).
     d. After all copies, aggregate ¯Δ = S1 / S0; update θʳ = θ^{r-1} + η_srv ¯Δ.
  3. Output final model θᴿ.

- **Design tradeoffs:**
  - Noise level κ: Larger κ increases privacy but risks second-order errors; default κ=0.01 works well.
  - Number of copies m: More copies improve stability/forgetting but increase compute/communication; m=2 sufficient for most, m=3 sometimes helps, m=4 can hurt some algorithms.
  - Round/epoch allocation: More rounds (smaller local epochs) preserves utility but may weaken forgetting; fewer rounds (more epochs) strengthens forgetting but risks over-updating.
  - Algorithm choice: Some algorithms (NPO) are noise-robust; others (GradAscent) benefit from multi-copy stabilization. MPU is algorithm-agnostic.

- **Failure signatures:**
  - Forgetting collapse: Forget Quality near 0 (e.g., <10⁻³) indicates failed unlearning.
  - Utility collapse: Model Utility drops sharply (e.g., below 0.2) suggests over-unlearning.
  - Persistent privacy leakage: |PrivLeak| > 20 indicates abnormal loss patterns.
  - High variance across copies: Per-copy updates vary wildly; increase m or reduce κ.

- **First 3 experiments:**
  1. Baseline replication: Run MPU (m=2, κ=0.01, NPO) on Llama-3.2-1B and TOFU Split99. Expected: FQ ≈ 0.92, FTR ≈ 0.63, MU ≈ 0.60, PrivLeak ≈ 28 (Table 1).
  2. Noise denoising ablation: Compare (a) Clean (no noise, single copy), (b) Noised (single copy with same average noise), (c) MPU (m=2, κ=0.01). Expect MPU to match Clean FQ and beat Noised for unstable algorithms (GradAscent, DPO) (Table 6 vs. 7).
  3. Copy number scaling: Vary m ∈ {2,3,4} with κ=0.01 and GradAscent. Expect improvement from m=2 to m=3, possible drop at m=4; observe runtime increase (Table 8).

## Open Questions the Paper Calls Out
1. What are fundamental limits on communication/computational efficiency for privacy-preserving server-client unlearning, and can we design MPU variants with lower overhead without sacrificing privacy or efficacy?
2. Does MPU retain guarantees when the client uses adaptive optimizers like Adam, which may not commute with the reparameterizations? The analysis assumes deterministic gradient-based methods, but experiments use AdamW.
3. How can MPU be extended to multiple clients concurrently submitting forget requests while preserving each client’s data privacy and server model confidentiality?
4. Are the reparameterization symmetries sufficient to prevent a malicious client from reconstructing the server’s original model from multiple perturbed copies? Could there be additional symmetries or reconstruction attacks?

## Limitations
- Implementation details (block partitioning, reparameterization sampling, client hyperparameters) are underspecified, hindering exact replication.
- Privacy guarantee relies on symmetry indistinguishability; no formal proof beyond linearization, and second-order errors could leak information if noise is large.
- The algorithm-agnostic assumption may not hold for unlearning methods that depend on internal statistics altered by reparameterization.

## Confidence
- Dual non-disclosure mechanism: High (theoretically sound and experimentally validated).
- Client unlearning independence: Medium (proof holds for gradient-based methods; others may not satisfy invariance).
- Noise cancellation via harmonic aggregation: High for small κ (≤0.01), Medium for larger κ due to second-order effects.
