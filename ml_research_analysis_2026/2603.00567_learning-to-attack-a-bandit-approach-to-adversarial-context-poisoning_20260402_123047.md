# Learning to Attack: A Bandit Approach to Adversarial Context Poisoning

## Quick Facts
- **arXiv ID:** 2603.00567  
- **Source URL:** https://arxiv.org/abs/2603.00567  
- **Reference count:** 40  
- **Primary result:** AdvBandit induces up to 2.8× higher cumulative victim regret and improves target-arm pull ratios by 1.7–2.5× compared to SOTA baselines, with attack efficiency up to 2.1× higher.

## Executive Summary
AdvBandit is a black‑box adversarial attack against neural contextual bandits (NCBs) that frames context poisoning as a continuous‑armed bandit problem. The attacker, with only access to observed contexts and victim actions, builds a surrogate policy via maximum‑entropy inverse reinforcement learning (MaxEnt IRL). Attack parameters—effectiveness, statistical evasion, and temporal smoothness—are selected using GP‑UCB. Perturbations are generated with projected gradient descent (PGD) on the surrogate, and a limited attack budget is managed by a query selection mechanism. Experiments on Yelp, MovieLens, and Disin datasets with five victim NCB algorithms show that AdvBandit significantly increases victim regret and target‑arm pulls while outperforming existing attacks. Theoretical analysis yields sublinear attacker regret and a linear lower bound on victim regret in the number of attacks.

## Method Summary
The attacker operates over a horizon $T$ with a strict budget $B$. It maintains a sliding window $D_t$ of recent context‑action pairs and periodically retrains a MaxEnt IRL module to produce a UCB‑aware policy $\hat{\pi}_\phi$ that mimics the victim’s exploration‑exploitation trade‑off. Each round, from the current context $x_t$ the attacker computes a 5‑dimensional feature vector $\psi(x_t)$ (policy entropy, defense weight, Mahalanobis gradient distance, regret gap, relative time). These features feed a multi‑objective score $v(x_t)$ combining success probability, regret gap, and defense weight; if $v(x_t)$ exceeds an adaptive quantile threshold $\tau_v$, an attack is triggered. For an attack, the attacker queries a Gaussian process bandit (GP‑UCB) to choose a 3‑dimensional parameter $\lambda\in[0,1]^3$, then solves a PGD problem on the surrogate to find an $\ell_\infty$‑bounded perturbation $\delta_t$ that minimizes a weighted sum of effectiveness, evasion, and smoothness losses. The pipeline consists of four components: Surrogate Builder, Feature Extractor, Query Selector, Arm Selector, and Perturbation Engine, with the IRL retraining schedule $\Delta_{\text{IRL}}$ and window size $W$ tuned to track victim drift.

## Key Results
- Up to **2.8× higher cumulative victim regret** across five victim algorithms on Yelp, MovieLens, and Disin.
- **Target‑arm pull ratio** improved by **1.7–2.5×** over state‑of‑the‑art attacks.
- **Attack efficiency** (regret per attack) increased by up to **2.1×**.

## Why This Works (Mechanism)

### Bandit‑Based Parameter Selection
**Claim:** Modeling attack parameter selection as a continuous‑armed bandit allows the attacker to efficiently learn the trade‑off between effectiveness, statistical evasion, and temporal smoothness without victim internals.  
**Mechanism:** The 3D parameter vector $\lambda\in[0,1]^3$ is treated as arms. Over $B$ attack rounds, GP‑UCB balances exploitation (high predicted reward $\mu$) and exploration (high uncertainty $\sigma$). Reward is binary (1 if victim picks target arm under perturbed context, else 0). The GP input is a low‑dimensional state $s_t$ that includes contextual features $\psi(x_t)$ and attack history.  
**Core assumption:** Reward function $r(s,\lambda)$ is smooth over $\lambda$, enabling GP generalization.  
**Evidence:** The paper explicitly “formulates context poisoning as a continuous‑armed bandit problem… GP‑UCB guides arm selection” (abstract, Sec 4.4) and provides an attacker regret bound $O\!\big(\sqrt{n\gamma_n\log(n/\rho)} + \sqrt{n\cdot d_\Theta/W} + \sqrt{n\cdot\Delta_{\text{IRL}}} + n\cdot\epsilon_{\text{mis}}\big)$.  
**Break condition:** Large victim policy drift between IRL retrainings (large $\Delta_{\text{IRL}}$) makes $r(s,\lambda)$ non‑stationary faster than the GP adapts, degrading regret.

### MaxEnt IRL Surrogate Construction
**Claim:** Maximum‑entropy inverse reinforcement learning builds an accurate surrogate policy using only observed context‑action pairs, without reward or gradient access.  
**Mechanism:** A sliding window $D_t$ of recent $(x_\tau,a_\tau)$ trains a neural network to maximize likelihood under a softmax policy with UCB‑aware Q‑values: $\hat{\pi}_\phi(a|x) \propto \exp\!\big(\hat{h}_\phi^r(x,a) + \beta_t\sigma_\phi^u(x,a)/\tau\big)$. This reproduces the victim’s exploration‑exploitation balance. The surrogate informs both feature extraction and perturbation generation.  
**Core assumption:** Victim policy lies in the IRL model class (realizability) or is approximated with bounded misspecification error $\epsilon_{\text{mis}}$.  
**Evidence:** Abstract mentions “constructs a surrogate model using a maximum‑entropy inverse reinforcement learning module”; Section 4.1 details the UCB‑aware MaxEnt IRL; Appendix E.1&E.2 link IRL error $\epsilon_{\text{IRL}}(t)$ to victim and attacker regret.  
**Break condition:** Highly stochastic victim policies or frequent retraining may require a large window $W$ to capture dynamics; too small $W$ yields a stale surrogate and high $\epsilon_{\text{IRL}}$.

### Gradient‑Based Perturbation via PGD
**Claim:** Using PGD on the surrogate with multi‑objective regularization (effectiveness, statistical evasion, temporal smoothness) robustly generates perturbations that coerce the victim into selecting the target arm while evading defenses.  
**Mechanism:** Given $\lambda_t$ from GP‑UCB, solve $\delta^* = \arg\min_{\|\delta\|_\infty\leq\epsilon} \lambda^{(1)}L_{\text{eff}} + \lambda^{(2)}(R_s + R_n) + \lambda^{(3)}R_t$, where $L_{\text{eff}}=-\log\hat{\pi}_\phi(a^\dagger|x+\delta)$ pushes the target arm, $R_s$ penalizes Mahalanobis distance of gradients from normal statistics, $R_n$ (if present) penalizes deviation from a null model, and $R_t$ enforces smoothness across time. PGD iterates using gradients from the surrogate reward network $\hat{h}_\phi^r$.  
**Core assumption:** Surrogate reward $\hat{h}_\phi^r(x,a)$ is $L_h$‑Lipschitz, enabling PGD to find a successful $\delta$ within the $\ell_\infty$ ball.  
**Evidence:** Abstract: “generates perturbations with PGD.” Section 4.5 specifies PGD on the surrogate. Section 5.1 defines the attackability margin $\alpha_t = \Delta(x_t,a^\dagger_t) - 2L_h\epsilon$.  
**Break condition:** Sharp, non‑smooth victim boundaries (e.g., decision trees) or poor surrogate calibration ($\epsilon_{\text{mis}}$ large) can prevent PGD from finding effective $\delta$.

## Foundational Learning

### Neural Contextual Bandits
**Why needed:** The victim is a neural contextual bandit; understanding its UCB‑style exploration (e.g., R‑NeuralUCB) and regret structure $O(\sqrt{T})$ is essential to interpret attack impact.  
**Quick check:** How does the exploration bonus $\beta_t\sigma_t(x,a)$ affect the perturbation magnitude $\Delta(x_t,a^\dagger_t)$ required to flip the action?

### Inverse Reinforcement Learning
**Why needed:** AdvBandit’s surrogate is built via MaxEnt IRL; grasping its objective and sample complexity $O\!\big(\sqrt{d_\Theta\log K / W}\big)$ is critical for choosing retraining schedule $\Delta_{\text{IRL}}$ and window size $W$.  
**Quick check:** What causes the IRL approximation error $\epsilon_{\text{IRL}}(t)$ to increase when $W$ is too small or the victim’s policy drifts between retrainings?

### Gaussian Process Bandits
**Why needed:** The attacker’s core adaptive loop is a GP‑UCB over $\lambda$; understanding information gain $\gamma_n$ and acquisition function $\mu+\beta\sigma$ explains the choice of low‑dimensional features and minimal $\lambda$ dimensionality.  
**Quick check:** Why does reducing $\lambda$ from 5D to 3D improve sample efficiency by ~28× for $B=200$, given $\gamma_n \approx (\log n)^{d_{\text{gp}}+1}$?

## Architecture Onboarding

### Component Map
Surrogate Builder -> Feature Extractor -> Query Selector -> Arm Selector -> Perturbation Engine

### Critical Path
The MaxEnt IRL module must be updated (retrained every $\Delta_{\text{IRL}}$) before feature extraction because gradient statistics depend on the current reward network $\hat{h}_\phi^r$. The Query Selector uses the extracted features $\psi(x_t)$ to compute score $v(x_t)$. If $v(x_t) \geq \tau_v$, the Arm Selector runs GP‑UCB to obtain $\lambda_t$, after which the Perturbation Engine executes PGD to generate $\delta_t$.

### Design Tradeoffs
- **Feature dimensionality:** $\psi(x)\in\mathbb{R}^5$ balances GP tractability (low $d_{\text{gp}}$) and information retention. Ablation on Yelp shows 5D features yield regret 287 vs. 673 with raw 20D.
- **Query selection aggressiveness:** Pareto filtering + Chebyshev scalarization (score $v$) with adaptive threshold $\tau_v$ uses nearly full budget (197/200 attacks) while maintaining higher average $v(x_t)$ than single‑objective baselines.
- **$\lambda$ dimensionality:** 3D $\lambda$ outperforms 5D (e.g., regret 573 vs. 587 on Yelp) because the GP‑UCB sample complexity grows exponentially with dimension; 3D offers a good trade‑off between expressiveness and efficiency.

### Failure Signatures
- **Stalled victim regret:** Flat cumulative victim regret $R_v(T)$ indicates λ selection failure, high IRL error, or overly conservative query thresholds.
- **High IRL KL divergence:** $D_{\text{KL}}(\hat{\pi}_\phi\|\pi^*) > 0.1$ on validation suggests surrogate drift; remedy by decreasing window $W$ or increasing retraining frequency.
- **Budget waste:** Attacks used $\ll B$ despite many high‑$v(x_t)$ contexts → $\tau_v$ too high. Lower quantile factor or relax Pareto filter.
- **Oscillating $\lambda$ values:** GP‑UCB λ does not converge → increase exploration constant $\beta_{\text{GP}}$ or refinement steps $N_{\text{refine}}$; check $\Delta_{\text{IRL}}$ alignment with victim non‑stationarity.

### First 3 Experiments
1. **Baseline comparison:** Run AdvBandit against five SOTA attacks (Liu, Ma, Garcelon, Ilyas, Wang) on R‑NeuralUCB across Yelp, MovieLens, and Disin. Expect AdvBandit to achieve ~2.8× higher victim regret at $T=5000$.
2. **Ablation: $\lambda$ dimensionality:** Systematically vary $\lambda$ dimensionality (1D–5D) and observe optimal performance at 3D despite theoretical expressiveness of higher dimensions.
3. **Ablation: Query selection:** Replace adaptive quantile $\tau_v$ with random, fixed threshold, $\epsilon$‑greedy, and offline oracle Top‑B. The adaptive quantile should achieve >90% of oracle performance while using near‑full budget and achieving higher average $v(x_t)$.

## Open Questions the Paper Calls Out
1. **Multi‑agent extension:** How can AdvBandit be extended to multi‑agent bandit settings? The paper mentions this as future work but ignores coordination, competition, and equilibria.
2. **Stackelberg game formulation:** Can attack and defense be modeled as a Stackelberg game? The conclusion suggests it, but a precise game definition, defender commitment, and equilibrium analysis are missing.
3. **Surrogate model class robustness:** How effective is AdvBandit against victim policies outside the IRL’s realizability class? Current evaluations use only five similar NCB algorithms; misspecification could cause failures on unseen architectures (e.g., evolutionary, tabular, non‑smooth).
4. **Robust defenses:** What defenses can mitigate AdvBandit‑style attacks? Existing defenses like trust‑weighting prove insufficient; a provably robust defense and empirical validation are needed.

## Limitations
- **Hyperparameter ambiguity:** Critical hyperparameters (GP‑UCB kernel parameters $\sigma_f,\sigma_n$, IRL temperature $\tau$, adaptive weights $\gamma,\eta$) are not empirically validated, hindering exact replication.
- **Victim model gaps:** Implementation specifics for R‑NeuralUCB’s trust‑weighting and RobustBandit’s defense statistic ($\sigma_{\text{VIC}}$) are incompletely defined, requiring assumptions that may alter comparative results.
- **Dataset & scope constraints:** Evaluation is limited to three datasets and five victim algorithms; generalization to other bandit settings or real‑world deployment constraints remains unknown.

## Confidence
- **High:** Overall architecture and bilevel attack formulation (Section 4). The sequential pipeline (IRL → Features → GP‑UCB → PGD) is clearly described.
- **Medium:** Theoretical regret bounds (Theorem 1, 2). Analysis structure is sound but depends on unstated constants (e.g., $c_\beta$, $\Delta_{\text{IRL}}$ scaling) and vague $\epsilon_{\text{mis}}$ term.
- **Low:** Exact reproducibility of reported performance (e.g., “2.8× higher regret”). Missing hyperparameters and victim implementation details prevent precise recreation without substantial tuning.

## Next Checks
1. **Kernel sensitivity ablation:** Systematically vary GP‑UCB kernel parameters ($\ell\in\{0.1,\dots,1.0\}$, $\sigma_f\in\{0.1,1.0,10.0\}$, $\sigma_n\in\{10^{-3},10^{-2},10^{-1}\}$) on Yelp/R‑NeuralUCB; measure impact on attacker regret and victim regret lift.
2. **Reward definition stress test:** Compare binary success reward vs. continuous regret‑reduction reward $\rho_t = \Delta(x_t,a^\dagger_t) - \Delta(x_t,\tilde{a}_t)$ in GP‑UCB; assess sample efficiency changes.
3. **Query threshold calibration:** Replace adaptive quantile $\tau_v(b,T-t)$ with fixed percentiles (10th, 30th, 50th, 70th, 90th) across the budget horizon; track budget consumption and final $v(x_t)$ distribution to validate the adaptive heuristic.
