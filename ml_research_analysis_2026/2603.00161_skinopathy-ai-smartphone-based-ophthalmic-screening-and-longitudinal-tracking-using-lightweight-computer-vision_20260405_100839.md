# SKINOPATHY AI: Smartphone-Based Ophthalmic Screening and Longitudinal Tracking Using Lightweight Computer Vision

## Quick Facts
- **arXiv ID:** 2603.00161
- **Source URL:** https://arxiv.org/abs/2603.00161
- **Reference count:** 23
- **Primary result:** SKINOPATHY AI delivers five explainable, deterministic smartphone-based ophthalmic screening modules with strong pilot metrics (e.g., redness Spearman r_s=0.86 vs. Efron grade; blink MAE=2.1 bpm; lesion MAE=0.31 mm) and longitudinal trend tracking, all processed locally for privacy.

## Executive Summary
SKINOPATHY AI addresses global disparities in ophthalmic screening by enabling commodity smartphones—without external attachments or cloud AI—to quantify conjunctival redness, estimate blink rate, analyze pupil light reflex, index scleral color (icterus/pallor proxies), and measure lesion encroachment with millimeter accuracy. Its five deterministic modules prioritize explainability and privacy through local OpenCV/MediaPipe processing. The system provides conservative triage guidance, session persistence, and PDF reports, forming a foundation for future clinically validated mobile ophthalmoscopy tools in low-resource settings.

## Method Summary
The system comprises a React frontend and FastAPI backend with MongoDB persistence. The backend implements five analysis modules using hand-crafted OpenCV and MediaPipe algorithms: redness via luminance-weighted LAB a* within a scleral mask; blink rate via MediaPipe FaceMesh Eye Aspect Ratio with adaptive thresholding; pupil light reflex via Pupil Illumination Response time-series; scleral color indices via LAB/HSV statistics after gray-world white balance; and lesion encroachment via iris-diameter calibration (fixed HVID prior) and heuristic color masking. All media processing occurs locally; raw media is not stored. The pipeline is triggered per-module via REST endpoints, with results aggregated into session PDFs.

## Key Results
- Conjunctival redness correlates with Efron grade (Spearman r_s=0.86).
- Blink rate estimation MAE = 2.1 ± 0.9 bpm.
- Pupil latency error = 42 ± 18 ms vs. clinical pupillometer.
- Icterus index AUC = 0.79.
- Lesion encroachment MAE = 0.31 ± 0.12 mm vs. slit-lamp.

## Why This Works (Mechanism)

### Mechanism 1: Conjunctival redness quantification
- **Claim:** Conjunctival redness is quantified reliably via luminance-weighted mean of the LAB a* channel within a scleral mask.
- **Mechanism:** CIE LAB separates chromaticity (a*, b*) from luminance (L*). A scleral mask is created via luminance and saturation thresholds. The algorithm computes the spatial expectation of a* over this mask, weighted by L* to prioritize brighter sclera, then linearly maps the result to a 0–10 score calibrated to the Efron grade.
- **Core assumptions:** (1) Hyperemia shifts scleral reflectance, increasing a*. (2) Luminance weighting reduces shadow/occlusion noise. (3) A fixed linear mapping holds across smartphone cameras after gray-world white balance.
- **Evidence:** Section 4.2 details LAB conversion, mask definition (Eq. 9–10), weighting (Eq. 11), and normalization (Eq. 14–16). The abstract lists this module. Corpus shows no direct replication; evidence is internal.
- **Break condition:** Performance degrades under mixed lighting or when the scleral mask incorrectly includes iris/pupil due to poor gaze angle.

### Mechanism 2: Blink rate estimation
- **Claim:** Blink rate is estimated robustly using MediaPipe FaceMesh's Eye Aspect Ratio (EAR) with an adaptive, fps-aware threshold and temporal smoothing.
- **Mechanism:** For each frame, EAR is computed from six periorbital landmarks. A causal moving average over a window sized by video fps smooths jitter. An adaptive blink threshold (τ_blink = median(EAR_baseline) - α·σ) is derived from the first 1.5 seconds. A finite-state machine requires EAR < τ_blink for a minimum adaptive frame count to register a blink.
- **Core assumptions:** (1) MediaPipe FaceMesh provides accurate, stable periorbital landmarks. (2) Baseline EAR distribution is stable within a short session. (3) The typical adult blink range (15–20 bpm) anchors triage bands.
- **Evidence:** Section 4.3 defines EAR (Eq. 17–18), smoothing (Eq. 19–20), adaptive threshold (Eq. 21–23), and state machine (Eq. 24–25). The abstract cites this approach. Neighbors use MediaPipe for eye tracking but not adaptive blink rate.
- **Break condition:** Fails if baseline includes blink artifacts, video fps is highly variable, or facial occlusion causes landmark dropout.

### Mechanism 3: Millimeter-scale lesion encroachment
- **Claim:** Millimeter-scale lesion encroachment measurement and longitudinal tracking are achieved via iris-diameter calibration and polar-coordinate analysis of a heuristic lesion mask.
- **Mechanism:** MediaPipe iris landmarks estimate iris radius (ρ_iris). A population-mean Horizontal Visible Iris Diameter (HVID = 11.8 mm) gives pixel-to-mm scale factor λ = HVID / (2·ρ_iris). A heuristic lesion mask is created via multi-space color thresholding within an annular band (65–98% of ρ_iris) restricted to nasal/temporal sectors. Maximum inward penetration from the limbus yields d_mm = d_px · λ. Longitudinal trend is an OLS slope on sequential d_mm values.
- **Core assumptions:** (1) Population-mean HVID approximates any individual (±9.3% uncertainty). (2) Heuristic mask accurately isolates lesions. (3) Limbal boundary coincides with ρ_iris.
- **Evidence:** Section 4.6 details polar calibration (Eq. 62–68), mask creation (Eq. 69–74), and encroachment computation (Eq. 75–81). The abstract mentions this capability. Neighbors use different calibration methods; the HVID assumption is not validated externally.
- **Break condition:** Fails if MediaPipe iris detection fails (fallback to HoughCircles degrades accuracy), heuristic mask fails for pale/low-contrast lesions, or calibration error becomes significant for small encroachments.

## Foundational Learning
- **Concept:** CIE LAB and HSV color spaces  
  **Why needed:** Core to redness, icterus, and pallor modules. LAB a* isolates redness; LAB b* isolates yellowness (icterus); HSV saturation gates scleral regions. Understanding OpenCV's LAB scaling (uint8 0–255) is critical.  
  **Quick check:** Why is the a* channel preferred over raw RGB for redness quantification, and how does OpenCV store LAB values?

- **Concept:** MediaPipe FaceMesh landmark topology  
  **Why needed:** Provides iris center, iris ring landmarks (for PIR and lesion calibration), and periorbital landmarks (for EAR). Engineers must know which indices correspond to eye canthi, lid margins, and iris points to debug failures.  
  **Quick check:** Which six MediaPipe landmarks define the Eye Aspect Ratio (EAR), and what does `refine_landmarks=True` add for the pupil module?

- **Concept:** Geometric calibration from anatomical priors  
  **Why needed:** The lesion module converts pixels to millimeters using a population HVID prior. Understanding the fixed HVID assumption and uncertainty propagation is essential for interpreting millimeter results.  
  **Quick check:** If the estimated iris radius ρ_iris = 50 pixels, what is the pixel-to-mm scale factor λ, and what is its approximate 95% uncertainty range?

## Architecture Onboarding
**Component map:**  
User interacts with React frontend -> captures media via `getUserMedia`/`MediaRecorder` -> sends multipart POST to FastAPI backend endpoint (e.g., `/api/analyze/redness`) -> backend runs OpenCV/MediaPipe pipeline -> stores metrics in MongoDB -> frontend fetches session PDF via ReportLab.

**Critical path:**  
User consent -> create session (POST `/api/sessions`) -> for each module: capture media -> POST to `/api/analyze/{module}` -> store result in session -> user views/downloads PDF report (GET `/api/sessions/{id}/report.pdf`).

**Design tradeoffs:**  
- *Heuristics vs. learned models:* Transparent and debuggable but brittle to lighting/variation; a trained segmentation model would improve robustness at the cost of auditability.  
- *Local vs. cloud processing:* Ensures privacy and offline function but limits model complexity; tradeoff favors accessibility over peak performance.  
- *Population HVID prior vs. physical calibration:* Simpler UX (no calibration object) but introduces ~±9% scale error; future versions may support optional calibration cards.

**Failure signatures:**  
- *Redness:* a* score near 0 or 10 across many images → likely mask failure (e.g., including iris) or extreme white balance.  
- *Blink:* Rate >60 bpm or <5 bpm in healthy adult → likely false positives from facial motion or poor landmark continuity.  
- *Pupil:* Noisy PIR time-series without clear constriction dip → poor iris tracking or insufficient light stimulus contrast.  
- *Lesion:* Encroachment = 0 mm on visibly affected eye, or d_mm >5 mm → mask false negative or calibration from small ρ_iris inflating λ.  
- *System:* API 500 errors on `/api/analyze` → MediaPipe load failure or OOM.

**First 3 experiments:**  
1. **LAB a* sanity check:** Run redness module on 10 controlled images (same eye, varying light) to verify a* changes monotonically with induced redness and mask excludes iris.  
2. **EAR threshold stress test:** Record 10-second blink videos at different fps (30, 60, 120) with deliberate partial blinks; verify adaptive threshold adjusts and false blink count remains low.  
3. **Calibration uncertainty demo:** Measure ρ_iris on 20 diverse eye images; compute λ range. For a known pterygium (e.g., 2 mm at slit lamp), simulate λ uncertainty's propagation to d_mm error band.

## Open Questions the Paper Calls Out
1. Which lightweight segmentation model (e.g., U-Net, Fast-SCNN) can effectively replace SKINOPATHY AI's heuristic pterygium segmentation?  
2. Can an automated, synchronized light stimulus on smartphones standardize pupil light reflex latency measurements?  
3. Do device-specific color calibration and white balance correction reduce inter-device bias in redness and scleral color indices?

## Limitations
- **External validation gap:** No independent clinical validation beyond the authors' pilot study; performance across diverse populations, devices, and pathologies is unknown.
- **Heuristic brittleness:** All modules rely on hand-crafted thresholds and rules sensitive to lighting, skin tone, anatomy, and video quality.
- **Calibration priors:** Lesion measurement uses a fixed population HVID (11.8 mm), introducing ~±9% scale error; longitudinal trend validity remains unvalidated.
