# Finite-State Controllers for (Hidden-Model) POMDPs using Deep Reinforcement Learning

## Quick Facts
* arXiv ID: 2602.08734
* Source URL: https://arxiv.org/abs/2602.08734
* Reference count: 40
* Primary result: Lexpop scales to large POMDPs (up to 520k states) and HM-POMDPs (up to 262k states), extracts compact finite-state controllers (3-10 nodes) with near-optimal verified values, and uses iterative worst-case POMDP selection to achieve robust policies, outperforming state-of-the-art solvers.

## Executive Summary
Lexpop is a framework for solving large partially observable Markov decision processes (POMDPs) and their robust hidden-model variant (HM-POMDPs). It combines deep reinforcement learning (DRL) with finite-state controller extraction to produce policies that are both high-performing and formally verifiable. The core pipeline trains a recurrent neural network (RNN) policy using proximal policy optimization (PPO) on a vectorized simulator built upon the Storm model checker. The trained RNN is then distilled into a compact stochastic finite-state controller (FSC) via either automata learning (Alergia) or a novel self-interpretable Gumbel-softmax network (SIG). For HM-POMDPs, Lexpop iteratively improves robustness by identifying worst-case POMDP instances within the family via deductive verification (Paynt) and incorporating them into the training buffer. Experiments on benchmarks with up to hundreds of thousands of states show Lexpop significantly outperforms prior solvers Saynt and rfPG, while producing FSCs whose verified values closely match the empirical performance of the RNN policies.

## Method Summary
Lexpop’s methodology consists of four main components: (1) a vectorized simulator (VecSim) that efficiently generates parallel trajectories from POMDP models, (2) a PPO agent that optimizes an RNN policy using these trajectories, (3) an extraction module that converts the RNN into an FSC, and (4) a verification engine (Storm/Paynt) that computes the exact value of the FSC. For standard POMDPs, the process is run once: train RNN, extract FSC, verify. For HM-POMDPs, an outer loop is introduced: after verification, the worst-case POMDP for the current FSC is added to a buffer of training instances; the RNN is then retrained on this mixed buffer (new worst-cases plus initial instances), and the cycle repeats. The extraction can be performed either by applying the Alergia algorithm to a trace dataset or by training a SIG network—a recurrent network with a Gumbel-softmax bottleneck—to mimic the RNN’s input-output behavior. The resulting FSC is small enough for formal analysis yet retains the performance of the neural policy.

## Key Results
* **Scalability:** Lexpop handles POMDPs with up to 520k states and HM-POMDPs with up to 262k states, surpassing the capabilities of model-based solvers like Saynt and rfPG.
* **Compactness and fidelity:** Extracted FSCs contain only 3–10 memory nodes, and their verified values are within a small margin of the RNN’s empirical performance, demonstrating effective distillation.
* **Robustness via worst-case iteration:** For HM-POMDPs, the iterative inclusion of worst-case POMDPs identified by verification yields policies with significantly higher robust value compared to random instance sampling.

## Why This Works (Mechanism)
### Deep RL scalability via vectorized simulation
Deep reinforcement learning with an RNN policy can compute high-quality policies for large POMDPs where model-based methods fail. A vectorized simulator built on Storm generates massive parallel trajectories, and PPO optimizes the RNN parameters. The RNN's hidden state compresses the observation history into a sufficient statistic. The approach relies on the RNN's expressive power and the effectiveness of PPO in the given reward-shaped environment. Evidence: The vectorized simulator is described in Section 4 and enables scaling to large state spaces. A break condition is if the RNN's memory capacity is insufficient or reward shaping yields an un-learnable signal.

### Effective FSC extraction from RNN policies
Finite-state controllers can be extracted from the trained RNN with high fidelity, enabling formal verification. Two methods are used: (1) Automata learning (Alergia) merges compatible nodes from a prefix tree of trajectories, (2) a self-interpretable Gumbel softmax network (SIG) trains a surrogate with a discrete bottleneck to directly output FSC parameters. The underlying assumption is that a small stochastic Mealy machine can closely approximate the RNN's input-output behavior on the relevant distribution. Evidence: Section 5 details both extraction methods and shows compact FSCs with small value gaps. Break condition: if the RNN relies on continuous or high-dimensional hidden state patterns that cannot be quantized without significant performance loss.

### Iterative worst-case POMDP selection for robustness
For HM-POMDPs, iteratively incorporating worst-case POMDPs identified by deductive verification is crucial for learning robust FSCs. Given a candidate FSC, verification (via Paynt) computes its worst-case POMDP within the family; this POMDP is added to the training buffer. The RNN is then retrained on the buffer, focusing on its weaknesses. The loop repeats. The assumption is that the set of worst-case POMDPs across iterations covers the critical corner cases of the HM-POMDP family. Evidence: The abstract and Section 4 describe this loop; the neighbor rfPG uses a similar idea but with model-based updates, highlighting the novelty of combining it with scalable DRL. Break condition: if worst-case POMDPs are unstable or the buffer fails to cover all critical scenarios.

## Foundational Learning

### POMDPs (Partially Observable Markov Decision Processes)
**Why needed:** Formalizes decision-making under partial observability, where the agent chooses actions based on observations that do not fully reveal the underlying state. The paper addresses both standard POMDPs and the hidden-model variant (HM-POMDPs) where transition probabilities are uncertain within intervals.
**Quick check:** Given a POMDP, what is the difference between a policy and a belief MDP, and why can't belief MDPs scale?

### Finite-State Controllers (FSCs)
**Why needed:** FSCs are compact, stochastic controllers that map memory states and observations to actions and next memory states. They serve as the final output: a deployable and formally analyzable policy that avoids the curse of dimensionality of belief states.
**Quick check:** How does an FSC avoid the need to explicitly maintain a belief state over the underlying POMDP's states?

### Deep Reinforcement Learning (PPO with RNNs)
**Why needed:** Provides a scalable, model-free method to find high-performing policies that generalize over large state spaces by learning from environment interactions. The recurrent architecture captures history-dependent decision-making necessary for POMDPs.
**Quick check:** Why is a recurrent architecture (like LSTM/GRU) necessary in the policy network for a POMDP?

### Automata Learning & Gumbel Softmax
**Why needed:** Extraction techniques to convert a black-box RNN policy into a white-box, formally analyzable FSC. Automata learning merges behaviorally similar states; Gumbel Softmax enables differentiable training of a network with discrete latent variables.
**Quick check:** What is the key difference between using a straight-through estimator and Gumbel Softmax for training a network with discrete latent variables?

## Architecture Onboarding
### Component map
Vectorized Simulator (VecSim) -> PPO Agent (RNN policy) -> Extraction Module (Alergia or SIG network) -> Verification Engine (Storm/Paynt). For HM-POMDPs, verification output (worst-case POMDP) feeds back into the training buffer.

### Critical path
For a single POMDP: VecSim generates parallel trajectories -> PPO updates the RNN -> Extraction module trains on recent trajectories to produce an FSC -> Verification engine computes exact value of the FSC -> Decide whether to continue training. For HM-POMDPs: after verification, Paynt identifies the worst-case POMDP for the current FSC -> this POMDP is added to a buffer -> the RNN is retrained on the buffer (which includes initial POMDPs and accumulated worst-cases) -> loop repeats.

### Design tradeoffs
* Extraction: Alergia is principled (convergence guarantee) but slow and produces larger FSCs; SIG is fast and controllable in size but heuristic with no guarantee and may over-quantize.
* Vectorization: JAX offers speed but requires static shapes; tradeoff between batch size and memory. Dynamic action spaces need careful masking to preserve on-policyity.
* Robust loop: Buffer size and geometric progression factor (q=0.4) balance learning current worst-case vs. remembering past ones. Too few initial POMDPs can lead to poor coverage.

### Failure signatures
* Empirical value (RL) >> Verified value (FSC): Extraction fidelity loss, likely due to SIG network too small or Alergia over-merging.
* Verified value << Baseline (Saynt/rfPG): RNN failed to learn a good policy; check reward shaping, learning rate, entropy regularization.
* Robust loop unstable (wild swings in worst-case value): Worst-case POMDPs not converged or buffer management (q) inappropriate.

### First 3 experiments
1. **Single-POMDP sanity check:** Run Lexpop on a small benchmark (maze-10). Verify that extracted FSC value matches empirical RL value within 1%. Compare SIG (size=3) vs Alergia (size~20) verification times.
2. **Scalability stress test:** Run on a large benchmark (drone-2-8-1, ~520k states). Compare time-to-solution against Saynt (30m timeout). Expected: Lexpop finishes training+extraction within timeout while Saynt times out with suboptimal policy.
3. **Robustness core mechanism:** On an HM-POMDP (moving_obstacles). Run RobustLexpop with worst-case selection (green line) vs random POMDP selection (red line). Expected: worst-case selection yields higher robust value and smaller gap between empirical and verified robust values.

## Open Questions the Paper Calls Out
* Theoretical guarantees: The paper does not provide formal bounds on extraction error or robust loop convergence. Unknown: how to derive such bounds for the combined DRL and extraction pipeline.
* Hyperparameter sensitivity: The paper uses fixed hyperparameters without systematic sensitivity analysis. Unknown: how sensitive Lexpop is to choices like RNN hidden size, extraction method parameters, and buffer management across diverse domains.
* Worst-case coverage: The reliance on approximate worst-case identification via Paynt may miss critical scenarios. Unknown: whether a more exhaustive search would yield better robust policies and how approximation errors propagate.
* Domain generalization: The paper evaluates on specific benchmark families. Unknown: how Lexpop performs on entirely new domains, such as those with continuous observations, stochastic costs, or vastly larger state spaces.

## Limitations
* No theoretical guarantees for extraction error or robust loop convergence.
* Benchmarks are domain-specific; hyperparameter sensitivity is unexplored.
* Approximate worst-case POMDP computation via Paynt may miss critical scenarios.

## Confidence
* Deep RL scalability (Mechanism 1): High confidence based on empirical success on large POMDPs, though generalizability across diverse structures remains unproven.
* FSC extraction fidelity (Mechanism 2): Medium confidence; extracted FSCs are compact with small value gaps, but SIG is heuristic and Alergia may over-merge, with no fidelity guarantees.
* Iterative worst-case selection (Mechanism 3): High confidence; clear improvement over random selection, consistent with prior work (rfPG), but evaluated on few HM-POMDPs.
