# Contrastive Learning for Diversity-Aware Product Recommendations in Retail

## Quick Facts
- arXiv ID: 2602.08886
- Source URL: https://arxiv.org/abs/2602.08886
- Reference count: 18
- Primary result: Cross-entropy contrastive loss with 100 in-batch negatives increased catalog coverage by 26.4%, reduced Gini Coefficient by 6.5%, and improved NDCG@10 by 6.4% (offline); online A/B test showed 2.53% coverage lift and 9.59% diversity improvement.

## Executive Summary
The paper tackles popularity bias in IKEA's recommender system, where a long-tail distribution limits exposure for most products. To enhance catalog coverage and diversity without sacrificing relevance, the authors integrate contrastive learning into an existing LSTM-based pipeline that uses cosine similarity. Two negative sampling strategies are introduced: in-batch negatives and adaptive top-k filtering. Their best configuration (cross-entropy loss with 100 in-batch negatives) achieved substantial gains in coverage, fairness (lower Gini), and NDCG on the IKEA Netherlands dataset. An online A/B test confirmed these improvements in a real-world setting.

## Method Summary
The approach builds on a three-stage pipeline. First, static product embeddings are learned offline via Word2Vec on user view sequences (embedding size 64, window 5, skip-gram). Second, an LSTM (1 layer, hidden size 128) processes sequences of item embeddings and predicts the embedding of the next item. Third, recommendations are generated by querying an ANNOY index (angular metric, 100 trees) for nearest neighbors to the predicted embedding. The authors modify the standard cosine similarity loss by adding contrastive components. They experiment with two loss variants: a weighted loss that increases the weight on the positive similarity and subtracts the mean similarity to negatives, and a cross-entropy loss that treats similarity scores as logits with a temperature τ. Negatives are sampled in-batch (other samples' true labels, excluding items already in the input sequence) with a cap of 100, and optionally filtered to the top-k hardest negatives based on cosine similarity. Training uses Adam (learning rate 0.001, batch size 128) with early stopping on validation NDCG@10.

## Key Results
- Offline on IKEA data: catalog coverage +26.4%, Gini Coefficient -6.5%, NDCG@10 +6.4%.
- Online A/B test on IKEA website: coverage +2.53%, diversity +9.59% over baseline.
- Cross-entropy loss with 100 in-batch negatives outperformed other configurations.

## Why This Works (Mechanism)
Contrastive learning forces the model to not only pull the predicted embedding toward the true next-item embedding but also push it away from strategically chosen negatives. By using in-batch negatives (which often include popular items) and hard negatives (most similar items), the model learns to discriminate against head items and to refine the embedding space for tail products. This reduces the model's tendency to recommend only popular items, thereby increasing catalog coverage and lowering the Gini coefficient while maintaining or even improving ranking accuracy (NDCG). The temperature parameter in the cross-entropy loss sharpens the distribution, emphasizing the correct item among negatives.

## Foundational Learning

**Contrastive Learning**  
*Why needed:* Provides a framework to learn representations by contrasting positive pairs against negatives, directly optimizing for discrimination rather than just similarity.  
*Quick check:* Monitor loss decreasing and verify that the positive similarity is higher than negative similarities on a held-out batch.

**Negative Sampling**  
*Why needed:* Efficiently approximates the full softmax over the entire catalog by selecting a small subset of informative negatives (popular or hard).  
*Quick check:* Ensure negatives do not include the anchor's own history items; for in-batch, check that at least one negative per anchor exists.

**LSTM for Sequential Recommendation**  
*Why needed:* Captures user session dynamics and temporal dependencies in view sequences to predict next interaction.  
*Quick check:* Compare LSTM hidden state against a simple averaged embedding baseline on NDCG.

**Cosine Similarity Loss**  
*Why needed:* Aligns predicted and target embeddings in a high-dimensional space; works well with normalized vectors.  
*Quick check:* Verify that all embeddings are L2-normalized before similarity computation.

**Word2Vec Item Embeddings**  
*Why needed:* Provides pre-trained, semantically meaningful item representations based on co-view patterns, reducing need for end-to-end training.  
*Quick check:* Check nearest neighbors of a few known item pairs (e.g., similar furniture) to assess quality.

**ANNOY Approximate Nearest Neighbor Search**  
*Why needed:* Enables fast retrieval from a large catalog at inference time while preserving cosine similarity.  
*Quick check:* For a random query, compare ANNOY's top-100 results with brute-force cosine to recall >95%.

## Architecture Onboarding

**Component map:**  
User view sequences -> Word2Vec embedding lookup -> LSTM encoder -> Predicted embedding -> ANNOY index (all product embeddings) -> Top-K recommendations

**Critical path:**  
1. Preprocess raw logs into fixed-length sequences (max 100).  
2. Train Word2Vec on the first chronological split to obtain static embeddings.  
3. Train LSTM on the second split using contrastive loss; the model outputs an embedding for the next item.  
4. Build ANNOY index from all product embeddings (frozen).  
5. At inference, given a session, run LSTM to get a query embedding, then retrieve nearest neighbors via ANNOY.

**Design tradeoffs:**  
- *Negative sampling:* In-batch negatives are cheap and dynamic, but may be too easy; adaptive top-k filters for hard negatives but adds overhead.  
- *Frozen embeddings:* Word2Vec embeddings are static, which simplifies training but may limit adaptation; updating them could improve performance but increases complexity.  
- *Loss choice:* Cross-entropy with temperature yields sharper probability distribution, often better than weighted cosine but requires careful tuning of τ.  
- *Retrieval metric:* Using angular distance in ANNOY matches cosine similarity; if vectors are not normalized, mismatch degrades performance.

**Failure signatures:**  
- False negatives in in-batch sampling: If an item from the anchor's input sequence appears in the negative set, the model is penalized for predicting items the user already saw, leading to biased learning. Detect by checking intersection per batch.  
- Embedding normalization mismatch: If vectors are not normalized, cosine similarity values differ from ANNOY's angular distances, causing retrieval inconsistency. Check by computing norms.  
- Contrastive loss not improving diversity: If coverage or Gini does not improve while NDCG stays flat, negatives may be too easy or too many; adjust sampling cap or temperature.  
- Overfitting to validation: Early stopping on NDCG@10 may lead to models that do not generalize to coverage; monitor both metrics.

**First experiments:**  
1. **Baseline replication:** Train the vanilla LSTM pipeline with cosine loss (no contrastive) on RetailRocket using assumed hyperparameters; establish baseline metrics (coverage, Gini, NDCG) for comparison.  
2. **Negative set integrity check:** Write a validation routine that, for each batch, computes the intersection between the anchor's input item set and its in-batch negative set; assert that the intersection is empty. Log any violations.  
3. **Loss-retrieval consistency:** Ensure all product embeddings are L2-normalized and ANNOY is built with `metric='angular'`. For a random test query, compute cosine scores between predicted embedding and retrieved top-10, verify they rank in the same order as ANNOY. Also, plot cross-entropy loss curve to confirm it decreases smoothly.
