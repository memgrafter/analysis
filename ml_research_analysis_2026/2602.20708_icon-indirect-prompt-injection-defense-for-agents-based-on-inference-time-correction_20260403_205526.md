# ICON: Indirect Prompt Injection Defense for Agents based on Inference-Time Correction

## Quick Facts
- **ArXiv ID:** 2602.20708  
- **Source URL:** https://arxiv.org/abs/2602.20708  
- **Reference count:** 15  
- **Primary result:** ICON achieves a 0.4% Attack Success Rate (ASR) on indirect prompt injection attacks and improves utility under attack by over 50% relative to state-of-the-art baselines.

## Executive Summary
Indirect Prompt Injection (IPI) attacks compromise LLM agents by placing malicious instructions within retrieved content, hijacking the agent’s execution. Existing defenses either over-refuse (breaking task continuity) or fail to detect subtle injections. ICON introduces an inference-time framework that detects attacks via latent space attention anomalies and surgically steers attention to neutralize threats without terminating workflows. It combines a Focus Intensity Score (FIS) to quantify anomalous attention concentration, a lightweight Latent Space Trace Prober (LSTP) trained on adaptive attack samples to classify trajectories, and a Mitigating Rectifier (MR) that selectively suppresses adversarial attention dependencies. ICON attains near-perfect defense (ASR 0.4%), preserves agent utility (>50% gain), trains in minutes on small datasets, and generalizes to multi-modal agents and out-of-distribution attack variants.

## Method Summary
ICON operates in two phases. **Offline**, it generates adaptive IPI attacks using an LLM-as-optimizer, computes per-head attention entropy to define FIS, and selects attack-sensitive layers/heads. A lightweight CNN+MLP classifier (LSTP) is trained on aggregated FIS features (min/mean/std entropy vectors) to distinguish benign from attacked trajectories. **Online**, during generation, ICON monitors attention weights. If the LSTP flags an attack, the MR intervenes: for each anomalous head (high FIS), it computes a suppression threshold θ as a quantile of attention weights, masks high‑weight positions, and scales them down before the softmax. This redistribution restores focus to benign context tokens, allowing the agent to continue its task.

## Key Results
- **ASR 0.4%** on TrojanTools and InjectAgent benchmarks, drastically lower than baselines (e.g., Repeat Prompt 62.8%, MELON 18.5%).
- **Utility under Attack (UA) improved >50%** relative to no‑defense and >20% over heuristic baselines, maintaining task continuity.
- **Efficient & general**: LSTP trains in <2 minutes on 255 samples; defense transfers to multi‑modal agents and unseen attacks (AgentDojo OOD detection >97%).

## Why This Works (Mechanism)

#### Mechanism 1: Attention Collapse Detection via FIS
ICON identifies successful IPI attacks by an “attention collapse” pattern: abnormally concentrated focus on injected tokens within specific heads. FIS = 1 − average token entropy per head; low entropy (high FIS) indicates over‑focusing. Core assumption: adversarial redirection forces attention onto a small malicious payload, creating a sparse peak. Evidence: formal definition (Sec 4.5) and empirical FIS elevation in attacked runs. Break condition: attacks that avoid sparsity (e.g., distributed semantic manipulation) may evade detection.

#### Mechanism 2: Latent Space Trace Prober (LSTP) Classification
LSTP classifies trajectories by learning from aggregated head‑level entropy dynamics. It builds fixed‑length feature vectors (min/mean/std) from entropy sequences of K attack‑sensitive layers, concatenates them, and uses a hybrid CNN+MLP with adaptive pooling. This isolates “attention sink” patterns from variable lengths. Core assumption: these statistics form a stable, low‑dimensional manifold separating adversarial from benign executions. Evidence: >97% detection on OOD AgentDojo when trained only on TrojanTools. Break condition: future attacks that mimic benign entropy volatility may confuse the classifier.

#### Mechanism 3: Mitigating Rectifier (MR) Surgical Steering
MR neutralizes attacks by selectively suppressing anomalous query‑key dependencies without aborting generation. For each high‑FIS head, it computes θ as the (1‑τ)‑th percentile of attention weights, creates a binary mask M for weights ≥ θ, and modifies attention: Ã = A ⊙ [1 + M·(γ−1)] (γ < 1). The subsequent softmax redistributes focus to unmasked tokens. Core assumption: adversarial over‑focus is sparse; suppressing those few weights disrupts the attack while preserving benign context. Evidence: heatmaps (Fig 3) show anomalous peaks suppressed post‑mitigation. Break condition: legitimate task context that also requires concentrated attention (e.g., critical tool parameters) may be inadvertently suppressed if τ/γ are mis‑set.

## Architecture Onboarding

**Component map:**  
Critical Layer/Head Selector → FIS Calculator → Feature Aggregator → Latent Space Trace Prober (LSTP) → Mitigating Rectifier (MR)

**Critical path:**  
At each generation step:  
1. Compute attention weights for all layers/heads.  
2. For K pre‑selected critical layers, extract per‑head attention matrices.  
3. FIS Calculator computes per‑head token entropy and aggregates S_l,h.  
4. Feature Aggregator builds a fixed‑length vector z using min/mean/std across heads in these layers.  
5. LSTP classifies z as ATTACK or BENIGN.  
6. If ATTACK, MR triggers: for each anomalous head (high FIS), compute θ as (1‑τ)‑th percentile, create mask M for weights ≥ θ, apply Ã = A ⊙ [1 + M·(γ−1)].  
7. Continue generation using modified attention (after softmax).

**Design tradeoffs:**  
- **Detection Latency vs. Precision:** Restricting to K layers and simple features (min/mean/std) reduces compute but may miss attacks whose signature lies outside selected layers.  
- **Steering Scope (τ) vs. Utility:** Larger τ (higher percentile) masks more weights, increasing suppression of potential adversarial signals but risking damage to benign focus (e.g., critical parameters).  
- **Steering Intensity (γ) vs. Stability:** Lower γ more aggressively suppresses masked weights but may cause drastic latent shifts; higher γ subtler but possibly ineffective.  
- **Training Data Diversity:** Training on TrojanTools yields efficiency but may limit generalization; more diverse attack samples improve robustness at the cost of longer training.

**Failure signatures:**  
- **High ASR (False Negative):** Attack succeeds; likely FIS not elevated or LSTP misclassification – check if attack signature lies outside selected layers.  
- **High Over‑Refusal / Low UA (False Positive or Over‑Steering):** Task fails; likely MR’s θ too low or γ too aggressive – inspect post‑mitigation attention maps for excessive dispersion.  
- **No Effect (Pass‑Through):** LSTP detected but MR didn’t restore utility; possibly τ too small or anomalous heads mis‑identified – verify which heads were masked and their pre/post distributions.

**First 3 experiments:**  
1. **Reproduce Table 2 (Main Results):** Integrate ICON (LSTP+MR) into a ReAct agent with Qwen3‑8B. Evaluate ASR and UA across attack types (Ignore Instruction, Combined Attacks, TrojanTools) against baselines.  
2. **Ablate MR’s Steering Parameters (τ, γ):** On a held‑out set of successful IPI samples, vary τ (e.g., 0.7–0.95) and γ (0.3–0.9), measure ASR and UA to map the trade‑off surface.  
3. **Visualize Attention Steering (Replicate Figure 3):** For a successful intervention case, extract attention matrices for a high‑FIS head before/after MR; plot heatmaps to confirm anomalous peaks are suppressed and attention disperses.

## Open Questions the Paper Calls Out

**Open Question 1: Is the “over‑focusing” attention pattern a universal and necessary latent signature for all successful IPI attacks across diverse agent architectures and attack strategies?**  
- **Basis:** Defense hinges on the empirical insight that IPI induces abnormal concentration (Sec 4.1, 4.5). Evaluations cover specific attacks/models; not proven universal.  
- **Why unresolved:** Future attacks may avoid sparse peaks (e.g., distributed semantic manipulation), causing FIS to miss them.  
- **What evidence would resolve:** Systematic red‑teaming to craft attacks that minimize FIS while succeeding; broader evaluation across diverse methodologies.

**Open Question 2: How does the selection of “attack‑sensitive” layers (L*) based on FIS generalize across fundamentally different LLM architectures (e.g., dense vs. MoE, different positional encodings)?**  
- **Basis:** LSTP selects K layers via FIS; tested on dense decoder‑only transformers (Qwen, Llama, Mistral). Not studied on radically different architectures.  
- **Why unresolved:** The locus of attention collapse may differ across architectures; fixed layer selection may fail without re‑calibration.  
- **What evidence would resolve:** Ablations with varying layer selection (random, all, last‑layer) across MoE, vision‑language models; analysis of FIS distributions per layer across architectures.

**Open Question 3: To what extent does the Mitigating Rectifier’s attention steering preserve the semantic coherence and logical correctness of complex, multi‑step agent plans beyond just avoiding malicious tool calls?**  
- **Basis:** Evaluation uses high‑level task success (UA) but not fine‑grained plan quality. MR redistributes attention but may alter the original benign plan.  
- **Why unresolved:** Steered execution might complete the high‑level request but deviate from optimal or intended steps (e.g., skipping verification).  
- **What evidence would resolve:** Compare intermediate reasoning traces and tool call sequences against gold‑standard benign trajectories; measure plan fidelity (steps, intermediate states).

**Open Question 4: Does ICON’s training pipeline (LLM‑as‑Optimizer synthesized attacks on TrojanTools) create a robust enough decision boundary for truly novel, zero‑day IPI attacks?**  
- **Basis:** Training uses TrojanTools; OOD tests on AgentDojo/InjectAgent still within known “tool‑calling hijack” attacks. Not tested on truly novel payload formats, injection locations, or new tool categories.  
- **Why unresolved:** Synthesis optimizes for attacks stealthy against specific models; novel attacks may exploit unknown vulnerabilities or target different behaviors.  
- **What evidence would resolve:** Red‑teaming with diverse community attack techniques (encoding, homoglyphs, data exfiltration); testing on agents with new tool categories (code interpreter, DB queries).

**Open Question 5: What are the computational and memory overheads of ICON’s real‑time intervention (LSTP + MR) during long‑horizon agent deployments, and how does this scale with model size and sequence length?**  
- **Basis:** Paper emphasizes training efficiency and small parameter count but does not measure inference latency or memory overhead per token.  
- **Why unresolved:** For long contexts, running the prober and modifying attention matrices each step could add non‑trivial latency; claim of “near‑zero deployment overhead” lacks empirical validation.  
- **What evidence would resolve:** Benchmark end‑to‑end agent execution time and memory across varying context lengths (1k, 4k, 16k tokens) with/without ICON; break down overhead by component.

## Limitations
- **Hyperparameter opacity:** Optimal values for steering scope (τ), intensity (γ), and LSTP architecture are undisclosed; results likely rely on tuned settings not detailed.
- **Head selection criteria:** Process for choosing critical layers (beyond highest mean FIS) and thresholding anomalous heads is unspecified, hindering reproducibility.
- **Attack model dependency:** Defense assumes IPI always causes attention collapse; attacks avoiding sparse peaks could evade detection, a break condition not tested.

## Confidence
- **Detection Mechanism (FIS+LSTP):** Medium
- **Generalization to Multi‑Modal & OOD:** Low‑Medium
- **Surgical Steering Efficacy & Utility Preservation:** Medium
