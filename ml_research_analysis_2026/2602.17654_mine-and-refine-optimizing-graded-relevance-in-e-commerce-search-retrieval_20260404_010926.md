# Mine and Refine: Optimizing Graded Relevance in E-commerce Search Retrieval

## Quick Facts
- **arXiv ID:** 2602.17654
- **Source URL:** https://arxiv.org/abs/2602.17654
- **Reference count:** 39
- **Primary result:** Offline NDCG@10 +10.39%, Recall@10 +10.08%, Precision@10 +10.96%; online add-to-cart +2.5%, conversion +1.1%, gross order value +0.9%.

## Executive Summary
The paper introduces "Mine and Refine", a framework for learning semantic embeddings that handle graded relevance (exact, substitute, complement) and noisy long-tail queries while providing clear similarity score boundaries for stable production. It uses a multilingual Siamese retriever first trained with a label-aware supervised contrastive loss on data labeled by a finetuned lightweight LLM. Then, via ANN-based hard mining and LLM re-annotation to avoid false negatives, the model is refined with a novel multi-class circle loss that explicitly sharpens inter-class similarity boundaries. Spelling augmentation and synthetic queries further improve robustness. Offline evaluations show double-digit relative gains across key ranking metrics, and production A/B tests confirm statistically significant lifts in add-to-cart, conversion, and order value.

## Method Summary
The method follows a two-stage training pipeline. Stage 1 trains a Siamese two-tower encoder from a pretrained multilingual embedding model using a supervised contrastive (SupCon) loss on (query, item) pairs labeled with three-level relevance (2=exact, 1=substitute/complement, 0=irrelevant) by a finetuned lightweight LLM. Stage 2 performs hard mining: for each query, the Stage 1 model retrieves top-k items (k=100-200) via ANN; these mined pairs are re-labeled by the same LLM to distinguish true hard negatives (label 0 ranked high) and hard positives (label 1 or 2 ranked low). The model is then refined on the combined dataset (original + re-annotated hard set) using a multi-class circle loss that enforces explicit similarity boundaries between relevance levels. Spelling variants (30-50% of queries) and synthetic queries generated from item attributes further augment the training data.

## Key Results
- **Offline:** NDCG@10 +10.39%, Recall@10 +10.08%, Precision@10 +10.96% over a strong pretrained baseline.
- **Online:** Add-to-cart rate +2.5%, conversion rate +1.1%, gross order value +0.9% (all statistically significant).
- **Separability:** The multi-class circle loss yields sharper inter-class similarity score distributions, enabling stable thresholding and hybrid blending in production.

## Why This Works (Mechanism)
### Mechanism 1: Scalable policy-consistent labeling with a finetuned LLM
- **Claim:** A finetuned lightweight LLM provides scalable, policy-consistent three-level relevance labels, reducing annotation cost while maintaining alignment with human judgment and business rules.
- **Mechanism:** The LLM is finetuned on a human-annotated seed dataset to predict exact match (2), substitute/complement (1), and irrelevant (0). An engagement-driven audit samples disagreements between LLM labels and engagement signals, using more capable LLMs and expert validation to correct residual label noise. This creates a high-quality, large-scale supervision source.
- **Core assumption:** A lightweight LLM, once finetuned on representative human annotations, can generalize to predict relevance according to complex, multi-level product policies across diverse queries and items. Engagement signals can identify systematic labeling errors when used as a heuristic audit filter.
- **Evidence anchors:** Abstract states the goal; Section 3.1 reports 87.6% 3-class accuracy and 5.74% error reduction via audit. Neighboring work on LLM labeling supports feasibility.
- **Break condition:** If the finetuning distribution is not representative of the full query/item distribution (e.g., missing categories, niche queries), or if engagement signals poorly correlate with true relevance for certain query types, label quality degrades and propagates noise.

### Mechanism 2: Two-stage training with explicit similarity boundaries
- **Claim:** A two-stage "Mine and Refine" regimen first establishes a robust global semantic space (SupCon) and then explicitly sharpens inter-class similarity boundaries (multi-class circle loss) using LLM-reannotated hard samples, yielding better separability for graded relevance.
- **Mechanism:** Stage 1 uses label-aware SupCon on LLM-labeled data, pulling together items of the same relevance level while pushing apart different levels. Stage 2 performs ANN mining to find confusable items; these are re-annotated by the policy-aligned LLM to avoid false negatives. A novel multi-class circle loss (with parameters Δ, O) is then applied to enforce explicit similarity boundaries (e.g., push label 2 similarities >0.75, label 0 similarities <0.25), forcing clearer score gaps.
- **Core assumption:** Explicitly optimizing for predefined similarity score boundaries between relevance levels improves downstream system stability (thresholding, hybrid blending) more than loss functions that only optimize ranking order. LLM re-annotation of mined pairs is necessary to maintain label fidelity under aggressive mining.
- **Evidence anchors:** Abstract mentions multi-class circle loss for sharp boundaries; Section 4.4 details the loss formulas and boundary targets (Δ2,p=0.75, Δ0,n=0.25); Section 5.2 and Figure 3 show improved margin distributions.
- **Break condition:** If Δ/O hyperparameters are poorly calibrated for the embedding distribution or business needs, the model may over-penalize valid mid-relevance items or create unnaturally wide gaps that harm recall. If the LLM used for re-annotation has lower accuracy on the hard, confusable cases, refinement could inject noise.

### Mechanism 3: Hard mining with label-aware re-annotation to avoid false negatives
- **Claim:** Offline ANN-based hard mining surfaces query-item pairs where the current model is most confused; however, in a graded relevance setting, top-ranked items are often substitutes/complements (label 1), not true negatives (label 0). Treating them as negatives would collapse the margin between label 1 and 0. The LLM re-annotation step re-labels these mined pairs according to policy, allowing the selection of true hard negatives (label 0 ranked high) and hard positives (label 1/2 ranked low), which are then fed into the circle loss to sharpen boundaries precisely between the correct strata.
- **Mechanism:** Mining identifies items retrieved by the Stage 1 model that are often mis-ranked. A naive approach would treat all top-k items as negatives; instead, each mined pair is re-labeled by the finetuned LLM. This yields hard negatives (label 0 but ranked high) and hard positives (label 1/2 but ranked low), which are used in the circle loss to adjust boundaries without conflating relevance levels.
- **Core assumption:** The Stage 1 model retrieves a significant number of items that are relevant but under-ranked, and irrelevant items that are over-ranked. These are the most valuable for refining the decision boundaries between relevance classes.
- **Evidence anchors:** Abstract mentions mining hard samples via ANN and re-annotating to avoid false negatives; Section 4.4 explicitly defines the selection criteria (hard negatives: label 0, rank > k/2; hard positives: label 1/2, rank < k/2). Adjacent work on graded relevance thresholds underscores the pitfall of naive mining.
- **Break condition:** If the Stage 1 model is already too weak to retrieve meaningful hard samples, mining yields few useful examples. If LLM re-annotation consistency is low on the hard subset (e.g., subtle substitute distinctions), the selected set could be mislabeled and harm refinement.

## Foundational Learning
### Supervised Contrastive Learning (SupCon)
- **Why needed:** The first stage uses SupCon to build a global semantic space where items sharing the same relevance level for a query are pulled together, and items of different levels are pushed apart. Its multi-class extension accommodates three relevance labels.
- **Quick check:** How does the multi-class SupCon loss (Eq. 2) differ from binary InfoNCE, and why is it more suitable for three-level relevance?

### Circle Loss
- **Why needed:** The core refinement mechanism is a multi-class circle loss. Original circle loss unifies contrastive and softmax by using adaptive weights (O) and margins (Δ) to control convergence targets for positive/negative similarities. The paper adapts it to three strata (2 vs 0, 1 vs 0, 2 vs 1) to enforce explicit score boundaries.
- **Quick check:** In Case I (L2,0), what is the intended effect of Δ2,p=0.75 and Δ0,n=0.25 on the similarity scores s_i for label 2 items and s_j for label 0 items?

### Hard Negative Mining with Label Noise Management
- **Why needed:** In standard binary retrieval, top ANN hits are assumed negative. Here, they are often positive (label 1/2). Mining must be coupled with label verification (LLM re-annotation) to obtain reliable hard negatives and positives for the circle loss.
- **Quick check:** Why is simply taking the top-k ANN results as negatives (like ANCE) problematic in three-level relevance, and what specific step in this pipeline mitigates that?

## Architecture Onboarding
### Component map
Labeling Service -> Stage 1 Trainer -> Mining Module -> Re-annotation Service -> Stage 2 Trainer -> Deployment

### Critical path
The critical path is the ordered sequence: Labeling Service → Stage 1 Trainer → Mining Module → Re-annotation Service → Stage 2 Trainer → Deployment. Skipping or altering any step (e.g., omitting re-annotation or discarding original data in Stage 2) causes failure modes such as catastrophic forgetting or label noise corruption.

### Design tradeoffs
- *Siamese vs. asymmetric:* Siamese chosen for stability despite potential capacity loss; ablation shows Siamese + circle loss wins.
- *Mining scope (k):* Larger k finds harder/more diverse samples but increases noise & compute cost; paper finds k=100-200 optimal.
- *Circle Loss Δ parameters:* Predefined boundaries (0.75, 0.25, etc.) are a design choice; must be set based on desired separability; incorrect values may overfit or under-sharpen.
- *Augmentation ratio:* Synthetic queries and spelling variants added at low ratios (~30-50% of queries for spelling). Too high degrades performance or separability (Table 5,6).

### Failure signatures
- **Embedding collapse:** If Stage 2 uses only mined hard samples and discards original data, model forgets global structure. Monitor: NDCG@10 drops sharply, similarity distributions for label 2/1/0 overlap more.
- **Poor separability:** If circle loss is not used or Δ boundaries are wrong, violin plots show overlapping score distributions across relevance levels, leading to unstable thresholding in production.
- **High false negative rate in mining:** If LLM re-annotation is skipped, mining amplifies label noise. Symptom: Recall may improve but Precision/NDCG degrades, especially on tail queries.
- **Spelling brittleness:** If spelling augmentation is done incorrectly (e.g., in-place substitution), model performance on clean queries drops (Table 6, -7% Recall@10).

### First 3 experiments
1. **Reproduce Stage 1 SupCon baseline:** Train Siamese model only on original LLM-labeled data with SupCon loss. Validate it achieves reasonable NDCG@10 (e.g., +7.53% over larger pretrained baseline as in Table 1) and that score distributions for labels 0,1,2 have noticeable but imperfect separation.
2. **Run mining & re-annotation pipeline:** Use Stage 1 model to generate top-200 ANN results for a sample of training queries. Feed these pairs to the finetuned LLM. Verify that a significant portion (~23.4% from audit) of disagreements in the mined set are resolved by the more capable LLM/audit, and that newly identified hard negatives (label 0 ranked high) and hard positives (label 1/2 ranked low) exist.
3. **Apply multi-class circle loss refinement:** Train from Stage 1 checkpoint using the combined dataset (original + re-annotated hard set) with circle loss. Use the specified Δ parameters (0.75, 0.6, 0.4, 0.25). Measure: (a) NDCG@10 improvement over Stage 1 (aim for ~+3% relative, e.g., 7.53% → 10.39%), (b) increased margin between label 2 and 0 similarity distributions, (c) stable training (no collapse).

## Open Questions the Paper Calls Out
1. **Can the margin hyperparameters (Δ and O) in the multi-class circle loss be automatically learned from data rather than manually set?**  
   *Basis:* The authors set specific numeric values for Δ and O based on a heuristic reflection principle without describing tuning.  
   *Why unresolved:* Fixed margins may not be optimal across datasets or numbers of relevance levels; manual tuning limits applicability.  
   *What evidence would resolve it:* Treat margins as trainable parameters (with constraints) and optimize jointly on a validation set, or perform systematic hyperparameter search to see if performance beyond the reported values is achievable. Compare retrieval metrics and separability distributions.

2. **Can we reduce the labeling cost of the pipeline by replacing the expensive LLM with a more efficient classifier while maintaining label quality and retrieval performance?**  
   *Basis:* Section 3.1 describes finetuning a lightweight LLM for labeling and using more capable LLMs for engagement audits; re-annotation multiplies LLM calls.  
   *Why unresolved:* LLM usage incurs cost, latency, and rate limits; frequent retraining could become a bottleneck. A cheaper alternative that preserves accuracy is needed for sustainable scaling.  
   *What evidence would resolve it:* Train a smaller model (e.g., distilled transformer) on data labeled by the current LLM. Use it to label new pairs, and compare labeling accuracy (against human-annotated test set) and downstream retrieval performance relative to the full-LLM pipeline. Explore active learning to minimize LLM calls by only labeling uncertain samples.

3. **Would multiple rounds of mining and refinement (iterative Mine and Refine) yield further improvements over a single round, or does the benefit saturate quickly?**  
   *Basis:* The authors implement a single iteration of mining (Stage 1 → mining → Stage 2) and cite iterative refinement from prior work but do not experiment with more than one cycle.  
   *Why unresolved:* Later iterations might expose additional confusions, potentially sharpening boundaries further. Conversely, repeated mining risks overfitting to noise or catastrophic forgetting if not carefully managed.  
   *What evidence would resolve it:* Run a multi-iteration experiment: after the first Refine stage, use the updated model to perform another round of ANN mining and LLM re-annotation, then retrain (maintaining a mixture of original and newly mined data). Evaluate offline metrics (NDCG@10, Recall@10) and separability after each iteration to identify trends. Check for degradation on held-out easy queries to detect forgetting.

4. **Could in-batch negatives be safely incorporated under graded relevance by filtering out false negatives with the policy-aligned LLM, thereby improving training efficiency and potentially accuracy?**  
   *Basis:* In Section 4.4, the authors avoid in-batch negatives because the assumption that items relevant to one query are irrelevant to others is fragile with three-level labels. They rely solely on offline mined negatives, which are more expensive to obtain.  
   *Why unresolved:* In-batch negatives provide a large, zero-cost set of negative examples; if we could reliably exclude items that actually belong to positive or moderate relevance classes (using the LLM), the efficiency gains could be substantial. However, the cost of labeling every in-batch item with the LLM might negate benefits, so a trade-off exists.  
   *What evidence would resolve it:* During training, for each batch, collect all item embeddings except the designated positives. Pass each (query, item) pair through the LLM (or a fast surrogate trained on LLM labels) and only include those labeled 0 as negatives. Compare retrieval performance and training throughput against the baseline that uses only offline mined negatives. Also report the fraction of in-batch items filtered out (i.e., not true negatives) to quantify noise reduction.

## Limitations
- Major unknowns block full replication: exact Stage 1 hyperparameters (batch size, LR schedule, temperature), complete ANN index settings (HNSW parameters), and precise LLM finetuning data distribution.
- The reliance on a finetuned LLM for scalable labeling introduces potential distribution shift; its accuracy on long-tail or multilingual queries is not fully evidenced, risking label noise propagation.
- The predefined circle loss boundaries (Δ values) are chosen heuristically; their optimality across diverse product categories is unvalidated and may require costly manual tuning.

## Confidence
- **Mechanism 1 (LLM labeling pipeline):** High
- **Mechanism 2 (Two-stage training with explicit boundaries):** High
- **Mechanism 3 (Hard mining with LLM re-annotation):** Medium
