# HAPEns: Hardware-Aware Post-Hoc Ensembling for Tabular Data

## Quick Facts
- **arXiv ID:** 2603.10582
- **Source URL:** https://arxiv.org/abs/2603.10582
- **Reference count:** 40
- **Primary result:** HAPEns significantly outperforms baseline methods in hypervolume metrics on 83 tabular classification datasets by constructing diverse Pareto-optimal ensembles that balance predictive accuracy and hardware deployment cost.

## Executive Summary
Traditional post-hoc ensembling methods focus solely on predictive performance, often producing ensembles that are too costly to deploy. HAPEns addresses this by explicitly incorporating hardware efficiency into the ensemble selection process. Using a quality diversity optimization framework with a niching strategy over a 2D behavior space (e.g., memory footprint vs. loss correlation), it generates a Pareto front of ensembles offering different accuracy-cost trade-offs. Extensive experiments on 83 tabular datasets show that HAPEns achieves substantially higher hypervolume than state-of-the-art baselines, demonstrating superior ability to find efficient yet accurate ensembles. Memory footprint stands out as a particularly effective hardware objective. Even a simple greedy multi-objective variant (Multi-GES) outperforms traditional single-objective GES.

## Method Summary
HAPEns operates on a precomputed pool of model predictions on validation/test folds and per-model hardware costs (memory, inference time, disk). It defines a 2D behavior descriptor for each ensemble: (average loss correlation, total memory footprint). The behavior space is discretized into a 7×7 grid, creating 49 niches. An evolutionary algorithm maintains an archive of the best (lowest validation loss) ensemble in each niche. Starting from random ensembles, the algorithm iteratively selects parents from the archive using a dynamic mix of best-in-niche and random choices, applies two-point crossover on model indices and mutation that increments model counts. Offspring are evaluated on validation loss and their hardware descriptor; they then compete within their assigned niche to update the archive. After a fixed evaluation budget (e.g., 10,000), the set of all evaluated ensembles is post-processed to extract the Pareto front with respect to (inverted accuracy, normalized hardware cost). Baselines include GES* (all intermediate ensembles from greedy forward selection), Multi-GES (static weighted sum of accuracy and inference time), and QDO-ES (quality diversity without hardware awareness).

## Key Results
- HAPEns achieves significantly higher hypervolume than GES*, QDO-ES, and Multi-GES across 83 datasets.
- Using memory footprint as the hardware objective yields the strongest trade-offs.
- Even Multi-GES, a straightforward multi-objective extension of greedy selection, markedly improves over standard GES*.

## Why This Works (Mechanism)
### Mechanism 1: Niching preserves diverse hardware-accuracy trade-offs
HAPEns partitions the 2D behavior space (e.g., memory vs. loss correlation) into a 7×7 grid, and ensembles compete only within their assigned niche. This ensures that multiple solutions with distinct hardware-accuracy profiles survive, preventing the collapse to a single best ensemble that a single-objective greedy search would cause. Evidence: The paper states that the method "constructs diverse ensembles along the Pareto front... by maintaining a population across niches defined by a behavior space" and describes the grid-based niching. Potential break condition: If niche boundaries are fixed and do not adapt to data distribution, or if the behavior dimensions fail to distinguish meaningful hardware differences, diversity may degrade.

### Mechanism 2: Separating objective and behavior steers toward deployable ensembles
HAPEns treats predictive loss as the sole fitness objective, while the hardware cost is part of the ensemble's descriptor used for niching. This separation allows the search to explore low-cost regions early, preserving candidates that are initially less accurate but have high potential for cost-efficiency. A combined scalar objective would likely discard such candidates prematurely. Evidence: The paper explicitly "balances accuracy against hardware efficiency" and uses descriptor `d(E)=(ALC, HW)` with fitness `L(E)`. In experiments, HAPEns produces ensembles more condensed toward lower hardware cost compared to QDO-ES. Break condition: If the chosen hardware metric does not reflect true deployment constraints (e.g., using ensemble size instead of real memory), the behavior space may mislead.

### Mechanism 3: Dynamic parent selection adapts to search progress
Parent selection alternates between deterministic (best-in-niche) and stochastic (random) modes every 10 iterations, with probabilities adjusted based on which mode yields better fitness improvement. This dynamically balances exploiting the current best solutions and exploring under-sampled niches without requiring manual tuning. Evidence: Section 3 describes the combined dynamic strategy; EXP3 shows robust performance across cost metrics, indicating adaptability. Break condition: If the 10-iteration window is too short or long relative to dataset complexity, the adaptation may be too slow or jittery, harming efficiency.

## Architecture Onboarding
- **Component Map:** Model Pool & Cost Profiler -> Behavior Space Definer -> Niche Grid & Archive -> Evolution Engine -> Evaluator -> Pareto Extractor. (The Evolution Engine and Evaluator interact in a loop that updates the archive.)
- **Critical Path:** Initialize random ensembles → evaluate → assign to niches. Loop: select parents from archive (dynamic mix) → crossover/mutate → evaluate offspring → update niche archives → repeat until evaluation budget exhausted → extract non-dominated Pareto set from all evaluated ensembles.
- **Design Tradeoffs:**  
  *Behavior space dimensionality:* 2D keeps niche count manageable (7×7=49); higher dimensions explode combinatorially.  
  *Grid resolution:* Fixed 7×7 balances diversity and sparsity; finer grids risk empty niches, coarser reduces resolution.  
  *Hardware metric choice:* Memory footprint was most effective; time or disk may be less correlated with deployment constraints.
- **Failure Signatures:**  
  *Archive collapse:* Many niches empty → diversity loss → narrow Pareto front.  
  *Cost-accuracy correlation:* If all low-cost models are weak, Pareto front becomes a straight trade-off with no low-cost high-accuracy options.  
  *Duplicate explosion:* Mutation or rejection sampling ineffective → many identical offspring → stagnation (emergency brake triggers).
- **First Experiments:**  
  1. **Baseline replication:** Run GES*, Multi-GES (weight 0.68), QDO-ES on a small dataset subset; verify HAPEns ranks highest in hypervolume as reported.  
  2. **Ablation: Cost metric:** Run HAPEns with memory, time, disk individually; confirm memory/time yield highest HV.  
  3. **Sensitivity: Niche count:** Vary grid size (5×5, 7×7, 9×9) on 2–3 datasets; monitor Pareto solution count and HV. Expect 7×7 optimal.

## Open Questions the Paper Calls Out
1. Can dynamic adjustment of objective weights in HAPEns improve adaptation to varying hardware constraints compared to static weighting? (Future work suggested in Section 6.)
2. How does simultaneous optimization of multiple hardware cost metrics (e.g., memory and inference time) affect Pareto front quality relative to optimizing each separately? (Not explored due to scalability concerns.)
3. Why does memory footprint consistently outperform other metrics like inference time in balancing accuracy and deployment cost? (Not analyzed; may correlate with model complexity.)
4. Do the hardware-aware ensembles selected on simulated measurements maintain their trade-offs when deployed on real heterogeneous hardware? (Requires real-device benchmarking.)

## Limitations
- Incomplete specification of QDO hyperparameters (evaluation budget, archive update frequency, sliding parameters) hinders exact replication.
- The focus on memory as the primary hardware metric may not generalize to deployment scenarios where latency or disk usage are critical.
- The fixed 7×7 grid and choice of behavior dimensions (memory vs. loss correlation) are arbitrary and may not be optimal for all datasets.

## Confidence
- Pareto front construction via niching: Medium
- Explicit hardware objectives improve trade-offs: Medium
- Dynamic parent selection benefits search: Medium
- Overall hypervolume superiority: Medium
