# Conservative & Aggressive NaNs Accelerate U-Nets for Neuroimaging
## Quick Facts
- **arXiv ID:** 2601.17180
- **Source URL:** https://arxiv.org/abs/2601.17180
- **Reference count:** 16
- **Primary result:** Conservative NaNs reduce convolutions by an average 30% with no segmentation/denoising accuracy loss; speedups exceed 2× when NaN density is ≥75%.

## Executive Summary
The paper tackles computational waste in medical image CNNs caused by numerical noise in max pooling/unpooling operations, which can make up to two-thirds of convolutions redundant. It introduces Conservative NaNs (marking all numerically tied max indices as NaN during unpooling) and Aggressive NaNs (outputting NaN directly when a pooling window has many near-equal values). Combined with NaN Convolutions that skip compute when a patch's NaN ratio exceeds a threshold, the method accelerates inference without architectural changes. On neuroimaging U-Nets, Conservative NaNs consistently skip ~30% of convolutions with zero accuracy loss, while Aggressive NaNs achieve higher skipping (up to 69%) but with some degradation. For inputs with >67% NaNs—common in high-resolution MRIs—the approach yields an average 1.67× speedup, rising above 2× at 75%+ NaN density.

## Method Summary
The method modifies standard max pooling/unpooling and convolution layers. Conservative NaNs alters unpooling: during pooling, if multiple values in a window are equal within ε=1e-7, all their indices are stored; during unpooling, NaNs are placed at all those indices unless a single stable max exists. Aggressive NaNs alters pooling: if the count of values near the maximum exceeds a threshold *t₁*, the pooling output is NaN. These NaNs propagate through the network. NaN Convolution wraps standard convolution: for each sliding window, if the fraction of NaN inputs ≥ *t₂*, the entire output location is set to NaN (skipping multiply-accumulate operations). For patches below *t₂*, NaNs are replaced by a summary value (mean or sampled max) to enable computation. The system is applied as drop-in replacements to existing layers, requiring only threshold tuning.

## Key Results
- Conservative NaNs reduced convolutions by an average 30% (up to 64.64% per layer) on neuroimaging models, with no loss in Dice (segmentation) or PSNR (denoising).
- Aggressive NaNs achieved higher skipping (up to 69.30%) but incurred accuracy drops in some models (e.g., PSNR decrease in FONDUE).
- For inputs with >67% NaNs (typical in brain MRI), inference speedup averaged 1.67×; speedups exceeded 2× when NaN density reached 75–90%.

## Why This Works (Mechanism)
**Mechanism 1:** Redundant computations are eliminated by propagating NaNs from numerically unstable max indices (where values are tied within ε). The core assumption is that such voxels are dominated by floating-point noise and do not meaningfully influence final outputs. Evidence: Monte Carlo arithmetic analysis showed many model embeddings were pure noise yet segmentations remained accurate. Break condition: if downstream layers are sensitive to NaNs in semantically meaningful regions (e.g., dense tissue), accuracy degrades—observed with Aggressive NaNs in some cases.

**Mechanism 2:** Aggressive NaNs preemptively marks entire pooling windows as NaN if many values are near-equal (*Counter > t₁*), avoiding unstable index propagation earlier. The assumption is that windows with many tied values are fundamentally ambiguous. Evidence: The formalism defines pooling output as NaN under this condition; experiments show higher skipping but occasional performance impact when *t₁* is too low. Break condition: suppressing too many voxels harms models sensitive to background/foreground distinctions.

**Mechanism 3:** NaN Convolution skips multiply-accumulate when the NaN ratio in a sliding window patch ≥ *t₂*. The assumption is that patches dominated by NaNs contribute negligibly to the final output. Evidence: Speedup experiments consistently exceeded 2× at 75% and 90% NaN presence. Break condition: if *t₂* is set too low, patches with residual signal may be skipped, harming accuracy; if too high, skipping is insufficient.

## Foundational Learning
- **Concept: Numerical Stability & Floating-Point Noise**
  - *Why needed:* The method hinges on distinguishing numerical noise (artifacts of finite precision) from true signal. Understanding ε-thresholds and significant digits explains why "near-equal" values are unstable.
  - *Quick check:* If two float32 values differ by 1e-8, are they reliably distinguishable as different signals? What does this imply for max index selection?
- **Concept: Max Pooling/Unpooling Index Propagation**
  - *Why needed:* Instability originates in non-deterministic index selection when values tie. The solutions directly modify the standard "store index / place value at index" mechanism.
  - *Quick check:* In a 2×2 window with [[1.0, 1.0+1e-8], [1.0, 1.0]], how many indices does max_pool2d return? Is the index consistent across forward passes?
- **Concept: NaN Semantics & Propagation in PyTorch**
  - *Why needed:* NaNs are the skipping vehicle. Engineers must know NaN != NaN, that NaNs propagate through arithmetic, and that native convolutions may produce NaNs if inputs contain them—hence the need for explicit NaN handling in NaN Convolution.
  - *Quick check:* What is `torch.tensor([1.0, float('nan')]) * 2`? How does this differ from the behavior needed when `r_c,h,w < t₂` in NaN Convolution?

## Architecture Onboarding
**Component map:** Standard nn.MaxPool2d/3d → ConservativeNaNPool/AggressiveNaNPool → Modified indices/NaNs → Corresponding MaxUnpool2d/3d (placing NaNs) → NaNConv (wrapped around nn.Conv2d/3d) → Output.

**Critical path:** 1. Replace pooling/unpooling and wrap convolutions with NaNConv (t₂=1.0, Approach A). Validate baseline accuracy matches original. 2. Sweep t₂ downward (e.g., 0.8→0.4), measuring skip ratio and Dice/PSNR to find accuracy breakpoint. 3. Enable AggressiveNaNPool (set t₁), then repeat t₂ sweep. 4. Benchmark inference speed across controlled NaN densities.

**Design tradeoffs:** Conservative vs. Aggressive: Conservative is safer (no accuracy loss reported) but skips less; Aggressive skips more but risks degrading valid signal. Approach A (mean substitution) smooths outputs; Approach B (Gaussian sample) adds variability. t₂ is the primary speed knob—lower values speed up inference but risk accuracy loss; optimal t₂ is data/model-dependent.

**Failure signatures:** Silent accuracy drop (e.g., Dice/PSNR degrades subtly in homogeneous tissue regions). NaN explosion (final outputs become all NaN/zero). No speedup (NaN density never exceeds t₂, common in natural images). Diagnose by monitoring layer-wise NaN ratios and per-slice metrics.

**First 3 experiments:** 1. Conservative NaN baseline on FastSurfer: apply with t₂=0.5, Approach A; record layer-wise skip ratio and Dice; expect ~30% skipping with no loss. 2. Aggressive NaN threshold sweep: enable Aggressive (t₁=3), sweep t₂ from 1.0 to 0.4; plot skipped convolutions vs. Dice to identify knee point. 3. Speed validation: generate synthetic inputs with precise NaN fractions (50%, 67%, 75%, 90%); benchmark GPU/CPU inference; verify speedup >1.5× at 67% and >2× at 75%+.

## Open Questions the Paper Calls Out
1. How can NaN propagation be extended to layers like adaptive pooling and linear layers to maintain efficiency gains across entire architectures?
2. Can NaN-based skipping be combined with other efficiency techniques (e.g., sparse tensors, quantization, pruning) to yield multiplicative speedups without degradation?
3. What specific data and architectural characteristics determine whether Conservative or Aggressive NaNs will yield substantial speedups (>50% skipping) with negligible accuracy loss?
4. Can thresholds (ε, t₁, t₂) be automatically adapted per layer or dataset to eliminate manual tuning while preserving performance?

## Limitations
- The exact *t₁* threshold for Aggressive NaNs is undefined; the paper treats it as user-defined but does not specify values used in key experiments.
- Implementation details for NaN replacement in Approach A/B (e.g., mean/max computed per window or globally) are ambiguous.
- Pre-trained model weights for FastSurfer v2.1.1 and FONDUE v1.1 are not verifiable via provided links, hindering exact replication.
- Handling of NaNs in final layers for classification models (e.g., Xception) remains unspecified; the paper notes NaNs are converted to zeros before adaptive pooling/linear layers but details are missing.

## Confidence
- **Mechanism (noise-driven redundancy):** Medium. Supported by Monte Carlo arithmetic analysis but lacks independent validation.
- **Performance results (30% avg skip for Conservative; up to 69% for Aggressive):** Medium-High. Precise numbers are claimed across four models, but raw experimental data/code checksums are absent.
- **Inference speedup (≥1.67× for >67% NaNs):** Medium. Benchmarks are plausible but hardware/driver specifics may affect replicability.
