# MoXaRt: Audio-Visual Object-Guided Sound Interaction for XR
## Quick Facts
- **arXiv ID**: 2603.10465
- **Source URL**: https://arxiv.org/abs/2603.10465
- **Reference count**: 40
- **Primary result**: Achieved 36.2% improvement in listening comprehension and the lowest Word Error Rate (0.3824) among baselines, with ~2 s latency for up to 5 sources.

## Executive Summary
MoXaRt is a system for audio-visual object-guided sound interaction in extended reality (XR) that addresses the problem of entangled sound sources. It employs a real-time cascaded architecture: a coarse audio-only separation runs in parallel with visual detection of sources (faces, instruments); visual anchors then guide refinement networks to isolate individual sources from a single audio channel. The system handles up to five concurrent sources with a consistent latency of approximately 2 seconds. In a user study with 22 participants across six real-world scenarios, MoXaRt increased listening comprehension by 36.2% (p = 0.0058) and significantly reduced cognitive load (p < 0.001). Technical evaluation on a new dataset of 30 one-minute recordings showed the offline model achieved the lowest Word Error Rate (0.3824) compared to baselines, and the real-time distilled model outperformed AudioScopeV2.

## Method Summary
MoXaRt's core method is a two-stage cascaded architecture designed for real-time operation. The first stage performs coarse source separation directly from the audio channel, while simultaneously running a visual detector to identify sound-producing objects (e.g., faces, instruments) in the video stream. The visual detections provide spatial and semantic anchors that guide a second-stage refinement network, which re-isolates each source from the original single-channel audio using the coarse estimates and visual context. This design leverages both modalities to improve separation quality, especially in adversarial acoustic environments. The system can separate up to five concurrent sources and maintains a processing latency of about 2 seconds.

## Key Results
- In a 22-participant user study across six real-world XR scenarios, MoXaRt increased listening comprehension by 36.2% (p = 0.0058) and substantially reduced cognitive load (p < 0.001).
- The offline model achieved the lowest Word Error Rate (0.3824) on a new dataset of 30 one-minute recordings compared to baseline methods.
- The real-time distilled model significantly outperformed its architectural basis (AudioScopeV2) while consistently processing up to 5 concurrent sources with ~2 s latency.

## Why This Works (Mechanism)
MoXaRt works by combining coarse audio separation with visual grounding to resolve entangled sounds. The coarse separation provides an initial but noisy estimate of individual sources. Visual detection identifies the positions and identities of sound-producing objects in the scene, creating anchors that are semantically and spatially meaningful. These anchors guide the refinement networks to re-extract each source from the original mixed audio, effectively using visual context to disambiguate overlapping sounds. This cascaded approach allows the system to handle multiple sources and improves robustness in challenging acoustic conditions, leading to better downstream performance like speech recognition and reduced cognitive load for users.

## Architecture Onboarding
**Component map**:  
Audio stream -> Coarse Audio Separator -> Initial source estimates; Video stream -> Visual Detector (faces, instruments) -> Visual anchors; Initial estimates + anchors -> Refinement Networks -> Final separated sources. All components run in real-time with parallel audio and visual processing.

**Critical path**:  
The overall latency is determined by the slower of the coarse separation and visual detection stages, followed by the refinement networks. Since coarse separation and visual detection operate concurrently, their maximum completion time precedes refinement. The refinement stage then processes each source (potentially in parallel) to produce final outputs. Any delay in visual detection (e.g., due to complex scenes) directly increases end-to-end latency.

**Design tradeoffs**:  
- *Latency vs. quality*: More iterative refinement or deeper networks improve separation but increase latency; MoXaRt balances with a fixed ~2 s budget.  
- *Number of sources*: Supporting more sources strains both visual detection and refinement, leading to performance degradation; the system caps at 5.  
- *Visual dependency*: The system relies on clear visual detection; occluded or non-visible sources limit effectiveness.  
- *Computational resources*: Running both audio and visual models in real-time demands significant GPU/CPU, potentially limiting deployment on low-power XR devices.

**Failure signatures**:  
- Visual detection misses (e.g., faces turned away) result in missing anchors, causing refinement to revert to coarse outputs or produce distorted sources.  
- Exceeding the source capacity (>5) leads to dropped or merged sources, reducing separation quality.  
- High reverberation or noise in the audio degrades the coarse stage, which the refinement may not fully correct.  
- Latency spikes if either audio or visual processing exceeds expectations, causing lag in XR interaction and potential VR sickness.

**First experiments**:  
1. Evaluate separation quality (e.g., SDR, WER) on synthetic mixtures with ground-truth sources to quantify baseline performance and identify failure modes.  
2. Measure end-to-end latency on target XR hardware (e.g., Meta Quest 3) while varying the number of sources and scene complexity to characterize real-time behavior.  
3. Conduct a within-subjects user study comparing MoXaRt against an audio-only baseline on a listening comprehension task in adversarial environments to validate claimed benefits.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: How does interactive latency impact user performance and subjective experience in XR sound separation systems?
- Basis in paper: [explicit] Section 7.1 states that "further investigation is required to determine how such delays are perceived by users and their ultimate impact on the subjective experience."
- Why unresolved: MoXaRt operates with a fixed ~2s latency, but the trade-offs between latency, separation quality, and user-centric metrics (e.g., cognitive load) are not empirically established.
- What evidence would resolve it: Conduct controlled user studies varying system latency (e.g., 0.5s to 3s) while measuring listening comprehension scores, NASA-TLX for cognitive load, and qualitative feedback across diverse XR scenarios.

### Open Question 2
- Question: Can gaze-based source prioritization effectively enable scalable sound separation in environments with numerous concurrent sources?
- Basis in paper: [explicit] Section 7.3 proposes that "future work should leverage gaze-based prioritization to isolate only the K sources relevant to the user" to handle scalability beyond four sources.
- Why unresolved: Current cascaded architecture attempts to separate all detected sources, leading to performance degradation with increased sources; the gaze-based approach remains conceptual and unevaluated.
- What evidence would resolve it: Implement a prototype integrating real-time gaze tracking to select target sources, then test in multi-source (5+) acoustic scenes comparing separation metrics (e.g., WER, DNSMOS) and computational load against full-separation baselines.

### Open Question 3
- Question: What natural input modalities (e.g., gaze, micro-gestures) provide the most seamless and socially acceptable control for interactive sound remixing in XR?
- Basis in paper: [explicit] Section 7.4 notes that "future iterations of MoXaRt could benefit from more natural input modalities" as the current controller-based interface may hinder social engagement.
- Why unresolved: No comparative evaluation of alternative interaction techniques exists; the suitability of hands-free methods for precise volume control and source selection in dynamic social settings is unknown.
- What evidence would resolve it: Design and deploy alternative interfaces (e.g., gaze-dwelling for selection, pinch gestures for volume) in a within-subjects user study, measuring task efficiency, error rates, and social comfort across the scenarios from the user study.

## Limitations
- Small private dataset (30 minutes) with ≤5 sources limits generalizability to more sources and diverse scenes.
- High latency (~2 s) may be unsuitable for interactive XR and was not measured on target hardware.
- User study underpowered (22 participants) with insufficient reporting on demographics and task design, affecting external validity.
