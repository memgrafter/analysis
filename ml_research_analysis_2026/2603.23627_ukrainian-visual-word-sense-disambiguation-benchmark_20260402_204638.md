# Ukrainian Visual Word Sense Disambiguation Benchmark

## Quick Facts
*   **arXiv ID:** 2603.23627
*   **Source URL:** https://arxiv.org/abs/2603.23627
*   **Reference count:** 0
*   **Primary result:** All tested multimodal models significantly underperformed the English CLIP baseline on the new Ukrainian Visual-WSD benchmark, with top HIT@1 at 42.78 vs. 60.48.

## Executive Summary
This paper introduces the first benchmark for Visual Word Sense Disambiguation (V-WSD) in Ukrainian, a low-resource language. The benchmark consists of 87 polysemous nouns, each paired with a target image and nine challenging negatives, curated from Ukrainian Wikipedia and refined by experts. Eight multimodal models were evaluated zero-shot. All models performed substantially worse than a previously established zero-shot CLIP baseline for English, highlighting a significant performance gap for low-resource languages on this fine-grained visual-semantic task.

## Method Summary
The benchmark dataset was constructed semi-automatically: an initial set of polysemous nouns from a Ukrainian homonym dictionary was expanded by retrieving relevant Wikipedia articles and their associated images. Philology experts then refined the set, ensuring accurate sense-image mappings and curating a challenging set of nine negative images per instance. These negatives were carefully tiered: three representing alternative senses of the target word, three showing visually similar concepts from the same domain, and three random distractors. Model evaluation is performed zero-shot. For models with accessible encoders (e.g., CLIP variants), a query phrase is built from the target word and its contextual triggers. The text embedding of this query is compared via cosine similarity to the image embeddings of all ten candidates, and the images are ranked. For closed API models (GPT-4V, GPT-4o), a prompt instructs the model to rank the images. Performance is measured using Mean Reciprocal Rank (MRR) and HIT@1.

## Key Results
*   The top-performing model on the Ukrainian benchmark achieved an HIT@1 of 42.78 and an MRR of 60.30.
*   All eight evaluated models significantly underperformed the zero-shot multilingual CLIP baseline previously reported for English (HIT@1: 60.48, MRR: 73.88).
*   The substantial gap reveals a notable deficiency in current multimodal models' ability to handle fine-grained visual sense disambiguation for low-resource languages like Ukrainian.

## Why This Works (Mechanism)
### Mechanism 1: Challenging Negative Sampling
- **Claim:** The benchmark's structured negative image sampling (3 alternative senses, 3 similar-domain concepts, 3 random) creates a difficult test requiring fine-grained discrimination.
- **Mechanism:** Domain-aware negatives (alternative senses, similar concepts) act as plausible distractors that are visually or conceptually close to the target, while random negatives introduce global interference. Expert validation ensures these negatives are relevant and challenging, preventing models from relying on coarse heuristics.
- **Evidence Anchors:** [abstract] "each paired with a target image and nine challenging negative images, curated semi-automatically from Ukrainian Wikipedia and refined by philology experts." [section 3.2] Details on negative construction from the same Wikipedia domain.
- **Break Condition:** If negatives were trivially distinct, the task would not probe nuanced discrimination; validity depends on negatives being plausible alternatives.

### Mechanism 2: Embedding-Based Ranking Evaluation
- **Claim:** Ranking images by the cosine similarity between the multimodal embeddings of the text query and candidate images provides a sensitive metric for V-WSD.
- **Mechanism:** Models map semantically aligned text-image pairs to proximate vectors in a joint embedding space. The evaluation directly tests this alignment by selecting the image with the highest cosine similarity to the query embedding, measuring the model's ability to match the intended visual sense.
- **Evidence Anchors:** [section 4] Describes the process of comparing query and image embeddings via cosine similarity. [section 4.1] Defines MRR and HIT@1.
- **Break Condition:** For models not exposing embeddings (e.g., GPT-4V), prompting is used instead, which may introduce noise or bias compared to a true embedding similarity measurement.

### Mechanism 3: Low-Resource Language Performance Gap
- **Claim:** The large performance drop on Ukrainian vs. English is primarily caused by Ukrainian's low-resource status, limiting multimodal representation quality.
- **Mechanism:** Multilingual pretraining data is heavily skewed toward high-resource languages. Ukrainian has less aligned image-text data, suffers from subword tokenizer imbalance, and "one-size-fits-all" domain adaptation fails to capture language-specific semantics and cultural visual contexts, leading to poorer cross-modal alignment.
- **Evidence Anchors:** [abstract] Direct comparison to English CLIP baseline showing significant underperformance. [section 1] Discusses tokenizer imbalance and data scarcity issues for low-resource languages.
- **Break Condition:** If future work introduces dedicated large-scale Ukrainian image-text pretraining or effective cross-lingual transfer, the gap could close, confirming resource scarcity as the primary driver.

## Architecture Onboarding
**Component Map:**
Benchmark Data (JSON/CSV) -> Query Builder -> Model Interface (Text Encoder + Vision Encoder) -> Ranking Engine (Cosine Similarity) -> Metrics Calculator (MRR, HIT@1). For API models: Benchmark Data -> Prompt Builder -> API Client -> Response Parser -> Ranking Engine.

**Critical Path:**
1.  Load a benchmark entry (target word, triggers, 10 image paths/URLs).
2.  Construct the text query string (e.g., target word + trigger words).
3.  Obtain the query embedding from the model's text encoder.
4.  For each of the 10 images, load/preprocess and obtain its image embedding from the vision encoder.
5.  Compute cosine similarity between the single query embedding and each of the 10 image embeddings.
6.  Sort the images by descending similarity; identify the rank of the ground-truth positive image.
7.  Repeat for all entries; aggregate ranks to compute final MRR and HIT@1.
8.  For API-based models, replace steps 3-5 with a single prompt that asks the model to return a ranked list of the 10 images.

**Design Tradeoffs:**
*   **Precomputation vs. On-the-fly:** Precomputing all image embeddings speeds up evaluation but requires significant storage and locks in a specific model. On-the-fly computation is flexible but slow, especially for large models or API calls.
*   **Model Choice:** Open-source models (CLIP variants) allow full control and fast local execution. API models (GPT-4V/o) offer potential state-of-the-art capability but introduce cost, latency, rate limits, and potential nondeterminism.
*   **Data Handling:** Robust error handling for corrupt image files or inaccessible URLs is needed. Skipping failed entries vs. failing the entire run is a key decision.
*   **Reproducibility:** Using fixed seeds for any randomness (e.g., image ordering if shuffled) and choosing deterministic model versions is critical for fair comparison.

**Failure Signatures:**
*   **Extremely low HIT@1 (<5%):** Indicates a fundamental failure, likely the model cannot map the Ukrainian query to any relevant visual concept.
*   **High variance across words:** Suggests sensitivity to specific semantic domains or image styles not well-represented in training.
*   **Frequent crashes/exceptions:** During image loading, preprocessing, or API calls, pointing to environment or data access issues.
*   **Inconsistent rankings for API models:** Large variance in scores across multiple runs with the same input suggests prompt sensitivity or nondeterministic model behavior.

**First 3 Experiments:**
1.  **Baseline Replication:** Evaluate a standard zero-shot multilingual CLIP model (e.g., `clip-ViT-B-32-multilingual-v1`) on the Ukrainian benchmark. This confirms the evaluation pipeline's correctness and establishes a local baseline to compare against the paper's reported scores.
2.  **Architecture Comparison:** Compare performance across different model families (e.g., different CLIP variants, BLIP, GPT-4o) to analyze the impact of encoder architecture, pretraining data, and model scale on the Ukrainian V-WSD task.
3.  **Negative Sampling Ablation:** Re-run the evaluation using only a subset of the nine negatives (e.g., only the 3 random negatives, or only the 6 domain-aware negatives) to quantify how much each negative tier increases task difficulty and discriminates between model capabilities.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How does incorporating undocumented but widely used Ukrainian neo-lexemes (e.g., "бот" as "program agent", "град" as "combat vehicle") affect Visual-WSD model performance and benchmark validity?
- **Basis in paper:** Future plans section identifies these words as missing from current lexicography and planned for inclusion; Limitations section notes exclusion of such "undocumented homonyms" as a constraint.
- **Why unresolved:** The current benchmark excludes these terms, so their impact on measuring model capabilities for modern, evolving language use remains unknown.
- **What evidence would resolve it:** Expand the benchmark with a curated set of neo-lexemes, re-evaluate models, and compare performance shifts.

### Open Question 2
- **Question:** To what extent does reliance on Ukrainian Wikipedia—with its noted issues of missing images, incomplete sections, and misleading links—bias the benchmark's difficulty and generalizability compared to the English benchmark built from a more complete resource?
- **Basis in paper:** Data sources section explicitly details Ukrainian Wikipedia's shortcomings and how they necessitated expert intervention, unlike the presumably more reliable English Wikipedia used in prior work.
- **Why unresolved:** The semi-automatic curation process was shaped by these deficiencies, but the specific influence of Wikipedia's incompleteness on image selection difficulty and resulting model scores is unquantified.
- **What evidence would resolve it:** Construct a controlled subset of the benchmark using an alternative, high-quality image-text source (e.g., curated datasets), then compare model performance and error patterns against the Wikipedia-derived version.

### Open Question 3
- **Question:** What specific factors—such as subword tokenizer imbalance, training data distribution mismatch, or vision-text alignment disparities—are the primary drivers of the significant performance gap between Ukrainian and English in Visual-WSD?
- **Basis in paper:** Introduction discusses general challenges for low-resource languages and the results show a large gap, but the paper does not isolate or test these hypothesized causes.
- **Why unresolved:** The gap is established descriptively, but no ablation or diagnostic analysis pinpoints which factors contribute most, hindering targeted improvement.
- **What evidence would resolve it:** Conduct controlled experiments: (a) analyze tokenizer coverage and embedding quality for Ukrainian vs. English; (b) vary training data composition for multimodal models; (c) probe model attention or alignment metrics on Ukrainian vs. English samples.

## Limitations
*   **Dataset Access:** The benchmark is not publicly released, blocking direct replication and independent verification of results.
*   **Underspecified Negative Sampling Logic:** The exact criteria and rules used by experts to assign images to the three negative tiers (alternative sense, similar concept, random) are not detailed, limiting understanding of each tier's contribution to difficulty.
*   **Prompt Engineering Ambiguity:** For API-based models, the exact prompt template, image presentation order, and whether order effects were controlled are not specified, risking unreported sensitivity.
