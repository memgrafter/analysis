# Do Multi-Agents Dream of Electric Screens? Achieving Perfect Accuracy on AndroidWorld Through Task Decomposition

## Quick Facts
- **arXiv ID:** 2602.07787
- **Source URL:** https://arxiv.org/abs/2602.07787
- **Reference count:** 17
- **Primary result:** Minitap achieves 100% success on AndroidWorld (116 tasks), exceeding human performance (80%) and prior best (97.4%).

## Executive Summary
Minitap is a multi-agent mobile interaction system that achieves perfect 100% accuracy on the AndroidWorld benchmark, surpassing human performance (80%) and the previous state-of-the-art (97.4%). It addresses key failure modes in single-agent systems through three targeted mechanisms: cognitive separation across six specialized agents to prevent context pollution, deterministic post-validation of text input to ensure execution reliability, and meta-cognitive reasoning to escape repetitive loops. Ablations confirm the individual contributions of each mechanism. The system operates efficiently with an average task time of 31 seconds and reduces cost by 32% via optimized model allocation, assigning frontier models only to the central Cortex agent while using budget models elsewhere.

## Method Summary
Minitap employs a fixed multi-agent graph architecture built on LangGraph, comprising six specialized agents: Planner decomposes goals into subgoals; Orchestrator manages subgoal lifecycle and routing; Contextor fetches device state from UI accessibility hierarchies and screenshots; Cortex makes central decisions using JSON actions and meta-cognitive analysis; Executor dispatches tool calls in strict sequence; Summarizer compresses history. The system integrates three key innovations: (1) cognitive separation isolates reasoning processes to prevent context pollution; (2) deterministic post-validation ensures text input accuracy via a six-step verification sequence (focus, cursor positioning, input, re-fetch UI, extract text, compare); (3) meta-cognitive reasoning in the Cortex analyzes decision history to detect cycles and trigger strategy changes. Hybrid perception combines UI hierarchy and visual screenshot, and the Executor runs actions sequentially. Evaluation uses a Kubernetes infrastructure provisioning fresh Android emulators per task, with programmatic verification of success. Cost optimization is achieved by using frontier models only for the Cortex and budget models for other agents, reducing cost by 32% while maintaining perfect accuracy.

## Key Results
- 100% success rate on AndroidWorld (116 tasks), exceeding human performance (80%) and prior best (97.4%).
- Ablation contributions: multi-agent decomposition (+21 points), verified execution (+7 points), meta-cognition (+9 points).
- Average task completion time: 31 seconds; cost reduction of 32% via optimized model allocation.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Isolating reasoning processes into specialized agents ("cognitive separation") prevents context pollution and reasoning drift in long-horizon tasks.
- **Mechanism:** Six agents (Planner, Orchestrator, Contextor, Cortex, Executor, Screen Analyzer) each maintain a focused context window appropriate to their role (e.g., Planner reasons about goal structure without execution noise). This modular decomposition replaces a monolithic agent where mixed traces degrade performance.
- **Core assumption:** A single LLM cannot simultaneously maintain optimal context for planning, perception, execution history, and state assessment over many steps; mixing these contexts ("pollution") causes reasoning errors.
- **Evidence anchors:**
  - [abstract] States multi-agent decomposition addresses "context pollution from mixed reasoning traces" and contributed +21 points in ablations.
  - [section 3.2] Categorizes 16 failures (38%) under "Context Management," split into "reasoning drift," "context pollution," and "state staleness."
  - [section 4.1] Details the six-agent LangGraph architecture where each node has a scoped role (e.g., Contextor only gathers device state, Summarizer manages history).
- **Break condition:** If a task inherently requires frequent cross-domain synthesis (e.g., planning must constantly reference recent execution errors), strict agent boundaries could introduce coordination overhead or information loss, potentially negating benefits.

### Mechanism 2
- **Claim:** Deterministic post-validation of text input actions against actual device state ("verified execution") eliminates silent failures that cause cascading errors in form-filling tasks.
- **Mechanism:** For text entry, the system uses a fixed, non-LLM procedure: (1) focus element with fallbacks, (2) type text, (3) immediately read fresh UI hierarchy, (4) extract actual field content, (5) compare intended vs. actual. The Cortex receives this verification result, enabling informed retry or adaptation.
- **Core assumption:** LLM-generated action commands for text input are unreliable due to keyboard state, focus issues, and encoding problems; only deterministic code with direct state inspection can confirm success.
- **Evidence anchors:**
  - [abstract] Lists "deterministic post-validation of text input" as a key mechanism, contributing +7 (or +15 with sequential execution) points.
  - [section 3.2] Identifies "Text input failures" as 12 of 17 "Execution Reliability" failures, where agents believed text was entered correctly when it was not.
  - [section 4.2] Explicitly describes the 6-step validation sequence and separation of intent (Cortex) from verification (deterministic code).
- **Break condition:** If the device state retrieval (UI hierarchy) is itself delayed, inaccurate, or inconsistent with visual rendering (e.g., due to asynchronous UI updates), the verification check could produce false negatives/positives, misleading the Cortex.

### Mechanism 3
- **Claim:** Meta-cognitive reasoning that continuously analyzes the decision history ("meta-cognitive reasoning") detects and escapes repetitive action loops.
- **Mechanism:** Before each decision, the Cortex examines the sequence of prior agent outputs and actions to identify cycles (repeating state-action sequences without progress), evaluate current strategy failure, and trigger a deliberate strategy change (e.g., replanning via Orchestrator).
- **Core assumption:** Standard LLM-driven agents lack intrinsic mechanisms to notice they are in a loop; they require an explicit, history-monitoring layer to detect stagnation and force exploration of alternatives.
- **Evidence anchors:**
  - [abstract] Credits "meta-cognitive reasoning" with +9 points for preventing "repetitive loops without escape."
  - [section 3.2] Categorizes "Repetitive loops" (5 failures) under "Error Recovery," where the agent attempts the same failing action repeatedly.
  - [section 4.3] Describes the Cortex analyzing "cycle detection," "strategy evaluation," and "evidence accumulation" from history to trigger pivots.
- **Break condition:** If the cycle detection heuristic is too sensitive, it might interrupt valid, slow progress; if too lenient, it might miss subtle loops. The mechanism's efficacy depends on the quality of the history representation and the Cortex's ability to interpret it.

## Architecture Onboarding
- **Component map:**
  - **Graph Nodes:** Planner (decomposes goal → subgoals), Orchestrator (tracks subgoal status, routes to replan), Contextor (fetches device state), Cortex (central decision: JSON actions + subgoal signals), Executor (dispatches tool calls), Summarizer (compresses history).
  - **Utility Agents:** Outputter, Hopper, Video Analyzer (off-graph).
  - **Infrastructure:** ExecutorToolNode (sequential execution), Device Controller (ADB/fb-idb/WebDriverAgent abstraction), Convergence node (synchronization).
- **Critical path:** Input task → Planner (subgoals) → Orchestrator (sets current subgoal) → loop: Contextor (state) → Cortex (decide) → parallel: Orchestrator (check completion) + Executor (run actions) → Summarizer → Convergence → Orchestrator (route: continue/replan/finish).
- **Design tradeoffs:**
  - **Cost vs. Accuracy:** Frontier models needed only for Cortex (complex perception/reasoning); other agents can use budget models (Platform Default config saves 32% cost). Risk: over-degrading non-Cortex agents (e.g., Planner) drops SR to ~58%.
  - **Modularity vs. Overhead:** Six agents prevent context pollution but add graph routing latency. Benefit outweighs cost as tasks get longer.
  - **Deterministic verification vs. Speed:** Sequential text validation with state reads ensures reliability but adds per-action delay. Acceptable trade-off as failures are costlier.
- **Failure signatures:**
  - **Context pollution:** Symptoms: Reasoning drift, forgetting steps, contradictory decisions. Cause: Single-agent mixing planning/execution traces. Fix: Cognitive separation (multiple agents).
  - **Silent execution failure:** Symptom: Task diverges after a form-fill action; agent proceeds on false assumption. Cause: Unvalidated text input. Fix: Verified execution with post-validation.
  - **Repetitive loops:** Symptom: Same failing action (e.g., scroll) repeats without progress; timeout. Cause: No loop detection. Fix: Meta-cognitive reasoning in Cortex.
- **First 3 experiments:**
  1. **Ablation - Remove multi-agent decomposition:** Replace six agents with a single monolithic agent (using same frontier model). Expected: SR drops ~21 points (to ~79%) due to context pollution and drift.
  2. **Ablation - Disable verified execution:** Bypass the 6-step text validation; let Cortex directly command text entry. Expected: SR drops ~7-15 points, especially on tasks with multiple form fields.
  3. **Ablation - Disable meta-cognitive reasoning:** Remove Cortex's history analysis for cycle detection. Expected: SR drops ~9 points on tasks with ambiguous UI states requiring iterative exploration (e.g., "find setting X").

## Limitations
- Undisclosed agent prompts, temperature settings, and implementation details hinder exact replication.
- Performance claims rely on proprietary models; transferability to other model families is unclear.
- Evaluation uses emulators; real-world device variability and generalizability beyond AndroidWorld are unaddressed.

## Confidence
- 100% success rate on AndroidWorld: Medium
- Causal attribution of gains (+21, +7, +9 points): Medium
- 32% cost reduction via model allocation: High
- Generalization beyond AndroidWorld: Low
