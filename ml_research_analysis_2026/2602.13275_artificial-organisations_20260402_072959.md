# Artificial Organisations
## Quick Facts
- **arXiv ID**: 2602.13275
- **Source URL**: https://arxiv.org/abs/2602.13275
- **Reference count**: 18
- **Primary result**: Architectural constraints (compartmentalisation and adversarial review) generate reliable collective behavior from unreliable AI agents in document composition, with 52% fabrication detection, 79% quality improvement, and emergent honest refusal on impossible tasks.

## Executive Summary
The paper explores a core challenge in multi-agent AI safety: individual agents may be unreliable. It tests whether institutional design—specifically compartmentalisation and adversarial review—can produce reliable outcomes from unreliable components. The authors implement the Perseverance Composition Engine, a document composition system with three specialised agents: a Composer that drafts text, a Corroborator with source access that verifies factual substantiation, and a Critic without source access that evaluates argumentative quality. Information asymmetry is architecturally enforced.

In an evaluation across 474 tasks, the Corroborator detected fabrication in 52% of drafts. Iterative revision cycles (average 4.3 iterations) produced a 79% improvement in quality scores, at a cost of $0.29 per project. Remarkably, when faced with impossible tasks that would require fabrication, the system evolved to refuse honestly and suggest alternatives—a behaviour not explicitly instructed nor individually incentivised. These findings suggest that structural constraints can yield reliable collective performance without assuming full individual alignment.

## Method Summary
The system is orchestrated by a state machine (GraphState) that manages an iterative workflow. Agents have compartmentalised information access enforced by tool provisioning: the Composer drafts documents; the Corroborator, granted access to candidate source documents, issues a binary verdict (SUBSTANTIATED/FABRICATED); the Critic, denied source access, produces a numeric quality score (0–100) and feedback. Workflow steps: task specification → Composer generates draft → Corroborator verifies → Critic evaluates → if Critic score ≥ τ (85) and no fabrication, project terminates; otherwise, feedback is fed back to Composer for revision. Documents are stored with visibility levels (PUBLIC, CANDIDATE, DRAFT, CRITIC, FEEDBACK) to maintain asymmetry. The experiment runs 474 discrete composition projects, measuring fabrication detection, quality improvement, iterations to convergence, and token-based cost.

## Key Results
- The Corroborator flagged fabrication in 52% of drafts.
- Iterative revisions achieved a 79% quality improvement over an average of 4.3 iterations, costing $0.29 per project.
- On tasks assigned as impossible (requiring fabrication), the system converged to honest refusal with alternative proposals—an emergent behaviour not explicitly programmed.

## Why This Works (Mechanism)
Compartmentalisation enforces information asymmetry, ensuring no single agent can both fabricate and conceal it. The Corroborator's access to sources allows it to detect unsupported claims, while the Critic's lack of source access forces it to judge solely on argument structure, preventing reliance on hidden knowledge. Their adversarial feedback loops compel the Composer to revise substantively. The state machine's convergence threshold guarantees termination once quality suffices. The emergent refusal pattern likely emerges because the feedback dynamics penalise fabrication (Corroborator flags it) and reward constructive alternatives (Critic scores quality), leading the Composer to discover honest refusal as a stable strategy under impossible constraints.

## Foundational Learning
**Compartmentalisation**  
- *Why needed*: Prevents any agent from possessing complete context, thereby limiting undetected fabrication.  
- *Quick check*: Confirm Critic cannot retrieve CANDIDATE documents; attempt to prompt it to list candidate sources.

**Adversarial Review**  
- *Why needed*: Provides independent verification (Corroborator) and evaluation (Critic) to drive iterative refinement.  
- *Quick check*: Inspect Corroborator output for explicit citations of unsupported claims and Critic output for numeric scores with explanatory comments.

**State Machine Orchestration**  
- *Why needed*: Governs the iterative cycle and convergence condition, ensuring systematic progress.  
- *Quick check*: Simulate a project and verify that the workflow repeats until Critic score ≥85 or fabrication is resolved, with GraphState correctly propagating feedback.

**Cost-aware Caching**  
- *Why needed*: Reduces token usage and monetary expense by reusing retrieval results across iterations.  
- *Quick check*: Measure cache hit rate; the paper reports 83%—a significantly lower rate would increase costs.

## Architecture Onboarding
**Component map**  
Task Specification → Composer → Draft Document → Corroborator → Verdict (SUBSTANTIATED/FABRICATED) → Critic → Score (0–100) + Feedback → GraphState aggregates; if Score < τ (85) or Verdict=FABRICATED, loop back to Composer with feedback; else Output Final Document. Supporting components: DocumentStore (with visibility levels PUBLIC, CANDIDATE, DRAFT, CRITIC, FEEDBACK) and Compressor (manages context length).

**Critical path**  
1. Composer produces initial draft.  
2. Corroborator checks facts against sources.  
3. Critic evaluates argument quality.  
4. GraphState decides: if quality sufficient (Score≥85) and no fabrication, project ends; otherwise, Composer revises using feedback and returns to step 2.

**Design tradeoffs**  
- Compartmentalisation improves reliability but adds iteration latency and retrieval cost.  
- Adversarial review increases token usage; caching mitigates but introduces complexity.  
- Convergence threshold τ balances final quality against number of iterations (and thus cost).  
- Information asymmetry may hinder holistic reasoning, potentially requiring more cycles.

**Failure signatures**  
- Critic can access CANDIDATE documents → compartmentalisation breach.  
- Corroborator rarely flags fabrication on known challenging tasks → verification ineffective.  
- Critic scores plateau below τ → feedback not improving drafts.  
- Actual cost far exceeds $0.29 → caching or model pricing mismatch.  
- System never refuses impossible tasks → emergent honesty not realised.

**First experiments**  
1. **Compartmentalisation audit**: Prompt Critic to “summarise the candidate documents”; if it can, compartmentalisation fails.  
2. **Ablation of Corroborator feedback**: Replace Corroborator verdicts with random or always SUBSTANTIATED; quality improvement should disappear, confirming the loop’s importance.  
3. **Cost impact of caching**: Disable caching and run a batch; compare total token count and cost to the reported $0.29 to quantify caching’s contribution.

## Open Questions the Paper Calls Out
**1. Architectural comparison**  
- *Question*: Does architectural enforcement of compartmentalisation and adversarial review produce superior reliability outcomes compared to single-agent baselines or policy-based compartmentalisation?  
- *Basis*: Authors call for controlled architectural comparison through ablation studies.  
- *Why unresolved*: No comparative experiments conducted; evidence limited to a single architecture.  
- *Resolution*: Conduct experiments measuring fabrication detection, quality trajectories, and convergence efficiency across three conditions: current architecture, single-agent (performing all roles), and policy-based (compartmentalisation instructed but not enforced).

**2. Cross-model generalisation**  
- *Question*: Do the observed patterns of fabrication detection (52%) and iterative improvement (79% over 4.3 iterations) hold across diverse model families?  
- *Basis*: Authors explicitly prioritise cross-model replication.  
- *Why unresolved*: All results used Claude 4.5; unknown for other models.  
- *Resolution*: Replicate the 474 tasks using multiple model families (Claude, Gemini, GPT, Llama, Mistral) and compare key metrics.

**3. Domain transfer**  
- *Question*: Can institutional design principles (compartmentalisation, adversarial review) improve reliability in domains beyond document composition?  
- *Basis*: Authors propose domain variation studies.  
- *Why unresolved*: Current evidence confined to document composition; applicability elsewhere speculative.  
- *Resolution*: Implement analogous compartmentalised architectures in other task domains (e.g., code generation, planning, data analysis) and test for similar patterns of fabrication detection, iterative refinement, and honest refusal under impossible constraints.

## Limitations
- Exact agent prompts and state machine transition logic remain unreleased, preventing prompt-level replication and potentially masking subtle leaks.  
- The distribution and difficulty of the 474 tasks are not characterised, limiting assessment of generalisability across document types.  
- Implementation details of the Compressor and message history management are unknown, affecting cost benchmarking and iteration behaviour analysis.  
- The code repository is not publicly available, so no independent audit of compartmentalisation enforcement exists.  
- Potential dataset contamination or task shortcutting is not addressed; source documents used for fabrication detection are not described.

## Confidence
- Structural efficacy (compartmentalisation + adversarial review → reliable outcome): **Medium**  
- Cost efficiency ($0.29/project): **Low**  
- Emergent honest refusal on impossible tasks: **Low**
