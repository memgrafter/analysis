# AdaptOrch: Task-Adaptive Multi-Agent Orchestration in the Era of LLM Performance Convergence

## Quick Facts
- arXiv ID: 2602.16873
- Source URL: https://arxiv.org/abs/2602.16873
- Reference count: 3
- Primary result: AdaptOrch dynamically routes tasks to one of four canonical topologies, achieving 12–23% higher accuracy than static baselines with identical underlying models across coding, reasoning, and RAG benchmarks.

## Executive Summary
As large language models (LLMs) converge in capability, the choice of individual model becomes less critical than how multiple agents are orchestrated. AdaptOrch introduces a task‑adaptive framework that represents each problem as a dependency directed acyclic graph (DAG) and selects among four canonical orchestration topologies (parallel, sequential, hierarchical, hybrid) based on structural properties of the DAG, such as parallelism width and coupling density. The system employs a linear‑time routing algorithm and an adaptive synthesis phase with consistency scoring to combine agent outputs. Evaluated on coding (SWE‑bench), reasoning (GPQA), and RAG (HotpotQA) benchmarks, AdaptOrch improves accuracy by 12–23% over static single‑topology baselines while using the same set of five convergent LLMs. These results indicate that orchestration topology is now the primary performance lever in the era of LLM performance convergence.

## Method Summary
AdaptOrch processes tasks through a six‑stage pipeline. First, a decomposer LLM parses the task into subtasks with explicit dependencies and coupling labels (none, weak, strong, critical), producing a weighted DAG where vertices represent subtasks, edges encode dependencies, weights estimate token costs, and coupling values represent inter‑subtask dependencies. Second, structural properties are computed: parallelism width ω (maximum number of vertices in any layer of a topological sort), critical path length δ (longest path sum of weights), and average coupling γ. Third, a linear‑time router maps the DAG to one of four topologies using thresholded rules (θ_ω, θ_γ, θ_δ): parallel (τP) for high parallelism and low coupling; sequential (τS) for low parallelism; hierarchical (τH) for high coupling; hybrid (τX) for intermediate cases. Fourth, execution follows the chosen topology: τP runs all subtasks concurrently; τS runs them sequentially with context propagation; τH uses a lead agent to assign and synthesize; τX executes layers in parallel and sequentially between layers. Fifth, an adaptive synthesis phase computes a consistency score (CS) from pairwise embedding similarities; high CS triggers a merger LLM, low CS triggers an arbiter LLM. Sixth, if the arbiter output remains inconsistent, γ is increased and the router re‑evaluates (up to five iterations). All underlying LLMs are drawn from a pool of five ϵ‑convergent models, and accuracy is the primary metric.

## Key Results
- AdaptOrch achieves 12–23% higher accuracy than static single‑topology baselines across SWE‑bench, GPQA, and HotpotQA using identical underlying models.
- Orchestration topology selection dominates model selection when LLMs are ϵ‑convergent, with variance from topology exceeding that from model choice by a factor of Ω(1/ϵ²).
- The adaptive synthesis phase alone contributes a 5.5 percentage point improvement, and the linear‑time router generalizes across domains with varying topology distributions.

## Why This Works (Mechanism)
### Mechanism 1: Performance-Driven Topology Selection
- **Claim:** When LLMs are ϵ‑convergent, the variance in system performance from orchestration topology exceeds that from model selection by a factor of Ω(1/ϵ²).
- **Mechanism:** The *Performance Convergence Scaling Law* (Prop. 1) mathematically formalizes that for tasks with decomposable DAGs (ω(Gₜ) > 1), the quality gap between parallel and sequential execution scales with (ω−1)² and inversely with coupling (1−γ)². This gap dominates model-choice variance (bounded by ϵ²) as ϵ→0.
- **Core assumption:** Task decomposition yields valid DAGs with structural properties (ω, γ) predictive of topology performance; Lipschitz aggregation ensures per‑subtask errors compound linearly.
- **Evidence anchors:**
  - [abstract] "orchestration topology... now dominates system-level performance over individual model capability."
  - [section 3.4] Formal variance ratio Varτ/VarM ≥ (ω−1)²(1−γ)²/(4ϵ²k).
  - [corpus] Neighbors (e.g., G-Designer, S-DAG) confirm multi-agent topology impacts performance, but do not directly validate the scaling law.
- **Break condition:** Fails if tasks are atomic (|V|=1) or fully coupled (γ≈1), where 1−γ≈0 eliminates topology variance.

### Mechanism 2: Linear-Time DAG-to-Topology Routing
- **Claim:** Task dependency DAGs can be mapped to one of four canonical topologies (parallel, sequential, hierarchical, hybrid) in O(|V|+|E|) time using structural thresholds.
- **Mechanism:** *Algorithm 1* computes parallelism ratio r = ω/|V|, coupling γ, and subtask count |V|. Thresholds (θω, θγ, θδ) classify DAGs: e.g., if r > θω and γ ≤ θγ → τP (parallel). This exploits Dilworth’s theorem (ω chains needed for parallelism) and coupling penalty.
- **Core assumption:** Thresholds calibrated on dev sets generalize to unseen tasks; approximate ω (layer-width) suffices for routing.
- **Evidence anchors:**
  - [section 4.3] "routing decision runs in O(|V|+|E|)" and threshold definitions.
  - [section 5.3] Routing distribution varies by domain (e.g., SWE-bench → 62% hybrid), confirming adaptation.
  - [corpus] Gradientsys and Verified Multi-Agent Orchestration use DAG decomposition but lack formal routing.
- **Break condition:** Thresholds become brittle if DAG features have multi‑modal distributions beyond four clusters (Fig. 12).

### Mechanism 3: Adaptive Synthesis with Consistency Scoring
- **Claim:** Parallel agent outputs can be merged reliably using a heuristic consistency score (CS) and re‑routing on failure, with provable termination.
- **Mechanism:** *Algorithm 2* computes CS via pairwise embedding similarity. If CS < θCS, an arbiter agent resolves conflicts; persistent failure triggers re-routing with increased coupling estimate γ′ = γ+0.2, eventually forcing hierarchical τH (single-arbiter) within ≤5 iterations.
- **Core assumption:** CS approximates logical coherence; embedding similarity correlates with contradiction likelihood.
- **Evidence anchors:**
  - [section 4.5] "CS captures semantic similarity rather than logical coherence" and termination bound.
  - [section 5.2] Synthesis provides largest ablation gain (−5.5 pp).
  - [corpus] VMAO uses plan‑execute‑verify‑replan, but AdaptOrch’s re‑routing is topology‑specific.
- **Break condition:** High subtask diversity yields low CS despite non‑contradictory outputs, causing unnecessary re‑routing.

## Foundational Learning
- **Concept: ϵ‑Convergence of LLMs**
  - *Why needed:* Establishes the regime where model selection variance becomes negligible vs. topology variance (Prop. 1).
  - *Quick check:* If all models score within 0.03 on MMLU, does Varτ/VarM exceed 20 for a task with ω=3, γ=0.4, k=5?
- **Concept: DAG Structural Properties (ω, δ, γ)**
  - *Why needed:* Direct inputs to the routing algorithm; ω (antichain width) measures parallelizability, γ (coupling density) penalizes parallel gains.
  - *Quick check:* Given a DAG with 6 nodes, max layer size=4, and average edge coupling=0.6, would it route to τP or τH?
- **Concept: Canonical Topologies (τP, τS, τH, τX)**
  - *Why needed:* Defines the solution space; each has distinct execution/synthesis patterns affecting latency and context preservation.
  - *Quick check:* When would τX (hybrid) be preferred over pure τP or τS?

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can AdaptOrch's threshold-based routing be replaced with a learned classifier for better topology selection?
- **Basis in paper:** Section 7.1 explicitly lists "Learned routing: Replace threshold-based routing with a lightweight classifier trained on (DAG features, optimal topology) pairs" as future work.
- **Why unresolved:** The current routing uses fixed thresholds statically calibrated on a dev split, which may not generalize to diverse or evolving task structures across domains.
- **What evidence would resolve it:** Construct a dataset of task DAGs with oracle-optimal topologies (via exhaustive evaluation), train a classifier on structural features, and compare routing accuracy and downstream task performance against the threshold-based method on held‑out benchmarks.

### Open Question 2
- **Question:** Does dynamic re‑orchestration during execution improve AdaptOrch's accuracy by adapting to revealed coupling?
- **Basis in paper:** Section 7.1 proposes "Dynamic re‑orchestration: Allow topology changes mid‑execution when partial results reveal unexpected coupling" as future work.
- **Why unresolved:** AdaptOrch assumes static DAGs and coupling estimates; real‑time execution might expose inaccurate coupling, requiring topology shifts to avoid synthesis failures or suboptimal merging.
- **What evidence would resolve it:** Implement a mid‑execution re‑routing mechanism that re‑estimates coupling based on partial outputs, then test on tasks where initial coupling is misestimated, measuring accuracy improvement and re‑routing frequency.

### Open Question 3
- **Question:** How can cost constraints be incorporated into topology routing for budget‑aware multi‑agent systems?
- **Basis in paper:** Section 7.1 includes "Cost‑aware routing: Extend the routing algorithm to jointly optimize accuracy and API cost under budget constraints" as future work.
- **Why unresolved:** Current routing optimizes accuracy only, but parallel topologies incur higher API costs, which may violate budget limits in practical deployments.
- **What evidence would resolve it:** Define a cost‑aware objective function balancing accuracy and token/API expenses, integrate it into Algorithm 1, and evaluate accuracy‑cost trade‑offs across benchmarks under varying budget constraints to identify Pareto‑optimal configurations.

## Limitations
- DAG decomposition quality is critical; errors or missing dependencies propagate to routing and execution.
- Thresholds (θ_ω, θ_γ, θ_δ) and the consistency score (CS) heuristic are brittle and sensitive to embedding model choice and tuning.
- The Performance Convergence Scaling Law (Prop. 1) relies on strong assumptions (ϵ‑convergence, Lipschitz aggregation) and has limited empirical validation.
