# See and Remember: A Multimodal Agent for Web Traversal

## Quick Facts
- **arXiv ID**: 2603.02626
- **Source URL**: https://arxiv.org/abs/2603.02626

- **Primary result**: V-GEMS achieves a 28.7% performance gain over the WebWalker baseline, increasing success rate from 0.49 to 0.65 on the EverWebQA benchmark.

## Executive Summary
LLM-based web navigation agents frequently struggle with spatial disorientation, navigation loops, and arithmetic hallucinations. This paper presents V-GEMS, a multimodal agent that integrates visual grounding, an explicit memory stack, a symbolic counter, and an adaptive US Calculator. Visual grounding via a vision-language model resolves element ambiguities; the memory stack enables stateful backtracking to break loops; the symbolic counter guarantees precise arithmetic; and the US Calculator selectively invokes the VLM only when textual DOMs are insufficient. Evaluated on the newly introduced EverWebQA benchmark, V-GEMS outperforms the WebWalker baseline by 28.7%, boosting success from 0.49 to 0.65. Ablation studies confirm the contributions of the memory stack and VLM.

While the results are promising, the study has limitations. EverWebQA is a fresh benchmark not yet vetted by the community, and the evaluation compares only against WebWalker, omitting other recent agents. Moreover, the adaptive trigger heuristic lacks quantitative analysis, and no human evaluation has been conducted. Thus, the broader applicability and real-world utility of V-GEMS remain to be fully established.

## Method Summary
Based on the provided key outcome (as reproduction notes were absent), V-GEMS processes each web page by extracting its textual DOM and capturing a screenshot. An adaptive US Calculator first assesses whether the DOM alone suffices for action selection; if not, a vision-language model processes the screenshot to provide visual grounding, clarifying element locations. The agent’s controller (an LLM) then reasons over this information to choose the next action (e.g., click, type). A dedicated symbolic counter handles any required arithmetic, preventing number-related hallucinations. The memory stack records visited page states; if a state repeats, the agent backtracks to avoid loops. This architecture aims to combine the flexibility of LLMs with the reliability of symbolic components and selective perception.

## Key Results
- V-GEMS yields a 28.7% improvement over WebWalker on EverWebQA, raising success rate from 0.49 to 0.65.
- Ablation studies demonstrate that the memory stack eliminates navigation loops and the VLM resolves visual ambiguities in complex domains.
- The symbolic counter effectively mitigates arithmetic hallucinations.

## Why This Works (Mechanism)
V-GEMS addresses the core weaknesses of LLM-based agents through targeted mechanisms. Visual grounding resolves the ambiguity inherent in textual DOMs, ensuring clicks target the correct elements even when descriptors overlap or are poorly labeled. The memory stack maintains an explicit history of visited states, enabling the agent to recognize and break out of navigation loops through systematic backtracking. Arithmetic operations are delegated to a deterministic symbolic counter, avoiding the numeric errors common in LLM outputs. Finally, the adaptive US Calculator optimizes computational efficiency by invoking the expensive VLM only when the DOM is insufficient, thus retaining speed without sacrificing accuracy.

## Architecture Onboarding
**Component Map**  
The agent comprises:  
- Textual DOM parser and screenshot capture  
- US Calculator (heuristic trigger)  
- Vision-Language Model (VLM)  
- LLM-based Controller  
- Memory Stack (state history)  
- Symbolic Counter (arithmetic)  

Data flow: DOM + screenshot -> US Calculator -> [if needed] VLM -> Controller (with DOM±VLM output) -> Action -> Memory Stack update. Symbolic Counter is invoked whenever arithmetic is required.

**Critical Path**  
1. Load page; extract DOM and screenshot.  
2. US Calculator determines if VLM is needed; if yes, invoke VLM to obtain grounded elements.  
3. Controller decides next action using disambiguated elements.  
4. Execute action; push current state onto Memory Stack.  
5. Check for repeated states; if detected, backtrack.  
6. If task involves arithmetic, route the computation to the Symbolic Counter.

**Design Tradeoffs**  
- *VLM latency vs. accuracy*: More detailed VLM prompts improve grounding but increase response time.  
- *Memory stack depth*: Deeper stacks prevent more loops but consume more memory and may delay backtracking.  
- *Symbolic counter coverage*: Limited to predefined arithmetic forms; out-of-scope calculations revert to LLM, risking errors.  
- *US Calculator heuristic simplicity*: Simple rules are fast but may incorrectly judge when VLM is necessary.

**Failure Signatures**  
- Navigation loop: identical or near-identical states appear repeatedly in memory.  
- Visual misidentification: VLM returns incorrect element coordinates or labels, causing failed clicks.  
- Arithmetic error: wrong numerical result when the LLM is allowed to compute instead of the Symbolic Counter.  
- Excessive VLM usage: US Calculator triggers VLM on most pages, leading to high latency.

**First Experiments**  
1. Run V-GEMS vs. WebWalker on EverWebQA to confirm the reported 28.7% gain.  
2. Ablate the memory stack (disable backtracking) to quantify its impact on loop avoidance and success rate.  
3. Ablate visual grounding (disable VLM) to measure performance on tasks requiring visual disambiguation.

## Limitations
- EverWebQA is a newly introduced benchmark; its difficulty spectrum and real-world relevance are not yet validated by independent studies.
- Evaluation is confined to a single baseline (WebWalker); comparisons with other state-of-the-art agents (e.g., GPT‑4V‑based) are missing.
- The adaptive US Calculator relies on a heuristic trigger whose precision, recall, and computational overhead are not quantified.
