# $τ$-Voice: Benchmarking Full-Duplex Voice Agents on Real-World Domains

## Quick Facts
- **arXiv ID:** 2603.13686
- **Source URL:** https://arxiv.org/abs/2603.13686
- **Reference count:** 40
- **Primary result:** State-of-the-art full-duplex voice agents achieve 31–51% pass@1 under clean audio and 26–38% under realistic conditions, trailing text-only reasoning by 34–54 percentage points.

## Executive Summary
τ-Voice introduces the first benchmark to holistically evaluate full-duplex voice agents on complex, multi-step customer service tasks under realistic acoustic and conversational conditions. It extends the text-based τ²-bench with a tick-based simulation orchestrator and an LLM-driven voice user simulator that introduces controllable accents, background noise, and natural turn-taking behaviors (interruptions, backchannels). Evaluation across 278 tasks reveals that existing voice-native APIs (OpenAI Realtime, Gemini Live, xAI Grok) retain only 30–45% of the capability of a comparable text model (GPT-5), with acoustic factors like accents causing severe degradation. The benchmark demonstrates that current systems struggle with real-time reasoning and interactive decision-making, not just speech recognition.

## Method Summary
The τ-Voice framework builds upon τ²-bench’s task definitions and database-backed verification. A central tick-based orchestrator (Δt=200ms) decouples simulation time from wall-clock, coordinating bidirectional audio streams. For each tick, it delivers mixed user/agent audio chunks to the agent API and distributes corresponding transcripts. The voice user simulator uses an LLM (GPT-4.1) to generate dialogue acts, which are converted to speech via TTS (ElevenLabs) and degraded with acoustic effects (noise, frame drops) and persona-specific accents. The simulator’s turn-taking module decides when to interrupt or produce backchannels. Agent actions (tool calls) are executed against a domain database, and task completion is verified via deterministic assertions and LLM-based scoring.

## Key Results
- **Large voice-text gap:** SOTA voice agents score 31–51% pass@1 (clean) and 26–38% (realistic) vs. 85% for a text model on identical tasks.
- **Accents are critically challenging:** The most damaging acoustic factor, causing up to a 38% relative performance drop for some providers.
- **Failures are primarily agent-caused:** Qualitative analysis attributes 79–90% of failures to agent behavior (reasoning, tool use, timing), not user simulator actions.

## Why This Works (Mechanism)
τ-Voice isolates the challenges of full-duplex voice interaction by decoupling simulation time (ticks) from real-world latency, enabling controlled, repeatable experiments. The orchestrator’s strict 200ms grid forces agents to make incremental decisions under tight time pressure, mirroring live conversation. The voice user simulator introduces acoustic and interactional complexity—accents, noise, interruptions—that text-based evaluation inherently ignores. By leveraging τ²-bench’s verifiable database states, the benchmark provides an objective measure of task completion despite noisy, real-time inputs. This design surfaces the core bottleneck: maintaining reasoning coherence and tool-call accuracy while managing the continuous, overlapping speech streams of natural dialogue.

## Foundational Learning
- **Tick-based discrete-event simulation:** A fixedΔt loop (200ms) orchestrates audio/transcript delivery, ensuring deterministic simulation despite variable API latency. *Why needed:* Models real-time conversational rhythm; enables fair timing comparisons. *Quick check:* Sum of audio chunks per tick equals exactly Δt; no overlap or gap in playback timeline.
- **Voice user simulator with persona control:** LLM prompt + TTS + acoustic effects generate user speech with specific accents, noise profiles, and turn-taking logic. *Why needed:* Creates diverse, reproducible test conditions without human labor. *Quick check:* Spectrograms show expected spectral shifts for accents (e.g., formant variation for Bengali); noise SNR matches Table 13.
- **Full-duplex API integration:** Agent systems stream and receive audio continuously, with VAD-driven turn detection and transcript linearization for overlapping speech. *Why needed:* Replicates commercial voice agent architectures (e.g., OpenAI Realtime). *Quick check:* Agent receives linear transcript (Table 11 format) where contained speech segments are inserted at correct timestamps.
- **Database-verified task completion:** Final database state is compared against a ground-truth JSON via deterministic checks and LLM assertions. *Why needed:* Objective metric for multi-step task success beyond dialogue coherence. *Quick check:* All modified database fields (e.g., `order status`, `customer address`) match expected final state for a passing run.
- **Turn-taking metric suite:** Responsiveness (RR, RY), latency (LR, LY), interrupt rate (IA), selectivity (SBC, SVT, SND). *Why needed:* Quantifies conversational naturalness beyond task success. *Quick check:* High RR (e.g., OpenAI 100%) correlates with low SVT; check for inverse relationship in Table 8.
- **Provider-agnostic adapter layer:** Normalizes audio timestamps, VAD events, and partial transcripts across OpenAI, Gemini, xAI APIs. *Why needed:* Ensures fair comparison across incompatible streaming interfaces. *Quick check:* Agent input buffer always contains exactly 200ms of mixed audio per tick, regardless of provider packetization.

## Architecture Onboarding
**Component Map:**  
τ²-bench tasks/policies → Orchestrator (tick loop, audio mixing) → Agent API (streaming audio in, tool calls out) ← Voice User Simulator (LLM → TTS → effects → acoustic persona)  
Database ← Tool Execution ← Agent  
Assertion Engine ← Final Database State → pass@1

**Critical Path:**  
1. Load task JSON and initial database.  
2. For each 200ms tick: orchestrator plays previous tick’s mixed audio to agent, collects new agent audio chunk, applies VAD.  
3. Simulator consumes tick to decide user action (speak/interrupt/silence), generates audio, degrades it, mixes with agent audio for next tick.  
4. When user turn ends (VAD silence), orchestrator finalizes user transcript and delivers to agent.  
5. Agent emits tool calls; orchestrator executes against DB.  
6. Loop until task policy signals completion or timeout; run assertions to determine pass/fail.

**Design Tradeoffs:**  
- **Tick duration (200ms):** Short enough for natural turn-taking but may penalize agents needing >200ms for internal reasoning.  
- **Linearization of overlapping speech:** Simplifies LLM input but loses acoustic overlap cues; may overestimate transcript quality.  
- **TTS-based accents vs. human speech:** Controllable and reproducible but lacks full variability of real disfluencies and channel effects.

**Failure Signatures:**  
- **Tick desync:** Audio buffer lengths ≠200ms; "no-response" errors when user turn ends with agent buffer non-empty.  
- **Accent mismatch:** Systematic drops on specific personas (e.g., Bengali, Sichuan Mandarin) without corresponding noise degradation.  
- **Tool call missing:** Final DB state lacks expected modifications (e.g., `modify_pending_order_items` not called).  
- **Interruption overuse:** High IA + low SBC indicates agent speaks over user without backchannels.  
- **Latency spikes:** Wall-clock time per tick >200ms consistently; correlates with reduced pass@1.

**First Three Experiments:**  
1. **Validate orchestrator timing:** Run a 10-minute simulation with a dummy agent that echoes audio. Log buffer occupancy per tick; verify cumulative playback equals wall-clock time with zero drift.  
2. **Persona intelligibility check:** Human raters (N=5) transcribe 100 simulator utterances per accent persona (no noise). Compute WER; should be <15% for "clean" persona, >30% for challenging accents per paper’s expectation.  
3. **Provider adapter equivalence:** Execute identical task on OpenAI and Gemini with fixed random seed. Compare transcript strings at each tick and interruption patterns; expect systematic differences in VAD sensitivity or partial output format.

## Open Questions the Paper Calls Out
- **Latency vs. reasoning:** How does voice agent performance scale with tool call latency and multi-step reasoning depth under full-duplex constraints?
- **Accent generalizability:** Do the accent vulnerabilities observed with TTS personas generalize to real human speech recordings and diverse speaker demographics?
- **Turn-taking tradeoff root cause:** What is the root cause of the fundamental trade-off between responsiveness (100% for OpenAI) and selectivity (6%)? Can a single agent master both?
- **Audio-native vs. thinking time:** To what extent does the voice-text gap stem from the audio-native architecture itself versus the lack of "thinking time" (silent reasoning) available to voice agents?
- **Simulator patience bias:** How robust are the reported failure attributions (79-90% agent-caused) to variations in user simulator patience and tool call latency?

## Limitations
- **Code release incomplete:** Core components (orchestrator, transcript linearization, provider adapters) not publicly released; reproduction relies on inferred design.
- **Simulator ≠ human:** TTS accents and perfect simulator memory/patience may not capture real user variability; 5-second delay test suggests some robustness but not exhaustive.
- **Unreleased evaluation details:** LLM assertion prompts, model version, and voice metric aggregation formulas are undisclosed, affecting claim confidence.
