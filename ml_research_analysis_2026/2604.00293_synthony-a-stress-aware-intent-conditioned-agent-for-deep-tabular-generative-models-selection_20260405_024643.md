# SYNTHONY: A Stress-Aware, Intent-Conditioned Agent for Deep Tabular Generative Models Selection

## Quick Facts
- **arXiv ID:** 2604.00293
- **Source URL:** https://arxiv.org/abs/2604.00293
- **Reference Count:** 40
- **Primary Result:** A zero-shot framework that matches dataset stress profiles to synthesizer capabilities, achieving a Top-1 accuracy of 44.4% and a Spearman rank correlation of 0.573 on held-out test pairs, substantially outperforming static heuristics and zero-shot LLM selectors.

## Executive Summary
Selecting the optimal deep generative model for tabular data synthesis is challenging because model performance is highly non-uniform across datasets with different inherent stressors (e.g., skew, cardinality) and user intents (e.g., privacy, fidelity). SYNTHONY addresses this by first computing a "stress profile" of a dataset across four interpretable dimensions that quantify difficulty. It then matches this profile against a pre-calibrated capability registry that encodes the known strengths and weaknesses of various synthesizer families. This match score is reweighted by intent-specific scale factors, optimized via Bayesian optimization to align with empirical rankings. Evaluated on a benchmark of 7 datasets and 10 synthesizers, SYNTHONY’s rule-based variant significantly outperforms simpler heuristics and a zero-shot LLM selector, approaching the performance of an oracle-informed kNN baseline while offering better interpretability and zero-shot applicability to new models.

## Method Summary
The SYNTHONY pipeline begins with a **Stress Profiling** stage that analyzes a tabular dataset to compute its requirement vector across four dimensions: long-tail skew, cardinality complexity, Zipfian imbalance, and small sample size. Raw statistics are quantized into discrete requirement levels. Next, a **Capability Registry** contains hand-crafted integer scores (0-4) for each synthesizer family across six robustness dimensions. A **Scoring Function** compares the dataset's requirements against each model's capabilities, producing a base match score. This score is multiplied by **Intent-Specific Scale Factors**, parameters optimized using Bayesian Tree-structured Parzen Estimator (TPE) on a training split of dataset-intent pairs to maximize Spearman correlation with an oracle performance ranking. The final ranked list is produced, with tie-breaking rules and hard-problem routing for extreme cases. The system is designed for zero-shot application, requiring no runtime model training or sampling.

## Key Results
- On a held-out test set of dataset-intent pairs, the SYNTHONY SF-only variant (optimized scale factors only) achieves a Spearman rank correlation of 0.573 and Top-1 selection accuracy of 44.4%.
- This substantially outperforms a static heuristic baseline (Spearman 0.422) and a zero-shot LLM selector (Spearman -0.087).
- An ablation study confirms that removing the stress profiling capability matching reduces performance to Spearman 0.430, highlighting its critical role.
- The approach nearly matches an oracle-informed kNN baseline (Spearman 0.578) while being interpretable and applicable to new synthesizers without retraining.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Stress profiling translates raw dataset statistics into predictive meta-features that expose systematic failure modes of generative models.
**Mechanism:** Four stress dimensions are measured: (i) long‑tail skew via maximum absolute Fisher–Pearson skewness, (ii) cardinality complexity via maximum unique value count, (iii) Zipfian concentration via top‑20% frequency ratio in categorical columns, and (iv) small‑sample regime via row count thresholding. These raw values are quantized into discrete requirement levels that map directly to known architectural weaknesses.
**Core assumption:** Dataset difficulty along these axes predicts synthesizer performance consistently across model families.
**Evidence anchors:** Paper abstract and Section 3.2 define the stress profile ϕ(D) and requirement vector r. Ablation in Section A.7 shows removing stress profiling drastically hurts performance.
**Break condition:** If a dataset exhibits failure modes outside these four dimensions (e.g., temporal dynamics, complex feature interactions), the stress profile may misrepresent its true difficulty.

### Mechanism 2
**Claim:** A hand‑crafted capability registry encodes each synthesizer family’s robustness to each stress dimension, enabling zero‑shot matching without runtime evaluation.
**Mechanism:** Each model g receives integer scores c_{g,j} ∈ {0,…,4} for six capability dimensions. The match function m_j assigns 1.0 if c_{g,j} ≥ r_j, 0.7 if one level below, 0.4 if two levels below, and 0.0 otherwise. The base score sums contributions across required dimensions.
**Core assumption:** Model families have stable, interpretable strengths and weaknesses; hand‑crafted scores capture these sufficiently for accurate selection.
**Evidence anchors:** Section 3.3 defines the capability registry C_g. Section A.5 ablation shows removing capability matching drops Spearman from 0.573 to 0.430.
**Break condition:** If a new synthesizer family does not fit the existing capability dimensions, or if the hand‑crafted scores are inaccurate, the matching will be flawed.

### Mechanism 3
**Claim:** Intent‑conditioned scale factors reweight capability contributions according to user objectives, calibrated via Bayesian optimization to align with empirical rankings.
**Mechanism:** For each intent i, a vector α_i ∈ [0,10]^6 multiplies the base match scores. These parameters are optimized (together with optional capability scores) using TPE to maximize average Spearman correlation on a training split.
**Core assumption:** The relative importance of capabilities remains stable for a given intent across datasets; thus a fixed α_i per intent generalizes.
**Evidence anchors:** Section 3.4 describes the Bayesian optimization. Table 1 shows SF-only (18 parameters) outperforms joint optimization (78 parameters), suggesting overfitting risk.
**Break condition:** With few training pairs (12), scale factors may overfit; a single α_i may be insufficient if intents are not well-separated.

## Architecture Onboarding
**Component map:** Data Infrastructure (StochasticDataAnalyzer, ColumnAnalyzer) → computes stress profile → Model Core (CapabilityRegistry in `config/modelcapabilities.json`, BenchmarkRunner) → Orchestration (ModelRecommendationEngine, HybridScorer) → final ranking. Persistence via SQLite. Exposed via REST API (FastAPI), MCP server (JSON-RPC), and CLI.

**Critical path:** A typical `POST /analyze-and-recommend` workflow: (1) Upload CSV/Parquet → (2) Data Infrastructure computes stress profile ϕ(D) → (3) Orchestration loads capability registry → (4) Apply hard filters (exclusions, CPU/DP constraints) → (5) Detect hard problems (simultaneous skew+cardinality+Zipf) → (6) Derive requirement vector r from ϕ(D) → (7) Score each model: S(g)=∑_j α_{i,j}·m_j(c_{g,j}, r_j) (+ empirical quality bonus) → (8) Rank models descending → (9) Tie‑breaking rules → (10) Return ranked list with confidence and reasoning.

**Design tradeoffs:**
- Hand‑crafted capability scores vs. learned: Hand‑crafted preserves interpretability and avoids overfitting on small benchmark; learned could capture nuances but require more data.
- Additive scoring assumes independence among capability dimensions; simplifies optimization but may ignore interactions (e.g., high cardinality and severe skew compounding).
- Hard‑problem routing (to GReaT) provides a fast path for extreme cases but may be brittle if stress thresholds are not well‑calibrated.
- Scale factor calibration via Bayesian optimization on only 12 training pairs is sample‑inefficient; joint optimization (78 parameters) overfits, while SF‑only (18 parameters) generalizes better.
- Zero‑shot LLM path included for flexibility but performs poorly (Spearman −0.087); thus rule‑based remains the reliable default.

**Failure signatures:**
- Empty model pool after hard filters → dataset too extreme or constraints too tight; returns an error.
- Very low confidence score (<0.3) → poor match between stress profile and capability registry; possibly missing capability dimension.
- Discrepancy between training and test performance of optimized scale factors → overfitting; consider reducing tuned parameters or collecting more training data.
- LLM recommendation contradicts rule‑based ranking with negative correlation → ignore LLM path; use rule‑based or hybrid with caution.

**First 3 experiments:**
1. **Validate stress profiling:** Run `synthony-profile dataset/input_data/Bean.csv --verbose` and check reported stress levels align with manual inspection. Ensure detectors function correctly.
2. **Test rule‑based selection:** Run `synthony-recommender -i dataset/input_data/Bean.csv --method rulebased` and verify top‑ranked model aligns with stress profile (e.g., high cardinality → TabDDPM). Optionally compute oracle ranking via benchmark harness.
3. **Assess scale factor calibration:** Execute `python scripts/optimize_scaling.py` to run Bayesian optimization on the training split. Compare Spearman on training vs. test sets (Table 1) to evaluate improvement and overfitting.

## Open Questions the Paper Calls Out
### Open Question 1
**Question:** Can capability scores be learned from data instead of hand‑crafted, and does this improve selection?
**Basis in paper:** Explicitly identified as a key direction for future work in Section 5, citing the hand‑crafted registry as a bottleneck.
**Why unresolved:** Hand‑crafted scores may not generalize to new synthesizers/datasets and rely on expert bias.
**What evidence would resolve it:** Train a meta‑learner on a large benchmark (≥20 datasets, ≥15 synthesizers) to predict capabilities; compare selection performance (Spearman) to hand‑crafted baseline.

### Open Question 2
**Question:** Do synergistic stressors (e.g., skew+cardinality+Zipf) require non‑additive scoring to avoid misranking?
**Basis in paper:** The paper notes the additive independence assumption may miss interaction effects and gives an example of compounding challenges in Section 3.3.
**Why unresolved:** Current scoring treats dimensions independently, possibly mis‑scoring for datasets with multiple stressors.
**What evidence would resolve it:** Identify multi‑stressor datasets in an expanded benchmark; test scoring functions with interaction terms or learned non‑linear models; measure accuracy improvements.

### Open Question 3
**Question:** What additional meta‑features can capture privacy risk, and can they enable accurate intent‑conditioned selection for privacy?
**Basis in paper:** Explicitly states the privacy intent is the hardest to model because no single architectural property reliably predicts privacy performance (Section 4.5).
**Why unresolved:** Stress profiles lack privacy‑specific signals; current privacy capability is coarse.
**What evidence would resolve it:** Correlate dataset characteristics (e.g., feature uniqueness, k‑anonymity) with empirical privacy metrics; augment SYNTHONY’s profiling and evaluate privacy selection accuracy.

### Open Question 4
**Question:** Will SYNTHONY maintain accuracy on a larger, more diverse benchmark, and will tree‑based dominance decrease?
**Basis in paper:** Explicitly notes that CART’s strong showing partly reflects the composition of the 7‑dataset benchmark and calls for expansion to ≥20 datasets and additional model families to reduce single‑model dominance (Section 5).
**Why unresolved:** The benchmark may not represent full diversity of tabular data; selection model may overfit to prevalent patterns.
**What evidence would resolve it:** Build a benchmark with ≥20 datasets covering wide ranges of size, cardinality, skew, and include diverse synthesizers; re‑evaluate SYNTHONY’s performance and model family distribution.

## Limitations
- **Small benchmark:** Evaluation uses only 7 datasets and 10 synthesizers, limiting generalizability to broader tabular data distributions and modern synthesizer architectures.
- **Limited stress dimensions:** Stress profiling covers only four axes; other potential difficulties (temporal dynamics, complex feature interactions, data modifications) are not captured.
- **Hand‑crafted capability scores:** The registry relies on expert knowledge and may be subjective, incomplete, or inaccurate for new or unconventional synthesizer families.
- **Overfitting risk in intent scaling:** Scale factor optimization uses only 12 training pairs; joint tuning of 78 parameters hurt test performance, indicating high variance and potential overfitting.

## Confidence
- **Stress profiling effectiveness:** Medium. Strong ablation signal supports its predictive role, but limited to four dimensions and a small benchmark.
- **Capability registry utility:** Medium. Ablation confirms benefit, yet hand‑crafted nature may not generalize to unseen models or datasets.
- **Intent‑aware scaling (SF‑only):** Low. SF‑only works on current test set, but scale factors likely overfit the small training set; generalizing to new intents is uncertain.
- **Overall selection approach:** Medium. Results are promising but constrained by benchmark size and hand‑crafted components; scalability to larger, more diverse settings remains an open question.

## Next Checks
