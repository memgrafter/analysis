# Using LLMs for Knowledge Component-level Correctness Labeling in Open-ended Coding Problems

## Quick Facts
- arXiv ID: 2602.17542
- Source URL: https://arxiv.org/abs/2602.17542
- Reference count: 25
- Primary result: LLM-based KC labeling significantly outperforms problem-level correctness on Power Law (RMSE 0.069 vs 0.083, r² 0.383 vs 0.320) and AFM (AUC 0.631 vs 0.538), with high human agreement (Cohen's Kappa 0.74).

## Executive Summary
The paper addresses the lack of fine-grained knowledge component (KC) correctness labels in open-ended coding problems. It proposes an LLM-based framework that uses chain-of-thought prompting to evaluate each KC's correctness in student code and employs a temporal context-aware mapping to align KCs with individual submissions. Evaluated on the CodeWorkout dataset, the method yields learning curves that better fit the Power Law of Practice and improves predictive performance in the Additive Factors Model compared to using problem-level labels. Human evaluation confirms strong agreement between LLM and expert labels, demonstrating reliability.

## Method Summary
The method operates in an inference-only pipeline. For each student's first attempt, it selects relevant KCs via temporal context-aware mapping: the student's last attempt is embedded with CodeBERT and compared to embeddings of correct reference solutions; KCs from the closest reference are chosen. Then, an LLM (GPT-4o or Qwen3) is prompted with the problem statement, the code, and the selected KCs, using chain-of-thought instructions to reason about KC presence and correctness. The LLM's response is parsed into binary labels per KC, producing a per-submission, per-KC correctness matrix for downstream analysis (e.g., learning curves, AFM).

## Key Results
- Power Law fit improves: RMSE decreases (0.069 vs. 0.083) and r² increases (0.383 vs. 0.320) versus problem-level baseline.
- Additive Factors Model AUC increases (0.631 vs. 0.538).
- Human evaluation shows substantial agreement between LLM and expert labels (Cohen's Kappa 0.74).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Chain-of-thought (CoT) prompting improves reliability of LLM-generated KC correctness labels by requiring explicit intermediate reasoning about KC presence and application.
- **Mechanism:** The LLM is instructed to first determine if a KC is used in the student code and then judge its correctness, rather than outputting a binary label directly. This stepwise reasoning leverages the LLM's capacity for structured problem-solving, reducing hallucinations and improving label consistency.
- **Core assumption:** Explicit reasoning steps constrain the LLM to ground its judgment in the specific code constructs, leading to more cognitively faithful annotations.
- **Evidence anchors:**
  - [abstract] "we employ a chain-of-thought prompting strategy... guiding the LLM to reason about the presence of each KC and the correctness of its application"
  - [section 2] "This structured prompting strategy encourages consistent and interpretable KC correctness judgments"
  - [section 3] Ablation study shows CoT variants (GPT-4o, Qwen3) significantly outperform the same model without CoT on RMSE/r².
- **Break condition:** If the LLM's intermediate reasoning becomes incoherent or diverges from the code's actual structure (e.g., referencing non-existent variables), the final label may be unreliable.

### Mechanism 2
- **Claim:** Temporal context-aware Code-KC mapping aligns the set of KCs to an individual student's solution strategy by using the last attempt as a proxy for their intended complete solution.
- **Mechanism:** The embedding of the student's last code submission is compared to embeddings of reference correct solutions (clustered by strategy). The KCs associated with the closest reference solution are selected for labeling on the *first* attempt. This filters out KCs not relevant to the student's chosen approach.
- **Core assumption:** A student's final (last) attempt on a problem, even if incomplete, better represents their intended solution strategy and the full set of KCs they aimed to apply than their first attempt.
- **Evidence anchors:**
  - [section 2] "we identify the closest correct code using cosine distance since... the last attempt is a mostly-complete or near-correct version that includes all KCs the student use"
  - [section 3] For GPT-4o, using the context-aware KC selection improved r² from 0.291 (Generated set without selection) to 0.383 (Selected set).
  - [corpus] Neighbor papers (e.g., "Pattern-based KC Extraction") also emphasize aligning KCs to specific code patterns/strategies.
- **Break condition:** If a student's last attempt is a drastically different strategy from their first attempt (e.g., changed approach after a hint) or if the last attempt is a completely unrelated copy, the mapping may attribute irrelevant KCs.

### Mechanism 3
- **Claim:** Using automatically generated, fine-grained KC sets (vs. coarse human-defined sets) captures diverse solution strategies, leading to learning curves that better fit the Power Law of Practice.
- **Mechanism:** KCs are generated from a diverse set of correct reference solutions via LLM prompting. This creates a more comprehensive and granular KC inventory for a problem. When combined with the context-aware mapping, the labeling process can assign only the KCs pertinent to a student's specific solution.
- **Core assumption:** Human-created KC sets often overlook valid alternative solution strategies and may have too coarse or sparse granularity, obscuring partial mastery when propagated from problem-level labels.
- **Evidence anchors:**
  - [abstract] "...leverages large language models (LLMs) to label KC-level correctness directly from student-written code"
  - [section 2] "automated KC generation takes code diversity into account and alleviates this issue" where "this issue" refers to KCs exercised fewer than three times.
  - [section 3] Generated KC sets consistently outperform Human sets in baseline conditions (e.g., GPT-4o: Generated RMSE 0.086 vs Human 0.110).
  - [corpus] Directly supported by the strongly related paper "Automated Knowledge Component Generation..." (arxiv:2502.18632).
- **Break condition:** If generated KCs are too numerous, overlapping, or abstract (e.g., "use loops" vs "use for-loop with correct bounds"), they may become less interpretable and harder for the LLM to judge correctly, or for downstream models to use.

## Foundational Learning
- **Knowledge Components (KCs)**: Fine-grained skills or concepts students apply in code. *Why needed*: The framework aims to label correctness at this granularity instead of whole-problem level. *Quick check*: How does labeling at KC level change interpretation of an "incorrect" submission?
- **Learning Curves & Power Law of Practice**: Theory that error rates decrease with practice following a power function. *Why needed*: The primary evaluation checks if KC labels produce learning curves that follow this law, connecting labels to cognitive theory. *Quick check*: Why would problem-level labels cause non-decreasing error rates?
- **Additive Factors Model (AFM)**: A predictive model of student performance that sums contributions from KCs. *Why needed*: AFM requires KC-level correctness data; improved AUC indicates higher-quality labels. *Quick check*: What does improved AFM AUC signify about KC label quality?

## Architecture Onboarding
- **Component map**: Input Parser -> KC Context Selector -> LLM Prompt Engine -> LLM Inference -> Label Parser -> Output (KC correctness matrix). For generated KCs, the KC Context Selector is active; for human KCs, it may be bypassed.
- **Critical path**: Student first attempt -> (KC Context Selector if needed) -> LLM Prompt Engine -> LLM -> Label Parser -> Labels. The context selector is critical for generated KCs to filter irrelevant ones.
- **Design tradeoffs**:
  - LLM choice: GPT-4o (proprietary, higher cost) vs Qwen3 (open-weight, may be more sensitive to ambiguities).
  - CoT vs no CoT: CoT improves metrics but increases token cost; no CoT is cheaper but less accurate.
  - KC granularity: Generated KCs increase coverage but risk noise; human KCs are interpretable but sparse.
- **Failure signatures**:
  - LLM output not parseable into {KC: 0/1} format.
  - Low human-LLM agreement (Kappa < 0.7) on validation sample.
  - Learning curves for some KCs show increasing error rates with attempts.
  - For context mapping, low cosine similarity between last attempt and matched reference.
- **First 3 experiments**:
  1. Baseline Comparison: Run full pipeline vs problem-level baseline; compare Power Law RMSE/r² and AFM AUC.
  2. CoT Ablation: Remove CoT instructions; compare metrics to CoT version.
  3. Human Validation Sample: Have two experts label 80 submissions; compute Cohen's Kappa between humans and between humans and LLM.

## Open Questions the Paper Calls Out
1. **Does incorporating problem difficulty metrics improve label accuracy?** *Basis*: Future work suggestion. *Unresolved*: Current framework omits difficulty. *Evidence needed*: Augment prompts with difficulty indicators and test label accuracy/learning curve fit.
2. **How does integrating test case correctness enhance evaluation?** *Basis*: Suggestion to connect KC labels with test outcomes. *Unresolved*: Only code structure used. *Evidence needed*: Hybrid model using both; measure AFM AUC improvement and feedback specificity.
3. **Can LLM-based labeling simulate realistic student errors to improve feedback?** *Basis*: Extension for error simulation. *Unresolved*: Framework only labels correctness. *Evidence needed*: Generate error variants; compare error distributions to real data and test feedback effectiveness.
4. **How reliable is the assumption that final attempts reflect intended strategies?** *Basis*: Limitation noted. *Unresolved*: Last attempt may not match early strategy. *Evidence needed*: Annotate intended strategies from early drafts; compute alignment with final-attempt KCs.

## Limitations
- Missing exact prompt templates and KC generation hyperparameters hinders exact replication.
- Evaluation limited to CodeWorkout dataset; generalizability to other coding contexts is uncertain.
- Break conditions (e.g., low similarity mappings) are identified but not quantitatively assessed for failure rates.

## Confidence
- CoT mechanism: High (supported by ablations and known LLM reasoning benefits)
- Temporal context mapping: Medium (metrics improve but assumption about last attempt representativeness lacks edge-case validation)
- Generated KC sets: Medium (outperform human sets but potential for overgranular/abstract KCs is unmeasured)
- Overall evaluation validity: High (clear improvements on theoretical metrics, but may not capture all cognitive aspects)

## Next Checks
1. Prompt recovery: Request full prompt templates and few-shot examples from authors; test output format stability on n=50 samples at temperature=0.
2. KC generation reproduction: Implement generation pipeline on CodeWorkout references, vary clustering parameters (k, pooling) to match reported KC counts and diversity.
3. Mapping robustness test: Sample cases with low cosine similarity (<0.7) between last attempt and nearest reference; quantify occurrence frequency and impact on KC relevance via human review.
