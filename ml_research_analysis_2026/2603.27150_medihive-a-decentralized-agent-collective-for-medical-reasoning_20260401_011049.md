# MediHive: A Decentralized Agent Collective for Medical Reasoning
## Quick Facts
- **arXiv ID:** 2603.27150
- **Source URL:** https://arxiv.org/abs/2603.27150
- **Reference count:** 23
- **Primary result:** Achieves 84.3% accuracy on MedQA and 78.4% on PubMedQA, outperforming single-LLM and centralized multi-agent baselines using the same model backbone.

## Executive Summary
MediHive presents a decentralized multi-agent system (D-MAS) for complex medical reasoning, moving beyond single-agent and centrally managed multi-agent limitations. Autonomous LLM-based agents self-assign specialized roles, engage in evidence-based debates only when necessary, and iteratively fuse insights through a shared, passive memory pool to reach consensus without a central coordinator. Evaluated on MedQA and PubMedQA, MediHive demonstrates superior accuracy, with ablations underscoring the critical contributions of chain-of-thought reasoning and self-evolving role assignment to its performance gains.

## Method Summary
MediHive is a zero-shot framework using N autonomous agents (default N=5) operating in five phases: (1) **Self-evolving role assignment**—agents propose and then refine roles based on peer proposals, optimizing for clarity, differentiation, and alignment; (2) **Initial analysis**—each agent generates chain-of-thought reasoning, an answer, and a confidence score; (3) **Conditional debate**—if initial answer agreement falls below a threshold τ_agree (e.g., 0.8), a fixed number of adversarial rebuttal/defense cycles is triggered; (4) **Iterative fusion**—agents read peer outputs from the shared memory and update their reasoning and answers over multiple rounds until agreement stabilizes or a round limit K is reached; (5) **Reporter aggregation**—outputs the majority answer if consensus reached, else a confidence-weighted vote. The shared memory is an append-only log accessible to all agents, enabling decentralized coordination.

## Key Results
- MediHive achieves 84.3% accuracy on MedQA and 78.4% on PubMedQA with Llama-3.1-70B-Instruct, surpassing single-LLM and centralized multi-agent baselines.
- Ablation studies show that disabling self-evolving role assignment reduces MedQA accuracy by 2.8% (84.3% → 81.5%), and removing chain-of-thought reasoning causes severe performance degradation.
- The conditional debate mechanism activates only when necessary, and iterative fusion typically converges within a few rounds, indicating efficient consensus-building.

## Why This Works (Mechanism)
### Mechanism 1: Decentralized Peer-to-Peer Coordination
**Claim:** Robust consensus emerges without a central manager through autonomous agents reading from and appending to a shared memory pool, independently detecting disagreements.  
**Core assumption:** Given identical evidence and clear protocols, agents self-synchronize via local updates.  
**Evidence anchors:** [abstract] describes decentralized framework with shared memory and no central coordinator; [section III.A & III.B.2] details passive memory and independent disagreement detection; neighbor papers (e.g., Symphony, AgentNet) support decentralized viability.  
**Break condition:** If agreement ≥ τ_agree not achieved within K fusion rounds, system falls back to reporter-mediated confidence-weighted vote, indicating autonomous consensus failed to stabilize.

### Mechanism 2: Self-Evolving Role Assignment
**Claim:** Two-step proposal and refinement ensures complementary, non-redundant expert perspectives (e.g., GI Specialist vs. Geriatrician) rather than static or overlapping roles.  
**Core assumption:** Semantically distinct specializations cover the medical problem space more effectively.  
**Evidence anchors:** [section III.A] defines refinement criteria (Clarity, Differentiation, Alignment) with example role specialization; [section IV.C (Ablation)] shows 2.8% accuracy drop when disabled; corpus signal on role confusion highlights addressed problem.  
**Break condition:** If final roles remain semantically similar (high pairwise similarity), role redundancy reduces diversity and harms accuracy.

### Mechanism 3: Conditional Debate and Iterative Fusion
**Claim:** Separating adversarial stress-testing (debate) from integrative synthesis (fusion) improves reasoning robustness; debate triggers only when initial answers disagree.  
**Core assumption:** Structured adversarial critique surfaces hidden assumptions better than purely cooperative discussion, and phase separation prevents premature convergence.  
**Evidence anchors:** [section III.B.2 & B.3] defines conditional activation and distinct purposes; [section IV.C (Ablation)] supports importance of structured CoT; neighbor paper on multiagent debate explores related ideas but not conditional separation.  
**Break condition:** Debate too short may miss weaknesses; too long may generate noise or entrenched positions. Fusion may fail if conflicts irreconcilable.

## Architecture Onboarding
Component Map:  
Agents (A_i) -> Shared Memory Pool (M) -> Reporter  
Agents read/write M independently; M is append-only and passive.

Critical Path:  
1. Query added to M.  
2. Phase 1 (Role): ProposeRole → read peers → RefineRole → final roles in M.  
3. Phase 2 (Analyze): Each agent generates (Reasoning, Answer, Confidence) based on Q and R_i → append to M.  
4. Phase 3 (Conditional Debate): If agreement < τ_agree, run T_debate cycles of Debate (Rebuttal/Defense/Proposal) → append to M.  
5. Phase 4 (Fusion): For k=2 to K (or until agreement ≥ τ_agree for 2 rounds): read context from M → Fuse → update (Reasoning, Answer, Confidence) → append.  
6. Phase 5 (Reporter): Determine termination → aggregate final Answer → SynthesizeTrace(M) → return (a*, trace).

Design Tradeoffs:  
- Number of agents (N): Optimal at 5; fewer reduces diversity, more increases noise/convergence cost.  
- Debate trigger (τ_agree): Lower increases thoroughness but cost; higher may skip needed debate (~0.8 default).  
- Fusion context window: Round k=2 uses full history; k>2 uses only previous round—trade-off between comprehensive context and focus.

Failure Signatures:  
- Persistent low agreement: Fusion exhausts K without reaching τ_agree.  
- Role collapse: Final roles have high semantic similarity (e.g., multiple "Generalist").  
- Debate escalation: Cycles produce antagonistic/repetitive arguments without new evidence.  
- Reporter overuse: Final answer always from confidence-weighted vote, never supermajority.

First 3 Experiments:  
1. **Role Diversity Stress Test:** On 100 diverse medical queries, compute pairwise semantic similarity (e.g., sentence-BERT cosine) of final roles; target median similarity < 0.3.  
2. **Debate Trigger Sensitivity:** Vary τ_agree from 0.6 to 0.95 on MedQA subset; measure final accuracy, debate activation frequency, and average tokens per query; identify optimal accuracy/efficiency trade-off.  
3. **Fusion Round Limit Impact:** Run with K ∈ {2,3,4,5,∞}; plot accuracy and average rounds to convergence; determine practical K capturing most gains.

## Limitations
- Prompt engineering gap: Exact prompt templates for agent operations (ProposeRole, Debate, Fuse) are unreported, risking significant behavioral variance in reproduction.
- Hyperparameter opacity: Critical defaults (e.g., max fusion rounds K, precise τ_agree) are not specified, making replication of reported performance speculative.
- Concurrency ambiguity: Practical implementation of shared memory (thread safety, read/write ordering) is underspecified, introducing potential race conditions.

## Confidence
- Mechanism 1 (Decentralized Coordination): Medium — architectural description clear but no direct ablation against true centralized variant; fallback to reporter suggests pure decentralized consensus may not always stabilize.
- Mechanism 2 (Self-Evolving Roles): High — strongly supported by ablation (2.8% drop) and explicit refinement criteria.
- Mechanism 3 (Conditional Debate/Fusion): Medium-High — phases explicitly described and CoT ablation supports structured reasoning, but conditional trigger’s isolated contribution not tested.
- Overall Performance Claim (84.3% MedQA): Medium — results reported but unknown prompts and K prevent verification; may not generalize to smaller backbones.
