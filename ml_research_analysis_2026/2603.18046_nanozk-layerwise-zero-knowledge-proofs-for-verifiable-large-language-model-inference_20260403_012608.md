# NANOZK: Layerwise Zero-Knowledge Proofs for Verifiable Large Language Model Inference

## Quick Facts
- **arXiv ID:** 2603.18046
- **Source URL:** https://arxiv.org/abs/2603.18046
- **Reference count:** 17
- **Primary result:** Layerwise ZK proofs with constant size (6.9KB/layer), zero accuracy loss via 16-bit lookup tables, and Fisher-guided selective verification achieve 23ms verification and 52× speedup over EZKL.

## Executive Summary
NANOZK addresses the critical lack of cryptographic verification in LLM APIs, where service providers could substitute models or quantize weights without detection. It introduces a layerwise zero-knowledge proof framework that decomposes transformer inference into independent per-layer proofs, each with constant size regardless of model width. This decomposition enables parallel proving and selective verification. Non-arithmetic operations (softmax, GELU, LayerNorm) are approximated with 16-bit lookup tables that introduce no measurable accuracy loss. Fisher information guides efficient partial verification by prioritizing sensitive layers. The system achieves 23ms verification time, a 52× average speedup over EZKL (up to 228× for larger MLPs), and formal soundness error below 10⁻³⁷.

## Method Summary
NANOZK proves transformer inference correctness by treating each layer as an independent zero-knowledge circuit. For each layer, it generates a zk-SNARK proof (using Halo2 with inner product argument) that the computation was performed correctly on committed inputs and outputs. Adjacent layers are cryptographically linked via SHA-256 commitments, forming a chain. Non-arithmetic functions are implemented via precomputed 16-bit lookup tables to remain ZK-compatible without accuracy loss. A Fisher information-based importance score, precomputed on calibration data, allows verifiers to selectively check only the most sensitive layers for a given verification budget.

## Key Results
- Constant per-layer proof size (~6.9 KB) independent of model width.
- Zero measurable accuracy loss: identical WikiText-2 perplexity for GPT-2, GPT-2-Medium, and TinyLLaMA-1.1B (∆PPL = 0.00%).
- Fisher-guided selection captures 65–86% of model sensitivity with 50% of the proving cost, versus 51–79% for random.
- Verification time 23 ms; 52× average speedup over EZKL (up to 228× for larger MLPs).
- Formal soundness error below 10⁻³⁷.

## Why This Works (Mechanism)

**Mechanism 1: Layerwise decomposition yields constant-size proofs and parallel proving while maintaining soundness.** Each transformer layer is proven independently with a zero-knowledge proof; cryptographic commitments (SHA-256) to the layer’s input and output are included. Adjacent proofs share consistent commitments, forming a chain. A compositional soundness theorem shows the composite proof’s error is bounded by the sum of layer errors plus negligible hash-collision probability. The core assumption is that decoder-only transformer layers are sequentially dependent without skip connections and the commitment hash function is collision-resistant. Evidence includes Theorem 3.1 and Equation 3 in the paper. Break conditions: architectures with skip connections may break the constant-size guarantee; a hash collision breaks the chain.

**Mechanism 2: Lookup-table approximations for softmax, GELU, and LayerNorm introduce no measurable accuracy loss while remaining ZK-compatible.** Precomputed function values over a fixed operating range are used; during ZK evaluation, the input is quantized to 16-bit fixed-point and the output retrieved via lookup. Range constraints verify correct lookup. Quantization errors (~10⁻⁵) are smaller than the model’s inherent robustness and largely cancel due to normalization. The core assumption is that quantization error is below the network’s noise tolerance and predefined ranges cover all activations in practice. Evidence includes Table 1 (max absolute errors ≤ 9×10⁻⁶) and WikiText-2 perplexity results. Break condition: activations outside the lookup ranges on out-of-distribution data cause clamping errors that may degrade performance; changing activation functions may require range adjustments.

**Mechanism 3: Fisher information-guided layer selection captures more model sensitivity than random selection for a given verification budget.** A per-layer importance score is computed as the trace of the Fisher information matrix normalized by parameter count. Verifying top-*k* layers by this score empirically captures 62–86% of total Fisher mass at 50% budget versus 51–79% for random. The core assumption is that layers with higher Fisher information exert greater influence on the output distribution; verifying them deters economically-motivated adversaries targeting high-impact layers. Evidence includes Table 2 for GPT-2-Small, TinyLLaMA-1.1B, and Phi-2. Break condition: an adversary modifying low-Fisher layers may evade detection; Fisher scores depend on calibration data distribution and require a representative dataset and model gradients.

## Architecture Onboarding
- **Component map:** Lookup table manager -> Layerwise proof module -> Commitment chain manager -> Halo2 IPA prover/verifier; Fisher calculator (offline) -> importance scores -> Parallel orchestrator (for selective verification).
- **Critical path:** 1) User query arrives. 2) Provider runs native forward pass to obtain activations. 3) For each transformer layer, generate a ZK proof in parallel using Halo2 IPA. 4) Compute SHA‑256 commitments for inputs/outputs and verify chain consistency. 5) If selective verification requested, use precomputed Fisher scores to choose which layer proofs to send. 6) Verifier checks selected proofs and commitment chain; accept or reject.
- **Design tradeoffs:** 
  - Constant proof size vs. proving latency: per‑layer proof time (~6.2 s) accumulates; parallelism reduces wall‑clock time at CPU/memory cost.
  - Accuracy preservation vs. range coverage: fixed‑range LUTs achieve zero loss on tested data but risk distortion if activations exceed ranges; widening ranges increases circuit size.
  - Full vs. selective verification: full verification gives cryptographic certainty; Fisher‑guided selection improves efficiency but offers probabilistic security.
  - Transparent setup vs. trusted setup: Halo2 avoids a ceremony, simplifying deployment and offering post‑quantum resistance, but may yield larger proofs than pairing‑based SNARKs.
- **Failure signatures:**
  - Perplexity increase > 0.1%: LUT range insufficient or quantization too coarse; check activation histograms.
  - Proof time >> 6.2 s per layer: circuit degree or memory pressure too high; verify Halo2 configuration and model width.
  - Commitment mismatch errors: inconsistent inputs/outputs across layers; ensure correct chaining and that proofs come from the same forward pass.
  - Fisher coverage lower than expected: calibration data mismatched deployment distribution; recompute Fisher on more representative data.
- **First 3 experiments:**
  1. **Constant proof size validation:** Generate single‑block proofs for GPT‑2 variants (d = 64, 128, 256, 512, 768). Measure proof size; expect ~6.9 KB across all.
  2. **Accuracy preservation test:** Evaluate WikiText‑2 perplexity for original vs. lookup‑approximated GPT‑2, GPT‑2‑Medium, TinyLLaMA. Expect identical values (∆PPL = 0.00%).
  3. **Fisher vs. random selection:** On TinyLLaMA‑1.1B, compute Fisher scores using a calibration set. At 50% budget (11 layers), compare importance coverage for Fisher‑selected vs. random (≥ 5 runs). Expect Fisher ≥ 86%, random ~79%.

## Open Questions the Paper Calls Out
**Open Question 1:** How can ZK proof generation for LLM inference be accelerated to be practical for real‑time deployment, particularly by adapting sequential ZK protocols like Halo2 IPA to parallel GPU architectures?  
*Basis:* The limitations section states: "Proving remains orders of magnitude slower than native inference... Our current implementation targets CPU; GPU acceleration could substantially reduce proving time, though porting IPA‑based proving to GPU requires careful handling of the sequential multi‑scalar multiplication steps."  
*Why unresolved:* CPU proving time (minutes) is far slower than native inference (seconds), and sequential dependencies in IPA’s inner product argument prevent straightforward GPU parallelization, leaving a significant performance gap.  
*What evidence would resolve it:* A working GPU implementation of Halo2 IPA (or a similar ZK system) that achieves at least an order of magnitude speedup over the CPU baseline for LLM‑scale circuits, with a detailed analysis of how sequential steps are parallelized, validated on transformer models up to GPT‑2 scale.

**Open Question 2:** Can we design a selective verification scheme for LLM inference that retains full cryptographic soundness while reducing verification overhead, instead of relying on probabilistic importance metrics like Fisher information?  
*Basis:* The paper explicitly notes: "Fisher‑guided selection is an efficiency optimization, not a security guarantee. A worst‑case adversary could target low‑Fisher layers specifically. Applications requiring cryptographic certainty must verify all layers."  
*Why unresolved:* Current selective verification only offers probabilistic assurance; a malicious prover could exploit unverified low‑importance layers to produce incorrect outputs. There is no known method to achieve the same soundness error as full verification with only partial checks.  
*What evidence would resolve it:* A cryptographic construction that allows verifying any subset of layers such that the overall soundness error equals that of verifying all layers (e.g., through random sampling with amplification or a novel combinatorial argument), accompanied by a formal proof and implementation showing the same ε ≤ 10⁻³⁷ guarantee.

**Open Question 3:** Do the 16‑bit lookup table approximations for softmax, GELU, and LayerNorm preserve model accuracy across a diverse range of tasks and metrics beyond perplexity on WikiText‑2?  
*Basis:* Evaluation is restricted to perplexity on WikiText‑2 for three models: "Table 5 demonstrates... perplexity remains identical to two decimal places." No other benchmarks or metrics are reported.  
*Why unresolved:* Perplexity is a language modeling measure; other capabilities (reasoning, coding, multilingual understanding) may be more sensitive to small numerical errors. The three models tested are also all decoder‑only LMs; other architectures might behave differently.  
*What evidence would resolve it:* Comprehensive experiments on standard benchmarks (e.g., MMLU, HumanEval, BIG‑Bench) covering a variety of model families (encoder‑decoder, multimodal) showing that the approximations do not cause statistically significant degradation compared to the original models.

**Open Question 4:** Can the layerwise proof decomposition be extended to neural network architectures that include skip connections bypassing multiple layers, such as ResNets or encoder‑decoder transformers?  
*Basis:* The decomposition relies on the assumption: "each layer’s output depends only on the previous layer’s output, not on any global state shared across non‑adjacent layers (i.e., no skip connections that bypass the sequential chain in standard decoder‑only transformers)."  
*Why unresolved:* Many high‑performing architectures (e.g., DenseNet, U‑Net, some transformer variants) have cross‑layer skip connections that create dependencies between non‑consecutive layers, violating the independence required for per‑layer proofs and breaking the commitment chain.  
*What evidence would resolve it:* A modified framework that handles such skip connections—e.g., by grouping layers with skip dependencies into single proofs or adding extra cryptographic constraints linking the skipped layers—together with a formal soundness proof and demonstration on a model like ResNet‑50 or an encoder‑decoder transformer.

## Limitations
- **Lookup table range coverage:** Fixed 16‑bit ranges for softmax/GELU/LayerNorm may fail on out‑of‑distribution data or new architectures, causing clamping errors not captured by WikiText‑2 tests.
- **Fisher‑guided partial verification security:** The assumption that adversaries only target high‑Fisher layers is unproven; tampering with low‑Fisher layers could evade detection while still affecting outputs subtly.
- **Performance claims & generalizability:** Speedups (52× avg vs. EZKL) and constant 6.9KB proof size are measured on specific models (GPT‑2 variants, TinyLLaMA). Results may vary with different model sizes, attention heads, or hardware.
