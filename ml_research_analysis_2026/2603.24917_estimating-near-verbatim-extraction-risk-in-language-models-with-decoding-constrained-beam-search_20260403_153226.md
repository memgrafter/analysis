# Estimating near-verbatim extraction risk in language models with decoding-constrained beam search
## Quick Facts
- **arXiv ID:** 2603.24917
- **Source URL:** https://arxiv.org/abs/2603.24917
- **Reference count:** 40
- **Primary result:** A deterministic, scalable lower-bound estimator for near-verbatim extraction risk reveals rates up to 2.57% on OLMo2 models, unlocking thousands of previously zero-risk sequences with substantial mass.

## Executive Summary
Measuring the risk that a language model will output near-verbatim copies of its training data is computationally intractable via exact methods. This paper introduces **decoding-constrained beam search**, a modification of standard beam search that incorporates top-k decoding and distance-based viability pruning (using Hamming or Levenshtein distance). The algorithm efficiently yields a *provable lower bound* on the extraction probability for a given text. Evaluated on OLMo2 models (7B–32B) with Wikipedia data, the method finds near-verbatim extraction rates significantly higher than verbatim-only rates, with the effect scaling with model size. The approach makes large-scale, deterministic privacy/copyright audits feasible at a cost comparable to ~20 Monte Carlo samples.

## Method Summary
The core method modifies beam search in two ways: (1) it restricts the token candidates at each step to a top-k set rather than the full distribution, and (2) it prunes any partial beam sequence whose best possible completion (via edit distance) cannot fall within a predefined near-verbatim threshold of the target text. This pruning is safe because it discards only sequences that could never contribute to the lower bound. The algorithm tracks the accumulated probability mass of all viable beams that reach the end of the target sequence, providing a deterministic lower bound on the true extraction probability. The computational cost is empirically shown to be similar to running ~20 standard Monte Carlo sampling trials.

## Key Results
- Near-verbatim extraction rates on OLMo2 reach up to **2.57%** for the 32B model, compared to a verbatim-only rate of 1.42%.
- The method **unlocks thousands of sequences** previously assessed as having zero verbatim risk, with individual sequence near-verbatim mass often exceeding 0.85.
- Near-verbatim mass dominates at smaller model scales and scales with model size; the gap between verbatim and near-verbatim risk widens with larger models.

## Why This Works (Mechanism)
Standard beam search explores high-probability paths but does not guarantee coverage of all sequences that could contribute to extraction probability. By combining **top-k decoding** (limiting the search space) with **viability pruning based on edit distance** (removing paths that cannot possibly match the target within the allowed deviation), the algorithm focuses computation on only those continuations that can increase the lower-bound mass. The pruning condition is conservative: a partial sequence is discarded only if even its *best possible* completion (minimal achievable edit distance) exceeds the threshold. This ensures no viable path is removed, making the final sum a valid lower bound. The top-k constraint introduces a slight approximation, but the bound remains correct under that constraint.

## Foundational Learning
- **Beam Search:** A heuristic search algorithm that maintains a fixed number (beam width) of the most promising partial sequences at each step. *Why needed:* Provides a structured way to explore high-probability generation paths. *Quick check:* What happens if beam width is 1? (Greedy decoding.)
- **Top-k Decoding:** Restricts sampling to the k most likely next tokens at each step. *Why needed:* Controls computational cost and search space. *Quick check:* How does increasing k affect diversity and cost?
- **Edit Distance (Hamming/Levenshtein):** Metrics quantifying the dissimilarity between two strings (character or token level). *Why needed:* Defines "near-verbatim" – a sequence within a threshold edit distance is considered an extraction. *Quick check:* Which metric is better for capturing small word swaps vs. character typos?
- **Lower Bound Estimation:** A value guaranteed to be less than or equal to the true probability. *Why needed:* Enables risk assessment without intractable exact computation; a lower bound allows conservative auditing. *Quick check:* What are the trade-offs of using a lower bound vs. an unbiased estimator?

## Architecture Onboarding
**Component Map:**  
Input Target Text -> Tokenization -> Decoding-Constrained Beam Search (with Top-k Candidates) -> Viability Pruning (Edit Distance Check) -> Accumulate Mass on Completion -> Output Lower Bound

**Critical Path:**  
1. Initialize beam with start tokens.  
2. At each step: expand each beam state with top-k next tokens.  
3. For each new partial sequence, compute minimal achievable edit distance to target suffix.  
4. Prune if minimal distance > remaining allowed edits.  
5. If sequence matches target within threshold, add its probability to total mass.  
6. Repeat until target length reached or all beams pruned.

**Design Tradeoffs:**  
- **Beam width vs. cost:** Wider beams increase chance of finding viable paths but linearly increase computation.  
- **Top-k vs. bound tightness:** Smaller k reduces cost but may exclude the actual high-probability extraction path, weakening the lower bound.  
- **Distance threshold vs. sensitivity:** Tighter thresholds (small edit distance) focus on verbatim copies; looser thresholds capture more near-matches but may include false positives (non-extractions).

**Failure Signatures:**  
- Bound close to zero despite known extractions: beam too narrow or top-k too small.  
- Runtime spikes unexpectedly: token vocabulary large and distance computation not cached efficiently.  
- High variance across runs: algorithm is deterministic; variance indicates implementation bug (e.g., non-deterministic pruning).

**First Three Experiments:**  
1. **Vary beam width** (e.g., 5, 10, 20) on a fixed model/text; measure change in lower bound and runtime.  
2. **Compare Hamming vs. Levenshtein** on same texts; assess unlocked sequences and bound tightness.  
3. **Apply to a small model (<100M)** where exact enumeration is possible on short texts; verify bound is always ≤ true probability and assess gap magnitude.

## Open Questions the Paper Calls Out
The paper identifies several directions for future work and open questions:
- **Generalization across domains:** The evaluation is limited to Wikipedia text; it remains unknown whether similar near-verbatim extraction rates occur in other domains like code, books, or multi-lingual corpora.
- **Cross-architecture validity:** Experiments were conducted only on OLMo2 models; the behavior on other architectures (e.g., GPT-style decoder-only models, encoder-decoder models like T5) needs investigation.
- **Bound tightness:** The algorithm provides a lower bound; the typical gap between this bound and the true extraction probability (especially for larger models and longer sequences) is an open question.
- **Hyperparameter sensitivity:** The choice of beam width, top-k, and edit distance thresholds may significantly affect the reported rates; a systematic analysis is lacking.
- **Scalability to larger contexts and models:** The cost equivalence to ~20 Monte Carlo samples was shown for models up to 32B and fixed context lengths; scalability to very long contexts or models with hundreds of billions of parameters requires further validation.

## Limitations
- Evaluation limited to Wikipedia text; generalizability to other domains (e.g., code, books) is unknown.
- Algorithm provides only a lower bound; true extraction risk could be higher if pruning is too aggressive or top-k excludes viable paths.
- Experiments conducted solely on OLMo2 model family; other architectures (e.g., decoder-only GPT, encoder-decoder T5) may behave differently.
- Hyperparameter sensitivity (beam size, top-k, distance thresholds) not thoroughly analyzed; results may depend on choices.
- Cost equivalence (~20 MC samples) demonstrated only for specific model sizes and context lengths; scalability to very long contexts or larger models needs validation.

## Confidence
- **Algorithm correctness (provable lower bound):** High  
- **Computational cost ≈20 MC samples:** Medium (empirical support limited to 7B–32B models, fixed contexts)  
- **Near-verbatim superiority (rates, unlocked sequences, scaling):** Medium (evidence from OLMo2/Wikipedia only)  
- **Scalability for large-scale audits:** Medium (preliminary; large-scale studies pending)  

## Next Checks
1. **Cross-model/domain replication:** Apply method to at least two other model families (e.g., LLaMA, GPT-2) and two additional corpora (e.g., The Pile, Project Gutenberg) to test generalizability of near-verbatim findings.
2. **Tightness of lower bounds:** For a small model (<1B parameters), compute exact extraction probabilities via exhaustive enumeration on short target sequences (length ≤ 20 tokens); compare to the algorithm's lower bounds to measure typical gap.
3. **Hyperparameter sensitivity:** Systematically vary beam width (5–50), top-k (10–100), and edit distance thresholds; for each setting, record extraction rate, number of unlocked sequences, and runtime to identify stable operating regimes and worst-case bound deterioration.
