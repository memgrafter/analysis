# FAMOSE: A ReAct Approach to Automated Feature Discovery

## Quick Facts
- arXiv ID: 2602.17641
- Source URL: https://arxiv.org/abs/2602.17641
- Reference count: 40
- Primary result: Achieves state-of-the-art performance with average ROC-AUC improvement of 0.23% on large classification datasets and RMSE reduction of 2.0% on regression tasks.

## Executive Summary
FAMOSE addresses the feature engineering bottleneck in tabular machine learning by using a ReAct agent to autonomously explore, generate, and refine features through iterative hypothesize-test-refine loops. The agent leverages tools to write and execute code, evaluate validation performance, and adapt based on feedback. After discovery, a minimum redundancy maximum relevance (mRMR) algorithm selects a compact final feature set. Evaluated on 27 datasets, FAMOSE shows consistent improvements over baselines and robustness across LLMs and base models.

## Method Summary
FAMOSE employs a ReAct-style agent that iteratively proposes candidate features, generates Python functions to create them, and evaluates their impact on a validation set using a performance delta threshold (≥1%). The agent runs for up to 20 rounds with 10 steps each, stopping early after 6 rounds without improvement. Retained features are passed to mRMR, which selects a parsimonious subset by minimizing redundancy and maximizing relevance to the target. This decouples creative generation from deterministic selection, ensuring effectiveness.

## Key Results
- For large classification datasets (>10K instances), FAMOSE improves average ROC-AUC by 0.23% over baselines.
- For regression tasks, it reduces RMSE by 2.0% on average.
- The method demonstrates robustness across LLMs (Claude, Deepseek) and base models (XGBoost, Random Forest, Autogluon).

## Why This Works (Mechanism)
### Mechanism 1: Iterative Contextual Refinement
The ReAct loop maintains a rolling context of prior features, code, and outcomes, functioning as a dynamic few-shot prompt. This guides the LLM to avoid ineffective patterns and build on successes, progressively aligning proposals with predictive structure. Evidence from the paper attributes innovation to this history-based conditioning; if context grows too large or is poorly parsed, benefits diminish.

### Mechanism 2: Tool-Grounded Execution
Integrated tools—metadata generator, Python compiler, and feature evaluator—force grounding in actual data constraints. The evaluator computes validation performance delta, providing immediate feedback. Error correction and regex for hallucinated names ensure feasibility, reducing hallucination. Tool failures or data leakage would corrupt the learning signal.

### Mechanism 3: Decoupled Selection with mRMR
Separating generation (LLM) from selection (mRMR) yields a compact, high-performing set. mRMR minimizes redundancy while maximizing relevance, solving a combinatorial optimization more consistently than LLM judgment. Ablations confirm mRMR's necessity; if relevance metrics misalign with the final model, selection may omit critical features.

## Foundational Learning
- **ReAct Framework**: The agentic loop of reasoning and acting with tools is essential for closed-loop feature engineering, avoiding abstract hallucinations by grounding in execution. Quick check: How does tool execution differ from chain-of-thought in reducing hallucination?
- **Minimum Redundancy Maximum Relevance (mRMR)**: This algorithm selects features by balancing relevance to the target and redundancy among features, providing a deterministic filter post-generation. Quick check: What would mRMR do with two highly predictive but redundant features?
- **Tool-Augmented LLM Agents**: Integrating LLMs with external tools (code execution, data inspection) ensures feasibility and provides feedback for practical applications. Quick check: What problem does the feature evaluation tool solve in this context?

## Architecture Onboarding
### Component Map
ReAct Agent Core (LLM) -> Tool Suite (metadata_generator, python_compiler, feature_evaluator) -> Round Manager -> mRMR Selector -> External Model (XGBoost). Data flows via Data Split Manager.

### Critical Path
1. For each CV fold, initialize empty feature set F and baseline score E0.
2. For round r=1 to 20: run ReAct agent with up to 10 steps; for each candidate feature, evaluate delta = 1 - E(X∪F∪{f})/E(X∪F); keep best f with delta ≥ 0.01; add to F.
3. Stop early if no improvement in last 6 rounds.
4. Apply mRMR to F to select F* using inner CV.
5. Train model on F* and evaluate on test fold.
6. Repeat for all folds; aggregate results.

### Design Tradeoffs
- LLM cost/time vs. exploration depth: More rounds/steps improve exploration but increase expense; early stopping and 1% goal balance this.
- Generality vs. efficiency: General LLM and mRMR work across datasets but may be slower than domain-specific algorithms.
- Agent autonomy vs. control: Tools and performance threshold constrain output, with prompt goals steering search.

### Failure Signatures
- Tool failure: Repeated code errors or hallucinated columns, agent stuck in retry loops.
- Performance stagnation: No delta > 0 after several rounds, early stopping triggers, small F.
- mRMR failure: Selects 0/1 feature or degrades performance, indicating all generated features are redundant or irrelevant.
- Resource exhaustion: Time/memory limits exceeded, especially on large datasets or with token limits.

### First 3 Experiments
1. Sanity check on balance-scale: Verify FAMOSE rediscovers the torque feature and achieves near-perfect score.
2. Ablate iterative goal: Remove "improve by 1%" prompt on credit-g dataset; compare feature count, diversity, and ROC-AUC to standard version.
3. Tool injection test: Corrupt metadata_generator or feature_evaluator on a small dataset; monitor if agent degrades or error-correction recovers.

## Open Questions the Paper Calls Out
### Open Question 1
How can token consumption and computational expense be reduced while maintaining feature quality? The paper explicitly notes cost as a limitation due to token-heavy reasoning. Unresolved because high costs hinder adoption; evidence would come from benchmarking cost-performance trade-offs and developing compression strategies.

### Open Question 2
To what extent does FAMOSE rely on LLM pre-trained knowledge, and can RAG improve results on specialized tasks? The paper suggests RAG might help but doesn't evaluate it. Unresolved due to lack of empirical comparison; evidence would be performance on niche datasets with and without retrieval.

### Open Question 3
Which component of the iterative loop—historical memory, validation feedback, or multi-step reasoning—drives innovation? The paper hypothesizes history is key but doesn't isolate contributions. Unresolved without ablations; evidence would require systematic removal or alteration of each component.

## Limitations
- Full system prompt and dynamic insertion logic are unspecified, risking variability in agent behavior.
- Exact implementation of the feature_evaluation tool, including error handling and hallucination correction, is not open-sourced, hindering reproducibility.
- mRMR configuration (e.g., mutual information estimation for mixed data, optimal feature count selection) lacks detail, and sensitivity is unknown.

## Confidence
- Iterative ReAct Loop Mechanism: Medium (relies on self-report; limited external validation)
- Tool-Grounded Execution: Medium-High (ablations support robustness, but tool specifics opaque)
- mRMR Decoupling Advantage: Medium (ablation evidence, but no direct comparison to LLM selection)
