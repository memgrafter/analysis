# Voices of the Mountains: Deep Learning-Based Vocal Error Detection System for Kurdish Maqams

## Quick Facts
- **ArXiv ID:** 2602.20744
- **Source URL:** https://arxiv.org/abs/2602.20744
- **Reference count:** 2
- **Primary result:** Overall detection F1=0.311 (recall 39.4%, precision 25.8%); type-specific F1: fine pitch 0.492, rhythm 0.536, modal drift 0.133.

## Executive Summary
This paper introduces a deep learning system for detecting vocal errors in Kurdish maqam singing, specifically the Bayati‑Kurd mode. The work responds to the inadequacy of Western‑based automatic singing assessment for microtonal traditions. The proposed model is a two‑headed CNN‑BiLSTM with attention that operates on log‑mel spectrograms, performing both error detection and type classification (fine pitch, rhythm, modal drift).  
Trained on 50 songs (15 199 windows, 221 annotated errors), the model yields modest overall detection performance (F1=0.311) with good identification of fine pitch (F1=0.492) and rhythm (F1=0.536) errors, but fails to reliably detect modal drift (F1=0.133, recall 8%). The findings highlight that with sufficient data, automatic assessment can handle common error types, while rare, subtle deviations like modal drift remain challenging due to extreme class imbalance and possibly insufficient architectural modeling. The study also notes limitations such as single‑expert annotation and lack of validation across other maqams.

## Method Summary
The authors collected 50 Kurdish vocal performances in the Bayati‑Kurd maqam, each annotated by an expert for errors. Audio was resampled to 22.05 kHz, converted to mono, peak‑normalized, and divided into overlapping windows (3 s and 10 s) with augmentation to increase diversity. Features were extracted as log‑mel spectrograms (1024 FFT, 512 hop, 128 mel bins) and standardized.  
The model architecture comprises a four‑block CNN (3×3 conv, batch norm, ReLU, 2×2 max pooling) that maps the spectrogram to a spatial‑temporal feature sequence. These feed into a two‑layer bidirectional LSTM (256 units per direction, dropout 0.3) to capture longer context. An attention pooling layer (MLP with Tanh and dropout) computes weighted sums to produce a 512‑dimensional context vector per window. Two task‑specific heads attach to this shared representation: a detection head (dropout, linear, sigmoid) predicts whether the window contains any error, and a type classification head (linear, ReLU, dropout, linear, softmax) predicts one of three error types (fine pitch, rhythm, modal drift).  
Training used weighted binary cross‑entropy for detection, focal loss (γ=2.0) with class α‑weights (modal drift α=5.0) for classification, and weighted sampling to mitigate severe class imbalance (796 error windows: 537 fine pitch, 212 rhythm, 47 modal drift). Optimization employed Adam with a scheduled learning rate.

## Key Results
- Full‑song evaluation: detection recall 39.4%, precision 25.8%, F1=0.311.
- Type classification on detected errors: fine pitch F1=0.492, rhythm F1=0.536, modal drift F1=0.133.
- Modal drift recall is extremely low (8.0%), indicating the model rarely detects this rare error type.

## Why This Works (Mechanism)

### Mechanism 1: Multi‑Task Shared Representation Learning
- **Claim:** A shared CNN‑BiLSTM backbone with two output heads improves efficiency and allows inter‑task knowledge transfer between error detection and error classification.
- **Mechanism:** The CNN extracts local spectro‑temporal patterns (e.g., pitch bends, rhythmic instability), the BiLSTM models longer phrased context (important for modal stability), and the attention mechanism weights informative time steps. The single backbone generates a 512‑dimensional context vector used by both the detection head (sigmoid) and the type‑classification head (softmax).
- **Core assumption:** Features useful for detecting *that* an error exists are also useful for determining *what type* of error it is, despite the different label distributions.
- **Evidence anchors:**  
  - Abstract: “We developed a two‑headed CNN–BiLSTM with attention mode to decide whether a window contains an error and to classify it based on the chosen errors.”  
  - Section 3: Details the shared architecture up to the attention layer before branching.  
  - Corpus: The training set has 796 error windows but only 47 modal drift windows; the shared representation must generalize from abundant (fine pitch, rhythm) to rare (modal drift) examples.
- **Break condition:** Severe class imbalance, especially with ultra‑rare classes like modal drift (5.9% of training errors), causes the shared representation to be dominated by majority‑class patterns. The model learns to detect “error‑like” spectro‑temporal phenomena but fails to differentiate the subtle, context‑dependent cues for modal drift, as evidenced by its 8.0% recall.

### Mechanism 2: Log‑Mel Spectrogram as Primary Input Representation
- **Claim:** Log‑mel spectrograms provide a perceptually motivated, lower‑dimensional representation that preserves microtonal pitch variations and rhythmic transients crucial for maqam error detection, outperforming raw audio or standard 12‑TET pitch contours.
- **Mechanism:** The mel scale approximates human frequency resolution, compressing high frequencies. The log amplitude mimics loudness perception. Together, they create an image‑like input where microtonal inflections (quarter‑tones) and rhythmic displacements appear as localized spectral patterns rather than being quantized away.
- **Core assumption:** Patterns of deviation from a “clean” Bayati‑Kurd performance—whether pitch fluctuation, timing offset, or modal contour shift—manifest as distinct textural changes in the log‑mel time‑frequency plane that a CNN can learn.
- **Evidence anchors:**  
  - Section 3: “Audio is converted to log‑mel spectrograms (1024 FFT, 512 hop, 128 mel bins)… The model uses sliding windows…”  
  - Section 2.2: References prior work (Yeşiler et al., 2018) showing microtonal pitch representations outperform 12‑tone quantization for makam recognition.  
  - Corpus: Weak direct evidence; the paper does not compare against alternative inputs (e.g., CQT, raw waveform). This is an **assumption** based on standard MIR practice and cited literature.
- **Break condition:** If the microtonal deviations or modal drift signatures are too subtle or diffuse in the spectrogram (e.g., very slow pitch drift), they may be smoothed out by the mel filterbank and windowing, making them indistinguishable from noise or normal expressive vibrato. This likely contributes to the poor modal drift recall.

### Mechanism 3: Class Imbalance Mitigation via Loss Engineering and Sampling
- **Claim:** A combination of weighted sampling, focal loss for classification, and class/α‑weights (αmodal drift = 5.0) partially counteracts the 6:1.8:1 error‑type imbalance, preventing the model from ignoring minority classes entirely.
- **Mechanism:** Focal loss (γ=2.0) down‑weights easy examples and focuses learning on hard, misclassified ones. Weighted sampling ensures each batch sees a roughly balanced number of error windows. The α‑weight increases the loss contribution from the rare modal drift class.
- **Core assumption:** The model’s default behavior under standard cross‑entropy would be to learn a “predict fine pitch” heuristic for >95% of error windows, yielding zero recall for rare classes.
- **Evidence anchors:**  
  - Section 3: Explicitly lists “weighted binary cross‑entropy for detection, focal loss (γ= 2.0) for type… class and α‑weights (αmodal drift = 5.0)”.  
  - Section 4.4: Notes “Type prediction was more accurate than detection throughout” and “modal drift stayed low with high variance, matching class sizes (537, 212, 47).”  
  - Corpus: Strong evidence from Table 5: modal drift is only 5.9% of training errors.
- **Break condition:** The techniques are insufficient when the minority class has **extremely few examples** (47 modal drift windows) spanning very few songs (only 8 songs contain modal drift). The model cannot learn a robust representation for a class with such low prior probability and high intra‑class variability. This is directly evidenced by the 8.0% modal drift recall and the fact that only 5 of 25 true modal drift events were detected.

## Foundational Learning

### Concept: Microtonal/Maqam Pitch Theory
- **Why needed here:** The system’s purpose is to replace/augment human teachers who judge adherence to Bayati‑Kurd modal intervals (e.g., neutral seconds, three‑quarter tones), not Western 12‑TET. Understanding *what* constitutes a “fine pitch error” vs. an acceptable ornament requires domain knowledge.
- **Quick check:** What is the primary acoustic difference between a correctly performed “pitch bend” in Bayati‑Kurd and a “fine pitch error” in the same context?

### Concept: Multi‑Task Learning in Deep Learning
- **Why needed here:** The architecture shares a backbone for two related but distinct problems: binary detection (error vs. clean) and multi‑class classification (error type). This impacts gradient flow, representation learning, and loss weighting.
- **Quick check:** If the detection head performs poorly (F1=0.216) while the classification head performs better on detected windows (macro‑F1=0.387), what does this suggest about the shared representation vs. task‑specific heads?

### Concept: Handling Extreme Class Imbalance
- **Why needed here:** The dataset has a 12:1 ratio between the most common (fine pitch) and rarest (modal drift) error types. Standard training would produce a model that never predicts the rare class.
- **Quick check:** How does focal loss (γ=2.0) modify the standard cross‑entropy loss to focus on hard/rare examples? What is a potential pitfall of setting γ too high?

## Architecture Onboarding

### Component Map
Resampled Audio -> Windowing -> Log‑Mel Spectrogram -> CNN -> BiLSTM -> Attention -> [Detection Head, Type Head]

### Critical Path
Windowed Log‑Mel Spectrogram → CNN → BiLSTM → Attention → [Detection Sigmoid, Type Softmax]. The attention‑weighted vector must encode sufficient information for both binary and multi‑class decisions.

### Design Tradeoffs
- **Shared vs. Separate Backbones:** A shared backbone reduces parameters and forces joint learning but can bias representation towards majority tasks (fine pitch). Separate backbones for rare classes would require more data.
- **Window Length (3s vs. 10s):** 3s windows capture fine details but less phrase context (needed for modal drift). 10s windows provide context but may dilute local error signals.
- **Attention vs. Simple Pooling:** Attention focuses on informative frames (e.g., the exact moment of a pitch error) but may struggle if the error signal is very diffuse (as in modal drift). Mean/max pooling might retain more subtle, spread‑out cues.

### Failure Signatures
- High false positive rate on expressive singing: Model misinterprets legitimate maqam ornaments (e.g., *tahrir*, pitch slides) as fine pitch errors.
- Very low recall for modal drift (8.0%): Model fails to detect slow, cumulative pitch deviations from the modal center, often confusing them with fine pitch or rhythm.
- Confusion between fine pitch and rhythm: Confusion matrix shows 6 rhythm errors classified as fine pitch and 4 vice‑versa. Spectro‑temporally, a rushed note (rhythm) and an intonation error (pitch) can look similar.

### First 3 Experiments
1. **Ablate the attention mechanism:** Replace with global average pooling. If modal drift recall improves, it suggests attention suppresses subtle, distributed drift cues.
2. **Train with a modal‑drift‑focused data augmentation:** Apply targeted pitch‑shift/time‑stretch augmentations *only* to the 47 modal drift windows to synthetically increase their diversity and force the model to learn invariant drift features.
3. **Decouple the heads:** Freeze the CNN‑BiLSTM backbone (trained on detection) and train *only* the type classification head on a balanced subset of error windows. If classification F1 for modal drift improves, it indicates the shared representation is not modal‑drift‑discriminative and the head needs specialized training.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** What is the minimum number of annotated modal drift examples required to achieve recall >50% in Kurdish maqam error detection?
- **Basis in paper:** The authors state modal drift is severely underrepresented with only 25 examples (11.3% of errors) and recall of 8.0%, and future work aims to expand coverage to 100–150 examples. The class imbalance directly limits model learning.
- **Why unresolved:** The paper lacks an ablation study measuring recall as a function of modal drift sample size. Without this, it is unclear whether simply adding more data will suffice or if architectural changes are needed.
- **What evidence would resolve it:** Systematically varying the number of modal drift samples in training (e.g., via oversampling, synthetic data, or new collections) and plotting recall against sample count to identify a saturation point or diminishing returns.

### Open Question 2
- **Question:** Do rhythm‑aware and pitch‑aware feature enhancements (e.g., beat‑synchronized analysis, pitch contour smoothness metrics) reduce the confusion between fine pitch and rhythm error classification?
- **Basis in paper:** The confusion matrix shows significant misclassification (6 rhythm→fine pitch, 4 fine pitch→rhythm). The authors suggest including such features in future work to minimize this confusion.
- **Why unresolved:** The current model uses generic log‑mel spectrograms without explicit rhythmic or pitch‑derivative features. It is unknown whether these modifications would disentangle the spectro‑temporal patterns of the two error types.
- **What evidence would resolve it:** An ablation experiment comparing the baseline CNN‑BiLSTM against variants augmented with rhythm‑specific (e.g., onset strength, tempo estimates) or pitch‑specific (e.g., vibrato rate, pitch deviation curvature) inputs, measuring changes in the fine‑pitch/rhythm confusion matrix.

### Open Question 3
- **Question:** How well does a model trained solely on Bayati‑Kurd generalize to other Kurdish maqams (e.g., Hijaz, Sega) without retraining?
- **Basis in paper:** The study focuses exclusively on Bayati‑Kurd, and future work mentions “porting the pipeline to more maqams.” The generalizability across maqams, which have distinct microtonal intervals and melodic rules, is an open question.
- **Why unresolved:** No cross‑maqam evaluation is presented. Differences in modal structure and ornamentation may cause domain shift, but the extent is unknown.
- **What evidence would resolve it:** Evaluate the trained Bayati‑Kurd model on a small, annotated dataset of another maqam (e.g., Hijaz) without adaptation, reporting detection/classification metrics. A significant drop would indicate poor generalization, motivating few‑shot transfer learning experiments.

### Open Question 4
- **Question:** Is the fixed detection threshold of 0.750 optimal across all singers and songs, or does optimal threshold vary with vocal timbre, recording quality, or error density?
- **Basis in paper:** The threshold was selected via validation macro‑F1 search (0.30–0.90) and applied uniformly to the full‑song evaluation. Singer contributions are uneven (1–6 songs each), and false positives/negatives may be singer‑specific.
- **Why unresolved:** The paper does not analyze threshold sensitivity per singer or correlate performance with singer/recording variables. A single threshold may not balance precision/recall for diverse voices.
- **What evidence would resolve it:** Compute per‑song detection metrics across a range of thresholds and analyze variance. Cluster songs by singer or acoustic properties (e.g., pitch range, SNR) to determine if threshold tuning per cluster improves overall F1.

## Limitations
- Modal drift failure is primarily attributed to data scarcity (47 windows), but the paper does not rule out architectural or representational mismatches; the model may be incapable of capturing slow, cumulative pitch deviations regardless of data volume.
- External validity is unknown: performance on other Kurdish maqams, different singers, or varied recording conditions is unestablished.
- The “error” labels rely on a single expert annotator; inter‑annotator agreement for subtle distinctions (e.g., expressive *tahrir* vs. fine pitch error) is not reported, introducing potential label noise.

## Confidence
- **High:** The reported metrics (recall 39.4%, precision 25.8%, F1=0.311) and class‑specific breakdowns are directly from the paper’s evaluation tables.
- **Medium:** The assertion that the shared CNN‑BiLSTM backbone enables inter‑task knowledge transfer is plausible architecture design, but negative transfer to the rare modal drift class is not formally measured (e.g., via separate single‑task baselines).
- **Low:** The claim that log‑mel spectrograms are optimal for microtonal maqam representation is an assumption based on prior work for *makam* recognition; no ablative comparison (e.g., vs. CQT, raw waveform) is provided for this specific error detection task.

## Next Checks
1. Ablate the attention mechanism: replace with global average pooling and measure modal drift recall.
2. Conduct targeted data augmentation for modal drift: apply subtle, slow pitch‑shift and time‑stretch transforms only to the 47 modal drift training windows, retrain, and measure change in modal drift recall.
3. Separate‑head transfer learning: freeze the CNN‑BiLSTM backbone trained on detection, train only a new balanced type‑classification head, and assess if modal drift classification improves.
