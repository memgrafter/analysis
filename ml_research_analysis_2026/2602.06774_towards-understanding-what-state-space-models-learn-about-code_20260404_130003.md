# Towards Understanding What State Space Models Learn About Code

## Quick Facts
* arXiv ID: 2602.06774
* Source URL: https://arxiv.org/abs/2602.06774
* Reference count: 40
* Pretrained CodeSSM captures code syntax and semantics better than RoCoder, but fine-tuning for type inference degrades long-range understanding; targeted architectural changes recover and boost performance across tasks.

## Executive Summary
This paper presents the first systematic analysis of State Space Models (SSMs) for code understanding, comparing the SSM-based CodeSSM against the Transformer-based RoCoder. Using a classifier-free probing method (DirectProbe) and a novel spectral kernel analysis framework (SSM-Interpret), it reveals that pretrained CodeSSM layers with complementary forward/backward filter types (one high-pass, one low-pass) encode the richest syntactic and semantic properties. However, fine-tuning on a short-range task (type inference) induces a spectral shift in early layers toward high-frequency kernels, harming long-range relation capture. Guided by these insights, the authors propose architectural modifications—adding a high-frequency CNN path and increasing kernel diversity—which mitigate the shift and yield significant gains on code retrieval and type inference benchmarks.

## Method Summary
The study employs two core analytical tools. First, **DirectProbe** evaluates hidden representations without training a probe, using agglomerative clustering on token-pair embeddings to assess separability for code-specific relations (AST sibling, distance, DFG edge). Second, the novel **SSM-Interpret** framework classifies SSM convolution kernels by their frequency response: it computes the Fourier transform of each kernel, then uses spectral centroid and Low-to-High Frequency Energy Ratio (LHFR) to label filters as low-pass, band-pass, or high-pass. These tools are applied to compare pretrained and fine-tuned variants of CodeSSM (SSM-based) and RoCoder (Transformer-based). The analysis identifies a problematic spectral shift during fine-tuning and informs two architectural interventions—CodeSSM-HF (adds a parallel CNN path) and CodeSSM-8kernel (increases SSM kernel count)—which are then evaluated on downstream tasks (NLCodeSearch, SQA, type inference).

## Key Results
* Pretrained CodeSSM encodes code syntax and semantics more effectively than RoCoder, as shown by higher DirectProbe accuracy across layers and tasks.
* Fine-tuning CodeSSM on type inference causes a spectral shift: early-layer kernels become high-pass, and forward/backward kernels lose complementary filter types, correlating with degraded long-range relation capture.
* Architectural modifications inspired by the analysis significantly improve performance: NLCodeSearch +5.5 MRR, Long Context Retrieval +3.49 MRR, and type inference +1.28 F1.

## Why This Works (Mechanism)

### Mechanism 1: Complementary Filter Behavior Enables Rich Context Capture
Layers where forward and backward kernels have complementary frequency responses (one high-pass, one low-pass) capture more code properties. Their element-wise multiplication in the time domain yields a composite frequency response that spans both short- and long-range dependencies, leading to higher DirectProbe accuracy on syntactic and semantic tasks. This complementarity is lost when both kernels adopt the same filter type.

*Evidence anchors:* Abstract; Section 4.2 and Figure 5a (filter classification vs. probing accuracy).

### Mechanism 2: Spectral Shift During Fine-Tuning Degrades Long-Range Understanding
Fine-tuning on a short-range task (type inference) drives early-layer SSM kernels toward high-pass filters. When both forward and backward kernels become high-pass, their combined output suppresses low frequencies, biasing the model toward local patterns and harming performance on long-distance relations (e.g., AST distance >5).

*Evidence anchors:* Abstract; Section 4.2 and Figure 5c (filter shift); Figure 4 (accuracy drop for long distances).

### Mechanism 3: Architectural Modifications Mitigate Spectral Shift and Improve Performance
Adding a CNN path (CodeSSM-HF) explicitly handles local context, reducing pressure on SSM kernels to become high-pass. Increasing kernel diversity (CodeSSM-8kernel) allows the layer to cover multiple frequency bands simultaneously. Both interventions preserve complementary filter patterns and multi-crested spectra, leading to better representation quality and downstream task gains.

*Evidence anchors:* Abstract; Section 5 and Table 1 (performance gains); Section 5.2 and Figures 5d, 6 (improved kernel spectra).

## Foundational Learning

- **Concept: State Space Models (SSMs)**
  - **Why needed here:** SSMs are the core architecture studied; understanding their continuous-time formulation, discretization, and convolution-kernel equivalence is essential for the frequency-domain analysis.
  - **Quick check question:** How is the SSM layer's convolution kernel derived from the state matrix A and input matrix B, and what does this imply about its inductive bias?

- **Concept: DirectProbe (Classifier-Free Probing)**
  - **Why needed here:** DirectProbe provides a purer assessment of what representations are inherently encoded, without the inductive biases of a trained probe, enabling fair comparison between CodeSSM and RoCoder.
  - **Quick check question:** What is the core algorithmic step in DirectProbe that avoids training a classifier, and why does this matter for comparative model analysis?

- **Concept: Frequency-Domain Kernel Analysis (SSM-Interpret)**
  - **Why needed here:** SSM-Interpret links model parameters to functional behavior by classifying kernels as low-pass, band-pass, or high-pass based on spectral statistics, revealing the range of dependencies each layer captures.
  - **Quick check question:** How do spectral centroid and LHFR thresholds discriminate between filter types, and what does each category signify about the model's receptive field?

## Architecture Onboarding

- **Component map:**
  CodeSSM Encoder -> (Forward SSM Kernel * Backward SSM Kernel) -> [Probing via DirectProbe] / [Kernel analysis via SSM-Interpret]
  CodeSSM-HF: Parallel CNN path (kernel size 3) added to SSM block
  CodeSSM-8kernel: 8 SSM kernels per layer instead of 2

- **Critical path:**
  1. Pretrain CodeSSM and RoCoder on Wikipedia + StarCoder code.
  2. Fine-tune each on SQA and type inference tasks.
  3. Extract layer-wise token representations for probing datasets; run DirectProbe for AST sibling, distance, DFG edge.
  4. Extract SSM forward/backward kernels; compute Fourier spectra; classify filter types using spectral centroid and LHFR.
  5. Correlate filter types (complementary vs. same) with DirectProbe accuracy across layers.
  6. Identify spectral shift in early layers of fine-tuned CodeSSM-typeinf.
  7. Design and train CodeSSM-HF and CodeSSM-8kernel under same regime.
  8. Evaluate all models on NLCodeSearch, SQA, and type inference; re-run kernel analysis on new variants.

- **Design tradeoffs:**
  - Efficiency vs. expressiveness: SSMs offer linear complexity but limited frequency diversity per layer; adding kernels or CNN paths improves coverage at modest parameter cost.
  - Kernel diversity vs. cancellation: More kernels increase frequency band coverage but risk out-of-phase cancellations when forward/backward outputs are multiplied (e.g., 1024-kernel variant).
  - Inductive bias injection: CNN path explicitly encodes local patterns, reducing need for SSM kernels to become high-pass, but introduces separate trainable parameters.

- **Failure signatures:**
  - Representational degradation: Drop in DirectProbe accuracy for long-distance AST relations (≥5) after fine-tuning, especially in early layers.
  - Spectral homogenization: Early-layer kernels shift to high-pass, and forward/backward filters become identical (loss of complementarity).
  - Downstream regression: Lower performance on global-context tasks (e.g., type inference) despite maintained local task performance.
  - Kernel anomalies: Excessive kernel count yields spectra with alternating crests/troughs, indicating out-of-phase components that may cancel.

- **First 3 experiments:**
  1. Run DirectProbe on CodeSSM and RoCoder (pretrained and fine-tuned) across all 12 layers for AST sibling, distance, and DFG edge tasks; plot accuracy vs. layer and distance.
  2. Apply SSM-Interpret to CodeSSM variants: extract kernels, compute Fourier transforms, classify using spectral centroid and LHFR; correlate filter types with probing accuracy.
  3. Train CodeSSM-HF and CodeSSM-8kernel; evaluate on NLCodeSearch, SQA, and type inference; re-run kernel analysis to confirm mitigation of spectral shift.

## Open Questions the Paper Calls Out
- How can SSM-Interpret's spectral classification thresholds be generalized to diverse SSM architectures?
- What causes the spectral shift toward high frequencies during fine-tuning, and can training adjustments prevent it?
- Do CodeSSM's spectral behavior and the benefits of high-frequency paths generalize to other SSMs and domains?

## Limitations
* Reproducibility is hindered by unreleased model checkpoints and probing code.
* Probing datasets are derived from a single code corpus, limiting generalizability across languages or paradigms.
* Causal claims about kernel spectra rely on correlations; the 1024-kernel ablation shows diminishing returns, indicating complex interactions.

## Next Checks
1. **Task-range controlled fine-tuning**: Fine-tune CodeSSM on purely local (e.g., token prediction) vs. long-range (e.g., method generation) tasks; use SSM-Interpret to track spectral shifts and link to DirectProbe changes for long-distance relations.
2. **Spectral-constrained kernel diversity**: Train CodeSSM with multiple kernels but enforce fixed spectral centroid bands via regularization; measure DirectProbe performance to isolate the effect of frequency coverage from kernel count.
3. **Cross-domain kernel analysis**: Apply SSM-Interpret to SSMs (e.g., Mamba, S4) trained on diverse domains (other programming languages, natural language) to test whether identified patterns and degradation phenomena are code-specific or universal.
