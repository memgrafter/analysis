# Feynman: Knowledge-Infused Diagramming Agent for Scalable Visual Designs

## Quick Facts
- **arXiv ID:** 2603.12597
- **Source URL:** https://arxiv.org/abs/2603.12597
- **Reference count:** 40
- **Primary result:** Synthesized 106,930 well-aligned diagram-caption pairs from 10,693 unique programs at a cost under $400 and curated the Diagramma benchmark with 1,059 multiple-choice questions.

## Executive Summary
Feynman is an LLM agent that addresses the need for scalable, high-quality diagram-caption pairs to improve multi-modal AI systems. It decouples knowledge elicitation from visual production by first enumerating domain-specific ideas, then planning and translating them into Penrose declarative programs, and finally refining them iteratively via a panel of MLLM judges. At a cost of less than $400, Feynman produced 106,930 well-aligned diagram-caption pairs from 10,693 unique programs and released the Diagramma benchmark (1,059 MCQs). Evaluation of 17 MLLMs on Diagramma showed that even the best model (Claude-3.5-Sonnet) achieved only 59.64% accuracy, revealing persistent challenges in diagram reasoning.

## Method Summary
Feynman’s pipeline consists of four steps: (1) Knowledge Planning – an LLM enumerates abstract “ideas” for a domain; (2) Code Planning – the LLM devises a plan mapping these ideas to Penrose Substance elements; (3) Iterative Visual Refinement – the LLM generates Substance code, Penrose compiles it into diagram variations, and a panel of MLLM judges scores and provides feedback for revisions; (4) Rendering – Penrose’s optimization-based layout solver produces diverse diagrams. Captions and multiple-choice QA are then generated from the final Substance. The approach leverages Penrose’s declarative formalism to separate conceptual structure from visual styling and uses randomness in layout solving to ensure visual diversity while preserving semantics.

## Key Results
- Generated 106,930 well-aligned diagram-caption pairs from 10,693 unique Penrose programs at a cost of less than $400 using GPT-4o-mini.
- Achieved an 82.5% final yield rate in ablation studies.
- Curated the Diagramma benchmark with 1,059 multiple-choice questions; the best-performing MLLM (Claude-3.5-Sonnet) scored 59.64% overall accuracy.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Decoupling knowledge elicitation from visual production enables scalable generation of semantically rich diagrams.
- **Mechanism:** Feynman first uses an LLM to enumerate domain-specific “ideas” (knowledge components) in an abstract, text-based form. These ideas are then translated into Penrose Substance code, which declaratively specifies conceptual elements (nodes, edges) and their relationships without low-level visual details. The Style code and Penrose’s optimizer then map this abstract Substance to concrete geometry, handling layout automatically.
- **Core assumption:** LLMs can reliably enumerate core conceptual knowledge for a domain, and this knowledge can be faithfully captured in a simple, declarative formalism (Substance) separate from visual styling.
- **Evidence anchors:** 
  - [abstract] “…decouples knowledge elicitation from visual production by first enumerating domain-specific ideas, then planning and translating them into Penrose declarative programs…”
  - [section 2.2] “We leverage this large capacity of knowledge of LLM by designing domain-specific prompts to ask an LLM to enumerate pieces of knowledge (‘ideas’)…”
  - [section 2.1] “Substance contains no low-level visual details, it is simpler and easier to generate correctly.”
- **Break condition:** If the LLM fails to enumerate diverse or correct conceptual “ideas” for a domain, the downstream visual generation lacks meaningful content, regardless of rendering quality.

### Mechanism 2
- **Claim:** Iterative refinement using a panel of vision-language model (MLLM) judges improves diagram correctness and alignment, compensating for code-generation errors in a single shot.
- **Mechanism:** After an initial Substance program is generated and compiled, Penrose produces diagram variations. These images are sent to multiple MLLM judges that score them against criteria (e.g., correct representation, legible text). An aggregated score and textual feedback loop back to the coding agent, which attempts to revise its Substance code. This cycle repeats until a quality threshold is met or a round limit is hit.
- **Core assumption:** MLLMs can act as reliable “visual critics” for diagram-quality aspects (conceptual fidelity, clarity) that are hard to specify in code, and their feedback can be used by the coding LLM to improve the Substance program.
- **Evidence anchors:**
  - [abstract] “…with iterative refinement via a panel of visual judges.”
  - [section 2.4] “In the first round, Feynman receives the plans from the previous planning steps and attempts to generate the first code sample. If the code is successfully compiled into a diagram, then Feynman run Penrose to generate variations of this diagram and send them to a panel of visual judges to assess its quality.”
  - [algorithm 1] Explicit loop showing compilation → judging → feedback → retry.
- **Break condition:** If the judge panel consistently rejects diagrams (scores below threshold) across many rounds, indicating either irreparable Substance code or a mismatch between the judge’s criteria and the intended diagram semantics, the process times out.

### Mechanism 3
- **Claim:** Penrose’s optimization-based rendering engine injects controlled randomness during layout solving, producing visually diverse diagrams from identical Substance code while preserving conceptual semantics.
- **Mechanism:** The geometric constraints and objectives defined by Style code define a space of valid layouts where random initialization yields distinct but semantically equivalent diagrams. This diversity is valuable for training and evaluating MLLMs.
- **Core assumption:** The space of valid layouts defined by Style constraints is sufficiently large and the optimizer converges reliably from random seeds, yielding diverse but semantically equivalent diagrams.
- **Evidence anchors:**
  - [abstract] “The optimization-based rendering of Penrose preserves the visual semantics while injecting fresh randomness into the layout, thereby producing diagrams with visual consistency and diversity.”
  - [section 2.1] “Penrose samples from this space when rendering a diagram, providing Feynman the ability to produce many different examples even from just one set of concepts (Fig. 6).”
  - [figure 6] Shows diverse layouts (e.g., Cayley graphs, Sierpinski triangles) from the same Substance.
- **Break condition:** If the Style constraints are under-specified or the optimizer fails to converge for certain Substance inputs, the rendered diagrams may become degenerate (overlapping elements) or lose intended semantics.

## Foundational Learning
- **Concept: Conceptual Diagramming (Penrose `Substance`/`Style`)**  
  - **Why needed here:** This is the core representation that decouples knowledge from visuals. Understanding how to encode domain concepts (Substance) and visual rules (Style) is essential to leverage Feynman’s pipeline.  
  - **Quick check question:** Given a domain (e.g., “graph algorithms”), what would a simple Substance program for a node with two outgoing edges look like, and what Style rules might enforce edge routing?

- **Concept: LLM as Knowledge Elicitor & Coder**  
  - **Why needed here:** The pipeline’s scalability hinges on using LLMs for two distinct, prompt-engineered tasks: (1) creative knowledge enumeration, and (2) code generation (Substance + planning). Understanding prompt design for these roles is critical.  
  - **Quick check question:** What are the key differences in the prompt structure for the “Idea” step (knowledge enumeration) versus the “Code Planning” step (translating an idea to Substance syntax)?

- **Concept: Iterative Visual Refinement with MLLM Judges**  
  - **Why needed here:** This is the quality control loop. Understanding how to set up judge criteria, parse feedback, and decide on early-stopping thresholds is necessary to balance cost and quality.  
  - **Quick check question:** If the judge panel gives contradictory feedback (e.g., one says “text is illegible,” another says “fine”), how should the aggregated feedback message to the agent be constructed?

## Architecture Onboarding
**Component map:** Idea Generator → Code Planner → Coder & Refiner → Penrose Engine → Judge Panel → Deduplicator → Caption & QA Generator (with feedback from Judge Panel to Coder & Refiner)

**Critical path:** Idea → Code Plan → Initial Code → Compile → Judge → (if score < θ) Feedback → back to Coder → else Accept → Caption/QA

**Design tradeoffs:**  
- Cost vs. Scale: Using GPT-4o-mini for coding keeps costs low ($400 for 100k pairs) but may reduce initial code quality, increasing needed refinement rounds.  
- Generality vs. Control: Shared Style/Domain code simplifies generation but limits stylistic variation per domain; varying these per Substance is future work.  
- Judge Reliability: Using multiple MLLMs averages out individual biases but increases API cost and latency.

**Failure signatures:**  
- Parsing Failure: LLM output cannot be parsed into Substance code (skip round).  
- Compilation Failure: Penrose optimizer cannot satisfy constraints; error traceback fed back.  
- Judge Rejection: Persistently low scores (<θ) on criteria like “Correct Representation” or “Legible Text” after N_max rounds; indicates fundamental flaw in Substance encoding.

**First 3 experiments:**  
1. **End-to-End Single Sample:** Run Idea → Accept for one simple domain (e.g., “Lewis structures”). Verify output Substance compiles, judges score >80%, and caption is accurate. Debug prompt chains.  
2. **Scaling Curves:** For 2–3 domains (one “knowledge-dense” like chemical reactions, one “knowledge-sparse” like “complementary triangles”), plot number of final Substance programs vs. cumulative input/output tokens. Expect linear vs. decaying trends per Section 4.2.  
3. **Ablation of Planning Steps:** Disable Idea step (KP off) and/or Code Plan step (CP off) on a fixed token budget. Measure impact on (a) final yield rate, (b) average judge score, (c) average rounds to acceptance (per Table 3). Expect KP+CP+S combination to yield highest quality.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can Feynman integrate external knowledge sources (e.g., via RAG) to overcome LLM knowledge gaps in specialized domains?  
  - *Basis:* The limitations section explicitly states reliance on implicit LLM knowledge reduces effectiveness in domains with incomplete/biases knowledge, and suggests integrating a RAG pipeline as future work.  
  - *Why unresolved:* Current knowledge planning depends solely on LLM internal knowledge; no mechanism exists to supplement with authoritative external sources, limiting diagram accuracy in niche or evolving domains.  
  - *What evidence would resolve it:* A comparative study implementing RAG in the knowledge planning step, measuring improvements in diagram correctness and knowledge diversity across domains where LLMs are known to be weak (e.g., recent scientific findings).

- **Open Question 2:** Can Penrose’s Style and Domain systems be systematically extended to allow programmable, user-controllable aesthetic parameters (e.g., color palettes, layout constraints)?  
  - *Basis:* The future work section explicitly states a focus on “systematically varying Style and Domain programs in PENROSE” to enable flexible and customizable diagram generation.  
  - *Why unresolved:* Current style variation is limited to Penrose’s default optimization; users cannot directly specify stylistic attributes, hindering applications requiring brand consistency or specific visual themes.  
  - *What evidence would resolve it:* An extended Penrose API with parametric style controls, validated via user studies comparing aesthetic satisfaction and task-specific suitability against default-generated diagrams.

- **Open Question 3:** What underlying factors (e.g., LLM domain knowledge density, diagram complexity) explain the differing scaling behaviors (linear vs. decaying) observed across domains in Feynman’s production-to-scale analysis?  
  - *Basis:* Section 4.2 observes two distinct scaling trends and attributes them to “(1) the base model’s knowledge within the specific domain, and (2) the scalability of the domain for diagramming,” but provides no quantitative analysis or controlled experiments.  
  - *Why unresolved:* The attribution remains speculative; the interplay between LLM knowledge, domain entropy, and Penrose’s expressiveness is not isolated or measured, preventing predictive scaling models.  
  - *What evidence would resolve it:* A controlled study correlating LLM performance on domain-specific knowledge probes with token efficiency and yield rates, while systematically varying diagram complexity within and across domains.

- **Open Question 4:** Does the use of MLLMs with known deficiencies in diagram reasoning (as shown on Diagramma) as visual judges introduce systematic biases that degrade Feynman’s iterative refinement?  
  - *Basis:* Section 2.4 uses a panel of MLLM judges (GPT-4o-mini, Claude, Gemini), yet Section 3.2 and Table 2 show these models achieve at most 59.64% on Diagramma, indicating poor diagram reasoning. Their feedback may therefore be unreliable.  
  - *Why unresolved:* No analysis of judge consistency, agreement with human judgments, or correlation between judge scores and final diagram correctness; risks a feedback loop amplifying judge-specific failures.  
  - *What evidence would resolve it:* An ablation study using different judge pools (including high-performing models and humans), measuring agreement rates and final yield/quality metrics to isolate judge impact.

- **Open Question 5:** Can training multi-modal LLMs on Feynman’s synthetic dataset (106k diagram-caption pairs) improve their performance on diagram reasoning benchmarks like Diagramma?  
  - *Basis:* The paper releases the dataset and benchmark but only evaluates existing MLLMs; no experiments are conducted to test whether the synthetic data can *train* better models, leaving its utility for model improvement unknown.  
  - *Why unresolved:* Synthetic data may suffer from distribution shift, subtle errors, or lack of challenge diversity, potentially failing to transfer to real-world reasoning; this is a critical gap for data-centric AI progress.  
  - *What evidence would resolve it:* Pre-training or fine-tuning experiments with state-of-the-art MLLMs on the Feynman dataset, followed by rigorous evaluation on Diagramma and out-of-distribution diagram benchmarks to measure gains and failure modes.

## Limitations
- Hyperparameter opacity: Exact deduplication thresholds, judge aggregation, and round limits are unspecified, hindering exact replication.
- Judge prompt incompleteness: Missing full templates for diagram_intent and past_questions_prompt may cause variability in QA diversity and scoring consistency.
- Domain instruction gaps: The complete domain-specific Code Planning prompts and examples are not provided, limiting reproducibility across all 38 domains.

## Confidence
- Scalability & cost claim: **High**
- Mechanism validity (decoupling + iterative refinement): **Medium**
- Diagramma benchmark results: **High**
