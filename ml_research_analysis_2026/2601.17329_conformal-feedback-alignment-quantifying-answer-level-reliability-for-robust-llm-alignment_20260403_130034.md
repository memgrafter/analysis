# Conformal Feedback Alignment: Quantifying Answer-Level Reliability for Robust LLM Alignment
## Quick Facts
- **arXiv ID:** 2601.17329  
- **Source URL:** https://arxiv.org/abs/2601.17329  
- **Reference count:** 22  
- **Primary result:** On Llama2-7B with Summarize, CFA-DPO achieves an overall score of 67.30 vs. base DPO 65.68 (+1.62), outperforming standard uncertainty-aware baselines.

## Executive Summary
Conformal Feedback Alignment (CFA) tackles noisy preference labels in RLHF/DPO by shifting focus from preference-level to answer-level reliability. It uses Conformal Prediction to assign each generated answer a reliability score via prediction sets with guaranteed coverage. These scores are aggregated into a per-pair weight that modulates the alignment loss (DPO or PPO), prioritizing training on comparisons built from reliable answers. Experiments across datasets and models show consistent improvements in robustness and data efficiency.

## Method Summary
CFA operates in four stages:

1. **Supervised Fine-Tuning (SFT):** The pre-trained model is fine-tuned on the target dataset to produce a reference policy π_ref.

2. **Preference Data Generation:** For each prompt, multiple responses (e.g., 4–9) are sampled from the SFT model. An AI judge (e.g., GPT-4) is prompted to create pairwise preferences among these responses, yielding triples (x, y⁺, y⁻).

3. **Answer Reliability Scoring via Conformal Prediction:**
   - Compute a nonconformity score s(x,y) for each response.
     * **White-box variant:** s = -log π_ref(y|x) (negative log-probability under the reference policy).
     * **Black-box variant:** s = λ₁·(1 - frequency) + λ₂·entropy + λ₃·(1 - similarity). Here frequency is the fraction of sampled responses matching y, entropy measures diversity among samples, and similarity compares y to a high-quality reference (e.g., using ROUGE). *Unknown:* exact values of λ₁,λ₂,λ₃ and the similarity metric.
   - Using a held-out calibration set of 100 prompts, determine quantile thresholds q_{α₁} and q_{α₂} for chosen coverage levels (e.g., α₁=0.5, α₂=0.8). Answers with s ≤ q_{α₁} form the high‑confidence set A_high; those with s ≤ q_{α₂} form the lower‑confidence set A_low (A_high ⊆ A_low). The coverage guarantee ensures that for new data, a correct answer falls in A_low with probability ≥1−α₂.

4. **Weight Computation and Training:**
   - For each preference pair (y⁺, y⁻), check membership in A_high and A_low.
   - Define weight u as:
     - u = q_{α₁} if y⁺ ∈ A_high and y⁻ ∈ A_high,
     - u = q_{α₂} if y⁺ ∈ A_low and y⁻ ∈ A_low,
     - u = (q_{α₁} + q_{α₂})/2 otherwise (i.e., answers in different sets). *Assumption:* linear averaging appropriately reflects joint reliability.
   - Train with uncertainty‑weighted alignment:
     * **CFA‑DPO:** Loss = -E_{(x,y⁺,y⁻)}[ u · log σ( β·(log π_θ(y⁺|x)/π_ref(y⁺|x) - log π_θ(y⁻|x)/π_ref(y⁻|x)) ].
     * **CFA‑PPO:** First train a reward model with weighted binary cross‑entropy, then optimize π_θ via PPO with reward shaping scaled by u.
   - The reference policy π_ref remains fixed; reliability scores do not change during training.

## Key Results
- CFA‑DPO on Llama2‑7B/Summarize: Overall score 67.30 vs. base DPO 65.68 (+1.62).
- Consistent gains across Summarize, WebGPT, and Pairwise datasets with Llama2‑7B, Llama3.1‑8B, and Qwen2.5‑7B.
- Outperforms preference‑level uncertainty methods (WPO, IW‑DPO) in ablation, demonstrating the benefit of answer‑level weighting.
- Scalability analysis shows CFA maintains or improves relative gains on smaller models (e.g., Qwen3 0.6B) and limited data regimes (5%–20% of Summarize), indicating robust data efficiency.

## Why This Works (Mechanism)

### Mechanism 1: Answer‑Level Reliability via Conformal Prediction
**Claim:** Conformal Prediction provides a distribution‑free, statistically valid measure of answer‑level reliability by constructing prediction sets with user‑defined coverage guarantees.
**How:** For each answer (x, y), a nonconformity score s(x,y) is computed. Using a calibration set, quantile thresholds q_{α} are determined for chosen coverage levels (e.g., α₁=0.5, α₂=0.8). Answers with s ≤ q_{α} belong to the corresponding set, indicating they are “typical” and thus more reliable. The coverage guarantee ensures that for new data, a correct answer falls in the set with probability ≥1−α.
**Core assumption:** The nonconformity score correlates with semantic/quality reliability, and the calibration set is representative.
**Evidence anchors:** Abstract mentions constructing CP sets; Section 3.2 details scoring functions and coverage guarantee.
**Break condition:** Non‑representative or too‑small calibration set invalidates coverage and makes set membership misleading.

### Mechanism 2: Set‑Wise Uncertainty Aggregation
**Claim:** A deterministic aggregation function translates the membership of the preferred (y⁺) and dispreferred (y⁻) answers in the two CP sets into a single weight u for the preference pair.
**How:** Define sets A_high (high‑confidence, low nonconformity) and A_low (lower‑confidence). For a pair, if both answers are in A_high, u = q_{α₁}; if both in A_low, u = q_{α₂}; if they split, u = (q_{α₁}+q_{α₂})/2. This assumes the trustworthiness of a comparison depends on the reliability regimes of the individual answers.
**Core assumption:** Preference judgment reliability is a function of the individual answer reliabilities, not an independent property of the pair.
**Evidence anchors:** Section 4.2 gives Equation 7; abstract mentions aggregating reliabilities into weights.
**Break condition:** If the relationship between set membership and true quality is highly nonlinear, or two low‑reliability answers in the same set still yield noisy preferences, the linear aggregation may fail.

### Mechanism 3: Uncertainty‑Weighted Alignment Loss
**Claim:** Multiplying the DPO or PPO loss by the answer‑derived weight u re‑weights gradients, causing the model to prioritize learning from preference comparisons built on reliable answers and down‑weight noisy ones.
**How:** The standard loss is scaled by u: DPO loss becomes −E[u·logσ(β·Δθ,ref)]; for PPO, the reward model pref. loss and policy loss are similarly weighted. This treats preferences as soft evidence, damping gradients from low‑u (unreliable) pairs.
**Core assumption:** Noisy preferences primarily originate from low‑quality individual answers; filtering such pairs yields a cleaner learning signal.
**Evidence anchors:** Section 4.3 shows weighted loss equations; Section 5.4 ablation shows CFA beats preference‑level UQ methods (WPO, IW‑DPO).
**Break condition:** If dominant noise is in the preference label itself (e.g., evaluator inconsistency), answer‑level weighting may miss the primary failure mode.

## Architecture Onboarding
**Component map:** Calibration Data → CP Scorer (white/black‑box) → Set Membership & Aggregator → Alignment Trainer → Policy Model (π_θ). The CP Scorer uses the fixed reference policy π_ref to compute nonconformity scores; scores do not change during alignment training.

**Critical path:**
1. Calibrate CP thresholds (q_{α₁}, q_{α₂}) on a held‑out set of 100 prompts.
2. For each training preference pair (x, y⁺, y⁻), compute s(x,y⁺) and s(x,y⁻) using π_ref and the chosen CP variant.
3. Determine membership of y⁺ and y⁻ in A_high and A_low.
4. Compute weight u based on membership (high‑confidence both → q_{α₁}; low‑confidence both → q_{α₂}; split → average).
5. Perform a gradient update using the u‑weighted alignment loss (CFA‑DPO or CFA‑PPO).
6. Periodically re‑calibrate if data distribution shifts (e.g., after full epoch) to maintain coverage guarantees.

**Design tradeoffs:**
- White‑box CP (log‑probs) is precise/cheap but requires model access; black‑box (sampling) works for APIs but is heavier/noisier; black‑box needs hyperparameters λ₁,λ₂,λ₃ and N samples.
- Coverage levels (α₁, α₂): lower α gives higher coverage but includes less reliable answers; higher α yields stricter high‑confidence set. Heuristic α₁=0.5, α₂=0.8 balances between reliability and pair filtering.
- Weight aggregation: linear averaging in the split case is simple/interpretable but may not capture the full uncertainty; alternatives (min, product) unexplored.

**Failure signatures:**
- **Poor calibration:** Small calibration set (100) yields unstable thresholds. Diagnostic: empirical coverage of A_low on validation should approximate 1−α₂; large deviation indicates mis‑calibration.
- **Overly dominant split pairs:** If u distribution heavily peaks at (q_{α₁}+q_{α₂})/2, the CP sets are not discriminating; consider adjusting α or improving nonconformity score (e.g., increase N for black‑box).
- **No gain over DPO:** May indicate noise is preference‑level rather than answer‑level, or reference policy is already high‑quality. Compare against preference‑level UQ baselines (WPO, IW‑DPO) to confirm.
- **Distribution shift:** When test prompts differ from calibration, coverage guarantees may not hold; monitor performance and re‑calibrate as needed.

**First 3 experiments (as outlined in the paper):**
1. **Baseline Comparison (RQ1):** Train CFA‑DPO/CFA‑PPO on Summarize, WebGPT, Pairwise with Llama2‑7B, Llama3.1‑8B, Qwen2.5‑7B. Evaluate via LLM‑as‑a‑judge; expect consistent improvement over base DPO/PPO and SFT.
2. **Scalability Analysis (RQ2):** Vary model size (Qwen3 series 0.6B–8B) and data size (5%–100% of Summarize). CFA should maintain/grow relative improvement, especially on smaller models/data.
3. **Ablation against Preference‑Level UQ (RQ3):** Compare CFA to WPO and IW‑DPO on Llama2‑7B/Summarize. Also compare white‑box vs. black‑box CP to show potential gains from better scoring.

## Open Questions the Paper Calls Out
- **Multimodal extension:** How can CFA be extended to vision‑language models with image/video feedback? (Conclusion suggests this as future work).
- **Hybrid uncertainty:** Can answer‑level reliability be combined with preference‑level uncertainty (e.g., ensemble variance) into a unified weighting scheme, and would this outperform either alone? (Limitations note they are not combined in current work).
- **Adaptive coverage selection:** How should α be selected adaptively for a dataset/model rather than using fixed values? (Sensitivity analysis shows “sweet points” (0.7–0.8) but selection remains heuristic).
- **Human‑in‑the‑loop calibration:** Can human confidence annotations improve CP reliability when AI feedback is biased or OOD? (Conclusion suggests this as future work).

## Limitations
- Missing black‑box CP hyperparameters (λ₁, λ₂, λ₃) and exact similarity metric; these critically affect reliability scores and reproducibility.
- No details on preference pair creation (prompt sampling, judge prompt), hindering exact replication.
- Fixed 100‑prompt calibration set may be too small and non‑robust to distribution shift; no analysis of calibration size sensitivity.
- The choice of coverage levels (α₁, α₂) is heuristic (typically 0.5/0.8) and not adaptive; performance may vary with dataset noise characteristics.
- The aggregation function u (Eq. 7) is a simple heuristic; its optimality is not justified and alternative formulations could perform better.

## Confidence
- CFA outperforms base DPO by +1.62 on Summarize: **Medium** (limited datasets; reproduction may vary with unknown hyperparameters).
- CP yields answer‑level reliability: **Medium** (theoretical guarantee; empirical correlation with answer quality not shown).
- Aggregation function u (Eq. 7) is effective: **Low** (novel heuristic, no prior validation; could be suboptimal).
