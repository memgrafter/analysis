# From Decoupled to Coupled: Robustness Verification for Learning-based Keypoint Detection with Joint Specifications

## Quick Facts
- arXiv ID: 2603.05604
- Source URL: https://arxiv.org/abs/2603.05604
- Reference count: 22
- Primary result: Proposed first coupled robustness verification for heatmap-based keypoint detectors, achieving significantly higher verified rates than decoupled baseline (e.g., 90.7% vs 0% at α=0.1 with 4 non-overlapping perturbations).

## Executive Summary
The paper presents a formal verification framework for heatmap-based keypoint detectors that accounts for joint deviations across all keypoints. It formulates robustness as a falsification problem using a mixed-integer linear program (MILP) that combines reachable heatmap sets (approximated as zonotopes) with a polytope output specification derived from downstream task requirements. This coupled approach captures interdependencies that decoupled per-keypoint verifications overlook, yielding stronger robustness certificates. Evaluated on pose estimation with 23 keypoints on an airplane dataset, the method achieves a 90.7% verified rate under strict error thresholds (α=0.1) with four local occlusions, while a decoupled baseline fails completely (0%). The framework uses pruning to reduce MILP size by orders of magnitude, though a gap between formal verification and empirical robustness remains, primarily due to over-approximation in reachability analysis.

## Method Summary
Given a seed image and a set of perturbations, the input module constructs the convex hull of perturbed images as the input set. The backbone network's reachable set of heatmap outputs is over-approximated by a zonotope, which is a linear combination of a center and generators with bounded coefficients. The allowable keypoint errors are encoded as a convex polytope (linear inequalities) based on task-specific thresholds (e.g., pose tolerance). The verification MILP decides whether any heatmap in the zonotope can lead to keypoints outside the polytope. It includes continuous variables for zonotope coefficients, deviation vector δv, binary selectors for the argmax operation (which maps heatmaps to coordinates), and an indicator for specification violation. Dynamic indexing constraints link the selected heatmap pixel to its value and enforce that it exceeds all in-bound values for the same heatmap. Pruning removes pixel indices that are guaranteed not to affect feasibility based on zonotope bounds, drastically cutting the number of binary variables. Infeasibility of the MILP provides a sound robustness certificate for the entire input set.

## Key Results
- Coupled verification achieves 90.7% verified rate for non-overlapping local occlusions at α=0.1 with 4 perturbations, compared to 0% for a decoupled baseline.
- Pruning reduces the MILP size by approximately three orders of magnitude for non-overlapping perturbations, enabling tractable solving.
- Verification time increases with the number of perturbations and decreases with stricter output thresholds; however, a gap persists between formally verified and empirically observed robustness due to reachable set conservatism.

## Why This Works (Mechanism)
### Mechanism 1: Coupled output specification via polytope
The method models allowable keypoint deviations as a convex polytope P_v δv ≤ b_v, capturing task-level interdependencies and allowing error compensation if tolerated by the downstream task. The core assumption is that the task's robustness requirements can be expressed as a convex polytope in joint error space—true for many geometric tasks with linearized error propagation. Evidence includes the abstract's claim of bounding joint deviations and Section 4's definition of δV. The decoupled baseline's independent per-keypoint bounds illustrates the improvement. This mechanism fails if the task's requirements are non-convex or cannot be tightly approximated by a polytope, leading to over-approximation and weaker certificates.

### Mechanism 2: Reachable heatmap set via zonotope over-approximation
The backbone network's heatmap outputs for all inputs in the convex set X are over-approximated as a zonotope Z = C + Σ α_k G_k with α_k ∈ [-1,1]. This convex representation maintains linearity, enabling sound integration into the MILP. The assumption is that network nonlinearities (e.g., ReLU) can be abstracted using standard zonotope operations, which is typical for ReLU networks. The paper states this in Section 5 and the abstract. Zonotopes are compact but may become overly conservative for deep networks, especially with many ReLUs, resulting in false negatives (i.e., failing to certify a robust model). Over-approximation magnitude is the break condition.

### Mechanism 3: MILP falsification with dynamic indexing and pruning
The verification reduces to an MILP that encodes (i) zonotope membership, (ii) polytope violation via binary r, and (iii) existence of a keypoint whose argmax heatmap value exceeds all in-bound values. Dynamic indexing uses binary variables Δ to select the pixel corresponding to candidate location (v*+δv) and adds maximality constraints (the selected heatmap value is greater than all others). Pruning eliminates dominated pixel indices based on zonotope bounds, reducing binary variables dramatically. The core assumption is that argmax can be encoded linearly and that pruning does not discard necessary indices; the latter holds if the dominance test using zonotope bounds is sound. Evidence appears in Section 5.2–5.3 and the abstract. Failures include over-pruning (causing false infeasibility) or MILP blowup without pruning.

## Architecture Onboarding
Input module → Backbone (F_b) → Reachability analyzer → Polytope spec → Pruner → MILP builder → MILP solver

### Critical path
1. Compute reachable zonotope Z = C + Σ α_k G_k for backbone heatmaps over input set X.
2. For each keypoint, generate candidate out-of-bound error regions (δv outside polytope δV but within image) and corresponding pixel sets S_out.
3. Apply pruning to S_out and the complementary in-bound set S_in to eliminate dominated indices using zonotope bounds.
4. Build MILP: include zonotope membership (Eq. 3), polytope violation (Eqs. 5), dynamic indexing constraints (6)-(8), and maximality condition (9).
5. Solve MILP; infeasibility certifies robustness, feasibility yields a counterexample.
6. Aggregate results over seeds and perturbation settings to compute verified rates.

### Design tradeoffs
- Zonotope tightness vs. size: Tighter polyhedra reduce conservativeness but increase computational overhead.
- Pruning aggressiveness: More pruning yields smaller MILPs but risks false infeasibility if dominance checks are unsafe.
- MILP argmax encoding: Binary per-pixel-per-keypoint scales as O(HW·K); pruning is essential for high-resolution outputs.
- Coupled vs. decoupled: Coupled captures joint requirements but increases MILP complexity; decoupled is simpler but often overly conservative.

### Failure signatures
- Solver timeout/memory exhaustion: Likely due to large heatmap resolution or many keypoints with insufficient pruning.
- Low verified rate vs. empirical robustness: Suggests over-approximation in reachable set or polytope; check zonotope tightness and linearization quality.
- Infeasible MILP despite known counterexample: Possible over-pruning; disable pruning to diagnose.
- High variance in verification time: Expect nondeterminism; use fixed solver settings and seeds.

### First 3 experiments
1. Synthetic sanity check: Implement a tiny network (e.g., one conv + ReLU) and manually compute its reachable zonotope. Use the MILP to verify robustness on the scenarios from Appendix A; expect infeasibility in the first (robust) case and feasibility in the second (non-robust) case.
2. Decoupled vs. coupled replication: On the airplane pose dataset, run both verification methods under identical conditions (α=0.1, m=4, non-overlapping occlusions). Confirm the large gap (e.g., ~90% vs 0%) reported in the paper.
3. Pruning impact study: For a fixed seed and perturbation setting, compare MILP size (variables, constraints) and verification time with pruning enabled vs. disabled. Expect >1000× reduction for non-overlapping perturbations and consistent feasibility results.

## Open Questions the Paper Calls Out
### Open Question 1
Question: How can the gap between formally verified robustness and empirical robustness be narrowed, given that it is largely caused by conservativeness in reachable set over-approximations?
Basis in paper: The authors state: "A limitation of the current framework is that, under strict output specifications, there remains a noticeable gap between the verified robustness rates and the empirical robustness observed through testing-based evaluation. This gap stems from the conservativeness of reachable set over-approximations."
Why unresolved: Over-approximation using zonotopes may be too coarse; tightening it is non-trivial without sacrificing soundness or efficiency.
What evidence would resolve it: Demonstration of alternative reachable set representations (e.g., zonotope refinements, polyhedral abstractions) that significantly reduce the gap on standard benchmarks, with quantitative comparison showing verified rates approaching empirical rates.

### Open Question 2
Question: Can the coupled verification framework scale to keypoint detectors with hundreds of keypoints and modern architectures (e.g., transformers) while maintaining soundness and tractable verification times?
Basis in paper: The authors indicate future work will "extend the applicability of the proposed method to larger and more complex keypoint detection networks."
Why unresolved: The MILP size grows with keypoint count; scaling may cause combinatorial explosion in binary variables and constraints, making verification intractable.
What evidence would resolve it: Successful verification of models with ≥100 keypoints on a representative dataset, reporting solver runtimes within practical bounds (e.g., minutes), possibly aided by advanced MILP solving or problem-specific decompositions.

### Open Question 3
Question: Why does pruning reduce MILP size by about three orders of magnitude for non-overlapping local perturbations but only about two orders for overlapping ones? What structural differences in the reachable sets explain this?
Basis in paper: The paper reports: "pruning reduces the problem size by approximately three orders of magnitude for non-overlapping images, but only by about two orders for overlapping ones." However, no explanation is given.
Why unresolved: Understanding this could lead to better pruning heuristics and insights into the nature of semantic perturbations.
What evidence would resolve it: Analysis of the pre- and post-pruning index sets for both perturbation types, including distributions of heatmap values, correlations among keys, and metrics of redundancy; perhaps also sensitivity to generator magnitudes and overlap ratios.

### Open Question 4
Question: What causes the observed decrease in verification time with stricter output error bounds (lower α) in the non-overlapping setting?
Basis in paper: The authors note that "verification time ... decreases with stricter thresholds" and Table 3 shows lower average times at α=0.1 vs α=1.0 for non-overlapping cases. No explanation is provided.
Why unresolved: The trend is counterintuitive because stricter bounds should reduce the allowable output set, potentially making the feasibility check harder; understanding it would improve solver tuning.
What evidence would resolve it: Empirical data on solver behavior (feasibility ratio, number of branch-and-bound nodes) across α, coupled with analysis of how the output polytope δV changes and how this affects the size of the pruned search space.

## Limitations
- Over-approximation in zonotope reachability creates a persistent gap between verified and empirical robustness, especially for deep networks.
- Pruning relies on sound dominance checks; overly aggressive pruning based on loose bounds can lead to false infeasibility, incorrectly rejecting robustness certificates.
- Reproduction requires exact model architecture, pretrained weights, dataset occlusion definitions, and pose-to-keypoint linearization, which are not provided, hindering independent validation.
