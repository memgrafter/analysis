# Semantic Search over 9 Million Mathematical Theorems

## Quick Facts
- **arXiv ID:** 2602.05216
- **Source URL:** https://arxiv.org/abs/2602.05216
- **Reference count:** 40
- **Primary result:** A semantic search system using LLM-generated natural-language slogans and dense retrieval achieves 45.0% Hit@20 at the theorem level on 111 expert queries, far exceeding generative AI and web search baselines.

## Executive Summary
Finding exact mathematical theorems in large digital libraries is difficult because existing tools return entire papers rather than specific statements. This work builds a corpus of 9.2 million theorems from arXiv and seven other sources. Each theorem is converted into a concise English "slogan" using an LLM to avoid raw LaTeX, which is then embedded with Qwen3-Embedding (8B) and indexed with HNSW for fast similarity search. On queries from professional mathematicians, the system retrieves the correct theorem within top-20 results 45.0% of the time and the correct paper 56.8% of the time, dramatically outperforming ChatGPT, Gemini, Google Search, and arXiv's own search. The authors release the dataset, search tool, and API.

## Method Summary
The pipeline begins with robust LaTeX parsing: a three-stage process using plasTeX, TeX logging, and regex fallbacks to extract theorem bodies and metadata, applying filters to remove fragments and expand basic macros. Next, an LLM (DeepSeek V3) generates a short English slogan for each theorem; prompts vary by including just the theorem body or the body plus additional context like the paper's introduction. These slogans are embedded using Qwen3-Embedding-8B with a specific instruction template. For storage, PostgreSQL with pgvector holds the vectors; an HNSW graph index is built on binary-quantized embeddings (sign function) for a fast first-stage Hamming distance search. At query time, the user's question is embedded identically, an initial candidate set is retrieved via HNSW, and the top results are reranked using full-precision cosine similarity (optionally boosted by citation counts). The system handles short queries by duplicating them and supports filters by arXiv category or author.

## Key Results
- **Theorem-level Hit@20:** 45.0% on 111 professional mathematician queries.
- **Paper-level Hit@20:** 56.8%, substantially higher due to multiple theorems per paper.
- **Ablation:** Including the paper's introduction in the slogan generation prompt yields the best retrieval (Hit@1 0.368 vs. 0.316 for body-only).
- **Baseline comparison:** Outperforms ChatGPT 5.2 (19.8%), Gemini 3 Pro (27.0%), Google Search (37.8% paper-only), and arXiv search (2.7%).
- **Efficiency:** End-to-end latency ~3 seconds over the 9.2M theorem corpus.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Representing theorems as natural-language slogans improves retrieval compared to raw LaTeX.
- **Mechanism:** An LLM converts each theorem into concise English, avoiding symbolic notation; this keeps the embedding model in its natural-language domain.
- **Core assumption:** Embedding models capture semantic similarity better in natural language than in LaTeX strings.
- **Evidence anchors:** [abstract] states slogan representation outperforms raw LaTeX; [Section 3.3] details slogan generation; [corpus] all 9.2M theorems have slogans.

### Mechanism 2
- **Claim:** Including additional paper context (introduction) in the slogan prompt yields higher-quality slogans and better retrieval.
- **Mechanism:** The prompt extends to include the theorem body plus the first section; the LLM uses this broader framing to produce a more precise summary.
- **Core assumption:** The introduction often states the theorem's contribution and assumptions, helping disambiguate.
- **Evidence anchors:** [Section 4.5.1] ablation shows body+introduction (Hit@1 0.368) beats body-only (0.342) and body+abstract (0.316); [Table 3] compares context windows.

### Mechanism 3
- **Claim:** HNSW indexing with binary quantization enables interactive latency (~3 s) across 9 M+ theorem vectors.
- **Mechanism:** Embeddings are stored with an HNSW graph index on binary-quantized vectors; Hamming distance retrieves candidates fast, which are then reranked by cosine similarity.
- **Core assumption:** HNSW provides logarithmic search with high recall; binary quantization preserves enough signal for first-stage retrieval.
- **Evidence anchors:** [Section 3.4] describes the retrieval pipeline; [Section 5] reports ~3 s latency vs. 60+ s for LLM baselines; [corpus] scale (9.2 M) necessitates efficient indexing.

## Architecture Onboarding
- **Component map**  
  Ingestion -> Slogan layer -> Embedding layer -> Storage -> Retrieval -> Services  
  - Ingestion: plasTeX/TeX‑logging/regex parsers → theorem bodies + metadata.  
  - Slogan layer: LLM API (DeepSeek V3) with prompts (body vs. body+context).  
  - Embedding layer: Qwen3‑Embedding‑8B (or alternatives) → 4096‑d vectors.  
  - Storage: PostgreSQL + pgvector; HNSW index on binary‑quantized vectors; raw slogans and LaTeX stored alongside.  
  - Retrieval: Query embedding → HNSW (Hamming) → metadata filter → cosine rerank → results.  
  - Services: REST API, MCP server, HuggingFace UI; feedback collection.

- **Critical path** (query → result)  
  1. User query reaches API.  
  2. Query embedded using same model.  
  3. HNSW search retrieves candidate set (200–800).  
  4. Candidate pool filtered by arXiv tag, author, etc. (optional).  
  5. Reranking by cosine similarity (or composite score with citations).  
  6. JSON response with theorem slogan, rendered LaTeX, source URL.  
  7. Total end‑to‑end latency ≈3 s.

- **Design tradeoffs**  
  - Embedding model size: larger → better recall but slower and costlier; smaller → faster but lower Hit@20.  
  - Quantization: binary reduces memory and speeds Hamming search but may lose subtle distinctions; compensated by larger candidate pool.  
  - Slogan context: including introduction improves quality (Table 3) but raises LLM token cost; body‑only reduces cost.  
  - Reranking: cross‑encoder improves Hit@1 (Sec. 4.4) at extra compute; sometimes omitted for throughput.  
  - Index maintenance: offline embedding means lag for new papers; batch updates vs. stream processing trade‑off.

- **Failure signatures**  
  - Sudden drop in Hit@20 for specific arXiv categories → parsing errors or slogan degradation.  
  - High fraction of results from few papers → ranking diversity issue (observed with ChatGPT/Gemini).  
  - Latency spikes >5 s → HNSW parameters (ef_search) too high or rerank pool too large.  
  - User feedback (thumbs down) clusters on certain query patterns → slogan generation may need prompt revision.  
  - Missing theorems due to parsing heuristics → monitor counts of filtered theorems (e.g., <8 chars).

- **First 3 experiments**  
  1. **Reproduce validation**: Load default index (Qwen3‑8B, body+introduction), run 111 queries, compute Hit@20/MRR. Expect ~45% theorem‑level.  
  2. **Context ablation**: Compare body‑only vs. body+introduction slogans on a held‑out sample; measure delta to confirm context benefit (Section 4.5.1).  
  3. **Embedder comparison**: Swap in Gemma‑0.3B or multilingual‑E5; re‑embed and re‑index; evaluate performance and latency to see trade‑offs (Table 2, Table 8).

## Open Questions the Paper Calls Out
### Open Question 1
How can semantic representations of mathematical theorems be improved beyond natural-language slogans to better capture formal mathematical relationships and precise symbolic content?  
*Basis:* Authors state semantic understanding remains an open challenge (Sec. 2) and that slogans lose formal structure. *Why unresolved:* Slogans lose notation critical for mathematical meaning. *Evidence needed:* Compare hybrid representations (slogan-LaTeX, formal languages, graphs) on same evaluation set, especially for heavy notation.

### Open Question 2
What is the optimal context (e.g., abstract, introduction, full paper) for generating high-quality theorem slogans, and how does this interact with theorem type (e.g., lemma vs. theorem) or mathematical domain?  
*Basis:* Ablation (Sec. 4.5.1) shows introduction helps, but study limited to algebraic geometry and few authors. *Why unresolved:* Optimal context may vary by theorem complexity, field conventions, or centrality. *Evidence needed:* Large-scale experiments varying context length across stratified theorem types and arXiv categories, evaluating slogan quality intrinsically and extrinsically.

### Open Question 3
How well does the system generalize to queries from non-expert mathematicians or from underrepresented mathematical subfields not well-covered in the validation set?  
*Basis:* Validation set (111 queries) curated by professionals across 12 of 32 arXiv math tags, weighted toward algebraic geometry, analysis, PDEs. *Why unresolved:* Real users include students and researchers in niche areas; performance may drop for fields with different terminology or theorem density. *Evidence needed:* User studies with diverse pools (graduate students, less-represented tags) analyzing success by expertise and category.

### Open Question 4
Can hybrid retrieval approaches combining dense vector search with sparse methods (e.g., BM25) or symbolic formula matching improve theorem-level search at scale?  
*Basis:* System uses only dense retrieval; no sparse method evaluated. Related work mentions formula-level retrieval (NTCIR, ARQMath) but not integrated. *Why unresolved:* Sparse methods may better handle exact terms/notations; hybrid could leverage both. *Evidence needed:* Implement and compare pure dense, pure sparse (BM25 on slogans/LaTeX), and hybrid pipelines (dense first-stage + sparse rerank) on same query set.

### Open Question 5
How can theorem parsing accuracy and coverage be improved to reduce fragmentation and malformed extractions, given the limitations of current LaTeX parsers?  
*Basis:* Datasheet (A.4, A.7) notes some statement bodies, titles, labels may be fragmented due to parsing methods not handling all LaTeX styles. *Why unresolved:* Parsing errors lead to missing/invalid theorems, reducing recall; fallback strategies are brittle for complex macros. *Evidence needed:* Develop a more robust parser (e.g., ML to detect theorem environments) and evaluate precision/recall on held-out papers with diverse packages, measuring impact on corpus size and retrieval quality.

## Limitations
- **Evaluation reproducibility blocked:** The 111 expert queries and 7,356-paper test set are unreleased, preventing exact verification of reported metrics.
- **Implementation details underspecified:** Binary HNSW search parameters (m, ef_construction, ef_search) and exact Hamming operator customizations are not provided, hindering replication of ~3 s latency claim.
- **Parsing and slogan generation heuristics:** Macro expansion scope, "first section" extraction logic, and prompt nuances are vague, risking coverage/quality variance across sources.

## Confidence
- **Slogan representation improves retrieval:** High. Ablations (Table 3) show significant gains; mechanism aligns with embedding model strengths.
- **Context (introduction) enhances slogan quality:** High. Direct experimental evidence in Section 4.5.1 supports the claim.
- **HNSW+binary quantization enables interactive scale:** Medium. Approach is standard, but without exact parameters and recall benchmarks, the ~3 s latency claim is assumed.
- **Overall system performance vs. baselines:** Low. Comparisons are on unreleased queries; absence of test set prevents external validation.
