# POLAR:A Per-User Association Test in Embedding Space

## Quick Facts
- **arXiv ID**: 2603.15950
- **Source URL**: https://arxiv.org/abs/2603.15950
- **Reference count**: 22
- **Primary result**: POLAR separates bots from humans with AUROC up to 0.961 on the best single axis and maintains AUROC ~0.96 when combining axes, with Brier score ≤ 0.061.

## Executive Summary
POLAR addresses the ecological fallacy in lexical association testing by providing per-user effect sizes rather than corpus-level aggregates. It represents each user with a private deterministic token added to a pretrained masked language model. Fine‑tuning with a user‑aware masking objective and an alignment loss yields a stable user embedding in the same space as wordpieces. For any pair of lexical sets A and B, POLAR projects the user vector onto the axis defined by the centroids of those sets, producing a standardized effect size. Permutation testing under label exchangeability gives calibrated p‑values, and Benjamini–Hochberg controls the false discovery rate. On the fox8‑23 bot–human benchmark, POLAR achieves AUROC up to 0.961 and well‑calibrated scores, demonstrating strong individual‑level separation.

## Method Summary
Each user is mapped to a deterministic token (e.g., `usr3af12b9cde`) that is prepended to every post. The tokenizer vocabulary and embedding matrix of a pretrained masked LM (e.g., BERT) are expanded to include these tokens. During fine‑tuning, the standard masked LM loss is applied with a higher mask probability on the user token, and an alignment term nudges the user token embedding toward the average of the non‑user token embeddings in the same post. This produces a fixed‑length user vector summarizing the author’s style. For a lexical axis (A,B), centroids are the mean embeddings of the word lists. A user’s standardized score is (mean(cosine to A) – mean(cosine to B)) divided by the standard deviation of all cosine similarities; this equals a scaled projection onto (ā – b̄). Permutation of the A/B labels generates a null distribution for the score, from which a two‑sided p‑value is estimated. The Benjamini–Hochberg procedure applied to all users on a given axis controls the false discovery rate at a pre‑specified level.

## Key Results
- Best single axis (Scam/Finance vs Daily Life) yields AUROC 0.961 on fox8‑23.
- Combining multiple axes maintains AUROC ~0.96.
- Scores are well‑calibrated, with Brier score ≤ 0.061.

## Why This Works (Mechanism)

### Mechanism 1: User token embeddings capture style
- **Claim**: Private deterministic user tokens, fine‑tuned via masked language modeling (MLM), produce stable user embeddings that summarize an author’s linguistic style.
- **Mechanism**: Each user ID is hashed to a unique token. This token is prepended to all posts by that user. The embedding matrix of a pretrained masked LM is resized to include these tokens. During fine‑tuning, the MLM loss is applied with higher mask probability on the user token. An alignment term nudges the user token’s embedding toward the mean of the post’s non‑user token embeddings. This forces the token to capture distributional regularities across the user’s posts.
- **Core assumption**: An author’s lexical and stylistic preferences are sufficiently stable and frequent within their posting history to be compressible into a single vector via contextual aggregation.
- **Evidence anchors**: The fox8‑23 results show that these user vectors separate bots (LLM‑generated style) from humans (organic style) on multiple axes, implying the tokens captured style differences.

### Mechanism 2: Standardized projection yields interpretable scores
- **Claim**: Standardized effect sizes computed via projection onto lexical axis centroids yield interpretable, scale‑stable per‑user association scores.
- **Mechanism**: For an attribute pair (A, B), compute the mean embedding of each set (ā, b̄). For a user vector **û**, compute cosine similarities to all attribute words, then take the means for A (d_A) and B (d_B). The statistic s(u; A, B) = (mean(d_A) – mean(d_B)) / sd(d_all). This is equivalent to projecting **û** onto the axis (ā – b̄) and scaling by the pooled dispersion of similarities, making the score unitless and comparable across different attribute pairs.
- **Core assumption**: The centroid difference (ā – b̄) faithfully represents a bipolar semantic dimension, and the dispersion sd(d_all) appropriately normalizes for internal variability and set size.
- **Evidence anchors**: Axis centroids are well‑separated (cos(ā, b̄) = 0.74–0.87). Score distributions (Figures 3 and 4) show clear separation along named semantic frames, supporting interpretability.

### Mechanism 3: Permutation testing with BH control yields calibrated p‑values
- **Claim**: Permutation testing with Benjamini–Hochberg (BH) control provides calibrated per‑user p‑values and controls false discoveries across multiple users and axes.
- **Mechanism**: Under the null hypothesis of no differential association, the labels on the combined similarity vector d_all (size m+n) are exchangeable. For each user, M random permutations of these labels generate a null distribution of s(k). A two‑sided p‑value is estimated as (1 + count(|s(k)| ≥ |s_obs|)) / (1 + M). Since this test is run for every user on a given axis, the BH procedure is applied to the vector of p‑values to control the false discovery rate (FDR) at α=0.05.
- **Core assumption**: Exchangeability holds for the permuted labels (i.e., similarities to A vs. B are symmetric under random shuffling for a user with no true association). This requires that the attribute sets are pre‑defined and not derived from the user data.
- **Evidence anchors**: The paper reports well‑calibrated Brier scores and controlled FDR in the fox8‑23 experiments.

## Foundational Learning
- **Private user tokens**: Unique tokens added to the vocabulary for each user. *Why needed*: To represent an author’s cumulative style as a fixed vector in the embedding space. *Quick check*: After fine‑tuning, does the user token’s nearest neighbors in embedding space correspond to stylistic features of that user?
- **Masked language model fine‑tuning with user‑aware masking**: Adapting a pretrained LM by masking user tokens more often and adding an alignment loss. *Why needed*: To encourage the user token to absorb information from the user’s posts while retaining the LM’s general language knowledge. *Quick check*: Compare the LM’s perplexity on masked user tokens before and after fine‑tuning; it should improve.
- **Lexical axes (bipolar semantic dimensions)**: Pre‑defined sets of words representing opposing concepts (e.g., “Scam/Finance” vs “Daily Life”). *Why needed*: To define interpretable directions in embedding space for computing association scores. *Quick check*: Compute centroid difference and verify that cosine similarity between the two centroids is negative and significantly different from zero.
- **Projection‑based standardized effect size**: For a user vector **û**, compute (mean(sim to A) – mean(sim to B)) / sd(all similarities). *Why needed*: To produce a unitless, scale‑stable measure of differential association. *Quick check*: For synthetic users embedded exactly at a centroid, the score should be extreme in the expected direction; for vectors orthogonal to the axis, the score should be near zero.
- **Permutation testing with exchangeability**: Randomly permuting the labels of the A/B similarities to build a null distribution of the score. *Why needed*: To obtain calibrated p‑values without distributional assumptions. *Quick check*: Under the null (shuffle similarities), the observed score should be near the median of the null distribution.
- **Benjamini–Hochberg FDR control**: Applied to per‑user p‑values to control false discoveries across multiple tests. *Why needed*: To maintain a desired error rate when testing many users and axes. *Quick check*: In a simulation with known true nulls, the proportion of false rejections should not exceed the nominal α.

## Architecture Onboarding
**Component Map (plain text)**  
User Posts → Tokenizer (prepends deterministic user token) → Masked LM (fine‑tuned with user‑aware masking and alignment loss) → User Embedding vector → For each lexical axis (A,B): Compute Centroids (ā, b̄) → Project user onto (ā – b̄) → Compute standardized effect size s(u) → Permutation test (shuffle labels of similarities to A/B) → Two‑sided p‑value → Benjamini‑Hochberg across all tests → Output significance and score.

**Critical Path**  
1. Tokenize posts with prepended user tokens.  
2. Fine‑tune masked LM using the combined MLM + alignment objective.  
3. Extract the user token embedding for each user.  
4. For a chosen lexical axis, compute centroids and project user vectors.  
5. Calculate the standardized score.  
6. Perform permutations to obtain a p‑value.  
7. Apply BH across all users and axes.  

**Design Tradeoffs**  
- Adding a private token per user inflates the embedding matrix and requires enough posts for the token to converge; a trade‑off between personalization and memory.  
- Mask probability on user tokens: higher values force the model to infer the token from context but risk degrading overall language modeling.  
- Alignment loss weight: too strong pulls the token toward the post average, possibly erasing individuality; too weak leads to unstable embeddings.  
- Attribute word set size: larger sets give more robust centroids but may introduce irrelevant words; smaller sets are sensitive to word choice.  
- Permutation count: more permutations improve p‑value accuracy but increase computational cost.  
- Combining axes can boost detection power but sacrifices interpretability of individual dimensions.

**Failure Signatures**  
- Collapsed user embeddings (very low variance) indicating insufficient data or overly strong alignment.  
- High cosine similarity between axis centroids (e.g., >0.9), suggesting the word sets do not form a meaningful bipolar dimension.  
- Permutation p‑values clustering near zero even for shuffled null data, implying violation of exchangeability (e.g., attribute words correlated with user metadata).  
- BH false discovery rate substantially above the nominal α, often due to many correlated tests or too few permutations.  
- Missing attribute words after tokenization (OOV) leading to unreliable centroids.

**First Experiments** (exactly 3)  
1. **User embedding sanity check**: Train POLAR on a small fox8‑23 sample, visualize user embeddings with PCA/t‑SNE colored by bot/human. Expect visible separation.  
2. **Axis validity**: Choose a well‑studied semantic axis (e.g., positive vs negative sentiment). Compute POLAR scores for a dataset with ground‑truth sentiment labels (e.g., product reviews). Expect strong correlation (e.g., >0.7).  
3. **Calibration check**: Create synthetic null data by randomly shuffling attribute labels among users. Run permutation tests with M=1000. Verify that the proportion of p‑values ≤0.05 is close to 0.05 and that BH maintains FDR near 0.05 over many repetitions.

## Limitations
- Low‑activity users (<2 posts are discarded; performance for sparse users with a few posts is unknown).  
- Attribute set curation heavily influences results; robustness to word‑list variations is not evaluated.  
- Generalization: all experiments are on the fox8‑23 bot‑human benchmark; applicability to other domains, languages, or demographic attributes remains an open question.

## Confidence
- **Separation performance on fox8‑23**: High  
- **User token as a stable style summary**: Medium  
- **Interpretability via lexical axes**: Medium  
- **Generalization beyond the benchmark**: Low  
- **Causal interpretation of scores**: Low  

## Next Checks
1. **Sparse‑user robustness**: Stratify analysis by post count (2–5, 6–20, >20) and report AUROC/Brier for each stratum.  
2. **Attribute set variation**: Generate 20–50 plausible word lists for a key axis (via synonyms, WordNet, LLM) and measure variance in user rankings and AUROC.  
3. **Cross‑corpus transfer**: Apply the trained POLAR model without retraining to a different user‑level dataset with a known binary attribute (e.g., gender in the Blog Authorship Corpus) and report AUROC.
