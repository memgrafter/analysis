# Fair Feature Importance Scores via Feature Occlusion and Permutation

## Quick Facts
- **arXiv ID:** 2602.09196
- **Source URL:** https://arxiv.org/abs/2602.09196
- **Reference count:** 5
- **Primary result:** Model-agnostic fairness importance scores via permutation and occlusion detect bias correlated with protected attributes and reveal fairness‑accuracy trade‑offs.

## Executive Summary
The paper tackles the lack of model-agnostic feature importance metrics tailored for fairness, as opposed to accuracy. It proposes two approaches: a permutation-based score that measures the change in a fairness metric when a feature is randomly permuted, and an occlusion-based score that compares models trained with and without the feature. To manage the computational burden of occlusion, the authors introduce a minipatch learning approximation that trains many small models on random subsets. Synthetic experiments confirm that both metrics assign negative scores to features correlated with a protected attribute, indicating their bias‑detection capability. Real-world case studies on Adult Income and German Credit datasets identify specific biased features (e.g., “Relationship: Husband”) and highlight fairness‑accuracy trade‑offs, demonstrating practical utility and scalability.

## Method Summary
The permutation score is computed by first training a base model on the full dataset. For each feature, its values in the evaluation set are randomly shuffled, and the model’s predictions on this perturbed set are used to compute a fairness metric. The score equals the difference between the permuted and original fairness metrics; a negative value suggests the feature contributes to unfairness. The occlusion score directly estimates the feature’s causal effect on fairness by retraining the model without that feature. Because full retraining for every feature is computationally intensive, the authors employ minipatch learning: for each feature, they sample many small random subsets (minipatches) of the training data, train a model on each subset that excludes the feature, evaluate the fairness of each minipatch model on a fixed test set, and average the results to approximate the full‑data occlusion effect. This approximation dramatically reduces runtime while preserving detection accuracy.

## Key Results
- Both metrics assign negative fairness scores to features correlated with a protected attribute in synthetic simulations, validating bias detection.
- Case studies on Adult Income and German Credit datasets pinpoint biased features (e.g., “Relationship: Husband”) and illustrate fairness‑accuracy trade‑offs.
- The occlusion method’s minipatch approximation enables scalable application without sacrificing the ability to identify problematic features.

## Why This Works (Mechanism)
Permutation importance for fairness relies on the principle that randomly permuting a feature breaks any statistical association it has with the outcome and with the protected attribute. If the model uses that feature to produce disparate impacts, permuting it will degrade the fairness metric, yielding a negative score. Occlusion provides a more direct causal estimate: by removing the feature during training, we assess whether the model’s fairness depends on that feature. The minipatch learning approximation retains this causal interpretation while lowering computational cost. Training many models on small random patches averages out noise and approximates the full‑dataset retraining effect, assuming patches are representative and model training is stable.

## Foundational Learning
1. **Model-agnostic feature importance**
   - *Why needed:* To explain any black-box model without internal access, enabling fairness analysis across model types.
   - *Quick check:* Perturb a feature (e.g., by permutation) and measure the change in model predictions or fairness.

2. **Fairness metrics**
   - *Why needed:* Provide a quantitative definition of unfairness (e.g., statistical parity, equal opportunity).
   - *Quick check:* Compute the metric on model predictions split by the protected attribute.

3. **Permutation importance for fairness**
   - *Why needed:* A cheap, simple way to assess a feature’s impact on fairness by disrupting its relationship with the outcome.
   - *Quick check:* Randomly permute feature values in the test set, recompute fairness, and compare to the original.

4. **Occlusion with minipatch learning**
   - *Why needed:* Directly measures the necessity of a feature for fairness; minipatch learning reduces the cost of repeated retraining.
   - *Quick check:* For each feature, train multiple models on small random subsets that exclude the feature, average their fairness, and compare to the full model.

## Architecture Onboarding
**Component Map:**  
Data -> Base Model Training (full features) -> Model Bank  
For each feature:  
- Permutation branch: Permutation Unit -> Permuted Datasets -> Model Evaluation -> Δ Fairness Calculation  
- Occlusion branch: Minipatch Sampler -> Multiple Model Training (without feature) -> Model Evaluation -> Aggregator -> Δ Fairness Calculation  
All Δ Fairness -> Score Normalization -> Importance Scores

**Critical Path:**  
1. Train base model on the full dataset.  
2. For permutation: permute each feature in the evaluation set, run base model, compute fairness metric, record Δ.  
3. For occlusion with minipatch: for each feature, sample K minipatches; for each, train a model excluding the feature; evaluate on original test set; average fairness; compute Δ from full model.  
4. Normalize scores across features and output.

**Design Tradeoffs:**  
- *Permutation* is computationally cheap but may miss causal effects and assumes feature independence; *Occlusion* is more direct but expensive, mitigated by minipatch approximation which introduces estimation variance.  
- Minipatch size and number balance cost and accuracy: smaller patches reduce compute but increase noise.  
- Choice of fairness metric influences scores; different metrics can lead to different feature rankings.

**Failure Signatures:**  
- *Permutation:* High variance in scores across random seeds; biased features receiving near‑zero scores when model relies on proxy features.  
- *Occlusion:* Large dispersion in fairness across minipatch models; scores that diverge significantly from permutation without clear reason.  
- General: Inconsistent signs between the two methods or unstable scores when changing minipatch parameters.

**First Experiments:**  
1. Synthetic validation: Generate data with a protected attribute and a known biased feature; verify both metrics assign negative scores to that feature and near‑zero to neutral features.  
2. Real‑world bias detection on Adult Income: Apply the metrics, confirm that “Relationship: Husband” receives a negative score, and compare with domain knowledge.  
3. Scalability analysis: Measure runtime and memory usage of occlusion with and without minipatch on increasing dataset sizes; assess stability of scores across different minipatch configurations.

## Limitations
- Only two public datasets (Adult Income, German Credit) were evaluated; findings may not generalize to other domains or protected attributes.
- The minipatch approximation for occlusion may misestimate feature importance when features are highly interdependent.
- No comparison to existing fairness importance methods (e.g., fair SHAP); relative performance remains unknown.

## Confidence
- Bias detection validity: Medium  
- Scalability of occlusion (via minipatch): Medium  
- Practical utility and fairness‑accuracy trade‑offs: Low–Medium
