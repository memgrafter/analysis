# Personalized Parameter-Efficient Fine-Tuning of Foundation Models for Multimodal Recommendation

## Quick Facts
- **arXiv ID:** 2602.09445
- **Source URL:** https://arxiv.org/abs/2602.09445
- **Reference count:** 40
- **Primary result:** PerPEFT improves NDCG@20 by up to 15.3% on four e-commerce datasets while adding only 1.3% extra parameters relative to the CLIP backbone.

## Executive Summary
Multimodal recommendation systems often rely on frozen foundation models like CLIP to generate item embeddings. However, these embeddings are user-agnostic, ignoring individual preferences. PerPEFT addresses this by clustering users based on interest and assigning each cluster a dedicated parameter-efficient fine-tuning (PEFT) module. These group-specific modules adapt the foundation model to emphasize item aspects relevant to their cluster. Additionally, group-specific negative sampling forces each module to discriminate among items within its cluster’s purchase distribution. Experiments on four Amazon datasets show PerPEFT outperforms the strongest baseline by up to 15.3% in NDCG@20, gains hold across multiple PEFT backbones, and incurs minimal parameter overhead (~1.3% of CLIP).

## Method Summary
PerPEFT operates in two phases. First, a Global PEFT model (shared PEFT module, MLP projector, transductive item embeddings, and SASRec backbone) is trained on all data. Then, user predictive embeddings from SASRec are clustered (K-Means, k=8) to define interest groups. For each group, a distinct copy of the PEFT module and MLP projector is initialized from the Global PEFT parameters, while transductive embeddings and SASRec remain shared. During group-specific training, mini-batches contain users from a single group; the loss uses negative samples drawn exclusively from items purchased by that group. Only the group’s PEFT and MLP are updated alongside the shared components. At inference, users are assigned to their cluster (or nearest centroid for new users) and scored using the corresponding group’s item embeddings.

## Key Results
- Up to **15.3%** improvement in NDCG@20 over the best baseline across four e-commerce datasets.
- Consistent gains when using different PEFT methods (LoRA, (IA)³, IISAN).
- **Only ~1.3%** additional parameters compared to the frozen CLIP model.

## Why This Works (Mechanism)
**Mechanism 1: Group-specific PEFT modules**  
Assigning a dedicated PEFT module to each user cluster allows the foundation model to produce item embeddings conditioned on that cluster’s interests. Clustering (e.g., K-Means on global predictive embeddings) discovers groups; only users from a given cluster train that cluster’s module, driving it to specialize on item aspects relevant to the cluster. (Evidence: abstract; Sec 3.2.1). Core assumption: within-cluster users share similar item attributes they value. Break condition: if clusters are not interest-separated or the PEFT method lacks capacity.

**Mechanism 2: Group-specific negative sampling**  
Negatives are sampled only from items purchased by the given cluster (I^(c)). This yields harder negatives within the cluster’s item distribution, forcing the PEFT module to capture subtle distinctions among items that are relevant to that group. (Evidence: abstract; Sec 3.3.2; ablation in Sec 4.6). Break condition: cluster’s item pool is too small, making negatives too easy or causing overfitting.

**Mechanism 3: Shared transductive embeddings & SASRec backbone**  
All groups share the same transductive item embeddings (h_k) and SASRec sequence model, while only the adaptation layers (PEFT and MLP) are group-specific. This maintains parameter efficiency because the expensive multimodal adaptation is personalized but the collaborative/sequential components remain universal. (Evidence: Sec 3.2.4; parameter counts in Sec 3.4; IISAN precedent). Break condition: if sequential behavior or fundamental interaction patterns differ significantly across groups; ablation with a larger shared PEFT did not help, underscoring the need for group-specific PEFT.

## Foundational Learning
**Concept: Parameter-Efficient Fine-Tuning (PEFT)**  
*Why needed here:* PerPEFT extends PEFT to the group level; understanding how LoRA/(IA)³/IISAN modify a frozen model clarifies what part of the network is personalized.  
*Quick check:* When training a group-specific PEFT module, which parameters of the foundation model are updated, and how does this affect the item embedding computation?

**Concept: User Representation in Sequential Recommendation**  
*Why needed here:* User clustering relies on predictive embeddings from a sequential model (e.g., SASRec). Knowing how purchase history is transformed into a user vector explains the clustering input.  
*Quick check:* How does SASRec generate a user’s predictive embedding from their item sequence, and why should this reflect their interest?

**Concept: Negative Sampling in Recommendation**  
*Why needed here:* The training loss and the choice of negative items shape the PEFT module’s specialization. Group-specific negatives are a key innovation.  
*Quick check:* In the binary cross-entropy loss, what role do negative items play, and how does restricting negatives to a cluster’s purchased items change the learning signal for that cluster’s PEFT module?

## Architecture Onboarding
**Component map:**  
Frozen CLIP → Group-specific PEFT module → Group-specific MLP projector → adds Shared transductive embedding (h_k) → final item embedding (z_k^(c)). Shared SASRec processes user sequences of these embeddings. Each cluster c has its own negative sampler drawing from I^(c).

**Critical path:**  
- Offline: Train Global PEFT → compute user predictive embeddings → cluster users (K-Means, k=8) → obtain groups U^(c) and item pools I^(c).  
- Initialize PerPEFT: copy Global PEFT’s PEFT modules and MLP projectors to each cluster (C copies). Keep transductive h_k and SASRec shared.  
- Training: For each mini-batch (all users from same cluster c): compute items’ embeddings using CLIP+PEFT_c+MLP_c + h_k → feed sequences to SASRec → compute binary cross-entropy loss with negatives from I^(c) → update PEFT_c, MLP_c, h_k, and SASRec.  
- Inference: For user u in cluster c, use precomputed z_k^(c) to score items via SASRec. For new user, assign to nearest cluster centroid (using base model) and use that cluster’s embeddings.

**Design tradeoffs:**  
- Number of groups C: Larger C increases specialization but reduces per-group data; paper found C=8 optimal.  
- PEFT method choice: Must be compatible with CLIP; (IA)³ achieved best results, balancing parameter efficiency and expressiveness.  
- Shared vs. group-specific components: Sharing h_k and SASRec minimizes parameters but assumes group-agnostic collaborative/sequential dynamics; if groups differ, performance may degrade.

**Failure signatures:**  
- No improvement over Global PEFT: inspect cluster coherence (themes in item titles) and verify group-specific negative sampling is active.  
- High run-to-run variance: likely too few users per group; increase C or merge small clusters.  
- Unexpected memory/time increase: ensure batching groups by same cluster to avoid recomputing item embeddings per user; check for unnecessary duplication.

**First 3 experiments:**  
1. Cluster sanity check: For each top-sized group, list 10 most frequent words in purchased item titles; expect semantic themes (e.g., "golf", "tent").  
2. Attention divergence: For a fixed item, compute token-level attention maps using two different groups’ PEFT modules; expect distinct focus areas.  
3. Negative sampling ablation: Train PerPEFT with global negatives (full catalog) vs. group-specific negatives; observe significant performance drop for global version, confirming the design choice.

## Open Questions the Paper Calls Out
- Lack of theoretical analysis: Why does personalized PEFT improve performance? No formal bounds connect grouping to representation quality.  
- Handling missing modalities: Items may lack text or images; extending PerPEFT to modality-incomplete data remains open.  
- Modeling users with multiple interests: Hard clustering forces single-group assignment; users with cross-group interests need a more flexible approach (e.g., soft assignments).

## Limitations
- Exact hyperparameters (learning rates, weight decay, negative count, MLP architecture) are not specified; reproduction requires grid search.  
- Clustering details (random seed, PCA usage) are omitted, which can affect group assignments.  
- Procedure for assigning new/unseen users to clusters is not fully described.

## Confidence
- Mechanism 1 (group-specific PEFT): High  
- Mechanism 2 (group-specific negative sampling): Medium  
- Mechanism 3 (shared transductive embeddings & SASRec): Medium  

## Next Checks
1. Cluster coherence: Verify each cluster’s top purchased items form a coherent thematic category.
2. Attention divergence: Ensure PEFT modules produce distinct attention patterns for the same item across clusters.
3. Negative sampling ablation: Confirm removing group-specific negatives significantly harms performance, validating its necessity.
