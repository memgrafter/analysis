# The Condensate Theorem: Transformers are O(n), Not $O(n^2)$

## Quick Facts
- arXiv ID: 2602.06317  
- Source URL: https://arxiv.org/abs/2602.06317  
- Reference count: 30  
- Primary result: Trained transformers concentrate attention on a small dynamic subset; selecting three learned components (anchor, local window, dynamic top‑k) yields bit‑identical outputs to full attention, reducing complexity to O(n) and enabling >159× speedup on 131K tokens.

## Executive Summary
The quadratic bottleneck in self‑attention is not a fundamental limitation of transformer architectures. The Condensate Theorem shows that trained language models already learn to concentrate attention mass on a tiny fraction of token positions, and that by explicitly selecting only three components—the attention sink at position 0, a local window of recent tokens, and a dynamic set of top‑k positions chosen via Q·Kᵀ scores—one can compute attention that is bit‑identical to the full O(n²) operation under standard float32 arithmetic. This equivalence holds because contributions from all omitted positions fall below the unit in the last place (ULP) and are rounded away. The authors validate the approach on 12 different pretrained models, achieving 100% token‑level match on more than 1,500 generated tokens. A specialized implementation reduces asymptotic complexity to O(n) and demonstrates a measured 159× speedup at sequence lengths of 131 K tokens (3.94 ms vs 628 ms), with projections exceeding 1,200× at 1 M tokens, implying >99.9% reduction in inference cost compared to FlashAttention.

The work overturns the prevailing assumption that attention must be approximated for long contexts; instead, the necessary sparsity is already implicit in trained models and can be extracted exactly with a simple, content‑aware selection rule. This opens a path to massive context windows in production systems without sacrificing accuracy, and the technique is complementary to existing IO‑aware kernels.

## Method Summary
The Condensate method is a runtime sparsification technique applied to pretrained autoregressive transformers without any weight modification. During token generation, for each query position it constructs a Condensate Set comprising: (1) the anchor at position 0, (2) a fixed‑size local window covering the most recent W tokens, and (3) a dynamic set of k positions with the highest Q·Kᵀ scores relative to the query. Attention scores are computed only over this subset, followed by softmax and renormalization. Because trained models produce extremely peaked distributions, all excluded positions have softmax weights below the float32 ULP (~6×10⁻⁸), so omitting them does not alter the final floating‑point values. To preserve the ability to track long‑range shifts, a small number of “pillar” layers (∈ P) still perform full attention over the entire cache; these pillar outputs feed a Spike Tracker that updates a persistent set S of historically important positions, which can be added to future Condensate Sets. The KV cache may be pruned to retain only positions that have appeared in recent Condensate Sets, keeping memory usage bounded. The method therefore achieves exact equivalence to full attention under greedy decoding while reducing computational complexity from O(n²) to O(n).

## Key Results
- The quadratic bottleneck in transformer attention is not fundamental; trained models concentrate attention on a small, identifiable subset of positions (the Condensate Set).
- Selecting three components—anchor (position 0), a local window, and dynamic top‑k via Q·Kᵀ scores—yields bit‑identical outputs to full O(n²) attention under float32 because omitted contributions fall below the unit in the last place.
- Validated across 12 architectures with 100% token match on 1,500+ generated tokens; reduces complexity to O(n) and achieves a 159× measured speedup at 131 K tokens (3.94 ms vs 628 ms), with projected >1,200× at 1 M tokens and >99.9% inference cost reduction versus Flash Attention.

## Why This Works (Mechanism)
#### Mechanism 1: Contributions below float32 ULP
- **Claim:** Positions outside the Condensate Set contribute less than the float32 unit in the last place (ULP), so removing them yields bit‑identical outputs.
- **Mechanism:** Trained models push softmax weights of non‑condensate positions below ~6×10⁻⁸. In IEEE 754 float32, adding such a tiny value to a sum ≥1.0 does not change the stored result. Renormalizing over the Condensate Set therefore reproduces the exact float32 values of full softmax.
- **Core assumption:** Hardware uses IEEE 754 float32; the model’s softmax is sufficiently peaked that excluded weights are below ULP.
- **Evidence anchors:** Abstract: “excluded contributions fall below float32 precision”; Section 2.2: “Excluded positions have softmax weights <10⁻⁷. In float32 (23‑bit mantissa), adding a value <2⁻²⁴ ≈6×10⁻⁸ to a sum ≥1.0 does not change the stored result.”
- **Break condition:** Using higher precision (float64) or high‑temperature sampling that flattens the distribution can push weights above ULP, breaking exact equivalence.

#### Mechanism 2: Trained attention is inherently concentrated
- **Claim:** Gradient descent on language modeling objectives drives the attention distribution to be extremely skewed, with >95% of mass on <1% of positions at long sequences. This learned sparsity is absent in randomly initialized models.
- **Mechanism:** The optimization process favors peaked attention as an efficient way to fit data, leading to a long‑tail distribution where almost all mass lies on a small set.
- **Core assumption:** Training induces attention concentration as a byproduct of fitting data.
- **Evidence anchors:** Abstract: “trained models already learn to concentrate attention sparsity”; Section 1.1: “Trained models produce extreme concentration. Random Q,K,V produce uniform attention; trained models concentrate.”; Section 3.4: Table 1 shows 87.8% mass on 52% of positions for GPT‑2 Layer 6; Table 2 shows increasing concentration with length.
- **Break condition:** Models not trained on long contexts or tasks requiring diffuse attention may not exhibit such concentration.

#### Mechanism 3: Condensate Set captures all significant contributions
- **Claim:** The Condensate Set (anchor + local window + dynamic top‑k) can be identified per query using Q·Kᵀ scores, and attending only to these positions yields full‑attention equivalence.
- **Mechanism:** For a query, compute dot products with cached keys. Positions with highest scores (plus the fixed anchor and local window) capture essentially all information because other positions have negligible scores. This selection is dynamic and content‑dependent.
- **Core assumption:** Q·Kᵀ scores reliably indicate which positions contribute significantly to the output.
- **Evidence anchors:** Abstract: “dynamically computed top‑k positions via Q·Kᵀ scores”; Section 1.1: “The Q·Kᵀ scores—which must be computed anyway—directly encode which positions matter.”; Section 2.1: Definition of Condensate Set; Section 3.6: Single‑needle retrieval tests show dynamic top‑k finds remote needles.
- **Break condition:** High‑temperature sampling flattens the softmax distribution, potentially including many positions above ULP; a fixed top‑k budget may then miss important tails.

## Architecture Onboarding
**Component map:**  
Prefill Phase -> Initialize KV Cache (full attention)  
Decode Loop (per generated token):  
  Layer Stack (for each of L layers):  
    Projections (q,k,v) -> RoPE (rotary encoding) -> Condensate Selector ( Anchor (pos 0) + Local Window (last W tokens) + Dynamic Top‑k (highest q·k scores) ) -> Attention (full softmax if layer ∈ P else sparse over Condensate Set) -> (if pillar layer) Spike Tracker (update persistent set S) -> Update KV Cache  
  Output Logits -> Next token  
KV Cache Manager: optionally prune keys/values to retain only positions that have appeared in recent Condensate Sets  

**Critical path:** In sparse layers, cost is dominated by computing q·k for the candidate set (size ≈ |C|) and softmax over |C|. In pillar layers, the full q·Kᵀ (O(n)) dominates. Overall per‑token latency is the sum across layers.

**Design tradeoffs:**  
- Window size W: Larger W improves local recall but increases cost linearly.  
- Top‑k budget k: Larger k improves long‑range recall but increases cost.  
- Pillar count |P|: More pillars improve persistent set quality but add O(n) cost per pillar layer.  
- Cache eviction: Aggressive pruning saves memory but risks losing future important positions; persistent set mitigates this.

**Failure signatures:**  
- Token divergence from full‑attention reference (any mismatch indicates missing critical positions).  
- Attention mass on middle tokens exceeding a few percent (failure to concentrate).  
- Memory usage growing linearly with context (cache not pruned).  
- Speedup below projections, especially at moderate lengths where overhead dominates.

**First 3 experiments:**  
1. **Attention Mass Profiling:** Compute the fraction of softmax mass captured by anchor+window vs. adding top‑k for various sequence lengths. Expect >99% mass on a constant‑size set.  
2. **Token Match Validation:** Implement Condensate selection and sparse attention; run greedy decoding on a short prompt and verify 100% token‑level match with full attention.  
3. **Scaling Benchmark:** Measure latency of sparse vs. full attention across sequence lengths (1K, 4K, 16K). Confirm O(n) scaling for sparse and O(n²) for full; observe crossover around 2K tokens.

## Open Questions the Paper Calls Out
#### Open Question 1
- **Question:** Is the extreme attention concentration observed (and exploited) by the Condensate Theorem a necessary outcome of gradient‑based training on autoregressive language modeling objectives, or merely a common empirical pattern?
- **Basis in paper:** [explicit] The authors state: "A formal proof would additionally need to show that all trained models must exhibit this concentration, which we leave as an open question—though the universality of the observation suggests it is intrinsic to gradient‑based attention learning."
- **Why unresolved:** The paper provides extensive empirical evidence across 12 architectures but lacks a formal theoretical argument proving that the optimization dynamics of next‑token prediction *must* lead to softmax weights below the float32 ULP for non‑Condensate positions.
- **What evidence would resolve it:** A mathematical proof linking the loss landscape, gradient magnitudes, and the properties of the softmax nonlinearity to show that minimizing cross‑entropy loss on standard corpora inexorably pushes the mass of the learned attention distribution onto a bounded set of positions for any sufficiently trained model.

#### Open Question 2
- **Question:** Does the numerically exact equivalence guaranteed under greedy decoding hold under common stochastic sampling strategies (e.g., nucleus sampling, temperature > 0), and if not, what is the approximation error?
- **Basis in paper:** [explicit] In the Limitations section: "Our validation uses greedy decoding. Under sampling with high temperature, tail positions may contribute above the ULP threshold, potentially breaking exact equivalence."
- **Why unresolved:** The core theorem relies on contributions being < float32 ULP (~6e‑8). Raising temperature flattens the softmax distribution, potentially lifting previously negligible weights above the ULP threshold. The empirical impact on distributional sampling (e.g., diversity, quality) is unmeasured.
- **What evidence would resolve it:** Systematic generation experiments comparing sparse vs. full attention across a range of temperatures (e.g., 0.7, 1.0) and sampling methods (nucleus p=0.9), measuring divergence in token distributions (e.g., KL divergence), sequence‑level metric changes (perplexity, MAUVE), and failure cases where bit‑identical outputs break down.

#### Open Question 3
- **Question:** What is the layer‑ and head‑specific optimal configuration (window size W, top‑k budget k, pillar layer set P) that maintains 100% greedy‑decoding equivalence while minimizing compute across diverse model architectures (e.g., varying depth, width, GQA ratios)?
- **Basis in paper:** [inferred] The paper uses a fixed budget (~97 positions) and a simple rule for pillar layers (|P|/L ≤ 1/16). It notes "optimal parameters (W,k) may vary by model" and shows layer‑adaptive windows for late layers only. The systematic selection of P is not explored; it is set arbitrarily small.
- **Why unresolved:** The work presents a universal *principle* (select positions with high Q·Kᵀ scores) but the practical *implementation* (hyperparameters W, k, P, τ for spike persistence) is chosen conservatively. No automated or theoretically‑grounded method exists to determine the minimal sufficient set Cᵢ per layer/head for a new model without full‑attention profiling.
- **What evidence would resolve it:** A large‑scale study profiling attention topologies across hundreds of models (varying sizes, training data, objectives) to derive scaling laws or heuristics for setting (W, k, P) based on model metadata (e.g., number of layers, GQA ratio). Validation would show these auto‑tuned configurations maintain 100% greedy match while reducing compute closer to the theoretical minimum.

#### Open Question 4
- **Question:** Do models pre‑trained exclusively on short contexts (e.g., 2K tokens) fail to learn the condensate pattern when evaluated at extreme lengths (e.g., 100K+ tokens), and can fine‑tuning recover it?
- **Basis in paper:** [explicit] In Limitations: "Models trained on short contexts may not generalize concentration patterns to longer sequences."
- **Why unresolved:** All validation models (GPT‑2, Pythia, Qwen2, TinyLlama, Mistral) were trained with contexts ≥ 8K (except early GPT‑2 variants). The paper tests them at long lengths but does not evaluate a model explicitly trained with a short (e.g., 2K) token context window to see if the learned sparsity pattern breaks down when extrapolated.
- **What evidence would resolve it:** Take a modern model with a short pre‑training context (e.g., a 2K‑token Llama variant), run the Condensate analysis at its native length (should show concentration), then evaluate at 32K+ tokens. Measure the drop in attention mass captured by the Condensate Set and the rate of token‑mismatch errors between sparse and full attention. A follow‑up experiment would fine‑tune such a model on long‑context data and re‑measure.

#### Open Question 5
- **Question:** Can the Condensate Theorem’s sparse pattern be seamlessly integrated with FlashAttention’s IO‑aware kernel optimizations to yield multiplicative speedups beyond the reported 159×?
- **Basis in paper:** [explicit] In Related Work: "These approaches are complementary: our sparse pattern can be implemented within a FlashAttention‑style kernel for maximum efficiency." However, all benchmarks use a separate proprietary Triton kernel vs. PyTorch’s SDPA (FlashAttention backend).
- **Why unresolved:** FlashAttention optimizes memory access for the *dense* O(n²) computation. The Condensate pattern introduces *irregular* memory accesses (gathering keys/values from arbitrary Condensate positions). Combining them requires a new kernel that fuses the sparse selection logic with tiling and recomputation to minimize HBM accesses, which is non‑trivial.
- **What evidence would resolve it:** A public implementation of a fused "Topological FlashAttention" kernel that respects the Condensate selection (Anchor+Window+Top‑k) while using FlashAttention’s tiling strategy for the dense operations on the selected subset. Benchmark this fused kernel against the standalone sparse kernel and vanilla FlashAttention to measure the combined gain, especially at scales > 100K tokens.

## Limitations
- **Hyperparameter gaps:** Optimal window size (W), top‑k budget (k), and pillar layer count (|P|) are model‑specific and not fully specified. Reproduction requires tuning, and defaults may underperform on architectures not in the test set.
- **Proprietary speedup kernel:** The reported 159× speedup uses an unstated, optimized “Topological Attention” kernel. The public reference implementation benchmarks correctness, not latency; achieving similar speedups requires access to this proprietary code.
- **Vague adaptive rules:** The “layer‑adaptive” window adjustment via RepScore is described conceptually but lacks precise algorithmic details, hindering exact replication of its claimed benefits.
