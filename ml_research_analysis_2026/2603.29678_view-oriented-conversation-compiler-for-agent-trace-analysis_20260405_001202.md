# View-oriented Conversation Compiler for Agent Trace Analysis
## Quick Facts
- arXiv ID: 2603.29678
- Source URL: https://arxiv.org/abs/2603.29678
- Reference count: 40
- Primary result: VCC improves agent reflection by transforming raw JSONL logs into line-number-consistent views, boosting task completion pass rates and reducing token consumption by 50-67%.

## Executive Summary
Modern agent execution logs in raw JSONL format are verbose and deeply structured, making them difficult for analysis. The View-oriented Conversation Compiler (VCC) addresses this by compiling logs into three views: a lossless full view, a user-interface view that collapses internal details, and an adaptive view filtered by a relevance predicate. In AppWorld experiments, using VCC views as input to a reflector agent increased task completion pass rates across all three model configurations (Opus, Sonnet, Haiku), reduced reflector token consumption by 50-67%, and yielded more concise learned memory files. These results underscore that message format is a critical, often overlooked, component of context engineering for agent systems.

## Method Summary
The study evaluates VCC within an epoch-based context engineering loop. A generator agent executes tasks from the AppWorld benchmark (90 training tasks), producing raw Claude Code JSONL traces. A reflector agent then analyzes each trace and the evaluation outcome, editing a shared `MEMORY.md` file with rules. The reflector's input format is the only variable: either raw JSONL or VCC's compiled views (UI+full or adaptive). After two epochs (~180 analyses), the final memory is tested on AppWorld test splits (test_normal: 168 tasks; test_challenge: 416 tasks). Metrics include pass rates (task_goal_completion, scenario_goal_completion), reflector token usage, and memory file size. VCC's compiler consists of a lexer, parser (lowering records to a typed IR), a single line assignment pass, and view emitters that produce the three projections while maintaining line-number consistency.

## Key Results
- Task completion pass rates improved across all model configurations when using VCC views instead of raw JSONL.
- Reflector token consumption dropped by 50-67% due to the compressed UI view and semantic filtering.
- Learned memory files were smaller and more focused, indicating higher precision in rule extraction.

## Why This Works (Mechanism)
The paper proposes three plausible mechanisms for VCC's effectiveness:
1. **Token reduction via view summarization**: The UI view collapses each tool call, thinking block, and harness noise into one-line summaries, shrinking the token load the reflector must process.
2. **Enhanced semantic navigation**: The adaptive view preserves block-level role annotations (e.g., `[tool_call]`, `[thinking]`) and line-range pointers, enabling the reflector to distinguish intentions from observations and perform targeted dereferencing—something a flat JSONL text cannot provide.
3. **Lossless progressive disclosure**: Because all views project from a single IR with a shared line-number coordinate system, the reflector can start with an overview (UI) and then follow pointers to recover exact original content in the full view without misalignment. This combination of compression and precise cross-view linking likely directs the reflector's attention to relevant information more efficiently.

## Foundational Learning
- **Structured Intermediate Representation (IR)**
  - *Why needed*: VCC decouples parsing of raw logs from view generation. The IR is a language-agnostic sequence of typed nodes (user, assistant, tool_call, etc.) that all views project from.
  - *Quick check*: If a `tool_result` node were misclassified as `assistant`, how would the UI view's summary and the adaptive view's role annotation be affected?

- **View Projection vs. Multi-level Memory Abstraction**
  - *Why needed*: VCC's views are dynamic projections, not irreversible summaries. This preserves full fidelity while allowing selective hiding; the original content remains accessible via pointers.
  - *Quick check*: If VCC's views were precomputed summaries (like MemGPT’s levels) instead of IR projections, how would the experiment results likely change in terms of memory size and reflection quality?

- **Line-Number Coordinate System as Structural Invariant**
  - *Why needed*: A single, canonical line-number assignment ensures that any pointer from a view to the full view resolves to the exact original lines, enabling a reliable progressive-disclosure workflow.
  - *Quick check*: Which step in the VCC pipeline enforces that lowering passes cannot renumber lines, and why is imposing this order critical?

## Architecture Onboarding
- **Component map**: Lexer -> Parser -> Line Assigner -> View Emitters (Full Emitter, UI Emitter, Adaptive Emitter) with the Predicate Engine feeding the Adaptive Emitter.
- **Critical path**: Raw JSONL → Lex → Parser → IR → Line Assigner → (Full/UI/Adaptive) Emitters → Structured Views. The line assignment must occur after parsing and before any emission.
- **Design tradeoffs**:
  * Expressiveness vs. parser complexity: Adding support for a new agent runtime requires a new lexer/parser but reuses the view pipeline.
  * Dynamic projection vs. precomputation: VCC avoids storing summaries (low storage, high query-time cost) but requires parsing the full IR per view.
  * Single-file contiguity vs. distributed trace: VCC's full view is one contiguous file; splitting traces would break O(1) pointer dereference.
- **Failure signatures**:
  * Misaligned pointers: UI summary line reference points to a block of a different type in the full view.
  * Missing content in adaptive view: Predicate matches but block is elided (e.g., match inside a block, not at block level).
  * Harness noise appearing in UI view: System reminders still present, indicating parser stripping failure.
  * Reassembly failure: Split assistant messages appear as separate blocks, suggesting parser grouping is broken.
- **First 3 experiments**:
  1. Parse & Line-Accuracy: Feed a sample JSONL through lex+parse; verify node counts, tool call conversion to YAML scalars, and thinking block identification.
  2. UI View Compression Ratio: Compare token counts of raw JSONL vs. UI view; confirm each tool call is one line, harness XML absent, and random UI pointer dereferences match full view content.
  3. Adaptive Predicate Sanity: Apply a simple regex (e.g., "File not found") and ensure matching lines are emitted with correct role annotations, matched blocks include preceding headers, and document vs. index ordering behaves as expected.

## Open Questions the Paper Calls Out
- Does the benefit of VCC extend to other agent benchmarks (e.g., SWE-bench, WebArena) beyond AppWorld?
- What is the optimal relevance predicate ρ (regex, BM25, embedding, LLM-judged) for different analysis tasks?
- Are the improvements due to structural semantics and pointers, or merely due to the raw token reduction? (Needs ablation with length-matched, unstructured truncation.)
- How should UI view elision rules be defined for non-Claude-Code agents (e.g., web agents, multi-agent conversations)?
- How does reflector capability interact with VCC's benefits? Are weaker or stronger models helped more? (Needs factorial design crossing generator and reflector strengths.)

## Limitations
- Exact Claude Code JSONL schema and transformation rules are not fully specified, hindering faithful reproduction.
- Reflector's prompt template, memory output format, and LLM-based merge procedure are missing.
- External validity is limited: results are restricted to AppWorld with Claude models; other frameworks and domains remain unverified.

## Confidence
- Token reduction: High (direct 50-67% measurement)
- Reflection precision: Medium (evidence is indirect: more concise memory)
- Cross-view consistency: Medium (structural guarantee but no empirical validation of pointers)
- Foundational concepts (IR, projection, line system): Medium (logical soundness but implementation depends on missing specs)

## Next Checks
- **Pointer Integrity Audit**: Sample 50 tool calls from UI view; verify that dereferencing the pointer's line range in the full view yields the exact original block without misalignment. Acceptable failure rate <1%.
- **Token Savings Realization Check**: Instrument the reflector to log actual context tokens per analysis. Compare raw JSONL vs. VCC UI+full conditions; if token gap is <30% of the reported 50-67%, the reflector is not properly leveraging the compressed view.
- **Adaptive Predicate Sensitivity Test**: Run reflector with adaptive view using three predicates: (a) likely paper's BM25/embedding-based ρ, (b) simple keyword regex, (c) random filter. Measure changes in pass rates and memory quality. A large drop from (a) to (b) confirms ρ quality is critical.
