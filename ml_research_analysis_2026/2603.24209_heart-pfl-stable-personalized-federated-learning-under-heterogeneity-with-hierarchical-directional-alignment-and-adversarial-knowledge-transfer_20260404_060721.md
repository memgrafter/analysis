# HEART-PFL: Stable Personalized Federated Learning under Heterogeneity with Hierarchical Directional Alignment and Adversarial Knowledge Transfer
## Quick Facts
*   **arXiv ID:** 2603.24209
*   **Source URL:** https://arxiv.org/abs/2603.24209
*   **Reference Count:** 40
*   **Primary Result:** Achieves state-of-the-art personalized accuracy with only 1.46M trainable parameters: 63.42% on CIFAR-100, 84.23% on Flowers-102, and 95.67% on Caltech-101 under Dirichlet non-IID partitions, while remaining robust to out-of-domain proxy data.

## Executive Summary
HEART-PFL is a personalized federated learning (PFL) framework designed to handle severe data heterogeneity across clients. It introduces two complementary mechanisms: Hierarchical Directional Alignment (HDA), which aligns global and local representations in a depth-aware manner (cosine similarity for early layers, MSE for deep layers) to preserve client-specific semantics; and Adversarial Knowledge Transfer (AKT), which stabilizes the global adapter via symmetric KL distillation on both clean and adversarially perturbed proxy data. The method uses lightweight adapters on a frozen backbone, achieving strong personalization gains and robustness with minimal communication cost.

## Method Summary
HEART-PFL employs a frozen backbone (e.g., ResNet-18) with two sets of lightweight adapters: a per-client personalized adapter ($\tilde{\omega}_k$) and a global adapter ($\tilde{\theta}$). Clients locally train $\tilde{\omega}_k$ to minimize task loss plus an HDA loss, which aligns features from the global model ($\theta$) with client-specific class-wise prototypes computed at multiple layers—using cosine similarity for early layers and MSE for deep layers. After local training, each client creates a copy $\tilde{\phi}_k$ initialized from $\tilde{\theta}$, trains it briefly on local data, and sends it to the server. The server averages $\tilde{\phi}_k$ to update $\tilde{\theta}$, then performs AKT: it generates adversarial examples from a proxy dataset $D_\rho$ using PGD attacks targeting both $\tilde{\theta}$ and each $\tilde{\phi}_k$, and updates $\tilde{\theta}$ by minimizing symmetric KL divergence between the ensemble of local adapter logits and global adapter logits on both clean and adversarial samples.

## Key Results
*   Sets new state-of-the-art personalized accuracy on CIFAR-100 (63.42%), Flowers-102 (84.23%), and Caltech-101 (95.67%) under Dirichlet non-IID ($\alpha=0.1$).
*   Demonstrates robustness to out-of-domain proxy data (e.g., using Flowers-102 as proxy for CIFAR-100 clients) with minimal accuracy drop.
*   Achieves these results with only 1.46M additional trainable parameters per client, making it communication-efficient.

## Why This Works (Mechanism)
### Mechanism 1: Hierarchical Directional Alignment (HDA)
*   **Claim:** HDA preserves client-specific semantics while aligning global and local representations by using layer-specific similarity metrics.
*   **Mechanism:** Early-layer features (generic patterns) are aligned via cosine similarity for directional consistency; deep-layer features (class-specific semantics) are aligned via MSE for precise matching. This avoids erasing personalization cues that single-layer alignment might suppress.
*   **Core Assumption:** The hierarchical feature space can be partitioned into "early" (generic) and "deep" (semantic) stages, and each stage requires a different alignment objective.
*   **Evidence Anchors:** The abstract and Section 3.2 define the semantic-aware alignment function with cosine for early layers and MSE for deep layers; Figure 4 shows performance peaks at a specific layer partition, validating the hierarchical approach. Neighbor papers (FedProto, FedORGP) use single-layer alignment, indicating HDA's novelty.

### Mechanism 2: Adversarial Knowledge Transfer (AKT)
*   **Claim:** AKT stabilizes global adapter updates under heterogeneity by making distillation bidirectional and robust to out-of-domain proxy data.
*   **Mechanism:** The server distills knowledge using symmetric KL divergence on both clean and adversarially perturbed proxy samples. This ensures the global adapter does not overfit to any single client's biased ensemble and gains robustness from diverse feature views.
*   **Core Assumption:** Clean proxy data alone leads to brittle distillation under client drift; adversarial perturbations expose the model to diverse decision boundaries, and symmetric KL prevents one-sided bias propagation.
*   **Evidence Anchors:** The abstract and Section 3.3 define the AKT loss on clean and adversarial samples via PGD. Figure 6 shows AKT flattens the loss landscape, indicating stability. Neighbors like CAFEDistill use standard distillation without adversarial robustness, making AKT's combination novel.

### Mechanism 3: Complementary Synergy
*   **Claim:** HDA and AKT are complementary: HDA enhances client-specific representation quality, while AKT ensures these refined local models contribute stably to the global adapter.
*   **Mechanism:** HDA provides high-quality, hierarchy-aware client prototypes that guide local training; AKT aggregates these diverse local adapters robustly via adversarial symmetric distillation, preventing any single client's noise from dominating.
*   **Core Assumption:** Personalization quality (from HDA) and global stability (from AKT) are co-dependent and can be jointly optimized without trade-off.
*   **Evidence Anchors:** Table 3 shows HDA+AKT together (63.42%) outperforms each alone (~58-59%); Figure 5 shows AKT's full version (clean+adv+sKL) best for both personalized and global metrics. Neighbors typically address either alignment or distillation separately.

## Foundational Learning
*   **Concept: Personalized Federated Learning (PFL)**
    *   **Why needed:** HEART-PFL is a PFL method; understanding that the goal is per-client model improvement under non-IID data explains why HDA and AKT target client specificity and stability.
    *   **Quick Check:** How does PFL differ from standard FL in objective, and why does heterogeneity make personalization necessary?
*   **Concept: Prototype-based Representation Alignment**
    *   **Why needed:** HDA extends prototype alignment across layers; knowing that prototypes are class-wise feature averages and alignment reduces representation discrepancy is key.
    *   **Quick Check:** What are the risks of aligning only at a single layer (e.g., shallow prototype methods) under client heterogeneity?
*   **Concept: Knowledge Distillation with Adversarial Robustness**
    *   **Why needed:** AKT builds on ensemble distillation but adds adversarial samples and symmetric KL; understanding standard distillation and adversarial training is prerequisite.
    *   **Quick Check:** Why might standard KL distillation (server→client) fail under non-IID data, and how do adversarial examples and symmetric KL address this?

## Architecture Onboarding
*   **Component Map:**
    Clients (frozen backbone $\psi$, trainable personalized adapter $\tilde{\omega}_k$, local prototype bank $P_k$, temporary adapter $\tilde{\phi}_k$) -> Server (global adapter $\tilde{\theta}$, proxy dataset $D_\rho$, adversarial generator) -> Clients.
*   **Critical Path:**
    1.  Client: train $\tilde{\omega}_k$ for $E_{client}$ epochs via SGD to minimize local task loss + L_HDA.
    2.  Client: create $\tilde{\phi}_k$ copy of $\tilde{\theta}$, train briefly on local data via CE loss.
    3.  Server: aggregate $\tilde{\phi}_k$ via averaging to update $\tilde{\theta}$.
    4.  Server: generate $x_{adv}$ from $D_\rho$ using PGD w.r.t. $\tilde{\theta}$ and each $\tilde{\phi}_k$.
    5.  Server: update $\tilde{\theta}$ via Adam using symmetric KL loss on $\{x_\rho, x_{adv}\}$.
*   **Design Tradeoffs:**
    *   Adapter size vs. personalization: Smaller adapters (1.46M) reduce communication but may limit capacity; adapters outperform full fine-tuning in efficiency.
    *   Proxy data choice: In-domain proxy yields best results, but out-of-domain proxy (Figure 3) works nearly as well, indicating robustness. Highly mismatched domains may still degrade.
    *   Layer partition in HDA: More early-layer cosine alignment improves directional consistency but too many layers may suppress deep semantics (Figure 4).
*   **Failure Signatures:**
    *   L_HDA diverges or plateaus high -> layer partition or learning rate misconfiguration.
    *   Global adapter accuracy fluctuates wildly across rounds -> AKT's symmetric KL weight too high or adversarial perturbation too strong.
    *   Personalization gap between clients narrows (all clients similar) -> HDA over-regularizing, losing client specificity.
*   **First 3 Experiments:**
    1.  **HDA layer partitioning ablation:** progressively apply cosine similarity from layer 0 to L, measure alignment (cosine similarity between global features and client prototypes), feature norm variance, and test accuracy. Expect optimal at a mid-depth partition (e.g., 2 layers in ResNet-18).
    2.  **AKT component ablation:** run with (a) clean only, (b) adversarial only, (c) clean+adversarial without symmetric KL, (d) full AKT. Measure both personalized and global test accuracy; full AKT should be best on both.
    3.  **Out-of-domain proxy robustness:** use proxy dataset from a different domain than clients (e.g., Flowers102 proxy for CIFAR100 clients). Compare accuracy drop vs. in-domain proxy; minimal drop confirms AKT's domain robustness.

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** What is a principled, architecture-agnostic method for determining the boundary between "early" and "deep" network layers in HDA?
*   **Basis:** The paper states the partition is set empirically (e.g., at layer 2 for ResNet-18) but provides no general rule.
*   **Why Unresolved:** The optimal partition depends on architecture, depth, and task. Without guidelines, applying HDA to new models requires costly, dataset-specific tuning.
*   **Resolving Evidence:** A systematic study across diverse architectures correlating layer semantics (e.g., via probing) with performance of cosine vs. MSE alignment to yield a heuristic or automatic metric.

### Open Question 2
*   **Question:** What is the theoretical or mechanistic explanation for the observed synergy between HDA and AKT?
*   **Basis:** The authors claim complementary gains but do not analyze *why* they are complementary.
*   **Why Unresolved:** The causal relationship (e.g., does HDA's alignment make AKT more effective, or vice versa?) is unclear, which is crucial for future PFL design.
*   **Resolving Evidence:** Controlled experiments measuring feature diversity/norm variance under HDA alone vs. with AKT, loss landscape flatness contributions, or formal analysis linking HDA's variance reduction to AKT's stabilization.

### Open Question 3
*   **Question:** What properties of the proxy dataset $D_\rho$ are essential for AKT's out-of-domain robustness, and can an optimal or universal proxy be identified?
*   **Basis:** The paper shows robustness with mismatched domains (e.g., Flowers102 proxy for CIFAR100) but does not explain why or if other proxies work similarly.
*   **Why Unresolved:** Practitioners need guidance on $D_\rho$ selection. Is robustness due to diversity, label distribution, or feature statistics? Can a small generic dataset suffice universally?
*   **Resolving Evidence:** A large-scale study varying $D_\rho$'s domain, size, label coverage, and feature distribution to identify robust proxy characteristics or determine if domain mismatch inherently regularizes.

### Open Question 4
*   **Question:** How does the use of adversarial examples in AKT specifically contribute to stabilizing global updates under client heterogeneity, beyond standard clean-data distillation?
*   **Basis:** Authors state adversarial examples "increase feature diversity" and AKT flattens the loss landscape, but the precise role of adversarial examples (vs. symmetric KL) is not isolated.
*   **Why Unresolved:** Disentangling the contribution of adversarial examples from symmetric KL is necessary to understand if robustness comes from perturbations themselves or the bidirectional constraint under perturbation.
*   **Resolving Evidence:** Ablation studies comparing AKT variants: (a) clean+symmetric KL, (b) only adversarial+standard KL, (c) adversarial+symmetric KL without clean data. Measure personalization gaps, gradient variance, and adversarial robustness.

## Limitations
*   **HDA layer partition** is not specified (which ResNet-18 layers are early vs. deep) and requires empirical tuning.
*   **Proxy dataset $D_\rho$** construction (source, size, sampling) is unspecified, hindering replication and deployment.
*   **Adversarial hyperparameters** (PGD step size, bound, iterations) are omitted, risking improper robustness tuning.

## Confidence
*   **HDA alignment effectiveness:** **High** – Ablation (Figure 4) validates layer-partition sensitivity; mechanism aligns with hierarchical feature theory.
*   **AKT stability contribution:** **Medium** – Loss landscape flattening (Figure 6) supports robustness, but break conditions (e.g., extreme perturbation) are untested.
*   **Synergy (HDA+AKT):** **Medium** – Combined gains shown (Table 3), but independent scaling effects and failure modes lack deeper analysis.
