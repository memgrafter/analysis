# ChartNet: A Million-Scale, High-Quality Multimodal Dataset for Robust Chart Understanding

## Quick Facts
- arXiv ID: 2603.27064
- Source URL: https://arxiv.org/abs/2603.27064
- Reference count: 40
- Primary result: Fine-tuning VLMs on ChartNet yields large, consistent gains across reconstruction, data extraction, summarization, and QA, with models like LLaVA-7B improving by up to +41.8 points and even smaller models surpassing GPT-4o on some tasks.

## Executive Summary
ChartNet addresses the scarcity of high-quality supervision for chart understanding by introducing a million-scale multimodal dataset generated through a code-guided synthesis pipeline. Starting from seed chart images, a VLM converts them into executable plotting code, which an LLM then augments across diverse chart types and libraries. Rendered images are rigorously filtered for visual quality. Each sample is paired with five aligned modalities: code, image, CSV, natural language summary, and QA pairs with chain-of-thought reasoning. Fine-tuning vision-language models of various sizes (256M–7B) on ChartNet produces substantial improvements on tasks ranging from code reconstruction to data extraction and QA, and these gains transfer to public benchmarks, demonstrating the dataset’s effectiveness.

## Method Summary
The pipeline comprises five stages. First, Chart-to-Code: a VLM (e.g., pixtral-large) translates seed images into Python plotting scripts. Second, Code Augmentation: an LLM (e.g., gpt-oss-120b) modifies the scripts—altering chart types, libraries, and data—while maintaining executability, yielding variations. Third, Rendering: the code is executed with libraries like matplotlib, seaborn, plotly, and pygal to produce images. Fourth, Quality Filtering: a VLM checks each image against eight defect categories (e.g., missing data, labeling issues, legend problems) and discards flawed charts. Fifth, Attribute Generation: for retained samples, the code anchors the extraction of ground-truth CSV, generation of a natural language summary, and creation of QA pairs with CoT via a multi-stage LLM process. The final dataset contains 1.5 million synthetic samples plus 30,000 real-world ones, each with five perfectly aligned modalities. Models are fine-tuned via supervised SFT on task-specific subsets, with evaluation using GPT-4o-as-judge for most tasks and fuzzy matching for QA.

## Key Results
- Fine-tuning LLaVA-7B on ChartNet yields large gains: data extraction +41.8 points to 58.8%, reconstruction execution +38.6 to 83.9%, summarization +29.1 to 80.3%, and QA +15.2 to 70.3%.
- Smaller models surpass far larger proprietary ones; e.g., Granite-Vision-2B achieves 70.3% extraction vs. GPT-4o’s 46.7%.
- Improvements generalize to external benchmarks: ChartCap BLEU4 increases from 1.6 to 12.4 after fine-tuning.

## Why This Works (Mechanism)
**Mechanism 1: Code-guided synthesis as a structured intermediate representation**  
The pipeline uses executable plotting code as a semantic anchor to generate diverse, realistic chart images at scale. A VLM converts seed charts into code, and an LLM systematically augments it—changing types, libraries, data—while preserving executability. Code’s discrete, compositional nature allows controlled exploration of the chart space. Evidence: a 77% code execution rate confirms most code is functional; the quality filter reduces visual defects from 14.9% to 5.9%. If the initial VLM produces inaccurate code, errors propagate through augmentation and rendering.

**Mechanism 2: Five aligned modalities provide dense, program-grounded supervision**  
Each sample contains image, code, CSV, summary, and QA with CoT, all derived from the same code. This forces strict alignment: the image matches the code’s output, the CSV matches plotted points, the summary describes the image accurately, and the reasoning is verifiable from data and visual structure. The code acts as the primary anchor, teaching joint reasoning over geometry, data, and language. Consistent gains across all tasks from fine-tuning suggest effective transfer. Misalignment (e.g., summary referencing absent data) would introduce conflicting signals and harm learning.

**Mechanism 3: Rigorous quality filtering ensures high visual fidelity**  
After rendering, a VLM judges each image against eight defect categories (e.g., overlapping text, incorrect scales). This automated filter targets issues that would confuse a learner, boosting signal-to-noise ratio. Human validation on 3,157 samples and the reduction in defect rate (14.9% → 5.9%) support its reliability. If the VLM judge lacks precision/recall, it may admit flawed samples or unnecessarily cull acceptable ones, hurting diversity or quality.

## Foundational Learning
**Concept: Programmatic Data Synthesis**  
*Why needed*: ChartNet treats code as a superior latent space for generating controlled multimodal data compared to direct image/text generation.  
*Quick check*: Why is plotting code a more effective intermediate representation for generating diverse chart datasets than directly prompting an LLM or VLM to describe or draw a chart?

**Concept: Multimodal Grounding via Shared Anchor**  
*Why needed*: The five-aligned-modality design relies on a single ground-truth anchor (plotting code) to align perception, structure, syntax, and semantics.  
*Quick check*: In the ChartNet tuple, which modality serves as the primary semantic anchor, and how does this anchor enable the generation of the other four modalities with consistency?

**Concept: Quality Filtering as Differentiable Curation**  
*Why needed*: At scale, manual curation is infeasible; the pipeline uses a VLM as a differentiable filter, requiring automated translation of abstract quality goals into a structured prompt.  
*Quick check*: What are the risks of using a single VLM both to generate chart data and later to filter its own outputs? How does the pipeline mitigate this circularity risk?

## Architecture Onboarding
The generation pipeline’s critical path is: Seed Selection → Chart-to-Code (VLM) → Code Augmentation (LLM) → Rendering (plotting libraries) → Quality Filtering (VLM) → (for surviving samples) Attribute Generation (VLM) → QA & CoT Pipeline (LLM multi-stage) → Final Packing. Failures at any stage (e.g., non-executable code, rejected image) terminate that sample’s progress.

**Component map**:  
Seed Source -> VLM (Chart-to-Code) -> LLM (Code Augmentation) -> Renderer -> VLM (Quality Filter) -> (for surviving samples) Attribute Generation -> QA Pipeline -> Final Packing  

**Design tradeoffs**:  
- *Synthetic vs. Real*: Synthetic data provides scale and perfect alignment but risks distribution shift; mitigated by a 30K real subset.  
- *Quality vs. Quantity*: Aggressive filtering (5.9% defect rate post-filter) rejects ~36.5% of renders, reducing yield but ensuring high signal.  
- *Modality Alignment Cost*: Generating five aligned modalities per sample is computationally heavy but yields rich supervision for multi-task learning.

**Failure signatures**:  
- Code execution rate <77% indicates VLM code generation errors.  
- Pre-filter visual error rate ~14.9% indicates augmentation LLM produces charts with readability issues.  
- Modality misalignment (e.g., CSV not matching plotted points) indicates attribute generation VLM lacks proper vision grounding.

**First 3 experiments** to validate the pipeline:
1. Run the full pipeline on 10 seed charts; verify: code executes >90%, images plausible, CSV matches plotted data exactly, summaries faithful, QA reasoning verifiable.
2. Sample 200 filtered-out and 200 kept charts; have humans judge readability against the 8 defect categories. Compute filter precision/recall; target >85% human agreement.
3. For 100 random final samples, attempt CSV reconstruction from image alone and QA from summary alone. Large accuracy drop (>20% absolute) when removing either modality confirms strong grounding.

## Open Questions the Paper Calls Out
**Open Question 1**: Do ChartNet’s synthetic charts generalize to unseen real chart styles?  
*Basis in paper*: Core dataset is 1.5M synthetic; only 30K real. No OOD evaluation.  
*Why unresolved*: Synthetic may not cover real diversity; needed for real use.  
*What evidence would resolve it*: Test finetuned models on held-out real charts; measure performance drop.

**Open Question 2**: How do remaining 5.9% visual errors after filtering affect model performance?  
*Basis in paper*: Quality filtering leaves 5.9% error (Section 3.4) with no impact analysis.  
*Why unresolved*: Small errors may still degrade reliability.  
*What evidence would resolve it*: Compare models trained on clean vs. full data; correlate errors with performance.

**Open Question 3**: Are the five modalities per sample consistent, and does misalignment hurt performance?  
*Basis in paper*: Each sample generated separately; alignment assumed but not verified.  
*Why unresolved*: Misalignment could confuse models during training.  
*What evidence would resolve it*: Audit consistency; correlate with scores; introduce controlled noise.

## Limitations
- Exact training/evaluation hyperparameters and prompt templates are unspecified, hindering faithful reproduction.  
- Dependence on proprietary models (GPT-4o, pixtral-large, gpt-oss-120b) for generation, filtering, and judging raises reproducibility and bias concerns.  
- Potential distribution shift: synthetic charts may not fully capture real-world chart diversity despite a 30K real subset.
