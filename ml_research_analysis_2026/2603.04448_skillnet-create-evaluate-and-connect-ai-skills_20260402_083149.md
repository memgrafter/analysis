# SkillNet: Create, Evaluate, and Connect AI Skills

## Quick Facts
- arXiv ID: 2603.04448
- Source URL: https://arxiv.org/abs/2603.04448
- Reference count: 40
- Primary result: SkillNet-augmented agents improve average reward by 40% and reduce execution steps by 30% across multiple backbone models, enabling cumulative capability growth.

## Executive Summary
SkillNet introduces an open infrastructure for creating, evaluating, and organizing AI skills to overcome the lack of systematic consolidation in current agents. By transforming fragmented experiences into a structured network of modular, composable skills, it enables agents to reuse past solutions efficiently. The system features a multi-dimensional evaluation framework (Safety, Completeness, Executability, Maintainability, Cost-awareness) that ensures high-quality skill curation. Experimental results on ALFWorld, WebShop, and ScienceWorld show that SkillNet-augmented agents achieve a 40% average reward improvement and 30% reduction in execution steps across diverse backbone models, demonstrating the potential for cumulative capability growth.

## Method Summary
The SkillNet infrastructure comprises three main stages: skill creation, evaluation, and organization. Skill creation uses LLMs to extract reusable patterns from diverse sources (trajectories, code, documentation) and package them into a standardized format (`SKILL.md`). Evaluation employs rubric-guided LLM scoring on five dimensions, with sandbox execution for executability, and achieves near-perfect human-model agreement (QWK ~1.0). Skills are then organized into a three-layer ontology (taxonomy, typed relation graph, package library) via automated embedding and LLM-based edge inference. The resulting repository of over 200,000 curated skills powers agents that retrieve and compose skills through the `skillnet-ai` toolkit.

## Key Results
- Average reward improvement of 40% and step reduction of 30% on ALFWorld, WebShop, and ScienceWorld benchmarks.
- Gains consistent across multiple backbone models (DeepSeek V3.2, Gemini 2.5 Pro, o4 Mini).
- Human-model agreement on evaluation dimensions reaches near-perfect QWK (~1.0), validating the quality control.

## Why This Works (Mechanism)
### Mechanism 1: Systematic Skill Consolidation
- **Claim:** Transforming fragmented heterogeneous inputs (trajectories, code, docs) into standardized, reusable skill packages reduces redundant problem-solving by making past solutions durable and discoverable.
- **Mechanism:** A multi-source automated pipeline uses LLMs to extract executable patterns from diverse data, structures them with `SKILL.md` metadata and optional resources, then applies deduplication, filtering, and categorization to produce a curated skill repository.
- **Core assumption:** Fragmented experience can be reliably abstracted into a portable, self-documenting capability unit that bridges declarative knowledge and executable logic.
- **Evidence anchors:** The abstract states SkillNet transforms fragmented experience into a structured network of skills. Section 2 defines skills as lightweight, modular, reusable abstractions with a three-step lifecycle and a file-based structure ensuring portability.
- **Break condition:** If skill creation cannot accurately capture procedural intent, skills may be incomplete, incorrect, or overly specific, leading to low reuse and skill pollution.

### Mechanism 2: Principled Multi-Dimensional Evaluation
- **Claim:** A rigorous, automated evaluation framework (Safety, Completeness, Executability, Maintainability, Cost-awareness) ensures only high-fidelity skills enter the repository, enabling reliable reuse without relying solely on downstream task performance.
- **Mechanism:** An LLM-based evaluator (GPT-5o-mini) guided by fine-grained rubrics scores each dimension on a three-level scale (Good/Average/Poor); for Executability, sandbox execution validates runtime correctness. Human validation on 200 samples shows near-perfect QWK (~1.0).
- **Core assumption:** Intrinsic skill properties can be assessed robustly by models aligned with human judgment, providing a scalable quality gate independent of specific downstream tasks.
- **Evidence anchors:** The abstract mentions the framework and its validation. Section 3.4 details each dimension, the automated pipeline, and presents quality distribution and validation metrics (MAE < 0.03, QWK ~1.0).
- **Break condition:** If evaluation rubrics fail to capture critical failure modes (e.g., subtle security flaws), low-quality skills pass filtering, causing agent failures during composition or execution.

### Mechanism 3: Graph-Based Skill Organization for Compositional Reasoning
- **Claim:** Modeling skills as nodes in a typed relation graph (`similar_to`, `compose_with`, `depend_on`, `belong_to`) enables efficient retrieval, dependency resolution, and workflow synthesis beyond isolated skill lookup.
- **Mechanism:** The Skill Ontology layers a taxonomy (categories/tags), a relation graph (instantiated skills with edges), and a package library. Automated analysis uses semantic embedding + LLM inference to construct edges, supporting global reasoning.
- **Core assumption:** Explicit relational structure among skills is discoverable and exploitable to automate planning and composition at scale, improving over ad-hoc skill chaining.
- **Evidence anchors:** Sections 3.2 & 3.5 describe the three-layer ontology and automated graph construction enabling retrieval, composition, dependency resolution, and workflow synthesis. Section 5 shows application examples where agents decompose tasks into skill workflows.
- **Break condition:** If relation inference produces noisy or sparse graphs (e.g., missing `depend_on` edges), agents may attempt invalid compositions leading to runtime failures or inefficient plans.

## Foundational Learning
- **Concept: Skill as a Unitary Knowledge Representation**  
  *Why needed here:* This reframes capability from model parameters or transient prompts to an externalized, version-controlled asset, enabling cumulative growth rather than episodic learning.  
  *Quick check:* What are the three key components stored in a skill's package (per Section 2), and how does the SKILL.md file differ from a standard code comment?

- **Concept: Multi-Dimensional Evaluation vs. Task-Success Evaluation**  
  *Why needed here:* Task reward is a lagging, noisy signal; SkillNet's intrinsic evaluation aims to predict utility *before* deployment. Distinguishing these is key to understanding the quality control mechanism.  
  *Quick check:* Why might a skill that leads to high task reward still score Poor on the Maintainability dimension? Give an example based on the dimension's definition.

- **Concept: Skill Relation Graph as a Planning Scaffold**  
  *Why needed here:* Agents compose workflows, not just pick one skill. The graph provides structural knowledge (dependency, similarity) for composition, more reliable than LLM-inferred chains from scratch.  
  *Quick check:* If Skill A `compose_with` Skill B, what does this imply about their typical use in a workflow, and how might an agent use this edge during planning?

## Architecture Onboarding
### Component Map
Input Adapters → Skill Creation Engine → Skill Curation Pipeline (Deduplication → Filtering → Tagging → Evaluation) → Ontology & Graph Builder → Skill Package Library → Toolkit & API → Front-end Website

### Critical Path
Raw Input → [Creation → Filtering → Evaluation] → [Graph Integration] → Package Library → skillnet-ai download/analysis. Evaluation is a mandatory filter *before* graph integration and release.

### Design Tradeoffs
- **Scale vs. Curation Overhead:** Fully automated creation+filtering enables 200k+ candidates but requires rigorous evaluation to avoid pollution. Manual audits are periodic samples only.
- **Generality vs. Specificity:** Skills range from lightweight guidance to full code bundles. More executable skills boost Executability scores but increase maintenance cost (affecting Maintainability).
- **Automation vs. Human Alignment:** LLM-based evaluation scales but relies on rubrics and model capability; human validation is limited to sampled audits.

### Failure Signatures
- **Skill Pollution:** Low Safety or Completeness scores, high redundancy (similar_to clusters with poor variation). Detect via: evaluation score histograms (Fig 4a), graph density analysis.
- **Broken Composition:** Missing depend_on or false compose_with edges cause execution failures when agents attempt planned workflows. Detect via: failed workflow executions during skillnet analyze or post-deployment agent runs.
- **Stale Packages:** Skills in packages not updated despite upstream changes (e.g., API deprecation). Detect via: low Maintainability scores, high Cost-awareness due to error recovery.

### First 3 Experiments
1. Baseline Comparison: Run ReAct, Expel, and Few-Shot baselines vs. +SkillNet on ALFWorld, WebShop, ScienceWorld using DeepSeek V3.2, Gemini 2.5 Pro, o4 Mini (Table 1, Fig 6). Success criterion: +SkillNet shows >30% step reduction and >40% reward increase.
2. Evaluation Validation: Perform human annotation on 200 sampled skills across 5 dimensions. Success criterion: QWK > 0.95, MAE < 0.05 between human and LLM evaluator (Fig 4b).
3. Generalization Test: Evaluate on unseen splits of benchmarks (Table 1 columns). Success criterion: Performance gains persist on unseen tasks, indicating skill transferability rather than memorization.

## Limitations
- Scalability of LLM-based skill extraction to highly novel or noisy domains (e.g., unstructured legacy docs) is uncertain.
- Potential bias in Safety/Completeness rubrics due to reliance on a single LLM (GPT-5o-mini) and limited human audits.
- Absence of explicit reproduction notes limits verification of pipeline transparency and resource requirements.

## Confidence
- Systematic Skill Consolidation: Medium
- Multi-Dimensional Evaluation: High
- Graph-Based Organization: Medium

## Next Checks
1. Cross-Domain Skill Extraction Stress Test: Run the creation pipeline on out-of-distribution sources (e.g., math textbooks, hardware manuals) and measure skill usability via human expert review of Completeness/Executability.
2. Graph Edge Ablation Study: Systematically remove inferred depend_on/compose_with edges in controlled experiments on WebShop to quantify their marginal contribution to step reduction beyond semantic search.
3. Longitudinal Skill Pollution Audit: Re-evaluate a 10% random sample of repository skills after 6 months of agent usage to detect drift in Maintainability/Safety scores, correlating with real-world failure logs.
