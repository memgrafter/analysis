# CUICurate: A GraphRAG-based Framework for Automated Clinical Concept Curation for NLP applications

## Quick Facts
- **arXiv ID:** 2602.17949
- **Source URL:** https://arxiv.org/abs/2602.17949
- **Reference count:** 17
- **Primary result:** An automated framework combines graph-based retrieval from UMLS with LLM filtering and classification to produce larger concept sets than manual benchmarks while matching human precision, with recall up to 0.92, stable outputs, low cost (<$0.10 per run), and completion in minutes.

## Executive Summary
CUICurate automates the curation of UMLS concept sets for clinical NLP, a task traditionally requiring significant manual effort from clinical experts. The framework uses a GraphRAG approach that first retrieves a relevant candidate set of CUIs from a filtered UMLS knowledge graph via semantic embedding and relationship-based expansion. This candidate set is then refined and classified by large language models, separating CUIs into those that definitively represent a target concept and those requiring contextual confirmation. Evaluated on five clinical concepts, the system generates substantially larger concept sets than manual benchmarks without sacrificing precision, offering a scalable, cost-effective alternative.

## Method Summary
The method constructs a knowledge graph from UMLS Metathesaurus files, retaining CUIs from specific source vocabularies and six semantic types. Each CUI is embedded using `text-embedding-3-large` and indexed with FAISS. For a target concept, its description is embedded and the top nearest neighbors are retrieved. This seed set is optionally expanded via child relationships (though optimal settings used no expansion). The retrieved CUIs are chunked and filtered by an LLM (GPT-5-mini) to retain only those relevant to the target. The filtered CUIs are then classified by GPT-5 into "definitive" or "context-dependent" categories using few-shot prompting. Performance is evaluated against clinician-adjudicated gold-standard sets.

## Key Results
- Concept sets were substantially larger than manual benchmarks while matching human precision for chronic heart failure, ischaemic stroke, and poor mobility.
- GPT-5-mini achieved filtering recall of 0.50–0.92; GPT-5’s classification distribution (56% definitive, 44% context-dependent) closely aligned with clinician judgements.
- Outputs were stable across runs, computationally inexpensive (under $0.10 per run with GPT-5-mini), and completed in minutes compared to 1–2 hours for manual curation.

## Why This Works (Mechanism)
### Mechanism 1  
**Claim:** Graph-based retrieval efficiently constrains the UMLS search space by leveraging semantic similarity and explicit ontology relationships.  
**Mechanism:** A target concept description is embedded; top-k nearest neighbors are retrieved via FAISS and optionally expanded through child relationships within a subgraph filtered by semantic types.  
**Core assumption:** Clinically relevant CUIs are either semantically close to the query or connected via UMLS relationships.  
**Evidence anchors:** [abstract] "combining graph-based retrieval from a UMLS knowledge graph with LLM filtering and classification." [section] Methods details the FAISS retrieval and child expansion. [corpus] Weak; similar graph retrieval used in radiology ontology papers but not directly validated for UMLS.  
**Break condition:** For concepts with structurally isolated gold-standard CUIs (e.g., "poor mobility", recall 0.53), retrieval misses valid CUIs due to weak connectivity and high embedding distance.

### Mechanism 2  
**Claim:** LLM-based filtering captures clinical nuance and indirect manifestations, improving recall while maintaining precision.  
**Mechanism:** LLMs filter CUIs based on direct assertion, subtypes, synonyms, and proxy indicators (e.g., related procedures), using prompts tailored to the target concept.  
**Core assumption:** LLMs can interpret UMLS CUI names and clinical implications from brief descriptors.  
**Evidence anchors:** [abstract] "LLM filtering... produced substantially larger concept sets than manual benchmarks whilst matching human precision." [section] Results show high recall/precision for three concepts; conservative filtering for fluid overload and LVSD. [corpus] Supported by hybrid LLM frameworks for rare disease phenotyping.  
**Break condition:** For concepts with indirect manifestations (e.g., fluid overload inferred from edema), LLMs may exclude valid CUIs by requiring direct assertion, reducing recall (GPT-5-mini recall 0.50 for LVSD).

### Mechanism 3  
**Claim:** Classification into "definitive" and "context-dependent" categories provides actionable granularity for NLP pipelines.  
**Mechanism:** LLMs classify each filtered CUI based on whether additional context is needed to confirm the target concept, guided by few-shot examples and target descriptions.  
**Core assumption:** Clinicians reliably distinguish these categories and LLMs can approximate human judgment with proper prompting.  
**Evidence anchors:** [abstract] "GPT-5 provided classification distributions... that closely aligned with clinician judgements." [section] Results show macro recall 0.72 vs. manual 0.75; misclassifications for poor mobility reflect ambiguous task definition. [corpus] Limited; corpus focuses on entity extraction, not classification alignment.  
**Break condition:** Ambiguity in clinical interpretation, especially for functional concepts (e.g., "poor mobility"), leads to discrepancies between LLM and clinician classifications due to differing views on baseline vs. situational impairment.

## Foundational Learning
- **Concept: GraphRAG**  
  *Why needed:* Core retrieval paradigm that integrates UMLS graph structure with semantic search to focus candidate generation.  
  *Quick check:* How does adding graph traversal to vector retrieval improve coverage of clinically relevant but hierarchically distant CUIs?
- **Concept: UMLS CUIs**  
  *Why needed:* Atomic units being curated; UMLS’s breadth introduces noise, necessitating set-based curation.  
  *Quick check:* Why can’t single CUIs reliably represent clinical concepts, and how do concept sets address this?
- **Concept: LLM Prompt Engineering for Clinical Tasks**  
  *Why needed:* Guides LLMs to perform filtering/classification with clinical specificity; prompt design affects recall, precision, and alignment.  
  *Quick check:* What prompt elements (e.g., few-shot examples, exclusion rules) are critical for distinguishing definitive vs. context-dependent CUIs?

## Architecture Onboarding
- **Component map:** UMLS Knowledge Graph -> Embedding & Indexing (text-embedding-3-large + FAISS) -> Graph Retrieval -> LLM Filtering (GPT-5-mini) -> LLM Classification (GPT-5)
- **Critical path:** Target concept -> description -> embedding -> FAISS top-k retrieval -> graph expansion (child relationships) -> semantic type filtering -> LLM filtering (chunked) -> LLM classification (chunked) -> output concept sets.
- **Design tradeoffs:** Retrieval: high k improves recall but increases noise and LLM cost; `max_neighbours` controls expansion breadth. LLM choice: GPT-5-mini is cheaper/more conservative; GPT-5 aligns better with clinicians. Classification granularity: two-class scheme simplifies review but may obscure nuance.
- **Failure signatures:** Retrieval: low recall for dispersed concepts (high isolated node ratio). Filtering: sudden recall drop for specific concepts (e.g., LVSD) suggests prompt under-specification. Classification: low Cohen’s κ (e.g., 0.32 for LVSD) signals clinician disagreement or LLM misinterpretation.
- **First 3 experiments:**  
  1. Vary retrieval parameters (k, max_neighbours) for "chronic heart failure" vs. "poor mobility" to plot recall vs. noise and identify robust settings.  
  2. Compare GPT-5-mini vs GPT-5 on "fluid overload" using identical retrieval output to quantify precision-recall trade-offs.  
  3. Manually inspect misclassifications for "poor mobility" to determine if errors stem from prompt ambiguity or LLM clinical reasoning gaps.

## Open Questions the Paper Calls Out
1. How does CUICurate's performance generalize to a broader and more diverse set of clinical concept types, including symptoms, procedures, medications, and rare diseases?  
2. To what extent can alternative graph-construction and embedding strategies improve retrieval recall for concepts with diffuse UMLS representations (e.g., "poor mobility") without overwhelming the LLM with noise?  
3. How do CUICurate-derived concept sets impact downstream clinical NLP tasks, such as improving agreement between concept normalisation tools or enhancing the accuracy of patient phenotyping and cohort construction?  
4. What are the precise clinical and ontological factors that drive the ambiguity between "definitive" and "context-dependent" classifications, and can this boundary be more formally defined?  
5. Does the reliance on GraphRAG-retrieved CUIs as the gold-standard evaluation set systematically underestimate the true recall of both manual and automated methods by excluding valid CUIs that are graph-isolated?

## Limitations
- **Reproduction blockers:** Four unknowns prevent faithful replication: exact CUI embedding text, substitute model performance for non-public GPT-5/GPT-5-mini, unavailable gold-standard sets, and incomplete prompt formatting.
- **External validity:** Evaluation limited to five target concepts; performance for other entity types (e.g., procedures) and structurally sparse UMLS regions remains unknown.
- **LLM alignment uncertainty:** Classification alignment relies on a single clinician adjudication; inter-rater reliability and consistency across diverse clinicians are unmeasured, especially for functional concepts.

## Confidence
- Mechanism 1 (Graph retrieval efficiency): **High** – Directly described, supported by recall results and break condition analysis.
- Mechanism 2 (LLM filtering nuance): **Medium** – Claims supported for three concepts but break conditions show fragility; external corpus provides partial analogies.
- Mechanism 3 (Classification granularity): **Low** – Limited direct evidence; clinician alignment based on single set with low Cohen’s κ for some concepts; corpus lacks comparable studies.

## Next Checks
1. **Retrieval sensitivity analysis:** Systematically vary k (100–1000) and `max_neighbours` (100–500) across all five concepts; plot recall vs. retrieved CUI count to identify robust parameters and confirm break conditions for isolated concepts.
2. **Model substitution impact test:** Replace GPT-5-mini/GPT-5 with public equivalents (e.g., GPT-4o, Claude 3.5 Sonnet) using identical prompts; compute delta in filtering/classification F1 to quantify reproducibility risk.
3. **Prompt specification audit:** A/B test original classification prompt against a clarified version that disambiguates "context-dependent" with clinical examples; measure change in clinician-LLM agreement (Cohen’s κ) for "poor mobility".
