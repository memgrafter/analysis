# TML-Bench: Benchmark for Data Science Agents on Tabular ML Tasks

## Quick Facts
- **arXiv ID**: 2603.05764  
- **Source URL**: https://arxiv.org/abs/2603.05764  
- **Reference count**: 33  
- **Primary result**: MiniMax-M2.1-TEE achieves the best aggregate normalized performance score across all competitions.

## Executive Summary
TML-Bench introduces a reproducible benchmark for evaluating autonomous coding agents on end-to-end tabular machine learning tasks. The benchmark leverages four real-world Kaggle competitions, three strict time budgets (240 s, 600 s, 1200 s), and ten open-source large language models (LLMs). Each configuration is run five times using the Kilo Code harness; success requires a valid submission and a private-holdout score. MiniMax-M2.1-TEE emerges as the top performer in aggregate normalized score, while average performance generally increases with longer time budgets. Reliability varies across models, with run-to-run variability evident in individual scaling trends.

## Method Summary
The Kilo Code harness orchestrates each evaluation: given a competition's dataset and rules, an LLM agent autonomously generates Python code for data preprocessing, model training, and prediction. The code executes in a sandboxed environment; if a valid submission file is produced within the allocated time, it is evaluated on the competition’s private holdout set. The resulting score is normalized across competitions to enable fair comparison. For each competition, time budget, and LLM combination, five independent runs are performed to capture variability.

## Key Results
- MiniMax-M2.1-TEE achieves the highest aggregate normalized performance score.
- Average performance improves with larger time budgets.
- Model reliability (success rate and run-to-run variability) differs meaningfully among LLMs; scaling with budget is noisy for some individual models at five runs.

## Why This Works (Mechanism)
The benchmark’s realism stems from authentic Kaggle competitions, which provide well-defined objectives, diverse tabular datasets, and unbiased private-holdout evaluation. Time constraints mimic practical development limits, forcing agents to make efficient algorithmic decisions. Repeated runs quantify reliability, while normalization allows aggregated comparison across heterogeneous tasks. This combination yields a robust measure of both correctness and consistency for autonomous coding agents.

## Architecture Onboarding
**Component map**: Competition Spec -> LLM Agent -> Code Interpreter -> Evaluation Module  
**Critical path**: Receive competition details → Generate code → Execute in sandbox → Produce submission → Evaluate on holdout → Return score  
**Design tradeoffs**: Time budget limits exploration but adds realism; sandbox isolation prevents resource conflicts but may restrict external data access; limited runs reduce statistical power but keep evaluation cost manageable.  
**Failure signatures**: No valid submission file; runtime exceptions; time elapsed exceeding budget; submission format mismatch.  
**First experiments**:  
1. Baseline run of MiniMax-M2.1-TEE at 1200 s across all competitions.  
2. Full evaluation of all LLMs at the longest time budget to identify top candidates.  
3. Expanded replication (20 runs) of the best performing LLM to quantify reliability.

## Limitations
- Only four Kaggle competitions used; may not generalize to broader tabular tasks.  
- Evaluation limited to open-source LLMs; proprietary models remain unbenchmarked.  
- Five runs per setting insufficient for robust estimation of variability.  

## Confidence
- Benchmark validity: Medium  
- MiniMax-M2.1-TEE best performance: Medium  
- Performance improves with time: Medium  
- Reliability differences: Medium
