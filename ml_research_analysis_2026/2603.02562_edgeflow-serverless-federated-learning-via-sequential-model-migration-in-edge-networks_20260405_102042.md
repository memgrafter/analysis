# EdgeFLow: Serverless Federated Learning via Sequential Model Migration in Edge Networks

## Quick Facts
- **ArXiv ID:** 2603.02562  
- **Source URL:** https://arxiv.org/abs/2603.02562  
- **Reference count:** 19  
- **Primary result:** EdgeFLow reduces communication overhead by 50-80% versus FedAvg while achieving comparable or improved test accuracy on FashionMNIST and CIFAR-10 under non-IID settings.

## Executive Summary
EdgeFLow reimagines federated learning in edge networks by eliminating the central cloud server. Instead, it orchestrates sequential model migration between edge base stations, with clients grouped into fixed clusters. Each round, only one cluster performs local training; its base station aggregates the models and directly passes the updated global model to the next base station. This serverless approach cuts communication costs substantially while maintaining convergence guarantees under non-convex objectives and non-IID data. Theoretical analysis introduces a cluster-level heterogeneity metric λ²_m(t), and experiments on FashionMNIST and CIFAR-10 confirm accuracy parity or gains (e.g., 87.97% vs 86.89% on FashionMNIST NIID A) with 50-80% less communication overhead.

## Method Summary
EdgeFLow operates in T global rounds. Clients are partitioned into M fixed clusters, each anchored to an edge base station. For round t, a scheduler selects an active cluster m(t). The corresponding base station broadcasts the current global model θ^t to its clients. Each client performs K local SGD epochs on its data, then uploads the updated model back. The base station aggregates (averaging) to produce θ^{t+1}. The scheduler then instructs the current base station to migrate θ^{t+1} directly to the base station of the next cluster m(t+1), bypassing any cloud. Two migration policies are studied: fixed sequential order (EdgeFLowSeq) and random selection (EdgeFLowRand). The method assumes edge base stations have reliable, lower-latency interconnections. Theoretical convergence bounds incorporate the cluster heterogeneity λ²_m(t) and local steps K. Practical implementation uses a simple CNN (6 layers) with SGD (learning rate η=0.01 in the minimal reproduction) and client data partitions that simulate IID and non-IID distributions (NIID A/B). Communication overhead is measured as total transmitted parameters across all client uploads and base-to-base migrations, showing 50-80% reduction compared to FedAvg in multi-hop edge topologies.

## Key Results
- EdgeFLow attains equal or higher test accuracy than FedAvg on non-IID data; e.g., FashionMNIST NIID A: 87.97% vs 86.89%, CIFAR-10 NIID A: 81.58% vs 77.04%.
- Communication overhead is reduced by 50-80% relative to FedAvg, with larger savings in deeper edge network topologies (e.g., chain of base stations).
- Convergence is provable under non-convex objectives and non-IID data, with the bound influenced by cluster heterogeneity and size; larger clusters improve accuracy but increase migration payload.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** EdgeFLow reduces global communication overhead by replacing cloud-centric aggregation with sequential model migration between edge base stations.
- **Mechanism:** The framework organizes clients into fixed clusters anchored to edge base stations. Only the active cluster's clients train locally in a round. After local training, the edge base station aggregates models to update the global model, which is then directly transmitted to the next scheduled base station, bypassing the cloud entirely.
- **Core assumption:** Edge base stations have reliable, lower-latency connectivity to each other compared to the high-latency, multi-hop paths to a distant cloud server.
- **Evidence anchors:** 
  - [abstract] "replaces traditional cloud servers with sequential model migration between edge base stations."
  - [section II.B] "The base station updates the global model...then propagates it to the next scheduled edge node." and "This edge-to-edge transfer forms a serverless model migration, bypassing the cloud entirely."
  - [corpus] Corpus neighbors discuss decentralized/serverless FL but do not directly validate EdgeFLow's specific migration sequence; evidence for the broad paradigm shift is strong, but the specific sequential protocol's advantages are primarily from the paper.
- **Break condition:** If the sequential order of clusters causes significant staleness (e.g., a critical cluster is scheduled too late) or if inter-edge-backhaul links become unreliable/high-latency, the communication savings may degrade or convergence may be impaired.

### Mechanism 2
- **Claim:** Fixed cluster formations and sequential activation control data heterogeneity effects (λ²_m(t)) per round, supporting convergence under non-IID data.
- **Mechanism:** Unlike FedAvg's random client sampling each round, EdgeFLow uses persistent clusters. The heterogeneity bound (λ²_m(t)) in Theorem 1 is defined per *cluster* (Eq. 7). By maintaining fixed cluster membership, the statistical similarity within a cluster (and thus λ²_m(t)) is stable across rounds, making the heterogeneity term more predictable and controllable than in random sampling.
- **Core assumption:** The fixed clustering creates intra-cluster homogeneity that is sufficiently better than the global average heterogeneity experienced in random client selection (FedAvg).
- **Evidence anchors:**
  - [section II.B] "Clients are dynamically grouped into fixed localized clusters."
  - [section III, Assumption 3] Defines cluster-level heterogeneity λ²_m(t) and bounds it.
  - [section III, Remark 1] "Unlike EdgeFlow where the number of clusters m remains fixed, and thereby enables better control over the range of λ²_m(t), the traditional FL approach suffers from indeterminate cluster counts and greater randomness."
- **Break condition:** If cluster formation fails to group similar clients (e.g., due to poor initialization or dynamic data distribution shifts), λ²_m(t) could remain high, negating the theoretical advantage and harming convergence.

### Mechanism 3
- **Claim:** Edge-based aggregation and migration enable provable convergence for non-convex objectives under non-IID data, with bounds influenced by cluster size and heterogeneity.
- **Mechanism:** The convergence proof (Theorem 1) adapts standard FL analysis by substituting the global gradient ∇F(θ^t) with a cluster-specific gradient ∇F_m(t)(θ^t) and accounting for the cluster heterogeneity term λ²_m(t). The sequential migration ensures that the global model version (θ^t) used by the active cluster is the one last aggregated at an edge node, not a cloud server.
- **Core assumption:** The model update equation (Eq. 3) correctly represents the aggregated effect of K local steps from the active cluster, and the stochastic gradient assumptions (bounded norm/variance) and L-smoothness hold for the local objectives.
- **Evidence anchors:**
  - [section III, Theorem 1] Provides the convergence bound: `1/T Σ E[||∇F(θ^t)||^2] ≤ 4/(KηT)(F(θ^0)-F^*) + 2/T Σ λ²_m(t) + ...`
  - [section III, Eq. 3] "θ^{t+1} ← θ^t - (η/N_m(t)) Σ_{n∈N_m(t)} Σ_{k=0}^{K-1} ˜g_t^{n,k}"
  - [section III, Assumptions 1-3] List the mathematical assumptions (L-smoothness, bounded gradients, heterogeneity).
- **Break condition:** Violation of any core assumption (e.g., unbounded gradients, non-smooth objectives, or unaccounted-for system heterogeneity beyond λ²_m(t)) would invalidate the bound. The proof also assumes independent client sampling within a cluster, which may not hold if clients share data correlations.

## Architecture Onboarding
**Component map:**  
Client Layer -> Edge Cluster Layer (Base Station) -> Sequential Migration Scheduler -> Model Store (at each Base Station)

**Critical path:**  
Scheduler selects cluster m(t) -> BS m(t) broadcasts θ^t to its clients -> Clients in N_m(t) train locally -> Clients upload models to BS m(t) -> BS m(t) aggregates to θ^{t+1} -> Scheduler selects next cluster m(t+1) -> BS m(t) migrates θ^{t+1} to BS m(t+1)

**Design tradeoffs:**
- Cluster size (N_m) vs. Communication Savings: Larger N_m reduces per-client uploads but increases model migration payload.
- Fixed vs. Dynamic Sequencing: Fixed sequence may cause stale model delays for late clusters; random spreads staleness but adds unpredictability.
- Local Epochs (K): Increasing K reduces communication rounds but may increase drift term in convergence bound.

**Failure signatures:**
- High cluster heterogeneity (λ²_m(t)): slow/stalled convergence for a cluster.
- Stale global model propagation: delayed migration causes later clusters to train on outdated models, leading to oscillating accuracy.
- Imbalanced cluster data: clusters with fewer samples have less influence, biasing global model.

## Limitations
- Hyperparameters (learning rate, optimizer) and exact CNN architecture are unspecified, hindering exact replication.
- NIID partition generation logic is vague; the actual cluster heterogeneity λ²_m(t) is unknown.
- Communication counting is ambiguous (which transmissions included), so reported compression ratios may vary with assumptions.
- Theoretical assumptions rely on smoothness and bounded gradients; real edge environments may violate these.
- Evaluation limited to two datasets and fixed topologies; generalizability unclear.

## Confidence
- Communication reduction: High (mechanism sound, empirical savings 50-80%).
- Convergence under non-IID: Medium (proof standard but clustering's effect on λ² needs empirical validation).
- Accuracy parity/improvement: Medium (limited datasets; IID results not emphasized).
- Theoretical guarantees: Medium (assumptions hold in controlled settings but may not in dynamic edges).
