# Building an Ensemble LLM Semantic Tagger for UN Security Council Resolutions

## Quick Facts
- arXiv ID: 2603.05895
- Source URL: https://arxiv.org/abs/2603.05895
- Reference count: 0
- Primary result: GPT-4.1 achieved highest performance (Cleaning CPR 84.9%, Tagging CPR 99.99%, TWF 99.92%); smaller models (e.g., GPT-4.1-mini) delivered comparable results at ~20% of the cost.

## Executive Summary
This paper introduces an ensemble system that uses multiple large language model (LLM) runs to add semantic XML tags to UN Security Council resolutions, which are notoriously noisy due to OCR errors and two-column formatting. The core method generates candidate outputs with stochastic sampling (temperature=1) and selects the best one using two automatic metrics: Content Preservation Ratio (CPR), which measures fidelity to the original text via character bigrams, and Tag Well-Formedness (TWF), which ensures syntactic validity of the XML. The approach avoids reliance on human-annotated gold standards. Results show GPT-4.1 performs best, but smaller models like GPT-4.1-mini achieve near-identical metrics at a fraction of the cost, demonstrating a scalable and cost-effective solution for reliably tagged documents.

## Method Summary
The system operates in two sequential stages: **cleaning** (converting raw two-column OCR text to linear, readable text) and **tagging** (adding XML tags for entities like locations and dates). For each document and each stage, the system runs multiple LLM calls across several OpenAI models (temperature=1). Each output is evaluated: cleaning outputs are scored by CPR against the raw input; tagging outputs are scored by CPR against the cleaned text, plus TWF (for well-formed XML) and tag count (nT). The best cleaning output is the one with highest CPR. The best tagging output is selected by sorting outputs descending by CPR, then TWF, then nT (lexicographic order). This ensemble selection leverages LLM variability to find a high-fidelity transformation without needing reference data.

## Key Results
- GPT-4.1 achieved the highest metrics: Cleaning CPR 84.9%, Tagging CPR 99.99%, TWF 99.92%.
- Smaller models (e.g., GPT-4.1-mini) attained comparable performance at approximately 20% of the cost, indicating strong cost-effectiveness.
- The ensemble approach consistently improved content preservation over single runs, with gains attributed to sampling diverse outputs and selecting the most faithful one.

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** Leveraging LLM stochasticity via temperature > 0 creates diverse outputs, enabling selection of a superior result through empirical metrics.  
**Mechanism:** Setting `temperature=1` induces run-to-run variability in token sampling. An ensemble of multiple runs (across models) generates a candidate set of outputs for the same input. A deterministic metric (CPR) then selects the output that best preserves the original document content, effectively using randomness as a search space exploration tool.  
**Core assumption:** The "best" output for a faithful document transformation task exists within the distribution of possible LLM outputs and can be identified by a content preservation metric.  
**Evidence anchors:** Abstract states the system leverages LLM performance variability; Section 3.2.1 describes using temperature=1 with multiple runs and choosing the best output based on metrics.  
**Break condition:** If the task has a single objectively correct answer, stochasticity may only generate incorrect variants, and the metric may fail to distinguish truly faithful output from plausible but incorrect hallucinations.

### Mechanism 2
**Claim:** The Content Preservation Ratio (CPR) metric, based on character bigram frequency, effectively quantifies unintended content alteration (hallucination/omission) in noisy document transformation.  
**Mechanism:** CPR computes the ratio of preserved bigram frequency between input and output. A higher ratio indicates fewer additions or omissions of character sequences. This provides an automated, reference-free fidelity check for cleaning and tagging tasks where the primary requirement is to preserve the source text verbatim while applying structural modifications.  
**Core assumption:** Character bigram frequency is a robust proxy for textual content integrity, even in OCR-corrupted, two-column formatted text where word-level or edit-distance metrics may be brittle.  
**Evidence anchors:** Abstract introduces CPR to avoid hallucinations; Section 3.3.1 defines CPR and justifies bigrams over edit distance due to noisy two-column format.  
**Break condition:** For text with highly repetitive or structured boilerplate (e.g., legal headers), bigram frequency may be preserved even if semantic meaning is altered, or minor OCR corrections might lower CPR despite being desirable changes.

### Mechanism 3
**Claim:** The Tag Well-Formedness (TWF) metric ensures syntactic correctness of the XML-like tagging output, a prerequisite for downstream parsing and knowledge graph construction.  
**Mechanism:** A simple deterministic algorithm tokenizes the output, tracking open/close tag pairs. TWF is the ratio of correctly nested and closed tag pairs to total pairs. This enforces structural validity independent of the semantic accuracy of tagged spans, preventing malformed XML that would break downstream pipelines.  
**Core assumption:** Well-formed XML structure is a necessary (though not sufficient) condition for a viable semantic tagging output; a syntactically invalid document is useless regardless of tag placement accuracy.  
**Evidence anchors:** Abstract mentions TWF for XML structure; Section 3.3.2 details the algorithm (matching closing tags to last open tag, ensuring no unclosed tags).  
**Break condition:** If the tagging schema requires attributes, mixed content, or complex nesting beyond simple open/close pairs, this basic TWF check would be insufficient to guarantee validity.

## Foundational Learning
- **LLM Output Stochasticity & Temperature:** Needed because the entire ensemble method depends on the LLM producing variant outputs from the same prompt when `temperature > 0`. Understanding the trade-off between consistency (temperature=0) and diversity is core to the design.  
  *Quick check:* What is the likely effect on the ensemble's candidate pool if `temperature` is set to 0?
- **N-gram Based Text Similarity Metrics:** Needed because CPR uses character bigram frequency as its core signal. One must understand why this is chosen over word-level or edit-distance metrics in the context of OCR noise and columnar text.  
  *Quick check:* Why might Levenshtein distance be less reliable than bigram frequency for measuring content preservation in two-column OCR text?
- **XML Well-Formedness vs. Validity:** Needed because TWF checks for *well-formedness* (proper nesting/closing), not *validity* against a schema. The system prioritizes syntactic parsability first.  
  *Quick check:* If an output has all tags properly closed but uses a tag not in the allowed list (`<place>` instead of `<location>`), would TWF be 100%? What would be missing?

## Architecture Onboarding
- **Component map:**  
  Input Loader -> Cleaning Pipeline -> Metrics Evaluator -> Ensemble Selector -> Cleaned Doc -> Tagging Pipeline -> Metrics Evaluator -> Ensemble Selector -> Output Writer  
  (Metrics Evaluator and Ensemble Selector are reused in both stages; Metrics computes CPR for cleaning, and CPR, TWF, nT for tagging.)
- **Critical path:** Raw Doc -> [Cleaning Ensemble: Pipeline + Metrics + Selector] -> Cleaned Doc -> [Tagging Ensemble: Pipeline + Metrics + Selector] -> Tagged XML Doc.
- **Design tradeoffs:**  
  - *Cost vs. Coverage:* More models/runs increase chance of a high-quality output but linearly increase cost. The experiment uses 2 runs/model as a fixed budget.  
  - *Metric Simplicity vs. Semantic Truth:* CPR/TWF are cheap, automatic proxies. They cannot guarantee correct semantic tagging (e.g., tagging "Council" as `<location>`), only content preservation and structure.  
  - *Model Diversity:* Using models of different sizes/generations (GPT-4.1 to GPT-5-nano) explores the performance-cost frontier. Omitting one tier might miss a cost-effective optimum.
- **Failure signatures:**  
  - *Cleaning Failure:* Consistently low CPR across all runs (<70%) suggests the prompt is inadequate for the document's noise level or the models are incapable. Output may have merged columns or unremoved hyphens.  
  - *Tagging Failure:* High CPR but low TWF (<95%) indicates the model preserved text but mangled tag syntax (unclosed tags). High TWF but low nT suggests overly conservative tagging.  
  - *Ensemble Stagnation:* If multiple runs/models produce identical outputs (low variability), the ensemble offers no benefit over a single run.
- **First 3 experiments:**  
  1. **Single vs. Ensemble Baseline:** Process 10 docs with a single run of GPT-4.1 (temp=0) and compare CPR/TWF to the 14-run ensemble. Hypothesis: Ensemble significantly improves CPR for cleaning by recovering from occasional poor runs.  
  2. **Runs-per-Model Sensitivity Test:** For a single model (e.g., GPT-4.1-mini), vary runs per document (1, 2, 5, 10). Plot CPR improvement vs. added cost. Identify point of diminishing returns to optimize the "2 runs" parameter.  
  3. **Metric Sanity Check against Human:** For 2–3 tagged documents, have a human annotator verify: (a) does the selected output have fewer hallucinations/omissions than a random non-selected output? (b) is the XML structure well-formed? This validates that CPR/TWF correlate with human-judged fidelity.

## Open Questions the Paper Calls Out
- **What ensemble methodology best consolidates multiple LLM tagging outputs to maximize tag coverage and consistency?** The current approach selects a single output per document, ignoring potential complementary tags from other runs. A comparison of aggregation strategies (e.g., union, intersection) on a validation set using metrics like nT and tag agreement is needed.
- **How should the custom XML tags be mapped to the Akoma Ntoso schema to ensure standards compliance?** The current tag set (<location>, etc.) is not aligned with Akoma Ntoso's structured elements, hindering interoperability. A defined mapping implemented in the pipeline, validated by Akoma Ntoso schema validators, would resolve this.
- **Do CPR and TWF metrics effectively measure semantic tagging quality as judged by human experts?** These automatic metrics may not capture semantic accuracy or practical usability for knowledge graph construction. Human evaluation of tagged documents correlated with CPR/TWF scores on a gold-standard subset would resolve this.

## Limitations
- **Model identifiers:** Paper's names (e.g., GPT-4.1, GPT-5-mini) may not map to current public API identifiers, blocking exact replication.
- **Chunking:** No strategy specified for documents exceeding 8k tokens; likely truncation or preprocessing occurred but is undocumented.
- **Metric limitations:** CPR uses bigram frequency—may preserve text even if semantic meaning is altered; TWF checks only basic nesting, not schema validity or attributes.

## Confidence
- **Ensemble via stochasticity:** Medium (LLM variability is documented, but the "best output exists in distribution" assumption is task-dependent and unproven)
- **CPR as fidelity proxy:** Medium (justified for OCR noise, but untested on highly repetitive boilerplate where bigrams persist despite semantic changes)
- **TWF for syntactic validity:** Medium-High (simple stack-based well-formedness is reliable for basic XML but insufficient for complex tagging schemas)
- **Cost-effectiveness claim:** Low (depends on current API pricing; paper provides no cost breakdown or sensitivity analysis)
