# Visual Prompt Discovery via Semantic Exploration

## Quick Facts
- arXiv ID: 2603.16250
- Source URL: https://arxiv.org/abs/2603.16250
- Reference count: 40
- Primary result: SEVEX achieves 78.9% average task accuracy on BlindTest/BLINK benchmarks, surpassing SketchPad by 14.3% while increasing inference cost by only 10.9% and reducing exploration cost to 11.5% of a competing automated method.

## Executive Summary
Large Vision-Language Models (LVLMs) suffer from systematic perception failures that are often addressed through manual, inefficient trial-and-error to discover effective visual prompts—executable code that manipulates input images. This paper introduces SEVEX, an automated framework that discovers task-specific visual prompts via semantic exploration. SEVEX constructs a dynamic tree over an abstract "idea space" of high-level strategies, using a novelty-guided search to navigate the vast prompt space efficiently. It incorporates semantic backpropagation from sample-wise analysis to learn from successes and failures, guiding future exploration. On challenging perception benchmarks, SEVEX significantly outperforms prior methods in accuracy and cost-effectiveness, while also demonstrating that optimal prompts are model-specific and do not transfer across LVLM backbones.

## Method Summary
SEVEX is an iterative, automated framework for discovering optimal visual prompts for a given LVLM on a specific task. It operates over an abstract idea space where each node represents a high-level strategy (e.g., "use depth estimation to check naturalness") rather than raw code. The framework maintains a dynamically expanding tree. In each iteration, a node is selected using a Novelty-guided UCT (NUCT) score that balances predicted gain, novelty relative to siblings, and parent saturation. The selected idea is translated into executable Python code and a text prompt by an Engineer agent, then run on a development set to obtain an accuracy reward. An Analyst agent performs sample-wise failure analysis to generate "Actionable Insights," which are consolidated and backpropagated to ancestor nodes' histories. Finally, an Expansion agent generates new sibling or child nodes, initialized with self-evaluation scores. This loop runs for a fixed number of iterations (50), after which the best-performing prompt (highest dev accuracy) is evaluated on a held-out test set.

## Key Results
- SEVEX achieves a 78.9% average task accuracy on BlindTest and BLINK benchmarks, outperforming the previous state-of-the-art automated method (SketchPad, 64.6%) by a large margin.
- Despite requiring more inference-time computation than a naive model, SEVEX’s inference cost increase is modest (10.9%), and its exploration cost (tokens per iteration) is only 11.5% of SketchPad+APE, a competing automated approach.
- Discovered prompts are highly model-specific; transferring prompts between different LVLM backbones (e.g., Gemini vs. GPT-4V) leads to significant performance drops, underscoring the need for automated, model-tailored optimization.

## Why This Works (Mechanism)
### Mechanism 1: Abstract Idea Space
- **Claim:** Operating on an abstract *idea space* (high-level strategies) instead of raw code mitigates the *distraction caused by lengthy, low-level code*.
- **Mechanism:** The agent first reasons about conceptual strategies before implementation. This decoupling prevents the LVLM/agent from being overwhelmed by implementation details, focusing exploration on semantic intent.
- **Core assumption:** LVLM perception failures are best addressed by high-level visual strategy changes, not fine-grained code tweaks; low-level code length directly contributes to context distraction.
- **Evidence anchors:** [abstract] "addresses two major challenges... (1) the distraction caused by lengthy, low-level code... leverages an abstract idea space"; [section 3.1] "define the search space in a high-level domain... each node represents a distinct *idea*".
- **Break condition:** If the mapping from abstract idea to executable code becomes a bottleneck (e.g., ideas consistently infeasible) or if failures stem from factors unaddressable by high-level strategy changes.

### Mechanism 2: Dynamic Tree Search with Novelty-Guided Selection
- **Claim:** A *dynamic tree search with novelty-guided selection* efficiently navigates the vast, unstructured prompt space.
- **Mechanism:** The tree expands with sibling/child nodes. Unexecuted nodes are prioritized by a score combining agent-predicted gain (`sgain`), novelty vs. siblings (`snovel`), and parent saturation. This encourages breadth (novelty) and depth (promising branches) without exhaustive search.
- **Core assumption:** The search space is combinatorially explosive; a guided tree search with exploration bonuses can find high-reward nodes with limited experiments. Novelty prevents saturation on mediocre branches.
- **Evidence anchors:** [abstract] "dynamic tree search with a novelty-guided selection algorithm"; [section 3.3] Novelty-guided UCT (NUCT) formula with saturation penalty; [section 4.4] Ablation shows "SEVEX w/o Tree Structure" underperforms on complex tasks.
- **Break condition:** If the agent's self-evaluation scores (`sgain`, `snovel`) are systematically misleading, guidance degrades to random walk.

### Mechanism 3: Semantic Backpropagation
- **Claim:** *Semantic backpropagation* from sample-wise analysis distills failure/success patterns into actionable insights that guide future ideation, improving sample efficiency.
- **Mechanism:** After executing a visual prompt, an analyst examines per-sample results to generate implications (e.g., "crop region was too small"). These are backpropagated and consolidated up the tree, influencing subsequent idea generation to avoid repeating mistakes and reinforce effective patterns.
- **Core assumption:** Raw accuracy scores are insufficient; fine-grained, semantic lessons from failures/successes are necessary to steer the high-level search and are transferable across similar idea branches.
- **Evidence anchors:** [abstract] "semantic feedback-driven ideation process... analyzing sample-wise results"; [section 3.5] "Rather than simply propagating numerical rewards, we implement Semantic Backpropagation... back-propagated to the Experiment History"; [section 4.4] Ablation shows "SEVEX w/o Semantic Backprop" underperforms.
- **Break condition:** If sample-wise analysis is too noisy or implications are too vague/incorrect, backpropagation injects harmful bias.

## Architecture Onboarding
- **Component map:** Idea Space & Tree (T) -> Selection Engine (NUCT) -> Engineer Agent -> LVLM + Tools -> Analyst Agent -> Insight Synthesizer -> Expansion Agent -> back to Tree. Core loop: Selection → Engineer → Execute → Analyst → Backpropagate → Expand.
- **Critical path:** Select node using NUCT; Engineer translates idea to implementation; Execute on dev set for accuracy reward; Analyst generates per-sample insights; Insights consolidated and backpropagated; Expansion generates new nodes; Tree updated.
- **Design tradeoffs:** Exploration cost vs. Stability (more iterations yield better prompts but higher upfront cost; tree depth/branching controls this); Abstractness vs. Feasibility (too abstract ideas may be un-implementable, too concrete limits exploration; Implementation step bridges); Sample-wise analysis depth (analyzing all dev samples is costly; using "representative images" trades detail for efficiency).
- **Failure signatures:** Stagnation (max reward never exceeds baseline, suggests insufficient idea space or tools); Divergence (high variance in rewards across sibling branches, suggests unstable LVLM responses or overly sensitive prompts); Backpropagation pollution (consistent performance drop after cycles, suggests flawed insight synthesis or dev set overfitting).
- **First 3 experiments:** 1. Sanity Check - Tool Execution: Verify visual toolset works (e.g., draw a line) and Engineer generates executable code from a simple idea. 2. Baseline Replication - Naive & SketchPad: Run Naive and SketchPad on one task (e.g., `LineIntersections`) to establish bounds and confirm failure modes. 3. Minimal SEVEX - Shallow Tree: Run SEVEX for 5 iterations on a single task with `k=1`; observe if any improvement over Naive occurs, testing the basic loop.

## Limitations
- **Generalizability:** Results are tied to Gemini-2.5-flash and a fixed 11-tool set; unknown if SEVEX transfers to other LVLMs (e.g., GPT-4o) or tool sets.
- **Evaluation Stability:** Dev set size is small (30 images/task); variance across different random splits is unreported, risking overfitting to a specific dev split.
- **Mechanism Evidence:** Causal role of the abstract idea space is inferred from ablations but not directly isolated; alternative explanations (e.g., tree structure alone) aren't fully disentangled.

## Confidence
- Performance Superiority (78.9% vs. 64.6%): Medium – Supported by benchmark numbers but depends on unreproduced implementation details and single-run results.
- Cost Efficiency (11.5% exploration cost vs. SketchPad+APE): Low-Medium – Token counts reported, but without runtime profiling, practical efficiency claim is weak.
- Non-Transferability across Backbones: Medium – Based on cross-backbone experiment (Sec. 4.5) with two models; broader validation needed.
- Mechanism Validity (idea space, tree search, backpropagation): Low – Supported by component ablations, but internal agent behaviors are black-box and lack fine-grained validation.

## Next Checks
1. **Cross-Model Replication:** Run SEVEX with at least two additional open-weight LVLMs (e.g., LLaVA-NeXT, InstructBLIP) on a subset of BlindTest tasks to confirm non-transferability and measure performance variance.
2. **Dev-Set Sensitivity Analysis:** Re-run SEVEX on 5 different random 30-image dev splits per task; report mean±std of final test accuracy to quantify stability risk from small dev sets.
3. **Ablate the Idea Space:** Replace the abstract idea generator with a direct code generator (no abstraction) while keeping tree search/backpropagation identical; compare convergence speed and final accuracy to isolate the benefit of high-level semantic reasoning.
