# IPD: Boosting Sequential Policy with Imaginary Planning Distillation in Offline Reinforcement Learning

## Quick Facts
- arXiv ID: 2603.04289
- Source URL: https://arxiv.org/abs/2603.04289
- Reference count: 40
- Primary result: IPD achieves state-of-the-art performance on D4RL benchmarks, significantly outperforming prior value-based and transformer-based methods across diverse tasks, with improved stability and a positive scaling law relating augmented data volume to performance.

## Executive Summary
Offline reinforcement learning (RL) aims to learn effective policies from static, previously collected datasets without further environmental interaction. Decision Transformers (DTs) have shown promise by treating RL as a sequence modeling problem, but they struggle to leverage suboptimal demonstrations and lack explicit planning capabilities, leading to suboptimal performance. The Imaginary Planning Distillation (IPD) framework addresses these limitations by integrating model-based planning with sequence modeling. IPD first learns a probabilistic ensemble world model to capture environment dynamics and an uncertainty measure, along with a quasi-optimal value function via Implicit Q-Learning. It then identifies suboptimal trajectories in the offline data by comparing real returns with imagined returns, and replaces them with reliable rollouts generated by Model Predictive Control (MPC) constrained to the model's uncertainty set. The resulting augmented dataset, which combines original demonstrations with high-quality imagined trajectories, is used to train a Transformer policy. The training employs a value-guided loss that regularizes action predictions using the learned Q-function, and replaces the conventional fixed return-to-go prompt with the state-dependent value function, eliminating manual tuning. On the D4RL benchmark, IPD sets new state-of-the-art results across Gym, Kitchen, and Adroit domains, demonstrating superior performance, enhanced stability, and a positive scaling law where performance improves as more augmented data is incorporated.

## Method Summary
IPD consists of three main stages. First, it learns a high-quality value function and an ensemble world model from the offline dataset. The value function is trained using Implicit Q-Learning (IQL) with Huber-expectile regression to obtain a quasi-optimal estimate without overestimation bias. The world model comprises an ensemble of probabilistic dynamics networks (Gaussian transitions) and a reward model, providing epistemic uncertainty via ensemble disagreement measured by geometric Jensen-Shannon divergence. Second, the method identifies suboptimal portions of the dataset by comparing the actual return of a state with an imagined return computed by rolling out the quasi-optimal policy through the world model over a horizon. States where the imagined return significantly exceeds the real return are selected. For each selected state, MPC is used to generate candidate trajectories (using the world model and value function for lookahead), and only rollouts in which all state-action pairs have uncertainty below a threshold are retained, ensuring reliability. These rollouts augment the original dataset. Third, a Transformer policy is trained on the combined dataset with a loss that combines standard action prediction and a Q-value regularization term that encourages higher-valued actions. At inference, the policy is conditioned not on a manually specified return-to-go but on the learned value function V_ψ(s), which provides a dynamic, state-appropriate prompt. This distillation transfers the planning knowledge of the value function and world model into the sequence model.

## Key Results
- IPD achieves state-of-the-art normalized returns on D4RL benchmarks, surpassing both value-based methods (e.g., IQL, CQL) and transformer-based approaches (e.g., DT, QDT).
- The framework demonstrates consistent improvements across diverse domains (Gym, Kitchen, Adroit) and exhibits greater training stability compared to prior transformer methods.
- Empirical analysis reveals a positive scaling law: increasing the volume of augmented imaginary data leads to monotonic performance gains, confirming the effectiveness of the data augmentation strategy.

## Why This Works (Mechanism)
### Mechanism 1: Uncertainty-Aware Data Augmentation
- **Claim**: IPD replaces suboptimal trajectories with reliable MPC rollouts by leveraging uncertainty estimation.
- **Mechanism**: A quasi-optimal value function computes imaginary returns (via MPC rollouts) and real returns from offline data; states with high return difference are selected. MPC generates rollouts constrained to an uncertainty set derived from an ensemble world model's disagreement, ensuring only confident predictions augment the dataset.
- **Core assumption**: The uncertainty measure (geometric Jensen-Shannon divergence) accurately flags unreliable model predictions, preventing error propagation.
- **Evidence**: The paper's abstract describes learning a world model with uncertainty and replacing suboptimal trajectories with imagined optimal rollouts. Section 3.3 details the suboptimal state identification via return comparison and the MPC planning with uncertainty constraint (Eqs. 12, 25). The method is inspired by model-based planning work like TD-MPC but adds offline-specific uncertainty filtering.
- **Break condition**: If the uncertainty threshold κ is too lenient, noisy rollouts corrupt the augmented data; if too strict, augmentation is insufficient, limiting performance gains.

### Mechanism 2: Value-Guided Policy Distillation
- **Claim**: IPD distills planning knowledge by regularizing Transformer training with Q-function gradients and using the value function as a dynamic return-to-go (RTG) prompt.
- **Mechanism**: The training loss combines mean-squared error action prediction with a Q-value regularization term (∇_η Q(s, π_η(context, V_ψ(s), s))), encouraging the policy to take actions with higher predicted value. The value function V_ψ(s) is also used at inference as the RTG prompt instead of a manually tuned constant, providing state-dependent guidance.
- **Core assumption**: The quasi-optimal value function, trained via Huber-expectile IQL, offers stable and optimal targets for both data augmentation and policy training.
- **Evidence**: The abstract mentions a value-guided objective that promotes distillation of the optimal policy and replacing manually-tuned RTG with the learned value function. Section 3.4 presents the IPD loss (Eq. 26) with Q-regularization and dynamic RTG. The use of value guidance relates to prior works like QT and Reformer, but IPD uniquely combines it with MPC-augmented data.
- **Break condition**: If the value function overestimates out-of-distribution actions due to dataset bias, it may misguide the policy, especially for states outside the augmented distribution.

### Mechanism 3: MPC for Trajectory Stitching
- **Claim**: MPC generates coherent optimal rollouts that stitch suboptimal segments into high-return trajectories.
- **Mechanism**: Given a candidate state, MPC samples multiple trajectories (horizon H_m) using the world model and selects the first action from the trajectory with highest cumulative discounted return (Eq. 25). This combines multi-step lookahead with the value function's estimate of the remaining horizon, allowing the policy to improve upon myopic actions in suboptimal data.
- **Core assumption**: Short-horizon MPC with a learned model can approximate optimal actions within reliable regions, compensating for suboptimal demonstrations.
- **Evidence**: The abstract describes reliable, imagined optimal rollouts generated via Model Predictive Control. Section 3.3 outlines the MPC procedure, including how the value function is used in return computation and an uncertainty check. The effectiveness of MPC in model-based RL is well-established (e.g., TD-MPC), and IPD adapts it to offline settings via uncertainty-aware rollouts.
- **Break condition**: If the MPC horizon H_m is too long, model errors compound; if too short, actions become myopic and fail to stitch long-horizon goals.

## Foundational Learning
- **Concept**: Ensemble World Model with Uncertainty Quantification  
  - **Why needed**: To simulate environment transitions for data augmentation while quantifying epistemic (model) uncertainty, ensuring only high-confidence rollouts are trusted.  
  - **Quick check**: Why use an ensemble of Gaussian models instead of a single deterministic model? (Answer: Ensemble disagreement estimates epistemic uncertainty, critical for filtering unreliable predictions in offline settings.)

- **Concept**: Implicit Q-Learning (IQL) with Huber-Expectile Regression  
  - **Why needed**: To learn a quasi-optimal value function from offline data without OOD overestimation, providing targets for augmentation and policy guidance.  
  - **Quick check**: How does Huber-expectile loss improve robustness over standard expectile regression? (Answer: It reduces sensitivity to outliers by transitioning from quadratic to linear penalty beyond a threshold.)

- **Concept**: Model Predictive Control (MPC)  
  - **Why needed**: For planning in the learned model to generate optimal actions that improve upon suboptimal demonstrations during augmentation.  
  - **Quick check**: Why not directly use the quasi-optimal policy (π_QOP) for rollouts instead of MPC? (Answer: MPC allows multi-step lookahead and can select better first actions by evaluating full trajectories, whereas π_QOP may be myopic.)

## Architecture Onboarding
- **Component map**: Offline Dataset -> Learn World Model & Value Function -> Identify Suboptimal States -> Generate MPC Rollouts (Uncertainty Filtered) -> Augmented Dataset -> Train Transformer with Value-guided Loss & Dynamic RTG -> Policy  
  (Note: The Value Function is reused at multiple stages: for state selection, MPC return computation, and as RTG during policy training and inference.)

- **Critical path**: The core pipeline comprises: (1) train a probabilistic ensemble world model and a quasi-optimal value function (via IQL) on the offline data; (2) compute return discrepancies to select suboptimal states; (3) for each, run MPC (with world model and value function) to generate a rollout that passes the uncertainty constraint; (4) merge these rollouts into the training set; (5) train a GPT-style Transformer on the augmented trajectories using the IPD loss (action MSE + Q-regularization) while conditioning on V_ψ(s_t) as return-to-go.

- **Design tradeoffs**:
  - Uncertainty threshold κ: Lower values increase reliability but reduce augmentation volume; higher values risk incorporating erroneous rollouts.
  - MPC horizon H_m: Longer horizons improve planning but increase computational cost and sensitivity to model errors.
  - Augmentation ratio N_aug: More augmented data generally improves performance (scaling law) but requires more compute and storage.

- **Failure signatures**:
  - High variance in evaluation scores: Likely from unstable value function or poor RTG replacement, causing inconsistent policy behavior.
  - Degradation on complex tasks (e.g., Adroit): May indicate world model cannot capture complex dynamics or MPC horizon is insufficient.
  - Overfitting to augmented data: If uncertainty filter is too permissive, the policy may memorize low-quality rollouts.

- **First 3 experiments**:
  1. **Main benchmark comparison**: Evaluate IPD against baselines (IQL, CQL, DT, QDT, etc.) on D4RL Gym, Kitchen, and Adroit tasks to demonstrate SOTA performance.
  2. **Ablation on data generation methodology**: Compare MPC-based augmentation vs. greedy Q-learning (using π_QOP directly) to show MPC's superiority in generating high-quality rollouts.
  3. **Scaling law analysis**: Vary the volume of augmented data (controlled by N_aug) and measure policy performance to reveal a positive correlation, validating the benefit of imaginary data.

## Open Questions the Paper Calls Out
1. **Uncertainty Measure Reliability**: How well does the Jensen-Shannon (GJS) divergence-based uncertainty U(s,a) correlate with the actual reliability of model-predicted rollouts in unseen environments? The paper uses U(s,a) to filter rollouts but does not empirically validate that low uncertainty directly translates to high-fidelity predictions on held-out domains. Without such validation, it is unclear whether U(s,a) effectively captures epistemic uncertainty or merely reflects in-distribution coverage, potentially allowing corrupt rollouts into the augmented dataset. Controlled experiments measuring ground-truth transition errors against U(s,a) across diverse OOD states from multiple D4RL tasks, and comparing GJS with alternative estimators (e.g., ensemble variance, likelihood-based), would help resolve this.

2. **Universality of the Scaling Law**: Does the observed positive scaling law between augmented data volume and performance hold universally across all offline RL task families, or does it break down in sparse-reward or highly stochastic environments? The paper notes a positive scaling law based on limited D4RL medium-replay tasks; it is not tested on, e.g., sparse-reward Adroit or long-horizon Kitchen tasks with different data qualities. In severely suboptimal or noisy datasets, augmenting more data could inject harmful biases. Systematic variation of N_aug across a broader suite (including sparse and long-horizon) would identify breaking points and correlate with world model error metrics.

3. **Sensitivity to Value Function Errors**: How sensitive is IPD's final performance to inaccuracies in the pretrained quasi-optimal value function Vψ(s), given its central role in suboptimal state identification, MPC returns, and dynamic RTG prompting? The pipeline relies on Vψ for multiple steps, yet the paper does not analyze failure modes when Vψ is inaccurate. In offline RL, value overestimation/underestimation is common; misranking states could corrupt the augmented dataset. Artificially perturbing Vψ (adding bias, noise, or dropout) and measuring performance degradation relative to baselines would quantify this sensitivity and reveal potential brittleness.

4. **Inference-Time Efficiency Trade-off**: What are the computational trade-offs of IPD's inference-time use of the learned value function for dynamic RTG, compared to manually tuned return-to-go search in Decision Transformers? IPD eliminates costly manual tuning and improves stability, but querying a neural value function at every timestep adds forward passes. The net efficiency gain depends on the relative cost of the value network versus multiple DT rollouts, which is task-dependent. Benchmarking wall-clock inference latency and memory footprint of IPD against DT with RTG search across varying context lengths and batch sizes would clarify the speed-accuracy trade-offs.

5. **Interaction of MPC Parameters and Uncertainty Threshold**: How do the choices of MPC horizon H_m, number of rollouts N_mpc, and uncertainty threshold κ jointly affect the diversity and optimality of augmented trajectories? These parameters are set heuristically; the paper does not study their joint effect on coverage or risk of model exploitation. Grid searches over these hyperparameters across tasks, evaluating augmented trajectory diversity (state-space coverage) and correlation between cumulative MPC returns and downstream performance, would identify robust settings and interactions.

## Limitations
- **Uncertainty threshold (κ)**: The exact value for filtering reliable MPC rollouts is unspecified. A poor choice risks either corrupting data (κ too high) or insufficient augmentation (κ too low).
- **Data selection strategy**: The implementation of top-K state selection (per-trajectory vs. global) and the precise role of N_aug in the selection formula are ambiguous, affecting augmentation diversity and scaling behavior.
- **Scaling law quantification**: While a positive correlation between augmented data volume and performance is claimed, the functional form and specific N_aug ranges tested are not detailed, limiting predictive utility.
