# Lead Zirconate Titanate Reservoir Computing for Classification of Written and Spoken Digits
## Quick Facts
- **ArXiv ID:** 2604.00207
- **Source URL:** https://arxiv.org/abs/2604.00207
- **Reference Count:** 0
- **Primary Result:** A physical reservoir using an unpoled PZT cube achieves 89.0% accuracy on MNIST, a 2.4 percentage point improvement over the best linear baseline (86.6%).

## Executive Summary
This study presents a physical reservoir computing system built from an unpoled lead zirconate titanate (PZT) cube. The system classifies handwritten digits (MNIST) and spoken digits (AudioMNIST) by encoding images/audio into 8-bit binary sequences, driving them through the PZT cube, and using the resulting voltage trace as features for a logistic regression readout. The reservoir significantly outperforms strong linear baselines on MNIST (89.0% vs 86.6%) but performs comparably on AudioMNIST (88.2% vs 88.1%). The authors argue that physical reservoirs offer the greatest benefit for tasks of "intermediate difficulty"—where linear methods fail but complex models like CNNs are not strictly necessary. A CNN trained on the same preprocessed data sets an upper bound, suggesting the reservoir's value is task-dependent.

## Method Summary
The core pipeline transforms data into a 1D binary stream via task-specific preprocessing (Hilbert curve for MNIST, vertical scan after MFCC for AudioMNIST), then groups bits into 1024 consecutive 8-bit vectors. A Teensy 4.1 microcontroller drives these parallel 8-bit values onto the PZT cube at a configurable nanosecond-scale delay. The cube's nonlinear and temporally extended response is captured by an oscilloscope as an 8192-sample voltage trace per input sequence. After a reset period, this trace serves as a high-dimensional feature vector. A fixed-architecture logistic regression readout is trained on these features. The same readout and preprocessing are used for baseline comparisons (direct logistic regression, summed window, Gaussian noise injection), isolating the computational contribution of the physical PZT reservoir.

## Key Results
- On MNIST, the PZT reservoir achieves **89.0%** test accuracy, significantly outperforming the best baseline (summed window logistic regression) at **86.6%**.
- On AudioMNIST, the reservoir achieves **88.2%** accuracy, statistically equivalent to the best baseline of **88.1%**.
- CNN upper bounds on the preprocessed binary data are **97.4%** (MNIST) and **90.1%** (AudioMNIST), indicating the reservoir provides a bridge between simple linear models and optimal classifiers for the given representation.

## Why This Works (Mechanism)
### Nonlinear Feature Expansion
The PZT cube's nonlinear current-voltage characteristics transform linearly inseparable 1024-bit input patterns into a higher-dimensional (8192-sample) feature space where classes become more separable for a linear classifier. The physical nonlinearity provides a richer basis for expansion than simple linear combinations or noise injection. Evidence includes the significant MNIST improvement over a Gaussian noise baseline and the paper's explicit attribution of performance to the material's strong nonlinearity.

### Fading Memory Temporal Processing
The piezoelectric stress-strain dynamics give PZT a fading memory: previous inputs create persistent mechanical/electrical states that interact with subsequent signals. This temporal coupling allows the single-node reservoir to process sequential dependencies in the 8-bit stream, mimicking a recurrent layer. The existence of an optimal timing parameter (~10 ns delay) supports this mechanism, as performance peaks when the clock rate matches the material's decay timescale.

### Intermediate-Difficulty Task Benefit
The reservoir provides net benefit primarily for tasks where baseline linear methods underperform but the problem remains within the reservoir's computational capacity (i.e., before a CNN's upper bound is reached). MNIST showed a substantial baseline-reservoir gap, while AudioMNIST did not, consistent with this hypothesis. The contrast suggests reservoir computing is not universally superior but depends on aligning task complexity with substrate dynamics.

## Architecture Onboarding
Input Encoder -> Signal Generator -> Physical Reservoir -> Signal Acquisition -> Feature Store -> Trainable Readout

**Critical Path:** Dataset -> Preprocessing (to 1D binary) -> Sliding Window (to 8-bit vectors) -> Teensy Drive Sequence -> PZT Physical Transformation -> Oscilloscope Capture -> Feature Vector -> Logistic Regression Training/Inference.

**Design Tradeoffs:**
- **Encoding:** Hilbert curve (MNIST) preserves 2D spatial locality; vertical scan (AudioMNIST) preserves temporal spectral structure. Tradeoff between locality and alignment with reservoir's sequential processing.
- **Timing Parameter (Delay):** Controls effective "clock rate" relative to PZT's decay. Too fast (5 ns): states don't develop. Too slow (20 ns): memory decays. Optimal ~10 ns.
- **Binary vs. Analog Input:** Binary ensures voltage swing and reliability; analog could encode more information but risks distortion and hardware complexity.
- **Dimensionality:** 1024-bit input -> 8192-sample output. Higher dimension increases classifier capacity but risks overfitting with limited data.

**Failure Signatures:**
- **No reservoir benefit:** Accuracy ≈ direct/summed-window baseline. Indicates task too simple or reservoir dynamics not excited properly (wrong timing, faulty connections).
- **High variance across folds:** σ > 2%. Suggests unstable dynamics from timing sensitivity, temperature drift, or contact issues.
- **Benefit eliminated by Gaussian noise baseline:** Implies advantage may stem from stochastic separation rather than intended nonlinear dynamics.

**First 3 Experiments:**
1. **Baseline Replication & Attribution:** With PZT disconnected (or replaced by wire), run full pipeline for Direct LR, Summed Window, and Gaussian Noise baselines. Verify accuracies match paper (~86.6% MNIST, ~88.1% AudioMNIST) to confirm encoding/readout pipeline.
2. **Timing Parameter Sweep:** For a fixed dataset (e.g., 1000 MNIST samples), run reservoir pipeline at 5 ns, 10 ns, 15 ns, 20 ns, 25 ns, 50 ns delays. Plot accuracy vs. delay; expect peak near 10 ns to validate timing assumption and find system-specific optimum.
3. **Noise Robustness & Variance Check:** At optimal timing, process same test set 10+ times. Calculate mean and standard deviation. Also vary timing slightly (±2 ns). High run-to-run variance or sensitivity indicates fragile operating regime; may need better shielding or stabilization.

## Open Questions the Paper Calls Out
- **Which ML tasks benefit most?** The paper compared only two tasks; the "intermediate difficulty" principle lacks systematic validation across diverse problems. Resolution requires benchmarking on a broad suite with quantifiable difficulty metrics.
- **What properties of MNIST made it amenable?** Was it the Hilbert scan's locality preservation, digit variability, or something else? Ablation studies varying preprocessing (scan curves, binarization, analog levels) are needed.
- **How can encoding be optimized?** Current binary sliding window discards information. Alternative encodings (analog amplitudes, frequency modulation) could better leverage reservoir nonlinearity. Testing diverse encodings and measuring feature quality/accuracy would resolve this.

## Limitations
- **Missing hardware details:** Exact pad selection, oscilloscope firmware mods, and Teensy timing code are unspecified, hindering exact replication.
- **CNN upper bound issue:** The CNN was trained on the same preprocessed binary data, potentially understating true task difficulty and weakening the intermediate-difficulty claim.
- **Overfitting risk:** High-dimensional features (8192) with limited training samples raise overfitting concerns; regularization strategy and hyperparameter search are not thoroughly detailed.

## Confidence
- **Nonlinearity-driven feature expansion:** High – Significant MNIST improvement over strong baselines, including a Gaussian noise control.
- **Fading memory mechanism:** Medium – Timing sweep shows a performance peak, but causality is not cleanly isolated from static nonlinearity.
- **Intermediate-difficulty hypothesis:** Medium – Inference based on only two datasets; broader task diversity is required for validation.
