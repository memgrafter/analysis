# IGenBench: Benchmarking the Reliability of Text-to-Infographic Generation

## Quick Facts
- arXiv ID: 2601.04498
- Source URL: https://arxiv.org/abs/2601.04498
- Reference count: 40
- Primary result: IGenBench reveals that current text-to-infographic models, despite achieving high question-level accuracy (Q-ACC up to 0.90), suffer from fragile end-to-end correctness (infographic-level accuracy I-ACC ≤ 0.49) due to universal bottlenecks in data-related dimensions, indicating they are not yet reliable for autonomous infographic generation.

## Executive Summary
Text-to-infographic (T2I) generation lacks reliable automatic evaluation. IGenBench introduces a benchmark of 600 curated prompts spanning 30 infographic types and an automated evaluation framework that decomposes verification into 10 atomic yes/no question types answered by a multimodal LLM. The framework yields question-level accuracy (Q-ACC) and infographic-level accuracy (I-ACC). Evaluating 10 T2I models shows a three-tier performance hierarchy, with the top model achieving Q-ACC 0.90 but I-ACC only 0.49. Data Completeness emerges as a universal bottleneck (approx. 0.21), and the large gap between Q-ACC and I-ACC across all models highlights the fragility of end-to-end correctness. The evaluation aligns strongly with human judgment (Pearson correlation 0.90), underscoring that current T2I models are not yet suitable for autonomous infographic generation without significant improvements.

## Method Summary
IGenBench’s evaluation pipeline operates without training. For each of the 600 prompts, the system first generates a set of verification questions derived from the prompt text and three seed requirements (Data Completeness, Data Ordering, Data Encoding). These questions are classified into 10 types (e.g., presence of labels, correct chart type). A multimodal LLM (Gemini-2.5-Pro) answers each question with a yes/no judgment on the generated infographic image. Question-level accuracy (Q-ACC) is the fraction of correctly answered questions; infographic-level accuracy (I-ACC) is the fraction of prompts for which all questions are answered correctly. The dataset and ground-truth data are publicly released, enabling reproducible evaluation.

## Key Results
- **Three-tier model hierarchy**: Top model (e.g., DALL-E 3) reaches Q-ACC 0.90 but I-ACC 0.49, showing that high partial correctness does not guarantee end-to-end success.
- **Data Completeness bottleneck**: All models struggle with Data Completeness (scores around 0.21), failing to include all required data points from the prompt.
- **Wide Q-ACC/I-ACC gap**: The large discrepancy between the two metrics across the board indicates that even models with few per-question failures have near-zero I-ACC, revealing fragility in meeting all constraints simultaneously.

## Why This Works (Mechanism)
The framework works because it decomposes the complex, holistic task of infographic verification into atomic, binary questions that are easier for a multimodal LLM to answer reliably. Each question targets a specific visual or semantic constraint (e.g., “Does the chart include a title?”). The seed requirements ensure coverage of critical data-related dimensions (Completeness, Ordering, Encoding). By aggregating answers, the system provides both fine-grained diagnostics (Q-ACC per question type) and a strict end-to-end correctness measure (I-ACC). The use of a powerful MLLM (Gemini-2.5-Pro) that strongly correlates with human judgment (Pearson 0.90) ensures that automated scores are meaningful and consistent.

## Architecture Onboarding
Prompt -> Question Augmentation -> T2I Model -> Infographic Image -> MLLM Evaluation -> Q-ACC/I-ACC

**Critical Path**: From an input prompt to final metrics, the pipeline flows: (1) generate verification questions (prompt-based + seed requirements), (2) produce an infographic via a T2I model, (3) feed the image and each question to the MLLM, (4) collect yes/no answers, (5) compute Q-ACC and I-ACC.

**Design Tradeoffs**: 
- Using a single MLLM (Gemini-2.5-Pro) increases consistency but may bias results toward its strengths.
- Binary yes/no questions simplify evaluation but may lose nuance (e.g., “partially correct”).
- Seed requirements guarantee coverage of data dimensions but might miss other infographic aspects.
- Strict I-ACC (all-or-nothing) measures reliability but may penalize models for minor, irrelevant errors.

**Failure Signatures**:
- High Q-ACC but I-ACC ≈ 0: The model fails at least one constraint on many prompts; the failing question type may be rare but critical.
- Uniformly low Data Completeness: The model omits required data points across types.
- Disagreement across models on specific question types indicates those aspects are particularly challenging (e.g., Data Ordering).

**First Three Experiments**:
1. **MLLM robustness check**: Run the evaluation with a different MLLM (e.g., GPT-4o) on a small subset to see if rankings change.
2. **Prompt formatting sensitivity**: Vary the data table serialization (CSV, YAML) in the prompts and measure score differences.
3. **Multi-panel verification audit**: Manually inspect 5 multi-chart infographics to verify that the “Bonus” question generation logic correctly isolates per-chart constraints.

## Limitations
- Exact data table string format used in prompts is undisclosed, making full reproduction sensitive to serialization choices.
- Gemini-2.5-Pro evaluation settings (temperature, top-p) are not reported, which could affect answer consistency.
- The “Bonus” handling for multi-panel infographics—generation of per-chart questions—is underspecified.
