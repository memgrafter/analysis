# OneLatent: Single-Token Compression for Visual Latent Reasoning

## Quick Facts
*   **arXiv ID:** 2602.13738
*   **Source URL:** https://arxiv.org/abs/2602.13738
*   **Reference Count:** 7
*   **Primary Result:** Compresses full Chain-of-Thought reasoning into a single latent token, reducing output length by 11× with only a 2.21% average accuracy drop across five reasoning benchmarks.

## Executive Summary
OneLatent addresses the high inference cost of Chain-of-Thought (CoT) reasoning by replacing verbose textual intermediate steps with a single, continuous latent token. The method uses a deterministic text-to-image rendering of the CoT trace and a frozen DeepSeek-OCR vision encoder to extract a dense hidden-state target. A language model is then trained via a three-stage curriculum to align its latent token representation to this visual target. This provides a stable, inspectable supervision signal without requiring the model to generate the CoT text during inference. On long-chain logical reasoning tasks, OneLatent achieves near-perfect accuracy with extreme token compression (up to 87.4×), demonstrating effective compression-constrained generalization.

## Method Summary
The core pipeline begins with a standard CoT generation for training examples. These textual reasoning steps are deterministically rendered into fixed-size images (1024x1024 PNGs). A frozen DeepSeek-OCR vision-encoder stack processes each image, and its final hidden state at the last visual position is extracted as a high-dimensional target vector `v`. The target language model is trained in three stages: 1) a "cold start" on standard (Question + CoT + Answer) sequences to establish a reasoning prior, 2) alignment where the model's special `<|begin-latent|>` token's hidden state `h_bot` is regressed toward `v` via MSE loss while predicting the answer, and 3) fine-tuning with the single-latent interface but without the MSE loss, allowing the model to internalize the compressed representation for optimal answer generation. At inference, the model processes a prompt containing only the question and the single latent slot before autogregressively decoding the answer.

## Key Results
*   Compresses average output length by 11× (from 74.62 to 6.78 tokens) with a minor 2.21% average accuracy drop relative to standard textual CoT.
*   Improves the proposed Output Token Contribution (OTC) efficiency metric by 6.8×.
*   Achieves near-perfect accuracy on long-chain logical reasoning with one token (99.80% on ProntoQA, 97.80% on ProsQA) and compression ratios up to 87.4× on enhanced datasets.

## Why This Works (Mechanism)

### Mechanism 1: Visual Target Alignment
*   **Claim:** Aligning a single latent token to frozen vision-encoder hidden states from rendered CoT images provides a stable, inspectable supervision signal that compresses multi-step reasoning.
*   **Mechanism:** The full textual CoT is rendered into a fixed-size image. A frozen DeepSeek-OCR encoder processes this image, and its final hidden state `v` is used as a regression target for the LLM's latent token hidden state `h_bot` via MSE loss during Stage 2. This transfers the structured information of the entire reasoning trace into one continuous vector.
*   **Core Assumption:** The vision encoder's hidden state is a sufficient and stable representation of the complete CoT's semantic and logical content for the target task.
*   **Evidence Anchors:** Abstract, Section 3.4 (target extraction), and Table 3 (ablations showing Stage 2's necessity).
*   **Break Condition:** Significant rendering distortion or a misalignment between the vision encoder's representation space (trained for OCR) and the LLM's reasoning logic could cause sharp accuracy drops.

### Mechanism 2: Three-Stage Curriculum
*   **Claim:** A curriculum (cold start CoT → latent alignment → answer fine-tuning) stabilizes training under extreme token compression.
*   **Mechanism:** Stage 1 builds a baseline reasoning prior with explicit CoT generation. Stage 2 introduces the single-latent interface and the MSE alignment objective, overriding the CoT path. Stage 3 removes the alignment loss, prompting the model to consolidate the latent representation for pure answer generation.
*   **Core Assumption:** Direct training with the single-latent interface from scratch would fail due to the lack of a pre-trained reasoning prior and the difficulty of aligning to high-dimensional visual targets.
*   **Evidence Anchors:** Abstract, Section 3.5 (loss definitions), and Table 3 (staged ablation showing Stage 2 and 3 contributions).
*   **Break Condition:** Improper ordering or an abrupt transition from Stage 2 to Stage 3 could cause catastrophic forgetting of the latent representation.

### Mechanism 3: MDL-Induced Inductive Bias
*   **Claim:** A fixed single-latent token interface acts as a Minimum Description Length (MDL)-style inductive bias, forcing the model to encode only sufficient computation for the answer.
*   **Mechanism:** The strict one-slot budget prevents the model from emitting verbose or redundant textual scaffolds. The training objectives (visual alignment followed by answer-only loss) implicitly optimize for a compressed internal state that is merely informative enough to generate the correct answer.
*   **Core Assumption:** A single high-dimensional vector can encapsulate the intermediate state of multi-step logical/arithmetic reasoning for the tested benchmarks.
*   **Evidence Anchors:** Abstract, Section 1 (MDL discussion), and results showing preserved accuracy with massive compression on logical tasks.
*   **Break Condition:** Tasks where the reasoning chain itself is the required output (e.g., verification, pedagogy) or where intermediate states are highly sequential/non-linear would likely see unacceptable degradation, as hinted by performance on arithmetic-heavy benchmarks.

## Architecture Onboarding

### Component Map
Rendering Module (Algorithm 1) -> Target Extraction Pipeline (Frozen DeepSeek-OCR) -> Target Vector `v` (disk storage) -> Training Loop (Three-Stage Scheduler with MSE loss in Stage 2) -> Inference Engine (Question + 1 latent token -> Answer)

### Critical Path
1.  Generate standard CoT traces for training data.
2.  Render each CoT into a fixed-size PNG (offline, precomputation).
3.  Extract a single `[1, d_model]` target vector `v` from each image using the frozen vision encoder (offline).
4.  Stage 1: Train LM on (Question + CoT + Answer) to establish reasoning prior.
5.  Stage 2: Train LM on (Question + [latent] + Answer) with an additional MSE loss between the latent token's hidden state `h_bot` and the precomputed `v`.
6.  Stage 3: Continue training on (Question + [latent] + Answer) but remove the MSE loss to fine-tune for answer generation.
7.  Inference: For a new question, format it with the single latent slot and decode only the answer tokens.

### Design Tradeoffs
*   **Single vs. Multi-token latent:** Single token maximizes compression and simplicity but risks losing capacity for complex, multi-faceted reasoning; multi-token retains more compute.
*   **Frozen vs. Trainable vision encoder:** Frozen provides stable, inspectable targets but may have a domain gap with rendered images; trainable could adapt but risks instability and loses auditability.
*   **Fixed canvas size vs. dynamic:** Fixed size enables deterministic targets and efficient batching but may force extreme font scaling for very long CoTs, potentially harming OCR quality.

### Failure Signatures
*   **OCR Quality Check Failure:** The rendering algorithm (Algorithm 1) repeatedly fails to meet the quality threshold `τ` for a sample, resulting in a missing `.png` or `.pt` file and an unusable training target.
*   **Alignment Loss Divergence:** During Stage 2, the MSE loss (`||h_bot - v||²`) trends upward or becomes NaN, suggesting poor latent token initialization or an incompatible target space.
*   **Stage 3 Accuracy Collapse:** Upon dropping the MSE loss, validation accuracy plummets. This indicates the latent representation was not properly consolidated in Stage 2 and relied on the alignment loss as a crutch.

### First 3 Experiments
1.  **Reproduce rendering pipeline:** Process 10 GSM8K-Aug CoT samples through Algorithm 1. Visually inspect all output images for readability, consistent font, and proper 1024x1024 canvas fit.
2.  **Validate target extraction:** Feed 5 rendered images into the frozen DeepSeek-OCR stack. Confirm the output is a `[1, d_model]` vector and that vector norms are stable across samples without extreme outliers.
3.  **Run Stage 1 baseline:** Train a base model for 1 epoch using only Stage 1 (explicit CoT) on a small subset (e.g., 1000 GSM8K samples). Record baseline CoT accuracy and average output length to establish the pre-compression reference.

## Open Questions the Paper Calls Out
The paper asks: "Can we train a model that *only* performs reasoning in its latent space, and if so, what is the minimal sufficient interface?" It also questions the theoretical limits of single-token compression for different reasoning types and whether the visual-supervision approach can be generalized to other modalities or encoder choices.

## Limitations
*   **Representation Sufficiency:** The core assumption that a single frozen vision-encoder hidden state is a sufficient supervisory target is validated only on selected benchmarks. Performance drops on arithmetic-heavy tasks (GSM8K-Hard, SVAMP) suggest limitations for dense, sequential computation.
*   **Vision-Encoder Domain Gap:** The DeepSeek-OCR encoder is trained on natural documents. Rendered CoT images are synthetic with fixed layouts; potential scaling distortions for long traces may create a domain gap not quantified.
*   **Task Scope:** Evaluation is limited to question-answer benchmarks. The method's applicability to tasks where the reasoning chain itself is the output (e.g., verification, proof generation) is unknown and likely limited by extreme compression.

## Confidence
*   **Claim 1 (Visual Target Alignment Mechanism):** Medium Confidence. Strong internal evidence (ablation in Table 3) but lacks external validation; the causal link from rendering → vision state → latent token → accuracy is correlational.
*   **Claim 2 (Curriculum Stabilization):** High Confidence (Internal), Medium Confidence (Generalization). The paper's own ablations robustly show the curriculum's necessity for their results. Confidence is lower for whether this exact sequence is optimal across different models/tasks.
*   **Claim 3 (Single-Token Sufficiency & MDL Bias):** Medium Confidence. Results on logical chain tasks (ProntoQA/ProsQA) are compelling, but the average 2.21% accuracy drop masks significant variance. The boundary of what reasoning survives extreme compression is not mapped.

## Next Checks
1.  **Render Quality Stress Test:** Systematically vary CoT length (5, 20, 50 steps) on long-chain tasks. For each, run the rendering algorithm and compute an OCR readability score (e.g., Tesseract confidence). Correlate this score with final model accuracy on the corresponding samples to test if rendering distortion is a primary failure mode.
2.  **Vision-Encoder Representation Probe:** Extract target vectors `v` from rendered CoT images and from a matched set of *natural* text images (photos of handwritten/printed reasoning). Train two identical OneLatent models using each `v` source. Compare their accuracy and OTC on a held-out set to quantify the domain gap's impact.
3.  **Curriculum Transition Ablation:** Modify Stage 3 to gradually anneal the MSE loss weight (from Stage 2's weight to 0) over several steps instead of an immediate drop. Train on a long-chain logical benchmark (e.g., ProsQA) and measure final accuracy and training stability (loss variance). An improvement would validate the hypothesized fragility of the abrupt transition.
