# Personalized Fall Detection by Balancing Data with Selective Feedback Using Contrastive Learning
## Quick Facts
- arXiv ID: 2603.17148
- Source URL: https://arxiv.org/abs/2603.17148
- Reference count: 37
- Primary result: Selective feedback via gradient-based ranking and contrastive learning improves average F1-score by up to 25% in personalized fall detection, from 0.73 to 0.91.

## Executive Summary
Personalized fall detection suffers from data imbalance: scarce fall events and abundant non-fall (ADL) feedback bias models toward routine activities and reduce fall sensitivity. This paper addresses the problem by combining semi-supervised clustering using a pretrained Siamese Neural Network (SNN) with contrastive learning to select informative, diverse ADL samples from user feedback. The selection uses gradient-based ranking within DBSCAN clusters to prioritize windows with high temporal variation. The selected data is merged with the original dataset to retrain a personalized model. Real-time experiments with ten participants show that training from scratch with selective data yields the highest performance, improving average F1-score by up to 25% (from 0.73 to 0.91). Few-shot learning with selective data provides a 7% improvement (F1 0.78). Crucially, the selective approach maintains and improves recall (from ~0.80 to 0.88) over time, while using all feedback causes recall to plummet from 0.80 to 0.41. The SNN clustering component generalizes strongly, achieving 85–94% accuracy across multiple activity recognition datasets.

## Method Summary
The pipeline starts with a Transformer model (M₀) pretrained on the SmartFallMM dataset. Deployed on a smartwatch, M₀ generates fall alerts; users confirm true positives (TP) and false positives (FP) via prompts, collecting feedback windows of 128 accelerometer samples (~4s). For each window, nine similarity features (PLCC, DTW, cosine) between axis pairs are computed. These features are fed into a pretrained SNN (also trained on SmartFallMM with contrastive loss) to obtain 32-dimensional embeddings. DBSCAN clusters the embeddings without a preset cluster count. Within each cluster, windows are ranked by their average gradient (mean absolute difference between consecutive points); the top x windows (≈20% of total feedback divided by cluster count) are selected per cluster. The selected set is merged with the original SmartFallMM data, and a personalized model Mₚᵢ is trained using one of three strategies: Training from Scratch (TFS), Transfer Learning (TL, freezing lower Transformer layers), or Few-Shot Learning (FSL, fine-tuning on a small subset). The personalized model is then deployed. Evaluation uses an 80-20 within-subject split of the feedback data.

## Key Results
- Training from scratch with selective feedback raised average F1-score by up to 25%, from 0.73 (baseline) to 0.91.
- The selective approach preserved and improved recall (0.88) across personalization rounds, whereas using all feedback reduced recall drastically from 0.80 to 0.41.
- Few-shot learning with selective data yielded a 7% relative improvement (F1 0.78), offering a computationally efficient alternative.
- SNN clustering achieved 85–94% accuracy on multiple HAR datasets, demonstrating strong generalization.

## Why This Works (Mechanism)
### Mechanism 1: Generalizable Embeddings via Contrastive Pretraining
- **Claim**: Pretraining a Siamese Neural Network (SNN) with contrastive loss yields embeddings that generalize across users and datasets, enabling effective clustering of unseen feedback.
- **Mechanism**: The SNN is trained on SmartFallMM using contrastive loss, which minimizes Euclidean distance for same-class pairs and maximizes it for different-class pairs up to a margin. This creates a discriminative embedding space where similar motion patterns (falls/ADLs) cluster together, regardless of user.
- **Core assumption**: The pretraining dataset (SmartFallMM) is sufficiently diverse to capture the variability of real-world falls and ADLs, so the learned embeddings transfer to new users.
- **Evidence**: Abstract and Section 4.3 describe the SNN training with contrastive loss for discriminative embeddings. The SNN achieves 85–94% clustering accuracy across datasets (Section 6.2).
- **Break condition**: If a user performs ADLs/falls not represented in SmartFallMM (e.g., culturally specific movements), SNN embeddings may not separate clusters adequately, degrading selection.

### Mechanism 2: Diverse ADL Sampling via Density-Based Clustering and Gradient Ranking
- **Claim**: DBSCAN clustering on SNN embeddings automatically discovers latent activity groups in user feedback without requiring a preset cluster count, and gradient-based selection within each cluster picks windows with high temporal variation, which are more informative for learning fall patterns while maintaining ADL diversity.
- **Mechanism**: Feedback windows are embedded via the pretrained SNN. DBSCAN groups embeddings based on density (eps, min_samples), forming clusters of similar motions and marking outliers as noise. This avoids artificial grouping and adapts to the user’s data distribution. Within each cluster, the mean absolute gradient (temporal variation) across accelerometer points is computed; the top x windows with highest gradient are selected. This emphasizes abrupt motions (fall-like) and prevents over-representation of frequent, low-variation ADLs (e.g., walking).
- **Core assumption**: The SNN embedding space has locally dense regions corresponding to distinct activity types, so DBSCAN’s density-based approach recovers meaningful clusters. High-gradient windows are more discriminative for fall detection.
- **Evidence**: Section 4.4 defines the gradient metric and selection protocol. Section 6.3.2 shows gradient-based selection yields F1 0.91 vs. random 0.85. Figure 6 reports cluster-label alignment averaging 89%, supporting DBSCAN’s effectiveness.
- **Break condition**: If SNN embeddings are too isotropic or clusters have irregular shapes/densities, DBSCAN may merge distinct activities or split one activity into multiple clusters. Also, if some falls exhibit low gradient (slow collapse) or ADLs have high gradient (sports), selection may mis-prioritize.

## Foundational Learning
### Concept 1: Contrastive Learning in Siamese Networks
- **Why needed**: The SNN’s embeddings rely on contrastive loss to group similar motion patterns; understanding this loss is key to why the SNN generalizes.
- **Quick check**: In a Siamese network with contrastive loss, what is the effect on the embedding distance for a positive pair (same class) versus a negative pair (different classes)? *Answer: Positive pairs are pulled together (distance reduced), negative pairs are pushed apart beyond a margin.*

### Concept 2: DBSCAN Density-Based Clustering
- **Why needed**: The feedback is clustered automatically without a predefined k; DBSCAN’s parameters directly affect cluster formation and selection balance.
- **Quick check**: How does DBSCAN handle noise points, and what happens if ε is set too small or too large? *Answer: Noise points are those not belonging to any dense region; too small ε yields many fragmented clusters and noise, too large ε merges distinct clusters.*

### Concept 3: Gradient as a Proxy for Informativeness in Time Series
- **Why needed**: Sample selection hinges on the gradient metric; it must capture dynamic motions (falls) without overfitting to high-variation ADLs.
- **Quick check**: Why might a higher average gradient in a 4-second accelerometer window indicate a more informative sample for fall detection? *Answer: Falls involve rapid changes in acceleration, leading to high temporal variation captured by gradient.*

### Concept 4: Transformer Architecture for Time Series Classification
- **Why needed**: The base model (M₀) and personalized models are Transformers; understanding its adaptation (e.g., positional encoding, MLP head) is necessary to interpret retraining results.
- **Quick check**: How is the Transformer adapted for variable-length time series windows in this fall detection setup? *Answer: Windows are fixed to 128 samples; positional encoding likely relative or learned; MLP head maps sequence embedding to binary classification.*

## Architecture Onboarding
**Component map**
Initial Model (M₀) → Feedback Recorder → Feature Extraction (9-D) → Pretrained SNN → DBSCAN Clustering → Gradient-based Selector → Merged Dataset (selected + original) → Retraining Module (TFS/TL/FSL) → Personalized Model (Mₚᵢ).

**Critical path**
1. Deploy M₀ → collect TP/FP feedback windows over ~6 days.
2. For each window, compute 9 similarity features (PLCC, DTW, cosine for axis pairs).
3. Embed windows using SNN; apply DBSCAN to form clusters.
4. For each cluster, compute gradient (mean absolute consecutive differences); select top x = 0.2 × total_windows/num_clusters windows.
5. Merge selected windows with original SmartFallMM; retrain Mₚᵢ via TFS, TL, or FSL.
6. Deploy Mₚᵢ on user’s device.

**Design tradeoffs**
- TFS yields highest F1 (0.91) but is computationally heavy; FSL offers best efficiency (F1 0.78) for on-device updates.
- Selective (20%) vs. all feedback: Selective prevents ADL bias (recall 0.88 vs. 0.41) at slight precision cost.
- Gradient-based vs. random: Gradient selection improves F1 by 6% (0.91 vs. 0.85) by prioritizing dynamic windows.
- SNN vs. other features: Using similarity metrics (F1 0.91) outperforms raw time series (0.67) and statistical features (0.63).

**Failure signatures**
- Recall decay: Using all feedback leads to steady recall drop over retraining cycles (0.80 → 0.41).
- Cluster imbalance: Some ADLs (e.g., drinking water) cluster less accurately (85% accuracy), risking under-representation.
- SNN mismatch: If user’s motions are out-of-distribution for SmartFallMM (e.g., different sensor placement), SNN embeddings may not separate activities.
- Gradient misalignment: If falls have low gradient (slow falls) or ADLs have high gradient (e.g., sweeping), selection may mis-prioritize, hurting sensitivity.

**First 3 experiments**
1. **Retraining strategy comparison**: For one participant, run TFS, TL, FSL with selective (20%) data. Expect TFS ≈0.9 F1, FSL ≈0.78, TL ≈0.71.
2. **Selection method ablation**: Same participant, compare gradient-based vs. random (20%) selection. Expect gradient-based F1 ≈0.91, random ≈0.85.
3. **Cluster validation**: Visualize SNN embeddings (t-SNE) colored by known activity labels. Expect dense clusters for distinct activities (e.g., wearing jacket, sitting) and more overlap for subtle ones (e.g., drinking water).

## Open Questions the Paper Calls Out
1. **Optimizing few-shot learning**: How can few-shot learning be enhanced to match training-from-scratch performance while remaining efficient for on-device wearables? Current FSL lags (F1 0.78 vs 0.91). Resolution requires systematic exploration of architectures and fine-tuning protocols.
2. **Transfer learning underperformance**: Why does transfer learning (freezing lower Transformer layers) perform worse (F1 0.71) than training from scratch or few-shot? Understanding layer selection and feature similarity could improve adaptation.
3. **SNN clustering across demographics**: How does clustering accuracy vary with user demographics and ADL patterns, and can it be improved for fine-grained activities? Per-activity clustering accuracy ranges 85–94%, with lower scores for subtle movements. Evidence from demographics and alternative metrics is needed.
4. **Generalization to other HAR tasks**: Can the selective feedback strategy generalize to other time-series activity recognition tasks (e.g., gait monitoring, sports analytics)? Validation on diverse datasets and sensor modalities is required.

## Limitations
- **Dataset & Real-World Generalization**: Results are based on SmartFallMM (30 participants) and 10-person feedback trials; generalization to culturally novel ADLs, different sensor placements, and diverse fall etiologies is uncertain.
- **Clustering & Selection Parameterization**: DBSCAN hyperparameters and cluster redistribution logic are unspecified; gradient selection assumes high temporal variation correlates with fall-discriminative windows, which may fail for slow collapses or dynamic ADLs.
- **Long-Term & Scalability**: Experiments span only ~6 days per user; long-term performance degradation and computational cost of training from scratch for on-device deployment remain untested.

## Confidence
- SNN pretraining generalization: Medium
- DBSCAN clustering for diverse ADLs: Medium
- Gradient-based selection efficacy: Medium-High
- Overall personalized improvement (F1 +25%): High

## Next Checks
1. **Out-of-Distribution ADL Stress Test**: Introduce ADLs absent from SmartFallMM into feedback; expect sharp drop in cluster purity and F1 if SNN fails to generalize.
2. **DBSCAN Parameter Sweep**: Systematically vary ε and min_samples on pooled feedback; measure cluster count, silhouette scores, and F1. Expect optimal performance within a narrow band.
3. **Gradient Metric Correlation Analysis**: For each cluster, compare gradient values of known fall vs. ADL windows; validate that selected high-gradient windows indeed contain a higher fall proportion. Expect strong positive correlation in most clusters.
