# MM-ReCoder: Advancing Chart-to-Code Generation with Reinforcement Learning and Self-Correction
## Quick Facts
- **arXiv ID:** 2604.01600  
- **Source URL:** https://arxiv.org/abs/2604.01600  
- **Reference count:** 40  
- **Primary result:** MM-ReCoder achieves state-of-the-art performance on chart-to-code generation benchmarks, notably 86.5% low-level score on ChartMimic and 63.2% text-match score on Plot2Code, with consistent improvement via self-correction.

## Executive Summary
MM-ReCoder introduces a reinforcement learning framework for chart-to-code generation that overcomes key limitations of existing models. Prior approaches rely on supervised fine-tuning and fail to improve code via self-correction even when given execution feedback. MM-ReCoder uses a two-stage Group Relative Policy Optimization (GRPO) strategy: first, a shared first-turn rollout enhances self-correction ability; second, full-trajectory optimization improves overall coding performance. It employs a hybrid reward combining rule-based element matching and model-based visual assessment, and a cold-start SFT phase to learn multi-turn response patterns. Evaluated on ChartMimic, Plot2Code, and ChartX, MM-ReCoder achieves state-of-the-art results and consistently improves code quality through multiple correction turns.

## Method Summary
The training pipeline consists of two phases. Phase 1 (cold-start) fine-tunes a vision-language model (Qwen2.5-VL-7B) on Chart2Code-160k to learn basic code generation, then on 7k curated two-turn self-correction examples (generated by Qwen3-VL-235B and filtered by improvement) to learn the multi-turn format. Phase 2 applies two-stage RL with GRPO. Stage 1: for each chart, sample one first-turn output, execute to get feedback, then sample eight second-turn outputs conditioned on that common first-turn; update only the second-turn policy. Stage 2: roll out eight full trajectories (first+second turns) per chart; compute reward from the final turn and update both turns jointly. The reward is a weighted sum of format (binary), rule-based (element match via matplotlib hooks), and model-based (Qwen2.5-VL-72B holistic score) components. At inference, the model iteratively generates, executes, and corrects code up to a maximum number of turns.

## Key Results
- State-of-the-art on ChartMimic (86.5% low-level score) and Plot2Code (63.2% text-match), outperforming comparable and larger proprietary models.
- Consistent positive improvement through multi-turn self-correction; unlike prior MLLMs that degrade already-executable code.
- High execution rate and improved visual quality as measured by both rule-based and model-based metrics.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The two-stage multi-turn GRPO strategy disentangles first-turn generation from second-turn refinement, enabling effective self-correction without suffering from code repetition or reward hacking.
- **Mechanism:** Stage 1 fixes a shared first-turn output per group and applies RL updates only to second-turn candidates, forcing the policy to explore refinement variations. Stage 2 then rolls out full trajectories (both turns) and optimizes jointly, leveraging the now-competent self-correction to improve overall coding performance.
- **Core assumption:** Self-correction ability can be elicited by isolating second-turn gradients; premature joint optimization causes the model to repeat first-turn code or intentionally degrade first-turn quality to game the improvement bonus.
- **Evidence anchors:**
  - [abstract] "The first stage enhances the model’s self-correction ability via rolling out a shared first turn, while the second stage improves the coding capability with full-trajectory optimization."
  - [section 3.4.2] Full-trajectory with γ=0, η=0 yields 46.9% repeated code and only 3.4% improved samples; adding η=0.1 causes exploitation. Shared-first-turn achieves 14.4% improved samples and 16.8% repetition. Two-stage combines strengths (86% low-level, low repetition).
  - [corpus] Neighboring RL chart-to-code works (ChartMaster, ChartCoder) treat generation as single-turn; they lack any multi-turn strategy, underscoring the novelty of disentangled training.
- **Break condition:** If after Stage 1 the model still shows >50% repetition or negative improvement on executable outputs, the disentanglement may be incomplete. If Stage 2 reintroduces high repetition, the assumption that the model has internalized correction may be false.

### Mechanism 2
- **Claim:** A hybrid reward that combines rule-based element matching and model-based visual assessment yields charts that are both semantically faithful and visually coherent, whereas each alone suffers from critical blind spots.
- **Mechanism:** Rule-based reward hooks into matplotlib to extract chart elements (type, text, color, layout) and computes similarity metrics; it is precise but cannot detect overlapping text or stylistic flaws. Model-based reward (Qwen2.5-VL-72B) scores six holistic aspects (type, layout, text, data, style, clarity) on a 0–100 scale, capturing quality beyond individual elements. A small format reward ensures structural compliance. These are linearly combined.
- **Core assumption:** The two reward modalities provide complementary supervision: rule-based anchors semantic correctness, model-based acts as a high-level quality critic that penalizes visual defects even when element-level scores are perfect.
- **Evidence anchors:**
  - [section 3.4.1] Figure 3: a chart with overlapping text receives rule reward 1.0 but model reward 0.8. Table 6: removing model-based reward reduces high-level score from 83.7% to 78.6%; removing rule-based reduces low-level from 83.9% to 78.2%.
  - [abstract] "We explore rule-based and model-based rewards. While rule-based reward helps the model faithfully reproduce chart elements, model-based reward effectively improves the visual quality."
  - [corpus] ChartMaster uses separate low- and high-level rewards but in a single-turn RL setting; the extension to multi-turn with explicit hybrid design is new.
- **Break condition:** If model-based reward is poorly calibrated (e.g., from a weak judge), it may penalize correct charts. Extreme weighting (e.g., β=0.9) can degrade low-level fidelity as seen in Table 6.

### Mechanism 3
- **Claim:** Cold-start SFT on chart-code pairs and curated two-turn correction data provides the syntactic and conversational scaffolding for self-correction, but RL is required to transform this scaffolding into reliable improvement on already-executable code.
- **Mechanism:** First SFT on Chart2Code-160k teaches basic code generation. Second SFT on 7k two-turn examples (teacher-generated and filtered by Δ score ≥0.02) instills the multi-turn response pattern. However, without RL, the model often degrades second-turn outputs (negative average improvement). The subsequent RL stages (Mechanism 1) then refine the policy using execution feedback, overriding SFT’s distribution and enabling positive correction.
- **Core assumption:** SFT can imbue the structural knowledge (format, turn-taking) but cannot overcome distribution shift between static demonstration data and the dynamic, interactive distribution of self-correction; RL closes that gap by online optimization.
- **Evidence anchors:**
  - [section 3.3 & Table 5] After multi-turn cold-start, average low-level improvement is -0.54% (degradation). After applying RL (two-stage), improvement becomes +0.30% and execution rate rises.
  - [abstract] "The cold-start stage provides the model with basic coding knowledge and the ability to generate multi-turn coding responses, but it is not sufficient to guarantee reliable improvements in the second turn."
  - [corpus] Prior SFT-only chart-to-code models (ChartCoder, ChartLlama) show no self-correction ability; even large proprietary MLLMs (Qwen3-VL) exhibit near-zero or negative improvement on executable code (Figure 1, Table 3), highlighting the insufficiency of SFT.
- **Break condition:** If cold-start data are too noisy or filtered too aggressively, the model may learn poor correction patterns that RL cannot fully repair.

## Foundational Learning
- **Concept:** Reinforcement Learning from Environment Feedback (RLEF)  
  - **Why needed here:** MM-ReCoder optimizes code generation via interaction with a Python execution environment, requiring understanding of policy gradients, on-policy sampling, and advantage estimation. GRPO extends REINFORCE with group-relative baselines to reduce variance.  
  - **Quick check question:** How does the group-relative advantage normalization in GRPO stabilize training compared to using a global baseline?

- **Concept:** Multi-turn Self-Correction in LLMs  
  - **Why needed here:** The model must condition its refinement on its own prior output and execution feedback, which involves chaining generations, preserving context, and avoiding degenerate behaviors like repetition.  
  - **Quick check question:** Why might jointly optimizing both turns in early training lead to the policy repeating its first-turn code, and how does the shared-first-turn strategy prevent this?

- **Concept:** Hybrid Reward Design for Visual Code Tasks  
  - **Why needed here:** Chart quality assessment requires both fine-grained element matching (e.g., text strings, colors) and holistic visual judgment (e.g., clarity, style). Engineers must combine deterministic rule-based scores with learned model-based scores and balance their contributions.  
  - **Quick check question:** What specific visual flaw might a rule-based reward miss that a model-based reward can detect, and vice versa?

## Architecture Onboarding
- **Component map:**  
  Input encoder (Qwen2.5-VL) → Policy network πθ → Execution environment → Reward modules (format, rule-based, model-based) → RL trainer (GRPO)  
- **Critical path:**  
  1. Gather chart-code pairs and two-turn correction demonstrations.  
  2. Perform two SFT stages: first on Chart2Code-160k, then on 7k two-turn data.  
  3. RL Stage 1: For each query, rollout first turn o¹; execute; generate feedback f¹; rollout G second-turns o²ᵢ conditioned on shared (o¹, f¹). Compute R(o²ᵢ) and apply GRPO update to second-turn tokens.  
  4. RL Stage 2: For each query, rollout G full trajectories (o¹ᵢ, o²ᵢ). Compute trajectory reward R(o²ᵢ) (γ=0) and apply GRPO update to both turns.  
  5. At inference, loop: generate code → execute → if not satisfactory and turns < max, feed back image/error as new turn.
- **Design tradeoffs:**  
  - *Shared-first-turn vs full-trajectory*: Shared isolates self-correction learning, avoids repetition, but may neglect first-turn quality; full optimizes end-to-end but risks collapse; two-stage balances.  
  - *Reward weighting*: Rule-based is cheap and precise but misses global quality; model-based captures more but costs compute and can be inconsistent; Table 6 shows performance robust to moderate weight changes.  
  - *Cold-start data source*: Using a teacher model (Qwen3‑VL‑235B) introduces bias but scales; filtering by Δ score ensures only clear improvements are kept, limiting noisy attempts at cost of diversity.  
  - *Number of correction turns*: More turns yield diminishing returns and possible regression after ~4 turns (Table 4); practical inference must cap turns for latency.
- **Failure signatures:**  
  - High second‑turn code repetition (>50%) indicates failed self-correction learning (observed in full‑trajectory ablations).  
  - Negative average improvement on already‑executable outputs means the model degrades correct charts (as with Qwen baselines).  
  - Sudden drop in first‑turn quality when using η>0 suggests reward hacking (first‑turn deliberately worsened).  
  - Training vs evaluation reward gap (Fig. A1) hints at overfitting to training distribution; monitor for plateauing eval gains.  
  - Model‑based reward noise may cause instability; if low‑level score drops while high‑level rises, the judge may be over‑penalizing element mismatches.
- **First 3 experiments:**  
  1. **Cold‑start sanity check:** Load the post‑SFT‑2 policy, generate on 10 ChartMimic images. Verify presence and ««python blocks, and that second‑turn code is not identical to first‑turn. Compute manual Δ low‑level score.  
  2. **Rollout strategy comparison:** On a small subset (e.g., 100 images), train three models for 50 steps: (a) shared‑first‑turn only, (b) full‑trajectory (γ=0.5, η=0.1), (c) two‑stage (first 25 steps shared, next 25 full). Compare % improved samples, % repeated code, and average low‑level improvement. Expect (a) high improvement % but lower overall score; (b) high repetition; (c) best balance.  
  3. **Reward ablation (single‑turn):** Train three models with reward configurations: (i) only rule‑based, (ii) only model‑based, (iii) balanced (α=0.8, β=0.1). Evaluate on ChartMimic low/high‑level scores. Expected: (i) high low‑level but lower high‑level; (ii) high high‑level but lower low‑level; (iii) both high. Also inspect charts for overlapping text in (i) and element mismatches in (ii).

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Why do existing MLLMs exhibit negative improvement on already executable code during self-correction, and what specific training dynamics cause this failure?
- **Basis in paper:** Explicit: Figure 1 and Section 3.2 show that models like Qwen3-VL degrade chart quality when the first-turn code is executable, while MM-ReCoder improves. The paper attributes this to lack of refinement training but does not dissect the underlying cause.
- **Why unresolved:** The paper presents the symptom and solution (shared-first-turn RL) without analyzing why models fail—e.g., whether they misdiagnose correct elements, suffer from reward hacking, or face distribution shifts in self-correction data.
- **What evidence would resolve it:** Controlled ablations on training data (e.g., filtering executable first-turn samples), probing model outputs for error types, and comparing activation patterns between successful and failed self-correction attempts.

### Open Question 2
- **Question:** How does the quality and source of the cold-start self-correction data impact the final performance, and can we reduce reliance on large teacher models?
- **Basis in paper:** Inferred: Cold-start uses Qwen3-VL-235B to generate 7k two-turn samples. The paper shows that without cold-start, RL still works but with lower scores (Table A3), suggesting teacher data is helpful but not fully necessary.
- **Why unresolved:** No experiments varying teacher model size, data diversity, or synthetic vs. human annotations. It remains unclear how teacher quality correlates with self-correction capability and whether cheaper alternatives exist.
- **What evidence would resolve it:** Train with teachers of varying scales (e.g., 8B vs. 235B), different data sources (e.g., rule-based synthetic corrections), or no teacher (RL from random initialization), measuring final low-level score and self-correction success rate.

### Open Question 3
- **Question:** To what extent can the two-stage RL strategy (shared-first-turn then full-trajectory) generalize to other multimodal coding tasks (e.g., webpage-to-code, SVG-to-code), and what task-specific adaptations are required?
- **Basis in paper:** Explicit: The method is evaluated only on chart-to-code benchmarks (ChartMimic, Plot2Code, ChartX). The authors claim it is the first self-correction model for this domain but do not test transferability.
- **Why unresolved:** Different tasks may have distinct code structures, execution feedback, or error patterns. The reward design (rule-based + model-based) is tailored to charts; other tasks may need different reward signals or rollout strategies.
- **What evidence would resolve it:** Apply the same training pipeline to benchmarks like Design2Code or Web2Code, report self-correction improvements, and conduct ablation studies on reward adaptation and turn strategies.

## Limitations
- Exact reward weights (α for rule-based, β for model-based) after ablation are not explicitly stated; they must be inferred, potentially leading to replication variance.
- The rule-based reward implementation details (e.g., matplotlib instrumentation, library versions) are not provided, making exact replication of element extraction difficult.
- Dataset splits and filtering thresholds for the 7k two-turn correction data (e.g., improvement ≥0.02) are undisclosed, hindering faithful reconstruction of the training corpus.

## Confidence
- Two-stage GRPO disentanglement: High  
- Hybrid reward (rule + model): Medium  
- Cold-start SFT + RL pipeline: High
