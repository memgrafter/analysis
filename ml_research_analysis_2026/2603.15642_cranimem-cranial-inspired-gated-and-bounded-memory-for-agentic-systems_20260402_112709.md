# CraniMem: Cranial Inspired Gated and Bounded Memory for Agentic Systems

## Quick Facts
- **arXiv ID:** 2603.15642
- **Source URL:** https://arxiv.org/abs/2603.15642
- **Reference count:** 35
- **Primary result:** CraniMem reduces noise-induced performance drop (Δnoise = 0.011) compared to Vanilla RAG (0.027) and Mem0 (0.036) on HotpotQA with Qwen2.5-7B-Instruct, while achieving higher macro-averaged F1 in noisy conditions (0.312).

## Executive Summary
CraniMem introduces a neurocognitively inspired memory architecture for LLM agents to improve robustness against distractors. It combines goal-conditioned gating, utility tagging, a bounded episodic buffer, and a structured knowledge graph with scheduled consolidation. On a long-horizon QA benchmark with injected noise, CraniMem demonstrates significantly smaller performance degradation and higher recall compared to baseline RAG and memory systems, albeit at the cost of increased latency.

## Method Summary
CraniMem employs a dual-store memory system. Incoming inputs are first filtered by a goal-conditioned gating module that uses embedding similarity and an LLM-based utility tagger to assign scores based on importance, surprise, and emotion. Accepted inputs are stored in a fixed-size episodic buffer for short-term context. Periodically, a consolidation scheduler computes a replay score for each buffer item (base utility multiplied by a frequency bonus) and transfers high-scoring items to a knowledge graph via an extraction and upsert process, while pruning the rest. For query answering, the system retrieves from both the recent buffer and the knowledge graph, merging results to provide context to the LLM. This design aims to selectively encode relevant information, maintain continuity, and build a structured long-term knowledge base while controlling memory growth.

## Key Results
- On HotpotQA with injected noise, CraniMem (Qwen2.5-7B-Instruct) achieves macro-averaged F1 of 0.312, outperforming Vanilla RAG (0.068) and Mem0 (0.198).
- CraniMem exhibits a substantially smaller performance drop due to noise (Δnoise = 0.011) compared to Vanilla RAG (0.027) and Mem0 (0.036).
- Across multiple LLM backbones, CraniMem consistently reduces noise drop, demonstrating stronger robustness to distractors, though with higher end-to-end latency.

## Why This Works (Mechanism)
### Goal-conditioned input gating with utility tagging
An embedding-based similarity check discards inputs below a noise threshold; passed inputs are tagged with utility scores (importance, surprise, emotion). This composite utility guides encoding and consolidation, suppressing low-relevance inputs and reducing interference. Evidence: section 3; gating threshold τ_noise and utility aggregation in section B.1.

### Bounded dual-store architecture
A fixed-size FIFO episodic buffer provides short-range continuity, while a structured knowledge graph stores consolidated semantic knowledge for multi-hop recall. This separation prevents unbounded growth and enables efficient retrieval. Evidence: abstract, section 3; buffer and graph details in B.2, B.4.

### Scheduled utility-weighted consolidation
Periodically, buffer items are scored (BaseUtility * (1 + α*FreqBonus)); items above τ_consolidation are extracted into the graph, others pruned. This selective rehearsal controls memory growth and prioritizes salient, frequently accessed experiences. Evidence: abstract, section 3; ReplayScore formula in B.3.

## Architecture Onboarding
- **Component map:** Input Processor -> Gating Module -> Episodic Buffer -> Consolidation Scheduler -> Linkage Engine -> Knowledge Graph Store -> Retrieval Module -> LLM Backend. Retrieval also directly reads from Episodic Buffer.
- **Critical path:** Input → Gating (filter+tag) → Buffer (store) → [Periodic: Consolidation Scheduler → Replay Scoring → Linkage Engine → Graph Update] → Retrieval (Buffer+Graph) → LLM Generation.
- **Design tradeoffs:**
  - Robustness vs. Latency: Gating and consolidation add overhead (~112s vs 58s for Vanilla RAG); aggressive pruning risks losing subtle dependencies.
  - Boundedness vs. Completeness: Fixed buffer and pruning ensure scalability but may discard transiently critical information if thresholds are mis-set.
  - Graph Complexity vs. Extraction Fidelity: Rich graph extraction enables detailed queries but is error-prone and costly.
- **Failure signatures:**
  - High noise drop: Gating ineffective (τ_noise too low) or utility tagging unreliable; inspect retrieval for distractors.
  - Low clean recall: Over-pruning (τ_consolidation too high), buffer too small, or poor graph linkage.
  - Latency spikes: Consolidation too frequent or graph extraction slow; profile and adjust buffer size/interval.
  - Graph inconsistency: Duplicate/conflicting nodes from upsert errors; check extraction prompts.
- **First 3 experiments:**
  1. Gating Threshold Sweep: Vary τ_noise and measure Δnoise and clean F1 to find optimal noise rejection vs. information retention.
  2. Buffer Size Ablation: Test episodic buffer sizes (e.g., 5,10,20,50) to determine minimal size preserving short-term continuity without excessive pruning.
  3. Consolidation Frequency Tuning: Compare consolidating every k turns vs. only on idle states; assess impact on graph growth, retrieval quality, and latency.

## Limitations
- Critical hyperparameters (τ_noise, τ_consolidation, buffer size N, frequency bonus α) are not reported, hindering exact replication.
- Details on noise injection schedule, embedding model for gating similarity, LLM used for utility tagging, dataset sampling, and hardware for latency measurements are missing.
- The system's higher end-to-end latency may limit deployment in real-time applications.

## Confidence
- Robustness claim (smaller Δnoise): Medium (mechanisms are well-specified but magnitude depends on unreported thresholds).
- Exact performance numbers (e.g., F1=0.312): Low (contingent on undisclosed hyperparameters and evaluation details).
- Architectural novelty and design tradeoffs: High (dual-store design with utility-weighted consolidation is clearly differentiated).
