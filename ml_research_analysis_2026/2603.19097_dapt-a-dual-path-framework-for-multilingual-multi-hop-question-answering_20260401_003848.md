# DaPT: A Dual-Path Framework for Multilingual Multi-hop Question Answering
## Quick Facts
- **arXiv ID**: 2603.19097
- **Source URL**: https://arxiv.org/abs/2603.19097
- **Reference count**: 0
- **Primary result**: DaPT improves average EM by 18.3% over HippoRAG2 on MuSiQue and by 6.8% on HotpotQA across five languages.

## Executive Summary
DaPT addresses the lack of multilingual multi-hop QA benchmarks and the English dependency of existing RAG systems. It translates three English multi-hop QA datasets into five languages and proposes a dual-path framework that decomposes source and English queries in parallel, fuses their sub-question graphs via semantic similarity, and uses bilingual retrieval with answer verification. On MuSiQue, DaPT achieves an 18.3% average Exact Match (EM) gain over the strongest baseline (HippoRAG2). Ablation studies show that removing decomposition reduces EM by 16.2 points, proving its necessity.

## Method Summary
DaPT operates in three stages: (1) **Parallel Planning**: Both the source-language query and its English translation are decomposed into acyclic sub-question graphs using an LLM. (2) **Node Fusion**: Corresponding nodes across the two graphs are aligned using BGE-m3 cosine similarity (threshold τ=0.8), merged, and topologically sorted to define an execution order. (3) **Bilingual Retrieval & Answering**: For each sub-question (including merged bilingual nodes), documents are retrieved from both source-language and English corpora. Candidate answers are generated, then a "Judge" verifies semantic consistency between the two language paths. The source-language answer is selected if valid; otherwise, a "ReGen" step regenerates using the accumulated reasoning path. The final answer synthesizes all sub-answers.

## Key Results
- DaPT outperforms HippoRAG2 by +6.8% EM on HotpotQA and +15.5% EM on MuSiQue (averaged over languages).
- It exceeds a simple translate-then-answer approach by +3.2 EM points, demonstrating the benefit of cross-lingual fusion.
- Ablation removing the decomposition phase causes a 16.2-point EM drop, confirming its critical role.

## Why This Works (Mechanism)
DaPT’s gains stem from its dual-path decomposition and fusion mechanism. By decomposing queries in both the source language and English, it captures language-specific reasoning nuances while leveraging the typically richer English knowledge base. The fusion step aligns equivalent reasoning steps across languages, allowing the system to retrieve evidence from both corpora and verify consistency. This mitigates the "English-only" bias of standard RAG, where a poor translation or lack of source-language documents can break the reasoning chain. The verification (Judge) and regeneration (ReGen) steps ensure that merged nodes produce coherent answers before proceeding.

## Foundational Learning
- **Multilingual Multi-hop QA**: Reasoning over multiple documents across languages. *Why needed*: Evaluates systems beyond monolingual, single-document settings. *Quick check*: Can the system answer questions requiring evidence from two or more documents in a non-English language?
- **Query Decomposition**: Breaking complex questions into ordered sub-questions. *Why needed*: Simplifies multi-hop retrieval into single-hop steps. *Quick check*: Does each sub-question refer to only one entity/event and depend only on previously answered sub-questions?
- **Graph Fusion via Semantic Similarity**: Merging nodes from parallel graphs using embedding similarity. *Why needed*: Aligns reasoning steps that may be phrased differently across languages. *Quick check*: Are merged nodes semantically equivalent (same fact/entity) despite wording differences?
- **Bilingual Retrieval**: Querying both source-language and English corpora. *Why needed*: Maximizes relevant document recall when source-language content is sparse. *Quick check*: Does retrieved evidence from the weaker language path still contribute useful facts?
- **Answer Verification (Judge)**: Checking consistency between language-specific answers. *Why needed*: Prevents propagation of errors from a single language’s retrieval/answer generation. *Quick check*: Does Judge correctly identify when source and English answers contradict?
- **Regeneration (ReGen)**: Re-answering using full path context after verification failure. *Why needed*: Allows recovery from initial retrieval/answer mistakes by incorporating later evidence. *Quick check*: Does ReGen produce a correct answer when the initial attempt failed?

## Architecture Onboarding
**Component Map**:
Query (Source LANG) -> Decompose -> Graph A
Query (English) -> Decompose -> Graph B
Graph A + Graph B -> Node Fusion (BGE-m3, τ=0.8) -> Merged Graph
Merged Graph -> Topological Sort -> Execution Order
Execution Order -> For each node: Bilingual Retrieval (k=3) -> Answer Gen (GPT-4o-mini) -> Judge (Consistency Check)
Judge: Pass -> Select Source Answer; Fail -> ReGen (full path) -> Answer
All sub-answers -> Synthesize -> Final Answer

**Critical Path**: The reasoning chain is defined by the topologically sorted merged graph. Each node must be answered (via bilingual retrieval and verification) before dependent nodes can be processed.

**Design Tradeoffs**:
- *Graph Fusion Generality vs. Precision*: A lower τ merges more nodes (potentially over-merging distinct steps); higher τ preserves separation but may miss equivalent reasoning.
- *Bilingual Retrieval Cost vs. Recall*: Querying two corpora doubles retrieval cost but improves recall in low-resource languages.
- *Verification Strictness vs. Progress*: A strict Judge may halt chains unnecessarily; lenient Judge may propagate errors.

**Failure Signatures**:
- Cyclic or disconnected graphs from decomposition.
- Low fusion scores (<τ) causing under-merging and missed cross-lingual links.
- Judge disagreement rate >40% between language paths, indicating unstable answers.
- ReGen invoked repeatedly on the same node, suggesting persistent inconsistencies.

**First Three Experiments**:
1. **Prompt Sensitivity**: Vary `Decompose` and `Judge` prompt wording on 50 dev samples; measure EM change.
2. **Retrieval Configuration Audit**: Compare DaPT using HippoRAG2’s exact retrieval setup (index, k) vs. reported k=3; isolate performance impact.
3. **Translation Consistency Check**: Manually verify entity consistency in 100 translated questions per language; compute error rate.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: Do translation artifacts in machine-translated multilingual multi-hop QA benchmarks compromise evaluation validity?
- **Basis in paper**: [inferred] Authors used GPT-4o-mini translation with rules and human checks, but did not assess how translation impacts reasoning structure or answer consistency.
- **Why unresolved**: Translation may change nuance or reasoning steps, leading to incorrect performance estimates for MM-hop RAG systems.
- **What evidence would resolve it**: Human evaluation of reasoning equivalence between original and translated questions; error analysis linking failures to translation errors; creation of manually verified parallel benchmark.

### Open Question 2
- **Question**: How does the similarity threshold τ for graph fusion affect DaPT performance across language pairs?
- **Basis in paper**: [explicit] The method uses a fixed τ=0.8 to merge sub-question nodes, but no sensitivity analysis is provided.
- **Why unresolved**: Threshold may control the trade-off between over-merging and under-merging, and optimal value might differ by language due to embedding space variations.
- **What evidence would resolve it**: Systematic experiments varying τ (e.g., 0.5-0.95) for each language pair, measuring EM/F1; possibly learning τ on a development set.

### Open Question 3
- **Question**: Is DaPT's bilingual retrieval effective with a monolingual (English-only) corpus, or does it require a multilingual corpus?
- **Basis in paper**: [inferred] Authors claim cross-lingual context but state "same corpus" for all languages without clarifying its language composition; it is thus unclear whether a purely English corpus suffices.
- **Why unresolved**: Real-world deployments may have limited document languages; knowing corpus requirements is key for applicability.
- **What evidence would resolve it**: Experiments with corpora of varying language compositions (English-only vs. multilingual) while keeping other factors constant, measuring performance impact.

### Open Question 4
- **Question**: Does the LLM's decomposition quality vary across languages, and could this limit DaPT's benefits in low-resource languages?
- **Basis in paper**: [inferred] DaPT relies on LLM decomposition in both source and English, but no analysis of decomposition correctness across languages is given.
- **Why unresolved**: Poor decomposition in certain languages could break the reasoning chain, explaining performance gaps; without quantifying decomposition quality, it's hard to pinpoint bottlenecks.
- **What evidence would resolve it**: Human evaluation of a sampled set of decompositions per language, scoring completeness and correctness; correlation between these scores and end-to-end EM.

## Limitations
- **Unspecified Prompts**: Exact prompt templates for decomposition, verification, and regeneration are not provided, making full replication dependent on reconstruction.
- **Retrieval Configuration Ambiguity**: Details of the retrieval index (e.g., BM25 vs. FAISS) and query encoding (e.g., whether sub-questions are encoded with BGE-m3) are not fully clarified.
- **Translation Protocol Gaps**: The specific rules and human verification process for maintaining entity consistency during translation are not elaborated, risking dataset fidelity issues.

## Confidence
- **Performance Gains vs. Baselines**: Medium-High. Results are numerically specific and compare to known baselines, but unreported prompts/configurations introduce variability.
- **Necessity of Decomposition (Ablation)**: Medium. The large EM drop is compelling but depends on the specific implementation of the removed component.
- **Effectiveness over Translate-then-Answer**: Medium. The 3.2 EM improvement suggests cross-lingual fusion helps, but hinges on unspecified bilingual retrieval/verification mechanisms.

## Next Checks
1. **Prompt Sensitivity Analysis**: Systematically vary `Decompose` and `Judge` prompts on a small dev set (n=50) to measure EM variance and quantify robustness to prompt engineering.
2. **Retrieval Configuration Audit**: Re-run DaPT using HippoRAG2’s exact retrieval setup (index type, embedding model for queries, top-k) versus the reported k=3 for other steps to isolate the performance contribution of retrieval changes.
3. **Translation Consistency Audit**: Randomly sample 100 translated questions per language and manually verify that key entities (persons, locations, dates) match the English source; compute error rate; if >5%, the translated data may degrade performance unfairly.
