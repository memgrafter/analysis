# User Preference Modeling for Conversational LLM Agents: Weak Rewards from Retrieval-Augmented Interaction

## Quick Facts
- **arXiv:** 2603.20939
- **Source:** https://arxiv.org/abs/2603.20939
- **Reference count:** 40
- **Key result:** VARS achieves comparable task success to Reflection (55.2% vs 54.4%) while significantly reducing timeout rate (26.4% vs 28.8%, p<0.05) and user effort (193.6 vs 207.5 tokens per session) on the MultiSessionCollab benchmark.

## Executive Summary
LLM assistants typically lack persistent user models, forcing users to repeat preferences in every conversation. This paper introduces VARS, a framework that maintains per-user dual preference vectors (long-term and short-term) in a shared embedding space. These vectors are updated online from weak, heuristic feedback without fine-tuning the underlying models. Experiments on a synthetic benchmark spanning math and code tasks show that VARS matches a strong Reflection baseline in task success while reducing user timeout and token effort, demonstrating improved interaction efficiency. The dual-vector design yields interpretable separation: long-term vectors capture cross-session preference overlap, while short-term vectors adapt within sessions.

## Method Summary
VARS augments a retrieval-augmented generation (RAG) pipeline with a structured preference memory and personalization vectors. A lightweight extractor converts recent dialogue into (condition, action) tuples stored as memory cards. At inference, a frozen cross-encoder reranker scores candidates based on the user’s query plus a dot-product bonus between the memory’s item vector and the user’s effective preference vector \(z_{\text{eff}} = \beta_L z(L) + \beta_S z(S)\). The top notes are injected into the LLM. After the user’s next turn, a keyword-based heuristic estimates a reward for the previous retrieval, and a gated REINFORCE-style update adjusts both vectors. The long-term vector accumulates updates across sessions; the short-term vector decays and resets at session boundaries. No backbone fine-tuning occurs; personalization is confined to the low-dimensional user vectors.

## Key Results
- **Task success:** VARS 55.2% vs Reflection 54.4% (comparable)
- **Timeout rate:** VARS 26.4% vs Reflection 28.8% (p<0.05) and vs RAG 44.3%
- **User effort:** VARS 193.6 vs Reflection 207.5 tokens per session (p<0.05)
- **Interpretability:** Long-term vectors correlate with cross-user preference overlap; short-term vectors capture session-specific shifts.

## Why This Works (Mechanism)
VARS’s efficiency emerges from three intertwined mechanisms.  
1. **Dual-vector separation** keeps a persistent long-term vector \(z(L)\) that accumulates stable preferences across sessions, while a resetting short-term vector \(z(S)\) adapts to transient context. Their combination biases retrieval toward both enduring and situational needs (ablation shows each contributes uniquely).  
2. **User-aware scoring** adds a dot-product bonus \(\langle z_{\text{eff}}, v_m \rangle\) to the reranker, steering retrieved memories toward those aligning with the user’s learned preferences. This simple linear modulation in a shared PCA space effectively personalizes retrieval without altering the frozen backbone.  
3. **Online weak-reward updates** treat retrieval as a policy and apply a REINFORCE gradient using a fast, keyword‑based reward \( \hat{r}_t \) derived from the user’s next turn. Gating by retrieval attribution stabilizes learning; the updates are cheap and avoid per‑user fine‑tuning, enabling continuous personalization.

## Architecture Onboarding
**Component map:**  
Preference Extractor → Preference Memory → Dense Retrieval → Reranker (with Dual User Vectors) → Selected Notes → LLM → Response → Reward Estimator → Update Module → Dual User Vectors

**Critical path (inference → update loop):**  
1. User query → dense retrieval over memory embeddings → candidate set.  
2. Reranker computes base scores \(s_0\) and adds \(\langle z_{\text{eff}}, v_m \rangle\); top‑J notes selected.  
3. Notes injected into LLM to generate assistant response.  
4. User’s next turn triggers keyword‑based reward \(\hat{r}_t\) and gating \(g_t\).  
5. Advantage \(A_{\text{retr}}^t = g_t(\hat{r}_t - b_U)\) updates \(z(L)\) cumulatively and \(z(S)\) with decay.  
6. At session end, \(z(S)\) resets.

**Design tradeoffs:**  
- *Frozen backbones* vs expressivity: No fine‑tuning ensures stability but limits adaptation to the backbone’s existing knowledge.  
- *Weak rewards* vs robustness: Heuristic reward is cheap but may miss subtle feedback; gating is critical to avoid drift.  
- *Dual‑vector* vs simplicity: Two timescales improve interpretability and performance but add hyperparameters (\(\beta_L,\beta_S,\lambda\)).

**Failure signatures:**  
- Over‑cautious clarification (agent asks unnecessary questions when many conflicting preferences retrieved).  
- Preference overload (agent tries to satisfy all injected notes → verbose, unfocused responses; high timeout in RAG).  
- Early user disengagement (simulator terminates sessions if initial responses weak).

**First 3 experiments:**  
1. **Main comparison** on MultiSessionCollab with 60 profiles × 60 sessions measuring success, timeout, token use.  
2. **Dual‑vector ablation** disabling \(z(L)\) or \(z(S)\) on a math‑hard subset with stronger backbone (GPT‑4o‑mini).  
3. **User‑vector representation analysis** correlating pairwise cosine similarity of long‑term vectors with Jaccard overlap of revealed preferences across users.

## Limitations
- Evaluation limited to 60 synthetic user profiles on math and code tasks; real‑world diversity unexplored.  
- The keyword‑based reward heuristic may not generalize to nuanced feedback; gating is brittle.  
- PCA projection risks discarding preference‑relevant signals; no alternative dimensionality choices tested.  
- Long‑term stability of the persistent vector over many sessions remains unexamined.

## Confidence
- Dual‑vector separation: Medium  
- User‑aware retrieval bias: Medium  
- Online weak‑reward learning: Medium  
- Overall efficiency gains: High
