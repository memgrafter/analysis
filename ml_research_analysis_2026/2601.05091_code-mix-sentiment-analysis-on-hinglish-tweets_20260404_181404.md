# Code-Mix Sentiment Analysis on Hinglish Tweets

## Quick Facts
*   **arXiv ID:** 2601.05091
*   **Source URL:** https://arxiv.org/abs/2601.05091
*   **Reference Count:** 24
*   **Primary Result:** Fine-tuned mBERT achieves a weighted F1-score of 0.67 on a merged Hinglish-24k test set, outperforming SVM (0.65) and Naive Bayes (0.62) baselines for sentiment analysis of Romanized Hinglish tweets.

## Executive Summary
This paper addresses the challenge of performing accurate sentiment analysis on Hinglish (Hindi-English code-mixed) tweets, a task complicated by spelling variations, slang, and out-of-vocabulary terms. The proposed solution fine-tunes the multilingual BERT (mBERT) model, leveraging its subword tokenization to handle noisy Romanized text and its cross-lingual pretraining to understand both Hindi and English components. Evaluated on a merged dataset of ~24k tweets (Hinglish-24k), the fine-tuned mBERT model yields a weighted F1-score of 0.67, establishing a new benchmark and demonstrating the effectiveness of multilingual transformers for this real-world social media analysis problem in India.

## Method Summary
The method involves fine-tuning the `bert-base-multilingual-cased` model on a curated, merged dataset of 24,111 Hinglish tweets (Hinglish-24k). Preprocessing includes regex cleanup (URLs, mentions), emoji replacement with emotional tokens, lowercase conversion, stop-word removal, and filtering of duplicates and low-quality entries. The text is tokenized using mBERT's WordPiece tokenizer with a maximum sequence length of 128. A linear classification head is added on top of the [CLS] token's representation. The model is trained for 3 epochs using the AdamW optimizer (learning rate 2e-5, batch size 8) on an 80/10/10 train/validation/test split. Performance is primarily measured by weighted F1-score and compared against TF-IDF based SVM and Naive Bayes baselines.

## Key Results
*   Fine-tuned mBERT achieves a **weighted F1-score of 0.67** on the 2,412-sample test set.
*   This **surpasses the SVM (0.65) and Naive Bayes (0.62)** baseline models.
*   The **Neutral class** presents the greatest difficulty, with an F1-score of 0.60, indicating challenges in distinguishing objective statements from mild subjectivity.

## Why This Works (Mechanism)
### Mechanism 1: Subword Tokenization Handles Noisy Orthography
- **Claim:** WordPiece subword tokenization mitigates the impact of spelling variations and out-of-vocabulary (OOV) terms in Romanized Hinglish.
- **Mechanism:** Unknown or morphologically variant words (e.g., "shukria", "shukriya") are segmented into frequent subword units (e.g., "shuk", "##ria") present in the multilingual vocabulary. The model composes meaningful embeddings from these shared subword representations.
- **Evidence Anchors:** [abstract] states the approach manages "spelling variations, slang, and out-of-vocabulary terms." [section 4.2] illustrates splitting like "likhna" → "li", "##kh", "##na." The corpus context (COMMENTATOR, MUTANT) confirms OOV and annotation challenges are prevalent.
- **Break Condition:** If spelling variation or novel slang exceeds the subword vocabulary's decomposition capacity, tokens remain effectively unknown, degrading performance.

### Mechanism 2: Multilingual Pretraining Enables Cross-Lingual Transfer
- **Claim:** mBERT's pretraining on 104 languages, including Hindi and English, provides cross-lingual knowledge transfer for code-mixed input.
- **Mechanism:** mBERT learns a shared embedding space and contextual representations from monolingual corpora. This allows it to infer semantics and syntax for code-switched segments by aligning representations across languages within a single sequence.
- **Evidence Anchors:** [abstract] highlights leveraging "multilingual capabilities." [section 2.2] explicitly states mBERT is "inherently suitable for Hinglish by leveraging shared vocabulary spaces." Neighbors (HiFACTMix, CONFLATOR) use multilingual models as primary baselines, establishing the paradigm.
- **Break Condition:** Failure occurs if code-mixing involves highly divergent syntax/scripts or extremely rare switching patterns not encountered during pretraining.

### Mechanism 3: Fine-Tuning Adapts to Domain-Specific Noise
- **Claim:** Fine-tuning on the Hinglish-24k tweets adapts mBERT's generic multilingual representations to the informal syntax and sentiment expressions of social media.
- **Mechanism:** Supervised learning on labeled Hinglish data updates mBERT's weights, aligning the [CLS] token representation and classification head with the target sentiment labels. This adjusts contextual embeddings to capture task-specific patterns like slang and domain-specific negation.
- **Evidence Anchors:** [section 4.3] describes the linear head and dropout. [section 5.1] provides hyperparameters (2e-5 lr, 3 epochs) typical for adaptation. Neighbors show similar fine-tuning pipelines for code-mixed sentiment.
- **Break Condition:** Inadequate or non-representative fine-tuning data leads to overfitting to training set biases and poor generalization.

## Architecture Onboarding
- **Component map:** Input Tweet -> mBERT Tokenizer (WordPiece) -> mBERT Encoder (12 layers) -> [CLS] Token Representation -> Dropout -> Linear Classification Layer -> Softmax Output (Negative/Neutral/Positive).
- **Critical path:** The tokenizer's vocabulary must cover subwords of both English and Romanized Hindi. The final hidden state of the [CLS] token is the sole input to the classifier. Model performance depends on mBERT's ability to generate a contextually rich representation from this mixed-language sequence.
- **Design tradeoffs:** Sequence length (128) truncates longer tweets, losing context. Batch size (8) constrained by GPU memory (Apple M3). Low learning rate (2e-5) prevents catastrophic forgetting but requires more epochs. Class imbalance (37.3% Neutral) is handled via weighted F1-score, not oversampling.
- **Failure signatures:** Low Neutral F1-score (0.60) indicates model conflates objective statements with mild subjectivity. Errors on sarcasm ("great service. Waited 2 hours.") and ambiguous slang ("mast") show limits in pragmatic understanding. A high OOV rate in tokenizer output for novel slang would be a precursor.
- **First 3 experiments:**
  1.  **Baseline Establishment:** Train and evaluate SVM and Naive Bayes with TF-IDF on the preprocessed training set to establish the ~0.65 performance ceiling for non-contextual models.
  2.  **mBERT Fine-tuning:** Fine-tune `bert-base-multilingual-cased` on the 80% training split (19,288 samples) using AdamW (lr=2e-5, batch=8, epochs=3). Evaluate on the held-out 10% test set (2,412 samples).
  3.  **Error Analysis & Class-wise Evaluation:** Compute per-class (Negative, Neutral, Positive) precision, recall, and F1-score. Manually inspect misclassified examples, focusing on Neutral errors to categorize failure modes (borderline sentiment, sarcasm, ambiguous slang).

## Open Questions the Paper Calls Out
### Open Question 1: Addressing the Neutral Class Performance Gap
- **Question:** How can the model's persistent difficulty with the [Neutral] class (F1=0.60) be systematically addressed?
- **Basis in paper:** Error analysis identifies "borderline neutral/subjective" tweets (e.g., mild opinions) as a primary error source.
- **Why unresolved:** The paper identifies the problem but provides no investigation into the linguistic characteristics of neutral tweets or targeted mitigation strategies (e.g., data augmentation, loss re-weighting).
- **What evidence would resolve it:** A qualitative/quantitative breakdown of misclassified neutral tweets, followed by experiments with class-balanced sampling, focal loss, or incorporating subjectivity detection features.

### Open Question 2: Tokenization Strategy Optimization for Hinglish Noise
- **Question:** To what extent do Hinglish spelling variations challenge subword tokenization, and can tokenization be optimized beyond mBERT's default WordPiece?
- **Basis in paper:** Methodology emphasizes subword tokenization's importance but provides no empirical validation of its efficacy specific to Hinglish noise or comparison with alternatives (BPE, Unigram).
- **Why unresolved:** The claim is asserted without an ablation study measuring tokenization consistency, vocabulary coverage, or performance impact on controlled Hinglish noise.
- **What evidence would resolve it:** An ablation comparing tokenization strategies on a curated test set with controlled spelling variations, measuring tokenization outcomes and downstream performance.

### Open Question 3: Comparison with Other Multilingual Transformers
- **Question:** How does mBERT's performance compare to other state-of-the-art multilingual transformers like XLM-R or mT5 on Hinglish-24k, especially given XLM-R's larger training corpus?
- **Basis in paper:** Related work cites studies suggesting XLM-R's potential superiority for Romanized Hindi, but experiments only benchmark against traditional ML (SVM, Naive Bayes).
- **Why unresolved:** The "strong benchmark" claim is limited by the narrow model comparison; the optimal transformer architecture for Hinglish remains unclear.
- **What evidence would resolve it:** A systematic evaluation of multiple multilingual transformers (mBERT, XLM-R, mT5) fine-tuned on the identical Hinglish-24k split, with statistical significance testing.

## Limitations
*   **Unspecified Preprocessing:** Faithful replication is blocked by two missing details: the exact emoji-to-text mapping (beyond a few examples) and the complete stop-word/filler list used for filtering.
*   **Static Benchmark:** Evaluation is confined to the curated Hinglish-24k test set; unknown how the model generalizes to newer slang, emerging platforms, or different demographic Hinglish varieties.
*   **Class-Specific Weakness:** The model shows a pronounced performance drop on the Neutral class (F1=0.60), indicating a limitation in handling objective or mild expressions common in social media.

## Confidence
*   **Claim Cluster 1 (Subword Tokenization Mitigates OOV):** **Medium Confidence.** The mechanism is sound and partially evidenced, but lacks a direct ablation comparing to word-level tokenization on the same data. The "break condition" is plausible but untested.
*   **Claim Cluster 2 (mBERT Enables Cross-Lingual Transfer):** **High Confidence.** This is the core, validated contribution. The experiment directly compares mBERT against non-multilingual baselines, showing a measurable lift (0.67 vs. 0.65/0.62).
*   **Claim Cluster 3 (Fine-Tuning Adapts to Social Media Noise):** **Medium Confidence.** The standard fine-tuning procedure is described, and performance gain over static models supports adaptation. However, a controlled ablation separating *domain* adaptation from *task* adaptation is absent.
