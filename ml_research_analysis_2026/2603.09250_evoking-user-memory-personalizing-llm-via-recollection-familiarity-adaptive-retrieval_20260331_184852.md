# Evoking User Memory: Personalizing LLM via Recollection-Familiarity Adaptive Retrieval

## Quick Facts
- **arXiv ID:** 2603.09250
- **Source URL:** https://arxiv.org/abs/2603.09250
- **Reference count:** 40
- **Primary result:** On PersonaMem, RF-Mem achieves up to +0.0136 absolute accuracy improvement over baselines across memory scales (32K–1M tokens) while maintaining retrieval latency near one-shot methods.

## Executive Summary
RF-Mem addresses the challenge of accurate and scalable memory retrieval for personalized large language models. Inspired by the dual-process theory of human memory, it introduces a retriever that dynamically switches between a fast Familiarity path (direct top‑K similarity) and an iterative Recollection path that clusters and mixes embeddings to build evidence chains. This adaptation is guided by a familiarity signal computed from the mean similarity and entropy of initial retrieval results. Evaluated on PersonaMem, PersonaBench, and LongMemEval across memory scales from 32K to 1M tokens, RF-Mem consistently surpasses both one‑shot dense retrieval and full‑context methods, achieving higher accuracy and recall while maintaining low latency. The framework demonstrates that cognitive‑inspired mechanisms can effectively balance precision and efficiency for long‑term personalization.

## Method Summary
RF-Mem is a dual‑process memory retriever for personalized LLMs. For a user query, it first probes the memory corpus using a dense retriever to obtain top‑K candidates and their similarity scores. From these, it computes a familiarity signal: the mean similarity and the entropy (after temperature‑scaled softmax) of the scores. A gate then selects either the Familiarity path (if familiarity is high) which returns the top‑K memories directly, or the Recollection path (if familiarity is low). The Recollection path operates iteratively: it retrieves a larger set, clusters the embeddings into B groups, computes centroids, and creates new probe queries by α‑mixing each centroid with the current query (plus the original query). These new queries are used in the next round, and the process repeats for R rounds or until K unique memories are gathered. The final set is re‑ranked and returned.

The method adapts to query difficulty without additional training, leveraging embedding geometry to explore memory facets. Key hyperparameters include softmax temperature λ, thresholds θ_high/θ_low/τ, beam width B, fanout F, mixing factor α, and max rounds R. By selectively engaging deeper search only when needed, RF‑Mem aims to optimize the trade‑off between retrieval accuracy and computational cost.

## Key Results
- On PersonaMem, RF‑Mem achieves answer accuracies of 0.6350 (32K), 0.5394 (128K), and 0.4589 (1M), surpassing baselines by up to +0.0136.
- Retrieval latency remains comparable to one‑shot dense retrieval (e.g., 5.09 ms vs 7.09 ms at 32K memory scale).
- Consistent gains on PersonaBench and LongMemEval with higher Recall@K scores across memory sizes.

## Why This Works (Mechanism)

### Mechanism 1: Familiarity Signal Estimation via Mean Score & Entropy
- **Claim:** RF‑Mem determines retrieval certainty by jointly modeling the average similarity of the top‑K probe results (mean score) and the distributional uncertainty of those scores (entropy). High mean with low entropy indicates confident "familiar" recognition; low mean or high entropy indicates "unfamiliar" need for deeper search.
- **Mechanism:** After an initial probe retrieval returning top‑K candidates with scores `s_i`, the system normalizes scores using a softmax with temperature λ to produce a probability distribution `p_i`. The mean `¯s = (1/K) Σ s_i` captures overall similarity. The entropy `H(p) = - Σ p_i log p_i` quantifies uncertainty about which item is most relevant. The selection policy uses thresholds `θ_high`, `θ_low` on `¯s` and `τ` on `H(p)` to choose between paths.
- **Core assumption:** The combination of central tendency (mean) and spread (entropy) reliably signals whether a one‑shot top‑K retrieval will capture the relevant memory, based on the premise that high‑quality retrieval lists have both high average similarity and peaked distributions.
- **Evidence anchors:**
  - [abstract]: "RF‑Mem measures the familiarity signal through the mean score and entropy. High familiarity leads to the direct top‑K Familiarity retrieval path, while low familiarity activates the Recollection path."
  - [section 2.1]: "Given probe scores {s_i}_i=1^K, we normalize them... The uncertainty is then measured by the entropy... The final selection combines the familiarity of the mean score with the uncertainty of the entropy."
  - [corpus]: Weak direct evidence; neighboring papers like *REMem* discuss reasoning with episodic memory but do not define a familiarity‑uncertainty gate. Supports the broader context of memory retrieval but not this specific mechanism.
- **Break condition:** The logic fails if the mean‑entropy combination is not a valid proxy for retrieval certainty, e.g., if high‑entropy lists still contain the correct item in the top‑K, or if low‑entropy lists miss the correct item. Also, thresholds may need adaptation for different embedding spaces or tasks.

### Mechanism 2: Recollection via Iterative Cluster-and-Mix
- **Claim:** When familiarity is low, RF‑Mem initiates a multi‑round "recollection" process that progressively expands evidence by clustering candidate memories, creating centroids, and blending each centroid with the current query to form new retrieval probes, simulating deliberate contextual reconstruction.
- **Mechanism:** Starting from the initial probe, at each round `r`: (1) Retrieve top‑N (with N = (B+r)F) candidates; (2) Cluster their embeddings into `B` groups (KMeans); (3) For each cluster centroid `g_b^{(r)}`, generate a "recollect query" via α‑mixing: `x_{b}^{(r+1)} = norm(α x^{(r)} + (1-α) g_b^{(r)} + x_t)`, where `x_t` is the original query; (4) Use these new queries for the next retrieval round. Unique hits across rounds are aggregated and re‑ranked up to K.
- **Core assumption:** Semantic clusters in the embedding space represent coherent memory facets; blending a centroid with the query steers the retrieval toward that facet while preserving query intent (via α and residual `x_t`), enabling stepwise evidence chaining.
- **Evidence anchors:**
  - [abstract]: "In the Recollection path, the system clusters candidate memories and applies α‑mix with the query to iteratively expand evidence in embedding space, simulating deliberate contextual reconstruction."
  - [section 2.3]: "Given the top‑N memory C^{(r)}, we group the candidate memory embeddings into B clusters... Each cluster centroid... is blended with the current query to form a recollect query... This retrieve‑cluster‑mix routine is repeated across rounds, progressively expanding evidence chains."
  - [corpus]: Neighbors like *REMem* and *EverMemOS* acknowledge the importance of episodic or structured memory for reasoning, providing contextual support but not the specific α‑mix cluster refinement.
- **Break condition:** If clustering is ineffective (e.g., no coherent groups due to noise or small N), centroids become meaningless. The α‑mix may overshoot if α is too high (stays local) or too low (drifts from query). Also, beam fanout `F` and rounds `R` must be bounded to control cost.

### Mechanism 3: Adaptive Path Switching
- **Claim:** The system dynamically chooses between fast Familiarity retrieval and slower, deeper Recollection based on the familiarity signal from Mechanism 1, thereby balancing accuracy and latency.
- **Mechanism:** After computing `¯s` and `H(p)` from the probe, apply the policy in Equation (3): if `¯s ≥ θ_high` → Familiarity; if `¯s ≤ θ_low` → Recollection; else if `H(p) ≤ τ` → Familiarity, else → Recollection. This gating adapts to the perceived uncertainty of the retrieval context.
- **Core assumption:** There exist regimes where a one‑shot top‑K is sufficient (high familiarity) and regimes where it is insufficient (low familiarity). The thresholds `θ_high`, `θ_low`, `τ` separate these regimes.
- **Evidence anchors:**
  - [abstract]: "RF‑Mem is a familiarity uncertainty‑guided dual‑path memory retriever... High familiarity leads to the direct top‑K Familiarity retrieval path, while low familiarity activates the Recollection path."
  - [section 2.1]: "This gating mechanism follows our cognitive motivation: when the familiarity signal is strong, the system relies on the fast Familiarity path for confident recognition; when the signal is weak, it engages the Recollection path to deliberately reconstruct evidence."
  - [corpus]: Not directly evidenced; neighboring works like *PersonalAI* compare storage/retrieval approaches but do not implement adaptive gating.
- **Break condition:** If the thresholds are poorly calibrated for a given corpus or embedding model, the switch may misfire: unnecessary Recollection wastes latency, or unwarranted Familiarity misses relevant memories. The entropy gate may be unstable if the score distribution is pathological.

## Foundational Learning
- **Concept: Dual‑Process Theory (Cognitive Psychology)**
  - *Why needed here:* RF‑Mem’s architecture is explicitly grounded in the recollection‑familiarity dual‑process model of human memory. Understanding this theory explains why two distinct retrieval modes exist and how they are governed by a familiarity signal.
  - *Quick check question:* According to dual‑process theory, what mental experience does "familiarity" provide, and what triggers "recollection"?
- **Concept: Embedding Similarity & Softmax Temperature**
  - *Why needed here:* The familiarity signal relies on cosine similarities between query and memory embeddings, and the softmax temperature `λ` controls the sharpness of the probability distribution used for entropy calculation.
  - *Quick check question:* How does increasing the softmax temperature `λ` affect the entropy `H(p)` computed from the probe scores?
- **Concept: K‑Means Clustering & Centroid Computation**
  - *Why needed here:* The Recollection path groups retrieved candidates into `B` clusters and uses their centroids as semantic anchors for query mixing. Clustering quality directly impacts the effectiveness of evidence expansion.
  - *Quick check question:* In the context of RF‑Mem’s recollection, what is the purpose of computing a cluster centroid from retrieved memory embeddings before mixing with the query?

## Architecture Onboarding
- **Component map:**  
  1. **Input:** User query `q` and memory corpus `M` (indexed embeddings).  
  2. **Probe Retriever:** Computes top‑K probe similarity scores `s_i`.  
  3. **Familiarity Estimator:** Calculates mean `¯s` and entropy `H(p)` from probe scores.  
  4. **Gate:** Compares `(¯s, H(p))` against thresholds to select path.  
  5. **Familiarity Path:** Returns top‑K memories by direct similarity.  
  6. **Recollection Path:** Loop (retrieve top‑N → KMeans → α‑mix → new queries) until `R` rounds or `K` unique items collected.  
  7. **Output:** Ranked memory set `S` (size ≤ K) for LLM generation.
- **Critical path:** Probe → Familiarity Estimator → Gate → (if Recollection) [Retrieve → Cluster → Mix]×R → Aggregate → Return Top‑K. The probe and gate are the decision hub; the recollection loop introduces iterative expansion.
- **Design tradeoffs:**  
  - *Latency vs. Recall:* Recollection increases latency (more retrievals + clustering) but can improve recall on complex queries. The gate aims to invoke Recollection only when needed.  
  - *Beam width (B) & Fanout (F):* Larger `B` explores more cluster branches; larger `F` retrieves more per round. Both increase coverage but also cost and risk noise.  
  - *α‑mix balance:* Low `α` (centroid‑heavy) explores divergent facets; high `α` (query‑heavy) stays close to original intent. Tuning `α` affects recall vs. precision.
- **Failure signatures:**  
  - *Frequent Recollection on simple queries:* High entropy from probe despite a correct answer being in top‑K → wasted latency.  
  - *Clustering divergence:* Poorly separated clusters cause centroids to mix unrelated memories → `α`‑mix drifts from query intent.  
  - *Threshold mismatch:* For a new corpus with different similarity scale, `θ_high/θ_low/τ` may be too strict/lenient causing systematic misrouting.
- **First 3 experiments:**  
  1. *Probe retrieval sanity check:* Run a fixed probe (K=20) on a sample corpus, plot `¯s` and `H(p)` histograms. Verify `¯s` distribution is meaningful and `H(p)` varies with query ambiguity.  
  2. *Isolated path evaluation:* Run **only** Familiarity (always take top‑K) and **only** Recollection (always run full loop) on a validation set. Compare accuracy and latency to understand individual contribution.  
  3. *Gate validation:* Run RF‑Mem with fixed `θ_high/θ_low/τ` and manually inspect misrouted cases (e.g., Recollection invoked but Familiarity would have sufficed). Use findings to adjust thresholds or consider learning them (as in Appendix D.6).

## Open Questions the Paper Calls Out
- **Open Question 1**
  - Question: Can RF‑Mem's familiarity‑recollection switching generalize to multimodal user memories (e.g., images, audio)?
  - Basis in paper: [explicit] Limitations: "evaluation is confined to dialogue‑style personalized memory and does not yet explore other modalities (e.g., cross‑modal histories)."
  - Why unresolved: The design uses text‑specific embeddings and cosine similarity; other modalities may yield different familiarity‑entropy distributions, affecting routing.
  - What evidence would resolve it: Benchmark RF‑Mem on a multimodal dataset (e.g., MMVet) with vision‑language encoders and analyze switching accuracy versus text‑only baseline.

- **Open Question 2**
  - Question: Is list entropy alone sufficient to estimate uncertainty for routing, or are richer signals needed?
  - Basis in paper: [explicit] "we adopt list entropy as a lightweight uncertainty proxy; although effective, it may not fully capture finer‑grained task difficulty or user intent."
  - Why unresolved: Entropy depends only on similarity score distribution; it may not reflect semantic ambiguity or true task difficulty, leading to suboptimal path selection.
  - What evidence would resolve it: Compare entropy against human difficulty ratings, or replace with calibration‑aware signals in a controlled experiment on routing error.

- **Open Question 3**
  - Question: How can RF‑Mem incorporate temporal dynamics into its memory index to model evolution and conflicts?
  - Basis in paper: [explicit] "our retrieval operates over a static embedding index, without modeling temporal updates of memory or potential conflicts across long‑term sessions."
  - Why unresolved: A static index cannot adapt to memory decay, recency, or contradictory updates, risking outdated or inconsistent retrieval.
  - What evidence would resolve it: Augment memory entries with timestamps, design time‑aware similarity functions, and evaluate on longitudinal memory benchmarks with freshness metrics.

- **Open Question 4**
  - Question: What privacy‑preserving mechanisms can be added to RF‑Mem's recollection to avoid exposing sensitive user information?
  - Basis in paper: [explicit] "downstream deployments should include safeguards to prevent unintended resurfacing of sensitive information, a direction we identify as important future work for quantifying and mitigating such risks."
  - Why unresolved: The recollection process may amplify exposure of sensitive content via iterative retrieval; the paper lacks any privacy analysis or controls.
  - What evidence would resolve it: Integrate a sensitive entity detector or differential privacy into the retrieval loop, measure retention of sensitive data while tracking performance drop.
