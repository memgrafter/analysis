# Logic-Parametric Neuro-Symbolic NLI: Controlling Logical Formalisms for Verifiable LLM Reasoning

## Quick Facts
- **arXiv ID:** 2601.05705
- **Source URL:** https://arxiv.org/abs/2601.05705
- **Reference count:** 38
- **Primary result:** A logic-parametric framework using LogiKEy achieves up to 77.67% explanation success rate on normative reasoning (BENR) with KD modal logic and GPT-4o, outperforming FOL and logic-external approaches.

## Executive Summary
Fixed logical formalisms in neuro-symbolic Natural Language Inference (NLI) systems hinder robustness across domains. This paper introduces a logic-parametric framework that treats the logic itself as a controllable parameter, leveraging the LogiKEy methodology to embed multiple classical and non-classical logics (e.g., FOL, KD modal, deontic conditionals) into Higher-Order Logic (HOL). The system iteratively refines natural language explanations into formal, verifiable theories using an LLM and Isabelle/HOL prover. On the new BENR dataset for normative reasoning, logic-internal strategies (where normative principles are built into the logic’s axioms) consistently outperform logic-external ones. KD modal logic achieves the highest success rate (77.67% with GPT-4o), requires fewer refinement iterations, and yields faster solving times. Results reveal a clear domain dependency: FOL favors commonsense reasoning, while deontic and modal logics excel in ethical domains, underscoring the importance of logic selection for proof efficiency and explanation quality.

## Method Summary
The task is verifiable NLI: given a premise, hypothesis, and natural language explanation, the system must produce a formal theory in a chosen logic that an automated theorem prover can verify. The pipeline has four stages: (1) Autoformalization: an LLM translates the NL explanation into Isabelle/HOL axioms within the selected logic’s LogiKEy embedding; (2) Syntax & Consistency Check: validates the formalization for syntactic correctness and non-contradiction; (3) Theorem Proving: attempts to prove the hypothesis from the premises using Isabelle’s Sledgehammer/Nitpick; (4) Explanation Refinement: if the proof fails, the LLM is given symbolic feedback and generates a revised explanation, repeating up to three iterations. The method compares logic-internal approaches (using built-in normative axioms, e.g., KD’s Oφ→Pφ) against logic-external ones (adding similar axioms as premises to FOL). Models evaluated: GPT-4o and DeepSeek-V1. Datasets: BENR (103 examples) focused on normative/bioethical reasoning.

## Key Results
- KD modal logic achieves the highest explanation success rate (up to 77.67% with GPT-4o), significantly surpassing FOL and logic-external variants.
- Logic-internal strategies require fewer refinement iterations and reduce average solving time compared to FOL, indicating more efficient proof search.
- Performance is domain-dependent: FOL performs better on commonsense reasoning, while deontic (DDL_CJ) and modal (KD) logics excel in ethical domains, demonstrating that logic choice must align with domain characteristics.

## Why This Works (Mechanism)
The framework’s effectiveness stems from embedding normative principles directly into the logic’s axioms (logic-internal approach). For instance, KD modal logic includes seriality and the bridge axiom Oφ→Pφ, which align with common patterns in normative reasoning. This structural integration means fewer explicit premises are needed, simplifying the proof search space for the theorem prover. The LogiKEy methodology provides a uniform Higher-Order Logic foundation, allowing Isabelle/HOL to apply its automated tactics across different logics without reimplementing proof search. Consequently, when the LLM’s autoformalization roughly matches the logic’s native inference patterns, proof attempts succeed faster and with less refinement. The iterative refinement loop uses symbolic feedback from failed proof steps to guide the LLM toward adding missing bridge rules or correcting malformed expressions, progressively converging on a verifiable explanation.

- **Neuro-symbolic NLI:** Combines neural language understanding (LLM) with symbolic verification (theorem prover). *Why needed:* Ensures LLM outputs are logically sound and interpretable. *Quick check:* Does each explanation yield a machine-checked proof?
- **Logic-parametrization:** Treats the logical formalism as a configurable parameter rather than a fixed choice. *Why needed:* Allows adaptation to domain-specific reasoning patterns (e.g., modal for ethics). *Quick check:* Can the pipeline run with different logics (FOL, KD, etc.) by simply switching configuration?
- **LogiKEy method:** Encodes various logics as Isabelle/HOL theories. *Why needed:* Enables a single prover to handle multiple logics uniformly. *Quick check:* Are the target logics (KD, DDLE, DDL_CJ) available as Isabelle sessions?
- **Autoformalization:** LLM-based translation from natural language to formal logic. *Why needed:* Bridges human explanations to machine-verifiable form. *Quick check:* Is the generated Isabelle code syntactically valid for the selected logic?
- **Theorem proving (Isabelle/HOL):** Automated proof search using Sledgehammer/Nitpick. *Why needed:* Provides formal verification of the NLI explanation. *Quick check:* Does the prover succeed within resource limits for valid theories?
- **Logic-internal vs. external:** Where normative principles reside (inside logic axioms vs. added as premises). *Why needed:* Affects proof efficiency and alignment with domain patterns. *Quick check:* Compare success rates of internal (KD) vs external (FOL+axioms) on normative examples.

## Architecture Onboarding
Component map: Autoformalization → Syntax & Consistency Check → Theorem Proving → Explanation Refinement (loops back to Autoformalization upon failure).  
Critical path: The iterative refinement cycle—failed proof generates feedback that modifies the natural language explanation, which is re-formalized and re-proven. Success depends on the LLM’s ability to interpret symbolic feedback and incorporate missing rules without introducing errors.  
Design tradeoffs:  
- Logic choice: Modal/deontic logics offer built-in normative operators but may be less familiar to LLMs; FOL is general but requires more explicit axioms.  
- Internal vs external: Internal reduces premise load but may be semantically rigid; external is flexible but can bloat the theory and confuse the prover.  
- Automation vs control: Full automation risks malformed formalizations; adding manual checks slows the pipeline.  
Failure signatures:  
1. Malformed formalization: Syntax errors or type mismatches in Isabelle code (caught in Stage 2).  
2. Proof search stall: Prover fails to find a proof within time/memory limits, often due to missing bridge lemmas.  
3. Semantic violation: The formalization violates the logic’s frame conditions (e.g., KD’s seriality axiom unsatisfied), causing indirect failures.  
First three experiments:  
1. Baseline replication: Run the pipeline on BENR with GPT-4o and KD logic. Confirm success rate ~77% and average iterations ≤2.  
2. Logic comparison test: Execute the same pipeline with FOL, KD, DDLE, DDL_CJ across BENR domains. Verify that modal/deontic logics outperform FOL on normative items.  
3. Malformed input injection: Introduce examples that violate KD seriality or DDL consistency. Observe whether refinement repairs the violation or merely adds compensating axioms.

## Open Questions the Paper Calls Out
1. **How does performance vary across a broader spectrum of LLMs?**  
   *Basis:* Explicit – authors used only GPT-4o and DeepSeek-V1.  
   *Why unresolved:* Interaction between LLM biases and logical constraints unexplored.  
   *Evidence needed:* Systematic evaluation across diverse models (open/closed, sizes, reasoning-trained) on BENR.

2. **Can systems dynamically select or combine logics within a single reasoning episode?**  
   *Basis:* Inferred – conclusion proposes logic-adaptive architectures, but tests used static logic per run.  
   *Why unresolved:* Mechanisms for hybrid or context-aware logic choice not investigated.  
   *Evidence needed:* Meta-controller that recommends logic based on input features, benchmarked against best single-logic baseline.

3. **What are the cognitive/epistemic trade-offs between logic-internal and logic-external formalizations for moral reasons?**  
   *Basis:* Explicit – paper defines and contrasts both; internal performed better.  
   *Why unresolved:* Theoretical reasons (proof complexity, explicitness of norms, defeasibility handling) not formally analyzed.  
   *Evidence needed:* Formal comparison of minimal axiom sets for key normative inferences; controlled experiments isolating formalization effect on refinement and runtime.

4. **Do deontic/modal advantages stem from better match to BENR patterns versus inherent logic properties?**  
   *Basis:* Inferred – domain-dependency observed; logics chosen for normative relevance.  
   *Why unresolved:* Unclear if gap is due to correspondence between inference rules and dataset patterns or general factors (LLM familiarity with modal keywords, HOL embedding efficiency).  
   *Evidence needed:* Error analysis categorizing missing rules; evaluation on synthetically perturbed BENR (replace normative terms with neutral ones); human evaluation of formalization intuitiveness.

5. **How are semantic violations of a logic’s prerequisites handled and can refinement repair them?**  
   *Basis:* Explicit – pipeline includes consistency check, but refinement strategies focus on missing rules, not violated axioms.  
   *Why unresolved:* Refinement loop’s ability to diagnose and correct violations (e.g., KD seriality) unclear.  
   *Evidence needed:* Test cases with premise sets violating frame conditions; analyze prover error messages and LLM refinement outputs for correct diagnosis and repair.

## Limitations
- Unreleased prompts, hyperparameters, and BENR dataset prevent exact replication of experiments.
- Small, domain-specific corpus (103 examples) limits the generalizability of performance claims.
- Evaluation restricted to two LLMs, leaving model-dependent effects unexplored.

## Confidence
- Logic-internal strategies yield higher success rates: **Medium** (empirical results clear but depend on unreleased artifacts).
- Domain dependency of logic choice (FOL vs. deontic/modal): **Medium** (supported by BENR but requires cross-dataset verification).
- Technical soundness of LogiKEy embedding and pipeline design: **High** (built on established Isabelle/HOL infrastructure and prior Faithful-Refiner framework).
