# Can LLM Agents Generate Real-World Evidence? Evaluating Observational Studies in Medical Databases
## Quick Facts
- arXiv ID: 2603.22767
- Source URL: https://arxiv.org/abs/2603.22767
- Reference count: 40
- Primary result: Best agent achieves 39.9% task success rate; scaffold choice causes >30% performance variation.

## Executive Summary
This paper introduces RWE-bench, a benchmark for evaluating large language model (LLM) agents on end-to-end observational studies using the MIMIC-IV clinical database. It addresses a gap in assessing whether LLMs can autonomously execute real-world evidence generation from raw data to final evidence bundles. The benchmark comprises 162 tasks derived from peer-reviewed studies, requiring agents to follow protocols, query databases, perform statistical analyses, and produce structured outputs. Results show persistent challenges: the top agent (Claude-Sonnet-4 with RWEAgent) reaches only 39.9% task success, and scaffold design significantly impacts performance. An automated LLM judge enables scalable cohort validation but highlights precision-recall trade-offs, underscoring the need for more robust, domain-specific agent systems.

## Method Summary
The evaluation uses RWE-bench, a suite of 162 tasks extracted from published observational studies on MIMIC-IV (v2.2). Each task provides a study protocol (background, methods, research questions) and requires the agent to generate a tree-structured evidence bundle containing cohort definitions, statistical analyses, and answers to multiple-choice questions. Agents operate in a sandboxed Docker environment with an R workspace and PostgreSQL database, following one of three scaffolds (MLAB, OpenHands, RWEAgent) under fixed resource constraints (max 100 steps, 2 hours total). Performance is measured via question-level metrics (accuracy, regulatory alignment for effect estimates, significance match for p-values) and task-level success rate (all answers correct and analyses aligned). For RWEAgent runs, an LLM judge (GPT-5) screens generated cohorts for validity, excluding tasks with >80% patient exclusion rate.

## Key Results
- Best task success rate: 39.9% (Claude-Sonnet-4 with RWEAgent); best open-source model (MiniMax-M2.1) reaches 30.4%.
- Agent scaffold choice induces over 30% variation in performance, outweighing individual model differences in many comparisons.
- Automated cohort evaluation via LLM judge efficiently flags invalid cohorts but exhibits precision-focused screening with limited recall.

## Why This Works (Mechanism)
LLM agents can parse study protocols and generate executable code (SQL/R) to manipulate medical databases, producing structured evidence trees. The scaffold design guides the agent through iterative steps: planning, coding, validation, and submission. Success depends on the agent's ability to correctly interpret clinical questions, construct valid cohorts, apply appropriate statistical tests, and align results with the protocol. The tree structure enforces organization, while the audit file and LLM judge provide automated checks to catch common errors like fabricated patient IDs or oversized cohorts.

## Foundational Learning
- **Observational study execution**: Why needed: To assess real-world treatment effects from electronic health records. Quick check: Agent output includes a complete cohort definition and statistical analysis for each question.
- **Tree-structured evidence bundles**: Why needed: To hierarchically organize findings from multiple research questions. Quick check: Verify all protocol questions are addressed in separate branches with supporting analysis.
- **Cohort validation**: Why needed: To ensure patient subsets are correctly defined and feasible. Quick check: Audit file contains valid MIMIC-IV IDs, reasonable size (<50k), and clear inclusion/exclusion logic.
- **Statistical alignment**: Why needed: To match reported effect sizes and p-values with ground truth. Quick check: Compare agent's effect estimates and significance (RAR, SMR metrics) against study conclusions.
- **Agent scaffold design**: Why needed: To steer LLMs through complex, multi-step analysis. Quick check: Monitor agent's step count, termination behavior, and recurrence of errors like repeated code edits.

## Architecture Onboarding
- **Component map**: Protocol -> Agent Scaffold (with LLM) -> Database (MIMIC-IV) -> Evidence Tree -> Evaluation (LLM judge + metrics)
- **Critical path**: Protocol interpretation → SQL/R code generation → cohort extraction → statistical analysis → answer submission (gated by MCQ correctness).
- **Design tradeoffs**: Scaffold complexity (e.g., memory compression in RWEAgent) vs. reliability; closed-source vs. open models balancing capability and cost; token efficiency vs. analytical thoroughness.
- **Failure signatures**: Early termination (finish_task after first submission); invalid cohorts (fabricated IDs, ambiguous definitions); stuck execution (repeated errors, max steps reached); high token consumption without progress.
- **First experiments**:
  1. Run one task with a single model (e.g., Claude-Sonnet-4) to validate environment setup (Docker, DB connection, R packages).
  2. Test cohort generation rules with a simple protocol to verify audit file compliance (ID validity, size limits).
  3. Compare scaffold behaviors on a trivial task to observe termination patterns and step efficiency.

## Open Questions the Paper Calls Out
The paper does not explicitly enumerate open questions or future work. However, the findings and limitations imply several directions for further research:
- How can agent scaffold design be refined to reduce performance variability and improve overall task success rates?
- What modifications to the LLM judge can enhance recall without sacrificing precision in cohort validation?
- How can the benchmark be generalized beyond MIMIC-IV to other clinical databases or medical domains?
- What strategies can address reproducibility challenges arising from unreleased code and environment specifics?

## Limitations
- Codebase not released at submission; scaffold implementations rely on descriptions that may omit critical logic.
- Undocumented environment specifics (Docker tags, R package versions, PostgreSQL drivers) risk silent reproducibility gaps.
- MIMIC-IV access requires credentialed approval, creating a barrier to independent benchmarking.

## Confidence
- Agent scaffold causes >30% performance variation: Medium
- Reported model success rates (39.9%/30.4%): Low
- LLM judge precision-recall trade-off: Medium
