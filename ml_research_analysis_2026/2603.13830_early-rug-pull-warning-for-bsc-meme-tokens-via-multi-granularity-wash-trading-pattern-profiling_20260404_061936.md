# Early Rug Pull Warning for BSC Meme Tokens via Multi-Granularity Wash-Trading Pattern Profiling

## Quick Facts
- **arXiv ID:** 2603.13830
- **Source URL:** https://arxiv.org/abs/2603.13830
- **Reference count:** 16
- **Primary result:** Multi-granularity wash-trading pattern profiling with Random Forest achieves AUC 0.9098 for early rug-pull detection on BSC meme tokens.

## Executive Summary
This paper tackles the challenge of early rug-pull detection for Binance Smart Chain (BSC) meme tokens, where anomalies are scarce and supervision is weak. It introduces an end-to-end framework that profiles wash-trading patterns at three granularities—Self, Matched, and Circular—to construct 12 token-level behavioral features from transaction, address, and flow signals. Evaluated on 7 tokens and 33,242 transaction records using Random Forest, the model achieves strong performance (AUC 0.9098, PR-AUC 0.9185, F1 0.7429) and a mean lead time of ~3.8 hours before rug-pull events. Ablation studies confirm the dominance of trade-level features, with address-level features providing stable complementary gains. The low false positive (1) and false negative (8) counts on a tiny test set suggest potential as a high-precision screener for human-in-the-loop triage, though generalizability remains a major concern.

## Method Summary
The proposed framework first identifies wash-trading transactions through three pattern types: Self (single address circular transfers), Matched (two addresses reciprocal transfers), and Circular (multi-address loops). From these, 12 token-level behavioral features are engineered, capturing aspects like transaction frequency, unique counterparty ratios, and flow concentration. A Random Forest classifier is then trained on labeled token lifespans (rug-pull vs. normal). The approach is evaluated retrospectively on a small set of confirmed rug-pull tokens and their matched normal counterparts, with performance measured via AUC, PR-AUC, F1, and lead time.

## Key Results
- Achieves AUC 0.9098, PR-AUC 0.9185, and F1 0.7429 on the test set, outperforming Logistic Regression.
- Ablation shows trade-level features are primary (ΔPR-AUC -0.1843), while address-level features provide stable complementary gain (ΔPR-AUC -0.0573).
- Mean lead time of 3.8133 hours before rug-pull, with an error profile of FP=1 and FN=8 on the test data.

## Why This Works (Mechanism)
Rug-pull scams on BSC meme tokens frequently involve wash-trading to fabricate artificial volume and attract investors. By modeling wash-trading at multiple granularities (Self, Matched, Circular), the framework captures nuanced behavioral deviations from legitimate trading activity. These patterns reflect coordinated manipulation that is statistically anomalous in normal token ecosystems, providing early warning signals before the developer drains liquidity.

## Foundational Learning
- **Wash-trading detection:** Identifying fake transactions (e.g., circular transfers) is core to spotting manipulation. *Why needed:* Rug-pulls often rely on wash-trading to simulate demand. *Quick check:* Find address clusters with reciprocal or circular token flows.
- **Behavioral feature engineering:** Translating raw transaction logs into token-level metrics (e.g., transaction count, counterparty diversity). *Why needed:* Condenses complex sequences into discriminative signals for classification. *Quick check:* Compute per-token statistics like average transaction value or unique sender/receiver ratios.
- **Weak supervision:** Handling scarce positive (rug-pull) labels via heuristics or external validation. *Why needed:* True rug-pull events are rare and often identified only after the fact. *Quick check:* Use blockchain explorers or scam alert lists as noisy labels.
- **Imbalanced evaluation:** Prioritizing PR-AUC over accuracy for rare-event detection. *Why needed:* Accuracy is misleading when negatives vastly outnumber positives. *Quick check:* Ensure precision and recall are both high (>0.7) for practical utility.
- **Random Forest classifier:** An ensemble method robust to overfitting on small datasets and providing feature importance. *Why needed:* Balances performance with interpretability for forensic analysis. *Quick check:* Compare feature importance rankings against domain expectations.
- **Lead time measurement:** Computing hours between first alert and actual rug-pull. *Why needed:* Quantifies practical timeliness for intervention. *Quick check:* Align alert timestamps with known liquidity-removal events.

## Architecture Onboarding
Component map: Raw Transaction Data -> Wash-Trading Pattern Detection (Self/Matched/Circular) -> Behavioral Feature Aggregation (12 token-level features) -> Random Forest Classification -> Alert Generation

Critical path: The pipeline's efficacy hinges on accurate pattern detection and feature extraction, as these transform raw blockchain data into the discriminative inputs for the classifier.

Design tradeoffs: Handcrafted feature engineering prioritizes interpretability and forensic relevance but may miss emergent patterns; Random Forest offers robustness on small data but may underfit complex dynamics; static snapshot analysis simplifies deployment but ignores temporal concept drift.

Failure signatures: High false positives on legitimate high-activity tokens (e.g., popular airdrops); false negatives on slowly executed rug-pulls or novel wash-trading tactics; degradation in performance on tokens with atypical lifespans (e.g., long dormant periods).

First experiments:
1. Replicate the feature extraction pipeline on a larger, diverse token set to validate feature stability and ranking.
2. Retrain the Random Forest with different hyperparameters (e.g., class weights, tree depth) to optimize for precision versus recall.
3. Implement a simple time-windowed analysis (e.g., sliding 24-hour features) to assess sensitivity to early vs. late-stage trading patterns.

## Limitations
- **Small-scale validation:** Evaluation on only 7 tokens (33k transactions) severely limits statistical robustness and generalizability.
- **Labeling uncertainty:** Weak supervision with scarce positives risks mislabeling "normal" tokens (e.g., failed projects) and inflating performance.
- **Static snapshot assumption:** No assessment of concept drift or evolving scam tactics, critical for real-world early warning.

## Confidence
- Multi-granularity feature utility (Self/Matched/Circular): **High** (well-motivated by forensics, strong ablation support).
- Reported performance metrics (AUC 0.9098, PR-AUC 0.9185): **Medium** (promising but on tiny dataset; overfitting risk).
- Practical utility as a high-precision screener: **Low** (error profile derived from minuscule test set; lead time lacks distribution analysis).

## Next Checks
1. **Scalability & Diversity Test:** Replicate on a larger, chronologically diverse dataset (100+ tokens, multiple market cycles) to validate performance stability and feature importance.
2. **Cross-Chain Generalizability:** Apply the exact feature extraction pipeline and model to memetoken datasets from other chains (Ethereum, Solana, TON) to test chain-agnostic vs. BSC-specific patterns.
3. **Temporal Robustness & Concept Drift Audit:** Conduct time-series split validation (train on early-period tokens, test on later-period tokens) to measure viability for future warning, not just retrospective analysis.
