# xaitimesynth: A Python Package for Evaluating Attribution Methods for Time Series with Synthetic Ground Truth

## Quick Facts
- **ArXiv ID**: 2603.06781
- **Source URL**: https://arxiv.org/abs/2603.06781
- **Reference count**: 17
- **Primary result**: Provides a standardized Python package for time series attribution evaluation using synthetic data with known ground truth masks, replacing per-study reimplementations with a shared, turnkey toolkit.

## Executive Summary
Time series attribution evaluation suffers from a lack of ground truth, forcing researchers to repeatedly build custom synthetic data pipelines. This paper introduces **xaitimesynth**, a Python package that addresses this gap by generating synthetic time series via an additive model (background signal plus localized, class-discriminating feature) and automatically tracking the feature window as a binary ground truth mask. It offers a fluent API and YAML configuration for flexible, reproducible dataset definitions and bundles standard localization metrics (e.g., AUC-PR, AUC-ROC, Relevance Mass Accuracy) for direct evaluation. By codifying the entire evaluation workflow—from synthetic data creation to metric computation—the package reduces implementation overhead and promotes standardization in time series XAI research.

## Method Summary
xaitimesynth generates synthetic datasets through an additive process: `x = n + f`, where `n` is a configurable background signal (e.g., Gaussian noise, seasonal patterns) and `f` is a localized feature (e.g., Gaussian pulse, oscillation) placed within specific time windows and channels. The feature's temporal and spatial extent is automatically recorded as a binary mask, serving as ground truth. Users define datasets via a `TimeSeriesBuilder` fluent interface or a YAML configuration, specifying signal/feature compositions per class. After generating train/test splits (`Dataset` objects containing `X`, `y`, `masks`), external XAI methods produce attributions for the test set. The package's metrics module then computes localization scores by comparing attributions against the stored masks.

## Key Results
- Replaces ad-hoc, per-study synthetic pipeline implementations with a reusable, open-source toolkit (MIT license).
- Embeds known ground truth via an additive model with automatic mask tracking, enabling sanity checks for attribution correctness.
- Provides a turnkey system combining data generation and standardized localization metrics for time series attribution evaluation.

## Why This Works (Mechanism)
### Mechanism 1: Ground Truth via Additive Model
The package's core generation model (`x = n + f`) ensures the feature location is known by construction. If a classifier attains high accuracy, the only plausible source of class-discriminating information—absent systematic artifacts—is the intended feature, making its location a valid benchmark for attributions. Evidence: The abstract and Section 3.1 detail `TimeSeriesBuilder` and internal mask creation. Break condition: Validity collapses if background generation introduces unintended, class-dependent statistical artifacts (e.g., variance differences) that models exploit.

### Mechanism 2: Lowered Engineering Friction
A fluent API and YAML configuration abstract the software overhead of implementing and documenting synthetic pipelines, enabling concise, reproducible dataset definitions. Identical specifications produce identical datasets (given fixed seeds), codifying the data-generating process. Evidence: Abstract mentions API/YAML; Section 3.1 shows examples. Break condition: Reproducibility is compromised if the configuration format lacks expressiveness for novel, complex generation logic (e.g., non-additive interactions).

### Mechanism 3: Bundled Localization Metrics
Pre-implemented metrics (AUC-PR, AUC-ROC, Relevance Mass/Rank Accuracy) directly quantify spatial alignment between continuous attributions and binary masks, avoiding per-study metric reimplementation. This provides interpretable "pointing" accuracy. Evidence: Abstract lists metrics; Section 3.2 defines their logic. Break condition: Metrics may mislead if mismatched to attribution characteristics (e.g., rank-based metric for dense scores) or synthetic feature definitions.

## Foundational Learning
- **Synthetic Data Generation for XAI Sanity Checks**  
  *Why needed*: The package assumes known causal features allow sanity checks on attributions.  
  *Quick check*: What are two ways a model could achieve high accuracy without learning the intended feature? (1) Exploiting background artifacts (e.g., noise variance differences). (2) Overfitting to spurious synthetic patterns unrelated to the feature.

- **Localization vs. Perturbation-Based Evaluation**  
  *Why needed*: xaitimesynth provides localization metrics; users must know when to apply each.  
  *Quick check*: If an attribution scores high on AUC-PR but low on infidelity (a perturbation metric), what might this indicate? The attribution may point to the feature but not reflect the model's actual functional reliance on that region.

- **Time Series Attribution Methods**  
  *Why needed*: Attributions come from external methods (e.g., Integrated Gradients, SHAP).  
  *Quick check*: Why are standard image attribution metrics often insufficient for time series? They ignore temporal dependencies and sequential structure, requiring adaptation for 1D ordered data.

## Architecture Onboarding
**Component map**:  
TimeSeriesBuilder → (Signal/Feature Generators) → Dataset (X, y, masks) → Metrics Module. YAML Loader → TimeSeriesBuilder.

**Critical path**:  
1. Define dataset via `TimeSeriesBuilder`/YAML (signals/features per class, lengths).  
2. Generate train/test splits with `.build()`.  
3. Explain test `X` with external XAI → `attributions`.  
4. Evaluate: `metric(attributions, test_dataset)`.  
5. Iterate with varied builder configs.

**Design tradeoffs**:  
- Simplicity vs. expressivity: Additive model eases mask tracking but cannot capture complex non-additive boundaries.  
- Metric coverage vs. focus: Curated common metrics; excludes newer/specialized ones.  
- Fluent API vs. YAML: API offers programmatic flexibility; YAML aids sharing/versioning.

**Failure signatures**:  
- Synthetic data is too easy (model accuracy ≈100%).  
- Feature leakage into class-dependent background.  
- Metric-attribution mismatch (e.g., point-wise metric on rank-based attributions).  
- Shape mismatch between attributions and masks.

**First 3 experiments**:  
1. Replicate Listing 1 exactly; use dummy attributions to verify metric outputs and mask alignment.  
2. Build a 2-channel dataset where the feature appears only in channel 0 for class 0 and channel 1 for class 1; confirm perfect attribution yields AUC-PR = 1.0.  
3. On a simple dataset, create three flawed attributions: (a) correctly located but too broad, (b) correctly located but noisy, (c) localized in wrong window; compare how metrics rank these failures.

## Limitations
- **Generative model scope**: The additive model cannot express non-additive class boundaries or feature interactions, limiting ecological validity.
- **Metric-attribution alignment**: Standard localization metrics may mislead for non-sparse or concept-based attributions.
- **Synthetic data realism**: Generated series may not match real time series statistical properties (e.g., autocorrelation), risking artifacts that models exploit.

## Confidence
- **Standardized synthetic pipeline**: High (concrete implementation addresses reimplementation problem).
- **Reproducible dataset definition**: Medium (expressiveness for complex/non-additive logic unproven).
- **Turnkey evaluation**: High (metrics are clear and integrated) / Medium (appropriateness for all attribution types uncertain).

## Next Checks
1. **Test non-additive generation limits**: Attempt to define datasets requiring multiplicative interactions or context-dependent effects using custom generators; verify mask tracking remains valid.
2. **Metric robustness across attribution types**: Generate one dataset; compute metrics using attributions from diverse methods (Integrated Gradients, SHAP, DeepLIFT, naive gradient). Compare scores for systematic biases.
3. **Statistical artifact detection**: For a multivariate dataset, perform two-sample tests (e.g., on autocorrelation, variance) between class-wise background signals; significant differences indicate unintended leakage.
