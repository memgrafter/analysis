# MemPO: Self-Memory Policy Optimization for Long-Horizon Agents
## Quick Facts
- arXiv ID: 2603.00680
- Source URL: https://arxiv.org/abs/2603.00680
- Reference count: 17
- Primary result: Achieves absolute F1 gains of 25.98% over base model and 7.1% over previous SOTA, while reducing token consumption by 67.58% and 73.12% respectively across five long-horizon benchmarks.

## Executive Summary
Long-horizon agents face challenges with expanding context that degrades performance and increases token usage. Existing memory systems are external and passive, not optimized for task goals. MemPO introduces self-memory policy optimization, enabling the policy to autonomously summarize and manage history via a `<mem>` action. It uses group-relative RL to assign tokens a combined advantage: a trajectory-level score from final answer correctness, plus for memory tokens an extra step-level reward based on the conditional probability that the memory contains information needed to produce the correct answer. This directs the model to keep only task-relevant details. Tested on five long-horizon benchmarks, MemPO achieves substantial improvements in both accuracy and token efficiency.

## Method Summary
MemPO formalizes agent actions: `<mem>` (memory summary), `<think>` (reasoning), `<tool_call>` (tool call). The training proceeds in two phases: first, behavior cloning fine-tunes the base model (Qwen2.5-7B) on ~10K synthetic trajectories generated by GPT-4.1 to learn the required action format. Second, MemPO employs Group Relative Policy Optimization (GRPO) with a novel token-level advantage scheme. For each rollout, a group of trajectories per query is generated, and a binary reward (1 for correct answer, else 0) is computed at the trajectory level. This yields a trajectory-level advantage \(A^T\) via group normalization. Additionally, for tokens belonging to `<mem>` segments, an extra step-level advantage \(A^M\) is derived from a memory reward: \(R^M = P(s_{ans} \mid s_{mem}^t) - \epsilon\), where \(s_{ans}\) is the ground-truth answer, \(s_{mem}^t\) is the memory summary at that step, and \(\epsilon\) approximates the bias from the prefix. The final advantage for a token i at step t is \(A_i = A^T + A^M\) if the token is within a `<mem>` segment, else \(A^T\). The policy is optimized with the clipped PPO objective plus a KL penalty to a reference model. During inference, only the latest memory summary is retained as context for the next step, discarding full history to bound token usage.

## Key Results
- Absolute F1 improvement of 25.98% over the base model and 7.1% over previous SOTA.
- Token consumption reduced by 67.58% (vs base) and 73.12% (vs SOTA).
- Validated on five long-horizon benchmarks: multi-objective QA, single-hop QA, and deep research tasks.

## Why This Works (Mechanism)
### Mechanism 1
- Claim: Self-memory actions compress interaction context by replacing full history with a generated summary.
- Mechanism: At each step t, the agent outputs a `<mem>` segment that condenses information from all prior steps s<t. This summary then serves as the sole historical context for the next step (along with immediate observations), bounding per-step token count.
- Core assumption: A learned summary can preserve sufficient information for future reasoning without retaining raw history.
- Evidence anchors:
  - [abstract]: "enables the agent (policy model) to autonomously summarize and manage their memory during interaction with environment."
  - [section 3.1]: "s_mem^t represents the model-generated summary of effective information from previous outputs s<t, which is enclosed by <mem> </mem>."
  - [corpus]: Neighboring papers (e.g., MemGPT, Mem0, A-MEM) rely on external, passive memory stores; MemPO internalizes memory generation as a policy action.
- Break condition: If summaries become too lossy (e.g., due to poor reward signals), critical details may be omitted, leading to performance degradation.

### Mechanism 2
- Claim: Step-level memory reward based on conditional probability directs the model to retain information that is predictive of the correct final answer.
- Mechanism: For each `<mem>` segment in a trajectory, compute \(R^M = P(s_{ans} \mid s_{mem}^t) - \epsilon\), where \(s_{ans}\) is the ground-truth answer string and \(\epsilon\) approximates \(P(s_{ans} \mid s_{<t})\). This reward is group-normalized into \(A^M\) and added to the trajectory advantage for memory tokens.
- Core assumption: Higher conditional probability of the correct answer given a memory summary indicates that the summary contains task-relevant information.
- Evidence anchors:
  - [abstract]: "assigns tokens a combined advantage: a trajectory-level score from final answer correctness, plus for memory tokens an extra step-level reward based on the conditional probability that the memory contains information needed to produce the correct answer."
  - [section 4.2]: Equations (4)-(5) formalize \(R^M\) using token-level probabilities from the policy model.
  - [corpus]: Prior RAG-based memory systems (e.g., A-MEM) retrieve based on embedding similarity, which may not correlate with task utility; MemPO’s reward directly measures utility via the answer distribution.
- Break condition: Noisy probability estimates early in training could misguide memory; also, \(\epsilon\) may not perfectly remove prefix bias.

### Mechanism 3
- Claim: Token-level advantage combination focuses policy updates on memory tokens, improving memory quality while maintaining reasoning capability.
- Mechanism: In the PPO objective, tokens within `<mem>` segments receive advantage \(A = A^T + A^M\), while all other tokens receive only the trajectory-level \(A^T\). This amplifies gradients for memory-generation decisions.
- Core assumption: Memory tokens are the primary control point for what information persists; augmenting their advantage yields better compression.
- Evidence anchors:
  - [section 4.3]: Equation (9) defines the final token-level advantage.
  - [section 4.4]: The optimization objective (10) uses this advantage in the clipped surrogate objective.
  - [experiments]: Ablation in Figure 3 (left) shows that adding \(A^M\) yields significant F1 gains over vanilla GRPO.
- Break condition: If \(A^M\) dominates \(A^T\), the policy might overoptimize memory at the expense of other actions (e.g., reasoning, tool use). KL regularization mitigates this.

## Foundational Learning
- Group Relative Policy Optimization (GRPO):
  - Why needed: MemPO builds on GRPO for its trajectory-level advantage \(A^T\), which avoids learning a value network and enables efficient group-based credit assignment.
  - Quick check: How does GRPO compute advantages for trajectories in a group? (Normalize group rewards by mean and std.)
- Conditional Probability Estimation:
  - Why needed: The memory reward \(R^M\) requires computing \(P(s_{ans} \mid s_{mem}^t)\) using the model’s own token probabilities.
  - Quick check: Given a context string and a target answer, how would you compute its probability under an autoregressive LLM? (Multiply token probabilities conditioned on preceding tokens.)
- Behavior Cloning Warm-start:
  - Why needed: The policy is first fine-tuned on synthetic trajectories (from GPT-4.1) to learn the required action format (`<mem>`, `<think>`, `尷`, `<answer>`) before RL training.
  - Quick check: Why not train with RL from scratch? Because RL may struggle to discover the required action structure without demonstration.

## Architecture Onboarding
**Component Map**: Agent policy -> Environment -> Reward computation -> GRPO optimizer -> Updated policy  
**Critical Path**:  
1. Behavior cloning: fine-tune base model on demonstration trajectories to learn action format.  
2. RL rollout: for each query, sample N=16 trajectories using current policy and environment interaction; collect memories and final answers.  
3. Reward assignment: compute binary reward for each trajectory; compute memory reward \(R^M\) for each `<mem>` token segment; group-normalize to get \(A^T\) and \(A^M\).  
4. Policy update: compute token-level advantages (\(A^T + A^M\) for memory tokens, else \(A^T\))); run PPO clip step with KL penalty.  
5. Inference: at test time, only the latest memory summary is retained as context for the next step, discarding full history.

**Design Tradeoffs**:  
- Self-memory vs external memory: Internalizing memory generation as a policy action avoids retrieval overhead but risks losing information if summaries are poor.  
- Token-level advantage: Boosting memory tokens improves memory quality but may cause overfitting if step-level reward is noisy.  
- Truncated context: Using only the last memory summary drastically reduces token usage but may omit long-range dependencies if summaries fail.

**Failure Signatures**:  
- High rate of invalid action formats (missing tags) after behavior cloning.  
- Low conditional probability scores for memory segments relative to prefix, indicating poor retention.  
- No improvement or degradation in F1 when \(A^M\) is added, suggesting reward mis-specification.  
- Token count not decreasing as expected, possibly due to not discarding full history during rollouts.

**First Experiments**:  
1. Verify behavior cloning success: Evaluate the BC model on a held-out set; ensure >95% of trajectories have valid `<mem>`/`<answer>` tags and non-empty memory content.  
2. Sanity-check reward computation: For a few trajectories, manually compute \(P(s_{ans} \mid s_{mem})\) and \(\epsilon\) using a fixed reference model; confirm \(R^M\) values are positive for useful memories and negative for useless ones.  
3. Run a minimal MemPO training run with a small batch (e.g., 8 queries, N=4 rollouts, 1 PPO epoch) and monitor whether F1 and token usage move in the right direction compared to a GRPO baseline without \(A^M\).

## Open Questions the Paper Calls Out
- **Open Question 1**: Does the bias from non-equivalent states in group-relative advantage calculation significantly affect memory quality, and can better normalization than the \(\epsilon\) term mitigate it? (Basis: Limitations mention states not completely equivalent; \(\epsilon\) is heuristic.)
- **Open Question 2**: Is conditional probability \(P[answer|memory]\) the optimal memory reward, or could alternatives like mutual information or usage-based rewards improve results? (Basis: Future work mentions optimizing memory reward design.)
- **Open Question 3**: Why does 1-step truncated context outperform full context on long-horizon tasks? Is it due to reduced attention dilution or forced memory efficacy? (Basis: Fig 3 shows 1-step best; paper cites attention dilution but doesn't test it.)
- **Open Question 4**: Does MemPO generalize beyond QA to other long-horizon tasks (e.g., coding, robotics) where correctness signals are less clear? (Basis: All benchmarks QA-based; future work mentions scalability without evidence.)

## Limitations
- Exact reward computation details ambiguous: unclear whether \(P(s_{ans}|s_{mem})\) and \(\epsilon\) use current policy \(\pi_\theta\), reference \(\pi_{ref}\), or a separate model; handling of multiple correct answers unspecified.
- Behavior cloning data generation specifics not provided: prompts, tool setup, and filtering criteria for the 10K trajectories are unavailable, risking distribution mismatch.
- Missing hyperparameters: KL coefficient \(\beta\), group aggregation details, and handling of rollouts exceeding step limit not documented, hindering precise replication.

## Confidence
- Overall performance claim: Medium (supported by experiments but lacks raw data and statistical tests).
- Mechanism 1 (self-memory summary compression): Medium (clear method but effectiveness depends on reward; no independent verification of information preservation).
- Mechanism 2 (step-level memory reward via conditional probability): Medium (novel but sensitive to probability estimation; implementation ambiguities).
- Mechanism 3 (token-level advantage boosting memory tokens): Medium-High (ablation shows benefit, but depends on correct advantage mixing).
