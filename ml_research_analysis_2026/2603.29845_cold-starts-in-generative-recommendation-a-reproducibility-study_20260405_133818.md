# Cold-Starts in Generative Recommendation: A Reproducibility Study
## Quick Facts
*   **arXiv ID**: 2603.29845
*   **Source URL**: https://arxiv.org/abs/2603.29845
*   **Reference Count**: 40
*   **Primary Result**: Item cold-start is substantially harder than user cold-start; textual identifiers boost item cold-start but harm warm-start performance, and scaling model size or applying RL fine-tuning does not reliably close the gap.

## Executive Summary
This reproducibility study systematically evaluates cold-start recommendation in generative models. By reproducing representative systems under unified protocols, the work isolates the effects of model scale, item identifier design, and training strategy. The central finding is that item cold-start presents a significantly greater challenge than user cold-start, with sharp performance drops. Increasing model parameters yields only marginal gains, failing to bridge the cold-start performance gap. The choice of item identifier is critical: textual titles improve item cold-start by leveraging pre-trained semantics but degrade performance for warm-start items and user cold-start. In contrast, learned semantic codes (e.g., from OPQ) offer a more balanced trade-off. Furthermore, reinforcement learning fine-tuning, intended to align generation with ranking metrics, does not consistently improve cold-start outcomes and can reduce robustness.

## Method Summary
The study replicates generative recommendation models (e.g., TIGER, P5, OneRec) and traditional baselines on Amazon-Toys, MicroLens, and Steam datasets. Data undergoes 5-core filtering. Cold-start splits are defined chronologically for items (train on first 90% of interactions, test on last 10%) and by user hold-out (10% of users excluded from training). Evaluation uses Recall@10 and NDCG@10 under warm, user cold-start, and item cold-start settings. For generative models, constrained decoding via a trie over the item identifier vocabulary ensures valid outputs. The experimental protocol isolates factors of interest: model scale (varying Flan-T5 size in TIGER), identifier design (atomic IDs, textual titles, semantic codes from RQ-VAE/OPQ), and training strategy (SFT vs. SFT+RL).

## Key Results
*   **Cold-start disparity**: Item cold-start performance is systematically and substantially lower than user cold-start across all models and datasets, with gaps often exceeding 20% in Recall@10.
*   **Identifier design trade-off**: Textual item identifiers (titles) markedly improve item cold-start but cause notable degradation in warm-start and user cold-start performance. Compositional semantic codes (e.g., OPQ) provide a more robust balance.
*   **Scaling and RL limitations**: Increasing generative model parameter count yields only marginal, monotonic improvements that do not close the cold-start gap. Reinforcement learning fine-tuning fails to consistently enhance cold-start metrics and can harm overall robustness.

## Why This Works (Mechanism)
### Mechanism 1: Textual Identifier Trade-off
*   **Claim**: Textual identifiers improve item cold-start performance by leveraging pre-trained semantic knowledge but degrade warm and user cold-start due to token ambiguity and reduced discriminability.
*   **Mechanism**: Pre-trained language models (PLMs) interpret textual item descriptors (e.g., titles) using their semantic understanding, providing inductive bias for unseen items. However, overlapping tokens and semantic similarity increase confusion during decoding for items with sufficient interaction history, ranking precision.
*   **Core Assumption**: The generation bottleneck shifts from semantic interpretation (for cold items) to contextual disambiguation (for warm items).
*   **Evidence Anchors**:
    *   [abstract] “Textual identifiers can substantially improve item cold-start but introduce clear trade-offs by harming warm and user cold-start performance.”
    *   [section 5.3] “Textual identifiers achieve the strongest performance under item cold-start… but substantially underperform in warm-test and user cold-start.”

### Mechanism 2: Limited Impact of Model Scaling
*   **Claim**: Scaling model size yields only marginal gains for cold-start because larger PLMs improve semantic representation but cannot overcome the fundamental distribution shift from missing interaction patterns.
*   **Mechanism**: Increased parameters enhance the model's ability to capture complex semantic relationships, offering slight improvements in modeling user preferences from limited context. However, item cold-start primarily suffers from the absence of collaborative signals (behavioral co-occurrence) that semantics alone cannot recover.
*   **Core Assumption**: The cold-start gap is mainly a data distribution problem (training vs. test item visibility) rather than a model capacity limitation.
*   **Evidence Anchors**:
    *   [abstract] “Scaling model size provides only marginal improvements and does not fundamentally close the cold-start gap.”
    *   [section 5.2] “Although performance increases monotonically with model size, the relative improvements under item cold-start settings are modest and the absolute performance gap… remains substantial.”

### Mechanism 3: Reinforcement Learning Reward Misalignment
*   **Claim**: Reinforcement learning does not reliably improve cold-start performance because reward functions built from training distribution patterns fail to generalize under distribution shift.
*   **Mechanism**: RL fine-tuning optimizes generation for downstream metrics using rewards derived from in-distribution data. This encourages exploitation of frequent identifier patterns. Under cold-start, where target items/users deviate from the training distribution, these reward signals become misaligned, destabilizing generation for unseen identifiers or sparse contexts.
*   **Core Assumption**: RL reward design implicitly assumes test-time availability of similar behavioral patterns as in training, which breaks for cold-start entities.
*   **Evidence Anchors**:
    *   [abstract] “Reinforcement learning does not reliably improve cold-start performance and can even reduce robustness.”
    *   [section 5.4] “Adding an RL stage… does not consistently improve… can even slightly degrade performance… RL optimization is driven by reward signals constructed from the training distribution.”

## Architecture Onboarding
*   **Component Map**: User history sequence -> Backbone PLM (e.g., T5) -> Identifier module -> Generated token sequence -> Constrained decoding (trie) -> Ranked item list
*   **Critical Path**: Process user interaction history with PLM to generate an item identifier token sequence. Use a trie over the full item identifier vocabulary to constrain decoding to valid items, then rank candidates by generation probability.
*   **Design Tradeoffs**:
    *   Identifier type: Textual -> strong item cold-start but weak warm-start; Semantic codes -> balanced but sensitive to quantization; Atomic -> fails for cold items.
    *   Training: Supervised Fine-Tuning (SFT) -> stable but metric-agnostic; Reinforcement Learning (RL) -> metric-aligned but risky under distribution shift.
*   **Failure Signatures**:
    *   Item cold-start Recall@10 near 0 for atomic/semantic-code models.
    *   Warm-start performance drop when switching to textual identifiers.
    *   RL fine-tuning decreasing both warm and cold metrics.

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question**: What theoretical mechanisms explain how identifier design (e.g., quantization structure, token factorization) influences cold-start performance?
*   **Basis in paper**: [explicit] Future work: investigate "the theoretical mechanisms behind identifier design, particularly focusing on how aspects like quantization structure and token factorization impact the models’ cold-start performance." Limitations note lack of theoretical analysis.
*   **Why unresolved**: The study offers empirical evidence but lacks a theoretical foundation. Principled identifier design remains guided by trial and error.
*   **What evidence would resolve it**: A formal analysis linking identifier properties to generalization bounds under distribution shift, with empirical validation across datasets and architectures.

### Open Question 2
*   **Question**: Can cold-start-aware training objectives (e.g., diversity-driven rewards, exploration mechanisms) improve cold-start performance without sacrificing warm-start robustness?
*   **Basis in paper**: [explicit] Future work: "investigate whether incorporating cold-start-aware objectives, such as diversity-driven rewards or exploration mechanisms for unseen items, can overcome the current limitations and allow generative recommenders to generalize more effectively without sacrificing overall robustness."
*   **Why unresolved**: Standard RL often fails, suggesting reward misalignment. It is unknown if objectives explicitly targeting cold-start scenarios can yield consistent gains.
*   **What evidence would resolve it**: Experiments integrating such objectives (e.g., rewarding coverage of cold items) demonstrating significant cold-start improvements while preserving warm-start quality.

### Open Question 3
*   **Question**: How do multimodal item features and dynamic item pools (continuous addition of new items) affect cold-start generalization in generative recommendation?
*   **Basis in paper**: [inferred] Limitations: "our analysis does not fully capture the complexity of real-world recommendation scenarios, which often involve richer modalities, dynamic item pools, and evolving user preferences." The study used only textual identifiers and static splits.
*   **Why unresolved**: Real-world systems often use images/audio and face continuous item influx. The observed trade-offs may not hold with multimodal cues or streaming addition.
*   **What evidence would resolve it**: Systematic evaluation on datasets with multimodal features and simulations of dynamic item addition, measuring identifier and strategy performance under these conditions.

## Limitations
*   Unknown random seeds for data splits and model initialization cause variability in cold-set definitions and absolute performance values.
*   Precise hyperparameters for each model on each dataset are not provided; reliance on defaults risks configuration drift from the original results.
*   Official implementations may differ in library versions or preprocessing, affecting full reproducibility.

## Confidence
*   **Item cold-start harder than user cold-start**: High (robust across all datasets and models).
*   **Scaling model size offers marginal gains**: High (TIGER experiments show monotonic but small relative improvements).
*   **Identifier design trade-offs**: High (textual identifiers boost item cold-start but harm warm/user cold-start; OPQ codes balance).
*   **RL fine-tuning unreliability**: Medium (some runs degrade performance; confidence limited by narrow reward designs tested).
