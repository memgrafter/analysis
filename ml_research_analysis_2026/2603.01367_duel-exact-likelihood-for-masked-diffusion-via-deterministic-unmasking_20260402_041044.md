# DUEL: Exact Likelihood for Masked Diffusion via Deterministic Unmasking

## Quick Facts
- **arXiv ID**: 2603.01367
- **Source URL**: https://arxiv.org/abs/2603.01367
- **Reference count**: 40
- **Primary result**: DUEL enables exact likelihood computation for masked diffusion models under deterministic unmasking, yielding proper perplexity and closing up to 82% of the gap with autoregressive models.

## Executive Summary

Masked diffusion models (MDMs) lack proper likelihood evaluation: the standard evidence lower bound (ELBO) is both loose and computed under the training distribution, not the test-time distribution. This yields misleading perplexity estimates, especially when comparing to autoregressive models. DUEL resolves these issues by formalizing deterministic unmasking policies and proving that, for such policies, the exact likelihood collapses from an intractable sum over all ordered partitions to a single deterministic generation trajectory. As a result, MDMs can be evaluated with true perplexity for the first time. Empirically, proper evaluation narrows the gap between MDMs and autoregressive models substantially: on in-domain data (OpenWebText) the gap shrinks by 21–32%, and on zero-shot benchmarks the reduction reaches 82%. Even more strikingly, oracle unmasking orderings found by exhaustive search achieve lower perplexity than autoregressive models (e.g., 36.47 vs. 52.11 on AG News), highlighting the latent potential of order selection.

## Method Summary

The task is to compute the exact log-likelihood of a ground-truth sequence under a pretrained masked diffusion model (MDM) that employs a deterministic test-time unmasking rule \(F\). The inputs are: a trained denoiser \(x_\theta\) (e.g., a DiT) that maps a partially masked sequence to token logits, an evaluation dataset, and a deterministic policy \(F\) that selects which masked positions to reveal at each step based solely on the current state. The core method is Algorithm 2 (DUEL likelihood estimator). Starting from a fully masked sequence, at each step it computes the token probability distribution \(P = \text{softmax}(x_\theta(z))\), determines the set of positions \(I = F(z)\), and for each \(\ell \in I\) adds the log-probability \(\log P_\ell[x_\ell]\) of the true token to an accumulator. All selected tokens are then revealed in \(z\). The sequence of states exactly mirrors the unique path taken by the generator (Algorithm 1) when run with the same \(F\). The accumulated sum equals the exact log-likelihood \(\log p_{\pi_F\theta}(x)\). Hence, the intractable sum over all possible ordered partitions collapses to a single deterministic trajectory, computable in linear time with respect to the number of unmasking steps. Training of the MDM still uses the standard ELBO loss, but evaluation now reflects the actual test-time distribution induced by \(F\).

## Key Results

- For any deterministic unmasking policy, exact likelihood computation reduces to following a single generation trajectory, avoiding the exponential sum over ordered partitions.
- Proper perplexity evaluation under DUEL closes up to 32% of the gap with autoregressive models on in-domain data (OpenWebText) and up to 82% on zero-shot benchmarks.
- Oracle unmasking orderings found by exhaustive permutation search achieve lower perplexity than autoregressive models (e.g., 36.47 vs. 52.11 on AG News), demonstrating the latent potential of order selection.

## Why This Works (Mechanism)

### Mechanism 1
**Claim**: For deterministic unmasking policies, exact likelihood computation collapses from a super-exponential sum over all ordered partitions to evaluating a single deterministic trajectory.  
**Mechanism**: A deterministic rule \(F(z)\) maps any partially masked sequence \(z\) to a fixed set of positions to unmask. When computing \(p_{\pi_F\theta}(x)\) for a ground-truth sequence \(x\), only the ordered partition \(\sigma^*\) that matches “\(F\) applied to each intermediate revealed state” has nonzero probability under \(\pi_F\theta\). All other \(\sigma\) satisfy \(\pi_F\theta(\sigma_t \mid x_{\sigma_{<t}}) = 0\) at some step because \(\sigma_t \neq F(x_{\sigma_{<t}})\). The likelihood sum reduces to \(p_{\pi_F\theta}(x, \sigma^*) = \prod_t \prod_{\ell \in \sigma^*_t} p_\theta(x^{(\ell)} \mid x_{\sigma^*_{<t}})\).  
**Core assumption**: The unmasking policy is deterministic (\(\pi_F\theta\) is Dirac-delta on \(F(z)\)).  
**Evidence anchors**:
- [abstract] “exact likelihood computation collapses to a single generation trajectory.”
- [section 4.2] Theorem 4.3: “Algorithm 2 computes \(\log p_{\pi_F\theta}(x)\) exactly.”
- [corpus] Related works explicitly unify “leading MDM sampling strategies that employ deterministic position selection.”
**Break condition**: Fails for stochastic unmasking policies (e.g., uniform random selection) where multiple orderings have nonzero probability and summing remains intractable.

### Mechanism 2
**Claim**: DUEL likelihood computation (Algorithm 2) follows the exact same path as generation (Algorithm 1), but replaces token sampling with log-probability accumulation.  
**Mechanism**: Both algorithms iterate: (1) compute \(P = \text{softmax}(x_\theta(z))\), (2) select \(I = F(z)\). Generation samples \(x_\ell \sim \text{Cat}(P_\ell)\) and reveals; DUEL instead accumulates \(\sum_{\ell \in I} \log P_\ell[x_\ell]\) then reveals. The revealed tokens \(x_{\sigma_{<t}}\) become identical at each step because DUEL uses ground-truth tokens, causing the selection \(F(z)\) to match the generation trajectory exactly.  
**Core assumption**: Ground-truth tokens \(x\) are provided during evaluation; \(F\) depends only on the denoiser’s predictions \(P\) (deterministic function of \(z\)); absorbing forward process (once unmasked, positions stay revealed).  
**Evidence anchors**:
- [abstract] “exact likelihood under the test-time distribution.”
- [section 4.2] “Algorithm 2 implements this procedure” with Figure 3 highlighting differences.
- [corpus] Related works (oracle search in Section 6.2.2) rely on this property to enumerate orderings.
**Break condition**: Requires access to ground-truth tokens (cannot be used during generation). Does not support remasking (Wang et al., 2025a) where tokens can be re-masked, as the predictable trajectory property breaks.

### Mechanism 3
**Claim**: DUEL provides proper perplexity—the natural analogue of autoregressive perplexity—by evaluating the test-time distribution \(p_{\pi_F\theta}\), not the training distribution \(p_{\pi_{\text{unif}}\theta}\) that the ELBO bounds.  
**Mechanism**: The ELBO computes \(\mathbb{E}_{\pi_{\text{unif}}}[-\sum \log p_\theta(\text{token} \mid \text{context})]\), averaging over uniform random orderings. This both (a) underestimates likelihood due to variational gap and (b) measures the wrong distribution because test-time uses deterministic \(F\), not uniform random selection. DUEL computes exact \(p_{\pi_F\theta}\), making it sensitive to both denoiser quality and unmasking policy.  
**Core assumption**: Test-time deployment uses deterministic unmasking policies (\(F\)), which is standard for high-performing MDMs (greedy confidence, margin, etc.).  
**Evidence anchors**:
- [abstract] “MDMs are substantially better than previously thought: the MDM‑autoregressive perplexity gap shrinks.”
- [section 5] “The ELBO … is also computed under the training distribution rather than the test-time distribution.”
- [section 6.1] Tables 2‑4 show DUEL closes 21‑82% of the gap; Table 5 shows DUEL reduces LLaDA perplexity from ELBO bound.
**Break condition**: If test-time uses stochastic policies (e.g., sampling from masked positions uniformly), then the relevant distribution is \(p_{\pi_{\text{unif}}\theta}\) and ELBO may be appropriate (though still loose). DUEL’s “properness” assumes deterministic \(F\) matches deployment.

## Foundational Learning

- **Concept**: Masked diffusion forward/reverse processes  
  Why needed here: DUEL builds on the MDM framework where a clean sequence \(x\) is noised to fully masked \(z_T\) via an absorbing Markov chain, then generation reverses this process with a learned denoiser.  
  Quick check question: What is the key property of the absorbing forward process that simplifies training and enables the AO‑ARM interpretation?

- **Concept**: Any‑order autoregressive (AO‑ARM) interpretation  
  Why needed here: DUEL formalizes MDMs as AO‑ARMs where generation decomposes into position selection (policy \(\pi$) and token prediction (denoiser $p_\theta$). This separation is essential to define the induced distribution $p_{\pi\theta}$ and prove exact likelihood for deterministic $\pi$.  
  Quick check question: How does the AO‑ARM perspective differ from the standard latent‑variable diffusion view, and why does it enable exact likelihood?

- **Concept**: Ordered partitions vs. permutations  
  Why needed here: MDMs unmask sets of positions in parallel, which is naturally described by an ordered partition (a sequence of subsets that partition the set of positions) rather than a permutation. This distinction is crucial because deterministic unmasking policies collapse the likelihood sum over all ordered partitions to a single one, making exact computation feasible.  
  Quick check question: What is the computational consequence of moving from permutations (sequential) to ordered partitions (parallel) for likelihood computation?

## Architecture Onboarding

Component map:
Denoiser xθ → Unmasking rule F → Policy πFθ → (Sampler, Likelihood estimator)

Critical path:
1. Train an MDM using standard ELBO loss with uniform random timesteps and, implicitly, uniform random position selection.
2. At test time, choose a deterministic unmasking rule F (e.g., greedy confidence).
3. To evaluate exact likelihood of a sequence x under (xθ, F): run Algorithm 2, which simulates generation but substitutes xℓ for samples. The log‑likelihood is the sum of accumulated log‑probabilities.
4. For generation: run Algorithm 1, which samples tokens according to Pℓ. The distribution induced is exactly pπFθ(x) whose log‑prob Algorithm 2 computes.

Design tradeoffs:
- **NFE vs. quality**: Fewer function evaluations increase parallelism but may hurt quality as each step selects tokens with less context.
- **Rule selection**: Different F yield different distributions; DUEL allows direct comparison (e.g., greedy confidence, probability margin, confidence threshold).
- **Block size (L′)**: For block‑diffusion models, F operates within blocks; smaller blocks restrict policy flexibility, larger blocks increase oracular potential.
- **Deterministic vs. stochastic test policy**: DUEL only applies for deterministic F; stochastic test policies would require summing over orderings.

Failure signatures:
- **Remasking not supported**: Strategies that allow re‑masking previously unmasked tokens break the unique‑trajectory property; DUEL does not directly apply.
- **Non‑deterministic F at test**: If F includes randomness, likelihood is a sum over orderings; DUEL cannot compute it exactly.
- **Order‑sensitive denoiser assumption**: If the denoiser is globally order‑insensitive, all policies induce the same distribution; DUEL still works but yields no insights from policy variation.
- **Reference model contamination**: Generative perplexity (samples scored by GPT‑2) can diverge from true likelihood rankings, especially at low NFE.

First 3 experiments:
1. **Baseline replication**: Train a small MDM (e.g., 110M DiT) on OpenWebText. Compute ELBO (Monte Carlo) and DUEL perplexity (greedy confidence). Verify DUEL is lower than ELBO, and both are higher than an ARM baseline. Confirm the “gap closed” metric behaves as described.
2. **Sampler comparison sweep**: For a trained model, vary NFE ∈ {128, 256, 512, 1024} and evaluate 4 deterministic rules (left‑to‑right, greedy, margin, threshold) with DUEL perplexity. Expect consistent ranking (probability margin best at low NFE) and convergence at high NFE. Contrast with generative perplexity to see ranking crosses.
3. **Oracle search**: Take a block‑diffusion model (L′ = 4). For a validation batch, exhaustively search all 4! = 24 block permutations per block. Expect oracle perplexity far below ARM (e.g., 36 vs. 52 on AG News). This demonstrates latent potential in order selection.

## Open Questions the Paper Calls Out

### Open Question 1
Can DUEL's exact likelihood computation be extended to remasking diffusion models, where tokens can be re‑masked during generation?  
**Basis in paper**: The conclusion lists “extending to remasking paradigms” as a key future direction, noting that remasking enables iterative refinement absent in standard MDMs.  
**Why unresolved**: Remasking breaks the deterministic trajectory assumption underlying DUEL's single‑path likelihood computation; the framework currently requires that once a token is revealed, it stays revealed.  
**What evidence would resolve it**: A theoretical extension showing how to compute exact likelihood when the unmasking policy can re‑mask positions, perhaps by considering cyclic or multi‑visit trajectories, or empirical validation on remasking models like those in Wang et al. (2025a) or Huang et al. (2025).

### Open Question 2
How can we learn unmasking orderings at test time that approach oracle perplexity without access to ground‑truth tokens?  
**Basis in paper**: The oracle search section states: “developing strategies that approach its performance without such access is a promising direction; recent work on lookahead unmasking (Lee et al., 2025) takes initial steps.”  
**Why unresolved**: Oracle perplexity uses ground‑truth tokens to select the optimal ordering per sequence, which is unavailable at test time. Current learned policies (e.g., Jazbec et al., 2025) train a policy network, but it's unclear how closely they can approach the oracle.  
**What evidence would resolve it**: Benchmarking test‑time search methods (e.g., beam search over orderings, learned policies) against the oracle on diverse datasets to measure the achievable gap.

### Open Question 3
Are state‑of‑the‑art MDMs order‑sensitive in practice, and how does this property affect the equivalence of different unmasking policies?  
**Basis in paper**: Theorem 4.2's proof assumes order‑sensitivity to show policy‑dependent distributions. Remark C.7 notes that if networks were order‑insensitive, all policies would induce the same distribution. However, the paper does not empirically verify order‑sensitivity.  
**Why unresolved**: The entire DUEL framework relies on the fact that different policies yield different distributions. If MDMs were order‑insensitive, then choices like greedy confidence vs. probability margin would not affect likelihood, contradicting empirical results (Table 6)—but those results could be due to other factors. Direct tests of order‑sensitivity are absent.  
**What evidence would resolve it**: Controlled experiments where we isolate the effect of generation order on token predictions, e.g., by fixing some positions and measuring prediction changes under different masking orders, across model architectures and training regimes.

### Open Question 4
Does DUEL's exact likelihood enable improved model selection or architecture design in scientific domains like protein design, where likelihood is a primary evaluation metric?  
**Basis in paper**: The conclusion and impact statement explicitly list “applying to scientific domains (protein design, molecular generation) where likelihood‑based evaluation is essential” as future work.  
**Why unresolved**: The paper only evaluates DUEL on language modeling benchmarks. Scientific domains often have different characteristics (e.g., discrete structured outputs, physical constraints) and may use different MDM variants (e.g., for graphs or sequences). It's unknown whether the same perplexity improvements and insights transfer.  
**What evidence would resolve it**: Applying DUEL to existing diffusion models for proteins or molecules, comparing ELBO vs. DUEL perplexity, and checking if the gap closed patterns resemble those in language tasks. Also, using DUEL to guide architecture choices (e.g., block size) in these domains.

### Open Question 5
What factors determine the magnitude of the perplexity gap reduction achieved by DUEL across different datasets and model architectures?  
**Basis in paper**: Tables 2–5 show varying gap closed percentages (e.g., 21–32% on OWT, 12–31% on LM1B, up to 82% on zero‑shot). The paper does not analyze why the gap differs so much.  
**Why unresolved**: Understanding this could help predict when DUEL will have the biggest impact and whether certain model designs (e.g., block diffusion) inherently benefit more. It may relate to dataset properties (e.g., domain similarity, sequence length) or model order-sensitivity.  
**What evidence would resolve it**: Correlational analysis between gap closed and metadata (dataset size, domain, sequence length) or model characteristics (architecture, training objective). Ablation studies varying model order‑sensitivity or data distribution to see effect on gap closed.

## Limitations

- DUEL does not support stochastic or remasking unmasking policies; it is restricted to deterministic policies with the absorbing forward process.
- The method assumes an order‑sensitive denoiser; if the denoiser is globally order‑insensitive, policy choice becomes irrelevant and the exact likelihood loses discriminative power.
- Implementation details such as tie‑breaking for deterministic rules and handling of sequence lengths not divisible by block size are underspecified, potentially affecting reproducibility.
