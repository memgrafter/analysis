# HELM: Hierarchical and Explicit Label Modeling with Graph Learning for Multi-Label Image Classification

## Quick Facts
- **arXiv ID:** 2603.11783  
- **Source URL:** https://arxiv.org/abs/2603.11783  
- **Reference count:** 40  
- **Primary result:** HELM achieves state-of-the-art AUPRC (0.904 on UCM) and improves AUPRC by up to 37% under 1% labeled data in semi-supervised settings.

## Executive Summary
HELM introduces a novel framework for hierarchical multi-label image classification in remote sensing, addressing two critical challenges: the prevalence of multi-path label hierarchies (where an image can belong to multiple non-overlapping branches) and the underutilization of abundant unlabeled data. The method integrates three key innovations: hierarchy-specific class tokens within a Vision Transformer to capture fine-grained label interactions; a graph convolutional branch that explicitly encodes the label hierarchy via GraphSAGE; and a self-supervised BYOL branch that leverages unlabeled imagery. Evaluated on four remote sensing datasets (UCM, AID, DFC-15, MLRSNet), HELM consistently outperforms prior art in both fully-supervised and semi-supervised regimes, especially when labeled data is extremely scarce. It sets new records, including AUPRC of 0.904 on UCM and ranking loss as low as 0.006 on DFC-15, while demonstrating up to 37% AUPRC improvement over baselines with only 1% labeled data.

## Method Summary
HELM builds upon a ViT-B/16 backbone pretrained on ImageNet. The core modification is the addition of one learnable class token for every label in the hierarchy (total M tokens); these are concatenated with the standard patch tokens and processed by the transformer. After encoding, the M class token embeddings are fed into three parallel branches. The **classification branch** averages the tokens and passes them through a fully connected layer to produce binary predictions (sigmoid), trained with binary cross-entropy on labeled data. The **graph branch** interprets the class token embeddings as node features on a directed graph representing the label hierarchy (edges = parent-child relations). A two-layer GraphSAGE performs message passing on this graph, and the resulting node embeddings are pooled and classified, also with binary cross-entropy (on labeled data). The **self-supervised BYOL branch** processes each image (labeled or unlabeled) to generate two augmented views; an online network (shared ViT + MLP predictor) predicts the target network’s representation (EMA of online network), with a cosine similarity loss applied to all images. The total loss is a weighted sum of the three branch losses. Training uses AdamW with a cosine learning rate schedule; weak augmentations (flips, blur) are applied for supervised branches, while stronger augmentations (color jitter, cropping, random erasing) are used for BYOL. Mixed precision and multiple GPUs accelerate training.

## Key Results
- State-of-the-art AUPRC on UCM dataset: 0.904 (supervised) and ranking loss as low as 0.006 on DFC-15.
- In semi-supervised learning with only 1% labeled data, HELM improves AUPRC by up to 37% compared to baseline methods.
- Consistently superior performance across four remote sensing datasets, demonstrating effectiveness in both fully-supervised and low-label regimes.

## Why This Works (Mechanism)
### Mechanism 1: Hierarchy-specific class tokens
**Claim:** Hierarchy-specific class tokens enable explicit modeling of fine-grained label interactions and dependencies within a multi-path hierarchy.  
**Mechanism:** The ViT encoder is modified to include one learnable token per label (leaf and intermediate). These tokens are concatenated with image patch tokens and processed through self-attention, allowing each label token to gather relevant visual evidence and interact with other label tokens. The final embeddings from these tokens are used for classification.  
**Core assumption:** Separate tokens for each label allow the model to maintain distinct representations specialized for their semantic concepts while still participating in joint attention to capture cross-label relationships, even for labels in multiple non-overlapping branches.  
**Evidence anchors:** ([abstract] "uses hierarchy-specific class tokens within a Vision Transformer to capture nuanced label interactions"; [section] Page 2, §2.2: "These tokens serve a dual purpose...")  
**Break condition:** Extremely large hierarchies (thousands of labels) may cause computational bottlenecks; sparse or non-hierarchical relationships may render extra parameters ineffective.

### Mechanism 2: Graph Convolutional Networks for hierarchical encoding
**Claim:** Graph Convolutional Networks (GCNs) explicitly encode the hierarchical structure by propagating information along parent‑child relationships, enriching label embeddings with structural context.  
**Mechanism:** A directed graph is constructed from the label hierarchy (nodes = labels, edges = parent‑child links). The hierarchy‑specific token embeddings from the ViT serve as initial node features. A GraphSAGE layer performs message passing over this graph, allowing each label’s representation to aggregate information from its parents and children. This generates hierarchy‑aware embeddings that are then used for prediction.  
**Core assumption:** The hierarchical dependencies (e.g., if an image contains a child label it likely also contains its parent) can be effectively captured by graph‑based message passing, and these dependencies improve prediction consistency and accuracy, especially for rare or ambiguous labels.  
**Evidence anchors:** ([abstract] "employs graph convolutional networks to explicitly encode the hierarchical structure and generate hierarchy‑aware embeddings"; [section] Page 2, §2.4: "A GraphSAGE operator ϕ(·) is applied to propagate information and generate structure‑aware embeddings: ˜zg = ϕ(˜zCLS; G)")  
**Break condition:** If the hierarchy is poorly defined (incorrect parent‑child links) or the graph is extremely dense/cyclic (violating the DAG assumption), message passing may propagate noisy signals; very deep hierarchies risk over‑smoothing.

### Mechanism 3: Self-supervised BYOL for leveraging unlabeled data
**Claim:** Self-supervised BYOL learning on unlabeled data improves representation robustness and generalization, particularly under extreme label scarcity.  
**Mechanism:** For each image (labeled or unlabeled), two augmented views are created. An online network (sharing the ViT encoder) predicts the latent representation of one view from the other. A target network (with weights as an exponential moving average of the online network) provides a stable target. This encourages the encoder to learn invariant representations across augmentations, which are then used for the downstream HMLC task.  
**Core assumption:** Representations learned via instance discrimination (without labels) are transferable to the HMLC task and help the model learn more general visual features, reducing overfitting when labeled data is limited.  
**Evidence anchors:** ([abstract] "integrates a self-supervised branch to effectively leverage unlabeled imagery"; [section] Page 2, §2.5: Loss equation (3) defines BYOL objective; Page 3, Figure 2 and Table 5 show large AUPRC gains at 1–5% labeled data)  
**Break condition:** If unlabeled data is from a substantially different distribution than labeled data (domain shift), self‑supervised features may not transfer well; BYOL can be sensitive to augmentation design.

## Architecture Onboarding
**Component map:**  
Input image → ViT encoder (with M hierarchy‑specific CLS tokens + Np patch tokens) → three branches: (1) Classification: average‑pooled CLS tokens → FC → predictions; (2) Graph: CLS tokens as node features → GraphSAGE over label graph → pooled → predictions; (3) BYOL: two augmented views → online/target networks (shared ViT + MLP predictor/projector) → cosine similarity loss. Total loss: L = Ls + Lg + Lb.

**Critical path:** Data begins with image patchification and concatenation of M learnable class tokens. The ViT processes the combined sequence. The final [CLS] token embeddings are split: one copy goes to the classification head, another to the graph branch (which constructs the batch’s label graph and applies GraphSAGE), and the full encoder serves the BYOL branch. The three losses (Ls for classification, Lg for graph, Lb for BYOL) are summed and backpropagated jointly.

**Design tradeoffs:**
- Multiple tokens vs. single token: Adding M tokens increases parameters and memory but enables explicit per‑label modeling; the graph branch adds only ~107K parameters, while BYOL roughly doubles encoder cost.
- GraphSAGE depth: Two layers balance non‑linearity and over‑smoothing; deeper risks losing label‑specific distinctions.
- BYOL augmentations: Weak augmentations (flips, blur) for supervised branches to preserve label semantics; strong augmentations (color jitter, cropping, erasing) for BYOL to learn invariances, preventing label corruption.

**Failure signatures:**
- Poor performance on multi‑path hierarchies (e.g., images with labels from distant branches) suggests the graph or token mechanisms fail to capture long‑range dependencies.
- Large gap between supervised and semi‑supervised results indicates BYOL or graph branch not effectively using unlabeled data.
- High training loss but low test performance may indicate overfitting due to insufficient unlabeled data or poor augmentations.
- UMAP visualizations showing poorly separated clusters at higher hierarchy levels indicate weak hierarchical reasoning.

**First 3 experiments:**
1. Ablation study: Train HELM variants (`HELM_g`, `HELM_b`, full `HELM`) on UCM with 10% labeled data; compare AUPRC and ranking loss to confirm each branch’s contribution (as in Table 1 and Table 5).
2. Token count sensitivity: Replace hierarchy‑specific tokens with a single CLS token (HMLC baseline) and run supervised training. Measure performance drop to validate the necessity of multiple tokens.
3. Graph structure ablation: Replace the GCN with a simple linear projection of CLS tokens (no message passing). Evaluate on multi‑path heavy dataset (MLRSNet) to see if hierarchical dependencies are actually being modeled.

## Open Questions the Paper Calls Out
1. **Automatic hierarchy discovery**  
   **Basis:** Future work explicitly states the need to remove manual construction (reliance on CORINE and ChatGPT).  
   **Why unresolved:** Current framework requires predefined hierarchies, a bottleneck for scaling to new domains.  
   **What evidence would resolve it:** Demonstrate that automatically induced hierarchies (e.g., from label co‑occurrence or feature similarities) can be integrated into HELM’s graph branch without degrading performance compared to manual CORINE‑based hierarchies.

2. **Improved high‑level hierarchical coherence**  
   **Basis:** Limitations note that sibling labels under the same parent (e.g., ‘sand’ and ‘water’ under ‘Water Bodies’) sometimes fail to reflect shared grouping, as seen in UMAP (Figure 5).  
   **Why unresolved:** Hierarchy‑specific tokens and GraphSAGE may prioritize local parent‑child relationships over global sibling coherence, limiting hierarchical reasoning to fine‑grained levels.  
   **What evidence would resolve it:** Quantitative clustering metrics or visualizations showing more coherent groupings at intermediate hierarchy levels after modifications to the graph propagation or token interaction.

3. **Alternative self‑supervised objectives for computational efficiency**  
   **Basis:** Appendix states BYOL introduces significant computational overhead and does not compare to other SSL methods.  
   **Why unresolved:** The BYOL choice is presented as a component but not validated as optimal; other SSL strategies might offer similar benefits with lower cost.  
   **What evidence would resolve it:** Experimental comparison of HELM’s BYOL branch against other leading SSL approaches (e.g., SimCLR, MAE, DINO) within the same framework, measuring the trade‑off between performance and computational cost across different labeled proportions.

4. **Robustness of LLM‑assisted hierarchy construction**  
   **Basis:** Appendix details ChatGPT‑assisted mapping followed by manual validation as key to creating hierarchical label structures.  
   **Why unresolved:** No independent evaluation of LLM‑generated hierarchy quality or sensitivity to errors/biases; success may be tied to the specific remote sensing domain and CORINE taxonomy.  
   **What evidence would resolve it:** Study the impact of perturbed or fully automatic LLM‑generated hierarchies on HELM’s performance, or apply the same pipeline to a completely different hierarchical multi‑label domain (e.g., medical imaging with disease taxonomies).

5. **Relative contribution of BYOL vs. graph branch in semi‑supervised gains**  
   **Basis:** Ablation shows both `HELM_g` (graph only) and `HELM_b` (BYOL only) improve over the baseline; synergy is clear but the relative contribution, especially under extreme label scarcity (1%), is not disentangled.  
   **Why unresolved:** The graph branch loss is computed only on labeled samples, so its direct SSL signal is limited. BYOL provides the main SSL benefit, but the graph might structurally organize representations learned from unlabeled data, a less‑quantified factor.  
   **What evidence would resolve it:** Controlled experiment freezing one branch after pre‑training or training with labeled‑only vs. unlabeled data through the other branch to isolate their complementary roles.

## Limitations
- **Scalability:** Memory usage grows linearly with the number of labels, making it potentially expensive for large label sets (>100).
- **Reproducibility:** Exact hyperparameters for BYOL (MLP dimensions, EMA decay, augmentations), GraphSAGE configuration, and CLS token initialization are not fully specified, hindering exact replication.
- **Robustness:** The method is sensitive to errors in the manually constructed hierarchy (e.g., incorrect parent‑child links, cycles) and relies on ImageNet‑pretrained ViT, which may limit cross‑domain generalization.
