# Did You Check the Right Pocket? Cost-Sensitive Store Routing for Memory-Augmented Agents
## Quick Facts
- arXiv ID: 2603.15658
- Source URL: https://arxiv.org/abs/2603.15658
- Reference count: 6
- Primary result: An oracle router reduces context tokens by 62% (299 vs 787) and increases QA accuracy from 81.3% to 86.7% on GPT-4o-mini compared to uniform retrieval.

## Executive Summary
Memory-augmented agents typically retrieve from all memory stores uniformly, incurring high token costs and suffering accuracy degradation from irrelevant context. This work recasts memory retrieval as a store-routing problem, where a router selects a subset of stores to query. An oracle router, choosing only the correct stores, achieves both higher QA accuracy and substantially fewer tokens than uniform retrieval. A fixed heuristic policy (STM+Summary+LTM) also performs strongly. However, a hybrid heuristic router, while achieving high synthetic coverage (94%), underperforms on end-to-end QA (70.7% accuracy), revealing a gap between routing decisions and answer extraction. The paper formalizes store selection as a cost-sensitive optimization, explicitly trading expected accuracy against retrieval cost, and introduces metrics (coverage, exact match, waste) to quantify the accuracy–efficiency trade-off.

## Method Summary
The paper evaluates store-routing policies on two evaluation fronts: synthetic queries with ground-truth store labels derived from LoCoMo/LongMemEval taxonomies (1,000 queries, 70/30 train/test), and a real QA dataset (150 questions) spanning the same query types. Memory is partitioned into four stores: STM, Summary, LTM, and Episodic. Baselines include uniform retrieval (all stores), an oracle (perfect routing via taxonomy mapping), fixed subsets (e.g., STM+Sum+LTM), and a hybrid heuristic combining rule-based triggers with embedding-similarity fallback. For end-to-end QA, full store contents are concatenated as context for GPT-3.5-turbo and GPT-4o-mini; accuracy is measured via substring match and token counts via `tiktoken`. The routing problem is formalized as π*(q) = argmax_G E[Acc(q,G)] − λ Σ_{s∈G} c_s, where c_s is a store-specific cost (STM=1, Sum=1, LTM=3, Epi=5) and λ controls the accuracy–cost trade-off.

## Key Results
- Oracle routing yields 86.7% QA accuracy vs 81.3% for uniform retrieval, using 62% fewer tokens (299 vs 787) on GPT-4o-mini in the long-context regime.
- A fixed STM+Sum+LTM policy achieves 84.7% accuracy, competitive with the oracle.
- The hybrid heuristic attains 94% synthetic coverage but only 70.7% end-to-end QA accuracy, indicating a 23.3-point gap due to extraction errors and over-retrieval noise.

## Why This Works (Mechanism)
### Mechanism 1
- Claim: Selecting only relevant memory stores improves QA accuracy and reduces token cost by eliminating distracting context.
- Mechanism: A router inspects the query and chooses a subset of stores; retrieval is restricted to those stores, reducing irrelevant tokens that can mislead the LLM.
- Core assumption: Irrelevant tokens from unnecessary stores impair the LLM’s ability to identify the correct answer, especially in long contexts.
- Evidence anchors:
  - [abstract]: "oracle router achieves higher accuracy while using substantially fewer context tokens compared to uniform retrieval"
  - [section]: Finding 1 in Section 5.2 shows oracle 86.7% vs uniform 81.3% with 62% fewer tokens; Section 5.3 discusses "Needle in a haystack" and "Conflicting information" effects.
- Break condition: If the router omits a required store (low coverage), the answer becomes unretrievable; if it includes too many stores (high waste), token cost rises and accuracy may suffer from noise.

### Mechanism 2
- Claim: Store routing can be formalized as a cost-sensitive subset-selection optimization, explicitly trading expected answer accuracy against retrieval cost.
- Mechanism: The router solves π*(q) = argmax_G E[Acc(q,G)] − λ Σ_{s∈G} c_s, where c_s is the cost (e.g., tokens) of accessing store s and λ controls the trade-off.
- Core assumption: There is a monotonic relationship where adding more stores increases cost but may yield diminishing or negative returns to accuracy beyond a point.
- Evidence anchors:
  - [abstract]: "We additionally formalize store selection as a cost-sensitive decision problem that trades answer accuracy against retrieval cost"
  - [section]: Section 3.4 defines Equation (4) and interprets λ=0 as uniform retrieval.
- Break condition: If λ is too low, the policy approaches uniform retrieval (high cost, potential accuracy drop); if too high, it may omit necessary stores, reducing accuracy.

### Mechanism 3
- Claim: Heuristic routers can achieve high synthetic coverage but still underperform end-to-end QA due to extraction errors and over-retrieval-induced noise.
- Mechanism: The hybrid heuristic (rule-based + fallback) selects correct stores in 94% of synthetic cases but only achieves 70.7% QA accuracy, because even correct store selection may not guarantee answer extraction, and over-retrieval adds distracting context.
- Core assumption: Synthetic routing labels derived from query taxonomies are an imperfect proxy for real-world answerability; downstream performance depends on both retrieval and generation.
- Evidence anchors:
  - [abstract]: "show that routing decisions are a first-class component" and "motivate learned routing mechanisms"
  - [section]: Table 1 (94% coverage) vs Table 2 (70.7% accuracy); Section 5.4 analyzes the 12% routing error and 18% extraction error contributions.
- Break condition: If extraction errors dominate, improving routing alone yields limited gains; joint optimization of routing and retrieval may be needed.

## Architecture Onboarding
- Component map: Router -> Memory Stores (STM, Summary, LTM, Episodic) -> Retriever (per store) -> LLM
- Critical path: 1. Receive query. 2. Router predicts store subset G. 3. For each store s in G, retrieve relevant content (full or ranked). 4. Concatenate retrieved texts into context. 5. Prompt LLM with context + query. 6. Return answer.
- Design tradeoffs:
  - Fixed subset (e.g., STM+Sum+LTM) vs. adaptive router: fixed is simpler and often strong, but adaptive can handle diverse queries more efficiently.
  - Full-store retrieval vs. within-store ranking: full retrieval simplifies analysis but may waste tokens; ranking within stores could further reduce tokens but adds complexity.
  - Token cost vs. accuracy: selective routing reduces tokens but risks missing required stores; the cost-sensitive framework quantifies this.
- Failure signatures:
  - Low coverage on synthetic evaluation → router missing required stores.
  - High waste → over-retrieval, likely to harm long-context accuracy.
  - Large gap between synthetic coverage and QA accuracy → extraction failures or context noise issues.
- First 3 experiments:
  1. Synthetic routing evaluation: Use query-type labels to measure coverage, exact match, waste of routing policies in isolation.
  2. LLM QA evaluation: Run end-to-end on real questions, compare policies for accuracy and token usage across short/long contexts.
  3. Feature ablation: Remove semantic or embedding signals to assess their contribution to routing quality on synthetic labels.

## Open Questions the Paper Calls Out
1. **How can store-routing policies be learned end-to-end to directly optimize question-answering accuracy, overcoming the limitations of current heuristic approaches?**
   - Basis: The paper identifies a 16 percentage point gap between the hybrid heuristic (70.7% QA accuracy) and oracle routing (86.7% on GPT-4o-mini). The authors explicitly state that closing this gap "will likely require routing policies that are learned end-to-end and optimized directly for downstream QA outcomes rather than relying solely on hand-designed heuristics."
   - Why unresolved: Heuristic routing, while achieving high synthetic coverage (94%), underperforms on real QA due to extraction failures and over-retrieval noise. Current policies do not jointly optimize store selection with within-store retrieval or generation.
   - What evidence would resolve it: A learned routing component (e.g., neural network or reinforcement learning agent) trained on the QA task, where routing decisions are rewarded based on final answer correctness. Evaluation should match the paper's setup: compare QA accuracy and token count against heuristic and oracle baselines, demonstrating a significant reduction in the heuristic-oracle gap.

2. **Beyond synthetic taxonomies, how can ground-truth store requirements be reliably annotated for real-world memory-augmented agent queries?**
   - Basis: The paper uses query-type mappings from benchmarks (LoCoMo, LongMemEval) to generate synthetic store labels. The authors acknowledge this "does not fully capture the variability present in real-world deployments" and suggest human validation would be stronger.
   - Why unresolved: Synthetic labels assume ideal store semantics and consistent query types, but real user queries may have ambiguous store dependencies due to imperfect memory updates, cross-store references, or evolving information. Human annotation is expensive and may suffer from inconsistency.
   - What evidence would resolve it: Collect a dataset of real user queries with human annotations indicating necessary stores (with agreement metrics). Compare routing policy performance using synthetic vs. human labels to quantify bias. Develop semi-automated labeling protocols that combine heuristics with human oversight.

3. **Do the accuracy and efficiency benefits of selective store routing generalize across diverse LLM architectures and context management strategies?**
   - Basis: The study evaluates only two model families (GPT-3.5-turbo, GPT-4o-mini). The limitation section explicitly states that "testing additional architectures and training paradigms would strengthen claims about generalization," especially for models with different context handling.
   - Why unresolved: Models differ in how they utilize long contexts, attend to relevant information, and integrate retrieved content. Routing might be more critical for models with limited context windows or attention sparsity, while others might handle noise better. Unknown if findings hold for open-source or smaller models.
   - What evidence would resolve it: Replicate the experiments with a diverse set of LLMs (e.g., Claude 3, Llama 3, Mistral) spanning various sizes and architectures. Measure the oracle vs. uniform accuracy gap and token savings across models. Analyze correlations with model-specific properties like context length or attention mechanisms.

4. **How does the choice of store-level routing policy interact with within-store retrieval ranking (e.g., top-k vs. full store) in determining overall QA performance?**
   - Basis: The paper uses full store concatenation to isolate routing effects, but notes that production systems use within-store ranking. The authors identify this interaction as an "important direction for future study."
   - Why unresolved: Routing selects stores but if within-store retrieval returns noisy passages, even correct stores may not yield answers. Conversely, strong within-store ranking might reduce the need for precise routing. The combined design space is unexplored.
   - What evidence would resolve it: Conduct a factorial experiment varying routing (uniform, heuristic, oracle) and within-store retrieval (full store, top-5 passages, dense retrieval). Evaluate QA accuracy and token count. Use statistical analysis (e.g., ANOVA) to measure main effects and interactions. Explore joint optimization methods.

## Limitations
- Generalizability: Experiments only on LoCoMo/LongMemEval with GPT models; unknown if benefits hold for other domains or LLM families.
- Learned router missing: Paper motivates but does not implement a learned routing policy; heuristic may not be optimal.
- Synthetic label noise: Query-type to store mapping may be approximate; coverage metrics may not fully predict real answerability.
- Extraction bottleneck: Large gap between synthetic coverage (94%) and QA accuracy (70.7%) suggests LLM extraction limits; routing alone may not suffice.
- λ sensitivity: Cost-sensitive trade-off is formulated but the choice of λ is not explored; practical allocation unclear.

## Confidence
- Uniform retrieval reduces accuracy and inflates token cost: **High**
- Oracle routing improves both efficiency and QA performance: **High**
- Fixed STM+Sum+LTM policy is competitive: **Medium**
- Cost-sensitive subset selection formalization is sound: **Medium**
- Heuristic routers achieve high synthetic coverage but underperform end-to-end: **High**
- Selective store retrieval enhances the accuracy–efficiency trade-off: **High**
