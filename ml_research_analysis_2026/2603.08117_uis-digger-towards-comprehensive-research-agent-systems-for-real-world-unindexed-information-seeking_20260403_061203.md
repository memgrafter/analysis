# UIS-Digger: Towards Comprehensive Research Agent Systems for Real-world Unindexed Information Seeking

## Quick Facts
- **arXiv ID:** 2603.08117
- **Source URL:** https://arxiv.org/abs/2603.08117
- **Reference count:** 40
- **Primary result:** UIS-Digger achieves 27.27% accuracy on the UIS-QA benchmark, surpassing systems using more advanced LLMs like O3 and GPT-4.1.

## Executive Summary
This paper introduces Unindexed Information Seeking (UIS), a critical challenge where vital information resides on webpages not indexed by search engines. Existing state-of-the-art agents show a drastic performance drop on a new expert-annotated benchmark, UIS-QA (110 QA pairs), falling from ~70% on GAIA to ~24%. To address this, the authors propose UIS-Digger, a multi-agent framework that employs dual-mode browsing (textual and visual) and integrates a file reader. The system uses a ~30B-parameter LLM fine-tuned via Supervised Fine-Tuning (SFT) and Rejection Sampling Fine-Tuning (RFT). UIS-Digger's 27.27% accuracy on UIS-QA demonstrates the efficacy of its proactive, tool-augmented approach and highlights a significant gap in current agent evaluation paradigms.

## Method Summary
UIS-Digger is a multi-agent framework comprising a planner and four specialized agents (web searcher, web surfer, file reader, and the planner itself). The web surfer executes a dual-mode browsing strategy: it primarily uses fast textual HTML parsing but dynamically switches to visual screenshot analysis for complex elements like charts, maintaining a shared browser state across modes. The system is trained in two stages: SFT initializes the model with teacher-generated correct trajectories, and RFT bootstraps further by having the model generate diverse samples, filtering correct ones via reject sampling, and reweighting by difficulty. This approach enables a relatively small backbone LLM to master the complex, long-horizon tool use required for UIS.

## Key Results
- State-of-the-art agents (e.g., on GAIA) experience a severe performance collapse on UIS-QA, dropping from 70.90 to 24.55.
- UIS-Digger achieves 27.27% accuracy on UIS-QA, outperforming baselines using more advanced LLMs (O3, GPT-4.1) by a significant margin.
- The framework demonstrates that proactive interaction with unindexed sources via specialized tools and training is more critical than raw LLM capability for UIS tasks.

## Why This Works (Mechanism)
### Dual-mode browsing with shared memory enables efficient and accurate webpage understanding.
The web surfer agent toggles between a fast textual mode (HTML parsing) for most actions and a visual mode (screenshot analysis) for elements difficult to parse textually (e.g., charts, dynamic content). A single synchronized browser state is maintained across modes to prevent desynchronization. This balances completeness and efficiency.
*Evidence:* [section 3.1]: "we introduce a dual-model memory-shared browsing strategy, to balance both completeness in functionality and high efficiency."

### Multi-agent decomposition with specialized roles handles diverse action spaces.
A planner decomposes the query and coordinates four domain-specialized agents (searcher, surfer, reader, synthesis) via a request-response message system, with each agent having private memory. This division reduces per-agent complexity and allows for tool specialization.
*Evidence:* [section 3.1]: Full description of agents and their tools.

### Two-stage training (SFT then RFT) with synthetic data bootstraps capability in a small backbone LLM.
SFT initializes the model with teacher-generated correct trajectories. RFT uses the SFT model to generate diverse samples, filters correct ones via reject sampling, and reweights by difficulty to reinforce successful strategies and encourage exploration.
*Evidence:* [section 3.2]: Detailed pipeline for data synthesis and two-stage training.

## Architecture Onboarding
Planner -> Web Searcher -> Web Surfer -> File Reader; Planner synthesizes final answer.
1. User query → Planner. 2. Planner decomposes and sends subtasks to Searcher or Surfer. 3. Searcher retrieves URLs/snippets; may delegate deep crawling to Surfer. 4. Surfer navigates pages, toggles modes; if a file is downloaded, it hands off to Reader. 5. Reader extracts text; agents may iterate. 6. Collected evidence returns to Planner for synthesis.
- **Design tradeoffs:** Dual-mode (visual richness vs. speed), multi-agent (specialization vs. communication overhead), synthetic training (data scaling vs. distribution gap).
- **Failure signatures:** Excessive browsing actions without progress; failure to retrieve the gold root website; unused crawl tool on search result pages; confident but unsupported final answers.
- **First 3 experiments:** 1) End-to-end validation on UIS-QA examples. 2) Ablation: disable visual mode and measure drop on visual samples. 3) Training analysis: compare base, SFT, RFT models on a held-out UIS-QA subset.

## Open Questions the Paper Calls Out
- **How can the distribution gap between synthetically generated UIS QA pairs and real-world UIS scenarios be systematically reduced?** Synthetic data may not capture full complexity, noise, and dynamics of authentic sources, limiting generalization (Section 5).
- **Can intermediate process supervision be integrated to distinguish high-quality from low-quality but correct trajectories?** Reject sampling's sparse final-answer signal misses nuances in exploration efficiency and tool-use optimality (Section 5).
- **To what extent does the backbone LLM’s intrinsic capability determine the UIS performance upper bound, and how can frameworks better leverage advanced LLMs?** Performance disparities persist even with broad action spaces, suggesting fundamental LLM abilities are a bottleneck (Section 4.3).
- **How stable are UIS benchmarks over time given dynamic web content, and what methodologies mitigate temporal drift?** Websites evolve; questions anchored to specific pages may become too easy or unsolvable as content changes or replicates (Section 5).

## Limitations
- Synthetic data used for SFT/RFT may not fully capture the complexity and noise of real UIS tasks, risking distribution shift and limited generalization.
- The shared browser state in dual-mode browsing is a critical but fragile assumption; desynchronization during mode switches could cause silent failures.
- Performance (27.27%) indicates substantial room for improvement; current tool integration or reasoning depth may be insufficient, and scalability of multi-agent coordination is unproven.

## Confidence
- **Dual-mode browsing mechanism:** Medium. Design is specified, but state integrity and VLM reliability are unvalidated in ablation.
- **Multi-agent decomposition:** Medium. Architecture is clear and aligns with trends, but planner robustness and message fidelity lack quantitative failure analysis.
- **Two-stage training efficacy:** Medium-Low. Pipeline described, but without validation on synthetic vs. real trajectory distributions, overfitting/coverage risks are high.
- **UIS-QA benchmark validity:** Medium. Expert-annotated but small (110 pairs); nascent field signals uncertain generalizability.
