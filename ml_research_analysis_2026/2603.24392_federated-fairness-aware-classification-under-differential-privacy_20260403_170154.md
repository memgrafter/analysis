# Federated fairness-aware classification under differential privacy
## Quick Facts
- **arXiv ID**: 2603.24392
- **Source URL**: https://arxiv.org/abs/2603.24392

## Executive Summary
The paper introduces FDP-Fair, a novel algorithm for fairness-aware classification in federated learning under differential privacy. FDP-Fair extends to the federated setting with (ε,δ)-federated differential privacy guarantees, and a simpler variant CDP-Fair for single-server scenarios. The method employs Gaussian mechanisms and a private binary tree to perform threshold search, ensuring fairness constraints while preserving privacy. Theoretical analysis provides an excess risk decomposition that isolates the effects of privacy and fairness, showing that demographic disparity can be controlled within α plus an error term ρ that captures privacy and fairness estimation. Extensive experiments on synthetic and real datasets demonstrate the inherent trade-offs among privacy, fairness, and accuracy, validating the theoretical bounds.

## Method Summary
The submission did not include explicit reproduction notes; however, the key outcome describes the proposed FDP-Fair algorithm. FDP-Fair operates in a federated setting where clients perform local updates with Gaussian noise to satisfy differential privacy. The server aggregates these updates and then uses a private binary tree to search for the optimal classification threshold that meets a demographic parity constraint (α). This threshold search is itself differentially private, contributing to the overall (ε,δ)-FDP guarantee. An alternative CDP-Fair variant simplifies this for a single-server setting. The theoretical analysis decomposes the excess risk into four components: intrinsic classification cost, privacy cost, non-private fairness cost, and private fairness cost. The disparity bound α + O(ρ) reflects the interplay between the target fairness level α and the accumulated error ρ induced by privacy mechanisms.

## Key Results
- Proposes FDP-Fair (federated) and CDP-Fair (single-server), the first algorithms for fairness-aware classification under differential privacy.
- Achieves (ε,δ)-federated DP using Gaussian mechanisms and a private binary tree for threshold search; theoretical guarantees bound demographic disparity within α + O(ρ) and separate excess risk into intrinsic, privacy, and fairness components.
- Validates the privacy–fairness–accuracy trade-offs through experiments on synthetic and real datasets, supporting the theoretical findings.

## Why This Works (Mechanism)
FDP-Fair succeeds by carefully constructing a differentially private pipeline: local client updates are perturbed with Gaussian noise calibrated to the sensitivity of the federated learning process. On the server, aggregation (e.g., averaging) leverages the composition of differential privacy to maintain the overall budget. The core fairness mechanism is a private search for a threshold that enforces demographic parity. This search is implemented via a binary tree where noise is added at each node, allowing the server to identify a suitable threshold without revealing individual client information. The Gaussian mechanism ensures that the noise magnitude scales with sensitivity and the desired privacy parameters (ε,δ), while the binary tree reduces the number of queries needed compared to a linear scan, limiting privacy loss. This design yields a formal (ε,δ)-FDP guarantee and controls disparity through the parameter α and the accumulated error ρ.

## Architecture Onboarding
**Component Map**:  
Client Local Computation → Noised Update → Server Aggregation (DP) → Private Binary Tree Threshold Search → Model Broadcast → Client Update (repeat).  

**Critical Path**:  
1. Clients compute local model updates (e.g., gradients) and add Gaussian noise.  
2. Server aggregates noised updates, maintaining DP.  
3. Server executes private binary tree search to find a threshold that satisfies demographic parity α.  
4. Server applies threshold to produce final classifier and distributes it to clients.  

**Design Tradeoffs**:  
- *Privacy vs Accuracy*: Larger ε reduces noise, improving accuracy but weakening privacy.  
- *Communication Efficiency*: Binary tree reduces threshold query count, cutting communication rounds.  
- *Fairness Tightness*: Smaller α enforces stricter parity but may increase error; ρ captures additional cost due to privacy.  
- *Computational Load*: Private tree search adds server-side work proportional to tree depth.

**Failure Signatures**:  
- Disparity significantly exceeding α + O(ρ) indicates insufficient privacy budget or algorithmic error.  
- Excessively high loss suggests noise variance too large or inadequate number of clients.  
- Communication overhead grows with tree depth; deep trees may become impractical.

**First Three Experiments**:  
1. Vary ε and measure accuracy/disparity on synthetic data; confirm privacy–accuracy trade-off.  
2. Compare FDP-Fair vs CDP-Fair on a real dataset; assess federated vs single-server performance.  
3. Sweep α to evaluate impact on disparity and accuracy; estimate ρ by comparing private vs non‑private fairness costs.
