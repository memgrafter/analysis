# OpenSeeker: Democratizing Frontier Search Agents by Fully Open-Sourcing Training Data

## Quick Facts
- **arXiv ID**: 2603.15594  
- **Source URL**: https://arxiv.org/abs/2603.15594  
- **Reference count**: 10  
- **Primary result**: With only 11.7k synthesized training samples and simple SFT, OpenSeeker achieves new SOTA on search benchmarks (e.g., 29.5% on BrowseComp EN, 48.4% on BrowseComp-ZH), outperforming models backed by massive corporate resources.

## Executive Summary
OpenSeeker addresses the chronic lack of transparent, high-quality training data for frontier web search agents, which has limited progress to well-funded corporations. It introduces two core innovations: (1) Fact-grounded scalable QA synthesis that reverse-engineers the web graph via topological expansion and entity obfuscation to generate complex, multi-hop queries; (2) Denoised trajectory synthesis using retrospective summarization to produce high-quality tool-use sequences. Trained with a single supervised fine-tuning (SFT) run on only 11.7k synthesized samples, OpenSeeker achieves state-of-the-art performance on key benchmarks, including a more than doubling of the prior best open-source score on BrowseComp. The work fully open-sources its complete training dataset and model weights, democratizing research in search agents.

## Method Summary
The method comprises three stages. First, a QA synthesis pipeline processes a web corpus (~68GB English, ~9GB Chinese). Starting from a seed page, it expands into a local subgraph, extracts entities, generates an initial question, then applies entity and question obfuscation to force multi-hop reasoning, and verifies solvability and difficulty using a base model. Second, trajectory synthesis employs a teacher LLM to generate ReAct-style sequences; during generation the context combines summarized long-term history with raw short-term observations to denoise the signal. Third, for training, a student model (Qwen3-30B-A3B) is fine-tuned via SFT to predict the same expert steps but conditioned on the original raw observation history, compelling the model to learn denoising. No continual pre-training or reinforcement learning is used.

## Key Results
- **BrowseComp (EN)**: 29.5%, more than doubling the prior best open-source result (15.3%).
- **BrowseComp-ZH (ZH)**: 48.4%, surpassing Alibaba’s Tongyi DeepResearch (46.7%) despite its CPT+SFT+RL pipeline.
- **xbench-DeepSearch**: 74.0%; **WideSearch**: 59.4% item F1.

## Why This Works (Mechanism)

### Mechanism 1: Fact-grounded scalable QA synthesis
- **Claim**: The pipeline generates complex, multi-hop queries that mandate deep graph traversal by reverse-engineering the web's topological connectivity.  
- **Mechanism**: Graph Expansion creates a local subgraph from a seed; Entity Extraction builds an Entity Subgraph; Entity Obfuscation vaguerizes specific entities; Question Obfuscation turns a straightforward fact into a puzzle solvable only by traversing the preserved graph structure. Dual-criteria verification (solvability via a base model, difficulty control) ensures quality.  
- **Core assumption**: Complex reasoning requires navigating a connected information space, not mere factual recall; query design structurally enforces multi-node traversal.  
- **Break condition**: If subgraph expansion yields disconnected clusters or obfuscation introduces irrecoverable ambiguity, the solvability check fails, rejecting the sample.

### Mechanism 2: Denoised trajectory synthesis
- **Claim**: Using retrospective summarization during teacher generation but training on raw history forces the student to internalize robust information extraction from noisy tool outputs.  
- **Mechanism**: A teacher model generates reasoning/actions on a context where older raw observations are replaced by summaries (Summarized History + Raw Short-Term Context). The resulting expert trajectories are clean. For training, the student predicts the same steps but sees the original, raw, uncompressed history. This asymmetry compels the student to learn to ignore irrelevant noise.  
- **Core assumption**: Frontier search performance is bottlenecked by extracting precise information from noisy tool outputs; learning must occur under realistic noise.  
- **Break condition**: If summarization loses critical information, the teacher's action becomes suboptimal; if raw context is too noisy, student training may not converge.

### Mechanism 3: High data quality reduces need for CPT/RL
- **Claim**: Exceptional fidelity and difficulty of synthesized data make simple SFT sufficient to achieve frontier performance, bypassing costly continual pre-training or RL.  
- **Mechanism**: Synthesized data provides accurate supervision for the entire reason→tool→observe loop; questions are provably hard and trajectories optimally denoised. This distribution allows the model to learn the correct policy from high-signal examples, reducing the exploration burden RL typically addresses.  
- **Core assumption**: The primary limitation is scarcity of training data that faithfully represents long-horizon, noisy, multi-hop search; solving the data problem simplifies training.  
- **Break condition**: If the synthesized data distribution mismatches true test distributions (e.g., different ambiguity types, website structures), SFT may overfit and fail.

## Architecture Onboarding
Component map:  
Web Corpus -> QA Synthesis Engine -> (q, y) -> Trajectory Synthesis Engine -> τ* -> Training Pipeline (SFT on raw history) -> OpenSeeker model -> Inference Agent

Critical path:  
Web Corpus → QA Synthesis → (q, y) → Trajectory Synthesis (with denoised context) → τ* → Strip summaries for training → (q, raw τ*) → SFT → OpenSeeker model.

Design tradeoffs:
- Scalability vs. Control: Graph expansion parameter (k) balances difficulty and compute; larger k yields harder samples but reduces total synthetic volume.
- Synthesis Fidelity vs. Generalizability: Real-world web navigation is used, but artificial obfuscation may not match natural queries; risk of overfitting.
- Denoising Asymmetry: Summarization during synthesis adds compute overhead; tradeoff is cleaner teacher trajectories vs. risk that student cannot learn from noisier raw format.

Failure signatures:
1. Low average tool calls per trajectory (<20): questions are too easy, failing difficulty.
2. High variance in performance across benchmarks: data distribution is narrow (e.g., limited website structures or entity types).
3. Model over-relies on parametric knowledge: answers correctly without invoking tools, indicating insufficient difficulty verification.

First 3 experiments:
1. **Replicate QA synthesis on a small corpus**: Run the full pipeline on 100 seed pages; manually inspect 10 outputs to verify that questions require multi-page visits and answers are unambiguously present in the subgraph.
2. **Ablate denoised trajectory synthesis**: Train two models on identical (q, τ*) pairs; one uses raw history (as in paper), the other uses the denoised/summarized history. Compare performance; expect the raw-history model to be more robust.
3. **Data efficiency curve**: Train on subsets of the OpenSeeker data (1k, 5k, 10k, 11.7k samples) via SFT. Plot performance vs. sample count; a steep early improvement (>25% from 1k→5k) would validate the high-signal claim.

## Open Questions the Paper Calls Out
### Open Question 1
- *Question*: Can supervised fine-tuning (SFT) alone consistently match the performance of models trained with continual pre-training (CPT) and reinforcement learning (RL) across all key search benchmarks, or does the observed superiority on BrowseComp-ZH depend on dataset-specific factors?  
- *Basis in paper*: OpenSeeker (SFT only, 11.7k samples) surpasses Tongyi DeepResearch (CPT+SFT+RL) on BrowseComp-ZH (48.4% vs. 46.7%) but was evaluated on a 200-sample subset of BrowseComp due to resource constraints, leaving full benchmark performance unknown.  
- *Why unresolved*: The paper lacks comprehensive head-to-head evaluation on full test sets and across varied model scales, partly due to a single training run without hyperparameter tuning.  
- *What evidence would resolve it*: Replicate training with multiple seeds, systematic hyperparameter optimization, and full evaluation on all benchmarks—including complete BrowseComp—to determine if SFT alone is broadly competitive or gains are corpus-specific.

### Open Question 2
- *Question*: How does scaling the web corpus size (e.g., to terabytes) quantitatively affect the diversity, complexity, and downstream model performance of fact-grounded QA synthesis?  
- *Basis in paper*: The authors claim their QA synthesis is scalable to TB-scale web archives but only used ~68GB English and ~9GB Chinese data, noting "TB-scale web archives still largely untapped."  
- *Why unresolved*: The scalability assertion is theoretical; empirical validation on larger corpora is absent, so the correlation between corpus size and improvements in data diversity (e.g., topic coverage, multi-hop depth) and agent capability remains unknown.  
- *What evidence would resolve it*: Generate datasets from progressively larger web corpora (e.g., 100GB, 1TB), measure entity/subgraph diversity and question complexity distributions, and train agents to assess performance gains per scale increment.

### Open Question 3
- *Question*: Does the asymmetric training design—using denoised (summarized) context during trajectory synthesis but raw context during model training—successfully compel the agent to learn intrinsic denoising and robust information extraction, or could similar performance be achieved with symmetric raw-context synthesis?  
- *Basis in paper*: The methodology decouples synthesis (teacher uses summarized history) from training (student uses raw history), hypothesizing this forces denoising capability learning, but no ablation compares this against symmetric raw-context synthesis.  
- *Why unresolved*: The paper provides no direct evidence that the model internalizes denoising; observed gains might stem from higher-quality teacher trajectories or other factors.  
- *What evidence would resolve it*: Train agents under two conditions: (1) proposed asymmetric pipeline, (2) symmetric raw-context synthesis (teacher also sees raw history). Evaluate both on real-world noisy web tasks and on synthetic tests with controlled observation noise levels.

### Open Question 4
- *Question*: Can the OpenSeeker synthesis framework be generalized beyond web search to produce training data for multi-modal agents or agents with diverse tool suites (e.g., code execution, database querying), and what modifications would be required?  
- *Basis in paper*: The future work section states intent to "extend the agent’s capabilities beyond pure web search by integrating a more diverse set of tools and data sources."  
- *Why unresolved*: The pipeline is specifically engineered for web graph reverse-engineering and text-based tools; its applicability to other modalities or tools is unexplored, with unknown challenges in grounding, trajectory design, and verification.  
- *What evidence would resolve it*: Adapt the QA synthesis to non-web domains (e.g., questions requiring code or scientific dataset tools) and the denoised trajectory method to handle multi-modal observations. Success would be demonstrated by training agents that achieve competitive performance on benchmarks involving diverse tools.

## Limitations
- **Replication blockers**: Exact web corpus source/preprocessing and teacher LLM identity are unreported, preventing faithful reproduction.
- **Lack of external validation**: Zero citations indicate findings are not yet corroborated by independent work.
- **Potential distribution mismatch**: Artificially obfuscated queries may not generalize to natural user intent, risking benchmark overfitting.

## Confidence
- **High**: Reported benchmark scores (BrowseComp, xbench-DeepSearch, WideSearch).
- **Medium**: Effectiveness of graph-based QA synthesis mechanism.
- **Medium**: Sufficiency of SFT without continual pre-training or RL.

## Next Checks
1. **QA difficulty audit**: Sample 50 synthesized QAs; verify >80% require ≥3 tool calls and fail a zero-shot base model, confirming multi-hop enforcement.
2. **Denoising asymmetry ablation**: Train two models on identical data—one with raw history, one with summarized history; expect >5% absolute gain on xbench-DeepSearch for raw-history model.
3. **Data efficiency test**: Train on subsets (1k, 5k, 10k, 11.7k); expect steep early improvement (>25% jump from 1k→5k) validating high-signal data claim.
