# Temporal Text Classification with Large Language Models
## Quick Facts
- **arXiv ID:** 2603.11295
- **Source URL:** https://arxiv.org/abs/2603.11295
- **Reference count:** 14
- **Primary result:** Proprietary LLMs (e.g., GPT‑4o, Claude 3.5) achieve Macro F1 > 0.90 on longer inputs with few‑shot prompting; open‑source models improve substantially via fine‑tuning but remain below proprietary performance.

## Executive Summary
This paper addresses the underexplored problem of Temporal Text Classification (TTC) with Large Language Models. The authors evaluate seven LLMs (both proprietary and open‑source) on three historical corpora (Portuguese and English) using zero‑shot, few‑shot, and fine‑tuning paradigms. Proprietary models demonstrate strong in‑context learning, exceeding 0.90 Macro F1 on longer inputs with just five examples. Open‑source models show modest few‑shot results (0.44–0.53 F1) but gain up to ~0.77 F1 when fine‑tuned with LoRA. Additionally, analysis on model‑generated synthetic test data preserves performance rankings, though absolute scores shift, especially in zero‑shot settings.

## Method Summary
The task is to automatically assign a temporal label (e.g., century, decade) to a text segment. The study uses three historical datasets: Colonia (Portuguese, 5 classes spanning the 16th–20th C.), CLMET (English, three ~70‑year periods from 1710–1920), and DTE (English, variable intervals from 1700–2010). Texts are chunked into fixed lengths (10, 50, 100 tokens). Evaluation uses Macro F1. Three paradigms are tested: (1) zero‑shot prompting (direct classification), (2) few‑shot prompting (5 examples provided), and (3) fine‑tuning via LoRA for open‑source models. Synthetic test sets are generated by prompting proprietary models in few‑shot mode to create period‑specific text.

## Key Results
- Proprietary models (GPT‑4o, Claude 3.5) achieve strong few‑shot performance, often > 0.90 F1 on 100‑token inputs.
- Open‑source models improve dramatically with fine‑tuning (gains up to ~0.30 F1) but still lag behind proprietary few‑shot scores (max ~0.77 F1).
- Performance rankings are largely preserved on synthetic test data, though zero‑shot scores shift more than fine‑tuned ones.

## Why This Works (Mechanism)
**Mechanism 1: Few‑shot unlocking of latent temporal reasoning**  
*Claim:* Providing five exemplars calibrates the model’s internal representation of diachronic linguistic patterns, enabling accurate TTC.  
*Mechanism:* The exemplars act as stylistic anchors; the model aligns its pre‑trained knowledge of temporally stratified language to the classification schema. Longer inputs yield more discriminative signal, hence higher F1.  
*Evidence:* Few‑shot consistently outperforms zero‑shot across proprietary models and datasets, with gaps widening for 100‑token inputs (e.g., GPT‑4o on Colonia: 0.78→0.96).  
*Break condition:* Very short inputs (e.g., 10 tokens) provide sparse temporal cues, limiting benefit.

**Mechanism 2: Fine‑tuning specialization for open‑source models**  
*Claim:* LoRA fine‑tuning updates adapter weights to capture task‑specific temporal features, compensating for weaker innate reasoning.  
*Mechanism:* Parameter‑efficient updates learn mappings from textual markers to time periods without catastrophic forgetting.  
*Evidence:* Fine‑tuned open‑source models rise from ~0.44–0.53 F1 (few‑shot) to ~0.61–0.78 F1, drastically surpassing prompting and a traditional SVM baseline.  
*Break condition:* Gains depend on training data quality/diversity; insufficient or biased data leads to plateau or degradation.

**Mechanism 3: Synthetic data retains ranking but not absolute scores**  
*Claim:* Model‑generated texts preserve enough temporal signal to maintain relative performance ordering across models.  
*Mechanism:* Generators reproduce dominant, learnable temporal markers (e.g., high‑frequency lexical items) even if nuanced cues are distorted.  
*Evidence:* Rankings on authentic and synthetic test sets correlate; models that perform well few‑shot tend to remain strong after fine‑tuning. However, zero‑shot deltas can be large (±0.11).  
*Break condition:* If synthetic text erased all period‑specific markers or introduced confounders, rankings would collapse.

## Foundational Learning
**Temporal Text Classification (TTC)**  
*Why needed:* Defines the core task of assigning a time span to a text based on diachronic language change.  
*Quick check:* Given a text snippet, what are three primary linguistic evidence types (e.g., lexical, syntactic, orthographic) a classifier would use to distinguish an 18th‑century text from a 19th‑century one?

**In‑Context Learning (Few‑Shot Prompting)**  
*Why needed:* Primary paradigm for leveraging proprietary LLMs without weight updates; tests whether exemplars activate latent temporal knowledge.  
*Quick check:* If a model’s few‑shot TTC performance improves drastically from its zero‑shot score, what does that most directly suggest about the model’s pre‑trained knowledge and its interface with the prompt?

**Parameter‑Efficient Fine‑Tuning (LoRA)**  
*Why needed:* Enables adaptation of open‑source models by updating a low‑rank decomposition of weights, making task specialization feasible.  
*Quick check:* How might the fine‑-tuning objective (cross‑entropy loss on temporal class labels) implicitly force the LoRA adapters to learn about diachronic features?

## Architecture Onboarding
Input Preprocessor -> Prompt Engine -> Model Inference Engine -> Evaluation Aggregator.  
Synthetic Data Generator also uses the Prompt Engine (with different templates) to produce new test sets.  
Fine‑Tuning Pipeline: Training Data -> Alpaca Formatter -> LoRA Training -> Adapter (optionally merged) -> Model Inference Engine (with adapter) -> Evaluation.

**Critical path** for evaluating a new model/dataset: Dataset Load → Chunking → Prompt Construction → Inference → Score Calculation.  
For fine‑tuning: Dataset Load → Format to Alpaca → LoRA Training → Adapter Merge (optional) → Inference on Test Set → Score Calculation.

**Design tradeoffs**
- Chunking standardizes length but discards long‑range context.
- Prompt template complexity can boost performance at the cost of engineering effort.
- Fine‑tuning on authentic data is gold‑standard but limited; synthetic data scales cheaply but risks artifacts.

**Failure signatures**
- Proprietary model: sudden drop in F1 for 100‑token vs. 50‑token inputs, or high variance across few‑shot example seeds.
- Open‑source after fine‑tuning: fine‑tuned score lower than few‑shot, indicating catastrophic forgetting or poor hyperparameters.
- Synthetic data collapse: zero‑shot F1 near random on synthetic sets while authentic > 0.4.

**First 3 experiments**
1. Baseline replication: Run zero‑shot and 5‑shot for GPT‑4o on Colonia (100‑token); expect ~0.91 F1 few‑shot.
2. Open‑source sanity check: Fine‑tune Gemma‑2‑9B on CLMET (100‑token) with LoRA (rank 8, α 16) for 3 epochs; expect 0.75–0.78 F1.
3. Synthetic stress test: Generate synthetic DTE test sets with Claude 3.5 (5‑shot); evaluate few‑shot LLaMA‑3.2‑8B; expect large negative delta in zero‑shot (≈ –0.09).

## Open Questions the Paper Calls Out
**Open Question 1:** Why do synthetic test datasets cause systematic performance degradation in zero‑shot LLM predictions for TTC, while few‑shot and fine‑tuned settings remain more robust?  
*Basis:* Section 4 shows zero‑shot shifts larger than fine‑tuned (e.g., Mistral on CLMET: –0.11 at few‑shot vs +0.11 at fine‑tuned).  
*Why unresolved:* Paper speculates parameter updates stabilize performance but does not analyze representational reasons for zero‑shot instability to stylistic shifts.  
*Evidence needed:* Controlled experiments measuring lexical/syntactic divergence between authentic and synthetic datasets, coupled with probing of model hidden states to identify which temporal cues are misrepresented.

**Open Question 2:** What underlies the non‑monotonic performance changes observed when fine‑tuning open‑source models on varying quantities of synthetic data (e.g., 10–1K samples), and how does this relate to overfitting versus beneficial stylistic alignment?  
*Basis:* Limitations note non‑monotonic behavior with synthetic data warrants deeper investigation.  
*Why unresolved:* The study used a fixed synthetic data quantity without systematically scaling or diagnosing whether fluctuations stem from noise or mismatched temporal distributions.  
*Evidence needed:* Ablation with incremental synthetic data sizes, tracking fine‑tuning loss curves on authentic vs. synthetic validation sets, and measuring stylistic fidelity (e.g., period‑specific n‑gram preservation).

**Open Question 3:** Why does fine‑tuning, despite yielding large absolute gains for open‑source models, fail to close the performance gap with proprietary LLMs on TTC, and what architectural or training data factors contribute to this disparity?  
*Basis:* Results show fine‑tuned open‑source max ~0.77 F1 vs. proprietary few‑shot often > 0.90; gap persists.  
*Why unresolved:* Paper does not dissect whether gap arises from pretraining corpus temporal diversity, model scale, reasoning mechanisms, or optimization efficiency.  
*Evidence needed:* Comparative analysis of internal representations (e.g., temporal attention patterns), scaling experiments matching parameter counts, and correlation of pretraining data temporal coverage with TTC accuracy.

**Open Question 4:** How does decreasing temporal interval fineness (e.g., from century‑level to decade‑level) affect LLM accuracy on TTC, and does this impact vary across language families or text genres?  
*Basis:* Conclusion proposes extending to finer granularities; all datasets use coarse intervals (70–100 years).  
*Why unresolved:* No experiments with finer intervals are reported; interaction with linguistic factors unknown.  
*Evidence needed:* Create TTC benchmarks with finer intervals (10–20 years) across multiple languages/genres, measure accuracy decay curves, analyze confusion matrices for systematic biases.

**Open Question 5:** To what extent do LLMs’ TTC capabilities transfer across typologically diverse languages (e.g., agglutinative, tonal), and how is this transfer mediated by pretraining language coverage and script?  
*Basis:* Conclusion mentions extending to more languages; study only covers English and Portuguese (both Indo‑European, Roman script).  
*Why unresolved:* Performance on typologically varied languages, especially low‑resource or non‑Roman scripts, is unexplored.  
*Evidence needed:* Evaluation on TTC datasets for languages with diverse morphosyntactic features (e.g., Arabic, Finnish, Chinese), controlling for pretraining data proportions and measuring cross‑lingual transfer from English/Portuguese fine‑tuning.

## Limitations
- Unspecified few‑shot example sampling, fine‑tuning hyperparameters, and tokenization strategy impede exact replication.
- Synthetic data generation lacks manual validation; risk of temporal bias in generated texts.
- Potential data leakage not addressed due to public corpora and standard splits.
