# DepthCharge: A Domain-Agnostic Framework for Measuring Depth-Dependent Knowledge in Large Language Models

## Quick Facts
- arXiv ID: 2603.23514
- Source URL: https://arxiv.org/abs/2603.23514
- Reference count: 8
- Primary result: DepthCharge reveals depth-dependent performance variation (EVD 3.45–7.55) and shows model rankings vary by domain, with cost not predicting depth performance.

## Executive Summary
Large language models (LLMs) are often evaluated using static question sets that do not capture how well they sustain accuracy under adaptive, follow-up questioning—a key requirement for professional applications. DepthCharge addresses this gap with a domain-agnostic framework that probes knowledge depth by adaptively drilling into concepts the model itself mentions, verifying facts on-demand from authoritative sources, and applying survival statistics with constant sample sizes per depth. Across four domains and five frontier models, DepthCharge uncovers substantial hidden variation: Expected Valid Depth (EVD) ranges from 3.45 to 7.55, model rankings differ by domain, and cost does not correlate with depth performance. These findings demonstrate that domain-specific, depth-sensitive evaluation is essential for assessing LLM reliability in real-world, multi-turn interactions.

## Method Summary
DepthCharge begins with diverse seed questions for a given domain. For each correct answer, it extracts key concepts and generates follow-up questions targeting those concepts, constructing a personalized probing tree. Each follow-up question is derived from a verifiable fact retrieved in real time from a tier-appropriate source (e.g., Wikipedia for common knowledge, professional literature for specialist tiers). The model's answer is scored by an LLM evaluator checking entailment against the retrieved fact. To ensure statistical robustness, exactly N=30 questions are asked at each depth level, distributed among all surviving paths. Cumulative survival probability S(d) = ∏_{i=1}^{d} A(i) (where A(i) is accuracy at depth i) models the chance a random path survives up to depth d. The evaluation stops when S(d) falls below a survival threshold θ (default 20%). The Expected Valid Depth (EVD) sums S(d) across depths, summarizing the depth at which the model maintains accurate responses. This on-demand fact verification and adaptive drilling make the framework reusable across any domain with publicly verifiable facts.

## Key Results
- Expected Valid Depth (EVD) spans 3.45 to 7.55 across model-domain pairs, indicating wide differences in how deeply models can sustain accuracy.
- Model rankings change dramatically depending on the domain, proving that aggregate benchmark scores do not reliably predict depth-based performance.
- There is no correlation between model cost and depth performance; cheaper models sometimes achieve greater depth in specific domains.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Adaptive drilling reveals model-specific knowledge boundaries by following concepts the model itself mentions, rather than a fixed script.
- **Mechanism:** For each correct answer, the system extracts key concepts (e.g., "neuraminidase inhibitors" from a treatment explanation) and generates follow-up questions about those specific concepts. This creates a personalized probing tree where failure depths depend on the model's own output, exposing genuine gaps that static questions miss.
- **Core assumption:** A model's chosen terminology and emphasized concepts indicate the boundaries of its reliable knowledge; drilling into these reveals where its competence ends.
- **Evidence anchors:**
  - [abstract] "adaptive probing that generates follow-up questions based on concepts the model actually mentions"
  - [section 3.2] "drilling directions are determined by what the model says... This creates personalized probing paths that reveal each model’s actual knowledge boundaries."
  - [corpus] Weak signal: KGLens [paper_id: 253452] probes LLM knowledge with knowledge graphs, suggesting structured probing aligns with knowledge representation, but does not address adaptive follow-up.
- **Break condition:** If the model's answer contains no extractable concepts (e.g., overly vague or incorrect), the path terminates. The mechanism fails to probe depth if initial answers are too poor to generate meaningful drilling directions.

### Mechanism 2
- **Claim:** On-demand fact verification from tier-appropriate authoritative sources provides ground truth without pre-built test sets, enabling domain-agnostic deployment.
- **Mechanism:** Before generating each question, the system searches for a verifiable fact (e.g., Wikipedia summary for COMMON tier, clinical guidelines for PROFESSIONAL). The question is derived from this fact, and the model's answer is scored via entailment against the fact. This real-time sourcing eliminates manual test construction.
- **Core assumption:** Authoritative, publicly available sources (Wikipedia, professional literature) contain sufficient verifiable facts to generate questions at increasing specificity tiers for any valid domain.
- **Evidence anchors:**
  - [abstract] "on-demand fact verification from authoritative sources"
  - [section 3.3] Describes tiered sourcing (Wikipedia, retrieval-augmented systems for professional+). "This on-demand approach enables domain-agnostic testing: the same framework works for cardiology, tax law, or quantum physics without modification."
  - [corpus] PEEK [paper_id: 253452] and ALIGNed-LLM [paper_id: 34555] use knowledge graphs for factual alignment, supporting the premise that external structured knowledge can verify LLM output.
- **Break condition:** At high specificity tiers (SPECIALIST, CUTTING_EDGE), verifiable facts may be scarce or non-existent for certain drilling directions. The probe is marked failed ("no ground truth available"), which itself signals domain knowledge boundaries but limits depth measurement.

### Mechanism 3
- **Claim:** Cumulative survival statistics with constant sample size (N=30 per depth) yield statistically reliable depth profiles by preventing sample-size attrition from distorting results.
- **Mechanism:** At each depth, exactly N questions are asked, distributed across all surviving paths (e.g., 1 question each if 30+ paths survive; 10 questions each if 3 paths survive). Accuracy at depth *d* is *A(d)*. Cumulative survival *S(d)* = ∏_{i=1}^{d} *A(i)* models the probability of a random path surviving all questions up to depth *d*. Expected Valid Depth (EVD) sums *S(d)* until *S(d) < θ* (default 20%).
- **Core assumption:** A constant number of observations per depth is necessary for meaningful statistical inference; otherwise, dwindling path counts produce unreliable survival estimates at greater depths.
- **Evidence anchors:**
  - [abstract] "survival statistics with constant sample sizes at every depth level"
  - [section 3.4] "This ensures that accuracy at depth D is always based on 30 observations, not 1. The expansion at each depth prevents statistical fragility."
  - [section 5.3] Shows confidence intervals tighten with larger N (N=30 gives ±17pp at 50% accuracy vs ±26pp for N=10).
  - [corpus] ATLAS [paper_id: 61865] uses IRT for efficient measurement but samples breadth; DepthCharge's constant-N approach is a deliberate trade-off for depth reliability.
- **Break condition:** If cumulative survival drops very rapidly (e.g., *S(2)* < θ), the evaluation stops early with few depth points, reducing the resolution of the depth profile. The constant-N design cannot compensate for fundamentally low survival.

## Foundational Learning
### Survival Analysis & Cumulative Probability
Why needed: The EVD metric is a cumulative product of per-depth accuracies. Understanding that *S(d)* represents the joint probability of surviving all prior depths is key to interpreting why small accuracy drops compound into large EVD differences.
Quick check: If a model has 90% accuracy at depth 1 and 80% at depth 2, what is its cumulative survival at depth 2? (Answer: 0.9 * 0.8 = 0.72 or 72%).

### Domain-Agnostic Design via On-Demand Ground Truth
Why needed: The framework's core value is applying the same methodology to any domain with verifiable facts. This hinges on replacing pre-curated test sets with real-time fact retrieval.
Quick check: Why can't DepthCharge evaluate the domain "subjective aesthetic preferences in modern art"? (Answer: Lacks verifiable factual claims; ground truth is contested.)

### Adaptive vs. Static Evaluation
Why needed: The adaptive mechanism (drilling into model-mentioned concepts) is what exposes the "surface competence illusion." Static benchmarks ask the same questions of all models; adaptive questions depend on the model's output, personalizing the difficulty path.
Quick check: How does adaptive drilling create a different measurement than a fixed, increasing-difficulty question set? (Answer: Fixed set tests a preset knowledge map; adaptive drilling tests the knowledge map the model reveals through its answers.)

## Architecture Onboarding
### Component Map
Drilling Engine -> Fact Verifier/Retriever -> Question Generator -> Target Model Interface -> Entailment Scorer -> Survival Tracker -> Concept Extractor -> Drilling Engine (next depth). Configuration provides parameters (N, Q, θ) to all components.

### Critical Path
1. Initialize: Generate initial_branches (diverse seed questions) for depth 1.
2. For each depth d until stopping condition:
   a. Distribute exactly N questions among surviving paths from depth d-1 (sample paths if more than N survive; assign multiple questions per path if fewer than N survive).
   b. For each assigned question and its path's concept:
      i. Fact Verifier retrieves a verifiable fact from the tier-appropriate source.
      ii. Question Generator creates a closed-ended question based on the fact.
      iii. Target Model Interface queries the model and receives an answer.
      iv. Entailment Scorer judges whether the answer entails the fact (correct/incorrect).
      v. If correct, Concept Extractor identifies key concepts in the answer; these become new child paths for depth d+1.
   c. Count correct responses c_d at this depth.
3. Compute A(d) = c_d / N, S(d) = S(d-1) * A(d). If S(d) < θ, terminate; else increment d and repeat from step 2.
4. Compute Expected Valid Depth (EVD) = Σ_{d=1}^{D} S(d).

### Design Tradeoffs
- Adaptive vs. Comparable: Adaptive drilling reveals model-specific gaps but means models are asked different questions at the same depth, preventing direct item-level comparison. Tradeoff: personalized depth measurement vs. fixed-question-set comparability.
- Evaluator LLM vs. Human: Using an LLM evaluator is scalable and reproducible but results are relative to that evaluator. Human review increases confidence but is expensive and non-scalable. Tradeoff: scalability/automation vs. absolute accuracy certification.
- Constant-N vs. Path-Following: Always asking N questions per depth maintains statistical power but probes many sub-concepts if few paths remain, testing breadth within a concept at depth. Tradeoff: statistical validity vs. potentially exploring tangential sub-concepts.

### Failure Signatures
- Early collapse: S(1) or S(2) very low (< 0.5). Model fails basic follow-ups immediately.
- Flat survival curve: A(d) remains high for many depths then crashes. Model maintains accuracy through foundational tiers but fails at specialist level.
- Erratic depth progression: Rapid fluctuations in A(d) (e.g., 90% -> 30% -> 90%). May indicate unstable concept extraction or lucky paths hitting walls.
- Fact retrieval failure rate: High percentage of "no ground truth available" at higher tiers suggests domain lacks sufficient public literature or retrieval system inadequacy.

### First 3 Experiments
1. **Sanity Check - Single Domain, Single Model:** Run DepthCharge on a well-understood domain (e.g., general Medicine) with a strong model. Verify COMMON accuracy near 100%, monotonically decreasing A(d) through tiers, and EVD around 7.5. Confirms pipeline works.
2. **Parameter Sensitivity - Vary N:** On the same domain/model, run with N=10, 30, 50. Check that EVD converges (differences <0.5 depth units) while confidence intervals widen with smaller N. Validates constant-N design.
3. **Evaluator Stability - Cross-Evaluator:** From a full evaluation, sample 50 question-answer pairs. Score them with three different LLM families as evaluators. Compute rank correlation (Spearman's ρ) of model EVDs from each evaluator. Expect high correlation (>0.9) even if absolute accuracies differ. Tests claim that relative rankings are evaluator-stable.

## Open Questions the Paper Calls Out
1. How stable are DepthCharge model rankings across different evaluator models, and what is the scale of variation introduced by evaluator choice? Larger-scale evaluator sensitivity analyses across more evaluator choices would strengthen confidence in ranking stability.
2. To what extent do DepthCharge depth profiles generalize across diverse knowledge domains beyond the four tested (Medicine, Constitutional Law, Ancient Rome, Quantum Computing)? Additional domains would further strengthen generalizability claims.
3. How do alternative survival metrics (e.g., windowed survival, weighted depths) compare to cumulative survival in predicting real-world LLM reliability under sustained questioning? Alternative formulations merit exploration for different use cases.
4. What is the optimal method for integrating DepthCharge's depth probing with breadth-focused adaptive testing frameworks (e.g., ATLAS) to achieve efficient and comprehensive LLM evaluation? Future work could combine both approaches for comprehensive evaluation that is both broad and deep.

## Limitations
- The primary evaluator model used in the main experiments is unspecified, affecting absolute EVD scores and cross-study comparability.
- Details of the retrieval-augmented fact verification for PROFESSIONAL+ tiers are underspecified, hindering reproducibility in novel domains.
- Adaptive drilling prevents direct item-level comparisons between models, as they receive different question sequences; EVD reflects personalized probing paths rather than a shared test set.

## Confidence
- Depth measurement mechanism (survival statistics, constant-N design): High
- Domain-agnostic claim (on-demand verification works for arbitrary domains): Medium
- Evaluator stability across LLM families: Medium-Low

## Next Checks
1. Conduct an evaluator agreement study: sample 100 question-answer pairs from a full evaluation; score with 3+ diverse evaluator models; compute Cohen’s κ for binary correctness and Spearman’s ρ for EVD rankings to quantify sensitivity.
2. Perform a fact-yield pre-test for candidate new domains: simulate 50 retrieval queries per tier; require ≥80% successful fact extraction at COMMON/TEXTBOOK and ≥60% at PROFESSIONAL to deem the domain viable.
3. Run a constant-N convergence test: evaluate the same model/domain with N=15, 30, 60; expect EVD differences <0.5 depth units, larger divergence indicates insufficient N for stable estimation.
