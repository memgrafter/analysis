# Trajectory-Informed Memory Generation for Self-Improving Agent Systems

## Quick Facts
- **arXiv ID:** 2603.10600  
- **Source URL:** https://arxiv.org/abs/2603.10600  
- **Reference count:** 21  
- **Primary result:** Subtask-level tips with LLM-guided retrieval improve held-out task performance by up to 3.6 pp in Task Goal Completion and 14.3 pp in Scenario Goal Completion, with dramatic gains on complex tasks (+28.5 pp SGC, 149% relative increase).

## Executive Summary
LLM-powered agents often fail to systematically learn from past executions, repeating inefficiencies and missing recovery strategies. This paper introduces a framework that automatically extracts structured, actionable “tips” from agent trajectories, categorizing them as strategy, recovery, or optimization patterns. These tips are stored in an adaptive memory with provenance and retrieved at runtime to augment the agent’s prompt. Evaluated on the AppWorld benchmark, the best configuration (subtask-level tips with LLM-guided retrieval) yields significant gains: +3.6 percentage points in Task Goal Completion and +14.3 pp in Scenario Goal Completion, with especially large improvements on complex tasks (SGC +28.5 pp, 149% relative increase). The work demonstrates that trajectory-informed memory can substantially enhance agent self-improvement without additional training.

## Method Summary
The framework operates in three phases. First, trajectory analysis: agent executions are segmented into logical subtasks using an LLM, and for each subtask, 2–4 actionable tips are generated covering strategies, recovery patterns, and optimizations. Second, storage: subtask descriptions are generalized (entity abstraction, verb normalization, context removal); tips are clustered by semantic similarity using cosine similarity on embeddings (threshold ∼0.85); within clusters, an LLM deduplicates and synthesizes consolidated tips. Tips are stored with dual representations (vector embeddings and metadata). Third, runtime retrieval: for a new query, relevant tips are selected via cosine similarity (τ∈[0.5,0.7]) or LLM-guided selection, and the top 5 are injected into the agent’s prompt. The agent uses a ReAct loop with GPT-4.1, capped at 30 steps. Memory is constructed from AppWorld train/dev trajectories and evaluated on test-normal tasks.

## Key Results
- Subtask-level tips with LLM-guided retrieval: +3.6 pp TGC (73.2% vs baseline ~69.6%) and +14.3 pp SGC (64.3% vs ~50%) on test-normal.  
- Complex tasks show dramatic gains: +28.5 pp SGC, representing a 149% relative improvement.  
- LLM-guided retrieval outperforms cosine similarity for scenario goal completion (+7.2 pp SGC over cosine for subtask-level tips).

## Why This Works (Mechanism)
The improvement likely stems from the systematic extraction and retrieval of actionable patterns that address common failure points. By converting raw trajectories into structured tips, the framework distills effective strategies and recovery methods, enabling agents to avoid previously encountered pitfalls and to apply proven tactics. Retrieval ensures that the most relevant experience is made available at inference time, effectively augmenting the agent’s reasoning without retraining. The categorization into strategy, recovery, and optimization helps target different aspects of task execution, while the dual representation (embeddings + metadata) supports both fast similarity search and context-rich selection.

## Foundational Learning
The paper builds on several core concepts:
- **Trajectory Segmentation**: Breaking down long-horizon tasks into manageable subtasks (why needed: to isolate learnings and enable targeted tip generation; quick check: use an LLM to split a sample trajectory into subtasks and verify coherence).
- **Tip Extraction**: Converting observed behaviors into concise, actionable advice (why needed: to make experiential knowledge explicit and reusable; quick check: generate tips for a given subtask and assess whether they are specific and non-trivial).
- **Semantic Clustering**: Grouping similar tips using embedding similarity (why needed: to consolidate redundant patterns and reduce memory bloat; quick check: compute pairwise similarities for a set of tips and verify that cluster members share a common theme).
- **Provenance Tracking**: Storing source trajectory IDs with each tip (why needed: to enable attribution and future refinement; quick check: retrieve the source of a tip and confirm it matches an original trajectory).
- **Runtime Retrieval**: Selecting relevant tips at inference time via similarity or LLM-guided selection (why needed: to adapt the agent’s knowledge to the current context; quick check: for a new task, retrieve tips and judge their applicability).
- **Adaptive Memory**: Evolving the memory as new trajectories are added (why needed: to continuously improve the agent; quick check: add a new trajectory, regenerate tips, and confirm that new insights are incorporated).

## Architecture Onboarding
**Component Map**:  
Trajectory Data -> Segmentation -> SubTask Nodes -> Tip Generation -> Raw Tips -> Generalization -> Tip Embeddings -> Clustering -> Consolidated Tips -> Storage (Vector DB + Metadata) -> Runtime Query -> Retrieval -> Prompt Injection -> ReAct Agent (GPT-4.1).

**Critical Path**: The pipeline flows from raw trajectories to tip extraction, generalization, clustering, storage, and finally retrieval-injection at runtime. The most crucial step is tip extraction quality, as it determines the utility of stored knowledge.

**Design Tradeoffs**:  
- Granularity: Task-level vs subtask-level tips. Subtask-level offers finer-grained applicability but increases memory size and retrieval complexity.  
- Retrieval method: Cosine similarity is cheap but less nuanced; LLM-guided selection is more accurate but adds latency and cost.  
- Consolidation: Aggressive clustering reduces redundancy but risks over-generalization; conservative clustering preserves diversity but may increase noise.

**Failure Signatures**:  
- Noisy retrieval: Irrelevant tips appear in the prompt, confusing the agent (diagnose by sampling retrieved tips and checking relevance).  
- Over-consolidation: Tips become vague or contradictory (inspect clusters and consolidated tips).  
- Poor segmentation: Subtasks are ill-defined, leading to incoherent tips (review segmentation outputs).

**First Three Experiments**:  
1. Baseline establishment: Run a ReAct agent (GPT-4.1, 30 steps) on AppWorld test-normal without memory to confirm baseline scores (~69.6% TGC, 50% SGC).  
2. Retrieval relevance audit: For 50 random test tasks, collect the top-5 retrieved tips and manually evaluate relevance; aim for >80% relevance. If lower, adjust similarity threshold or switch to LLM-guided retrieval.  
3. Consolidation ablation: Disable tip clustering/consolidation and compare performance against the full system to measure the impact of deduplication.

## Open Questions the Paper Calls Out
- **How does LLM choice affect tip quality and agent performance?** The authors plan to evaluate with Qwen and GPT-OSS to assess how tip quality and retrieval effectiveness vary across model families. (Unresolved: only GPT-4.1 was used.)  
- **What modifications are needed to extend the framework to multi-agent systems, and how does cross-agent attribution impact learning efficiency?** Single-agent attribution ignores interactions between agents; cross-agent failures or complementary strategies require new mechanisms for credit assignment and memory sharing.  
- **To what extent do the improvements on AppWorld generalize to other agent benchmarks (e.g., WebArena, Mind2Web)?** Evaluation is confined to AppWorld; no cross-benchmark validation is provided.  
- **Why does LLM-guided retrieval improve scenario goal completion more than cosine similarity, and how can retrieval be optimized for both task and scenario goals?** Results show LLM-guided selection yields a +7.2 pp SGC gain over cosine for subtask-level tips, while cosine sometimes gives higher TGC; this divergence is not deeply explained.

## Limitations
- Major uncertainties include: exact LLM prompts for segmentation/extraction/consolidation; embedding model and clustering/retrieval thresholds; generalizability beyond AppWorld.  
- Replication may deviate from reported numbers due to unspecified prompt wording and parameter choices.  
- The framework’s effectiveness on domains with different characteristics (e.g., coding, robotics) remains unproven.

## Confidence
- Pipeline description: **High** (clear three-phase process).  
- Performance claims: **Medium** (depends on undocumented prompt and parameter choices).  
- Generalizability: **Low** (no cross-benchmark evidence).
