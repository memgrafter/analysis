# Agentic Test-Time Scaling for WebAgents
## Quick Facts
*   **arXiv ID:** 2602.12276
*   **Source URL:** https://arxiv.org/abs/2602.12276
*   **Reference count:** 40
*   **Primary result:** CATTS dynamically allocates test-time compute based on vote-derived uncertainty, achieving up to 9.1% absolute improvement over React while using up to 2.3× fewer tokens than uniform scaling.

## Executive Summary
Long-horizon web agents suffer from diminishing returns when uniformly scaling test-time compute (e.g., sampling more candidates per step) due to error compounding and the prevalence of routine steps. This paper introduces CATTS (Confidence-Aware Test-Time Scaling), a framework that uses the distribution of sampled actions to estimate per-step uncertainty. CATTS dynamically invokes a more expensive arbiter LLM only for contentious decisions where the vote is dispersed; for steps with clear consensus, it uses a cheap majority vote. On WebArena-Lite and GoBrowse, CATTS significantly improves the accuracy-compute tradeoff, demonstrating that intelligent allocation of inference-time resources is more effective than blind scaling for complex, sequential web tasks.

## Method Summary
CATTS operates on a fixed base agent (ReAct-style) without any training. At each decision step, the agent samples *N* candidate actions. These actions are semantically deduplicated to prevent vote splitting among equivalent phrases. From the cleaned vote distribution, an uncertainty score (entropy or top-1/top-2 margin) is calculated. If this score exceeds a threshold *τ*, an arbiter LLM is queried to select the best action from the deduplicated set. Otherwise, the action with the most votes is chosen. The threshold *τ* is tuned on a validation set to balance success rate and token cost. The core innovation is replacing uniform scaling (always sampling *N* and/or always arbitrating) with a gated policy that concentrates expensive arbitration on steps with genuinely diffuse preferences.

## Key Results
*   On WebArena-Lite, CATTS achieves a 47.9% success rate with *N*=10, a 9.1% absolute improvement over the React baseline (38.8%), while consuming only 405K tokens—a 56% reduction versus a non-adaptive majority vote system.
*   CATTS uses up to 2.3× fewer total tokens than approaches that uniformly invoke an arbiter at every step, confirming the efficiency of dynamic gating.
*   Analysis reveals a bimodal distribution of step-level uncertainty: many steps are routine (high consensus), while a smaller set are contentious pivots. CATTS’s selective arbitration targets the latter, avoiding wasteful calls on the former.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Dynamically allocating test-time compute based on per-step uncertainty improves the accuracy–compute tradeoff for long-horizon web agents.
**Mechanism:** The system samples *N* candidate actions per step, clusters them semantically, and computes an uncertainty score (entropy *H* or margin Δ). If uncertainty exceeds a threshold *τ*, an arbiter LLM is invoked; otherwise, majority vote is used. This concentrates compute on steps with diffuse vote distributions where the correct decision is less obvious, based on the assumption that the vote distribution predicts downstream impact.
**Evidence anchors:** [abstract] states vote-derived uncertainty correlates with downstream success; [section 4.1] shows successful trajectories have lower entropy and higher margins; corpus notes CATTS uniquely uses vote signals without token probabilities.
**Break condition:** If the uncertainty metric is miscalibrated (e.g., high entropy on routine steps), the gate misallocates compute, either wasting it on easy steps or omitting arbitration on hard ones.

### Mechanism 2
**Claim:** LLM-based arbitration improves selection in contentious regimes but harms performance when applied to high-consensus steps.
**Mechanism:** The arbiter reasons over deduplicated candidates to break ties or discard implausible options. However, when candidates already show strong agreement (e.g., 9/10 agree), the arbiter may incorrectly override the consensus with a minority action.
**Evidence anchors:** [section 3.3] shows uniform arbiter scaling can degrade performance; [section 4.1] Figure 3 shows high-consensus override tasks have 35.0% vs. 46.9% success; [section 4.4] defines "Regime 1: Redundancy."
**Break condition:** If the arbiter is biased against majority actions or misled by surface features, override failures occur even in moderately uncertain steps, reducing gains.

### Mechanism 3
**Claim:** Long-horizon web agent steps naturally separate into redundant (high consensus) and contentious (genuine uncertainty) regimes; treating them differently yields better efficiency.
**Mechanism:** Vote distribution analysis reveals a bimodal entropy profile: many steps have near-perfect consensus (entropy ≈ 0), others have high entropy. Redundant steps are procedurally obvious (e.g., form filling) and suffer diminishing returns from more sampling. Contentious steps are trajectory pivots where diverse plausible actions compete; a single wrong choice causes irreversible error compounding.
**Evidence anchors:** [section 4.4] explicitly defines the two regimes; [appendix I] Figure 6 histograms show ~42% of steps have top-1 probability > 0.9; [section 1] notes error compounding.
**Break condition:** If categorization is noisy (e.g., a pivotal step appears high-consensus due to correlated sampling errors), CATTS may skip needed arbitration, causing failure.

## Architecture Onboarding
*   **Component map:**
    Base agent (ReAct) -> Semantic deduplicator -> Uncertainty calculator -> Gating logic -> [if uncertain] Arbiter model -> [else] Majority vote -> Environment executor -> next observation
*   **Critical path:** At each step *t*: (a) base agent samples *N* actions; (b) deduplicator clusters; (c) compute *H<sub>t</sub>*, Δ<sub>t</sub>; (d) if *U<sub>t</sub>* > *τ*, call arbiter, else take argmax *p<sub>t</sub>*; (e) execute action, get new observation.
*   **Design tradeoffs:**
    *   *N* vs. *K*: Larger *N* gives finer-grained vote distribution but increases base cost; *K* (arbiter calls) adds selection cost. CATTS reduces *K*, making larger *N* more affordable.
    *   Threshold *τ*: Lower *τ* means more arbitration (higher cost, potential overrides); higher *τ* saves tokens but risks missing contentious steps. Sweep results show robustness around *τ* ∈ [0.4, 0.7].
    *   Arbiter model choice: Paper uses same model as base; a stronger arbiter might improve contentious-step selection but increases per-call cost.
*   **Failure signatures:**
    *   **High-consensus override:** Arbiter selects minority action when vote has clear winner (Δ > 0.7), leading to failure.
    *   **Non-monotonic scaling:** Success rate drops when increasing *N* or *K* beyond optimal.
    *   **Poor uncertainty calibration:** High entropy on routine steps (e.g., due to sampling noise) triggers unnecessary arbitration, wasting tokens.
*   **First 3 experiments:**
    1.  Replicate static majority vote scaling: Run with *N* ∈ {1, 3, 5, 10, 20} on WebArena-Lite. Expect diminishing returns after *N*=5.
    2.  Test uniform arbiter scaling: Fix *N*=5, vary arbiter calls *K* ∈ {1, 5, 10, 20}. Record success and tokens; expect plateau or drop at high *K*.
    3.  Measure vote distribution statistics: From *N*=10 runs, compute per-step entropy *H<sub>t</sub>* and margin Δ<sub>t</sub>. Plot histograms to verify bimodality (~42% steps top-1 > 0.9, ~49% entropy > 0.6).

## Open Questions the Paper Calls Out
*   **OQ1:** Does the CATTS framework generalize to agentic tasks beyond web navigation, such as robotic control or tool-use in code environments? The paper's analysis is specific to web navigation environments; error compounding and uncertainty patterns may differ elsewhere.
*   **OQ2:** Are entropy and top-1/top-2 margin from candidate vote distributions the optimal or only effective uncertainty signals? Other signals (e.g., reasoning trace consistency, diversity of predicted states) could exist.
*   **OQ3:** What is the theoretical reason why vote-derived uncertainty correlates with downstream success, and can this be formalized? The correlation is empirical but not derived from first principles; a formal model connecting step entropy to trajectory-irrecoverable error is needed.
*   **OQ4:** Can the arbiter be improved to avoid overriding high-consensus decisions, and is this a capability or threshold problem? The arbiter is a fixed LLM; its override failures might stem from prompt design or biases. Could a better arbiter relax the gating threshold?
*   **OQ5:** How sensitive is CATTS to the choice of uncertainty threshold *τ*, and can a universal, model-agnostic threshold be derived? Optimal *τ* varies by *N* and benchmark; deployment often lacks validation data. An adaptive or meta-predicted *τ* would be more practical.

## Limitations
*   Exact model identities (`gpt-oss-120b`) and sampling hyperparameters (temperature, top-p) are unspecified, hindering exact replication.
*   Evaluation is limited to WebArena-Lite and GoBrowse; generalization to other agent domains (e.g., robotics, code) is unproven.
*   Performance is sensitive to the uncertainty threshold *τ* and semantic deduplication quality; miscalibration leads to misallocated compute.

## Confidence
*   **Claim 1** (dynamic gating based on vote uncertainty improves accuracy-compute tradeoff): **High**. Supported by consistent improvements (up to 9.1% absolute) and token reduction across two benchmarks; ablation shows regime separation.
*   **Claim 2** (arbiter benefits only contentious steps, harms high-consensus): **High**. Clear evidence from uniform scaling experiments and override analysis (Figure 3).
*   **Claim 3** (web steps naturally split into redundant vs contentious regimes): **Medium**. Histograms show bimodality, but pattern may be dataset-specific; needs validation on more diverse environments.
