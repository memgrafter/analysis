# Japanese AI Agent System on Human Papillomavirus Vaccination: System Design

## Quick Facts
- **arXiv ID:** 2601.10718
- **Source URL:** https://arxiv.org/abs/2601.10718
- **Reference Count:** 35
- **Primary Result:** A dual-purpose system combining a ReAct-agent RAG chatbot and an automated report generator achieved high scores (>4.8/5) for chatbot response quality and perfect reference validity for institutional reports in simulated evaluations.

## Executive Summary
This paper presents a system designed to combat HPV vaccine hesitancy in Japan through two integrated components: a public-facing chatbot that provides verified, cited answers to queries, and an automated report generator that analyzes trends for medical institutions. The chatbot utilizes a ReAct agent to dynamically retrieve and synthesize information from five heterogeneous knowledge sources (academic papers, official documents, news, social media, and chat history). The report system aggregates and interprets data from these sources to produce structured summaries. Evaluated on simulated data, both components demonstrated high performance in relevance, correctness, and completeness, suggesting a feasible architecture for delivering trustworthy health information and analyzing public discourse.

## Method Summary
The system architecture centers on a unified vector database (Qdrant) storing chunked documents from five sources, all embedded using a Japanese-optimized model (`pfnet/plamo-embedding-1b`). The chatbot employs a ReAct agent controller that iteratively reasons, selects appropriate retrieval tools, and synthesizes responses with inline citations. A separate citation validator ensures claims are supported. The report generator runs on a schedule, using specialized analyzers (e.g., LDA topic modeling, LLM-based stance classification) to process each source collection over a defined period. An orchestrator aggregates these analyses into a bilingual PDF report with visualizations. Evaluation used LLM-as-judge metrics on simulated conversations and temporal report samples.

## Key Results
- Chatbot single-turn evaluations averaged 4.80/5 for relevance, correctness, routing, reference quality, and professional identity; multi-turn scores improved to 4.98/5.
- Report generation consistently scored between 4.0 and 5.0/5 for completeness and correctness, with perfect (5.0) reference validity across all tested periods.
- The system successfully integrated heterogeneous data sources and demonstrated a functional bidirectional flow: public chatbot queries informed institutional trend reports.

## Why This Works (Mechanism)
### Mechanism 1: Iterative Multi-Tool Orchestration
- **Claim:** The ReAct agent's iterative multi-tool orchestration yields higher-quality, context-aware responses than static retrieval or single-tool approaches.
- **Mechanism:** A single controller agent dynamically selects and sequences calls to five specialized tools (papers, web, social media, news, chitchat) within a reasoning loop. It analyzes the query and conversation history, identifies information gaps, retrieves from the most relevant source(s), validates results, and decides if further retrieval is needed before synthesizing a cited response.
- **Core assumption:** Different query types require distinct knowledge sources, and combining evidence across these sources within a single turn/multi-turn context improves answer completeness and correctness.
- **Evidence anchors:** [abstract] "Retrieval-Augmented Generation chatbot using ReAct agent architecture with iterative multi-tool orchestration"; [section 2.3.1/Figure 2] details the controller's decision cycle.
- **Break condition:** If the controller's selection logic consistently misroutes queries (e.g., retrieving academic papers for procedural questions best answered by official documents), response quality degrades.

### Mechanism 2: Unified Vector Database for Heterogeneous Sources
- **Claim:** A unified vector database embedding heterogeneous document types enables consistent semantic search across the entire evidence landscape.
- **Mechanism:** All documents, despite originating from different source types (formal papers vs. casual tweets), are chunked and embedded into the same 2048-dimensional vector space. A single cosine similarity search retrieves relevant passages from any collection, allowing seamless context switching by the ReAct controller.
- **Core assumption:** A single embedding space can meaningfully represent semantic similarity between queries and documents ranging from peer-reviewed journals to fragmented social posts.
- **Evidence anchors:** [abstract] "a vector database integrating documents from..."; [section 2.2] describes the embedding and similarity search process.
- **Break condition:** If the embedding model is biased toward one source type's linguistic patterns (e.g., formal language), search performance for other types (e.g., colloquial social media) will suffer, causing missed information.

### Mechanism 3: Bidirectional Data Flow for Institutional Insights
- **Claim:** The bidirectional data flow—using chatbot interactions as input to institutional reports—creates a feedback loop where public concerns directly inform medical institution strategy.
- **Mechanism:** Anonymized user conversations are stored in a dedicated "chat" collection. The report generator's "Chat Analyzer" queries this collection to identify trending questions, knowledge gaps, and demographic patterns, synthesizing them with social media and news analysis in the executive summary.
- **Core assumption:** Aggregated, anonymized chat logs represent a valid, high-signal sample of the broader public's information needs, distinct from passive social media discourse.
- **Evidence anchors:** [abstract] "providing verified information... while providing institutional stakeholders with systematic public discourse analysis"; [section 2.4.3] lists Chat Analysis as a report component.
- **Break condition:** If chatbot users are not representative of the hesitant population (e.g., only tech-savvy individuals), the Chat Analysis will produce a skewed view, leading to misallocated institutional resources.

## Foundational Learning
- **Concept: Retrieval-Augmented Generation (RAG)**
  - *Why needed:* Grounds LLM responses in specific, verifiable documents to maintain medical credibility and avoid hallucinations.
  - *Quick check:* What is the risk of a pure generative chatbot (no retrieval) in a medical context like HPV vaccination?

- **Concept: ReAct Agent (Reasoning + Acting)**
  - *Why needed:* Dynamically choosing from five different knowledge sources per query requires explicit reasoning about *which* tool to use *when*. ReAct provides the "think-act-observe" framework for this.
  - *Quick check:* Why can't a simple router (one-step classification) replace the iterative ReAct loop for this multi-source problem?

- **Concept: Topic Modeling & Stance Classification for Social Media**
  - *Why needed:* The report's "Social Media Analysis" module must transform millions of raw posts into digestible trends (topics) and sentiment summaries (stance) for institutions.
  - *Quick check:* How does LDA-based topic modeling differ from an LLM summarizing "what people are talking about"? What are the trade-offs?

## Architecture Onboarding
- **Component map:** Data Sources (PubMed, MHLW, News APIs, Twitter) -> Ingestion & Vector DB (Scalable collection -> preprocessing -> embedding -> storage in Qdrant collections) -> Chatbot Interface (Streamlit UI -> ReAct Controller -> 5 Tool Wrappers -> Citation Validator -> Response) & Report Generator (Orchestrator -> 4 Analyzers -> LLM analysis -> structured data -> PDF assembly). Shared resource: Unified Vector Database.
- **Critical path (Chatbot):** User query -> Controller reasoning (with history) -> Tool selection -> Vector search in relevant collection(s) -> Result observation -> Synthesis decision -> LLM generation with citations -> Citation validator -> Final response.
- **Critical path (Report):** Scheduled trigger -> Orchestrator calls each Analyzer (query specific collection for time window) -> LLM analysis (e.g., LDA, stance classification) -> Visualization gen -> Orchestrator aggregates -> LLM writes executive summary -> PDF render.
- **Design tradeoffs:** Single Controller vs. Specialized Agents (efficiency vs. routing errors); Citation Transparency vs. Response Fluency (trust vs. smoothness); Report Detail vs. Actionability (comprehensiveness vs. clarity).
- **Failure signatures:** Chatbot: Repetitive use of `chitchat` tool for factual queries; responses with `[citation missing]`; loss of user context in multi-turn. Reports: "Completeness" score <4.0 for a section; "Citation Correctness" <4.0; flat sentiment/stance graphs.
- **First 3 experiments:**
  1.  **Tool Selection Sanity Check:** Run 50 known-domain queries (e.g., "MHLW's latest guidelines" -> `web` tool). Goal: >90% correct single-tool routing for unambiguous queries.
  2.  **Citation Chain Validation:** For 50 random chatbot responses, trace each citation to its source chunk in Qdrant. Manually verify 20 for true support. Goal: 100% reference validity.
  3.  **Temporal Report Consistency:** Generate reports for three adjacent 30-day periods. Compare topic distributions and sentiment trends. Flag abrupt, unexplained swings (>20% change) as potential instability.

## Open Questions the Paper Calls Out
- **Open Question 1:** How does exclusive reliance on Twitter/X Japanese social media data affect capturing the full spectrum of public sentiment, especially among underrepresented groups like the elderly?
  - *Basis:* Explicitly notes Twitter/X data may underrepresent elderly and digitally limited populations.
  - *Why unresolved:* Potential systematic sampling bias skews sentiment analysis and topic modeling, impacting report validity.
  - *Resolving evidence:* Comparative study across multiple platforms (LINE, Facebook, forums) with demographic surveys to quantify representation gaps and measure performance against a stratified gold-standard sample.

- **Open Question 2:** Does LLM-based automated evaluation reliably correlate with human expert judgment across all dimensions, especially nuanced ones like "routing" or "helpfulness"?
  - *Basis:* Acknowledges LLM evaluation may differ from human judgment; validation showed larger discrepancies for routing (diff=0.55).
  - *Why unresolved:* Validation was on a small, volunteer dataset; unclear if it holds for real-user interactions, diverse queries, or different LLM judges.
  - *Resolving evidence:* Large-scale, multi-round evaluation by a diverse human expert panel (clinicians, communicators) on a broad real-world sample, compared against varied LLM-as-judge configurations to identify susceptibility by dimension and query type.

- **Open Question 3:** What is the actual impact of the system's bidirectional design on measurable public health outcomes, such as HPV vaccine uptake or reduced misinformation belief?
  - *Basis:* States prospective deployment with real users is needed to evaluate health outcomes; current evaluation is on simulated data and content quality.
  - *Why unresolved:* The core hypothesis that this architecture influences behavior is unproven. It is unknown if transparent AI communication and feedback loops improve rates/attitudes versus static sources.
  - *Resolving evidence:* Longitudinal, controlled field trial (cluster-randomized) in Japanese regions. Intervention group uses live system; controls use standard websites/FAQs. Primary outcomes: vaccination rate changes (registry data) and validated survey measures of vaccine confidence/misinfo over 12-24 months.

- **Open Question 4:** How does inline citation and source attribution in chatbot responses affect user trust, perceived credibility, and information retention compared to non-cited LLM responses?
  - *Basis:* Proposes A/B testing to assess if citation transparency affects user trust; this effect is an unstated assumption.
  - *Why unresolved:* Causal effect of this specific feature is untested; citations could increase trust or overwhelm/confuse users.
  - *Resolving evidence:* Controlled user study where participants interact with cited vs. non-cited chatbot versions on identical queries. Post-interaction surveys measure trust (validated scales), credibility, and recall. Optional: eye-tracking to assess engagement with citations.

- **Open Question 5:** To what extent is the system's architecture and performance transferable to other multilingual public health contexts with different languages, regulatory frameworks, and vaccine types?
  - *Basis:* Claims the framework is transferable and suggests cross-lingual expansion and comparative studies across vaccine types.
  - *Why unresolved:* System is deeply integrated with Japanese-language processing, Japanese government sources, and the specific HPV context in Japan. Many components (embedding model, scrapers, stance classifier) are Japan-specific; ReAct logic and report templates may need re-engineering.
  - *Resolving evidence:* Implement and fully evaluate replication for a different vaccine (e.g., MMR in a European country) in its local language. Success = comparable evaluation scores + qualitative assessment of required architectural modifications, identifying modular vs. context-bound components.

## Limitations
- Evaluation relies on **simulated conversations and LLM-as-judge metrics**, not real user outcomes (e.g., actual vaccine intent change).
- **LLM backend, prompts, and evaluation rubrics are unspecified**, preventing exact score replication and obscuring performance drivers.
- **Social media/data collection methodology lacks detail** (e.g., Twitter API filters, time windows), affecting reproducibility of the public discourse analysis component.
- The **chat user sample may not represent** the hesitant population, risking biased "Chat Analysis" insights for institutions.

## Confidence
- **ReAct multi-tool orchestration improves response quality:** Medium. Strong internal metrics, but no external corpus support; performance depends heavily on the unstated LLM's reasoning ability.
- **Unified vector DB for heterogeneous sources works:** Medium. Plausible given modern embeddings, but embedding bias across formal/colloquial Japanese is a critical unvalidated risk.
- **Bidirectional feedback loop is valid and useful:** Low. The "representative chat sample" core assumption is untested and likely flawed due to self-selection bias.
- **Report generation produces complete, correct, and helpful summaries:** Medium-High. Consistent scores (4.0-5.0) and perfect reference validity are strong, but based on simulated/temporal data without human expert validation on completeness/helpfulness.
