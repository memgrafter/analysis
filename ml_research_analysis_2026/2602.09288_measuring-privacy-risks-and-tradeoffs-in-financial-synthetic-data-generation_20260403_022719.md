# Measuring Privacy Risks and Tradeoffs in Financial Synthetic Data Generation

## Quick Facts
- arXiv ID: 2602.09288
- Source URL: https://arxiv.org/abs/2602.09288
- Reference count: 40
- Primary result: DP-CTGAN maintains reasonable downstream utility and class balance across privacy budgets (ϵ=1,5,10), while DP-TVAE suffers from severe mode collapse, especially under strong privacy.

## Executive Summary
The paper examines the privacy‑utility tradeoff in synthetic financial tabular data generation, a domain characterized by severe class imbalance and mixed data types. The authors introduce differentially private (DP) extensions of CTGAN and TVAE by eliminating privacy leak sites, using DP‑Adam, and enforcing per‑sample gradient isolation. Experiments across multiple financial datasets reveal that DP‑CTGAN retains balanced accuracy and class distribution across privacy budgets (ϵ=1,5,10), whereas DP‑TVAE collapses dramatically under strong privacy. Standard privacy metrics (DCR) prove highly dataset‑dependent and weakly correlated with ϵ, and membership inference attacks yield near‑random success rates for most generators, casting doubt on their effectiveness. Finally, downsampling to balance classes benefits weaker generators (e.g., Gaussian Copula) but yields mixed outcomes for stronger models.

## Method Summary
DP‑CTGAN and DP‑TVAE modify the original CTGAN and TVAE to provide formal differential privacy. Key changes include: replacing conditional vector generation with Poisson sampling of real records, computing the WGAN gradient penalty per real‑synthetic pair instead of globally, and training the discriminator with DP‑Adam (per‑sample clipping + Gaussian noise). The generator remains non‑DP but inherits privacy via post‑processing. Evaluation uses TabDiff for column‑wise and pairwise distribution fidelity, XGBoost balanced accuracy for downstream utility, and both DCR and membership inference attacks for privacy. The study varies privacy budgets (ϵ∈{1,5,10}) and assesses the impact of class balancing via downsampling the majority class.

## Key Results
- DP‑CTGAN preserves balanced accuracy and class balance across ϵ=1,5,10, while DP‑TVAE suffers severe mode collapse under strong privacy.
- DCR metrics are dataset‑dependent and do not correlate with ϵ; membership inference attack success rates remain near random (~0.5) for most generators, questioning their reliability for financial data.
- Downsampling to address class imbalance improves utility for weak generators (e.g., Gaussian Copula) but has mixed effects on stronger models.

## Why This Works (Mechanism)
**Differential Privacy in CTGAN.** Original CTGAN leaks privacy via (a) conditional vectors derived from aggregate statistics, (b) mixing real sample gradients in the WGAN penalty, and (c) non‑private Adam updates. DP‑CTGAN patches these by: (1) deriving conditional vectors from Poisson‑sampled real records; (2) computing the gradient penalty per real‑synthetic pair and accumulating for per‑sample clipping; (3) training the discriminator with DP‑Adam, adding Gaussian noise post‑clipping. The generator, trained only on discriminator outputs, inherits DP via post‑processing, yielding an (ϵ,δ)‑DP guarantee if per‑sample isolation is preserved and preprocessing uses only non‑private metadata ranges. Evidence: Section 4.1.2 details replacements; break condition: gradient mixing before clipping or non‑private conditional statistics invalidates DP.

**Class Balancing and Utility.** Extreme class imbalance in financial data causes mode collapse in autoencoder‑based generators (TVAE) and oversampling in GANs (CTGAN). Downsampling the majority class rebalances training data. This helps generators with limited capacity to model the minority class (e.g., Gaussian Copula) by forcing equal focus, yielding large utility gains (+47.5% balanced accuracy on AD). However, models already capturing complex patterns (TabDiff) lose representation power from reduced majority samples, so utility changes little. Evidence: Section 6.5 shows quantitative improvements for weak generators; break condition: if minority prevalence is extremely low (<0.5%), downsampling may remove too many majority samples, harming even weak models.

**Limitations of DCR Metrics.** DCR measures distances among synthetic, real, and random datasets. These distances are dominated by dataset‑specific properties (e.g., cluster density, feature ranges) rather than privacy loss. For instance, the dense GM dataset yields low DCR irrespective of generator or ϵ, while sparse CR gives high scores, obscuring any DP effect. Thus, DCR does not consistently correlate with ϵ and cannot reliably compare privacy across financial datasets. Evidence: Tables 6 and 7 show >10× variability across datasets for the same generator; break condition: DCR might correlate with ϵ only in uniform, low‑dimensional data, not typical financial data.

## Architecture Onboarding
**Component map**  
Data -> Pre‑processing (uniform binning) -> Conditional vector sampler -> Generator -> Synthetic samples; Real samples + Synthetic samples -> Discriminator -> Gradient penalty calculator -> Per‑sample clipping -> DP‑Adam -> Discriminator update; Generator updates via discriminator output (non‑DP). Synthetic dataset -> Downstream evaluator (XGBoost classifier, MIA discriminator).

**Critical path**  
Data → Pre‑process → (Sample conditions → Generate synthetic → Select paired real → Compute D loss/grad‑penalty → Clip+noise → Update D) × epochs → Generate synthetic dataset → Evaluate (quality, utility, privacy).

**Design tradeoffs**  
- Privacy vs. Utility: Lower ϵ adds more noise, degrading quality and utility, but may improve class balance.  
- Per‑sample penalty vs. stability: Redesigning the gradient penalty for per‑sample isolation maintains WGAN‑GP stability without privacy leaks but alters training dynamics.  
- Balancing classes: Downsampling helps weak generators but can distort the true distribution and harm strong models.

**Failure signatures**  
- Mode collapse: Extreme minority class underrepresentation (<1%) in DP‑TVAE outputs, sometimes yielding all‑synthetic‑class datasets.  
- Privacy metric anomaly: DCR scores varying >10× across datasets for the same generator, with weak or no monotonic trend as ϵ changes.  
- MIA stagnation: Success rates stuck near 0.5 across all generators and ϵ, indicating attack failure or genuine privacy.

**First 3 experiments**  
1. Sanity check DP implementation: Train DP‑CTGAN on a small balanced dataset (e.g., CR) with ϵ=∞ and ϵ=1. Verify column shapes/utility drop slightly but MIA remains ∼0.5. If MIA spikes >0.55, check per‑sample clipping and Poisson sampling.  
2. Privacy‑utility curve: For BM, train DP‑CTGAN at ϵ∈{1,5,10,∞}. Plot balanced accuracy vs. ϵ; expect smooth degradation. A sharp drop suggests implementation errors (e.g., incorrect noise scale).  
3. Class balance ablation: Train Gaussian Copula on original vs. downsampled (50/50) data for GM. Expect substantial utility gain from downsampling. If none, inspect minority class percentage in synthetic output (should be ~50% if balanced).

## Limitations
- The formal DP guarantee for DP‑CTGAN relies on correct per‑sample gradient isolation and DP‑Adam; a subtle bug could invalidate the (ϵ,δ)‑DP claim.
- The benefit of downsampling for weak generators is shown on a few datasets; its effectiveness for extremely rare minorities (<0.5%) or other financial domains remains uncertain.
- Near‑random MIA results for non‑DP generators are unexpected and unexplained, possibly reflecting fundamental MIA limitations for financial tabular data or evaluation flaws.

## Confidence
- DP‑CTGAN achieves a formal (ϵ,δ)‑DP guarantee: Medium confidence (implementation complexity raises trust concerns).
- Class balancing improves utility for weak generators: Medium confidence (evidence limited to selected datasets).
- Membership inference attack reliability for financial synthetic data: Low confidence (explanation for random rates missing).

## Next Checks
1. DP Accounting Audit: Replicate DP‑CTGAN training on one dataset (BM) with ϵ=1. Independently compute privacy loss using a privacy accountant (e.g., Opacus) on observed gradient norms and noise scale; confirm empirical ϵ matches the reported value.
2. Minority Class Scarcity Stress Test: For a dataset with minority class <0.5%, evaluate a weak generator (Gaussian Copula) with and without downsampling. Determine whether downsampling still improves balanced accuracy or data loss dominates.
3. MIA Controlled Baseline: Run the MIA attack on real training data versus held‑out real data for the same target model (XGBoost). If the attack succeeds (AUC > 0.6) on real data but fails on synthetic data, the MIA setup is valid; if it fails on both, the attack is flawed.
