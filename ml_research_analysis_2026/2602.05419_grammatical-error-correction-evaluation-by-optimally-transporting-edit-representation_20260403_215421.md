# Grammatical Error Correction Evaluation by Optimally Transporting Edit Representation

## Quick Facts
- **arXiv ID**: 2602.05419
- **Source URL**: https://arxiv.org/abs/2602.05419
- **Reference Count**: 30
- **Primary Result**: UOT-ERRANT achieves state-of-the-art edit-level correlations on SEEDA meta-evaluation (Pearson up to .950, Spearman up to .979), significantly outperforming prior metrics like ERRANT, PT-ERRANT, and CLEME.

## Executive Summary
Existing GEC evaluation metrics, such as ERRANT, suffer from a dominance of unchanged tokens, which dilutes the signal for meaningful edits. This paper introduces UOT-ERRANT, a novel metric that evaluates corrections by transporting *edit vectors*—representations of individual edits' semantic impact derived from contextual sentence embeddings. Using unbalanced optimal transport (UOT), the metric softly aligns these vectors between a system hypothesis and a reference, naturally handling over- and under-correction. The transport plan decomposes into precision, recall, and F0.5, providing an interpretable and highly correlated assessment with human judgments, especially in high-edit domains.

## Method Summary
Given a source sentence, a system hypothesis, and a reference, UOT-ERRANT first extracts atomic edits (spans and corrections) using ERRANT. For each edit, it computes an *edit vector*: the difference between the sentence embedding of the fully corrected sentence and the embedding of that sentence with the single edit reverted. This vector captures the edit's contextual semantic contribution. Hypothesis and reference edits become discrete distributions where mass equals the L2 norm of each edit vector. UOT solves for a soft alignment plan between these distributions using Euclidean distance as the cost matrix, with unbalanced constraints (λ₁=λ₂=0.1) allowing untransported mass. True Positives are the transported mass; False Positives and False Negatives are the leftover hypothesis and reference masses, respectively. Precision, recall, and F0.5 are then computed. For multiple references, the best F0.5 is selected.

## Key Results
- On SEEDA meta-evaluation, UOT-ERRANT achieves the highest system-level Pearson and Spearman correlations for edit-level metrics, notably .950/.979 on the Base setting.
- It shows particularly large gains in high-edit domains (+Fluency), with correlations of .705/.851, outperforming strong baselines like PT-ERRANT and CLEME by a significant margin.
- The metric provides interpretable soft alignments between edits, improving pairwise system agreement (e.g., for GPT-3.5) and demonstrating robustness to over-correction.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: The edit vector captures the semantic impact of an individual edit by measuring the change in the sentence embedding when that edit is removed, while keeping other edits contextually present.
- **Mechanism**: For an edit \(e\) in the set \(E\) extracted from the source sentence \(S\), compute the corrected sentence \(S^E\) (all edits applied) and its corrupted variant \(S^{E\setminus\{e\}}\) (all edits except \(e\)). The edit vector is \(V(e) = \text{Enc}(S^E) - \text{Enc}(S^{E\setminus\{e\}})\), where \(\text{Enc}\) is a sentence encoder (e.g., ELECTRA mean pooling). This isolates the contribution of \(e\) in the context of other corrections.
- **Assumption**: The encoder produces sufficiently sensitive representations such that removing a meaningful edit changes the embedding in a direction proportional to its semantic effect.
- **Evidence anchors**: 
  - [abstract] "propose edit vector, a representation for an edit, and introduce a new metric, UOT-ERRANT, which transports these edit vectors... edit vectors are derived from differences in sentence embeddings when individual edits are removed."
  - [section 3.1] Equation (1) and surrounding text define the edit vector and its context.
- **Break condition**: If the encoder’s representations are insufficiently sensitive to single-edit changes, the edit vectors may become noisy and degrade transport alignment.

### Mechanism 2
- **Claim**: Unbalanced Optimal Transport (UOT) provides a soft alignment between hypothesis and reference edit vectors, naturally handling over-correction and under-correction without forcing one-to-one matching.
- **Mechanism**: Hypothesis edit vectors are treated as discrete distributions with masses equal to their L2 norms; reference edit vectors similarly. The cost matrix uses Euclidean distance between vectors. UOT (Equation 4) with entropy regularization (\(\epsilon = 0.1\)) and symmetric KL penalties (\(\lambda_1 = \lambda_2 = 0.1\)) yields a transport plan \(T\) where entry \(T_{ij}\) quantifies how much hypothesis edit \(i\) aligns with reference edit \(j\). The relaxation allows some mass to remain untransported, modeling extra or missing edits.
- **Assumption**: Similar semantic edits yield similar edit vectors, so Euclidean distance reflects edit similarity; the UOT penalty parameters appropriately balance strictness and flexibility for GEC.
- **Evidence anchors**:
  - [abstract] "transports these edit vectors from hypothesis to reference using unbalanced optimal transport... The transport plan decomposes into precision, recall, and F0.5."
  - [section 3.2] Details of UOT and its motivation for GEC.
- **Break condition**: If edit vectors are not discriminative, the Euclidean cost may fail to distinguish correct from incorrect edits, leading to over-optimistic transport.

### Mechanism 3
- **Claim**: Decomposing the UOT plan into true positive (TP), false positive (FP), and false negative (FN) components yields precision, recall, and F0.5 scores that align with standard GEC evaluation while leveraging the soft alignment.
- **Mechanism**: TP = \(\sum_{i,j} T_{ij}\) (transported mass). FP = total hypothesis mass (sum of norms) minus TP. FN = total reference mass minus TP. Precision = TP/(TP+FP), Recall = TP/(TP+FN), F0.5 = \((1+0.5^2) \times\) precision \(\times\) recall / \((0.5^2\) precision + recall).
- **Assumption**: The norm of an edit vector appropriately weights the edit’s importance; transported mass directly corresponds to correct edit matches.
- **Evidence anchors**:
  - [abstract] "The transport plan decomposes into precision, recall, and F0.5."
  - [section 3.3] Provides Equations (7)-(12) and the decomposition logic.

## Foundational Learning
- **Concept**: Unbalanced Optimal Transport (UOT)
  - *Why needed*: UOT-ERRANT's core alignment mechanism relies on solving an OT problem with relaxed marginal constraints to handle missing and extra edits. Understanding the Kantorovich formulation, Sinkhorn algorithm, and the effect of λ parameters is essential.
  - *Quick check*: "What is the key difference between balanced and unbalanced OT, and why does unbalanced OT better model edit matching in GEC?"
- **Concept**: ERRANT-style Edit Extraction
  - *Why needed*: The metric operates on atomic edits (spans and corrections) identified by tools like ERRANT; knowing how edits are defined ensures correct input pipeline.
  - *Quick check*: "How does ERRANT perform automatic alignment and edit categorization between a source and corrected sentence?"
- **Concept**: Contextualized Sentence Embeddings (e.g., ELECTRA, BERT)
  - *Why needed*: Edit vectors are computed from sentence embeddings; familiarity with mean pooling, the [CLS] token, and the semantic properties of these models is necessary.
  - *Quick check*: "Why might mean pooling of ELECTRA discriminators be preferred over a static embedding for capturing edit impact?"
- **Concept**: Grammatical Error Correction (GEC) Evaluation
  - *Why needed*: To understand the limitations of token-based metrics (e.g., M², GLEU) and the motivation for edit-level evaluation.
  - *Quick check*: "Why do unchanged tokens dominate traditional similarity measures, and how does focusing on edits address this?"

## Architecture Onboarding
1. **Edit Extractor** -> 2. **Edit Vectorizer** -> 3. **UOT Solver** -> 4. **Score Aggregator**

**Critical path**:
1. Ensure consistent edit extraction (same source sentence, same ERRANT version).
2. Vectorization must correctly apply all other edits when removing a single one; off-by-one errors in span indices lead to incorrect vectors.
3. UOT parameter selection: default λ=0.1 works on SEEDA but may need re-tuning for new domains (use GJG15 style dev set).

**Design tradeoffs**:
- *Removing vs. adding edits*: Removing yields context-aware vectors but requires full-edited sentence; adding is cheaper but less accurate.
- *Mass weighting*: L2 norm (default) vs. uniform; L2 improves correlation but biases toward content-word edits.
- *Cost metric*: Euclidean vs. cosine; Euclidean includes vector length, which matters for semantically large edits.
- *Encoder choice*: ELECTRA-base default; RoBERTa-base gave lower correlation in +Fluency; LaBSE improved +Fluency but hurt Base.

**Failure signatures**:
- In low-edit domains (e.g., GMEG-Data), performance may drop because edit vectors for punctuation (small norms) dominate.
- Computational cost scales with total number of edits; systems like GPT-3.5 with many edits increase runtime linearly.
- If reference set is very small or non-matching, the soft alignment may overcredit hypothesis edits that are semantically close but surface-different.

**First 3 experiments**:
1. Run ERRANT on a known CoNLL-2014 system output and verify the edit list matches expected spans.
2. Compute norms for a diverse set of edits (e.g., verb tense vs. punctuation) and confirm content-word edits have larger norms.
3. Construct a tiny synthetic example with 2 hypothesis and 2 reference edits and ensure TP+FP+FN equals the sum of masses and that the transport plan satisfies UOT constraints.

## Open Questions the Paper Calls Out
- **Open Question 1**: What encoder model properties (architecture, pre-training objectives) yield edit vectors that best align with human-perceived edit impact across GEC domains? The paper only experiments with three encoders and finds domain-dependent performance, but does not systematically vary encoder properties.
- **Open Question 2**: Can the edit vector framework be effectively transferred to other text modification tasks (e.g., text simplification, ASR error correction) without task-specific redesign? The methodology is validated only on GEC; other tasks have different edit characteristics.
- **Open Question 3**: Does the norm-based weighting of edits in UOT-ERRANT encode social biases (e.g., against certain demographics) through correlations between edit norms and protected attributes? The paper raises this risk in Appendix B but does not investigate it.
- **Open Question 4**: Why does UOT-ERRANT's correlation drop significantly on low-edit domains like GMEG-Data, and can the metric be made robust across error density spectrums? The paper speculates it is due to high punctuation edit proportion but does not rigorously test this.

## Limitations
- **Reference dependency**: SEEDA lacks provided references; users must gather and align external corpora (CoNLL-2014, etc.), risking misalignment.
- **Edit application ambiguity**: Details on applying/reverting multiple edits (especially overlapping spans) are underspecified; off-by-one tokenization errors are likely.
- **Encoder robustness**: Edit vectors rely on ELECTRA-base sensitivity; domain shifts (e.g., GMEG-Data) may yield noisy vectors, as performance drop suggests.

## Confidence
- **Edit vector representation (Mechanism 1)**: Medium. Clear formulation but encoder sensitivity not extensively validated.
- **UOT alignment (Mechanism 2)**: High. Standard method with tuned hyperparameters; theoretically sound.
- **Score decomposition (Mechanism 3)**: High. Directly derived from transport plan; consistent with GEC metrics.
