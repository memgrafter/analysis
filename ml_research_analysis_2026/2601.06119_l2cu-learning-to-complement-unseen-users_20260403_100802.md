# L2CU: Learning to Complement Unseen Users

## Quick Facts
- **arXiv ID:** 2601.06119  
- **Source URL:** https://arxiv.org/abs/2601.06119  
- **Reference count:** 40  
- **Primary result:** L2CU achieves state-of-the-art post-alteration accuracy (e.g., 0.989 on CIFAR-10N, 0.993 on CIFAR-10H) while maintaining high positive alteration rates (correcting errors) and low negative alteration rates (harming correct labels), demonstrating effective generalization to unseen users across image and text domains without access to ground truth labels.

## Executive Summary
L2CU addresses the Learning to Complement (L2C) challenge for unseen users in human-AI cooperative classification. Existing methods fail because they rely on a single global user model and cannot handle sparse, noisy annotations from diverse annotators. L2CU introduces a framework that first identifies distinct annotator profiles by clustering users based on their noisy labeling patterns. For each profile, it augments sparse training data using a profile-specific label transition matrix and trains a dedicated AI cooperative model. At test time, an unseen user is profiled via a one-vs-all SVM classifier, and an entry condition ensures the model is only used if it outperforms the user on a clean validation set. Evaluated on multiple datasets, L2CU consistently outperforms state-of-the-art L2D and L2C methods, yielding high complementarity with robust alteration rates.

## Method Summary
L2CU operates in three phases. First, **profile identification**: for each annotator with sufficient labels, a fixed-length label vector is constructed by concatenating noisy labels per class. These vectors are clustered using Fuzzy K-Means, with the optimal number of profiles \(K\) selected via silhouette score. Second, **per-profile model training**: for each profile \(k\), a label transition matrix \(T^k\) is estimated from the noisy/consensus label pairs of its members. This matrix is used to augment the profile’s sparse training data, generating additional noisy labels. A cooperative model \(m^θ_k(x, \hat{y}) = d^ζ(f^ψ(x) ⊕ h^ϕ(\hat{y}))\) is then trained on the augmented data, combining a base model’s prediction with an encoding of the user’s label, using a loss that includes a forward-correction term aligned with \(T^k\). Third, **test-time inference**: an unseen user’s label vector on a clean validation set is classified by a one-vs-all SVM (trained on training users) to assign a profile. If the base model \(f^ψ_k\) outperforms the user on the validation set (entry condition), \(m^θ_k\) is deployed to alter the user’s labels on test samples; otherwise, the user’s raw labels are used.

## Key Results
- L2CU achieves superior post-alteration accuracy: 0.989 on CIFAR-10N, 0.993 on CIFAR-10H, and competitive results on Fashion-MNIST-H, Chaoyang, and AgNews.
- It consistently yields high positive alteration rates (\(A^+\)) and low negative alteration rates (\(A^-\)), effectively correcting user errors without harming correct labels.
- The framework generalizes across image and text domains and operates without ground truth labels during training.

## Why This Works (Mechanism)

### Mechanism 1: Clustering Annotators into Profiles
- **Claim:** Clustering annotators into profiles captures distinct, consistent labeling error patterns that generalize to unseen users.
- **Mechanism:** Fuzzy K-Means clusters fixed-length label vectors (Eq. 1), where each vector encodes an annotator’s noisy labels across all classes. The optimal cluster count \(K\) is selected via silhouette score.
- **Core assumption:** Annotators with similar confusion matrices (systematic mislabeling between specific class pairs) have similar label vectors, allowing clustering to isolate meaningful, reusable error patterns.
- **Evidence anchors:** Abstract and Section III.B.1 detail the label vector construction and clustering. Weak indirect support from neighboring multi-expert modeling work.
- **Break condition:** If silhouette scores are low or negative across all tested \(K\), indicating no stable cluster structure, profile identification fails.

### Mechanism 2: Profile-Specific Noisy Label Augmentation
- **Claim:** Augmenting sparse training data with samples generated from the profile’s transition matrix mitigates data sparsity while preserving characteristic noise patterns.
- **Mechanism:** For profile \(k\), a label transition matrix \(T^k\) (Eq. 2) is estimated from members’ noisy labels. This matrix is sampled to generate \(G\) additional noisy labels per training sample, creating augmented dataset \(\hat{D}^k\).
- **Core assumption:** The estimated \(T^k\) accurately represents the conditional noise distribution \(P(\tilde{Y}=n|\bar{Y}=c,R=k)\), and sampling generates plausible, pattern-consistent labels.
- **Evidence anchors:** Section III.B.2 and Section V-E (visualizations of estimated noise matrices). Ablation 2 shows a significant accuracy jump from \(G=0\) to \(G=1\).
- **Break condition:** If \(T^k\) is highly inaccurate (e.g., due to insufficient labels per class), augmented data misrepresents the profile’s noise pattern and harms learning.

### Mechanism 3: Profile-Specific Cooperative Model Fusion
- **Claim:** The cooperative model learns to fuse the base model’s prediction with the specific noisy pattern of its assigned profile via a learned joint distribution, enabling complementarity.
- **Mechanism:** Model \(m^θ_k(x, \hat{y}) = d^ζ(f^ψ(x) ⊕ h^ϕ(\hat{y}))\) concatenates base model logits and an encoding of the user’s label. A decision network \(d^ζ_k\) predicts the final class, trained with a loss including a forward-correction term (Eq. 4) that aligns predictions with \(T^k\).
- **Core assumption:** Combining the base model’s clean signal with a learned representation of the human’s systematic error allows \(d^ζ_k\) to disambiguate and correct errors more effectively than either alone.
- **Evidence anchors:** Section III.B.3 defines the model and loss. Ablation 1 shows performance drops significantly when either \(h^ϕ\) or \(d^ζ\) is removed. Section V.F (Table 5) shows correct decisions even when both human and base model are wrong.
- **Break condition:** If the base model’s predictions are uninformative or the human label encoder \(h^ϕ_k\) cannot compress the noise pattern usefully, fusion fails to improve over the base model.

## Foundational Learning
- **Concept:** Multi-Rater Learning & Sparse Annotation  
  *Why needed:* L2CU’s training data consists of sparse, noisy labels where each annotator labels only a subset. The entire pipeline—from profile identification to augmentation—depends on handling this sparsity and multiple noise sources.  
  *Quick check:* How would the label vector \(s_j\) (Eq. 1) change if every annotator labeled every sample? What would be the implication for profile clustering?

- **Concept:** Label Transition Matrix (Noise Modeling)  
  *Why needed:* The profile-specific transition matrix \(T^k\) is the core artifact that quantifies and preserves each profile’s systematic mislabeling behavior, used for both data augmentation and the forward-correction loss.  
  *Quick check:* In the loss term of Eq. 4, what is the purpose of applying \((T^k)^⊤\) to the model’s prediction? How does this relate to “forward correction” in learning with noisy labels?

- **Concept:** Human-AI Complementarity vs. Deferral (L2C vs. L2D)  
  *Why needed:* L2CU is an L2C method that aims for synergistic partnership where AI intervenes to correct human errors, shaping the model architecture (fusing human label \(\hat{y}\)) and evaluation metrics (alteration rates).  
  *Quick check:* Why is the entry condition (comparing base model vs. user accuracy on validation set) more critical for an L2C system than for a typical L2D system?

## Architecture Onboarding
- **Component map:**  
  Sparse Multi-Rater Data → Profile Identification (Fuzzy K-Means) → Per-Profile Augmentation (T^k) & Model Training → SVM Profiling Training → Test-Time: User Label Vector → SVM Profile Prediction → Entry Condition Check → Cooperative Inference (use \(m^θ_k\) or user label)

- **Critical path:**  
  1. Profile Identification (Sec. III.B.1)  
  2. Augmentation & Model Training per profile (Sec. III.B.2, III.B.3)  
  3. SVM Profiling Training (Sec. III.C)  
  4. Test-Time Profiling & Entry Condition  
  5. Cooperative Inference

- **Design tradeoffs:**  
  - \(K\) vs. Generalization: Larger \(K\) increases specificity but reduces training data per profile, risking over-adaptation.  
  - Augmentation \(G\) vs. Distortion: More samples improve sufficiency but risk drifting if \(T^k\) is poorly estimated.  
  - Hard vs. Soft Profile Assignment: Hard assignment (top SVM profile) outperforms soft blending.  
  - Entry Condition Strictness: Rejecting users when base model is not better prevents degradation but reduces coverage.

- **Failure signatures:**  
  - Low silhouette score (<0.1) for all \(K\): Profile clustering failed; annotator noise patterns not distinguishable.  
  - High \(A^-\) (negative alteration rate): Selected profile’s model harms correct user labels; check entry condition or SVM accuracy.  
  - SVM profiling error (Ablation 7): Mismatched profiles lead to many non-engaging (NI) users; profile features may be insufficient.  
  - Poor performance on high-noise-rate datasets (e.g., 90% noise): Transition matrix estimation and forward-correction become unreliable.

- **First 3 experiments:**  
  1. **Profile Validation & Visualization:** Run profile identification on a simulated dataset with known noise patterns. Visualize estimated \(T^k\) matrices (like Fig. 4) to confirm recovery of injected noise between class pairs.  
  2. **Augmentation Necessity Test:** Train models for a given profile with \(G=0\) vs. \(G=1\). Measure post-alteration accuracy on a held-out set from that profile; expect significant jump with \(G≥1\).  
  3. **Entry Condition Sanity Check:** On a validation set \(V\) for a test user, plot base model’s accuracy vs. user accuracy across samples. Entry condition should trigger only when base model’s accuracy is consistently higher.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can L2CU be extended to handle users drawn from a *distribution-agnostic* setting, where test users may come from a different distribution than training users?  
  *Basis:* Explicitly stated in “FUTURE DIRECTIONS”.  
  *Why unresolved:* Current framework assumes test users are from same distribution as training users; distribution shifts could cause mismatches.  
  *What evidence would resolve:* Experiments with synthetic or real-world user distributions that deliberately shift between train/test sets; evaluate profile-matching accuracy and cooperation performance.

- **Open Question 2:** How sensitive is L2CU’s performance to errors in the *consensus label estimation* (e.g., from Crowdlab) used during training, especially when annotator noise is high?  
  *Basis:* Inferred; L2CU relies on Crowdlab to estimate consensus labels when ground truth is unavailable.  
  *Why unresolved:* Noisy consensus labels may distort \(T^k\) estimates and profile clusters; paper assumes Crowdlab accuracy but does not test robustness.  
  *What evidence would resolve:* Controlled experiments on simulated datasets with known ground truth; compare performance when trained with true labels vs. estimated consensus under varying noise.

- **Open Question 3:** How does the *size and representativeness* of the clean validation set \(V\) used in the entry condition affect reliability in deciding whether to engage the AI model?  
  *Basis:* Inferred; entry condition uses a small clean validation set \(V\) per user; robustness to sample size or distributional mismatch is unanalyzed.  
  *Why unresolved:* A small or unrepresentative \(V\) may lead to incorrect entry decisions; real-world deployment may face cost constraints in obtaining clean validation data.  
  *What evidence would resolve:* Ablation varying \(M\) (samples per class) and introducing distribution shifts between \(V\) and test data; track false positive/negative rates of entry condition and impact on cooperation.

- **Open Question 4:** Why do real annotator datasets (except Chaoyang) yield *very low silhouette scores* for profile clustering, and how does this affect validity and generalizability of identified profiles?  
  *Basis:* Explicitly noted in Table 2: low silhouette scores likely due to many annotators with subtle noise patterns making profiles harder to distinguish.  
  *Why unresolved:* Low scores suggest poorly separated clusters yet L2CU still improves performance; unclear if profiles capture meaningful patterns or overfit.  
  *What evidence would resolve:* Detailed cluster analysis: visualize distributions, measure inter-/intra-cluster variance, correlate silhouette scores with accuracy gains; test alternative clustering methods or features.

- **Open Question 5:** What are appropriate *benchmarking standards and evaluation protocols* for L2C methods targeting unseen users, given existing L2C methods often require same users in train/test?  
  *Basis:* Inferred; Table 1 and related work highlight that many L2C methods are not designed for unseen users and lack standardized evaluation.  
  *Why unresolved:* Without standardized evaluation, fair assessment of progress is difficult; paper uses diverse datasets and custom metrics but field lacks consensus.  
  *What evidence would resolve:* Propose a benchmark suite with standardized splits (e.g., leave-one-user-out), including simulated and real multi-rater datasets; define core metrics and encourage community adoption.

## Limitations
- Exact hyperparameters (MLP architectures, learning rates, SVM kernel) are unreported, hindering exact replication.
- Profile clustering assumes a stable cluster structure; low silhouette scores on real datasets may invalidate the separation of profiles.
- The entry condition requires a per-user clean validation set, which may be impractical in many real-world scenarios.

## Confidence
- **Profile clustering captures generalizable error patterns:** Medium – supported by silhouette scores and simulation, but real-world separability is uncertain.
- **Profile-specific augmentation preserves noise patterns:** High – ablation shows necessity; visualizations match simulated patterns.
- **Cooperative model learns effective fusion:** High – ablation confirms both components; model corrects when base and user are both wrong.

## Next Checks
1. **Cluster structure validation:** On a dataset with injected noise patterns, compute silhouette scores for varying \(K\) and compare estimated \(T^k\) to ground truth. Expect high silhouette and accurate \(T^k\) recovery.
2. **Augmentation robustness test:** For a profile, train with \(G=0,1,5\) and with corrupted \(T^k\) (random row permutations). Measure accuracy drop; significant drop with \(G=0\) and corrupted \(T^k\) confirms dependence.
3. **Entry condition calibration:** Across test users, plot base model vs. user validation accuracy and track alteration rates (\(A^+, A^-\)). Check if threshold (base > user) maximizes net benefit; if not, adjust threshold.
