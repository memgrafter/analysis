# Tracking Cancer Through Text: Longitudinal Extraction From Radiology Reports Using Open-Source Large Language Models

## Quick Facts
- arXiv ID: 2603.09638
- Source URL: https://arxiv.org/abs/2603.09638
- Reference count: 5
- Primary result: Open-source LLM pipeline achieves >93% attribute-level accuracy in longitudinal lesion extraction from radiology reports with high inter-reader agreement, enabling privacy-preserving cancer tracking.

## Executive Summary
Radiology reports contain crucial longitudinal cancer data but are unstructured, complicating automated analysis, and proprietary LLMs raise privacy concerns. This work presents an open-source, locally deployable pipeline using the `llm_extractinator` framework with the `qwen2.5-72b` model to extract and link target, non-target, and new lesions across timepoints according to RECIST criteria. Evaluated on 50 Dutch CT Thorax/Abdomen report pairs, the system achieves attribute-level accuracies of 93.7% for target lesions, 94.9% for non-target lesions, and 94.0% for new lesions, with inter-reader agreement of 93.3%. These results demonstrate that open-source LLMs can attain clinically meaningful performance in longitudinal oncology tasks while ensuring data privacy and reproducibility.

## Method Summary
The pipeline processes pairs of radiology reports for the same patient by concatenating the prior and current reports into a single prompt. The prompt incorporates RECIST conventions (e.g., lesion categorization, measurement extraction) and includes an in-context example of a Dutch RECIST table. The `llm_extractinator` framework manages prompt templating, inference with the quantized `qwen2.5-72b-instruct-q4_K_M` model, and enforces a strict Pydantic v2 schema for output validation. The schema defines nested structures for lesions (label, description, size, SE-IMA, note), reports, and overall output. The system is evaluated on manually annotated report pairs, measuring attribute-level accuracy for lesion type, size, and SE-IMA. The local deployment on two NVIDIA A100 GPUs ensures data privacy but limits model choice.

## Key Results
- Attribute-level accuracy: target lesions 93.7%, non-target lesions 94.9%, new lesions 94.0%.
- High inter-reader agreement of 93.3% between the model and human annotators.
- The pipeline processes report pairs without reliance on external services, preserving data privacy.

## Why This Works (Mechanism)

### Mechanism 1: Longitudinal Linking via Concatenation
- **Claim**: The system achieves longitudinal lesion tracking by processing report pairs in a single context, enabling the LLM to link corresponding findings across timepoints.
- **Mechanism**: By concatenating two sequential radiology reports and prompting the model to extract from the "current" report while using the prior one for reference, the model assigns consistent stable labels (e.g., `TL_liver`) and classifies lesions as persistent, resolved, or new. This leverages in-context learning for temporal reasoning without fine-tuning.
- **Core assumption**: Radiologists' descriptions contain sufficient consistent textual cues (e.g., location, adjectives) for the model to recognize the same lesion.
- **Evidence anchors**: Abstract: "extract and link target, non-target, and new lesion data across time points"; Section 2.2.1: "Reports were always processed in concatenated pairs..."
- **Break condition**: Fails if prior context is absent, if descriptions change drastically (e.g., due to treatment), or if the model hallucinates links.

### Mechanism 2: Schema-Driven Output Constraint
- **Claim**: High attribute-level accuracy is achieved by enforcing a rigid, schema-driven output structure that constrains the LLM's generation.
- **Mechanism**: The `llm_extractinator` framework uses a Pydantic v2 schema to define the exact JSON structure (nested `Lesion`, `Report`, `OutputParser` models). The LLM is prompted to produce output matching this schema, and validation rejects non-conforming generations, reducing format errors and ensuring all required fields are addressed.
- **Core assumption**: A sufficiently capable open-source LLM (`qwen2.5-72b`) can reliably follow complex, nested JSON schema instructions, especially with an in-context example.
- **Evidence anchors**: Abstract: "implemented using the llm_extractinator framework... to produce structured JSON outputs"; Section 2.2.2: "The output parser serves as a blueprint... specified by a Pydantic v2 schema..."
- **Break condition**: Fails if the LLM ignores the schema (especially with less capable models), if required fields are insufficient for clinical nuances, or if the parser cannot recover from deviations.

### Mechanism 3: In-Context Learning with RECIST Heuristics
- **Claim**: Domain-specific performance is bootstrapped via a small set of in-context examples and carefully engineered prompt rules that encode RECIST conventions.
- **Mechanism**: The prompt includes one detailed example of a Dutch RECIST table and its correct JSON extraction, plus heuristics like "rightmost numeric value before last valid SE-IMA is the measurement". This translates implicit radiology formatting knowledge into explicit instructions, reducing ambiguity in size extraction and lesion categorization.
- **Core assumption**: The typical structure of Dutch CT Thorax/Abdomen reports (tabular measurements with SE-IMA identifiers) is homogeneous enough that a single example and a few general rules can cover most variations.
- **Evidence anchors**: Section 2.2.1: "The prompt included an in-context example illustrating the Dutch RECIST table format... Key prompt rules reflecting RECIST conventions were summarized..."; Section 4: "the model’s understanding of lesion identity was generally robust" but "occasionally struggled when tabular sections were wrapped across lines."
- **Break condition**: Fails on reports with highly atypical formatting (e.g., no tables, prose-only measurements), when rules conflict, or when radiologists use non-standard abbreviations or footnote symbols not covered by the rules.

## Foundational Learning

- **Concept: RECIST 1.1 Criteria for Solid Tumors**
  - *Why needed*: The extraction task is defined by RECIST rules (target, non-target, new lesions; measurement principles). Misunderstanding RECIST leads to incorrect lesion categorization and size extraction.
  - *Quick check*: What are the three lesion categories defined by RECIST, and what distinguishes a "target" from a "non-target" lesion?

- **Concept: Structured Output Generation with LLMs**
  - *Why needed*: The system's value lies in producing machine-readable JSON. Understanding how to constrain an LLM's output into a strict schema using frameworks like Pydantic and prompting is essential.
  - *Quick check*: If an LLM is instructed to output JSON matching a Pydantic model, what happens if it generates a string that is valid JSON but does not match the model's field requirements?

- **Concept: Longitudinal Data Linkage**
  - *Why needed*: The core innovation is linking findings across time, which requires entity resolution (same lesion across reports) and state change tracking (persistent, new, resolved).
  - *Quick check*: In a two-report sequence, what identifiers or descriptive attributes would you rely on to determine if a "3cm liver lesion" in report A is the same as a "2.5cm hepatic lesion" in report B?

## Architecture Onboarding

*Component map*: Input (Dutch radiology report pairs) -> Concatenation -> Prompt templating (llm_extractinator) -> LLM inference (qwen2.5-72b-instruct-q4_K_M) -> Output parsing (Pydantic schema) -> Validation -> JSON output

*Critical path*:
1. Receive a pair of report texts for a single patient.
2. Concatenate prior report then current report into a single prompt string.
3. Inject prompt into `llm_extractinator` with the Pydantic schema.
4. LLM generates text output; parser attempts to coerce into schema.
5. If parsing fails, system may retry (temperature=0) or record failure.
6. Valid JSON is stored for downstream analysis.

*Design tradeoffs*:
- Privacy vs. Performance: Local deployment ensures privacy but limits model choice to those fitting on available GPUs (hence qwen2.5-72b-q4). A larger proprietary model might be more accurate but is unusable.
- Schema Rigidity vs. Flexibility: Strict schema ensures clean data but may cause failures on edge cases (e.g., "nm" for not measurable). Optional fields mitigate but can lead to incomplete extraction.
- Single Example vs. Generalization: One in-context example simplifies prompt engineering but may not cover all Dutch report formatting nuances, leading to errors on wrapped tables.

*Failure signatures*:
- Parsing failure: LLM output is not valid JSON or deviates from schema.
- Attribute error: Correct lesion identified but size_mm or se_ima is wrong or missing.
- Linkage error: Same lesion gets different label across timepoints, or a new lesion is misclassified as persistent.
- Systematic bias: Consistent misreading of tabular data (e.g., always taking the leftmost number instead of rightmost before SE-IMA).

*First 3 experiments*:
1. **Debug set tuning**: Run the 10-pair debug set with iterative prompt revisions. Goal: achieve >90% attribute accuracy on this small set.
2. **Single-report baseline**: Process only the current report (without prior context). Measure drop in longitudinal linkage accuracy to quantify the value of concatenation.
3. **Full pipeline on test set**: Run the final prompt+parser on all 50 report pairs. Compute attribute-level accuracy for TL, NTL, NL and parse success rate.

## Open Questions the Paper Calls Out

1. **Does the pairwise approach scale to >2 timepoints?**  
   - *Basis*: The pipeline concatenates exactly two reports (Sec 2.2.1).  
   - *Why unresolved*: Longer sequences were not tested; temporal consistency might degrade.  
   - *Resolution*: Run the pipeline on patient histories with ≥3 reports, using either chained pairwise extraction or a modified prompt handling all timepoints, and compare lesion linkage accuracy.

2. **Does the model generalize to non-Dutch or multi-institutional reports?**  
   - *Basis*: Evaluation used only Dutch CT Thorax/Abdomen reports from one hospital (Sec 2.1).  
   - *Why unresolved*: Variations in terminology, structure, and language may affect extraction accuracy.  
   - *Resolution*: Test the pipeline on a diverse set of reports (different languages, hospitals, modalities) and compare performance metrics.

3. **Can explicit rules or additional in-context examples improve handling of ambiguous measurements (e.g., "nm", dashes, footnote asterisks)?**  
   - *Basis*: The discussion notes errors in such cases and suggests more examples or rules (Sec 4).  
   - *Why unresolved*: The current pipeline lacks specific handling, leading to occasional null misassignments.  
   - *Resolution*: Design and incorporate a set of deterministic rules or curated examples targeting these patterns, then evaluate on a subset containing these ambiguities, measuring change in error rates.

## Limitations
- **Prompt/Schema opacity**: The exact prompt text and full Pydantic schema are not provided, making faithful replication difficult.
- **Dataset scope**: Evaluation is limited to 50 Dutch CT Thorax/Abdomen report pairs; performance may not generalize to other modalities, languages, or institutions.
- **Longitudinal linking assumption**: The method relies on consistent textual cues for lesion identity, which may fail when descriptions change significantly or when radiologists use synonymous phrasing.

## Confidence
- Faithful replication without original prompt/schema: **Low**
- Performance on similar Dutch CT reports: **Medium**
- Generalization to other languages/modalities: **Low**
- Handling of edge cases (e.g., ambiguous measurements): **Medium**
