# Leakage Safe Graph Features for Interpretable Fraud Detection in Temporal Transaction Networks
## Quick Facts
- **arXiv ID:** 2603.06632
- **Source URL:** https://arxiv.org/abs/2603.06632
- **Reference count:** 19
- **Primary result:** A Random Forest classifier with causally computed graph features achieves ROC-AUC 0.85 and Average Precision 0.54 on the Elliptic dataset's future test set under strict temporal splits.

## Executive Summary
This paper tackles look-ahead bias in fraud detection on temporal transaction networks by introducing a causal graph feature extraction protocol. Graph features (degree, PageRank, HITS, k-core, etc.) are computed using only edges observed up to each transaction's timestep, preventing future information from influencing historical risk scores. Evaluated on the Elliptic Bitcoin dataset with temporal splits, the hybrid model (transaction attributes + graph features) reaches ROC-AUC 0.85 and Average Precision 0.54. Graph features alone have weak discriminative power but provide interpretable network context for human investigators, and probability calibration improves reliability for operational triage workflows.

## Method Summary
The pipeline begins with a temporal graph builder that constructs, for each timestep \(t\), a historical subgraph \(G_{\leq t}\) from edges with timestamps \(\leq t\). A causal feature extractor then computes structural descriptors (directed degree, PageRank, HITS hub/authority, k-core on the undirected projection, neighbor degree statistics, two-hop reachability) on \(G_{\leq t}\), applying \(\log(1+x)\) transforms to heavy-tailed features. These are merged with transaction attributes via a feature assembler. A temporal split enforcer partitions data: training (timesteps \(\leq 34\)), validation (35–41), and test (\(\geq 42\)). A class-weighted Random Forest is trained on the training set, with hyperparameter tuning and probability calibration (sigmoid or isotonic) performed on the validation set. Final evaluation on the held-out test set reports ROC-AUC, Average Precision, Precision@K, Brier score, and calibration curves.

## Key Results
- The hybrid model (transaction + graph features) achieves test ROC-AUC 0.85 and Average Precision 0.54.
- Graph-only model performance is poor (ROC-AUC 0.562, AP 0.049), but the hybrid model matches or slightly exceeds transaction-only performance, indicating graph features add complementary context.
- Probability calibration (Platt scaling or isotonic regression) improves Brier score and aligns predicted probabilities with true frequencies, enhancing reliability for triage.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Causal, time-respecting feature extraction prevents look-ahead bias and yields realistic performance estimates for temporal fraud detection.
- **Mechanism:** For each timestep \(t\), graph features are computed on the historical subgraph \(G_{\leq t}\) containing only edges observed at or before \(t\), ensuring no future transaction flows influence structural descriptors (e.g., degree, PageRank).
- **Core assumption:** Fraud indicators from network structure are sufficiently captured by transaction history up to prediction time; future connectivity does not retroactively change the inherent risk of past transactions.
- **Evidence anchors:** Abstract and Section 2.2.5 explicitly define causal variants using only edges up to each timestep. Related work (e.g., CaT-GNN) also emphasizes temporal causality.
- **Break condition:** If fraudsters adapt rapidly and relevant network structure evolves faster than the feature computation window, historical features may lag, reducing signal.

### Mechanism 2
- **Claim:** Even with weak standalone discriminative power, graph features provide complementary, interpretable network context that aids human investigators.
- **Mechanism:** Hand-crafted structural descriptors (k-core, hub/authority scores) translate raw transaction flows into human-readable risk factors (e.g., "central hub", "dense neighborhood"), presented alongside transaction attributes to support analyst reasoning.
- **Core assumption:** Investigators can more effectively triage and understand flagged transactions when network-level explanations are available.
- **Evidence anchors:** Abstract and Section 4.3 (ablation showing graph-only poor but hybrid matches transaction-only). Indirect support from forensics-focused graph studies.
- **Break condition:** If graph features are too noisy or fail to capture domain-relevant structures (e.g., money laundering layers), they may confuse investigators.

### Mechanism 3
- **Claim:** Probability calibration aligns model risk scores with true outcome frequencies, making them reliable for operational triage where probabilities inform decisions.
- **Mechanism:** Post-hoc calibration (sigmoid or isotonic) is fit on the validation set to adjust raw Random Forest outputs, improving reliability as measured by Brier score and calibration curves.
- **Core assumption:** Downstream workflows consume risk scores as probabilities and require well-calibrated estimates to avoid over- or under-confidence.
- **Evidence anchors:** Abstract and Section 3.6 (calibration evaluation, Fig. 4). Distinctive focus compared to many fraud detection papers that prioritize discrimination.
- **Break condition:** Under severe temporal distribution shift between validation and test periods, calibration may not generalize, leading to misaligned probabilities.

## Foundational Learning
- **Temporal Look-Ahead Bias in Graph Analytics:** Why needed: core methodological contribution; without understanding how future edges leak, evaluations are invalid. Quick check: When computing degree at time \(t\), exclude edges with timestamp \(> t\); enforce by building graph only from edges \(\leq t\).
- **Interpretable Graph Centrality Measures:** Why needed: chosen features (PageRank, HITS, k-core); knowing their semantics explains why they might flag fraud (e.g., centrality for money mules). Quick check: High k-core indicates a node is in a dense core; suspicious in money laundering because it suggests being part of a tightly connected group.
- **Probability Calibration for Risk Scores:** Why needed: model outputs used for triage; uncalibrated probabilities can mislead about actual risk. Quick check: Tree ensembles are miscalibrated due to bias in boosting/forest averages; isotonic regression fits a non-linear monotonic function to map scores to true probabilities.

## Architecture Onboarding
- **Component map:** Temporal Graph Builder -> Causal Feature Extractor -> Feature Assembler -> Temporal Split Enforcer -> Model Trainer -> Calibrator -> Evaluator
- **Critical path:** Raw temporal edges -> historical subgraph construction (per timestep) -> causal feature extraction -> feature matrix assembly -> temporal split enforcement -> model training (train -> validation selection) -> final test evaluation. Must never use future edges in feature computation for any sample.
- **Design tradeoffs:**
  - Hand-crafted vs. learned graph features: Hand-crafted offer interpretability and low cost but may miss complex patterns; GNNs could improve accuracy but reduce transparency and risk leakage if not temporally constrained.
  - Recomputing features per timestep: Ensures causality but increases computational overhead versus static graph.
  - Calibration vs. discrimination: Calibration improves probability reliability but may slightly reduce discrimination metrics; trade-off depends on operational need.
- **Failure signatures:**
  - Validation ROC-AUC ≫ test ROC-AUC (e.g., validation 0.977 vs test 0.853) suggests possible leakage or unrealistic hyperparameter tuning.
  - Calibration curve shows systematic S-shape deviation (over-confidence in mid-range probabilities) indicating miscalibration not fixed.
  - Graph feature importances high in hybrid but graph-only near random (ROC-AUC ~0.5) – could indicate graph features are proxies for leakage.
- **First 3 experiments:**
  1. Baseline transactional model: Train Random Forest on transaction attributes only under strict temporal split; establish reference ROC-AUC and AP.
  2. Causal graph feature ablation: Compare hybrid (T+G) vs. graph-only (G) and transaction-only (T) models to measure incremental value; confirm graph-only performs poorly but hybrid matches/surpasses T.
  3. Calibration impact: Fit sigmoid and isotonic calibrators on validation; compare Brier scores and calibration curves of uncalibrated vs. calibrated models on test; assess whether probability reliability improves without major AUC loss.

## Open Questions the Paper Calls Out
- **Can learning higher-order subgraph patterns under the causal protocol yield predictive gains?** Basis: Future work proposes feature learning beyond handcrafted descriptors. Why unresolved: Handcrafted features provided minimal incremental value; not evaluated.
- **How effective are temporal GNNs respecting causality against performance decay from temporal shift?** Basis: Future work includes temporal GNNs and domain adaptation. Why unresolved: Static RF used; no evaluation of temporal GNNs or robustness to decreasing illicit rate.
- **Do causally computed graph features improve human investigator efficiency?** Basis: Inferred claim from interpretability; no user study. Why unresolved: Operational utility assumed but not validated with experts.
- **Does the leakage-safe protocol generalize to other financial networks?** Basis: Inference; only Elliptic evaluated. Why unresolved: External validity uncertain for different topologies, velocities, or labeling quality.

## Limitations
- Graph algorithm parameters (PageRank damping, HITS convergence, k-core variant) are unspecified, affecting feature distributions and performance.
- Random Forest hyperparameters and calibration details (search space, selection criterion, whether calibrator refit on combined train+val) are missing, impeding exact replication.
- Interpretability claim—graph features aiding investigators—is not directly validated; no user study or qualitative analysis provided.

## Confidence
- Causal feature extraction prevents look-ahead bias: High
- Graph features provide complementary interpretable context: Medium
- Probability calibration improves triage reliability: Medium

## Next Checks
1. **Leakage verification:** For random timesteps and nodes, recompute features on \(G_{\leq t}\) and then after injecting a future edge (timestamp \(> t\)); vectors must be identical.
2. **Graph feature impact quantification:** Ablate by adding one graph feature group at a time to transaction-only baseline; measure incremental ROC-AUC/AP on validation to isolate each group's contribution.
3. **Calibration drift assessment:** Split test set into early and late blocks; fit calibrator on validation only; compute Brier score and ECE on each block to detect temporal misalignment.
