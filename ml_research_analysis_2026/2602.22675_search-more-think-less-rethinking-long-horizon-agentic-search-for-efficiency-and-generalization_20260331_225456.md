# Search More, Think Less: Rethinking Long-Horizon Agentic Search for Efficiency and Generalization

## Quick Facts
- **arXiv:** 2602.22675
- **Source:** https://arxiv.org/abs/2602.22675
- **References:** 40
- **Primary:** SMTL achieves state-of-the-art accuracy on deep search and research benchmarks while reducing reasoning steps by ~70% and increasing tool calls per step 3.5x versus prior agents.

## Executive Summary
SMTL is a long-horizon agentic search framework that shifts from sequential reasoning to parallel evidence acquisition. It dynamically refines execution plans and compresses context under a 128K token budget, trained via supervised fine-tuning and reinforcement learning on a unified data pipeline covering deterministic QA and open-ended research. The agent sets new records on BrowseComp, GAIA, Xbench, and DeepResearch Bench, demonstrating superior efficiency and cross-task generalization compared to existing methods.

## Method Summary
SMTL employs a parallel workflow: an initial plan is decomposed into sub-tasks executed concurrently via web search and page crawling tools. Every Δ=5 steps, the plan is dynamically refined based on new evidence. If context exceeds 128K tokens, an overflow trigger forces refinement and discards pre-plan context to stay within budget. Training uses two stages: (1) SFT on Qwen3-30B-A3B with trajectories distilled from teacher models (DeepSeek-V3.2 for deterministic QA, GPT-5 for research), and (2) RL with a modified RLOO algorithm using binary correctness rewards. Inference runs up to 300 steps with the same refinement and compression logic.

## Key Results
- **Benchmark dominance:** BrowseComp 48.6% (300 steps) / 43.6% (100 steps), GAIA 75.7%, Xbench 82.0%, DeepResearch Bench 45.9%.
- **Efficiency leap:** On BrowseComp, SMTL-100 uses 60.4 steps vs. Mirothinker-v1.0’s 206 (70.7% reduction) while improving accuracy.
- **Higher throughput:** Tool calls per step rise from 1.0 to 3.5, evidencing more effective parallel evidence gathering.

## Why This Works (Mechanism)
SMTL’s gains stem from three intertwined innovations: (1) **parallel evidence acquisition** avoids sequential bottlenecking, allowing multiple information streams to contribute concurrently; (2) **dynamic plan refinement** periodically re-orients the agent based on accumulated evidence, preventing rigid adherence to an initial suboptimal plan; (3) **overflow-triggered compression** actively manages the 128K context window by discarding outdated plan context rather than summarizing, preserving space for fresh evidence. The unified data pipeline ensures the model learns both deterministic question-answering and open-ended synthesis behaviors under a single operational paradigm, enabling robust generalization.

## Architecture Onboarding
**Component map:** Initial Plan -> Parallel Tool Execution (web_search, crawl_page) -> Evidence Aggregation -> Plan Refinement (every Δ=5) -> Overflow Compression (at 128K) -> Answer Synthesis  
**Critical path:** Plan generation initiates parallel tool calls; after Δ steps, the aggregator feeds evidence into a refinement module that updates the plan; if context overflows, compression discards pre-plan history; synthesis produces final answer upon completion or step limit.  
**Design tradeoffs:** Parallelism risks incoherent evidence aggregation versus speed gains; compression avoids information loss by dropping old plans but may lose early crucial clues; binary reward simplifies RL but yields high variance.  
**Failure signatures:** Tool format JSON errors causing immediate termination; context compressions coinciding with steep accuracy drops on long-horizon tasks; RL stagnating due to unfiltered environment errors.  
**First three experiments:**  
1. Run the parallel agent on 50 BrowseComp queries with max_steps=100, Δ=5, top-k=5; record average steps and tool calls/step to validate ~60 steps and 3.5 calls/step.  
2. Ablate Δ (plan refinement interval) across {1,5,10,20} on GAIA; measure accuracy change to confirm periodic refinement necessity.  
3. Implement overflow compression and log context length trajectories on DeepResearch Bench; correlate compression frequency with readability scores to assess information loss impact.
