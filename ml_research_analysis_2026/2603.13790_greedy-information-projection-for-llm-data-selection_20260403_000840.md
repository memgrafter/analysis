# Greedy Information Projection for LLM Data Selection

## Quick Facts
- **arXiv ID:** 2603.13790
- **Source URL:** https://arxiv.org/abs/2603.13790
- **Reference Count:** 40
- **Primary Result:** Greedy Information Projection (GIP) matches or exceeds full-data fine-tuning on instruction-following and reasoning benchmarks using only 1–20% of selected examples.

## Executive Summary
This paper introduces Greedy Information Projection (GIP), a framework for selecting high-quality, diverse subsets of data for fine-tuning large language models (LLMs). GIP formulates data selection as a mutual information maximization problem between data embeddings and a query signal (e.g., LLM judgments or geometric scores). It employs a greedy matching-pursuit algorithm to balance quality and diversity inherently, achieving near-linear computational scaling. Experiments on MT-Bench, Alpaca-Eval, and GSM8K with Qwen3-8B show that using 1–20% of GIP-selected data can match or surpass the performance of fine-tuning on the full dataset. The method unifies quality and diversity selection without requiring external validation or gradient computations.

## Method Summary
GIP addresses the data subset selection problem by framing it as maximizing the mutual information I(S; Q) between a selected subset S of data examples and a query signal Q. The query signal represents the desired property (e.g., instruction-following capability, reasoning correctness). The greedy algorithm starts with an empty set and iteratively adds the example that maximally increases this mutual information, approximated via embedding similarities. This process inherently promotes diversity (by covering distinct embedding regions) and quality (by aligning with the positive query signal). The approach operates solely in embedding space, avoiding the need for model gradients or external validation models, and scales near-linearly with dataset size.

## Key Results
- On GSM8K with Qwen3-8B, 20% of data selected via GIP (using MP+MA query signals) achieves 83.24% accuracy vs. full-data fine-tuning at 81.96%.
- On MT-Bench, 1% of GIP-selected data (MP+MA) scores 8.26 vs. full-data fine-tuning score of 7.74.
- GIP consistently matches or outperforms full-data baselines across instruction-following and reasoning tasks using very small subsets (1–20%).

## Why This Works (Mechanism)
GIP works by casting data selection as a mutual information maximization problem: I(S; Q), where S is the selected subset and Q is a query signal encoding desired properties (e.g., instruction-following scores). The greedy algorithm iteratively adds the example that yields the largest marginal increase in this mutual information, approximated by embedding similarities. This process inherently balances quality (similarity to the query) and diversity (coverage of distinct embedding regions). The use of a single embedding space avoids the need for model gradients or external validation, and the incremental updates keep computational scaling near-linear.  
*Assumption: The embedding space captures task-relevant semantics.*

## Foundational Learning
The method draws on several foundational concepts:
- **Mutual information** as a measure of dependence between the selected subset and the query signal.
- **Submodular optimization**: The greedy selection algorithm approximates the maximum of a submodular function (mutual information) with a (1-1/e) guarantee if the objective is submodular.
- **Representation learning**: embeddings are used to compute similarities, assuming that semantic similarity reflects task relevance.
- **Core-set selection**: akin to selecting a representative subset that preserves information about the full dataset.

## Architecture Onboarding
**Component Map**  
Embedding Encoder -> Similarity Matrix -> Greedy Selection Loop -> Final Subset

**Critical Path**
1. Encode all candidate examples and query signal into a shared embedding space.
2. Compute pairwise similarities (or a similarity matrix) between examples and the query signal.
3. Run greedy forward selection: at each step, add the example maximizing marginal gain in mutual information (approximated by similarity to current subset and query signal).
4. Output the final selected subset of defined size.

**Design Tradeoffs**
- *Quality vs. Diversity:* The mutual information objective inherently balances both; mutual information increases by adding examples that are similar to the query (quality) and that cover new regions (diversity).
- *Computational Cost:* Greedy selection scales near-linearly with dataset size due to incremental updates, but requires storing/computing similarity matrices, which can be memory-intensive for very large datasets.
- *Query Signal Dependence:* Performance is tied to the quality and representativeness of the query signal (e.g., MP, MA scores); a poor query signal will degrade selection.

**Failure Signatures**
- Selected subset appears homogeneous (low diversity) if the query signal embedding is narrow or if the greedy algorithm myopically picks only top-similarity examples without exploring.
- Performance drop if the embedding space does not capture task-relevant semantics; downstream fine-tuning won't benefit from the selected subset.
- Slow selection runtime on large datasets if similarity matrix recomputation is not optimized.

**First Three Experiments**
1. Re-run GIP selection on a small fixed dataset (e.g., 1k examples) while logging mutual information gain per iteration to verify monotonic increase and visualize selected examples in embedding space (e.g., via t-SNE).
2. Ablate the query signal: use a random signal vs. the proposed signal (MP/MA) to isolate the impact of the query definition on final subset quality.
3. Compare runtime of GIP vs. random selection vs. other subset selection methods (e.g., core-set) as dataset size scales from 1k to 100k examples, measuring wall-clock time and peak memory.

## Open Questions the Paper Calls Out
The paper does not explicitly list open questions. However, based on its scope and limitations, the following questions arise for future investigation:
- How does GIP generalize to other model architectures (e.g., Llama, Mistral) and larger scales?
- What is the sensitivity of performance to the choice of query signal (MP, MA) and can weaker signals still yield good selection?
- Can the mutual information objective be theoretically shown to be submodular, and what are the exact approximation guarantees?
- How does GIP compare to other efficient selection methods (e.g., clustering-based, gradient-based) in terms of accuracy-efficiency trade-offs?
- Does the selected subset transfer across tasks, or is it task-specific?

## Limitations
- Evaluation limited to Qwen3-8B on GSM8K/MT-Bench; unclear if results transfer to other models or domains.
- Query signals (MP, MA) are not defined; their extraction may need extra data or computation.
- No ablation separating quality vs. diversity contributions, so the claimed balance is not empirically validated.
- Scaling claim (“near-linear”) lacks empirical timing evidence.

## Confidence
- Performance parity/exceeds full-data: **Medium** (promising but narrow evidence).
- Unified quality–diversity without external validation: **Medium** (theoretically sound, needs broader tests).
- Near-linear computational scaling: **Low** (no data provided).
