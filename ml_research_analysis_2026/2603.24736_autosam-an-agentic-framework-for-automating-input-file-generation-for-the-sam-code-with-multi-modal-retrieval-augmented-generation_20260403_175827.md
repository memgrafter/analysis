# AutoSAM: an Agentic Framework for Automating Input File Generation for the SAM Code with Multi-Modal Retrieval-Augmented Generation
## Quick Facts
- arXiv ID: 2603.24736
- Source URL: https://arxiv.org/abs/2603.24736
- Reference count: 40
- Primary result: AutoSAM automates SAM input file generation from heterogeneous engineering documents, achieving 100% structured input utilization, ~88% PDF text extraction, and 100% vision-based geometric extraction, producing runnable and physically plausible models while identifying missing data.

## Executive Summary
AutoSAM is an agentic framework that automates the creation of input files for the SAM nuclear reactor simulation code. By combining a large language model (LLM) agent with retrieval-augmented generation (RAG) over SAM documentation and specialized multimodal tools, the system ingests diverse engineering documents (PDFs, images, spreadsheets) and produces a human-auditable intermediate YAML representation that is then transformed into valid SAM input decks. Tested on four cases, including complex multi-physics scenarios, AutoSAM consistently generates runnable models with physically plausible results and explicitly flags missing assumptions, demonstrating a significant step toward reducing manual effort in nuclear systems analysis.

## Method Summary
The framework centers on a ReAct-based LLM agent personalized with engineered system instructions derived from SAM manuals and equipped with retrieval capabilities from a static vector store of solver documentation. The agent employs a suite of seven tools: parsers for Excel/text files, a PDF analyzer that extracts text and equations via Nougat and describes figures using a vision-LLM, an image analyzer that interprets schematics to extract geometry and topology, an input file creator that generates solver-specific syntax from the intermediate YAML, a validator that checks completeness and consistency, and a Python execution tool. The workflow proceeds from document ingestion through structured intermediate YAML (which undergoes optional human review) to final input generation and deterministic validation. This modular design ensures traceability and auditability while allowing adaptation to other solvers by updating instruction sets and domain-specific tools.

## Key Results
- 100% utilization of structured inputs (Excel, JSON, YAML) in generating SAM input files.
- Approximately 88% extraction accuracy from PDF text content (including equations and tables).
- 100% completeness in extracting geometric and topological information from images/schematics.
- All four test cases produced runnable SAM models with physically plausible transient or steady-state behavior, and the system explicitly identified missing data and assumptions.

## Why This Works (Mechanism)
### Mechanism 1: Specialized System Instructions
The agent is initialized with persistent, carefully engineered system instructions that encode SAM’s input syntax, required blocks, parameter types, and physics domains. These instructions compensate for the fact that general-purpose LLMs lack inherent knowledge of solver-specific conventions. By providing a high-priority template, the agent constructs structurally valid input files. Break condition: If SAM’s syntax evolves beyond the static instruction set, outputs may become incorrect until instructions are updated.

### Mechanism 2: Retrieval-Augmented Generation (RAG)
The SAM user guide and theory manual are embedded into a vector store; during inference, similarity search retrieves relevant excerpts which are fed to the LLM as contextual evidence. This solves the problem that solver-specific details are not memorized by the LLM, reducing hallucinations and improving accuracy of parameter specifications. Break condition: Queries outside the embedded manual scope or failed retrieval may lead to missing or incorrect parameters.

### Mechanism 3: Multimodal Document Parsing Tools
Specialized tools parse heterogeneous document formats: a PDF tool uses Nougat for text/equations and a vision-LLM for figure descriptions; an image tool interprets schematics to extract geometry and topology; spreadsheets are read directly. This enables the agent to reconstruct complete models from non-plain-text data. Break condition: Tools may fail on low-quality scans, handwritten annotations, or complex layouts, resulting in missing or erroneous extractions.

## Foundational Learning
- **ReAct Agent Pattern**: The agent interleaves reasoning (thought) with tool calls (action), allowing it to decide which tool to use for a given document and how to synthesize extracted data. *Why needed*: Enables dynamic selection among multiple parsing and retrieval tools based on document content. *Quick check*: How does the agent decide whether to call the PDF analysis tool versus the image analysis tool when given an engineering document folder?

- **Retrieval-Augmented Generation (RAG)**: Grounds the agent’s outputs in authoritative, up-to-date solver documentation by retrieving relevant excerpts from embedded manuals during generation. *Why needed*: SAM’s manuals are not in the LLM’s training data; RAG provides precise, context-relevant details. *Quick check*: What is the role of vector embeddings in the AutoSAM RAG pipeline, and how does the system handle retrieving information from both static (manuals) and dynamic (user docs) directories?

- **Multimodal Document Understanding**: Combines text, equation, table, and image interpretation to extract simulation parameters from engineering documents. *Why needed*: Critical information (e.g., system layout from diagrams, tabulated properties) exists in formats that standard LLM context windows cannot parse directly. *Quick check*: Why can’t the LLM directly process a PDF page containing a diagram, and how does the PDF analysis tool bridge this gap?

## Architecture Onboarding
**Component map**: The core LLM agent (ReAct pattern) with system instructions interacts with a static vector store (SAM manuals) and a dynamic vector store (user PDFs/images). It uses tools: (1) Excel/text readers, (2) PDF analyzer (Nougat + vision-LLM + embedding), (3) Image analyzer (vision-LLM + embedding), (4) Input file creator, (5) Input validator, (6) Python execution tool, and (7) Instruction-passing tools. The intermediate artifact is a human-auditable YAML representation. Data flows: User documents → Agent (with retrieval and parsing tools) → Intermediate YAML → Input creator → SAM input file → Validator.

**Critical path**:
1. User provides documents and a prompt.
2. Agent retrieves relevant manual excerpts and uses parsing tools to extract data.
3. Agent synthesizes extracted data into intermediate YAML.
4. Human reviews/edits YAML (optional but enforced checkpoint).
5. Input creator tool transforms YAML into SAM input file.
6. Input validator tool checks completeness and consistency.

**Design tradeoffs**:
- Human auditability vs. full automation: The intermediate YAML ensures traceability but adds a manual step.
- Solver-specific vs. agnostic: Parsers and RAG are reusable; input creator/validator are solver-specific, requiring re-engineering for new solvers.
- Context window limits: Large models with long contexts may still struggle with many components; multi-agent decomposition may be needed for scalability.

**Failure signatures**:
- Missing parameters in final input file (validator reports incomplete blocks).
- Physically implausible values that pass deterministic checks but fail sanity review.
- Tool failures: PDF tool returns empty text for scanned pages; image tool misinterprets schematic labels.
- Hallucinated connectivity: Agent incorrectly connects components despite available diagram.

**First 3 experiments**:
1. Single-pipe steady-state: Validates baseline data ingestion from structured Excel and generation of a runnable, physically correct model (constant temperature profile, pressure drop).
2. Solid-fuel channel with reactivity feedback: Tests multi-physics coupling (fluid flow + solid heat conduction + point kinetics) from structured inputs, verifying transient response to inlet temperature ramp and correct feedback sign.
3. ABTR core: Stress-tests multimodal ingestion; extracts parallel-channel topology from an image, reconciles parameters from PDF, and generates a model that runs and exhibits expected uneven flow distribution and temperature rise, while explicitly labeling assumptions.

## Open Questions the Paper Calls Out
- How can AutoSAM achieve full end-to-end automation, including simulation execution, runtime error resolution, and post-processing?
- What multi-agent architectures can effectively decompose large system models to overcome context window constraints?
- What formal verification and validation protocols are needed for regulatory acceptance of AI-generated input files?
- How can the AutoSAM framework be efficiently adapted to other system codes like RELAP5 or TRACE?
- How does the quality of AutoSAM-generated input files compare to those produced by human experts?

## Limitations
- Unknown implementation details: Exact system instructions, intermediate YAML schema, and validator rule logic are not disclosed, hindering full replication.
- Generalizability concerns: Performance metrics are based on four specific test cases; robustness to poor-quality scans, complex diagrams, or novel solver features remains unproven.
- Human-in-the-loop bottleneck: The mandatory YAML review step, while ensuring auditability, limits end-to-end automation and introduces variability based on reviewer expertise.

## Confidence
- Structured input utilization (100%): Medium
- PDF text extraction (~88%): Medium
- Vision-based geometric extraction (100% completeness): Low
- Runnable & physically plausible outputs: Medium

## Next Checks
- Schema reconstruction: Infer the intermediate YAML structure from test case descriptions and figures; attempt to regenerate a known input file.
- Tool robustness stress test: Process a diverse set of real-world engineering PDFs/images through the PDF and image analysis tools; quantify extraction success rates and failure modes.
- Ambiguity handling probe: Present the agent with incomplete or contradictory source documents; evaluate whether it consistently flags assumptions/omissions versus hallucinating missing parameters.
