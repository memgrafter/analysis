# DARE: Aligning LLM Agents with the R Statistical Ecosystem via Distribution-Aware Retrieval

## Quick Facts
- **arXiv ID**: 2603.04743  
- **Source URL**: https://arxiv.org/abs/2603.04743  
- **Reference count**: 40  
- **Primary result**: DARE achieves state-of-the-art retrieval (93.47% NDCG@10) and boosts end-to-end task success rates from 6.25–25% to 56.25–75% across six LLMs.

## Executive Summary
Large Language Model (LLM) agents struggle to effectively utilize R's extensive statistical ecosystem because existing retrieval methods ignore critical data distribution characteristics (e.g., sparsity, dimensionality, distributional assumptions). This paper introduces DARE, a lightweight 23M-parameter distribution-aware retrieval model that fuses function metadata with data profiles via a contrastive dual-encoder. Trained on RPKB—a curated knowledge base of 8,191 CRAN functions—DARE significantly outperforms larger models in retrieval accuracy and efficiency. When integrated into the RCodingAgent for R-based statistical analysis, DARE elevates task success rates across multiple LLMs, demonstrating that distribution-aware retrieval is key to unlocking domain-specific tool use.

## Method Summary
The task is to build a retrieval system that matches natural-language queries and inferred data profiles to appropriate R statistical functions. The input is RPKB, a curated database of 8,191 CRAN functions, each annotated with documentation and a structured `data_profile` (e.g., modality, distribution assumption). DARE uses a shared dual-encoder (initialized from `all-MiniLM-L6-v2`) to embed concatenated inputs: `[query; data_profile]` for queries and `[function_doc; function_profile]` for functions. Training employs an InfoNCE contrastive loss with in-batch negatives over a 85% training split (245,730 pairs) for 100 epochs. The trained encoder enables efficient maximum inner product search (MIPS) over precomputed function embeddings. Reproduction requires: (1) acquiring RPKB from the project repository, (2) training DARE with specified hyperparameters, and (3) integrating the retriever into RCodingAgent to evaluate on 16 statistical tasks.

## Key Results
- **Retrieval accuracy**: DARE achieves 93.47% NDCG@10 on RPKB, a 17% relative gain over larger baseline models.
- **Efficiency**: Inference latency of 3.7ms and throughput of 8,512 QPS, suitable for real-time agent loops.
- **End-to-end impact**: RCodingAgent success rates increase from 6.25–25% (without DARE) to 56.25–75% across six LLMs when using DARE.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: DARE's distribution-aware embedding improves retrieval accuracy by conditioning on data profiles concatenated with query and documentation text.
- **Mechanism**: A shared-weight dual-encoder maps concatenated inputs (query + profile; doc + profile) into a shared vector space. Contrastive InfoNCE loss fine-tunes the encoder to maximize similarity for matched pairs and minimize it for mismatches, thereby embedding distributional constraints.
- **Core assumption**: Statistical function applicability depends on both semantic intent and data distribution characteristics; ignoring these leads to suboptimal tool selection.
- **Evidence anchors**: [abstract] notes existing methods ignore data distribution; [section 3.3] defines the concatenated embeddings and contrastive loss.

### Mechanism 2
- **Claim**: Contrastive fine-tuning with in-batch negatives efficiently transfers domain knowledge into a lightweight encoder.
- **Mechanism**: Starting from a pre-trained sentence transformer, each batch treats all other query-function pairs as negatives, pushing the model to distinguish subtle distributional incompatibilities without explicit negative mining.
- **Core assumption**: In-batch negatives provide sufficient diversity and hardness for fine-grained statistical tool discrimination.
- **Evidence anchors**: [section 3.3] describes in-batch negative training; [section 5.1] shows SOTA performance with only 23M parameters.

### Mechanism 3
- **Claim**: Integrating DARE as a plug-and-play module decouples tool selection from code generation, enabling reliable R ecosystem use.
- **Mechanism**: RCodingAgent queries DARE with a natural-language request and inferred data profile, retrieves top-k functions, and injects structured documentation (JSON) into the LLM context. The LLM then generates R code using these precise tool descriptions, reducing hallucination and execution errors.
- **Core assumption**: Providing accurate, context-aware tool documentation at inference time mitigates LLMs' limited native R knowledge.
- **Evidence anchors**: [section 3.4] describes structured metadata injection; [section 5.3] shows downstream success rate improvements.

## Foundational Learning
- **Concept**: Contrastive Learning (InfoNCE Loss)  
  *Why needed*: Forms the core training objective; understanding temperature scaling and in-batch negative sampling is key to reproducing performance.  
  *Quick check*: What effect does increasing the temperature τ have on the contrastive loss gradient flow?

- **Concept**: Bi-encoder Retrieval Architecture  
  *Why needed*: DARE uses a shared dual-encoder for efficient indexing; appreciating trade-offs with cross-encoder designs explains its low-latency deployment.  
  *Quick check*: Why can function embeddings be precomputed offline in a bi-encoder system?

- **Concept**: Data Profiling for Statistical Methods  
  *Why needed*: The data profile (modality, distribution, dimensionality) is the distinctive input enabling distribution-aware retrieval; profiles must be accurately generated.  
  *Quick check*: How might automatic data profile generation using an LLM introduce biases into the retrieval process?

## Architecture Onboarding
- **Component map**: User Query & Data Profile → DARE Retriever (dual-encoder) → Precomputed Function Embeddings (RPKB) → Top-k Function Documentation (JSON) → RCodingAgent (LLM with context) → R Code Execution → Output Comparison → Task Evaluator

- **Critical path**: User query → Data profile inference (from query/dataset) → DARE retrieval (MIPS over precomputed embeddings) → Top-k function docs injected into LLM context → LLM code generation → Execution in R environment → Output comparison to ground truth.

- **Design tradeoffs**: Accuracy vs efficiency (lightweight encoder vs larger models); specificity vs generality (distribution-aware vs semantic-only); retrieval granularity (function-level vs package-level) and context length (documentation size vs LLM capacity).

- **Failure signatures**: High recall with low NDCG (ranking issues); latency >10ms in agent loop; no success rate improvement with DARE (retrieval mismatch, profile error, or LLM ignoring context); failure to extract correct output from executed code (e.g., nested list access).

- **First 3 experiments**:
  1. Retrieval benchmarking: Run DARE and 9 baseline embedding models on RPKB test set; compute NDCG@10, MRR@10, Recall@10 to validate distribution-aware gains.
  2. Efficiency profiling: Measure single-query latency and batch throughput (QPS) on fixed hardware to confirm low overhead for real-time agent use.
  3. Agent end-to-end evaluation: Integrate DARE into RCodingAgent; run 6 LLMs on 16 statistical tasks; compare success rates with/without DARE to quantify downstream impact.

## Open Questions the Paper Calls Out
The paper does not explicitly enumerate open questions; however, the limitations section highlights several areas that warrant further investigation:
- How can the data profile generation process (using Grok/MiMo) be standardized to ensure replication and reduce variance?
- What are the exact implementation details of RCodingAgent (retrieval frequency, JSON injection format) that are necessary for reproducing the end-to-end results?
- Does the distribution-aware retrieval approach generalize to programming language ecosystems beyond R/CRAN, such as Python or JavaScript?

## Limitations
- Exact LLM prompts and data profile generation for RPKB (using Grok/MiMo) are unspecified, risking replication variance.
- RCodingAgent implementation details (retrieval frequency, JSON injection format) are partially described and not open-sourced, requiring reconstruction.
- Generalizability beyond R/CRAN to other ecosystems (Python, JS) is untested.

## Confidence

- **Efficiency (3.7ms latency)**: High (clearly specified dual-encoder + MIPS architecture)
