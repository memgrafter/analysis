# Agentified Assessment of Logical Reasoning Agents
## Quick Facts
- arXiv ID: 2603.02788
- Source URL: https://arxiv.org/abs/2603.02788
- Reference count: 2
- Primary result: The auto-formalization agent achieves 86.70% accuracy on the FOLIO validation set, outperforming the chain-of-thought baseline (73.89%).

## Executive Summary
The paper introduces Agentified Assessment (AAA), a framework where an assessor agent orchestrates evaluation by dispatching tasks, enforcing execution budgets, parsing outputs, and logging structured failures via a standardized agent-to-agent interface. This decoupling separates evaluation logic from agent implementation, enabling robust benchmarking and cost-effective scaling. As a case study, the authors implement an auto-formalization agent that translates natural language into Z3Py code and uses SMT solving for entailment, evaluated on a repaired FOLIO dataset. Results show the auto-formalization agent achieves 86.70% accuracy—a 12.81-point gain over chain-of-thought—with especially large improvements on contradiction (FALSE) and uncertain (UNCERTAIN) cases.

## Method Summary
The AAA framework centralizes evaluation within an assessor agent, which dispatches tasks, enforces budgets (timeouts, retries), and parses outputs via a standardized agent-to-agent (A2A) interface. This decoupling allows any agent implementing the interface to be evaluated consistently across benchmarks. For the case study, the auto-formalization agent receives natural language premises and a conclusion, generates Z3Py code, and executes it in a sandbox (60s timeout). A self-repair loop handles execution failures by regenerating code up to three times. The SMT solver determines the entailment label (TRUE/FALSE/UNCERTAIN) via unsatisfiability checks on the formalized expressions.

The evaluation uses a cleaned FOLIO dataset. Original annotations were verified with the Vampire theorem prover; mismatched or inconsistent instances were repaired using an LLM critique and refiner loop. This process fixed 1.5–3.8% of labels, producing a more reliable benchmark. A chain-of-thought baseline, prompted for step-by-step reasoning and a final label, is compared under identical settings.

## Key Results
- Overall accuracy: Auto-formalization 86.70% vs. Chain-of-Thought 73.89% (12.81% absolute gain).
- Contradiction (FALSE) cases: 77.05% vs. 44.26% (32.79% gain).
- Indeterminate (UNCERTAIN) cases: 91.30% vs. 84.06% (7.24% gain).

## Why This Works (Mechanism)
**Mechanism 1: Assessor Agent Decouples Evaluation**  
The assessor agent isolates evaluation concerns (task dispatch, budget enforcement, output parsing, failure logging) from the agent's internal logic. This separation ensures that integration overhead scales O(1) with the number of benchmarks and makes failure modes explicit through structured error types (e.g., TIMEOUT, PARSEERROR). By requiring only a standardized A2A interface, the agent can be reused across multiple assessors, simplifying deployment and auditability.

**Mechanism 2: Solver-Based Auto-Formalization**  
Auto-formalization grounds natural language reasoning in a sound SMT solver (Z3). The agent translates premises and conclusion into Z3Py code and checks unsatisfiability conditions to assign TRUE, FALSE, or UNCERTAIN labels. This eliminates the ambiguity and inconsistency of free-text chain-of-thought, particularly improving detection of contradictions (FALSE) and handling of uncertain cases. The self-repair loop further adds robustness by handling execution errors.

**Mechanism 3: Dataset Verification and Repair**  
The original FOLIO dataset contains annotation and translation errors. The repair pipeline first uses the Vampire theorem prover to verify consistency and label correctness. Problematic instances are then processed by an LLM critique agent that diagnoses specific errors (e.g., unbalanced parentheses), followed by a refiner agent that corrects them. This iterative process reduces label errors (3.8% training, 1.5% validation) and improves alignment between natural language and formal representations, yielding a cleaner benchmark for evaluation.

## Foundational Learning
**Agent-to-Agent (A2A) Protocol**  
*Why needed*: It is the communication backbone of AAA; without a stable schema, the assessor cannot reliably parse outputs or enforce budgets.  
*Quick check*: How does the protocol ensure that a timeout reported by the assessor reflects the agent's execution environment rather than harness overhead?

**Satisfiability Modulo Theories (SMT) Solving with Z3Py**  
*Why needed*: The method's correctness relies on accurate mapping of logical entailment to unsatisfiability and correct encoding of NL into Z3 expressions; errors in quantifier handling break the reasoning.  
*Quick check*: Why are `premises ∧ ¬conclusion` and `premises ∧ conclusion` used for TRUE and FALSE respectively? What would swapping them cause?

**Data-Centric Validation in Formal Datasets**  
*Why needed*: The cleaned FOLIO split underpins all reported results. Understanding Vampire-based verification and LLM repair is crucial to judge the benchmark's integrity.  
*Quick check*: If premises are inconsistent (`⊨ ⊥`), what is the appropriate label and how does the pipeline handle it?

## Architecture Onboarding
Component map (plain text):  
Assessor Agent → Agent Under Test → Z3Py Sandbox → Agent Under Test → Assessor Agent

Critical path:  
1. Assessor loads a task (premises, conclusion, gold) from cleaned FOLIO.  
2. Assessor sends task via A2A to the agent.  
3. Agent generates Z3Py code (using LLM) and executes in sandbox (60s timeout). On failure, self-repair regenerates (up to 3 attempts).  
4. Agent returns label (TRUE/FALSE/UNCERTAIN) via A2A.  
5. Assessor parses label, compares to gold, logs correctness, error type (e.g., TIMEOUT, PARSEERROR), and latency.  
6. After all tasks, assessor computes aggregate accuracy and per-category breakdowns.

Design tradeoffs:  
- **Assessor budget vs. agent complexity**: Tight timeouts may cause spurious TIMEOUTs for complex code; loose timeouts increase evaluation cost.  
- **Formal verification vs. translation brittleness**: Solver is sound but dependent on correct Z3Py; semantic mismatches may yield wrong labels without detection.  
- **Repair loop iterations**: More attempts improve robustness but increase evaluation time and may overfit to simple syntax errors.

Failure signatures:  
- `PARSEERROR`: Agent's final label not in {TRUE, FALSE, UNCERTAIN}.  
- `TIMEOUT`: Z3 execution exceeded 60 seconds.  
- `RUNTIMEERROR`: Z3 raised an exception (malformed expressions, undefined symbols).  
- `VERIFICATIONMISMATCH`: Dataset-level label conflict detected during cleaning.

First 3 experiments:  
1. **Baseline replication**: Run both agents on the cleaned FOLIO validation set (203 instances) with identical settings (Gemini 2.5 Flash, T=0.0) and confirm the reported accuracy numbers.  
2. **Failure mode analysis**: Compare the distribution of structured failure types (TIMEOUT, RUNTIMEERROR, PARSEERROR) between the auto-formalization and CoT agents to see if one shifts errors from reasoning to execution.  
3. **Repair loop ablation**: Disable the self-repair mechanism in the auto-formalization agent and measure the drop in overall accuracy and increase in RUNTIMEERROR rate to quantify the loop's impact.

## Open Questions the Paper Calls Out
1. Can the AAA framework be extended to richer tool-using agent settings (e.g., multi-tool orchestration, external APIs)? The current evaluation only covers a single-tool auto-formalization agent.  
2. To what extent can automated repair within the data cleaning pipeline reduce manual review, and what primary failure modes limit full automation? The pipeline still flags 19.2% of validation instances for manual review.  
3. Is the auto-formalization agent's performance gain specific to the Gemini 2.5 Flash backbone, or does it generalize across LLMs with different capabilities? No cross-model ablation is provided.  
4. What specific error modes cause the auto-formalization agent to underperform relative to chain-of-thought on TRUE entailment cases? The paper reports only a tiny gain (90.41% vs 89.04%) and provides no analysis.

## Limitations
- **AAA protocol opacity**: The A2A interface specification is insufficiently detailed, making faithful reproduction difficult.  
- **Auto-formalization brittleness**: The self-repair loop targets execution errors but may not catch semantic misalignments where syntactically valid Z3Py encodes incorrect logic.  
- **Dataset repair assumptions**: The repair pipeline assumes annotation errors are fixable via parsing; ambiguous natural language may lead to irreconcilable misalignments not flagged.

## Confidence
- AAA decouples assessment from agent implementation: Medium  
- Auto-formalization + SMT improves accuracy, especially on FALSE/UNCERTAIN: High  
- Dataset verification/repair produces a more reliable benchmark: Medium
