# GEBench: Benchmarking Image Generation Models as GUI Environments
## Quick Facts
- **arXiv ID:** 2602.09007
- **Source URL:** https://arxiv.org/abs/2602.09007
- **Reference count:** 40
- **Primary result:** GEBench reveals that current image generation models excel at single-step GUI transitions but fail on multi-step planning and spatial grounding, highlighting key bottlenecks in icon interpretation, text rendering, and localization accuracy.

## Executive Summary
GEBench is a new benchmark designed to evaluate image generation models when used as GUI environments. It comprises 700 samples across five task types, ranging from simple single-step interactions to complex multi-step planning and spatial grounding. The evaluation metric, GE-Score, assesses five dimensions via VLM judges: Goal Achievement, Interaction Logic, Content Consistency, UI Plausibility, and Visual Quality. Results show a significant performance drop from single-step to multi-step tasks, and grounding tasks remain particularly challenging, with current models lacking precision in localization and temporal coherence.

## Method Summary
The GEBench data pipeline starts from screen recordings of real applications, with actions annotated in JSON. These undergo rule-based preprocessing to ensure action-GUI consistency, followed by expert verification and statistical calibration to produce a balanced set of 700 samples. The benchmark covers Single-step, Multi-step, Real App, Fictional App, and Grounding tasks. For evaluation, a model generates the next GUI state(s) given an initial state and instruction. Three VLMs (Gemini-1.5-Flash-Native, GPT-4o, Qwen2.5-vl-235b) score each output on the five dimensions using detailed rubrics. The final GE-Score is the average of these dimension scores, linearly scaled to 0–100%.

## Key Results
- Current models achieve high scores on single-step tasks (e.g., Nano Banana Pro: 84.50) but drop significantly on multi-step tasks (68.65), indicating poor long-horizon planning.
- Grounding tasks yield the lowest scores (<20% even for top models), revealing a fundamental lack of spatial precision.
- The analysis identifies three primary bottlenecks: icon interpretation, text rendering accuracy, and localization precision.

## Why This Works (Mechanism)
GEBench succeeds because it isolates critical aspects of GUI generation through its five-dimensional GE-Score, each tied to a functional requirement: achieving user goals, maintaining logical interaction flow, preserving content across steps, ensuring UI plausibility, and upholding visual quality. By using VLMs as judges, the evaluation scales beyond human annotation while capturing nuanced aspects. The diverse task types expose specific weaknesses: single-step tests immediate generation; multi-step tests temporal coherence; grounding tests spatial accuracy. This structure provides a clear diagnostic signal for model developers, highlighting not just overall performance but the dimensions that limit real-world deployment.

## Architecture Onboarding
**Component map:**  
Raw Recordings -> Task Annotation -> Rule-based Preprocessing -> Expert Verification -> Statistical Calibration -> Benchmark Dataset.  
Model Generation -> VLM Scoring (per dimension) -> GE-Score Aggregation.

**Critical path:** The most fragile steps are (a) annotation quality during task annotation, (b) consistency of VLM judges across models, and (c) the calibration of scores to avoid bias. A failure in any of these can invalidate the entire evaluation.

**Design tradeoffs:**  
- *VLMs vs. human evaluators:* VLMs provide scalability but may lack human-like understanding of GUI ergonomics.  
- *Five dimensions vs. single score:* The multi-dimensional score offers diagnostic detail but complicates reporting and may hide tradeoffs between dimensions.  
- *Diverse task types:* Covering a broad spectrum ensures comprehensive testing but increases benchmark size and complexity.

**Failure signatures:**  
- **Multi-step:** Visual or logical drift across consecutive frames (e.g., disappearing widgets, inconsistent layouts).  
- **Grounding:** Misaligned UI elements (e.g., a menu offset from expected coordinates).  
- **Text rendering:** Illegible or garbled text, especially in dense interfaces.  
- **Icon interpretation:** Incorrect semantic understanding of icon functionality leading to wrong actions.

**First experiments:**

## Open Questions the Paper Calls Out
1. **How can image generation models achieve precise spatial grounding for coordinate-based GUI interactions?**  
   *Basis:* Grounding task results show universally low GOAL scores; models fail to map normalized coordinates to exact pixels.  
   *Why unresolved:* Fundamental deficiency in spatial reasoning and execution.  
   *What evidence:* A model scoring >50% on grounding tasks with architectural changes like coordinate-conditioned attention.

2. **Why do current models fail to maintain temporal coherence over multi-step trajectories?**  
   *Basis:* Performance drops dramatically from single-step to multi-step (e.g., 84.50 → 68.65).  
   *Why unresolved:* Lack of long-horizon planning and reliance on shortcut mapping.  
   *What evidence:* Model that maintains CONS/LOGIC >80 over 5-step trajectories, with analysis showing reduced error propagation.

3. **Does GE-Score fully capture functional plausibility, or overemphasize visual fidelity?**  
   *Basis:* Section 5.3 notes a paradox; GE-Score weights dimensions equally without validation.  
   *Why unresolved:* May guide research toward aesthetics over functionality.  
   *What evidence:* Correlation studies between GE-Score components and human evaluations of task completion success.

4. **How can text rendering be improved in generated GUIs?**  
   *Basis:* Text degradation is a key bottleneck; models treat text as texture causing overlapping characters.  
   *Why unresolved:* Current models cannot render precise structured text needed for GUIs.  
   *What evidence:* Quantitative improvement in OCR accuracy on UI-plausible text samples with new architectural constraints.

## Limitations
- **VLM judge configuration** (prompts, temperature, etc.) is not disclosed, hindering exact replication of GE-Score.
- **Statistical calibration** step in data construction lacks detailed algorithmic description, raising concerns about sample balance.
- **Metric validation** is limited; GE-Score relies solely on VLM judgments without human evaluation to confirm alignment with human perception of GUI quality.

## Confidence
- Benchmark construction and representativeness: **Medium** (pipeline mostly specified but missing calibration details).
- GE-Score reliability: **Low** (opaque VLM configuration and no human validation).
- Performance trends and bottleneck analysis: **Medium** (findings inherit uncertainties of benchmark and metric).
