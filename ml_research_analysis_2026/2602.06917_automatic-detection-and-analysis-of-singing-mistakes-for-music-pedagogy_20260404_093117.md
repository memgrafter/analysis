# Automatic Detection and Analysis of Singing Mistakes for Music Pedagogy

## Quick Facts
- arXiv ID: 2602.06917
- Source URL: https://arxiv.org/abs/2602.06917
- Reference count: 40
- Primary result: TCN model achieves event F1 up to 67.5% (pitch) and 82.3% (amplitude) on Teacher 1; deep learning significantly outperforms rule-based baselines.

## Executive Summary
This paper introduces a system for automatic detection of singing mistakes in Indian Art Music (IAM) pedagogy. The authors present the M3 dataset—synchronized teacher–learner recordings with frame-level annotations for pitch and amplitude errors—and frame the task as audio event detection using stacked teacher–learner pitch contours and amplitude features. Deep learning models (CNN, CRNN, TCN) are trained; the Temporal Convolutional Network (TCN) with dilated convolutions yields the best performance, achieving event F1 scores of 67.5% (frequency) and 82.3% (amplitude) on one teacher’s data. Learning-based methods significantly surpass rule-based baselines, while cross‑teacher transfer reveals lower performance (~56.6% event F1) due to teacher‑specific annotation differences. The study also proposes data augmentation to mitigate amplitude class imbalance and a collar‑based evaluation to accommodate annotation uncertainty.

## Method Summary
The task is defined as frame‑wise binary classification of pitch and amplitude mistakes in synchronized teacher‑learner audio. Input features include octave‑normalized log‑scale pitch contours and log‑compressed RMS energy, optionally chromagrams. The M3 dataset is split 70:15:15 for training, validation, and testing. Models include CNN, CRNN, and TCN; all use time‑distributed sigmoid outputs and weighted binary cross‑entropy loss to address class imbalance. For amplitude mistakes, a data augmentation algorithm perturbs energy in static note segments to increase minority‑class examples. Evaluation employs collar‑based frame‑wise and event‑based metrics (80 ms and 200 ms collars respectively) to tolerate annotation timing imprecision. The rule‑based baseline applies fixed thresholds per frame without temporal context.

## Key Results
- TCN outperforms CNN, CRNN, and rule‑based baselines, reaching event F1 up to 67.5% (pitch) and 82.3% (amplitude) on Teacher 1.
- Data augmentation via energy perturbation of static note segments substantially improves amplitude detection by mitigating severe class imbalance.
- Cross‑teacher transfer performance drops to ~56.6% event F1, revealing that annotation differences (tolerance thresholds) limit model generalization.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Deep learning models (TCN, CRNN) outperform rule‑based systems by implicitly learning temporal context and continuity patterns from teacher‑learner paired features.
- **Mechanism:** The stacked pitch/amplitude contours provide a relative error signal when compared frame‑wise. Convolutional and recurrent layers aggregate information over multiple frames, allowing the network to distinguish sustained deviations (true mistakes) from transient tracking noise or stylistic vibrato. The Temporal Convolutional Network (TCN) uses dilated convolutions to expand the receptive field, capturing longer‑range dependencies crucial for identifying phrase‑level errors.
- **Core assumption:** Singing mistakes manifest as temporally contiguous events rather than isolated frame discrepancies, and their characteristics can be learned from synchronized teacher‑learner audio without explicit score notation.
- **Evidence anchors:**
  - [abstract] "...learning‑based methods are superior to rule‑based methods."
  - [section IV.C] "The task is formulated as an audio event detection problem... The models are trained using the weighted binary cross‑entropy loss..."
  - [section VI] "TCN achieves best performance... with event F1 up to 67.5% (frequency) and 82.3% (amplitude)... RB baseline relies on fixed thresholds applied frame‑by‑frame and lacks temporal context."
- **Break condition:** If mistakes are predominantly ultra‑brief (<100 ms) or occur in highly polyphonic/noisy contexts where reliable pitch extraction fails, the temporal aggregation may instead smooth out true errors or introduce false positives.

### Mechanism 2
- **Claim:** Data augmentation via controlled energy perturbation of static note segments mitigates severe class imbalance for amplitude mistakes, improving detector sensitivity.
- **Mechanism:** The augmentation algorithm identifies stable note segments in learner audio and applies random scaling factors (both up and down) to generate synthetic amplitude error examples. This directly increases the proportion of amplitude‑mistake frames in the training batch, preventing the model from being dominated by the "no mistake" class and learning a trivial always‑zero predictor.
- **Core assumption:** Amplitude errors in real data are sparse because learners tend to match loudness roughly; simulated errors in stable notes are representative of real amplitude mistakes (e.g., sustained too soft/loud).
- **Evidence anchors:**
  - [section IV.B.2] "Amplitude mistakes are relatively rare... leading to class imbalance... To address this, we augment learner audio by introducing artificial amplitude errors."
  - [section VI.A] "Table IV highlights the effectiveness of data augmentation: the model trained with augmented data (TCN aug) consistently outperforms its non‑augmented counterpart..."
  - [corpus] The corpus evidence is weak; neighbor papers (e.g., RUMAA, SingFake) address mistake detection but not specifically amplitude augmentation for class imbalance.
- **Break condition:** If real amplitude mistakes are highly context‑dependent (e.g., only during ornamentation or specific emotional phrases) rather than occurring in static notes, the augmentation distribution would be mismatched, potentially degrading performance or causing false alarms on sustained phrases.

### Mechanism 3
- **Claim:** The collar‑based evaluation framework with dilated temporal boundaries accounts for inherent annotation uncertainty and enables meaningful comparison between systems.
- **Mechanism:** Human annotators cannot mark exact frame‑level mistake boundaries. The collar (T_c = 80 ms frame‑based, 200 ms event‑based) softens ground truth intervals, forgiving small timing discrepancies between prediction and annotation. This transforms a brittle exact‑match problem into a robust overlap‑based metric, aligning evaluation with perceptual tolerance.
- **Core assumption:** A mistake is perceptually meaningful over a short time window, and minor shifts in onset/offset (±T_c) do not change the pedagogical judgment.
- **Evidence anchors:**
  - [abstract] "...a new evaluation methodology is proposed... to accommodate annotation uncertainty."
  - [section IV.D] "...since it is exceedingly laborious... to mark the exact onset and offset... we adopt a collar‑based annotation scheme with soft temporal boundaries."
  - [section VI.A] "Introducing a collar improves frame‑wise metrics across models... reflecting realistic tolerance for annotator boundary uncertainty."
- **Break condition:** If the pedagogical application requires precise timing feedback (e.g., for rhythmic alignment in tala), a large collar would mask critical timing errors, making the metric insufficiently sensitive for that use case.

## Foundational Learning

- **Concept: Audio Event Detection (AED)**
  - *Why needed here:* The task is framed as detecting temporal events (mistakes) in a continuous audio stream, not classifying whole excerpts. This requires frame‑level binary outputs and handling event continuity.
  - *Quick check question:* How does the collar‑based evaluation in this paper differ from standard AED event metrics, and why is that adaptation necessary?

- **Concept: Class Imbalance in Deep Learning**
  - *Why needed here:* Amplitude mistake frames are vastly outnumbered by "no mistake" frames. Standard loss functions would be biased toward the majority class, causing the model to ignore rare but critical errors.
  - *Quick check question:* What is the specific mechanism by which weighting the binary cross‑entropy loss helps, and why was data augmentation chosen as a complementary strategy?

- **Concept: Teacher‑Student Synchronization for Paired Comparison**
  - *Why needed here:* Mistakes are defined relative to the teacher’s performance. The system relies on frame‑aligned teacher‑learner features (`(ˆp_t[n], ˆp_ℓ[n])`), requiring robust time alignment during recording or post‑processing.
  - *Quick check question:* If the synchronization drifts by more than the collar size, what is the expected impact on performance metrics, and how might the system fail silently?

## Architecture Onboarding

- **Component map:**
  1. **Input Pipeline:** Load synchronized teacher‑learner WAVs → extract pitch contours (Praat) or RMS energy → apply tonic normalization (pitch) → stack features.
  2. **Feature Engineering:** For pitch: log‑scaled, octave‑invariant contour or chromagram. For amplitude: log‑RMS. For augmentation: note segmentation (MIDI mapping, stability checks) → energy scaling of static notes.
  3. **Model Heads:** Shared architecture (1D‑CNN for contours, 2D‑CNN for chroma) → Temporal modeling (CNN/CRNN/TCN) → Time‑Distributed Sigmoid Output (frame‑level probability).
  4. **Training:** Weighted binary cross‑entropy loss, Adam optimizer, early stopping. Class weights computed from training set frequencies.
  5. **Evaluation:** Collar application on ground truth → frame‑based (precision, recall, F1) and event‑based (matching via overlap) metrics.

- **Critical path:** Accurate pitch extraction & synchronization → correct feature stacking → model selection (TCN recommended) → proper collar selection for target use case.

- **Design tradeoffs:**
  - *Pitch contour vs. Chromagram:* Contour preserves fine‑grained deviation for monophonic singing but is sensitive to pitch‑tracker errors; chromagram is more robust to octave errors but may smear microtonal differences.
  - *Model complexity:* TCN captures long dependencies but has more hyperparameters; CNN is simpler but may miss phrase‑level mistakes.
  - *Collar size:* Smaller collar is stricter but punishes annotation noise; larger collar is lenient but may hide systematic timing errors.

- **Failure signatures:**
  - **Systematic false negatives on rapid phrases:** Model fails to capture mistakes during fast ornamentation (see Fig. 6c). Likely due to receptive field insufficient or pitch tracker ambiguity.
  - **Cross‑teacher performance collapse:** Frame‑F1 drops >15 points when training on Teacher 1, testing on Teacher 2. Indicates overfitting to teacher‑specific tolerance thresholds (Table VII) rather than general mistake patterns.
  - **High event‑based F1 but low frame‑based F1:** Model detects events but with many fragmented, short activations. Indicates lack of temporal hysteresis; solution: add median filtering post‑processing.

- **First 3 experiments:**
  1. **Baseline replication:** Train the rule‑based model (`|ˆp_t - ˆp_ℓ| > β`) on a single teacher’s training set, optimize β/γ on validation. Establish the performance gap (expected: ~20‑30% lower F1 than TCN).
  2. **Collar sensitivity sweep:** For a fixed trained TCN model, evaluate frame‑F1 across collar widths (0, 40 ms, 80 ms, 200 ms). Plot metric vs. collar to find knee point; validate that 80 ms matches paper’s rationale.
  3. **Augmentation ablation:** Train TCN with and without `TCN_aug` on Teacher‑1 amplitude task. Compare amplitude event‑F1; expect significant lift (Table IV shows +17% event‑F1 in Scenario 1).

## Open Questions the Paper Calls Out

- **Improvisation extension:** How can the framework be extended to support learners engaged in improvisation rather than strict imitation? (Basis: future work mentions "expanding the framework to accommodate learner improvisation and stylistic variations." Unresolved because M3 dataset and models are designed for imitation; needs improvisation recordings and methods to distinguish errors from style.)
- **Learning benefits:** What are the tangible learning benefits of automated mistake detection feedback in real‑world music pedagogy? (Basis: future work notes "Longitudinal classroom studies will be critical to assessing the practical benefits." Unresolved due to lack of evidence on outcome improvement; requires controlled trials measuring skill acquisition and acceptance.)
- **Teacher annotation variability:** How can teacher‑specific differences in mistake annotation be reconciled to improve system generalization? (Inferred from cross‑teacher performance drop; unresolved because annotation tolerance thresholds differ; needs guidelines normalization or teacher‑adaptive models.)
- **Annotation uncertainty capture:** How should annotation uncertainty be quantitatively captured in evaluation metrics for different mistake types and teachers? (Inferred from fixed collar usage; unresolved because collar size may not align with perceptual tolerance; needs perceptual studies and adaptive metrics.)

## Limitations
- Model specification gaps: Exact TCN architecture (dilation rates, causal padding) and event post‑processing thresholds (hysteresis) are not described, blocking exact replication.
- Augmentation generalizability: Amplitude augmentation assumes errors occur in static notes; effectiveness for context‑dependent errors (e.g., ornamentation) is unknown.
- Annotation consistency: Teacher‑specific tolerance thresholds cause significant cross‑teacher performance drop, limiting model generalization to new instructors.

## Confidence
- Deep learning vs. rule‑based superiority: **High**
- Augmentation for amplitude imbalance: **Medium**
- Cross‑teacher transfer limitations: **High**
- Collar‑based evaluation validity: **Medium**
