# ATBench: A Diverse and Realistic Trajectory Benchmark for Long-Horizon Agent Safety

## Quick Facts
- **arXiv ID:** 2604.02022  
- **Source URL:** https://arxiv.org/abs/2604.02022  
- **Reference count:** 40  
- **Primary result:** Even state-of-the-art models like GPT-5.4 struggle, achieving only 76.7% F1 on binary safety classification and 33.6% on fine-grained risk-source diagnosis.

## Executive Summary
ATBench addresses the lack of realistic, diverse, and fine-grained benchmarks for evaluating long-horizon safety in LLM-based agents. It constructs 1,000 trajectories using a three-dimensional safety taxonomy (risk source, failure mode, real-world harm), a heterogeneous tool pool of 2,084 APIs, and a delayed-trigger protocol that models risk emergence across multi-step interactions. Experiments show that current models—including frontier and guard models—perform poorly on both binary safety classification and fine-grained risk attribution, with particular difficulty on tool-mediated risks. The benchmark enables stratified analysis, revealing persistent challenges in diagnosing indirect harms and demonstrating significantly higher difficulty than prior agent-safety benchmarks.

## Method Summary
ATBench is built via a taxonomy-guided generation engine. A three-dimensional taxonomy (8 risk sources, 14 failure modes, 10 harm types) acts as a scaffold, ensuring systematic coverage of distinct causal pathways. Trajectories are synthesized by a planner that selects tools from a large, heterogeneous pool sourced from real APIs (RapidAPI), prior benchmarks (ToolBench), and simulated safety-critical tools. A delayed-trigger protocol structures each trajectory into setup and exploit episodes, where early benign actions create state later reused to trigger harm. Generated outputs undergo rule-based and LLM-based filtering, followed by a full human audit (5 reviewers, 165 corrections). The final dataset contains 1,000 trajectories (503 safe, 497 unsafe) averaging 9.01 turns and 3,954 tokens, with paired safe/unsafe variants derived from the same scenario skeleton.

## Key Results
- SOTA models struggle: GPT-5.4 achieves only 76.7% F1 on binary safety classification and 33.6% on risk-source diagnosis.
- Tool-mediated risks (e.g., “malicious tool execution,” “tool description injection”) are particularly hard, with near-zero accuracy for many models.
- ATBench is substantially more difficult than prior agent-safety benchmarks due to its design choices (tool diversity, trajectory length, delayed triggers).

## Why This Works (Mechanism)

### Mechanism 1: Taxonomy-guided diversity
The three-dimensional taxonomy enables controllable diversity by sampling orthogonal slices (risk source, failure mode, harm) to instantiate specific risk patterns. This scaffold forces the generation engine to cover distinct causal pathways rather than repeating superficial scenarios. Evidence: The taxonomy drives the planner’s blueprint generation, and while neighboring benchmarks use hierarchical taxonomies, ATBench’s orthogonal design is novel for long-horizon safety. Break condition: If fine-grained diagnosis remains poor despite the taxonomy, labels may not cleanly separate real causal mechanisms or models lack reasoning to map traces to labels.

### Mechanism 2: Delayed-trigger realism
The long-context delayed-trigger protocol captures realistic risk emergence by separating setup and exploit episodes. Early benign actions create state (permissions, data, configurations) that is later reused to trigger harm, decoupling the risk source from its manifestation. Evidence: Trajectories are explicitly structured into two episodes with context carry-over; exploit steps are grounded in prior tool outputs or permissions, mirroring real-world attacks like reconnaissance followed by exfiltration. Break condition: If models perform similarly on immediate vs. delayed variants, the protocol may not introduce meaningful additional difficulty.

### Mechanism 3: Tool heterogeneity challenge
A large, heterogeneous tool pool (2,084 APIs) from real-world sources forces evaluation under diverse interface conditions, preventing overfitting to narrow tool-use patterns. The same risk slice can be realized with different tool combinations, parameter styles, and response formats. Evidence: Tools are sourced from RapidAPI, ToolBench, and simulated safety-critical tools; the planner selects from this pool per trajectory. This contrasts with prior benchmarks focusing on functional correctness. Break condition: If performance anti-correlates with tool count, difficulty may stem from tool complexity rather than long-horizon reasoning.

## Foundational Learning
- **Taxonomy-guided synthetic generation:** Understanding how the three-dimensional taxonomy translates into concrete trajectories explains ATBench’s coverage of risk patterns. Quick check: For slice (Indirect Prompt Injection, Provide Inaccurate Info, Info-ecosystem Harm), the planner would include tools that inadvertently spread misinformation via third-party content.
- **Delayed risk emergence modeling:** Grasping how earlier steps silently set up later failure is key to ATBench’s long-horizon realism. Quick check: In a trajectory, a setup episode might grant file write permissions; the exploit episode uses those permissions to delete critical data.
- **Tool-mediated risk attribution:** Tool-centric risks introduce new attack surfaces beyond user prompts. Quick check: “Choosing Malicious Tool” is harder than “Direct Prompt Injection” because it requires verifying tool legitimacy from schemas and history, not just parsing user intent.

## Architecture Onboarding
- **Component map:** Taxonomy Controller -> Planner -> Step Executors (Query Generator, Tool Call Simulator, Simulated Data Generator, Agent Response Generator) -> Validation Layer (rule-based + LLM-based filter) -> Human Audit Pipeline.
- **Critical path:** Taxonomy slice selection → Planner blueprint generation → Step-wise execution with risk injection → Filtering → Human audit → Dataset release. The blueprint must encode the delayed-trigger structure.
- **Design tradeoffs:** 
  - Diversity vs. Realism: More tools/taxonomy slices increase coverage but risk implausibility; mitigated by delayed triggers and filtering.
  - Coverage vs. Granularity: Single primary label per dimension stabilizes evaluation but discards secondary causes in multi-causal failures.
- **Failure signatures:**
  - High binary but low fine-grained accuracy → model detects unsafety but cannot attribute cause.
  - Poor performance on tool-mediated risks → weak tool-interface security reasoning.
  - Guard models failing despite high single-turn scores → training lacks trajectory-level, tool-mediated patterns.
- **First 3 experiments:**
  1. Binary safety classification on all 1,000 trajectories to establish baseline difficulty.
  2. Fine-grained diagnosis accuracy per taxonomy leaf category to pinpoint failure concentrations.
  3. Cross-benchmark comparison against R-Judge, ASSE-Safety, ATBench500 to demonstrate ATBench’s higher difficulty.

## Open Questions the Paper Calls Out
- How can ATBench support multiple risk labels per trajectory to capture multi-causal failures? The current single-label simplification may overlook interacting risks.
- How can ATBench be extended to multilingual settings to cover global agent safety? All trajectories are in English, ignoring language-specific risks and region-specific tools.
- Why are tool-mediated risks much harder for agents to detect than user-driven risks? Understanding the root cause (e.g., over-trust in tools, weak verification) is essential for effective safety mechanisms.

## Limitations
- Dataset and code not yet publicly released, blocking independent replication.
- Generation hyperparameters and human audit decision rules are underspecified.
- Three-dimensional taxonomy may not capture multi-causal or cross-dimensional risks.
