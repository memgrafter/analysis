# TeleTables: A Benchmark for Large Language Models in Telecom Table Interpretation

## Quick Facts
- **ArXiv ID:** 2601.04202
- **Source URL:** https://arxiv.org/abs/2601.04202
- **Reference Count:** 17
- **Primary Result:** Smaller models (<10B) struggle with 3GPP tables (cons@16 <62.6%); fine-tuning a 7B model raises performance from 26% to 58% cons@16.

## Executive Summary
TeleTables is a benchmark designed to evaluate large language models on interpreting dense tabular data from 3GPP telecom standards. The benchmark comprises 500 human-verified multiple-choice questions derived from 3GPP tables, presented in various formats (HTML, JSON, Markdown, images). Results indicate that general-purpose models under 10B parameters fail both to recall standard knowledge and to interpret tables, while reasoning-oriented models achieve high accuracy (e.g., Qwen3-32B: 92.6% cons@16). HTML format is generally optimal. Fine-tuning a 7B model on 3GPP data dramatically improves its performance, demonstrating the necessity of domain-specific training.

## Method Summary
The TeleTables pipeline transforms 3GPP PDF specifications into a structured benchmark. It begins by extracting tables via caption regex and converting them into multiple representations (HTML, JSON, Markdown, PNG) using Pandoc. A multimodal refinement agent (Qwen2.5-VL-72B) harmonizes these representations and enriches them with surrounding context. The benchmark construction proceeds in two stages: first, a basic MCQ generator creates simple questions from each table representation, validated by a majority vote; second, a more powerful model (Qwen3-32B) synthesizes five basic questions into a multi-step difficult question, which is filtered by a small model to ensure appropriate challenge. Human experts finally verify factual correctness and answer clarity. Evaluation harness runs models in their best-supported format(s), collecting 16 stochastic responses per question to compute pass@1 and cons@16.

## Key Results
- Small models (<10B) cannot recall 3GPP knowledge (∼35% cons@16 without tables) nor interpret tables even when provided (<62.6% cons@16).
- Reasoning-focused models achieve the highest accuracy; Qwen3-32B reaches 92.6% cons@16.
- HTML representation yields the strongest performance across most models; multimodal models drop significantly on image-only inputs.
- Fine-tuning a 7B model on TeleTables training data boosts cons@16 from 26% to 58%, surpassing larger generalist models.

## Why This Works (Mechanism)
### Mechanism 1: Pretraining Gap and Inductive Bias
General-purpose LLMs under 10B parameters exhibit poor performance on 3GPP table questions because their pretraining data lacks exposure to telecom standards and their architectures lack inductive biases for navigating dense, hierarchical tables. Models learn statistical patterns from their training corpus; if 3GPP specifications are underrepresented, they fail to develop internal representations for the domain's structures and terminology. Evidence: models score ∼35% cons@16 without the table (failed recall) and <50% cons@16 with the table (failed interpretation). The mechanism is falsified if a model achieves >90% cons@16 without the table.

### Mechanism 2: Format Affinity from Pretraining
Model performance is influenced by the table's textual representation format, with HTML generally optimal due to alignment with models' web-based pretraining. Different formats encode structural relationships with varying explicitness; HTML's nested tags match patterns commonly seen in web data. Evidence: Across models, HTML performance is highest or near-highest (e.g., Qwen3-32B: 92.0% HTML vs. 90.4% JSON/MD). The mechanism is weakened if a model shows no significant (>5pp) performance difference across formats.

### Mechanism 3: Fine-Tuning Efficacy
Domain-specialized fine-tuning on 3GPP table data drastically improves a small model's performance, proving that the bottleneck is knowledge acquisition rather than inherent reasoning capacity. Fine-tuning updates model weights to recognize domain-specific patterns and to operate over table structures. Evidence: a 7B model's cons@16 jumps from 26% to 58% after fine-tuning, making it the strongest open-weight model on TeleTables. The mechanism would be contradicted if fine-tuning yielded <10pp gain.

## Architecture Onboarding
### Component Map (pipeline flow)
Source Document → Table Extraction → Metadata & Context Enrichment → Multimodal Refinement Agent → Basic MCQ Generator → Basic MCQ Validator → Difficult MCQ Generator → Difficult MCQ Validator → Simplicity Filter → Human Validation → Benchmark Release → Model Evaluation

### Critical Path
The construction sequence: extract tables from 3GPP PDFs → convert to multiple formats → refine with VL model → generate and validate basic MCQs → synthesize difficult MCQs → filter for difficulty → human validation → release benchmark → evaluate models by format selection, inference, and scoring.

### Design Tradeoffs
- Format vs. Token Cost: HTML most accurate but ~73% more tokens than Markdown, affecting context length.
- Automation vs. Cost: Using a 72B VL model ensures fidelity but is expensive; a 7B model is cheaper but may err on complex tables.
- Complexity vs. Coverage: The difficult MCQ stage increases benchmark difficulty but may create questions too hard for all but top reasoning models, narrowing fair comparison.

### Failure Signatures
- Small Model Failure: cons@16 <60% even with table (e.g., Llama3.1-8B) → cannot parse or reason.
- Format Mismatch: Model's best format is not HTML (e.g., Llama prefers MD) → pretraining distribution differs.
- Vision Model Drop: Multimodal model performance plummets on IMAGE-only vs. text (e.g., Gemma: 81.0% HTML → 53.8% IMAGE) → vision encoder weak on fine-grained tables.
- Reasoning Model Resilience: High performance on Difficult subset (>80% cons@16) for reasoning models vs. collapse for non-reasoning variants.

### First 3 Experiments
1. **Format Sensitivity Baseline**: Run a strong model (e.g., Qwen2.5-VL-72B) on all single formats (HTML, JSON, MD, IMAGE) and dual combos to verify HTML optimality and multi-format benefit for smaller models.
2. **Scale vs. Reasoning Study**: Compare non-reasoning (Qwen2.5-32B) vs. reasoning (Qwen3-32B) models on the Difficult subset to isolate reasoning training effect.
3. **Fine-Tuning Replication**: Fine-tune a 7B model (e.g., Qwen2.5-7B-Instruct) on a TeleTables subset and measure performance delta on a held-out test set to confirm ~30pp gain.

## Open Questions the Paper Calls Out
1. **RAG Integration**: How does a realistic RAG retrieval component, with potential errors, affect LLM performance compared to the perfect retrieval setup evaluated in the paper? The paper's Future Work explicitly mentions evaluating RAG capabilities.
2. **Fine-Tuning Impact on Internal Recall**: Does domain-specialized fine-tuning improve LLMs' internal recall of 3GPP knowledge when the table is not provided, or does it only enhance table-interpretation skills? The paper's evaluations only use the table-provided setting.
3. **HTML Advantage Cause**: What is the primary reason HTML yields the best performance—its structural expressiveness or the fact that LLMs' pretraining corpora contain disproportionately more HTML-formatted tables? The paper speculates but does not disentangle these factors.
4. **Generator Model Bias**: Does the choice of LLM used in the automated MCQ generation pipeline (Qwen2.5-VL-72B, Qwen3-32B) introduce measurable biases in the resulting benchmark (question difficulty, distractor plausibility, topic coverage)? The pipeline relies solely on Qwen models.
5. **Temporal/Structural Generalization**: To what extent do models fine-tuned on TeleTables (Releases 18/19) generalize to tables from future 3GPP releases or to tables with substantially different structures? The benchmark is a static snapshot.

## Limitations
- **Generalizability**: Findings are specific to 3GPP specs; unknown how they transfer to other technical domains (medical, legal) with different table structures.
- **Benchmark Construction Bias**: MCQ generation uses large VL models (72B), potentially embedding their strengths/weaknesses into the benchmark distribution.
- **Evaluation Metric**: cons@16 measures consistency but may penalize valid reasoning diversity; pass@1 alone is not reported for all comparisons.

## Confidence
- **Mechanism 1 (Pretraining Gap & Inductive Bias)**: Medium. Correlative evidence (poor zero-shot recall, scale-dependent failure), but no direct corpus analysis of 3GPP representation in pretraining data.
- **Mechanism 2 (Format Affinity)**: Medium. Consistent HTML preference is compelling, but the causal factor (expressiveness vs. bias) remains inferential without controlled data-mix experiments.
- **Mechanism 3 (Fine-Tuning Efficacy)**: High. Direct, reproducible experimental result with large gain (26% → 58%), corroborated by neighboring domain-adaptation studies.

## Next Checks
1. **Corpus Exposure Audit**: Quantify 3GPP spec representation in standard pretraining corpora (e.g., The Pile, RedPajama) for models of varying scales.
2. **Controlled Format Ablation**: Re-train a small model (e.g., 7B) on identical table data with normalized tokenized representations (HTML vs. linearized JSON) to isolate whether HTML's advantage is semantic or tokenization-related.
3. **Fine-Tuning Replication Across Architectures**: Replicate the 7B fine-tuning experiment on at least two other model families (e.g., Llama 3.1, Mistral) using the same TeleTables training subset.
