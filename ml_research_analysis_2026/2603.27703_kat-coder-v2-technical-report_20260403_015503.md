# KAT-Coder-V2 Technical Report

## Quick Facts
- arXiv ID: 2603.27703
- Source URL: https://arxiv.org/abs/2603.27703
- Reference count: 26
- Primary result: Achieves 79.6% on SWE-bench Verified via a Specialize-then-Unify paradigm with five domain experts.

## Executive Summary
KAT-Coder-V2 introduces a "Specialize-then-Unify" framework to mitigate fragmentation in agentic coding systems. The approach trains five domain-specific experts—SWE, WebCoding, Terminal, WebSearch, and General—through supervised fine-tuning (SFT) and reinforcement learning (RL) using dedicated data pipelines and sandbox environments. A high-throughput orchestration system (KwaiEnv) and novel RL stabilizers (MCLA) and optimizers (Tree Training) enable efficient scaling. The experts are then consolidated into a single unified model via On-Policy Distillation (OPD), which combines sparse environmental rewards with dense, step-level supervision from the best-performing expert for each rollout. Empirical results demonstrate competitive performance on coding benchmarks: 79.6% on SWE-bench Verified, 88.7 on PinchBench, first place across all frontend aesthetics scenarios, and strong generalist capabilities on Terminal-Bench Hard (46.8) and τ²-Bench (93.9).

## Method Summary
KAT-Coder-V2 uses a Specialize-then-Unify paradigm. First, five domain experts (SWE, WebCoding, Terminal, WebSearch, General) are trained independently: each undergoes supervised fine-tuning (SFT) on large-scale, high-quality domain-specific trajectories built via specialized pipelines (e.g., Issue-PR for SWE, Tri-Perspective for WebCoding), followed by reinforcement learning (RL) within a domain-specific sandbox environment. The RL phase leverages MCLA to stabilize mixture-of-experts routing and Tree Training to accelerate training on tree-structured agent trajectories. The experts are then unified into a single model via On-Policy Distillation (OPD): for mixed-domain prompts, the student model generates trajectories while a dynamically selected best-performing expert (teacher) provides dense step-level log-prob supervision, jointly optimized with a standard RL sparse-reward loss.

## Key Results
- SWE-bench Verified: 79.6% (vs. Claude Opus 4.6 at 80.8%)
- PinchBench: 88.7 (surpassing GLM-5 at 86.4 and MiniMax M2.7 at 87.1)
- Frontend aesthetics: first-place scores across Landing Page (59.8), Slides (57.6), and Data Visualization (67.6)

## Why This Works (Mechanism)
### Mechanism 1: Domain Specialization via Orthogonal Expert Training
- **Claim:** Decomposing agentic coding into orthogonal expert domains (SWE, WebCoding, Terminal, WebSearch, General) and training them independently reduces capability interference and allows each to reach a local optimum.
- **Mechanism:** For each domain, a dedicated supervised fine-tuning (SFT) phase constructs large-scale, high-quality, domain-specific trajectory data using specialized pipelines (e.g., Issue-PR for SWE, Tri-Perspective for WebCoding). This is followed by reinforcement learning (RL) within that domain's sandbox environment, using environment feedback to optimize multi-step decision-making. The orthogonality assumption means the specialized data and reward signals for one domain do not conflict with those of another.
- **Core Assumption:** The fundamental skills and knowledge required for each domain (e.g., aesthetic judgment for WebCoding vs. CLI reasoning for Terminal) are largely non-overlapping and can be cleanly separated.
- **Evidence:** Supported by the abstract and Section 3.2 (separate data pipelines and training objectives); neighboring reports also explore multi-expert paradigms, though direct evidence for orthogonality is limited to internal design.
- **Break Condition:** If significant skill overlap exists between domains (e.g., code comprehension needed in both SWE and Terminal), independent training could lead to redundant learning or mutually incompatible internal representations, preventing effective later fusion.

### Mechanism 2: Agentic Scaling, Stabilization, and Speedup
- **Claim:** Scaling agentic RL along task complexity, intent alignment, and scaffold generalization, stabilized by MCLA and accelerated by Tree Training, yields high-quality, diverse training data and efficient optimization.
- **Mechanism:** The "Agentic Scaling" paradigm uses an internal Autobuilder system to generate tasks that are (1) complex (near frontier model capability), (2) diverse in prompt style (from expert to colloquial), and (3) scaffold-agnostic (across Claude Code, OpenCode, etc.). This creates a rich RL dataset. MCLA stabilizes MoE RL training by averaging K=8 prefetched log-probabilities to reduce variance from stochastic routing. Tree Training eliminates redundant computation in tree-structured agent trajectories by flattening them via DFS and applying per-token loss weights, achieving up to 6.2× speedup.
- **Core Assumption:** 1) Performance gains from RL scale with the diversity and difficulty of interaction data, not just volume. 2) MoE instability in RL is significantly driven by log-probability variance and can be mitigated by simple averaging. 3) Agent trajectories from modern scaffolds are inherently tree-structured with shared prefixes.
- **Evidence:** Described in the abstract, Section 3.3.1 (definition of Agentic Scaling, MCLA, and Tree Training logic), and supported by neighboring work on agent infrastructure and long-horizon training.
- **Break Condition:** If log-prob variance is not the primary source of MoE instability (e.g., expert load imbalance dominates), MCLA would have limited effect. If agent scaffolds produce predominantly linear trajectories, Tree Training's speedup benefit would vanish.

### Mechanism 3: On-Policy Distillation for Unified Model
- **Claim:** On-Policy Distillation (OPD) consolidates multiple domain experts into a single model without catastrophic forgetting by combining sparse environmental rewards with dense, step-level log-prob supervision from the best-performing expert for each on-policy rollout.
- **Mechanism:** The unified Student model generates complete trajectories for mixed-domain prompts. For each trajectory, the expert (Teacher) that would have achieved the highest final reward (or score) for that specific task is dynamically selected. The Student's policy is jointly optimized with a standard RL loss (using the verifier's sparse reward) and an OPD loss that minimizes the KL divergence between the Student's action log-probabilities and the Teacher's log-probabilities at each step. This provides dense, on-policy guidance aligned with successful behavior.
- **Core Assumption:** 1) For any given task, one expert is consistently superior and can be reliably identified. 2) The Teacher's log-probabilities provide a sufficient and unbiased learning signal for the Student's intermediate reasoning steps. 3) The combined loss prevents the model from overwriting specialized capabilities with generalist ones.
- **Evidence:** Outlined in the abstract and Section 3.4 (dynamic teacher selection and joint optimization); the specific OPD innovation lacks external corroboration in the provided corpus.
- **Break Condition:** If no single expert is consistently best for a given task (e.g., tasks require hybrid skills where different experts excel at different subtasks), dynamic teacher selection becomes noisy or contradictory, harming the Student's learning.

## Foundational Learning
- **KwaiEnv Modular Infrastructure** – Decouples datasets, sandboxes, scaffolds, and verifiers to enable high-throughput, multi-scaffold trajectory collection. *Why needed:* Without KwaiEnv, the Specialize-then-Unify pipeline would be infeasible due to engineering overhead. *Quick check:* How does KwaiEnv's "Separation of Concerns" allow a new scaffold to be integrated with minimal code changes?
- **Tree Training** – Eliminates redundant computation in tree-structured agent trajectories by flattening via DFS and applying per-token loss weights, achieving up to 6.2× speedup. *Why needed:* Agent scaffolds produce branching trajectories; naive training recomputes shared prefixes, creating a bottleneck. *Quick check:* In Tree Training, what are the three lightweight components required beyond DFS flattening and per-token reweighting?
- **On-Policy Distillation (OPD)** – Consolidates multiple experts into one by combining sparse rewards with dense, step-level log-prob supervision from the best-performing expert during on-policy rollouts. *Why needed:* Addresses catastrophic forgetting from weight averaging, sparse gradients from RL, and exposure bias from offline SFT. *Quick check:* What two losses are jointly optimized during OPD, and what does each provide?

## Architecture Onboarding
- **Component map:** Dataset Module → Sandbox Cluster (via Wanqing) → Scaffold (Claude Code/OpenClaw/etc.) → LLM Proxy → Trajectory Manager → RL Engine (KRL) → Model Weights. Key systems: KwaiEnv (orchestration), KRL (RL framework with Tree Training & live engine switching), SGLang (inference service), Megatron (training service).
- **Critical path:** The end-to-end training loop depends on the seamless handoff between the SGLang inference service (handling agent-tool-sandbox interactions during rollout) and the Megatron training service (performing policy updates). The live context switch and weight sync between these services is the core system bottleneck and innovation for high-concurrency training.
- **Design tradeoffs:**
  - *Modularity vs. Integration Latency:* KwaiEnv's decoupling allows independent iteration but introduces network/serialization overhead in the proxy layer compared to a monolithic agent scaffold.
  - *Tree Training Complexity vs. Speed:* Implementing tree-structured attention masks and custom position IDs adds engineering complexity but is orthogonal to standard parallelism, offering large speedups for branching trajectories.
  - *Dynamic Teacher Selection vs. Consistency:* OPD's per-task teacher selection is flexible but introduces a non-stationary training target; noisy selection could destabilize training.
- **Failure signatures:**
  - **MoE Instability:** Sudden spikes in loss, divergent expert routing patterns, or collapsed expert utilization during RL training, indicating MCLA/IcePop are insufficient.
  - **Scaffold Coupling:** New scaffold integration fails or requires significant code changes, violating KwaiEnv's "black-box" integration promise.
  - **Tree Training Artifacts:** Incorrect gradient scaling or attention masking leads to performance drop on branching tasks; validate by comparing linear vs. tree trajectory batches.
- **First 3 experiments:**
  1. Sanity-check a single expert's SFT pipeline (SWE expert on a small subset, verify trajectory quality and baseline improvement).
  2. Validate KwaiEnv's scaffold decoupling (integrate a new simple scaffold, configure via YAML, run rollout, verify trajectory capture).
  3. Benchmark Tree Training speedup (run a training step with Tree Training enabled vs. disabled, measure wall-clock time and gradient equivalence).

## Limitations
- Orthogonality Assumption: The claim that five expert domains have largely non-overlapping skills is untested externally; significant overlap could cause redundant learning or incompatible representations.
- MCLA's Primary Mechanism: The assertion that MoE RL instability is primarily due to log-probability variance lacks comparative ablation against other sources like expert load imbalance.
- OPD Teacher Selection Reliability: Dynamic selection of a single "best" expert assumes clear superiority; noisy signals for hybrid-skill tasks could degrade Student learning.

## Confidence
- Specialize-then-Unify Paradigm: Medium
- Agentic Scaling & Stabilization (Tree Training speedup): Medium-High
- Agentic Scaling & Stabilization (MCLA efficacy): Medium
- On-Policy Distillation: Medium-Low

## Next Checks
- Probe skill overlap & interference: Train SWE expert on a small subset of Terminal-Bench Hard tasks (and vice versa). Measure performance drop on primary domain vs any transferred gains.
- Ablate MCLA's specific contribution: Run controlled MoE RL experiments comparing standard MoE RL, MoE RL with MCLA (K=8 averaging), and IcePop-only. Track loss stability, expert load balance, and final performance.
- Analyze OPD teacher selection consistency: During OPD rollouts, log the selected "best expert" per task. Compute Gini coefficient or entropy of teacher assignments across diverse prompts. High entropy indicates poor consistency.
