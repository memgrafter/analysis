# Solving Cyclic Antibandwidth Problem by SAT

## Quick Facts
- **arXiv ID:** 2601.04239
- **Source URL:** https://arxiv.org/abs/2601.04239
- **Reference count:** 40
- **Primary result:** Introduces SAT-CAB, the first exact SAT solver for the Cyclic Antibandwidth Problem, proving optimality for 14 of 24 instances and discovering new optimal solutions on Harwell-Boeing graphs.

## Executive Summary
The Cyclic Antibandwidth Problem (CABP) is an NP-hard graph labeling problem lacking prior exact methods for general graphs. This paper presents SAT-CAB, the first SAT-based exact solver, featuring a compact encoding called Cyclic Ladder that decomposes cyclic At-Most-One constraints into overlapping blocks using Sequential Counter. This reduces clause and variable counts from quadratic to linear in the number of vertices. Extensive experiments on standard benchmarks show SAT-CAB matches or outperforms leading heuristics and commercial solvers, while providing global optimality guarantees. The main limitation is memory consumption on large or dense graphs due to formula size.

## Method Summary
For a candidate cyclic antibandwidth value \(k\), SAT-CAB encodes CABP constraints—bijection (VERTICES, LABELS) and edge (CYCLIC‑\(k\))—into SAT. The core innovation is the Cyclic Ladder encoding: each (CYCLIC‑\(k\)) constraint is a cyclic sequence of At-Most-One (AMO) constraints over consecutive label windows. The encoding groups overlapping windows into blocks, applies Sequential Counter per block, and links adjacent blocks by sharing auxiliary variables, achieving linear growth. Symmetry breaking fixes the label of the max-degree vertex to \(\leq n/2\). Search over \(k\) uses parallel multi‑process execution with a binary pruning strategy: upon finding a feasible \(k\), all lower \(k\) are terminated; upon proving \(k\) infeasible, all higher \(k\) are terminated. The system integrates the CaDiCaL SAT solver and prioritizes \(k\) values via a tree traversal.

## Key Results
- First exact SAT solver for CABP on general graphs, eliminating reliance on heuristics.
- Outperforms or matches best heuristics (MS-GVNS, HABC-CAB, MACAB) and commercial solvers (CPLEX, Gurobi) under a 150‑second limit.
- Proves optimality for 14 of 24 benchmark instances and discovers several new optimal solutions on Harwell‑Boeing graphs.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The Cyclic Ladder encoding reduces SAT formula size from quadratic to linear in vertices compared to direct encodings.
- **Mechanism:** The (CYCLIC‑\(k\)) constraint decomposes into two cyclic sequences of AMO constraints. The encoding groups overlapping AMO constraints into blocks, encodes each block using Sequential Counter (introducing auxiliary variables per block), and connects adjacent blocks with additional clauses. By reusing auxiliary variables when blocks share the same variable set, total clauses and auxiliary variables grow linearly with \(n\).
- **Evidence anchors:** [abstract]: "drastically reducing the number of clauses and auxiliary variables"; [section 4.5]: Table 3 shows \(O(n)\) vs. \(O(n^2)\); [corpus]: neighboring work on overlapping cardinality constraints supports the concept, but Cyclic Ladder is novel.

### Mechanism 2
- **Claim:** Parallel SAT solving with binary pruning on candidate \(k\) values reduces time to optimality by eliminating inferior branches early.
- **Mechanism:** Multiple processes solve different \(k\) concurrently. A priority queue (e.g., binary search order) ordains exploration. A SAT result for \(k\) terminates all processes with \(k' < k\) (feasible subrange); an UNSAT result terminates all \(k' > k\) (infeasible subrange). This exploits monotonicity: if \(k\) feasible, all smaller \(k\) feasible; if \(k\) infeasible, all larger \(k\) infeasible.
- **Evidence anchors:** [section 5.1.1]: "parallel framework employs a multi‑processing strategy… candidate values can be prioritized"; Algorithm 2 details process management; [corpus]: parallel SAT portfolios are known, but this monotonic pruning is CABP‑specific.

### Mechanism 3
- **Claim:** Symmetry breaking by assigning the highest‑degree vertex a label \(\leq n/2\) reduces the search space by at least half without losing optimal solutions.
- **Mechanism:** For any labeling \(f\), the reversed labeling \(f'(v)=n+1-f(v)\) is also feasible with same CAB value. By fixing the max‑degree vertex to the first half of labels, exactly one from each symmetric pair is retained.
- **Evidence anchors:** [section 3.4]: "reversed labeling… satisfies (VERTICES) and (LABELS)… symmetry breaking constraint eliminates the symmetric solution"; [section 5.1.1]: inspired by Sinnl [31]; [corpus]: symmetry breaking common in SAT‑based graph problems.

## Foundational Learning
- **At‑Most‑One (AMO) constraints**  
  Enforce that at most one variable in a set is true. **Why needed:** CABP’s (CYCLIC‑\(k\)) constraint is a cyclic sequence of AMO constraints ensuring no two adjacent vertices on the cycle receive labels within \(k-1\) of each other. **Quick check:** For variables \(x_1,\dots,x_w\), what does AMO encode? Why must AMO hold for every window of \(w\) consecutive labels on the cycle?
  
- **Sequential Counter encoding**  
  Introduces auxiliary variables representing cumulative sums to encode "at most one true" with linear clause growth. **Why needed:** Cyclic Ladder uses Sequential Counter inside each block to encode the AMO constraint efficiently. **Quick check:** Given \(x_1,\dots,x_w\), describe the role of auxiliary variables \(R_{i,j}\) in Sequential Counter.
  
- **Cyclic distance**  
  On a cycle of \(n\) vertices, distance between labels \(a\) and \(b\) is \(\min(|a-b|, n-|a-b|)\). **Why needed:** CABP maximizes the minimum cyclic distance between labels of adjacent vertices. **Quick check:** For \(n=7\), \(f(u)=2\), \(f(v)=6\), compute cyclic distance. If \(k=3\), are these labels allowed on an edge?

## Architecture Onboarding

**Component map:**  
Graph loader -> ILP generator -> Cyclic Ladder encoder -> Symmetry breaker -> Parallel coordinator -> SAT solver wrapper -> Solution extractor -> Statistics logger

**Critical path:**  
1. Load graph, compute initial LB/UB from formulas or heuristics.  
2. Initialize priority queue with candidate \(k\) values (binary search order).  
3. For each \(k\): generate full SAT formula (all edge constraints + symmetry breaking + vertex/label constraints) → invoke CaDiCaL.  
4. On SAT: extract labeling, update best \(k\), terminate all processes with lower \(k\).  
5. On UNSAT: update upper bound, terminate all processes with higher \(k\).  
6. When queue empty, return best \(k\) and labeling. Formula generation (step 3) is dominant; SAT solving is runtime bottleneck.

**Design tradeoffs:**  
- **Encoding compactness vs. propagation:** Cyclic Ladder minimizes formula size but introduces auxiliary variables that may weaken unit propagation.  
- **Parallelism granularity:** Parallelizing over \(k\) is embarrassingly parallel, but similar \(k\) yield nearly identical formulas; no clause sharing is implemented.  
- **Symmetry breaking strength:** Current constraint (max‑degree vertex) is cheap but only breaks one symmetry; multiple max‑degree vertices leave residual symmetry.

**Failure signatures:**  
- **Memory exhaustion (MO):** SAT formula too large for dense graphs or large \(n\) (e.g., 3D mesh instances). Monitor CNF size before solving.  
- **Timeout (TO) without optimality:** Solver hits time limit before proving \(k+1\) infeasible; check if best \(k\) is marked optimal.  
- **Incorrect bounds:** Starting LB/UB too narrow may cause premature termination; verify via heuristics.  
- **Dependency/build failure:** Missing CaDiCaL v2.1.3 or incompatible C++ standard; capture compiler logs.

**First 3 experiments:**  
1. Validate Cyclic Ladder encoding size on a small instance (e.g., \(n=9\), \(w=3\)) by manually computing clause/variable counts and comparing to Table 3.  
2. Test iterative solving on a trivial graph (path of 4 vertices) to verify it finds the known optimal \(k\) and proves \(k+1\) UNSAT.  
3. Observe parallel pruning on a medium instance (e.g., Harwell‑Boeing *A-pores1*) by running with 1 vs. 4 processes and inspecting logs for early termination of subranges.

## Open Questions the Paper Calls Out
- **Can additional symmetry‑breaking constraints be identified?** Basis: Only reversal symmetry via max‑degree vertex is addressed. Unresolved: Rotational or other symmetries unexplored. Evidence needed: Formal symmetry group characterization and efficient SAT‑encodable predicates with experimental validation.
- **Can the SAT encoding be compressed further for dense graphs?** Basis: Current encoding per edge yields \(O(|E|\cdot n)\) clauses; \(O(|E|)\) factor remains. Unresolved: No shared structure across edges. Evidence needed: Novel encoding sharing clauses across edges (e.g., graph decomposition) to lower asymptotic dependence, with scalability tests on dense graphs.
- **Can graph features prioritize \(k\) values more effectively?** Basis: Parallel strategy uses static binary tree traversal independent of graph properties. Unresolved: Degree distribution, diameter, density not exploited. Evidence needed: Predictive model (e.g., machine learning) from graph features to guide \(k\) ordering, yielding faster convergence.
- **Is a hybrid SAT–metaheuristic approach feasible?** Basis: Conclusion suggests hybrids; no concrete method. Unresolved: How to combine optimality guarantees with heuristic scalability. Evidence needed: Architecture using metaheuristic solutions to warm‑start or bias SAT solver, with empirical improvement on large hard instances.
