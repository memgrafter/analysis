# OSExpert: Computer-Use Agents Learning Professional Skills via Exploration

## Quick Facts
- **arXiv ID:** 2603.07978  
- **Source URL:** https://arxiv.org/abs/2603.07978  
- **Reference count:** 40  
- **Primary result:** OSExpert improves success rate on long‑horizon tasks by ~20% (from ~10% to ~30%) and reduces execution time by ~80%, closing the efficiency gap to human experts.

## Executive Summary
OSExpert is a framework enabling computer‑use agents to autonomously learn professional skills through systematic exploration of graphical user interfaces. It employs a GUI‑based depth‑first search (GUI‑DFS) to discover and verify unit functions, composes these into higher‑level composite skills, and trains a fast LoRA‑tuned planner for single‑pass inference. A skill‑boundary check early‑aborts infeasible queries, avoiding wasteful test‑time scaling. Evaluated on the new OSExpert‑Eval benchmark (113 tasks across six environments), OSExpert achieves substantial gains in both success rate and efficiency, addressing long‑standing limitations of current agents.

## Method Summary
OSExpert operates in two phases. First, during offline exploration, a planning module generates UI interaction plans, an action module executes them using fine‑grained primitives, and a feedback module classifies outcomes (intermediate, terminal, error). Valid terminal states are stored as unit skills in a skill set; the process repeats depth‑first. After unit skills are collected, the agent self‑proposes composite tasks to build higher‑level skills. Second, for inference, a lightweight LoRA‑tuned planner is trained on the skill trajectories to produce complete plans in one forward pass. Before planning, a skill‑boundary check consults the skill set (including recorded failures); if the query matches a known failure, it aborts early. Otherwise, the planner outputs a plan, the action module executes it, and failures trigger a fallback with skill injection.

## Key Results
- On OSExpert‑Eval (113 tasks, six environments), OSExpert achieves an absolute success rate improvement of ~20% on long‑horizon tasks, raising success from ~10% to ~30%.
- Average completion time is reduced by ~80%, nearly matching human expert efficiency.
- Generalization to the OSWorld benchmark shows smaller but consistent gains, confirming broader applicability.

## Why This Works (Mechanism)
**Mechanism 1 – GUI‑DFS exploration discovers reliable procedural knowledge.** Starting from top‑level UI elements, the algorithm depth‑first explores the state space: it generates plans, executes actions, and classifies states. Terminal states are condensed into verified unit skills and stored. This bottom‑up approach autonomously builds a comprehensive skill set without human‑curated queries, and fine‑grained primitives ensure precise control.

**Mechanism 2 – Skill composition handles long‑horizon workflows.** After unit skills are learned, the agent autonomously proposes a curriculum of composite tasks that combine multiple unit functions in sequence. These composites are validated and added to the skill set, enabling complex workflows to be executed as single higher‑level plans.

**Mechanism 3 – Fast planner and boundary check boost efficiency.** A LoRA‑tuned planner, trained on collected trajectories, generates full plans in one forward pass, eliminating per‑step deliberation overhead. The skill‑boundary check consults the skill set (including failures) to abort infeasible queries before wasteful test‑time attempts, dramatically reducing latency.

## Architecture Onboarding
**Component map:**  
Planning Module → Action Module → Feedback Module; Skill Set Database stores skills and failures; Fine‑Grained Primitive Database supports Action Module; LoRA‑Tuned Planner (trained on Skill Set) generates inference plans; Skill Boundary Check queries Skill Set before planning.

**Critical path:**  
1. *Initialization:* Planning Module proposes top‑level UI exploration targets.  
2. *Exploration loop (GUI‑DFS):* Pop a node, replay to restore state, execute next action with Action Module, get Feedback. On terminal state, add skill; on error, retry/record failure; on intermediate, generate new plans and push nodes.  
3. *Post‑exploration:* Organize skills, train LoRA‑Tuned Planner, optionally extend skill set via self‑proposed composite curriculum.  
4. *Inference:* Skill Boundary Check aborts infeasible queries; if feasible, LoRA‑Tuned Planner outputs full plan; Action Module executes; failures fall back to test‑time scaling with skill injection.

**Design tradeoffs:**  
- DFS vs. BFS: DFS yields earlier skills and lower memory; BFS gives broader shallow coverage but delays skill acquisition.  
- Exploration depth bound: Shallow misses complex functions; deep increases cost/risk of dead ends.  
- Primitive database: Manual design reduces annotation cost versus end‑to‑end training but requires domain expertise.  
- Base model dependence: Stronger models produce more reliable exploration; weaker models risk incomplete/noisy skills.

**Failure signatures:**  
- Low long‑horizon success despite skill set → poor composition or insufficient unit skills.  
- Poor fine‑grained accuracy → missing/incorrect primitives or grounding failures.  
- Minimal efficiency gain → fast planner under‑trained or boundary check underutilized.  
- Weak unseen UI generalization → overfitted skills; compositionality does not transfer.

**First 3 experiments:**  
1. *Main performance on OSExpert‑Eval:* Compared against OpenCUA, Computer‑Use‑Preview, Qwen‑3‑VL, CoAct‑1, Agent‑S3. Tables 2‑3 show ~20% absolute success gain and ~80% latency reduction.  
2. *Ablation study:* Removed fine‑grained skills, fast planner, and boundary check individually (Table 3 variants). Boundary check contributed most to efficiency; fine‑grained skills were crucial for precision tasks.  
3. *Evaluation on OSWorld:* Tested generalization to standard computer‑use tasks (Table 4). Gains were smaller due to simpler tasks but consistent, confirming environment learning benefits existing benchmarks.

## Open Questions the Paper Calls Out
1. **Offline exploration vs. test‑time scaling trade‑off** – When should each paradigm be preferred?  
2. **Automating fine‑grained primitives** – Can discovery, verification, and refinement of primitives be done without manual design?  
3. **Scaling to large/dynamic GUIs** – How to handle environments with hundreds of tools, dynamic layouts, or frequent version changes without prohibitive cost?  
4. **Cross‑application skill transfer** – Can procedural skills be abstractly represented and transferred to unseen but related applications?

## Limitations
- Fine‑grained primitive database and composite skill generation algorithm are not detailed, hindering reproducibility.  
- Use of proprietary models (GPT‑5, UI‑TARS) and unreleased benchmark (OSExpert‑Eval) and baselines limits accessible replication.  
- GUI‑DFS coverage and efficiency assumptions lack direct validation; skill‑boundary check error rates are unknown.

## Confidence
- **Overall performance** (~20% success gain, ~80% latency reduction): *Medium*  
- **GUI‑DFS exploration mechanism:** *Medium*  
- **Skill composition mechanism:** *Low*  
- **Fast planner & boundary check mechanism:** *Medium*
