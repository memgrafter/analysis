# Generalizable Self-Evolving Memory for Automatic Prompt Optimization

## Quick Facts
- **arXiv ID:** 2603.21520
- **Source URL:** https://arxiv.org/abs/2603.21520
- **Reference count:** 40
- **Primary result:** MemAPO achieves state-of-the-art average accuracy (70.7% on GPT-4o-mini) across six reasoning benchmarks while reducing optimization costs by ~57% compared to TextGrad.

## Executive Summary
Automatic prompt optimization for large language models has traditionally focused on searching for task‑specific prompts without accumulating reusable knowledge across tasks. This paper introduces MemAPO, a self‑evolving memory framework that maintains a dual‑memory system: a Correct‑Template Memory (CTM) that distills successful reasoning strategies into reusable templates, and an Error‑Pattern Memory (EPM) that captures common failure modes as negative constraints. For each new query, MemAPO retrieves relevant templates and error patterns to construct an augmented prompt, then uses iterative self‑reflection to refine the answer. The generated experiences are used to update both memories, enabling continuous improvement and cross‑task generalization. Experiments on six reasoning benchmarks show MemAPO consistently outperforms representative baselines, achieving the best average accuracy (70.7% on GPT‑4o‑mini) and reducing optimization costs by approximately 57% relative to TextGrad. Ablation studies confirm that both memory components and the self‑evolving paradigm are essential to its effectiveness.

## Method Summary
MemAPO operates in three stages. First, retrieval: the incoming query is embedded, and the system retrieves the top‑k (k=3) most similar CTM templates based on their index embeddings, alongside all stored EPM error rules. The prompt composer then assembles an augmented prompt consisting of the instruction, retrieved error rules, and template strategies. Second, evaluation with self‑reflection: the target LLM (Mt) generates an initial answer. If an external evaluator deems it incorrect, a reflection meta‑prompt produces a corrective insight that is added to the reflection set; the model retries up to a maximum of z=3 times. Third, memory update: after a success or exhaustion of retries, the system updates the memories. Successful trajectories either create a new template (if no relevant templates exist) or update existing templates via a decision meta‑prompt with verification on three sampled cases. Failures are summarized into a generalized error rule and merged with similar existing patterns (similarity threshold θ_error=0.7). When template count exceeds 30, similar templates are merged to maintain efficiency.

## Key Results
- Best average accuracy (70.7% on GPT‑4o‑mini) on diverse reasoning benchmarks.
- ~57% reduction in optimization cost versus strong baselines like TextGrad.
- Ablation studies confirm the complementary contributions of Correct‑Template Memory and Error‑Pattern Memory.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** The Correct‑Template Memory (CTM) enables transfer of successful reasoning strategies across heterogeneous tasks by distilling reusable procedural knowledge from past correct trajectories.  
**Mechanism:** Successful question‑answer pairs with reflections are abstracted into templates containing an index (applicability conditions), a strategy (abstract reasoning steps), and supporting cases. For a new query, semantically similar templates are retrieved via embedding similarity and injected into the prompt as positive guidance.  
**Core assumption:** Effective reasoning strategies for new problems share underlying structural similarities with past solved problems, and abstracting away specific content preserves transferability.  
**Evidence anchors:** [abstract] “distills successful reasoning trajectories into reusable strategy templates”; [section 3.3] formal definition of template T={I, S, C} and retrieval via top‑k similarity.  
**Break condition:** No template with similarity score above threshold θ_corr is retrieved for a query, forcing the system to rely solely on base prompting or error patterns.

### Mechanism 2
**Claim:** The Error‑Pattern Memory (EPM) reduces repeated failures by capturing and generalizing common mistake modes from incorrect generations, providing negative constraints during prompt construction.  
**Mechanism:** Failed attempts with reflections are summarized into concise error rules (R) describing root causes and prevention principles. All stored error patterns are retrieved unconditionally for every query, framing the prompt with explicit “RULES” to avoid known pitfalls.  
**Core assumption:** Many failure modes are recurrent across tasks and can be abstracted into generalizable principles that, when stated, help the LLM self‑correct.  
**Evidence anchors:** [abstract] “organizing incorrect generations into structured error patterns that capture recurrent failure modes”; [section 3.3] definition of EPM as a repository of R rules and retrieval of all patterns; [section 3.6] EPM update via summarization of reflections into a generalized rule and merging with similar existing patterns.  
**Break condition:** An error pattern is too generalized (low similarity to new failure) or fails to capture a novel failure mode, leading to unmitigated repetition of the mistake.

### Mechanism 3
**Claim:** Iterative self‑reflection within the prompt evaluation stage allows the target LLM to correct its own intermediate outputs using retrieved memories, reducing dependency on external optimizers and generating high‑quality experiences for memory updates.  
**Mechanism:** For a query, the model generates an initial answer conditioned on retrieved templates and error patterns. If evaluated (via ϕ) as incorrect, a reflection meta‑prompt produces a corrective insight (ref) added to the reflection set L. The model retries generation with updated L, looping up to a maximum retry count z.  
**Core assumption:** The same LLM can effectively critique and improve its own reasoning when provided with structured error patterns and successful strategy templates, simulating a form of verbal reinforcement learning.  
**Evidence anchors:** [abstract] “Through iterative self‑reflection, it evaluates and refines responses”; [section 3.5] detailed equations (4,5) and loop logic for generating ˆa0 and ref, with termination on success or max retries; [section 4.3 ablation] removing self‑reflection collapses to single‑pass generation, likely degrading performance; results show benefit of the loop.  
**Break condition:** Maximum retries z is reached without producing a correct answer, indicating the retrieved memories and reflection capacity were insufficient to resolve the query.

## Foundational Learning
**Dual‑Memory Abstraction (CTM vs. EPM)**  
*Why needed here:* Separating positive strategies (CTM) from negative constraints (EPM) allows the system to simultaneously encourage effective reasoning patterns and discourage known failure modes, creating a more balanced prompt than either alone.

**Retrieval‑Augmented Prompt Composition**  
*Why needed here:* The memory repository grows over time; effective prompt construction requires selecting the most relevant subset of experiences (top‑k CTM templates, all EPM rules) for a specific query without overwhelming context length.  
*Quick check:* On what basis are CTM templates retrieved, and why are all EPM patterns retrieved instead of a subset?

**Self‑Reflection as Experience Generation**  
*Why needed here:* The memory update stage requires high‑quality experiences (successful trajectories and failure summaries). The self‑reflection loop within the evaluation stage generates these by iteratively improving a single attempt, providing the raw material (trajectories, reflections) for memory distillation.

## Architecture Onboarding
### Component Map
New query q → Retrieval Module (embeds q, retrieves top‑k CTM templates and all EPM rules) → Prompt Composer (builds augmented prompt paug = [p_Inst, R_q, T_q^(k)]) → Target LLM (Mt) generates answer a0 → Evaluation (via ϕ). If incorrect: Reflection Loop (meta‑prompt p_meta_ref) produces corrective insight ref, updates reflection set L, and Mt retries (max z times). After success or max retries: Memory Update Controller (invokes p_meta_corr, p_meta_act, p_meta_sum, p_meta_error_update) → updates CTM (create/update/delete) and/or EPM (summarize/merge) → memories stored for next queries.

### Critical Path
1. Query received.
2. Retrieve relevant CTM templates (top‑k by similarity > θ_corr) and all EPM patterns.
3. Construct augmented prompt.
4. Generate initial answer.
5. If answer incorrect, reflect and retry (up to z times).
6. On termination (success or failure), update memory: for success, possibly create new CTM template or update existing ones with verification; for failure, summarize error rule and merge into EPM.
7. Proceed to next query.

### Design Tradeoffs
- **Memory size vs. relevance:** Larger CTM improves coverage but increases retrieval noise and context length; capped at 30 templates with merging to balance.
- **Template specificity vs. generalization:** Overly specific templates don’t transfer; overly general ones are useless. Index I and case set C help anchor applicability.
- **Negative guidance overload:** Retrieving all EPM rules risks prompt saturation; relies on model’s ability to filter relevant constraints.

### Failure Signatures
- Memory bloat/irrelevant retrieval: many low‑similarity templates added, degrading performance.
- Stagnant or conflicting memory updates: redundant or contradictory templates appear, leading to inconsistent guidance.
- Prompt saturation from EPM: excessive token consumption and potential distraction.
- Cold‑start degradation on novel domains: insufficient relevant memories for unseen task types.

### First Three Experiments
1. **Main performance comparison:** Run MemAPO and baselines (ProTeGi, OPRO, TextGrad, etc.) on 6 datasets (BBH, BBEH, AQuA, Gaokao Math/Geo/History) with GPT‑4o‑mini and Qwen3‑8B; measure accuracy and cost. Expect MemAPO to achieve best average accuracy (~70.7%) and ~57% cost reduction vs. TextGrad.
2. **Cross‑domain generalization:** Optimize on mixed‑domain tasks (e.g., Gaokao MathQA + Gaokao History). Expect baselines to degrade while MemAPO maintains gains, demonstrating memory’s role in reconciling heterogeneous reasoning demands.
3. **Ablation study:** Remove CTM only, EPM only, or both from MemAPO. Expect significant drops (e.g., 18‑22% on math tasks), confirming both components contribute synergistically.

## Open Questions the Paper Calls Out
1. **Extending to multimodal reasoning**  
   *Question:* How can MemAPO be extended to support multimodal reasoning tasks?  
   *Basis:* The Limitations section explicitly states: “The current framework focuses on textual reasoning tasks… Extending the memory architecture to support multimodal experiences may further enhance the generality.”  
   *Why unresolved:* The paper only evaluates on text‑based benchmarks; no multimodal integration is implemented or tested.  
   *Resolution evidence:* Implement a version that encodes multimodal data (e.g., images, audio) into memory and evaluate on multimodal benchmarks.

2. **Memory capacity limits and scalability**  
   *Question:* How does the memory capacity limit (e.g., top‑k templates, merge threshold) affect long‑term performance and scalability?  
   *Basis:* The design caps templates at 30 and merges similar ones (Section 3.6), and Figure 4 shows performance drops with too many templates. These constraints are heuristically chosen, not theoretically analyzed.  
   *Why unresolved:* The optimal capacity across diverse task distributions is unknown; aggressive merging may lose useful strategies, while large memory may cause noise.  
   *Resolution evidence:* Systematic experiments varying capacity limits and merge thresholds across large‑scale task sequences, measuring performance retention and template diversity.

3. **Quality of automatically generated templates**  
   *Question:* What is the quality and reliability of automatically generated templates via meta‑prompts?  
   *Basis:* Template creation/update relies on LLM‑generated summaries (meta‑prompts in Appendix A.6) without external validation beyond sampled cases. The robustness of this abstraction process is not assessed.  
   *Why unresolved:* LLMs might produce templates that are overgeneralized, incorrect, or contradictory, which could degrade future retrieval and reasoning.  
   *Resolution evidence:* Human evaluation of template correctness and generality; measuring correlation between template quality metrics and downstream accuracy.

4. **Retrieval under extreme heterogeneity**  
   *Question:* How does MemAPO’s retrieval mechanism perform when tasks are extremely heterogeneous, with low semantic overlap?  
   *Basis:* The retrieval uses semantic similarity (Section 3.4), and the cross‑domain experiment (Table 2) shows some degradation but still effective. However, it’s unclear how far generalization holds.  
   *Why unresolved:* The paper only mixes two related domains (math vs. history); true heterogeneity (e.g., combining logic puzzles, creative writing, code generation) might break retrieval.  
   *Resolution evidence:* Evaluate on deliberately diverse task sets (e.g., spanning multiple domains from BIG‑Bench, AGIEval, coding datasets) and analyze retrieval success rates.

5. **Optimal retrieval scope vs. inference efficiency**  
   *Question:* What is the optimal trade‑off between retrieval scope (number of templates) and inference efficiency in real‑world deployment?  
   *Basis:* Figure 4 shows performance peaks at top‑3 templates with increasing token cost; but cost reduction in Figure 2 is measured across whole optimization, not per‑query inference.  
   *Why unresolved:* During deployment, each query incurs token costs from retrieved memories; the paper does not optimize for inference‑time cost vs. accuracy.  
   *Resolution evidence:* Detailed cost‑performance curves for different top‑k values and memory sizes, considering both accuracy and token budget constraints.

## Limitations
- Template index generation/embedding algorithm is unspecified, risking retrieval relevance.
- Template merge policy when CTM exceeds 30 items is vague, potentially causing redundancy or loss of useful strategies.
- EPM retrieves all patterns unconditionally, which may prompt‑saturate; optimal filtering unknown.
- Cold‑start generalization to unseen domains not evaluated.

## Confidence
- CTM enables cross‑task strategy transfer: **Medium**
- EPM reduces repeated failures via negative constraints: **Medium**
- Iterative self‑reflection improves answer quality: **Medium**

## Next Checks
1. **Index formulation study:** Compare different index designs (e.g., slot‑based vs. free‑text) on retrieval precision and final accuracy across tasks.
2. **Merge policy ablation:** Vary merge thresholds (e.g., similarity > 0.8 vs. 0.9) and strategies (pairwise vs. hierarchical clustering) to measure memory efficiency and performance trade‑offs.
3. **Zero‑domain evaluation:** Test MemAPO on tasks from entirely new domains (e.g., scientific QA) without pre‑accumulated memory to quantify cold‑start capability and need for seeding.
