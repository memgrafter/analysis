# CFRecs: Counterfactual Recommendations on Real Estate User Listing Interaction Graphs
## Quick Facts
*   **arXiv ID:** 2602.05861
*   **Source URL:** https://arxiv.org/abs/2602.05861
*   **Reference Count:** 26
*   **Primary Result:** A two-stage GNN/VAE framework generates valid, sparse counterfactual graph perturbations that increase predicted transaction probability by an average of 7.2% on real-world data.

## Executive Summary
CFRecs addresses the need for actionable, data-driven advice in real estate by generating counterfactual modifications to user-listing interaction graphs. The method proposes that minimal, valid changes to a user's interaction history or a listing's price can significantly improve the chance of a transaction. It frames this as a graph modification problem, trained and evaluated on a large, proprietary dataset from Zillow. The work demonstrates a practical application of graph generative models for prescriptive analytics in a high-stakes domain.

## Method Summary
The approach uses a two-stage pipeline. First, a Relational Graph Convolutional Network (GCN) classifier is trained to predict the binary transaction outcome from a subgraph of user-listing interactions and attributes. This classifier serves as an oracle for the second stage. Second, a Graph Variational Autoencoder (VAE) is trained to generate perturbations. The VAE's encoder produces node latent distributions, and its decoder reconstructs node features (user preferences, listing price) and edge probabilities. The VAE is trained with a composite loss that balances reconstruction fidelity, a counterfactual margin ranking loss (to maximize the oracle's predicted probability for the modified graph), a KL divergence, and explicit sparsity regularization. Generated edges and node feature changes are binarized/thresholded to produce the final, sparse counterfactual graph.

## Key Results
*   The GNN classifier achieves a test ROC-AUC of **71.3%** on Zillow's dataset.
*   Generated counterfactual graphs have an **83% success rate** (positive lift) with an average improvement of **7.2%** in predicted transaction probability.
*   Counterfactuals drive significant engagement increases: views (+18.6%), saves (+17.3%), and submits (+40.7%).

## Why This Works (Mechanism)
The method works by explicitly optimizing graph modifications against a learned, differentiable model of transaction probability. The VAE's decoder is trained to output small changes (in edges and continuous node features) that the frozen classifier scores highly. The counterfactual ranking loss encourages a margin between the factual and counterfactual predictions, pushing the generator to find *improving* perturbations. Sparsity is enforced by weighting edge reconstruction loss and by applying thresholds post-generation, ensuring recommendations are parsimonious and interpretable. The relational GNN classifier captures complex, multi-typed interaction patterns (views, saves, submits) that are predictive of a transaction, providing a meaningful oracle for the generator.

## Architecture Onboarding
**Component Map:** Subgraph Sampling -> GNN Classifier Training -> Freeze Classifier -> Graph-VAE Generator Training -> Thresholding & Validation

**Critical Path:** The classifier must first achieve meaningful predictive performance. Its weights (excluding the final prediction MLP) initialize the VAE encoder. The VAE is then trained to fool this specific, frozen classifier. The entire pipeline's success depends on the classifier's generalization and the VAE's ability to navigate the high-dimensional graph space under the composite loss.

**Design Tradeoffs:** The primary trade-off is between *modification magnitude* (sparsity) and *outcome lift*. Stronger sparsity regularization (higher α) yields fewer edge/feature changes but may limit achievable lift. The loss coefficients (α, β, γ, δ) and the margin in the counterfactual loss control this trade-off. Another trade-off is between *feature change* (price, preferences) and *structural change* (edges); the relative weights of L_X (feature loss) vs. L_I (edge loss) determine which is preferred.

**Failure Signatures:**
1.  **Classifier failure:** Test ROC-AUC << 71.3% indicates incorrect relational message passing, subgraph sampling bias, or insufficient model capacity.
2.  **Generator stagnation:** Counterfactual graphs show no lift (P_cf <= P_factual). This suggests the VAE cannot optimize the counterfactual loss, possibly due to poor coefficients, a frozen classifier that is too brittle, or gradient issues.
3.  **Unrealistic outputs:** Generated user preferences or listing prices have low cosine similarity to original values, indicating β is too low or feature reconstruction is not being prioritized.
4.  **Edge chaos:** Generated graphs are either completely dense (no sparsity) or completely empty (no lift). Indicates a misconfigured edge decoding threshold or inappropriate α.

**First 3 Experiments:**
1.  **Classifier Baselines:** Train the described Relational GCN on the 6946/500/500 split. Tune embedding dimension (e.g., 64, 128) and number of layers (2,3,4) to target ROC-AUC ~71%. Verify inclusion of the densified fourth interaction matrix (views + views²).
2.  **VAE Sanity Check:** With the best classifier frozen, train the VAE with a *reconstruction-only* loss (α=1, β=1, γ=0, δ=0). Validate that it can reconstruct node features and edges (AUC for edge reconstruction) reasonably well on a hold-out set. This establishes a functional generator before adding the counterfactual objective.
3.  **Loss Coefficient Sweep:** Train the full VAE with γ=1 (counterfactual loss) and vary α (edge weight) and β (feature weight) on a small grid (e.g., (0.2,0.5,1) for both). On a validation set, measure (a) average lift, (b) success rate (lift > 0), and (c) average sparsity (% edges changed). Identify a region that yields >5% lift with <15% edge change.

## Limitations
*   **Critical hyperparameters are unreported:** Embedding sizes, layer counts, dropout rates, VAE latent dimensions, and precise edge binarization thresholds are not specified, preventing exact replication.
*   **Loss coefficients are tuned but not disclosed:** The values of (α, β, γ, δ) and the margin *W* used for the main results are omitted; the reported performance depends on these choices.
*   **Dataset access is barred:** The proprietary Zillow dataset is not public, making external verification and comparative research impossible. Subgraph generation parameters (walk length, restart) are also unspecified.

## Confidence
*   **Claim:** GNN classifier achieves test ROC-AUC of 71.3%. **Confidence:** Medium. Architecture is described but key hyperparameters are missing; achieving this exact number likely requires unreported tuning.
*   **Claim:** Generated counterfactuals have 83% success rate and 7.2% average lift. **Confidence:** Low-Medium. These results are highly sensitive to the VAE's loss balancing and thresholds, which are underspecified.
*   **Claim:** Framework generates interpretable, sparse modifications. **Confidence:** Medium. The objective includes sparsity terms, but exact sparsity levels depend on unknown post-processing thresholds.
