# MemBuilder: Reinforcing LLMs for Long-Term Memory Construction via Attributed Dense Rewards

## Quick Facts
*   **arXiv ID:** 2601.05488
*   **Source URL:** https://arxiv.org/abs/2601.05488
*   **Reference Count:** 40
*   **Primary Result:** A 4B parameter model achieves SOTA on long-term dialogue memory benchmarks (LoCoMo 84.23%, LongMemEval 85.75%, PerLTQA 93.14%), outperforming prompting-based systems and Claude 4.5 Sonnet.

## Executive Summary
MemBuilder is a framework that trains small LLMs to construct effective long-term memories for multi-session dialogues using reinforcement learning. It addresses the credit assignment problem in long horizons by providing dense, per-session rewards via synthetic QA pairs. Furthermore, it introduces contribution-aware gradient weighting to scale policy updates based on each memory type's downstream retrieval usage. Starting from a supervised cold-start, the method yields a 4B model that significantly surpasses prior work and large proprietary models across multiple long-term memory benchmarks, demonstrating strong out-of-distribution generalization.

## Method Summary
MemBuilder employs a two-stage training process. First, a lightweight SFT phase on expert trajectories (from Claude 4.5 Sonnet) instills the ability to produce valid, structured memory operations within a multi-dimensional architecture (Core, Episodic, Semantic, Procedural). Second, RL training uses an adapted GRPO algorithm (ADRPO). For each dialogue session, the policy model proposes operations for all four memory types based on retrieved prior memories. Multiple rollouts are sampled. Dense rewards are computed per rollout by answering pre-generated synthetic questions about the just-processed session using the constructed memory bank, with accuracy as the reward signal. The policy update applies a weight to each memory type's gradient term, amplifying it for the component with the highest retrieval count during the QA evaluation.

## Key Results
*   A 4B model achieves SOTA on LoCoMo (84.23%), LongMemEval (85.75%), and PerLTQA (93.14%), outperforming prompting-based frameworks (e.g., Mem0, MIRIX) and Claude 4.5 Sonnet.
*   Generalizes effectively to out-of-distribution benchmarks (LoCoMo, PerLTQA) despite being trained solely on LongMemEval.
*   Ablations confirm that both dense intermediate rewards and contribution-aware gradient weighting are essential for the RL gains over the SFT baseline.

## Why This Works (Mechanism)

### Mechanism 1: Dense Session-Level Rewards
**Claim:** Dense session-level rewards provide effective learning signals for each memory operation in long trajectories, overcoming the credit assignment problem of sparse end-of-trajectory rewards.
**Mechanism:** For each conversation session τ, synthetic QA pairs are generated using an expert model (Claude 4.5 Opus) based on the session content and retrieved prior memories. During RL rollouts, the model's constructed memory bank M(τ) is evaluated on these questions by a judge (GPT-4.1-mini). The resulting accuracy (rtask) is assigned as a reward immediately after session τ, rather than only at the final session.
**Core Assumption:** A memory bank's utility for answering questions about the *just-processed* session correlates with its long-term downstream utility; thus, per-session evaluation provides a valid, dense training signal.
**Evidence Anchors:** [abstract] mentions "synthetic session-level question generation to provide dense intermediate rewards." [section 3.4.1] details the synthetic QA generation and reward formula. Related work explores dense rewards but this specific per-session approach for multi-session dialogue is novel.
**Break Condition:** If the synthetic questions fail to be representative of the *true* distribution of long-term downstream questions (e.g., too simple, lack temporal reasoning), optimizing for them may not improve final QA performance.

### Mechanism 2: Contribution-Aware Gradient Weighting
**Claim:** Contribution-aware gradient weighting resolves the multi-dimensional memory attribution problem by scaling policy updates based on each memory component's downstream retrieval usage.
**Mechanism:** After N rollouts for a session, the QA answering phase retrieves from each candidate memory bank. Retrieval counts h(m) for Episodic, Semantic, and Procedural memories are recorded. The memory type with the highest count (dominant contributor d) receives an amplified gradient weight α > 1 (empirically α=4), while others use weight 1. Core Memory, always included in context, uses fixed weight 1. This scales the unclipped term in the PPO-style objective.
**Core Assumption:** The frequency with which a memory component's entries are retrieved during question answering is a reliable proxy for its contribution to the session's task reward; thus, amplifying its gradient updates the policy to improve that component's construction.
**Evidence Anchors:** [abstract] states "contribution-aware gradient weighting that scales policy updates based on each component’s downstream impact." [section 3.4.2] defines the dominant contributor and weight assignment, explicitly linking gradient magnitude to retrieval counts.
**Break Condition:** If retrieval count does not strongly correlate with *actual* contribution to answer correctness (e.g., frequently retrieved but contains noise), weighting by count misattributes credit and harms learning.

### Mechanism 3: Multi-Dimensional Memory Architecture
**Claim:** A multi-dimensional memory architecture with specialized action spaces enables more organized, retrievable, and temporally-aware storage than monolithic or RAG-chunk approaches, which is necessary for effective long-term dialogue.
**Mechanism:** The memory bank M is decomposed into four components with distinct roles and operations (e.g., Core uses {APPEND, REPLACE, REWRITE}; Episodic uses {ADD, UPDATE, MERGE}). The same LLM acts as four parallel "agents," each receiving the same input but outputting operations specific to its memory type. This structure forces semantic separation (e.g., events vs. facts) and preserves temporal history via UPDATE/MERGE that reference previous entries.
**Core Assumption:** Decomposing memory along cognitive dimensions yields a representation more effective for selective retrieval and temporal reasoning than treating history as a flat sequence of text chunks.
**Evidence Anchors:** [abstract] mentions "multi-dimensional memory design." [section 3.2] defines the four memory types and their distinct action spaces. [section 4.4.2] shows RL training changes action distributions (e.g., Core shifts to REPLACE), indicating the model learns dimensional distinctions.
**Break Condition:** If the overhead of maintaining four separate stores and the cognitive load on the policy model outweigh the benefits—e.g., if retrieval frequently needs to cross boundaries or the optimal structure is domain-specific—this architecture could be suboptimal.

## Foundational Learning
*   **Concept: Reinforcement Learning with Policy Gradients (e.g., PPO/GRPO)**
    *   *Why needed here:* ADRPO extends GRPO. Understanding advantage estimates, clipping, and reference models is essential for the training objective (Equation 12) and how attributed rewards/weights integrate.
    *   *Quick check question:* In the GRPO objective, what is the purpose of the clipping term in the `min()` function, and what would happen if it were removed?

*   **Concept: Retrieval-Augmented Generation (RAG) and Memory Architectures**
    *   *Why needed here:* MemBuilder's construction phase builds a structured store for later retrieval. The framework contrasts with standard RAG (static chunks) and prompting-based systems. Understanding RAG's limitations contextualizes the proposed multi-dimensional memory.
    *   *Quick check question:* Why might retrieving from pre-structured episodic/semantic memories be more effective for temporal reasoning questions than retrieving from raw session chunks?

*   **Concept: Long-Horizon Credit Assignment in Dialogue**
    *   *Why needed here:* The core problem is assigning credit for memory operations made dozens of sessions earlier to a final QA outcome. This requires understanding why sparse rewards fail in long-horizon tasks and how dense intermediate rewards attempt to solve it.
    *   *Quick check question:* If you only get a reward after 30 sessions, why is it difficult for an RL agent to know whether an operation in session 5 was good or bad?

## Architecture Onboarding
*   **Component map:** Policy Model (Qwen3-4B-Instruct) -> Memory Bank (4 components: Core, Episodic, Semantic, Procedural) <- Retrieval System (text-embedding-3-small). Reward Computation -> QA Judge (GPT-4.1-mini) + Answer Model (Claude 4.5 Sonnet). Orchestrator (ADRPO in verl framework) coordinates rollouts, reward calculation, and weighted gradient updates.
*   **Critical path:**
    1.  **Session Processing:** For session τ: retrieve top-20 from M(τ-1) -> policy infers 4 memory operations -> update M(τ).
    2.  **Rollout Branching:** At session τ, sample N rollouts producing N candidate M(τ)^i.
    3.  **Reward Evaluation:** For each M(τ)^i, answer pre-generated questions -> judge scores -> compute r_task^i.
    4.  **Attribution:** For each M(τ)^i, run QA retrieval -> count h(m) per memory type -> identify dominant type -> assign weights w(m).
    5.  **Gradient Update:** Compute advantages A^i (within-group normalized). For each token of each memory type's output, apply weighted GRPO loss with clip(ρ,1-ϵ,1+ϵ)A^i and w(m) on unclipped term. Backpropagate sum.
*   **Design tradeoffs:**
    *   **Dense rewards vs. compute cost:** Gen/eval of synthetic QA per session drastically increases API calls but provides learning signals. Tradeoff: training cost vs. sample efficiency.
    *   **Contribution weighting vs. stability:** Amplifying gradients for "dominant" type (α=4) improves performance but risks destabilizing other types. Requires careful α tuning.
    *   **Multi-dimensional orchestration vs. complexity:** Four separate agents increase action space complexity and risk invalid outputs. Mitigated by SFT cold-start. A monolithic memory might be simpler but less organized.
*   **Failure signatures:**
    *   High invalid action rate (>5-10%): indicates policy not respecting JSON schema/action space. Likely need more SFT or better prompt engineering.
    *   Reward hacking via verbose memory: if average memory lengths grow unbounded, the length penalty ℓ is insufficient. Check ℓ thresholds and λ weight.
    *   Severe imbalance in memory type usage: e.g., Core always APPEND, Procedural never UPDATE. Suggests policy hasn't learned semantic distinctions or synthetic rewards don't incentivize them.
    *   OOD performance collapse: if LoCoMo/PerLTQA scores drop far below LongMemEval, synthetic QA distribution may not generalize. Check synthetic question diversity and retrieval parameters.
*   **First 3 experiments:**
    1.  **SFT Cold-Start Validation:** Train RL from base model vs. SFT checkpoint. Expect RL-from-base to underperform (79.31% vs 84.23% on LoCoMo) due to invalid actions. Confirms SFT's stabilizing role.
    2.  **Gradient Weighting Ablation:** Vary α ∈ {1,2,4,8,16}. Expect peak at α=4. α=1 (no weighting) lower; α=16 (over-amplification) lower. Validates contribution-aware scaling.
    3.  **Reward Density Ablation:** Train with reward density 1/d (d∈{1,2,4,8}). Expect performance to degrade monotonically as density decreases. At density 1/8, performance falls below SFT baseline, confirming dense rewards are necessary.

## Open Questions the Paper Calls Out
*   **Open Question 1:** How do inaccuracies or ambiguities in synthetic QA pairs affect the stability and final performance of MemBuilder's RL training? The paper acknowledges potential noise in synthetic data but does not investigate its impact on learning.
*   **Open Question 2:** What are the boundaries of MemBuilder's out-of-distribution generalization? Are there dialogue domains, lengths, or question complexities beyond which the trained model fails? Generalization was tested on similar long-term benchmarks, not on drastically different settings.
*   **Open Question 3:** Is retrieval count an optimal measure for contribution-aware gradient weighting, or can more nuanced attribution methods further improve memory construction? The current heuristic assumes frequency equals contribution; more sophisticated attribution (e.g., answer relevancy, Shapley values) may yield finer-grained credit assignment.
*   **Open Question 4:** Can the dependency on expert SFT trajectories for cold-start be reduced or eliminated without sacrificing training stability or final performance? Relying on closed-source experts introduces cost and bias; alternative cold-start strategies are unexplored.

## Limitations
*   **Hyperparameter Gaps:** Exact SFT/RL training details (optimizer settings, scheduler, sequence length, exact synthetic QA filtering) are unspecified, hindering faithful replication.
*   **Attribution Heuristic:** The retrieval-count based gradient weighting is a heuristic with no guarantee that frequency correlates with true contribution to answer correctness.
*   **Architectural Overhead:** The multi-dimensional memory design introduces action space complexity and orchestration cost; its benefit relative to a simpler flat memory store is not benchmarked.

## Confidence
*   **Dense Rewards Effectiveness:** Medium. Evidence from ablations is strong, but the break condition (synthetic QA representativeness) is unvalidated, risking distribution shift.
*   **Contribution Weighting Utility:** Medium. The heuristic shows empirical gains (α=4), but the core assumption (retrieval count ≈ contribution) is unproven and may misattribute credit.
*   **Multi-Dimensional Memory Necessity:** Medium. Supported by action distribution shifts, but the overhead vs. flat memory tradeoff is not measured, and generalization to other domains is unknown.

## Next Checks

2.  **Retrieval-Contribution Correlation:** For held-out dialogues, systematically ablate retrieval from each memory type (Episodic/Semantic/Procedural) and measure the impact on QA accuracy to test if count-based weighting aligns with actual utility.
