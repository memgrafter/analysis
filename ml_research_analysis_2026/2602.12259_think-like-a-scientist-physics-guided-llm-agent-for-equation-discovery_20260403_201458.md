# Think like a Scientist: Physics-guided LLM Agent for Equation Discovery

## Quick Facts
- arXiv ID: 2602.12259
- Source URL: https://arxiv.org/abs/2602.12259
- Reference count: 40
- Primary result: KeplerAgent achieves substantially higher symbolic accuracy (42.34% on LSR-Transform; 75%/45% on clean/noisy DiffEq) and lower normalized MSE compared to baselines, with better long-term prediction robustness and lower compute consumption.

## Executive Summary
KeplerAgent is a physics-guided LLM agent for equation discovery that mimics a scientist’s multi‑step reasoning. It iteratively calls physics‑based tools (e.g., symmetry discovery, visual analysis) to extract structural properties from data and then configures symbolic regression backends (PySINDy, PySR) with those constraints. By pruning the hypothesis space with physical insights, it outperforms direct LLM‑to‑equation methods on benchmarks and exhibits greater robustness to noise.

## Method Summary
The framework centers on a ReAct‑style agent (GPT‑4o‑mini) that maintains a shared workspace (files) and an experience log (history of tool calls and outcomes). The agent is instructed to first use a python_interpreter for exploratory analysis. Based on the data type and findings, it then invokes a symmetry_discovery tool (fits a Lie generator matrix via equivariance loss) or a visual_subagent (converts plots into operator recommendations). These intermediate results are automatically translated into concrete arguments for symbolic regression tools: PySINDy receives a symmetry constraint (`use_symmetry=True`, `lie_generator`), while PySR may receive a template expression (`expression_spec`) to guide its search. The loop repeats, refining configurations using past results, until the prediction error (MAPE) falls below 0.1% or a maximum iteration limit is reached.

## Key Results
- Symbolic accuracy: 42.34% on LSR‑Transform (vs. PySR 37.84%, LLM‑SR 31.53%); 75% on clean DiffEq (vs. PySR 40%) and 45% on noisy DiffEq (vs. PySR 15%).
- Lower normalized pointwise and long‑term prediction errors.
- More compute‑efficient than LLM‑SR; comparable runtime to PySR but with higher accuracy.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: The LLM agent’s orchestration of physics‑based tools extracts intermediate structural properties (symmetries, functional forms) that meaningfully constrain the symbolic regression search space, reducing hypothesis complexity compared to direct equation guessing.
- **Mechanism**: The agent calls specialized tools to analyze data and infer physical invariants. For differential equations, the symmetry discovery tool computes a Lie generator matrix from the data, which is then fed to PySINDy as `lie_generator` to restrict the parameter space to an equivariant subspace. Visual subagents convert plots into operator recommendations, and code interpreters provide statistics. These structured findings are translated into concrete SR backend configurations, reducing the effective search space.
- **Core assumption**: Physical systems often possess exploitable structure (symmetries, separability, etc.) that, when correctly identified, prunes the space of plausible equations without eliminating the true model.
- **Evidence anchors**: Abstract mentions “coordinates physics‑based tools to extract intermediate structure and uses these results to configure symbolic regression engines… substantially higher symbolic accuracy.” Section 3.3 details tool specifications (e.g., feeding symmetry matrix to PySINDy). Neighboring work (LLM‑SR, SR‑Scientist) confirms the gap: current LLM‑SR “largely treat equation discovery as a relatively direct mapping from data to an expression.”
- **Break condition**: If the system lacks discoverable structure with the provided tools, or the agent misinterprets tool outputs (e.g., incorrect symmetry), the constrained search may exclude the true equation.

### Mechanism 2
- **Claim**: The agent’s iterative reasoning cycle, mediated by a shared workspace and experience log, enables progressive refinement of both the hypothesis space and candidate equations, mimicking the human scientist’s workflow of probe → infer → constrain → search.
- **Mechanism**: At each step, the agent observes workspace files and the experience log (past tool calls/outcomes), reasons about the next action, and calls a tool. Tools write results to both. The agent uses this state to avoid redundancy (e.g., repeating identical calls) and build cumulative knowledge (e.g., learning from a low‑MAPE equation to adjust SR parameters). This closed loop allows hypotheses to be refined across iterations.
- **Core assumption**: Stepwise accumulation of intermediate findings provides a more reliable foundation for final equation selection than a single end‑to‑end mapping from raw data to equation.
- **Evidence anchors**: Section 3.2: “The agent reads and writes to a shared workspace… and an experience log… allowing it to progressively narrow the hypothesis space.” Section 3.4: Experience log records “each tool invocation, its arguments, and a textual summary” to avoid redundancy. Appendix C.2 trace shows agent using symmetry result from Step 2 to configure SINDy in Step 3, then adjusting polynomial degree after observing unchanged MAPE in Step 4.
- **Break condition**: If the agent fails to integrate past results (e.g., ignores a discovered symmetry, repeats failed configurations), the iterative process degenerates into random search.

### Mechanism 3
- **Claim**: Automatic translation of intermediate structural findings into concrete SR backend parameters (function library, constraints, template expressions) by the LLM agent bridges the gap between abstract physical insights and actionable algorithmic configurations, the primary bottleneck in traditional SR.
- **Mechanism**: The agent maps high‑level findings to tool‑specific arguments. For example, a discovered rotation symmetry matrix `[[0,-1],[1,0]]` is passed as `lie_generator` to PySINDy with `use_symmetry=True`. A visualization suggesting periodicity leads to a PySR template like `sin(f(x1)) + g(x2)`. This automation replaces manual expert tuning, making constraint‑based SR accessible.
- **Core assumption**: LLMs possess sufficient meta‑knowledge about SR tool APIs and the semantics of physical properties to perform this translation correctly without human intervention.
- **Evidence anchors**: Section 3.3: PySINDy tool spec exposes `use_symmetry` and `lie_generator`; PySR tool spec prioritizes `expression_spec` as “crucial for reducing the hypothesis space.” Section 4.5: KeplerAgent achieves 75% SA on clean DiffEq vs. PySR’s 40%, demonstrating automated constraint application outperforms default configurations. Corpus: LLM‑SRBench evaluation shows “LLM‑guided methods can outperform many classical baselines” but “exact recovery rates remain modest,” implying naive LLM equation proposal without structured constraint translation is insufficient.
- **Break condition**: If the agent proposes invalid tool arguments (malformed `expression_spec`, incorrect `lie_generator` shape) or misapplies constraints (over‑restrictive library that omits necessary terms), the SR backend may fail to find the true equation.

## Architecture Onboarding

**Component map**  
LLM Agent (GPT‑4o‑mini) orchestrates tools (python_interpreter, visual_subagent, symmetry_discovery, pysindy, pysr). All tools read/write to a shared workspace (file directory) and an experience log (textual history). The agent observes the workspace and log to decide next actions.

**Critical path**  
1. Initial analysis: Agent must call `python_interpreter` first (unless prior experience exists).  
2. Structure inference: Based on data type and analysis, agent calls `symmetry_discovery` or `visual_subagent`.  
3. SR configuration: Agent selects `pysindy` (for ODE/PDE with linear‑in‑parameters form) or `pysr` (for general forms), translating insights into arguments (`lie_generator`, `expression_spec`).  
4. Refinement: If MAPE ≥ 0.1%, agent returns to step 2 or 3, adjusting parameters using past results from the log.  
5. Termination: When MAPE < 0.1% (or max iterations reached), agent outputs `final_result`.

**Design tradeoffs**  
- Tool specification depth vs. context length: Exposing many SR parameters confuses the agent; the paper limits to crucial ones (e.g., `expression_spec`) to simplify decisions, but may sacrifice fine‑grained control.  
- Stopping criterion rigidity: The 0.1% MAPE threshold is strict for noisy real data, causing wasted iterations; mitigated by a max‑iteration cap.  
- Symmetry discovery fidelity: The tool optimizes a numerical Lie generator; slight errors may require agent “rounding” to exact forms (e.g., 0.678 → 1 for rotation), an inference step not guaranteed.

**Failure signatures**  
- Repetitive tool calls: Agent repeats calls with negligible parameter changes (e.g., unchanged polynomial degree).  
- Tool under‑utilization: Agent skips `symmetry_discovery` for PDEs where it could help, or never uses `visual_subagent` if no plots generated early.  
- Invalid arguments: Malformed `expression_spec` or mismatched `lie_generator` dimensions cause tool failures.  
- Stuck in local optima: Agent settles on medium‑MAPE equation without trying alternative tools (e.g., switching from `pysindy` to `pysr`).

**First 3 experiments**  
1. **LSR‑Transform benchmark**: Compare symbolic accuracy and runtime against PySR and LLM‑SR on 111 transformed algebraic equations; verifies physics‑guided constraint translation improves SA while using less compute.  
2. **DiffEq clean/noisy benchmark**: Test on 10 ODE/PDE systems (20 equations). Measures SA, pointwise NMSE, and long‑term prediction error; validates robustness to noise and superior simulation stability.  
3. **Reaction‑diffusion case study**: Inspect agent’s reasoning trace on a challenging PDE; reveals strengths (using symmetry to reduce MAPE) and weaknesses (failure to further improve or switch tools), highlighting iterative refinement limitations.

## Open Questions the Paper Calls Out
1. **Expanding the physics toolset** – How can the toolset be expanded with additional physics‑based tools (e.g., dimensional analysis, bifurcation structure) while managing context window growth and avoiding performance degradation?  
   *Explicit basis*: “Scaling up the toolbox raises a practical challenge: the tool specifications inflate the context and make it harder for the agent to remember earlier information. The broader LLM‑agent literature suggests remedies, such as decomposing the main agent’s planning and executing functionality into subagents or a workflow graph with multiple nodes, or using retrieval‑augmented generation to select only a small subset of relevant tools at each iteration. Adapting these ideas to our toolkits is a natural next step.”

2. **Tool selection for large toolkits** – Can retrieval‑augmented generation (RAG) or multi‑agent decomposition effectively reduce the tool selection burden in large physics toolkits, enabling dynamic choice of only the most relevant tools per step without losing necessary context?  
   *Explicit basis*: “The broader LLM‑agent literature suggests remedies, such as decomposing the main agent’s planning and executing functionality into subagents or a workflow graph with multiple nodes, or using retrieval‑augmented generation… to select only a small subset of relevant tools at each iteration.”

3. **Extending symmetry discovery to nonlinear symmetries** – How can the symmetry discovery tool be extended to handle nonlinear symmetries and symmetries that involve independent variables (e.g., time) in differential equation systems?  
   *Explicit basis*: “The equivariance error in (1) is only applicable to linear symmetries acting solely on dependent variables. More generally, some symmetries of differential equation systems can act with nonlinear functions on the total space containing both independent variables and dependent variables. We may still use an equivariance error term for discovering those symmetries, but the exact formulation would be different from (1) and likely more complicated.”

4. **Formalizing agent reasoning via structured state space** – How can we formalize the agent’s reasoning process via a structured state space, where each state encodes the current hypothesis space of equations and tools perform explicit state transformations, to improve interpretability and systematic analysis?  
   *Explicit basis*: “Another complementary direction is to make the agent’s internal reasoning more explicit by defining a structured state space for symbolic regression. Each state would represent the current hypothesis space of equations with active constraints, and each tool would perform a well‑defined transformation of this state. Such a formulation explicitly formalizes the agent’s reasoning process, yielding more controlled behavior and making it easier to systematically analyze its reasoning trajectories across datasets and tasks.”

## Limitations
- Exact hyperparameters for the `symmetry_discovery` tool (network architecture, optimizer, convergence criteria, matrix regularization) are omitted, hindering exact replication and possibly affecting constraint reliability.
- The format of the initial user query and required prior knowledge are unspecified, leading to variability in agent behavior and reproducibility.
- Evaluation is restricted to synthetic benchmarks (LSR‑Transform, DiffEq); real‑world data may contain different noise, sparsity, and complexity, so generalization remains unproven.

## Confidence
- Physics‑based constraints prunes search space: **High** (theoretically grounded and empirically supported).
- Iterative reasoning progressively refines hypotheses: **Medium** (evidence from traces, but repetitive loops indicate brittleness).
- Overall outperformance on benchmarks: **Medium** (consistent results on curated datasets; real‑world robustness uncertain).
- Automatic translation of insights into SR configurations: **Medium** (often useful but occasional misapplications).
