# Benchmarking Few-shot Transferability of Pre-trained Models with Improved Evaluation Protocols

## Quick Facts
- **ArXiv ID:** 2603.00478
- **Source URL:** https://arxiv.org/abs/2603.00478
- **Reference Count:** 40
- **Primary Result:** The Hyperparameter Ensemble (HPE) protocol enables robust, label-free evaluation in few-shot regimes, revealing that full-parameter fine-tuning (Full-FT) via distributed "micro-adjustments" and pre-trained model choice are dominant factors, while many advanced transfer algorithms offer negligible gains.

## Executive Summary
The paper identifies critical flaws in few-shot transfer learning evaluation—the "validation setillusion" from unreliable hyperparameter tuning with scarce data and the "sampling lottery" from high variance due to limited task sampling. It introduces the FEWTRANS benchmark (10 diverse datasets) and the Hyperparameter Ensemble (HPE) protocol, which aggregates predictions across a hyperparameter grid to eliminate the need for validation sets. Key findings show that the choice of pre-trained model (e.g., DINOv2, CLIP) is the primary performance driver, and that simple full-parameter fine-tuning (Full-FT) consistently outperforms more sophisticated parameter-efficient methods (e.g., LoRA, prompt tuning). Mechanistically, Full-FT succeeds by making small, distributed updates that reshape high-level features without overfitting. For multimodal models like CLIP, the study quantifies a severe performance drop on domains with linguistically rare class names (e.g., Fungi), establishing a strong negative correlation (ρ = -0.881) between text rarity and adaptation gain.

## Method Summary
The core contribution is the FEWTRANS benchmark coupled with the Hyperparameter Ensemble (HPE) evaluation protocol. FEWTRANS comprises 10 curated datasets spanning natural and specialized domains, each with predefined base/novel class splits for multimodal evaluation. The protocol samples 600 tasks per dataset, where each task involves a variable number of classes (2–15) and imbalanced few-shot support sets (≤10 shots per class). For each task, a pre-defined hyperparameter grid (3×3×3 for unimodal; 5×3 for multimodal) is applied: multiple models are trained on the same support set under different learning rates and epochs. Final predictions are made by averaging logits across all grid configurations, thereby avoiding validation-based hyperparameter selection. Performance is reported as mean accuracy with 95% confidence intervals over all tasks, enabling robust comparisons of pre-trained models and transfer algorithms under extreme data scarcity.

## Key Results
- Pre-trained model selection (e.g., DINOv2, CLIP) is the dominant factor in few-shot transfer performance; many sophisticated transfer algorithms (LoRA, prompt tuning) provide no significant advantage over full-parameter fine-tuning (Full-FT).
- Full-FT avoids overfitting via distributed "micro-adjustments" (small parameter updates across all layers) that reshape high-level features without leaving the flat minima basin of the pre-trained model.
- Multimodal models (CLIP) exhibit a performance collapse on domains with linguistically rare class names; a strong negative correlation (ρ = -0.881) exists between adjusted Zipf frequency of class names and adaptation gain, which Full-FT mitigates by directly aligning visual features.

## Why This Works (Mechanism)

**Mechanism 1: Hyperparameter Ensemble (HPE) mitigates the "validation set illusion"**
- **Claim:** HPE aggregates predictions across a hyperparameter grid, eliminating the need for a separate validation set in extreme few-shot regimes.
- **Mechanism:** For each task, multiple models are trained with different learning rates and epochs on the same small support set. Test-time logits are averaged across all configurations, implicitly capturing the high-performance region of the hyperparameter landscape without validation-based selection.
- **Core assumption:** The loss landscape around optimal hyperparameters is relatively flat; thus, averaging across a grid that includes the optimal region stabilizes performance against volatile configurations.
- **Evidence anchors:** [abstract] "propose the Hyperparameter Ensemble (HPE) protocol to overcome the 'validation set illusion'"; [section V.A] Formal definition of logit averaging and robustness analysis showing HPE approximates Oracle best.
- **Break condition:** If the pre-defined hyperparameter grid completely misses the optimal region (e.g., all learning rates are too high/low), HPE cannot recover performance and may degrade below the best single configuration.

**Mechanism 2: Full-parameter fine-tuning (Full-FT) avoids overfitting via "micro-adjustments"**
- **Claim:** Full-FT applies very small parameter updates across all layers, preserving pre-trained knowledge while reshaping high-level features without overfitting.
- **Mechanism:** Layer-wise analysis shows Full-FT yields small ΔW norms (L2 ~0.01–0.07), especially in deeper blocks, keeping updates within the flat minima basin. Concurrently, Centered Kernel Alignment (CKA) reveals larger feature distribution shifts in deep layers, indicating effective task-specific reshaping.
- **Core assumption:** Pre-trained models reside in broad, flat minima basins; small perturbations maintain generalization while allowing specialization.
- **Evidence anchors:** [abstract] "full fine-tuning succeeds via distributed 'micro-adjustments' and more flexible reshaping of high-level semantic representations"; [section VI.A] Parameter update heatmaps and CKA similarity plots (Figure 5).
- **Break condition:** If the downstream task is highly dissimilar to pre-training data, even micro-adjustments may not align features sufficiently, or larger updates might be necessary, increasing overfitting risk.

**Mechanism 3: Multimodal failure due to linguistic rarity**
- **Claim:** CLIP's zero-shot capability fails on domains with linguistically rare class names because the text encoder provides poor initialization; Full-FT compensates by directly aligning visual features.
- **Mechanism:** Adjusted Zipf scores quantify term rarity in downstream class names. A strong negative correlation (ρ = -0.881) exists between text rarity and few-shot adaptation gain. When textual anchors are rare (e.g., *Agaricus cupreobrunneus*), prompt-based methods fail, forcing Full-FT to re-align visual representations from scratch.
- **Core assumption:** CLIP relies on common language semantics in its pre-training corpus; rare terms create "textual silence" that prompt-based methods cannot overcome.
- **Evidence anchors:** [abstract] "quantify the performance collapse of multimodal models in specialized domains as a result of linguistic rarity"; [section VI.C] Scatter plot (Figure 6) and discussion of vocabulary/compositional/technical shifts.
- **Break condition:** If the pre-training corpus already covers the rare terminology (e.g., domain-specific corpora), the negative correlation weakens, and prompt-based methods may recover without Full-FT.

## Architecture Onboarding
**Component map:** Dataset filter -> Task sampler -> Hyperparameter grid -> Trainer -> Ensemble aggregator -> Evaluator

**Critical path:**  
1. Filter datasets for multimodal compatibility, diversity, and integrity.  
2. Determine base hyperparameter ranges on a held-out dataset.  
3. For each of 600 tasks per dataset: sample support/query sets.  
4. For each hyperparameter config: adapt pre-trained model on support set.  
5. Aggregate test logits across all configs → predict labels.  
6. Report mean accuracy and 95% CI across all tasks.

**Design tradeoffs:**  
- *Grid size vs. compute:* Larger grids improve oracle approximation but increase training cost linearly.  
- *Dataset diversity vs. noise:* Including rare-domain datasets (e.g., Fungi) reveals text shift but may have label noise; filtering mitigates but reduces challenge.  
- *HPE stability vs. individual peaks:* Ensemble smooths volatility but may dilute a configuration that excels on a narrow task distribution.

**Failure signatures:**  
- High variance (wide 95% CI) across 600 tasks → insufficient task sampling or overly sensitive algorithm.  
- HPE score significantly below Oracle best → hyperparameter grid missed optimal region or loss landscape is exceptionally sharp.  
- CKA similarity remains high in deep layers after Full-FT → adaptation failed to reshape features; likely poor learning rate or insufficient training.

**First 3 experiments:**  
1. *HPE vs. Oracle validation:* For a fixed pre-trained model and dataset, compute Oracle best (oracle selection on held-out data) and HPE score across 600 tasks. HPE should approximate Oracle within ~2% if grid is adequate.  
2. *Full-FT micro-adjustment replication:* Train Full-FT and LoRA on a 1-shot task; compute layer-wise ΔW L2 norms and CKA. Expect Full-FT: small ΔW (0.01–0.07) and lower deep-layer CKA vs. LoRA.  
3. *Text rarity correlation:* For CLIP on all 10 datasets, compute adjusted Zipf scores for class names and plot adaptation gain (HPE accuracy - zero-shot) vs. Zipf. Expect negative Spearman ρ ≈ -0.88.

## Open Questions the Paper Calls Out
1. Under what theoretical conditions does the Hyperparameter Ensemble (HPE) protocol provably approximate the Oracle best hyperparameter performance in non-convex, few-shot optimization landscapes?
2. What specific mechanistic properties of full-parameter fine-tuning (Full-FT) enable it to avoid catastrophic overfitting in extreme few-shot regimes, and why do parameter-efficient fine-tuning (PEFT) methods fail to replicate this despite constraining update magnitudes?
3. To what extent does the "text domain shift" quantified by adjusted Zipf scores directly cause the failure of multimodal (e.g., CLIP) zero-shot transfer, and can this be mitigated algorithmically without full fine-tuning?
4. How should few-shot benchmarks be designed to evaluate the trade-off between adaptation performance and computational/efficiency metrics (e.g., peak memory, training time), and does the current dominance of pre-trained model choice hold when these costs are explicitly normalized?
5. Does the "sampling lottery" effect—the extreme performance variance from task sampling—exhibit predictable structure (e.g., tied to dataset intrinsic properties like class in-image variance or inter-class similarity), or is it fundamentally random noise?

## Limitations
- The held-out dataset used to center the hyperparameter grid is unspecified, risking mis-scaled ranges.
- Exact base/novel class splits and random seeds for task sampling are not provided, hindering precise replication of the 600-task distribution.
- HPE’s robustness assumes the grid encompasses the optimal region; a narrow or offset grid could cause significant underperformance relative to Oracle.

## Confidence
- HPE mitigates validation set illusion: **Medium** (grid coverage uncertain).
- Full-FT succeeds via micro-adjustments: **Medium** (empirical but task-dependent).
- Text rarity causes multimodal failure: **Medium** (strong correlation but limited datasets).
- Pre-trained model choice dominates algorithm design: **High** (consistent across extensive comparisons).

## Next Checks
