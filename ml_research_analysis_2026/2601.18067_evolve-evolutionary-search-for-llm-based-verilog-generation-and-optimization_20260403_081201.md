# EvolVE: Evolutionary Search for LLM-based Verilog Generation and Optimization

## Quick Facts
- **arXiv ID:** 2601.18067
- **Source URL:** https://arxiv.org/abs/2601.18067
- **Reference count:** 40
- **Primary result:** Achieves state-of-the-art functional pass rates (98.1% on VerilogEval v2) and reduces PPA product by up to 66% on IC-RTL, surpassing human reference implementations.

## Executive Summary
Automating Verilog hardware design with LLMs is hindered by their sequential reasoning biases and lack of domain-specific training data. This paper introduces EvolVE, an evolutionary framework that combines Monte Carlo Tree Search (MCTS) for functional correctness, Idea-Guided Refinement (IGR) for Power, Performance, Area (PPA) optimization, and Structured Testbench Generation (STG) for fine-grained feedback. Evaluated on established benchmarks (VerilogEval v2, RTLLM v2) and a new PPA suite (IC-RTL), EvolVE sets new records in functional pass rates and significantly outperforms human designs in PPA, while STG reduces token consumption by over 60%.

## Method Summary
EvolVE operates without model fine-tuning. Starting from a natural language specification, an LLM generates an initial Verilog candidate. The framework then enters an evolutionary loop: a search controller (MCTS or IGR) selects a parent design from an archive, prompts the LLM to create a child modification using the parent’s code and feedback, and evaluates the child via STG and RTL simulation. MCTS builds a tree with UCT-based selection to exploit promising branches; IGR first generates diverse architectural ideas, then sequentially refines each. STG automatically parses the DUT’s ports, generates test vectors (exhaustive or constrained-random), and computes a continuous correctness score. Evaluation uses open-source tools (Icarus Verilog, Yosys) for rapid iteration, with commercial EDA tools reserved for final validation. Standard budgets include 300 nodes per problem and LLM temperature 0.6.

## Key Results
- **Functional correctness:** 98.1% pass rate on VerilogEval v2 and 92% on RTLLM v2, setting new state-of-the-art.
- **PPA optimization:** Reduces the Area × Latency product by up to 66% on Huffman Coding and by 17% in geometric mean across all IC-RTL tasks, beating human references.
- **Efficiency:** Structured Testbench Generation (STG) cuts token consumption by over 60% for DeepSeek-R1-FP4 by providing dense feedback.

## Why This Works (Mechanism)
**Monte Carlo Tree Search (MCTS)** maximizes functional correctness by structuring the design space as a tree. Nodes represent Verilog candidates; the UCT formula balances exploration of untested modifications with exploitation of high-scoring designs. Each iteration selects a leaf node, prompts the LLM for a child based on parent feedback, evaluates it via simulation, and backpropagates the score. This incremental approach efficiently navigates a vast, non-smooth space where small edits yield large functional swings. The search stops when a candidate passes all tests or the node budget is exhausted.

**Idea-Guided Refinement (IGR)** excels at PPA optimization by enabling global architectural exploration. It first generates `k` diverse high-level ideas (e.g., “use a systolic array”), then sequentially refines each idea over `m` steps with differential edits. This multi-start approach avoids the local optima that a single-tree search (like MCTS) might converge to when optimizing multi-objective metrics. The assumption is that PPA gains require fundamental architectural changes, not local RTL tweaks. Chains terminate after `m` steps or no improvement.

**Structured Testbench Generation (STG)** accelerates convergence by providing dense, fine-grained functional feedback. It parses the DUT’s ports into semantic classes (Clock/Reset, Control, Datapath) and auto-generates exhaustive (for small buses) or constrained-random vectors. Instead of binary pass/fail, it computes a continuous correctness score `P_stg` as the fraction of passed vectors. This gradient signal guides search toward partially correct designs, reducing reliance on costly LLM debugging. The loop breaks when `P_stg` reaches 1.0 for generative tasks.

## Foundational Learning
- **HDL Semantics:** Verilog’s concurrent, clock-synthesizable semantics differ from LLMs’ sequential training. Misunderstanding blocking assignments or reset behavior can yield code that compiles but fails synthesis. STG catches such issues via fine-grained simulation.
  - *Quick check:* Why might LLM-generated Verilog compile with Icarus but fail Yosys synthesis, and how does STG’s feedback help?
- **Evolutionary Search vs. Single-Shot Generation:** EvolVE treats design as a state-space search where `(code, score, feedback)` are nodes. MCTS exploits local gradients efficiently; IGR explores distinct architectural basins. The trade-off depends on task type.
  - *Quick check:* For PPA optimization, why might IGR (multi-start) be more effective than MCTS (single-tree), and vice-versa for functional generation?
- **Testbench as a Dense Reward Function:** Standard verification yields binary outcomes. STG repurposes the testbench to output a continuous score, transforming a sparse-reward problem into one with a denser gradient, dramatically improving sample efficiency.
  - *Quick check:* How does generating exhaustive tests for a 4-bit control bus (16 vectors) versus random sampling for a 32-bit bus balance thoroughness with simulation time?

## Architecture Onboarding
- **Component map:** Problem Description (D) → LLM (M) → Archive (A) & Node Set (N) → Evaluator (E: STG + Simulator) → Search Controller → back to LLM for child generation.
- **Critical path (Generative Task):** D → M generates seed V → E(V,T) returns (S,F) stored in N & A → Controller selects parent (via IGR/MCTS) → M generates child from (V_parent, F_parent, D) → E(child,T) → update N,A, backpropagate (MCTS) → repeat until S=1.0 or budget exhausted.
- **Design tradeoffs:**
  - MCTS is sample-efficient for local bug fixes but may converge to suboptimal architectures; IGR explores multiple ideas but consumes more tokens for idea generation.
  - STG’s deterministic test generation is computationally free but simulation time scales with vector count; width-constrained policies manage this trade-off.
  - Open-source tools (Iverilog, Yosys) enable rapid search iteration; commercial tools (Synopsys) are used only for final validation due to cost.
- **Failure signatures:**
  - Compilation/Syntax Error: `S = C_penalty` with error message.
  - Functional Failure: `0 < S < 1.0` from STG with failing test details.
  - Optimization Stagnation: PPA score plateaus below human baseline, indicating local optima.
  - Token/Time Budget Exhaustion: `n_count >= L_max` with `S_max < target`.
- **First 3 experiments:**
  1. **Baseline functional scaling:** Run `DeepSeek-R1-FP4-MCTS` on Mod-VerilogEval v2 with budgets [15, 50, 100, 200, 300]. Expect monotonic pass-rate increase, ~2.49 nodes/problem.
  2. **Strategy comparison:** On RTLLM v2, compare `GPT-OSS-120B-IGR` vs. `GPT-OSS-120B-MCTS`. Expect IGR to match/surpass for PPA tasks (if extended), MCTS stronger for pure functional pass rate.
  3. **STG ablation:** On Mod-VerilogEval v2, run `DeepSeek-R1-FP4-MCTS` with STG disabled. Measure nodes and tokens to solution; expect >60% token reduction with STG enabled.

## Open Questions the Paper Calls Out
1. How can STG be extended to verify designs without executable reference models (golden designs) for novel IP?
2. How can we systematically create and standardize PPA optimization benchmarks that reflect industrial design complexity?
3. How can fully automated synthesis and PPA extraction be integrated into the evolutionary loop for real-time feedback?
4. How can a formal knowledge base of microarchitectural optimization patterns be effectively leveraged to guide LLM-based PPA exploration?
5. How can MCTS be modified to directly optimize for multi-objective PPA metrics instead of functional correctness alone?

## Limitations
- **Artifact availability:** Core code (EvolVE implementation, IC-RTL benchmark) is unreleased, preventing direct replication; prompt details and STG signal classification rules are unspecified.
- **Validation scope:** IGR’s PPA superiority is primarily supported by internal ablations on the new IC-RTL benchmark, lacking cross-model or cross-benchmark confirmation.
- **Generalization uncertainty:** Results rely on specific LLMs (DeepSeek-R1-FP4, GPT-OSS-120B); transfer to other model families (e.g., smaller open weights or commercial non-open models) is unknown.
