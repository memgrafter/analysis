# Securing the Floor and Raising the Ceiling: A Merging-based Paradigm for Multi-modal Search Agents
## Quick Facts
*   **ArXiv ID:** 2603.01416
*   **Source URL:** https://arxiv.org/abs/2603.01416
*   **Reference Count:** 9
*   **Primary Result:** A training-free merging paradigm (OBM) combining a pretrained VLM and a text-based search agent achieves higher zero-shot performance and serves as an effective warm-start for RL, composing multimodal search capabilities without extra multimodal training.

## Executive Summary
The paper tackles the high cost and instability of training multimodal search agents (VLMs with tool-use) by proposing a training-free merging approach. Instead of costly reinforcement learning (RL) or large-scale supervised data, it fuses a pretrained vision-language model (VLM) with a specialist text-based search agent via parameter-level model merging, using Optimal Brain Merging (OBM). OBM employs saliency-aware sparsification and sign consensus to preserve cross-modal critical parameters and resolve interference. On four benchmarks, the zero-shot merged agent establishes a higher performance floor (e.g., ~78% text search rate). When used to initialize RL training, it yields faster convergence and a higher peak performance, demonstrating that cross-modal capabilities can be effectively composed without additional multimodal training.

## Method Summary
The method defines "task vectors" (fine-tuned weights minus a shared base model's weights) for the VLM's language module (δ_V, from Qwen2.5-VL) and the search agent's language module (δ_S, from Search-R1). It merges these into the base model's language module (θ_base from Qwen2.5-7B). Optimal Brain Merging (OBM) improves upon naive linear merging (Task Arithmetic) by first computing a saliency score for each parameter in each task vector using an activation-aware Hessian approximation on a small calibration set. It sparsifies each task vector to its top-p% salient parameters. During merging, for parameters where task vectors conflict in sign, OBM uses a saliency-weighted sign consensus to decide the final direction, preserving parameters deemed more important by the saliency maps. The vision encoder and projector from the VLM are transplanted frozen. The final agent is evaluated zero-shot and as a warm-start for PPO-based RL fine-tuning on search trajectories.

## Key Results
*   **Zero-shot floor improvement:** OBM achieves a substantially higher search rate (e.g., 78.94% on MMSearch) and accuracy (~20% absolute over Qwen-VL) compared to baselines like TIES and DARE, without any multimodal training.
*   **Effective warm-start:** Initializing RL from an OBM-merged checkpoint leads to faster convergence and a higher peak average accuracy (27.59%) and search rate (77.77%) than starting from the base VLM.
*   **Cross-modal parameter preservation:** Ablations show that using multimodal calibration data (vs. text-only) is critical for preserving the vision-language alignment, as evidenced by significantly higher image search rates (SR_img).

## Why This Works (Mechanism)
### Mechanism 1: Linear Composition of Task Vectors
**Claim:** Cross-modal capability composition is achievable via parameter-level merging, avoiding costly multimodal training.
**Mechanism:** The pretrained VLM provides visual perception; the specialist text-based search agent (Search-R1) provides tool-use reasoning logic. These are combined by linearly summing their task vectors (fine-tuned weights minus base weights) relative to a shared backbone (Qwen2.5-7B). This transplants search "instincts" into the VLM's language module.
**Core Assumption:** The requisite capabilities are linearly separable in weight space and can be recombined without destructive interference.
**Evidence Anchors:**
*   [Abstract] "By fusing a text-based search agent with a base VLM, we show that multi-modal search capabilities can be effectively composed without any additional multi-modal training data."
*   [Section 3.2] Defines task vectors δS and δV and their linear combination θ_merged = θB + λSδS + λVδV.
**Break Condition:** Fails if the two task vectors operate on fundamentally non-overlapping or antagonistic parameter subspaces, causing severe interference that degrades either visual grounding or reasoning logic.

### Mechanism 2: Saliency-Aware Sparsification via Hessian Approximation
**Claim:** Saliency-aware sparsification preserves cross-modal critical parameters and mitigates interference.
**Mechanism:** OBM estimates each parameter's importance (saliency) by its contribution to loss on a small calibration set, using a forward-pass-based MSE approximation (H_l = 2X_lX_l^⊤). It retains only top-p% salient parameters per task vector before merging. This pruning is activation-aware: saliency for the VLM's language module (δV) is computed with the vision encoder/projector frozen but active, capturing dependencies between modalities.
**Core Assumption:** Diagonal Hessian elements approximated via layer-wise MSE on calibration data are a valid proxy for parameter importance in preserving multimodal reasoning performance.
**Evidence Anchors:**
*   [Abstract] "OBM computes saliency via activation-aware Hessian approximations on a small calibration set to preserve cross-modal critical parameters and resolve interference."
*   [Section 3.3] Details the saliency formula s_i = (1/2)h_{ii}δ_i^2 and the layer-wise MSE objective ΔL_l = ∥ΔW_l X_l∥^2_2. Explicitly states that "the saliency of δV inherently captures the activation-aware dependencies between the language backbone and the frozen vision-projection modules."
**Break Condition:** Computation fails if calibration data is completely out-of-distribution. The method also assumes pruning does not remove synergistic parameters that are individually low-saliency but collectively critical.

### Mechanism 3: Saliency-Weighted Sign Consensus
**Claim:** Saliency-weighted sign consensus during merging resolves directional conflicts between task vectors in a modality-aware manner.
**Mechanism:** When task vectors conflict (sign(δS,i) ≠ sign(δV,i)), OBM does not apply a simple majority vote. Instead, it computes a weighted consensus direction σ_i using the *saliency scores* of each task vector as weights: σ_i = sign(∑ s_i^{(k)} · sign(δ̂_i^{(k)})). Parameters aligned with σ_i are kept, preserving values from the task deemed more important for that specific parameter by the saliency map.
**Core Assumption:** Parameter importance (saliency) is task-specific and should modulate conflict resolution, rather than treating all parameters equally.
**Evidence Anchors:**
*   [Section 3.3] Equation (6) defines the weighted consensus mechanism. States the goal is to ensure "parameters vital to 'multi-modal synergy' are retained with their correct task-specific orientations."
*   [Section 4.2] Empirical evidence: TIES "may inadvertently eliminate small-magnitude parameters that are nonetheless critical for bridging visual perception and search reasoning." OBM's superior zero-shot search rate (78.94% on MMSearch) versus TIES (49.12%) supports this mechanism.
**Break Condition:** If saliency estimates are highly inaccurate (e.g., due to tiny calibration set), weighted consensus may reinforce incorrect importance weights, potentially amplifying rather than resolving interference.

## Foundational Learning
*   **Concept: Task Vectors and Linear Model Merging (Task Arithmetic)**
    *   **Why needed:** The entire paradigm rests on representing fine-tuned adaptations (search reasoning from Search-R1, visual grounding from Qwen-VL) as additive vectors from a shared base (θB).
    *   **Quick Check:** Given base model weights θB and two fine-tuned checkpoints θA (for ability A) and θB (for ability B), write the formula for a merged model θM using Task Arithmetic with coefficients λA and λB.
*   **Concept: Hessian-Based Parameter Saliency (Optimal Brain Damage/Compression)**
    *   **Why needed:** OBM's core innovation is using second-order loss sensitivity (via a Hessian approximation) to decide *which* parameters to merge.
    *   **Quick Check:** In the context of OBM, what does a high saliency score s_i for a parameter i indicate, and how is it approximately computed without full backpropagation?
*   **Concept: Cross-Modal Architectural Entanglement in VLMs**
    *   **Why needed:** A VLM's language module parameters are subtly aligned with its visual projection layers. Merging must preserve this delicate alignment.
    *   **Quick Check:** Why might a merging algorithm designed for unimodal LLMs (like TIES) fail when applied to fuse a language model with a VLM's language module?

## Architecture Onboarding
**Component map:**
Base Model (θB: Qwen2.5-7B) -> Merged Language Module (θM_lang) + Frozen Vision Encoder/Projector (from Qwen2.5-VL) -> Final Search Agent
Specialist A (VLM: Qwen2.5-VL-7B-Instruct) provides δV (language module) and frozen vision parts.
Specialist B (Search Agent: Search-R1) provides δS (language module).
Merging Engine (OBM) computes saliency maps sV, sS on calibration data, sparsifies δV and δS, applies weighted sign consensus, and sums to θB.

**Critical path:**
1.  **Calibration Data Selection:** Choose 128 multimodal samples (MMStar) for δV saliency and 128 text samples (NQ-HotpotQA) for δS saliency.
2.  **Saliency Computation:** Run forward passes through each specialist on its calibration data, collect layer activations X_l, compute s_i = (1/2)*(X_lX_l^⊤)_{ii} * δ_i^2, and prune to top-p=0.7.
3.  **Sign Consensus & Merge:** For remaining parameters, compute σ_i = sign(∑ s_i^{(k)} · sign(δ̂_i^{(k)})), zero out mismatches, and merge: θM_lang = θB_lang + δ_S + δ_V.
4.  **Evaluation (Zero-Shot):** Test merged agent on benchmarks (FVQA-test, InfoSeek, MMSearch, LiveVQA) with provided tool-use prompts. Metrics: Accuracy, Search Rate (SR), SR_img, SR_txt.
5.  **Warm-Start RL:** Initialize PPO training from OBM checkpoint vs. base VLM on 5k search trajectories. Track accuracy and search rate over training steps.

**Design tradeoffs:**
*   **Calibration Cost vs. Robustness:** Multimodal calibration is essential but requires both image and text data.
*   **Sparsity (p) vs. Capacity:** Lower p reduces interference but risks losing critical parameters. Tuned to p=0.7.
*   **Coefficient Tuning (λ):** OBM sets λ=1 for both task vectors, relying on sparsity p to control effective strength, unlike Task Arithmetic's tuned λ.
*   **Computation vs. Precision:** Layer-wise MSE is a cheap Hessian approximation but may miss inter-layer dependencies.

**Failure signatures:**
1.  **Catastrophic Interference:** Sudden drop in accuracy/search rate (e.g., DARE's collapse). Caused by stochastic/magnitude-based pruning.
2.  **Search Instinct without Skill:** High Search Rate but low Accuracy. Indicates tool invocation without effective evidence integration.
3.  **Modality Collapse:** Very low SR_img. Suggests vision-language alignment was broken during merge.
4.  **Overfitting in Late Training:** TIES shows peak in-domain performance but degrades out-of-domain later.

**First 3 experiments:**
1.  **Replicate Zero-Shot Merging:** Implement OBM exactly. Verify OBM (p=0.7) achieves ≥78% text search rate on MMSearch and >20% absolute accuracy improvement over base Qwen-VL.
2.  **Ablation on Calibration Data:** Compare default OBM (multimodal + text calibration) vs. OBM-Text (text-only) vs. Oracle (benchmark samples). Expect >15% absolute drop in SR_img for text-only calibration.
3.  **Warm-Start RL Comparison:** Initialize two PPO runs (from Qwen-VL and from OBM). Expect OBM to reach base model's 2-epoch accuracy within ~14 steps and achieve higher peak average accuracy (~27.5%) earlier (e.g., step 44).

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** How can we achieve fine-grained coordination between visual evidence and specific tool selection in merged multi-modal search agents?
*   **Basis in paper:** [explicit] The authors state: "while merging successfully implants the ‘will’ to search, the fine-grained coordination between visual evidence and specific tool selection—such as knowing exactly when to trigger an image search versus a text search—is a higher-order skill that requires further optimization."
*   **Why unresolved:** Merged agents exhibit a "text-centric" bias and suboptimal tool selection. Zero-shot agents tend to overuse text search, indicating a lack of nuanced decision-making.
*   **What evidence would resolve it:** Develop mechanisms that dynamically select tools based on visual content, possibly via a learned policy or explicit gating modules, and evaluate the accuracy/search rate trade-off. RL from the merged initialization could train such coordination.

### Open Question 2
*   **Question:** How does the performance of OBM vary with the size, domain, and modality composition of the calibration set used for saliency estimation?
*   **Basis in paper:** [inferred] The authors use a fixed 128-sample multimodal VQA calibration set; no analysis of sensitivity beyond comparing multimodal vs. text-only.
*   **Why unresolved:** Saliency estimates rely on calibration data representativeness. A small or biased set may misidentify critical parameters. This is crucial for real-world deployment with limited calibration resources.
*   **What evidence would resolve it:** Systematically vary calibration set size (e.g., 64, 128, 512, 1024) and domain while measuring zero-shot and RL-fine-tuned performance to reveal robustness and optimal sizing.

### Open Question 3
*   **Question:** Can the cross-modal merging paradigm generalize to models without a shared base model (e.g., different architectures or pretraining)?
*   **Basis in paper:** [inferred] The method assumes task vectors are defined relative to the same base model θB (Qwen2.5). The authors note that both Search-R1 and Qwen-VL share the same ancestry, implying limited applicability.
*   **Why unresolved:** If the technique only works with models sharing a common base, its applicability is restricted. Many scenarios involve combining off-the-shelf models from different families.
*   **What evidence would resolve it:** Perform merging between models with different bases (e.g., Llama-based VLM and GPT-based search agent) using alignment techniques (linear projections, adapters). Performance on benchmarks would indicate generalizability.

### Open Question 4
*   **Question:** Could merging include the vision encoder and projector parameters to further improve cross-modal synergy, rather than only merging language modules?
*   **Basis in paper:** [inferred] The authors transplant the vision encoder and projector from the VLM unchanged, merging only language modules. They cite the delicate alignment but do not explore merging vision parts.
*   **Why unresolved:** The vision encoder might contain features beneficial for search decisions (e.g., identifying entities for image search). Freezing it may miss opportunities for tighter integration, especially for tasks requiring visual grounding of search queries.
*   **What evidence would resolve it:** Extend OBM to compute saliency for vision encoder and projector parameters and merge them. Compare resulting agent’s accuracy, search rates (especially SR_img), and generalization against language-only merging.

## Limitations
*   RL hyperparameters (PPO settings, reward shaping) and full search tool implementation details are undisclosed, hindering faithful replication of warm-start experiments.
*   The method requires a small but modality-appropriate calibration set; performance sensitivity to calibration data distribution and size is not fully explored.
*   The merging is restricted to models sharing a common base architecture (Qwen2.5), limiting generalizability to heterogeneous model families.

## Confidence
*   **Cross-modal merging establishes a higher zero-shot performance floor:** High – consistent improvements across four benchmarks.
*   **OBM's saliency-aware merging preserves cross-modal critical parameters better than magnitude-based methods:** Medium – ablations support the claim, but alternative saliency formulations might yield similar gains.
*   **Warm-starting RL with OBM leads to faster convergence and higher peak:** Medium – positive trend observed, but missing RL hyperparameters could alter the magnitude of the benefit.
