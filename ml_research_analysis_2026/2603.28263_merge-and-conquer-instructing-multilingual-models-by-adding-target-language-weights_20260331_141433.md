# Merge and Conquer: Instructing Multilingual Models by Adding Target Language Weights

## Quick Facts
- **arXiv ID:** 2603.28263
- **Source URL:** https://arxiv.org/abs/2603.28263
- **Reference count:** 0
- **Primary result:** Parameter‑space interpolation between a language‑specific base model and an instructed model transfers linguistic competence to low‑resource languages while preserving instruction‑following ability, achieving near state‑of‑the‑art performance at a fraction of the training cost.

## Executive Summary
Adapting instruction‑tuned large language models to low‑resource languages typically requires costly continual pre‑training or high‑quality instruction data. This paper presents a lightweight alternative: merge a language‑specific base model (further pre‑trained only on target‑language text) with an existing instructed model via parameter‑space interpolation. Experiments on Basque, Galician, Catalan, and Spanish using Llama 3.1 and Qwen 3 families demonstrate that simple merging strategies—especially linear interpolation and Task Arithmetic—yield substantial gains on multiple‑choice benchmarks and machine translation (BLEU) while retaining instruction‑following capabilities measured by IFEval. The approach avoids the expense of joint adaptation and establishes model merging as a viable and efficient solution for low‑resource language extension.

## Method Summary
The core method combines two models: a base instructed model (already aligned to follow instructions) and a language‑specific base model obtained by continued pre‑training on monolingual text. The merge is performed by weighted averaging of their parameters (linear interpolation) or by adding a scaled task vector (Task Arithmetic). Sparsification variants such as DARE (random dropout with rescaling) and Breadcrumbs (threshold‑based filtering) are also explored to reduce interference. For a single target language, the language model’s weight is typically set between 0.5 and 1.0, balancing target‑language proficiency against instruction retention. Multilingual merges combine several language‑specific models simultaneously, aiming for balanced cross‑lingual performance. The entire process requires only a single forward pass over the parameters and no additional training.

## Key Results
- Monolingual merging significantly improves target‑language multiple‑choice accuracy and BLEU scores, often matching or exceeding more expensive joint adaptation methods.
- Linear and Task Arithmetic merges achieve these gains with minimal computational overhead and preserve instruction‑following (IFEval scores remain close to the original instructed model at optimal weights).
- Multilingual merging yields balanced competence across all included languages, though peak performance on any single language is lower than that of monolingual merges.

## Why This Works (Mechanism)

### Mechanism 1: Parameter‑Space Linear Interpolation as Knowledge Transfer
- **Claim:** Merging via weighted averaging (`θ_merge = w_base·θ_base + Σ w_i·θ_i`) transfers language‑specific weights from the base model into the instructed model while preserving instruction‑following capabilities.
- **Mechanism:** The instructed model’s weights already encode general instruction alignment. The language‑specific base model contains updated weights that enhance linguistic competence for the target language. Linear interpolation combines these, assuming the optimal merged point lies on the linear path between them. This is a form of vector addition in parameter space, where the language‑specific "delta" is added to the instructed model.
- **Core assumption:** The linguistic knowledge from the base model and the instruction‑following capabilities from the instructed model are linearly compatible and do not destructively interfere when averaged.
- **Evidence anchors:**
  - [abstract]: "merging a language‑specific base model... with an existing instructed model via parameter‑space interpolation... successfully transfers language proficiency while retaining instruction‑following capabilities."
  - [section 3.2]: Defines linear merging formally as a weighted average.
  - [section 5.1]: Monolingual merge results (Table 3) show clear gains in target‑language benchmarks and translation while maintaining instruction‑following (IFEval), e.g., `Llama 3.1 8Bmerge‑EU` vs. `Instruct` on EU tasks.
- **Break condition:** Performance degradation in instruction‑following (Table 4) or collapse in generation tasks (e.g., Breadcrumbs failure in Table 5) indicates nonlinear incompatibility or interference beyond what linear averaging can resolve.

### Mechanism 2: Task Vector Representation and Additive Composition
- **Claim:** Representing adaptation as a task vector (`τ_i = θ_i - θ_base`) allows the instructed model’s "instruction skill" to be preserved by keeping `θ_base` fixed and only adding the language‑specific delta.
- **Mechanism:** The base instructed model (`θ_base`) serves as a reference containing the instruction alignment. The language‑adapted base model (`θ_lang`) differs primarily in linguistic parameters. Their difference (`τ_lang`) is a vector encoding *only* the language adaptation signal. Adding this vector to `θ_base` attempts to inject language knowledge without altering the core instruction‑following weights, conceptually "editing" the model for a new language.
- **Core assumption:** The task vector `τ_lang` is sparse or modular enough that adding it does not significantly disrupt the parameters responsible for instruction following in `θ_base`.
- **Evidence anchors:**
  - [section 3.2]: Describes Task Arithmetic: "MTA(...) = θ_base + Σ w_i·(θ_i - θ_base)".
  - [section 5.1]: Task Arithmetic merges achieve results comparable to Linear merges (Tables 3, 7), supporting the vector‑additive transfer hypothesis.
  - [corpus neighbor "Grow Up and Merge"]: Mentions scaling strategies where task vectors are used for adaptation, suggesting a common underlying principle.
- **Break condition:** If `τ_lang` is dense or conflicts with instruction parameters, adding it causes catastrophic forgetting or degradation in non‑target tasks, as seen with high `w_i` in Task Arithmetic causing rapid collapse (Figure 1, bottom row).

### Mechanism 3: Sparsification and Conflict Resolution via Pruning/Masking
- **Claim:** Methods like DARE (random dropout + rescaling) and Breadcrumbs (threshold‑based filtering) improve merging by reducing interference between the language and instruction signals in the task vector.
- **Mechanism:** The raw task vector `τ` may contain conflicting or redundant updates. DARE randomly drops a proportion `p` of elements and rescales, approximating the expected value while introducing stochasticity to break co‑adaptation. Breadcrumbs deterministically filters out very small and very large updates, keeping only "mid‑range" parameters deemed most informative for the language task. Both aim to retain the linguistic signal while minimizing detrimental overlap with instruction‑following parameters.
- **Core assumption:** The most useful language‑specific updates are neither negligible nor extreme outliers; pruning them reduces interference.
- **Evidence anchors:**
  - [section 3.2]: Details DARE’s dropout‑and‑rescale operation and Breadcrumbs’ threshold filtering.
  - [section 5.2]: Table 5 shows DARE and Breadcrumbs often match or exceed Linear/Task Arithmetic in benchmarks but are unstable in generation (Breadcrumbs fails catastrophically in MT). This suggests sparsification helps in some contexts but risks losing critical generative parameters.
  - [corpus neighbor "NeuronMoE"]: Discusses neuron‑guided sparsity for multilingual extension, aligning with the principle of selective parameter activation.
- **Break condition:** Over‑pruning (high dropout rate `p` or tight thresholds) removes essential language‑generation parameters, leading to collapse in text‑generation tasks (e.g., near‑zero BLEU for Breadcrumbs on Galician/Catalan in Table 5). Under‑pruning fails to resolve interference, harming instruction following.

## Foundational Learning

- **Concept: Parameter Space Interpolation**
  - *Why needed here:* The core method merges models by combining their weights directly. Understanding that model weights are points in a high‑dimensional space, and merging is geometric interpolation (linear or otherwise), is fundamental.
  - *Quick check question:* If two models are fine‑tuned from the same initialization, why might their weight differences (`θ_ft - θ_base`) represent "task knowledge" that can be transported?

- **Concept: Task Vectors and Editing**
  - *Why needed here:* Task Arithmetic formalizes merging as adding a "task vector." This concept connects model merging to the idea of "editing" a model's behavior by applying a targeted parameter shift, which is key to understanding how language knowledge is injected.
  - *Quick check question:* What is the risk if the task vector (`τ_lang`) contains changes that are not specific to language but also affect reasoning or safety?

- **Concept: Interference in Multi‑Task/Weight Space**
  - *Why needed here:* Merging two models trained for different objectives (instruction‑following vs. language modeling) can cause parameter conflicts. Techniques like TIES/DARE/Breadcrumbs exist to mitigate this. Recognizing destructive interference as a central problem explains why naive averaging sometimes fails.
  - *Quick check question:* Give an example of how a parameter update beneficial for Basque morphology might harm English instruction following if added indiscriminately.

## Architecture Onboarding

- **Component map:**
  1. **Base Instructed Model** (`θ_instruct`): Pre‑trained + instruction‑tuned (e.g., Llama 3.1 Instruct). Starting point; must retain `θ_instruct`'s alignment.
  2. **Language‑Specific Base Model** (`θ_lang`): Continued pre‑trained *only* on target‑language corpora (no instructions). Provides the linguistic delta.
  3. **Merge Function** (`M`): Algorithm combining `θ_instruct` and `θ_lang` (Linear, Task Arithmetic, DARE, Breadcrumbs).
  4. **Merge Weights** (`w_instruct`, `w_lang`): Scalars controlling influence balance; sum to 1 for Linear.
  5. **Evaluation Harness**: Suite of benchmarks (multiple‑choice, MT, IFEval) to measure language proficiency vs. instruction retention.

- **Critical path:**
  1. Train or obtain `θ_lang` (continued pre‑training on monolingual corpus).
  2. Select `θ_instruct` (public instructed variant).
  3. Choose merge method `M` and initial `w_lang`.
  4. Compute `θ_merge = M(θ_instruct, θ_lang, w_lang)`.
  5. Evaluate `θ_merge` on target‑language tasks and instruction benchmarks.
  6. Iterate: adjust method/hyperparameters based on failure modes.

- **Design tradeoffs:**
  - **Language proficiency vs. Instruction retention:** Higher `w_lang` improves target‑language scores but degrades IFEval (Figure 1). Optimal `w_lang` often ∈ [0.5, 1.0) for low‑resource languages.
  - **Method simplicity vs. stability:** Linear is simplest and most stable; Task Arithmetic is similarly strong but more sensitive to `w_lang`. DARE/Breadcrumbs introduce sparsity but can cause generation collapse (Table 5).
  - **Monolingual vs. multilingual merging:** Monolingual maximizes target‑language performance; multilingual (`merge‑multi` with `w_i = 0.25` each) balances cross‑lingual competence but rarely matches monolingual peaks (Table 3).

- **Failure signatures:**
  1. **Catastrophic forgetting in instruction following:** IFEval scores drop significantly below `θ_instruct` baseline. Likely cause: `w_lang` too high or method with dense interference (unpruned Task Arithmetic).
  2. **Degraded language generation:** Low BLEU or incoherent outputs, especially with Breadcrumbs (Table 5). Likely cause: over‑pruning of generative parameters.
  3. **Imbalanced multilingual competence:** One language dominates performance in `merge‑multi`. Likely cause: unequal `w_i` or underlying corpus size/quality differences.
  4. **No improvement over baseline:** `θ_merge` ≈ `θ_instruct` on target language. Likely cause: `θ_lang` insufficiently trained (see corpus size Table 1) or `w_lang` too low.

- **First 3 experiments:**
  1. **Baseline replication:** Reproduce Table 3’s Linear monolingual merge for one language (e.g., Basque) with `w_lang=1.0`. Verify target‑language benchmark improvement and IFEval drop.
  2. **Proportion sweep:** For Linear and Task Arithmetic, vary `w_lang` ∈ [0.0, 1.0] in increments of 0.25. Plot tradeoff curves similar to Figure 1 to identify optimal operating point for your language/model pair.
  3. **Method comparison:** Run Linear, Task Arithmetic, DARE (`p=0.5`), and Breadcrumbs (default thresholds) on a single language. Evaluate on multiple‑choice, MT, and IFEval to observe the stability pattern (Table 5) and detect generation collapse early.

## Limitations
- **Generalizability scope:** Experiments cover only 4 languages (Basque, Galician, Catalan, Spanish) and 2 model families (Llama 3.1, Qwen 3). Findings may not transfer to other low‑resource languages (e.g., with different script families or morphological typology) or newer architectures.
- **Generation reliability:** Sparsification methods (DARE/Breadcrumbs) show catastrophic failure in machine translation but not in multiple‑choice tasks; the boundary between useful pruning and loss of generative parameters is not characterized.
- **Instruction‑following evaluation:** Reliance on IFEval (synthetic) may not reflect real‑world instruction adherence; human evaluation is absent.

## Confidence

- **Task Arithmetic performs comparably to linear merging:** Medium
- **Sparsification (DARE/Breadcrumbs) mitigates interference:** Medium‑Low
- **Multilingual merging yields balanced cross‑lingual competence:** Medium
