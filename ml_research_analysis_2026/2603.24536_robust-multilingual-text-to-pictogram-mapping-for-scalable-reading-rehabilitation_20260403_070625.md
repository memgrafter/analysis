# Robust Multilingual Text-to-Pictogram Mapping for Scalable Reading Rehabilitation

## Quick Facts
- **arXiv ID:** 2603.24536  
- **Source URL:** https://arxiv.org/abs/2603.24536  
- **Reference count:** 0  
- **Primary result:** A multilingual AI system achieves high keyword-to-pictogram coverage (79.4–97.9%) and clinical acceptability (>95% for European languages, ~90% for Arabic) with real-time latency (<228 ms/sentence).

## Executive Summary
This paper introduces a language-agnostic AI pipeline that automatically enriches text with pictograms to support reading rehabilitation for children with Special Educational Needs and Disabilities (SEND). By integrating unsupervised keyword extraction, contextual semantic disambiguation, and the ARASAAC pictogram repository, the system provides scalable, multilingual visual scaffolding. Evaluated on *Le Petit Prince* across five languages, it delivers high coverage of relevant pictograms per sentence, strong clinician-rated correctness, and interactive processing speeds, demonstrating feasibility for real-world therapeutic applications.

## Method Summary
The pipeline processes input text through a fixed sequence: detect language (Lingua), segment sentences (NLTK), tokenize/lemmatize (spaCy with simplemma fallback), extract top-3 keywords (YAKE), retrieve candidate pictograms from ARASAAC by keyword lemma, disambiguate via cosine similarity between keyword local context (±2 words) and pictogram definition embeddings (multilingual SentenceTransformers), handle numeric cases heuristically, reorder pictograms by original keyword position, and output for UI display. No model training is performed; it relies on precomputed ARASAAC definition embeddings and off-the-shelf NLP tools.

## Key Results
- **Coverage:** Keyword-to-pictogram mapping achieved 79.4% (Arabic) to 97.9% (Italian) across evaluated languages.  
- **Density:** Mean of 2.02–2.56 pictograms per sentence.  
- **Clinical acceptability:** Over 95% of pictogram selections rated "Correct" or "Acceptable" for European languages; approximately 90% for Arabic.  
- **Latency:** End-to-end processing averaged 176–228 ms per sentence, meeting interactive thresholds.

## Why This Works (Mechanism)
### Mechanism 1: Language-agnostic preprocessing
A cascading strategy (Lingua → NLTK → spaCy/simplemma) normalizes input across diverse languages. SpaCy provides accurate tokenization and lemmatization where dedicated models exist; simplemma offers a lightweight fallback. This ensures robust morphological analysis for pedagogically relevant languages, as evidenced by the system's consistent pipeline execution in Section III.B. The break condition occurs when a language lacks both spaCy and functional simplemma support, or when rich inflection defeats fallback heuristics.

### Mechanism 2: Keyword extraction with YAKE
YAKE ranks lexical units (including multiword expressions) using language-independent statistical features (casing, frequency, context diversity). The top-3 keywords per sentence are retained, assuming salience correlates with conceptual importance for SEND comprehension. Section III.B.3 details this choice, and Section II.B grounds it in pedagogical literature. The break condition arises when YAKE's statistical signal misses critical abstract verbs or selects irrelevant proper nouns for specific genres or learner profiles.

### Mechanism 3: Contextual disambiguation via embeddings
Sentence-context embeddings (multilingual SentenceTransformers) align keyword senses with pictogram definitions. The local context around a keyword (±2 words) is embedded and compared via cosine similarity to precomputed ARASAAC definition embeddings; the highest match is selected. High clinical acceptance rates (Section V.B) provide correlative evidence of semantic alignment. The break condition involves polysemous keywords where the embedding space fails to distinguish senses, or ARASAAC definitions are too brief to capture contextual nuances.

## Architecture Onboarding
### Component Map
Raw text → Language & Sentence Handler (Lingua + NLTK) → Linguistic Preprocessor (spaCy/simplemma) → Keyword Extractor (YAKE) → Pictogram Candidate Retriever (ARASAAC lookup) → Contextual Disambiguator (SentenceTransformers similarity) → Special Case Handler (numerics) → Output Composer (reorder) → Interface Layer (ARTIS UI).

### Critical Path
The longest latency component is the embedding computation for contextual disambiguation; offline precomputation of ARASAAC definition embeddings is essential to meet the ~200 ms interactive threshold.

### Design Tradeoffs
- **Repository Coverage vs. Consistency:** Using ARASAAC ensures clinical reliability and style consistency but creates equity gaps across languages (e.g., Arabic performance). Generative models were rejected due to inconsistency risks.
- **Real-time Latency vs. Ambiguity Resolution:** On-the-fly definition embedding would increase latency 5–10×; precomputation trades storage for speed.
- **Simplicity (fixed top-3 YAKE) vs. Pedagogical Precision:** Fixed top-3 is language-agnostic and fast but may misalign with specific SEND profiles; human facilitator overrides are the ultimate safety net.

### Failure Signatures
- **High "0 pictograms" sentence rate:** Indicates ARASAAC coverage gap for extracted keywords; check per-language K2P coverage.
- **High "Incorrect" pictogram rate:** Suggests polysemy, abstract concept unmapped, or failed disambiguation; audit similarity scores for incorrect cases.
- **Latency spikes >400 ms:** Typically from slow spaCy tokenization or sentences with many keywords triggering multiple lookups; profile per-component times.
- **Script errors in Arabic:** Default NLTK tokenizer may not handle Arabic script; requires language-specific validation.

### First 3 Experiments
1. **Coverage Sanity Check:** Run full pipeline on a 100-sentence corpus for a new language; report mean keywords/sentence, K2P coverage, mean pictograms/sentence; compare to Table II.
2. **Disambiguation Edge Case Audit:** Manually sample 50 sentences where system selects pictogram with similarity <0.6; have bilingual expert rate "Correct/Acceptable/Incorrect" to test lower disambiguation bound.
3. **Latency Isolation Profiling:** Instrument per-component timing on full *Le Petit Prince* per language; identify whether latency is dominated by linguistic preprocessing or embedding search.

## Limitations
- ARASAAC snapshot version and access details are unreported, hindering replication and precise coverage assessment.
- The exact SentenceTransformer model variant is unspecified, affecting disambiguation reproducibility.
- Fixed top-3 YAKE output lacks pedagogical tuning for diverse SEND profiles and text genres.
- Clinical audit limited to 200 sentences per language, limiting statistical robustness of acceptability metrics.

## Confidence
- **Multilingual robustness:** Medium (validated on five languages but not on low-resource ones where fallbacks may fail).
- **Semantic appropriateness:** Medium for European languages; Low for Arabic (due to repository coverage gaps).
- **Real-time efficiency:** High (measured latencies consistently within interactive thresholds).
