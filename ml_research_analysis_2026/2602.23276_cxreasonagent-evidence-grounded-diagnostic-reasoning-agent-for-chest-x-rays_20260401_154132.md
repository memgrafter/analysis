# CXReasonAgent: Evidence-Grounded Diagnostic Reasoning Agent for Chest X-rays

## Quick Facts
- **arXiv ID**: 2602.23276
- **Source URL**: https://arxiv.org/abs/2602.23276
- **Reference count**: 25
- **Primary result**: CXReasonAgent achieves 99.7% faithfulness and 0.3% hallucination on the CXReasonDial benchmark, far surpassing LVLM baselines.

## Executive Summary
Chest X-ray interpretation requires evidence-grounded, multi-step reasoning, but large vision-language models (LVLMs) often produce plausible yet ungrounded responses. This paper introduces CXReasonAgent, an agent that integrates an LLM with clinically grounded diagnostic tools to perform deterministic evidence extraction from chest X-rays. The agent uses a tool-calling planner to invoke rule-based tools that produce quantitative measurements, spatial observations, and annotated images, and then generates responses solely from this evidence buffer. Evaluated on CXReasonDial, a multi-turn dialogue benchmark with 1,946 dialogues covering 12 diagnostic tasks, CXReasonAgent consistently outperforms LVLM baselines; for example, with Gemini-3-Flash it achieves 99.7% faithfulness and 0.3% hallucination (versus 43–57% faithfulness and 40–55% hallucination for LVLMs). Even small LLM backbones like Qwen3-4B surpass all LVLMs, demonstrating that the agent design—not model scale—yields reliable, verifiable diagnostic reasoning. This highlights the importance of integrating clinically grounded tools for safety-critical clinical AI.

## Method Summary
CXReasonAgent is a modular system that separates evidence extraction from response generation. An LLM core interprets user queries and plans which diagnostic tool to call from a suite of rule-based modules (implemented via CheXStruct). These tools extract deterministic, structured evidence (measurements, observations, annotated images) directly from the chest X-ray. The extracted evidence is stored in a persistent evidence buffer, which the LLM then uses to generate its response without ever accessing the raw image. This hard constraint ensures all claims are traceable to the image-derived evidence. The system requires no model training; extending to new diagnostic tasks only requires adding corresponding tools. Evaluation uses the CXReasonDial benchmark, with metrics (faithfulness, hallucination) assessed by an LLM-as-a-Judge.

## Key Results
- On CXReasonDial, CXReasonAgent with Gemini-3-Flash achieves 99.7% faithfulness and 0.3% hallucination, compared to 43–57% faithfulness and 40–55% hallucination for LVLM baselines.
- Even with a small 4B-parameter LLM (Qwen3-4B), the agent surpasses all LVLM baselines, indicating that the tool-augmented design is more critical than model size.
- The agent maintains high performance under dynamic user simulation, where queries adapt based on previous responses.

## Why This Works (Mechanism)
CXReasonAgent achieves reliable diagnostic reasoning through three key mechanisms:

1. **Deterministic Evidence Extraction**: The agent uses clinically validated, rule-based tools (CheXStruct) to extract quantitative measurements, spatial observations, and annotated images from the chest X-ray. These tools produce reproducible, verifiable outputs that serve as a solid foundation for reasoning. The LLM then synthesizes responses solely from this evidence, never from parametric knowledge alone.

2. **Strict Evidence Buffer Separation**: A hard architectural barrier prevents the LLM from accessing raw image pixels. All tool outputs are stored in an evidence buffer, and the LLM is forced to generate responses conditioned only on that buffer. This eliminates hallucination because any claim must be directly traceable to a tool's prior output.

3. **Modular, Zero-Shot Task Extension**: Diagnostic capabilities are not embedded in the LLM's weights but are provided by tools. To support a new diagnostic task, a developer need only create a new tool implementing a clinically validated algorithm. The LLM's tool-planning capability allows it to leverage this new tool without retraining, enabling adaptable deployment.

## Foundational Learning
Three key concepts underpin the CXReasonAgent design:

- **Clinically Structured Diagnostic Reasoning**: Chest X-ray interpretation follows a sequential, evidence-based process (e.g., locate heart borders, measure cardiothoracic ratio, conclude cardiomegaly). The agent mimics this by gathering evidence stepwise before concluding.
  *Quick check*: What are the typical sequential evidence-gathering steps a radiologist follows to assess for "aortic knob enlargement" on a frontal CXR?

- **Tool-Augmented LLMs (Agentic Workflows)**: Instead of a monolithic vision-language model, CXReasonAgent uses an LLM as an orchestrator that calls specialized tools. This modularity allows incorporating deterministic, domain-specific computations.
  *Quick check*: In a tool-augmented agent, what is the primary role of the central LLM versus the specialized tools it calls?

- **Multi-Turn Dialogue State Tracking**: The benchmark involves multi-turn dialogues, so the agent must maintain context and coherence across turns, remembering what evidence has been provided and inferring user intent from follow-up questions.
  *Quick check*: In a "bottom-up" dialogue pattern about lung nodules, what might the user's second turn request after first asking for the nodule's location?

## Architecture Onboarding
The CXReasonAgent architecture comprises four main components:

- **Dialogue Manager**: Manages conversation history and passes the current query plus full context to the LLM Core.
- **LLM Core**: Acts as orchestrator. In the first phase, it interprets the user query and decides which diagnostic tool to invoke. In the second phase, it generates a response using only the evidence buffer.
- **Diagnostic Tool Suite**: A registry of rule-based modules (e.g., calculate_ctr, detect_tracheal_deviation, generate_heatmap). Each tool takes a chest X-ray and returns structured text evidence and optionally an annotated image.
- **Evidence Buffer**: A persistent, turn-level data structure that accumulates outputs from all called tools. The LLM can read from it but cannot modify it.

**Critical path**: User Query → Dialogue Manager → LLM Core (query interpretation) → Tool Call → Diagnostic Tool Suite → Evidence Buffer update → LLM Core (response generation) → Response → Dialogue Manager.

**Design tradeoffs**:
- Deterministic tools (CheXStruct) ensure reproducibility and explainability but are limited to predefined tasks and may fail on poor-quality images; a learned tool could be more robust but less transparent.
- Larger LLM backbones improve tool planning and multi-turn stability but increase cost; smaller models (Qwen3-4B) still work but with slightly lower performance on some metrics.
- The evidence buffer only contains outputs from called tools; if the LLM misses a necessary tool, the buffer lacks critical evidence, leading to incomplete or hallucinated responses.

**Failure signatures**:
- Tool mis-invocation: LLM calls the wrong tool due to misidentifying the diagnostic task or evidence type.
- Tool execution failure: A tool returns an error, nonsensical value, or incorrect measurement.
- LLM ignoring evidence buffer: The response includes facts not present in the buffer, indicating the LLM injected parametric knowledge.

**First 3 experiments**:
1. **Baseline sanity check**: Run the agent on a single-turn query with a known CXR. Verify that the correct tool is called, the buffer populates with expected measurements, and the response accurately reports those values against ground truth.
2. **Tool planning robustness**: Feed ambiguous or multi-intent queries (e.g., "Is there anything wrong here? Also, what's the CTR?"). Check whether the agent correctly splits the query into separate tool calls and provides coherent evidence for each part.
3. **Dynamic interaction stress test**: Use the dynamic user simulator setting, but also perturb the evidence buffer (e.g., inject incorrect measurements). Observe whether follow-up queries remain coherent and whether the agent recovers or compounds errors.

## Open Questions the Paper Calls Out
1. **Generalization to new tasks and modalities**: How can CXReasonAgent be extended beyond the current 12 chest X-ray tasks to other imaging modalities (e.g., CT, MRI) and diagnostic tasks? The system currently relies on task-specific tools; generalization requires developing new clinically validated tools and verifying tool selection accuracy.
2. **Minimal LLM requirements**: What is the smallest LLM backbone that can reliably identify diagnostic tasks and plan tool calls? The paper shows Qwen3-4B works, but the lower bound and critical capabilities (e.g., medical knowledge, instruction following) are not determined.
3. **Robustness to tool failures**: How does the agent handle inaccurate or failing tools? The current design assumes tools always produce correct outputs; in practice, tool errors could propagate. Resilience mechanisms (e.g., self-consistency checks) are needed.

## Limitations
- **CheXStruct tool opacity**: The core diagnostic tools are not open-sourced, hindering reproducibility and independent validation of the evidence extraction pipeline.
- **Prompt and evaluation details**: Exact system prompts for agent planning/response and the LLM-as-a-Judge evaluation are undisclosed, leading to potential variance in replication.
- **Benchmark scope**: Evaluation is restricted to 12 pre-defined tasks on CXReasonDial; performance on unseen clinical queries, complex multi-pathology images, or real-world noisy CXR acquisitions is unknown.

## Confidence
- Strict tool-evidence separation drastically reduces hallucination vs. LVLMs: **Medium-High** (architectural constraint is sound, but depends on tool accuracy).
- Small LLMs (e.g., Qwen3-4B) can effectively plan tool use without retraining: **Medium** (results compelling but prompts may bias; performance on more complex queries untested).
- The design enables zero-shot extension to new diagnostic tasks: **Low-Medium** (theoretically valid, but only demonstrated within the 12-task set; true novelty unvalidated).

## Next Checks
1. **Tool output verification**: Run the CheXStruct tools on a stratified sample of CXReasonDial images and quantify agreement of extracted measurements (e.g., CTR) with radiologist ground truth to establish evidence fidelity.
2. **Prompt & constraint audit**: Construct the agent prompts and perform a "buffer cheating" test: insert a false datum into the tool output (e.g., "CTR: 1.0" on a normal CXR). If the LLM repeats it, the buffer constraint holds; if it corrects it, the LLM may be using parametric knowledge.
3. **Dynamic simulator stress test**: Run the dynamic user simulation with deliberately perturbed evidence buffers (e.g., missing key measurements, contradictory values) to assess agent robustness and recovery.
