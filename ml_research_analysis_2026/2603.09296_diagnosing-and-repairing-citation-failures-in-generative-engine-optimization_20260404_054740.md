# Diagnosing and Repairing Citation Failures in Generative Engine Optimization

## Quick Facts
- **arXiv ID:** 2603.09296
- **Source URL:** https://arxiv.org/abs/2603.09296
- **Reference Count:** 40
- **Primary Result:** A diagnostic framework (AgentGEO) achieves a 40%+ relative improvement in citation rates while modifying only 5% of content on average, significantly outperforming generic optimization methods.

## Executive Summary
The paper identifies a critical gap in Generative Engine Optimization (GEO): existing methods optimize for broad "contribution" to a response rather than the binary "citation" event content creators desire, and they apply uniform rewrites without diagnosing the specific reason an individual document fails to be cited. To address this, the authors introduce a diagnostic GEO framework. Its core is AgentGEO, an agentic system that contrasts an uncited document with a cited competitor to pinpoint a precise failure mode from a novel taxonomy, selects a targeted repair tool from a specialized library, and iterates until the document achieves citation. Crucially, it aggregates edits across multiple queries to produce query-invariant improvements. The framework is evaluated on MIMIQ, a new document-centric benchmark where each webpage is associated with many queries, enabling held-out testing for generalization. AgentGEO substantially increases citation rates with minimal content changes, while analysis reveals that some failures (e.g., competitive redundancy) are inherently unrecoverable through content edits alone.

## Method Summary
The task is to diagnose why a target webpage fails to be cited by a generative engine for a given query and apply minimal, effective edits to secure citation. Inputs include the target HTML, a set of training queries, a failure taxonomy, and a library of specialized content/HTML editing tools. The objective is to maximize binary citation rate on held-out queries while preserving content fidelity (low modification ratio). The procedure centers on the AgentGEO pipeline: First, a *Diagnose-then-Repair Loop* runs per training query. The system retrieves a cited competitor for the same query, uses an LLM with the taxonomy to diagnose the failure mode (e.g., MISSING INFO, WINDOW TRUNCATION), and selects a corresponding tool from the library. It applies the tool's LLM-driven prompt to a specific HTML chunk of the target page, then retests citation. The loop uses memory to avoid repeating ineffective tools. After processing a batch of queries (default 5), a *Batch Aggregation* step merges successful edits by grouping them by the edited chunk index and ranking them by severity and confidence to select a single edit per chunk. Finally, *Localized Editing* applies these aggregated edits only to their identified structural HTML chunks (e.g., `<div>`, `<p>`) to limit overall page modifications.

## Key Results
- AgentGEO achieves a 40%+ relative improvement in citation rate (e.g., 79.52% vs. 68.80% for the best baseline).
- It modifies only ~5% of the page's content on average, compared to ~25% for generic rewriting methods like AutoGEO.
- Diagnostic optimization yields consistent gains across generative engines (GPT, Claude) and citation mechanisms, while generic methods can harm long-tail content performance.

## Why This Works (Mechanism)

### Mechanism 1: Heterogeneous Failure Diagnosis
- **Claim:** Citation failures arise from distinct root causes across the fetching, parsing, and generation stages of a GE pipeline, not a uniform lack of content quality.
- **Mechanism:** A structured failure taxonomy classifies vulnerabilities into Technical Integrity (10.1%), Semantic Alignment (62.2%), Content Quality (27.1%), and Systemic Exclusion (0.6%). This enables selection of a precisely targeted intervention (e.g., HTML repair vs. fact augmentation) instead of a one-size-fits-all rewrite.
- **Core Assumption:** Different failure modes require fundamentally different repair strategies; treating them as identical leads to wasted or harmful edits.
- **Break Condition:** If failure modes are not meaningfully distinct (e.g., "semantic gap" always co-occurs with "information scarcity"), the diagnostic premise collapses and generic rewrites could perform equally well.

### Mechanism 2: Iterative, Surgical Repair with Memory
- **Claim:** An iterative loop that diagnoses, applies a localized edit, and remembers ineffective tools achieves higher citation rates with fewer modifications than blanket page rewriting.
- **Mechanism:** For an uncited document, the system (1) compares it to a cited competitor to identify a specific competitive disadvantage, (2) selects a specialized tool from a library, (3) applies the edit only to the responsible HTML chunk, (4) uses memory to prevent re-using tools that failed for that query, and (5) aggregates edit suggestions across multiple training queries to find changes that make the document robustly citable.
- **Core Assumption:** Citation can be "fixed" by surgically addressing the specific, localized reason for non-citation relative to a competitor, not by globally rephrasing the entire page.
- **Break Condition:** If the GE's citation decision is largely stochastic or based on factors completely orthogonal to the diagnosed vulnerabilities (e.g., hidden ranking signals), the repair loop will fail to converge reliably.

### Mechanism 3: Document-Centric Evaluation for Generalization
- **Claim:** Evaluating optimization on the same query used for development leads to overfitting; true improvement in citation-worthiness is measured by performance on multiple, held-out queries associated with the same document.
- **Mechanism:** The MIMIQ benchmark associates each webpage with 60 diverse queries (varying intent, persona, phrasing). Optimization uses a training query subset; evaluation on unseen test queries tests for robustness. Variants (OOD personas, noisy HTML) further probe generalization and fault tolerance.
- **Core Assumption:** Content creators cannot anticipate exact user queries; therefore, optimization must produce a page that is broadly citable across query variations, not just for a few seed queries.
- **Break Condition:** If the held-out test queries are semantically too similar to the training queries (despite different phrasing), the evaluation does not genuinely test for overfitting avoidance.

## Foundational Learning

- **Concept: Citation vs. Contribution**  
  **Why needed:** The paper's foundation is that existing GEO optimizes for "contribution" (the fraction of a response text attributed to a source), but content creators care about the binary "citation" event (being listed as a source). Optimizing for contribution misaligns interventions.  
  **Quick check:** If a document is cited but its content contributes only 1% to the final answer, is that a success from the creator's perspective? Yes, for visibility; no, for influence.

- **Concept: Diagnostic vs. Generic Optimization**  
  **Why needed:** AgentGEO's core innovation is shifting from "what generic improvements might help?" to "why did *this* document fail?". Understanding the specific failure mode (from the taxonomy) is prerequisite to selecting an effective, minimal tool.  
  **Quick check:** For a document failing due to "Window Truncation" (content cut off by context limits), would a generic "improve writing style" tool likely help? No, as the issue is structural/positional, not stylistic.

- **Concept: Document-Centric Benchmarking**  
  **Why needed:** Prior GEO benchmarks are query-centric, encouraging overfitting to specific questions. MIMIQ's multi-query, document-centric design (train/test split on queries per page) is central to measuring a page's *intrinsic* improved visibility.  
  **Quick check:** Why is evaluating an optimized page on the exact same query it was optimized for a flawed experimental design? It measures query-specific memorization, not general citation-worthiness.

## Architecture Onboarding

- **Component Map:** Failure Taxonomy (static) -> Tool Library (specialized editors) -> Diagnose-then-Repair Loop (per query, with memory) -> Batch Aggregation (merge per-query edits) -> Localized Editing (apply to HTML chunks).

- **Critical Path:** For a target page and a batch of training queries: 1) Partition page into structure-aware HTML chunks. 2) For each query: Run diagnose-then-repair loop (compare to cited competitor -> diagnose failure -> select & apply tool to a chunk -> retest; iterate with memory). 3) After all queries, aggregate successful edits by chunk index, rank by severity/confidence, select top edit per chunk. 4) Apply aggregated edits simultaneously to original page. 5) Repeat for next batch until convergence or max iterations.

- **Design Tradeoffs:**  
  - **Batch Size:** Larger batches (e.g., 5) promote query-invariant improvements but may dilute document-specific fixes; batch=1 may overfit.  
  - **Locality vs. Impact:** Chunk-level edits preserve semantic fidelity but may miss cross-chunk synergies; whole-page rewriting risks high modification rates and drift.  
  - **Tool Specificity vs. Coverage:** Specialized tools are precise for known failures but require a comprehensive library; generic tools cover more cases but with lower efficacy per mode.  
  - **Memory Constraint:** Prevents tool repetition cycles but adds state management complexity.

- **Failure Signatures:**  
  - **No citation after N iterations:** Likely a "Systemic Exclusion" failure (competitive redundancy, truncation) unrecoverable by content edits.  
  - **High modification rate (>15%):** Indicates over-aggressive aggregation or poor tool selection, violating faithfulness.  
  - **Performance drop on OOD personas:** Signals overfitting to training query distribution during batch aggregation.  
  - **Edits repeatedly target same chunk:** Suggests a persistent failure mode or an insufficient tool library.

- **First 3 Experiments:**  
  1. **Ablate diagnosis:** Replace the diagnosis step with a random tool selector. Expected: Major citation rate drop, confirming diagnosis necessity.  
  2. **Disable memory:** Allow tool repetition within a query's loop. Expected: More iterations per query, possible cyclic behavior, lower final CR.  
  3. **Test batch aggregation:** Compare batch=1 (sequential updates) vs. batch=5 (aggregated). Expected: batch=1 may score higher on training queries but generalize worse to test queries due to overfitting.

## Open Questions the Paper Calls Out
1. How does AgentGEO's diagnostic and repair performance translate when applied directly to production, black-box commercial generative engines (e.g., Google AI Overviews, Perplexity, ChatGPT Search) whose pipelines and citation mechanisms are not fully observable?
2. Can the scalability of AgentGEO's iterative diagnosis-and-repair loop be improved via knowledge distillation or more efficient diagnosis strategies without sacrificing its targeted, low-modification advantage?
3. What are the precise systemic, non-content factors (e.g., domain authority signals, source reputation, recency biases in the retrieval index) that cause "Systemic Exclusion" failures (Competitive Redundancy, Window Truncation), and can these be addressed by interventions beyond content modification?
4. How generalizable is the proposed failure taxonomy across different generative engine architectures (e.g., retrieval-augmented vs. fully parametric, inline vs. pre-hoc attribution) and as these systems evolve?
5. Does the diagnostic optimization process for citation create trade-offs with other desiderata for web content, such as long-term user engagement, factual robustness, or accessibility for human readers?

## Limitations
- Systemic failures (competitive redundancy, window truncation) appear inherently unrecoverable via content-only edits, setting a ceiling on achievable citation rates.
- The tool library may not cover all possible failure modes; diagnosis relies on an LLM which could misclassify edge cases.
- Batch aggregation discards edits when multiple tools target the same chunk, potentially losing beneficial combined effects.
- LLM-driven edits risk semantic drift or factual alteration despite fidelity constraints and low modification percentages.

## Confidence
- **Taxonomy (Medium):** Novel and data-driven (949 pairs), but its generalizability beyond the analyzed sample and across GE architectures is an assumption.
- **AgentGEO Efficacy (Medium):** Strong results (+40% rel. CR, 5% mod. rate) but depend on unspecified LLM settings, chunking heuristics, and tool-confidence heuristics.
- **MIMIQ Validity (Medium-High):** Sound document-centric design addresses prior benchmark flaws; OOD/HTML robustness supports utility, but lack of public splits hinders full verification.
- **Generalization Claims (Medium):** Transfer across GPT/Claude and citation mechanisms is demonstrated, but real-world commercial GE remains untested.

## Next Checks
1. **Cross-engine generalization:** Replicate AgentGEO on real APIs for commercial generative engines (Perplexity, You.com, ChatGPT Search) across domains and languages to test framework universality.
2. **Tool-gap stress test:** Inject synthetic failures not in the taxonomy (e.g., specific parsing errors) and measure diagnosis accuracy and recovery rate to stress-test tool library coverage.
3. **Faithfulness audit:** Conduct a human evaluation of 100 aggregated edits to detect factual or conceptual drift beyond what TF-IDF/embedding similarity metrics capture.
