# Easy to Learn, Yet Hard to Forget: Towards Robust Unlearning Under Bias

## Quick Facts
- **ArXiv ID:** 2602.21773
- **Source URL:** https://arxiv.org/abs/2602.21773
- **Reference Count:** 19
- **Primary Result:** CUPID attains near-zero forget accuracy on unbiased test sets (e.g., 3.75% on BAR) and minimal bias-related performance gap (2.88%) without a retain set.

## Executive Summary
Machine unlearning under data bias is challenged by "shortcut unlearning," where models forget spurious correlations instead of the intended causal class information. This paper introduces CUPID, a three-stage framework that first partitions the forget set by loss landscape sharpness, then disentangles model parameters into causal and bias pathways via Hessian-based saliency, and finally applies tailored gradient updates that route forgetting signals appropriately. Evaluated on Waterbirds, BAR, and Biased NICO++, CUPID outperforms existing methods, achieving the lowest forget accuracy and smallest performance gap while preserving retain accuracy and privacy—all without requiring a retain set.

## Method Summary
CUPID operates on a pre-trained biased model and a designated forget class (the entire forget set). First, per-sample sharpness ω_sharpness(x) is computed using a single-step adversarial perturbation; the forget set is split into a causal-approximated subset D_causal_f (sharpest k%, e.g., k=5%) and a bias-approximated subset D_bias_f (remaining). Second, a binary saliency mask m_c identifying the "causal pathway" is derived: for each parameter θ_i, the score ½·θ_i²·E[H(θ,x)_ii] over D_causal_f is computed, and the top τ_p percentile (τ_p=50%) is masked. Third, gradients are computed: g_f on the full forget set and g_causal on D_causal_f. The total forget gradient is projected onto the causal direction: g_proj = (g_f·g_causal/‖g_causal‖²)·g_causal, with the residual defined as g_bias = g_f - g_proj. The final update combines these components element-wise, weighted by ω_sharpness and masked by m_c: Δθ = α·[(ω_sharpness·g_proj ⊙ m_c) + (g_bias ⊙ (1−m_c))]. This surgical update forgets the target class while preserving bias-conflicting features and retain set performance—without any retain data.

## Key Results
- **Forget Accuracy:** Near-zero on unbiased test sets (e.g., 3.75% on BAR), significantly lower than competing methods.
- **Bias Gap:** Minimal performance difference between bias-aligned and bias-conflicting samples (△ gap reduced to 2.88%).
- **Robustness:** High retain accuracy (>90% on Waterbirds) and strong privacy (low MIA attack success); ablations confirm all three components are essential.

## Why This Works (Mechanism)
### Mechanism 1: Loss landscape sharpness partitions the forget set
- **Claim:** Loss landscape sharpness (ω_sharpness) can partition the forget set into subsets approximating bias-aligned (easy, flat) and bias-conflicting (hard, sharp) samples.
- **Mechanism:** Compute per-sample sharpness via a single-step adversarial perturbation: ω_sharpness(x) = L(θ_adv, x) - L(θ_o, x), where θ_adv = θ_o + η·(∇L(θ_o,x)/‖∇L(θ_o,x)‖). Samples with low sharpness form D_bias_f; high sharpness form D_causal_f (top k%).
- **Core assumption:** Bias-aligned samples lie in flat minima (good generalization), while bias-conflicting samples occupy sharper regions (harder to learn). This geometric distinction reflects reliance on shortcuts vs. causal features.
- **Evidence:** The abstract notes distinct sharpness for different biases; Figure 1(d) shows bias-aligned samples clustering near zero sharpness and bias-conflicting samples having a broader, higher distribution. Related sharpness-aware unlearning work exists, but this specific partitioning is novel.
- **Break condition:** Significant overlap in sharpness distributions would contaminate subsets, making disentanglement ineffective.

### Mechanism 2: Hessian-based saliency disentangles causal and bias pathways
- **Claim:** Parameters can be separated into a "causal pathway" (important for D_causal_f) and a "bias pathway" (important for D_bias_f) using a saliency mask that combines parameter magnitude and local Hessian curvature.
- **Mechanism:** For each parameter θ_o,i, compute saliency score s_i = ½·θ_o,i²·E_{x~D_causal_f}[H(θ_o, x)_{ii}]. Parameters in the top τ_p percentile (e.g., 50%) are assigned to the causal pathway (mask m_c = 1); others to bias pathway (m_c = 0).
- **Core assumption:** Parameters that are large in magnitude and located in high-curvature regions on D_causal_f are disproportionately responsible for encoding the harder-to-learn causal features. Smaller, flatter-region parameters handle the easier shortcuts.
- **Evidence:** The abstract and Section "Causal Pathway Identification" describe combining magnitude and Hessian, citing LeCun et al. (1989). Ablation in Table 3 shows removing this component drastically degrades performance.
- **Break condition:** Noisy Hessian estimates (e.g., from small batch sizes for D_causal_f) yield an unreliable mask, misassigning parameters and harming retain accuracy.

### Mechanism 3: Disentangled gradients enable surgical forgetting
- **Claim:** Routing refined causal and bias gradients to their respective pathways allows forgetting causal class information while mitigating shortcut unlearning.
- **Mechanism:** Compute g_causal as average gradient on D_causal_f. Project the full forget gradient g_f onto g_causal: g_proj = (g_f·g_causal/‖g_causal‖²)·g_causal. Define bias gradient g_bias = g_f - g_proj. Update parameters as Δθ = α·[(ω_sharpness·g_proj ⊙ m_c) + (g_bias ⊙ (1−m_c))], i.e., causal pathway receives g_proj weighted by sample sharpness, bias pathway receives g_bias.
- **Core assumption:** g_causal is dominated by signals for true causal features; thus g_proj isolates the component that forgets class information. The orthogonal residual g_bias mainly contains bias/shortcut signals.
- **Evidence:** Abstract mentions "tailored gradients" and "routing refined causal and bias gradients". Section "Targeted Pathway Update" details the process. Table 4 ablation shows both gradient components are necessary and synergistic; using only g_bias fails to forget, using only g_proj improves but is suboptimal.
- **Break condition:** If D_causal_f is too small or noisy, g_causal becomes an unreliable proxy for the causal direction, misaligning g_proj and causing ineffective forgetting or retain degradation.

## Foundational Learning
#### Loss Landscape Sharpness
- **Why needed:** Serves as the primary partitioning signal; the hypothesis is that bias-aligned samples reside in flat minima while bias-conflicting samples occupy sharper regions.
- **Quick check:** If sharpness is computed via a single gradient step perturbation, what distribution would you expect for a model that has memorized a spurious correlation? (Bias-aligned samples near zero sharpness; bias-conflicting samples higher and broader.)

#### Hessian-based Parameter Saliency
- **Why needed:** To identify which parameters are most responsible for processing the harder causal samples, combining curvature (second derivative) with magnitude to find "important" weights.
- **Quick check:** Why not use just gradient magnitude? What additional signal does the diagonal Hessian element provide? (Curvature indicates sensitivity; large magnitude in high-curvature regions suggests parameters crucial for the objective.)

#### Gradient Projection & Orthogonal Decomposition
- **Why needed:** To separate the total forget gradient into a component aligned with forgetting causal features (g_proj) and a residual bias component (g_bias), enabling targeted updates.
- **Quick check:** Given vectors a and b, how do you compute the component of a that is parallel to b? How do you get the orthogonal component? (Parallel: (a·b/‖b‖²)·b; orthogonal: a - parallel.)

## Architecture Onboarding
**Component map:**
Forget set → Sharpness Calculator → Partition Module → {D_causal_f, D_bias_f}
D_causal_f → Saliency Mask Generator → binary mask m_c
D_f, D_causal_f, m_c → Gradient Router → projected (g_proj) and bias (g_bias) gradients
Gradients → Update Applier → final parameter update

**Critical path:**
Forward pass → Compute per-sample sharpness → Partition forget set → Compute Hessian on D_causal_f → Generate m_c → Compute gradients → Project & decompose → Apply disentangled update.

**Design tradeoffs:**
- Sharpness threshold (k): Lower k yields purer D_causal_f but noisier g_causal; optimal around k=5% balances purity and stability.
- Saliency sparsity (τ_p): Higher τ_p selects fewer, more salient parameters but risks insufficient pathway coverage; τ_p=50% used.
- Hessian estimation cost: Exact per-sample diagonal Hessian is expensive; approximations trade accuracy for scalability.

**Failure signatures:**
- High Forget Accuracy (>20%) on unbiased test set.
- Large △ gap (>15–20%) between bias-aligned and bias-conflicting forget samples.
- Grad-CAM visualizations still highlight spurious features.
- Ablation: removing any component (partitioning, pathway ID, targeted update) causes performance collapse (Table 3).

**First 3 experiments:**
1. **Validate Sharpness Partitioning:** Replicate Figure 1(d) by plotting sharpness distributions for known bias-aligned vs. bias-conflicting samples; expect clear separation.
2. **Ablation Study:** Systematically exclude Sharpness Partitioning, Causal Pathway Identification, and Targeted Update (as in Table 3); anticipate dramatic increase in FA and △ gap without all three.
3. **Baseline Comparison:** Compare CUPID against standard unlearning methods (NegGrad, Random Label, etc.) on Waterbirds, BAR, and Biased NICO++; CUPID should achieve lower FA and smaller △ gap, especially on unbiased test sets.

## Open Questions the Paper Calls Out
### Open Question 1: Extending CUPID to abstract concept erasure
- **Basis:** The Conclusion states that adapting the surgical approach to erase abstract concepts (e.g., artistic style, toxic language) is future work.
- **Why unresolved:** The current framework targets binary entanglement between a class label and a single spurious attribute. Abstract concepts are distributed, multi-faceted, and entangled with numerous features, likely requiring more sophisticated pathway identification.
- **What evidence would resolve it:** Apply a modified CUPID to benchmark tasks like removing watermarks from image classifiers or gender bias from text models. Success would be measured by effective concept removal (via probing or concept activation vectors) with minimal utility loss, supported by ablation of new mechanisms.

### Open Question 2: Sufficiency of an impure partition
- **Basis:** The paper acknowledges that D_causal_f may contain some bias-aligned samples and argues that functional enrichment, not purity, is the goal; optimal performance occurs at k=5%, not with a "purer" set.
- **Why unresolved:** The trade-off between partition purity and stability is not systematically analyzed. The threshold k is chosen heuristically; it is unclear how dataset bias severity or model architecture affects the optimal impurity level.
- **What evidence would resolve it:** A study varying k across bias strengths (e.g., 90:10 to 99.9:0.1). Correlating partition purity (against true bias labels) with final metrics (FA, △ gap) would reveal whether there is a purity threshold below which performance collapses, or if a broad functional range is acceptable.

### Open Question 3: Universality of the sharpness–bias correlation
- **Basis:** The core methodological insight posits that bias-aligned samples cluster in a narrow distribution near zero sharpness, while bias-conflicting samples exhibit a broader, higher-sharpness distribution.
- **Why unresolved:** The evidence is limited to ResNet-50 on three image datasets. The sharpness metric may be confounded by sample difficulty, label noise, or data curvature. It is unknown if this relationship holds for other architectures (e.g., Transformers), modalities (NLP, tabular), or training regimes.
- **What evidence would resolve it:** Replicate the sharpness analysis (Figure 1d) across diverse models, datasets, and training procedures (e.g., group-DRO). Consistent separation would strengthen the principle; inconsistent results would necessitate a more robust differentiator.

### Open Question 4: Hybrid scenario with a small retain set
- **Basis:** The paper explicitly operates without a retain set and compares to methods both with and without retain data, but does not explore a hybrid where a small retain set is available.
- **Why unresolved:** Real-world unlearning (e.g., GDPR) often allows retention of other data. CUPID's surgical updates may interfere with or synergize with retain-set-based strategies; this trade-off is unexamined.
- **What evidence would resolve it:** Introduce a small, balanced retain set for all methods, including a CUPID variant optionally incorporating retain gradients. Compare FA, RA, and △ gap in this low-retain regime against standard retain-set methods (e.g., DELETE, SALUN) to clarify trade-offs and potential synergies.

## Limitations
- **Hessian estimation:** The exact per-sample diagonal Hessian is prohibitively expensive for ResNet-50; the paper's approximation method is unspecified, creating a major implementation ambiguity.
- **Sharpness metric:** The single-step perturbation (Eq. 2) and top-k threshold lack sensitivity analysis; overlap in sharpness distributions between bias-aligned and bias-conflicting samples would invalidate the partitioning assumption.
- **Generalizability:** All validation uses three synthetic bias datasets; performance on natural, uncontrolled biases is unknown.
