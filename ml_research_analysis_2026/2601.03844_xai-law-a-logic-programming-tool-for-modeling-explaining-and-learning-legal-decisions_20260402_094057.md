# XAI-LAW: A Logic Programming Tool for Modeling, Explaining, and Learning Legal Decisions
## Quick Facts
- **arXiv ID:** 2601.03844
- **Source URL:** https://arxiv.org/abs/2601.03844
- **Reference count:** 40
- **Primary result:** XAI-LAW uses Answer Set Programming to model Italian criminal law, automatically generate explainable decisions, and refine its knowledge base by learning rules from past judgments via ILASP, handling precedent contradictions with legal maxims.

## Executive Summary
XAI-LAW is an AI system that encodes Italian Criminal Code articles in Answer Set Programming (ASP) to support criminal trials. It produces legally consistent decisions together with human-readable justifications, and it can improve its knowledge by inducing new rules from historical judgments using Inductive Logic Programming (ILASP). Contradictions among precedents are resolved using built-in legal maxims (lex specialis, superior, posterior). Empirical evaluation on real verdicts shows that explanation generation is fast (xclingo2 average 0.078s, xASP average 1.65s), while ILASP learning times vary widely depending on dataset complexity and the use of mode declarations. The tool is publicly released.

## Method Summary
The system builds an ASP knowledge base (`Plaw`) containing manually encoded statutory rules. Vagueness (e.g., object adherence levels) and exceptions (e.g., violence negating snatch theft) are handled via choice rules and default negation (`not`). Contradictions between precedents are resolved using built‑in maxims (`lex specialis`, `superior`, `posterior`) or flagged with a `contradiction` predicate. A CDCL‑based ASP solver computes stable models that represent legally consistent outcomes for a given case fact set. To extend `Plaw`, past judgments are translated into ILASP examples; ILASP then searches a hypothesis space (defined by direct rules or mode declarations) for minimal rule sets `H` such that `B ∪ H` explains the examples under brave or cautious reasoning. Learned rules are added to the knowledge base with a marker predicate (`using_judgment`). Explanations are derived from the stable model using either xclingo2 (textual trace trees) or xASP (dependency graphs), both exploiting the supportedness of atoms.

## Key Results
- ILASP learning times range from 0.196 s to 549.576 s, with mode declarations dramatically increasing runtime.
- Explanation generation is highly efficient: xclingo2 averages 0.078 s, xASP averages 1.65 s.
- The tool successfully models Italian criminal law and automatically resolves conflicts between precedents using legal maxims.

## Why This Works (Mechanism)
### Mechanism 1: ASP-Based Non-Monotonic Legal Reasoning
- **Claim:** The tool models Italian Criminal Code articles and judicial reasoning by encoding legal rules in Answer Set Programming (ASP), which can represent exceptions, defaults, and contradictory precedents through stable model semantics.
- **Mechanism:** Immutable legal rules (from statutes) are encoded as ASP rules. Vagueness (e.g., object adherence levels) and exceptions (e.g., violence negating snatch theft) are handled via choice rules and default negation (`not`). Contradictions between precedents are resolved using built‑in maxims (`lex specialis`, `superior`, `posterior`) or flagged with a `contradiction` predicate. A CDCL‑based ASP solver computes stable models that represent legally consistent outcomes for a given case fact set.
- **Core assumption:** Legal reasoning is fundamentally non‑monotonic—new facts or exceptions can override previous conclusions—and ASP’s stable model semantics can formally capture this.
- **Evidence anchors:**
  - [abstract] "using Answer Set Programming (ASP), and to semi‑automatically learn legal rules from examples based on prior judicial decisions... contradictions may arise; these are properly handled by the system..."
  - [section 3.1] "rule ‘if you subtract an object...’ was translated... `theft_snatch(R, V) :- theft(R, V, C), res_violence(R, C), not person_violence(R, V).`"
  - [section 3.4] "contradiction(...) :- only_pain(I), illness(I)."
- **Break condition:** If the ASP program becomes inconsistent (no stable model) under all refinements, or if contradictions between maxims cannot be prioritized, the system cannot produce a coherent decision without expert intervention.

### Mechanism 2: Inductive Logic Programming for Rule Refinement
- **Claim:** The system refines its knowledge base by inducing new legal rules from past judgments using ILASP, generalizing from examples while respecting the ASP background knowledge.
- **Mechanism:** Past verdicts are encoded as context‑dependent examples with inclusions (atoms that must appear), exclusions (atoms that must not), and context facts. ILASP searches a hypothesis space (defined via direct rule declarations or mode declarations) for minimal rule sets `H` such that `B ∪ H` explains the examples under brave or cautious reasoning. Learned rules are added to `Plaw` with a marker predicate (`using_judgment`) to distinguish them from statutory rules.
- **Core assumption:** Patterns in judicial decisions can be captured by logical rules that are discoverable from examples, and these rules can extend the initially encoded statutory model.
- **Evidence anchors:**
  - [abstract] "the tool integrates an inductive logic programming system for ASP, which is employed to generalize legal rules from case examples."
  - [section 5.1] `#pos({beatings("R", "V"), ...}, {derive_illness("V")}, {harmful_intention("R"). ...}).` and "The learned rules have been added to the background knowledge... with a marker predicate."
  - [section 5.2] Table 1 shows ILASP timing on different datasets, indicating the process is feasible but computationally variable.
- **Break condition:** If the hypothesis space is too constrained (missing relevant predicates) or too large (infeasible search), ILASP may fail to find a hypothesis or take excessive time. Noisy or contradictory examples can also prevent convergence.

### Mechanism 3: Explanation Generation via xASP/xclingo2
- **Claim:** The tool provides human‑understandable justifications for ASP outcomes by tracing rule applications, either as natural language trees (xclingo2) or dependency graphs (xASP).
- **Mechanism:** After solving, xclingo2 uses user‑provided `%!trace` annotations on rules/facts to produce a hierarchical textual justification. xASP constructs a Directed Acyclic Graph (DAG) where nodes are inferred facts and edges are rules, visualizing the support chain. Both methods leverage the "supportedness" of atoms in the stable model.
- **Core assumption:** Legal decisions are acceptable only if their logical derivation is interpretable by experts; exposing the rule activation path fulfills this.
- **Evidence anchors:**
  - [abstract] "provides explanations through a tool that leverages the ‘supportedness’ of stable models."
  - [section 4] Detailed example with xclingo2 annotations producing a tree, and xASP graph description with "average time 1.65s".
  - [section 2.3] Discusses "explainability" contrast with black‑box systems like COMPAS.
- **Break condition:** If the explanation graph/tree becomes too large (combinatorial explosion of supported rules), it may become incomprehensible. Annotations must be carefully crafted by domain experts to map ASP predicates to meaningful legal concepts.

## Foundational Learning
- **Concept: Stable Model Semantics (ASP)**
  - Why needed here: Defines the formal meaning of the legal rule program; determines which sets of conclusions (e.g., guilty of theft) are consistent with the encoded statutes and facts.
  - Quick check question: Given a rule `p(X) :- q(X), not r(X).` and facts `q(a). r(b).`, what atoms are in all/can be in some stable model?

- **Concept: Inductive Logic Programming (ILP) / ILASP**
  - Why needed here: Allows the system to automatically learn new rules from past judgments, adapting the legal model without manual recoding.
  - Quick check question: What is the difference between brave and cautious reasoning in the context of legal example coverage?

- **Concept: Legal Vagueness & Non‑Determinism**
  - Why needed here: Legal concepts (e.g., "tight adherence") are often undefined; ASP choice rules model this as multiple possible interpretations to be resolved by evidence.
  - Quick check question: How would you encode a legal standard like "significant force" using ASP choice rules?

## Architecture Onboarding
- **Component map:** Plaw Core -> ILASP Learner -> Validation/Refinement Loop -> Explanation Module -> Interface
- **Critical path:** New case facts → ASP solver with Plaw ∪ facts → Stable model(s) → Explanation generation → (Optional) ILASP learning from new judgment → Plaw update after expert review.
- **Design tradeoffs:** Manual vs. automated encoding (accuracy vs. bottleneck); hypothesis space size (expressiveness vs. ILASP time, per Table 1); multiple stable models (comprehensiveness vs. explanation complexity).
- **Failure signatures:** 
  - No stable model for a case → either facts are contradictory or Plaw is too restrictive.
  - Excessive ILASP time (> minutes) → hypothesis space too large (mode declarations) or examples noisy.
  - Explanation graph with >50 nodes → likely too complex for human review; may need abstraction.
- **First 3 experiments:**
  1. **Simple statutory test:** Encode a clear case of theft (object taken from person, no violence). Verify `theft_snatch` and not `robbery` is the unique stable model. Time solvers.
  2. **Vagueness test:** Encode a snatch theft with `unknown_adherence`. Check multiple stable models (different adherence levels). Verify xclingo2 tree shows correct branch.
  3. **ILASP learning test:** Take 5 similar past judgments for a crime (e.g., personal injury). Define hypothesis space with direct rules. Run ILASP; verify learned rule matches a known pattern and adds `using_judgment`. Check total time under 10s.

## Open Questions the Paper Calls Out
The paper identifies several open questions for future research:
- How can the full ASP encoding of the Italian Criminal Code (`Plaw`) be completed and publicly released to enable broader validation?
- Can ILASP learning be made more efficient and predictable, given the observed high variability in runtimes, especially with mode declarations?
- How can the system address the unavailability of original judgment datasets for independent replication of learning experiments?
- What alternative approaches can handle precedent contradictions that are not resolved by the three maxims (`lex specialis`, `superior`, `posterior`)?
- How can explanation generation be further improved to enhance readability for non‑technical legal experts?

## Limitations
- The complete ASP encoding of all Italian Criminal Code articles (`Plaw`) is not released, preventing full‑scale replication and testing.
- The original judgment datasets (Foroplus/DeJure) used for ILASP training are unavailable, so learning performance cannot be independently verified.
- ILASP learning times show high variability and can become prohibitive, especially with mode declarations.
