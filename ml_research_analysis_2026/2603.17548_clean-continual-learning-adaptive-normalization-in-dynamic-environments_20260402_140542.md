# CLeAN: Continual Learning Adaptive Normalization in Dynamic Environments

## Quick Facts
- **arXiv ID:** 2603.17548
- **Source URL:** https://arxiv.org/abs/2603.17548
- **Reference count:** 40
- **Primary result:** CLeAN, an adaptive normalization method using EMA for min/max estimation and a learned scaling network, consistently achieves performance comparable to the global normalization upper bound and significantly reduces catastrophic forgetting on continual learning benchmarks for tabular cybersecurity data.

## Executive Summary
This paper tackles the overlooked challenge of data normalization in continual learning (CL) for tabular data, where standard per-chunk min-max scaling fails due to distribution shifts. The proposed solution, CLeAN, maintains globally consistent normalization bounds across sequential data chunks using an Exponential Moving Average (EMA) to estimate feature minima and maxima, complemented by a learnable element-wise scaling network. Evaluated on two large cybersecurity intrusion detection datasets across multiple CL strategies (Reservoir Replay, A-GEM, EWC), CLeAN stabilizes to near-ideal global normalization performance and demonstrably reduces catastrophic forgetting while maintaining high accuracy and AUROC. The work positions adaptive normalization as a powerful, standalone mechanism for enhancing stability in dynamic, non-stationary tabular environments.

## Method Summary
CLeAN introduces two key adaptations to standard min-max normalization for CL settings. First, it replaces per-chunk statistics with smoothed, memory-efficient estimates of global feature minima (`ˆm_t`) and maxima (`ˆM_t`) updated via an Exponential Moving Average (EMA) using the current chunk's raw statistics. Second, it applies a learned diagonal neural network `Φ` (an affine transformation) to the EMA-normalized features, allowing the model to adjust feature magnitudes for optimal predictive performance. During training on each sequential experience `t`, the EMA parameters are updated *before* normalizing the current chunk's data, ensuring a consistent input distribution for the primary model `f_Θ`. The entire system—EMA estimators, scaling network `Φ`, and predictive model `f_Θ`—is trained end-to-end. This design avoids storing historical data while tracking evolving data ranges, contrasting with baselines like local per-chunk scaling or Continual Normalization (CN) which adapts mean/std.

## Key Results
- CLeAN achieves average accuracy and AUROC comparable to the theoretical global normalization upper bound after an early stabilization period, outperforming local and CN baselines.
- It significantly reduces average catastrophic forgetting compared to local and CN normalization when combined with replay and regularization strategies (Reservoir, A-GEM, EWC).
- The method demonstrates robust retention capabilities across both UNSW-NB15 and CICIDS-2017 datasets, validating its effectiveness in realistic, large-scale tabular streams.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** CLeAN mitigates catastrophic forgetting by maintaining stable, globally consistent normalization bounds across non-stationary data chunks, preventing representation drift.
- **Mechanism:** An Exponential Moving Average (EMA) updates per-feature min/max estimators (`ˆM_t`, `ˆm_t`) using local chunk statistics (`M_t`, `m_t`). This creates a smoothed, memoryful estimate of global data range that evolves gradually rather than resetting per chunk.
- **Core assumption:** Gradual distribution shifts are more common than instantaneous jumps; EMA smoothing prevents overreaction to transient outliers while tracking slower trends.
- **Evidence anchors:** Abstract states CLeAN uses "an Exponential Moving Average (EMA) module, enabling the model to adapt to evolving data distributions." Section 3.5 defines EMA update rules; Section 4.4 notes early non-stabilization followed by stable bounds.
- **Break condition:** Extremely abrupt distribution shifts (e.g., adversarial scaling) may cause EMA lag, leading to temporary normalization instability and performance dips as seen early in training.

### Mechanism 2
- **Claim:** A learned element-wise scaling network (`s_Φ`) refines normalized features to better align with the predictive model's internal representation needs, beyond simple min-max scaling.
- **Mechanism:** After EMA-based min-max normalization (`ˆX_t`), a diagonal neural network `Φ` applies a per-feature affine transformation (`s_Φ(·)`), trained end-to-end with the main model `f_Θ`. This allows the normalization to learn nonlinear adjustments accounting for feature importance or model sensitivity.
- **Core assumption:** Fixed min-max scaling is suboptimal; the model benefits from adaptive, learned adjustments to feature magnitudes.
- **Evidence anchors:** Abstract mentions "a learned scaling layer Φ" and that normalization "becomes more reliable" after training. Section 3.5 describes `Φ` as a neural network with diagonal weight matrix applied post-EMA normalization.
- **Break condition:** With very small buffer sizes or highly sparse early data, `Φ` may overfit initial chunks, causing poor generalization until EMA stabilizes and sufficient data arrives.

### Mechanism 3
- **Claim:** CLeAN acts as an implicit regularizer that reduces interference between gradient updates across experiences by stabilizing input distributions, complementing explicit CL methods.
- **Mechanism:** Consistent normalization bounds reduce covariate shift *between* experiences. Gradient updates computed on chunk `X_t` use inputs scaled similarly to past chunks, reducing parameter updates that degrade performance on earlier distributions.
- **Core assumption:** Part of catastrophic forgetting stems from input distribution instability; stabilizing inputs reduces the need for aggressive parameter-level regularization.
- **Evidence anchors:** Abstract claims CLeAN is a "powerful, standalone mechanism" for mitigating forgetting. Section 4.4 states CLeAN "exhibits significantly improved memorization capabilities... complementing existing techniques."
- **Break condition:** If the predictive model `f_Θ` itself is highly unstable, input stabilization alone may insufficiently prevent interference, and explicit CL methods remain necessary.

## Architecture Onboarding
- **Component map:**
  EMA Estimators (`ˆM_t`, `ˆm_t`) -> Local Statistics Compute (`M_t`, `m_t`) -> Scaling Network `s_Φ` -> Predictive Model `f_Θ`. The loop: update EMA → normalize via `(X_t - ˆm_t)/(ˆM_t - ˆm_t)` → apply `s_Φ` → train `f_Θ` and `Φ`.

- **Critical path:**
  Initialize `ˆM_0=1`, `ˆm_0=0`. For each new chunk `t`: compute `M_t`, `m_t` from current training data → update `ˆM_t`, `ˆm_t` via EMA → compute `ˆX_t` using updated estimators → apply `s_Φ` → forward/backward pass on `f_Θ` and `Φ`. EMA update must precede current chunk normalization.

- **Design tradeoffs:**
  - **EMA decay `η`:** High `η` (≈1) smooths aggressively, lagging during rapid shifts but stabilizing; low `η` adapts quicker but risks outlier sensitivity.
  - **Scaling network `Φ` complexity:** Diagonal matrix is lightweight but limits feature interactions; a full network could overfit with limited sequential data.
  - **Compute overhead:** EMA and `Φ` add minimal parameters/compute vs. baseline min-max; tradeoff is acceptable for stability gains.

- **Failure signatures:**
  1. **Early performance dip:** Accuracy/AUROC drop in first 1-2 experiences as `Φ` and EMA are untrained/unstabilized.
  2. **Plateau below global bound:** If `η` too low, noise dominates; if `Φ` capacity too high, overfitting occurs.
  3. **Divergence in forgetting metric:** If accuracy drops drastically on past tasks, EMA may have been destabilized (check `ˆM_t - ˆm_t` for NaNs/zeros).

- **First 3 experiments:**
  1. **Baseline comparison on UNSW-NB15:** Train with Global, Local, CN, CLeAN under Reservoir replay. Expect CLeAN to match Global accuracy after stabilization and show lower forgetting than Local/CN.
  2. **Ablation of `η`:** Run CLeAN with `η ∈ {0.9, 0.95, 0.99}` on CICIDS-2017. Expect higher `η` reduces forgetting but slows early adaptation; observe tradeoff curve.
  3. **Zero-replay stress test:** Use Finetuning (no buffer) with CLeAN vs. Local normalization. Expect CLeAN to show significantly less forgetting due to stable inputs even without replay memory.

## Open Questions the Paper Calls Out
- **Open Question 1:** How does the EMA smoothing parameter `η` influence CLeAN's convergence speed, stability, and final performance under different distribution shift conditions? *Basis:* Authors explicitly state a systematic analysis of `η` is left for future work.
- **Open Question 2:** Does integrating CLeAN with hybrid continual learning methods (e.g., replay-regularization combinations) yield further improvements in accuracy and forgetting reduction? *Basis:* Conclusion proposes investigating interaction with advanced hybrid techniques.
- **Open Question 3:** Can CLeAN be extended to multimodal data streams and large-scale real-time deployment without sacrificing performance? *Basis:* Authors propose extending adaptive normalization to multimodal scenarios and large-scale systems.

## Limitations
- **Dataset scope:** Results are limited to two cybersecurity datasets; generalization to other tabular domains (e.g., finance, healthcare) is unverified.
- **Hyperparameter opacity:** Key values (`η`, `λ_CN`, buffer size, EWC `λ`, `Φ` learning rate) are unspecified, forcing guesswork in reproduction.
- **Architecture details:** `Φ`'s full design (depth, activations, bias) is vague; the assumed simple affine transform may differ from the true implementation.

## Confidence
- **Mechanism 1 (EMA stabilization):** High. Strongly supported by equations, ablation discussion, and consistent performance approaching the global bound.
- **Mechanism 2 (learned scaling `Φ`):** Medium. Paper asserts `Φ`'s role, but direct evidence (e.g., ablation without EMA) is weak; neighbors show adaptive affine transforms in other contexts but not for tabular CL.
- **Mechanism 3 (implicit regularization):** Low. Claim is largely inferential; no ablation isolating CLeAN from explicit CL methods (e.g., using CLeAN alone without replay/EWC).
