# Toward Automatic Filling of Case Report Forms: A Case Study on Data from an Italian Emergency Department

## Quick Facts
- arXiv ID: 2602.23062
- Source URL: https://arxiv.org/abs/2602.23062
- Reference count: 0
- Primary result: Zero-shot LLaMA-3 8B Instruct achieves micro-F1 0.920 but macro-F1 0.548 on a 134-item CRF, with a severe bias predicting "unknown" (90.42% accuracy) over informative values (1.57%).

## Executive Summary
This study investigates the feasibility of automatically populating a 134-item Case Report Form (CRF) from unstructured Italian emergency department clinical notes using large language models (LLMs). The authors introduce a novel dataset of 290 Italian clinical notes with gold-standard CRF annotations. In a zero-shot setting using LLaMA-3 8B Instruct, the model demonstrates high token-level accuracy (micro-F1 0.920) but poor performance on non-"unknown" values (macro-F1 0.548), revealing a strong bias toward the majority "unknown" class. The work highlights both the potential and the critical limitations of using out-of-the-box LLMs for sparse, structured information extraction in clinical domains.

## Method Summary
The approach uses a zero-shot prompting strategy with LLaMA-3 8B Instruct. The 290-note dataset (NLP-FBK/SGB-crf-italian) contains Italian clinical texts and corresponding structured annotations for 134 CRF items with predefined English value sets. Each (note, item) pair is processed independently via a structured prompt containing a system role, item group context, an item-specific instruction listing allowed values, and the full clinical note. The model is instructed to extract a value from the provided list, defaulting to "unknown." Performance is evaluated using micro-F1 (overall accuracy) and macro-F1 (balanced across items), with a baseline of always predicting the most frequent value ("unknown").

## Key Results
- The created dataset contains 290 Italian emergency department notes annotated for a 134-item CRF; 96.38% of all item labels are "unknown."
- Zero-shot LLaMA-3 8B Instruct yields micro-F1 0.920 and macro-F1 0.548.
- The model shows a drastic performance gap: 90.42% accuracy on "unknown" values versus only 1.57% on other values, indicating a severe "cautious" bias.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Zero-shot cross-lingual information extraction from clinical Italian notes into a structured English CRF schema is feasible with open-weight LLMs.
- **Mechanism:** The model leverages its pre-trained multilingual and medical-domain knowledge to map unstructured Italian clinical text to predefined English CRF items and their allowed value sets, without task-specific fine-tuning, guided by the prompt's explicit definitions.
- **Core assumption:** The LLM's internal representations align Italian clinical language with the English CRF terminology and value constraints via the prompt.
- **Evidence anchors:** Paper abstract states CRF-filling can be approached zero-shot. Section 3 details the prompt structure with item definitions and value lists. External support is weak; evidence is primarily from the target study.
- **Break condition:** Model fails to select values from the provided allowed list or outputs in Italian instead of the required schema values.

### Mechanism 2
- **Claim:** Structured prompting with explicit, per-item value enumeration enforces schema adherence and prevents invalid value generation.
- **Mechanism:** Providing the complete set of allowed values within the prompt constrains the LLM's decoding to a closed vocabulary, reducing hallucination of non-permitted answers.
- **Core assumption:** The LLM will respect the instruction to choose only from the listed values.
- **Evidence anchors:** Section 3 describes including the list of allowed values. Section 4 notes the model consistently adhered to the schema. No direct external corpus anchor.
- **Break condition:** Analysis of outputs reveals values not present in the item's allowed set.

### Mechanism 3
- **Claim:** Out-of-the-box LLMs exhibit a strong "cautious" bias toward predicting the "unknown" value, driven by extreme sparsity and class imbalance.
- **Mechanism:** The model's inherent uncertainty estimation and safety training, combined with the statistical prevalence of "unknown" (96.38%), default it to the majority/"safe" answer when evidence is ambiguous or absent.
- **Core assumption:** The generation probability distribution is skewed toward the most frequent pattern (predicting "unknown") due to data distribution and safety objectives.
- **Evidence anchors:** Abstract mentions bias favoring "unknown." Section 4 shows 90.42% vs 1.57% accuracy split, linking it to clinical documentation patterns. Neighboring work discusses sparsity in clinical IE but does not directly anchor this bias mechanism.
- **Break condition:** Bias-correction techniques (e.g., few-shot non-"unknown" examples, recalibration) fail to improve recall on non-"unknown" values.

## Foundational Learning
- **Concept: Zero-Shot Learning for Structured IE**  
  *Why needed here:* The task requires mapping free-text notes to a fixed schema without in-domain training examples. Understanding how LLMs use in-context specifications (definitions, value lists) is critical.  
  *Quick check:* How would you design a prompt to maximize the chance an LLM outputs a value from a closed set without showing examples?
- **Concept: Handling Extreme Class Imbalance**  
  *Why needed here:* The "unknown" class dominates (~96%). Standard accuracy is misleading; macro-F1 is essential to measure informative value extraction.  
  *Quick check:* Why does a model that predicts "unknown" for every field achieve >96% micro-F1 but near-zero utility?
- **Concept: Cross-Lingual Prompting for Domain-Specific Tasks**  
  *Why needed here:* Source text (Italian) and target schema (English) are in different languages. The engineer must reason about the LLM's multilingual competence and prompt translation clarity.  
  *Quick check:* What risks arise when CRF item names and allowed values are in English but the source clinical note is in Italian?

## Architecture Onboarding
- **Component map:** Data Loader -> Prompt Generator -> LLM Inference Client -> Output Parser -> Evaluator
- **Critical path:** Note ingestion -> Loop over 134 CRF items -> Prompt generation -> LLM call (134x per note) -> Parse & validate -> Store prediction -> Aggregate all (note,item) predictions -> Compute metrics.
- **Design tradeoffs:**  
  *Zero-shot vs. Fine-tuning:* Zero-shot is fast but biased; fine-tuning on 290 notes risks overfitting.  
  *Per-item vs. Batch prompting:* Independent calls avoid cascading errors but are inefficient (134 calls/note).  
  *Constraint decoding:* Relying on prompt-listed values is simple but not foolproof; formal constrained decoding is more robust but complex.
- **Failure signatures:**  
  **High "unknown" rate:** >95% of non-"unknown" gold items predicted as "unknown".  
  **Schema violation:** Predicted value not in the item's allowed list.  
  **Language mismatch:** Output in Italian instead of required English value string.  
  **Non-determinism:** Inconsistent outputs with temperature >0.
- **First 3 experiments:**  
  1. **Baseline sanity check:** Implement "always predict most frequent value" ("unknown") to confirm expected micro-F1 ~0.963 and macro-F1 ~0.353.  
  2. **Single-item smoke test:** For a simple item (e.g., Gender), manually inspect prompts and outputs for 5 notes to verify extraction from Italian text.  
  3. **Bias quantification:** Replicate Table 2 by computing precision, recall, and F1 separately for "unknown" and combined "other" classes to confirm the 90%+ vs ~1.5% split.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can the strong bias of LLMs toward predicting "unknown" for CRF items be systematically corrected to improve performance on informative minority classes?
- **Basis in paper:** Results section explicitly identifies a "cautious behaviour favours 'unknown' answers" as a key limitation, showing 90.42% accuracy on "unknown" but only 1.57% on other values. Conclusion reiterates that "out-of-the-box tools are not sufficient" and bias correction is needed.
- **Why unresolved:** The paper demonstrates the bias but does not investigate or propose mitigation strategies.
- **What evidence would resolve it:** Ablation studies comparing techniques like cost-sensitive learning, modifying decoding to penalize "unknown", or few-shot fine-tuning with balanced samples, measuring impact on macro-F1 while ensuring schema adherence.

### Open Question 2
- **Question:** What methods are most effective for reliably extracting values for CRF items that are sparsely annotated or completely absent in the training data (the "quarter of items never appeared")?
- **Basis in paper:** Dataset analysis reveals "roughly three-quarters of the items are represented," meaning ~25% have zero annotations. Combined with poor non-"unknown" performance (1.57%), this suggests a challenge for learning on rare classes.
- **Why unresolved:** Zero-shot approach provides no learning signal for unrepresented or rare items. Paper does not explore few-shot examples or data augmentation from similar ontologies.
- **What evidence would resolve it:** Controlled experiments introducing synthetic or transfer-learned examples for zero-shot items, evaluating if targeted data (e.g., from external sources like the European Clinical Case Corpus) improves recall for these items.

### Open Question 3
- **Question:** Can the observed strong correlations between clinical note categories (e.g., anamnesis, discharge summaries) and specific CRF item groups (e.g., History taking, Final diagnosis) be exploited to improve CRF-filling accuracy?
- **Basis in paper:** Data Analysis states there are "correlations between item groups and note categories, which are easily explained by the note’s function." For instance, anamnesis notes align with history items. However, the experimental setup processes each note independently for all items, ignoring this signal.
- **Why unresolved:** The pilot model treats all items uniformly per note, missing an opportunity to weight or prioritize item groups based on note metadata.
- **What evidence would resolve it:** An ablation study where the model is either provided with the note category as context or where item inference is conditioned on the predicted note type, comparing macro-F1 against the uniform baseline.

### Open Question 4
- **Question:** What prompting or fine-tuning strategies are necessary for LLMs to achieve clinically acceptable performance on the minority, high-value CRF items (e.g., specific diagnoses, treatments) that are currently predicted correctly only 1.57% of the time?
- **Basis in paper:** Conclusion states pilot results show feasibility but "out-of-the-box tools are not sufficient" and there is a need to "engineer dedicated LLM-based solutions that can meet clinical quality requirements." The poor non-"unknown" recall directly motivates this.
- **Why unresolved:** Only a zero-shot prompt with a generic instruction was tested. Paper does not explore chain-of-thought, domain-specific fine-tuning on Italian clinical text, or incorporating external medical knowledge bases.
- **What evidence would resolve it:** Systematic comparison of advanced prompting (e.g., step-by-step reasoning) and parameter-efficient fine-tuning (e.g., LoRA) on a held-out portion, with success defined by clinically meaningful thresholds (e.g., >80% recall on critical items).

### Open Question 5
- **Question:** How can the dataset be expanded and enriched to support longitudinal CRF-filling, where multiple notes from the same patient episode are linked, without compromising patient privacy?
- **Basis in paper:** Dataset section explains current anonymization "limits longitudinal reconstruction at the patient level" because "notes referring to the same patient among different categories cannot be mapped together." It explicitly states that "Future dataset releases are planned to refine anonymisation procedures so that cross-note linkage can be supported."
- **Why unresolved:** The current release is a static snapshot of single notes, preventing research on how information accumulates across a patient's journey. The methodological challenge of privacy-preserving linkage is acknowledged but not addressed.
- **What evidence would resolve it:** Development and validation of a privacy-preserving pseudonymization protocol (e.g., using differential privacy or trusted third-party linkage) that allows release of patient-level note clusters, followed by pilot CRF-filling experiments that fuse information across linked notes.

## Limitations
- Exact prompt wording (structure described but not verbatim) may affect performance and is unclear.
- Allowed value lists per CRF item are not explicitly provided; must be extracted from the dataset schema, risking inconsistencies.
- Language of prompt instructions (English vs. Italian) is unspecified, critical for cross-lingual mapping.
- Dataset access via Hugging Face may require authentication or handle version changes; format must be verified.

## Confidence
- **Zero-shot feasibility claim:** **Medium** (supported by paper's own evidence; weak external support).
- **Prompt-enforced schema adherence claim:** **Low** (inferred; prompt uncertainty weakens direct evidence).
- **Strong "unknown" bias claim:** **High** (strongly supported by results and domain knowledge).
