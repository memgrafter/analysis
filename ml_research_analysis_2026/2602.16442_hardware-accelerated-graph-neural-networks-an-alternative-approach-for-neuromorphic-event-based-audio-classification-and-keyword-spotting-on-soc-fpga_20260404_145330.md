# Hardware-accelerated graph neural networks: an alternative approach for neuromorphic event-based audio classification and keyword spotting on SoC FPGA

## Quick Facts
- **arXiv ID:** 2602.16442
- **Source URL:** https://arxiv.org/abs/2602.16442
- **Reference count:** 40
- **Primary result:** Achieves 92.3% accuracy on the SHD dataset (19.3% higher than prior FPGA SNNs) with far fewer parameters, and demonstrates the first end-to-end FPGA implementation for keyword spotting, reaching 95% word-end detection accuracy with 10.53 µs latency and 1.18 W average power.

## Executive Summary
This paper presents a hardware accelerator on a SoC FPGA for efficient, low-latency processing of neuromorphic event-based audio streams. The core innovation lies in converting audio from an artificial cochlea into sparse spectro-temporal event-graphs, which are processed by a graph neural network (GNN) with a novel skip-step neighbor search to bound computation. The system achieves state-of-the-art classification accuracy on the Spiking Heidelberg Digits (SHD) dataset and pioneers an end-to-end FPGA implementation for keyword spotting (KWS), demonstrating sub-11 µs latency and low power consumption. The design leverages quantization-aware training and a hardware-optimized pipeline to enable real-time edge deployment.

## Method Summary
The method transforms asynchronous audio events into graphs where vertices are events (channel, timestamp) and edges connect events within defined channel/time radii. A hardware-optimized graph convolutional network (based on PointNetConv) processes these graphs. Key techniques include: (1) a skip-step neighbor search that linearly reduces neighbor evaluations; (2) quantization-aware training (8-bit) for integer-only arithmetic in programmable logic (PL); and (3) for KWS, a recurrent head (GRU) that updates every 10 ms window. The system is implemented on a Xilinx Zynq UltraScale+ ZCU104, with the graph generator and convolutions in PL and optional head placement in either PL or the processing system (PS).

## Key Results
- **Classification (SHD):** 92.3% top-1 accuracy, using 39× fewer parameters than prior FPGA SNNs.
- **Keyword Spotting:** 95% word-end detection accuracy; 10.53 µs end-to-end latency; 1.18 W average power.
- **Efficiency:** Skip-step neighbor search reduces FLOPs per event by a factor of ten with minimal accuracy loss (~0.44%).

## Why This Works (Mechanism)

### Mechanism 1: Sparse Event-Graphs Reduce Memory and Computation
**Claim:** Converting audio streams to sparse event-graphs via an artificial cochlea reduces memory and computational costs while preserving temporal precision.
**Mechanism:** The artificial cochlea acts as a band-pass filter bank, generating asynchronous events only when signal intensity crosses a threshold in a frequency channel. This creates a sparse spectro-temporal graph where vertices are events (channel, timestamp) and edges connect events within defined channel/time radii. Sparse data and deterministic neighbor access patterns (via fixed skip-step) bound computation per event, unlike SNNs with nondeterministic memory access.
**Core assumption:** Sparsity and deterministic neighbor search translate directly to lower dynamic power and bounded latency on reconfigurable hardware.
**Evidence anchors:**
  - Abstract: "Audio signals from an artificial cochlea are converted into sparse event-graphs, which are processed by a hardware-optimized graph convolutional network... achieving... far fewer parameters."
  - Section 3.1.1: "Events are stored in 1D context memory... Only the most recent event per channel is stored... The number of neighbours... is limited to 1, significantly reducing required memory."
  - Corpus: Neighbor papers focus on SNNs or event-vision; this work's distinct graph-based approach for audio is not directly mirrored, suggesting a novel mechanism.
**Break condition:** If event rate becomes extremely high (approaching dense sampling), sparsity benefits diminish and memory/throughput bottlenecks emerge.

### Mechanism 2: Skip-Step Neighbor Search Linearly Reduces FLOPs
**Claim:** The skip-step neighbor search linearly reduces FLOPs per event while maintaining sufficient graph connectivity for accurate classification.
**Mechanism:** Instead of scanning all channels within radius `r_ch`, the hardware reads channels at fixed intervals (`skip_step`). For `r_ch=100` and `skip_step=10`, only 21 edges are formed per new event (vs. ~200 with no skip). This reduces per-event FLOPs from ~3.5M to ~0.37M with minimal accuracy drop (~0.44% between skip=1 and skip=10).
**Core assumption:** A sparse, regularly sampled neighbor set preserves spectro-temporal relationships critical for audio patterns.
**Evidence anchors:**
  - Section 3.1.1: Derives cycle count formula `(1+2·r_ch/s)/2 + N_div` for `r_ch=100`, `skip_step=10`.
  - Section 4.2.1: "Using connections with a skip_step of 10 reduces FLOPs by a factor of ten... confirming a linear relationship."
  - Corpus: No direct comparison in neighbors; this parameterized skip approach is a unique contribution for hardware-efficient GNNs.
**Break condition:** If `skip_step` is too large (e.g., 20 in Table 2 leading to 89.66% float accuracy vs 92.74% for skip=10), connectivity loss degrades model capacity beyond recovery by other parameters.

### Mechanism 3: Integrated Feature Extractor + Recurrent Head Enables Real-Time KWS
**Claim:** An integrated graph convolutional feature extractor + GRU-based recurrent head enables real-time, end-to-end keyword spotting on continuous event streams with low latency (<11 µs) and high word-end detection (>95%).
**Mechanism:** The system processes events in small fixed windows (Δt=10ms). Within each window, event-graph features are max-pooled to a single vector, then fed to a STEM (2-layer MLP) and GRU. The GRU updates a hidden state every Δt, producing class scores and a confidence signal. The state machine-controlled head reuses vector multipliers to minimize resources, and its infrequent activation (every 10ms) limits power draw.
**Core assumption:** Windowed pooling with a recurrent head can capture keyword temporal extent without requiring sample-level context accumulation.
**Evidence anchors:**
  - Abstract: "The system achieves... 95% word-end detection accuracy with only 10.53 µs latency and 1.18 W average power consumption."
  - Section 3.3.2: "The GRU updates are... once per Δt window, enabling strictly online operation... At each time step... two outputs are produced: (i) class probabilities... (ii) a scalar confidence score."
  - Section 4.4: Table 8 shows total latency 10.53 µs for end-to-end KWS, with GRU head latency only 2.05 µs.
**Break condition:** Keywords with long internal silences or requiring context longer than the GRU's effective memory (or Δt window) may not be properly detected; the 10ms window is a hard constraint.

## Foundational Learning

- **Concept: Event-based vs. frame-based signal representation**
  - **Why needed:** The pipeline assumes asynchronous, address-event representation (AER) from the cochlea. Events encode *changes*, not absolute values, which is why graph construction uses timestamps as positional features and processing is inherently sparse.
  - **Quick check:** How does the event rate (kEPS) of the SHD dataset compare to a traditional 16kHz audio sample rate, and what does that imply for required computation per second?

- **Concept: Graph Neural Network message passing on point clouds (PointNetConv)**
  - **Why needed:** The feature extractor uses a PointNet-style convolution where each event aggregates features from its neighbors via max-pooling. This is the core computation mapped to hardware; understanding the `max_j φ([X_j || (P_j - P_i)])` operation explains the need for neighbor feature memory (BRAM) and sequential edge processing.
  - **Quick check:** In Equation (1), what is the role of the max-pooling across neighbors, and why does it make the layer permutation-invariant with respect to neighbor order?

- **Concept: Quantization-aware training (QAT) for integer-only hardware**
  - **Why needed:** All multipliers in PL use integer arithmetic. The paper uses QAT (Section 4.1) to maintain accuracy after 8-bit quantization, which is essential for the resource/power gains; without it, floating-point units would dominate DSP/LUT usage.
  - **Quick check:** Why are batch norm layers "folded" during quantization (Section 3.1.2), and how does that avoid adding parameters in the deployed model?

## Architecture Onboarding

- **Component map:**  
  Graph Generator -> Graph Convolution x4 -> Pooling -> [Classification Head | KWS Head]  
  (Graph Generator: reads events, maintains per-channel context, performs skip-step neighbor search; Convolutions: sequential feature transforms with neighbor aggregation; Pooling: global average for classification, per-window max for KWS; Heads: MLP for classification, STEM+GRU for KWS)

- **Critical path:** Event → Graph Generator → Conv1 → Conv2 → Conv3 → Conv4 → Pooling → Task Head. Graph generator latency ~8 µs at 200 MHz; convolution per event depends on neighbor count (max_edges); KWS head activates every 10 ms.

- **Design tradeoffs:**
  1. **`r_ch` vs. `skip_step`:** Larger `r_ch` increases connectivity/accuracy but linearly increases read cycles. Smaller `skip_step` reduces reads but increases edges (and FLOPs quadratically in later layers).
  2. **Parallel multiplier units:** More units reduce per-event latency but increase DSP/LUT usage. Configurable based on resource budget.
  3. **Head placement:** PS head saves PL resources but adds PS-PL communication latency (~171 µs in Table 6) and higher system power. PL head minimizes latency (8.45 µs total) but uses more PL resources.
  4. **Pooling operator:** Average pooling best for long samples (classification), max pooling better for short Δt (KWS) due to hardware simplicity and noise robustness.

- **Failure signatures:**
  - **High per-event latency:** Check `r_ch` and `skip_step` causing many edges; verify MAX_EDGE matches actual neighbor count; check BRAM port contention.
  - **Low accuracy vs. software model:** Check positional normalization (PN) scaling; if missing, quantized training may diverge. Verify QAT was performed.
  - **Incorrect KWS timing:** Validate Δt window and hysteresis thresholds against dataset activity histograms. If confidence peak is consistently early/late, GRU may need more hidden units or different training loss weighting.
  - **Resource overutilization:** Reduce vector multiplier duplication factor; lower output channel sizes; move head to PS.

- **First 3 experiments:**
  1. **Ablation: Skip-step sweep.** Implement graph generator with `r_ch=100` and test `skip_step` ∈ {5,10,15,20}. Measure per-event cycle count and SHD accuracy. Expect ~linear FLOP reduction, accuracy peak at skip=10.
  2. **Head placement benchmark.** Implement base model (64 channels) two ways: (a) PL feature extractor + PS MLP head, (b) fully PL. Measure total latency and system power. Expect ~20× latency reduction with PL head at cost of ~12% more LUTs.
  3. **Pooling operator test for KWS.** Replace graph max pooling with average pooling in the KWS pipeline (keeping Δt=10ms). Retrain quantized model on SSC-11, measure `Acc_K` and `Acc_{K,Δ}`. Expect small (<1%) drop or possible gain depending on noise.

## Open Questions the Paper Calls Out
1. **Live sensor integration:** What are the effects on latency, power, and accuracy when the FPGA-based event-graph GNN processes live events from a real neuromorphic cochlea versus pre-recorded data?
2. **Lower-bit quantization:** Can lower-bit quantisation (4-bit or 2-bit) maintain acceptable accuracy while further reducing FPGA resource usage and power for the event-graph GNN?
3. **Modality portability:** How portable is the proposed hardware architecture to other event-based modalities, such as event cameras, and what modifications are needed?

## Limitations
- Implementation gaps in reproduction details (zero-neighbor feature, precise positional normalization formula, context memory initialization, classification head size, quantization parameters, batch-norm folding).
- Performance degrades if event rate is too high (sparsity lost), `skip_step` >10 (connectivity loss), or KWS keywords require context >10 ms / GRU memory.
- Power consumption is based on Vivado simulation; on-board measurement may differ.

## Confidence
- **Sparse event-graphs reduce memory/computation:** Medium (parameter reduction shown, but no direct power measurement; break condition noted).
- **Skip-step neighbor search reduces FLOPs linearly:** High (ablation data confirms linearity and <0.5% drop at skip=10).
- **End-to-end GNN+GRU KWS achieves low latency/high detection:** Medium (metrics presented, but rely on heuristic label generation and fixed window; potential failure on long silences).
- **8-bit QAT preserves accuracy:** Medium (reported numbers show small drop from FP32, but details of quantization scheme are unspecified).
- **Hardware design meets resource/power targets:** Medium (Vivado estimates provided, but no on-board power measurement).
