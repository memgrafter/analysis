# Split-on-Share: Mixture of Sparse Experts for Task-Agnostic Continual Learning

## Quick Facts
- **arXiv ID:** 2601.17616
- **Source URL:** https://arxiv.org/abs/2601.17616
- **Reference count:** 40
- **Primary result:** SETA achieves state-of-the-art accuracy on domain-specific continual learning benchmarks (e.g., FOMC 59.0, C-STANCE 46.8) while maintaining superior retention (R_T 30.47%) and lower forgetting (F_T 19.28%), with only minor degradation on general reasoning (GEN loss -18.42).

## Executive Summary
Continual learning for large language models (LLMs) is challenged by catastrophic forgetting, where learning new tasks degrades performance on previously learned ones. This paper introduces SETA (Split-on-Share), a method that decomposes a pre-trained LLM’s parameters into sparse, modular experts: unique experts (frozen after training) capture task-specific patterns, while shared experts (stabilized via elastic anchoring) handle reusable features. A dynamic gating network selects the appropriate experts at inference without requiring task IDs. Evaluated on LLaMA-2 7B across domain-specific benchmarks, SETA achieves state-of-the-art average accuracy (e.g., FOMC 59.0, C-STANCE 46.8) and superior retention (R_T 30.47% vs 27.32%) with lower forgetting (F_T 19.28 vs 27.52) compared to prior methods. Moreover, SETA better preserves general reasoning abilities, as evidenced by a lower GEN loss (-18.42), demonstrating an effective plasticity-stability trade-off.

## Method Summary
SETA begins with a pre-trained LLM (e.g., LLaMA-2 7B) and applies sparse subspace selection to the Value (V) projection matrices of each Transformer layer. For a given task, a warm-up forward/backward pass on a small batch computes the importance of each l×l block (l=256) via average absolute gradient; the top-k blocks (per layer or globally) form the active subspace P_t. For subsequent tasks, the Split-on-Share (SoS) mechanism compares the current subspace P_t with the cumulative historical indices P_{1:t−1}. Overlapping blocks become plastic Shared Experts (E_s), while non-overlapping historical blocks are frozen as Unique Experts (E_u); new blocks not in the history become new Unique Experts. Only the Shared Experts and the new Unique Experts are trained on the current task using a composite loss (cross-entropy plus elastic anchoring regularization, which penalizes changes to frequently used blocks with a frequency-based weight n_j). Historical Unique Experts remain frozen. A unified gating network—a linear layer W_g—dynamically selects experts during inference without task identifiers. After each task, the gating network is expanded via weight inheritance to maintain logit invariance when experts split, ensuring that the outputs for unchanged pathways remain consistent.

## Key Results
- SOTA on domain-specific benchmarks: FOMC (59.0 vs I-LoRA 53.9) and C-STANCE (46.8 vs 44.4).
- Superior retention and forgetting: R_T 30.47% (vs 27.32%); F_T 19.28 (vs 27.52).
- Better general reasoning preservation: GEN loss -18.42 (lower is better).

## Why This Works (Mechanism)
SETA mitigates catastrophic forgetting by isolating task-specific knowledge in frozen unique experts while allowing shared features to adapt in a regularized manner. The Split-on-Share (SoS) policy dynamically determines which parts of the sparse parameter subspace are shared across tasks (overlap with historical activations) and which are unique, preventing destructive overlap. Elastic Anchoring applies a frequency-based penalty to changes in shared experts, preserving common knowledge. The unified gating network, inherited across tasks, selects the appropriate combination of experts at inference without task IDs, enabling task-agnostic operation. Together, these mechanisms maintain a balance between plasticity (learning new tasks) and stability (retaining old tasks) while keeping expert growth sub-linear.

## Foundational Learning
- **Catastrophic Forgetting**: The tendency of neural networks to lose previously acquired knowledge when learning new information. *Why needed*: It is the core problem SETA aims to solve. *Quick check*: Train a small model on MNIST, then on CIFAR; MNIST accuracy should drop sharply if forgetting occurs.
- **Sparse Expert Models (Mixture of Experts)**: Neural networks that activate only a subset of parameters (experts) per input. *Why needed*: SETA architectures rely on modular, sparse parameterization to isolate task-specific adaptations. *Quick check*: In an MoE layer, verify that only a few experts are selected for each token (e.g., top-2 gating weights non-zero).
- **Elastic Weight Anchoring**: Regularization that penalizes changes to weights proportionally to their historical usage frequency. *Why needed*: It stabilizes shared experts, preventing them from overwriting important common features. *Quick check*: Compute the average weight change for high-frequency vs low-frequency blocks; high-frequency blocks should exhibit smaller updates.
- **Continual Learning**: A paradigm where tasks arrive sequentially without access to previous data. *Why needed*: Defines the evaluation protocol and constraints under which SETA operates. *Quick check*: After sequential training on three datasets, evaluate on all three; performance on earlier tasks should remain high.
- **Gating Network**: A learned module that routes inputs to appropriate experts. *Why needed*: Enables task-agnostic inference by automatically selecting relevant experts based on input. *Quick check*: For a given input, the gating output should assign high probability to experts known to handle that domain.

## Architecture Onboarding
**Component Map:**  
Input tokens -> Transformer layers -> For each layer: Gating Network (W_g) + Sparse Expert Blocks (Unique/Shared) in V-projection -> Expert output weighted sum -> Rest of layer (attention, FFN unchanged) -> Next layer -> LM head.

**Critical Path:**  
A token passes through the model layer by layer. At each layer, the representation is fed to the gating network, which produces scores over the currently active expert blocks (those whose indices belong to the union of shared and new unique sets for that layer). The experts apply their respective l×l transformations to the value projection input; the weighted combination replaces the standard V projection. The result proceeds through the layer’s residual connection and feed-forward sub-layer (which may also contain expert blocks?). After the final layer, the LM head generates logits.

**Design Tradeoffs:**  
- **Expert granularity (block size l):** Smaller blocks increase adaptability but raise routing complexity and potential interference; larger blocks reduce overhead but may co-locate unrelated features.
- **Threshold choices (τ_ect, τ_trt):** These control merging of unique blocks into shared. Too low τ_ect merges distinct task knowledge, harming uniqueness; too high τ_trt leaves tiny fragments unmerged, causing linear expert growth.
- **Elastic Anchoring strength (λ):** Higher λ better protects shared knowledge but can impede adaptation to new tasks; lower λ risks overwriting.
- **Gating network size:** Larger gating can more precisely weight many experts but introduces more parameters and risk of overfitting; smaller gating is efficient but may become a bottleneck.

**Failure Signatures:**  
- Rapid decline in retention (R_T) after a few tasks, indicating excessive shared growth or poor freezing of unique experts.
- Sudden drop in accuracy on tasks whose experts were recently split, pointing to gating weight initialization errors (logit invariance failure).
- Very noisy or static block selection patterns across tasks, suggesting insufficient warm-up or gradient instability.
- Linear increase in total number of unique blocks per task, signifying ineffective merging (τ_trt too high or overlap threshold mis-set).

**First Experiments:**  
1. **Sparse Selection Sanity Check:** After warm-up on a single task, visualize the selected block indices per layer (e.g., heatmap). Confirm that patterns are non-random and differ across tasks.
2. **SoS Partitioning Validation:** After processing two tasks, compute per-layer counts of Shared and Unique blocks. Ensure that the intersection (Shared) is non-zero and that Unique blocks from task 1 remain frozen (no gradient updates) during task 2 training.
3. **Gating Logit Invariance Test:** Record the full gating logits on a fixed batch before adding new experts. After expert split and weight inheritance, recompute logits; they should be identical for the old expert subset, confirming that routing decisions are preserved.

## Open Questions the Paper Calls Out
- **How does SETA scale to larger model sizes and different architectures?**  
  *Basis*: The paper states that extending to larger models and alternative architectures remains an important direction for future work.  
  *Why unresolved*: Computational constraints limited experiments to LLaMA-2 7B; scalability of expert routing and SoS mechanism is unknown.  
  *What evidence would resolve it*: Train SETA on larger models (e.g., LLaMA-2 70B) and diverse architectures; measure performance, memory, and efficiency.

- **How does SETA perform on longer task sequences with greater diversity?**  
  *Basis*: The paper notes that experiments focus on a fixed sequence of domain-level tasks; broader task diversity and longer sequences may reveal additional behaviors.  
  *Why unresolved*: Only 6 tasks tested; unclear if SoS and gating can handle more complex, varied sequences.  
  *What evidence would resolve it*: Conduct experiments with 10+ tasks spanning multiple domains/languages; track retention, forgetting, and shared subspace evolution.

- **Can the shared subspace design be made principled instead of heuristic?**  
  *Basis*: The paper acknowledges that the design of the shared subspace remains heuristic; developing principled strategies to consolidate or shrink shared experts as tasks grow is an important avenue.  
  *Why unresolved*: Current thresholds τ_ect and τ_trt are hand-tuned; no theory for when to merge or split experts.  
  *What evidence would resolve it*: Develop adaptive or learned thresholds; analyze stability-plasticity trade-offs; compare with learned consolidation policies.

- **How can bias propagation through shared experts be mitigated?**  
  *Basis*: The paper suggests future work should explore fairness-aware expert routing, bias auditing, and regularization strategies.  
  *Why unresolved*: Shared experts may amplify biases from early tasks; no fairness mechanism in SETA.  
  *What evidence would resolve it*: Audit bias in shared vs. unique experts; design fairness constraints for routing or anchoring; measure fairness metrics across tasks.

## Limitations
- Key hyperparameters (τ_ect, τ_trt, exact top-k block count, elastic anchoring λ, frequency schedule n_j) are not reported, hindering exact reproduction.
- Evaluation is limited to LLaMA-2 7B on six specific domain benchmarks; generalizability to larger models or more diverse tasks remains unproven.
- No official code release is available, making independent verification difficult.

## Confidence
- **Domain SOTA** (FOMC 59.0, C-STANCE 46.8): *Low* (hyperparameters and implementation details missing).
- **Retention/Forgetting** (R_T 30.47%, F_T 19.28%): *Medium* (metrics are well-defined but thresholds for SoS and sparse selection are unknown).
- **General reasoning preservation** (GEN loss -18.42): *Low* (impact of λ and gating not fully detailed).
- **Plasticity-stability trade-off**: *Medium* (mechanism is sound but empirical results rely on unreported values).
