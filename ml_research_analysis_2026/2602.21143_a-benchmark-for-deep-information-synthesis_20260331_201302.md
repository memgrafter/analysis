# A Benchmark for Deep Information Synthesis
## Quick Facts
- **arXiv ID:** 2602.21143
- **Source URL:** https://arxiv.org/abs/2602.21143
- **Reference Count:** 27
- **Primary Result:** State-of-the-art LLMs and deep research agents perform poorly on DEEPSYNTH; the best agent achieves only 8.97 F1 and 17.5 LLM-judge score, with no model attaining perfect exact match.

## Executive Summary
This paper introduces DEEPSYNTH, a novel benchmark designed to evaluate agents on real-world tasks that require multi-source information synthesis and insight inference. Constructed via a rigorous multi-stage pipeline, DEEPSYNTH comprises 120 challenging tasks spanning 7 domains and 67 countries, each with verifiable structured answers. Evaluation of 11 leading LLMs and 3 agent frameworks reveals severe limitations: current systems struggle with long reasoning chains, exhibit catastrophic failure on under-represented regions (e.g., zero F1 on Africa tasks), and commit frequent navigation and synthesis errors. The results underscore the need for improved tool use, global data coverage, and chain fidelity in deep research agents.

## Method Summary
DEEPSYNTH is built using a four-stage annotation pipeline: (1) **Data Source Identification**—experts curate official, diverse sources; (2) **Hypothesis Generation**—they formulate insights before analysis; (3) **Hypothesis Validation**—manual verification of hypotheses; (4) **Task Formulation**—distillation into concise questions with structured JSON answers. This ensures tasks require genuine multi-source integration, not retrieval. Evaluation uses automated metrics (Exact Match, F1 on key-value pairs) and an LLM-judge, with agents equipped with web search, browsing, document parsing, and code execution tools. Experiments compare end-to-end performance, tool ablations, and regional/difficulty variants.

## Key Results
- Best model (Gemini-Pro-2.5) scores only 6.25 F1; best agent (o3-deep-research) reaches 8.97 F1 and 17.5 LLM-judge score.
- No model achieves perfect exact match on any task.
- Performance degrades sharply with more intermediate steps; providing ground-truth intermediates yields large gains.
- All models fail completely (0.0 F1) on Africa-focused tasks, highlighting geographic bias.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: DEEPSYNTH's multi-stage pipeline constructs tasks that force genuine multi-source synthesis, not mere retrieval or memorization.
- **Mechanism**: Experts select official diverse sources, generate hypotheses before analysis, manually validate them, and design tasks with verifiable JSON answers. This encodes a gap between surface-level question wording and the deep integration required, filtering out shortcut solutions.
- **Core assumption**: Real-world synthesis can be operationalized as source curation → hypothesis → analysis → verifiable task, inherently eliminating heuristic solvability.
- **Evidence anchors**:
  - [abstract]: "...constructed using a multi-stage data collection pipeline that requires annotators to collect official data sources, create hypotheses, perform manual analysis, and design tasks with verifiable answers."
  - [section §2.2]: Details the four-step pipeline and filtering for "usefulness" and "insightfulness".
- **Break condition**: If hypothesis generation/validation becomes mechanical or sources are cherry-picked, shortcuts may contaminate the benchmark.

### Mechanism 2
- **Claim**: Staggering performance drop with more intermediate steps and large gains from ground-truth intermediates identify "reasoning chain fidelity" as a primary bottleneck, not raw reasoning capability.
- **Mechanism**: Tasks require decomposing into sequences (fetch, compute, compare). Failures propagate through the chain. Providing correct intermediates isolates the final synthesis step, showing models still struggle to combine inputs into structured output, indicating deficits in state maintenance, precise arithmetic, and schema adherence.
- **Core assumption**: End-to-end failure is primarily due to error propagation from early steps, not the final reasoning step itself.
- **Evidence anchors**:
  - [section §5 RQ1]: "all models struggle as the number of intermediate steps increases."
  - [section §5 RQ2 & Table 3]: Large F1/EM improvements when intermediates provided (e.g., Smolagent GPT-4.1: 3.75 → 10.50 F1).
  - [section §4.1 / Table 2]: Low precision indicates frequent extraneous/incorrect outputs.
- **Break condition**: If models achieve high performance without ground-truth intermediates on multi-step tasks, the bottleneck shifts to planning/gathering.

### Mechanism 3
- **Claim**: Severe performance disparities across geographic regions (e.g., 0.0 F1 on Africa tasks) are causally linked to imbalanced data coverage in pre-training corpora and tool-augmentation data, not inherent task difficulty.
- **Mechanism**: The benchmark's intentional geographic diversity exposes a "global coverage" bias. Agents relying on web search/browsing inherit biases from indexable web data; regions with sparse official statistics (e.g., many African nations) create access barriers, leading to navigation errors or failure to locate primary sources.
- **Core assumption**: Tool-augmented LLMs amplify geographic/linguistic biases from training data and the web, making synthesis on under-represented regions harder due to source unavailability.
- **Evidence anchors**:
  - [section §5 RQ5 & Table 5]: Explicitly shows 0.0 F1 on Africa for all models.
  - [abstract]: "...difficulty with ... under-represented regions (e.g., zero F1 on Africa tasks)."
  - [section §2.1d]: Cites diversity as a key design criterion.
- **Break condition**: If Africa performance parity is achieved by only augmenting web indexes (without model changes), bottleneck is tool/data coverage; if parity requires model changes, bottleneck includes reasoning over noisier signals.

## Foundational Learning
- **Concept**: Multi-source Information Synthesis  
  **Why needed here**: Agents must integrate fragmented structured (tables) and unstructured (paragraphs) data from multiple web pages into a single, coherent, structured answer, beyond QA or single-document summarization.  
  **Quick check**: Given two sources—a PDF table of country GDP and a paragraph on regional policy—how would you design a task that *requires* combining both to produce a JSON answer?
- **Concept**: Tool-Augmented Chain Fidelity  
  **Why needed here**: DEEPSYNTH tasks average 7.54 intermediate steps. Success requires not just using tools but preserving correctness through the entire chain; a single error propagates.  
  **Quick check**: If an agent correctly retrieves a data table but mis-parses a column header in a code step, what is the likely final outcome, and how might you detect this intermediate failure?
- **Concept**: Verifiable, Structured Output Generation  
  **Why needed here**: Strict metrics (Exact Match, F1 on key-value pairs) demand perfect adherence to a JSON schema, including precise numeric rounding and key names.  
  **Quick check**: The answer must be `{"CountryX": 12.3, "CountryY": 45.6}`. Would `{CountryX: 12, CountryY: 45.6}` pass Exact Match? What about F1? Why might an LLM fail here?

## Architecture Onboarding
- **Component map**: Planner/Decomposer -> Tool Manager -> State Tracker -> Synthesizer/Formatter. Optional: Validator.
- **Critical path**: Input Question → Planner generates step list → For each step: Tool Manager executes → State Tracker updates → After all steps, Synthesizer formats final JSON → Output.
- **Design tradeoffs**:
  - *Strict schema vs. flexible reasoning*: Forcing JSON at intermediates improves debuggability but may stifle free-form reasoning.
  - *Tool diversity vs. complexity*: Many tools increase coverage but failure surfaces (navigation and synthesis errors dominate).
  - *Verifiable answers vs. real-world ambiguity*: Closed-form answers simplify insight generation.
- **Failure signatures**:
  - **Navigation error**: Visits wrong URL, cannot find data, fails to interact with dynamic page elements.
  - **Synthesis error**: Correct data fragments but incorrect comparison, miscalculation, or wrong JSON structure/values.
  - **No answer / Technical issue**: Agent halts or tools crash.
- **First 3 experiments**:
  1. **Baseline replication**: Run exact setup from §3 on DEEPSYNTH-Dev with one model (e.g., GPT-4.1) to establish reference and validate tool pipeline.
  2. **Tool ablation**: Systematically disable one tool kit at a time to quantify each capability’s contribution; expect largest drop from removing web search.
  3. **Regional stress test**: Create a minimal set of Africa-focused tasks; run an agent and manually inspect traces to confirm whether failure is due to source unavailability (navigation) or reasoning on available data (synthesis).

## Open Questions the Paper Calls Out
- **Open Question 1**: Why do all evaluated agents fail completely (0% F1) on Africa-specific tasks, while performing non-zero on other regions?  
  **Basis in paper**: Table 5 shows 0.0 F1 on Africa; pipeline relied on experts from limited nationalities and data sources may underrepresent African official statistics.  
  **Why unresolved**: Paper identifies geographic bias but does not analyze whether failure stems from data scarcity, language/format barriers, or cultural nuance.  
  **What evidence would resolve it**: Controlled experiments varying data source origin, language, and region while holding task structure constant; qualitative error analysis on African tasks to isolate failure modes.
- **Open Question 2**: What is the primary bottleneck in multi-step synthesis—failure in information retrieval/navigation or failure in reasoning/synthesis over retrieved information?  
  **Basis in paper**: Error analysis (Table 4) shows navigation and synthesis errors nearly equally frequent; intermediate step accuracy decays steeply, suggesting cascading failures.  
  **Why unresolved**: Reports both error types but does not quantify their relative contribution or test whether improving one subsystem yields gains.  
  **What evidence would resolve it**: Ablations isolating retrieval quality (provide gold documents) vs. reasoning quality (provide gold intermediate values); step-wise error injection to measure propagation sensitivity.
- **Open Question 3**: Can intermediate reasoning steps be reliably generated and utilized by agents without human annotation, and does this improve sample efficiency?  
  **Basis in paper**: Table 3 shows large F1 gains when ground-truth intermediate steps provided; current benchmark’s steps are manually curated, limiting scalability.  
  **Why unresolved**: Demonstrates benefit of planning but does not explore whether models can generate equivalent plans autonomously or how to train them on such sparse supervision.  
  **What evidence would resolve it**: Experiments where agents generate their own intermediate steps (e.g., via chain-of-thought) and are evaluated on correlation with success; learning curves comparing models trained with/without synthetic intermediate supervision.
- **Open Question 4**: How do different tool configurations (code execution vs. web browsing vs. document parsing) interact to solve synthesis tasks, and which capabilities are most limiting?  
  **Basis in paper**: Tool ablation (Table 3) shows modest drops when removing search, document processing, or code; frameworks vary in tool access but no controlled comparison isolates each tool’s marginal contribution.  
  **Why unresolved**: Small baseline scores make differences hard to interpret; interactions between tools (e.g., code to parse browsed tables) are not disentangled.  
  **What evidence would resolve it**: Systematic factorial ablation of tools across diverse tasks, measuring accuracy and efficiency (steps, time); error analysis linking tool failure modes to task types.
- **Open Question 5**: To what extent do annotator demographics and source selection bias the task distribution, and how does this affect measured model robustness?  
  **Basis in paper**: Annotators are 81.25% PhD holders from 11 countries (mostly Asia/Europe); data sources cover 67 countries but task distribution is skewed (Table 5: 38.3% Europe, 8.3% Africa).  
  **Why unresolved**: Acknowledges diversity goals but does not assess whether task difficulty correlates with annotator background or source reliability.  
  **What evidence would resolve it**: Re-annotation by diversely-sourced annotators to measure inter-annotator agreement and task difficulty shifts; correlation analysis between source metadata (country, language, update frequency) and model performance.

## Limitations
- Dataset access location not provided in paper, preventing download and verification.
- Tool configurations underspecified (exact browser automator, search API, document parser not detailed).
- Main evaluation input format ambiguous (e.g., inclusion of reasoning chains in prompts).
- Original runs require expensive API calls and rate-limit management.

## Confidence
- Pipeline filters shortcuts: Medium (process described but no independent audit of annotation rigor).
- Chain fidelity bottleneck: High (strong empirical support: Table 3 shows large gains when intermediates provided).
- Geographic disparity due to data coverage: Medium (performance gap clear, but causal attribution indirect).

## Next Checks
1. **Audit task construction**: Sample 30 tasks, verify source diversity, and confirm answers are not trivially retrievable via web search.
2. **Tool ablation replication**: Using a fixed agent (e.g., smolagents), systematically disable browse/search/code to recompute contributions to chain fidelity (reproduce Table 3).
3. **Geographic bias isolation**: Match 20 Africa and 20 Europe tasks by step count and domain; test agents with/without access to region-specific official data portals to distinguish source unavailability from reasoning failure.
