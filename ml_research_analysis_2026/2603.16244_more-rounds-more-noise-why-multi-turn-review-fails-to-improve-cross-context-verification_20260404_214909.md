# More Rounds, More Noise: Why Multi-Turn Review Fails to Improve Cross-Context Verification

## Quick Facts
- **arXiv ID:** 2603.16244
- **Source URL:** https://arxiv.org/abs/2603.16244
- **Reference count:** 8
- **Primary result:** Single-pass Cross-Context Review (CCR) achieves significantly higher F1 (0.376) than all tested multi-turn Dynamic CCR (D-CCR) variants.

## Executive Summary
This paper empirically tests whether adding multi-turn Q&A rounds to Cross-Context Review (CCR) improves LLM-based artifact verification. Counter to expectations, extending review beyond a single independent round harms performance. The optimal number of separated review rounds is one; additional rounds increase recall but cause a severe collapse in precision due to "false positive pressure" (fabricating findings when real errors are exhausted) and "Review Target Drift" (critiquing the Q&A conversation instead of the artifact). For greater verification effort, parallel independent reviews (an ensemble) outperform sequential iterative review.

## Method Summary
The study compared single-pass CCR against four multi-turn Dynamic CCR (D-CCR) variants using 30 artifacts (10 code, 10 documents, 10 scripts) with 5 injected errors each (150 total errors). All sessions used Claude Opus 4.6 via separate CLI invocations to ensure strict context isolation. In D-CCR, a first reviewer (B1) generates questions; an independent author agent (A′) answers; a second reviewer (B2) then reviews the artifact plus the Q&A exchange (or only questions, depending on condition). Reviewer findings were matched to ground truth errors using line proximity, Korean suffix stripping, and fuzzy substring matching. Primary metrics were F1, precision, and recall, with statistical significance assessed via paired t-tests on per-artifact scores.

## Key Results
- Single-pass CCR (F1=0.376) significantly outperformed all multi-turn D-CCR variants (best: D-CCR-2b F1=0.303, p<0.001).
- Multi-turn review increased recall by ~0.08 but precision dropped from 0.30 to 0.20 due to a 62% rise in false positives.
- Duplicate findings (re‑discoveries of same true errors) increased from 15% (CCR‑1) to 30% (D‑CCR‑2c), inflating false positive count.
- A 3‑review majority‑vote ensemble of independent CCR‑1 passes achieved F1=0.393, surpassing all sequential multi‑turn conditions.

## Why This Works (Mechanism)
### Mechanism 1: False Positive Pressure
- **Claim:** In later review rounds, the LLM fabricates errors when the artifact’s real errors are exhausted, disproportionately increasing false positives and collapsing precision.
- **Mechanism:** After round one discovers most objective errors, the instruction to “find new errors” creates a pressure to produce findings. With few remaining true errors, the model generates speculative, low‑confidence, or incorrect findings to satisfy the request.
- **Core assumption:** The artifact contains a finite set of discoverable errors; once these are identified, further rounds yield diminishing true positives and rising noise.
- **Evidence anchors:** Abstract statement; Section 6.1 quantifies Round 2 false positive increase (3–4.5 new FPs per artifact); example case C3 where 6 of 7 Round 2 findings were false.
- **Break condition:** If the artifact has an inexhaustible number of valid review points (e.g., style nitpicks) or if the model refuses to speculate when uncertain, pressure may not produce false positives.

### Mechanism 2: Review Target Drift
- **Claim:** When the reviewer receives the prior Q&A exchange, it shifts attention from the artifact to the conversation, generating findings about the author’s answers rather than the artifact itself.
- **Mechanism:** The dialogue content becomes a salient secondary target; the reviewer critiques answer correctness, consistency, or clarity instead of focusing solely on the original artifact.
- **Core assumption:** The reviewer’s attention is malleable and can be captured by conversational context, even against explicit instructions.
- **Evidence anchors:** Abstract statement; Section 4.2 pilot v1 prompt caused egregious drift; v2 prompt reduced but did not eliminate it.
- **Break condition:** If the reviewer is given a strict, unbreakable constraint (e.g., output must reference only artifact elements) and the model adheres perfectly, drift may be minimized.

### Mechanism 3: Duplicate Finding Inflation
- **Claim:** A second review round often re‑discovers errors already flagged in round one; these duplicates are penalized in the precision metric, lowering F1 despite constant or slightly increased true positives.
- **Mechanism:** The same error remains present and can be detected again; evaluation treats subsequent matches as “Dup” (non‑TP) rather than TP, inflating the denominator of precision without increasing numerator.
- **Core assumption:** Error detection is stochastic; a fresh review pass can rediscover known errors, and the metric discourages redundancy.
- **Evidence anchors:** Section 5.1 defines Findings = TP + FP + Dup; Table 1 shows Dup rising from 1.43 (CCR‑1) to 3.70 (D‑CCR‑2b) to 5.60 (D‑CCR‑2c); Section 5.7 notes duplicate rates increase from 15% to 30%.
- **Break condition:** If the second round is forced to only output findings not previously reported (e.g., via a suppression list), duplicates could be avoided, but the model may lack perfect memory.

## Foundational Learning
- **Concept: Cross‑Context Review (CCR)**
  - *Why needed here:* The paper extends CCR, which separates production and review sessions to avoid anchoring. Understanding CCR explains why single‑pass with separation works and sets the baseline for testing multi‑turn variants.
  - *Quick check question:* What problem does context separation solve in LLM review?
- **Concept: Precision‑Recall Tradeoff**
  - *Why needed here:* The core result is a recall gain at a severe precision cost. Grasping these metrics clarifies why more findings do not equal better performance.
  - *Quick check question:* How does an increase in duplicate findings affect precision and recall?
- **Concept: False Positive Pressure**
  - *Why needed here:* This mechanism is the primary driver of multi‑turn failure; recognizing it helps diagnose spurious outputs in iterative LLM verification.
  - *Quick check question:* Why might a reviewer be tempted to fabricate findings in a second round?

## Architecture Onboarding
- **Component map:**
  A -> Artifact -> B1 (Round 1 review + questions) -> Q&A -> A′ (author answers) -> B2 (Round 2 review)
- **Critical path:**
  1. Producer Agent (A) generates artifact.
  2. Reviewer Agent (B1) performs first review and raises questions.
  3. Author Agent (A′) answers questions using only artifact and questions.
  4. Reviewer Agent (B2) performs second review on artifact plus Q&A exchange (variant‑dependent).
  5. Findings from B1 and B2 are pooled (or B2 only for D‑CCR‑2c) and matched to ground truth.
- **Design tradeoffs:**
  - *Separation vs. interaction:* Strict context separation avoids anchoring but loses clarifying dialogue.
  - *Round count:* One round optimal; additional rounds increase noise via false positive pressure.
  - *Continuity:* Including Q&A (2b) slightly outperforms questions‑only (2a) but both underperform single‑pass.
  - *Compute allocation:* Ensemble of independent CCR‑1 reviews beats sequential iterative review.
- **Failure signatures:**
  - Surge in false positives in Round 2, especially speculative or conversation‑related claims.
  - High duplicate rate (≥30%) across rounds.
  - Findings that reference “author’s answer” or critique the dialogue.
  - Precision dropping below 0.20 while recall climbs above 0.60.
- **First 3 experiments:**
  1. **Baseline replication:** Execute CCR‑1 on a subset of artifacts; confirm F1 ~0.376 and precision ~0.30.
  2. **Multi‑turn comparison:** Run D‑CCR‑2b; expect F1 ~0.303, recall +0.08, precision ~0.20, and increased FP/dup.
  3. **Independence check:** Run D‑CCR‑2c; expect worst F1 (~0.263), highest dup rate, confirming that mere repetition degrades performance.

## Open Questions the Paper Calls Out
- **Open Question 1:** What underlying factor(s) drive false positive pressure in multi‑turn LLM review, and can modifying round‑two instructions to explicitly permit "no new errors" reduce FP generation while maintaining recall gains?
- **Open Question 2:** Can architectural interventions—such as forcing the reviewer to reference only the artifact (not Q&A) or using separate agents for artifact analysis and Q&A critique—eliminate Review Target Drift without losing the recall benefit from multi‑turn interaction?
- **Open Question 3:** Do the observed multi‑turn degradation effects (high FP pressure, Review Target Drift) generalize beyond Claude Opus 4.6 and injected errors to other LLM families and naturally occurring errors?
- **Open Question 4:** What is the optimal aggregation method for independent parallel reviews (ensemble), and how does its performance compare to the theoretical upper bound represented by expert human reviewers?

## Limitations
- **Artifact & prompt opacity:** Exact 30 artifacts and full Korean prompts are not public, forcing reproduction via approximation.
- **Mechanism evidence:** Support for false positive pressure and review target drift relies primarily on internal analysis with weak external corpus parallels.
- **Generalization:** Results are specific to Claude Opus 4.6 and synthetic, low‑error‑density artifacts; performance on real‑world, error‑rich artifacts is unknown.

## Confidence
- **Experimental Outcome (CCR‑1 > all D‑CCR variants):** High
- **Mechanism 1 (False Positive Pressure):** Medium
- **Mechanism 2 (Review Target Drift):** Medium
- **Ensemble Superiority Claim:** Low

## Next Checks
