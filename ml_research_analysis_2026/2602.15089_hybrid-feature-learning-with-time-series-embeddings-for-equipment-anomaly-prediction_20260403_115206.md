# Hybrid Feature Learning with Time Series Embeddings for Equipment Anomaly Prediction

## Quick Facts
- arXiv ID: 2602.15089
- Source URL: https://arxiv.org/abs/2602.15089
- Reference count: 34
- Primary result: Hybrid model achieves 91–95% precision and 0.995 ROC-AUC on HVAC anomaly prediction across 30/60/90-day horizons, with false positive rate ≤1.1%.

## Executive Summary
Pure deep learning models for HVAC anomaly prediction fail on real-world data, with Granite TinyTimeMixer achieving only 9–11% precision due to probability concentration near 0.5. This study proposes a hybrid framework that combines 64-dimensional time series embeddings from a fine-tuned foundation model with 28 domain-informed statistical features (e.g., volatility, trend, drawdown) using a LightGBM classifier. Evaluated on 64 equipment units and 51,564 samples, the hybrid model achieves 91–95% precision and 0.995 ROC-AUC across 30-day, 60-day, and 90-day horizons, with a false positive rate ≤1.1% and a detection rate of 88–94%, demonstrating production-ready performance for predictive maintenance.

## Method Summary
The approach processes 90-day sliding windows from multivariate daily sensor data (≈3.6 sensors per equipment). For each window, 28 statistical features—covering basic statistics, trend (e.g., slope), and volatility (e.g., rolling standard deviation, drawdown)—are computed per sensor and averaged to form a 28-dimensional vector. In parallel, the Granite TinyTimeMixer encoder is fine-tuned using LoRA (rank=16) with focal loss (γ=2.0) on the anomaly classification task; the mean-pooled encoder output yields a 64-dimensional time series embedding. The two representations are concatenated (92 dimensions) and fed into a LightGBM gradient boosting classifier. Separate models are trained for each prediction horizon (30, 60, 90 days). Training uses a temporal split (January 2023–September 2024 for training, October–December 2024 for testing) and handles class imbalance (≈9-10% anomaly rate) via `scale_pos_weight`. Inference has low latency (~4.5 ms per sample).

## Key Results
- Precision: 91–95% across all prediction horizons (30, 60, 90 days).
- ROC-AUC: 0.995, indicating excellent discriminative ability.
- False positive rate ≤1.1% with detection rate 88–94%, achieving production-ready reliability.

## Why This Works (Mechanism)
### Mechanism 1: Statistical features capture domain-specific precursors
- **Claim:** Explicit statistical features capture domain-specific anomaly precursors (volatility, trend) that are poorly represented in generic time series embeddings.
- **Mechanism:** The 28 engineered features directly quantify operational instability (e.g., rolling standard deviation, drawdown) and directional shifts (trend slope) known to precede HVAC failures. These provide calibrated, interpretable signals that a classifier can threshold reliably.
- **Core assumption:** Domain knowledge about failure modes (e.g., “increased volatility indicates degradation”) can be systematically encoded into statistical measures that complement learned patterns.
- **Evidence anchors:** 
  - [abstract] “...combines 64-dimensional time series embeddings... with 28-dimensional statistical features based on domain knowledge... including trend, volatility, and drawdown indicators.”
  - [section 6.4] “Volatility Features (11 features): 29.3% total importance” and “Among statistical features, volatility-related measures... account for 57% of the statistical feature importance.”
  - [corpus] Weak support; neighboring papers also explore hybrid/statistical features but lack direct comparison to this specific feature set.
- **Break condition:** If domain-informed features do not correlate with failure modes (e.g., volatility measures show no divergence pre-failure), the hybrid model’s performance would collapse to the baseline.

### Mechanism 2: Foundation model embeddings capture complex temporal dependencies
- **Claim:** Foundation model embeddings capture complex, long-range temporal dependencies and cross-sensor interactions that are difficult to express as manual features.
- **Mechanism:** Granite TinyTimeMixer, pretrained on diverse time series, learns a compressed representation (64-dim) of the 90-day window that implicitly encodes patterns like seasonal cycles, multi-sensor phase relationships, and subtle degradation trajectories not captured by univariate statistics.
- **Core assumption:** The pretraining objective (forecasting) induces representations that are transferable to anomaly classification, even after LoRA fine-tuning.
- **Evidence anchors:**
  - [abstract] “...integrates 64-dimensional time series embeddings from Granite TinyTimeMixer... Time series embeddings... contribute 48.5% total importance.”
  - [section 4.2] “Rather than using the decoder’s forecast output, we extract the encoder’s internal representations... yields a fixed-size 64-dimensional embedding.”
  - [section 7.1] “Deep embeddings excel at capturing implicit temporal patterns but struggle with explicit statistical properties.”
- **Break condition:** If the foundation model’s pretraining corpus is fundamentally mismatched to HVAC dynamics (e.g., dominated by financial or IoT data), the embeddings may contain irrelevant patterns, limiting their contribution.

### Mechanism 3: LightGBM fuses heterogeneous features effectively
- **Claim:** LightGBM effectively fuses heterogeneous feature types (dense embeddings vs. sparse statistics) by learning nonlinear interactions and robustly handling their distributional differences.
- **Mechanism:** Gradient boosting decision trees create hierarchical, rule-like splits that can combine an embedding dimension (e.g., dim 42) with a statistical feature (e.g., rolling volatility) in a single decision node. This allows the model to learn conditions like “high embedding value AND elevated volatility” that would be missed by linear fusion.
- **Core assumption:** Tree-based models are superior to neural classifiers for this hybrid tabular format due to inherent handling of feature heterogeneity and robustness to outliers.
- **Evidence anchors:**
  - [abstract] “...learned using a LightGBM gradient boosting classifier.”
  - [section 4.4] “Unlike simple concatenation followed by linear classification, LightGBM discovers complex decision boundaries through hierarchical feature interactions.”
  - [section 6.4] Feature importance is distributed, indicating combinations are used; LightGBM baseline (stats-only) achieves 79-87% precision, showing its strength even without embeddings.
- **Break condition:** If the optimal decision boundary is highly non-monotonic and requires dense, continuous feature interpolation beyond tree capacity, a neural fusion head might outperform LightGBM.

## Foundational Learning
- **Parameter-Efficient Fine-Tuning (LoRA):** 
  - Why needed: Fine-tuning the full 1M-parameter TinyTimeMixer on 51k samples risks overfitting. LoRA (rank r=16) updates only 29k parameters (22.1%), preventing catastrophic forgetting while adapting to the anomaly detection task.
  - Quick check: If you increase LoRA rank to 64, what is the most likely outcome on this dataset’s test set? (A) Improved precision, (B) Degraded precision due to overfitting, (C) Unchanged performance.
- **Horizon-Specific Classification:** 
  - Why needed: Anomaly precursors likely differ for 30-day vs. 90-day warnings (e.g., gradual volatility buildup vs. sudden trend reversal). Training separate LightGBM models per horizon allows each to specialize.
  - Quick check: Why not train a single multi-output model? What risk does horizon-specific training mitigate? (Consider feature importance shifts: volatility ↑ for 90d, trend ↓).
- **Focal Loss for Imbalanced Learning:** 
  - Why needed: Anomaly rate is ~9-10%. Standard cross-entropy would be dominated by normal samples. Focal loss (γ=2.0) down-weights easy negatives, forcing focus on rare anomalies during fine-tuning.
  - Quick check: If you set γ=0 (standard CE), what happens to the Granite TS baseline’s already poor precision? It likely (A) improves, (B) worsens, (C) stays similar.

## Architecture Onboarding
- **Component map:**  
  1. Input: 90-day multivariate window (L=90, C≈3.6 sensors/equipment).  
  2. Path A (TS Embeddings): Granite TinyTimeMixer encoder (frozen) + LoRA adapters → mean-pooled 64-dim vector.  
  3. Path B (Stats): Per-sensor window → 28 statistical features → normalized 28-dim vector.  
  4. Fusion: Concatenation [h_TS; f_stat] → 92-dim vector.  
  5. Classifier: LightGBM (tree-based) → anomaly probability per horizon (3 separate models).  
  6. Output: Binary label (anomaly within h∈{30,60,90} days).  
- **Critical path:** Raw sensor data → statistical feature computation (must be correct) → embedding extraction (must use fine-tuned encoder) → fusion → LightGBM inference. Errors in feature computation are fatal.  
- **Design tradeoffs:**  
  - Embedding size (64): Larger may capture more patterns but increases LightGBM complexity & risk of overfitting; smaller loses information.  
  - LoRA rank (r=16): Higher rank increases capacity but also trainable params; lower may under-adapt. Chosen as sweet spot.  
  - LightGBM depth (7): Deeper trees model complex interactions but risk overfitting on 92 features; shallower may be insufficient.  
- **Failure signatures:**  
  - Pure DL failure: Prediction probabilities all 0.51-0.53. Indicates model not learning discriminative task.  
  - Statistical-only weakness: Higher FPR (2.6% vs 0.6% hybrid) at similar recall, showing missing temporal patterns.  
  - Feature importance skew: If embeddings >80% or stats >80%, the hybrid synergy is lost; balanced ~50/50 is expected.  
- **First 3 experiments:**  
  1. Replicate baseline failure: Train Granite TS (v1.0) with LoRA on your subset. Confirm probability concentration near 0.5 and ROC-AUC ~0.5.  
  2. Ablation - statistical features: Train LightGBM with embeddings ONLY. Expect precision ~10-15% and ROC-AUC ~0.5-0.6.  
  3. Ablation - embeddings: Train LightGBM with stats ONLY. Expect precision ~80% and ROC-AUC ~0.98.

## Open Questions the Paper Calls Out
- **Question 1:** How can transfer learning and domain adaptation techniques be effectively integrated into the hybrid framework to enable cross-domain generalization to new HVAC subsystems (e.g., chillers, air handlers) with limited labeled data?  
  *Basis:* Section 7.4 identifies “Transfer Learning and Domain Adaptation” as a key direction, noting that embeddings learned from large equipment fleets could accelerate adaptation to new sites with limited historical data.
- **Question 2:** Can multi-task learning objectives (e.g., joint anomaly prediction and time-to-failure estimation, multi-class failure type classification) improve the predictive performance and operational utility of the hybrid model compared to separate single-horizon models?  
  *Basis:* Section 7.4 proposes extending to multi-task learning, such as joint prediction of anomaly probability and time-to-failure.
- **Question 3:** What online learning mechanisms can enable continuous adaptation of the hybrid model to evolving equipment conditions (e.g., seasonal shifts, degradation trends) and maintenance feedback without requiring full periodic retraining?  
  *Basis:* Section 7.4 calls for online learning to handle non-stationary environments and incorporate maintenance feedback.
- **Question 4:** How can advanced explainability methods (e.g., SHAP, counterfactual analysis, causal discovery) be integrated into the hybrid framework to provide deeper, instance-level insights into anomaly causes, moving beyond aggregated feature importance?  
  *Basis:* Section 7.4 highlights explainability and causal analysis as a direction to enhance trust.
- **Question 5:** What architectural and algorithmic modifications are necessary to extend the hybrid system from daily batch processing to real-time sub-hourly anomaly detection for integration with SCADA systems and closed-loop control?  
  *Basis:* Section 7.4 calls for real-time streaming integration to enable sub-hourly detection and SCADA integration.

## Limitations
- **Reproducibility blockers:** Exact Granite TinyTimeMixer model identifier, precise mathematical definitions for all 28 statistical features, and criteria for the “normal operation period” are unspecified, preventing faithful replication.
- **Label engineering sensitivity:** Anomaly labels depend on the chosen normal period and percentile bounds (5th/95th); small changes could alter label balance and model difficulty.
- **Limited generalization scope:** Evaluation is restricted to 64 pump systems from a single HVAC context; cross-system or cross-environment validation is missing, raising concerns about overfitting to specific operational profiles.

## Confidence
- **Hybrid Model Performance Claims (91–95% precision, 0.995 AUC):** High Confidence. Metrics are specific, evaluated on a large test set, and the pure DL baseline failure provides a strong anchor.
- **Mechanism Explanations (statistical features for precursors, embeddings for long-range patterns):** Medium Confidence. Evidence is correlational (feature importance splits); break conditions are logical but not directly tested.
- **Foundational Concepts (LoRA, horizon-specific training, focal loss):** Low Confidence. These are plausible implementation choices but their specific necessity for the reported results is not validated.

## Next Checks
- **Rigorous Ablation Study:** Train and evaluate three models: (a) Stats-only with LightGBM, (b) Embeddings-only with LightGBM, (c) Hybrid. Ensure identical preprocessing, hyperparameter tuning budgets, and validation strategies. This directly tests the claim that both feature types are necessary.
- **Feature Importance Stability:** Repeat LightGBM training with 10 different random seeds and report variance in the split between embedding vs. statistical feature importance. High variance would undermine the reported synergistic balance (~50/50).
- **Out-of-Distribution (OOD) Stress Test:** Apply the trained model to a temporally distant hold-out period (e.g., a full summer season if trained on winter/spring) or to equipment from a different site. Measure degradation in precision and AUC. A production-ready model should show graceful degradation rather than catastrophic failure.
