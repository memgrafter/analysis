# Transforming Omnidirectional RGB-LiDAR data into 3D Gaussian Splatting

## Quick Facts
- **arXiv ID:** 2603.06061
- **Source URL:** https://arxiv.org/abs/2603.06061
- **Reference Count:** 28
- **Primary Result:** A pipeline enabling robust 3D Gaussian Splatting from omnidirectional logs by overcoming ERP distortion (via cubemap SfM) and LiDAR density bottlenecks (via PRISM downsampling), achieving up to 0.36 dB PSNR gains and keyframe reuse of 35.5%–51.3%.

## Executive Summary
This paper presents a system to convert archived omnidirectional (equirectangular, ERP) RGB-LiDAR logs into high-fidelity 3D Gaussian Splatting (3DGS) digital twins. The core challenge is that standard Structure-from-Motion (SfM) fails on distorted ERP imagery, and raw LiDAR clouds are prohibitively dense for 3DGS initialization. The proposed solution introduces an ERP-to-cubemap projection to enable reliable SfM, a color-stratified PRISM downsampling to compress LiDAR while preserving photometric detail, and a robust FPFH+ICP alignment to fuse the two modalities. Evaluated on three real-world sequences, the LiDAR-reinforced pipeline consistently improves rendering quality over vision-only baselines and achieves efficient keyframe reuse, demonstrating a practical method for repurposing existing omnidirectional sensor logs.

## Method Summary
The pipeline processes synchronized ERP images and LiDAR sweeps through several stages. First, keyframes are selected based on ORB feature stability and homography overlap. Each ERP keyframe is converted to six cubemap faces via ray mapping onto a unit cube, producing rectilinear images suitable for standard SfM (COLMAP) to recover camera poses and a sparse point cloud. Concurrently, LiDAR sweeps are aggregated into a unified metric map using ICP-based odometry; each point is colorized by projecting it into ERP images using calibration data. The colored LiDAR cloud is aggressively downsampled via PRISM, which partitions RGB space and samples up to *n* points per bin to retain chromatic diversity. The downsampled LiDAR and SfM clouds are then aligned using FPFH features for global registration followed by ICP refinement, with weights to reject dynamic outliers. The fused point cloud initializes 3DGS (Gaussian means, covariances, spherical harmonics), which is trained for 30k iterations within a single 16GB GPU budget.

## Key Results
- On Dormitory 1, LiDAR-reinforced 3DGS improves over vision-only: PSNR +0.36 dB, SSIM +0.0047, LPIPS -0.0068 at *n*=100.
- Keyframe reuse ratios reach 35.5%–51.3% across sequences, indicating effective data repurposing.
- SfM reconstruction rates are 82.4%–88.9%, confirming robust pose recovery from cubemap projections.

## Why This Works (Mechanism)
### Mechanism 1: ERP-to-Cubemap Projection for Robust SfM
- **Claim:** Converting ERP images to cubemap faces enables reliable feature matching and successful SfM reconstruction, overcoming distortion-induced failures.
- **Mechanism:** ERP pixels are mapped to 3D rays via spherical coordinates; each ray intersects a unit cube to generate six rectilinear images. This yields pinhole-equivalent views where standard SfM pipelines extract and match features without ERP's non-linear pole stretching.
- **Core assumption:** Rectilinear projection eliminates the non-uniform sampling of ERP that degrades feature descriptors.
- **Evidence anchors:** [abstract] mentions "ERP-to-cubemap conversion for robust SfM"; [section III.A] provides the ray mapping equations; related work consensus identifies omnidirectional distortion as a key problem.
- **Break condition:** Insufficient texture or extreme lighting can still cause SfM failure even on rectilinear faces.

### Mechanism 2: PRISM Color-Stratified Downsampling for LiDAR Density Control
- **Claim:** PRISM downsampling reduces computational burden while preserving color diversity essential for high-quality 3DGS rendering.
- **Mechanism:** RGB space is partitioned into bins; up to *k* points are sampled per bin. This ensures visually rich regions (high chromatic variation) are retained even under aggressive decimation, while homogeneous areas are heavily subsampled.
- **Core assumption:** Color diversity is a proxy for photometric complexity; retaining points across the spectrum maintains visual features for Gaussian splat color.
- **Evidence anchors:** [abstract] introduces "PRISM—a color-stratified downsampling strategy"; [section III.C] formalizes the sampling per bin (Eq. 3).
- **Break condition:** In narrow-gamut scenes (e.g., all-gray), color stratification may discard geometrically important points because bins fill with similar colors.

### Mechanism 3: FPFH+ICP for Cross-Modal Alignment
- **Claim:** Two-stage alignment using Fast Point Feature Histograms (FPFH) for global registration and Iterative Closest Point (ICP) refinement yields accurate rigid transformation between scale-ambiguous SfM points and metric LiDAR.
- **Mechanism:** FPFH describes local point geometry for a rough global alignment (RANSAC-based). This seeds ICP, which minimizes point-to-point distances under a weight function to reject outliers and converge precisely.
- **Core assumption:** A rigid transformation exists between the modalities for static scene geometry.
- **Evidence anchors:** [abstract] cites "FPFH based global registration and Iterative Closest Point (ICP)"; [section III.D] details the weighted ICP objective (Eq. 4).
- **Break condition:** Low overlap between SfP and LiDAR points (e.g., from poor keyframes or dynamics) can mislead global registration, causing ICP to converge to a local minimum.

## Architecture Onboarding
- **Component map:** Keyframe Selection -> ERP-to-Cubemap Conversion -> SfM Reconstruction -> LiDAR Aggregation -> LiDAR Colorization -> PRISM Downsampling -> Cross-Modal Alignment -> 3DGS Initialization
- **Critical path:** Keyframe extraction → ERP conversion → SfM → LiDAR aggregation/colorization → PRISM → FPFH+ICP → fused point cloud → 3DGS. Most failure-prone steps: SfM reconstruction and cross-modal alignment.
- **Design tradeoffs:**
  - PRISM parameter *n*: Larger *n* retains more points (better coverage, higher fidelity) but increases memory/time; smaller *n* is efficient but risks under-sampling color diversity.
  - Alignment initialization: Using trajectory metadata helps ICP avoid local minima, but poor metadata (e.g., odometry drift) harms alignment.
  - Deterministic settings: Fixed parameters ensure reproducibility but may not suit all environments (e.g., texture-poor vs. rich scenes).
- **Failure signatures:**
  - SfM reconstruction rate <80% indicates insufficient keyframes or persistent distortion.
  - ICP RMSE > ~0.3 m suggests misalignment; visual point cloud overlay check recommended.
  - 3DGS training: Gaussian count explosion, high LPIPS, or floating artifacts indicate poor initialization.
- **First 3 experiments:**
  1. **PRISM sweep validation:** Run pipeline with *n* ∈ {1,5,10,20,50,100}; record reduction ratios, alignment fitness/RMSE, final 3DGS PSNR/SSIM/LPIPS. Identify optimal trade-off.
  2. **Modality ablation:** Compare vision-only SfM vs. LiDAR-reinforced (PRISM *n*=50) on repetitive geometry scene; measure PSNR/SSIM gaps.
  3. **Visual diagnostics:** After PRISM, visualize point cloud color distribution and spatial coverage; ensure color bins populated and structural edges/thin objects preserved.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can residual spherical-image distortion be mitigated during LiDAR colorization to improve RGB-to-LiDAR matching in difficult regions?
- **Basis in paper:** Limitation 1: "residual spherical-image distortion still limits robust RGB color-to-LiDAR matching during LiDAR colorization in difficult regions."
- **Why unresolved:** Current pipeline projects LiDAR onto ERP without full distortion modeling, causing color mismatches near poles and degrading fused point cloud quality.
- **What evidence would resolve it:** A distortion-aware colorization method (e.g., using spherical camera model with distortion parameters) that improves color assignment accuracy and yields higher PSNR/SSIM in final 3DGS.

### Open Question 2
- **Question:** How does the pipeline generalize to diverse environments, sensor setups, and data conditions beyond the three AIR Lab sequences?
- **Basis in paper:** Limitation 2: "Experiments were conducted on only three outdoor sequences from the same sensor platform, so broader validation across more scenes, devices, and environmental conditions is still required."
- **Why unresolved:** Fixed configuration may not adapt to different scene structures, lighting, weather, or calibrations; robustness and failure modes remain unknown.
- **What evidence would resolve it:** Evaluation on additional datasets (e.g., KITTI-360, nuScenes) with varied conditions, reporting consistent reuse ratios, alignment fitness, and rendering quality.

### Open Question 3
- **Question:** What are the optimal PRISM downsampling parameters and ICP initialization strategies across diverse scenes, and can they be automatically selected?
- **Basis in paper:** Limitation 3: "We did not perform exhaustive parameter search for PRISM and ICP, so the current settings may be suboptimal for some trajectories."
- **Why unresolved:** Optimal density likely depends on scene texture, geometry, and LiDAR distribution; no automated selection exists.
- **What evidence would resolve it:** Large-scale study correlating scene features with optimal *n* and ICP parameters, or an adaptive algorithm that selects parameters based on input characteristics.

### Open Question 4
- **Question:** How can the system be extended to handle dynamic objects and operate in real-time for online digital twin construction?
- **Basis in paper:** Limitation 4: "the evaluation is offline and mostly static-scene oriented, leaving dynamic-object robustness and real-time deployment constraints for future work."
- **Why unresolved:** Pipeline assumes static scenes; dynamic objects cause misalignments. Processing is computationally heavy and not optimized for real-time.
- **What evidence would resolve it:** Dynamic object filtering (e.g., motion segmentation) showing improved robustness in dynamic sequences; optimized incremental SfM/GPU-ICP achieving >30 fps on edge hardware.

## Limitations
- **Unreported hyperparameters:** Exact SfM thresholds, keyframe selection criteria, and ICP convergence/weight settings are unspecified, risking reproducibility.
- **PRISM brittleness:** Color-stratified sampling may discard geometrically critical points in low-chromatic-variation scenes (e.g., all-gray environments).
- **Cross-modal alignment dependency:** FPFH+ICP assumes sufficient SfM-LiDAR overlap; dynamic objects or poor initial guesses can cause misalignment.

## Confidence
- ERP-to-cubemap enables robust SfM: **Medium** (plausible mechanism, but no direct ablation vs. alternatives).
- PRISM preserves photometric complexity: **Medium** (evaluated on 3 sequences; lacks diverse scene validation).
- FPFH+ICP achieves accurate registration: **High** (uses standard techniques; fitness/RMSE metrics reported).
