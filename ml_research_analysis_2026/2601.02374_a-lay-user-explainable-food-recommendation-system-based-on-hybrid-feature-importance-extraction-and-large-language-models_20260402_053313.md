# A Lay User Explainable Food Recommendation System Based on Hybrid Feature Importance Extraction and Large Language Models

## Quick Facts
- **arXiv ID:** 2601.02374
- **Source URL:** https://arxiv.org/abs/2601.02374
- **Reference Count:** 27
- **Primary Result:** Hybrid SHAP‑LLM system with GPT‑4 produced the most preferred explanations (51.7% of plain explanations) and average ratings near 4/5, outperforming FLAN models by ~1 point.

## Executive Summary
This paper tackles poor transparency in food recommendation systems by proposing a hybrid post‑hoc XAI framework. It extracts dual‑perspective (user‑centric and recipe‑centric) feature importance via SHAP applied to surrogate decision trees, then uses prompted large language models (GPT‑4, GPT‑3.5, Flan T5) to convert these structured insights into natural, persuasive explanations. A user study with 19 lay participants shows GPT‑4 achieving the highest satisfaction (~4/5) and being the most preferred model. Results suggest that combining SHAP with LLMs can significantly enhance perceived transparency and user trust in diet‑related recommendations.

## Method Summary
The system builds on a rule‑based food recommender that filters allergens and computes calorie needs. For a given user‑recipe pair, two shallow decision‑tree surrogates are pre‑trained: one predicts recommendation from user attributes (user‑centric), the other predicts preference from recipe attributes (recipe‑centric). SHAP values are computed on these trees to quantify feature contributions. The top features and their values are inserted into a fixed prompt (e.g., “Convince me that ‘recipe name’ is better for me, given …”) and sent to an LLM. The LLM generates a concise, personalized explanation. The framework is evaluated through a within‑subjects survey where participants rate and compare explanations from different LLMs.

## Key Results
- All four LLMs averaged ratings above 2.5/5; GPT models (~4/5) outperformed FLAN T5 models by approximately one point.
- GPT‑4 was the most preferred model, selected for 51.7% of plain explanations.
- Users favored explanations that were personalized, concise, and incorporated relevant statistics and preferences, indicating improved satisfaction and transparency.

## Why This Works (Mechanism)
**Mechanism 1: Dual‑perspective feature importance via SHAP on surrogates**  
*Claim:* Hybrid feature importance yields understandable, dual‑perspective explanations.  
*Mechanism:* Two decision‑tree surrogates are trained—one on user features (predicts recommendation), one on recipe features (predicts preference). SHAP values from each tree quantify feature contributions. These values are combined to form the explanation basis.  
*Core assumption:* Surrogate trees accurately approximate the rule‑based recommender; SHAP values reflect true influence.  
*Break condition:* If the rule‑based system relies on complex interactions not captured by shallow trees, surrogates become poor approximations, leading to misleading importances.

**Mechanism 2: LLM‑driven narrative generation**  
*Claim:* Prompted LLMs transform structured importance into persuasive, lay‑friendly text.  
*Mechanism:* SHAP‑derived feature‑value pairs are inserted into a fixed prompt template and fed to an LLM, which generates a fluent, personalized justification.  
*Core assumption:* LLMs can reliably map structured data into coherent, convincing narratives that highlight key factors.  
*Break condition:* If the LLM produces factually inconsistent or irrelevant content, trust degrades despite fluency.

**Mechanism 3: User‑centered validation**  
*Claim:* User surveys confirm the hybrid approach improves satisfaction, with GPT‑4 excelling.  
*Mechanism:* A within‑subjects study with 19 participants rates plain and contrastive explanations on a 5‑point Likert scale and records model preference.  
*Core assumption:* The small sample reflects broader lay user preferences and the Likert scale captures satisfaction reliably.  
*Break condition:* If the sample is biased or too small, preference rankings may not generalize; if explanations ignore key constraints, satisfaction drops.

## Foundational Learning
- **SHAP (Shapley Additive Explanations)**  
  *Why needed:* Provides a game‑theoretic, consistent method to attribute predictions to input features, core to extracting interpretable importance from surrogate models.  
  *Quick check:* How does SHAP assign values and why is it preferable to permutation importance?

- **Prompt Engineering for LLMs**  
  *Why needed:* Explanation quality hinges on a prompt that effectively translates SHAP outputs into persuasive, user‑centric language.  
  *Quick check:* What risks arise if the prompt does not explicitly instruct the LLM to base its explanation on the provided attributes?

- **User‑Centered Evaluation in XAI**  
  *Why needed:* The goal is lay user trust; objective metrics alone are insufficient. Human assessments are necessary.  
  *Quick check:* Besides Likert ratings, what other methods could measure whether an explanation truly aids lay understanding?

## Architecture Onboarding
**Component map:** User Profile & Recipe Database → Rule‑Based Recommender → Feature Importance Module (User‑Centric Surrogate Tree + Recipe‑Centric Surrogate Tree + SHAP) → Explanation Generator (Prompt Builder + LLM) → Natural Language Explanation. Evaluation: Survey Interface collects ratings and preferences.

**Critical path:**  
1. User submits profile.  
2. Rule‑based recommender outputs a recipe.  
3. Feature importance module retrieves pre‑trained surrogates, computes SHAP values for the pair.  
4. Prompt built and sent to LLM; explanation returned.  
5. (Evaluation) User rates explanation.

**Design tradeoffs:**  
- Rule‑based vs. ML recommender: Rule‑based ensures transparency but may reduce accuracy.  
- Surrogate model choice: Decision trees are interpretable but may oversimplify, risking fidelity.  
- LLM selection: GPT‑4 yields higher satisfaction but is costlier and slower than FLAN.  
- Post‑hoc vs. intrinsic: Post‑hoc allows plug‑and‑play but risks fidelity gaps between surrogate and original system.

**Failure signatures:**  
- User ratings consistently below 2.5 or high variance across participants.  
- LLM outputs ignore SHAP values or contain factual errors about the recipe.  
- SHAP values contradict domain knowledge (e.g., a user with a mushroom allergy gets a mushroom recipe with high positive importance).  
- Long latency (>10 s) if surrogates are retrained per request instead of pre‑trained.

**First 3 experiments:**  
1. Replicate the full pipeline and run a survey with ≥20 participants to confirm GPT‑4 average ratings >3.5.  
2. Ablation – feature perspective: Use only user‑centric SHAP and measure change in user satisfaction; expect a drop if recipe attributes matter.  
3. Prompt sensitivity: Vary prompt phrasing (e.g., “Explain why …” vs. “Convince me …”) and analyze impact on output length, persuasiveness, and factual consistency.

## Open Questions the Paper Calls Out
1. **Generalizability** – The evaluation used only 19 participants, likely from a limited demographic. Does the system perform similarly across diverse user groups? A large‑scale, multi‑site study is needed.  
2. **Comparison with other LLMs** – The study tested GPT‑4, GPT‑3.5, and Flan T5 but not other models (Claude, Llama, nutrition‑fine‑tuned). Are the observed preferences model‑specific or inherent to the approach? Systematic benchmarking across models is required.  
3. **Over‑trust and critical engagement** – Could the persuasive LLM style induce blind acceptance? The paper flags this risk but did not test it. An experiment with deliberately flawed recommendations could measure user detection and over‑reliance.  
4. **Handling complex trade‑offs** – How does the system behave when preferences conflict (e.g., low‑cost vs. organic) or involve cultural nuances? The SHAP‑plus‑“convince‑me” prompt may oversimplify. Qualitative analysis on curated challenging cases and user studies on those would clarify.

## Limitations
- Small evaluation (n=19) threatens generalizability and statistical validity.  
- Prompt and SHAP feature selection details are underspecified, hindering replication.  
- No measurement of surrogate tree fidelity; explanations may misrepresent the true reasoning.  
- Absence of baseline comparisons prevents claiming improvement over alternatives.  
- No empirical assessment of LLM factual consistency; risk of hallucination remains unquantified.

## Confidence
- Hybrid SHAP‑surrogate yields dual‑perspective explanations: **Medium** (theoretically plausible but fidelity unverified).  
- LLM transforms SHAP outputs into persuasive narratives: **Low** (prompt‑dependent, no consistency guarantees).  
- Survey results show GPT‑4 superiority: **Low** (small, non‑random sample; no significance testing).

## Next Checks
1. **Fidelity test:** Compute agreement between the surrogate trees and the rule‑based recommender on a large test set; aim for >95% match. If lower, refine surrogates.  
2. **Prompt robustness:** Conduct an ablation study removing SHAP features or altering the instruction; have domain experts rate outputs for factuality and relevance.  
3. **Large‑scale user study:** Recruit ≥100 diverse lay participants in a within/between‑subjects design, add a baseline explanation method, and apply statistical tests to compare models.
