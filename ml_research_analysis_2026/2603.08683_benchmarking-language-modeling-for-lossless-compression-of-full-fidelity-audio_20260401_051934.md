# Benchmarking Language Modeling for Lossless Compression of Full-Fidelity Audio
## Quick Facts
- **ArXiv ID**: 2603.08683
- **Source URL**: https://arxiv.org/abs/2603.08683
- **Reference count**: 0
- **Primary result**: Byte-level tokenization enables tractable 24-bit audio compression, with language models outperforming FLAC at 8-bit (217% improvement) and 16-bit (18%) but underperforming at 24-bit (-9%).

## Executive Summary
This paper introduces Trilobyte, a byte-level tokenization scheme for lossless audio compression using language models. Prior LM-based approaches were limited to 8-bit audio due to exponential vocabulary growth with bit depth. Trilobyte replaces sample-level tokens with fixed-size byte tokens, reducing vocabulary scaling from O(2^b) to O(1) and enabling tractable modeling of 24-bit audio. Benchmarking across multiple domains and bit depths shows LM compression significantly outperforms FLAC at 8-bit and yields modest gains at 16-bit, but underperforms at 24-bit. The work demonstrates that a single trained model can compress audio at varying bit depths via lower-byte masking, maintaining performance comparable to dataset-specific models.

## Method Summary
Trilobyte employs byte-level tokenization: audio samples are split into fixed-size byte chunks (e.g., 3 bytes for 24-bit), each mapped to a token in a fixed 256-token vocabulary. A Transformer language model processes the token sequence to predict next-token probabilities, which are used by an arithmetic coder for entropy encoding. This avoids the exponential vocabulary growth of sample-level tokenization, enabling tractable modeling of high-bit-depth audio. The model can be trained on mixed bit-depth audio and applied to various bit depths via lower-byte masking, where only a subset of bytes in each sample are predicted based on context.

## Key Results
- At 8-bit depth, LM compression (Trilobyte) achieves an average 217% improvement over FLAC.
- At 16-bit depth, LM compression yields an average 18% improvement over FLAC.
- At 24-bit depth, LM compression underperforms FLAC by 9% on average.

## Why This Works (Mechanism)
The core mechanism is byte-level tokenization: instead of treating each audio sample as a token (which would require a vocabulary size of 2^b for b-bit depth), Trilobyte splits samples into fixed-size byte chunks (e.g., 3 bytes for 24-bit) and tokenizes each byte individually. This reduces the vocabulary to a constant 256 tokens regardless of bit depth, making language modeling tractable for high-fidelity audio while preserving lossless reconstructability through deterministic byte recombination.

## Foundational Learning
1. **Language Modeling for Compression**  
   *Why needed*: Provides adaptive probability estimation for entropy coding, replacing static models.  
   *Quick check*: Measure perplexity on held-out token sequences; lower perplexity indicates better probability estimation.

2. **Tokenization**  
   *Why needed*: Converts continuous audio into discrete symbols that LMs can process.  
   *Quick check*: Verify lossless reconstruction by comparing original and detokenized audio bit-for-bit.

3. **Bit Depth**  
   *Why needed*: Determines dynamic range and potential vocabulary explosion in sample-level schemes.  
   *Quick check*: Compute vocabulary size as 2^bit_depth for sample-level tokenization; observe exponential growth.

4. **Vocabulary Size**  
   *Why needed*: LM complexity and training difficulty scale with vocabulary; large vocabularies hinder modeling.  
   *Quick check*: Compare model performance (e.g., bits/back) across different vocabulary sizes on a fixed dataset.

5. **Lossless Compression**  
   *Why needed*: Guarantees perfect reconstruction of the original signal.  
   *Quick check*: Ensure decompressed output is bit-identical to input; compression ratio = original size / compressed size.

## Architecture Onboarding
**Component Map**: Raw Audio -> ByteTokenizer -> Transformer LM -> Token Probabilities -> Arithmetic Coder -> Compressed Bitstream

**Critical Path**: The processing pipeline: (1) Audio samples are split into fixed-size byte groups, (2) Each byte is mapped to a token (0-255), (3) The Transformer LM processes the token sequence and predicts next-token distributions, (4) An arithmetic coder uses these distributions to encode the tokens into a bitstream.

**Design Tradeoffs**:
- Fixed 256-token vocabulary vs. exponential sample-level vocabulary: enables high bit-depth modeling but may lose cross-byte correlations.
- Context window length: longer contexts improve compression but increase memory and latency quadratically (for Transformers).
- Model scale: larger models capture more structure but require more compute and may overfit on small datasets.

**Failure Signatures**:
- Performance degradation at 24-bit depth indicates model capacity or data limitations.
- High memory usage for long sequences due to self-attention.
- Poor generalization to unseen domains if training data lacks diversity.

## Limitations
- Evaluation datasets are undisclosed, raising concerns about domain diversity and generalizability.
- Computational overhead (memory, latency, energy) of LM compression is not benchmarked against FLAC, limiting practical adoption assessment.
- Reproducibility is unclear without public code or model releases.
