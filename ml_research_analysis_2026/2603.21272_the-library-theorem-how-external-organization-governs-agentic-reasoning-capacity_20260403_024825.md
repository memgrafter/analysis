# The Library Theorem: How External Organization Governs Agentic Reasoning Capacity

## Quick Facts
- arXiv ID: 2603.21272
- Source URL: https://arxiv.org/abs/2603.21272
- Reference count: 5
- Primary result: Indexed access to external memory (via a B-tree) reduces retrieval cost from linear to logarithmic per query, yielding up to 154× token savings at scale; a "parametric memory competition" failure occurs when models bypass retrieval on familiar content.

## Executive Summary
This paper introduces the "Library Theorem," which formalizes the transformer context window as an I/O page and proves that organizing an agent's external memory with an index (e.g., a B-tree) yields exponentially lower retrieval cost compared to sequential scanning. Theoretical bounds are O(log_b N) versus Ω(N) page reads per query, and O(T log_b T) versus Θ(T²) cumulative cost over T steps. Controlled experiments with GPT-4o-mini and GPT-5.4 across three content types confirm the theory: on abstract content, indexed agents achieve constant retrieval regardless of store size, while sequential scans scale linearly. However, on familiar encyclopedia content, models often ignore retrieval and rely on parametric knowledge, exhausting token budgets and collapsing accuracy. Two-level indexing (DEEP-INDEXED) restores constant retrieval and accuracy. The core design insight is to use language models for index construction (semantic understanding) but deterministic algorithms for index traversal (to avoid protocol bypass).

## Method Summary
The authors formalize the transformer context window as an I/O page, treating memory access as a sequence of page reads. They prove that using an index (such as a B-tree) reduces the worst-case retrieval cost. Empirically, they build a lookup benchmark where an LLM agent retrieves items from an external store of size M (50–5,000). The store contains random hashes, integers, or encyclopedia entries. The agent is prompted to either sequentially scan pages or use a pre-built index (the index itself is constructed by the LLM based on the store content). The main metrics are number of page reads and token usage, with accuracy as a secondary measure. The experiments compare two model families (GPT-4o-mini and GPT-5.4) and various conditions.

## Key Results
- Indexed retrieval achieves O(log_b N) page reads per query, demonstrated by nearly constant reads (median ≈1) even as store size grows to 5,000 items, while sequential scans show linear scaling (e.g., 21 reads at M=500). Cumulative token cost separation reaches 154× at large scales.
- Even with a stronger model (GPT-5.4), sorted pages without an index fail to close the gap; GPT-5.4 attains near-optimal log₂ N search but still loses 5× in efficiency due to extra token generation for reasoning.
- On familiar encyclopedia content, a "parametric memory competition" failure occurs: agents bypass retrieval and generate answers from internal knowledge, exhausting token budgets and collapsing accuracy to 27% at M=200; two-level indexing (DEEP-INDEXED) restores constant retrieval and high accuracy.

## Why This Works (Mechanism)
The mechanism hinges on separating semantic understanding from deterministic traversal. Language models excel at constructing an index from unstructured data because they can grasp meaning and create structured keys (e.g., sorting by topic, generating summaries). However, during retrieval, if the model is left to reason freely, it may skip reading the index or the target page and instead rely on parametric memory—a "protocol bypass" that leads to errors and token waste. By enforcing a deterministic traversal algorithm (e.g., binary search on a sorted list or B-tree navigation), the model is compelled to follow the protocol of reading the index and then the relevant page. This ensures that retrieval cost scales logarithmically and that the answer is grounded in the external store. The failure on familiar content arises because the model's parametric knowledge is strong enough to answer directly, making it "lazy" and skipping the retrieval step; using a deep two-level index (with a high-level semantic index pointing to sub-indices) makes bypass less attractive and forces disciplined access.

## Foundational Learning
Before diving into the system, readers should grasp these concepts:

- **B-tree index**: A self-balancing tree structure that allows O(log_b N) lookups. *Why needed*: It provides the theoretical foundation for logarithmic retrieval cost. *Quick check*: Given a B-tree of order 4 with 100 keys, what is the maximum number of page reads to find a key? (Answer: ≈3-4)
- **I/O page abstraction**: Treating the transformer’s context window as a fixed-size block of memory that must be read in full. *Why needed*: It frames memory access as a costly operation, aligning with LLM token budgets. *Quick check*: If the context window is 8K tokens and each "page" holds 512 tokens, how many pages are needed to hold 10K tokens? (Answer: 20 pages, with some overflow)
- **Asymptotic complexity in LLM cost**: Translating algorithmic O() bounds into token usage. *Why needed*: Connects theoretical CS to practical LLM inference costs. *Quick check*: If sequential scan costs O(N) page reads and N=1000, how many reads? (Answer: ~1000, but exact depends on query).
- **Parametric memory competition**: The phenomenon where an LLM relies on its internal weights rather than external retrieved data. *Why needed*: Explains the primary failure mode when external memory is not enforced. *Quick check*: When does this tend to occur? (Answer: On familiar, high-frequency facts that the model has memorized).
- **Deterministic vs. semantic traversal**: Using fixed algorithms (e.g., binary search) versus free-form LLM reasoning for navigation. *Why needed*: Highlights the design choice that prevents bypass. *Quick check*: What is a simple deterministic traversal for a sorted list? (Answer: Binary search).

## Architecture Onboarding
**Component Map**: Agent -> Index (LLM-constructed) -> Sorted Pages (Memory Store) -> Query. The agent receives a query, consults the index to locate the relevant page, reads that page, and formulates the answer. For deep indexing, a two-level structure is used: a high-level semantic index points to sub-indices, which in turn point to pages.

**Critical Path**: Upon receiving a query, the agent executes: (1) parse query, (2) traverse index (deterministic algorithm), (3) fetch the target page(s), (4) read page contents, (5) generate answer using retrieved text. Steps 2 and 3 must be completed before step 4; step 5 must use only retrieved content (enforced by prompt).

**Design Tradeoffs**: 
- *Index construction*: Using an LLM yields flexible, semantic indices (e.g., sorting by relevance), but can be expensive and error-prone. Deterministic traversal is cheap and reliable but requires the index to be structured (e.g., sorted keys).
- *Index depth*: A single-level index may become large to hold in context; a two-level index spreads the cost but adds traversal steps.
- *Enforcement*: Strict prompting to use retrieved content mitigates bypass but may reduce answer quality if retrieval is incomplete.

**Failure Signatures**:
- *Protocol bypass*: The model generates an answer without referencing retrieved text (detected by absence of quotes or citations), often on familiar topics.
- *Index traversal errors*: The model misinterprets index structure, leading to wrong page reads (e.g., off-by-one errors).
- *Token exhaustion*: Excessive page reads or verbose reasoning consume the context budget, causing truncation or failure.

**First Three Experiments**:
1. **Baseline sequential scan**: Query a store of 100 random hashes without an index, measure page reads and accuracy. Expect linear scaling.
2. **Indexed retrieval**: Build a B-tree index (LLM-constructed sorted keys), query the same store, measure page reads. Expect constant ~1 read independent of store size.
3. **Parametric competition test**: Replace random hashes with well-known encyclopedia facts (e.g., "capital of France"), repeat both conditions. Indexed retrieval should remain constant; sequential scan may show bypass and accuracy collapse.

## Limitations
- Model dependency: Results are demonstrated only on GPT-4o-mini and GPT-5.4; generalizability to other model families is unknown.
- Content scope: The benchmark uses synthetic hashes/integers and static encyclopedia entries; performance on dynamic, structured, or proprietary data remains unverified.
- Real-world integration: The "protocol bypass" failure was observed in a controlled single-query setting; its prevalence in multi-step, tool-use agent workflows is unclear.

## Confidence
- Formal complexity bounds (O(log_b N) vs Ω(N)): High
- Empirical retrieval cost reduction (abstract content): Medium
- Parametric memory competition collapse: Low
