# Brainstacks: Cross-Domain Cognitive Capabilities via Frozen MoE-LoRA Stacks for Continual LLM Learning

## Quick Facts
- **arXiv ID:** 2604.01152
- **Source URL:** https://arxiv.org/abs/2604.01152
- **Reference count:** 30
- **Primary result:** Achieves zero catastrophic forgetting in continual multi-domain learning by using frozen MoE-LoRA stacks with orthogonal subspace separation and a meta-router that discovers transferable cognitive primitives, enabling cross-domain composition without forgetting.

## Executive Summary
Brainstacks introduces a modular continual learning system for LLMs that prevents catastrophic forgetting by freezing each domain’s expertise into a dedicated MoE-LoRA adapter stack. New domains train via residual boosting on top of frozen stacks, with null-space gradient projection enforcing hard orthogonal separation between domain parameter subspaces. A meta-router, trained on oracle-derived optimal stack combinations, selectively activates stacks at inference, eliminating interference and revealing that stacks encode transferable cognitive primitives (e.g., numerical reasoning) rather than domain-specific knowledge. This architecture achieves zero forgetting while enabling emerging cross-domain capabilities, such as medical queries benefiting from chat and math stacks.

## Method Summary
The system sequentially trains per-domain MoE-LoRA adapter stacks on a frozen 4-bit quantized base model. For each domain, an inner loop of residual boosting trains multiple stacks: after a stack is frozen, a new one learns the residual error left by predecessors. Before training a new domain, an outer loop computes a null-space projector via randomized SVD on activation deltas from all frozen stacks and applies it to the active stack’s gradients, mathematically constraining updates to the orthogonal complement of prior subspaces. After all domains are trained, an outcome-based sigmoid meta-router is trained, using targets discovered by exhaustive loss measurement on a validation set to predict which stack combinations optimally solve each prompt. During inference, only stacks with router weight above a threshold are loaded, with offloaded stacks kept on disk.

## Key Results
- MoE-LoRA converges 2.5× faster than a parameter-matched single LoRA adapter.
- Zero forgetting is achieved: isolated domain evaluation loss matches training-time values exactly, even after training many subsequent domains.
- The meta-router reveals transfer: 97% of medical prompts route to the chat and math stacks despite those stacks having no medical data, improving generation quality.
- On Gemma 3 12B, routed inference maintains base model performance across zero-shot benchmarks while adding targeted capabilities.

## Why This Works (Mechanism)

### Mechanism 1: Null-Space Gradient Projection
- **Claim:** Randomised SVD computes a projector from activation deltas of frozen stacks; projecting new stack gradients onto the orthogonal complement enforces geometric subspace separation, eliminating interference and zero forgetting.
- **Mechanism:** Before training a new domain, validation data is passed through all frozen stacks to collect their parameter deltas. The top-K principal directions of these deltas are computed via SVD to form a basis matrix V. The projector P = V·Vᵀ is applied to the active stack’s gradient: δ_proj = δ - δ·P. The active stack’s update is thus confined to directions unused by prior stacks.
- **Core assumption:** Catastrophic forgetting is primarily caused by new-domain updates writing to parameter directions already important for prior domains. A hard linear constraint prevents such writes.
- **Evidence anchors:** [abstract] "null-space gradient projection enforcing orthogonal subspace separation"; [section 3.5] "The active stack is isolated by linear algebra—it operates in the orthogonal complement of the frozen subspace by construction."
- **Break condition:** If the base model’s hidden dimension is insufficient or the subspaces become saturated, projection will fail to find an orthogonal direction, causing subspace collision and forgetting (seen in PSN experiments with random init).

### Mechanism 2: Residual Boosting
- **Claim:** Training multiple sequential stacks per domain (inner loop) deepens capability by having each new stack learn the residual error left by frozen predecessors, overcoming single-stack capacity limits.
- **Mechanism:** For a given domain, after one stack is frozen, another is added and trained on the same data. Because the frozen stack provides a constant correction, the loss landscape shifts; the new active stack learns what the first could not capture, rather than relearning the same signal.
- **Core assumption:** A single adapter stack has a finite capacity to correct the base model’s outputs for a complex domain; additive residuals allow incremental refinement.
- **Evidence anchors:** [section 4.1] Figure 3: chat domain loss decreases from 0.8741 (single LoRA) to 0.8531 after 3 residual rounds. [section 3.3] describes the iterative residual process.
- **Break condition:** Diminishing returns; if the first stack already captures most of the learning signal, subsequent residual gains fall below the convergence threshold (δ_min=0.002).

### Mechanism 3: Outcome-Based Meta-Router
- **Claim:** A router trained on oracle-discovered optimal stack combinations (not domain labels) selectively activates stacks, eliminating ungated interference and revealing that stacks encode compositional cognitive primitives.
- **Mechanism:** For each prompt in the router’s training set, an exhaustive greedy search evaluates all domain stack combinations to find which minimise loss. These binary combination targets train a small sigmoid-gated router, which at inference maps the base model’s hidden states to per-stack activation probabilities. Multi-stack activation is allowed (sigmoid, not softmax), but only weights > threshold (0.12) load a stack.
- **Core assumption:** The optimal combination of domain stacks for a prompt is a learnable function of the prompt’s semantics and can be discovered by brute-force validation.
- **Evidence anchors:** [section 5.1] Medical prompts route to chat+math stacks 97% of the time despite zero medical data in those stacks. [section 3.6] explains the outcome-based target discovery.
- **Break condition:** If the base model’s hidden states lack predictive signal for optimal combinations, router accuracy drops, leading to under- or over-activation and re-introduced interference. Data contamination (e.g., code-like formatting in reasoning data) can cause router conflation.

## Foundational Learning

- **Concept: MoE-LoRA (Mixture-of-Experts LoRA)**
  - **Why needed here:** It is the atomic building block. Each Brainstack is a MoE-LoRA module with multiple low-rank experts and a noisy top-K router, allowing distributed domain expertise within a single adapter.
  - **Quick check:** What is the purpose of the auxiliary load-balance loss in MoE-LoRA, and what would happen without it?

- **Concept: Null-Space Projection for Continual Learning**
  - **Why needed here:** It is the core anti-forgetting mechanism. The engineer must understand that gradients are projected *before* weight updates using a linear algebraic constraint (P = V·Vᵀ) derived from prior domain activations.
  - **Quick check:** How does randomised SVD make the null-space projection computationally feasible for high-dimensional hidden states (e.g., 3840-dim)?

- **Concept: Outcome-Based Routing vs. Label-Based Routing**
  - **Why needed here:** The meta-router’s training paradigm is the architectural innovation that discovers cognitive primitives. It contrasts with traditional multi-task routing that uses domain IDs.
  - **Quick check:** Why might a prompt’s nominal domain label be a poor target for training the router?

## Architecture Onboarding

- **Component map:**
  Base Model (frozen 4-bit) -> StackedMoELoRALayer (per projection) -> MoE-LoRA Delta (N experts, router) 
  Inner Loop (Residual Boosting) -> Outer Loop (Null-Space Projection) -> Meta-Router (sigmoid gating) 
  Manifest & Disk Offload (load stacks > threshold)

- **Critical path:**
  1. Train Domain 1 (e.g., Chat) using residual boosting (Algorithm 1). Freeze all stacks from Domain 1.
  2. Before Domain 2 (e.g., Code): compute null-space projectors from *all* frozen stacks (Domain 1). Train Domain 2 with projection active. Freeze Domain 2 stacks.
  3. Repeat for subsequent domains in curriculum order (chat → code → math → medical → reasoning), recomputing cumulative projectors each time.
  4. After all domains: train meta-router on all domains’ validation data using oracle combination discovery.
  5. Inference: base model runs; router predicts domain weights; load only stacks with weight > threshold (0.12).

- **Design tradeoffs:**
  - Subspace Capacity vs. Domain Count: Each domain claims ~64 directions (1.7% on 3840-dim). More domains risk capacity overflow; may require larger hidden dim or fewer directions.
  - Router Accuracy vs. Training Data Fidelity: Router highly sensitive to training data characteristics (e.g., reasoning data must avoid code-like formatting). Poor data causes misrouting.
  - Training Time vs. Stack Count: Residual boosting and SVD add overhead. More stacks per domain increase training time linearly but yield diminishing returns.
  - Inference Latency vs. Domain Activation: Loading stacks from disk (~1s/stack) delays if no cache hit. Trade-off between resident GPU memory (cost) vs on-demand loading (latency).

- **Failure signatures:**
  - Catastrophic forgetting in a prior domain: Isolation loss increases during later domain training. Indicates subspace collision; check SVD computation and projection application.
  - Ungated interference (all stacks fire): Non-domain prompts generate irrelevant outputs (e.g., math prompts formatting text). Expected without router; validate by running with all stacks active.
  - Router conflation (e.g., reasoning always routing with code): Inspect router training data for contamination (code snippets). Check oracle discovery logs: is reasoning’s contribution sub-threshold?
  - Stack corruption during training: Loss spikes to very high values (e.g., ~28M in GRPO). BestStackCallback should catch and restore; if not, a bad stack was frozen.
  - Poor convergence on a domain: Check dataset quality, training order (medical before math fails), data contamination from previous domains.

- **First 3 experiments:**
  1. **MoE-LoRA vs. Parameter-Matched Single LoRA:** Train MoE-LoRA (4 experts, r=16) on Alpaca. Validate MoE-LoRA converges 2.5× faster per step and matches/beats single LoRA (r=64) validation loss despite higher training loss (aux loss).
  2. **Ungated Interference Matrix Analysis:** After full Brainstacks training for two domains, disable router and measure per-domain validation loss with all stacks active. Expect: isolation loss matches training value (zero forgetting), but ungated loss is much higher, demonstrating interference.
  3. **Meta-Router Training and Oracle Discovery:** After full SFT, compute oracle combination targets on held-out prompts via greedy loss search. Train sigmoid router (8 epochs). Analyze routing patterns: do medical prompts route to chat+math stacks? Target accuracy >90% single-top1.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** Can the outcome-based meta-router be trained efficiently without exhaustive greedy oracle search over domain combinations, especially as the number of domains grows?
- **Basis in paper:** [inferred] The meta-router uses a greedy oracle that evaluates each domain combination per prompt to find the minimising loss. This discovery scales exponentially and is not addressed.
- **Why unresolved:** No alternative (e.g., RL, differentiable selection) is explored; the scalability bottleneck remains for systems with dozens of domains.
- **What evidence would resolve it:** Implement and compare alternative router training methods (e.g., reinforcement learning with reward = loss reduction) on scalability and routing quality with 5–10 domains.

### Open Question 2
- **Question:** Do the claimed transferable cognitive primitives generalize to domains that are primarily knowledge-intensive rather than skill-intensive?
- **Basis in paper:** [explicit] The central finding is that stacks encode primitives (instruction-following, numerical reasoning), supported by medical prompts routing to chat+math stacks. Authors propose testing legal/finance domains.
- **Why unresolved:** Evidence comes from reasoning/skill-heavy domains. Knowledge-intensive domains (legal codes, historical facts) might force stacks to memorise facts, challenging the universality of the primitive claim.
- **What evidence would resolve it:** Train Brainstacks on knowledge-intensive domains. Analyse whether these stacks are ever activated by non-nominal-domain prompts and whether their internal representations cluster with primitive stacks or form domain-specific clusters.

### Open Question 3
- **Question:** Is it possible to build a modular continual learning system that achieves zero forgetting and cross-domain composition without requiring a pretrained base model?
- **Basis in paper:** [explicit] The PSN experiment fails on a randomly initialised model, concluding stacks need an established representation space. A Partitioned Subspace Network is proposed as future work.
- **Why unresolved:** Brainstacks relies on residual refinements to a competent base model. Native continual pretraining—building modular capability subspaces from random init—remains unsolved.
- **What evidence would resolve it:** Design a Partitioned Subspace Network where each domain phase claims dedicated hidden dimensions from the start with explicit orthogonalisation. Train sequentially from random init and measure per-domain loss matching separate-from-scratch baselines and absence of forgetting.

### Open Question 4
- **Question:** Can LatentMoE-style compression be applied to Brainstacks’ stacks to reduce memory footprint by an order of magnitude without degrading cross-domain quality?
- **Basis in paper:** [explicit] Section 8.3 proposes LatentMoE to project hidden states into a small latent space (e.g., 256D) before routing and expert computation, potentially reducing per-stack memory ~16×.
- **Why unresolved:** The interaction between latent projection and the meta-router’s selective gating is unknown; low-dimensional representations might lose fine-grained information needed for cross-domain composition. Orthogonal subspace guarantees may not hold after projection.
- **What evidence would resolve it:** Integrate LatentMoE into Brainstacks, train on 2–3 domains, compare against full-dimensional baseline on: (a) per-stack memory usage, (b) generation quality across single and mixed-domain prompts, (c) router selection accuracy and resulting interference.

## Limitations
- Meta-router scalability is questionable due to reliance on exhaustive oracle combination search, which scales exponentially with domain count and is sensitive to training data formatting.
- Subspace capacity is limited (~1.7% usage per domain on Gemma 3 12B), suggesting a hard ceiling (~60 domains); the paper does not explore this boundary or what happens when orthogonal projection fails.
- The practical benefit of residual boosting beyond a single stack is unclear, with only marginal loss improvements (e.g., 0.8741 → 0.8531) and uncertain downstream task gains.

## Confidence
- **Zero forgetting via null-space projection:** High (mechanism mathematically precise; isolation losses match training values).
- **Cognitive primitive transfer (router discovery):** Medium (97% medical→chat+math routing compelling but may be artifact of dataset overlap or router overfitting).
- **MoE-LoRA convergence speed:** High (2.5× faster clearly measured).
- **Subspace capacity limit:** Low (no direct empirical failure analysis; extrapolated from usage stats).
- **Residual boosting necessity:** Medium (loss improves but cost-benefit vs. larger single LoRA unclear).

## Next Checks
1. **Stress-test meta-router robustness:** Re-train the router with intentionally contaminated reasoning data (e.g., inject code snippets). Measure mis-routing rates and generation quality on medical/math prompts. Expect if fragile: medical prompts route to code stacks >20% of the time.
2. **Probe subspace capacity limits:** Incrementally add domains (10+, 20+) on Gemma 3 12B, tracking per-domain subspace usage (rank-64 projection). At point where isolation loss degrades >5%, inspect projected gradient norms to confirm subspace collision.
3. **Ablate residual boosting:** Compare a single large LoRA (r=64) versus Brainstacks with 3 residual stacks on the same domain, matched for total parameters. Evaluate not just loss but downstream task accuracy (e.g., GSM8K for math) to see if residual stacking yields usable gains beyond optimizer noise.
