# Fix Before Search: Benchmarking Agentic Query Visual Pre-processing in Multimodal Retrieval-augmented Generation

## Quick Facts
- arXiv ID: 2602.13179
- Source URL: https://arxiv.org/abs/2602.13179
- Reference count: 40
- Primary result: Introduced V-QPP-Bench, showing that agentic preprocessing of imperfect visual queries recovers MRAG performance degraded by up to 98.6%, and that supervised fine-tuning on the benchmark enables a 4B MLLM to match or surpass larger proprietary models.

## Executive Summary
Multimodal Retrieval-Augmented Generation (MRAG) systems typically assume clean visual queries, making them vulnerable to real-world imperfections like rotation, blur, and clutter. This paper introduces V-QPP-Bench, a comprehensive benchmark for Visual Query Pre-Processing (V-QPP) that frames the task as agentic: an MLLM must diagnose flaws and apply perceptual tools (rotate, deblur, crop, etc.) to refine queries before retrieval. The benchmark comprises 46,700 imperfect queries across 10 corruption types and 5 retrieval paradigms. Experiments reveal that imperfections cause severe degradation in retrieval and QA performance, that oracle preprocessing nearly restores perfect results, and that off-the-shelf MLLMs struggle with tool selection and parameter prediction. However, supervised fine-tuning on just 1,000 training examples enables a 4B model to achieve performance comparable to much larger proprietary systems, highlighting the potential of training robust V-QPP agents.

## Method Summary
The authors construct V-QPP-Bench by applying 10 controlled corruptions (e.g., geometric transformations, blur, noise, semantic ambiguities) to clean images from InfoSeek and ViQuAE datasets, yielding 46,700 imperfect queries. For each corruption, an oracle sequence of tool calls—selected from a library of 8 atomic operations (rotate, flip, lum, deblur, denoise, locate, crop, fill)—is defined to reverse the degradation, with precise parameters. The V-QPP task is formulated as an agentic decision problem: given a corrupted image and a question, an MLLM outputs a JSON sequence of tool calls that are executed sequentially to produce a refined image. This refined image is then encoded by a multimodal retriever (e.g., Nomic embed-text-v1.5) to fetch relevant contexts from a knowledge base, and a generator MLLM produces the final answer. The paper evaluates five MRAG paradigms (I2T, Caption‑then‑Retrieve, I2I, Composed, API) and trains agents via supervised fine‑tuning (SFT) on 1,000 samples using LoRA (rank 8, learning rate 1e‑4, 3 epochs, batch size 8).

## Key Results
- Visual imperfections degrade retrieval significantly, with Recall@5 dropping up to 98.6% on RealWorld queries.
- Oracle preprocessing (perfect tool selection and parameters) nearly restores original MRAG performance for reversible corruptions, confirming that most degradation is recoverable.
- Off‑the‑shelf MLLMs (e.g., GPT‑4o, Qwen‑VL) show poor tool selection and parameter accuracy, leading to limited gains.
- Supervised fine‑tuning on V‑QPP‑Bench enables a 4B‑parameter model to match or exceed larger proprietary models in both tool usage metrics and end‑to‑end QA accuracy.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Visual imperfections (e.g., rotation, blur, clutter) severely degrade retrieval recall and end‑to‑end MRAG performance.
- **Mechanism:** Imperfections alter the image embedding space distribution, causing misalignment with the indexed knowledge base and lowering similarity scores for relevant documents.
- **Core assumption:** Standard MRAG pipelines assume queries are noise‑free; any deviation creates a distribution shift that retrievers cannot handle robustly.
- **Evidence anchors:**
  - [abstract] "Imperfections cause severe degradation—up to 98.6% Recall@5 drop for RealWorld queries."
  - [section 5.2] Quantified recall drops per corruption type (e.g., RealWorld −98.6%, Expand −80.3%).
  - [corpus] Evidence insufficient in neighboring papers; this claim is primarily supported by the authors’ own experiments.
- **Break condition:** If retrievers become invariant to all considered corruption types without any preprocessing, the mechanism would no longer hold.

### Mechanism 2
- **Claim:** Oracle preprocessing (perfect tool selection and parameter prediction) nearly restores perfect MRAG performance for most imperfections, demonstrating high restoration potential.
- **Mechanism:** Applying the inverse transformation of the corruption realigns the query embedding with the knowledge base, recovering the original retrieval quality.
- **Core assumption:** Most corruptions are reversible (or approximately reversible) with appropriate tools; for irreversible ones (e.g., cropping), no tool can recover lost information.
- **Evidence anchors:**
  - [abstract] "Oracle preprocessing nearly restores perfect performance."
  - [section 5.3] Oracle results show recovery close to original for geometric distortions and semantic ambiguities, but limited gains for quality degradations due to irreversible pixel loss.
  - [corpus] No direct evidence; neighboring works do not evaluate oracle tool performance.
- **Break condition:** When corruption causes permanent information loss (e.g., aggressive cropping) or tool‑inherent artifacts (e.g., deblurring adds noise), the oracle ceiling drops below original performance.

### Mechanism 3
- **Claim:** Supervised fine‑tuning on V‑QPP‑Bench enables a compact model to match or exceed larger proprietary MLLMs in both tool usage and end‑to‑end MRAG performance.
- **Mechanism:** Task‑specific training teaches the MLLM to correctly diagnose imperfections and generate accurate tool‑selection + parameter JSON sequences, overcoming zero‑shot bottlenecks.
- **Core assumption:** The agentic decision‑making for visual preprocessing is learnable from demonstrated trajectories (imperfect → oracle actions).
- **Evidence anchors:**
  - [abstract] "Supervised fine‑tuning on the benchmark enables a 4B model to match or surpass larger proprietary models."
  - [section 5.4] SFT model shows balanced tool selection accuracy and higher retrieval recall across corruption types compared to zero‑shot baselines.
  - [corpus] Insufficient; adjacent benchmarks (e.g., MRAG‑Suite) focus on evaluation, not training for tool use.
- **Break condition:** If the required tool‑use complexity (e.g., long‑horizon planning, unseen parameters) exceeds the capacity of SFT on the provided 1,000‑sample training set, the gains would not generalize.

## Foundational Learning
- **Multimodal Retrieval‑Augmented Generation (MRAG):** Integrates external knowledge into a generator via retrieval from a multimodal corpus. *Why needed:* The V‑QPP pipeline directly feeds into the retriever; understanding MRAG clarifies why query quality matters for downstream answer generation. *Quick check:* How does the multimodal query embedding differ from a text‑only query embedding in a typical MRAG system?
- **Agentic tool use in MLLMs:** MLLMs output structured tool calls (e.g., JSON) to interact with external functions. *Why needed:* V‑QPP is formulated as an agentic task where the model must select appropriate tools and parameters, not just produce free‑form text. *Quick check:* What are the key challenges in training an MLLM to select appropriate tools and predict precise parameters (e.g., rotation angle, bounding box)?
- **Benchmark construction via reverse‑engineering corruptions:** Imperfect images are generated by applying known corruptions, and oracle tool sequences are derived by inverting those corruptions. *Why needed:* This reverse design ensures reproducible evaluation with ground‑truth optimal actions. *Quick check:* Why is it necessary to define both the corruption function *f* and its inverse *f⁻¹* (oracle) for each imperfection type?

## Architecture Onboarding
- **Component map (plain text):** Imperfection Generator -> Tool Library -> V-QPP Agent -> Retriever -> Generator
- **Critical path:** Input visual query → Agent tool selection → Sequential tool execution → Refined image → Retrieve top‑K contexts → Generate answer.
- **Design tradeoffs:**
  - Tool granularity: Fine‑grained atomic tools (e.g., separate `locate` + `crop`) increase flexibility but require multi‑step reasoning.
  - Forced retrieval vs. agent‑decided: Forced retrieval isolates V‑QPP impact; agent‑decided adds realism but introduces confounders.
  - Parameter space: Discrete (rotate angles) vs. continuous (brightness factor); JSON schema enforces structure but limits expressivity.
- **Failure signatures:**
  - Tool selection imbalance: Model over‑uses a few tools (e.g., always `crop`) regardless of corruption type.
  - Parameter errors: Inaccurate bounding boxes (`locate` → `crop/fill`) or wrong rotation/flip values.
  - Irreversible corruption bottleneck: Cropping, heavy blur/noise show limited oracle recovery; gains capped by information loss.
- **First 3 experiments:**
  1. Vulnerability quantification: Run retrieval on imperfect queries (no preprocessing) vs. original to measure recall degradation across all 10 corruption types.
  2. Oracle upper bound: Apply perfect tool sequences (known inverse transforms) to establish maximum possible recovery for each corruption.
  3. Zero‑shot agent evaluation: Test off‑the‑shelf MLLMs (e.g., GPT‑4o, Qwen‑VL) on V‑QPP and measure tool selection accuracy, parameter scores, and end‑to‑end MRAG performance to identify baseline bottlenecks.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How do V‑QPP agents perform on queries with multiple concurrent visual imperfections compared to single‑corruption scenarios?
- **Basis in paper:** [explicit] In Section 4.1, the authors state: "While real‑world imperfections often involve multiple concurrent corruptions and our benchmark supports generating such compositions, we focus on single‑corruption scenarios to enable fine‑grained analysis of each operation’s individual impact."
- **Why unresolved:** The current benchmark and evaluations are restricted to single‑corruption cases, leaving the agent’s capability to diagnose and sequentially apply multiple tools for intertwined imperfections unexplored. Real‑world queries often exhibit several flaws simultaneously.
- **What evidence would resolve it:** Extend V‑QPP‑Bench to include multi‑corruption samples (e.g., rotated and blurred images). Evaluate existing V‑QPP agents on this extended set, measuring tool selection accuracy, parameter prediction, and end‑to‑end retrieval/MRAG performance compared to single‑corruption baselines.

### Open Question 2
- **Question:** Can reinforcement learning (RL) improve V‑QPP agent training beyond supervised fine‑tuning (SFT), particularly for generalizing to unseen corruption types and optimizing for end‑to‑end MRAG rewards?
- **Basis in paper:** [explicit] In Section 5.4, the authors suggest: "Future work may explore end‑to‑end joint optimization or reinforcement learning to further enhance V‑QPP capabilities." The conclusion also mentions "more advanced training paradigms (e.g., reinforcement learning)."
- **Why unresolved:** The paper only demonstrates SFT on a small dataset. RL could directly optimize retrieval‑based rewards and handle tool selection as a sequential decision problem, potentially overcoming SFT’s limitations in generalization and long‑term credit assignment.
- **What evidence would resolve it:** Implement an RL training setup where the agent receives reward signals based on retrieval success after tool execution. Compare RL‑trained agents against SFT agents on held‑out corruption types and measure sample efficiency, tool usage diversity, and final MRAG accuracy.

### Open Question 3
- **Question:** What are the trade‑offs between always‑forced retrieval and agent‑decided retrieval in V‑QPP pipelines regarding accuracy, efficiency, and robustness?
- **Basis in paper:** [inferred] The paper implements an agent‑decided retrieval mode (Section A.3) but primarily reports results under forced retrieval to isolate V‑QPP impact. The authors note that agent‑decided retrieval simulates realistic scenarios where unnecessary retrieval may introduce noise, but its effects are not analyzed.
- **Why unresolved:** Forcing retrieval always might still retrieve irrelevant contexts if the image remains ambiguous, or incur unnecessary computational cost. Allowing the agent to skip retrieval could improve efficiency but risks missing necessary knowledge. The optimal strategy remains unclear.
- **What evidence would resolve it:** Conduct experiments comparing forced retrieval versus agent‑decided retrieval across all imperfection types. Measure end‑to‑end QA accuracy, retrieval relevance, and inference latency. Analyze when the agent correctly decides to retrieve or not, and correlate with image quality after preprocessing.

### Open Question 4
- **Question:** Which additional perceptual tools are needed to address real‑world visual imperfections not covered by the current V‑QPP tool library (e.g., perspective distortion, color casts, extreme low resolution)?
- **Basis in paper:** [inferred] The tool library includes eight atomic tools (Section 4.2), but the authors acknowledge limitations: some corruptions like Crop are irreversible, and the taxonomy may not capture all real‑world defects. The benchmark’s imperfections are predefined and synthetic.
- **Why unresolved:** Real‑world user queries may include issues such as non‑axis‑aligned perspective warps, unnatural color balances, or severe pixelation that lack corresponding tools. Without appropriate tools, agents cannot effectively preprocess such queries.
- **What evidence would resolve it:** Collect a diverse corpus of real‑world imperfect query images from applications (e.g., mobile search, e‑commerce). Identify common imperfections absent from the current taxonomy. Design and integrate new tools (e.g., perspective correction, color normalization, super‑resolution) into the library. Evaluate whether adding these tools improves performance on the new samples.

### Open Question 5
- **Question:** How well does a V‑QPP agent trained on V‑QPP‑Bench generalize to out‑of‑distribution domains (e.g., medical imaging, satellite photos) and truly unscripted user‑generated imperfect images?
- **Basis in paper:** [inferred] The benchmark uses InfoSeek (web‑based QA) and ViQuAE (named entities), which are specific to general knowledge domains. The imperfection generation is synthetic, using controlled corruptions on curated images. Generalization to other domains or natural imperfections is not tested.
- **Why unresolved:** The agent might overfit to the visual styles and corruption patterns in the training data. Real‑world deployment could involve entirely new contexts (e.g., X‑ray images with noise, satellite images with cloud cover) where tool applicability may differ.
- **What evidence would resolve it:** Transfer a V‑QPP agent fine‑tuned on V‑QPP‑Bench to external datasets from diverse domains (e.g., medical VQA datasets with imperfect scans, satellite imagery benchmarks). Measure performance degradation in retrieval and QA accuracy. Perform error analysis to identify domain‑specific challenges in tool selection and parameter prediction.

## Limitations
- Tool implementations (deblur/denoise specifics) are underspecified, risking deviation from original recovery estimates.
- Retrieval corpus construction details for ViQuAE are incomplete, potentially invalidating recall comparisons.
- Benchmark corruptions are synthetic; real‑world noise may not align, limiting ecological validity.

## Confidence
- Mechanism 1 (Imperfections degrade MRAG): Medium
- Mechanism 2 (Oracle restores performance): Medium for reversible corruptions, Low for irreversible ones
- Mechanism 3 (SFT enables small models): Medium
