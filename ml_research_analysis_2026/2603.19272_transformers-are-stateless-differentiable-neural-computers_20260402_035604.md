# Transformers are Stateless Differentiable Neural Computers

## Quick Facts
- arXiv ID: 2603.19272
- Source URL: https://arxiv.org/abs/2603.19272
- Reference count: 11
- Primary result: A causal Transformer layer is formally equivalent to a stateless Differentiable Neural Computer (sDNC), unifying Transformers under a memory-centric framework.

## Executive Summary
The paper bridges Transformers and Differentiable Neural Computers (DNCs) by introducing stateless DNCs (sDNCs) and proving that a single causal Transformer layer exactly implements an sDNC. This equivalence identifies key/value projections as controller emissions, the value matrix as write-once memory, and self-attention as content-based memory reads. The result extends to multi-head attention (multiple read heads) and cross-attention (separate encoder-decoder memories), providing a novel memory-centric perspective on Transformer architecture.

## Method Summary
The authors formalize sDNCs as DNCs without recurrent state and with write-once memory. They then construct a mapping from a causal Transformer layer: the query and key projections serve as the controller’s emissions; the value matrix acts as the memory that is written once per token; and the attention operation performs content-based reads from this memory. The proof shows that for any sequence, the Transformer’s output can be interpreted as the sDNC’s read vector. This theoretical foundation unifies two previously distinct neural architectures and suggests new directions for memory-augmented models.

## Key Results
- Theorem: A single causal Transformer layer is exactly equivalent to a stateless DNC.
- Mapping: Key/value projections correspond to controller emissions; the value matrix is write-once memory; self-attention implements content-based reads.
- Extensions: Multi-head attention maps to multiple read heads; cross-attention extends the framework to encoder-decoder settings with separate memories.

## Why This Works (Mechanism)
In an sDNC, the controller emits keys that address memory, and writes values that are never overwritten. During autoregressive processing, each token's key and value are written to memory exactly once, and subsequent tokens can read any previously written value via content-based addressing. Transformer self-attention computes exactly this: for a given query, the compatibility with all prior keys determines read weights, and the values weighted by these softmax weights form the output. The write-once property aligns with the cumulative nature of the value matrix, and the stateless controller matches the absence of recurrent state in the Transformer layer. Hence, the mechanisms coincide perfectly.

## Foundational Learning
- **Self-Attention**: Core operation that computes weighted sums of values based on query-key similarity. *Why needed*: Enables content-based retrieval from the memory of previous tokens. *Quick check*: Given Q, K, V, can you compute attention as softmax(QKᵀ/√d_k)V?
- **Content-Based Addressing**: Memory retrieval by comparing a query with stored keys. *Why needed*: Allows flexible access to stored information independent of location. *Quick check*: Is the attention score directly analogous to a content-based address in DNCs?
- **Write-Once Memory**: A memory store where each write occurs once and is never modified. *Why needed*: Simplifies the DNC model and matches the Transformer's value accumulation. *Quick check*: Does the Transformer ever overwrite a previously written value?
- **Stateless Controller**: A controller that does not maintain hidden state across time steps. *Why needed*: Removes recurrence, enabling parallelization. *Quick check*: Are the Transformer layer's computations only a function of the current input and previous memory?
- **Multi-Head Attention**: Multiple attention heads operating in parallel. *Why needed*: Increases capacity to capture diverse relational patterns. *Quick check*: Do separate heads correspond to independent read heads in sDNCs?
- **Causal Masking**: Restricts attention to previous positions. *Why needed*: Enables autoregressive generation and enforces write-once reads. *Quick check*: Does the mask prevent attending to future tokens, thus respecting the write-once memory timeline?

## Architecture Onboarding
**Component map:** Input Tokens → Linear Projections (Query, Key, Value) → Scaled Dot-Product Attention → Output Projection. In sDNC terms: Controller (Q,K) → emits Key (K) and writes Value (V) to Memory (V matrix) → Read via content-based weights (softmax(Q·Kᵀ)) → Read vector ∑(weights·V) → Output.

**Critical path:** For each token t: compute q_t, k_t, v_t; append (k_t,v_t) to memory; for all later tokens s>t, q_s accesses memory to read from all previous v's. This yields a fully parallelizable computation during training.

**Design tradeoffs:** Write-once memory trades off the ability to update or erase information for simplicity and trainability; multi-head attention increases expressive power at the cost of memory and compute; causal masking ensures valid temporal ordering but prohibits bidirectional context.

**Failure signatures:** Inability to modify memory leads to failure on tasks requiring iterative updates (e.g., counting); attention saturation (uniform weights) indicates loss of discriminative retrieval; gradient propagation over very long sequences may vanish, harming long-range learning.

**First experiments:** 1) Evaluate on a synthetic copying task of increasing length to test memory retention; 2) Compare Transformer and sDNC on associative recall benchmarks; 3) Ablate multi-head attention and measure changes in long-context accuracy to isolate head contributions.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: How can Transformer layers be augmented with selective write operations to allow dynamic memory updates while maintaining trainability?
- Basis in paper: [explicit] The Discussion proposes selective writes as a promising direction but provides no implementation details.
- Why unresolved: Selective writes require differentiable, parallelizable mechanisms that don't disrupt attention's content-based reads.
- What evidence would resolve it: A concrete integration scheme (e.g., gated value updates) that improves performance on long-context tasks without sacrificing scalability.

### Open Question 2
- Question: Does the sDNC equivalence hold for multi-layer Transformer architectures with residual connections and feed-forward networks?
- Basis in paper: [inferred] Theorem 1 proves equivalence only for a single causal layer; interactions across layers with residuals are unanalyzed.
- Why unresolved: Residual additions and feed-forward transformations may alter the memory read/write dynamics when stacked.
- What evidence would resolve it: A formal extension of the theorem to deep stacks or empirical validation that per-layer sDNC behavior composes correctly.

### Open Question 3
- Question: Can the sDNC framework be generalized to non-causal self-attention (e.g., bidirectional models like BERT)?
- Basis in paper: [explicit] The paper only addresses causal self-attention and cross-attention; non-causal masking is not considered.
- Why unresolved: Non-causal attention accesses future tokens, conflicting with the sDNC's write-once, causally accumulating memory.
- What evidence would resolve it: A revised sDNC definition that accommodates arbitrary attention masks, or a proof that such attention cannot be represented as an sDNC.

### Open Question 4
- Question: What are the representational limitations of sDNCs relative to full DNCs for algorithmic reasoning tasks?
- Basis in paper: [inferred] The paper highlights missing DNC features (erase, temporal links) but does not quantify their impact on computational capacity.
- Why unresolved: Without explicit write control or temporal structures, sDNCs may be unable to learn certain algorithms that full DNCs can.
- What evidence would resolve it: Theoretical characterization of the class of functions computable by sDNCs, or comparative benchmarks on algorithmic tasks (e.g., sorting, copying).

## Limitations
- Theoretical analysis focuses on idealized causal Transformer layers, omitting common components like layer normalization, residual connections, and rotary embeddings.
- The write-once memory abstraction does not capture the dynamic memory updates observed in trained Transformers.
- Empirical validation of the proposed equivalence beyond the formal mapping is not presented.

## Confidence
- Theoretical Equivalence (causal Transformer layer ↔ sDNC): High
- Generalizability to Full Transformer Architectures (with residuals, LayerNorm, etc.): Low
- Practical/Computational Implications of the memory-centric view: Medium
