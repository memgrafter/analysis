# A Hierarchical Multi-Agent System for Autonomous Discovery in Geoscientific Data Archives

## Quick Facts
- **ArXiv ID:** 2602.21351  
- **Source URL:** https://arxiv.org/abs/2602.21351  
- **Reference count:** 40  
- **Primary result:** PANGAEA‑GPT autonomously resolves all runtime errors (5/5) and significantly outperforms baselines on an agentic search benchmark (mean score 8.14/10 vs. 5.46/10 and 2.87/10).

## Executive Summary
Geoscientific data archives such as PANGAEA are underutilized due to format heterogeneity and inconsistent metadata. This paper introduces PANGAEA‑GPT, a hierarchical multi‑agent framework that centralizes task planning in a Supervisor and delegates to specialist workers tailored to data modalities (e.g., Oceanographer for multidimensional arrays, DataFrame for tabular data). The system executes code in sandboxed Jupyter environments, self‑corrects by parsing execution tracebacks, and applies reflexive visual quality control via a vision‑language model. Evaluated on four real‑world use‑cases (oceanography, ecology), it autonomously fixed all five encountered runtime errors without human intervention. On a benchmark of 100 natural language queries, it achieved a mean score of 8.14/10, far surpassing keyword search (5.46/10) and single‑pass LLM (2.87/10) baselines, with major gains in precision and parameter coverage. The work demonstrates the viability of agentic AI for end‑to‑end autonomous discovery in complex scientific archives.

## Method Summary
The architecture comprises a Search Agent that iteratively refines queries using a ReAct loop to retrieve datasets from PANGAEA’s Elasticsearch API. Metadata from retrieved datasets is introspected to derive binary feature flags (gridded array, depth axis, geospatial coordinates, temporal index). A Supervisor Agent, implemented as a stateful LangGraph planner, uses these flags to decompose the user request and route subtasks to appropriate Worker Agents. Workers generate Python code that executes in an isolated, persistent Jupyter kernel (UUID‑based workspace). Execution errors are captured and fed back to the generating agent, which parses the traceback, refactors the code, and retries. For figures, a Visualisation Agent produces plots influenced by a RAG index of domain exemplars; a vision model then evaluates the figure against a ten‑point rubric and provides structured feedback, iterating up to five times until a threshold is met. A “Wise Agent” (different LLM) escalates unresolved errors after retry limits. Finally, a Writer Agent synthesizes all outputs into a coherent report.

## Key Results
- All 5 runtime errors encountered across four end‑to‑end use‑cases were autonomously resolved without human intervention.  
- Agentic search benchmark over 100 queries: mean score 8.14/10, significantly higher than keyword search (5.46/10) and single‑pass LLM (2.87/10), with large gains in precision and parameter coverage.  
- Reflexive visual quality control consistently produced publication‑ready figures within ≤5 iterations.

## Why This Works (Mechanism)
### Mechanism 1: Data‑Type‑Aware Routing
The Supervisor inspects precomputed metadata feature flags (gridded array, depth axis, geospatial coordinates, temporal index) to assign subtasks to specialist agents (e.g., Oceanographer for N‑dimensional arrays, DataFrame for tabular data). This prevents mismatches such as routing a NetCDF file to a DataFrame‑only agent, ensuring appropriate tool usage (xarray vs pandas). Evidence: Section 2.1 and 5.1.4 describe the flagging and routing logic. Failure condition: Incomplete or incorrect metadata (e.g., missing depth flag) causes misrouting that downstream agents cannot correct.

### Mechanism 2: Sandboxed Deterministic Execution with Self‑Correction
Each user session runs in an isolated Jupyter kernel with a persistent filesystem and state. Agents generate Python code; errors (stderr) are fed back, and the agent parses the traceback, refactors, and re‑executes automatically. This allows recovery from common runtime errors. Evidence: Abstract and Section 5.2.4 detail the loop. Assumption: Errors are recoverable via syntactic/semantic code fixes, not fundamental data issues. Break condition: Persistent or complex algorithmic failures exceed retry limits, triggering Wise Agent escalation.

### Mechanism 3: Reflexive Visual Quality Control
After plot generation, a vision‑language model evaluates the figure against a ten‑point rubric (axis labels, legend completeness, depth inversion, etc.). If the score is below threshold, structured feedback guides the agent to refactor the code. The loop iterates up to 5 times until the figure meets publication standards. Evidence: Section 2.2.1 and 5.2.6. Assumption: Visual flaws are diagnosable and correctable via deterministic code changes. Break condition: Critic inconsistency or agent inability to implement fixes leads to stall after max iterations.

## Architecture Onboarding
- **Component map:**
Search Agent → Supervisor Agent → Worker Agents (Oceanographer, Ecologist, DataFrame, Visualization, Writer)  
Worker Agents → Sandbox Environment (isolated Jupyter kernel, UUID filesystem, package installer)  
Visualization Agent → Reflexive QC Loop (vision model critic)  
Errors (after retries) → Wise Agent (Claude Opus)  
All intermediates → Writer Agent → final report

- **Critical path:**
1. Natural language query → Search Agent (iterative ReAct) → top K datasets.  
2. Metadata harvest → feature flags → Supervisor planning → task decomposition.  
3. Data‑type routing → Worker code generation → sandbox execution.  
4. If error → traceback feedback → self‑correction loop (retry limit → Wise Agent escalation).  
5. For plots → generation → reflexive QC (iterate until threshold).  
6. All artifacts → Writer Agent → final report.

- **Design tradeoffs:**
  - Centralization vs robustness: Supervisor simplifies state but is a single point of failure for misrouting; future work may add validation hooks or distributed consensus.  
  - Determinism vs autonomy: Sandbox enforces code determinism, but upstream LLM reasoning is stochastic, affecting reproducibility of generated code.  
  - Generality vs depth: Five specialists cover broad domains; adding a new domain (e.g., sedimentology) requires updating prompts, routing rules, and metadata features.

- **Failure signatures:**
  - Supervisor misrouting (e.g., gridded array task sent to DataFrame Agent) cannot be corrected downstream.  
  - Hallucinated but syntactically valid code that produces scientifically invalid outputs (e.g., wrong CRS) evades sandbox and visual QC.  
  - Metadata poverty: Sparse/inconsistent metadata leads to low retrieval precision; agentic search helps but cannot overcome the “long‑tail” problem.  
  - Visual QC stall: Critic provides contradictory feedback or agent cannot implement fix after 5 iterations.

- **First 3 experiments:**
  1. End‑to‑end sandbox test: Query a known simple PANGAEA CSV dataset. Verify: retrieval, correct routing to DataFrame Agent, loading, computing mean, basic plot, QC pass, one‑sentence summary. Checks state persistence and routing logic.  
  2. Error‑recovery drill: Replicate Scenario 2 (datetime mismatch). Verify agent encounters `AttributeError`, parses traceback, refactors to use `pd.Timestamp.normalize()`, and re‑executes successfully. Also test Wise Agent escalation by artificially inducing a persistent error.  
  3. Visual QC stress test: Prompt for a multi‑panel figure with overlapping labels. Verify initial plot scores below threshold, critic provides specific feedback (e.g., “legend overlaps axis”), agent applies fix, score improves, loop terminates within ≤5 iterations with score ≥ threshold. Additionally, test with an invalid fix (e.g., non‑existent matplotlib argument) to observe stall behavior.

## Open Questions the Paper Calls Out
- **Domain‑specific validation hooks:** How can independent validation (e.g., CRS consistency checks, unit‑conversion verification) detect and correct Supervisor misrouting? Currently no such layer exists.  
- **Transferability to other repositories:** Does the architecture work for NASA EOSDIS, GBIF, etc., with distinct APIs and metadata schemas? Only PANGAEA has been evaluated.  
- **Integration of domain‑specific foundation models:** Can specialized models (e.g., OceanGPT, GeoGalactica) reduce hallucinations and improve multi‑step reasoning with geoscientific knowledge? The current system uses generic LLMs.  
- **Evaluation circularity:** The benchmark uses an LLM judge (Gemini) for a system driven by another LLM (GPT). Human expert annotation is needed to calibrate scores and identify systematic blind spots.  
- **Asynchronous exploration mode:** What advances are required for agents to autonomously explore archives over extended periods, identify correlations, and generate machine‑actionable metadata without excessive spurious findings? Needs hallucination detection, significance filtering, and validation protocols.

## Limitations
- **Proprietary LLM dependence:** System behavior hinges on inaccessible, versioned models (GPT‑5.2, Claude Opus 4.6), limiting reproducible benchmarking.  
- **Metadata dependency:** Performance degrades with incomplete metadata; Supervisor misrouting is an uncorrectable single‑point failure.  
- **Evaluation scope:** Validation restricted to 4 use‑cases and 100 curated queries; generalizability to other geoscience domains remains unproven.

## Confidence
- **High:** Self‑correction mechanism (5/5 runtime errors resolved). Direct evidence from sandbox traceback parsing logs.  
- **Medium:** Agentic search benchmark superiority (mean score 8.14 vs 5.46/2.87). Scores depend on a non‑deterministic judge (Gemini 3 Pro) and may vary.  
- **Low:** General claim of addressing “underutilization” of archives. No longitudinal study on real‑world adoption or impact.

## Next Checks
1. Metadata introspection stress test: Run on datasets with deliberately corrupted/minimal metadata to quantify Supervisor misrouting rates and identify failure thresholds.  
2. Error recovery consistency trial: Repeat the same error‑prone scenario (e.g., datetime mismatch) 10 times with temperature = 0 to measure variance in self‑correction success and code generation strategies.  
3. Visual QC loop adversarial test: Generate plots with specific rubric violations (e.g., inverted depth axis, overlapping legends) to verify the critic provides actionable feedback within ≤5 iterations and does not stall on contradictory scoring.
