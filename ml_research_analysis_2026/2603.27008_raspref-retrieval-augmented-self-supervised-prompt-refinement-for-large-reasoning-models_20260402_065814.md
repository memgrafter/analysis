# RASPRef: Retrieval-Augmented Self-Supervised Prompt Refinement for Large Reasoning Models
## Quick Facts
- arXiv ID: 2603.27008
- Source URL: https://arxiv.org/abs/2603.27008
- Reference count: 8
- Primary result: Retrieval-augmented prompting achieved 95.0% accuracy on a 500-example GSM8K subset, beating a static prompting baseline of 85.6%.

## Executive Summary
RASPRef introduces an automatic prompt refinement framework for reasoning language models. It leverages a retrieval mechanism over past successful reasoning trajectories and self-supervised evaluation signals—including multi-sample consistency, verifier feedback, and model critiques—to iteratively improve prompts without human annotation or task-specific supervision. On a 500-example subset of GSM8K, the approach yields a 9.4 percentage point gain over static prompting, underscoring the value of retrieved contextual guidance for multi-step reasoning.

## Method Summary
RASPRef operates as an iterative loop. At each iteration, it retrieves a set of high-quality reasoning trajectories from a database built from previously successful model outputs. These trajectories serve as contextual examples to generate or refine a candidate prompt. The candidate is then evaluated using multiple self-supervised signals: consistency across multiple model samples, feedback from an external verifier (e.g., a theorem prover or answer checker), and critiques from the model itself. The best-performing prompt, according to a weighted combination of these signals, is selected and used to update the retrieval database or proceed to the next iteration. No human-labeled data or task-specific supervision is required.

## Key Results
- Achieved 95.0% accuracy on 500-example GSM8K subset vs. 85.6% for static prompting.
- Demonstrated a 9.4% absolute improvement by incorporating retrieved reasoning trajectories.
- Showed that self-supervised signals (consistency, verifier, critiques) effectively guide prompt refinement.

## Why This Works (Mechanism)
Retrieval provides diverse, successful reasoning patterns that the model can emulate, grounding the prompt in concrete, high-quality examples. Self-supervised evaluation offers a no-label training signal: multi-sample consistency identifies robust reasoning steps, verifier feedback ensures correctness, and model critiques highlight potential flaws. The iterative loop allows progressive refinement—each cycle selects prompts that better align with the model’s reasoning tendencies, leading to improved performance without manual intervention.

## Architecture Onboarding
**Component Map**  
Retrieval Database -> Candidate Prompt Generator -> Self-Supervised Evaluator -> Prompt Selector -> (loop back to Retrieval Database update)

**Critical Path**  
1. Retrieve top-k successful reasoning trajectories.  
2. Generate/refine candidate prompt using retrieved context.  
3. Evaluate candidate via multi-sample consistency, verifier, and critique signals.  
4. Select best prompt; update retrieval database if needed.  
5. Repeat until convergence or budget limit.

**Design Tradeoffs**  
- Retrieval diversity vs. relevance: broader set may introduce noise but improve exploration.  
- Number of self-supervised signals: more signals increase robustness but raise computational cost.  
- Iteration depth: more cycles can refine further but with diminishing returns.

**Failure Signatures**  
- Poor retrieval quality leads to degenerate prompts (e.g., overfitting to narrow patterns).  
- Over-reliance on a single self-supervised signal may bias refinement (e.g., consistency alone may reward memorization).  
- Memory leak: retrieval database polluted with low-quality trajectories from early iterations.

**First Experiments**  
1. Vary the retrieval size (k) to measure impact on accuracy and diversity.  
2. Ablate self-supervised signals: remove verifier feedback or critiques to isolate contributions.  
3. Compare RASPRef against both zero-shot prompting and a set of human-engineered prompts of similar length.

## Limitations
- Evaluation confined to a 500-example subset of GSM8K; unknown generalizability to full test set or other tasks.
- Baseline definition (static prompting) is ambiguous, making the reported improvement hard to interpret.
- Implementation details (retrieval database construction, signal weighting, iteration count) are not fully specified, hindering replication.
