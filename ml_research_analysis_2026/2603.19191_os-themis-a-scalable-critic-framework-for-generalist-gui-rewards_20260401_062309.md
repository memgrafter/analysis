# OS-Themis: A Scalable Critic Framework for Generalist GUI Rewards

## Quick Facts
- arXiv ID: 2603.19191
- Source URL: https://arxiv.org/abs/2603.19191
- Reference count: 40
- Primary result: Achieves 10.3% absolute improvement in success rate on AndroidWorld via online RL training.

## Executive Summary
OS-Themis addresses the challenge of providing scalable and precise reward signals for GUI agents in reinforcement learning, where existing methods suffer from contextual loss and evidence dilution. The framework decomposes trajectories into verifiable milestones using a Selector and Verifier agent, then employs a Reviewer and Judge agent to audit the evidence chain and produce robust outcome rewards. Evaluated on the new OmniGUIRewardBench (OGRBench) benchmark, OS-Themis achieves state-of-the-art performance across platforms. In online RL training on AndroidWorld, it yields a 10.3% absolute improvement in success rate, and for trajectory filtering in self-training loops, it provides a 6.9% gain, demonstrating effective data curation for agent self-evolution.

## Method Summary
OS-Themis comprises two modules. The Milestone Verification Module (MVM) uses a Selector Agent to extract key steps from a GUI trajectory as milestones with explicit assessment goals, and a Verifier Agent to locally verify each milestone using before/after screenshots, focusing on state transitions. The Verdict Calibration Module (VCM) employs a Reviewer Agent to critically audit the initial milestone set and verification results, identifying issues like missing checks or lenient criteria, and iteratively refines them. A Judge Agent then synthesizes the full deliberation history (milestone evolution, feedback, etc.) to produce a final binary reward. This collaborative multi-agent workflow distributes cognitive load, enabling focused reasoning on sub-tasks and improving scalability for long-horizon evaluations.

## Key Results
- State-of-the-art performance on OmniGUIRewardBench (OGRBench) across all tested platforms.
- 10.3% absolute improvement in success rate in online RL training on AndroidWorld.
- 6.9% gain in trajectory filtering for self-training loops, enabling more effective data curation for agent self-evolution.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Decomposing trajectories into discrete, verifiable milestones isolates critical signals and mitigates contextual loss from long-horizon evaluations.
- **Mechanism**: The Selector Agent extracts key steps as milestones with explicit assessment goals (e.g., "cursor at top of note"), and the Verifier Agent checks each milestone locally using before/after screenshots, focusing on state transitions rather than holistic trajectory assessment.
- **Core assumption**: GUI tasks can be broken into independently verifiable subgoals, and local evidence is less noisy than global aggregation.
- **Evidence anchors**: Abstract and section 3.2; corpus shows trend toward granular verification methods.
- **Break condition**: If milestone selection is incomplete or assessment goals are vague, leading to missed critical steps or persistent contextual loss.

### Mechanism 2
- **Claim**: The Verdict Calibration Module audits the evidence chain to counteract evidence dilution from trivial successes, yielding robust binary rewards.
- **Mechanism**: The Reviewer Agent critically reviews the initial milestone set and verification results, identifying issues like missing checks or lenient criteria, and iteratively refines the set. The Judge Agent synthesizes the full deliberation history to produce the final reward, weighting process over surface-level outcomes.
- **Core assumption**: Iterative review can uncover outcome-determining failures masked by accumulated minor successes in one-shot judgments.
- **Evidence anchors**: Abstract and section 3.3; limited direct corpus evidence on reward auditing with iterative review.
- **Break condition**: If the Reviewer fails to detect key issues due to bias or if the Judge over-relies on compromised evidence, reintroducing false positives.

### Mechanism 3
- **Claim**: A collaborative multi-agent workflow with specialized roles improves precision and scalability over monolithic judges by distributing cognitive load.
- **Mechanism**: Agents assume distinct functions: Selector (decomposition), Verifier (local verification), Reviewer (critical audit), Judge (final synthesis). This division enables focused reasoning, reduces individual agent burden, and supports iterative refinement.
- **Core assumption**: Specialization in sub-tasks of trajectory evaluation enhances accuracy and handles long-horizon complexity better than a single generalist model.
- **Evidence anchors**: Abstract and section 3.1; multi-agent frameworks in GUI use decomposition; OS-Themis extends with audit loop for reward robustness.
- **Break condition**: Poor inter-agent coordination, ambiguous role boundaries, or cascading errors from one agent degrading downstream judgments.

## Architecture Onboarding
**Component map**: GUI Trajectory -> Selector Agent -> Verifier Agent -> Reviewer Agent (iterative refinement) -> Judge Agent -> Binary Reward

**Critical path**: The trajectory is first processed by the Selector to generate initial milestones with assessment goals. The Verifier then checks each milestone locally. The Reviewer audits the milestone set and verification results, providing feedback that may trigger additional iterations between MVM and VCM. Once converged, the Judge synthesizes the entire deliberation history to output the final binary reward.

**Design tradeoffs**:
- Precision vs. recall: Framework prioritizes precision to avoid false positives in RL, tolerating moderate recall loss.
- Latency vs. accuracy: Multi-agent calls increase evaluation time (~117s/trajectory) but improve reward reliability.
- Scalability: Decomposition handles long trajectories; test-time voting strategies allow precision-recall tuning.

**Failure signatures**:
- High false positive rate in validation rewards, causing policy degradation.
- Reviewer consistently missing issues (e.g., case mismatches, unsaved states), leading to over-optimistic judgments.
- Judge producing "uncertain" verdicts frequently due to conflicting or missing verifier evidence.
- Milestone selection skewed toward trivial steps, failing to capture outcome-critical transitions.

**First 3 experiments**:
1. Run OS-Themis on one OGRBench trajectory with Qwen3-VL-8B, logging each agent's output to understand the workflow.
2. Compare full OS-Themis against variants removing Selector or Reviewer on a small dataset; observe precision drops.
3. Evaluate the same trajectory using DigiRL and ZeroGUI; note differences in selected steps and final reward to appreciate contextual loss and evidence dilution issues.

## Open Questions the Paper Calls Out
The paper does not explicitly identify open questions. However, based on the limitations and future work discussed, potential open questions include improving the computational efficiency of the multi-agent pipeline for high-throughput RL, and enhancing robustness to inter-agent miscommunication or cascading errors.

## Limitations
- Benchmark Generalization: OGRBench's task distribution and diversity relative to real-world GUI complexity are unclear; advantages may not generalize beyond curated scenarios.
- Multi-Agent Robustness: Reliance on coherent inter-agent communication is a vulnerability; failure modes from miscoordination or cascading errors are not deeply analyzed.
- Scalability in Practice: The 117s/trajectory latency is high for high-throughput RL pipelines; trade-off between scalability and computational cost needs empirical validation.

## Confidence
- **Mechanism 1 (Milestone Decomposition): High**. Strong empirical support from state-of-the-art results on OGRBench and AndroidWorld, and thorough ablation studies in section 3.2 demonstrate the effectiveness of milestone-based verification.
- **Mechanism 2 (Verdict Calibration): Medium**. The paper shows overall gains from the VCM, but limited direct evidence isolates its contribution; the iterative review process is novel but not extensively validated.
- **Mechanism 3 (Multi-Agent Workflow): Medium**. While multi-agent specialization improves scalability, the paper acknowledges potential failure modes from inter-agent coordination and does not provide comprehensive robustness analysis.
