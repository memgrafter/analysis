# Beyond Closed-Pool Video Retrieval: A Benchmark and Agent Framework for Real-World Video Search and Moment Localization

## Quick Facts
- **ArXiv ID**: 2602.10159  
- **Source URL**: https://arxiv.org/abs/2602.10159  
- **Reference count**: 40  
- **Primary result**: RVMS-Bench and RACLO reveal that state-of-the-art MLLMs perform poorly on real-world video retrieval, with top retrieval recall 57.0% and moment localization 38.9%.

## Executive Summary
This paper addresses the disconnect between idealized video retrieval benchmarks and real-world open-web search scenarios, where users rely on fuzzy, multi-dimensional memory cues. The authors introduce RVMS-Bench, a benchmark of 1,440 human-verified samples spanning 20 categories and four duration groups, annotated with a hierarchical description (Global Impression, Key Moment, Temporal Context, Auditory Memory). They also propose RACLO, an agent framework that simulates the human "Recall-Search-Verify" cognitive process through abductive reasoning: fragmented cues are transformed into search queries, candidate videos are retrieved, and parallel video-level and frame-level verification localizes relevant moments. Evaluation of Gemini-3-Pro and GPT-5.2 shows insufficient capabilities, with best retrieval recall of 57.0% and moment localization accuracy of 38.9% under the Model+Rule setting. Performance degrades significantly on longer videos and unstructured content, highlighting key challenges for future multimodal video understanding.

## Method Summary
RVMS-Bench construction involved collecting open-web videos and annotating them using a four-level hierarchical framework: Global Impression (G) summarizes the entire video; Key Moment (K) identifies the most memorable segment; Temporal Context (T) specifies the time relation of K; Auditory Memory (A) captures distinctive sounds. This structure emulates how humans recall video memories. The RACLO agent operates in three stages: **Recall** – an MLLM performs abductive reasoning on the input cues to generate diverse search queries; **Search** – these queries retrieve candidate videos from a web-scale index; **Verify** – parallel MLLM-based modules assess video-level consistency against G and frame-level alignment with K/T. The final output is a ranked set of localized moments. The framework aims to handle fragmented cue inputs (e.g., K+T without G), though the verification step currently depends on G for binary classification.

## Key Results
- Best retrieval recall: **57.0%** (Gemini-3-Pro, Model+Rule setting, tasks with Global Impression).  
- Best moment localization accuracy: **38.9%** (GPT-5.2).  
- Performance degrades with video duration (>30 minutes) and in unstructured categories (Variety Shows, Lifestyle Vlogs).

## Why This Works (Mechanism)
RACLO works by emulating human memory search: abductive reasoning bridges the gap between fragmented, fuzzy cues and concrete search queries, enabling retrieval from open-web video collections. The parallel verification leverages both global semantic consistency (via Global Impression) and fine-grained temporal alignment (via Key Moment and Temporal Context) to filter false positives and localize precise moments. This two-tier verification mimics human "gut feeling" and detailed scrutiny, improving robustness compared to direct end-to-end model prediction. The hierarchical cue representation allows the system to operate even with partial information, though the current implementation requires Global Impression for definitive verification.

## Foundational Learning
- **Abductive Reasoning**: Inferences from incomplete cues to generate plausible hypotheses (search queries). *Why needed*: Real-world memories are fragmented; abductive reasoning fills gaps. *Quick check*: Does the generated query set cover plausible variations?
- **Hierarchical Memory Description**: Decomposes video memory into four dimensions (G, K, T, A). *Why needed*: Captures multi-aspect human recall; enables modular processing. *Quick check*: Are all four aspects consistently annotated across samples?
- **Video Moment Localization**: Pinpointing exact timestamps within videos that match a query. *Why needed*: Real-world search often aims at specific segments, not entire videos. *Quick check*: Evaluation metrics (e.g., mRecall@s) measure temporal precision.
- **Open-Domain Video Retrieval**: Searching videos from an unconstrained pool (the open web) rather than a fixed dataset. *Why needed*: Reflects actual user scenarios where videos are not pre-indexed. *Quick check*: Does the benchmark include diverse, web-sourced videos?
- **Parallel Verification**: Simultaneous video-level and frame-level consistency checks. *Why needed*: Balances coarse relevance and fine-grained alignment; reduces false positives. *Quick check*: Compare performance when using one vs. both verifiers.

## Architecture Onboarding
**Component Map**:  
Memory cues (G, K, T, A) → Abductive Query Expansion (MLLM) → Video Search Engine → Parallel Verification: (Video-level Verifier using G) and (Frame-level Verifier using K/T) → Fusion/Decision → Localized Moment Output.  
*(Note: Verification strictly requires G for binary classification; tasks without G are not fully supported.)*

**Critical Path**: Input cues are processed by the abductive reasoning module to generate multiple search queries. These queries retrieve a candidate set of videos. Each candidate is evaluated by the video-level verifier against G to filter irrelevant videos. Surviving videos are passed to the frame-level verifier, which scans frames to locate moments matching K and T. The final output combines scores from both verifiers to produce ranked moment proposals.

**Design Tradeoffs**: RACLO prioritizes interpretability and cognitive plausibility over end-to-end efficiency. The reliance on G for verification ensures a clear decision boundary but excludes tasks lacking G. Parallel verification improves accuracy but increases computational cost. The abductive query expansion is flexible but sensitive to prompt engineering and MLLM biases.

**Failure Signatures**:  
- Query reasoning errors: misgenerated search queries leading to zero retrieval.  
- Verification failure: when G is absent, the system cannot perform binary classification, causing tasks to be skipped.  
- Degradation on long videos: due to context window limits or attention inefficiency in MLLMs.  
- Poor performance on unstructured content: rapid cuts and background noise confuse retrieval and localization.

**First Experiments**:  
1. **Full Benchmark Evaluation**: Run RACLO on all 1,440 RVMS-Bench tasks, reporting retrieval recall and localization accuracy overall and by cue combination, duration, and content category.  
2. **Ablation of Abductive Reasoning**: Replace the abductive query expansion with a rule-based keyword extractor from the cue text; compare performance to quantify the contribution of reasoning.  
3. **Verification Module Analysis**: Disable video-level or frame-level verification individually to measure their separate contributions, and test alternative fusion strategies.

## Open Questions the Paper Calls Out
1. **Verification without Global Impression**: How can we design an effective video verification mechanism for queries that lack Global Impression (G) cues? *Basis*: RACLO’s verification module is logically strictly dependent on G; tasks without G are excluded from evaluation, leaving a significant portion unevaluated. *Why unresolved*: No alternative strategies explored; limits assessment of real-world memory search across all cue combinations. *What evidence would resolve*: Develop verification using other cues (K, T, A) via multi-cue consistency or learned thresholds; validate on non-G tasks.

2. **Retrieval-Localization Gap in Open-Source MLLMs**: Why do state-of-the-art open-source MLLMs (e.g., Qwen3-VL-235B) show a large disparity between retrieval performance (36.6%) and moment localization accuracy (4.0%)? *Basis*: Strong retrieval via image-text alignment but dramatic drop in localization indicates a bottleneck in mapping fuzzy cues to timestamps. *Why unresolved*: Root cause unclear—could be temporal resolution, audio-visual sync, or training data. *What evidence would resolve*: Ablation studies on frame sampling density, temporal attention mechanisms, and audio cues; error analysis of localization failures.

3. **Robustness to Long Videos and Unstructured Content**: What architectural or training modifications can improve model robustness on long-duration videos (>30 minutes) and unstructured content categories (e.g., Variety Shows, Lifestyle Vlogs)? *Basis*: All models show downward trend with duration; open-source models suffer more; performance fluctuates in loosely structured, high-noise categories. *Why unresolved*: Specific limitations in long-context processing and high-entropy visual streams not analyzed. *What evidence would resolve*: Compare long-video techniques (hierarchical transformers, memory-augmented networks) on RVMS-Bench; probe internal representations for long-range dependencies.

4. **Improving Abductive Query Expansion**: Can the abductive query expansion step be improved beyond hand-crafted prompts? *Basis*: RACLO uses a fixed CoT prompt; failure analysis shows query reasoning errors when MLLM misinterprets input. *Why unresolved*: Static approach may not generalize across diverse topics and fuzzy descriptions; no investigation into few-shot, iterative, or supervised methods. *What evidence would resolve*: Design alternative strategies (rule-based extraction, few-shot prompting, trained query generator); evaluate retrieval recall, precision, and human relevance.

## Limitations
- **Benchmark Scope & Generalizability**: RVMS-Bench’s 1,440 samples may not capture full diversity of real-world open-web searches; inter-annotator agreement for hierarchical annotations is unreported.
- **Transparency & Reproducibility**: RACLO’s implementation details (prompts, LLM settings) are unspecified; computational cost of parallel verification and failure modes are not analyzed.
- **Evaluation Limitations**: Testing only on two proprietary MLLMs; no cross-dataset validation; Model+Rule setting’s rule-based components are unclear, hindering reproducibility.
