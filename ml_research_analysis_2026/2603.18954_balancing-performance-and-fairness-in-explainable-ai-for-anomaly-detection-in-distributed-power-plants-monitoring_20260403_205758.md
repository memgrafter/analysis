# Balancing Performance and Fairness in Explainable AI for Anomaly Detection in Distributed Power Plants Monitoring

## Quick Facts
- **arXiv ID:** 2603.18954
- **Source URL:** https://arxiv.org/abs/2603.18954
- **Reference count:** 29
- **Primary result:** LightGBM achieves F1-score 0.99 and Disparate Impact Ratio ~0.95, with SHAP identifying actionable predictors (fuel consumption rate, runtime per day) for real-time deployment.

## Executive Summary
This study tackles anomaly detection in distributed diesel generator monitoring, addressing extreme class imbalance, lack of interpretability, and regional fairness issues. The proposed supervised machine learning framework integrates ensemble models (LightGBM, XGBoost) with advanced resampling (SMOTE with Tomek Links/ENN) to balance data and improve recall. Key outcomes include near-perfect F1-score (0.99), equitable regional performance (DIR ~0.95), and operator-friendly explanations via SHAP. The framework is containerized for low-latency inference, demonstrating a practical path for deployable, fair, and interpretable industrial anomaly detection.

## Method Summary
The research uses a proprietary dataset of 8,479 generator telemetry samples from 24 regional clusters in Cameroon (2017–2018). Features include raw metrics (fuel, runtime) and engineered ones (consumption rate, runtime per day). To handle severe class imbalance (normal >85%), SMOTE is combined with Tomek Links or Edited Nearest Neighbors (ENN) **only on training data**. Multiple classifiers (LR, SVM, KNN, MLP, ensembles like LightGBM, XGBoost, CatBoost, RF) are evaluated under two strategies: a single global model and cluster-specific models. Hyperparameters are tuned via grid search. Performance is measured by F1-score, precision, recall, AUC-ROC; fairness by Disparate Impact Ratio (DIR) across clusters; and generalization by Maximum Mean Discrepancy (MMD). SHAP values provide post-hoc interpretability.

## Key Results
- LightGBM achieves an F1-score of 0.99, with ensemble models consistently outperforming baselines.
- Disparate Impact Ratio (DIR) averages ~0.95 across clusters, indicating minimal regional bias (fair zone: 0.8–1.25).
- SHAP analysis identifies `fuel consumption rate` and `runtime per day` as dominant, actionable predictors for anomaly classification.
- Containerized deployment yields low-latency inference (<0.001s), supporting real-time monitoring.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Ensemble learning combined with advanced resampling (SMOTE with Tomek Links/ENN) mitigates extreme class imbalance, enabling high anomaly detection recall without excessive false positives.  
**Mechanism:** SMOTE synthetically oversamples minority anomaly classes, while Tomek Links/ENN remove overlapping or noisy samples from the majority class, creating a balanced, cleaner training distribution. Ensemble models (LightGBM, XGBoost) then aggregate multiple weak learners to learn robust decision boundaries, reducing variance and overfitting to the majority class.  
**Core assumption:** Synthetic samples approximate the true minority distribution, and removal of ambiguous samples does not discard critical signal.  
**Evidence anchors:** [abstract]: "integrates ensemble methods [...] with advanced resampling techniques (SMOTE with Tomek Links and ENN) to address imbalance." [section 3.4.1]: describes the workflow where "data balancing on the training data is achieved using SMOTE with ENN or Tomek Links" and ensemble models are selected for handling imbalanced/noisy data.  
**Break condition:** If SMOTE-generated artifacts create unrealistic feature combinations that do not reflect real generator anomalies, model performance on unseen majority-class patterns may degrade, or fairness metrics (DIR) may worsen due to synthetic bias.

### Mechanism 2
**Claim:** SHAP transforms black-box ensemble predictions into operator-understandable feature attributions, enabling actionable maintenance decisions.  
**Mechanism:** SHAP computes Shapley values from game theory to assign each feature a contribution score for a given prediction. For each anomaly classification, it shows how much features like `runtime per day` or `consumption rate` pushed the prediction toward "anomaly" versus "normal."  
**Core assumption:** Shapley values provide a locally accurate and consistent explanation, and operators can reliably map these contributions to physical causes (e.g., high `runtime per day` → mechanical fault).  
**Evidence anchors:** [abstract]: "Interpretability is achieved through SHAP [...] SHAP analysis highlights fuel consumption rate and runtime per day as dominant predictors, providing actionable insights." [section 3.6]: defines the SHAP value formula and states it "empowers operators to pinpoint root causes." [Figures 13-16]: show SHAP summary plots where `runtime per day` consistently has the highest mean absolute SHAP value across models and clusters.  
**Break condition:** If the model's learned correlations are spurious (e.g., due to data leakage or unmeasured confounders), SHAP will faithfully explain a flawed model, leading operators to incorrect root-cause conclusions.

### Mechanism 3
**Claim:** The Disparate Impact Ratio (DIR) quantifies and helps monitor regional fairness, ensuring anomaly detection does not systematically disadvantage specific operational clusters.  
**Mechanism:** DIR is calculated as the ratio of the anomaly detection rate for a designated "minority" cluster to the average detection rate for "majority" clusters. A DIR near 1.0 indicates equitable performance. The framework evaluates DIR for all clusters, flagging values outside the fair zone (0.8–1.25).  
**Core assumption:** A cluster's operational characteristics (climate, usage) are legitimate factors for model adaptation, and fairness requires similar true positive rates *given* those characteristics, not identical absolute rates.  
**Evidence anchors:** [abstract]: "fairness is quantified using the Disparate Impact Ratio (DIR) across operational clusters." [section 3.5]: defines DIR formula and states it "ensures equitable detection across clusters." [Figures 17-20]: present DIR calculations for minority clusters (BANYO, NGAOUNDERE 2, MAKARY), showing ensemble models generally fall within the fair zone.  
**Break condition:** If cluster labels are proxies for unmeasured operational variables (e.g., maintenance quality) rather than neutral geography, enforcing DIR equality could force the model to ignore legitimate signal, reducing overall performance (F1-score).

## Foundational Learning
- **Concept: Supervised Imbalanced Classification**  
  Why needed: Anomalies are rare (<15%), so models must learn from skewed data to avoid trivial "normal" predictions.  
  Quick check: Why might accuracy be misleading here, and which metric better captures detection of rare anomalies?
- **Concept: Ensemble Methods (Gradient Boosting)**  
  Why needed: Combines weak learners to handle complex, noisy industrial data better than single models (e.g., SVM, LR).  
  Quick check: How does boosting differ from bagging (e.g., Random Forest) in handling class imbalance, and why might boosting be preferred?
- **Concept: Post-Hoc Explainability (SHAP)**  
  Why needed: Operators need to understand *why* an anomaly was flagged to trust the system and act on root causes.  
  Quick check: What is the key difference between SHAP and permutation importance in terms of explanation granularity?
- **Concept: Fairness Metrics (DIR)**  
  Why needed: Models may perform well globally but poorly for specific regions, leading to biased maintenance allocation. DIR quantifies this disparity.  
  Quick check: Does a DIR of 0.95 for a cluster indicate the model is *more* or *less* likely to detect anomalies there compared to average?
- **Concept: Domain Shift & MMD**  
  Why needed: Operational patterns differ across clusters; a model trained on one may fail in another. MMD measures distributional difference to anticipate generalization gaps.  
  Quick check: What does a high MMD value between training and test clusters suggest about expected model performance?

## Architecture Onboarding
### Component Map
Data Ingestion & Storage -> Preprocessing Service -> Model Training Pipeline -> Evaluation & Monitoring Module -> Explainability Engine -> Deployment Service -> Operator Dashboard

### Critical Path
For real-time inference: Telemetry -> Preprocessing (feature engineering) -> Model Prediction -> SHAP Calculation -> Alert & Dashboard Update. Target latency <0.001s.

### Design Tradeoffs
- **Global vs. Cluster-Specific Models:** Global models simplify maintenance but may underperform on outlier clusters; cluster-specific models adapt better but require more storage/retraining.
- **Precompute vs. Real-time SHAP:** Precomputing SHAP for common scenarios reduces latency but lacks per-prediction granularity; real-time SHAP is flexible but adds compute overhead.
- **Fairness Intervention:** Adjusting decision thresholds per cluster to improve DIR may reduce overall F1-score; tradeoff must be quantified.

### Failure Signatures
- **Performance drop:** F1-score on a cluster's test set falls >10% below global average; check for concept drift or inadequate cluster-specific data.
- **High MMD (>0.1) between train/test clusters:** Indicates severe domain shift; consider cluster-specific model or domain adaptation.
- **DIR outside [0.8, 1.25] for a cluster:** Systematic bias; investigate data representation or model calibration for that cluster.
- **SHAP inconsistency:** Top feature (`runtime per day`) has low SHAP value for a cluster where domain knowledge says it should be critical; suspect data quality or model misfit.

## Open Questions the Paper Calls Out
1. **How does the anomaly detection framework generalize to diverse geographic regions and multi-year operational data beyond the single-year Cameroon dataset?** The dataset spans a single year and limited clusters, restricting generalization to broader contexts. Future work will explore larger and more diverse datasets, multi-year deployments, and cross-region validation.
2. **What fairness-aware training objectives (e.g., adversarial debiasing, fairness constraints) can be integrated during model training to achieve equitable regional anomaly detection without sacrificing performance?** The fairness evaluation uses DIR post-hoc, with some clusters showing bias (e.g., NGAOUNDERE 2 DIR <0.8). Future work will explore fairness-aware training objectives to improve equitable performance.
3. **Can hybrid deep learning models (e.g., LSTM-based sequence models combined with gradient boosting) improve temporal anomaly detection in streaming generator data compared to static feature-engineered ensembles?** Current deployment considerations focus on batch and streaming anomaly detection, but hybrid deep learning approaches may further enhance temporal modeling. Future work will investigate such architectures.

## Limitations
- The proprietary TeleInfra dataset prevents external replication and limits generalizability beyond the studied context.
- Exact hyperparameter grids and final tuned values for each model are not disclosed, hindering precise reproduction.
- Fairness analysis assumes geographic clusters are neutral proxies; unmeasured confounders (e.g., maintenance quality) may invalidate DIR as a bias measure.
- Real-time deployment claims (<0.001s latency) lack stress-testing details, hardware specifications, and SHAP compute overhead quantification.

## Confidence
- **Performance (F1=0.99):** Medium. Results are internally consistent but vulnerable to overfitting from resampling; no independent verification.
- **Fairness (DIR~0.95):** Medium. DIR values are presented, but cluster labels may be proxies for confounders; fairness could be accidental rather than engineered.
- **Explainability (SHAP feature dominance):** Medium. SHAP is mathematically sound, but mapping to actionable root causes remains subjective and domain-specific.
- **Deployment (low-latency):** Low. Single-point measurement without load testing or reproducible environment; SHAP compute overhead unquantified.

## Next Checks
1. **Cross-dataset replication:** Implement the full pipeline (SMOTE+ENN, LightGBM, SHAP) on a public imbalanced anomaly dataset (e.g., NAB, SMD). Verify F1 >0.95 and consistency of top SHAP features with known anomaly drivers.
2. **Confounder audit for fairness:** If auxiliary data (generator age, maintenance records) become accessible, test whether cluster membership predicts these factors. Recompute DIR after adjusting for confounders; significant change would undermine fairness claims.
3. **Latency stress test:** Deploy the containerized model with and without SHAP under increasing query loads (1–100 req/s). Measure p99 latency and resource usage; a >10x slowdown with SHAP enabled would challenge real-time feasibility.
