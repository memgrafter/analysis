# CapNav: Benchmarking Vision Language Models on Capability-conditioned Indoor Navigation

## Quick Facts
*   **arXiv ID:** 2602.18424
*   **Source URL:** https://arxiv.org/abs/2602.18424
*   **Reference Count:** 40
*   **Primary Result:** CapNav reveals systematic VLM performance degradation with tighter mobility constraints, with top models (Gemini-2.5-pro) approaching but not surpassing average human performance (0.67 vs. 0.61).

## Executive Summary
CapNav is a new benchmark for evaluating vision-language models (VLMs) on indoor navigation tasks conditioned on the physical capabilities of an agent (e.g., humanoid, wheelchair). It uses 45 real-world 3D scenes, 473 tasks, and 5,075 per-edge traversability annotations to test if models can predict feasible paths and reason about physical constraints. Evaluation of 13 VLMs shows performance drops sharply for constrained agents, with key failure modes being path hallucination (44%) and dimension neglect (13%)—the inability to reason about precise spatial metrics like narrow passage widths. While more visual input helps stronger models, it reveals a visual integration bottleneck.results indicate current VLMs lack a grounded internal model of embodiment, limiting their utility for real-world assistive or robotic navigation.

## Method Summary
The benchmark uses a passive, video-based setup to isolate spatial reasoning from exploration policy. For each task, a VLM is given: (1) a uniformly-sampled set of frames from a touring video of an indoor scene, (2) a human-annotated navigation graph (nodes=rooms, edges=walkable connections), (3) a natural-language question (e.g., "from kitchen to bedroom"), and (4) an agent profile (physical dimensions & capabilities). The model must output a JSON with a feasibility judgment, a path (node sequence), and a reason. Evaluation uses four metrics against ground-truth traversability labels: Feasibility F1, Path Validity (PV), Route Traversability Accuracy (RTA), and Reasoning Validity (RV). These are equally weighted into a composite CapNav score.

## Key Results
*   Performance degrades systematically with tighter mobility constraints; the humanoid agent's score (39.12%) is far below the unconstrained human (57.83%).
*   Top proprietary models (Gemini-2.5-pro) approach but do not surpass average human performance (CapNav 0.67 vs. 0.61).
*   Primary failure modes are path hallucination (44% of errors) and dimension neglect (13%), especially for narrow passages and tight turns.

## Why This Works (Mechanism)
### Mechanism 1: Lack of Embodiment Grounding
*   **Claim:** VLM navigation performance degrades with tighter mobility constraints because models are not trained to ground spatial reasoning in physically grounded embodiment constraints.
*   **Mechanism:** Pre-trained on web data, VLMs lack exposure to diverse physical forms and their affordances. They default to human-centric reasoning, failing to adjust feasibility judgments for non-human profiles (e.g., wheelchair), leading to path proposals that violate dimensional or capability limits.
*   **Evidence Anchors:**
    *   Performance gap: humanoid (39.12%) vs. human (57.83%).
    *   Systematic deficit across all tested models as constraints tighten.
    *   Failure signatures include ignoring stated profile capabilities.
*   **Break Condition:** If constrained-agent performance was statistically indistinguishable from the unconstrained human baseline.

### Mechanism 2: Visual Integration Bottleneck
*   **Claim:** Increasing visual input does not uniformly improve performance because VLMs struggle to synthesize spatial information across multiple, discontinuous viewpoints.
*   **Mechanism:** Passive navigation requires integrating egocentric video frames into a coherent topological/metric scene model. VLM architectures are optimized for single-image or short-sequence tasks, so their perception modules fail at long-range spatial correspondence. More frames provide more evidence but exceed the model's fusion capacity, causing saturation or degradation, especially in weaker models.
*   **Evidence Anchors:**
    *   Frame-sensitivity curves show uneven benefits: strong models gain, weak models plateau or degrade.
    *   Qualitative analysis: weak models lack robust cross-frame integration; extra frames can increase obstacle hallucinations.
*   **Break Condition:** If performance improved monotonically and significantly with increased frame budget for all model capacities.

### Mechanism 3: Dimension Neglect
*   **Claim:** VLMs fail at precise metric reasoning on spatial constraints (narrow passages, turning radii) despite handling binary qualitative obstacles (stairs) adequately.
*   **Mechanism:** Visual-semantic alignment is coarse-grained, sufficient for identifying object categories and symbolic affordances (blocking), but insufficient for estimating continuous quantities. This forces reliance on heuristics ("a hallway is wide enough") rather than metric verification from the scene.
*   **Evidence Anchors:**
    *   All models perform markedly better on salient obstacles (stairs) than on metric obstacles (narrow clearances).
    *   13% of failures explicitly cite missed geometric constraints.
*   **Break Condition:** If models achieved parity in accuracy between salient and metric obstacle types.

## Foundational Learning
*   **Vision-Language Models (VLMs) & Embodied AI**
    *   **Why needed:** CapNav evaluates off-the-shelf VLMs in a passive navigation framework. Understanding that typical VLM training lacks an "agent body" concept is key to interpreting failures on capability conditioning.
    *   **Quick Check:** What is the difference between a VLM's typical "visual grounding" task and the "spatial reasoning with physical constraints" task in CapNav?
*   **Graph-Based Navigation Abstraction (NavGraphs)**
    *   **Why needed:** The benchmark uses a pre-constructed, human-annotated navigation graph. The VLM reasons *about* this graph from video, not *discover* it. This abstracts away perception of connectivity but isolates spatial-logical reasoning.
    *   **Quick Check:** How does representing a 3D space as a connectivity graph simplify the task, and what critical information might be lost for a capability-aware task?
*   **Embodiment-Specific Affordances & Constraint Modeling**
    *   **Why needed:** The core of CapNav is the agent profile (dimensions, capabilities). Interpreting results requires understanding how a constraint like "width=0.9m" translates to a traversability decision on a graph edge labeled "narrow passage."
    *   **Quick Check:** For a "wheelchair" profile, list three environmental features that could make a graph edge non-traversable and the physical reason for each.

## Architecture Onboarding
*   **Component Map:**
    Scene Data (3D scans -> touring video + graph) -> Task Engine (VLM generates tasks) -> Traversability Annotation Layer (human labels per-agent edge feasibility) -> Evaluation Harness (queries target VLM, parses JSON, compares to ground truth).
*   **Critical Path:**
    1.  **Data Curation:** Select scene -> record tour video -> manually annotate navigation graph -> generate/verify tasks -> **per-agent, per-task traversability annotation** (most labor-intensive).
    2.  **Model Evaluation Loop:** For each (scene, task, agent) triplet: construct prompt (video frames, node list, question, profile) -> query VLM -> parse JSON (`answer`, `path`, `reason`) -> lookup ground-truth edge labels -> compute metrics.
*   **Design Tradeoffs:**
    *   **Passive vs. Interactive:** Passive video isolates spatial reasoning from exploration policy noise but cannot evaluate online decision-making or recovery.
    *   **Graph Ground Truth:** Using a clean, human-annotated graph provides perfect topology but removes the challenge of *perceiving* connectivity from raw pixels.
    *   **LLM-as-Judge:** Scalable reasoning evaluation but introduces judge bias; validated with 300 human samples (89% agreement).
*   **Failure Signatures:**
    *   **Path Hallucination (44%):** Predicted path includes non-adjacent nodes or wrong start/end.
    *   **Obstacle Hallucination (13%):** Cites a blocking obstacle that does not exist.
    *   **Dimension Neglect (13%):** Fails to detect narrow passages/tight turns for a wide agent.
    *   **Ability Hallucination (rare):** Reasoning contradicts the agent profile (e.g., "wheelchair can climb stairs").
*   **First 3 Experiments:**
    1.  **Baseline Establishment:** Run all 13 VLMs on full test set (default frames, no thinking). Report composite CapNav score and per-agent scores. Confirm all beat random walk (0.29) but most are below human avg (0.61).
    2.  **Frame Budget Sensitivity:** For a strong (Gemini-2.5-pro) and weak (Intern-VL3.5-8B) model, evaluate across frame settings (16, 32, 64, 1 FPS). Plot CapNav score vs. frame count to visualize the "visual bottleneck."
    3.  **Obstacle-Type Failure Analysis:** For a representative model (e.g., Doubao-Seed), select tasks where ground truth infeasibility is due to one of four annotated obstacle types (stairs, sill, narrow path, turning space). Calculate accuracy in predicting infeasibility AND providing a correct reason per type.

## Open Questions the Paper Calls Out
1.  How can VLMs be trained to jointly optimize obstacle awareness and dimension reasoning without increasing false positives? Fine-tuning reduces dimension neglect but may shift errors toward overly aggressive obstacle judgments.
2.  What architectural modifications or training paradigms can overcome the visual integration bottleneck where additional frames do not consistently improve performance, especially for smaller models?
3.  Can spatial information injection (depth estimates, topological priors, or map-like intermediate representations) reliably improve dimension reasoning for narrow passages and turning radii, and which representation type is most effective?
4.  Will RL-based tuning with task-level rewards under embodiment constraints significantly improve beyond supervised fine-tuning, and what reward structures best encode mobility constraints?
5.  How does the graph abstraction limit evaluation of real-world navigation, and can benchmarks capture more continuous, viewpoint-dependent traversability that current graph-based approaches miss?

## Limitations
*   **Unknown frame sampling:** Exact method for video frame extraction (linear vs. keyframe) is unspecified, potentially affecting performance comparisons.
*   **LLM judge ambiguity:** The reasoning evaluation model's specifics and susceptibility to prompt bias are not fully documented, though human validation (89% agreement) provides partial reassurance.
*   **Graph abstraction limits:** The pre-annotated graph removes the challenge of perceiving connectivity from raw pixels, and the passive format prevents testing active exploration or recovery.
*   **Generalizability:** Results may not transfer to interactive embodied agents or continuous action spaces, as CapNav evaluates planning over a fixed graph rather than execution.

## Next Checks
1.  **Test embodiment fine-tuning:** Fine-tune a base VLM (e.g., Qwen-VL) on data explicitly linking agent profiles to geometric constraints. Measure if the humanoid–human performance gap narrows significantly.
2.  **Probe multi-view fusion limits:** Ablate frame sequence order: compare performance on coherent touring videos vs. scrambled frame orders. A large drop on scrambled inputs confirms dependence on cross-view integration.
3.  **Controlled metric reasoning experiment:** Generate synthetic tasks with parametrically varied passage widths (0.8m–1.4m) against a fixed agent width (0.9m). Plot accuracy vs. width ratio to quantify dimensional estimation precision and compare to human curves.
