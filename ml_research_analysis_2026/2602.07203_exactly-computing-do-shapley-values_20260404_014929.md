# Exactly Computing do-Shapley Values

## Quick Facts
- arXiv ID: 2602.07203
- Source URL: https://arxiv.org/abs/2602.07203
- Reference count: 40
- Primary result: Exact do-Shapley computation reduces to O(r(d+e)) via irreducible sets; boundary sampler achieves machine precision with m≥r; non-parametric identifiability requires only d singleton checks.

## Executive Summary
The paper tackles the exponential complexity of computing do-Shapley values for Structural Causal Models (SCMs). By reformulating do-Shapley in terms of irreducible sets, they partition the space of coalitions into equivalence classes, enabling exact computation in time linear in the number of classes r. For limited query budgets, they propose a boundary sampler that efficiently discovers distinct classes and leverages simulated sampling to produce accurate estimates, achieving orders-of-magnitude lower error than agnostic baselines and exact results when the budget matches r. Additionally, they prove that verifying non-parametric identifiability of all do-Shapley values requires only checking singleton interventions, reducing the number of ID algorithm calls from 2^d to d. Experiments on real-world graphs show r is often much smaller than 2^d, highlighting the practical benefits.

## Method Summary
The core methodological contributions are threefold. First, they define the basis (S⁻) and closure (S⁺) of a coalition S, showing that all subsets between them have identical interventional value. This partitions the power set into r irreducible sets (closed sets), and the Shapley sum becomes a weighted linear combination over these classes. Second, they give an algorithm to enumerate all closed sets via lattice exploration, allowing exact computation of do-Shapley values in O(r(d+e)) time (plus T per value query). Third, for a fixed query budget m, they design a boundary sampler that systematically explores the lattice of closed sets using a priority queue and neighbor expansion, guaranteeing discovery of min(m, r) distinct classes. After querying these classes, they use a simulated sampler to generate many coalitions within the discovered sub-lattice and feed them to a base estimator (e.g., RegressionMSR) for variance-reduced estimation. Finally, they establish that non-parametric identifiability of all do-Shapley values follows from identifiability of only the singleton interventions, drastically simplifying the identifiability check.

## Key Results
- Exact do-Shapley computation reduces from exponential to O(r(d+e)) time, where r (≤ 2^d) is the number of irreducible sets.
- For a query budget m, the boundary sampler discovers min(m, r) distinct equivalence classes; it reduces relative MSE by orders of magnitude versus agnostic baselines as m → r, and achieves machine precision when m ≥ r.
- Non-parametric identifiability of all do-Shapley values requires only checking the d singleton coalition interventions, rather than all 2^d classes.

## Why This Works (Mechanism)

### Mechanism 1: Exact Computation via Irreducible Sets
**Claim:** By grouping coalitions into equivalence classes based on causal structure, exact do-Shapley computation reduces from O(2^d) to O(r(d+e+T)), where r (≤ 2^d) is the number of irreducible sets.  
**Mechanism:** For any coalition S, the *basis* S⁻ is the subset of nodes with open causal paths to Y within S; the *closure* S⁺ includes all nodes that S blocks. Every coalition between S⁻ and S⁺ yields the same interventional value ν(S). This partitions the powerset into r classes; the Shapley sum becomes ϕ_i = ∑_{j=1}^r ν(c_j) w_i(c_j), with weights w_i(c) computed in O(d) from basis/closure sizes.  
**Core assumption:** The value function ν(S) depends only on which variables have active paths to Y; intervening on "redundant" variables does not change the outcome.  
**Evidence anchors:**
- [abstract] "We reformulate do-Shapley values in terms of the irreducible sets of the underlying SCM. Leveraging this insight, we can exactly compute do-Shapley values in time linear in the number of irreducible sets r."
- [section 2] "These classes constitute a partition of the powerset of all d features. ... we leverage this structure to compress the Shapley summation into a linear combination of class values."
- [section 3] Algorithm 2 enumerates all closed sets (closures) via lattice exploration using Lemma 3.1.  
**Break condition:** Worst-case r = 2^d (e.g., a fully connected DAG with no redundant interventions), so complexity remains exponential. The per-class cost O(d+e+T) also depends on the value-function evaluation time T.

### Mechanism 2: Boundary Sampling for Fixed-Budget Approximation
**Claim:** With a query budget m, the boundary sampler discovers min(m, r) distinct equivalence classes without redundancy, achieving orders-of-magnitude lower error than structure-agnostic methods and exact Shapley values when m ≥ r.  
**Mechanism:** Maintain a priority queue of candidate classes (closed sets) ordered by expected weight magnitude |w_i(c)|. Warm-start with random sets of each size. In each iteration, sample a class proportionally to its weight, query ν(c), and add to the sample. Generate neighboring classes by toggling one variable in the basis or adding a variable to the closure (via FindClass). This guarantees each query yields a new class. After sampling, use SimulatedSampler (Algorithm 5) to generate many coalition queries from the discovered sub‑lattice and feed them to a base estimator (e.g., RegressionMSR).  
**Core assumption:** The lattice of closed sets is connected under the neighbor relation, and the weight magnitude is a good proxy for a class’s contribution to the Shapley value.  
**Evidence anchors:**
- [abstract] "As the query budget approaches r, our estimators can produce more accurate estimates than prior methods by several orders of magnitude, and, when the budget reaches r, return the Shapley values up to machine precision."
- [section 4] "We propose a boundary sampler, a targeted exploration strategy guaranteed to identify min(m, r) distinct equivalence classes when run with m queries." (Algorithm 3)
- [section 6] Figure 5 shows empirical convergence at m = r.  
**Break condition:** The weight heuristic may mis‑prioritize if many classes have similar weights but small overall contributions; however, the guarantee of discovering all classes when m ≥ r does not depend on the heuristic as long as the queue does not empty prematurely. Per‑iteration cost O(d(d+e)) can be high for large d and dense graphs.

### Mechanism 3: Efficient Identifiability Check via Singletons
**Claim:** Non‑parametric identifiability of all do‑Shapley values requires checking only the d singleton interventions {i}, reducing the number of required ID algorithm calls from up to 2^d to d.  
**Mechanism:** Prove that if any coalition intervention P_S(Y) is not identifiable, then some singleton {s} is also not identifiable. The proof follows the ID algorithm’s call stack: a non‑identifiable call ends with a *hedge* (R‑rooted C‑forest pair). In that call, the intervened set S intersects the closure of the original coalition; thus a singleton in S is non‑identifiable. Contrapositively, if all singletons are identifiable, all coalitions are identifiable.  
**Core assumption:** The causal graph is an ADMG (latent‑variable projection of an SCM) and the ID algorithm is sound and complete for non‑parametric identifiability.  
**Evidence anchors:**
- [abstract] "we prove that non‑parametric identifiability of do‑Shapley values requires only the identification of interventional effects for the d singleton coalitions, rather than all classes."
- [section 5] "Theorem 5.1. The do‑Shapley value ϕ_i is identifiable if, and only if, ∀j∈[d], ν({j}) is identifiable."
- [appendix E] Full proof (Lemma E.8, Theorem E.7, Corollary E.14).  
**Break condition:** The result holds strictly in the non‑parametric setting; parametric assumptions might alter identifiability. Also assumes the graph is correctly specified; misspecification can invalidate the conclusion.

## Foundational Learning

### Concept: Shapley Values
- **Why needed:** do‑Shapley is a direct application of Shapley’s game‑theoretic attribution to causal value functions. The original formula (Equation 2) explains why naive computation is exponential and how the marginal contributions combine.

### Concept: Structural Causal Models (SCMs) and the do-operator
- **Why needed:** The value function ν(S) = E[Y|do(S=x_S)] is defined via interventions. Understanding do‑calculus (e.g., rule 3) is necessary to see why ν(S) = ν(S⁻) for redundant S.

- **Why needed:** The applicability of do‑Shapley depends on whether ν(S) can be estimated from observational data. The ID algorithm determines this; Section 5’s simplification relies on identifiability theory.

## Architecture Onboarding

### Component map
Graph Handler -> Value Function -> FindClass -> AllClasses -> BoundarySampler -> SimulatedSampler -> Estimator

### Critical path
*Exact computation:*  
1. Run AllClasses → list of closures.  
2. For each closure, call FindClass to get basis and weight w_i(c).  
3. Sum over classes: ϕ_i ← ∑_c ν(c)·w_i(c).  

*Fixed‑budget estimation:*  
1. Run BoundarySampler(m) → set C of distinct classes.  
2. Query ν(c) for each c ∈ C.  
3. If |C| = r (queue empty), compute exact sum as above; else:  
   a. Run SimulatedSampler(C, k·m) to produce dataset D.  
   b. Pass D to BaseEstimator → Shapley estimates.

### Design tradeoffs
- **Exact vs. approximate:** Exact requires r may be exponential; boundary sampler trades exactness for bounded runtime. The simulated sampling phase adds O(m·d) time but dramatically reduces variance.
- **Neighbor expansion:** BoundarySampler uses both upper (add unused variables) and lower (remove basis variables) neighbors; this ensures lattice connectivity but increases per‑iteration cost O(d(d+e)). Limiting to one direction could miss classes.
- **Weight heuristic:** Prioritizing classes by |w_i(c)| reduces variance early but is not required for convergence; it may bias exploration if many small‑weight classes exist.
- **Base estimator choice:** RegressionMSR and LeverageSHAP both benefit from non‑redundant samples; RegressionMSR often yields lower error in sparse budget regimes (per experiments).

### Failure signatures
- **Explosion of r:** Monitor size of AllClasses output; if r grows too large (e.g., >10⁶), switch to estimation early.
- **Graph cycles:** Lemmas require a DAG. Ensure input graph is acyclic; cycles break basis/closure definitions.
- **Value‑function inconsistency:** If two coalitions in the same class produce different ν values, the caching assumption fails. Validate FindClass by checking that its basis/closure indeed yield same ν on a few test instances.
- **Identifiability violation:** Run the O(d) singleton identifiability check before any expensive computation; if any singleton fails, abort or collect additional data/instrumental variables.
- **BoundarySampler deadlock:** The queue should empty only when all classes have been found (|C| = r). If it empties prematurely, inspect neighbor generation or class deduplication logic.

### First 3 experiments
1. **Unit test FindClass** on a tiny graph (d=3). Enumerate all subsets, manually compute basis/closure, compare with algorithm output.
2. **Exact vs. brute force** for d ≤ 5: compute do‑Shapley by summing over all 2^d coalitions and compare with AllClasses result.
3. **Boundary sampler convergence** on the SCM from Figure 1 (known r=4). Run with m = 1,2,...,8 and verify:
   - Every query discovers a new class until m = r.
   - Shapley estimates match exact values at m = r and remain stable beyond.

## Open Questions the Paper Calls Out
- **Graph misspecification sensitivity:** How sensitive are do-Shapley values to errors in the causal graph? The paper assumes a correct graph; the impact of misspecification is unknown.
- **Graph properties controlling r:** What structural properties of the causal graph determine the number of irreducible sets r? Predicting r would help estimate computational cost and guide causal discovery.
- **Theoretical bounds for boundary sampler:** What are the theoretical error bounds for the boundary sampler, and is it optimal? The paper presents empirical gains but lacks formal analysis.

## Limitations
- **Scalability of r:** Only empirical evidence on TALENT; no theoretical guarantee that r ≪ 2^d for arbitrary graphs.
- **Boundary sampler heuristic:** Weight‑based priority may bias exploration; worst-case exponential r remains possible.
- **Identifiability scope:** Theorem 5.1 holds only for non‑parametric ADMGs; violations (e.g., misspecification) break the simplification.
