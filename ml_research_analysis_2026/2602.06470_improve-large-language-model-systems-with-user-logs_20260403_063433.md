# Improve Large Language Model Systems with User Logs

## Quick Facts
- **arXiv ID:** 2602.06470
- **Source URL:** https://arxiv.org/abs/2602.06470
- **Reference count:** 40
- **Primary result:** UNO achieves state-of-the-art performance on MemoryBench across multiple models (e.g., Qwen3-8B, phi-4), significantly outperforming RAG and memory-based baselines in both Norm-Score and Z-Score while maintaining computational efficiency and demonstrating effective online evolution.

## Executive Summary
This paper introduces UNO, a framework for improving large language model (LLM) systems using noisy, unstructured user logs. It addresses the Signal-or-Noise Dilemma and off-policy optimization by distilling logs into semi-structured rules and preference pairs, clustering samples via dual-feature embeddings, and quantifying a cognitive gap between the model’s prior knowledge and log data. This gap assessment adaptively selects between a Primary Experience Module (direct LoRA fine-tuning) for low-gap clusters and a Reflective Experience Module (critic LoRA for iterative refinement) for high-gap clusters. Evaluated on the MemoryBench benchmark, UNO consistently surpasses existing baselines and shows robust adaptation to incremental user feedback.

## Method Summary
UNO processes raw user interaction logs `(q, y, F)` through four stages. First, a preprocessing step uses the base LLM to filter noise and distill each trajectory `F` into a concise rule set `R`, then generates a revised response `y_w` to form preference pairs `(q, y_w, y_l, R)`. Second, samples are clustered using a dual-feature vector combining normalized embeddings of the query `q` and rule set `R` via agglomerative clustering (Ward, `ε_var=4`). Third, for each cluster, a cognitive gap score `g_i` is computed by comparing the base LLM’s self-generated rules `R_i^LLM` with the distilled `R_i` using a reranker; clusters with mean gap `μ_k ≤ τ*` (0.45) are low-gap. Fourth, low-gap clusters train an Expert LoRA via DPO (validated by an LLM-as-Judge verifier with win-rate threshold `γ=0.53`); high-gap or failed clusters train a Critic LoRA to predict `R_i` at inference time. At deployment, a new query is routed to the nearest cluster: low-gap clusters use the Expert LoRA, while high-gap clusters run a critique-and-revise loop with the Critic LoRA.

## Key Results
- UNO achieves state-of-the-art performance on MemoryBench across multiple models (Qwen3-8B, phi-4) and tasks, with significant gains in Norm-Score and Z-Score over RAG and memory-based baselines.
- The adaptive design yields complementary benefits: the Primary Experience Module excels in low-gap (aligned) clusters, while the Reflective Experience Module mitigates degradation in high-gap (noisy) clusters.
- The framework demonstrates effective online evolution, continuing to improve with incremental user logs without catastrophic forgetting.

## Why This Works (Mechanism)

### Mechanism 1: Rule Distillation for Signal Extraction
- **Claim:** Converting noisy, unstructured user logs into semi-structured rule sets and preference pairs allows extraction of actionable improvement signals while filtering irrelevant content.
- **Mechanism:** An LLM acts as a "teacher" to distill each user interaction trajectory `F_i` into a concise set of explicit editing guidelines `R_i`. These rules, paired with the original and revised responses, form a preference dataset suitable for direct preference optimization (DPO).
- **Core assumption:** The base LLM can reliably identify and articulate useful feedback embedded in free-form user comments, transforming implicit signals into explicit, trainable objectives.
- **Evidence anchors:** [abstract] mentions distillation into rules and pairs; [section 3.3.1] details feedback filtering, rule extraction, and revision generation; neighboring papers discuss noise but not this specific distillation method.

### Mechanism 2: Cognitive Gap as a Risk-Aware Selector
- **Claim:** Quantifying the semantic distance (cognitive gap) between the base model’s self-generated expectations and user-log-derived rules provides a proxy for noise risk, guiding the choice of optimization strategy.
- **Mechanism:** For each sample, the base LLM generates its own rule set `R_i^LLM` without log access. A reranker computes `g_i = Dist(R_i^LLM, R_i)`. The cluster-level average `μ_k` determines if the cluster is "Low-Gap" (model’s prior aligns with log feedback) or "High-Gap" (potential noise or novel signals).
- **Core assumption:** In low-gap regions, high-quality feedback aligns with model cognition while noise is random and less likely to align, making them separable. In high-gap regions, distributions of useful novel signals and noise converge from the model’s perspective.
- **Evidence anchors:** [abstract] introduces cognitive gap; [section 3.3.3] formalizes the dilemma, defines `g_i`, and presents Assumption 3.1 and Theorem 3.4 on variance reduction; neighbors do not address this specific gap metric.

### Mechanism 3: Adaptive Module Selection for Robustness
- **Claim:** Switching between a Primary Experience Module (direct LoRA fine-tuning) for low-gap clusters and a Reflective Experience Module (critic LoRA for iterative refinement) for high-gap clusters balances efficient learning with noise robustness.
- **Mechanism:** Low-gap clusters: train an Expert LoRA via DPO, validated by an LLM-as-Judge verifier using distilled rules. High-gap clusters: train a Critic LoRA to predict rules `R_i` from `(q_i, y_i)`; at inference, the critic suggests revisions before the base LLM regenerates.
- **Core assumption:** Direct parameter updates are low-risk only when log feedback is highly aligned with existing knowledge (low gap). When alignment is poor, keeping parameters fixed and using a lightweight critic module protects against noise.
- **Evidence anchors:** [abstract] describes adaptive selection; [section 3.4 & 3.5] detail training objectives and validation; Table 2 (ablation) shows full UNO outperforms primary-only and reflective-only variants.

## Foundational Learning

- **Concept: Dual-Feature Clustering (Query + Rule Embeddings)**
  - **Why needed here:** Grouping sessions by both intent (query) and correction principles (rules) ensures cluster homogeneity, decoupling tasks and reducing intra-cluster variance in cognitive gap.
  - **Quick check:** If only clustering by query embeddings, what risk does this pose for the cognitive gap calculation within a cluster?

- **Concept: Cognitive Gap Quantification as a Risk Proxy**
  - **Why needed here:** It formally bridges raw log noise and optimization strategy choice, providing a pre-filter to avoid expensive DPO on likely-noisy clusters and explaining why direct fine-tuning fails in high-noise settings.
  - **Quick check:** Under Assumption 3.1, why does a high average gap `μ_k` indicate the LLM cannot reliably separate "novel signal" from "noise" in that cluster?

- **Concept: Parameter-Efficient Adaptation (LoRA) with Validation Loop**
  - **Why needed here:** Full fine-tuning on noisy, heterogeneous logs risks catastrophic forgetting and overfitting. LoRA provides targeted updates, and the LLM-as-Judge verifier offers a lightweight, rule-aligned quality check before deployment.
  - **Quick check:** Why is using the distilled rule set `R_i` as context for the verifier more aligned with the optimization goal than using standard perplexity on validation samples?

## Architecture Onboarding

- **Component map:** Preprocessor -> Clusterer -> Gap Assessor -> Module Trainer (Primary/Reflective) -> Inference Router
- **Critical path:** Raw Log (`q, y, F`) -> Rule Distillation (`R_i`) -> Preference Pair -> Cluster Assignment -> Gap Assessment -> Path Decision -> Module Training (Expert *with* Verifier *or* Critic) -> Inference Router -> Response.
- **Design tradeoffs:**
  - **Primary Path:** Fast (single generation), best for aligned data. **Risk:** Overfitting to noise if gap assessment/verification fails.
  - **Reflective Path:** Slower (two generations + critic), more robust in noisy/high-gap clusters. **Risk:** Critic may learn spurious patterns or add latency.
  - **Clustering Granularity:** Tighter clusters (`ε_var` low) improve gap estimate reliability but risk over-splitting and sparse training data.
- **Failure signatures:**
  - High primary module failure rate: many clusters with `μ_k ≤ τ*` fail verifier (`WinRate_best ≤ γ`). Suggests `τ*` too high or poor rule distillation.
  - Reflective path underperformance: Reflective clusters show no improvement vs. base model. Suggests ineffective critic training or non-actionable `R_i`.
  - Router misassignment: New queries with large centroid distance (>1.2) but forced into worst-matching cluster. High outlier rate suggests centroids are not representative.
- **First 3 experiments:**
  1. Rule Extraction Sanity Check: Manually inspect `R_i` for 50 random samples per dataset; target >90% non-empty, avg clarity >3.5/5.
  2. Gap Threshold Sensitivity: Ablate `τ*` (e.g., {0.35,0.45,0.55}). Plot validation WinRate of primary modules vs. `μ_k` bin; expect steep drop past optimal `τ*`.
  3. Path Selection Justification: On held-out data, force all samples through Primary and Reflective paths; compare performance. Expect Primary to win on low-gap samples, Reflective to avoid degradation on high-gap samples.

## Open Questions the Paper Calls Out
- **Question 1:** How robustly does the cognitive gap metric separate high-signal from noisy user logs across diverse real-world distributions?
  - *Basis:* Defined in Section 3.3.3, with assumptions (3.1) and theoretical bounds; validation limited to MemoryBench simulator.
  - *Why unresolved:* Theoretical separation relies on strong assumptions (Lipschitz continuity, metric properties) that may not hold for arbitrary LLM semantics and log noise patterns; empirical evidence is confined to a single synthetic benchmark.
  - *Resolving evidence:* Annotate real production logs for signal/noise, compute gap distributions per cluster, and test if low-gap clusters consistently yield higher signal-to-noise ratios across domains and models.

- **Question 2:** To what extent do User Simulator-generated logs in MemoryBench capture the noise characteristics of authentic production user logs?
  - *Basis:* Evaluation uses only MemoryBench with a User Simulator (Section 4.1); simulator validation via A/B testing but no comparison to real log noise profiles.
  - *Why unresolved:* Real logs contain idiosyncratic biases, sparse feedback, and ambiguous corrections that a simulator may not replicate, potentially overstating UNO’s generalizability.
  - *Resolving evidence:* Collect and annotate a corpus of real production logs; compare noise statistics (feedback sparsity, coherence, rule extractability) between simulator and real logs; re-evaluate UNO on real logs.

- **Question 3:** How sensitive is UNO’s performance to the cognitive gap threshold `τ*` and can it be determined adaptively?
  - *Basis:* `τ*` is set heuristically to 0.45 (Section 4.3) and critically governs path selection.
  - *Why unresolved:* No analysis explores `τ*`’s stability across datasets or models; a fixed threshold may misclassify clusters in new environments.
  - *Resolving evidence:* Sweep `τ*` across a wide range on multiple datasets; measure cluster assignment consistency, final performance, and computational cost; develop an adaptive method (e.g., based on cluster variance or validation win-rate).

- **Question 4:** What is the exact computational trade-off of the Reflective Experience Module’s critique-and-revise loop during inference?
  - *Basis:* Reflective Path requires two LLM calls plus Critic LoRA execution (Section 3.6); Figure 2 correlates extra tokens with performance but lacks granular latency/throughput/cost analysis.
  - *Why unresolved:* Claims of efficiency lack wall-clock time, tokens generated, or cost per query details, which are vital for real-world deployment with latency budgets.
  - *Resolving evidence:* Report average inference latency, tokens generated (input/output), and estimated cost for UNO’s reflective vs. primary paths across batch sizes; compare against RAG baselines; identify break-even points where gains justify added cost.

## Limitations
- Exact prompts for rule distillation, revision generation, and the simulated verifier are omitted, hindering replication.
- Cognitive gap metric (τ*=0.45) and reranker choice may not generalize across models or datasets; theoretical assumptions (Assumption 3.1) are strong with shallow empirical support.
- Outlier threshold `d=1.2` and win-rate threshold `γ=0.53` are heuristic; their scaling to many clusters or datasets is unclear.

## Confidence
- **Mechanism 1 (Rule distillation):** Medium – plausible but unverified under high noise or domain shift.
- **Mechanism 2 (Gap quantification):** Low – theoretical assumptions are strong; empirical support is shallow.
- **Mechanism 3 (Adaptive selection):** High – ablation (Table 2) shows complementary gains, though external validity remains open.
