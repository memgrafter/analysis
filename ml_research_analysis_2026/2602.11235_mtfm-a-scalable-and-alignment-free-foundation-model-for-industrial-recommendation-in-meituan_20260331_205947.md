# MTFM: A Scalable and Alignment-free Foundation Model for Industrial Recommendation in Meituan

## Quick Facts
- **arXiv ID**: 2602.11235
- **Source URL**: https://arxiv.org/abs/2602.11235
- **Reference count**: 40
- **Primary result**: MTFM improves multi-scenario recommendation with up to 0.76pp GAUC gains and 2× training throughput, driving online orders up by +2.98%.

## Executive Summary
MTFM is a scalable, alignment-free foundation model for multi-scenario industrial recommendation, proposed by Meituan. It eliminates the need for manually aligned feature schemas by processing raw scenario-specific features through separate tokenizers into heterogeneous tokens (H, R, T). The core architecture uses Hybrid Target Attention (HTA), which interleaves full attention layers with Grouped-Query Attention and efficient target attention layers that only update exposure tokens (T), drastically reducing quadratic complexity. Additional optimizations such as user-level sample aggregation and custom kernels further boost training efficiency.

In offline evaluations, MTFM achieves consistent GAUC improvements across multiple scenarios (average 0.36 percentage points for CTR and 0.29pp for CTCVR) with maximum gains up to 0.76pp and 0.53pp. Online A/B tests confirm significant business gains, including a 2.98% increase in orders for the SQS scenario and 1.45% for PHF. The HTA mechanism delivers a 2× training throughput speedup while maintaining modeling accuracy.

## Method Summary
MTFM tackles multi-scenario recommendation by decoupling each scenario's raw features via separate MLP tokenizers into heterogeneous tokens (H: historical, R: real-time, T: exposure). These tokens are aggregated at the user level to form dense training sequences and processed by a stack of Hybrid Target Attention (HTA) blocks. Each block interleaves a full attention layer (using Grouped-Query Attention) with multiple target attention layers that only update T-token embeddings, while H- and R-tokens are passed via shortcuts. A dynamic attention mask based on timestamps prevents information leakage across scenarios and time. The model is trained with Adam (lr=3e-4) on these aggregated sequences, employing a multi-task MMoE head for scenario-specific predictions. Key hyperparameters include embedding dimension 768, 4 blocks (B=4), and a target-to-full attention ratio of 3:1 (K=3). System optimizations such as kernel fusion and CPU‑GPU pipelining further accelerate training. Reproduction requires implementing the tokenizer, HTA block, dynamic mask construction, and user-level aggregation, but details such as exact tokenizer MLP architectures, dynamic mask logic for overlapping timestamps, and MMoE configuration are not fully disclosed.

## Key Results
- **Offline performance**: Average GAUC improvements of 0.36pp (CTR) and 0.29pp (CTCVR), with maximum gains of 0.76pp (CTR) and 0.53pp (CTCVR) across scenarios.
- **Online impact**: +2.98% orders for SQS scenario and +1.45% for PHF in A/B tests.
- **Efficiency**: Hybrid Target Attention (HTA) yields a 2× training throughput speedup.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** MTFM eliminates the need for manually aligned, homogeneous input features across heterogeneous recommendation scenarios by using scenario-specific tokenization.
- **Mechanism:** Raw features from each scenario (user profile, cross features, item features, sequences) are processed by separate MLP tokenizers into embeddings. These "heterogeneous tokens" (H-, R-, T-tokens) are merged into a single sequence where token type and origin encode scenario membership implicitly, removing the requirement for a shared feature schema.
- **Core assumption:** Feature spaces across industrial scenarios (e.g., restaurant vs. food recommendation) are intrinsically incompatible; forcing alignment causes information loss and engineering overhead.
- **Evidence anchors:**
  - [abstract]: "Instead of pre-aligning inputs, MTFM transforms cross-domain data into heterogeneous tokens, capturing multi-scenario knowledge in an alignment-free manner."
  - [section 3.2.1]: Details token types (H, R, T) and scenario-specific tokenizers (different MLPᵢ, MLPₛ). States: "scenario-specific features... are treated as scenario-specific. This configuration is dictated by the fundamental structural divergence between domains."
  - [corpus]: Corpus shows related work (e.g., PEPNet, STAR) relies on "strict feature alignment" or "fixed template[s]" (neighbor abstracts). MTFM's stated novelty is breaking this paradigm.
- **Break condition:** If all integrated scenarios share an identical, stable feature schema, the complexity of heterogeneous tokenization may outweigh its benefits, and simpler aligned input methods could suffice.

### Mechanism 2
- **Claim:** The Hybrid Target Attention (HTA) mechanism maintains modeling capacity for long, heterogeneous sequences while drastically reducing computational cost compared to full Transformer attention.
- **Mechanism:** The model stack interleaves a small number of full attention layers (with Grouped-Query Attention, GQA) with many more efficient Target Attention layers. Target Attention updates only T-tokens (exposure behaviors), treating H- and R-tokens as static key-value sources via a shortcut. This reduces the dominant quadratic cost per layer from O(N²) to O(K·N·L_T + N²/(K+1)), where L_T << N is the number of T-tokens.
- **Core assumption:** Global dependency capture (via occasional full attention) is sufficient when combined with targeted updates to decision-critical tokens (T-tokens), avoiding the need for full attention in every layer.
- **Evidence anchors:**
  - [abstract]: "We further integrate Grouped-Query Attention and a customized Hybrid Target Attention to minimize memory usage and computational complexity."
  - [section 3.2.2]: Defines the hybrid block structure (𝐾 target layers, 1 full layer per block), formalizes the complexity reduction, and describes the shortcut connection: "In the Target Attention Layers, we update only the embeddings of T-tokens, while the embeddings of other tokens... are passed to the next layer via a shortcut connection."
  - [section 4.3 (RQ2)]: Empirical validation shows hybrid configurations (e.g., 3:1 ratio) match full-attention performance (Δ AUC < 0.001) while improving throughput and memory.
- **Break condition:** If the decision-critical information is distributed not primarily in T-tokens but equally across all token types (H, R, T), the shortcut mechanism could lead to significant information loss, degrading performance.

### Mechanism 3
- **Claim:** User-level sample aggregation across scenarios reduces training instance count and increases sequence density, significantly improving training throughput without altering model semantics.
- **Mechanism:** During offline training, all exposure events for a single user across all scenarios within a time window are aggregated into one training sample. This replaces many sparse, single-exposure samples with one dense sample containing multiple scenarios' candidates and features for that user, reducing total instance count.
- **Core assumption:** User behaviors across scenarios are correlated and can be modeled jointly within a single forward pass; aggregating them does not violate the independence assumptions of stochastic gradient descent when properly batched.
- **Evidence anchors:**
  - [abstract]: "We first introduce a multi-scenario user-level sample aggregation that significantly enhances training throughput by reducing the total number of instances."
  - [section 3.3.1]: Explains the aggregation: "we aggregate all exposure behaviors... at the user-level... each user 𝑢 corresponds to multiple training samples... [aggregated into] D𝑢". It decouples scenario-agnostic (H, R) and scenario-specific (U, C, I) features for concatenation.
  - [section 3.3.2 (Training Optimization)]: Quantifies the throughput gain from this pipeline design as part of a 20% improvement from CPU-GPU pipeline optimizations, with the aggregation itself being the foundational step.
- **Break condition:** If user behaviors across scenarios are entirely independent and temporally disjoint, aggregation might introduce misleading context or increase sequence length beyond practical limits without proportional signal gain, hurting efficiency.

## Foundational Learning
- **Concept: Transformer Attention & Sparse Patterns**
  - *Why needed here:* MTFM's core innovation (HTA) is a modification of standard Transformer attention. Understanding full attention's O(N²) cost, the role of masks (dynamic timestamp-based), and the concept of token-specific update (Target Attention) is essential to grasp the efficiency trade-off.
  - *Quick check question:* "How does the Target Attention layer's shortcut connection change the gradient flow and information propagation for non-T-tokens compared to a standard Transformer layer?"
- **Concept: Multi-Scenario vs. Single-Scenario Recommendation Paradigms**
  - *Why needed here:* MTFM's goal and architecture are defined in opposition to the "harmonize-then-decompose" paradigm (STAR, M3OE) and aligned-input generative models (MTGR, OneTrans). Knowing the prior art's limitations (rigidity, see-saw effect) is key to understanding MTFM's design choices.
  - *Quick check question:* "Why is 'feature alignment' a fundamental bottleneck for scaling multi-scenario models in industrial settings, according to the paper's argument?"
- **Concept: System-Model Co-design for Industrial Scale**
  - *Why needed here:* The claimed efficiency gains are not just from the HTA algorithm but from deep integration with the training/inference stack (user-level aggregation, custom kernels, pipeline optimization, sparse inference). This holistic view is necessary to replicate results.
  - *Quick check question:* "What are the two main categories of system-level optimizations (data pipeline vs. kernel) described, and what specific bottleneck does each address?"

## Architecture Onboarding
- **Component map:**
  1. Data Pipeline: Raw logs → User-level aggregation (merges multi-scenario exposures per user) → Feature split (scenario-agnostic H/R vs. scenario-specific U/C/I) → Tokenization (separate MLPs for H, R, T).
  2. Model Forward: Token embeddings → Sort by timestamp → Dynamic mask construction → Stacked HTA Blocks (interleaved Full + Target layers) → Final T-token embeddings → Multi-task tower (MMoE) → Scenario-specific predictions.
  3. Inference Subgraph: For scenario s, prune to subgraph using only Uˢ, Cˢ, Iˢ tokens and corresponding T-tokens; reuse shared H/R token representations.
- **Critical path:** The most computationally critical and novel path is the **Target Attention layer operation**. It takes the full token sequence, but only computes and updates the T-token sub-matrix, using H/R tokens as static K/V. The dynamic mask's correct application on this sub-matrix is vital to prevent leakage.
- **Design tradeoffs:**
  - **HTA Ratio (K:1):** More target layers (higher K) increase speed but risk losing global context if full attention layers are too sparse. Paper finds (3:1) optimal.
  - **Tokenization Granularity:** Separate tokenizers per sequence type (H₁, H₂...) preserve heterogeneity but increase parameter count and potential overfitting on sparse scenario-specific features.
  - **Aggregation Window Size:** Larger windows increase user sample density (better throughput) but increase sequence length (cost) and risk temporal leakage if mask is imprecise.
- **Failure signatures:**
  - **Performance degradation on a specific scenario:** Likely a masking error in Target Attention (e.g., R-tokens leaking future info for that scenario) or insufficient full attention layers to capture that scenario's cross-scenario dependencies.
  - **Throughput lower than expected:** Check if user-level aggregation is active (instance count drop). Verify custom kernels (FlashAttention variant, GLN fusion) are loaded. Profile for CPU-GPU blocking in data loading.
  - **Memory spike:** Possibly incorrect GQA configuration (query/key-value head ratio), or dynamic mask not being applied as a sparse pattern.
- **First 3 experiments:**
  1. **HTA Ablation:** Train with (0:16) all-full, (16:0) all-target, and (3:1)*4 hybrid on a validation set. Confirm hybrid matches full-attention AUC within 0.05pp and significantly beats all-target. Measure throughput gain.
  2. **Mask Correctness Validation:** Create a synthetic sample with known timestamp ordering. Inspect the dynamic mask M to ensure: (a) H-tokens visible to all, (b) R-tokens only visible to later tokens, (c) T-tokens only visible to themselves. Run a forward pass and check attention weights violate these rules.
  3. **Scenario Subgraph Isolation:** For a multi-scenario trained model, disable all scenario-specific modules (MLPₛ for U/C/I, scenario-specific MMoE experts) for scenario *s* during inference. Performance should collapse to near-random, confirming the subgraph pruning works and scenario knowledge is not trivially shared via shared H/R alone.

## Open Questions the Paper Calls Out
- **Open Question 1**
  - Question: How does MTFM generalize to domains beyond food delivery (e.g., e-commerce, video) with different feature spaces and business objectives?
  - Basis in paper: [inferred] the evaluation is limited to three food-centric scenarios (HP, PHF, SQS) within Meituan; no cross-domain experiments are reported.
  - Why unresolved: The claim of extensibility is not validated on truly heterogeneous domains, leaving uncertainty whether the tokenization and attention mechanisms transfer.
  - What evidence would resolve it: Offline and online studies on at least two distinct domains (e.g., e-commerce, streaming) showing comparable GAUC gains and efficiency.
- **Open Question 2**
  - Question: Can the hybrid attention architecture benefit from adaptive allocation of target vs. full attention layers (e.g., per-layer or per-scenario ratios) rather than a fixed global ratio?
  - Basis in paper: [inferred] the paper uses a static (K=3, B=4) configuration based on limited ablation; no adaptive mechanism is explored.
  - Why unresolved: A static ratio may be suboptimal across layers or scenarios; adaptivity could improve accuracy-efficiency trade-off.
  - What evidence would resolve it: Experiments with learnable or heuristic-based dynamic ratios, comparing GAUC and throughput against the static baseline.
- **Open Question 3**
  - Question: What are the privacy and fairness implications of user-level sample aggregation across scenarios? Could it expose sensitive cross-scenario behavior or bias against users with limited cross-scenario activity?
  - Basis in paper: [inferred] user-level aggregation is adopted for efficiency without discussing privacy or bias trade-offs.
  - Why unresolved: Regulations (e.g., GDPR) and ethical concerns require understanding data exposure; aggregating across scenarios may reveal private interests.
  - What evidence would resolve it: Privacy impact assessment and fairness metrics (e.g., performance disparity across user activity levels) after aggregation.
- **Open Question 4**
  - Question: Do the scaling laws observed for MTFM hold for extremely large models (e.g., >100x relative GFLOPs), or do diminishing returns appear at trillion-parameter scales?
  - Basis in paper: [inferred] scaling experiments only go up to 70x relative to MMoE; larger scales are not investigated.
  - Why unresolved: Existing scaling law research in other domains suggests potential inflection points; unknown if MTFM benefits continue linearly.
  - What evidence would resolve it: Training and evaluating significantly larger MTFM variants (e.g., 100x, 200x) and plotting performance vs. compute to identify trends.
- **Open Question 5**
  - Question: How robust is the dynamic masking strategy (used to prevent information leakage) to timestamp noise or missing temporal information, which are common in real-world systems?
  - Basis in paper: [inferred] the mask construction assumes precise, ordered timestamps; no robustness analysis is provided.
  - Why unresolved: Inaccurate timestamps could cause either leakage (if mask is too permissive) or loss of valid context (if too restrictive), affecting model quality.
  - What evidence would resolve it: Controlled experiments with perturbed timestamps (e.g., random shifts, missing values) measuring changes in GAUC and possibly redesigning the mask.

## Limitations
- **Implementation gaps**: Exact tokenizer MLP architectures, dynamic mask construction logic, grouped-query attention group sizes, and MMoE expert configuration are unspecified, hindering faithful reproduction.
- **Generalization boundaries**: The alignment-free advantage assumes high scenario heterogeneity; benefits may diminish if scenarios share stable schemas. HTA's shortcut mechanism may degrade performance if critical signals are distributed across all token types, not just T-tokens.
- **System-dependent gains**: Reported throughput speedups rely heavily on proprietary custom kernels and CPU-GPU pipeline optimizations; gains may not transfer to standard deep learning stacks.

## Confidence
- **Alignment-Free Heterogeneous Tokenization**: Medium
- **Hybrid Target Attention (HTA) Efficiency-Capacity Trade-off**: High
- **User-Level Sample Aggregation Throughput Gains**: Medium

## Next Checks

Run a forward pass and programmatically inspect the dynamic attention mask to verify strict adherence: H-tokens always visible, R-tokens visible only to later tokens within the same user window, T-tokens self-attention only. Any violation indicates leakage risk.
2. **Tokenization Granularity Ablation**: Replace the paper's unspecified heterogeneous tokenizers with a shared tokenizer and a simpler alignment scheme. Measure GAUC and throughput degradation on a held-out scenario to isolate the cost of heterogeneity.
3. **Subgraph Pruning Verification**: After multi-scenario training, perform inference on target scenario *s* with all scenario-specific modules (Uˢ/Cˢ/Iˢ embedding tables, scenario-specific MMoE experts) zeroed out or removed. Performance should collapse to near-baseline, confirming that shared H/R tokens alone do not trivially encode scenario-specific signals.
