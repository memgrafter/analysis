# Learn Hard Problems During RL with Reference Guided Fine-tuning
## Quick Facts
- arXiv ID: 2603.01223
- Source URL: https://arxiv.org/abs/2603.01223
- Reference count: 34
- Primary result: ReGFT + DAPO achieves 70.0% on AIME24, improving over Raw + DAPO (67.1%) and yielding stronger pass@k scaling.

## Executive Summary
Reward sparsity in reinforcement learning for mathematical reasoning hinders learning on hard problems where the base model cannot produce any correct solutions. This paper introduces Reference-Guided Fine-Tuning (ReGFT), which leverages partial human-written reference solutions to elicit model-generated reasoning trajectories that remain within the model's distribution. These trajectories are used for supervised fine-tuning before applying RL. On OmniMath training and three benchmarks (AIME24, AIME25, BeyondAIME), ReGFT improves the model’s pass rate on hard problems, accelerates DAPO reinforcement learning, and achieves higher final accuracy compared to both a raw model and ReFT (which uses only self-generated correct traces). Notably, ReGFT + DAPO obtains 70.0% on AIME24 versus 67.1% for Raw + DAPO with 64 responses per problem. The approach also yields stronger and more consistent pass@k scaling with increased test-time compute.

## Method Summary
ReGFT operates in two stages. First, for problems where the base model initially fails, the authors take a human reference solution and provide the first 80% as a prefix. They prompt the model to generate the remaining reasoning steps. Because the prefix anchors the solution and guides the model along a promising path, the model is more likely to produce a full correct trajectory while staying within its own distributional manifold. The set of correct, model-generated trajectories is collected and used for supervised fine-tuning (SFT). Second, the fine-tuned model is further optimized with the DAPO reinforcement learning algorithm, using a rule-based verifier to reward correct final answers. This warm-start with successful trajectories alleviates reward sparsity and gives RL a better starting point.

## Key Results
- ReGFT + DAPO reaches 70.0% accuracy on AIME24, surpassing Raw + DAPO (67.1%) with 64 responses per problem.
- ReGFT accelerates DAPO convergence and yields higher final accuracy than both the raw model and ReFT (which uses only self-generated correct traces without references).
- ReGFT demonstrates stronger and more consistent pass@k scaling, meaning that gains compound when more samples are drawn at test time.
- Results are validated on OmniMath training and three challenging benchmarks: AIME24, AIME25, BeyondAIME.

## Why This Works (Mechanism)
Reward sparsity occurs when the base model has zero probability of generating a correct solution for a given hard problem, so RL receives no learning signal. ReGFT breaks this deadlock by using partial reference prefixes to steer the model toward correct completions that are still generated by the model itself. This yields a collection of successful traces that belong to the model’s own distribution, providing a dense supervised signal. After SFT on these traces, the model acquires a non-zero chance of solving previously unsolvable problems. Subsequent RL (DAPO) can then refine the policy using outcome rewards, as it now receives positive signals for those problems. The prefix-based guidance also preserves the model’s native reasoning style better than full imitation, aiding generalization. In essence, ReGFT converts a sparse-reward RL problem into a supervised warm-start followed by standard RL, enabling systematic improvement on hard problems.

## Architecture Onboarding
Component map:
Reference Solutions -> Prefix Extraction -> Model Generation (Base Model conditioned on prefixes) -> Correct Trajectory Filtering -> Supervised Fine-Tuning -> DAPO Reinforcement Learning -> Final Model

Critical path:
1. Obtain human reference solutions for a selected set of hard problems.
2. Extract prefixes (e.g., first 80% of each solution).
3. Prompt the base model to generate continuations; filter those that are fully correct using a verifier.
4. Perform supervised fine-tuning on the resulting (prefix, correct continuation) pairs.
5. Apply DAPO RL with reward on final answer correctness.
6. Evaluate on test benchmarks.

Design tradeoffs:
- Prefix length: Shorter prefixes offer less guidance but keep the model more autonomous; longer prefixes increase correctness but may lead to imitation and reduced diversity.
- Reference coverage: Covering more hard problems with references improves potential learning but requires more human annotation.
- SFT intensity: Extensive SFT on reference-guided data risks overfitting to the reference style; RL must then recover adaptability.

Failure signatures:
- Few or no correct trajectories generated after prefix conditioning, indicating the prefix is insufficient or the model lacks the underlying capability.
- Overfitting during SFT, evidenced by stagnation or drop on validation problems without references.
- DAPO fails to improve or degrades accuracy, possibly due to reward noise, KL penalty mis‑tuning, or insufficient exploration.

Three first experiments:
1. Vary prefix length (50%, 80%, 90%) and measure the yield of correct trajectories and their distributional distance (e.g., via embeddings) from the model’s ordinary outputs.
2. Compare ReGFT against ReFT (self-generated correct traces only) in terms of SFT data quality and subsequent RL performance to isolate the benefit of reference guidance.
3. Ablate reference coverage: include references for 0%, 25%, 50%, and 100% of the hard problem set and evaluate final pass@k on held-out hard problems to quantify scaling and cost-benefit trade-offs.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: How can reinforcement learning systematically expand a language model's problem-solving capabilities beyond its initial competence, particularly for tasks where the base model generates no correct trajectories?
- Basis in paper: [explicit] The introduction explicitly poses this as the central research question: "How can RL enable a model to solve problems that the base model is originally unable to solve?"
- Why unresolved: While ReGFT partially mitigates reward sparsity by using reference-guided trajectories, many hard problems remain unsolvable even after RL, and the full extent to which RL can induce genuinely new reasoning capabilities (rather than amplifying existing ones) is not fully characterized.
- What evidence would resolve it: Evaluating RL after ReGFT on a set of problems never seen during training (including those without reference solutions), measuring the proportion that become solvable, and analyzing whether the solutions employ reasoning strategies absent from the training data.

### Open Question 2
- Question: What is the optimal design for partial reference hints in ReGFT—such as the fraction of the solution provided, the granularity of guidance, or the selection criteria for hard problems—to maximize the generation of correct, in-distribution trajectories?
- Basis in paper: [inferred] The paper uses fixed heuristics (first 80% of reference solutions, problems with <25% initial accuracy) without justification or ablation.
- Why unresolved: These design choices are arbitrary; providing too little guidance may fail to aid the model, while too much may encourage imitation of human style rather than model-native reasoning, undermining generalization.
- What evidence would resolve it: Systematic experiments varying hint length (e.g., 50%, 90%), hint format (e.g., key steps vs. partial proofs), and hardness thresholds, measuring the correctness and distributional alignment of generated trajectories, and subsequent RL performance.

### Open Question 3
- Question: To what extent do the improvements from ReGFT generalize to mathematical domains or problem types not represented in the reference-augmented training set (OmniMath), and what factors limit cross-domain transfer?
- Basis in paper: [inferred] Evaluation is confined to OmniMath-trained models on AIME/BeyondAIME benchmarks; no experiments on other reasoning domains (e.g., logic, coding) or diverse problem styles.
- Why unresolved: Gains may be specific to the distribution of Olympiad-style problems in OmniMath; without broader testing, it is unclear whether ReGFT fosters broadly applicable reasoning skills or domain-specific adaptations.
- What evidence would resolve it: Applying ReGFT to diverse reasoning tasks with appropriate reference solutions (e.g., MATH, GPQA, code generation), comparing performance against domain-specific SFT baselines, and analyzing transfer of reasoning patterns.

### Open Question 4
- Question: How do limitations in automatic verification, such as false negatives for open-ended proofs, constrain the effectiveness of ReGFT and RLVR, and can improved verifier design unlock further performance gains on hard problems?
- Basis in paper: [explicit] Section 4.3.1 explicitly identifies verifier unreliability: "the rule-based verifier used in OmniMath cannot reliably assess open-ended or proof-style solutions, leading to false negatives."
- Why unresolved: Verifier errors may filter out correct but non-standard solutions during ReGFT trajectory synthesis and RL, capping the maximum achievable performance; addressing this could enhance both stages.
- What evidence would resolve it: Developing a more robust verifier (e.g., learned, step-wise, or multi-modal), measuring changes in the number of problems solvable via reference-guided sampling, and evaluating final RL accuracy compared to the rule-based verifier.

## Limitations
- **Reference dependency**: ReGFT requires human-written reference solutions for at least some hard problems, raising cost, scalability, and coverage concerns.
- **Narrow evaluation**: Results are reported only on three mathematics benchmarks; generalization to other reasoning domains (e.g., code, logic) remains unknown.
- **Statistical robustness**: The paper provides point estimates without confidence intervals or significance tests, so observed improvements might be within random variation.
