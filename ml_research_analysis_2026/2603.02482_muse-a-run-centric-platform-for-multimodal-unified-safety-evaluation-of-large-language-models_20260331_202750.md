# MUSE: A Run-Centric Platform for Multimodal Unified Safety Evaluation of Large Language Models

## Quick Facts
- arXiv ID: 2603.02482
- Source URL: https://arxiv.org/abs/2603.02482
- Reference count: 7
- Primary result: Multi-turn attacks achieve 90–100% hard ASR against models with 90–100% single-turn refusal, and the dual-metric framework reveals partial information leakage missed by binary metrics.

## Executive Summary
MUSE is an open-source, run-centric platform designed for multimodal safety evaluation of large language models. It addresses the text-centric limitation of existing evaluations by integrating automatic cross-modal payload generation, multi-turn attack algorithms, and a provider-agnostic routing system. The platform introduces a dual-metric framework (hard vs. soft Attack Success Rate) using a five-level safety taxonomy, revealing partial information leakage that binary metrics miss. Across six multimodal LLMs from four providers, MUSE demonstrates that multi-turn strategies achieve 90–100% hard ASR even when single-turn refusal rates are 90–100%. Inter-Turn Modality Switching (ITMS) accelerates convergence but has model-family-specific effects. The run-centric architecture enables reproducible, scalable red-teaming and provides a foundation for future multimodal safety research.

## Method Summary
MUSE implements a run-centric evaluation pipeline. It starts from a set of harmful goals (AdvBench) and automatically converts each goal into multimodal payloads (text, audio, image, video) using TTS, text rendering, and video composition. Attacks are orchestrated by pluggable strategies (Crescendo, PAIR, Violent Durian) that engage the target model over multiple turns; ITMS augments these by rotating modalities between turns. The system routes requests to various model providers through a unified interface. Each turn’s response is judged by a GPT-4o model using a five-level safety taxonomy, yielding hard and soft ASR metrics. All interactions are stored as persistent runs, enabling batch execution, resumption, and aggregated analysis. The authors evaluate six multimodal LLMs (Qwen3-Omni, Qwen2.5-Omni, Gemini 2.5 Flash, Gemini 3 Flash Preview, GPT-4o, Claude Sonnet 4) across approximately 3700 runs.

## Key Results
- Multi-turn attacks achieve 90–100% hard ASR against models with 90–100% single-turn refusal.
- Inter-Turn Modality Switching (ITMS) accelerates convergence but its effect on final ASR is model-family-specific (e.g., improves for Gemini, lowers for Qwen).
- Dual-metric framework reveals significant partial information leakage: soft ASR > hard ASR across many scenarios.

## Why This Works (Mechanism)

**1. Dual-metric evaluation exposes partial leakage.** MUSE uses a five-level safety taxonomy to distinguish full Compliance (harmful capability directly transferred) from Partial Compliance (incomplete but actionable information). Hard ASR counts only Compliance; soft ASR includes both, with the gap (GZW) quantifying partial resistance erosion. This assumes partial compliance is a meaningful safety failure. Evidence: abstract and section 3.5 define the taxonomy; neighboring papers discuss metric limitations but not this dual system. Break condition: if human validation fails to correlate with harm potential or GZW proves inconsistent.

**2. ITMS accelerates convergence through modality switching.** Inter-Turn Modality Switching (ITMS) augments multi-turn attacks by rotating modalities per turn, creating a “surprise” effect that destabilizes early defenses. It does not uniformly raise final ASR; effects are model-family-specific. Core assumption: safety alignment does not generalize uniformly across modalities. Evidence: abstract and section 4.4 ablation across six modality configurations. Break condition: controlled experiments show no convergence speed difference or modality effects are universal.

**3. Run-centric architecture enables scalable red-teaming.** Each attack is a persistent “run” storing configuration, conversation state, generated media, judgments, and outcomes. This supports batch orchestration, stop/resume, and longitudinal analysis. Core assumption: unified audit trail is necessary to correlate modality transitions with erosion. Evidence: abstract and section 3.2. Break condition: run metadata overhead prevents scaling or storage issues.

## Foundational Learning
- **Concept: Five-level safety taxonomy (vs. binary)** – Why needed: To distinguish harmful outcomes beyond simple refusal/compliance, capturing partial leakage that binary ASR hides. Quick check: “Under MUSE’s taxonomy, when is a response with disclaimers but actionable steps classified as Compliance versus Partial Compliance?”
- **Concept: Cross-modal payload generation pipeline** – Why needed: To deliver identical harmful intent via text, audio (TTS), image (rendered text), or video (composite), testing modality-specific safety gaps. Quick check: “What transformation does MUSE apply to an attacker’s text prompt to create a video payload?”
- **Concept: Provider-agnostic model routing** – Why needed: Different APIs (OpenAI, Google, Anthropic, Qwen) have varying modality support and payload formats; routing normalizes these for the attack engine. Quick check: “Where in MUSE’s architecture would you implement a new model provider’s specific API authentication and content formatting?”

## Architecture Onboarding
**Component map:** Frontend (browser UI) -> Backend core (FastAPI) -> Attack strategy engine -> Payload generator -> Model router -> Target model. Backend core also -> LLM judge. All components read/write Data model (attack_runs, batch_attack_runs, attack_turn_results).

**Critical path:** User config → run creation → attack engine → per-turn: payload generation → model router → target response → judge labeling → storage → aggregation → metrics/dashboard.

**Design tradeoffs:**
- Extensibility vs. complexity: New attack strategies require interface implementation but increase orchestration state.
- Modality coverage vs. latency: Video synthesis is slow; excluded in ablation to manage throughput.
- Judge consistency vs. cost: Single GPT-4o judge is consistent but may embed biases; human validation limited.

**Failure signatures:**
- Judge disagreement spikes: monitor per-turn label distributions.
- Modality conversion errors: check asset cache keys; PIL/FFmpeg failures cause stalls.
- Provider API throttling: watch rate-limit backoffs; ensure retry logic.

**First 3 experiments:**
1. Replicate single-turn baseline (Table 1): 50 AdvBench goals in each supported modality per model.
2. Run main red-teaming (Table 2): 5 strategies × 6 models × 50 goals; verify cumulative ASR curves.
3. Conduct ITMS ablation (Table 3): For omni-modal models, run Crescendo across 6 modality configurations; confirm model-family-specific ASR deltas.

## Open Questions the Paper Calls Out
1. **Generalization of the five-level taxonomy to human annotations:** The current validation is limited; a large-scale multi-annotator study is needed to confirm agreement and correlation with harm.
2. **Reasons for model-family-specific ITMS effects:** The paper shows opposing trends (Gemini vs. Qwen) but does not hypothesize underlying causes (e.g., training data, fine-tuning).
3. **Mitigations for partial information leakage:** No solutions proposed; need experiments testing safety techniques on soft ASR.
4. **Robustness of ITMS convergence to attacker/judge model diversification:** Current results use GPT-4o for both; generalizability unknown.
5. **Impact of native video rotation on ITMS:** Video was excluded due to latency; effect of true video modality switching remains unknown.

## Limitations
- Undisclosed multimodal prompt rephrasing and judge rubric hinder exact replication.
- Limited human validation (small sample) leaves uncertainties about the five-level taxonomy’s reliability.
- ITMS ablation excluded video due to latency, possibly biasing modality-specific conclusions.

## Confidence
- Dual-metric framework exposes partial leakage: **High**
- ITMS accelerates convergence (family‑specific effects): **Medium**
- Run‑centric architecture enables scalable red‑teaming: **Medium**

## Next Checks
1. Judge validity study: Randomly sample 200 judged responses; have domain experts apply the five-level taxonomy; measure inter-label agreement and correlation with harm.
2. ITMS mechanism isolation: Compare ITMS against random-modality baseline and fixed-modality controls; evaluate average turns to first success and final ASR.
3. Baseline replication: Using described rephrasing pipeline, generate multimodal prompt sets from 50 AdvBench goals and run single-turn tests; verify Table 1 refusal rates within ±5%.
