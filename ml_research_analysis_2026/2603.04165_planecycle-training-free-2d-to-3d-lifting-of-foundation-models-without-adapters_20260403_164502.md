# PlaneCycle: Training-Free 2D-to-3D Lifting of Foundation Models Without Adapters

## Quick Facts
- **arXiv ID:** 2603.04165  
- **Source URL:** https://arxiv.org/abs/2603.04165  
- **Reference count:** 36  
- **Primary result:** PlaneCycle (PCg) with DINOv3 ViT-B/16 achieves **87.8% average AUC** across six 3D classification benchmarks under linear probing, surpassing slice-wise 2D (85.1%) and full 3D flattening (81.7%); with fine‑tuning it reaches 91.2% AUC, matching standard 3D models.

## Executive Summary

PlaneCycle introduces a novel, training‑free operator that enables pretrained 2D foundation models (e.g., Vision Transformers) to process 3D volumetric data without any weight modifications or additional parameters. The method cyclically applies the frozen 2D backbone to orthogonal 2D slices (HW, DW, DH) of a 3D volume, progressively aggregating 3D information across network layers. By reshaping the volume into slices, processing each with the original 2D layer, and cycling the plane choice (e.g., HW→DW→DH→HW), the model builds a coherent 3D representation while preserving the base model’s inductive biases. Global tokens are handled via adaptive pooling, and for ViTs rotary positional embeddings are adjusted per plane.

Evaluated on MedMNIST classification and segmentation benchmarks, PlaneCycle (PCg variant) with DINOv3 ViT-B/16 attains **87.8% average AUC** under linear probing (frozen backbone), beating slice‑wise 2D (85.1%) and full 3D flattening (81.7%). With full fine‑tuning it reaches **91.2% AUC**, comparable to ViViT (88.8%) and other 3D models. For segmentation, zero‑training feature Dice scores improve by up to **15 points** over baselines. The approach reduces computational complexity relative to full 3D attention while maintaining the efficiency of the original 2D backbone.

## Method Summary

PlaneCycle acts as a lightweight wrapper around any pretrained 2D network. For a 3D input tensor of shape D×H×W×C, the wrapper selects one of three orthogonal planes (e.g., HW) and reshapes the volume into a batch of 2D slices along that axis. The slices are flattened into token sequences and concatenated with global tokens. Global tokens from the previous layer are pooled using adaptive average pooling to match the new number of slices. The frozen 2D backbone (e.g., a ViT block) processes the entire token set independently for each slice, effectively applying the same 2D transformation *P* times (where *P* is the number of slices). After processing, outputs are reshaped back to the 3D layout. By inserting such operators at multiple layers and cycling the plane choice (e.g., HW→DW→DH→HW), information integrates across all three volumetric dimensions. The method introduces no new parameters and works with both CNNs and ViTs; for ViTs it adds plane‑specific rotary positional embeddings and two global token strategies: global mean pooling (PCm) and grouped pooling (PCg), with PCg generally performing better.

## Key Results
- **Linear probing AUC:** PCg (DINOv3 ViT-B/16) averages **87.8%** across six MedMNIST classification datasets, exceeding slice‑wise 2D (85.1%) and full 3D flattening (81.7%).
- **Full fine‑tuning:** **91.2% AUC**, matching or surpassing standard 3D models like ViViT (88.8%).
- **Segmentation:** Zero‑training feature Dice scores improved by up to **15 points** over 2D/3D baselines.

## Why This Works (Mechanism)

PlaneCycle’s effectiveness rests on three interlocking mechanisms:

**Mechanism 1: Cyclic spatial aggregation across orthogonal planes**  
*Claim:* By cycling spatial aggregation across HW, DW, and DH planes throughout depth, the method achieves progressive 3D fusion while preserving the pretrained 2D inductive biases.  
*Mechanism:* Each operator processes a frozen 2D layer (e.g., ViT block) on all slices of a chosen plane. For a volume with *P* slices, the layer is applied *P* times independently. Over successive layers, the plane cycles (e.g., HW→DW→DH→HW), allowing information to propagate across all volumetric directions. The core assumption is that the 2D backbone’s learned patterns generalize to any orthogonal projection, and repeated cross‑plane re‑representation implicitly encodes a 3D prior. *Evidence:* The abstract states the cyclic distribution enables progressive 3D fusion; Section 2.2 details the reshaping and cycle schedule; related work (corpus) lacks direct parallels, underscoring novelty. *Break condition:* Disrupting the cycle (using a single plane) collapses performance to near the 2D slice‑wise baseline (Table 1).

**Mechanism 2: Parameter‑free reuse of frozen backbone**  
*Claim:* PlaneCycle introduces no new parameters and works in a training‑free manner by simply reshaping inputs and outputs, allowing the original 2D weights to be reused unchanged.  
*Mechanism:* The operator is a pure wrapper: reshape the 3D tensor to 2D slices, apply the frozen layer *F*θ to each slice, then reshape back. No additional weights are introduced; the backbone is applied identically *P* times per layer. Global token handling uses parameter‑free adaptive pooling. Core assumption: The distribution of token activations after reshaping and pooling remains compatible with the frozen backbone, especially during linear probing. *Evidence:* The abstract declares “introduces no additional parameters”; Section 2.2 confirms “We reuse the pretrained 2D weights…”. *Break condition:* If the backbone is highly sensitive to input distribution shifts (e.g., from HW to DW), performance degrades; the PCg variant is designed to mitigate this.

**Mechanism 3: Adaptive global token pooling**  
*Claim:* Proper handling of global (class/register) tokens during plane transitions is critical; PCm and PCg provide training‑free projections that maintain a consistent volumetric context.  
*Mechanism:* When switching planes, the number of slices (*P*) changes, causing a mismatch in global token counts per slice. The solution pools the global tokens *G*ᵢ ∈ ℝ^{P'×g×C} to *G* ∈ ℝ^{P×g×C} using adaptive average pooling. PCm pools globally across all slices; PCg pools within groups to preserve slice‑wise statistics. The pooled globals are concatenated with slice tokens before *F*θ. Core assumption: A simple statistical mapping suffices to keep the class token semantically coherent across planes. *Evidence:* Section 2.3 defines both strategies; Section 3.2 shows PCg outperforms PCm in 5/6 linear probing settings, validating the design. *Break condition:* If the backbone relies on a fixed class token position, pooling and broadcasting may disrupt it; performance gaps between PCm and PCg indicate this vulnerability.

## Foundational Learning

**Transfer Learning & Frozen Backbones**  
*Why needed here:* PlaneCycle’s value hinges on reusing a frozen pretrained 2D model; only a new classifier head is trained during linear probing. Understanding that the “3D knowledge” emerges from the frozen backbone’s features, not weight updates, is essential.  
*Quick check:* In a linear probe, are the original 2D backbone weights updated? What does this imply about where the 3D representation is formed?

**Self‑Supervised Vision Transformers (DINOv2/DINOv3)**  
*Why needed here:* The paper uses DINOv3 as backbone, which is self‑supervised and known for strong semantic alignment and robustness (e.g., via register tokens). These properties may explain why the features remain stable under orthogonal plane projections.  
*Quick check:* How might a model pretrained with contrastive or reconstruction objectives differ in response to PlaneCycle’s projections compared to a supervised ImageNet‑pretrained model?

**Volumetric Data Representation (HW, DW, DH planes)**  
*Why needed here:* 3D medical volumes (D×H×W) are fundamentally different from 2D images; slicing along different axes yields semantically distinct projections (axial, coronal, sagittal). Cyclic rotation is necessary to capture structures that are better aligned along specific directions.  
*Quick check:* Why would processing only the HW plane (axial slices) miss anatomical structures that are better aligned along the DW (coronal) or DH (sagittal) directions?

## Architecture Onboarding

**Component map (plain text):**  
1. Input (3D tensor *X*ᵢ ∈ ℝ^{D×H×W×C}, global tokens *G*ᵢ ∈ ℝ^{P'×g×C}) →  
2. Operator Wrapper (select axis *P* ∈ {D,H,W}, reshape *X*ᵢ to ℝ^{P×(DHW/P)×C}, adaptively pool *G*ᵢ to ℝ^{P×g×C}) →  
3. Core Processor (concatenate [*G*,*X*] to ℝ^{P×(g+DHW/P)×C}, apply frozen 2D layer *F*θ (e.g., ViT block) *P* times independently) →  
4. Output (split and reshape tokens back to *X*ₒ ∈ ℝ^{D×H×W×C}, *G*ₒ ∈ ℝ^{P×g×C}) →  
5. Network Integration (insert PlaneCycle operators at multiple depths with a fixed cycle schedule, e.g., HW→DW→DH→HW).

**Critical path:** Volume → Plane selection → Slice flattening → Shared 2D layer application (with global tokens) → Slice restoration → Next layer with different plane. Global token pooling occurs before each application of *F*θ.

**Design tradeoffs:**  
- *Efficiency vs. Fusion depth:* PlaneCycle reduces attention cost by a factor of the smallest dimension compared to full 3D flattening, but 3D fusion is incremental across layers, not instantaneous.  
- *Plane cycle schedule:* Assigning more HW operators exploits higher axial resolution in medical scans, but the optimal schedule for anisotropic or non‑medical data is unknown.  
- *Global token strategy:* PCg (grouped pooling) generally outperforms PCm (global mean) but adds mild complexity; naive copying fails.

**Failure signatures:**  
- Feature misalignment across planes (e.g., PCA shows scattered clusters).  
- Linear probe performance collapses to the 2D slice‑wise baseline.  
- Fine‑tuning yields no gain over baselines despite extra cost.

**First 3 experiments:**  
1. Linear probing baseline replication on MedMNIST Organ using DINOv3‑B/16; expect PCg AUC ≈86.5 (vs. 2D:85.1, 3D:81.7).  
2. Plane ablation: Replace all PlaneCycle ops with HW‑only (no cycle). Expect AUC drop >5 points, approaching 2D baseline.  
3. Pooling verification: Implement both PCm and PCg; on Nodule dataset, PCg should exceed PCm by ≥2 AUC points.

## Open Questions the Paper Calls Out

1. **How does PlaneCycle compare between CNN and ViT backbones?**  
   The paper acknowledges it is architecture‑agnostic but only evaluates ViTs. Systematic comparisons on CNNs (e.g., ConvNeXt, ResNet) are needed across the same benchmarks to understand differences in inductive bias handling.

2. **Does the cyclic schedule optimally preserve pretrained biases for all 3D modalities and resolutions?**  
   The fixed 4‑layer cycle (HW→DW→DH→HW) is heuristic; its effectiveness on non‑medical data (e.g., Kinetics videos) or highly anisotropic volumes is unknown. Potential failure modes include misaligned slice semantics or suboptimal fusion depth.

3. **What are the scalability trade‑offs for very large foundation models and high‑resolution volumes?**  
   Although theoretical complexity matches the 2D backbone (D‑fold reduction), practical overhead (memory for reshaping, RoPE indexing) and performance on billion‑parameter models (e.g., DINOv3‑7B) are not fully validated. Wall‑clock comparisons against optimized full 3D attention are lacking.

## Limitations
- RoPE indexing formulas and PCg grouping criteria are underspecified, hindering exact replication.  
- Evaluation is restricted to medical volumetric datasets; generalization to natural 3D domains (video, RGB‑D) remains untested.  
- Real‑world computational efficiency (memory, throughput) at large scales is not thoroughly measured.
