# Detecting Object Tracking Failure via Sequential Hypothesis Testing

## Quick Facts
- **arXiv ID**: 2602.12983  
- **Source URL**: https://arxiv.org/abs/2602.12983  
- **Reference count**: 40  
- **Primary result**: Provably controls false positive rate (FPR ≤ α=10%) while achieving low average detection delay (ADD) for real-time object tracking failure detection, using a lightweight, model-agnostic e‑process.

## Executive Summary
The paper introduces a formal, statistically grounded method for detecting object tracking failures in real time. By interpreting tracking as a sequential hypothesis test, the approach accumulates evidence using e‑processes, which provide anytime‑valid guarantees on false alert rates. The method is model‑agnostic and supports both supervised (using ground‑truth IoU) and unsupervised (using tracker response‑map metrics) quality signals. Evaluated on two trackers across four benchmarks, it strictly maintains the prescribed false positive rate (FPR ≤ 10%) while achieving low average detection delay (ADD), demonstrating effective and reliable failure detection without compromising safety.

## Method Summary
The method is a model‑agnostic wrapper that monitors an object tracker. For each frame, it computes a quality metric \(M_t\). For supervised evaluation, \(M_t\) is Normalized Generalized IoU (NGIoU) using ground truth; for unsupervised, it uses Peak Correlation (PC), Certainty Gain (CG), or Sharpness Gain (SG) derived from the tracker’s response map. It maintains an e‑process \(X_t = \prod_{i=1}^t (1 + \lambda_i (\epsilon - M_i))\) initialized to 1. The betting rate \(\lambda_i\) is adapted online (via aGRAPA or SF‑OGD) to maximize expected log‑growth under failure while preserving the supermartingale property. An alert triggers when \(X_t \ge 1/\alpha\). Ville’s inequality guarantees \(\mathbb{P}(\text{false alert}) \le \alpha\) for any stopping time, providing rigorous false positive control. No training is required; all updates are online and computationally lightweight.

## Key Results
- FPR strictly controlled at ≤ 10% (α=0.1) across all tested metrics and datasets; often substantially lower (e.g., 0–9.6% for NGIoU).  
- ADD ranges from ~21 to 178 frames, with supervised NGIoU generally yielding lower delays than unsupervised metrics.  
- The adaptive betting rate (SF‑OGD) improves detection speed compared to aGRAPA, especially with appropriate recency windows.

## Why This Works (Mechanism)

### Mechanism 1: Sequential hypothesis testing with e‑processes ensures anytime‑valid false positive control
The method frames failure detection as a sequential test between \(H_0\) (adequate tracking) and \(H_1\) (failure). It maintains an e‑process \(X_t\) that grows multiplicatively when the quality metric \(M_t\) falls below tolerance \(\epsilon\). Under \(H_0\), \(X_t\) is a nonnegative supermartingale, and Ville’s inequality guarantees \(\mathbb{P}(\sup_t X_t \ge 1/\alpha) \le \alpha\) for any stopping time, providing rigorous control of false alerts without assumptions on the track length. The alert condition \(X_t \ge 1/\alpha\) yields a uniformly valid test. The core assumption is that \(M_t\) is a bounded, informative signal: it should reliably drop below \(\epsilon\) when failure occurs. If \(M_t\) is insensitive (e.g., remains high despite drift), \(X_t\) may not grow, causing missed alerts even though FPR remains controlled.

Evidence anchors: Abstract states “provably containing false alerts”; Section 3.1 formalizes hypotheses; Section 3.2 discusses metric design. The broader e‑process literature (e.g., “On Continuous Monitoring…”) supports the framework.

### Mechanism 2: Adaptive betting rates accelerate evidence accumulation under failure
The multiplicative update uses a betting rate \(\lambda_t\) that determines how much evidence to add per frame. To minimize detection delay under \(H_1\), \(\lambda_t\) is chosen to maximize the expected log‑growth of \(X_t\) given past data. Two algorithms are proposed: aGRAPA estimates mean and variance of recent \(M_i\) to set \(\lambda_t\) (Eq. 12); SF‑OGD uses stochastic gradient descent on log‑loss (Eq. 13). Both are clipped to \([0, 1/(2\epsilon)]\) to preserve the e‑process supermartingale property. By adapting to recent trends (e.g., decreasing \(M_t\)), they increase \(\lambda_t\) when failure is likely, speeding up the growth of \(X_t\) and reducing ADD. The recency window \(w_E\) balances responsiveness and stability.

Evidence: Abstract mentions “quickly identifies when tracking failures set in”; Section 3.3 derives the methods; Figure 6 shows SF‑OGD generally yields lower ADD and is less sensitive to \(w_E\) than aGRAPA.

### Mechanism 3: Metric choice trades off reliability (supervised) against applicability (unsupervised)
The quality metric \(M_t\) directly determines sensitivity to failure. Supervised metrics like NGIoU compare tracker output to ground truth, providing a direct measure of accuracy. They are reliable and yield low ADD but require ground truth, limiting use to offline evaluation or simulation. Unsupervised metrics (PC, CG, SG) rely solely on the tracker’s response map and are applicable in deployment without ground truth. However, they can be less sensitive: for instance, peak correlation may remain high even when the tracker drifts (Figure 5), causing delayed or missed alerts. The trade‑off: supervised metrics offer better detection performance; unsupervised metrics sacrifice some sensitivity for broader applicability. The e‑process framework remains valid regardless of metric choice, as long as the metric is bounded and appropriately calibrated with \(\epsilon\).

Evidence: Table 2 shows NGIoU typically achieves lower ADD than unsupervised metrics; Figure 5 demonstrates PC’s insensitivity; Open Question 2 calls for improved unsupervised metrics.

## Foundational Learning
1. **Sequential Hypothesis Testing** – Needed to make decisions on streaming data without a fixed sample size, allowing early stopping. Quick check: Does the test allow anytime stopping while controlling Type‑I error? (Yes, via e‑process/Ville’s inequality.)  
2. **E‑process** – A supermartingale‑like sequence that under \(H_0\) yields valid p‑values at any time. Quick check: Is \(X_t\) nonnegative and \(\mathbb{E}[X_t|\mathcal{F}_{t-1}] \le X_{t-1}\) under \(H_0\)?  
3. **Supermartingale & Ville’s Inequality** – Provide the theoretical backbone: a nonnegative supermartingale cannot exceed a threshold too often with high probability, regardless of stopping rule. Quick check: Does the bound \(\mathbb{P}(\sup_t X_t \ge 1/\alpha) \le \alpha\) hold? (Shown via Ville.)  
4. **Betting Strategies / Optimization** – The betting rate \(\lambda_t\) determines how aggressively evidence is accumulated; optimizing it reduces detection delay while preserving the e‑process property. Quick check: Is \(\lambda_t\) clipped to \([0, 1/(2\epsilon)]\) to maintain supermartingale?  
5. **Tracking Quality Metrics (NGIoU, PC, CG, SG)** – Provide the per‑frame signal \(M_t\); must be bounded and sensitive to failures. Quick check: Is \(M_t\) in a known range (e.g., [0,1]) and does it drop when failure occurs on sample videos?

## Architecture Onboarding
**Component map**:  
Tracker → (predictions / response maps) → Metric computation → λ_t update (using recency window) → E‑process update → Alert decision  

**Critical path**:  
1. Receive frame \(t\).  
2. Run tracker to get prediction box and/or response map.  
3. Compute quality metric \(M_t\) (NGIoU if ground truth available; else PC/CG/SG).  
4. Optionally smooth \(M_t\) (exponential smoothing factor 0.25).  
5. Update \(\lambda_t\) using aGRAPA or SF‑OGD over recent smoothed metrics (window \(w_E\)).  
6. Update e‑process: \(X_t = X_{t-1} \cdot (1 + \lambda_t (\epsilon - M_t))\).  
7. If \(X_t \ge 1/\alpha\), trigger failure alert.  
8. Repeat for next frame.

**Design tradeoffs**:  
- Supervised vs unsupervised metric: supervised (NGIoU) gives better sensitivity but needs ground truth; unsupervised (PC, CG, SG) works without GT but may miss subtle failures.  
- Betting rate algorithm: aGRAPA (simpler, running stats) vs SF‑OGD (gradient‑based, usually lower ADD but requires learning‑rate tuning).  
- Recency window \(w_E\): smaller window → faster reaction but higher variance in \(\lambda_t\); larger window → stable but slower to abrupt changes.  
- Tolerance \(\epsilon\): defines “adequate” tracking; too low increases misses, too high increases false alerts.

**Failure signatures**:  
- False positive: \(X_t\) grows without true failure (e.g., noisy \(M_t\), low \(\epsilon\)); alert in pre‑failure region.  
- False negative: \(X_t\) fails to grow during failure (e.g., \(M_t\) stays above \(\epsilon\), or \(\lambda_t\) too small).  
- Slow detection: \(X_t\) grows but takes many frames to cross threshold (conservative \(\lambda_t\) or small deviation).

**First three experiments**:  
1. **Baseline e‑process with fixed λ**: Implement constant \(\lambda\) (e.g., 0.5) and NGIoU; run on a few videos with known failures to verify that \(X_t\) grows only during failures and FPR ≤ α over many noise‑augmented trials.  
2. **Compare supervised vs unsupervised**: Using SF‑OGD, evaluate NGIoU and PC on a small set; measure ADD and FPR; expect NGIoU to have lower ADD, both to control FPR.  
3. **Sensitivity to recency window \(w_E\)**: With SF‑OGD, vary \(w_E\) (5, 10, 20 frames) on a video with clear failure; plot \(X_t\) and observe impact on ADD; confirm that too large \(w_E\) delays detection, too small may cause spurious growth.

## Open Questions the Paper Calls Out
1. **Integration with tracker adaptation**: How can failure detection be coupled with automated tracker adaptation (e.g., re‑initialization) while preserving the e‑process’s statistical guarantees? Adaptation may violate the supermartingale property of \(X_t\).  
2. **Design of better unsupervised metrics**: What unsupervised signals (hand‑crafted or learned) can achieve sensitivity comparable to NGIoU, especially in failure modes where current metrics (e.g., peak correlation) remain high?  
3. **Extension to multi‑object tracking**: How to adapt the sequential framework to MOT, where failure is a system‑level concept (e.g., ID switches) and requires aggregating multiple per‑object metrics into a single \(M_t\) or using multiple e‑processes with appropriate correction?  
4. **Automatic setting of ground‑truth failure window \(w_{\text{GT}}\)**: The definition of true failure uses a fixed consecutive‑frame requirement \(w_{\text{GT}}\) (2 seconds or 10 frames). How does this choice affect FPR and ADD, and can it be set automatically based on video characteristics?

## Limitations
- Simulation parameters (e.g., magnitude of Gaussian noise added in N_trials) are unspecified, hindering exact reproducibility.  
- Protocol for handling videos with multiple failure events (recovery and re‑failure) is not clearly defined, potentially affecting FPR/ADD computation.  
- Unsupervised metrics may be insensitive to certain failure modes (e.g., visual drift where peak correlation remains high), leading to missed alerts despite valid FPR control.

## Next Checks
1. **Noise quantification**: Specify the standard deviation σ for the added Gaussian noise in N_trials; conduct sensitivity analysis over a range (e.g., σ = 0.001–0.05) to ensure noise does not alter tracker behavior or metric distributions.  
2. **Failure segment protocol**: Define a clear rule for videos with multiple failure segments (e.g., consider only the first failure, or treat each sustained drop below ε as a separate event). Re‑evaluate FPR and ADD under this rule.  
3. **Metric stress‑test**: Evaluate existing unsupervised metrics (PC, CG, SG) on failure cases where the tracker’s response map remains high despite visual drift (as in Figure 5). If detection delays are excessive, explore new unsupervised metrics or combinations.
