# Chained Prompting for Better Systematic Review Search Strategies

## Quick Facts
- arXiv ID: 2602.00011
- Source URL: https://arxiv.org/abs/2602.00011
- Reference count: 17
- Primary result: Chained prompting with GPT‑4o‑mini achieves average recall of 0.90 on systematic review search strategy generation, a 362% relative improvement over LEADS (0.24) and a 10% gain over LEADS+ensemble (0.82).

## Executive Summary
Systematic reviews require effective search strategies to identify all relevant studies, but manual construction is time‑consuming and prior automated methods often yield low recall. This paper introduces an LLM‑based chained prompt engineering framework that decomposes the search strategy formulation into sequential stages: (1) objective reformulation from the review’s title/abstract, (2) PICO element extraction, (3) domain concept identification, (4) keyword expansion, and (5) Boolean query construction. Evaluated on a filtered subset of the LEADSInstruct dataset (81 PubMed‑indexed systematic reviews), the full pipeline achieves an average recall of 0.90, substantially outperforming the previous state‑of‑the‑art LEADS (0.24) and LEADS+ensemble (0.82). The framework also produces higher‑quality PICO elements, providing a stronger foundation for high‑recall queries.

## Method Summary
The authors address the problem of automatically generating high‑recall literature search queries for systematic reviews. They use the LEADSInstruct dataset, which contains PubMed‑indexed systematic reviews along with titles, abstracts, list of included studies (PMIDs), and machine‑generated PICO elements. After filtering to reviews published 2012–2016 with ≤1,000 citations and no API retrieval errors, 81 reviews remain. The core method is a four‑stage chain of prompts executed with GPT‑4o‑mini, preceded by an objective reformulation step in the “full pipeline”: first, a structured objective is synthesized from the title/abstract; then PICO elements are extracted; next, domain‑specific concepts are identified; then each concept is expanded into a set of keywords/synonyms; finally, a Boolean query string is assembled using OR within concepts and AND between them. The generated query is run against PubMed via its API, retrieved PMIDs are compared to the ground‑truth included set, and recall is computed. Key implementation details such as exact prompt templates are not disclosed, requiring reconstruction. The evaluation metric is recall only; precision is not reported.

## Key Results
- Average recall of the full pipeline: **0.90**, compared to LEADS (0.24) and LEADS+ensemble (0.82).
- Starting from LEADS‑provided PICO (i.e., omitting the objective reformulation step) yields recall 0.62, demonstrating the importance of the initial reformulation module.
- Error analysis revealed that manual replacement of automatically derived objectives with protocol‑based objectives restored perfect recall in three problematic cases, underscoring the sensitivity to objective quality.

## Why This Works (Mechanism)
### Mechanism 1: Decomposition reduces cognitive load and error propagation
**Claim:** Breaking the complex task of search strategy formulation into sequential, focused sub‑tasks improves recall by limiting the scope of each transformation and preventing error accumulation.  
**Mechanism:** The chain prompts the LLM to perform one specialized transformation per step (PICO extraction → concept mapping → keyword expansion → Boolean assembly). This modularization allows the model to concentrate on a narrower objective with a defined output structure, leading to richer and more precise intermediate results than a single, broad prompt.  
**Core assumption:** An LLM can perform specialized text transformations more reliably when constrained to a single, well‑defined instruction format and output schema per stage.  
**Evidence anchors:** [abstract] “decomposes the task into sequential stages: PICO element extraction, concept identification, keyword generation, and Boolean query construction.”; [section III.B] details the four distinct prompt steps, each with a system/user prompt pair and structured output.  
**Break condition:** If an early stage (e.g., PICO extraction) produces a fundamentally incorrect or incomplete structure, all subsequent stages build on a flawed foundation, leading to catastrophic recall failure.

### Mechanism 2: Progressive refinement expands lexical coverage
**Claim:** Layered enrichment of search terms across stages systematically expands the lexical coverage of the query, capturing synonyms and related concepts essential for high recall.  
**Mechanism:** Starting from structured PICO elements (Step 1), the pipeline maps them to domain‑specific concepts (Step 2) and then expands each concept into a set of keywords/variants (Step 3). This deliberate layering ensures that the final Boolean query (Step 4) contains a broad OR‑grouped set of terms for each core concept, rather than a limited set derived in one step.  
**Core assumption:** A concept‑based expansion (PICO → Concepts → Keywords) is more effective for recall than directly mapping PICO to keywords or using a monolithic prompt.  
**Evidence anchors:** [section III.B.3] “This step enriches the search space by including synonyms, spelling variants, and related terminologies, ensuring higher recall.”; [section IV.B] higher recall (0.87) is achieved with the full pipeline versus starting from LEADS PICO (0.62), demonstrating the value of the concept/keyword expansion steps.  
**Break condition:** If keyword generation (Step 3) fails to include critical synonyms or uses non‑standard terminology that does not match the indexing in target databases (e.g., MeSH terms), recall suffers despite a well‑structured Boolean syntax.

### Mechanism 3: Objective reformulation provides a higher‑quality foundation
**Claim:** Re‑formulating a clear, structured objective from the review’s title/abstract before PICO extraction yields a more accurate PICO structure than using the raw title/abstract or pre‑generated PICO elements.  
**Mechanism:** The “full pipeline” adds an initial step to synthesize a precise objective string. The authors’ engineered prompt for this step appears better at capturing the review’s true scope than the implicit objective used by LEADSInstruct’s pre‑generated PICO. This leads to more accurate PICO elements in Step 1, which propagates through the chain.  
**Core assumption:** The quality of the initial textual objective is a primary determinant of final search strategy recall; a structured, LLM‑generated objective can correct for ambiguities in a title/abstract.  
**Evidence anchors:** [section IV.B] Full pipeline recall: 0.87. Pipeline starting from LEADS‑provided PICO: 0.62. Authors attribute this gain to their objective reformulation prompt.; [section IV.D.3] Error analysis: “In three cases, the automatically derived objectives… were insufficient… When we manually replaced these with… objectives… recall to 1.0.”  
**Break condition:** If the review’s title/abstract is ambiguous, missing key methodological details (e.g., comparator, specific outcome), or poorly written, the LLM’s reformulated objective may be incorrect or incomplete, dooming the pipeline.

## Foundational Learning
- **PICO Framework (Population, Intervention, Comparison, Outcome)**  
  *Why needed:* It is the foundational taxonomic structure the entire pipeline is designed to extract, refine, and operationalize. Understanding PICO is necessary to interpret the model’s outputs at each stage and to debug failures.  
  *Quick check:* Given a clinical research question, can you correctly identify which component corresponds to “patients with diabetes” (Population), “metformin” (Intervention), “placebo” (Comparison), and “HbA1c reduction” (Outcome)?

- **Boolean Logic & Proximity Operators in Literature Search**  
  *Why needed:* The final output is a Boolean query string. Understanding OR (synonym expansion), AND (concept intersection), and proximity operators (e.g., NEAR, adjacency) is essential to evaluate whether the generated query correctly represents the intended search logic and to adapt it for different databases.  
  *Quick check:* How would you combine “myocardial infarction” OR “heart attack” with “aspirin” using Boolean operators to find studies discussing either term for the heart condition with the drug?

- **Prompt Chaining / multi‑stage LLM workflows**  
  *Why needed:* The core innovation is the chained prompting architecture. One must understand why and how to break a complex IR task into dependent sub‑tasks with constrained outputs, rather than relying on a single, end‑to‑end prompt.  
  *Quick check:* What are two potential risks of using a single prompt to generate a complete Boolean query from a research objective, and how does chaining mitigate them?

## Architecture Onboarding
- **Component map:** Objective Reformulation → PICO Extraction → Concept Identification → Keyword Expansion → Query Synthesis → (External: PubMed API execution & evaluation)
- **Critical path:** Objective Reformulation → PICO Extraction → Concept Identification → Keyword Expansion → Query Synthesis.
- **Design tradeoffs:**  
  • Speed vs. Recall: The chained approach incurs 4–5 LLM calls, slowing execution compared to a single‑call method, but yields higher recall.  
  • Generality vs. Structure: Strict JSON‑like output formats enable automated parsing but may restrict LLM expressivity.  
  • Model Choice: GPT‑4o‑mini used for cost/availability; architecture is model‑agnostic, and a more powerful model might further improve performance.
- **Failure signatures:**  
  • PICO Extraction Failure: Missing or merged fields (e.g., Intervention and Outcome combined).  
  • Concept Over/Under‑generation: Too many vague concepts or too few specific ones, leading to noisy or incomplete queries.  
  • Keyword Truncation/Synonym Gap: Absence of critical domain synonyms or controlled vocabulary (e.g., MeSH terms).  
  • Query Syntax Error: Incorrect Boolean nesting, missing parentheses, or invalid operators.
- **First 3 experiments:**  
  1. **Isolate Stage 1 Performance:** Run the pipeline using gold‑standard objectives from protocols instead of auto‑generated ones; measure recall gain vs. full auto pipeline to quantify marginal contribution of objective reformulation.  
  2. **Ablation Study - Keyword Expansion:** Replace Step 3 (Keyword Expansion) with a simple synonym generator (e.g., WordNet) or use concept terms directly; measure recall drop to validate LLM‑based context‑aware expansion.  
  3. **Prompt Sensitivity Test:** Create 2‑3 variants of the PICO extraction prompt (e.g., with/without examples, different phrasing); run on a 10‑review subset; compare PICO accuracy (F1 vs. human) and final recall to assess robustness and identify minimal effective design.

## Open Questions the Paper Calls Out
### Open Question 1
**Question:** How does the chained prompting pipeline generalize to other bibliographic databases (e.g., Embase, Cochrane Library) beyond PubMed?  
**Basis in paper:** The conclusion states that future work will focus on extending the approach to additional bibliographic databases beyond PubMed, indicating that current evaluation is limited to PubMed.  
**Why unresolved:** The paper only evaluates on PubMed‑indexed systematic reviews via LEADSInstruct, so performance on other databases with different indexing systems and controlled vocabularies is unknown.  
**What evidence would resolve it:** Re‑running the pipeline on equivalent datasets from other databases (e.g., using their APIs) and comparing recall and precision metrics.

### Open Question 2
**Question:** What specific aspects of prompt engineering design are responsible for the significant improvement in PICO extraction quality compared to LEADS?  
**Basis in paper:** The results show that using their engineered prompt instead of LEADS' prompt improves recall from 0.62 to 0.87, but the paper does not analyze which prompt elements drive this difference.  
**Why unresolved:** The comparison is between two end‑to‑end prompts without ablation studies to isolate contributing factors, making it unclear which design principles are critical.  
**What evidence would resolve it:** Conducting controlled experiments varying prompt components (e.g., step‑by‑step instructions, output format specifications, few‑shot examples) to measure impact on PICO extraction accuracy.

### Open Question 3
**Question:** Can the objective reformulation step be automated more robustly to eliminate errors arising from reliance solely on titles and abstracts?  
**Basis in paper:** Error analysis reveals that in three of five low‑recall cases, automatically derived objectives from titles/abstracts were insufficient, and manual reformulation using protocols achieved perfect recall.  
**Why unresolved:** The current pipeline uses a single prompt to generate objectives from titles/abstracts, which may miss nuances captured in full protocols; no alternative automated methods are explored.  
**What evidence would resolve it:** Developing and testing new prompting strategies that incorporate additional context (e.g., full review texts, protocol sections) or external knowledge sources to generate more comprehensive objectives.

### Open Question 4
**Question:** How does the pipeline handle systematic reviews with non‑standard terminology or highly specialized jargon that deviates from common medical vocabulary?  
**Basis in paper:** One error case involved terminology mismatch (e.g., “workers” vs. “adults”), suggesting the keyword generation step may fail to capture domain‑specific or informal terms.  
**Why unresolved:** The pipeline’s keyword expansion relies on standard synonyms and variants; it is unclear if it can adapt to unconventional phrasing without manual intervention.  
**What evidence would resolve it:** Evaluating the pipeline on a subset of reviews with known terminology variations (e.g., occupational health studies using lay terms) and measuring recall differences; testing modifications like incorporating term clustering or user‑provided glossaries.

## Limitations
- **Prompt opacity:** Exact stage prompts are not disclosed; reproduction requires inference, risking drift from the intended implementation.
- **Dataset constraints:** Evaluation on only 81 systematic reviews (2012‑2016, ≤1,000 citations) limits generalizability to modern or highly cited reviews and increases result variance.
- **Metric narrowness:** Only recall is reported; precision and F1‑score are unknown, obscuring the trade‑off between sensitivity and specificity.

## Confidence
- Decomposition improves recall (Mechanism 1): **Medium‑High** – supported by ablation and error analysis, though isolated stage impact not fully quantified.
- Progressive expansion (Mechanism 2): **Medium** – comparison with LEADS‑PICO baseline suggests value, but concept identification quality not directly tested head‑to‑head.
- Objective reformulation (Mechanism 3): **High** – manual substitution restored perfect recall in error cases, providing strong causal evidence.
- Overall reported recall (0.90): **Medium‑High** – directly measured on specified subset, but limited dataset and potential prompt inconsistencies reduce certainty.

## Next Checks
