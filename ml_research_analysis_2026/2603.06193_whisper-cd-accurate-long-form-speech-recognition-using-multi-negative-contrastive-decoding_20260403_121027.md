# Whisper-CD: Accurate Long-Form Speech Recognition using Multi-Negative Contrastive Decoding

## Quick Facts
- arXiv: 2603.06193
- Source: https://arxiv.org/abs/2603.06193
- Reference count: 0
- Primary result: Training-free contrastive decoding reduces WER by up to 24.3 pp and improves decoding throughput by 48% compared to beam search on long-form English speech recognition.

## Executive Summary
Whisper-CD is a training‑free inference‑time framework that mitigates hallucinations, repetition loops, and content omissions in Whisper’s long‑form speech recognition. It introduces contrastive decoding by comparing logits from clean audio against those from three acoustically perturbed inputs (Gaussian noise, silence, and temporal shift). The negatives are aggregated via a log‑sum‑exp operation and combined with clean logits to guide token‑by‑token greedy decoding. Evaluated on five English long‑form benchmarks, Whisper-CD achieves substantial WER reductions (up to 24.3 percentage points on CORAAL) and a 48% throughput improvement over beam search, all without retraining the underlying model.

## Method Summary
At inference, audio is split into 30‑second segments. For each segment, four parallel forward passes are executed: one clean audio path and three perturbed paths (additive Gaussian noise at 10 dB, all‑silence spectrogram, and a leftward temporal shift by 7 seconds). The encoder outputs are computed in a batch, and autoregressive decoding proceeds with four decoder states sharing prefix tokens. At each decoding step, clean logits ℓ_pos and negative logits ℓ_negₖ from each perturbed path are extracted. The contrastive decoding logits are formed as ℓ_CD = (1+α)ℓ_pos − α·log((1/K)∑exp(ℓ_negₖ/τ)), with α typically set to 1.0 and τ=1.0. The next token is sampled greedily from ℓ_CD. This process repeats across segments, using previously generated text as context.

## Key Results
- Reduces word error rate (WER) by up to 24.3 percentage points on CORAAL.
- Improves decoding throughput by 48% compared to beam search.
- Requires no model retraining; works with pretrained Whisper checkpoints.

## Why This Works (Mechanism)
Whisper‑CD exploits the observation that hallucinated tokens are often not robust to acoustic perturbations. By contrasting clean logits against those from perturbed inputs, tokens that are highly sensitive to distortions (i.e., likely spurious) are suppressed. The three perturbations target distinct failure modes: Gaussian noise reveals tokens that appear spuriously in quiet contexts, silence prevents output when no speech is present, and temporal shift encourages consistency across time. The log‑sum‑exponential aggregate (with temperature τ) smoothly approximates the maximum negative logit, avoiding over‑penalization from a single outlier. The coefficient α balances the contrast strength; its optimal value varies across datasets. This token‑level adjustment during greedy decoding effectively reduces repetition, omissions, and false insertions while maintaining high speed.

## Foundational Learning
- **Contrastive Decoding**: Adjusts token probabilities by comparing a clean input with perturbed negatives. *Why needed*: Suppresses tokens that are not robust to acoustic variations, which often correlate with hallucinations. *Quick check*: What effect would using only one negative have compared to three?
- **Log‑Sum‑Exp (LSE)**: A smooth approximation to the maximum (or average) of a set of values. *Why needed*: Provides a differentiable way to aggregate negative logits without extreme penalties from single outliers. *Quick check*: How does temperature τ influence the LSE? (Higher τ ≈ average, lower τ ≈ max.)
- **Greedy Decoding**: Selects the token with highest probability at each step. *Why needed*: Keeps computational cost low and aligns with the reported throughput gains. *Quick check*: Why not combine Whisper‑CD with beam search? (Would multiply the number of paths and increase cost.)
- **Audio Perturbations (Noise, Silence, Shift)**: Techniques to create negative inputs. *Why needed*: Each targets a specific hallucination pattern (e.g., noise captures spurious tokens, silence prevents output in quiet, shift enforces temporal consistency). *Quick check*: Which perturbation is most effective at reducing repetition loops?
- **Long‑Form ASR Segmentation**: Splitting audio into fixed‑length chunks (30 s). *Why needed*: Whisper’s encoder is trained on 30 s segments; long audio must be processed with overlapping or contiguous chunks and context carryover. *Quick check*: How would using a different segment length affect hallucination frequency?

## Architecture Onboarding
**Component Map**:  
Raw audio → 30 s segmentation → Four parallel branches (clean, Gaussian noise, silence, temporal shift) → Whisper encoder (shared weights) → Whisper decoder (four parallel autoregressive paths sharing prefix tokens) → Logit extraction → Contrastive aggregation (ℓ_CD formula) → Token sampling (greedy) → Text output.

**Critical Path**:  
The decoding loop for each segment: (1) batch‑encode all four inputs; (2) for each decoding step, compute clean and negative logits via the decoder; (3) aggregate via ℓ_CD; (4) sample next token; (5) update all decoder states. The steps repeat until an end‑of‑text token is produced, then the next segment begins with previous text as context.

**Design Tradeoffs**:  
- *Number of negatives*: More perturbations can improve robustness but increase computational cost (4× encoder passes).  
- *Hyperparameter α*: Controls contrast strength; too high harms clean speech accuracy (e.g., TED‑LIUM degradation), too low yields insufficient suppression. Requires per‑dataset tuning.  
- *Segment length*: Fixed at 30 s by Whisper’s training; longer segments could reduce context fragmentation but exceed memory limits.  
- *Decoding strategy*: Greedy used for speed; beam search could be layered but would multiply paths and cost.

**Failure Signatures**:  
- Repetition loops persisting in output (especially with Whisper large‑v3).  
- WER degradation on certain datasets when α is too high (e.g., TED‑LIUM).  
- Throughput slowdown if token count reduction does not offset the 4× encoder cost (observed in large‑v3‑turbo).  
- Omission of content if the contrastive term over‑penalizes valid tokens.

**First Three Experiments**:  
1. **Baseline replication**: Run Whisper large‑v3 on a small subset of CORAAL using the default long‑form pipeline; verify baseline WER and throughput.  
2. **Single‑negative test**: Implement Whisper‑CD with only Gaussian noise perturbation (α=1.0); compare to baseline to isolate the effect of contrastive decoding.  
3. **Full perturbation sweep**: Run Whisper‑CD with all three negatives across α ∈ {0.5, 1.0, 1.5, 2.0} on all five benchmarks; record WER and tokens/second to identify optimal α per dataset and validate the reported improvements.
