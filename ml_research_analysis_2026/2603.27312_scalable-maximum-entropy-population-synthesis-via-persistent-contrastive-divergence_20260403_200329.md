# Scalable Maximum Entropy Population Synthesis via Persistent Contrastive Divergence
## Quick Facts
- arXiv ID: 2603.27312
- Source URL: https://arxiv.org/abs/2603.27312
- Reference count: 40
- Primary result: Scales to K=50 categorical attributes (|X| grows 18 orders) with mean relative error 0.010–0.018 and runtime O(K), while achieving an 86.8× effective sample size advantage over generalized raking on Syn-ISTAT.

## Executive Summary
Maximum entropy population synthesis creates realistic synthetic microdata from aggregate census constraints but suffers from a computational bottleneck: exact expectation computation becomes infeasible beyond about K=20 categorical attributes due to the exponential tuple space. This paper introduces GibbsPCDSolver, which replaces exact summation with a stochastic estimate using a persistent pool of synthetic individuals advanced by Gibbs sweeps via Persistent Contrastive Divergence. The method maintains competitive accuracy (mean relative error ~0.01–0.03) while scaling linearly with the number of attributes K rather than the tuple space size |X|. Crucially, it preserves population diversity: the effective sample size equals the pool size N, whereas competing methods like generalized raking suffer severe degeneracy (Neff ≈ 0.012N), making the approach viable for agent-based urban simulations.

## Method Summary
GibbsPCDSolver optimizes a maximum entropy model defined by aggregate constraints using an exponential family formulation pλ(x) ∝ exp(∑ λj fj(x)). Instead of enumerating all possible tuples, it maintains a persistent pool of N synthetic individuals. Each outer iteration advances the pool by s Gibbs sweeps (Glauber dynamics), where each attribute is updated conditioned on the others. The model expectations Epλ[fj] are estimated from the pool's empirical frequencies. The gradient g = (α̂ − α) updates the natural parameters λ via Adam. Efficient per-sweep computation is achieved by precomputing a `lookup` structure that maps each attribute to the constraints it participates in, allowing vectorized energy evaluation without scanning the full constraint set. The pool persists across iterations, reducing bias compared to contrastive divergence with reinitialization and ensuring the final synthetic population has full effective sample size Neff = N.

## Key Results
- Scales to K=50 attributes (|X| ~ 10¹⁸) with mean relative error (MRE) in [0.010, 0.018] and runtime scaling as O(K).
- On Syn-ISTAT (K=15, |X|≈1.7×10⁸), achieves MRE=0.030 on training constraints.
- Produces populations with effective sample size Neff = N, an 86.8× diversity advantage over generalized raking (Neff≈0.012N), essential for agent-based simulations.

## Why This Works (Mechanism)
### Mechanism 1: Stochastic Expectation via Persistent Pool
*Claim*: GibbsPCDSolver scales with K and N rather than |X| because it replaces exact enumeration with a stochastic estimate from a persistent Gibbs pool.  
*Mechanism*: A pool of N synthetic individuals is maintained across iterations. At each gradient step, the pool is advanced by s Gibbs sweeps; the empirical frequencies of constraint features in the pool approximate the model expectations Epλ[fj].  
*Core assumption*: The persistent Markov chain, with appropriate s and λ update schedule, remains approximately stationary relative to pλ, providing an unbiased (or low-bias) gradient estimate.  
*Evidence anchors*: [abstract] describes the persistent pool and Gibbs sweeps; [section 3.2] Proposition 1 derives Gibbs conditionals and Algorithm 1 implements the update.  
*Break condition*: Mixing is poor or N too small → pool distribution deviates from pλ, causing MRE to plateau above 1/(2√N) or diverge.

### Mechanism 2: Efficient Gibbs Conditionals via Factored Exponential Family
*Claim*: Each Gibbs update for an attribute requires only O(dk·|lookup[k]|) operations, avoiding O(|X|).  
*Mechanism*: From pλ(x) ∝ exp(∑ λj fj(x)), the conditional pλ(Ak=v | rest) ∝ exp(∑_{j∈J(k,v,rest)} λj). Precomputed `lookup[k]` maps attribute k to constraints it participates in, enabling vectorized energy computation over the pool.  
*Core assumption*: Constraint matrix is sparse enough that |lookup[k]| ≪ |X|; domain sizes dk are modest.  
*Evidence anchors*: [section 3.2] Proposition 1 and Algorithm 1 line 6 show conditional derivation and vectorized accumulation.  
*Break condition*: Constraints become dense → lookup[k] grows, per-sweep cost approaches O(|X|), losing scalability.

### Mechanism 3: Persistence Reduces Bias and Maintains Diversity
*Claim*: Persistence of the pool across gradient steps yields a lower-bias estimate than reinitializing (CD-k) and ensures the synthetic population has full effective sample size Neff = N.  
*Mechanism*: The pool acts as a persistent Markov chain; as λ updates slowly via Adam, the chain continues from its previous state, better tracking the current model distribution. Uniform pool weights avoid raking's weight collapse.  
*Core assumption*: Persistence time is long enough for the chain to mix between λ updates; Adam step sizes are small.  
*Evidence anchors*: [section 2.4] describes Persistent Contrastive Divergence; [section 5.3] shows Neff = N vs. raking's Neff ≈ 0.012N.  
*Break condition*: λ changes too fast or s too small → pool becomes stale, increasing bias; if N too small, variance dominates.

## Architecture Onboarding
- **Component map**: Constraint processor → precomputes `lookup[k]` for each attribute k → Pool manager → holds N×K array of synthetic individuals → Gibbs sweep engine → updates each attribute using `lookup[k]` and λ → Expectation estimator → computes empirical α̂ from pool → Optimizer wrapper → Adam updates λ → Stopping monitor → checks MRE improvement.
- **Critical path**:  
  1. Precompute `lookup` from constraint set.  
  2. Initialize λ=0, pool uniformly.  
  3. Outer loop: advance pool by s Gibbs sweeps (shuffle attributes, compute energies via `lookup`, sample new values).  
  4. Estimate α̂ from pool; compute gradient g = α̂ − α.  
  5. Adam update λ.  
  6. Update MRE history; break if relative improvement < τ.
- **Design tradeoffs**:  
  - Pool size N: Larger N ↓ variance (MRE floor ~1/(2√N)) but ↑ per-iteration cost; sweet spot N≈25k–100k for K~15.  
  - Sweeps s: More sweeps ↓ mixing bias but ↑ time; s=1 for sparse binary, s=5 for mixed arity at K=15.  
  - Learning rate η: Smaller η stabilizes complex constraints; default 0.01 for K≥15. η=0.05 oscillates with ternaries.  
  - Acceleration: Numba JIT critical for K≥20 (5–15× speedup).
- **Failure signatures**:  
  - MRE plateaus above 1/(2√N) → mixing bias (increase s) or N too small.  
  - MRE oscillates/diverges → η too high or s too low.  
  - Raking degeneracy (Neff ≪ N) → contrast to GibbsPCD's full Neff.  
  - Constraint violation after initial decrease → pool collapse (increase N or s).
- **First 3 experiments**:  
  1. Controlled validation (A0, A1a, A1b): Compare against exact L-BFGS on K=6,8,10; validate MRE/KL convergence and variance floor.  
  2. Scaling experiment (sec 5.1): K∈{12,20,30,40,50}, ternary patterns; show MRE∈[0.010,0.018] while |X| grows 18 orders; confirm O(K) runtime; demonstrate raking failure at K=40.  
  3. Held-out generalization (sec 5.2): Train on unary+binary only; evaluate on ternary constraints; show GibbsPCDSolver outperforms raking on high-degree node ternary (T3).

## Open Questions the Paper Calls Out
- **Heterogeneous constraint universes**: How to handle constraints that apply to different subpopulations (e.g., marital status only for adults)? The current method assumes a single reference population; a conditional gradient estimator restricted to relevant subpools is proposed but not implemented.
- **Deep generative model integration**: Can deep generative models (VAEs, flows) be combined with aggregate-constrained synthesis? Deep models typically need individual microdata, while MaxEnt needs only aggregates; a hybrid could leverage limited microdata for richer representations.
- **GPU acceleration**: Can batched GPU evaluation of Gibbs conditionals further accelerate the solver? Even with Numba, runs at K=15, N=100k take ~23 minutes; parallelizing Gibbs sweeps across many samples on a GPU is an open engineering problem.

## Limitations
- Exact atomic feature enumeration (fⱼ) is not specified; reproduction depends on provided code.
- Random seeds and full hyperparameter schedules (e.g., stopping window W) are not disclosed; reported metrics may have unquantified variance.
- O(K) scalability claim assumes constraint sparsity; performance under denser constraint sets (many high-order interactions) is not evaluated.

## Confidence
- Stochastic expectation via persistent pool: **High** (clear mechanism, Proposition 1, Neff=N validation).
- Efficient Gibbs conditionals: **Medium** (derivation solid, but real-world sparsity of `lookup[k]` not quantified).
- Persistence reduces bias: **Medium** (Neff advantage convincing, but direct ablation vs. CD-k not shown).
