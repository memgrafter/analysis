# Modeling Programming Skills with Source Code Embeddings for Context-aware Exercise Recommendation

## Quick Facts
- arXiv ID: 2602.10249  
- Source URL: https://arxiv.org/abs/2602.10249  
- Reference count: 25  
- Primary result: Jina source code embeddings achieve mean skill prediction accuracy of 0.69, outperforming TF-IDF, CodeBERT-cpp, and GraphCodeBERT, and the skill-based recommendation yields a higher percentage of suitable exercises than baselines.

## Executive Summary
This paper presents a system for personalizing programming homework in large introductory courses. It models student skill progression using source code embeddings from recent lab submissions. The core method selects the embedding closest to the centroid of a student’s latest lab, predicts proficiency across eight programming topics with independent MLP classifiers, and recommends exercises by ranking via cosine similarity between predicted skill vectors and problem skill vectors. Evaluated across seven course offerings, the approach demonstrates superior skill prediction accuracy and recommendation suitability compared to baselines based on solution correctness or time.

## Method Summary
The pipeline consists of four steps:  
1. **Encoding**: Each student code submission is processed by `jina-embeddings-v2-base-code` to produce a 768-dimensional vector.  
2. **Context summarization**: For a student’s most recent lab, the centroid of all submission embeddings is computed. The actual submission whose embedding is nearest (Euclidean distance) to this centroid is selected as the student’s context representation 𝑥𝑒.  
3. **Skill prediction**: Eight independent MLP classifiers (input 768-d, hidden 100, output 4 classes) are trained—one per topic—to map 𝑥𝑒 to a skill level (0–3). The MLPs are retrained after each lab using historical labeled data.  
4. **Recommendation**: Homework problems carry instructor-provided skill vectors (0–3 per topic). For a student, the system predicts a skill vector 𝑦̂ 𝑒, computes cosine similarity to every problem’s skill vector, and returns the top-k most similar problems. The system updates dynamically as new labs are submitted.

## Key Results
- Jina embeddings achieve a mean skill prediction accuracy of 0.69, surpassing TF-IDF (0.59), CodeBERT-cpp (0.66), and GraphCodeBERT (0.64).  
- The centroid‑nearest context representation yields a higher percentage of suitable exercises than alternative summarization strategies (e.g., averaging embeddings).  
- Skill‑based ranking outperforms baselines based on solution correctness or time, confirming that predicted skills are a stronger signal for context‑aware recommendation.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Representing a student’s current programming context by the single code embedding most proximate to the centroid of their latest lab submissions provides a more effective signal for skill prediction than averaging all submissions.  
- **Mechanism**: For a student’s most recent lab, all their code submission embeddings are mean‑pooled to form a centroid vector. The system then selects the actual submission whose embedding has the smallest Euclidean distance to this centroid. This selected vector becomes the student’s context representation 𝑥𝑒.  
- **Core assumption**: A real, observed solution (not an artificial average) better captures a coherent and valid snapshot of the student’s ability at that moment, and the centroid of recent submissions approximates the student’s overall recent performance state.  
- **Evidence anchors**:  
  - [abstract] “selects the embedding closest to the submission centroid”  
  - [section 3.2] “selecting the embedding closest to the centroid of the last lab attended by the student… using a real submission is more representative than averaging embeddings”  
  - [corpus] Neighbor papers (e.g., [2], [13]) use averaged embeddings; this paper’s explicit comparison (Figure 1) shows the centroid‑nearest strategy yields higher suitability.  
- **Break condition**: If a student’s latest lab submissions are extremely heterogeneous (e.g., multiple attempts on very different problems with widely varying quality), the centroid may not correspond to any “typical” solution, and the nearest neighbor could be an outlier that misrepresents skill.

### Mechanism 2
- **Claim**: Predicting proficiency in eight discrete programming topics via independent MLP classifiers, each trained on the selected context embedding, produces a skill profile vector that aligns meaningfully with the latent skill demands of unseen exercises.  
- **Mechanism**: Eight separate multiclass MLPs (labels 0‑3) are trained, one per topic. The chosen context embedding 𝑥𝑒 is fed to all eight, yielding a predicted skill vector 𝑦̂ 𝑒. Each homework problem 𝑝𝑐 has an instructor‑labeled skill vector (based on a reference solution). Recommendations rank problems by cosine similarity between 𝑦̂ 𝑒 and the problem’s skill vector.  
- **Core assumption**: (a) Skill in each topic is relatively independent and can be inferred from the semantic patterns in recent code; (b) the skill vector space is meaningfully structured so that similarity correlates with exercise appropriateness.  
- **Evidence anchors**:  
  - [abstract] “predicts students’ proficiency across eight programming topics using separate MLP classifiers”  
  - [section 3.2] “each representing a separate multiclass problem… we train eight independent MLPs”  
  - [Table 2] Mean prediction accuracy 0.69 (Jina), with topic‑specific variation (e.g., Struct 0.98, Repetition 0.37), indicating the embeddings contain discriminative signals but also highlighting topic‑dependent effectiveness.  
- **Break condition**: If skills are actually highly prerequisite or correlated (e.g., mastery of arrays depends on loops), independent classifiers may produce inconsistent profiles; also, for topics with very few training examples (e.g., Struct), the classifier may not generalize.

### Mechanism 3
- **Claim**: Using the predicted skill vector as the sole ranking signal for homework exercises yields a higher percentage of “suitable” recommendations (i.e., problems requiring only skills introduced since the student’s last submission) than baselines based on solution time or correctness.  
- **Mechanism**: After each lab, the system retrains the MLPs, predicts the student’s skill vector, computes cosine similarity to every candidate homework problem’s skill vector, and returns the top‑𝑘 by similarity. Suitability is defined by whether all required skills fall within the interval between the student’s last lab and the current class.  
- **Core assumption**: Skill vector similarity is a more precise proxy for “right‑at‑the‑edge‑of‑understanding” exercise selection than coarse‑grained metrics like time or binary correctness, because it captures multidimensional knowledge state.  
- **Evidence anchors**:  
  - [abstract] “produced a higher percentage of suitable exercises than baselines based on correctness or time”  
  - [section 4.2] “Our skill‑based ranking metric… outperformed all other methods” (Figure 1d showing nearest‑centroid + skills highest).  
  - [corpus] Related systems (e.g., [20]) rely on time/correctness; this paper’s direct comparison shows skill‑based ranking superior.  
- **Break condition**: If the problem skill labeling is inconsistent or noisy (e.g., different instructors label differently), the reference vectors may not truly reflect skill demands, making similarity misleading. Also, if the course pace is very fast, the “suitable” interval definition may be too restrictive for any method.

## Foundational Learning

**Concept**: Source Code Embeddings (Transformer‑based, e.g., Jina)  
- **Why needed here**: Raw code must be converted to a fixed‑size vector that encodes semantic and syntactic patterns correlated with programming constructs (e.g., loops, conditionals). Jina’s multilingual, long‑context capability is central to the representation.  
- **Quick check**: Why might a model pretrained on 30 languages (Jina) still work well on a C++‑only course, and what does “Matryoshka Representation Learning” enable?

**Concept**: Multilayer Perceptron (MLP) for Multiclass Classification  
- **Why needed here**: To learn a mapping from a high‑dimensional embedding (768‑d) to a small set of discrete skill levels (0‑3) for each topic. The MLP approximates a nonlinear function that disentangles skill‑related features.  
- **Quick check**: If the MLP for “Function” skill has 100 hidden units and uses L2 regularization (𝜆=0.1), what is the intended effect on overfitting in this low‑data regime?

**Concept**: Cosine Similarity as a Ranking Metric  
- **Why needed here**: To compare two vectors (student skill profile vs. problem skill vector) in a way that is invariant to magnitude and focuses on directional alignment, which is hypothesized to reflect “similar overall skill demand.”  
- **Quick check**: Given two problems with skill vectors 𝐴 = [2,1,0,…] and 𝐵 = [1,2,0,…], and a student vector 𝑆 = [2,1,0,…], which problem would cosine similarity rank higher for that student, and why?

## Architecture Onboarding

**Component map**: Code Encoder -> Context Summarizer -> Skill Predictors -> Ranking Engine

**Critical path**:  
Student submits lab code → Encoder produces embeddings → Summarizer picks “centroid‑nearest” embedding → MLPs predict 8‑t skill vector → Ranking module compares to all candidate problem skill vectors → Top‑𝑘 exercises returned.

**Design tradeoffs**:  
- Centroid‑Nearest vs. Averaging: Nearest preserves a real code sample but may be skewed by a single outlier attempt; averaging smooths noise but may yield a non‑semantic vector (not a valid solution).  
- Independent MLPs vs. Multi‑task Model: Independent MLPs are simple, require less data per task, and allow per‑skill diagnostics; they ignore potential skill correlations that a joint model could capture.  
- Static Problem Labels vs. Dynamic: Instructor labels are consistent but may not reflect student perception; could later incorporate crowd‑sourced or auto‑generated labels.

**Failure signatures**:  
- Skill prediction accuracy << 0.69 (Jina baseline) on validation → likely issues: encoder failure (check embedding norms), MLP underfitting (increase hidden size/epochs), label inconsistency.  
- Recommendations have low suitability % (near random ~12.5% for 8 topics) → either skill vectors are meaningless (re‑examine labeling) or the “suitable” interval definition is too strict.  
- High variance across lab weeks → context representation may not scale as skill complexity grows; consider including more than just latest lab.

**First 3 experiments**:  
1. **Baseline Replication**: Implement the exact pipeline with Jina embeddings. Train MLPs on 2018‑2024 data, evaluate on 2025 labs. Reproduce Table 2 mean accuracy ≈0.69. If lower, debug embedding extraction (e.g., token truncation).  
2. **Summarization Ablation**: For the 2025 labs, run the recommendation loop with all four summarization strategies (Figure 1). Confirm that “nearest‑to‑centroid of last lab” yields the highest suitability %.  
3. **Skill Vector Sanity Check**: Randomly sample 20 homework problems, manually verify their instructor‑assigned skill labels against the problem statements. Inconsistencies here would explain poor ranking performance.

## Limitations
- The “suitable exercise” definition depends on instructor‑defined skill progression intervals, which may be subjective or inconsistent.
- Topic‑specific skill prediction accuracy varies widely (e.g., 0.98 for Struct vs. 0.37 for Repetition), indicating inconsistent model performance.
- The context is derived solely from the latest lab, ignoring longer‑term student performance and potentially misrepresenting skill if recent submissions are anomalous.

## Confidence
- Jina embeddings outperform other code models: High  
- Centroid‑nearest submission as context: Medium  
- Skill‑based ranking superiority: Low  

## Next Checks
1. **Context Robustness Test**: For students with high variance in their latest lab submissions (measured by pairwise embedding distance), manually check if the centroid‑nearest sample is a “typical” solution. Compare recommendation suitability using centroid‑nearest vs. simple average embedding.  
2. **Label Sanity Audit**: Recruit two independent instructors to re‑label the skill vectors (0‑3) for a random subset of 50 homework problems. Calculate inter‑rater reliability and remeasure ranking performance with consensus labels.  
3. **Cross‑Course Validation**: Apply the fully retrained model (using all 2018‑2024 data) to a different introductory programming course (e.g., Python‑based) with its own skill taxonomy. Report drop in mean prediction accuracy and suitability %.
