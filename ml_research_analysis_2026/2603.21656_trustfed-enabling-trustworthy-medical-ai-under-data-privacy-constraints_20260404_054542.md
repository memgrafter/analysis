# TrustFed: Enabling Trustworthy Medical AI under Data Privacy Constraints
## Quick Facts
- **ArXiv ID:** 2603.21656
- **Source URL:** https://arxiv.org/abs/2603.21656
- **Reference Count:** 40
- **Primary Result:** Achieves distribution-free, finite-sample coverage guarantees (empirical coverage within 1–2% of nominal 0.90/0.80) in heterogeneous federated medical AI.

## Executive Summary
TrustFed addresses the challenge of providing reliable uncertainty quantification in federated medical AI, where data cannot be centralized due to privacy constraints. Existing federated conformal prediction methods struggle with data heterogeneity and class imbalance. TrustFed introduces a privacy-preserving framework that assigns test samples to clients with similar learned representations and aggregates local calibration thresholds using a soft-nearest aggregation. This yields sample-adaptive prediction sets with distribution-free coverage guarantees without requiring central data access. Evaluated on six diverse medical imaging datasets (430k+ images), TrustFed consistently achieves empirical coverage within 1–2% of nominal levels while maintaining compact sets, outperforming baselines even under severe heterogeneity and bias.

## Method Summary
TrustFed employs a three-stage pipeline. First, a global CortiNet model is trained across clients using standard federated averaging (FedAvg). After training, the global model is frozen. Second, each client locally computes nonconformity scores (1 – predicted probability for the true class) on its private calibration set, determines a threshold τ_k as the (1–α)(m_k+1) quantile, and stores a feature bank containing embeddings of its calibration samples from the frozen global model. Third, for a test sample, its embedding is broadcast to all clients; each returns the minimum Euclidean distance to its feature bank. The server selects the N_k clients with smallest distances and aggregates their thresholds via τ = max(τ_j). The final prediction set includes all classes with nonconformity score ≤ τ. All raw data, scores, and embeddings remain on clients; only scalar distances and thresholds are communicated, preserving privacy.

## Key Results
- Consistently achieves empirical coverage within 1–2% of nominal levels (0.90, 0.80) across six distinct medical imaging modalities.
- Maintains compact prediction sets, even under severe class imbalance and client-specific biases.
- Outperforms baselines, providing statistically guaranteed uncertainty for trustworthy multi-institutional healthcare AI.

## Why This Works (Mechanism)
TrustFed's effectiveness relies on three interconnected mechanisms:

1. **Representation-aware client assignment**: The server assigns each test sample to the N_k clients whose locally stored feature banks (embeddings of calibration samples) are closest in Euclidean distance to the test sample's embedding from the frozen global model. This groups clients with similar learned feature distributions, approximating exchangeability of nonconformity scores across those clients—a key requirement for conformal prediction. Evidence from the paper includes the abstract, Section 2 (Eqs. 7,8). Failure occurs when the global model's representations are not semantically discriminative (e.g., due to model collapse), leading to under-coverage.

2. **Soft‑nearest threshold aggregation**: The final threshold τ(x) is the maximum among the individual client thresholds τ_j from the N_k selected neighbors. This conservative aggregation mitigates risk from imperfect client assignment: even if the "nearest" client is suboptimal, at least one neighbor's threshold likely bounds the true conditional threshold, thereby preserving coverage. Evidence: abstract, Section 2 (Eq. 11), Section 3.3 (shows reduced variance). Break conditions include using an excessively large N_k (causing overly large sets) or selecting a semantically incoherent neighbor set (invalid thresholds).

3. **Privacy preservation**: No raw calibration images, labels, nonconformity scores, or feature embeddings leave the client device. Only scalar quantities—the per‑client minimum distance and the aggregated threshold—are communicated. The server performs all selection and aggregation without ever accessing any individual‑level data. Evidence: abstract, Section 2. The privacy model assumes an honest‑but‑curious server; inference attacks on the sequence of distances could potentially leak information.

## Architecture Onboarding
- **Component map:**  
  Global CortiNet model (f_θ, frozen after FL training) → Local Client Stores (each holds private calibration set D_cal^k, nonconformity scores S_k, local threshold τ_k, feature bank B_k of embeddings) → Server Orchestrator (manages FL rounds, test‑time distance collection, N_k‑neighbor selection, threshold aggregation, prediction set return).

- **Critical path:**  
  1. Federated training (FedAvg) obtains a global model.  
  2. Each client computes τ_k via quantile of S_k on D_cal^k and constructs B_k using the frozen model.  
  3. For a test sample x: compute ϕ(x) via the global model; all clients return min Euclidean distance to their B_k; server selects top‑N_k clients; collects τ_j from those clients; sets τ = max(τ_j); returns {y: 1 - p_y(x) ≤ τ}.

- **Design tradeoffs:**  
  - **Coverage vs. Efficiency:** Larger N_k improves robustness to assignment errors but inflates prediction set size.  
  - **Privacy vs. Utility:** Sharing richer data (e.g., full embeddings or scores) could tighten sets but would violate privacy. TrustFed minimizes communication to scalars.  
  - **Heterogeneity handling:** Representation‑aware assignment assumes feature‑space similarity correlates with calibration‑distribution similarity; this may fail under non‑semantic shifts (e.g., scanner artifacts).

- **Failure signatures:**  
  - Systematic under‑coverage (< nominal) → likely N_k too small or non‑discriminative global representations.  
  - Excessively large sets → N_k too large or overly heterogeneous neighbor set.  
  - High variance in coverage across clients/classes → inconsistent client assignment quality.

- **First three experiments to run:**

  2. **Ablation on assignment strategy:** Replace representation‑aware assignment with (a) random client selection and (b) raw‑pixel distance selection. Expect drops in coverage stability and increases in set size, demonstrating the value of learned representations.

## Open Questions the Paper Calls Out
1. **Multi‑modal federated settings:** Current evaluation uses single‑modality datasets; extending to heterogeneous data types (e.g., imaging + text) raises alignment and calibration challenges.  
2. **Regression, structured prediction, and segmentation:** The classification‑specific nonconformity score needs adaptation; coverage guarantees for continuous or spatial outputs remain untested.  
3. **Theoretically guided N_k selection:** The neighborhood size is tuned empirically; formal bounds relating N_k to client dissimilarity or calibration size could optimize the coverage‑efficiency trade‑off.  
4. **Failure conditions for representation‑aware assignment:** The assumption that feature similarity implies exchangeability may break under spurious correlations or distribution shifts that affect representations but not labels; controlled experiments are needed.  
5. **Alternative threshold aggregation:** The max operator is conservative; exploring weighted averages or quantile pooling might improve efficiency without sacrificing coverage.

## Limitations
- **Incomplete reproducibility details:** Missing hyperparameters (communication rounds, local epochs, batch size) and CortiNet architecture specifics hinder exact replication.
- **Ambiguous data partitioning:** The number of clients K and the non‑IID splitting scheme (e.g., Dirichlet α) are not specified, making heterogeneity control unclear.
- **Privacy analysis superficial:** While only scalar distances are shared, no formal grounding against membership inference attacks is provided; potential leakage remains unquantified.

## Confidence
- **Representation-aware client assignment:** Medium confidence. Internal ablations show benefit, but external validation across diverse settings is limited.
- **Soft‑nearest threshold aggregation:** Medium confidence. Empirically reduces coverage variance, but robustness under extreme heterogeneity and theoretical justification are not fully developed.
- **Privacy preservation:** Low confidence. Relies on intuitive minimal communication; no formal privacy proof and vulnerable to inference attacks in principle.

## Next Checks
1. **Oracle assignment bound:** Use ground‑truth client distributions to assign each test sample to its best‑matching client; compare TrustFed's coverage and set size to this oracle to quantify the cost of imperfect assignment.
2. **Systematic N_k sweep:** Across all six datasets, vary N_k from 1 to K, record coverage and average set size, and analyze how the trade‑off changes with heterogeneity level.
3. **Membership inference on distances:** Simulate an adversary that observes the vector of minimum distances for a set of test samples and attempts to infer the originating client; measure attack accuracy to assess potential privacy leakage.
