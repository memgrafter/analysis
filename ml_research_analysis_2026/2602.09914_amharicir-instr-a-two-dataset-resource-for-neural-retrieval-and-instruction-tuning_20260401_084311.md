# AmharicIR+Instr: A Two-Dataset Resource for Neural Retrieval and Instruction Tuning

## Quick Facts
- **arXiv ID:** 2602.09914
- **Source URL:** https://arxiv.org/abs/2602.09914
- **Reference Count:** 28
- **Primary Result:** Introduces two manually verified Amharic datasets (1,091 retrieval triplets, 6,285 instruction pairs) and establishes RoBERTa-based retrieval benchmarks (NDCG@10 = 0.845, MAP@10 = 0.812).

## Executive Summary
This paper tackles the severe lack of high-quality supervised data for Amharic, a low-resource language, in two key NLP tasks: neural retrieval and instruction tuning. It introduces two novel, manually validated datasets: a retrieval triplet set (query, positive document, negative document) and an instruction prompt-response set. The datasets were built via a reusable, multi-source pipeline combining expert curation, web scraping, LLM generation, and rigorous native-speaker validation. Baseline fine-tuning experiments on the retrieval data show that a RoBERTa-based dense retriever achieves strong performance, providing the first robust benchmarks for Amharic information retrieval and generation research.

## Method Summary
The core contribution is a six-step, language-agnostic methodology for creating high-quality supervised data in low-resource settings. First, domain and task coverage are specified by experts. Second, candidate data (queries/documents for retrieval, prompt/response pairs for instruction) is generated from multiple sources: curated expert examples, web harvesting, and LLM synthesis. Third, explicit supervision is defined: for retrieval, this means identifying a relevant positive and a challenging negative (including hard negatives with lexical overlap) for each query; for instruction, it means ensuring responses are fluent, relevant, and factually plausible. Fourth, native Amharic speakers manually validate and correct all candidates. Fifth, language-specific normalization is applied (e.g., script standardization, punctuation cleanup). Finally, the datasets are released in a standardized format with predefined train/validation/test splits, along with baseline model checkpoints.

## Key Results
-   A manually verified Amharic retrieval dataset of 1,091 query-positive-negative triplets.
-   A manually verified Amharic instruction dataset of 6,285 prompt-response pairs.
-   Fine-tuned RoBERTa achieves NDCG@10 of 0.845 and MAP@10 of 0.812 on the retrieval test set, outperforming SPLADE and ColBERT baselines.

## Why This Works (Mechanism)
The retrieval dataset's effectiveness stems from its manually verified triplet structure. Native-speaker validation ensures positives genuinely satisfy the query and negatives are truly non-relevant, even when lexically overlapping (hard negatives). This provides clean contrastive supervision signals, enabling a neural retriever to learn robust semantic matching in a morphologically complex language where automatic heuristics (like click logs) are scarce or unreliable. A break condition would be inconsistent human judgments, introducing label noise that degrades model learning.

The instruction dataset's quality arises from a two-stage LLM-human hybrid pipeline. Initial LLM generation provides topical diversity and scale, while native-speaker review corrects grammatical errors, hallucinations, and cultural mismatches, preserving the intended instruction semantics. This leverages LLM creativity but uses human judgment as a critical filter for authenticity. A break condition is superficial correction that misses subtle errors, leading to models that generate fluent but factually or contextually inappropriate responses.

The proposed six-step pipeline is presented as generalizable to other low-resource languages by decoupling the repeatable workflow from language-specific artifacts (e.g., templates, web sources, normalization rules). Its explicit emphasis on native validation as a non-skippable quality cornerstone addresses a common bottleneck. A break condition for transfer is a lack of available native validators or extremely limited web presence in the target language, which would force costly adaptations and potentially compromise quality or coverage.

## Foundational Learning
-   **Concept: Contrastive Learning for Dense Retrieval**
    -   **Why needed:** The retrieval dataset uses triplet-based contrastive training (e.g., InfoNCE loss). Understanding this is key to interpreting why the triplet structure and hard negatives are crucial for learning meaningful embedding spaces.
    -   **Quick check:** How does training with a "hard negative" (a document lexically similar but semantically irrelevant) improve a retriever's robustness compared to using only random negatives?
-   **Concept: Instruction Tuning (Supervised Fine-Tuning)**
    -   **Why needed:** The instruction dataset is designed for supervised fine-tuning of LLMs to follow Amharic prompts. This requires distinguishing it from pretraining and understanding why human correction for "factual plausibility" is vital for low-resource languages.
    -   **Quick check:** Why might an instruction dataset manually corrected for factual plausibility be more important for Amharic than for a high-resource language like English?
-   **Concept: Low-Resource Language NLP Challenges**
    -   **Why needed:** Amharic's morphological richness and Ge'ez script create unique challenges for tokenization, sparsity, and semantic matching, which the dataset's design (e.g., normalization, hard negatives) aims to mitigate.
    -   **Quick check:** How might Amharic's complex morphology create a "vocabulary mismatch" problem for both sparse (BM25) and dense retrievers?

## Architecture Onboarding
Data Loader -> Preprocessor -> Model Wrapper -> Training Loop -> Evaluation Harness -> Baseline Reference Implementations

**Critical Path:**
1.  Clone repository and install dependencies (transformers, datasets, torch, evaluation metrics).
2.  Download and inspect dataset splits (train/val/test). Verify Amharic script rendering and basic statistics.
3.  Run provided baseline training script (or replicate from paper) on a small subset to validate end-to-end pipeline.
4.  Evaluate on test split to reproduce baseline numbers from Table 2 (e.g., RoBERTa's NDCG@10 ~0.845).
5.  Iterate: modify model architecture, negative mining, or preprocessing; re-train and re-evaluate on validation before final test.

**Design Tradeoffs:**
-   **Triplet Volume vs. Quality:** The small retrieval set (1,091 triplets) ensures high quality but risks overfitting. May require aggressive data augmentation (synthetic queries, cross-encoder hard negative mining).
-   **Model Architecture:** RoBERTa (dense) performed best in paper; ColBERT (late interaction) offers better recall/interpretability; SPLADE (sparse) offers efficiency/lexical interpretability but was less effective here. Choice depends on deployment needs.
-   **Normalization Aggressiveness:** Over-normalization (e.g., stemming) may lose meaningful Amharic morphological cues. Under-normalization leaves noise. The paper's punctuation/whitespace cleanup is a safe starting point; deeper morphological processing should be tested cautiously.

**Failure Signatures:**
-   **Retrieval:** Test NDCG@10 < 0.5; model fails to rank (e.g., precision flat across K); high similarity scores for (q, d-) pairs during debugging.
-   **Instruction:** Generated responses fluent but consistently off-topic, contain uncorrected Amharic grammar errors, or hallucinate facts on out-of-domain prompts.
-   **Data Pipeline:** Unicode decoding errors (corrupted Ge'ez script); abnormal vocabulary size post-tokenization; high duplicate rate not filtered.

**First 3 Experiments:**
1.  **Baseline Reproduction:** Fine-tune the provided `RoBERTa-Amharic-Embed-Medium` on official training triplets. Goal: Match test NDCG@10 ≥ 0.80 (approaching paper's 0.845) to validate environment and data loading.
2.  **Negative Mining Ablation:** Compare paper's native-validated hard negatives against a baseline using only random corpus negatives. Train identical models and measure NDCG@10 delta. Expected: Hard negatives yield significant improvement.
3.  **Cross-Model Generalization Test:** Use the retrieved documents from Experiment 1's best model to supply context for a RAG system generating responses to instruction dataset prompts. Evaluate if retrieved context yields accurate, on-topic generations, testing joint dataset utility.

## Limitations
-   **Annotation Consistency Unknown:** No reported inter-annotator agreement metrics for native-speaker relevance judgments; label noise risk remains unquantified.
-   **Residual LLW Error Unevaluated:** No ablation comparing raw LLM output vs. corrected data; the depth and impact of manual correction (e.g., catching subtle hallucinations) are unclear.
-   **Cross-Linguistic Feasibility Untested:** The "language-agnostic" claim lacks validation via replication in another low-resource language; feasibility may degrade with smaller validator pools or less web presence.

## Next Checks
1.  **Annotation Consistency Audit:** Re-annotate a random 10% of the retrieval triplet validation set with a second native speaker. Compute Cohen's Kappa for positive/negative relevance judgments to quantify label agreement.
2.  **Residual LLM Error Analysis:** Sample 100 post-correction prompt-response pairs from the instruction dataset. Categorize remaining flaws (grammar, factuality, cultural mismatch, relevance) to measure dataset noise upper bound.
3.  **Cross-Linguistic Pipeline Piloting:** Apply the exact six-step pipeline to a different low-resource language (e.g., Somali). Document required adaptations and resulting dataset quality metrics (validator agreement, harvest yield) to stress-test generalizability.
