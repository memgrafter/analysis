# Self-Routing: Parameter-Free Expert Routing from Hidden States

## Quick Facts
- **arXiv ID:** 2604.00421
- **Source URL:** https://arxiv.org/abs/2604.00421
- **Reference count:** 6
- **Primary result:** Eliminates the learned router projection in MoE by using a fixed hidden-state subspace as expert logits, matching or exceeding learned-router performance while achieving significantly higher expert utilization entropy without an auxiliary load-balancing loss.

## Executive Summary
Self-Routing proposes a parameter-free alternative to the learned router in Mixture-of-Experts (MoE) layers. Instead of a linear projection, it directly reserves the last *N* dimensions of the token's hidden state as the logits for *N* experts. This simple change removes all dedicated routing parameters. Evaluated on GPT-2-scale language modeling and ImageNet-1K with DeiT-S, Self-Routing is competitive with standard learned routers on downstream benchmarks and demonstrates markedly more balanced expert utilization (17% higher normalized entropy) without requiring an explicit load-balancing loss. The work suggests that the hidden-state distribution inherently contains linearly separable routing signals that can be accessed via a fixed coordinate slice.

## Method Summary
Self-Routing modifies only the router component within each MoE layer. For a token representation *h* with hidden dimension *H* and *N* experts, the last *N* coordinates are sliced and used directly as the expert logits: `logits = h[..., -N:]`. These logits then undergo standard top-*k* selection, softmax normalization, and weighted aggregation with expert outputs. No learned parameters are introduced for routing; the backbone and expert networks are trained end-to-end, forcing the representation to develop routing-relevant information in the designated dimensions. All other aspects of the MoE implementation (dispatch mechanism, expert networks) remain unchanged from a standard setup.

## Key Results
*   On GPT-2-scale language modeling (8 experts), Self-Routing is competitive: HellaSwag 39.0% vs. 38.5% (learned), PIQA 67.4% vs. 65.6%, LAMBADA 18.9 vs. 19.3.
*   Achieves 17% higher normalized routing entropy (72.36% vs. 61.71%) without any explicit load-balancing loss, indicating more uniform expert usage.
*   On ImageNet-1K with DeiT-S/16 (4 experts), attains 79.92% top-1 accuracy, slightly improving over the learned-router MoE baseline (79.42%).

## Why This Works (Mechanism)
### Mechanism 1: Direct Subspace Access
- **Claim:** Routing logits can be read directly from a designated hidden-state subspace without a learned projection.
- **Mechanism:** The last *N* dimensions of the token representation are used *as-is* as expert logits (`z = h[..., -N:]`), bypassing the standard linear router `z = hW_r`. End-to-end training shapes the backbone parameters so that these coordinates encode routing preference.
- **Evidence:** [abstract] "uses a designated subspace of the token hidden state directly as expert logits, eliminating the router projection entirely"; [section 2.2] "we reserve the last N dimensions of the token representation as routing logits".

### Mechanism 2: Implicit Balance via Coordinate Consistency
- **Claim:** Fixed, coordinate-aligned routing may inherently induce more balanced expert utilization than a learned router, even without an explicit load-balancing loss.
- **Mechanism:** By consistently extracting logits from the same coordinates across all layers, training dynamics may encourage those dimensions to stabilize into a "balanced routing manifold." The absence of per-layer learned router weights could prevent the formation of routing patterns that overly concentrate on a subset of experts.
- **Evidence:** [section 4.2] "Self-Routing yields consistently higher expert-utilization entropy... about 17% higher average normalized routing entropy and no explicit load-balancing loss."; [figure 2] shows higher entropy across most layers.

### Mechanism 3: Implementation Simplicity & Memory Savings
- **Claim:** Parameter-free routing reduces implementation complexity and memory overhead while remaining compatible with standard MoE kernels.
- **Mechanism:** Removing the router projection eliminates `L × H × N` learned parameters. Routing logits are obtained via a simple tensor slice, avoiding extra matrix multiplications and requiring no additional backward-pass computation for router gradients.
- **Evidence:** [section 2.2] "eliminates dedicated router parameters... remains naturally compatible with optimized attention implementations"; [table 1] shows a small parameter count difference (520.81M vs. 520.74M).

## Architecture Onboarding
- **Component map:** Router Module (modified: slice last N dims) -> Expert Networks (FFWs, unchanged) -> Top-k Selection & Aggregation (unchanged)
- **Critical path:**
  1. In each MoE layer's forward pass, after computing the token hidden state `h`, slice: `logits = h[..., -num_experts:]`.
  2. Apply top-*k* selection and softmax normalization over the sliced logits.
  3. Dispatch tokens to experts and aggregate outputs as in standard MoE.
  4. Backpropagation updates only backbone/expert parameters; the slice operation has no learnable weights.
- **Design tradeoffs:**
  - **vs. Learned Router:** Loses per-layer adaptability but gains parameter/impl. simplicity and (in this study) better load balance.
  - **vs. Fixed Random Projection:** Same parameter count, but Self-Routing uses a coordinate-aligned slice rather than a random linear map. The paper suggests this alignment may aid optimization.
  - **vs. Random Routing:** Maintains input-dependent routing (content-aware), which is empirically necessary for good performance.
- **Failure signatures:**
  - **Routing Collapse:** All tokens assigned to ≤2 experts across all layers (check max expert fraction per layer). Indicates the reserved dimensions failed to develop discriminatory signal.
  - **Performance Drop vs. Dense:** If MoE with Self-Routing underperforms the dense baseline significantly, the routing signal may be insufficient or capacity increase not utilized.
  - **Entropy Divergence:** Normalized entropy << 1.0 in later layers, especially if early layers are already balanced.
- **First 3 experiments:**
  1. **Coordinate Ablation:** Test different fixed subsets (first *N*, middle *N*, learned linear combination) to verify the last-*N* choice is not magical.
  2. **Entropy Tracking:** During training, track per-layer normalized routing entropy. Does Self-Routing's advantage emerge early or late? Compare with/without load-balancing loss.
  3. **Scaling Test:** Increase `num_experts` (e.g., 8 → 16). Does the performance gap with learned router widen, narrow, or reverse?

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Does Self-Routing maintain its competitive performance and expert balance when scaled to different numbers of experts, larger model scales, and more diverse tasks beyond GPT-2-scale language modeling and ImageNet-1K?
- **Basis in paper:** The authors state in the limitations: "What remains to be seen is whether our observations will hold for different numbers of experts, larger scales, and more challenging domains."
- **Why unresolved:** Evaluation is restricted to specific configurations (8 experts in GPT-2 Small, 4 experts in DeiT-S/16) and domains; generalizability is untested.
- **What evidence would resolve it:** Systematic experiments varying expert counts (e.g., 16, 32), model sizes, and tasks (e.g., machine translation, code generation) to compare Self-Routing against learned routers.

### Open Question 2
- **Question:** Is Self-Routing's improved expert utilization primarily driven by the use of fixed coordinate-aligned logits or by the consistency of applying the same coordinate subspace across all layers?
- **Basis in paper:** The authors note: "further investigation is also needed to understand whether the benefits of Self-Router come primarily from aligning the routing logits to the coordinates, or from using the same coordinates across all layers."
- **Why unresolved:** The fixed random projection baseline uses a consistent but non-coordinate-aligned projection, making it unclear which factor—coordinate alignment or layer-wise consistency—dominates.
- **What evidence would resolve it:** Ablation studies where the designated subspace varies per layer (e.g., random subsets each layer) or where coordinates are permuted, measuring changes in performance, entropy, and expert dominance.

### Open Question 3
- **Question:** Does the coordinate-aligned routing in Self-Routing inherently ease optimization and foster consistent expert specialization across layers relative to learned routers?
- **Basis in paper:** Inferred from the authors' conjecture that Self-Routing "may make optimization easier, by allowing a consistent notion of 'specialization' across layers," based on higher routing entropy and stability without load-balancing loss.
- **Why unresolved:** No direct analysis of optimization dynamics or expert specialization patterns is provided; the conjecture is based on indirect empirical trends.
- **What evidence would resolve it:** Compare training trajectories (loss curves, gradient norms) and analyze expert activation distributions over time and layers to assess convergence speed, stability, and whether experts develop consistent functional roles.

### Open Question 4
- **Question:** How sensitive is Self-Routing to the choice of which hidden state dimensions are designated for routing, such as using the first *N* dimensions instead of the last *N*?
- **Basis in paper:** Inferred; the paper uses the last *N* dimensions for simplicity but states that "any designated *N*-dimensional subset" could be used, implying this choice is arbitrary and unexplored.
- **Why unresolved:** Different hidden state regions may encode distinct information; selecting a non-optimal subspace could degrade routing quality, but this is not evaluated.
- **What evidence would resolve it:** Experiment with alternative subspaces (e.g., first *N*, middle *N*, random *N* coordinates) across multiple layers and measure impacts on accuracy, entropy, and utilization patterns.

## Limitations
- **Training hyperparameters not fully reported.** The paper states they share the "same optimization recipe" but does not give specific values for learning rate, batch size, or total steps, impeding exact replication.
- **Scalability unknown.** Experiments are limited to GPT-2-scale language modeling and DeiT-S/16; performance on larger models, more experts, or more challenging domains remains untested.
- **No justification for coordinate choice.** The rationale for using the last *N* dimensions versus other fixed subsets (first *N*, random indices) is not explored theoretically or empirically.

## Confidence
- **Self-Routing removes router parameters and computational overhead:** High
- **Competitive task performance vs. learned router:** Medium
- **Improved expert utilization without load-balancing loss:** Medium
