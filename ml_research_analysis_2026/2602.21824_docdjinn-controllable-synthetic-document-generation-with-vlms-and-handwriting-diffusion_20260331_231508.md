# DocDjinn: Controllable Synthetic Document Generation with VLMs and Handwriting Diffusion

## Quick Facts
- arXiv ID: 2602.21824
- Source URL: https://arxiv.org/abs/2602.21824
- Reference count: 40
- Primary result: Synthetic document generation reduces annotation cost; augmenting 100 real samples achieves 87% of full dataset performance.

## Executive Summary
DocDjinn tackles the high cost and privacy concerns of obtaining labeled document data by generating realistic synthetic documents from unlabeled seeds. It combines Vision‑Language Models (VLMs) for layout and content creation with diffusion models for handwriting variation, producing multi‑task annotations for KIE, VQA, CLS, and DLA. Evaluated on eleven benchmarks, synthetic augmentation of just 100 real samples attains 87% of the performance of the full real dataset, while synthetic‑only training reaches 70.8%, demonstrating substantial annotation reduction while preserving downstream accuracy.

## Method Summary
DocDjinn’s pipeline begins with seed selection: unlabeled seed documents are encoded using multi‑modal embeddings (LayoutLMv3, CLIP, Sentence Transformers), reduced via UMAP, and clustered with HDBSCAN. From each cluster, documents are sampled densely (α=1) to maximize intra‑cluster diversity and coverage. For each batch, a VLM (Claude Sonnet 4.5) receives the seeds and a task‑specific prompt, then generates an HTML representation along with ground‑truth annotations (JSON for VQA, class labels for CLS, etc.). The HTML is rendered to a PDF, and the VLM identifies regions that require handwritten text or visual elements (stamps, barcodes). A diffusion model trained on IAM synthesizes handwriting aligned to those segments, while pre‑defined assets add visual stamps or logos. Finally, OCR and task constraints (e.g., ANLS ≥ 0.75) verify annotation quality; invalid samples are discarded.

## Key Results
- Augmenting 100 real samples with synthetic data achieves 87% of full real‑world dataset performance across downstream tasks.
- Synthetic‑only training attains 70.8% of full real performance on average.
- The approach is validated on eleven document understanding benchmarks covering KIE, VQA, CLS, and DLA.

## Why This Works (Mechanism)
DocDjinn works because it leverages the semantic and layout understanding of VLMs to generate distributionally aligned synthetic documents. Real seeds as few‑shot examples guide the VLM to imitate the target domain’s visual and textual patterns. Clustering‑based seed selection ensures diversity while avoiding duplication, and handwriting diffusion adds realistic variation to handwritten content, which is often the hardest for downstream models. The verification step enforces annotation fidelity, maintaining a high‑quality training signal. Together, these components produce a synthetic dataset that, even in small quantities, effectively supplements real data and reduces annotation costs.

## Foundational Learning
- **Vision‑Language Models (VLMs)**: Needed to generate plausible document layouts and content from seeds and prompts.  
  *Quick check*: Run a zero‑shot VLM on a seed image and ask for an HTML rendering; assess realism.
- **Handwriting Diffusion**: Needed to synthesize diverse, realistic handwritten text matching the document’s style.  
  *Quick check*: Generate handwriting for given text lines and compare to real samples via FID or human inspection.
- **Multi‑modal Embeddings**: Needed to represent documents across visual, textual, and layout features for clustering.  
  *Quick check*: Compute embeddings for a few documents and verify that similar documents are close in the embedding space.
- **Clustering for Seed Selection**: Needed to sample a diverse yet representative subset of seeds from a large unlabeled set.  
  *Quick check*: Apply HDBSCAN to embeddings and check cluster cohesion (e.g., Silhouette score).
- **Verification via OCR/Constraints**: Needed to filter out low‑quality generations and ensure annotation correctness.  
  *Quick check*: Run OCR on generated PDFs and check that extracted text matches the GT within threshold (ANLS ≥ 0.75).

## Architecture Onboarding
**Component Map**:  
Raw Seeds → Embedding Extraction → Clustering → Seed Sampling → VLM Generation → HTML Rendering → Handwriting/Visual Enhancement (Diffusion) → Annotation Extraction → Verification → Synthetic Documents

**Critical Path**: For a batch, the essential sequence is: (1) select seeds via clustering and sampling, (2) invoke the VLM to generate HTML and GT, (3) render PDF and identify enhancement regions, (4) apply handwriting diffusion and add visual elements, (5) extract annotations and verify constraints. Each step depends on the previous; failures require retries.

**Design Tradeoffs**:  
- *VLM choice*: Claude Sonnet yields high quality but is proprietary and costly; open‑source VLMs reduce cost but suffer lower GT success rates.  
- *Diffusion realism*: Higher quality handwriting may require more compute and longer training; a lightweight model produces recognizable but less natural script.  
- *Verification strictness*: Tight constraints (ANLS ≥ 0.75) ensure annotation quality but lower yield; looser constraints increase dataset size but risk noise.

**Failure Signatures**:  
- Low GT validity rate (e.g., < 50% pass verification) indicating VLM or prompt issues.  
- Extreme class imbalance in classification tasks (e.g., memos dominating) reflecting sampling bias.  
- Degraded vision‑model performance on real data when synthetic data is used, often due to domain gap (high FID) or taxonomy mismatches.

**First Experiments**:  
1. Implement seed selection on a small benchmark (e.g., RVL‑DIP) and examine diversity of selected seeds via cluster visualization.  
2. Run VLM generation for a single seed with a simple task prompt; manually inspect the HTML rendering and GT accuracy.  
3. Evaluate the handwriting diffusion model on a held‑out IAM test set; report FID and sample readability.

## Open Questions
1. **Question**: How should degradation techniques be integrated to best match real document appearance?  
   **Basis**: Section 4.6 explicitly calls out "pristine synthetic documents lack real‑world degradations" and suggests borrowing from DocGenie.  
   **Why unresolved**: Clean synthetic docs create a domain gap harming vision models on real datasets with artifacts.  
   **Resolving evidence**: Implement a degradation pipeline, measure Layout‑FID and vision task performance on artifact‑rich datasets.

2. **Question**: What sampling strategies can fix severe class imbalance in synthetic classification datasets?  
   **Basis**: Section K.2 and Fig. 24 show synthetic CLS data has extreme imbalance (e.g., ~45% memos vs <2% specialized classes). Section 4.6 suggests "constrained sampling strategies."  
   **Why unresolved**: Current α=1 intra‑cluster sampling amplifies dominant patterns, causing the VLM to overgenerate some classes and neglect others.  
   **Resolving evidence**: Test stratified/balanced sampling across clusters, measure classification accuracy per class, especially underrepresented ones.

3. **Question**: How can annotation taxonomies be aligned between synthetic and real DLA datasets to improve performance?  
   **Basis**: Section 4.5 and K.4 detail mismatches: list‑item definitions, visual element variety, table diversity, formula vs picture labeling, caption failures. Section 4.6 notes "annotation taxonomy differences affect DLA scores."  
   **Why unresolved**: The VLM’s semantic labeling differs from target dataset rules (e.g., DocLayNet’s semantic list‑items vs distance‑based), causing quantitative gaps despite qualitatively reasonable layouts.  
   **Resolving evidence**: Analyze specific taxonomy conflicts, modify prompts/post‑processing to enforce target rules, remeasure DLA mAP with consistent labeling.

4. **Question**: How does handwriting quality affect document understanding, and can better synthesis improve performance on handwritten‑content tasks?  
   **Basis**: Table 3 shows LayoutLMv3 degrades on DocVQA‑HW with synthetic addition (+8.17 ANLS gap) while BERT improves, indicating "synthetic handwriting lacks authentic visual characteristics" (Section 4.3).  
   **Why unresolved**: Current diffusion model produces clean, standardized handwriting without natural variation, pressure effects, or paper texture that real handwriting exhibits.  
   **Resolving evidence**: Enhance diffusion with realistic variations, evaluate on DocVQA‑HW and similar benchmarks to see if vision model performance improves toward text‑only baseline.

## Limitations
- Proprietary VLM (Claude Sonnet) API specifics are undocumented, preventing exact replication of the pipeline.
- Handwriting diffusion model training details (data split, augmentations, convergence) are missing, requiring training from scratch.
- Severe class imbalance in synthetic classification data (e.g., memoranda overrepresented) persists with no clear mitigation beyond α tuning.

## Confidence
- Performance claims (87% with 100 real samples, 70.8% synthetic‑only): Medium
- Distribution alignment via clustering: Medium
- Generalization across tasks (KIE, VQA, CLS, DLA): Low‑Medium
