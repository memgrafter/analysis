# Efficient Point Cloud Processing with High-Dimensional Positional Encoding and Non-Local MLPs

## Quick Facts
- arXiv ID: 2603.04099
- Source URL: https://arxiv.org/abs/2603.04099
- Reference count: 40
- Primary result: HPENet V2-XL achieves 72.6% mIoU on S3DIS Area-5 (+4.0% over PointNeXt-XL) with only 21.5% of its FLOPs.

## Executive Summary
This paper introduces HPENet V2, a point cloud processing framework built on the Abstraction-Refinement (ABS-REF) two-stage view. It proposes High-dimensional Positional Encoding (HPE) to embed relative coordinates into high-dimensional features, replaces costly local MLPs with non-local MLPs in abstraction stages, and adds a Backward Fusion Module (BFM) for cross-resolution context. Across multiple benchmarks (S3DIS, ScanObjectNN, ScanNet, etc.), HPENet V2 delivers superior accuracy with substantially lower computational cost. For example, on S3DIS Area-5, the XL variant reaches 72.6% mIoU—improving over PointNeXt-XL by 4.0%—while using only 21.5% of its FLOPs. The components also boost transformer-based backbones, e.g., +2.5% mIoU on Point Transformer with fewer FLOPs.

## Method Summary
HPENet V2 reinterprets point cloud MLP architectures through an ABS-REF lens: the Abstraction (ABS) stage downsamples points and aggregates local context, while the Refinement (REF) stage preserves resolution and expands receptive field via multiple neighbor-based operations. Key innovations include: (1) High-dimensional Positional Encoding (HPE) that projects relative coordinates into a high-dimensional space via sinusoidal or MLP transformations, enhancing geometric representation; (2) Non-local MLPs (PreConv) in ABS stages (after the first) that process entire point sets before grouping, reducing computational cost; and (3) Backward Fusion Module (BFM) that fuses multi-resolution features in the decoder via channel attention. The network adopts a hybrid strategy: the first ABS uses local MLP for detail preservation, while later ABS stages use PreConv, and REF stages use local MLPs. This design yields a family of models (V2-S to XL) that balance accuracy and efficiency.

## Key Results
- HPENet V2-XL: 72.6% mIoU on S3DIS Area-5 (+4.0% vs. PointNeXt-XL) with 21.5% FLOPs.
- HPENet V2-S: +1.1% mAcc on ScanObjectNN with 50% FLOPs.
- On ScanNet: +2.5% mIoU with lower compute.
- Boosts transformer backbones: +2.5% mIoU on Point Transformer with fewer FLOPs.

## Why This Works (Mechanism)

**ABS-REF Two-Stage View**: The paper clarifies that recent performance gains in point cloud MLPs stem from adding a Refinement (REF) stage, not just improving Abstraction (ABS). ABS downsamples via FPS and aggregates local context (intra-set), while REF processes the downsampled set with grouped neighbors (inter-set) without changing resolution, increasing receptive field and enabling deeper networks. This is supported by mathematical definitions (Eqs. 1-5) and architectural comparisons in Figures 3-4.

**High-dimensional Positional Encoding (HPE)**: HPE embeds relative coordinates (Δp) into high-dimensional features via sinusoidal or MLP projections, then aligns with feature space. This high-dimensional projection mitigates spectral bias, capturing finer geometric relationships. Applied after grouping in both ABS and REF, HPE significantly outperforms low-dimensional PE and absolute coordinates. Ablations (Tables 11-12) show optimal performance at C/4 dimensionality on S3DIS.

**Non-local MLPs (PreConv)**: Replacing local MLPs on grouped neighbor tensors (Conv) with non-local MLPs on the full input point set (PreConv) in ABS stages reduces FLOPs by ~k× (k neighbors). HPE compensates for the loss of implicit local positional info. A hybrid strategy—Conv only in the first ABS stage for robustness, PreConv elsewhere—achieves the best trade-off (Table 1). This approach maintains accuracy while cutting compute, validated by robustness tests under sparse inputs (Figure 11).

## Architecture Onboarding

**Component map**  
Input (N×3 + N×C_in) -> Point Embedding (C_e) -> Encoder (4 Blocks) -> Decoder (FP + BFM) -> Head (MLP).  
Each Block: ABS (FPS -> KNN -> [HPE] -> MLP -> Pool) -> optional REF (KNN -> [HPE] -> MLP -> [SOP] -> MLP). BFM fuses multi-resolution features in decoder.

**Critical path**  
1. Data flow: Input -> Embedding -> [ABS(REF)*] (Encoder) -> [FP + BFM] (Decoder) -> Classifier.  
2. HPE insertion: After KNN in ABS/REF; takes grouped relative coordinates, outputs high-dimensional features added to neighbor features.  
3. Non-local MLP path: In ABS (after first stage), MLP operates on input features (N×C) before grouping; grouping happens after MLP.  
4. BFM path: Takes low- and high-resolution features; high-res features pooled (max & mean) -> MLP -> Sigmoid -> scaling; scaled high-res concatenated with low-res after injecting pooled stats.

**Design tradeoffs**  
- HPE dimensionality (C_mlp): Higher (e.g., C) increases capacity and FLOPs; lower (C/4) is efficient but risks under-encoding (Table 12 guides choice).  
- Local vs. Non-local in ABS: First stage should use Conv (local MLP on neighbors) for detail/robustness; later stages use PreConv (non-local MLP on inputs) for efficiency. Hybrid recommended (Table 1).  
- REF stage count (B): More REF layers deepen model, increase context, raise FLOPs. Configurable per model variant (e.g., V2-S B=[0,0,0,0] vs. V2-XL B=[3,6,3,3]).  
- BFM cost vs. gain: Adds minimal parameters/FLOPs; improves mAcc by ~0.5% via better multi-resolution fusion (Table 11).

**Failure signatures**  
- Poor segmentation boundaries: Likely HPE ineffective; check HPE applied in both ABS/REF and relative coordinates used (not absolute).  
- Low mIoU on small objects/clutter: May indicate insufficient REF stages or missing BFM; verify REF count and BFM insertion.  
- Excessive FLOPs: Check if Conv used in later ABS stages; only first ABS should use Conv.  
- Degraded robustness to sparse points: Likely first ABS stage not using Conv; ensure first block uses local aggregation.

**First 3 experiments**  
1. Ablation of Local Aggregation Strategy: Replicate Table 1 on a small subset (e.g., S3DIS Area 1) with variants: all Conv, all PreConv, hybrid (first Conv, rest PreConv), all without HPE. Validate FLOP reduction and mIoU changes.  
2. HPE Dimensionality Sweep: For HPENet V2-S, vary HPE projection dimension (3, C/8, C/4, C/2, C) on S3DIS Area-5. Plot mIoU vs. FLOPs to confirm C/4 optimal (per Table 12).  
3. HPE Placement Check: For HPENet V2-B, train with HPE only in ABS, only in REF, and both (as proposed) on S3DIS Area-5. Expect both-stage HPE to significantly outperforms single-stage variants (per Table 11).

## Open Questions the Paper Calls Out
1. **HPE for synthetic point clouds**: How can HPE be optimized for synthetic datasets (ModelNet40, ShapeNetPart) where relative coordinates are less discriminative? The limitation is acknowledged but no adaptive solution is proposed.
2. **Theoretical foundation of ABS-REF**: Can the separation of local aggregation (PreConv in ABS, local MLPs in REF) be theoretically formalized to guide design beyond empirical trade-offs? The paper lacks analytical reasoning for why resolution-preserving refinement benefits more from non-local updates.
3. **BFM design principles**: What is the quantitative contribution of each BFM component (dual pooling, inverted MLP) and can it be simplified? The paper shows efficacy but does not dissect the mechanism.
4. **Compatibility with transformer variants**: Does adding HPE and non-local MLPs to transformers with complex native positional biases (e.g., grouped vector attention) cause redundancy or synergy? The study is limited to two architectures.
5. **Optimal HPE projection dimension**: What is the fundamental reason that high-dimensional projection (C/4) helps, and how does optimal dimension scale with resolution and task complexity? The link to Fourier feature theory is indirect.

## Limitations
- Generalizability of the ABS-REF decomposition to non-MLP backbones (e.g., pure transformers, sparse convolutions) is uncertain.
- Real-world inference speed may not match FLOP reductions due to KNN overhead and memory bandwidth considerations.
- Robustness to extreme point density variations beyond tested scenarios (e.g., very sparse scans) is not fully validated.

## Confidence
- ABS-REF Framework Clarity: **High** (clear mathematical definitions and consistent application).
- HPE Efficacy: **Medium** (strong internal ablations but no external replication or theoretical analysis of high-dimensional projection effects).
- PreConv Efficiency Trade-off: **Medium** (FLOP analysis and ablations convincing, but wall-clock speed and memory impact not measured).

## Next Checks
1. Decompose a Non-ABS-REF Model: Insert resolution-preserving REF stages into a single-stage MLP (e.g., PointMLP) and evaluate on S3DIS Area-5 to test the ABS-REF hypothesis.
2. HPE Dimensionality Sweep on Downstream Tasks: Vary HPE projection dimension across classification (ModelNet40) and detection (ScanNet) to validate whether C/4 remains optimal.
3. PreConv vs. Conv Under Varying k: Benchmark hybrid (first Conv, rest PreConv) against all-PreConv and all-Conv for different neighbor sizes k on ScanObjectNN to confirm robustness at small k and efficiency at large k.
