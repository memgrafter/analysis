# SLDP: Semi-Local Differential Privacy for Density-Adaptive Analytics

## Quick Facts
- **arXiv ID:** 2602.18910
- **Source URL:** https://arxiv.org/abs/2602.18910
- **Reference count:** 39
- **Primary result:** SLDP achieves lower Mean Squared Error in mean estimation and higher F1-score in classification compared to standard LDP, and lower Mean Relative Error in spatial range queries than LDP-KDTree, while approaching central DP utility.

## Executive Summary
Local Differential Privacy (LDP) provides strong per-user privacy guarantees but suffers from high utility cost when adaptive, density-dependent domain discretization is needed because iterative refinement consumes the privacy budget repeatedly. This paper introduces Semi-Local Differential Privacy (SLDP), a framework that assigns each user a data-dependent privacy region that naturally shrinks in dense areas. The core innovation is an interactive protocol with an honest-but-curious server that privately estimates these regions using locally noised membership signals over a public channel, with the key property that the cumulative privacy cost does not scale with the number of refinement iterations. This enables high-resolution adaptive grids. Experiments on synthetic and real-world datasets demonstrate that SLDP significantly improves utility (lower MSE, higher F1, lower MRE) over standard LDP and LDP-KDTree, and approaches the performance of central DP.

## Method Summary
SLDP operates in two phases: partition construction and value release. In the first phase, the server maintains a hierarchical grid (e.g., quadtree) and iteratively refines cells. Users respond to queries about their membership in frontier cells by adding Laplace noise to their binary indicators. The server uses noisy counts to decide splits, enforcing a k-anonymity constraint: a cell is split only if all children are estimated to contain at least k samples. This yields a private partition where each leaf cell has at least k true points, and cell sizes adapt to local density. Crucially, privacy loss accumulates only at the final stage when each user’s leaf cell is determined, not during intermediate rounds, due to a transcript equality property for neighboring datasets until leaf identification. In the second phase, users add noise to their data values (or produce synthetic points) with sensitivity calibrated to their privacy region’s diameter. The overall (ε,δ)-DP guarantee holds with respect to an adjacency relation that allows a user to move anywhere within their true privacy region.

## Key Results
- SLDP reduces MSE in mean estimation and increases F1-score in classification compared to standard LDP.
- For spatial range queries, SLDP yields lower Mean Relative Error than LDP-KDTree.
- SLDP’s utility approaches that of central DP, while satisfying (ε,δ)-DP under a semi-local threat model.

## Why This Works (Mechanism)
### Mechanism 1: Data-dependent k-anonymous partition
**Claim:** Privacy regions are data-dependent and shrink in dense areas via a k-anonymous partition.  
**Mechanism:** The server coordinates an interactive protocol where users respond with locally noised membership indicators over a public channel to a fixed hierarchical grid. The server privately estimates cell counts and recursively splits cells only if all children are estimated to contain at least k samples.  
**Core assumptions:** The honest-but-curious server does not collude with users; the hierarchical grid is fixed and data-independent; local noise satisfies ε-LDP per message.  
**Evidence anchors:** Abstract and Section 3 define the partition; Section 4 proof shows transcript privacy.  
**Break condition:** If estimated child counts fall below k + Δᵗ (noise-correction term) prematurely, refinement stops early, leading to larger privacy regions and reduced adaptivity.

### Mechanism 2: Redefined adjacency within privacy regions
**Claim:** Two datasets are neighbors if a single user moves within the same leaf cell of the true k-anonymous partition.  
**Mechanism:** Adjacency is defined by potential movement of a point within its privacy region, not the whole domain. The server’s private estimate of the partition must closely match the true partition.  
**Core assumptions:** The true partition exists and is k-anonymous; the server’s estimate is accurate with high probability.  
**Evidence anchors:** Abstract; Definition 3.1 and Theorem 4.1.  
**Break condition:** Significant divergence between estimated and true partitions can mis-specify adjacency and violate (ε,δ)-SLDP.

### Mechanism 3: Iteration-independent privacy cost
**Claim:** Cumulative privacy cost does not scale with refinement iterations.  
**Mechanism:** Privacy loss accumulates only when the user’s leaf cell is identified. For any neighboring datasets, the transcript distributions are identical until the leaf is reached (see proof step (6)).  
**Core assumptions:** The server follows the protocol; the user’s stopping time τᵢ is finite and coincides for neighboring datasets until leaf.  
**Evidence anchors:** Abstract; Remark 4.1; Proof of Theorem 4.1.  
**Break condition:** If the depth limit T is too small so that some users do not reach their true leaf, the final leaf is coarser, making the adjacency set larger and potentially introducing dependence on T.

## Architecture Onboarding
#### Component Map
Server -> Public Channel -> Users; Users -> Public Channel -> Server; Privacy Auditor (monitors transcript)

#### Critical Path
1. Server initializes with root cell.
2. Iteration t: Server broadcasts frontier Fᵗ (set of active cells).
3. For each cell in frontier, active users in parent cell respond with noised indicator.
4. Server estimates n̂(Fⱼᵗ), computes correction Δⱼᵗ from parent’s true count.
5. If n̂(Fⱼᵗ) ≥ k + Δⱼᵗ for all children, parent becomes inactive; else, parent added to output partition F̂.
6. Repeat until frontier empty or max depth T.
7. Post-partition: Users apply final noise with sensitivity based on leaf cell’s function range.

#### Design Tradeoffs
- Privacy vs. Granularity: Larger k → coarser, more private; smaller k → finer, higher utility but risk of incorrect splits.
- Noise Correction Δⱼᵗ: The bound is conservative; tighter bounds could improve accuracy but must not break DP.
- Communication: O(T × max frontier size) rounds; high resolution increases latency.
- Trust Model: Requires honest-but-curious server; a malicious server could break transcript equality.

#### Failure Signatures
- Partition Leakage: Final partition reveals high-density boundaries (e.g., spurious empty cells in dense areas).
- Budget Misallocation: Too much ε on partition leaves little for final noise, hurting utility.
- Stopping Too Early: k too high relative to N stops at root, reducing SLDP to standard LDP.

#### First 3 Experiments
1. **Convergence Test:** On synthetic 1D uniform data, verify partition becomes finer as N increases and cell sizes shrink in denser regions (for clustered data).
2. **Privacy Budget Accounting:** Implement transcript equality check. For two neighboring datasets, compute empirical log-likelihood ratio of full transcript; should concentrate around 0 ± ε with probability 1−δ.
3. **Baseline Comparison:** Replicate mean estimation on 2D Gaussian mixture. Compare MSE of SLDP (ε/2 for partition, ε/2 for noise) vs. LDP (ε on all points) vs. central DP. Expect SLDP to approach central DP and beat LDP.

## Open Questions the Paper Calls Out
1. **Partition Error Impact:** How do errors in the privately estimated partition affect the privacy-utility trade-off? The analysis assumes accurate estimation; no bounds on partition error probability or its utility impact are provided.
2. **Robustness to Dropout:** Can the protocol handle user dropout or asynchronous participation? Dropout can bias count estimates and cause incorrect splits; no mitigation is proposed.
3. **Optimal Budget Split:** What is the optimal split of the privacy budget between partition construction and value release? The paper uses a fixed 50/50 split without justification.
4. **Extension to Non-axis-aligned Decompositions:** Does SLDP extend to non-axis-aligned hierarchies (e.g., k-d trees)? Generalizing may affect the iteration-independent privacy property and requires new analysis.

## Limitations
- Several parameters are poorly specified, including the choice of x(δ) in the split condition to achieve overall δ=0.05, the budget allocation for SLDP-Quantization, and the correct interpretation of PrivTree parameters. These block faithful reproduction.
- The guarantee relies on an honest-but-curious server following the protocol exactly; a malicious server could violate the transcript equality argument.
- The depth limit T and its interaction with k are not fully clarified; insufficient depth can weaken the privacy guarantee.

## Confidence

- Mechanism 2 (adjacency within privacy regions): Medium
- Mechanism 3 (iteration-independent privacy cost): High
