# Mobile-Agent-v3.5: Multi-platform Fundamental GUI Agents

## Quick Facts
- **arXiv ID:** 2602.16855
- **Source URL:** https://arxiv.org/abs/2602.16855
- **Reference count:** 18
- **Primary result:** GUI-Owl-1.5 achieves state-of-the-art performance among open-source models on 20+ benchmarks, including 56.5% on OSWorld and 71.6% on AndroidWorld.

## Executive Summary
This paper presents Mobile-Agent-v3.5, a system for building native multi-platform GUI agents capable of robust automation across desktop, mobile, and browser environments. The core contribution is the GUI-Owl-1.5 model family, built on Qwen3-VL, which integrates three key innovations: a Hybrid Data Flywheel for efficient trajectory and grounding data collection, a Unified Agent Capability Enhancement pipeline with chain-of-thought synthesis, and a Multi-platform Reinforcement Learning algorithm (MRPO) for stable cross-device policy learning. The approach yields significant performance gains, setting new open-source benchmarks on diverse GUI tasks.

## Method Summary
The method centers on a three-stage training pipeline. First, a Hybrid Data Flywheel combines simulated virtual environments (for scalable atomic operations and challenging scenarios) with cloud-based real-device sandbox rollouts (for realistic app interactions) to generate diverse, high-quality trajectory and grounding data. Second, all trajectories are augmented with step-wise chain-of-thought reasoning—including observation summarization, memory extraction, reflection, and tool invocation—through a unified synthesis pipeline. Third, multi-platform reinforcement learning with the proposed MRPO algorithm stabilizes training by using a device-conditioned policy, an oversampled rollout buffer, token-ID transport for log-prob consistency, and alternating per-device optimization to mitigate gradient interference.

## Key Results
- GUI-Owl-1.5 achieves SOTA among open-source models on OSWorld (56.5%), AndroidWorld (71.6%), WebArena (48.4%), ScreenSpot-Pro (80.3%), OSWorld-MCP (47.6%), MobileWorld (46.8%), and GUI Knowledge Bench (75.5%).
- Ablations demonstrate the critical role of the Hybrid Data Flywheel (removing virtual env data drops PC-Eval/Mobile-Eval from ~75% to ~42%) and Unified CoT synthesis (removing CoT reduces OSWorld from 52.9% to 47.4% and AndroidWorld from 71.6% to 65.0%).
- MRPO stabilizes multi-platform RL; naive mixed-batch training causes performance oscillations and lower final scores.

## Why This Works (Mechanism)

### Mechanism 1: Hybrid Data Flywheel
**Mechanism:** Efficiently collects diverse, high-quality GUI interaction and grounding data by combining simulated/web-rendered virtual environments (for scalable atomic operation trajectories and challenging scenarios like pop-ups) with cloud-based real-device sandbox rollouts (for realistic app interactions). Trajectories are mined/cleaned, and grounding data is augmented via app GUI synthesis and multi-window generation.  
**Core assumption:** Real-world data collection is too costly/slow; synthetic data can be high-fidelity if validated and diverse.  
**Evidence anchors:** The abstract and Section 2.2.1–2.2.2 detail the virtual environments for trajectory production, DAG-based task synthesis, and grounding augmentation pipelines. Neighboring work (e.g., *Mobile-Agent-v3*, *GUI-Xplore*) supports the importance of synthetic data for generalization.

### Mechanism 2: Unified CoT Synthesis for Agent Capabilities
**Mechanism:** Augments all trajectory data with step-wise reasoning (observation, memory, reflection, tool invocation) to improve long-horizon planning and memory. For each step, a VLM/LLM synthesizes a screen description, query-relevant memory extraction, outcome reflection vs. expectation, and progress update.  
**Core assumption:** Raw action sequences lack explicit decision rationale; injecting structured thoughts during training teaches the model to internally simulate planning.  
**Evidence anchors:** The abstract and Section 2.3.2 describe the CoT generation pipeline. Section 3.3 (Table 10) shows ablation performance drops when removing CoT.

### Mechanism 3: Multi-platform RL with MRPO
**Mechanism:** Stabilizes reinforcement learning across heterogeneous device environments under a single policy. MRPO addresses: (i) device-conditioned policy π(a|o,d); (ii) online oversample-and-select rollout buffer to prevent group collapse in GRPO; (iii) token-ID transport to align env/training log-probs; (iv) alternating per-device optimization to reduce gradient interference.  
**Core assumption:** Mixing multi-platform trajectories in one batch causes conflicting gradients; device-specific curriculum yields stable, generalizable policy.  
**Evidence anchors:** The abstract and Section 2.4.3 detail MRPO components. Section 3.3 (Fig 8b) shows mix-platform training causes oscillations, while alternating training stabilizes performance.

## Foundational Learning
- **Vision-Language Models (VLMs):** Foundation for parsing screenshots and generating outputs (e.g., bounding boxes). GUI-Owl-1.5 builds on Qwen3-VL. *Quick check:* How does a VLM typically parse a screenshot to output a bounding box for "click 'Submit' button"?
- **Reinforcement Learning from Environment Feedback (RL):** Final stage uses MRPO to align the model with long-horizon success rewards. *Quick check:* What is the purpose of a "group" in GRPO, and why might all trajectories in a group have identical outcomes?
- **Multi-platform GUI semantics:** Desktop, mobile, and web interfaces differ in interaction paradigms (e.g., gestures vs. shortcuts) and widget sets. *Quick check:* Why might a "long press" action exist on mobile but not on desktop web, and how should the action space abstract this?

## Architecture Onboarding
**Component map:** Qwen3-VL backbone -> Hybrid Data Flywheel (simulated + cloud sandbox data collection) -> Unified CoT Annotation (step-wise reasoning synthesis) -> SFT (multi-device trajectories with tool calls) -> MRPO RL (alternating per-device optimization) -> Inference (device-conditioned policy, context compression, token-ID transport).

**Critical path:** Data collection (flywheel) → CoT annotation → SFT alignment → Multi-platform RL (alternating devices). The RL stage depends on a competent SFT model; failures propagate earlier.

**Design tradeoffs:**
- Model size vs. deployment: Small models (2B/4B) for edge/real-time vs. large thinking models (32B/235B) for complex planning.
- Trajectory diversity vs. quality: Virtual envs give scale but risk sim-to-real gap; cloud rollouts give realism but are slow/expensive.
- Unified vs. specialized policy: Single policy simplifies deployment but may plateau on niche platforms; alternating RL mitigates interference but extends training time.

**Failure signatures:**
- Grounding fails on multi-window/high-res: Insufficient hard grounding data synthesis.
- Tool/MCP calls mis-specified: SFT data lacks diverse tool invocation patterns.
- Performance drop on unseen app: Overfitting to training app distribution.
- RL training instability: Rollout buffer diversity collapse or device-conditional gradient interference.

**First 3 experiments:**
1. Ablate virtual environment trajectories: Train without virtual-env data; expect drop on PC-Eval/Mobile-Eval from ~75% to ~42%.
2. Ablate Unified CoT synthesis: Train without step-wise thoughts; expect OSWorld/AndroidWorld drops (52.9%→47.4%, 71.6%→65.0%).
3. Compare MRPO vs. naive mix-platform RL: Expect oscillations and lower final scores with mixed-batch training.

## Open Questions the Paper Calls Out
- How well does the hybrid flywheel capture real-world app updates, rare UI patterns, or edge cases?
- Does synthetic reasoning amplify errors if generation is noisy or misaligned with optimal actions?
- Can a single policy specialize adequately across divergent platforms (e.g., mobile gestures vs. keyboard shortcuts) with alternating RL?
- Are reported scores on 20+ benchmarks truly generalizable to unseen apps/OS versions, or are they in-domain?

## Limitations
- **Sim-to-real gap:** Hybrid data collection may not fully capture real-world app updates or rare UI edge cases.
- **CoT quality:** Synthetic reasoning could amplify errors if misaligned with optimal actions, harming long-horizon success.
- **Policy interference:** MRPO’s alternating optimization may still struggle with divergent interaction paradigms across platforms.
