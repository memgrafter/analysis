# A Behaviour-Aware Federated Forecasting Framework for Distributed Stand-Alone Wind Turbines

## Quick Facts
- arXiv ID: 2603.05263  
- Source URL: https://arxiv.org/abs/2603.05263  
- Reference count: 27  
- Primary result: A behaviour-aware federated two-stage framework (DRS-auto clustering + cluster-specific FedAvg LSTM) achieves competitive forecasting accuracy (test MSE 0.0179) on 400 Danish turbines, significantly outperforming geographic partitioning (MSE ~0.065) while preserving data privacy.

## Executive Summary
This paper introduces a federated learning framework for short-term wind power forecasting across distributed, stand-alone turbines. It addresses two key challenges: maintaining data privacy and handling high heterogeneity in turbine behaviours. The proposed solution consists of two stages: first, turbines are grouped into behavioural clusters using a privacy-preserving federated K-means algorithm with Double Roulette Selection (DRS) initialization and recursive Auto-split refinement; second, each cluster trains a dedicated LSTM model via FedAvg. Evaluated on 400 Danish turbines, the method discovers seven coherent behavioural clusters and yields forecasting accuracy (test MSE 0.0179, R² 0.699) that matches a strong centralized k-means++ baseline and far surpasses geographic grouping. The approach offers a practical, privacy-compliant solution for heterogeneous turbine fleets.

## Method Summary
The framework operates in two federated stages without sharing raw turbine data. Stage 1 clusters turbines based on long-term operational statistics (e.g., mean power, variability, zero-power ratio) computed locally. A server coordinates recursive federated K-means: it initializes centroids via Double Roulette Selection (DRS), which samples clients and points proportionally to squared distances to emulate k-means++ seeding without exposing raw data. Each turbine performs local K-means updates, sends cluster counts and updated centroids to the server, which aggregates weighted centroids. An Auto-split controller uses silhouette scores and size thresholds to recursively partition nodes until coherence or size criteria are met. Stage 2 spawns independent FL tasks per leaf cluster; each turbine trains an identical LSTM–MLP on local time-series windows (24 history, 3-step ahead) and shares model updates via FedAvg. The server aggregates per-cluster models, which are then used for inference.

## Key Results
- Achieved test MSE 0.0179, RMSE 0.130, MAE 0.088, R² 0.699 on 400 Danish turbines.
- Behavioural clustering (DRS-auto) discovered seven coherent clusters and matched centralized k-means++ accuracy.
- Significantly outperformed geographic partitioning (test MSE ~0.065), demonstrating the superiority of behaviour-based grouping.

## Why This Works (Mechanism)

### Behavioural clustering reduces statistical heterogeneity within FL client groups
- **Claim:** Grouping turbines by long-term operational statistics (e.g., mean power, variability) creates more homogeneous client subsets for FL, improving convergence and accuracy versus geographic or single global models.
- **Mechanism:** Locally computed behavioural features are used in federated K-means to partition turbines so that within-group time series are statistically similar. Per-cluster FedAvg then trains an LSTM on a less non-IID distribution, mitigating inter-turbine variability.
- **Core assumption:** Similar long-term statistical fingerprints imply similar short-term dynamics, so a shared forecaster per group is effective.
- **Evidence:** [abstract] behaviour-aware grouping outperforms geographic partitioning; [section 4.1] details features; [section 8.2] Tables 6–7 show DRS-auto and K++-auto beat Geo-3/7 in MSE/RMSE.
- **Break condition:** If behavioural features do not predict short-term patterns, no gain over random/geographic partitions.

### Double Roulette Selection (DRS) enables privacy-preserving, balanced federated K-means initialization
- **Claim:** DRS provides high-quality seeding for federated K-means without sharing raw data, leading to more stable and balanced cluster hierarchies than k-means++ in the federated context.
- **Mechanism:** Two-level probabilistic sampling: first select a client with probability proportional to its samples' total squared distance to existing centroids; then select a specific sample from that client proportional to its squared distance. This emulates k-means++ seeding using only client-level aggregates.
- **Core assumption:** Client-level distance aggregates are sufficient proxies for full dataset dispersion; sampling distant clients/points yields better initial centroids.
- **Evidence:** [section 5.2] full DRS description; [section 8.1] DRS-auto yields seven clusters and "splits large clusters more evenly" vs. K++-auto; [section 9.1] "DRS produces more balanced clusters".
- **Break condition:** If client-level dispersion statistics are uninformative (e.g., all clients similar), DRS reduces to random sampling with no benefit.

### Cluster-specific FL aligns model capacity with data distribution
- **Claim:** Training a dedicated LSTM per behavioural cluster via FedAvg outperforms a single global FL model because it reduces within-task heterogeneity and avoids fitting multi-modal patterns.
- **Mechanism:** Each cluster acts as an independent FL task; all turbines in a cluster collaboratively train the same LSTM architecture, sharing only model updates. The model learns patterns specific to that behavioural group.
- **Core assumption:** Discovered clusters are internally coherent enough that separate models achieve lower error than one global model, outweighing smaller per-cluster data size.
- **Evidence:** [section 6.3] cluster-specific FL reduces heterogeneity; [section 8.2] DRS-auto (7 clusters) beats Geo-3 (3 clusters) and matches K++-auto (6 clusters); [section 8.3] per-cluster metrics vary, confirming distinct patterns.
- **Break condition:** If clusters are too small or inter-cluster differences negligible, a single global model may perform equally or better.

## Foundational Learning

### Federated Averaging (FedAvg)
- **Why needed:** Core privacy-preserving optimisation primitive used in both clustering (centroid updates) and forecasting (LSTM updates) to aggregate local updates without sharing raw data.
- **Quick check:** In FedAvg, what two steps does each client perform locally before sending an update, and what does the server do with the received updates?

### Silhouette Score
- **Why needed:** Used in Auto-split to decide whether a federated K-means partition has meaningful substructure (high separation) and should be split further.
- **Quick check:** What does a silhouette score near +1 indicate about a cluster's assignment, and what does a score near -1 indicate?

## Architecture Onboarding

**Component map:**
1. Local Feature Extraction -> 2. Federated Clustering Module (DRS-auto) -> 3. Cluster Assignment -> 4. Per-Cluster FL Orchestrator -> 5. Local LSTM Training & 6. Cluster Model Aggregator (repeat per cluster) -> 7. Inference

**Critical path:** Data must flow through feature extraction, federated clustering, assignment, then per‑cluster FL cycles (local training + aggregation) before inference. Clustering completes before forecasting starts; forecasting clusters are independent.

**Design tradeoffs:**
- DRS vs. k-means++: DRS is more privacy‑preserving and yields balanced hierarchies but is more complex; K++-auto breaks strict federation initially.
- Recursive Auto-split vs. Flat K: Auto-split discovers hierarchical structure and handles imbalance; flat K is simpler but forces fixed flat partition.
- Behavioural vs. Geographic: Behavioural directly targets model heterogeneity; geographic is a trivial fallback but mixes behaviours, hurting accuracy.

**Failure signatures:**
- Clustering: Extremely imbalanced leaf clusters; silhouette scores <0.2 across splits; high within-cluster feature stds (from Table 4).
- Forecasting: Diverging train/test loss per cluster; very high MSE in a cluster with decent silhouette; R² near 0/negative on test for multiple clusters.
- System: LSTM FedAvg taking hundreds of rounds to converge (should plateau by ~50); communication dominated by one huge cluster.

**First 3 experiments:**
1. Reproduce DRS-auto clustering: Implement recursive Auto-split with DRS init on the six behavioural features; verify ~7 leaf clusters and match Table 3/4 cluster types.
2. Run per-cluster FedAvg LSTM: For a representative cluster (e.g., Cluster 3), implement the LSTM–MLP and run FedAvg; replicate convergence curves in Figure 6.
3. Baseline comparison: Implement one geographic grouping (Geo-7) and flat Fed-KMeans (K=6); train LSTMs and compare test MSE/RMSE against DRS-auto; expect Geo-7 ~0.065 vs. ~0.02.

## Open Questions the Paper Calls Out

1. **Optimal re-clustering interval:** What frequency and trigger for periodic re-clustering handle concept drift? Paper discusses every four months but lacks empirical study on interval, window size, or drift detection.
2. **Impact of imbalanced cluster sizes:** How do imbalanced clusters (e.g., one large "normal" cluster plus small anomalous ones) affect FL dynamics (convergence, fairness)? Paper notes this may affect dynamics but uses standard FedAvg without analysis.
3. **Automated anomaly handling:** Can the framework automatically identify and handle anomalous turbines (e.g., shut-down, constant output) without manual rules like those for Cluster 4? Paper manually filtered Cluster 4 and excluded Cluster 1, suggesting custom treatment but no automation.
4. **Scalability bottlenecks:** How does the framework scale in communication, server load, and time as turbines grow to thousands? Paper evaluates 400 turbines, notes training dominated by largest cluster, and does not model dropouts or stragglers.
5. **Sensitivity to feature window:** To what extent does the assumption of stationary behaviour within a one-year clustering window hold? Paper uses one year for "long-term" features but does not test sensitivity to window length or seasonal biases.

## Limitations
- Critical hyperparameters (LSTM architecture details, FedAvg settings), exact train/test splits, and missing data handling are not specified, blocking exact replication.
- Clusters with very few turbines (e.g., Cluster 2 with 4 turbines) may produce unstable models; DRS randomness could lead to variable cluster counts across seeds.
- No released code or data further impedes independent verification; wall-clock times reported for fixed fleet size may not scale.

## Confidence
- Behavioural clustering improves forecasting over geographic partitioning: **High** (direct empirical result: large MSE reduction).
- DRS initialization yields more balanced clusters than k-means++: **Medium** (supported qualitatively but lacks quantitative balance metrics).
- Cluster-specific FL outperforms a single global FL model: **Medium** (asserted but no direct global baseline comparison; indirect inference from other results).

## Next Checks
1. **Single global FL baseline:** Train an LSTM via FedAvg on all turbines (no clustering) using identical hyperparameters and data splits; report test MSE/RMSE alongside DRS-auto to confirm the need for clustering.
2. **Initialization ablation:** Fix Auto-split parameters and run DRS-auto vs. K++-auto over ≥10 random seeds; compute cluster size variance, average silhouette, and forecasting accuracy; test whether DRS consistently produces more balanced partitions and whether balance correlates with accuracy.
3. **Hyperparameter robustness:** For a representative cluster, vary LSTM hidden size, dropout, and local epochs; plot test MSE to verify the paper’s configuration is stable and that the gain over a geographic baseline persists across a reasonable range.
