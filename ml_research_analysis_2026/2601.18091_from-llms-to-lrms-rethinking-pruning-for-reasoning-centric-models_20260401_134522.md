# From LLMs to LRMs: Rethinking Pruning for Reasoning-Centric Models

## Quick Facts
- **arXiv ID:** 2601.18091  
- **Source URL:** https://arxiv.org/abs/2601.18091  
- **Reference count:** 40  
- **Primary result:** Pruning for reasoning-augmented LLMs requires task-specific strategies; static depth excels on classification, static width on generation/reasoning, while dynamic methods catastrophically fail on long-chain reasoning unless constrained (e.g., MOD’s Top‑k).

## Executive Summary
Pruning large language models (LLMs) for efficiency is well‑studied for instruction‑following models, but its application to reasoning‑centric models (LLM‑think) remains unexplored. This paper conducts a controlled study aligning calibration and recovery data with each model’s original training distribution, comparing static depth, static width, and dynamic pruning across 17 classification, generation, and reasoning tasks. Findings reveal that depth pruning preserves classification performance best, width pruning degrades more gracefully on generation and reasoning, and dynamic pruning (e.g., SkipGPT) succeeds on simpler tasks but fails catastrophically on long‑chain reasoning. The work concludes that pruning strategies must be explicitly tailored to reasoning‑centric workloads, with static methods or constrained dynamic routing (e.g., MOD) recommended for such models.

## Method Summary
The study compares pruning methods on two 8B‑parameter Llama‑3.1 variants: an instruction‑following model (tulu‑3‑SFT) and a reasoning‑augmented model (fine‑tuned on OpenThoughts). All pruning experiments use the model’s original training corpus for calibration (computing importance scores) and subsequent LoRA fine‑tuning (recovery). Structured pruning is evaluated: static depth (removing layers via SLEB, ShortGPT, or Taylor sensitivity), static width (removing channels via LLM‑Pruner or SliceGPT), and dynamic (token‑wise layer skipping via MOD, D‑LLM, SkipGPT). Performance is measured on 17 benchmarks spanning classification (BoolQ, ARC), instruction‑following/generation (IFEval, HumanEval), and reasoning (MATH‑500, AIME‑2024). The core experimental control ensures that calibration and recovery data match the model’s paradigm, isolating the effect of pruning strategy per workload.

## Key Results
- Depth pruning outperforms width on classification (e.g., Shortened‑Taylor: 7.04% decline vs. SliceGPT: 10.10% at 20% sparsity).
- Width pruning degrades more gracefully than depth on generation and reasoning (e.g., at 40% sparsity: generation decline 41.83% vs. 55.57%; reasoning 77.69% vs. 85.38%).
- Dynamic pruning (SkipGPT, D‑LLM) excels on classification/generation (2–7% decline) but catastrophically fails on reasoning (>90% decline); MOD’s Top‑k constraint retains ~40% reasoning performance.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Static depth pruning preserves classification performance better than static width because classification relies on high‑level abstract features aggregated across layers, which are disrupted less by removing entire layers than by distorting per‑layer representational subspaces.  
**Mechanism:** Depth pruning shortens the sequential path but maintains full‑width representations in remaining layers; the final representation retains discriminative signals. Width pruning compresses the feature space used throughout all layers, potentially losing nuanced class distinctions.  
**Core assumption:** Classification is less sensitive to precise depthwise computation than to the richness of the final pooled representation.  
**Evidence anchors:**  
- [abstract]: “depth pruning outperforms width pruning on classification tasks”  
- [section 5, Table 1]: Shortened‑Taylor 7.04% vs. SliceGPT 10.10% at 20% sparsity  
- [corpus]: *Think Before You Prune* notes reasoning models depend on “long chain‑of‑thought reasoning processes”, implying classification has different sensitivity.

### Mechanism 2
**Claim:** Static width pruning degrades more gracefully on generation and reasoning than depth pruning because these tasks require sustained depth for sequential dependencies and iterative refinement; width reduction attenuates but does not eliminate depthwise signal propagation.  
**Mechanism:** Width pruning (e.g., SliceGPT) removes low‑variance directions, creating a consistent lower‑dimensional manifold across all layers, preserving the full depth needed for step‑by‑step transformation. Depth pruning abruptly truncates the computational graph, breaking continuity.  
**Core assumption:** Generation and reasoning depend on minimum depth to maintain state and refine outputs; compressing width is a softer constraint than deleting layers.  
**Evidence anchors:**  
- [abstract]: “width pruning is more robust for generation and reasoning”  
- [section 5, Figure 4]: At 40% sparsity, width decline 41.83% vs. depth 55.57% on generation; 77.69% vs. 85.38% on reasoning.  
- [corpus]: *Fragile Knowledge, Robust Instruction‑Following* reports width pruning affects parametric knowledge (used in reasoning) more than instruction‑following.

### Mechanism 3
**Claim:** Dynamic pruning (e.g., SkipGPT) succeeds on classification/generation but catastrophically fails on long‑chain reasoning because token‑level routing introduces path instability that disrupts the consistent computational trajectory required for multi‑step logical coherence.  
**Mechanism:** Dynamic methods skip layers for “easy” tokens. Reasoning requires each token to depend on precise transformations from all previous tokens across many layers; ad‑hoc skipping creates inconsistent computational paths, breaking the logical thread (e.g., repetitive outputs).  
**Core assumption:** Reasoning requires a stable, contiguous computation path through model depth; dynamic skipping violates this.  
**Evidence anchors:**  
- [abstract]: “dynamic pruning excels on classification and generation but remains challenging for long‑chain reasoning” and “SkipGPT… catastrophically fail on reasoning (>90% decline).”  
- [section 5, Table 2 & Figure 5]: SkipGPT retains ~58% on generation at 20% sparsity but ~2.7% on reasoning; training loss on LLM‑think substantially higher than static methods.  
- [corpus]: *Reasoning Model Is Superior LLM‑Judge* highlights reasoning models exhibit “biased” yet consistent internal processes, suggesting path disruption harms reasoning disproportionately.

## Foundational Learning
- **Structured vs. Unstructured Pruning**  
  **Why needed:** Paper focuses on *structured* pruning (removing layers, heads, channels) for real hardware speedups; unstructured weight pruning rarely accelerates LLMs on GPUs.  
  **Quick check:** Why does removing individual weights rarely accelerate LLM inference on modern GPUs?

- **Training Distribution Alignment**  
  **Why needed:** Core experimental control uses the model’s original training data for calibration and recovery; misalignment causes performance drops (Figure 2).  
  **Quick check:** What happens to pruned model performance if calibration uses general‑domain text (e.g., C4) instead of the model’s instruction‑tuning corpus?

- **Chain‑of‑Thought (CoT) Reasoning**  
  **Why needed:** LLM‑think is defined by explicit CoT generation; findings about depth preservation and dynamic routing failure depend on the multi‑step nature of CoT.  
  **Quick check:** How does output length/structure of an LLM‑think response differ from a standard LLM‑instruct response?

## Architecture Onboarding
Component map:  
Data Pipeline (original training corpus → calibration set → recovery set) → Pruning Core (importance estimator → structured mask) → Recovery Stage (LoRA fine‑tuning) → Evaluation Suite (17 tasks: classification, generation, reasoning)

Critical path:  
1. Match data to model paradigm: use *OpenThoughts* for LLM‑think, *tulu‑3‑sft‑mixture* for LLM‑instruct.  
2. Choose pruning type based on task: for reasoning, prioritize static width or MOD; avoid aggressive depth or token‑level dynamic routing.  
3. Validate with alignment ablation: test calibration/recovery data impact (Figure 2) before comparing methods.

Design tradeoffs:  
- Depth vs. Width: Depth removal reduces sequential ops but risks breaking reasoning chains; width reduction maintains depth but may lose fine‑grained features.  
- Static vs. Dynamic: Dynamic offers higher efficiency for simple tasks but introduces optimization instability and path fragmentation for complex reasoning.  
- Calibration cost: Taylor (depth) requires gradients; PCA (width) needs activation statistics—balance accuracy with overhead.

Failure signatures:  
- Repetitive/garbled outputs on reasoning tasks → dynamic routing failure.  
- Catastrophic drop on classification with width pruning at high sparsity → over‑compression of feature space.  
- High training loss during recovery (Figure 5) → poor calibration or misaligned recovery data.  
- Forgetting to freeze early/late layers in depth pruning → unexpected performance drop.  
- Insufficient calibration samples (e.g., <1024) → unstable layer rankings.

First 3 experiments:  
1. Replicate Figure 2: Prune with mismatched calibration data (e.g., C4 for LLM‑think) to observe severe collapse.  
2. Static Depth vs. Width on Classification: Apply Shortened‑Taylor (depth) and SliceGPT (width) at 20% sparsity on ARC‑Easy; expect depth to win by ~1–2%.  
3. Dynamic Routing on Reasoning: Run SkipGPT on GSM8K; expect near‑zero accuracy at 20% sparsity, while MOD retains ~40%.

## Open Questions the Paper Calls Out
1. What specific mechanistic properties of reasoning‑augmented LLMs cause dynamic token‑wise routing (e.g., SkipGPT) to catastrophically fail (>90% decline) on long‑chain reasoning, while static pruning or constrained dynamic routing (MOD) retains ~40% performance? The paper hypothesizes path continuity but lacks rigorous analysis (e.g., probing representations, attention stability).  
2. How can dynamic pruning architectures be modified or trained to preserve long‑chain reasoning capabilities while maintaining efficiency benefits? The paper identifies MOD’s Top‑k constraint as a partial solution but leaves architectural design (e.g., hybrid routers, reasoning‑aware losses) open.  
3. To what extent do observed pruning paradigm differences generalize across model scales (sub‑1B, 70B+) and architectures beyond Llama‑3.1‑8B? The study is limited to 8B Llama models; scaling effects on redundancy and router trainability are unknown.  
4. Is strict alignment of pruning calibration/recovery data with original training distribution necessary for all paradigms, or can robust, distribution‑agnostic strategies be developed? The paper shows alignment yields superior performance but does not explore generalized calibration/recovery techniques.  
5. Is there a quantifiable relationship between reasoning chain length/complexity and optimal pruning strategy (depth vs. width, static vs. dynamic)? The paper treats all reasoning benchmarks as a block without analyzing intra‑task variations (e.g., MATH‑500 vs. JEEBench).

## Limitations
- Calibration/recovery protocols (sample count, batch size, gradient use) are unspecified, hindering exact replication.  
- Dynamic router implementation details (MOD Top‑k, SkipGPT thresholds) are underspecified.  
- Study limited to 8B Llama models and two training distributions; generalizability across scales and architectures is uncertain.  
- Evaluation hyperparameters (prompts, few‑shot settings, generation parameters) not fully documented.

## Confidence
- **Depth > width on classification**: High (7% vs 10% drop at 20% sparsity, Table 1).  
- **Width > depth on generation/reasoning**: High (41.8%/77.7% vs 55.6%/85.4% at 40% sparsity, Figure 4).  
- **Dynamic methods fail on reasoning**: High (>90% drop for SkipGPT/D‑LLM; MOD ~40% with Top‑k, Table 2, Figure 5).  
- **Data alignment critical**: High (mismatched calibration causes severe collapse, Figure 2).  
- **Pruning must match workload**: High (all results support this directive).

## Next Checks
1. **Cross‑architecture test**: Replicate key findings on a non‑Llama 8B model (e.g., Mistral‑7B) to assess generality.  
2. **Calibration robustness**: Vary calibration sample size (512–4096) and measure stability of layer rankings and performance.  
3. **Representation analysis**: Compute CCA between pruned/dense hidden states across layers to test depth vs. width mechanisms and dynamic path stability.
