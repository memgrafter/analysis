# Can LLMs Model Incorrect Student Reasoning? A Case Study on Distractor Generation

## Quick Facts
- **ArXiv ID:** 2603.15547
- **Source URL:** https://arxiv.org/abs/2603.15547
- **Reference count:** 40
- **Primary result:** LLMs generate plausible distractors by first solving correctly then simulating specific student errors, achieving proportional match up to 0.52 with CoT and 0.56 with correct answer in prompt.

## Executive Summary
This paper explores whether large language models (LLMs) can model incorrect student reasoning by generating distractors for multiple-choice math questions. The authors introduce a taxonomy to annotate LLM reasoning traces and analyze two state-of-the-art models, DeepSeek-V3.2 and GLM-4.7. Key findings reveal that LLMs predominantly employ a misconception-based pipeline: they first solve the problem correctly, then simulate specific student errors by branching from the correct solution, and finally curate a set of plausible distractors. Chain-of-thought prompting significantly improves distractor quality (proportional match from 0.34 to 0.52), and providing the correct solution in the prompt yields an additional 8% relative improvement. However, failures often arise from imperfect solution recovery and overly conservative distractor selection, indicating room for improvement in the selection mechanism.

## Method Summary
The study uses a dataset of 429 math problems from the Eedi platform. Several prompting strategies are employed: a simple direct prompt, a chain-of-thought (CoT) prompt, and prompts that include the correct solution. LLMs generate verbose reasoning traces, which are annotated with an eight-category taxonomy (e.g., INTER, CORR, ERR_DESC, ERR_SIM, INST, PLAUS, CURATE) to decode the reasoning process. Distractor quality is evaluated using proportional match—the fraction of generated distractors that semantically match human-authored ones—as determined by an LLM judge. The analysis examines the temporal order of strategies, consistency of error simulation, and failure modes. The overall pipeline involves input processing, prompt construction, trace generation, annotation, and evaluation.

## Key Results
- LLMs predominantly follow a misconception-based pipeline: correct solution → error simulation → distractor curation, aligning with expert educational practices.
- Chain-of-thought prompting raises distractor quality (proportional match) from 0.34 (direct prompting) to 0.52.
- Providing the correct solution in the prompt yields an additional 8% relative improvement in proportional match (e.g., 0.56 for DeepSeek-V3.2).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** LLMs generate plausible distractors by first solving the problem correctly, then deliberately simulating common student errors by "branching off" from the correct solution pathway.
- **Mechanism:** The correct solution acts as an anchor. The LLM identifies specific procedural steps in that solution and intentionally applies a "buggy" transformation or incorrect operation at a branching point, propagating the error to a final answer.
- **Core assumption:** LLMs possess internal representations of common procedural misconceptions (e.g., forgetting to divide all terms) that they can apply contextually to a correct solution scaffold.
- **Evidence anchors:**
  - [abstract] "...they first solve the problem correctly, then simulate specific student errors by branching from the correct solution..."
  - [section 4.2] Temporal analysis shows CORR (correct answer reference) appears early, followed by ERR_DESC/ERR_SIM/INST sequences in 92.5% (DeepSeak) / 97.8% (GLM) of traces.
  - [section 4.3] Error simulation reliability is high (92% consistent), but failures propagate from incorrect CORR recovery.
- **Break condition:** If the LLM cannot recover a coherent correct solution (CORR failure), the entire error-injection pipeline fails, as the branching foundation is invalid.

### Mechanism 2
- **Claim:** LLMs employ an implicit "overgenerate-and-rank" strategy, exploring many candidate error pathways (often >10) before selecting a final, curated set of three distractors.
- **Mechanism:** The reasoning trace reveals extensive exploration (ERR_DESC > INST). The LLM does not stop at the first three candidate errors but generates more, then uses plausibility judgments (PLAUS) and set-level curation (CURATE) to select, filter for diversity, and discard implausible or redundant candidates.
- **Core assumption:** The LLM's generative process has a built-in search/selection component that can be directed toward pedagogical goals like negative discrimination and set homogeneity.
- **Evidence anchors:**
  - [section 4.2] Manual inspection: DeepSeak considers ~12.6 hypothetical solutions vs. ~5.9 in CoT. High frequency of ERR_DESC beyond the three required distractors indicates exploration.
  - [section 4.3] CURATE reduces correct answers and repetitions, indicating active set-level filtering. However, analysis shows it is "overly conservative," discarding valid distractors.
  - [corpus] Neighbor papers like "Improving Automated Distractor Generation... with Overgenerate-and-rank" (FMR 0.531) support this as a recognized effective pattern.
- **Break condition:** If the selection/curation module (PLAUS/CURATE) is misaligned with human pedagogical judgment (as found: discards valid distractors), the final set quality degrades even with good candidate generation.

### Mechanism 3
- **Claim:** The quality of generated distractors is critically anchored to the explicit presentation of the correct solution within the prompt, which improves alignment with human-authored distractors by 8%.
- **Mechanism:** Providing the correct answer in the prompt reduces the cognitive load and potential error in the LLM's internal "solution recovery" (CORR) sub-task. It forces a shared, unambiguous reference point for subsequent error simulation, making the misconception-based pipeline more reliable.
- **Core assumption:** LLMs do not have perfect, deterministic access to the correct solution for a given problem, even when capable of solving it. External anchoring mitigates this unreliability.
- **Evidence anchors:**
  - [abstract] "Providing the correct solution in the prompt yields an additional 8% relative improvement."
  - [section 4.1] Table 2 shows proportional match increases from simple prompt (0.52) to prompt with correct answer revealed (0.56) for DeepSeak-V3.2.
  - [section 4.3] "Failures arise primarily from failures in recovering the correct solution... Providing the correct answer in the prompt significantly improves proportional match."
- **Break condition:** If the provided correct answer is itself incorrect or ambiguous (though the paper filters for unambiguous problems), the anchoring would propagate errors.

## Foundational Learning
- **Concept: Strategy Taxonomy for LLM Reasoning (Cognitive Task Analysis)**
  - **Why needed here:** The paper's core contribution is a taxonomy (INTER, CORR, ERR_DESC, etc.) to *describe* and *diagnose* the LLM's internal process. An engineer must understand this vocabulary to interpret traces, build evaluation tools, and prompt-engineer effectively.
  - **Quick check question:** What is the difference between ERR_DESC (abstract error description) and ERR_SIM (explicit incorrect computation) in a distractor-generating trace?
- **Concept: Misconception-Based vs. Similarity-Based Distractor Design**
  - **Why needed here:** The paper finds LLMs spontaneously use the misconception-based approach (preferred in learning sciences) instead of superficial similarity heuristics. Understanding this distinction is key to evaluating output quality and aligning with educational principles.
  - **Quick check question:** Give an example of a similarity-based distractor and a misconception-based distractor for simplifying `(6+9m)/3`. Which is more diagnostically informative?
- **Concept: Evaluation Metrics for Distractor Quality (Proportional Match, #correct, #repetitions)**
  - **Why needed here:** The paper uses proportional match (fraction of generated distractors matching human-authored ones) as the primary quality signal. An engineer must understand this metric's limitations (requires semantic equivalence judgment) and the importance of checking for accidental correct answers and redundancy.
  - **Quick check question:** Why is exact string match insufficient for evaluating distractor generation, and how does the paper address this?

## Architecture Onboarding
**Component map:** Input Processor -> Prompt Manager -> Reasoning Engine -> Trace Annotator -> Evaluation Module (optional: Failure Diagnoser)

**Critical path:** Input Problem → Prompt Manager (w/ correct answer) → Reasoning Engine (trace generation) → Trace Annotator (strategy tags) → Evaluation Module (proportional match) → Analysis (alignment with expert process, failure modes). For one-off generation, steps 4-6 can be skipped.

**Design tradeoffs:**
- **Trace Verbosity vs. Cost:** Reasoning traces are long (~6,800 chars) and expensive to generate/annotate. CoT is cheaper but provides less process insight.
- **Annotation Granularity:** The 8-category taxonomy balances generality and resolution. Finer granularity (e.g., sub-types of PLAUS) reduces reliability.
- **Prompt Guidance vs. Emergence:** Enforcing a multi-step procedure (§C.3) showed marginal gain over self-organized reasoning, suggesting strong models already emulate best practices. Over-prompting may stifle useful exploration.

**Failure signatures:**
- **CORR Failure:** Trace lacks a clear, correct final answer or contains arithmetic errors in the solution phase. Manifests as low proportional match even with good error simulation.
- **CURATE Failure:** Trace shows many candidate INSTs/ERR_DESCs but final selection includes redundant options, a correct answer, or omits plausible distractors. Indicates misjudged plausibility or diversity.
- **ERR_SIM Failure:** An ERR_DESC is followed by an INST that does not logically follow from the described error. (Rare per paper's 92% reliability check).

**First 3 experiments:**
1. **Replicate Performance Baseline:** Run simple prompt vs. CoT vs. reasoning prompts on the Eedi subset (N=429) for one model (e.g., DeepSeak-V3.2). Verify proportional match gains (Table 2).
2. **Apply Taxonomy:** Use the provided annotation pipeline (chunking + problem-specific examples) to annotate 30-50 traces from the best condition (reasoning + correct answer). Measure strategy frequencies and temporal evolution (like Table 3, Fig. 2). Confirm dominance of ERR_DESC and early CORR.
3. **Diagnose Failure Mode:** Manually inspect 20 low-performing traces (proportional match < 0.5). Label each with `CORR_failed?` and `CURATE_failed?`. Quantify which failure type dominates, expecting CORR issues to be primary.

## Limitations
- **Evaluation metric dependency:** The primary proportional match relies on an LLM judge for semantic equivalence, introducing subjectivity and potential judge bias not fully quantified.
- **Curation mechanism opaqueness:** The "overgenerate-and-rank" hypothesis is inferred from trace patterns but not directly probed; internal selection criteria remain a black box.
- **Generalizability:** Findings are based on a specific subset of Eedi math problems (N=429) and two proprietary models; performance may not transfer to other domains, question types, or open-weight models.

## Confidence
- **High Confidence:** LLMs predominantly use a misconception-based pipeline (solve correctly → simulate specific error → curate). Supported by strong temporal analysis (92.5%+ consistent sequence) and reliability checks on error simulation (92%).
- **Medium Confidence:** LLMs employ an implicit overgenerate-and-rank strategy. Evidence is correlational (excess candidate generation) and supported by adjacent literature, but the selection mechanism is not directly observed or controlled.
- **High Confidence:** Providing the correct solution in the prompt significantly improves distractor quality (8% relative gain). Supported by a clear ablation study (Table 2) and linked to reduced CORR failure.
- **Medium Confidence:** Primary failure mode is incorrect solution recovery (CORR failure). The paper states this but does not systematically decompose failure rates into CORR vs. CURATE vs. ERR_SIM errors across the full dataset.

## Next Checks
1. **Audit the Curation Filter:** Manually analyze a sample of *rejected* candidate distractors from high-quality traces (reasoning + correct answer prompt). Quantify how many rejected options are actually plausible and educationally valid, directly measuring the "overly conservative" CURATE failure.
2. **Isolate CORR Dependency:** Run an experiment where the model is prompted with the *incorrect* solution (mimicking a common student error) and asked to generate distractors. Compare quality against the standard "correct answer in prompt" condition. A significant drop would confirm the pipeline's brittle dependence on an accurate CORR anchor.
3. **Test Prompting for Curation Alignment:** Design a prompt explicitly instructing the model to prioritize distractor *diversity* and *negative discriminative power* (e.g., "ensure each wrong answer reflects a distinct error"). Re-evaluate proportional match and repetition rates. A reduction in discarded valid distractors would indicate CURATE misalignment is prompt-sensitive.
