# The Overlooked Role of Graded Relevance Thresholds in Multilingual Dense Retrieval
## Quick Facts
*   **arXiv ID:** 2601.04395
*   **Source URL:** https://arxiv.org/abs/2601.04395
*   **Reference count:** 40
*   **Primary result:** The choice of threshold for converting graded (0–3) relevance scores into binary labels during fine-tuning is a critical, overlooked factor that significantly impacts multilingual retrieval performance, with optimal thresholds varying systematically by language resource level.

## Executive Summary
This paper investigates the impact of the threshold used to convert graded relevance scores into binary labels during the fine-tuning of multilingual dense retrieval models. Using a dataset annotated with 0–3 scores across six languages, the authors demonstrate that the optimal threshold is not universal but varies with language resource levels: lower-resource languages benefit from more inclusive thresholds (e.g., τ=1), while higher-resource languages prefer stricter ones (e.g., τ=3). A poorly chosen threshold can degrade performance below the non-fine-tuned baseline, whereas a well-chosen one improves nDCG@10, increases data efficiency, and mitigates annotation noise. The study also reveals complex, non-additive interactions when mixing languages during training, where a single global threshold harms the target language if not aligned with its optimal setting. The findings establish threshold calibration as a essential, previously neglected component of multilingual retrieval fine-tuning pipelines.

## Method Summary
The authors construct a multilingual fine-tuning dataset using the MIRACL corpus for six languages (fi, ar, ja, ru, es, en). For each language, they use GPT-4o to generate search-intent queries for passages, retrieve top-5 candidates with `multilingual-e5-large`, and annotate query-passage pairs with graded relevance scores (0–3). This data is downsampled to 300K instances per language while balancing the count of non-zero scores. To fine-tune, they apply a threshold τ ∈ {1,2,3} to convert scores to binary labels (score ≥ τ = positive), then train `multilingual-e5-large` with an InfoNCE loss using in-batch negatives. Performance is evaluated on MIRACL dev sets (monolingual/mixture) and CLIRMatrix (cross-lingual) using nDCG@10. The core experimental manipulation is the threshold value, analyzed across monolingual training, multilingual mixtures, and cross-lingual transfer scenarios.

## Key Results
*   Threshold choice dramatically affects outcomes: poor thresholds degrade性能 below the baseline, while optimal ones yield consistent gains.
*   Optimal thresholds systematically correlate with language resource level: lower-resource languages (e.g., Arabic, Finnish) perform best with lower thresholds (τ=1), while higher-resource languages (e.g., English, Russian) prefer higher thresholds (τ=3).
*   In multilingual mixture training, a single uniform threshold creates harmful interactions; the target language’s optimal threshold must be prioritized to avoid performance regression.

## Why This Works (Mechanism)
### Mechanism 1
The threshold converts graded relevance into binary supervision for contrastive learning, directly controlling the diversity and strictness of positive examples the model internalizes. A lower threshold (e.g., τ=1) includes more moderately relevant passages as positives, encouraging broader semantic matching. A higher threshold (e.g., τ=3) restricts positives to only highly relevant passages, forcing a sharper decision boundary. This choice shapes the embedding space geometry during fine-tuning. The base model's pre-trained representations have varying degrees of calibration across languages; thus, the optimal "distance" for positives differs systematically.
*Evidence anchors:*
[abstract] "A well-chosen threshold can improve effectiveness... whereas a poorly chosen one can degrade performance."
[section 4.2] "Lower-resource languages tend to benefit from lower thresholds... higher-resource languages perform better with higher thresholds."
[corpus] Figure 4 shows lower annotation agreement for low-resource languages, suggesting their relevance boundaries are noisier and may benefit from a more inclusive threshold.
*Break condition:* This mechanism fails if the base model has no meaningful pre-trained representations for a language (e.g., truly zero-shot), as thresholding only adjusts existing signal.

### Mechanism 2
Threshold calibration mitigates the impact of noisy or inconsistent graded relevance annotations, particularly for lower-resource languages where LLM agreement is lower. By raising the threshold, one can filter out ambiguous or weakly annotated positives that might introduce noise. Conversely, a lower threshold might be robust to annotation conservatism (e.g., an LLM that rarely gives a "3") by accepting more "2" scores as positives. The threshold acts as a denoising lever aligned with annotator behavior.
*Evidence anchors:*
[section 4.1] "Agreement is substantially lower for lower-resource languages... These differences... motivate examining how threshold choices affect the preparation of fine-tuning data."
[section 4.2] "Models fine-tuned on Gemma-based relevance scores underperform... qualitative trends largely hold across annotators," indicating thresholding can partially buffer against annotator-specific biases.
[corpus] Figure 3 shows distributional shifts between annotators, especially for scores 2 and 3.
*Break condition:* If annotation noise is uniformly random or the grading scale itself is inconsistent (e.g., different interpretation of "2" across languages), thresholding may discard valid signal without stabilizing training.

### Mechanism 3
In multilingual mixture fine-tuning, a single uniform threshold applied to all languages creates complex, non-additive interactions that can harm the target language's performance unless the threshold is carefully chosen for that target. The threshold defines what constitutes a "positive" for each language in the mix. If the optimal threshold for Language A (low) differs from Language B (high), mixing them forces a compromise. This alters the training distribution's effective "hardness" and can either introduce conflicting signals or provide complementary ones, depending on the alignment between the chosen threshold and the target language's needs.
*Evidence anchors:*
[section 5] "Multilingual mixtures yield distinct behaviors... a single global threshold is clearly suboptimal. The threshold appropriate for the target language may differ from that suitable for the enriching language."
[section 5, Table 1] For Arabic (low-resource), adding any other language harms performance more severely at τ=3 than at τ=1. For Russian (high-resource), enrichment helps more at τ=3.
*Break condition:* If all languages in the mixture have identical optimal thresholds (unlikely given resource disparities), this interaction effect vanishes. Also, if the model architecture has strong per-language adapters that prevent interference, the global threshold's impact might be reduced.

## Foundational Learning
*   **Concept: Contrastive Learning with In-Batch Negatives**
    *Why needed here:* The paper's entire analysis hinges on how fine-tuning data (positives/negatives) is constructed for contrastive objectives (e.g., InfoNCE loss). The threshold directly defines these pairs.
    *Quick check question:* If you set a very low threshold (τ=1), what happens to the number of positive pairs per query, and how might that affect the loss's signal-to-noise ratio?
*   **Concept: Graded Relevance vs. Binary Relevance**
    *Why needed here:* The core innovation is leveraging the nuance in a 0–3 score rather than discarding it. Understanding why graded labels exist (e.g., nDCG) and their typical collapse to binary is prerequisite.
    *Quick check question:* Why might an LLM assign a "2" instead of a "3" to a passage? What information is lost when we only keep "3" as positive?
*   **Concept: Language Resource Level & Pre-training Exposure**
    *Why needed here:* The primary observed pattern (low-resource → lower optimal τ) is attributed to differences in pre-training data abundance. This requires understanding that model "familiarity" with a language affects what it needs to learn during fine-tuning.
    *Quick check question:* If a language was well-represented in the pre-training corpus (e.g., English), would you expect its model to already have a robust notion of "high relevance"? How would that influence the ideal threshold?

## Architecture Onboarding
*Component Map:*
Corpus & Baseline Retriever -> Query Generation Module -> Relevance Annotation Module -> Thresholding & Dataset Construction -> Fine-tuning Engine -> Evaluation Harness

*Critical path:* Query Generation → Candidate Retrieval → Relevance Annotation → **Threshold Selection** → Dataset Construction → Fine-tuning → Evaluation. The **threshold selection** is the pivotal, often overlooked, decision point between annotation and training.

*Design tradeoffs:*
- **Threshold vs. Training Data Quantity:** A well-chosen threshold can achieve gains with less data (Section 4.2). A poor threshold may require more data to overcome noise but might still underperform.
- **Uniform vs. Per-Language Thresholds:** Uniform thresholds are simpler but suboptimal in mixed-language training (Section 5). Per-language thresholds add complexity but align with the evidence.
- **Annotation Cost vs. Threshold Flexibility:** Using a fine-grained (0–3) scale costs more than binary labeling but enables post-hoc threshold tuning. The paper argues this flexibility justifies the cost.

*Failure signatures:*
- **Performance drop below baseline** when fine-tuning with a poorly chosen threshold, especially on low-resource languages with τ=3 or high-resource with τ=1.
- **Increased sensitivity to annotation source** (GPT-4o vs. Gemma) when threshold is misaligned, as noise is not filtered.
- **In multilingual mixtures, performance regression for the target language** when the added language's optimal threshold conflicts with the target's, and a single compromise threshold is used.

*First 3 experiments:*
1.  **Monolingual Threshold Sweep:** For each of 6 languages, fine-tune with 50K–300K instances at τ=1,2,3. Measure nDCG@10 on MIRACL dev. Goal: Identify resource-dependent threshold pattern (low-resource→τ=1, high-resource→τ=3).
2.  **Multilingual Mixture Impact:** For a target language (e.g., Arabic), fine-tune on 150K target-only vs. 150K target + 150K from another language (e.g., English), at each τ. Measure delta. Goal: Show that adding a high-resource language harms low-resource targets more at stricter τ.
3.  **Cross-lingual Threshold Transfer:** Take models from Exp. 1 (fine-tuned on Language X at various τ) and evaluate on CLIRMatrix pairs (X→Y). Goal: Confirm that the optimal τ for a query language is consistent across monolingual and cross-lingual tasks, and is primarily driven by the query language's resource level.

## Open Questions the Paper Calls Out
*   How does pre-training data composition (language coverage, domain diversity) influence the optimal graded relevance threshold for multilingual dense retrieval?
*   To what extent does candidate retrieval bias—introduced by using a baseline retriever to generate training candidates—affect the distribution of graded relevance labels and the optimal threshold?
*   Can we develop automatic methods to select the optimal relevance threshold per language or task, reducing reliance on manual grid search?
*   Do the observed benefits of graded relevance thresholds generalize to other dense retrieval architectures beyond contrastive learning (e.g., generative retrieval, late-interaction models)?

## Limitations
*   Exact prompts, downsampling procedure, and fine-tuning hyperparameters (e.g., optimizer details) are not fully specified, impeding exact replication. LLM annotation reliability varies across languages (lower agreement for low-resource), potentially distorting threshold patterns.
*   Evaluation is restricted to six languages from MIRACL; it is unclear whether findings generalize to other languages, especially those with different scripts or typologies.
*   The study uses a single base model (`multilingual-e5-large`); threshold effects might differ for other architectures.

## Confidence
*   **High confidence:** Threshold choice critically influences fine-tuning outcomes; poorly chosen thresholds can degrade performance below the non-fine-tuned baseline. This holds consistently across monolingual, mixture, and cross-lingual scenarios.
*   **Medium confidence:** Optimal thresholds vary systematically with language resource level (low-resource languages benefit from more inclusive thresholds). Supported by clear trends across six languages, but broader language coverage is needed.
*   **Medium confidence:** In multilingual mixtures, a single uniform threshold creates complex, non-additive interactions that can harm the target language. Evidence from several target/auxiliary pairs shows target-specific effects, but the underlying mechanism may involve untested variables.
*   **Medium confidence:** The same resource-dependent pattern extends to cross-lingual retrieval. However, cross-lingual factors (e.g., query/document language mismatch) may moderate the effect.

## Next Checks
1.  **Extend language diversity:** Replicate the threshold sweep on at least five additional languages spanning diverse resource levels and language families (e.g., Swahili, Tamil, Yoruba) to test the universality of the resource-dependent pattern.
2.  **Human annotation gold standard:** Collect human graded relevance scores for a balanced subset (e.g., 10K instances per language) and re-run the threshold analysis to determine whether the observed pattern persists beyond LLM-specific biases.
3.  **Architecture generality:** Repeat key monolingual and mixture experiments with at least two other multilingual encoders (e.g., `BGE-M3`, `XLM-RoBERTa`) to verify whether findings are model-agnostic or specific to `multilingual-e5-large`.
