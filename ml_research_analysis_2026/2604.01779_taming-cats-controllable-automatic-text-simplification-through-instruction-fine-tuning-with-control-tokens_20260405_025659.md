# Taming CATS: Controllable Automatic Text Simplification through Instruction Fine-Tuning with Control Tokens

## Quick Facts
- **arXiv ID:** 2604.01779
- **Source URL:** https://arxiv.org/abs/2604.01779
- **Reference count:** 0
- **Primary result:** Instruction fine‑tuning with control tokens yields reliable readability control but compression control is limited by data variation; error‑based metrics (MAE) are essential for evaluation.

## Executive Summary
The paper tackles the limited controllability in Automatic Text Simplification (ATS) by using instruction fine‑tuning of open‑source large language models (LLMs) with discrete control tokens that specify target readability levels (e.g., FKGL) or compression ratios. Experiments across multiple domains show that models reliably learn readability control when the training data contains sufficient variation in the target attribute, but compression control remains poor because existing parallel corpora exhibit minimal length change. The study further reveals that standard simplification metrics (SARI, LENS) do not penalize ignoring the control token, making error‑based metrics—specifically Mean Absolute Error between target and predicted attribute—indispensable for proper evaluation. Additionally, model size matters less than data representativeness; even 1–3B parameter models can be competitive. Naïve data splitting introduces distributional mismatch that harms both training and evaluation, underscoring that success in controllable ATS hinges on curated data and proper evaluation design.

## Method Summary
The approach consists of instruction fine‑tuning (IFT) on LLMs where each training example is formatted as a conversation: the user provides the source text and a control token specifying the desired attribute value (e.g., `<FKGL=5>`), and the assistant’s response is the target simplification. The control token is placed in the assistant’s response prefix, so the model learns the conditional distribution of the simplification given the source and control token. To avoid train‑test distribution mismatch, the datasets are stratified by readability (using the Kolmogorov–Smirnov test) ensuring splits are statistically representative. After fine‑tuning, inference is performed by greedy decoding with multiple seeds, and outputs are evaluated on two axes: control alignment via MAE (difference between requested and computed attribute), and simplification quality via SARI and LENS. The method is applied to several open‑source LLMs (1–7B parameters) across multiple simplification datasets.

## Key Results
- Readability control (measured by FKGL, ARI, Dale‑Chall) is reliably achieved when training data encodes sufficient variation in the attribute.
- Compression control underperforms consistently due to minimal length variation in sentence‑aligned corpora.
- Standard simplification metrics (SARI, LENS) are insufficient to measure control; error‑based metrics (MAE) are essential, and their use reveals that smaller models can be competitive when data is representative.

## Why This Works (Mechanism)
**Control Token Conditioning** – The model learns to map discrete control tokens to target attributes via IFT. The token is prepended to the assistant’s response, conditioning generation on the specified value. This works provided the training data covers a wide enough range of the attribute; otherwise the learning signal is weak and MAE remains high. Evidence includes the abstract, Section 4.1 (dynamic prompt construction), and Section 7’s conclusion linking controllability to data variation.

**Stratified Partitioning** – Naïve random splits often misrepresent the attribute distribution, causing the test set to contain out‑of‑distribution values. By employing the Kolmogorov–Smirnov (KS) test to minimize divergence between splits, the authors ensure that both training and evaluation sets reflect the full attribute spectrum. This prevents spurious performance drops and stabilizes training. Evidence: Abstract highlights naive split pitfalls; Section 5.1 details KS‑based stratification; Section 6.1 demonstrates lower KS divergence with this method.

**Error‑Based Evaluation** – SARI and LENS measure general simplification quality but ignore whether the output matches the requested attribute. The authors advocate for MAE, which directly quantifies deviation from the target value. MAE uncovers cases where models simplify correctly in absolute terms but disregard the control token. Evidence: Abstract and Section 4.4 define the dual evaluation; Section 7 stresses that measuring control requires error‑based metrics.

## Foundational Learning
- **Instruction Fine‑Tuning (IFT) with Control Tokens**: Why needed: The entire method relies on IFT to imbue LLMs with control capabilities; understanding prompt formatting, loss masking, and token placement is key. Quick check: *Why is the control token included in the assistant’s response prefix rather than only in the user instruction? What would happen if it were only in the user message?*
- **Readability and Compression Metrics**: Why needed: These metrics define the control targets; practitioners must know how they are computed (e.g., FKGL, compression ratio) and interpret their values. Quick check: *Why might sentence splitting drastically reduce ARI without changing vocabulary? How is character compression calculated if the output is longer than the source?*
- **Evaluation Metric Suite for ATS**: Why needed: Distinguishing simplification quality (SARI, LENS) from control alignment (MAE) is critical; conflating them leads to misleading evaluations. Quick check: *If a model achieves low MAE but low SARI, what might its outputs look like? Conversely, if SARI is high but MAE is high, what is the model likely doing?*

## Architecture Onboarding
Stratification Validator -> Data Preprocessor -> Prompt Builder -> Fine‑Tuning Engine -> Evaluation Runner

Critical path: Data curation → Attribute computation → Stratified splitting → Prompt formatting → IFT → Multi‑seed inference → Metric calculation

Design tradeoffs:
- **Token rounding vs. precision:** Readability values are rounded to integers and compression to one decimal, simplifying the token vocabulary but potentially limiting fine‑grained control (e.g., `<FKGL=5>` vs. `<FKGL=5.4>`).
- **Filtering strictness:** Monotonic filtering (keeping only pairs where readability decreases) ensures simplification but may reduce diversity and shift the attribute distribution, harming learning for some metrics.
- **Full fine‑tuning vs. LoRA:** Full fine‑tuning is used for models ≤4B, while LoRA (parameter‑efficient fine‑tuning) is used for larger models. This introduces a confounding factor in scaling experiments and may restrict adaptation capacity.

Failure signatures:
1. High MAE across the test set: the model ignores the control token and outputs the source or a default simplification.
2. Low training MAE but high test MAE: distributional mismatch from poor stratification; test set contains attribute values not seen during training.
3. High SARI/LENS but high MAE: the model simplifies generically but not to the target attribute (e.g., always produces moderately simple text).
4. Compression control MAE (~0.3–0.4) is much lower than readability MAE (~2–3): reflects that compression ratios in existing corpora are tightly clustered near 1.0, so even random outputs yield low MAE; readability’s wider spread makes MAE a more meaningful indicator.

First 3 experiments:
1. **Data variation audit:** For each dataset and attribute, plot histograms of (target – source) deltas. Expect large, varied deltas for readability but small deltas (0.0–0.2) for compression. If compression deltas are minimal, control learning will be poor.
2. **Stratification check:** Compute KS divergence for candidate stratification variables (FKGL, ARI, Dale‑Chall, character/word counts). Choose the variable yielding the lowest mean KS across random seeds, and verify by plotting train/test distributions of that attribute.
3. **Baseline vs. fine‑tuned MAE comparison:** On a small model (e.g., Llama‑3.2‑1B), run inference on a few test instances without fine‑tuning and after fine‑tuning. Fine‑tuning should lower MAE for readability; for compression, MAE may stay similarly low due to the data’s narrow range, illustrating that low MAE alone does not prove successful control learning.

## Open Questions the Paper Calls Out
**Open Question 1** – How can new text simplification datasets be constructed to provide sufficient variation in compression ratios for effective control learning? The paper notes that existing corpora have minimal length variation, and without diverse compression targets progress is stunted. Resolving this requires the creation and release of parallel corpora where complex‑simple pairs span a wide, intentional range of compression ratios (e.g., from significant reduction to expansion), followed by demonstrations that models fine‑tuned on such data achieve low MAE across the spectrum.

**Open Question 2** – Which error‑based evaluation metric (e.g., MAE on readability scores, compression ratios) most reliably correlates with human judgments of successful controllability? The authors argue that MAE is indispensable but do not validate it against human perception of whether a simplification meets the requested level. A human evaluation study comparing control success ratings with various automatic error‑based metrics would identify the best predictor.

**Open Question 3** – Under what data conditions (attribute distribution, dataset size, domain) does increasing language model scale lead to monotonic improvements in controllability? The paper finds non‑monotonic scaling gains and suggests data properties dominate, but does not isolate the specific characteristics (e.g., minimum attribute variance, required sample size) that determine when scaling matters. Controlled experiments varying data distribution and size across models of different scales would address this.

## Limitations
- **Data‑centric control limits:** The claim that compression control fails due to minimal corpus variation is based on existing datasets; it remains unclear whether architectural changes could extract subtle compression signals from such data, or if truly diverse corpora are a prerequisite.
- **Stratification methodology:** Using the KS test on a single attribute (FKGL) for splitting is justified, but it is uncertain whether this optimally preserves distributions for other control attributes (ARI, Dale‑Chall) or semantic content, potentially introducing hidden biases.
- **Token granularity & generalization:** Rounding readability to integers and compression to one decimal simplifies the token vocabulary but may hinder fine‑grained control. It is unknown how model performance scales with increased token precision or whether learned mappings smooth between discrete token values.

## Confidence
- **Data‑variation dependence:** **High** – Strongly supported by systematic experiments showing readability control succeeds where variation exists and compression control fails where it does not.
- **Stratified splitting necessity:** **Medium** – Empirical evidence shows KS‑stratified splits reduce divergence and improve stability, but the causal link to performance (vs. correlation) is not isolated from other curation steps.
- **Insufficiency of SARI/LENS and need for MAE:** **High** – Clear logical distinction backed by examples where models ignore control tokens yet score well on standard metrics; MAE exposes these failures.

## Next Checks
1. **Controlled Data Variation Experiment:** Construct a synthetic dataset where source sentences are fixed and target simplifications are generated with programmatically controlled compression ratios across a wide, uniform range (e.g., 0.5 to 1.5 in 0.1 increments). Train a model and measure compression control MAE. If the data‑variation hypothesis holds, the model should achieve significantly lower MAE than with existing corpora.
2. **Alternative Stratification & Attribute Analysis:** Re‑split key datasets (e.g., WikiLarge) using multiple divergence metrics (Jensen‑Shannon, Earth Mover’s Distance) on multiple attributes simultaneously (FKGL + compression ratio). Train models on each split variant and compare test MAE distributions. The KS‑on‑FKGL method should outperform random splits; a multi‑attribute measure may yield marginal gains.
3. **Token Precision Ablation Study:** For readability‑controlled models, re‑train without rounding: preserve target FKGL as floats (e.g., `5.37`) and create unique control tokens (e.g., `<FKGL=5.37>`). Compare MAE and SARI against the integer‑rounded baseline on a test set with fine‑grained targets. Finer precision should reduce MAE for intermediate values, testing the smoothness of the learned control function.
