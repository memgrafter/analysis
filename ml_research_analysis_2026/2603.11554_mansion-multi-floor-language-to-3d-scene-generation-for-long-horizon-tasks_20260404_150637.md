# MANSION: Multi-floor lANguage-to-3D Scene generatIOn for loNg-horizon tasks

## Quick Facts
- **arXiv ID**: 2603.11554
- **Source URL**: https://arxiv.org/abs/2603.11554
- **Reference count**: 40
- **Primary result**: First language-driven framework generating building-scale multi-floor 3D environments; MansionWorld dataset of 1,000+ diverse buildings; state-of-the-art embodied agents fail on multi-floor tasks (0% success in four-floor settings).

## Executive Summary
Current embodied AI benchmarks are limited to single-floor residential environments, failing to capture the complexity of real-world long-horizon tasks that span multiple floors and require rich spatial reasoning. MANSION addresses this gap with a hybrid MLLM-geometry pipeline that generates vertically aligned, navigable multi-floor floorplans and a Task-Semantic Scene Editing Agent to provision scenes for task execution. The resulting MansionWorld dataset contains over 1,000 diverse buildings (2–10 stories, 10,000+ rooms) with executable scenes in AI2-THOR. Evaluation shows that existing state-of-the-art embodied agents suffer drastic performance drops on multi-floor tasks, establishing MANSION as a critical testbed for future research.

## Method Summary
MANSION decouples high-level semantics from low-level geometry. A multimodal LLM (MLLM) first produces a building program (floor counts, vertical cores) and per-floor bubble diagrams (room topology with areas). A deterministic constrained-growth solver then converts each diagram into a vector floorplan via hierarchical splitting, ensuring no overlap, adjacency constraints, and vertical alignment of cores (stairs/elevators). A ReAct-based Task‑Semantic Scene Editing Agent checks task preconditions against a static JSON scene graph and uses a physics engine to place objects correctly if needed. The pipeline requires no training; it leverages MLLM open‑vocabulary abilities and rule‑based geometry for scalable, diverse building generation.

## Key Results
- **Dataset scale**: MansionWorld contains 1,000+ buildings (2–10 stories, 10,000+ rooms) with fully executable scenes in AI2-THOR.
- **Floorplan quality**: Constrained‑growth solver achieves 76.74% micro‑IoU on ResPlan‑1K, demonstrating strong generalization beyond residential data.
- **Embodied task failure**: State‑of‑the‑art agents (BUMBLE, COME‑robot) achieve 0% success in four‑floor settings, highlighting the difficulty of long‑horizon multi‑floor tasks.

## Why This Works (Mechanism)

### Constrained-growth floorplan generation with vertical alignment
- **Claim**: Generates feasible multi‑floor buildings by recursively splitting parent regions under hard constraints that preserve vertical cores (stairs/elevators) and exterior contours across floors.
- **Mechanism**: Takes a room topology graph. A hub node seeds hierarchical splitting. The MLLM proposes seed rectangles for children within the parent region. The geometry solver then grows polygons from these seeds with target areas, ensuring no overlap, respecting adjacency constraints, and maintaining vertical alignment (e.g., load‑bearing walls). Adaptive radii and energy‑based scoring guide the search.
- **Evidence anchors**:  
  - [abstract] "hybrid MLLM‑geometry pipeline with a constrained‑growth solver to produce vertically aligned floorplans, ensuring navigable structures."  
  - [section 3.1] Detailed algorithm: hierarchical splitting, cutting MLLM node, single‑cut solver, energy‑based scoring.  
  - [section 4.1] Achieves 76.74% micro‑IoU on ResPlan‑1K; ablation shows hierarchical splitting improves from 45.65% to 63.56%.  
  - [corpus] Neighbors like ChatHouseDiffusion focus on single‑floor generation and degrade on ResPlan (Table 3); none explicitly model vertical alignment.  
- **Break condition**: Fails if the MLLM generates an invalid graph (e.g., missing vertical cores) or seeds far from feasible areas; also struggles with very high room counts (>15) or inconsistent vertical core placement across floors.

### Task‑Semantic Scene Editing Agent for precondition enforcement
- **Claim**: Guarantees that a generated building is executable for a given long‑horizon task by automatically checking and provisioning missing objects or connectivity while preserving structural realism.
- **Mechanism**: Operates via a ReAct loop. Decomposes the task into preconditions (e.g., path exists, object present). Uses fast checks against a static JSON scene graph (no simulation) for topology and object queries. If a precondition fails, invokes action tools (PlaceInContainer, PlaceOnSurface) that trigger a temporary physics engine to place objects correctly, then updates the JSON.
- **Evidence anchors**:  
  - [abstract] "Task‑Semantic Scene Editing Agent that modifies scenes via open‑vocabulary commands to meet task needs."  
  - [section 3.2] Describes Check‑and‑Provision workflow (Figure 4) and hybrid state management.  
  - [section 4.2] Object placement yields 100% reachability and zero collisions, confirming provisioning reliability.  
  - [corpus] Prior work (e.g., Holodeck) generates scenes from scratch but does not edit existing ones for task readiness; MANSION’s agent fills this gap.  
- **Break condition**: Cannot handle structural changes (e.g., adding doors) beyond its object‑placement tools. Placement can fail if surfaces are too cluttered or the physics solver cannot find collision‑free poses.

### Decoupled MLLM‑geometry pipeline for open‑world generalization
- **Claim**: Enables generation of diverse building types without retraining by separating high‑level semantics (MLLM) from low‑level geometry (deterministic solver).
- **Mechanism**: MLLMs handle only semantic tasks: building program planning, per‑floor bubble diagrams, and seed proposals. The geometric solver is a non‑learning, constraint‑based system (constrained growth, energy scoring) that operates under the MLLM’s guidance. This avoids data‑driven overfitting and leverages MLLMs’ open‑vocabulary capabilities.
- **Evidence anchors**:  
  - [abstract] "This design achieves true open‑world scalability, generating diverse building types without new data or retraining."  
  - [section 3.1] "We employ an MLLM‑driven hybrid architecture that decouples high‑level semantics from low‑level geometry."  
  - [section 4.1] On ResPlan‑1K (non‑residential), MANSION achieves 76.74% micro‑IoU while ChatHouseDiffusion drops to 29.36%, demonstrating strong generalization.  
  - [corpus] ChatHouseDiffusion and HouseDiffusion are trained on residential RPLAN and show limited generalization; MANSION’s non‑learned solver avoids this limitation.  
- **Break condition**: If the MLLM misinterprets the description and proposes an infeasible program (e.g., excessive rooms), the solver may be unable to satisfy constraints. Hand‑crafted energy weights might need retuning for exotic layouts.

## Architecture Onboarding
- **Component map**:  
  User Input -> Whole Building Planner (MLLM) -> Per‑Floor Planners (MLLM) -> Geometric Solver -> Scene Instantiation -> AI2‑THOR scene. Task‑Semantic Scene Editing Agent can modify the scene before/after instantiation. Cross‑Floor Assets & Skills (stair/elevator models, APIs) are used by embodied agents. MansionWorld Dataset stores generated buildings.
- **Critical path**:  
  1. Derive numeric constraints (floor count, area) and building footprint from description.  
  2. Whole Building Planner produces global program.  
  3. For each floor: Per‑Floor Planner creates bubble graph → Geometric Solver generates layout.  
  4. Scene Instantiation assembles a complete 3D scene.  
  5. (Optional) Task‑Semantic Scene Editing Agent checks and edits the scene for a specific task.
- **Design tradeoffs**:  
  - Hard constraints vs. expressiveness: Strict topological and vertical alignment guarantees navigability but may limit layout diversity.  
  - MLLM guidance vs. deterministic solver: Open‑vocabulary semantic control comes with variable seed quality; the solver ensures geometric validity but depends on MLLM outputs.  
  - Fast static checks vs. accurate physics: The editing agent uses a static JSON for most queries to avoid simulation overhead; physics is invoked only for object placement, limiting full physical validation.  
  - Hierarchical splitting vs. global optimization: Splitting simplifies the problem and scales, but may not produce globally optimal area distribution.
- **Failure signatures**:  
  - Constrained growth exhausts all retries without success → likely poor MLLM seeds or impossible topology.  
  - Object placement reaches reachability <100% or has collisions → placement algorithm or physics constraints too tight.  
  - Task editing agent enters a loop (repeatedly failing a check) → missing tool or unfixable precondition (e.g., structural change needed).  
  - Multi‑floor embodied agent success rate 0% → possible skill API bug (e.g., floor transition), or VLM misidentification of objects/rooms.
- **First 3 experiments**:  
  1. Floorplan generation validation: Run MANSION on the T2D test set, compute micro‑ and macro‑IoU against ground truth (reproduce Table 2). Confirms geometry solver accuracy.  
  2. Object placement quality: Generate a library scene, measure reachability and collision count as in Table 4. Validates instantiation and reachability enforcement.  
  3. Single‑floor embodied task: Deploy BUMBLE (with object‑type augmentation) in a MansionWorld apartment to fetch and deliver an item. Expect ~60% success (Table 5 baseline); verifies integration of skills and scene execution.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: How can object placement diversity be improved in highly structured environments (e.g., classrooms) while preserving regularity and reachability?
- **Basis in paper**: [explicit] The user study (Sec. 4.2) notes MANSION's slight underperformance on Classroom regarding object count and diversity, hypothesizing that repetitive desk/chair formations reduce perceived diversity.
- **Why unresolved**: The current group‑based placement prioritizes regularity and reachability, leading to repetitive arrangements for grid‑like layouts. The anchor‑based grouping and matrix constraints produce uniform placements that lack variety.
- **What evidence would resolve**: Conduct a study comparing human ratings of diversity across placement algorithms with controlled randomness within structural constraints. Could incorporate stochasticity in anchor positions within allowed ranges or learn diverse placement priors from non‑residential datasets.

### Open Question 2
- **Question**: What algorithmic improvements are needed to enable embodied agents to successfully complete long‑horizon multi‑floor tasks (e.g., four‑story environments)?
- **Basis in paper**: [explicit] Sec. 4.3 states "All methods fail in the four‑floor setting, reflecting the difficulty... The results also highlight the need to develop new algorithms tackling long‑horizon robotics tasks."
- **Why unresolved**: Existing agents (BUMBLE, COME‑robot) rely on VLMs that struggle with object identification and planning over many floors; they lack robust memory and cross‑floor coordination. The high‑level planner gets overwhelmed.
- **What evidence would resolve**: Systematic ablation studies isolating failure modes (vision, memory, planning), and development of novel memory architectures or hierarchical planners that can handle building‑scale task graphs, evaluated on MANSION's four‑floor benchmark.

### Open Question 3
- **Question**: How can floorplan generation methods generalize better to complex, out‑of‑distribution building layouts without retraining?
- **Basis in paper**: [inferred] In Sec. 4.1, CHD's zero‑shot performance on ResPlan‑1K is poor, while MANSION's constrained growth achieves higher IoU. The authors hypothesize that CHD's training on near‑duplicate RPLAN data limits diversification.
- **Why unresolved**: Data‑driven diffusion models like CHD are constrained by their training distribution; they cannot easily adapt to new building types or layouts without additional training data. MANSION's rule‑based growth generalizes but may not capture fine‑grained statistical patterns.
- **What evidence would resolve**: A controlled study comparing data‑driven vs. hybrid approaches across varied building types, measuring generalization with limited training. Also investigating data augmentation strategies to reduce duplication bias.

## Limitations
- **Vertical alignment specifics**: The algorithm for preserving load‑bearing walls and stair cores across independently generated floors is underspecified, which is critical for multi‑floor navigability.
- **MLLM prompt engineering**: Exact system prompts, visual encoding (e.g., image resolution, color schemes), and hyperparameters for the "cutting MLLM node" are not disclosed, making reproducibility sensitive to prompt design.
- **Scene instantiation details**: The generation and selection of "room cards" (material preferences, openness types) from LLM outputs lack a defined taxonomy and integration procedure with the building‑level style.

## Confidence
- **Constrained‑growth solver**: Medium (strong single‑floor results and ablations, but break conditions for complex topologies and cross‑floor consistency mechanism remain unclear).
- **Task‑Semantic Scene Editing Agent**: High (concrete placement results with 100% reachability and zero collisions; limitations explicitly bounded to object‑level edits).
- **Decoupled pipeline generalization**: Medium (generalization beyond residential data demonstrated, but performance tied to quality of open‑vocabulary MLLM outputs, which is variable and not fully characterized).

## Next Checks
1. Inspect vertical core alignment: Generate a multi‑floor building and explicitly measure the positional deviation (in centimeters) of stair/elevator polygons across consecutive floors. A deviation >0.5m would indicate a flaw in the alignment enforcement.
2. Stress‑test editing agent with improbable preconditions: Provide tasks requiring structurally impossible edits (e.g., "place a grand piano in the middle of a load‑bearing wall") to confirm the agent correctly fails or requests human intervention instead of forcing invalid placements.
3. Run sensitivity analysis on MLLM prompts: Systematically vary the prompt wording and image encoding for the bubble diagram generation stage. Quantify the resulting micro‑IoU variance to establish the robustness boundary of the hybrid pipeline.
