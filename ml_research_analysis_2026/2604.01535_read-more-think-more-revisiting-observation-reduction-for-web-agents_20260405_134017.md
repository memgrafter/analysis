# Read More, Think More: Revisiting Observation Reduction for Web Agents
## Quick Facts
- arXiv ID: 2604.01535
- Source URL: https://arxiv.org/abs/2604.01535
- Reference count: 18
- Primary result: Higher-capability models benefit from detailed HTML observations, while lower-capability models perform better with compact accessibility trees; thinking token budget and observation history further modulate performance.

## Executive Summary
This study revisits observation reduction in LLM-based web agents, challenging the assumption that compact representations always improve performance. Experiments on WorkArena L1 reveal that the optimal observation representation depends on model capability and thinking token budget. Higher-capability (proprietary) models achieve significantly better task success with detailed HTML inputs—gaining up to +17.5 percentage points over compact accessibility trees (a11y)—and this benefit grows with increased thinking tokens. In contrast, lower-capability (open-source) models perform better with a11y. Error analysis indicates HTML helps stronger models exploit layout cues (e.g., CSS z-index) to reduce grounding errors like intercepted clicks, while weaker models suffer more from not-found errors due to hallucination under longer inputs. Incorporating observation history consistently improves success rates across models, and a diff-based history provides a token-efficient alternative.

## Method Summary
The study evaluates LLM-based web agents on the WorkArena L1 benchmark (330 tasks) using various observation representations: HTML, accessibility tree (a11y), and a11y with screenshots. Agents are configured with different observation histories (no history, 4-step history, 9-step history full or diff) and varying thinking token budgets. The primary metric is task success rate; secondary metrics include grounding error breakdowns (not-found, intercepted) and action repetition. Experiments span proprietary models (Claude Sonnet 4, GPT-5.1, Gemini 2.5 Flash, o3-mini) and open-source models (GPT-OSS family, Qwen3-VL, Llama-3.1). The AgentLab framework manages environment interaction via id-based action grounding with Playwright.

## Key Results
- High-capability models see up to +17.5 pp improvement with HTML over a11y; low-capability models perform better with a11y.
- The HTML advantage grows with larger thinking token budgets.
- Adding observation history improves success rates across models; diff-based history offers token efficiency.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: For higher-capability models, HTML observations improve task success over a11y by providing layout cues (e.g., CSS z-index) that reduce intercepted click grounding errors.
- **Mechanism**: Detailed HTML includes CSS style information that encodes element stacking order. Capable models can reason over this to avoid clicking on overlapped elements, thus lowering interception failures.
- **Core assumption**: The model has sufficient reasoning capability to parse and utilize CSS layout information within its thinking process.
- **Evidence anchors**:
  - [abstract] "Error analysis indicates HTML helps stronger models exploit layout cues (e.g., CSS z-index) to reduce grounding errors like intercepted clicks"
  - [section] Section 3.3: "Intercepted errors decrease across all models, particularly for higher-capability ones. The HTML used in our experiments includes CSS style information specifying z-index... We hypothesize that higher-capability models leverage this information to infer element overlap."
  - [corpus] Corpus evidence is weak; neighboring papers discuss HTML/a11y representations but not the specific mechanism of layout cues for grounding.
- **Break condition**: If HTML does not include CSS layout information (e.g., z-index) or if the model cannot reason over such details, the benefit disappears.

### Mechanism 2
- **Claim**: Larger thinking token budgets amplify the performance gap between HTML and a11y, with HTML showing greater gains as thinking tokens increase.
- **Mechanism**: Extended thinking tokens allow the model to more thoroughly process the verbose HTML input, filtering irrelevant details and focusing on actionable elements, thereby reducing hallucination and improving grounding.
- **Core assumption**: The model's reasoning process can effectively leverage additional tokens to extract and utilize relevant information from longer observations.
- **Evidence anchors**:
  - [abstract] "this benefit grows with increased thinking tokens."
  - [section] Section 3.2: "increasing reasoning effort from low to high for gpt-5.1 yields a larger performance gain from HTML. A similar trend is observed for gemini-2.5-flash, where increasing thinking budget from 128 to 16384 also leads to a larger gain from HTML."
  - [corpus] Corpus evidence is moderate; some neighboring papers address long-context reasoning but not the specific interaction with observation representation.
- **Break condition**: If the thinking budget is severely limited or the model does not effectively utilize extra tokens for observation processing, the amplification effect may not occur.

### Mechanism 3
- **Claim**: Incorporating observation history consistently improves task success by reducing action repetition and enhancing progress tracking.
- **Mechanism**: Historical observations provide context about prior actions and page changes, enabling the agent to avoid redundant actions and better infer task state transitions.
- **Core assumption**: The agent's policy can successfully integrate historical information to adjust future decisions.
- **Evidence anchors**:
  - [abstract] "Incorporating observation history consistently improves success rates across models"
  - [section] Section 3.4: "The results show that adding observation history improves performance for most models and settings." Also: "a lower repetition rate is associated with a higher success rate, and adding observation history tends to reduce the repetition rate."
  - [corpus] Corpus evidence is weak; neighboring papers on memory (e.g., Chain-of-Memory) exist but do not directly support this specific finding.
- **Break condition**: If history becomes too long and causes distraction, or if the model cannot effectively parse the history due to context limits, the benefit may saturate or reverse.

## Architecture Onboarding
- **Component map**:
  LLM Policy -> Observation Renderer -> History Buffer -> Action Grounding -> Environment
  (The agent loop: step t: get current observation o_t (HTML/a11y), append history if any, construct prompt, LLM outputs action a_t, grounded via Playwright, environment returns o_{t+1} and reward.)

- **Critical path**:
  1. At step *t*, agent obtains current page observation *o_t* (formatted as HTML or a11y).
  2. If history is enabled, retrieves *k* past observation-action pairs (full or diff).
  3. Constructs prompt with task instruction, *o_t*, and history; sends to LLM.
  4. LLM generates action string *a_t* with optional reasoning tokens.
  5. Action is grounded via Playwright using element IDs; execution may fail with grounding errors.
  6. Environment transitions to new state; returns *o_{t+1}* and reward.
  7. Repeat until termination or step limit.

- **Design tradeoffs**:
  - **Observation detail vs noise**: HTML provides layout cues but increases token count and risk of hallucination for weaker models; a11y is compact but may omit useful information.
  - **History completeness vs efficiency**: Full history preserves all details but consumes many tokens; diff history is token-efficient but may omit unchanged context.
  - **Thinking budget vs cost**: More thinking tokens improve exploitation of detailed observations but increase latency and cost.

- **Failure signatures**:
  - High *not-found* grounding errors when using HTML with lower-capability models → indicates hallucination under long inputs.
  - High *intercepted* errors with a11y → indicates lack of layout information to avoid overlapping elements.
  - High action repetition rate → suggests insufficient history context or poor progress tracking.

- **First 3 experiments**:
  1. **Baseline replication**: On WorkArena L1, compare HTML vs a11y for a high-capability (e.g., GPT-5.1 high) and a low-capability model (e.g., GPT-OSS-20b). Measure success rates and grounding error breakdowns.
  2. **Thinking budget sweep**: For a single model with controllable thinking (e.g., Gemini), vary thinking budget (e.g., 128 vs 16384) and compute Δ(success) between HTML and a11y. Expect larger Δ with larger budget.
  3. **History evaluation**: With a11y as observation, compare hist0, hist4, hist9 (full vs diff). Measure success rates and action repetition rates. Expect diff to match full with fewer tokens.

## Open Questions the Paper Calls Out
- **Open Question 1**: Do the findings on observation representation generalize to other websites and domains beyond WorkArena L1? (The study is confined to a single benchmark on ServiceNow; generalization is unverified.)
- **Open Question 2**: Would the observed trends between model capability, thinking tokens, and observation representation hold under alternative grounding schemes (e.g., coordinate-based or vision-based grounding)? (The experiments are limited to id-based grounding.)
- **Open Question 3**: What specific components of HTML (e.g., CSS z-index, full DOM nesting) are responsible for the reduced grounding errors in higher-capability models, and can their individual contributions be quantified? (Evidence is correlational; ablation needed.)
- **Open Question 4**: How does combining detailed observation representations (e.g., full HTML) with longer observation histories affect performance, and does the token efficiency of diff-based history persist for tasks with horizons beyond 15 steps? (History experiments fixed representation to a11y; interaction with HTML and longer tasks unexplored.)

## Limitations
- Findings are based on WorkArena L1 (ServiceNow), limiting generalizability to other web domains.
- Proprietary model token budgeting (reasoning effort) is opaque and may vary across providers.
- HTML includes CSS style information that may not be present on all sites; real-world HTML is often messier and may include extraneous data.

## Confidence
- HTML advantage for high-capability models: Medium (empirical support but single benchmark; replication needed)
- Thinking budget amplification: Medium (trend observed, but budget control coarse and model-specific)
- Observation history (diff) benefits: High (consistent improvements across models and tasks)

## Next Checks
- Cross-benchmark replication: Run identical experiments on a publicly available web agent benchmark (e.g., Mind2Web or WebArena) to confirm generalizability.
- Token budget fine-grained study: For a model with explicit thinking token control (e.g., Gemini), vary budgets in small increments (e.g., 256, 1024, 4096) and measure HTML vs a11y performance gap to establish a dose-response relationship.
- CSS ablation: Create a variant of HTML observations with all CSS style attributes removed; compare against standard HTML on high-capability models to isolate the contribution of layout cues.
