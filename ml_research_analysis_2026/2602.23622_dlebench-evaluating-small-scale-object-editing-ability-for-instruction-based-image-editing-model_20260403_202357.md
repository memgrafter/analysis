# DLEBench: Evaluating Small-scale Object Editing Ability for Instruction-based Image Editing Model

## Quick Facts
- **arXiv ID:** 2602.23622  
- **Source URL:** https://arxiv.org/abs/2602.23622  
- **Reference count:** 33  
- **Primary result:** DLEBench reveals universal struggles among IIEMs for small-scale object edits (<10% area); top model Gemini-3-Pro scores only 48.97/100 on Instruction Following, with "Change Count" as the hardest task.

## Executive Summary
DLEBench introduces a benchmark to evaluate instruction-based image editing models (IIEMs) on small-scale object edits (1–10% image area), a previously overlooked capability gap. It provides 1,889 samples across seven instruction types and a dual-mode evaluation framework (Tool-driven and Oracle-guided) with refined rubrics to overcome misalignment between LMM-as-a-Judge and human evaluations. Testing ten IIEMs shows severe performance deficits, particularly for editing object counts. The proposed evaluation modes significantly improve correlation with human judgments, establishing a more reliable assessment protocol for fine-grained image editing.

## Method Summary
DLEBench constructs its dataset via a semi-automated three-stage pipeline: (1) counterfactual synthesis from visual reasoning QA pairs to generate editing instructions and metadata, (2) a crop-and-edit strategy with adaptive bounding box expansion to create reference images for tiny targets, and (3) human verification to ensure semantic and visual fidelity. For evaluation, it employs a dual-mode framework: Tool-driven mode uses an LMM with external tools (GroundingDINO, Zoom-In, localize_differences, Enhancer) to compensate for limited fine-grained perception, while Oracle-guided mode pre-crops or masks images using human-annotated bounding boxes to isolate the edit region. Both modes apply hierarchical 4-point rubrics for Instruction Following and Visual Consistency to minimize subjectivity.

## Key Results
- All ten evaluated IIEMs perform poorly: Gemini-3-Pro leads with 48.97/100 on Instruction Following; open-source Bagel-Think achieves the highest overall score of 61.00.
- "Change Count" is the most challenging instruction type, with models failing to accurately edit multiple small objects.
- The proposed dual-mode evaluation (Tool-driven and Oracle-guided) achieves higher Spearman correlation and lower MAE with human judgments than standard LMM-as-a-Judge, with Krippendorff’s α > 0.79 for inter-annotator agreement.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** A semi-automated three-stage pipeline can transform existing visual reasoning datasets into a benchmark for small-scale object editing.
- **Mechanism:** The pipeline uses (1) counterfactual synthesis to convert QA pairs into editing instructions/metadata, (2) a crop-and-edit strategy with adaptive bbox expansion to generate high-quality reference images for tiny targets, and (3) human verification to ensure semantic and visual fidelity.
- **Core assumption:** Small-scale object editing is a distinct capability gap not covered by existing benchmarks; valid editing instructions and reference images can be derived from visual reasoning context.
- **Evidence anchors:** [abstract] "We design a semi-automated three-stage transformation pipeline..." [section 3.1] Details of Metadata Construction, Reference Image Generation, Human Verification. [corpus] Neighboring benchmarks (I2EBench, EdiVal-Agent) focus on general editing, not small-scale construction.

### Mechanism 2
- **Claim:** Refined, failure-mode-based score rubrics for Instruction Following (IF) and Visual Consistency (VC) reduce subjectivity and enable precise error diagnosis.
- **Mechanism:** Replaces ambiguous descriptors (e.g., "most changes missing") with 4-point hierarchical scales defined by concrete failure modes (Localization Failure → Wrong Action → Over Modification → Flawless Execution for IF; Scene Collapse → Multiple Anomalies → Single Anomaly → Perfect Consistency for VC). Evaluation follows a strict sequential check (e.g., localization → action → preservation).
- **Core assumption:** Model performance on small-scale editing can be systematically decomposed into localized failure types, and human annotators can reliably distinguish these modes.
- **Evidence anchors:** [abstract] "refined score rubrics to minimize subjectivity and ambiguity..." [section 4.1] Full rubrics (Tables 3, 5) and mandated evaluation process. [section 7] Human annotation document shows high Krippendorff's Alpha (>0.79).

### Mechanism 3
- **Claim:** A dual-mode evaluation framework (Tool-driven and Oracle-guided) using an LMM with external tools or oracle bboxes achieves much higher correlation with human judgment than vanilla LMM-as-a-Judge.
- **Mechanism:** Tool-driven: LMM agent iteratively calls tools (Grounding, Zoom-In, localize_differences, Enhancer) to compensate for poor fine-grained perception. Oracle-guided: Human-annotated target bboxes pre-crop images for IF and mask targets for VC, forcing the LMM to ignore localization.
- **Core assumption:** State-of-the-art LMMs lack native visual resolution/attention to reliably evaluate edits affecting <10% of an image; their performance can be augmented via tool augmentation or oracle pre-processing.
- **Evidence anchors:** [abstract] "dual-mode evaluation framework... addressing the misalignment..." [section 4.2] Describes Tool-driven iterative loop and Oracle-guided cropping/masking. [section 5.3] Figure 8 shows higher Spearman ρ / lower MAE for dual modes vs. LMM-as-a-Judge.

## Architecture Onboarding
- **Component map:**  
  Data Source Layer (visual reasoning datasets) → Transformation Pipeline (GPT-4.1 synthesis, human bbox, Gemini crop-edit) → Benchmark Artifacts (1,889 samples) → Evaluation Engine (LMM + Tool Suite OR Oracle pre-crop/mask) → Scoring Rubrics (IF/VC 4-level scales)
- **Critical path:**  
  Raw Visual QA Sample → GPT-4.1 Metadata → Human Bbox & Verify → Gemini Crop-Edit → Final DLEBench Sample → (Tool-driven: LMM+Tools iterating OR Oracle-guided: Pre-crop/mask) → Rubric-based Label → Score
- **Design tradeoffs:**  
  - Tool-driven: Practical (no human annotation at eval time) but depends on tool reliability (GroundingDINO struggles with tiny objects, necessitating Zoom-In loops).  
  - Oracle-guided: Maximizes reliability (bypasses localization) but requires human bboxes, eliminating fully automated evaluation.  
  - Rubric design: Hierarchical failure modes improve reproducibility but may still require subjective judgment on "Over Modification" boundaries.
- **Failure signatures:**  
  - In Tool-driven: LMM repeatedly calls Zoom-In without converging on target bbox (localization loop failure).  
  - In Oracle-guided: Low IF scores despite perfect bboxes indicate fundamental model inability to execute the edit.  
  - Systemic: High "Localization Failure" rate across models confirms small-object perception as primary bottleneck.
- **First 3 experiments:**  
  1. Benchmark Characterization: Compare DLEBench's target area CDF against prior benchmarks to validate small-scale focus.  
  2. Model Stress-Test: Evaluate 10 IIEMs on DLEBench, measuring IF/VC per instruction type; expect near-uniform low scores, especially on "Change Count".  
  3. Evaluation Validation: Compute Spearman ρ and MAE between each evaluation mode (Tool-driven, Oracle-guided, LMM-as-a-Judge) and human judgments; expect Oracle-guided > Tool-driven > LMM-as-a-Judge.

## Open Questions the Paper Calls Out
1. **How can we automatically generate a balanced set of small-scale editing instructions across all seven types without manual annotation?**  
   *Basis in paper:* [explicit] Authors identify unbalanced instruction distribution as a primary limitation and state they "will develop an automated data expansion pipeline" (Section 6).  
   *Why unresolved:* Manual curation is labor-intensive; current imbalance (e.g., few "Change Count" samples) prevents comprehensive evaluation.  
   *What evidence would resolve it:* An automated pipeline that synthesizes high-quality, semantically valid samples for underrepresented instruction types with human verification, demonstrating improved coverage and model performance correlation.
2. **What architectural or training modifications enable IIEMs to accurately edit multiple small-scale objects in cluttered scenes?**  
   *Basis in paper:* [explicit] "Change Count" is hardest due to "inherent complexity of accurately isolating and enumerating multiple small target objects" (Section 5.2).  
   *Why unresolved:* All evaluated IIEMs show severe performance drops on Change Count, indicating a fundamental gap in spatial reasoning and counting under low pixel ratios.  
   *What evidence would resolve it:* Introduce explicit multi-object localization and counting modules (e.g., iterative detection heads, count-aware loss functions); show significant improvement (>20% gain) on Change Count subset.
3. **Can the dual-mode evaluation framework be unified into a single automated method that maintains human-level alignment without requiring oracle human annotations?**  
   *Basis in paper:* [explicit] Oracle-guided uses human bboxes (high correlation), Tool-driven is automated but lower correlation; standard LMM-as-a-Judge misaligns (Sections 4.2, 5.3).  
   *Why unresolved:* Trade-off between practicality (Tool-driven) and reliability (Oracle-guided) limits scalable evaluation.  
   *What evidence would resolve it:* Develop a self-verifying LMM or learned localization module achieving Spearman ρ >0.90 and MAE <0.08 vs. human judgments, fully automated and generalizable across IIEMs.

## Limitations
- Pipeline scalability & corpus novelty: Human verification rejection rate unknown; derived data may inherit biases from source corpora (MME-Realworld, etc.), limiting diversity.
- Tool-driven evaluation robustness: Depends on external tools; possible failure if localization loops fail (>30% non-convergence) as noted in break conditions.
- Rubric generalizability: Hierarchical failure modes improve reproducibility but may have subjectivity in boundary cases (e.g., distinguishing "Over Modification" from "Single Anomaly").

## Confidence
- **Pipeline scalability & corpus novelty:** Medium confidence (human verification rate unreported; corpus biases plausible but not quantified).
- **Tool-driven evaluation robustness:** Medium confidence (tool reliability depends on external implementations; break condition not stress-tested in paper).
- **Rubric generalizability:** High confidence (Krippendorff’s α >0.79 and strong human alignment in validation experiments).
