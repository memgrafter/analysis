# Learning to Rewrite Tool Descriptions for Reliable LLM-Agent Tool Use

## Quick Facts
- arXiv ID: 2602.20426
- Source URL: https://arxiv.org/abs/2602.20426
- Reference count: 40
- Primary result: Trace-Free+ achieves 70.1% subtask success and 54.0% query success on StableToolBench, outperforming D0 and D1 baselines.

## Executive Summary
This paper tackles tool interface quality as a key bottleneck for LLM-agent tool use, especially in cold-start or privacy-constrained scenarios where execution traces are unavailable. Existing trace-dependent methods also optimize tools in isolation. The authors introduce Trace-Free+, a curriculum learning framework that first learns from trace-rich supervision and then adapts to generating improved descriptions without traces. They build a large-scale dataset by annotating real APIs, synthesizing multi-step queries, collecting execution traces, and producing data-independent (D1) and trace-aware (D2) descriptions. Fine-tuning models like Qwen3-4B on this data yields a generalizable description generator. On StableToolBench, Trace-Free+ reaches 70.1% subtask success and 54.0% query success, surpassing D0 (67.3%, 48.0%) and D1 (66.5%, 49.4%). Cross-domain evaluation on RestBench TMDB shows 88.1% subtask success (vs D0 69.8%). As the number of candidate tools grows beyond 100, Trace-Free+ exhibits the smallest performance drop, demonstrating robustness.

## Method Summary
The pipeline begins with a tool health annotator that probes APIs to filter "good" tools and gather successful call examples. A query synthesizer then uses tool schemas and historical call data to generate dependency-aware synthetic queries requiring multi-step tool usage. A tool-using agent executes these queries to collect execution traces (successes and failures). An improver generates enhanced descriptions: D1 via general guidelines, and D2 by extracting rules from failed traces using RIMRULE. These improved descriptions, paired with original tools and optionally trace summaries, form a supervised fine-tuning dataset. A curriculum learning strategy mixes trace-based and trace-free examples, starting with 10% trace-based and increasing to 90% trace-free. The fine-tuned model (e.g., Qwen3-4B) then generates improved descriptions for unseen tools at inference time, with or without traces.

## Key Results
- Trace-Free+ achieves 70.1% subtask-level success and 54.0% query-level success on StableToolBench, outperforming D0 (67.3%, 48.0%) and D1 (66.5%, 49.4%).
- Cross-domain evaluation on RestBench TMDB yields 88.1% subtask success, compared to D0's 69.8%.
- With over 100 candidate tools, Trace-Free+ shows the smallest performance degradation, demonstrating robustness to large tool pools.

## Why This Works (Mechanism)
### Mechanism 1: Curriculum Learning for Trace Transfer
- **Claim:** Mixing trace-based and trace-free examples enables the model to transfer supervision from trace-rich training to trace-free deployment.
- **Mechanism:** The model first observes how execution traces reveal failure causes and usage constraints, then gradually adapts to generating descriptions without traces, forcing internalization of abstract schema-based reasoning.
- **Core assumption:** Patterns from traces (e.g., parameter errors, ordering dependencies) are generalizable to unseen tools using only schema and description information.
- **Evidence anchors:** Curriculum improves over non-curriculum baselines (Trace-Free+ 70.1% SL vs Trace-Free 67.8% SL); ablation in Table 4 shows benefit of progressive mixing.

### Mechanism 2: Rule Extraction from Failed Traces
- **Claim:** Encoding failure modes as natural language rules (via RIMRULE) materially improves descriptions.
- **Mechanism:** Failed trajectories are compared to successful ones to identify root-cause errors; these are distilled into compact textual rules capturing constraints (e.g., format requirements, call ordering). Incorporating these into D2 descriptions provides explicit guidance absent in original human-oriented descriptions.
- **Core assumption:** Failures are systematic and reusable across queries; natural language rules make descriptions more actionable without requiring traces at inference.
- **Evidence anchors:** D2 (69.5% SL) outperforms D1 (66.5% SL) in trace-based evaluation; rules are derived from real failure patterns.

### Mechanism 3: Dependency-Aware Synthetic Queries
- **Claim:** Multi-step queries with inter-tool dependencies generate richer execution traces for description improvement.
- **Mechanism:** By analyzing tool call histories, the synthesizer selects APIs forming coherent workflows and generates natural language queries requiring all APIs in sequence. Agent execution on these queries yields traces with ordering mistakes, parameter errors, and output misuse—signals for refining descriptions.
- **Core assumption:** Queries with strong dependencies force agents to reason about tool chaining, exposing more failure modes than single-hop queries.
- **Evidence anchors:** Cross-domain transfer to RestBench TMDB (88.1% SL) suggests captured patterns are transferable beyond training domain.

## Foundational Learning
**Curriculum Learning** - Why needed: To transfer knowledge from trace-rich training to trace-free deployment, understanding how mixing strategies affect retention versus adaptation is key. - Quick check: What if trace-based and trace-free examples were sampled randomly instead of following a curriculum?

**Tool Interface Specification** - Why needed: Optimizing natural language descriptions requires knowing what makes an interface effective for LLM agents (clarity, completeness, constraints). - Quick check: Which specific description elements most strongly predict correct parameter generation?

**Execution Trace Supervision** - Why needed: Traces provide the training signal; understanding their collection, content (calls, errors, observations), and relation to description quality is foundational. - Quick check: Why are both successful and failed traces needed, and how do they contribute differently to D1 versus D2?

**Teacher-Forcing Evaluation** - Why needed: This protocol isolates description quality from agent planning errors, critical for interpreting metrics like SL/QL. - Quick check: How would results differ with standard end-to-end evaluation, and what would that reveal about descriptions versus agent reasoning?

## Architecture Onboarding
**Component map**
Tool Health Annotator -> Query Synthesizer -> Trace Collector -> Description Improver -> SFT Trainer -> Inference Engine

**Critical path**
Raw APIs -> Health Annotation -> Seed Tools -> Query Synthesis -> Trace Collection -> Description Improvement (D1/D2) -> SFT Dataset Construction -> Curriculum Training -> Generator Model -> Inference on Unseen Tools -> Improved Descriptions -> Agent Evaluation

**Design tradeoffs**
- Curriculum vs. Mixed Training: Staged curriculum (10% trace-based then 90% trace-free) chosen over uniform mixing for higher trace-free performance; adds training complexity.
- Synthetic vs. Real Queries: Synthetic queries ensure controlled dependencies and unlimited data but risk domain shift; mitigated by cross-domain evaluation.
- Parameter Fixing vs. Description Only: Focus on descriptions because parameter fixing without traces is extremely challenging; joint optimization left for future work.
- Per-tool vs. End-to-end Optimization: Per-tool description improvement scales better and generalizes more than end-to-end agent RL, but may miss multi-tool interaction effects.

**Failure signatures**
- Poor cross-domain performance (e.g., model trained on StableToolBench fails on RestBench) indicates overfit queries or rules.
- Sharp performance drop as tool count scales (comparable to D0) suggests descriptions lack discriminative power in large candidate sets.
- Small gap between Trace-Free and Trace-Free+ implies curriculum did not effectively transfer trace knowledge.
- Large teacher-forcing versus end-to-end gap (unmeasured) could imply descriptions don't fully resolve planning issues.

**First 3 experiments**
1. Reproduce trace-free main results on StableToolBench using provided splits (Split B train, Split A test) and verify Trace-Free+ > D1 > D0 in SL/QL as in Table 1.
2. Validate curriculum effect: Ablate by training models with 100% trace-based, 100% trace-free, and 50-50 mixing; compare all on trace-free test set. Expect curriculum to match or exceed best.
3. Test scaling robustness: Replicate Figure 3 by incrementally adding irrelevant tools and plotting query success versus candidate count; confirm Trace-Free+ has the shallowest drop slope.

## Open Questions the Paper Calls Out
- **Joint optimization of agent fine-tuning and tool interfaces:** How can both be optimized together? Currently treated sequentially; joint training could enable mutual adaptation but is unexplored.
- **Joint optimization of parameter schemas and descriptions:** The method assumes fixed schemas; extending to jointly refine schemas and descriptions could address schema defects.
- **Generalization to non-API tools:** Does the framework apply to databases or code execution environments? Only RESTful APIs are evaluated.
- **End-to-end training:** Can tool interface optimization be combined with agent training in an end-to-end fashion? Sequential training may miss opportunities for further gains.

## Limitations
- Implementation details for query synthesis and rule extraction are missing, hindering reproducibility.
- Teacher-forcing evaluation isolates description quality but not agent planning; end-to-end performance gap is unknown.
- Cross-domain evaluation limited to TMDB; broader generalization unproven.
- Synthetic queries may not reflect real user intent distribution.

## Confidence
- Trace-Free+ outperforms baselines: **High** (consistent gains across metrics).
- Curriculum transfer benefit: **Medium** (ablation shows improvement but schedule optimality not fully explored).
- D2 rule enhancement: **Medium** (improves over D1 with traces; trace-free benefit may be confounded).
- Synthetic query realism: **Low** (no validation against natural queries).
- Cross-domain generalizability: **Medium** (strong on TMDB but single domain).

## Next Checks
1. Curriculum design: Compare progressive (10%→90%) versus random mixing and reverse curriculum (90%→10%) on trace-free test set to isolate sequencing effect.
2. End-to-end impact: Deploy Trace-Free+ descriptions in a full agent (GPT-4) on StableToolBench and RestBench; compute success rates and gap versus teacher-forcing.
3. Trace fidelity: Sample generated queries and traces; analyze failure mode distribution and compare to real ToolBench traces; verify correctness of extracted rules in D2.
