# HALT: Hallucination Assessment via Log-probs as Time series
## Quick Facts
- **arXiv ID**: 2602.02888
- **Source URL**: https://arxiv.org/abs/2602.02888
- **Reference count**: 34
- **Primary result**: HALT (5M) outperforms Lettuce (30× larger ModernBERT) on HUB (macro-F1 67.0 vs 64.0) and FA V A (61.6 vs 40.3) with 60× speedup.

## Executive Summary
Hallucinations in large language models (LLMs) pose significant safety risks, yet many detection methods rely on internal model access, external retrieval, or surface‑text analysis, limiting their applicability—especially for proprietary APIs. HALT addresses this by introducing a purely black‑box approach that consumes only the top‑20 token log‑probabilities at each generation step. These log‑probabilities are treated as a time series, processed by a lightweight gated recurrent unit (GRU) augmented with entropy‑based features to capture model calibration bias. By avoiding hidden states and raw text, HALT works with any model that exposes token‑level probabilities.

Evaluation on HUB—a new benchmark covering ten capabilities—and on FA V A shows that HALT, with only 5 million parameters, achieves superior performance while being dramatically faster. On HUB it records a macro‑F1 of 67.0 compared to Lettuce’s 64.0, and on FA V A it reaches 61.6 versus 40.3. The 60× speedup underscores its efficiency. These results confirm that log‑prob trajectories contain robust signals for hallucination detection, offering an effective, model‑agnostic solution.

## Method Summary
HALT treats the sequence of log‑probabilities for the top‑20 candidate tokens at each generation step as a univariate or multivariate time series. For every token position, the method collects the log‑prob values of these 20 tokens and optionally computes the entropy of the corresponding probability distribution to quantify uncertainty. The resulting sequence (log‑prob vectors ± entropy) is fed into a small GRU (a few layers, few hidden units) that learns temporal patterns indicative of hallucinations. The final hidden state of the GRU is passed to a simple classifier (e.g., a linear layer) that outputs a decision (hallucination vs. non‑hallucination) or a score. Because the input is limited to top‑k log‑probs—information typically available through LLM APIs—the detector operates as a black box, requiring no model gradients, hidden states, or even the generated text itself. Training is performed on a labeled dataset of model outputs with known hallucination status.

## Key Results
- HALT (5M parameters) attains macro‑F1 **67.0** on the HUB benchmark, beating Lettuce (macro‑F1 **64.0**) despite having **30× fewer parameters**.
- On FA V A, HALT achieves macro‑F1 **61.6** compared to Lettuce’s **40.3**.
- HALT delivers a **60× speedup** relative to Lettuce, making it suitable for low‑latency applications.

## Why This Works (Mechanism)
Hallucinations often arise from mis‑calibrated model confidence, where the assigned probabilities do not reflect true correctness. The trajectory of top‑k log‑probabilities across generation steps encodes how the model’s confidence evolves; abnormal patterns—such as sudden drops, oscillations, or sustained high confidence on incorrect paths—are characteristic of fabricated content. Entropy features further highlight moments of distributional uncertainty. A lightweight GRU is adept at capturing these temporal dynamics without needing the full model state. Because the signals exist in the log‑prob series itself, HALT can detect hallucinations using only this limited black‑box information.

## Foundational Learning
- **Log‑probability time series**  
  *Why needed*: Provides a compact, model‑agnostic representation of confidence over the generation sequence.  
  *Quick check*: For each token, extract the logits of the top‑k candidates from the API and plot their values over time.

- **Gated Recurrent Unit (GRU)**  
  *Why needed*: Efficiently models temporal dependencies in the log‑prob sequence with far fewer parameters than transformers.  
  *Quick check*: Implement a single‑layer GRU and verify it can learn to predict a sine wave from noisy samples.

- **Entropy**  
  *Why needed*: Quantifies the spread of the probability distribution at each step; spikes often accompany hallucinations.  
  *Quick check*: Compute entropy = –∑ pᵢ log pᵢ for the top‑k distribution; high values indicate diffuse, uncertain predictions.

- **Black‑box detection**  
  *Why needed*: Extends hallucination mitigation to proprietary models where only output probabilities are exposed.  
  *Quick check*: Run HALT end‑to‑end using only an API that returns top‑k token log‑probs; ensure no hidden states are used.

- **Model calibration bias**  
  *Why needed*: Hallucinations are closely tied to over‑ or under‑confidence; HALT directly targets this bias.  
  *Quick check*: Measure Expected Calibration Error (ECE) on a held‑out set; compare before/after applying HALT’s features.

## Architecture Onboarding
**Component map**: `Log‑prob extraction -> Feature stacking (entropy) -> GRU -> Classifier`

**Critical path**:  
1. The target LLM generates a token sequence; for each token, the API returns the log‑probabilities of the top‑20 candidates.  
2. These vectors are arranged into a time‑series matrix (steps × 20).  
3. Per‑step entropy is computed and appended to the vector (or used as a separate channel).  
4. The GRU processes the sequence; its final hidden state is pooled.  
5. A linear classifier consumes the pooled state to produce a hallucination score or label.

**Design tradeoffs**  
- *Top‑k size*: Larger *k* preserves more distributional information but increases input dimensionality; HALT chooses *k*=20 as a balance.  
- *GRU vs. Transformer*: GRU reduces parameters and memory, enabling the 60× speedup; it may miss very long‑range dependencies that a transformer could capture.  
- *Black‑box restriction*: Excluding internal states limits the feature set but maximizes applicability to closed models.  
- *Entropy feature*: Adds negligible computation yet often improves sensitivity to uncertain predictions.

**Failure signatures**  
- Elevated false‑positive rates on inherently uncertain but correct generations (e.g., creative writing).  
- Degraded performance when the optimal top‑k differs from 20; very small *k* may discard critical tail information.  
- Poor calibration on models that are extremely over‑confident across the board, reducing entropy contrast.  
- Short sequences (< 5 tokens) provide insufficient temporal context for the GRU to learn meaningful patterns.

**First experiments**  
1. *Baseline sanity check*: Run HALT on a set of clearly non‑hallucinated outputs from the target model to establish typical entropy ranges and GRU activation distributions.  
2. *Ablation on top‑k*: Evaluate HALT with *k* ∈ {5, 20, 50} to verify robustness to this hyperparameter for the given model and task.  
3. *Speed benchmark*: Measure end‑to‑end inference latency per sample and compare it against a reference detector (e.g., Lettuce) to confirm the claimed speedup under your hardware constraints.

## Limitations
- HUB is a novel benchmark; its coverage and potential biases have not been independently validated.
- Comparisons are limited to Lettuce; other state‑of‑the‑art hallucination detectors were not evaluated.
- The use of only the top‑20 tokens may discard informative tail probabilities; sensitivity to this choice remains unclear.
