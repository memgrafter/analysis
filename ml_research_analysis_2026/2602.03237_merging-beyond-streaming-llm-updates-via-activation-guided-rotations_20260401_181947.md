# Merging Beyond: Streaming LLM Updates via Activation-Guided Rotations
## Quick Facts
- arXiv ID: 2602.03237
- Source URL: https://arxiv.org/abs/2602.03237
- Reference count: 40
- Primary result: Streaming merging with ARM surpasses fully converged SFT checkpoints, achieving up to +3.0 avg points on math reasoning for 7B models and +1.9 for 14B models.

## Executive Summary
This paper introduces Streaming Merging, a paradigm that treats model merging as an iterative optimization process to approximate supervised fine-tuning (SFT) dynamics. The core method, Activation-guided Rotation-aware Merging (ARM), uses activation differences to derive rotation matrices that align parameter subspaces, treating merging coefficients as learning rates. This allows the merged model to move beyond the affine hull of input checkpoints and follow data-driven trajectories. Experiments on models from 1.7B to 14B parameters show that ARM with streaming merging surpasses fully converged SFT checkpoints, achieving improvements of up to +3.0 average points on math reasoning for a 7B model and +1.9 for a 14B model. ARM also enhances performance on code generation and after reinforcement learning, using only early training checkpoints and requiring minimal additional compute.

## Method Summary
Streaming Merging reinterprets model merging as an iterative process rather than a one-shot combination. Starting from an early checkpoint, the method repeatedly applies the Activation-guided Rotation-aware Merging (ARM) operator. For each iteration, ARM collects activations from the current model and a reference checkpoint on a small calibration set, computes the activation difference ΔA, and performs SVD to extract left singular vectors U, which serve as a rotation matrix. The model parameters are updated as `W_new = W_current + λ U (W_ref - W_current)`, where λ acts as a learning rate. The reference selection follows a two-phase schedule: initially, a fixed set of early checkpoints are used as anchors to stabilize alignment; after several iterations, the scheme transitions to a sliding window where the most recent merged model becomes the reference. The process continues until convergence criteria (e.g., weight angular change) or a maximum number of iterations. This approach enables the merged model to approximate SFT update directions without additional gradient computation, using only early checkpoints and minimal calibration data.

## Key Results
- ARM with streaming merging yields improvements of up to +3.0 average points on math reasoning for a 7B model and +1.9 for a 14B model compared to converged SFT checkpoints.
- The approach enhances performance on code generation and after reinforcement learning, using only early training checkpoints and minimal additional compute.
- Streaming merging consistently outperforms single-turn merging across model scales from 1.7B to 14B parameters.

## Why This Works (Mechanism)
### Mechanism 1: Streaming Merging as Iterative Optimization
- **Claim:** Streaming Merging reinterprets model merging as an iterative optimization process rather than a static interpolation, enabling performance beyond a single merged checkpoint.
- **Mechanism:** Starting from early training checkpoints, the framework applies a sequence of merging operations. Each iteration uses a merging operator (e.g., ARM) on the current merged model and a reference (either an anchored checkpoint or models from a sliding window), progressively refining the parameters.
- **Core assumption:** The parameter differences between consecutive training checkpoints contain complementary knowledge about the optimization trajectory that can be leveraged in a streaming fashion.
- **Evidence anchors:** Abstract; Section 3.1 formal definitions; corpus shows neighboring papers focus on single-turn merging.
- **Break condition:** If geometric discrepancy between merging candidates is too small (e.g., late-stage converged checkpoints), streaming iterations yield minimal gain.

### Mechanism 2: Activation-Guided Rotation Aligns Subspaces
- **Claim:** Activation-guided rotation (via SVD of activation differences) aligns parameter subspaces, allowing the merged model to approximate gradient descent directions and escape the affine hull of input checkpoints.
- **Mechanism:** For a pair of checkpoints (Wi, Wj), collect calibration data activations A_i = W_i X and A_j = W_j X. Compute ΔA = A_j - A_i, perform SVD (ΔA = UΣVᵀ), and use the left singular vectors U as an orthogonal rotation matrix. Apply this rotation to the task vector (W_j - W_i) before scaling by a learning-rate-like coefficient λ.
- **Core assumption:** The principal components (U) of activation shifts ΔA empirically estimate the dominant error directions (gradient subspace) encountered during the intervening training steps, under i.i.d. data assumptions (XᵀX ≈ cI).
- **Evidence anchors:** Abstract; Section 3.2 theoretical derivation; Section 3.3 Equation (3); neighboring papers use activations for static weighting, not rotation.
- **Break condition:** If calibration data is misaligned with the target task distribution, the computed U may rotate along irrelevant subspaces, harming performance.

### Mechanism 3: Two-Phase Streaming Schedule Stabilizes Alignment
- **Claim:** A two-phase streaming schedule (anchoring followed by sliding-window refinement) stabilizes early-stage alignment while adapting to later-stage optimization shifts.
- **Mechanism:** Initially, use a fixed set of early checkpoints as anchors to establish a stable geometric reference (Eq. 4). After several iterations, switch to a sliding window where the most recent merged model becomes the reference for subsequent merges (Eq. 5), allowing adaptation to more recent optimization dynamics.
- **Core assumption:** Early checkpoint differences exhibit larger geometric divergence requiring stable anchoring, while later differences are smaller and benefit from adaptive, windowed refinement.
- **Evidence anchors:** Section 3.1; Section 5; Appendix A.7 ablation shows hybrid best for smaller models, anchoring alone for converged 14B.
- **Break condition:** If training dynamics are highly non-stationary (e.g., in RL), the anchored phase may lock in suboptimal directions, and the sliding window may introduce instability without sufficient geometric shift.

## Foundational Learning
- **Supervised Fine-Tuning (SFT) dynamics**: Understanding gradient descent, learning rates, and loss landscape geometry is essential to grasp why rotation aligns with optimization. Quick check: How does a learning rate η balance step size and direction in gradient descent, and what might happen if only direction (not magnitude) is adjusted?
- **Singular Value Decomposition (SVD) and activation-based analysis**: SVD decomposes a matrix into orthogonal basis and singular values; left singular vectors span the feature space. Quick check: Given ΔA representing activation shifts, what do the columns of U represent, and why are they suitable for rotating weight matrices?
- **Model merging baselines (Task Arithmetic, TIES, DARE)**: Knowing limitations of linear interpolation (affine hull constraint) and data-aware methods clarifies ARM's novelty. Quick check: What is the "affine hull" in merging, and why does conventional merging restrict solutions to it?

## Architecture Onboarding
**Component map:**
Checkpoint Manager -> Calibration Data Loader -> Activation Extractor -> SVD Engine -> Merging Operator (ARM) -> Streaming Scheduler -> Evaluation Harness

**Critical path:** 
Checkpoint selection → Activation collection for (current, reference) → SVD on ΔA → Compute U → Apply ARM update → Check convergence → If not converged, update current model and select next reference (per schedule) → Repeat.

**Design tradeoffs:**
- Rotation computation cost: Full SVD on large activation matrices is expensive; trade off between batch size (stability) and speed.
- Schedule choice: Anchoring gives stability but may cause rigidity; sliding window adds adaptability but risks oscillation. Hybrid is best but adds hyperparameters.
- Early vs. late checkpoints: Very early checkpoints may need more iterations; late checkpoints converge faster but offer less complementary knowledge. Paper recommends 2-3 checkpoints total.

**Failure signatures:**
1. Performance degradation after first merge: λ too large or U misaligned due to noisy calibration data.
2. Oscillating validation scores across iterations: Sliding window too aggressive; increase anchoring steps or reduce λ.
3. No improvement over single checkpoint: Checkpoints too similar (late stage), or batch size too small causing ill-conditioned U.
4. Catastrophic forgetting: ARM's rotation may overshoot; try lowering λ or using AIM-style constraints.

**First 3 experiments:**
1. Single-turn vs. Streaming: Apply ARM in one shot vs. iterative streaming. Expect streaming to yield higher final score.
2. Rotation necessity: Ablate U (i.e., use TA) within streaming schedule. Expect significant drop, especially for smaller models.
3. Batch size sensitivity: Test batch sizes {16, 64, 256} for activation collection. Expect performance to stabilize at 64; smaller batches noisier, larger minimally better but costlier.

## Open Questions the Paper Calls Out
### Open Question 1
Can ARM's activation-guided rotations consistently approximate gradient descent dynamics in reinforcement learning (RL) settings characterized by high variance and sparse rewards? The paper hypothesizes that noisy policy gradients and sparse rewards hinder stable semantic alignment but lacks controlled experiments.

### Open Question 2
Under what conditions does the theoretical alignment between activation differences (via SVD) and gradient directions break down, particularly when calibration data deviates from i.i.d. assumptions? The paper assumes i.i.d. inputs but does not test robustness to biased or non-stationary calibration data.

### Open Question 3
What is the optimal scheduling policy (e.g., anchoring duration, sliding window size, transition criteria) for streaming merging across different model convergence regimes and scales? The paper uses a hybrid schedule but admits it is heuristic; no analysis links schedule to loss landscape properties.

## Limitations
- Activation extraction protocol (layer, token pooling, bias/LayerNorm handling) is not fully specified, potentially affecting performance.
- The streaming schedule (anchoring duration, transition) is heuristic and may not generalize across model scales and tasks.
- Repeated full SVD incurs high computational cost and scaling to larger models/streams is untested; calibration data sensitivity is not systematically evaluated.

## Confidence
- Streaming merging outperforms single-turn merging: **High**
- Activation-guided rotation aligns with gradient directions: **Medium**
- Two-phase schedule optimality: **Low**
