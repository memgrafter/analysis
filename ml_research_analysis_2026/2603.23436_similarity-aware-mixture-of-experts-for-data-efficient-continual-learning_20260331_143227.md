# Similarity-Aware Mixture-of-Experts for Data-Efficient Continual Learning

## Quick Facts
- **arXiv ID:** 2603.23436
- **Source URL:** https://arxiv.org/abs/2603.23436
- **Reference count:** 40
- **Primary result:** On ImageNet-R with 1% data, achieves 71.5% Final Average Accuracy, surpassing state-of-the-art baselines.

## Executive Summary
Continual learning under per-task data scarcity and unknown task overlap remains a formidable challenge. This paper introduces a similarity-aware mixture-of-experts (SA-MoE) framework that leverages a frozen pre-trained vision transformer and a dynamically growing prompt pool. Two key innovations are incremental global pooling to gradually expand capacity and reduce routing noise, and instance-wise prompt masking based on Relative Mahalanobis Distance to separate in-distribution samples (routed to old prompts) from out-of-distribution samples (routed to new prompts). Evaluations on diverse benchmarks (ImageNet-R, 5-Datasets, DomainNet, M-EMNIST) demonstrate substantial improvements in sample efficiency, scalability, and forgetting reduction, particularly in low-data regimes and mixed task sequences.

## Method Summary
The SA-MoE framework builds upon a frozen pre-trained vision transformer backbone. It maintains a global prompt pool that incrementally grows: at the start of each new task, a fixed number of fresh prompts are added and initialized orthogonally to existing ones. For each incoming sample, a Relative Mahalanobis Distance (RMD) score is computed from the sample’s [CLS] embedding against feature statistics (per-class means/covariances and a global background) accumulated from all previously seen tasks. Samples with RMD below a threshold (the q‑quantile of past RMD scores) are considered in‑distribution and routed only to previously updated prompts; others are out‑of‑distribution and routed exclusively to the new prompts added for the current task. From this masked subset, a query mechanism (cosine similarity between the [CLS] embedding and learnable prompt keys) selects the top‑K most relevant prompts. The selected prompts are combined (e.g., concatenated) with the [CLS] feature and fed to a lightweight classification head, which is trained alongside the selected prompts. After each task, the statistics buffer is updated with features from the just‑completed task; no historical data is retained. This design balances knowledge reuse and isolation: incremental pool growth ensures sufficient capacity even with scarce data, while instance‑wise masking prevents negative transfer by exploiting distributional similarity.

## Key Results
- **ImageNet-R (1% data):** Final Average Accuracy reaches 71.5%, surpassing existing methods.
- **5‑Datasets (15 tasks):** FAA of 88.45%.
- **M‑EMNIST:** FAA of 99.31%, with consistent gains in low‑data and mixed‑task sequences while reducing forgetting.

## Why This Works (Mechanism)
The paper attributes the method’s effectiveness to three synergistic mechanisms:

1. **Incremental Global Pooling** – The prompt pool expands gradually with tasks. This increases selection frequency of previously updated prompts early in training, improving the signal‑to‑noise ratio for their updates. Evidence: Section 5.1 shows that restricting pool size when the task index *t* is small leads to more frequent reuse of past prompts. A break condition: if tasks are extremely similar, gradual expansion may under‑allocate capacity, causing representational collapse.

2. **Instance‑wise Prompt Masking** – Using RMD computed from past task statistics, each sample is classified as ID or OOD. ID samples query only old prompts; OOD samples query only new prompts. This separation prevents negative transfer. Evidence: Table 1 reports an AUC of 0.877 for RMD‑based separation, outperforming other query mechanisms (~0.6–0.75). A break condition: with extremely scarce past data, RMD may misclassify ID as OOD, leading to unnecessary prompt proliferation.

3. **Combined Adaptive Routing** – Incremental pooling controls temporal capacity growth, while instance‑wise masking controls instantaneous routing. Together they strategically balance parameter sharing and isolation. Evidence: Figure 4 shows the combination yields the highest accuracy across data proportions, especially in low‑data regimes. The advantage diminishes for disjoint tasks with ample data (Table 5).

## Architecture Onboarding
**Component map:** The system comprises a frozen ViT backbone (*f*<sub>θ</sub>) that extracts the [CLS] token; a growing prompt pool (*P*) with learnable keys; an instance‑wise masking module that uses RMD to decide routing to old or new prompts; a query mechanism that selects top‑*K* prompts from the masked subset via cosine similarity; a classification head (*g*<sub>ψ</sub>) that receives the [CLS] feature augmented with selected prompts; and a task statistics buffer (*H*<sub>*t*</sub>) storing per‑class and global feature statistics. Data flow: input image → *f*<sub>θ</sub> → *z* = [CLS] → RMD computation and masking → available prompt subset → query → selected prompts ⊕ *z* → *g*<sub>ψ</sub> → prediction.

**Critical path:** For each new task *t*:  
1. Expand prompt pool: *P*<sub>*t*</sub> = *P*<sub>*t*−1</sub> ∪ {*N*<sub>new</sub> new prompts} (initialized orthogonal).  
2. For each batch:  
   a. Compute *z* = *f*<sub>θ</sub>(*x*)[CLS].  
   b. Compute RMD<sub>*t*</sub>(*x*) using *H*<sub>*t*−1</sub>.  
   c. Apply mask: if RMD ≤ τ<sub>*t*</sub> (the *q*‑quantile of past RMD), set available pool = *P*<sub>*t*−1</sub><sup>′</sup> (previously updated prompts); else available pool = {new prompts}.  
   d. Query: compute cosine similarity between *z* and keys of prompts in the available pool; select top‑*K*.  
   e. Forward: ŷ = *g*<sub>ψ</sub>( *z* ⊕ selected_prompts ).  
   f. Backward: update only selected prompts and *g*<sub>ψ</sub> with task loss.  
3. After task: update *H*<sub>*t*</sub> using all task‑*t* features (class means, covariances, global stats).  
At inference, no task ID is used; the same masking (with *H*<sub>*T*−1</sub>) and query are applied.

**Design tradeoffs:**  
- Prompt length *L*<sub>p</sub>: longer prompts increase capacity but risk overfitting under data scarcity.  
- Quantile *q* for τ<sub>*t*</sub>: higher *q* (e.g., 0.99) makes masking stricter (fewer samples routed to new prompts), potentially missing novel concepts; lower *q* allows more exploration but increases interference.  
- Orthogonal initialization: reduces initial interference but may not align with semantic structure; depends on backbone quality.  
- Fixed vs. learnable prompt keys: fixed keys (random) would degrade routing but improve stability; the paper uses learnable keys.

**Failure signatures:**  
- High Δusage (training‑inference prompt assignment mismatch) indicates routing instability.  
- Rising forgetting measure (FFM) on long sequences suggests insufficient prompt allocation or mis‑detected OOD samples.  
- RMD separation AUC below 0.8 signals ineffective OOD detection; consider alternative metrics.  
- Prompt pool collapse (many prompts never selected) or dominance (few prompts monopolize usage) points to capacity mismatch.

**First three experiments to reproduce understanding:**  
1. **Ablation on incremental pooling:** Train on ImageNet‑R with 1% data, comparing a fixed global pool size vs. incremental expansion. Measure FAA and prompt selection entropy; expect incremental to show higher entropy and higher FAA.  
2. **OOD mask validation:** On a mixed sequence like M‑EMNIST, compute RMD for each batch and label samples by true task novelty (e.g., recurring vs. new author/object). Verify that samples from recurring distributions are predominantly masked as ID (routed to old prompts).  
3. **Stress test under high similarity:** Construct a 20‑task sequence of extremely similar tasks (e.g., 2 classes per task from CIFAR‑100). Compare SA‑MoE (incremental + adaptive) against a task‑specific prompt baseline. Expect degradation due to under‑allocation; monitor prompt pool growth and usage concentration.

## Open Questions the Paper Calls Out
1. **Extension to regression** – The method relies on class‑wise statistics, which do not directly transfer to regression tasks. Developing a regression adaptation and testing on continual‑learning regression benchmarks is needed.
2. **Alternative OOD detectors** – Only RMD is evaluated; a systematic comparison of various OOD mechanisms (e.g., energy‑based, likelihood‑based) within the framework is required to identify the most robust.
3. **Integration of distribution metrics into query** – The current separation of masking and query may be suboptimal; incorporating distribution distances directly into similarity scoring could improve prompt efficiency.
4. **Robustness of RMD over long sequences** – Feature drift due to prompt learning may stale the static statistics. Analyzing detection accuracy over many tasks and using adaptive updates (e.g., exponential moving averages) would clarify potential degradation.

## Limitations
- **Hyperparameter sensitivity:** Performance hinges on prompt length, number of new prompts per task, OOD quantile threshold, and learning rates; these are not systematically studied.
- **Reliance on frozen pre‑trained representations:** The approach assumes a stable feature space from a frozen ViT; its effectiveness on other architectures (e.g., CNNs, LLMs) or with less powerful backbones is uncertain.
- **Scalability and storage costs:** Maintaining per‑class feature statistics and an ever‑growing prompt pool consumes memory; RMD computation adds computational overhead, especially for long task sequences.

## Confidence
- Incremental global pooling mitigates routing noise: **Medium**
- Instance‑wise prompt masking via RMD separates ID/OOD samples: **Medium**
- Combined adaptive routing improves FAA, especially in low‑data regimes: **Medium**
