# Scaling Tasks, Not Samples: Mastering Humanoid Control through Multi-Task Model-Based Reinforcement Learning

## Quick Facts
- **arXiv ID:** 2603.01452
- **Source URL:** https://arxiv.org/abs/2603.01452
- **Reference count:** 17
- **Primary result:** EZ-M achieves state-of-the-art performance on HumanoidBench with 1M environment steps, solving 7/9 Medium and 10/14 Hard tasks using only a 16M-parameter model, demonstrating positive scaling with task count.

## Executive Summary
This paper introduces EfficientZero-Multitask (EZ-M), a sample-efficient model-based reinforcement learning algorithm for multi-task robotic control. EZ-M leverages a shared world model trained on aggregated data from multiple tasks, exploiting invariant physical dynamics to learn robust, task-agnostic representations. With temporal and path consistency regularizations, it stabilizes long-horizon planning under heterogeneous task data. Evaluated on HumanoidBench with a strict 1M-step budget, EZ-M surpasses strong multi-task baselines and scales positively with the number of tasks, establishing task scaling as a key axis for improvement in model-based RL.

## Method Summary
EZ-M extends EfficientZero-v2 to the multi-task setting. It maintains independent replay buffers per task to avoid data imbalance, and uses a shared dynamics model with a task embedding injected into all major modules (representation, dynamics, reward, value/policy). The model operates in a latent space with a consistency loss (SimSiam) to align predicted and encoded states, and a path consistency loss to align bootstrapped value targets with cumulative reward predictions. Policy improvement uses Gumbel search (a variant of MCTS) to generate high-quality targets for the policy and value heads in a "reanalyze" step. Training optimizes a combination of reward prediction, value prediction, policy distillation, and consistency losses over unrolled model steps.

## Key Results
- Achieves state-of-the-art sample efficiency on HumanoidBench with only 1M environment steps.
- Solves 7/9 Medium-difficulty tasks and 10/14 Hard-difficulty tasks using a 16M-parameter model, outperforming larger baselines (e.g., BRC with 1B parameters).
- Performance scales positively with the number of tasks trained simultaneously (from 1 to 9 tasks).
- Ablations confirm the critical role of independent replay buffers and path consistency regularization.

## Why This Works (Mechanism)

### Mechanism 1: Task Diversity Regularizes Dynamics Learning
**Claim:** Training a shared dynamics model on diverse multi-task data exposes it to a broader state distribution, preventing overfitting and improving sample efficiency.
**Mechanism:** Physical dynamics \(P(s'|s,a)\) are invariant across tasks. A single dynamics model \(G_\phi\) trained on aggregated transitions learns a more general representation of the environment’s causal structure, as formalized by the existence of a unique optimal \(\phi^*\) minimizing prediction error across all tasks (Lemma 5.2).
**Core assumption:** Dynamics learning is the dominant sample-complexity bottleneck (\(d_{\text{dyn}} \gg d_{\text{rew}}\)), and task diversity sufficiently covers the global state space.
**Evidence anchors:** Abstract statement on shared world model; Lemma 5.2; positive scaling with task count (Fig 4).
**Break condition:** If tasks have truly disjoint dynamics (different morphologies), the shared model may suffer interference.

### Mechanism 2: Model-Based RL Avoids Gradient Interference
**Claim:** Unlike model-free multi-task policy learning, MBRL’s dynamics learning objective has no conflicting losses across tasks.
**Mechanism:** In MF-MTL, policy gradients for different tasks can conflict if optimal actions differ in similar states (Proposition 5.1). MBRL’s primary supervised loss \(G_\phi(h_t, u_t) \to h_{t+1}\) is independent of task rewards; the physical outcome of \((s,a)\) is objective, so gradients from all tasks reinforce the same correct dynamics prediction.
**Core assumption:** The latent representation \(h = H(s)\) is sufficiently expressive and shared.
**Evidence anchors:** Proposition 5.1; gradient similarity analysis (Fig 3) showing EZ-M’s dynamics module maintains high similarity for related tasks and low for distant ones, indicating positive transfer without destructive interference.
**Break condition:** If the state representation is not task-agnostic or action spaces mismatch across tasks, interference could reappear.

### Mechanism 3: Consistency Losses Stabilize Long-Horizon Planning
**Claim:** Temporal and path consistency regularizations stabilize imagined rollouts and align reward/value predictions, which is critical when mixing heterogeneous multi-task data.
**Mechanism:** 
- *Temporal Consistency* (SimSiam loss) minimizes distance between predicted latent \(\hat{h}_{t+1}\) and encoded true state \(H(s_{t+1})\), preventing representation drift.
- *Path Consistency* enforces \(\hat{v}(h_t) \approx \hat{r}(h_t,u_t) + \gamma \hat{v}(h_{t+1})\) via cross-entropy, aligning bootstrapped value targets with cumulative discounted rewards and preventing compounding errors in tree search.
**Core assumption:** Stop-gradient on targets prevents training collapse and allows reward/value heads to learn from stable targets.
**Evidence anchors:** Section 4.1–4.2 descriptions; ablation (Fig 5) showing severe performance drop without path consistency.
**Break condition:** If latent space is not structured for meaningful similarity metrics or initial reward/value predictions are too misaligned, the consistency losses may provide insufficient signal.

## Foundational Learning

- **Concept: Reinforcement Learning Fundamentals (MDPs, Policy vs. Value, Model-Based vs. Model-Free)**
  - *Why needed:* The paper contrasts MBRL and MFRL theoretical properties and uses terms like policy \(\pi(a|s,\tau)\), value \(v(s)\), dynamics \(P(s'|s,a)\), and planning via tree search. Understanding these is essential to grasp why MBRL’s structure enables task scaling.
  - *Quick check:* In a model-based algorithm, what is the primary learned component that is shared across tasks, and how does it differ from the shared component in a model-free multi-task method?

- **Concept: Multi-Task Reinforcement Learning Challenges (Gradient Interference, Heterogeneous Reward Scales)**
  - *Why needed:* The core hypothesis is that task scaling benefits MBRL specifically because it avoids MF’s gradient conflict (Prop 5.1). The paper also addresses reward scale variation via categorical prediction without normalization.
  - *Quick check:* Why might training a single policy network on tasks with opposite optimal actions in the same state cause problems for model-free methods but not for a shared dynamics model?

- **Concept: Monte Carlo Tree Search (MCTS) & Gumbel Search (Planning)**
  - *Why needed:* EZ-M uses Gumbel search (not classic MCTS) for policy improvement and target generation ("reanalyze"). This planning step uses the learned world model to produce better-than-behavioral targets (policy \(\pi\), value \(v\)).
  - *Quick check:* How does Gumbel search differ from traditional MCTS in terms of node expansion and what it optimizes for (visit counts vs. Gumbel scores)?

- **Concept: Representation Learning & Latent Dynamics**
  - *Why needed:* The world model operates in a latent space \(h = H(s)\). The consistency losses directly act on these latents. Understanding that the model learns a compressed, task-agnostic dynamics is key.
  - *Quick check:* What is the purpose of the stop-gradient operator in the temporal consistency loss \(\mathcal{L}_{\text{SimSiam}}(h_k, \hat{h}_k)\)?

## Architecture Onboarding

### Component map
Input Encoders -> Shared Representation Backbone (with Task Embedding) -> Dynamics Module & Reward Module & Value-Policy Module. Consistency Losses (SimSiam, Path Consistency) act on latent states and value/reward predictions. Gumbel Search Planner uses value, reward, and policy predictions to generate improved targets. Independent Replay Buffers feed data to the learner.

### Critical path
1. Data collection: Rollout worker samples task uniformly, executes current policy (via Gumbel search), stores transition in task-specific buffer.
2. Training: Learner samples batch from all buffers, encodes states and actions, unrolls model for K steps to get predicted latents, rewards, values, and policy logits.
3. Target computation: Periodically run "full reanalyze": for each replayed state, perform Gumbel search with latest model to obtain policy and value targets; compute n-step TD returns for reward targets.
4. Loss: Combine cross-entropy losses for reward, value, and policy (on search-selected actions), plus SimSiam consistency and path consistency losses. Update networks.
5. Broadcast updated weights to rollout and reanalyze workers.

### Design tradeoffs
- Independent Replay Buffers vs. monolithic: IER prevents dominant tasks from overwhelming sampling but requires more memory and careful scheduling.
- Gumbel Search vs. MCTS: Gumbel reduces node expansions (efficiency) but relies heavily on accurate value estimates; poor value heads degrade search quality.
- Task Embedding Injection: Must be added to all major modules (Dyn, Rew, VP) for proper specialization; over-sharing (no embedding) causes collapse.
- Categorical Value/Reward: Handles heterogeneous scales without normalization but requires choosing support bins and may lose precision for extreme values.

### Failure signatures
- Sudden performance collapse on all tasks: Likely caused by inconsistent gradients from monolithic replay buffer or missing task conditioning. Check IER and embedding injection.
- Stagnant learning on complex contact tasks (e.g., sit-hard): Indicates dynamics model failure; may need better contact modeling or more capacity.
- High variance in normalized returns across seeds: Could be from unstable value learning; verify path consistency loss is active and value ensemble is used.
- Gumbel search selecting invalid actions: Check action masking is correctly applied during policy head inference and search candidate generation.

### First 3 experiments
1. **Ablation of Independent Experience Replay (IER):** Train with a single shared replay buffer vs. independent buffers on HumanoidBench-Medium. Expect severe degradation with shared buffer due to data imbalance (Fig 5).
2. **Scaling Task Cardinality:** Train EZ-M on 1, 4, and 9 tasks simultaneously with fixed total environment steps (1M). Measure average normalized return. Expect positive scaling law (Fig 4).
3. **Gradient Similarity Analysis:** For a pair of related tasks (e.g., walk/run) and a pair of distant tasks (e.g., walk/crawl), compute cosine similarity of gradients for Dynamics, Reward, and Value-Policy modules during training. Expect high similarity for related tasks in Dynamics/Reward but low in Value-Policy? (Actually paper shows all EZ-M modules maintain high similarity for related pair vs. BRC's lower similarity; see Fig 3). This validates positive transfer without interference.

## Open Questions the Paper Calls Out

**Open Question 1:** Can the high computational cost of MCTS planning in EZ-M be substantially reduced via policy distillation without sacrificing performance on HumanoidBench tasks?
- *Basis:* The Discussion identifies "computational overhead of tree search" as a limitation and proposes future work on "distilling the planner into a lightweight policy for real-time inference."
- *Why unresolved:* No experimental evaluation or theoretical analysis of distillation efficacy is provided.
- *What evidence would resolve it:* Compare original EZ-M with a distilled version (e.g., behavior cloning from MCTS rollouts) measuring both inference latency and final normalized returns across tasks.

**Open Question 2:** Does the structural advantage of MBRL for multi-task scaling (positive transfer from shared dynamics) hold when task-specific reward functions involve fundamentally different objectives that may conflict at the level of optimal behaviors?
- *Basis:* Theoretical analysis (Section 5) and gradient similarity experiments (Fig. 3) assume tasks share the same physical embodiment and similar state/action spaces (e.g., locomotion gaits). The "Dynamics Invariance" lemma relies on this shared transition model.
- *Why unresolved:* Empirical validation is limited to HumanoidBench, where tasks are whole-body control variants. It remains unclear if positive scaling persists for distinct physical goals (e.g., locomotion vs. manipulation).
- *What evidence would resolve it:* Introduce a suite of humanoid tasks that pair locomotion with distinct manipulation subtasks (e.g., "walk while carrying"), measure EZ-M's performance scaling compared to MF baselines, and analyze gradient similarity and returns.

**Open Question 3:** Is the key assumption of "Dynamics Dominance" (\(d_{\text{dyn}} \gg d_{\text{rew}}\)) valid across the diverse reward structures in HumanoidBench?
- *Basis:* Theorem 5.3's asymptotic efficiency relies on Assumption 1, which posits that learning physical dynamics is much more sample-intensive than learning a task-specific reward. This is motivated by theoretical work on reward-free exploration but not empirically verified.
- *Why unresolved:* No direct measurement or comparison of sample complexity (\(d_{\text{dyn}}\) vs. \(d_{\text{rew}}\)) for the tasks is provided.
- *What evidence would resolve it:* Pre-train the dynamics model on a subset of tasks and freeze it, then train only reward/value heads on new tasks, measuring sample efficiency gains relative to learning everything from scratch.

**Open Question 4:** What specific aspects of contact-rich dynamics (as in sit-hard) cause the world model's predictions to degrade, and can the temporal/path consistency mechanisms be enhanced?
- *Basis:* Failure Case Analysis states that "the intricate self-contact dynamics in sitting poses are harder for the world model to predict accurately."
- *Why unresolved:* No diagnostic analysis (e.g., prediction error statistics on contact states) or targeted modifications are tested to pinpoint the failure cause.
- *What evidence would resolve it:* Analyze prediction errors on states involving limb self-contact versus free-swinging states, and design/test targeted modifications (e.g., contact-aware state augmentations) in an ablation.

**Open Question 5:** Does the use of independent experience replay buffers (IER) remain beneficial as the number of tasks scales very large (e.g., hundreds)?
- *Basis:* IER is highlighted as the "most critical component" in the ablation for mitigating data imbalance. However, the scaling experiment only goes up to 9 tasks.
- *Why unresolved:* The trade-off space is not analyzed: with many tasks, individual buffers may contain too little data, and memory/scheduling overhead grows linearly. The optimal buffer strategy for massive task sets is unknown.
- *What evidence would resolve it:* Scale task cardinality beyond 9 (e.g., 50, 100 tasks), comparing IER against a monolithic buffer with prioritized replay and a hybrid scheme, measuring performance, buffer hit rates, and sample efficiency per task.

## Limitations
- **Replay sampling schedule unspecified:** The balanced task sampling schedule (uniform vs. proportional vs. round-robin) from independent buffers is not detailed; biased sampling could undermine task scaling and hard-task learning.
- **Gumbel search details missing:** Exact implementation (σ function, sequential halving procedure) is omitted, which is critical for policy improvement and target quality in reanalyze.
- **Value mixing parameters undefined:** Variance thresholds (Var̂, Var̂_min) and α computation formula for mixing TD and search value targets are not fully specified, potentially affecting stability across heterogeneous reward scales.
- **Reanalyze frequency ambiguous:** The term "full reanalyze" is unclear whether it occurs every gradient step or periodically; this impacts sample efficiency claims.

## Next Checks

1. **Sampling schedule ablation:** Train on HumanoidBench-Medium with uniform, proportional (by buffer fill), and round-robin task sampling. Measure average normalized return and per-task solve rates. Expect uniform maximizes scaling; biased sampling degrades hard tasks.
2. **Gumbel search sensitivity:** Replace Gumbel search with random action selection or standard MCTS. Replicate gradient similarity analysis (Fig 3). Expect significant performance drop and altered gradient patterns, confirming search’s role in positive transfer.
3. **Value mixing parameter sweep:** Grid-search variance thresholds (e.g., Var̂_min ∈ [0.01, 0.2]) and mixing weight schedules. Track training stability (loss variance) and final returns. Identify robust hyperparameter range for heterogeneous tasks; expect collapse outside bounds.
