# GARCH-FIS: A Hybrid Forecasting Model with Dynamic Volatility-Driven Parameter Adaptation

## Quick Facts
- **arXiv ID:** 2603.14793
- **Source URL:** https://arxiv.org/abs/2603.14793
- **Reference count:** 37
- **Primary result:** GARCH-FIS significantly outperforms SVR, LSTM, and ARIMA-GARCH benchmarks, achieving MAE/MAPE often below 2% and R² above 0.96 on ten financial assets, with minimal error accumulation over 100-step recursive forecasts.

## Executive Summary
This paper presents GARCH-FIS, a hybrid model that integrates a GARCH(1,1) volatility estimator with a Takagi-Sugeno-Kang Fuzzy Inference System (FIS) to address the limitations of standalone GARCH models (linearity, poor nonlinear handling) and static fuzzy systems (inflexibility to volatility regimes). The core innovation is the dynamic adjustment of FIS membership function widths based on the conditional volatility estimated by GARCH, enabling the model to widen membership functions during high-volatility periods for robustness and narrow them during stable periods for precision. The fuzzy rule base is automatically constructed using the Wang-Mendel method. Empirical tests on ten diverse financial assets demonstrate GARCH-FIS’s consistent superiority over SVR, LSTM, and ARIMA-GARCH benchmarks in terms of MAE, MAPE, and R², along with exceptional stability in long-horizon recursive forecasts.

## Method Summary
GARCH-FIS operates within a recursive rolling window framework. At each forecasting step, a sliding window of historical prices (size 10) provides the input. A GARCH(1,1) model is fitted to the returns from this window to estimate the one-step-ahead conditional volatility. This volatility is transformed into price volatility using the window’s mean price (ˆσ = ¯X × σ/100). The resulting value sets the half‑width of triangular membership functions for all input variables in a zero‑order TSK FIS. The FIS rule base is static, generated offline via the Wang‑Mendel method: for each training window, a fuzzy rule is formed by assigning each price to the triangular membership function with the highest degree, and rules with identical antecedents are merged by averaging their consequents weighted by firing strengths. During prediction, the current window’s prices are fuzzified using the volatility‑scaled membership functions; the weighted average of rule consequents produces the price forecast. After each forecast, the predicted price is appended to the window (oldest dropped), and the process repeats, with the GARCH volatility and FIS parameters updated at every step to reflect the latest market conditions.

## Key Results
- Achieves lowest MAE and MAPE (often below 2%) and high R² (0.965–0.973 for major indices) across ten diverse financial assets.
- Outperforms SVR, LSTM, and ARIMA‑GARCH benchmarks consistently in both single‑step and multi‑step horizons.
- Exhibits minimal error accumulation and superior stability in 100‑step recursive forecasts compared to alternatives.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Dynamically adjusting FIS membership function widths based on GARCH‑estimated price volatility enhances robustness and precision across volatile and stable market regimes.
- **Mechanism:** The GARCH(1,1) model estimates conditional return volatility (σₜ). This is transformed into price volatility (ˆσₜ = ¯Xₜ × σₜ/100) using the rolling window’s mean price (¯Xₜ). This ˆσₜ directly sets the half‑width of all triangular membership functions. During high volatility, wider functions make the FIS less sensitive to outliers (robustness). During low volatility, narrower functions increase resolution for subtle price movements (precision).
- **Core assumption:** The optimal width of a fuzzy membership function for a given market state is a monotonic function of current price volatility.
- **Evidence anchors:**  
  [abstract] "membership functions are automatically widened during high‑volatility market regimes to bolster robustness and narrowed during stable periods to enhance precision."  
  [section 3.3] "The width parameter ˆσₜ is derived from the conditional volatility estimated by the GARCH(1,1) model… enables the model to adapt its inference granularity… widening the membership functions in high‑volatility periods… narrowing them in low‑volatility phases."
- **Break condition:** In markets where volatility and optimal fuzzification are non‑monotonic or where GARCH’s linear variance equation fails to capture true conditional volatility (e.g., during extreme jumps or structural breaks), this linear width scaling could degrade performance.

### Mechanism 2
- **Claim:** The recursive rolling forecasting framework, which incorporates the model’s own one‑step forecasts into the next‑step input window and updates FIS parameters, mitigates error accumulation in long‑horizon forecasts.
- **Mechanism:** After predicting ˆPₜ₊₁, this value is appended to the rolling window (replacing the oldest actual price). The window’s new mean (¯Xₜ₊₁) and a fresh GARCH volatility estimate (σₜ₊₁ → ˆσₜ₊₁) then define the FIS parameters (centers and width) for the next prediction. This creates a closed loop: `forecast → update window & volatility → re‑parameterize FIS → forecast`.
- **Core assumption:** Using the most recent *forecasted* price in the window’s mean calculation provides a more responsive estimate of the current trend than a window of only historical prices, and the updated volatility estimate accurately reflects the next‑step risk environment.
- **Evidence anchors:**  
  [abstract] "recursive rolling multi‑step forecasting… the updated mean of the sliding window data—which now incorporates the most recent predicted price—jointly determines the parameters… for the next prediction."  
  [section 3.1, Figure 1] "The process begins at time t… subsequently, using historical return data up to time t, the GARCH(1,1) model estimates… σₜ₊₁… Both the price forecast ˆPₜ₊₁ and the volatility estimate ˆσₜ₊₁ are then embedded into the updated FIS parameter set Θₜ₊₁… Roll the window: Form the new input vector Xₜ₊₁ by incorporating ˆPₜ₊₁."
- **Break condition:** If the initial forecast error (ˆPₜ₊₁) is large and the market is trending, incorporating this error into the window’s mean could compound bias. The mechanism assumes the GARCH volatility update is fast enough to compensate, which may fail in persistent mis‑specification.

### Mechanism 3
- **Claim:** Using the Wang‑Mendel method to automatically generate a fixed rule base from training data provides a parsimonious, interpretable, and sufficiently expressive nonlinear mapping layer, which is stable during recursive forecasting.
- **Mechanism:** During offline training, for each windowed sample, the antecedent (which fuzzy set the input belongs to) is determined by the window’s volatility‑scaled membership functions. The consequent value is the target price. Duplicate antecedents are merged, and their consequents are averaged (weighted by rule firing strength). This yields a static set of IF‑THEN rules. During forecasting, only the *parameters* (centers/widths) of the antecedent membership functions change; the rule antecedents (the “labels” like “near MA”) and consequents remain fixed.
- **Core assumption:** The nonlinear relationship between (volatility‑scaled) input features and the target price can be adequately captured by a fixed set of fuzzy rules generated from historical data, and that relationship does not fundamentally change over time—only the *granularity* of input interpretation (membership widths) needs adaptation.
- **Evidence anchors:**  
  [abstract] "the model’s fuzzy rule base is automatically constructed from data using the Wang‑Mendel method, promoting interpretability and adaptability."  
  [section 3.2.2] "We employ the WM method… to automatically generate the fuzzy rule base… For each unique antecedent, the consequent value dₖ is a weighted average… Each unique antecedent is paired with its calculated consequent to form a complete fuzzy rule."  
  [section 3.3] "During the multi‑step recursive rolling forecasting process, the rule base of the FIS remains fixed. Adaptation… is achieved solely through dynamic adjustment of the membership‑function parameters."
- **Break condition:** In a market with a structural break that changes the fundamental input‑output mapping (e.g., a new trading mechanism), a fixed rule base would become obsolete. The model assumes volatility adaptation is sufficient, which may not hold if the *shape* of the nonlinear relationship changes, not just its scale.

## Foundational Learning
- **GARCH(1,1) Volatility Modeling**  
  *Why needed here:* To estimate time‑varying, clustered volatility (σₜ) from returns, which is the driver for parameter adaptation. Without understanding how GARCH separates conditional mean and variance, the volatility transformation (ˆσₜ) cannot be justified.  
  *Quick check question:* In the GARCH(1,1) equation σ²ₜ = ω + αε²ₜ₋₁ + βσ²ₜ₋₁, what do the ARCH(α) and GARCH(β) terms represent, and why must α+β<1?
- **Takagi‑Sugeno‑Kang (TSK) Fuzzy Inference System**  
  *Why needed here:* The FIS is the nonlinear mapping engine. Understanding TSK’s structure—antecedents (fuzzy membership functions), rule base, and consequents (linear functions or constants)—is essential to grasp what is being adapted (only antecedents’ parameters).  
  *Quick check question:* In a zero‑order TSK FIS, what is the output if two rules fire with strengths 0.7 and 0.3, and their consequents are constant values 10 and 20, respectively?
- **Recursive Rolling Window Forecasting**  
  *Why needed here:* This is the operational core. It defines the data usage pattern (only past/present), the update cycle, and the source of concept drift. It distinguishes this from a static one‑step model.  
  *Quick check question:* In a 10‑step recursive forecast with a 20‑day rolling window, what is the input window for step 5, and how does it differ from the initial window?

## Architecture Onboarding
- **Component map:**  
  Data Stream → Rolling Window Manager → GARCH(1,1) Module → Volatility Transformer → FIS Parameter Update → Fixed‑Rule FIS Engine → Recursive Controller (orchestrates the loop)
- **Critical path:** The tight coupling between Volatility Transformer, FIS Parameter Update, and Fixed‑Rule FIS Engine. The adaptation loop: GARCH‑estimated price volatility directly determines FIS membership widths, which then affect fuzzy inference.
- **Design tradeoffs:**  
  1. *Fixed rule base vs. dynamic parameters:* trading rule stability/interpretability for potential loss of long‑term structural adaptation.  
  2. *Rolling window size (W=10):* smaller W reacts faster to regime changes but gives noisier estimates; larger W is smoother but slower; W=10 is a heuristic balance.  
  3. *Volatility transformation (ˆσ = ¯X × σ/100):* assumes price moves proportionally to return volatility; may fail for low‑priced assets or extreme moves.
- **Failure signatures:**  
  1. **Divergence in high volatility:** MAE grows super‑linearly with successive steps during a crisis.  
  2. **Oscillatory error:** repeated pattern of over‑ and under‑forecasting around turning points.  
  3. **Parameter instability:** extreme swings in estimated ˆσ causing wild oscillations in membership widths.
- **First 3 experiments:**  
  1. **Single‑Step Sanity Check:** Compare GARCH‑FIS 1‑step MAE/MAPE against a static‑parameter FIS (same rules, fixed width) and standalone GARCH(1,1) mean forecast. Expect: GARCH‑FIS > Static FIS > GARCH mean.  
  2. **Volatility‑Width Correlation Test:** For a volatile asset (e.g., Gold Futures), plot ˆσₜ (from GARCH on true data) vs. actual membership width used in the correct one‑step forecast; expect strong positive correlation. Also plot width vs. subsequent absolute forecast error; expect a U‑shaped relationship.  
  3. **Multi‑Step Error Accumulation Stress Test:** Run a 100‑step recursive forecast on a historically volatile period (e.g., 2020 COVID crash for S&P 500). Plot cumulative MAE for GARCH‑FIS, ARIMA‑GARCH, and LSTM; expect GARCH‑FIS error curve lowest and flattest.

## Open Questions the Paper Calls Out
1. **Multivariate GARCH extension:** How can multivariate GARCH models be incorporated to capture cross‑asset volatility dependencies, and does this improve portfolio‑level forecasting accuracy? (Future research explicitly mentions this.)
2. **Deep learning integration:** What specific deep learning architectures (e.g., CNNs, attention) can be integrated with FIS while preserving volatility‑driven adaptation, and does this yield statistically significant improvements? (Future research mentions exploring deep integration.)
3. **Comparison with other fuzzy‑GARCH hybrids:** How does GARCH‑FIS compare to other fuzzy‑GARCH hybrids (e.g., Hung’s adaptive fuzzy GARCH, Mohammed’s FIS‑neural‑EGARCH) across the same datasets? (Related work cites these but no direct comparison.)
4. **Membership function alternatives:** Would using non‑triangular membership functions (e.g., Gaussian, trapezoidal) or allowing individual widths based on local density improve performance? (Current design uses fixed‑shape triangular functions with uniform width.)
5. **Empirical validation of adaptation mechanism:** Is the volatility‑driven adaptation quantitatively correlated with improved forecasting stability across different market regimes? (Claims are theoretical; no quantitative analysis linking width changes to error reductions across regimes.)

## Limitations
- Volatility measure mismatch: training uses rolling price standard deviation for membership widths, while forecasting uses GARCH‑based price volatility; this may degrade fuzzy set alignment.
- Recursive noise amplification: after the first step, GARCH volatility is estimated from windows containing predicted prices, potentially compounding errors.
- Fixed rule base rigidity: the Wang‑Mendel generated rule base may become obsolete during structural breaks; the model assumes volatility scaling alone suffices for long‑term adaptation.
