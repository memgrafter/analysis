# CLAA: Cross-Layer Attention Aggregation for Accelerating LLM Prefill

## Quick Facts
- **arXiv ID:** 2602.16054
- **Source URL:** https://arxiv.org/abs/2602.16054
- **Reference count:** 23
- **Primary result:** CLAA reduces Time-to-First-Token (TTFT) by up to 39% on Llama-3.1-8B at a 10% token keep rate while achieving 47.13% LongBench accuracy, nearly matching the Oracle upper bound (47.83%) and outperforming baselines like FastKV (46.81%) and GemFilter (37.59%).

## Executive Summary
The prefill stage of long-context LLM inference is a significant computational and memory bottleneck. Existing token-pruning heuristics for acceleration, such as GemFilter and FastKV, rely on unstable single-layer importance estimates that vary dramatically across model depth, leading to unpredictable accuracy drops. To diagnose this, the authors introduce an Answer-Informed Oracle—an offline metric that defines ground-truth token importance by measuring how much attention generated answer tokens pay to each prompt token. The Oracle reveals that single-layer heuristics have low and volatile rank correlation with true importance, particularly at intermediate layers. Motivated by this, they propose Cross-Layer Attention Aggregation (CLAA), which defers compression for the first four layers to protect early semantic representations and then aggregates importance scores across a window of subsequent layers by taking the maximum. This cross-layer stabilization yields robust token rankings. On LongBench with Llama-3.1-8B, CLAA reduces TTFT by up to 39% compared to the full KV cache baseline and matches the Oracle’s accuracy within 0.7%, while showing superior robustness on retrieval-focused benchmarks like Needle-in-a-Haystack and RULER.

## Method Summary
CLAA is a prefill-stage KV cache compression method with two core components. First, it defers any compression for the initial *m* layers (e.g., *m*=4), ensuring early layers process the full, uncompressed context to build stable foundational representations. Second, starting from a designated pruning layer *l*<sub>p</sub>, it computes per-token importance scores for the preceding *n* layers using an observation window of recent token queries (e.g., last 8 tokens) attending to all prompt keys. The final score for each token is the maximum score it received across this window of layers. At *l*<sub>p</sub>, CLAA prunes the hidden state sequence to keep only the top-k tokens by these aggregated scores and compresses the KV cache accordingly for all subsequent layers.

## Key Results
- CLAA reduces TTFT by up to **39%** versus full KV cache at a 10% token keep rate on Llama-3.1-8B.
- Achieves **47.13%** average accuracy on LongBench, closing >99% of the gap to the Oracle upper bound (47.83%) and outperforming FastKV (46.81%) and GemFilter (37.59%).
- Demonstrates superior and more consistent robustness on long-context retrieval tasks (Needle-in-a-Haystack, RULER) compared to single-layer heuristics, which fail sharply at specific depths.

## Why This Works (Mechanism)

### Mechanism 1: Oracle Diagnosis of Single-Layer Instability
The Answer-Informed Oracle provides a ground-truth importance ranking by, after a full generation, measuring attention from answer token queries to all prompt keys (aggregating via max-pooling across heads/layers). This reveals that token importance scores from any single layer (as used by GemFilter, FastKV) have low and highly volatile Spearman correlation with the Oracle across model depth, with severe drops at specific layers. The Oracle’s offline nature means it cannot be used at runtime, but it exposes the fundamental flaw of trusting a single layer’s heuristic.

### Mechanism 2: Cross-Layer Max Aggregation Stabilizes Rankings
CLAA aggregates importance scores across a window of *n* consecutive layers (e.g., *n*=4) by taking the maximum score each token received in any of those layers. This preserves tokens deemed important by at least one layer while filtering out layer-specific noise and transient misrankings. The max operator is a simple but effective fusion that assumes true importance will be signaled by at least one layer’s attention pattern, even if others ignore it.

### Mechanism 3: Deferred Compression Protects Early Representations
By processing the first *m* layers (e.g., *m*=4) with the full, uncompressed KV cache, CLAA prevents premature distortion of the low-level semantic features built in early layers. Ablations show later pruning layers (*l*<sub>p</sub>) consistently improve accuracy, supporting the hypothesis that early pruning causes irrecoverable information loss.

## Architecture Onboarding
**Component map:**  
Input tokens -> Embedding layer -> Early uncompressed block (layers 0 to m-1) -> Scoring module (per layer m to l_p-1) -> Layer-score buffer (stores last n score vectors) -> Pruning layer l_p (aggregates buffer via max, selects top-k tokens, prunes hidden states) -> Compressed block (layers l_p+1 onward, with compressed KV) -> Final norm -> Output logits

**Critical path:**  
1. Full forward pass through first *m* layers with complete KV cache.  
2. For each subsequent layer before *l*<sub>p</sub>: compute importance scores using last *W* token queries, compress KV cache accordingly, full forward pass.  
3. At layer *l*<sub>p</sub>: aggregate buffered scores from last *n* layers via max, prune hidden state sequence to top-k tokens.  
4. Continue forward pass through remaining layers with the pruned sequence and compressed KV.

**Design tradeoffs:**  
- *Defer layers (m):* Larger *m* increases peak memory during early layers but protects foundational representations.  
- *Aggregation window (n):* Larger *n* improves robustness to layer noise but adds memory for storing score buffers and slight compute overhead.  
- *Observation window (W):* Larger *W* provides more queries for scoring but increases attention compute during scoring.  
- *Pruning layer (l_p):* Later *l_p* yields higher accuracy but reduces the number of layers that benefit from compression, limiting TTFT gains.

**Failure signatures:**  
- **OOM in early layers** if *m* is too large for the prompt length and GPU memory budget.  
- **Sharp accuracy drops** on specific tasks (e.g., summarization) where token importance evolves during generation, indicating static pre-pruning may be inherently limited.  
- **Degradation in multi-turn conversations** because importance from early turns may not carry over, and CLAA does not dynamically re-score across turns.  
- **Sensitivity to aggregation window size** if *n* is too small (unstable) or too large (includes noisy layers).

**First 3 experiments:**  
1. **Layer-wise ranking correlation:** Compute Spearman ρ between each heuristic’s token ranking and the Oracle across all 30+ layers to diagnose instability (Figure 2).  
2. **LongBench main evaluation:** Compare accuracy and TTFT across 16 tasks at keep rates 10%, 20%, 40% (Table 1).  
3. **Needle-in-a-Haystack retrieval:** Place “needle” facts at varying depths in long contexts; measure retrieval accuracy to test consistency of pruning (Figure 3).

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions for future work. Its limitations section notes avenues like multi-turn adaptation and cross-model validation, but these are framed as limitations rather than open questions.

## Limitations
- The Answer-Informed Oracle is an offline metric; its assumption that answer-to-prompt attention defines true importance may fail for tasks with transformed information (e.g., abstractive summarization).
- CLAA’s hyperparameters (*m*=4, *n*=4, *W*=8) were tuned for Llama-3.1-8B; optimal settings for other architectures or extreme context lengths are unknown.
- Memory overhead from deferred compression can cause OOM for very long prompts on memory-constrained GPUs.
- Evaluation is limited primarily to Llama-3.1 family; generalization to other model families (e.g., Mistral, Cohere) and architectures is unverified.

## Confidence
- **Single-layer heuristic instability:** High (empirically verified via Oracle correlation across 30+ layers).
- **Cross-layer max aggregation stabilizes rankings:** High (consistently outperforms single-layer baselines on multiple benchmarks).
- **Deferred KV compression improves accuracy:** Medium (ablation shows benefit at *m*=4; larger *m* may be needed for other models).
- **Overall TTFT reduction (up to 39%) with minimal accuracy loss:** High (validated on LongBench with 16 tasks).
- **Robustness on retrieval tasks (Needle-in-a-Haystack, RULER):** Medium-High (strong results but limited task diversity; summarization tasks show flat correlations for all methods).

## Next Checks
1. **Cross-model verification:** Replicate the Oracle rank correlation analysis and CLAA performance on at least two additional model families (e.g., Mistral, Cohere) to test the generality of the layer-instability diagnosis and CLAA’s gains.
2. **Task diversity probe:** Assess CLAA on tasks that challenge the answer-attention proxy (e.g., abstractive summarization, multi-turn conversations), measuring both accuracy and Oracle correlation to understand failure modes.
3. **Hyperparameter sensitivity study:** Systematically vary *m*, *n*, and *l*<sub>p</sub> across context lengths (2K–128K) and GPU memory limits to produce a practical tuning guide for deployment.
