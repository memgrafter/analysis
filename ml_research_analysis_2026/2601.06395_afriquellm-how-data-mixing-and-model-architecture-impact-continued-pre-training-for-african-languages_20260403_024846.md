# AfriqueLLM: How Data Mixing and Model Architecture Impact Continued Pre-training for African Languages

## Quick Facts
- arXiv ID: 2601.06395
- Source URL: https://arxiv.org/abs/2601.06395
- Reference count: 40
- Primary result: AfriqueLLM shows that a carefully curated data mixture in continued pre-training (CPT) significantly improves LLM performance on African languages, with AfriqueQwen-14B achieving state-of-the-art results despite smaller size.

## Executive Summary
AfriqueLLM addresses the poor performance of open-weight LLMs on African languages, especially in reasoning, by applying continued pre-training (CPT) with a meticulously designed data mixture across 20 languages. The study reveals that data composition is the dominant factor for gains, outweighing architectural choices. Key findings include consistent improvements from integrating code, math, and high-quality synthetic data (the CMS recipe), and dramatic relative gains for Qwen 3 models post-CPT. The approach yields large absolute improvements for covered low-resource languages and enhances long-context document translation, outperforming task-specific fine-tuned baselines.

## Method Summary
The authors perform CPT on base models (Gemma-3-PT, Llama-3-PT, Qwen-3-PT) using 25.2 billion tokens. The CMS data mixture comprises monolingual African and high-resource text (22.8B tokens, sourced from FineWeb2, WURA, MADLAD-400 with UniMax sampling), code (967M Python tokens from CornStack-Python), math (1.07B tokens from FineMath-4+), and synthetic translations (324M tokens via GPT-4.1). An optional parallel corpus component was tested but omitted in the final recipe. Training uses standard hyperparameters (learning rate 5e-5, cosine scheduler with min_lr 0.01, global batch 4M tokens, context length 16k, packing) for one epoch on multi-node clusters (up to 64 H100 GPUs), with DeepSpeed ZeRO, Flash-Attention 3, and Liger-Kernel. Evaluation is conducted on AfroBench-Lite and AFRIDOC-MT benchmarks.

## Key Results
- Data composition is the dominant factor for performance gains on African languages.
- The CMS recipe (code, math, synthetic) consistently improves multilingual reasoning and translation across architectures.
- Qwen 3-based models exhibit the largest relative improvements; AfriqueQwen-14B scores 63.79 average, surpassing Gemma 3 27B (60.33).
- CPT yields large absolute gains for covered low-resource languages (e.g., +37.1 points for Hausa with AfriqueQwen-8B).
- The approach enhances long-context document translation, outperforming task-specific fine-tuned baselines.

## Why This Works (Mechanism)
The CMS data mixture enhances model capabilities by integrating diverse skill sets: code and math tokens inject reasoning patterns, synthetic translations provide high-quality parallel data for low-resource languages, and extensive monolingual text maintains language coverage. This combination allows models to leverage cross-lingual transfer from high-resource languages while acquiring specialized skills for African languages. Synthetic data, in particular, offers clean, aligned examples that reduce noise compared to raw parallel corpora, benefiting larger models more due to their higher capacity.

## Foundational Learning
- **Continued Pre-training (CPT)**: Why needed: To adapt foundation models to new languages without catastrophic forgetting. Quick check: Monitor loss on target language validation set; should decrease steadily.
- **Data Mixing for Multilingualism**: Why needed: To balance language representation and skill acquisition. Quick check: Verify token distribution matches recipe; e.g., code/math占比 should be ~8% combined.
- **Synthetic Data Generation**: Why needed: To overcome data scarcity for low-resource languages. Quick check: Evaluate synthetic translations for fluency and accuracy using a small human subset or COMET.
- **UniMax Sampling**: Why needed: To prevent high-resource language dominance in long-tail scenarios. Quick check: Analyze per-language batch frequencies; low-resource languages should appear reasonably often.
- **Cross-lingual Transfer**: Why needed: To exploit similarities between languages for improved performance on unseen tasks. Quick check: Test model on related language pairs; positive transfer indicates effective learning.

## Architecture Onboarding
- **Component Map**: Data Curation (Monolingual, Code, Math, Synthetic) -> Tokenization & Sampling (UniMax) -> CPT Training (Base Model + Hyperparameters) -> Evaluation (AfroBench, AFRIDOC-MT)
- **Critical Path**: 1. Assemble and balance data sources to exact token quotas. 2. Tokenize with base model tokenizer and apply UniMax sampling. 3. Configure training with DeepSpeed, Flash-Attention, Liger-Kernel. 4. Run CPT on multi-GPU cluster for ~6000-7000 steps. 5. Evaluate on standardized benchmarks using SSA-COMET for translation.
- **Design Tradeoffs**: 
  - Synthetic vs. Parallel Data: Synthetic is cleaner but requires GPT-4.1; parallel is cheaper but noisier.
  - HRL Data Inclusion: Capping HRL tokens at 1B mitigates forgetting but may limit retention.
  - Model Scale: Larger models benefit more from synthetic data but require more compute; smaller models may converge faster.
- **Failure Signatures**:
  - Catastrophic forgetting: Sharp drop in high-resource language scores; diagnose by tracking HRL benchmark performance during training.
  - Memory overflow: OOM errors at 16k context; resolve by enabling efficient kernels and adjusting batch size.
  - Evaluation mismatch: Incompatible scores if not using SSA-COMET; ensure correct metric computation.
- **First Experiments**:
  1. Prepare a minimal CMS dataset for one African language (e.g., Swahili) with 100M tokens total.
  2. Run CPT on a small base model (e.g., Gemma-3-4B-PT) for 100 steps to verify pipeline stability.
  3. Evaluate on AfriMGSM and Flores for that language to confirm directional improvement.

## Open Questions the Paper Calls Out
1. Why do Qwen 3 models exhibit significantly larger relative improvements from CPT compared to Gemma 3 and Llama, despite lower initial African language performance? The paper hypothesizes stronger latent fast adaptation capabilities but lacks empirical validation. Evidence needed: Controlled study comparing internal representations and training dynamics.
2. How does the optimal CPT data mixture vary with model architecture and scale, particularly regarding the trade-off between synthetic data and parallel corpora for larger models? Ablations show for Gemma 3 12B, parallel data degrades performance vs. synthetic, but this may not generalize. Evidence needed: Factorial experiment across multiple model families and scales.
3. To what extent can CPT data mixtures enable zero-shot transfer to African languages not included in training? Only Qwen models show modest positive transfer for unseen languages. Evidence needed: Evaluation on broad set of unseen languages, controlling for language family, and testing modifications like adapters.
4. How can we mitigate catastrophic forgetting of high-resource language capabilities during CPT? Qwen models degrade less, but reasons unknown. Evidence needed: Study forgetting dynamics using influence functions, vary HRL data, and explore continual learning techniques.

## Limitations
- Synthetic data sources (Web Organizer, OpenMathReasoning) are unreleased, limiting replication and possibly introducing GPT-4.1 biases.
- The SSA-COMET model and filtering threshold are unavailable, preventing exact reconstruction of parallel data components.
- The training requires significant compute (up to 64 H100 GPUs), which may not be accessible for all researchers.

## Confidence
- Data composition dominance: High
- Architecture superiority (Qwen over larger models): Medium
- Synthetic data benefits: Medium
- CPT gains for covered low-resource languages: High
- Generalization to unseen African languages: Low

## Next Checks
1. Replicate the CMS data mix using open-source synthetic data (e.g., NLLB translations) to assess portability beyond GPT-4.1.

3. Conduct a smaller-scale CPT experiment (e.g., 1B tokens) on limited hardware to compare learning curves and convergence with full-scale results.
