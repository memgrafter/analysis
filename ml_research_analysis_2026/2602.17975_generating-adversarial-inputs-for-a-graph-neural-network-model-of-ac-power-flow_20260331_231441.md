# Generating adversarial inputs for a graph neural network model of AC power flow

## Quick Facts
- **arXiv ID:** 2602.17975
- **Source URL:** https://arxiv.org/abs/2602.17975
- **Reference count:** 30
- **Primary result:** A GNN surrogate for AC power flow is highly vulnerable to small, targeted input perturbations (as low as 0.04 per-unit), causing significant constraint violations (up to 3.4 per-unit error in reactive power).

## Executive Summary
This work investigates adversarial robustness in neural network surrogates for AC power flow by formulating two optimization problems to generate worst-case inputs. The first maximizes the prediction error of the CANOS-PF graph neural network relative to true AC power flow solutions. The second finds minimal perturbations to a valid operating point that cause the network's output to appear feasible while the true solution violates a specified constraint (e.g., voltage lower bound). Experiments on the IEEE 14-bus system reveal that the model can exhibit errors up to 3.4 per-unit for reactive power and 0.08 per-unit for voltage magnitude. Critically, causing a constraint violation can require changing only two input variables by as little as 0.04 per-unit, indicating severe susceptibility to small, targeted disturbances that could compromise grid reliability if such surrogates are deployed operationally.

## Method Summary
The authors use the CANOS-PF graph neural network (7.5 million parameters), trained on the PF∆ Task-1.1 dataset for the IEEE 14-bus grid from PGLib-OPF. They solve two constrained optimization problems in Julia using JuMP, PowerModels (for AC power flow equations), and MathOptAI.jl (to embed the trained PyTorch model via a gray-box interface). Problem 1 (maximum-error) maximizes the absolute difference between the GNN output and AC power flow solution for target variables (voltage magnitudes on PQ buses, reactive power on PV/reference buses). Problem 2 (constrained-error) minimizes the L1 norm of the perturbation from a selected training point such that the GNN output is feasible but the AC power flow output violates a chosen constraint (e.g., voltage magnitude < 0.94 per-unit minus δ=0.04). Inputs are active/reactive power injections and voltage magnitudes/angles, with non-dispatchable loads and the reference bus fixed. The solver IPOPT is configured with specific tolerances and a linear solver (MA57). Key reproduction challenges include the unreleased PF∆ library/dataset, unspecified dependency versions, and ambiguous training data ordering for Problem 2.

## Key Results
- Maximum voltage magnitude error on PQ buses reached **0.08 per-unit**.
- Maximum reactive power error on PV/reference buses reached **3.4 per-unit**.
- Minimal perturbation to cause a voltage constraint violation was **0.04 per-unit**, often involving changes to only **two input variables**.

## Why This Works (Mechanism)
The max-error optimization directly searches the input space for points where the GNN surrogate's approximation deviates most from the true AC power flow solution, exploiting the non-convexity and sensitivity of the power flow equations. The constrained-error formulation identifies minimal perturbations that lead to a "false feasible" GNN output (within limits) while the true AC solution violates a critical constraint. This misalignment occurs because the GNN, trained to minimize overall error, may still make specific errors in localized regions of the input space that violate physical limits. By framing these as constrained optimization problems with embedded AC power flow equations, the method systematically uncovers such failure modes. The gray-box embedding of the GNN allows derivative-based solvers like IPOPT to navigate the combined space, though the non-convex AC power flow constraints contribute to solver sensitivity.

3.  **Adversarial Robustness Analysis:** The practice of finding inputs that cause maximum error or constraint violation in a model. *Why needed: Assesses reliability and safety of ML surrogates in critical infrastructure.* Quick check: Do generated adversarial points produce significantly larger errors than typical test points?
4.  **Constrained Nonlinear Optimization:** Formulating an optimization with objectives, variable bounds, and equality/inequality constraints (here, AC PF and NN output constraints). *Why needed: Precisely defines the search for worst-case or minimal perturbation scenarios.* Quick check: Does the JuMP model correctly represent all physical and model constraints before solving?
5.  **Gray-box Model Embedding:** Treating a trained NN as a black-box function within an optimization framework (e.g., via MathOptAI.jl), potentially without analytical derivatives. *Why needed: Allows using general-purpose solvers for problems involving pre-trained networks.* Quick check: Can the embedded GNN be evaluated consistently within JuMP during optimization?
6.  **Power System Operational Limits:** Engineering constraints like minimum/maximum voltage magnitudes (e.g., 0.94–1.06 per-unit) that define secure grid operation. *Why needed: The adversarial goal is to violate these limits while the surrogate misses the violation.* Quick check: Are all relevant bounds correctly applied to both NN outputs and AC PF variables?

## Architecture Onboarding
**Component Map:**  
PF∆ Task-1.1 Training Data -> CANOS-PF GNN (PyTorch) -> MathOptAI.jl (gray-box export) -> JuMP Optimization Model -> PowerModels (AC PF constraint builder) -> IPOPT Solver -> Adversarial Input Points & Error Metrics

**Critical Path:**  
1. Load or train CANOS-PF on Task-1.1 data.  
2. For each optimization problem, define input variables (injections, voltages) within PGLib bounds.  
3. Embed the GNN as a constraint or objective component via MathOptAI.jl.  
4. Encode AC power flow equations using PowerModels, fixing loads and reference bus.  
5. Specify problem-specific objective (maximize error or minimize L1 norm) and constraint (AC PF feasible, GNN feasible, AC PF violates bound by δ).  
6. Solve with IPOPT and extract results.

**Design Tradeoffs:**  
- *Gray-box vs. white-box:* Gray-box is simpler to implement for arbitrary PyTorch models but may provide less accurate gradients to IPOPT; white-box would require deriving full Jacobians of the GNN w.r.t. inputs.  
- *Solver choice:* IPOPT handles large-scale nonlinear problems well but is sensitive to scaling, initial points, and constraint conditioning; alternative solvers (e.g., KNITRO) might converge more reliably on the non-convex AC PF formulation.  
- *Problem formulation:* Maximizing absolute error requires solving separate problems per bus/variable type, increasing computational load but isolating vulnerabilities.

**Failure Signatures:**  
- IPOPT reports non-convergence (e.g., "Maximum iterations exceeded")—often for buses with near-singular Jacobians or poor initial points.  
- MathOptAI.jl throws evaluation errors—indicates a mismatch between GNN input expectations and JuMP variable ordering or scaling.  
- Model reports infeasible—likely due to overly tight bounds, fixed loads inconsistent with feasible power flow, or incorrect reference bus specification.

**First Three Experiments:**  
1. Train CANOS-PF on a small subset (e.g., first 100 training points) and confirm validation MSE is on the order of 1e-3 and power balance loss ~0.7, matching Table I trends.  
2. Solve Problem 2 (constrained-error) for a single PQ bus (e.g., bus 11) using the first training point; verify the found perturbation has L1 norm ≤0.05 per-unit and modifies ≤2 input variables.  
3. Solve Problem 1 (max-error) for bus 4 (a PQ bus) and check that the voltage magnitude error exceeds 0.05 per-unit, approaching the reported 0.08.

## Limitations
- **Critical dependency on unreleased code/data:** The PF∆ library and Task-1.1 dataset are not known to be public, making direct reproduction impossible without author assistance.
- **Ambiguities in experimental setup:** The exact order of training points for Problem 2 and the precise reference bus (though likely bus 1) are unspecified, affecting result replication.
- **Sensitivity to software environment:** Unstated versions of JuMP, PowerModels, MathOptAI.jl, IPOPT, and PyTorch are likely to cause compatibility or convergence issues, as nonlinear optimization is notoriously sensitive.

## Confidence
- **Vulnerability metrics (max/min errors):** Low. Numerical results depend on unreleased data, training seeds, and optimization details.
- **Reproducibility of optimization framework:** Medium. The formulation is clear, but gray-box embedding and IPOPT sensitivity reduce certainty without exact environment control.
- **Generalizability beyond IEEE 14-bus:** Very low. The study provides no evidence on scalability to larger, more complex grids.
