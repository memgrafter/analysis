# CrossHGL: A Text-Free Foundation Model for Cross-Domain Heterogeneous Graph Learning

## Quick Facts
- **arXiv ID:** 2603.27685  
- **Source URL:** https://arxiv.org/abs/2603.27685  
- **Reference Count:** 40  
- **Primary Result:** CrossHGL achieves average relative improvements of 25.1% in Micro‑F1 for node classification and 7.6% for graph classification over state‑of‑the‑art baselines.

## Executive Summary
CrossHGL is a foundation model for cross‑domain heterogeneous graph learning that operates without textual attributes and under few‑shot supervision. It transforms heterogeneous graphs into homogeneous structures with semantically enriched edge features via SVD‑based feature alignment and automated meta‑pattern mining. A Tri‑Prompt mechanism (feature, edge, structure) enables parameter‑efficient self‑supervised pre‑training across multiple source domains. During adaptation, source prompts are composed with target‑specific open prompts, and a prototypical classifier leverages the few‑shot support set. Evaluated on node and graph classification tasks, CrossHGL consistently outperforms strong baselines, especially in low‑shot regimes, while remaining competitive when node features are degenerate.

## Method Summary
CrossHGL processes heterogeneous graphs by first unifying node feature dimensions through SVD alignment and mining frequent interaction patterns (meta‑patterns) via constrained random walks. Each meta‑pattern induces edges between target nodes whose features aggregate intermediate node attributes, yielding a homogeneous graph preserving relational semantics. A frozen GNN backbone is modulated by three lightweight prompts: feature and edge prompts scale input features element‑wise, while a structure prompt modifies GNN layer transformations. In pre‑training, the Tri‑Prompt generates multiple views (positive, negative, augmented) and uses a contrastive loss (DGI‑style) to learn transferable representations across source domains. For few‑shot target adaptation, the backbone remains frozen; source prompts are combined through attention into composed prompts, and additional open prompts are initialized. A dual‑branch inference (feature‑focused and structure‑focused) produces node embeddings, from which class prototypes are derived from the support set. Classification of query nodes follows via cosine similarity to these prototypes.

## Key Results
- Average relative improvement of **25.1%** in Micro‑F1 for node classification and **7.6%** for graph classification versus state‑of‑the‑art baselines.
- Peak performance of **85.18%** Micro‑F1 on DBLP node classification.
- Maintains competitiveness in feature‑degenerated settings (e.g., Freebase) with limited supervision.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Semantic‑preserving graph transformation mitigates cross‑domain heterogeneity by converting heterogeneous graphs into homogeneous ones while retaining relational semantics in enriched edge features.  
**Mechanism:** SVD aligns node features of different types to a unified dimension. Automated meta‑pattern mining via constrained random walks discovers high‑frequency interaction patterns. For each meta‑pattern, edges between target nodes are created with features aggregating intermediate node features from all matching path instances.  
**Core assumption:** Multi‑relational semantics can be effectively compressed into edge features without loss and a homogeneous GNN can process these enriched edges.  
**Break condition:** If meta‑patterns are not transferable across domains or SVD truncation discards discriminative features, critical information may be lost.

### Mechanism 2
**Claim:** The Tri‑Prompt mechanism decouples adaptation of features, edge semantics, and topology, enabling a frozen GNN backbone to capture transferable knowledge via self‑supervised contrastive learning.  
**Mechanism:** Three lightweight prompts act as modulators: feature and edge prompts filter input features (element‑wise multiplication), while structure prompt intervenes in GNN layers (residual modulation). In pre‑training, DGI contrastive loss is applied with positive (original), negative (shuffled features), and augmented (edge‑dropped) views, using prompts to generate diverse representations.  
**Core assumption:** Prompts can efficiently adapt a fixed backbone to multiple domains and contrastive learning on graphs with these prompts yields representations generalizable across domains.  
**Break condition:** Insufficient prompt expressiveness or misaligned contrastive objectives across domains may hinder transfer.

### Mechanism 3
**Claim:** Prompt composition with prototypical learning enables parameter‑efficient few‑shot adaptation by combining source prompt knowledge with target‑specific open prompts and using non‑parametric class prototypes.  
**Mechanism:** For each prompt type, composed prompts are attention‑weighted sums of source prompts; open prompts are randomly initialized for the target domain. During fine‑tuning, edge features are modulated by composed and open edge prompts; node representations are obtained via two branches (feature‑focused and structure‑focused) that fuse composed and open prompts. Class prototypes from the support set are used for classification via cosine similarity.  
**Core assumption:** Source prompt knowledge is linearly combinable and prototypes from few‑shot samples are representative of their classes.  
**Break condition:** Attention weights may fail to select appropriate source prompts or the few‑shot support set may be unrepresentative, leading to misaligned prompts and unreliable prototypes.

## Architecture Onboarding
**Component map (plain text flow):**  
Raw Heterogeneous Graphs → Semantic‑preserving Transformation Module → Homogeneous Graphs with Enriched Edge Features → Shared GNN Backbone (modulated by Tri‑Prompt Module) → Representations → Multi‑domain Pre‑training Engine → (trained foundation) → Cross‑domain Fine‑tuning Module (compose source prompts + open prompts, dual‑branch, prototypical classifier) → Predictions

**Critical path:**  
1. Transform all source and target heterogeneous graphs into homogeneous graphs with enriched edge features.  
2. Pre‑train: For each source domain, apply source‑specific prompts to the backbone, generate positive/negative/augmented views, compute contrastive loss, and update prompts and backbone.  
3. Fine‑tune: Freeze backbone. For target domain, compute composed prompts from source prompts via attention. Initialize open prompts. Use dual‑branch to embed support set, compute class prototypes, and classify query nodes.

**Design tradeoffs:**  
- Freezing the backbone reduces parameters and overfitting risk but limits adaptation capacity; prompts offer a middle ground.  
- Homogenization retains semantics in edges but may yield high‑dimensional features; SVD alignment reduces dimensionality at the cost of potential information loss.  
- Prompt composition assumes linear combinability of source knowledge; non‑linear combinations could be more expressive but increase complexity.  
- Contrastive pre‑training uses local‑global mutual information; alternative objectives might capture different structural aspects.

**Failure signatures:**  
- Notable performance drop on feature‑degenerate datasets (e.g., Freebase) indicates insufficient handling of sparse attributes.  
- High variance across random seeds in few‑shot splits suggests instability in prompt learning or prototype estimation.  
- Ablating any prompt component (feature, edge, structure) leads to substantial degradation, confirming their complementary roles.  
- If source domains are highly dissimilar, composed prompts may fail to generalize, harming target adaptation.

**First 3 experiments:**  
1. **Overall performance comparison:** Tables II & III show CrossHGL beating homogeneous GNNs, heterogeneous GNNs, contrastive methods, and graph foundation models under leave‑one‑out cross‑domain few‑shot evaluation.  
2. **K‑shot robustness analysis:** Figure 3 evaluates performance from 1‑shot to 10‑shot on ACM; CrossHGL consistently outperforms baselines, especially in low‑shot regimes (K≤3).  
3. **Prompt component ablation:** Table IV demonstrates that removing any of the three prompts degrades performance across all target datasets, confirming their essential and complementary contributions.

## Open Questions the Paper Calls Out
1. **Extension to other graph‑level tasks:** The authors note the need to extend CrossHGL to tasks beyond classification, such as regression, link prediction, and generation.
2. **Improving feature‑degenerate performance:** Freebase results reveal vulnerability when node features are sparse or low‑dimensional; the paper offers no targeted remedies.
3. **Robustness to transformation hyperparameters:** Sensitivity of meta‑pattern mining (e.g., number of patterns K, random walk length) is unexplored; full automation would be valuable.
4. **Handling novel node/edge types:** The leave‑one‑out protocol assumes schema overlap; adaptation to previously unseen types in the target domain remains unexamined.

## Limitations
- Performance drop on feature‑degenerated datasets suggests limited robustness when node attributes are scarce.
- A frozen backbone may hinder adaptation to large domain shifts.
- Evaluation is confined to four datasets; broader validation across more diverse domains is needed.
