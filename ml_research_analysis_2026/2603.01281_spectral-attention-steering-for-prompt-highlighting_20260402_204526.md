# Spectral Attention Steering for Prompt Highlighting

## Quick Facts

- **arXiv ID**: 2603.01281  
- **Source URL**: https://arxiv.org/abs/2603.01281  
- **Reference count**: 40  
- **Primary result**: SEKA and AdaSEKA achieve state-of-the-art training-free prompt steering with negligible latency (~0.03s per sample) and full FlashAttention compatibility, significantly outperforming PASTA and inverting the lost‑in‑the‑middle curve.

## Executive Summary

Prompt highlighting aims to steer a model’s attention toward user‑specified tokens without retraining. Existing methods (e.g., PASTA) edit the full attention matrix post‑computation, making them incompatible with memory‑efficient kernels like FlashAttention. This paper introduces Spectral Editing Key Amplification (SEKA), which edits key embeddings *before* attention using spectral projections learned from contrastive data. The extension AdaSEKA dynamically combines multiple expert projections based on the query vector. Both methods are evaluated on standard benchmarks (CounterFact, BiasBios, Pronouns Changing) and show substantial gains over strong baselines, add only marginal overhead, and remain fully compatible with optimized attention. Notably, SEKA reverses the characteristic U‑shaped performance drop in the “lost‑in‑the‑middle” setting when steering middle passages.

## Method Summary

SEKA learns low‑dimensional relevance subspaces for key embeddings via spectral decomposition of contrastive data. Synthetic prompts with positive (relevant), negative (irrelevant), and neutral contexts for the same answer span are generated. For each layer and attention head, cross‑covariance matrices Ω⁺ and Ω⁻ are computed from the extracted key embeddings of positive and negative contexts. SVD yields top singular vectors (P⁺) and bottom singular vectors (P⁻), capturing a variance threshold γ. Heads are further filtered by the average ℓ₂ distance between positive and negative keys (δ_min). At inference, for highlighted tokens, the key is modified as k′ = k + (g⁺·P⁺k + g⁻·P⁻k)/2. This pre‑attention edit amplifies attention to the highlighted tokens without materializing the full attention matrix.

AdaSEKA extends this by learning multiple expert projection matrices from task‑specific datasets. During generation, the query vector at the last token computes coefficients αₘ that dynamically combine the expert subspaces into a single projection P_dynamic. The key edit becomes k′ = k + g·P_dynamic k. The query‑driven routing allows adaptation to the prompt’s semantic intent without manual hyperparameter tuning per task.

## Key Results

- SEKA and AdaSEKA significantly outperform strong baselines (e.g., PASTA) on standard steering benchmarks (CounterFact, BiasBios, Pronouns Changing) while adding negligible overhead (SEKA ~0.03s vs. PASTA +1.03s per sample).  
- Both methods remain fully compatible with memory‑efficient attention implementations like FlashAttention.  
- SEKA successfully inverts the U‑shaped “lost‑in‑the‑middle” performance drop when steering middle passages.

## Why This Works (Mechanism)

### Mechanism 1: Spectral Learning of Relevance‑Aligned Projections
- **Claim**: A low‑dimensional subspace of key embeddings encodes relevance; spectral decomposition of contrastive key pairs extracts projection matrices that amplify attention to highlighted tokens.  
- **Mechanism**: From synthetic contrastive prompts, extract key embeddings h⁺ (positive) and h⁻ (negative) for the same answer span. Compute per‑head cross‑covariances Ω⁺ = (1/n) h⊤h⁺ and Ω⁻ = (1/n) h⊤h⁻. SVD of each gives singular vectors; the top k⁺ vectors (largest singular values) form P⁺, the bottom k⁻ vectors (smallest) form P⁻, where k⁺/k⁻ capture a cumulative variance γ.  
- **Core assumption**: The distributional shift between positive and negative embeddings is structured and concentrated in a few principal components.  
- **Evidence anchors**: [abstract] “SEKA uses spectral decomposition to steer key embeddings towards latent directions that amplify attention scores for certain tokens.”; [section 3.1] formalizes offline learning, synthetic data construction (Appendix A), and SVD‑based projection selection.  
- **Break condition**: If synthetic contrastive data poorly reflects real relevance shifts, or the shift is not low‑rank, the extracted projections become ineffective.

### Mechanism 2: Pre‑Attention Key Embedding Editing
- **Claim**: Modifying key embeddings as k′ = k + (g⁺·P⁺k + g⁻·P⁻k)/2 before attention computation increases attention scores for highlighted tokens without materializing the full attention matrix.  
- **Mechanism**: For a highlighted token’s key at layer ℓ and head h, an additive term composed of projections onto the relevance subspaces is applied. The resulting attention logit becomes qᵢ⊤k′ⱼ/√dₖ = original + qᵢ⊤(g⁺·P⁺kⱼ + g⁻·P⁻kⱼ)/(2√dₖ). Only keys of highlighted tokens (marked **) are edited.  
- **Core assumption**: The linear transformation in key space reliably increases attention from queries, given the learned projections.  
- **Evidence anchors**: [abstract] “SEKA … directly editing key embeddings before attention computation.”; [section 3.2] derives the logit modification (Eq. 5) and shows equivalence to a low‑rank attention matrix bias.  
- **Break condition**: Over‑amplification (excessive g⁺) can cause attention collapse; inaccurate projections from poor head selection may degrade performance.

### Mechanism 3: Query‑Driven Adaptive Expert Routing (AdaSEKA)
- **Claim**: AdaSEKA dynamically combines multiple expert projection matrices based on the query vector, enabling task‑adaptive steering without manual tuning.  
- **Mechanism**: Experts {U⁺ₘ} are learned from task‑specific data. At inference, the last‑token query q_ℓ,h computes coefficients αₘ ∝ Σ_{k=1}^K (qᵢ⊤u⁺ₘ^{(k)})·σ⁺ₘ^{(k)}, where u⁺ₘ^{(k)} is the k‑th top singular vector and σ⁺ its singular value. The combined projection is P_dynamic = Σₘ αₘ U⁺ₘ,:,:K U⁺ₘ,:,:K⊤. Editing: k′ = k + g·P_dynamic k.  
- **Core assumption**: The last token’s query effectively summarizes the prompt’s semantic intent and its alignment with expert subspaces selects the appropriate projection.  
- **Evidence anchors**: [abstract] “Adaptive SEKA (AdaSEKA), a query‑adaptive variant that uses a training‑free routing mechanism to dynamically combine multiple expert subspaces based on the prompt’s semantic intent.”; [section 3.3] describes the routing formulation.  
- **Break condition**: If all queries strongly favor one expert, the expert bank may be redundant; weak alignment could lead to noisy combinations.

## Architecture Onboarding

### Component map
synthetic_data_generator → projection_learner → head_selector → [store projections] → (router for AdaSEKA) → inference_hook → evaluator

### Critical path
1. Generate synthetic contrastive dataset (or multiple task datasets for AdaSEKA).  
2. Extract key embeddings for answer spans from the model.  
3. Compute cross‑covariance matrices Ω⁺, Ω⁻ per (layer, head).  
4. Perform SVD; choose k⁺, k⁻ meeting variance threshold γ.  
5. Form projection matrices P⁺ = U⁺ₗ,:,:k⁺ U⁺ₗ,:,:k⁺⊤ and P⁻ similarly.  
6. (Optional) Run head selection: compute D_ℓ,h = mean_token ||h⁺ – h⁻||₂; keep if D_ℓ,h ≥ δ_min.  
7. (AdaSEKA only) Store expert SVD components; at inference, compute αₘ per prompt and form P_dynamic.  
8. During generation, register hooks on selected heads; edit keys of highlighted tokens.  
9. Run generation and evaluate.

### Design tradeoffs
- **Pre‑attention vs post‑hoc**: Pre‑attention editing (SEKA) enables FlashAttention compatibility; post‑hoc (PASTA) requires the full attention matrix and is inefficient.  
- **Static vs dynamic projections**: SEKA’s fixed projections are simple and fast; AdaSEKA adds query‑driven routing for task adaptability with minor overhead.  
- **Head selection**: Broad selection (low δ_min) increases coverage but may add noise; strict selection (high δ_min) reduces interference but may omit useful heads.  
- **Projection design**: Using both positive and negative projections allows separate control of amplification and suppression; a single projection could simplify but may be less expressive.

### Failure signatures
- **No metric improvement**: Hyperparameters (γ, δ_min, gains) may be misconfigured; verify head selection hasn’t excluded all heads.  
- **Degraded coherence**: Gains too high (especially g⁺) cause over‑focus on highlighted tokens. Monitor for repetition or ignoring context.  
- **Attention not shifted**: Visualize attention maps; lack of increased weights on highlights indicates incorrect projections or hook misplacement.  
- **Unexpected overhead**: Excessive latency suggests too many steered heads or incompatibility with attention optimizations; check FlashAttention usage.  
- **AdaSEKA routing collapse**: If one expert dominates all queries, the expert bank may be redundant; examine αₘ distributions.

### First 3 experiments
1. **Synthetic sanity check**: Run SEKA on a tiny model (e.g., 1.7B) with minimal synthetic data; verify key embeddings are modified (norm change) and attention logits to highlighted tokens increase.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question**: Why does markdown emphasis boost Qwen3 but not Gemma3?  
- **Basis in paper**: [explicit] Qwen3’s **‑marked baseline strong; Gemma3 not (Sec 5.1).  
- **Why unresolved**: No analysis of causes (e.g., architecture, data).  
- **What evidence would resolve it**: Compare attention to emphasis tokens, train with/without emphasis.

### Open Question 2
- **Question**: Can δ_min be set automatically without validation tuning?  
- **Basis in paper**: [explicit] δ_min tuned via grid search (App F).  
- **Why unresolved**: Manual tuning burdensome for new models.  
- **What evidence would resolve it**: Use heuristic from embedding norm distribution.

### Open Question 3
- **Question**: Is the last token query optimal for AdaSEKA routing?  
- **Basis in paper**: [inferred] Uses last token as global aggregator (Sec 3.3), not compared.  
- **Why unresolved**: Other tokens may capture different intent.  
- **What evidence would resolve it**: Test first token, average, learned weighting.

### Open Question 4
- **Question**: Does SEKA work with FlashAttention at ultra‑long contexts?  
- **Basis in paper**: [inferred] Claims compatibility but no empirical test with FlashAttention.  
- **Why unresolved**: Real deployments need memory‑efficient attention.  
- **What evidence would resolve it**: Benchmark with FlashAttention on >100k‑token contexts.

## Limitations
- Synthetic contrastive data scale and diversity are unspecified; risk of distribution mismatch with real relevance shifts.  
- Head selection threshold δ_min lacks universal guidance and requires manual tuning per model/task.  
- SVD implementation details (numerical stability, component count) are omitted, affecting reproducibility.
