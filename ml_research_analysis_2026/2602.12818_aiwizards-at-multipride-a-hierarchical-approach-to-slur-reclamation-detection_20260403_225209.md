# AIWizards at MULTIPRIDE: A Hierarchical Approach to Slur Reclamation Detection

## Quick Facts
- **arXiv ID:** 2602.12818  
- **Source URL:** https://arxiv.org/abs/2602.12818  
- **Reference count:** 15  
- **Primary result:** The hierarchical dual-encoder achieves statistically comparable performance to a strong BERT baseline on MultiPRIDE (Italian F1: 0.88±0.04 vs 0.90±0.03; Spanish F1: 0.64±0.02 vs 0.67±0.04; p>0.05).  

## Executive Summary
This paper addresses the challenge of distinguishing reclaimed slur usage (in-group, affirming) from offensive use in social media text, where interpretation depends on user identity and context. The authors propose a hierarchical dual-encoder architecture: a user encoder is weakly supervised via LLM-generated proxy labels (LGBTQ+ affiliation likelihood) from tweet and bio text, and its latent representations are fused with a text encoder (fine-tuned for slur reclamation) using a learned gating mechanism. On the MultiPRIDE dataset (Italian, Spanish) the model achieves performance statistically equivalent to a strong BERT-based baseline, validating a modular framework for incorporating user-level sociolinguistic context without sacrificing accuracy.

## Method Summary
The approach uses three training stages. First, a user encoder (a language-specific BERT model) is fine-tuned on a weakly supervised proxy task: predicting LGBTQ+ affiliation likelihood, where labels are generated by prompting an LLM (DeepSeek-V3.3) on the concatenation of tweet and user biography. Second, a separate text encoder (same architecture) is fine-tuned on the primary slur reclamation classification task. Third, a dual-encoder model combines the two: the CLS token representations are fed into a gating network (a two-layer MLP with tanh and sigmoid) that outputs a dynamic weight vector; the fused representation is a weighted sum (g ⊙ h_text + (1-g) ⊙ h_user). A Linear Probing–Fine-Tuning (LPFT) regimen is applied: initially train only the gating network and classifier with frozen encoders, then unfreeze and jointly fine-tune all components at a lower learning rate. The model is trained with cross-entropy loss (class-weighted for Spanish) and evaluated using macro F1.

## Key Results
- Italian development: dual-encoder F1 0.88±0.04 vs baseline 0.90±0.03 (p>0.05).  
- Spanish development: dual-encoder F1 0.64±0.02 vs baseline 0.67±0.04 (p>0.05).  
- Official test set: dual-encoder Italian F1 0.85, Spanish F1 0.70, consistent with development parity.  

## Why This Works (Mechanism)

### Mechanism 1: Weakly supervised user profiling
**Claim:** Weakly supervised user profiling via LLM-generated proxy labels induces representations that capture sociolinguistic context relevant to slur reclamation.  
**Mechanism:** A BERT-like user encoder is fine-tuned to predict a binary "LGBTQ+ affiliation" signal, automatically generated by an LLM from the concatenated tweet and biography. This forces the encoder to internalize latent patterns correlated with perceived in-group alignment.  
**Core assumption:** Textual evidence of LGBTQ+ affiliation (as judged by an LLM) is statistically associated with the capability to use slurs reclamatory.  
**Evidence anchors:** Abstract and Section 2.4 describe the use of fuzzy labels for representation learning; Section 4.2 provides error analysis; proxy task accuracy is moderate (Italian F1 0.75, Spanish 0.79).  
**Break condition:** If proxy task accuracy is near random, the learned representations likely encode noise rather than meaningful signal.

### Mechanism 2: Learned gating fusion
**Claim:** A learned gating mechanism dynamically fuses user-context and text-focused representations, allowing the model to weigh their contribution per-instance.  
**Mechanism:** The final hidden states of the two encoders are concatenated and passed through a two-layer network (tanh + sigmoid) to produce a gating vector g. The fused representation is g ⊙ h_text + (1-g) ⊙ h_user.  
**Core assumption:** The optimal balance between text semantics and user identity context is instance-dependent and can be learned from the primary task loss.  
**Evidence anchors:** Section 3.2.3 describes the gating mechanism; Section 4.2 error analysis suggests the gating can be misled by noisy user signals.  
**Break condition:** If g converges to a constant (all ~0 or all ~1) across the validation set, the mechanism collapses to a single-encoder model.

### Mechanism 3: Staged training (LPFT)
**Claim:** A staged training procedure (Linear Probing then Fine-Tuning) prevents catastrophic interference and preserves the user encoder's sociolinguistic representations while adapting to the primary task.  
**Mechanism:** First, train only fusion and classifier with frozen encoders; second, jointly fine-tune all components with a lower learning rate.  
**Core assumption:** The user encoder's weights encode a useful, broadly applicable "user context" manifold; direct end-to-end training would cause overfitting and overwrite this signal.  
**Evidence anchors:** Section 3.3.1 outlines LPFT; Section 3.2.1 reports that joint fine-tuning after LPFT outperforms freezing the user encoder entirely.  
**Break condition:** If performance drops significantly when moving from Stage 1 to Stage 2, the fine-tuning step is destroying the user representations.

## Foundational Learning
- **Weak Supervision for Representation Learning**  
  Why needed: No ground-truth user identity labels exist; LLM-generated fuzzy labels provide a training signal without manual annotation of protected attributes.  
  Quick check: What are the risks of using an LLM's judgment on identity as a training target, and how does using it *only for representation learning* mitigate them?

- **Gated Fusion of Heterogeneous Encoders**  
  Why needed: The two encoders develop representations in different subspaces; a simple merge may force one signal to dominate. Gating allows a learned, instance-specific blend.  
  Quick check: How would you diagnose whether your gating mechanism is actually learning to dynamically weight the two inputs, versus learning a static weight?

- **Class Imbalance Mitigation**  
  Why needed: The dataset has ~80% non-reclamatory instances; without mitigation, models bias toward the majority class, reducing recall for the minority.  
  Quick check: The authors tried Focal Loss but found Cross Entropy worked better for Spanish. What does this suggest about the nature of the imbalance or the decision boundary in this specific task?

## Architecture Onboarding

**Component map:**  
Input Processor → (Tweet + Bio) → [User Encoder → h_user] & [Text Encoder → h_text] → Gating Network (takes [h_text; h_user] → g) → Fusion (g ⊙ h_text + (1-g) ⊙ h_user) → Classifier → Output

**Critical path:**  
1. Preprocess: Concatenate tweet and user bio with [SEP]; create stratified 70/15/15 splits.  
2. Generate proxy labels using DeepSeek-V3.2 with language-specific prompts (temperature 0).  
3. Train user encoder on proxy task; save checkpoint.  
4. Train text encoder on main task; save checkpoint.  
5. Build dual-encoder: load both checkpoints (initially frozen); add random gating network and classifier.  
6. Stage 1 (LPFT): Train gating+classifier with frozen encoders (LR 2e-5).  
7. Stage 2: Unfreeze all, fine-tune with lower LR (5e-6) until validation macro F1 plateaus.

**Design tradeoffs:**  
- Proxy label noise vs. signal: Imperfect LLM labels may harm user encoder quality.  
- Modularity vs. performance: Dual-encoder adds parameters and complexity but did not statistically beat the baseline, trading potential gains for interpretability.  
- Resource cost: Running two BERT-like models doubles memory/computation.

**Failure signatures:**  
- User encoder proxy accuracy ~50% → noisy or meaningless representations.  
- Gating vector g has near-zero variance → mechanism collapsed to static weighting.  
- Performance drop >0.1 F1 when moving from Stage 1 to Stage 2 → catastrophic forgetting.  
- Model predicts >95% non-reclamatory → class imbalance not addressed.

**First 3 experiments:**  
1. **Ablation: User Encoder Contribution.** Compare `text_encoder_only` vs. `dual_encoder`. If dual-encoder F1 is not significantly better, the user context adds no value.  
2. **Ablation: Gating Mechanism.** Replace learned gating with simple concatenation (`[h_text; h_user]`) or averaging (`(h_text+h_user)/2`). If these perform similarly, the gating overhead may be unnecessary.  
3. **Proxy Label Sensitivity.** Vary the LLM's confidence threshold for generating labels (e.g., only use samples with probability >0.9). Does a cleaner, smaller proxy dataset yield a stronger user encoder and better final performance?

## Open Questions the Paper Calls Out
1. How can the gating mechanism in dual-encoder architectures be enhanced to more dynamically balance textual and user-contextual signals for slur reclamation detection?  
   *Basis:* Future work mentions developing more expressive fusion strategies for heterogeneous latent spaces.  
   *Why unresolved:* Current gating uses a simple learned vector; error analysis suggests user signals may override strong lexical cues.

2. What auxiliary supervision methods for user-oriented representation learning yield latent spaces that best correlate with slur reclamation context?  
   *Basis:* Future work states refining the auxiliary supervision used to induce user-oriented representations.  
   *Why unresolved:* Current LLM-based proxy labels are weakly supervised; proxy task performance is moderate (~0.73–0.78 F1).

3. Can integrating social network structures or multimodal content improve slur reclamation detection beyond textual and biographical data?  
   *Basis:* Future work proposes integration of further contextual encoders, such as those operating on social network structures or multimodal inputs (e.g., images).  
   *Why unresolved:* The model currently uses only text; additional contexts may capture identity or discourse cues absent from text.

4. Do explicit regularization mechanisms (e.g., contrastive objectives, token-level supervision) reduce false positives caused by over-reliance on user contextual signals?  
   *Basis:* Error analysis suggests introducing explicit regularization mechanisms, contrastive objectives, or token-level supervision to better disentangle reclaimed usage from overtly denigratory language.  
   *Why unresolved:* Misclassifications of clearly offensive slurs indicate user signals may dominate; the model lacks constraints to prioritize lexical indicators.

## Limitations
- Proxy labels generated by DeepSeek-V3.2 are unvalidated and potentially biased.  
- Gating mechanism may collapse to static weighting; its dynamic behavior is unverified.  
- Training details (epochs, LR scheduler, gating initialization) are underspecified, hindering faithful reproduction.  
- Evaluation limited to Italian and Spanish; broader language generalizability unknown.  
- Ethical concerns around inferring protected attributes via LLMs remain unresolved.

- **Gated fusion:** Medium

## Next Checks
1. **Gating dynamics diagnosis:** Compute mean ± std of the gating vector `g` on the dev set. Near‑zero variance indicates collapse; substantial variance confirms instance‑specific weighting.  
2. **Ablation of gating:** Replace learned gating with simple concatenation (`[h_text; h_user]`) and averaging (`(h_text+h_user)/2`). A significant F1 drop relative to the proposed model would validate gating’s utility.  
3. **Proxy label quality audit:** Manually annotate a random subset of users (e.g., 200) for LGBTQ+ affiliation. Measure Cohen’s κ against LLM labels and correlate with user‑encoder proxy accuracy to assess label fidelity.
