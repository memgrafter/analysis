# Vibe Coding an LLM-powered Theorem Prover
## Quick Facts
- **arXiv ID:** 2601.04653
- **Source URL:** https://arxiv.org/abs/2601.04653
- **Reference count:** 13
- **Primary result:** Isabellm combines stepwise LLM tactic generation with planning, micro-RAG, rerankers, and counterexample-guided repair to prove lemmas beyond Sledgehammer’s reach; however, its fill-and-repair mechanisms fail even with state-of-the-art LLMs.

## Executive Summary
The paper introduces Isabellm, an LLM-driven theorem prover for Isabelle/HOL that targets goals resistant to conventional automation like Sledgehammer. By interleaving a stepwise prover (LLM-suggested tactics validated by Isabelle via beam search) with a high-level Isar planner augmented by micro-RAG, rerankers, and counterexample-guided repair, the system achieves proof synthesis on challenging lemmas. Empirical results indicate success on some Sledgehammer-unmanageable cases, but the fill-and-repair component proves unreliable even with GPT-5.2 and Gemini-3 Pro, exposing limitations in LLM reasoning for complex algorithmic tasks.

## Method Summary
Isabellm employs a two-layer architecture. First, an Isar planner generates a high-level proof outline. Second, a stepwise prover fills the outline with concrete tactics, guided by an LLM whose outputs are checked by Isabelle. The system uses micro-RAG to retrieve relevant lemmas and definitions from the formal library, and rerankers to prioritize promising tactic sequences. When proofs fail, a counterexample-guided repair mechanism attempts to diagnose and fix errors, but this phase consistently fails across top-tier LLMs. The integration of these components aims to balance exploration (via beam search) with symbolic validation.

## Key Results
- Isabellm automatically proves certain higher-order logic lemmas that Sledgehammer cannot.
- The fill-and-repair mechanism, despite advanced LLMs (GPT-5.2, Gemini-3 Pro), fails reliably, highlighting a bottleneck.
- The work demonstrates practical value of LLM-guided search for formal proof synthesis while exposing fundamental code generation/reasoning limitations.

## Why This Works (Mechanism)
LLMs provide flexible, context-aware tactic generation for Isabelle/HOL, covering gaps in traditional automation. Isabelle’s validation ensures logical soundness. Beam search over tactic sequences explores a broad space without exhaustive enumeration. The Isar planner supplies a high-level structure that reduces the search horizon. Micro-RAG grounds the LLM in the formal library, improving lemma selection. Rerankers refine the candidate set, and counterexample-guided repair offers an automated debugging loop—although this last component currently fails, the overall synergy enables proofs that were previously out of reach.

## Architecture Onboarding
### Component Map
Planner -> Isar Outline -> Stepwise Prover (LLM + Beam Search) -> Isabelle Validation ; Stepwise Prover <-> Micro-RAG ; Stepwise Prover <-> Reranker ; Isabelle Validation -> Repair (on failure) -> Stepwise Prover

### Critical Path
The main data flow: from a goal statement, the Planner produces an Isar skeleton; the Stepwise Prover fills each subgoal with tactics suggested by the LLM, using Micro-RAG to fetch relevant lemmas and Rerankers to guide choices; Isabelle validates each tactic; if a subgoal fails, the Repair module (fill-and-repair) attempts to modify the tactic or context. Successful completion yields a verified proof term.

### Design Tradeoffs
- **Beam search width vs. runtime:** Larger beams increase coverage but slow validation.
- **RAG retrieval scope vs. noise:** Too many retrieved items may confuse the LLM; too few may miss useful lemmas.
- **Repair automation vs. fragility:** The fill-and-repair mechanism aims to reduce manual intervention but currently introduces failure modes that block proof completion.
- **Planner simplicity vs. outline quality:** Overly abstract outlines may be unhelpful; too detailed outlines constrain the LLM’s flexibility.

### Failure Signatures
- **Repair timeouts or syntactic errors:** The fill-and-repair module produces malformed Isabelle code even with advanced LLMs.
- **Persistent tactic rejection:** Isabelle repeatedly rejects LLM-suggested tactics despite beam search and reranking.
- **Outline mismatch:** The Isar plan does not align with the goal structure, causing dead ends.
- **Excessive search:** Beam search exhausts resources without finding a valid proof step.

## Limitations
- The claim of beating Sledgehammer lacks quantitative details (number of lemmas, benchmark composition).
- It is unclear whether fill-and-repair failures stem from inherent LLM reasoning limits or from suboptimal repair algorithm design.
- Generalization beyond the presumably curated lemma set to a broader formal library remains uncertain.
