# Massively Parallel Exact Inference for Hawkes Processes

## Quick Facts
- **arXiv ID:** 2604.01342  
- **Source URL:** https://arxiv.org/abs/2604.01342  
- **Reference count:** 24  
- **Primary result:** The paper achieves exact maximum likelihood estimation for multivariate Hawkes processes with exponential kernels by reformulating the sequential intensity recurrence into a matrix product form, enabling parallel prefix scan with $O(N/P + \log N)$ time, constant memory via batching, and orders-of-magnitude speedups on real-world large datasets.

## Executive Summary
Multivariate Hawkes processes are powerful for modeling cascading events, but their maximum likelihood estimation scales quadratically with the number of events, hindering application to large datasets. This work overcomes the bottleneck by expressing the intensity recurrence as a product of sparse transition matrices, which can be computed in parallel using a prefix scan algorithm (Blelloch scan). The approach yields exact likelihoods and gradients without approximations and introduces a batching scheme that maintains constant memory usage. Empirical results demonstrate near-linear scaling and enable fitting of massive real-world data, including the full MemeTracker corpus and Chicago crime incidents.

## Method Summary
The core idea is to convert the affine recurrence for Hawkes intensities into a linear matrix product via state augmentation. For exponential kernels, the augmented state vector (including a constant 1) evolves via a sparse block-structured transition matrix. The product of these matrices over the event sequence can be computed with an associative operation that costs only $O(M)$ per multiplication (where $M$ is the number of nodes) instead of $O(M^3)$. A parallel prefix scan (Blelloch) then reduces the sequence in $O(N/P + \log N)$ time on $P$ processors. The same formulation enables exact gradients through auxiliary state scans. Batching splits the sequence into chunks; the final state of one batch seeds the next, guaranteeing constant peak memory regardless of $N$.

## Key Results
- **Scalable exact inference:** Achieves orders-of-magnitude speedups over sequential and naive implementations; scales to thousands of nodes and tens of millions of events.
- **Constant memory usage:** Batching scheme maintains a fixed memory footprint, allowing previously intractable datasets (e.g., MemeTracker: $3.2\times10^7$ events; Chicago crime: $8.4\times10^6$ events) to be processed on a single GPU.
- **Empirical scaling:** Demonstrates stable linear scaling in epoch time and memory across a wide range of $N$, with accurate parameter recovery on synthetic benchmarks.

## Why This Works (Mechanism)

### Mechanism 1: Matrix‑product reformulation
- **Claim:** The sequential affine recurrence for the Hawkes intensity can be reformulated as a linear matrix product via state augmentation, enabling parallel prefix scan.
- **Mechanism:** Define augmented state $\tilde{R}^k_i = [R^k_i; 1]$, where $R^k_i$ aggregates past excitations. Construct transition matrices $M^k_i$ with a block‑sparse structure so that $\tilde{R}^k_i = M^k_i \tilde{R}^k_{i-1}$. The entire sequence reduces to prefix products $\prod_{j=1}^i M^k_j$.
- **Core assumption:** The Hawkes process uses exponential kernels, making the recurrence affine in the state vector.
- **Evidence anchors:**  
  - Abstract: “the Hawkes process intensity can be expressed as a product of sparse transition matrices admitting a linear‑time associative multiply, enabling computation via a parallel prefix scan.”  
  - Section 3: “reformulating the affine recurrence (4) to an equivalent matrix product form using state augmentation.”  
  - Corpus: Neighboring papers focus on kernel variants or low‑rank approximations, not this specific matrix‑product form.
- **Break condition:** Fails for non‑exponential kernels where decay is not multiplicatively separable over time intervals.

### Mechanism 2: Sparse matrix multiplication
- **Claim:** The product of sparse transition matrices can be computed with an $O(M)$ associative operation, drastically reducing per‑step cost.
- **Mechanism:** For two matrices $\begin{pmatrix} s_A I_M & v_A \\ 0^\top & 1 \end{pmatrix}$ and $\begin{pmatrix} s_B I_M & v_B \\ 0^\top & 1 \end{pmatrix}$, their product is $\begin{pmatrix} s_A s_B I_M & s_A v_B + v_A \\ 0^\top & 1 \end{pmatrix}$. This combines a scalar multiply and vector add, avoiding $O(M^3)$ dense multiplication.
- **Core assumption:** The state augmentation yields exactly this block structure, which persists across multiplications.
- **Evidence anchors:**  
  - Abstract: “reformulating the sequential intensity recurrence into a matrix product form using sparse transition matrices.”  
  - Section 3: “each product of $(M+1)\times(M+1)$ transition matrices is done in $O(M)$ operations rather than the usual $O(M^3)$.”
- **Break condition:** If the augmented state includes additional terms (e.g., time‑varying base rates without careful handling), the matrix structure may change and lose $O(M)$ efficiency.

### Mechanism 3: Exact batching with constant memory
- **Claim:** Batching the event sequence while propagating the final state between batches yields exact gradients with constant peak memory.
- **Mechanism:** After processing batch $b$, the final state $\tilde{R}^k_{(b-1)N_b}$ is used as the initial state for batch $b$. Because the recurrence is linear, the prefix product over the full sequence equals the product of batch‑wise prefix products applied sequentially. The same holds for gradient state vectors $K^k_i$ and $L^k_i$.
- **Core assumption:** The recurrence is linear (after augmentation) and memoryless; the state fully captures past influence.
- **Evidence anchors:**  
  - Abstract: “naturally yields a batching scheme to maintain constant memory usage, avoiding GPU memory constraints.”  
  - Section 3.2: “for each batch $b$, we can independently compute the per‑batch states … using the final state of the previous batch.”  
  - Corpus: Neighboring papers on scalable Hawkes often use approximations; this exact batching is unique to the linear exponential case with prefix scan.
- **Break condition:** If the model includes non‑Markovian elements (e.g., long‑term memory beyond exponential decay), the state may need to incorporate more history, breaking constant‑memory batching.

## Architecture Onboarding

### Component Map
Sequential recurrence baseline → Matrix product formulation → Prefix scan module → Gradient computation → Batching controller

### Critical Path
- **Forward pass:** Build list of sparse transition matrices → Apply Blelloch prefix scan → Recover states $R^k_i$ → Compute intensities $\lambda_i$ and loss.
- **Backward pass:** Similar scans for auxiliary states $K^k_i$ and $L^k_i$ → Combine with saved forward states → Compute gradients for $\alpha$, $\gamma$, $\mu$.
- **Batching:** Wraps both forward and backward passes; between batches the final augmented state is carried over.

### Design Tradeoffs
- **Blelloch vs Hillis‑Steele:** Blelloch has lower total work ($O(N/P+\log N)$) and is better for $N \gg P$; Hillis‑Steele has more parallelism but $O(N\log N / P)$ work.
- **Manual gradients vs autograd:** Manual avoids interpreter overhead and graph storage, but requires careful derivation; autograd simplifies implementation at possible performance cost.
- **Batch size:** Larger batches reduce $\log N$ overhead and kernel launch overhead but increase memory; smaller batches increase communication and state‑carry cost. Must fit within GPU memory.

### Failure Signatures
- **Memory explosion:** Without batching, storing intermediate prefix matrices uses $O(K M N)$ memory → CUDA OOM. Remedy: enable batching or reduce batch size.
- **Incorrect gradient accumulation:** Forgetting to reset accumulators or mishandling state propagation between batches leads to wrong updates.
- **Numerical overflow/underflow:** Using absolute timestamps instead of inter‑event differences $\Delta t_i$ causes large exponentials. Ensure $\Delta t_i$ are used; also watch for zero $\Delta t_i$ (duplicate timestamps) which are fine.

### First 3 Experiments
1. **Correctness check:** On a tiny synthetic dataset ($N=100$, $M=5$), compare log‑likelihood and gradients from the prefix scan implementation against a sequential $O(N^2)$ reference. Values should match within floating‑point tolerance ($\approx$1e‑6).
2. **Weak scaling:** Fix $M$, $K$, vary $N$ from $2^{10}$ to $2^{26}$ on a single GPU. After core saturation, epoch time should scale linearly with $N$ (slope $\approx 1$ on log‑log). Peak memory must remain constant when batching is active.
3. **Batching sanity:** With large $N$, vary batch size; peak memory should scale inversely with number of batches, and total epoch time should increase only by a modest constant factor. Log‑likelihood must be identical across batch sizes, confirming exactness.

## Limitations
- Exact replication is hindered by missing details on synthetic data generation, MemeTracker subset selection, and Chicago crime preprocessing.
- The method is restricted to exponential kernels and linear state recurrences; it does not extend to non‑exponential or non‑Markovian kernels.
- Implementation pitfalls (e.g., prefix scan padding for non‑power‑of‑two lengths, state carry between batches) can cause correctness or performance issues.
