# Imputation of Unknown Missingness in Sparse Electronic Health Records
## Quick Facts
- **arXiv ID:** 2602.20442
- **Source URL:** https://arxiv.org/abs/2602.20442
- **Reference count:** 18
- **Primary result:** Denoise2Impute-T achieved average denoising AUPRC of 65.53% (improvement ~2% over baselines) and hospital readmission prediction AUPRC of 21.51% (improvement ~0.5% over unprocessed data).

## Executive Summary
Sparse electronic health records (EHRs) often contain binary diagnosis codes where a value of 0 ambiguously represents a true negative or a missing positive diagnosis (unknown missingness). This paper proposes Denoise2Impute, a Set Transformer-based denoising network, and its extension Denoise2Impute-T with adaptive thresholding to address this problem. On a real EHR dataset with 993 ICD codes, Denoise2Impute-T achieved a denoising AUPRC of 65.53%, outperforming baselines by approximately 2%. For hospital readmission prediction, Denoise2Impute-T yielded an AUPRC of 21.51%, a statistically significant improvement of about 0.5% over using unprocessed data and all other imputation methods. The approach also demonstrated consistent gains across multiple downstream ICD prediction tasks.

## Method Summary
The method leverages two overlapping EHR datasets: a noisy source D1 (where 0s may be missing positives) and a complementary source D2. For each patient, the noisy vector from D1 is combined element-wise with the vector from D2 via a logical OR to form the clean target x. Denoise2Impute employs a Set Transformer as the denoiser network gθ, which processes the binary EHR as an unordered set and outputs a probability for each code. Training minimizes a weighted cross‑entropy loss that assigns a multiplier λ = 2.0 to errors where the true value is 1 but the input is 0 (missing positive). Random masking (30%) of the input further regularizes the model. Denoise2Impute‑T extends this by adding a per‑code threshold ϕ, learned after freezing gθ via a continuous sigmoid relaxation. The final imputed value is a data‑dependent convex combination of the original input and the denoiser’s output, controlled by ϕ. The model is trained with AdamW (lr = 3e‑4, weight decay = 1e‑5) for 50 epochs.

## Key Results
- Average denoising AUPRC: 65.53% (Denoise2Impute‑T), ~2% above competing baselines.
- Hospital readmission prediction AUPRC: 21.51% (Denoise2Impute‑T), statistically significant improvement of ~0.5% over unprocessed data and all other imputation methods.
- Consistent performance gains observed across multiple downstream ICD prediction tasks.

## Why This Works (Mechanism)
### Mechanism 1: Set Transformer Captures Pairwise and Higher‑Order Interactions
The Set Transformer architecture processes the patient’s EHR as an unordered set of code embeddings through stacked Set Attention Blocks, enabling permutation‑invariant computation of attention weights across all code pairs and higher‑order combinations. This design allows the model to learn clinically meaningful co‑occurrence patterns that resolve the ambiguity of zeros (e.g., a positive obesity code increases the posterior probability that a missing diabetes code should be imputed to 1). The core assumption is that the joint distribution over diagnosis codes contains stable, learnable structure. Evidence includes the paper’s statement that the model “learns relationships between different dimensions of EHRs… a positive diabetes diagnosis is correlated with high glucose” and the known capacity of Set Transformers to model such interactions. Performance degrades for extremely rare codes with insufficient co‑occurrence examples, as noted in the discussion.

### Mechanism 2: Adaptive Thresholding Stabilizes Denoising
Denoise2Impute‑T introduces a learned per‑code threshold ϕ that determines whether to trust the original input value or replace it with the denoiser’s output. Formally, the output f(˜x) = ωϕ(˜x)˜x + (1‑ωϕ(˜x))gθ(˜x), where ωϕ approximates the optimal weighting derived under an unknown‑missingness noise model. The thresholding network (implemented via a sigmoid relaxation) learns to assign high weight to the identity branch when the input likely matches the clean data distribution, thereby preventing over‑denoising. The mechanism relies on the assumption that the ambiguity between true negatives and missing positives can be partially resolved by estimating the likelihood of the observed vector under the clean distribution. The theoretical derivation in the paper (Theorem 1) supports this form for mean‑squared error; the adaptation to binary cross‑entropy is heuristic. Break conditions include misalignment between the assumed noise model and the true EHR noise, or extreme threshold collapse (all ϕ → 0 or 1).

### Mechanism 3: Weighted Loss Prioritizes Missing‑Positive Corrections
The training loss assigns a multiplier λ = 2.0 to cross‑entropy terms for cases where the noisy input is 0 but the target is 1. This increases the gradient signal for activating zeros, counteracting the class imbalance caused by EHR sparsity where most zeros are true negatives. The core assumption is that failing to impute a true positive (false negative) is more harmful for downstream tasks than incorrectly imputing a 1 (false positive). Evidence is the empirical improvement in AUPRC when using the weighted loss versus an unweighted one. However, an excessively large λ could cause over‑imputation; the paper’s fixed λ = 2.0 was chosen empirically without full sensitivity analysis.

## Foundational Learning
### Concept 1: Binary Denoising as a Discriminative Sub‑Problem
The innovation lies in re‑framing EHR imputation from filling known missing values (NaNs) to distinguishing true negatives from missing positives among all zeros. This requires learning a discriminative function that outputs a probability score per code, later thresholded. **Quick check question:** If you treat all zeros as missing and impute, what fundamental problem arises with sparse EHR data that this approach solves?

### Concept 2: Set Permutation Invariance
ICD codes have no inherent order in the tabular vector; the model must produce identical outputs for any permutation of the input vector. Using a standard Transformer with positional encodings would impose an arbitrary and misleading structure on code relationships. **Quick check question:** Why is a standard Transformer with learned positional embeddings a poor architectural choice for this tabular EHR denoising task?

### Concept 3: Optimal Denoising as Convex Combination
Theorem 1 provides a theoretical justification for the Denoise2Impute‑T architecture. It posits that the optimal estimator is not purely the denoised output nor the identity, but a weighted average where the weight depends on the match between the input vector and the clean data distribution. This directly inspires the adaptive threshold design. **Quick check question:** In Equation (3), what does a low value of ω(˜x) imply about the relationship between the input vector ˜x and the clean data distribution p(x)?

## Architecture Onboarding
- **Component map:** Input (noisy binary EHR vector ˜x, size = 993) → Denoiser (gθ: Set Transformer with 4 SAB layers, D=200, 10 heads) → Probability vector p = gθ(˜x) → Thresholding network (ωϕ: scalar ϕ per code, learned via sigmoid relaxation) → Combiner: f_d(˜x) = ωϕ(˜x)˜x_d + (1‑ωϕ(˜x))p_d → Output (binary vector after thresholding at 0.5).
- **Critical path:**  
  1. Construct training pairs (˜x, x) from overlapping datasets D1 and D2 via element‑wise OR.  
  2. Stage 1: Train gθ with weighted cross‑entropy loss (λ=2.0), random input masking (p=0.3), AdamW (lr=3e‑4, weight decay=1e‑5), batch size 48, 50 epochs.  
  3. Stage 2: Freeze gθ; optimize ϕ using same loss on combined output f(˜x) with sigmoid approximation (α=100). Constrain 0 ≤ ϕ_j ≤ m00_j (mean of p when ˜x_j=0 and x_j=0 on train).  
  4. Inference: For new patient ˜x, compute p = gθ(˜x) and then f(˜x) = I[p_d ≥ ϕ_d].
- **Design tradeoffs:**  
  - Set Transformer vs. MLP: Set Transformer captures higher‑order code interactions but is computationally heavier (O(T²) attention); MLP is faster but may miss dependencies.  
  - Thresholding (T) vs. none: Thresholding stabilizes output but requires two‑stage training and an extra hyperparameter (α).  
  - Loss weighting (λ): Balances emphasis on 0→1 corrections; higher λ combats sparsity‑induced bias but risks over‑imputation.
- **Failure signatures:**  
  1. All ϕ_d collapse to 0 or 1, disabling thresholding.  
  2. Denoiser’s p_d remains low (<0.5) for true positives with supporting codes, indicating failure to learn co‑occurrence patterns.  
  3. Downstream task AUPRC falls below the baseline using unprocessed D1 data, showing net noise introduction.  
- **First 3 experiments:**  
  1. Synthetic noise ablation: Train on a synthetic noisy dataset with random 0‑masking matching D1’s prevalence; compare dimension‑wise AUPRC against prevalence imputation and MLP.  
  2. Denoising accuracy: Compute average (macro) AUPRC between imputed f(˜x) and true x across all 993 codes on real test set; benchmark against prevalence, k‑NN, softImpute, MLP, DAE, CDAE.  
  3. Downstream utility (ICD prediction): For a held‑out target ICD code, set it to 0 in all patient EHRs, run imputation, train LightGBM to predict the true code, and measure AUPRC improvement over using D1 directly.

## Open Questions the Paper Calls Out
1. **Training data requirements:** The method needs paired noiseless (D2) and noisy (D1) EHR datasets. Real‑world data sharing restrictions make this challenging; proposed alternatives (overlapping populations, synthetic masking, active learning) remain unverified for large‑scale deployment.  
2. **Multimodal integration:** How to incorporate other EHR modalities (labs, medications, clinical notes, time‑series) into the denoising process without compromising efficiency? The current model is designed for static binary vectors only.  
3. **Long‑tail performance:** Certain rare ICD codes suffer from extreme sparsity and insufficient training examples, limiting the model’s ability to learn reliable co‑occurrence patterns. No techniques (e.g., hierarchical embeddings, meta‑learning) are explored.  
4. **Theoretical optimality:** Theorem 1 derives the optimal denoiser for mean‑squared error with real‑valued data, but the method uses binary cross‑entropy. The convex‑combination form’s optimality for the binary case is unproven and may be heuristic.  
5. **Joint training:** The two‑stage training (first gθ, then ϕ) may be suboptimal; end‑to‑end joint optimization could improve performance but is not investigated.

## Limitations
- Real EHR datasets D1/D2 are not publicly available; reproduction relies on synthetic data that may not capture true sparsity and co‑occurrence structures.  
- Theoretical derivation assumes MSE loss on real‑valued data, while the training uses binary cross‑entropy, raising concerns about the optimality of the convex‑combination approach.  
- Baseline implementations (e.g., k‑NN, softImpute) lack detailed specifications, risking unfair comparisons and possibly understating their performance.

## Confidence
- Set Transformer architecture learns clinically meaningful pairwise and higher‑order interactions: **Medium** confidence (supported by architectural appropriateness but not direct ablation of attention weights).  
- Adaptive thresholding stabilizes denoising: **Low** confidence (theoretical mismatch with binary loss, risk of threshold collapse, empirical λ choice not fully justified).  
- Weighted cross‑entropy loss prioritizes missing‑positive corrections: **Medium** confidence (empirical AUPRC gains shown, but break condition not systematically tested).

## Next Checks
1. **Noise model stress test:** Re‑derive optimal denoising under binary symmetric noise instead of Gaussian; simulate corrupted binary data to verify whether f(x)=ωx+(1‑ω)gθ(x) remains optimal.  
2. **Threshold collapse monitoring:** During Stage 2 training of ϕ, track the proportion of codes where ϕ_d hits the constraint bounds (0 or m00_j); if >20%, relax constraints or reduce sigmoid slope α.  
3. **Downstream feature audit:** Replicate hospital readmission task using *only* the 993 ICD codes (no other features) and report AUPRC with 95% CIs via bootstrapping; compare strictly against baselines applied to raw D1 data to isolate imputation impact.
