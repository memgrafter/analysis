# HO-SFL: Hybrid-Order Split Federated Learning with Backprop-Free Clients and Dimension-Free Aggregation

## Quick Facts
- arXiv ID: 2603.14773
- Source URL: [https://arxiv.org/abs/2603.14773](https://arxiv.org/abs/2603.14773)
- Reference count: 40
- Primary result: HO-SFL achieves first-order convergence with backprop-free clients, halving memory and cutting communication by 42% via dimension-free scalar aggregation.

## Executive Summary
HO-SFL introduces a hybrid-order optimization framework for split federated learning that eliminates the need for backpropagation on resource-constrained edge clients. By reformulating the split learning objective via Lagrangian duality, the optimization landscape is decoupled into a server-side first-order update and a client-side zeroth-order update. The server computes precise gradients for its submodel and provides activation gradients as feedback to clients. Clients use these gradients to perform zeroth-order updates via random perturbations, sending only scalar projections instead of full model parameters. This design reduces client memory footprint by over 50% (to ~4GB for 1B-parameter LLMs) and communication costs by 42% while maintaining convergence rates comparable to first-order baselines on CIFAR-10 and GLUE benchmarks. Theoretically, HO-SFL converges in O(√(d_c/(PT))) steps, where the dimension dependence is limited to the smaller client submodel rather than the full model.

## Method Summary
HO-SFL operates in a split federated learning setting where each client holds a local submodel (θ_c) and the server holds the remaining submodel (θ_s). Training alternates between: (1) client forward pass to compute activations z = f_c(x; θ_c) sent to server; (2) server completes forward pass, computes loss, and performs backpropagation to update θ_s and obtain the activation gradient λ = ∇_z ℓ; (3) server broadcasts λ to clients; (4) each client performs a zeroth-order update: generate P random perturbations u_p ~ N(0, I) from shared seeds, compute forward passes with perturbed parameters θ_c + µ u_p to get activations ˜z_p, then compute scalar projections v_p = λᵀ (˜z_p - z); (5) clients send scalars v_p to server; (6) server aggregates scalars across participating clients (average) and broadcasts aggregated scalars ¯v_p; (7) clients reconstruct an approximate gradient estimate ˆg_c = (1/(Pµ)) Σ_{p=1}^P ¯v_p u_p and update θ_c using an optimizer (e.g., AdamW). To handle stragglers, clients replay missed rounds using stored seeds and aggregated scalars from server history. The dimension-free aggregation is achieved because only P scalars are transmitted per client per round, independent of client model dimension d_c.

## Key Results
- Theoretically converges in O(√(d_c/(PT))) steps, with dimension dependence limited to client submodel dimension d_c.
- Reduces client memory by >50% (e.g., ~4GB for 1B-parameter LLMs) compared to first-order split FL.
- Cuts communication costs by 42% via scalar-only model aggregation while matching first-order baseline convergence on CIFAR-10 and GLUE.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Lagrangian reformulation decouples the optimization landscape, enabling server-side first-order updates and client-side zeroth-order updates simultaneously.
- **Mechanism:** By treating client-server activation consistency as an equality constraint `z = f_c(x; θ_c)` and introducing a Lagrange multiplier `λ`, the global loss decomposes into a server-side objective `L_s(θ_s) = ℓ(f_s(z; θ_s), y)` (minimized via backpropagation) and a client-side objective `L_c(θ_c) = λᵀ f_c(x; θ_c)` (minimized via zeroth-order optimization). The multiplier `λ` is set to the activation gradient `∇_z ℓ` computed by the server.
- **Core assumption:** The stationarity condition `∇_z L_λ = 0` correctly identifies `λ` as the activation gradient, and the auxiliary variable `z` can be anchored to the current client forward pass `f_c(x; θ_c^t)`.
- **Evidence anchors:**
  - [Section 3.2] Explicit derivation of the Lagrangian and the two sub-problems.
  - [Section 3.3] Algorithm 1 implements this decoupling: server updates `θ_s` via BP and computes `λ_m^t`; clients update `θ_c` via ZO using `λ_m^t`.
  - [Corpus] Neighbor papers (e.g., "Lean Clients...") explore similar hybrid-order ideas but do not use Lagrangian decoupling, suggesting this is a novel architectural insight.
- **Break condition:** If the activation gradient `λ` is a poor proxy for the true gradient `∇_{θ_c} ℓ` (e.g., due to highly non-linear `f_c` or poor conditioning), client-side ZO updates may diverge from the global optimum.

### Mechanism 2
- **Claim:** Shared randomness enables dimension-free model aggregation, drastically reducing communication costs.
- **Mechanism:** Clients generate perturbation vectors `u_p` from shared random seeds `s_p`. Instead of transmitting full model parameters `θ_c ∈ ℝ^d_c`, they send only scalar projection values `v_{m,p} = λ_mᵀ (f_c(x; θ_c + µ u_p) - f_c(x; θ_c))`. The server aggregates these scalars `¯v_p = (1/K) Σ_{m∈S_t} v_{m,p}` and broadcasts them back. Clients reconstruct an approximate gradient `ˆg_c = (1/(Pµ)) Σ_{p=1}^P ¯v_p u_p`.
- **Core assumption:** The gradient estimator `(1/(Pµ)) Σ v_p u_p` is unbiased for the directional derivative along the subspace spanned by the random perturbations, and the aggregation of scalars is sufficient for reconstruction.
- **Evidence anchors:**
  - [Abstract] "enables dimension-free model aggregation, drastically lowering communication costs."
  - [Section 3.3] Detailed procedure for scalar projection, aggregation, and gradient reconstruction (Algorithms 1–2).
  - [Corpus] "Achieving Dimension-Free Communication..." (neighbor) uses ZO for FL aggregation, but in a different (non-split) context.
- **Break condition:** If the client model dimension `d_c` is very small, the overhead of multiple scalar transmissions may outweigh the benefit. The estimator's variance also increases if `P` is too low relative to `d_c`.

### Mechanism 3
- **Claim:** Hybrid-order design mitigates the dimension-dependent convergence slowdown of pure zeroth-order optimization, achieving a convergence rate comparable to first-order methods.
- **Mechanism:** The server performs precise first-order updates on its submodel `θ_s`. The client-side ZO gradient `ˆg_c` is guided by the server's activation gradient `λ`, which provides a descent direction aligned with the global loss curvature. The theoretical convergence rate is `O(√(d_c/(P T)))` instead of the standard `O(√(d/(P T)))` for pure ZO on the full model.
- **Core assumption:** The client-side dimension `d_c` is significantly smaller than the full model dimension `d` (i.e., `d_c << d`), and the server's gradient feedback `λ` accurately reflects the local geometry needed for client updates.
- **Evidence anchors:**
  - [Abstract] "Theoretically converges in O(√(d_c/PT)) steps, with dimension dependence limited to the smaller client submodel."
  - [Section 4] The proof (Theorem 4.4 & Corollary 4.5) shows the rate depends on `d_c`, not `d`.
  - [Corpus] Neighbors like "On the Convergence of Zeroth-Order Federated Tuning..." analyze ZO-FL convergence but not hybrid-order.
- **Break condition:** If `d_c` is not sufficiently small, the `√d_c` factor dominates. If `λ` is a poor surrogate for the true client gradient (e.g., due to severe client drift in highly non-IID data), the alignment assumption breaks.

## Architecture Onboarding

**Component map:**  
Client holds θ_c, performs forward pass z = f_c(x; θ_c), executes ZO update: generates P perturbations u_p from shared seeds, computes v_p = λᵀ (f_c(x; θ_c + µ u_p) - z), sends scalars {v_p}. Must synchronize state if straggling (Algorithm 3).  
Server holds θ_s, receives (z, y), completes forward pass f_s(z; θ_s), computes loss. Performs BP: updates θ_s using g_s = ∇_{θ_s} ℓ, computes λ = ∇_z ℓ. Aggregates client scalars ¯v_p = (1/K) Σ v_{m,p}, broadcasts them.  
Communication: Uplink: clients send (z, y) [full z] and later {v_p} [scalars]. Downlink: server sends λ [full vector] and later {¯v_p} [scalars + seeds].

**Critical path:**  
1. Client forward: z_m^t → server.  
2. Server BP & feedback: compute g_s, λ_m^t; update θ_s^{t+1}; send λ_m^t.  
3. Client ZO projections: using λ_m^t and shared seeds, compute v_{m,p}^t; send scalars.  
4. Server scalar aggregation: compute ¯v_p^t; broadcast.  
5. Client gradient reconstruction & update: ˆg_c = (1/(Pµ)) Σ ¯v_p^t u_p; update θ_c^{t+1}.

**Design tradeoffs:**  
- **Memory vs. Convergence:** Eliminating client-side BP reduces memory ~50% but introduces ZO estimation bias/variance. Mitigated by small d_c and sufficient P.  
- **Communication vs. Accuracy:** Dimension-free aggregation (scalars only) reduces comms ~42% vs. full model transmission. However, λ (activation gradient) is still sent high-dimensionally; could be compressed or approximated.  
- **Latency vs. Parallelism:** Decoupling allows client ZO computations to overlap with server BP and network transfers (latency hiding), but requires careful synchronization for stragglers (Algorithm 3 adds replay overhead).

**Failure signatures:**  
- **Divergence / Stagnation:** If P too small or µ poorly set (too large → high bias; too small → numerical noise), client updates become ineffective.  
- **Client Drift (Non-IID):** Although dimension-free aggregation reduces drift by frequent updates, highly skewed data can still cause λ to misrepresent global gradient. Monitor gap ∥∇_{θ_c} L(θ^t) - λ^t ∥.  
- **State Desync:** Straggling clients replaying old rounds with server's historical (s_τ, ¯v_τ) must reconstruct correctly. Bug in replay would corrupt θ_c.

**First 3 experiments:**  
1. **Convergence comparison vs. first-order SFL:** Run on CIFAR-10 IID/Non-IID and GLUE. Metric: validation accuracy vs. processed samples. Expect HO-SFL to match SFL convergence speed while reducing memory.  
2. **Memory footprint profiling:** For LLaMA-3.2-1B + LoRA on SST-2, measure peak client GPU memory. Expect ~4 GB (inference-level) vs. ~8+ GB for SFL and ~20 GB for full local training.  
3. **Communication cost breakdown:** Log total bytes sent/received per client and server over training. Expect HO-SFL to show largest reduction in "Model (Up/Down)" components due to avoiding full θ_c transmission, confirming dimension-free aggregation.

## Open Questions the Paper Calls Out
- **Open Question 1:** Does HO-SFL work for full training from scratch? *Basis:* Only fine-tuning tested (Sec 5); theory assumes small steps near pre-trained optimum. *Why unresolved:* Long training may amplify ZO noise; hybrid decoupling untested for full training. *What evidence:* Full pre-training experiments on vision/LLM benchmarks comparing convergence and memory vs. first-order methods.
- **Open Question 2:** How to choose client split dimension d_c optimally? *Basis:* Rate ∝ √d_c but split is fixed heuristically. *Why unresolved:* No theoretical guidance for d_c given hardware constraints; poor choice wastes memory or slows convergence. *What evidence:* Adaptive split algorithm that adjusts d_c during training based on memory/feedback, validated on heterogeneous devices.
- **Open Question 3:** Is HO-SFL robust to stragglers and heterogeneous client speeds? *Basis:* Latency analysis assumes ideal overlap; no empirical straggler study. *Why unresolved:* Synchronous ZO steps may cause server idle times if clients lag, eroding communication savings. *What evidence:* Large-scale testbed experiments with diverse devices and network conditions, measuring convergence under controlled stragglers.
- **Open Question 4:** Can the d_c dependence in the convergence rate be eliminated by more advanced ZO estimators? *Basis:* Corollary 4.5 still contains √d_c; Proposition 4.3 bias scales with d_c³. *Why unresolved:* Current Gaussian finite-difference estimator is inherently dimension-sensitive; unknown if dimension-free rate possible. *What evidence:* Develop a dimension-independent ZO estimator, integrate into HO-SFL, and prove/empirically show improved rate.

## Limitations
- No systematic guidance for selecting zeroth-order hyperparameters (perturbation count P and smoothing µ) across different client model dimensions and datasets; trade-offs are evaluated only via limited ablations.
- The claimed 42% communication reduction depends on amortizing seed transmission over many rounds; per-round overhead details (e.g., seed size, compression) are not fully specified, making reproducibility of the exact cost challenging.
- Theoretical convergence guarantees depend on an unknown constant Γ (e.g., bound on activation gradient norms, Jacobian and Hessian operators), which is not practically estimable, hindering verification of the O(√(d_c/(PT))) rate in real deployments.
