# Drift-Aware Continual Tokenization for Generative Recommendation

## Quick Facts
- **arXiv ID:** 2603.29705
- **Source:** https://arxiv.org/abs/2603.29705
- **Reference count:** 40
- **Primary result:** DACT reduces token change rates to ~13% (vs. ~99% for full fine-tuning) while consistently improving Hit Rate@5/10 and NDCG@5/10 across three datasets and two generative recommenders.

## Executive Summary
Generative recommendation models (GRMs) rely on item tokenizers that map items to token sequences, but collaborative drift—changes in item popularity and interaction patterns—causes identifier instability and misalignment when tokenizers are naively fine‑tuned. DACT introduces a two‑stage continual learning framework: (1) fine‑tuning augmented by a Collaborative Drift Identification Module (CDIM) that predicts item‑level drift confidence, enabling differentiated updates—drifting items adapt freely while stationary items are anchored; (2) hierarchical code reassignment with a relaxed‑to‑strict strategy that updates tokens conditionally across layers. Evaluated on three Amazon datasets with TIGER and LCRec, DACT achieves superior recommendation accuracy, maintains stronger alignment between quantized embeddings and collaborative filtering (CF) signals, and drastically reduces token changes compared to full retraining or incremental fine‑tuning.

## Method Summary
DACT addresses continual tokenization under collaborative drift via two stages. First, during tokenizer fine‑tuning on new period data, CDIM ingests previous item latents, current detached latents, and updated CF embeddings to output a drift confidence score per item. Items are split into a drifting set (top‑K confidence) and a stationary set (the rest). A differentiated loss is applied: drifting items minimize reconstruction and CF alignment losses to freely adapt, while stationary items add an anchoring penalty to preserve previous latents, thus protecting token‑embedding alignment. Second, after fine‑tuning, hierarchical token reassignment is performed: the first layer token is always recomputed; deeper layers update only if the first layer token changed, exploiting the residual structure of RQ‑VAE to minimize unnecessary disruption. The updated token sequences then fine‑tune the GRM. This design balances plasticity and stability, requiring minimal extra parameters and training overhead compared to joint retraining.

## Key Results
- **Consistent performance gains:** DACT surpasses baselines (frozen, full fine‑tuning, Reformer) in Hit Rate@5/10 and NDCG@5/10 on all three datasets across four continual periods.
- **High token stability:** Reduces average code change rate to ~13% (vs. ~99% for full fine‑tuning), preserving identifier consistency.
- **Stronger CF alignment:** Maintains higher cosine similarity between quantized item embeddings and current CF embeddings over time.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** CDIM identifies item‑level collaborative drift by comparing current and previous latent representations against updated CF signals.
- **Mechanism:** CDIM constructs query vectors from previous latents \( r^{p-1}_i \), current detached \( \tilde{r}^p_i \), and CF embeddings \( h^p_i \). These query a learnable pattern memory (key‑value slots) via attention, yielding a drift confidence \( d_i \). High confidence indicates significant drift, low confidence stability.
- **Core assumption:** Collaborative drift manifests as a measurable divergence between old and new item representations relative to current CF signals; patterns are reusable across items and time.
- **Evidence anchors:**
  - Abstract describes CDIM outputting item‑level drift confidence for differentiated optimization.
  - Section 3.1.1 details query construction, pattern matching, and confidence prediction equations.
  - Corpus shows prior methods ignore drift in existing items; CDIM is novel for drift detection.
- **Break condition:** Abrupt shifts (e.g., viral trends) may render historical patterns obsolete, causing misclassification.

### Mechanism 2
- **Claim:** Differentiated update strategy balances plasticity and stability via tailored loss functions.
- **Mechanism:** Items split into drifting set \( I_d \) (top‑K confidence) and stationary set \( I_s \). For \( I_d \), minimize reconstruction and CF losses \( \mathcal{L}_{\text{drift}} \); for \( I_s \), add anchoring loss \( \mathcal{L}_{\text{anchor}} \) that penalizes deviation from previous latents, yielding \( \mathcal{L}_{\text{stable}} \). This preserves token‑embedding alignment for stable items while allowing adaptation for drifting ones.
- **Core assumption:** Token‑embedding alignment is highly sensitive to changes in stationary items; anchoring prevents catastrophic forgetting while still permitting weak CF alignment.
- **Evidence anchors:**
  - Abstract explicitly mentions "drifting items adapt freely while stationary items are anchored."
  - Section 3.1.2 defines \( \mathcal{L}_{\text{drift}} \), \( \mathcal{L}_{\text{stable}} \), and the anchoring term.
  - Corpus indicates naive fine‑tuning changes >90% of tokens; DACT’s selective updates reduce changes (Table 4).
- **Break condition:** Inaccurate split (due to CDIM errors) may cause over‑anchoring or over‑adaptation, degrading performance.

### Mechanism 3
- **Claim:** Hierarchical code reassignment with relaxed‑to‑strict strategy limits unnecessary token changes, preserving identifier stability.
- **Mechanism:** After fine‑tuning, first‑layer tokens are always reassigned (active adaptation). For layers \( l \geq 2 \), reassignment occurs only if the first‑layer token changed (\( c^p_{i,1} \neq c^{p-1}_{i,1} \)). This exploits RQ‑VAE’s residual structure: first layer captures dominant semantics; deeper layers encode finer details conditionally.
- **Core assumption:** GRM’s token‑embedding alignment is most sensitive to first‑layer tokens; deeper layers can be stabilized conditionally without losing essential collaborative information.
- **Evidence anchors:**
  - Abstract mentions hierarchical code reassignment updating tokens conditionally.
  - Section 3.2 formalizes the conditional update rule (Eq. 24).
  - Corpus notes that prior work only handles new items; DACT’s hierarchical strategy specifically targets minimal disruption for existing items.
- **Break condition:** If drift is reflected solely in deeper residual variations without first‑layer change, tokens may remain misaligned.

## Architecture Onboarding
**Component map:**  
Previous Latents (r^{p-1}) & Current Detached Latents (˜r^p) & CF Embeddings (h^p) -> CDIM -> Drift Confidence (d_i) -> Item Split (I_d, I_s) -> Differentiated Losses (L_drift, L_stable) -> Tokenizer Update -> Hierarchical Reassignment (layer‑1 always; deeper layers conditional) -> Updated Tokens -> GRM Fine‑tuning

**Critical path** (for each continual period \( p \)):
1. Load previous tokenizer and fine‑tuned CF model from \( D_{p-1} \).
2. Compute previous latents \( r^{p-1}_i \) for all items using old tokenizer.
3. During tokenizer fine‑tuning on \( D_p \), obtain current detached latents \( \tilde{r}^p_i \).
4. CDIM predicts drift confidence \( d_i \) from \( (r^{p-1}_i, \tilde{r}^p_i, h^p_i) \).
5. Split items: \( I_d = \text{topK}(d_i) \), \( I_s = \text{rest} \).
6. Compute total loss \( \mathcal{L}_{\text{Tokenizer}} = \mathcal{L}_{\text{drift}} + \theta \mathcal{L}_{\text{stable}} + \beta \mathcal{L}_{\text{global}} + \zeta \mathcal{L}_{\text{reg}} \) and update tokenizer.
7. Perform hierarchical reassignment: always update layer‑1 tokens; for \( l \geq 2 \), update only if layer‑1 token changed.
8. Fine‑tune GRM on \( D_p \) using new token sequences.

**Design tradeoffs:**
- Differentiated vs uniform update: Selective updates reduce disruption but rely on accurate drift detection; uniform adaptation (full fine‑tuning) adapts all items but destroys alignment.
- Hierarchical reassignment: Active first layer ensures dominant semantics adapt; conditional deeper layers minimize changes but may miss subtle drifts.
- CDIM pattern memory: Learnable slots capture reusable patterns but add parameters; fixed patterns may not generalize across domains.

**Failure signatures:**
- High code change rates (~>50%) despite DACT, indicating ineffective differentiation or reassignment.
- CDIM confidence distribution near 0.5 for most items, suggesting training collapse or pattern memory failure.
- Performance drop on old items while new items improve, indicating over‑adaptation at stability’s expense.
- GRM’s HR/NDCG declines over periods, signaling token‑embedding misalignment.

**First 3 experiments:**
1. **Overall performance** – Compare DACT against baselines on TIGER/LCRec across four periods, showing gains in Hit Rate@5/10 and NDCG@5/10.
2. **Ablation study** – Remove CDIM, differentiated strategy, global constraint, or reassignment to measure each component’s contribution.
3. **Code change rate analysis** – Quantify layer‑wise token change rates; DACT reduces changes dramatically (e.g., ~13% vs ~99% for fine‑tuning).

## Open Questions the Paper Calls Out
1. **Decoupled collaborative signals:** Can DACT be extended to handle separate tokenization for different CF aspects (e.g., co‑occurrence vs. popularity)?
2. **Dynamic hierarchical reassignment:** Should reassignment rules vary per codebook layer or item scale in large corpora?
3. **Scalability of pattern memory:** How does fixed‑size CDIM memory (S=32) affect performance with millions of items?
4. **Non‑collaborative drift:** Can DACT incorporate temporal or contextual features to handle drift beyond CF signal changes (e.g., seasons, events)?
5. **Cross‑domain generalization:** Does DACT work equally well in domains other than Amazon retail (e.g., movies, news)?

## Limitations
- CF/GRM hyperparameters (architecture, training schedule, fine‑tuning steps) are unspecified, hindering exact replication.
- CDIM’s pattern memory may fail during abrupt collaborative shifts, leading to misclassified drift confidences.
- Hierarchical reassignment assumes first‑layer changes indicate overall drift; drift confined to deeper residuals may be missed.
