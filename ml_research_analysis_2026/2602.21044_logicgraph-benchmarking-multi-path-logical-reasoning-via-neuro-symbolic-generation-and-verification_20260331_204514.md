# LogicGraph : Benchmarking Multi-Path Logical Reasoning via Neuro-Symbolic Generation and Verification

## Quick Facts
- **arXiv ID:** 2602.21044
- **Source URL:** https://arxiv.org/abs/2602.21044
- **Reference count:** 28
- **Primary result:** LogicGraph reveals a "divergence gap": state-of-the-art LLMs achieve high convergent success (e.g., Gemini-3-Pro 96.11% Success Rate) but low divergent metrics (Diversity 59.60%, Versatility 79.44%), with performance degrading sharply as reasoning depth increases.

## Executive Summary
LogicGraph introduces the first benchmark for multi-path logical reasoning, addressing the limitation of current LLM evaluations that focus only on single-proof convergent tasks. The benchmark is constructed via a neuro-symbolic pipeline: backward Logic DAG generation produces high-depth (average 6.01 steps) problems with 2–19 exhaustive minimal proofs and logical distractions; semantic instantiation transforms these into natural language; and a Prover9-based filter ensures logical soundness. Evaluation uses a reference-free system that translates LLM outputs to formal expressions and verifies them stepwise and globally, providing both convergent (Success Rate, Precision, Shortest Path Finding Rate) and divergent (Diversity, Versatility, Originality) metrics. Experiments on around 15 SOTA LLMs uncover a significant divergence gap: models like Gemini-3-Pro achieve 96.11% Success Rate but only 59.60% Diversity and 79.44% Versatility, with all metrics declining as depth grows. Error analysis shows primary failures in logical execution (invalid deduction, insufficient premise), indicating that models commit to single routes and fabricate steps rather than systematically exploring alternatives.

## Method Summary
The LogicGraph benchmark is built through three stages. **Stage 1: Logic DAG Generation** – Starting from a sampled conclusion, the system recursively applies seven fundamental argument forms (e.g., Modus Ponens, Hypothetical Syllogism) to add premises in a backward direction. To induce multiple proof paths, an intermediate conclusion is selected and re-expanded, creating alternative routes. Fresh atomic identifiers prevent unintended premise sharing, guaranteeing that each minimal support set (a set of premises that entails the conclusion with no proper subset doing so) is distinct. This yields problems with 2–19 minimal proofs and an average depth of 6.01 steps. **Stage 2: Semantic Instantiation** – An LLM receives the DAG and a domain theme (with 32 entity types), then produces Prover9 expressions for all logical nodes and renders a coherent natural language narrative containing premises and a goal. **Stage 3: Solver-based Filtering** – Prover9 validates each instance by checking local entailment for every edge, global derivability of the goal, and satisfiability of the full premise set. The final dataset contains 900 instances stratified by the number of ground-truth paths (Small: 2–4, Medium: 5–7, Large: ≥8).

For evaluation, a reference-free pipeline processes an LLM’s response: (1) an LLM extractor structures the output into solution steps and resolves references; (2) a translator LLM converts each natural language step into a Prover9 formula; (3) Prover9 verifies local validity (premises ⊢ step) and global validity (used premises ⊢ goal) for each step; (4) an LLM taxonomist classifies failures into Semantic Comprehension (misinterpretation, omission, hallucination) and Logical Execution (invalid deduction, rule misapplication, insufficient premise); (5) metrics are computed: convergent (Success Rate, Precision, Shortest Path Finding Rate) and divergent (Diversity, Versatility, Originality).

## Key Results
- LogicGraph provides the first multi-path logical reasoning benchmark, with problems containing 2–19 minimal proof paths and an average reasoning depth of 6.01.
- SOTA LLMs exhibit a divergence gap: Gemini-3-Pro achieves 96.11% Success Rate but only 59.60% Diversity and 79.44% Versatility.
- The dominant failure mode is logical execution errors (invalid deduction, insufficient premise), indicating that models tend to commit early to a single path and fabricate steps rather than explore alternatives.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Backward Logic DAG generation yields logically sound, high-depth, multi-path problems with exhaustive ground-truth proofs.
**Mechanism:** The generator starts from a target conclusion and recursively applies seven fundamental argument forms (e.g., Modus Ponens, Hypothetical Syllogism) to add premises in a backward direction. To create multiple paths, after an initial chain is built, an intermediate conclusion is selected and re-expanded, producing alternative routes. New premises are assigned fresh atomic identifiers unless they correspond to an existing node, ensuring that each minimal support set is unique and that no unintended premise sharing occurs. This symbolic construction guarantees logical validity at the DAG level.
**Core assumption:** The logical structure of the DAG remains unchanged during the natural language instantiation stage; surface realization does not alter the underlying inference relationships.
**Evidence:** The paper reports an average depth of 6.01 steps and problems with 2–19 minimal proofs (abstract). Section 4.1 details the bottom-up construction and the use of atomic identifiers. The approach is aligned with prior neuro-symbolic benchmarks that rely on symbolic backbones for sound generation.
**Break condition:** If the LLM-based semantic instantiation introduces ambiguities that allow multiple formal interpretations (e.g., a natural language rule that could map to different logical forms), the ground-truth proof set derived from the original DAG may become incomplete or incorrect, as the Prover9 filter only checks the intended formalization.

### Mechanism 2
**Claim:** The reference-free evaluator (LLM translator + Prover9 verifier) provides reliable, fine-grained assessment of open-ended LLM-generated proofs, avoiding brittleness of string matching and LLM-as-a-Judge hallucination.
**Mechanism:** The evaluation pipeline first uses an LLM to parse the model's natural language proof into structured steps and translate each into a Prover9 expression, resolving anaphoric references. Prover9 then checks two conditions: local validity (the cited premises entail the step) and global validity (the union of all used premises entails the final conclusion). Failed steps are further classified via an LLM into two axes: Semantic Comprehension (A1–A3) and Logical Execution (B1–B3).
**Core assumption:** LLMs can accurately serve as formalization parsers when provided with precise Prover9 mappings from the generation phase, and Prover9’s binary correctness judgments constitute a sound ground truth for logical validity.
**Evidence:** The evaluator achieves high agreement with human experts: 98.80% Step Accuracy and 95.22% Proof Accuracy (abstract). Section 5.1 describes the pipeline; Appendices C.4–C.5 provide qualitative evidence that LLM-as-a-Judge fails on compressed valid inferences (false negatives) and accepts invalid gap-filled inferences (false positives), while Prover9 does not.
**Break condition:** Errors in the LLM translator—such as mis-parsing a natural language step into an incorrect Prover9 formula—will corrupt the verification results, leading to false error classifications. The pipeline’s reliability is therefore contingent on the translator’s accuracy, which is not explicitly quantified.

### Mechanism 3
**Claim:** Dual-axis evaluation (Convergent vs. Divergent metrics) uncovers a "divergence gap" in LLMs: high success in finding *a* correct path but low coverage of the full solution space, which degrades sharply with reasoning depth.
**Mechanism:** Convergent metrics measure the ability to produce at least one valid proof (Success Rate), the proportion of valid among generated proofs (Precision), and the ability to find the shortest path. Divergent metrics assess breadth: Diversity measures coverage of distinct ground-truth minimal support sets; Versatility measures coverage of distinct reasoning families (groups of paths sharing many inference nodes); Originality measures how frequently a path is used across models. By tracking these against average reasoning depth, one isolates exploration ability from raw correctness.
**Core assumption:** Real-world reasoning often admits multiple valid derivations, and an agent’s flexibility is indicated by its ability to enumerate them. A model that consistently finds only one path, even if correct, exhibits a reasoning limitation distinct from simple logical incompetence.
**Evidence:** Experiments on ~15 SOTA LLMs show near-perfect convergent scores but much lower divergent scores (e.g., Gemini-3-Pro: SR 96.11%, Diversity 59.60%, Versatility 79.44%) (Section 6.2). Figure 4 demonstrates that Diversity and Versatility drop earlier and faster than Success Rate as average path length increases, confirming that exploration falters with depth.
**Break condition:** If the definition of a "distinct path" (minimal support set) does not align with human intuition of strategic diversity, metrics like Versatility may misrepresent genuine reasoning flexibility. The grouping into families based on shared inference nodes is a proxy and may not capture all meaningful strategic differences.

## Foundational Learning
### Minimal Support Set / Minimal Proof
- **Why needed here:** The core task is enumerating all `MinSup(S, G)` sets. Understanding this formal definition (a set of premises that entails the conclusion and no proper subset does) is critical to grasp what constitutes a "valid path" and why inference node reuse complicates enumeration.
- **Quick check:** Given premises {A, A→B, B→C, C→D} and goal D, list all minimal support sets. Is {A, A→B, B→C, C→D} minimal? Is {A, C→D}?

### Neuro-Symbolic Pipeline
- **Why needed here:** The entire benchmark construction and evaluation rely on integrating neural (LLM for instantiation/translation) and symbolic (DAG construction, Prover9 verification) components. Understanding the division of labor and failure modes of each is key.
- **Quick check:** In the generation pipeline, what role does the LLM play vs. the symbolic graph builder? In the evaluation pipeline, what role does the LLM play vs. Prover9? What specific error does each component guard against?

### Convergent vs. Divergent Thinking (Guilford, 1967)
- **Why needed here:** The paper's evaluation framework is explicitly inspired by this psychological taxonomy. Convergent metrics test "correctness," divergent metrics test "exploration breadth." Misinterpreting this leads to misunderstanding the paper's central thesis about a "divergence gap."
- **Quick check:** If a model outputs 5 proof paths for a problem with 10 ground-truth paths, but all 5 are from the same reasoning family (sharing most intermediate nodes), what would its Diversity and Versatility scores likely be? What does this tell us about its reasoning?

## Architecture Onboarding
### Component Map
Logic DAG Generator -> Semantic Instantiator (LLM) -> Natural Language Renderer (LLM) -> Solver-based Filter (Prover9) -> Test-time Prompt -> Evaluation Pipeline (Extractor & Translator (LLM) -> Verifier (Prover9) -> Error Taxonomist (LLM) -> Metrics Calculator)

### Critical Path
The evaluation's integrity depends on the Translation (Extractor & Translator) → Verification (Prover9) loop. A failure in translation corrupts all downstream metrics. The most computationally expensive stage is Prover9 verification for multiple long proofs.

### Design Tradeoffs
- **Synthetic soundness vs. real-world noise:** The backward construction guarantees logical validity but yields clean, distraction-free structures. Real-world text includes ambiguity, irrelevant details, and implicit knowledge; the "logical distractions" in LogicGraph are structurally defined, not semantically noisy.
- **Exhaustive ground truth vs. scalability:** Generating all minimal supports is computationally hard. The proposed method (unique atomic IDs, systematic expansion) aims for exhaustiveness but may still miss paths in highly branched DAGs if not all expansion orders are tried. The paper claims exhaustiveness via construction rather than enumeration.
- **Reference-free verification vs. translation dependency:** Avoiding LLM-as-a-Judge reduces hallucination bias but makes the system dependent on the LLM translator's fidelity; a poor translator becomes a bottleneck.

### Failure Signatures
- **High SR, low Diversity/Versatility:** Model finds one or few high-probability routes without exploring alternatives (early commitment). Example: o3 exhibits this pattern.
- **Low Precision:** Model generates many solutions, but most are invalid due to "result-oriented fabrication" (hallucinating steps to force the conclusion). Example: Qwen3-235B-A22B; error distribution shows high Invalid Deduction/Insufficient Premise.
- **Depth-induced degradation:** All metrics (especially divergent ones) drop sharply as reasoning depth increases beyond 5–6 steps, indicating error accumulation and narrowing search.
- **Family conflation:** Model may output multiple solutions that are not truly distinct (they belong to same "family" sharing many inference nodes), inflating solution count but not Versatility.

### First 3 Experiments
1. **Meta-Evaluation:** Compare the neuro-symbolic evaluator’s step and proof accuracy against human judgments and LLM-as-a-Judge baselines to validate the evaluation apparatus.
2. **Main Model Comparison:** Run the full evaluation pipeline on a suite of ~15 SOTA LLMs across the 900-instance benchmark, stratified by difficulty (Small/Medium/Large), to establish the divergence gap observation.
3. **Depth/Error Analysis:** (a) Plot all metrics against average reasoning step length to show degradation patterns; (b) Use the error taxonomy to aggregate failure reasons across models, identifying logical execution (especially invalid deduction, insufficient premise) as the primary failure mode.

## Open Questions the Paper Calls Out
- **Can LLMs be trained or prompted to systematically explore all minimal proof paths in multi-path logical reasoning problems, rather than fixating on a single high-probability route?**  
  *Basis:* Experimental results show low Diversity (max 59.60%) and Versatility (max 79.44%) despite near-perfect Success Rate.  
  *Why unresolved:* Current models lack an explicit training signal that encourages exhaustive enumeration of distinct proof paths.  
  *Resolving evidence:* Introduce fine-tuning or reinforcement learning objectives that reward coverage of ground-truth minimal supports; evaluate whether such methods increase Diversity/Versatility without sacrificing Precision on LogicGraph and transfer to new multi-path tasks.

- **How does reasoning depth affect the quality and diversity of generated proof paths, and what mechanisms cause the observed sharp degradation in performance beyond certain depths?**  
  *Basis:* Figure 4 and Section 6.3 show that both convergent and divergent metrics decline steadily as depth increases, with Diversity/Versatility dropping earlier and faster than Success Rate.  
  *Why unresolved:* The paper documents the correlation but does not diagnose whether degradation stems from error accumulation, limited working memory, or a collapse in exploration strategy under increased complexity.  
  *Resolving evidence:* Controlled experiments on LogicGraph instances with matched solution-space size but varying depth, analyzing error propagation patterns (e.g., at which step invalid deductions appear); probing model internals to see if attention or state representations degrade with depth.

- **Can reference-free evaluation of multi-path reasoning be made more computationally efficient without sacrificing the high agreement with human judgments achieved by neuro-symbolic verification?**  
  *Basis:* The paper notes that the neuro-symbolic verification process is computationally intensive compared to simple multiple-choice evaluations.  
  *Why unresolved:* LLM-as-a-Judge is cheaper but unreliable; no intermediate approach balancing cost and formal rigor for open-ended proof generation is explored.  
  *Resolving evidence:* Develop and benchmark approximate verification methods (e.g., lightweight SMT solvers, learned verifiers trained on Prover9 judgments) on LogicGraph, measuring both speed and agreement with human annotations.

- **To what extent do the synthetic, distraction-free premises of LogicGraph reflect the challenges of real-world multi-path reasoning, and how transferable are model capabilities to domains with ambiguous or incomplete information?**  
  *Basis:* The paper acknowledges that the dataset remains synthetically constructed, while real-world reasoning involves ambiguity, fuzzy logic, and probabilistic inference.  
  *Why unresolved:* The clean logical separation may inflate model performance; it is unknown whether models that excel on LogicGraph can handle noisy, under-specified, or contradictory information typical of real applications.  
  *Resolving evidence:* Extend LogicGraph with controlled noise (irrelevant facts, paraphrased rules with ambiguous quantifiers, probabilistic weakenings) and measure model robustness; test whether performance on LogicGraph correlates with outcomes on natural multi-path reasoning benchmarks or real-world case studies.

## Limitations
- **DAG enumeration algorithm not fully specified:** The paper describes constructing multi-path DAGs but does not detail the algorithm for extracting all minimal support sets, raising questions about exhaustiveness.
- **LLM translator fidelity unquantified:** The evaluation pipeline relies on an LLM to translate natural language steps to Prover9; the error rate of this component is not reported, potentially affecting metric reliability.
- **Family grouping criterion underspecified:** The definition of "reasoning family" (shared inference nodes) and the threshold for distinctness are not fully described, which may render Versatility scores brittle.
