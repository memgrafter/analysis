# Synthetic Data Powers Product Retrieval for Long-tail Knowledge-Intensive Queries in E-commerce Search

## Quick Facts
- **arXiv ID**: 2602.23620
- **Source URL**: https://arxiv.org/abs/2602.23620
- **Reference Count**: 16
- **Primary Result**: A data synthesis framework using multi-reward RL query rewriting and dual-relevance filtering significantly improves retrieval for long-tail knowledge-intensive e-commerce queries, with online A/B test gains up to +8.62pt in Query Goodrate and +31.59% in GSB.

## Executive Summary
The paper tackles poor retrieval performance on long-tail, knowledge-intensive e-commerce queries, which suffer from scarce training data and complex user intent. The proposed solution is a data synthesis framework that first trains a multi-candidate query rewriting model via multi-reward reinforcement learning (optimizing for semantic relevance, product-domain alignment, and diversity). This model generates expanded queries, which are processed through an offline retrieval pipeline using a dense bi-encoder. A dual-relevance filtering stage—combining a business-specific classifier and a conservative general-purpose LLM—then filters high-quality query-product pairs. These synthetic pairs implicitly distill the offline system’s capabilities into the online retrieval model during training. Offline evaluations show substantial gains across all query types, and online A/B testing confirms meaningful improvements in human-assessed relevance.

## Method Summary
The framework operates in two phases. In the offline synthesis phase, a query rewriting model is optimized using REINFORCE++ with three continuous rewards: Query Semantic Relevance (QSR), Product-side Distribution Alignment (PDA), and Diversity. Rewrites are used to retrieve candidate products via a dense retriever. Each candidate pair is scored by a business-specific relevance model; pairs passing a high threshold are re-evaluated by a general-purpose LLM to filter out false positives from lexical overfitting. The surviving high-confidence pairs form synthetic training data. In the online phase, the standard retrieval model is fine-tuned on this synthetic data, implicitly learning to associate expanded query representations with relevant products without deploying the costly rewriting or dual-filter components at inference time.

## Key Results
- Offline metrics improve across all four query categories (e.g., Negative queries see +12.95pt Item Goodrate).
- Online Side-By-Side human evaluation shows Query Goodrate increases up to +8.62pt for alternative-intent queries.
- GSB (a commercial metric) improves by up to +31.59% in A/B testing.

## Why This Works (Mechanism)
**Mechanism 1: Multi-Reward RL for Faithful & Aligned Rewrites**  
Optimizing the rewriting model with combined rewards for semantic equivalence (QSR), product-terminology alignment (PDA), and candidate diversity produces rewrites that preserve intent while conforming to the product corpus’s lexical distribution. This enhances downstream retrieval recall without semantic drift. The heuristic reward weights (α=1.0, β=0.5, γ=0.1) balance these objectives; if PDA overpowers QSR, rewrites may become superficial keyword-stuffing.

**Mechanism 2: Dual-Relevance Filtering to Mitigate Distribution Shift**  
The business-specific relevance model tends to overvalue lexical overlap, while a general-purpose LLM lacks domain nuance. By applying the LLM as a conservative second filter only to high-scoring business pairs, the pipeline removes both lexical false positives and semantically mismatched pairs, yielding high-precision synthetic data. If the LLM filter is too aggressive, valid domain-specific pairs may be discarded, reducing synthetic data yield.

**Mechanism 3: Implicit Distillation via High-Quality Synthetic Pairs**  
Training the online dense retriever on the filtered synthetic pairs allows it to internalize the judgment of the stronger offline components (rewriter and dual classifiers). The synthetic distribution, though shifted from raw logs, aligns better with the ideal long-tail query-intent space, improving recall without altering the online architecture.

## Architecture Onboarding
**Component Map**:  
Original Query → Multi-Reward RL Rewriter (offline) → Multiple Candidate Queries → Offline Dense Retriever → Candidate Products → Business Relevance Classifier → High-Score Pairs → General LLM Filter → Filtered (Query, Product) Pairs → Synthetic Training Data → Online Retriever Fine-Tuning

**Critical Path**: Long-tail query → rewrite expansion → initial retrieval → dual-filter → synthetic pair generation → retrieval model training.

**Design Tradeoffs**:  
- Using large LLMs (42B MoE, 30B) for rewriting/filtering maximizes quality but increases cost and latency.  
- Conservative LLM filtering improves precision but may lower recall of valid domain-specific pairs.  
- Heuristic reward weighting simplifies RL training but may not generalize across query types.

**Failure Signatures**:  
- Rewrites become keyword-stuffed (PDA reward dominance).  
- Synthetic data yield drops sharply (LLM filter too aggressive).  
- Online performance degrades on certain query types (distribution shift unbridgeable by fine-tuning).

**First Three Experiments**:  
1. Ablate each reward component (QSR, PDA, Diversity) to measure individual impact on rewrite quality and final retrieval metrics.  
2. Vary the general LLM filter threshold to chart the precision-recall trade-off for synthetic pairs and correlate with downstream retrieval performance.  
3. Human-annotate a sample of filtered pairs to validate precision; compare annotation results with automatic scores to calibrate filter aggressiveness.

## Open Questions the Paper Calls Out
### Open Question 1
How can the framework incorporate multimodal information (e.g., images, visual style) to handle queries requiring visual reasoning, such as "same-style clothing"? The current pipeline processes only text, ignoring visual cues critical for some knowledge-intensive intents. Extending retrieval and relevance modules with multimodal encoders and evaluating on visually oriented queries would resolve this.

### Open Question 2
What specific modifications to the multi-reward RL scheme (QSR, PDA, Diversity) are needed to optimally improve performance on alternative-intent queries (e.g., seeking affordable substitutes)? The current rewards focus on semantic consistency and product-language alignment but may not capture comparative reasoning. Integrating a contrastive reward on affordable alternatives and conducting ablations on the Alternative query subset would provide evidence.

### Open Question 3
Does fine-tuning the general-purpose query-rewrite and query-product relevance classifiers on domain-specific annotated data reduce false positives and improve the precision of the synthesized query-product pairs? The paper uses off-the-shelf LLMs with conservative prompts; supervised fine-tuning on targeted annotations could yield a better precision-recall balance. Collecting an annotated validation set and comparing fine-tuned versus prompted filtering would resolve this.

### Open Question 4
What are the computational and monetary costs of scaling this data synthesis framework to cover millions of long-tail queries, and can efficiency be improved via model distillation or caching without significant quality loss? The pipeline uses multiple large-model calls per query; scaling implies orders of magnitude more queries. Measuring per-query costs at scale and experimenting with distilled models or caching would provide evidence.

## Limitations
- Medium confidence in multi-reward RL effectiveness due to missing ablation studies and heuristic weighting.
- Medium confidence in dual-filter synthetic data quality due to lack of independent human validation; conservative LLM may discard valid domain-specific pairs.
- Low confidence in generalizability beyond e-commerce, as evaluation is confined to a single domain.

## Confidence
- **Overall improvement**: High (confirmed by online A/B test).
- **Multi-reward RL effectiveness**: Medium (no ablation; heuristic weights unverified).
- **Dual-filter synthetic data quality**: Medium (no human audit; conservative LLM may be over-aggressive).
- **Generalizability to other domains**: Low (single-domain evaluation).
