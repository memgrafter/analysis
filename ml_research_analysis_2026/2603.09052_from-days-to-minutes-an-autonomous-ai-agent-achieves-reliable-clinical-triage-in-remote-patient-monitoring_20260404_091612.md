# From Days to Minutes: An Autonomous AI Agent Achieves Reliable Clinical Triage in Remote Patient Monitoring

## Quick Facts
*   **arXiv ID:** 2603.09052
*   **Source URL:** https://arxiv.org/abs/2603.09052
*   **Reference Count:** 40
*   **Primary Result:** An autonomous AI agent (Sentinel) using dynamic clinical context retrieval achieved >95% emergency sensitivity and >88% actionable sensitivity in remote patient monitoring triage, outperforming individual clinicians.

## Executive Summary
Remote patient monitoring (RPM) systems are hampered by data overload and a lack of clinical context, leading to delayed triage decisions. This study introduces Sentinel, an autonomous AI agent that integrates with the Model Context Protocol (MCP) to dynamically access 21 clinical tools and retrieve comprehensive patient context for each reading. Evaluated against a human majority-vote standard on 467 retrospective cases, Sentinel demonstrated high sensitivity for emergencies (95.8%) and actionable events (88.5%) with good specificity (85.7%). It significantly outperformed individual clinician reviewers (97.5% vs. 60.0% emergency sensitivity) and showed strong self-consistency. The system operated at a low reported cost per triage, suggesting a path toward scalable, timely clinical oversight in RPM.

## Method Summary
The evaluation used a retrospective cohort of 467 RPM cases. A human majority-vote from an unspecified number of clinicians served as the reference standard for triage categorization (e.g., emergency, actionable, non-actionable). Sentinel's architecture leveraged the Model Context Protocol (MCP) to autonomously invoke a suite of 21 clinical tools—potentially including lab lookups, medication checks, and history retrieval—to build a full contextual picture for each vital sign or symptom reading. The AI then reasoned through this enriched context to produce a triage classification. Performance was measured against the human standard, and a leave-one-out analysis compared Sentinel directly against individual clinician reviewers. Overtriage cases were subjected to independent physician adjudication for validation.

## Key Results
*   Sentinel achieved **95.8% sensitivity for emergencies** and **88.5% sensitivity for actionable events** against a human majority-vote standard (N=467), with **85.7% specificity**.
*   In a leave-one-out clinician comparison, Sentinel **outperformed every individual reviewer**, achieving **97.5% emergency sensitivity** versus a clinician aggregate of **60.0%**.
*   The agent showed **near-perfect self-consistency** (Fleiss’ κ=0.850) and was reported to operate at a **median cost of $0.34 per triage decision**.

## Why This Works (Mechanism)
The system's performance is attributed to its **dynamic, context-rich decision-making loop** enabled by the Model Context Protocol (MCP). For each incoming RPM reading (e.g., a blood pressure value), Sentinel does not rely on static thresholds. Instead, it autonomously determines which of the 21 available clinical tools are relevant, queries them in sequence (e.g., retrieving recent lab results, current medication list, past diagnosis history, and trend data), and aggregates all returned data into a comprehensive, patient-specific context window. The core AI reasoning engine (details unspecified) then processes this rich, multi-modal context to generate a triage decision. **Assumption:** The mechanism's success hinges on the MCP's reliable orchestration of tool calls and the AI's ability to synthesize disparate data points into a coherent clinical judgment, effectively mimicking the information-gathering process of a human clinician but at machine speed and without fatigue. The high self-consistency suggests the contextual retrieval and reasoning process is robust and deterministic for similar input patterns.

## Foundational Learning
The system's capability is built upon the **foundational principle that clinical triage decisions require more than isolated data points**; they require synthesis of the patient's current state within their longitudinal health trajectory. Sentinel operationalizes this by making "context retrieval" the first-class, automated step in its pipeline. **Inference:** This contrasts with simpler alerting systems that apply fixed rules to single parameters. The learning appears to be in the *integration strategy*—how the agent learns (via its training) to select the right combination of tools and weigh their outputs for different presenting patterns—rather than in learning clinical knowledge from scratch. The MCP serves as the infrastructure that makes this dynamic, tool-augmented reasoning possible and reproducible.

## Architecture Onboarding
*Component Map:* Patient Raw Data (vitals/symptoms) -> MCP Orchestrator -> [Tool 1, Tool 2, ... Tool 21] (EHR lookup, med history, etc.) -> Enriched Context -> AI Reasoning Engine -> Triage Decision (Emergency/Actionable/Observation)

*Critical Path:* Data Ingestion -> Dynamic Tool Invocation via MCP -> Context Aggregation -> Clinical Reasoning -> Final Triage Label.

*Design Tradeoffs:* Speed vs. Context Depth: The system prioritizes comprehensive context retrieval (via up to 21 tools) for each case, likely increasing latency but improving accuracy over simpler threshold-based alerts. Autonomy vs. Oversight: Full automation reduces clinician burden but requires extremely high reliability to avoid missed emergencies.

*Failure Signatures:* Primary failure mode is **tool unavailability or inaccurate return data**, leading to incomplete context and potential misclassification. A secondary mode is **reasoning edge cases** where the AI misinterprets complex, multi-morbidity contexts not well-represented in training.

*First Three Experiments:*
1.  **Tool Coverage & Success Rate Audit:** Quantify the percentage of cases where all 21 tools returned valid, timely data versus cases where tools failed or timed out.
2.  **Latency vs. Accuracy Pareto Frontier:** Measure triage decision latency against sensitivity/specificity, testing if fewer tools can achieve similar performance for low-complexity cases.
3.  **Clinician-in-the-Loop Validation:** Present Sentinel's reasoning and tool outputs for a random sample of overtriaged and undertriaged cases to clinicians to identify systematic reasoning flaws vs. data retrieval flaws.

## Limitations
*   Evaluation is based on a **single retrospective cohort (N=467)** with unclear demographic and clinical diversity, limiting generalizability.
*   The **human benchmark composition is unspecified** (number of clinicians, their specialties, agreement rates), making it hard to judge the strength of the comparison.
*   **Overtriage validation was selective**, covering only the "most severe disagreements" with physician adjudication, not all false positives.
*   **Cost analysis appears incomplete**, excluding critical real-world expenses like system integration, maintenance, infrastructure, and clinician time for oversight/validation.
*   The **21 clinical tools and their MCP integration lack transparent validation**, raising significant safety and reliability concerns for deployment.
