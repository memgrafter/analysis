# Dataset Color Quantization: A Training-Oriented Framework for Dataset-Level Compression

## Quick Facts
- **arXiv ID:** 2602.20650  
- **Source URL:** https://arxiv.org/abs/2602.20650  
- **Reference count:** 36  
- **Primary result:** DCQ achieves 89.15% top‑1 accuracy on CIFAR‑10 with ResNet‑18 at 2‑bit (∼98% compression) and 35.95% on ImageNet‑1K at 96% compression, outperforming prior methods by large margins.

## Executive Summary
High storage costs caused by color redundancy in image datasets limit the scalability of deep learning. This paper introduces Dataset Color Quantization (DCQ), a framework that reduces dataset size by learning cluster‑shared color palettes, allocating bits based on model attention (Grad‑CAM++), and refining palettes to preserve edges. DCQ consistently surpasses existing color quantization (ColorCNN, CQFormer) and dataset pruning (CCS, EL2N) techniques on CIFAR‑10/100, Tiny‑ImageNet, and ImageNet‑1K under aggressive compression. It generalizes across architectures (ResNet‑34/50, Swin Transformer) and tasks (segmentation, detection), and combines with pruning for extreme compression (>99%) while maintaining competitive accuracy.

## Method Summary
DCQ compresses an entire image dataset by reducing the number of colors per image to a shared, cluster‑level palette. First, images are clustered into groups of similar chromaticity using features from a pre‑trained network. For each cluster, Grad‑CAM++ identifies semantically salient pixels; their colors are aggregated and K‑means is applied to create an initial palette of size \(2^q\). This palette is then refined via differentiable optimization with an edge‑preservation loss (using a straight‑through estimator) to maintain structural details. The final per‑image representation stores only palette indices. During training, images are reconstructed on‑the‑fly from the stored palettes and indices. The method is model‑agnostic and can be combined with other compression strategies.

## Key Results
- **CIFAR‑10 (ResNet‑18):** 79.90% accuracy at 1‑bit (96% compression) vs. 73.02% (CCS) and 59.15% (ColorCNN); 89.15% at 2‑bit vs. 77.32% (CCS).  
- **ImageNet‑1K:** 35.95% top‑1 accuracy at 96% compression vs. 31.31% (CCS).  
- **Extreme compression:** Combined with pruning, DCQ achieves >99% compression with 70.73% accuracy on CIFAR‑10.

## Why This Works (Mechanism)

### Cluster‑Shared Palettes for Cross‑Image Consistency
DCQ stabilizes training under aggressive compression by learning a single color palette per cluster of chromatically similar images, reducing color‑space fragmentation. Images are clustered using shallow‑layer features; within each cluster a common palette of size \(2^q\) is generated via K‑means on all pixel colors. This enforces that similar images share the same representative colors, preserving semantic boundaries while cutting storage redundantly.  
*Core assumption:* Cross‑image palette consistency aids the model’s feature learning by avoiding arbitrary color shifts across semantically similar regions.  
*Break condition:* If clusters mix images with dissimilar color distributions (e.g., due to poor feature choice), the shared palette increases per‑image quantization error and harms accuracy.

### Attention‑Guided Palette Allocation
DCQ retains critical semantics by biasing palette sampling toward image regions salient to the model, as identified by Grad‑CAM++ attention maps. For each image, the top \(k\)% of pixels by attention value are selected; their colors are aggregated across a cluster and K‑means is applied to form the palette, concentrating capacity on semantically relevant colors.  
*Core assumption:* Not all colors equally affect model performance; those in high‑attention regions are indispensable and should be preserved preferentially.  
*Break condition:* If the pre‑trained model’s attention is misaligned with the true task (e.g., biased by dataset artefacts), palette allocation may emphasize irrelevant colours and degrade generalisation.

### Edge‑Preserving Palette Refinement
DCQ maintains structural details lost in naive colour quantisation by refining palettes through differentiable optimisation of an edge‑distribution loss. After initial palette generation, a differentiable quantisation pipeline (with straight‑through estimator) maps each pixel to its nearest palette colour. The palette parameters are adjusted to minimise the edge loss \(EL\), which measures mean‑squared differences of Sobel‑filtered gradients in LAB colour space between original and quantised images.  
*Core assumption:* Edge continuity is vital for effective feature learning; preserving it during palette optimisation avoids abrupt texture disruptions.  
*Break condition:* If the weight of edge loss is too high, palette colours may distort to preserve edges at the expense of overall colour accuracy; if too low, edges remain degraded.

## Architecture Onboarding

**Component map**  
Feature Extractor -> Clustering Module -> Attention Module -> Color Aggregator -> Palette Generation -> Palette Refinement -> Storage & Reconstruction

**Critical path**  
1. Extract shallow features for all images using the pre‑trained model.  
2. Run K‑means clustering on these features to assign each image to a cluster.  
3. For each cluster:  
   a. Compute Grad‑CAM++ maps for all images.  
   b. Aggregate colours from the top‑k % pixels of each map.  
   c. Perform K‑means on the aggregated colour set to obtain an initial palette.  
   d. Refine the palette via gradient descent on the edge‑loss objective.  
4. Store the final palette for the cluster and, for each image, the colour indices.  
5. During neural‑network training, load indices and corresponding palette to reconstruct quantised images.

**Design tradeoffs**  
- Number of clusters \(k\): Larger \(k\) increases palette specificity but reduces cross‑image sharing; smaller \(k\) enhances sharing but may increase distortion.  
- Attention percentage \(k_{Gra}\% \): Higher values include more colours (potentially preserving context) but also noise; lower values focus on the most salient regions but risk omitting background cues.  
- Edge‑loss weight: Balances colour fidelity and edge preservation; requires tuning to avoid over‑sharpening or blurry edges.  
- Feature layer depth: Shallow layers capture colour distributions well but are less semantically abstract; deeper layers encode semantics but may decouple from colour.

**Failure signatures**  
- Poor cluster separation: Visualising cluster contents reveals mixing of semantically/colour‑wise distinct images. Remedy: increase \(k\) or adjust feature extraction.  
- Palette stagnation during refinement: Palette colours change minimally after optimisation. Check edge‑loss weight and STE implementation.  
- High training instability: Accuracy fluctuates wildly or fails to converge; likely due to excessive colour distortion. Try higher bit‑rates or verify palette quality visually.  
- Unexpected storage growth: Total stored indices exceed budget; reduce \(k\) or explore hierarchical palette coding.

**First 3 experiments**  
1. Baseline replication: Run DCQ on CIFAR‑10 with ResNet‑18, 2‑bit quantisation; compare against Table 1 to verify correctness.  
2. Component ablation: Disable CAC (random clustering), attention (aggregate all pixels), and edge refinement (skip differentiable step) one at a time; measure drop in test accuracy.  
3. Hyper‑parameter sweep: On a 1 000‑image CIFAR‑10 subset, vary \(k\) (5, 10, 20, 50) and \(k_{Gra}\%\) (20 %, 30 %, 50 %, 80 %) to identify sensitive ranges.

2. **Architectures for quantized data:** What neural network architectures are best suited for learning from color‑quantized datasets, and can they be co‑designed with the quantization process to improve training efficiency and final performance?

## Limitations
- Pre‑trained model details (training protocol, augmentations) are unspecified, affecting clustering and Grad‑CAM++ quality.  
- Refinement hyperparameters (learning rate, number of steps, edge‑loss weights) are not provided; defaults may diverge from the paper’s choices.  
- Hyperparameters tuned on CIFAR‑10 (cluster count, attention threshold) may not generalize to larger datasets.
