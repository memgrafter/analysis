# Analyzing LLM Instruction Optimization for Tabular Fact Verification

## Quick Facts
- arXiv ID: 2602.17937
- Source URL: https://arxiv.org/abs/2602.17937
- Reference count: 32
- Primary result: Instruction optimization with DSPy consistently improves accuracy for tabular fact verification; MiPROv2 stabilizes CoT gains, SIMBA boosts ReAct particularly for larger models, and behavioral analysis shows SIMBA induces more direct reasoning and reduces unnecessary tool calls.

## Executive Summary
Tabular fact verification requires models to determine whether a textual claim is supported by a structured table. This paper explores whether automatically optimizing the instruction (prompt) for a given reasoning method—direct prediction, Chain-of-Thought (CoT), ReAct (with SQL), or CodeAct (with Python)—can improve performance across multiple LLM families and datasets. Using the DSPy framework, the authors apply three optimizers (COPRO, MiPROv2, SIMBA) to a hybrid training set and evaluate on TabFact, PubHealthTab, SciTab, and MMSci with Qwen3, Gemma3, and GPT-4o models. Results demonstrate that instruction optimization yields consistent accuracy gains, with MiPROv2 providing the most stable improvements for CoT and SIMBA offering the largest benefits for ReAct agents, especially at larger model scales. Behavioral analysis reveals that SIMBA’s optimizations encourage more direct reasoning, enhance numerical comparisons in CoT, and reduce unnecessary tool calls in ReAct. While CoT remains effective for smaller models, optimized ReAct can achieve competitive performance but requires careful tuning. Generalization to the out-of-domain MMSci dataset varies across model families.

## Method Summary
The study employs DSPy to tune prompt instructions for tabular fact verification. Four prompting techniques are implemented as modules: Direct (binary/ternary classification), CoT (step-by-step reasoning), ReAct (SQL tool calls), and CodeAct (Python tool calls). Starting from a seed instruction ("Verify the given claim against the provided table data."), the optimizers COPRO (beam search), MiPROv2 (Bayesian), and SIMBA (contrastive introspective) evolve instructions using a hybrid training set (100 instances from TabFact, SciTab, PubHealthTab). Optimized instructions are then deployed with each LLM backbone (Qwen3-8B/32B, Gemma3-12B/27B, GPT-4o) to predict labels on four test datasets. Performance is measured via accuracy and macro-F1; additionally, behavioral metrics such as tool call frequency, reasoning trajectory length, and execution success rates are logged for analysis.

## Key Results
- Instruction optimization consistently improves accuracy across model families and datasets.
- MiPROv2 yields the most stable gains for Chain-of-Thought prompting.
- SIMBA provides the largest benefits for ReAct agents, particularly at larger model scales.
- Behavioral analysis reveals that SIMBA encourages more direct reasoning, enhances numerical comparison abilities in CoT, and reduces unnecessary tool calls in ReAct.
- CoT remains effective for smaller models, while optimized ReAct can achieve competitive performance but requires careful optimization.
- Generalization to MMSci varies across model families.

## Why This Works (Mechanism)

### Heuristic Infusion via Instruction Optimization
Optimizers like SIMBA and MiPROv2 introduce task-specific heuristics into the prompt by evaluating candidate instructions on training data. Successful candidates accumulate clauses that steer the model toward patterns critical for tabular verification, e.g., focusing on ordinal terms or numerical comparisons. This exploits the LLM’s sensitivity to prompt wording, biasing its reasoning trajectory. Evidence: SIMBA-optimized direct prediction added ordinal-focused clauses, improving performance on ordinal claims by 4.5% (Table 8); CoT instructions added numerical emphasis, yielding a 2.4% gain on comparative claims (Table 9). Behavioral analyses confirm more direct reasoning paths.

### Tool-use Refinement for ReAct Agents
For ReAct agents, instruction optimization reduces unnecessary tool calls by teaching the model to first assess whether the table directly contains required information. Optimizers identify trajectories with excessive or incorrect tool usage and generate rules such as “if the table explicitly contains the information, call finish without executing unnecessary SQL.” This shifts the agent’s behavior toward mental checks before tool invocation, lowering error rates from malformed calls. Evidence: For Qwen3-32B ReAct, SIMBA reduced tool usage from 90% to 35.4% while increasing reasoning length by 33% and maintaining similar error rates (Section 5.2). Error analysis shows tool execution errors are mitigated when calls are more selective.

### Optimizer-specific Stability and Scaling Effects
The choice of optimizer influences both the magnitude and stability of gains. MiPROv2’s Bayesian optimization over bootstrapped few-shot demonstrations yields consistent improvements, especially for CoT, across model scales. SIMBA’s introspective rule generation benefits from larger models’ superior self-reflection, leading to larger gains for ReAct when model size increases. Evidence: Across Qwen3, Gemma3, and GPT-4o, MiPROv2 often achieves highest or near-highest F1 with low variance (Tables 2–4). SIMBA produces the biggest jumps for Qwen3-32B and Gemma3-27B ReAct (Section 5). Ablation on random seeds confirms robustness (Table 14).

## Architecture Onboarding

### Component Map
Hybrid train set + Seed prompting module -> Optimizer (COPRO/MiPROv2/SIMBA) -> Optimized prompting module -> LLM backbone (Qwen3/Gemma3/GPT-4o) -> Test datasets -> Predictions -> Evaluation (Accuracy, Macro-F1) & Behavioral logs -> Analysis

### Critical Path
1. Load seed instruction and hybrid training set.
2. Run optimizer for fixed iterations/budget to produce final instruction.
3. Deploy optimized instruction in the corresponding module and run inference on each test dataset.
4. Collect predictions, compute metrics, and optionally record trajectories for behavioral analysis.
5. Repeat across all model-optimizer-technique combinations.

### Design Tradeoffs
- **Optimizer selection**: COPRO may overfit; MiPROv2 offers efficiency and stability; SIMBA yields large gains but may produce lengthy instructions.
- **Model size**: Larger models extract more benefit from optimized instructions but incur higher cost; smaller models may mishandle complex rules.
- **Prompting technique**: CoT is robust for small models; ReAct/CodeAct can achieve competitive performance with large models but require careful tuning.
- **Training data**: Hybrid data improves generalization for SIMBA; single-source data yields simpler but less generalizable instructions.

### Failure Signatures
- **No improvement**: Could be due to poor seed instruction, optimizer misconfiguration (e.g., forcing tool use), or insufficient training data.
- **ReAct still high tool error rate**: Indicates optimizer failed to teach proper tool schema adherence; may need more iterations or a different optimizer (SIMBA recommended).
- **Poor generalization to MMSci**: Suggests overfitting to source domains; remedy by including MMSci-like data in training.
- **SIMBA instructions too lengthy**: May exceed model context or introduce contradictions; monitor length and consider truncation.
- **Resource exhaustion**: Large models need multi-GPU; long code traces may blow memory; limit ReAct steps, use gradient checkpointing.

### First 3 Experiments
1. **Baseline performance characterization**: Run zero-shot inference with seed instruction on all test sets for each prompting technique and model to establish reference points.
2. **Optimization and main evaluation**: For each optimizer and suited technique, run optimization on hybrid train set, then evaluate optimized instructions on test sets. Compare gains across model families and datasets.
3. **Behavioral shift validation**: For promising optimizer-model pairs, collect detailed trajectories. Quantify tool call frequency, reasoning length, success rate. Sample error cases to taxonomize failure modes.

## Open Questions the Paper Calls Out

### Open Question 1
**Question:** How do different instruction optimization algorithms (e.g., COPRO, MiPROv2, SIMBA) compare in their ability to adapt prompts for specific model architectures beyond Qwen3 and Gemma3, such as Llama or Claude?  
**Basis in paper:** The authors restrict their scope to Qwen3 and Gemma3, noting that generalizability to other architectures remains open; they also compare only three optimizers and suggest newer techniques like GEPA could reveal different trade-offs.  
**Why unresolved:** Empirical findings are limited to two model families; architectural differences could lead to different optimization dynamics and performance ceilings.  
**What evidence would resolve it:** Systematic evaluation of the same DSPy optimizers across a broader spectrum of model families (e.g., Llama, Claude) on tabular fact verification benchmarks, measuring accuracy and behavioral shifts.

### Open Question 2
**Question:** What specific characteristics of optimized instructions (e.g., length, heuristic density, structural constraints) are most predictive of strong generalization from in-domain training data to out-of-domain test sets, particularly for larger models like GPT-4o?  
**Basis in paper:** For Qwen3 and Gemma3, instructions optimized on TabFact/SciTab/PubHealthTab often generalize well to MMSci, but this pattern does not hold for GPT-4o, possibly because GPT-4o’s SIMBA-generated instructions generalize less effectively.  
**Why unresolved:** The paper analyzes instruction content qualitatively but does not quantify features or correlate them with cross-dataset performance, especially by model scale.  
**What evidence would resolve it:** Feature ablation study measuring attributes (token count, procedural/declarative ratio, domain term inclusion) of optimized instructions and correlating them with performance deltas between seen and unseen datasets.

### Open Question 3
**Question:** To what extent can instruction optimization for tool-augmented agents (ReAct/CodeAct) mitigate the performance gap caused by poor tool execution reliability (e.g., SQL syntax errors, Python runtime failures) on complex tabular reasoning tasks?  
**Basis in paper:** Error analysis shows 25% of ReAct errors and 30% of CodeAct errors are code-related (execution failures). SIMBA reduces unnecessary tool calls but does not eliminate execution errors; many failures stem from code generation issues.  
**Why unresolved:** It is unclear if optimized instructions can improve the correctness of tool calls when needed; root cause may be the model’s inherent code-generation capability rather than instruction phrasing.  
**What evidence would resolve it:** Experiment decoupling tool execution failures by using a perfect tool simulator (always returns correct results for syntactically valid queries) versus a real executor; compare performance gains from instruction optimization under both conditions to isolate impact on tool-call planning versus correctness.

### Open Question 4
**Question:** How does the composition and domain diversity of the hybrid training set used for instruction optimization affect the stability and final performance of different optimizers across model scales?  
**Basis in paper:** The hybrid set (100 instances) is used throughout; an ablation shows SIMBA benefits more from the hybrid set while MiPROv2 is less sensitive, hinting at complex interactions between optimizer search strategy and training data distribution.  
**Why unresolved:** The ablation only tests single-source vs. hybrid on one model (Qwen3-32B) with CoT; it does not explore varying domain mixtures or complexity distributions, nor their interaction with model size.  
**What evidence would resolve it:** Controlled study training with multiple training set compositions (varying domain ratios, complexity levels) and measuring not only final accuracy but also optimization stability (variance across seeds, convergence speed) for each optimizer-model pairing.

### Open Question 5
**Question:** For ReAct agents, what is the optimal balance between language-based reasoning and tool invocation that instruction optimization converges to, and is this balance task- or model-dependent?  
**Basis in paper:** Behavioral analysis shows SIMBA reduces tool usage for Qwen3-32B (90% → 35.4%) while increasing reasoning length by 33%; for Qwen3-8B, tool use remains similar but success rate improves slightly.  
**Why unresolved:** The paper shows optimization changes behavior but does not establish a causal link between specific behavioral metrics and final accuracy; it’s unclear if “more direct reasoning” is universally beneficial or if an optimal tool-use frequency exists per dataset/model.  
**What evidence would resolve it:** Analysis correlating per-instance behavioral metrics (tool-call count, trajectory length, tool success rate) with correctness after optimization, across datasets and models, to identify thresholds where accuracy peaks.

## Limitations
- Exact model checkpoints, DSPy version, and tool implementations are unspecified, hindering faithful replication.
- Generalization to MMSci is inconsistent across models, suggesting overfitting to training domains.
- Mechanisms rely on behavioral correlations without causal isolation; break conditions indicate limits when targeted patterns are absent or tool suppression is excessive.

## Next Checks
1. **Heuristic ablation**: Remove heuristic clauses from SIMBA-optimized CoT instructions; evaluate on ordinal/numerical claim subsets. Also add only heuristics to baseline to isolate their effect.
2. **Cross-domain transfer**: Train optimized instructions on the hybrid set and test on MMSci; then include MMSci in training to measure transfer impact and diagnose overfitting.
