# Recurrent Preference Memory for Efficient Long-Sequence Generative Recommendation

## Quick Facts
- **arXiv ID:** 2602.11605
- **Source URL:** https://arxiv.org/abs/2602.11605
- **Reference count:** 40
- **Primary result:** Rec2PM-O (overwriting) achieves H@1 15.04 on MerRec with HSTU, beating full‑context (14.24) while reducing storage to ~1KB and latency to ~10ms.

## Executive Summary
Generative recommendation models that attend to long user histories face O(L²) computational costs and noise amplification from stochastic interactions. This paper introduces Recurrent Preference Memory (Rec2PM), which compresses lifelong sequences into compact, persistent token embeddings called Preference Memory. The method uses a self‑referential teacher‑forcing training strategy: a globally supervised reference memory guides parallelized recurrent updates during training, avoiding serial unrolling and BPTT instability. At inference, memory is updated iteratively. On the MerRec benchmark with HSTU backbone, Rec2PM‑O (overwriting) achieves H@1 15.04 and N@50 32.48, surpassing full‑context and KV‑cache baselines while reducing per‑user storage to ~1KB and matching short‑context latency. Results on an industrial dataset further validate the denoising effect of the memory bottleneck.

## Method Summary
Rec2PM processes a user’s interaction sequence in fixed‑length segments. A set of learnable query vectors Q_mem (C slots) acts as an information bottleneck. During training, a two‑stage parallel procedure is used. **Stage 1** constructs a global representation by interleaving raw segments with Q_mem and applying a custom attention mask that allows each Q_mem to attend only to preceding raw tokens, producing reference memories m_ref_h for each segment. **Stage 2** builds independent local subsequences [M_ref_{h‑1}; S_h; Q_mem] for all segments in parallel. Within each, the shared Transformer predicts next items (loss L_AR) and generates an updated memory m_upd_h from Q_mem. A consistency loss L_con = ‖m_ref_h − m_upd_h‖² forces the recurrent update to match the global reference. The final loss L = L_AR + λ L_con (λ=1) is back‑propagated. At inference, memory M_0 is initialized from the first segment. For subsequent segments, the current memory M_{k‑1} is concatenated with S_k and Q_mem; the Transformer outputs predictions and a new memory m_k, which updates M_k via either overwriting (M_k = m_k) or appending (M_k = [M_{k‑1}; m_k]). The token‑based memory representation yields extreme storage efficiency (~1KB per user for C=4, d=64, fp16) compared to per‑layer KV caches.

## Key Results
- On MerRec (HSTU), Rec2PM‑O (overwriting) achieves H@1 15.04 and N@50 32.48, beating Full‑context (H@1 14.24, N@50 31.41) and KV‑Mask‑O (H@1 14.56).
- Reduces per‑user storage to ~1KB (vs. 32KB for KV‑cache) and attains ~10 ms latency, comparable to short‑context models, while delivering 107 % of HSTU‑Full’s accuracy at only 8 % of its latency.
- On an industrial short‑video dataset, Rec2PM improves Hit Ratio@1000 to 0.3306 vs. 0.3243 with explicit reconstruction loss, confirming the denoising bottleneck’s benefit.

## Why This Works (Mechanism)

### Mechanism 1: Preference Memory as a Denoising Information Bottleneck
The Memory Encoder uses global learnable query vectors Q_mem to extract a compact representation m from a user’s history. Forced compression (e.g., 4–20 tokens for thousands of interactions) limits capacity, preventing the model from memorizing irrelevant or accidental interactions. The Decoder conditions predictions on this distilled state, assuming that user histories contain significant stochastic noise that harms generalization if directly attended to. Evidence includes the abstract’s denoising claim, the contrast between implicit (L_AR) and explicit reconstruction (L_Rec) supervision, and ablations showing that weakening the bottleneck (adding L_Rec) harms performance. If the noise floor is negligible, the bottleneck may discard useful granular signals, causing a drop below full‑attention performance.

### Mechanism 2: Self‑Referential Teacher Forcing for Parallel Training
A two‑stage parallel procedure avoids BPTT instability. Stage 1 generates reference memories m_ref by letting the model attend to the full raw history with a custom mask. Stage 2 simulates the recurrent update process in parallel: each segment’s update is supervised by the reference memory from the previous segment (M_ref_{h‑1}) via a consistency loss L_con. This decouples update steps and prevents error accumulation. The global reference memory m_ref is assumed to be a high‑quality target for an ideal incremental update. The ablation table shows that removing L_con causes a significant drop (H@1 15.04 → 14.43), proving its necessity. If m_ref becomes a poor supervisor (e.g., due to distribution shift or mis‑set λ), the updater may fail to learn meaningful transitions.

### Mechanism 3: Token‑Based Memory for Storage Efficiency
Preference Memory is a fixed‑size set of C token embeddings stored and updated per user (e.g., 4 × 64‑dim = 1 KB for fp16). At inference, these tokens are concatenated with the working segment and processed by the standard Transformer, avoiding per‑layer KV‑cache storage. The assumption is that semantic information for long‑term preference can be captured by a small set of re‑attended embeddings. Measurements show Rec2PM‑O storage = 1 KB vs. 32 KB for KV‑Mask‑O, latency similar to short‑context (~10 ms) while matching or exceeding KV‑cache accuracy. For tasks requiring precise layer‑specific contextual knowledge (e.g., complex logical reasoning), the compressed token state may lose information that KV caches preserve, potentially leading to accuracy drops.

## Foundational Learning

### Information Bottleneck Principle
- **Why needed:** Explains why compression can improve robustness: the memory’s limited capacity forces the model to discard noise and retain only predictive signals.
- **Quick check:** If we increased C dramatically (e.g., 1000 tokens), how would the model’s noise filtering and performance change? Likely weaker denoising, possibly overfitting to noise.

### Teacher Forcing for Recurrent State Training
- **Why needed:** Clarifies how Rec2PM trains a recurrent update mechanism without BPTT; the “teacher” is the reference memory from the global pass.
- **Quick check:** In Stage 2 training, why is it crucial that the input to the updater is M_ref_{h‑1} and not the previously predicted M_upd_{h‑1}? Because using the predicted state would propagate errors; the reference provides a clean target.

### Token‑Based vs. KV‑Cache‑Based Memory Persistence
- **Why needed:** Central to the storage‑efficiency claim: token memory stores a final integrated embedding per slot, while KV caches store intermediate per‑layer states for every token.
- **Quick check:** For a 16‑layer, 64‑dim model with memory of 4 slots, which format (token vs. KV‑cache) is cheaper and by what factor? Token: 4 × 64 × 2 bytes = 512 B; KV‑cache: 2 × 16 × 4 × 64 × 2 bytes = 16.4 KB; factor ~32× cheaper.

## Architecture Onboarding

**Component map:**  
Input Segmentor splits user sequence S into fixed‑length segments S_k. Memory Queries Q_mem (C learnable vectors) are combined with each segment as [M_{k‑1}; S_k; Q_mem]. The Unified Transformer (shared parameters) processes this concatenation with causal masking; the same layers serve to predict next items from S_k tokens (decoder role) and to generate memory embeddings from Q_mem positions (encoder role). The Memory Updater combines previous memory M_{k‑1} and new memory m_k into M_k (overwriting or appending). The Two‑Stage Trainer orchestrates parallel training: Stage 1 builds E_global by interleaving all S_h with Q_mem and applies a special mask (Q_mem sees only preceding raw tokens) to produce m_ref_h; Stage 2 constructs E_local,h = [M_ref_{h‑1}; S_h; Q_mem] for all h, computes next‑item loss L_AR and consistency loss L_con between m_upd_h and m_ref_h.

**Critical path:**  
- *Inference:* Initialize M_0 from S_0. For each subsequent segment k, compute E_k = [M_{k‑1}; S_k; Q_mem], extract predictions on S_k and m_k from Q_mem, then update M_k via overwriting/appending.  
- *Training:* Parallel global reference pass (Stage 1) yields m_ref_h for all segments; parallel local pass (Stage 2) uses M_ref_{h‑1} (stop‑grad) to compute m_upd_h, L_AR, and L_con; summed loss is back‑propagated through shared weights.

**Design tradeoffs:**  
- **Overwriting vs. Appending:** Overwriting enforces a strict bottleneck (better denoising, constant storage); appending grows memory (more capacity, weaker bottleneck, linearly growing storage). Overwriting consistently outperforms.  
- **Number of slots C:** Too small (C=1) loses capacity; too large (C=16) weakens denoising. Optimal C is dataset‑dependent; MerRec best at C=4–8.  
- **Consistency loss weight λ:** λ = 0 fails to learn recurrent updates; λ too high may overfit to reference; paper uses λ = 1.

**Failure signatures:**  
1. **Absence of L_con:** Performance drops sharply (e.g., H@1 15.04 → 14.43 in Table 3), indicating the recurrent update mechanism is not learned.  
2. **Temporal overlap robustness failure:** If recent S_k overlaps heavily with M_{k‑1}, naive models double‑count; Rec2PM is robust (Table 9), but a failure would show a significant HR drop.  
3. **C too small:** Performance approaches the short‑context baseline, signalling memory cannot capture long‑term signals.

**First 3 experiments:**  
1. **Main Benchmark Comparison (Table 1):** Evaluate Rec2PM‑O/A against Tok‑Serial, KV‑Mask, Short‑context, and Full‑context on MerRec with HSTU/SASRec backbones.  
2. **Consistency Loss Ablation (Table 3):** Train Rec2PM‑O with λ = 0 to demonstrate the necessity of L_con.  
3. **Efficiency & Storage Analysis (Table 5):** Measure per‑user storage and inference latency for Rec2PM vs. KV‑Mask vs. Full‑context, validating the storage‑latency trade‑off.

## Open Questions the Paper Calls Out
1. **Generalization of denoising bottleneck:** Does the noise‑filtering benefit hold across domains with different noise characteristics? (Only two datasets tested; noise profiles vary.)  
2. **Theoretical justification of self‑referential teacher forcing:** Why does the proposed two‑stage parallel training outperform alternatives? (Lack of formal analysis of gradient dynamics or convergence.)  
3. **Appending vs. Overwriting:** Why does appending underperform, and what is the mechanism of noise accumulation? (Hypothesized but unverified; needs memory‑state analysis.)  
4. **Memory slot count (C) dependence:** What explains non‑monotonic performance with C (best at 4–8, drops at 1 and 16)? (Optimal C may depend on intrinsic interest dimensionality; not studied.)  
5. **Disentanglement benefit:** Does the emergent temporal/semantic specialization of memory slots directly improve accuracy, and can it be explicitly encouraged? (No causal evidence; could be engineered via auxiliary losses.)

## Limitations
- **Masking details underspecified:** The exact attention masks for Stage 1 and Stage 2 are not formally defined, risking incorrect implementation of reference memory supervision.
- **Unified architecture ambiguity:** It is unclear whether memory generation and item prediction use identical Transformer parameters in a single forward pass or separate modules, affecting gradient flow and optimization.
- **Generalization scope limited:** The denoising bottleneck claim is validated only on two recommendation datasets; its benefit for other domains (e.g., news, e‑commerce) remains speculative.

## Confidence
- **Claim:** Preference Memory acts as a denoising information bottleneck. **Confidence:** Medium (supported by ablations but assumes noise prevalence universally).  
- **Claim:** Self‑referential teacher‑forcing enables stable parallel training. **Confidence:** High (ablation shows L_con essential; procedure well‑described).  
- **Claim:** Token‑based memory representation achieves extreme storage efficiency without accuracy loss. **Confidence:** High (measurements confirm).  
- **Claim:** Rec2PM’s design generalizes across recommendation domains. **Confidence:** Low (validated on two datasets only).

## Next Checks
1. **Mask correctness test:** For a fixed batch, compute reference memories m_ref_h and verify via attention visualization that each Q_mem attends only to preceding raw tokens S_{0:h} (not to future segments or other Q_mem).  
2. **Unified forward pass verification:** Ensure gradients from L_AR flow through the same layers that process Q_mem positions; confirm m_k updates when S_k content changes even if prediction targets are fixed.  
3. **Bottleneck capacity boundary test:** Run Rec2PM with C = 1 and C = 32 on MerRec; expect C=1 to underfit (near short‑context performance) and C=32 to degrade due to weakened bottleneck, confirming dataset‑dependent optimal C.
