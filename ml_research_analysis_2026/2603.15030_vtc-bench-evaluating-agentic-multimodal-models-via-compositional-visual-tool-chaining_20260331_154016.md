# VTC-Bench: Evaluating Agentic Multimodal Models via Compositional Visual Tool Chaining

## Quick Facts
- arXiv ID: 2603.15030
- Source URL: https://arxiv.org/abs/2603.15030
- Reference count: 40
- Primary result: The top-performing model, Gemini-3.0-Pro, achieves only ~51% accuracy, exposing severe limitations in current MLLMs' tool composition capabilities.

## Executive Summary
Existing benchmarks for evaluating tool-use capabilities of multimodal large language models (MLLMs) are limited by sparse tool sets and simple trajectories, failing to capture complex tool composition in real-world scenarios. VTC-Bench addresses this by introducing a diverse suite of 32 OpenCV operations and 680 curated VQA problems organized across a nine-level cognitive hierarchy, each accompanied by ground-truth execution trajectories. Evaluating 19 leading MLLMs using both code-driven and interface-driven tool invocation reveals that current models struggle to adapt to diverse tools and compose multi-tool plans, relying instead on a narrow subset of functions and producing overly short toolchains. Proprietary models gain substantially from tool augmentation, while open-source models see minimal improvement. The benchmark establishes a rigorous baseline and highlights the gap between passive visual perception and active visual agentic reasoning.

## Method Summary
VTC-Bench constructs a comprehensive evaluation framework for tool-augmented visual reasoning. It defines a tool library of 32 OpenCV functions spanning four categories: Geometry, Enhancement, Feature Extraction, and Drawing. The dataset comprises 680 image-question pairs, each requiring a sequence of tool calls to answer. Tasks are organized into nine categories within a three-tier cognitive hierarchy: Perception Enhancement, Quantitative Estimation, and Compositional Reasoning. Ground-truth execution trajectories, typically 4–6 steps long, are provided for each instance. Evaluation is performed in three zero-shot settings per model: Base (no tools), Code-driven (using a Python code interpreter), and Interface-driven (using atomic tool calls). Both deterministic rule-based matching and GPT-4o-based answer validation are employed. Key metrics include Average Pass Rate (APR), Tool Call Rate (TCR), Mean Absolute Error (MAE) of chain length, and Tool Usage Efficiency (effective steps over total steps). The benchmark is implemented using the Qwen-Agent framework for models with native tool support and Thyme for open-source tool-use models, with a maximum of 20 interaction rounds.

## Key Results
- Top model (Gemini-3.0-Pro) accuracy: ~51%.
- All models exhibit depth deficiency: predicted toolchains are typically 1–2 steps, far shorter than ground-truth (4–6 steps).
- Models rely on a narrow subset of tools (e.g., zoom, crop) and fail to generalize across the diverse 32-tool set; open-source models show minimal gains from tool augmentation, whereas proprietary models improve significantly.

## Why This Works (Mechanism)
### Mechanism 1: Diverse tool suite forces composition
Claim: The 32-tool OpenCV suite forces models to engage in tool composition rather than relying on a narrow set of familiar functions.  
Mechanism: Tools cover geometry, enhancement, feature extraction, and drawing, requiring models to select and chain appropriate operations for tasks. This tests planning and generalization to unseen combinations.  
Core assumption: Models with limited tool repertoire or inability to compose will fail on tasks requiring diverse operations.  
Evidence: Abstract and Section 3.1 note models struggle with diverse tool-sets; the rich tool-set enables extensive combinations.  
Break condition: If models were pre-trained on exhaustive tool compositions, the diversity would not reveal planning deficits.

### Mechanism 2: Cognitive hierarchy reveals progressive capability gaps
Claim: The nine-level cognitive hierarchy structures tasks from basic perception to complex reasoning, exposing where models fail.  
Mechanism: Tasks are tiered: Tier 1 (Perception Enhancement), Tier 2 (Quantitative Estimation), Tier 3 (Compositional Reasoning). Performance drops on higher tiers, indicating that foundational perception is prerequisite for effective tool use.  
Core assumption: Visual agentic ability builds hierarchically.  
Evidence: Abstract and Section 3.1 describe the hierarchy; Section 4.2 shows strong performance on perception tasks but bifurcated outcomes on quantitative estimation.  
Break condition: If models could skip foundational tiers and still solve higher-tier tasks, the hierarchy would not predict performance.

### Mechanism 3: Ground-truth trajectories diagnose planning inefficiencies
Claim: Providing ground-truth execution trajectories enables diagnosis of planning inefficiencies beyond final accuracy.  
Mechanism: Reference toolchains allow computing metrics like MAE and Tool Usage Efficiency, exposing that models produce overly short chains and misuse tools.  
Core assumption: Intermediate step analysis is necessary to understand failure modes.  
Evidence: Abstract mentions ground-truth trajectories; Section 3.3 defines Effective Toolchain and backtracking; Section 4.3 shows models favor narrow subsets, causing inefficiencies.  
Break condition: If models always produced optimal-length, diverse toolchains, the ground truth would not add diagnostic value.

## Architecture Onboarding
### Component map
Tool Library (32 OpenCV functions) -> Task Dataset (680 VQA instances with ground-truth toolchains) -> Evaluation Engine (dual-paradigm: code-driven & interface-driven) -> Metrics (APR, TCR, MAE, Tool Usage Efficiency)

### Critical path
1. Task design: Define toolset and cognitive hierarchy, curate images and questions.  
2. Trajectory annotation: Generate and verify ground-truth toolchains (using models like Gemini-3.0-Pro and human experts).  
3. Framework implementation: Integrate Qwen-Agent/Thyme, implement tools, set hyperparameters.  
4. Model evaluation: Run models in zero-shot with tool augmentation (code and interface modes).  
5. Analysis: Compute metrics, compare with ground truth, produce distribution analyses.

### Design tradeoffs
- Tool diversity vs. complexity: More tools increase realism but raise planning horizon; VTC-Bench uses 32 to balance.  
- Code vs interface: Code offers flexibility but may be error-prone; interface provides structure but may limit expressiveness; benchmark includes both.  
- Multiple-choice format: Enables automated scoring but may not capture open-ended reasoning; they use LLM-as-a-judge for open-ended.  
- Zero-shot evaluation: Fair comparison but may understate fine-tuned potential.

### Failure signatures
- Depth deficiency: Predicted toolchain lengths peak at 1–2 steps while ground truth often 4–6.  
- Tool concentration: Overuse of few tools (e.g., zoom in, crop) as shown in Fig. 6.  
- Strategic misselection: Using inappropriate tools like Draw Circle for measurement (Fig. 8a).  
- Output over-reliance: Blindly trusting tool outputs without verification (Fig. 8b).

### First 3 experiments
1. **Main evaluation (Table 4)**: Test 19 models on all tasks, compare base vs. tool-augmented (code/interface) to assess overall performance and gains.  
2. **Tool utilization analysis (Fig. 6, 7, Table 5)**: Analyze tool call distributions, chain lengths, and efficiency metrics to identify depth deficiency and narrow repertoire.  
3. **Prompt ablation (Fig. 9)**: Vary prompt strength and provide ground-truth tools to measure impact on APR, revealing that correct tool knowledge alone is insufficient.

## Open Questions the Paper Calls Out
### Open Question 1
Question: Why do current MLLMs struggle to generalize to diverse and unseen visual tools, and what architectural changes could improve tool adaptability?  
Basis in paper: The authors state that "models struggle to adapt to diverse tool-sets and generalize to unseen operations."  
Why unresolved: Generalization is fundamental for real-world deployment, but VTC-Bench reveals severe deficits. The root cause—whether due to training data limitations, architectural constraints, or lack of explicit tool grounding—remains unknown.  
What evidence would resolve it: Ablation studies isolating training data diversity, architectural modifications (e.g., explicit tool embeddings), and evaluation on held-out tool sets could identify the bottleneck.

### Open Question 2
Question: What explains the persistent challenge in multi-tool composition, causing models to rely on a narrow tool subset and produce suboptimal plans?  
Basis in paper: "Multi-tool composition remains a persistent challenge. When facing complex tasks, models struggle to formulate efficient execution plans, relying heavily on a narrow, suboptimal subset of familiar functions."  
Why unresolved: Compositional reasoning is key for complex visual tasks, but models exhibit a "depth deficiency" and poor tool diversity. It is unclear whether this stems from insufficient training on composite trajectories, lack of planning mechanisms, or reward mis-specification in RL approaches.  
What evidence would resolve it: Compare models trained with explicit compositional objectives, analyze planning module capabilities, and measure performance on tasks requiring specific tool chains.

### Open Question 3
Question: Why do proprietary MLLMs gain substantially from tool augmentation while open-source models gain minimally, and what does this disparity imply for open-source development?  
Basis in paper: "Proprietary models show substantial gains from tool augmentation, while open-source models gain minimally."  
Why unresolved: This gap suggests proprietary models may have better inherent reasoning or tool integration capabilities, but the specific factors—such as training data, model scale, or reinforcement learning—are not isolated. Understanding this is critical for democratizing tool-augmented MLLMs.  
What evidence would resolve it: Controlled experiments equating model size and training data, but varying tool-augmentation strategies; analysis of internal representations during tool invocation.

### Open Question 4
Question: Why do MLLMs exhibit 'depth deficiency', generating toolchains much shorter than ground truth, and how can we encourage deeper, more complete reasoning?  
Basis in paper: From Fig.10 and analysis: models consistently produce 1-2 step chains while ground truth requires 4-6 steps. The authors term this "depth deficiency."  
Why unresolved: Shallow planning leads to incomplete solutions. Possible causes include insufficient credit assignment over long horizons, lack of intermediate supervision, or the ease of early stopping. This bottleneck impedes complex task execution.  
What evidence would resolve it: Incorporate intermediate reward signals, train with longer trajectories, or augment prompts with step-by-step demonstrations to encourage depth.

## Limitations
- Data accessibility: Public release of the full 680-sample dataset with ground-truth toolchains is unverified; reproduction hinges on this.
- Tool implementation fidelity: Precise schemas and error handling for the 32 OpenCV tools in the interface-driven paradigm are underspecified.
- Benchmark generalizability: Results may reflect the specific tool/task design; transfer to other visual tool ecosystems (e.g., PIL, custom APIs) is unknown.

## Confidence
- Tool composition demand: High
- Hierarchical capability gaps: Medium
- Diagnostic value of trajectories: Medium
