# Is Human Annotation Necessary? Iterative MBR Distillation for Error Span Detection in Machine Translation
## Quick Facts
- arXiv ID: 2603.12983
- Source URL: https://arxiv.org/abs/2603.12983
- Reference count: 12
- Primary result: Self-trained models via Iterative MBR Distillation achieve 0.862 SPA and 0.939 SOFTF1 on WMT24 Metrics Shared Task, exceeding human-annotated baselines.

## Executive Summary
Training accurate Error Span Detection (ESD) models typically relies on costly and inconsistent human-annotated data. This paper introduces Iterative MBR Distillation, a self-evolution framework that eliminates the need for human supervision by leveraging Minimum Bayes Risk decoding on an off-the-shelf large language model to generate high-quality pseudo-labels from unlabeled translation data. Models fine-tuned with these pseudo-labels using SFT, DPO, or KTO objectives are evaluated on the WMT24 Metrics Shared Task test sets. The results show that the self-trained models significantly outperform both the unadapted base model and models fine-tuned on human annotations on system-level (Soft Pairwise Accuracy) and span-level (SOFTF1) metrics, while maintaining competitive sentence-level accuracy (Acc\*eq). This demonstrates that high-quality ESD models can be trained entirely without human-annotated error spans.

## Method Summary
Iterative MBR Distillation operates in cycles over unlabeled source-translation pairs. For each input, the current model generates a diverse set of candidate error span predictions (C=256) using high-temperature top-K sampling. Minimum Bayes Risk decoding then selects the best candidate (E⁺) and worst candidate (E⁻) based on average SOFTF1 utility against all other candidates. These pairs form a pseudo-labeled dataset. The model is fine-tuned on this dataset using one of three objectives: SFT (using E⁺ as target), DPO (using E⁺ preferred over E⁻), or KTO (using E⁺ as desirable and E⁻ as undesirable). A reference model is maintained for DPO/KTO. After fine-tuning, the updated model becomes the base for the next iteration. This loop repeats for T iterations (typically 2), allowing the model to progressively align its greedy outputs with the MBR optimum.

## Key Results
- MBR Distill (T=2, SFT) achieves 0.862 SPA and 0.939 SOFTF1, surpassing Gold-SFT (0.826 SPA, 0.915 SOFTF1) and the unadapted base model.
- Sentence-level accuracy (Acc\*eq) remains competitive with supervised baselines.
- The approach eliminates reliance on human-annotated error spans while achieving state-of-the-art ESD performance.

## Why This Works (Mechanism)
Three mechanisms explain the success:

**Mechanism 1: MBR consensus selection**  
MBR decoding selects higher-quality pseudo-labels than individual model generations by aggregating consensus across a diverse candidate set. For each input, the model generates multiple candidate error spans. The MBR scorer computes the average SOFTF1 utility of each candidate against all other candidates; the candidate with the highest average utility (E⁺) is selected as the positive pseudo-label, and the lowest (E⁻) as a negative pair. This filters out idiosyncratic, low-quality generations. The core assumption is that the candidate distribution contains a mode aligned with true error spans, and averaging pairwise SOFTF1 surfaces this mode [abstract, section 3.2]. Evidence includes prior work linking MBR to improved ESD/MT evaluation [corpus]. A break condition occurs if candidate diversity is low (e.g., low temperature), causing consensus collapse to a poor mode.

**Mechanism 2: Iterative distillation amortization**  
Iterative distillation amortizes the computational cost of MBR decoding while enabling the model's weights to evolve toward a state where greedy decoding approximates MBR's output. In each iteration, the model is fine-tuned on MBR-selected pseudo-labels from the previous iteration. The updated model then generates new candidates from which new, presumably better, MBR pseudo-labels are derived. Over T iterations, the model's distribution is optimized to directly produce outputs that would have been selected by MBR, reducing the need for expensive candidate aggregation at inference. The assumption is that training on (E⁺, E⁻) pairs moves the model's distribution toward E⁺ [abstract, section 4]. Break condition: if MBR selection is flawed (e.g., corrupted utility function), the model trains on bad data, causing catastrophic drift.

**Mechanism 3: Metric-aligned pseudo-label advantages**  
Training on MBR-selected labels improves span-level performance beyond human-annotated supervision because pseudo-labels are more consistent with the model's own representation and the SOFTF1 utility. E⁺ maximizes average SOFTF1 against the candidate set, aligning with the model's generation "style". Human annotations may represent a different annotation style or contain idiosyncrasies not aligned with the model's internal representation, causing a distribution shift. Self-generated, consensus-based labels minimize this shift, providing a more effective learning signal. Evidence: abstract and Table 2 show MBR Distill variants exceeding human-supervised baselines on SOFTF1 and SPA; prior work supports MBR's advantage. Break condition: if the base model's initial generation distribution is severely misaligned (e.g., never generates correct span format), the MBR consensus will also be misaligned, reinforcing a poor equilibrium.

## Foundational Learning
Three key concepts underpin the approach:

### Minimum Bayes Risk (MBR) Decoding
- **Why needed**: It is the core signal generation mechanism that selects a hypothesis minimizing expected loss (maximizing expected utility) against a distribution of samples, rather than just maximizing model probability.
- **Quick check**: For a given input, if candidate A has a SOFTF1 of 0.9 with every other candidate and candidate B has a SOFTF1 of 0.5 with every other candidate, which will MBR select as E⁺? Why?

### Utility Function (SOFTF1)
- **Why needed**: The utility function defines what "risk" means for ESD. SOFTF1 measures span-level overlap, directly optimizing for the span-level metric used in evaluation. Its soft nature handles partial credit and empty annotations robustly.
- **Quick check**: Why is a soft overlap metric (SOFTF1) preferred over exact match for the MBR utility in ESD? What property does it have that exact match lacks?

### Preference Learning Objectives (DPO, KTO)
- **Why needed**: These allow training on relative judgments (E⁺ is better than E⁻) without needing a separate reward model. They are used to train the model to rank the MBR-selected best hypothesis above the worst.
- **Quick check**: What is the key difference in data requirement between DPO and KTO? Why might KTO be applicable even if only E⁺ is available from MBR?

## Architecture Onboarding
**Component map**  
Unlabeled input (x) -> Candidate Generator (samples C candidates from M_θ) -> Candidate Set S -> MBR Scorer (computes scores, selects E⁺ and E⁻) -> Pseudo-label Dataset Constructor -> Training Loop (optimizes M_θ with chosen objective) -> Updated M_θ. Iteration Controller repeats this loop for T cycles.

**Critical path**  
The iterative loop of generate → MBR score → select pseudo-labels → fine-tune → repeat. Each iteration amends the model's weights so that subsequent greedy decoding better matches the MBR optimum.

**Design tradeoffs**
- Diversity vs. quality: High temperature/Top-K improves candidate diversity (better MBR consensus) but increases noise. The paper uses temp=2.0, K=10.
- Iteration depth (T): More iterations allow refinement but risk diversity collapse and performance saturation/decline (observed at T=3). Requires monitoring utility variance.
- Objective choice: SFT is simplest and performed well. DPO/KTO add contrastive signal but require a reference model and may be less stable.
- Utility function: SOFTF1 is robust but assumes span overlap as primary desideratum; alternative utilities could shift MBR optimum.

**Failure signatures**
- Utility variance plateau/decline: Sharp decrease in variance of estimated MBR scores across candidates indicates diminishing returns and potential overfitting, as seen when T=3 performance dropped.
- Degeneration in candidate content: Collapsing diversity (e.g., all candidates become identical or predict only a single error span type) signals failure to maintain useful exploration.
- SPA/SOFTF1 divergence: If span-level (SOFTF1) performance declines while sentence-level (Acc\*eq) remains stable, the model may be losing fine-grained discrimination power.

**First 3 experiments**
1. Baseline MBR Utility Verification: Run static MBR decoding on the base model with C=256 candidates for a small validation set. Verify that the selected E⁺ has statistically higher SOFTF1 against a held-out human reference than greedy/MAP outputs.
2. Single-Iteration Distillation Impact: Perform only T=1 (generate, MBR select, SFT fine-tune). Compare model performance (greedy) against Base Model and a model fine-tuned on the base model's greedy outputs (no MBR). This isolates the value of MBR selection.
3. Preference Objective Comparison: For fixed T=2, compare SFT, DPO, and KTO under identical settings. Measure changes in SOFTF1 and SPA to determine if contrastive learning improves span discrimination.

## Open Questions the Paper Calls Out
1. **Diversity collapse**: Why does candidate diversity decrease during iterative MBR distillation, leading to performance degradation at higher iterations (T≥3), and how can diversity be effectively maintained? The paper reports the drop but does not investigate the underlying cause.
2. **Model capacity**: Does iterative MBR distillation work for base models of varying capacities, and can it effectively bootstrap from weaker or randomly initialized models? All experiments used Qwen3-30B-A3B-Instruct-2507; no ablation over model size or initialization.
3. **Generalization**: How does the approach generalize to language pairs and domains beyond the WMT Metrics Shared Task evaluation sets, particularly for low-resource or typologically diverse languages? Evaluation is restricted to three translation directions; no testing on other pairs or domains.

## Limitations
- The approach relies on unspecified details: exact GEMBA-MQM prompt template and disambiguation (Juraska et al., 2025), precise SOFTF1 utility implementation (Lyu et al., 2025), and techniques to sustain candidate diversity beyond two iterations.
- Performance fragility is evidenced by the drop at T=3 due to candidate diversity collapse and utility variance saturation.
- Generalization is uncertain, especially for low-resource languages or when the base model's initial generation distribution is poorly aligned with true error spans.
