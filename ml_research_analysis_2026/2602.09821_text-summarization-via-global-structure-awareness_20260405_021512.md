# Text summarization via global structure awareness

## Quick Facts
- **arXiv ID:** 2602.09821  
- **Source URL:** https://arxiv.org/abs/2602.09821  
- **Reference count:** 37  
- **Primary result:** GloSA-sum improves ROUGE‑L by up to +2.17 over baselines, achieves human‑evaluated scores of 4.3/5 for coherence and informativeness, and runs 6–8× slower than TextRank but 2–3× faster than BART/PEGASUS.

## Executive Summary
GloSA-sum is an extractive summarization framework that incorporates global document structure using topological data analysis (TDA). It constructs a semantic‑weighted graph from sentence embeddings and applies persistent homology exactly once to identify core semantic clusters (H₀) and logical cycles (H₁), storing them in a Protected Pool. Subsequent compression uses lightweight proxy metrics (TopoScore and TaskScore) guided by this topological backbone, avoiding repeated expensive TDA computations. A hierarchical strategy handles long documents by processing segments in parallel and then applying a final global pass. Evaluated on GovReport, ArXiv, and PubMed, GloSA‑sum achieves state‑of‑the‑art ROUGE‑L improvements (+2.17) and high human ratings (4.3/5) while maintaining a favorable runtime between fast graph methods and costly transformer models.

## Method Summary
GloSA‑sum follows an unsupervised extractive pipeline. First, sentences are encoded using a pretrained model (e.g., `all‑mpnet‑base‑v2`) to obtain L2‑normalized embeddings. A sparse graph is built via mutual k‑nearest neighbors; edge weights combine semantic distance (1 − cosine similarity) and positional decay (`exp(−|i−j|/τ)`). Treating the embeddings as a point cloud, a Lazy Witness Complex is constructed and persistent homology up to dimension 1 is computed. Long‑lived H₀ components (clusters) and H₁ cycles (loops) are extracted; sentences corresponding to landmarks in these features form the Protected Pool. Then, iteratively, non‑protected sentences are scored by a weighted sum of TopoScore (negative sum of shortest‑path lengths to protected nodes) and TaskScore (query relevance, if provided). The lowest‑score sentence is removed until the target compression ratio is reached. For documents longer than ~1000 sentences, a two‑level hierarchical process splits the text into segments, applies the above locally in parallel, concatenates the local summaries, and performs a final global compression.

## Key Results
- ROUGE‑L improvements up to +2.17 over BigBird and BART on GovReport, ArXiv, and PubMed.  
- Human evaluation: 4.3 / 5 for coherence and informativeness.  
- Efficiency: 6–8× slower than TextRank but 2–3× faster than BART/PEGASUS, balancing accuracy and cost.

## Why This Works (Mechanism)

### Mechanism 1: Persistent homology extracts a robust topological backbone
**Claim:** Persistent homology applied once to a semantic‑weighted graph extracts a robust global structural backbone (semantic clusters via H₀, logical cycles via H₁) that persists across scales, distinguishing signal from noise.  
**Mechanism:** Sentences are embedded and connected in a sparse graph using mutual k‑NN with hybrid edge weights (semantic + positional). A Lazy Witness Complex is built on this point cloud. Persistent homology tracks feature “birth/death” across a filtration; long‑lived H₀ features form core themes (dense semantic clusters), while long‑lived H₁ features form logical cycles (recurrent argumentative loops). These are stored in a Protected Pool.  
**Core assumption:** Meaningful discourse structure manifests as topologically persistent features in the high‑dimensional embedding space, and these features remain stable under local sentence removal.  
**Evidence anchors:** [abstract] “constructs a semantic‑weighted graph… applies persistent homology once to identify core semantic clusters (H₀) and logical cycles (H₁)”; [section 3.3–3.4] detailed graph construction and Protected Pool initialization; neighbor papers also explore global context, but GloSA‑sum uniquely uses TDA for a one‑time analysis.  
**Break condition:** When the document’s discourse lacks stable topological features (e.g., thematically scattered news like CNN/DM), both H₀ and H₁ persistence are low, leading to an ineffective/empty Protected Pool (Appendix B.5).

### Mechanism 2: Protected Pool decouples TDA from compression
**Claim:** The Protected Pool mechanism decouples expensive topological analysis from iterative compression, enabling efficient summarization without re‑computing TDA, while preserving the identified backbone.  
**Mechanism:** The one‑time TDA result (P) is fixed. Subsequent iterative sentence deletion uses lightweight proxy scores (TopoScore = shortest‑path sum to P nodes; TaskScore = query relevance). This avoids the prohibitive cost of recomputing persistent homology at each iteration.  
**Core assumption:** The initial topological backbone is a sufficient proxy for global importance throughout compression; local edits do not invalidate the global structure.  
**Evidence anchors:** [abstract] “performs persistent homology only once… subsequent compression uses lightweight proxy metrics… avoiding repeated high‑cost computations”; [section 3.5] formal scoring function `Score(si) = λ·TopoScore + (1−λ)·TaskScore` and iterative deletion; [section 4.5] ablation: removing Protected Pool causes severe degradation (>5 ROUGE drop), confirming its necessity.  
**Break condition:** If the document’s logical flow is highly nonlinear or if key sentences not in P are crucial for downstream tasks (e.g., specific factual details), the topology‑only backbone may miss task‑critical information.

### Mechanism 3: Hierarchical strategy scales to long documents
**Claim:** The hierarchical strategy (segment‑local TDA + global refinement) scales GloSA‑sum to ultra‑long documents while coordinating intra‑segment integrity with inter‑segment coherence.  
**Mechanism:** Long document D is split into T segments. Each segment undergoes independent local GloSA‑sum (graph, TDA, compression) in parallel. The locally compressed segments are concatenated into D′, then a final global compression pass (using same proxy metrics but on D′) removes cross‑segment redundancy.  
**Core assumption:** Local semantic/logical structures can be effectively summarized independently, and a lightweight global pass suffices to reconcile them without full‑document TDA.  
**Evidence anchors:** [abstract] “hierarchical strategy that integrates segment‑level and global summarization”; [section 3.6] two‑level design details and parallelization rationale; [section 4.5] ablation: hierarchical is indispensable for GovReport (long docs) but negligible for CNN/DM (short).  
**Break condition:** If segments are too short or lack coherent internal structure (e.g., very short paragraphs), local TDA may fail to find persistent features, propagating weakness to the global stage.

## Foundational Learning
- **Concept: Persistent Homology (H₀/H₁)**
  - Why needed: Provides the mathematical tool to convert semantic graph into multi‑scale topological signatures; H₀ = themes, H₁ = logical cycles.
  - Quick check question: Given a filtration of a point cloud, what does a long‑lived H₁ bar in the persistence diagram represent?

- **Concept: Semantic Graph Construction (mutual k‑NN + hybrid weights)**
  - Why needed: Transforms variable‑length text into a fixed, sparse graph suitable for TDA; balances semantic proximity with sequential coherence to avoid noisy edges.
  - Quick check question: How does the hybrid weight `wij = α·dsem_ij + (1−α)·exp(−|i−j|/τ)` encode both global and local discourse?

- **Concept: TopoScore (shortest‑path to Protected Pool)**
  - Why needed: Approximates a sentence’s topological importance (connectivity to backbone) without re‑running TDA; enables efficient iterative compression.
  - Quick check question: Why is the TopoScore negative sum of shortest‑path lengths? What does a very negative value indicate?

## Architecture Onboarding
Component map: Sentence Encoder -> Graph Builder -> TDA Analyzer -> Protected Pool Manager -> Iterative Compressor -> Hierarchical Manager

Critical path: For a single document (non‑hierarchical), the flow is: encode sentences -> build graph -> compute persistent homology (once) -> extract Protected Pool -> iterate: compute scores (TopoScore via shortest paths, TaskScore) -> delete lowest‑score non‑protected sentence until target compression met.

Design tradeoffs:
- One‑time TDA vs. Repeated: Saves ~O(M) TDA computations but assumes static backbone.
- Proxy metrics (TopoScore) vs. Exact TDA: Speed vs. precision in importance ranking.
- Hierarchical vs. Flat: Scalability to long docs vs. risk of fragmenting global structure.

Failure signatures:
- Empty/small Protected Pool (check `len(P) << expected`): indicates low persistence → likely poor structure (CNN/DM case).
- Disconnected graph after segment split: local TDA fails → need adjust `k` or segment size.
- High redundancy in final summary: proxy scores misranking → tune λ/β.

First 3 experiments:
1. Validate TDA extraction: On a short, well‑structured doc (e.g., one GovReport section), visualize persistence diagram; confirm H₀/H₁ bars align with human‑identified themes/cycles.
2. Test Protected Pool necessity: Run ablation `w/o Protected Pool` (random or centrality‑based deletion) on GovReport; expect >5 ROUGE‑L drop.
3. Benchmark efficiency: Measure runtime vs. TextRank/BART on a 10k‑sentence synthetic doc; expect 6–8× slower than TextRank but 2–3× faster than BART/PEGASUS.

## Open Questions the Paper Calls Out
- Does GloSA‑sum’s summarization quality generalize across downstream tasks beyond QA? The paper only evaluates on SQuAD 2.0 QA, leaving generalizability unknown.
- For which document genres does TDA fail to identify a stable backbone? The paper notes failure on CNN/DM but lacks systematic analysis and mitigation strategies.
- What is the optimal segmentation criterion for hierarchical compression? The paper uses arbitrary splits (natural boundaries or fixed length) without comparison.
- Could higher‑dimensional topological features (e.g., H₂) improve summarization? The paper dismisses H₂ as irrelevant for sequence‑like data without empirical validation.

## Limitations
- TDA implementation details (Lazy Witness Complex parameters, landmark ratio, max edge length) and many hyperparameters (α, τ, λ, K, M) are unspecified, hindering exact reproduction.
- The TopoScore formula appears to have a discrepancy between Section 3.5 (shortest‑path sum) and Appendix (persistence gain + bridge centrality), creating ambiguity.
- One‑time TDA assumption may break if compression significantly alters the global structure, and hierarchical segmentation can break cross‑segment logical cycles.

## Confidence
- Persistent homology backbone: **High** (validated on long structured docs), **Medium** (general domains due to break condition).  
- Protected Pool necessity: **High** (ablation shows >5 ROUGE‑L drop).  
- Hierarchical scaling: **High** for long docs; **Low** for short texts.
