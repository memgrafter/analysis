# UETQuintet at BioCreative IX -- MedHopQA: Enhancing Biomedical QA with Selective Multi-hop Reasoning and Contextual Retrieval

## Quick Facts
- arXiv ID: 2601.06974
- Source URL: https://arxiv.org/abs/2601.06974
- Reference count: 16
- Primary result: Achieved Exact Match 0.84 and Concept Level Score 0.863, ranking second on the BioCreative IX MedHopQA leaderboard.

## Executive Summary
The UETQuintet system tackles the challenge of multi-hop reasoning in biomedical question answering (BioCreative IX MedHopQA). It classifies questions as either direct (answerable in one hop) or sequential (requiring stepwise decomposition) using a stacking ensemble model. Sequential questions are decomposed into sub-questions; each hop retrieves context from search engine snippets and Wikipedia sentences, generates an answer, and uses it as an anchor for the next hop. Direct questions are processed without decomposition. Final answers are normalized to Wikipedia page titles to align with standard biomedical concepts. This selective approach aims to avoid hallucination from unnecessary decomposition while enabling complex reasoning.

On the MedHopQA test set, the system achieved an Exact Match score of 0.84 and a Concept Level Score of 0.863, securing second place on the competition leaderboard. The results demonstrate the effectiveness of combining selective decomposition, multi-source retrieval, and normalization for biomedical QA.

## Method Summary
The pipeline begins with question simplification and feature extraction (linguistic, structural, embedding). A stacking classifier—Random Forest and XGBoost as base learners with Logistic Regression as meta-learner—is trained on 453 annotated samples to predict whether a question is direct or sequential. For sequential questions, an LLM decomposes them into a chain of sub-questions, sub-queries, and initial anchor entities. The system then iterates over hops: for each, it retrieves the top 10 search snippets and the top *m* TF-IDF-similar Wikipedia sentences (combined as context), and generates an answer using an LLM prompted with the current sub-question, previous anchor, and retrieved context. The generated answer becomes the anchor for the next hop. Direct questions skip decomposition and are answered in a single step. Finally, the short answer is normalized by mapping it to a Wikipedia page title via the Wikipedia API. Distinct LLMs (e.g., gpt-4o-mini, gpt-o3-mini) may be used for decomposition and answer generation.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Classifying questions as *direct* or *sequential* prevents inappropriate decomposition, improving efficiency and accuracy.
- **Mechanism:** A stacking ensemble model (Random Forest + XGBoost meta-classified by Logistic Regression) uses linguistic, structural, and embedding features to label questions. Sequential questions undergo LLM-based decomposition into sub-questions; direct questions skip this step.
- **Core assumption:** Decomposing direct questions introduces hallucination risks or unnecessary complexity. The classifier’s accuracy (reported F1 0.83) is sufficient to separate the two classes.
- **Evidence anchors:**
  - [abstract] "sequential questions are decomposed into a chain of sub-questions... direct questions are processed directly."
  - [section 3.1] Details the feature extraction, stacking architecture (Eq. 1–2), and motivation: "using LLMs for question decomposition can lead to irrelevant sub-questions due to hallucination."
  - [corpus] Neighbor papers (e.g., "To Reason or Not to: Selective Chain-of-Thought") explore similar selective reasoning, providing indirect support for the approach’s premise.
- **Break condition:** If the classifier’s F1 drops significantly (e.g., <0.75) on biomedical data, or if decomposition of *some* direct questions is later found beneficial, the classification strategy may need re-evaluation.

### Mechanism 2
- **Claim:** Iterative answer generation with *anchor propagation* enables step-by-step multi-hop reasoning by using each sub-answer as context for the next hop.
- **Mechanism:** For a sequential question with *n* hops, at hop *i*, the LLM generates an answer *a'ᵢ* using sub-question *Qᵢ*, sub-query *qᵢ*, previous anchor *aᵢ₋₁*, and retrieved context *Cᵢ*. *a'ᵢ* becomes the anchor for hop *i+1* (or final answer if last hop).
- **Core assumption:** Each hop’s answer is a correct and sufficiently precise "anchor" for the next reasoning step. Errors propagate if an early anchor is wrong.
- **Evidence anchors:**
  - [abstract] "sequential questions are decomposed into a chain of sub-questions to perform reasoning across a chain of steps."
  - [section 3.2] "The model iteratively answers each hop, using the previous answer as the anchor for the next." Figure 1b visualizes this loop.
  - [section 4.2] Setting LLM temperature to 0 suggests reliance on deterministic anchor flow.
- **Break condition:** If a significant portion of errors stem from inconsistent anchor values (e.g., entity mismatches between hops), the anchoring method may need validation or correction (e.g., entity linking).

### Mechanism 3
- **Claim:** Multi-source retrieval (search engine snippets + Wikipedia sentences via TF-IDF) and Wikipedia-based answer normalization jointly improve answer fidelity to biomedical concepts.
- **Mechanism:** Retrieval combines search engine snippets *{sⱼ}* with top-*m* TF-IDF-selected Wikipedia sentences *{kⱼ}* as context *Cᵢ*. Final short answers are normalized by mapping *a'ᵢ* to Wikipedia page headings via API, aligning with standard biomedical terminology.
- **Core assumption:** Wikipedia headings provide authoritative normalization for biomedical entities, and TF-IDF effectively selects salient sentences from the crawled corpus.
- **Evidence anchors:**
  - [section 3.2] Defines *Cᵢ* as combination of snippets and Wikipedia sentences. Describes TF-IDF vectorization and cosine similarity for sentence selection.
  - [section 3.2] "We implement a normalization step based on Wikipedia. For each short answer... we extract the page’s heading title."
  - [section 4.3] Runs 2–5 show incremental gains from adding Wikipedia retrieval (Run 2,4) and normalization (Run 3), supporting their individual contributions.
- **Break condition:** If Wikipedia’s biomedical coverage is insufficient for the domain, or if TF-IDF fails to select contextually relevant sentences (e.g., due to term mismatch), performance may plateau or degrade.

## Foundational Learning
- **Concept: Multi-hop reasoning**  
  *Why needed here:* Biomedical questions often require chaining facts (e.g., gene → chromosome). The system explicitly decomposes and propagates information across hops.  
  *Quick check question:* For "Which chromosome contains the gene most commonly associated with hereditary hemochromatosis?", what are the minimal sub-questions? (Answer should identify gene first, then chromosome.)

- **Concept: Retrieval-Augmented Generation (RAG)**  
  *Why needed here:* LLMs lack up-to-date, specialized biomedical knowledge. The system retrieves external snippets and Wikipedia articles to ground answer generation.  
  *Quick check question:* Why not rely solely on the LLM’s pre-trained knowledge for biomedical QA? (Answer: Pre-training cutoffs and domain specificity limit coverage; retrieval provides current, targeted evidence.)

- **Concept: Stacking ensemble for classification**  
  *Why needed here:* Question-type classification is a critical, error-sensitive decision point. A stacking model aims for higher robustness than a single classifier.  
  *Quick check question:* What are the base learners and meta-learner in the stacking model? (Answer: RF and XGBoost as base; Logistic Regression as meta-classifier.)

## Architecture Onboarding
- **Component map:**  
  `Input → Question Simplification → Feature Extraction → Stacking Classifier → [If sequential: Decomposition (LLM) → Hop Loop (Retrieval → Answer Gen → Anchor update); If direct: Single Answer Gen] → Answer Normalization → Output`

- **Critical path:**  
  The classification decision (sequential vs. direct) is the first branch point. For sequential questions, the decomposition quality and anchor propagation through hops form the longest dependency chain.

- **Design tradeoffs:**
  - *Classification overhead vs. decomposition risk:* Training a classifier adds complexity but avoids LLM hallucination on direct questions.
  - *Retrieval source richness vs. noise:* Combining search snippets and Wikipedia increases coverage but may introduce irrelevant context.
  - *Normalization precision vs. fallback:* Wikipedia heading matching is strict; failures lead to unnormalized answers, potentially hurting Exact Match.

- **Failure signatures:**
  - Low classifier F1 (<0.8) → many sequential questions misrouted as direct (unanswered multi-hop) or direct questions unnecessarily decomposed (hallucinated sub-questions).
  - Low-quality retrieval context (e.g., snippets unrelated to sub-query) → LLM generates answers unsupported by evidence.
  - Normalization fails (no Wikipedia page found) → exact match drops even if concept is correct.
  - Anchor drift: Sub-answer *a'ᵢ* changes entity form (e.g., "HFE gene" → "HFE") causing next-hop retrieval to miss key terms.

- **First 3 experiments (as per paper's Run 1–5 progression):**
  1. **Baseline:** Use only search engine snippets, no Wikipedia retrieval, no normalization. Establishes core retrieval+generation performance.
  2. **Add Wikipedia-based retrieval for yes/no questions only:** Tests if Wikipedia context helps a specific question type. Isolates Wikipedia’s contribution.
  3. **Add Wikipedia-based normalization:** Apply normalization to outputs from Experiment 2. Measures if heading mapping improves exact match.

## Open Questions the Paper Calls Out
- **Open Question 1**  
  - *Question:* How well does the lightweight stacking ensemble for classifying sequential vs. direct questions generalize to diverse, unseen biomedical question distributions beyond the 453 human-annotated samples?  
  - *Basis in paper:* [inferred] The classification model was trained on only 453 samples and evaluated solely on the competition test set, with no assessment of performance on external or more varied biomedical QA datasets.  
  - *Why unresolved:* The small, task-specific training data may not capture the full spectrum of linguistic and structural variations in biomedical questions, risking overfitting and limited applicability to real-world settings.  
  - *What evidence would resolve it:* Evaluate the classifier on multiple large-scale, publicly available biomedical QA datasets (e.g., PubMedQA, BioASQ) with different question styles and topics, measuring accuracy and F1-score to confirm robustness.

- **Open Question 2**  
  - *Question:* To what extent do errors in LLM-generated sub-questions propagate and degrade final answer accuracy in multi-hop sequential reasoning?  
  - *Basis in paper:* [inferred] The framework relies on LLM decomposition for sequential questions but cites hallucination risks; no error analysis links sub-question quality to final EM/Concept scores.  
  - *Why unresolved:* Without quantifying decomposition fidelity (e.g., via human evaluation of sub-questions), it is unclear whether performance gains stem from correct reasoning chains or compensatory retrieval/LLM strengths masking decomposition flaws.  
  - *What evidence would resolve it:* Conduct a manual audit of sub-questions for a random sample of sequential queries, categorize error types (irrelevant, missing dependencies), and correlate these with final answer correctness to measure propagation impact.

- **Open Question 3**  
  - *Question:* Do advanced dense retrieval methods (e.g., bi-encoder models with biomedical embeddings) outperform the TF-IDF and search engine snippet approach for retrieving relevant biomedical context?  
  - *Basis in paper:* [inferred] The retrieval phase uses traditional TF-IDF cosine similarity on Wikipedia sentences and search snippets, with no comparison to modern neural retrievers that capture semantic nuances.  
  - *Why unresolved:* Biomedical text involves complex terminology and relations; TF-IDF’s lexical matching may miss contextually relevant passages, potentially limiting answer generation quality.  
  - *What evidence would resolve it:* Replace the TF-IDF component with a dense retriever (e.g., using BioBERT or PubMedBERT embeddings) in a controlled ablation study, comparing retrieval recall@k and downstream QA metrics (EM, Concept Score) on the same dataset.

- **Open Question 4**  
  - *Question:* How does the choice of LLM (size, architecture, biomedical fine-tuning) affect multi-hop reasoning fidelity and answer normalization in biomedical QA?  
  - *Basis in paper:* [inferred] The system uses gpt-4o-mini and gpt-o3-mini, with a one-off test of gpt-4o-search-preview; no systematic study compares LLM variants or explores trade-offs between cost, speed, and accuracy.  
  - *Why unresolved:* Different LLMs vary in biomedical knowledge, reasoning depth, and instruction adherence; the optimal model for decomposition vs. answer generation remains unknown, and normalization reliance on Wikipedia may interact with LLM capabilities.  
  - *What evidence would resolve it:* Run the full pipeline with multiple LLMs (e.g., open-source biomedical models like BioMedLM, various GPT versions) under identical conditions, analyzing performance breakdowns per question type and normalization success rates to identify optimal configurations.

## Limitations
- Prompt templates for decomposition and answer generation are omitted (replaced with `(...)`), hindering exact replication.
- Classifier feature set and the 453 annotated samples are not publicly available; this obscures whether the stacking model generalizes.
- Retrieval parameters (e.g., snippet count, TF-IDF settings) and token limits are underspecified, risking implementation drift.
- No ablation studies isolating classification errors, anchor propagation failures, or normalization coverage are provided, leaving the relative contribution of each component uncertain.
- Performance depends on specific LLMs (e.g., gpt-4o-mini); cross-model robustness is unknown.

## Confidence
- *Selective classification avoids inappropriate decomposition*: **Medium**. Reported F1=0.83 suggests reasonable accuracy, but feature details and full error impact are missing.
- *Iterative anchor propagation enables stepwise reasoning*: **Medium**. The mechanism is described and used, but no direct evidence that anchors improve correctness over alternatives.
- *Multi-source retrieval + Wikipedia normalization boosts fidelity*: **High**. Ablation runs (2–5) show clear incremental gains, strongly supporting the claim.

## Next Checks
1. **Classifier replication**: Obtain or reconstruct the 453-sample dataset and feature pipeline; train the stacking model and verify F1 ≥0.80 on a held-out set.
2. **Anchor drift analysis**: For a random subset of sequential questions, automatically trace entity mentions across hops; quantify inconsistency rates and correlate with final answer correctness.
3. **Normalization coverage audit**: Sample 200 biomedical entities from MedHopQA; test Wikipedia title mapping success rate and measure how failures affect Exact Match in the pipeline.
