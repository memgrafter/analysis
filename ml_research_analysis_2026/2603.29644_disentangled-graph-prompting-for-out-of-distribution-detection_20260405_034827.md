# Disentangled Graph Prompting for Out-Of-Distribution Detection

## Quick Facts
- **ArXiv ID**: 2603.29644
- **Source URL**: https://arxiv.org/abs/2603.29644
- **Reference count**: 40
- **Primary result**: On ten datasets, DGP achieves an average relative AUC improvement of 3.63% over the best baseline (SEGO), reduces FPR95 by 46.25% on average, and cuts training time by up to 64×, while remaining compatible with diverse pre‑trained GNN encoders.

## Executive Summary
The paper introduces Disentangled Graph Prompting (DGP), a method for graph out‑of‑distribution (OOD) detection when OOD data is unavailable during training. DGP follows a pre‑training+prompting paradigm: it freezes a pre‑trained graph neural network (GNN) encoder and learns to generate two prompt graphs by modifying edge weights—one class‑specific guided by ID labels and one class‑agnostic. Effective losses supervise these generators and prevent trivial solutions. Extensive experiments on ten datasets show DGP significantly outperforms the strongest baseline (SEGO) in AUC and FPR95, while also offering substantial training speed gains. The approach demonstrates flexibility across different pre‑trained encoders and suggests a promising direction for test‑time adaptation in graph OOD detection.

## Method Summary
DGP operates on a frozen GNN encoder pre‑trained on in‑distribution (ID) graphs. For a given input graph, two MLP‑based generators produce adjacency matrices \(A^{(1)}\) (class‑specific) and \(A^{(2)}\) (class‑agnostic) by weighting existing edges based on node embeddings from the encoder. These prompted graphs are re‑encoded by the same frozen GNN to obtain graph‑level representations \(h^{(1)}\) and \(h^{(2)}\). A predictor MLP maps these representations to class logits, producing probabilities \(z^{(1)}\) and \(z^{(2)}\). Training uses three losses: (i) class‑specific cross‑entropy between \(z^{(1)}\) and true ID labels, encouraging preservation of discriminative edges; (ii) class‑agnostic cross‑entropy between \(z^{(2)}\) and a uniform distribution, encouraging capture of edges common to all classes; (iii) distance regularization that pushes \(h^{(1)}\) and \(h^{(2)}\) away from the original graph representation via Mahalanobis distance (implemented as \(\alpha_1/L_{\text{distance‑1}} + \alpha_2/L_{\text{distance‑2}}\)). Generators and predictor are trained via alternating gradient steps. At test time, the predictor is discarded and the OOD score is computed as \(S(G) = \text{MD}(h^{(1)}) + \gamma \cdot \text{MD}(h^{(2)})\). The method requires only ID data and a pre‑trained encoder.

## Key Results
- Average relative AUC improvement of 3.63% over the best baseline (SEGO) across ten datasets.
- Average reduction in FPR95 by 46.25%, indicating fewer false alarms at a fixed true positive rate.
- Training time reduction up to 64× compared to some baselines, while maintaining competitive performance with various pre‑trained encoders.

## Why This Works (Mechanism)

### 1. Frozen Encoder with Edge‑Weight Prompting
The pre‑trained GNN encoder is kept frozen while learnable prompt graphs are generated by modifying edge weights. For an input graph \(G\), two separate MLP‑based generators produce class‑specific (\(\phi_1\)) and class‑agnostic (\(\phi_2\)) adjacency matrices \(A^{(1)}, A^{(2)}\) by computing edge weights from node embeddings \(a_i, a_j\): \(A_{ij}^{(*)} = \text{MLP}(\text{CONCAT}(a_i, a_j); \Omega_{(*)})\). These prompt graphs are fed into the frozen encoder, yielding representations \(h^{(1)}, h^{(2)}\). This allows the encoder to adapt to the OOD task without retraining its parameters. Core assumption: the pre‑trained encoder already captures useful graph representations; only the input topology needs adjustment. Evidence: abstract and section 4.2 explicitly describe frozen encoders and edge‑weight adjustment; neighbor papers also explore test‑time adaptation.

### 2. Disentanglement via Dual‑Branch Supervision
Disentanglement losses supervise the two prompt generators to capture complementary ID patterns: the class‑specific branch \(\phi_1\) is encouraged to preserve discriminative subgraphs via cross‑entropy with true labels; the class‑agnostic branch \(\phi_2\) is encouraged to amplify edges common to all ID classes via cross‑entropy with a uniform label distribution. A predictor MLP produces \(z^{(1)}, z^{(2)}\). Mathematically, \(\mathcal{L}_{\text{class‑specific}} = \text{CE}(y, \log z^{(1)})\) and \(\mathcal{L}_{\text{class‑agnostic}} = \text{CE}(\bar{y}, z^{(2)})\). The assumption is that ID class labels provide supervision to separate class‑specific from class‑agnostic factors, both informative for OOD detection because OOD graphs lack either. Evidence: abstract, section 4.3.1–4.3.2; related work uses label‑guided generation but DGP’s contrastive loss design is novel.

### 3. Distance Regularization to Prevent Trivial Solutions
To avoid degenerate prompts (e.g., identity or all‑edges), distance losses based on Mahalanobis distance push prompt representations away from the original graph representation. For each prompt representation \(h^{(*)}\), compute \(\mathcal{L}_{\text{distance‑*}} = \text{MD}(h^{(*)})\), where \(\text{MD}(\cdot)\) is the inverse Mahalanobis distance to the ID cluster center computed from original representations. The total distance loss \(\mathcal{L}_{\text{dis}} = \alpha_1 / \mathcal{L}_{\text{distance‑1}} + \alpha_2 / \mathcal{L}_{\text{distance‑2}}}\) is minimized together with the disentanglement losses. Core assumption: the original graph is a neutral starting point; useful prompts should deviate meaningfully. Evidence: section 4.3.3 and ablation in 4.4.3 confirm the regularization’s role. Break conditions include extreme hyperparameter values.

## Architecture Onboarding
**Component map**  
Pre‑trained GNN Encoder → Prompt Generators (ϕ₁, ϕ₂) → Re‑encode (frozen GNN) → Predictor → Losses. At test time: Prompt Generators → Re‑encode → Mahalanobis scoring.

**Critical path**  
1. Input graph G is encoded once with frozen GNN to obtain node embeddings a_i.  
2. Generators ϕ₁, ϕ₂ compute prompt adjacency matrices A^{(1)}, A^{(2)} from a_i.  
3. The frozen GNN re‑encodes A^{(1)} and A^{(2)} to produce pooled graph representations h^{(1)}, h^{(2)}.  
4. Predictor maps h^{(1)} and h^{(2)} to class probabilities z^{(1)}, z^{(2)}.  
5. Disentanglement loss: L_class‑specific = CE(y, log z^{(1)}) and L_class‑agnostic = CE(ȳ, z^{(2)}).  
6. Distance loss: compute Mahalanobis distance MD(h) relative to ID statistics; L_dis = α₁/L_distance‑1 + α₂/L_distance‑2.  
7. Alternating gradient updates: first minimize L_disentangle (update ϕ₁, ϕ₂, predictor); then minimize L_dis (update ϕ₁, ϕ₂ while fixing predictor).  
8. After training, discard predictor; for a test graph, compute S(G) = MD(h^{(1)}) + γ·MD(h^{(2)}).

**Design tradeoffs**  
- Frozen encoder vs. prompt expressivity: Freezing ensures efficiency and leverages pre‑training but limits adaptation; if pre‑training is poor, performance caps.
- Dual branches vs. complexity: Two generators add computation but capture complementary patterns; ablations show both are needed.
- Mahalanobis clustering: Assumes ID data forms a single (or few) clusters; may fail for multi‑modal ID distributions.

**Failure signatures**  
- Trivial prompts: generators output adjacency nearly identical to original or constant; detected by very low distance loss. Remedy: increase α₁,α₂.
- Training divergence (NaN): due to unstable MD computation or large learning rates; remedy: gradient clipping, lower LR, add ridge to covariance.
- Poor OOD discrimination: validate that class‑specific predictor attains reasonable accuracy; check MD statistics calculated on original graphs; adjust λ,γ.
- Over‑regularization: too high α leads to unrealistic prompts and AUC drop.

**First 3 experiments**  
1. **Ablation study** (Fig 4a): Removing either class‑specific or class‑agnostic branch or distance loss degrades performance, confirming each component’s contribution.
2. **Encoder initialization analysis** (Fig 4b): Comparing random vs. pre‑trained (GCL/SimGRACE) encoders shows pre‑training is essential for DGP’s gains.
3. **Hyperparameter sensitivity** (Fig 5): Sweeping λ, γ, and α reveals dataset‑dependent preferences (e.g., BZR favors class‑agnostic, PTC favors class‑specific) but generally stable within reported ranges.

## Open Questions the Paper Calls Out
- How can DGP’s prompt generation be extended to heterogeneous, temporal, or extremely large graphs?
- What theoretical guarantees exist for the disentanglement of class‑specific and class‑agnostic patterns in improving OOD detection performance?
- How does DGP’s effectiveness vary with different pre‑training objectives beyond contrastive learning (e.g., GraphMAE, supervised)?
- Can DGP be adapted to scenarios with limited or noisy ID labels, reducing its reliance on clean label information?
- What are the computational limits of DGP for very large graphs, and can approximate prompting (e.g., on subgraphs) maintain performance?

## Limitations
- **Distance loss formulation ambiguity**: The use of α / mean(MD) may invert intended regularization, risking optimization of the opposite objective.
- **Under‑specified Mahalanobis implementation**: Covariance structure (diagonal vs. full) and clustering details are missing, potentially causing instability and reproducibility issues.
- **Dependence on high‑quality pre‑trained encoders**: If the frozen encoder is poorly initialized or mismatched to the target domain, DGP cannot recover useful signals. Pre‑training hyperparameters are not fully reported.

## Next Checks
1. **Resolve L_dis sign**: Empirically test whether decreasing L_dis increases or decreases the Mahalanobis distance of prompt representations. If MD decreases (more ID‑like), revise the loss to -α·mean(MD) and measure impact on OOD AUC.
2. **Covariance structure ablation**: On a subset of datasets, compare diagonal vs. full covariance (with ridge) for Σ. Monitor condition number of Σ and OOD metrics (AUC, FPR95) to assess stability.
3. **Edge weight distribution analysis**: After training, compute statistics (min, max, variance) of generated edge weights from both generators. If weights are extreme or uniform, apply a sigmoid/softplus activation and re‑evaluate on a validation set to gauge effect.
