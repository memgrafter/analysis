# Agent-Dice: Disentangling Knowledge Updates via Geometric Consensus for Agent Continual Learning

## Quick Facts
- arXiv ID: 2601.03641
- Source URL: https://arxiv.org/abs/2601.03641
- Reference count: 40
- Primary result: Agent-Dice achieves the highest average Z-score (AvgZ) across GUI and tool-use agent continual learning benchmarks, significantly outperforming sequential fine-tuning and other baselines.

## Executive Summary
Agent-Dice addresses catastrophic forgetting in LLM-based agent continual learning by disentangling shared knowledge from task-specific interference. It operates post-hoc on task vectors (differences from a pre-trained model) via a two-stage fusion: geometric consensus filtering prunes conflicting updates by majority sign vote, and curvature-based importance weighting amplifies salient parameters via a masked Softmax on magnitudes. Evaluations on GUI (OS-Atlas-Pro-7B, Qwen3-VL-8B) and tool-use (Qwen3-8B, Llama-3.1-8B) agents show state-of-the-art performance with minimal overhead.

## Method Summary
Given a pre-trained model θ_pre and K fine-tuned models {θ_k} from separate tasks, Agent-Dice first computes task vectors τ_k = θ_k - θ_pre. The fusion proceeds element-wise: for each parameter i, an active set S_i is built by majority vote on sign(τ_k,i); τ_k,i for k ∉ S_i are zeroed. Within S_i, weights w_k,i = exp(|τ_k,i|) / Σ_{j∈S_i} exp(|τ_j,i|) are assigned via Softmax on absolute magnitudes. The fused update is Δθ_i = Σ_k w_k,i * τ_k,i, yielding θ_fused = θ_pre + Δθ. This avoids retraining and balances stability (filtering) and plasticity (weighting).

## Key Results
- Agent-Dice attains the highest average Z-score (AvgZ) across all tested continual learning scenarios; e.g., on OS-Atlas-Pro-7B, AvgZ=0.73 vs. 0.14 for the best baseline.
- Ablation studies confirm both the geometric consensus filtering and curvature-based weighting stages are essential for performance.
- Computational overhead is low, averaging ~77 seconds on GPU, making it practical for typical model sizes.

## Why This Works (Mechanism)
### Mechanism 1: Geometric Consensus Filtering for Stability
- **Claim:** Prunes conflicting gradient updates to preserve stability.
- **Mechanism:** For each parameter, a majority vote on the sign of task vectors determines an active set; only tasks with majority-aligned signs contribute to the final update.
- **Core assumption:** A true descent direction exists and independent tasks align with it with probability >0.5.
- **Evidence:** Theorem 2 shows exponential error decay via Hoeffding's inequality; filtering excludes outlier tasks.

### Mechanism 2: Curvature-Based Importance Weighting for Plasticity
- **Claim:** Amplifies shared, high-saliency parameters to enhance plasticity.
- **Mechanism:** Within the consensus set, a masked Softmax on absolute magnitudes |τ_k,i| assigns higher weights to parameters with larger updates, interpreted as higher local curvature.
- **Core assumption:** Parameter update magnitude correlates with local loss sensitivity and saliency of shared knowledge.
- **Evidence:** Theorem 3 derives that under a saliency constraint, the maximum entropy solution is a Boltzmann distribution (Softmax).

### Mechanism 3: Two-Stage Disentanglement
- **Claim:** Sequential filtering then reweighting disentangles common from conflicting knowledge, balancing stability and plasticity.
- **Mechanism:** First, sign consensus ensures the fused update follows a majority direction (stability). Second, magnitude weighting adapts step size per parameter (plasticity).
- **Core assumption:** The pre-trained model lies in a linear mode connectivity basin, enabling valid linear aggregation of task vectors.
- **Evidence:** Theorem 1 shows fused update approximates one gradient step on a surrogate multi-task loss; experiments show highest AvgZ; ablations demonstrate necessity of both stages.

## Foundational Learning
- **Task vectors**: Displacement vectors τ_k = θ_k - θ_pre representing parameter changes from fine-tuning on task k. *Why needed*: Agent-Dice operates element-wise on these to fuse updates. *Quick check*: How does the sign of a task vector component relate to the gradient direction during fine-tuning?
- **Catastrophic forgetting**: The tendency of sequential fine-tuning to lose performance on earlier tasks when learning new ones. *Why needed*: This is the stability-plasticity dilemma Agent-Dice addresses. *Quick check*: Why does sequential fine-tuning typically cause forgetting in LLM agents?
- **Linear mode connectivity**: The property that models fine-tuned on different tasks can be interpolated linearly without loss increase. *Why needed*: Justifies that linear combinations of task vectors approximate joint multi-task optimization. *Quick check*: What does it mean for a pre-trained model to lie in a "linear mode connectivity basin"?

## Architecture Onboarding
**Component map:**
Pre-trained model θ_pre and fine-tuned checkpoints {θ_k} → Compute task vectors τ_k → Element-wise sign voting to build active sets S_i → Masked Softmax on |τ_k,i| within S_i to get weights w_k,i → Weighted sum Δθ_i = Σ_k w_k,i * τ_k,i → Fused model θ_fused = θ_pre + Δθ.

**Critical path:**
1. Extract task vectors from all fine-tuned checkpoints.
2. For each parameter i, compute majority sign → binary mask (active set).
3. For parameters with active tasks, compute element-wise Softmax on magnitudes to assign weights.
4. Aggregate weighted task vectors into Δθ.
5. Add Δθ to pre-trained model.

**Design tradeoffs:**
- Consensus threshold δ: Default K/2 (strict majority). Lower δ increases plasticity but risks outlier inclusion; higher δ improves stability but may prune useful updates.
- Softmax temperature: Implicit β=1; scaling magnitudes could adjust weighting sharpness.
- Granularity: Element-wise vs. layer-wise; element-wise more precise but noisier.

**Failure signatures:**
- Many parameters have small margins in sign vote (|V_i - K/2| ≈ 0) → active sets either empty or full, reducing filtering effect.
- One task dominates magnitude distribution → Softmax assigns near-zero weight to others, losing diversity.
- Post-fusion KL divergence to pre-trained similar to sequential fine-tuning → fusion not reducing drift.

**First 3 experiments:**
1. Ablation: Remove Stage 1 (sign voting) and Stage 2 (Softmax) separately; expect performance collapse.
2. Model similarity: Compute KL divergence between fused model and individual task models; expect fused closer to base than sequentially trained models.
3. Overhead: Measure fusion time on GPU/CPU; expect ~77s avg on GPU, negligible vs. full training.

## Open Questions the Paper Calls Out
1. **Generalization to other agent domains**: Does Agent-Dice work for robotics, game-playing, or multi-modal reasoning agents beyond GUI and tool-use? *Basis*: Limitations section acknowledges evaluation on limited scenarios. *Why unresolved*: Generalization unproven. *Resolving evidence*: Apply to diverse agent benchmarks.
2. **Robustness of linear mode connectivity assumption**: How valid is Theorem 1's linearity assumption for highly dissimilar sequential tasks? *Basis*: Theoretical reliance on linear basin. *Why unresolved*: No empirical measurement of interpolation loss. *Resolving evidence*: Measure linear path loss between pre-trained/task models and fused model.
3. **Optimal consensus threshold δ**: How does δ relate to error probability when p (sign-flip probability) is unknown or varies? *Basis*: δ fixed at K/2; no sensitivity analysis. *Why unresolved*: May discard correct directions if p ≤ 0.5. *Resolving evidence*: Theoretical derivation of δ as function of p; empirical sweep of δ and trade-off analysis.
4. **Curvature weighting vs. noise amplification**: Does magnitude-based Softmax truly reflect salience, or amplify noisy updates? *Basis*: Theorem 3 proxies salience with |τ_k,i|. *Why unresolved*: No validation that large |τ_k,i| corresponds to retention-important parameters. *Resolving evidence*: Compare Softmax against alternatives (uniform, other exponents) and correlate with Fisher information or gradient variance.
5. **Scalability overhead**: How does fusion cost scale with number of tasks K and model size d? *Basis*: Overhead measured only for small K and 7B-8B models. *Why unresolved*: No scaling analysis for large K or d (e.g., 70B+). *Resolving evidence*: Empirical scaling experiments varying K and d, measure time and memory.

## Limitations
- Theoretical assumptions (linear mode connectivity, p>0.5, magnitude=curvature) lack empirical validation for large LLM agents.
- Reproduction details are ambiguous: Softmax temperature β, exact θ_pre definition, handling of non-linear parameters, and fusion protocol for baselines.
- Fixed consensus threshold δ=K/2 may be brittle for highly conflicting tasks; no sensitivity analysis provided.

2. **Saliency proxy correlation**: Compute per-parameter Fisher information or gradient variance across tasks; test correlation with |τ_k,i| to validate curvature assumption.
3. **Threshold sensitivity sweep**: Vary consensus threshold δ across a wide range (e.g., 0.3K to 0.7K) and evaluate AvgZ to assess robustness and optimal operating point.
