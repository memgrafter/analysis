# Rodent-Bench

## Quick Facts
- **arXiv ID:** 2602.18540
- **Source URL:** https://arxiv.org/abs/2602.18540
- **Reference count:** 40
- **Primary result:** None of the evaluated MLLMs (Gemini-2.5-Pro, Gemini-2.5-Flash, Qwen-VL-Max) achieve performance sufficient for practical use in rodent behavior annotation; best model weighted MCC only 0.199 on Long benchmark.

## Executive Summary
Rodent-Bench introduces a benchmark to assess whether state-of-the-art Multimodal Large Language Models (MLLMs) can automatically annotate rodent behaviors from long videos—a task that is currently manual and time‑consuming. The benchmark comprises six diverse datasets (social interactions, grooming, scratching, freezing) with videos lasting 10–35 minutes, and requires models to output structured JSON segments with precise start/end times. Evaluated on Gemini-2.5-Pro, Gemini-2.5-Flash, and Qwen-VL-Max under zero‑shot conditions, the models perform poorly across all metrics (MCC, mAP, accuracy). The best model, Gemini-2.5-Pro, reaches a weighted MCC of 0.199 on the Long benchmark and only modest accuracy (~0.68) on grooming detection. The paper identifies key challenges in temporal segmentation, distinguishing subtle behaviors, handling extended sequences, and producing consistent JSON outputs, suggesting that current MLLMs lack the necessary capabilities for this specialized scientific annotation task.

## Method Summary
Rodent-Bench evaluates MLLMs on converting raw video into temporally segmented behavior annotations. The benchmark aggregates six existing datasets covering various rodent behaviors, with video durations ranging from 1 to 35 minutes. Two versions are provided: Short (≤10 minutes) and Long (≤35 minutes). Models are prompted with dataset‑specific instructions that define the target behaviors and require output in a strict JSON format containing non‑overlapping segments (`segment_number`, `start_time`, `end_time`, `behavior`). Three top MLLMs are tested: Gemini-2.5-Pro and Gemini-2.5-Flash (which accept native video) and Qwen-VL-Max (which processes frames extracted every 0.5 seconds). All inference is zero‑shot, with no fine‑tuning or prompt optimization beyond the provided templates. Performance is measured using second‑wise accuracy, macro F1, mean average precision (mAP) over IoU thresholds, mutual information, and Matthew’s correlation coefficient (MCC). The evaluation pipeline includes video ingestion, prompt generation, API calls to the models, output parsing and validation, and metric computation against ground‑truth segmentations.

## Key Results
- **Inadequate performance:** No model achieved practical utility; the best result (Gemini-2.5-Pro) obtained a weighted MCC of 0.199 on the Long benchmark.
- **Behavior‑specific success only:** Grooming detection—a high‑motion behavior—was the only scenario where accuracy approached acceptable levels (~0.68 second‑wise for Gemini-2.5-Pro); other behaviors like freezing performed near chance.
- **Systematic failures:** All models struggled with temporal segmentation (malformed JSON, boundary errors), subtle state discrimination (e.g., freezing vs. resting), and maintaining consistency across long videos, indicating fundamental limitations.

## Why This Works (Mechanism)
### Mechanism 1: Temporal segmentation exposes lack of structured output capability
- **Claim:** The benchmark’s requirement for precise temporal segmentation exposes a core limitation in MLLMs’ ability to generate structured, time‑aligned outputs from continuous video.
- **Mechanism:** Models must process long‑duration video (10–35 minutes) and produce a JSON file of non‑overlapping segments with exact start/end times. This forces the model to perform temporal parsing, boundary detection, and consistent formatting—capabilities not naturally emergent from next‑token prediction trained on static images or short clips.
- **Core assumption:** Current MLLMs lack explicit temporal segmentation heads or training objectives for continuous time‑series annotation.
- **Evidence:** The paper repeatedly notes “challenges in temporal segmentation” (abstract, sec. 4.2); metrics like mAP directly evaluate segment overlap (sec. 3.2); and formatting errors (e.g., “end_long_time” instead of “end_time”) are documented (sec. 4.2, appendix F.1).
- **Break condition:** If a model consistently produces malformed JSON or segments with large temporal drift (>1 second gaps/overlaps), the mechanism fails.

### Mechanism 2: Subtle behavior confusion due to coarse motion bias
- **Claim:** The inclusion of subtle, context‑dependent behaviors (e.g., freezing vs. resting) reveals MLLMs’ dependence on coarse motion cues over fine‑grained ethological understanding.
- **Mechanism:** Freezing is defined by the *absence* of movement combined with specific postural cues (ears forward). MLLMs, trained on datasets emphasizing active objects/actions, may default to binary motion detection (“moving” vs “still”) without integrating spatial context or species‑specific knowledge.
- **Core assumption:** MLLMs’ visual representations are optimized for salient motion and object recognition, not for nuanced, low‑motion behavioral states.
- **Evidence:** The Freezing dataset description distinguishes it from resting by ear position (sec. 3.1); section 4.2 explicitly states performance is “severely limited by distinguishing subtle behavioral states”; figure 2 shows near‑chance MCC (~0.004) on freezing for Gemini‑Pro despite better performance on grooming.
- **Break condition:** If a model cannot achieve MCC >0.2 on freezing while achieving >0.5 on grooming, the mechanism is likely active.

### Mechanism 3: Extended video length strains long‑range temporal coherence
- **Claim:** Long video durations test the models’ capacity for long‑range temporal coherence, which is strained by context window limits and lack of explicit memory mechanisms.
- **Mechanism:** Even models with large context windows (e.g., Gemini 1M tokens) must compress ~180k frames (10 min @ 30fps) into a token stream. This forces aggressive subsampling or loss of fine‑detail over time, preventing consistent labeling across the full sequence.
- **Core assumption:** MLLMs process video as a flat token sequence without hierarchical temporal abstraction or external memory.
- **Evidence:** Videos range 10–35 minutes; two benchmark versions (Short/Long) were created due to model limitations (sec. 3.1); context window sizes are listed in appendix B.1–B.3; and the authors note “challenges in handling extended video sequences” (sec. 4.2).
- **Break condition:** Performance degradation >15% in weighted MCC when moving from Short to Long benchmark indicates failure to maintain coherence over time.

## Foundational Learning
### Concept 1: Temporal segmentation evaluation (e.g., mAP, IoU)
- **Why needed:** Rodent behavior annotation is a segmentation problem—identifying start/end of discrete bouts—not per‑frame classification. Standard classification metrics (accuracy) are insufficient; mAP over IoU thresholds measures boundary alignment.
- **Quick check:** If a predicted segment overlaps 70% with a ground truth segment, is that a "true positive" at IoU=0.5? What about at IoU=0.7?

### Concept 2: Class imbalance and chance baselines
- **Why needed:** Datasets have skewed behavior proportions (e.g., scratching 23.4% vs. 76.6% not scratching). Raw accuracy can be misleading; MCC and mutual information provide distribution‑independent baselines (zero = random).
- **Quick check:** Given a dataset with 90% "other", what is the chance‑level second‑wise accuracy if predicting all‑"other"?

### Concept 3: Structured output constraints in MLLMs
- **Why needed:** The task requires strict JSON formatting with timestamps. MLLMs are not inherently constrained to schema, leading to format errors that break automated evaluation.
- **Quick check:** How would you use a Pydantic model (as in appendix A.2) to validate a model's JSON response before scoring?

## Architecture Onboarding
**Component map:** Video Ingestion -> Prompt Template Engine -> MLLM API Client -> Output Parser & Validator -> Scoring Module.
**Critical path:** Video → (frames/samples) → prompt with schema → MLLM inference → raw text → JSON parse → validation → metric computation.
**Design tradeoffs:**
- *Frame sampling vs. native video:* Frame‑sampling (Qwen) loses audio/temporal nuance; native video (Gemini) may hit token limits.
- *Schema strictness:* Overly rigid JSON schema may cause failures if model deviates slightly; lenient parsing risks invalid comparisons.
- *Metric choice:* Second‑wise accuracy favors majority classes; mAP is sensitive to boundary precision but computationally heavier.
**Failure signatures:**
- Repeated JSON parse errors (missing commas, unclosed brackets).
- Segments with `start_time >= end_time` or negative durations.
- Sudden drops in mAP while accuracy remains stable—indicates boundary misalignment, not label confusion.
- High variance across videos within same dataset—suggests inconsistency in model’s temporal parsing.
**First 3 experiments:**
1. **Sanity check on grooming dataset:** Verify pipeline yields >0.6 second‑wise accuracy for Gemini‑Pro (per figure 2). Confirms baseline functionality.
2. **Format stress test:** Run Qwen‑VL‑Max on a 9‑minute clip; confirm frequency of malformed JSON (>50% per section F.1). Validates output parser robustness needs.
3. **Length sensitivity test:** Compare Gemini‑Pro on the same 10‑minute video from both Short and Long benchmarks. If performance diverges >10% in MCC, context window management is a key failure mode.

## Open Questions the Paper Calls Out
**Open Question 1:** How can temporal reasoning and segmentation capabilities be enhanced in MLLMs to achieve accurate per‑second behavioral annotations on long videos?  
*Basis:* Explicitly stated by authors: “enhanced temporal reasoning capabilities are needed …” and “significant challenges in temporal segmentation.”  
*Why unresolved:* Current MLLMs perform poorly on segmentation metrics (e.g., MCC near zero on many datasets).  
*Resolution evidence:* Integration of temporal modeling modules (e.g., temporal convolutions, memory‑augmented transformers) into MLLMs, with Rodent‑Bench showing substantial improvement (weighted MCC >0.7).

**Open Question 2:** To what extent can supervised fine‑tuning or specialized prompting improve MLLM performance beyond the zero‑shot baseline?  
*Basis:* Explicit limitation: “our evaluation uses zero‑shot inference without fine‑tuning or extensive prompt optimization… it may underestimate achievable performance.”  
*Why unresolved:* No fine‑tuning experiments have been conducted; the poor zero‑shot results might not reflect the upper bound.  
*Resolution evidence:* Fine‑tune each model on a representative subset of Rodent‑Bench, then compare metrics (MCC, mAP) against zero‑shot baseline.

**Open Question 3:** How do state‑of‑the‑art MLLMs compare to human experts in annotating rodent behaviors, particularly on subtle distinctions like freezing vs. resting?  
*Basis:* Explicit identification: “we lack human annotator baselines to contextualize model performance.”  
*Why unresolved:* Without human performance benchmarks, the performance gap relative to experts is unknown.  
*Resolution evidence:* Recruit trained behavioral neuroscientists to label a common test set from Rodent‑Bench; compute human accuracy and inter‑annotator agreement; directly compare to MLLM metrics.

**Open Question 4:** What architectural or decoding modifications can ensure consistent, machine‑readable JSON output from MLLMs during video annotation tasks?  
*Basis:* Inferred from reported formatting errors: “both Flash and Qwen models struggle with correct formatting… rendering the JSON file unreadable.”  
*Why unresolved:* Malformed outputs hinder automated evaluation and deployment; current prompting and schema constraints are insufficient.  
*Resolution evidence:* Implement and test methods such as constrained beam search, grammar‑guided decoding, or post‑processing validation loops, measuring reduction in malformed responses (<1% failure rate) while preserving annotation accuracy.

## Limitations
- **Video selection & preprocessing** unspecified: The exact filenames for “first 25 videos” and truncation logic are unreported, risking dataset mismatch.
- **API & generation details** missing: Critical hyperparameters (temperature, max_tokens) and retry logic for malformed JSON are not disclosed, affecting reproducibility.
- **Label harmonization** unclear: The method for mapping dataset‑specific behavior labels to a common ontology for aggregated metrics is not detailed.
