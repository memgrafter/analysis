# One Supervisor, Many Modalities: Adaptive Tool Orchestration for Autonomous Queries

## Quick Facts
- **arXiv ID:** 2603.11545
- **Source URL:** https://arxiv.org/abs/2603.11545
- **Reference count:** 31
- **Primary result:** Reduces time-to-accurate-answer by 72%, conversational rework by 85%, and cost by 67% compared to a hierarchical baseline, while maintaining accuracy parity.

## Executive Summary
Multimodal AI systems often suffer from inefficiency and brittleness when using monolithic LLM deployments or hierarchical routing. This paper introduces a centralized orchestration framework where a Supervisor dynamically decomposes user queries and delegates subtasks to modality-appropriate tools using adaptive routing, sidestepping predetermined decision trees. The system leverages a Couplet Framework for perceptual tasks, a memory hierarchy for context, and verification mechanisms for local repair.

Evaluated on 2,847 real-world queries, the approach achieves a 72% reduction in time-to-accurate-answer, 85% reduction in conversational rework, and 67% cost reduction compared to a matched hierarchical baseline, all while maintaining comparable accuracy. The results demonstrate that adaptive orchestration can substantially improve efficiency and robustness in multimodal interactions.

## Method Summary
The method centers on a Supervisor agent that acts as a centralized orchestrator. Upon receiving a query with possible attachments, it first runs a two-stage decomposition: attachment analysis (MIME, signatures) and an SLM classifier to assign a modality flag. Based on the flag and user-selected cost tier, the Supervisor dynamically constructs an execution graph, routing subtasks to appropriate tools. For non-text modalities, the Couplet Framework pairs traditional models (e.g., YOLO, CLIP) with lightweight SLM coordinators for efficient processing; for text, RouteLLM selects among weak/strong models. A five-layer memory system (short-term, full history, modality-specific, relevant, compressed) provides context, with relevance scoring combining semantic similarity, recency, and modality alignment. After tool execution, outputs are verified via confidence thresholds and internal consistency checks, enabling local repair (alternative tool or clarification) without restarting the pipeline.

## Key Results
- 72% reduction in time-to-accurate-answer (TTA) vs. hierarchical baseline.
- 85% reduction in conversational rework.
- 67% reduction in cost.
- Accuracy parity maintained (no statistically significant difference).

## Why This Works (Mechanism)

### Mechanism 1: Adaptive Routing Execution Graph
- **Claim:** Dynamic query decomposition and adaptive routing eliminate brittle, predetermined decision trees.
- **Mechanism:** The Supervisor reads formal tool specifications (pre/post-conditions, latency priors) and composes an execution graph at runtime via a two-stage classification (attachment analysis + SLM flagging). This avoids fixed pathways; if a tool fails (e.g., OCR on handwriting), low confidence triggers dynamic reselection (e.g., vision analysis) without restarting the entire pipeline.
- **Core assumption:** Tool specifications are sufficiently expressive to enable correct composition, and the SLM classifier generalizes to unseen query patterns.
- **Evidence:** The paper reports 85% reduction in conversational rework and describes local repair mechanisms in Section 3, noting how cascading failures inherent in hierarchical pipelines are eliminated.
- **Break condition:** Incomplete tool specifications or SLM misclassification on novel modality combinations could lead to inappropriate routing and system failures.

### Mechanism 2: Couplet Framework Efficiency
- **Claim:** The Couplet Framework (domain-specific model + lightweight SLM coordinator) provides cost- and latency-efficient perceptual processing without sacrificing accuracy.
- **Mechanism:** For non-text modalities, the Supervisor dispatches perceptual subtasks to optimized traditional models (YOLO, CLIP, Tesseract) instead of a monolithic multimodal LLM. A small language model (SLM) translates natural language into structured inputs for the model and contextualizes its raw outputs back into conversational responses.
- **Core assumption:** Traditional models exist for the perceptual task and their outputs can be reliably contextualized by a lightweight SLM.
- **Evidence:** Benchmarks show perceptual tasks benefit from routing to specialized models (e.g., object detection in 180 ms/frame) versus end-to-end LLM vision approaches (e.g., 2.4 s/frame) (abstract). Section 3 details how the Couplet Framework preserves the core contribution while making perceptual processing efficient.
- **Break condition:** If a perceptual task exceeds the capability of available traditional models or requires deep multimodal reasoning only a frontier LLM provides, routing to the Couplet Framework could degrade accuracy.

### Mechanism 3: Hierarchical Memory and Verification
- **Claim:** Hierarchical, modality-specific memory with unified context scoring reduces rework by maintaining coherent state and enabling local verification.
- **Mechanism:** A five-layer memory architecture (short-term, full history, modality-specific, relevant, compressed) is managed by the Supervisor. Relevant context is retrieved via semantic search and scored by a weighted combination of semantic relevance, temporal recency, and modality alignment. This memory feeds into tool selection and output verification, allowing detection of inconsistencies (e.g., conflicting extracted data) and triggering local repair or user clarification before finalizing a response.
- **Core assumption:** The memory scoring function (Equation 8) correctly prioritizes context that prevents rework-causing errors.
- **Evidence:** The paper reports 85% rework reduction and an ablation study showing that removing memory layers caused 28% time-to-accurate-answer regression, while disabling verification increased rework substantially (Section 5).
- **Break condition:** If memory retrieval returns irrelevant or misleading context (e.g., due to semantic search errors on cross-modal queries), the Supervisor may make incorrect routing or synthesis decisions, increasing rework.

Why needed: The economic benefits stem from this routing. Engineers need to grasp the three computational tiers (`trad_couplet`, `open_src`, `closed_src`) and how RouteLLM's win-prediction model classifies queries as `strong` or `weak` (and sub-flags) to invoke the appropriate tier.

## Architecture Onboarding

**Component Map**  
Supervisor -> Decomposition Subsystem  
Decomposition Subsystem -> Attachment Analysis  
Decomposition Subsystem -> SLM Classifier  
Supervisor -> RouteLLM Module  
RouteLLM Module -> Cost Knob Selector  
Supervisor -> Couplet Framework  
Couplet Framework -> Traditional Models (YOLO, CLIP, Tesseract, Whisper)  
Couplet Framework -> SLM Coordinators  
Supervisor -> Tool Pool  
Tool Pool -> Tools (Semantic Analyzer, Image/Audio/Document Tools, Memory Tools, Orchestration Tools)  
Supervisor -> Memory System  
Memory System -> Layers (M_short, M_full, M_modality, M_relevant [Qdrant], M_compressed)  
Supervisor -> Validation & Repair  
Validation & Repair -> URL Checker, Confidence Monitors, Clarification Hook

**Critical Path**  
1. Ingest: Receive query Q_user, attachments A_attach; generate session ID.  
2. Decompose: Attachment analysis → modality detection; SLM classification → flag assignment.  
3. Validate: URL/file validation; if flag ≠ attachment modality, reassign to `moe`.  
4. Route: Based on flag and K_cost: for `routellm` run RouteLLM; for `vision`/`audio`/`document` use Couplet Framework; for `complex`/`moe` build multi-agent graph with parallel branches.  
5. Execute: Run tools in graph order, respecting dependencies; persist state after each agent.  
6. Verify: Check outputs (tool confidence, internal consistency); on failure, local repair (try alternative tool or generate clarification `C_quest_clarify`).  
7. Synthesize: Aggregate all branch results; update memory layers (M_short, M_full, M_modality, M_relevant, M_compressed); compress if needed.  
8. Respond: Return final response; log full trace H_session.

**Design Tradeoffs**  
- Centralization vs. Scalability: A single Supervisor simplifies reasoning but becomes a bottleneck at extreme QPS; mitigated by multi-tier architecture (many queries handled by cheap `trad_couplet`/`open_src` models).  
- Couplet Exclusivity: Cost/latency gains are tied to a fixed set of traditional models (YOLO, CLIP, etc.); adding a new perceptual capability requires manual integration into the Couplet catalog.  
- Memory Overhead: Five-layer memory, especially vector search on `M_relevant`, adds ~40-80ms latency per query; weighting (α=0.6, β=0.3, γ=0.1) is empirically tuned and may not generalize to all domains.  
- SLM Dependency: The entire decomposition relies on a 3.8B parameter model (Phi-3.5-mini); its errors cascade. The fallback to `moe` is a safety net but may route unnecessarily.

**Failure Signatures**  
- URL/Attachment Validation Failure: Logs "URL invalid or unreachable" → system attempts local file path, then errors; user must fix input.  
- Low Confidence from Tool: e.g., OCR confidence < threshold → triggers tool reselection (to vision analysis) or clarification ("I notice this is handwritten...").  
- Memory Retrieval Noise: Irrelevant context injected → synthesis inconsistencies; monitor by comparing output against retrieved snippets.  
- RouteLLM Misclassification: Simple query sent to `closed_src` tier (cost bloat) or complex query to `open_src` (low quality); check via BERT-similarity audit between weak/strong model outputs on a sample.  
- Supervisor Loop: If clarification cycle doesn't terminate (e.g., user provides unhelpful responses), monitor for high clarification-turn counts per session; graph has explicit termination conditions.

**First 3 Experiments**  
1. **Single-Modality Text Routing:** Submit 100 varied text queries (coding, math, summarization) with `K_cost=open_src`. Verify RouteLLM routes ~96% to weak models and that `subflag` selection matches expected model (e.g., CodeLLaMA for coding). Measure cost vs. all-GPT-4 baseline.  
2. **Couplet Efficiency for Vision:** Send identical image queries to the system (`vision` flag) and to a monolithic LLM-with-vision (e.g., GPT-4o). Measure latency per frame and cost. Expected: ~180ms/frame (YOLO+SLM) vs. ~2400ms/frame (LLM).  
3. **Local Repair vs. Hierarchical Restart:** Use the "handwritten notes" case study query. In a forked hierarchical baseline (fixed decision tree), measure total time to user's final correct answer (including manual reformulation). In the centralized system, measure time to autonomous recovery. Expected: ~6s vs. ~28s, with zero user rework in the centralized path.

## Limitations
- External validity: Limited independent validation (0 citations, neighbor FMR ~0.54); results may not generalize beyond the evaluated query set.
- Couplet framework rigidity: Efficiency gains rely on a fixed catalog of traditional models; novel perceptual tasks (e.g., 3D point cloud analysis) may force fallback to costly LLMs.
- SLM dependency: Entire decomposition hinges on a 3.8B Phi-3.5-mini; misclassifications on edge-case modality combinations could trigger unnecessary `moe` routing or failures.

## Confidence
- Primary outcome claims (72% TTA reduction, 85% rework reduction, 67% cost reduction, accuracy parity): High
- Mechanism 1 (adaptive routing): Medium
- Mechanism 2 (Couplet efficiency): High for measured benchmarks, Medium for broader applicability
- Mechanism 3 (memory-driven rework reduction): High

## Next Checks
1. **SLM robustness to out-of-distribution modality combinations:** Generate synthetic queries with rare or hybrid modality attachments (e.g., handwritten diagram + audio narration) not in training distribution. Measure routing accuracy and `moe` fallback rate.
2. **Memory noise impact on rework:** Inject irrelevant but semantically plausible context into `M_relevant` (e.g., past queries on similar topics but different intents). Quantify increase in clarification turns and incorrect tool selections.
3. **Couplet framework boundary test:** Evaluate on perceptual tasks outside the supported catalog (e.g., medical image segmentation, tactile signal interpretation). Measure accuracy drop and cost/latency deviation from Couplet baseline.
