# Prime Once, then Reprogram Locally: An Efficient Alternative to Black-Box Service Model Adaptation

## Quick Facts
- arXiv ID: 2604.01474
- Source URL: https://arxiv.org/abs/2604.01474
- Reference count: 40
- Primary result: AReS achieves a +27.8% gain over zero-shot on GPT-4o, outperforms SOTA by +2.5% (VLMs) and +15.6% (VMs) while reducing API calls by >99.99% and cutting training time by >98%.

## Executive Summary
Closed-box service model adaptation via zeroth-order optimization (ZOO) suffers from high API costs, instability, and failure on modern robust APIs like GPT-4o. This paper introduces AReS, a two-stage approach that first primes a local encoder using a single API call to the service model, then performs efficient glass-box reprogramming entirely locally. By transferring knowledge in one pass, AReS eliminates all further API dependence, achieving dramatic reductions in cost and time while substantially improving accuracy. On GPT-4o, AReS yields a +27.8% gain over zero-shot, where ZOO methods stagnate, and across ten datasets it outperforms state-of-the-art by +2.5% for vision-language models and +15.6% for vanilla models.

## Method Summary
AReS operates in two stages. **Priming**: The service API is queried once per training image to obtain predictions (probability vectors). These are used to train a lightweight linear head attached to a frozen local pre-trained encoder via KL divergence loss, aligning the local model’s output distribution with the service’s. **Glass-box visual reprogramming**: With the primed local model fixed, a visual prompt—a small perturbation added to input images—is optimized using cross-entropy loss against true labels. For tasks with disjoint label spaces (vanilla models), a Bayesian-guided label mapping (BLM) bridges source and target labels. After training, only the local model (encoder + primed head) and the learned prompt are required for inference; no further API calls occur. This shifts adaptation from expensive, unstable black-box ZOO to efficient first-order optimization on a local proxy.

## Key Results
- +27.8% gain over zero-shot on GPT-4o; ZOO methods fail to improve.
- Outperforms SOTA by +2.5% on VLMs and +15.6% on VMs across ten datasets.
- Reduces API calls by >99.99% and training time by >98%.

## Why This Works (Mechanism)
### Mechanism 1: Single-Pass Knowledge Transfer via Priming
- **Claim:** A one-time API call to the service model `F_S` transfers sufficient knowledge to align the output distributions (logits/probabilities) of a local encoder `F_L`, making `F_L` amenable to downstream reprogramming.
- **Mechanism:** During priming, a lightweight linear head is trained on `F_L` using `F_S`'s predictions as soft targets (via KL divergence loss). This aligns `F_L`'s output space towards `F_S`'s, establishing an `ϵ`-faithful relationship (Definition 1) that bounds the performance gap (Theorem 3).
- **Core assumption:** The service model `F_S` is superior or better aligned to the downstream data distribution `D_T` than the local model `F_L` (Assumption 1), and the priming effectively reduces the distributional divergence to a small `ϵ` (Assumption 2).
- **Evidence anchors:**
  - [abstract] "AReS initiates a single-pass interaction with the service API to prime an amenable local pre-trained encoder."
  - [section 4] "This priming objective... is defined as: `L_P(p_L, p_S) := - Σ p_S,j log p_L,j`, where... `p_S/p_L` are the output probabilities... This loss is equivalent to the Kullback-Leibler divergence."
  - [corpus] Neighbor papers discuss API auditing and energy efficiency but do not directly address priming mechanisms; evidence is primarily from the AReS paper itself.
- **Break condition:** Priming fails if the local model's capacity is insufficient to mimic `F_S`'s output space given the downstream data, leading to a large `ϵ` that breaks the theoretical bound (Theorem 3). Manifested as poor performance after local VR, especially on highly complex datasets (Sec 10.7).

### Mechanism 2: Elimination of Ongoing API Dependency
- **Claim:** By transferring knowledge to a local model in a single pass, all subsequent training and inference occur locally via glass-box (first-order) optimization, removing the need for repeated expensive and unstable API calls.
- **Mechanism:** After priming, the visual prompt `P` is optimized using exact gradients from the primed local model `F_L(·;θ^*)` (Eq 2). The service model `F_S` is never queried again. Inference uses only the local model: `ŷ = gout(F_L(gin(x, P^*); θ^*))`.
- **Core assumption:** The locally primed model possesses sufficient representational capacity to be effectively fine-tuned for the downstream task via input-level reprogramming (visual prompting).
- **Evidence anchors:**
  - [abstract] "eliminating all further API dependence... reducing API calls by over 99.99%."
  - [section 4] "Consequently, all subsequent adaptation and inference rely solely on this local proxy, eliminating all further API costs."
  - [section 5.1] Table 2 shows API calls drop from ~754M (BlackVIP) to 0.02M, with inference cost zero.
- **Break condition:** The local model is too weak to capture the target task's complexity even after priming, causing local VR to plateau at low accuracy. This is dataset-dependent (e.g., Food101, Cars in Table 2).

### Mechanism 3: Synergistic Knowledge Combination
- **Claim:** AReS can synergistically combine the specialized knowledge of the powerful service model with the inductive biases of the local model, sometimes surpassing the theoretical ceiling of glass-box reprogramming on the service model alone.
- **Mechanism:** Priming aligns the local model's representation toward the service model's output space. Subsequent local VR then leverages both the transferred knowledge and the local model's inherent feature biases. This can correct errors made by either model in isolation.
- **Core assumption:** The service and local models have complementary strengths and weaknesses on the downstream task; their combined knowledge space is richer than either alone.
- **Evidence anchors:**
  - [section 10.5] "AReS's performance can surpass that of a glass-box reprogramming approach on the service model itself... This synergistic effect... allows AReS to correctly classify samples that neither... could handle individually."
  - [section 10.5] Table 15 shows on Flowers102, AReS (RN101 service) achieves 51.3%, beating both the service glass-box (42.3%) and local VR (38.7%).
  - [corpus] No direct neighbor evidence; concept related to multi-view ensemble trust [34] cited in paper.
- **Break condition:** Knowledge is not complementary but redundant or conflicting. If the local model's biases are detrimental to the transfer (e.g., severe domain gap), synergy fails and performance may not exceed the service model's glass-box upper bound.

## Foundational Learning
- **Concept: Model Reprogramming (MR) / Visual Reprogramming (VR)**
  - *Why needed here:* MR is the core problem AReS solves: adapting a pre-trained model without parameter updates via input transformations (`gin`) and label mapping (`gout`). Understanding this paradigm (Sec 3) is essential to see how AReS changes the game.
  - *Quick check question:* What are the two key functions (`gin`, `gout`) in model reprogramming, and what challenges arise when the source and target label spaces are disjoint?

- **Concept: Zeroth-Order Optimization (ZOO)**
  - *Why needed here:* ZOO is the standard approach for closed-box reprogramming (BAR, BlackVIP). AReS's motivation is to overcome ZOO's high cost and instability (Sec 2, 4). Knowing ZOO's gradient estimation methods (RGF, SPSA-GC) explains the inefficiency AReS avoids.
  - *Quick check question:* Why does SPSA-GC (used in BlackVIP) require multiple API calls per update, and what is the fundamental limitation of gradient estimates in ZOO?

- **Concept: Knowledge Distillation (KD)**
  - *Why needed here:* The priming stage uses a KL divergence loss akin to KD, but with a different goal: preparing the local model for reprogramming, not final task performance (Sec 4). This distinction is crucial for understanding why priming works across disjoint label spaces.
  - *Quick check question:* How does AReS's priming objective differ from traditional KD in terms of label space requirements and end goal?

## Architecture Onboarding
- **Component map:** Service API (`F_S`) -> (query once) -> Priming Head (`θ`) trained on Local Encoder (`F_L`) -> (freeze `θ`) -> Visual Prompt (`P`) optimized on `F_L` -> deploy `F_L + θ^* + P^*` locally. For VMs: includes Bayesian-guided Label Mapping (BLM) between source and target labels.
- **Critical path:** `Service API` → (query once) → `Priming Head` trained on `Local Encoder` → (freeze `θ`) → `Visual Prompt` optimized on `Local Encoder` → deploy `Local Encoder + θ^* + P^*` locally.
- **Design tradeoffs:**
  - *API calls vs. Local Capacity:* Single API call vs. reliance on local model's expressive power. Poor local model → limited gains.
  - *Priming Data:* Uses downstream data (labeled or unlabeled). More unlabeled data improves priming (Fig 3d) but requires more local compute.
  - *Prompt Complexity:* Compact prompts preferred; larger prompts hurt ZOO stability (Table 12), but AReS uses stable FOO, allowing effective small prompts.
- **Failure signatures:**
  1. **High `ϵ` (Poor Priming):** After priming, `F_L`'s outputs still far from `F_S`. Local VR yields minimal gain over zero-shot/local VR baseline. Check: Compare primed local zero-shot accuracy to service zero-shot.
  2. **Local Model Saturation:** Local VR plateaus at low accuracy despite good priming. Indicates local model lacks capacity for target task. Check: Glass-box VR on local model alone (Table 10, 11).
  3. **Dataset-Specific Ceiling:** Performance significantly below glass-box service VR on certain datasets (Food101, Cars). Indicates inherent limitation of input-level prompting for that domain (Sec 10.7).
- **First 3 experiments:**
  1. **Priming Ablation:** Compare AReS with/without priming (Table 6). Isolate priming's contribution to final performance.
  2. **Local Baseline Comparison:** Compare AReS against glass-box VR on the local model alone (Local VR, Table 10, 11). Quantify priming's enhancement effect.
  3. **API Cost Measurement:** Total API calls (training + inference) for AReS vs. ZOO baselines (BAR, BlackVIP) across datasets (Table 2, 3). Verify >99.99% reduction claim.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can AReS be extended to generative vision-language tasks like VQA that require free-form textual outputs rather than fixed label classification?
  - *Basis in paper:* Section 8.2 explicitly states this as a future direction.
  - *Why unresolved:* AReS currently relies on a fixed label mapping and cross-entropy loss; generative tasks require decoding and sequence-level optimization, which are incompatible with the current formulation.
  - *What evidence would resolve it:* A new AReS framework that incorporates a generator head trained via supervised or reinforcement learning, evaluated on VQA benchmarks.

- **Open Question 2:** Can AReS be integrated with black-box test-time adaptation to handle non-stationary distributions, thereby eliminating the need for frequent service API calls during deployment?
  - *Basis in paper:* Section 12 suggests combining AReS with online adaptation strategies.
  - *Why unresolved:* AReS assumes a stationary downstream distribution after priming; test-time adaptation typically requires online updates, potentially conflicting with eliminating API dependency.
  - *What evidence would resolve it:* A hybrid approach where the primed local model is further adapted at test time using only local unlabeled data, with empirical validation on distribution-shift benchmarks (e.g., ImageNet-C).

- **Open Question 3:** What causes the performance ceiling on certain fine-grained datasets (e.g., Food101, Stanford Cars) for both glass-box and closed-box reprogramming, and how can AReS overcome this limitation?
  - *Basis in paper:* Section 10.7 identifies this as an open direction.
  - *Why unresolved:* Even with full service model access, reprogramming fails to improve over zero-shot on these datasets, suggesting inherent limitations of input-level perturbations.
  - *What evidence would resolve it:* An analysis correlating dataset characteristics (e.g., inter-class similarity, background complexity) with reprogramming efficacy, followed by targeted modifications to priming or visual prompt design.

## Limitations
- Local model capacity limits performance on some datasets (e.g., Food101, Cars); no capacity study.
- Prompt design (size, init, universality) not specified → reproducibility risk.
- Bayesian-guided Label Mapping (BLM) algorithm cited but not detailed; implementation may diverge.
- Theoretical assumptions (service superiority, ε-faithfulness) unverified; Theorem 3's bound abstract.
- Generalization to other APIs untested.
- Synergy claim based on one dataset.

## Confidence
- High: API call reduction >99.99% and comparable accuracy to ZOO – directly measured.
- Medium: Priming transfers knowledge – gains shown but alignment (ε) not quantified.
- Low: Surpassing glass-box service VR – isolated Flowers102 result; weak theory.
