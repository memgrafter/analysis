# Using Vision + Language Models to Predict Item Difficulty

## Quick Facts
- **arXiv ID:** 2603.04670
- **Source URL:** https://arxiv.org/abs/2603.04670
- **Reference count:** 20
- **Key outcome:** Multimodal GPT-4.1-nano model predicts visualization literacy item difficulty (MAE = 0.224) better than vision-only (MAE = 0.282) or text-only (MAE = 0.338) models.

## Executive Summary
This study evaluates whether multimodal large language models can predict the difficulty of data visualization literacy test items. Using a dataset of 154 PNG items with images and text, three modeling approaches were compared: text-only, vision-only, and multimodal. The multimodal model, which integrated visual and textual features, achieved the lowest mean absolute error (MAE = 0.224) on the validation set. When applied to a held-out test set of 46 items, the multimodal model achieved a mean squared error (MSE) of 0.10805, demonstrating its potential for automated psychometric analysis and item development.

## Method Summary
The researchers used GPT-4.1-nano to predict item difficulty through three distinct approaches: analyzing text alone, visualization images alone, or both combined. The dataset was split 80/20 into validation and test sets, with the validation set filtered to PNG images (N=154) for model comparison. For each item, the model was prompted to analyze specific features (chart type, axis clarity, cognitive task, distractor plausibility) and output a structured JSON prediction. The multimodal model with lowest MAE on the validation set was selected and applied to the test set. No fine-tuning occurred; the approach relied on zero/few-shot prompting.

## Key Results
- Multimodal model achieved lowest validation MAE (0.224) compared to vision-only (0.282) and text-only (0.338) models
- Multimodal model's centered prediction distribution suggests better balance of visual and textual cues
- Test set MSE of 0.10805 achieved using multimodal model, though 6 SVG items required default predictions

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Integrating visual and textual input features improves prediction accuracy over using either modality alone.
- **Mechanism:** The multimodal model simultaneously processes the chart image (visual encoding, layout, complexity) and the question/text (semantic demand, distractor plausibility). This allows it to model interactions where a simple chart paired with a tricky question is as difficult as a complex chart with a straightforward question.
- **Core assumption:** The LLM's internal representation space can effectively align and reason over disparate feature types (pixel data vs. token sequences) to synthesize a holistic difficulty estimate.
- **Evidence anchors:**
  - [abstract] "The multimodal approach, using both visual and text features, yields the lowest mean absolute error (MAE) (0.224), outperforming the unimodal vision-only (0.282) and text-only (0.338) approaches."
  - [section 2.2] The system prompt for the multimodal model instructs analysis of "visual elements, textual demands, answer option quality, and their interaction."
  - [corpus] Neighbors include work on text-only item difficulty prediction and visualization literacy, but none directly test the multimodal combination as done here. Evidence for the mechanism is primarily anchored in this paper's results.
- **Break condition:** If the performance gap between multimodal and the best unimodal model shrinks or reverses on a larger, more diverse dataset with robust image format support, the inferred superiority of integration would be weakened.

### Mechanism 2
- **Claim:** The distribution of predicted scores indicates unimodal models are systematically biased, which multimodal learning mitigates.
- **Mechanism:** The vision-only model's predictions cluster at high easiness (peak 0.85-0.9), likely over-indexing on chart aesthetics or clarity while ignoring textual traps. The text-only model's spread and cluster at low easiness (~0.25) suggests it may over-penalize dense text or undervalue visual clarity. The multimodal model's centered distribution suggests it balances these cues.
- **Core assumption:** The observed prediction distributions directly reflect the models' feature utilization biases, not just random error.
- **Evidence anchors:**
  - [section 3.1] "The vision-only model tends to predict higher easiness scores... The Text-only model’s predictions are more spread out, with a notable cluster around 0.25. The multimodal model’s more centered distribution likely reflects a better balance..."
  - [section 2.2] The distinct prompt instructions for each model explicitly steer attention to different feature sets, supporting the interpretation that distribution differences arise from feature focus.
  - [corpus] The neighbor paper "Estimating Item Difficulty Using Large Language Models..." likely examines text-only LLM biases, providing contextual support, but not direct evidence for this specific distribution claim.
- **Break condition:** If re-running with different random seeds or minor prompt changes drastically alters the unimodal distribution shapes, the observed bias might be an artifact of the specific prompt or test set, not a fundamental mechanism.

### Mechanism 3
- **Claim:** The LLM (GPT-4.1-nano) acts as a zero/few-shot feature extractor and synthesizer for psychometric constructs without task-specific fine-tuning.
- **Mechanism:** The model leverages its pre-trained knowledge of visualization conventions, language comprehension, and task difficulty heuristics (e.g., "more options = harder", "cluttered chart = harder") from its broad training. The structured JSON output (via Pydantic) forces a consolidated judgment. It does not learn from the 154-item validation set but applies in-context reasoning from the system prompt.
- **Core assumption:** The model's in-context "analysis" described in prompts corresponds to a meaningful, human-interpretable feature extraction process that correlates with true difficulty drivers.
- **Evidence anchors:**
  - [section 2.2] "We use the GPT-4.1-nano model... Three distinct modeling approaches were devised... instructions to analyze [specific features] and provide an estimated prediction." This indicates a zero/few-shot prompting strategy.
  - [section 4.1] Limitation: "The reliance on a single, proprietary LLM also presents a limitation, as performance may vary across models and platforms." This acknowledges the mechanism is model-dependent.
  - [corpus] Neighbor papers (e.g., "SMART: Simulated Students...") explore different LLM-based approaches, but this paper's specific use of a vanilla multimodal API for direct prediction is distinct. Corpus provides little direct anchor for this zero-shot claim.
- **Break condition:** If a controlled experiment where the model is given *only* the true difficulty value in the prompt (without features) produces similar MAE, it would indicate the model is not using the specified features meaningfully, invalidating this mechanism.

## Foundational Learning

**Concept: Multimodal Representation Learning**
- *Why needed here:* To understand how a single model processes and fuses two fundamentally different data types (image pixels and text tokens) to produce a unified difficulty score. This is core to the "multimodal" approach's hypothesized advantage.
- *Quick check question:* What are two different ways a model might fuse visual and textual features (e.g., early fusion vs. late fusion), and which approach does the GPT-4.1-nano API implicitly use?

**Concept: Classical Test Theory & Item Difficulty**
- *Why needed here:* The target variable ("easiness" = proportion correct) is a classical test theory measure. Understanding its properties (range 0-1, sample-dependent) is crucial for interpreting MAE/MSE values and model utility.
- *Quick check question:* If an item has a difficulty (proportion incorrect) of 0.8, what is its easiness, and what does that imply about the item's performance?

**Concept: Zero/Few-Shot Prompting with Structured Outputs**
- *Why needed here:* The entire modeling approach is a prompt engineering exercise. Understanding how system prompts, user inputs, and output schemas (Pydantic) work together to constrain LLM output is essential for replicating the architecture.
- *Quick check question:* Why might the researchers use a Pydantic model to define the expected JSON output instead of just asking the LLM for a number?

## Architecture Onboarding

**Component map:**
Data Source -> Preprocessor -> LLM Client Wrapper -> Prompt Templates -> Output Parser -> Evaluator -> Experiment Tracker

**Critical path:** Data Preparation → Prompt Definition → API Call Loop (per item) → Output Parsing → Metric Calculation → Model Selection → Test Set Inference → Final Reporting

**Design tradeoffs:**
- **API cost vs. Dataset size:** Calling the multimodal API 154+ times is costly. A tradeoff is using a smaller, stratified validation subset.
- **Prompt specificity vs. generality:** Highly detailed prompts (listing "chart type, axis clarity...") may bias the model but produce more interpretable reasoning. Vague prompts may yield more naturalistic but less consistent feature usage.
- **Image handling:** PNG convenience vs. SVG comprehensiveness. The PNG filter simplified implementation but introduced test set bias (6 SVG items).

**Failure signatures:**
- **High MAE + narrow prediction range:** Model predicts near-constant value (e.g., always ~0.5), failing to learn difficulty variation.
- **Systematic bias in residuals:** Validation plot shows predictions consistently too high for certain chart types or question lengths.
- **Parser errors:** Frequent Pydantic validation failures indicate the LLM is not following the structured output instruction, corrupting data.
- **SVG handling failure:** As seen, inability to process a file format leads to meaningless default predictions for a subset.

**First 3 experiments:**
1. **Baseline Unimodals:** Reproduce the core result by running text-only and vision-only prompts on the full 154-item PNG validation set, confirming MAE gaps.
2. **Format Robustness:** Implement SVG-to-PNG conversion (e.g., CairoSVG) and re-run the multimodal model on the original 46-item test set to get a clean MSE without default values.
3. **Prompt Ablation:** For the multimodal model, run variants removing specific instruction clauses (e.g., "and their interaction" or "distractor plausibility") to measure their contribution to the MAE reduction.

## Limitations
- **PNG filtering of validation set** introduces potential dataset bias and complicates comparison with the test set
- **SVG handling limitation** in the API caused default predictions for 6 test items, likely inflating the reported MSE
- **Single proprietary model dependency** means results may not generalize to other LLMs or open-source alternatives

## Confidence

**High confidence:** The core finding that the multimodal model achieves lower MAE than text-only or vision-only on the PNG-filtered validation set is well-supported by the reported numbers and a clear experimental design.

**Medium confidence:** The interpretation that this MAE reduction reflects meaningful integration of visual and textual features is reasonable but not definitively proven; it could partly reflect dataset bias or specific prompt engineering.

**Low confidence:** The reported test set MSE (0.10805) is unreliable due to the SVG handling issue and lack of transparency on the final prediction process for those items.
