# SEval-NAS: A Search-Agnostic Evaluation for Neural Architecture Search

## Quick Facts
- **arXiv ID:** 2603.00099
- **Source URL:** https://arxiv.org/abs/2603.00099
- **Reference count:** 37
- **Primary result:** Achieved strong Kendall τ correlations (up to 0.9742) for latency and memory predictions across multiple edge devices, with weaker accuracy predictions.

## Executive Summary
SEval-NAS addresses a fundamental rigidity in neural architecture search (NAS): the hardcoded evaluation of hardware metrics like latency and memory. It introduces a search-agnostic evaluator that predicts these metrics by converting any neural architecture into a standardized string via autograd graph traversal, then embedding the string with a pre-trained T5 transformer and applying a regression head. This decouples representation from prediction, enabling new constraints to be added to existing NAS pipelines (e.g., FreeREA) with minimal code changes. Empirical results on NATS-Bench and HW-NAS-Bench show high correlations for hardware costs, though accuracy prediction remains a weakness. Integration demonstrates practical utility, albeit with increased search time for latency constraints.

## Method Summary
The method involves an offline training phase and a search-time inference phase. First, a dataset of architectures and their measured metrics (accuracy, latency, memory) is built from NAS benchmarks. Each architecture is converted to a string by performing a forward pass, traversing the autograd graph breadth-first, and concatenating operation names and parameter values. This string is tokenized and fed into a T5 transformer encoder (small/base/large), whose output embedding is passed through a linear predictor head to regress the target metrics. The trained evaluator is then plugged into a NAS controller’s loop: candidate architectures are evaluated by the predictor instead of (or in addition to) traditional hardcoded functions, guiding search toward constraint-satisfying architectures.

## Key Results
- Hardware cost predictions (latency, memory) achieve high Kendall τ correlations (e.g., τ = 0.9742 for FPGA latency, >0.85 for most devices).
- Accuracy predictions are consistently weaker across benchmarks.
- Integration into FreeREA enables novel latency/memory constraints with little code modification; search time roughly doubles for latency constraints but remains efficient relative to standard NAS.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** SEval-NAS decouples neural architecture representation from hardware metric prediction by converting any computational graph into a standardized string via autograd traversal.
- **Mechanism:** A breadth-first traversal of the autograd graph generated during a forward pass extracts operation names and parameter values into a sequential string. This string is tokenized universally, enabling any architecture within the supported framework (e.g., PyTorch) to be encoded without architecture-specific hand-engineering.
- **Core assumption:** The structural and parametric information contained in this traversal sequence is sufficient to capture the architectural features that determine hardware costs, which are more directly linked to graph topology than final accuracy.
- **Evidence anchors:** The abstract and section 3.1 (Algorithm 1) describe the traversal and string construction. Neighboring work (MONAS, LLM-NAS) also explores learned predictors, but SEval-NAS’s specific string-based, graph-traversal mechanism is distinct.
- **Break condition:** Architectures with dynamic control flow (e.g., conditional execution) may not be fully captured by a single static graph traversal, leading to incomplete representations.

### Mechanism 2
- **Claim:** A pre-trained, frozen T5 transformer encoder effectively maps the variable-length architecture strings into a dense embedding space that preserves patterns relevant to hardware cost prediction.
- **Mechanism:** The tokenized sequence is processed by a T5 encoder. Self-attention models dependencies between tokens representing different operations and their positions in the graph. The final embedding vector is fed to a simple predictor head for regression.
- **Core assumption:** The semantic relationships between architectural "building blocks" encoded by T5 are transferable to hardware cost prediction, even without task-specific pre-training on architecture data.
- **Evidence anchors:** Section 3.2 describes the transformer’s role in robust feature extraction. Sections 4.3–4.4 (ablation studies) show that all T5 variants achieve strong Kendall τ for latency/memory, supporting the encoding’s effectiveness.
- **Break condition:** Architectures with novel operation types or parameter configurations unseen in training will produce embeddings in low-confidence regions, yielding unreliable predictions.

### Mechanism 3
- **Claim:** SEval-NAS acts as a plug-and-play "evaluator" module that can be inserted into any NAS search loop with minimal code changes, enabling the introduction of new metrics without redesigning the search algorithm.
- **Mechanism:** The NAS controller generates candidate architectures. Instead of the original evaluation, the candidate is passed to SEval-NAS: `string = f(G_a)`, `embedding = g(string)`, `predicted_metrics = h(embedding)`. These predictions are used by the controller’s utility function for ranking/selection.
- **Core assumption:** The prediction model generalizes well enough to the specific search space and hardware platform to provide a ranking that correlates with true hardware costs, thus guiding search effectively.
- **Evidence anchors:** The abstract notes integration into FreeREA enabled new constraints with minimal changes. Section 3.3 describes the modular design. Section 4.5 reports successful integration and search outcome changes.
- **Break condition:** If the evaluator’s training data distribution does not match the architectures generated by the controller (e.g., different search space, new layer types), predictions may be biased or uninformative, derailing search.

## Architecture Onboarding
- **Component map:** Graph Traversal Module -> Tokenizer -> Evaluator (T5 Encoder + Predictor Head) -> NAS Controller. Training Data Pipeline feeds the Evaluator during the training phase.
- **Critical path:**
  1. Training Phase: Prepare dataset D → Train Evaluator E (regression loss on D). Offline, one-time cost per metric/platform.
  2. Search Phase (per iteration): Controller generates a → Traversal & Tokenization → Evaluator Inference (m̂ = E(Tₐ)) → Controller updates based on u(m̂).
- **Design tradeoffs:**
  - Prediction accuracy vs. inference latency: Larger T5 models (base/large) may improve correlation for some edge-device latencies but increase evaluator inference time.
  - Training data fidelity vs. generality: Evaluator performance is bounded by the quality and hardware specificity of benchmark data; deploying on a new device requires new profiling.
  - Frozen vs. fine-tuned encoder: Frozen T5 leverages general sequence features; fine-tuning could improve performance but needs more data/compute.
- **Failure signatures:**
  - High variance in accuracy predictions (systematically low Kendall τ) indicating the string representation may not capture task-specific performance factors.
  - Outlier performance on specific hardware (e.g., much weaker latency correlation for Edge TPU due to negative latency values) showing sensitivity to data quality.
  - Search collapse on memory constraint (very few viable architectures found) suggesting the evaluator’s memory predictions define a very narrow feasible region.
- **First 3 experiments:**
  - Replicate core benchmark evaluation: Train T5-small on NATS-Bench TSS/SSS for latency/memory, reproduce scatter plots and Kendall τ values (Figures 2–4).
  - Replicate HW-NAS-Bench latency prediction: Train latency-only evaluator on NAS-Bench-201 (CIFAR-10) subset, reproduce high τ values for Edge GPU, FPGA, etc., and note Edge TPU anomaly.
  - Integrate into a simple NAS loop: Fork FreeREA, replace evaluation with trained latency predictor, run small-scale search with latency constraint, verify search time increase, constraint satisfaction, and comparable accuracy.

## Limitations
- Accuracy prediction is systematically weaker, likely because hardware costs are more directly linked to graph topology than to task-specific performance factors.
- Evaluator performance is tightly bound to the benchmark’s hardware measurements and search space; generalization to unseen devices or novel architecture types is unproven.
- The exact tokenization pipeline and string formatting are not fully disclosed, introducing ambiguity that could affect reproducibility and performance.

## Confidence
- Graph-to-string conversion mechanism: High (clearly defined in Algorithm 1, logically sound for static graphs)
- T5 encoder effectiveness for hardware metrics: Medium (strong empirical results, but contribution of pre-training vs. fine-tuning unclear)
- Plug-and-play integration across NAS paradigms: Medium (demonstrated for FreeREA, but scalability to other methods un evaluated)
