# LingxiDiagBench: A Multi-Agent Framework for Benchmarking LLMs in Chinese Psychiatric Consultation and Diagnosis

## Quick Facts
- arXiv ID: 2602.09379
- Source URL: https://arxiv.org/abs/2602.09379
- Reference count: 40
- Primary result: LLMs achieve 92.3% accuracy on binary depression-anxiety classification but only 28.5% on 12-way differential diagnosis.

## Executive Summary
Psychiatric diagnosis faces a critical shortage of professionals and suffers from subjectivity, while progress in AI is hampered by the absence of realistic, clinician-verified, multi-turn benchmarks. This paper introduces LingxiDiagBench, a multi-agent framework built on LingxiDiag-16K, a dataset of 16,000 synthetic Chinese consultation dialogues aligned with real electronic medical record (EMR) distributions across 12 ICD-10 psychiatric categories. The framework employs separate patient and doctor agents to simulate multi-turn consultations, supporting both static evaluation (analysis of fixed transcripts) and dynamic real‑time interaction.

Results reveal that large language models (LLMs) perform well on binary depression‑anxiety classification (up to 92.3% accuracy) but struggle with more complex diagnostic tasks: 43.0% for comorbidity recognition and 28.5% for 12‑way differential diagnosis. Dynamic consultation consistently underperforms static analysis, indicating that LLMs have ineffective information‑gathering strategies during interactive dialogue. Moreover, LLM‑as‑a‑Judge scores for consultation quality correlate only moderately (r=0.43) with diagnostic accuracy, suggesting that structured questioning does not guarantee correct diagnoses. The benchmark and code are publicly released.

## Method Summary
LingxiDiagBench constructs LingxiDiag-16K, an EMR‑aligned synthetic dataset covering 12 ICD‑10 psychiatric categories. The generation pipeline extracts demographic, diagnostic, and linguistic features from real EMRs to build a knowledge graph, then samples synthetic patient profiles and generates consultations via a patient agent. The patient agent is guided by a system prompt that enforces brevity, colloquial language, emotional restraint, and honesty, with response lengths sampled from the real clinical distribution to enhance authenticity.

The framework includes a doctor agent that interacts with the patient agent, implementing one of four strategies: Free‑form, Symptom‑Tree, APA‑Guided (structured into five phases), or APA‑Guided with retrieval‑augmented guidelines (MRD‑RAG). A diagnosis agent consumes the full dialogue transcript to predict ICD‑10 codes. Evaluation is performed statically (fixed dialogues fed directly to the diagnosis agent) and dynamically (end‑to‑end interaction). A suite of LLMs (Qwen, Baichuan, GPT, Claude, etc.) is tested on classification tasks (binary, 4‑way including comorbidity, 12‑way) and on consultation quality via LLM‑as‑a‑Judge.

## Key Results
- LLMs achieve up to 92.3% accuracy on binary depression‑anxiety classification, but accuracy drops to 43.0% for comorbidity recognition (4‑way) and 28.5% for 12‑way differential diagnosis.
- Dynamic consultation (real‑time interaction) consistently yields lower accuracy than static analysis of the same dialogues, revealing a gap in information‑gathering strategies.
- LLM‑as‑a‑Judge scores for overall consultation quality correlate only moderately (r=0.43) with diagnostic accuracy, indicating that high‑quality dialogue structure does not guarantee correct diagnoses.

## Why This Works (Mechanism)

### Mechanism 1: Distributionally aligned synthetic data
- **Claim**: Distributionally aligned synthetic data enables realistic and scalable benchmark construction.
- **Mechanism**: The generation pipeline extracts demographic, diagnostic, and linguistic features from real EMRs to build a knowledge graph, then samples synthetic cases that preserve these distributions, maintaining ecological validity while avoiding privacy issues.
- **Core assumption**: Matching the distributions of real patient data yields synthetic cases that are effectively indistinguishable for model evaluation.
- **Evidence**: The abstract notes the dataset is "designed to reproduce real clinical demographic and diagnostic distributions". Section 3.2 details the generation process and shows Table 2 with close alignment in age, gender, and diagnostic frequencies, and Figures 2‑3 illustrate low Jensen‑Shannon divergence in linguistic distributions.
- **Break condition**: If the source real data is biased, the synthetic benchmark inherits those flaws; rare comorbidity patterns may be undersampled.

### Mechanism 2: Prompt engineering and length control in the Patient Agent
- **Claim**: Prompt engineering and length control in the Patient Agent substantially improve simulation authenticity.
- **Mechanism**: LingxiDiag‑Patient uses a system prompt enforcing brevity, colloquial language, emotional restraint, and honesty (expressing uncertainty). Response lengths are sampled from the real clinical distribution, countering LLMs' default verbosity and over‑polished output.
- **Core assumption**: Real psychiatric patients give short, fragmented, emotionally subdued responses; modeling these traits yields more realistic conversational partners.
- **Evidence**: The abstract highlights "a more suitable prompting context than prior approaches". Section 3.3 describes prompt rules and length control; Table 3 shows LingxiDiag‑Patient (e.g., Qwen3‑32B Overall 4.67) far exceeds MDD‑5K‑Patient (max 4.09), with gains in Brevity (4.67 vs 1.18), Proactivity (4.62 vs 1.07), Restraint (4.67 vs 1.36), and Polish (4.66 vs 1.33).
- **Break condition**: Over‑constraining may reduce response diversity and fail to capture atypical but valid patient behaviors; cultural/linguistic generalizability is uncertain.

### Mechanism 3: APA‑Guided protocol with MRD‑RAG for the Doctor Agent
- **Claim**: A phased clinical protocol (APA‑Guided) with retrieval‑augmented diagnostic guidelines (MRD‑RAG) improves doctor agent information gathering and diagnostic accuracy.
- **Mechanism**: APA‑Guided structures questioning into five phases (screening, assessment, deep‑dive, risk, closure) to ensure comprehensive coverage. MRD‑RAG retrieves relevant ICD‑10 criteria for top differentials, guiding next‑question selection and grounding decisions in external knowledge.
- **Core assumption**: Systematic symptom elicitation plus evidence‑based retrieval reduces omission errors and focuses on diagnostically salient information.
- **Evidence**: The abstract states that "adding MRD‑RAG to APA‑Guided can improve end‑to‑end diagnostic performance" and that "ineffective information‑gathering strategies significantly impair downstream diagnostic reasoning". Section 3.4 describes the four doctor strategies and MRD‑RAG; Table 6 shows APA‑Guided + MRD‑RAG consistently achieves the highest accuracy across LLMs (e.g., Grok‑4.1‑Fast 43.0% 12‑way, DeepSeek‑V3.2 92.3% binary) and strong LLM‑as‑a‑Judge scores.
- **Break condition**: Retrieval quality depends on the knowledge base; irrelevant or contradictory guidelines may mislead. The rigid phase structure could hinder detection of atypical presentations.

## Architecture Onboarding
### Component map
The LingxiDiagBench system comprises:
- **Data**: LingxiDiag‑16K (synthetic EMRs + dialogues) and LingxiDiag‑Clinical (real cases).
- **Agents**: Patient Agent (LLM + profile + history), Doctor Agent (LLM + strategy), Diagnosis Agent (LLM + full transcript).
- **Strategies**: Free‑form, Symptom‑Tree, APA‑Guided, APA‑Guided + MRD‑RAG (includes retrieval module).
- **Evaluation**: Static (fixed dialogues → Diagnosis Agent), Dynamic (interaction loop → Diagnosis Agent + LLM‑as‑a‑Judge).
- **Utils**: Retriever for MRD‑RAG, LLM‑as‑a‑Judge (multiple evaluator models), metric calculators.
- **Flow (dynamic)**: patient profile → Patient Agent → [Doctor question → Patient response] loop until closure → final dialogue → Diagnosis Agent → metrics.

### Critical path (run a dynamic experiment)
1. Load a test sample (patient profile + ground truth).
2. Initialize Patient Agent with profile.
3. Initialize Doctor Agent with chosen strategy/LLM.
4. Loop turn‑taking until closure condition (per strategy).
5. Save full dialogue.
6. Run Diagnosis Agent to predict ICD codes.
7. Compute classification metrics vs. ground truth.
8. Optionally run LLM‑as‑a‑Judge for quality scores.
9. Repeat/aggregate over many samples.

### Design tradeoffs
- **Static vs Dynamic**: Static is reproducible and fully informative but cannot evaluate information gathering; dynamic tests interactive skill but introduces variance and relies on patient agent fidelity.
- **Synthetic vs Real data**: Synthetic (16K) scales and protects privacy but may miss rare cases; real data is authentic but limited and may contain noise.
- **Structured vs Free‑form**: Structured (APA) ensures coverage but can be rigid; free‑form allows flexibility but risks omission.
- **Model size**: Larger LLMs yield higher accuracy but are costlier; smaller models enable rapid iteration but sacrifice performance.

### Failure signatures
- **Patient Agent**: Low honesty (<3) or high verbosity (brevity <2) indicates unnatural simulation; check prompt adherence.
- **Doctor Agent**: Low LLM‑as‑a‑Judge scores (e.g., Clinical Accuracy <3) or highly variable accuracy across seeds; long dialogues with irrelevant questions.
- **Systemic**: Dynamic accuracy markedly below static (>15% gap) suggests poor information gathering; low correlation (<0.3) between quality and accuracy indicates decoupling.
- **Infrastructure**: Retrieval failures, token limit exceeded, infinite loops in dialogue generation.

### First 3 experiments
1. **Static baseline replication**: Evaluate Qwen3‑32B on the static test set for 2/4/12‑way tasks. Verify results match Table 4 (e.g., 12‑way accuracy ~0.241, Top‑3 ~0.566).
2. **Patient agent sanity check**: Compare LingxiDiag‑Patient (Qwen3‑32B) against MDD‑5K‑Patient using LLM‑as‑a‑Judge on fixed doctor questions. Expect improvements in brevity, restraint, and overall realism (Table 3).
3. **Strategy impact test**: Run dynamic evaluation with GPT‑5‑Mini across all four doctor strategies on 100 samples. Measure 12‑way accuracy and LLM‑as‑a‑Judge overall; expect APA‑Guided + MRD‑RAG to achieve the highest accuracy.

## Open Questions the Paper Calls Out
1. **Question**: How can patient simulation fidelity be improved for training diagnostic models?  
   **Basis**: "Designing more personalized and authentic patient simulation environments... remains an open research challenge."  
   **Why unresolved**: Current agents fail to capture full diversity of patient communication styles and atypical presentations.  
   **Resolution evidence**: Clinician ratings of dialogue realism; quantitative comparison of linguistic diversity between real and simulated patients.

2. **Question**: Under what clinical conditions does retrieval‑augmented reasoning (MRD‑RAG) improve dynamic consultation accuracy?  
   **Basis**: "the benefit of retrieval‑augmented strategies may be data‑dependent, warranting further investigation."  
   **Why unresolved**: MRD‑RAG helps on synthetic data but not consistently on real clinical cases.  
   **Resolution evidence**: Systematic experiments across diagnostic categories, case complexity levels, and data sources.

3. **Question**: How can LLMs' diagnostic reasoning be enhanced independently of consultation quality?  
   **Basis**: "moderate correlation (r=0.43) between LLM dialogue quality scores and classification task performance... substantial room for improvement in diagnostic reasoning."  
   **Why unresolved**: Models produce structured consultations yet struggle with comorbidities and differential diagnosis.  
   **Resolution evidence**: Architectural changes decoupling information gathering from diagnosis; training objectives targeting diagnostic accuracy.

4. **Question**: How can synthetic psychiatric datasets better represent rare disorders and atypical presentations?  
   **Basis**: "limited diversity in rare presentations and atypical symptom profiles."  
   **Why unresolved**: Data generation follows EMR distributions that undersample rare conditions.  
   **Resolution evidence**: Performance evaluation on held‑out rare cases; diversity metrics of generated symptom profiles.

5. **Question**: What benchmarks are needed to evaluate treatment planning and longitudinal psychiatric care?  
   **Basis**: "future work will extend the benchmark to cover treatment planning, follow‑up assessment, or longitudinal care coordination."  
   **Why unresolved**: Current evaluation stops at initial diagnosis; clinical utility requires ongoing management.  
   **Resolution evidence**: New benchmark tasks with standardized treatment decisions and multi‑session trajectories.

## Limitations
- Synthetic data ecological validity: While distributional alignment (age, gender, diagnosis frequency) is demonstrated, it is unclear whether linguistic and symptomatic nuances of real psychiatric discourse are fully captured; biased source EMRs may propagate.
- Patient agent constraint trade‑off: Enforcing brevity and emotional restraint may reduce response diversity, potentially missing atypical but clinically valid presentations; cultural/linguistic generalizability is uncertain.
- Dynamic evaluation reliability: The consistent static‑dynamic performance gap (~15–30%) suggests poor information‑gathering strategies, but it is uncertain whether this stems from doctor agent limitations or patient agent fidelity.

## Confidence
- Synthetic data realism: Medium
- Patient agent improvements: High
- APA‑Guided + MRD‑RAG efficacy: Medium

## Next Checks
1. Patient agent diversity stress test: Run the Patient Agent with adversarially varied prompts (e.g., increased verbosity, emotional lability) and measure (a) dialogue naturalness via clinician ratings, and (b) downstream diagnostic accuracy variance.
2. MRD‑RAG sensitivity analysis: Perturb the retrieved ICD‑10 guidelines (insert minor errors, remove key criteria) and quantify accuracy drop vs. a no‑retrieval baseline to assess over‑reliance on retrieval.
3. Cross‑cultural generalizability probe: Translate a subset of patient profiles and evaluate the same doctor agents in an English‑language setting; compare performance delta to identify linguistic/cultural biases.
