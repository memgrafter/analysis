# Regularizing Attention Scores with Bootstrapping
## Quick Facts
- arXiv ID: 2604.01339
- Source URL: https://arxiv.org/abs/2604.01339
- Reference count: 40
- Primary result: Bootstrapping-based regularization reduces noisy attention scores by ~10× improvement in suppression factor D while preserving salient regions.

## Executive Summary
Vision Transformers (ViTs) produce noisy, non-sparse attention maps that hinder interpretability. This paper introduces Attention Regularization via Bootstrapping (ARB), which treats attention scores as noisy realizations and uses bootstrapping to estimate a null distribution of scores expected by chance. From this distribution, ARB computes statistical significance (p-values) and local false discovery rates (LFDR) for each score, enabling automated thresholding to zero out spurious attention. On Imagenette and medical CT scans, ARB yields a ~10× improvement in the suppression factor D, effectively removing noise while retaining salient regions. The automated π0-thresholding balances sensitivity and specificity without manual tuning, demonstrating bootstrapping as an effective, general tool for regularizing attention scores and enhancing ViT interpretability.

## Method Summary
The ARB module operates on the attention scores produced by a ViT. It first resamples the input features via bootstrapping to generate multiple surrogate attention matrices under the null hypothesis of no meaningful token relationships. These surrogates form a null distribution. For each observed attention score, a p-value is computed as the proportion of surrogate scores exceeding it, and the local false discovery rate (LFDR) is estimated using the π0 parameter (the proportion of true null hypotheses). An automated threshold derived from π0 is then applied to zero out scores that are not statistically significant. The resulting sparse attention map highlights truly relevant token interactions. ARB is differentiable and can be integrated into training or used post-hoc.

## Key Results
- Suppression factor D improved by approximately 10× compared to unregularized attention on Imagenette and medical CT scans.
- Automated π0-thresholding provides a strong balance between sensitivity and specificity without manual tuning.
- ARB achieves drastic improvement in shrinkage and sparsity of attention maps, effectively removing noise while preserving salient regions.

## Why This Works (Mechanism)
Bootstrapping creates a data-driven null distribution that captures the variability of attention scores due to random fluctuations in feature representations. By comparing each observed score to this distribution, ARB identifies those that are statistically significantly higher than chance. The use of local false discovery rate (LFDR) controls the expected proportion of false positives among the selected scores, ensuring that sparsity does not discard truly important connections. The π0 parameter, estimated from the null distribution, automatically calibrates the threshold stringency, adapting to the specific dataset and model. This statistical regularization yields attention maps that are both sparse and faithful to the underlying signal, thereby improving interpretability without requiring manual threshold selection.

## Foundational Learning
- **Attention Mechanism**: Core component of Transformers that computes pairwise token interactions via dot product and softmax. *Why needed*: ARB directly regularizes attention scores. *Quick check*: Given query and key vectors, attention score = (q·k)/(√d) followed by softmax over keys.
- **Bootstrapping**: Resampling technique to estimate the sampling distribution of a statistic. *Why needed*: Generates a null distribution for attention scores without parametric assumptions. *Quick check*: To bootstrap a dataset of size N, sample N instances with replacement to create a new dataset; repeat many times.
- **P-value**: Probability under the null hypothesis of observing a score as extreme as the observed. *Why needed*: Quantifies the statistical significance of each attention score. *Quick check*: If 95% of bootstrap scores are below an observed score, the p-value is 0.05.
- **False Discovery Rate (FDR)**: Expected proportion of false positives among rejected hypotheses. *Why needed*: Controls multiple testing errors when thresholding many attention scores. *Quick check*: If 100 hypotheses are rejected and 3 are estimated false, FDR = 0.03.
- **Sparsity**: Property of having many zero values in a representation. *Why needed*: Sparse attention maps are easier to interpret and may reduce noise. *Quick check*: Sparsity can be measured as the fraction of zero elements in the attention matrix.

## Architecture Onboarding
**Component Map**: Input Tokens -> Multi-Head Self-Attention -> Attention Scores -> ARB (Bootstrap Sampling -> Null Distribution -> P-value/LFDR Estimation -> π0-thresholding) -> Sparse Attention Weights -> Weighted Values -> Residual & Feed-Forward -> Output

**Critical Path**: (1) Compute attention scores. (2) Generate bootstrap samples to build null distribution. (3) Compute per-score p-values and LFDR. (4) Estimate π0 and apply threshold to zero out non-significant scores. (5) Use sparse attention for downstream computation.

**Design Tradeoffs**:
- Bootstrap sample size: More samples yield accurate null estimates but increase computational cost.
- Thresholding: π0 estimation may be sensitive to the proportion of true nulls; alternative FDR methods could be considered.
- Integration: Training-time ARB allows the model to adapt to sparsity but adds overhead; post-hoc application is cheaper but may not optimize task performance.
- Sparsity level: Controlled by π0-threshold; trade-off between interpretability (higher sparsity) and retention of relevant information.

**Failure Signatures**:
- Over-sparsity: Excessive zeroing leads to performance drop on downstream tasks (e.g., classification accuracy) and loss of important token relationships.
- Under-sparsity: Threshold too low, residual noise, interpretability gains minimal.
- Computational bottleneck: Bootstrapping memory/time becomes prohibitive for large batch sizes or high-resolution inputs.
- Domain mismatch: Null distribution estimated on training data may not generalize to test data with different statistics, causing mis-calibrated thresholds.

## Open Questions the Paper Calls Out
The paper does not explicitly enumerate open questions, but its limitations and future work suggestions highlight several unresolved issues:
- Computational overhead: The memory and time cost of bootstrapping is not quantified, especially for large batch sizes or high-resolution inputs.
- Generalizability: ARB's effectiveness on other vision transformer variants (e.g., DeiT, Swin) and on other modalities (e.g., NLP) is unknown.
- Validation: Independent validation on standard benchmarks (e.g., ImageNet-1k) and comparisons with other sparsity methods (e.g., Top-k pruning, SparseBERT) are needed.
- Training integration: The trade-offs of using ARB during training (allowing the model to adapt to sparsity) versus post-hoc application require further study.
