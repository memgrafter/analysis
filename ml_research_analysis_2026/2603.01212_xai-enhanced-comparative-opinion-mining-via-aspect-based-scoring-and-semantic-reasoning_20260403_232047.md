# XAI-enhanced Comparative Opinion Mining via Aspect-based Scoring and Semantic Reasoning

## Quick Facts
- arXiv ID: 2603.01212
- Source URL: https://arxiv.org/abs/2603.01212
- Reference count: 17
- Primary result: XCom achieves state-of-the-art Macro/Micro F1 (58.56% / 58.38%) on SUDO dataset, outperforming fine-tuned T5 by nearly 3 points, with SHAP explanations validated by faithfulness.

## Executive Summary
This paper introduces XCom, an explainable AI model for comparative opinion mining from same-user reviews. It addresses the lack of transparency in transformer-based models by integrating an aspect-based rating predictor, a semantic analyzer, and a SHAP-based explainability module. XCom processes reviews into aspect-specific sentence pairs, then fuses score-based and semantic-based classification signals to predict comparative opinions (better, similar, worse). Evaluated on the SUDO beer review dataset, XCom achieves SOTA performance and provides token-level explanations that are shown to be faithful via removal experiments.

## Method Summary
XCom follows a modular pipeline: Reviews are split into sentences, and four BERT-based binary classifiers filter sentences into four aspects (appearance, aroma, palate, taste). For each aspect, the filtered sentence pairs undergo dual-path classification: a score-based branch computes minimum sentiment ratings (via adjective dictionary or XGBoost fallback), while a semantic branch encodes the raw sentences. Their probability distributions are summed to yield the final comparative label. A SHAP module post-hoc explains the decision by masking tokens and measuring output impact. The model uses BERT-base encoders (~110M parameters) and is trained end-to-end for each branch before fusion.

## Key Results
- SOTA on SUDO: Macro-F1 58.56%, Micro-F1 58.38%, ~3 points above fine-tuned T5.
- SHAP explanations validated: significant Macro-F1 drop when removing top-ranked adjective tokens, demonstrating faithfulness.
- Superior computational efficiency compared to large general-purpose LLMs.

## Why This Works (Mechanism)

### Mechanism 1: Dual-path fusion
**Claim:** Performance gain stems from fusing two complementary classification signals—a score-based predictor using aspect-specific rating aggregation and a semantic-based classifier using direct sentence-pair encoding—via probability summation.
**Mechanism:** For each aspect, the model independently processes structured input. The score-based branch computes minimum sentence rating scores (via adjective dictionary or XGBoost on TF-IDF) to create a numeric comparison vector. The semantic branch encodes the raw sentence pair. Their final class probabilities (after softmax) are summed to produce the output distribution. This design leverages both explicit sentiment intensity and implicit comparative cues.
**Core assumption:** The two pathways capture non-redundant, complementary signals; combining them robustifies prediction.
**Evidence anchors:** [section 3.2] defines fusion rule `pfinal = pr + ps`; [section 5.1] ablation shows removing semantic branch causes ~30% F1 drop and improper fusion drops >16%.
**Break condition:** If fusion yields no gain over the single best branch on a new dataset, the complementary signal assumption fails.

### Mechanism 2: SHAP-based explanations
**Claim:** The integrated SHAP module provides faithful, token-level attributions, validated by a faithfulness evaluation showing significant performance degradation on removal of top-ranked tokens.
**Mechanism:** SHAP approximates model output with a linear model, computing Shapley values by evaluating output changes when tokens are replaced with `[MASK]` across feature subsets. Absolute values rank token importance. Faithfulness is measured by Macro-F1 drop when sequentially removing top-k vs. bottom-k adjective tokens.
**Core assumption:** Token-level Shapley values from masking accurately reflect model reliance for comparative decisions.
**Evidence anchors:** [section 3.3] describes masking approach; [section 4.4] Figure 5 shows steep F1 drop for top-k removal but slow decline for bottom-k.
**Break condition:** If top-k and bottom-k removal curves converge, SHAP attributions are not faithful.

### Mechanism 3: Aspect-based pre-processing
**Claim:** The aspect classification module reduces noise by filtering reviews into aspect-specific comparable units, critical for downstream modules.
**Mechanism:** Raw review pairs are segmented; four BERT classifiers label each sentence per aspect. Only sentences labeled 1 for a given aspect are retained, forming aspect-specific tuples `Pua = (s1a, s2a)`. This structured input feeds dual classifiers.
**Core assumption:** Accurate sentence-level aspect filtering is necessary; errors propagate catastrophically.
**Evidence anchors:** [section 3.1] details BERT classifiers; [section 4.2/Table 2] aspect classification F1 ~95.38%; [section 5.1] ablation: removing aspect classification causes ~17% F1 drop.
**Break condition:** If aspect classification F1 falls below ~80%, downstream performance collapses disproportionately.

## Architecture Onboarding

**Component map:**  
Aspect Classifiers (4x BERT) → Aspect-Tuple Builder → (parallel:  
  Path A: Rating Predictor (Adjective Scorer / XGBoost fallback → min aggregation) → Score-Based Classifier (Transformer + linear layer)  
  Path B: Semantic-Based Classifier (Transformer + linear layer))  
→ Fusion Module (softmax sum → argmax) → Final Aspect Labels  
→ (post-hoc) SHAP Explainer (wraps pipeline per aspect)

**Critical path:**  
1. Input reviews split into sentences.  
2. Four BERT aspect classifiers label sentences; only those matching aspect `a` are kept.  
3. For each aspect `a`, aspect-tuple builder pairs sentences from review1 and review2.  
4. Rating predictor computes numeric scores per review; score-based branch encodes `[CLS] score1 [SEP] score2 [SEP]`.  
5. Semantic branch encodes `[CLS] s1a [SEP] s2a [SEP]`.  
6. Both branches produce logits; softmax probabilities summed; argmax gives comparative label.  
7. SHAP explains the final label for an aspect by masking tokens and measuring impact.

**Design tradeoffs:**  
- Modularity vs. Cascading Errors: Clear stages aid debugging but propagate errors; ablation quantifies the cost.  
- Interpretability vs. Computational Cost: SHAP adds post-hoc computation; base model kept small (~110M) vs. large LLMs for efficiency.  
- Rule-Based (min-score) vs. Learned Scoring: Heuristic captures "weakest link" in beer reviews; XGBoost fallback for OOV cases; may not generalize.

**Failure signatures:**  
- Aspect misclassification: Sentences filtered into wrong aspect tuples, producing semantically incoherent comparisons.  
- Rating score under/over-estimation: Incorrect dictionary scoring or XGBoost errors skew numeric branch.  
- Poor SHAP faithfulness: Top-k and bottom-k token removal curves converge; explanations not aligned with model dependence.

**First 3 experiments:**  
1. **Aspect classifier verification:** Fine-tune the four BERT classifiers on SUDO sentences; compute per-aspect and macro F1. Expect ~95% (as in Table 2).  
2. **Score-branch isolation:** For a held-out set, compute rating scores and compare `lr` vs. `ls` distributions; confirm complementary signals and fusion benefit.  
3. **SHAP faithfulness replication:** Compute SHAP values for test instances; sequentially remove top-k and bottom-k adjective tokens; plot Macro-F1 drop vs. k. Must reproduce steep early drop for top-k and shallow decline for bottom-k.

## Open Questions the Paper Calls Out

- **End-to-end redesign:** How can XCom be restructured as a unified model to eliminate cascading errors from separate modules? The authors propose future work on a joint learning framework.  
- **Structured cross-review explanations:** How can SHAP be enhanced to provide comparative insights across both reviews, e.g., linking key tokens? They are exploring a graph-based approach.  
- **Domain generalization:** To what extent does XCom generalize beyond beer reviews to other product domains? The SUDO dataset is domain-limited; experiments on diverse datasets are needed.  
- **Cross-aspect dependencies:** How can interdependencies between aspects (e.g., correlated satisfaction) be modeled to improve accuracy and explanation coherence? A graph neural network or shared attention layer is suggested.

## Limitations
- Unknown hyperparameters (optimizer, scheduler, splits) hinder faithful replication.
- SHAP faithfulness evaluation focuses only on adjective tokens, biasing the assessment.
- Pipelined architecture is vulnerable to cascading errors from early-stage mistakes.

## Confidence
- Performance superiority (SOTA on SUDO): Medium
- Dual-path fusion mechanism: Medium
- SHAP faithfulness: Low
- Aspect preprocessing effectiveness: High
