# FedAvg-Based CTMC Hazard Model for Federated Bridge Deterioration Assessment

## Quick Facts
- arXiv ID: 2602.20194
- Source URL: https://arxiv.org/abs/2602.20194
- Reference count: 22
- Primary result: Federated CTMC hazard model converges to NLL ~0.76–0.80 in 50 rounds with negligible communication (<25 KB/round) on synthetic heterogeneous bridge data.

## Executive Summary
This paper introduces a federated learning framework for estimating a Continuous-Time Markov Chain (CTMC) hazard model to assess bridge deterioration across multiple municipalities. Using FedAvg, each municipality locally optimizes a log-linear hazard model with three transition types and three covariates via mini-batch SGD on the CTMC log-likelihood, uploading only a 12-dimensional pseudo-gradient per communication round. The server aggregates updates with sample-weighted averaging, gradient clipping, and momentum. Experiments on synthetic data show stable convergence of the global negative log-likelihood to approximately 0.76–0.80 within 50 rounds, with decreasing gradient norms as user scale increases and minimal communication overhead. The approach enables collaborative model training while keeping sensitive inspection records private.

## Method Summary
The method adapts FedAvg to a CTMC hazard model where each user (municipality) holds local bridge inspection records with covariates (age, coastline distance, deck area) and observed state transitions. The hazard for each transition type is log-linear: Λ_k(t|x) = exp(β_k^T x). Users minimize the local negative log-likelihood (Eq. 5) over mini-batches using SGD for K=3 steps with learning rate η_local=0.01. Instead of sending full model updates, they compute a pseudo-gradient g_u = (β_init - β_K)/η_local and upload it with their local sample count n_u. The server aggregates these via sample-weighted average ¯g_r = Σ n_u g_u / Σ n_u, applies ℓ2 clipping (δ=1.0) and momentum (µ=0.9), then updates the global β with η_global=0.05. This process repeats for R=50 rounds with 10% user participation per round. The framework preserves data sovereignty as only gradients, not raw data, are shared.

## Key Results
- Average global negative log-likelihood converges to ~0.76–0.80 within 50 communication rounds across user scales (500–4,000).
- Aggregated gradient norm decreases monotonically with user scale (from 0.354 to 0.140), indicating improved stability.
- Communication overhead remains negligible: <25 KB per round for 400 users due to 12-dimensional gradient transmission.

## Why This Works (Mechanism)
The method works because FedAvg efficiently handles heterogeneous data distributions via sample-weighted aggregation, while the pseudo-gradient formulation reduces communication bandwidth. Momentum and gradient clipping stabilize training across varying user scales, preventing outlier updates from dominating. The CTMC log-likelihood is convex in β, ensuring local SGD steps move toward the global optimum. Partial participation (10%) further reduces communication costs without sacrificing convergence, as the large user base provides sufficient gradient signals each round. The design inherently incentivizes participation: each user gains access to a global model trained on diverse data, which would be unattainable from their local (region-specific) data alone.

## Foundational Learning
- **Continuous-Time Markov Chain (CTMC)**: Models state transitions as continuous-time process with transition intensities (hazards). *Why needed*: Captures deterioration as time-dependent state changes between condition states. *Quick check*: Verify hazard function Λ_k(t|x) = exp(β_k^T x) and log-likelihood integration over observed intervals (Eq. 5).
- **Hazard Model**: Parametric form for transition intensities in CTMC. *Why needed*: Allows covariate effects (age, location, size) to modulate transition rates. *Quick check*: Ensure log-linear specification with one β per transition type and correct handling of absorbing state.
- **Federated Averaging (FedAvg)**: Distributed optimization where users perform local updates and server averages models. *Why needed*: Enables training without centralizing sensitive data. *Quick check*: Confirm partial user sampling per round and model broadcast/aggregation cycle.
- **Pseudo-gradient**: Uploading (β_init - β_K)/η_local instead of full model. *Why needed*: Reduces communication to fixed-size vector independent of local steps. *Quick check*: Check that local updates use constant η_local and pseudo-gradient is scaled accordingly.
- **Sample-weighted Averaging**: Aggregating user updates weighted by local sample counts n_u. *Why needed*: Accounts for heterogeneous dataset sizes, preventing bias from uniform averaging. *Quick check*: Verify server computes ¯g_r = Σ n_u g_u / Σ n_u, not simple mean.
- **Gradient Clipping and Momentum**: ℓ2 norm clipping (δ=1.0) and momentum (µ=0.9) on server. *Why needed*: Clipping stabilizes against outlier gradients; momentum accelerates convergence in noisy federated setting. *Quick check*: Apply clipping before momentum update; ensure momentum accumulates over rounds.

## Architecture Onboarding
Component map: User Data -> Local SGD (K steps) -> Pseudo-gradient Upload -> Server Aggregation (weighted avg, clip, momentum) -> Global Model Broadcast -> User Data

Critical path: (1) Server selects ρ|U| random users and sends current β; (2) Each user runs K mini-batch SGD on local NLL, computes g_u; (3) Users upload (g_u, n_u); (4) Server computes ¯g_r, clips, updates momentum v_r, then β; (5) Repeat for R rounds.

Design tradeoffs: 
- Pseudo-gradients vs. full model: reduces communication but assumes constant η_local; may lose adaptivity.
- Partial participation (ρ=10%): lowers communication but requires sufficient users for gradient diversity; scale experiments show robustness.
- Clipping threshold δ=1.0: prevents large updates but may underrepresent strong local signals; tuned for synthetic data.
- Momentum µ=0.9: speeds convergence but introduces inertia; may overshoot if local gradients noisy.

Failure signatures:
- NLL stagnates >1.5: likely CTMC log-likelihood bug or too high η_global.
- Gradient norm ∥¯g_r∥ remains large (>10): inadequate clipping or heterogeneous data imbalance.
- Final β offset from expected (e.g., β₀ positive): incorrect sample-weighted aggregation or normalization.
- Communication >25 KB/round: transmitting full models or extra metadata.

First experiments:
1. Single-user CTMC log-likelihood gradient check: validate local update direction matches analytical gradient on synthetic batch.
2. Two-user FedAvg round: confirm server aggregation yields correct β update when users have equal n_u.
3. 500-user, 10-round trial: reproduce reported NLL drop to ~0.9 and gradient norm decrease; scale later.

## Limitations
- Evaluation solely on synthetic data; real bridge networks may exhibit different heterogeneity, missing data, and spatial correlations.
- Implementation ambiguities: local-max normalization details, mini-batch strategy, exact server aggregation formula require code inspection.
- No formal privacy analysis beyond raw data non-sharing; vulnerable to gradient inversion attacks.
