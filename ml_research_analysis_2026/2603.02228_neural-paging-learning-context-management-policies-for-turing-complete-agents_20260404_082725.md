# Neural Paging: Learning Context Management Policies for Turing-Complete Agents

## Quick Facts
- **arXiv ID**: 2603.02228
- **Source URL**: https://arxiv.org/abs/2603.02228
- **Reference count**: 31
- **Primary result**: Introduces a hierarchical architecture with a learned Page Controller that decouples reasoning from memory management, reducing computational complexity from O(N²) to O(N·K²) and demonstrating robustness with mild fault cascades on synthetic traces.

## Executive Summary
The increasing demand for long-horizon reasoning in LLM-based agents is hindered by the quadratic complexity of self-attention over extended contexts. Neural Paging proposes a hierarchical architecture that separates the reasoning process from memory management. At the core is a learned Page Controller that selectively loads relevant “pages” of past context into a fixed-size active window, thereby bounding the effective context seen by the reasoner.

The authors prove that under a bounded context reuse assumption (parameter Kb), the architecture reduces the worst-case computational complexity from O(N²) to O(N·K²). They also establish a robustness bound (Theorem 4) showing that faults (e.g., page evictions) cause only mild cascades. On synthetic traces with Kb=8, the bound is validated: the empirical cascade factor is ~1.13 versus a worst-case of 9. Moreover, the empirical competitive ratio of LRU on these traces is ~1.9, substantially lower than the theoretical worst-case bound of 8, suggesting significant slack for improvement via learned policies. These findings motivate the use of learned context selection for efficient, robust long-horizon agents.

## Method Summary
The Neural Paging architecture comprises two main components: a Page Controller and a Reasoner. The Reasoner is typically an LLM that operates on a fixed-size context window. All past interactions are stored in a large memory store, partitioned into fixed-size pages. The Page Controller, implemented as a neural network, observes the current state (including the active context and possibly the task) and decides which pages to load into the active window. This decision is made at each step before the Reasoner generates an action. The system thus decouples memory management from reasoning.

The theoretical analysis introduces the bounded context reuse parameter Kb, defined as the maximum number of distinct pages referenced between two accesses to the same page. Under this assumption, the authors prove that the total number of page references (and hence the computational load on the Reasoner) scales as O(N·K²), where N is the trajectory length and K is the number of pages that fit in the active window. The robustness bound (Theorem 4) shows that a single page fault can cause at most O(Kb) additional faults. Empirically, the authors train the Page Controller on synthetic traces with known fault patterns and evaluate on held-out traces. They compare against LRU and measure competitive ratios and fault cascade factors.

## Key Results
- **Complexity reduction**: The hierarchical design achieves O(N·K²) computational complexity under bounded context reuse, a significant improvement over the O(N²) cost of naive full-context attention.
- **Robustness validation**: On synthetic traces with Kb=8, the empirical fault cascade factor is ~1.13, far below the worst-case prediction of 9, confirming mild error propagation.
- **Competitive slack**: The LRU baseline’s empirical competitive ratio is ~1.9 on these traces, substantially lower than the worst-case bound of 8, indicating room for learned policies to further close the gap.

## Why This Works (Mechanism)
The mechanism hinges on the decoupling of concerns: the Page Controller specializes in predicting which context pages will be useful for future reasoning, while the Reasoner focuses on decision-making within a fixed window. By limiting the Reasoner’s input to a small set of pages, attention becomes linear in the number of pages rather than the total history. The learned policy implicitly optimizes for long-term utility, reducing unnecessary page loads and thus the number of attention operations. The bounded context reuse assumption further ensures that the number of distinct pages referenced across the trajectory is limited, enabling the O(N·K²) bound. Empirically, the mild fault cascades indicate that even when a needed page is evicted, the system can often recover because other pages contain sufficient information, a property likely enhanced by the learned selection strategy.

## Architecture Onboarding
**Component map**: Memory Store -> Page Controller -> Active Context Buffer -> Reasoner -> Action; Environmental feedback updates Memory Store.

**Critical path**:
1. Agent receives new observation and appends it to Memory Store.
2. Page Controller selects a set of pages from Memory Store to load into Active Context Buffer.
3. Reasoner consumes Active Context Buffer to produce an action.
4. Action executes, generating next observation and reward, which are appended to Memory Store, and the loop repeats.

**Design tradeoffs**:
- Page size: Smaller pages give finer granularity but increase management overhead; larger pages reduce overhead but may waste context space.
- Number of active pages (K): Larger K improves recall but increases computational cost O(N·K²).
- Learned policy vs. heuristic: Learned policies can adapt to task structure but require training data and risk overfitting; heuristics (e.g., LRU) are simple and robust but suboptimal.
- Bounded context reuse (Kb) assumption: Enables theoretical guarantees but may not hold for all tasks; if Kb is large, the O(N·K²) bound weakens.

**Failure signatures**:
- Sudden drop in task success rate after a specific number of steps, suggesting a cascading error from missed context.
- High page fault rate (pages loaded but immediately evicted).
- Large gap between the policy’s performance and an offline optimum on a trace, indicating poor page selection.

**First experiments**:
1. **Synthetic trace training**: Train the Page Controller on generated traces with known optimal page selection and measure its ability to minimize page faults and downstream errors.
2. **Baseline comparison**: Compare the learned policy against LRU on the same synthetic traces, reporting competitive ratios and robustness to injected faults.
3. **Simple long-horizon benchmark**: Deploy the full system on a task requiring memory (e.g., a partially observable grid-world) to evaluate end-to-end success rate and context efficiency relative to a full-context baseline.

## Open Questions the Paper Calls Out
- Does the bounded context reuse parameter (Kb) remain small and bounded on natural, open-world agent trajectories, or does the O(N·K²) complexity guarantee weaken significantly?
- How does the robustness bound (Theorem 4) hold under realistic error models involving perceptual aliasing, partial observability, or environment stochasticity, rather than idealized synthetic faults?
- Can a learned Page Controller policy trained on synthetic traces generalize to diverse, long-horizon tasks and consistently outperform strong adaptive heuristics (e.g., LRU) in terms of both competitive ratio and end-task performance?

## Limitations
- The theoretical O(N·K²) complexity depends on a bounded context reuse parameter Kb; this assumption is not validated on natural, open-world agent trajectories where Kb may be larger or unbounded.
- Experimental validation used synthetic traces with controlled fault patterns, which may not capture the complexity of real-world cascading errors arising from partial observability or environment stochasticity.
- The advantage of learned policies over baselines like LRU remains unproven on diverse, long-horizon tasks; existing results are limited to synthetic data.

## Confidence
- **Theoretical O(N·K²) reduction**: Medium (depends on Kb assumption; not tested on natural traces).
- **Robustness bound (Theorem 4)**: Medium (synthetic validation supportive but not conclusive for real dynamics).
- **LRU competitive ratio slack**: Medium (observed only on synthetic traces).

## Next Checks
1. **Test Kb Stability**: Run the hierarchical architecture on established long-horizon agent benchmarks (e.g., WebShop, AgentBench) to measure empirical distribution of context reuse and verify if Kb remains small and bounded.
2. **Fault Cascade Stress Test**: Introduce realistic error models (e.g., perceptual aliasing, transient sensor noise) into agent trajectories and measure empirical cascade severity versus Theorem 4’s predicted mild faults.
3. **Policy Generalization**: Train the Page Controller on diverse tasks (beyond synthetic traces) and compare its context selection performance against adaptive baselines (e.g., ARC, LRU) using task success rate and context efficiency metrics.
