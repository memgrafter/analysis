# Code World Models for Parameter Control in Evolutionary Algorithms
## Quick Facts
- **arXiv ID:** 2602.22260
- **Source URL:** https://arxiv.org/abs/2602.22260
- **Reference Count:** 21
- **Primary Result:** CWM-greedy achieves 100% success on deceptive Jump_k landscapes where all adaptive baselines fail (0%), without requiring oracle knowledge.

## Executive Summary
This paper introduces Code World Models (CWMs) for adaptive parameter control in evolutionary algorithms. The method uses an LLM to synthesize a Python simulator from suboptimal optimizer trajectories, then applies greedy one-step planning to select mutation strength. On standard benchmarks (LeadingOnes, OneMax), it nears optimal performance. On the deceptive Jump_k benchmark, it achieves perfect success where all baselines fail. On rugged NK-Landscapes, it outperforms all baselines when provided empirical transition statistics, using less data and generalizing better than DQN.

## Method Summary
The approach consists of three stages: (1) collect diverse offline trajectories of (1+1)-RLS_k on the target problem; (2) prompt an LLM (Claude Sonnet 4) with a problem description and a stratified sample of transitions (or an empirical transition table for complex landscapes) to synthesize a `SynthesizedCWM` class implementing `predict_next_state`, `evaluate_state`, etc.; (3) at runtime, for current state *s*, query the CWM for each legal *k*, evaluate predicted next states, and select *k* maximizing expected fitness. The "normalized_fitness" trick enables continuous scoring. For Jump_k and NK, an empirical table of P(improve) and mean Δf per (fitness bin, *k*) is included in the prompt.

## Key Results
- On LeadingOnes/OneMax (n=50), CWM-greedy achieves within 2–6% of the optimal policy.
- On Jump_k (deceptive), CWM-greedy reaches 100% success rate; all adaptive baselines (including EAα) achieve 0%.
- On NK-Landscape (rugged, no closed-form), CWM-greedy with empirical table achieves mean best fitness 36.94 vs. 36.32 for best baseline (p<0.001).
- Compared to DQN: uses less data (200 vs. 500 trajectories), higher success (100% vs. 58%), and generalizes to unseen *k* (78% vs. 0% for *k*=3).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Suboptimal optimizer trajectories contain sufficient information to synthesize a simulator that accurately predicts fitness improvements under different mutation strengths.
- **Mechanism:** The LLM is prompted with a mathematical problem description and a stratified sample of state-action transitions from diverse, non-oracle policies. It generates Python code encoding a probabilistic model (e.g., hypergeometric distribution) of how bit-flip mutations change fitness. The `normalized_fitness` trick enables the model to output continuous expected fitness gains, allowing discrimination between actions.
- **Core assumption:** The optimizer's dynamics are Markovian with respect to fitness (or sufficient state representation), and the LLM can infer the underlying generative process from examples.
- **Evidence anchors:** CWM achieves policy correlations τ=0.784/ρ=0.916 on LeadingOnes, recovering the optimal descending ramp from non-optimal demonstrations; on Jump_k, the empirical transition table enables recognition that only *k*=k_jump yields positive drift at the valley edge.

### Mechanism 2
- **Claim:** Greedy one-step lookahead over the synthesized CWM is sufficient for high-performance parameter control, eliminating the need for MCTS or multi-step planning.
- **Mechanism:** The CWM provides a differentiable score (expected next fitness) for each candidate *k* at the current state. The planner executes *k* = argmax_k CWM.eval(CWM.predict(s, k)). Since the (1+1)-RLS_k is memoryless and the optimal adaptive policy for these benchmarks is effectively greedy in expectation (maximizing single-step drift), planning horizon 1 is optimal.
- **Core assumption:** The optimal control policy is myopic (or near-myopic) with respect to expected fitness gain per step. The CWM's one-step predictions are accurate enough that myopic planning does not get trapped by short-term deceptions.
- **Evidence anchors:** CWM-greedy outperforms CWM-MCTS on LeadingOnes (1,045 vs. 1,273 steps); MCTS rollouts collapse to *k*=1, indicating the model's gradients are reliable and planning depth adds no value.

### Mechanism 3
- **Claim:** Augmenting the LLM prompt with empirical transition statistics (P(improve|fitness,k), mean Δf) enables CWM synthesis for landscapes with no closed-form mathematical model.
- **Mechanism:** When a mathematical description is insufficient (e.g., rugged NK-Landscape), the prompt includes a pre-computed lookup table derived from training trajectories. The LLM integrates this table into the CWM's `predict_next_state` method, effectively creating a data-driven simulator that generalizes the empirical dynamics.
- **Core assumption:** The empirical transition table, if sufficiently detailed and stratified by fitness and *k*, captures the essential dynamics of the optimizer on the landscape. The LLM can correctly interpret and code this tabular data into a functional simulator.
- **Evidence anchors:** On NK, CWM with empirical table achieves τ=0.553 vs. τ=-0.137 without the table; mean best fitness 36.94 vs. ≤35.0 without table.

## Foundational Learning
- **Concept: Markov Decision Process (MDP) Simplification**
  - **Why needed here:** The (1+1)-RLS_k is treated as a stateful process where the next state depends only on current fitness and chosen *k*. The CWM-greedy approach assumes the optimal policy is greedy on the expected one-step reward in this MDP. Understanding this simplification is key to why one-step planning works.
  - **Quick check:** If the state included more than just fitness (e.g., bitstring pattern or stagnation counter), would a one-step greedy planner still be optimal? (Not necessarily; the paper assumes fitness is a sufficient statistic, which holds for LeadingOnes/OneMax but may not for all landscapes.)

- **Concept: Normalized Fitness as a Continuous Score**
  - **Why needed here:** Unlike integer fitness ranks, normalized continuous fitness (e.g., f/n) allows the CWM to output fine-grained expected values for `evaluate_state`. This is crucial for distinguishing between actions that yield the same integer improvement probability but different expected magnitudes.
  - **Quick check:** Why can't the CWM simply predict P(improvement) and choose the action with highest probability? (Because maximizing improvement probability alone is not optimal; maximizing expected fitness gain E[Δf] is the correct objective, which requires continuous-valued predictions.)

- **Concept: Hypergeometric Dynamics for Bit-Flip Mutations**
  - **Why needed here:** For Jump_k, the probability of escaping the deceptive valley depends on hypergeometric probabilities: selecting exactly the *k* specific zero-bits among *n*. The CWM must learn or be prompted to encode this combinatorial relationship to recognize that only *k*=k_jump has non-zero probability of improvement at the valley edge.
  - **Quick check:** If the CWM were given only trajectories from random policies (which rarely hit the valley edge), could it still infer the correct hypergeometric model? (The paper enriches the prompt with an empirical transition table that includes valley-edge statistics, so the LLM doesn't have to infer combinatorics solely from sparse valley-edge visits.)

## Architecture Onboarding
- **Component map:**
  Trajectory Collector -> Prompt Engineer -> LLM Synthesis Engine -> Validator -> Greedy Planner -> Empirical Statistics Module

- **Critical path:**
  1. Collect diverse trajectories covering all fitness regimes and *k* values.
  2. Compute empirical transition table (if needed).
  3. Build prompt with description + trajectory samples + empirical table.
  4. Call LLM; validate and refine synthesis until code executes without error.
  5. Deploy greedy planner; monitor CWM's action合理性.
  6. Evaluate on benchmark with fixed budget; compare to baselines.

- **Design tradeoffs:**
  - Single-shot vs. iterative synthesis: Single-shot is fast (~€0.04) but risks incorrect code; iterative may overfit to validation set.
  - Prompt content: Math description alone works for unimodal; empirical table needed for deceptive/rugged. Including full trajectories blows up token count; stratified 30 samples + summary table is efficient.
  - Planning horizon: Greedy 1-step is sufficient here; MCTS adds 100× overhead with no gain in Markovian settings. If dynamics require multi-step strategy, MCTS may be needed.

- **Failure signatures:**
  - Validation failures: LLM-generated code crashes on `predict_next_state`. Signal: refinement loop exceeds 5 attempts. Fix: improve prompt formatting, ensure empirical table covers all bins.
  - Poor correlation on held-out transitions: τ < 0.5. Signal: CWM's action rankings disagree with true improvements. Fix: increase trajectory diversity, adjust binning.
  - Generalization collapse on unseen *k*: Success rate drops to 0% for *k* ≠ training value. Signal: CWM encodes memorization rather than parametric model. Fix: ensure prompt includes multiple *k* values.
  - Stagnation on high-fitness states: CWM always selects *k*=1 prematurely. Signal: empirical table lacks data for high-fitness, large-*k* combinations. Fix: oversample transitions from near-optimum states.

- **First 3 experiments:**
  1. **LeadingOnes sanity check:** Train CWM on n=50 with standard trajectory set. Validate that synthesized CWM reproduces the descending *k* ≈ ⌊n/(i+1)⌋ ramp and achieves mean steps within 10% of optimal (983). Expected: ~1,045 steps, τ>0.75.
  2. **Jump_k valley-edge verification:** Run CWM-greedy on Jump_k (*k*_jump=2) and inspect its action at fitness = *n* (valley edge). It must select *k*=2 with probability 1.0. Also check success rate: should be ~100% vs. 0% for EAα.
  3. **NK empirical table ablation:** Train two CWM on same NK trajectories: one with empirical table in prompt, one without. Compare mean best fitness across 15 instances. Expected: with table ~36.94, without ~≤35.0 (worse than static_5).

## Limitations
- Prompt opacity: Exact wording, delimiters, and few-shot examples are not disclosed, hindering exact replication.
- LLM inference settings: Temperature, top_p, and validation tolerances are unspecified; performance may be sensitive.
- Scalability: Experiments use *n*=50; no evidence that approach scales to larger or continuous domains.
- Transition table limits: The table’s size and binning may not extend to higher dimensions.

## Confidence
- **CWM-greedy performance dominance:** Medium (strong empirical results but dependent on unreported prompt/validation specifics).
- **LLM synthesis accuracy from suboptimal trajectories:** Medium (high correlations on unimodal benchmarks, but relies on LLM version and problem description).
- **Sufficiency of greedy one-step planning:** Medium-Low (validated only on Markovian, myopia-friendly landscapes; may fail on strategic, non-Markovian problems).
- **Need for empirical transition statistics on rugged landscapes:** High (ablation shows dramatic drop without the table, confirming its critical role).

## Next Checks

2. **Transition table granularity ablation (NK landscape):** Vary the number of fitness bins (5, 10, 20) and measure mean best fitness; expect significant degradation with coarse bins (<10).
3. **Partially observable test:** Hide the valley-edge fitness in a Jump_k variant; assess whether CWM-greedy still achieves >90% success rate, probing the limits of myopic planning under partial observability.
