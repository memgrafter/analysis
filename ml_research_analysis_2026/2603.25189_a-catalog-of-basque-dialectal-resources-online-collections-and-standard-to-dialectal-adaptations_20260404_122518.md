# A Catalog of Basque Dialectal Resources: Online Collections and Standard-to-Dialectal Adaptations

## Quick Facts
- **arXiv ID:** 2603.25189  
- **Source URL:** https://arxiv.org/abs/2603.25189  
- **Reference count:** 0  
- **Primary result:** Created a catalog of Basque dialectal resources and produced two adapted datasets: Parallel XNLIvar (manual gold-standard NLI) and BasPhyCowest (automatic physical commonsense), with evaluation showing both contain significant dialectal features.

## Executive Summary
This paper tackles data scarcity for Basque dialects by first compiling a comprehensive catalog of existing online resources (news, radio, tweets, dictionaries, videos) to improve discoverability. It then presents two approaches to create dialectal data: manual adaptation of the XNLI NLI dataset into three Basque dialects (Western, Central, Navarrese-Lapurdian), yielding a high-quality parallel gold-standard test set (Parallel XNLIvar); and automatic adaptation of a physical commonsense dataset (BasPhyCo) into Western dialect using LLM prompting (BasPhyCowest), followed by a native-speaker pairwise evaluation that confirms the presence of dialectal features. The work provides both a resource map for the research community and concrete datasets for evaluating dialectal NLP.

## Method Summary
The authors first aggregated fragmented Basque dialectal content into a structured catalog with metadata (source type, dialect, modality, license). For manual adaptation, native-speaking linguists translated standard NLI items (XNLIeu) into target dialects while preserving semantics, generating 5,000 parallel premise-hypothesis pairs (Parallel XNLIvar). For automatic adaptation, they used the Latxa-It-70B LLM with few-shot prompts to transform Standard Basque sentences from BasPhyCo into Western dialect. A deduplication step ensured identical source sentences mapped to identical adaptations across stories. The automatic outputs were validated via a pairwise comparison task where native speakers judged which of two sentences (standard vs. adapted) was more dialectal, with Cohen’s κ measuring annotator agreement.

## Key Results
- Cataloged diverse Basque dialectal resources across modalities into a single inventory, highlighting many sources with unclear or restrictive licensing.
- Parallel XNLIvar: 5,000 NLI instances manually adapted into three dialects; Levenshtein distances from Standard Basque: Western 15.56, Central 24.73, Navarrese-Lapurdian 29.36.
- BasPhyCowest: Automatic adaptation via LLM prompting; manual evaluation (Cohen’s κ=0.71) found both orthographic and non-standard prompts produced significantly more dialectal features than the standard baseline, with non-standard orthography yielding slightly more dialectal output.

## Why This Works (Mechanism)
**Mechanism 1: Resource Cataloging as Discoverability Fix**  
Cataloging aggregates distributed, heterogeneous dialectal content into a structured inventory, reducing the "search cost" for researchers. This makes previously fragmented resources findable and assessable, directly addressing a key bottleneck in dialectal NLP. Break condition: licensing barriers or link rot render entries unusable.

**Mechanism 2: Manual Translation for Gold-Standard Parallel Data**  
Native-speaker linguists translate standard test items into dialects, controlling for semantic content while varying form. This captures authentic syntactic, morphological, and lexical features, creating a reliable benchmark for evaluating dialectal NLP performance. Break condition: the process is slow, expensive, and yields only a small-scale, written dataset that may not reflect spontaneous speech.

**Mechanism 3: LLM Prompting with Human-in-the-Loop Validation**  
Few-shot prompts guide an LLM to transform standard text into dialect. A subsequent pairwise evaluation by native speakers validates the dialectalness of outputs, leveraging human judgment to compensate for potential LLM errors. This offers a scalable path to "silver-standard" data. Break condition: systematic LLM failures (e.g., untransformed sentences) and validation limited to one dialect reduce generalizability.

## Architecture Onboarding
**Component map:**  
Resource Catalog -> Adaptation Pipeline (Manual: Native Translators / Automatic: LLM Prompting) -> Validation Framework (Pairwise Native Speaker Evaluation) -> Distribution Layer (Public Repository)

**Critical path:** Catalog Identification -> Data Sourcing/Cleaning -> Adaptation (Manual or Automatic) -> Native Speaker Evaluation -> Analysis & Release. The evaluation step is a critical gating function; without it, adapted data quality remains unknown.

**Design tradeoffs:**  
- Manual vs. Automatic: Manual yields gold-standard quality but is slow and small-scale (5k instances); automatic is fast/scalable (356 stories) but requires rigorous validation and has error modes.  
- Evaluation: Pairwise comparison is intuitive but may not capture all dialectal features; the "dialectalness" metric is perceptual, not a comprehensive linguistic inventory.  
- Scope: Focus on written texts excludes spoken variation (e.g., uncataloged videos), limiting coverage.

**Failure signatures:**  
- Catalog: Dead links, missing licenses (many N/A entries), inability to scrape dynamic content.  
- Manual: Inconsistent dialectal rule application across translators, individual translator bias.  
- Automatic: High "Neither" selections indicate failed adaptation; disagreement on common words (e.g., *heldu* vs. *iritsi*) signals vague feature boundaries.

## Open Questions the Paper Calls Out
- **To what extent do LLM adaptation errors stem from prompt limitations vs. model knowledge gaps?**  
  *Basis:* Paper notes evaluators observed errors; does not categorize root causes.  
  *Why unresolved:* No error typology or ablation study.  
  *Evidence needed:* Detailed error analysis comparing prompting strategies, model sizes, and dialects.

- **How effective are automatic methods for other Basque dialects (e.g., Navarrese-Lapurdian, Zuberoan)?**  
  *Basis:* Adaptation evaluated only for Western dialect.  
  *Why unresolved:* Other dialects remain unexamined; linguistic distance suggests Navarrese-Lapurdian may be harder.  
  *Evidence needed:* Manual pairwise evaluation by native speakers of other dialects.

- **Is Levenshtein distance valid for quantifying "dialectalness" in Basque?**  
  *Basis:* Higher Central distance attributed to word order changes (a genuine dialectal trait), conflating syntactic variation with noise.  
  *Why unresolved:* No alternative metric proposed or tested.  
  *Evidence needed:* Correlate Levensin distance with linguist-annotated feature counts across adapted datasets.

- **Does the five-dialect classification (Zuazu 2008) suit NLP tasks?**  
  *Basis:* Paper adopts classification without questioning; Levenshtein data hints at misalignment with computational similarity (e.g., Western closer to standard than Central).  
  *Why unresolved:* Choice is foundational but taken from dialectology without empirical validation for clustering.  
  *Evidence needed:* Feature-based clustering of catalog texts and comparison to Zuazu map, measuring impact on downstream tasks.

- **What solutions exist for licensing barriers that block resource use?**  
  *Basis:* Paper cites licensing issues as main limitation for incorporating valuable online sources.  
  *Why unresolved:* No practical framework presented.  
  *Evidence needed:* Standardized licensing negotiation consortium or successful rights-securement case studies.

## Limitations
- **Catalog sustainability:** Dynamic sources (tweets, radio) may become inaccessible via API changes; many entries lack clear licenses (marked N/A), hindering data aggregation.
- **Evaluation depth:** Pairwise comparison measures relative dialectalness, not absolute correctness or comprehensive feature coverage; the subtle effect of non-standard orthography may not generalize.
- **Generalizability:** Adapted datasets are written only, excluding spoken variation; automatic adaptation validated solely for Western dialect—performance for more divergent dialects is unknown.

## Confidence
- **Cataloging claim:** High – verifiable inventory addresses discoverability bottleneck, but long-term utility depends on link maintenance.
- **Manual adaptation claim:** High – Parallel XNLIvar is a tangible gold-standard with rigorous methodology, though small-scale.
- **Automatic adaptation claim:** Medium – human evaluation supports dialectalness, but limited to one dialect and a perceptual metric; systematic LLM errors remain uncharacterized.
