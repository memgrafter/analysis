# tensorFM: Low-Rank Approximations of Cross-Order Feature Interactions
## Quick Facts
- **arXiv ID:** 2602.15229
- **Source URL:** https://arxiv.org/abs/2602.15229
- **Reference count:** 11
- **Primary result:** tensorFM reduces inference complexity to O(nkrd²) versus FwFM's O(n²k) while achieving competitive or superior AUC on real-world datasets and significant gains on synthetic high-order interaction data.

## Executive Summary
tensorFM is a factorization machine designed for high-order feature interactions in multi-field categorical data. It employs a low-rank Canonical Polyadic (CP) decomposition to model interaction tensors of order ℓ (2 ≤ ℓ ≤ d). This structure enables inference that scales linearly with the number of fields n, overcoming the quadratic cost of prior models like the Field-weighted Factorization Machine (FwFM). The model demonstrates strong empirical performance, matching or exceeding FwFM on Criteo and Avazu datasets and outperforming all baselines on the COMPAS recidivism dataset. On synthetic data with known 4-wise interactions, tensorFM shows a clear accuracy advantage over pairwise-only models, confirming its ability to capture true high-order signals efficiently.

## Method Summary
tensorFM addresses binary classification on multi-field categorical inputs where each instance has exactly one active feature per field (n fields). The model score is the sum of a linear term and ℓ-order interaction terms for ℓ = 2 to d. For each order ℓ, a tensor S[ℓ] ∈ ℝ^{n×…×n} parameterizes field interactions. To avoid exponential cost, S[ℓ] is factorized via CP decomposition as S[ℓ] = Σ_{j=1}^{r} u_j^{[1]} ⊗ … ⊗ u_j^{[ℓ]}, where each u_j^{[b]} ∈ ℝ^n and r is the CP rank. Inference for an input x proceeds by: 1) retrieving k-dimensional embeddings for active features to form matrix A_x ∈ ℝ^{k×n}; 2) for each ℓ, computing M_b = A_x U^{[ℓ][b]} for b=1..ℓ; 3) summing across ranks j the product of corresponding columns of M_b; 4) aggregating contributions from all ℓ and adding the linear score. Training uses binary cross-entropy loss with AdaGrad, hyperparameter optimization (learning rate, regularization, d, r) via Optuna.

## Key Results
- Efficiency: Inference complexity is O(nkrd²), linear in field count n, versus FwFM's O(n²k). On Criteo, tensorFM(3,32) achieves 80.94% AUC vs FwFM's 80.87%.
- Synthetic data: On 4-wise interaction data, tensorFM(4,4) reaches 65.55% AUC, substantially higher than AFM's 61.56%.
- Real-world: tensorFM(4,4) achieves 77.74% AUC on Avazu (vs FwFM 77.28%) and tensorFM(1,3) attains 85.29% on COMPAS, beating all baselines.

## Why This Works (Mechanism)
### Low-rank CP decomposition enables efficient high-order inference
The core mechanism factorizes each high-order interaction tensor S[ℓ] into a sum of r rank-1 tensors. This transforms evaluating the full ℓ-way interaction sum from an exponential O(n^ℓ) operation into O(ℓ r k n) operations (Lemma 2). The method relies on the assumption that the true interaction structure is well-approximated by a low-rank tensor. If the required CP rank approaches n, the complexity advantage diminishes. Empirical results on real and synthetic data support that moderate ranks (e.g., r=32) suffice for strong performance.

### Extension of FwFM with linear scaling in fields
tensorFM generalizes FwFM (which only models pairwise interactions via a matrix) to orders ℓ > 2 while preserving linear scaling in the number of fields n. By applying CP decomposition to each S[ℓ] and aggregating as in Theorem 3, total inference cost is O(nk Σ_{ℓ=2}^d ℓ r_ℓ) ≲ O(nk r d²). FwFM, with r_2 = n, incurs O(n²k). The addition of higher-order terms yields measurable AUC gains on datasets where such interactions exist (e.g., COMPAS, synthetic data), justifying the extra parameters and computation.

### Interpretable field-level interactions
The model explicitly parameterizes ℓ-way interactions among fields, not just features. By aggregating over feature embeddings within each field (Section 5.6), one obtains a scalar strength for each field tuple. These strengths correlate with mutual information between the field tuple and the label (Pearson 0.3995 on COMPAS), and there is >40% overlap in top-k triplets. This provides a direct, data-driven way to identify important multi-field synergies, unlike black-box pairwise or deep models.

## Foundational Learning
- **Canonical Polyadic (CP) Decomposition:** Factorizes a tensor into a sum of rank-1 components. *Why needed:* It is the mathematical engine that reduces high-order tensor cost to linear in n; without it, tensorFM would be intractable. *Quick check:* Given an ℓ-order tensor of size n×…×n with CP rank r, how many parameters are needed, and how does that compare to the full tensor’s n^ℓ?

## Architecture Onboarding
**Component map:** Sparse input -> Feature embedding lookup (V) -> A_x matrix -> For each order ℓ (2..d): compute M_b = A_x U^{[ℓ][b]} for b=1..ℓ -> elementwise product across b and sum over k/r -> aggregate all ℓ terms -> add linear score (w,x)+b -> sigmoid output.

**Critical path:** 1) Input binary vector x with n active features (one per field). 2) Gather embeddings: A_x = V[feature indices] (shape: batch × n × k). 3) For ℓ in 2..d: a) compute ℓ matrices M_b = A_x U^{[ℓ][b]} (size: batch × k × r). b) For each rank j, compute ∏_{b=1}^ℓ (M_b[:,:,j]) and sum over k. c) Sum across ranks j to get ℓ-order contribution. 4) Sum ℓ-contributions, add linear term. 5) Apply sigmoid.

**Design tradeoffs:** - Rank r: larger r improves expressivity but increases constant factor O(ℓ r k n). Choose minimal r where validation AUC plateaus. - Order d: higher d captures complex synergies but increases memory (Σ ℓ·r_ℓ params) and overfitting risk. - Embedding size k: standard trade-off between capacity and cost; fixed across models for fair comparison.

**Failure signatures:** - Underfitting: validation AUC does not improve with increased r or d; may indicate insufficient model capacity or lack of high-order signal. - Overfitting: training AUC →1 while validation lags; reduce d, r, or increase regularization. - Numerical instability: CP parameters explode; use small Gaussian initialization and gradient clipping. - High latency: ensure efficient implementation (e.g., pre-compute A_x, avoid redundant matrix multiplies).

**First 3 experiments:** 1) **Real-world benchmark:** Train tensorFM, FwFM, FM, etc. on Avazu and Criteo; report AUC, LogLoss, and theoretical FLOP counts to show competitive accuracy with lower quadratic-free complexity. 2) **Synthetic high-order test:** Generate data where label depends solely on a 3-wise or 4-wise field interaction; demonstrate tensorFM with appropriate d recovers near-perfect AUC while pairwise-only models (FM, FwFM) lag. 3) **Ablation on rank/order:** On Avazu, vary r ∈ {1,2,4,8,16} and d ∈ {2,3,4}; plot validation AUC and loss to confirm monotonic gains up to a point, validating contributions of higher orders and rank.
