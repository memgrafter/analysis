# Reinforcement Learning with Symbolic Reward Machines
## Quick Facts
- arXiv ID: 2603.03068
- Source URL: https://arxiv.org/abs/2603.03068
- Reference count: 26
- Primary result: Introduces Symbolic Reward Machines (SRMs) that eliminate the need for labeling functions in reward machines, enabling end-to-end learning of non-Markovian rewards with standard RL interfaces.

## Executive Summary
The paper addresses a key limitation of Reward Machines (RMs) in reinforcement learning: the requirement for a manual labeling function that maps raw environment states to high-level events. This manual step hinders compatibility with standard RL environments. The authors propose Symbolic Reward Machines (SRMs), which directly process raw environment states using symbolic guards (e.g., linear real arithmetic) instead of propositional events. Two algorithms are introduced: QSRM, which uses a given SRM to accelerate learning via multi-updates, and LSRM, which infers an SRM during learning either with provided guard formulas or learned formula templates. Experiments on discrete (Office World) and continuous (Mountain Car) tasks show that QSRM matches the performance of QRM while respecting the standard MDP interface, and LSRM successfully learns interpretable SRMs and near-optimal policies, demonstrating end-to-end learning of non-Markovian rewards.

## Method Summary
The core idea is to replace the propositional guard evaluation in RMs with symbolic guard formulas evaluated directly on raw states. QSRM extends Q-learning by maintaining separate Q-tables for each SRM state and performing updates for all hypothetical SRM states at each environment step, leveraging the known SRM structure. LSRM removes the need for a known SRM by iteratively inferring a consistent SRM from counterexample trajectories using an SMT solver. It encodes constraints for determinism, state consistency, reward agreement on counterexamples, and transition usage, then extracts the SRM from the solver's model. Two variants are explored: LSRM-GF with fixed guard formulas supplied by the user, and LSRM-FT where guards are constructed from template formulas (e.g., axis-aligned boxes) to avoid quantifiers. After each inference, Q-tables are reset and learning restarts with the updated SRM.

## Key Results
- QSRM achieves performance identical to QRM on discrete and continuous tasks while using only raw state observations, eliminating the labeling function.
- LSRM (both GF and FT variants) converges to optimal policies in finite MDPs and attains high performance (mean10 metric near 1.0) in continuous Mountain Car, despite not being almost surely equivalent to the ground truth SRM.
- LSRM learns interpretable SRMs that are structurally similar to the ground truth in discrete tasks, confirming end-to-end acquisition of non-Markovian reward structure.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** SRMs eliminate the labeling function requirement by processing raw environment states through symbolic guards instead of high-level events.
**Mechanism:** For each SRM transition, the guard φ (e.g., a linear real arithmetic formula) is directly evaluated against the raw state s (s |= φ). The SRM uses the guard that evaluates to true to determine the next state and reward output. This bypasses the need for a separate labeling function L:S→2^P that maps states to propositions.
**Core assumption:** The environment state can be decomposed into variables Var (e.g., position coordinates) and guards can be expressed in a decidable logic (LRA). The SRM must be deterministic (mutually exclusive guards) and complete (every state has a valid outgoing transition).
**Evidence anchors:** 
- [abstract] "SRMs consume only the standard output of the environment and process the observation directly through guards that are represented by symbolic formulas."
- [section 3] Definition 2: "SRMs receive the environment state directly and handle it through guards... s |= φ" describes the core processing.
- [corpus] Corpus mentions RMs require "labeling function" and SRMs "lift this requirement."
**Break condition:** Fails if state variables cannot be captured by the logic, or if determinism requirement forces over-constrained guards. In LSRM-FT, inadequate formula templates may prevent expressing necessary guards.

### Mechanism 2
**Claim:** QSRM accelerates learning while respecting standard MDP interfaces by simulating multi-updates across all hypothetical SRM states for each observed transition.
**Mechanism:** Maintains separate Q-tables for each SRM state q ∈ Q_SRM. For each environment transition (s, a, s', r), QSRM updates Q-values for all q' ∈ Q_SRM using the reward that the SRM *would* output if it were in state q' given s' (computed via SRM(q', s')). This leverages the known SRM structure for efficient credit assignment without requiring labeled events.
**Core assumption:** The SRM is known (QSRM), deterministic, and transition guards partition the state space. The environment reward must exactly match SRM outputs (i.e., SRM correctly represents the task).
**Evidence anchors:**
- [section 3.1] Algorithm 1 Line 6-8: "for u' ∈ Q_SRM do" loop updating all Q-tables in parallel.
- [section 3.1] "QRM accelerates the learning process by performing a multi-update step: QRM not only updates the Q-value of the current RM state but also updates the Q-values for all RM states corresponding to the observed environment state."
- [abstract] "QSRM matches QRM performance while respecting the standard MDP interface."
**Break condition:** Convergence degrades to standard Q-learning if SRM is incorrect or if function approximation (DQSRM) suffers from deadly triad issues. Multi-update provides no benefit if SRM states are not properly segregated.

### Mechanism 3
**Claim:** LSRM infers a consistent SRM by encoding counterexample trajectories as SMT constraints, ensuring the learned SRM generates identical reward sequences on all observed trajectories.
**Mechanism:** When environment reward differs from hypothesis SRM reward, the full trajectory is added to counterexample set E. LSRM encodes constraints φ_det (determinism), φ_state (unique SRM state per timestep), φ_trans (reward consistency on counterexamples), and φ_used (transition usage). For LSRM-GF with fixed guard formulas Ψ, constraints use precomputed unsatisfiability checks. For LSRM-FT, guards are constructed from templates via disjunctive normalization to enforce determinism without quantifiers.
**Core assumption:** Counterexamples will eventually cover all relevant state-sequence patterns (infinite visitation). Guard formulas (LSRM-GF) or templates (LSRM-FT) are expressive enough to represent the true SRM.
**Evidence anchors:**
- [section 4] "LSRM stops the (D)QSRM algorithm and adds the current trajectory to a set of counterexamples E."
- [section 4.1] φ_trans constraint (Eq 3): "xe,t,p ∧ dp,φ,q ∧ (s_e,t+1 |= φ) ⇒ x_e,t+1,q ∧ o_p,φ = r_e,t+1"
- [section 4.3] Theorem 2 and 3 prove convergence to almost surely equivalent SRM under infinite visitation.
- [section 5.2] Empirically shows learned SRMs match ground truth structures in discrete tasks.
**Break condition:** If counterexamples miss critical state-space regions, learned SRM may be inconsistent on unseen trajectories. If formula templates are insufficient (LSRM-FT), no consistent SRM exists within template family; inference fails or produces approximate SRM.

## Foundational Learning
- **Markov Decision Processes (MDPs)**
  - *Why needed here:* SRMs extend MDPs by replacing Markovian rewards with non-Markovian ones while keeping state, action, transition structure. Understanding standard (S, A, p, R) is crucial to see how SRMs modify only the reward interface.

- **Reward Machines (RMs)**
  - *Why needed here:* SRMs are positioned as a solution to RM limitations. RMs require a labeling function L:S→2^P, creating a gap between raw states and RM inputs. Understanding RMs clarifies the exact problem SRMs solve.
  - *Quick check:* In the RM framework, what role does the propositional alphabet P play, and why does its dependence on L create integration challenges with standard RL environments?

- **Satisfiability Modulo Theories (SMT)**
  - *Why needed here:* LSRM's SRM inference encodes consistency constraints as an SMT formula φ_SRM. The solver finds boolean assignments for transition existence (dp,φ,q) and numeric rewards (op,φ) that satisfy all counterexample runs. Without SMT, exhaustive search over SRM structures would be intractable.
  - *Quick check:* Why does LSRM-FT need a different determinism constraint (Eq 9) compared to LSRM-GF (Eq 1), and how does the box template construction guarantee determinism without quantifiers?

## Architecture Onboarding
**Component map (plain text flow):**
Environment -> (state, reward) -> SRM guard evaluation -> (next SRM state, SRM reward) -> QSRM (updates all Q-tables per SRM state) -> Policy. For LSRM: Controller compares environment reward vs SRM reward; if mismatch, adds trajectory to counterexample set E -> SRM Inferencer (SMT solver) produces new SRM -> reset Q-tables and restart learning.

**Critical path (LSRM learning loop):**
1. Initialize basic SRM (single self-loop state).
2. Run one QSRM episode: for each step, agent acts based on current (s, q); environment returns (s', r_env); SRM(q, s') returns (q', r_srm).
3. If r_env ≠ r_srm at any step, store full episode trajectory (s_0...s_T, r_env,1...r_env,T) in E.
4. If counterexample found, invoke inferencer: build φ_SRM from E, solve with Z3, extract new SRM.
5. Reset Q-tables/policy network; repeat from step 1.

**Design tradeoffs:**
- QSRM vs LSRM: QSRM is simpler and convergent given correct SRM; LSRM removes manual SRM design but relies on sufficient exploration and adequate templates.
- LSRM-GF vs LSRM-FT: GF requires user-provided guard formulas (domain expertise); FT uses template shapes (e.g., boxes) but may learn coarser approximations.
- Determinism constraint encoding: GF uses precomputed unsatisfiability (fast); FT uses disjunctive guard construction (quantifier-free but may increase guard complexity).
- Completeness via self-loops: Adding φ_p,out self-loops ensures every state has an outgoing transition but may introduce redundant zero-reward paths.

**Failure signatures:**
- Non-convergent LSRM: φ_SRM repeatedly unsatisfiable, inferencer keeps increasing |Q| without finding SRM → insufficient templates or contradictory counterexamples.
- Poor performance in continuous domains: DQSRM/DQNR not reaching mean10 ≈ 1.0; often due to function approximation limitations (deadly triad), not SRM structure.
- SRM structural mismatch: LSRM-FT produces guards with tiny numerical differences causing non-equivalence on continuous spaces, yet policy may still be near-optimal.
- SMT explosion: Number of boolean variables scales as |Q|²|Ψ| (GF) or |Q|²f per state (FT); large |Q| or f leads to intractable solving.

**First 3 experiments:**
1. **Discrete Office World, known SRM (QSRM vs QRM):** Validate that QSRM achieves identical learning curves to QRM on tasks like post_inner_offices, confirming SRMs respect standard MDP interface without labels.
2. **Continuous Mountain Car (DQSRM vs DQRM):** Test scalability to infinite state spaces; expect similar performance between DQSRM and DQRM, demonstrating symbolic guards handle continuous variables via LRA.
3. **LSRM inference validation:** For finite tasks, compare LSRM-GF/FT output SRMs against ground truth (Fig 10, 8, 9). Check structural equivalence (state counts, transitions) and reward sequence equivalence on uniform random trajectories.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: Under what conditions does LSRM-FT learn an almost surely equivalent SRM in continuous state spaces?
- Basis in paper: [inferred] In the continuous Mountain Car task, LSRM-FT produced an SRM that was not almost surely equivalent to the ground truth (Section 5.2), while the convergence theorem only applies to finite MDPs.
- Why unresolved: The theoretical guarantee assumes infinite samples and finite state spaces; continuous spaces introduce uncountably many states, making finite-sample equivalence uncertain and its impact on policy optimality unclear.
- What evidence would resolve it: Formal finite-sample analysis of LSRM-FT, or empirical studies measuring equivalence and performance as a function of experience.

### Open Question 2
- Question: Does the use of restricted box formula templates limit the performance of LSRM-FT in continuous domains?
- Basis in paper: [inferred] LSRM-FT was implemented only with box templates; the authors note that other templates are possible but not evaluated (Section 4.2).
- Why unresolved: The suboptimal performance in continuous tasks might stem from insufficient expressiveness of box templates to represent the true SRM's guards.
- What evidence would resolve it: Implementation and evaluation of more expressive template families (e.g., linear inequalities with multiple variables, disjunctions) on continuous benchmarks, measuring both SRM correctness and policy performance.

### Open Question 3
- Question: How does the computational complexity of LSRM's SMT-based SRM inference scale with the size of the task?
- Basis in paper: [inferred] The inference algorithm encodes counterexamples into an SMT problem (Sections 4.1-4.2), but no complexity analysis or scaling experiments are provided.
- Why unresolved: SMT solving can be exponential; for large state spaces or long counterexamples, inference may become intractable, limiting applicability.
- What evidence would resolve it: Theoretical complexity analysis of the constraint encoding, and empirical measurements of inference time on tasks with varying numbers of states, actions, and counterexamples.

### Open Question 4
- Question: Can the SRM framework be extended to partially observable Markov decision processes (POMDPs)?
- Basis in paper: [explicit] The paper assumes fully observable MDPs throughout (e.g., Definition 1 and Section 2).
- Why unresolved: Many real-world problems involve partial observability; guards currently depend on the full state, which is unavailable.
- What evidence would resolve it: A formal definition of SRMs over belief states or observation histories, combined with an inference algorithm and evaluation on POMDP benchmarks.

## Limitations
- Generalizability: Experiments confined to Office World and Mountain Car; performance on high-dimensional, stochastic, or partially observable environments remains unproven.
- Exploration & Template Dependency: LSRM's convergence proofs assume infinite visitation and expressive templates; insufficient exploration or inadequate templates may cause failure in complex tasks.
- Scalability of Inference: SMT-based SRM inference may become intractable with many SRM states or complex guards, limiting applicability to larger problems.
- Function Approximation Risks: DQSRM inherits deep RL's deadly triad issues, potentially destabilizing learning despite symbolic structure.

## Confidence
