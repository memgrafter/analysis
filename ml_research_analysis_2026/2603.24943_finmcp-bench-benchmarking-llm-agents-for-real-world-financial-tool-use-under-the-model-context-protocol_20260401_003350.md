# FinMCP-Bench: Benchmarking LLM Agents for Real-World Financial Tool Use under the Model Context Protocol

## Quick Facts
- **arXiv ID:** 2603.24943
- **Source URL:** https://arxiv.org/abs/2603.24943
- **Reference count:** 2
- **Primary result:** FinMCP-Bench introduces a 613-sample dataset using 65 real MCP tools; Qwen3-235B-A22B-Thinking achieves 64.27% Tool F1 but performance drops on multi-turn samples.

## Executive Summary
FinMCP-Bench addresses the absence of realistic benchmarks for evaluating LLM agents in financial tool use, particularly for complex multi-tool orchestration and extended multi-turn dialogues. The authors construct a dataset from 1,484 real user logs of a deployed financial assistant, augmented with synthetically generated multi-tool scenarios (via dependency graphs) and multi-turn dialogues (via role-playing), all validated by domain experts across 10 real-world financial scenarios using 65 actual Model Context Protocol (MCP) tools. Evaluation of six LLMs shows larger Qwen3 models lead, with Qwen3-235B-A22B-Thinking achieving the highest Tool F1 (64.27%) and Exact Match (25.92%). Performance consistently declines on multi-turn samples, highlighting significant challenges in maintaining accurate tool orchestration over extended interactions with complex dependencies.

## Method Summary
The benchmark construction combines three data sources: (1) 1,484 real user logs from a production financial assistant to ground the dataset in authentic interactions, (2) synthetically generated multi-tool chains created by constructing tool dependency graphs to model complex financial workflows, and (3) synthetically extended multi-turn dialogues produced through expert role-playing to simulate follow-up queries and context shifts. All generated samples undergo rigorous validation by financial domain experts to ensure realism, correctness, and coverage of 10 specific financial scenarios. The final dataset comprises 613 unique samples, each requiring invocation of one or more of 65 actual MCP tools from a real financial data ecosystem.

## Key Results
- Dataset scale: 613 samples across 10 financial scenarios using 65 real MCP tools.
- Top performer: Qwen3-235B-A22B-Thinking, with Tool F1 of 64.27% and Exact Match Rate of 25.92%.
- Multi-turn challenge: Model performance drops significantly on synthetically extended multi-turn dialogues, indicating difficulty in sustaining accurate tool orchestration over extended contexts.

## Why This Works (Mechanism)
The benchmark's effectiveness stems from its hybrid construction: rooting in real user logs captures genuine financial intents and tool usage patterns, while synthetic augmentation systematically fills coverage gaps for rare but critical multi-tool and multi-turn scenarios. Expert validation ensures the synthetic data aligns with real-world financial reasoning and MCP tool constraints, creating a challenging yet realistic test bed that measures an agent's ability to handle both the complexity and persistence required in actual financial assistance tasks.

## Foundational Learning
- **Model Context Protocol (MCP)**  
  *Why needed:* Standardizes how LLMs discover, describe, and invoke external tools, enabling portable agent-tool integration.  
  *Quick check:* Explain how MCP abstracts the details of a specific tool's API into a standardized interface for the LLM.
- **Tool Orchestration**  
  *Why needed:* Financial queries often require sequentially chaining multiple tools (e.g., fetch data → calculate → visualize).  
  *Quick check:* Given a request to "compare Q1 revenue growth of Company X vs. sector average," list the likely tool calls and their order.
- **Multi-Turn Dialogue Management**  
  *Why needed:* Real financial analysis involves follow-ups, corrections, and context buildup across many turns.  
  *Quick check:* How should an agent track and update its plan when a user asks "What about the last 5 years?" after seeing a chart?
- **Synthetic Data Generation via Dependency Graphs**  
  *Why needed:* To create complex multi-tool scenarios that are infrequent in logs but crucial for robust evaluation.  
  *Quick check:* If tool A outputs a ticker symbol used by tool B, what does the dependency graph look like?
- **Expert Validation for Financial Realism**  
  *Why needed:* Ensures benchmark samples reflect true financial workflows and avoid unrealistic tool sequences.  
  *Quick check:* What would a validation expert check for in a sample about "calculating Sharpe ratio for a portfolio"?

## Architecture Onboarding
Component map: Real User Logs -> Synthetic Multi-Tool Graphs -> Multi-Turn Role-Play -> Expert Validation -> Final Dataset  
Critical path: Collect raw logs → extract atomic intents → generate candidate complex samples via graph-based expansion → simulate multi-turn extensions through role-play → filter/repair via expert review → curate final 613-sample benchmark.  
Design tradeoffs: Synthetic data increases scenario diversity and difficulty but may introduce subtle deviations from true user behavior; real logs ensure authenticity but under-represent complex chains.  
Failure signatures: Performance collapse on multi-turn samples (vs. single-turn) indicates failure to maintain plan/context; errors on tools with chained dependencies show weak reasoning about data flow.  
First experiments:  
1. Measure model performance strictly on the real-log subset vs. the full synthetic-augmented set to quantify synthetic data impact.  
2. Test a non-Qwen/GPT model (e.g., Claude 3.5 Sonnet) on the benchmark to check generalizability of the scaling trend.  
3. Implement a simple retrieval-augmented context tracker and evaluate its effect on multi-turn Tool F1.

## Limitations
- Synthetic multi-turn dialogues may not fully capture the unpredictability and error recovery of genuine extended user-assistant interactions.
- Evaluation covers only six models (primarily Qwen/GPT), so findings on model scaling may not hold for other architectures or smaller open-source models.
- The 65 MCP tools belong to one specific financial data ecosystem; results may not transfer to different tool APIs or broader financial domains.
