# When Only the Final Text Survives: Implicit Execution Tracing for Multi-Agent Attribution

## Quick Facts
- **arXiv ID:** 2603.17445  
- **Source URL:** https://arxiv.org/abs/2603.17445  
- **Reference Count:** 40  
- **Primary Result:** IET recovers agent segments and transition graphs with high accuracy (token >0.94, IoU ~0.93) on 4–6 agents in star/chain/tree patterns while preserving generation quality.

## Executive Summary
Multi-agent LLM systems often lack accountability when only the final text is available because execution logs and agent identifiers are typically not preserved. This paper introduces Implicit Execution Tracing (IET), a method that embeds agent-specific statistical signals directly into token distributions during generation. These signals act as a self-verifying trace that survives even when logs are missing. After generation, a post‑hoc detection pipeline—using sliding‑window scoring and change‑point detection—recovers segment boundaries, assigns agent labels, and reconstructs the underlying transition graph. Across coordination patterns (star, chain, tree) and agent counts (4–6), IET achieves token‑level accuracy above 0.94, IoU ~0.93, and transition similarity (EdgeSim) up to 0.97. The approach remains robust under identity removal, boundary corruption, and PII redaction, and it does so while preserving the quality of the generated text, enabling effective failure attribution in multi‑agent LLMs.

## Method Summary
IET operates in two phases. During generation, each agent is assigned a unique cryptographic key. The generation process is modified so that the token distribution for the agent is conditioned on this key, introducing subtle but distinct statistical fingerprints into the output text. These fingerprints are designed to be indistinguishable from normal language variation to a human reader but remain detectable through statistical analysis. In the post‑hoc phase, the final text is processed with a sliding window that computes a score for each token indicating the likelihood of belonging to a particular agent. Change‑point detection algorithms identify where the underlying agent switches, thereby segmenting the text. Each segment is then labeled by matching its statistical signature to the known keys (or inferring them if keys are unknown). Finally, the sequence of agent labels is used to reconstruct a transition graph that captures how agents passed the task among themselves.

## Key Results
- **High attribution accuracy:** Token‑level accuracy exceeds 0.94 and IoU is approximately 0.93 across star, chain, and tree coordination patterns with 4–6 agents.
- **Faithful graph reconstruction:** Transition similarity (EdgeSim) reaches up to 0.97, demonstrating that the original agent interaction structure can be recovered with high fidelity.
- **Robustness:** IET tolerates identity removal, boundary corruption, and PII redaction while maintaining attribution performance and without degrading generation quality.

## Why This Works (Mechanism)
IET succeeds because the key‑conditioned statistical signals are embedded directly into the token probabilities, making them an inherent part of the generative process. These signals persist in the final text regardless of whether explicit agent identifiers are present. The detection pipeline leverages the fact that the statistical properties of tokens change at segment boundaries, allowing change‑point detection to precisely locate transitions. The use of sliding‑window scoring smooths noise and provides a robust per‑token estimate, while the known (or learnable) keys enable accurate labeling even in the absence of explicit identifiers. Thus, the final text itself becomes a self‑contained audit trail.

## Architecture Onboarding
- **Component Map (plain text):**  
  Key‑Conditioned Embedding → LLM Token Generation → Sliding‑Window Scoring → Change‑Point Detection → Agent Labeling → Transition Graph Reconstruction
- **Critical Path:** The generation phase embeds signals; the detection phase segments the text; labeling and graph reconstruction complete the trace. Each step depends on the previous.
- **Design Tradeoffs:**  
  - *Signal Strength vs. Generation Quality:* Stronger embeddings improve detection but risk degrading fluency.  
  - *Window Size vs. Boundary Precision:* Larger windows reduce noise but blur exact transition points.  
  - *Model Agnosticity vs. Signal Retention:* Different LLMs may alter statistical signals differently; a tradeoff between universal applicability and embedding reliability.
- **Failure Signatures:**  
  - Merged segments (missed change points) indicate insufficient signal strength or poor window choice.  
  - Spurious segments (false positives) suggest noisy scoring or over‑sensitive detection.  
  - Mislabeling of agents may arise from key interference or insufficient separation in feature space.  
  - Complete signal loss after heavy redaction or paraphrasing.

  2. Test IET across coordination patterns (star, chain, tree) and scale agent counts (4–6 → >10) to establish baseline performance and scalability.  
  3. Apply controlled perturbations (identity removal, boundary corruption, PII redaction) to quantify robustness and identify failure thresholds.

## Limitations
- **Sparse method details:** The exact embedding technique and its impact on token distributions are unclear, hindering reproduction and further refinement.
- **Limited evaluation:** Experiments involve only small agent counts (4–6) and simple coordination patterns; scalability to larger, dynamic graphs remains unproven.
- **Basic robustness tests:** Only straightforward perturbations (identity removal, boundary corruption, PII redaction) were considered; adversarial attacks and edge cases are not addressed.
- **No generation quality metrics:** The claim that IET preserves output quality lacks quantitative support (e.g., BLEU, ROUGE, human evaluation).
- **Missing comparisons:** No direct benchmarking against alternative attribution methods (e.g., AgentTrace) limits understanding of relative effectiveness.
