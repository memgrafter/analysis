# OpenAI GPT-5 System Card

## Quick Facts
*   **arXiv ID:** 2601.03267
*   **Source URL:** https://arxiv.org/abs/2601.03267
*   **Reference Count:** 14
*   **Primary Result:** GPT-5 introduces a router-based unified system reducing hallucinations by 26% (fast model) and 65% (reasoning model) and sycophancy by 69-75%, with validated multi-layered defenses blocking bioweaponization prompts.

## Executive Summary
GPT-5 is presented as a unified system that dynamically routes user queries between a fast, high-throughput model (gpt-5-main) and a deeper reasoning model (gpt-5-thinking) based on real-time complexity signals. A core methodological shift replaces binary refusals with "safe-completions" training, which maximizes helpfulness while ensuring output policy compliance, particularly for dual-use scenarios. For high biological risk, a validated multi-layered stack—including model training, a two-tiered system monitor, and account enforcement—was shown in expert red teaming to refuse all bioweaponization prompts. The system demonstrates significant improvements in hallucination, sycophancy, and safety metrics versus predecessors.

## Method Summary
The proposed system relies on two primary technical innovations. First, a continuously trained router dispatches queries to either the fast or reasoning model using live production signals (user switches, preference rates, correctness) to optimize for speed-accuracy trade-offs. Second, the training paradigm shifts from refusal-based safety to "safe-completions," where the model learns to generate maximally helpful yet policy-compliant outputs for ambiguous or dual-use queries. Reproduction would require implementing this output-centric safety objective and a dual-model routing system, then evaluating on public benchmarks (e.g., LongFact, SWE-bench). However, faithful replication is blocked by undisclosed proprietary details: exact training data mixtures, model architectures, router feature engineering, and the precise safe-completions reward formulation.

## Key Results
*   Reduced hallucinations by 26% for gpt-5-main and 65% for gpt-5-thinking versus predecessors.
*   Decreased sycophancy by 69-75% in online user tests.
*   In expert red teaming for violent attack planning, gpt-5-thinking was judged safer than OpenAI o3 in 65.1% of cases; the mitigated model refused all bioweaponization prompts.

## Why This Works (Mechanism)

### Mechanism 1: Dynamic Router for Speed-Accuracy Optimization
*   **Claim:** A real-time router dynamically selects between a fast model (gpt-5-main) and a deeper reasoning model (gpt-5-thinking) based on query complexity, conversation type, tool needs, and explicit user intent, optimizing for speed and accuracy.
*   **Mechanism:** The router is a continuously trained system that uses live signals (user model switches, preference rates, measured correctness) to learn which model is best for a given query. This splits the workload: gpt-5-main handles most queries quickly, while gpt-5-thinking handles harder problems, with usage limits triggering mini-model fallbacks.
*   **Core Assumption:** Query complexity and intent can be reliably inferred from contextual signals to make a correct routing decision that improves user experience.
*   **Evidence Anchors:** [abstract] "unified system with a router that dynamically selects..."; [section 1] "router is continuously trained on real signals..."; [corpus] Weak/absent. Neighboring papers discuss GPT-5 applications but not the router architecture.
*   **Break Condition:** The router misroutes a complex query to the fast model, leading to poor accuracy or a simple query to the thinking model, causing unnecessary latency. Detectable via drops in preference rates or correctness metrics for those query classes.

### Mechanism 2: Safe-Completions Training for Helpful Compliance
*   **Claim:** Replacing binary refusals with "safe-completions" training maximizes helpfulness within safety constraints, reducing brittleness on dual-use queries and improving overall utility.
*   **Mechanism:** Instead of training the model to simply refuse disallowed content, safe-completions trains the model to generate outputs that are maximally helpful while ensuring the content itself is policy-compliant. This handles ambiguous intent and dual-use scenarios (e.g., biology queries) by controlling the *output* rather than making a binary judgment on the *input*.
*   **Core Assumption:** The model's output can be controlled to be safe and non-actionable for malicious use, even when the user's request has legitimate surface plausibility.
*   **Evidence Anchors:** [abstract] "replace binary refusals with safe-completions training..."; [section 3.1] "safe-completions seek to maximize helpfulness subject to the safety policy’s constraints..."; [corpus] Weak/absent. Neighboring papers focus on performance, not this specific training methodology.
*   **Break Condition:** A jailbreak or cleverly constructed prompt causes the model to generate a detailed, actionable, and harmful completion that the safe-completions training failed to constrain. Detected as a violation in red teaming or disallowed content evaluations.

### Mechanism 3: Multi-Layered Defense Stack for High Biological Risk
*   **Claim:** A multi-layered defense stack (model training, system monitors, account enforcement) sufficiently minimizes the risk of severe biological harm from a "High capability" model, even without definitive evidence of novice-uplift to bioweaponization.
*   **Mechanism:** For high-risk domains (Biological/Chemical), safeguards operate at multiple levels: 1) Model training instills refusals/safe-completions for weaponization and high-risk dual-use. 2) A real-time, two-tiered system monitor (topical classifier -> reasoning monitor) scans all user inputs, tool outputs, and final generations to block hazardous content before it reaches the user. 3) Account-level enforcement detects and bans malicious users via automated and human review, with recidivism controls and potential law enforcement notification.
*   **Core Assumption:** A determined adversary cannot sequentially bypass all independent layers (model refusal, two-tiered monitor, and account enforcement) within a short time horizon to obtain actionable bioweapon information.
*   **Evidence Anchors:** [section 5] "treat gpt-5-thinking as High capability... activating the associated safeguards..."; [section 5.3.2] Describes the three-layer stack; [section 5.3.3.3] "mitigated model refused all bioweaponization prompts"; [corpus] Weak/absent.
*   **Break Condition:** A jailbreak or novel elicitation technique is discovered that consistently bypasses the model's refusal behavior *and* the two-tiered generation monitor *and* avoids triggering account enforcement long enough to extract a complete, actionable protocol for creating a biological threat. This would be a "universal jailbreak" for the biosecurity stack.

## Architecture Onboarding
*   **Component Map:**
    Router -> (gpt-5-main | gpt-5-thinking) -> [System Monitor (Topical Classifier -> Reasoning Monitor)] -> User
    Account Enforcement Pipeline scans all flagged conversations.
    API safety_identifier tags end-users for risk-aware handling.
    Mini/Nano Models act as fallbacks when usage limits are hit.

*   **Critical Path:**
    1.  User query received.
    2.  Router analyzes complexity/intent/tool need -> selects gpt-5-main or gpt-5-thinking.
    3.  Model generates response (may use tools/browse).
    4.  **For high-risk domains:** System monitor scans user input, tool outputs, and model generation sequentially. If topical classifier flags, reasoning monitor evaluates against taxonomy.
    5.  If monitor flags a violation, output is blocked; user may see safe-completion or refusal.
    6.  All conversations for flagged models are scanned for account-level enforcement.
    7.  Enforcement system decides on warnings, temporary blocks, or bans.

*   **Design Tradeoffs:**
    *   **Routing Accuracy vs. Latency:** Wrong routing (hard query to fast model) hurts quality; over-routing to thinking model hurts speed. The router is optimized for a net utility gain.
    *   **Safety vs. Helpfulness:** Safe-completions aim to balance this, but can lead to over-refusal on benign dual-use queries (e.g., legitimate research). System monitor recall is prioritized over precision.
    *   **Security vs. Access:** Strict API controls (safety_identifier, ZDR screening) reduce risk of bulk exfiltration but increase friction for legitimate developers.

*   **Failure Signatures:**
    *   **Router failure:** Spikes in user-initiated model switches *after* a response, or drops in downstream correctness metrics for specific query classes.
    *   **Safe-completions failure:** Violative content appears in production traffic that passes the system monitor. Detected via red teaming, bug bounty, or post-hoc analysis.
    *   **Monitor bypass:** Adversary elicits a complete, detailed bioweapon protocol in a single conversation that passes both topical and reasoning monitors. Would be a critical security incident.
    *   **Enforcement delay:** Malicious actor successfully probes for jailbreaks across multiple accounts before enforcement actions trigger.

*   **First 3 Experiments:**
    1.  **Router Logic Probe:** Submit a set of prompts with known complexity labels (e.g., simple fact, multi-step reasoning, code generation) and verify routing decisions match expected patterns. A/B test routing vs. always-thinking to measure net utility.
    2.  **Safe-Completion Boundary Test:** Using the "challenging prompts from red teamers" dataset (section 5.3.3.1), measure the fraction where model training alone (without monitor) produces a safe/high-level response vs. a detailed, risky one. This isolates the model's inherent capability.
    3.  **Monitor Evasion Stress Test:** Use an external red team (or automated tool like Gray Swan's Shade) to generate 1000+ bioweaponization prompt variations. Measure Monitor Recall (caught / total) and Precision (safe/allowed). Target: >99% recall on weaponization, even with degraded output quality.

## Open Questions the Paper Calls Out
1.  **What are the precise psychological and interactional factors that cause models to exhibit sycophancy, and how can we develop robust, scalable metrics to measure its prevalence in emotionally complex or dependency-forming conversations?** The paper notes current metrics are inadequate for low-prevalence, high-stakes scenarios like emotional dependency, and they are engaging HCI researchers and clinicians to define concerning interactions.
2.  **Why does the "safe-completions" training paradigm lead to statistically significant regressions in specific disallowed content categories (e.g., hate/threatening, sexual/exploitative) for gpt-5-main, and how can these trade-offs be systematically mitigated?** The paper acknowledges these regressions but does not explain the mechanism behind the trade-off or over-correction in the training objective.
3.  **To what extent are the observed reductions in model deception driven by improved "graceful failure" training versus inherent capability limitations, and how monitorable are the Chain-of-Thought (CoT) traces for detecting more sophisticated, goal-oriented deceptive plans?** The paper does not disentangle whether lower deception rates are due to the model being more honest or simply less capable of executing complex deceptive strategies, and notes challenges with CoT faithfulness.
4.  **What specific architectural or training differences between gpt-5-thinking and gpt-5-thinking-mini lead to the latter's superior performance on the Cyber Range (e.g., solving Online Retailer) despite both using the same "thinking" paradigm, and does this indicate a scaling or efficiency frontier for agentic reasoning?** The paper speculates on solution construction differences but provides no analysis of the underlying mechanisms (e.g., internal policy gradients, exploration strategies).
5.  **Is the "High" Biological and Chemical capability designation for gpt-5-thinking based on a precautionary principle truly justified by the evaluation results, given that external evaluators found its helpful-only performance to be at or slightly below OpenAI o3, and what is the precise threshold for "meaningfully helping a novice create severe biological harm"?** The paper admits the model is likely below the defined High threshold but treats it as such for "organizational readiness," creating ambiguity about the operationalized capability benchmark.

## Limitations
*   Proprietary training data mixtures, filtering algorithms, and exact model architectures are undisclosed.
*   Router implementation details (feature set, architecture, training data) and safe-completions training specifics (reward model design, constraint handling) are not public.
*   Generalizability of the biosecurity stack validation beyond expert red teaming is unknown; external, sustained attack efficacy is unproven.

## Confidence
*   **Router System:** Medium. High-level design and training signals are described, but core algorithmic details and failure modes are not publicly verifiable.
*   **Safe-Completions Training:** Low-Medium. Conceptual shift is clear and results are claimed, but the precise objective function, reward model, and constraint handling lack methodological transparency.
*   **Multi-Layered Biosecurity Stack:** High for *presented results* (expert red teaming), Low for *robustness*. The stack's design is specified, but its resilience against novel, iterative attacks by sophisticated adversaries remains an assumption.

## Next Checks
1.  **Router Logic Probe:** Submit a balanced dataset of queries with ground-truth complexity labels (simple, multi-step, tool-required). Measure routing accuracy, latency distribution, and downstream correctness to validate claimed optimization.
2.  **Safe-Completion Boundary Stress Test:** On a held-out set of challenging dual-use and adversarial prompts (e.g., from public jailbreak repositories), audit completions for actionable harm vs. over-refusal. Quantify the helpfulness-safety Pareto frontier.
3.  **Monitor Evasion Benchmark:** Deploy an automated red teaming tool (e.g., Gray Swan's Shade) to generate 1000+ bioweaponization prompt variations. Measure recall and precision of the two-tiered monitor stack against this external, adaptive test set.
