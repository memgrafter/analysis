# Adaptive Memory Admission Control for LLM Agents

## Quick Facts
- **arXiv ID**: 2603.04549
- **Source URL**: https://arxiv.org/abs/2603.04549
- **Reference count**: 6
- **Primary result**: A-MAC achieves F1 0.583 on LoCoMo (+7.8% over A-mem) and reduces latency by 31% to 2644ms.

## Executive Summary
LLM agents suffer from poor memory admission control, accumulating hallucinated or obsolete information. This paper presents A-MAC, a system that frames memory admission as a decision problem using five interpretable factors: future utility (via a single LLM call), factual confidence (ROUGE-L overlap), semantic novelty (embedding similarity), temporal recency (exponential decay), and content type prior (rule-based patterns). Weights for these factors are learned via cross-validation to balance precision and recall. On the LoCoMo benchmark, A-MAC attains an F1 score of 0.583, outperforming state-of-the-art A-mem by 7.8% while lowering latency by 31% to 2644ms. Ablation studies identify the type prior as the most influential feature; its removal decreases F1 by 0.107. The hybrid design efficiently combines lightweight rule-based feature extraction with a single LLM-assisted utility assessment.

## Method Summary
A-MAC solves the memory admission problem for LLM agents by learning a thresholded linear model over five features. Inputs are a multi‑turn conversation history and the existing memory store. The pipeline first extracts atomic, self‑contained candidate memories from the dialogue. For each candidate, the following normalized features are computed:
- **Utility (U)**: rated 0–1 by one LLM call, estimating future usefulness.
- **Confidence (C)**: maximum ROUGE‑L overlap with supporting spans in prior conversation turns.
- **Novelty (N)**: 1 minus the maximum cosine similarity (using Sentence‑BERT embeddings) to any stored memory.
- **Recency (R)**: exponential decay `exp(−0.01·τ)`, where `τ` is hours since the candidate was first mentioned.
- **Type Prior (T)**: a rule‑based score (e.g., higher for preferences, lower for transient feelings) derived from pattern matching.

These features are combined into a composite score `S(m) = Σ ω_i · f_i(m)`. The weight vector `ω` (non‑negative, sum=1) and admission threshold `θ` are selected via cross‑validated grid search on a small labeled dataset to maximize F1. Candidates with `S ≥ θ` are admitted. If a candidate conflicts with an existing memory (cosine similarity > 0.85), the higher‑scoring representation is kept and contents are merged. The hybrid approach relies on just one LLM invocation per candidate and fast deterministic computations for the other features, yielding high efficiency.

## Key Results
- **LoCoMo F1**: 0.583, a 7.8% improvement over A‑mem (0.541).
- **Latency**: 2644 ms, 31% lower than A‑mem.
- **Ablation**: Removing the Type Prior feature reduces F1 by 0.107, confirming its dominant contribution.

## Why This Works (Mechanism)

### Mechanism 1: Decomposition into five factors
- **Claim**: Decomposing memory value into five complementary factors yields more reliable admission than monolithic or single‑criterion policies.
- **Mechanism**: Each candidate memory `m` is scored on Utility (U, LLM‑based), Confidence (C, ROUGE‑L overlap with supporting turns), Novelty (N, 1 − max cosine similarity to existing memories), Recency (R, exponential decay based on time since mention), and Type Prior (T, rule‑based pattern matching). A linear weighted sum `S(m)=∑wᵢ·fᵢ(m)` with learned weights `wᵢ` and threshold `θ` decides admission.
- **Core assumption**: The five factors are sufficiently independent and together capture the essential dimensions of long‑term memory value (usefulness, reliability, redundancy, temporal relevance, persistence).
- **Evidence anchors**: 
  - [abstract] "decomposes memory value into five complementary and interpretable factors: future utility, factual confidence, semantic novelty, temporal recency, and content type prior."
  - [section] Section 3.2 details the computation of each factor and their normalization to [0,1].
  - [corpus] Neighboring papers (e.g., Mem0, A‑mem) use monolithic LLM‑driven policies; A‑MAC’s multi‑factor decomposition is novel, so direct corpus support is weak.
- **Break condition**: If any factor becomes highly correlated with others or if a factor’s extractor fails (e.g., ROUGE‑L misses nuanced hallucinations), the linear combination may not improve over simpler baselines.

### Mechanism 2: Hybrid efficiency via single LLM call
- **Claim**: A hybrid design that uses a single LLM call for semantic utility while computing the remaining four features with deterministic rules achieves a superior accuracy‑efficiency trade‑off.
- **Mechanism**: The costly Utility feature requires one LLM invocation per candidate; Confidence, Novelty, Recency, and Type Prior are computed via fast, interpretable operations (ROUGE‑L, embedding cosine, arithmetic decay, regex patterns), all of which can be parallelized.
- **Core assumption**: The four rule‑based features can be computed reliably without LLM assistance and still provide discriminative signals for admission.
- **Evidence anchors**: 
  - [abstract] "combines lightweight rule‑based feature extraction with a single LLM‑assisted utility assessment".
  - [section] Section 4.5 latency breakdown shows Utility accounts for 97.6% of total latency (2580 ms), while the other features together take <65 ms.
  - [corpus] Corpus contains efficient memory systems (e.g., MemoryBank) but none explicitly combine a single LLM call with multiple rule‑based features; evidence for this exact hybrid pattern is weak.
- **Break condition**: If rule‑based features prove too coarse or if the single LLM call becomes a bottleneck (e.g., API latency spikes), the hybrid design may lose its efficiency advantage.

### Mechanism 3: Learned threshold balances precision/recall
- **Claim**: Learning admission weights and threshold via cross‑validated grid search on a small labeled dataset automatically adapts the policy to the domain, identifying the most important factors.
- **Mechanism**: Given ground‑truth admission labels, the system searches over weight vectors `ω` (non‑negative, sum=1) and thresholds `θ` to maximize validation F1; the best configuration is applied to new candidates.
- **Core assumption**: The training data is representative and the linear scoring model is expressive enough to capture the optimal decision boundary.
- **Evidence anchors**: 
  - [section] Section 3.3 describes the learning procedure: "learned through cross‑validated optimization" and grid search over `ω` and `θ`.
  - [section] Ablation results (Table 2) show that removing Type Prior hurts F1 by 0.107, and the learned weights assign it the highest importance, confirming that learning correctly identified the dominant factor.
  - [section] Threshold analysis (Table 3) shows optimal `θ=0.55`; sensitivity around this value indicates robustness.
  - [corpus] Some neighbors (e.g., Hindsight) use retrospective scoring but not cross‑validated linear weighting; direct evidence is limited.
- **Break condition**: If training labels are noisy or biased, or if the optimal boundary is non‑linear, the linear model may underfit, leading to poor generalization.

## Foundational Learning

- **ROUGE‑L for factual confidence**: 
  - *Why needed*: Confidence `C(m)` uses ROUGE‑L overlap between a candidate and supporting conversation turns to measure whether the candidate is grounded in prior evidence, thereby reducing hallucination propagation.
  - *Quick check*: Does ROUGE‑L measure exact word overlap or longest common subsequence? How might it fail on paraphrase‑based support?

- **Sentence‑BERT embeddings for novelty**: 
  - *Why needed*: Novelty `N(m)=1−max_{m'∈M} cos(ϕ(m),ϕ(m'))` quantifies how semantically distinct a candidate is from existing memories, preventing redundant storage.
  - *Quick check*: If two memories are about the same event but phrased differently, will their embeddings be similar enough for `N≈0`? What factors affect embedding similarity?

- **Exponential temporal decay**: 
  - *Why needed*: Recency `R(m)=exp(−λ·τ(m))` models that older information is less likely to be useful, where `τ` is elapsed time and `λ` controls decay rate.
  - *Quick check*: How does the half‑life change with `λ`? If `λ=0.01` per hour, what is the half‑life and is it reasonable for conversational memory?

## Architecture Onboarding

- **Component map**: Candidate Extraction -> Feature Computation (U, C, N, R, T) -> Policy Scoring (S = ω·features) -> Thresholding (S ≥ θ) -> Conflict Resolution (similarity > 0.85)

- **Critical path**:
  1. Input: conversation history `H` and current memory store `M`.
  2. Extract atomic candidates from `H`.
  3. For each candidate, compute all five features (U via LLM; C, N, R, T via fast rules).
  4. Compute composite score `S(m)` and compare to threshold `θ`.
  5. If admitted, check for conflicts with existing memories (cosine similarity > 0.85); if conflict and `S(m)` is higher, replace or merge memories.
  6. Update memory store `M`.

- **Design tradeoffs**:
  - *Precision vs Recall*: Lower `θ` increases recall but adds noise; higher `θ` improves precision but may miss useful facts. Tuning required for domain.
  - *LLM cost vs rule reliability*: Using a single LLM call reduces expense but relies on rule‑based features for most of the decision; if rules are poorly calibrated, accuracy suffers.
  - *Interpretability vs adaptivity*: The linear model is transparent but may not capture complex interactions; deeper models could improve performance at the cost of explainability.

- **Failure signatures**:
  - *Memory bloat* (many admissions, low precision): Check `θ`; possibly Type Prior weights too low or pattern rules too permissive.
  - *Missing context* (low recall): Verify Utility scoring isn’t overly strict; examine if candidates are being filtered early by Confidence (ROUGE‑L mismatches due to paraphrasing).
  - *Latency spikes*: LLM API latency or failures; consider caching or batching.
  - *Poor cross‑domain performance*: Training data mismatch; retrain weights on domain‑specific data.

- **First 3 experiments**:
  1. **Main benchmark comparison**: Evaluate A‑MAC against baselines (Random, MemGPT, MemoryBank, Equal Weights, A‑mem) on LoCoMo test set; report precision, recall, F1, and latency.
  2. **Ablation study**: Remove each feature in turn to quantify its contribution to F1; confirms Type Prior as most influential.
  3. **Threshold sensitivity**: Vary `θ` on validation folds to determine optimal operating point and robustness; best F1 at `θ=0.55` with flat plateau between 0.50–0.60.

## Open Questions the Paper Calls Out

1. **Domain generalization**: To what extent do A‑MAC’s five interpretable features generalize to conversational domains outside LoCoMo (e.g., technical or multi‑party dialogues)? The paper reports performance variation within LoCoMo (Personal F1=0.482, Professional F1=0.338), suggesting limitations in capturing implicit context and domain‑specific terminology. Multi‑benchmark evaluation is needed.
2. **ROUGE‑L reliability**: How reliably does the ROUGE‑L‑based Confidence feature prevent hallucinations compared to more sophisticated consistency checks or LLM‑based veracity scoring? The ablation shows moderate impact (ΔF1=−0.015), and no direct hallucination metrics are reported. A targeted evaluation with gold‑standard factual consistency labels would clarify.
3. **Temporal decay optimality**: Is the fixed exponential decay (`λ=0.01` per hour) optimal across all conversation types? The paper does not justify this choice; recency was the least influential feature in ablation, which could be due to suboptimal `λ` rather than irrelevance. Dynamic decay adapted to conversation pace or topic volatility may improve performance.
4. **Non‑linear models**: Could more expressive learned models (e.g., neural networks with feature interactions) improve admission performance beyond the linear weighted sum while maintaining interpretability? The paper uses a linear model for transparency but provides no comparison to non‑linear alternatives; potential underfitting is suggested by the performance gap over Equal Weights.

## Limitations

- **Missing implementation details**: The exact atomic segmentation and normalization pipeline (coreference and temporal resolution) and candidate extraction algorithm are not fully described.
- **Underspecified components**: Definitions for supporting spans (Confidence), Type Prior patterns, LLM prompt template and rating scale for Utility, and conflict‑resolution merging procedure lack complete details.
- **Grid search ambiguity**: The resolution and sampling method for weights and threshold during cross‑validation are not provided, hindering exact replication.
