# Structured Distillation for Personalized Agent Memory: 11x Token Reduction with Retrieval Preservation

## Quick Facts
- **arXiv ID:** 2603.13017
- **Source URL:** https://arxiv.org/abs/2603.13017
- **Reference count:** 21
- **Primary result:** Compresses conversation exchanges from 371 to 38 tokens (11× reduction) while preserving 96% of verbatim retrieval quality (MRR 0.717 vs 0.745) with vector search; hybrid fusion exceeds verbatim baseline (MRR 0.759).

## Executive Summary
The paper addresses the high cost of storing and querying full verbatim agent conversation histories. It introduces *structured distillation*, where each exchange is compressed into a compound object (exchange_core, specific_context, room_assignments, files_touched) averaging 38 tokens, while the original is retained for display. On 4,182 conversations (14,340 exchanges), this achieves an 11× token reduction. Retrieval quality, measured by Mean Reciprocal Rank (MRR) over 201 queries, shows that vector-based search on distilled text suffers no significant degradation (MRR 0.717), whereas keyword-based BM25 degrades substantially. A hybrid approach fusing verbatim BM25 with distilled vector search slightly outperforms the best pure-verbatim baseline (MRR 0.759 vs 0.745). The results are mechanism-dependent: vector search is robust to compression, BM25 is not, and fusion leverages their complementary strengths.

## Method Summary
The method involves a two-layer storage and retrieval architecture. First, a batch distillation job uses an LLM (Claude Haiku) to process each verbatim exchange from a corpus of developer-focused Claude Code logs, outputting a structured "palace" object with four fields designed to capture decision essence, specific context, spatial assignments, and touched files. The original verbatim text is kept for drill-down. For retrieval, two indices are maintained: a vector index (FAISS with all-MiniLM-L6-v2 embeddings) built on the distilled text; and a keyword index (BM25 via DuckDB FTS) that can be built on either verbatim or distilled fields. At query time, a configuration parser selects a mode (pure distilled, pure verbatim, or cross-layer fusion) and a fusion strategy (e.g., CombMNZ, weighted sum). The system retrieves top candidates, maps distilled IDs back to verbatim snippets, and returns results. Performance is evaluated by grading result snippets with multiple LLMs and computing MRR.

## Key Results
- Token reduction: average exchange size drops from 371 tokens (verbatim) to 38 tokens (distilled), an 11× compression.
- Retrieval preservation: The best pure distilled vector configuration (Core+Rooms, HNSW, Weighted) achieves MRR 0.717, preserving 96% of the best verbatim baseline MRR 0.745.
- Mechanism dependency: All 20 vector search comparisons show non-significant degradation; all 20 BM25 comparisons show significant degradation with large effect sizes.
- Hybrid gain: A cross-layer fusion (BM25 on verbatim + HNSW on distilled) reaches MRR 0.759, slightly exceeding the best pure-verbatim baseline.

## Why This Works (Mechanism)

### Mechanism 1: Vector search tolerates aggressive compression
- **Claim:** Vector-based search remains effective after 11× token reduction because the distilled representation preserves semantic essence.
- **Mechanism:** The structured distillation produces compact text (exchange_core + specific_context) by reusing the original participants' specific terminology ("surviving vocabulary"). Although only ~27% of exchange-specific rare tokens survive, ~96.8% of query tokens are retained. The embedding model (all-MiniLM-L6-v2) maps this compressed text into a vector space where semantic similarity remains detectable; removal of boilerplate may even denoise the representation.
- **Core assumption:** Semantic similarity search is robust to removal of filler; the core decision and technical details carry sufficient meaning for the embedding to match relevant queries.
- **Evidence anchors:**
  - [abstract] All 20 vector search comparisons show non-significant degradation; best pure distilled MRR 0.717 (96% of verbatim 0.745).
  - [section 5.2] With HNSW, 10/10 distilled configurations show no statistically significant mean grade degradation (Bonferroni-corrected); effect sizes negligible to small (|d| ≤ 0.25).
  - [corpus] Original 371 tokens/exchange reduced to 38 tokens/distilled object (Table 2).
- **Break condition:** If distillation paraphrases or omits query-critical identifiers/error strings, vector similarity signal weakens.

### Mechanism 2: BM25 suffers from lexical loss
- **Claim:** BM25 retrieval degrades substantially under compression because it depends on exact lexical overlap with the original text.
- **Mechanism:** BM25 scores based on term frequency, inverse document frequency, and field length. Distillation removes most exchange-specific rare tokens (only 27% of high-IDF tokens survive), eliminating many discriminative keywords. The compressed text is shorter with altered term statistics, reducing lexical overlap needed for high BM25 scores.
- **Core assumption:** BM25's effectiveness in this domain is heavily tied to verbatim vocabulary; compressing away that vocabulary attacks its core matching signal.
- **Evidence anchors:**
  - [abstract] All 20 BM25 comparisons show significant degradation (effect sizes |d|=0.031–0.756).
  - [section 5.2] BM25 depends on lexical overlap; 11× compression removes verbatim vocabulary; all 20 BM25 configurations show statistically significant mean grade degradation post-Bonferroni.
  - [corpus] Token reduction ratio (371→38) implies drastic lexical material loss; 27% survival rate of high-IDF tokens (Section 3.2).
- **Break condition:** If query contains only common terms that remain in distilled core, BM25 degradation may be minor; failure occurs when query's discriminative tokens are discarded.

### Mechanism 3: Cross-layer fusion covers complementary blind spots
- **Claim:** Fusing verbatim BM25 with distilled vector search creates complementary pathways that together surpass the best pure-verbatim baseline.
- **Mechanism:** Verbatim BM25 excels at matching exact identifiers/phrases (high precision on specific terms), while distilled vector search captures semantic intent and abstracts noise. Orthogonal strengths cover each other's blind spots: queries failing in one mode succeed in the other. Fusion strategies (CombMNZ, weighted sum) combine ranked lists.
- **Core assumption:** Errors made by verbatim BM25 and distilled vector search are largely uncorrelated; combining them improves overall recall and precision.
- **Evidence anchors:**
  - [abstract] Best cross-layer setup MRR 0.759, exceeding best pure verbatim baseline.
  - [section 5.1] Highest-MRR configuration: cross-layer fusing BM25 on verbatim with HNSW on distilled (MRR=0.759).
  - [section 5.7] Coverage analysis: 42 queries solved only by distilled, 45 only by verbatim; oracle union solves 191/201 queries.
- **Break condition:** If retrieval pathways return highly overlapping top results (e.g., for very specific queries), fusion benefit diminishes; suboptimal fusion weights can harm performance.

## Foundational Learning
- **Concept:** Mean Reciprocal Rank (MRR)
  - **Why needed:** Primary outcome metric; measures how early the first perfectly relevant result appears (reciprocal rank averaged over queries). Interpreting "96% preservation" (0.717 vs 0.745) requires understanding MRR.
  - **Quick check:** If MRR = 0.5, what is the average rank of the first perfectly relevant result? (Answer: 2)
- **Concept:** Multiple comparisons correction (Bonferroni)
  - **Why needed:** Paper runs 40 paired tests comparing distilled vs verbatim modes; without correction, Type I errors inflate. The mechanism-dependent conclusion hinges on proper statistical control (α = 0.05/40 = 0.00125).
  - **Quick check:** With 40 independent tests at nominal α=0.05, how many false positives expected by chance? How does Bonferroni adjust the threshold? (Answer: 2 false positives expected; threshold becomes 0.00125.)
- **Concept:** Fleiss’ κ for inter-rater agreement
  - **Why needed:** Relevance grades come from 5 LLM graders with κ=0.175 (Slight). Low agreement casts doubt on absolute score interpretations; valid inference is the consistent directional pattern across graders.
  - **Quick check:** Does a low κ mean results are invalid? What does the paper claim about pattern consistency despite low agreement? (Answer: Not invalid; paper claims directional patterns are consistent even with low absolute agreement.)

## Architecture Onboarding
- **Component map:**
  - Corpus Storage (verbatim exchanges) -> Distillation Batch Job (LLM produces palace objects) -> Index Layer (Vector index on distilled text; BM25 index built on-the-fly from verbatim or distilled fields) -> Search Orchestration (config parser, retrieval, fusion) -> Evaluation Harness (LLM graders, metric aggregation).
  - User query enters at Search Orchestration; verbatim snippets returned via back-references from palace objects.
- **Critical path:**
  1. User issues query.
  2. System selects configuration (e.g., "Distill Core+Rooms / Exact / Weighted" or "Cross: BM25(V)+HNSW(D)").
  3. For verbatim BM25: build in-memory index on concatenated fields; compute BM25 scores.
  4. For vector: load FAISS index; embed query; perform nearest neighbor search.
  5. If cross-layer, retrieve from both indices separately and fuse ranked lists by chosen strategy.
  6. Map each distilled object ID back to verbatim snippet (ply_start-ply_end) and return.
  7. Grading (offline) follows similar flow with skeleton snippets and LLM grading.
- **Design tradeoffs:**
  - Recall vs context cost: Distilled layer reduces tokens 11× enabling thousands of exchanges in a single prompt; verbatim remains for drill-down.
  - Vector vs keyword: Vector search tolerates compression; BM25 suffers but provides high precision on exact terms. Hybrid cross-layer offsets this.
  - Precomputed vs on-the-fly: Vector index is static after distillation; BM25 indices are built lazily at query time (acceptable for single-user scale).
  - Distillation model choice: All palace objects produced by Claude Haiku 4.5; different models may change compression ratio or quality.
- **Failure signatures:**
  - BM25-only distilled modes show large effect sizes (up to |d|=0.756) and significant mean grade degradation, especially for conceptual/phrase queries.
  - Low inter-rater agreement (κ=0.175) means absolute grade differences must be interpreted cautiously; rely on directionally consistent patterns across graders.
  - Exact-term queries sometimes perform better in distilled modes (e.g., Core+Files/HNSW: 2.08 vs Full Text/HNSW: 1.93) because file metadata surfaces identifiers verbatim.
  - Queries with no strong answer (e.g., vague phrases) score near floor (mean grade <1) across all configs, indicating corpus gaps.
- **First 3 experiments:**
  1. Reproduce verbatim baselines: Run Full Text with BM25-FTS and HNSW; confirm MRR ~0.745 and 0.645 respectively.
  2. Validate pure distilled vector search: Index distilled Core+Rooms with Exact/Weighted; perform paired t-test vs Full Text/Exact; expect non-significant (p > 0.00125) and MRR ~0.717.
  3. Cross-layer fusion benchmark: Combine BM25-FTS on verbatim with HNSW on distilled using CombMNZ or W70; expect MRR ~0.759, exceeding best pure verbatim.

## Limitations
- **Corpus Specificity:** Results derived from Claude Code logs (developer-focused, technical exchanges); generalization to other domains (e.g., customer support, casual chat) is uncertain.
- **Grading Reliability:** Fleiss’ κ = 0.175 (Slight) across 5 LLM graders; absolute MRR scores may be sensitive to grading interpretation despite consistent directional patterns.
- **Model Dependence:** Distillation used Claude Haiku 4.5; performance likely varies with different LLMs (smaller models may lose nuance; larger ones may improve compression).

## Confidence
- **Vector search preservation (non-significant degradation):** High – 20 paired tests with Bonferroni correction, negligible-to-small effect sizes (|d| ≤ 0.25).
- **BM25 degradation (significant loss):** High – All 20 BM25 comparisons significant post-correction, large effect sizes (|d| up to 0.756).
- **Cross-layer fusion exceeding verbatim baseline:** Medium – Slight improvement (MRR 0.759 vs 0.745) in a single best configuration; may not hold across all fusion strategies or corpora.
- **Generalizability to other agent/memory systems:** Low – Claims tied to specific distillation schema, embedding model (all-MiniLM-L6-v2), and technical corpus.

## Next Checks
1. **Multi-model distillation replication:** Re-run the distillation pipeline with at least two other LLMs (e.g., GPT-4o-mini, Llama-3-8B) and re-evaluate retrieval quality to quantify model dependence of the 38-token structure.
2. **Cross-corpora evaluation:** Apply the same distilled schema and retrieval setup to a public conversational dataset (e.g., MultiWOZ, TaskMaster) to test domain portability and measure relative MRR changes.
3. **Relevance labeling reliability study:** Replace LLM graders with 3–5 domain-expert human annotators on a subset of 50 queries; compute Cohen’s κ and compare MRR correlation to LLM-graded results to validate the grading signal.
