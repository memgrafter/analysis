# Learning from Anonymized and Incomplete Tabular Data

## Quick Facts
- **arXiv ID:** 2602.01217
- **Source URL:** https://arxiv.org/abs/2602.01217
- **Reference count:** 40
- **Primary result:** Granularity-based imputation via specialization regains substantial utility relative to original data baselines, achieving highest average F1 retention (mean loss 0.09 excluding extreme cases, 0.12 including).

## Executive Summary
This paper tackles a realistic yet understudied setting: tabular data where each attribute may be original, generalized (e.g., age range), or missing due to user-driven privacy controls. Standard ML pipelines discard the semantics of generalizations, leading to significant utility loss. The authors propose **specialization**, a granularity-based imputation method that expands generalized and missing entries into plausible concrete variants using observed data patterns, filters to a fixed number of relevant candidates, and applies record weighting to control dataset growth. Evaluated across four datasets, multiple privacy distributions, and three deployment scenarios (anonymization at training, inference, or both), specialization consistently recovers utility, with the best performance in scenarios where anonymization occurs only at training or inference. Key findings include: (1) generalized values always outperform pure suppression; (2) optimal preparation depends on the deployment scenario; (3) privacy metrics suggest preparation does not meaningfully increase re-identification risk.

## Method Summary
The core method, **specialization**, processes an anonymized dataset by: (1) **expansion**: for each generalized or missing value, enumerate all concrete values consistent with the transformation—numeric generalizations become interval midpoints, categorical generalizations and missingness expand to all observed original values within the corresponding group (or all observed values for missing); (2) **filtering**: retain at most a fixed number \(\tilde{v}\) of the most plausible variants per record based on a column profile built from observable original values; (3) **weighting**: assign each expanded variant a weight \(1/|S_i|\) (where \(|S_i|\) is the number of retained variants for record \(i\)) to normalize the total weight per original record to 1. During training, these weights are used in the loss function; at inference, predictions from multiple variants are aggregated via weighted average. The method is contrasted with baselines: simple imputation, MICE, C-MICE, forced generalization, no preparation, and LLM-based prediction. Evaluation uses macro F1 for utility and marketer risk/k-anonymity for privacy, across privacy distributions (e.g., 66% original, 17% generalized, 17% missing) and deployment scenarios (AnTr: anonymized training only; AnTe: anonymized inference only; AnBo: both anonymized).

## Key Results
- Specialization achieves the highest average F1 retention across datasets and scenarios, with mean loss of 0.09 (excluding extreme cases) and 0.12 (including).
- Generalized values consistently outperform pure suppression (missingness) in utility preservation.
- Scenario-dependent optimality: no preparation works best when both training and inference are anonymized (AnBo); when only one side is anonymized (AnTr or AnTe), specialization bridges the representation gap.
- Privacy metrics (marketer risk, k-anonymity) show no meaningful increase in re-identification risk due to preparation.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The specialization algorithm can reconstruct plausible concrete values from generalized and missing entries by expanding them using observed data patterns, thereby preserving the partial information encoded in privacy transformations.
- **Mechanism:** For each anonymized attribute, the algorithm enumerates all original values consistent with the transformation: numeric generalizations are replaced by interval midpoints; categorical generalizations and missing values expand to all observed original values within the corresponding generalization group (or all observed values for missing). This expansion is guided by a column profile built from observable original values in the anonymized dataset, which supplies candidate distributions. [Section 4.3]
- **Core assumption:** The observed original values in the anonymized dataset are representative of the underlying population distribution for those attributes, and the generalization boundaries are meaningful and align with observed value groups.
- **Evidence anchors:**
  - [abstract] "granularity-based imputation via specialization, which expands generalized and missing values into plausible concrete variants using observed data patterns"
  - [Section 4.3] detailed algorithm including specialization step and profile construction.
  - [corpus] Neighboring works such as NAIM and MissDiff focus on imputation under generic missingness but do not account for structured generalization semantics; our use of observed patterns for expansion is distinct.
- **Break condition:** If no original values are observable for an attribute (e.g., all entries are missing or generalized to non-overlapping abstract groups with no original anchors), specialization cannot generate meaningful candidates and degrades to forced generalization or missingness imputation.

### Mechanism 2
- **Claim:** Record weighting introduces normalization to control dataset inflation from specialization, ensuring each original record contributes equally to the learned model and preventing bias toward specialized variants.
- **Mechanism:** After expanding each record into multiple concrete variants, assign each variant a weight of \(1/|S_i|\), where \(|S_i|\) is the number of retained variants for that record. This ensures the total weight per original record sums to 1. During training, sample weights (or loss weighting) incorporate these values; for inference, predictions from multiple variants are aggregated via weighted average. [Section 4.3: Weighting]
- **Core assumption:** The original anonymized record is a valid statistical unit whose contribution should not be multiplied by the expansion process; weighting restores the original representation’s influence.
- **Evidence anchors:**
  - [abstract] "applies record weighting to control dataset growth"
  - [Section 4.3] "Weighting: ... assigning weight \(w = 1/|S_i|\)"
  - [corpus] Not explicitly addressed in neighboring imputation literature; typical multiple imputation uses equal weights across imputations, whereas our per‑record normalization directly addresses combinatorial explosion.
- **Break condition:** If the number of highly plausible variants per record is large, weights become very small; with \(\tilde{v}\) too low, informative variants may be omitted, leading to underrepresentation of certain feature regions and potential information loss.

### Mechanism 3
- **Claim:** Consistent data preparation across training and inference, aligned with the deployment scenario, mitigates distribution shifts; however, the optimal choice (e.g., specialization, no preparation) depends on whether anonymization is present only in training, only in inference, or in both.
- **Mechanism:** In scenarios where training and inference share the same anonymization patterns (AnBo), no preparation often suffices because the model learns decision boundaries directly from coarsened representations. When only one side is anonymized (AnTr or AnTe), preparation (specialization) bridges the representation gap by making the anonymized side more concrete. [Section 3.3, 6.3]
- **Core assumption:** Distribution shift between training and inference feature spaces is a primary cause of utility loss; making representations consistent reduces this shift. Also, the learned model can tolerate added noise from specialization as long as semantic constraints are respected.
- **Evidence anchors:**
  - [abstract] "consistent data representations are crucial for maintaining downstream utility"
  - [Section 6.3] "AnBo performs best when operating directly on anonymized data without any preparation."
  - [corpus] Prior work on missing data imputation [20] finds imputation effectiveness depends on whether missingness affects training, inference, or both, aligning with our scenario‑dependent findings.
- **Break condition:** If anonymization patterns are highly heterogeneous and no original values are available, specialization fails to generate concrete variants; or if training data is extremely small, even consistent preparation may not generalize, causing overfitting.

## Architecture Onboarding
- **Component map:** Anonymized Dataset -> (Specialization (Expander+Filterer+Weighter) | Standard Imputation (simple/MICE/C-MICE) | LLM-based Imputation/Prediction | Forced Generalization | No Preparation) -> Prepared Dataset -> XGBoost Classifier -> Predictions -> Evaluation (Macro F1, Privacy Metrics). For LLM-based: Anonymized Dataset -> LLM-based -> Predictions -> Evaluation.
- **Critical path:**  
  1. Characterize dataset’s privacy distribution (fraction of original/generalized/missing) and deployment scenario.  
  2. Choose preparation method and hyperparameters (e.g., specialization \(\tilde{v}\)).  
  3. Apply preparation to training data (and test data if required).  
  4. Train ML model on prepared training set (or use LLM directly).  
  5. Evaluate on prepared test set.  
  6. Compare with original data baseline and compute privacy metrics.
- **Design tradeoffs:**  
  - Specialization vs. Simplicity: Specialization yields higher utility but adds computational overhead (dataset expansion) and requires sufficient original values. Forced generalization and no‑prep are simpler but lose granular information.  
  - Filtering cardinality \(\tilde{v}\): Larger \(\tilde{v}\) retains more candidate variants but increases compute and risks overfitting; smaller \(\tilde{v}\) may lose plausibility. Paper finds \(\tilde{v}=2\) optimal.  
  - LLM‑based vs. model‑based: LLMs bring external knowledge but are slow and costly; specialization uses in‑domain patterns but fails without any original values.  
  - AnBo scenario: Avoid preparation to skip overhead; but if distributions shift (e.g., due to inconsistent anonymization), preparation may be needed despite added cost.
- **Failure signatures:**  
  - **Performance collapse in AnTe scenario:** indicates that training on original data cannot handle generalized inference; need preparation (specialization) or LLM prediction.  
  - **Over‑specialization:** if F1 drops when increasing \(\tilde{v}\) beyond 2, likely due to noisy or implausible variants.  
  - **Privacy metrics worsening drastically after preparation:** suggests method may be reversing anonymization (though paper found this not typical).  
  - **Inconsistent F1 across datasets:** specialization works better on datasets with clear categorical hierarchies; on mainly numeric or flat domains, benefit reduced.
- **First 3 experiments:**  
  1. **Submethod validation:** For standard imputation (simple/MICE/C‑MICE) and specialization (\(\tilde{v} \in \{1,2,3,5\}\)), evaluate macro F1 on a held‑out dataset (e.g., Income with 66‑17‑17) to confirm \(\tilde{v}=2\) and simple imputation are best per paper.  
  2. **Scenario‑specific test:** Train on original data and test on anonymized (AnTe) with and without specialization to measure distribution shift mitigation; expect large gap without specialization.  
  3. **Generalization benefit:** Compare best F1 using 66‑17‑17 (mix of generalized and missing) vs 66‑0‑34 (only missing) under specialization to confirm that keeping generalized values yields utility gains.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can we gather real-world datasets with actual user-driven privacy decisions to empirically validate the proposed data preparation methods?
- **Basis in paper:** [explicit] The authors state in the Conclusion: "Future work may address gathering real-world datasets or extend to other downstream ML and analytical tasks on comparable data representations." They also note in the Assumptions section that evaluations rely on synthetically generated datasets due to the lack of real-world data with privacy ground truth.
- **Why unresolved:** Current evaluations use simulated privacy transformations, which may not capture the complexity, heterogeneity, and user-specific patterns of actual privacy choices in systems like PODs. Without real-world data, the generalizability of the findings—especially regarding utility gains and privacy risks—remains uncertain.
- **What evidence would resolve it:** Collection and public release of datasets where users' granular privacy preferences (original, generalized levels, missing) are recorded alongside original values, enabling realistic evaluation under varying user-driven anonymization patterns and validation of the scenario-dependent method performance.

### Open Question 2
- **Question:** How can we design privacy metrics that accurately reflect the privacy guarantees of heterogeneous, user-driven anonymization schemes like those studied in this work?
- **Basis in paper:** [explicit] The authors note in the Discussion: "It is important to note that such privacy transformations do not provide formal guarantees and future work would therefore benefit from introducing metrics better aligned with informing user-driven privacy decisions." In Privacy Results, they observe that classical metrics like marketer risk and k‑anonymity "may not adequately capture the privacy properties" and can be misleading (e.g., unprepared anonymized data appears less private despite intended stronger protection).
- **Why unresolved:** Standard metrics treat generalized values and missingness as exact identifiers, ignoring their set-valued semantics. This leads to counterintuitive assessments where increased heterogeneity inflates uniqueness metrics without actual re-identification risk reduction, failing to guide users in making informed privacy choices.
- **What evidence would resolve it:** Development of new privacy metrics that model the information leakage from set-valued attributes (e.g., via entropy-based measures or adversarial re‑identification probability that accounts for generalization hierarchies), validated through user studies and empirical risk analysis on real or simulated heterogeneous datasets.

### Open Question 3
- **Question:** Can Large Language Models (LLMs) effectively approximate domain hierarchies for feature generalization when no original values are available, and how does this approach compare to the proposed specialization method in terms of utility and scalability?
- **Basis in paper:** [explicit] The authors mention in the Assumptions section: "In practice, domain hierarchies are often known or inferable, and future work could leverage LLMs to approximate them, especially when no original values remain." They also show that LLM-based methods become competitive in the 0-66-34 distribution (no original data), while specialization declines without observed originals to build profiles.
- **Why unresolved:** Specialization relies on original values to infer possible concrete variants for generalizations and missing values. When no original values exist, specialization degenerates toward no preparation for categorical features, limiting its utility. Using LLMs to hallucinate or retrieve plausible hierarchies for specialization in such cases is unexplored, and trade-offs against direct LLM prediction are unclear.
- **What evidence would resolve it:** Experiments where LLMs generate candidate value sets for generalized/missing entries (e.g., for "education" → {"High School", "Bachelors", ...}) based on prompts, then integrate with specialization's filtering and weighting. Compare this hybrid approach to pure LLM imputation/prediction and standard specialization on datasets with no original values, measuring F1 utility, computational cost, and privacy impact.

### Open Question 4
- **Question:** What pre-filtering strategies (e.g., feature importance-based specialization, domain consolidation) can reduce the computational overhead of the specialization method without significant utility loss, especially for high-cardinality categorical features?
- **Basis in paper:** [explicit] In the Scalability section, the authors state: "Exploring such pre-filtering strategies is a promising direction for future work." They note that specialization increases dataset size by up to \(\tilde{v}×\), and for high-cardinality categorical features, even \(\tilde{v}=2\) can cause non-negligible overhead. They suggest prioritizing specialization of important features or consolidating large domains during data collection.
- **Why unresolved:** The current specialization uses a uniform \(\tilde{v}=2\) and profile-based filtering across all anonymized attributes. This does not account for feature importance or domain size, potentially wasting resources on low-impact attributes or exploding variant counts for high-cardinality ones. No systematic evaluation of adaptive pre-filtering exists.
- **What evidence would resolve it:** Implement and test strategies like: (1) ranking attributes by importance (e.g., via SHAP values on partially original data) and only specializing top-k; (2) clustering similar generalization groups to reduce candidate sets; (3) dynamic \(\tilde{v}\) per attribute based on domain cardinality. Evaluate these on large datasets with many categorical features, measuring scalability (runtime, memory) and utility retention (F1) across privacy distributions.

## Limitations
- Limited dataset diversity: evaluated on only four datasets, restricting generalizability across domains.
- Privacy metrics inadequacy: standard metrics may not fully capture re-identification risks in heterogeneous anonymization; differential privacy not considered.
- Specialization dependency: requires observed original values to build profiles; fails when none are available.
