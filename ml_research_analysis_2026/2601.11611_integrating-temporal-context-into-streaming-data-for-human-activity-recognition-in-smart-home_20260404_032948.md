# Integrating Temporal Context into Streaming Data for Human Activity Recognition in Smart Home
## Quick Facts
- arXiv ID: 2601.11611
- Source URL: https://arxiv.org/abs/2601.11611
- Reference count: 30
- Primary result: The method improved accuracy and F1-score over state-of-the-art, especially in low-data regimes (average +8.83% accuracy, +9.83% F1-score).

## Executive Summary
This paper addresses Human Activity Recognition (HAR) from sparse streaming smart home sensors by integrating temporal context through three mechanisms: clustering daily activities into time periods to compute separate mutual information weighting matrices, adding cyclical encodings for time-of-day and day-of-week, and including a binary location-change feature. Evaluated on four CASAS datasets, the approach outperforms state-of-the-art in three, with notable gains (up to ~36% accuracy, ~51% F1 excluding "Other") in low-sensor settings. Results highlight the value of temporal context when spatial coverage is limited.

## Method Summary
The pipeline uses event-based sliding windows (size tuned per dataset) to segment raw sensor streams. For each window, a base feature vector records sensor activation counts (or final state). This vector is enriched with: (1) cyclical sine/cosine features of the hour and day-of-week, (2) a binary feature indicating if the last two events originated from different sensors (location change), and (3) period-specific mutual information (MI) weighting—the base vector is multiplied by one of three MI matrices (morning/afternoon/night) derived from training data; the period is assigned based on clustering activity start times. Classification uses a distance-weighted KNN, with K and window size selected via grid search on a user-specific validation set. The model is retrained on combined training and validation data before final testing.

## Key Results
- Outperforms state-of-the-art in three of four CASAS datasets (TM006, TM007, TM008).
- Average improvements: +8.83% accuracy, +9.83% F1-score across all datasets; excluding the dominant "Other" class yields larger relative gains (~36% accuracy, ~51% F1).
- Gains are most pronounced on low-sensor datasets, indicating temporal context is particularly beneficial when spatial signals are sparse.

## Why This Works (Mechanism)
### Mechanism 1: Time-Period-Specific Mutual Information Weighting
- **Claim:** Segmenting the day into temporal clusters (morning/afternoon/night) and computing separate mutual information (MI) matrices for each period improves feature weighting by capturing time-dependent spatial sensor relationships.
- **Mechanism:** The method first clusters activities into three periods by minimizing average intra-cluster distance of activity-descriptor vectors (start hour, one-hot activity, event count). Offline, it computes an MI matrix M_I_χ for each period T_χ, where M_I_χ(i,j) measures the likelihood of sensors i and j firing consecutively within that period's activity segments. During online feature extraction, the event frequency vector is multiplied by the MI matrix corresponding to the current time period, weighting sensors based on time-specific co-occurrence patterns.
- **Core assumption:** Sensor co-occurrence patterns (spatial context) are not static but vary systematically with circadian activity rhythms; modeling this variance yields more discriminative features.
- **Evidence anchors:**
  - [abstract] "...clustering activities into morning, afternoon, and night, and encoding them into the feature weighting method calculating distinct mutual information matrices."
  - [section 3.1] Full derivation of temporal clustering (Eq. 1–4) and period-specific MI computation (Eq. 5–6).
  - [corpus] No direct corpus evidence; neighboring papers focus on deep learning or different temporal modeling approaches.
- **Break condition:** If activity patterns do not exhibit clear temporal clustering (e.g., irregular schedules), the fixed three-period segmentation may misalign MI weights, potentially degrading performance versus a global MI matrix.

### Mechanism 2: Cyclical Time Encoding
- **Claim:** Representing hour-of-day and day-of-week as sine/cosine pairs preserves cyclical continuity (e.g., 23:00 ≈ 00:00), improving a KNN classifier's ability to generalize across temporal boundaries.
- **Mechanism:** Two scalar time features (hour h ∈ [0,23], day d ∈ [0,6]) are transformed into four features: sin(2πh/24), cos(2πh/24), sin(2πd/7), cos(2πd/7). This maps linear time onto a circle, ensuring temporal proximity in the feature space matches actual chronological proximity.
- **Core assumption:** Temporal proximity is meaningful for activity recognition (similar times have similar activity patterns), but numeric time encoding (e.g., hour as integer) artificially distances wrap-around points.
- **Evidence anchors:**
  - [abstract] "...incorporating time of day and day of week as cyclical temporal features..."
  - [section 3.2] Explicit equations (7–10) and visualization (Fig. 3) demonstrating circular embedding.
  - [corpus] Weak; no neighboring abstracts explicitly validate cyclical encoding for this HAR setting.
- **Break condition:** If the classification model (KNN) is insensitive to Euclidean distance in feature space or if temporal patterns are not cyclical (e.g., shift-work with arbitrary schedules), the encoding may add noise without benefit.

### Mechanism 3: Location Change Indicator
- **Claim:** A binary feature signaling a change in the firing sensor between the last two events in a window captures location transitions, which are strong cues for activity boundaries.
- **Mechanism:** For a window's event sequence, compare the sensor ID of the latest event (s_t) to the prior event (s_{t-1}). If different, set feature = 1; else 0. This explicitly encodes inter-sensor movement, complementing aggregated frequency features.
- **Core assumption:** Activity transitions often involve moving between locations (rooms), and sensor change events are proximal indicators of such transitions in sparse PIR/door sensor streams.
- **Evidence anchors:**
  - [abstract] "...adding a binary feature to track the user's location." (paraphrased as location change)
  - [section 3.2] "Location Change Feature" subsection describing the binary indicator.
  - [corpus] No direct corpus evidence; neighboring work uses different transition modeling (e.g., RL-based feature generation).
- **Break condition:** In single-room activities or if sensor placement yields frequent false positives (e.g., multiple sensors per room firing for one activity), this feature may introduce misleading signals.

## Foundational Learning
- **Concept: Mutual Information for Sensor Weighting**
  - *Why needed here:* SWMI weights sensor events based on their predictive power for the activity label, derived from training data. The temporal MI extension requires understanding how MI quantifies dependency between consecutive sensor events.
  - *Quick check question:* If in training data sensor A firing is always followed by sensor B firing within the same activity segment, what would the MI value M_I(i=A, j=B) reflect, and why is this useful for weighting?

- **Concept: Cyclical Feature Encoding**
  - *Why needed here:* Time-of-day is inherently cyclical; naive numeric encoding breaks topological continuity, harming distance-based classifiers like KNN. This concept ensures the model treats 23:59 and 00:01 as adjacent.
  - *Quick check question:* Why would representing "Monday" as integer 1 and "Sunday" as integer 7 mislead a KNN classifier about their similarity, and how do sine/cosine transforms fix this?

- **Concept: k-Nearest Neighbors Classification on Imbalanced Data**
  - *Why needed here:* The paper uses KNN as a non-parametric classifier that can handle multi-class problems and requires no dedicated training phase, but weighted F1-score is used to account for class imbalance (dominant "Other" class).
  - *Quick check question:* In a highly imbalanced HAR dataset where "Sleep" occupies 40% of windows and "Cook" 5%, why is accuracy a misleading metric, and how does weighted F1-score provide a fairer assessment?

## Architecture Onboarding
- **Component map:** Sensor stream input → event-based sliding window segmentation → base feature extraction (sensor counts) → append cyclical time features and location change binary → select time-period-specific MI matrix (morning/afternoon/night) → element-wise multiply with base vector → distance-weighted KNN classification → accuracy/F1 evaluation.
- **Critical path:** The core innovation path is Feature Extraction → Temporal Augmentation → Classification. Specifically: (window events) → (compute base feature vector) → (append cyclical + location features) → (select appropriate MI matrix by current time) → (element-wise multiply with base vector) → KNN classification. Any break in augmentation logic (e.g., incorrect time clustering) compromises the weighted feature vector.
- **Design tradeoffs:**
  - Feature complexity vs. data regime: Temporal features yield larger absolute gains on low-sensor (TM) datasets but marginal/no gains on high-sensor (Aruba) dataset. Adding features increases dimensionality, which may hurt generalization with very limited training data per user.
  - Model choice (KNN): KNN's non-parametric nature avoids overfitting on small user-specific datasets but scales poorly with feature dimension and requires storing all training vectors. It also implicitly assumes local smoothness in feature space, which cyclical encoding supports.
  - Time clustering granularity: Three periods are data-driven but fixed across all datasets. Finer clustering (e.g., hourly) might capture more nuance but risks overfitting and empty clusters.
- **Failure signatures:**
  - Confusion with "Other" class: Normalized confusion matrices (Fig. 4) show most classes are frequently misclassified as "Other", indicating temporal features may not fully disentangle heterogeneous unlabeled transitions.
  - Activity-specific drops: "Enter Home" and "Leave Home" show consistently low recall, suggesting location change feature alone may not capture brief/external-entry patterns.
  - Dataset-dependent efficacy: No improvement on Aruba dataset (Table 2), possibly due to higher sensor density (39 vs ~18) already providing strong spatial cues, making temporal additions redundant or noisy.
- **First 3 experiments:**
  1. Baseline replication: Implement SWMI [13] and BSS [10] baselines exactly as described, using the same event-based windowing and KNN hyperparameter tuning per user. Validate that reproduced metrics match Table 2/3 within 2% tolerance. This establishes a trustworthy reference before adding temporal components.
  2. Ablation on single dataset (e.g., TM006): Starting from SWMI base, incrementally add: (a) cyclical features only, (b) location feature only, (c) both. Also test SWMI-Temp alone. Measure Δaccuracy/F1 (all classes) and Δ (excluding "Other") to isolate each contribution's impact. Expected: cyclical + location yields largest gain; SWMI-Temp smaller gain.
  3. Cross-dataset generalization check: Train on TM006 (low-sensor) and test on TM007 (same family, similar sensor count) vs. train on Aruba (high-sensor) and test on TM006. Hypothesis: temporal features should show stronger transfer from low-sensor to low-sensor datasets, validating their utility in resource-constrained deployments.

## Open Questions the Paper Calls Out
1. **Question:** Do temporal features work for multi-occupant smart homes?  
   **Basis in paper:** [explicit] The authors acknowledge the single-inhabitant limitation and propose multi-person exploration.  
   **Why unresolved:** Overlapping activities and ambiguous sensor events in multi-occupant settings were not evaluated.  
   **What evidence would resolve it:** Test on multi-user datasets with adapted labeling/features and compare metrics.

2. **Question:** How can models generalize to new users with minimal labeled data?  
   **Basis in paper:** [explicit] The authors state models are highly user-specific and suggest self-supervised or unsupervised methods.  
   **Why unresolved:** Per-user training is costly; transferability to unseen users remains unknown.  
   **What evidence would resolve it:** Implement few-shot or domain adaptation on unlabelled data and evaluate on new users with few samples.

3. **Question:** What dataset properties determine the benefit magnitude of temporal context?  
   **Basis in paper:** [inferred] The paper observed larger gains on low-data datasets (e.g., fewer sensors) and linked this to temporal context usefulness.  
   **Why unresolved:** Only four datasets were compared; confounding factors prevent causal conclusions.  
   **What evidence would resolve it:** Perform controlled experiments varying sensor density and event sparsity across many datasets or apply statistical regression to isolate predictors.

4. **Question:** Are the gains from temporal features consistent across classifiers beyond KNN?  
   **Basis in paper:** [inferred] The study exclusively used KNN; other common classifiers were not tested.  
   **Why unresolved:** Some classifiers (e.g., deep models) may inherently learn temporal patterns, potentially reducing feature engineering benefits.  
   **What evidence would resolve it:** Replicate experiments with multiple classifiers (SVM, Random Forest, LSTM) on identical features and compare performance deltas.

## Limitations
- Exact temporal train/val/test splits for CASAS datasets are unspecified, hindering precise replication.
- Hyperparameter search ranges and selected values (K, window size) are not provided, making it difficult to determine optimal settings.
- Evaluation limited to KNN; generalizability to other classifiers unknown.
- The dominant "Other" class remains highly confused; gains when excluding it may not translate to practical utility.
