# RGB-Event HyperGraph Prompt for Kilometer Marker Recognition based on Pre-trained Foundation Models

## Quick Facts
- **arXiv ID:** 2602.22026  
- **Source URL:** https://arxiv.org/abs/2602.22026  
- **Reference count:** 40  
- **Primary result:** HGP-KMR achieves **95.1%** accuracy on EvMetro5K, a **3.4%** absolute gain over the PARseq baseline while adding only **0.8M** parameters.

## Executive Summary
Kilometer Marker Recognition (KMR) in metro environments is hampered by low light, motion blur, and overexposure, which degrade standard RGB OCR systems. This paper introduces **HGP-KMR**, a method that fuses RGB and event data using a hypergraph prompt module to inject multi‑modal features into a pre‑trained RGB OCR foundation model (PARseq). The authors also release **EvMetro5K**, the first large‑scale RGB‑Event dataset for KMR, containing 5 599 synchronized samples. HGP‑KMR reaches state‑of‑the‑art accuracy of **95.1%** on EvMetro5K and shows strong generalisation to WordArt* (91.5%) and IC15* (92.9%) benchmarks, all with a minimal parameter overhead.

## Method Summary
HGP‑KMR builds on PARseq, an OCR model with a Vision Transformer (ViT) backbone and a permuted autoregressive decoder. For each sample, an RGB frame and a reconstructed event grayscale image (both resized to 32×128) are embedded into token sequences. The event tokens are processed by a separate ViT encoder (L layers) to produce modality‑specific features. The RGB embeddings and event features are concatenated and formed into a per‑sample hypergraph via K‑nearest‑neighbors (K = 10). Two hypergraph convolution (HGCN) layers transform these features into a prompt vector, which is added to the output of every ViT block in the RGB backbone. The decoder (K = 6 permutations) predicts the text sequence. Training uses Adam (lr = 7e‑4), a 1‑cycle scheduler, and cross‑entropy loss.

## Key Results
- **95.1%** sequence accuracy on EvMetro5K test set.  
- **3.4%** absolute improvement over the PARseq baseline; adds only **0.8M** parameters.  
- Competitive transfer: **91.5%** on WordArt* and **92.9%** on IC15*.

## Why This Works (Mechanism)
The hypergraph prompt captures high‑order interactions between RGB and event tokens, enabling the frozen RGB backbone to adapt to the complementary temporal cues from event data without full fine‑tuning. Event streams are less affected by motion blur and overexposure, providing robust edges and intensity changes. The prompt is injected layer‑wise, allowing the ViT blocks to modulate their representations progressively. This efficient fusion leverages the strong textual priors of PARseq while compensating for RGB weaknesses, leading to significant gains with minimal added complexity.

## Foundational Learning
- **Vision Transformer (ViT)** – Splits images into patches and processes them with self‑attention. *Why needed:* Handles long‑range dependencies in visual data, forming the backbone for PARseq and the event encoder. *Quick check:* Implement patch embedding and a single attention block; verify gradient flow on a dummy image.
- **Pre‑trained OCR model (PARseq)** – A transformer‑based recogniser trained on large text datasets. *Why needed:* Provides a powerful decoder and language‑aware representations; fine‑tuning from this prior speeds convergence. *Quick check:* Load PARseq (e.g., via official repo) and run inference on a simple scene text image.
- **Event cameras** – Sensors that output asynchronous streams of pixel‑wise intensity changes. *Why needed:* Offer high temporal resolution and high dynamic range, complementing RGB in challenging lighting and fast motion. *Quick check:* Use an event simulator (e.g., from [15]) to generate events from a video and reconstruct a grayscale frame.
- **Hypergraph Neural Networks** – Generalise graphs to hyperedges connecting multiple nodes, modelling higher‑order relationships. *Why needed:* RGB‑Event fusion is not merely pairwise; hypergraphs can capture complex cross‑modal interactions. *Quick check:* Build a small hypergraph from feature vectors and apply a single HGCN layer; ensure output dimension changes as expected.
- **Prompt tuning for transformers** – Inject small, trainable prompts into a frozen backbone to adapt it to new tasks. *Why needed:* Allows parameter‑efficient adaptation of large foundation models; only the prompt and hypergraph are updated. *Quick check:* Add a learnable vector to the input of a transformer block and verify it influences predictions after training.

## Architecture Onboarding
**Component map (data flow):**  
RGB_frame -> Embedding -> T_RGB; Event_frame -> Embedding -> T_E; T_E -> Event_ViT (L layers) -> F_E; [T_RGB, F_E] -> Concat -> Hypergraph (K‑NN, K=10) -> HGCN (2 layers) -> P; for i=1..L: ViT_i(T_RGB) + P -> T_RGB; T_RGB -> Decoder -> Output_sequence.

**Critical path:** The hypergraph prompt generation and its layer‑wise addition to each RGB ViT block are essential; skipping them reverts the model to a simple dual‑encoder baseline.

**Design tradeoffs:**  
- *Event representation:* Grayscale images are easy to handle but discard fine temporal structure; richer formats (voxel grids, raw events) may improve performance at the cost of complexity.  
- *Hypergraph connectivity:* Fixed K=10 offers a balance between capturing relationships and keeping computation tractable; larger K increases receptive field but risks noise.  
- *Parameter efficiency:* Freezing the RGB backbone and only training the prompt/HGCN (0.8 M) reduces overfitting and memory use, yet limits the model’s capacity to adapt to domain shifts.

**Failure signatures:**  
- Accuracy <80% suggests broken data preprocessing (e.g., mis‑aligned RGB‑event pairs or incorrect event reconstruction).  
- No improvement over PARseq baseline indicates the hypergraph module may be incorrectly integrated or the prompt might be too weak.  
- Out‑of‑memory errors point to K‑NN computation on high‑dimensional tokens; using approximate nearest neighbours or lowering batch size may help.

**First three experiments:**  
1. **Baseline replication:** Train PARseq on EvMetro5K (RGB only) to confirm the reported baseline accuracy and validate the dataset pipeline.  
2. **Hypergraph ablation:** Remove the hypergraph prompt addition (i.e., fuse by simple concatenation or addition without HGCN) and compare performance to isolate its contribution.  
3. **Hyper‑parameter sensitivity:** Vary the number of neighbours K in the hypergraph (e.g., 5, 10, 20) and measure accuracy to assess robustness of the graph construction.

## Open Questions the Paper Calls Out
1. **Adaptive mechanisms** – How can event filtering or intensity‑aware modulation be incorporated to further improve robustness under extreme conditions like overexposure?  
2. **Large multi‑modal models** – To what extent can integrating models such as Qwen‑VL enhance KMR accuracy within the HGP‑KMR framework?  
3. **Optimal hypergraph construction** – What is the best choice of K, distance metric, and graph‑building strategy for RGB‑Event text recognition?  
4. **Event representation impact** – How does using alternative event formats (voxel grids, raw events) compare to the grayscale reconstruction, especially under varying motion speeds?

## Limitations
- The exact PARseq architecture dimensions (hidden size, number of layers) and event input normalisation details are not fully disclosed, making precise replication difficult.  
- The isolated effect of the hypergraph prompt module lacks thorough ablation; its contribution relative to simpler fusion mechanisms is uncertain.  
- The EvMetro5K dataset is not publicly released, blocking independent verification and further research on this task.

## Confidence
