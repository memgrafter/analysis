# Language-Aware Distillation for Multilingual Instruction-Following Speech LLMs with ASR-Only Supervision

## Quick Facts
*   **arXiv ID:** 2603.07025
*   **Source URL:** https://arxiv.org/abs/2603.07025
*   **Reference count:** 0
*   **Primary result:** Introduces a language-aware query bank and gating network to mitigate interference in multilingual Speech LLMs, achieving a 14% relative gain on instruction following and a 32% improvement on Audio-MLQA over strong baselines.

## Executive Summary
Training multilingual Speech LLMs to follow instructions using only ASR data is challenged by **language interference** within a shared, static query projector that maps speech embeddings to a frozen LLM's input space. This interference causes dominant languages to overshadow lower-resourced ones. This paper proposes a solution that replaces the single static query sequence with a **language-specific query bank** and a lightweight **gating network (Q-Former)**. The gating network dynamically selects or mixes the appropriate query tokens based on the input speech's language identity, effectively disentangling language-specific features. The system is trained via a combination of input/output distillation losses and a language ID loss, all computed from ASR-only data. The method demonstrates substantial improvements on both open-ended instruction following and a new spoken QA benchmark, with hard query selection proving more effective than soft mixing.

## Method Summary
The approach trains a lightweight Q-Former projector to bridge a frozen speech encoder (Whisper) and a frozen instruction-tuned LLM (Llama-SEA-LION), using only ASR supervision. It replaces the conventional single set of static query tokens with a **bank of language-specific query sequences**. A **gating network** processes the speech encoder's output to produce language logits. During training, these logits are used with a straight-through estimator for **hard selection** (choosing one language's queries) or for **soft mixing** (weighted sum of queries). The projector is trained with three losses: (1) **Input distillation** aligns the projected speech embeddings with the text transcript embeddings from the LLM's input layer, (2) **Output distillation** aligns the LLM's final hidden states from speech vs. text conditioning, and (3) **LID loss** supervises the gating network's language prediction. Scheduled teacher forcing supports stable gating network training.

## Key Results
*   The proposed model with **hard query selection** achieves a **14% relative gain** on open-ended instruction-following evaluations compared to the ML-DiVA baseline.
*   It yields a **32% improvement** on the new **Audio-MLQA** spoken question-answering benchmark.
*   **Hard selection consistently outperforms soft mixing**, indicating that strong decoupling of language-specific information is more beneficial than a softened averaging approach.

## Why This Works (Mechanism)

### Mechanism 1: Dedicated Query Subspaces Decouple Language Mappings
*   **Claim:** Language-specific query tokens reduce interference by providing dedicated representation subspaces for each language's phonetic-semantic mappings, preventing dominant languages from overwriting shared parameters.
*   **Mechanism:** A single static query sequence `Q` must compromise across all languages. A bank `B = {Q^(k)}` stores separate query sets per language. The gating network routes an utterance to its language-specific query subspace (`Q̃`) before projection.
*   **Core assumption:** Language interference arises primarily from the projector's query tokens being forced to represent multiple languages simultaneously; separate queries can isolate these mappings.
*   **Evidence anchors:** Paper identifies shared static query projector as source of interference [abstract, Sec 2.2.1]. Hard selection, which enforces strict decoupling, outperforms soft mixing [Sec 4.3].
*   **Break condition:** If languages are typologically very similar or training data is perfectly balanced, interference may be minimal, reducing the marginal benefit of a query bank.

### Mechanism 2: Dynamic Routing via Gating Network
*   **Claim:** The Q-Former gating network enables data-dependent routing, handling code-switching or uncertain language identities via soft mixing, while hard selection provides strong decoupling.
*   **Mechanism:** An utterance-level language identifier (LID) `g = G_ϕ(H)` is computed from speech embeddings `H`. Logits `g` either select a single query (`hard`) or compute a weighted sum (`soft`). A straight-through estimator allows gradient flow during training while maintaining discrete selection at inference.
*   **Core assumption:** A deterministic language label or strong LID signal exists per training sample, and the gating network can reliably predict it from speech features; scheduled teacher forcing aids convergence.
*   **Evidence anchors:** Gating network architecture described in Sec 2.2.2. Both gating variants achieve >94.9% LID accuracy [Sec 4.3], enabling effective routing.
*   **Break condition:** If speech features lack clear language-discriminative cues (e.g., heavy accent, noise, intra-utterance code-switching), the gating network may misroute, causing performance drops.

### Mechanism 3: Distillation Losses Align Speech-Text Behavior
*   **Mechanism:** Three distillation losses align speech-conditioned LLM behavior with the text-only teacher: (1) **Input distillation** (`L_IN`) matches projected speech embeddings `Z` to transcript embeddings `Y` (audio tail to text head). (2) **Output distillation** (`L_OUT`) matches final hidden states from speech vs. text conditioning. (3) **LID loss** (`L_LID`) supervises the gating network. The combined loss `L = λ_IN L_IN + λ_OUT L_OUT + λ_LID L_LID` trains both the projector's capacity and the routing policy.
*   **Core assumption:** Matching intermediate representations is a sufficient proxy for matching end-task behavior, and routing ensures each language's alignment happens in its dedicated query space.
*   **Evidence anchors:** Loss definitions in Sec 2.3. Ablation shows increasing query length `L` reduces `L_IN` by 89% [Sec 4.3], confirming capacity's role. Hard-gating model's 14% gain over ML-DiVA shows effective routing improves downstream performance beyond capacity alone [Sec 4.1].
*   **Break condition:** If the speech encoder's representations are fundamentally mismatched to the LLM's text space, distillation losses may not converge regardless of routing. Poor λ weight tuning could also imbalance objectives.

## Foundational Learning
*   **Concept: Multimodal alignment via lightweight projectors (e.g., Q-Former).**
    *   **Why needed here:** The core task is training a projector that maps frozen speech encoder outputs to the frozen LLM's input space using only ASR data. Understanding how a Q-Former attains cross-modal alignment is prerequisite to grasping why a single set of queries fails multilingually.
    *   **Quick check question:** How does a Q-Former, initialized from a text decoder, learn to attend to speech features to produce text-like embeddings, and why might a single set of queries be insufficient for multiple languages?

*   **Concept: Language interference in multilingual representation learning.**
    *   **Why needed here:** The paper's diagnosis is that a shared static projector causes "language interference." This requires understanding how parameter sharing in multilingual models can lead to catastrophic interference for low-resource/language-distant pairs.
    *   **Quick check question:** In a shared projection layer, what specific mechanism causes dominant languages to "overshadow" others, and how might dynamic routing mitigate this?

*   **Concept: Distillation objectives for behavior alignment (input vs. output).**
    *   **Why needed here:** Training uses two distillation losses. Distinguishing between matching input embeddings (`L_IN`) and matching hidden states (`L_OUT`) is key to understanding what "alignment" means here versus logit-level distillation.
    *   **Quick check question:** What is the hypothesized difference in what `L_IN` and `L_OUT` enforce, and why might `L_OUT` be a "cheaper but close approximation" to full output distribution matching?

## Architecture Onboarding
*   **Component map:**
    1.  **Frozen Speech Encoder (Whisper-large-v3):** `H = E_sp(x) ∈ R^{T×d_s}`. No gradients.
    2.  **Query Bank & Gating Network:** Trainable bank `B = {Q^(k) ∈ R^{L×d_ℓ}}_{k=1}^K`. Gating `G_ϕ(H)` produces logits `g ∈ R^K` for selection/mixing.
    3.  **Q-Former Projector:** Attends over `H` with effective queries `Q̃` (from bank) to produce `Z = P_θ(Q̃, K, V) ∈ R^{L×d_ℓ}`. Lightweight, trainable.
    4.  **Frozen LLM (Sea-LION-v3-8B-IT):** Takes `Z` as prefix. No gradients to encoder or LLM.
    Flow: Speech `x` -> Encoder `H` -> Gating `g` -> Query Selection/Mixing `Q̃` -> Q-Former `Z` -> LLM Generation.

*   **Critical path:** The trainable components are the query bank, gating network, and Q-Former projector. The only data flows are: (a) speech -> encoder -> gating -> query selection -> Q-Former -> LLM, and (b) text transcript -> LLM (for teacher embeddings). Losses: `L_IN` (match `Z` tail to text head), `L_OUT` (match LLM final hidden state from speech vs. text), `L_LID` (match `g` to true language).

*   **Design tradeoffs:**
    *   **Hard vs. Soft Routing:** Hard (`argmax`) gives stronger decoupling but risk of brittle routing; Soft (`softmax mixing`) is smoother but risks "averaging" interference. Paper finds hard superior for final performance.
    *   **Query Bank Capacity `L`:** Larger `L` reduces alignment loss (Table 3) but increases parameters and compute. Tradeoff between representation power and efficiency.
    *   **Gating Architecture:** Conv-DS (LID-style) vs. Attn-Pool. Similar LID accuracy; choice may affect robustness to variable-length speech.

*   **Failure signatures:**
    *   **High `L_LID` loss:** Gating network cannot predict language; routing fails → performance drop on low-resource languages.
    *   **High `L_IN`/`L_OUT` despite training:** Projector capacity insufficient (`L` too small) or speech-text embedding mismatch too large.
    *   **Degradation on specific languages:** Language not in query bank? Or misrouting due to ambiguous speech features. Check per-language validation scores.
    *   **Unstable training early on:** Without scheduled teacher forcing (`p_tf`), random query initialization may cause collapse; monitor routing entropy.

*   **First 3 experiments:**
    1.  **Validate LID accuracy:** On a held-out set, compute LID accuracy (using ground-truth language labels). Must be >90% for effective routing. If <80%, inspect gating network inputs (`H`) for discriminability.
    2.  **Query capacity sweep:** Train with `L ∈ {64, 128, 256}` while keeping other hyperparams fixed. Measure `L_IN` and downstream task scores (e.g., Audio-MLQA). Expect diminishing returns beyond 256.
    3.  **Hard vs. Soft ablation:** Train identical models differing only in routing (hard straight-through vs. soft). Evaluate on low-resource language (e.g., Indonesian) and high-resource (English). Confirm hard gives larger relative gain on low-resource, indicating better interference reduction.

## Open Questions the Paper Calls Out
*   **Open Question 1: Scalability with Number of Languages.**
    *   **Question:** How does the performance, parameter efficiency, and routing accuracy of the language-aware distillation framework change as the number of languages K increases far beyond the six evaluated in the paper?
    *   **Basis in paper:** The authors propose a query bank with one query sequence per language (K total) and a gating network that outputs K logits (Sec 2.2.1). They acknowledge that the static projector fails with increased language diversity (Sec 2.2), but their experiments are limited to six languages (Sec 4, Table 2). No scaling results are provided.
    *   **Why unresolved:** The linear growth of query parameters and gating dimensionality may become impractical for hundreds of languages; the gate may struggle to discriminate among many options, potentially reintroducing interference or reducing LID accuracy. The trade-off between capacity and scalability is unknown.
    *   **What evidence would resolve it:** Conduct experiments varying K from small (6) to large (e.g., 50, 100, 200) using a broad language sample. Report downstream task performance (instruction following, QA), LID accuracy, total trainable parameters, and inference latency. Analyze whether query sharing or clustering could mitigate scaling costs.

*   **Open Question 2: Generalization to Unseen Languages.**
    *   **Question:** Can the model handle languages that were not present in the ASR training data (zero-resource) at test time, and what architectural modifications or training schemes are necessary to enable such generalization?
    *   **Basis in paper:** The training data consists solely of ASR corpora for six languages (Sec 3.1, Table 1). The gating network is supervised by a language ID loss with labels only for those languages (Eq. 1). The query bank contains a dedicated query for each seen language (Sec 2.2.1). The paper does not address the scenario of an input speech in an unseen language.
    *   **Why unresolved:** At test time, an utterance from an unknown language would produce language logits that do not correspond to any known query; the gating mechanism would still select among the existing queries, potentially forcing a poor match. Without a mechanism for unknown languages, the system may fail catastrophically for zero-resource languages.
    *   **What evidence would resolve it:** Propose and evaluate strategies such as (i) adding an "unseen" query that catches unknowns, (ii) routing to the nearest known language query based on acoustic distance, or (iii) meta-learning the gating network to handle novel classes. Test on held-out languages with no ASR data, measuring degradation in task performance and the proportion of utterances routed to the unseen branch.

*   **Open Question 3: Impact of Linguistic Similarity.**
    *   **Question:** How does the degree of linguistic similarity between pairs of languages affect the magnitude of interference in the static projector and the relative benefit of the proposed language-aware routing?
    *   **Basis in paper:** The authors write: "Particularly for distant pairs such as English and Chinese, this lack of language-specific flexibility leads to performance degradation due to language interference" (Sec 2.2). They also observe improved performance for Indonesian, a lower-resourced language (Sec 4.1). However, no systematic variation or metric of language similarity is analyzed across the six languages.
    *   **Why unresolved:** The claim that distant languages suffer more is based on anecdotal evidence. Without quantifying similarity (e.g., lexical, phylogenetic, or phonological distance), it is unclear whether the gains from language-aware routing are predictable and whether the method would be most beneficial for typologically distant language sets.
    *   **What evidence would resolve it:** Compute standard language distance metrics (e.g., from URIEL or Ethnologue) for all language pairs in the study. Correlate these distances with the performance gap between the shared projector baseline and the language-aware model. Run controlled experiments with artificially defined language groups to test causality.

*   **Open Question 4: Optimal Training for the Gating Network.**
    *   **Question:** Is scheduled teacher forcing the optimal training strategy for the gating network, or could alternative approaches (e.g., pre-trained LID, curriculum, or reinforcement learning) yield better stability, higher LID accuracy, and improved downstream performance?
    *   **Basis in paper:** The paper uses scheduled teacher forcing, where ground-truth language labels are fed to the gate with a decaying probability (Sec 2.2.2). This is described as a stabilization technique. No comparisons to other training schemes are reported.
    *   **Why unresolved:** Teacher forcing may bias the gate early on and slow convergence for languages with scarce data. Other methods might help the gate learn more robust language-specific representations, especially under data imbalance or when extending to many languages. The design choice is not justified empirically.
    *   **What evidence would resolve it:** Ablate training strategies: baseline (no TF), constant TF, cosine-annealed TF (current), pre-trained LID (freeze or fine-tune), curriculum (start with easy languages), and RL-based routing (reward based on downstream loss). Compare convergence curves, final LID accuracy, and task metrics.

## Limitations
*   **Unspecified training details:** Key hyperparameters like loss weighting coefficients (λ_IN, λ_OUT, λ_LID), scheduled teacher forcing schedule parameters, and precise gating network architectures (Conv-DS downsampling factors, Attn-Pool MLP dimensions) are not provided.
*   **Evaluation reproducibility:** The GPT-4.1 judging prompts for Audio-MLQA and open-ended evaluations are unavailable, making exact replication of reported scores impossible.
*   **Data preprocessing ambiguity:** Details on tokenization for LLM input, padding strategies for variable-length sequences, and exact TTS systems used for evaluation are not described.

## Confidence
*   **Mechanism 1 (query bank reduces interference):** Medium. Hard selection outperforming soft mixing supports decoupling, but the break condition for similar/balanced languages is untested.
*   **Mechanism 2 (gating network dynamic routing):** Medium-High. >94.9% LID accuracy validates routing feasibility, but robustness to code-switching or heavy accents—a key break condition—is unexamined.
*   **Mechanism 3 (distillation losses align representations):** Medium. Loss reductions correlate with gains, but sensitivity to λ weights and the relationship between `L_IN` minimization and downstream performance are unknown.

## Next Checks
1.  **Imbalanced-language interference test:** Train baseline (static query) vs. proposed under skewed distributions (e.g., 80% English, 20% pooled others). Measure per-language performance delta on low-resource languages to isolate interference reduction attributable to the query bank.
2.  **Code-switched routing robustness:** Construct test utterances with intra-utterance language switches (e.g., English-Indonesian). Evaluate LID accuracy and Audio-MLQA scores for hard vs. soft routing to validate whether soft mixing indeed handles ambiguous speech better.
3.  **λ-weight sensitivity sweep:** Systematically vary λ_IN, λ_OUT, λ_LID (e.g., {0.1, 1.0, 10.0}) while monitoring `L_IN` convergence and final Audio-MLQA gains. Identify whether the paper’s likely λ=1 is optimal or if different weight regimes alter the hard-vs-soft conclusion.
