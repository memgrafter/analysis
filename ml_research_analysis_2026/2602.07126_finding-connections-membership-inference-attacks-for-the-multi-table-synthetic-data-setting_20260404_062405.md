# Finding Connections: Membership Inference Attacks for the Multi-Table Synthetic Data Setting

## Quick Facts
- arXiv ID: 2602.07126
- Source URL: https://arxiv.org/abs/2602.07126
- Reference count: 40
- Primary result: MT-MIA exposes user-level privacy leakage in multi-table synthetic data, outperforming single-table attacks by up to 15+ percentage points in TPR at 0% FPR.

## Executive Summary
The paper addresses a critical privacy risk: synthetic relational data, generated to preserve utility while protecting individual privacy, may still leak membership information through inter-table dependencies. Existing membership inference attacks (MIAs) focus on single-table settings and fail to audit such relational leakage. The authors propose MT-MIA, a no-box attack that treats a user entity across multiple tables as a heterogeneous subgraph. Using a heterogeneous graph neural network (HGNN) with a bifurcated design, MT-MIA learns embeddings that combine parent attributes and relational context. Trained via self-supervised reconstruction on the synthetic dataset, the attack scores membership by nearest-neighbor distance in the embedding space. Experiments on three datasets and two state-of-the-art multi-table generators show MT-MIA significantly surpasses single-table baselines (e.g., +15 TPR points at zero FPR on Airlines with ClavaDDPM). The results reveal that even advanced generators leak information, and a fidelity-privacy tradeoff exists: higher-quality synthetic data correlates with greater vulnerability.

## Method Summary
MT-MIA transforms a relational database into a heterogeneous graph where each row is a node labeled by its table type and foreign keys become typed edges. For each entity (e.g., a user), the connected subgraph spanning its records across tables is extracted. The attack employs an HGNN encoder Mθ that applies multiple heterogeneous message-passing layers (e.g., GATv2) to propagate information across node types. From the final node embeddings, two signals are derived: z_parent from the root (parent) node and z_context from a type-specific global attention pooling over child nodes. These are fused by a dynamic gated unit to produce z_final. The encoder is trained on the synthetic graph G_synth together with two decoders: one reconstructs the parent node’s features, the other reconstructs the sum of child node features. This self-supervised objective forces the encoder to capture patterns memorized by the generator. After training, a reference bank of embeddings from all synthetic subgraphs is built. For a target real subgraph, its embedding is computed, and its membership score is the negative squared Euclidean distance to the nearest neighbor in the reference bank. The attack is evaluated using AUC and TPR at low FPR thresholds.

## Key Results
- MT-MIA achieves up to 15+ percentage points higher TPR at 0% FPR compared to single-table MIA baselines across three datasets (Airlines, California Census, Airbnb).
- Both parent attributes and relational context contribute to leakage; the gated fusion adaptively weights these signals but sometimes one dominates.
- A fidelity-privacy tradeoff is observed: higher-quality generators (ClavaDDPM) exhibit stronger membership leakage than lower-fidelity ones (RealTabFormer).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Representing relational databases as heterogeneous graphs captures inter-table dependencies invisible to single-table attacks, enabling user-level membership inference.
- **Mechanism**: Each row becomes a node with type label; foreign keys become typed edges; a user entity forms a connected subgraph across tables. This explicitly models relationships that define a user.
- **Core assumption**: Privacy leakage occurs at the user-entity level and is mediated through relational structure (e.g., conditional dependencies between parent and child tables).
- **Evidence anchors**:
  - Abstract: “Synthetic relational data release leaks user-level privacy through inter-table dependencies, which single-table Membership Inference Attacks (MIAs) fail to audit.”
  - Section 3.1: “Relational databases naturally induce heterogeneous graphs… This transformation preserves the relational schema as a meta-structure governing the connectivity patterns between different node types.”
  - Corpus: The MIDST Challenge (arXiv:2603.19185) reported that strongest attacks relied exclusively on a designated main table, confirming the prevalence of relational leakage.
- **Break condition**: The graph representation provides advantage only when leakage arises through inter-table relationships; if all leakage is confined to independent single-table distributions, single-table attacks suffice.

### Mechanism 2
- **Claim**: An HGNN encoder with bifurcated pathways for parent and relational context, combined with dynamic gated fusion, learns embeddings that encode both intrinsic attributes and structural patterns, which are discriminative for membership.
- **Mechanism**: The encoder applies multiple heterogeneous message-passing layers (e.g., GATv2). Then a global attention pool aggregates child nodes into z_context, while the root node forms z_parent. A gating unit modulates the integration into z_final.
- **Core assumption**: Membership signal may reside in parent attributes, child relational patterns, or their interaction; the gating mechanism allows the attack to adaptively emphasize the more informative component without prior knowledge.
- **Evidence anchors**:
  - Abstract: “MT-MIA … targets learned representations of user entities via Heterogeneous Graph Neural Networks.”
  - Section 4.1: “To capture the semantics of the relational schema, we utilize a stack of L heterogeneous message passing layers… we bifurcates the resulting node embeddings into two distinct semantic vectors: Parent Signal and Relational Context… Dynamic Gated Unit… to adaptively modulate the integration.”
  - Corpus: Limited direct evidence; neighboring works on multi-table generation (e.g., arXiv:2507.06996) emphasize modeling relational structure but do not specifically use HGNNs, making this an innovation of MT-MIA.
- **Break condition**: The HGNN requires sufficient relational connectivity; it may fail on schemas with very sparse relationships or when memorization is not expressed in neighborhood structure.

### Mechanism 3
- **Claim**: Training the HGNN with a self-supervised reconstruction objective (reconstructing parent features and aggregated context) creates an embedding space where training subgraphs cluster near synthetic subgraphs, enabling membership inference via a nearest-neighbor distance score.
- **Mechanism**: The encoder and two decoders are trained on synthetic subgraphs to reconstruct both the root node’s features and the sum of its neighbors’ features. After training, for a real test subgraph, the membership score is the negative Euclidean distance to the closest synthetic embedding (DCR attack).
- **Core assumption**: Synthetic data generated from a training set contains memorized patterns of training subgraphs; these patterns are reflected in the latent space learned by the reconstruction task, such that member subgraphs have embeddings closer to synthetic ones than non-members.
- **Evidence anchors**:
  - Abstract: “MT-MIA performs membership inference by learning graphical representations of user-centric subgraphs… under a No-Box threat model.”
  - Section 4.2: “We train Mθ using a self-supervised reconstruction objective… For a target node i… the composite reconstruction loss… membership scoring: f(h*) = -min_{h⊆Gsynth} ||Mθ(h*)-Mθ(h)||^2”
  - Corpus: Distance-based attacks are common in single-table MIAs; see “Ensembling Membership Inference Attacks” (arXiv:2509.05350) and the MIDST Challenge which employed various distance metrics, supporting the principle that memorization induces proximity in some feature space.
- **Break condition**: The reconstruction objective assumes synthetic data faithfully reproduces training patterns; if the generator is heavily regularized or synthetic data is of very low fidelity, the embedding may not separate members from non-members. Also, if reconstruction tasks are too easy or too hard, the learned representation may not capture the relevant signal.

## Foundational Learning
- **Membership Inference Attacks (MIA)**
  - Why needed: MT-MIA is a specific instantiation of MIA; understanding the adversarial goal (distinguishing training records) and evaluation metrics (AUC, TPR@FPR) is essential to interpret results.
  - Quick check: “What does a TPR of 0.15 at FPR=0.001 suggest about the privacy risk of a synthetic data release?”
- **Heterogeneous Graph Neural Networks (HGNNs)**
  - Why needed: The attack’s encoder processes multi-type nodes and edges; knowing how message passing and attention work on heterogeneous graphs explains how relational information is integrated.
  - Quick check: “In a heterogeneous graph, why might we use separate weight matrices for different node types?”
- **Relational Databases and Subgraph Extraction**
  - Why needed: MT-MIA operates on user-centric subgraphs derived from relational schemas; understanding foreign keys and how to decompose a database into disjoint connected components is necessary to construct attack inputs.
  - Quick check: “Given a ‘Users’ table and an ‘Orders’ table linked by user_id, how would you define a subgraph for a single user?”

## Architecture Onboarding
**Component map**  
Data Ingestion -> Subgraph Sampler -> Encoder (Mθ) -> Reconstruction Heads (Dφ, Dψ) -> Trainer. After training: Encoder (frozen) -> Reference Bank -> Membership Scorer -> Evaluator.

**Critical path**  
1. Preprocess: Build synthetic and real graphs; extract disjoint user subgraphs.  
2. Train encoder+decoders on synthetic subgraphs until reconstruction loss converges.  
3. Freeze encoder; generate embeddings for all synthetic subgraphs to populate reference bank.  
4. For each real subgraph (from train and holdout), compute embedding, query reference bank for nearest neighbor distance to obtain score.  
5. Evaluate attack performance metrics (AUC, TPR@FPR).

**Design tradeoffs**  
- HGNN choice: GATv2 offers expressive attention but may be overkill; simpler RGCN could be faster but less discriminative.  
- Reconstruction loss weighting (λp, λc): Tuning needed; imbalance may cause the encoder to ignore one signal.  
- Gated fusion vs concatenation/average: Gating adds adaptability but increases parameters and risk of overfitting on small synthetic data.  
- Training data: Using all synthetic subgraphs assumes synthetic data is abundant; if scarce, few-shot adaptation may be required.  
- Scoring metric: Euclidean distance is simple; alternatives like cosine could be used.

**Failure signatures**  
- Reconstruction loss plateaus at high value: encoder not learning; check model capacity, learning rate, synthetic data quality.  
- Embeddings form a single cluster: no separation; likely TPR@0 is 0. Inspect gating weights for vanishing signals (all near 0 or 1).  
- Gating weights saturated: may indicate one signal dominates; consider tuning λp/λc.  
- Training instability (loss spikes, NaNs): reduce learning rate, increase batch size, gradient clipping.  
- High variance across runs: sensitivity to initialization or data splits; fix seeds, average over multiple runs.

**First 3 experiments**  
1. Motivating Example Validation: Recreate the toy dataset from Section 3.5 (Customers-Transactions with cardinality 1 vs 100). Verify MT-MIA achieves AUC > 0.95 while DCR on parent table yields AUC ≈ 0.5.  
2. Full Dataset Benchmark: Run MT-MIA on one dataset (e.g., Airlines) with ClavaDDPM generator. Compare against single-table baselines (DCR, MC). Expect MT-MIA to show significantly higher TPR@0% FPR (e.g., >10 pp improvement).  
3. Ablation Study: Disable the gated fusion (use average of z_parent and z_context) or remove context reconstruction (λc=0). Measure drop in AUC/TPR to isolate contributions.

## Open Questions the Paper Calls Out
- **Open Question 1**: How can membership inference attacks be made feasible under less conservative threat models (e.g., shadow-box) in multi-table settings given the computational cost of training shadow models for relational generators? *Basis*: Shadow attacks are computationally prohibitive for multi-table generators like ClavaDDPM (up to an hour per run). Without scalable methods, the true upper bound of privacy vulnerability remains unknown.  
- **Open Question 2**: Can user-level differential privacy mechanisms be designed specifically for relational data generation that provably protect against user-level membership inference? *Basis*: Existing DP mechanisms for tabular data do not account for relational structure where privacy must encompass all connected items as a unit.  
- **Open Question 3**: What is the mechanistic relationship between synthetic data fidelity (marginal, intra-tabular, relational) and membership vulnerability in multi-table generators? *Basis*: The paper observes a fidelity-privacy tradeoff but does not explain the causal link; understanding which fidelity components drive leakage is needed.  
- **Open Question 4**: Which HGNN architectural choices (message passing schemes, pooling strategies, signal fusion) optimize membership discrimination for relational synthetic data across diverse schemas and generators? *Basis*: MT-MIA uses a specific heuristic design; systematic comparison is lacking.

## Limitations
- Exact hyperparameters and subgraph construction rules are not provided, hindering exact replication.  
- The attack’s effectiveness depends on synthetic data fidelity; heavy regularization or low-fidelity generators may collapse the embedding signal.  
- The assumption that privacy leakage is always mediated at the user-entity level via relational structure may not hold for schemas with sparse relationships.

## Confidence
- Graph representation captures inter-table leakage: High
- HGNN with gated fusion integrates parent/context signals: Medium
- Self-supervised scoring via nearest-neighbor works: Medium
- Fidelity-privacy tradeoff: Medium
