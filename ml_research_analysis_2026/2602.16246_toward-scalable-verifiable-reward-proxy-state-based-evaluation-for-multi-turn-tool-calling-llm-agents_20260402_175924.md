# Toward Scalable Verifiable Reward: Proxy State-Based Evaluation for Multi-turn Tool-Calling LLM Agents

## Quick Facts
- arXiv ID: 2602.16246
- Source URL: https://arxiv.org/abs/2602.16246
- Reference count: 13
- Primary result: Proposes Proxy State-Based Evaluation, an LLM-based outcome verification method that replaces deterministic backends, yielding stable model rankings (e.g., GPT-5 high RE: 85.76% GC vs. minimal: 66.04%) and effective training signal (SFT on Qwen3-30B: +11.7% GC), with >90% human-LLM agreement.

## Executive Summary
The paper introduces Proxy State-Based Evaluation, a cost-effective alternative to deterministic backends for multi-turn tool-calling agent benchmarks. It uses an LLM state tracker to infer a structured proxy final state from the interaction trace, and LLM judges to verify goal completion and detect hallucinations against scenario constraints. The method produces stable, model-differentiating rankings and provides reliable reward signals for training; fine-tuning Qwen3-30B with off-policy rollouts improved goal completion by 11.7%. High human-LLM agreement (>90%) and low hallucination rates demonstrate the approach's scalability and robustness.

## Method Summary
The benchmark framework defines scenarios (z) specifying user goal g(z), user facts u(z), initial system state s0(z), expected final state s*(z), and required agent behavior b*(z). A Reasoning Agent (RA) interacts via a ReAct loop with a user simulator (f_user) and tool simulators (f_tool for call_account, call_commerce). After each tool step, an LLM state tracker (f_state) consumes the full interaction prefix to update a proxy state s̃_t,k, approximating the latent database state. At termination, two LLM judges evaluate goal completion (J_goal) and hallucinations (J_hall) by comparing the final proxy state and trajectory against the scenario specifications. The environment generates on-policy or off-policy rollouts with binary outcome labels; successful trajectories can be used for rejection-sampling fine-tuning or SFT to train agents that generalize to unseen scenarios.

## Key Results
- Model rankings are stable and discriminative: GPT-5 high RE achieved 85.76% goal completion, while minimal achieved 66.04%.
- Supervised fine-tuning (SFT) on Qwen3-30B with off-policy rollouts improved goal completion from 65.64% to 77.34% (+11.7%).
- High reliability: human-LLM judge agreement exceeds 90%, and with full scenario facts, tool/user hallucination rates are low (1.33% and 0.67% respectively).

## Why This Works (Mechanism)
### Mechanism 1: Proxy State Inference
Claim: Final state-based evaluation can be reliably performed without a deterministic backend by inferring a structured "proxy" final state from the full interaction trace using an LLM state tracker.  
Mechanism: A scenario defines an expected final state s*(z). An LLM state tracker f_state consumes the entire trajectory (user messages, tool calls, tool outputs) to infer the current proxy state s̃_t,k at each step, updating it based on the semantic effect of tool calls rather than executing on a database. The final proxy state s̃_T is then compared to s*(z) by an LLM judge to determine goal completion.  
Core assumption: The LLM state tracker can accurately synthesize a coherent, structured representation of the world state from the textual trace of interactions, and this proxy state is sufficiently consistent for outcome-based scoring.  
Evidence anchors: Abstract states f_state infers a structured proxy state; Section 3.1 defines the proxy state; internal experiments show stable rankings across models.  
Break condition: If the state tracker's internal representation becomes inconsistent or diverges from a logically coherent world state (e.g., due to long-horizon error accumulation), the final state comparison becomes invalid.

### Mechanism 2: LLM Judges for Outcome Verification
Claim: LLM-based judges can reliably automate outcome evaluation (goal completion, hallucination detection) when calibrated against human experts and given a complete scenario specification.  
Mechanism: Two specialized LLM judges are used: J_goal compares the (trajectory, final proxy state) against the scenario's expected final state and behavior (s*(z), b*(z)). J_hall checks for tool/user hallucinations against the scenario's system/user facts (s0(z), u(z)). Human expert annotations validate the judges.  
Core assumption: LLM judgments on structured outcome conditions are stable and align with human domain expert judgments, provided the scenario specifications are unambiguous and complete.  
Evidence anchors: Abstract mentions LLM judges verifying goal completion and detecting hallucinations; Section 4 reports >90% human-LLM agreement; ablation shows hallucination rates rise when facts are removed.  
Break condition: If scenario definitions are ambiguous or lack critical constraints, or if judge models are weak/inconsistent, human-LLM agreement would drop, undermining evaluation reliability.

### Mechanism 3: Transferable Training from Simulated Rollouts
Claim: Rollouts (trajectories with reward labels) generated from this simulated environment provide effective, transferable supervision for training reasoning agents (RA), even when the rollouts are off-policy (from a stronger teacher).  
Mechanism: The benchmark acts as an on-policy data generator. Successful trajectories (c=1) are filtered and used for rejection-sampling fine-tuning (RFT) or supervised fine-tuning (SFT). The training signal is the final outcome (goal completion) derived from the proxy state evaluation. This learns policies that generalize to unseen scenarios.  
Core assumption: The policy learned from successful interaction traces in this proxy environment captures the necessary skills (tool selection, state reasoning) that transfer to held-out scenarios with similar structure, despite the simulation being LLM-based rather than deterministic.  
Evidence anchors: Abstract mentions on/off-policy rollouts provide supervision that transfers; Section 5 shows SFT on Qwen3-30B improved GC; neighbor papers support synthetic trajectory training.  
Break condition: If the state tracker or judges have systematic biases, the reward labels on rollouts become misaligned with true task success, leading to reward hacking or learning degenerate policies.

## Architecture Onboarding
**Component map:**  
Scenario (z) -> Reasoning Agent (RA) -> (Tool Calls / User Messages) -> User Simulator (f_user) & Tool Simulators (f_tool) -> State Tracker (f_state) updates proxy state (s̃) -> (repeat per step/turn) -> Final show_to_user -> LLM Judges (J_goal, J_hall) evaluate.

**Critical path:** User Query -> RA reasoning -> Tool Call -> Tool Sim (reads current s̃, outputs r) -> State Tracker updates s̃ -> repeat per turn -> RA show_to_user -> User Sim may issue <done> -> Final s̃_T -> Judge evaluation vs. s*(z).

**Design tradeoffs:**  
- Proxy vs. Deterministic: Trades engineering cost & flexibility (easy scenario iteration) for potential state inconsistency ("simulator hallucination") guarded by careful specification and strong f_state.  
- LLM-as-Judge vs. Code Assertions: Trades rigid, perfect but brittle code checks for flexible, nuanced, but potentially inconsistent LLM judgments (mitigated by human calibration).  
- Full-context state tracking vs. incremental: Uses full prefix f_state(τ≤(t,k)) to avoid error accumulation, at cost of longer context and no true step-by-step state evolution.

**Failure signatures:**  
- High tool/user hallucination rates (>5%) indicate incomplete scenario facts or weak f_state/f_tool.  
- Low human-LLM judge agreement (<85%) indicates poor judge calibration or ambiguous scenario definitions.  
- Poor GC correlation with model scaling suggests the benchmark is not differentiating or is gamed.  
- Training yields no improvement or degradation on Z_test indicates reward signal misalignment.

**First 3 experiments:**  
1. **State Tracker Sanity Check**: Run a simple scenario with 1-2 tool calls. Manually inspect inferred proxy state s̃ after each step to see if it reflects expected updates (e.g., balance changes).  
2. **Judge Baseline - Human Agreement**: Sample 50 trajectories from Z_test. Have two humans annotate c, h_tool, h_user. Compute three-way agreement with LLM judges; target >90%.  
3. **Training Signal Test - On-policy RFT**: For a base RA, generate 10 rollouts per scenario on Z_train, filter for c=1, and perform RFT. Evaluate GC on Z_test; expect slight improvement (paper ~1.47%). If GC drops, suspect data leakage or catastrophic forgetting.

## Open Questions the Paper Calls Out
- **Domain Generalization**: Does proxy state-based evaluation generalize beyond e-commerce and account management? The paper only evaluates on 208 scenarios in these two domains.
- **Component Model Sensitivity**: How does the choice of LLM for simulator and judge components affect evaluation reliability and cost? Limited ablations (only state tracker) are presented.
- **Minimal Scenario Specification**: What is the minimal set of facts required to maintain low hallucination rates? Ablations show removal increases hallucinations but no completeness threshold is defined.
- **Long-Horizon Stability**: Can the proxy state tracker maintain accuracy over long interactions (>20 turns)? The benchmark caps at 10 turns; performance on longer traces is unevaluated.

## Limitations
- Exact prompt templates and few-shot examples for all LLM components (f_state, f_user, f_tool, judges) are undisclosed, hindering faithful reproduction.
- Implementation details of the coordination between state tracker updates and tool simulator reads, as well as training rollout generation specifics (prompts, seeds, data mixing), are ambiguous.
- Judge calibration methodology (e.g., how human-LLM disagreements were resolved or fine-tuning) is unspecified, affecting reliability validation.
