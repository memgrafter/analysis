# Internal Representations as Indicators of Hallucinations in Agent Tool Selection

## Quick Facts
- **arXiv ID:** 2601.05214
- **Source URL:** https://arxiv.org/abs/2601.05214
- **Reference count:** 6
- **Primary result:** Real-time detection of tool-calling hallucinations via single-pass final-layer representations, achieving up to 86.4% accuracy.

## Executive Summary
Tool-calling hallucinations in LLM-based agents—including incorrect function selection, malformed parameters, and tool bypass—undermine reliability. This paper proposes a method that detects hallucinations in real time during generation by extracting and classifying internal representations from the final transformer layer of a single forward pass. A lightweight classifier is trained on features from key token positions (function name, arguments, closing delimiter). Across reasoning tasks in multiple domains and models, the method achieves up to 86.4% accuracy and strong recall (e.g., 0.86 for GPT-OSS-20B). It outperforms multi-sampling baselines (NCP, Semantic Similarity) in recall while requiring only one forward pass, enabling low-overhead, production-ready deployment.

## Method Summary
The detector leverages the same forward pass used for generation. When the model emits a structured tool call (e.g., `<functioncall>ToolName(arg1, arg2)`), the system identifies the token indices for the start of the function name (`t_func`), the span of argument tokens (`T_args`), and the closing delimiter (`t_end`). It extracts the final-layer hidden states for these positions and constructs a feature vector `z_i` by concatenating `h_tfunc`, the mean-pooled `h_Targs`, and `h_tend`. A two-layer MLP classifier, trained on data automatically labeled via reference-agreement (mask the ground-truth call and have the model regenerate; matches yield non-hallucination labels), predicts a binary hallucination probability. This design introduces negligible additional latency and avoids expensive multi-sampling.

## Key Results
- Up to 86.4% detection accuracy and strong recall (0.86 for GPT-OSS-20B) across multiple models and domains.
- Outperforms multi-sampling baselines (NCP, Semantic Similarity) in recall while using only one forward pass.
- Single-forward-pass operation adds minimal overhead, suitable for production.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** The final-layer hidden states of an LLM during tool-call generation contain discriminative signals that distinguish correct tool invocations from hallucinations.  
**Mechanism:** During the forward pass that generates a structured tool call, the model's internal representation at key token positions encodes information about the semantic and syntactic validity of the call. A lightweight classifier trained on these representations learns to map these patterns to a binary hallucination label.  
**Core assumption:** Correct and hallucinated tool calls produce measurably different activation patterns in the final transformer layer, reflective of the model's internal "confidence" or structural alignment with the learned tool schema.  
**Evidence anchors:**  
- [abstract] "leverage LLMs' internal representations during the same forward pass used for generation" and "demonstrating strong detection performance (up to 86.4% accuracy)".  
- [section: Problem Formulation & Method] Formalizes learning a classifier `hθ` from final-layer representation `z` and defines hallucination categories.  
- [corpus] Neighbors like "Reducing Tool Hallucination via Reliability Alignment" and "Robust Hallucination Detection in LLMs via Adaptive Token Selection" investigate internal state signals, providing contextual support for the premise, though not directly for the specific 3-point feature design.  
**Break condition:** This mechanism would fail if internal representations for correct and hallucinated calls are not linearly separable or if the hallucination signal is only present in earlier layers or distributed across the full sequence in a way not captured by the proposed pooling.

### Mechanism 2
**Claim:** A compact feature vector constructed from representations at three semantically significant token positions (function name, arguments, closing delimiter) is sufficient for accurate classification.  
**Mechanism:** The function name token (`t_func`) captures tool selection intent. The average of argument token representations (`T_args`) captures parameter type/shape compliance. The closing delimiter token (`t_end`) signals structural completion. Concatenating these creates a fixed-size representation (`z_i`) that the classifier uses.  
**Core assumption:** The hallucination signal is concentrated at or can be effectively summarized by these specific positions, and simple averaging over the argument span is an adequate aggregation strategy.  
**Evidence anchors:**  
- [section: Final-Layer Feature Extraction] Explicitly defines the three positions and the concatenation operation `z_i = [h_tfunc || avg(h_Targs) || h_tend]`.  
- [section: Ablation Study] Tests alternatives and finds "Last-Layer Rep." (mean pooling) performs best, supporting the choice of sequence aggregation.  
- [corpus] Weak direct evidence. Corpus neighbors focus on different detection methods (multi-agent debate, retrieval). The assumption of positional importance is not directly validated by neighbors.  
**Break condition:** This design fails if critical hallucination cues exist in tokens *outside* these three positions (e.g., in the prompting context or in earlier generated tokens) or if argument-level signals require more sophisticated pooling (e.g., attention-weighted) to be captured.

### Mechanism 3
**Claim:** The classifier can be trained in an unsupervised manner via reference-agreement labeling, enabling practical deployment without costly manual annotation of hallucinated examples.  
**Mechanism:** For each user query, the ground-truth tool call is masked from the prompt. The LLM is prompted to generate a tool call *again*. If this second generation matches the ground-truth (function name and canonicalized arguments), it's labeled "non-hallucination." Any deviation is labeled "hallucination." This leverages the model itself to generate both correct and incorrect examples for training the detector.  
**Core assumption:** The model's own re-generation under identical context will sometimes produce hallucinations, and the frequency/type of these self-generated hallucinations is sufficiently representative of real hallucinations encountered at inference.  
**Evidence anchors:**  
- [section: Method] "We assign binary labels by comparing predicted and reference calls...yi = 1 if function name differs or arguments fail to match."  
- [abstract] "unsupervised training framework that automatically generates labeled data by masking ground-truth tool calls."  
- [corpus] The "Tool-MAD" neighbor uses multi-agent debate for verification, implying a different paradigm. No neighbor directly investigates self-supervised labeling for tool hallucination, making this an assumption.  
**Break condition:** The labeling heuristic fails if the model never hallucinates when re-prompted on a known-correct context (no positive examples), or if the hallucinations it generates are systematically different (e.g., only "tool bypass" but never parameter errors) from those occurring in natural, first-pass generation.

## Foundational Learning
- **Concept: Transformer Final-Layer Representations**  
  *Why needed here:* The entire method depends on extracting and interpreting the `h_(L)_t` vectors from the last transformer layer. Understanding that these are contextualized, dense embeddings that summarize the model's internal state up to token `t` is prerequisite.  
  *Quick check:* If you take the final-layer hidden state for the token immediately before the function name is generated, what does that representation primarily encode about the upcoming tool call?

- **Concept: Tool-Calling Hallucination Taxonomy**  
  *Why needed here:* The paper defines five hallucination types (function selection, appropriateness, parameter, completeness, tool bypass). The classifier is trained on a unified binary label, but recognizing these categories is essential for interpreting failure modes and dataset construction.  
  *Quick check:* Give an example of a "tool bypass" hallucination that would still produce a syntactically valid-looking `<functioncall>` block?

- **Concept: Supervised Classification with Neural Networks**  
  *Why needed here:* The core output is a trained two-layer MLP (`hθ`). Understanding input feature vector construction (`z_i`), the feed-forward architecture (`W1`, `ϕ`, `w2`), sigmoid output, and binary cross-entropy loss is necessary to implement and troubleshoot the system.  
  *Quick check:* What is the purpose of the linear projection `Π` in the feature construction equation, and why might it be left as the identity mapping?

## Architecture Onboarding
**Component map:**  
LLM Engine -> Feature Extractor -> Hallucination Classifier -> Policy Executor

**Critical path:**  
Standard agent loop → LLM generates full response with tool call → **During same forward pass**, cache final-layer states → After tool call string is emitted, Feature Extractor identifies token positions → Classifier scores `p_i` → Policy Executor decides → Tool executed or not.

**Design tradeoffs:**
- *Feature Complexity vs. Performance:* The ablation shows minimal gain from complex pooling (Attention-Weighted, Multi-Scale) over simple mean pooling. Opt for the simplest (mean pooling over `T_args`) to minimize latency.
- *Classifier Capacity vs. Overfitting:* A two-layer MLP with 512 hidden units is used. Deeper/wider networks risk overfitting on the relatively small, automatically labeled dataset. The paper uses dropout (0.1) and early stopping.
- *Threshold `τ`:* Chosen via grid search on validation set for balanced performance. Optimizing for high recall (catching more hallucinations) may increase false positives, blocking correct calls. Deployment goal dictates the tradeoff.

**Failure signatures:**
- *High False Negative Rate:* Classifier often outputs `p_i < τ` for hallucinated calls. Check: Are the three token positions correctly identified? Is the mean pooling over arguments losing critical per-token signals? Is the classifier underfitting?
- *High False Positive Rate:* Classifier often outputs `p_i > τ` for correct calls. Check: Is the reference-agreement labeling noisy? Are there systematic differences in tool schemas between training and deployment causing distribution shift?
- *Poor Cross-Model Generalization:* A classifier trained on Qwen-7B performs poorly on Llama-3.1-8B. This is expected; the paper notes "model-specific classifiers." Do not attempt a one-size-fits-all classifier without extensive multi-model training data.

## Open Questions the Paper Calls Out
1. **Robust function equivalence determination:** The paper notes difficulty in determining function equivalence beyond exact string matching due to synonyms and contextual inappropriateness. Unresolved because string matching yields noisy labels that may mis-train the classifier. Resolution requires evaluating on a dataset with curated function aliases and contextual appropriateness annotations, measuring impact on detector performance against human judgments.
2. **Unified cross-architecture hallucination detector:** Future work proposes investigating a unified detector that works effectively across different model families. Unresolved because the paper trains separate classifiers per model due to architectural differences (e.g., Qwen’s Group Query Attention vs. Llama’s RoPE), suggesting internal representations may not be directly transferable. Resolution: train a single classifier on pooled features from multiple models and evaluate zero-shot generalization on unseen architectures, analyzing representation similarity via techniques like CCA or probing.
3. **Optimal feature aggregation for subtle hallucinations:** The ablation study shows mean pooling performs best but notes that future work could explore field-aware pooling or lightweight attention over argument spans while maintaining single-pass efficiency. Unresolved because simple averaging may dilute important token-specific signals (e.g., within complex argument structures), and the study did not test learnable aggregation or hybrid methods. Resolution: compare attention-weighted pooling over argument spans, token-type embeddings, or small neural aggregators against mean pooling, focusing on parameter-hallucination recall and computational overhead.
4. **Generalization to non-mathematical domains:** Evaluation is restricted to mathematical reasoning domains (e.g., loan calculations, BMI) where hallucinations may differ from those in creative or conversational tool use. Unresolved because patterns like semantic drift or inappropriate tool chaining in non-mathematical APIs are unexplored. Resolution: test the trained model (or retrain) on diverse non-mathematical tool-calling datasets (e.g., Glaive’s general APIs, software development tools), measuring per-category hallucination type detection and analyzing feature distributions.

## Limitations
- Unsupervised labeling via reference agreement may generate hallucinations that are systematically different from natural ones, causing a distribution shift.
- Three-position feature extraction assumes hallucination signals are localized; cues in surrounding context or earlier tokens could be missed.
- The classifier is model-specific; training on one LLM may not transfer to others without re-training. Evaluation on static benchmarks may not reflect dynamic, interactive deployment conditions.

## Confidence
- Final-layer representations encode hallucination signal: Medium
- Three token positions suffice for classification: Medium
- Reference-agreement labeling produces valid training data: Low

## Next Checks
1. **Labeling heuristic distribution match:** For identical queries, compare the distribution of hallucination types (function vs. parameter errors) between first-pass natural hallucinations and self-generated ones from masked re-generation.
2. **Cross-model zero-shot transfer:** Train a classifier on Model A (e.g., Qwen-7B), test directly on Model B (e.g., Llama-3.1-8B). Measure accuracy/recall drop to quantify model-specificity.
3. **Extended context and pooling ablation:** Augment features with pre-generation (token before `t_func`) and post-generation (tokens after `t_end`) states, and replace mean pooling with attention-weighted pooling. Evaluate improvement on original method's failure cases.
