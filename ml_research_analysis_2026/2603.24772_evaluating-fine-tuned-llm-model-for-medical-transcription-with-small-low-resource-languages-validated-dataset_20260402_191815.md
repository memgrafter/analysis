# Evaluating Fine-Tuned LLM Model For Medical Transcription With Small Low-Resource Languages Validated Dataset

## Quick Facts
- **arXiv ID:** 2603.24772
- **Source URL:** https://arxiv.org/abs/2603.24772
- **Reference Count:** 38
- **Primary Result:** Fine-tuned LLaMA 3.1-8B on 7 Finnish clinical dialogues achieved BERTScore F1=0.8230 and ROUGE-L=0.4982, indicating strong semantic similarity despite low lexical overlap (BLEU=0.1214).

## Executive Summary
This study explores the feasibility of using a general-purpose large language model (LLaMA 3.1-8B) for medical transcription in Finnish, a low-resource language with complex morphology. By fine-tuning on a tiny, manually validated dataset of just 7 simulated clinical dialogues, the authors demonstrate that semantic accuracy (measured by BERTScore) can reach clinically meaningful levels. The work employs parameter-efficient fine-tuning (LoRA) and 4-bit quantization to enable training on limited academic hardware, highlighting a privacy-preserving, open-source approach for sensitive medical contexts. Despite the dataset's extreme smallness, results suggest that structured clinical documentation generation is achievable without native-language pretraining.

## Method Summary
The pipeline converts Finnish clinical dialogues (audio MP3s) into supervised text-to-text pairs: an ASR transcript (from Whisper large‑v3) serves as input, and a manually structured clinical note serves as target. The LLaMA 3.1‑8B model is loaded in 4‑bit quantized form and adapted using LoRA. Training follows a 7‑fold cross‑validation scheme (leave‑one‑dialogue‑out) to maximize data utility and evaluate generalization. Models are trained for 3 epochs with a batch size of 1, a maximum sequence length of 512 tokens, and the Hugging Face `Trainer` API. Performance is assessed via BLEU (lexical precision), ROUGE‑L (content recall), and BERTScore (semantic similarity).

## Key Results
- BERTScore F1: **0.8230** (high semantic alignment with references)
- ROUGE‑L: **0.4982** (moderate longest common subsequence recall)
- BLEU: **0.1214** (very low n‑gram/lexical match)

## Why This Works (Mechanism)

### Mechanism 1
Fine‑tuning a general‑purpose LLM (LLaMA 3.1‑8B) on a tiny, domain‑specific Finnish corpus generates clinically meaningful structured documentation despite poor lexical n‑gram match. The model learns to map the semantic intent and key medical entities from noisy, colloquial speech to the formal, structured style of reference transcripts. The fine‑tuning process optimizes next‑token prediction on the target clinical format, forcing the model to internalize clinical discourse patterns and Finnish medical terminology rather than surface word forms. A small, high‑quality, validated dataset contains sufficient signal to teach this domain‑specific mapping, even if the base model lacks Finnish pre‑training. Evidence: high BERTScore (0.823) and ROUGE‑L (0.498) vs. low BLEU (0.121) indicate semantic capture without exact wording; the manually validated JSON dataset provides clear supervised signal.

### Mechanism 2
Seven‑fold cross‑validation is an effective mitigation strategy for model evaluation and overfitting prevention given an extremely small dataset (n=7). By iteratively using 6 dialogues for training and 1 for testing (leave‑one‑out), the method maximizes data utility, tests generalization across different clinical scenarios, and provides a stable performance estimate. It forces the model to learn features generalizable to unseen clinical dialogues within this narrow domain, assuming the 7 dialogues are sufficiently diverse. Evidence: the paper explicitly uses 7‑fold CV due to limited samples to avoid unstable estimates; per‑file results (Table II) show consistent BERTScore range (0.7642–0.8621).

### Mechanism 3
Using an open‑source LLM (LLaMA) with 4‑bit quantization and LoRA adapters enables feasible, privacy‑preserving domain adaptation on limited academic hardware. Parameter‑Efficient Fine‑Tuning (PEFT) via LoRA updates only small adapter matrices injected into attention layers, drastically reducing trainable parameters and memory footprint. Combined with 4‑bit quantization (nf4), the 8B‑parameter model fits into a single 40GB GPU (NVIDIA A100). Local deployment on a secure supercomputer (CSC Puhti) avoids sending sensitive clinical data to external APIs. Evidence: the paper details 4‑bit quantized LoRA training on one A100; the motivation emphasizes open‑source models for privacy‑oriented deployment under GDPR.

## Architecture Onboarding
Data Source -> ASR Pre‑processor (Whisper large‑v3) -> JSON Pairing -> Base Model (LLaMA 3.1‑8B, 4‑bit) -> LoRA Adapters (q/k/v/o projections) -> Trainer (causal LM) -> Evaluator (BLEU/ROUGE/BERTScore)

**Critical path:** Audio → Whisper transcript → JSON formatting → quantized LLaMA loading → LoRA configuration → 7‑fold CV training loop → per‑fold evaluation → metric aggregation.

**Design tradeoffs:**
- Sequence length capped at 512 tokens to fit memory, potentially truncating long patient histories.
- LoRA rank (unstated) balances memory vs. capacity for Finnish morphological adaptation.
- Single model (LLaMA 3.1‑8B) evaluated; no comparison to smaller Finnish‑pretrained models (e.g., FinBERT) or other open LLMs.
- Automatic metrics only; no human evaluation for clinical accuracy/safety.

**Failure signatures:**
- High BLEU + low BERTScore: model parroting surface phrases without understanding.
- Low scores across all metrics: incorrect JSON formatting, tokenizer mismatch, or LoRA misapplication.
- High metric variance across CV folds: dataset heterogeneity or data leakage between folds.

**First 3 experiments:**
1. Reproduce preprocessing: take one MP3, run through Whisper large‑v3, verify transcript against provided human reference, confirm JSON matches training input format.
2. Baseline sanity check: run unfine‑tuned LLaMA 3.1‑8B on a validation dialogue prompt; record BERTScore (should be ~0.3–0.5). If >0.7, task is trivial or data leaked.
3. LoRA rank sensitivity: train on Fold 1 with ranks 4, 8, 16; compare BERTScore and GPU memory to find minimal rank matching paper’s average (~0.82).

## Open Questions the Paper Calls Out

4. Do architectural refinements such as structured end‑of‑sequence tokens or retrieval augmented generation (RAG) improve accuracy and reduce hallucinations in the fine‑tuned LLM for Finnish medical transcription?
5. How does human expert evaluation correlate with automatic metrics for assessing the quality of Finnish medical transcriptions generated by the fine‑tuned LLM?

## Limitations
- Dataset size (n=7) and missing GitHub link; unclear JSON structure for target notes.
- No human evaluation; automatic metrics may not reflect clinical safety or real‑world usability.
- Potential overfitting and unknown BERTScore variance across folds.
- Base model lacks Finnish pretraining; generalizability to broader clinical Finnish uncertain.

## Confidence
- Fine‑tuning improves semantic accuracy (BERTScore 0.823): **Medium** (small dataset, no human check)
- 7‑fold CV yields robust performance estimate: **Medium** (standard for small data but each fold may be non‑IID)
- LoRA + 4‑bit deployment feasible on single A100: **High** (well‑established method, clear hardware specs)
