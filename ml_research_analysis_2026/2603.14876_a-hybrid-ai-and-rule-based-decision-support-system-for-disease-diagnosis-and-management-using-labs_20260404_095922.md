# A Hybrid AI and Rule-Based Decision Support System for Disease Diagnosis and Management Using Labs

## Quick Facts
- **arXiv ID:** 2603.14876
- **Source URL:** https://arxiv.org/abs/2603.14876
- **Reference count:** 19
- **Primary result:** A hybrid clinical decision support system combining rule-based confirmation (59 conditions) with an XGBoost classifier (11 disease groups) achieves 83.10% Top-5 accuracy on 593,055 patient records and provides SHAP-based explanations.

## Executive Summary
This paper presents a hybrid Clinical Decision Support System (CDSS) designed to reduce misdiagnosis by leveraging laboratory data. The system integrates a rule-based expert system—which applies clinically validated thresholds to directly confirm specific diseases—with an XGBoost multi-class classifier that predicts probabilities across 11 broader disease categories. Trained on a large dataset of 593,055 patients from US primary care centers, the model attains strong predictive performance (Top-5 accuracy 83.10%) and includes explainable AI components (SHAP values) to build physician trust. The output is a ranked list of likely diagnoses, suggested confirmatory labs, and transparent reasoning, all delivered within the electronic health record workflow.

## Method Summary
The CDSS uses structured laboratory results (CBC, CMP, lipid panel, etc.) and patient demographics as input. A rule-based module checks lab values against 59 clinician-curated criteria to issue definitive ICD-10 codes for diseases with unambiguous lab signatures. For cases without rule confirmation, an XGBoost classifier—trained on 37 ICD-10 codes grouped into 11 categories—predicts disease probabilities, natively handling missing lab values. The system weights classes via inverse frequency (square root heuristic) to address imbalance, employs grid search with 5-fold cross-validation for hyperparameter tuning, and uses SHAP to explain each prediction. Evaluation on a held-out test set reports Top-N accuracy and per-disease recall.

## Key Results
- Achieved **Top-5 accuracy of 83.10%** on the test set.
- High recall for key disease groups: URTI (94.3% at Top-5) and normal findings (91.6%).
- Predicted disease prevalence closely matched true prevalence in the data, indicating good calibration.

## Why This Works (Mechanism)
### Mechanism 1: Hybrid Fusion of Rule-Based and ML Systems
The system combines the precision of guideline-derived rules for direct diagnosis confirmation with the pattern-recognition flexibility of machine learning. Rules cover diseases with definitive lab signatures, while the XGBoost model suggests likely diagnoses when rules do not fire. This complementary design improves coverage and trust, assuming the rule set is comprehensive and the ML model generalizes well. Evidence: the architecture is explicitly described in the paper [section 2.1] and aligns with trends in neighboring hybrid CDSS research. Break condition: gaps in rule coverage or poor ML calibration could cause the true diagnosis to fall outside the Top-N list.

### Mechanism 2: Laboratory Data as Primary Diagnostic Signal
Routine lab tests provide objective, quantifiable features that correlate with disease states. The rule-based module uses fixed thresholds, while XGBoost learns nonlinear associations from historical data. By excluding subjective inputs (symptoms, exam), the system ensures feature consistency across sites but inherently limits applicability to non-lab-driven conditions. Evidence: the dataset and model design focus solely on lab results [section 3]. Break condition: diseases primarily manifested through symptoms or imaging (e.g., depression, early cancer) will have low recall.

### Mechanism 3: SHAP-Based Explainability for Trust Building
SHAP values attribute each lab feature's contribution to predicted probabilities, providing global and local explanations. This transparency allows clinicians to audit whether the model's reasoning aligns with medical knowledge, fostering adoption. Evidence: the system explicitly outputs SHAP plots and states they help develop trust [section 2.1]. Break condition: if explanations highlight clinically irrelevant features or appear arbitrary, trust may erode despite accurate predictions.

## Architecture Onboarding
### Component map
Data Ingestion -> [Rule-Based Module, ML Module] (parallel) -> [Explanation Module, Recommendation Module] -> Orchestrator & UI

### Critical path
1. Input: EHR supplies latest lab panel and demographics.
2. Parallel: Rule-based module applies 59 rules; ML module computes probabilities for 11 disease groups (tolerating missing values).
3. Ranking: System produces Top-N (default N=5) likely diagnoses from ML probabilities, shown alongside confirmed diagnoses.
4. Explanation & recommendation: SHAP values computed for top predictions; confirmatory lab suggestions retrieved.
5. Output: Physician receives confirmed diagnoses, ranked likely diagnoses with SHAP plots, and follow-up lab recommendations. Cycle repeats when new labs return.

### Design tradeoffs
- **Rule coverage vs. maintenance**: Rules are auditable but require manual updates; ML adapts but is less transparent without SHAP.
- **Data exclusivity**: Labs ensure consistency but omit symptoms/exam, limiting accuracy for non-lab-driven diseases.
- **Class imbalance**: Weighting by inverse frequency retains all data but may still leave rare diseases underserved; under-sampling loses data.
- **Top-N choice**: N=5 balances recall and cognitive load; adjusting N trades off completeness vs. overwhelm.
- **Model complexity**: XGBoost offers performance and missing-value handling, but SHAP computation adds latency for real-time use.

### Failure signatures
- **Rule-based failures**: No rules fire for a known condition → coverage gaps; excessive conflicting firings → thresholds too permissive.
- **ML model failures**: Low recall for specific categories (e.g., Hypothyroidism 52.8%) → data sparsity or poor features; dense confusion matrix → overlapping lab patterns.
- **Explanation failures**: SHAP highlights irrelevant features → spurious correlations; physician confusion → trust erosion.
- **Recommendation failures**: Suggested labs not gold-standard → outdated knowledge base.

### First 3 experiments
1. **Reproduce Top-N accuracy**: Using held-out test set (20% of 593,055), compute Top-N accuracy for N=1..11; verify Top-5 ≥83.10%.
2. **Per-disease recall profiling**: Replicate Table 3; identify categories with <70% Top-5 recall (e.g., Hypothyroidism).
3. **Explainability plausibility check**: For 50 random patients, have a clinical expert review SHAP feature attributions; document >80% alignment with known pathophysiology.

## Open Questions the Paper Calls Out
1. **Impact of non-laboratory data**: How will integrating vital signs, social history, and symptoms affect accuracy, robustness, and utility?
2. **Conflict resolution**: What framework resolves discrepancies between rule-based confirmation and AI-based likely diagnoses?
3. **Explainability impact**: Does SHAP explanation measurably improve physician trust, situational awareness, and decision-making in real-world settings?
4. **Performance disparities**: Why do recall rates vary widely across disease groups (e.g., URTI 94.3% vs. IHD 48.8%), and can targeted adjustments improve low performers?
5. **Clinical outcome validation**: How does the hybrid CDSS compare to standard care or standalone systems in reducing diagnostic errors and inappropriate test ordering prospectively?

## Limitations
- **Rule coverage gaps**: The 59-conditions rule set likely excludes symptom-driven diseases (e.g., depression, osteoarthritis), limiting diagnostic scope.
- **Generalizability risk**: Training data (2000–2023) may not reflect current lab practices or emerging diseases; covariate shift could degrade performance.
- **Unproven trust mechanism**: SHAP's ability to build physician trust is assumed but lacks empirical validation in clinical settings.

## Confidence
- **Hybrid fusion mechanism**: High (clearly described, aligns with literature)
- **Lab-data sufficiency**: Medium (strong metrics but inherent limitations for non-lab conditions)
- **SHAP-based trust hypothesis**: Medium (plausible but no real-world adoption evidence)
