# pathsig: A GPU-Accelerated Library for Truncated and Projected Path Signatures

## Quick Facts
- **arXiv ID:** 2602.24066
- **Source URL:** https://arxiv.org/abs/2602.24066
- **Reference count:** 33
- **Primary result:** A GPU-accelerated library for path signatures achieving 10–30× forward speedups and near-minimal memory, with support for flexible word projections and windowed signatures.

## Executive Summary
pathsig is a PyTorch-integrated library that accelerates path signature computation on GPUs. It introduces a novel parallelization strategy based on prefix-closed word sets and Horner’s method, enabling efficient forward and backward passes with memory usage near the theoretical minimum. The library supports arbitrary word projections (including anisotropic truncation) and windowed signatures, making it suitable for large-scale gradient-based learning. Benchmarks on an NVIDIA H200 show speedups of 10–30× for forward truncated signatures and up to 4–10× for training compared to existing libraries. An application to fractional Brownian motion Hurst estimation demonstrates the practical benefits of sparse lead–lag projections, achieving a 6.25× feature reduction and 2.24× training speedup while improving Hurst estimation accuracy.

## Method Summary
pathsig computes path signatures in a word-indexed basis using CUDA kernels that parallelize updates over prefix-closed sets of words. For each time step, threads assigned to a base word update all its prefixes using Horner’s method, avoiding tensor expansions and minimizing inter-thread dependencies. The same framework supports arbitrary finite prefix-closed word projections and anisotropic truncation by adjusting the word set. Backpropagation is memory-efficient: intermediate signature values are reconstructed on-the-fly during the backward pass using Chen’s relation and the group-like property, avoiding storage of all intermediate signatures. The library integrates with PyTorch’s autograd, and also provides log-signature computation and windowed signatures via an inversion-based method.

## Key Results
- Forward truncated signatures are 10–30× faster than keras_sig and pySigLib on an NVIDIA H200.
- Training (forward + backward) sees speedups of up to 4–10×, with peak memory scaling as \(O(B \cdot D_{\text{sig}})\) rather than \(O(B M D_{\text{sig}})\).
- Windowed signatures achieve a median speedup of 153× over baselines.
- A sparse lead–lag projection reduces feature dimension by 6.25× and training time by 2.24× while improving Hurst estimation accuracy.

## Why This Works (Mechanism)
### Mechanism 1: Parallel GPU throughput via prefix-closed word sets
The core idea is to decompose the signature update into independent units based on prefix-closed sets. Each CUDA thread handles all prefixes of a single word \(w\). For each time increment \(\Delta X_j\), the thread updates coefficients for \(w\) using Horner’s method, which computes the contribution from \(\exp(\Delta X_j)\) without forming the full tensor. This eliminates inter-thread dependencies beyond shared reads of \(\Delta X_j\), enabling massive parallelism. The dependency in Chen’s relation (Equation 3) involves only a word and its proper prefixes, so grouping by \(P_w\) localizes all required prior values. Evidence: [abstract], [section 3.1], [section 3.2]. Break condition: If the word set \(I\) is not prefix-closed, some required prefix values may be missing, leading to incorrect results.

### Mechanism 2: Flexible word projections via prefix-closed sets
Any finite prefix-closed word set \(I\) (e.g., truncation, anisotropic, or user-defined) can be processed by the same kernel. The kernel iterates over \(P_w \cap I\) for each thread’s base word \(w \in I\). This naturally extends to anisotropic truncation, where weighted word degrees remain prefix-closed by construction. Evidence: [abstract] mentions support for projections and anisotropic truncation; [section 7] formalizes projections \(\pi_I\) and anisotropic signatures \(\mathcal{S}_{\gamma}^{\leq r}(X)\); [section 8] demonstrates sparse lead-lag projections built from allowed primitives that are prefix-closed. Break condition: Non-prefix-closed \(I\) will produce incorrect signatures unless the library internally pads to the prefix-closure (which it does not do automatically).

### Mechanism 3: Memory-efficient backpropagation via on-the-fly reconstruction
The forward pass stores only the final signature \(S_{0,T}(X)\). During backward, for each word \(w\), gradients require values at split points \(t_j\): \(S_{0,t_j}(X,\cdot)\) and \(S_{t_j,T}(X,\cdot)\). Using the group-like property and Chen’s relation, these are reconstructed recursively from the stored \(S_{0,T}(X)\) and the \(\Delta X_j\) (saved from forward). Propositions 4.2 and 4.6 give the backward recursions for suffixes and prefixes, respectively. This avoids storing all intermediate signatures, achieving memory near \(O(|\text{output}|)\). Evidence: [abstract] notes near-minimal peak memory; [section 4] describes the reconstruction; [section 6.2] Table 2 shows memory scaling; related libraries like pySigLib and Signatory also use memory-efficient backprop, but pathsig integrates it with its word-basis design. Break condition: Numerical instability may accumulate for very deep signatures or long sequences due to repeated inversion; the paper does not report issues but this is a potential risk.

## Foundational Learning
- **Concept:** Tensor algebra and word-indexed basis.
  - *Why needed:* The signature lives in the tensor algebra \(T((\mathbb{R}^d))\), and words index the basis. Understanding this is essential to grasp why prefix-closed sets correspond to independent computation units (Chen’s relation sums over prefix-suffix splits).
  - *Quick check:* If a word \(w = (i_1, i_2)\) is in your computation set, which other words must also be included to satisfy prefix-closure? (Answer: all prefixes: \(\epsilon, (i_1), (i_1,i_2)\).)
- **Concept:** Chen’s relation.
  - *Why needed:* It provides the recursive formula \(S_{0,T} = S_{0,t_j} \otimes S_{t_j,T}\) that underlies both forward updates and backward reconstruction.
  - *Quick check:* Given \(S_{0,T} = S_{0,t_j} \otimes S_{t_j,T}\) and \(S_{t_j,T} = S_{t_j,t_{j+1}} \otimes S_{t_{j+1},T}\), how would you express \(S_{0,t_j}\) in terms of \(S_{0,t_{j+1}}\) and \(\Delta X_{j+1}\)? (Answer: \(S_{0,t_j} = S_{0,t_{j+1}} \otimes \exp(-\Delta X_{j+1})\).)
- **Concept:** Chain rule for path increments.
  - *Why needed:* The gradient \(\partial L / \partial \Delta X_j\) bridges output gradients \(\partial L / \partial S_{0,T}(X,w)\) to input path gradients, expressing dependence on prefixes/suffixes at the split point.
  - *Quick check:* If the model output depends only on words of length 1 (\(I = \{(1), (2), ..., (d)\}\)), what does Proposition 4.1 simplify to? (Answer: For \(w=(i)\), only the split \(u=\epsilon, v=w\) contributes, so \(\partial L / \partial \Delta X^{(i)}_j = \sum_{w=(i)} \partial L / \partial S_{0,T}(X,w) \cdot S_{t_j,T}(X,w)\).)

## Architecture Onboarding
**Component map:**  
Word encoder/decoder -> Prefix-closed set builder -> CUDA forward kernel & CUDA backward kernel -> PyTorch autograd wrapper

**Critical path:**  
Input path \(\rightarrow\) piecewise linear interpolation \(\rightarrow\) compute increments \(\Delta X_j\) \(\rightarrow\) forward kernel (prefix-closed updates) \(\rightarrow\) output signature. Backward: output gradients \(\rightarrow\) backward kernel (reconstruct intermediates via suffix/prefix recursion) \(\rightarrow\) accumulate \(\partial L / \partial \Delta X_j\) \(\rightarrow\) chain rule to input path gradients.

**Design tradeoffs:**
- Memory vs computation: Prioritizes low memory by recomputing intermediates in backward, increasing backward compute.
- Thread granularity: One thread per base word \(w\) (handling all \(P_w\)) improves memory locality but may underutilize GPU for small word sets.
- Projection flexibility: Supporting arbitrary \(I\) adds kernel complexity but enables applications like sparse lead-lag.

**Failure signatures:**
- Out-of-memory during forward: likely if user provides a non-prefix-closed projection causing implicit padding.
- Numerical drift in log-signature: deep signatures or long sequences may suffer from inversion instability.
- Suboptimal GPU utilization: for very long sequences and small batch/depth, parallelism over words may be insufficient to saturate the GPU.

**First 3 experiments:**
1. **Baseline throughput test:** Compare forward and backward times for a standard truncated configuration (e.g., \(B=32, M=100, d=6, N=6\)) against keras_sig and pySigLib. Expect ≥10× forward speedup.
2. **Projection impact test:** On a synthetic Hurst estimation task, compare full truncation vs. sparse lead-lag projection. Measure feature dimension, training time, and validation error; expect dimension reduction and speedup with maintained/improved accuracy.
3. **Memory scaling test:** Increase sequence length \(M\) (e.g., 100–2000) with fixed \(B,d,N\). Monitor VRAM; pathsig’s memory should grow linearly with \(B \cdot D_{\text{sig}}\), not with \(M\).

## Open Questions the Paper Calls Out
1. **Can word projections be learned?**  
   The paper notes that projection selection is heuristic and manual (Section 7). No method for learning projections (e.g., via differentiable masks) is proposed.
2. **Does partitioning retained words improve expressiveness?**  
   Section 7.1 suggests partitioning words into subsets with separate transformations could be more expressive, but provides no experimental validation.
3. **How to determine anisotropy weights automatically?**  
   Anisotropy weights \(\gamma\) are treated as hyperparameters (Section 7.2). A data-driven approach to set them based on channel variability is absent.
4. **Numerical stability of windowed signatures?**  
   The inversion-based method for overlapping windows is noted as potentially unstable for long sequences (Section 5), but no analysis or stable alternative is given.

## Limitations
- The library requires user-provided word sets to be prefix-closed; violations lead to incorrect signatures without warning.
- Performance claims depend on specific benchmark conditions (GPU model, CUDA/PyTorch versions) that are not fully disclosed; speedups may vary.
- Numerical stability for deep signatures or log-signatures is not systematically evaluated; inversion-based windowed signatures may degrade for long sequences.
- Implementation is CUDA-only, limiting use to NVIDIA GPUs.

## Confidence
- **High:** Prefix-closed decomposition with Horner’s method correctly implements Chen’s relation; backpropagation via on-the-fly reconstruction achieves near-minimal memory.
- **Medium:** Exact speedup figures (10–30× forward, 4–10× training) depend on undisclosed benchmark details; arbitrary projection support is reliable only for prefix-closed sets.
