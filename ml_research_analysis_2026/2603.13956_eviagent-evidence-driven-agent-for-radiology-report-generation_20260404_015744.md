# EviAgent: Evidence-Driven Agent for Radiology Report Generation

## Quick Facts
- **arXiv ID:** 2603.13956  
- **Source URL:** https://arxiv.org/abs/2603.13956  
- **Reference count:** 16  
- **Primary result:** EviAgent surpasses state-of-the-art generalist and specialized medical models on MIMIC-CXR, CheXpert Plus, and IU-Xray, achieving up to 13.6 absolute SembScore improvement.

## Executive Summary
EviAgent introduces an evidence-driven agent framework to address the "black-box" limitations of multimodal LLMs in automated radiology report generation. It decomposes the task into planning, tool-augmented reasoning via a ReAct loop, explicit evidence extraction, and final report synthesis. The system integrates multiple discriminative visual experts (classification, posture recognition, visual grounding, segmentation) and a retrieval-augmented knowledge base to ground each step in verifiable visual evidence and domain knowledge. Evaluations on three public chest X-ray datasets show consistent superiority over both generalist frontier models and medical-specific models across clinical metrics, with ablations confirming the necessity of each component. The framework prioritizes traceability and clinical admissibility over raw speed.

## Method Summary
EviAgent employs a sequential four-stage pipeline. First, a Planner (Qwen3-VL-8B) generates a structured execution plan before any tool use, decomposing report generation into granular units (e.g., disease screening, localization). Second, a Tool Executor manages a ReAct-style loop: the planner iteratively selects and invokes specialized tools—a classifier (Swin-Transformer), posture recognizer (CheXagent), visual grounding model (MAIRA-2), segmenter (MedSAM), or RAG module—appending structured outputs to memory. Third, an Evidence Extractor distills this interaction history into a pure evidence chain *E*, filtering out procedural noise. Finally, a Generator (Qwen3-VL-8B) synthesizes the report conditioned solely on *E*. The RAG knowledge base contains 50 image-report-label triplets per CheXpert pathology (14 total), embedded with GME-Qwen2-VL and retrieved via pathology-specific queries. All communication uses the Model Context Protocol (MCP).

## Key Results
- On MIMIC-CXR: RaTEScore 52.6, SembScore 43.6, RadCliQ−1 76.6, representing absolute gains up to 13.6 Semb points over the best baseline.
- LLM-as-a-Judge evaluations confirm significant improvements in accuracy, localization, professionalism, and clinical admissibility.
- Ablation studies validate the necessity of each component; removing classification, localization, or retrieval causes consistent performance drops.

## Why This Works (Mechanism)

### Structured Planning and Task Decomposition
- **Claim:** Predefined planning prevents error propagation and creates a traceable diagnostic roadmap.
- **Mechanism:** The Planner analyzes the image and instruction to produce a coarse-grained execution plan *before* tool invocation. This decomposes the complex goal into sequential, goal-oriented units (e.g., "screen for diseases," then "localize findings"), constraining subsequent tool selections to a coherent strategy.
- **Core assumption:** A high-level *a priori* plan prevents random or misaligned explorations that would derail reasoning.
- **Evidence anchors:**  
  - [abstract]: "breaking down the complex generation process into granular operational units" and "coordinates a transparent reasoning trajectory."  
  - [section 3.1]: "Instead of attempting to generate the report immediately, the model formulates a structured execution plan."  
  - [corpus]: Nearest neighbor work on multi-agent decomposition (FMR 0.49) supports architectural decomposition as a lever.
- **Break condition:** A vague, incomplete, or misaligned initial plan (e.g., omitting localization) leads to compounded errors regardless of tool accuracy.

### ReAct-Style Tool-Augmented Loop
- **Claim:** The iterative loop enables dynamic refinement of coarse hypotheses via specialized visual evidence.
- **Mechanism:** Guided by the plan, the agent cycles through: generate a thought trace, select and invoke a tool (Classifier, Localization, RAG), receive a structured output, and append to memory. This allows adaptation—e.g., if classification detects "atelectasis," the next step invokes grounding to localize it.
- **Core assumption:** Each tool provides a discrete, verifiable output that the LLM planner can reliably parse and integrate, reducing hallucination by anchoring decisions in external computation.
- **Evidence anchors:**  
  - [section 3.1]: "This stage functions as a process of dynamic refinement... the agent spontaneously adapts its trajectory."  
  - [section 3.2.1]: Details discriminative tools providing "precise visual interpretation capabilities."  
  - [section 4.4 (Ablation)]: Removing "Localization" causes RaTE drops, proving reliance on spatially-grounded feedback.
- **Break condition:** Consistently low-confidence, misformatted, or contradictory tool outputs (e.g., classifier says "pneumonia" but grounding finds no region) lead to unproductive retry loops or conflicting evidence synthesis.

### Explicit Evidence Extraction
- **Claim:** Filtering procedural noise from the interaction history constructs a pure, structured evidence chain that conditions the final report, ensuring traceability and reducing hallucination.
- **Mechanism:** After the ReAct loop, the system parses the verbose memory (thoughts, actions, observations) to isolate only valid, concrete tool outputs (probabilities, bbox coordinates, retrieved snippets). This curated set *E* is the sole factual basis for report synthesis.
- **Core assumption:** Raw interaction history mixes meta-reasoning with results; without distillation, the generator may incorporate uncertainties or formatting artifacts as "facts."
- **Evidence anchors:**  
  - [section 3.1]: "By filtering out procedural artifacts and consolidating these findings, the system constructs a structured evidence chain E."  
  - [section 4.4 (Ablation)]: Removing "Evidence Extraction" degrades RadCliQ−1 (e.g., IU-Xray: 110.2 → 106.8), confirming its noise-reduction role.  
  - [Figure 2 (Qualitative)]: Output tags evidence sources (`[Classifier]`, `[Grounding]`, `[RAG]`), enabling traceability.
- **Break condition:** An extractor that is too permissive (includes low-confidence outputs) or too restrictive (filters valid findings) pollutes or starves the evidence chain, corrupting the report's factual basis.

## Foundational Learning
- **Concept: Multimodal discriminative visual expertise.**  
  **Why needed:** The agent relies on pre-trained specialist models (Swin-Transformer, MAIRA-2, CheXagent) for low-level, pixel-anchored evidence that a generalist LLM cannot reliably produce. The agent's reasoning is only as good as its perceptual inputs.  
  **Quick check:** If the visual grounding model consistently misses small pleural effusions, the final report will likely omit or mislocalize this finding, and the evidence chain will lack supporting coordinates.

- **Concept: ReAct (Reasoning + Acting) loop for tool orchestration.**  
  **Why needed:** This paradigm lets the LLM planner handle high-level strategy while outsourcing precise, deterministic tasks to tools. The loop's iterative nature mimics a radiologist's "look, find, question, look again" process.  
  **Quick check:** In a ReAct loop, the *Thought* is the planner's reasoning step (e.g., "The classifier suggests pneumonia; I should localize the consolidation"); the *Observation* is the tool's output. A faulty Observation (e.g., grounding returns an incorrect bbox) would mislead the subsequent Thought, causing the planner to draw wrong conclusions.

- **Concept: Retrieval-Augmented Generation (RAG) for domain knowledge.**  
  **Why needed:** LLMs' internal knowledge is static and may lack specific clinical phrasing, rare cases, or up-to-date guidelines. RAG injects analogous historical cases, providing stylistic and factual priors.  
  **Quick check:** For a query generated from classifier outputs "Edema" and "Atelectasis," two separate queries are sent: one embedding "Edema" and one embedding "Atelectasis," each retrieving top-k similar past reports from the respective pathology-specific knowledge base.

## Architecture Onboarding
**Component map:** Planner (Qwen3-VL-8B) → Tool Executor (ReAct loop) → Toolbox (Classifier, Posture Recognition, Visual Grounding, Segmentation, RAG, Web Search) → Evidence Extractor → Generator (Qwen3-VL-8B). All communication uses MCP.

**Critical path:** The most failure-sensitive path is: Classifier Output → Planner's Next Thought → Localization Tool Invocation → Evidence Chain Construction. An early classification error propagates through localization and is cemented in the evidence, making later correction impossible.

**Design tradeoffs:** Primary tradeoff is **inference latency vs. traceability & accuracy**. The multi-round, tool-dependent loop is significantly slower than an end-to-end MLLM forward pass. The system trades speed for debuggability, clinical trust, and mitigation of parametric hallucination.

**Failure signatures:**
1. **Error Propagation from Classification:** Wrong classifier output (high false positive/negative) leads to irrelevant localization/retrieval, yielding a coherent but factually incorrect report. *Trace:* Evidence chain contains confidently stated but wrong disease labels.
2. **Localization Mismatch:** Grounding fails to find a region for a correctly classified disease (e.g., due to subtlety). Planner may hallucinate a location or omit the finding, hurting localization metrics. *Trace:* Evidence chain lists a disease but has empty or nonsensical bbox coordinates.
3. **Retrieval Irrelevance:** RAG returns dissimilar cases (low similarity scores). Planner may incorporate irrelevant clinical phrasing or findings. *Trace:* Evidence chain contains findings unsupported by the image (e.g., "history of surgery" for a trauma case).

**First 3 experiments:**
1. **Ablate the Classification Tool (`w/o Cls.`)**: Remove the initial classification step. Expect severe SembScore drop (as in Table 3: MIMIC-CXR Semb ~23.1 vs. 43.6 full) due to unguided, likely hallucinated, tool invocation.
2. **Ablate the Localization Tools (`w/o Loc.`)**: Disable grounding and segmentation. Expect RaTEScore decrease (Table 3 shows drops), as reports lack spatially precise descriptors.
3. **Ablate the Retrieval Module (`w/o Ret.`)**: Disable RAG. Expect RadCliQ−1/Professionalism decrease (Table 3 shows drops), as reports become generic and less professionally aligned.

## Open Questions the Paper Calls Out
1. **Question:** How can EviAgent's inference latency be reduced to enable real-time clinical deployment without sacrificing evidence-driven accuracy?  
   **Basis in paper:** [explicit] The Limitations section states that the multi-round agentic workflow introduces computational overhead compared to end-to-end models.  
   **Why unresolved:** Latency is a critical barrier to clinical adoption; radiologists require near-instant feedback.  
   **What evidence would resolve it:** Systematic benchmarking of optimized tool invocation (parallel execution, caching) and infrastructure improvements (quantization) to quantify latency reduction while maintaining performance.

2. **Question:** To what extent do errors in the discriminative perception tools propagate through the ReAct loop and degrade final report quality, and how can such error cascades be mitigated?  
   **Basis in paper:** [inferred] Ablations show removing the classification tool causes the largest drop; qualitative analysis links final report discrepancies to tool errors.  
   **Why unresolved:** System reliability depends on these external experts, but their failure modes and downstream impact are not fully characterized.  
   **What evidence would resolve it:** Controlled experiments injecting synthetic errors into tool outputs, measuring report degradation, and developing confidence-aware planning or error-correction mechanisms.

3. **Question:** How does the RAG module's reliance on a fixed set of 14 pathologies (from CheXpert labels) affect EviAgent's ability to handle rare, uncommon, or previously unseen findings?  
   **Basis in paper:** [inferred] Knowledge bases are built from MIMIC-CXR training set (50 samples per pathology), and retrieval is confined to these labels.  
   **Why unresolved:** Real-world radiology includes numerous rare conditions not covered by CheXpert, potentially limiting generalizability.  
   **What evidence would resolve it:** Evaluation on datasets with broader pathology sets (e.g., NIH ChestX-ray14) and analysis of failure cases where relevant knowledge was absent.

4. **Question:** How robust is EviAgent to ambiguous or low-quality images where initial tool outputs are uncertain, and does the planning stage adequately account for uncertainty during decomposition?  
   **Basis in paper:** [inferred] Planning occurs before tool execution; the ReAct loop may not dynamically adjust for uncertain or conflicting evidence.  
   **Why unresolved:** Clinical images often have artifacts or atypical presentations, requiring uncertainty-aware reasoning.  
   **What evidence would resolve it:** Testing on artificially degraded images or datasets with uncertainty annotations, measuring how the agent's plan and tool selection change with confidence scores.

5. **Question:** What is EviAgent's impact on radiologist workflow and diagnostic confidence when used as a collaborative tool in real-world clinical environments?  
   **Basis in paper:** [explicit] Ethical Considerations state generated reports require mandatory radiologist validation and should not replace expert judgment.  
   **Why unresolved:** The paper evaluates only on public datasets using automated metrics; actual clinical utility, user trust, and integration challenges remain unmeasured.  
   **What evidence would resolve it:** Prospective user studies with radiologists assessing report usefulness, time savings, and agreement rates in daily practice.

## Limitations
- Implementation details (prompt templates, evidence extraction algorithm, RAG query formulation) are not publicly released, hindering exact replication.
- Tool reliability assumptions (e.g., classifier false positives, grounding failures) are asserted but not stress-tested with worst-case inputs.
- No analysis of contradictory tool outputs (e.g., classifier detects disease but grounding finds no region) or how the planner resolves them.

## Confidence
- **Architectural design (planning + ReAct + evidence extraction):** High  
- **Report quality gains vs. baselines:** High  
- **Causal role of each mechanism (via ablations):** Medium  

## Next Checks
1. **Error propagation stress test:** Systematically inject classification errors (false positives/negatives) and measure degradation in RaTEScore/SembScore to quantify break conditions in the planning loop.
2. **Evidence extraction fidelity study:** Create a human-annotated gold-standard evidence chain for a sample set; compute precision/recall of the automatic extractor to validate noise-filtering claims.
3. **RAG relevance ablation:** Swap retrieved reports with intentionally mismatched (wrong pathology) reports and measure drop in LLM-as-a-Judge professionalism/clinical admissibility to isolate RAG’s contribution.
