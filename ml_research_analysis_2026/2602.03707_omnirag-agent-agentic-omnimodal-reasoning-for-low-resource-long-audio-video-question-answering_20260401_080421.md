# OmniRAG-Agent: Agentic Omnimodal Reasoning for Low-Resource Long Audio-Video Question Answering

## Quick Facts
- **ArXiv ID:** 2602.03707  
- **Source URL:** https://arxiv.org/abs/2602.03707  
- **Reference count:** 40  
- **Primary result:** The approach raises Qwen2.5-Omni-7B accuracy from 25.00 to 29.69 on average on OmniVideoBench, WorldSense, and Daily-Omni, while reducing VRAM usage from up to 60GB to 15GB, demonstrating effective budget-conscious operation for long audio‑video QA.

## Executive Summary
OmniRAG-Agent tackles the challenge of long‑form audio‑video question answering in low‑resource settings. It builds external image and audio retrieval banks to fetch fine‑grained evidence without processing the entire stream, employs a multi‑turn agent loop to adaptively gather clues, and uses Group Relative Policy Optimization (GRPO) for end‑to‑end improvement. Evaluated on three benchmarks, it consistently outperforms prior methods under constrained memory and compute budgets, achieving higher accuracy with only 15GB VRAM. The work demonstrates that prudent retrieval, iterative reasoning, and RL‑based tuning can yield strong performance even with limited resources.

## Method Summary
The method integrates three key components. First, a multi‑modal retrieval‑augmented generation module constructs an image bank (by frame sampling) and an audio bank (via ASR), both indexed with CLIP embeddings. The agent issues natural‑language queries to retrieve the top‑K relevant snippets. Second, a multi‑turn agent loop runs for up to 20 steps: the OmniLLM policy, given a compact state summarising the history, outputs a thought, a retrieval query, and a stop/continue decision; retrieved evidence is appended to the history. Finally, the policy is trained with GRPO, using a gated reward that couples format validity (XML tags) and answer correctness. This joint optimization improves tool‑use correctness and final answer quality while keeping KL divergence bounded relative to a reference policy.

## Key Results
- On OmniVideoBench, WorldSense, and Daily‑Omni, OmniRAG‑Agent consistently outperforms prior low‑resource methods; Qwen2.5‑Omni‑7B accuracy improves from 25.00 to 29.69 on average.  
- Memory footprint is reduced to 15GB VRAM compared to up to 60GB for baselines, enabling deployment on budget hardware.  
- The system shows strong cross‑benchmark performance across long audio‑video inputs (20 seconds to 30 minutes).

## Why This Works (Mechanism)
**1. Multi‑modal retrieval‑augmented generation (RAG).** By building separate external image and audio banks and using CLIP‑based retrieval, the agent can fetch short, relevant snippets without dense encoding of the whole video. Frame sampling and ASR segments are indexed; natural‑language queries retrieve top‑K matches via text‑image or text‑text similarity (Section 4.1). This reduces compute while bringing key evidence into context. The mechanism assumes the banks contain the necessary scattered snippets and that CLIP/ASR indexing matches queries effectively. If retrieval fails due to sparse sampling or embedding mismatch, the agent cannot obtain needed evidence.

**2. Multi‑turn agentic reasoning.** The agent maintains an interaction history and a compact state. At each turn it generates a thought, a retrieval query, and a stop/continue decision. The environment returns retrieved snippets, the state updates, and the loop repeats. This iterative process allows the agent to refine queries, cover multiple temporal segments and modalities, and progressively narrow down the evidence space (Section 4.2). It assumes the question requires dispersed evidence that a single retrieval step cannot capture. If the policy produces irrelevant follow‑up queries, loops, or stops prematurely, the mechanism degrades.

**3. Group Relative Policy Optimization (GRPO).** The policy is trained end‑to‑end with a reinforcement learning objective that combines a format reward (enforcing structured XML‑like tags) and a performance reward (exact match), the latter gated by the format reward. Advantages are standardized within a group of sampled trajectories, and KL regularization keeps updates within a trust region (Section 4.3). This joint optimisation improves tool‑use correctness and answer quality. The gated reward design assumes format correctness is a necessary precursor to performance; misalignment (e.g., format reward dominating) or poor KL tuning can stall learning.

## Architecture Onboarding
**Component Map:**  
Input (Q, X) → Bank Construction Module (downsample X, sample frames → B_img, run ASR → B_aud) → Agent Core (OmniLLM policy π_θ) → Tool Environment (RETRIEVEIMG / RETRIEVEAUD return top‑K snippets) → State Manager (maintains H_t, computes compact state F(h_t) via summarization S_t) → Answer Generator (final answer y). An optional RL Trainer collects trajectories, computes gated reward R, and updates π_θ via GRPO.

**Critical Path (Inference):**
1. Build image and audio banks from the input stream (once).
2. Initialise agent state with question Q and downsampled video ˜X.
3. For each turn (up to T=20):
   a. Agent outputs thought z_t, query q_t, and stop flag c_t.
   b. If stop is signalled, break and generate answer.
   c. Else, invoke appropriate retrieval tool, obtain evidence E_t.
   d. Update history H_t and state F(h_t).
4. Output final answer y.

**Design Tradeoffs:**
- Retrieval budget K: larger K increases recall but also context length and compute.
- Multi‑turn depth T: more turns allow more evidence gathering but risk error accumulation and latency.
- Bank construction sampling interval Δ: sparse banks reduce memory but may miss evidence; dense banks increase size.
- Compact state summarisation: summarisation reduces memory but may lose detail needed for later queries.

**Failure Signatures:**
- No relevant retrieval: agent repeatedly obtains snippets unrelated to the question.
- Looping behaviour: agent issues similar queries across turns without progress.
- Premature stop: agent decides to answer after insufficient evidence collection.
- Format violation: output does not conform to required XML tags, breaking parsing and training.
- Memory overflow: interaction history grows beyond the model’s context window if state summarisation fails.

**First 3 Experiments:**
1. **Reproduce baseline:** Run the base OmniLLM (e.g., Qwen2.5‑Omni‑7B) on a small subset without RAG/agent/RL; verify low accuracy (~25%).
2. **Enable single‑turn RAG:** Activate retrieval banks but restrict agent to one tool call; expect accuracy improvement and verify snippet relevance.
3. **Enable multi‑turn agent loop:** Allow 5‑10 turns with the same RAG; measure gain over single‑turn and log average turns and evidence recall rate.

## Limitations
- The exact specification of the compact state summarisation operator S_t is not defined.
- The stopping condition implementation (e.g., binary head, token, or probability threshold) remains unspecified.
- The precise CLIP variant used for image/audio retrieval (and whether it is fine‑tuned) is unclear.
- Potential error accumulation in long multi‑turn loops is acknowledged but not extensively analysed.
- Evidence for GRPO’s effectiveness in this exact setting relies primarily on the paper’s own experiments; broader validation is limited.

## Next Checks
1. **Ablation of the agent loop:** Compare single‑turn RAG against multi‑turn (with identical banks) to isolate the benefit of iterative reasoning.
2. **Sensitivity analysis of bank construction:** Vary frame sampling interval Δ and audio segment density to measure effects on accuracy, retrieval recall, and memory consumption.
3. **Alternative GRPO reward experiments:** Train with modified reward formulations (e.g., remove format gate, use continuous scores) to test robustness and generalisation to held‑out examples.
