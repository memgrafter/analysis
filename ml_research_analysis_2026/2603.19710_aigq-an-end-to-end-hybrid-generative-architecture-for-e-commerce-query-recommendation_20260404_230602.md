# AIGQ: An End-to-End Hybrid Generative Architecture for E-commerce Query Recommendation

## Quick Facts
- **arXiv ID:** 2603.19710
- **Source URL:** https://arxiv.org/abs/2603.19710
- **Reference count:** 40
- **Primary result:** Online A/B testing: HintQ UCTR +7.42%, attributed orders +10.31%, GMV +10.68%, 7-day retention +3.73%.

## Executive Summary
AIGQ introduces the first end-to-end generative framework for pre-search query recommendation (HintQ) on Taobao, addressing shallow semantics, cold-start, and serendipity in traditional ID-based systems. It combines Interest-Aware List Supervised Fine-Tuning (IL-SFT) to construct ranked training samples from user behavior, and Interest-aware List Group Relative Policy Optimization (IL-GRPO) for fine-grained reward alignment via query-level and sequence-level signals. A hybrid offline-online deployment (AIGQ-Direct for nearline personalization, AIGQ-Think for diversity) enables low-latency serving. Extensive offline and online evaluations demonstrate substantial gains, validated by daily RL updates that continuously align with live user feedback.

## Method Summary
AIGQ reformulates HintQ as a list generation problem. Inputs consist of user profile and time-ordered behavior sequences, encoded via compressed prompts with special tokens. Training proceeds in two stages: (1) IL-SFT builds supervision targets by aggregating candidate queries (clicked, top-ranked, global search, LLM-generated) into rank-ordered lists using session-aware boundaries (single exposure for Direct, day-level for Think) and interest-guided re-ranking. (2) IL-GRPO applies policy gradient with dual rewards: query-level (CTR model reward, ROUGE-L, length penalty) and sequence-level (format compliance, repetition penalty), normalized per position and globally, and combined with a balancing coefficient. Two variants are trained: AIGQ-Direct generates flat query lists for nearline user-to-query caching; AIGQ-Think produces structured chain-of-thought with trigger-to-query mappings for offline index construction. Online, the system merges nearline cache and real-time x2q lookup with other recall channels.

## Key Results
- **Offline:** AIGQ-Think with IL-SFT+IL-GRPO achieves Cate HR@30 0.4704 and Unique Cates 9.8.
- **Online A/B:** HintQ UCTR +7.42%, attributed orders +10.31%, GMV +10.68%, 7-day retention +3.73%.
- **Continuous learning:** Daily RL updates improve PVR and CTR, confirming live feedback alignment.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Interest-Aware List Supervised Fine-Tuning (IL-SFT) improves HintQ relevance and diversity by constructing training samples that explicitly model nuanced, multi-faceted user intent through session-aware aggregation and interest-guided label re-ranking.
- **Mechanism:** IL-SFT treats the output as an ordered list of queries rather than an unstructured token sequence. It first defines a session scope (single exposure for Direct, day-level for Think), then aggregates candidate queries from system priors (ranking scores) and feedback priors (clicks > exposures). These candidates are re-ranked by quantified interest strength to form the supervision target list.
- **Core assumption:** The production ranking model and user click signals implicitly encode interest strength, allowing a heuristic combination (e.g., clicked queries first, then top-ranked) to produce a high-quality, ranked label list that teaches the LLM to generate lists respecting user interest density.
- **Evidence anchors:**
  - [abstract] "constructs ranked training samples via session-aware behavior aggregation and interest-guided label re-ranking"
  - [section 3.3] Details the session definitions and label construction formulas (Eqs. 3 & 4).
- **Break condition:** If system ranking scores become stale or misaligned with true user preference, or if session definitions fail to capture coherent intent (e.g., overly broad day-level sessions mixing unrelated searches), the constructed label list quality degrades, limiting IL-SFT's effectiveness.

### Mechanism 2
- **Claim:** Interest-aware List Group Relative Policy Optimization (IL-GRPO) aligns generated query lists with live user preferences by enabling fine-grained credit assignment through position-wise (query-level) and global (sequence-level) reward signals, enhanced by a daily-updated CTR model reward.
- **Mechanism:** IL-GRPO extends GRPO by computing advantages not just for the full sequence but per query slot using normalized query-level rewards (CTR, ROUGE-L, length) and sequence-level rewards (format, repetition). This allows the policy gradient to distinguish a high-quality query in a mediocre list from a low-quality one in an otherwise good list.
- **Core assumption:** Separate, normalized reward signals at query and sequence granularity can be combined linearly without interference, and the CTR model's predicted probability, when appropriately scaled, provides a differentiable, real-time proxy for user preference that drives alignment.
- **Evidence anchors:**
  - [abstract] "dual-component reward mechanism that jointly optimizes individual query relevance and global list properties, enhanced by a CTR model reward"
  - [section 3.5] Defines the dual rewards (Eq. 10), advantage computation (Eq. 11), and daily update cycle (Eq. 15).
- **Break condition:** If query-level and sequence-level rewards become conflicting (e.g., a semantically coherent but low-CTR query), the balancing coefficient λ may fail to find a stable optimum. Also, if the CTR model reward (Eq. 14) suffers from extreme sparsity or non-stationarity, the scaled signal could become uninformative or destabilizing.

### Mechanism 3
- **Claim:** The hybrid offline-online deployment (AIGQ-Direct nearline u2q + AIGQ-Think real-time x2q) achieves low-latency serving while balancing personalization accuracy and interest diversity, meeting industrial constraints.
- **Mechanism:** AIGQ-Direct runs heavy LLM inference asynchronously upon behavioral signals, caching personalized user-to-query lists for later retrieval. AIGQ-Think's reasoning outputs are distilled offline into a compact trigger-to-query index (x2q) using relevance+effectiveness scoring, enabling real-time lookup for recency-gap filling.
- **Core assumption:** The staleness in the nearline u2q cache (hours) is acceptable for most users, and the x2q index, built from reasoning over broader day-level signals, can effectively supplement it with high-quality, diverse triggers that capture recent intent shifts.
- **Evidence anchors:**
  - [abstract] "hybrid offline-online architecture comprising AIGQ-Direct for nearline personalized user-to-query generation and AIGQ-Think... to enrich interest diversity"
  - [section 4] Describes the asynchronous caching for u2q and the offline x2q index construction with scoring (Eq. 19).
- **Break condition:** If user intent changes very rapidly (e.g., session-based shopping with short sessions), the nearline cache staleness could render u2q outputs irrelevant. If the x2q index construction (trigger mapping) fails to generalize (e.g., triggers too specific or too broad), real-time retrieval may return low-quality or duplicate queries, harming user experience.

## Foundational Learning

**Concept: List-wise Generative Retrieval**
- *Why needed here:* AIGQ reformulates HintQ from a pointwise scoring/reranking problem to an ordered list generation task. This requires understanding how to train LLMs to produce ranked candidate lists directly, not just next tokens or single items.
- *Quick check question:* How does modeling the output as an ordered list (vs. a set or sequence without ranking supervision) change the training objective and evaluation metrics?

**Concept: Reinforcement Learning with Fine-Grained Advantage Estimation**
- *Why needed here:* Standard RL methods assign a single reward to the entire generated sequence, causing credit assignment problems in list generation. IL-GRPO requires understanding how to decompose a list-level objective into position-specific advantages using group-normalized statistics.
- *Quick check question:* Why is normalizing the query-level advantage within the same position across group rollouts (Eq. 12) critical for stable policy updates in list generation?

**Concept: Hybrid Offline-Online Serving for LLMs in Industrial Systems**
- *Why needed here:* Deploying a billion-parameter LLM for real-time recommendation faces strict latency budgets. The engineer must grasp the trade-offs between async cache freshness, index-based real-time lookup, and their combined coverage.
- *Quick check question:* What specific user behavior signal triggers the nearline AIGQ-Direct inference, and how does the x2q index address the recency gap that the nearline cache cannot?

## Architecture Onboarding

**Component map:** User Context Engineering → IL-SFT Training Pipeline (Session aggregator → Label curator → Direct/Think variants) → IL-GRPO Trainer (Rollout sampler → Dual-reward calculator → Advantage normalizer → Policy updater) → Deployment Stack (Nearline u2q service + Offline x2q builder → OnlineHintQ recall merge)

**Critical path:** Data collection (logs) → Sample construction (IL-SFT) → Supervised fine-tuning → RL rollout & reward computation (CTR model daily updated) → Policy update → Daily export of u2q cache & x2q index → Online merge & ranking.

**Design tradeoffs:**
- Direct vs. Think: Direct offers higher precision but lower diversity; Think adds reasoning for diversity but higher latency and complexity.
- Cache staleness vs. freshness: Nearline u2q reduces online latency but lags behind current intent; x2q fills gaps but relies on reasoning generalizability.
- Reward complexity vs. stability: Dual-level rewards improve alignment but require careful normalization and λ tuning to avoid conflicts.

**Failure signatures:**
- Sharp drop in Cate HR@30/Query HR@30 offline, indicating IL-SFT/GRPO misconfiguration.
- High duplicate rate in generated queries (monitor Unique Cates metric), suggesting repetition penalty ineffective.
- Online latency spike if u2q cache misses force fallback to expensive real-time LLM call.
- GMV/CTR decline in A/B test, possibly from CTR reward scaling (γ, β in Eq. 14) mis-set or stale CTR model.

**First 3 experiments:**
1. Reproduce IL-SFT gain: Train AIGQ-Direct with/without interest-guided label re-ranking on a held-out day. Expect ~0.012 gain in Cate HR@30.
2. Validate IL-GRPO dual-reward: Ablate sequence-level reward (R_seq). Expect drop in diversity (Unique Cates) and format issues.
3. Test daily RL update cycle: Disable daily policy updates after initial training in a short A/B test. Expect gradual CTR/PVR decay over ~5 days.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** How can multimodal context (e.g., product images, user-generated content) be integrated into AIGQ to further improve query generation accuracy and diversity?
- **Basis in paper:** The conclusion states: "enriching query generation through more precise multimodal context understanding" as a future direction.
- **Why unresolved:** The current AIGQ framework relies solely on textual user behavior and profile data; multimodal signals are not incorporated despite their potential to capture richer intent.
- **What evidence would resolve it:** An extended model variant that processes multimodal inputs (e.g., CLIP embeddings, image captions) should be implemented and evaluated offline (e.g., Cate HR@30, Unique Cates) and online (e.g., UCTR, GMV) against the text-only baseline to measure incremental gains.

### Open Question 2
- **Question:** What are the exact trade-offs between model compression (distillation/quantization) and recommendation quality in AIGQ-Think for real-time deployment?
- **Basis in paper:** The conclusion proposes "enabling scalable real-time reasoning through efficient deployment techniques such as distillation or quantization."
- **Why unresolved:** While AIGQ-Think is deployed via an offline x2q index, the paper does not explore compressing the model itself for direct real-time inference, leaving unknown the cost in terms of latency vs. accuracy.
- **What evidence would resolve it:** Conduct systematic experiments distilling or quantizing AIGQ-Think (e.g., to 3-bit or smaller student models), measuring changes in inference latency, memory footprint, and key metrics (Cate HR@30, Query HR@30, PVR) to define Pareto frontiers.

### Open Question 3
- **Question:** How sensitive is IL-GRPO's performance to the balancing coefficient λ between query-level and sequence-level rewards?
- **Basis in paper:** IL-GRPO uses a fixed λ (Eq. 11) to combine normalized query and sequence advantages without reported sensitivity analysis.
- **Why unresolved:** The optimal λ likely depends on dataset characteristics and reward definitions; an improper balance could over-optimize diversity at the cost of relevance or vice versa.
- **What evidence would resolve it:** Perform an ablation sweeping λ across a range (e.g., 0.1 to 2.0) and measure impact on both query-level (ROUGE-L, CTR reward) and list-level (repetition penalty, format compliance) metrics, identifying robust settings.

### Open Question 4
- **Question:** What is the optimal cache update frequency for AIGQ-u2q nearline recall to maximize personalization recency without exceeding storage/compute budgets?
- **Basis in paper:** Section 4.1 describes asynchronous caching but does not analyze the trade-off between update interval (e.g., per-behavior, hourly, daily) and recommendation freshness.
- **Why unresolved:** Too frequent updates increase system load and may not improve user experience significantly; too infrequent updates miss real-time intent shifts, degrading metrics.
- **What evidence would resolve it:** Simulate or deploy varying update policies (e.g., trigger on specific actions, time-based intervals), measure resulting cache hit rates, user engagement (Search UV, retention), and system resource usage to determine cost-effectiveness.

## Limitations
- **CTR reward specification:** Scaling factors (γ, β) and feature set for the daily-updated CTR model are undisclosed, hindering exact reward signal replication.
- **Prompt/token engineering:** Exact special tokens for behavior encoding and teacher LLM prompts for Think’s CoT generation are underspecified, affecting input representation fidelity.
- **Cache staleness tolerance:** Acceptable nearline delay for AIGQ-Direct is not quantified; rapid intent shifts may degrade relevance before cache refresh.
