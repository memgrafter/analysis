# Align and Adapt: Multimodal Multiview Human Activity Recognition under Arbitrary View Combinations

## Quick Facts
- **arXiv ID:** 2602.08755
- **Source URL:** https://arxiv.org/abs/2602.08755
- **Reference count:** 40
- **Primary result:** AliAd achieves state-of-the-art F1-scores in most tested multiview HAR scenarios and demonstrates robust performance under arbitrary missing views, with reduced computational complexity.

## Executive Summary
This paper introduces AliAd, a framework for multimodal multiview human activity recognition (HAR) designed to handle arbitrary missing views during both training and inference. The method addresses the challenge of aligning and fusing information from an unpredictable subset of available views. It combines an adjusted center contrastive loss for view alignment without reconstruction, an attention mechanism to weight views by quality, and a mixture-of-experts (MoE) head for adaptive fusion. Evaluated on four multiview HAR datasets with 3–9 views, AliAd consistently outperforms prior methods, particularly in missing-view settings, while offering improved computational efficiency.

## Method Summary
AliAd processes each input view separately through dedicated encoders to generate view-specific features. To align these features without explicit reconstruction, it employs an adjusted center contrastive loss that pulls together features from the same sample across different views while pushing apart features from different samples, operating within each batch to avoid an O(V²) complexity. A quality-aware attention module then weights these aligned features based on their estimated reliability. Finally, a mixture-of-experts (MoE) head adaptively fuses the weighted features, with a dedicated load-balancing loss to ensure experts are utilized evenly across the diverse combinations of available views.

## Key Results
*   AliAd achieves the highest F1-score in 10 of 12 tests under complete-view training across four datasets, outperforming prior state-of-the-art methods.
*   It demonstrates superior robustness and accuracy in arbitrary missing view scenarios, significantly outperforming baselines at various random missing rates.
*   The proposed adjusted center contrastive loss reduces computational complexity from O(V²) to O(V) compared to standard pairwise contrastive approaches, validated by runtime analysis.

## Why This Works (Mechanism)
The adjusted center contrastive loss effectively aligns view-specific feature spaces by treating each view's feature as an anchor and contrasting it with the features of other views for the same sample, mitigating the need for view reconstruction and its associated complexity. The attention module provides a learned, data-driven mechanism to discount low-quality or occluded views, making the system robust to arbitrary missingness. The MoE head allows the model to specialize different experts for different view combinations, enabling adaptive fusion that generalizes to unseen subsets of views during inference.

## Foundational Learning
*   **Contrastive Learning for Representation Alignment:** Aligns embeddings from different views of the same instance. *Why needed:* Ensures view-specific features exist in a common space before fusion. *Quick check:* Measure feature similarity (e.g., cosine) for same/different samples across views before and after applying the loss.
*   **Attention for Dynamic Weighting:** Assigns importance scores to each view's features. *Why needed:* Downweights unreliable or missing views to prevent them from degrading the fused representation. *Quick check:* Visualize attention weights for inputs with synthetically degraded views (e.g., blur, occlusion).
*   **Mixture-of-Experts (MoE) for Adaptive Fusion:** Employs multiple expert networks with a gating mechanism. *Why needed:* Handles the combinatorial explosion of possible view subsets by allowing specialists for different combinations. *Quick check:* Analyze expert activation patterns for different held-out view sets; experts should show specialization.
*   **Load Balancing in MoE:** Regularizes the gating network to ensure all experts are used. *Why needed:* Prevents a few experts from dominating, which is crucial for generalizing to rare view combinations. *Quick check:* Compute the coefficient of variation of expert utilization across training batches; it should decrease with the balancing loss.
*   **Multiview HAR:** Recognizing human activities from multiple synchronized camera viewpoints. *Why needed:* Provides complementary information and reduces view-specific occlusions. *Quick check:* Benchmark single-view vs. multiview performance on a standard dataset like NTU RGB+D.
*   **Arbitrary Missing Views:** The core challenge where any subset of views may be absent at test time. *Why needed:* Reflects real-world failures (e.g., camera blockage, failure). *Quick check:* Randomly mask views during evaluation and measure performance drop relative to a model trained only on complete views.

## Architecture Onboarding
**Component Map:**
Input Views (V) -> Individual View Encoders -> Aligned Features (via Adjusted Center Contrastive Loss) -> Quality-aware Attention Module -> Weighted Features -> Mixture-of-Experts (MoE) Head -> Activity Prediction

**Critical Path:** 1) Encode each available view independently. 2) Align all encoded features into a common space using contrastive loss. 3) Compute attention weights for each view. 4) Apply weights and route the combined representation through the MoE head for final classification.

**Design Tradeoffs:**
*   *Separate Processing vs. Cross-view Interaction:* Processing views separately (vs. early fusion/Transformers) enables robustness to arbitrary missingness but may miss fine-grained dependencies between views.
*   *Contrastive Alignment vs. Reconstruction:* Using contrastive loss avoids the computational cost and potential artifacts of reconstructing missing views, but relies on the assumption of shared semantic information across views.
*   *MoE Complexity vs. Specialization:* The MoE head adds parameters and inference cost but is necessary to handle the vast number of possible view combinations effectively.

**Failure Signatures:**
*   Performance collapse on modalities with very low inter-view mutual information (e.g., ECG, EEG) where contrastive alignment assumption fails.
*   Degradation under highly imbalanced training data where certain view combinations are extremely rare, leading to "expert starvation."
*   Inability to model explicit cross-view spatial or temporal relations, potentially harming tasks where inter-view geometry is critical.

**First 3 Experiments to Onboard:**
1.  **Ablation of Core Components:** Train ablations without the adjusted contrastive loss, without the attention module, and without the MoE load-balancing loss on a dataset like NTU RGB+D 120 to isolate their individual contributions.
2.  **Synthetic Missing View Robustness Test:** Introduce random missing views at evaluation (e.g., 25%, 50%, 75% missing) and compare AliAd's accuracy drop against a baseline that uses a Transformer for cross-view fusion but requires all views at input.
3.  **Expert Utilization Analysis:** For the trained MoE head, input batches with known, controlled view combinations (e.g., only camera 1, only camera 2, cameras 1+3) and visualize which experts are activated by each combination type.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can the adjusted center contrastive loss be effectively adapted for domains with very low mutual information among views, such as electrocardiography or electroencephalography, where the assumption of shared information may not hold?
- **Basis in paper:** [explicit] In the Conclusion, the authors state: "In rare cases when views share minimal mutual information, contrastive learning’s effectiveness would be limited. Our approach samples negative pairs for contrastive loss within each batch, which is effective when the data are diverse. This may be less effective when samples are highly similar, as often seen in modalities like electrocardiography or electroencephalography. These issues need to be addressed when adapting the proposed method to other fields besides HAR."
- **Why unresolved:** The current method relies on contrastive learning to align views based on mutual information, which may fail or degrade performance when views have little common information, limiting applicability to certain modalities.
- **What evidence would resolve it:** Systematic evaluation of AliAd on datasets with low mutual information modalities (e.g., ECG or EEG) under arbitrary missing view scenarios, comparing performance with alternative loss functions that do not assume high mutual information, and analyzing when contrastive learning becomes ineffective.

### Open Question 2
- **Question:** How can cross-view interactions be modeled in a manner that remains robust to arbitrary missing views, given that AliAd processes views separately and only fuses them at the end, potentially missing dependencies between views?
- **Basis in paper:** [explicit] In the Conclusion, the authors note: "Our method processes views separately to accommodate missing data. While it retains useful view-specific features, it does not model cross-view interactions, except at the fusion step. Although experiments show it performs favorably compared to methods incorporating cross-view interactions (e.g., using Transformer), this remains an avenue for future exploration, particularly in scenarios with missing views."
- **Why unresolved:** Modeling cross-view interactions could enhance feature representation by capturing inter-view dependencies, but existing methods like Transformers may not handle missing views flexibly, creating a trade-off between interaction modeling and missing-view robustness.
- **What evidence would resolve it:** Development of a hybrid architecture that integrates cross-view mechanisms (e.g., sparse attention or graph-based interactions) with the current separate processing, evaluated on multiview HAR datasets with varying missing rates, measuring improvements in accuracy and robustness compared to AliAd and Transformer-based baselines.

### Open Question 3
- **Question:** What load balancing strategy in the mixture-of-experts head optimally handles highly imbalanced view combinations, such as when certain view subsets dominate training data, to ensure robust generalization to rare combinations?
- **Basis in paper:** [inferred] From Section 3.3.2, the authors propose a separate load balancing loss for individual views and fusion to prevent disjoint expert allocation. However, in scenarios with extreme imbalance (e.g., one-view combinations far more frequent), the current coefficient of variation squared approach may not fully mitigate expert starvation for rare combinations.
- **Why unresolved:** The load balancing strategy aims for even expert utilization, but with imbalanced data, experts might still specialize unevenly, harming performance on underrepresented view combinations, which is critical for arbitrary missing view scenarios.
- **What evidence would resolve it:** Controlled experiments using synthetic or real datasets with skewed view combination frequencies, analyzing expert activation patterns and task performance on rare combinations, and comparing alternative balancing losses (e.g., fairness-aware or adaptive weighting) to the current method.

## Limitations
*   Evaluation is restricted to four multiview HAR datasets (3–9 views); scalability to a larger number of views and other modalities (e.g., skeleton sequences, audio) is untested.
*   Missing-view experiments use only randommissing rates; realistic structured missing patterns (e.g., whole-camera failure, persistent motion blur) are not explored.
*   The definition and estimation of "view quality" for the attention module are not thoroughly justified and may not generalize across datasets with different characteristics.

## Confidence
*   **Performance superiority on evaluated datasets:** High. Results are consistent across four datasets and against multiple baselines.
*   **Robustness to random missing views:** High. Experiments explicitly show maintained advantage under varying random missing rates.
*   **Computational efficiency claim (O(V)):** Medium. The analysis compares against a naive O(V²) implementation but not against a potentially optimized O(V²) baseline; hidden constants are not discussed.
*   **Generalizability to other domains/modalities:** Low. Authors explicitly identify low mutual information modalities as a key unresolved challenge.
*   **Ablation study validity:** High. Ablations confirm the contribution of each proposed component.

## Next Checks

2.  Conduct missing-view experiments with structured patterns simulating real-world camera failures (e.g., all views from a specific camera angle missing) to assess robustness beyond random dropout.
