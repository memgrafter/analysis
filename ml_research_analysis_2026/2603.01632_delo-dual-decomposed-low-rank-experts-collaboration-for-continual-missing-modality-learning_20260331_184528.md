# DeLo: Dual Decomposed Low-Rank Experts Collaboration for Continual Missing Modality Learning

## Quick Facts
- arXiv ID: 2603.01632
- Source URL: https://arxiv.org/abs/2603.01632
- Reference count: 17
- Primary result: DeLo achieves state-of-the-art Average Performance (78.20%) and Average Forgetting (6.34%) on UPMC-Food101-CMML with 70% missing modalities, substantially outperforming RebQ and prompt-based methods.

## Executive Summary
DeLo introduces the first LoRA-based framework for Continual Missing Modality Learning (CMML), addressing the challenge of sequentially adapting a pre-trained multimodal model to incomplete data while preventing catastrophic forgetting. It features a dual-decomposed low-rank expert architecture with separate visual and textual factor pools to eliminate modality interference, and a cross-modal guided routing mechanism that dynamically selects factors for both complete and missing inputs. Task-partitioned experts and a task-key memory structurally isolate knowledge across tasks and enable task-agnostic inference. Evaluations on CMML benchmarks demonstrate robust stability-plasticity trade-offs, with consistent state-of-the-art performance in average performance and forgetting across varying missing ratios.

## Method Summary
DeLo extends LoRA by decomposing the adaptation matrix into modality-specific low-rank factors. For each task, it maintains separate expert pools for vision and text. During training on a new task, only the current task's pools and classifier are updated; all previous task pools and the backbone remain frozen. Routing uses queries derived from the backbone's hidden states; for missing modalities, the query from the available modality serves as a proxy, leveraging the pre-trained model's shared semantic space. A non-trainable Task-Key Memory stores a centroid per task, updated via exponential moving average, allowing inference without task IDs by routing to the nearest centroid. The total loss combines classification, alignment (enforcing paired query similarity), and consistency (stabilizing proxy routing) terms.

## Key Results
- On UPMC-Food101-CMML with 70% missing modalities, DeLo achieves 78.20% Average Performance (AP) and 6.34% Average Forgetting (FG), significantly outperforming RebQ (71.62% AP, 6.44% FG) and all prompt-based methods.
- DeLo consistently ranks first across missing ratios (30%–70%) on both UPMC-Food101-CMML and MM-IMDb-CMML, demonstrating robust stability-plasticity trade-offs.
- Ablations confirm the critical role of modality-specific factor pools (unified pool causes major AP/FG degradation), cross-modal guided routing (removal leads to catastrophic failure on missing inputs), and alignment/consistency losses.

## Why This Works (Mechanism)

**Mechanism 1: Preventing Modality Interference via Decomposed Factor Pools**  
DeLo replaces a single shared LoRA expert pool with two disentangled pools—visual and textual—so that gradient updates from image-only and text-only samples do not compete. For each input, factors are independently selected from each pool to compose modality-specific update matrices ΔW_v and ΔW_t, which are summed to form the final LoRA update. This physical separation isolates updates by data type, preventing suboptimal entangled adaptations. The core assumption is that competing gradients in a shared space degrade performance; evidence includes the paper's abstract and sections describing the decomposition, though direct validation is limited to ablations showing performance drops when pools are unified. A break condition would be tasks requiring deeply integrated visual-textual reasoning that cannot be captured by a simple sum of separate updates.

**Mechanism 2: Cross-Modal Guided Routing for Missing Modalities**  
When a modality is missing, DeLo uses the query from the available modality as a proxy to route factors from that modality's pool. This relies on the assumption that visual and textual queries (q_v, q_t) from complete data are semantically aligned in the frozen backbone's space, making one a valid substitute for the other. The alignment loss (L_align) explicitly enforces this similarity during training. Evidence includes the abstract's mention of dynamic selection for missing inputs and the section detailing proxy query usage. If the pre-trained model's vision and text encoders are poorly aligned, the proxy query may misguide selection, degrading performance on missing-modality inputs.

**Mechanism 3: Task-Partitioned Experts and Task-Key Memory for Forgetting Prevention**  
DeLo employs a task-partitioned architecture: during training on task T_k, only its dedicated factor pools (P_v^k, P_t^k) and classifier are updated; all previous pools are frozen. This physical isolation prevents gradient interference across tasks. For task-agnostic inference, a non-trainable Task-Key Memory stores a centroid key_k per task, updated via EMA on batch queries. At test time, the query's cosine similarity to keys predicts the task ID, activating the correct pool. The core assumptions are that isolation prevents catastrophic forgetting and that discriminative task centroids exist. Evidence includes the abstract's structural prevention claim, the section's description of freezing parameters, and Figure 4a's t-SNE showing separated task clusters. If tasks are highly semantically overlapping (e.g., fine-grained categories), centroids may not be separable, causing misrouting and performance loss.

## Foundational Learning

**Low-Rank Adaptation (LoRA)**
- *Why needed here:* DeLo is built upon LoRA's principle of parameter-efficient fine-tuning via low-rank matrix decomposition (ΔW = BA). Understanding this base is essential to grasp how DeLo's decomposed variant extends it.
- *Quick check:* In standard LoRA, if W ∈ R^{d_out × d_in} and rank r << min(d_out, d_in), what are the dimensions of matrices A and B?  
  A ∈ R^{r × d_in}, B ∈ R^{d_out × r}.

**Mixture-of-Experts (MoE) & Dynamic Routing**
- *Why needed here:* DeLo's expert pool and instance-based routing (selecting top-r factors from a larger pool E) are directly inspired by MoE. The selection mechanism is a core operational detail.
- *Quick check:* What is the purpose of having a larger factor pool (E) than the selected rank (r) in a MoE-like system?  
  To provide a diverse set of experts from which the router can select the most relevant ones per input, enabling dynamic adaptation.

**Catastrophic Forgetting in Continual Learning**
- *Why needed here:* The entire motivation for the task-partitioned architecture is to mitigate catastrophic forgetting. Understanding the problem (gradient interference overwriting old knowledge) is key to appreciating the "partition" solution.
- *Quick check:* Why does learning on a new task T_{k+1} cause performance on a previous task T_k to drop in a standard fine-tuning setup?  
  Because the gradient updates for T_{k+1} overwrite parameters that were optimized for T_k, leading to loss of previously acquired knowledge.

**Modality Alignment in Multimodal Models**
- *Why needed here:* The Cross-Modal Guided Routing relies on the assumption that visual and textual embeddings from the same sample are semantically aligned. This is a baseline property of pre-trained models like ViLT.
- *Quick check:* What inductive bias allows a model like ViLT to produce embeddings (q_v, q_t) from an image-text pair that can be compared directly via cosine similarity?  
  Pre-training on large-scale paired data forces the model to align vision and text representations in a shared semantic space.

## Architecture Onboarding

**Component map:**  
Frozen Backbone (ViLT-B/32) -> Hidden states per modality -> Modality-Specific Factor Pools (per task: P_v^k, P_t^k) <- Cross-Modal Guided Router (scores factors, top-r selection) -> Decomposed LoRA Expert (composes ΔW_v + ΔW_t) -> Layer output. Task-Key Memory (non-trainable centroids) <- Queries from router; at inference, selects task pool. Task-Partitioned Heads (one per task) for classification.

**Critical path:**  
1. Input (image/text/dummy) -> Frozen Backbone -> Hidden state h per modality.  
2. Generate query q = Avg(h) for each present modality.  
3. If modality missing: use proxy query from available modality for missing one's router.  
4. For each modality, router selects r factors from current task's modality-specific pool.  
5. Composed ΔW_v and ΔW_t are applied to the layer's weights.  
6. Classification via the head of the predicted task (from Task-Key Memory).

**Design tradeoffs:**  
- Pool Size (E) vs. Rank (r): Larger E offers more diverse experts but more parameters/compute; larger r increases adaptation capacity but risks overfitting. Paper finds r=4 optimal.  
- Modality Separation vs. Expressivity: Strict separation prevents interference but may limit representational capacity if joint visual-textual components are needed; ΔW_v + ΔW_t is a simple collaboration.  
- Task Partitioning vs. Scalability: Physical isolation guarantees no forgetting but linearly increases parameters with tasks; Task-Key Memory adds minimal overhead but assumes separable task distributions.

**Failure signatures:**  
1. Poor separation in Task-Key Memory t-SNE: overlapping clusters indicate non-separable tasks, leading to inference misrouting.  
2. High forgetting (FG) despite high AP on current task: task-partitioning or routing failing to activate correct past pools.  
3. Performance collapse on missing-modality inputs vs. complete inputs: cross-modal guided routing ineffective; proxy queries unaligned.  
4. Single-modality pools showing similar selection patterns: router not learning modality-specific strategies, ineffective decomposition.

**First 3 experiments:**  
1. Ablation: w/o Modality-Specific Factor Pool (unified pool) -> expect significant AP drop and FG increase due to modality interference.  
2. Ablation: w/o Cross-Modal Guide (disable proxy query for missing modalities) -> expect catastrophic failure on high missing-ratio settings.  
3. Ablation: Loss Components (remove L_align or L_con) -> expect progressive AP improvement when adding these losses, validating their necessity.

## Open Questions the Paper Calls Out
1. Can DeLo's dual-decomposed expert architecture generalize to scenarios with more than two modalities (e.g., audio-vision-text) without increasing modality interference? The design separates only visual and textual pools; extension to N modalities is untested.
2. How robust is the Task-Key Memory's clustering-based routing when faced with a large number of continual tasks (e.g., 100+), where task features may overlap or drift? Validation only on 10 tasks; scalability to long sequences unexplored.
3. Does the Cross-Modal Guided Routing remain effective when the semantic alignment between modalities is weak (i.e., qv ≈ qt does not hold), such as in datasets with mismatched image-text pairs? Assumption not validated under low-modality-correlation conditions.

## Limitations
- Dataset split ambiguity: The exact algorithm for generating CMML splits (session partitioning, missing modality sampling) is not provided, blocking exact replication.
- Layer application opacity: The paper does not specify which Transformer layers are adapted with DeLo experts, leaving key architectural details unclear.
- Generalizability constraints: Claims rely on ViLT-B/32’s pretrained modality alignment; performance with other backbones or tasks with high semantic overlap remains untested.

## Confidence
- Modality interference mitigation: High (ablations show significant drops without separate pools).
- Cross-modal guided routing: High for ViLT (alignment loss ablations confirm), Medium for broader applicability (untested on poorly aligned models).
- Catastrophic forgetting prevention: High for evaluated task sequences, Medium for fine-grained or highly overlapping tasks (t-SNE only on 10 tasks).
- Overall SOTA performance: High for specific settings (UPMC-Food101-CMML, MM-IMDb-CMML), Medium for external validity (limited benchmarks).

## Next Checks
