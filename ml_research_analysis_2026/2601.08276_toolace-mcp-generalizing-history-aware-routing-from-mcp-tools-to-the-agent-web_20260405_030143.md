# ToolACE-MCP: Generalizing History-Aware Routing from MCP Tools to the Agent Web
## Quick Facts
- arXiv ID: 2601.08276
- Source: https://arxiv.org/abs/2601.08276
- Citations: 21
- Primary result: Achieves 53.44% accuracy on MCP-Universe, outperforming GPT-4o (47.41%) and Gemini-2.5-Pro (49.79%), and generalizes to agent selection with 91.6% accuracy.

## Executive Summary
ToolACE-MCP addresses the scalability and generality bottlenecks in the emerging Agent Web by enabling precise navigation of large-scale tool and agent ecosystems. The framework constructs a dependency-rich Candidate Graph via self-evolutionary mutation to expand and differentiate semantically similar candidates. It then synthesizes history-aware multi-turn trajectories through a multi-agent simulation to generate supervision data for training a router. The resulting Light Routing Agent is a plug-and-play module that uses only two tools—router invocation and execution—decoupling routing logic from concrete definitions. Evaluated on MCP-Universe and MCP-Mark, ToolACE-MCP surpasses leading LLM baselines, demonstrates robustness under noise and scaling, and generalizes to agent selection without additional training.

## Method Summary
The pipeline consists of five stages. (1) **Graph Construction**: Tool specifications are embedded using `all-MiniLM-L6-v2`; edges connect pairs with cosine similarity > τ=0.82. (2) **Self-Evolutionary Mutation**: Five operators (e.g., Parameter Mutation, Workflow Chaining) mutate existing tools, adding new nodes and mutation edges to expand diversity while preserving relationships. (3) **Candidate Sampling**: A DFS-style random walk from seed nodes yields locally coherent subsets (e.g., five candidates). (4) **Trajectory Synthesis**: A multi-agent simulation (Planner, Assistant, User, Tool) generates multi-turn dialogues conditioned on the subset, with tool results simulated. (5) **Supervision Extraction**: At assistant invocations, the chosen candidate is labeled along with the preceding history and current query. Finally, the **Router** is fine-tuned via LoRA (r=8) on Qwen3-8B. Inference uses a Light Routing Agent with only two tools: router invocation and execution.

## Key Results
- MCP-Universe accuracy: 53.44% (vs GPT-4o 47.41%, Gemini-2.5-Pro 49.79%).
- MCP-Mark accuracy: 60.00%.
- Agent Route Benchmark accuracy: 91.6% (zero-shot transfer).
- Ablation: Removing historical context causes a 5–8% absolute drop in accuracy.

## Why This Works (Mechanism)
The dependency-rich graph, enhanced by self-mutation, ensures that semantically related yet functionally varied tools are reachable during sampling, providing both diversity and relevance. Multi-turn trajectory synthesis explicitly trains the router to condition on interaction history, which is essential for disambiguating tool selection as user intent evolves. The light router’s separation of routing logic from concrete tool definitions enables cross-domain generalization, even to agent selection. Moreover, the synthetic data pipeline generates large-scale, history-rich training samples without real API calls, overcoming data scarcity.

## Foundational Learning
Key concepts underpinning ToolACE-MCP:
- **Model Context Protocol (MCP)**: Standardizes tool descriptions via schemas, enabling uniform representation. *Quick check*: Can you retrieve a tool’s input schema from its spec?
- **Embedding-based semantic similarity**: Measures functional equivalence between tools. *Quick check*: Compute cosine similarity between two tool description embeddings.
- **Graph-based candidate modeling**: Captures tool dependencies for coherent subset sampling. *Quick check*: Build an adjacency list from similarity edges and traverse locally.
- **Self-evolutionary mutation**: Scales the candidate pool by creating valid variants with controlled drift. *Quick check*: Apply a parameter mutation operator to modify a tool’s argument type.
- **Multi-agent simulation**: Generates realistic dialogue histories without real user interaction. *Quick check*: Simulate a three-turn conversation where the assistant calls a tool.
- **Parameter-efficient fine-tuning (LoRA)**: Adapts large models with minimal overhead. *Quick check*: Apply LoRA to a transformer layer and verify trainable parameters.

## Architecture Onboarding
- **Component map**: Tool Specs → Embedder → Graph Builder (with Self-Mutation) → Subset Sampler → Trajectory Generator → Data Extractor → LoRA Trainer → Light Routing Agent
- **Critical path**: Graph construction and mutation define the candidate universe; trajectory synthesis provides history-rich supervision; LoRA training equips the router to use both candidate semantics and dialogue history. Disrupting any stage—e.g., poor mutation validity or unrealistic trajectories—degrades final accuracy.
- **Design tradeoffs**:
  - Similarity threshold τ: balances graph sparsity vs. noise; too high yields isolated nodes, too low creates irrelevant edges.
  - Mutation operators: higher diversity risks invalid tools; validation is needed.
  - Trajectory realism: fully automated simulation may stray from real user behavior; prompt engineering is key.
  - Model size: Qwen3-8B is cost-effective but may underfit complex routing; larger models could improve.
- **Failure signatures**:
  - Low accuracy despite decreasing training loss → candidate graph lacks functional diversity or data mismatch.
  - High rate of invalid tool calls in generated trajectories → synthesis prompts underspecified.
  - Router ignores history → history-sensitive examples underrepresented or sequence length insufficient.
- **First three experiments**:
  1. Build a graph from 200 seed MCP tools; compute average degree and connectivity; inspect edge examples to verify τ=0.82 yields meaningful links.
  2. Implement 3 mutation operators (Parameter Mutation, Workflow Chaining, Usage Extension); generate 200 variants; manually verify validity and semantic drift.
  3. Generate 500 trajectories for random 5-node subsets; parse tool calls; report schema compliance rate; if <90%, refine simulation prompts.

## Open Questions the Paper Calls Out
- **Scaling to larger models**: The study only fine-tuned Qwen3-8B; it is unknown whether performance gains extend to >10B parameter models. *Evidence needed*: Train the same pipeline on larger backbones and compare scaling trends.
- **Specialized agent routing models**: The router was trained on tool data but generalized to agents; a dedicated agent-router might yield further improvements. *Evidence needed*: Construct an agent-specific trajectory dataset and train a router from scratch.
- **Applicability to other retrieval problems**: The paradigm could be used for long-term memory management, but this remains unexplored. *Evidence needed*: Adapt the pipeline to a conversational memory benchmark and evaluate retrieval accuracy.

## Limitations
- Trajectory synthesis details (prompts, turn-taking, tool result simulation) are underspecified, hindering replication.
- Mutation operator implementation (LLM settings, validation logic) lacks precision, risking inconsistent variant quality.
- Benchmark construction (candidate pools per task, history formatting) is opaque, making exact comparison difficult.
