# Structure-Preserving Graph Contrastive Learning for Mathematical Information Retrieval
## Quick Facts
- **arXiv ID:** 2603.08012
- **Source URL:** https://arxiv.org/abs/2603.08012
- **Reference count:** 14
- **Primary result:** A topology-preserving augmentation (Variable Substitution) outperforms standard graph augmentations like Node Drop for mathematical formula retrieval, achieving bpref scores up to 0.59/0.58 (full relevance) on the NTCIR-12 dataset using the TangentCFT base model.

## Executive Summary
This paper addresses a fundamental challenge in applying graph contrastive learning (GCL) to mathematical information retrieval: standard graph augmentations often distort the semantic meaning of formula graphs by altering critical operators or structure. The authors propose Variable Substitution, a simple augmentation that randomly swaps the identities of variable and number nodes while preserving the graph's topology (edges and operator nodes). Evaluated on the NTCIR-12 benchmark using the TangentCFT model, Variable Substitution yields substantial improvements in retrieval accuracy over generic techniques like Node Drop or Edge Drop. The method demonstrates robust performance across different graph layouts (SLT/OPT) and batch sizes, establishing that preserving structural integrity is paramount for effective contrastive learning on dense, small-scale formula graphs.

## Method Summary
The core innovation is a structure-preserving data augmentation for GCL applied to mathematical formula graphs. Standard GCL pipelines create two augmented views of an input graph to form a positive pair for contrastive loss. Instead of removing nodes or edges (e.g., Node Drop), which frequently destroys the semantic validity of a formula, Variable Substitution only replaces the textual labels of leaf nodes (variables and constants) with other labels from the same category, leaving the entire operator-operand hierarchy intact. This ensures the positive pair represents two semantically equivalent variations of the same formula. The augmented graphs are processed by a TangentCFT-based encoder, which uses a Token Embedding Generator (random walks + fastText) to create initial node features. The model is trained to minimize a contrastive loss (e.g., InfoNCE) that pulls embeddings of the original and augmented graphs together while pushing apart embeddings from other formulas in the batch.

## Key Results
- Variable Substitution achieves the highest full-relevance bpref scores: **0.59 (SLT)** and **0.58 (OPT)**, surpassing Node Drop (max 0.54/0.55) and Edge Drop.
- It leads in partial relevance as well, with scores up to **0.70 (SLT)**.
- Performance is stable across batch sizes and graph layouts (SLT vs. OPT), with minimal standard deviation (0.001–0.009), unlike generic augmentations which show greater variance and sensitivity.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Preserving graph topology during augmentation prevents semantic distortion of mathematical formulas.
- **Mechanism:** Variable Substitution alters only node identities (variables/numbers) without changing edges or operator nodes, maintaining the core algebraic structure and syntactic relationships. This allows the contrastive learning objective to focus on learning invariant structural patterns rather than being confounded by topological noise.
- **Core assumption:** The semantic meaning of a formula is primarily encoded in its graph topology (operator-operand hierarchy, spatial layout) rather than specific variable names or constant values. Swapping these is a benign transformation.
- **Evidence anchors:**
  - [abstract]: "Standard graph augmentations distort mathematical formula graphs by altering critical operators or structure. ... Variable Substitution ... preserves topology by randomly swapping variable and number node identities."
  - [section 3.3]: "This process alters node identities while preserving the graph’s topology."
  - [section 4.4, Figure 2/3]: Consistent, significant performance gains over Node Drop/Edge Drop across both SLT and OPT layouts and all batch sizes.
- **Break condition:** If the variant variable/constant identities themselves carry critical, non-interchangeable semantic weight (e.g., in physics formulas where *c* always denotes the speed of light). The paper does not test this boundary.

### Mechanism 2
- **Claim:** Contrastive learning on mathematical graphs is highly sensitive to augmentation strategy due to the graphs' small size and high semantic density.
- **Mechanism:** In small, dense formula graphs, removing or masking any element (a popular GCL augmentation) has a high probability of destroying a functionally critical component (an operator, a key operand), creating a "negative" example that is not just a differently styled version of the same formula but a *different, invalid, or nonsensical formula*. This teaches the model to discriminate between valid formula structures and noise, not between variations of the same concept.
- **Core assumption:** The success of contrastive learning hinges on the "positive pair" (original and augmented view) representing the *same underlying mathematical concept*. Generic augmentations frequently violate this assumption for formula graphs.
- **Evidence anchors:**
  - [introduction]: "the compact nature of formula graphs means that even seemingly minor alterations ... can drastically distort the formula’s fundamental meaning."
  - [section 2]: "standard graph augmentation techniques ... often struggle with the small size of formula graphs."
  - [section 4.4]: Generic methods (Node Drop, etc.) consistently and significantly underperform Variable Substitution.
- **Break condition:** For extremely large or sparse mathematical graphs (e.g., a full proof tree), removing a node might be less catastrophic. The paper's domain is compact expressions, so this break condition is outside its tested scope.

### Mechanism 3
- **Claim:** A structure-preserving augmentation yields more robust and stable representations, as evidenced by insensitivity to batch size and consistent performance across graph layout types (SLT vs. OPT).
- **Mechanism:** By not corrupting the structural signal, the model's learning objective remains stable and focused. The learned embeddings are therefore less dependent on incidental training dynamics (like the number of negative samples provided by batch size) and more reflective of the inherent graph structure.
- **Core assumption:** Instability in GCL results from noisy augmentation destroying the semantic core of the positive pair. Stabilizing the augmentation stabilizes the learning process.
- **Evidence anchors:**
  - [section 4.4]: "larger batch sizes ... only yield marginal performance gains" and "results are highly stable; ... standard deviations were minimal across all settings."
  - [section 4.4, Figures 2 & 3]: Variable Substitution leads in both SLT and OPT, and its relative advantage is more pronounced in the stricter "full relevance" setting.
- **Break condition:** If model instability were primarily caused by other factors (e.g., optimizer choice, learning rate schedule), fixing augmentation would have little effect. The evidence suggests this is not the primary cause here.

## Foundational Learning
- **Concept: Graph Contrastive Learning (GCL)**
  - **Why needed here:** The entire method is an augmentation technique *for* GCL. You must understand that GCL creates "positive pairs" from two augmented views of the same graph and "negative pairs" from different graphs, training an encoder to pull positives together and push negatives apart.
  - **Quick check question:** If Node Drop creates a graph missing the addition operator from `a + b`, is this a valid "positive view" of the original formula? Why or why not?
- **Concept: Mathematical Formula Graph Representations (SLT vs. OPT)**
  - **Why needed here:** The paper's experiments and claims are anchored to these two specific, domain-standard representations. Understanding their difference (SLT: spatial layout; OPT: operational hierarchy) is crucial to interpret why Variable Substitution might work differently for each.
  - **Quick check question:** Which graph type would likely be more sensitive to swapping a variable `x` with `y` in a formula like `f(x) = x^2`? Why?
- **Concept: The NTCIR-12 Dataset and Bpref Metric**
  - **Why needed here:** This is the evaluation ecosystem. Bpref (binary preference) handles incomplete relevance judgments. The "full" vs. "partial" relevance thresholding directly impacts what "success" means and explains why Variable Substitution's lead is larger under the stricter "full" threshold.
  - **Quick check question:** If a method excels at "full relevance" but not "partial," what does that suggest about its retrieval behavior?
- **Concept: Token Embedding Generator (TEG)**
  - **Why needed here:** It provides the initial node features for the GNN. Its design (random walks + fastText) is a key component of the base model and interacts with the augmentation strategy.
  - **Quick check question:** Why might fastText embeddings from random walks be more suitable for Variable Substitution than one-hot encodings for symbol tokens?

## Architecture Onboarding
**Component map:**  
Input (raw formula) -> Graph Structure Generator (SLT/OPT) -> Token Embedding Generator (random walks + fastText -> 100D node features) -> Graph Contrastive Learning Module (applies Variable Substitution augmentation to create positive views; computes contrastive loss with in-batch negatives) -> Formula Embedding Generator (trained readout function over GNN) -> Online Query Module (cosine similarity ranking)

**Critical path:** The efficacy hinges on **step 4 (Variable Substitution)**. If this augmentation fails to create a valid positive pair (one that preserves semantic equivalence), the entire contrastive signal is corrupted. The TEG (step 3) must produce embeddings that remain meaningful even after variable substitution.

**Design tradeoffs:**
- **Simplicity vs. Expressivity:** Variable Substitution is simple and stable but may be less expressive than learnable augmentations (e.g., SOLA-GCL). The tradeoff is robustness for a narrow, high-stakes domain.
- **Generality vs. Specificity:** The method is exquisitely tailored for formula structure. Its performance on non-mathematical graphs (chemical, program syntax) is an open question; the paper does not test cross-domain transfer.
- **SLT vs. OPT:** The paper shows Variable Substitution works for both, but its advantage is larger for SLT. An engineer must choose the base representation based on the task's need for spatial vs. operational precision.

**Failure signatures:**
1.  No performance gain over Node Drop: Indicates either the implementation of Variable Substitution is flawed (e.g., substituting non-variable nodes), or the specific formula dataset/task does not rely on the preserved topology.
2.  High variance across random seeds: The paper reports low std dev (0.001-0.009). High variance suggests unstable augmentation or fragile training.
3.  Performance degrades with larger batch size: Contrary to the paper's "marginal gains," a drop could indicate the contrastive objective is already saturated or conflicting with other loss components.

**First 3 experiments:**
1.  **Replication of Baseline:** Implement TangentCFT base model + Node Drop augmentation on NTCIR-12. Verify you can reproduce a bpref score within the reported range (~0.52-0.54 for SLT full relevance, Fig 2). This validates your pipeline.
2.  **Ablation - Augmentation Type:** Replace Node Drop with your implementation of Variable Substitution, keeping all else identical (batch size, graph layout, TEG). Measure the delta in bpref. Expect a significant positive jump (~+0.05) for SLT full relevance.
3.  **Robustness Check - Batch Size:** For Variable Substitution only, run with batch sizes 256, 1024, 4096. Confirm performance is stable (std dev <0.01) and does not drastically fall with smaller batches, as reported.

## Limitations
- The evaluation is restricted to a single dataset (NTCIR-12) and a single base model (TangentCFT), limiting generalizability claims.
- The approach assumes variable/constant identities are semantically interchangeable, which may not hold for formulas with conventional symbols (e.g., *c* for speed of light, *i* for imaginary unit); this boundary is untested.
- Exact implementation details (hyperparameters, aggregation methods) are unreported, hindering precise replication.

## Confidence
- **High:** Variable Substitution outperforms generic augmentations (Node/Edge Drop) on NTCIR-12; results are stable across layouts and batch sizes.
- **Medium:** Claim that topology preservation is the primary mechanism—untested boundary cases where variable identity carries critical semantics.
- **Low:** Generalization claims beyond compact formula graphs (e.g., to large proof trees) or to other base models/datasets lack evidence.
