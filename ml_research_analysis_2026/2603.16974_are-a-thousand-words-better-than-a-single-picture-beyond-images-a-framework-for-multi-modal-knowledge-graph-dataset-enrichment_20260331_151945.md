# Are a Thousand Words Better Than a Single Picture? Beyond Images -- A Framework for Multi-Modal Knowledge Graph Dataset Enrichment

## Quick Facts
- **arXiv ID:** 2603.16974
- **Source URL:** https://arxiv.org/abs/2603.16974
- **Reference Count:** 40
- **Primary Result:** An automatic pipeline that converts images to text and fuses descriptions yields consistent link prediction gains up to +7% Hits@1 and dramatic improvements (+201% MRR) on entities with ambiguous logo/symbol images.

## Executive Summary
Multi-Modal Knowledge Graphs (MMKGs) often suffer from limited visual coverage and struggle with ambiguous yet relevant images like logos. This paper introduces "Beyond Images," a fully automatic, model-agnostic pipeline that enriches MMKG entities by retrieving additional web images, captioning all visuals (original and new) using off-the-shelf models, and fusing these captions into a single coherent summary via an LLM. This textual summary replaces or augments the original entity text, requiring no changes to downstream model architectures. Evaluated across three datasets and four MMKG models, the approach delivers consistent performance improvements, with particularly dramatic gains on challenging entities where direct visual processing fails.

## Method Summary
The framework comprises three sequential modules. First, the **Modality Extension Module** uses entity names or QIDs to crawl English Wikipedia, retrieving all associated images to scale visual coverage. Second, the **Semantic Generation Module** applies three image captioning models (BLIP2, GIT, LLaVA) to every retrieved and original image, generating a descriptive sentence per image. Third, the **LLM-based Semantic Fusion Module** inputs all captions for an entity into an instruction-tuned LLM (e.g., Mistral) with a fixed prompt, producing a single consolidated, entity-aligned paragraph. This final text summary is then used in place of the original entity description during MMKG model training and evaluation.

## Key Results
- Consistent improvements in link prediction across three datasets (MKG-W, MKG-Y, DB15K) and four models (MyGO, NativE, MMRNS, AdaMF), with gains up to **+7% Hits@1**.
- On a challenging subset of entities with ambiguous logo/symbol images, converting images to text yields **+201.35% MRR** and **+333.33% Hits@1**.
- LLM-based fusion of captions consistently outperforms simple concatenation, demonstrating the value of semantic summarization.

## Why This Works (Mechanism)
### Mechanism 1: Scaling Visual Coverage via Automated Retrieval
The claim is that large-scale, automatic image retrieval addresses the scalability limitation of manual MMKG curation. The mechanism uses entity names to crawl Wikipedia, downloading all associated images and metadata in bulk. This replaces manual per-entity searching with a programmable operation. The core assumption is that Wikipedia provides sufficiently comprehensive and relevant images for most public MMKG entities. Evidence includes the substantial increases in total images and entities with images reported across datasets, and the methodology description in Section 3.1. A break condition occurs if Wikipedia lacks images for an entity or retrieved images are semantically irrelevant (e.g., maps for a person).

### Mechanism 2: Converting Ambiguous Visuals to Explicit Text
The claim is that transforming all images, including ambiguous logos/symbols, into textual descriptions converts weak visual signals into usable semantic features. The mechanism applies three off-the-shelf image-to-text models (BLIP2, GIT, LLaVA) to every image, generating a descriptive sentence with a fixed prompt. The core assumption is that these models produce sufficiently accurate and entity-relevant descriptions even for sparse-semantic visuals. Evidence includes the abstract's statement on converting visuals to text, the Section 3.2 description, and an example where BLIP2 identifies "Beastie Boys" from an album cover logo. Break conditions include model failure on highly abstract or culturally specific visuals, producing irrelevant or hallucinated descriptions.

### Mechanism 3: LLM-Based Summarization for Noise Reduction and Entity Alignment
The claim is that fusing multiple per-image captions into a single, coherent summary using an LLM filters out task-irrelevant content and redundancy. The mechanism collects all captions for an entity, feeds them to an instruction-tuned LLM with a prompt to integrate them into one rich paragraph about the entity. The core assumption is that LLMs can distill, filter, and reorganize captions to preserve relation-relevant details while discarding visual fluff. Evidence includes the abstract's description, the Section 3.3 prompt and model details, and Table 2 showing "Fusion" outperforming concatenation. A break condition is the LLM generating summaries that hallucinate facts, omit key details, or drift from entity semantics, heavily influenced by prompt design.

## Foundational Learning
- **Concept: Multi-Modal Knowledge Graphs (MMKGs)**
  *Why needed:* The framework operates on MMKGs, which combine structured triples with non-textual modalities. Understanding their structure and link prediction task is essential.
  *Quick check:* Given an MMKG triple and entity images, what does the model learn from image embeddings versus the textual description?
- **Concept: Image-to-Text (Captioning) Models**
  *Why needed:* Converting ambiguous images to text is the core innovation. Knowing how models like BLIP2 or LLaVA work explains the choice and potential failure modes.
  *Quick check:* How might a captioning model's training data affect its ability to describe a corporate logo?
- **Concept: Large Language Model (LLM) Instruction Following**
  *Why needed:* The fusion step relies on an LLM to follow a specific summarization prompt. Understanding instruction tuning, context limits, and output control is key to predicting summary quality.
  *Quick check:* What risks arise if the LLM's prompt does not constrain output to entity-specific facts?

## Architecture Onboarding
- **Component map:** Entity list -> Modality Extension (retrieve images) -> Semantic Generation (caption images) -> LLM-based Semantic Fusion (summarize captions) -> Entity summary -> Downstream MMKG model (unchanged)
- **Critical path:** Entity list triggers bulk Wikipedia crawl; retrieved images are captioned in parallel by three models; all captions per entity are fed to an LLM for fusion; the summary file is loaded by the standard MMKG training script.
- **Design tradeoffs:**
  - *Data-side vs. model-side:* Modifies dataset, not models, ensuring broad compatibility but relies on external model quality.
  - *Automation vs. control:* Fully automatic pipeline vs. optional human audit interface; tradeoff between scalability and description fidelity.
  - *Coverage vs. noise:* Retrieving more images increases diversity but also increases chance of irrelevant images, requiring robust captioning/fusion.
- **Failure signatures:**
  - **Retrieval failure:** Low image count per entity after crawling; indicates Wikipedia coverage gap.
  - **Captioning failure:** High rate of nonsensical or empty captions; suggests captioning model mismatch.
  - **Fusion failure:** LLM summaries contain hallucinations or omit key entity attributes; detectable via human audit interface.
  - **Downstream degradation:** MMKG model performance drops on enriched data; likely due to noisy summaries.
- **First 3 experiments:**
  1. **Sanity check on small subset:** Run full pipeline on 10 diverse entities; manually inspect images, captions, and summaries for factual grounding.
  2. **Captioning model ablation:** On a fixed entity set, generate captions with each of the three models; compare caption quality and downstream Hits@1 using MyGO on MKG-W to identify the best backbone.
  3. **Fusion ablation:** For a single entity, compare concatenated captions vs. LLM summaries from Mistral, LLaMA, and Flan-T5; evaluate summary coherence via human spot-check and measure MRR change.

## Open Questions the Paper Calls Out
- How can temporal signals (e.g., timestamps, versioned descriptions) be integrated to model entity evolution and improve link prediction for time-sensitive facts?
- To what extent does the choice of prompt for image captioning and the granularity of descriptions impact the quality of the final LLM-fused summary and downstream performance?
- Why do different MMKG model architectures exhibit varying degrees of reliance on raw image embeddings versus generated text descriptions, and what architectural modifications could maximize the benefit of the enriched textual modality?
- Can the optional human-auditing interface be optimized into an active learning loop to maximize description quality improvement per unit of human annotation effort, and what is the cost-benefit trade-off?
- Does the pipeline's effectiveness generalize beyond English-centric corpora and Western-dominated image datasets when using multilingual captioning models and fusion LLMs?

## Limitations
- **Scalability assumption:** Relies on Wikipedia having sufficient images for all entities; performance likely degrades for niche or non-notable entities.
- **Captioning generalization:** Heavy reliance on BLIP2/GIT/LLaVA; unverified performance on culturally specific or abstract symbols beyond provided examples.
- **LLM fusion hallucination risk:** No systematic evaluation of factual drift in fused summaries; the human audit interface is optional and unreported in main results.

## Confidence
- **Overall Gains (+7% Hits@1):** High – Consistent across 3 datasets/4 models with clear ablation.
- **Ambiguous Image Improvement (+201% MRR):** Medium – Strong subset results but subset size/definition unspecified.
- **Mechanism Validity (Retrieval → Caption → Fusion):** Medium – Component-wise evidence exists but end-to-end causality not fully disentangled.
- **Architecture-Neutrality:** High – Modular design validated by testing multiple downstream models unchanged.

## Next Checks
1. **Caption Quality on Ambiguous Modalities:** Manually evaluate 100 logo/symbol images from the challenging subset; measure entity name recall and relevance in captions from each model. Failure if <50% captions correctly describe the symbol.
2. **Fusion Hallucination Audit:** Sample 200 fused summaries; annotate for invented relations/facts vs. verifiable from source captions. Failure if >10% contain ungrounded claims.
3. **Retrieval Coverage Stress Test:** For 500 random entities across datasets, compute Wikipedia image availability. Failure if >15% entities yield <2 relevant images post-filtering.
