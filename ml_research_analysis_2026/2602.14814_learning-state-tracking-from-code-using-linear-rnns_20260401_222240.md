# Learning State-Tracking from Code Using Linear RNNs

## Quick Facts
- **arXiv ID:** 2602.14814
- **Source URL:** https://arxiv.org/abs/2602.14814
- **Reference count:** 40
- **Primary result:** Linear RNNs (DeltaNet with extended eigenvalue range [-1,1]) learn state-tracking from code REPL traces with sparse supervision, while Transformers fail; probabilistic code execution reveals inherent instability in linear RNNs due to exponential norm decay under finite precision, which nonlinear RNNs can mitigate.

## Executive Summary
The paper tackles state-tracking in code, a fundamental capability for language models to understand program semantics. It introduces a benchmark that transforms permutation composition tasks into Python REPL traces, interleaving variable swaps with `print` statements that partially reveal the current permutation state. This bridges the gap between standard state-tracking tasks and next-token prediction, providing dense supervision while remaining realistic. Experiments compare Transformers and linear RNNs (DeltaNet). Results show that DeltaNet, when equipped with an extended eigenvalue range [-1,1], reliably learns to track permutations even with sparse reveals and generalizes to longer sequences; Transformers degrade as reveal spacing increases. Theoretical analysis via a Probabilistic Finite-State Automaton model reveals that for stochastic code execution with partial observations, linear RNNs suffer exponential norm decay in their unnormalized state representation under finite precision, while nonlinear RNNs can maintain stability through normalization. This work thus demonstrates both the potential of tailored linear architectures for deterministic state-tracking and a fundamental limitation in stochastic settings.

## Method Summary
The authors generate synthetic Python REPL traces representing permutations of five variables. Each trace consists of a sequence of swap commands (e.g., `a, b = b, a`) and `print` statements that output the current cumulative permutation. The reveal spacing `s` determines how many swaps occur between successive prints. Models are trained via next-token prediction to reproduce the transcript, so at each step the target is the correct next token (either a command or the printed state). Training follows a four-stage curriculum with increasing sequence lengths (8, 16, 32, 64) and reveal spacings (1, 2, 4, 8). Two architectures are compared: a Transformer and DeltaNet, a linear RNN where the state-transition matrix is `A = I - β k k^⊤`. Crucially, DeltaNet is tested with two eigenvalue ranges: `[0,1]` (β in [0,1]) and `[-1,1]` (allowing β>1). The primary metric is scaled accuracy at reveal positions, and models are evaluated on longer sequences (128 steps) and varying spacings to test extrapolation.

## Key Results
- DeltaNet with eigenvalues [-1,1] achieves high scaled accuracy on permutation state-tracking across all reveal spacings and generalizes to sequences of 128 commands, while Transformer accuracy degrades sharply with increased spacing and fails on full permutations.
- An interpretability analysis reveals a specific attention head in DeltaNet that uses β=2 to produce an eigenvalue of -1, enabling operations necessary for odd permutations.
- Theoretical analysis shows that for probabilistic state-tracking (modeled as PFSA-SR), linear RNNs experience exponential norm decay in the unnormalized state under finite precision due to partial reveals, whereas nonlinear RNNs avoid this by performing normalization internally.

## Why This Works (Mechanism)

### Mechanism 1: REPL Trace Dense Supervision
The conversion of permutation composition into Python REPL traces with interleaved `print` statements provides dense, partial supervision. Each print reveals a subset of the cumulative state, turning a sequence-to-state mapping into a sequence-to-sequence problem where the target at each position is the revealed partial state. This aligns with the autoregressive training objective and gives the model multiple learning signals along the sequence. The model must accumulate and update an internal representation of the full state between reveals, using the partial information to correct errors. The reveal spacing controls difficulty; when spacing exceeds the model's effective memory, accuracy drops. Evidence: the abstract and Section 4 describe the trace generation; Figure 3 shows Transformer accuracy degrading with increased spacing.

### Mechanism 2: Extended Eigenvalue Spectrum Enables Permutation Primitives
The DeltaNet recurrence `A = I - β k k^⊤` yields eigenvalues `1` (multiplicity n-1) and `1-β`. Restricting `β ∈ [0,1]` limits eigenvalues to `[0,1]`, which only implements forgetting or averaging. Allowing `β > 1` yields eigenvalues below 0, supporting sign flips needed for odd permutations (determinant -1). A learned head sets `β=2` to achieve eigenvalue -1, enabling a specific permutation primitive. Evidence: The abstract states the eigenvalue extension enables tracking; Section 3 details the parameterization; Section 4.1 shows only `DeltaNet[-1,1]` learns, while `[0,1]` fails; Figure 5 identifies a head with β=2.

### Mechanism 3: Nonlinear Normalization Requirement for Probabilistic State-Tracking
For code with unobservable branches, state transitions become probabilistic. The true belief state `b_t` (a probability vector) updates as `h_{t+1} = T_σ Z_σ h_t` followed by nonlinear normalization `x/||x||_1`. A linear RNN stores `h_t` without normalization, so partial reveals (via `Z_σ`) prune probability mass and the `B` term cannot replenish all entries adaptively. This leads to exponential norm decay `||h_t|| ~ Π s_k` where `s_k < 1` are survival probabilities, causing eventual underflow in finite precision. Nonlinear RNNs can incorporate normalization internally, maintaining stability. Evidence: The abstract mentions the decay; Section 5 introduces PFSA-SR, derives the decay, and shows Figures 9-10; Section 5.3 notes adversarial sequences force decay.

## Architecture Onboarding

### Component map
Input Encoding (token → k_t, v_t, β_t, q_t) → State Update (H_t = A(x_t) H_{t-1} + B(x_t), with A = I - β_t k_t k_t^⊤, B = β_t k_t v_t^⊤) → Output Decoder (ŷ_t = dec(H_t, q_t)). The Eigenvalue Controller is the subnetwork that produces β_t.

### Critical path
1. State representation: A middle-layer head in DeltaNet (e.g., Layer 12, Head 3) uses β=2 to manipulate state signs.
2. Update propagation: Between reveals, A (with extended eigenvalues) permutes state vectors correctly.
3. Replenishment on reveal: During a print, B injects high probability into entries corresponding to the printed values, counteracting decay.

### Design tradeoffs
- Expressivity vs. parallelizability: Linear RNNs (DeltaNet) are parallelizable but require specific eigenvalue design; nonlinear RNNs (LSTMs) can normalize but are slower.
- Joint vs. marginal representation: Full n!-dimensional belief is precise but unstable; n×n marginal is more efficient and replenishable but still prone to decay under adversarial reveals.
- Supervision density: Dense reveals ease learning; sparse reveals test long-term memory.

### Failure signatures
- Transformer: Accuracy drops sharply as reveal spacing s increases; learns shortcuts relying on immediate context.
- DeltaNet[0,1]: Cannot learn at all, fails to represent sign-flip operations.
- DeltaNet[-1,1] under probabilistic transitions: Performance degrades on PFSA-SR tasks; hidden failure: exponential norm decay in unnormalized state, causing collapse on long/adversarial sequences.
- Numerical instability: Extreme state norm growth/shrinkage during training if β>1 used without scaling.

### First 3 experiments
1. **Replication:** Train DeltaNet[0,1], DeltaNet[-1,1], and Transformer on S_5 REPL traces with spacing 1. Expect DeltaNet[-1,1] to converge >95% accuracy; others fail.
2. **Ablation:** For trained DeltaNet[-1,1], clamp β per head to [0,1] and identify the critical head(s) whose restriction causes accuracy drop (expected: head with β≈2).
3. **Adversarial test:** Generate a PFSA-SR sequence for n=3 with alternating probabilistic swap (elements 2 & 3) and a reveal confirming element 2. Run DeltaNet[-1,1] and measure norm of the unrevealed element's state component; expect exponential decay.

## Open Questions the Paper Calls Out

### Open Question 1: Generalization to Real-World Code
**Question:** Does the superior performance of linear RNNs with extended eigenvalues on synthetic permutation REPL traces generalize to real-world code execution tasks?
**Basis in paper:** The Conclusion explicitly states that experiments focus on synthetic permutations rather than real-world code, simplifying away parsing, control flow, and memory management.
**Why unresolved:** Real code introduces complexities (nested control structures, scoping, dynamic memory) that may alter state-tracking dynamics; current evaluation uses idealized, uniform random permutations and controlled reveals.
**What evidence would resolve it:** Apply the REPL trace methodology to real code datasets (e.g., CRUXEval or system call logs), convert actual executions into traces with strategic print statements, and compare linear RNNs vs. Transformers on scalability and generalization.

### Open Question 2: Hybrid Linear-Nonlinear Architectures
**Question:** Can interleaving linear recurrence with periodic nonlinear normalization stabilize linear RNNs for probabilistic state-tracking while maintaining computational efficiency?
**Basis in paper:** Future Work mentions investigating hybrid architectures that interleave linear recurrence with periodic nonlinear normalization similar to TTT and Titans.
**Why unresolved:** The theoretical analysis shows linear RNNs suffer exponential decay under probabilistic state-tracking; hybrids could mitigate this, but their design space, impact on parallelization, and effectiveness are unknown.
**What evidence would resolve it:** Construct specific hybrid models (e.g., DeltaNet with inserted normalization layers every k steps), train them on PFSA-SR tasks with adversarial reveal sequences, and evaluate stability, accuracy, and computational overhead.

### Open Question 3: Nonlinear RNNs on Probabilistic Benchmarks
**Question:** How do nonlinear RNN architectures (e.g., LSTMs, GRUs, modern gated RNNs) compare to linear RNNs on the PFSA-SR benchmark for probabilistic state-tracking?
**Basis in paper:** The abstract and Introduction note that linear RNNs can be worse than nonlinear RNNs at tracking states in probabilistic setups, and probabilistic state-tracking is a promising benchmark for evaluating nonlinear RNNs.
**Why unresolved:** The study only compared linear RNNs and Transformers; nonlinear RNNs were discussed theoretically but not empirically tested on the PFSA-SR framework.
**What evidence would resolve it:** Train standard nonlinear RNNs (LSTMs, GRUs) and recent nonlinear parallelizable RNNs on PFSA-SR tasks, measure belief tracking ability, norm stability, and generalization under adversarial conditions.

## Limitations
- **Implementation details:** The exact parameterization in the `flash-linear-attention` codebase for achieving the `[-1,1]` eigenvalue range in DeltaNet, and the mapping from permutation state to `print` output tokens, are not fully specified, risking replication mismatches.
- **Task generality:** Results are demonstrated on synthetic, fully deterministic permutation tasks; it is unclear whether they generalize to real-world code with complex control flow, I/O, and non-permutation operations.
- **Stability & scale:** The theoretical exponential norm decay for linear RNNs in probabilistic settings is derived from simplified models; its practical impact on longer, realistic code sequences and potential mitigations (e.g., gating) remain uncertain.

## Confidence
- **Core empirical result** (DeltaNet[-1,1] succeeds, Transformer fails on permutation REPL traces): High.
- **Mechanism: Extended eigenvalues enable permutation tracking** (interpretability of β=2 head): Medium.
- **Theoretical limitation: Linear RNNs fail on probabilistic belief updates** (exponential norm decay under partial reveals): Medium.
