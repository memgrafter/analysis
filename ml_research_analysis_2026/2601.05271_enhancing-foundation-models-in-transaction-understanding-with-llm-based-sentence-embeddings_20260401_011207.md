# Enhancing Foundation Models in Transaction Understanding with LLM-based Sentence Embeddings

## Quick Facts
- arXiv ID: 2601.05271
- Source URL: https://arxiv.org/abs/2601.05271
- Reference count: 5
- Primary result: A hybrid framework using offline LLM-generated sentence embeddings to initialize categorical field embeddings in a lightweight transformer model improves transaction prediction tasks on a billion-transaction dataset, with up to +3.93% relative improvement and no runtime LLM cost.

## Executive Summary
The paper tackles semantic information loss in foundation models for transaction data caused by index-based representations of categorical merchant fields. It introduces a hybrid framework where LLM-generated sentence embeddings are precomputed offline and used to initialize the embedding layers for merchant name, MCC, and location in a transformer-based model. This injects rich semantic knowledge while preserving production efficiency, as online serving only requires a simple lookup. Enriching raw transaction fields with multi-source data and constraining LLM prompts to one-word outputs yields consistent, high-quality embeddings. Evaluated on a billion-transaction dataset, the method consistently outperforms a vanilla ID-based model across regression (next amount) and classification (next MCC/location/merchant) tasks, as well as a proprietary metric.

## Method Summary
The proposed solution decouples semantic enrichment from real-time inference. First, raw categorical fields (merchant name, MCC, location) are enriched by joining with external databases (e.g., MCC descriptions, geo-data). These enriched texts are fed into a structured prompt with a one-word constraint (e.g., "This sentence: '[enriched text]' means in one word:"). An LLM (e.g., Llama3-8b) processes each prompt, and the final non-padding token's hidden state is extracted, normalized, and stored as the embedding for that categorical value. During model training, a foundation transformer model (based on Yeh et al., 2025) loads these precomputed vectors as initial weights for the corresponding embedding layers, rather than random initialization. The model is then trained on sequential transaction data via multi-task learning. At inference time, the system simply looks up the precomputed embeddings, avoiding any LLM call.

## Key Results
- Consistent performance gains over ID-based baselines across tasks: reduced MAE for next amount prediction, higher accuracy/F1 for next MCC/location/merchant prediction, and up to +3.93% relative improvement on a proprietary transaction metric.
- Llama3-8b embeddings and initializing all three categorical fields (merchant, MCC, location) yielded the most robust improvements.
- The hybrid approach maintains production scalability, as LLM inference is amortized offline and online serving remains a lightweight transformer forward pass.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Offline precomputation of LLM-generated sentence embeddings and their use as weight initializations for categorical field embedding layers injects semantic world knowledge into a lightweight transaction model, mitigating the semantic information loss caused by traditional index-based categorical representations.
- **Mechanism:** The foundation model normally learns embeddings for categorical fields from random initialization, capturing only co-occurrence patterns (collaborative filtering signals). This paper replaces random initialization with vectors derived from an LLM's hidden states, which encode richer semantic relationships (e.g., "Costco" shares meaning with "wholesale retailer"). During fine-tuning, the model starts from a semantically informed point, requiring fewer updates to learn meaningful representations and generalizing better to cold-start or sparse categorical values.
- **Core assumption:** The semantic relationships encoded in a static, pre-trained LLM's embedding space are relevant and beneficial for the downstream transaction understanding tasks.
- **Evidence anchors:** 
  - [abstract] "...uses LLM-generated embeddings as semantic initializations... leverages LLM semantic understanding while maintaining production efficiency."
  - [section 3.4.1] "This initialization provides... immediate access to semantic relationships encoded by LLMs, reduced training time... and improved generalization to unseen categorical values."
  - [corpus] Neighbor papers establish context of LLMs for transactional tasks but do not directly evidence *this specific initialization mechanism*. The evidence is **weak**; the mechanism is inferred from architecture and results.
- **Break condition:** If the pre-trained LLM's semantic space is misaligned with transactional objectives (e.g., over-emphasizes linguistic semantics irrelevant to financial behavior), initializations could hinder learning or require significantly longer fine-tuning to override.

### Mechanism 2
- **Claim:** A structured pipeline of multi-source data fusion followed by a constrained "one-word limitation" prompt design generates more consistent, context-rich, and noise-resistant LLM embeddings for categorical fields compared to naively prompting the raw text.
- **Mechanism:** Raw transactional data is sparse (e.g., "365 MARKET"). Multi-source fusion enriches each record with external, structured context (e.g., linking merchant name to its official MCC, location geo-data). The one-word prompt forces the LLM to distill the fused context into a compact, focused semantic representation. The embedding is extracted from the final hidden state of this constrained output, reducing variance from verbose or irrelevant generations.
- **Core assumption:** The distilled, single-word-focused output from an LLM, when primed with enriched contextual data, produces a more stable and semantically anchored sentence embedding than an unconstrained summary of the raw text.
- **Evidence anchors:**
  - [abstract] "Our approach employs multi-source data fusion to enrich merchant categorical fields and a one-word constraint principle for consistent embedding generation."
  - [section 3.2.1] "Initial experiments with simple, single-source prompts... yielded suboptimal results... This motivated our multi-source fusion approach..."
  - [section 3.2.2] "To ensure consistency and reduce noise... we implement an explicit one-word limitation principle..."
  - [corpus] **Missing/weak.** No neighbor paper directly validates this specific prompt engineering method. The principle is cited from prior work on scaling sentence embeddings, but its application here is novel and unevidenced in the cited corpus.
- **Break condition:** The one-word constraint may oversimplify complex categorical entities, discarding nuance critical for specific tasks. If the fused context contains noise or errors, the constrained prompt will consistently propagate that noise.

### Mechanism 3
- **Claim:** The decoupled, hybrid architecture (offline LLM embedding generation + online lightweight transformer model) achieves a Pareto frontier of semantic richness and production efficiency, enabling deployment at billion-transaction scale where full LLM inference is infeasible.
- **Mechanism:** The computational bottleneck of running an LLM for every transaction in real-time is prohibitive. By precomputing embeddings for all unique categorical values *once* offline and storing them as a static lookup table, the online serving path only requires a simple embedding layer lookup. The model's transformer backbone remains unchanged and efficient. The semantic "boost" is thus a one-time computational cost amortized across all future inferences of that categorical value.
- **Core assumption:** The semantic meaning of a merchant is static enough that a pre-trained, offline-generated embedding remains valid for the model's entire deployment lifetime without needing frequent refreshes.
- **Evidence anchors:**
  - [abstract] "While Large Language Models (LLMs) can address this limitation through superior semantic understanding, their computational overhead challenges real-time financial deployment."
  - [section 1] "Unlike end-to-end LLM methods... our framework precomputes semantic embeddings offline... This design preserves semantic richness and sequential context while meeting the latency and scalability requirements..."
  - [section 3.1] "By precomputing embeddings for selected attributes offline, we decouple the semantic enrichment phase from the inference pipeline."
  - [corpus] Neighbors discuss scalable ML for transactions, supporting the *need* for efficiency, but not this *specific* hybrid mechanism. Evidence is **contextual**.
- **Break condition:** If merchant semantics drift significantly over time (e.g., a merchant changes business type), the static precomputed embeddings become stale, degrading performance unless a costly re-embedding pipeline is triggered.

## Foundational Learning
### Concept: Sequential Tabular Modeling
- **Why needed here:** The foundation model processes a user's transaction *sequence* (ordered by time), not isolated rows. It must capture temporal dependencies (e.g., a user's pattern of grocery shopping followed by dining) to predict the next transaction. This differs from static tabular classification.
- **Quick check question:** How does the model's use of time-aware position embeddings differ from standard transformer positional encoding, and why is this critical for transaction data with irregular time gaps?

### Concept: Categorical Embedding Strategies (ID-based vs. Semantic)
- **Why needed here:** The core problem is replacing ID-based embeddings (which learn from co-occurrence) with semantically initialized embeddings. Understanding the limitations of pure ID-based embeddings (cold-start, no world knowledge) is key to grasping the paper's motivation.
- **Quick check question:** What is a concrete example of a "cold-start" problem for a new merchant that an ID-based embedding would struggle with, but an LLM-initialized embedding might handle better?

### Concept: Transfer Learning via Weight Initialization
- **Why needed here:** The paper does not fine-tune the LLM; it transfers knowledge by initializing a *different* model's weights. This is a specific form of transfer learning where the source (LLM) and target (transaction model) architectures differ.
- **Quick check question:** Why is simply *concatenating* an LLM embedding as an additional feature to an ID embedding potentially less effective than *initializing the entire embedding layer* with the LLM vector?

## Architecture Onboarding
### Component map
Data Ingestion & Fusion (raw transactions + external DBs) -> Prompt Generation (field-specific templates with one-word constraint) -> Offline Embedding Service (batch LLM inference, extract last token hidden state, store in KV store) -> Model Training (load precomputed vectors into embedding layers of TREASURE model, train on sequences) -> Online Serving (lookup embeddings, forward pass through trained model). The offline embedding generation is the critical setup path.

### Critical path
Data Fusion -> Prompt Generation -> Offline Embedding Generation (One-time bulk job) -> Model Training (with embedding lookup) -> Online Serving (Lookup + Forward Pass). The offline embedding generation is the critical path for deployment setup.

### Design tradeoffs
- Static vs. Dynamic Embeddings: Static precomputation is efficient but cannot capture semantic drift. A periodic re-embedding job (e.g., monthly) trades freshness for compute cost.
- LLM Choice vs. Cost: Larger LLMs (Llama2-13b) may yield better semantics but increase offline compute/storage (~4KB per merchant for 1024-dim float32). Smaller models are cheaper but may underperform.
- Prompt Complexity vs. Consistency: Richer prompts (with more context) may yield better embeddings but increase token count/LLM cost. The one-word constraint ensures consistency but may lose nuance.

### Failure signatures
- **Task-Specific Degradation:** Performance drops specifically on next-merchant/MCC prediction while amount/location prediction remains stable, suggesting LLM embeddings failed to capture discriminative merchant semantics.
- **Training Instability:** Loss diverges or model fails to converge when initialized with LLM embeddings, indicating a severe mismatch between LLM output space and model's expected embedding distribution.
- **Stale Embedding Impact:** A/B test shows performance decay over time for merchants whose business model changed (e.g., a restaurant that became a grocery store), while ID-based baseline is less affected.

### First 3 experiments
1. **Single-Field Ablation:** Train models initializing *only* MCC, *only* merchant, and *only* location. Measure delta vs. Vanilla on respective prediction tasks (next MCC, next merchant, next city) to isolate each field's impact.
2. **LLM Architecture Sweep:** For a fixed initialization strategy (e.g., All Fields), compare Llama2-7b, Llama2-13b, Llama3-8b, Mistral-7b to validate robustness of gains and identify optimal model size/type.
3. **Prompt Stress Test:** For a single field (e.g., merchant), compare three prompt designs: (a) Raw name only, (b) Name + MCC (multi-source), (c) Name + MCC + one-word constraint. Evaluate resulting embeddings via a probe task (e.g., linear classifier on merchant embeddings to predict MCC) to validate fusion and constraint principles.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Can more sophisticated prompt engineering or domain-specific fine-tuning of LLMs enhance the semantic representation quality for financial transaction fields beyond the current one-word constraint approach?
- **Basis in paper:** The "Limitations" section cites "Prompt Engineering Sophistication": the one-word limitation is a simple approach and more sophisticated optimization or domain-specific fine-tuning could enhance quality.
- **Why unresolved:** The paper does not explore advanced prompting (e.g., chain-of-thought, few-shot) or fine-tuning LLMs on financial corpora compared to static, constrained prompts.
- **What evidence would resolve it:** Systematic study comparing current one-word prompts against (a) automatically optimized prompts and (b) embeddings from LLMs fine-tuned on financial text/transaction descriptions, evaluated on downstream tasks and embedding quality metrics.

### Open Question 2
- **Question:** Would integrating state-of-the-art, specialized sentence embedding models (e.g., NV-Embed, Qwen3-embedding) as alternatives to general-purpose LLMs provide further performance gains in this hybrid framework?
- **Basis in paper:** The "Limitations" section under "Model Coverage": evaluation focused on established LLM architectures and did not include recent specialized sentence embedding models; testing these could yield improvements.
- **Why unresolved:** Experiments were constrained to a specific set of open-source LLMs. Specialized embedding models are optimized for high-quality sentence vectors and might be more suitable than decoder-only LLMs in a zero-shot prompting setup.
- **What evidence would resolve it:** Re-run core experiments by replacing the LLM embedding source with leading specialized embedding models. Compare performance to determine if they offer superior semantic initialization.

### Open Question 3
- **Question:** To what extent does the proposed framework generalize to other categorical fields in transaction data beyond merchant name, MCC, and location (e.g., transaction channel, payment method, currency)?
- **Basis in paper:** The "Limitations" section under "Categorical Field Scope": framework currently addresses MCC, merchant, and location, but not other fields like channels, payment methods, or temporal patterns; generalizability remains unvalidated.
- **Why unresolved:** Efficacy is demonstrated only for three specific field types. Other fields may have different semantic richness or might rely more on ID-based collaborative signals.
- **What evidence would resolve it:** Extend the pipeline to one or more new categorical fields (e.g., transaction channels). Evaluate impact on downstream tasks to see if improvements are consistent, diminished, or negative.

### Open Question 4
- **Question:** How can the framework's static, offline-generated embeddings be adapted to capture temporal dynamics, such as evolving merchant characteristics, seasonal business changes, or shifting market conditions?
- **Basis in paper:** The "Limitations" section under "Static Embedding Approach": current framework generates embeddings offline and does not account for evolving merchant characteristics or dynamic market conditions; this static approach may limit capturing temporal semantic changes.
- **Why unresolved:** Embeddings are precomputed once and frozen. In reality, a merchant's business model or a location's economic profile can change, which a static embedding might misrepresent over time.
- **What evidence would resolve it:** Propose and evaluate a dynamic embedding strategy, e.g., periodic re-embedding (quarterly) or a mechanism where the foundation model conditionally adjusts the initial embedding based on temporal context or recent transaction history. Success measured by improved performance on time-sensitive tasks.

## Limitations
- Architecture details of the foundation model (Yeh et al., 2025) are missing, hindering exact replication (e.g., transformer configuration, time-aware positional encoding).
- Prompt engineering specifics (exact templates, fusion logic) are not fully described, relying on illustrative examples.
- Static precomputed embeddings risk staleness as merchant semantics drift over time; no mechanism for updates is provided.
