# CREAM: Continual Retrieval on Dynamic Streaming Corpora with Adaptive Soft Memory

## Quick Facts
- **arXiv ID:** 2601.02708  
- **Source URL:** https://arxiv.org/abs/2601.02708  
- **Reference count:** 40  
- **Primary result:** CREAM outperforms the strongest unsupervised baseline by 27.79% in Success@5 and 44.5% in Recall@10 on average, achieving performance comparable to or exceeding supervised methods.

## Executive Summary
CREAM tackles the challenge of continual information retrieval in dynamic, unlabeled streaming corpora—settings where traditional retrieval systems fail due to distribution shifts and lack of ground-truth labels. It introduces an adaptive soft memory mechanism that enables self-supervised learning through three core techniques: fine-grained token-level similarity estimation, regularized cluster prototyping via RP-LSH, and stratified coreset sampling. Evaluated on LoTTE and MSMARCO benchmarks, CREAM achieves substantial gains over unsupervised baselines and matches or surpasses supervised approaches, demonstrating the viability of unsupervised continual retrieval.

## Method Summary
CREAM maintains a dynamic soft memory that incrementally clusters streaming documents using summary statistics (count, linear sum, squared sum) and RP-LSH-based prototypes. For each new instance, it assigns to the nearest cluster if within a scaled distance threshold; otherwise, it creates a new cluster. The memory is regularly pruned via an eviction rule to prevent bloat. For self-supervised encoder updates, CREAM samples queries proportionally to cluster sizes and selects a coreset maximizing document coverage within each cluster. It then forms contrastive pairs: the top-1 retrieved document as positive and bottom-(k-1) from top-K clusters as negatives. The encoder is trained with a contrastive loss. At inference, retrieval uses token-level ColBERT-style late interaction between the query and candidate documents from the nearest clusters.

## Key Results
- **Significant gains:** Average improvement of 27.79% in Success@5 and 44.5% in Recall@10 over the strongest unsupervised baseline.
- **Supervised-competitive:** Performance matches or exceeds supervised methods on both LoTTE and MSMARCO under shared/disjoint protocols.
- **Ablation impact:** Removing fine-grained similarity or the soft memory structure causes the largest performance drops (e.g., -18.08% S@5 without soft memory).

## Why This Works (Mechanism)
### Mechanism 1: Fine-grained token-level similarity estimation
- **Claim:** Fine-grained token-level similarity estimation enables robust relevance scoring under distribution shifts by preserving granular semantic information.
- **Mechanism:** Instead of mean-pooling representations, CREAM computes the sum of maximum cosine similarities between each query token and all document tokens (ColBERT-style late interaction). This captures fine-grained matching signals that single-vector similarity misses.
- **Core assumption:** Token-level interactions are necessary to detect subtle contextual shifts (e.g., "agent" meaning drug vs. person) without explicit labels.
- **Evidence anchors:** 
  - [abstract] "three core techniques: fine-grained similarity estimation"
  - [section 4.1] Equation (5) and statement: "we adopt a token-level similarity approach inspired by ColBERT's late interaction to preserve the semantic granularity."
  - [section 5.4] Ablation shows dramatic drop when removed.
- **Break condition:** Extreme token length mismatches could make computation prohibitive without approximation (addressed by RP-LSH).

### Mechanism 2: Regularized cluster prototyping via RP-LSH
- **Claim:** RP-LSH enables efficient, semantically faithful streaming clustering at fixed token length.
- **Mechanism:** RP-LSH projects variable-length token embeddings into fixed-length (H×d) hash buckets, creating prototypes that aggregate semantically similar tokens. Theorem 4.1 provides a theoretical bound (h ≥ ⌈log₂(8 ln M / ε²)⌉) to choose hash bits balancing distortion and cost.
- **Core assumption:** LSH preserves cosine similarity relationships well enough for cluster assignment while drastically reducing pairwise computation.
- **Evidence anchors:** 
  - [abstract] "regularized cluster prototyping via RP-LSH"
  - [section 4.2.1] Full description and proof of Theorem 4.1.
  - [section 5.4] Table 5 shows performance improves with larger LSH bit size (0→6→12).
- **Break condition:** If semantic distinctions require finer granularity than chosen H, cluster cohesion may degrade.

### Mechanism 3: Stratified coreset sampling
- **Claim:** Stratified coreset sampling selects pseudo-labeled query-document pairs that maintain the semantic diversity of the soft memory for effective self-supervised contrastive learning.
- **Mechanism:** For each cluster, queries are sampled proportionally to cluster size. Then an iterative coverage-maximization algorithm selects queries whose associated top-m nearest documents have minimal overlap, ensuring broad document coverage within the cluster.
- **Core assumption:** A coreset maximizing coverage over the cluster's document space provides a representative, diverse training set that prevents overfitting to narrow subtopics.
- **Evidence anchors:** 
  - [abstract] "stratified coreset sampling"
  - [section 4.3.1] Equation (7) and description: "the union of all D_q maximally covers D_i."
  - [section 5.3] Ablation "w/o soft memory" shows large performance drop (avg -18.08% S@5).
- **Break condition:** Highly imbalanced clusters or many outlier queries may under-represent small but important clusters; the coverage objective assumes document sets per query reasonably indicate cluster content.

## Architecture Onboarding
- **Component map:**
  Retrieval Module (uses current encoder f_t and memory M_t to compute token-level similarity and return top-k)  
  → Memory Update Module (assigns new instances to clusters via SimDist and thresholds, updates RP-LSH prototypes, evicts old documents, samples queries proportionally)  
  → Encoder Update Module (selects coreset queries via coverage maximization, picks positives/negatives, updates f_t with contrastive loss)

- **Critical path:** Memory Update must complete before Encoder Update, as the latter depends on the current memory structure. Retrieval uses the up-to-date encoder and memory.

- **Design tradeoffs:**
  - RP-LSH bit size H: Larger H improves semantic fidelity but increases compute (Theorem 4.1 bound).
  - Assignment factor λ: Larger λ reduces new clusters but risks topic conflation; smaller λ risks fragmentation.
  - Eviction factor γ: Controls forgetting rate; larger γ retains more documents but risks memory bloat.
  - Top-K clusters for negatives: Larger K provides more contrast but may introduce noise.

- **Failure signatures:**
  - Early performance collapse if initial clustering is incoherent.
  - Memory bloat without eviction if γ is too large.
  - Stagnation after domain shift if λ is too small, leading to many small clusters under-represented in sampling.

- **First 3 experiments:**
  1. Ablation study: Remove each core component (fine-grained similarity, encoder update, soft memory) to quantify contributions.
  2. Hyperparameter sensitivity: Vary LSH bit size, initial cluster count, λ, γ.
  3. Baseline comparison: Against supervised/unsupervised MCL methods and BM25 under shared/disjoint protocols.

## Limitations
- Hyperparameter sensitivity: Performance depends on dataset-specific settings for LSH bits, λ, γ, and top-K.
- Theoretical-practical gap: Theorem 4.1's RP-LSH bound assumes idealized conditions; robustness on non-stationary streams is unverified.
- Limited external validation: No independent replication; claims rely solely on authors' experiments.

## Confidence
- Fine-grained token-level similarity: Medium (ablation strong but no direct controlled comparison to pooled reps).
- RP-LSH cluster prototyping: Medium (empirical bit-size trend supports, but theoretical bound's practical robustness unverified).
- Stratified coreset sampling: Medium (memory's overall contribution clear, but isolated effect not reported).
- Overall superiority over baselines: High (consistent large gains on two benchmarks, multiple metrics).
