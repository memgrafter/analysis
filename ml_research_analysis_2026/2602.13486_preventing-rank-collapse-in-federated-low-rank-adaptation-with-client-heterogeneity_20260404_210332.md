# Preventing Rank Collapse in Federated Low-Rank Adaptation with Client Heterogeneity

## Quick Facts
- **arXiv ID:** 2602.13486
- **Source URL:** https://arxiv.org/abs/2602.13486
- **Reference count:** 30
- **Primary result:** raFLoRA mitigates rank collapse in federated LoRA, achieving consistent accuracy improvements (up to ~2.5% absolute) while preserving higher-rank energy and communication efficiency.

## Executive Summary
Federated Low-Rank Adaptation (FedLoRA) enables efficient fine-tuning of large models in a privacy-preserving distributed setting. However, when clients have heterogeneous rank capacities (i.e., different low-rank dimensions), uniform aggregation across all clients dilutes the contributions of higher-rank updates, causing a geometric decay of singular values—known as rank collapse. This work introduces raFLoRA, a rank-partitioned aggregation scheme that decomposes each client’s LoRA update into non-overlapping rank partitions and aggregates each partition only among clients whose rank supports it. By aligning aggregation groups with rank capabilities, raFLoRA prevents the dilution and preserves the energy of higher-rank singular components. Experiments on image classification (CIFAR100), text classification (20NG), and mathematical reasoning (GSM8K with LLaMA-3.2-3B) show consistent accuracy gains over strong baselines like FlexLoRA. Moreover, raFLoRA retains ~70% of higher-rank energy after 100 rounds compared to near-zero in baselines, remains robust to data heterogeneity and client participation variations, and does not increase communication cost.

## Method Summary
In standard FedLoRA, each client computes a low-rank update ΔW = AB of rank r (chosen based on local resources) and sends the two matrices to the server. The server averages all received updates element-wise and broadcasts the aggregated ΔW back. When clients have different ranks, the averaging process implicitly pads lower-rank updates with zeros to match the largest rank, resulting in a weighted sum that disproportionately shrinks larger singular values—this is rank collapse.

raFLoRA modifies this pipeline as follows:
1. After locally computing ΔW of rank r, the client decomposes ΔW into r non-overlapping rank‑1 partitions. This can be done via an SVD and splitting the singular vectors, or simpler deterministic partitioning.
2. The client sends each partition separately to the server, along with its rank r.
3. For partition index i (1 ≤ i ≤ max_r), the server aggregates only those updates coming from clients with local rank r ≥ i. This ensures that partition i receives contributions exclusively from clients that possess the i‑th singular component.
4. The server averages the received partitions and concatenates them (in order) to reconstruct the global update ΔW_global.
5. The global model is updated and the next round begins.

This rank‑partitioned aggregation eliminates the zero‑padding mismatch, thereby preserving the relative magnitudes of singular values across partitions. The communication cost is comparable to FedLoRA because the total number of transmitted scalars remains O(d·r) per client (where d is the hidden dimension). The method is compatible with any LoRA variant and can be implemented with minor modifications to the FedLoRA server and client logic.

## Key Results
- **Accuracy gains:** CIFAR100: 86.59%±0.75 vs FlexLoRA 84.02%±1.17; 20NG: 64.80%±0.34 vs 63.05%±0.83; GSM8K (LLaMA‑3.2‑3B): 41.62%±1.15 vs 40.21%±0.42.
- **Energy preservation:** After 100 rounds, raFLoRA retains ~70% of the higher‑rank singular energy, whereas baseline methods collapse to nearly 0%.
- **Robustness:** Performance remains stable across varying data distributions (IID/non‑IID), client participation rates (10%–100%), and heterogeneous rank configurations.

## Why This Works (Mechanism)
Uniform averaging in FedLoRA treats all client updates as having the same rank by zero‑padding lower‑rank matrices. This causes each singular component of the aggregated matrix to be the average of a mixture of genuine singular values (from high‑rank clients) and zeros (from low‑rank clients). As rounds progress, this mixing leads to a geometric decay in the magnitude of higher singular values—effectively collapsing the rank.

raFLoRA’s partition‑wise aggregation circumvents this by grouping clients with the same effective rank contribution. Each partition i is averaged only among clients that have at least i singular components, so the i‑th singular value is computed as the mean of the i‑th singular values from those capable clients. No zero‑padding contamination occurs, and the relative scale of each singular component is preserved across rounds. This matches the theoretical intuition that the product of averages is not the average of products; by partitioning, raFLoRA ensures that the global update better approximates the ideal full‑rank average. Hence, higher‑rank energy is retained, preventing collapse.

## Architecture Onboarding
**Component map**  
Client (Local Data, LoRA Trainer, Partition Module) -> Server (Partition‑wise Aggregator, Global Model Distributor) -> Client (update global model)

**Critical path**
1. Server broadcasts the current global model to selected clients.
2. Each client computes its LoRA update ΔW of rank r (chosen per client).
3. Client decomposes ΔW into r non-overlapping rank‑1 partitions.
4. Client sends all partitions together with rank identifier to server.
5. For each partition index i, server collects updates from clients with r ≥ i.
6. Server performs element‑wise average per partition, concatenates them to form ΔW_global, and updates the global model.
7. Loop returns to step 1.

**Design tradeoffs**
- *Partition granularity:* Finer partitions (e.g., rank‑1) provide finer alignment but may leave some partitions with very few contributors, increasing statistical noise. Coarser partitions reduce noise but risk partial dilution if ranks vary.
- *Communication overhead:* raFLoRA’s message size per client is O(d·r) (same as FedLoRA). The extra rank metadata is negligible.
- *Heterogeneity handling:* The method assumes clients report their true rank; misreporting can either leave partitions empty or cause mismatched partitions, harming convergence.

**Failure signatures**
- *Empty partition:* No client with rank ≥ i for a given i → that partition is omitted, effectively dropping a singular component and reducing model capacity.
- *High variance in partition size:* If only one or two clients contribute to a high‑index partition, the average becomes noisy, potentially destabilizing training.
- *Client dropout during round:* Missing partitions may lead to incomplete global update; the server must define a timeout or fallback (e.g., reuse previous partition value).

**First experiments**
1. Measure singular value energy retention over rounds for raFLoRA vs. uniform FedLoRA under controlled heterogeneous rank settings.

3. Compare full‑rank partitioning (as in raFLoRA) against alternative schemes like random grouping or weighted averaging to validate the design choice.

## Limitations
- Experiments are limited to small models (≤3B parameters) and three tasks; scalability to larger foundation models remains untested.
- Theoretical analysis of the rank‑partitioned aggregation mechanism (e.g., convergence bounds, energy preservation guarantees) is lacking.
- Evaluation is conducted in simulated FL environments without real‑world network variability, client churn, or severe covariate shift.
