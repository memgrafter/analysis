# MixFormer: Co-Scaling Up Dense and Sequence in Industrial Recommenders

## Quick Facts
- **arXiv ID**: 2602.14110
- **Source URL**: https://arxiv.org/abs/2602.14110
- **Reference count**: 35
- **Primary result**: MixFormer-medium achieves +1.28% AUC and +1.60% UAUC offline gains over strong baselines; decoupled variant reduces FLOPs by 36% with >30% serving speedup.

## Executive Summary
Industrial recommender systems often use separate modules for modeling user behavior sequences and dense feature interactions, leading to competition for computational resources during scaling. MixFormer addresses this co-scaling challenge by proposing a unified Transformer backbone with shared parameters that jointly models both sequence and dense components, enabling effective joint scaling and deep cross-interaction. Furthermore, a user-item decoupling strategy optimizes inference latency by separating user and item computations.

Offline experiments on the large-scale Douyin dataset show that MixFormer-medium achieves +1.28% AUC and +1.60% UAUC improvements compared to the strongest stacked baseline (STCA→RankMixer) while using comparable parameters. The decoupled variant reduces FLOPs by 36% with minimal accuracy drop and yields over 30% serving speedup. Large-scale online A/B tests on Douyin and Douyin Lite confirm consistent user engagement gains, including +0.0415% in active days and +0.2799% in in-app duration.

## Method Summary
MixFormer introduces a unified Transformer architecture where user behavior sequences and dense features are processed through a shared parameter backbone. This design allows the model to jointly scale both components without the typical resource competition, facilitating deep cross-interactions. For inference, a user-item decoupling strategy separates the computation of user and item representations, significantly reducing latency. The model is evaluated on Douyin's industrial recommendation dataset, demonstrating improvements over stacked baselines such as STCA and RankMixer.

## Key Results
- Offline: MixFormer-medium: +1.28% AUC, +1.60% UAUC vs. strongest stacked baseline (STCA→RankMixer) with comparable parameters.
- Decoupled variant: 36% FLOPs reduction, minimal accuracy drop, >30% serving speedup.
- Online A/B tests: +0.0415% active days, +0.2799% in-app duration on Douyin and Douyin Lite.

## Why This Works (Mechanism)
The unified Transformer backbone with shared parameters allows sequence modeling and feature interaction to scale jointly, avoiding competition for independent resource pools. This sharing enables deep cross-interaction because gradients from both tasks update the same parameters, enriching the learned representations. Additionally, the user-item decoupling strategy reduces computational redundancy at inference by separating user and item computations, lowering latency without sacrificing the joint modeling during training.

## Architecture Onboarding
**Component Map**: User sequence tokens and dense feature tokens are concatenated into a single sequence and fed into a shared Transformer stack. The final hidden state of the [CLS] token is used for prediction.

**Critical Path**: Raw inputs → tokenization/embedding → shared Transformer (self-attention over combined tokens) → prediction MLP. Shared parameters ensure both sequence and dense information influence each other via attention throughout the stack.

**Design Tradeoffs**:
- Shared parameters reduce total model size and encourage cross-modal interactions but may limit specialization for each modality.
- Decoupling user and item inference reduces latency but might slightly reduce accuracy due to loss of joint optimization at inference; trade-off controlled by minimal accuracy drop.
- Increasing Transformer depth improves representation power but increases latency; co-scaling allows balancing these aspects.

**Failure Signatures**:
- Training instability or slow convergence if learning rates for sequence and dense branches are unbalanced.
- Higher than expected latency if decoupling is improperly implemented (e.g., still computing user and item together).
- Degraded performance on certain user groups if the model fails to capture long-term sequences due to limited sequence length.

**First Experiments**:
1. Baseline Comparison: Implement MixFormer on a public dataset (e.g., MovieLens) and compare with separate towers for sequence and dense features to verify the benefit of sharing.
2. Ablation Study: Remove the shared backbone (use separate Transformers) and measure performance and parameter count.
3. Latency Measurement: Test the user-item decoupling by measuring inference time on fixed hardware with and without decoupling, verifying the claimed speedup.
