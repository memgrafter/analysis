# Failure Detection in Chemical Processes Using Symbolic Machine Learning: A Case Study on Ethylene Oxidation

## Quick Facts
- **arXiv ID:** 2603.06767
- **Source URL:** https://arxiv.org/abs/2603.06767
- **Reference count:** 11
- **Primary result:** DisPLAS achieved average AUC 0.92 on nontrivial failures, outperforming random forest (0.87) and MLP (0.83), while generating compact interpretable models (average rule body length 3.33).

## Executive Summary
This paper tackles safety-critical failure detection in chemical processes, where neural AI methods lack explainability and real failure data is scarce. The authors introduce DisPLAS, a symbolic machine learning system that learns probabilistic rules from simulated ethylene oxidation data. DisPLAS supports two tasks: `T_static` for causal, long-term cause-effect analysis from steady-state data, and `T_dynamic` for early, multi-class failure classification from short-term trajectories. Results show DisPLAS achieves higher AUC than several baselines while producing human-readable rules, enabling an "AI-in-the-loop" operator support framework.

## Method Summary
The method uses DisPLAS, a probabilistic inductive logic programming (ILP) system, to learn interpretable rules from discretized process data. Data is generated via AVEVA Process Simulation (APS) for an ethylene oxidation flowsheet under nominal and failure conditions. Two learning tasks are defined: `T_static` extracts causal relationships by predicting downstream variable shifts given upstream contexts; `T_dynamic` classifies failure types using absolute values and rates of change at a short timepoint (`t_short_term`). Models are evaluated via cross-validation using AUC and rule compactness (average rule body length).

## Key Results
- DisPLAS achieves average AUC 0.92 on nontrivial failures, exceeding random forest (0.87) and MLP (0.83).
- Learned models are highly compact, with average rule body length 3.33; using only real-world sensors reduces this to 3.0 while maintaining AUC 0.92.
- `T_dynamic` enables early detection within 6 seconds, and `T_static` provides causal insights useful for design and HAZOP.

## Why This Works (Mechanism)

### Mechanism 1: Compact Probabilistic Rule Learning
**Claim:** DisPLAS learns compact, probabilistic rules that balance predictive accuracy with interpretability.  
**Mechanism:** It extends FastLAS by discretizing probability values (Φ) and optimizing the posterior probability P(H|⟨C+, C−⟩) over a hypothesis space of rules of the form `prob ϕ ← body`. The scoring function combines rule complexity (body length) with penalties for misclassified examples, favoring simpler hypotheses that still fit the data.  
**Core assumption:** Process failures can be captured by a small set of context-dependent probabilistic rules over discretized process variable states, and these rules' probabilities can be effectively approximated from a discrete set.

### Mechanism 2: Static Causal Analysis (`T_static`)
**Claim:** The `T_static` task extracts causal, long-term cause-effect relationships from steady-state process data.  
**Mechanism:** For a given failure context (e.g., a specific upstream perturbation), it learns rules predicting downstream variable bucket shifts (increase/decrease/nominal). The context includes upstream variable states, and the rule body relates these to downstream outcomes, modeling how perturbations propagate.  
**Core assumption:** A failure's "fingerprint" in steady-state includes predictable directional changes in downstream variables that are robust to minor noise and can be captured by simple rules.

### Mechanism 3: Dynamic Failure Classification (`T_dynamic`)
**Claim:** The `T_dynamic` task enables early, multi-class failure classification from short-term process trajectories.  
**Mechanism:** Using data from a specific short timepoint after perturbation (`t_short_term`), it learns rules that classify the failure type based on absolute process variable values (`v(value)`) and their short-term changes (`v∆=↗/↘/≈`). The multi-label approach handles exclusive failure classes.  
**Core assumption:** Different failures induce measurably distinct short-term sensor response patterns (in both absolute values and rates of change) within a window small enough for early detection.

## Foundational Learning

- **Symbolic Machine Learning (Inductive Logic Programming)**  
  *Why needed:* To produce human-readable, verifiable rules instead of black-box models, critical for safety-critical operator trust and HAZOP validation.  
  *Quick check:* Given a learned rule, can a process engineer trace its logical conditions back to known process physics or design documents?

- **Probabilistic Logic Programming (Discrete Bayesian Extension of ASP)**  
  *Why needed:* To handle noisy sensor data and inherent process uncertainty while maintaining a logical structure. The discretized probabilities allow tractable learning from limited data.  
  *Quick check:* Does the assigned probability to a rule reflect both empirical support from data and a prior preference for rule simplicity?

- **Answer Set Programming (ASP) with Default Negation**  
  *Why needed:* To represent context-dependent exceptions (e.g., "high temperature *unless* cooling is active") and stable model semantics for reasoning about process states.  
  *Quick check:* Can you write an ASP rule using `not` to model a failed state that persists unless a specific reset action occurs?

## Architecture Onboarding

**Component map:**  
Process Simulator (APS) -> Data Preprocessor -> DisPLAS Learner -> Rule Evaluator & Agent Interface

**Critical path:** Simulator runs → Discretization & WCDPI creation → DisPLAS task configuration (`T_static`/`T_dynamic`, mode bias) → Learning → Rule validation (ROC/AUC) → Integration into agent framework.

**Design tradeoffs:**  
- *Interpretability vs. Accuracy:* Smaller rule bodies improve readability but may miss complex interactions; Table 2 shows slight accuracy dips with fewer rules.  
- *Static vs. Dynamic Tasks:* `T_static` offers causal insights for design/HAZOP but is not real-time; `T_dynamic` is for online detection but depends heavily on chosen `t_short_term`.  
- *Sensor set size:* Using all process variables (Config 14) gives highest avg(AUC)=0.94 but is less practical; using only real-world sensors (Config 15) gives avg(AUC)=0.92 with simpler rules (avg body 3.0).

**Failure signatures:**  
- *Solver timeouts:* With many failures/runs/variables (e.g., Config 1 with trivial experiments included), solving time peaks at ~2 hours—indicates overly large hypothesis space.  
- *Low AUC on nontrivial experiments:* (<0.85) suggests `t_short_term` is too small, mode bias is poorly tuned, or failures are too similar.  
- *High average rule body length:* (>4) indicates failure to penalize complexity sufficiently—rules become less interpretable.

**First 3 experiments:**  
1. **Baseline `T_dynamic`:** Run with default parameters (nontrivial experiments, n_runs=75, `t_short_term`=6s, real-world variables). Validate achievable AUC~0.92 and rule simplicity.  
2. **`t_short_term` sweep:** Systematically vary `t_short_term` (2s to 20s). Measure AUC and rule confidence (avg prob). Identify earliest timepoint where nontrivial failures achieve AUC>0.90—this is the operational detection window.  
3. **Sensor reduction stress test:** Using only M1.PV and M2.PV (Config 16) to see if minimal sensor set retains accuracy. If AUC drops significantly (<0.85), expand to include upstream critical variables.

## Open Questions the Paper Calls Out

1. **Scaling to simultaneous faults:** How can the DisPLAS approach be scaled to handle simultaneous faults in complex chemical processes? The current study is limited to non-simultaneous failures, and scalability issues arise with more failures and variables.

2. **Robustness to unseen failure modes:** How can symbolic machine learning models be made robust to unseen failure modes not represented in the training data? The model is trained on a limited set of simulated failures and may fail to generalize to novel failure scenarios.

3. **Process decomposition for distributed agents:** What practical mechanisms are needed to decompose a complex chemical process into sub-processes for distributed agent learning in the proposed AI-in-the-loop framework? Without a decomposition strategy, scalability and agent collaboration remain theoretical.

4. **Operator-centric evaluation:** To what extent do the learned probabilistic rules align with human operator expertise and support effective real-time failure detection? Rule quality is assessed by metrics like AUC, but operator understanding, trust, and decision-making impact are unmeasured.

## Limitations
- **Data dependency:** Results rely on proprietary AVEVA Process Simulation (APS); recreating the exact dynamics in an alternative simulator is nontrivial and may yield different performance.
- **Generalizability:** Evaluation uses simulated data; performance on real plant data with sensor noise, unmodeled disturbances, and different failure modes is unknown.
- **Baseline reproducibility:** Specific hyperparameters for neural baselines after Optuna optimization are unreported, risking mismatch in comparative evaluations.

## Confidence
- **Primary performance claim (DisPLAS AUC > baselines):** Medium. Results are empirically sound in the controlled simulation but lack external validation on real systems or alternative simulators.
- **Interpretability/compactness claim:** High. Directly supported by reported average rule body length (3.33) and provided example rules.
- **General mechanism (probabilistic rules capture process causality):** Medium. Evidence is limited to one specific process (ethylene oxidation); break conditions for other chemical processes are not tested.
