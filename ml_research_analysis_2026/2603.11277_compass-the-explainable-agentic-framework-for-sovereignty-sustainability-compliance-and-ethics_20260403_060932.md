# COMPASS: The explainable agentic framework for Sovereignty, Sustainability, Compliance, and Ethics

## Quick Facts
- **arXiv ID:** 2603.11277
- **Source URL:** https://arxiv.org/abs/2603.11277
- **Reference count:** 37
- **Primary result:** COMPASS introduces a multi-agent orchestration architecture that concurrently evaluates agent actions on sovereignty, carbon-awareness, compliance, and ethics using RAG-augmented LLM judges, yielding explainable scores and reducing hallucination.

## Executive Summary
The paper addresses the lack of unified governance frameworks for LLM-based agents that integrate digital sovereignty, sustainability, compliance, and ethics. COMPASS proposes an agentic system where an Orchestrator intercepts user prompts and dispatches them to four specialized sub‑agents, each employing Retrieval‑Augmented Generation (RAG) to ground its assessment in relevant regulatory documents. An LLM‑as‑judge then produces a quantitative score and a natural‑language justification for its dimension. These outputs are synthesized in real time, with conflict resolution to produce an optimized action. Automated evaluation shows that RAG significantly improves semantic coherence (BERTScore) and reduces hallucination compared to a vanilla LLM baseline.

The framework enables transparent, simultaneous assessment of all four dimensions, providing both scores and explainable rationale. This supports operators in deploying agentic AI that respects jurisdictional sovereignty, minimizes environmental impact, adheres to regulations, and aligns with ethical principles. The modular design allows each dimension to evolve independently while the Orchestrator manages trade‑offs.

## Method Summary
COMPASS is an agentic AI framework built around an Orchestrator and four specialized sub‑agents (Sovereignty, Carbon, Compliance, Ethics). Each sub‑agent uses Retrieval‑Augmented Generation (RAG) to query a vector database of curated reference documents (e.g., Canadian Digital Sovereignty Framework, EU AI Act). The retrieved passages are inserted into a prompt for an LLM‑as‑judge (Mistral‑7B-Instruct-v0.2), which is instructed to output a JSON object containing a quantitative score (0.0–1.0) and an explanation. The Decision Synthesiser aggregates the four scores and any constraints, resolves conflicts via an unspecified weighting or arbitration mechanism, and generates a final, optimized action. The authors evaluate the framework by running a set of test cases both with RAG enabled and with a vanilla LLM baseline, measuring the BERTScore similarity between the generated justifications and the source documents to assess grounding and hallucination. Results indicate that RAG improves semantic coherence and grounding.

## Key Results
- RAG‑augmented evaluations achieve higher BERTScore similarity to source documents than vanilla LLM, indicating better grounding and reduced hallucination.
- The Orchestrator can concurrently evaluate all four dimensions and synthesize conflicting scores into a single, explainable decision.
- Test cases demonstrate dimension‑specific quantitative scoring (0.0–1.0) aligned with domain criteria such as sovereignty thresholds, carbon‑efficiency, regulatory compliance, and ethical alignment.

## Why This Works (Mechanism)

### Mechanism 1: Real‑time multi‑dimensional evaluation
Claim: The framework mediates real‑time, multi‑dimensional evaluation of agent actions before execution.  
Mechanism: The Orchestrator intercepts a user prompt and concurrently dispatches it to four specialized sub‑agents. Each sub‑agent uses RAG to retrieve relevant documents and an LLM‑as‑judge to assign a quantitative score and generate an explanation. The scores and constraints are aggregated, conflicts resolved, and a final optimized action is produced.  
Core assumption: Parallel pre‑execution evaluation of distinct normative dimensions is necessary and feasible, and sub‑agent outputs can be aggregated despite potential conflicts.  
Evidence: Abstract and Section 2.1 describe the concurrent dispatch; Figure 1 illustrates the flow.  
Break condition: If evaluations are not truly concurrent or conflict resolution is not deterministic/explainable, the "real‑time" and "simultaneous" claims fail.

### Mechanism 2: RAG grounding improves coherence and reduces hallucination
Claim: RAG integration grounds normative evaluations in verified, context‑specific documents, enhancing semantic coherence and mitigating hallucination.  
Mechanism: Each sub‑agent queries a vector database of curated reference documents. Retrieved chunks are inserted into the LLM‑as‑judge's prompt, forcing the evaluation to rely on supplied text.  
Core assumption: Access to authoritative, jurisdiction‑ and domain‑specific text at inference time improves accuracy and traceability of normative judgments.  
Evidence: Abstract states RAG enhances BERTScore and mitigates hallucination; Section 2.5 explains customization; Section 3 (Tables 5‑8) report BERTScore comparisons.  
Break condition: If retrieved documents are irrelevant/outdated, or the LLM ignores them, grounding fails and performance approximates the vanilla LLM baseline.

### Mechanism 3: LLM‑as‑judge yields explainable quantitative scores
Claim: The LLM‑as‑judge methodology produces explainable, quantitative scores for each dimension, enabling transparency.  
Mechanism: A system prompt defines evaluation principles and a scoring rubric (0.0–1.0), and mandates a JSON output with score and explanation. The user prompt includes RAG context and query parameters; the judge's output is constrained to this format.  
Core assumption: A capable LLM (Mistral‑7B) guided by a structured prompt and rubric can reliably simulate expert judgment on complex normative concepts.  
Evidence: Abstract and Section 2.4 describe the JSON format and prompt structure; Section 2.3 lists LLM configuration.  
Break condition: Inconsistent scores across equivalent inputs or explanations that are post‑hoc rationalizations would undermine explainability and quantitative claims. The paper lacks human validation.

## Architecture Onboarding
- **Component map:** Orchestrator composes four sub‑agents (SovereigntyAgent, CarbonAgent, ComplianceAgent, EthicsAgent). Each sub‑agent includes a VectorDB, a RAGRetriever, and an LLMJudge. The DecisionSynthesiser aggregates scores and constraints and produces visualizations. A ConcreteApplicationAgent (e.g., BankingBot) inherits from Orchestrator.

- **Critical path:**  
  1) User prompt received by Orchestrator.  
  2) Orchestrator calls `Synchronise()`.  
  3) Concurrent dispatch of (RAG context + query) to all four sub‑agents' LLMJudge.  
  4) Each LLMJudge returns `{score, explanation, constraints}`.  
  5) DecisionSynthesiser aggregates, identifies conflicts, applies weighting/resolution, and generates final score/action.  
  6) Orchestrator executes or suggests the OptimisedOutput.

- **Design tradeoffs:**  
  - *Latency vs. Assurance:* Four concurrent evaluations + RAG latency increases response time versus a single LLM call.  
  - *Modularity vs. Conflict Complexity:* Isolating concerns in sub‑agents simplifies development but defuses complex, cross‑dimensional trade‑offs to the Synthesiser, which is underdeveloped.  
  - *Local Execution vs. Performance:* Using a local LLM (Mistral‑7B) ensures sovereignty but may reduce judgment quality compared to a larger cloud model (a tradeoff the framework itself would evaluate).

- **Failure signatures:**  
  - **RAG Failure:** Irrelevant/empty retrieved chunks → judge relies on parametric memory → scores resemble "Vanilla LLM" baseline (lower BERTScore similarity).  
  - **Judge Failure:** LLM outputs non‑JSON, JSON with wrong keys, or scores outside [0,1] → synthesiser crashes or produces invalid output.  
  - **Conflict Stalemate:** Two sub‑agents give diametrically opposed scores (e.g., 0.9 vs. 0.1) with no resolution strategy → Synthesiser cannot produce a single "optimized" action.  
  - **Inheritance Bypass:** A developer modifies ConcreteApplicationAgent to call the base LLM directly, skipping `GetEthicalClearance()` → governance is circumvented.

- **First 3 experiments:**  
  1. **Sub‑agent unit test:** For a single dimension, feed a fixed query and RAG context. Assert the LLMJudge returns valid JSON with a float score in [0,1] and a non‑empty explanation string. Repeat with 10 varied documents to check consistency.  
  2. **RAG ablation validation:** Run the same 10 test cases with RAG enabled and disabled. Compute the BERTScore between the generated explanation and the source document(s). Expect higher similarity with RAG. Also manually audit explanations for hallucinated citations.  
  3. **Orchestrator integration test:** Mock the four sub‑agents to return predefined score/explanation/constraint tuples. Feed a user prompt to the Orchestrator. Verify the DecisionSynthesiser produces the expected bar/radar chart JSON and that the final OptimisedAction respects a simple rule (e.g., if any score < 0.5, flag for review).

## Open Questions the Paper Calls Out
The paper does not explicitly list open questions. However, the limitations and design choices raise important questions for future work:
- How should the Decision Synthesiser's conflict resolution be designed to be both effective and explainable?
- What are the optimal RAG configuration details (chunk size, embedding model, retrieval top‑k) for normative evaluation?
- How reliable are LLM‑as‑judge scores compared to human experts across sovereignty, carbon, compliance, and ethics?
- Can the framework handle more than four dimensions or more complex multi‑agent interactions without excessive latency?

## Limitations
- RAG implementation details (chunking, retrieval query, top‑k) are unspecified, hindering reproducibility and assessment of grounding quality.
- Conflict resolution algorithm is undescribed and untested, undermining the Synthesiser's ability to handle cross‑dimensional trade‑offs.
- LLM‑as‑judge scores lack human validation; the reliability and soundness of generated explanations remain unknown.

## Confidence
- Concurrent real‑time mediation: Medium (Assumption: sub‑agents truly run in parallel and the Orchestrator does not become a bottleneck)
- RAG grounding improves coherence: Medium‑High (Evidence from BERTScore, but retrieval quality not manually validated)
- Explainable quantitative scoring: Low (Unknown: LLM judges may produce post‑hoc rationalizations; lacks human validation)
- Conflict resolution: Low (Unknown: algorithm unspecified and untested; potential for arbitrary decisions)
- Overall framework utility: Medium (Depends on resolving conflict resolution and validating LLM judgments; modular design is promising)
