# TAME: A Trustworthy Test-Time Evolution of Agent Memory with Systematic Benchmarking

## Quick Facts
- arXiv ID: 2602.03224
- Source URL: https://arxiv.org/abs/2602.03224
- Reference count: 40
- Primary result: TAME mitigates agent memory misevolution, achieving joint improvements in task performance and trustworthiness across science, math, and tool-use domains.

## Executive Summary
Agent memory evolution during test-time can degrade trustworthiness as agents pursue utility at the expense of safety. This paper introduces TAME, a dual-memory framework that separates strategy execution from trustworthiness evaluation. By maintaining an executor memory for task strategies and an evaluator memory for safety critiques, TAME implements a closed loop with memory filtering, utility-prioritized drafting, trustworthy refinement, and dual-track updates. Experiments on Qwen3-32B and GPT-5.2 using the new Trust-Memevo benchmark show that TAME prevents the typical trustworthiness decline seen in baseline systems while maintaining or improving task accuracy. For instance, with GPT-5.2, TAME reaches 0.702 on GPQA and 0.647 on AIME alongside higher trustworthiness scores, outperforming baselines that sacrifice either safety or performance. Ablations confirm the necessity of the refinement and filtering steps.

## Method Summary
TAME operates in a test-time learning paradigm where an agent iteratively updates memory without weight changes. The system comprises two agents: an Executor that generates actions based on strategy memories, and an Evaluator that filters retrieved executor strategies using its own trust-evaluation memory, drafts a utility-focused plan, then refines it with constitutional constraints. Memory updates occur in dual tracks: the Executor records outcomes with distilled strategies, while the Evaluator stores its evaluation strategies and trust assessments. This creates a self-correcting loop where safety critiques guide future retrieval. The pipeline follows: retrieve relevant memories, filter for trustworthiness, draft a high-utility solution, refine it to meet constitutional principles, generate final response, abstract new strategies, and update both memory banks.

## Key Results
- TAME achieves joint gains: with GPT-5.2, it attains 0.702 on GPQA (science) and 0.647 on AIME (math) while improving trustworthiness scores.
- On the Trust-Memevo benchmark across science, math, and tool-use domains, TAME consistently mitigates the trustworthiness degradation observed in baselines like ReasoningBank.
- Ablation studies show that removing refinement or filtering leads to significant drops in trustworthiness, confirming their critical roles.

## Why This Works (Mechanism)
The paper presents three key mechanisms:

### Decoupling Execution and Evaluation
The system maintains independent memory banks: `M_exec` for task strategies and `M_eval` for trust evaluation. The Evaluator filters executor strategies using historical safety feedback before they influence response generation. This prevents the Executor's memory from accumulating "toxic shortcuts" that optimize solely for task reward. The filtering function `Φ` removes strategies correlated with trustworthiness violations, purifying the context used for drafting.

### Utility-Prioritized Drafting Followed by Trustworthy Refinement
The Evaluator first generates a plan draft `ρ_draft` conditioned on filtered memory and a utility instruction, maximizing the likelihood of task success. In a second phase, it refines `ρ_draft` into `ρ*` by applying constitutional constraints `C` and trust strategies. This staged approach avoids the over-alignment problem that can occur if safety constraints are applied immediately, preserving high-utility reasoning paths.

### Dual-Track Memory Updates
After each step, the Executor memory is updated with `(query, distilled_strategy, outcome)`, while the Evaluator memory is updated with `(query, eval_strategy, trust_strategy, outcome)`. This stores both execution results and meta-cognitive critiques. Future retrieval uses the Evaluator's memory to interpret outcomes and safety evaluations, enabling the system to treat failed or unsafe strategies as negative constraints and steer evolution toward trustworthy solutions.

Each mechanism addresses a facet of the misevolution problem, and ablations confirm their necessity.

## Architecture Onboarding
**Component map**:  
M_exec --(retrieval)--> A_eval --(filtering)--> ˆs_exec --(drafting)--> ρ_draft --(refinement)--> ρ* --> A_exec --(generation)--> a(t)  
A_eval also reads from M_eval for trust strategies; both memories are updated after each step.

**Critical path**:  
1. Retrieve s_exec from M_exec and s_eval/s_trust from M_eval for query q.  
2. Evaluator filters s_exec → ˆs_exec using Φ (depends on s_eval, s_trust).  
3. Evaluator drafts ρ_draft conditioned on ˆs_exec and I_utility.  
4. Evaluator refines ρ_draft into ρ* using constitutional constraints C and s_trust.  
5. Executor generates a(t) using ρ* and ˆs_exec.  
6. Abstract a(t) into s_exec_new; evaluate a(t) to produce s_eval_new, s_trust_new.  
7. Dual-track update: M_exec ← M_exec ∪ (q, s_exec_new, y_outcome); M_eval ← M_eval ∪ (q, s_eval_new, s_trust_new, y_outcome).

**Design tradeoffs**:  
- Separation vs. Coupling: Strict separation prevents safety contamination but adds latency; single memory is simpler but prone to misevolution.  
- Utility-First Drafting: Generating an unconstrained draft risks toxicity that may be irrecoverable if constraints are weak or refinement fails.  
- Memory Granularity: Distilled strategies are generalizable but may lose nuance; raw trajectories are rich but noisy and harder to retrieve.

**Failure signatures**:  
- Misevolution resurgence: Trustworthiness scores decline after initial improvement.  
- Utility collapse: Task performance drops significantly below ReasoningBank baseline.  
- Stagnant Evaluator Memory: Little change in M_eval size/content over many steps.  
- Filtering exhaustion: Filter removes most retrieved strategies, leaving insufficient context.

**First 3 experiments**:  
1. **Baseline comparison**: Run ReasoningBank vs. TAME on Trust-Memevo Science domain (MMLU-Pro/GPQA). Track task accuracy and trustworthiness per evolution step (e.g., every 50 problems). Expect TAME to maintain or improve trustworthiness while both improve accuracy, but baselines show trustworthiness decline.  
2. **Ablation of refinement**: Run TAME-NoRef (remove refinement, use ρ_draft as final plan) on GPQA. Compare trustworthiness and accuracy to full TAME. Expect similar accuracy but lower trustworthiness, confirming refinement's safety role.  
3. **Filtering validation**: For sampled queries, log indices of s_exec removed by Φ. Manually inspect if removed strategies contain clear safety risks that were retained in M_exec. Validates that filtering targets toxic strategies.

## Limitations
- Long-term stability of the Evaluator memory (M_eval) is unproven; it may degrade as executor strategies evolve.
- Utility-first drafting could produce irrecoverably toxic drafts if constitutional constraints are weak or refinement step fails.
- The Trust-Memevo benchmark covers only three domains and tested models are limited (Qwen3-32B, GPT-5.2), raising generalizability concerns.

## Confidence
- Core claim (TAME mitigates misevolution): **High**
- Mechanism 1 (decoupling): **Medium**
- Mechanism 2 (utility-first then refinement): **Medium**
- Mechanism 3 (dual-track updates): **Medium**
*Note: High confidence for overall effectiveness based on strong empirical results; medium for individual mechanisms due to reliance on ablations and lack of long-term stability data.*
