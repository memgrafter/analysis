# ReFeed: Retrieval Feedback-Guided Dataset Construction for Style-Aware Query Rewriting
## Quick Facts
- arXiv ID: 2603.01417
- Source URL: https://arxiv.org/abs/2603.01417
- Reference count: 2
- Primary result: ReFeed constructs a style-aware query rewriting dataset from failed retrieval cases, achieving 67.5% verification success and improved ranking in few-shot validation.

## Executive Summary
ReFeed tackles the challenge of style mismatch between user queries and domain documents, which often leads to retrieval failures. The method automatically builds a style-aware query rewriting dataset by detecting failed retrieval instances, employing LLMs to rewrite queries to align with the style of relevant documents, and verifying the effectiveness via re-retrieval. Using SQuAD, the pipeline generated 11,044 verified query-rewrite pairs from 16,000 initial misses (67.5% success). Few-shot experiments demonstrated that these pairs significantly enhance document ranking, moving queries from outside the top-10 to top-2 positions, without any model fine-tuning. This validates the potential of retrieval-aligned rewriting as a lightweight technique for improving retrieval performance.

## Method Summary
The ReFeed pipeline constructs a style-aware query rewriting dataset through three sequential steps: (1) **Failed retrieval detection**: For each query in a corpus, an initial retrieval (e.g., BM25 or dense retriever) is run; cases where no relevant document appears within a predefined top‑k (e.g., top‑10) are flagged as failures. (2) **LLM rewriting**: A large language model (LLM) is prompted with the original query and a relevant document (or its content) to generate a rewritten query that preserves the original intent but matches the document's style (e.g., terminology, phrasing). (3) **Re‑retrieval verification**: The rewritten query is used to re‑run retrieval; if a relevant document now appears within a stricter threshold (e.g., top‑2), the pair is considered verified and added to the dataset. The pipeline is unsupervised with respect to annotated rewrites, relying solely on retrieval signals for validation.

## Key Results
- Constructed 11,044 verified (original, rewritten) query pairs from 16k failed retrieval cases (67.5% verification rate).
- Few-shot validation showed substantial ranking improvement: queries previously not in top-10 advanced to top-2 positions.
- Demonstrated retrieval-aligned rewriting without fine-tuning, using only a small set of generated pairs.

## Why This Works (Mechanism)
The mechanism relies on the principle that retrieval performance is heavily influenced by lexical and semantic alignment between queries and documents. Style mismatch (e.g., user queries using colloquial terms while documents use formal terminology) leads to poor term overlap or embedding similarity, causing retrieval failures. By explicitly rewriting queries to adopt the style of relevant documents, ReFeed increases the likelihood that the query and document share surface‑level features (words, phrases) and deeper stylistic patterns that retrieval models exploit. Re‑retrieval verification ensures that the rewrite actually improves the ranking of a relevant document, filtering out ineffective or harmful rewrites. This creates a dataset of query‑rewrite pairs that are optimized for retrieval, which can then be used in few‑shot learning to teach models to produce retrieval‑friendly queries without any fine‑tuning of the retriever itself.

## Foundational Learning
ReFeed builds on several foundational concepts in information retrieval and natural language processing: (1) **Query‑document lexical gap**: Prior work has long recognized that user queries often differ in vocabulary and structure from document content, hindering retrieval. (2) **Leveraging LLMs for text transformation**: The in‑context learning abilities of large language models allow them to perform rewriting tasks with minimal examples. (3) **Self‑training with verification**: Using retrieval performance as an automatic label for rewrite quality is akin to self‑training paradigms where model outputs are validated by downstream metrics. (4) **Dataset synthesis**: Recent trends in using model‑generated data for training, often with verification loops, are extended here to the specific case of style‑aligned query rewriting.

## Architecture Onboarding
The architecture of ReFeed is a modular pipeline that iterates over a collection of (query, document) pairs. Initially, a retriever is indexed on the document corpus. For each query, the system: (a) retrieves a set of documents; (b) checks if any relevant document (e.g., containing the answer for SQuAD) is present within a high cutoff (e.g., top‑10); if not, the query is a failure candidate. For each failure, the system retrieves the most relevant document(s) (even if not top‑1) and feeds their content along with the query to an LLM to produce a rewrite. The rewritten query is then submitted to the same retriever; success is defined if a relevant document now ranks within a higher cutoff (e.g., top‑2). Verified (query, rewrite) pairs are collected. The final dataset can be used to train or prompt a rewriting model in a few‑shot setting. The pipeline’s design allows different retrievers and LLMs to be plugged in with minimal changes.

## Open Questions the Paper Calls Out
The paper identifies several open questions that warrant further investigation: (1) **Cross‑domain validity**: The dataset was constructed exclusively from SQuAD; it remains unknown whether the style‑aware rewriting approach generalizes to other domains (e.g., conversational search, e‑commerce) with different query and document characteristics. (2) **Downstream impact**: While retrieval rankings improve in a few‑shot setting, it is unclear whether these rewrites ultimately enhance downstream task performance, such as answer accuracy in a RAG pipeline. (3) **Failure analysis**: The 32.5% of rewrites that failed verification hint at systematic issues (e.g., semantic drift, over‑stylization, hallucination) that require dedicated analysis to understand and mitigate. (4) **Bias propagation**: LLM‑based rewriting may introduce or amplify style biases inherent to the model, raising concerns about fairness and robustness.

## Limitations
- Domain generalization: Dataset derived solely from SQuAD; unknown if style-aware rewrites transfer to other domains (e.g., conversational search, e-commerce).
- Success metric dependency: Verification relies on re-retrieval hitting a top-k threshold; may not correlate with downstream task performance (e.g., answer accuracy in RAG).
- Scalability & bias: LLM-driven rewriting may propagate model-specific style biases; 32.5% unverified rewrites suggest substantial failures without error analysis.

## Confidence
- Dataset construction pipeline (failed retrieval detection → LLM rewrite → re-retrieval verification): High
- Claim: "Retrieval-aligned rewriting without fine-tuning" improves ranking: Medium
- Claim: Style mismatch is a primary failure cause: Low
