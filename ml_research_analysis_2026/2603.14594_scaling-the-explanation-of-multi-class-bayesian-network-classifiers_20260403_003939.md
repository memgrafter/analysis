# Scaling the Explanation of Multi-Class Bayesian Network Classifiers

## Quick Facts

- arXiv ID: 2603.14594
- Source URL: https://arxiv.org/abs/2603.14594
- Reference count: 0
- Primary result: Introduces an f-tree-based algorithm that compiles multi-class Bayesian network classifiers into OR-decomposable NNF circuits, enabling efficient explanation with substantial speedups over prior binary-class methods.

## Executive Summary

The paper tackles the problem of explaining decisions made by multi-class Bayesian network classifiers (BNCs). While previous approaches could only handle binary classifiers, the authors develop a novel compilation algorithm that produces OR-decomposable negation normal form (NNF) circuits for any multi-class BNC. The key idea is to embed a feature tree (f-tree) within a jointree of the Bayesian network, which partitions the input features into subsets. This partitioning exploits d-separation to allow early classification of partial feature instantiations, avoiding the need to enumerate all features. The compiled circuit supports efficient queries for explanations such as complete and general reasons.

The algorithm is evaluated on a comprehensive benchmark of 554 problems drawn from five real-world Bayesian networks. It solves 492 problems within a 4-hour timeout, compared to only 166 solved by the state-of-the-art baseline. On notoriously hard instances (e.g., the andes network), compilation time drops from over 11,000 seconds to under 30 seconds. Theoretical analysis shows a time complexity exponential in a compilation width ω_T, which is empirically much smaller than the brute-force bound ω+|X|, explaining the speedups. The size of the output circuits remains comparable to those from prior binary-class compilations, indicating that the approach scales without bloating the representation.

## Method Summary

The algorithm proceeds in three phases. First, it constructs a jointree for the Bayesian network using a minfill heuristic. From this jointree, it selects an f-tree: a connected sub-tree that includes the class variable Y and all feature variables X, ideally containing many feature-splitting edges (separators that contain no Y or X variables). The f-tree defines a recursive partitioning of features: each edge splits the tree into two sides, and for a feature-splitting edge, the separator d-separates the features on Y’s side (U) from those on the other side (V). This yields the factorisation P(Y,X)=P(Y,U,s)·P(V|s).

Second, for a target class y_i, the algorithm compiles an AND-decomposable NNF representing the negative instances (all x where some other class y_j has at least as high posterior). It does so by recursively traversing the f-tree. At a node q, given a factor M over Y, the fixed U, and the separator from the parent, it first calls `decide-negative` to check if the current partial instantiation already determines negativity via the sign of Δ_ij_S(u). If undecided, it processes the left child: enumerates all instantiations v_l of V_l (the features in the left subtree), projects M to obtain M_qr = P(Y,u,v_l,S_qr) for the right child, and recursively compiles an NNF α over V_r. Since V_l and V_r are disjoint, the conjunction v_l ∧ α is AND-decomposable; collecting all such terms and disjoining them preserves AND-decomposability. The recursion bottoms out at leaves where all features are instantiated.

Third, the resulting AND-decomposable NNF for negatives is negated (using NNF’s De Morgan laws) to produce an OR-decomposable NNF for the positive class Π_i. This OR-decomposability ensures that queries for explanations can be answered efficiently, e.g., by checking validity or performing model counting. The overall time complexity is O(n exp ω_T), where ω_T is the maximum of the jointree width ω and additional parameters ω_R, ω_L that capture the sizes of U_q and V_q along critical paths of the f-tree. The width ω_T is typically far smaller than ω+|X|, providing an exponential advantage.

## Key Results

- Solved 492 out of 554 benchmark problems (vs. 166 by baseline) within a 4-hour timeout.

## Why This Works (Mechanism)

### Early Classification via Feature-Splitting Edges
The algorithm exploits feature-splitting edges in the f-tree—edges whose separator contains no variable from Y∪X. For such an edge, the separator d-separates the feature set U (on the Y side) from V (the other side). The joint distribution factorises as P(Y,U,s)·P(V|s). Given a partial instantiation u on U, the classification condition P(y_i|u) > P(y_j|u) is equivalent to the sign of Δ_ij_S(u) = Σ_s (P(y_i,u,s)−P(y_j,u,s)). If this sum is uniformly positive (or negative) over all s, the decision between y_i and y_j is already determined without instantiating any feature in V. This early classification can terminate recursion early, avoiding enumeration of V. The presence of feature-splitting edges is therefore crucial for efficiency; if none exist, the algorithm degrades to full enumeration.

### Recursive AND-Decomposable Compilation
The negative class set for y_i is compiled into an AND-decomposable NNF via a depth-first traversal of the f-tree. Starting at the root with factor M = P(Y,∅,S_root), the procedure `compile-negative(q, M)` first checks `decide-negative(M, S_pq, y_i)`. If it yields true/false, a trivial circuit (true or false) is returned. Otherwise, it processes the left child: for each instantiation v_l of V_l (the features in the left subtree), it projects M onto v_l and S_qr to obtain M_qr = P(Y,u,v_l,S_qr). It then recursively compiles an NNF α_r from the right child. The conjunction (v_l ∧ α_r) is added to a set of terms. Because V_l and V_R are disjoint, these terms are AND-decomposable; their disjunction yields an AND-decomposable NNF. The recursion ensures that all necessary combinations are covered. The correctness follows from the factorisation along edges and the disjointness of V_l and V_r. Assumptions: the f-tree is binary and features are only in leaves; otherwise the decomposition may break.

### Reduced Compilation Width ω_T
The time complexity is bounded by O(n exp ω_T), where ω_T = max(ω, ω_R, ω_L). Here ω is the jointree width (size of largest cluster minus one), ω_R = max_{q on rightmost path} (|U_q|+|C_q|), and ω_L = max_{q in left children} (|V_q|+ftw(q)). Intuitively, ω_T replaces the brute-force exponent ω+|X| because early classification often limits the effective number of features that need to be enumerated within a single recursive call: along the rightmost path, only U_q (features left of the path) matter, and along left children, only V_q (features in that subtree) matter. Empirically, ω_T is much smaller than ω+|X|, as shown in Table 2 for the benchmark networks. This reduction is the source of the exponential speedup; however, the advantage depends on the f-tree structure. An unbalanced f-tree or separators that include many features can make |U_q| or |V_q| large, pushing ω_T toward ω+|X|.

## Architecture Onboarding

**Component map:**  
JointreeBuilder → constructs jointree → FTreeBuilder (selects f-tree) & FactorManager (computes marginals, caches factors). CircuitBuilder uses these for each target class y_i: calls CompileNegative(root, P(Y,∅,S_root)). CompileNegative traverses f-tree; at each node, invokes DecideNegative (which checks early classification using Theorem 1). If undecided, CompileNegative enlists FactorManager to project factors and enumerates left subtree instantiations, then recurses on right child. The output of CompileNegative (AND-decomposable NNF) is passed back to CircuitBuilder, which negates it to produce an OR-decomposable class formula.

**Critical path:** For each target class y_i:
1. Obtain an f-tree (precomputed) and initial factor P(Y,∅,S_root) from FactorManager.
2. Call `compile-negative(root, M)`. At a node q with parent separator S_pq, first execute `decide-negative(M, S_pq, y_i)`. If it yields true/false, return the corresponding constant circuit.
3. Otherwise, enumerate all instantiations v_l of the left subtree’s feature set V_l. For each v_l, compute M_qr = P(Y,u,v_l,S_qr) via FactorManager.
4. Recursively compile the right child with M_qr to obtain α_r.
5. Conjoin v_l with α_r, collect all such terms, and disjoin them to form an AND-decomposable NNF for this node.
6. Propagate result upwards. After recursion finishes, the root returns an AND-decomposable NNF representing all x where y_i is not the maximum-posterior class.
7. CircuitBuilder negates this NNF to get the OR-decomposable circuit for Π_i.

**Design tradeoffs:**
- *f-tree selection*: Choosing an f-tree with many feature-splitting edges maximises early classification opportunities, reducing ω_R and ω_L. However, finding an optimal f-tree is NP-hard; the paper uses a heuristic (pruning a jointree), which may sacrifice some partitioning benefits for simplicity.
- *Memory vs. time*: FactorManager caches conditional factors P(V|S_pq) for each node to avoid redundant computation. This uses exponential memory in |V_q|+ftw(q). For large subtrees, caching may be infeasible, forcing a time-memory tradeoff (e.g., recomputation).
- *Binary vs. multi-class*: The algorithm treats multi-class naturally by comparing all other classes in `decide-negative`. There is no extra penalty per class beyond compiling one NNF per class, making it more scalable than prior OBDD-based methods that struggled with multiple classes.

**Failure signatures:**
- **No early classification**: If `decide-negative` almost never returns early, the recursion enumerates nearly all feature instantiations, leading to exponential blowup. Monitor the fraction of `decide-negative` calls that return nil (undecided).
- **High compilation width ω_T**: When ω_T approaches ω+|X|, the theoretical advantage vanishes. Compute ω_T; if it is only slightly less than ω+|X|, the f-tree likely lacks sufficient splitting edges or is unbalanced.
- **Memory overflow**: If a node q has |V_q| large, the cached factor P(V|S_pq) may consume excessive memory. Track per-node memory usage; consider disabling caching or using approximation if memory is exhausted.

**First experiments:**

## Open Questions the Paper Calls Out

1. **Scaling with number of classes**: The algorithm is designed for multi-class BNCs, but experiments were restricted to binary target variables. How does compilation time and success rate scale with the number of classes? An evaluation on a diverse set of multi-class networks is needed.
2. **Network characteristics for width advantage**: Which structural properties of a Bayesian network (e.g., jointree width, feature count, connectivity) lead to a large gap between ω_T and ω+|X|? The empirical evidence is limited to five networks; a broader study could identify predictors.
3. **Automatic f-tree construction**: The algorithm requires an f-tree as input but does not specify how to obtain one that minimises ω_T. An optimal or heuristic method for constructing low-width f-trees would improve performance guarantees.
4. **Circuit size growth with classes/features**: How does the size of the compiled OR-decomposable NNF scale with the number of classes and the cardinality of feature variables? Can size be controlled (e.g., via simplification) without losing OR-decomposability? This is important for large problems.

## Limitations

- **Incomplete benchmark specification**: The paper does not provide the exact feature subsets and thresholds for the 554 problems, making exact replication difficult.
- **Underspecified jointree/f-tree construction**: The use of a minfill heuristic and f-tree selection is described only at a high level; variations in tie-breaking or pruning could lead to different widths and runtimes.
- **Ambiguous circuit size comparison**: The paper compares NNF node counts to OBDD node counts, but it is unclear whether these metrics are directly comparable; a uniform measure is needed to validate the claim of comparable circuit sizes.
