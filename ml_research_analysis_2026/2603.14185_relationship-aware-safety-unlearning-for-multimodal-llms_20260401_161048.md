# Relationship-Aware Safety Unlearning for Multimodal LLMs
## Quick Facts
- arXiv ID: 2603.14185
- Source URL: https://arxiv.org/abs/2603.14185
- Reference count: 40
- Primary result: Relationship-aware unlearning on CLIP achieves average forgetting ∆cos ≈ 0.62 against paraphrase, contextual, and OOD attacks, while preserving safe concepts with minimal drift (0.0115–0.0608).

## Executive Summary
The paper introduces a relationship-aware safety unlearning framework for multimodal large language models, focusing on eliminating unsafe object-relation-object (O-R-O) tuples like "child–drinking–wine". Unlike prior unlearning methods that target isolated concepts and cause collateral damage, this approach constructs a graph of unsafe and safe relations and applies targeted edits via LoRA adapters. A multi-objective loss simultaneously suppresses unsafe relational embeddings while preserving individual objects, safe neighboring relations, and model consistency, with an adversarial term for robustness. Evaluated on CLIP by removing "kid eating hamburger", the method achieves substantial forgetting (average ∆cos ≈ 0.62) under diverse attacks and retains utility with minimal drift on preserved concepts, demonstrating selective relational unlearning.

## Method Summary
The method comprises three main steps. First, an unsafe O-R-O tuple is represented as a graph where nodes are objects and edges are relations. For the unsafe edge (e.g., child–drinking–wine), safe neighboring tuples are added: alternative objects for the same relation (adult–drinking–wine), alternative relations for the same objects (child–holding–wine), and a new safe relation between original objects (child–eating–wine). Second, synthetic image-text pairs for all graph elements (unsafe, safe edges/nodes, neutral concepts, and adversarial variants) are generated using Gemini or similar models. Third, a multi-objective loss is computed on CLIP embeddings: L3 pushes unsafe O-R-O embeddings apart; L1/L2/L4 pull safe edges, safe nodes, and neutral concepts together; Lc enforces consistency with the base model; Ladv adversarially pushes paraphrased/contextual/ood unsafe variants. The loss is optimized via AdamW on low-rank adapter weights (LoRA) injected into CLIP’s attention and projection layers, keeping the base model frozen. Evaluation uses cosine similarity changes (∆cos) on attack sets and absolute drift on preservation sets.

## Key Results
- Forgetting robustness: average ∆cos ≈ 0.62 across paraphrase, contextual, and out-of-distribution image attacks.
- Utility preservation: minimal absolute drift (0.0115–0.0608) on safe single nodes, new safe edges, new safe nodes, and neutral edges.
- Ablation: using only the unsafe push term (L3) severely degrades utility, confirming the necessity of the full balanced loss design.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Graph representation of O-R-O tuples enables selective suppression of specific relational edges while preserving individual object and safe-relation representations.
- **Mechanism:** The graph explicitly marks the unsafe edge (e.g., child–wine via drinking) and includes safe neighbors (e.g., adult–drinking–wine, child–holding–wine). The loss is guided to adjust only the embeddings corresponding to the unsafe association.
- **Core assumption:** Model relational knowledge is separable in embedding space such that editing similarity for a specific triple does not broadly affect marginal object embeddings.
- **Evidence anchors:** Abstract and Section 3.1 detail graph construction; ablation (full loss needed) supports the approach.

### Mechanism 2
- **Claim:** The multi-objective loss balances forgetting and preservation by combining push and pull terms with consistency regularization and adversarial robustness.
- **Mechanism:** Six terms: L3 (unsafe push), L1/L2/L4 (safe edge/node/neutral pull), Lc (consistency via MSE), Ladv (adversarial push). Their gradients can be balanced via hyperparameters to target only unsafe relations.
- **Core assumption:** Loss terms are compatible and can be weighted to avoid interference.
- **Evidence anchors:** Loss equation in Section 3.2; convergence plots in Section 4.5; ablation (removing Lc or Ladv) in Section 4.7 shows performance drop.

### Mechanism 3
- **Claim:** LoRA confines updates to low-rank adapters, enabling parameter-efficient unlearning with minimal changes to the base model, thereby preserving broad utility.
- **Mechanism:** LoRA injects trainable matrices B, A such that ΔW = BA into attention and projection layers; only these adapters are trained, leaving pretrained weights frozen.
- **Core assumption:** Unsafe relational information is sufficiently localized in the adapted layers and can be modified with low-rank updates.
- **Evidence anchors:** Abstract and Section 3.2 describe LoRA use; Section 6 highlights minimal preservation drift; PEFT literature supports general efficiency.

  *Why needed:* The paper’s loss extends standard unlearning to a relational context with multiple preservation terms; knowing baseline MU helps understand the novelty.  
  *Quick check:* What is the risk of using only a forget-set gradient (no retention terms) when unlearning in large models?

- **Concept:** Parameter-efficient fine-tuning (LoRA).  
  *Why needed:* LoRA is the mechanism for applying updates; understanding its low-rank decomposition, where it’s inserted, and why it’s memory-efficient is key to replicating the approach.  
  *Quick check:* How does LoRA’s low-rank adaptation (W + ΔW = W + BA) avoid catastrophic forgetting compared to full fine-tuning?

## Architecture Onboarding
**Component map:** Graph Builder -> Data Synthesizer -> Loss Calculator -> LoRA Adapter -> Base Model

**Critical path:** Define unsafe tuple -> Build relational graph -> Generate synthetic data for all graph terms -> Compute multi-objective loss using base embeddings -> Backprop through LoRA adapters -> Update adapters -> Evaluate cosine similarity on test attacks and preservation cases.

**Design tradeoffs:**  
- Hyperparameter balancing (α, β, δ, γ, λ_adv) affects forgetting-utility trade-off; requires careful tuning.  
- Graph completeness: Omitting safe neighbors risks collateral damage; including too many increases data generation and compute.  
- LoRA rank: Higher rank may capture edits better but increases memory; lower rank may insufficiently forget.  
- Synthetic data quality: Generated images/texts must accurately reflect concepts; low quality harms loss signal.

**Failure signatures:**  
- High absolute drift on safe node/edge metrics (|Δcos| > 0.1) indicates utility degradation.  
- Low forgetting (Δcos < 0.3) on paraphrase/contextual/OOD attacks means unlearning is brittle.  
- Loss curves: Consistency loss (Lc) rising suggests destabilization; adversarial loss (Ladv) not decreasing may leave model vulnerable.  
- LoRA gradient norms: Outlier magnitudes could indicate conflicting loss terms or poor hyperparameters.

**First 3 experiments:**  
1. **Baseline sanity check:** Train with only L3 (unsafe push) vs. full loss. Expect baseline forgets but destroys utility; full model balances.  
2. **Ablation study:** Remove one loss term at a time (e.g., no Lc, no Ladv) and measure ∆cos on unsafe attacks and preservation cases. Expect missing Lc increases drift; missing Ladv reduces robustness.  
3. **Attack robustness:** After full training, test on held-out paraphrase prompts, contextual variations, and OOD images. Expect significant ∆cos (>0.4) across all, confirming generalized forgetting.

## Open Questions the Paper Calls Out
#### Open Question 1
- **Question:** How can causal tracing and selective pruning achieve surgical unlearning of unsafe O-R-O tuples with minimal parameter updates and zero collateral damage?
- **Basis in paper:** Section 5.1 proposes investigating "Causal Tracing and Neuron Pruning" to identify minimal neurons for unlearning.
- **Why unresolved:** The current method uses LoRA adapters with broad updates; no implementation or evaluation of neuron-level edits exists.
- **What evidence would resolve it:** Identify causal neurons via tracing, prune them, and measure forgetting efficacy vs. utility loss compared to LoRA.

#### Open Question 2
- **Question:** Can proactive adversarial data generation using a red-team model significantly improve robustness against paraphrased and compositional attacks compared to the current static L_adv?
- **Basis in paper:** Section 5.2 suggests employing a "Red-Team Generative Model" to create challenging adversarial prompts.
- **Why unresolved:** L_adv currently uses basic paraphrases; the impact of dynamic, hard adversarial examples is untested.
- **What evidence would resolve it:** Train with adversarially generated prompts, evaluate on a compositional robustness benchmark, compare forgetting stability metrics.

#### Open Question 3
- **Question:** What is a standardized, auditable Relational Safety Score (RSS) that quantifies both suppression of unsafe tuples and preservation of safe concepts?
- **Basis in paper:** Section 5.4 proposes formalizing an RSS combining suppression rate, preservation rate, and attack resistance.
- **Why unresolved:** No concrete definition or validation; current metrics are disparate (∆cos, drift).
- **What evidence would resolve it:** Define RSS formula, validate against human judgments on diverse O-R-O scenarios, correlate with downstream task performance.

#### Open Question 4
- **Question:** How can the relationship-aware unlearning framework be adapted to generative multimodal LLMs (e.g., diffusion models) to prevent generation of unsafe compositions?
- **Basis in paper:** Section 5.3 states scaling to generative models is needed, specifically targeting diffusion U-Net layers.
- **Why unresolved:** The paper only evaluates on CLIP encoders; generator-side unlearning with probability-based losses is unexplored.
- **What evidence would resolve it:** Modify loss to minimize unsafe generation probability, test on Stable Diffusion with image quality and safety metrics.

## Limitations
- Graph construction specifics (selection and number of safe neighboring tuples) are underspecified, limiting reproducibility and scalability.
- Loss balancing hyperparameters and LoRA rank sensitivity are not systematically studied, leaving the robustness of the forgetting-utility trade-off uncertain.
- The method relies entirely on synthetic data for training, raising concerns about overfitting and real-world transferability.
- Evaluation is restricted to a single unsafe tuple; scalability to multiple interconnected unsafe concepts remains unproven.

## Confidence
- Graph-based representation enables selective relational editing: **Medium**
- Multi-objective loss balances forgetting and utility: **Medium-High**
- LoRA enables parameter-efficient, minimal-drift unlearning: **High**
- Method achieves robust forgetting under diverse attacks: **Medium**
