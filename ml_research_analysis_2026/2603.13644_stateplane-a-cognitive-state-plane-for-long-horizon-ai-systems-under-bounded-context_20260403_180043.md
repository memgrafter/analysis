# StatePlane: A Cognitive State Plane for Long-Horizon AI Systems Under Bounded Context

## Quick Facts
- arXiv ID: 2603.13644
- Source URL: https://arxiv.org/abs/2603.13644
- Reference count: 4
- Primary result: StatePlane introduces a model-agnostic cognitive state plane that externalizes and manages episodic, semantic, and procedural state via selective encoding, goal-conditioned retrieval, and bounded reconstruction, achieving long-horizon reasoning without expanding context windows or retraining models.

## Executive Summary
StatePlane addresses the failure of LLMs/SLMs to maintain coherent state across long interactions due to bounded context. It introduces a model-agnostic cognitive state plane that externalizes and manages episodic, semantic, and procedural state via selective encoding, goal-conditioned retrieval, and bounded reconstruction. The core result is a formal framework and reference architecture that achieves long-horizon reasoning without expanding context windows or retraining models, including KV-aware algorithms, security mechanisms (write-path anti-poisoning), and an evaluation suite with six benchmarks measuring commitment compliance, rationale stability, and adversarial robustness.

## Method Summary
StatePlane implements a model-agnostic control plane with two main APIs: `PrepareContext` (read path) and `CommitOutcome` (write path). A PostgreSQL store holds typed state objects (MemoryFact, Episode, Procedure) with hierarchical namespaces. Selective encoding uses an information bottleneck to compress interaction history into a latent state that retains only future-relevant information. Goal-conditioned retrieval classifies query intent and applies policy filters to retrieve evidence-type state objects. Bounded reconstruction synthesizes a minimal context patch that adheres to a strict token budget, preserving logical dependencies. The security layer includes write-path anti-poisoning and audit logging.

## Key Results
- Formal framework and reference architecture for long-horizon reasoning without context expansion or retraining.
- KV-aware algorithms and security mechanisms including write-path anti-poisoning.
- Evaluation suite with six benchmarks measuring commitment compliance, rationale stability, and adversarial robustness.

## Why This Works (Mechanism)
### Mechanism 1: Selective Encoding via Information Bottleneck
- **Claim:** Selective encoding via an information bottleneck preserves decision-relevant state while discarding noise, enabling continuity under bounded capacity.
- **Mechanism:** An information-theoretic objective (min I(S;H) - β·I(S;Y_future)) compresses interaction history H into a latent state S that retains only information predictive of future outcomes Y.
- **Core assumption:** The utility of past experience for future decisions can be captured by a low-dimensional representation S, and β can be tuned to balance compression with relevance.
- **Evidence anchors:** [abstract] "selective encoding via information-theoretic constraints"; [section VI.C] formalizes the bottleneck objective (Equation 3).
- **Break condition:** If future utility (Y_future) is poorly modeled or salience signals are miscalibrated, critical state may be pruned, leading to loss of binding constraints.

### Mechanism 2: Goal-Conditioned Retrieval with Typed Evidence Semantics
- **Claim:** Goal-conditioned retrieval with typed evidence semantics reconstructs context that is policy-compliant and minimally sufficient, preventing prompt injection and scope leakage.
- **Mechanism:** The retriever classifies query intent (factual/procedural/experiential) and applies policy filters (π) to ranking. Retrieved objects are typed (MemoryFact, Episode, Procedure) and treated as "evidence, not instruction," blocking imperative text from overriding system policy.
- **Core assumption:** Intent can be reliably classified from the current query and active policy scope, and typed schemas are sufficient to enforce semantic boundaries.
- **Evidence anchors:** [abstract] "goal-conditioned retrieval with intent routing" and "retrieved state is evidence, not instruction."; [section V.A, IX.C] details intent routing and the "evidence not instruction" guardrail.
- **Break condition:** Intent misclassification or insufficient policy rules will retrieve irrelevant or non-compliant state, causing reasoning errors or policy violations.

### Mechanism 3: Bounded Reconstruction Guarantee
- **Claim:** Bounded reconstruction guarantees |C_t| ≤ L_max at every invocation by synthesizing constraints and commitments from retrieved state, not by copying fragments.
- **Mechanism:** The State Reconstructor takes retrieved state objects and generates a minimal, coherent context patch that fits the token budget, preserving logical dependencies (e.g., "because of X, Y is binding").
- **Core assumption:** The state objects contain sufficient structured data (goals, rationales, preconditions) to reconstruct causal and normative links without the original text.
- **Evidence anchors:** [abstract] "bounded reconstruction" and "composes bounded working context."; [section VI.D] formalizes the hard token budget constraint (Equation 4).
- **Break condition:** If state objects lack necessary rationale or precondition fields, reconstruction will produce incomplete or contradictory context, violating commitment compliance.

## Foundational Learning
### Episodic Segmentation (Tulving, 1972)
- **Why needed here:** StatePlane must identify event boundaries to trigger encoding. Without accurate segmentation, state bloat occurs or critical transitions are missed.
- **Quick check question:** What signal would indicate a "goal shift" in a customer support dialogue: a new topic, an explicit statement, or a change in action pattern?

### Information Bottleneck (Tishby et al., 2000)
- **Why needed here:** Underlies selective encoding (Equation 3). An engineer must understand the trade-off β to configure compression vs. retention.
- **Quick check question:** If β is set too high (strong compression), what type of information is most likely to be lost: frequently repeated facts or rare but critical exceptions?

### Goal-Conditioned Retrieval
- **Why needed here:** Prevents "shotgun" retrieval of irrelevant history. The query's goal (g_t) and scope must align with stored state's metadata.
- **Quick check question:** How does the "scope" parameter (e.g., `case/project/*`) prevent a model from retrieving a user's personal preference into an organizational compliance check?

## Architecture Onboarding
**Component map:** Event Boundary Detector -> Episodic Encoder -> State Store -> Goal-Conditioned Retriever -> State Reconstructor -> Security Layer

**Critical path:** The two-call contract: (1) `PrepareContext` → Retriever/Reconstructor → C_t, (2) `CommitOutcome` → Encoder/WriteGate → State Store. All state evolution flows through this path.

**Design tradeoffs:**
- Salience estimation cost vs. accuracy: Complex models improve boundary detection but add latency; lightweight heuristics are faster but miss subtle shifts.
- Write gate strictness vs. utility: Aggressive filtering blocks poisoning but may reject valid insights; permissive filtering risks state bloat.
- Namespace granularity: Fine-grained scopes improve isolation but complicate policy management; broad scopes risk leakage.

**Failure signatures:**
- State bloat: State Store grows exponentially → check decay parameters (λ) and pruning threshold (ϵ).
- Reconstruction truncation: C_t consistently hits L_max with incomplete rationale → check salience scores and retrieval ranking.
- Cross-scope leakage: Sensitive data appears in C_t for a narrower scope → audit ABAC rules and namespace mappings.

**First 3 experiments:**
1. Bounded reconstruction stress test: With L_max = 512, 1024, 2048 tokens, measure Commitment Compliance Rate (CCR) on the LH-PCT benchmark. Expect CCR to plateau if reconstruction preserves key constraints.
2. Write-path poisoning defense: Simulate adversarial inputs that try to promote malicious procedures. Measure Policy Violation Rate (PVR) with write gate ON vs. OFF. Expect PVR near 0 with gate ON.
3. Ablation: Salience estimator: Replace the salience function with a naive length-based heuristic. Track Exception Handling Accuracy (EHA) on the ELR benchmark. Expect significant drop if heuristic misses critical exceptions.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can salience estimation algorithms be improved to better capture task-relevant information for retrieval in StatePlane?
- **Basis in paper:** [explicit] The limitations state: "salience quality directly affects retrieval relevance."
- **Why unresolved:** The current salience function (utility, surprise, novelty) may not fully align with all domain-specific decision contexts, risking retrieval of suboptimal state.
- **What evidence would resolve it:** Empirical studies comparing different salience models across the six benchmarks, measuring correlation between salience scores and downstream decision correctness or commitment compliance.

### Open Question 2
- **Question:** Can write-path gating mechanisms be optimized to reduce latency without compromising security or governance guarantees?
- **Basis in paper:** [explicit] The limitations note: "write gate introduces latency."
- **Why unresolved:** The trade-off between thorough security checks and system responsiveness is not quantified; real-time applications may be impeded.
- **What evidence would resolve it:** Benchmarking write-path latency under varying policy strictness and load, developing asynchronous or tiered gating prototypes, and evaluating impact on end-to-end task completion time and security incident rates.

### Open Question 3
- **Question:** How does StatePlane perform when the underlying agent model acts adversarially or negligently, violating the assumed agent-plane cooperation?
- **Basis in paper:** [explicit] The limitations state: "governance assumes agent–plane cooperation."
- **Why unresolved:** The threat model addresses external attacks but not compromised or malicious internal agents that could deliberately malform events, bypass gates, or misuse retrieved state.
- **What evidence would resolve it:** Red-team testing where agent models are prompted to exfiltrate state, poison the store, or ignore policy constraints; measuring breach rates and identifying residual vulnerabilities.

### Open Question 4
- **Question:** Do the proposed six benchmarks sufficiently and robustly measure long-horizon state management across diverse real-world domains?
- **Basis in paper:** [explicit] The limitations state: "benchmarks depend on domain definition quality."
- **Why unresolved:** The benchmarks are synthetic or narrowly defined; their ability to generalize to unforeseen long-horizon tasks is unproven.
- **What evidence would resolve it:** Independent replication studies across new domains, expert evaluations of benchmark fidelity to real-world complexity, and correlation analysis between benchmark scores and actual enterprise deployment outcomes.

### Open Question 5
- **Question:** Could a controlled form of memory reconsolidation be integrated into StatePlane without breaking provenance, auditability, and reproducibility?
- **Basis in paper:** [explicit] The discussion states: "StatePlane deliberately rejects implicit reconsolidation... instead, supports explicit evolution through its promotion lifecycle."
- **Why unresolved:** Explicit promotion is rigid; real-world knowledge often requires subtle updates upon recall. Forgoing all reconsolidation may limit adaptability and force unnecessary duplication.
- **What evidence would resolve it:** Designing a versioned reconsolidation protocol (e.g., creating new state objects with links to originals), then testing if audit trails remain comprehensible and if decision quality improves on dynamic tasks.

## Limitations
- **Unspecified Algorithms:** The exact implementation of the Event Boundary Detector and Salience function is not provided; their design—especially computing future utility without oracle knowledge—remains a conceptual gap.
- **Schema Dependency:** The reconstruction guarantee assumes state objects always capture necessary causal/normative links; if encoding omits critical rationale fields, reconstruction will fail silently.
- **Policy & Scope Complexity:** Correctness of "evidence not instruction" enforcement depends on exhaustive, perfectly calibrated policy rules and scope definitions, which are not detailed and likely brittle in complex deployments.
