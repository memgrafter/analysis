# Efficient Crawling for Scalable Web Data Acquisition (Extended Version)

## Quick Facts
- **arXiv ID**: 2602.11874  
- **Source URL**: https://arxiv.org/abs/2602.11874  
- **Reference count**: 40  
- **Primary result**: SB‑CLASSIFIER retrieves 90% of statistical dataset targets while crawling only ~20% of pages on large websites, achieving greater efficiency (fewer HTTP requests, less non-target data) than baseline crawlers.

## Executive Summary
Efficiently locating statistical dataset (SD) files on large websites is challenging because exhaustive crawling is too costly and search engines index only a small fraction. This paper introduces SB‑CLASSIFIER, a focused crawler that combines reinforcement learning with sleeping bandits to prioritize link groups likely to lead to new targets. By clustering hyperlinks with similar DOM tag paths into actions and using an online URL classifier (trained on 2‑gram features) to estimate target likelihood without fetching content, SB‑CLASSIFIER minimizes unnecessary HTTP requests. Across 18 websites (22.2M pages), it significantly outperforms baselines (BFS, FOCUSED, TP‑OFF, TRES), retrieving 90% of targets while crawling only about 20% of pages on large sites, and generally requires the fewest requests and least non-target data volume to reach 90% coverage.

## Method Summary
SB‑CLASSIFIER operates as a reinforcement learning agent where actions correspond to clusters of hyperlinks sharing similar DOM tag paths. The agent uses a sleeping bandits framework: actions (clusters) can be inactive (“asleep”) if deemed unpromising, conserving resources. A lightweight URL classifier, trained incrementally on character 2‑grams, predicts the probability that a given URL leads to an SD file. This prediction informs the reward signal (number of newly discovered targets) and allows the agent to estimate action values without incurring expensive HEAD requests. The crawler iteratively selects an action, fetches a URL from its associated frontier, extracts any SD files from the page, updates the classifier, and adjusts the action’s value using a learning rate controlled by parameter α. Clustering similarity is governed by threshold θ; optimal settings were found at θ=0.75, α=2√2 with a logistic regression classifier on URL‑only features.

## Key Results
- On large sites (e.g., il, wh), SB‑CLASSIFIER achieves 90% target recall while crawling only ~20% of the total pages.
- It significantly outperforms four baseline crawlers (BFS, FOCUSED, TP‑OFF, TRES) in both coverage and efficiency metrics (HTTP requests, non-target data volume).
- The best configuration employs 2‑gram URL features, a similarity threshold θ=0.75, α=2√2, and logistic regression on URL‑only data.

## Why This Works (Mechanism)
SB‑CLASSIFIER’s efficiency stems from three synergistic design choices. First, grouping links by DOM tag path into actions reduces the combinatorial action space while preserving contextual cues: links that appear in similar page locations often have comparable relevance to targets. Second, the sleeping bandits mechanism dynamically prioritizes promising actions and temporarily disables low‑yield ones, focusing crawl budget on high‑value regions. Third, the URL‑only classifier provides a cheap, real‑time estimate of target likelihood, enabling accurate reward attribution and value updates without fetching pages solely for assessment. Together these elements allow the crawler to learn a policy that rapidly homes in on SD files, bypassing vast swaths of irrelevant content.

## Foundational Learning
- **Reinforcement Learning (RL)**: Provides the framework for sequential decision‑making under delayed reward. *Why needed*: Crawling is a sequential process where each URL choice impacts future discovery. *Quick check*: Understand Markov Decision Processes, value functions, and policies.
- **Multi‑Armed Bandits (MAB)**: A simplified RL setting balancing exploration and exploitation. *Why needed*: At each step the crawler must choose an action without knowing future outcomes. *Quick check*: Know ε‑greedy and Upper Confidence Bound (UCB) strategies.
- **Sleeping Bandits**: An MAB variant where only a subset of arms is active. *Why needed*: The crawler’s action space (link clusters) is huge; sleeping bandits allow ignoring low‑potential clusters to save resources. *Quick check*: Familiar with Sleep‑Rank or similar algorithms that manage arm activation.
- **URL‑Based Classification with n‑grams**: Extracts character‑level patterns from URLs to predict content type. *Why needed*: Fetching content to decide relevance is expensive; URL cues often suffice. *Quick check*: See how n‑gram features are generated and used with logistic regression.
- **DOM Tag Path Analysis**: The structural path in the HTML tree (e.g., `/html/body/div[2]/a`) identifies link context. *Why needed*: Links sharing similar tag paths often lead to similar content, enabling meaningful clustering. *Quick check*: Understand XPath or CSS selector syntax.
- **Focused Crawling**: Tailors the crawl to a specific information need. *Why needed*: General web crawling is unfocused; here the goal is to retrieve statistical datasets only. *Quick check*: Review classic focused crawling strategies (e.g., best‑first, context graphs).

## Architecture Onboarding
**Component Map**:  
URL Frontier → Action Clustering (by DOM tag path) → Sleeping Bandits RL Agent (policy selects action) → Fetch Module (retrieves page) → Target Extractor (identifies SD files) → Reward Calculator (counts new targets) → RL Agent (updates action value) ↔ URL Classifier (online update with URL features and label)

**Critical Path**:
1. Incoming URL is assigned to a cluster (action) based on its DOM tag path similarity to existing clusters (θ threshold).
2. The RL agent, using sleeping bandits, picks an active action; if chosen action is asleep, it is woken with some probability.
3. A URL from the selected action’s sub‑frontier is dequeued and fetched.
4. Page content is scanned for known SD file extensions/patterns; discovered new files increment the reward.
5. The action’s value is updated: \( Q_{\text{new}} = (1-\alpha)Q_{\text{old}} + \alpha \times \text{reward} \), where α controls learning rate.
6. The URL classifier is trained incrementally on the fetched URL’s 2‑gram features and the binary label (target found?).

**Design Tradeoffs**:
- *Clustering granularity*: Higher θ yields fewer, larger actions (faster learning but less precision); lower θ increases action space (more nuanced but slower).
- *URL‑only inference*: Forgoes content‑based cues for speed, potentially missing targets whose URLs lack distinguishing patterns.
- *Sleeping bandits*: Allows scaling to many actions but introduces complexity in managing sleep schedules and wake thresholds.
- *Simple n‑gram features*: Fast to compute and robust to minor variations, yet may not capture semantic regularities.

**Failure Signatures**:
- *Poor recall*: RL agent over‑exploits a few actions; adjust α or exploration rate.
- *High non‑target fetch rate*: Clustering fails to separate target‑rich from target‑poor links; lower θ or revise similarity metric.
- *Classifier underperformance*: Target prediction accuracy drops; increase feature size (e.g., 3‑grams) or collect more training data.
- *Memory blowup*: Number of distinct actions grows unchecked; increase θ or implement action merging.

**First Three Experiments**:
1. Baseline comparison: Run SB‑CLASSIFIER against BFS, FOCUSED, TP‑OFF, and TRES on a held‑out website; measure target coverage vs. pages crawled and data volume.
2. Parameter sensitivity: Vary θ (e.g., 0.5–0.9) and α (e.g., 0.1–2√2) to gauge impact on recall and efficiency; locate stable operating region.
3. Ablation study: Disable the sleeping bandits mechanism (i.e., treat all actions always active) and/or replace the URL classifier with random guessing; quantify contribution of each component to overall performance.

## Limitations
- Evaluation covered only 18 websites, raising concerns about generalizability and possible selection bias.
- The approach assumes static HTML; its effectiveness on JavaScript‑heavy or dynamically rendered sites remains unknown.
- The URL classifier’s reliance on simple 2‑grams may not generalize to novel URL patterns not seen during training.
- Clustering based solely on DOM tag paths could be brittle across diverse website templates.
- No overhead metrics (CPU, memory) for the RL agent at scale are reported.

## Confidence

- Requires fewest HTTP requests and least non‑target data volume generally: **Medium**
- Optimal configuration (2‑grams, θ=0.75, α=2√2, logistic regression) is robust: **High**

## Next Checks
