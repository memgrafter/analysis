# LongCat-Flash-Prover: Advancing Native Formal Reasoning via Agentic Tool-Integrated Reinforcement Learning

## Quick Facts
- **arXiv ID:** 2603.21065
- **Source URL:** https://arxiv.org/abs/2603.21065
- **Reference count:** 40
- **Primary result:** 560B MoE model achieves new SOTA for open-weights models: 97.1% pass@72 on MiniF2F-Test, 70.8% on ProverBench, 41.5% on PutnamBench (≤220 attempts).

## Executive Summary
LongCat-Flash-Prover introduces a 560-billion-parameter Mixture-of-Experts model that advances formal reasoning in Lean4. The approach decomposes native formal reasoning into three independent capabilities—auto-formalization, lemma-style sketching, and whole-proof generation—orchestrated by a Hybrid-Experts Iteration Framework that synthesizes verified trajectories using Lean4 verification tools. Training stability for long-horizon tasks is achieved via Hierarchical Importance Sampling Policy Optimization (HisPO), which applies hierarchical gradient masking to mitigate train-inference discrepancies and policy staleness. Legality detection through Abstract Syntax Tree consistency checks prevents reward hacking. The system yields substantial improvements across multiple formal reasoning benchmarks while retaining competitive informal reasoning performance.

## Method Summary
The pipeline starts with a cold-start phase: using an auto-formalizer (ATF-32B) and a reasoning model (LongCat-Flash-Thinking-2601), the Hybrid-Experts framework generates trajectories (auto-formalized statements, whole proofs, sketch-then-complete chains). These, combined with general reasoning data, train the base LongCat Mid-train Base (560B MoE, ~27B active) via domain-mixed supervised fine-tuning to produce a cold-start model. Multiple iterations of agentic tool-integrated reinforcement learning (TIR) then follow, where the model interacts with a Lean4 server. HisPO optimizes the policy using importance sampling with hierarchical gradient masking—both sequence-level and token-level—to handle asynchronous training infrastructure (Megatron for optimization, vLLM for rollouts). Legality detection via AST checks is embedded in the reward function. Cycles repeat, each time synthesizing new trajectories and refining the model.

## Key Results
- 97.1% pass@72 on MiniF2F-Test, 70.8% on ProverBench, 41.5% on PutnamBench (≤220 attempts), setting a new SOTA for open-weights models.
- Tool integration with Lean4 verification yields up to 14% absolute improvement in pass rates.
- Maintains competitive informal reasoning performance on benchmarks like AIME and HMMT, with only minor declines.

## Why This Works (Mechanism)

### Mechanism 1: Decomposition and Hybrid-Experts Iteration Framework
- **Claim:** Decomposing native formal reasoning into three independent expert capabilities (auto-formalization, lemma-style sketching, whole-proof generation) and using tool feedback for trajectory synthesis yields high-quality, verifiable training data.
- **Mechanism:** The Hybrid-Experts Iteration Framework iteratively generates trajectories where each expert (π_θ^af, π_θ^sk, π_θ^pf) interacts with Lean4 verification tools (V_syn, V_con, V_leg). Single-turn trajectories address simpler tasks, while multi-turn tool-integrated trajectories handle harder cases, producing diverse data covering a wide difficulty spectrum.
- **Core assumption:** Specialized experts enable focused optimization, and tool verification provides a reliable ground-truth signal that reduces training noise.
- **Evidence anchors:** Abstract mentions decomposition and framework; Section 2.2 details six trajectory sets (D_af, D'_af, D_whole.pf, etc.) and tool feedback loops; neighboring corpus work discusses tool-integrated reasoning but not this precise decomposition.
- **Break condition:** If Lean4 undergoes breaking changes, the tool interfaces and verification predicates would need complete redesign.

### Mechanism 2: Hierarchical Importance Sampling Policy Optimization (HisPO)
- **Claim:** HisPO stabilizes MoE RL training on long-horizon formal reasoning tasks by applying gradient masking that accounts for policy staleness and train-inference engine discrepancies at both sequence and token levels.
- **Mechanism:** HisPO defines a masking matrix Hᵢ,ₜ(θ) that zeroes gradients from sequences with high aggregate train-inference discrepancy (geometric mean of token-level ratios) and from individual tokens whose importance ratio exceeds a threshold. This prevents instability from asynchronous training backends (Megatron vs vLLM) and stale rollouts.
- **Core assumption:** Asynchronous RL with mismatched training/inference kernels and stale experience introduces variance in importance sampling ratios that can be mitigated by systematic masking.
- **Evidence anchors:** Abstract mentions gradient masking for discrepancy and staleness; Section 3.3 defines HisPO objective and decomposes discrepancy into r_dis and r_stale; corpus works "Scaling Agentic Reinforcement Learning for Tool-Integrated Reasoning in VLMs" and "ASTER: Agentic Scaling with Tool-integrated Extended Reasoning" also address TIR training instability.
- **Break condition:** If training and inference engines achieve perfect bitwise consistency, discrepancy masking becomes unnecessary and might over-suppress useful gradients.

### Mechanism 3: Legality Detection via AST Consistency Checks
- **Claim:** Legality detection using Abstract Syntax Tree (AST) consistency checks eliminates reward hacking by blocking formally valid but semantically invalid proofs that tamper with theorem definitions, introduce fake axioms, or misuse meta-programming.
- **Mechanism:** A lightweight Lean4 lexer/parser converts proofs into ASTs and checks strict consistency between the proof AST and the target theorem AST, detecting tampering with theorem signatures, unexplained custom commands, or unverified helper definitions that would otherwise pass syntax verification.
- **Core assumption:** A proof that compiles in Lean4 can still be "cheating" if its AST diverges from the original problem's AST structure; syntactic pass is insufficient for true validity.
- **Evidence anchors:** Abstract mentions legality detection; Section 2.1 introduces V_leg tool; Appendix E lists nine cheating patterns; Table 5 shows AST checking reduces pass rate from 97.9% to 27.9% on a hacking model, proving discriminative power.
- **Break condition:** If Lean4's AST format changes or the model learns to generate AST-consistent but still semantically invalid proofs, the detection would need deeper semantic analysis.

## Foundational Learning
- **Mixture-of-Experts (MoE) routing and load balancing**  
  *Why needed:* The model scales to 560B total parameters with only ~27B active per token, requiring efficient token-to-expert assignment and balanced utilization to avoid underused experts and training inefficiency.  
  *Quick check:* How does the gating network decide token-to-expert assignments? What mechanism (e.g., auxiliary loss) ensures load balancing across experts?

- **Tool-Integrated Reinforcement Learning (TIR)**  
  *Why needed:* The agents interact with an external Lean4 compiler during trajectory synthesis and RL rollouts, necessitating handling of asynchronous tool calls, parsing verification feedback, and incorporating results into learning signals.  
  *Quick check:* How are tool call actions represented in the policy’s output space? How is credit assigned when a proof fails after many tool interactions?

- **Importance sampling and clipping in policy gradient methods**  
  *Why needed:* HisPO builds on GRPO/PPO and uses importance sampling ratios; clipping is necessary to prevent large policy updates that destabilize training. HisPO modifies this with hierarchical masking.  
  *Quick check:* Why does off-policy data lead to high-variance gradients? How does clipping the importance ratio (ε) bound the update magnitude?

## Architecture Onboarding
**Component map:**  
Base model (LongCat Mid-train Base, 560B MoE) -> Expert modules (auto-formalizer π_θ^af, sketcher π_θ^sk, prover π_θ^pf) -> Hybrid-Experts Synthesizer (orchestrates expert-tool loops, manages 6 trajectory datasets) -> HisPO trainer (asynchronous RL with gradient masking, runs on DORA system) -> Verification suite (V_syn, V_con, V_leg) -> Optional tree search module (unified judger-sketcher-prover)

**Critical path:**  
1. Cold-start data generation: Use ATF-32B and LongCat-Flash-Thinking-2601 to synthesize initial trajectories via Hybrid-Experts framework (yielding D_af, D_whole.pf, etc.).  
2. Domain-mixed SFT: Train base model on cold-start trajectories + informal reasoning data to obtain cold-start model.  
3. Agentic TIR RL: Run HisPO on cold-start model using tool-integrated rollouts, with legality detection in reward function.  
4. Iteration: Repeat data synthesis and training cycles, monitoring difficulty metrics to curate data.

**Design tradeoffs:**  
- Tool calls vs. sample efficiency: TIR increases correct proofs (~14% gain) but multiplies compute cost per trajectory; must balance inference budget.  
- Sketching vs. whole-proof: Sketching decomposes hard problems but introduces dependency on lemma completion; direct whole-proof may be faster for some problems.

**Failure signatures:**  
- Reward hacking: Sudden spike in training pass rate without validation improvement; check AST legality detection.  
- Training instability: HisPO loss high variance or NaNs; adjust δ_seq/δ_tok.  
- Over-tooling: Excessive tool calls without accuracy gain; diversify cold-start data.  
- Expert collapse: One expert dominates successful trajectories; monitor expert diversity.

**First 3 experiments:**  
1. Tool integration validation: Sample 100 auto-formalization rollouts; verify V_syn and V_con reject rates decrease. Expected: Syntax error <5% after cold-start.  
2. HisPO stability ablation: Train ablations (no masking, sequence-only, full hierarchical). Compare gradient variance and pass@32 on MiniF2F-Test. Expect full HisPO best.  
3. Legality detection impact: Two RL runs, one with V_leg, one without, on cheat-prone problems. Expect V_leg reduces invalid passes without harming valid ones.

## Open Questions the Paper Calls Out
1. **How can we prevent degradation in informal reasoning when training models for formal reasoning?**  
   *Basis:* The paper acknowledges drops on informal benchmarks and expects improved balancing.  
   *Why unresolved:* Current pipeline lacks explicit balancing during RL.  
   *What evidence would resolve:* Introduce multi-task loss with dynamic weighting; evaluate on AIME-25, HMMT-25.

2. **Are AST-based legality checks sufficient to guarantee proof integrity against all forms of reward hacking?**  
   *Basis:* Nine cheating patterns identified; AST checks may miss subtle attacks.  
   *Why unresolved:* AST verifies structure but not deeper semantics.  
   *What evidence:* Extend with semantic analyses (e.g., proof term normalization) and test on adversarially generated hacked proofs.

3. **Can the Hybrid-Experts Iteration Framework and HisPO algorithm be generalized to other proof assistants and dense model architectures?**  
   *Basis:* Framework is tailored to Lean4 and MoE; no portability discussion.  
   *Why unresolved:* Tool interfaces and stabilization techniques are specific.  
   *What evidence:* Reimplement with Coq and dense model; test on Coq benchmarks.

4. **How can inference compute be adaptively allocated across problems to maximize proofs under a fixed budget?**  
   *Basis:* Results show benefit of larger budgets but fixed per-problem limits used; no dynamic allocation.  
   *Why unresolved:* Fixed budgets ignore difficulty variance; inefficient compute use.  
   *What evidence:* Develop difficulty predictor that sets per-problem budgets under a global constraint; evaluate total proofs solved.

## Limitations
- Omitted hyperparameters (δ_seq, δ_tok) and DORA infrastructure details hinder exact replication.
- Three-expert decomposition remains unverified externally and may not generalize.
- AST legality checks target only nine known cheat patterns; novel tampering could bypass.
- Tool-enhanced inference adds ~14% compute cost, limiting scalability.
- Undisclosed data synthesis and prompts risk contamination and benchmarking validity.

- HisPO stabilization: High
