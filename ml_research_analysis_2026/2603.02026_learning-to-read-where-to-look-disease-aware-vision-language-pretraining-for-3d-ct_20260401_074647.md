# Learning to Read Where to Look: Disease-Aware Vision-Language Pretraining for 3D CT
## Quick Facts
*   **arXiv ID:** 2603.02026
*   **Source URL:** https://arxiv.org/abs/2603.02026
*   **Reference count:** 21
*   **Primary result:** A unified 3D CT vision-language model achieves SOTA text-to-image retrieval and halves the axial snippet localization error without sacrificing disease classification performance.

## Executive Summary
This paper introduces RadFinder, a 3D CT vision-language model designed to overcome the dual challenges of coarse supervision (report-level only) and limited annotated data. The authors combine a large internal dataset (98k report-volume pairs) with public data and employ a multi-task pretraining strategy. The core innovation is an intra-scan localization task that predicts the axial depth of a text snippet within a volume, mined from radiology reports. This is integrated alongside standard global report-volume alignment (SigLIP) and a prompt-based disease classification loss. The resulting single model sets a new state-of-the-art in text-to-image retrieval on CT-RATE and dramatically improves snippet localization accuracy, while maintaining competitive disease classification, demonstrating that fine-grained spatial alignment can be learned without sacrificing broader retrieval or diagnostic capabilities.

## Method Summary
RadFinder employs a multi-task pretraining framework on 3D CT volumes and radiology reports. The vision encoder is a SPECTRE-based two-stage system: a frozen ViT-Large backbone processes non-overlapping 128×128×32-voxel windows (at 0.75×0.75×3.0mm³ spacing), and a trainable 4-layer combiner aggregates these into a global volume embedding and per-depth slice embeddings (spaced 12mm apart). The text encoder uses a Qwen3-Embedding model with LoRA adapters. Both modalities are projected into a 512-dim shared space via SigLIP-style heads. Three losses are combined: (1) symmetric SigLIP contrastive loss for global report-volume alignment, (2) a prompt loss using LLM-extracted binary disease labels (structured as text prompts) with class-balancing, and (3) a localization loss (cross-entropy with Gaussian-soft targets) that aligns a text snippet embedding with its correct axial depth embedding within the same volume. The model is trained on a mix of internal and public data (total >160k pairs) with text augmentations, using a weighted sum of losses (λ=8 for prompt, β=1 for localization relative to SigLIP).

## Key Results
*   **Retrieval:** Achieves R@10 of 31.5 on CT-RATE text-to-image retrieval, a significant improvement over the prior SOTA of 22.2.
*   **Localization:** Reduces mean absolute error (MAE) for axial snippet depth prediction to 36.3mm, nearly halving the previous best baseline of 67.0mm.
*   **Classification:** Attains an AUC of 83.8 on 18 CT-RATE disease classes, remaining competitive with top models while adding strong localization capability.

## Why This Works (Mechanism)
The model succeeds because the snippet localization task forces the vision and text encoders to learn fine-grained, spatially resolved alignments *within* a single scan. This intra-scan objective complements the global inter-scan contrastive task. The architecture naturally produces per-depth slice embeddings, and the localization loss directly trains these to be textually grounded. This spatial precision does not degrade global retrieval because the global combiner still aggregates information effectively, and the prompt loss provides a stable, structured supervision signal for disease semantics. The tasks are complementary: global retrieval learns report-level correspondence, disease prompts learn structured medical semantics, and localization learns precise spatial grounding.

## Foundational Learning
*   **Contrastive Vision-Language Pretraining (SigLIP):** The foundation for aligning global image and text representations. *Why needed:* Establishes a basic cross-modal semantic alignment before adding fine-grained tasks. *Quick check:* Verify global report-volume retrieval performance on a held-out set before adding other losses.
*   **Prompt-based Classification:** Using natural language prompts (e.g., "No finding is present.") with binary labels as classification anchors. *Why needed:* Provides a structured, interpretable supervision signal for disease knowledge without requiring a separate classifier head. *Quick check:* Check that similarity scores between a volume embedding and positive/negative prompt pairs for a known disease are discriminative.
*   **Axial Depth Prediction as a Localization Task:** Framing the problem as a classification over discrete axial depth bins. *Why needed:* Converts a continuous localization problem into a learnable classification task compatible with the slice-based architecture. *Quick check:* For a validation snippet, plot similarity scores between its text embedding and all slice embeddings of its volume; the peak should align with the correct depth bin.
*   **Multi-Task Pretraining:** Jointly optimizing contrastive, classification, and localization objectives. *Why needed:* Encourages the shared representation to capture multiple facets of medical information (global semantics, disease presence, spatial location). *Quick check:* Monitor each loss's gradient norm during training; no single loss should dominate or vanish entirely.
*   **3D Window-based Processing (SPECTRE):** Decomposing a large 3D volume into smaller patches/windows for a ViT backbone. *Why needed:* Makes processing high-resolution 3D CT scans computationally feasible. *Quick check:* Reconstruct a volume from its window embeddings via the combiner and measure reconstruction error (e.g., MSE) as a sanity check.
*   **LLM for Automated Label Extraction:** Using a large language model to parse reports into structured binary findings. *Why needed:* Scales the creation of dense, multi-label disease supervision from free-text reports. *Quick check:* Manually annotate a small sample of reports and compute agreement (e.g., F1) with the LLM's extracted labels.

## Architecture Onboarding
**Component Map:**
3D CT Volume -> SPECTRE Vision Encoder (Window Backbone + Global Combiner) -> Volume Embedding & Slice Embeddings per Depth -> Projection Head -> Normalized 512-D Vector
Radiology Report / Snippet -> Qwen3-Embedding (with LoRA) -> Text Embedding -> Projection Head -> Normalized 512-D Vector
Normalized Vectors -> SigLIP Loss (Global), Prompt Loss (Disease), Localization Loss (Depth) -> Weighted Sum Loss

**Critical Path:** The most important data and gradient flow for the novel contribution is: (1) Snippet text and its *corresponding volume* are processed; (2) The snippet's text embedding is compared against *all slice embeddings* from that same volume; (3) The localization loss computes cross-entropy against the depth bin where the true slice resides. This forces alignment within a scan.

**Design Tradeoffs:**
1.  **Window Size/Stride vs. Global Context:** Larger windows or overlapping strides capture more local detail but increase compute; the chosen 128³ non-overlapping windows balance detail and efficiency, but the global combiner must effectively aggregate them.
2.  **Loss Weighting (λ, β):** The prompt loss (λ=8) is heavily up-weighted, likely because the binary classification task is noisier (from LLM labels) and needs stronger signal. The localization loss (β=1) is equal to the base SigLIP weight, suggesting it is considered a primary task, not an auxiliary.
3.  **Depth Resolution (12mm):** Coarse resolution simplifies the classification task but limits precise anatomical localization. The MAE of ~36mm reflects this inherent quantization.

**Failure Signatures:**
*   **Retrieval Degradation:** If global SigLIP loss is overshadowed by other losses, cosine similarity distributions for report-volume pairs will cluster near zero, and R@10 will be low.
*   **High Localization MAE:** If snippet mining is flawed (wrong depth assignment) or the localization loss gradient is too weak relative to others, the snippet-slice similarity profile will be flat or peak at incorrect depths.
*   **Random Classification AUC (~0.5):** Indicates the prompt embeddings are not discriminative. Likely causes: LLM label extraction is completely mismatched with the actual report content or prompt templates are ineffective.

**First 3 Experiments:**
1.  **Ablation - Localization Loss Impact:** Train a model without the localization loss (β=0) and compare snippet localization performance (using the slice embeddings from the trained model) versus the full model. Isolates the contribution of the intra-scan task.
2.  **Sensitivity - Loss Weight β:** Train models with varying β (e.g., 0.1, 1, 10) while fixing λ. Monitor (a) localization MAE, (b) global retrieval R@10, and (c) classification AUC. Identifies the Pareto frontier and confirms β=1 is non-trivial.
3.  **Component Validation - Combiner Efficacy:** With a frozen window backbone, train only the global combiner on a reconstruction task (predicting masked windows) or the global contrastive task. Measure the quality of the resulting global volume embedding via retrieval. Validates that the combiner can aggregate window features meaningfully.

## Limitations
*   **Snippet Mining Pipeline:** The precise regex, DICOM mapping heuristics, and "content verification" step for the 262k snippet-slice pairs are not disclosed. This makes exact replication of the high-precision mining (99.4% precision, 90.2% recall) impossible without internal data.
*   **LLM-Based Label Extraction:** The exact QA prompts, LLM choice (beyond "an LLM"), and binarization thresholds for extracting 319 findings are not specified. This introduces uncontrolled noise that directly affects the prompt loss.
*   **SPECTRE Checkpoint Details:** The exact window stride, global combiner architecture, and public availability of the SPECTRE checkpoint are unknown. Using a proxy (e.g., SimCLR-pretrained ViT) introduces a distribution shift that could impact performance.

## Confidence
*   **Claim: RadFinder achieves SOTA text-to-image retrieval on CT-RATE (R@10 31.5).** Confidence: **Medium**. The architecture and loss are clear, but performance is sensitive to the large-scale internal data and specific preprocessing which are not publicly available for verification.
*   **Claim: The snippet localization MAE is reduced to 36.3mm.** Confidence: **Low**. This result is critically dependent on the quality of the mined snippet-slice pairs and the correctness of the axial depth assignment, both of which rely on unspecified internal heuristics and data.
*   **Claim: Adding the localization task does not degrade retrieval or classification.** Confidence: **Medium**. The multi-task design is sound and the loss weighting is specified, but the absence of degradation in the reported numbers could be influenced by the specific, non-public data mix and training regimen.

## Next Checks
1.  **Validate Snippet Mining on Public Data:** Implement the described regex patterns on a public dataset that includes both reports and DICOM series (e.g., a subset of CT-RATE with DICOMs). Manually verify a sample of extracted "series X, image Y" references to estimate the precision/recall of the depth assignment without the internal "content verification" step.
2.  **Evaluate LLM Label Extraction Concordance:** Use a standard, open LLM (e.g., GPT-4o-mini) with a simple QA prompt template ("Does the report mention {finding}?") to extract labels on a public dataset with ground-truth annotations (if available, e.g., a subset of Rad-ChestCT). Compute agreement metrics (e.g., F1) to gauge the noise level introduced by this process.
3.  **Gradient Analysis for Loss Balancing:** During a short training run, log the gradient norms (or magnitudes) for each of the three loss terms (SigLIP, Prompt, Localization) per batch. Check if the relative weighting (λ=8, β=1) results in roughly balanced gradient contributions or if one loss dominates, which would explain performance changes in ablations.
