# Balancing Multiple Objectives in Urban Traffic Control with Reinforcement Learning from AI Feedback

## Quick Facts
- **arXiv ID:** 2602.20728  
- **Source URL:** https://arxiv.org/abs/2602.20728  
- **Reference count:** 34  
- **Primary result:** RLAIF matches manually tuned baseline throughput and enables prompt-driven steering of directional priorities (e.g., NS throughput from 49% to 77%).

## Executive Summary
This paper addresses the challenge of multi-objective reward design in reinforcement learning for urban traffic signal control. It extends the Reinforcement Learning from AI Feedback (RLAIF) paradigm by using large language model (LLM) annotators with structured prompts that explicitly list objectives and user-specified trade-offs to generate pairwise preference labels over trajectory segments. The approach is evaluated in a SUMO simulation of a four-way intersection. Results show that RLAIF learns policies competitive with a grid-searched linear scalarization baseline—achieving similar throughput—while only slightly increasing carbon emissions (65 g/s vs. 60 g/s). Moreover, by varying natural language instructions (e.g., “NS only”), the system can steer the policy toward desired directional priorities, demonstrating flexible, user-aligned control without manual reward engineering.

## Method Summary
The proposed method replaces hand-specified scalar rewards with a learned reward model derived from LLM-generated pairwise preferences. The agent interacts with a SUMO-based traffic environment, storing transitions in a replay buffer. Periodically, pairs of trajectory segments are sampled, converted into natural language descriptions via a rule-based module, and presented to an LLM annotator (gpt-4.1-nano) along with a user instruction that enumerates the objectives and desired trade-off (e.g., maximize throughput while minimizing emissions). The LLM, following a chain-of-thought prompt, outputs a preference label (or uncertainty). These preferences train an ensemble of neural networks (the reward model) using a Bradley-Terry loss. After each reward model update, all transitions in the replay buffer are relabeled with the latest reward values, ensuring consistency. A DQN policy is then trained on the relabeled buffer. This loop enables the policy to optimize a latent utility that reflects the user’s multi-objective preferences without explicit scalarization.

## Key Results
- RLAIF achieved throughput comparable to the best manually grid-searched linear scalarization baseline, but with a modest emissions increase (65 g/s vs. 60 g/s).
- Lane-priority experiments showed that natural language prompts effectively steer behavior: specifying “NS only” raised north-south throughput from 49% (equal priority) to 77%.
- The approach eliminates manual reward engineering, offering a scalable way to align traffic control policies with diverse user preferences.

## Why This Works (Mechanism)
### Mechanism 1: Structured Prompting Elicits Cross-Objective Preferences
The prompt template forces the LLM to sequentially analyze each segment’s performance per objective, evaluate the overall balance against the user specification, and then output a preference label. This chain-of-thought structure turns the inherently ambiguous task of comparing multi-objective outcomes into a deterministic reasoning process. Under the core assumption that a sufficiently capable LLM, when given clear criteria, can approximate a human-like trade-off prioritizer, the system generates preference labels that reflect the desired balance. If the LLM’s biases misalign with traffic physics, the preferences become invalid, derailing learning.

### Mechanism 2: Reward Model Distills Latent Utility
Training a reward model ensemble on the LLM’s pairwise preferences (via cross-entropy loss under a Bradley-Terry model) allows the RL agent to optimize a scalar reward that implicitly encodes the user’s underlying multi-objective utility function. The reward model serves as a consistent, learnable approximation of the LLM’s judgment, converting noisy annotations into a dense reward signal for DQN. Overfitting to spurious patterns or underfitting due to biased preference data would corrupt the latent utility and degrade policy performance.

### Mechanism 3: Replay Buffer Relabeling Stabilizes Learning
Because the reward model evolves during training, historical transitions in the replay buffer would otherwise be evaluated by an outdated reward function, introducing non-stationarity. Fully relabeling the entire buffer with the latest reward model whenever it updates aligns all data with the current reward definition, preventing bootstrapping from inconsistent targets. This practice, standard in RLAIF, stabilizes policy learning at the cost of slower early convergence when the reward model is still changing rapidly.

## Architecture Onboarding
### Component Map (plain text)
SUMO Environment <-> Policy Network (DQN) -> Replay Buffer B (stores transitions). Periodic annotation: Replay Buffer B -> sample pairs -> Observation-to-Text Module -> LLM Annotator (gpt-4.1-nano) -> Preference Buffer D. Reward Model (ensemble of MLPs) trained on D -> relabels Replay Buffer B. Policy Network trained on relabeled B.

### Critical Path
1. Agent interacts with SUMO using current policy πθ, pushes (s,a,s') to Replay Buffer B.
2. Every 5000 environment steps, sample many trajectory segment pairs from B.
3. Translate each segment’s state sequence into a natural language description using rule-based templates.
4. Query the LLM with the user instruction (objectives + trade-off) and the two descriptions; obtain a preference label (1, 2) or uncertain (0). Store non-0 labels in Preference Buffer D.
5. Train the reward model ensemble on a batch from D via cross-entropy loss.
6. Relabel all transitions in Replay Buffer B with the latest reward model outputs.
7. Update the policy πθ (DQN) using a batch from the relabeled B.
8. Repeat from step 1.

### Design Tradeoffs
- **Annotation cost vs. quality:** More LLM queries improve the reward model but increase token cost; the system filters ~44% of labels as uncertain. Longer segments may yield higher uncertainty.
- **Ensemble disagreement sampling:** Focusing annotation on pairs where reward models disagree prioritizes informative examples but risks biasing the preference dataset toward hard cases unless balanced with random samples.
- **LLM choice:** Using a small, fast model (gpt-4.1-nano) reduces cost but may limit reasoning quality; a more capable model could lower uncertainty at higher expense.
- **Prompt sensitivity:** System behavior is controlled via natural language instructions; minor wording changes might produce unexpected trade-offs, posing a fragility risk.

### Failure Signatures
- **High uncertainty rate (>60%):** LLM cannot discern differences; likely due to short segments, poor text translations, or uninformative observations. Check segment length and description clarity.
- **Reward model loss divergence:** Inconsistent or contradictory preferences in D; inspect a sample of LLM outputs for coherence with the user instruction.
- **Policy collapse to a single objective:** One objective becomes trivially maximized and others ignored; monitor per-objective metrics (throughput, emissions, directional split) separately.
- **Sensitivity to prompt phrasing:** Large performance swings with slight instruction rephrasing indicate unreliable LLM grounding; run prompt ablations.
- **Non-converging relabeling instability:** Wild oscillations after each reward update suggest the reward model is non-stationary; reduce update frequency or slow learning rate.

### First 3 Experiments
1. **Baseline replication:** Implement the grid-searched linear scalarization baseline and determine the best weight for throughput vs. emissions. This establishes a target for RLAIF to match without manual tuning.
2. **Throughput-Emission comparison:** Train RLAIF with an instruction that balances throughput and emissions. Compare final average throughput and carbon emission (g/s) against the Linear baseline and single-objective DQNs. Expect RLAIF to achieve competitive throughput with only a small emission penalty.
3. **Lane priority steering:** Train multiple RLAIF instances with different user specifications (e.g., “NS only”, “NS priority”, “Equal priority”, “EW priority”, “EW only”). Measure the final NS vs. EW throughput split. Expect a clear, monotonic shift (e.g., NS throughput from 49% to 77%) as instruction emphasis increases.

## Open Questions the Paper Calls Out
- **Open Question 1:** How does multi-objective RLAIF scale to larger traffic networks with multiple intersections, and does it maintain performance without excessive annotation cost? The paper only evaluates a single intersection; city-scale generalization is unknown.
- **Open Question 2:** What causes the high proportion of uncertain preference labels (44%) in LLM annotations, and how can the annotation workflow be improved to reduce uncertainty? The paper reports this but provides no analysis or mitigation.
- **Open Question 3:** How sensitive is multi-objective RLAIF to the choice of language model and prompt design? The paper uses a single LLM and fixed prompt template without comparative analysis.
- **Open Question 4:** How does multi-objective RLAIF compare to state-of-the-art multi-objective RL algorithms (e.g., Pareto-based methods) in achieving diverse trade-offs and sample efficiency? The only baseline is linear scalarization.

## Limitations
- Segment length for preference annotation is unspecified; the temporal scope critically affects LLM judgment quality and uncertainty rates.
- DQN hyperparameters (ε-decay, discount factor, buffer size, training frequency) are omitted, forcing guesswork in reproduction and potentially causing performance gaps.
- Evaluation is limited to a single four-way intersection; scalability to larger networks and stochastic traffic demands remains unaddressed.
- The approach relies on a specific LLM (gpt-4.1-nano) and prompt structure; sensitivity to these choices is not explored.

## Confidence
- Core claim (RLAIF avoids manual reward engineering while matching throughput): Medium – throughput matched but emissions slightly higher; key parameters missing.
- Prompt-based directional steering: High – clear monotonic shift demonstrated (49% → 77% NS).
- Replay buffer relabeling stabilizes learning: High – standard RLAIF technique, indirectly supported by slower early convergence versus stationary rewards.

## Next Checks
1. **Temporal Scope Sensitivity:** Vary segment length (5, 10, 20 transitions) in the annotation pipeline; measure LLM uncertainty rate and final policy multi-objective performance to identify an optimal horizon.
2. **Prompt Ablation:** Remove the chain-of-thought structure from the LLM prompt; assess the impact on preference consistency and the policy’s ability to balance throughput vs. emissions.
3. **Cross-Method Benchmark:** Compare RLAIF against a Pareto-based MORL method (e.g., MO-DQN) on the same intersection; evaluate whether RLAIF approximates the Pareto front or collapses to a biased scalarization.
