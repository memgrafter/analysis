# Why Agent Caching Fails and How to Fix It: Structured Intent Canonicalization with Few-Shot Learning

## Quick Facts
- **arXiv ID:** 2602.18922
- **Source URL:** https://arxiv.org/abs/2602.18922
- **Reference count:** 13
- **Primary result:** Reframes caching as canonicalization, achieves 91.1% accuracy on MASSIVE with 2–5ms latency and 97.5% cost reduction.

## Executive Summary
Existing caching for personal AI agents fails because it optimizes for classification accuracy rather than the true requirements of cache keys: consistency (same intent → same key) and precision (each key maps predominantly to one intent). This work redefines the problem as a canonicalization task and introduces W5H2, a structured intent decomposition into (WHAT, WHERE) pairs that isolates the tool-sequence decision from varying parameters. Using few-shot contrastive learning (SetFit), the method yields a fast, accurate local classifier. Coupled with a five-tier cascaded routing and risk-controlled thresholding, the system serves 85% of queries locally, reducing monthly cost per user by 97.5% while maintaining safety.

## Method Summary
The approach consists of three core components: (1) W5H2 decomposes user queries into seven fields (Who, What, When, Where, Why, How, How Much) and uses only the (ACTION, TARGET) pair as the cache key. This creates language-agnostic, parameter-separated keys that remain stable across paraphrases. (2) SetFit fine-tunes a sentence transformer with contrastive loss on 8–16 examples per intent class, producing a deterministic embedding-space classifier that operates in 2–5 ms and achieves near-supervised accuracy (91.1% on MASSIVE vs. 97.3% for full BERT). (3) A five-tier cascade routes queries: Tier 0 fingerprinting (entity placeholder hashing) catches simple variations; Tier 1 BERT handles high-confidence common patterns; Tier 2 SetFit processes lower-confidence queries with abstention based on RCPS thresholds; Tiers 3 and 4 fall back to a cheap LLM or a deep agent for novel or complex tasks. Temperature scaling calibrates confidence, and RCPS guarantees that the unsafe hit rate stays below a chosen α with high probability. The result is a precise, consistent cache-key mapping that dramatically cuts LLM costs.

## Key Results
- SetFit attains 91.1%±1.7% accuracy on MASSIVE (8 classes) in ~2–5 ms, far surpassing GPTCache (37.9%) and a 20B LLM (68.8% at 3,447 ms).
- On NyayaBench v2 (20 classes) the method reaches 55.3%±1.0% accuracy (62.6% with 16-shot), demonstrating reasonable performance on a harder benchmark.
- A five-tier cascade serves 85% of queries locally, cutting monthly cost per user by 97.5% (from $31.72 to $0.80). Zero-shot cross-lingual transfer yields 37.7% mean accuracy across 30 languages.

## Why This Works (Mechanism)
### Mechanism 1: Reframing as Canonicalization
Cache effectiveness depends on key consistency and precision, not classification accuracy. The paper formalizes cache-key generation as a canonicalization function f: Query → Key, evaluated by clustering quality (V-measure combining homogeneity h and completeness c). This shifts focus from label correctness to the stability and purity of key groups, enabling a mapping that is tolerant to label noise while still producing useful clusters. The authors show that prior methods achieve low V-measure (e.g., 0.650 for an LLM on MASSIVE) while their approach reaches 0.813.

### Mechanism 2: W5H2 Structured Decomposition
Decomposing queries into seven W5H2 fields and using only the (ACTION, TARGET) pair yields language-agnostic, parameter-separated cache keys. Different phrasings or parameter values map to the same key (e.g., "email from Alice" and "check mail" → `(retrieve_email, email)`). This isolates the decision about which tool sequence to invoke from mutable parameters, allowing safe substitution at execution time. Ablation experiments confirm that the full (WHAT, WHERE) pair outperforms using only the target or other subsets, demonstrating its discriminative power.

### Mechanism 3: Few-Shot Contrastive Learning and Cascaded Routing
SetFit fine-tunes a sentence transformer with contrastive loss on a handful of examples per class (8–16), creating an embedding space where same-intent queries cluster tightly. This yields a fast (2–5 ms) classifier with accuracy approaching fully-supervised BERT. A five-tier cascade (fingerprint → BERT → SetFit → cheap LLM → deep agent) routes queries by confidence, with risk-controlled thresholds (RCPS) guaranteeing that the probability of an unsafe cache hit (SetFit’s key mismatching the deep agent’s plan) stays below α. Temperature scaling improves calibration. With 85% of traffic satisfied locally, the system reduces monthly cost per user by 97.5% while maintaining safety.

## Foundational Learning
- **Canonicalization vs Classification**: The caching problem requires a stable, deterministic mapping from surface form to cache key; a correct but inconsistent mapping is useless, while a consistent but “wrong” key can still be valuable if it groups identical intents. *Quick check:* If “check email” and “fetch mail” always map to `email_retrieve` but the ground-truth label for “fetch mail” is `retrieve_email_alternative`, is this function accurate? ## Architecture Onboarding
**Component Map:** Tier 0: Fingerprint (NER → typed placeholder → template hash, <1ms) → Tier 1: BERT (full fine-tune, ~5–10ms, high confidence τ>0.85) → Tier 2: SetFit (few-shot contrastive, ~2–10ms, with compound detection) → Tier 3: Cheap LLM (e.g., DeepSeek V3, $0.001–0.003/req, structured extraction) → Tier 4: Deep Agent (full LLM agent, $0.05–0.15/req).

**Critical Path:** A query enters at Tier 0. If the fingerprint matches a cached template, it is served immediately. Otherwise, it proceeds to BERT; if confidence >0.85, the predicted cache key is used. If BERT is uncertain, the query goes to SetFit; if SetFit’s confidence exceeds the RCPS threshold τ*, the key is used. Otherwise, the query is sent to the cheap LLM for structured extraction; the result becomes a new labeled example and may update the BERT/SetFit models. If the cheap LLM fails or the task is complex, the query escalates to the deep agent.

**Design Tradeoffs:** Coverage vs. Safety (τ): lowering τ increases hit rate but risks unsafe hits; RCPS selects τ* to guarantee unsafe_rate ≤ α with probability 1–δ. Granularity (W5H2 classes): fewer classes are easier to learn with few-shot but may under-separate intents; more classes improve discrimination but lower accuracy (8-class MASSIVE 91.1% vs. 20-class NyayaBench 55.3%). Model size vs. Calibration: smaller NLI models (22M) can outperform larger ones (280M) for binary decisions due to better calibration; do not default to the largest model for threshold-based tasks.

**Failure Signatures:** GPTCache/Embedding-Similarity: high precision when it fires but low coverage; cosine similarity threshold is a double-edged sword (too strict misses paraphrases, too permissive admits false positives like “check email” vs. “send email”). SetFit on Hard Distributions: low V-measure on NyayaBench v2 (V=0.517) indicates both mixed keys and scattered intents; per-class analysis shows certain classes (e.g., `manage_tasks`) have very low accuracy, becoming failure hotspots. Calibration Drift: SetFit is overconfident (ECE~0.5); without temperature scaling, RCPS thresholds become overly conservative, killing coverage.

**First Three Experiments:** 1. Replicate MASSIVE 8-class SetFit: Train SetFit-EN with 8 examples per class (seed 42). Verify accuracy ~91% and CPU latency <5ms. 2. Abstention Threshold Sweep on NyayaBench v2: With temperature-scaled SetFit, sweep confidence threshold τ and plot risk-coverage curve; identify τ that yields <5% unsafe rate. Expect low coverage (~3–16%) at high safety. 3. Cost Model Sanity Check: Using expected daily request volume and token profiles, compute monthly cost for “No Cache” (all Tier 4) vs. “W5H2” (85% local). Verify savings >97%; also test sensitivity to a 70% local hit rate (savings should remain ~87.8%).

## Open Questions the Paper Calls Out
- **Cross-lingual transfer for low-resource languages:** Zero-shot SetFit-Multi on 30 languages shows large performance gaps (Dravidian ~16%, Niger-Congo 13% vs. Indo-European ~50%). The authors suggest targeted few-shot examples may close the gap but no non-English training experiments were conducted. Resolution: add few-shot examples for low-resource families and measure gains; analyze script/morphology impact.
- **Actual query distribution across the five-tier cascade:** The cost model assumes traffic splits (30%/40%/15%/14%/1%) that were not empirically measured. Real-world usage could differ substantially, potentially undermining the projected 97.5% cost reduction. Resolution: collect logs from operational personal agents, classify queries into tiers via confidence thresholds, compute empirical distribution and actual costs.
- **Correlation between cache-key clustering quality and end-to-end execution safety:** The paper evaluates cache keys via V-measure but does not deploy the system in a live agent. High V-measure does not guarantee that all queries sharing a key require the same tool sequence; thus, cache hits may still cause incorrect tool invocations. Resolution: deploy the caching system in a test environment, trigger cached plans with diverse queries, record tool execution errors, and compute correlation between V-measure components and safety outcomes.

## Limitations
- NyayaBench v2’s intent-to-W5H2 mapping is provided as code, not formally specified, and labels come from a single annotator, risking ambiguity and reproducibility issues.
- The GPTCache baseline uses a reimplementation (embedding + KMeans) that may differ from the official library; results could be over- or underestimated.
- The cost model relies on static tier traffic splits (30%/40%/15%/14%/1%) and fixed token profiles; real query distribution drift could reduce local hit rate below the assumed 85%, weakening the projected savings.

## Confidence
- **Canonicalization reframing (evaluation via V-measure):** High. The theoretical shift from classification to canonicalization is well-motivated and empirically validated by consistent V-measure gains over baselines.
- **W5H2 structured decomposition:** Medium. Ablation studies support the (WHAT, WHERE) pair, but effectiveness depends on accurate field extraction from noisy, real-world queries—an assumption not fully stress-tested.
- **SetFit + cascade economics (97.5% cost reduction):** Medium. The projected savings rely on the assumed traffic distribution and calibrated thresholds; real-world drift or overconfidence could reduce actual cost reduction.

## Next Checks
1. **Canonicalization stability:** Collect a month of real agent queries, compute SetFit’s V-measure, and correlate with intra-class variance (e.g., edit distance within true intents). Expect V ≥ 0.65 if the canonicalization assumption holds.
2. **RCPS threshold safety:** Run an A/B test with τ* from calibration on 10k live requests; monitor unsafe hit rate (SetFit key ≠ deep agent plan). Must stay ≤ α=0.10 with 95% confidence.
3. **Cross-lingual robustness:** Evaluate per-language accuracy on NyayaBench’s 30 languages; identify failure families. Target mean accuracy ≥ 37.7% with no language family below 25%.
