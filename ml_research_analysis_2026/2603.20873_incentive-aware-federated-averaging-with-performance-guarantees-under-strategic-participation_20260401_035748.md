# Incentive-Aware Federated Averaging with Performance Guarantees under Strategic Participation

## Quick Facts
- **arXiv ID:** 2603.20873
- **Source URL:** https://arxiv.org/abs/2603.20873
- **Reference count:** 40
- **Primary result:** IncentFedAvg enables strategic clients to jointly optimize model and data contributions, converging to a Nash equilibrium with O(1/ε²) communication complexity while maintaining competitive test accuracy.

## Executive Summary
Federated learning (FL) typically assumes clients contribute fixed datasets, but in practice participation is strategic: clients weigh the cost of sharing data against the benefit of a better global model. This paper introduces **IncentFedAvg**, an algorithm where clients simultaneously perform local model updates and adjust their dataset sizes via projected gradient steps, aiming for a Nash equilibrium of a noncooperative game. The server aggregates client models using weights proportional to the current estimated dataset sizes. Theoretically, under convex (or nonconvex) smooth objectives, the global model converges to an optimal solution (or stationary point), and the participation vector converges linearly to the unique Nash equilibrium, with communication complexity O(1/ε²) rounds. Empirical evaluations on MNIST and CIFAR-10 demonstrate that client contributions stabilize and test accuracy is competitive with standard FedAvg. However, key experimental details (e.g., number of clients, hidden layer size) are missing, and the theory relies on strong monotonicity that may require careful regularization.

## Method Summary
IncentFedAvg operates in communication rounds. The server broadcasts the current global model \(\hat{x}_r\) and participation vector \(\hat{N}_r\). Each client \(i\) samples a subset of its local data of size \(\lceil N_{i,r} \rceil\), performs \(H\) local SGD steps (batch size 1) with step size \(\gamma\) to obtain an updated local model \(x_{i,r+1}\). Then the client updates its participation size via a projected gradient step: \(N_{i,r+1} = \Pi_{[N_i^{\min}, N_i^{\max}]}\big(N_{i,r} - \tilde{\gamma} (\nabla_{N_i} c_i(\hat{N}_r) - \nabla_{N_i} a_i(\hat{N}_r))\big)\), where \(a_i(N) = (W N)_i\) is the payoff (with \(W = Q Q^\top\) derived from client class distributions \(Q\)) and \(c_i(N_i) = \theta_i N_i + \frac{\lambda}{2} N_i^2\) is a linear cost plus quadratic regularizer. The client sends \((x_{i,r+1}, N_{i,r+1})\) back; the server aggregates the global model as a weighted average \(\hat{x}_{r+1} = \sum_i p_{i,r+1} x_{i,r+1}\) with \(p_{i,r+1} = N_{i,r+1} / \sum_j N_{j,r+1}\), and broadcasts the new participation vector. The game is shown to be a strongly monotone variational inequality when \(\lambda > \lambda_{\max}(W)\), ensuring linear convergence of the participation dynamics to a unique Nash equilibrium. The model convergence follows from FedAvg analysis adapted to time-varying weights and bounded gradient dissimilarity.

## Key Results
- Clients update dataset sizes via projected gradient to balance marginal payoff and cost, leading the participation vector to converge linearly to the unique Nash equilibrium.
- The global model converges to an optimal solution for convex objectives and to a stationary point for nonconvex objectives, with communication complexity \(O(1/\varepsilon^2)\) rounds.
- Experiments on MNIST and CIFAR-10 confirm stable contribution convergence and competitive test accuracy compared to standard FedAvg.

## Why This Works (Mechanism)
The core of IncentFedAvg is a coupled dynamics: model updates follow FedAvg with dynamic weights, while participation sizes follow a projected gradient on a game-theoretic objective. The payoff function \(a_i(N) = (W N)_i\) is linear, and the cost \(c_i(N_i)\) is quadratic (due to regularization). The combined update for \(N\) is equivalent to a forward step on the variational inequality \(\text{VI}(F, \mathcal{N})\) with \(F(N) = \nabla c(N) - \nabla a(N)\) and feasible set \(\mathcal{N} = \prod_i [N_i^{\min}, N_i^{\max}]\). With \(\lambda > \lambda_{\max}(W)\), \(F\) becomes strongly monotone (\(\mu_F = \lambda - \lambda_{\max}(W) > 0\)) and Lipschitz (\(L_F = \lambda + \lambda_{\max}(W)\)). Choosing \(\tilde{\gamma} \le \mu_F / L_F^2\) guarantees linear convergence of \(N\) to the unique Nash equilibrium (the solution of the VI). Simultaneously, the model updates can be analyzed as an inexact stochastic gradient method: the time-varying weights are slowly varying (bounded change) because \(N\) converges quickly, and the global objective satisfies smoothness and bounded variance assumptions. Under these conditions, the iterates \(\hat{x}_r\) satisfy a descent lemma that yields the stated convergence rates. The strong monotonicity condition is crucial: it decouples the two dynamics by ensuring participation stabilizes fast enough that the model updates behave like a standard FedAvg with slowly changing weights.

## Architecture Onboarding
**Component map:**  
Server (holds \(\hat{x}_r, \hat{N}_r\)) → broadcast → Client \(i\) (local data, \(N_{i,r}\), \(x_{i,r}\)) → local SGD (H steps) + projected gradient update of \(N_{i,r}\) → send \((x_{i,r+1}, N_{i,r+1})\) → Server aggregates \(\hat{x}_{r+1} = \sum_i p_{i,r+1} x_{i,r+1}\), forms \(\hat{N}_{r+1} = (N_{1,r+1},...,N_{m,r+1})\) → repeat.

**Critical path:** Each communication round consists of: (1) server broadcast; (2) client local computation (SGD loops and update of \(N\)); (3) client upload; (4) server aggregation. The participation update depends on the latest global \(\hat{N}_r\) and must be computed before the server aggregates the new model weights.

**Design tradeoffs:**  
- *Local steps \(H\)*: Larger \(H\) reduces communication frequency but may increase model drift; affects convergence guarantees.  
- *Model step size \(\gamma\)*: Must be small enough for smooth loss (cross-entropy) to avoid divergence; too small slows convergence.  
- *Participation step size \(\tilde{\gamma}\)*: Must satisfy \(\tilde{\gamma} \le \mu_F / L_F^2\) for linear convergence; larger values cause oscillations or divergence.  
- *Regularization \(\lambda\)*: Ensures strong monotonicity (\(\lambda > \lambda_{\max}(W)\)); too large may overly penalize data sharing, skewing equilibrium.  
- *Number of clients \(m\)*: Affects heterogeneity (gradient dissimilarity) and computational load; more clients increase per-round variability.  
- *Data partitioning (Dirichlet \(\alpha\))*: Controls non-iidness; extreme heterogeneity can violate gradient dissimilarity bounds, affecting model convergence.

**Failure signatures:**  
- \(N_i\) persistently hitting \(N_i^{\min}\) or \(N_i^{\max}\) and not moving → step size \(\tilde{\gamma}\) too small or cost/payoff imbalance.  
- Global training loss increasing or NaN → model step size \(\gamma\) too large, or local SGD instability.  
- Aggregation weights collapsing (some \(p_i \to 0\)) → many clients’ \(N_i\) approaching minimum; may starve informative clients.  
- Oscillations in \(N_i\) across rounds → \(\tilde{\gamma}\) too large relative to \(\mu_F/L_F^2\).  
- Slow convergence of model or participation → step sizes too small or heterogeneity too high.

**First 3 experiments to validate implementation:**  
1. **Strong monotonicity check**: For a chosen data partition, compute \(\lambda_{\max}(W)\) and ensure the chosen \(\lambda_{\text{reg}}\) (paper uses \(\lambda=10^{-5}\) but may need increase) satisfies \(\lambda_{\text{reg}} > \lambda_{\max}(W)\).  
2. **Exact replication**: Implement IncentFedAvg with MLP (hidden size 128), cross-entropy loss, Dirichlet(\(\alpha=0.5\)) partition (e.g., 100 clients). Use \(\gamma=0.005\) for CIFAR-10, \(\gamma=0.01\) for MNIST, local steps \(H \in \{1,5,10,20\}\), and run for 500 rounds. Record final test accuracy and plot \(N_i\) trajectories to confirm convergence. Compare to FedAvg baseline.  
3. **Sensitivity of \(\tilde{\gamma}\)**: Vary \(\tilde{\gamma}\) at fractions (0.1×, 0.5×, 1×) of the theoretical upper bound \(\mu_F / L_F^2\). For each, measure rounds until participation stabilizes (e.g., \(\max_i |N_i^{t+1} - N_i^t| < 10^{-3}\)) and observe oscillations to identify a robust choice.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can the convergence analysis be extended to the strongly convex setting to obtain sharper (e.g., linear) convergence rates and tighter communication complexity?
- **Basis in paper:** [explicit] In the Conclusion (and Abstract), the authors state: "For future work, extending the convergence analysis to the strongly convex setting could yield sharper rates and tighter complexity bounds."
- **Why unresolved:** Current guarantees cover convex and nonconvex (possibly non‑strongly convex) objectives, but miss the practically relevant strongly convex case where faster rates are often achievable.
- **What evidence would resolve it:** A full theoretical analysis of IncentFedAvg under strong convexity, proving linear (or at least O(1/ε) rather than O(1/ε²)) convergence, and experimental validation on strongly convex tasks (e.g., ridge regression) confirming the improved rates.

### Open Question 2
- **Question:** Can the framework incorporate more general cost functions (e.g., nonlinear, incorporating privacy or preprocessing costs) while still guaranteeing existence/uniqueness of a Nash equilibrium and maintaining FL performance?
- **Basis in paper:** [inferred] The authors acknowledge in Section 2 that "an agent’s cost for sharing data may be more complex than just the size of the total data shared, as it can also include losses due to data collection, preprocessing, and privacy concerns," yet they adopt a simple linear cost model cᵢ(Nᵢ)=λᵢNᵢ.
- **Why unresolved:** Real‑world FL involves diverse and possibly nonlinear cost structures; the linear assumption may be insufficient and could affect the strong monotonicity required for the NE convergence proof.
- **What evidence would resolve it:** Identify broad classes of cost functions (e.g., convex, smooth) that preserve strong monotonicity of the game (Assumption 2.2), extend the convergence analysis accordingly, and test with synthetic nonlinear costs in simulations.

### Open Question 3
- **Question:** Is IncentFedAvg incentive compatible, i.e., do clients have no incentive to deviate from the prescribed dataset size updates or to misreport their sizes? How robust is the algorithm to strategic misreporting or free‑riding?
- **Basis in paper:** [inferred] The algorithm assumes clients faithfully execute the NE‑seeking update and report their sizes honestly. However, the paper does not address potential deviations; strategic clients might exaggerate contributions to gain higher model weights or minimize effort.
- **Why unresolved:** Incentive compatibility is crucial for sustainable FL, yet the method lacks a game‑theoretic justification that truth‑telling is a best response. Deviations could break both the convergence of N to the NE and the global model quality.
- **What evidence would resolve it:** Formalize a dynamic game where clients choose reporting strategies; prove (or disprove) that honest reporting constitutes a Nash equilibrium of the meta‑game. Alternatively, design a verification or payment mechanism that aligns incentives, and empirically test robustness against misreporting.

### Open Question 4
- **Question:** Can the O(1/ε²) communication complexity be improved by integrating advanced FL optimization techniques (e.g., variance reduction, compression, or adaptive aggregation) without sacrificing equilibrium stability?
- **Basis in paper:** [inferred] The derived communication complexity in Theorems 4.5 and 4.8 is O(1/ε²) in both convex and nonconvex settings. This matches standard FedAvg but leaves room for improvement, especially for convex objectives where faster rates are known in non‑strategic FL.
- **Why unresolved:** The analysis uses standard SGD tools; leveraging recent FL advances (e.g., FedProx, SCAFFOLD) might reduce the complexity, but it is unclear how these interact with the strategic participation dynamics.
- **What evidence would resolve it:** Develop a variant of IncentFedAvg that incorporates such techniques, prove tighter complexity bounds (e.g., O(1/ε) under strong convexity, O(1/ε) with variance reduction), and empirically demonstrate faster communication convergence on benchmark datasets.

### Open Question 5
- **Question:** How do the theoretical guarantees degrade under extreme data heterogeneity (e.g., highly non‑IID client data), and can the dependence on heterogeneity measures (e.g., gradient dissimilarity constant B) be tightened?
- **Basis in paper:** [inferred] The convergence bounds rely on Assumption 4.4 (bounded gradient dissimilarity), which is standard but can be overly restrictive when client data distributions differ greatly. The constants G and B (and δ₀) appear explicitly in the error bounds, potentially leading to large gaps in practice.
- **Why unresolved:** Real FL deployments exhibit severe heterogeneity; understanding the sensitivity of both model performance and equilibrium convergence to these constants is vital for assessing the method’s practicality.
- **What evidence would resolve it:** Relax Assumption 4.4 by considering alternative heterogeneity metrics (e.g., client drift), derive bounds with more realistic constants, and conduct extensive experiments on highly heterogeneous datasets (e.g., FEMNIST, Shakespeare) to correlate performance with heterogeneity measures.

## Limitations
- Missing experimental details: number of clients, MNIST MLP hidden size, exact learning rates, rounds, and Dirichlet sampling procedure are not provided, hindering exact replication.
- The strong monotonicity condition may be violated due to the small regularization \(\lambda = 10^{-5}\) relative to realistic \(W\), threatening the claimed linear convergence of the participation vector.
- Payoff and cost models are highly simplified (linear payoff, linear+quadratic cost); real strategic behavior may be more complex and violate assumptions, and empirical results are described only qualitatively (“competitive”) without numeric accuracy figures.

## Confidence
- **Theoretical convergence (convex/nonconvex and Nash):** Medium
- **Communication complexity \(O(1/\varepsilon^2)\):** Medium
- **Empirical test accuracy:** Low
