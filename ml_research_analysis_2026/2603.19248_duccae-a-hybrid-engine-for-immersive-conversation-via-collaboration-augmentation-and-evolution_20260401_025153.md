# DuCCAE: A Hybrid Engine for Immersive Conversation via Collaboration, Augmentation, and Evolution

## Quick Facts
- **arXiv ID:** 2603.19248
- **Source URL:** https://arxiv.org/abs/2603.19248
- **Reference count:** 40
- **Primary result:** A hybrid architecture that decouples real-time response from asynchronous agentic execution, achieving sub-second responsiveness while handling complex long-horizon tasks, with significant improvements in user retention and task completion when deployed at scale.

## Executive Summary
DuCCAE is a hybrid engine designed for immersive conversational systems, addressing the fundamental trade-off between latency and capability. It introduces a dual-track execution mechanism: a Fast Track for immediate responses to simple intents, and a Slow Track that offloads complex planning and tool use to asynchronous multi-agent collaboration, synchronized via a unified shared state. The system orchestrates five specialized subsystems—Info, Conversation, Collaboration, Augmentation, and Evolution—to handle multimodal perception, intent routing, long-horizon task execution, tool integration, and continuous improvement. Evaluated on the Du-Interact benchmark, DuCCAE-V3 achieves high dispatch precision, task success, and response fidelity with an average latency of 1.88 seconds. Deployed in Baidu Search since June 2025, it tripled Day-7 user retention to 34.2% and increased complex task completion to 65.2%, while session depth grew threefold.

## Method Summary
DuCCAE’s architecture separates real-time interaction from heavyweight background processing. User inputs are first processed by the Info System, which converts multimodal signals into a structured textual state and maintains dual memory (user memory and agent memory). The Conversation System then classifies the query intent into Tier-1 (simple chat), Tier-2 (tool use), or Tier-3 (multi-agent planning). Tier-1 queries follow the Fast Track: the Responder generates an immediate response using the current state. Tier-2/3 queries are sent to the Slow Track: the Collaboration System creates a plan, executes it via the Executor (which may call the Augmentation System’s tools), and synthesizes a result. A unified Shared State holds session context and execution traces; when the Slow Track finishes, an event updates the Shared State, and the Responder integrates the result into the next turn without breaking immersion. The Evolution System continuously harvests interaction logs, uses automated judging to create training data, and periodically applies modular post-training (SFT and RL) to improve subsystem performance. This design allows sub-second responsiveness for simple queries while reliably executing complex, long-horizon tasks.

## Key Results
- **Benchmark performance (Du-Interact):** DuCCAE-V3 achieves 82.5% dispatch precision, 72.4% task success rate, 71.1% response fidelity, 4.3/5 empathy scores, and an average latency of 1,880 ms.
- **Deployment impact (Baidu Search, June 2025 onward):** Day-7 user retention tripled to 34.2%; complex task completion rate increased to 65.2%; session depth grew 3×.

## Why This Works (Mechanism)
### Mechanism 1: Decoupling Real-Time and Asynchronous Execution
DuCCAE resolves the latency-capability trade-off by routing user queries along two coordinated paths. The Fast Track handles lightweight Tier-1 intents with pre-loaded context, yielding sub-500ms responses. Complex Tier-2/3 intents are offloaded to the Slow Track, where a multi-agent collaboration system performs planning and tool use without blocking the interaction loop. A Unified Shared State maintains session context and execution traces, allowing asynchronous results to be seamlessly reintegrated when ready. The core assumption is that heavy-tail execution latency inherent in long-horizon tasks cannot be bounded to real-time budgets; blocking the user for such tasks degrades immersion. Evidence from the architecture section (Sec 2.1) details the Dual-Track Execution Mechanism and Event-Driven Synchronization. If the Shared State fails to preserve coherent context across tracks (e.g., due to topic shifts), the user experience becomes disjointed.

### Mechanism 2: Specialized Subsystem Orchestration
The system partitions functionality into five specialized subsystems, each optimized for distinct demands: the Info System converts multimodal inputs into a policy-aware textual state with dual memory separation; the Conversation System acts as a latency-aware gatekeeper for intent stratification and bridge-and-callback response generation; the Collaboration System executes long-horizon tasks via a Plan-Execute-Generate workflow with parallel/serial dependency optimization; the Augmentation System standardizes tool/RAG integration via protocols (MCP/A2A); the Evolution System drives continuous improvement via a data flywheel of automated judging and post-training. The underlying assumption is that a monolithic architecture cannot simultaneously satisfy real-time responsiveness, multimodal understanding, agentic reliability, and long-term adaptability. The paper’s Section 2.2 details each subsystem’s responsibilities and interactions. Misrouting by the Conversation Router or planning stagnation in the Collaboration System are potential failure points.

### Mechanism 3: Evolutionary Data Flywheel
DuCCAE employs a closed-loop learning process where real user interactions are harvested, judged automatically (on next-turn engagement, instruction compliance, sentiment alignment), and distilled into memory-compressed episodes. The resulting “Silver Dataset” fuels supervised fine-tuning, while human verification yields a “Gold Dataset” for reinforcement learning. Modular post-training targets specific subsystems (e.g., planning traces for Collaboration, conversational pairs for Conversation). The core assumption is that domain-specific evolutionary data derived from real failures is more valuable than scaling model parameters alone. The abstract and Section 2.2.5 describe this flywheel; Section 3.4.2 shows that V1→V3 improvements reflect this closed-loop process, with a mid-sized model surpassing a 70B zero-shot baseline. Risks include automated judging bias (e.g., over-rewarding engagement) that could lead to degenerate behavior not caught by human verification.

## Architecture Onboarding
**Component map:**  
User Input (Multimodal) → Info System (Textual state + Dual Memory) → Conversation System (Router + Responder)  
 ↳ Fast Track: Tier-1 → Responder → Output  
 ↳ Slow Track (Tier-2/3): Collaboration System (Planner → Executor → Generator) + Augmentation System (Tools/RAG) → results → Event → Shared State → Responder integrates → Output  
Evolution System (logs → judge → distill → post-train) (feedback loop)

**Critical path:** For a complex query, the flow is: User query → Query Understanding (routing to Tier-2/3) → Planner creates dependency graph → Executor runs tools/sub-agents (possibly in parallel) → Generator synthesizes result → Event updates Shared State → Responder reintegrates result into next response. The Fast Track (Tier-1 → Responder) must remain independent and non-blocking.

**Design tradeoffs:**  
- *Latency vs. Fidelity:* Visual perception via captioning reduces latency by 77% but sacrifices fine-grained visual cues.  
- *Memory vs. Context:* Dual-memory design prevents user profile pollution but adds state management complexity.  
- *Generality vs. Efficiency:* Specialized sub-agents improve reliability but increase system complexity and compute cost.

**Failure signatures:**  
- *Routing Mis-dispatch:* Simple queries incorrectly sent to Slow Track cause unnecessary latency.  
- *Planning Stagnation:* Ambiguous intents cause the planner to loop or fail (e.g., vague video retrieval).  
- *Contextual Drift:* User changes topic while Slow Track runs; delayed result interrupts new flow, indicating need for task preemption.  
- *Tool Execution Conflict:* Parallel tool calls without proper orchestration may cause race conditions, mitigated by a Robust Orchestration Engine.

**First 3 experiments:**  
1. **Routing Accuracy Stress Test:** Evaluate on Du-Interact’s hard-negative sessions to measure Dispatch Precision and analyze misrouting patterns.  
2. **Visual Perception Ablation:** Compare the deployed caption→LLM pipeline against a frozen VLM encoder on video-grounded queries, measuring fidelity (LLM-judge) and pre-LLM latency.  
3. **Evolution Impact A/B Test:** Run an online experiment comparing V1 (cold-start) vs. V3 (evolution) on Day-7 retention and complex task completion to quantify the flywheel’s contribution.

## Limitations
- Proprietary components (ERNIE-4.5, Baidu Search APIs) hinder exact replication; open-source substitutes may underperform.  
- Implementation details of Shared State synchronization and context folding are underspecified, risking drift.  
- The Du-Interact benchmark and evolution pipeline specifics are not public, limiting external validation.
