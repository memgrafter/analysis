# Inference-time Unlearning Using Conformal Prediction

## Quick Facts
- **arXiv ID:** 2602.03787
- **Source URL:** https://arxiv.org/abs/2602.03787
- **Reference count:** 33
- **Primary result:** Reduces unlearning error by up to 93% across challenging benchmarks (RWKU, WPU, WMDP) compared to state-of-the-art baselines, while preserving performance on retain sets and providing distribution-free guarantees.

## Executive Summary
The paper introduces an inference-time unlearning framework for large language models that avoids parameter updates. It uses an LLM-as-a-judge verifier to iteratively refine responses, with conformal prediction to bound the number of iterations and provide marginal coverage guarantees. The approach achieves substantial reductions in unlearning error (up to 93%) on multiple benchmarks while maintaining model utility on retained tasks, all without requiring access to the original training data.

## Method Summary
The method operates in two phases: calibration and inference. During calibration, for each example in a small calibration set, the iterative refinement algorithm runs until a verifier score exceeds a threshold λ, recording the required iteration count. The (1−α) quantile of these counts defines the maximum iterations Tα. At inference, for a given query, the model generates responses up to Tα times, each time incorporating previous responses and verifier feedback (score and reasoning). If any response reaches score ≥ λ, it is returned; otherwise, the best-scoring response among all iterations is returned. The base LLM parameters remain unchanged. The verifier is an LLM prompted to score responses on a scale (0–10) and provide textual feedback. The conformal guarantee ensures that for a fresh exchangeable test sample, the probability of accepting a response (score ≥ λ) is at least 1−α.

## Key Results
- Unlearning error reduced by up to 93% on RWKU, WPU, and WMDP benchmarks compared to state-of-the-art baselines (GA, NPO, best-of-N).
- Retain set performance is preserved, matching or exceeding baselines.
- Empirical coverage meets or exceeds the target (1−α) across datasets, validating the conformal guarantee.
- The approach works without access to original training data or a retain set.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Verifier-guided iterative refinement reduces unlearning error by systematically steering the LLM’s responses away from forbidden information.
- **Mechanism:** For each prompt, the algorithm samples responses conditioned on a history of previous attempts and verifier feedback (scores and reasoning). An LLM-as-a-judge verifier evaluates each response; if the score meets the acceptance threshold λ, the response is accepted. Otherwise, the best-scoring response seen so far is retained, and the history is updated with the new response and feedback. The loop repeats for up to T_α iterations. The feedback loop enables the LLM to gradually align its output with the unlearning goal.
- **Core assumption:** The verifier’s score and textual feedback are sufficiently accurate and actionable; the LLM can effectively incorporate that feedback to improve subsequent generations.
- **Evidence anchors:**
  - [abstract] “iteratively refines LLM responses using feedback from an approximately correct verifier”
  - [section 3.1] Algorithm 1 and Figure 1 illustrate the iterative process with verifier scoring and reasoning.
  - [corpus] The corpus contains related work on conformal unlearning but provides no direct evidence for this specific iterative feedback mechanism; thus we rely on the paper’s empirical results.
- **Break condition:** If the verifier’s feedback is consistently misleading or the LLM fails to adapt (e.g., due to limited instruction-following), subsequent iterations may not yield improvement, causing the algorithm to output a suboptimal response after exhausting T_α.

### Mechanism 2
- **Claim:** Conformal prediction sets a data-driven bound on the number of iterations, providing distribution-free marginal guarantees that the final response satisfies the unlearning threshold with probability ≥1-α while also capping computational cost.
- **Mechanism:** A calibration set is used to run the iterative algorithm until an acceptable response was found for each sample, recording the required iteration counts T_i. The (1-α) quantile of these counts defines T_α. During inference, the algorithm runs at most T_α iterations. Under exchangeability, the probability that a test prompt yields an acceptable response (verifier score ≥ λ) within T_α iterations is at least 1-α.
- **Core assumption:** Calibration and test inputs are independent and identically distributed; the verifier’s threshold λ is fixed; the algorithm’s stochastic process is consistent across calibration and test.
- **Evidence anchors:**
  - [abstract] “Conformal prediction sets the maximum number of iterations to provide distribution-free guarantees.”
  - [section 3.2] Theorem 1 and Lemma 1 formalize the coverage guarantee: ℙ[V(y) ≥ λ] ≥ 1-α.
  - [section 4.2] Figure 5 empirically validates that actual coverage meets or exceeds the target (1-α) across datasets.
- **Break condition:** Violations of exchangeability (e.g., distribution shift) or changes in verifier behavior between calibration and inference can cause coverage to drop below 1-α. Additionally, if the verifier’s score distribution changes, the computed T_α may no longer be valid.

### Mechanism 3
- **Claim:** Inference-time operation without parameter updates preserves the model’s original capabilities on retain tasks and eliminates the need for original training data or a retain set.
- **Mechanism:** The base LLM parameters remain untouched; only the generation procedure is modified for queries related to the unlearning target. This avoids the catastrophic forgetting or performance degradation seen in training-based unlearning methods. The method requires only a small calibration set and a verifier, not access to the original training corpus.
- **Core assumption:** The unlearning procedure is applied exclusively to prompts that require forgetting; retain prompts are processed by the base LLM directly. The verifier’s instructions accurately capture the unlearning goal without overgeneralizing to harmless information.
- **Evidence anchors:**
  - [abstract] “without modifying model parameters… preserves performance on retain sets.”
  - [introduction, para 5] “Because our framework operates at inference-time, it requires no parameter updates and does not compromise performance on unrelated tasks.”
  - [section 4.1] Baselines include training-based methods (GA, NPO); Figures 2, 3, and 4 show comparable retain set scores while achieving higher forget scores.
- **Break condition:** If the iterative refinement process inadvertently alters the model’s response distribution for retain queries (e.g., unlearning logic mistakenly applied broadly), performance could degrade. An overly aggressive verifier threshold might cause the LLM to refuse legitimate retain queries.

## Foundational Learning
- **Concept:** Split Conformal Prediction  
  - **Why needed here:** The framework’s coverage guarantee hinges on split conformal prediction to compute T_α from calibration data; understanding its exchangeability assumption, quantile estimation, and marginal coverage is essential.  
  - **Quick check:** “How is the calibration set used to determine T_α, and what does the guarantee ℙ[V(y) ≥ λ] ≥ 1-α mean in practice?”
- **Concept:** Machine Unlearning (Exact vs. Approximate)  
  - **Why needed here:** The paper contrasts its inference-time approach with existing parameter-based unlearning methods; knowing the limitations of exact (expensive retraining) and approximate (performance drop, weak guarantees) unlearning motivates the design.  
  - **Quick check:** “What are the key drawbacks of exact and approximate unlearning that this work aims to avoid?”
- **Concept:** LLM-as-a-Judge (Verifier Design)  
  - **Why needed here:** The verifier is central to scoring and providing feedback; its design (prompting, scoring scale, reasoning) directly impacts unlearning quality and the coverage guarantee.  
  - **Quick check:** “How is the verifier’s acceptance threshold λ chosen, and what does it mean for the verifier to be ‘approximately correct’?”

## Architecture Onboarding
- **Component map:**  
  Base LLM -> Verifier (score + reasoning) -> Iterative controller -> History tracker -> (loop back to Base LLM with updated history). The calibration module computes Tα from a calibration set.
- **Critical path (inference):**  
  1. For a new query (x, entity to unlearn), load precomputed Tα.  
  2. Initialize empty history H and best response y*.  
  3. For t = 1 to Tα:  
     a. Prompt the base LLM with x and H to get y_t.  
     b. Query verifier V(y_t; x, entity) to get score s_t and reasoning r_t.  
     c. If s_t ≥ λ, return y_t.  
     d. Else if s_t > current best score, set y* = y_t and update best score.  
     e. Append (y_t, s_t, r_t) to H.  
  4. After loop, return y*.
- **Design tradeoffs:**  
  - Verifier accuracy vs. cost: High-quality verifier yields reliable scores but slower/expensive; lightweight verifier may increase noise and required iterations.
  - Calibration set size: Larger yields more precise Tα but consumes more data/compute.
  - Feedback granularity: Including only scores vs. full reasoning; reasoning helps LLM adjust but uses tokens and may contain noise.
  - Tα vs. α: Smaller α (higher confidence) increases Tα, raising computational cost; larger α weakens guarantee.
- **Failure signatures:**  
  - Coverage shortfall: Fraction of test outputs with score ≥ λ significantly below 1−α.
  - Excess iterations: Many prompts exhaust Tα without reaching ≥ λ, indicating Tα too low or verifier too strict.
  - Verifier instability: Same response receives vastly different scores across runs.
  - Retain performance drop: If retain set scores decline, unlearning logic may have leaked to non-target queries or verifier mislabeled retain data.
- **First 3 experiments (to validate implementation):**  
  1. **Calibration & coverage test:** Use a small calibration set to compute Tα (α=0.1). Run on an independent test set and measure coverage; expect ≥0.9.
  2. **Iteration efficiency:** Compare average iterations against best-of-N baseline (e.g., N=10); expect significantly lower average iterations while achieving comparable or better scores.
  3. **Feedback ablation:** Disable textual feedback (only keep score history) and measure the increase in iterations or drop in coverage, isolating the benefit of reasoning.

## Open Questions the Paper Calls Out
1. **How can the verification process be optimized to reduce the computational overhead of iterative refinement while maintaining unlearning guarantees?**  
   Future research could enhance this framework’s efficiency by optimizing the verification process, potentially through the use of lightweight verifiers or the development of implicit feedback mechanisms.
2. **How robust are the distribution-free guarantees when the key assumptions (i.i.d. calibration data, approximately correct verifier) are violated in real-world deployment?**  
   The theoretical analysis relies on Assumption (A1) (i.i.d. calibration/test inputs) and Definition 1 (𝜖-noisy verifier). The paper acknowledges violations may occur "in practice where i.i.d. assumptions may be violated" but only provides limited empirical checks.
3. **Can the conformal unlearning framework be extended to provide unlearning guarantees for multi-turn conversational interactions, where the model must maintain unlearned behavior over an extended dialogue?**  
   In a multi-turn setting, an LLM might reveal partial information across turns that, when combined, leaks the forbidden knowledge. The current verifier scores single responses independently, so turn-level unlearning does not guarantee conversation-level unlearning.
4. **What is the comparative cost-benefit trade-off between inference-time unlearning (this method) and parameter-based unlearning methods (e.g., NPO, GA) regarding total computational budget and model utility degradation?**  
   The paper compares against parameter-based baselines on unlearning error and retain set accuracy, but does not report a direct comparison of total inference latency (including iterative calls) versus the one-time training cost of parameter methods.
5. **How does the choice of verifier (LLM-as-a-judge) and its instruction prompt affect the consistency and reliability of the unlearning guarantee across diverse unlearning goals (e.g., hiding a name vs. an entire topic)?**  
   The framework allows a "user to provide application-specific evaluation instructions" and uses a verifier built on "LLM-as-a-judge." The paper tests on datasets with varying granularity (entities, topics), but it is unclear how sensitive the final coverage and error rates are to prompt engineering.

## Limitations
- **Verifier quality dependency:** The method’s success hinges on an “approximately correct” LLM-as-a-judge, but the paper uses a proprietary model (Gemini 3 Pro) without detailed error analysis. No stress tests on verifier bias, inconsistency, or susceptibility to jailbreak attacks are reported.
- **Coverage guarantee assumptions:** Conformal coverage relies on exchangeability between calibration and test data. Performance under natural distribution shifts (e.g., new entity types, prompt styles) is not evaluated.
- **Computational cost:** Inference-time iteration adds latency; trade-offs between Tα, α, and wall-clock time versus parameter-based methods are incompletely characterized, especially for high-stakes deployment.

## Confidence
- *Verifier-guided refinement reduces error*: High (empirically validated across 3 benchmarks vs. SOTA baselines).
- *Conformal prediction provides distribution-free guarantees*: Medium (theorem holds under assumptions; empirical coverage meets targets on i.i.d. test sets, but shift robustness untested).
- *Inference-time operation preserves retain performance without training data*: High (retain metrics comparable to baselines; ablation shows no parameter updates).
- *Verifier is “approximately correct”*: Low (no independent validation of verifier accuracy; reliance on single proprietary model).

## Next Checks
1. **Verifier robustness test:** Replace Gemini with open-source judges (e.g., Llama-3-70B) and measure changes in Tα, coverage, and final unlearning error to quantify sensitivity to verifier quality.
2. **Distribution shift stress test:** Construct test sets with novel entities or domains (e.g., non-Wikipedia figures) and measure coverage deviation from 1−α to validate exchangeability assumption violations.
3. **Compute-efficiency benchmark:** Measure per-query latency and cost (FLOPs, API calls) against GA/NPO for equal unlearning efficacy, clarifying real-world feasibility.
