# Towards One-for-All Anomaly Detection for Tabular Data

## Quick Facts
- **arXiv ID:** 2603.14407
- **Source URL:** https://arxiv.org/abs/2603.14407
- **Reference count:** 40
- **Primary result:** OFA-TAD achieves state-of-the-art average AUROC (0.8345) and AUPRC (0.6629) across 34 datasets without retraining on targets.

## Executive Summary
Tabular anomaly detection (TAD) typically requires training a separate model for each dataset, which is costly and poorly generalizes. This paper introduces OFA-TAD, a one-for-all framework that trains once on multiple source datasets and then detects anomalies in any unseen target dataset using only normal target data as context, without retraining. OFA-TAD encodes samples using multi-view neighbor-distance profiles under different feature transformations, adaptively fuses view-specific anomaly scores via a mixture-of-experts network with entropy-regularized gating, and employs a multi-strategy anomaly synthesis mechanism to train under the one-class constraint. Evaluated on 34 datasets from 14 domains, OFA-TAD outperforms nine baselines, achieving average AUROC 0.8345 and AUPRC 0.6629, with ablations confirming the contribution of each component and showing improved performance with more source data and robustness under limited target context.

## Method Summary
OFA-TAD follows a multi-view distance encoding and adaptive fusion pipeline. During training, it uses multiple source datasets containing only normal samples. For each sample, M=4 feature transformations (raw, standardized, min-max, quantile) generate different metric spaces. In each view, the top-K nearest neighbor distances from the normal context are retrieved, then quantile-normalized to a uniform scale. These normalized distance sequences serve as a transferable representation of isolation. To fuse the views, each expert processes one sequence with positional embeddings and attention pooling to produce a view-specific score; a gating network takes the concatenated expert embeddings and predicts sample-wise weights (entropy-regularized) to combine the scores. Training is enabled by a multi-strategy anomaly synthesis module that generates pseudo-anomalies from normal batches via manifold extrapolation, inter-cluster interpolation, noise injection, and feature masking, yielding a binary classification objective with MSE loss. At test time on a new target dataset, only its normal training set is used to fit the transformations and neighbor index; test samples are scored through the same pipeline without any model updates.

## Key Results
- Average AUROC **0.8345** and AUPRC **0.6629** across 34 target datasets, surpassing nine strong baselines under the strict one-for-all protocol.
- Comprehensive ablations demonstrate that each component (multi-view encoding, MoE fusion, entropy regularization, anomaly synthesis) contributes significantly to performance.
- Performance scales positively with the number and diversity of source datasets and remains robust even when target context is limited.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Anomalies can be identified by their neighbor-distance profiles, which are transferable across tabular domains.  
**Mechanism:** For each sample, compute top‑K nearest neighbor distances in multiple metric spaces induced by different feature transformations (e.g., standardization, quantile normalization). The resulting sequences are normalized via quantile transformation to be cross‑dataset comparable. This representation focuses on relative isolation rather than absolute feature values, which remains meaningful despite heterogeneous feature semantics.  
**Core assumption:** Neighborhood structure (relative distances) is a universal indicator of anomaly across tabular domains.  
**Evidence anchors:** Abstract and Section 3.1 describe neighbor distance extraction and multi‑view transformation; Figure 2 demonstrates transformation sensitivity.  
**Break condition:** If anomalies are not isolated (e.g., contextual anomalies that appear normal in some contexts) or if distance metrics become uninformative due to extreme sparsity/high dimensionality, the neighbor‑distance pattern may lose discriminative power.

### Mechanism 2
**Claim:** The Mixture‑of‑Experts (MoE) gating network adaptively selects the most reliable view for each sample, handling dataset‑ and sample‑specific transformation preferences.  
**Mechanism:** Each view is processed by an expert that uses attention pooling over neighbor ranks to produce a view‑specific anomaly score. A gating network takes concatenated expert embeddings and predicts sample‑specific weights via softmax. The final score is a weighted sum of expert scores passed through sigmoid.  
**Core assumption:** The reliability of a view’s distance profile for anomaly judgment can be inferred from the profile itself and varies across samples.  
**Evidence anchors:** Abstract and Section 3.2 detail the gating module and attention pooling; Figure 6 visualizes dataset‑dependent gating weights.  
**Break condition:** If the gating network is inadequately regularized or expert embeddings are noisy, the gating may collapse to always selecting one view, losing multi‑view benefits. Also, without enough view diversity, gating cannot meaningfully differentiate.

### Mechanism 3
**Claim:** Multi‑strategy anomaly synthesis enables effective training under the one‑class constraint by providing diverse pseudo‑anomalies that approximate real anomaly distributions.  
**Mechanism:** Four complementary strategies generate negative samples: manifold extrapolation (beyond normal manifold), inter‑cluster interpolation (between clusters), noise injection (measurement errors), and feature masking (data corruption). Combined with normal samples, this yields a binary classification objective (MSE loss).  
**Core assumption:** Synthetic anomalies cover enough variety of real anomalies to train a discriminative boundary without true anomaly labels.  
**Evidence anchors:** Abstract and Section 3.3 enumerate the four synthesis strategies.  
**Break condition:** If synthetic anomalies are unrealistic or normal data is highly heterogeneous, the model may learn a biased boundary.

## Foundational Learning
### Neighbor‑distance representation
**Why needed:** Provides a domain‑agnostic token that isolates the core AD signal (isolation) from feature semantics, enabling cross‑dataset transfer.  
**Quick check:** How does representing a sample by its top‑K nearest neighbor distances avoid depending on feature meanings?

### Transformation sensitivity
**Why needed:** Different tabular datasets respond differently to feature scaling/normalization; ignoring this leads to a single fixed transformation that may be suboptimal for many domains.  
**Quick check:** Why might standardization work better than raw features on one dataset but not another?

### Mixture‑of‑Experts (MoE) with gating
**Why needed:** Allows the model to dynamically emphasize the most informative view per sample, rather than committing to a single global transformation, thus robustly handling diverse datasets.  
**Quick check:** What information does the gating network use to decide how much weight to give each expert’s score?

## Architecture Onboarding
**Component map:**  
Input handler → Transformation module (M views) → Neighbor indexer (build kNN on context) → Distance encoder (retrieve top‑K, compute distances, quantile normalize) → MoE scorer (experts + gating) → Final anomaly score.  
Training adds: Synthesis module → training loop (MSE loss).  

**Critical path (inference):**  
1. Fit transformations and neighbor index on the target’s normal training set.  
2. For each test sample: apply each transformation, query top‑K neighbors from the target context, compute distances, normalize via view-specific QuantileTransformer.  
3. Feed the normalized neighbor‑distance sequences into the MoE: positional embeddings → attention pooling per expert → expert score s(m); gating network predicts weights g from concatenated expert embeddings; final score = sigmoid(Σ g_m * s_m).  

**Design tradeoffs:**  
- More views improve robustness but increase neighbor retrieval and model size; the paper fixes M=4.  
- Fixed K neighbors balances simplicity and local/global signal; too small or too large K degrades performance.  
- One‑class training via synthesis avoids needing anomalies but risks distribution mismatch; strategies are hand‑crafted.  
- No target retraining enables on‑the‑fly deployment but limits adaptation; performance scales with context size.  

**Failure signatures:**  
- Anomalies that are not isolated (e.g., clustered) cause neighbor‑distance patterns to fail.  
- Gating collapse (one expert dominates) if entropy regularization insufficient or views noisy.  
- Context size too small (<5% of training samples) yields noisy neighbor statistics.  
- kNN search becomes a memory/time bottleneck for large target contexts.  
- Poor cross‑domain transfer if source datasets lack diversity.  

**First 3 experiments:**  
1. **Ablation study:** Sequentially remove gating (uniform fusion), MoE experts (non‑parametric pooling), attention (mean pooling), position embedding, and each synthesis strategy; measure impact on average AUROC (Table 2).  
2. **Context size sensitivity:** Vary the proportion of normal training samples used as context (0.1 → 1.0) for selected targets; plot AUROC/AUPRC vs. context ratio to confirm robustness under limited context.  
3. **Gating analysis:** Compute average gating weights per dataset across test samples; visualize as a heatmap (Figure 6) to show dataset‑dependent view preferences and confirm adaptive fusion.

## Open Questions the Paper Calls Out
1. **Scaling limits:** What are the theoretical and practical limits of scaling OFA‑TAD with source dataset diversity, and when does additional source data yield diminishing returns or negative transfer?  
2. **Learned transformations:** Can transformations be learned or adapted rather than handcrafted to further improve cross‑domain robustness?  
3. **Context size prediction:** What factors determine the minimal context size required for stable OFA‑TAD inference across different target domains, and can this requirement be predicted from source data properties?  
4. **Improved gating:** What alternative gating architectures or objectives could improve the MoE routing mechanism for more reliable view fusion under extreme domain shifts?

## Limitations
- Neighbor‑distance representation may fail for contextual or clustered anomalies.
- Gating network could collapse to a single expert, losing multi‑view benefits.
- Multi‑strategy anomaly synthesis is heuristic and may not cover real anomaly distributions.
- kNN‑based inference cost may become prohibitive for large target context sizes.
- Evaluation on 34 datasets may suffer from source‑target leakage and lacks statistical testing.

## Confidence
- **Neighbor‑distance transferability:** Medium  
- **Adaptive MoE fusion:** Medium  
- **Synthetic anomaly coverage:** Low  

## Next Checks
1. Apply OFA‑TAD to datasets with contextual anomalies (e.g., ECG heartbeats, seasonal sales) and compare AUROC to point‑anomaly datasets; a significant drop would confirm the hypothesized limitation.  
2. Perform an entropy regularization sweep (weights 0, 0.01, 0.1, 1) and record gating entropy and target AUROC to validate the necessity and strength of the regularization.  
3. Using a source dataset that contains real anomalies, train OFA‑TAD with normals + synthetic anomalies and with normals + real anomalies (as an upper bound); evaluate both on the same target sets to measure the synthetic coverage gap.
