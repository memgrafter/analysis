# AutoStan: Autonomous Bayesian Model Improvement via Predictive Feedback
## Quick Facts
- **ArXiv ID:** 2603.27766
- **Source URL:** https://arxiv.org/abs/2603.27766
- **Reference count:** 40
- **Primary result:** AutoStan automates Bayesian model improvement via a CLI coding agent loop, achieving NLPD 1.23 on a synthetic regression dataset with outliers—surpassing TabPFN's 1.25—while remaining fully interpretable.

## Executive Summary
AutoStan introduces a framework for autonomous Bayesian model improvement using a CLI coding agent that iteratively edits Stan code, runs MCMC, and evaluates changes via negative log predictive density (NLPD) on held-out data and MCMC diagnostics. The agent can inspect raw data to infer structure (e.g., outliers, group hierarchy) and propose appropriate model modifications. Evaluated on five datasets, AutoStan discovers sophisticated statistical structures such as Student-t robustness, heteroscedastic variance, contamination mixtures, hierarchical partial pooling, and varying slopes. It matches or outperforms baseline methods without domain-specific tuning, demonstrating that NLPD and sampler diagnostics alone suffice for autonomous Bayesian modeling. The approach retains the interpretability of Stan code, distinguishing it from black-box machine learning methods.

## Method Summary
AutoStan operates within a constrained file system interface. The agent receives `program.md` (general Bayesian workflow instructions) and `dataset.md` (dataset-specific details and evaluation command) along with the training data `train.csv`. The test data `test.csv` and the evaluation script `evaluate.py` are protected (unreadable but executable). The agent’s loop is: read available files and the history log `log.jsonl`; optionally inspect `train.csv`; propose a change to `model.stan`; execute `python evaluate.py --notes "..." --rationale "..."`; interpret the JSON output containing NLPD and diagnostics (divergences, R̂, ESS); decide to keep the change (append to log) or revert. The loop stops after three consecutive iterations without NLPD improvement or after 20 total iterations. The sole objective is minimizing NLPD, while diagnostics act as a validity check. This agent-agnostic design allows use with any CLI coding agent; the paper uses Claude Code.

## Key Results
- On a synthetic 1D regression dataset with outliers, AutoStan achieves an NLPD of 1.23, beating TabPFN (1.25) and approaching the known oracle (1.22).
- The agent autonomously discovers advanced model features: Student-t likelihood for robustness, heteroscedastic variance, contamination mixtures, hierarchical pooling, and varying slopes across different datasets.
- Across five benchmark datasets, AutoStan matches or outperforms baselines (including TabPFN and manually-specified hierarchical models) without any dataset-specific prompt engineering.

## Why This Works (Mechanism)
AutoStan’s success hinges on a closed-loop autonomous improvement cycle. A CLI coding agent proposes edits to a Stan model file; the model is compiled and sampled via MCMC; two complementary feedback signals are returned: (1) NLPD on held-out test data, which strictly rewards predictive accuracy and calibration, and (2) MCMC diagnostics (divergences, R̂, ESS) that signal inferential validity. The agent keeps a change only if NLPD improves *and* diagnostics indicate reliable sampling. This iterative process, guided solely by predictive performance and sampler health, enables the agent to explore model space without external critics.

Crucially, the agent is not limited to blind proposals; it performs exploratory data analysis on the training set before modeling. Leveraging pretrained statistical reasoning, it infers data characteristics such as group structure, outlier presence, or paired counts from anonymized columns and tailors its proposals accordingly. For instance, it may add a Student-t likelihood when outliers are detected, or introduce hierarchical priors when groups are identified. The combination of predictive feedback, diagnostic safeguards, and data-driven hypothesis generation allows the agent to discover sophisticated, context-appropriate structures.

Finally, the framework produces human-readable Stan code, preserving full interpretability. Each iteration’s model is a complete generative specification with explicit priors and likelihood, enabling statisticians to audit the evolutionary path, understand why changes were made (via recorded rationales), and build upon the results. This transparency contrasts with black-box predictors and underscores that autonomous Bayesian modeling can be both powerful and understandable.

## Foundational Learning
**Negative Log Predictive Density (NLPD)**  
*Why needed:* It is the sole optimization target. NLPD rewards calibrated predictive distributions—not merely point accuracy—explaining why robustifications (e.g., Student-t) and heteroscedasticity often improve scores.  
*Quick check:* Why would switching from Gaussian to Student-t likelihood typically lower NLPD on data with outliers?

**MCMC Diagnostics (divergences, R̂, ESS)**  
*Why needed:* They signal when a proposed model yields *invalid* inference, not just suboptimal predictions. The agent uses them to reject changes that improve NLPD but cause poor mixing or bias.  
*Quick check:* What does an R̂ value > 1.1 indicate about the posterior sample, and why might it cause the agent to revert a change?

**CLI Coding Agent Paradigm**  
*Why needed:* AutoStan relies on an agent that can read files, execute shell commands, and maintain state across iterations. Autonomy arises from the agent’s ability to plan and reason in this environment.  
*Quick check:* What are the minimal capabilities a CLI agent must have to implement the AutoStan loop (with no additional tools)?

## Architecture Onboarding
**Component map:**  
`program.md`, `dataset.md`, `train.csv` → CLI agent → `model.stan` → `evaluate.py` (uses `test.csv`) → `results/<dataset>/log.jsonl` + `report.md`

**Critical path:**  
1. Agent reads `dataset.md` and `train.csv`.  
2. Agent writes initial `model.stan` (if no history) or proposes a change based on `log.jsonl`.  
3. Agent executes `python evaluate.py --notes "..." --rationale "..."`.  
4. Agent reads NLPD and diagnostics from stdout, decides to `keep` (append to history) or `revert` (restore previous `model.stan`).  
5. Repeat until stopping conditions (3 non-improving iterations or 20 total).

**Design tradeoffs:**  
- *Held-out NLPD vs. cross-validation:* Fixed test set is computationally cheap but risks overfitting; cross-validation is more robust but costly. AutoStan opts for the former, acknowledging the limitation.  
- *Agent-agnostic vs. agent-tuned:* The framework works with any CLI agent, but performance depends on the agent’s statistical knowledge. No dataset-specific prompts simplify deployment but may hinder discovery on niche problems.  
- *Diagnostic reliance:* Heavy reliance on MCMC diagnostics assumes they catch all inferential failures (e.g., label-switching via R̂). Some pathologies may be subtle and go undetected.

**Failure signatures:**  
- *Persistent divergences* despite reparameterization attempts → fundamental model mis-specification.  
- *NLPD decreasing while R̂ > 1.1* → agent may be improving predictions via biased inference (e.g., funnel collapse).  
- *No improvement after 5–10 iterations* → agent stuck in local minima or lacks ideas for the data structure.  
- *`evaluate.py` crashes* due to invalid Stan syntax → agent must debug compilation errors autonomously.

**First 3 experiments:**  
1. **Hierarchical Small (n_j=8):** Establish baseline; expect immediate correct hierarchical model (low NLPD close to oracle). Tests agent’s ability to recognize group structure from anonymized data.  
2. **1D Regression Large (n=500):** Full discovery pipeline; expect outlier robustness (Student-t), nonlinear mean (sine), heteroscedasticity, contamination mixture. Validates NLPD-driven structural search.  
3. **Bundesliga (real data):** Real-world domain adaptation with named columns; expect Poisson attack/defense baseline, then hierarchical priors and home advantage. Confirms agent uses semantic labels appropriately.

## Open Questions the Paper Calls Out
1. **Regularization of NLPD optimization:** How can iterative NLPD optimization on a fixed held-out test set be regularized to prevent mild overfitting without incurring the high computational cost of cross-validation or test-set rotation?  
2. **Generalization beyond pretraining:** To what extent does the agent’s pretraining on statistical modeling examples enable its performance, and can AutoStan generalize to modeling problems that are structurally novel and not represented in its training data?  
3. **Diagnostic sufficiency:** Is the feedback from standard MCMC diagnostics (divergences, R̂, ESS) sufficient for the agent to reliably diagnose and fix sampling issues in complex models (e.g., highly correlated parameters, funnel geometries), or are additional diagnostics needed?  
4. **Reward design:** Does the use of a single scalar reward (NLPD) suffice for autonomous discovery of statistically efficient models, or would incorporating a complexity penalty or alternative proper scoring rules (e.g., CRPS) lead to better generalization and more parsimonious models?

## Limitations
- Only Claude Code v2.1.86 has been evaluated; other CLI agents may produce different trajectories.
- The `evaluate.py` internals (MCMC settings, NLPD computation) are not disclosed, hindering exact replication.
- Optimizing on a fixed test set risks overfitting; the paper did not explore cross-validation or test-set rotation.

## Confidence
- Closed-loop optimization with NLPD and MCMC diagnostics: **High**
- Agent’s ability to discover appropriate model structures autonomously: **Medium**
- Production of interpretable Stan models: **High**
- Overall claim of matching/outperforming baselines across datasets: **Medium**

## Next Checks
1. **Multi-agent replication:** Run AutoStan with at least two alternative CLI agents (e.g., GPT-4o, open-source agents) on the five datasets; compare final NLPD and model complexity.
2. **Diagnostic robustness:** Vary the R-hat threshold (e.g., 1.01 vs. 1.1) in `evaluate.py` and measure changes in agent decisions; ensure biased inference does not pass.
3. **Overfitting test:** Replace the fixed test set with 5-fold cross-validation inside the loop; check whether improvements persist across folds.
