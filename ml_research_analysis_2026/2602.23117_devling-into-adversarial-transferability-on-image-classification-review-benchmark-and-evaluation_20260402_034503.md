# Devling into Adversarial Transferability on Image Classification: Review, Benchmark, and Evaluation

## Quick Facts
- **arXiv ID:** 2602.23117
- **Source URL:** https://arxiv.org/abs/2602.23117
- **Reference count:** 40
- **Primary result:** Proposed a comprehensive benchmark revealing that established attacks like VMI-FGSM outperform many recent methods under fair evaluation, and identified common transferability strategies.

## Executive Summary
This paper tackles the fragmented evaluation of transfer-based adversarial attacks in image classification by introducing a standardized benchmark. It categorizes over 100 existing attacks into six classes and evaluates them fairly across a diverse suite of models—including CNNs, Vision Transformers, and adversarially defended variants—using consistent protocols. Key findings demonstrate that recent attack proposals often underperform classic baselines when evaluated under these rigorous conditions, highlighting the prevalence of biased comparisons. The work synthesizes effective strategies (e.g., momentum, input diversity) and establishes a much-needed foundation for reproducible attack and defense research.

## Method Summary
The benchmark uses a standardized protocol: a 1,000-image ImageNet-compatible subset (resized to 224×224) with a ResNet‑50 surrogate model (`weights="DEFAULT"` in torchvision). For each attack, adversarial examples are generated under ℓ∞ constraints (ε=16/255, step α=1.6/255, iterations T=10 for untargeted / 300 for targeted). These examples are saved as PNG/JPG files before being loaded to evaluate Attack Success Rate (ASR) on a diverse set of victim models, including four CNNs, four ViTs, and five hardened models (AT, HGD, RS, NRP, DiffPure). This procedure enforces fair comparison by controlling model versions and image quantization effects.

## Key Results
- Top-performing attacks include MEF (gradient-based), OPS (input transformation), BFA (advanced objective), LTP (generation-based), MBA (ensemble), and L2T (targeted).
- Many recently proposed methods underperform established baselines (e.g., VMI-FGSM) when evaluated within the standardized framework.
- Common effective strategies for enhancing transferability involve momentum, input diversity, seeking flat local minima, and feature-level manipulation.

## Why This Works (Mechanism)
The benchmark eliminates common sources of bias—such as outdated model weights, floating-point tensor evaluations, and inconsistent hyperparameters—by mandating specific weight versions (`weights="DEFAULT"`), image file saving (PNG/JPG), and explicit hyperparameter reporting. Evaluating across a wide spectrum of model architectures and defenses reveals which attack components genuinely generalize beyond narrow surrogate-victim pairs. This rigorous setup ensures that performance differences reflect algorithmic merit rather than experimental artifacts.

## Foundational Learning
1. **Adversarial Transferability**: *Why needed*: Attacks crafted on a surrogate model often fool other models; understanding this is core to the paper. *Quick check*: Generate FGSM on ResNet‑50, test misclassification on VGG‑16.
2. **ℓ∞ Constraint**: *Why needed*: Bounds perturbation magnitude for realistic attacks. *Quick check*: Verify max(|perturbation|) ≤ 16/255 after attack generation.
3. **Model Architecture Bias (CNNs vs ViTs)**: *Why needed*: Different architectures exhibit varying susceptibility to transferred attacks. *Quick check*: Compare ASR of a single attack on ResNet‑50 versus ViT‑B/16.
4. **Adversarial Defenses (AT, DiffPure, etc.)**: *Why needed*: Defenses alter transferability dynamics; benchmark includes them for robustness. *Quick check*: Run an attack on an adversarially trained (AT) model and observe ASR drop.
5. **Attack Taxonomy (Gradient-based, Input Transformation, etc.)**: *Why needed*: Groups methods by methodology to enable structured comparison. *Quick check*: Classify I-FGSM as gradient-based and SIM as input transformation.
6. **Attack Success Rate (ASR)**: *Why needed*: Primary metric for quantifying effectiveness. *Quick check*: Compute (number of misclassified adversarial images) / (total victim predictions).

## Architecture Onboarding
**Component map**: Dataset -> Surrogate Model (ResNet‑50) -> Attack Algorithm -> Adversarial Examples (saved as PNG/JPG) -> Victim Models (CNNs, ViTs, Defended) -> ASR Calculation  
**Critical path**: Accurate generation with prescribed hyperparameters (ε, α, T) followed by strict image format conversion before black-box evaluation.  
**Design tradeoffs**: Higher iteration counts (T) and complex augmentations improve ASR but increase computational cost; input diversity enhances transfer but may weaken surrogate attack success.  
**Failure signatures**: Sudden ASR drop when using older torchvision weights; unrealistically high ASR when evaluating tensors directly instead of loaded image files.  
**First experiments**:  
1. Reproduce VMI-FGSM baseline: Generate on ResNet‑50 surrogate, evaluate on VGG‑16, confirm ASR matches reported baseline (~70-80% untargeted).  
2. Quantify image format impact: Compare ASR when adversarial examples are loaded from PNG/JPG versus used as raw tensors; expect significant difference.  
3. Validate weight versioning: Run identical attack with `weights="DEFAULT"` versus an older checkpoint; document ASR divergence.

## Open Questions the Paper Calls Out
- **How can transfer-based attacks be made effective against stronger defenses (e.g., adversarial training, diffusion purification) and in complex realistic scenarios (e.g., physical world, cross-domain)?** Current benchmarks largely use basic models and simple defenses; advanced defenses and real-world conditions remain underexplored, and the interaction between attack components and these settings is not well understood.
- **What evaluation standards can ensure fair comparisons across transfer-based attacks, considering category overlap, computational cost, and reproducibility issues?** Direct cross-category comparisons may be misleading due to hybrid methods, and opaque reporting (missing hyperparameters, computational details) prevents fair assessment. Model versioning and storage formats introduce hidden variability.
- **Can we derive universal principles of adversarial transferability that span tasks (image classification, NLP, multimodal) and model types (CNNs, ViTs, LLMs)?** Task-specific designs obscure shared underlying principles; no unifying theory connects transferability mechanisms across continuous (images) and discrete (text) domains. Transferability is often attributed to heuristics without general explanation.

## Limitations
- Unknown hyperparameters for 100+ attacks (e.g., decay factors, augmentation policies) are not provided in the paper; reproduction depends entirely on an external repository.
- Full training recipes for adaptive/generation-based attacks (data splits, epochs, optimizers) are omitted, blocking replication of attack-specific surrogate models.
- The benchmark’s reproducibility hinges on an external codebase whose exact contents, versioning, and adherence to the described protocol cannot be verified from the paper alone.
