# Formulating Reinforcement Learning for Human-Robot Collaboration through Off-Policy Evaluation

## Quick Facts
- arXiv ID: 2602.02530
- Source URL: https://arxiv.org/abs/2602.02530
- Reference count: 40
- Primary result: Proposed OPE-based framework selects optimal state/reward configurations, yielding an RL policy that attains the lowest perceived workload (2.38/5), highest trust (3.54/5), and highest fluency (3.40/5) in human-robot collaboration.

## Executive Summary
This paper addresses the challenge of automatically selecting optimal state representations and reward functions for reinforcement learning in human‑robot collaboration without costly online trials. The framework leverages off‑policy evaluation (OPE) with logged interaction data to systematically rank candidate configurations: for each proposed state space or reward function, an offline RL agent (CQL) is trained, and a unified OPE estimator (DM‑FQE) predicts its expected return. State selection chooses the representation maximizing estimated return, while reward selection chooses the reward maximizing a separability metric between a predefined good and bad policy. Empirical validation on Lunar Lander (simulated) and NASA‑MATB‑II (real human subjects) demonstrates that the method successfully identifies effective configurations. The resulting RL policy, trained with these selections, outperforms rule‑based and fine‑tuned baselines in a human study, achieving superior workload, trust, and fluency metrics while maintaining consistent performance across varying cognitive loads.

## Method Summary
Given a logged dataset *D* of trajectories (state, action, reward, next state, done), the framework first defines candidate state spaces *{Sₖ}* and/or reward functions *{rⱼ}*. For each candidate, a separate offline RL agent is trained using the Conservative Q‑Learning (CQL) algorithm on *D*. Next, a single OPE estimator (DM‑FQE) is trained on the union of all candidate state spaces using the full dataset; this estimator can evaluate any policy derived from the candidates. Each offline policy is then assessed by the OPE estimator to obtain an estimated return. For state selection, the state space with the highest estimated return is chosen. For reward selection, the OPE estimator is used to compute the estimated returns of two predefined reference policies (one good, one bad) under each reward; the reward that maximizes a divergence measure (e.g., Jensen‑Shannon) between the two return distributions is selected. Finally, a new RL policy is trained from scratch using the chosen configuration and validated, often through online human‑robot interaction studies.

## Key Results
- The framework identified optimal configurations: original state space and full composite reward in Lunar Lander; task + physiological state with weighted reward in NASA‑MATB‑II.
- In the human study, the RL policy based on the selected configuration achieved the lowest perceived workload (2.38/5), highest trust (3.54/5), and highest fluency (3.40/5), outperforming both rule‑based and fine‑tuned RL agents.
- Specific task performance metrics included a tracking root‑mean‑square error (RMSE) of 24.10 pixels and a system‑monitoring failure rate of 15.56%.

## Why This Works (Mechanism)

### Mechanism 1: OPE‑Based Configuration Ranking
The core idea is to use off‑policy evaluation to estimate the performance of offline‑trained RL policies without additional online interactions. For each candidate configuration (state space or reward), an agent is trained via CQL. A single DM‑FQE estimator—trained on the full dataset using a union of all candidate state features—then evaluates each policy’s expected return. The configuration with the highest estimate is selected. This mechanism relies on the assumption that the logged data provides sufficient coverage of the state‑action space to train a reliable OPE estimator; insufficient coverage leads to high‑variance or biased estimates and unstable rankings. Evidence comes from the successful identification of optimal state and reward functions in both simulated and real‑world experiments.

### Mechanism 2: State Space Selection via OPE
By comparing the OPE returns of policies trained on different state representations, the framework reveals which features are truly informative. A state space that preserves critical task information while avoiding distractions (e.g., noise or irrelevant variables) yields a higher estimated return. The union state space used for the OPE estimator ensures that all candidate features are representable during evaluation, so performance differences reflect the quality of the representation. Results show that the original state space performed best in Lunar Lander and that adding human physiological signals improved performance in MATB‑II, demonstrating the method’s ability to pinpoint beneficial modalities while discarding unhelpful ones.

### Mechanism 3: Reward Function Selection via Policy Separability
Reward effectiveness is quantified by the OPE‑estimated separation between a known good policy (e.g., a high‑performing offline RL agent) and a known bad policy (e.g., random or uniformly poor). A reward that produces a large divergence (e.g., high Jensen‑Shannon or KL divergence) between the return distributions of these two reference policies is considered more discriminative and thus more likely to guide learning toward optimal behavior. The OPE estimator provides the needed return estimates for the reference policies under each candidate reward. This mechanism assumes that the reference policies are sufficiently distinct and that the OPE estimator preserves the relative ordering across rewards. Experimental validation shows that the reward with the highest separability metric also leads to the best final policy performance.

## Architecture Onboarding
**Component map**:  
Logged Data Buffer (*D*) → Candidate Generator → Offline RL Trainer → OPE Engine → Ranking & Selector

**Critical path**: Data collection → Candidate definition → Offline policy training for all candidates → Single OPE estimator training → Candidate evaluation & ranking → Selection.

**Design tradeoffs**:  
- *OPE estimator choice*: DM‑FQE offers lower variance but can be biased if the Q‑network is poorly fitted; Importance Sampling is unbiased but high‑variance. The paper uses DM‑FQE for stability.  
- *Union state space for OPE*: Using the union of all candidate features ensures the OPE estimator can evaluate any policy, but increases function approximation complexity.  
- *Predefined good/bad policies for reward selection*: Must be available and reliably distinguishable; their quality directly impacts the validity of the reward ranking.

**Failure signatures**:  
- High variance in OPE estimates across different random seeds or data subsets → indicates insufficient data coverage or poor OPE hyperparameters.  
- Inconsistent rankings between different OPE methods (e.g., DM vs. IS) → suggests unreliable selection; need more data or better offline RL training.  
- Selected state space lacks intuitive domain relevance (e.g., selects only noise features) → indicates data distribution is extremely limited or OPE failure.

**First 3 experiments**:  
1. Replicate Lunar Lander state selection: Train a DDQN collector for 1000 episodes, train CQL agents on candidate state spaces (*S*<sub>orig</sub>, *S*<sub>more</sub>, *S*<sub>less</sub>), train a DM‑FQE estimator on the union state space, and verify that *S*<sub>orig</sub> consistently ranks highest.  
2. Stress‑test OPE data efficiency: Systematically down‑sample the logged dataset (e.g., 10%, 30%, 50%) and recompute OPE rankings; measure the variance across folds to identify the minimal viable data volume for stable selection.  
3. Validate reward separation metric: On CartPole, manually design a “good” policy (high return) and a “bad” policy (random). Create reward variants with added noise or missing terms, and confirm that the ground‑truth optimal reward yields the highest Jensen‑Shannon / KL divergence between the two policies’ return distributions.

## Open Questions the Paper Calls Out
1. How can fine‑tuning in RL‑HRI balance adaptability with stability? The paper finds that RL fine‑tuning increased trust but also workload and instability, and calls for refining fine‑tuning mechanisms to improve stability.
2. How can XAI be incorporated into the OPE‑based RL pipeline to enhance user trust and transparency? The current framework is opaque; users lack insight into the robot’s decisions, potentially limiting acceptance.
3. How does the choice of OPE estimator affect state and reward selection in the proposed framework? The method uses only DM‑FQE, and potential sensitivity to estimator bias/variance remains unexplored.

## Limitations
- The framework depends on large, diverse logged datasets; coverage gaps in critical states can cause OPE ranking failures.
- DM‑FQE hyperparameters (network size, number of FQE iterations) are not detailed, risking reproducibility and stability across domains.
- Ambiguity in defining “good” and “bad” policies for the reward separation metric; the paper does not specify the selection criteria for these reference policies.
