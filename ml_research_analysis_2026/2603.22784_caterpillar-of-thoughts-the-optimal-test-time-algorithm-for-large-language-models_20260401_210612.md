# Caterpillar of Thoughts: The Optimal Test-Time Algorithm for Large Language Models
## Quick Facts
- **ArXiv ID:** 2603.22784
- **Source URL:** https://arxiv.org/abs/2603.22784
- **Reference count:** 40
- **Primary result:** The optimal test-time algorithm under a fully observable Markov chain model yields a caterpillar tree structure; the practical Caterpillar of Thoughts (CaT) algorithm improves success rate and reduces tokens compared to Tree-of-Thoughts on two reasoning benchmarks.

## Executive Summary
Large language models (LLMs) often require multiple generation steps to solve complex reasoning problems. This paper studies how to structure test‑time computation to reach correct solutions with minimal steps. The authors model the process as exploring a fully observable Markov chain, where each token generation moves the state forward and the algorithm can rewind to any previously visited state. Their core theoretical result shows that the optimal exploration strategy always generates a caterpillar tree—a single backbone with leaves attached—implying that backtracking is fundamentally limited. Based on this insight, they propose the Caterpillar of Thoughts (CaT) algorithm, which iteratively rewinds to the state with the smallest estimated remaining cost and expands it. On Game of 24 and 5×5 crossword puzzles, CaT achieves a higher success rate (81% vs. 74% for Tree-of-Thoughts) while cutting emitted tokens by over 20% (15.3k vs. 19.2k). Theoretically, they prove that rewinding can reduce the expected number of generations exponentially compared to linear, non‑rewinding approaches.

## Method Summary
The Caterpillar of Thoughts (CaT) approach frames test‑time LLM generation as navigating a fully observable Markov chain: each state is a partial solution string, and transitions correspond to token‑level generations. The algorithm maintains a set S of observed states. At each iteration, it selects a parent state x* from S. Theoretically, the optimal parent is the one with the smallest exact expected remaining cost O(x), yielding a non‑branching caterpillar‑shaped search tree. In practice, O(x) is intractable; CaT uses an LLM‑based estimator bO(x) (e.g., a rating prompt) and samples x* with probability proportional to exp(-bO(x*)). This policy balances exploitation of low‑cost states with exploration to mitigate estimation errors. Given x*, the system calls the LLM to generate a child state g ~ P(x*,·), adds g to S, and checks if g meets the target. The process repeats until a solution is found or a computational budget is exhausted.

## Key Results
- On the Game of 24 benchmark (100 puzzles), CaT achieved an 81% success rate (vs. 74% for Tree-of-Thoughts) and reduced total generated tokens from 19.2k to 15.3k (over 20% decrease).
- Similar improvements were observed on 5×5 crossword puzzles, demonstrating better token efficiency and higher solve rates.
- Theoretically, the caterpillar tree structure is provably optimal under the Markov model, and rewinding yields an exponential reduction in expected generations compared to non‑rewinding linear generation.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The search space can be modeled as a fully observable Markov chain where the algorithm can rewind to any previously visited state.
- **Mechanism:** Every token generation step is a state transition. The algorithm maintains a set of observed states S and chooses which state x′ ∈ S to rewind to for generating the next state g ~ P(x′,·). This creates a tree of explored states.
- **Core assumption:** The underlying LLM's token sampling process defines a stationary transition matrix P(·,·) over partial solutions (states), and the algorithm has full observability of all visited states.
- **Evidence anchors:**
  - [abstract] "...modeling test-time computation as an algorithm interacting with a Markov chain: at any point, the algorithm may resume generation from any previously observed state."
  - [section 2] "We consider a finite-state fully observable Markov chain M = (Ω, P)... an algorithm adaptively chooses both where to rewind and how long to explore."
  - [corpus] Neighbor titles discuss Tree/Graph of Thoughts structures; the corpus provides context for test-time search paradigms but does not directly anchor this specific Markov formalism. **Corpus evidence: indirect; the model is novel per this paper.**
- **Break condition:** If the Markov property fails (transitions depend on full history, not just current state) or the state space is not fully observable (cannot reliably identify/reward to past states), the model is invalid.

### Mechanism 2
- **Claim:** The optimal exploration strategy, minimizing expected steps to a target state z, always generates a caterpillar tree (a path with leaves attached).
- **Mechanism:** The optimal algorithm is a *non‑branching* algorithm. At any point, it maintains a single "minimizer" state x* (the state with smallest O(x) among observed). It repeatedly rewinds to x* and generates a child g. If O(g) < O(x*), x* is updated to g; otherwise, g becomes a leaf and x* remains unchanged. The core tree is a single path (x* updates), with discarded branches as leaves.
- **Core assumption:** The optimal value function O(x) (expected hitting time from x under optimal play) is well‑defined and computable via dynamic programming (Corollary 3.5). The algorithm's decision rule is x* = argmin_{x ∈ S} O(x).
- **Evidence anchors:**
  - [section 3.1] Theorem 3.3: "For any set of states S ⊆ Ω, there exists a state x ∈ S such that O(S) = O_NB(x)... the optimal algorithm is a non‑branching one."
  - [section 3.1] "Corollary 3.4... O(S) = min_{x∈S} O(x) = min_{x∈S} O_NB(x)."
  - [corpus] Neighbors like "Atom of Thoughts" leverage Markov properties but propose different structural assumptions (memoryless). **Corpus evidence: weak; caterpillar optimality is a novel theoretical result of this paper.**
- **Break condition:** If O(x) cannot be computed or estimated, the exact optimal strategy cannot be implemented. The proof relies on the state space being finite and the target absorbing.

### Mechanism 3
- **Claim:** In practice, with only noisy estimates of O(x), a softmax-based rewinding policy (Algorithm 4) achieves near‑optimal efficiency and is robust to estimation error.
- **Mechanism:** Instead of deterministically picking x* = argmin O(x), sample a parent state x* from observed set S with probability Pr[x*] ∝ exp(-bO(x*)), where bO(x) is a noisy estimator of O(x). This allows occasional exploration of non‑minimizer states, preventing the algorithm from permanently committing to a bad branch from an early misestimate.
- **Core assumption:** The estimator bO(x) is sufficiently accurate on average (e.g., via Laplacian noise with repeated sampling) to bias selection toward lower O(x) states. The distribution's temperature effectively controls the exploration‑exploitation tradeoff.
- **Evidence anchors:**
  - [section 5.1] "Algorithm 4 rewinds to a previously observed state… prioritizes states with smaller estimated hitting times."
  - [section 4.1] Theorem 4.5 provides a sample complexity guarantee under Laplacian noise: "total cost is at most O(ε² · O(x₀)³ log O(x₀)) in expectation" when bO(s) ~ Laplace(O(s), εO(s)).
  - [section 4.2] Explicitly shows adversarial (1±ε)-approximations are insufficient, justifying the Laplacian noise assumption.
  - [corpus] Neighbors like "SoftCoT++" use soft reasoning paths, providing analogous motivation for soft selection over hard search.
- **Break condition:** If the estimator bO(x) is systematically biased or has heavy‑tailed noise, the softmax may misguide exploration. The algorithm also assumes state O(x) estimates are independent across states, which may not hold if estimator shares context.

## Foundational Learning
- **Concept: Markov Chain & Rewinding**
  - **Why needed here:** The entire theoretical model treats test-time computation as navigating a Markov chain with the unique ability to restart from any previous node. Understanding states, transitions, and hitting times is prerequisite.
  - **Quick check question:** Given a simple chain A → B → C (target), with P(A→B)=0.7, P(A→D)=0.3 (dead end), what is the expected steps from A with optimal rewinding (allow restart from A)?
- **Concept: Optimal Substructure & Dynamic Programming**
  - **Why needed here:** The proof that the caterpillar is optimal hinges on dynamic programming: O(x) = 1 + min_{y∈children} [ P(x,y)⁻¹ O(y) ] for the non‑branching case. The value O(x) summarizes the optimal future cost from x.
  - **Quick check question:** If O(y1)=5, O(y2)=10, and P(x→y1)=0.2, P(x→y2)=0.8, what is O(x) for a non‑branching strategy that always continues from the child (no rewinding within the branch)?
- **Concept: Exploration‑Exploitation Trade‑off in Tree Search**
  - **Why needed here:** Algorithm 4 trades off greedily following the best estimated state (argmin bO) vs. exploring other promising states via softmax. This is a multi‑armed bandit problem applied to tree nodes.
  - **Quick check question:** How would setting a very low temperature in the softmax Pr[x*] ∝ exp(-bO(x*)/τ) change the algorithm's behavior versus a high temperature?

## Architecture Onboarding
- **Component map:** State Tracker → Value Estimator → Rewinding Selector → Transition Sampler → Termination Check
- **Critical path:**
  1. Initialize S = {x₀} (initial state).
  2. Loop: Select x* from S → Generate child g from x* via LLM → Add g to S.
  3. If g satisfies target, return success; else repeat.
- **Design tradeoffs:**
  - **Exact O(x) vs. Estimated bO(x):** Exact values yield provably optimal caterpillar search (Algorithm 1) but require pre‑computing O(·) over the entire (possibly huge) Markov chain (O(n²)). Estimated values enable practical application but lack optimality guarantees; softmax (Algorithm 4) adds robustness to noise.
  - **Single‑path (caterpillar) vs. Soft branching:** The theoretical optimal is strictly non‑branching (single backbone). Softmax introduces occasional branches, trading strict optimality for resilience to bad bO estimates.
  - **Tokenizer‑level vs. State‑level:** The model treats a "state" as a partial solution string. In practice, defining state boundaries (e.g., after a full reasoning step) is crucial; too granular (token‑level) makes O(x) intractable.
- **Failure signatures:**
  - **State explosion:** If the LLM generates highly diverse child states at each step, |S| grows too fast, making bO estimation and selection costly.
  - **Estimator collapse:** If bO(x) is too noisy or biased (e.g., LLM scorer is poor), the softmax may not prefer shorter paths, leading to random walk behavior and high token use.
  - **Target mis‑specification:** If the target state z is not properly defined (e.g., valid final answer format not enforced during generation), the chain may loop indefinitely without hitting z.
- **First 3 experiments:**
  1. **Reproduce Game of 24:** Implement Algorithm 4 with bO via an LLM prompt asking "Will this partial expression likely yield 24?" Use beam=5 for ToT comparison. Verify success rate >74% and token reduction >20% (target: 81% / 15.3k tokens).
  2. **Ablation: Noise robustness:** Intentionally add noise to bO (e.g., flip scores randomly) and measure degradation in success rate vs. non‑branching Algorithm 1 (which would fail catastrophically on a single bad O(x) estimate).
  3. **Scalability test:** Measure |S| growth and per‑step compute cost as maximum iterations increase. Validate that token growth is sub‑linear compared to breadth‑first search (ToT's beam expansion).

## Open Questions the Paper Calls Out
1. **Comparison with newer methods:** How does CaT perform against recent test‑time approaches (e.g., process reward models, Monte Carlo Tree Search) on a diverse set of reasoning benchmarks? The current evaluation is limited to Tree‑of‑Thoughts on only two tasks.
2. **Theoretical guarantees for the softmax variant:** What are the expected‑step bounds for Algorithm 4 when bO(x) is estimated by an LLM scorer with realistic errors? The optimality proof only covers the exact‑O version.
3. **Optimality under variable token costs:** Does the caterpillar tree remain optimal when minimizing total token count instead of number of steps, given that transitions may have different token lengths? The current model assumes unit cost per step.

## Limitations
- The Markov chain model’s assumptions (full observability, stationary transitions, exact rewinding) may not hold in practice for autoregressive LLMs.
- The definition of a “state” as a partial solution string is ambiguous; too fine‑grained causes explosion, while coarse choices may lose information.
- The LLM‑based estimator `bO(x)` is unvalidated and sensitive to prompt design; experiments are restricted to two synthetic puzzles, leaving broader applicability uncertain.

## Confidence
- **Theoretical optimality of caterpillar search:** **High**
- **Empirical superiority over Tree‑of‑Thoughts:** **Medium**
- **Broader applicability and scalability:** **Low**
