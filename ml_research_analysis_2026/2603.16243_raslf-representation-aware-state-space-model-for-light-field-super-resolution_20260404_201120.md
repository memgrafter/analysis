# RASLF: Representation-Aware State Space Model for Light Field Super-Resolution
## Quick Facts
- **arXiv ID:** 2603.16243
- **Source URL:** https://arxiv.org/abs/2603.16243
- **Reference count:** 40
- **Primary result:** RASLF sets a new state-of-the-art in light field super-resolution, achieving average PSNR 32.690 dB and SSIM 0.9472 on 4× upscaling across five benchmarks with only 0.95M parameters and 31.20G FLOPs.

## Executive Summary
RASLF addresses a critical limitation in current SSM-based light field super-resolution (LFSR) methods: the inadequate use of multi‑representation complementarity, which leads to fine‑texture loss and geometric misalignment. It introduces a representation‑aware state‑space framework comprising three novel components: a Progressive Geometric Refinement (PGR) block that employs a Panoramic Epipolar Representation for explicit parallax encoding; a Representation‑Aware Asymmetric Scanning (RAAS) strategy that prunes redundant scanning paths based on representation structure; and a Dual‑Anchor Aggregation (DAA) module that reduces hierarchical feature redundancy. Extensive experiments show that RASLF achieves state‑of‑the‑art accuracy (e.g., 32.690 dB average PSNR for 4× upscaling) while being more efficient than the strongest lightweight baseline. Ablations confirm that each component contributes to the favorable accuracy‑efficiency trade‑off.

## Method Summary
The RASLF framework is built upon state‑space models (SSMs) but re‑engineers their handling of light‑field data. First, the input light field is transformed into a Panoramic Epipolar Representation (PER) to encode parallax explicitly and in a panoramic (angular) manner. This PER is processed by a Progressive Geometric Refinement (PGR) block, which iteratively refines geometric features to align views accurately. Next, a Representation‑Aware Asymmetric Scanning (RAAS) mechanism adapts the scanning pattern of the SSM to the structural properties of each representation, pruning redundant scan paths to reduce computational load without sacrificing relevant context. Finally, a Dual‑Anchor Aggregation (DAA) module merges hierarchical features from different stages using two anchor points, minimizing feature redundancy and preserving details for reconstruction. The entire pipeline forms an end‑to‑end trainable model that balances high‑fidelity super‑resolution with low computational cost.

## Key Results
- **SOTA accuracy:** Average PSNR 32.690 dB and SSIM 0.9472 for 4× upscaling across five benchmark datasets.
- **Notable improvement on large‑parallax data:** +0.17 dB on the STF‑gantry dataset compared to prior methods.
- **Superior efficiency:** Only 0.95M parameters and 31.20G FLOPs, i.e., 12.8% fewer parameters and 17.9% lower FLOPs than the efficient L2FMamba baseline, with reduced inference time.

## Why This Works (Mechanism)
RASLF’s gains stem from its representation‑aware design. The Panoramic Epipolar Representation captures full parallax information, enabling the PGR block to align views explicitly and progressively refine geometry, which mitigates misalignment artefacts. RAAS tailors the SSM scanning to the underlying representation, eliminating redundant computations and focusing on informative regions—this improves both accuracy and efficiency. DAA’s dual‑anchor strategy aggregates multi‑scale features without simply concatenating them, thereby preserving complementary details while avoiding redundancy. Together, these components ensure that the model leverages multi‑representation complementarity effectively, leading to sharper textures and more robust performance across varied parallax conditions.

  - *Quick check:* Verify that the discrete SSM layer approximates a linear time‑invariant system with structured matrices (e.g., HiPPO) and supports fast inference via parallel scans.

  - *Why needed:* Captures both spatial and angular light information, enabling depth‑dependent effects and view synthesis essential for super‑resolution.  
  - *Quick check:* Ensure the input is a 2D array of sub‑aperture images from a calibrated camera array or plenoptic camera.

- **Epipolar Geometry**  
  - *Why needed:* Encodes the geometric constraints between views; exploitation of epipolar lines is key to modeling parallax and scene structure.  
  - *Quick check:* In rectified light fields, all epipolar lines should be horizontal and straight; check alignment of corresponding points across views.

- **Panoramic Epipolar Representation (PER)**  
  - *Why needed:* Extends classic epipolar slices to the full angular domain, providing a unified representation of parallax across all views.  
  - *Quick check:* Rearrange sub‑aperture images into epipolar slices and verify that disparities are consistent across the angular dimension.

- **Representation‑Aware Asymmetric Scanning**  
  - *Why needed:* Different representations have varying structural properties; scanning paths must be adapted to avoid wasting computation on irrelevant regions.  
  - *Quick check:* Generate scanning masks from representation statistics (e.g., gradient magnitude) and confirm that fewer scans are used in homogeneous areas while more scans focus on edges.

- **Dual‑Anchor Aggregation**  
  - *Why needed:* Hierarchical features often contain redundancy; selective aggregation via anchor points preserves diverse information without bloating the feature tensor.  
  - *Quick check:* Compare DAA against naive concatenation by measuring parameter count, FLOPs, and validation PSNR on a small subset.

## Architecture Onboarding
- **Component map:** Light Field Input -> Panoramic Epipolar Representation Encoding -> Progressive Geometric Refinement (PGR) -> Representation‑Aware Asymmetric Scanning (RAAS) -> Dual‑Anchor Aggregation (DAA) -> Reconstruction Head -> Super‑Resolved Light Field Output

- **Critical path:** The forward pass depends on PGR to produce geometry‑aware features, which RAAS then processes in a representation‑aware manner. DAA aggregates multi‑scale outputs from RAAS, and the final reconstruction upsamples to the target resolution. Disrupting any of these stages degrades performance.

- **Design tradeoffs:**  
  1. Accuracy vs. efficiency: RAAS prunes scans to cut FLOPs, but over‑pruning may lose critical context.  
  2. Geometric precision vs. cost: PGR uses iterative refinements; more iterations improve alignment but increase memory and time.  
  3. Feature richness vs. redundancy: DAA reduces redundancy by anchoring, yet inappropriate anchor selection could discard subtle details.

- **Failure signatures:**  
  - Blurry textures or loss of fine details, especially in occluded regions → possible insufficient PER encoding or over‑aggressive RAAS pruning.  
  - Visible misalignment between views, particularly in high‑parallax scenes → PGR refinement insufficient or RAAS failing to capture long‑range dependencies.  
  - FLOPs significantly higher than reported → RAAS pruning not activating or DAA anchors not limiting feature dimensionality.

- **First experiments:**  
  1. **Baseline reproduction:** Evaluate RASLF and a strong SSM‑based baseline (e.g., L2FMamba) on a standard dataset (e.g., EPFL) and compare PSNR/SSIM to confirm SOTA claims.  
  2. **Component ablation:** Disable PGR, RAAS, and DAA one at a time; measure changes in accuracy and FLOPs to verify each component’s contribution.  
  3. **Efficiency profiling:** On a fixed hardware platform, measure inference time, memory consumption, and actual FLOPs; ensure they align with the reported numbers and show advantage over the baseline.
