# Argument Mining as a Text-to-Text Generation Task

## Quick Facts
- **arXiv ID:** 2603.23949
- **Source URL:** https://arxiv.org/abs/2603.23949
- **Reference count:** 22
- **Primary result:** A unified text-to-text generation approach using FLAN-T5-XXL achieves state-of-the-art Component-F1 and Relation-F1 on three benchmark datasets (AAEC: 80.15, 61.19; AbstRCT: 72.86, 47.66; CDCP: 72.68, 33.96) and reduces inference time by ~30% on AbstRCT by omitting non-argumentative spans.

## Executive Summary
This paper simplifies argument mining (AM) by reformulating it as a single text-to-text generation task. Instead of separate pipelines for span identification, component classification, and relation classification, the proposed method uses an encoder-decoder model (T5/FLAN-T5) to directly generate an "argumentatively annotated text" string. This string encodes argumentative spans, their component types, and dependency relations via a structured notation (e.g., `[span|type|relation=target]`). The approach eliminates task-specific postprocessing and hyperparameter tuning, yielding state-of-the-art results on three AM benchmarks. Furthermore, by omitting non-argumentative text from the generation target, inference time is reduced significantly on datasets with high non-argumentative content without performance loss.

## Method Summary
The method adapts the Translation between Augmented Natural Languages (TANL) framework for AM. Input is raw text; the target output is a linearized string representing the full argument graph. Training involves fine-tuning a pretrained FLAN-T5 model (via QLoRA) to map input text to this target string. The target format uses bracket-enclosed annotations: `[span_text|component_type|relation=parent_span]` for dependent components, and `[span_text|component_type]` for root nodes. For components with multiple parents, two representations are explored: "repeated" (one annotation per parent) and "serial" (chained relations in one annotation). During inference, the generated string is parsed, and span texts are aligned back to the original input tokens using the Needleman-Wunsch algorithm to recover token indices. Components and relations are extracted from the parsed annotations.

## Key Results
- Achieves state-of-the-art Component-F1 and Relation-F1 on AAEC, AbstRCT, and CDCP using FLAN-T5-XXL.
- Omitting non-argumentative spans from the output format reduces inference time by ~30% on AbstRCT with no performance drop.
- The "serial" representation for multi-parent relations consistently outperforms the "repeated" representation on the CDCP dataset.

## Why This Works (Mechanism)
### Mechanism 1
*Claim:* Framing AM as a single text-to-text generation task collapses three subtasks (span identification, component classification, relation classification) into one model pass.
*Mechanism:* The model is trained to generate a structured string where argumentative spans are embedded with their component label and relation target using special notation. This forces joint prediction in one autoregressive step.
*Core assumption:* A powerful encoder-decoder LM can learn to generate this string directly, and the string can be parsed back into a valid graph without extra decoding algorithms.
*Evidence anchors:* Abstract states elimination of postprocessing; Section 3.2 defines the output format; results show SOTA without pipeline components.

### Mechanism 2
*Claim:* Excluding non-argumentative text spans from the target output reduces sequence length and inference time without harming performance.
*Mechanism:* The training data's target string contains only explicitly annotated argumentative components and their relations, shortening the decoder's generation sequence.
*Core assumption:* Non-argumentative context is unnecessary for learning the mapping to the core argumentative structure.
*Evidence anchors:* Abstract notes 30% speedup on AbstRCT; Section 3.3 aims to reduce tokens; Table 7 shows comparable/better F1 when omitting non-arg spans; Figure 2 shows speedup.

### Mechanism 3
*Claim:* Using a "serial representation" for components with multiple parents improves relation classification vs. a "repeated representation".
*Mechanism:* Serial chains multiple relations in a single annotation (e.g., `[child|type|rel=parent1|rel=parent2]`), keeping the child component's representation intact. Repeated creates separate annotations per parent-child pair.
*Core assumption:* A linearized, chained representation helps the autoregressive decoder maintain a coherent representation of a child component across its multiple relations.
*Evidence anchors:* Section 3.4 defines both; Table 8 shows serial yields higher Relation-F1 on CDCP; Section 5.4 hypothesizes repeated breaks one-to-many relationships into separate one-to-ones.

## Foundational Learning
- **Concept: Text-to-Text Generation (Seq2Seq)**
  *Why needed:* The entire method reframes structured AM prediction as sequence generation. Understanding how an encoder-decoder model transforms input to output is key.
  *Quick check:* In T5, what is the decoder's role in generating the target annotated string, and how does it differ from a decoder in machine translation?
- **Concept: TANL (Translation between Augmented Natural Languages) Framework**
  *Why needed:* TANL provides the specific schema for encoding entities/relations as natural language text (e.g., `[entity|type|relation=other_entity]`). This paper adapts that for AM.
  *Quick check:* How does the TANL format differ from a simple BIO tagging scheme for representing relations?
- **Concept: Argument Mining Structure (Components & Relations)**
  *Why needed:* The target output encodes argumentative components (e.g., Claim, Premise) and their dependency relations. Domain knowledge is essential to understand the notation's meaning and constraints.
  *Quick check:* For the AAEC dataset, what is the required relationship between a `CLAIM` component and a `MAJORCLAIM` component in the resulting dependency tree?

## Architecture Onboarding
- **Component map:** Raw text -> Data Prep (convert gold AM to TANL string) -> Encoder-Decoder LM (T5/FLAN-T5) fine-tuning -> Postprocess (parse string, Needleman-Wunsch alignment) -> Evaluation (F1 scores).
- **Critical path:** 1) Annotation Formatting Script: Must correctly convert dataset-specific AM annotations into the linearized target string; most dataset-specific and error-prone. 2) Training Loop: Standard seq2seq fine-tuning; key hyperparameter is LR; manage long sequences (max_len=1024). 3) Parsing Logic: Robustly split generated string on brackets/pipes to extract tuples; must handle generation errors.
- **Design tradeoffs:** Simplicity vs. generation fidelity: Unified format simplifies but risks unparsable strings. Sequence length vs. info density: Omitting non-arg spans reduces compute but may remove useful context. Multi-parent representation: Serial improves Relation-F1 but creates longer, more complex strings.
- **Failure signatures:** 1) High Component-F1, Low Relation-F1: model finds spans/types but fails relation syntax. 2) Low Span Recall / high Precision: model generates very conservative annotations. 3) Parsing rate crash: many strings fail to parse (unbalanced brackets).
- **First 3 experiments:**
  1. Replicate AAEC baseline (FLAN-T5-Base, w/ non-arg spans, repeated representation). Match Component-F1 ~75.55 and Relation-F1 ~58.51.
  2. On AbstRCT, train w/ and w/o non-argumentative spans; confirm ~30% inference speedup and no F1 drop.
  3. On CDCP, train FLAN-T5-XL with repeated vs. serial representation; verify serial yields higher Relation-F1 (~34.96 vs 33.96).

## Open Questions the Paper Calls Out
- **Open Question 1:** Does the approach generalize to decoder-only LLMs (e.g., GPT-4, LLaMA 2) without extensive fine-tuning?
  *Basis:* Limitations section states only encoder-decoder models were tested; preliminary few-shot GPT-4 results were poor.
  *Why unresolved:* No rigorous fine-tuning experiments on decoder-only LLMs; hypothesis untested.
  *Evidence needed:* Fine-tune a decoder-only LLM on the AM generation task and evaluate on AAEC, AbstRCT, CDCP; compare performance/efficiency to FLAN-T5-XXL.
- **Open Question 2:** What is the precise reason "serial representation" outperforms "repeated" for multi-parent relations on CDCP?
  *Basis:* Section 5.4 hypothesizes repeated breaks one-to-many into separate one-to-ones, harming full relationship capture.
  *Why unresolved:* Hypothesis is plausible but untested; specific mechanism (sequence length, attention, sparsity) unknown.
  *Evidence needed:* Error analysis/attention probing on multi-parent cases for both representations; test if differences vanish with models having stronger long-range dependencies.
- **Open Question 3:** Why does omitting non-argumentative spans reduce inference time by ~30% on AbstRCT without loss, and does this hold universally?
  *Basis:* Section 5.3 reports speedup on AbstRCT (49.30% non-arg words) but not on other datasets; AAEC has 28.09% non-arg, CDCP has 0%.
  *Why unresolved:* Underlying cause (output compression) not analyzed; generalizability across datasets/models untested.
  *Evidence needed:* Measure correlation between output token reduction and speedup across datasets with varying non-arg ratios; test omission on AAEC/CDCP; analyze scaling effect.
- **Open Question 4:** To what extent does the XXL's Relation-F1 gain on AAEC stem from better long-distance dependency capture (e.g., CLAIM-MAJORCLAIM across paragraphs)?
  *Basis:* Section 5.5 notes XL->XXL improvement is largest for inter-paragraph relations; hypothesizes longer dependency capture.
  *Why unresolved:* Correlation noted but not conclusive; other factors (improved component classification) could explain gain; not directly proven.
  *Evidence needed:* Error analysis by textual distance between arguments for XL vs. XXL; relation evaluation using gold components to isolate relation classifier; train with shortened context.

## Limitations
- Missing critical implementation details: Needleman-Wunsch alignment parameters, evaluation scripts for AbstRCT/CDCP, exact label-to-TANL mapping, minor training hyperparameters.
- No reporting of parsing rate or alignment error rates, which are crucial for a generation-based approach.
- Failure modes (unparsable outputs, misalignment, OOM) are identified but mitigation strategies are under-explored.

## Confidence
- **Mechanism 1** (unified generation collapses subtasks): Medium. SOTA results support, but parsing robustness and alignment uncertainties affect confidence.
- **Mechanism 2** (omitting non-arg spans reduces time without loss): Medium. Speedup shown on AbstRCT, but representation/evaluation details unclear; generalizability uncertain.
- **Mechanism 3** (serial representation improves multi-parent relation classification): Medium. Direct CDCP comparison shows improvement, but limited to one dataset and parsing is brittle.
