# InFi-Check: Interpretable and Fine-Grained Fact-Checking of LLMs

## Quick Facts
- **arXiv ID:** 2601.06666
- **Source URL:** https://arxiv.org/abs/2601.06666
- **Reference Count:** 37
- **Key Result:** InFi-Checker attains state-of-the-art fine-grained fact-checking performance (90.91% balanced accuracy) with a 27.65% absolute improvement over the best baseline, while also generalizing to binary fact-checking tasks.

## Executive Summary
Current fact-checking methods for large language models (LLMs) typically reduce the task to binary true/false classification, offering little insight into the nature of errors. InFi-Check addresses this by introducing a framework that produces interpretable, fine-grained analyses. Its core is a controlled data synthesis pipeline that automatically generates training examples where each claim is annotated with supporting evidence, specific hallucination type labels, justifications, and corrections. An LLM fine-tuned on this data, InFi-Checker, jointly predicts all these components for new claim-document pairs.

On the manually curated InFi-Check-FG benchmark, InFi-Checker achieves 90.91% balanced accuracy—a 27.65% absolute gain over the best baseline (GPT-4o one-shot). The model excels at identifying discourse-level errors where prior methods completely fail. Moreover, InFi-Checker generalizes to six binary fact-checking benchmarks, matching or exceeding specialized binary checkers. This demonstrates that fine-grained training not only yields richer diagnostics but also enhances standard factuality assessment.

## Method Summary
InFi-Check comprises two main phases: (1) a controlled data synthesis pipeline that creates large-scale, high-quality training data with fine-grained annotations, and (2) supervised fine-tuning of a base LLM (e.g., Llama-3.1-8B-Instruct) on this data to produce the InFi-Checker model. The pipeline processes a source document in five stages: generate a grounded claim, extract supporting evidence for each claim sentence via voting, select a specific error type and design a modification strategy using chain-of-thought prompting, construct a hallucinated claim by applying the error, and synthesize the full structured output (evidence, error label, justification, correction). This yields the InFi-Check-TR training set (15,660 examples) and the manually verified InFi-Check-FG benchmark (519 examples). During fine-tuning, the model learns to output a JSON-like response containing, for each claim sentence, the related evidence, a binary support decision, an error type, a reason, and a corrected version. At inference, InFi-Checker processes a new document-claim pair and generates this structured analysis end-to-end.

## Key Results
- Balanced accuracy of 90.91% on InFi-Check-FG, a 27.65% absolute improvement over one-shot GPT-4o (64.69%).
- Substantial gains on discourse-level errors: 95.31% on CorefE (vs. 0% for baselines) and 86.67% on LinkE (vs. 0% for baselines).
- Generalizes to six binary fact-checking benchmarks, achieving Macro-F1 scores comparable or superior to specialized binary checkers.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** A controlled data synthesis pipeline can produce high-quality, fine-grained fact-checking training data at scale.
- **Mechanism:** The pipeline starts with a source document, generates a grounded claim, extracts supporting evidence, then uses a chain-of-thought process to inject a specific fine-grained hallucination type and produce a justification and correction. This creates a supervised example where the target output includes all desired diagnostic components.
- **Core assumption:** Advanced LLMs can be precisely guided to generate specific, realistic error types (e.g., swapping an entity, reversing a causal link) when provided with a structured CoT prompt and a clear construction strategy.
- **Evidence anchors:**
  - [abstract] "controlled data synthesis pipeline that generates high-quality data featuring explicit evidence, fine-grained error type labels, justifications, and corrections."
  - [section 3] Details the 5-stage pipeline (Figure 2) and 9 construction strategies (Table 1, Table 13) for controlled error injection.
  - [corpus] Neighboring papers (e.g., Factcheck-Bench, OpenFactCheck) also identify the need for fine-grained benchmarks, supporting the motivation for a more nuanced data generation approach.
- **Break condition:** If the LLM used in the pipeline fails to reliably generate errors that strictly adhere to the specified type and are verifiably unsupported by the document, the data quality degrades, leading to a model that learns incorrect error patterns.

### Mechanism 2
- **Claim:** A fine-grained error taxonomy covering semantic and discourse-level hallucinations enables more sensitive and interpretable fact-checking than binary labels.
- **Mechanism:** By classifying errors into specific categories (PredE, EntE, CircE, CorefE, LinkE, OutE), the model must learn to distinguish subtle differences in how a claim deviates from the source. This forces a deeper, more structured analysis of the document-claim relationship rather than a superficial overall match.
- **Core assumption:** The defined error types (extended from Pagnoni et al.) capture the major, distinguishable hallucination patterns produced by state-of-the-art LLMs in grounded generation tasks.
- **Evidence anchors:**
  - [abstract] "failing to capture fine-grained error types."
  - [section 3.2] Explicitly details the strategies for constructing each error category, including novel ones like discourse link reversal.
  - [section 5.2] Shows InFi-Checker's largest performance gains are on discourse-level errors (CorefE, LinkE), where binary/coarse models completely fail (0% accuracy for LinkE in GPT-4o one-shot).
- **Break condition:** If LLM hallucinations evolve to form new patterns not covered by the taxonomy (e.g., subtle logical fallacies requiring multi-hop cross-document reasoning), the model's sensitivity will drop for those new error modes.

### Mechanism 3
- **Claim:** Joint training to predict supporting evidence, fine-grained error type, justification, and correction creates a model with superior interpretability and generalizable factuality sensitivity.
- **Mechanism:** The multi-component output structure forces the model to perform evidence grounding, error diagnosis, and repair simultaneously. The justification and correction steps require the model to articulate *why* something is wrong and *what* is right, which reinforces a correct understanding of the source document's facts and relations.
- **Core assumption:** The interpretable reasoning process (evidence selection → error classification → justification → correction) is a causally linked chain where each step depends on and reinforces the correctness of the previous steps, leading to more robust internal representations of factuality.
- **Evidence anchors:**
  - [abstract] "jointly output supporting evidence, classify error types, and provide justifications along with corrections."
  - [section 4.2] Describes the end-to-end supervised fine-tuning (SFT) on the structured data.
  - [section 5.4 & Table 5] InFi-Checker achieves high Sentence Alignment Ratio (SAR), indicating its judgments are consistent with its stated reasoning, not coincidental guessing.
  - [section 5.3] Shows that fine-grained training improves performance on standard binary fact-checking benchmarks, suggesting the learned diagnostic skills transfer.
- **Break condition:** If the components become disentangled during training (e.g., the model learns to generate plausible justifications without correctly identifying the error), the interpretability benefit is lost and performance could degrade on the core classification task.

## Foundational Learning
- **Concept: Hallucination Taxonomy (e.g., Pagnoni et al. 2021)**
  - Why needed here: Understanding the prior work on categorizing hallucinations (e.g., predicate, entity, discourse errors) is essential to grasp what InFi-Check extends and why a more granular taxonomy is valuable for analysis.
  - Quick check question: What is the key difference between an "Entity Error" and a "Discourse Link Error" in the context of summarization factuality?
- **Concept: Synthetic Data Generation for NLG Training**
  - Why needed here: The entire InFi-Check framework relies on programmatically creating training data. Knowing the principles of using LLMs to generate controlled perturbations (as in MiniCheck, FactCG) is prerequisite to understanding how they ensure data diversity and quality without massive human annotation.
  - Quick check question: Why is a "chain-of-thought" prompt used during the error construction stage, and what problem does it solve?
- **Concept: Multi-Task/Structured Output Training**
  - Why needed here: InFi-Checker is not just a classifier; it's trained to produce a structured JSON-like output with multiple fields. This requires understanding how to format training data and loss calculation for models generating constrained structured text.
  - Quick check question: If the model is trained to output evidence, an error label, *and* a correction, what is a potential risk during fine-tuning if the training data has noise in any one of these fields?

## Architecture Onboarding
- **Component map:** `Input (Document + Claim)` -> `Controlled Data Synthesis Pipeline` -> `InFi-Checker Model (SFT-trained LLM)` -> `Structured Analytical Output (evidence, error type, justification, correction)`
- **Critical path:** The core innovation path is: **High-quality synthetic data (with CoT) → Structured multi-component training → Model learns joint evidence-grounding & error-classification**.
- **Design tradeoffs:**
  - Synthetic Data Fidelity vs. Scale: The pipeline is scalable but relies on LLM capabilities for accurate error construction. Errors in the synthetic process become training noise.
  - Fine-Grained Complexity vs. Annotation Cost: The taxonomy provides rich analysis but requires a model capable of handling a multi-output structure. Human verification of the benchmark is expensive.
  - Interpretability vs. Inference Speed: Producing evidence, justification, and correction increases output length and latency compared to a binary classifier.
- **Failure signatures:**
  - Data Level: High rate of "Flaws in Claim" or "Incomplete Grounding" in human eval, indicating the grounded claim generation step is failing.
  - Model Level: Per-task accuracy collapses on specific error types (e.g., LinkE) while being good on others. Low Sentence Alignment Ratio (SAR) indicates inconsistent reasoning.
  - Inference Level: Model outputs non-compliance with the required schema (e.g., missing fields) or generates justifications that do not accurately cite the provided evidence.
- **First 3 experiments:**
  1. Validate Synthetic Data Quality: Conduct human evaluation on a sample of InFi-Check-TR to measure agreement on hallucination validity and grounding. Target: >90% agreement on error validity.
  2. Benchmark Sanity Check: Run baseline LLMs (GPT-4o, Claude) on InFi-Check-FG in zero-shot with the evaluation prompt. Establish a performance baseline. Expect low balanced accuracy (<65%) and near-zero on discourse errors.
  3. Component Ablation: Train a minimal version of InFi-Checker without the justification+correction output requirement. Measure the drop in Balanced Accuracy on InFi-Check-FG. A large drop (>10%) confirms the value of the interpretable training signal.

## Limitations
- Exact prompts and model versions for the data synthesis pipeline are undocumented, hindering full replication.
- Human evaluation indicates ~15% of synthetic training samples contain flaws (e.g., incomplete grounding), introducing potential noise.
- The model's structured JSON output can be brittle; performance may degrade if the schema is violated or under distribution shift.
- The six-category error taxonomy may not cover future hallucination patterns, limiting long-term applicability.
