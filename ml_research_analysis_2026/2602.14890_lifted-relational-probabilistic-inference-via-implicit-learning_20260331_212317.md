# Lifted Relational Probabilistic Inference via Implicit Learning
## Quick Facts
- **arXiv ID:** 2602.14890
- **Source URL:** https://arxiv.org/abs/2602.14890
- **Reference count:** 11
- **Primary result:** This paper resolves the tension between learning and reasoning in first-order relational probabilistic domains by introducing an implicit learning framework that never constructs an explicit model. It combines incomplete first-order axioms with independently sampled partial observations into a bounded-degree sum-of-squares (SOS) hierarchy, solvable in polynomial time.

## Executive Summary
The paper introduces a novel framework for lifted relational probabilistic inference that integrates learning from partial observations with logical reasoning without constructing an explicit probability distribution. The core technique simultaneously performs grounding-lift (collapsing symmetric ground moments) and world-lift (aggregating all partial world assignments into a single program), enabling polynomial-time inference for fixed SOS degree and quantifier rank. Partial data are incorporated via testability and confidence intervals, converting incomplete observations into valid constraints on moments. Theoretical results establish soundness, completeness, and polynomial bit-complexity, representing the first polynomial-time system for implicit first-order probabilistic relational inference from partial observations.

## Method Summary
Given a first-order knowledge base Δ (logical and expectation constraints), a set of partially observed i.i.d. models ρ^(1..m), and parameters d (SOS degree) and k (quantifier rank), the algorithm proceeds as follows: First, it performs a lifted grounding by collapsing renaming-equivalent ground monomials of degree ≤ d into lifted variables. For each partial model, it computes worst-case lower and upper bounds for each lifted monomial by solving small SOS subproblems that respect the witnessed constraints. These per-example bounds are averaged and adjusted using Hoeffding-based confidence intervals to form global moment bounds. Finally, a single lifted semidefinite program (SDP) is constructed with a positive semidefinite moment matrix, localizing matrices for logical constraints, and linear constraints enforcing the global moment bounds. Feasibility of the SDP implies that the query is inconsistent with Δ and the data. The overall runtime is polynomial in the bit-complexity of the input for fixed d and k.

## Key Results
- Simultaneous grounding-lift and world-lift collapse infinite symmetries and aggregate partial worlds, enabling tractable inference over large domains.
- Partial observations are handled via testability and confidence intervals, avoiding data imputation while maintaining high-probability guarantees.
- For fixed SOS degree d and quantifier rank k, the lifted SDP size and solution time are polynomial, with soundness and completeness guarantees (Theorems 4 and 5).

## Why This Works (Mechanism)

### Mechanism 1: Symmetry Exploitation via Double Lift
**Claim:** Simultaneous grounding-lift (collapsing renaming-equivalent ground monomials) and world-lift (encoding all partial worlds in parallel) avoids exponential grounding and enables polynomial-size representation.
**Mechanism:** Grounding-lift reduces the number of variables by sharing across symmetric ground atoms; world-lift aggregates all examples into one global SOS program instead of separate programs per world.
**Core assumptions:** The knowledge base is explicitly compact (bounded monomial ranges) and exhibits renaming symmetries.
**Evidence:** Theorem 2 establishes soundness/completeness with lifting; Algorithm 1 implements both lifts.
**Break condition:** If quantifier rank k is large relative to SOS degree d, or explicit compactness bounds are loose, the lifted moment matrix may not capture all symmetries, leading to non-tight or infeasible programs.

### Mechanism 2: Partial Observations via Testability and Confidence Intervals
**Claim:** Incomplete data are converted into valid polynomial constraints without imputation by using worst-case bounds per example and aggregating with confidence intervals.
**Mechanism:** For each partial model, solve SOS subproblems to compute LowerBound/UpperBound for each monomial, considering only witnessed constraints. Average these bounds across examples and apply Hoeffding-based inflation to obtain global empirical moment bounds that hold with high probability.
**Core assumptions:** Observations are i.i.d. from a masking process; all monomials have finite bounded support.
**Evidence:** Definitions 6–9 and Example 6 formalize witnessing and testability; Algorithm 1 lines 4–11 implement the bounds; Theorem 4 proves soundness via Hoeffding.
**Break condition:** If masking is not independent or per-example SOS subproblems are infeasible, bounds become invalid or vacuous.

### Mechanism 3: Bounded-Degree SOS Hierarchy for Polynomial-Time Inference
**Claim:** Restricting to a bounded-degree SOS hierarchy yields polynomial-time inference for fixed d and k, despite first-order expressiveness.
**Mechanism:** The problem is encoded as an SDP over lifted moment variables of degree ≤ d. The SDP size depends polynomially on input bit-complexity and d, k, not on domain size, due to lifting.
**Core assumptions:** A degree-d SOS refutation exists if the knowledge base is inconsistent (completeness); the solver can find it in polynomial time for fixed d (via explicit compactness).
**Evidence:** Abstract and Theorem 6 state polynomial bit-complexity; lifted SOS program construction (Algorithm 1 line 13) avoids exponential blow-up.
**Break condition:** If the true refutation requires degree > d, or the SDP solver fails to certify PSD within bit-complexity bounds, the algorithm may incorrectly return feasible.

## Foundational Learning

### Sum-of-Squares (SOS) Polynomials and Semidefinite Programming
**Why needed:** SOS provides a computationally tractable way to certify polynomial non-negativity and inconsistency, bridging probabilistic constraints and algebraic refutations. The entire algorithm reduces inference to solving an SDP derived from SOS conditions.
**Quick check:** Given a polynomial inequality p(x) ≥ 0, what does it mean for p to be a sum-of-squares, and how is this represented in an SDP moment matrix?  
*Answer:* p is SOS if it can be written as ∑_i q_i(x)^2. This is equivalent to the existence of a positive semidefinite moment matrix (P SD) satisfying certain linear constraints derived from p's coefficients.

### Lifted Inference via Symmetry Collapse
**Why needed:** Naive grounding of first-order formulas yields exponentially many ground atoms. Lifted inference exploits renaming symmetries (indistinguishability of individuals) to share variables across equivalent ground atoms, keeping the representation polynomial.
**Quick check:** What is the difference between grounding-lift (collapsing symmetric ground moments) and world-lift (aggregating over partial worlds) in this paper's context?  
*Answer:* Grounding-lift reduces variables by merging monomials that are equivalent under renaming of generic names; world-lift combines all partial world assignments into a single SOS program instead of treating each world separately.

### Testability and Witnessing under Partial Observability
**Why needed:** Partial models hide some atomic values. Testability determines whether a constraint can be verified despite missing data by using worst-case bounds derived from other constraints. Witnessing evaluates a constraint under these worst-case substituted values.
**Quick check:** How does Definition 6 (witnessing) differ from simply evaluating a polynomial on observed values? Why is it necessary for partial data?  
*Answer:* Witnessing replaces unobserved variables with their worst-case bounds (from per-example SOS subproblems) to ensure the polynomial inequality holds regardless of missing values. This allows constraints to be checked even when not all variables are observed.

## Architecture Onboarding

**Component map:**  
Input (Δ, ρ^(1..m), d, k, S, δ) -> Lifted grounding (enumerate degree≤d monomials, group by renaming equivalence) -> Per-example SOS subroutines (LowerBound/UpperBound for each lifted monomial per ρ^(i)) -> Aggregation (average bounds) -> Confidence adjustment (Hoeffding inflation) -> Construct lifted SOS program (moment matrix PSD, localizing matrices, moment bound constraints) -> Solve SDP -> Output (True if feasible, else False)

**Critical path:** The most computationally intensive step is the per-example SOS subproblems (step 3), but these are embarrassingly parallel. The final SDP size is determined by the number of lifted monomials (step 2), which is the primary bottleneck for scalability.

**Design tradeoffs:**  
- **SOS degree d vs. expressiveness:** Higher d captures more complex interactions but increases SDP size exponentially. Fixed d limits inference strength.
- **Explicit compactness:** Requires each monomial to have finite known bounds; without these, confidence intervals fail.
- **Naive norm S:** Controls Hoeffding adjustment; too loose yields vacuous bounds, too tight risks violating high-probability guarantee.

**Failure signatures:**  
1. Infeasible per-example SOS subproblem: indicates inconsistency between Δ and that specific ρ^(i).
2. SDP solver numerical failure: moment matrix not PSD within tolerance (may indicate d too low or precision issues).
3. Final False but expected True: could be due to overly conservative confidence intervals (insufficient m) or slight violation of Δ by true distribution.

**First 3 experiments:**  
1. **Sanity check with fully observed data:** Run with no missing values (∗-free ρ^(i)). Per-example bounds should exactly match observed values, and algorithm should reduce to standard lifted SOS inference. Validate against a propositional grounder on a tiny domain.
2. **Partial observability stress test:** Systematically hide known truth values in ρ^(i) and check that the returned answer remains correct only if the hidden proportion is within testability guarantees. Measure answer stability as masking probability increases.
3. **Scaling d and k:** On a fixed small KB, increase d and k until SDP size grows intractably. Plot SDP solve time vs. number of lifted monomials to identify practical limits for fixed d,k.

## Open Questions the Paper Calls Out
1. **Empirical scalability:** The paper does not evaluate on real-world relational datasets; it is unknown how runtime, memory, and solution quality scale with domain size, arity, and masking rate.
2. **Specialized SOS solvers:** Off-the-shelf SOS solvers may not exploit lifted symmetry and sparsity; new solvers tailored to this structure could improve scalability.
3. **Open universes:** The framework assumes a finite set of constants plus k generic names, effectively bounding domain size. Extension to truly unbounded domains while maintaining polynomial-time guarantees is open.
4. **Parameter selection:** No guidance is given for choosing SOS degree d, quantifier rank k, or naive norm bound S; adaptive strategies are needed.

## Limitations
- The exact encoding of "witnessing" into SOS constraints for per-example bound computation is not detailed, hindering faithful implementation.
- The masking process Θ(D) for generating partial data is unspecified, making synthetic data generation ambiguous.
- Parameter selection (d, k, S) lacks practical heuristics; choosing these incorrectly can break soundness/completeness.
- Lifting implementation (grouping renaming-equivalent monomials) is theoretically defined but algorithmically non-trivial.
- The theory relies on explicit compactness and testability conditions that may be difficult to verify in practice.

## Confidence
- **Simultaneous double-lift mechanism (grounding-lift + world-lift):** High – supported by Theorem 2 and lifted SOS framework; consistent with lifted inference literature.
- **Integration of partial observations via testability & confidence intervals:** Medium – theoretically sound (Theorems 4,5) but hinges on unspecified witnessing SOS subroutines and i.i.d. masking; no empirical validation.
- **Polynomial-time inference for fixed d,k:** Medium – Theorem 6 proves polynomial bit-complexity, but hidden constants and practical SDP solver performance may limit scalability; no runtime experiments reported.
