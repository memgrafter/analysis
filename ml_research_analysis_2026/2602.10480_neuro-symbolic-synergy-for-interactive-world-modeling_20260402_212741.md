# Neuro-Symbolic Synergy for Interactive World Modeling
## Quick Facts
- **arXiv ID:** 2602.10480
- **Source URL:** https://arxiv.org/abs/2602.10480
- **Reference Count:** 40
- **Primary Result:** NeSyS combines an LLM-based world model with symbolic Python rules, achieving higher accuracy than full fine-tuning while using 35-60% less training data via reciprocal, rule-guided training.

## Executive Summary
NeSyS introduces a framework for interactive world modeling that synergistically combines a neural language model with a symbolic world model composed of executable Python rules. Unlike prompt-based methods, the symbolic model directly modifies the LLM's output probability distribution during inference by treating rule scores as an energy term. A reciprocal training loop alternates between fine-tuning the neural model only on trajectories poorly explained by the current rules (reducing data needs) and refining the symbolic rules from the neural model's new errors. Evaluated on ScienceWorld, Webshop, and Plancraft with Llama3.2-1B and Qwen3-4B, NeSyS demonstrates consistent improvements in accuracy and data efficiency over full supervised fine-tuning baselines.

## Method Summary
The method operates in two phases. Phase 1 initializes a neural world model (a pre-trained instruct-tuned LLM) and induces an initial symbolic rule set from its errors on a development set. This involves clustering error trajectories, prompting an LLM to generate candidate Python scoring functions for each cluster, and validating rules that improve dev accuracy. During inference (Phase 2), for each candidate next-state, the neural model's probability *pᵢ* is combined with an aggregated symbolic energy *Eᵢ* via *p̃ᵢ = pᵢ exp(γEᵢ)*, and the highest *p̃ᵢ* is selected. The reciprocal training loop then: (1) selects training data proportional to *1/k* (where *k* is the number of active rules covering a training step), keeping all steps with *k=0*; (2) fine-tunes the neural model on this reduced, "harder" subset; (3) clusters the updated model's new errors to synthesize additional or refined rules; and (4) optimizes rule weights on the dev set. This loop ensures each component learns from the other's residual failures.

## Key Results
- NeSyS (Llama3.2-1B) achieves **68.3%** accuracy on ScienceWorld vs. **64.4%** for full supervised fine-tuning (SFT).
- On Webshop, NeSyS reaches **92.2%** vs. **47.5%** for SFT.
- On Plancraft, NeSyS scores **87.7%** vs. **80.5%** for SFT.
- The rule-guided data selection filters approximately **50%** of training data without accuracy loss.

## Why This Works (Mechanism)
### Mechanism 1
Direct probability distribution modification via symbolic energy terms enforces deterministic constraints without relying on LLM instruction-following. Symbolic rules output scores in [-1,1] aggregated into an energy term *Eᵢ*. This term multiplicatively rescales the neural model's candidate probability *pᵢ* to *p̃ᵢ = pᵢ exp(γEᵢ)*, reshaping the probability landscape directly. The core assumption is that executable Python rules can be evaluated efficiently and locally on candidate outputs, providing a reliable, discrete signal orthogonal to the LLM's probabilistic outputs. A break condition occurs if the symbolic rule set is incomplete or mis-specified, causing incorrect suppression or promotion of candidates.

### Mechanism 2
Rule-guided data selection reduces training redundancy by filtering out trajectories already explained by symbolic rules. Training steps are weighted by the number *k* of active symbolic rules covering them. Steps with *k=0* (uncovered) are kept entirely; others are sampled with probability ~1/k, prioritizing "hard" examples where symbolic knowledge is insufficient. The core assumption is that a significant portion of interactive trajectory data demonstrates behaviors fully determined by a compact rule set, making their repetition in neural fine-tuning unnecessary. A break condition is a poor initial rule coverage (many false negatives), which discards data containing essential nuanced or stochastic dynamics.

### Mechanism 3
Reciprocal refinement—training each component on the other's residual errors—prevents redundancy and drives mutual improvement. After initialization, an iterative loop runs: symbolic WM's rule-guided selection filters neural WM fine-tuning data; the refined neural WM's new errors are clustered to synthesize new/refined symbolic rules. Each model is explicitly trained on the "blind spots" of the other. The core assumption is that error spaces are complementary; failures are systematic and thus discoverable clusters from which generalizable rules can be induced. A break condition is if one model's errors become random noise, preventing rule induction from producing generalizable rules.

## Foundational Learning
- **Concept: Energy-Based Models & Probability Manipulation**
  *Why needed:* Understanding how an external scalar energy term integrates into a probabilistic model's output distribution (e.g., via Boltzmann resampling) is core to Mechanism 1.
  *Quick check:* How does multiplying the LLM's candidate probability by `exp(γEᵢ)` change the decision boundary compared to simply adding a logit bias?
- **Concept: Inductive Bias of Symbolic Rules**
  *Why needed:* To grasp why a small set of Python functions can cover a large portion of deterministic dynamics (enabling Mechanism 2's data reduction) and how their expressive limits define the boundary for neural learning.
  *Quick check:* For a rule `if action=="click[buy now]" and "Buy Now button" not in state: return -1`, what assumption about the environment's determinism makes this rule universally applicable?
- **Concept: Partially Observable Markov Decision Process (POMDP) Approximation**
  *Why needed:* The world modeling task approximates a latent-state POMDP using a textual belief state (truncated history). This framing defines the prediction problem and justifies trajectory-based training data.
  *Quick check:* If the belief state is a truncated history, what types of environment dynamics are fundamentally unrepresentable to the world model?

## Architecture Onboarding
- **Component map:**
  Neural WM (LLM) -> Inference Engine (modifies p_i with symbolic energy) -> Output
  Error Clustering -> Rule Induction Module (GPT-5-mini) -> Symbolic WM (rule set F)
  Symbolic WM -> Data Selector (computes k, samples 1/k) -> Neural WM Fine-Tuning
  Reciprocal Refinement Controller orchestrates the loop.
- **Critical path:** Initialize Neural WM (pre-trained) and Symbolic WM (from dev errors) -> Loop: [Rule-guided data selection] -> [Neural WM fine-tuning] -> [New error clustering] -> [Rule induction/reflection] -> [Weight optimization] -> repeat.
- **Design tradeoffs:**
  - Rule expressivity vs. generalization: Complex Python rules capture finer dynamics but risk overfitting and brittleness.
  - Data reduction vs. coverage: Aggressive filtering (high 1/k) risks losing data for dynamics not yet captured by any rule; % filtered is environment-dependent.
  - Computational cost: Rule evaluation is cheap, but rule induction (LLM prompting + dev validation) is expensive and offline.
- **Failure signatures:**
  1. Neural WM too weak (Phase 1): Poor neural signal (p_i near random) can be drowned by noisy symbolic scores.
  2. Catastrophic forgetting in Neural WM: Full fine-tuning may degrade capabilities on covered subtasks (e.g., Plancraft Smelt).
  3. Stagnant reciprocal loop: If errors become random, rule induction fails to produce useful rules, halting progress.
- **First 3 experiments:**
  1. **Component Isolation Test:** Evaluate initialized Neural WM and Symbolic WM separately on dev set; quantify error disjointness (low overlap needed for synergy).
  2. **Energy Term Sanity Check:** For dev examples with a known correct rule, manually compute E_i and verify p̃_i ranks the correct candidate highest.
  3. **Rule-Guided vs. Random Data Selection Ablation:** Train Neural WM on same budget using (a) rule-guided vs. (b) random sampling; compare final NeSyS accuracy.

## Limitations
- Rule weighting optimization loss and data selection sampling algorithm are underspecified, requiring empirical tuning.
- Clustering and rule induction stability depend on OPTICS/UMAP parameters and GPT-5-mini settings, leading to variable rule quality.
- Reciprocal loop scalability is unclear; dependency on an external LLM for rule induction may not scale to long-horizon tasks.

## Confidence

- Mechanism 2 (Rule-Guided Data Selection): Medium
