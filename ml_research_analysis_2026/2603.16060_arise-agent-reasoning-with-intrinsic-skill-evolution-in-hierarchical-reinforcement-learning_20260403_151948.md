# ARISE: Agent Reasoning with Intrinsic Skill Evolution in Hierarchical Reinforcement Learning

## Quick Facts
- **arXiv ID:** 2603.16060
- **Source URL:** https://arxiv.org/abs/2603.16060
- **Reference count:** 29
- **Primary result:** ARISE improves mathematical reasoning in 4B-class LLMs via a hierarchical skill-management framework, achieving up to 2.9 percentage point gains on Olympiad-level benchmarks and strong out-of-distribution performance.

## Executive Summary
Existing reinforcement learning methods for enhancing LLM reasoning treat each problem in isolation, discarding reusable strategies. ARISE introduces a hierarchical reinforcement learning framework where a single shared policy acts as both a high-level Skills Manager and a low-level Worker. The Manager maintains a tiered skill library, selecting relevant skills via conditional log-probability scores before execution and generating new skills by summarizing successful solution traces afterward. A hierarchical reward—combining problem correctness with a skill-use bonus—incentivizes the policy to leverage useful skills, fostering a co-evolutionary dynamic between reasoning ability and library quality. Experiments on two 4B instruction-tuned models across seven math benchmarks show ARISE consistently outperforms GRPO-family algorithms and memory-augmented baselines.

## Method Summary
ARISE employs a single shared policy network that dynamically assumes two roles: a high-level Skills Manager and a low-level Worker. At the start of a problem, the Manager selects a skill from a tiered library based on conditional log-probability scores relative to the current context. The Worker then executes the chosen skill to generate reasoning steps. Upon successful completion, the Manager summarizes the solution trace to create a new skill added to the library. Training uses a hierarchical reward signal that combines the final answer correctness with a bonus for using high-quality skills from the library. This design encourages reuse of effective strategies while continuously expanding the library with novel, successful patterns, creating a feedback loop where improved skills lead to better reasoning, which in turn yields better skills.

## Key Results
- ARISE outperforms GRPO-family algorithms and memory-augmented baselines across seven mathematical reasoning benchmarks.
- Achieves up to 2.9 percentage points higher average accuracy on Olympiad-level problems compared to baselines.
- Shows particularly strong improvements on out-of-distribution tasks, indicating better generalization.

## Why This Works (Mechanism)
The core mechanism is a co-evolutionary loop between a skill library and a unified policy. The hierarchical reward explicitly incentivizes the policy to reuse skills from the library, which encourages the discovery and retention of generally useful strategies. Because the same policy controls both skill selection (Manager) and execution (Worker), it learns to align skill creation with skill usage, ensuring new skills are relevant to the problems it encounters. The conditional log-probability selection provides a lightweight, context-aware retrieval mechanism that avoids the overhead of separate retrieval models. This closed loop causes the quality of the skill library and the policy's reasoning proficiency to improve together: better skills lead to more successful traces, which yield better new skills, further boosting performance.

## Foundational Learning
- **Hierarchical Reinforcement Learning:** Decomposes complex reasoning into high-level skill management and low-level execution. *Why needed:* Reduces the search space and enables reuse of macro-actions. *Quick check:* Is the high-level policy distinct from the low-level in architecture or just role?
- **Skill Library Management:** A shared repository of reusable reasoning patterns. *Why needed:* Captures and persistes strategies beyond single episodes. *Quick check:* How are skills indexed and retrieved? Is there a tiering mechanism?
- **Co-evolution of Skills and Policy:** Mutual improvement where policy performance and library quality reinforce each other. *Why needed:* Prevents skill library stagnation and aligns skill generation with current policy capability. *Quick check:* Do library metrics (e.g., skill reuse rate) correlate with performance over training?
- **Conditional Skill Selection:** Using conditional log-probability to score skill relevance given context. *Why needed:* Provides a simple, tunable relevance measure without extra parameters. *Quick check:* Does selection favor frequency over quality? How is the conditioning prompt constructed?
- **Hierarchical Reward Shaping:** Combining task success with a skill-use bonus. *Why needed:* Explicitly incentivizes leveraging the library rather than ad-hoc reasoning. *Quick check:* How is the skill bonus computed? Is it normalized or absolute?
- **Unified Policy Architecture:** A single network handling both Manager and Worker roles. *Why needed:* Reduces computational overhead and ensures skill selection matches execution style. *Quick check:* Does role-switching cause instability? How is context for each role differentiated?

## Architecture Onboarding
**Component map:**  
Manager (skill selection/generation) -> Worker (execution) -> Environment; Skill Library (shared storage); Hierarchical Reward (shapes both)

**Critical path:**  
1. Problem presented -> Manager selects skill from library using conditional log-probability.  
2. Worker executes selected skill, generating reasoning steps.  
3. Environment returns outcome (correct/incorrect) and intermediate trace.  
4. If successful, Manager summarizes trace into a new skill added to library.  
5. Hierarchical reward computed (correctness + skill bonus) updates shared policy.

**Design tradeoffs:**  
- Shared policy simplifies architecture and ensures consistency but may limit specialization for selection vs. execution.  
- Conditional log-probability selection is efficient and interpretable but may bias toward frequent skills and struggle with nuanced relevance.  
- Skill generation from traces risks adding noisy or redundant skills without robust filtering.

**Failure signatures:**  
- Low skill library hit rate (Manager frequently selects "default" reasoning).  
- Stagnant skill diversity (few new skills added after initial phase).  
- Performance drop on out-of-distribution problems despite in-distribution gains.  
- High variance in skill quality leading to unstable training curves.

**First experiments:**  
1. Scale ARISE to 7B and 13B parameter models to test architectural scalability and performance trends.  
2. Evaluate on non-math reasoning benchmarks (e.g., BBH, HellaSwag) to assess domain generality.  
3. Track skill library metrics (creation rate, reuse frequency, semantic diversity) across training and correlate with accuracy improvements.

## Limitations
- Evaluation restricted to 4B instruction-tuned models; scaling to larger or differently architected LLMs is unknown.
- Benchmarks are mathematically focused; generalization to other reasoning domains (e.g., commonsense, code) is not established.
- No reporting of computational overhead or sample efficiency compared to standard RL methods.
