# TDATR: Improving End-to-End Table Recognition via Table Detail-Aware Learning and Cell-Level Visual Alignment

## Quick Facts
- **arXiv ID**: 2603.22819
- **Source URL**: https://arxiv.org/abs/2603.22819
- **Reference count**: 40
- **Primary result**: TDATR achieves state-of-the-art performance on seven table recognition benchmarks without dataset-specific fine-tuning (e.g., TEDS 97.97 on PubTables-1M, 95.12 on PubTabNet) and SOTA cell localization (AP50 94.37 on iFLYTAB-full).

## Executive Summary
TDATR introduces a "perceive-then-fuse" training paradigm for end-to-end table recognition. It first learns robust table detail perception from diverse document-level tasks (OCR, element detection, Markdown parsing) via multi-task language modeling, without requiring table-specific annotations. Then, with limited table recognition data, it fine-tunes on HTML generation while activating a Structure-Guided Cell Localization (SGCL) module that uses structural priors from the generated HTML to refine cell bounding boxes. This decoupled approach reduces reliance on large annotated table datasets and explicitly aligns visual features with structural output. TDATR achieves SOTA results on multiple benchmarks and demonstrates strong generalization to varied table styles.

## Method Summary
TDATR uses a two-stage training strategy. **Stage 1 (Table Detail-Aware Learning)**: A vision-language model (Swin Transformer encoder + Transformer decoder) is trained on a large corpus of document images (webpages, papers, READMEs, etc.). A variety of tasks (spatially ordered text spotting, text spotting with box query, Markdown parsing, table cell/row/column detection, and table structure parsing) are reformulated as next-token prediction, sharing parameters with task-specific prompts. This stage builds a rich representation of textual and structural semantics. **Stage 2 (Table Detail Fusion Fine-tuning)**: The model is fine-tuned on the HTML parsing task using limited table recognition datasets (iFLYTAB-full, TabRecSet, PubTabNet, PubTables-1M, FinTabNet). Concurrently, the SGCL module is activated: it pools decoder hidden states between `<td>` tags to obtain cell representations, enhances them via bidirectional attention guided by row/column adjacency masks derived from these representations, and regresses initial cell boxes that are refined with multi-resolution visual features via DAB-DETR decoder layers. The total loss combines cross-entropy for HTML tokens and detection losses (L1, IoU, generalized IoU, structure consistency) with weighting factors. Both encoder and decoder are trained in both stages.

## Key Results
- SOTA on seven table recognition benchmarks (e.g., TEDS 97.97 on PubTables-1M, 95.12 on PubTabNet) without dataset-specific fine-tuning.
- SOTA cell localization: AP50 94.37 on iFLYTAB-full.
- Competitive with large VLMs on general OCR benchmarks (CC-OCR, OCRBenchv2, OmniDocBench1.5).

## Why This Works (Mechanism)

**Mechanism 1: Decoupled Perception-Fusion Pipeline**  
TDATR decouples table recognition into a perception stage (learning fine-grained table details from diverse document data) and a fusion stage (integrating these details to generate HTML with limited TR data). The perception stage uses multi-task language modeling to jointly learn structure and content without explicit table annotations, building a reusable representation that can be efficiently fine-tuned on HTML parsing with small TR datasets. *Break condition*: representations insufficiently general or misaligned with table domain. *Evidence*: Ablation shows major performance drops when perception tasks are removed (Table 7 T0 vs T3).

**Mechanism 2: Multi-Task Pretraining for Robust Detail Perception**  
Joint training on a diverse set of content recognition (OCR) and structure understanding tasks under a unified next-token objective creates a robust vision-language model that generalizes across table variations. The model learns to interweave textual and structural semantics from millions of document samples (webpages, papers, READMEs), mitigating data scarcity for any single TR dataset. *Break condition*: negative transfer due to conflicting objectives. *Evidence*: Complementary benefits from content vs. structure tasks (Table 7 T1/T2) and massive pretraining data scale.

**Mechanism 3: Structure-Guided Cell Localization for Visual Alignment**  
A dedicated SGCL module refines cell bounding boxes by leveraging structural relationships (row/column adjacency) extracted from the generated HTML sequence. It pools decoder hidden states for cell representations, enhances them via structure-guided attention using adjacency masks from pairwise similarities, and refines boxes with multi-resolution features via DAB-DETR. This yields accurate parallel cell localization. *Break condition*: errors in generated HTML structure (e.g., wrong spans) produce invalid adjacency masks, degrading localization. *Evidence*: SOTA AP50 (94.37 on iFLYTAB-full); failure cases include boundary confusion and span errors.

## Architecture Onboarding

**Component map**  
Image → Visual Encoder (Swin) → Multi-scale features (P₃,P₄,P₅) → Cross-resolution fusion → P'₃,P'₄ → (Path1: Decoder) V=P'₄ + task prompt T → Transformer Decoder → Hidden states hᵢ → HTML output; (Path2: SGCL) Pool hᵢ between `<td>` tags → cell representations C → Structure-guided enhancement (row/col projection + adjacency mask + masked self-attn) → enhanced C' → Box regression → B_init → DAB-DETR refinement (with P'₃,P'₄) → final cell boxes B.

**Critical path**  
Stage1: Train encoder+decoder on all detail-aware tasks (content + structure) with next-token prediction loss.  
Stage2: Fine-tune encoder+decoder on HTML parsing; simultaneously train SGCL module with combined detection losses. Both stages update all encoder/decoder parameters; SGCL only in Stage2.

**Design tradeoffs**  
- *Perceive-Then-Fuse vs. Joint Training*: Decoupling enables pretraining on cheap document data but risks domain gap; joint training fits TR directly but needs massive labeled TR data.  
- *Parallel SGCL vs. Sequential Coordinate Generation*: SGCL regresses all cell boxes in parallel (1.6× faster) but assumes token-to-cell correspondence; sequential generation is slower but may handle complex layouts.  
- *Structure Mask vs. Pure Visual Cues*: Structure-guided enhancement improves accuracy on ambiguous cells but depends entirely on correctness of HTML structure; pure visual cues would be more robust to sequence errors.

**Failure signatures**  
1. *Boundary confusion*: Merged or split cells in borderless tables with multi-line text.  
2. *Span number errors*: Incorrect `colspan`/`rowspan` counts, especially for large spans (>15).  
3. *Empty cell instability*: Unreliable boxes for empty cells due to weak visual cues.  
4. *Sequence truncation*: Autoregressive HTML generator may omit cells on very long tables.

**First 3 experiments**  
1. Ablation of pretraining tasks: disable Content Recognition (T1), Structure Understanding (T2), or both (T0) during perception stage and evaluate final TEDS after fusion (Table 7).  
2. Ablation of SGCL components: start with initial regression only (C1), add row/col attention (C2), structure masks (C3), and multi-resolution refinement (C4) to measure impact on TEDS and AP50 (Table 8).  
3. Single-dataset fine-tuning vs. unified: perform only fusion stage on PubTabNet (from same pretrained checkpoint) and compare to unified model on PubTabNet to test paradigm's absolute vs. generalization strength (Appendix G).

## Open Questions the Paper Calls Out
1. How can TDATR accurately distinguish cell boundaries from inter-character spacing in borderless tables with multi-line text to reduce boundary confusion errors?
2. How can the prediction of large row/column span cells (e.g., >15) be made more accurate to avoid span number errors?
3. What methods can enhance localization stability for densely packed or empty borderless cells that lack explicit visual cues?

## Limitations
- Reproduction is hindered by missing details: exact hyperparameters (LR, scheduler, batch size), Stage1 task mixing proportions, SGCL internal dimensions (mask threshold, projection sizes), and the specific "Donut Chinese" checkpoint configuration; also reliance on a commercial OCR engine for data generation creates a non-reproducible dependency.
- The "perceive-then-fuse" paradigm's data efficiency claim is validated only on the specific fusion datasets used; its generalization to entirely unseen table domains remains untested.
- SGCL's structural guidance is brittle to upstream HTML generation errors; span or ordering mistakes propagate directly to cell localization.

## Next Checks
1. **Representation Transfer Test**: Freeze the model after Stage1, probe on a held-out, stylistically divergent table dataset (e.g., historical tables or complex merged cells) using a lightweight adapter; quantify performance drop versus in-distribution tables.
2. **SGCL Robustness to Sequence Errors**: During Stage2 inference, systematically corrupt the generated HTML structure (random cell swaps, span errors, row deletions) before SGCL; measure AP50 degradation relative to a SGCL variant using only visual features.
3. **Task Interference Diagnosis**: Log per-task loss trajectories and gradient norms throughout Stage1; compute gradient cosine similarity between opposing tasks (e.g., fine-grained OCR vs. abstract structure parsing) to detect negative transfer.
