# AgriWorld:A World Tools Protocol Framework for Verifiable Agricultural Reasoning with Code-Executing LLM Agents

## Quick Facts
- **arXiv ID:** 2602.15325
- **Source URL:** https://arxiv.org/abs/2602.15325
- **Reference count:** 40
- **Primary result:** Agro-Reflective achieves 73.84% aggregate accuracy on AgroBench, with 92% bug recovery via an execute-observe-refine loop and robust performance under spatial/temporal distribution shifts.

## Executive Summary
Agricultural AI faces a dual challenge: foundation models lack interactive reasoning over heterogeneous spatiotemporal data, while LLMs cannot natively process such datasets. AgriWorld addresses this with a Python execution environment that unifies geospatial queries, remote sensing, crop simulation, and predictors under a canonical alignment operator. Built on top, the Agro-Reflective agent iteratively writes and executes code, observes structured results, and refines its approach in a closed loop. Evaluated on the AgroBench suite, it substantially outperforms text-only and one-shot tool-use baselines, particularly on forecasting and counterfactual analysis, while maintaining robustness to out-of-distribution shifts.

## Method Summary
AgriWorld provides a Python runtime with typed tool APIs for agricultural data operations (geospatial filtering, raster time series, crop simulation). The framework enforces a canonical alignment operator Π that reprojects and resamples all inputs to a task-specific coordinate reference system and temporal frequency, preventing upstream misalignment errors. Agro-Reflective, the LLM agent, uses an execute-observe-refine loop: it generates code, executes it in AgriWorld, receives structured observations (including runtime errors and artifact metadata like units and coverage), and reflects to produce corrected code. Final answers are validated by a protocol checker V that enforces schema validity, numeric tolerance, counterfactual consistency, and physical sanity. The agent (e.g., Qwen3-LoRA) is fine-tuned on AgroBench training tasks.

## Key Results
- **Aggregate accuracy:** 73.84% on AgroBench vs. 36.75% (text-only) and 48.2% (one-shot tool use).
- **Forecasting:** NRMSE 0.18 vs. 0.34 (one-shot).
- **Counterfactual analysis:** 71.4% success vs. 43.8% (one-shot).
- **Bug recovery:** Initial bugs (35%) are recovered in 92% of cases.
- **Robustness:** Accuracy drops only 12% under spatial OOD shift and 6% under temporal shift.

## Why This Works (Mechanism)

### Mechanism 1: Canonical Alignment Operator Π
- **Claim:** Π reduces spatiotemporal integration errors by unifying heterogeneous data into a task-specific working space.
- **Mechanism:** Π composites spatial reprojection (`S_reproject`) and temporal resampling (`T_resample`) with strict interpolation policies, ensuring vector parcels, raster time series, weather streams, and grid fields share a common CRS and temporal frequency before joint operations. This prevents misalignment failures (e.g., empty intersections from WGS84 parcels with UTM rasters) upstream.
- **Core assumption:** The chosen task-specific canonical CRS and temporal frequency are appropriate, and interpolation policies preserve physical semantics without significant artifacts.
- **Evidence anchors:** [abstract] mentions "Coordinate Alignment mechanism"; [section 3.2] defines Π = (T_resample ◦ S_reproject); neighbor papers (AgriAgent, Tool Decathlon) lack this primitive.

### Mechanism 2: Execute-Observe-Refine Loop
- **Claim:** The loop enables recovery from latent coding bugs and semantic errors that cause silent failures in one-shot tool execution.
- **Mechanism:** After each execution, the agent receives structured observations (o_t, O_t) including runtime errors, artifact metadata (units, CRS, validity ratios), and protocol violations. The reflection function ρ categorizes error types (e.g., SpatialMisalignment, UnitError) and generates targeted patches, transforming feedback into a debugging signal.
- **Core assumption:** ρ can correctly diagnose error types from metadata and generate syntactically/semantically valid patches.
- **Evidence anchors:** [abstract] describes the loop; [section 3.3] emphasizes artifact-driven reflection; [section 4.3] reports 92% recovery from initial 35% bug rate; neighbor "Reflexion" uses verbal reinforcement, while this is artifact-grounded.

### Mechanism 3: Verifiable Evaluation Protocol V
- **Claim:** Executable checkers constrain the agent’s hypothesis space to physically plausible, schema-compliant solutions, reducing plausible-but-incorrect answers.
- **Mechanism:** Each task instance includes a checker V that validates final answer ˆy and audit trail O against: (1) Schema Validity (strict JSON keys/units), (2) Numeric Tolerance (|ˆy − y*| < δ), (3) Counterfactual Consistency (causal direction with significance Δ), (4) Physical Sanity (unit homogeneity, valid-pixel coverage ν > τ_min). Loop terminates only on V=1.
- **Core assumption:** Reference simulator outputs y* and checker logic accurately encode ground truth and physical constraints.
- **Evidence anchors:** [abstract] introduces AgroBench with executable checkers; [section 3.4] describes four constraint levels; [section 4.2] shows large gains on counterfactuals; neighbors (EigenAI, Secure Tool Manifest) pursue different verifiability forms.

## Foundational Learning

### Concept: Spatiotemporal Data Alignment
- **Why needed:** Agricultural queries join disparate data types (vector parcels, raster satellite images, weather time series) that use different coordinate systems and temporal resolutions. Without alignment, spatial joins yield empty sets and temporal aggregations misrepresent phenological stages.

### Concept: Tool-Augmented LLM Reasoning
- **Why needed:** LLMs cannot process high-dimensional spatiotemporal tensors natively. The agent must generate syntactically correct Python code to invoke AgriWorld’s typed tool APIs, handle returned artifacts (DataFrames, plots), and chain operations, requiring understanding of tool signatures, schemas, and side effects.
- **Quick check:** "How does the agent’s interaction with AgriWorld differ from a standard Code Interpreter? What additional signals does Agro-Reflective exploit that a one-shot code generation does not?"

### Concept: Verifiable Scientific Protocols
- **Why needed:** In agriculture, a numerically plausible answer (e.g., "yield increase of 5%") may be wrong due to unit mismatches, spatial misalignment, or ungrounded counterfactuals. Verifiable evaluation requires answers to pass executable checks enforcing physical constraints, not just text similarity.
- **Quick check:** "List and briefly explain the four levels of constraints in the verifiable protocol V. Which level would catch an agent that reports yield in kg/ha but forgets to convert from g/m²?"

## Architecture Onboarding

### Component map
User Query → Agent (Agro-Reflective) ↔ AgriWorld Environment ↔ Protocol Checker (V)
    │               │                    │
    │      Memory (trace τ_t, artifacts O_t)    │
    │               │                    │
    └─── generates code ──── executes ──── returns (o_t, O_t)
          ↑                                   │
          └────── reflection (ρ) ←────────────┘

- **Agent:** LLM (e.g., Qwen3-LoRA) with policy π_θ, maintains memory of past (code, observation, artifact) tuples. Generates code patches via reflection function ρ.
- **Environment (AgriWorld):** Python runtime with state space S (Parcels, Raster TS, Grid Fields, Weather, Management). Exposes tool families (Geospatial, RS, Simulation, Predictors). Returns structured observations and cryptographic artifact hashes.
- **Protocol (V):** Task-specific checker function with schema, numeric, causal, and physical constraints. Terminates loop on success (z=1).

### Critical path
1. **Task binding:** Query q is bound to concrete data handles (parcel IDs, time ranges) → initial state s_in.
2. **Code generation:** Agent proposes code c_t targeting tools (e.g., `rs.load`, `sim.run`).
3. **Execution & artifact capture:** AgriWorld executes c_t, returns observation (stdout/stderr) and artifact α (type, payload, meta, prov). Meta includes units, CRS, validity ratios.
4. **Validation:** Protocol V checks provisional answer ˆy_t against constraints using O_1:t. If z=1, return final answer; else, agent reflects using M(α_t) and error report d.
5. **Patch & iterate:** Agent generates corrected code c_{t+1} based on reflection, repeats until T_max or success.

### Design tradeoffs
- **Alignment universality vs. precision:** Π chooses a single task-specific CRS/frequency, simplifying joins but potentially degrading data requiring native resolution (e.g., high-frequency irrigation events). System defaults to metric CRS (EPSG:3857) and daily resampling.
- **Reflection depth vs. compute budget:** Each reflection step costs one LLM call. Paper sets T_max=20; average convergence at 3.5 turns. Longer horizons yield diminishing returns but risk infinite loops.
- **Verifiability vs. tolerance:** Strict numeric tolerances (δ) and physical checks (ν > τ_min) prevent false positives but may reject valid answers in noisy regimes (e.g., cloudy days reducing ν). Protocol uses dynamic δ per task type.

### Failure signatures
- **Spatial misalignment:** `LowCoverageError` or empty DataFrames from `geo.sjoin`; validity ratio ν below τ_min in zonal stats.
- **Temporal misalignment:** Mismatched index lengths in merged DataFrames; weather time series not resampled to daily frequency before crop simulation.
- **Unit inconsistency:** Artifact meta shows conflicting units (e.g., mm vs. m) or agent forgets conversion. Checker fails at "Physical Sanity".
- **Unrecoverable bugs:** Agent repeatedly proposes same failing code pattern; reflection loop exhausts T_max without passing V. (92% recovery rate suggests most failures within loop capacity.)
- **Counterfactual invalidation:** Checker rejects because `M(s, a_intervene) - M(s, a_baseline)` is positive (intervention harms) or below significance Δ.

### First 3 experiments
1. **Basic lookup smoke test:**  
   Run task: "What is the crop type of parcel P123?"  
   Expected: Agent calls `geo.filter_parcels` or `parcel_lookup`, artifact returns metadata with `crop_type`. Verify parser extracts correct value and passes Schema Validity. Observe if first code contains syntax errors→requires reflection.
   
2. **Alignment failure & recovery:**  
   Modify task to involve a parcel in WGS84 and a Sentinel-2 raster in UTM zone 10N.  
   Expected: First attempt fails with empty spatial join. Agent should either (a) invoke alignment via Π automatically or (b) explicitly reproject via `rio.reproject`. Reflection should diagnose "SpatialMisalignment" and insert reprojection step. Measure recovery rate.
   
3. **Counterfactual causal check:**  
   Task: "If we reduce irrigation by 20% on parcel P456 during July, does predicted water stress decrease by at least 10%?"  
   Expected: Agent runs `sim.run` twice (baseline vs.干预). Checker verifies `stress_intervene - stress_baseline <= -0.1`. Agent must correctly interpret simulator output and formulate answer within tolerance. Test if agent mistakenly reports absolute stress values instead of difference.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** Can Agro-Reflective handle ambiguous real-world agronomic queries that require clarification, beyond the clear AgroBench tasks?
- **Basis in paper:** [inferred] AgroBench is generated from predefined tasks, not real user interactions.
- **Why unresolved:** Real workflows often involve ambiguous phrasing and iterative clarification.
- **What evidence would resolve it:** Conduct user studies with agronomists, measuring success on natural language queries vs. AgroBench.

### Open Question 2
- **Question:** What are the remaining 8% of bugs that Agro-Reflective's reflection loop fails to fix, and how can we recover them?
- **Basis in paper:** [explicit] Paper reports 92% recovery from initial bugs, leaving 8% unrecovered.
- **Why unresolved:** Unrecovered bugs limit reliability; their nature is unknown and unanalyzed.
- **What evidence would resolve it:** Analyze failed cases, categorize error types (e.g., complex spatial joins), and design targeted reflection enhancements.

### Open Question 3
- **Question:** Is the World-Tools-Protocol framework transferable to other spatiotemporal scientific domains (e.g., climate, epidemiology) with similar effectiveness?
- **Basis in paper:** [explicit] Conclusion suggests applicability but no cross-domain validation.
- **Why unresolved:** Different domains have unique data structures, tools, and validation protocols; transferability remains speculative.
- **What evidence would resolve it:** Adapt AgriWorld to another domain, implement domain-specific tools, and benchmark against baselines.

### Open Question 4
- **Question:** How does inaccuracy in AgriWorld's simulation/prediction tools affect Agro-Reflective's output reliability, and can the agent detect such tool errors?
- **Basis in paper:** [inferred] Tools are assumed correct; their real-world fidelity is not evaluated.
- **Why unresolved:** Inaccurate tools may yield incorrect answers that still satisfy validators, undermining verifiability.
- **What evidence would resolve it:** Inject controlled biases into tools (e.g., systematic overestimation) and test whether reflection or cross-validation can flag inconsistencies.

## Limitations
- AgriWorld code, AgroBench data, and LoRA fine‑tuning details are unreleased; replication requires full reimplementation.
- Reflection policy ρ (error categorization, patch generation) is underspecified; only high‑level description provided.
- Synthetic benchmark tasks may not capture full complexity of real agricultural workflows.

## Confidence
- **Canonical alignment operator (Π):** Medium. Mechanism is sound and cited, but no independent ablation results available.
- **Execute‑Observe‑Refine loop:** Medium‑High. Paper reports 92% bug recovery, but self‑reported without external audit.
- **Verifiable protocol (V):** Medium. Strong gains on counterfactuals suggest effectiveness, yet checker fidelity unverified.
- **Overall aggregate accuracy (73.84%):** Low‑Medium. Results cannot be independently reproduced without source code/dataset.

## Next Checks
