# From Multi-Agent to Single-Agent: When Is Skill Distillation Beneficial?

## Quick Facts
- **arXiv ID:** 2604.01608
- **Source URL:** https://arxiv.org/abs/2604.01608
- **Reference count:** 29
- **Primary result:** Metric freedom (F) predicts when distilling multi-agent systems into single-agent skills is beneficial; the adaptive distillation framework matches or exceeds original MAS performance while reducing cost by up to 8× and latency by up to 15×.

## Executive Summary
This paper investigates the inconsistent outcomes of distilling multi-agent systems (MAS) into single-agent skills, which can yield improvements or degradation on the same task. It reveals that skill utility is determined by the evaluation metric's "freedom" (F), a measure of scoring landscape rigidity computed via a Mantel test correlating output diversity with score variance. Guided by F, a two-stage adaptive distillation framework selectively extracts tools and knowledge while discarding restrictive structures for "free" metrics (high F), and applies iterative refinement only for "rigid" metrics (F ≤ 0.6). Across four tasks and eleven datasets, F strongly predicts skill utility (ρ = -0.62, p < 0.05). The adaptive system reduces computational cost by up to 8× and latency by up to 15× while matching or exceeding original MAS performance, and identical agent trajectories show opposite skill lifts under rigid versus free metrics.

## Method Summary
The method begins by computing metric freedom (F) from existing raw-agent runs (n=10) using a Mantel test between output distance and score distance matrices. Based on F, Stage 1 adaptive distillation converts the MAS into a single-agent skill: for high F (free metrics), it preserves tools and knowledge but discards coordination structures and encodes knowledge as conditional references to avoid over-constraining; for low F (rigid metrics), it retains decomposition hints and prioritizes explicit knowledge. If F ≤ 0.6, Stage 2 activates a four-agent iterative loop (Explore, Main, Analyzer, Runner) to refine the skill until convergence, sufficiency, oscillation, or budget exhaustion (max 15 iterations). The final skill is validated and deployed, optionally with tool integrations.

## Key Results
- Metric freedom (F) strongly correlates with headroom-normalized skill lift (ρ = -0.62, p < 0.05), predicting when distillation is beneficial.
- The adaptive distillation framework matches or exceeds original MAS performance on all 11 datasets, reducing cost by up to 8× and latency by up to 15×.
- Identical agent trajectories exhibit opposite skill lifts under rigid versus free metrics, demonstrating F's causal role.

## Why This Works (Mechanism)

### Metric Freedom Governs Skill Utility
**Claim:** F causally determines whether distillation provides utility by quantifying the topological rigidity of the evaluation metric's scoring landscape.  
**Mechanism:** A Mantel test correlates output diversity (D_out) and score diversity (D_score). Low F (rigid metric) means small output changes cause large score changes (e.g., exact method selection), so structured guidance from a distilled skill is highly valuable. High F (free metric) means diverse outputs yield similar scores, so imposing structure restricts exploration and harms performance.  
**Core assumption:** The relationship between output variation and score variation is stable across raw-agent runs to predict skill utility.  
**Evidence anchors:** F computed via Mantel test (Section 3.1); correlation with lift (Section 4.2).  
**Break condition:** If the Mantel correlation is unstable or the scoring landscape changes with model scale, F loses predictive power.

### Selective Extraction Preserves Valuable Components
**Claim:** Adaptive distillation (Stage 1) selectively extracts MAS components—keeping tools and knowledge but discarding coordination structures based on F—to avoid over-constraining on free metrics and under-guidance on rigid ones.  
**Mechanism:** Tools are always kept as they extend capability without constraining reasoning paths. Knowledge is encoded as conditional references for high F to preserve exploration, while for low F it is retained as explicit hints. Coordination structures (pipelines, task decomposition) are discarded for high F but kept for low F.  
**Core assumption:** Tools provide orthogonal value regardless of F, while knowledge and structural hints have differential value depending on metric freedom.  
**Evidence anchors:** Table 2 conversion rules; ablation showing tools and knowledge are complementary (Section 4.4).  
**Break condition:** If a task requires rigid pipelines even on free metrics (e.g., safety-critical sequential checks), discarding coordination structures causes failure.

### Iterative Refinement Exploits Reliable Signals
**Claim:** The skill iterator (Stage 2) improves performance only on low-F metrics because score changes reliably signal skill improvements; on high-F metrics, changes are indistinguishable from noise, risking overfitting.  
**Mechanism:** The four-agent loop (Explore, Main, Analyzer, Runner) targets iterative refinement exclusively when F ≲ 0.6. The Analyzer diagnoses failure root causes and revises skill guidance/tools/thinking paths. Termination detects oscillation or plateau.  
**Core assumption:** On low-F metrics, performance changes correlate with genuine skill improvements rather than random variation.  
**Evidence anchors:** Stage 2 recommended for F ≲ 0.6 (Section 3.3); Figure 5 shows rapid gains on low-F tasks vs. marginal gains on high-F.  
**Break condition:** If the metric is noisy even at low F (e.g., human evaluation with high variance), iteration may chase spurious signals.

## Foundational Learning

### Mantel test for metric freedom
**Why needed:** F is computed as 1−ρ(D_out, D_score) using a Mantel test; misunderstanding leads to incorrect F estimation and misguidance of distillation.  
**Quick check:** Why use Spearman’s rank correlation instead of Pearson for the Mantel test?  
**Answer:** Because distance matrices represent ranks or ordinal relationships; Spearman’s ρ captures monotonic associations without assuming linearity, which is appropriate for evaluating how output dissimilarity relates to score dissimilarity.

### Prompt caching cost modeling
**Why needed:** Cost comparisons (Section 4.6) rely on cache-adjusted pricing; raw vs. cached token counts affect Pareto frontier interpretation and require correct modeling to validate claimed reductions.  
**Quick check:** Why do original MAS baselines receive no cache benefit while single-agent methods do?  
**Answer:** MAS agents use distinct prompts per agent, preventing reuse across calls, whereas single-agent skills reuse identical prompts (especially with tools), enabling cache hits and lower effective cost.

### Headroom-normalized lift
**Why needed:** Raw skill lift confounds baseline performance ceiling; lift_norm = lift/(1−base) isolates skill utility relative to achievable improvement.  
**Quick check:** How does lift_norm clarify cases where raw-agent performance is already near 100%?  
**Answer:** When base ≈ 100%, raw lift is bounded near zero even if a skill is perfect; lift_norm reveals that little utility remains because the headroom is tiny, correctly indicating limited benefit from distillation.

## Architecture Onboarding

**Component map:**  
metric_freedom_computer -> adaptive_distiller_stage1 -> skill_iterator_stage2 (optional) -> validation_suite

**Critical path:**  
1. Compute F from existing raw-agent runs (n=10, no new inference).  
2. If F > 0.65, use Stage 1 output directly (minimal skill). If F ≤ 0.6, activate Stage 2.  
3. Run Stage 2 until convergence/sufficiency/oscillation/budget (max 15 iter).  
4. Select best skill version across iterations for deployment.

**Design tradeoffs:**  
- Tools always kept: increases cost but never harms exploration.  
- Knowledge encoded as conditional references for high F to avoid over-constraining; retained as hints for low F.  
- Stage 2 compute-intensive; only justified when F signal is strong (≤0.6).

**Failure signatures:**  
- F near 0.5 with high variance: ambiguous regime; test both Stage 1 and Stage 2 on small validation set.  
- Stage 2 oscillation: Analyzer fixes cause break other cases; implement “no repeat root-cause” constraint.  
- High-F task with rigid skill: performance degrades relative to raw agent; check that no pipeline hints remain in SKILL.md.

**First 3 experiments:**  
1. Replicate F computation on a held-out dataset to verify Mantel test implementation (correlation with expected direction).  
2. Ablate tools vs. knowledge on a low-F metric (e.g., CE-MSA) to confirm complementary lift.  
3. Run Stage 2 on a low-F task and a high-F task; expect rapid convergence on low-F, plateau on high-F.

## Open Questions the Paper Calls Out
1. **Estimating F for novel tasks without existing runs:** How can F be estimated from task descriptions or small validation sets? Currently requires n=10 raw-agent runs, limiting a priori application. Future work: proxy metrics from metadata or few-shot validation.
2. **Cross-task skill transfer:** Do skills distilled from one task transfer to related tasks? How does the target task's F influence transfer? Paper evaluates only same-task distillation; transfer could amplify practical value.
3. **Impact of foundation model progress:** As models become more capable, do metrics become "freer" (higher F) because models internalize knowledge, reducing need for distillation? Requires measuring F across model generations.
4. **Generalization to more tasks and metrics:** Benefits shown on 4 tasks and 6 metrics; correlation (ρ=-0.62) based on n=13. Broader validation needed to confirm F–lift correlation and refine thresholds.

## Limitations
- Original MAS implementations (APEX-SQL, CAIS, etc.) are not open-sourced; reimplementation may diverge, affecting comparative results.
- Stage 2 convergence/oscillation thresholds (e.g., "3+ consecutive iterations") are unspecified, necessitating task-specific tuning.
- F requires n=10 raw runs; no clear method to estimate it a priori for entirely new tasks.
- Correlation ρ=-0.62 is moderate, leaving room for other predictors of skill utility.
- Findings may not generalize beyond the four studied tasks (Text-to-SQL, Causal Estimation, Causal Discovery, Feature Engineering).

## Confidence
- **F as predictor:** Medium (empirical support but moderate correlation and sensitivity to distance metric choice).
- **Adaptive distillation:** Medium (validated on limited tasks; hyperparameter details missing for Stage 2).
- **Tool universality & F‑dependent knowledge:** Medium (ablation evidence but not broadly tested across domains).
- **Stage 2 iterative refinement:** Low (compute‑intensive, thresholds unspecified, benefits only on low‑F metrics).

## Next Checks
1. **F sensitivity:** Recompute F across all datasets using alternative output distance functions (e.g., embedding similarity) to confirm consistent correlation with lift.
2. **Stage 2 robustness:** On a low-F task, vary convergence/oscillation thresholds; report performance variance to identify stable settings.
3. **External validity:** Apply the pipeline to a new domain (e.g., HotpotQA) using F derived from 10 raw runs; test whether skill lift aligns with F prediction.
