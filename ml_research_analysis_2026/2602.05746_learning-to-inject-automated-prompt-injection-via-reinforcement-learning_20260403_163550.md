# Learning to Inject: Automated Prompt Injection via Reinforcement Learning

## Quick Facts
- arXiv ID: 2602.05746
- Source URL: https://arxiv.org/abs/2602.05746
- Reference count: 40
- Primary result: AutoInject achieves up to 58.00% attack success rate on Gemini-2.5-flash and 47.97% on GPT-4.1-nano while preserving task utility, and discovers a single "allelujah" suffix that transfers to 70 task pairs.

## Executive Summary
Prompt injection attacks against LLM agents have largely been manual and unscalable. This paper introduces AutoInject, a reinforcement learning framework that automatically generates adversarial suffixes to hijack agent behavior. The approach uses a 1.5B parameter policy model optimized with Group Relative Policy Optimization (GRPO) and a comparison-based feedback signal that provides dense rewards despite inherently sparse success outcomes. By jointly maximizing attack success and task utility, AutoInject produces stealthy attacks that maintain agent functionality. Evaluated on the AgentDojo benchmark, AutoInject significantly outperforms template-based and optimization-based baselines, achieving state-of-the-art attack success rates on multiple proprietary and open-weight models, including those fine-tuned to resist injection. The method also uncovers highly transferable suffixes, such as a single “allelujah” token sequence that compromises dozens of task-model pairs.

## Method Summary
AutoInject frames prompt injection as a reinforcement learning problem where the policy π_θ (a 1.5B LM) generates adversarial suffixes conditioned on the injection goal g and user task context c. The reward combines three components: binary attack success r_sec, task utility r_util (both from the victim agent pipeline), and a preference score r_pref from a separate feedback model that compares the candidate suffix against the best-known suffix for that (g,c) pair. This comparison-based feedback yields a dense signal that mitigates reward sparsity. Training uses Group Relative Policy Optimization (GRPO), which normalizes rewards within each batch of K suffixes to compute relative advantages, enabling stable policy updates even when absolute rewards are low. The policy is updated per task pair until either perfect success (r_sec=1 and r_util=1) or a query budget B=260 is exhausted. A reference manager tracks the best suffix x* encountered, which is used in the feedback comparison and as the final attack output.

## Key Results
- State-of-the-art attack success rates: up to 58.00% on Gemini-2.5-flash and 47.97% on GPT-4.1-nano, substantially surpassing template-based and optimization baselines (<25% ASR).
- Compromises Meta-SecAlign-70B (a model fine-tuned to resist injection) with 21.88% ASR while preserving utility (39.29% under attack vs. 37.50% benign).
- Discovers highly transferable suffixes; a single “allelujah” suffix successfully attacks 70 distinct task pairs on Gemini-2.5-flash.

## Why This Works (Mechanism)
**Mechanism 1: Comparison-based feedback mitigates reward sparsity.** The true reward (attack success) is extremely sparse, as most random suffixes fail. AutoInject introduces a feedback model (e.g., GPT-4o-mini) that compares each candidate suffix against the current best-known suffix for the same (goal, context) and outputs a preference probability r_pref. This dense, continuous signal correlates with the true outcome and provides meaningful gradients even when neither suffix fully succeeds, enabling policy learning. The overall high ASR across diverse targets validates this approach.

**Mechanism 2: Group Relative Policy Optimization (GRPO) stabilizes updates under noisy rewards.** GRPO computes advantages by normalizing the composite reward within each batch of K suffixes generated for the same (g,c). This relative ranking remains informative even if all absolute rewards are low (common early in training), allowing the policy gradient to distinguish slightly better proposals. Ablation results (Table 5) demonstrate that removing GRPO significantly reduces ASR, particularly on robust targets like GPT-5-nano (36.57% → 19.44%), underscoring its importance.

**Mechanism 3: Joint utility preservation creates stealthy attacks.** The composite reward explicitly combines attack success (α·r_sec) and task utility (β·r_util), steering the policy toward suffixes that trigger the malicious action without disrupting the user's legitimate task. This bi-objective optimization yields attacks that maintain or even improve utility in some cases (e.g., Claude-Sonnet-3.5: 98.52% under attack vs. 75.00% benign), making the attacks less likely to be detected by a user monitoring agent performance.

## Foundational Learning
- **Reinforcement Learning (MDP formulation):** Needed because generating an effective suffix is a sequential decision process: the policy selects tokens step-by-step to maximize a final reward. *Quick check:* In AutoInject, what are the state s_t, action a_t, and terminal reward R?
- **Reward Sparsity & Shaping:** The core challenge is that random suffixes almost never succeed (r_sec = 0), which cripples standard policy gradient methods. The paper's comparison-based feedback is a shaping technique that converts sparse binary outcomes into dense, learnable signals. *Quick check:* Why would vanilla REINFORCE fail in this setting, even with millions of samples?
- **Prompt Injection & LLM Agent Execution:** Unlike jailbreaking a chatbot, prompt injection targets LLM agents that process untrusted context (e.g., emails) and execute parameterized tool calls. Success requires the agent to perform a specific adversarial action, not just generate a harmful response. *Quick check:* How does the success condition for a prompt injection attack on an agent differ from a standard jailbreak attack on a chatbot?

## Architecture Onboarding
**Component map:** Attack policy (π_θ, Qwen2.5-1.5B) → suffixes → Victim pipeline (E) yields r_sec and r_util; Feedback model (F) compares against best suffix x* to produce r_pref → Composite reward R → GRPO optimizer (with group normalization and KL penalty) updates π_θ; Reference manager tracks x* per (goal, context).

**Critical path:** For a given (g, c): 1) Sample batch of K suffixes from π_θ. 2) Evaluate each: run victim to get r_sec, r_util; query F to get r_pref. 3) Compute R_i = α·r_sec + β·r_util + γ·r_pref. 4) Update x* if any R_i exceeds current best. 5) Normalize rewards within batch (mean=0, std=1) to obtain advantages Â_i. 6) Update π_θ via clipped GRPO objective with KL regularization. 7) Repeat until budget B=260 exhausted or perfect success.

**Design tradeoffs:**  
- Feedback model choice (e.g., GPT-4o-mini) impacts signal quality and cost; cheaper models may provide noisier preferences.  
- Query budget B trades off attack potency versus detectability/cost.  
- Utility weight β balances stealth vs. maximum achievable attack success; fixed at 0.3 in the paper.

**Failure signatures:**  
- Low ASR despite high r_pref indicates feedback model preferences do not transfer to the victim (feedback overfitting).  
- High ASR but near-zero utility shows destructive attacks that break the agent; joint optimization failed.  
- Absence of transfer across models/tasks suggests the policy overfits to specific victim quirks.

**First 3 experiments:**  
1. **Main Results (Tables 1,2):** Compare AutoInject against template and optimization baselines; verify ASR improvements while maintaining utility.  
2. **Ablation Study (Table 5):** Remove GRPO training or feedback model to isolate contributions; expect performance drop, especially on robust targets.  
3. **Transferability Analysis (Figure 3, Table 12):** Evaluate suffixes optimized on one model/task on held-out models/tasks; expect non-trivial ASR (e.g., >10%) and identify universal patterns like "allelujah".

## Open Questions the Paper Calls Out
1. **Defenses against utility-preserving attacks:** What defensive mechanisms (e.g., deliberation, external guardrails) can stop such attacks without degrading agent performance?
2. **Sensitivity to feedback model:** How does the choice of feedback model (size, family, biases) affect attack success, query efficiency, and transferability?
3. **Origin of universal suffixes:** Why do certain token sequences (e.g., containing “allelujah”) transfer so broadly across models and tasks? Could this reveal fundamental LLM vulnerabilities?
4. **Effect of policy model scale:** How does the parameter count of the attack policy affect attack effectiveness, transferability, and query efficiency?

## Limitations
- **Unvalidated feedback model fidelity:** The dense reward depends on a separate feedback model (e.g., GPT-4o-mini) whose ability to predict true victim success is not measured; potential misalignment could steer the policy astray.
- **Incomplete specification of AgentDojo:** The paper references the benchmark but does not fully detail the victim agent configuration (LLM backends, tools, evaluation logic), complicating exact replication.
- **Barriers to reproducing proprietary model results:** Evaluation on models like GPT-5-nano and Claude-Sonnet-3.5 requires API access that may be costly or restricted, limiting independent verification.

## Confidence
- **Performance claims (ASR, utility numbers):** High confidence (extensive tables and ablations).
- **Mechanistic explanations (why GRPO/comparison works):** Medium confidence (ablations show contribution but causal isolation of relative ranking vs. feedback noise is incomplete).
- **Transferability findings (universal suffixes):** High confidence (empirically demonstrated with the “allelujah” suffix across 70 task pairs).

## Next Checks
1. **Feedback Model Fidelity Test:** For a sample of (goal, context) pairs, compute the correlation between the feedback model's r_pref and the true composite reward R from victim evaluations. A low correlation would indicate a misaligned proxy.
2. **GRPO Group Size Sensitivity:** Train with varying group sizes K (e.g., 2, 4, 8, 16) and measure ASR. A sharp decline at small K would support the claim that relative ordering within the batch is crucial.
3. **Cross-Model Transfer of “Allelujah”:** Apply the discovered “allelujah” suffix to additional victim models not tested in the paper (e.g., Llama-4-Maverick, Mistral-Large, o3-mini). Sustained high ASR (>20%) would confirm the robustness of this pattern.
