# SaFeR-ToolKit: Structured Reasoning via Virtual Tool Calling for Multimodal Safety

## Quick Facts
- **arXiv ID:** 2603.02635
- **Source URL:** https://arxiv.org/abs/2603.02635
- **Reference count:** 40
- **Primary result:** SaFeR-ToolKit improves multimodal safety, helpfulness, and reasoning rigor on Qwen2.5-VL by enforcing a structured tool-calling protocol, while preserving general capabilities.

## Executive Summary
Vision-language models (VLMs) often fail at safety not due to lack of knowledge but because safety decisions are made without explicit, auditable reasoning, leaving them vulnerable to jailbreaks or over-refusal. SaFeR-ToolKit addresses this by formalizing safety as a structured protocol: the model generates a trace of virtual tool calls across Perception, Reasoning, and Decision layers before answering, with transitions constrained by a topology graph. A three-stage curriculum (SFT → DPO → GRPO) trains a single policy to obey this format and select appropriate tools. On Qwen2.5-VL (3B/7B), SaFeR-ToolKit dramatically boosts Safety, Helpfulness, and Reasoning Rigor without degrading general multimodal performance.

## Method Summary
SaFeR-ToolKit introduces a safety protocol where a VLM outputs a trace of tool calls (e.g., visual analysis, intent reasoning, boundary checking) before its final answer. Tools are organized into three layers, and valid sequences are restricted by a transition graph. Training proceeds in three stages: (1) SFT teaches the trace format and basic tool usage; (2) DPO refines tool selection by contrasting high-quality traces against perturbed ones (omissions, semantic mismatches); (3) GRPO optimizes adaptive tool invocation via a composite reward that enforces format compliance, sufficient depth, and semantic safety, using group-relative advantages. The result is a model whose safety decisions are broken into checkable intermediate steps.

## Key Results
- **Safety:** 3B: 29.39 → 84.40; 7B: 53.21 → 86.34
- **Helpfulness:** 3B: 45.04 → 71.13; 7B: 52.92 → 80.79
- **Reasoning Rigor:** 3B: 4.98 → 78.87; 7B: 19.26 → 85.34
- **General capabilities** (MathVista, MMMU, etc.) remained stable (e.g., 3B: 58.67 → 59.21; 7B: 66.39 → 66.81).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Structured trace enforcement makes safety decisions interpretable and forces verifiable intermediate reasoning.
- **Mechanism:** A planner defines a constrained transition graph over virtual tools (Perception, Reasoning, Decision). The responder must output a trace where each step is a tool call with an observation, respecting allowed transitions; the trace conditions the final answer.
- **Core assumption:** Explicit, machine-readable steps enable supervision and auditing, preventing opaque heuristics that jailbreaks exploit.
- **Evidence anchors:** Abstract: "formalizing safety as a structured protocol... forcing checkable intermediate steps"; Sec 3.1–3.2 defines tools and transition constraints (Eq.3); neighbor work on RL for function calling provides indirect support.

### Mechanism 2
- **Claim:** The three-stage curriculum (SFT → DPO → GRPO) progressively refines tool usage beyond final-answer supervision.
- **Mechanism:** SFT teaches trace format and basic tool invocation; DPO learns to prefer high-quality traces over degraded ones; GRPO optimizes adaptive tool depth and selection via a composite reward with group-relative advantages.
- **Core assumption:** Intermediate reasoning steps require explicit supervision because answer-level feedback alone cannot ensure correct verification.
- **Evidence anchors:** Abstract mentions "three-stage curriculum... GRPO directly supervises tool usage"; Sec 3.4 details objectives and data; Table 1 shows cumulative gains.

### Mechanism 3
- **Claim:** The composite GRPO reward (format + depth + semantic) balances thorough reasoning with safety gating.
- **Mechanism:** R = 0.1·R_fmt (tag compliance) + 0.2·R_dep (≥3 diverse calls, anti-repetition) + 0.7·R_sem (reward model scores with safety thresholds); group-relative advantage upweights better rollouts.
- **Core assumption:** A weighted sum can incentivize compliance, sufficient depth, and semantic safety without over-penalizing helpfulness.
- **Evidence anchors:** Abstract: "GRPO optimizes adaptive tool invocation via composite reward"; Sec 3.4.3 defines components; Fig.3 ablation shows each component's contribution.

## Architecture Onboarding
- **Component map:** Planner -> Tool Library -> Topology Templates -> Responder; Training Pipeline: SFT -> DPO -> GRPO; Reward Model + Composite Calculator; Data Generation (deterministic planner); Perturbation Model.
- **Critical path:**  
  - *Inference:* Input -> Planner config -> System prompt -> Responder -> Trace + Answer.  
  - *Training:* Data generation -> SFT -> DPO -> GRPO -> final policy.
- **Design tradeoffs:**  
  - Tool count vs. complexity: more tools improve coverage but risk incoherent traces.  
  - Topology rigidity vs. flexibility: strict graphs ensure safety gating but may limit adaptation.  
  - Reward weighting: high semantic weight (0.7) prioritizes safety but may reduce helpfulness.  
  - KL penalty magnitude: too low loses reference behavior; too high stifles exploration.
- **Failure signatures:**  
  - Format violations: missing `<thinking>`/`<answer>` tags or malformed tool syntax.  
  - Tool misuse: irrelevant tool selection or semantic mismatch.  
  - Transition violations: tool sequence ignoring allowed successors.  
  - Safety failure: jailbreak (high helpfulness, low safety) or over-refusal (both low).  
  - Depth deficiency: traces with <3 unique tools or high repetition (ρ(z) > 0.5).  
  - Reward hacking: high R_fmt/R_dep with low R_sem; inspect reward components.
- **First 3 experiments:**  
  1. Format compliance sweep: after each training stage, measure correct tag/tool presence; expect low→high.  
  2. Tool layer analysis: count Perception/Reasoning/Decision invocations; DPO should increase Reasoning, GRPO should increase Decision.  
  3. Reward weight ablation: train GRPO with variations (remove depth or tool quality) and evaluate Safety/Helpfulness; expect drop (as in Fig.3).

## Open Questions the Paper Calls Out
1. **Generalization to other VLM architectures?** Basis: Experiments only on Qwen2.5-VL; claim of generalizability not empirically validated. Why unresolved: Different architectures may interact differently with tool protocol. Evidence needed: Replicate on LLaVA/InternVL families.
2. **Dependence on tool library size?** Basis: Ablation removes entire layers, not individual tools; minimal set unknown. Why unresolved: Unclear if all 60 tools are necessary or if many are redundant. Evidence needed: Systematic removal of individual tools/subcategories.
3. **Structure vs. compute?** Basis: GRPO depth reward encourages longer chains; gains may stem from increased test-time compute rather than explicit structure. Why unresolved: Not decoupled from simple longer CoT. Evidence needed: Compare to free-form CoT with matched token budget, evaluating auditability.
4. **Robustness to protocol attacks?** Basis: DPO perturbations are static; protocol itself is a new attack surface. Why unresolved: Adaptive attacks corrupting trace integrity (e.g., fabricated tool observations) are untested. Evidence needed: Red-team suite targeting tool-calling process.
5. **Optimal reward hyperparameters?** Basis: Fixed weights (0.1, 0.2, 0.7) and thresholds (τ_safe=0.6, τ_task=0.6) without sensitivity analysis. Why unresolved: May not transfer across datasets/scales. Evidence needed: Grid search over weights/thresholds to map Pareto frontier.

## Limitations
- Dataset and tool definitions not publicly released; reconstruction requires compute and proprietary models.
- Evaluation relies on proprietary reward/judge models (Qwen3-VL-32B, GPT-5-mini), risking scoring bias.
- Tool interface details partially unspecified; implementation variations could alter outcomes.

## Confidence
- **Safety/Helpfulness/Rigor improvements:** Medium–High (large consistent gains, but single judge limits certainty).
- **Preservation of general capabilities:** High (benchmark scores nearly unchanged).
- **Mechanistic explanations (structured protocol, curriculum, reward):** Medium (internal ablations support causality, but independent verification needed).
