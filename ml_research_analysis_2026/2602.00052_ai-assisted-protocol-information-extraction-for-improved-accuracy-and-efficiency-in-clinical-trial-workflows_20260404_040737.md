# AI-assisted Protocol Information Extraction For Improved Accuracy and Efficiency in Clinical Trial Workflows

## Quick Facts
- arXiv ID: 2602.00052
- Source URL: https://arxiv.org/abs/2602.00052
- Reference count: 40
- Primary result: AI-assisted extraction using a clinical-trial-specific RAG system achieved 87.8% accuracy compared to 62.6% for standalone LLMs; in a user study, AI-assisted tasks were completed 40% faster, were rated as less cognitively demanding, and were strongly preferred.

## Executive Summary
This paper introduces an AI system for extracting structured data from clinical trial protocols, addressing challenges such as long document length, scattered information, and complex tabular formatting. The system combines a Retrieval-Augmented Generation (RAG) process for text-based elements with a vision-based approach for Schedule of Events (SoE) tables. Evaluated on 23 publicly available protocols, the RAG system achieved 87.8% extraction accuracy versus 62.6% for standalone large language models. A controlled experiment with 13 clinical research coordinators showed that AI-assisted extraction was 40% faster, imposed lower cognitive load, and received strong user preference. The work demonstrates how tailored AI pipelines can streamline protocol data extraction, a critical yet time-consuming step in clinical trial activation.

## Method Summary
The method employs two parallel extraction pipelines. For general data elements (e.g., inclusion criteria, endpoints), a RAG system first chunks protocols into semantically coherent sections that preserve hierarchical headers, then indexes them with vector embeddings (Cohere v3). For each query (e.g., “primary endpoints”), the retriever fetches the most relevant chunks, which are supplied to a generation LLM (Claude Sonnet 4.5) along with element-specific prompts to produce structured JSON. For the SoE, a transformer-based table detector (Microsoft Table Transformer) identifies table regions on PDF pages; these regions are converted to images and processed by a multimodal LLM (Claude Opus 4.5) that interprets visual layout and spatial relationships. Evaluation uses a hybrid human-LLM adjudication process to create ground truth and an LLM-as-judge (gpt-4o) to score extraction accuracy. A user study compared manual and AI-assisted extraction tasks, measuring completion time, cognitive load (NASA-TLX), and preference.

## Key Results
- RAG extraction accuracy: 87.8% (weighted average) vs. 62.6% for standalone LLMs.
- In the user trial, AI-assisted tasks were completed 40% faster than manual extraction.
- Participants reported lower cognitive demand and strongly preferred the AI-assisted approach.

## Why This Works (Mechanism)
### Mechanism 1: RAG overcomes context limits and confusion
The clinical-trial-specific RAG process improves accuracy by retrieving only relevant document chunks for each data element query. Protocols are split into hierarchical chunks; for a query like “primary endpoints,” the retriever fetches the top-k most relevant chunks, which are then supplied to the generation LLM with element-specific instructions. This ensures the model operates on focused context, avoiding dilution or loss of scattered information that occurs when the entire document is fed to a standalone LLM. Evidence: The abstract and section 3.1 highlight that RAG’s ability to retrieve and synthesize content from multiple locations provides a significant advantage. Break condition: If retrieval fails to surface the correct chunks (due to poor chunking, ambiguous queries, or unusual formatting), the generator lacks necessary context, leading to low accuracy for that element.

### Mechanism 2: Vision-based extraction preserves table structure
Complex Schedule of Events tables vary widely in formatting and are poorly handled by text-based PDF extraction. The system uses a two-stage method: a transformer-based table detector identifies table regions on each page; these regions are converted to images and fed to a multimodal LLM with SoE-specific prompting. The multimodal model directly interprets spatial layout, merged cells, and multi-page spans from the visual representation, preserving cues lost in text-only representations. Evidence: The paper notes that the multimodal approach mostly preserved spatial layout while text-only representations were regularly inaccurate or lost. Break condition: Failures occur if the detector misses a table or includes false positives, or if the multimodal LLM misinterprets highly non-standard or extremely dense layouts.

### Mechanism 3: Hybrid annotation enables scalable high-quality ground truth
Creating a large, accurate ground truth for semi-structured extraction is prohibitively labor-intensive. The authors used a hybrid human-AI framework: three candidate annotations per data element (one human expert, two LLMs) were synthesized by an independent LLM (gpt-5) adjudicator, which produced a final annotation, justification, and confidence score. Low-confidence decisions and a random sample were validated by human experts. This combines LLM scalability with human oversight for quality control. Evidence: Human adjudication confirmed the LLM’s decision in 87% of low-confidence cases (N=35) and 100% of random samples (N=24). Break condition: Systematic biases in the adjudication LLM or poor calibration of confidence scores could lead to errors, especially for nuanced clinical interpretations not captured in prompts.

## Architecture Onboarding
Component map: PDF Ingest -> Text Extraction & Page Imaging -> (RAG Pipeline: Chunking -> Vector DB -> Retrieval -> Generation) AND (SoE Pipeline: Table Detection -> Multimodal LLM) -> JSON Output -> Evaluation (LLM Judge) -> Adjudication (LLM Adjudicator) -> Human Review (if low confidence)

Critical path:
- General elements: Protocol PDF -> Chunking -> Vector Indexing -> Element Query -> Retrieval -> Generation -> JSON.
- SoE: PDF Page -> Table Detection -> Image Crop -> Multimodal Inference -> JSON.

Design tradeoffs:
- Chunk size vs. context completeness: Smaller chunks increase retrieval precision but may lose surrounding context; larger chunks risk irrelevance. Solution: context-aware chunking with reunion.
- Specialization vs. scalability: Each data element has tailored RAG chains/prompts for accuracy but increases development overhead.
- Automation vs. auditability: RAG stores source chunk references for traceability, essential for compliance but adds complexity.

Failure signatures:
- Empty fields in JSON: Retriever failed to find relevant context or generator didn’t synthesize.
- Generic/boilerplate responses: Retrieved context too generic or prompt insufficiently specific.
- Inconsistent formatting/naming: Inadequate schema enforcement or prompt instructions.
- High “low-confidence” rates: Ambiguous, contradictory, or dense source text; model divergence.

First 3 experiments:
1. Isolate Retrieval Quality: For a fixed set of complex queries, inspect if top-3 retrieved chunks contain the answer, testing chunking and embedding effectiveness.
2. Measure Multimodal SoE Robustness: Process protocols with known complex SoE tables, compare against gold standard; apply image perturbations (rotation, blur) to stress-test robustness.
3. Prompt Sensitivity Sweep: For high-variability categories, run generator with prompt variations to quantify influence and identify a robust baseline.

## Open Questions the Paper Calls Out
1. Real-world performance: How does the AI-assisted extraction system perform in actual clinical site workflows compared to the simulated environment used in the study? The authors recommend future real-world pilot deployments.
2. Generalization to complex designs: To what extent can the RAG system generalize to adaptive trial designs and highly specialized therapeutic domains? The evaluation dataset excluded such complexities.
3. LLM-as-judge biases: Do biases in the LLM-based evaluation framework affect the reported performance differences between RAG and standalone LLMs? The paper acknowledges potential model biases and small validation samples.
4. Impact of latest RAG configuration: Does the improved accuracy of the best RAG configuration (Claude Sonnet 4.5, 87.8%) translate to greater operational benefits (time savings, user satisfaction) compared to the earlier configuration (gpt-4o mini, 69.6%) used in the user experiment? This was not tested.

## Limitations
- Exact RAG parameters (chunk size, top-k) and full prompt templates are undocumented, hindering faithful replication.
- Human validation samples for the hybrid ground truth are small (35 low-confidence, 24 random), limiting confidence in evaluation reliability.
- Potential systematic biases in the LLM-as-judge and gpt-5 adjudicator are not thoroughly examined, especially for semi-structured elements with multiple valid representations.

## Confidence
- Mechanism 1 (RAG accuracy): Medium
- Mechanism 2 (vision SoE): Medium
- Mechanism 3 (hybrid annotation): Medium

## Next Checks
1. Retrieval sanity audit: For 20 elements where RAG failed, manually inspect whether the true answer exists in the top-3 retrieved chunks to isolate chunking/retrieval vs. generation issues.
2. Vision robustness stress test: Process 10 complex SoE tables with controlled image perturbations (5° rotation, slight blur) to quantify performance degradation and validate break conditions.
