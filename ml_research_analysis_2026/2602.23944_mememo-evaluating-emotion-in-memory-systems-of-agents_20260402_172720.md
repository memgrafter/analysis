# MemEmo: Evaluating Emotion in Memory Systems of Agents

## Quick Facts
- **arXiv ID:** 2602.23944
- **Source URL:** https://arxiv.org/abs/2602.23944
- **Reference count:** 9
- **Primary result:** Memory systems for LLMs lack robust evaluation in processing emotional information; the introduced HLME benchmark shows no system achieves robust performance across all tasks.

## Executive Summary
This paper introduces the Human-Like Memory Emotion (HLME) benchmark to evaluate how well LLM-based memory systems handle emotional information. The benchmark comprises three tasks: emotional information extraction, emotional memory updating, and emotional question answering. Five mainstream memory systems (MemOS, MemoBase, mem0, Mirix, Letta) are tested on multi-turn dialogues. Results reveal that each system exhibits specific strengths and weaknesses, but none performs robustly across all tasks. The study highlights fundamental gaps in current architectures for comprehensive emotional memory processing and underscores the need for improved design.

## Method Summary
HLME is constructed through a four-stage pipeline: persona seeding from existing datasets, dynamic extension with emotion binding, extraction of memory points and key events, and generation of multi-turn dialogues along with five types of questions. Two dataset variants are produced: Medium (~100 turns) and Large (longer with noise). Each turn contains emotion annotations, including a quadruple (subject, object, cause, intensity). The memory systems are evaluated in a black‑box manner: they process dialogues turn‑by‑turn, and their extracted facts, memory updates, and QA answers are judged by GPT‑4o‑mini. Metrics include accuracy, intensity MAE, slot F1 for extraction; update accuracy, intensity delta MAE, memory stability score for updating; and QA accuracy with evidence grounding F1 for QA. Latency and retrieval performance (top‑k) are also measured.

## Key Results
- No system achieves robust performance across all three tasks.
- Mirix excels in emotional information extraction on medium contexts but shows modest QA performance.
- Letta leads in long‑context updating stability, while mem0 suffers near‑zero update accuracy.
- MemOS achieves superior retrieval grounding for QA, especially with larger top‑k.

## Why This Works (Mechanism)
- **Retrieval architecture design** (e.g., hierarchical caching vs. vector search) directly determines a system's ability to ground emotional QA answers in verifiable evidence. Hierarchical caching (MemOS) prioritizes frequently accessed "hot" emotional memories, reducing retrieval scope and hallucination, whereas flat vector search (mem0) or multi‑agent coordination (Mirix) retrieve irrelevant noise or suffer coordination overhead.
- **Memory update logic** (active overwrite vs. append‑only) is the primary determinant of emotional state tracking accuracy. Systems with introspection or conflict‑resolution (Letta, MemOS) can dynamically overwrite outdated emotional states, while append‑only storage (mem0) cannot revise prior entries, leading to near‑zero update accuracy in long dialogues.
- **Multi‑agent architectures** introduce a trade‑off: parallel processing improves extraction accuracy on medium contexts but scales poorly for QA due to inter‑agent communication overhead. Mirix’s agents specialize in extraction, boosting EIE performance, but fragmented memory representation hinders QA aggregation.

## Foundational Learning
1. **Emotional Quadruple (Sub, Obj, Cause, Int)**  
   *Why needed:* HLME’s EIE task requires extracting structured emotional attributes to enable precise memory updates and traceable QA. Without this granularity, systems cannot link emotions to specific entities or causes.  
   *Quick check:* For “I’m frustrated because my flight was canceled again,” identify Sub (user), Obj (flight), Cause (cancellation), Int (frustration). Missing “again” could affect temporal pattern and intensity.

2. **Emotional State Transition (Consistency Tracking)**  
   *Why needed:* EMU evaluates if systems detect discrete shifts (e.g., anxious → relieved) and update memory accordingly by comparing current input against prior state.  
   *Quick check:* Given two dialogue turns: first mentions job insecurity (anxiety), then a job offer (joy). What evidence triggers the transition? The memory Update function should reflect the change in emotional attributes.

3. **Evidence Grounding in QA**  
   *Why needed:* EQA’s F1_evidence metric penalizes answers unsupported by retrieved memories, testing whether reasoning is traceable to stored emotional facts.  
   *Quick check:* For “Why did the user feel relieved last month?” does the snippet “promotion with salary increase” sufficiently ground the answer? What about “user mentioned feeling better”?

## Architecture Onboarding
- **Component map:**  
  Memory Store → Retrieval Engine → Update Controller → Extraction Module → QA Reasoner  
- **Critical path (emotional QA):**  
  User input → Retrieval (get relevant emotional history) → Extraction (parse current emotion) → Update Controller (determine if state changed) → QA Reasoner (ground answer in updated memory).  
- **Design tradeoffs:**  
  - *Write vs. Read Efficiency:* Mirix optimizes write (fast extraction) but hurts read (slow QA aggregation). MemOS optimizes read (fast hierarchical retrieval) with moderate write cost.  
  - *Stability vs. Sensitivity:* Letta’s aggressive overwrite (high Acc_update) risks stability; MemoBase’s compression (low MSS) loses nuance.  
  - *Centralized vs. Distributed:* Monolithic designs (MemOS, Letta) offer better evidence coherence for QA; multi‑agent (Mirix) scales extraction but fragments memory for reasoning.  
- **Failure signatures:**  
  - Update accuracy near zero → Append‑only storage (mem0).  
  - High write latency on medium contexts → Streaming compression bottlenecks (MemoBase).  
  - QA evidence F1 drops when top‑k increases → Attention interference from irrelevant memories (Letta on Large).  
  - Extraction high but QA low → Fragmented memory representation (Mirix).  
- **First 3 experiments:**  
  1. **EIE on HLME‑Medium:** Measure extraction accuracy (Acc, F1_slot) to identify which architecture best captures emotional quadruples in short‑to‑mid dialogues.  
  2. **EMU on synthetic emotional transition sequence:** Feed a dialogue with a clear state change (e.g., “I was upset about X, but now Y happened”) and check if update decision accuracy (Acc_update) and intensity delta (MAE∆) reflect the shift.  
  3. **EQA with varying top‑k (10→50) on HLME‑Large:** Test if evidence grounding F1 improves with larger retrieval, or if the system suffers from noise (signaling weak retrieval ranking or memory organization).

## Open Questions the Paper Calls Out
- How can memory systems balance emotional perception sensitivity with memory stability?
- How do different LLM backbones affect emotional memory performance on HLME?
- How robust and generalizable is the HLME benchmark across diverse memory architectures?
- What additional tasks and metrics are needed to fully assess emotional memory (e.g., implicit emotions, multi‑emotion conflicts)?

## Limitations
- The HLME dataset is not publicly available; reconstructed versions may differ in distribution and difficulty.
- Mapping diverse memory representations to the standard emotion quadruple format introduces systematic errors.
- Evaluation relies on unspecified LLM backbones and judge prompts, potentially affecting reproducibility and ranking stability.

## Confidence
- Overall claim (no system robust across all tasks): **High**
- Mechanism 1 (retrieval architecture determines grounding): **Medium**
- Mechanism 2 (update logic drives tracking accuracy): **Medium**
- Mechanism 3 (multi‑agent trade‑off between extraction and QA): **Medium**
