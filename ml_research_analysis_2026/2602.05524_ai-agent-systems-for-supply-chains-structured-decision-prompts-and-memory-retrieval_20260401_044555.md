# AI Agent Systems for Supply Chains: Structured Decision Prompts and Memory Retrieval

## Quick Facts
- **arXiv ID:** 2602.05524  
- **Source URL:** https://arxiv.org/abs/2602.05524  
- **Reference count:** 40  
- **Primary result:** A fixed-ordering prompt enables LLM-MAS optimality only in constant-demand settings; a memory-augmented agent (AIM-RM) with reinforcement learning logs matches learning-based benchmark performance across diverse scenarios without their computational cost.

## Executive Summary
This study evaluates large language model (LLM)-based multi-agent systems (MASs) for inventory management in multi-echelon supply chains. A structured prompt combining stepwise process descriptions and a safety-stock strategy allows an LLM-MAS to achieve optimal ordering policies in a restricted constant-demand setting but fails under time-varying or heterogeneous demand. To address adaptability, the proposed AIM-RM agent retrieves historically optimal decisions from reinforcement learning logs via state similarity matching. Across five experimental scenarios (varying uniformity and demand patterns), AIM-RM initialized with RL logs consistently attains the lowest average relative optimality gap, matching the performance of IPPO and MAPPO without their computational overhead. The results also reveal that increasing LLM reasoning effort can degrade performance in complex prompts, likely due to overthinking.

## Method Summary
The authors implement an LLM-MAS where each supply chain tier is an LLM agent. Agents observe local state (inventory, backlog, pipeline orders) and select order quantities. A base decision prompt (`PDM`) is extended with optional components: a stepwise process description (`PSD`), a safety-stock strategy (`PSS`), and a memory-based prompt module (`PMU`) that injects retrieved `(state, action, reward)` tuples. The memory module (`AIM-RM`) stores expert RL trajectories and retrieves nearest-neighbor states via Euclidean distance. The environment is an OR-Gym multi-echelon inventory MDP with deterministic demand. Performance is measured by relative optimality gap (`Δ`) compared to a known optimal linear program solution. Ablation experiments compare prompt configurations (with/without `PSD`, `PSS`, memory) and reasoning effort settings across constant/increasing/decreasing demand and uniform/diverse parameter scenarios.

## Key Results
- A fixed prompt (`PSD` + `PSS`) yields optimal ordering in the constant-uniform demand scenario but fails in time-varying or heterogeneous settings.
- AIM-RM initialized with RL logs achieves the lowest average `Δ` across all five test scenarios, matching IPPO/MAPPO performance without their training costs.
- Higher reasoning effort improves performance in simple prompts but degrades it in complex prompts (e.g., AIM-RM with memory), indicating an overthinking effect.

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** A fixed-ordering prompt combining stepwise process descriptions and a safety-stock strategy enables optimal ordering in a constant-demand multi-echelon supply chain.  
**Mechanism:** The structured prompt (`PSD` + `PSS`) encodes the inventory management procedure and a deterministic order-up-to policy with safety stock. This grounds the LLM's reasoning in a mathematically sound heuristic for stable demand.  
**Core assumption:** The environment has stationary, predictable demand and uniform parameters across tiers, making a static policy sufficient.  
**Evidence anchors:**  
- [abstract] "...fixed-ordering prompt... enabled an LLM-MAS to achieve optimal ordering policies in a restricted constant-demand scenario..."  
- [section 4.2.1] "In the constant-uniform scenario... the combination of the step description and safety-stock strategy yields the optimal reward."  
**Break condition:** Introduction of time-varying demand or heterogeneous tier parameters breaks the policy's assumptions, leading to suboptimal performance.

### Mechanism 2
**Claim:** Retrieval and referencing of historically optimal decisions (from RL logs) via state similarity matching (`AIM-RM`) enables adaptability across diverse supply chain scenarios, matching RL performance without computational cost.  
**Mechanism:** The memory module stores `(state, action, reward)` tuples from expert RL trajectories. At decision time, the agent retrieves `K` nearest neighbor states (Euclidean distance) and injects the corresponding `(action, reward)` pairs into the prompt (`PMU`), allowing the LLM to imitate coordinated, near-optimal behavior.  
**Core assumption:** State similarity is a valid proxy for action optimality; past expert solutions generalize to new but similar states.  
**Evidence anchors:**  
- [abstract] "AIM-RM... retrieves and references historically optimal decisions... consistently achieved the lowest average relative optimality gap (Δ)... matching the performance of learning-based benchmarks (IPPO, MAPPO)."  
- [section 4.2.2–4.2.6] `AIM-RM(w/ RL log)` ranks first or near-first across all five scenarios (Tables 2 & 3).  
**Break condition:** If the state representation fails to capture critical dynamics or the similarity threshold is inappropriate, retrieval yields irrelevant cases, degrading performance to `AIM-RM(w/o RL log)` levels.

### Mechanism 3
**Claim:** Increasing LLM reasoning effort does not universally improve performance and can degrade it in complex prompts (e.g., with memory retrieval), likely due to overthinking.  
**Mechanism:** Higher reasoning effort (more intermediate tokens) can lead the model to generate spurious reasoning, over-interpret retrieved cases, or over-complicate a heuristic that should be applied mechanically.  
**Core assumption:** The task has an optimal "reasoning depth"; exceeding it adds noise rather than signal, especially when the prompt already contains a structured strategy or retrieved examples.  
**Evidence anchors:**  
- [abstract] "The results also indicate that higher reasoning effort... can degrade it in complex prompts, likely due to overthinking."  
- [section 4.2.7] "Increasing reasoning effort does not consistently improve performance... for models such as `InvAgent(w/ step and safety-stock)` and `AIM-RM(w/ RL log)`, greater reasoning effort leads to a decline in performance."  
**Break condition:** Simple prompts may still benefit from more reasoning; degradation is prompt-dependent.

## Foundational Learning
- **Multi-Echelon Inventory Management (Lead Times & Bullwhip)**  
  *Why needed:* The problem involves coordinating orders across tiers with delivery lags (`L_m`). Misjudging lead times causes stockouts or excess inventory. The "bullwhip effect" (amplified order variability upstream) is a core failure mode.  
  *Quick check:* If Tier 0 faces increasing demand and has a lead time of 2 periods, when must Tier 1 place orders to avoid backlog at Tier 0?

- **Markov Decision Process (MDP) & Decentralized Execution**  
  *Why needed:* Each agent's decision (`O_m,t`) is an action in an MDP where state `s_m,t` includes inventory, backlog, and pipeline orders. The CTDE RL benchmarks (IPPO, MAPPO) solve this MDP; understanding decentralized execution is key to why LLM-MAS needs memory for coordination.  
  *Quick check:* In a decentralized setting, why can't a single agent's optimal policy depend only on its local state, and how does stored RL experience provide implicit coordination?

- **Prompt Engineering & In-Context Learning**  
  *Why needed:* The LLM's behavior is entirely prompt-driven (`PDM`, `PSD`, `PSS`, `PMU`). The study shows prompt structure critically determines success/failure. "Overthinking" is also a prompt-complexity interaction.  
  *Quick check:* What is the functional difference between the "step description" (`PSD`) and the "safety stock strategy" (`PSS`) in enabling the LLM to compute the correct order quantity?

## Architecture Onboarding
**Component map:**  
Environment Simulator (OR-Gym multi-echelon inventory MDP) -> Agent per tier (Decision Module: LLM; Prompt Assembly: constructs `PDM` from base, `PSD`, `PSS`, `PMU`; Memory Module: vector database `M_m` storing `(state_vec, action, reward)`) -> User Proxy (orchestrates round execution: collects actions, submits to env, distributes states/rewards, triggers memory update)

**Critical path:** State observation → Memory retrieval (if enabled) → Prompt construction → LLM inference → Action submission → Environment transition → Memory update.

**Design tradeoffs:**  
- Similarity measure: Fixed Euclidean norm on raw state vector (simple, fast) vs. learned embedding (potentially more robust).  
- Memory initialization: Cold start (`w/o RL log`) vs. pre-seeded with expert RL logs (`w/ RL log`). Pre-seeding gives immediate adaptability but requires accessible RL data.  
- Reasoning effort: `medium` vs. `high` token budget. `high` can harm performance in complex prompts (overthinking); `medium` is safer for `AIM-RM`.

**Failure signatures:**  
- Constant demand failure: Agent does not use safety stock formula correctly; `InvAgent(w/ step desc)` alone fails in `Const-Uni` (gap 3.33%).  
- Time-varying demand failure: Orders lag behind trend, causing backlog surges and bullwhip; e.g., `InvAgent(w/ step desc)` in `Inc-Div`, gap 104.55%.  
- Overthinking collapse: `AIM-RM(w/ RL log)` with `high` reasoning in `Inc-Uni` degrades sharply (gap 74.09% → 390.45%); agents may ignore retrieved cases or invent flawed reasoning.

**First 3 experiments:**  
1. Baseline verification: Run `InvAgent(w/ step desc and SS strategy)` in `Const-Uni` with `medium` reasoning. Expect optimal gap ~0%.  
2. Stress test adaptability: Run `AIM-RM(w/o RL log)` in `Inc-Div`. Expect poor performance (gap >160%).  
3. Memory + Reasoning tradeoff: Run `AIM-RM(w/ RL log)` in `Inc-Uni` with `medium` and `high` reasoning. Expect `medium` to rank well (gap ~74%), `high` to degrade sharply (>390%).

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Does a fixed Euclidean distance threshold and a uniform similarity metric optimally capture state similarity for memory retrieval in inventory management, or do adaptive, context-aware similarity measures and thresholds yield better performance?
- **Basis in paper:** [explicit] The authors identify the fixed similarity measure (Euclidean norm) and threshold value (τ=2) as a primary limitation.
- **Why unresolved:** The current implementation uses a static approach without investigating alternative distance metrics or dynamic thresholding, which could be critical as state importance may vary across different inventory scenarios.
- **What evidence would resolve it:** Systematic ablation experiments comparing various similarity functions and threshold selection strategies across the full suite of test scenarios, measuring impact on the relative optimality gap (Δ).

### Open Question 2
- **Question:** Can integrating a self-reflection mechanism into AIM-RM's memory logs demonstrably improve adaptability and performance, and what is the optimal format and frequency for generating and retrieving such reflective insights?
- **Basis in paper:** [explicit] The authors propose integrating self-reflection from prior work as a future direction to enhance AIM-RM by adding reflective summaries to historical logs.
- **Why unresolved:** The paper does not implement or test this mechanism. It is unclear if the added computational cost and potential noise from reflections would outweigh benefits, nor what structure is most effective for retrieval.
- **What evidence would resolve it:** Implementing a reflection module (e.g., based on Reflexion) within the agent loop, storing generated reflections alongside (s, a, r) tuples, and conducting comparative experiments against the baseline AIM-RM to quantify performance changes and analyze the content/utility of retrieved reflections.

### Open Question 3
- **Question:** To what extent does the "overthinking" phenomenon degrade LLM-based MAS performance in complex inventory prompts, and is this effect consistent across different model architectures (e.g., non-OpenAI reasoning models) and prompt structures?
- **Basis in paper:** [explicit] The authors observe that higher reasoning effort degrades performance in complex prompts (like AIM-RM) and attribute this to overthinking. They note this needs investigation beyond OpenAI models.
- **Why unresolved:** The evidence is correlational and limited to o4-mini and GPT-4.1. The causal mechanism is not isolated—degradation could stem from prompt complexity interaction rather than reasoning depth alone. The effect on other state-of-the-art reasoning models and on differently structured prompts is unknown.
- **What evidence would resolve it:** Controlled experiments varying reasoning effort (e.g., token budgets) across multiple LLM families while holding prompt content constant, using specially designed probes to separate the effects of reasoning depth from parsing/instruction-following complexity. Analysis of intermediate reasoning chains could identify failure modes.

### Open Question 4
- **Question:** Can AIM-RM's memory retrieval mechanism be made robust to scenarios where the agent appears to ignore relevant retrieved cases, and is this failure due to prompt design, LLM interpretation, or the intrinsic limitations of a vector-similarity approach for this sequential decision problem?
- **Basis in paper:** [inferred] The paper acknowledges that AIM-RM "occasionally seems to place an order without considering the input similarity cases." This is noted as difficult to assess due to potential "concealed reasoning" in models.
- **Why unresolved:** The root cause is undiagnosed. It could be that the prompt instruction for using memory (`PMU`) is inadequate, that the LLM lacks the capability to integrate retrieved examples into its decision logic, or that the retrieved examples, while state-similar, are not action-optimal for the current context.
- **What evidence would resolve it:** 1) Detailed case studies analyzing failed episodes: inspecting the retrieved cases presented to the agent and analyzing the generated reasoning for mentions/use of them. 2) Prompt ablation/modification studies testing different instructions for utilizing memory. 3) Evaluating the quality of retrieved cases—e.g., is the action in the retrieved (s, a, r) pair actually optimal for *its* subsequent state, and does that action generalize?

### Open Question 5
- **Question:** Will the performance advantage of AIM-RM (initialized with RL logs) persist under *stochastic* demand patterns, and can the system adapt effectively when the optimal policy itself changes due to demand volatility, not just trend?
- **Basis in paper:** [explicit] The authors explicitly identify extending to stochastic demand scenarios as a key future direction, noting the current study uses deterministic demand due to LLM cost constraints.
- **Why unresolved:** Deterministic demand simplifies the learning and evaluation target. Stochastic demand introduces noise and requires policies robust to variance. The memory mechanism may fail if the current state's stochastic outcome diverges from any single logged trajectory. The paper does not test AIM-RM's robustness to demand randomness.
- **What evidence would resolve it:** Re-running all experiments with stochastic demand distributions (e.g., Poisson, Gaussian) using the same experimental framework, possibly leveraging local open-weight reasoning models to manage cost. Key metrics would be the stability of AIM-RM's advantage over baselines and its sensitivity to the variance in demand distributions.

## Limitations
- Mechanism 1 (fixed prompt optimality) is proven only for the restrictive `Const-Uni` scenario; generalization to other constant-parameter settings or mild trend/noise is untested.
- Mechanism 2 (AIM-RM adaptability) is tightly coupled to the availability and quality of pre-seeded RL logs; cold-start performance is poor, limiting practical deployment.
- Mechanism 3 (overthinking) evidence is correlational and limited to specific OpenAI models (o4-mini, GPT-4.1); causality and consistency across model architectures remain unresolved.

## Confidence
- **Mechanism 1 (Fixed prompt optimality in constant demand):** High  
- **Mechanism 2 (AIM-RM adaptability via RL log retrieval):** Medium  
- **Mechanism 3 (Reasoning effort & overthinking):** Low  

## Next Checks
1. Test `AIM-RM(w/ RL log)` on *stochastic demand* (e.g., Poisson, seasonal) to probe the similarity retrieval's robustness beyond deterministic trends.
2. Ablate the similarity function: replace Euclidean distance with a learned embedding (e.g., from a small encoder trained on RL state-action pairs) and compare performance in `Inc-Div`.
3. Conduct a fine-grained sweep of `reasoning_effort` (token budget) for `AIM-RM` across all scenarios, measuring variance in output stability and correlation with prompt components.
