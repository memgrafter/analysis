# Performance of Neural and Polynomial Operator Surrogates
## Quick Facts
- arXiv ID: 2604.00689
- Source URL: https://arxiv.org/abs/2604.00689
- Reference count: 40
- Primary result: Polynomial surrogates (RB‑SG, RB‑TT) achieve better data efficiency and lower evaluation cost for smooth inputs (s≥2); FNO converges fastest for rough inputs (s≤1); H1‑trained neural operator improves data efficiency over L2 for rough inputs when Jacobian data is cheap; no universally best method.

## Executive Summary
This paper benchmarks neural and polynomial operator surrogate methods for accelerating expensive PDE solvers. Two PDEs—linear diffusion and nonlinear hyperelasticity—are discretized on 64×64 finite element meshes. Parametric input fields with varying smoothness s ∈ {0.5, 1.0, 2.0, 3.0} are generated via Matérn eigenfunction expansions. Four surrogate families are compared: reduced‑basis neural operators (L2 and H1 losses), Fourier neural operator (FNO), reduced‑basis sparse‑grid (RB‑SG) interpolation, and reduced‑basis tensor‑train (RB‑TT) for the linear case. Performance is measured by Monte‑Carlo L2/H1 errors, training/setup time t_T, and evaluation time t_E. Results show polynomial methods dominate for smooth inputs (s≥2) with high data efficiency and fast evaluation; FNO excels for rough inputs (s≤1); H1 training improves neural data efficiency for rough inputs if Jacobian computation is cheap. The study underscores that surrogate choice must align with smoothness, accuracy, and cost constraints.

## Method Summary
A large dataset (N=10000) of input‑output pairs (x, y) is generated for each smoothness s. Principal component analysis (PCA) on this dataset yields orthonormal encoder and decoder bases (M‑ and S‑orthonormal) that reduce dimensionality to d_in and d_out. All surrogates (except FNO) operate on the low‑dimensional coefficient maps c_in ↦ c_out. RB‑NO uses fully‑connected networks with GELU activations; H1 training adds a Jacobian loss computed via linearized PDE solves. FNO processes raw grid values with spectral convolutional layers and varying channel/mode counts. RB‑SG constructs a barycentric interpolant on a sparse grid in PCA space, with multi‑index level ℓ chosen to match training size n. RB‑TT (linear diffusion only) builds a tensor‑train representation of the solution map via ALS‑cross approximation, with polynomial degrees per dimension set by a heuristic. For each method, a hyperparameter sweep (network sizes, FNO channels/modes, sparse‑grid levels, TT ranks) is performed. Evaluation on K=250 test samples yields errors ε_{L²µ} and ε_{H¹µ}; timings t_T (setup) and t_E (per‑sample) are recorded. Pareto frontiers are plotted in error vs. data, time, etc.

## Key Results
- Polynomial surrogates (RB‑SG, RB‑TT) achieve lower errors with fewer samples and cheaper evaluation for smooth inputs (s≥2); RB‑SG convergence rate matches theory.
- For rough inputs (s≤1), FNO converges fastest with increasing training data.
- H¹‑trained RB‑NO improves data efficiency over L²‑only and rivals polynomial methods on rough inputs when Jacobian data is inexpensive.
- No surrogate is universally optimal; choice must reflect smoothness, accuracy, and cost trade‑offs.

## Why This Works (Mechanism)
Polynomial methods (RB‑SG, RB‑TT) exploit smoothness via global basis functions; for s≥2 the input‑output map is analytic, yielding spectral convergence and cheap evaluation. FNO uses local Fourier kernels that adapt to both smooth and non‑smooth features, making it robust on rough data but incurring FFT‑related evaluation overhead. H¹ training enforces derivative consistency, which matters when gradients are poorly captured by L² loss; this improves data efficiency on rough inputs, but only if Jacobian generation is cheap enough to amortize. Thus, the inductive bias of each surrogate aligns differently with the underlying PDE’s smoothness, driving the observed performance differences.

## Foundational Learning
1. **Reduced Basis Method (RBM)** – Why needed: Compresses high‑dimensional FE solutions into a low‑dimensional subspace via PCA, enabling efficient surrogate training and evaluation. Quick check: From a snapshot matrix, compute orthonormal basis that maximizes captured variance; ensure mass‑matrix orthonormality.
2. **Neural Operators** – Why needed: Learn mappings between function spaces directly, independent of discretization resolution. Quick check: Contrast with a standard neural network that maps vectors; an operator network takes a function representation (e.g., coefficients) and outputs another function’s coefficients.
3. **Fourier Neural Operator (FNO)** – Why needed: Performs convolutions in Fourier space, providing resolution invariance and efficient FFT‑based implementation. Quick check: Outline the layer: input → Fourier transform → multiply by learned frequency filters → inverse FFT → non‑linearity.
4. **Sparse Grid Interpolation** – Why needed: Approximates high‑dimensional smooth functions with fewer samples than full tensor grids by exploiting mixed derivatives. Quick check: Construct a 2D sparse grid using Clenshaw–Curtis points; confirm node count grows polynomially with dimension.
5. **Tensor‑Train (TT) Decomposition** – Why needed: Represents high‑dimensional tensors with a chain of low‑rank cores, reducing storage from exponential to linear dimension dependence. Quick check: Convert a 3D tensor to TT format via successive SVDs; verify core ranks remain small.
6. **Smoothness Classes (Sobolev/Hölder)** – Why needed: Approximation rates of polynomial methods depend on input smoothness s. Quick check: State how interpolation error for a C^s function decays with polynomial degree.

## Architecture Onboarding
- **Component map**:  
  Input generation (eigenfunction expansion) → FE discretization (FEniCS) → PDE solve → Snapshots (x,y) → PCA (encoder/decoder) → Low‑dimensional coefficients (c_in, c_out) → Surrogate: {RB‑NO (MLP), FNO (spectral conv), RB‑SG (barycentric), RB‑TT (TT‑ALS)} → Predicted c_out → Decode to y_pred → Error metrics (L2, H1). H¹ training adds Jacobian branch (linearized PDE solves) to RB‑NO loss.

- **Critical path**:  
  1. Implement and validate PDE solvers on 64×64 Q1 mesh.  
  2. Generate large dataset (N≈10000) of (x,y) for each s.  
  3. Compute PCA bases from dataset.  
  4. For each surrogate and hyperparameter choice: select n samples, construct/train, evaluate on K=250 test cases, record errors and timings.  
  5. Aggregate results, compute Pareto frontiers, produce plots.

- **Design tradeoffs**:  
  • Polynomial vs neural: Polynomials (RB‑SG, RB‑TT) offer ultra‑fast evaluation (tensor ops) but may need many samples for rough inputs; neural operators require training time but generalize better from few data (FNO on rough).  
  • Smoothness sensitivity: Polynomials converge rapidly only for s≥2; FNO is robust across s but t_E grows with grid size.  
  • H¹ loss improves RB‑NO data efficiency at cost of expensive Jacobian generation; benefit depends on amortization.  
  • FNO bypasses PCA, so its grid representation may not align perfectly with H¹ norm used in evaluation.

- **Failure signatures**:  
  • Plateauing error despite increasing n → insufficient PCA basis or surrogate capacity.  
  • Training loss stuck or exploding → bad learning rate, architecture mismatch, data scaling.  
  • GPU memory overflow in FNO → reduce channels, modes, or batch size.  
  • Oscillations/high error in RB‑SG → incorrect point selection or multi‑index level error.  
  • ALS non‑convergence in RB‑TT → polynomial degrees too high or poor initial ranks; monitor residuals.  
  • Jacobian computation orders of magnitude slower than forward solves → undermines H¹ data efficiency claim.  
  • Discrepancy in reported H¹ error vs. finite‑difference estimate → verify weighting by λ_i^s and norm consistency.

- **First three experiments**:  
  1. Reproduce Figure 2 (RB‑SG convergence) for s=2 and s=3: vary n and confirm error decays at theoretical rate ∼ n^{-s/2}.  
  2. Reproduce Figure 4 (FNO vs RB‑SG) for s=0.5: train FNO with different channel/mode settings and show it outperforms RB‑SG with comparable n.  
  3. H¹ vs L² RB‑NO on s=0.5: train both variants with same n, compare test errors; verify H¹ variant benefits when Jacobian data is included.

## Limitations
- Hyperparameter specifications incomplete (RB‑NO LR schedule, FNO depth, RB‑SG univariate point type, RB‑TT polynomial degrees and ALS tolerance) hinder exact replication.
- RB‑TT handling of the nonlinear coefficient exp(x) is not clarified, raising doubts about its correct application to diffusion.
- Jacobian computation cost for H¹ training is omitted, so the claimed data‑efficiency advantage for rough inputs may not hold under full cost accounting.
- PCA basis quality depends on the unspecified dataset size N_large, potentially affecting surrogate accuracy.

## Confidence
- Polynomial surrogates better for smooth inputs (s≥2): **High**.
- FNO converges fastest for rough inputs (s≤1): **Medium**.
- H¹‑trained RB‑NO improves data efficiency over L² and competes with polynomials for rough inputs when Jacobian cheap: **Medium**.
- No universally best method; choice depends on smoothness, accuracy, and cost: **High**.
