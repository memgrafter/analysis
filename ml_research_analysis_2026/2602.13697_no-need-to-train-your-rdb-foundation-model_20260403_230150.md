# No Need to Train Your RDB Foundation Model
## Quick Facts
- arXiv ID: 2602.13697
- Source URL: https://arxiv.org/abs/2602.13697
- Reference count: 35
- Primary result: JUICE encoder with pre-trained single-table ICL models achieves state-of-the-art AUC on RelBench classification without training and matches KumoRFM's MAE on regression.

## Executive Summary
Predicting targets in multi-table relational databases requires compressing variable-sized neighborhoods into fixed-length samples for in-context learning (ICL). Existing dense encoders mix columns, conflating units and roles, which harms ICL performance when label information is absent. This paper introduces JUICE, a parameter-free encoder that compresses only vertically within high-dimensional columns (where entities share units), thereby preserving column identities. Implemented via scalable SQL primitives and paired with pre-trained single-table ICL models (e.g., TabPFN), JUICE achieves state-of-the-art AUC on RelBench classification and matches KumoRFM's MAE on regression without any training. Ablations confirm stability across base models and encoder hops, and theoretical and empirical results show that cross-column dense compression increases estimation error when uninformative features exist.

## Method Summary
Given a relational database {T, R} and a target table X, the RDBLearn pipeline first extracts an H-hop heterogeneous subgraph for each target row (respecting temporal constraints). The JUICE encoder then processes each column within this subgraph: for every meta-path (sequence of edge types) connecting relevant tables, it computes aggregations (sum, mean, std, etc.) over the meta-path neighborhood using SQL. Each resulting feature depends solely on one original column and one meta-path; all such features are concatenated into a fixed-length vector for the row. The training set consists of these vectors paired with labels, forming an ICL sample set D. Finally, D and the vector for a test row are fed to a frozen pre-trained single-table ICL model (e.g., TabPFN) to predict the target. No parameters are trained; all operations are parameter-free and rely on scalable SQL primitives.

## Key Results
- JUICE achieves state-of-the-art AUC on RelBench classification without any training.
- JUICE matches KumoRFM's MAE on RelBench regression without training.
- Ablations show stable performance across different base ICL models and numbers of hops.

## Why This Works (Mechanism)
### Vertical Compression Within Columns
JUICE compresses neighborhoods only vertically within high-dimensional RDB columns, never across columns. For each column within H hops of the target row and for each meta-path, it computes aggregations (e.g., sum, mean) over the meta-path neighborhood using SQL. This ensures each derived feature depends solely on one original column and one meta-path, preserving column identities and roles. The core assumption is that column relevance varies across tasks and cannot be determined by a fixed encoder without labels; vertical compression is safe because units are homogeneous within a column. Evidence: the abstract argues for column-constrained compression, Section 3.1 formalizes it, and the corpus contrasts with dense cross-column encoders like Griffin. Break conditions: columns with very low cardinality yield uninformative aggregations, and omitting key meta-paths loses relational signals.

### Parameter-Free 1D GNN via Reparameterization
The meta-path GNN used in JUICE can be reparameterized to have no trainable parameters without losing expressiveness, given positively homogeneous activation (e.g., ReLU) and aggregation (e.g., sum, mean) functions and positive internal weights. Proposition 3.2 shows that the update equation factors out all parameters; scale factors are absorbed by the decoder or feature normalization. This allows JUICE to be parameter-free while retaining the ability to propagate information along meta-paths. Core assumption: activation and aggregation are positively homogeneous, internal weights positive, node features are 1D (from column truncation). Evidence: Section 3.3 and Proposition 3.2; abstract states encoder expressiveness not compromised. Break conditions: non-homogeneous operations (e.g., max with negative inputs) or multi-dimensional features break the simplification; the positive weight assumption may restrict sign information.

### Column-Aligned Meta-Path Features for ICL Decoder Simplicity
By separately encoding each column with each meta-path, JUICE produces features aligned with the original schema. The encoder splits the subgraph into column-wise 1D subgraphs, applies the parameter-free meta-path GNN per meta-path, and concatenates the 1D outputs. The resulting feature matrix columns correspond to (column, meta-path) pairs, preserving interpretability and allowing the ICL decoder to select relevant features without disentangling mixed representations. Core assumption: the ICL decoder (e.g., TabPFN) can effectively perform feature selection on such column-aligned features; task-dependent relevance is unknown at encoding time. Evidence: Section 3.2 details the procedure, Section 3.4 emphasizes preserved column roles, and Appendix C's performance inversion on graph foundation models supports that column-aligned parameter-free features excel in ICL. Break conditions: if the number of (column, meta-path) pairs exceeds the ICL model's input capacity, or if meta-paths fail to capture key relational patterns, performance degrades.

## Foundational Learning
- **In-Context Learning (ICL):** Why needed: Enables prediction for new tasks without retraining by conditioning on labeled examples. Quick check: "How does a Transformer model use a context of labeled examples to make a prediction for a new instance without updating its weights?"
- **Relational Databases as Heterogeneous Graphs:** Why needed: Provides a unified representation to define neighborhoods and meta-paths for encoding. Quick check: "Given an RDB with tables 'Students' and 'Enrollments' linked by student_id, how would you construct a heterogeneous graph for predicting student outcomes?"
- **Parameter-Free Encoder:** Why needed: Avoids training on unseen RDBs, which is essential for ICL with foundation models. Quick check: "Why might a parameter-free encoder be preferable to a trainable one in an ICL setting for unseen RDBs?"

## Architecture Onboarding
- **Component map:** RDB {T, R} and target table X -> Neighborhood extraction (compute H-hop subgraph for each target row) -> JUICE encoding (SQL aggregations per column and meta-path) -> ICL sample formation (assemble training set of feature vectors and labels) -> Prediction (feed samples and test vector to pre-trained ICL model).
- **Critical path:** Step 3 (JUICE encoding) is most critical; errors here propagate to predictions.
- **Design tradeoffs:** 
  - Vertical-only compression preserves column identities and leverages ICL decoder attention for interactions, but may miss explicit cross-column signals.
  - SQL implementation ensures scalability via database engines but restricts custom operations; common aggregators suffice.
  - Exhaustive meta-path enumeration within H hops ensures coverage but increases feature dimensionality; concatenating aggregators per meta-path controls this.
- **Failure signatures:**
  - Low-cardinality columns produce uninformative vertical aggregations.
  - Temporal leakage if neighborhood extraction includes future data.
  - Feature dimension mismatch with ICL model's context length or feature assumptions.
- **First 3 experiments:**
  1. Replicate RelBench classification tasks with RDBLearn; expect SOTA AUC without training.
  2. Ablate hops (H=2,3) and base ICL models (TabPFNv2, v2.5, LimiX) on RelBench; expect stable performance.
  3. Validate performance inversion: compare JUICE (ICL) vs dense encoder (supervised) on dataset with uninformative features; expect JUICE to excel in ICL setting.

## Open Questions the Paper Calls Out
1. **Automatic weighting of aggregations for homophily/heterophily:** JUICE uses fixed aggregators; how to adapt without labels? Basis: Appendix D identifies this as open. Unresolved because lacking a mechanism to exploit network effects. Evidence needed: theoretical criteria linking aggregator effectiveness to graph metrics; empirical gains on synthetic RDBs with varying homophily when using learned weighting.
2. **Formal sample complexity of JUICE for ICL:** Does it achieve minimax optimal O(n^{-2/κ}) rate? Basis: paper proves optimal for no encoder and degradation for dense encoders, but JUICE's rate unanalyzed. Unresolved due to feature expansion from meta-paths/aggregations. Evidence needed: probability bound showing error decays as n^{-2/κ} irrespective of meta-path count, or counterexample.
3. **Scalability limits of SQL implementation for massive RDBs:** What are practical limits for enterprise-scale schemas with thousands of tables? Basis: Section 5 claims scalability but only tests moderate benchmarks. Unresolved because join/aggregation cost may superlinear. Evidence needed: latency vs. schema size benchmarks; comparison with property graph databases.
4. **Sensitivity to evolving ICL decoder architectures:** JUICE assumes decoders handle column-aligned features and prune irrelevant ones; if future decoders require dense embeddings, compatibility fails. Basis: Stability shown across three decoders, but future models may differ. Unresolved because decoder evolution uncertain. Evidence needed: testing with diverse ICL models and analysis of necessary decoder properties.

## Limitations
- Base ICL models (e.g., TabPFN) are pre-trained on synthetic single-table data, which may not match real RDB distributions.
- Vertical compression assumes column homogeneity; low-cardinality or mixed-unit columns can yield uninformative features.
- The parameter-free guarantee relies on restrictive assumptions (positive homogeneous activations, positive weights) that may not hold for common variants.

## Confidence
- JUICE achieves SOTA AUC on RelBench classification without training: Medium
- Parameter-free encoder retains expressiveness for ICL: Medium
- Vertical compression preserves column identities and benefits ICL decoders: High
- JUICE outperforms dense encoders in ICL when uninformative features exist: High
