# TIDE: Token-Informed Depth Execution for Per-Token Early Exit in LLM Inference

## Quick Facts
- **ArXiv ID:** 2603.21365
- **Source URL:** https://arxiv.org/abs/2603.21365
- **Reference count:** 6
- **Primary result:** Reduces prefill latency by 7.2% and increases single-batch throughput by 6.6% on DeepSeek R1 Distill 8B without accuracy loss, with 98–99% of decoding tokens exiting early.

## Executive Summary
TIDE is a post-training system that enables per-token early exit in large language models without retraining the base model. It attaches tiny learned routers at periodic checkpoint layers to detect when a token's hidden state has converged to its final-layer representation. During inference, the full forward pass is run to preserve KV cache integrity, but the logits are computed from the earliest converged layer's hidden state. On 8B-class models, TIDE achieves nearly all tokens exiting early and reduces prefill latency while increasing throughput; calibration is fast (<3 minutes) and produces a small (~4 MB) router checkpoint.

## Method Summary
TIDE operates in two phases: calibration and inference. During calibration, a frozen model processes a small corpus (2,000 WikiText samples) with `output_hidden_states=True`. For each checkpoint layer (every *c*‑th layer, default *c*=4), a two‑layer MLP router is trained via binary cross‑entropy to predict whether a token's hidden state has converged, using cosine similarity > τ = 0.98 to the final layer as the label. The trained routers (~4 MB total) are saved. At inference, the model runs normally to collect all hidden states. The routers evaluate each checkpoint layer’s hidden state *post‑hoc*; the earliest layer where all tokens' router scores exceed an exit threshold θ is selected, and its normalized hidden state is used for the LM head. Fused CUDA kernels combine RMSNorm, router evaluation, and output redirection to minimize overhead.

## Key Results
- On DeepSeek R1 Distill 8B, 100% of prefill tokens exit early (5% at layer 11, rest at layer 31), reducing prefill latency by 7.2% and increasing single‑batch throughput by 6.6%.
- During decoding on a 95‑token math problem, 98–99% of tokens exit early while output correctness is maintained.
- Qwen3 8B shows 8.1% throughput gain at batch size 8.
- Calibration takes under 3 minutes; router checkpoint is ~4 MB.

## Why This Works (Mechanism)
### Mechanism 1: Convergence‑based per‑token exit
- **Claim:** TIDE enables per‑token early exit by using lightweight, post‑training routers to detect hidden state convergence without retraining.
- **Mechanism:** A one‑time calibration computes cosine similarity between checkpoint and final hidden states on WikiText; routers (2‑layer MLPs) are trained to predict convergence (label: cosine > τ). At inference, all layers run fully (preserving KV cache), routers evaluate each checkpoint’s hidden state post‑hoc, and the earliest converged layer’s state is used for logits.
- **Evidence:** [abstract, section 3.1] describes calibration, router structure, and post‑hoc selection; corpus neighbors (AdaPonderLM, SPAR‑K) acknowledge token‑level exit but TIDE’s no‑retraining approach is distinct.
- **Break condition:** Domain shift in calibration data may cause inaccurate convergence predictions and incorrect outputs when exiting too early.

### Mechanism 2: Universal Model Adapter
- **Claim:** TIDE instruments any HuggingFace causal LM via automatic structure probing, avoiding per‑architecture code.
- **Mechanism:** The adapter checks 17 known attribute paths (e.g., “largest ModuleList” for layers, “sibling‑of‑layers” for final norm) to locate layers, normalization, LM head, and embedding. Hidden dimension is taken from `model.config.hidden_size`; users can register custom adapters.
- **Evidence:** [abstract, section 3.2] lists covered architectures (LLaMA, Mistral, Qwen, GPT‑2, etc.) and fallback heuristics.
- **Break condition:** Novel or heavily customized architectures not matching the 17 paths or heuristics will fail initialization; future `transformers` library changes could break probing.

### Mechanism 3: Fused CUDA kernels
- **Claim:** Fused kernels reduce per‑token router evaluation and output selection overhead, making the post‑hoc approach wall‑clock efficient despite running all layers.
- **Mechanism:** Four kernels: (1) Fused LayerNorm + Route (down‑proj, SiLU, up‑proj, sigmoid); (2) Batch Compact (separates continuing vs. exiting tokens); (3) Exit Scatter; (4) Exit Projection. Templates cover common hidden dimensions (2048, 4096, 8192) and dtypes (fp32, fp16, bf16).
- **Evidence:** [section 3.4, 4] details kernel specialization and fusion; [section 5.2] shows latency reductions (5.5–7.2%) and throughput gains (up to +8.1%).
- **Break condition:** Unsupported hidden dimensions trigger a slower generic fallback; changing router bottleneck size may cause recompilation overhead.

## Foundational Learning
- **Concept: Hidden state convergence**  
  *Why needed:* TIDE’s exit decision relies on the signal that a token’s representation stabilizes before the final layer.  
  *Quick check:* If token A’s layer‑10 hidden state has cosine similarity 0.99 to its final layer, but token B’s is 0.85, TIDE’s router likely classifies token A as converged at layer 10 and token B as not, because the score exceeds θ sooner for token A.
- **Concept: Post‑hoc vs. in‑situ execution**  
  *Why needed:* TIDE runs all layers first, then selects output. This differs from modifying forward to skip layers; the trade‑off is cache integrity vs. potential compute savings.  
  *Quick check:* Post‑hoc execution ensures KV cache consistency across all layers but pays full compute cost; true in‑situ skipping saves FLOPs but risks cache discontinuities.
- **Concept: Token‑level adaptive computation**  
  *Why needed:* TIDE routes each token independently; “difficult” tokens (e.g., reasoning steps) may need deeper layers than function words.  
  *Quick check:* In a math problem, a function word like “the” likely exits earlier than a heavy‑reasoning token because its representation converges quickly; the router learns this from calibration data.

## Architecture Onboarding
- **Component map:** UniversalAdapter → Router (per checkpoint) → Calibrator → Inference engine → CUDA kernels
- **Critical path:**  
  Calibration: (a) Load frozen model; (b) Probe structure; (c) Run calibration data with `output_hidden_states=True`; (d) For each checkpoint layer, train router on `(hidden_state, cosine_sim_label)`; (e) Save routers.  
  Inference per step: (a) Full forward with hidden states; (b) Fused router kernel evaluates each checkpoint; (c) Find earliest layer where all tokens’ scores > θ; (d) Apply LMHead to that layer’s normalized hidden state.
- **Design tradeoffs:**  
  - *Post‑hoc vs. true skip:* Post‑hoc preserves KV cache and library compatibility but no FLOP savings from skipped layers; true skip risks cache misalignment.  
  - *Threshold τ (calibration) & θ (inference):* τ = 0.98 is conservative, clustering exits at penultimate layer; lower τ/θ may increase early exits but harm accuracy.  
  - *Checkpoint interval c:* Smaller c increases router memory/calibration cost but allows finer‑grained exit choices.
- **Failure signatures:**  
  - **No early exit:** All tokens score below θ at all checkpoints → fallback to final layer. Inspect router training labels and adjust θ.  
  - **Degraded quality:** Exiting too early with low scores → incorrect outputs. Check τ calibration; consider per‑layer θ tuning.  
  - **Throughput drop at large batch:** `output_hidden_states` overhead scales superlinearly. Profile kernel launch; consider hybrid (collect hidden states only at checkpoints).  
  - **Adapter failure:** Model not in known list and probing fallbacks fail → `RuntimeError`. Verify model’s `config` and layer structure.
- **First 3 experiments:**  
  1. **Sanity check:** Calibrate on 10 WikiText samples; inspect router scores on a single prompt—scores should increase with layer; stopwords likely score > θ earlier than content words.  
  2. **Exit rate validation:** With θ = 0.85, run prefill on 100 WikiText tokens; expect near‑100% exit rate, distribution across checkpoints if τ = 0.98 used (likely all at last checkpoint). Compare to Figure 2.  
  3. **Kernel equivalence test:** Run router evaluation in pure PyTorch vs. fused CUDA on random hidden states (batch=32, d=4096); ensure max absolute difference < 1e‑5.

## Open Questions the Paper Calls Out
- **Open Question 1:** How to implement true physical layer skipping while preserving KV cache integrity? *Basis:* Paper states true skip is future work due to cache discontinuity risks. *Why unresolved:* Post‑hoc approach runs all layers; true skip requires novel cache management.  
- **Open Question 2:** Can adaptive thresholding increase early exits without degrading quality? *Basis:* Paper uses fixed τ = 0.98 (conservative), clustering exits late. *Why unresolved:* No exploration of layer‑specific or input‑dependent thresholds.  
- **Open Question 3:** How does TIDE generalize to larger models (70B+) and multi‑GPU setups? *Basis:* Paper only evaluates 8B models on single GPU; states exit rates should increase with depth but untested on multi‑GPU.  
- **Open Question 4:** What optimizations mitigate `output_hidden_states` overhead that causes negative throughput scaling at large batches? *Basis:* Paper notes overhead becomes bottleneck; selective collection at checkpoints proposed but unimplemented.

## Limitations
- Calibration data limited to WikiText; may not capture domain‑specific convergence patterns.
- Exit threshold θ requires per‑model tuning; no automatic calibration across tasks.
- Quality evaluation sparse (only one math problem); lacking systematic benchmark results.
- UniversalAdapter heuristics may fail on non‑standard model implementations.

## Confidence
- **Token convergence detection:** Medium. Empirical evidence relies on cosine similarity heuristic; not proven universal.
- **Universal adapter compatibility:** Medium. Tested on 9 common architectures; unknown for future/custom models.
- **Post‑hoc execution efficiency:** Medium. Gains offset by full forward pass; limited by kernel template coverage.
- **Throughput improvements (prefill +6.6%, decoding +8.1%):** Medium. Only on two 8B models at small batches; scaling uncertain.
