# Agentic Unlearning: When LLM Agent Meets Machine Unlearning

## Quick Facts
- **arXiv ID:** 2602.17692
- **Source URL:** https://arxiv.org/abs/2602.17692
- **Reference Count:** 12
- **Primary Result:** Synchronized Backflow Unlearning (SBU) reduces privacy leakage (MIA Score) by 24.8% versus parameter-only methods while maintaining over 90% accuracy on retained medical QA data, and scales effectively to forget sets of 1000 items.

## Executive Summary
This paper introduces *agentic unlearning*, a framework to remove specified information from both the parameters and the persistent memory of LLM-based agents. The core challenge is *parameter-memory backflow*, where retrieval from memory reintroduces information that was supposedly forgotten in the model parameters. The proposed solution, Synchronized Backflow Unlearning (SBU), coordinates two pathways: a memory pathway that uses a dependency graph to prune records and derived artifacts, and a parameter pathway that uses stochastic reference alignment (KL divergence to a random model) to unlearn without catastrophic utility loss. The pathways are synchronized—memory unlearning executes first—to prevent recontamination. Evaluated on medical QA benchmarks, SBU achieves significant privacy improvements (higher MIA Score) compared to parameter-only baselines while preserving high accuracy on retained data, and demonstrates scalability to larger forget sets.

## Method Summary
SBU addresses agentic unlearning through a synchronized dual-update protocol. The **memory pathway** constructs a dependency graph over the agent's multi-layer memory (episodic, semantic, reflections, KG nodes). Upon a forget request, it adds the target to a persistent blocklist and traverses the graph to identify and delete exclusively-dependent artifacts via reference counting. The **parameter pathway** minimizes a weighted loss: cross-entropy on retained data to preserve utility, and a KL divergence term that aligns the model's outputs on the forget set with a frozen, randomly initialized reference model, driving predictions toward a high-entropy prior. Crucially, memory unlearning runs *before* parameter updates in each iteration, ensuring the parameter optimization operates on a retrieval context already sanitized of the forget set. The process repeats for several epochs, with the memory index rebuilt offline after sufficient blocklist updates.

## Key Results
- SBU reduces traces of targeted information as measured by Membership Inference Attack (MIA) Score, improving privacy by 24.8% compared to parameter-only unlearning baselines.
- The framework maintains over 90% accuracy on retained medical QA data, demonstrating limited utility degradation.
- SBU scales effectively to larger forget sets (e.g., 1000 items), achieving a MIA Score of 0.996, indicating robust cross-pathway forgetting.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Dependency-aware memory pruning prevents incomplete deletion that would leave derived artifacts exposing forgotten content.
- **Mechanism:** Memories and artifacts (episodic, summaries, reflections, KG nodes) are modeled as a dependency graph `G=(V,E)` with reference counters per node. For a forget request `D_F`: (1) add `D_F` to a persistent blocklist `B`; (2) traverse `G` from `D_F` to find dependent artifacts `Dep(D_F)`; (3) decrement reference counts for shared dependencies; (4) remove only nodes whose references drop to zero, preserving artifacts still supported by retained data.
- **Core assumption:** All residual exposure to forgotten information is bounded by the completeness of the dependency graph; any artifact reachable from `D_F` must be invalidated or have its reference count decremented.
- **Evidence anchors:** Abstract mentions "dependency graph-based pruning to delete records and derived artifacts"; Section 3.2 states the goal to "prune artifacts supported exclusively by forgotten data while preserving those with remaining valid sources".
- **Break condition:** Missing or incorrect edges in the dependency graph (e.g., implicit derivations not captured) leave residual artifacts that can reconstruct the forgotten content.

### Mechanism 2
- **Claim:** Stochastic reference alignment (KL-to-random) suppresses parametric knowledge without catastrophic over-unlearning.
- **Mechanism:** Instead of gradient ascent on `D_F`, the parameter pathway minimizes `L_KL = KL(p_θ ∥ p_θ0)`, where `p_θ0` is a frozen, randomly initialized model. This drives outputs on `D_F` toward a high-entropy prior rather than a uniform distribution, avoiding instability. The total loss `L_weight = L_DR_CE + λ_F T² L_DF_KL` retains utility on retained data `D_R`.
- **Core assumption:** Aligning the student model's distribution on the forget set with that of a random reference model effectively scrubs learned patterns more stably than forcing uniform entropy or maximizing loss.
- **Evidence anchors:** Abstract cites "stochastic reference alignment to guide model outputs toward a high-entropy prior"; Section 3.2 describes the "KL-to-random scheme... aligning to a structured high-entropy prior from a reference model".
- **Break condition:** If the random reference model shares initialization with the student or if temperature `T` is mis-specified, the alignment may fail to induce sufficient forgetting or cause distribution collapse.

### Mechanism 3
- **Claim:** Synchronized execution order (memory first, then parameters) prevents cross-pathway backflow recontamination.
- **Mechanism:** For each forget set `D_F`, the protocol: (1) executes memory unlearning first, immediately blocking `D_F` and pruning derived artifacts; (2) then runs parameter unlearning on the now-sanitized retrieval context. This ensures parameter updates do not re-encode `D_F` from retrieved memories.
- **Core assumption:** Backflow is a sequential process; breaking the loop requires that at no point can retrieval supply `D_F` during parameter updates.
- **Evidence anchors:** Abstract mentions "pathways are integrated via a synchronized dual-update protocol"; Section 3.2 states "memory pathway first... then parameter pathway... ensures parameter optimization operates on a clean retrieval context".
- **Break condition:** Asynchronous or batched updates where parameter optimization occurs before memory pruning completes would allow backflow.

## Foundational Learning
- **Concept:** Machine unlearning (e.g., gradient ascent, retraining, NPO)
  - *Why needed here:* SBU's parameter pathway builds on these but modifies them for dual-pathway coordination. Understanding their failure modes (catastrophic forgetting, incomplete scrubbing) explains why a new approach is needed.
  - *Quick check question:* Why does gradient ascent on the forget set often harm retain-set utility in LLMs?

- **Concept:** Retrieval-Augmented Generation (RAG) and agent memory loops
  - *Why needed here:* SBU targets agents where retrieval feeds generation, which writes new memories. Understanding this loop is essential to see why parameter-only unlearning fails (backflow).
  - *Quick check question:* In a memory-augmented agent, how can a fact deleted from memory still reappear in outputs?

- **Concept:** Dependency graphs and reference counting for data structures
  - *Why needed here:* The memory pathway's correctness relies on graph traversal and reference counts to prune only exclusively-dependent artifacts. This is a core data-structure invariant.
  - *Quick check question:* If a knowledge graph node is shared by two memories, one forgotten and one retained, what should happen to that node during unlearning?

## Architecture Onboarding
- **Component map:**
  Memory Store -> Dependency Graph G -> Blocklist B -> Parameter Pathway (Student f_θ, Reference f_θ0) -> Synchronizer -> Audit Log
  FAISS Index rebuilds triggered when |B| > τ

- **Critical path:**
  1. Receive forget request `D_F`.
  2. **Memory phase:** `B ← B ∪ D_F`; traverse `G` from `D_F` to compute `Dep(D_F)`; decrement node reference counts; remove zero-reference nodes; delete `D_F` vectors.
  3. **Parameter phase:** For `T_max` epochs, sample mixed batches from `D_R` and `D_F`; compute `L_CE` (retain) and `L_KL` (forget) with reference `f_θ0`; update `θ`.
  4. If `|B| > τ`, rebuild FAISS index offline.
  5. Log all operations to Audit Log.

- **Design tradeoffs:**
  - *Memory completeness vs. performance:* Full graph traversal is costly; trade off via incremental updates and threshold-based index rebuilds.
  - *Entropy vs. utility:* High `λ_F` or `T` increases forgetting but risks over-unlearning; tuning required per dataset.
  - *Dependency precision vs. safety:* Overly aggressive pruning (deleting shared artifacts) harms utility; conservative reference counting preserves utility but risks residual backflow if graph is incomplete.

- **Failure signatures:**
  - *Backflow persists:* MIA score remains high; check if memory unlearning sequence is violated or graph missing edges.
  - *Utility collapse:* Retain/test accuracy drops >5%; likely `λ_F` too high or `T` mis-set.
  - *Memory leaks:* Retrieval hit rate on `D_F` >0% post-unlearning; blocklist enforcement or graph pruning failed.
  - *Stale index:* FAISS not rebuilt after many blocklist updates; retrieval returns blocked items.

- **First 3 experiments:**
  1. **Ablation (w/o Memory):** Disable memory pathway, run parameter-only. Expect high MIA score despite good forget accuracy, confirming backflow.
  2. **Scalability test:** Increase `|D_F|` from 100→1000. Measure MIA score, runtime, memory usage. Expect linear-ish growth but robust privacy (MIA ~0.99+).
  3. **Agent loop simulation:** Store Q&A pairs, query, delete one, then probe with related questions. Track retrieval hit rates on forget vs. retain set across turns. Expect forget hits →0%, retain stable.

## Open Questions the Paper Calls Out
- **Question 1:** How can agentic unlearning be extended to multi-agent systems where memories and knowledge are shared across agents, potentially creating complex cross-agent dependency graphs that current dependency tracking cannot fully capture?
  - *Basis:* The conclusion states: "A limitation of our current approach is that dependency tracking may not fully capture cross-agent information flow in shared knowledge graphs. Future work will explore unlearning protocols specifically tailored for multi-agent collaborative environments."
  - *Why unresolved:* SBU assumes a single-agent memory architecture with a centralized dependency graph. In multi-agent settings, memories may be distributed, shared, or co-owned, leading to intertwined dependency chains that could circumvent unlearning.
  - *Resolving evidence:* A multi-agent unlearning protocol that traces and invalidates derived artifacts across agent boundaries, possibly using cryptographic provenance or distributed graph traversal, with experiments showing effective forgetting without breaking shared useful knowledge.

- **Question 2:** To what extent does the synchronization order (memory unlearning before parameter unlearning) impact the effectiveness of preventing backflow, and could alternative synchronization strategies (e.g., alternating updates, concurrent optimization) improve utility-forgetting trade-offs?
  - *Basis:* The paper describes a sequential protocol: "we execute both pathways sequentially: (1) block and remove target data from retrieval, then (2) update model parameters." This design is presented as necessary but not compared against alternatives.
  - *Why unresolved:* No ablation of synchronization order or exploration of other coordination mechanisms is provided. Alternative strategies might yield better utility or faster convergence while still avoiding backflow.
  - *Resolving evidence:* Controlled experiments varying sequence and concurrency of memory and parameter updates, measuring MIA scores and retained accuracy across forget set sizes and data distributions to identify optimal policies.

- **Question 3:** How does the performance of SBU scale with increasingly complex memory structures (e.g., deeper dependency graphs, higher branching factors) and larger forget sets beyond 1000 items, and what are the computational bottlenecks?
  - *Basis:* The paper demonstrates scalability up to 1000 forget items but notes dependency graph traversal costs: "O(|Vvis|+|Evis|) graph traversal cost." It does not analyze worst-case scenarios with highly interconnected memories.
  - *Why unresolved:* Real-world agents may have memories with many interdependent artifacts (e.g., summaries referencing multiple dialogues, knowledge graphs with cycles). Current evaluation uses relatively simple medical QA data; effectiveness in complex cases is unclear.
  - *Resolving evidence:* Stress testing with synthetic memory graphs of varying complexity, measuring time/memory overhead and unlearning efficacy (MIA score) as graph density and forget set size increase, to characterize practical limits and potential optimizations.

- **Question 4:** Can the hyperparameter sensitivity of the parameter unlearning pathway (λ_F and temperature T) be theoretically guided or automated to maintain utility across diverse domains and model scales without manual tuning?
  - *Basis:* The ablation study shows a narrow effective range for λ_F and T, and the paper states: "Our analysis reveals that entropy fallback is critical... The forgetting coefficient λ_F controls forgetting-utility trade-off." No method for automatic tuning is provided.
  - *Why unresolved:* Relying on grid search for each deployment scenario is impractical. The optimal trade-off likely depends on dataset characteristics, model architecture, and forget set size. A theoretical framework or adaptive algorithm could make SBU more robust.
  - *Resolving evidence:* Deriving a theoretical relationship between λ_F, T, and expected utility loss based on model capacity or data statistics, or designing an adaptive scheme that adjusts these parameters during unlearning based on validation metrics.

## Limitations
- Dependency graph construction and reference counting are underspecified; incomplete graphs risk residual backflow artifacts.
- Parameter pathway exhibits hyperparameter sensitivity; optimal λ_F and T values require tuning per dataset and may not generalize.
- The framework assumes a single-agent memory architecture; multi-agent or shared knowledge environments introduce untested cross-agent dependency challenges.

## Confidence
- **Overall efficacy (privacy-utility):** High. SBU demonstrates 24.8% MIA improvement and >90% retain accuracy on medical QA, scaling to 1000 forget items.
- **Dependency graph memory unlearning:** Low. Graph construction and reference counting details are underspecified; incomplete graphs could leave residual backflow.
- **Stochastic reference alignment (parameter pathway):** Medium. KL-to-random loss preserves utility but hyperparameter sensitivity and lack of comparisons to other unlearning methods limit robustness.
- **Synchronization order:** Medium. Necessity of memory-first sequencing is inferred; direct tests of reversal/concurrency are missing.

## Next Checks
1. **Graph coverage audit:** Manually build a gold-standard dependency graph for a small dataset. Measure automated graph's edge precision/recall. After unlearning, perform exhaustive retrieval queries for any artifact reachable from forget set; expect zero hits.
2. **Objective ablation:** Replace KL-to-random with gradient ascent, maximum entropy, and influence unlearning. Sweep λ_F to compare MIA and retain accuracy across forget sizes; assess stability.
3. **Order sensitivity experiment:** Run memory and parameter phases in reverse order and in parallel. Measure MIA and retrieval contamination; expect significant degradation if synchronization is essential.
