# †DAGGER: Distractor-Aware Graph Generation for Executable Reasoning in Math Problems

## Quick Facts
- **arXiv ID:** 2601.06853  
- **Source URL:** https://arxiv.org/abs/2601.06853  
- **Reference count:** 40  
- **Primary result:** DAGGER matches reasoning model accuracy on the distractor-augmented DISTRACTMATH-BN benchmark while using 89% fewer tokens, and its output token count strongly correlates with computational complexity (R²=0.600).

## Executive Summary
Chain-of-Thought (CoT) prompting is vulnerable to semantically coherent but computationally irrelevant information (distractors) in mathematical word problems, especially in low‑resource languages like Bangla. DAGGER addresses this by reformulating problem‑solving as the generation of an executable computational graph with explicit distractor node annotations, separating relevant computation from noise. Evaluated on DISTRACTMATH‑BN, DAGGER achieves weighted accuracy comparable to state‑of‑the‑art reasoning models while reducing token consumption by 89%. Its robustness emerges without any distractor‑augmented training data, and the token count of its outputs scales predictably with problem complexity, unlike free‑form reasoning.

## Method Summary
The authors construct DISTRACTMATH‑BN, a Bangla math benchmark (3,685 problems) by augmenting MGSM and MSVAMP with three distractor types (RED, OAD, NEED). For training, they use 3K samples from SOMADHAN and numina‑math‑cot‑bn, each paired with a computational graph annotation generated by GPT‑4.1. Graphs are filtered to ensure executable correctness. A two‑stage training procedure is applied to Gemma‑3 (4B/12B). First, supervised fine‑tuning (SFT) with RS‑LoRA (rank 64, α 128) teaches graph format and distractor tagging. Second, Group Relative Policy Optimization (GRPO) refines the model using a reward that combines valid JSON format, successful graph execution, and answer correctness. During inference, the model directly outputs a structured graph; an executor runs the graph to produce the final answer.

## Key Results
- Standard CoT models lose up to 41 percentage points in accuracy when distractors are present; specialized reasoning models lose 14–20 points but consume 5× more tokens.  
- DAGGER attains weighted accuracy on DISTRACTMATH‑BN comparable to reasoning models while using 89% fewer tokens.  
- Output token count for DAGGER correlates strongly with computational complexity (R²=0.600), in contrast to free‑form reasoning (R²=0.015).

## Why This Works (Mechanism)
DAGGER’s explicit computational graph structure forces the model to produce stepwise operations that can be deterministically executed. By treating distractor identification as a separate node attribute, irrelevant information is visually and computationally isolated, preventing it from influencing the calculation. The two‑stage training aligns the model with high‑quality graph annotations first, then uses reinforcement learning to directly optimize for graph executability and answer correctness. This objective‑driven approach naturally yields robustness to distractors without requiring explicit distractor examples during training, and the graph representation remains compact, explaining the dramatic token reduction.

## Architecture Onboarding
**Component map**  
Raw Bangla problem → Graph Generator (Gemma‑3 with RS‑LoRA) → Computational Graph (nodes with operations & distractor flags) → Graph Executor (deterministic Algorithm A.7) → Final Answer.  
Training pipeline: Raw problems → GPT‑4.1 annotation → Filtered graphs → SFT → GRPO → Final generator.  

**Critical path**  
Inference: the problem is fed once to the generator, the resulting graph is executed in a single pass to produce the answer. Training: the loop of generating multiple graphs per prompt, scoring them via the reward function, and updating the policy via GRPO.  

**Design tradeoffs**  
- Graph expressiveness vs. generation difficulty: richer node types improve correctness but complicate learning.  
- Distractor annotation cost vs. model performance: relying on a teacher model (GPT‑4.1) is cheap but may propagate errors.  
- Token efficiency vs. exhaustive reasoning: compact graphs save tokens but must still capture necessary steps.  
- GRPO hyperparameters (group size, clipping ϵ) affect stability and final accuracy.  

**Failure signatures**  
1. Very low distractor annotation rate (model rarely marks nodes as distractors).  
2. Degenerate graphs (e.g., single constant node) that satisfy format and execution but yield wrong answers.  
3. High token counts despite graph structure, indicating failure to prune irrelevant computation.  
4. Low execution rate (graphs that cannot be parsed or run).  

**First experiments**  
1. Reproduce baseline CoT vulnerability: Evaluate a strong CoT model on the original vs. distractor‑augmented Bangla problems; confirm accuracy drop.  
2. Measure SFT‑only performance: Train only the supervised stage; evaluate graph validity, execution rate, and answer accuracy to gauge GRPO’s incremental benefit.  
3. Token‑complexity correlation: For DAGGER outputs, count tokens and graph nodes; compute R² between token count and node count, comparing to free‑form CoT traces.

## Limitations
- The exact distractor insertion logic and coherence checks in building DISTRACTMATH‑BN are undocumented, making full benchmark reconstruction uncertain.  
- GRPO implementation details (group size, KL regularization, exact “group‑relative” comparison) are not specified, potentially affecting training dynamics and reproducibility.  
- Distractor annotations are model‑generated without human validation; the paper does not measure precision/recall of distractor tagging, leaving a gap in the robustness claim.

## Confidence
- Robustness emerges without explicit distractor‑augmented training: **Medium**  
- 89% token reduction vs. reasoning models: **High**  
- Token count correlates strongly with computational complexity (R²=0.600): **High**

## Next Checks
