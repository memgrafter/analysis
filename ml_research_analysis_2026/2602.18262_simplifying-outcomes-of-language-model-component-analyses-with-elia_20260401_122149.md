# Simplifying Outcomes of Language Model Component Analyses with ELIA

## Quick Facts
- **arXiv ID:** 2602.18262
- **Source URL:** https://arxiv.org/abs/2602.18262
- **Reference count:** 18
- **Primary result:** ELIA makes mechanistic interpretability outputs accessible to non-specialists via an interactive web app with AI-generated natural language explanations, achieving high comprehension (0.95–1.00) and strong user preference for interactivity.

## Executive Summary
ELIA addresses the accessibility gap in mechanistic interpretability by providing an interactive web application that automatically explains complex analysis results (attribution heatmaps, function vector spaces, circuit graphs) through natural language generated by a vision-language model. A user study with 18 participants across novice, intermediate, and expert levels demonstrated consistently high comprehension scores, with no significant dependence on prior LLM experience. The system incorporates a faithfulness verification pipeline to ensure explanations accurately reflect underlying model mechanics, yielding high agreement rates. Users strongly preferred interactive visualizations over static ones, highlighting the value of explorable interfaces for understanding model internals.

## Method Summary
ELIA integrates three core mechanistic interpretability analyses—Attribution Analysis, Function Vector Analysis, and Circuit Tracing—using OLMo-2-1124-7B as the subject model and Qwen2.5-VL-72B as the explainer vision-language model. The pipeline: a user submits a prompt, the subject model performs a forward pass, the selected analysis module computes results and generates an interactive visualization (e.g., heatmap, 3D PCA plot, circuit graph). The visualization image and a structured textual summary are fed to the VLM, which produces a natural language explanation (NLE). A faithfulness verifier programmatically checks quantitative claims against ground-truth data and uses constrained VLM calls for semantic claims, then displays verification status. The frontend, built with Streamlit and Plotly, presents the interactive visualization alongside the NLE and verification badge.

## Key Results
- Comprehension scores were near-perfect across all expertise levels (Novices: 0.95, Intermediates: 0.98, Experts: 1.00), with no significant correlation to prior LLM experience (ρ=0.30, p=0.23).
- Automated faithfulness verification achieved high agreement rates (86.8%–100%) for all explanation types.
- Interactive visualizations were strongly preferred over static ones; Function Vectors and Circuit Trace pages received significantly better UX ratings than Attribution Analysis (p=0.006).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** A vision-language model (VLM) can accurately translate complex mechanistic interpretability visualizations into natural language explanations (NLEs) that are comprehensible to non-specialists.
- **Mechanism:** The system feeds the VLM (Qwen2.5-VL-72B) a multimodal prompt containing the visualization (e.g., a heatmap or circuit graph) and a structured textual summary of key data points. The VLM is instructed to synthesize these inputs into a narrative that explains the salient patterns. This leverages the VLM's ability to jointly reason over visual and textual information.
- **Core assumption:** The VLM can correctly interpret the visualization's semantics and the associated numerical data to produce factually faithful explanations.
- **Evidence anchors:**
  - [abstract] Directly states the core methodology: "using a vision-language model to automatically generate natural language explanations (NLEs) for the complex visualizations."
  - [section 3.1] Describes the prompt structure: "a multi-modal prompt... combines the heatmap image with a rule-based textual summary... to generate a comprehensive, structured explanation."
  - [corpus] Evidence is weak; neighboring papers focus on different interpretability or visualization challenges, not VLM-based explanation generation for specific MI visualizations.
- **Break condition:** The VLM generates explanations containing claims that are systematically contradicted by the underlying data during faithfulness verification (e.g., misreporting which token had the highest attribution score).

### Mechanism 2
- **Claim:** Interactive, explorable visualizations are essential for user comprehension of complex model analysis results, significantly outperforming static representations.
- **Mechanism:** The interface (built with Plotly and Streamlit) allows users to hover over heatmap cells, rotate 3D PCA plots, and click on graph nodes. This interactivity enables users to form their own causal hypotheses and test them against the data, reducing cognitive load by letting them control information density.
- **Core assumption:** Active exploration leads to deeper mental model construction than passive viewing of pre-selected insights.
- **Evidence anchors:**
  - [abstract] Highlights a key finding: "users strongly preferred interactive visualizations over static ones."
  - [section 6.1] Provides quantitative UX evidence: Function Vectors and Circuit Trace pages (highly interactive) received "significantly more positive UX ratings" than the more static Attribution Analysis page (p=0.006).
  - [corpus] Evidence is weak; related works (e.g., LIT, BertViz) implement interactivity but ELIA's user study specifically compares interactive vs. static outcomes.
- **Break condition:** If user testing shows no significant difference in comprehension scores or UX ratings between interactive and static versions of the same analysis.

### Mechanism 3
- **Claim:** Automated faithfulness verification is a necessary safeguard that maintains user trust in AI-generated explanations by ensuring they accurately reflect the underlying model mechanics.
- **Mechanism:** A deterministic verification pipeline programmatically checks each factual claim in the NLE against ground-truth data (e.g., recalculated similarity scores, stored activation values). For semantic claims, the same VLM is used as a fact-checker but is constrained by hard-coded rules and exact synonym mappings to prevent self-affirmation.
- **Core assumption:** Ground-truth data from the analysis pipeline exists and is accessible for systematic claim checking.
- **Evidence anchors:**
  - [section 3.2] Details the multi-step verification: "a verification module programmatically checks each claim against the ground-truth data... For quantitative claims, this is a direct data comparison."
  - [section 4] Reports high verification agreement rates (86.8%–100%) across all explanation types, indicating the pipeline's effectiveness.
  - [corpus] Evidence is weak; adjacent work (e.g., FActScore) provides inspiration but ELIA's pipeline is tailored to MI visualizations.
- **Break condition:** Verification scores drop significantly below the reported ~90% range for multiple explanation types, indicating the verifier or the explanation model is failing to maintain fidelity.

## Foundational Learning
- **Concept:** Mechanistic Interpretability (MI)
  - **Why needed here:** ELIA is an application *of* MI techniques. Users must understand that the goal is to reverse-engineer model computations (e.g., finding "induction heads" or "function vectors"), not just correlate inputs/outputs.
  - **Quick check question:** What is the key difference between an attribution method (like Integrated Gradients) and an intervention-based method (like activation patching)?

- **Concept:** Attribution Analysis
  - **Why needed here:** This is one of the three core analyses ELIA simplifies. It assigns importance scores to input tokens for a given output.
  - **Quick check question:** If the token "France" has a high integrated gradients attribution score for the output "Paris", what does that imply about the model's reasoning?

- **Concept:** Function Vectors
  - **Why needed here:** This represents a higher-level, semantic analysis ELIA provides. Users need to grasp that a single vector in activation space can steer the model toward a specific task type (e.g., "country capitals").
  - **Quick check question:** How is a "function vector" for a task category (e.g., summarization) typically computed from model activations?

## Architecture Onboarding
- **Component map:**
  1.  Frontend: Streamlit app hosting interactive pages for Attribution, Function Vectors, and Circuit Tracing. Uses Plotly for dynamic plots.
  2.  Subject Model Backend: PyTorch/Transformers wrapper around OLMo-2-1124-7B. Generates outputs, computes attributions (via `inseq`), extracts activations for function vectors, and runs forward passes for circuit tracing.
  3.  Explanation Engine: API calls to Qwen2.5-VL-72B. Takes visualization images + structured data summaries, generates NLEs.
  4.  Faithfulness Verifier: Deterministic module that re-queries ground-truth analysis data and uses constrained VLM calls for semantic checks. Presents verification status to the user.
  5.  Pre-computed Assets: Faiss index of Dolma dataset (for Influence Tracer), pre-computed function vector space, trained Cross-Layer Transcoder (CLT) and its feature labels.

- **Critical path:** User submits prompt -> Subject model runs forward pass -> Analysis module (attribution/vector/circuit) computes results & visualization -> Visualization + data summary sent to VLM -> VLM returns NLE -> Verifier checks claims against analysis data -> Frontend displays visualization + NLE + verification badge.

- **Design tradeoffs:**
  - **VLM for Gen/Verification vs. Circularity:** Using the same powerful VLM (Qwen2.5-VL) for both explanation generation and fact-checking risks collusion. Mitigated by making the verifier deterministic (temp=0) and relying on programmatic checks for quantitative claims. Tradeoff: simplicity and consistency vs. theoretical risk of shared biases.
  - **Pre-computation vs. Flexibility:** Function vectors and CLT features are pre-computed offline for speed. Tradeoff: instantaneous UI response vs. inability to analyze novel tasks/categories on the fly without retraining.
  - **Narrative Specificity vs. Generalization:** Prompts to the VLM are highly tailored to each visualization type (e.g., specific instructions for PCA plots vs. circuit graphs). Tradeoff: higher explanation quality for known analyses vs. brittleness to new visualization formats.

- **Failure signatures:**
  - **Low Verification Rate:** If the faithfulness checker reports <80% verified claims for a given analysis type, the explanation pipeline is likely producing hallucinations or the data summary is mis-specified.
  - **Poor UX on Complex Visuals:** Consistently low "Visual Clarity" scores for the main circuit graph page, indicating the visualization is too dense even with an NLE.
  - **High Correlation Between Expertise & Score:** If the user study finds a strong positive correlation (ρ > 0.7) between prior LLM experience and comprehension, the interactive design + NLEs are failing to bridge the accessibility gap.

- **First 3 experiments:**
  1.  **Replicate Faithfulness Benchmarks:** Run the predefined verification suite (Table 1) on a new set of 20 random prompts for each analysis page. Confirm verification rates remain >85%. This validates the pipeline's stability.
  2.  **A/B Test Interactive vs. Static:** For the Attribution page, create a static image-only version. Randomly assign new users to interactive (current) vs. static. Measure comprehension (quiz scores) and time-on-task. Hypothesis: interactive group shows higher comprehension with similar or less time.
  3.  **Probe VLM Prompt Sensitivity:** Systematically vary the "structured textual summary" fed to the VLM (e.g., remove key data points, add noise). Measure change in NLE faithfulness and human-rated clarity. This identifies the minimal, most effective prompt structure.

## Open Questions the Paper Calls Out
- How well does ELIA generalize to other languages, LLM architectures, and explainer models? The current implementation is limited to English/German, OLMo-2, and Qwen2.5-VL.
- Which richer intervention tools (e.g., causal scrubbing, counterfactual editing) should be integrated to enhance user-centric interpretability without overwhelming non-experts?
- What are the long-term effects of using ELIA in professional settings on practitioners’ interpretability skills and workflows?
- To what extent do AI-generated explanations and interactive visualizations independently and synergistically contribute to user comprehension and preference? The study evaluated ELIA as a whole without isolating these components.

## Limitations
- Exact composition of the 120-category function vector dataset and the specific Dolma subset used for CLT training are unreported, hindering exact replication.
- User study sample size (n=18) and unclear recruitment criteria (beyond “undergraduate CS students”) limit the generalizability of the high comprehension scores.
- Potential circularity exists in using the same VLM (Qwen2.5-VL) for both explanation generation and semantic verification, despite constrained prompts.

## Confidence
- User comprehension scores and interactive preference statistical significance: **High**.
- Faithfulness verification pipeline robustness against self-affirmation: **Medium**.
- Claims about broad applicability to any MI technique or model architecture: **Low**.

## Next Checks
1. Generalizability Test: Re-run the user study with a different subject model (e.g., Llama-3-8B) and explainer VLM (e.g., GPT-4o) to confirm comprehension scores hold across architectures.
2. Circularity Ablation: Replace the VLM-based semantic verifier with a rule-based exact-match system for a subset of claims and measure the divergence in “verified” status to quantify circularity risk.
3. Dataset Fidelity Audit: For a random sample of the unreported function vector categories, manually inspect the top-activating prompts to verify they align with the claimed “function type,” assessing the integrity of the pre-computed space.
