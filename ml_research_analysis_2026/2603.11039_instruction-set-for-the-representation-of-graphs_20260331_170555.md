# Instruction set for the representation of graphs

## Quick Facts
- **arXiv ID:** 2603.11039
- **Source URL:** https://arxiv.org/abs/2603.11039
- **Reference count:** 4
- **Primary result:** IsalGraph encodes graphs as strings via a nine‑instruction VM, guaranteeing every string decodes to a valid simple graph; greedy encoding works in polynomial time for connected graphs; a canonical variant is conjectured isomorphism‑invariant; Levenshtein distance correlates strongly with graph edit distance on sparse benchmarks.

## Executive Summary
IsalGraph introduces a compact string representation for finite simple graphs using a virtual machine with a circular doubly‑linked list and two pointers. The interpreter accepts any string over a nine‑character alphabet and always produces a valid graph. A greedy graph‑to‑string algorithm (G2S) encodes any connected graph in polynomial time, while an exhaustive backtracking variant aims for a canonical isomorphism‑invariant string (still unproven). Empirical evaluation on several graph benchmarks shows a high Spearman correlation (up to 0.934) between Levenshtein distance of the strings and graph edit distance, particularly on sparse graphs. The greedy encoder scales approximately as O(n^4.5), whereas the canonical version scales as O(n^9), limiting practical use.

## Method Summary
The paper defines two complementary procedures: **StringToGraph (S2G)**—a deterministic interpreter that processes a string character‑by‑character, mutating a state consisting of a graph, a circular doubly‑linked list of node references, and two pointers—and **GraphToString (G2S)**, which builds a string by traversing a given graph. G2S has two modes: a greedy variant that at each step chooses the lowest‑cost pointer displacement and structural operation (node/edge insertion) that advances the traversal, and a canonical variant that exhaustively explores all starting nodes and neighbor orders to find the lexicographically smallest shortest string. The evaluation framework includes round‑trip correctness checks (S2G(G2S(G)) ≅ G), correlation between Levenshtein and graph edit distances on real‑world datasets, and measurement of encoding time complexity on synthetic graphs.

## Key Results
- Every string over the IsalGraph alphabet decodes to a valid finite simple graph; no invalid states are reachable.
- Greedy G2S encodes any connected graph in polynomial time (empirical scaling ~n^4.5).
- Canonical encoding (exhaustive backtracking) yields a string conjectured to be isomorphism‑invariant but scales as ~n^9, becoming infeasible beyond 12 nodes.
- Strong empirical correlation between Levenshtein distance and graph edit distance on sparse benchmarks (Spearman ρ up to 0.934).

## Why This Works (Mechanism)
**Mechanism 1: Universal Validity.** The instruction semantics are designed so that the interpreter state always consists of a simple graph and a circular doubly‑linked list with wrap‑around pointer moves. Insertion operations (`V`, `v`, `C`, `c`) add nodes or edges in a way that preserves simplicity (no self‑loops or parallel edges). Starting from a single node, every transition maintains these invariants, so any string—no matter the sequence—leads to a well‑defined simple graph.

**Mechanism 2: Greedy Encoding Correctness.** For any connected graph (or directed graph with all nodes reachable from the chosen start), the greedy G2S systematically covers all nodes and edges. It iterates over pointer displacement pairs in order of increasing total movement cost and checks in priority order whether adding a node or edge is applicable. The first applicable operation is emitted and the internal mappings updated. Because the reverse interpreter exactly inverts these operations, the round‑trip `S2G(G2S(G))` yields a graph isomorphic to `G`.

**Mechanism 3: Metric Locality.** The string encoding records a traversal where each structural edit (node or edge insertion) is accompanied by a bounded number of pointer moves. Consequently, a small edit in the graph typically induces only a few character changes in the string, and a small Levenshtein edit corresponds to at most one structural modification. This property holds particularly well for sparse graphs, where a single DFS‑like pass captures most topology, leading to the observed high correlation with graph edit distance.

## Architecture Onboarding
**Component map (plain text):**  
G2S: Graph -> String  
S2G: String -> Graph  
String distance: (String, String) -> Levenshtein matrix  

**Critical path:** Graph → G2S (greedy or canonical) → String → S2G → Graph for round‑trip; Graph pair → two strings → Levenshtein distance vs. GED for evaluation.

**Design tradeoffs:**  
- Greedy vs. Canonical: speed vs. guaranteed isomorphism invariance.  
- String length vs. traversal cost: shorter strings require smarter pointer moves but finding the global optimum is the canonical search’s purpose.  
- Validity guarantee: the nine‑instruction set ensures every string decodes to a valid graph, simplifying generative modeling.

**Failure signatures:**  
- G2S fails (infinite loop or missing nodes/edges) on disconnected graphs (undirected) or directed graphs with unreachable nodes.  
- Canonical encoding times out for graphs larger than ~12 nodes.  
- Round‑trip failure if `S2G(G2S(G))` is not isomorphic to `G` (unlikely but possible due to bugs).

**First 3 experiments:**  
1. Validity stress test: generate 1000 random strings of length 100, decode via S2G, verify all outputs are simple graphs.  
2. Round‑trip on exhaustive small graphs: enumerate all connected graphs up to 6 nodes, compute greedy‑min string (try all start nodes, pick shortest), decode, check isomorphism with original using VF2.  
3. Correlation replication: on IAM Letter LOW dataset, compute greedy‑min strings for all graphs, obtain all‑pairs Levenshtein distances, compute exact GED with unit costs (node/edge ins/del=1, node sub=0), calculate Spearman ρ (expect ≥0.93).

## Open Questions the Paper Calls Out
- **Open Question 1:** Does the canonical string constitute a complete graph invariant? Conjectured; only empirical support on very small graphs (n≤12); a formal proof is lacking.
- **Open Question 2:** What is the theoretical relationship between Levenshtein distance on IsalGraph strings and graph edit distance? Empirical correlation is strong but no bounds or analytic justification exist; the effect of graph density is not understood.
- **Open Question 3:** Can the super‑polynomial complexity of canonical encoding (empirical O(n^9)) be improved without sacrificing correctness? The paper reports no algorithmic advances; it is unclear whether the explosion is inherent.
- **Open Question 4:** How can IsalGraph be extended to encode disconnected graphs or directed graphs with unreachable nodes? The current G2S requires connectedness (or strong reachability from the start); no solution for general graphs is provided.
- **Open Question 5:** Is the nine‑instruction alphabet minimal? The design choices are not analyzed for optimality; a smaller alphabet might suffice.

## Limitations
- Canonical backtracking details (branching order, pruning) are unspecified, potentially affecting both isomorphism invariance and runtime scaling.
- G2S is restricted to connected graphs (or directed graphs with all nodes reachable from the start); no encoding exists for general graphs.
- No independent external validation; replication relies solely on the paper’s description.
