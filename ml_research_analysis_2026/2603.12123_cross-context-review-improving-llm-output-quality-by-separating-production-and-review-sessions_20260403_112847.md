# Cross-Context Review: Improving LLM Output Quality by Separating Production and Review Sessions

## Quick Facts
- arXiv ID: 2603.12123
- Source URL: https://arxiv.org/abs/2603.12123
- Reference count: 13
- Primary result: Cross-Context Review (CCR) achieves F1 score of 28.6%, significantly outperforming same-session self-review (24.6%, p=0.008) and other baselines.

## Executive Summary
The paper investigates why LLMs fail to detect errors in their own outputs when reviewing within the same production session. It identifies anchoring and sycophancy biases as root causes and introduces Cross-Context Review (CCR), where review occurs in a fresh session with only the final artifact. In experiments with Claude Opus on 30 artifacts containing injected errors, CCR achieved an F1 score of 28.6%, significantly higher than same-session self-review (24.6%), repeated self-review (21.7%), and context-aware subagent review (23.8%). The failure of repeated review to improve demonstrates that the benefit arises from context separation, not mere repetition.

## Method Summary
The study evaluated four review conditions using Claude Opus: Self-Review (SR) within the production session; Repeated Self-Review (SR2) with a second review in the same session; Subagent Review (SA) in a fresh session but with the original generation prompt; and Cross-Context Review (CCR) in a fresh session with only the artifact and a standardized review prompt. The artifacts consisted of 30 items (10 code snippets, 10 technical documents, 10 scripts) each pre-injected with five errors across five types and three severity levels. Each condition was run three times independently per artifact (360 total reviews). Error detection was evaluated by matching review findings to ground-truth errors using a heuristic scoring function (line proximity, keyword Jaccard, type match bonus) with a threshold of ≥2.0 for true positives, computing per-artifact precision, recall, and F1.

## Key Results
- CCR achieved an F1 score of 28.6%, outperforming SR (24.6%, p=0.008, Cohen's d=0.52), SR2 (21.7%, p<0.001, d=0.72), and SA (23.8%, p=0.004, d=0.57).
- Repeated self-review (SR2) performed worse than single SR, indicating that mere repetition within the same anchored context fails and may even degrade performance.
- Subagent review (SA) underperformed CCR despite having the generation prompt, suggesting that providing user intent context does not compensate for the lack of session separation.

## Why This Works (Mechanism)
The paper attributes CCR's success to three interrelated mechanisms:

**Anchoring Bias**: In same-session review, the model's initial output acts as an anchor, biasing subsequent judgment toward rationalizing earlier decisions rather than critically assessing the artifact. As noted in Section 2.2, "LLMs exhibit anchoring bias — initial information disproportionately shapes later judgments." Removing the production context eliminates this anchor.

**Sycophancy Bias**: RLHF-trained models tend to agree with their own outputs when authorship is known. Same-session review implicitly reveals authorship, triggering agreeableness over critique. The paper cites prior work showing that when authorship is anonymized, sycophantic bias nearly disappears. Session separation naturally achieves anonymization.

**Context Degradation**: Long production contexts (e.g., 50K+ tokens) cause attention dilution ("lost in the middle", "context rot"), making it harder to detect errors. A fresh review session uses a short context (∼5K tokens) containing only the artifact, focusing attention and improving scrutiny.

## Foundational Learning
- **Anchoring Bias in LLMs**: Why needed: Explains why repeated review (SR2) fails—the anchor persists across turns. Quick check: *If a model generates an answer then reviews it in the same thread, what existing belief will most likely bias its review?*
- **Sycophancy as Training Artifact**: Why needed: Clarifies why same-session review is structurally prone to agreement due to RLHF objectives. Quick check: *Why might anonymizing the artifact's source (via new session) lead to harsher critique?*
- **Context Window Attention Distribution**: Why needed: Provides a mechanical explanation: shorter contexts enhance attention focus on the artifact. Quick check: *How does reducing context from 50K to 5K tokens theoretically improve error detection?*

## Architecture Onboarding
- **Component map**: Production Session (generates artifact) → Export Phase (extracts artifact) → Review Session (fresh context, reviews artifact) → Integration Phase (applies findings).
- **Critical path**: Artifact extraction must isolate final output; new session launch ensures zero history carryover; structured review prompt guides systematic checks; findings integration modifies original or creates new artifact.
- **Design tradeoffs**: Simplicity vs. Depth (CCR is single-pass, cheap but may miss errors needing dialog); Cost vs. Coverage (extra session adds ~5K tokens vs. bloated context); Generality vs. Specialization (works for any model/artifact but not domain-optimized).
- **Failure signatures**: SR2 ≈ SR indicates anchoring context blocks improvement; SA < SR suggests any production context, even stripped, is detrimental; language confound (Korean vs. English) requires control experiments.
- **First 3 experiments**: 
  1. Baseline replication: Run SR vs. CCR on 10 simple code artifacts; expect CCR F1 > SR by ~3–5 points.
  2. SR2 control: Run three reviews per artifact within same session; expect no F1 gain, rising false positives.
  3. Context isolation test: Compare CCR (artifact only) vs. SA (artifact + prompt) on 10 documents; expect CCR > SA despite SA having more intent context.

## Open Questions the Paper Calls Out
- Does CCR maintain its performance advantage across different model families beyond Claude Opus 4.6? (Explicit limitation: only one model tested)
- To what extent does the observed CCR advantage stem from the language switch (Korean production → English review) rather than purely from context separation? (Explicit confound)
- What is the optimal number of sequential CCR passes to maximize error detection before diminishing returns? (Inferred from meta-validation showing different error classes caught)
- How does CCR's effectiveness generalize to domains outside software engineering tutorials, particularly safety-critical ones? (Explicit limitation: only three artifact types within one domain tested)
- Can dynamic, multi-turn CCR (reviewer asks follow-up questions) boost error detection beyond single-pass without reintroducing anchoring? (Proposed future direction)

## Limitations
- Reproduction fidelity: Exact generation prompts, error injection procedure, and `ClaudeCodeAgent` parameters are undocumented, risking artifact set divergence.
- Evaluation heuristic: Matching algorithm details (keyword lists, Jaccard tokenization, scoring weights) are unspecified, potentially misaligning automated scores with human judgment.
- Language confound: Production and review languages differed (Korean vs. English), possibly inflating CCR's advantage beyond pure context separation.

## Confidence
- Core result (CCR F1 improvement): High (statistically significant, well-documented)
- Proposed mechanisms (anchoring, sycophancy, context degradation): Medium (plausible but not experimentally disentangled)
- Generalizability to other models/domains: Low (lacks empirical validation beyond Claude Opus and software-engineering artifacts)

## Next Checks
1. Language-matched replication: Run all review conditions (SR, SR2, SA, CCR) in a single language (e.g., English) to isolate context separation from linguistic effects.
2. Prompt ablation: Introduce a condition where the review session receives the original generation prompt alongside the artifact, measuring the isolated impact of discarding user intent.
3. Human review benchmark: Sample reviews from all conditions and have domain experts annotate errors; compare automated F1 against human-validated scores to assess scoring reliability.
