# Experiential Reflective Learning for Self-Improving LLM Agents

## Quick Facts
- arXiv ID: 2603.24639
- Source URL: https://arxiv.org/abs/2603.24639
- Reference count: 37
- Primary result: ERL achieves 56.1% success on Gaia2, a +7.8% absolute improvement over ReAct and +5.2% over ExpeL.

## Executive Summary
Experiential Reflective Learning (ERL) is a novel framework enabling LLM agents to self-improve by reflecting on past task executions. After each attempt, the agent generates a structured heuristic—comprising analysis and trigger-action rules—which is stored in a persistent pool. During test time, the agent retrieves the most relevant heuristics using an LLM scorer and injects them into its system prompt, guiding its reasoning and tool usage. Evaluated on the Gaia2 benchmark, ERL achieves a 56.1% success rate, representing a +7.8% absolute improvement over the ReAct baseline and a +5.2% gain over ExpeL. The approach also enhances reliability, with pass@3 increasing by up to +10.6% on the Search split. ERL requires no parameter updates, multiple retries, or curated training sets, offering a simple yet effective mechanism for continual improvement.

## Method Summary
ERL operates in two phases. In the experience accumulation phase, the agent (a ReAct loop) interacts with the Gaia2 environment for each training task. Upon completion, a heuristic generation module (using GPT-5-mini) processes the task description, execution trajectory, and binary reward to produce a structured heuristic: an analysis of the outcome and a trigger-action guideline. This heuristic is stored in a persistent pool indexed by scenario ID. During test time, for a new task, an LLM (GPT-5.2) scores all stored heuristics for relevance along three criteria—task similarity, experience diversity, and guideline informativeness—and retrieves the top‑k (k=20). These heuristics are injected into the agent’s system prompt, conditioning its ReAct execution. The process requires no parameter updates and can be repeated iteratively, adding new heuristics from test runs to the pool.

## Key Results
- ERL overall success: 56.1% on Gaia2.
- Improves over ReAct by +7.8% and over ExpeL by +5.2%.
- Gains consistent across Execution (+8.3%) and Search (+7.1%) splits.
- Reliability metrics: pass@3 increased by +8.3% (Execution) and +10.6% (Search).

## Why This Works (Mechanism)
### Mechanism 1: Trajectory distillation into heuristics produces reusable, transferable knowledge.
- Claim: After a task, the agent receives a binary reward and prompts an LLM with the task, trajectory, and outcome to generate a heuristic, which is stored persistently.
- Mechanism: One execution provides enough information for the LLM to extract a general rule; the structured format aids clarity.
- Core assumption: Single‑attempt reflection yields generally applicable guidelines.
- Evidence: ERL reflects on task trajectories and outcomes to generate heuristics, capturing actionable lessons that transfer across tasks (abstract); section 2 describes heuristic generation using GPT‑5‑mini (corpus: ExpeL, AutoGuide use multi‑retry or contrastive pairs).
- Break condition: Missing or noisy reward signals, or vague reflection, can produce misleading heuristics that harm future performance.

### Mechanism 2: LLM‑based selective retrieval of relevant heuristics is essential; random or embedding‑based selection underperforms.
- Claim: For a new task, an LLM scores each heuristic on task similarity, experience diversity, and guideline informativeness, then injects the top‑k (k=20) into the agent’s prompt.
- Mechanism: The ranking LLM accurately predicts which heuristics will help; a modest k avoids context bloat.
- Core assumption: LLM ranking identifies useful heuristics better than embedding similarity.
- Evidence: Section 2 explains retrieval process; Figure 4 and Table 3b show LLM retrieval (56.1%) outperforms embedding retrieval (53.3%) and best random selection (53.8%) (corpus: AutoGuide uses embedding‑based context identification).
- Break condition: Misranking due to distribution shift or a pool dominated by low‑quality heuristics introduces irrelevant guidance; too large a k dilutes attention or exceeds the context window.

### Mechanism 3: Injecting retrieved heuristics into the agent’s context enables in‑context learning from past experiences, boosting success rates and reliability without parameter updates.
- Mechanism: The ReAct agent receives a system prompt augmented with the top‑k heuristics; the LLM is expected to incorporate the trigger‑action rules into its reasoning and tool usage.
- Core assumption: The LLM can consistently apply the provided guidelines alongside task instructions within the available context.
- Evidence: Abstract: "injected into the agent’s context to guide execution." Section 3: Figure 2: ERL 56.1% vs. baseline 48.3% (+7.8%). Figure 3: pass @ 3 and pass^3 gains indicate improved reliability. Ablation: raw‑trajectory few‑shot prompting (46.4%) fails to beat baseline, highlighting the value of heuristic abstraction (corpus: most self‑improvement approaches require parameter updates or multiple retries; ERL’s parameter‑free injection is a notable alternative).
- Break condition: Contradictory heuristics, context overflow, or systematic ignoring of guidance can nullify or reverse gains.

## Architecture Onboarding
- **Component map**: Agent Execution (ReAct) <-> Environment -> (Trajectory, Reward) -> Heuristic Generation -> Heuristic Pool -> Heuristic Retrieval -> Agent Execution (system prompt)
- **Critical path**:
  1. Training run: (task, trajectory, reward) → generate heuristic → add to pool.
  2. Test run: new task → retrieve top‑k heuristics → prepend to system prompt → ReAct execution → (optional) new heuristic added.
- **Design tradeoffs**:
  - Single‑attempt vs. multi‑retry: Single‑attempt cuts cost but risks lower‑quality heuristics; multi‑retry (ExpeL) improves quality at higher expense.
  - LLM vs. embedding retrieval: LLM ranking yields ~2.8% absolute gain over embedding but adds latency and API cost.
  - Heuristic abstraction: Compact and strategic but may lose fine‑grained context preserved in raw trajectories.
  - Injection point: System prompt ensures all turns see heuristics but increases per‑turn tokens; per‑turn retrieval (AutoGuide) targets specific steps but requires repeated calls.
- **Failure signatures**:
  - Split‑specific divergence: Overweighting failure heuristics helps Search but hurts Execution, or vice versa.
  - Ablation mismatch: If embedding retrieval matches LLM retrieval, the ranker prompt may be ineffective.
  - Pool contamination: Accumulation of poor/conflicting heuristics degrades retrieval quality.
  - Iterative ERL dip: Test performance may drop when heuristics accumulate from guided (non‑naive) runs.
  - Context overflow: Excessive k exceeds the LLM’s window or causes attention dilution.
- **First 3 experiments**:
  1. Baseline vs. ERL: Confirm ~7.8% gain on Gaia2.
  2. Retrieval ablation: Replace LLM retrieval with random or no selection; expect a significant drop.
  3. Token‑matched heuristic vs. raw trajectory: Provide the same number of experiences in either form; heuristics should yield higher success rates.

## Open Questions the Paper Calls Out
- **Open Question 1**: How to generate synthetic tasks for heuristic bootstrapping? Basis: Conclusion suggests synthetic task generation. Why unresolved: Generating diverse, realistic tasks automatically is hard. What evidence would resolve: Test if synthetic heuristics match real ones on test performance.
- **Open Question 2**: How to resolve heuristic conflicts and maintain retrieval quality at scale? Basis: Conclusion: "resolving conflicting guidelines and maintaining retrieval quality." Why unresolved: Large pools risk contradictions and poor retrieval. What evidence would resolve: Develop conflict resolution and hierarchical retrieval; evaluate on large pools.
- **Open Question 3**: Can heuristic representations be compressed for lower token usage without losing effectiveness? Basis: Section D: "more compact heuristic representations." Why unresolved: Text heuristics are verbose; compression may lose details. What evidence would resolve: Encode heuristics; compare token usage and success rates to original.
- **Open Question 4**: How to adapt ERL to dual‑control domains with unpredictable user behavior? Basis: τ2‑bench: "limitations around capturing user coordination strategies." Why unresolved: Single‑control heuristics may not generalize to dynamic user actions. What evidence would resolve: Enrich heuristics with user traces; evaluate on Telecom benchmark.

## Limitations
- **Environment and dataset unavailable**: The ARE platform and Gaia2 dataset are not publicly released, preventing direct replication.
- **Inaccessible model versions**: The specified models (gpt-5-mini, gpt-5.2) are likely internal; substitutes may yield different results.
- **Ambiguous splits and prompts**: Exact universe IDs and seeds for training/test are not fully documented; published prompts may be simplified, affecting heuristic quality and retrieval.

## Confidence
- **High**: Reported performance gains (ERL 56.1% vs. ReAct 48.3%) are internally consistent within the paper’s experiments and ablations.
- **Medium**: Mechanistic claims (heuristic transferability, LLM retrieval superiority) are supported but rely on unreproducible components (specific prompts, models, dataset).
- **Low**: Generalizability beyond Gaia2 or to other LLM families is unsupported; confidence in the exact retrieval ranking advantage drops with alternative models or simpler prompts.
