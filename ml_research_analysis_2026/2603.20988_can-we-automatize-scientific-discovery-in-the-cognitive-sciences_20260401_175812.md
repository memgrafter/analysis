# Can we automatize scientific discovery in the cognitive sciences?

## Quick Facts
- **arXiv ID:** 2603.20988
- **Source URL:** https://arxiv.org/abs/2603.20988
- **Reference count:** 23
- **Primary result:** Proposes a conceptual blueprint for an end-to-end automated discovery engine using LLMs to accelerate theory development in cognitive sciences by replacing manual steps with scalable synthesis and evaluation.

## Executive Summary
The paper addresses the slow, human-limited discovery cycle in cognitive sciences that restricts hypothesis space exploration. It proposes an automated framework where an LLM generates experimental paradigms, a cognitive foundation model simulates subject-conditioned behavioral data, LLM-based program synthesis discovers fitting computational models, and an LLM-critic optimizes for "interestingness" to close the loop. This shifts human roles to defining constraints and validating top candidates, aiming for high-throughput, in-silico theory development. No empirical metrics are reported; the contribution is the integrated system design.

## Method Summary
The proposed method integrates four components: (1) an LLM agent generates structured experiment specifications (e.g., MDPs) from cognitive goals and task grammar constraints; (2) a cognitive foundation model (e.g., Centaur) simulates behavioral data conditioned on experiment specs and subject metadata; (3) an LLM-based program synthesis engine performs high-throughput search over computational model code, evaluating fit to synthetic data; (4) an LLM-critic assigns an "interestingness" score to discovery tuples and feeds back to steer experiment generation. The loop is orchestrated to iteratively propose, simulate, model, and evaluate, with human oversight reserved for final validation.

## Key Results
- Conceptual blueprint for a fully automated, high-throughput discovery engine in cognitive sciences.
- Replaces manual hypothesis generation, data collection, and model fitting with scalable LLM-driven synthesis and evaluation.
- Shifts human contribution to setting constraints and validating top candidates, potentially accelerating theory development cycles.

## Why This Works (Mechanism)

### Mechanism 1: LLM as Experiment Sampler
LLMs are prompted with cognitive goals and task grammar constraints to generate structured experiment descriptions (e.g., MDPs). This expands the hypothesis space by combining task components in novel ways, bypassing human intuition limits. **Core assumption:** LLMs encode latent knowledge of valid experimental structures. **Evidence:** Paper states experiments are "directly sampled from an LLM" and refined based on feedback. **Break condition:** Generated paradigms are infeasible (incoherent state spaces) or fail to produce discriminable behavioral signatures.

### Mechanism 2: Cognitive Foundation Model for Data Generation
A model like Centaur, fine-tuned on diverse human behavioral datasets, autoregressively produces trial-by-trial choices conditioned on experiment specs and subject metadata. This replaces human data collection with high-fidelity, subject-specific simulations. **Core assumption:** Foundation models capture sufficient cognitive structure to simulate behavior for novel tasks and individual differences. **Evidence:** Paper claims such models generate "de novo data often indistinguishable from human behavior" and can extrapolate to new tasks. **Break condition:** Performance degrades on tasks with distributional shift or conditioning produces confabulated phenotypes.

### Mechanism 3: LLM-based Program Synthesis for Model Discovery
LLMs generate candidate computational model code (e.g., Python functions), which are evaluated on fit to synthetic data (e.g., likelihood). Top performers seed further iterations via evolutionary search, exploring a vast program space. **Core assumption:** The algorithmic hypothesis space contains valid cognitive mechanisms, and performance feedback reliably guides search. **Evidence:** Paper references systems like GeCCo that iteratively refine models based on predictive performance. **Break condition:** Search converges on overfitted ad hoc models or excludes valid architectures due to representation limits.

### Mechanism 4: LLM-critic for Interestingness Optimization
An LLM-as-judge evaluates discovery tuples (experiment, subject, data, models) on multi-dimensional criteria (novelty, simplicity, transferability, unification) to assign an "interestingness" score. This score biases the experiment generator toward theoretically valuable proposals, closing the loop. **Core assumption:** Multi-objective criticism can steer discovery away from trivial novelty toward meaningful science. **Evidence:** Paper proposes combining novelty with robustness, parsimony, etc. **Break condition:** Critic rewards superficial weirdness or becomes gameable, leading to pathological loops.

## Architecture Onboarding
**Component map:**  
Experiment Generator (LLM) → Simulated Subject (Cognitive Foundation Model) → Model Discoverer (LLM + Evaluator + Search Loop) → Discovery Critic (LLM-as-judge) → Loop Controller → (feeds back to) Experiment Generator

**Critical path:**  
Experiment Spec → Synthetic Data → Model Candidate Set → Interestingness Score → (feedback) → Next Experiment Spec

**Design tradeoffs:**
- Grammar Expressivity vs. Feasibility: Richer task language enables more novel experiments but increases infeasible spec generation.
- Search Breadth vs. Cost: High-throughput program search is computationally expensive; balance candidate pool size with evaluation budget.
- Interestingness Signal Complexity: Single scalar score is simple but gameable; multi-objective is robust but harder to tune.

**Failure signatures:**
- Pathological Loop: Critic rewards superficial novelty, leading to bizarre, non-interpretable experiments/models.
- Simulator-Exploiter Gap: Discovered models fit synthetic data perfectly but fail on real human data, indicating simulator misspecification.
- Representational Blind Spot: System never proposes tasks from key domains (e.g., social cognition) due to grammar/prompt biases.

**First 3 experiments:**
1. Unit Test - Experiment Generation: Prompt Experiment Generator for a standard task (e.g., two-armed bandit). Check if spec is valid and known.
2. Unit Test - Model Discovery: Feed fixed simple dataset (e.g., from Rescorla-Wagner) into Model Discoverer. Check if it rediscovers the known model.
3. Integrated Mini-Loop: Run 2 full cycles on a narrow task family (e.g., risk-sensitive choice) with a mock critic rewarding simpler models. Check if system evolves toward simpler models and experiment spec remains stable.

## Open Questions the Paper Calls Out

### Open Question 1
**Question:** How can a task grammar for automated experiment generation be designed to be maximally expressive across diverse cognitive domains without introducing unintended biases?  
**Basis in paper:** Paper identifies task grammar as a "central scientific object" that determines explorable space and must cover multiple domains while being pressure-tested.  
**Why unresolved:** No specification of how to construct/validate a comprehensive cross-domain grammar; risk of encoding limiting assumptions.  
**What evidence would resolve it:** Grammars that express known seminal experiments across subfields and pass adversarial probing for missing primitives.

### Open Question 2
**Question:** To what extent can cognitive foundation models serve as reliable substitutes for human participants in generating data for novel tasks and conditioned profiles?  
**Basis in paper:** Paper acknowledges debates on generalization, shortcuts, and distribution shift; may produce "plausible-looking behavior... for the wrong reasons."  
**Why unresolved:** Reliability under open-ended automated discovery is unproven; risk of illusion of mechanistic clarity.  
**What evidence would resolve it:** Systematic evaluation on held-out new task families and subgroup predictions vs. real human data, with consistent accuracy across distributions.

### Open Question 3
**Question:** How can an "interestingness" critic be operationalized to reliably steer discovery toward theoretically valuable outcomes while avoiding superficial novelty?  
**Basis in paper:** Paper warns closing the loop is "both enticing and dangerous," proposing multi-objective design but no concrete metric.  
**Why unresolved:** Defining/weighing criteria like "unification" automatically is unsolved at ML/philosophy of science intersection.  
**What evidence would resolve it:** Retrodiction studies where critic scores past breakthroughs highly and rejects known dead-ends.

### Open Question 4
**Question:** What practical protocols integrate scalable in-silico discovery with necessary in vivo human validation to prevent epistemic failure?  
**Basis in paper:** Paper emphasizes validation but doesn't address orchestration: frequency, basis, scale of human studies for efficient filtering.  
**Why unresolved:** Tension between high-throughput automation and costly testing needs efficient triggers to avoid "Library of Babel" problem.  
**What evidence would resolve it:** Simulated hybrid pipeline with fixed validation budget, measuring validated theories per human data collected vs. alternatives.

## Limitations
- Major uncertainties: Unrevealed details of the Centaur cognitive foundation model and unspecified LLM-critic prompt design prevent empirical verification.
- Conceptual blueprint is untested; failure modes like simulator-exploiter gaps or reward hacking are plausible given known LLM limitations.
- No empirical metrics reported; contribution is system design, not demonstration of efficacy.

## Confidence
- **Mechanism 1** (LLM as experiment sampler): Medium (analogous to general LLM capabilities but lacks domain validation)
- **Mechanism 2** (Cognitive foundation model for data): Low (unrevealed model details, generalization concerns)
- **Mechanism 3** (LLM-based program synthesis): Medium (proof-of-concept in other domains but not specific to cognitive modeling)
- **Mechanism 4** (LLM-critic for interestingness): Low (no concrete rubric, risk of reward hacking)

## Next Checks
1. **Data Generator Benchmark:** Use Centaur prompting to generate data for a canonical task (e.g., two-armed bandit). Compare choice statistics (probability matching, RTs) against human benchmarks. *Diagnostic: Significant deviation indicates simulator misspecification.*
2. **Interestingness Rubric Calibration:** Define critic's scoring dimensions with concrete prompts. Validate on expert-rated "interesting" vs. "boring" discovery tuples. *Diagnostic: Low agreement or high scores for trivial outputs.*
3. **End-to-End Unit Test:** Execute full loop for 5 iterations on a narrow task family (e.g., risk-sensitive foraging) with fixed synthetic data and simple model class. *Diagnostic: Monitor experiment feasibility and model convergence to known solutions vs. overfitting.*
