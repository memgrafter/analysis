# Bridging the Evaluation Gap: Standardized Benchmarks for Multi-Objective Search

## Quick Facts
- **ArXiv ID:** 2603.24084
- **Source URL:** https://arxiv.org/abs/2603.24084
- **Reference count:** 7
- **Primary result:** Introduced a standardized benchmark suite for multi-objective shortest-path search, enabling reproducible comparisons across a full spectrum of Pareto-front structures and dimensionalities.

## Executive Summary
Multi-objective search (MOS) evaluation suffers from fragmentation: algorithms are tested on heterogeneous instances, query sets, and solution definitions, preventing fair head-to-head comparison. This paper addresses the gap with a standardized benchmark suite that fixes graph instances, objective formulations, start‑goal query sets (50–100 per benchmark), and provides both exact and approximate reference Pareto‑optimal solutions. The suite spans four families—road networks, synthetic graphs, game‑based grids, and robotic motion‑planning roadmaps—covering a wide range of objective interactions (Pearson correlations |ρ|<0.01 to ρ=0.96–0.97) and Pareto‑set cardinalities (2 to 8,726). Empirical results show ε‑approximation dramatically shrinks solution sets (median 97.9% reduction at ε=0.1). The benchmarks thus enable robust, reproducible algorithmic evaluations and lay groundwork for future extensions.

## Method Summary
The benchmark suite consists of downloadable files for each instance: the graph (vertices, edges, additive edge‑local costs for each objective), a fixed set of start‑goal queries, and precomputed reference Pareto sets. Exact sets (ε=0) are generated using the NAMOA*dr algorithm; approximate reference sets for ε∈{0.01,0.05,0.1} are derived by pruning exact sets via ε‑dominance. To evaluate an algorithm, the user runs it on each query, collects the output solution set, and checks against the reference: for exact evaluation, all true Pareto solutions must be found; for approximate, every true Pareto solution must be ε‑dominated by some output solution. Metrics include Pareto‑set cardinality statistics (min/max/median/mean), runtime, memory usage, and approximation quality (e.g., fraction of true Pareto solutions covered). The methodology assumes classical MOS: non‑negative additive costs, Pareto minimization, and deterministic graphs.

## Key Results
- **Domain coverage:** Benchmarks include road networks (DIMACS, Extended, GER10), synthetic graphs (Random‑Cost Grids, NetMaker), game‑based grids (GUARDS), and robotic motion‑planning roadmaps (Panda‑RRG 2/8).
- **Objective interaction spectrum:** Pearson correlations ρ between objective edge‑cost vectors range from nearly independent (|ρ|<0.01 in Grid benchmarks) to highly correlated (ρ=0.96–0.97 in DIMACS).
- **Pareto‑set size variability:** Exact Pareto cardinalities per query range from 2 to 8,726; median cardinality at ε=0.1 is reduced by 97.9%, illustrating the power of bounded approximation.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Standardized benchmarks reduce evaluation fragmentation by fixing problem instances, query sets, and reference solutions.
- **Mechanism:** By providing deterministic graph instances, a fixed set of start‑goal queries per instance, and precomputed exact/approximate Pareto‑optimal solution sets, the suite eliminates variability in instance selection and solution definition. This allows direct, head‑to‑head comparison of any MOS algorithm on identical tasks.
- **Core assumption:** Fragmentation previously arose from heterogeneity in instance sources and query generation; fixing these components removes that source of noise.
- **Evidence anchors:**
  - [abstract] "By providing fixed graph instances, standardized start–goal queries, and both exact and approximate reference Pareto-optimal solution sets, this suite captures a full spectrum of objective interactions."
  - [section 4.1] "G1 Standardization. Benchmarks are defined using fixed graph instances, objective formulations, and standardized start–goal query sets, enabling direct comparison across algorithms."
  - [corpus] Corpus shows diverse MOS algorithm papers (e.g., OPMOS, Generalizing MOS) that historically used different benchmarks; the suite directly addresses this by offering a common base.
- **Break condition:** If future MOS problem formulations (e.g., non‑additive costs) become dominant, this mechanism fails as the suite only supports classical additive edge‑local costs (stated in Section 3).

### Mechanism 2
- **Claim:** Including benchmarks with varying objective correlations (from ρ≈0.96 to |ρ|<0.01) reveals algorithmic sensitivity to Pareto‑front structure.
- **Mechanism:** Pearson correlation between edge‑cost vectors (ρ) is a proxy for objective conflict. High ρ (DIMACS) yields small, compressed Pareto fronts; low ρ (Grid, Games) yields large, diffuse fronts. Testing across this spectrum shows whether an algorithm’s performance is tied to specific front geometries.
- **Core assumption:** Algorithm runtime/memory is systematically affected by the degree of objective conflict and resulting Pareto‑set size.
- **Evidence anchors:**
  - [abstract] "Results demonstrate diverse objective interactions: Pearson correlations range from nearly independent (|ρ|<0.01 in Grid benchmarks) to highly correlated (ρ=0.96–0.97 in DIMACS)."
  - [section 4.2] Reports ρ=0.96/0.97 for DIMACS and |ρ|<0.01 for Grid; Section 6 shows Pareto cardinality varies (min 2 to max 8,726).
  - [corpus] Corpus includes papers like "A Preprocessing Framework..." that explicitly study correlation effects, supporting the premise that correlation matters.
- **Break condition:** If algorithms are developed that are provably insensitive to correlation (unlikely given known dominance‑check costs), this diagnostic mechanism loses value.

### Mechanism 3
- **Claim:** Providing reference exact/approximate solution sets enables reproducible, bounded‑evaluation of approximate algorithms via ε‑dominance.
- **Mechanism:** For each query, a ground‑truth exact Pareto set Π* is computed (using NAMOA*dr). Approximate algorithm outputs can be verified by checking if every true Pareto solution is ε‑dominated by some output solution. Fixed ε‑values (0.0, 0.01, 0.05, 0.1) allow consistent quality measurement across studies.
- **Core assumption:** Reference solutions are correct and complete; NAMOA*dr is a reliable exact solver for these instances.
- **Evidence anchors:**
  - [section 5] "Reference solution sets are computed using the NAMOA*dr algorithm... capable of enumerating exact Pareto-optimal solution sets."
  - [section 6] "Pareto set cardinality decreases substantially as ε increases... median size at ε=0.1 reduced by 97.9%."
  - [corpus] Corpus includes A*pex and NAMOA*dr papers; while not validating correctness here, they establish NAMOA*dr as a standard exact baseline.
- **Break condition:** If NAMOA*dr fails on certain high‑dimensional or disconnected instances (undetected errors in reference sets), all approximate evaluations become suspect. The paper does not prove NAMOA*dr’s correctness on all provided graphs—this is an assumption.

## Foundational Learning
- **Concept:** Multi‑objective shortest path (MOS) problem definition.
  - **Why needed here:** The entire benchmark assumes the classical MOS formulation: additive edge costs, Pareto dominance, start‑goal queries. Without this, instance usage is invalid.
  - **Quick check question:** Given two path cost vectors (3,5) and (4,4), which dominates which under Pareto (minimization)?

- **Concept:** Pareto dominance and ε‑dominance.
  - **Why needed here:** Determines solution optimality (exact) and quality (approximate). The benchmark’s reference sets and evaluation protocol (§5) rely on these definitions.
  - **Quick check question:** For ε=(0.1,0.1), does vector (5,5) ε‑dominate (4.6,5.4)?

- **Concept:** Objective correlation via Pearson coefficient.
  - **Why needed here:** Central to characterizing benchmarks (§2, §4). ρ measures linear dependence between edge‑cost vectors; it predicts Pareto‑front size and structure.
  - **Quick check question:** If all edges have costs where c₁ = c₂ + constant, what is ρ(c₁, c₂)?

## Architecture Onboarding
- **Component map:**  
  Benchmark families (F1–F4) provide fixed graph instances; per‑instance artifacts include graph files, query sets (50–100 start‑goal pairs), and reference Pareto solution sets for ε∈{0.0,0.01,0.05,0.1}. An evaluation harness loads an instance, runs the algorithm on each query, and compares output to references via dominance checks. Metrics collected include Pareto‑set size, ε‑approximation quality, and resource usage.

- **Critical path:**  
  1. Select a benchmark family/variant (e.g., `Grid 4k×k` with 4 objectives).  
  2. Load the fixed graph and its 100 fixed queries.  
  3. For each query, run the MOS algorithm.  
  4. Compare algorithm’s output solutions to the provided reference set for the chosen ε.  
  5. Aggregate results (e.g., average Pareto‑set size reduction vs. exact, average runtime).

- **Design tradeoffs:**  
  - *Coverage vs simplicity:* The suite prioritizes breadth (4 families, varying dimensionality) over depth (few variants per family). Users needing specialized topologies must extend it.  
  - *Exact reference cost:* Precomputed sets enable fast verification but require significant storage for many‑objective instances (e.g., Panda‑RRG 8 has up to 8,726 solutions/query).  
  - *Classical formulation only:* Non‑additive, history‑dependent, or aggregation‑based MOS cannot use these benchmarks directly.

- **Failure signatures:**  
  - Algorithm returns non‑Pareto solutions: fails dominance check against reference Π*.  
  - Algorithm claims ε‑approximation but misses true Pareto solutions: some Π* solutions not ε‑dominated by output.  
  - Poor scaling on large fronts: disproportionate runtime on Grid/NetMaker queries where median Π* is large.  
  - Disconnection mishandling: in Games benchmarks, some queries have no path; algorithm must return empty set correctly.

- **First 3 experiments:**  
  1. **Baseline correlation test:** Run a simple label‑setting algorithm (e.g., NAMOA*) on DIMACS‑NY2 (ρ≈0.96) vs. Grid 2k×m (ρ≈0). Compare runtime and output cardinality; expect orders‑of‑magnitude difference in front size.  
  2. **ε‑sensitivity sweep:** On Panda‑RRG 8 (d=8), compute reference sets for ε=0.0,0.01,0.05,0.1. Run an approximate algorithm (e.g., A*pex) and verify ε‑dominance. Measure how output size tracks the reported 97.9% median reduction.  
  3. **Query variability check:** On NetMaker‑30k 3, inspect Pareto cardinality across the 50 queries. Confirm substantial variation (min 101, max 1,423). If algorithm performance correlates with query difficulty (e.g., geodesic distance), analyze that relationship.

## Open Questions the Paper Calls Out
1. **Question:** What are effective standardized benchmark designs for non‑classical multi‑objective search formulations, such as aggregation‑based models, hierarchical objectives, and history‑dependent costs, to complement the current classical benchmark suite?  
   **Basis in paper:** The conclusion states: "While this initial release focuses on classical non‑negative additive edge‑local costs, the suite is designed to be extensible. Future work will expand the benchmark to encompass emerging extensions in the field, including aggregation‑based models, hierarchical formulations, and history‑dependent objectives."  
   **Why unresolved:** The current suite only covers classical MOS with additive edge costs. These extended models are actively researched but lack standardized benchmarks, hindering reproducible evaluation and comparison.  
   **What evidence would resolve it:** Creation of benchmark instances for each extension with clear objective definitions, query sets, and reference solutions. Comprehensive empirical studies using these benchmarks to assess algorithm performance and identify model‑specific challenges.

2. **Question:** To what extent do the four included benchmark families represent the full diversity of real‑world multi‑objective pathfinding problems, and are there critical application domains or objective types absent from the suite?  
   **Basis in paper:** The suite spans road networks, synthetic graphs, game‑based grids, and robotic roadmaps (Sec. 4), aiming for diversity (Goal G3). However, it does not claim exhaustive coverage, and domains like supply chain routing, environmental planning, or communication networks are not addressed.  
   **Why unresolved:** MOS applications are broad and evolving. Overlooking key domains may bias algorithm evaluations and limit the suite’s utility for emerging problems. The current selection is pragmatic but not necessarily comprehensive.  
   **What evidence would resolve it:** A systematic survey of MOS applications to identify common graph structures, objective definitions, and missing scenarios. Development of new benchmark families based on gaps, validated by domain experts to ensure practical relevance.

3. **Question:** How do non‑linear interactions between objectives, beyond the linear Pearson correlation used in the paper, influence Pareto front structures and algorithm performance, and how can benchmarks be engineered to isolate these effects?  
   **Basis in paper:** The paper characterizes objective interaction solely via Pearson correlation (Sec. 2), which captures linear dependence. Benchmarks control correlation via design (e.g., independent costs in Grid), but non‑linear relationships (e.g., quadratic, threshold‑based) are not considered.  
   **Why unresolved:** Non‑linear trade‑offs are plausible in real‑world objectives (e.g., risk vs. distance with nonlinear risk zones), but current benchmarks do not vary non‑linearity systematically. This leaves unclear how algorithms handle such complexities or how to design them for robustness.  
   **What evidence would resolve it:** Synthetic benchmark families where edge costs are generated with prescribed non‑linear relationships (e.g., one objective as a nonlinear function of another). Empirical analysis of Pareto front properties and algorithm metrics across a spectrum of non‑linearities.

4. **Question:** What are the practical computational limits of MOS algorithms with respect to objective dimensionality, and how can benchmarks be scaled to stress‑test these limits beyond the current 10‑objective maximum?  
   **Basis in paper:** The suite includes GER 10 (10 objectives) and Panda‑RRG 8 (8 objectives), but does not explore higher dimensions. Theoretical worst‑case Pareto front growth is exponential, and approximate methods reduce cardinality (Fig. 3), but breaking points for scalability are unquantified.  
   **Why unresolved:** High dimensionality is a core challenge in MOS, yet the suite provides only a few high‑dimensional cases. Without systematic scalability testing, it is unknown how existing algorithms perform as dimensions increase further (e.g., 20, 50 objectives) or where fundamental limits lie.  
   **What evidence would resolve it:** Generation of benchmark instances with increasing objective counts (e.g., 15, 20, 50) using controlled topologies and cost distributions. Rigorous evaluation of state‑of‑the‑art exact and approximate algorithms on these instances to chart runtime, memory, and solution quality trends, identifying dimensionality thresholds.

## Limitations
- The benchmark’s reliability hinges on the unstated NAMOA*dr version and hardware used to generate reference solutions; variations could alter Pareto sets subtly (e.g., via tie‑breaking).
- The suite only covers classical additive edge‑cost MOS formulations; non‑additive, dynamic‑cost, or aggregation‑based problems fall outside its scope.
- High‑dimensional instances (e.g., Panda‑RRG 8) yield large reference sets (up to 8,726 solutions/query), imposing storage and verification burdens not fully quantified.

## Next Checks
1. **Cross‑validate reference sets:** For a subset of queries (e.g., Grid 2k×m, DIMACS‑NY2), recompute exact Pareto sets using an independent exact MOS solver (e.g., A*pex) and compare against the provided references. Any discrepancy undermines approximate evaluation integrity.
2. **Stress‑test storage/runtime:** Load and verify the largest reference sets (Panda‑RRG 8) on modest hardware (e.g., 16 GB RAM). Document load times and disk footprint to assess practical usability for average researchers.
3. **Challenge formulation assumption:** Attempt to apply the benchmarks to a non‑additive MOS problem (e.g., path‑dependent costs or concave aggregation). Confirm expected failure modes to validate the break condition noted in Mechanism 1.
