# Mitigating the Likelihood Paradox in Flow-based OOD Detection via Entropy Manipulation

## Quick Facts
- arXiv ID: 2602.09581
- Source URL: https://arxiv.org/abs/2602.09581
- Reference count: 40
- Primary result: Semantic Proportional Entropy Manipulation (SPEM) raises AUROC for OOD detection from 0.0256 to 0.9913 on CIFAR-10 vs. SVHN.

## Executive Summary
Normalizing flows assign higher likelihood to out-of-distribution (OOD) samples than in-distribution ones, a counterintuitive failure known as the likelihood paradox, which severely undermines their use for OOD detection. This paper introduces Semantic Proportional Entropy Manipulation (SPEM), a training‑free, post‑hoc method that resolves the paradox by manipulating input entropy. SPEM uses a fixed pretrained feature extractor to compute a semantic similarity score λ for each test sample; it then adds Gaussian noise with variance inversely scaled by λ before evaluating the flow’s likelihood. The resulting score cleanly separates in- and out-of-distribution data, achieving dramatic AUROC improvements across ten dataset pairs and outperforming seven likelihood‑based baselines. A noise‑only variant also performs strongly, highlighting that controlled entropy alone suffices.

## Method Summary
SPEM operates in three stages. First, a normalizing flow (e.g., ResFlow) is trained on in-distribution (ID) data with standard uniform dequantization. Second, a memory bank is constructed: a pretrained ResNet‑152 (with ReAct activation clipping) extracts features from all ID training images; these features are stored. Third, for each test image, its ResNet features are extracted and clipped identically, then λ is computed as the maximum cosine similarity to any memory bank entry. The test image is perturbed by adding i.i.d. Gaussian noise ε ∼ N(0, ((1−λ)α)²I), where α is a small hyperparameter (0.4 for ResFlow). The flow evaluates the negative log‑likelihood of the perturbed image; this score is used for OOD classification. A variant, SPEM‑noise, feeds only the noise vector ε into the flow. The method requires no retraining of the flow and is fully post‑hoc.

## Key Results
- On CIFAR‑10 (ID) vs. SVHN (OOD), SPEM lifts AUROC from 0.0256 (raw likelihood) to 0.9913.
- SPEM consistently outperforms seven prior likelihood‑based OOD detection methods across both “failure” and “non‑failure” regimes.
- The noise‑only variant (SPEM‑noise) also achieves strong AUROC, underscoring that entropy manipulation alone drives the improvement.

## Why This Works (Mechanism)
The likelihood paradox arises because the density learned by normalizing flows can assign high probability to OOD regions due to over‑fitting or inductive biases. SPEM manipulates input entropy to amplify the difference in likelihood between ID and OOD samples. For a test sample, λ measures its semantic proximity to the ID manifold: high λ indicates ID‑like content, low λ indicates OOD. SPEM adds scaled Gaussian noise with variance ((1−λ)α)²; thus OOD samples (low λ) receive stronger perturbation, moving them further into low‑density regions of the flow and drastically reducing their likelihood. ID samples (λ≈1) receive minimal noise, preserving their high likelihood. The noise‑only variant shows that the noise variance itself, when conditioned on λ, carries enough signal for OOD detection: the flow’s likelihood on pure noise correlates with the semantic similarity. This mechanism thus effectively turns the flow’s likelihood into a discriminative OOD score without any flow retraining.

## Foundational Learning
- **Normalizing Flows**: Invertible neural networks that enable exact likelihood computation. *Why needed*: They provide the baseline OOD score (log‑likelihood) and are the model whose paradox SPEM addresses. *Quick check*: Train a flow on MNIST; compare likelihoods on MNIST vs. FashionMNIST – paradox often visible as higher likelihood on FashionMNIST.
- **Likelihood Paradox**: The phenomenon where OOD data receive higher likelihood than in-distribution data under a trained flow, breaking the assumption that likelihood indicates membership. *Why needed*: It defines the core problem SPEM solves. *Quick check*: Train a flow on CIFAR-10; compute average likelihood on CIFAR-10 and SVHN – SVHN often yields higher values.
- **Entropy Manipulation**: Adding noise to inputs to increase their entropy, thereby testing the robustness of the likelihood model. *Why needed*: Central to SPEM’s approach; noise strength is scaled by λ. *Quick check*: Add Gaussian noise to images and observe how flow likelihood drops; OOD should drop more sharply.
- **Feature-Based Similarity (ResNet + ReAct)**: Using a pretrained classifier’s embeddings, with ReAct clipping, to measure semantic similarity to the ID training set. *Why needed*: λ quantifies how “in‑distribution” a sample appears semantically, guiding noise scale. *Quick check*: Compute cosine similarities between test images and an ID memory bank; expect a clear separation between ID and OOD.
- **ReAct Activation Clipping**: Clipping feature activations at a threshold (e.g., 90th percentile) to improve OOD discriminability. *Why needed*: It stabilizes the similarity distribution and prevents extreme activations from dominating. *Quick check*: Compare λ histograms with and without ReAct; ReAct should yield tighter ID clustering.

## Architecture Onboarding
Component map: MemoryBank ← (ResNet152+ReAct features of ID train) ; Test: x → ResNet152+ReAct → h(x) → λ = max_cosine_similarity(MemoryBank, h(x)) → σ = (1−λ)α → ε ∼ N(0, σ²I) → x′ = x + ε (or ε alone for SPEM‑noise) → Flow (ResFlow) → −log p_flow(x′) → OOD score.

Critical path: (1) Train flow on ID data; (2) Build memory bank; (3) For each test sample: compute λ, generate noise, compute perturbed likelihood, score.

Design tradeoffs: 
- Using a large ResNet‑152 adds computational overhead but provides rich semantic features.
- Memory bank size (full training set) may be prohibitive for large datasets; subsampling could speed up λ lookup but might reduce accuracy.
- Hyperparameter α controls noise magnitude; too small yields insufficient separation, too large may degrade ID likelihood and cause numerical issues.
- ReAct clipping threshold β must be chosen (paper uses 90th percentile); a poor choice could collapse λ distribution.
- The method is post‑hoc and model‑agnostic, but performance depends on the quality of the pretrained flow and feature extractor.

Failure signatures:
- λ distributions for ID and OOD heavily overlap → similarity signal weak.
- Flow training fails (NLL >5 bits/dim) → raw likelihood unreliable.
- No clear separation in OOD scores after perturbation (AUROC ~0.5).
- Numerical instability (NaNs) when adding noise with large σ.
- Forgetting dequantization during flow training or ReAct during feature extraction causes performance collapse.

First three experiments:
1. **Sanity‑check flow training**: Train ResFlow on CIFAR‑10; verify validation NLL converges to ~3-4 bits/dim and raw likelihood AUROC on SVHN is near random (∼0.0256).
2. **Inspect λ separation**: Build memory bank with ReAct; compute λ for ID validation and OOD test sets; plot histograms to confirm ID λ near 1 and OOD λ significantly lower.
3. **Apply SPEM**: Using λ from exp2, perturb test samples with α=0.4, compute scores, and evaluate AUROC; compare against raw likelihood and ensure dramatic improvement (≥0.95).

## Limitations
- Exact ResFlow architecture (coupling layers, Lipschitz constraints) is not fully specified; implementation variations may affect results.
- Memory bank construction (full vs. subsampled) and ReAct clipping granularity (global vs. per‑channel) are ambiguous.
- Hyperparameter α and the noise‑scale formula for SPEM‑noise may not generalize beyond the reported dataset pairs.

## Confidence
- SPEM efficacy (large AUROC gains): Medium
- Post‑hoc nature (no flow retraining required): High
- Role of entropy manipulation (supported by noise‑only baseline): Medium
