# LifeBench: A Benchmark for Long-Horizon Multi-Source Memory

## Quick Facts
- **ArXiv ID:** 2603.03781  
- **Source URL:** https://arxiv.org/abs/2603.03781  
- **Reference Count:** 40  
- **Primary Result:** State-of-the-art memory systems achieve only 55.22% accuracy on LifeBench.

## Executive Summary
LifeBench introduces a benchmark for evaluating memory systems on long-horizon, multi-source data. It synthesizes realistic one-year personal trajectories, including dense daily events and fragmented phone artifacts, and generates questions requiring both declarative (explicit facts) and non-declarative (habits, preferences) reasoning. The benchmark’s design leverages a partonomic hierarchy for scalable simulation and dual-agent validation for behavioral authenticity. On LifeBench, current memory systems score at most 55.22%, underscoring the difficulty of integrating diverse memory types over extended time scales.

## Method Summary
The LifeBench pipeline constructs synthetic user years in five stages. First, a persona is generated from anonymized social surveys and PersonaHub, capturing demographics, relationships, and lifestyle. Second, a hierarchical event tree is created: a yearly plot is decomposed into monthly thematic events and then into atomic events. Third, a dual-agent simulation produces daily activities—the subjective agent proposes human‑like plans based on persona and habits, while the objective agent validates physical feasibility (travel times, venue availability) using map APIs and calendars. Fourth, these activities are converted into fragmented phone artifacts (SMS, calls, photos, health logs, etc.) with realistic noise. Finally, a question‑answer generation module produces 2,003 QA pairs across five categories (IE, MR, TKU, ND, UA), grounded in the generated data and manually reviewed for quality.

## Key Results
- Top system accuracy on LifeBench is **55.22%** (MemU).  
- Dataset contains **2,003 QA pairs** across 10 user‑years; each day averages **~14 atomic events** and **~23 phone artifacts**.  
- Quality metrics: manual rationality **0.962–1.0**, relation consistency **0.83**, location authenticity **0.83**, trip authenticity **0.75**, event diversity (Shannon Entropy **0.75**, Simpson **0.78**).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** LifeBench forces memory systems to integrate declarative and non-declarative memory reasoning.
- **Mechanism:** The benchmark’s question categories (IE, MR, TKU, ND, UA) and dense, multi-source phone artifacts require systems to infer habits (non-declarative) from fragmented logs while also recalling explicit facts (declarative). Non-declarative reasoning (ND) questions specifically probe patterns like routines and preferences that must be extracted from repeated behaviors across the year-long simulation.
- **Core assumption:** Real-world personal agent behavior depends on both explicit recall and implicit habit/pattern recognition, which existing chat‑only benchmarks do not capture.
- **Evidence anchors:**
  - [abstract]: "LifeBench addresses the gap...integrating declarative and non-declarative memory reasoning over long-horizon, multi-source data."
  - [section 3.2.5]: "We further include nondeclarative memory reasoning questions that probe emotions, habits, and preferences, requiring models to infer patterns from long-range daily activities."
  - [corpus]: Neighbor papers like "UltraHorizon" and "LMEB" also target long-horizon memory but do not explicitly model non-declarative types; this underscores LifeBench’s distinct design choice.
- **Break condition:** If a system performs well on IE/MR/TKU but poorly on ND, it indicates a failure to model non-declarative memory. The 55.22% top accuracy, with ND scores notably lower (Fig 7), shows this mechanism is active and challenging.

### Mechanism 2
- **Claim:** A partonomic hierarchy enables scalable, coherent year-long event simulation.
- **Mechanism:** Events are structured in a nested tree (thematic → atomic) allowing parallel decomposition of thematic events into daily activities while preserving narrative coherence via top‑down constraints (plot outlines, monthly summaries) and bottom‑up contextual adjustments (persona, habits).
- **Core assumption:** Cognitive partonomic organization (events within events) mirrors human memory structuring and permits computational parallelization without losing global consistency.
- **Evidence anchors:**
  - [section 3.2.2]: "We construct a personal event partonomic tree...atomic events...decompose each thematic event into nested subevents...ensuring narrative and temporal consistency."
  - [section 3.3]: Parallel decomposition reduced event decomposition from 2 hours to 30 minutes via 24‑thread parallelization.
  - [corpus]: "BMAM" and "MemWeaver" also draw from brain‑inspired memory structures but focus on agent architectures, not data generation scalability.
- **Break condition:** If parallel generation introduces temporal inconsistencies (e.g., an atomic event contradicts its parent thematic event's location or participants), the hierarchy’s coherence guarantee fails. Manual evaluation showed high rationality (0.962–1.0), indicating the mechanism holds.

### Mechanism 3
- **Claim:** Dual‑agent simulation (subjective + objective) grounds daily activities in behavioral rationality and real‑world authenticity.
- **Mechanism:** The subjective agent proposes human‑like plans conditioned on persona and habits (non‑declarative drivers), while the objective agent enforces physical constraints (travel times, venue availability) via map APIs and calendar checks. This iterative validation ensures activities are both psychologically plausible and physically feasible.
- **Core assumption:** Human behavior emerges from the interplay of internal cognitive states (habits, emotions) and external environmental constraints; simulating both is necessary for realistic data.
- **Evidence anchors:**
  - [section 3.2.3]: "Dual-agent simulation...subjective agent simulates human behavior...objective agent validates...checking for time conflicts, travel times via map APIs, venue availability."
  - [section 3.4.2]: Automated evaluation includes "trip authenticity" (verification via AMap API) and "location authenticity," directly measuring the objective agent’s impact.
  - [corpus]: "AppGen" and "TrajLLM" generate trajectories but lack a dual‑agent verification loop for behavioral rationality.
- **Break condition:** If objective agent feedback is ignored or overridden by subjective agent, resulting activities would violate real‑world constraints (e.g., unrealistic commute times). Trip authenticity score of 0.75 (Table 3) indicates some failures, likely due to API data limits or subjective agent dominance.

## Foundational Learning

- **Declarative vs. Non‑declarative Memory**  
  *Why needed:* LifeBench’s ND category targets skills/habits that aren’t explicitly stated in logs but must be inferred from repeated actions (e.g., "How often do I play badminton?"). Without this cognitive distinction, one cannot design or interpret the benchmark’s question types.  
  *Quick check:* What is the difference between remembering *that* you ran 5km last Tuesday (declarative) and inferring you *usually* run on Tuesdays (non‑declarative)?

- **Partonomic Hierarchy**  
  *Why needed:* The entire scalable synthesis pipeline relies on decomposing a year‑long "plot" into thematic events, then atomic events, then daily activities. Misunderstanding this nesting would prevent grasp of how coherence is maintained across temporal scales.  
  *Quick check:* If a "Career Promotion" thematic event spans April–September, what would be an example of an atomic event within it, and how might it be adjusted by daily contextual factors?

- **Multi‑source Data Integration**  
  *Why needed:* Phone artifacts (SMS, calls, photos, health logs) are fragmented and partial. A memory system must align evidence across sources (e.g., a photo timestamp + SMS mention + health record) to answer questions. This is the core challenge LifeBench poses vs. chat‑only benchmarks.  
  *Quick check:* Given a photo of a cake (timestamp 2025‑04‑12), an SMS saying "I baked a cake" (same day), and a health log showing extra calories, what question could require integrating all three?

## Architecture Onboarding

**Component map:**  
Persona Synthesis → Hierarchical Outline Planning → Daily Activity Simulation → Phone Data Generation → QA Generation

**Critical path:**  
Persona → Yearly Plot → Monthly Thematic Events → Atomic Events → Daily Activities (parallelized in 2‑week blocks) → Phone Artifacts → QA. Dependencies: Daily activities depend on atomic events and persona; phone data depends on daily activities; QA depends on phone data. Parallelization occurs at thematic event decomposition and daily simulation (2‑week blocks).

**Design tradeoffs:**
- *Scalability vs. Coherence:* Parallelization assumes 2‑week activity independence; this risks losing fine‑grained temporal links across the boundary (e.g., a habit spanning weeks). The partonomic hierarchy mitigates this by keeping atomic event constraints.
- *Synthetic fidelity vs. Privacy:* Real‑world priors (maps, surveys) improve authenticity but may embed societal biases (acknowledged in limitations). No real individual data is used, but composites could resemble real people.
- *Dense events vs. Noise:* ~14 events/day and 23 artifacts/day create retrieval challenge but also include noise (irrelevant pushes, ads) simulating real phone clutter. Too much noise could make questions unanswerable; too little reduces realism.

**Failure signatures:**
- Temporal reasoning errors: System retrieves events from wrong month/week when answering TKU questions (e.g., "How many times this year?" includes outdated info).
- Non‑declarative omission: Fails to infer a habit (e.g., weekly badminton) from sparse logs, defaulting to "I don’t know."
- Source misalignment: Cannot connect a photo (visual evidence) to an SMS (textual evidence) about the same event, leading to incomplete multi‑hop answers.
- Hallucination from memory compression: Summarizing memory units introduces details not in source data (e.g., "chili‑garlic water" instead of "laundry detergent water").

**First 3 experiments:**
1. Single‑user simulation validation: Run the full pipeline for 1 user (8 hours). Check: Do manual rationality scores for daily activities exceed 0.95? Does location authenticity via AMap API exceed 0.80?
2. Baseline system probe: Feed raw LifeBench data (without summarization) into a vanilla RAG system. Measure accuracy per category (IE/MR/ND etc.). Expect near‑random on ND and TKU, highlighting the benchmark’s difficulty.
3. Parallelization integrity test: Compare a fully sequential simulation (58h) vs. parallelized (8h) on a subset of questions. Measure divergence in answers caused by the 2‑week independence assumption. Significant divergence indicates coherence breaks.

## Limitations
- Access to real‑world priors (CNSDA surveys, AMap API) may require credentials; substitutes likely lower data quality metrics (e.g., location authenticity < reported 0.83).
- Undisclosed LLM prompts/parameters risk coherence and rationality deviations when reproducing the pipeline.
- The 2‑week parallelization boundary may break long‑range temporal links, introducing coherence errors in non‑declarative patterns.

## Confidence
- Declarative / non‑declarative integration: **High**  
- Partonomic scalability: **Medium**  
- Dual‑agent authenticity: **Medium**

## Next Checks
1. **Parallelization integrity test:** Run a fully sequential vs. parallel simulation on identical seeds for 2 users; measure answer divergence on TKU/ND questions to quantify coherence loss at 2‑week boundaries.
2. **ND category probing:** Evaluate top memory systems (MemU, Hindsight) with ablated non‑declarative questions; if accuracy drops significantly (>15%) only on ND, it confirms the benchmark’s mechanism.
3. **Location authenticity audit:** Sample 100 failures from the 0.25 low‑score trips; classify errors as API data gaps (e.g., venue missing) vs. simulation flaws (e.g., impossible travel) to prioritize fixes.
