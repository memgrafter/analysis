# VisRef: Visual Refocusing while Thinking Improves Test-Time Scaling in Multi-Modal Large Reasoning Models

## Quick Facts
- **arXiv ID:** 2603.00207
- **Source URL:** https://arxiv.org/abs/2603.00207
- **Reference count:** 40
- **Primary result:** VisRef improves accuracy by up to 6.4% absolute over standard thinking under fixed compute budgets, and scales favorably with increased test-time tokens.

## Executive Summary
VisRef addresses a critical degradation in multi-modal large reasoning models (MLRMs): during extended test-time reasoning, models over-rely on textual priors and lose attention to visual tokens, harming performance on vision-dependent tasks. The proposed solution is a training-free, plug-and-play framework that adaptively reinjects a coreset of visual tokens at each reasoning step. Token selection uses Determinantal Point Processes to balance relevance to the current textual reasoning state and diversity among tokens. An entropy-based stopping criterion bounds test-time compute. Evaluated on MathVista, MM-Star, and MathVision with InternVL3.5, Qwen3-VL, and SAIL-VL2, VisRef yields absolute accuracy gains up to 6.4% compared to standard thinking and scales favorably with increased token budgets. The method is orthogonal to RL-based fine-tuning and requires no additional training.

## Method Summary
VisRef operates in a model’s “thinking” mode, where textual reasoning traces are generated step by step. At step \(k\), it constructs a projection matrix \(M_k\) from the text tokens generated so far: \(M_k = \sum_{j} z_{k}^{(j)} (z_{k}^{(j)})^T\), where \(z_k^{(j)}\) are token embeddings. Visual tokens \(V\) are projected into this textual subspace via a kernel \(L_k(i,j) = v_i^T M_k v_j\). A coreset \(V_k\) of size \(m = \lfloor 0.3 |V| \rfloor\) is selected by greedily maximizing \(\log \det(L_{V_k})\) (determinantal point process), promoting diverse and relevant tokens. The selected tokens are reinjected into the context, and the next reasoning step is generated. The loop continues until the entropy of the answer distribution \(H_k = -\mathbb{E}_y[\log \pi(y|x,\tau_{1:k})]\) falls below \(\delta_{\text{entropy}} = 0.25\) or \(K_{\text{max}} = 10\) steps is reached. This periodic visual refocusing counters the drift toward textual priors.

## Key Results
- Absolute accuracy improvements of up to 6.4% on MathVista, MM-Star, and MathVision with InternVL3.5, Qwen3-VL, and SAIL-VL2 under fixed compute budgets.
- Favorable test-time scaling: performance consistently improves with increased token budgets and outperforms parallel thinking.
- Training-free, plug-and-play, and complementary to reinforcement learning fine-tuning.

## Why This Works (Mechanism)
VisRef mitigates the model’s tendency to forget visual details during extended reasoning by periodically reintroducing visual evidence. The DPP-based selection ensures the reinjected tokens are both relevant to the current reasoning state (via the \(M_k\) projection) and diverse, maximizing information gain per token. The entropy stopping criterion prevents wasteful overthinking by terminating when the answer distribution becomes sufficiently confident. Together, these components maintain visual grounding throughout the reasoning process, leading to better performance on tasks requiring tight integration of视觉 and textual information.

No; without visual refocusing it may degrade due to visual grounding loss.
- **Multi-modal large reasoning models (MLRMs)**: Models that generate intermediate reasoning traces conditioned on images and text. *Why needed*: VisRef specifically targets MLRMs with a thinking mode. *Quick check*: Can a standard VQA model without explicit reasoning benefit? Not directly; the method requires textual reasoning traces.
- **Visual grounding**: Aligning textual reasoning with relevant image regions. *Why needed*: Degradation of visual grounding is the core problem. *Quick check*: Do models attend to image tokens less as reasoning length increases? Yes, as shown in the paper.
- **Determinantal Point Processes (DPPs)**: Probabilistic model for diverse subset selection. *Why needed*: To select a diverse yet relevant coreset of visual tokens. *Quick check*: Would random selection work as well? Ablations show DPP provides clear gains.
- **Entropy-based stopping**: Using answer distribution entropy to decide when to stop reasoning. *Why needed*: To bound compute and avoid overthinking. *Quick check*: Is a fixed step count less efficient? Yes; entropy adapts to task difficulty.
- **Reasoning traces**: Step-by-step textual output before final answer. *Why needed*: VisRef uses these tokens to compute \(M_k\). *Quick check*: Can the method work without explicit reasoning traces? No; it relies on textual token embeddings.

## Architecture Onboarding
**Component map:**  
Input (image + prompt) → Vision Encoder → Visual tokens \(V\) → MLRM (thinking mode) generates reasoning trace \(\tau_{1:k}\) → Extract text token embeddings → Compute \(M_k\) → Kernel \(L_k(v_i,v_j)=v_i^T M_k v_j\) → DPP greedy selection → Coreset \(V_k\) → Reinject \(V_k\) into context → Next reasoning step (loop) → Entropy estimator → Stop? → Final answer.

**Critical path:** The core loop comprises: (1) generating a reasoning step, (2) projecting visual tokens via \(M_k\), (3) selecting tokens via DPP, (4) reinjecting them, and (5) checking entropy. The loop iterates until stopping.

**Design tradeoffs:**
- Coreset size \(m\): Larger \(m\) provides more visual information but increases context length and latency; smaller \(m\) may miss crucial details. Paper uses \(m = 0.3|V|\).
- DPP selection: Greedy approximation is efficient (O(\(m^2 |V|\))) but suboptimal; exact DPP is NP-hard. Greedy yields near-optimal diversity in practice.
- Entropy estimation: Requires multiple answer samples to be reliable; more samples improve accuracy but increase compute. The paper samples multiple candidates per step.
- Stopping threshold \(\delta_{\text{entropy}}\): Lower values lead to longer reasoning (more compute) but higher confidence; higher values may stop prematurely. Default 0.25.

**Failure signatures:**
- DPP fails due to non-positive-definite \(L_k\): leads to negative/zero determinants and selection crashes. Diagnostic: check eigenvalues of \(L_k\); add small jitter (e.g., \(10^{-4}I\)) if needed.
- Entropy never drops below threshold: reasoning may loop until \(K_{\text{max}}\) without converging, wasting compute. Diagnostic: plot \(H_k\) over steps; adjust threshold if necessary.
- Context overflow: reinjection increases context length excessively, causing memory errors or slowed generation. Diagnostic: monitor context length; ensure \(m\) is moderate relative to model limits.
- No improvement over baseline: if visual tokens are already well-retained or \(M_k\) poorly captures reasoning, reinjection may not help.

**Exactly 3 first experiments:**
1. **Baseline replication**: Run standard thinking (no reinjection) on MathVista testmini with InternVL3.5-8B, record accuracy and average steps.
2. **VisRef verification**: Implement VisRef with default parameters (\(m=0.3|V|\), \(K_{\text{max}}=10\), \(\delta_{\text{entropy}}=0.25\)) and reproduce the reported gain on MathVista.
3. **Ablation - DPP necessity**: Replace DPP selection with random selection of \(m\) visual tokens; measure accuracy drop to isolate the effect of diversity.

## Limitations
- Implementation details for computing \(M_k^{1/2}\) and estimating entropy are unspecified, leading to potential instability and need for heuristics (e.g., matrix jitter, sample count choices).
- DPP selection can fail when the reasoning trace is very short, making \(M_k\) rank-deficient and causing numerical issues.
- Evaluation is limited to three benchmarks and three models, restricting generalizability; the causal link between reinjection and improved visual grounding lacks direct verification (e.g., attention analysis).

## Confidence
- **Method description:** High (algorithm is clearly specified aside from minor implementation details)
- **Empirical gains:** Medium (validated on multiple models but limited benchmark diversity)
- **Scalability:** Medium (shows favorable scaling with token budget, but compute cost and latency trade-offs not deeply analyzed)
