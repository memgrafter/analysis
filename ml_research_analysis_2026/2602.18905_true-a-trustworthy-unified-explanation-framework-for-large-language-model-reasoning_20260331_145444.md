# TRUE: A Trustworthy Unified Explanation Framework for Large Language Model Reasoning

## Quick Facts
- **ArXiv ID:** 2602.18905
- **Source URL:** https://arxiv.org/abs/2602.18905
- **Reference count:** 8
- **Primary result:** TRUE enables multi-level trustworthy LLM reasoning explanations via executable verification, local stability modeling, and causal failure attribution, showing high consistency on numerical tasks and robust failure mode identification.

## Executive Summary
This paper introduces TRUE, a framework to generate trustworthy, structural explanations for LLM reasoning. It redefines explanations as executable specifications verified through blind execution, models local reasoning stability via feasible-region DAGs built from structure-preserving perturbations, and identifies class-level failure modes using counterfactual interventions and Shapley value attribution. Results demonstrate that executable explanations achieve over 90% consistency on numerical benchmarks (GSM8K, MATH) but drop on knowledge/logic tasks (MMLU, BBH). The perturbation-based DAG drastically improves success rate prediction (∼80% cross-entropy reduction), and Shapley analysis reliably pinpoints dominant structural weaknesses even with small samples (n≈20).

## Method Summary
TRUE operates at three levels. At the instance level, it treats reasoning traces as executable procedures: an LLM generates step-by-step reasoning, and a separate blind executor (without access to the original problem) attempts to produce the final answer from those steps alone; consistency measures trustworthiness. Locally, for a given problem, structure-preserving perturbations generate semantically similar inputs; aggregating reasoning traces across these neighbors yields a feasible-region DAG that encodes the stable reasoning manifold. At the class level, samples are clustered, failure modes are abstracted from incorrect traces, counterfactual samples are generated by injecting/removing these modes, and Shapley values quantify each mode’s causal impact on accuracy.

## Key Results
- Executable consistency (EC) exceeds 90% on GSM8K and MATH but falls to ∼86.8% on MMLU and ∼73.2% on BBH.
- Feasible-region DAG construction reduces success-rate prediction cross-entropy by ∼80% on MATH compared to a CoT-sampling baseline.
- Counterfactual Shapley analysis identifies stable, dominant failure modes (e.g., date miscalculation, percentage confusion) with ranking consistency (Kendall τ > 0.8) for cluster sizes as small as n≈20.

## Why This Works (Mechanism)

### Mechanism 1: Executable Verification via Blind Execution
- **Claim:** Framing explanations as executable specifications and verifying them via blind execution provides a trustworthy, instance-level check on whether the reasoning trace encodes a complete, self-contained solution procedure.
- **Mechanism:** The LLM generates a step-by-step reasoning trace *E*. An independent executor *V*, without access to the original problem *x*, attempts to produce the final answer ŷ = *V*(*E*). If ŷ is correct, the explanation is deemed trustworthy because it contains sufficient operational information to function as a standalone solution.
- **Core assumption:** A reasoning trace that leads to the correct answer when executed in isolation likely reflects a valid reasoning structure, not a post-hoc rationalization.
- **Evidence anchors:** Abstract, Section 3.1 formalization of executable explanation and blind executor protocol.
- **Break condition:** If blind execution frequently fails to recover correct answers from traces that originally produced correct predictions (low EC), the mechanism indicates explanations are not self-contained procedural specifications but rely on implicit context from *x*.

### Mechanism 2: Local Stability via Feasible-Region DAG
- **Claim:** Constructing a feasible-region DAG from structure-preserving perturbations characterizes the local stability and executability of the reasoning process for a neighborhood of semantically similar inputs.
- **Mechanism:** For an anchor instance *x*, generate perturbed instances *N(x)* that preserve the underlying solution structure. Execute the model on all *N(x)* to collect reasoning steps. Aggregate steps into a DAG where nodes are merged reasoning steps (weighted by semantic correctness and execution success rate) and edges encode observed dependencies. This graph represents the space of valid reasoning trajectories near *x*.
- **Core assumption:** The reasoning structure for a problem class is locally smooth; semantically similar inputs will trigger variations of a common core reasoning DAG.
- **Evidence anchors:** Abstract, Section 3.2 detailing *N(x)* construction, step reliability weight *Wᵢ*, and DAG formation *G* = (*S*, *E*).
- **Break condition:** If trajectory coverage (GT Match, Pret Match) remains low even under aggressive perturbations, the DAG fails to capture the actual reasoning space, suggesting high structural variability or that perturbations did not preserve the reasoning pattern.

### Mechanism 3: Failure Mode Attribution via Counterfactuals and Shapley
- **Claim:** Cluster-level failure mode analysis using counterfactual perturbations and Shapley value attribution identifies recurring structural weaknesses and quantifies their causal influence on prediction errors.
- **Mechanism:** Group semantically similar samples into clusters *C*. Automatically discover minimal failure modes *fᵢ* (structural conditions present in incorrect reasoning). Generate counterfactual samples by injecting/removing these modes. Evaluate model performance on augmented set *C’*. Compute Shapley values ϕᵢ from the characteristic function *v*(*S*) (prediction correctness under failure set *S*) to quantify each mode’s marginal impact.
- **Core assumption:** Systematic failures arise from a small set of recurring structural deficiencies in the model’s reasoning process, whose effects can be isolated and measured via controlled interventions.
- **Evidence anchors:** Abstract, Section 3.3 pipeline: failure mode discovery, counterfactual generation, Shapley computation (Equation 11).
- **Break condition:** If Shapley importance rankings are unstable across subsamples (low Kendall τ) or identified modes show low causal impact (ϕᵢ ≈ 0), the assumed failure patterns may not be causally significant or are not consistently present.

## Foundational Learning
- **Concept: Executable Verification**
  - **Why needed:** To distinguish between superficially plausible reasoning traces and those that encode a complete, self-sufficient solution procedure. Without this, explanations could be post-hoc justifications.
  - **Quick check:** If given only the step-by-step explanation (no original question), can an external executor reliably produce the correct final answer?
- **Concept: Structure-Preserving Perturbation**
  - **Why needed:** To explore the local neighborhood of an input while maintaining the core reasoning structure, allowing assessment of stability without conflating it with problem-type changes.
  - **Quick check:** Does the perturbed instance require the same high-level reasoning approach (e.g., "set up equation, solve, interpret") as the original, even if numbers or entities change?
- **Concept: Shapley Value Attribution for Failure Modes**
  - **Why needed:** To move beyond correlation and quantify the *causal* contribution of each discovered failure mode to overall prediction errors across a problem class.
  - **Quick check:** If we could perfectly eliminate one failure mode across all samples, by how much would the class-level accuracy improve (marginal contribution)?

## Architecture Onboarding
- **Component map:** Explanation Generator (LLM with CoT/Plan-and-Solve prompts) produces reasoning trace *E*. Blind Executor (LLM + white-box tools) consumes *E* to predict ŷ. Perturbation Engine (LLM-assisted) generates *N(x)*. DAG Constructor aggregates steps over *N(x)* into weighted DAG *G*. Failure Discovery Module (LLM-assisted) proposes candidate failure modes *fᵢ*. Counterfactual Generator injects/removes *fᵢ* to create augmented cluster *C’*. Shapley Attribution computes ϕᵢ from model performance on *C’*.
- **Critical path:** Primary instance-level flow: *x* → generate *E* → blind execute *E* → compute EC. Parallel local branch: *x* → generate *N(x)* → execute all → build DAG *G*. Cluster-level branch: group *C* → discover *F* → generate *C’* → evaluate → compute Shapley ϕ.
- **Design tradeoffs:**
  - Perturbation diversity vs. structural fidelity: More aggressive perturbations increase DAG coverage but risk altering the core reasoning pattern, invalidating the local smoothness assumption.
  - Faithfulness vs. executability: Requiring explanations to be fully executable (no hidden reliance on *x*) may reduce OA but increases EC and trustworthiness.
  - Sample efficiency vs. stability: Shapley values are computationally expensive; subsampling improves efficiency but may reduce reliability of ϕᵢ rankings for small *n*.
- **Failure signatures:**
  - Low EC (<90% on simple numerical tasks) suggests explanations are not self-contained procedures.
  - DAG trajectory coverage (Pret%/GT%) plateaus at low percentages (<60%) even with aggressive perturbations, indicating high reasoning variability or poor perturbation strategy.
  - Shapley rankings (Kendall τ) drop sharply for *n* < 20, implying failure mode identification is not sample-efficient for that cluster.
- **First 3 experiments:**
  1. Executable Consistency (EC) Benchmark: Run E3 evaluation on GSM8K/MATH vs. MMLU/BBH to validate executable explanation consistency across task types.
  2. DAG Predictive Power Test: Construct feasible-region DAGs for MATH/MMLU-CF clusters and measure cross-entropy reduction against a baseline CoT-sampler predictor.
  3. Subsampling Stability Analysis: For GSM8K/BBH clusters, vary cluster size *n* ∈ {5,10,20,40} and plot Jaccard/Kendall metrics to determine sample size needed for stable failure mode discovery.

## Open Questions the Paper Calls Out
- What specific properties of knowledge/logic tasks cause lower executable consistency (EC) compared to numerical tasks?
- Does reliance on an LLM to generate perturbations bias the feasible-region DAG’s structural coverage?
- How do the computational cost and stability of Shapley-based failure mode attribution scale with larger cluster sizes or more failure modes?
- Are the discovered failure modes model-agnostic, or specific to the GPT family used in experiments?

## Limitations
- Prompt templates for explanation generation, perturbation, and failure abstraction are not provided, impeding exact replication.
- The precise definition and parameter bounds of "structure-preserving perturbations" are unspecified; perturbations may unintentionally alter reasoning structure.
- The analysis relies on small cluster sizes for stability claims (*n*≈20); confidence in generalizability is limited.

## Confidence
- **Instance-level executable verification (Mechanism 1): Medium** – EC >90% on numerical tasks demonstrates promise, but lower consistency on knowledge/logic tasks and lack of prompt details reduce certainty.
- **Local feasible-region DAG (Mechanism 2): High** – Large (~80%) cross-entropy reduction and high trajectory coverage indicate a robust signal likely reproducible despite missing perturbation specifics.
- **Cluster-level failure mode attribution (Mechanism 3): Medium** – Stable Shapley rankings at *n*≈20 are encouraging, yet dependence on LLM-generated abstractions and absence of alternative baselines temper confidence.
