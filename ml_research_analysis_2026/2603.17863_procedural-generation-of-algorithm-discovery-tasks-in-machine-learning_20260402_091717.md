# Procedural Generation of Algorithm Discovery Tasks in Machine Learning

## Quick Facts
- **arXiv ID:** 2603.17863
- **Source URL:** https://arxiv.org/abs/2603.17863
- **Reference count:** 40
- **Primary result:** DiscoGen generates ~100 billion diverse algorithm discovery tasks with a hidden meta-test split, enabling scalable prompt optimization that improves LLM performance as task diversity increases.

## Executive Summary
This paper presents DiscoGen, a procedural generator for machine learning algorithm discovery tasks that creates a vast space of ~100 billion distinct tasks by combining configurable parameters across multiple domains. A key innovation is the strict separation of meta-train and hidden meta-test datasets, which prevents data contamination during prompt engineering or model evaluation. The authors introduce DiscoBench, a standardized subset for assessing agent performance. Experiments with open-source LLMs using the MLGym agent framework demonstrate significant performance differences between simpler single-module tasks (80% success) and more complex all-module tasks (25.7% success). Furthermore, prompt optimization performance scales with the number of diverse training tasks, with meta-test Elo improving from 957 to 1071 as the training set size increases from 1 to 30 tasks. This work provides a foundation for sustainable, contamination-resistant research in algorithm discovery.

## Method Summary
DiscoGen procedurally generates tasks by defining a parameterized schema for machine learning pipelines (e.g., data types, model architectures, optimization objectives). Each instantiated task includes a unique meta-train split for development and a hidden meta-test split for final evaluation, ensuring no overlap. DiscoBench curates a representative subset of these tasks for standardized benchmarking. The MLGym agent framework is employed to interface LLMs with these tasks, executing code, observing outcomes, and iterating toward solutions. Performance is measured by task success rates and, for prompt optimization, by Elo ratings on the hidden meta-test set across varying amounts of diverse training tasks.

## Key Results
- DiscoGen's combinatorial parameter space yields approximately 100 billion unique tasks.
- LLM success rates vary sharply by complexity: 80% on single-module tasks vs. 25.7% on all-module tasks.
- Prompt optimization gains scale with training task diversity (Ktasks), improving meta-test Elo from 957 (K=1) to 1071 (K=30).

## Why This Works (Mechanism)
The hidden meta-test split effectively prevents data contamination by ensuring evaluation tasks are never exposed during prompt engineering, training, or hyperparameter tuning. This design enforces a principled evaluation regime where performance reflects genuine generalization to unseen algorithm discovery problems rather than overfitting to known benchmarks.

## Foundational Learning
- **Procedural Generation**: Creates tasks algorithmically from parameter spaces; needed for massive scale and diversity. *Quick check:* Sample tasks and verify no duplicates via hash or parameter vector comparison.
- **Meta-Train/Test Split**: Separates development and held-out evaluation data; critical for unbiased assessment. *Quick check:* Audit agent logs to confirm no access to meta-test during optimization.
- **Algorithm Discovery**: Automated design of machine learning pipelines; the core research objective. *Quick check:* Define clear, executable success criteria per task (e.g., accuracy threshold).
- **Prompt Optimization**: Iterative refinement of LLM prompts for a task distribution; improves robustness. *Quick check:* Run ablations with random or human-written prompts on a fixed validation set.
- **Task Diversity**: Variation in task instances; reduces risk of overfitting to spurious correlations. *Quick check:* Compute pairwise similarity metrics (e.g., code AST distance) among generated tasks.
- **LLM Evaluation**: Assessing large language models on complex, multi-step problems; measures reasoning and coding ability. *Quick check:* Compare LLM success rates against simple heuristic baselines or random search.

## Architecture Onboarding
Component Map: Parameter Space Configurator -> Task Generator -> Dataset Splitter -> Meta-Train Repository / Hidden Meta-Test Vault -> MLGym Agent (with Prompt Optimizer) -> Evaluator

Critical Path: Configure global parameter bounds -> Generate task instance -> Split into meta-train and hidden meta-test -> Agent explores meta-train, optimizes prompts -> Final evaluation on hidden meta-test produces score.

Design Tradeoffs: Scale vs. Semantic Diversity – combinatorial expansion may yield redundant tasks; secrecy vs. Reproducibility – hidden meta-test ensures fairness but limits external verification; Generality vs. Domain Specificity – broad parameter coverage may dilute focus on any single ML subfield.

Failure Signatures: Parameter collisions creating near-identical tasks; accidental meta-test leakage via prompt logs or agent memory; agent converging on meta-train without generalizing; task generation producing unsolvable or ill-defined instances.

First Experiments: 1) Compare LLM success rates on single-module vs. all-module tasks to validate complexity gradient. 2) Plot meta-test Elo vs. Ktasks to confirm scaling trend. 3) Attempt to reconstruct any meta-test task using only public generator and meta-train data to test contamination safeguards.

## Open Questions the Paper Calls Out
The paper does not explicitly call out any open questions. However, the identified limitations and suggested next checks point to several important research directions:
- How diverse is the semantic space of the ~100 billion generated tasks in practice?
- Can the hidden meta-test secrecy be maintained in open research environments where prompts and code are shared?
- Do the observed performance patterns generalize to other agent frameworks and closed-source models?
- Does prompt optimization continue to scale beyond Ktasks=30, and how does it behave with different task pools?

## Limitations
- The claimed "~100 billion tasks" relies on parameter combinatorics; empirical verification of semantic diversity and difficulty distribution is absent.
- Efficacy of the hidden meta-test split assumes perfect operational secrecy, which is challenging in open research environments with shared prompts and code.
- LLM evaluation is restricted to open-source models using the MLGym agent; results may not generalize to other agent architectures, closed-source models, or human experts.
- Scaling benefits in prompt optimization are demonstrated only up to Ktasks=30; extrapolation to larger or different task pools remains uncertain.
