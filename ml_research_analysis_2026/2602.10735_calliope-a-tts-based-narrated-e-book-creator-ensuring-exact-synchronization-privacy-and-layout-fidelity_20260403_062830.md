# Calliope: A TTS-based Narrated E-book Creator Ensuring Exact Synchronization, Privacy, and Layout Fidelity

## Quick Facts
*   **arXiv ID:** 2602.10735
*   **Source URL:** https://arxiv.org/abs/2602.10735
*   **Reference Count:** 22
*   **Primary Result:** An open-source framework that generates narrated EPUB 3 e-books with exact, drift-free audio-text synchronization by capturing timestamps directly during TTS, while surgically preserving the publisher's original layout and operating entirely offline.

## Executive Summary
Calliope is an open-source system that converts standard EPUB e-books into narrated EPUB 3 files with Media Overlays. It addresses a key gap in existing tools by ensuring **exact, drift-free synchronization** between highlighted text and audio playback. This is achieved by generating audio per sentence and deriving timestamps deterministically from the concatenated audio stream, rather than relying on error-prone forced alignment. The framework preserves the original book's typography and styling by surgically injecting synchronization anchors into the EPUB's XHTML structure. Furthermore, by using local open-source TTS models (XTTS-v2, Chatterbox), the entire pipeline runs offline, eliminating API costs, privacy risks, and copyright issues associated with cloud services.

## Method Summary
The pipeline operates in three phases. **Phase 1 (Extraction/Preservation):** The EPUB is parsed, its DOM traversed to identify block-level text containers, and original text is replaced *in-place* with segmented sentences wrapped in uniquely identified `<span>` tags. **Phase 2 (TTS/Synchronization):** Each sentence is synthesized using a local TTS model (XTTS-v2 or Chatterbox) with a provided reference voice embedding. The system handles model context limits via recursive splitting. Each audio segment is processed with a fade-out and 0.15s silence padding before concatenation. Timestamps (`t_start`, `t_end`) are calculated cumulatively from the concatenated stream to ensure gapless highlighting. **Phase 3 (Packaging):** SMIL synchronization files are generated mapping text IDs to audio clips, the EPUB's OPF manifest is updated with media overlay metadata, and the modified files are repackaged into a final EPUB 3.

## Key Results
*   Calliope achieved **zero synchronization drift** in evaluation, while forced alignment methods introduced significant drift (up to 34.91 seconds for Storyteller, mean -1.11s for Syncabook).
*   The surgical modification approach **preserved original publisher styling** (typography, CSS, embedded media) by only injecting structural anchors into existing XHTML elements.
*   The offline, local TTS-based design **eliminates API costs, privacy concerns, and copyright compliance issues** inherent in cloud-based narration services.

## Why This Works (Mechanism)

### Mechanism 1: Exact Synchronization via Direct Timestamping
*   **Claim:** Exact synchronization between text highlighting and audio is achieved without drift.
*   **Mechanism:** Timestamps are derived deterministically from the concatenated audio stream generated by the TTS engine. Each sentence’s audio segment is processed and concatenated; `t_start` is the cumulative sum of prior segment durations (including padding), and `t_end` is set to the next segment’s `t_start` (gapless continuity).
*   **Core assumption:** The TTS engine provides accurate per-segment duration measurements.
*   **Evidence anchors:** Abstract states timestamps are "captured directly during TTS"; Section 4.2.1 details the timestamp calculation (Equations 5-6) and gapless design.
*   **Break condition:** TTS model does not output interim duration data or produces inconsistent segment lengths due to internal state carry-over.

### Mechanism 2: Layout Preservation via Surgical DOM Injection
*   **Claim:** The publisher's original typography, styling, and embedded media are preserved.
*   **Mechanism:** The EPUB’s DOM is traversed to identify block-level text containers. Original text is replaced *in-place* with segmented text wrapped in `<span>` elements bearing unique IDs. No CSS or layout files are modified; only structural anchors are injected within existing elements.
*   **Core assumption:** EPUB content documents (XHTML) are well-formed and use nested block elements that can safely host new `<span>` children.
*   **Evidence anchors:** Abstract mentions "surgical modifications"; Section 4.1 describes DOM traversal and anchor injection within parent elements.
*   **Break condition:** Source EPUB uses malformed XHTML, non-standard CSS targeting direct text nodes, or scripting dependent on original text node positions.

### Mechanism 3: Offline Operation via Local TTS
*   **Claim:** The pipeline operates offline, eliminating API costs, privacy risks, and copyright compliance issues.
*   **Mechanism:** All audio synthesis uses local, open-source TTS models (XTTS-v2, Chatterbox) executed on the user's machine. No network calls are made; all inputs and outputs remain on-device.
*   **Core assumption:** Open-source TTS models can achieve sufficient quality for narrated e-books without cloud-based APIs.
*   **Evidence anchors:** Abstract explicitly states offline capability eliminates costs and privacy concerns; Section 5 details local environment setup with no cloud dependencies.
*   **Break condition:** Required TTS models are only available via commercial APIs or hardware constraints prevent local execution.

## Architecture Onboarding
*   **Component map:** EPUB Parser (EbookLib) -> DOM Processor (BeautifulSoup4) -> Text Normalizer & Segmenter -> TTS Engine Wrapper (XTTS-v2/Chatterbox) -> Timestamp Calculator -> SMIL Generator -> OPF Updater -> Packager
*   **Critical path:** EPUB input -> DOM traversal + span injection -> Sentence segmentation -> TTS synthesis (with error handling) -> Audio concatenation + timestamp calc -> SMIL generation -> OPF/manifest update -> ZIP packaging.
*   **Design tradeoffs:**
  *   Synchronization accuracy vs. TTS quality: Direct timestamps guarantee sync but per-sentence synthesis may harm prosody continuity; silence padding (δ) mitigates clicks but introduces small pauses.
  *   Layout preservation vs. structural robustness: Surgical DOM injection assumes well-formed EPUBs; malformed sources may break highlighting.
  *   Offline privacy vs. hardware cost: Local TTS avoids cloud costs but requires a decent GPU for speed; quantized models for mobile would trade quality for efficiency.
*   **Failure signatures:**
  *   **TTS failure:** Recursive splitting fails to resolve token overflow → segment produces no audio or crashes.
  *   **SMIL validation error:** Gaps/overlaps in `[t_start, t_end]` intervals cause reading systems to reject overlay.
  *   **Layout corruption:** CSS selectors in original EPUB target specific node positions; injected spans alter DOM tree, causing styling to misapply.
  *   **Audio artifact:** Inadequate fade-out/silence padding causes clicks or unnatural pauses between sentences.
*   **First 3 experiments:**
  1.  **Synchronization drift measurement:** Run Calliope on a test EPUB; extract SMIL timestamps. Use forced alignment (Syncabook/Storyteller) on same audio; compute per-sentence drift (expected: Calliope mean=0, forced alignment mean ≠ 0, P90 drift >50ms).
  2.  **Layout fidelity check:** Compare original EPUB CSS/rendering vs. Calliope output in a reference reader (Thorium). Use visual regression testing on key pages; check that injected `<span>` elements do not alter computed styles, font sizes, or image positions.
  3.  **Privacy/offline validation:** Monitor network traffic during pipeline execution; ensure zero external connections. Verify all file operations are local; check that no voice sample or EPUB content is uploaded.

## Limitations
*   Segmentation thresholds (λ+, λ-) and padding (δ) are likely hardcoded, not user-configurable.
*   Exact dependency versions (torch, transformers, EbookLib) are not pinned, risking environment replication issues.
*   Evaluation corpus size and diversity (e.g., non-English EPUBs, illustrated books) are unclear.

## Confidence
*   **Exact Synchronization:** High – Mechanism is deterministic; timestamps derived directly from TTS-generated audio durations.
*   **Layout Fidelity:** Medium – Relies on well-formed XHTML and standard CSS; break conditions exist for malformed or non-standard EPUBs.
*   **Offline Operation:** High – Explicitly uses local open-source models with no cloud dependencies in the design and implementation.
