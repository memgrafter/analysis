# MeGU: Machine-Guided Unlearning with Target Feature Disentanglement

## Quick Facts
- **ArXiv ID:** 2602.17088
- **Source URL:** https://arxiv.org/abs/2602.17088
- **Reference count:** 35
- **Primary result:** Matches retrain-level retain accuracy, reduces membership inference attack success by up to 79% vs. SSD, and cuts unlearning time by >59% versus full retraining.

## Executive Summary
Machine unlearning seeks to erase the influence of specific data from a trained model while maintaining utility on retained data, but suffers from a trade-off between aggressive forgetting and performance preservation. MeGU addresses this by leveraging zero-shot multimodal LLMs to semantically realign target data via perturbing labels and introducing a positive-negative feature noise pair to disentangle target-specific patterns from shared structures. Evaluated on CIFAR datasets for class-wise, sub-class, and random unlearning, MeGU consistently achieves retain accuracy within 0.35% of a retrained model, drastically lowers membership inference attack success, and significantly reduces computational overhead compared to full retraining.

## Method Summary
MeGU employs a two-stage pipeline. First, it queries a zero-shot multimodal LLM on a small exemplar subset to estimate inter-concept similarities, constructing a transition matrix. This matrix, combined with the model's logits on forget data, assigns instance-specific perturbing labels that are semantically distinct yet related to original concepts. Second, it generates per-class positive noise (aligned with perturbing labels) and negative noise (opposing original labels) from the frozen pretrained model. These noises are weighted and added to forget inputs, creating a perturbed dataset. Finally, the model is finetuned for a few epochs on this perturbed forget set alongside the retain set, shifting decision boundaries for target data while preserving shared features for retained classes.

## Key Results
- Retain accuracy within 0.35% of retrain on CIFAR-20 with ViT backbone.
- Membership inference attack success reduced by up to 79% compared to SSD.
- Unlearning time decreased by more than 59% relative to full retraining.

## Why This Works (Mechanism)
### Mechanism 1: MLLM-Guided Perturbing Label Assignment
A zero-shot MLLM estimates semantic similarities between concepts on a small exemplar set, encoding them into a transition matrix. For each forget instance, this matrix combines with the model's original prediction to assign a perturbing label that is semantically distinct, steering unlearning toward a new concept space without random labels. This relies on the MLLM's robust, human-like understanding of relationships; failure occurs if the MLLM is biased or inconsistent, leading to misaligned labels.

### Mechanism 2: Positive-Negative Feature Noise Pair
From the frozen model, negative noise (maximizing loss on original label) suppresses target-specific feature patterns, while positive noise (minimizing loss on perturbing label) reinforces features associated with the new concept. Their weighted combination disentangles unique target features from shared ones during finetuning. This assumes feature spaces can be decomposed into separable unique and shared patterns; if entanglement is too intricate, the noise may fail to isolate components, causing collateral forgetting.

### Mechanism 3: Coordinated Finetuning for Selective Boundary Shift
Joint finetuning on the perturbed forget set (with added noise) and retain set adjusts decision boundaries by learning mappings from disentangled inputs to new labels. The transition matrix ensures perturbing labels are instance-appropriate, avoiding overfitting. This leverages the malleability of model boundaries; however, with over-parameterization or poor noise weighting, finetuning may either under-unlearn or catastrophically forget retained knowledge.

## Architecture Onboarding
**Component map:**  
Pretrained classification model (ResNet18/ViT) -> Zero-shot MLLM (MMICL) -> Transition matrix T -> Feature noise generators (N_pos, N_neg) -> Finetuning module (optimizer on Dr ∪ Dp_f)

**Critical path:**  
1. Extract exemplars D_ex (10 images per class) from training data.  
2. Query MLLM on D_ex to compute per-instance similarities S_kl and build transition matrix T.  
3. For each forget sample, compute R_i = T · (I_yi · p_θ(x_i)) and assign perturbing label y_p_i via top-τ selection.  
4. Generate N_pos and N_neg per class by optimizing frozen model (minimize loss on y_p, maximize on y_i).  
5. Construct perturbed forget set Dp_f = {(x_i + αN_pos + (1-α)N_neg, y_p_i)}.  
6. Finetune pretrained model on Dp_f ∪ D_r for few epochs (e.g., 3 for ResNet18, 5 for ViT).

**Design tradeoffs:**  
- MLLM guidance vs. compute: Small D_ex (10/class) balances cost; precomputing T amortizes cost.  
- α control: Higher α (e.g., 0.7) emphasizes positive noise, better retaining performance but risking under-unlearning; lower α risks over-unlearning.  
- τ selection: Smaller τ (e.g., 0.3) yields semantically closer perturbing labels, preserving more features; larger τ may cause distribution shift.

**Failure signatures:**  
- Under-unlearning: High forget accuracy (Af near baseline) and high MIA score.  
- Over-unlearning: Significant drop in retain accuracy (Ar << retrain).  
- MLLM misguidance: Imbalanced perturbing label distribution; verify via histogram checks.

**First 3 experiments:**  
1. Class-wise unlearning on CIFAR-100 (forget entire classes like 'rocket') to validate against SOTA.  
2. Sub-class unlearning on CIFAR-20 (forget subclasses within superclasses) to stress-test disentanglement on entangled features.  
3. Random unlearning on CIFAR-10 (forget random instance subset) to assess robustness when forget/retain sets share classes.

## Open Questions the Paper Calls Out
- **Open Question 1:** How does the degree of feature-pattern entanglement between target and retained concepts quantitatively determine the unlearning-utility trade-off? The paper posits entanglement as fundamental but lacks a formal metric or empirical quantification across class pairs.  
- **Open Question 2:** To what extent can the computational overhead of MLLM-based guidance be reduced (e.g., via distillation or caching) without compromising unlearning quality? The paper acknowledges cost issues but doesn't evaluate alternative strategies like smaller MLLMs or feature-based similarity.  
- **Open Question 3:** Do the semantic biases inherent in the MLLM propagate into the unlearned model via perturbing label assignment? The paper assumes unbiased MLLM understanding but doesn't audit for societal biases or fairness impacts on retained predictions.  
- **Open Question 4:** How does the positive-negative feature noise pair interact with different model architectures and training paradigms (e.g., CNN vs. transformer, supervised vs. self-supervised)? Evaluations are limited to ResNet18 and ViT on CIFAR; generalizability to other architectures or modalities is untested.

## Limitations
- MLLM similarity estimation depends on prompt engineering and model choice, introducing potential bias.  
- Noise generation details (optimizer steps, regularization) are underspecified, hindering exact replication.  
- Assumption of separable unique/shared features may fail for highly entangled concepts; experiments only on CIFAR datasets.

## Confidence
- MLLM-guided label perturbation: Medium (ablations support but external model dependency).  
- Feature noise disentanglement: Medium (theoretically sound, limited direct feature evidence).  
- Overall unlearning performance: High (consistent across tasks, matches retrain, lowers MIA).
