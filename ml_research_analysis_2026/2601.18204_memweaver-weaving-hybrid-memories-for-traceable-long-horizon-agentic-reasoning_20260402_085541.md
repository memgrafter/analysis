# MemWeaver: Weaving Hybrid Memories for Traceable Long-Horizon Agentic Reasoning

## Quick Facts

- **ArXiv ID**: 2601.18204  
- **Source URL**: https://arxiv.org/abs/2601.18204  
- **Reference count**: 40  
- **Primary result**: MemWeaver raises Temporal F1 from 38.77 to 50.83 and Multi-Hop F1 from 24.35 to 26.00 with GPT-4o-mini while compressing context by >95% to ~1K tokens.

## Executive Summary

Long-horizon conversational agents require memory systems that maintain temporal consistency, support multi-hop reasoning, and provide evidence traceability across many sessions. Existing retrieval or summarization-based approaches fail due to temporal conflicts, brittle reasoning, and poor grounding. MemWeaver introduces a consolidation-centric tri-layer framework: (1) a temporally grounded knowledge graph for structured relational and time-aware reasoning, (2) an experience memory that abstracts reusable patterns from clustered interactions, and (3) a passage memory preserving raw textual evidence. A dual-channel retrieval strategy jointly accesses structured facts and supporting evidence. On the LoCoMo benchmark, MemWeaver substantially improves multi-hop and temporal QA accuracy and reduces input context length by over 95%, demonstrating efficient, evidence-grounded long-term reasoning.

## Method Summary

MemWeaver builds its memory in three offline stages. First, **Writing** processes each dialogue session to extract entity-relation triples with absolute timestamps via fixed LLM prompts; a session-level verification step then adds, updates, or denies triples in a global knowledge graph. Second, **Experience Induction** clusters all dialogue units using DBSCAN on embeddings; coherent clusters yield abstracted “experience” items (facts, strategies, preferences) through LLM prompting. Third, **Passage Memory** stores raw text spans linked to graph entities. During inference, **Dual-Channel Retrieval** operates in parallel: the structured arm retrieves relevant graph triples, expands neighbors, and selects with an LLM; the textual arm gathers passages/experiences attached to selected entities plus global dense hits. Retrieved contexts are merged and fed to the backbone LLM to generate answers.

## Key Results

- With GPT-4o-mini, MemWeaver raises Temporal F1 from 38.77 to 50.83 (+12.06) and Multi-Hop F1 from 24.35 to 26.00 (+1.65) on LoCoMo.
- Achieves >95% context reduction, condensing over 22K tokens to ~1K tokens per query.
- Outperforms baselines across strong (GPT-4o-mini) and small (Llama3.2-3B, Qwen2.5-1.5B) backbones, though gains diminish on the smallest models.

## Why This Works (Mechanism)

MemWeaver’s effectiveness stems from its consolidation-centric design that transforms raw dialogues into three complementary memory forms. The knowledge graph enforces temporal consistency by anchoring events to absolute times, enabling precise multi-hop and temporal reasoning. Experience memory abstracts reusable patterns from clusters of similar interactions, allowing agents to generalize strategies without overfitting to specific dialogues. Passage memory preserves raw textual evidence, ensuring traceability and facilitating correction. The dual-channel retrieval strategically balances precision (via the structured graph) and recall (via textual passages), delivering just enough relevant context to answer queries while keeping input compact. This architecture mitigates temporal conflicts by normalizing time, reduces brittleness through abstraction, and grounds answers in verifiable evidence, collectively supporting long-horizon agentic reasoning.

## Foundational Learning

- **Temporally grounded knowledge graphs**  
  *Why needed*: To model events and relations with precise timing, avoiding contradictions.  
  *Quick check*: Verify extracted triples have normalized absolute timestamps; temporal queries return correctly dated facts.

- **Experience memory via clustering**  
  *Why needed*: To distill reusable patterns from similar dialogues, enabling generalization beyond rote recall.  
  *Quick check*: Inspect induced experience items for coherence and non-redundancy across clusters.

- **Dual-channel retrieval**  
  *Why needed*: To combine high-precision structured facts with high-recall textual evidence, overcoming limitations of either alone.  
  *Quick check*: For a sample query, ensure both graph triples and supporting passages cover the answer rationale.

- **Consolidation-centric memory writing**  
  *Why needed*: To systematically transform raw conversations into structured, verified memories rather than passive storage.  
  *Quick check*: Review session-level verification outputs to confirm contradictions are resolved and updates propagate.

- **Evidence traceability**  
  *Why needed*: To enable auditing, correction, and user trust by linking claims back to source passages.  
  *Quick check*: Trace each factual claim in a generated answer to its originating passage or triple.

- **Context compaction**  
  *Why needed*: To keep inference feasible for long-horizon tasks by summarizing years of interaction into a few tokens.  
  *Quick check*: Measure token count of retrieved context versus raw history; expect >90% reduction.

## Architecture Onboarding

- **Component map**:  
  Input Dialogues → Writing Stage (Entity Extraction, Relation Extraction, Temporal Normalization, Session Verification) → Graph Memory & Passage Memory → Experience Induction (Clustering, Coherence Check, Induction) → Experience Memory → Inference: Query → Dual-channel Retrieval (Structured arm: Graph retrieval + LLM selection; Textual arm: Entity-linked + global dense) → Context Assembly → Backbone LLM → Answer

- **Critical path**: Offline processing of each dialogue session extracts and verifies knowledge graph triples and stores raw passages. After all sessions, experience clusters form and abstractions are induced. At inference, the query triggers parallel retrieval from the graph and textual stores; retrieved items are merged into a compact context for the LLM to generate an answer.

- **Design tradeoffs**:  
  - Structured vs. unstructured retrieval: Graph triples offer precision for relational reasoning but may miss nuance; passages provide coverage but can be noisy.  
  - Memory compaction vs. detail: Experience summarization reduces context but risks losing specifics; raw passages preserve detail but increase size.  
  - Offline vs. online updates: Consolidation is offline for stability; online routing buffers new units for batch processing, trading immediacy for efficiency.  
  - LLM reliance: Memory construction heavily depends on a powerful LLM (DeepSeek-V3.2), ensuring quality but increasing cost and limiting accessibility.

- **Failure signatures**:  
  - Poor temporal accuracy: Check normalized timestamps; revise temporal normalization prompt.  
  - Noisy/generic experiences: Inspect cluster coherence; adjust DBSCAN `eps` or induction prompt.  
  - Retrieval context too narrow: Verify graph expansion and textual hits; increase retrieval budgets.  
  - High latency: Profile LLM selector and graph expansion; consider caching or fewer hops.  
  - Degraded small-model performance: Ensure structured retrieval supplies high-precision triples; fallback to top-k if LLM selector fails.

- **Exactly 3 first experiments**:  
  1. Build a knowledge graph on 2–3 LoCoMo sessions and manually evaluate triple correctness and temporal normalization.  
  2. Run DBSCAN clustering on a dialogue-unit subset and review induced experiences for coherence and relevance.  
  3. Perform end-to-end retrieval on fixed queries; inspect retrieved triples and passages for coverage of ground-truth reasoning paths.

## Open Questions the Paper Calls Out

1. How does the quality and stability of MemWeaver's consolidated memory depend on the choice of backbone language model used for the offline construction phase?  
2. Can the tri-layer consolidation framework be effectively extended to handle multimodal interactions (e.g., images, audio) within the same structured and evidence-grounded paradigm?  
3. What is the theoretically optimal or practically learnable allocation of retrieval budgets (kr, kp, ke) across the three memory channels for different query types?  
4. How scalable and noise-resistant is the experience memory's DBSCAN clustering and LLM-induced abstraction process in open-world, long-running agent deployments with continuously emerging topics?  
5. Does MemWeaver's consolidation-centric design provide superior traceability and correctability of erroneous or outdated memories compared to passive retrieval or summary-based systems in interactive, user-corrective scenarios?

## Limitations

- Underspecified implementation details (DBSCAN distance metric, reclustering logic, exact LLM prompts/temperatures, backfill scoring) hinder faithful replication.
- Offline construction relies on DeepSeek-V3.2, a large proprietary model, limiting accessibility and raising cost concerns.
- Performance gains diminish with smaller backbone LLMs, and the system remains untested in interactive correction scenarios.

## Confidence

- **High**: Context reduction claim (>95% to ~1K tokens) – clearly described and directly measurable.
- **Medium**: Reported accuracy gains (e.g., +12.06 temporal F1 with GPT-4o-mini) – tri-layer design is sound, but missing parameters could alter results.
- **Low**: Small-model performance (Llama3.2-1B, Qwen2.5-1.5B) – sensitive to undisclosed prompt engineering and thresholds.

## Next Checks

- **Memory construction replication**: Build KG and experience memory on a LoCoMo subset using described prompts (or reasonable defaults); manually verify triple correctness and experience utility.
- **Retrieval component ablation**: Disable dual-channel arms and vary kr, kp, ke to measure isolated contributions to multi-hop/temporal F1, clarifying what drives improvements.
- **Cross-benchmark evaluation**: Apply MemWeaver to another long-horizon dialogue benchmark (e.g., LoCoMo-100 or Doc2Dial) to test generalizability of both accuracy gains and context compression.
