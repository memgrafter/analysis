# AWARE-US: Benchmark for Preference-Aware Resolution in Tool-Calling Agents

## Quick Facts
- arXiv ID: 2601.02643
- Source URL: https://arxiv.org/abs/2601.02643
- Reference count: 40
- Primary result: Locally weighted agents achieve 48% preference alignment; global weighting achieves 56% correct constraint relaxation; all methods outperform baselines in resolving infeasibility while preserving user-valued constraints.

## Executive Summary
Tool-calling agents often fail when user queries are underspecified or infeasible, either returning no results or making ad-hoc constraint relaxations that violate user intent. This work reframes infeasibility as a preference-aware query repair problem and introduces the AWARE-US benchmark, comprising 120+ persona-grounded car queries. The authors propose three methods to infer constraint importance from dialogue: local weighting (per-slot), global one-shot weighting (joint over all constraints), and pairwise ranking (LLM comparisons). Agents are trained via supervised fine-tuning (SFT) for constraint extraction and direct preference optimization (DPO) for repair policy. Experimental results show locally weighted agents achieve the highest preference alignment (48%), while global weighting attains the best correct relaxation rate (56%). All methods significantly surpass prior baselines, demonstrating the value of incorporating inferred preferences into infeasibility handling.

## Method Summary
The approach uses a two-stage training pipeline. Stage 1 (SFT) trains a roleplayer language model to output structured JSON containing extracted constraints and importance labels per clarification slot. Stage 2 (DPO) trains an agent policy to select which constraint to relax when the full constraint set yields no database results, using oracle-defined preference triples (preferred relaxation vs. plausible but incorrect alternatives). The agent interacts with a car catalog database via bitwise set operations to check feasibility and generate recommendations. Three preference inference methods are evaluated: (1) **Local weighting** assigns an importance score per slot based on that turn’s user response, relaxing the lowest weight first; (2) **Global one-shot weighting** jointly assigns normalized weights to all constraints after the full dialogue, relaxing the lowest global weight; (3) **Pairwise ranking** uses LLM comparisons to create an importance ordering and relaxes the lowest-ranked constraint. The AWARE-US benchmark provides persona-grounded queries, oracle weights, and reference relaxation choices for evaluation.

## Key Results
- Locally weighted agents achieve the highest preference alignment (48%), meaning they relax the oracle-identified constraint most often.
- Global one-shot weighting achieves the highest rate of correct constraint relaxation (56%) and better captures cross-turn trade-offs.
- All proposed methods (local, global, pairwise) significantly outperform prior baselines in resolving infeasibility while preserving user-valued constraints.

## Why This Works (Mechanism)

### Mechanism 1: Local Weighting
- **Claim:** Per-slot local weighting improves preference alignment by anchoring constraint importance to immediate, slot-specific user statements.
- **Mechanism:** During each clarification turn, the agent extracts a constraint and assigns a weight based solely on that turn’s user response. When the full query is infeasible, constraints are relaxed in ascending weight order. This ties priority directly to explicit, localized expressions (e.g., “must-have” vs “nice-to-have”).
- **Core assumption:** User intent can be reliably inferred from individual slot answers without requiring full-context aggregation; preference signals are present and decidable per slot.
- **Evidence anchors:** [abstract] locally weighted agents best align with user preferences (48%); [section 4] local weighting extracts constraints and importance scores from that local exchange; [section 6] local weighting is more robust to parsing noise.
- **Break condition:** Vague or contradictory user responses for a slot produce noisy weights, leading to incorrect relaxation order.

### Mechanism 2: Global One-Shot Weighting
- **Claim:** Global one-shot weighting captures cross-turn trade-offs but is sensitive to parsing noise.
- **Mechanism:** After the entire dialogue, the agent jointly processes all extracted constraints and their conversational context to assign normalized weights in a single pass. Relaxation chooses the lowest global weight, modeling dependencies like “Model matters more than MPG” that may span multiple turns.
- **Core assumption:** The full transcript contains sufficient cues to compute a consistent global importance ordering; later turns can override earlier ones.
- **Evidence anchors:** [abstract] global weighting achieves highest correct relaxation (56%); [section 4] global weighting computes weights conditioning jointly on (S, C) to capture cross-turn trade-offs; [section 6] global weighting better infers importance from multi-turn context but is more sensitive to parsing noise.
- **Break condition:** Constraint extraction errors (missing/incorrect constraints) corrupt the set, degrading both relaxation choice and final recommendation.

### Mechanism 3: Pairwise Ranking
- **Claim:** Pairwise ranking provides a preference ordering without calibrated weights but suffers from instability and lower downstream alignment.
- **Mechanism:** For every constraint pair, the LLM predicts which is more important given the dialogue. Aggregate pairwise wins into a score to induce a total order; relax the lowest-ranked constraint first.
- **Core assumption:** LLMs can perform consistent, transitive pairwise comparisons when prompted with context; aggregation yields a stable total order.
- **Evidence anchors:** [section 4] pairwise ranking predicts ci ≻ cj; [section 6] pairwise ranking shows consistently lower slot completion and downstream performance loss due to weaker constraint recovery.
- **Break condition:** Pairwise judgments may be intransitive or biased by prompt ordering, leading to inconsistent scores and suboptimal relaxation choices even if individual comparisons seem plausible.

## Architecture Onboarding
**Component map:**  
Roleplayer LM -> Agent LM -> Database Executor; Prompt Builders and Training Pipeline support.

**Critical path:**  
1. User provides base query + persona.  
2. Agent asks clarification questions per slot.  
3. Roleplayer responds; Agent extracts constraints (and optionally weights).  
4. Executor checks full constraint feasibility.  
5. If infeasible, Agent selects relaxation based on method (local/global/pairwise).  
6. Executor applies relaxed query; if non‑empty, recommend top‑ranked car by soft satisfaction score.  
7. Compare relaxation choice and recommendation to oracle for evaluation.

**Design tradeoffs:**  
- Local vs. Global weighting: Local ties importance to slot‑level evidence (more robust to extraction errors), global aggregates cross‑turn context (more sensitive to noise but captures trade‑offs).  
- Weighting vs. Pairwise: Weighting gives calibrated scores for ordering; pairwise avoids calibration but may yield intransitive rankings.  
- Greedy fallback: Adding greedy after weighting eliminates UNSAT but may override correct preference‑based relaxation.

**Failure signatures:**  
- Silent underspecification: Roleplayer fails to extract a constraint mentioned in persona → missing slot in Cₐ𝑑𝑑 → incorrect feasibility check.  
- Preference‑inconsistent repair: Agent relaxes a high‑importance constraint despite correct extraction → low Relax match.  
- UNSAT after relaxation: Agent chooses wrong relaxation (even if low weight) that still yields empty set → no recommendation.

**First 3 experiments:**  
1. Baseline evaluation: Run untrained LMs with each method on AWARE‑US test sets; measure slot completion, SAT rates, oracle agreement.  
2. SFT impact analysis: Compare base vs. SFT‑trained roleplayer on constraint extraction quality and downstream SAT‑after‑relaxation.  
3. DPO training comparison: Evaluate SFT+DPO trained agent against base; isolate improvements from reduced silent underspecification and better repair choices.

## Open Questions the Paper Calls Out

## Limitations
- Missing training hyperparameters, exact prompt templates, and executor details hinder exact replication.  
- Benchmark limited to car queries (120+ instances) may not generalize to other tool domains.  
- Pairwise ranking implementation details (aggregation, transitivity handling) are underspecified, affecting reproducibility.
