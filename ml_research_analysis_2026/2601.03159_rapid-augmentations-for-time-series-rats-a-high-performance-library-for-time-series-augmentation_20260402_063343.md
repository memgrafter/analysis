# Rapid Augmentations for Time Series (RATS): A High-Performance Library for Time Series Augmentation
## Quick Facts
- **arXiv ID**: 2601.03159
- **Source URL**: https://arxiv.org/abs/2601.03159
- **Reference count**: 35
- **Primary result**: RATS achieves an average speedup of 74.5% over tsaug (up to 94.8% on large datasets) and reduces peak memory usage by up to 47.9% through Rust-based parallelization.

## Executive Summary
RATS addresses the performance bottlenecks of Python-based time series augmentation by implementing a suite of 17 augmentation techniques in Rust, exposing Python bindings for usability. The library employs a unified pipeline with parallel execution via the Rayon framework, enabling efficient processing of large datasets. Benchmarking across 143 univariate time series datasets demonstrates significant improvements in runtime and memory consumption compared to the popular tsaug library, making large-scale augmentation feasible.

## Method Summary
RATS provides a high-performance augmentation pipeline where each transformation (augmenter) is implemented as a Rust struct with a common trait. The pipeline can be configured with any combination of augmenters and executed in parallel. Input data from Python (NumPy arrays) are converted to Rust vectors, processed across threads using Rayon's work-stealing scheduler, and the results are returned to Python. The benchmark suite uses a common pipeline of seven augmenters (AddNoise, Crop, Drift, Pool, Quantize, Resize, Reverse) applied to all 143 datasets from the aeon toolkit. Performance is measured via wall-clock time and peak memory (Python's memory_profiler), and output quality is assessed using Dynamic Time Warping (DTW) to ensure no degradation. This experimental design isolates the performance impact of the underlying implementation while maintaining functional parity with tsaug.

## Key Results
- Average runtime speedup of 74.5% over tsaug; up to 94.8% on large datasets (high sample count).
- Peak memory usage reduced by up to 47.9%.
- No statistically significant difference in augmentation quality (DTW) compared to tsaug.

## Why This Works (Mechanism)
RATS gains its performance by leveraging Rust's zero-cost abstractions, absence of a garbage collector, and guaranteed memory safety without runtime overhead. The core augmentation logic operates on contiguous arrays, enabling vectorized operations and cache-friendly access patterns. Parallelization is seamlessly integrated through Rayon, which automatically distributes the augmentation of individual time series across available CPU cores, exploiting data parallelism while handling load balancing. The use of PyO3 for bindings incurs minimal overhead because data exchange occurs as raw pointers to NumPy arrays, avoiding copies. Furthermore, the unified pipeline eliminates per-augmenter Python dispatch overhead present in tsaug, consolidating all transformations into a single compiled loop. These factors combine to yield substantial speedups and memory efficiency, especially as dataset size (number of series) increases.

## Architecture Onboarding
**Component Map**: Python API -> PyO3 Bridge -> Rust Core (Augmenter Trait, Pipeline, Parallel Scheduler) -> System Hardware

**Critical Path**: A user invokes `pipeline.apply(data)` from Python → PyO3 converts NumPy arrays to Rust vectors → Pipeline iterates over augmenters, each applying its transformation → Rayon splits the data into chunks and processes them concurrently on multiple threads → Results are collected, converted back to NumPy arrays, and returned to Python.

**Design Tradeoffs**: 
- Rust vs. pure Python: Rust gives speed but adds compile-time dependency; Python API maintains accessibility.
- Parallelism overhead: For small datasets, thread startup cost may dominate; RATS uses Rayon's global thread pool to mitigate.
- Memory vs. speed: In-place operations reduce memory but may affect safety; RATS opts for clear ownership to avoid aliasing, incurring some copies.
- Flexibility vs. performance: The unified pipeline limits dynamic per-sample branching but simplifies optimization.

**Failure Signatures**:
- Performance regression: RATS slower than tsaug, often due to incorrect parallelization (e.g., running single-threaded) or data copying.
- Memory blow-up: Unexpectedly high peak memory suggests hidden copies or large intermediate buffers.
- Incorrect outputs: DTW distances diverge significantly from tsaug, indicating mismatched augmentation parameters or implementation errors.
- Panics/crashes: Rust panics may surface as Python exceptions; typical causes include invalid shape assumptions or out-of-bounds access.

## Limitations
- **Pipeline definition mismatch**: Exact augmenter composition and parameters for the common pipeline are unspecified, risking non-comparable benchmarks. *Confidence: Medium*.
- **Hardware & environment dependency**: Performance is sensitive to CPU, memory, and software versions; missing specifications hinder exact replication. *Confidence: Low*.
- **Memory measurement fidelity**: Using Python's memory_profiler for Rust code may not capture true peak memory accurately. *Confidence: Medium*.

## Confidence
- Speedup over tsaug (average 74.5%): Medium
- Memory reduction (up to 47.9%): Medium
- Unified parallelized pipeline design: High
