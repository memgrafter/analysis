# ReasonAny: Incorporating Reasoning Capability to Any Model via Simple and Effective Model Merging

## Quick Facts
- **arXiv ID:** 2601.05560  
- **Source URL:** https://arxiv.org/abs/2601.05560  
- **Reference count:** 40  
- **One‑line result:** ReasonAny merges reasoning and domain models without performance collapse, recovering ~99% GSM8K and matching safety scores.

## Executive Summary
ReasonAny addresses the destructive performance collapse that occurs when existing model merging methods combine a long‑chain reasoning model with a domain‑specific expert. The key insight is that reasoning ability resides in model parameters with low gradient sensitivity on a reasoning calibration dataset, while domain expertise is concentrated in high‑gradient regions. The proposed method uses Contrastive Gradient Identification to select low‑gradient parameters for reasoning and high‑gradient parameters for the domain task, followed by conflict resolution via exclusion to ensure disjoint parameter masks. Experiments on safety, biomedicine, and finance tasks show that ReasonAny significantly outperforms state‑of‑the‑art baselines, preserving strong reasoning (e.g., ~99% GSM8K recovery on Qwen2.5‑7B) without sacrificing domain utility (e.g., harmfulness score 1.18 on Safety‑Tuned) and maintaining linguistic stability. Ablation studies confirm that both identification steps are necessary.

## Method Summary
Given a base model (pre‑trained), a reasoning expert (fine‑tuned for long chain‑of‑thought), and a domain expert (fine‑tuned for a specific task), ReasonAny proceeds as follows:

1. Compute task vectors: \(\tau_r = \theta_r - \theta_{base}\) and \(\tau_t = \theta_t - \theta_{base}\).
2. For each expert, run a few forward/backward passes on a small (≈100 samples) calibration set representative of its task. For every parameter, compute the average \(\ell_1\) norm of its gradients across samples, forming an importance vector \(I(\theta, D)\).
3. Contrastive identification: For the reasoning model, sort parameters by ascending \(I(\theta_r, D_r)\) and select the bottom \(p\) fraction (low‑gradient) into set \(N_r\). For the domain model, sort by descending \(I(\theta_t, D_t)\) and take the top \(p\) fraction (high‑gradient) into \(N_t\).
4. Conflict resolution: Enforce mutual exclusivity via set difference, i.e. \(M_r = N_r \setminus N_t\) and \(M_t = N_t \setminus N_r\).
5. Merge weights: \(\theta_{merged} = \theta_{base} + \lambda_r (\tau_r \odot M_r) + \lambda_t (\tau_t \odot M_t)\), with \(\lambda_r = \lambda_t = 1.0\) and \(p = 0.05\) in the main experiments.

The method assumes that capabilities are linearly composable when applied to disjoint parameter subspaces and that the chosen calibration sets elicit distinctive gradient patterns.

## Key Results
- **Reasoning preservation:** On Qwen2.5‑7B, ReasonAny recovers 86.28% GSM8K (≈99% of the reasoning expert’s performance) while merging with a safety expert.
- **Domain utility:** The merged model achieves a harmfulness score of 1.18 on Safety‑Tuned, matching the domain expert and far outperforming prior merging baselines that collapse reasoning.
- **Linguistic stability:** Perplexity remains low (e.g., close to base model levels), whereas competing methods yield high perplexity, indicating corrupted language modeling.

## Why This Works (Mechanism)
### Gradient contrast identifies distinct subspaces
- **Claim:** Reasoning capability lies in parameters with low gradient sensitivity on a reasoning calibration set; domain expertise lies in high‑gradient parameters.
- **Mechanism:** Contrastive Gradient Identification computes per‑parameter importance as the average gradient magnitude (\(\ell_1\)) over a task‑specific calibration dataset. It then selects the bottom‑\(K\) parameters for the reasoning model (\(N_r\)) and the top‑\(K\) for the domain model (\(N_t\)).
- **Evidence:** Reasoning models (e.g., DeepSeek‑R1‑Distill, QwQ) exhibit significantly lower nuclear norms of gradients on reasoning data compared to base models (Sec 2.2). The paper also shows that injecting only the low‑gradient fraction of the reasoning task vector preserves GSM8K performance, while the high‑gradient fraction causes collapse.
- **Break condition:** If the calibration data is unrepresentative or gradient estimates are noisy, the identified subspaces may not cleanly separate capabilities, leading to interference during merge.

### Exclusion prevents destructive interference
- **Claim:** Overlap between the selected subspaces causes catastrophic degradation of at least one capability.
- **Mechanism:** After initial selection, Conflict Resolution via Exclusion computes disjoint masks \(M_r = N_r \setminus N_t\) and \(M_t = N_t \setminus N_r\), ensuring no parameter is updated by both sources.
- **Evidence:** Ablation studies (Sec 4.3) show that removing either the reasoning parameter selection (w/o reason select) or the domain parameter selection (w/o safety select) leads to severe drops in reasoning and domain performance, respectively. This demonstrates that overlap is harmful and exclusion is necessary.
- **Break condition:** If the true parameter subspaces for reasoning and domain have substantial necessary overlap, the exclusion step may discard critical parameters, causing irrecoverable capability loss.

### Disjoint linear composition works
- **Claim:** Composing the base model with scaled, disjoint task vectors from the exclusive parameter sets synthesizes a model that retains both robust reasoning and domain utility.
- **Mechanism:** The final weights are \(\theta_{merged} = \theta_{base} + \lambda_r(\tau_r \odot M_r) + \lambda_t(\tau_t \odot M_t)\). Scaling factors \(\lambda\) adjust for magnitude differences; the masks guarantee that updates are applied to separate parameters.
- **Evidence:** Tables 1‑3 across safety, biomedicine, and finance domains show simultaneous high scores on reasoning benchmarks (GSM8K, MATH) and domain benchmarks (Safety‑Tuned harmfulness, PubMedQA, ConvFinQA) while perplexity remains stable. Hyperparameter analysis indicates monotonic improvement with \(\lambda\) up to 1.0 and insensitivity to the selection ratio \(p\) around 0.05.
- **Break condition:** Mis‑specified \(\lambda\) (too large causing divergence, too small yielding negligible utility) or incompatibility between base weights and task vectors could destabilize the composition or degrade language modeling.

## Foundational Learning
- **Gradient‑Based Parameter Importance**  
  *Why needed:* Forms the core of Contrastive Gradient Identification; gradient magnitude on a calibration set serves as a proxy for parameter saliency to a specific task.  
  *Quick check:* Why would parameters critical for long‑chain reasoning show *lower* gradient magnitudes on a reasoning dataset compared to parameters for domain‑specific tasks?

- **Task Vectors and Arithmetic Model Merging**  
  *Why needed:* The entire merging pipeline operates on task vectors \(\tau = \theta_{finetuned} - \theta_{base}\). This linear difference formulation assumes capabilities are displacement vectors in weight space that can be additively combined.  
  *Quick check:* What is the implicit assumption about the linearity of capability spaces when using \(\theta_{merged} = \theta_{base} + \tau_r + \tau_t\)?

- **Chain‑of‑Thought (CoT) Reasoning Models**  
  *Why needed:* The “reasoning model” in the paper refers specifically to models fine‑tuned for long CoT (e.g., DeepSeek‑R1‑Distill). Understanding that these models learn to generate extended reasoning traces is key to why their parameter updates differ.  
  *Quick check:* How might the training objective (e.g., GRPO for long‑CoT) influence the distribution of gradient magnitudes across layers compared to standard supervised fine‑tuning?

## Architecture Onboarding
Component map:  
Model Loader -> Calibration Data Manager -> Gradient Computation Module -> Subspace Identifier -> Conflict Resolver -> Composition Engine -> Evaluation Harness

Critical path: Load models -> Compute gradients on calibration data -> Identify subspaces (TopK/BottomK) -> Resolve conflicts (exclusion) -> Compose final weights -> Evaluate outputs.

Design tradeoffs:
- **Selection ratio \(p\):** Larger \(p\) includes more parameters but increases overlap risk; smaller \(p\) risks under‑representing capability. Paper recommends \(p = 0.05\) and finds insensitivity around this value.
- **Scaling factors \(\lambda\):** Crucial for balancing magnitude; too high can destabilize training dynamics, too low yields negligible utility. Monotonic improvement observed up to \(\lambda = 1.0\).
- **Calibration data size:** 100 samples per task trade off representativeness vs. computational overhead in gradient accumulation.
- **Exclusivity vs. overlap:** Strict exclusion assumes minimal necessary overlap; a less strict weighting scheme could be explored but was not studied.

Failure signatures:
- **Reasoning collapse:** GSM8K/MATH scores drop to near zero (e.g., TIES, DARE, FuseLLM in Table 1).
- **Domain utility loss:** Safety harmfulness reward increases, or biomedical/finance QA scores plummet.
- **Linguistic instability:** Extremely high perplexity (e.g., >1000) indicates corrupted language modeling head.
- **Deceptive safety:** Low ASR on HarmBench *with* reasoning collapse (due to nonsensical outputs not triggering classifier) – always check concurrent reasoning benchmark performance.

First 3 experiments:
1. **Gradient distribution verification:** For a model pair (e.g., Qwen2.5‑7B Instruct vs. DeepSeek‑R1‑Distill‑Qwen‑7B), compute and plot layer‑wise nuclear norms/MAD of gradients on respective calibration sets. Expect significantly lower norms for the reasoning model on reasoning data.
2. **Additive injection test:** Take \(\theta_{base}\) and add only the *lowest*‑gradient \(p\) fraction of \(\tau_r\). Validate that GSM8K recovers substantially vs. adding the *highest*‑gradient fraction, which should cause collapse.
3. **End‑to‑end sanity check:** Run full ReasonAny pipeline on small‑scale models (e.g., 1‑2B) with \(p=0.1\), \(\lambda=1.0\). Expect both reasoning and domain scores to be non‑zero and at least approach the weaker of the two expert models, confirming basic functionality before scaling.

## Open Questions the Paper Calls Out
1. **Disjoint subspace assumption:** The authors assume reasoning and domain subspaces are largely non‑overlapping, but the actual overlap magnitude and its impact on performance are not measured. Significant necessary overlap could limit the effectiveness of exclusion.
2. **Multi‑model merging:** The method is designed for merging two experts. Scalability to three or more models (e.g., multiple reasoning/domain experts) remains unexplored; binary exclusion may not suffice.
3. **Generality of gradient contrast:** The low‑gradient property of reasoning was observed on DeepSeek‑distilled and QwQ models. It is unclear whether this pattern holds for other reasoning models (e.g., OpenAI o1, Gemini Thinking) or different training schemes.
4. **Alternative importance metrics:** The reliance on gradient‑based attribution increases computational overhead. Whether simpler metrics (weight magnitude, Fisher information) can replace gradient computation without sacrificing performance is left as an open question.

## Limitations
- Calibration data size (≈100 samples) may yield noisy gradient estimates, affecting identification stability.
- The parameter set considered (e.g., embeddings, biases, LayerNorms) is not fully specified; omitting certain parameter types could break the gradient contrast.
- Hyperparameters (selection ratio \(p\), scaling factors \(\lambda\)) are fixed across tasks; they likely require task‑specific tuning for optimal results.
- The exclusion step discards any overlapping parameters, which might contain features necessary for one or both capabilities.
- The linear composition assumption may fail if nonlinear interactions between task vectors exist.

## Confidence
- **Gradient contrast (low‑gradient reasoning):** Medium confidence. Supported by empirical observations (Sec 2.2) but lacks theoretical justification; calibration dependency unknown.
- **Exclusion necessity:** High confidence. Ablation studies (Sec 4.3) clearly show catastrophic collapse without both identification steps.
- **Linear composition:** Medium‑high confidence. Multi‑domain results (Tables 1‑3) are strong but rely on fixed \(\lambda = 1.0\); scaling sensitivity suggests possible task dependence.

## Next Checks
1. **Gradient distribution:** Compute \(\ell_1\) norms for multiple model pairs (e.g., different base sizes, reasoning models) to verify that reasoning models consistently exhibit lower gradient magnitudes on reasoning calibration data than domain models on their respective data.
2. **Selective injection:** For a given reasoning model, add only the bottom‑\(p\)% of its task vector \(\tau_r\) to the base model and evaluate GSM8K; compare against adding the top‑\(p\)%. Expect success only with the low‑gradient fraction.
3. **Mask overlap:** Before exclusion, compute the Jaccard index between \(N_r\) and \(N_t\). After exclusion, verify that the masks \(M_r\) and \(M_t\) are completely disjoint. High pre‑exclusion overlap warns of potential over‑exclusion and capability loss.
