# A Multi-Agent Human-LLM Collaborative Framework for Closed-Loop Scientific Literature Summarization

## Quick Facts
- arXiv ID: 2604.01452
- Source URL: https://arxiv.org/abs/2604.01452
- Reference count: 40
- Primary result: Extracted 14 validated data points from 64 papers, finding an exponential model (R²=0.695) fit helium bubble growth versus irradiation dose and temperature better than linear (R²=0.503), confirming a nonlinear accelerating trend.

## Executive Summary
Scientific literature fragmentation slows discovery. This paper introduces Elhuyar, a multi-agent human-in-the-loop framework that structures literature review into sequential tasks: filtering relevant papers, extracting numerical data via LLMs with iterative consensus scoring (ICS) to reduce hallucinations, fitting mathematical models (e.g., linear, exponential), and generating reports with visualizations and summaries. Human scientists guide the query and inspect low-confidence extractions. In a materials science pilot analyzing tungsten under helium-ion irradiation, the system extracted 14 validated data points from 64 papers and identified an exponential relationship with superior fit (R²=0.695 vs. linear 0.503), consistent with microstructural theory.

## Method Summary
The pipeline begins with a scientist supplying a corpus, scientific query, and structured data definition. A yes/no filtering agent discards papers unlikely to contain required structured data. The extractor agent runs *k* independent LLM passes per document to output candidate numerical data points in JSON. Iterative consensus scoring (ICS) aggregates responses to compute confidence scores; high-confidence points are auto-accepted, medium flagged for human inspection, low discarded. A human inspector verifies flagged points. A model selection agent chooses candidate models from a predefined library; a non-LLM fitting agent computes parameters and R²; a report agent generates visualizations and a grounded text summary. The scientist then iterates based on the report.

## Key Results
- Extracted 14 validated data points from 64 papers on helium bubble growth in tungsten.
- Exponential model fit: R²=0.695; linear model fit: R²=0.503, demonstrating a nonlinear accelerating trend.
- All high-confidence data points (ICS ≥3) were correct after human validation.

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** Iterative Consensus Scoring (ICS) reduces LLM hallucinations and inconsistent extractions in numerical data extraction.
**Mechanism:** The extractor agent runs *k* independent LLM extraction passes for each document. A confidence score is calculated from the number of matching responses across passes. Low-confidence extractions are filtered; middling scores are flagged for human inspection; high-confidence extractions proceed. This aggregates independent stochastic outputs to estimate reliability.
**Core assumption:** Repeated, independent LLM queries under identical conditions will produce consistent outputs for correctly extractable facts but vary for incorrect or hallucinated ones.
**Evidence anchors:** [abstract] "...extracting numerical data via LLMs with iterative consensus scoring (ICS) to reduce hallucinations..." [section "Iterative Consensus Scoring (ICS)"] "This process improves reliability by evaluating the consistency of extracted pieces of data across multiple (k) independent runs of the LLM, reducing the likelihood of errors..."
**Break condition:** If *k* is too low or LLM outputs are highly correlated, consensus may not distinguish correct from incorrect extractions.

### Mechanism 2
**Claim:** A preliminary yes/no filtering agent reduces the risk of hallucination in downstream extraction by removing documents unlikely to contain the required structured data.
**Mechanism:** Before extraction, an LLM agent asks structured yes/no questions based on the scientist's `Data Definition` (e.g., "Does the document report pure tungsten samples?"). Only documents answering "yes" to all required conditions proceed to extraction. The paper argues yes/no judgments are more reliable for LLMs than precise numerical extraction.
**Core assumption:** LLMs are less prone to hallucination when making high-level binary judgments about a document's content relevance compared to extracting specific numerical values.
**Evidence anchors:** [abstract] "...filtering relevant papers..." [section "Yes-No Filtering Agent"] "This step is essential for improving the reliability of downstream extraction, as it limits the risk of hallucination when extracting numerical values from text..."
**Break condition:** If filtering criteria are poorly defined or yes/no judgments are inaccurate, relevant papers may be excluded or irrelevant ones may proceed.

### Mechanism 3
**Claim:** Human-in-the-loop validation closes the system by having a human scientist inspect low-confidence extractions and guide iterative refinement, ensuring final data reliability and query alignment.
**Mechanism:** Data points with middling ICS scores are flagged for manual verification. The scientist reviews flagged data against source text, confirming or correcting values. The validated dataset is used for modeling. The scientist also provides the initial query and `Data Definition` and can issue follow-up queries based on the report, creating a closed refinement loop.
**Core assumption:** Human experts can reliably discriminate between correct and incorrect LLM extractions, especially for ambiguous or low-confidence cases, and can steer the AI toward scientifically valuable lines of inquiry.
**Evidence anchors:** [abstract] "...human scientists... guide the query and inspect low-confidence extractions." [section "Human in the Loop Collaboration"] "Human inspectors can also manually check flagged data points..." [section "Results"] "All points with ICS above 3 were manually checked and found to be correct."
**Break condition:** If the proportion of flagged data is very high, human verification becomes prohibitive; inspectors may also introduce bias or error.

## Architecture Onboarding

**Component map:**
Scientist -> Yes/No Filtering Agent -> Targeted Corpus -> Extractor Agent (k runs) -> Raw Extractions -> ICS -> Confidence Scores -> Auto-Filter -> High-Confidence Data + Flag for Human -> Human Inspector -> Validated Dataset -> Model Selection Agent -> Model Types -> Model Fit+Eval Agent -> Fitted Models/Metrics -> Report Agent -> Final Report -> Scientist.

**Critical path (data flow for one iteration):**
Corpus → Filter Agent → Targeted Corpus → Extractor Agent (×k) → Raw Extractions → ICS → Confidence Scores → Auto-Filter → High-Confidence Data + Flag for Human → Validated Dataset → Model Selection Agent → Model Types → Model Fit+Eval Agent → Fitted Models/Metrics → Report Agent → Final Report → Scientist.

**Design tradeoffs:**
- Modularity vs. Integration Cost: Decoupled agents ease debugging/swapping but require careful orchestration and data format consistency.
- Precision vs. Recall (Filtering): Strict `Data Definition` improves precision but may exclude valid papers (e.g., with convertible units), reducing recall.
- Automation vs. Human Load: ICS reduces but does not eliminate human review; the consensus threshold balances automatic acceptance and flagging.
- Model Simplicity vs. Fit: Limited to a predefined model library (linear, exponential, logistic); no open-ended symbolic regression may miss true underlying laws.

**Failure signatures:**
- Low Dataset Yield: Very few data points survive filtering/ICS (e.g., 14 from 64), indicating overly strict definition, poor corpus relevance, or extraction failures.
- High Flag Rate: >50% of extractions flagged suggests ICS threshold too low, LLM unreliable, or ambiguous prompts.
- Model Fit Absurdity: Nonsensical parameters or R² near 0 indicates corrupted input data or fitting agent failure.
- Report Agent Grounding Failure: Text summary references information not in dataset/metrics, indicating reliance on parametric knowledge over grounded synthesis.

**First 3 experiments:**
1. **Synthetic Data Sanity Check:** Run full pipeline on provided synthetic "drakorium" corpus (250 docs, known ground truth). Verify 100% correct model selection, high R², and proper filtering.
2. **ICS Parameter Sweep:** On 5–10 real papers, vary *k* (1,3,5,10) and consensus threshold (1,2,3). Measure extraction uniqueness, dataset size, and precision (via full human audit) to find optimal trade-offs.
3. **Filtering Agent Ablation:** Compare full pipeline against a version skipping yes/no filtering. Measure LLM calls, invalid extractions from irrelevant papers, and final dataset purity to quantify filtering's value.

## Open Questions the Paper Calls Out

### Open Question 1
**Question:** Does the exponential relationship between helium bubble size, irradiation dose, and temperature in tungsten hold for temperatures exceeding 1200°C?
**Basis in paper:** The Discussion states insufficient data beyond 1200°C; theory predicts eventual saturation or competing mechanisms.
**Why unresolved:** Current dataset contains no points >1200°C, leaving high-temperature extrapolation untested.
**What evidence would resolve it:** New experimental studies reporting bubble sizes at >1200°C, extracted and modeled using the same pipeline to determine if the exponential fit persists.

### Open Question 2
**Question:** Can the Elhuyar framework be effectively generalized to scientific domains beyond materials science, such as biomedicine or chemistry?
**Basis in paper:** The Conclusion explicitly aims for a modular codebase for other teams to define variables on their corpora, implying cross-domain deployment is a planned but unproven next step.
**Why unresolved:** Only a single-domain deployment (tungsten irradiation) is presented; adaptability to other fields' data types, variables, and literature structures is unevaluated.
**What evidence would resolve it:** Successful re-implementation in at least two distinct scientific domains (e.g., clinical trial literature, organic synthesis), with documented modifications.

### Open Question 3
**Question:** To what extent do strict filtering criteria (e.g., requiring dose in dpa, pure tungsten, single-beam irradiation) reduce dataset completeness, and can criteria be relaxed without significantly increasing hallucination?
**Basis in paper:** Only 14 data points extracted from 64 papers; `Data Definition` mandated specific units and conditions, likely excluding many relevant studies, but trade-off is unanalyzed.
**Why unresolved:** System prioritizes precision via aggressive filtering; impact on recall and potential for convertible data in filtered papers is unknown; no ablation on filter stringency reported.
**What evidence would resolve it:** Ablation study varying filtering criteria (e.g., allowing dose conversion from ion fluence, including alloys), measuring changes in data count, ICS scores, and verification accuracy.

### Open Question 4
**Question:** How can the model selection agent be made more robust to optimizer failures, such as the zero R² event observed in the synthetic evaluation?
**Basis in paper:** Synthetic evaluation noted one model selection failure due to an optimizer error producing zero R² for two models, requiring human flagging; root cause and mitigation unaddressed.
**Why unresolved:** Such failures could bias model comparisons or go undetected in larger deployments; reliance on structured AI for fitting is a reliability gap.
**What evidence would resolve it:** Implementation and testing of robust optimization fallbacks (e.g., multiple algorithms, convergence checks) on synthetic and real datasets, with a failure rate metric pre/post intervention.

## Limitations
- Exact prompts for key agents (Filtering, Model Selection, Report) are undisclosed, hindering reproduction.
- ICS parameters (numeric matching tolerance, consensus threshold interpretation) and "Softmax factor" for GPT-4o-mini are ambiguous.
- Evaluation limited to a single materials-science case study; generalizability to other domains is unknown.

## Confidence
- **ICS reduces hallucinations:** Medium (pilot/synthetic results suggest efficacy, but no direct corpus evidence).
- **Yes/No filtering improves precision:** Low (theoretical basis from prior work, no ablation presented).
- **Human-in-the-loop ensures final reliability:** Medium (pilot reported all high-ICS points correct after human check, but sample size limited).
- **Framework yields domain-relevant model fits:** Medium (pilot demonstrated exponential fit superior to linear in one domain; needs cross-domain validation).

## Next Checks
1. **ICS parameter sweep:** Vary *k* (extraction runs) and consensus threshold on a controlled paper subset to measure precision-recall trade-off and identify optimal settings.
2. **Filtering agent ablation:** Compare full pipeline against version without filtering to quantify impact on downstream error rate and computational cost.
3. **Cross-domain replication:** Apply framework to a different scientific domain (e.g., biomedical literature) with analogous quantitative synthesis tasks to test generalizability.
