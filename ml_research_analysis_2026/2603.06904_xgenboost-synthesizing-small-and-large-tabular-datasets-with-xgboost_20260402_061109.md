# XGenBoost: Synthesizing Small and Large Tabular Datasets with XGBoost

## Quick Facts
- **arXiv ID:** 2603.06904  
- **Source URL:** https://arxiv.org/abs/2603.06904  
- **Reference count:** 40  
- **Primary result:** XGenBoost variants (XGenB-DF for small datasets, XGenB-AR for large) achieve state-of-the-art fidelity and utility while training in minutes on modest CPUs.

## Executive Summary
Synthetic tabular data generation must preserve statistical relationships, handle mixed data types, and scale efficiently. XGenBoost introduces two tree-ensemble generative models built on XGBoost: XGenB-DF, a denoising diffusion implicit model with per‑feature, per‑timestep XGBoost score estimators that natively combine Gaussian (numeric) and multinomial (categorical) diffusion; and XGenB-AR, a hierarchical autoregressive model where conditionals are learned via XGBoost classifiers, using fixed‑order factorization, quantile‑based dequantization for numerics, and clustering for high‑cardinality categories. Evaluated on 27 small and 11 large benchmarks, XGenB-DF leads in fidelity on small datasets, while XGenB-AR outperforms in fidelity, utility, and training efficiency on large datasets. Both train within minutes on CPUs, demonstrating that tree‑based generative models can match or exceed neural methods at lower computational cost.

## Method Summary
XGenB-DF adapts denoising diffusion to mixed tabular data. Forward diffusion adds noise: Gaussian for numeric features (variance schedule β_t) and multinomial for categoricals (uniform-multinomial transition). The reverse step uses XGBoost models—regressors for numeric scores, classifiers for categorical scores—trained to predict the score (gradient of the log density). Re‑parameterization via velocity prediction reduces the number of timesteps to T=50; sampling follows DDIM iterations. XGenB-AR uses a fixed feature order. Numeric features are quantile‑binned into discrete values (with rank‑preserving noise) and modeled via a hierarchical binary meta‑tree of height 5, where each node is an XGBoost binary classifier. Categorical features use multi‑class XGBoost; high‑cardinality categories are merged via K‑means clustering. During sampling, features are drawn sequentially conditioned on previous values; numeric samples are dequantized via empirical quantile functions. Both models avoid one‑hot encoding and handle mixed types natively.

## Key Results
- XGenB-DF ranks first in fidelity metrics (Shape, Trend) across the Small Benchmark (27 datasets).
- XGenB-AR ranks first in fidelity (Shape, Trend, Detection), utility (MLE), and training efficiency across the Big Benchmark (11 datasets).
- Both models train within minutes on modest CPUs, matching or exceeding neural methods at lower computational cost.

## Why This Works (Mechanism)
XGBoost provides a strong inductive bias for tabular data: it captures non‑linear interactions, handles mixed data types natively, and trains quickly on CPUs. In XGenB-DF, the score‑estimation task naturally decomposes by feature and timestep; XGBoost regressors/classifiers can accurately learn the complex mapping from noisy data to the score, enabling high‑fidelity iterative denoising. The use of a velocity re‑parameterization and DDIM further reduces the number of steps. In XGenB-AR, the autoregressive factorization, combined with hierarchical binary classification for numerics, efficiently models conditional distributions without exponential bin blow‑up. Quantile‑based dequantization preserves the continuous nature of numeric features while keeping the model discrete‑valued. The fixed ordering simplifies training and inference, and clustering mitigates high cardinality. Together, these choices yield state‑of‑the‑art results with minimal computational overhead.

- **Autoregressive Factorization**: Decomposes joint density into a product of conditionals; needed for XGenB‑AR. *Quick check*: Write the chain rule for a multivariate distribution given an ordering.
- **Gradient Boosting (XGBoost)**: Ensemble method that builds trees to minimize a differentiable loss; core learner for both models. *Quick check*: Describe how gradient boosting sequentially fits trees to residuals.
- **Mixed‑Type Data Handling**: Preserving numeric and categorical features without one‑hot; integral to XGenBoost’s efficiency. *Quick check*: Contrast one‑hot encoding with native categorical handling in tree methods.
- **Quantile‑Based Dequantization**: Maps discrete bins back to continuous values using empirical quantiles; used for numeric dequantization in XGenB‑AR. *Quick check*: Given a bin range and a uniform u∈[0,1], compute the output value.
- **Hierarchical Binary Classification**: Recursively splits numeric values via binary decisions; reduces multi‑class complexity. *Quick check*: Sketch a binary tree that predicts whether a numeric label is below/above a threshold at each depth.

## Architecture Onboarding
**Component Map (XGenB‑DF):**  
Raw Data → Create K noisy copies per timestep (Gaussian/Multinomial) → Train separate XGBoost regressors/classifiers for each (feature, timestep) → Sampling: start from pure noise → Iterative DDIM update using XGBoost predictions → Synthetic data.

**Component Map (XGenB‑AR):**  
Raw Data → Quantile binning of numerics (with rank noise) / Cluster high‑cardinality categoricals → Train per‑feature XGBoost classifiers in fixed order (hierarchical binary for numerics, multi‑class for categoricals) → Sequential sampling: for each feature, use trained model conditioned on previous samples → Dequantize numeric samples via empirical quantiles → Synthetic data.

**Critical Path**  
- *XGenB‑DF*: Training requires generating K noisy datasets (K=100) and training many XGBoost models; the longest single‑model training time dominates. Sampling loops over T=50 timesteps sequentially.  
- *XGenB‑AR*: Preprocessing (binning/clustering) → training all per‑feature models (can be parallelized) → sequential sampling loop over features; sampling time scales with number of features.

**Design Tradeoffs**  
- *DF*: High fidelity via fine‑grained timestep‑specific estimators; but large memory footprint (K expansion) and many models. Uses velocity reparam to cut T.  
- *AR*: Fast training/inference; but fixed ordering and quantization introduce approximation bias. Clustering reduces cardinality at cost of detail.

**Failure Signatures**  
- *DF*: Out‑of‑memory during dataset expansion; underfitted models leading to poor Shape/Trend.  
- *AR*: Low β‑Recall or poor marginal fits, indicating insufficient binning or bad category merging.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can XGenBoost's generative models be effectively adapted for imputation tasks, and how does their imputation performance compare to state-of-the-art imputation methods?  
- **Basis in paper:** [explicit] The paper states in Section 5: "None of XGenBoost’s models have currently been adapted for imputation." and suggests possible approaches like using a Besag pseudo‑likelihood objective for the autoregressive model or an inpainting method for the diffusion model.  
- **Why unresolved:** The paper's focus is on synthetic data generation, not imputation. The suggested adaptations are not implemented or evaluated.  
- **What evidence would resolve it:** Implement imputation variants of both XGenB‑DF and XGenB‑AR, evaluate on standard imputation benchmark datasets (e.g., with missing values), and compare against dedicated imputation methods in terms of imputation accuracy and downstream task performance.

### Open Question 2
- **Question:** What sequence order for autoregressive factorization yields the best performance for XGenB‑AR on mixed‑type tabular data, and can we predict optimal orders based on dataset characteristics?  
- **Basis in paper:** [explicit] Section 3.2 mentions: "We use a fixed‑order factorization... We tried various approaches, such as an ordering based on increasing/decreasing mutual information, but this did not yield a consistent improvement on all evaluation dimensions." This indicates that the choice of order remains an open question.  
- **Why unresolved:** They tested a few heuristic orders but did not find a consistent winner, leaving the optimal ordering unknown and potentially dataset‑dependent.  
- **What evidence would resolve it:** Conduct a systematic study across diverse datasets, evaluating many ordering strategies (e.g., random, fixed original order, mutual information, feature type, causal discovery, etc.) and analyze which orders work best for which dataset types. Could also learn ordering as part of training.

### Open Question 3
- **Question:** How does the inference time of XGenB‑AR scale with the number of features in tabular datasets, and what architectural modifications could improve scalability to high‑dimensional data?  
- **Basis in paper:** [explicit] Section 5 says: "However, for the datasets in the Big Benchmark, we found that inference time is on‑par with that of diffusion models... However, we recognize that inference time may become an issue when datasets have hundreds or thousands of features."  
- **Why unresolved:** The paper only evaluates on datasets with up to 90 features (libras). Inference scaling beyond that is not tested.  
- **What evidence would resolve it:** Empirically measure inference time on datasets with increasing feature counts (e.g., by subsampling or generating synthetic high‑dimensional data), extrapolate scaling trends, and propose modifications like parallelization, early stopping, or learned order to reduce inference latency.

### Open Question 4
- **Question:** Can combining XGenB‑DF and XGenB‑AR into a hybrid generative model leverage the high fidelity of diffusion for some features and the efficiency of autoregression for others, leading to overall improved synthesis?  
- **Basis in paper:** [explicit] Section 6 proposes: "XGenB‑DF and XGenB‑AR can be combined into a hybrid approach, where XGenB‑DF is used to first synthesize a set of low‑risk or complex features with very high fidelity, and XGenB‑AR subsequently synthesizes more private or simpler features at reduced privacy risk and lower training cost, conditioned on features synthesized by XGenB‑DF."  
- **Why unresolved:** This hybrid approach is suggested but not implemented or evaluated.  
- **What evidence would resolve it:** Design and implement a hybrid model where features are partitioned (e.g., by type, cardinality, or privacy sensitivity) and synthesized sequentially using both architectures. Evaluate on benchmarks to see if hybrid outperforms individual models in fidelity, utility, privacy, or efficiency.

## Limitations
- XGenB‑DF’s data iterator and per‑timestep training orchestration are unspecified, risking memory explosion and timing issues.
- Baseline hyperparameters and Shape/Trend/Detection evaluation code are not fully disclosed, hindering fair comparison.
- XGenB‑AR’s fixed ordering, hierarchical quantization, and category clustering introduce approximations that may limit expressiveness, especially on high‑cardinality features; evaluation is limited to 38 benchmarks.

## Confidence
- Mixed‑type without one‑hot: **High**  
- Fidelity SOTA on small datasets: **Medium** (depends on exact baseline tuning)  
- Utility SOTA on large datasets: **Medium** (relies on XGenB‑AR approximations)  
- Training efficiency: **High** (XGBoost is inherently fast)  
- Scalability to large datasets: **Medium** (avoids K× blowup but ordering/quantization may limit)
