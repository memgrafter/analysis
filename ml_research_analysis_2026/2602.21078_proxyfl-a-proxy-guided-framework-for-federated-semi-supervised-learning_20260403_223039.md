# ProxyFL: A Proxy-Guided Framework for Federated Semi-Supervised Learning

## Quick Facts
- **arXiv ID:** 2602.21078
- **Source URL:** https://arxiv.org/abs/2602.21078
- **Reference count:** 40
- **Primary result:** Consistently outperforms SOTA with +1.51–3.39% accuracy and 2.64× faster convergence in heterogeneous FSSL.

## Executive Summary
ProxyFL is a novel framework for federated semi‑supervised learning (FSSL) that addresses two key heterogeneity challenges: external distribution shifts across clients and internal mismatch between labeled and unlabeled data. It introduces a proxy‑based approach where classifier weight vectors serve as category representatives. The server performs Global Proxy Tuning (GPT) to refine aggregated proxies against outliers, while clients use Indecisive‑Categories Proxy Learning (ICPL) to incorporate low‑confidence unlabeled samples via a positive‑negative proxy pool. Experiments on CIFAR‑10/100, SVHN, and CINIC‑10 with 10% labels show consistent improvements over state‑of‑the‑art methods, e.g., +1.51–3.39% absolute accuracy over SAGE and up to 2.64× faster convergence. By aligning local and global category representations, ProxyFL achieves both higher accuracy and faster convergence under varying degrees of data heterogeneity, making it a robust solution for real‑world FSSL deployments.

## Method Summary
ProxyFL operates in the FSSL setting where each client possesses a small labeled dataset and a larger unlabeled one. Each client maintains a feature extractor θ and a classifier with weight vectors ω serving as category proxies. Training alternates between local updates and server aggregation.

On the server, after receiving local proxies, it first aggregates them via FedAvg to obtain Ω_avg. Then Global Proxy Tuning (GPT) fine‑tunes these proxies using a contrastive loss that pulls each global proxy toward its corresponding local proxies while pushing it away from proxies of other categories. The tuned proxies Ω_G are broadcast to clients.

On each client, for every batch, unlabeled samples are split by confidence (using the global model). High‑confidence samples receive a pseudo‑label and are trained with a FixMatch‑style KL loss. Low‑confidence samples are handled by Indecisive‑Categories Proxy Learning (ICPL): an indecisive set ξ of plausible categories is built based on global class priors; a positive proxy is constructed as a weighted sum of local classifier weights for categories in ξ; negative proxies are drawn from samples with disjoint ξ. An InfoNCE‑like contrastive loss is applied between the sample’s feature and the positive/negative proxies. Combined with the supervised loss on labeled data, the local model updates θ and ω. The global prior P′_G(Y) is updated each round from aggregated client priors.

This design simultaneously tackles external heterogeneity via GPT and internal mismatch via ICPL, leading to improved performance and convergence.

## Key Results
- On CIFAR‑10/100, SVHN, and CINIC‑10 with 10% labels, ProxyFL achieves +1.51–3.39% higher test accuracy than SAGE across Dirichlet α = 0.1–1.
- It reaches 30% accuracy on CIFAR‑100 (α=0.1) 2.64× faster than prior methods.
- Ablations confirm both GPT and ICPL contribute gains, with the full model delivering the best performance.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Global Proxy Tuning (GPT) explicitly optimizes global category proxies against outliers, mitigating external heterogeneity more robustly than naive weight averaging.
- **Mechanism:** The server treats classifier weight vectors as category proxies. After aggregating local proxies via standard weighted averaging, it fine‑tunes them with a contrastive objective that pulls a global proxy toward its corresponding local proxies while pushing it away from proxies of other categories. This explicitly optimizes the global category distribution against skewed client contributions.
- **Core assumption:** Classifier weights can serve as effective, low‑dimensional category representatives whose distribution shift reflects external data heterogeneity.
- **Evidence anchors:** 
  - [abstract] "...explicitly optimize global proxy against outliers instead of direct weights"
  - [section 5.1] Detailed loss function `L_GPT` and optimization on server.
  - [corpus] Neighbors focus on aggregation or debiasing, not explicit proxy optimization (weak indirect support).
- **Break condition:** If outlier client proxies are numerous or extreme, the contrastive tuning objective may struggle to find a globally representative centroid without additional regularization.

### Mechanism 2
- **Claim:** Indecisive‑Categories Proxy Learning (ICPL) incorporates low‑confidence unlabeled samples via a multi‑label "indecisive set" and a positive‑negative proxy pool, reducing pseudo‑label errors and internal heterogeneity.
- **Mechanism:** For a low‑confidence unlabeled sample, instead of assigning a single (potentially wrong) pseudo‑label, it constructs an `indecisive‑categories set` ξ based on global category priors. A sample's "positive proxy" is a weighted sum of local classifier weights for categories in ξ. It then forms a contrastive "positive‑negative proxy pool" where samples with disjoint ξ are negatives, enabling training on all samples while mitigating label noise.
- **Core assumption:** A set of plausible categories for an ambiguous sample increases the probability of including the true label compared to a single pseudo‑label, and contrastive learning with this fuzzy supervision is effective.
- **Evidence anchors:** 
  - [abstract] "...re‑include the discarded samples into training by a positive‑negative proxy pool to mitigate the impact of potentially‑incorrect pseudo‑labels."
  - [section 5.2] Full specification of ξ construction (Eq. 4), positive/negative proxy definitions (Eq. 6‑7), and ICPL loss (Eq. 8).
  - [section 6.3.4] Fig. 6 shows higher recall for ξ vs. single pseudo‑label accuracy.
- **Break condition:** If global prior `P'_G(Y)` is highly inaccurate due to severe server‑side drift or if the indecisive set becomes too large/noisy, the positive proxy construction may become uninformative.

### Mechanism 3
- **Claim:** The proxy‑based framework enables faster convergence and improved stability under heterogeneity by aligning local and global category representations.
- **Mechanism:** GPT provides a globally‑tuned, robust category reference for all clients. ICPL ensures all local samples (including low‑confidence) are trained with reference to these proxies via contrastive learning, creating a consistent learning objective across the federation. Theoretical analysis (Appendix C) shows convergence under standard smoothness/boundedness assumptions for both the server‑side GPT and client‑side ICPL optimization.
- **Core assumption:** Aligning local training objectives to a globally optimized proxy space reduces divergence among client models and stabilizes learning.
- **Evidence anchors:** 
  - [abstract] "It also converges significantly faster, e.g., 2.64× speedup..."
  - [section 6.3.2] Fig. 5(b) & Tab. 3 show faster early‑stage convergence.
  - [section C] Theorem 1 & 2 provide convergence proofs for the bi‑level optimization.
- **Break condition:** If the local model capacity is insufficient to align with the proxy space, or if communication frequency is too low, the convergence guarantees may not hold in practice.

## Foundational Learning
- **Concept: Federated Semi‑Supervised Learning (FSSL)**
  - *Why needed here:* The entire framework operates under the FSSL setting (Label‑at‑All‑Client) where each client has a small fraction of labeled data and abundant unlabeled data. This defines the core problem of heterogeneity in both labeled/unlabeled distributions (internal) and across clients (external).
  - *Quick check question:* What are the two distinct forms of data heterogeneity in FSSL, and which part of ProxyFL targets each?
- **Concept: Non‑IID / Data Heterogeneity in FL**
  - *Why needed here:* The design of GPT is a direct response to non‑IID classifier weight distributions across clients (Fig. 2a). The paper's experiments systematically vary Dirichlet α to control this external heterogeneity.
  - *Quick check question:* Why does simple FedAvg (or weight averaging) of classifiers fail under high external heterogeneity?
- **Concept: Contrastive Learning with Proxy Anchors**
  - *Why needed here:* ICPL uses a contrastive loss where the "positive" is a proxy (weighted sum of class weights) and "negatives" are features from samples with disjoint category sets. This is a specific application of contrastive principles to semi‑supervised FL with fuzzy labels.
  - *Quick check question:* In ICPL, what defines the positive proxy for a low‑confidence sample, and what makes a sample a negative candidate?

## Architecture Onboarding
- **Component map:**
  - **Server-side:** Global Proxy Tuning (GPT) module. Input: Uploaded local classifier weights `{ω_m}`. Output: Tuned global proxies `Ω_G`. Process: Contrastive optimization (Eq. 2) for `Q` epochs.
  - **Client-side:** Indecisive‑Categories Proxy Learning (ICPL) module. Input: Local batch (labeled, high‑conf unlabeled, low‑conf unlabeled), local model `f_m, h_m`, global model `f_G, h_G`, global prior `P'_G(Y)`. Output: `L_ICPL` loss. Process: Build category sets ξ, construct positive‑negative proxy pool, compute contrastive loss (Eq. 8). Also computes standard supervised (`L_s`) and FixMatch‑style (`L_u`) losses.
  - **Aggregation:** Standard FedAvg‑style for feature extractor parameters `θ` and *initial* classifier weights `ω` (before GPT). GPT outputs final `Ω_G` for next round.
- **Critical path:**
  1. Clients download global `(θ_G, Ω_G)`.
  2. Local training: compute `L_local = L_s + αL_u + βL_ICPL`; update `(θ_m, ω_m)`.
  3. Upload `(θ_m, ω_m)` to server.
  4. Server: aggregate `θ_G = Σ γ_m θ_m`, `Ω_G_avg = Σ γ_m ω_m`.
  5. Server: Run GPT optimization on `Ω_G_avg` for Q epochs to get final `Ω_G`.
  6. Repeat.
- **Design tradeoffs:**
  - *Proxy dimension (d):* Lower `d` (classifier weight size) reduces communication/computation but may lose representational capacity. Paper uses `d` from backbone (e.g., ResNet‑8 last layer).
  - *Tuning epochs (Q):* More epochs better fit client distribution but risk overfitting to client‑specific noise (Fig. 7). Paper sets Q=100 (CIFAR‑10/100/SVHN/CINIC‑10) and Q=10 (CIFAR‑100 due to more classes).
  - *Indecisive set threshold:* Relying on global prior `P'_G(Y)` is lightweight but assumes some correlation between global frequency and ambiguity. Alternative Top‑K selection is less adaptive.
- **Failure signatures:**
  1. **Poor convergence / oscillation:** Likely if ICPL's contrastive pool is too noisy (e.g., `ξ` sets are too large or disjointness criterion is too strict). Check distribution of |ξ| for low‑conf samples.
  2. **GPT proxies collapse or become outlier‑dominated:** Visualize t‑SNE of `Ω_G` vs. local `ω_m` (Fig. 5c). If `Ω_G` still aligns with a few outlier clients, GPT may have insufficient epochs or learning rate issues.
  3. **Performance degradation on high‑heterogeneity (α small):** Often due to ICPL failing to recover useful signal from low‑conf samples. Monitor the ratio of "correct category in ξ" (Fig. 6); if this is low, the prior `P'_G(Y)` may be unreliable early in training.
- **First 3 experiments:**
  1. **Module Ablation (Tab. 2):** Run with only GPT, only ICPL, both, and neither (baseline GPL). Expect both modules to individually improve baseline, with combination giving best results. Confirms both mechanisms address different heterogeneities.
  2. **Convergence Rate Analysis (Tab. 3 & 8):** Track rounds to reach accuracy thresholds (30%, 40%, 50%) on CIFAR‑100 with α=0.1, 0.5, 1. Expect ProxyFL to reach thresholds significantly faster (2×‑3× speedup) than SAGE and other FSSL baselines.
  3. **Proxy vs. Prototype Comparison (Tab. 5):** Replace classifier‑weight proxies with feature‑based prototypes (FedProto‑style). Expect ProxyFL (using model‑intrinsic weights) to outperform, especially on SVHN where prototype methods may fail catastrophically (`19.59%` for PROTO‑ALL), due to privacy risks or reconstruction issues with high‑dimensional features.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can we robustly aggregate client category distributions under data heterogeneity while preserving privacy?
- **Basis in paper:** [explicit] The authors explicitly question whether aggregation weights can be improved beyond simple averaging to better fit the global distribution.
- **Why unresolved:** ProxyFL introduces global proxy tuning but does not explore alternative aggregation strategies (e.g., robust statistics) or provide strong robustness guarantees.
- **What evidence would resolve it:** Empirical evaluation of multiple aggregation methods; theoretical analysis under adversarial settings; sensitivity to outlier proportions.

### Open Question 2
- **Question:** What methods can effectively include low‑confidence unlabeled samples in federated semi‑supervised learning without harming accuracy?
- **Basis in paper:** [explicit] Authors ask how to leverage low‑confidence samples, noting current methods discard them.
- **Why unresolved:** ProxyFL's indecisive‑categories set and prior P′_G(Y) are heuristic; optimal thresholding and set construction remain open.
- **Evidence:** Systematic study of threshold τ and set‑size; alternative probabilistic formulations; evaluation on ambiguous‑sampled datasets; robustness to prior miscalibration.

### Open Question 3
- **Question:** Can proxy‑guided FSSL be adapted to settings with extreme label scarcity (e.g., only a few clients have labels)?
- **Basis in paper:** [inferred] The paper only addresses Label‑at‑All‑Client; scenarios with partial or server‑only labels are unstudied.
- **Why unresolved:** GPT and ICPL rely on per‑client category statistics; clients without labels cannot compute local proxies or preferences, breaking the mechanism.
- **Evidence:** Extend ProxyFL with server‑side distillation or client clustering; experiments on partial‑label FSSL benchmarks; theoretical convergence analysis with imbalanced label participation.

## Limitations
The paper identifies several limitations and open issues:
- **Hyperparameter sensitivity:** GPT requires careful tuning of tuning epochs Q; the paper uses ad‑hoc values (100 vs. 10). Impact on stability and performance across datasets is unclear.
- **Global prior update protocol:** The timing of updating P′_G(Y) (before vs. after local training) and handling of empty indecisive sets are unspecified, potentially affecting ICPL reliability.
- **Proxy scalability:** Using classifier weights as proxies assumes they are low‑dimensional and informative; this may not hold for deeper networks or high‑class‑count datasets.
