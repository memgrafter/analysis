# Features as Rewards: Scalable Supervision for Open-Ended Tasks via Interpretability

## Quick Facts
- **arXiv ID:** 2602.10067
- **Source URL:** https://arxiv.org/abs/2602.10067
- **Reference count:** 40
- **Primary result:** RLFR reduces hallucinations by 58% on Gemma-3-12B-IT while costing ~90× less than using an LLM judge.

## Executive Summary
Hallucination reduction is an open-ended task where standard reinforcement learning (RL) requires expensive LLM judges for reward computation. This paper introduces Reinforcement Learning from Feature Rewards (RLFR), which uses interpretability probes to construct dense, well-calibrated reward signals from a frozen base model’s internal features. A two-stage probe system detects potential hallucinated entities and scores intervention quality (retraction/correction). These feature-based rewards train a policy via RL to intervene proactively. Combined with test-time Best-of-N sampling guided by the same probes, RLFR achieves a 58% hallucination reduction on Gemma-3-12B-IT, decomposing gains into a less hallucinatory policy, in-context corrections, and direct fixes. The approach is significantly cheaper than LLM-judge RL and maintains general benchmark performance.

## Method Summary
RLFR operates through a pipeline of lightweight linear probes trained on activations from a frozen base model. First, a Localization probe identifies entity spans in streaming text. A Classification probe then scores each entity for hallucination likelihood; if above a threshold, generation halts. The policy samples intervention candidates (retract or correct) for that entity. A Correction or Retraction probe—trained to imitate an LLM judge’s rubric—scores each candidate, providing the reward signal for a PPO-style RL update. This avoids costly per-step LLM calls. At inference, the system scales test-time compute via Best-of-N: for each detected entity, multiple intervention candidates are generated, the action type is chosen by majority vote, and the highest-scoring candidate among them is selected. Interventions can be inlined or collected separately.

## Key Results
- RLFR with Best-of-32 sampling reduces hallucinations by 58% compared to the original model.
- The reduction decomposes into: 10% from a less hallucinatory learned policy, 35% from in-context (inline) interventions, and 13% from direct intervention success.
- The approach costs approximately 90× less than an RL setup using an LLM judge for rewards.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Detection probes localize and classify potential hallucinations in streaming text, enabling targeted intervention.
- **Mechanism:** A two-stage probe system processes activations from the base model: a **Localization probe** (token-level) identifies entity spans, and a **Classification probe** (span-level) scores each entity for hallucination likelihood. If the score exceeds a threshold (0.7), the system halts generation to intervene on that first exceeding entity.
- **Core assumption:** The localization probe can reliably segment atomic factual claims, and the classification probe's predictions correlate with ground-truth factuality.
- **Evidence anchors:** [abstract] "novel probing framework that identifies candidate hallucinated claims"; [section 3.1] "Localization probe... classify Entities... when Classification probe fires"; [section B.3] detailed probe architectures.
- **Break condition:** Precision/recall degrade on policy activations, causing missed hallucinations or false positives that waste intervention budget.

### Mechanism 2
- **Claim:** Reward probes convert model features into cheap, dense supervision signals for RL, replacing expensive LLM judges.
- **Mechanism:** For each detected entity, the policy samples interventions (retract/correct). A **Correction probe** or **Retraction probe** (trained on base model activations and labels from an LLM judge) scores the intervention's quality. Probe outputs are used as rewards in a standard PPO-style RL update.
- **Core assumption:** Probe scores are well-calibrated proxies for the gold-standard judge's labels, and this ordering transfers to the student policy's activations without needing the base model at inference.
- **Evidence anchors:** [abstract] "features as reward functions... dense, well-calibrated reward signals"; [section 3.3] "train a probe to imitate the reward pipeline... cheap and dense reward"; [section 4.2] "Fixed and Retracted rates when the reward pipeline was run on activations from the base model versus the policy... activation source essentially does not change the Fixed or Retracted rates".
- **Break condition:** Probe rewards fail to correlate with gold labels on student model rollouts, causing reward hacking or stalled learning.

### Mechanism 3
- **Claim:** Test-time compute scalability via Best-of-N sampling guided by reward probes further reduces hallucinations.
- **Mechanism:** For each detected entity, the policy generates N intervention candidates. The action (retract/correct) is chosen by majority vote. Among candidates of the winning action, the one with the highest probe score is selected. This sampled intervention is either inlined or collected separately.
- **Core assumption:** The reward probe produces a reliable ranking of intervention quality within the same policy's output distribution.
- **Evidence anchors:** [section 4.2] "scale test time compute via BoN sampling... aggregate over n rollouts by majority voting to choose the action and then taking the highest rewarded sample"; [figure 7] probe-guided BoN outperforms LLM-judge BoN at N=256.
- **Break condition:** Scaling N yields diminishing returns; the probe ranking fails to discriminate quality interventions, causing both false positives and missed fixes to persist.

## Foundational Learning

### Concept: Probing for Interpretability
- **Why needed here:** The entire pipeline hinges on measuring model beliefs (factuality) via linear probes over activations. A new engineer must understand how probes are trained, validated (AUC, calibration), and applied in streaming generation.
- **Quick check question:** How would you diagnose a probe that has high validation AUC but low recall during streaming inference on a different model?

### Concept: Reinforcement Learning from Synthetic Rewards
- **Why needed here:** RLFR replaces human/LLM judges with feature-based rewards. An engineer must grasp standard PPO/GRPO objectives, the importance of reward shaping, and handling off-policy data (importance sampling clipping).
- **Quick check question:** What's the risk of using a frozen base model's probes to reward a student policy whose activations have drifted, and how does the paper mitigate it?

### Concept: Calibration and Reward Transfer
- **Why needed here:** Rewards must be well-calibrated (e.g., probe score 0.8 means ~80% chance of gold label) and must transfer from base to student model. An engineer should understand how to measure calibration (reliability diagrams) and test transfer by comparing probe scores on base vs. student rollouts.
- **Quick check question:** If the correction probe is perfectly calibrated on base model activations but becomes miscalibrated on student activations, what symptoms would you see in the training curves?

### Concept: In-Context Learning for Intervention
- **Why needed here:** Inline interventions leverage the model’s in-context learning to correct its own mistakes. An engineer must understand the distinction between policy improvements and in-context effects, and how to design intervention placements.
- **Quick check question:** Why might inline interventions sometimes cause degeneracy loops, and what design choices in RLFR mitigate this?

### Concept: Reward Shaping with Rubrics
- **Why needed here:** Probe rewards are combined with judge-based rubrics (format, action match, substantiveness) during RL training to ensure interventions are not only factually correct but also well-formed.
- **Quick check question:** How does the use of a multiplicative rubric-reward help prevent the policy from exploiting a single reward component?

## Architecture Onboarding

### Component map
Data Collection Pipeline -> Probe Suite -> RL Loop -> Inference Engine
- Data Collection Pipeline: Generates completions from base model, extracts entities (LLM grader), verifies with web search, samples interventions.
- Probe Suite: Four modules: Localization (token span detection), Classification (hallucination likelihood), Correction (intervention quality), Retraction (intervention quality).
- RL Loop: For each batch: generate from student policy, detect entities via probes on base activations, sample interventions, compute rewards (probe scores + rubrics), PPO/GRPO update with KL penalty.
- Inference Engine: Streaming generation with probe-based interruption, intervention sampling (vanilla/Best-of-N), and inline/not-inline placement.

### Critical path
1. Pre-train probes on labeled dataset derived from π_base and LLM-verified labels.
2. Initialize π_student = π_base. Start RL loop:
   a. Sample prompts → generate completions.
   b. Prefill with π_base → get activations → run Localization/Classification probes.
   c. For each entity above threshold, sample K intervention candidates from π_student.
   d. For each candidate, compute reward: apply rubric judges → use appropriate probe score (clipped) → Lagrange adjustment for retract/correct balance.
   e. Compute group advantages (mean-normalized over candidates per entity) → update π_student with K1 KL estimator.
   f. Optionally update π_ref every N steps.

### Design tradeoffs
- **Frozen base vs. policy probes:** Training rewards on base activations avoids probe evasion but assumes feature correspondence; training on policy activations risks reward hacking but may better match policy representations. Here they choose base features and validate transfer (Fig 9c).
- **Probe simplicity:** Low-capacity probes (linear attention) are sample-efficient and less prone to overfit than LLM judges, but may underfit complex intervention quality.
- **Inline vs. Not-inline:** Inline leverages in-context learning but risks degeneracy if interventions confuse the model. Not-inline measures direct policy capability but ignores ICL effects.

### Failure signatures
- **Probe transfer failure:** Drop in Fixed/Retract rates when running reward probes on student vs. base activations (Fig 9c shows none here).
- **Degeneracy loops:** Probes fire repeatedly after inline interventions, causing non-terminating rejection loops (mitigated by appending newlines).
- **Off-target effects:** Policy learns to reduce hallucinations by becoming generally less verbose (measured by KL divergence on non-hallucinated tokens remains low ~0.015).
- **Reward misspecification:** If probe rewards don't align with gold judge, policy could optimize for probe scores while producing worse interventions (checked by comparing to final Gemini evaluation).

### First 3 experiments
1. **Probe validation:** Train Localization and Classification probes on base model activations. Measure AUC (>0.94) and calibration on validation set. Then simulate streaming by running probes on policy rollouts and compute precision/recall at threshold 0.7 (~0.85 precision, ~0.56 recall inline).
2. **Reward transfer test:** For a fixed set of intervention candidates from the base model, compute probe scores on base vs. student activations. Confirm Fixed/Retract rates are nearly identical (Fig 9c).
3. **End-to-end ablation:** Compare (a) Base+Monitor, (b) RLFR (no BoN), (c) RLFR+BoN32, (d) RLFR-NI on hallucination rate. Decompose reduction into Policy, In-Context, Direct components (Fig 4, Table 13 rows 1, 4, 7, 16).

## Open Questions the Paper Calls Out
- **Open Question 1:** Can RLFR be effectively applied to other open-ended tasks beyond hallucination reduction, such as reducing verbosity, controlling agreeableness, or improving reasoning efficiency? (Section 5.1)
- **Open Question 2:** How can a cascade of reward functions be designed, where an expensive LLM judge is invoked only when feature-based probes are uncertain? (Section 5.1)
- **Open Question 3:** What are the causal mechanisms by which inline interventions reduce hallucinations—specifically, how do they alter the model's internal representations and in-context beliefs? (Section 5.1)
- **Open Question 4:** Does optimizing a policy against frozen feature probes induce systematic probe evasion or degradation in probe reliability over long-horizon training? (Section 5.2)
- **Open Question 5:** For which abstract concepts (e.g., truthfulness, harm, sycophancy) are model features reliably calibrated and thus suitable as reward signals? (Inferred)

## Limitations
- Probe transfer assumption is validated only on one model pair (Gemma-3-12B-IT); transfer may fail for divergent architectures or large behavioral drift.
- Gold labels rely on a single LLM judge (Gemini 2.5 Pro) with web search; judge disagreement or ground-truth ambiguity could affect results.
- The method is tailored to hallucination as discrete entity errors; generalization to other open-ended tasks with less clearly defined interventions is untested.
- Inline interventions cause degeneracy loops in ~3% of cases; mitigation (appending newlines) is heuristic.

## Confidence
- **Hallucination reduction efficacy (58%):** High – Rigorously decomposed with multiple ablations.
- **Cost efficiency vs. LLM judge (~90× cheaper):** Medium – Cost model assumptions are plausible but not systematically varied.
- **Probe-based reward transfer:** Medium – Transfer test is convincing but narrow; lacks stress tests.
- **Scalable supervision for open-ended tasks:** Low-Medium – Validated only on one well-defined task; broader claim extrapolates.

## Next Checks
