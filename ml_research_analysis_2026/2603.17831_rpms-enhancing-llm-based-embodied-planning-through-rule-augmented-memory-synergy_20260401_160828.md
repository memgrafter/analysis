# RPMS: Enhancing LLM-Based Embodied Planning through Rule-Augmented Memory Synergy

## Quick Facts
- arXiv ID: 2603.17831
- Source URL: https://arxiv.org/abs/2603.17831
- Reference count: 40
- Primary result: RPMS achieves 59.7% single-trial success on unseen ALFWorld tasks with Llama 3.1 8B (+23.9 pp over ReAct) and 98.5% with Claude Sonnet 4.5 (+11.9 pp), with rule retrieval alone contributing a statistically significant +14.9 pp gain; it also transfers to ScienceWorld (+9.1 avg. score).

## Executive Summary
Large language model (LLM) agents struggle in closed-world embodied environments (e.g., ALFWorld, ScienceWorld) because actions have strict preconditions and feedback is sparse, leading to invalid actions and progressive state drift. RPMS (Rule-Augmented Memory Synergy) addresses these failures through a conflict-managed architecture that enforces action feasibility via structured rule retrieval, gates episodic memory applicability using a lightweight belief state, and resolves conflicts via a rules-first arbitration policy. In evaluations on 134 unseen ALFWorld tasks, RPMS achieves 59.7% single-trial success with Llama 3.1 8B—a 23.9 percentage point gain over ReAct—and 98.5% with Claude Sonnet 4.5 (+11.9 pp). Rule retrieval alone contributed a statistically significant +14.9 pp improvement. Episodic memory, while harmful without filtering, becomes beneficial when combined with state-consistent filtering and arbitration. Moreover, RPMS transfers to ScienceWorld with GPT-4, yielding a +9.1 average score improvement, confirming the approach generalizes across distinct environments.

## Method Summary
RPMS is an inference-time modular system that enhances LLM planning without model training. At each step, it updates a deterministic belief state from the observation, retrieves relevant rules from a three-tier manual and episodic memories from a pre-populated store, filters memories for state compatibility, arbitrates conflicts with a rules-first policy, and constructs a prompt containing active rules, filtered memories, and the current state. The learning phase runs 140 seen ALFWorld tasks with rules-only to collect successful and failure snippets, applying deduplication to create a frozen memory bank. Baselines include ReAct with identical prompts but no knowledge injection.

## Key Results
- ALFWorld: 59.7% success (Llama 3.1 8B, +23.9 pp over ReAct) and 98.5% (Claude Sonnet 4.5, +11.9 pp).
- Rule retrieval alone yields +14.9 pp (statistically significant); memory is only beneficial with state-consistent filtering, otherwise harmful.
- ScienceWorld transfer with GPT-4: +9.1 average score over baseline.

## Why This Works (Mechanism)
### Mechanism 1: Reducing Invalid Actions via Rule-Based Feasibility Enforcement
RPMS reduces invalid action generation (P1) by injecting a three-tier hierarchical rule manual (Universal, Domain, Environment) into the LLM prompt at each step. These rules explicitly encode action preconditions (e.g., "heat is atomic, object stays in hand"), making feasibility criteria visible during decision-making rather than relying on latent knowledge. The core assumption is that explicit precondition semantics at inference time are more reliable for deterministic action spaces than prompting the model to infer them. Evidence includes the statistically significant +14.9 pp gain from rule retrieval alone. Performance degrades if the rule manual is incomplete or contains incorrect rules.

### Mechanism 2: Mitigating State Drift via State-Consistent Memory Filtering
RPMS mitigates state drift (P2) by gating episodic memory with a lightweight belief state filter (SCF). Before memories enter the prompt, they are filtered against a belief state signature (location, hand occupancy). Only memories with compatible preconditions (e.g., a "take" snippet requires hand empty if that was the case when recorded) are allowed. The assumption is that a compact deterministic belief state suffices to filter out corrupted advice. Evidence includes the ablation showing memory-only helps (+5.2 pp) but full RPMS gains more (+23.9 pp), proving SCF is critical. Limitation: belief state simplicity may let some mismatches through.

### Mechanism 3: Resolving Conflicts via Rules-First Arbitration
RPMS resolves conflicts between rule-based and memory-based guidance through a rules-first arbitration policy. After SCF, surviving memories are checked against active rules; entries suggesting actions that violate a rule are hard-removed, while non-contradictory but potentially conflicting entries receive a soft warning tag for the LLM to adjudicate. The assumption is that in closed-world settings with strict preconditions, rule-defined constraints are inviolable ground truth, while memory provides heuristic guidance. Evidence: naive combination (47.8%) underperforms rules-only (50.7%), while full arbitration (59.7%) yields clear improvement. Break condition: missing rules or ignored soft warnings can limit gains.

## Foundational Learning
- **Closed-world embodied environments**: Environments where actions have strict, often implicit preconditions and failures return sparse signals (e.g., "Nothing happens"). RPMS targets these, as standard ReAct fails due to invalid actions and state drift. *Quick check:* If an agent tries to `take apple` while already holding an object in ALFWorld, what happens, and why does this cause state drift?
- **Retrieval-Augmented Generation (RAG) for LLM agents**: RPMS uses RAG to inject structured rules and episodic experiences at inference time. The key difference: retrieving a general rule (e.g., "check open containers") vs. a specific past action sequence ("open fridge → take mug") is that rules encode constraints while memories provide heuristic strategies.
- **Factored belief state tracking**: RPMS maintains a minimal, deterministic approximation of the world state (e.g., location, hand occupancy) rather than a full model. This simplification enables efficient state-consistent filtering. *Quick check:* Why does RPMS track `holding=empty` as a binary flag instead of enumerating all objects?

## Architecture Onboarding
**Component map**:  
Observation → BeliefState Tracker → (Rule Manual retrieval, Episodic Memory retrieval) → State-Consistent Filtering → Rules-First Arbitration → Prompt Builder → LLM Decoder → Action → Environment → new Observation.

**Critical path**: The flow from observation to action: parse observation to update belief state; in parallel, query rule manual and memory store based on goal and belief signatures; apply SCF; apply arbitration; assemble prompt; generate action via LLM; execute.

**Design tradeoffs**:
- Rule manual completeness vs. authoring effort: High coverage needed for reliability, but manual creation is a bottleneck.
- Belief state simplicity vs. filtering precision: Simple occupancy signals are easy to maintain but may miss nuanced preconditions (e.g., container states).
- Memory entry granularity: Longer snippets provide context but become brittle; shorter ones lack context.
- Rules-first arbitration: Prevents rule violation but may discard memories with partially correct advice.

**Failure signatures**:
- High timeout rate: suggests missing or ignored rules.
- Task-type specific drops (e.g., Look tasks) when memory is used without proper filtering.
- Increased early incorrect terminations when rules are enforced (agent becomes more decisive).
- Belief state divergence from true state due to parsing failures.

**First 3 experiments**:
1. Compare RPMS (with Llama 3.1 8B) against ReAct on 134 unseen ALFWorld tasks, expecting >20 pp gain.
2. Conduct 2×2 ablation (Rules ON/OFF × Memory ON/OFF) to isolate contributions; expect Rules single-factor gain > Memory, and Full RPMS synergistic.
3. Ablate State-Consistent Filtering within Full RPMS to quantify its impact; expect significant drop (e.g., ~6 pp) confirming its necessity.

## Open Questions the Paper Calls Out
- **Automatic rule induction for environment-specific tier**: Can the Tier 3 rules be derived automatically from environment feedback? Manual authoring is a bottleneck; evidence would be an automated system producing verified rules with performance matching human-authored ones.
- **Finer-grained conflict arbitration**: Does entry-level arbitration limit performance? Sub-entry parsing (e.g., separating action sequences from context) could recover additional gains if it allows partial memory usage.
- **Consistent backbone evaluation across environments**: The paper uses different LLMs for ALFWorld and ScienceWorld, so it's unclear if gains are architectural or model-dependent. Testing both with the same model would isolate this.
- **Extending SCF beyond hand-occupancy**: SCF's lightweight proxy may let through mismatched memories in richer environments. A more expressive filter checking additional state variables could improve precision.
- **Memory quality/diversity and minimal set**: The relationship between memory coverage/diversity and performance is unclear. Systematic ablations varying memory subsets could identify the minimal effective memory.

## Limitations
- The exact rule manual content beyond provided examples is unknown; reproduction requires authoring a comprehensive set, risking omissions that affect performance.
- Memory learning algorithm (smart deduplication across rounds) is unspecified; assumed merging logic may alter memory composition.
- Retrieval threshold and scoring function are not quantified; heuristic implementations may diverge from intended behavior.

## Confidence
- ALFWorld success rate improvement (+23.9 pp) with Llama 3.1 8B: **High**.
- ScienceWorld transfer (+9.1 avg. score) with GPT-4: **Medium**.
- Conditional utility of memory (memory-only slight gain, combined large synergy): **High**.
- Rules-first arbitration benefit (naive combination worse, full arbitration better): **High**.

## Next Checks
1. **Probe rule completeness**: Stress-test the authored rule manual on a sample of failed ALFWorld tasks; if failures map to missing/unencoded preconditions, the manual is incomplete.
2. **SCF sensitivity analysis**: Replace the hand-occupancy filter with an oracle belief state (using ground-truth environment state) to measure potential upper-bound gains.
3. **Arbitration conflict audit**: Log memory entries flagged by hard removal vs. soft warnings; if many soft-conflict entries contain valid sub-advice, current entry-level arbitration may be overly aggressive.
