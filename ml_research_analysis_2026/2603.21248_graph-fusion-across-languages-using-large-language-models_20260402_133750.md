# Graph Fusion Across Languages using Large Language Models

## Quick Facts
- **ArXiv ID:** 2603.21248
- **Source URL:** https://arxiv.org/abs/2603.21248
- **Reference count:** 0
- **Primary result:** Achieves 88.0% precision at τ=0.90 and 88.3% Hits@1 on DBP15K Chinese‑English entity alignment in a zero‑shot setting, with recall 23.6%.

## Executive Summary
This paper addresses cross‑lingual knowledge graph fusion without relying on any pre‑aligned seed pairs. The authors propose a framework that uses large language models to align entities and relations across multilingual graphs. Triplets are linearized into natural language, grouped into entity‑centric batches to fit the LLM’s context, and processed in a sequential agglomeration pipeline with max‑confidence aggregation.

On the DBP15K Chinese‑English dataset, the method achieves 88.0% precision at a 0.90 confidence threshold and 88.3% Hits@1 accuracy on the predicted alignments. Although recall remains modest (23.6%) due to context limitations, the results demonstrate that LLMs can serve as effective zero‑shot semantic bridges for cross‑lingual KG integration.

## Method Summary
The framework processes two input KGs (or a fused graph plus a new candidate) in three stages. First, a **Partitioner** splits each graph’s triplets into batches by grouping all triplets that share the same head entity. Each batch is sized to stay within the LLM’s token limit, thereby preserving the local 1‑hop neighborhood. Second, a **Batch Pair Generator** forms the Cartesian product of all source and target batches, ensuring exhaustive coverage of potential alignments. Third, for each batch pair, a **Prompt Composer** linearizes the triplets into plain “head relation tail” strings and submits them to an LLM (Gemini 2.5 Flash, temperature 0.0) with a system message that requests JSON‑formatted alignments with confidence scores.

The LLM’s raw outputs are fed to a **Response Parser** that extracts valid JSON objects, falling back to partial‑JSON recovery when needed. An **Aggregator** then applies max‑confidence aggregation: for each source entity, the highest confidence target among all batch‑pair predictions is retained. Finally, a **Graph Merger** incorporates all predictions with confidence ≥ τ (default 0.90) into the unified graph by merging the corresponding entities and their relations. This pairwise fusion step can be repeated sequentially to incorporate an arbitrary number of graphs.

## Key Results
- Precision 88.0% at τ=0.90 on DBP15K Chinese‑English entity alignment.
- Hits@1 accuracy of 88.3% on the set of generated predictions.
- Recall is limited to 23.6% due to context constraints and strict thresholding.

## Why This Works (Mechanism)
**Linearization for Zero‑Shot Bridging**  
The framework converts each triplet into a simple natural language string (“head relation tail”). This linearization allows the LLM to apply its pre‑trained multilingual knowledge to map corresponding surface forms (e.g., “capital_of” ↔ “首都是”) without requiring explicit vector‑space alignment. The model reasons about entity and relation semantics based on the textual representation, effectively acting as a cross‑lingual semantic matcher. This approach depends on the assumption that the LLM’s internal knowledge contains adequate cross‑lingual information; if linearization strips too much structural nuance (e.g., entities with identical names but different topological roles), disambiguation performance deteriorates.

**Entity‑Centric Partitioning Preserves Local Context**  
Grouping triplets by head entity ensures that each batch delivered to the LLM contains the complete 1‑hop relational neighborhood of that head. This local structure provides contextual clues (co‑occurring relations and tail entities) that help the model distinguish between ambiguously named entities. The design presumes that a 1‑hop view is sufficient for most disambiguation; however, for entities whose global position (e.g., hub nodes) is needed for correct resolution, the partitioning may still lead to errors.

**Max‑Confidence Aggregation Filters Noise**  
Because each source‑target batch pair is processed independently, the same candidate alignment may appear multiple times with varying confidence scores. The aggregator keeps the maximum observed confidence for each pair, effectively crowdsourcing the model’s certainty across different local contexts. This filtering step discards spurious one‑off matches and stabilizes the sequential fusion against transitive error propagation. The empirical gap between true positives (mean confidence 0.980) and false positives (0.738) confirms that confidence is a reliable discriminator when a high threshold is applied.

## Architecture Onboarding
**Component map:**  
Input -> Partitioner -> Batch Pair Generator -> Prompt Composer -> LLM Engine -> Response Parser -> Aggregator -> Graph Merger

**Critical path:** Partition → Pair → Prompt → LLM → Parse → Aggregate → Merge. In the multi‑graph scenario this path repeats for each fusion step (N‑1 times for N input graphs).

**Design tradeoffs:**  
- **Precision vs. Recall:** The confidence threshold τ is the primary knob; higher τ yields higher precision but caps recall.  
- **Exhaustive vs. Selective Pairing:** Exhaustive Cartesian pairing guarantees discovery but is computationally heavy (768 pairs for DBP15K). Future work considers heuristic blocking for efficiency.  
- **Local vs. Global Context:** Entity‑centric batches manage the LLM’s context window but may miss global topological cues needed for some disambiguation cases.

**Failure signatures:**  
1. **Low prediction volume:** Number of unique alignments predicted is far below the ground‑truth size (e.g., 5 416 out of 15 000), indicating recall bottlenecks.  
2. **Confidence‑polarized errors:** A large gap between mean confidence of true positives (0.980) and false positives (0.738) is expected, but if many true positives fall below τ, recall suffers.  
3. **Parsing failures:** Malformed LLM outputs that the parser cannot salvage result in silent data loss for that batch pair.

**First 3 experiments to run:**  
1. **Sanity check linearization:** Feed a small set of gold‑aligned entity pairs through the exact prompt template and verify the LLM returns the expected alignment in the correct JSON format.  
2. **Vary τ on a subset:** Test thresholds (0.8, 0.9, 0.95) on a single graph pair to observe the precision‑recall tradeoff before scaling to the full dataset.  
3. **Test partition granularity:** Compare 1‑hop (baseline) against 2‑hop entity‑centric batches to quantify the effect of local context scope on precision, recall, and confidence calibration.

## Open Questions the Paper Calls Out
1. **How does replacing exhaustive Cartesian batch pairing with a heuristic semantic indexing strategy impact the precision‑recall trade‑off and computational efficiency of the fusion framework?**  
   *Basis:* Section 6 proposes moving from exhaustive pairing to a multi‑stage heuristic blocking and semantic indexing to reduce overhead and improve recall.

2. **Does incorporating global structural context (e.g., schema‑level summaries or hub node overviews) via hierarchical prompting reduce disambiguation errors for entities with identical surface labels but different ontological roles?**  
   *Basis:* Section 6 suggests integrating global context through hierarchical prompting to overcome the limitations of localized triplet views.

3. **Can curated integration sequences based on linguistic proximity or graph density mitigate transitive error propagation during sequential agglomeration of multiple graphs?**  
   *Basis:* Section 6 explores investigating merge orders that minimize semantic drift as more graphs are added, especially across linguistically distant languages.

4. **How effective are hybrid architectures where LLM‑generated alignments serve as “silver seeds” to bootstrap traditional GNN‑based aligners, combining zero‑shot reasoning with structural efficiency?**  
   *Basis:* Section 6 discusses using LLM outputs to initialize or fine‑tune GNNs for self‑improving systems, aiming to combine the high precision of LLMs with the recall of GNNs.

## Limitations
- Unspecified prompt wording and parsing logic affect reproducibility.
- Low recall (23.6% at τ=0.90) due to context constraints and strict thresholding.
- Sequential agglomeration risks transitive error propagation; not evaluated beyond pairwise fusion.

- **Entity‑centric partitioning:** Medium
