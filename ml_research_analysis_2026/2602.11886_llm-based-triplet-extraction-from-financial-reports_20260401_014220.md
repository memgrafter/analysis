# LLM-based Triplet Extraction from Financial Reports

## Quick Facts
- **arXiv ID:** 2602.11886  
- **Source URL:** https://arxiv.org/abs/2602.11886  
- **Reference count:** 4  
- **Primary result:** An ontology-driven evaluation pipeline with automatic document-specific ontology induction achieves 100% Ontology Conformance and, combined with hybrid verification (regex + LLM-as-a-judge), reduces Subject/Object Hallucination dramatically (e.g., SH from 65.2% to 1.6%).

## Executive Summary
This study tackles the absence of ground truth for evaluating LLM-based triplet extraction from financial annual reports. It proposes an ontology-driven pipeline that compares static manual ontologies against automatic per-document ontology induction. Using Gemini-2.5 Flash and Llama 4 Maverick on two reports, the pipeline chunks text, prompts extraction with the ontology, and verifies faithfulness via hybrid regex and LLM-judge. Automatic induction eliminates manual ontology drift, yielding 100% Ontology Conformance across all configurations. Hybrid verification slashes hallucination rates, though residual subject hallucination persists, linked to passive voice. Gemini shows stronger schema adherence; Llama benefits more from adaptive ontologies.

## Method Summary
Reports are segmented into non-overlapping 5-sentence chunks. Two ontology strategies are evaluated: (1) a single manual ontology curated from the Volvo report applied globally, and (2) an automatic induction process where Gemini-2.5 Flash sequentially processes chunks, proposing new entity types and relations that are merged into a running document-specific ontology. For each chunk, the extraction model (Gemini or Llama) is prompted with the full ontology to output JSON triplets. Faithfulness is verified in two steps: first, a regex exact-match checks if subject and object strings appear in the chunk; failing that, an LLM-as-a-judge decides semantic presence. Metrics (Ontology Conformance, Subject/Object/Relation Hallucination) are micro-averaged over all triplets per configuration.

## Key Results
- Automatic ontology induction achieves 100% Ontology Conformance for all model–report combinations, whereas manual ontology leads to lower OC (e.g., Llama 4 Maverick: 92.7%/89.4% on Volvo/Elekta).
- Hybrid verification drastically reduces hallucination: for Gemini with manual ontology, Subject Hallucination drops from 65.2% to 1.6% and Object Hallucination from 22.5% to 0.24%.
- Residual Subject Hallucination exceeds Object Hallucination; the paper attributes this to passive voice constructions. Gemini exhibits stronger schema adherence, while Llama 4 Maverick benefits more from the adaptive automatic ontology.

## Why This Works (Mechanism)
Automatic ontology induction aligns the extraction schema with each document’s specific terminology and relations, avoiding the drift that occurs when a static manual ontology built on one report is applied to another. Hybrid verification leverages regex for precise literal matching and delegates ambiguous cases (e.g., paraphrased entities) to an LLM judge, which captures semantic presence and thus reduces false hallucination flags. The remaining subject hallucination arises because passive constructions often omit explicit subjects, making them hard to verify even semantically.

## Foundational Learning
- **Ontology-driven evaluation:** Provides a closed schema for extraction and a metric (OC) without ground truth. *Quick check:* Does the ontology cover all relevant entity/relation types in the document?
- **Triplet extraction:** Structures information as (subject, predicate, object) for knowledge graph construction. *Quick check:* Are triplets unambiguous and properly segmented across sentences?
- **LLM-as-a-judge:** Enables semantic verification when exact string match fails. *Quick check:* What is the judge’s agreement with human annotations on a sample?
- **Hybrid verification:** Combines regex precision with LLM recall. *Quick check:* What proportion of entities are resolved by regex vs. judge?
- **Automatic ontology induction:** Adapts the schema to document-specific vocabulary, preventing manual drift. *Quick check:* How does ontology size grow per chunk and what fraction of extracted relations are covered?
- **Chunking strategy:** Limits context and focuses extraction. *Quick check:* Does chunk size affect cross-sentence relation capture?

## Architecture Onboarding
**Component map:**  
Financial Report -> Chunker -> Ontology Module (Manual or Automatic Inducer) -> Extraction Model (Gemini/Llama) -> Hybrid Verifier (Regex + LLM Judge) -> Metrics (OC, SH, OH, RH)

**Critical path:** For automatic induction, the sequential processing of chunks to build the ontology is the longest chain; extraction follows once the ontology is finalized. Manual ontology skips induction, shortening the path.

**Design tradeoffs:**  
- Smaller chunks risk splitting facts; larger chunks risk context overflow.  
- Manual ontology ensures consistency but may miss document-specific relations; automatic induction adapts but may bloat the schema.  
- Regex is fast but brittle to formatting; LLM judge is flexible but costly and potentially inconsistent.  
- Gemini vs. Llama involve tradeoffs between schema adherence and creative extraction.

**Failure signatures:**  
- High Relation Hallucination: extraction model ignores ontology constraints.  
- High Subject/Object Hallucination post-verification: chunk boundaries cut entities or passive voice obscures subjects.  
- Inconsistent judge decisions: high variance on borderline cases.  
- Ontology bloat: automatic induction adds numerous low-frequency relations, harming precision.

**First three experiments:**  
1. Replicate baseline metrics for one configuration (e.g., Gemini on Volvo with manual ontology).  
2. Introduce 1-sentence overlap in chunking and compare SH/OH to assess boundary artifacts.  
3. Manually annotate 100 LLM-judge fallback cases to measure agreement; target >95% to validate hybrid verification.

## Limitations
- The judge LLM identity and prompt are unspecified, risking inconsistent faithfulness evaluation.
- The exact manual ontology content is unreported, hindering exact replication and fair comparison.
- Extraction parameters (temperature, max tokens) and automatic induction thresholds (e.g., duplicate handling) are opaque, affecting determinism.

## Confidence
- Hybrid verification reduces hallucinations: **High**  
- Automatic ontology ensures 100% OC: **High**  
- Comparative model behavior (Gemini vs. Llama): **Medium**  
- Passive voice as explanation for residual SH: **Low**

## Next Checks
1. Judge reliability audit: manually label 100 random fallback cases; compute agreement with the LLM judge; target >95%.
2. Chunk overlap sensitivity test: re-run extraction with 1-sentence overlap on one report; compare triplet counts and SH/OH to baseline.
3. Manual ontology reconstruction: derive a minimal ontology from Volvo chunks that covers >95% of unique relations; compare OC/RH against the paper’s implied manual ontology.
