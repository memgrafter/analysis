# Translation Asymmetry in LLMs as a Data Augmentation Factor: A Case Study for 6 Romansh Language Varieties

## Quick Facts
*   **arXiv ID:** 2603.25489
*   **Source URL:** https://arxiv.org/abs/2603.25489
*   **Reference Count:** 40
*   **Primary Result:** Back-translating from low-resource Romansh varieties to high-resource German (LR→HR) for data augmentation yields an NLLB model that outperforms forward translation (HR→LR) by an average of 11.4 BLEU points, with a 23.2 BLEU gain for the lowest-resource variety.

## Executive Summary
Standard LLM-based data augmentation for low-resource languages typically involves forward translation from a high-resource language like German. This approach fails for Romansh, which has six mutually unintelligible varieties, because LLMs confuse the variants when generating them. The paper demonstrates that aligning the augmentation direction with the resource gradient—by back-translating authentic low-resource Romansh monolingual text into high-resource German (LR→HR)—produces high-quality synthetic parallel data. Training an NLLB model on this data significantly outperforms both forward-translated data and direct use of a strong LLM (Gemini 1.5 Pro) for all six varieties. Human evaluation confirms substantial improvements in fluency and variety-specific accuracy.

## Method Summary
The study compares two data augmentation directions using an LLM (Gemini 1.5 Flash): 1) **Forward Translation (HR→LR):** Translating German source text into each of the six Romansh varieties. 2) **Back-Translation (LR→HR):** Translating authentic Romansh monolingual text (from varied sources like news and Wikipedia) from each variety into German. The resulting synthetic parallel datasets are used to fine-tune the NLLB-200 model. A baseline is also established by directly prompting Gemini for translation (zero-shot). Performance is evaluated via BLEU scores on existing test sets for each variety and through human evaluation focusing on fluency and accuracy.

## Key Results
*   The LR→HR augmentation strategy yields an NLLB model that surpasses the direct Gemini 1.5 Pro translator by an average of **11.4 BLEU points** across all six Romansh varieties for German→Romansh translation.
*   For the lowest-resource variety, **Sutsilvan**, the performance gain is dramatic, at **23.2 BLEU points** over the Gemini baseline.
*   Human evaluation confirms that the LR→HR model produces translations that are **significantly more fluent and accurate** in all six varieties compared to the LLM baseline. Dictionary prompting provided minor automatic metric gains but no consistent human evaluation benefit.

## Why This Works (Mechanism)
The core mechanism is a **translation asymmetry** inherent in LLMs when dealing with a multi-variety low-resource language. LLMs exhibit a "fluency asymmetry": they are better at understanding (parsing) text in a low-resource language than at generating it accurately. Furthermore, a "standardization asymmetry" makes it easier to translate into a highly standardized language (German) than into a specific, non-standardized variety of a language like Romansh. When forced to generate a specific Romansh variety from German (HR→LR), the LLM produces outputs that are either generic or conflate features from different varieties, polluting the synthetic training data. The LR→HR direction bypasses this generative weakness; the LLM only needs to understand the authentic, variety-specific Romansh text (a relative strength) and translate it into high-resource, standardized German (a task it performs well). This creates clean synthetic German target data that, when paired with the original Romansh source, provides a high-quality signal for NMT fine-tuning.

## Foundational Learning
*   **Translation Asymmetry:** The observed disparity in LLM performance between translating *into* a low-resource language (hard) versus *out of* it (easier). **Why needed:** It explains why standard forward augmentation fails. **Quick check:** If an LLM generates more accurate translations from Language X to Language Y than from Y to X, and X is low-resource, asymmetry is present.
*   **Back-Translation for Data Augmentation:** A standard NLP technique where monolingual target data is machine-translated *into* the source language to create synthetic parallel corpora. **Why needed:** The paper repurposes this for a resource-gradient alignment strategy. **Quick check:** Does the augmentation direction follow the resource flow (LR text -> HR language) rather than oppose it?
*   **Variety vs. Dialect Continuum:** Romansh varieties are mutually unintelligible, behaving more like separate languages than dialects. **Why needed:** This characteristic is central to the LLM's confusion problem. **Quick check:** If speakers of Variant A cannot understand Variant B without prior exposure, they are distinct linguistic systems.
*   **LLM Confusion in Low-Resource Generation:** The propensity of large models trained on broad, noisy data to produce non-standard or amalgamated outputs for specific low-resource varieties. **Why needed:** It's the hypothesized root cause of poor HR→LR synthetic data. **Quick check:** Analyze LLM outputs for HR→LR; do they contain mixed lexical/grammatical markers from multiple target varieties?
*   **NLLB (No Language Left Behind):** A massively multilingual machine translation model from Meta AI, designed for many low-resource languages. **Why needed:** It serves as the base model for fine-tuning with augmented data. **Quick check:** Does the base model already have some capability in the target language family, or is it essentially zero-shot?
*   **Resource Gradient Alignment:** The principle of designing data augmentation pipelines so the linguistic flow goes from lower-resource to higher-resource data. **Why needed:** It leverages the LLM's strengths in understanding low-resource text and generating high-resource text. **Quick check:** Map the direction of synthetic data creation: is it LR_text -> HR_language or the reverse?

## Architecture Onboarding
**Component Map:**
Authentic Romansh Monolingual Text (Per Variety) -> LLM (Gemini 1.5 Flash, Prompted for German Translation) -> Synthetic German Sentences -> Paired with Original Romansh -> Filtered/Curated Dataset -> NLLB-200 Model (Fine-Tuned) -> Evaluation (BLEU, Human)

**Critical Path:** The fidelity of the **Synthetic German Sentences** is the critical bottleneck. Its quality is entirely dependent on the LLM's ability to accurately *understand* the specific Romansh variety and produce a correct German translation. A failure here propagates to a corrupted fine-tuning signal.

**Design Tradeoffs:**
1.  **Cost vs. Coverage:** Using a powerful, expensive LLM (Gemini) for augmentation yields high-quality synthetic data but limits the volume of text that can be processed due to API costs and rate limits.
2.  **Generative Fidelity vs. Automation:** The LR→HR method avoids the LLM's poor generative capacity for Romansh, but it requires a pre-existing corpus of authentic monolingual Romansh text, which may be scarce for some varieties.
3.  **Automatic Metrics vs. Human Judgment:** BLEU scores showed clear improvements, but the paper notes dictionary prompting's automatic gains did not translate to human evaluation, highlighting a potential metric misalignment.

**Failure Signatures:**
*   **HR→LR Augmentation Failure:** Degraded NLLB performance, especially for low-resource varieties, coupled with human evaluation showing variety confusion (e.g., Sutsilvan text translated with Vallader features).
*   **LLM Prompt Misconfiguration:** If the LLM prompt for back-translation fails to specify the correct Romansh variety, it will default to a more common or standardized variant (e.g., Rumantsch Grischun), reducing variety-specific accuracy in the synthetic data.
*   **Data Contamination:** If the authentic monolingual Romansh corpus used for back-translation is not purely monolingual or contains code-switching with German, the synthetic German targets will be noisy.

**First Three Experiments:**
1.  **Augmentation Direction Baseline:** Replicate the core experiment: train NLLB models using (a) HR→LR synthetic data, (b) LR→HR synthetic data, and (c) a control with no augmentation. Evaluate on all six varieties' test sets.
2.  **LLM Substitution:** Replace Gemini 1.5 Flash with a different LLM (e.g., GPT-4, Llama 3.1) for the augmentation step, keeping the LR→HR direction constant. Compare the quality of the resulting NLLB models to assess if the asymmetry effect is model-dependent.
3.  **Dictionary Integration Test:** Implement a more sophisticated dictionary integration than prompt-appending (e.g., constrained decoding where only dictionary-defined tokens are allowed for key lexical slots) during the LR->HR augmentation step. Compare automatic and human evaluation results to the standard LR→HR baseline.

## Open Questions the Paper Calls Out
*   **Open Question 1:** Can dictionary information be integrated more effectively into LLM-based data augmentation than simple prompting, such as through rejection fine-tuning or constrained decoding?  
    *Basis:* [explicit] The authors note that dictionary prompting offered minor automatic metric gains but no consistent human evaluation improvement, and suggest that "future work could employ the available dictionary information beyond prompting, such as for rejection fine-tuning."  
    *Why unresolved:* The paper only tested dictionary appended to the prompt; other integration methods remain unexplored.  
    *What evidence would resolve it:* A comparative study where dictionary constraints are applied during LLM generation (e.g., via token masking or reranking) versus prompt-only augmentation, measured by both automatic metrics and human evaluation of variety accuracy.
*   **Open Question 2:** Do the findings about augmentation direction (LR→HR superiority) generalize to other LLMs beyond Gemini 2.5 Flash, and does model size or architecture affect the translation asymmetry?  
    *Basis:* [explicit] The limitations state: "We limit our data augmentation experiments to one LLM with a good price-performance ratio (Gemini 2.5 Flash) and to greedy decoding, leaving experiments with alternative models and sampling strategies to future work."  
    *Why unresolved:* The observed effect is tied to a single model; different LLMs may exhibit different asymmetries or benefit differently from augmentation directions.  
    *What evidence would resolve it:* Replicate the experimental setup with multiple LLMs (e.g., GPT-4, Llama, open-source models) and sampling strategies (beam search, temperature sampling), comparing LR→HR vs HR→LR augmentation for Romansh.
*   **Open Question 3:** Can effective machine translation be built directly between Romansh varieties (e.g., Sursilvan→Vallader) using the same LR→HR augmentation approach, where one variety serves as the high-resource source?  
    *Basis:* [explicit] The authors state: "Future work could explore translation between Romansh varieties, as well as data augmentation for these directions." They also note that data is unevenly distributed across varieties.  
    *Why unresolved:* The study only considered German↔Romansh; inter-variety translation is a clear application need but was not tested.  
    *What evidence would resolve it:* Conduct experiments using monolingual data from a higher-resource variety (e.g., Sursilvan) to generate synthetic parallel data for a lower-resource variety (e.g., Sutsilvan), then train and evaluate an NMT model on that variety pair.
*   **Open Question 4:** What is the primary driver of the translation asymmetry—is it the LLM's reduced fluency in generating low-resource varieties, its inability to adhere to non-standardized orthographies, or a combination of both?  
    *Basis:* [explicit] The authors propose "two complementary explanations: 1. Fluency asymmetry: LLMs are better at understanding text in a low-resource language... than at generating it. 2. Standardization asymmetry: It is easier for an LLM to translate into a highly standardized language (German) than into a specific variety of a multi-variety language (Romansh)."  
    *Why unresolved:* The paper demonstrates the phenomenon but does not isolate or quantify the contribution of each factor.  
    *What evidence would resolve it:* Designed experiments that separately vary standardization level (e.g., compare translation into RG vs. a less standardized variety) and resource level (e.g., compare generation from high-resource vs. low-resource prompts), measuring fluency and variety accuracy.
*   **Open Question 5:** Would dictionary prompting in the HR→LR augmentation direction (German→Romansh) yield similar or different benefits compared to LR→HR, given its high cost and the authors' finding that it added little in the latter?  
    *Basis:* [explicit] The authors tested dictionary prompting only for LR→HR augmentation "due to the high cost of LLM usage for brute-force dictionary prompting." They also note it provided marginal BLEU gains but no consistent human evaluation improvement in that direction.  
    *Why unresolved:* It is unknown whether dictionary prompting could be more effective in the HR→LR direction, where the LLM already struggles with variety adherence, or if the cost outweighs benefits in both directions.  
    *What evidence would resolve it:* Run dictionary prompting experiments for HR→LR augmentation (German→Romansh) with the same prompt design, compare automatic and human evaluation metrics to the baseline HR→LR and LR→HR with/without dictionaries, and perform a cost-benefit analysis.

## Limitations
*   **Generalizability:** Findings are based on a single language family (Romansh) with six specific varieties. It is unknown if the observed "translation asymmetry" and success of LR→HR augmentation hold for other dialect continua (e.g., Arabic, Chinese) or language pairs with different resource gradients.
*   **Human Evaluation Scope:** The summary notes "significantly more fluent and accurate" translations but lacks details on human evaluation sample size, annotator expertise (e.g., native speakers of each variety), and specific error categories analyzed. This limits interpretation of the practical quality gains.
*   **Mechanism Specificity:** The core hypothesis is that LLMs confuse mutually unintelligible varieties during forward translation. While the LR→HR result is strong, the paper may not fully disentangle this confusion from other factors like the absolute volume of synthetic data or the specific linguistic distance between German and each Romansh variety.

## Next Checks
1.  **Cross-Linguistic Replication:** Re-run the exact forward vs. back-translation augmentation protocol on at least one other set of mutually unintelligible language varieties (e.g., Swiss German dialects, Serbian/Croatian/Bosnian) with a similar resource gradient to a high-resource language. Success would test generalizability.
2.  **Deep-Dive Human Evaluation:** Conduct a large-scale, variety-specific human evaluation with multiple native speaker annotators per Romansh variety. Annotators should judge translations (from both LR→HR and HR→LR models) for *variety-specific accuracy* (not just generic fluency) to directly measure if back-translation better preserves distinctive lexical/grammatical features.
3.  **Probing Model Confusion:** Analyze the intermediate representations (e.g., via attention patterns or probing classifiers) of the baseline LLM (Gemini 1.5 Pro) when it performs forward translation (German→Romansh). Specifically, test if the model's internal "Romansh" space collapses distinct varieties, and whether the LR→HR training regime in NLLB leads to more separable representations for each variety.
