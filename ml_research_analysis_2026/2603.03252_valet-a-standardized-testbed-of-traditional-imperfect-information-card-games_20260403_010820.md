# Valet: A Standardized Testbed of Traditional Imperfect-Information Card Games
## Quick Facts
*   **arXiv ID:** 2603.03252
*   **Source URL:** https://arxiv.org/abs/2603.03252
*   **Reference count:** 26
*   **Primary result:** Introduces Valet, a standardized testbed of 21 diverse imperfect-information card games with formally encoded rules (RECYCLE), and provides baseline metrics (branching factor, length, score distributions) showing MCTS agents consistently outperform random agents.

## Executive Summary
The paper addresses the critical problem of inconsistent and incomparable evaluations of AI algorithms for imperfect-information games, largely due to non-standardized rule implementations across different research frameworks. It introduces Valet, a testbed comprising 21 traditional card games with their rules formally encoded in the RECYCLE language to ensure uniform, unambiguous execution. Through extensive simulation, the authors empirically characterize each game's key properties (branching factor, length, score distributions), demonstrating substantial diversity. The baseline evaluation shows that Monte Carlo Tree Search (MCTS) with determinization significantly outperforms random play in nearly all games, establishing Valet as a robust, standardized benchmark suite for future research.

## Method Summary
Valet constructs a diverse testbed by selecting 21 traditional card games spanning genres like trick-taking, shedding, and gambling. The core mechanism is the formal, executable encoding of each game's rules in the RECYCLE domain-specific language, which precisely defines state, actions, visibility, and effects. To characterize the testbed, the authors run extensive simulations: for each game, they conduct 100 simulations with all-random agents and 100 simulations where one player uses an MCTS agent (with 10 determinizations and a simulation budget of 100× current action count) against random opponents. Key metrics logged per decision point include the number of legal actions (branching factor) and total decision points per game (length). Final scores from the MCTS condition are compared to the random baseline to assess the performance of a standard search algorithm across the diverse game set.

## Key Results
*   The 21 games exhibit substantial variation in core metrics (branching factor, game length, score distributions), confirming a diverse testbed.
*   MCTS agents consistently outperform random agents in 20 out of 21 games, providing strong baseline performance data.
*   Formal RECYCLE encodings provide a shared, unambiguous reference for game rules, aiming to eliminate implementation discrepancies as a confounder in future comparisons.

## Why This Works (Mechanism)
### Mechanism 1
*   **Claim:** Inconsistent AI performance comparisons arise primarily from non-standardized rule implementations.
*   **Mechanism:** Different frameworks (e.g., RLCard, OpenSpiel) implement the same named game with varying rules. A formally encoded reference in RECYCLE provides a single, executable specification to align implementations.
*   **Evidence:** [abstract] notes no single game is implemented in all frameworks and overlapping games often differ. [section 2] details specific stabilization choices (e.g., no passing in Hearts). The corpus shows multiple independent benchmark proposals, acknowledging the gap.

### Mechanism 2
*   **Claim:** A diverse, standardized testbed enables identification of algorithm components robust to game mechanics versus game-specific ones.
*   **Mechanism:** Measuring algorithm performance (like MCTS) across games with varied mechanics (player count, information structures) allows correlation with intrinsic game properties rather than idiosyncrasies.
*   **Evidence:** [abstract] emphasizes "diverse and comprehensive" design. [section 3] shows "substantial variation" in metrics. [section 4] states the testbed helps distinguish generalizing from genre-specific components.

### Mechanism 3
*   **Claim:** Standardized rule encoding in a domain-specific language (RECYCLE) reduces implementation ambiguity.
*   **Mechanism:** RECYCLE provides an unambiguous, executable specification. Any compliant agent interfaces with identical logic, eliminating interpretation errors and variant creep.
*   **Evidence:** [abstract] states the goal to "standardize implementations across systems." [section 2.3] calls encodings a "common reference for alignment." The CardStock system is built around RECYCLE, showing a prior implementation path.

## Architecture Onboarding
Game Definitions (RECYCLE files) -> Simulation Engine (e.g., CardStock) -> Agent Interface -> Metrics Collector -> Experiment Orchestrator

*   **Critical path:** To add a new game: 1) Encode rules in RECYCLE. 2) Verify engine simulation. 3) Run 100 random rollouts for baseline metrics. 4) Integrate into evaluation harness for MCTS vs. random scoring.
*   **Design tradeoffs:**
    *   *Depth vs. Breadth:* One stable variant per game maximizes algorithm comparison diversity but limits in-depth variant study.
    *   *Realism vs. Simplicity:* Rules are sometimes simplified (e.g., no splitting in Blackjack) to reduce decision space, potentially deviating from common house rules.
    *   *Evaluation Horizon:* Most games are single-round, speeding experiments but excluding multi-round match strategies.
*   **Failure signatures:**
    *   **Inconsistent Results Across Frameworks:** Same game shows different metrics on Valet vs. OpenSpiel/RLCard. Likely cause: rule interpretation divergence.
    *   **MCTS Fails to Beat Random:** Seen in Cuckoo. Suggests insufficient search horizon from short length or a misconfigured MCTS agent.
    *   **Extreme Pathological Metrics:** Very high branching factor (>50) or extreme length (thousands of steps). May indicate a buggy encoding or engine.
*   **First 3 experiments:**
    1.  **Sanity Check:** For Crazy Eights, run one random simulation and log each decision point's legal actions. Verify count matches expected rules (e.g., follow suit if able).
    2.  **Baseline Validation:** Replicate the paper's 100-random vs. 100-MCTS scenario for all 21 games. Confirm "MCTS consistently outperforms random in almost all games" and identify exceptions.
    3.  **Diversity Probe:** Plot average branching factor per decision-point index for all games on one chart. Visually confirm distinct profiles per genre (e.g., descending line for trick-taking) and identify outliers like Skitgubbe/Rummy.

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** How do game mechanics influence algorithm behavior in imperfect-information games?
*   **Basis in paper:** Authors state the need for "a systematic understanding of how game mechanics influence algorithm behaviour."
*   **Why unresolved:** Existing evaluations focus on few games; Valet provides diversity but cross-game analysis is lacking.
*   **What evidence would resolve it:** Systematic benchmarking of multiple algorithms across Valet's 21 games, with statistical correlation between mechanics and performance.

### Open Question 2
*   **Question:** What algorithmic components generalize across diverse imperfect-information card games?
*   **Basis in paper:** Authors claim Valet "helps distinguish algorithmic components that generalize across genres" but no empirical identification yet.
*   **Why resolved:** No study has used Valet to test which components work broadly.
*   **What evidence would resolve it:** Ablation studies across all games, comparing variants with/without specific components (e.g., determinization depth, opponent modeling); consistent performers are generalizable.

### Open Question 3
*   **Question:** How can Valet be extended to modern card games with mechanics like drafting and deck building?
*   **Basis in paper:** Conclusion proposes "a natural extension is a complementary testbed for modern card games, capturing mechanics such as drafting, deck building, asymmetric powers, and cooperative play."
*   **Why unresolved:** Valet only includes traditional games; modern mechanics are absent.
*   **What evidence would resolve it:** Encode a diverse set of modern card games in RECYCLE and integrate them into a standardized benchmark.

### Open Question 4
*   **Question:** How can agents better infer hidden information from action history in imperfect-information card games?
*   **Basis in paper:** Authors note that for Go Fish and Crazy Eights, MCTS shows little improvement because "CardStock’s determinizations account only for visibility and not for information inferred from action history."
*   **Why unresolved:** Current agents ignore action-based inference, limiting performance in such games.
*   **What evidence would resolve it:** Develop agents with belief updates from actions (e.g., Bayesian inference) and demonstrate improvement on affected games compared to standard MCTS.

## Limitations
*   MCTS configuration details (UCB constant, tree policy, determinization sampling) are unspecified, hindering exact replication.
*   Rule simplifications (e.g., no splitting in Blackjack) may deviate from common play, limiting real-world applicability.
*   Each game is represented by a single variant, preventing analysis of rule variation effects and multi-round match strategies.

## Confidence
*   Rule variation causes inconsistent comparisons: **Medium** (anecdotal evidence from multiple frameworks).
*   Diverse testbed will identify robust algorithm components: **Low** (diversity measured, but no demonstration of utility).
*   RECYCLE will standardize implementations: **Medium** (formal language exists, but community adoption unproven).
