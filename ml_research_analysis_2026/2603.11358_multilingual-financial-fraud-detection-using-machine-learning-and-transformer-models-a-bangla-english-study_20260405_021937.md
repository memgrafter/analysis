# Multilingual Financial Fraud Detection Using Machine Learning and Transformer Models: A Bangla-English Study

## Quick Facts
- **arXiv ID:** 2603.11358  
- **Source URL:** https://arxiv.org/abs/2603.11358  
- **Reference count:** 40  
- **Primary result:** Linear SVM with TF‑IDF achieved 91.59% accuracy and 91.30% macro F1, outperforming the transformer model.

## Executive Summary
This study investigates multilingual financial fraud detection in a Bangla‑English context, an area that remains underexplored for low‑resource languages. The authors compare classical machine learning models (Logistic Regression, Linear SVM, Ensemble) using TF‑IDF features against a transformer‑based architecture. Using 5‑fold stratified cross‑validation on a dataset of financial messages, the Linear SVM model achieved the best overall performance with 91.59% accuracy and 91.30% macro F1 score, surpassing the transformer’s 89.49% accuracy and 88.88% F1. The transformer, however, exhibited higher fraud recall (94.19%) at the cost of nearly double the false positive rate.

Exploratory analysis revealed that scam messages are longer, contain urgency‑inducing terms, and frequently include URLs (32%) and phone numbers (97%). Legitimate messages often include transactional confirmations and currency references such as “taka”. The findings suggest that classical ML with well‑engineered TF‑IDF features remains competitive for multilingual fraud detection, while performance is ultimately limited by code‑mixing and the low‑resource nature of Bangla.

## Method Summary
The study addresses binary classification of financial messages as legitimate (ham) or fraudulent (scam) in a Bangla‑English code‑mixed setting. The dataset contains around 523 messages, with approximately 80% English, 15–17% Bangla, and the remainder code‑mixed. Scam messages tend to be longer and include URLs (32%) and phone numbers (97%), while ham messages often reference transactions and the Bangla currency “taka”.

Two families of models were evaluated:  
(1) **Classical machine learning** (Logistic Regression, Linear SVM, and an Ensemble) using TF‑IDF features (unigrams and bigrams);  
(2) **A transformer‑based architecture** (unspecified but based on a multilingual pretrained checkpoint such as mBERT or XLM‑R) fine‑tuned on the same data.  
All models were assessed via 5‑fold stratified cross‑validation, reporting accuracy, macro‑averaged F1, PR‑AUC, and confusion matrices. The Linear SVM with TF‑IDF achieved the highest scores (91.59% accuracy, 91.30% macro F1), while the transformer reached 89.49% accuracy and 88.88% macro F1, with notably higher fraud recall (94.19%) but a false positive rate almost twice that of the SVM.

## Key Results
- Linear SVM (TF‑IDF) achieved 91.59% accuracy and 91.30% macro F1, outperforming all baselines.
- The transformer model achieved 89.49% accuracy and 88.88% macro F1, with higher fraud recall (94.19%) but nearly double the false positive rate compared to SVM.
- Exploratory analysis showed scam messages are longer, contain urgency cues, and include URLs (32%) and phone numbers (97%); legitimate messages contain transactional confirmations and currency references.

## Why This Works (Mechanism)
The study identifies three key factors underlying the observed performance:

1. **TF‑IDF captures high‑signal lexical markers** – The sparse, interpretable TF‑IDF features highlight terms that are frequent in scam messages but rare in legitimate ones (e.g., urgency words, phone numbers, URLs). This aligns well with linear classifiers like SVM, which are robust in high‑dimensional spaces and less prone to overfitting on noisy, code‑mixed text. The core assumption is that fraud messages contain consistent surface‑level markers that n‑gram statistics can capture.

2. **Transformer over‑sensitivity due to low‑resource code‑mixing** – The multilingual transformer (e.g., mBERT, XLM‑R) is pretrained primarily on high‑resource corpora. On Bangla‑English code‑mixed financial text, it tends to latch onto coarse fraud‑associated patterns (imperatives, numbers) without finely understanding intent, leading to a higher recall for fraud but nearly double the false positive rate compared to SVM.

3. **Dataset‑level constraints cap performance** – The linguistic complexity of the dataset—approximately 80% English, 15‑17% Bangla, with frequent code‑mixing—limits both approaches. Code‑mixed tokens are poorly represented in monolingual lexicons (for TF‑IDF) and in subword vocabularies (for transformers), creating a ceiling that neither model can surpass without more representative data or preprocessing.

Evidence includes error analysis showing scam messages are longer, contain URLs (32%) and phone numbers (97%), while legitimate messages reference transactions and currency (e.g., “taka”).

## Foundational Learning
- **TF-IDF Vectorization**  
  *Why needed:* The core competitive classical models operate on TF‑IDF features. Understanding how term frequency and inverse document frequency weight words is key to interpreting why scam terms (e.g., “claim”, phone numbers) get high weights.  
  *Quick check:* Why would the term “taka” (Bangla currency) likely have a high IDF (and thus high weight) in a fraud detection corpus?

- **Linear Classifiers for High-Dimensional Sparse Data**  
  *Why needed:* Both Logistic Regression and Linear SVM are applied to thousands of TF‑IDF features. Knowing how these models (hinge loss vs. log loss) handle sparse, noisy features explains their robustness compared to a dense transformer context.  
  *Quick check:* In what way does the max‑margin objective of Linear SVM potentially help with the noisy lexical features common in social engineering messages?

- **Multilingual Subword Tokenization**  
  *Why needed:* The transformer model uses a shared subword vocabulary for Bangla‑English code‑mixed text. Understanding tokenization is crucial to diagnosing why rare or mixed‑language terms might be split into many subtokens, diluting semantic meaning.  
  *Quick check:* If a Bangla word like “(dpokh)” (meaning “withdraw”) is out‑of‑vocabulary, how might the transformer’s subword tokenizer handle it, and what is a likely consequence?

## Architecture Onboarding
- **Component map**  
  Data → Preprocessing → TF‑IDF → Linear SVM  
  Data → Preprocessing → Tokenizer → Transformer → [CLS] pooling → Linear classifier → Prediction

- **Critical path** – The fastest route to reproduction is:  
  1. Implement TF‑IDF with Linear SVM using scikit‑learn.  
  2. Use a pretrained multilingual transformer (e.g., `xlm‑roberta‑base`) with Hugging Face `AutoModelForSequenceClassification`.  
  3. Ensure identical 5‑fold splits across both pipelines.  
  4. Compare per‑class metrics, not just accuracy.

- **Design tradeoffs**  
  - *SVM + TF‑IDF:* Low computational cost, interpretable features, but ignores word order and long‑range dependencies.  
  - *Transformer:* Captures context, potentially better for nuanced code‑mixing, but data‑hungry, computationally expensive, prone to over‑confidence on minority patterns (higher false positives here).  
  - *Hybrid suggestion:* Concatenate TF‑IDF features with transformer [CLS] embeddings before the classifier—may combine lexical precision with contextual awareness (not tested).

- **Failure signatures**  
  - *Transformer:* Consistently high false positive rate (>15% FP) on legitimate messages; poor performance on Bangla‑only or heavily code‑mixed samples (check per‑language subsets).  
  - *SVM:* Low fraud recall (<85%) if important fraud signals are non‑lexical (e.g., subtle persuasion) or if TF‑IDF bigrams fail to capture transliterated Bangla terms.  
  - *Both:* Performance collapse if training set language distribution differs drastically from test set (e.g., more Bangla in test).

- **First 3 experiments**  
  1. **Reproduce EDA:** Replicate Figures 1‑6 to validate dataset characteristics (message length, language %, URL/phone stats). Confirm scam messages are longer and contain more URLs/phones.  
  2. **Baseline TF‑IDF + Linear SVM:** Run with default scikit‑learn parameters, unigram+bigram, no class weighting. Should replicate ~91.5% accuracy. Tune `C` (regularization) if performance deviates.  
  3. **Transformer Fine‑tuning:** Use `xlm‑roberta‑base`, sequence length 128, batch size 16, 3 epochs, learning rate 2e‑5. Monitor per‑class F1; expect ~89.5% accuracy but with higher scam recall. Try freezing lower layers to see if it reduces false positives.

## Open Questions the Paper Calls Out
This study raises several open questions for future work:

1. **Fine‑tuning the transformer:** To what extent can fine‑tuning a multilingual transformer (e.g., mBERT, XLM‑R) on the Bangla‑English fraud detection dataset improve its performance and reduce its false positive rate compared to the off‑the‑shelf model used?  
2. **Hybrid feature representation:** Does a hybrid feature representation that concatenates TF‑IDF vectors with transformer embeddings enhance classification performance for multilingual fraud detection?  
3. **Code‑mixing patterns:** How do specific code‑mixing patterns (e.g., Bangla script with English words, transliteration) within messages impact the performance gap between TF‑IDF‑based models and multilingual transformers?  
4. **Minimum dataset size:** What is the minimum viable dataset size required for a transformer model to match or surpass classical ML performance on this Bangla‑English fraud detection task?  
5. **Engineered features:** Can explicit engineered features derived from the exploratory analysis (e.g., message length, presence of URLs/phone numbers, digit distribution, urgency keyword count) be integrated with TF‑IDF or transformer features to improve robustness?

## Limitations
- Exact transformer architecture and fine‑tuning hyperparameters (e.g., epochs, batch size, learning rate) are not documented.  
- The “Ensemble” classifier’s composition and voting scheme are ambiguous.  
- TF‑IDF preprocessing details (e.g., handling of Bangla Unicode, inclusion of URLs/phone numbers) are unspecified.  
- The dataset is small (~523 messages), raising concerns about statistical stability and generalizability.  
- No external validation on other multilingual fraud corpora; results may be dataset‑specific.
