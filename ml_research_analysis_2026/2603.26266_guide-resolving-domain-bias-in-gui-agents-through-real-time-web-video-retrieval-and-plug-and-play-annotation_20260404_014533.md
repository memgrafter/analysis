# GUIDE: Resolving Domain Bias in GUI Agents through Real-Time Web Video Retrieval and Plug-and-Play Annotation

## Quick Facts
- arXiv ID: 2603.26266
- Source URL: https://arxiv.org/abs/2603.26266
- Reference count: 40
- Primary result: GUIDE resolves domain bias in GUI agents by autonomously acquiring expertise from web tutorial videos, achieving 4.5–7.5% absolute score gains on OSWorld without model parameter changes.

## Executive Summary
GUI agents suffer from domain bias in planning and grounding due to scarce training data for specific applications. GUIDE addresses this by retrieving relevant web tutorial videos via a subtitle-driven Video-RAG pipeline, converting them into structured workflow and element description knowledge through an inverse dynamics annotation process, and injecting this knowledge into the agent’s modules as reference material. This plug-and-play approach yields consistent absolute gains of 4.5–7.5% on the OSWorld benchmark across multiple agent architectures. Planning knowledge contributes the majority of improvement, while grounding adds complementary benefits in complex domains.

The method operates without any model fine‑tuning, working with both single‑model and multi‑agent systems. Retrieval succeeds for 82.8% of tasks, topic extraction is 96% acceptable, and annotation costs approximately $0.25 per video.

## Method Summary
GUIDE comprises three stages. Stage 1: A Retrieval Agent processes the task instruction and application name to search YouTube and applies a three‑stage subtitle‑based filter (domain classification → topic extraction → relevance matching) to select up to two task‑relevant videos. Stage 2: An Annotation Agent processes each video: Whisper generates subtitles; MOG2 extracts keyframes; OmniParser detects UI elements; an inverse‑dynamics VLM (f_IDM) consumes consecutive keyframe pairs with element graphs, topic, and subtitle context to produce a “Thought & Action” narrative for meaningful transitions; an LLM decomposes aggregated trajectories into **Planning** (execution flow) and **Grounding** (≤15 element descriptions). Stage 3: The extracted knowledge is injected into the GUI agent’s planning and grounding modules as reference material, with prompts that emphasize verification against the live screenshot and priority of current observations. No model parameters are changed; the approach works across diverse agent architectures.

## Key Results
- GUIDE achieves absolute success rate gains of 4.5–7.5% on OSWorld across three agent architectures (single‑model and multi‑agent).
- Retrieval pipeline finds relevant videos for 82.8% of tasks; topic extraction is 96% acceptable.
- Annotation cost ≈ $0.25 per video; planning knowledge accounts for ~86–91% of the improvement, with grounding adding complementary gains in UI‑complex domains.

## Why This Works (Mechanism)
### Mechanism 1: Subtitle‑Driven Progressive Retrieval
- **Claim:** Web tutorial videos are filtered to find task‑relevant demonstrations by exploiting subtitle semantics, avoiding reliance on noisy video titles.
- **Mechanism:** A three‑stage subtitle analysis pipeline (domain classification → topic extraction → relevance matching) progressively narrows candidates. Subtitles provide narrated step descriptions that distinguish operational demos from theory or vlogs.
- **Core assumption:** Tutorial subtitles contain explicit mentions of GUI actions (e.g., “click Colors menu”) that correlate with genuine operation workflows.
- **Evidence anchors:**
  - [abstract] “subtitle‑driven Video‑RAG pipeline unlocks video semantics through subtitle analysis”
  - [section 3.2] “subtitles naturally contain narrated operation steps… serving as a textual semantic bridge”
  - [corpus] Weak; neighbors discuss video use but not subtitle‑driven filtering.
- **Break condition:** Auto‑generated subtitles lack action keywords (e.g., silent demos or non‑English narration), causing false negatives. Human eval shows ~9% recall loss in Stage 1.

### Mechanism 2: Inverse Dynamics Annotation with UI Priors
- **Claim:** Tutorial videos are converted into transferable “Planning” (workflow) and “Grounding” (element descriptions) knowledge by inferring actions between consecutive keyframes enhanced with UI element detection.
- **Mechanism:** A VLM (`f_IDM`) takes keyframe pairs, element graphs (from OmniParser), video topic, and subtitle context to produce a “Thought & Action NLP” narrative. A downstream LLM decomposes aggregated trajectories into planning (execution flow, considerations) and grounding (≤15 element descriptions) knowledge.
- **Core assumption:** Meaningful GUI operations produce detectable visual changes between keyframes *and* are narrated in subtitles, enabling joint inference.
- **Evidence anchors:**
  - [abstract] “inverse dynamics paradigm feeds consecutive keyframes enhanced with UI element detection into VLMs”
  - [section 3.3] “f_IDM takes keyframe pairs… with element graphs… to produce structured annotations”
  - [corpus] Neighbors (e.g., Watch&Learn) use similar IDM but without subtitle/UI context; GUIDE’s multi‑source input is distinctive.
- **Break condition:** (i) Tutorials are not screencasts (e.g., slide decks → grounding describes absent elements). (ii) Procedural mismatch (video solves different task → planning misaligns). Human eval: “Meaningful” filter has 91.6% recall for invalid frames; idle no‑action frames are harder (53.6% recall).

### Mechanism 3: Agent‑Agnostic Knowledge Injection
- **Claim:** Extracted natural‑language knowledge is injected into the agent’s planning and grounding contexts without parameter changes, yielding consistent gains across architectures.
- **Mechanism:** Knowledge is framed as “reference material” (not directives) and routed to architecturally matched modules (e.g., Worker system prompt for planning, Grounding Agent prompt for elements). A structured CoT template forces active cross‑referencing with the live screenshot.
- **Core assumption:** VLMs can follow reference‑based prompts and prioritize live observations over potentially stale video knowledge.
- **Evidence anchors:**
  - [abstract] “injected into the agent’s corresponding modules to address both manifestations… without modifying any model parameters”
  - [section 3.4] “knowledge is framed as reference material, not directives… the agent verifies suggestions against the current screenshot”
  - [corpus] Neighbors (e.g., RAG‑GUI) inject knowledge differently; GUIDE’s dual‑channel, plug‑and‑play design is novel.
- **Break condition:** Agent ignores injected knowledge entirely if relevance is low or conflicts with strong prior behavior. Success depends on the agent’s ability to interpret natural‑language references.

## Foundational Learning
- **Concept: Domain bias in GUI agents**
  - *Why needed here:* GUIDE targets two specific bias manifestations: planning (unknown workflows) and grounding (unknown UI layouts). Understanding this split is key to designing the dual‑channel knowledge.
  - *Quick check question:* Why would an agent know “adjust brightness” conceptually but fail on GIMP’s `Colors → Brightness‑Contrast` path?

- **Concept: Inverse dynamics for video annotation**
  - *Why needed here:* The pipeline turns videos into actionable knowledge by reversing the typical “state + action → next state” prediction. This allows extracting “what action caused this transition” from screen recordings.
  - *Quick check question:* How does providing UI element graphs (OmniParser) improve inverse dynamics inference over raw pixels alone?

- **Concept: Retrieval‑augmented generation (RAG) for videos**
  - *Why needed here:* GUIDE extends RAG to the video domain, where titles are noisy and content is opaque. Subtitles serve as the semantic bridge for content‑level retrieval.
  - *Quick check question:* Why is title‑based YouTube search insufficient for finding task‑relevant GUI tutorials?

## Architecture Onboarding
- **Component map:** Retrieval Agent → Annotation Agent → GUI Agent (any)
- **Critical path:** Task T → Retrieval (get videos) → Annotation (get knowledge) → Injection (modify agent prompt) → Execution (agent uses knowledge as reference)
- **Design tradeoffs:**
  - Retrieval precision vs. recall: High‑precision filtering avoids contaminating annotation but misses ~9% valid videos.
  - Grounding element count k: Optimal at k=5; too few loses info, too many adds noise.
  - Annotator strength vs. cost: Stronger VLMs yield higher‑quality knowledge but cost more; OmniParser + constrained prompts reduce dependence on annotator strength.
  - Latency: Knowledge injection adds ~2.1 s/step but reduces total steps on success, net modest wall‑clock overhead.
- **Failure signatures:**
  1. Planning mismatch: Retrieved video solves adjacent but wrong sub‑task.
  2. Grounding mismatch: Video format differs (e.g., browser‑based demo, slide deck); grounding describes UI elements absent in target environment.
  3. Retrieval failure: No relevant video found (17.2% of OSWorld tasks); agent reverts to baseline.
  4. Ignored knowledge: Agent consistently overrides injected guidance due to strong priors or low video relevance.
- **First 3 experiments:**
  1. Retrieval coverage audit on 361 OSWorld tasks to verify 82.8% success rate and analyze failure domains.
  2. Annotation quality human eval on 300 videos to measure Stage 1 classification precision/recall and Stage 2 topic extraction acceptability (target ≥96%).
  3. Knowledge channel ablation: Run +Planning vs. +Planning&Grounding on 50 tasks to confirm planning’s dominant contribution (~86–91%) and grounding’s complementary value in complex domains.

## Open Questions the Paper Calls Out
- **Question 1:** What are the root causes of the 17.2% of OSWorld tasks where GUIDE fails to retrieve any relevant tutorial video, and can coverage be substantially improved without sacrificing precision?
- **Question 2:** How does GUIDE's performance degrade when retrieved videos deviate from standard screencast formats (e.g., animated slide decks, browser‑based demos), and can a lightweight pre‑filter effectively screen out such videos to prevent grounding mismatch?
- **Question 3:** Why does the “Meaningful” filter achieve only 53.6% recall for idle no‑action frames, and can its sensitivity be improved to better distinguish semantically irrelevant visual changes from valid micro‑interactions?
- **Question 4:** To what extent do GUI agents actually comply with GUIDE's “use as reference, not directive” instructions when injected with planning and grounding knowledge, and does non‑compliance directly explain the planning/grounding mismatch failures?
- **Question 5:** What is the empirical cost‑performance trade‑off curve when scaling GUIDE’s annotation pipeline with cheaper, less capable VLMs (e.g., GPT‑4.1 Mini, Qwen3‑VL‑8B), and at what point does quality degradation offset the significant cost savings?

## Limitations
- Subtitle dependency causes false negatives when actions are not narrated (~9% recall drop).
- Non‑screencast videos introduce irrelevant grounding elements, leading to failure.
- Retrieval fails for ~17% of tasks, with no fallback strategy.
- Agent compliance with injection guidelines is not guaranteed; knowledge may be ignored.
- Exact reproduction hindered by unavailable models (GPT‑5.1) and unspecified OmniParser.
- OSWorld setup complexity and YouTube volatility affect reproducibility.
