# StrokeNeXt: A Siamese-encoder Approach for Brain Stroke Classification in Computed Tomography Imagery

## Quick Facts
- **arXiv ID:** 2602.15087
- **Source URL:** https://arxiv.org/abs/2602.15087
- **Reference count:** 31
- **Primary result:** StrokeNeXt achieves state-of-the-art stroke detection (98.7% accuracy, 0.987 F1-score) and subtype classification (98.8% accuracy, 0.988 F1-score) on 6,774 CT images with low latency (9ms) and high robustness.

## Executive Summary
StrokeNeXt introduces a Siamese dual-branch encoder for automated brain stroke classification from 2D CT images. Using two parallel ConvNeXt backbones, it extracts complementary features that are fused via a lightweight 1D convolutional decoder. Evaluated on the TEKNOFEST 2021 Stroke Dataset, StrokeNeXt-large attains 98.7% accuracy for stroke detection and 98.8% for subtype classification, outperforming CNN and Transformer baselines with statistical significance. The model demonstrates high sensitivity/specificity (>0.97), low calibration error (Brier <0.015), and efficient inference (9ms on NVIDIA A100).

## Method Summary
StrokeNeXt processes 224×224 normalized CT images through two independent ConvNeXt encoders (e.g., tiny to large variants). Each encoder outputs a feature vector after global average pooling. These vectors are stacked into a [B, C, 2] tensor and fused using a 1D convolution (kernel size 2) followed by a bottleneck (two 1×1 convolutions with a hidden layer). The fused representation is classified by a linear layer into stroke presence and subtype (ischemic/hemorrhagic). Training employs AdamW (lr=1e-4, weight decay=1e-5), mixed precision, 20 epochs, and augmentations (flips, rotations, color jitter). The model is evaluated on 6,774 images from the TEKNOFEST 2021 Stroke Dataset with an 80-10-10 split.

## Key Results
- Stroke detection: 98.7% accuracy, 0.987 F1-score.
- Subtype classification: 98.8% accuracy, 0.988 F1-score.
- Statistically significant gains over baselines (McNemar p<0.05), per-class sensitivity/specificity >0.97, Brier score <0.015, inference latency 9ms (large variant).

## Why This Works (Mechanism)
1. **Complementary Feature Extraction via Dual-Branch Siamese Encoder**: Two independent ConvNeXt branches process the same input without weight sharing, encouraging distinct optimization trajectories and specialized representations (e.g., one focusing on ischemic textures, another on hemorrhage density). Evidence: The paper explicitly aims for "complementary features" and section 3.2.1 states branches converge to distinct representations. Break condition: If branch outputs exhibit high cosine similarity, the diversity hypothesis fails.
2. **Efficient Fusion with Lightweight 1D Convolutional Decoder**: The stacked branch features `[B, C, 2]` are mixed by a 1D convolution (kernel=2) and a bottleneck (two 1×1 convs). This design is parameter-efficient compared to concatenation+MLP or attention, while maintaining expressivity. Evidence: Section 3.2.2 compares fusion methods; StrokeNeXt-tiny (57.6M) outperforms single-branch ConvNeXt-base (87.5M) despite fewer parameters. Break condition: Ablation showing no advantage over simpler fusions of comparable cost.
3. **Order-Aware Inductive Bias in Fusion**: The fixed stacking order (branch A then B) allows the 1D convolution to treat branches asymmetrically, exploiting any specialization. Evidence: Section 3.2.2 describes order-aware fusion; balanced per-class metrics might indicate specialization but not directly. Break condition: No consistent branch specialization patterns in feature analysis.

## Foundational Learning
- **Siamese/Twin Networks**: Why needed? StrokeNeXt’s core is a Siamese encoder with unshared weights to encourage complementary features. Quick check: Why might two identical networks with different random initializations and independent SGD updates learn different features from the same image? (Answer: Stochastic optimization can converge to distinct minima; diverse initializations and data augmentations may lead to specialization.)
- **ConvNeXt Architecture**: Why needed? ConvNeXt is the backbone, blending CNN efficiency with Transformer-like design (large kernels, LayerNorm, GELU). Quick check: How does ConvNeXt modernize ResNet while staying a CNN? (Answer: By replacing batch norm with LayerNorm, ReLU with GELU, and using large depthwise convolutions, it aligns with Transformers’ self-attention patterns.)

## Architecture Onboarding
- **Component map**: Input -> Branch1(ConvNeXt) -> f1 and Input -> Branch2(ConvNeXt) -> f2 (parallel) -> Stack(f1,f2) -> 1D_Conv -> Bottleneck(2x1x1) -> Classifier -> Output
- **Critical path**: Dual-branch feature extraction followed by fusion and classification.
- **Design tradeoffs**:
  - Dual-branch doubles encoder parameters but is claimed to improve accuracy; tiny variant still beats larger single-branch.
  - Fusion uses a simple 1D conv and bottleneck for low latency; more complex fusion (cross-attention) might help accuracy but hurt efficiency.
  - Order-aware stacking is a subtle bias; if branches don’t specialize, it’s wasted capacity.
- **Failure signatures**:
  1. Branch collapse: High cosine similarity between branch gradients/outputs; no gain over single-branch.
  2. Calibration degradation: High Brier/ECE despite high accuracy, possibly from insufficient dropout or poor bottleneck.
  3. Latency spike: Incorrect fusion implementation (e.g., unnecessary reshapes) slows inference.
- **First 3 experiments**:
  1. Baseline sanity check: Implement a single-branch ConvNeXt (same variant) with fusion decoder (using one encoder or duplicating); expect underperformance.
  2. Fusion ablation: Replace 1D fusion with (a) sum, (b) concat+MLP (matched params), (c) max pool along branch dim; compare accuracy/latency.
  3. Branch specialization probe: Extract penultimate features from each encoder on validation set; compute class-wise L2 distances and visualize with PCA/t-SNE to check for distinct focus.

## Open Questions the Paper Calls Out
1. How do patient demographics and clinical outcomes affect StrokeNeXt’s performance and generalizability across populations?
2. To what extent does StrokeNeXt generalize to varied CT acquisition protocols and other modalities like MRI?
3. How does computational efficiency scale across hardware (edge, CPU, varied GPUs) and what optimizations are needed for real-time use?
4. Does the Siamese dual-branch encoder provide statistically significant improvements over a single-branch model with equivalent parameters, and what are the individual contributions of each branch?

## Limitations
- Unspecified hyperparameters: Bottleneck hidden size `H`, stacking order, and weight initialization not fully detailed.
- Lack of mechanistic validation: No feature analysis to prove branch diversification or fusion benefits.
- Reproducibility concerns: Random seed for data split not provided; small dataset risks overfitting.

## Confidence
- Siamese diversity: Medium (theoretical basis but no direct evidence of complementarity)
- Fusion efficiency: Medium ( promising results but missing proper ablations)
- Order-aware bias: Low (no evidence of branch specialization; balanced performance suggests symmetry suffices)
- Overall SOTA claim: Medium (high metrics reported but rely on unspecified settings)

## Next Checks
1. Branch divergence check: Compute cosine similarity and per-class L2 distance between encoder outputs on held-out set; expect low similarity and class-dependent divergence.
2. Fusion ablation: Replace 1D fusion with channel-wise sum and concatenation+MLP (matched parameters); validate original fusion’s accuracy/latency advantage.
3. Order sensitivity test: Swap stacking order or encoder weights; if performance degrades, order-aware fusion provides meaningful asymmetry.
