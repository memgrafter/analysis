# A Rubric-Supervised Critic from Sparse Real-World Outcomes

## Quick Facts
- arXiv ID: 2603.03800
- Source URL: https://arxiv.org/abs/2603.03800
- Reference count: 34
- Primary result: Critic Rubrics with code survival supervision enable cross-backbone robust critics that improve SWE-bench solve rate via best-of-8 (+15.9 points) and early stopping (+17.7 points with 83% fewer attempts), and enhance training-time data curation (+1.2 points).

## Executive Summary
Real-world coding agent interactions lack dense, verifiable success signals like unit tests; outcomes such as PR merges are sparse and noisy. This paper introduces Critic Rubrics—24 segment-level behavioral features derived from interaction traces—and uses semi-supervised multi-task learning to jointly predict these rubrics and sparse outcome proxies (code survival or PR merge). The approach turns the vast majority of unlabeled segments into valid training data, addressing the credit assignment gap between academic benchmarks and production.

Training on code survival yields superior intrinsic discrimination compared to PR merge. Rubric supervision produces critics that generalize across LLM backbones and enable effective inference-time scaling: best-of-8 reranking improves SWE-bench accuracy by +15.9 points over random selection, and early stopping achieves +17.7 points while requiring 83% fewer attempts. Moreover, critic-selected trajectories improve SWE-bench solve rate by +1.2 points over random supervised fine-tuning.

## Method Summary
The method defines Critic Rubrics—24 binary or categorical behavioral features (e.g., "misunderstood intention", "insufficient testing") that can be automatically annotated on any agent trace using an LLM. These features provide dense, segment-level supervision. The critic model (Qwen3-4B-Instruct) is trained with a multi-task loss: for every segment, it predicts all 24 rubrics; for the small subset with outcome labels, it also predicts success (binary PR merge or continuous code survival). Code survival measures the fraction of a segment’s code that persists in the final merged PR diff, offering a finer-grained, segment-attributable signal.

The semi-supervised objective leverages the full dataset (~154K segments, 4% with survival labels, 6% with merge labels). After training, the critic can be used for best-of-K ranking, early stopping thresholds, and selecting high-quality trajectories for SFT data curation. Ablations compare success-only vs. rubric-supervised training and evaluate cross-backbone robustness.

## Key Results
- Intrinsic discrimination: Critics trained on code survival achieve higher AUC (0.69) on real-world data versus PR merge (0.58), despite fewer labeled segments.
- Inference-time scaling: Rubric-supervised critics yield Best-of-8 improvement of +15.9 points over random selection on SWE-bench mixed-outcome subset, and early stopping achieves +17.7 point gain with only 1.35 attempts on average (83% reduction). Success-only critics show backbone-specific overfitting (gains on Sonnet but degrade on Opus).
- Training-time curation: Using the critic to select trajectories for SFT improves SWE-bench solve rate by +1.2 points over random selection.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Critic Rubrics provide dense, segment-level supervision that enables semi-supervised learning from primarily unlabeled real-world interaction traces.
- **Mechanism:** The paper defines 24 binary/classification behavioral features (e.g., "misunderstood intention", "insufficient testing") that can be annotated from any agent trace via LLM-based annotation. These features serve as auxiliary prediction tasks in a multi-task loss, alongside the sparse outcome label (code survival/PR merge). This turns the 96% of segments without outcome labels into valid training data.
- **Core assumption:** Rubric features are causally linked to segment-level success/failure and are consistently detectable from trace-observable behavior.
- **Evidence anchors:**
  - [abstract] "Critic Rubrics... 24 behavioral features that can be derived from human-agent interaction traces alone. Using a semi-supervised objective, we can then jointly predict these rubrics and sparse human feedback (when present)."
  - [§3.1] "Rubrics are segment-level, trace-observable, and scalably annotatable... annotation process... yielding 24 features."
  - [§3.3] Rubric features show significant negative correlation with success across datasets (Fig. 3, Tab. 7), supporting construct validity.
  - [corpus] Neighbors (e.g., SCRIBE) also explore mid-level supervision for tool-using agents, indicating this addresses a known credit assignment gap.
- **Break condition:** If rubric features are not reliably annotatable (low inter-annotator agreement) or do not correlate meaningfully with downstream task success when used for selection.

### Mechanism 2
- **Claim:** Code survival is a more fine-grained and attributable outcome proxy than PR merge for segment-level critic learning.
- **Mechanism:** Code survival quantifies the fraction of a segment's code contributions that persist in the final merged PR diff. This provides a continuous, segment-attributable signal that captures partial successes (e.g., some edits kept, some reverted). In contrast, PR merge is a binary, PR-level signal that applies uniformly to all segments in a PR, ignoring later overwrites and human edits.
- **Core assumption:** The persistence of a segment's code changes in the final merged artifact is a more direct indicator of that segment's contribution to the ultimate outcome than whether the PR it belongs to was merged.
- **Evidence anchors:**
  - [§2.3] "Code survival... measures what fraction of a segment’s code contributions persist in the final merged diff... A segment whose code is fully reverted receives survival = 0."
  - [§4.3] "Critics trained on code survival achieve higher AUC on real-world data (0.69 vs 0.58) despite fewer labeled segments... survival is a more fine-grained, segment-attributable proxy."
  - [§3.3] User follow-up features (e.g., removal/reversion) show stronger association with code survival than PR merge (Fig. 3).
- **Break condition:** If code survival computation is too noisy or confounded by post-segment human edits not attributable to the agent, making it a poor learning target.

### Mechanism 3
- **Claim:** Rubric supervision promotes cross-backbone robustness in critics, enabling reliable inference-time scaling across different LLMs.
- **Mechanism:** Success-only critics overfit to spurious correlations specific to the LLM backbone used during training (e.g., lexical patterns, formatting quirks). Jointly predicting the 24 rubric features forces the model to learn more abstract, behavior-level representations of failure modes (e.g., "insufficient debugging", "file management errors") that are invariant to the underlying language model.
- **Core assumption:** Behavioral failure modes (captured by rubrics) are more fundamental and transferable than the superficial ways different LLMs express success/failure.
- **Evidence anchors:**
  - [§5.2] "Success-Only exhibits severe backbone-specific overfitting: it improves over random on Sonnet but can degrade below random on Opus... Rubric-supervised critics maintain consistent positive gains on both."
  - [Tab. 3] Success+Rubrics (BCE-floor) shows +15.9 MRR on Combined set vs. Success-Only's +5.7, with positive gains on both individual backbones.
  - [§5.1] Rubric-supervised models achieve better early stopping efficiency (1.35 vs 1.76 attempts) indicating better-calibrated scores.
- **Break condition:** If rubric features themselves are backbone-specific or if the multi-task architecture introduces interference that harms performance on all backbones.

## Foundational Learning
- **Concept: Semi-supervised multi-task learning**  
  *Why needed here:* Outcome labels (code survival, PR merge) cover only 4–6% of segments. Rubric annotations cover 100%, providing dense auxiliary supervision to leverage the full dataset.  
  *Quick check question:* If you have 1000 segments with only 40 outcome labels, how do you use the other 960 for critic training?

- **Concept: Credit assignment over long horizons**  
  *Why needed here:* Real-world interactions are multi-turn; a final PR merge may reflect work from multiple segments, and human edits after agent finish confound attribution. The segment-PR-commit hierarchy and code survival metric attempt partial credit assignment.  
  *Quick check question:* Why is it problematic to assign a PR merge label to every segment in that PR? What does code survival try to fix?

- **Concept: Behavioral cloning vs. reward modeling**  
  *Why needed here:* The critic is trained to predict human-evaluated rubrics (process) and sparse outcomes (result). This differs from pure reward modeling (e.g., pairwise preferences) and aims to capture failure modes, not just overall quality scores.  
  *Quick check question:* How does predicting a "did not follow instruction" rubric differ from learning a scalar reward from human preferences?

## Architecture Onboarding
**Component map:** Segment Extractor → Commit Attributor → Rubric Annotator → Critic Model → Downstream Policies

**Critical path:** Raw logs → Segment extraction → Commit attribution (for survival labels) → LLM rubric annotation → Critic training (joint loss on rubric + outcome) → Evaluation: AUC on test set, Best-of-K/early stopping on SWE-bench trajectories.

**Design tradeoffs:**
- Rubric granularity vs. annotation cost: 24 features balance coverage and reliability; more features risk annotation noise.
- Outcome proxy choice: Code survival is finer-grained but sparser and noisier to compute; PR merge is noisier at segment level but easier.
- Multi-task loss weighting: Rubric loss may dominate if outcome is very sparse; paper uses BCE-floor for survival to handle low-positive-rate.
- Context length: Real-world segments average 38K tokens; requires 64K context and truncation tradeoffs.

**Failure signatures:**
- Intrinsic: AUC near random (0.5) on held-out real-world test set indicates model not learning meaningful signal.
- Downstream: Best-of-K performance below Random@K suggests critic scores are anti-correlated or uncalibrated.
- Cross-backbone: Large performance delta between evaluation backbones indicates overfitting to training backbone.
- Training: Loss divergence on rubric heads or outcome head; high false-positive rate on rare rubrics ("risky actions").

**First 3 experiments:**
1. **Intrinsic validation:** Train critic with/without rubric supervision on real-world data; report AUC on held-out segments for PR merge and code survival. Expect rubric-supervised to have higher AUC on survival.
2. **Transfer test:** Train critic solely on SWE-Gym (benchmark) data; evaluate AUC on real-world test set. Expect near-random performance, confirming benchmark-real-world gap.
3. **Inference-time scaling:** Using a fixed set of SWE-bench trajectories from two backbones, run Best-of-8 and early stopping with different critics. Measure absolute gain over random selection and attempts required. Expect rubric-supervised to show consistent positive gains across backbones and better early stopping efficiency.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** How can we improve the transferability of critics trained on real-world interactions to novel agent scaffolds and user populations?
- **Basis in paper:** [inferred] The impact statement warns that critics may not transfer to different contexts; experiments only evaluate cross-backbone robustness within the same OpenHands scaffold.
- **Why unresolved:** Transferability is essential for widespread deployment; current evaluation is limited and may overfit to specific setups.
- **What evidence would resolve it:** Systematically evaluate critics across multiple agent frameworks (e.g., AutoGPT, LangChain) and diverse user groups; quantify performance drift and develop adaptation techniques.

### Open Question 2
- **Question:** What more reliable and granular outcome proxies can be used for segment-level success, given the noise and sparsity of even code survival?
- **Basis in paper:** [inferred] Code survival provides finer-grained supervision than PR merge but labels only 4% of segments and remains noisy and confounded by non-agent factors.
- **Why unresolved:** Sparse/noisy labels restrict critic training and evaluation; improved proxies could yield stronger learning signals.
- **What evidence would resolve it:** Propose new proxies (e.g., reviewer comments, post-merge bug reports) and validate them against human judgments or downstream task improvements.

### Open Question 3
- **Question:** Can we reduce the cost and latency of rubric annotation while preserving quality, avoiding reliance on expensive frontier LLMs like o3?
- **Basis in paper:** [inferred] Rubric annotation uses o3 with high reasoning effort, incurring ~17s/segment; the trained critic replicates annotations but initial rubric creation required costly LLM prompting.
- **Why unresolved:** Scalability to new domains or large datasets is hindered by annotation expense; cheaper methods are needed for broader application.
- **What evidence would resolve it:** Develop efficient annotation pipelines (e.g., self-training, smaller models, active learning) and measure consistency with expert annotations and downstream critic performance.

### Open Question 4
- **Question:** How can we accurately attribute success to individual segments in multi-turn conversations where later interactions may overwrite earlier contributions?
- **Basis in paper:** [inferred] The paper’s commit attribution is heuristic-based; PR merge labels apply uniformly to all linked segments, leading to potential miscredit when later user messages overwrite work.
- **Why unresolved:** Incorrect credit assignment degrades critic training; better attribution is needed for true segment-level evaluation.
- **What evidence would resolve it:** Introduce dynamic attribution models (e.g., temporal credit assignment, influence estimation) and evaluate on synthetic or manually annotated data with known segment contributions.

## Limitations
- Proprietary training data: Full real-world dataset (154K segments) and precise code survival computation are unreleased, blocking exact replication.
- Unspecified training details: Hyperparameters, loss weighting, and rubric annotation settings (LLM, temperature) are omitted, requiring heuristic recreation.
- Rubric subjectivity: 24 features are designer-selected; their causal validity and cross-domain portability (e.g., beyond coding) are unproven.

## Confidence
- **High:** Code survival as a finer-grained outcome proxy (supported by AUC gains: 0.69 vs 0.58).
- **Medium:** Rubric supervision improves cross-backbone robustness (consistent gains across Sonnet/Opus in Table 3).
- **Low:** Generalizability of rubric-based critics to new domains or tasks without in-distribution fine-tuning.

## Next Checks
