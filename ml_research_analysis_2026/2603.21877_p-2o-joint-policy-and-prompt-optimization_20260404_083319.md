# P^2O: Joint Policy and Prompt Optimization
## Quick Facts
- arXiv ID: 2603.21877  
- Source URL: https://arxiv.org/abs/2603.21877  
- Reference count: 40  
- Primary result: P²O substantially outperforms GRPO baselines on mathematical reasoning benchmarks, with gains of +12.9% on AIME24 and +11.7% on AIME25, and a +4.7% average improvement on out-of-distribution tests.

## Executive Summary
Reinforcement Learning with Verifiable Rewards (RLVR) often fails on hard samples with near-zero success rates, leading to sparse supervision and poor local optima. P²O addresses this by jointly optimizing prompts and policy: it identifies hard samples during training and uses the Genetic-Pareto (GEPA) algorithm to evolve prompt templates that elicit successful reasoning trajectories. It then distills these prompt-induced gains directly into model parameters via context distillation, removing dependency on inference-time prompts. On mathematical reasoning benchmarks, P²O outperforms GRPO baselines significantly. An ablation confirms that without context distillation, performance degrades below the GRPO baseline, proving the mechanism’s necessity.

## Method Summary
P²O alternates between two phases per training epoch. First, Policy Optimization: hard samples (identified by mean reward < τ over K=6 rollouts) are augmented with a randomly sampled prompt from the current template set Z, but policy gradients are computed on the original input to internalize reasoning patterns (context distillation). Non-hard samples use original inputs. The policy (Qwen3-4B) is updated via GRPO. Second, Prompt Optimization: For newly identified hard samples, GEPA evolves prompt templates on a held-out development set. Starting from an initial reference model π_init, GEPA maintains a Pareto front of candidate prompts evaluated on success rate, uses reflection to mutate prompts based on error feedback, and performs set cover to assign templates to each hard sample. The process repeats for 5 epochs.

## Key Results
- +12.9% absolute improvement on AIME24 over GRPO.
- +11.7% on AIME25.
- +4.7% average improvement on out-of-distribution benchmarks (AMC, MATH500, Minerva, Olympiad).
- Ablation: Removing context distillation reduces performance below GRPO, confirming the mechanism’s necessity.

## Why This Works (Mechanism)
P²O overcomes the RLVR exploration bottleneck by focusing prompt evolution on the hardest samples, where standard RL receives almost no reward signal. GEPA evolves prompts that elicit successful latent reasoning trajectories from the model, providing denser supervision. Context distillation then transfers these reasoning patterns into the policy itself, so the model no longer relies on external prompts at inference. The alternating optimization allows prompts to adapt to the current policy’s weaknesses while the policy gradually internalizes the improvements.

## Foundational Learning
- **Reinforcement Learning with Verifiable Rewards (RLVR)**: RL applied to tasks where success can be automatically checked (e.g., math problems). Needed because traditional RL relies on human feedback. Quick check: Explain how reward is computed in RLVR? Answer: Parse model output for final answer within \boxed{} and compare to ground truth; reward is 1 if correct, 0 otherwise.
- **Genetic-Pareto (GEPA)**: A genetic algorithm that maintains a Pareto front of prompt templates across multiple objectives (e.g., success rate, diversity). Needed to efficiently explore diverse, effective prompts for hard samples. Quick check: Describe how Pareto selection guides prompt mutations. Answer: Templates evaluated on a dev set; non-dominated ones retained; mutations proposed based on error analysis of underperforming prompts; selection favors those that improve coverage of hard samples.
- **Context Distillation**: Training the policy to mimic behavior under prompt augmentation but computing gradients on the original input, transferring prompt-based reasoning into the model. Needed to remove prompt dependency at inference. Quick check: Why compute policy gradient on original input? Answer: To ensure the policy learns to generate successful trajectories without the prompt, internalizing the reasoning pattern.
- **Hard Sample Mining**: Identifying queries where the model’s mean reward over multiple rollouts falls below a threshold τ. Needed to focus resources on the hardest cases that cause sparse RL signals. Quick check: How is a hard sample defined? Answer: Mean reward over K rollouts < τ (typically near zero).
- **GRPO (Group-Relative Policy Optimization)**: A PPO variant that uses group-normalized advantages to stabilize training. Provides the base RL update step. Quick check: What is the advantage computation in GRPO? Answer: For each group of K rollouts, compute mean and std of rewards; normalize each rollout’s reward to obtain advantage.

## Architecture Onboarding
**Component Map**  
Data (DeepMath-5K/DeepScaler-5K) -> Hard Sample Miner (identifies low-reward queries) -> Policy π_θ (Qwen3-4B) & Prompt Set Z -> GEPA (evolves Z) -> Context Distillation (updates π_θ on original inputs) -> GRPO updates -> Evaluation (AIME, etc.)

**Critical Path**  
For each epoch: (1) Mine hard samples; (2) For each hard sample, apply random prompt from Z, generate rollouts, compute GRPO advantage but update policy on original input (context distillation); (3) If new hard samples found, run GEPA to evolve new prompts based on dev set performance and assign templates via greedy set cover.

**Design Tradeoffs**
- Joint optimization vs. separate: combining prompt evolution and policy updates captures mutual benefits but adds algorithmic complexity.
- Prompt diversity vs. specialization: Pareto selection promotes a diverse front, while set cover assigns specialized templates; risk of overfitting to dev set.
- Computational cost: GEPA invokes repeated evaluations on a dev set and mutative language model calls; requires careful parallelization.

**Failure Signatures**
- Hard sample count does not decrease across epochs: indicates ineffective prompt evolution or mutation.
- Performance below GRPO baseline in the context-distillation ablation: suggests implementation error in gradient computation (updating on augmented input instead of original).
- Dev set reward saturation in GEPA: Pareto front stagnates, implying mutation operator lacks novelty or dev set is too small.

**First Three Experiments**
1. Ablate context distillation: Train without it and compare accuracy and hard sample reduction to isolate its contribution.
2. Vary hard sample threshold τ across a wide range (0.0–0.5) and measure final accuracy, convergence speed, and number of identified hard samples.
3. Log GEPA Pareto front size and prompt mutation operations across epochs; correlate diversity metrics with reduction in hard sample count.

## Open Questions the Paper Calls Out
1. Why does the optimal reflection source (self-reflection vs. teacher-reflection) for GEPA prompt evolution vary across datasets, and what properties of the task or model determine when self-generated refinements outperform external teacher feedback?
2. Does P²O’s joint optimization framework generalize to non-mathematical reasoning tasks with verifiable rewards (e.g., commonsense, logical deduction, code generation), or is it specifically effective for mathematical reasoning with binary outcomes?
3. How does the computational cost and sample efficiency of GEPA prompt optimization scale with the size of the template population, task complexity, and available computational budget?
4. How sensitive is P²O’s performance to the threshold τ used to define hard samples, and can an adaptive threshold improve robustness across varying data distributions and training stages?

## Limitations
- Template insertion function T(x, z) (position/system message) unspecified; minor implementation differences may affect policy learning and final results.
- GEPA's reflection meta-prompt and error feedback format not detailed; risk of inconsistent mutations and reproducibility issues.
- Greedy set cover assignment scoring (weights r̄_i) lacks theoretical justification; assignment stability may vary with random seeds.

## Confidence
- P²O surpasses GRPO on math benchmarks: **Medium** – strong empirical gains but depend on unspecified prompt engineering details.
- Context distillation is necessary: **High** – clear ablation shows performance drops below GRPO when removed.
- GEPA evolves effective templates: **Medium** – Pareto selection described, but mutation fidelity and dev set reliance are uncertain.
