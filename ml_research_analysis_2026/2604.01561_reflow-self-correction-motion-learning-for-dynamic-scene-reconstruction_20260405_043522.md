# ReFlow: Self-correction Motion Learning for Dynamic Scene Reconstruction

## Quick Facts
- **arXiv ID:** 2604.01561
- **Source URL:** https://arxiv.org/abs/2604.01561
- **Reference count:** 40
- **Primary result:** ReFlow achieves a mean PSNR of 28.20 dB on the Nvidia Monocular dataset, surpassing prior methods by over 1 dB while maintaining real-time rendering speeds (15–30 fps).

## Executive Summary
ReFlow introduces a novel framework for monocular dynamic scene reconstruction that removes the need for external motion guidance. By learning self-correcting 3D motion directly from video, it achieves state-of-the-art fidelity on multiple benchmarks. The core innovations include a Complete Canonical Space Construction module that aligns both static and dynamic regions via a geometric foundation model, a Separation-Based Dynamic Scene Modeling module that decouples static and dynamic Gaussian components, and a Self-correction Flow Matching mechanism that uses frame-to-frame photometric warping as self-supervision. On the Nvidia Monocular dataset, ReFlow reaches a mean PSNR of 28.20 dB, SSIM of 0.903, and LPIPS of 0.103, improving over prior art by more than 1 dB in PSNR. It also delivers competitive performance on Nerfies and HyperNeRF while preserving real-time rendering speeds comparable to the 4DGS baseline.

## Method Summary
ReFlow comprises three main modules. First, the Complete Canonical Space Construction (CSCS) uses the MonST3R geometry foundation model to estimate 3D coordinates for video frames, followed by coarse-to-fine alignment (keyframe global alignment then intra-clip refinement) to produce a unified canonical point cloud. Static and dynamic regions are separated using confidence masks. Second, the Separation-Based Dynamic Scene Modeling (SDSM) initializes two Gaussian representations: static Gaussians with time-invariant tri-plane features, and dynamic Gaussians with spatiotemporal feature planes and a deformation field. Third, the Self-correction Flow Matching mechanism introduces two photometric warping losses: Full Flow Matching, which supervises the full projected flow (camera + object motion) across the whole image; and Camera Flow Matching, which enforces consistency in static regions using only camera-induced flow. Training proceeds in two stages: a warm-up that optimizes static Gaussians with camera flow, and a full stage that jointly optimizes both static and dynamic components with both flow losses. The entire pipeline is built upon the 4DGS baseline, preserving its real-time rendering capabilities.

## Key Results
- **Nvidia Monocular:** PSNR 28.20 dB, SSIM 0.903, LPIPS 0.103 (>1 dB PSNR improvement over prior SOTA).
- **Nerfies–HyperNeRF:** PSNR 25.97, SSIM 0.674.
- **Efficiency:** Real-time rendering speeds (15–30 fps) on par with the 4DGS baseline.

## Why This Works (Mechanism)
### Mechanism 1: Complete Canonical Space Construction
- **Claim:** Initializing both static and dynamic scene regions in a coherent canonical space yields robust starting points for reconstruction.
- **Mechanism:** A geometry foundation model (MonST3R) estimates 3D point maps and confidence for keyframe pairs. Coarse-to-fine alignment first globally aligns keyframes (optimizing poses, intrinsics, depths), then refines all frames within clips using local adjustments. The fused point cloud is separated into static/dynamic components via confidence masks.
- **Core assumption:** MonST3R provides sufficiently accurate correspondences even amidst motion, and hierarchical alignment maintains global consistency without excessive memory.
- **Evidence anchors:** Abstract mentions CSCS; Section 3.2.1 details two-stage optimization; Table 3 row 3 shows +0.79 dB PSNR when adding this module.
- **Break condition:** Severe motion, textureless areas, or topological changes degrade foundation model accuracy, yielding noisy canonical geometry.

### Mechanism 2: Separation-Based Dynamic Scene Modeling
- **Claim:** Explicit decoupling of static and dynamic components allows region-specific motion constraints and prevents interference.
- **Mechanism:** From the canonical point cloud, static and dynamic points are split. Static Gaussians use time-invariant tri-plane spatial features; dynamic Gaussians add temporal feature planes and a deformation field. This disentanglement enables Camera Flow Matching to supervise static areas while Full Flow Matching handles full-scene motion.
- **Core assumption:** Dynamic masks reliably separate static/dynamic content, and separate representations efficiently model each.
- **Evidence anchors:** Abstract describes SDSM; Section 3.2.2 defines separate Gaussian parameters; Table 3 row 4 shows +0.40 dB improvement over CSCS alone (27.00 vs 26.60).
- **Break condition:** Inaccurate masks (e.g., dynamic objects labeled static) mix representations, causing static wobble or dynamic rigidity.

### Mechanism 3: Self-correction Flow Matching
- **Claim:** Using the video itself as supervision eliminates reliance on external motion priors and creates a self-correcting loop where motion is refined by its predictive power.
- **Mechanism:** Full Flow Matching warps the entire image using synthesized full flow (camera + object motion) and minimizes photometric error against the next frame. Camera Flow Matching does the same but only in static regions using camera-induced flow. Both losses directly supervise the 3D deformation fields.
- **Core assumption:** Frame-to-frame appearance changes primarily reflect 3D motion under brightness constancy; thus accurate motion should reconstruct the next frame via warping.
- **Evidence anchors:** Abstract introduces Full and Camera Flow Matching; Section 3.3 derives flow rendering and warping losses; Ablation (Table 6) shows Full Flow Matching yields +0.85 dB, adding Camera Flow gives total +1.20 dB (28.20).
- **Break condition:** Brightness changes, specularities, or non-rigid/topological changes violate photometric consistency, making warping errors misleading.

- **Why needed:** ReFlow explicitly avoids external optical flow supervision; distinguishing 2D pixel motion (optical flow) from 3D motion (scene flow) clarifies why external priors can be error-prone.

## Architecture Onboarding
#### Component Map
Input video -> Complete Canonical Space Construction -> Separation-Based Dynamic Scene Modeling -> Two-stage Optimization (Warm-up then Full)

#### Critical Path
1. Split video into clips (25–30 frames) and select keyframes.
2. Run MonST3R on keyframe pairs to obtain 3D point maps and confidence.
3. Coarse alignment: optimize keyframe poses, intrinsics, and depths using a global alignment loss.
4. Fine alignment: refine all frames within each clip using the coarse results.
5. Fuse aligned point clouds; separate static/dynamic using confidence masks.
6. Warm-up: freeze dynamic deformation, optimize static Gaussians with camera flow loss (λ_cf ≈0.3).
7. Full: jointly optimize static/dynamic Gaussians and deformation with both full flow loss (λ_ff ≈5.0 on Nvidia, 1.0 on HyperNeRF) and cross-time rendering weight (0.1×L_mc).

#### Design Tradeoffs
- **Foundation model choice:** MonST3R handles dynamic scenes but is slower; static-only models may fail on moving objects.
- **Clip size:** Larger clips improve global consistency but increase memory (O(N²) pairwise processing).
- **Separation threshold:** Tuning confidence threshold for masks trades off recall vs. precision of dynamic regions.
- **Flow loss weights:** λ values need balancing; complex scenes (HyperNeRF) use lower λ to allow flexibility.
- **Two-stage optimization:** Increases training time but prevents early collapse of dynamic components.

#### Failure Signatures
- Noisy canonical point clouds (failed coarse alignment).
- Dynamic masks with large errors (e.g., static background flickering).
- Warped image (I₁→I₂) remains blurry or misaligned throughout training.
- Static regions still exhibit wobble after camera flow matching.
- Training loss diverges when flow loss weights are too high.

#### First 3 Experiments
1. **Canonical space validation:** Visualize aligned point clouds from multiple views; static structures should be coherent across frames, dynamic regions present. Compare against raw COLMAP point cloud.
2. **Separation validation:** Render static-only Gaussians; verify temporal stability under camera motion. Render dynamic-only (static subtracted); check that moving objects are captured. Overlay dynamic masks on input frames to assess accuracy.
3. **Flow matching validation:** For a frame pair, compute warped image using predicted flow every 1000 iterations. Plot PSNR between warped image and target frame; should increase steadily. Ablate λ weights to observe sensitivity.

## Open Questions the Paper Calls Out
- **Open Question 1:** How does the quality of the geometry foundation model impact ReFlow's performance on scenes with topological changes or rapid object dynamics? The paper acknowledges this limitation in Section D but leaves it unaddressed; systematic evaluation with different foundation models or ground-truth geometry would clarify error propagation.
- **Open Question 2:** Is the self-correction flow matching robust to non-motion appearance variations (e.g., lighting changes) that cause photometric mismatches? The method assumes photometric consistency, but no mechanism is provided to handle lighting shifts; testing on videos with controlled lighting changes and possibly appearance-invariant losses would resolve this.
- **Open Question 3:** How does ReFlow handle occlusions in the flow matching process, where target pixels lack source correspondences? The warping-based loss implicitly assumes dense correspondences; integrating occlusion detection or evaluating on occlusion-heavy sequences would address this.

## Limitations
- MonST3r-dependent canonical initialization may fail on textureless regions or extreme motion, leading to noisy geometry.
- Dynamic mask thresholds are critical; inaccurate masks cause static-dynamic leakage and unstable camera flow supervision.
- Self-correction assumes photometric consistency; lighting changes, specularities, or exposure shifts can mislead flow matching.
