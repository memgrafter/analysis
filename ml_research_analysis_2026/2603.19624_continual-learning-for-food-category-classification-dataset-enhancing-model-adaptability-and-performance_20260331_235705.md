# Continual Learning for Food Category Classification Dataset: Enhancing Model Adaptability and Performance

## Quick Facts
- **arXiv ID:** 2603.19624  
- **Source URL:** https://arxiv.org/abs/2603.19624  
- **Reference count:** 25  
- **Primary result:** Achieves 98.38% ±2.32% accuracy on static vegetarian/non-vegetarian dish classification, but continual learning claims lack empirical validation.

## Executive Summary
The paper tackles catastrophic forgetting in food classification by proposing a continual learning framework that incrementally updates a text-based classifier to integrate new food categories without full retraining. Using dish names scraped from web sources, the authors apply TF-IDF vectorization and a regularized feedforward neural network, reporting high static classification performance (accuracy ~98.4%, F1 ~98.1%). However, the experiments evaluate only a static model trained on all data, not an incremental learning scenario. Thus, while the model performs well on the binary task, its ability to adapt to new categories while retaining prior knowledge—the core continual learning claim—remains unevaluated. Key limitations include heuristic-based labeling, unexplained high variance, and no comparison to standard continual learning methods.

## Method Summary
The dataset comprises 25,192 dish names (with `item_name`, `type`, and `ingredients`) scraped from Wikipedia and culinary sites, split 80/20 train/test. Labels (Vegetarian/Non-Vegetarian) are assigned via keyword heuristics (e.g., "salad", "tofu" for veg; "chicken", "beef" for non-veg). Text is vectorized with TF-IDF (max_features=5000, stop words removed). The model is a two-hidden-layer neural network (Dense 64 ReLU L2=0.01 → Dense 32 ReLU L2=0.01 → Sigmoid output), trained with Adam, binary cross-entropy, batch size 32, early stopping (patience=5). SMOTE is applied to the training set for class balancing. Hyperparameters are tuned via grid search. Critically, the paper does not describe how new categories are injected incrementally or how forgetting is measured—the reported metrics come from a single static evaluation on the test set.

## Key Results
- Accuracy: 98.38% ± 2.32%, Recall: 99.36% ± 0.14%, F1-score: 98.11% ± 0.67%
- Outperformed by SVM baseline (99.13% accuracy) in one comparison
- High variance (±2.32%) noted but not fully explained

## Why This Works (Mechanism)
The paper does not detail a specific continual learning mechanism (e.g., replay, regularization, distillation). The reported high static performance likely benefits from L2 regularization (reducing overfitting on TF-IDF features) and SMOTE (addressing class imbalance). However, the framework's claimed adaptability—incrementally adding new food categories without forgetting—is not experimentally demonstrated. Without an incremental training protocol or forgetting metrics, the mechanism for mitigating catastrophic inference remains unspecified and unverified.

## Foundational Learning
- **Catastrophic forgetting**: Core problem in continual learning where new tasks overwrite old knowledge; needed to frame the solution. *Quick check*: After training on new categories, measure accuracy drop on previously seen categories.
- **TF-IDF vectorization**: Converts text to sparse feature vectors; needed for numeric input. *Quick check*: Compare with simple bag-of-words; ensure stop-word removal improves consistency.
- **L2 regularization**: Penalizes large weights to prevent overfitting; needed for high-dimensional TF-IDF space. *Quick check*: Ablate L2 (set λ=0) and observe validation performance change.
- **SMOTE**: Synthetically oversamples minority class; needed for balanced binary classification. *Quick check*: Train without SMOTE and compare per-class recall.
- **Early stopping**: Halts training when validation loss plateaus; needed to avoid overfitting. *Quick check*: Plot training vs. validation loss across epochs.
- **Continual learning paradigms** (e.g., replay, EWC): Established techniques to mitigate forgetting; needed to benchmark the proposed approach. *Quick check*: Implement a simple replay buffer and measure forgetting on a toy incremental task.

## Architecture Onboarding
**Component map:**  
Dish Name (string) → TF-IDF Vectorizer (5000 features) → Dense(64, ReLU, L2=0.01) → Dense(32, ReLU, L2=0.01) → Sigmoid Output (binary)

**Critical path:**  
Data scraping → text cleaning → TF-IDF vectorization → SMOTE (train only) → neural network training (Adam, early stopping) → test evaluation

**Design tradeoffs:**  
- TF-IDF vs. contextual embeddings (e.g., BERT): TF-IDF is fast and interpretable but lacks semantic nuance for ambiguous dish names.
- Shallow network vs. deeper architectures: Shallow network trains quickly on sparse data but may underfit complex linguistic patterns.
- SMOTE vs. class weights: SMOTE balances classes synthetically but may introduce noisy samples; class weights avoid synthetic data but can bias loss.

**Failure signatures:**  
- High variance (±2.32% accuracy) across runs suggests dataset imbalance or unstable splits.
- Poor performance on dish names that violate keyword heuristics (e.g., "mock meat").
- No evidence of forgetting mitigation when new categories are added incrementally.

**First three experiments:**  
1. Reproduce static metrics: Fix random seed, run full pipeline as described, and report mean ± std of accuracy, F1, etc. over 5 seeds.
2. Audit labeling quality: Manually label a random sample of 500 dish names; compute agreement with heuristic labels and analyze model errors on disagreed samples.
3. Simulate incremental learning: Split data by cuisine type or ingredient clusters; train on initial subset, then add new clusters sequentially and measure old vs. new category accuracy after each step.

## Open Questions the Paper Calls Out
- **Comparison to standard CL methods:** How does the framework perform against Elastic Weight Consolidation, gradient episodic memory, or replay-based methods in mitigating catastrophic forgetting?
- **Dataset diversity impact:** What specific aspects of dataset diversity (cultural, linguistic) cause the high variance, and how can data augmentation or synthetic sampling improve stability?
- **Transformer integration:** Can BERT or similar models replace TF-IDF to improve semantic understanding and reduce variance, especially for novel dish descriptions?
- **Real-time user feedback:** How can a feedback loop be designed to personalize updates without amplifying noise or bias, and what is its effect on adaptation speed?
- **Heuristic labeling limits:** To what extent do keyword-based initial labels prevent learning categories without clear lexical markers (e.g., "vegan" dishes that mimic meat names)?

## Limitations
- **Heuristic labeling:** The exact keyword list for Veg/Non-Veg assignment is undisclosed, risking inconsistent or inaccurate labels.
- **No incremental evaluation:** The continual learning claim is not tested; experiments show only static model performance.
- **High unexplained variance:** The ±2.32% accuracy fluctuation is noted but not analyzed (e.g., due to split randomness, cuisine bias).

## Confidence
- **Static classification metrics (accuracy, F1, etc.):** Medium – replication is feasible but depends on undisclosed scraping/heuristic details; variance may be hard to match.
- **Continual learning capability (adaptation without forgetting):** Low – no incremental experiments were conducted; the framework’s behavior in a true continual setting is unknown.
