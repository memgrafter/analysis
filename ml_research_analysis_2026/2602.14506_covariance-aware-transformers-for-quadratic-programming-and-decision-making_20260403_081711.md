# Covariance-Aware Transformers for Quadratic Programming and Decision Making

## Quick Facts
*   **ArXiv ID:** 2602.14506
*   **Source URL:** https://arxiv.org/abs/2602.14506
*   **Reference Count:** 40
*   **Primary Result:** The proposed Time2Decide method, which prepends learned covariance tokens to a time series foundation model, achieves lower mean squared error (MSE) than standard predict-then-optimize (PtO) for portfolio optimization, particularly under loose rebalancing constraints (γ ≥ 1.5) and noisy return data.

## Executive Summary
This paper investigates the capability of transformer architectures to solve quadratic programming (QP) problems and improve decision-making in settings reliant on covariance matrices. Theoretically, it demonstrates that linear attention layers can be constructed to emulate gradient descent for unconstrained QPs by tokenizing matrix rows. With added fixed MLP modules, the same architecture can handle ℓ₁-regularized and ℓ₁-constrained QPs via iterative soft-thresholding and projected gradient descent. The authors instantiate this as **Time2Decide**, a method that enriches a time series foundation model (TSFM) by prepending tokens derived from the empirical covariance matrix of returns. This allows the model to condition its allocation predictions on second-order statistics in a single forward pass. Empirically, on portfolio optimization tasks, Time2Decide consistently outperforms both the base TSFM and the traditional two-stage predict-then-optimize pipeline, showing particular gains under noisier conditions and when rebalancing constraints are less tight.

## Method Summary
The core contribution is two-fold. First, it provides **constructive proofs** showing a single linear-attention transformer block, with specific tokenization of problem data (matrix rows, vectors, current iterate), can exactly emulate one iteration of gradient descent, ISTA (for ℓ₁-regularization), or projected gradient descent (for ℓ₁-constraints). Stacking such blocks simulates multiple optimization steps. Second, this theoretical insight is applied to portfolio optimization via **Time2Decide**. Here, a pre-trained TSFM is adapted. The empirical covariance matrix of historical returns is projected row-wise into a set of "covariance tokens." These tokens are prepended to the standard sequence of patched return and allocation data. The transformer then jointly processes all tokens to predict the next-period return and a raw, possibly infeasible, allocation. A final, separate projection step enforces portfolio constraints (e.g., budget, simplex). The entire model (covariance token MLP + TSFM backbone) is trained end-to-end using a loss that combines return prediction error with the deviation of the *projected* allocation from the mean-variance oracle solution.

## Key Results
*   Time2Decide achieves a test MSE of 0.0488 on clean data for γ=2.0, surpassing the PtO baseline's 0.0553.
*   Under noisy returns, the advantage widens: Time2Decide's MSE is 0.0476 versus PtO's 0.0781.
*   The method's relative improvement is most pronounced for looser rebalancing constraints (γ ≥ 1.5), where the predict-then-optimize plug-in approach struggles.

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** Linear attention can solve unconstrained quadratic programming problems by emulating gradient descent iterations.
**Mechanism:** A single linear-attention head processes tokens representing rows of the QP matrix **A** and vector **b** alongside a token holding the current iterate **xₖ**. Fixed query/key/value projections compute the quantity **A xₖ + b** as the attention output when attending from the **xₖ**-row token to the **A**-row tokens; combining this with a residual connection yields **xₖ₊₁ = xₖ - γ (A xₖ + b)**. Repeating this layer-by-layer simulates gradient descent steps; convergence follows under standard step-size conditions 0 < γ < 2/λ_max(A).
**Core assumption:** The tokenization correctly encodes matrix rows and iterates (content/id split with trailing constants), and the attention mechanism is linear (uses a kernel feature map, not softmax). The fixed weight matrices must exactly match the construction.
**Evidence anchors:**
*   [abstract] "We first show that the linear attention mechanism can provably solve unconstrained QPs by tokenizing the matrix variables row-by-row and emulating gradient descent iterations."
*   [section 3.2] Detailed proof with token layout Zₖ and weight specifications W_Q, W_K, W_V.
*   [corpus] Related works on neural QP solvers (e.g., "SCQPTH") show general interest but do not provide this specific linear attention emulation.
**Break condition:** Using softmax attention instead of linear attention breaks the exact emulation due to non-linear normalization. Learned weights may not satisfy the required fixed construction.

### Mechanism 2
**Claim:** With a fixed two-layer ReLU MLP, a single linear-attention block can solve ℓ₁-regularized QPs via ISTA and ℓ₁-constrained QPs via projected gradient descent.
**Mechanism:** The attention block first produces the unconstrained gradient step **yₖ = xₖ - γ (A xₖ + b)**. For ℓ₁-regularized QPs, a fixed MLP computes element-wise soft-thresholding **S_{γλ}(·)**, giving **xₖ₊₁ = prox_{γλ∥·∥₁}(yₖ)**. For ℓ₁-constrained QPs (ℓ₁-ball), the MLP is wrapped in a scalar threshold loop: iterate **θ ← θ + η ReLU(∥S_θ(yₖ)∥₁ - B)** until convergence; the final **S_θ*(yₖ)** equals the Euclidean projection onto the ℓ₁-ball.
**Core assumption:** MLP weights are exactly **W₁ = [I; -I]**, **W₂ = [I -I]** with bias, and ReLU implements the positive part. The threshold loop step size satisfies 0 < η ≤ 1/n and stabilizes.
**Evidence anchors:**
*   [abstract] "Furthermore, by incorporating MLPs, a transformer block can solve (i) ℓ₁-penalized QPs by emulating iterative soft-thresholding and (ii) ℓ₁-constrained QPs when equipped with an additional feedback loop."
*   [section 3.4] Full constructions for both regularized and constrained cases, including the threshold loop convergence proof.
**Break condition:** The mechanism relies on the specific fixed MLP; altering activation or making weights learnable breaks the guarantee. The loop requires enough iterations. The construction applies only to ℓ₁ constraints.

### Mechanism 3
**Claim:** Prepending learned covariance tokens to a time series foundation model enables end-to-end portfolio optimization that surpasses the predict-then-optimize pipeline, especially under noisy returns and loose rebalancing constraints.
**Mechanism:** The covariance matrix of the return series is projected via an MLP into *m* tokens (one per asset) representing rows of the covariance structure. These tokens are prepended to the usual patch tokens of returns and allocations. Joint self-attention then processes the full sequence, allowing the model to condition its allocation predictions on both historical returns and the second-order statistics. Training uses supervised targets derived from the mean-variance oracle, so the model learns to calibrate its reactions to return forecasts, performing an implicit shrinkage that reduces overfitting to noise compared to a plug-in estimator.
**Core assumption:** Covariance is a sufficient statistic for optimal allocation under mean-variance utility. The MLP produces informative token embeddings, and the foundation model has enough capacity. A feasibility projection remains necessary.
**Evidence anchors:**
*   [abstract] "We empirically find that Time2Decide consistently improves over SFT-TimePFN and Pretrained-TimePFN... Predict-then-Optimize (PtO) achieves the lowest errors at small rebalancing budgets... Time2Decide shows superior performance at larger budgets, surpassing PtO... under noise, Time2Decide’s MSE is 0.0476 compared to PtO’s 0.0781."
*   [section 5.3] Tables 4 and 5 present MSE results across γ regimes; Time2Decide dominates at γ ≥ 1.5 and in noisy settings.
**Break condition:** Very poor covariance estimates (e.g., short lookback) may mislead. The method assumes the allocation problem can be approximated by an ℓ₁-constrained QP; highly nonlinear transaction cost models may not fit.

## Architecture Onboarding
**Component map:** Historical returns (patched) -> Covariance computation -> Covariance Token MLP (row-wise projection) -> [Covariance tokens] + [Return/Allocation patch tokens] + Positional encoding -> TimePFN Transformer backbone (linear attention blocks + FFNs) -> Dual output heads (return forecast, raw allocation) -> Feasibility Projection (OSQP) -> Final allocation ŝₜ.

**Critical path:**
1.  For a batch, compute the empirical covariance matrix of the return patches over the lookback window.
2.  Generate covariance tokens via the row-wise MLP, prepend them to the patch tokens, and add positional encodings.
3.  Run the full sequence through the TSFM backbone to obtain the return prediction and raw allocation.
4.  Compute the oracle allocation (mean-variance solution with true next-period returns) and loss = λ_r ∥r̂ - r∥² + ∥ŝ_proj - s*∥².
5.  Backpropagate to train the covariance token MLP and the TSFM end-to-end. At inference, only the final projection is applied.

**Design tradeoffs:**
*   **Attention mechanism:** Linear attention enables the theoretical emulation and O(N) complexity but may have weaker empirical performance than softmax on some tasks; softmax loses provable link.
*   **Covariance token size:** Using one token per asset (m) adds linear overhead; compressing to fewer tokens loses resolution and hurts performance.
*   **TSFM depth:** More layers allow simulating more optimization iterations, but gains plateau and overfitting risk increases.
*   **λ_r balance:** Small λ_r focuses on allocation accuracy; large λ_r improves return forecasting but can degrade allocation under noise. Requires validation tuning.

**Failure signatures:**
*   High maximum constraint violation: raw allocations are far from feasible; check covariance token quality or model capacity.
*   Time2Decide does not beat Predict-then-Optimize under loose γ: model failed to learn calibrated shrinkage; consider increasing depth or adjusting λ_r.
*   Under noise, both degrade but PtO degrades more: if Time2Decide does not show this, covariance tokens may be uninformative; inspect MLP and covariance estimation stability.
*   Training loss does not decrease: possible tokenization issues (e.g., eigenvalue scaling), learning rate, or gradient flow through projection.
*   Overfits on training series but fails on new ones: dataset shift; increase training data diversity.

## Open Questions the Paper Calls Out
The paper primarily validates Time2Decide on portfolio optimization with ℓ₁ constraints and linear attention. Several open questions remain:  
*   Can the constructive linear attention designs be relaxed to allow learned weights while preserving near-optimal performance?  
*   How does the method scale to higher-dimensional QPs (e.g., thousands of assets) given the per-asset covariance tokens?  
*   Can the approach incorporate more complex constraints (e.g., cardinality, sector exposure) beyond ℓ₁?  
*   What is the theoretical convergence rate when stacking multiple blocks with approximate tokenization?  
*   Does the implicit covariance conditioning generalize to non-Gaussian return distributions?  
*   Can the separate feasibility projection be integrated into the transformer for end-to-end constrained optimization?

## Limitations
The Time2Decide method has several inherent limitations:  
*   **Exactness requires fixed weights and linear attention:** The theoretical emulation of gradient descent and proximal operators relies on precisely specified, frozen linear projections and linear attention. Deviations (e.g., learned weights, softmax) break the guarantee.  
*   **Constraint class restricted:** The constructions explicitly handle unconstrained, ℓ₁-regularized, and ℓ₁-constrained QPs. Extensions to other constraints (e.g., box, general linear) are not provided.  
*   **Covariance token dependency:** Performance hinges on accurate covariance estimation. With short lookbacks or highly volatile returns, the covariance tokens may become uninformative or misleading.  
*   **Separate projection step:** The model outputs a raw allocation that may violate constraints; a downstream solver (OSQP) is still needed for feasibility, adding computational overhead and potential distortion.  
*   **Empirical scope limited:** Evaluation is confined to portfolio optimization tasks with synthetic or specific real-world data. Generalization to other QP domains (e.g., resource allocation, signal processing) is not demonstrated.  
*   **Scalability concerns:** Prepending one token per asset increases sequence length linearly with asset count, which may become inefficient for very large universes.

## Confidence
*   **High confidence** in the theoretical constructions: the proofs are constructive and mathematically rigorous within the stated assumptions (linear attention, fixed MLP weights, correct tokenization).  
*   **Medium confidence** in the empirical superiority of Time2Decide for portfolio optimization under the tested conditions (γ regimes, noise levels). The results are consistent across multiple experiments, but the benchmark suite is relatively narrow (only a few baselines, limited dataset diversity).  
*   **Low confidence** that the method directly transfers to other quadratic programming contexts or more complex constraint sets without architectural modifications. The paper does not provide evidence beyond the portfolio domain.

## Next Checks
To further validate and extend the work:  
1.  **Broader domain validation:** Test Time2Decide on standard QP benchmark suites (e.g., QP LIB, Maros-Mészáros problems) with diverse constraint types.  
2.  **Weight relaxation study:** Train the linear attention weights with gradient descent while regularizing toward the theoretical construction; measure degradation in solution accuracy.  
3.  **Scalability stress test:** Evaluate runtime and memory as a function of asset count (e.g., 100, 500, 1000 assets) and compare with classical solvers.  
4.  **Covariance estimation robustness:** Systematically vary lookback window length, sampling frequency, and noise injection to characterize the breakdown point of covariance token utility.  
5.  **End-to-end constrained training:** Investigate whether the projection step can be replaced by a differentiable feasibility layer (e.g., via convex optimization layers) to enable full end-to-end learning.  
6.  **Comparison with neural QP solvers:** Benchmark against recent learning-based QP solvers (e.g., OptNet, QP-solving GNNs) on the same portfolio tasks to contextualize performance gains.
