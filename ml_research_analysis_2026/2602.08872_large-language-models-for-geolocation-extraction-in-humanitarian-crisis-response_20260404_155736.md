# Large Language Models for Geolocation Extraction in Humanitarian Crisis Response

## Quick Facts
- **arXiv ID:** 2602.08872
- **Source URL:** https://arxiv.org/abs/2602.08872
- **Reference count:** 40
- **Primary result:** Two-step LLM framework (NER + agent geocoder) achieves exact F1 0.84, near-parity false negative rates, and halves classification error disparity between high and low-income countries.

## Executive Summary
Humanitarian crisis response relies on accurate geolocation data from text, but current automated extraction suffers from geographic and socioeconomic bias. This paper introduces a two-step framework: few-shot large language model (LLM) based named entity recognition (NER) using JSON or Markdown output formats, followed by an LLM agent that performs geocoding via contextual reasoning and GeoNames queries. Evaluated on an extended HumSet dataset, the approach shows that LLM-based NER, especially GPT-4o with JSON output, yields high extraction accuracy (exact F1 0.84, partial recall 0.99) and substantially improves false negative rate parity across continents and income levels. The geocoding agent outperforms a rule-based baseline, raising exact precision from 0.69 to 0.88 and cutting classification error disparity by roughly half. These results demonstrate that LLMs can both enhance accuracy and promote fairness in crisis geolocation, enabling more inclusive data-driven humanitarian action.

## Method Summary
The proposed system processes humanitarian documents in two stages. First, documents are chunked with sizes tailored to the chosen LLM output format (JSON: 1000–2000 characters; Markdown: 200–500). A few-shot prompt guides the LLM to extract location toponyms; JSON returns a list while Markdown reproduces tagged text. Post-processing merges adjacent toponyms, and for JSON a dynamic-programming alignment matches extracted strings to the original text. Second, each extracted toponym is fed to a geocoding agent built with LangChain. The agent iteratively calls a GeoNames search tool and a selection tool that considers the document context, eventually emitting a geoname ID via a finish tool. Evaluation uses the extended HumSet corpus (467 English documents, 8,213 literal toponyms) for NER, and a gold-standard geocoding set (47 documents, 969 toponyms) for spatial accuracy. The framework is compared against pretrained NER models (spaCy, RoBERTa) and a rule-based geocoder from prior work.

## Key Results
- GPT-4o JSON NER achieves exact F1 of 0.84 and partial recall of 0.99, with near-parity in false negative rates across continents (ΔFNR ~0.01–0.02) and income levels.
- The agent-based geocoder raises exact precision to 0.88 (vs. 0.69 for the rule-based baseline) and reduces classification error disparity (ΔError) between high- and low-income countries by approximately half (0.18 vs. 0.35).
- LLM-based NER and the geocoding agent together improve fairness metrics, demonstrating the potential of LLMs to mitigate geographic and socioeconomic bias in crisis geolocation.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** LLM-based NER mitigates geographic bias in location extraction by improving recall for underrepresented regions compared to pretrained models.
- **Mechanism:** The system uses few-shot prompting with examples covering diverse locations, combined with a dynamic-programming alignment algorithm that matches extracted toponyms to the input text while preserving order. This allows the model to generalize from limited demonstrations and handle varied toponym expressions without task-specific retraining.
- **Core assumption:** LLMs possess inherent world knowledge that, when guided by carefully selected few-shot examples, can recognize location mentions across diverse geographic contexts more robustly than models trained on narrow, Western-centric corpora.
- **Evidence anchors:**
  - Abstract: "LLM-based methods substantially improve both the precision and fairness of geolocation extraction... particularly for underrepresented regions."
  - Section 4, Table 1 shows LLMs (e.g., GPT-5 Markdown) achieve near-parity in FNR across continents (~0.01–0.02), while RoBERTa variants show disparities up to 0.67.
  - Corpus: Neighbor papers (e.g., "Leave no Place Behind") confirm baseline biases; this paper's method directly addresses that.
- **Break condition:** If the few-shot examples fail to include representative toponyms from low-income or non-Western regions, the LLM may default to biases from its pretraining data, degrading recall for those areas.

### Mechanism 2
- **Claim:** The agent-based geocoder reduces geographic error disparities by using contextual reasoning to resolve ambiguous toponyms instead of relying solely on gazetteer string matching.
- **Mechanism:** For each extracted toponym, the agent iteratively calls `search_tool` (GeoNames queries) and `select_tool` (selection with context), integrating the document's surrounding text as reasoning steps. This allows it to distinguish between homonyms (e.g., "Cambridge" UK vs. US) and prefer appropriate administrative levels.
- **Core assumption:** Providing the LLM agent with both the toponym string and its surrounding narrative context enables more accurate disambiguation than rule-based systems that use isolated string matching or n-gram heuristics.
- **Evidence anchors:**
  - Section 3: The agent "leverages context to resolve ambiguous or low-resource toponyms" and uses explicit reasoning traces.
  - Section 4, Table 2 shows the agent reduces ΔError by ~50% across income levels (0.18 vs 0.35) and lowers classification error in all continents compared to the rule-based baseline.
  - Section 3 example: Agent correctly identifies "central Mediterranean" as the sea, while rule-based matches to "Davao" due to lexical similarity.
- **Break condition:** If the context provided is insufficient, contradictory, or references extremely obscure places absent from GeoNames, the agent may make incorrect selections or exhaust its action limit (15 calls) without resolution.

### Mechanism 3
- **Claim:** The choice of LLM output format (JSON vs. Markdown) creates a precision-recall-fairness trade-off that can be tuned for deployment needs.
- **Mechanism:** JSON output requires post-processing with dynamic alignment but enables processing longer chunks, leading to higher precision (fewer false positives). Markdown output reproduces the text verbatim with delimiters, capturing more mentions (higher recall) but at greater token cost and with more associative toponym false positives. This format-dependent behavior influences fairness metrics because different regions have varying densities of associative mentions.
- **Core assumption:** The verbatim reproduction requirement of Markdown prompts the LLM to be more permissive in tagging, while JSON's list format encourages more selective extraction. These inherent format constraints propagate to downstream fairness outcomes.
- **Evidence anchors:**
  - Section 4, Figure 2 shows JSON configurations have higher precision, Markdown higher recall.
  - Section 4, Table 1 shows high-FDR models (e.g., GPT-4o Markdown) have ΔFDR up to 0.56 by continent, driven by false positives in Europe where literal toponyms are sparse.
  - Section 3: JSON allows larger chunks (1000–2000 chars) vs. Markdown (200–500) to combat verbatim reproduction errors.
- **Break condition:** If document structure heavily uses associative references in certain regions (e.g., institutional names in Europe), Markdown's high recall will produce proportionally more false positives there, worsening FDR disparity unless corrected in post-processing.

## Foundational Learning
### Few-Shot Learning with LLMs
- **Why needed here:** The system avoids costly retraining by using in-context examples to steer the LLM toward humanitarian toponym extraction. Understanding prompt design and example selection is crucial for performance.
- **Quick check:** How would the model's behavior change if the few-shot examples all mentioned locations from high-income countries?

### Dynamic Programming for Text Alignment
- **Why needed here:** The JSON pipeline loses position information; the alignment algorithm optimally matches a list of extracted toponyms to their occurrences in the original text, handling duplicates and out-of-order predictions.
- **Quick check:** Why can't a simple greedy "first match" strategy work for aligning toponyms like ["Goma", "Goma", "Bukavu"] in the text "Goma, Bukavu, Goma"?

### Agent-Based Tool Use (Reasoning + Acting)
- **Why needed here:** The geocoding agent interleaves LLM reasoning with external tool calls (GeoNames search/select), enabling contextual disambiguation. This is a core departure from static rule-based geocoders.
- **Quick check:** What specific piece of context might cause the agent to select a city over a country when resolving "Paris"?

## Architecture Onboarding
**Component map:**  
Preprocessor (Chunker) → LLM NER (JSON/Markdown) → Postprocessor (Alignment/Merge) → Geocoding Agent (search_tool, select_tool, finish_tool) → Output coordinates

**Critical path:**  
Document → Chunker → LLM NER (format choice) → Post-process → For each tag: Agent (search → select → ...) → finish_tool → Evaluated coordinates. The agent's action limit (15 calls) and post-processing alignment are key integration points.

**Design tradeoffs:**  
- **JSON vs. Markdown:** JSON = higher precision, longer chunks, slower post-processing. Markdown = higher recall, shorter chunks, more tokens, verbatim failure risk.
- **Agent thoroughness vs. efficiency:** More search/select cycles improve disambiguation but risk hitting the 15-action limit on complex tags.
- **Gazetteer dependency:** Agent inherits GeoNames biases (e.g., feature code preferences); cannot resolve places missing from GeoNames.

**Failure signatures:**  
- **NER:** High FDR in Europe (Table 1) indicates over-tagging of associative mentions. Low recall in baseline models (RoBERTa) for Africa/Asia.
- **Geocoding:** Cross-continent errors (Figure 3, rule-based "Mediterranean → Davao"). Agent over-specification (e.g., "eastern South Sudan" → Eastern Equatoria instead of country).
- **Systemic:** Action exhaustion (`finish_tool` never called), unresolved toponyms (`geonameid=-1`), or high Δ metrics.

**First 3 experiments:**  
1. **Format Impact Test:** Run same documents through JSON and Markdown pipelines. Compare exact/partial F1 and token count/processing time. Expect Markdown > recall, JSON > precision.
2. **Geographic Parity Check:** Compute FNR/FDR by continent/income for best LLM NER (e.g., GPT-5 Markdown). Verify ΔFNR is low (<0.05) as in Table 1.
3. **Agent vs. Baseline:** On 10% sample (47 docs), run agent and rule-based geocoder. Measure @161km accuracy and ΔError by income. Expect agent's ΔError ~0.18 vs baseline ~0.35.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Can supervised prompt optimisation improve few-shot LLM NER and exceed fine-tuned models?
- **Basis in paper:** Future work should investigate supervised prompt optimisation for improved few-shot performance and potential gains over fine-tuning.
- **Why unresolved:** Current prompts are handcrafted; optimisation may boost accuracy and fairness without extra annotation.
- **What evidence would resolve it:** Supervised prompt optimisation (e.g., DSPy) applied to LLMs on HumSet; compare exact/partial F1 and fairness against baselines.

### Open Question 2
- **Question:** How does the framework perform on non-English humanitarian texts?
- **Basis in paper:** Only English HumSet documents were evaluated, although the dataset is multilingual and crises often involve other languages.
- **Why unresolved:** Performance in other languages is unknown; linguistic variation could affect accuracy and fairness.
- **What evidence would resolve it:** Evaluate the pipeline on non‑English HumSet portions (or translated versions) and report per‑language metrics, including fairness.

### Open Question 3
- **Question:** What can further reduce geographic and socioeconomic disparities in geocoding after the agent‑based improvements?
- **Basis in paper:** The agent reduced ΔError by about half but disparities remain (e.g., ΔError = 0.25 across continents); residual LLM biases are noted.
- **Why unresolved:** Remaining disparity may still omit some regions from crisis data.
- **What evidence would resolve it:** Ablation studies isolating biases (GeoNames, context handling), testing alternative knowledge sources or debiasing, and measuring fairness changes.

## Limitations
- Reproduction depends on inaccessible implementation details (exact few-shot prompts, alignment algorithm, context window size) and dataset versions.
- Fairness metrics rely on unspecified group assignment methods for false positives, which could affect reported disparity reductions.
- Evaluation is limited to English HumSet documents and inherits biases from the GeoNames gazetteer, limiting generalizability to other languages or extremely low-resource locations.
