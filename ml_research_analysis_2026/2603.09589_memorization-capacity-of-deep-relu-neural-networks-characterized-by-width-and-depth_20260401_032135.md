# Memorization capacity of deep ReLU neural networks characterized by width and depth

## Quick Facts
- **arXiv ID:** 2603.09589
- **Source URL:** https://arxiv.org/abs/2603.09589
- **Reference count:** 12
- **Primary result:** Tight memorization bounds: any ReLU network memorizing N δ-separated points with C labels satisfies W²L² = Ω(N log C / (log C + log δ⁻¹)), while a constructive network achieves W²L² = O(N (log δ⁻¹ + log C)); they match up to logarithmic factors when δ⁻¹ is polynomial in N.

## Executive Summary
This paper establishes the precise relationship between width and depth required for deep ReLU networks to memorize a dataset of N δ-separated points with C discrete labels. The authors derive both lower and upper bounds on the product W²L² that are tight up to logarithmic factors under a polynomial separation condition. Their constructive approach decomposes the memorization task into three subnetworks: a linear projection that maps inputs to integers with pairwise separation, a block-wise encoder that concatenates binary representations of inputs and labels, and a sequential bit-extraction module that retrieves the correct label for each input. The resulting trade-off quantifies exactly how width and depth interchange: larger width can compensate for shallower depth and vice versa. This work provides the first near-optimal characterization of memorization capacity for ReLU networks under separation constraints, answering a fundamental question in deep learning theory.

## Method Summary
The core method is a three-stage construction. First, a single linear layer projects the δ-separated d-dimensional inputs (norm ≤1) onto a 1D line such that the projected values are at least 2 apart and lie in [0,R] (Lemma 2.3). Second, the integer parts of these projections are partitioned into blocks of size S; within each block the binary strings of the integers and of the labels are concatenated to form two large integers u_j and w_j. A piecewise linear subnetwork F_2 computes these block identifiers and the encoded values (Lemma 2.5). Third, a depth‑controlled sequential module F_3 (Lemma 2.6) uses T‑layer bit‑extraction units to compare each integer part against the segments of u_j; upon a match it extracts the corresponding segment from w_j to output the label. The overall network is the composition F = F_3 ∘ F_2 ∘ F_1. The parameters S and T allow a smooth trade‑off: larger S reduces width but increases depth linearly, while larger T reduces width by processing more bits per layer but also increases depth. By optimizing S and T relative to N, log R, and log C, the construction achieves W²L² = O(N (log δ⁻¹ + log C)). A lower bound based on shattering arguments (Warren’s lemma) shows any memorizing network must satisfy W²L² = Ω(N log C / (log δ⁻¹ + log C)). When δ⁻¹ is polynomial in N the two bounds coincide up to logarithmic factors.

## Key Results
- **Lower bound:** Any ReLU network memorizing N δ-separated points with C labels requires W²L² = Ω(N log C / (log C + log δ⁻¹)).
- **Upper bound:** There exists a ReLU network with W²L² = O(N (log δ⁻¹ + log C)) that achieves memorization.
- **Optimality:** The bounds match up to logarithmic factors when δ⁻¹ is polynomial in N; thus the construction is nearly optimal in the worst case.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The network first projects high-dimensional separated inputs into a 1D line with guaranteed pairwise integer separation.
- **Mechanism:** A single-layer linear map (Lemma 2.3) scales the original d-dimensional points \(x_i\) (with \(\|x_i\| \le 1, \|x_i - x_j\| \ge \delta\)) to \(\bar{x}_i \in [0, R]\) such that \(|\bar{x}_i - \bar{x}_j| \ge 2\). This ensures all \(\lfloor \bar{x}_i \rfloor\) are distinct integers, making their binary representations uniquely decodable.
- **Core assumption:** Input points are \(\delta\)-separated and norm-bounded within the unit ball.
- **Evidence anchors:**
  - [abstract] Establishes the separation condition \(\|x_i - x_j\| \ge \delta\) and the projection step via Lemma 2.3.
  - [section 2.1, Step 1] Explicit construction of \(F_1\) and the property \(|\bar{x}_i - \bar{x}_j| \ge 2\).
- **Break condition:** If \(\delta\) is too small relative to network precision or the projection fails to achieve integer separation, the subsequent binary encoding becomes ambiguous.

### Mechanism 2
- **Claim:** Block-wise concatenation of binary strings transforms the set of \(N\) samples into a handful of large integers \(u_j, w_j\) that encode all input integers and labels compactly.
- **Mechanism:** The \(N\) projected points are partitioned into \(\lceil N/S \rceil\) blocks of size \(S\). For block \(j\), the integer parts \(\lfloor \bar{x}_i \rfloor\) are represented as \(\lceil \log R \rceil\)-bit strings and concatenated into \(u_j\). Similarly, labels \(y_i \in [C]\) become \(\lceil \log C \rceil\)-bit strings and form \(w_j\). A piecewise linear network \(F_2\) (Lemma 2.5) maps each \(\bar{x}_i\) to \((\bar{x}_i, u_j, w_j)\) where \(j = \lceil i/S \rceil\).
- **Core assumption:** Labels are discrete and finite (\(|Y| = C\)), enabling fixed-length binary representation.
- **Evidence anchors:**
  - [abstract] Mentions "block-wise encoding of inputs and labels into integers" and the parameters \(S\) (block size) and \(T\) (bit extraction depth) as central to the trade-off.
  - [section 2.1, Step 2] Detailed construction of \(u_j, w_j\) and the piecewise linear \(F_2\) via Lemma 2.5.
- **Break condition:** If labels are not discrete or require unbounded bit length, the concatenated integers \(w_j\) cannot represent all labelings exactly.

### Mechanism 3
- **Claim:** A sequential bit-extraction subnetwork \(F_3\) matches each \(\lfloor \bar{x}_i \rfloor\) to a segment of \(u_j\) to locate its position within the block, then extracts the corresponding label bits from \(w_j\).
- **Mechanism:** Based on Lemma 2.6, \(F_3\) uses \(T\)-layer modules to sequentially extract \(\rho\)-bit chunks from \(u_j\) (where \(\rho = \lceil \log R / T \rceil\)) and compare them to \(\lfloor \bar{x}_i \rfloor\) using interval check networks (Lemma 2.8). Upon match, it extracts the corresponding \(c\)-bit chunk from \(w_j\) (where \(c = \lceil \log C / T \rceil\)). The \(S\) blocks require \(S\) such cycles, total depth \(S(T+3)\).
- **Core assumption:** The integer parts are pairwise separated by \(\ge 2\), guaranteeing that only one segment can match any given \(\lfloor \bar{x}_i \rfloor\).
- **Evidence anchors:**
  - [abstract] Highlights the "sequential bit-extraction procedure with adjustable parameters \(S\) and \(T\)".
  - [section 2.1, Step 3 & Lemma 2.6] The formal construction using Lemmas 2.7 (bit extraction) and 2.8 (interval matching).
  - [section 2.2] Full proof of Lemma 2.6, showing how width \(4(2\lceil \rho/T \rceil + 2\lceil c/T \rceil + 1)\) and depth \(S(T+3)\) arise.
- **Break condition:** If the separation \(|\bar{x}_i - \bar{x}_j| < 2\), multiple segments could match, causing ambiguity. If \(T\) is too small relative to \(\log R, \log C\), width may blow up; if too large, depth increases.

## Foundational Learning
- **Concept: ReLU network expressiveness as piecewise linear functions.**
  - **Why needed here:** The entire construction relies on representing specific continuous piecewise linear (PWL) functions (e.g., \(g_u\) in Lemma 2.5) with bounded width/depth. Lemma 2.4 is the key tool: a PWL function with \(n\) pieces can be realized by a ReLU net with width \(6W+2\) and depth \(2L\) if \(6W^2L \ge n\).
  - **Quick check question:** If a piecewise linear function has \(n = 1000\) pieces, what is the minimal product \(W^2L\) needed to represent it according to Lemma 2.4?

- **Concept: Binary numeral system for encoding.**
  - **Why needed here:** The block encoding and bit extraction depend on representing integers and labels as fixed-length binary strings. The lengths \(\lceil \log R \rceil\) and \(\lceil \log C \rceil\) directly bound the parameters \(\rho, c\) and thus the network size.
  - **Quick check question:** If \(R = 1000\), what is the minimum number of bits required to represent any integer in \([0, R]\)? How does this affect the choice of \(T\) in Lemma 2.6?

- **Concept: VC-dimension and sign patterns for lower bounds.**
  - **Why needed here:** The lower bound (Theorem 3.2) uses shattering arguments: a network that memorizes all labelings of \(N\) points must realize at least \(C^N\) distinct sign patterns. Warren's lemma (Lemma 3.1) bounds sign patterns by a function of parameters \((W,L)\), yielding \(W^2L^2 \gtrsim N \log C / (\log \delta^{-1} + \log C)\).
  - **Quick check question:** Why does memorizing *any* labeling (not just one fixed labeling) require the network to shatter the point set? How does the separation \(\delta\) appear in the lower bound via the packing number \(T \asymp \delta^{-1}\)?

## Architecture Onboarding
- **Component map:** F1 (Projection) -> F2 (Block encoder) -> F3 (Bit extractor). F1: linear layer (width 1, depth 1) maps x_i to \bar{x}_i with separation ≥2 and range [0,R]. F2: two parallel piecewise linear subnetworks (Lemma 2.5) of width ~12W1+5 and depth 2L1, outputting (\bar{x}_i, u_j, w_j) where j = ceil(i/S). F3: sequential S cycles of bit-extraction+match modules (Lemma 2.6), width ~4(2⌈log R/T⌉+2⌈log C/T⌉+1), depth S(T+3), outputs y_i.
- **Critical path:** The data flow is x_i -> F1 -> \bar{x}_i -> F2 -> (\bar{x}_i, u_j, w_j) -> F3 -> y_i. Success depends on: (1) F1 separation, (2) F2 correct block indexing, (3) F3 unique match and extraction.
- **Design tradeoffs:** Parameters S (block size) and T (bits per layer) control the width-depth trade-off. Larger S reduces width (fewer blocks → smaller u_j, w_j) but increases depth linearly. Larger T reduces width (fewer bits handled per layer) but increases depth per block. To achieve W²L² = Θ(N(log δ⁻¹+log C)), set T ≳ max{log R, log C} and S ≍ √(N/(T+3)).
- **Failure signatures:**
 - Projection failure: F1 does not produce |\bar{x}_i - \bar{x}_j| ≥ 2 due to numerical issues or if δ is too small relative to precision.
 - Encoding collision: Two different ⌊\bar{x}_i⌋ fall into same bit segment of u_j because separation <2, causing label mix‑up.
 - Bit extraction overflow: T too small → width explodes; T too large → depth becomes impractical.
- **First 3 experiments:**
  1. **Validate F1 projection:** Generate N random δ-separated points in ℝ^d (unit ball). Apply linear map from Lemma 2.3. Check all \bar{x}_i ∈ [0,R] and |\bar{x}_i - \bar{x}_j| ≥ 2. Sweep δ and d to infer R scaling.
  2. **Test block encoding/decoding:** Fix S, R, C. For random blocks compute u_j, w_j. Use F2 (or manual) to map each \bar{x}_i to (\bar{x}_i, u_j, w_j). Then manually extract bits from u_j, w_j to recover ⌊\bar{x}_i⌋ and y_i. Confirm 100% recovery across many labelings.
  3. **Probe F3 width-depth tradeoff:** For N=100, vary S,T, build full network F = F3∘F2∘F1. Measure actual width and depth. Check that W ≈ max{√(N/S), (log R)/T, (log C)/T} and L ≈ 3 S (T+3), and that the network memorizes the training set with zero error.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Are the polylogarithmic factors between the upper bound W²L² = O(N(log(δ⁻¹)+log C)) and the lower bound W²L² = Ω(N log C/(log(δ⁻¹)+log C)) inherent to memorization with ReLU networks, or can they be eliminated?
- **Basis in paper:** In the conclusion (Section 4), the authors explicitly ask to "verify whether the polylogarithmic factors in the width-depth complexity bounds are inherent to the memorization problem of ReLU networks or merely technical artifacts of the current proof methods." They also note that the gap can be as large as (log N)² when δ⁻¹ is polynomial in N.
- **Why unresolved:** The lower bound relies on Warren’s lemma and a covering argument that may be loose; the upper bound uses a block-wise encoding that might not be optimal. It is unknown whether tighter analysis can achieve matching up to constant factors, or if the logarithmic factors are fundamental.
- **What evidence would resolve it:** A matching lower bound (e.g., W²L² = Ω(N(log(δ⁻¹)+log C))) or an improved construction with W²L² = O(N(log(δ⁻¹)+log C)). If such bounds hold, the polylog factors are artifacts; if not, proving a separation would show inherent limitation.

### Open Question 2
- **Question:** Do the width-depth memorization trade-offs extend to other activation functions (e.g., GELU, sigmoid), or are they unique to ReLU’s piecewise linear nature?
- **Basis in paper:** The conclusion states: "extending the structural design of this work to other mainstream activation functions (e.g., GELU, Sigmoid) is worth in-depth investigation, so as to clarify whether the width-depth trade‑off mechanism and complexity bounds obtained in this study are unique to ReLU or generalizable across different activation functions."
- **Why unresolved:** The construction uses ReLU-specific properties (linear pieces, easy implementation of max/threshold operations) for exact bit extraction. Activations like sigmoid are smooth and may require different techniques; it is not known if similar bounds hold.
- **What evidence would resolve it:** Construct explicit networks with non-ReLU activations that achieve comparable upper bounds, or prove lower bounds that differ fundamentally (e.g., requiring more parameters). A negative result (e.g., exponential blow‑up for sigmoid) would also be informative.

### Open Question 3
- **Question:** Can the memorization capacity results be improved for data with additional structure (e.g., lying on a low‑dimensional manifold or being sparse), and how do intrinsic dimensionalities affect the width‑depth trade‑off?
- **Basis in paper:** The conclusion proposes: "expanding the proposed framework to complex data scenarios, such as manifold‑valued data and high‑dimensional sparse data, and optimizing the module division and parameter allocation strategies according to specific data characteristics."
- **Why unresolved:** The current work assumes points are in the unit ball with a uniform separation condition, which may be far from realistic for structured data. The interplay between intrinsic dimension, sparsity, and memorization capacity is unexplored.
- **What evidence would resolve it:** Derive new bounds that depend on manifold dimension, effective dimension, or sparsity level, and provide corresponding network constructions. Alternatively, show that worst‑case (Euclidean) bounds cannot be improved even with such structure, proving robustness of current results.

### Open Question 4
- **Question:** Can standard optimization algorithms (GD/SGD) with random initialization find the minimal‑size ReLU networks that memorize N separated points, or do optimization landscapes impose obstacles?
- **Basis in paper:** The conclusion asks: "whether standard training algorithms (e.g., GD or SGD) can converge to a solution which memorizes N data samples while the size of the network is as small as possible."
- **Why unresolved:** The existence of a small memorizing network does not guarantee that gradient‑based methods can locate its parameters. Over‑parameterized networks are known to have favorable optimization properties, but the minimal‑size regime may exhibit bad local minima, ill‑conditioning, or require specific initialization.
- **What evidence would resolve it:** Theoretical guarantees (e.g., convergence to global optimum for the minimal architecture) or empirical demonstrations on synthetic separated datasets showing that SGD indeed reaches the memorization error with the predicted network size. Counterexamples would reveal a gap between expressivity and optimizability.

## Limitations
- **Strong data assumptions:** The analysis requires δ-separation and norm-bounding; real data may violate these, and tiny δ can cause floating‑point errors that break integer separation.
- **Implicit range dependence:** The projection lemma yields a range R whose dependence on d and δ is not explicit, making it hard to estimate concrete network sizes.
- **Fixed block parameters:** The choices of block size S and bit‑per‑layer T are made a priori without adaptive knowledge of N, δ, C; this may lead to suboptimal resource allocation in practice.
- **Lack of independent validation:** The paper has zero citations and moderate relatedness to existing work, indicating limited external verification of its claims and proofs.

## Confidence
- **Lower bound:** High (based on standard shattering arguments and Warren’s lemma)
- **Constructive upper bound:** Medium (lemmas appear plausible but require detailed proof verification)
- **Optimality claim:** Medium (the logarithmic gap remains; tightness depends on parameter choices)
