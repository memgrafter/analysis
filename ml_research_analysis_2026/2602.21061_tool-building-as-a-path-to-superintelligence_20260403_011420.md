# Tool Building as a Path to "Superintelligence"

## Quick Facts
- arXiv ID: 2602.21061
- Source URL: https://arxiv.org/abs/2602.21061
- Reference count: 23
- Primary result: Frontier LLMs using tool calls maintain near-unity step-success probability γ_g up to depth 127, while small LLMs show superlinear decay.

## Executive Summary
This paper presents a benchmark for multi-step reasoning based on GF(2) circuit reconstruction with adversarial sampling, directly measuring the step-success probability γ_g. The benchmark forces models to uniquely predict the next gate by integrating a revealed prefix and new evidence, eliminating shortcuts. Experiments reveal that small language models suffer superlinear decay in γ_g as depth increases, whereas frontier models equipped with tool calls sustain near-unity γ_g even at depths of 127. The work posits that thoughtful tool design, as encapsulated in the Diligent Learner framework, is essential for scaling reasoning toward superintelligence.

## Method Summary
The GF(2) circuit reconstruction benchmark involves generating random boolean circuits over the finite field GF(2). At each step, a prefix of gate outputs is revealed, and new evidence (e.g., a specific gate input) is provided. The model must predict the next gate uniquely, with adversarial sampling ensuring that correct prediction requires integrating both prefix and evidence. Exact-next accuracy across varying depths operationalizes γ_g. Models are tested with and without tool call capabilities to assess the impact on reasoning scalability.

## Key Results
- Small LLMs exhibit superlinear decay in γ_g with increasing depth.
- Frontier models with tool calls maintain γ_g ≈ 1 at depths up to 127.
- Tool design emerges as critical for sustaining reasoning performance at scale via the Diligent Learner framework.

## Why This Works (Mechanism)
Tool calls allow models to outsource complex computations or evidence retrieval, mitigating error accumulation in multi-step chains. By delegating precise operations to tools, models avoid compounding mistakes that plague unaugmented reasoning, thus preserving high per-step accuracy. This mechanism aligns with the Diligent Learner framework, where diligent tool use enables consistent integration of new evidence, supporting scalable logical inference.

## Foundational Learning
1. **Step-success probability γ_g**: Probability of correct next-step prediction given context. *Why needed*: Measures reasoning accuracy per step in isolation. *Quick check*: Compute exact-match on next-step predictions in a controlled, single-step setting.
2. **GF(2) circuit reconstruction**: Benchmark using finite field circuits. *Why needed*: Provides a formal, bias-resistant domain for logical inference. *Quick check*: Generate a random GF(2) circuit, reveal a prefix, and verify unique next-step via manual simulation.
3. **Adversarial sampling**: Query sampling that enforces unique correct next steps. *Why needed*: Prevents statistical shortcuts, ensuring models must reason. *Quick check*: For sampled queries, confirm only one next gate satisfies both prefix and evidence constraints.
4. **Tool calls**: External tool invocation by LLM. *Why needed*: Augments model with reliable computation for evidence gathering. *Quick check*: Implement a tool that evaluates GF(2) expressions and test if model usage improves γ_g.
5. **Diligent Learner framework**: Theory that tool use enables depth scaling in reasoning. *Why needed*: Explains how tools maintain high γ_g by reducing error propagation. *Quick check*: Compare γ_g decay curves with and without tool access across depths.

## Architecture Onboarding
Component map: Input Circuit -> Prefix Reveal -> LLM (with Tool Call) -> Tool Execution (if invoked) -> Evidence Integration -> Next Step Prediction

Critical path: Receiving a partially revealed circuit, iteratively predicting each next gate by combining the current prefix and any new evidence, with tool calls inserted to fetch or compute evidence as needed.

Design tradeoffs: Increasing depth raises complexity but risks γ_g decay; tool call frequency trades latency for accuracy; tool type selection affects integration overhead and reliability.

Failure signatures: Steep decline in γ_g with depth for tool-less models; inconsistent predictions when evidence is ambiguous or tool outputs are erroneous.

First experiments:
1. Run the benchmark on a small LLM without tools for depths 5, 10, 20 to establish baseline decay behavior.
2. Integrate a simple GF(2) arithmetic tool with a frontier model and test at depth 50 to confirm γ_g maintenance.
3. Ablate tool call strategy (e.g., mandatory vs. optional calls) and measure γ_g at depth 100 to identify optimal usage patterns.

## Limitations
- GF(2) benchmark may not capture broader reasoning patterns or human-like logic.
- Evaluation covers limited model families, restricting generalizability of claims.
- Causal impact of tool design parameters lacks systematic ablation studies.
