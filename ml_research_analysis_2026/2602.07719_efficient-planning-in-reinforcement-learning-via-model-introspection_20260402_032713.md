# Efficient Planning in Reinforcement Learning via Model Introspection

## Quick Facts
- **arXiv ID:** 2602.07719
- **Source URL:** https://arxiv.org/abs/2602.07719
- **Reference count:** 40
- **Primary result:** By introspecting learned symbolic models to derive milestone subgoals, a bilevel planner achieves optimal or near‑optimal performance with sub‑exponential scaling in sparse‑reward relational tasks, whereas baseline planners scale super‑linearly or worse.

## Executive Summary
Reinforcement learning (RL) planners often treat transition and reward models as black boxes, leading to computational inefficiency in long‑horizon, sparse‑reward tasks. This paper proposes **model introspection**—analyzing learned symbolic models (first‑order logic decision lists for reward, STRIPS‑like schemas for transitions) to automatically derive *milestones*: states that yield maximal immediate reward. A bilevel planner then uses greedy outer‑level search over milestone states and an inner heuristic search (e.g., STRIPS literal‑counting) to reach each milestone. This bridges RL and classical planning, turning exponential search into sub‑exponential growth on benchmark relational domains.

## Method Summary
Given learned deterministic models: a reward function as an FOL decision list and a transition model as STRIPS‑like action schemas (preconditions, add/delete lists), the planner first extracts the condition for maximal reward. Using a **state mutation** procedure, it recursively analyzes this logical formula to compute minimal literal changes (additions/deletions) that would satisfy the maximal‑reward clause. Each mutation defines a set of *milestone* states. The outer planner performs greedy best‑first search over these milestones. For each candidate milestone, an inner informed search (e.g., A* or greedy best‑first with a literal‑counting heuristic) finds any trajectory satisfying the mutation within the remaining horizon. The resulting sub‑plans are concatenated to form a full plan.

## Key Results
- In a grid navigation domain, introspector’s runtime grows linearly with distance to goal, while baseline planners (greedy, MCTS, beam) show super‑linear or degrading performance.
- In relational domains (Blocks‑World, drawers, bins), introspector’s runtime and node expansions scale sub‑exponentially with problem size (e.g., number of blocks), whereas exhaustive greedy search scales super‑exponentially.
- The approach consistently achieves optimal or near‑optimal rewards, demonstrating that symbolic model introspection can efficiently guide long‑horizon planning in large, sparse‑reward environments.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Treating the learned reward model as an interpretable program allows automatic derivation of *milestones*—future states that yield maximal reward—without manual task engineering.
- **Mechanism:** The algorithm performs *state mutation* on the reward program (a FOL decision list). Given the current state `s`, it recursively analyzes the reward formula to compute minimal changes (add/delete literals) that would satisfy the maximal‑reward condition. Each mutation describes a set of state modifications that, if achieved, triggers `r_max`.
- **Core assumption:** The reward model is represented as a symbolic, compositional program (e.g., FOL decision list) whose structure can be recursively analyzed. Milestones are defined by satisfying the *first* clause in the decision list that outputs `r_max` while falsifying all earlier clauses.
- **Evidence anchors:** [abstract]: "compute 'milestones' (states yielding maximal reward) by analyzing the reward program via a state mutation procedure." [section 5.1]: Pseudocode for `mutateT` over FOL formula types. [corpus]: Novelty lies in formalizing introspection as program analysis over learned RL models.
- **Break condition:** If the reward model's representation is not compositional (e.g., a black‑box neural network), the state mutation procedure may not be definable or tractable.

### Mechanism 2
- **Claim:** A *bilevel planner* uses milestones as abstract goals for outer‑level search, and a classical heuristic search (e.g., STRIPS literal‑counting) for inner‑level trajectory finding, decoupling long‑horizon guidance from local action sequencing.
- **Mechanism:** The outer loop performs greedy best‑first search over milestone states. For each candidate milestone (from mutation output), the inner loop runs an informed search (e.g., A* with literal‑counting heuristic) to compute a trajectory from the current state to *any* state satisfying the mutation. The outer loop aggregates these sub‑plans toward the final solution.
- **Core assumption:** The transition model is also interpretable (e.g., STRIPS‑like action schemas) so that a domain‑agnostic heuristic (literal‑counting) can be computed. The inner search must be complete/effective within the mutation's constraint.
- **Evidence anchors:** [abstract]: "bilevel planner: outer greedy search over milestones, inner heuristic search (e.g., STRIPS literal‑counting) to reach each milestone." [section 5.3]: Outer greedy search (Algorithm 5) and inner `search` function with STRIPS heuristic. [section 4]: Grid example uses Manhattan distance derived from transition model.
- **Break condition:** If the heuristic is admissible but too weak (e.g., literal‑counting fails to discriminate), inner search may still expand exponentially many nodes, offsetting gains.

### Mechanism 3
- **Claim:** Milestones create a *partial abstraction* of the state space that reduces effective search complexity from super‑exponential to sub‑exponential in relational domains with sparse rewards, by focusing expansion on reward‑relevant regions.
- **Mechanism:** Milestones act as intermediate goals that guarantee a reward upon attainment. The outer search thus operates over a much smaller "milestone space" (often linear or polynomial in problem size) rather than the full exponential state graph. The inner search is confined to finding *any* path to a mutation‑satisfying state, not necessarily the globally optimal path, leveraging heuristics to prune.
- **Core assumption:** The set of immediate milestones `G(s)` is much smaller than the full reachable state set `F(s)`, and the mutation procedure accurately targets this set. The environment's reward structure is such that obtaining `r_max` requires a sequence of milestone achievements.
- **Evidence anchors:** [abstract]: "runtime and node expansions scale sub‑exponentially with problem size, whereas exhaustive greedy search scales super‑exponentially." [section 5.4]: Empirical results in Blocks‑World, drawers, bins domains showing sub‑exponential vs. super‑exponential growth (Figures 4, 9–13). [section 3]: Definition of `G*(s)` and `G(s)` as the node expansion function for milestone space.
- **Break condition:** If the reward is not decomposable into multiple milestones (e.g., single distant goal), or if mutations produce too many candidate milestones, the outer search may still face combinatorial explosion.

## Foundational Learning
- **Concept: Relational Representations (FOL, STRIPS)**
  - *Why needed here:* The state space is combinatorial (infinitely many ground states). Relational representations (objects, predicates, action schemas) allow compact model specification and enable the symbolic analysis (state mutation) that is core to introspection.
  - *Quick check question:* Given a Blocks‑World state with blocks A on B, B on table, and hand empty, write the ground literals and identify which predicates would be in the `add`/`delete` lists of a `Pick(X)` action schema.

- **Concept: Program Analysis (Symbolic Execution over FOL)**
  - *Why needed here:* State mutation is essentially a symbolic execution of the reward program: it computes the condition on state facts needed to hit a reward clause without enumerating concrete states. This requires understanding how to recursively transform logical formulas into constraints on state modifications.
  - *Quick check question:* For an existential formula `∃X: OnTable(X)`, what mutations does `mutateT` return if `OnTable(A)` is false but mutable (i.e., an action can make it true)?

- **Concept: Heuristic Search (A*, Greedy Best‑First, STRIPS Heuristic)**
  - *Why needed here:* The inner planner must efficiently find *any* path satisfying a mutation. The STRIPS literal‑counting heuristic (counting unsatisfied goal facts) provides a fast, domain‑agnostic estimate of distance to a goal state defined by a mutation.
  - *Quick check question:* If a mutation requires making `{+OnTable(A), +Clear(B)}` true, and the current state has `On(A,B)` true (which `OnTable(A)` would delete), how might the literal‑counting heuristic score this state relative to one where `On(A,B)` is false?

## Architecture Onboarding
- **Component map:**
  Model Inputs (T_hat STRIPS, R_hat FOL decision list) -> State Mutation Module (mutateT) -> Milestone Enumeration -> Inner Planner (heuristic search over state space) -> Outer Planner (greedy best‑first over milestone space) -> Termination check (C_hat)

- **Critical path:**
  Current state s -> extract_maximal_reward_condition(R_hat) -> mutateT(s, condition) -> for each mutation m: inner_search(s, H, m) -> new_state (milestone reached, reward added) -> outer loop continues from new_state. Success when inner_search finds a state satisfying termination condition.

- **Design tradeoffs:**
  - *Model representation:* Must be symbolic/compositional for mutateT. FOL decision lists for reward are expressive but mutation complexity grows with formula depth. STRIPS for transitions limits to add/delete effects.
  - *Outer search strategy:* Paper uses greedy best‑first (by score). Could use BFS or A* if mutateT output is large, but greedy reduces outer expansions.
  - *Inner heuristic:* STRIPS literal‑counting is fast but not necessarily admissible. Could use more informed heuristics (e.g., planning graph) at higher computational cost.
  - *Mutation handling:* A mutation may correspond to many concrete milestone states. Inner search can return *any* satisfying state, which may lead to suboptimal global plans but improves speed.

- **Failure signatures:**
  1. **Mutation returns empty set (unsatisfiable):** The reward condition cannot be achieved from current state due to immutable facts or action limitations. Outer search will backtrack.
  2. **Inner search fails within horizon:** The mutation is satisfiable but requires > remaining steps. Outer node is discarded.
  3. **Heuristic misguides inner search:** Literal‑counting may suggest a path that leads to a dead‑end (e.g., in bins domain, closing a non‑empty bin). Caught when outer search from that milestone fails to progress; plan may be suboptimal but still correct if alternative mutations exist.
  4. **mutateT produces many spurious mutations:** If reward formula is disjunctive or has many existentials, outer queue may fill with low‑probability goals. Mitigated by greedy ordering.

- **First 3 experiments:**
  1. **Grid domain (Section 4):** Test basic efficiency on simple state space (integer coordinates). mutateT is trivial: single milestone (0,0); heuristic is Manhattan distance. Compare runtime vs. distance d to show linear vs. super‑linear scaling of baselines. Validates that introspection‑derived milestones + heuristic can match model‑free optimal policy efficiency.
  2. **Blocks‑World (Section 5.4):** Test in relational domain with n blocks. mutateT processes reward formula ∀X: OnTable(X). Measure runtime and node expansions vs. n. Expect sub‑exponential vs. greedy’s super‑exponential. Confirms scaling benefit with symbolic models.
  3. **Bins domain (Appendix D):** Test multiple milestones per episode (empty and close each bin). mutateT handles reward formula with existential ∃X: Bin(X) ∧ .... Measures scaling with number of items n. Shows sub‑exponential growth even with sequential rewards. Tests ability to chain milestone sub‑plans.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can model introspection be systematically applied to non‑interpretable models, such as deep neural networks used in model‑based RL, where the transition and reward functions are black‑box function approximators?
- **Basis in paper:** The authors state in Section 6.1 that "the development of introspection algorithms for this class of models [neural networks] would have a profound impact on the field" and note that current black‑box models are "notoriously difficult to interpret."
- **Why unresolved:** The proposed introspection method assumes models are implemented as interpretable programs (e.g., FOL decision lists). Neural networks lack such symbolic structure, making techniques like symbolic execution or state mutation non‑trivial to define.
- **What evidence would resolve it:** A demonstrated algorithm that can extract meaningful, analyzable symbolic representations (e.g., program sketches, logical constraints) from trained neural network dynamics models, or a novel introspection technique that operates directly on network weights/activations to synthesize milestones.

### Open Question 2
- **Question:** To what extent can the introspector's efficiency guarantees (sub‑exponential scaling) be maintained when the learned models (  T ,  R) are imperfect or inaccurate, as is typical in practical RL settings?
- **Basis in paper:** The paper assumes "the agent’s learning process has already converged such that  T and  R reproduce the behavior of T and R respectively" (Section 2.5). All empirical results rely on perfect ground‑truth models provided by the experimenter.
- **Why unresolved:** Real‑world model‑based RL deals with model approximation error. The state mutation procedure's correctness depends on the reward model's logical structure being accurate; errors could generate invalid or unsatisfiable milestones, leading to planning failure or inefficiency. The method's robustness to noise is unanalyzed.
- **What evidence would resolve it:** Empirical evaluation of introspector using learned (imperfect) models from standard model‑based RL algorithms in the same domains, measuring degradation in plan optimality and runtime scaling compared to ground‑truth models. Theoretical analysis bounding performance loss as a function of model error.

### Open Question 3
- **Question:** Can the model introspection approach be extended beyond discrete, relational domains with symbolic state representations to continuous or high‑dimensional observation spaces (e.g., pixel inputs), and if so, what form would "milestones" take?
- **Basis in paper:** The paper exclusively uses first‑order logical state representations (sets of ground predicates). The proposed state mutation procedure fundamentally relies on manipulating discrete, symbolic facts. The authors discuss representation learning but do not address bridging to raw or continuous perceptual inputs.
- **Why unresolved:** Defining mutable state changes and evaluating milestone conditions (FOL formulas) requires a symbolic state abstraction. In continuous domains, it is unclear how to automatically derive such a representation or what analogous "milestone" concept would exist (e.g., regions in latent space?).
- **What evidence would resolve it:** An algorithm that, given a continuous observation space and a learned model (e.g., a world model), automatically discovers a discrete abstract state representation suitable for symbolic state mutation, or a reformulation of milestones as goals in a learned latent space that can be efficiently targeted by planning.

### Open Question 4
- **Question:** How does the computational cost of the model introspection process (i.e., the state mutation and heuristic computation) scale with the complexity of the reward/transition models themselves (e.g., size of decision list, number of predicates), and does this introduce new bottlenecks?
- **Basis in paper:** The primary runtime results contrast introspector's planning time against baselines. However, the runtime of the `mutateT` procedure itself—especially for complex, large FOL formulas with quantifiers—is not decomposed or analyzed asymptotically. The paper claims sub‑exponential growth in problem size, but model complexity is a separate axis.
- **Why unresolved:** In the relational domains, the reward condition (e.g., `∀𝑋: OnTable(𝑋)`) is simple. Realistically, learned reward functions could be complex. The mutation procedure involves recursive decomposition and Cartesian products over substitutions; its cost is exponential in formula structure in the worst case. This could offset gains from reduced state‑space search if the model is very large.
- **What evidence would resolve it:** Empirical scaling experiments varying the complexity of the reward formula (e.g., number of conjuncts, quantifier nesting depth) in a controlled setting, measuring the proportion of total planning time spent in mutation vs. state‑space search. Theoretical worst‑case and average‑case analysis of `mutateT`.

### Open Question 5
- **Question:** Would alternative algorithms for the outer‑level "milestone‑space" search (beyond greedy best‑first) further improve efficiency, particularly in domains with interdependent or sequential milestones?
- **Basis in paper:** The outer loop in Algorithm 5 uses a greedy best‑first strategy, ordering candidate plans by current score. The authors note that "other techniques, such as exhaustive search, could be used as well." However, the trade‑offs between different search strategies (e.g., A*, Monte Carlo Tree Search over milestones) are unexplored.
- **Why unresolved:** Greedy search may fail to find globally optimal milestone sequences if early high‑reward milestones lead to dead ends or require costly sub‑plans. The paper's domains have a simple linear milestone dependency (all blocks on table). In environments with non‑linear, prerequisite‑based milestones (e.g., "get key A before opening door B"), a more sophisticated milestone planner might be needed to avoid backtracking and maintain sub‑exponential scaling.
- **What evidence would resolve it:** Comparative experiments in modified domains (e.g., with prerequisite chains, or where some milestones are "traps") using different outer‑level planners (A*, BFS, MCTS) while keeping the inner search fixed, measuring plan quality, success rate, and runtime.

## Limitations
- **Perfect model reliance:** The approach assumes accurate, symbolic transition and reward models (FOL decision lists, STRIPS). Errors or non‑symbolic representations (e.g., neural networks) would break the mutation analysis.
- **Reward formula expressiveness:** The `mutateT` procedure handles restricted FOL structures (decision lists, simple quantifiers). Complex nested formulas may yield unsatisfiable mutations or cause combinatorial explosion in the outer search.
- **Domain scope:** Experiments cover deterministic, fully observable, discrete settings. Extension to stochastic or continuous RL problems remains untested.

## Confidence
- **Milestone derivation (model introspection):** High – algorithm explicitly defined and sound for specified model class.
- **Sub‑exponential scaling (bilevel planner):** Medium‑High – empirical results in relational domains support claim, but scaling evidence limited to specific instances and lacks formal guarantees.
- **Bridging RL and classical planning:** Medium – proof‑of‑concept shown in synthetic benchmarks; real‑world applicability to high‑dimensional, stochastic RL environments remains speculative.

## Next Checks
1. **Model noise test:** Inject random errors (e.g., flip 5% of add/delete effects) into learned models and measure success rate and runtime growth. A sharp drop would highlight sensitivity to model imperfections.
2. **Complex reward stress test:** Create a Blocks‑World task with a nested reward formula (e.g., ∀X (OnTable(X) ∨ Clear(X))). Compare mutation count and planning time against the simpler ∀X OnTable(X) to assess `mutateT` scalability.
3. **Heuristic ablation:** Replace STRIPS literal‑counting with a more informed heuristic (e.g., planning‑graph hFF) in the inner search. Measure node expansions and wall‑clock time across domain sizes to evaluate impact on overall efficiency.
