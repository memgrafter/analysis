# When the Coffee Feature Activates on Coffins: An Analysis of Feature Extraction and Steering for Mechanistic Interpretability
## Quick Facts
- arXiv ID: 2601.03047
- Source URL: https://arxiv.org/abs/2601.03047
- Reference count: 5
- Primary result: Sparse autoencoders (SAEs) do not yet provide the systematic reliability needed for safety-critical AI interpretability, as feature steering proves fragile and interpretations often misalign with behavior.

## Executive Summary
This paper stress-tests the core claims of mechanistic interpretability (MI) by replicating and extending experiments using sparse autoencoders (SAEs) on Llama 3.1. While basic feature extraction and steering can be reproduced, the authors find that steering is highly sensitive to layer, coefficient, and context. Automated interpretations often fail to match a feature’s actual activation patterns or causal influence. Thematically similar features within a layer frequently lack clear distinctions, and many features exhibit spurious behaviors like hyperactivation. The results challenge the reliability of current SAE-based interpretability for AI safety and suggest a needed pivot toward robust output prediction and control.

## Method Summary
The study uses open-source models: Llama 3.1 8B and Neuronpedia’s pre-trained SAEs (Llama Scope, residual stream, 8× expansion, 32,768 features per layer). For a selected layer, inputs are passed through the model and SAE to obtain sparse latent activations. Steering intervenes by adding a coefficient multiple of a feature’s decoder vector to the SAE’s latent representation, then splicing the modified representation back into the transformer’s residual stream at that layer. Generation proceeds with fixed parameters (seed 16, temperature 0.5, frequency penalty 1.0). Evaluation involves logging activations, analyzing output text, and using an LLM (o4-mini) to automatically interpret features from activation samples on a corpus.

## Key Results
- Feature steering exhibits substantial fragility: effectiveness varies dramatically with layer depth, steering coefficient, and input context.
- Automated interpretations (LLM-generated labels from activation samples) frequently misalign with observed activation patterns and steering effects.
- Multiple features with similar descriptions (e.g., “coffee”) within the same layer often show no clear behavioral distinctions, undermining monosemantic claims.

## Why This Works (Mechanism)
### Mechanism 1
- Claim: SAEs can extract human-interpretable features and steering them causally influences output in intended ways.
- Mechanism: SAEs are trained on residual stream activations with a high-dimensional hidden layer and L1 penalty to produce sparse latents. Each latent is interpreted as a “feature.” Steering adds a coefficient of the feature’s decoder vector back into the residual stream during generation.
- Core assumption: Features are monosemantic and their directional influence on the residual stream causally affects token predictions aligned with that concept.
- Evidence anchors: Replication of a “coffee” feature activating on multilingual coffee terms; steering that feature changes alcoholic beverage outputs to coffee-related text.
- Break condition: The mechanism fails when interpretations do not match activation/steering, or when steering is highly sensitive to coefficient, layer, or context.

### Mechanism 2
- Claim: Interpretability and steerability of SAE-derived features are fragile and not systematically reliable.
- Mechanism: Feature behavior depends on layer position (middle layers more stable), steering coefficient (small changes cause disproportionate effects), and input context (some features activate only with specific surrounding tokens). Automated labeling does not guarantee behavioral alignment.
- Core assumption: Safety-critical applications require features that behave consistently across variations; current SAE features do not meet this bar.
- Evidence anchors: Context-sensitive features (e.g., activates only after “cup of”); identical descriptions across layers showing different behavior; steering a “tennis” feature with coefficient 1 outputting “soccer.”
- Break condition: Any safety-critical use fails when activation or steering is context-dependent, not distinguishable from similar features, or produces unintended outputs.

### Mechanism 3
- Claim: Automated interpretation pipelines (LLM labeling from activation samples) create a gap between a feature’s described concept and its actual computational role.
- Mechanism: An LLM summarizes top-activating text snippets, but the feature may actually be sensitive to specific syntactic patterns, tokens, or contexts not captured in the summary. Steering tests reveal the true influence.
- Core assumption: A human-interpretable label from sampling is sufficient to understand a feature’s causal role.
- Evidence anchors: A “pigeons and airborne topics” feature steering toward unrelated birds; a “Morocco” feature responding to the “mor” token; “exposure” feature activating on photography context not in description.
- Break condition: The label is misleading if activation is sparse/contextual or steering contradicts the label’s semantic scope.

## Foundational Learning
- Concept: Sparse Autoencoders (SAEs)
  - Why needed here: SAEs are the core tool for extracting features. Understanding their training (high-dimensional bottleneck, L1 penalty), output (feature activations, decoder directions), and limitations (dead/hyperactive features) is essential to evaluate claims.
  - Quick check question: If an SAE feature has a decoder vector, what does its latent activation value represent in the original model’s activation space?
- Concept: Mechanistic Interpretability (MI) Goals
  - Why needed here: The paper evaluates whether MI’s promise—human-understandable, controllable features—is achieved. Knowing the goal (causal understanding for safety) frames the stress-test.
  - Quick check question: How does “feature steering” differ from standard prompt engineering in terms of intended mechanism?
- Concept: Feature Steerability as Validation
  - Why needed here: Steering is presented as both a tool for safety and a verification of feature correctness. This dual role is central to the critique.
  - Quick check question: Why might a feature activate as expected but still steer the model in unexpected ways?

## Architecture Onboarding
- Component map:
  1. Base LLM (Llama 3.1 8B) -> 2. SAE per layer (Neuronpedia) -> 3. Steering intervention (modify latent) -> 4. Decode to residual stream -> 5. Continue forward pass through subsequent layers -> 6. Generate output tokens
- Critical path: Activation extraction → SAE latent computation → intervention on target feature latent → decode to residual → continue forward pass → output tokens.
- Design tradeoffs:
  - Reproducibility vs. scalability: Using fixed open-source SAEs/LLMs ensures reproducibility but limits analysis to 32k features/layer vs. Anthropic’s larger SAEs.
  - Automated interpretation vs. manual verification: Using an LLM to label features scales but introduces label noise and misalignment risks.
  - Steering coefficient selection: No principled method; sensitivity requires manual tuning per feature/layer.
- Failure signatures:
  - Hyperactive features activating on >90% of tokens.
  - Features with disproportionate activation on special tokens (e.g., <|begin_of_text|>).
  - Identical feature descriptions across layers showing different activation/steering behavior.
  - Steering coefficients producing non-conceptual or syntactic degradation (gibberish, off-topic).
  - Context-dependent features failing to activate on isolated trigger words.
- First 3 experiments:
  1. Replicate basic feature: Find a coffee-related feature in middle layer; show activation on coffee text; demonstrate steering coefficient +2 changes “margarita” output to coffee-related content.
  2. Test context sensitivity: Compare activation of a feature on isolated “coffee” vs. “cup of coffee” vs. unrelated contexts. Quantify mismatch.
  3. Compare similar features: In one layer, select 3–5 features with overlapping descriptions (e.g., all “coffee” related). Test activation on a fixed set of coffee terms and steering on same prompt. Show lack of clear distinction or consistent behavior.

## Open Questions the Paper Calls Out
- **Question 1:** Do thematically similar features (e.g., multiple “coffee” features) exhibit coherent and differentiated activation patterns or steering behaviors across different layers of the network?
- **Question 2:** What is the root cause of the interpretation–behavior gap, where automatically generated feature descriptions do not align with observed activation patterns or steering effects?
- **Question 3:** How precisely can steering coefficients be calibrated to produce reliable, on-concept output changes without side effects, and how do layer depth and feature type influence the “sweet spot”?
- **Question 4:** Why do some features exhibit spurious behavior, such as hyperactivation (density >90%) or disproportionate activation on the `<|begin_of_text|>` token, and do these represent meaningful model primitives or training artifacts?

## Limitations
- Implementation ambiguity: The exact steering intervention procedure (e.g., where/how the modified SAE latent is spliced back) is insufficiently specified, blocking exact code replication.
- Selection bias: The paper’s examples are cherry‑picked from 32k features per layer without a defined sampling strategy; it is unknown whether reported fragility is representative.
- Open‑source vs. proprietary gap: The study uses open‑source SAEs (8× expansion) while Anthropic’s key results often use larger SAEs; differences may explain performance gaps.

## Confidence
- High Confidence: Feature steering exhibits substantial sensitivity to coefficient, layer, and context.
- High Confidence: Automated LLM‑based interpretations frequently misalign with activation patterns and steering effects.
- Medium Confidence: SAE features within a layer often lack clear monosemantic distinctions.
- Low Confidence: The conclusion that MI must shift from representation interpretability to output prediction/control is a normative recommendation beyond the empirical scope.

## Next Checks
1. **Activation vs. Steering Discrepancy Audit**: For a stratified sample of features (high/medium/low specificity), quantitatively compare their top‑activating text samples with their steering outputs on a fixed prompt set. Compute semantic similarity (e.g., embedding‑based) between activation context and steered output context to quantify misalignment rate.
2. **Layer‑Wise Steering Consistency Probe**: For thematically similar features (e.g., “coffee”, “tennis”, “Morocco”) selected across all 32 layers, apply identical steering coefficients and prompts. Measure variance in output topic relevance (via classifier or LLM judge) and coherence (perplexity) across layers to validate that middle layers are more stable.
3. **Context‑Exclusion Stress Test**: For features reported as context‑sensitive, construct prompts that isolate the hypothesised trigger token (e.g., “coffee”) from its typical context (e.g., remove “cup of”). Measure activation drop relative to full context; define failure as >50% drop for features supposedly representing the core concept.
