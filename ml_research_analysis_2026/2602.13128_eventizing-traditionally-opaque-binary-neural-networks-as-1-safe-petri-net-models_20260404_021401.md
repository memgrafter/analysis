# Eventizing Traditionally Opaque Binary Neural Networks as 1-safe Petri net Models

## Quick Facts
- **arXiv ID:** 2602.13128
- **Source URL:** https://arxiv.org/abs/2602.13128
- **Reference count:** 40
- **Primary result:** Binary Neural Networks are modeled as 1-safe Petri nets to enable formal verification and causal explainability, passing all structural and behavioral checks on a minimal network but facing combinatorial scalability challenges.

## Executive Summary
This paper introduces a framework for representing the inference and training of Binary Neural Networks (BNNs) as modular Petri net (PN) models. By "eventizing" each discrete operation—such as binary multiplication, activation, and weight updates—the approach transforms opaque computations into an explicit, token-driven graph of causal dependencies. This representation allows for formal verification of critical properties (e.g., deadlock-freedom, 1-safeness) at multiple hierarchical levels using tools like Workcraft. Applied to a simple XOR BNN, the PN model passes all verification checks and its training loss trajectory initially aligns with a reference implementation before achieving a ~10% lower loss after 100 epochs. However, the model size grows combinatorially with network scale, highlighting a fundamental trade-off between transparency and practicality for real-world datasets.

## Method Summary
The authors decompose BNN operations into reusable, modular PN segments. Each segment corresponds to a specific computational step (e.g., pre-activation, gradient calculation, floating-point subtraction) with places representing data/state and transitions representing events. These segments are composed hierarchically—from individual operations to neurons, then to the full network—using proxy places for clean interfaces. The complete PN model is verified for structural properties (1-safeness, boundedness) and behavioral properties (deadlock-freedom, causal sequencing) using Workcraft's Mpsat backend. Validation involves simulating the PN and comparing its loss trajectory and intermediate metrics against a reference BNN implementation. The methodology explicitly exposes the fine-grained dataflow and ordering constraints that are hidden in conventional black-box BNN code.

## Key Results
- Formal verification (structural and behavioral) passed at all hierarchical levels for the constructed PN model.
- The PN model’s training loss trajectory initially matched a reference BNN but diverged after epoch 3, ultimately achieving ~10% lower loss after 100 epochs.
- The full PN for a minimal 2-2-1 BNN contained 92,211 elements (places+transitions+arcs), and scalability analysis indicated a combinatorial explosion for datasets like MNIST.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Eventizing BNN operations as Petri net transitions exposes fine-grained causal dependencies and ordering constraints hidden in black-box implementations.
- **Mechanism:** Each discrete BNN operation (e.g., binary multiplication, Sign function, weight update) is mapped to a PN segment where preplaces/postplaces represent data/state dependencies and transitions represent computational events. Token flow enforces happens-before relationships.
- **Evidence anchors:** The abstract states the approach captures internal operations as event-driven processes to expose causal relationships. Section III provides detailed PN segments (e.g., Figs. 5, 11, 14) showing explicit arcs linking operations. The corpus focuses on BNN hardware acceleration, so this mechanism is primarily a contribution of the paper itself.

### Mechanism 2
- **Claim:** Modular PN segment composition enables hierarchical verification of BNN components and the whole system, ensuring correctness by construction.
- **Mechanism:** Low-level operations are encapsulated into reusable PN blueprints (e.g., Sign function, Straight-Through Estimator, floating-point subtraction). These are composed into neuron-level and network-level PNs. Verification (safety, deadlock-freedom) is performed at each composition level.
- **Evidence anchors:** Section III describes constructing modular blueprints and composing them. Section IV reports verification outcomes at three hierarchical levels, preserving safety, boundedness, and deadlock-freedom. The corpus does not directly address PN modularity for BNN verification.

### Mechanism 3
- **Claim:** Formal verification of the PN model provides guarantees about the BNN's operational integrity (e.g., no deadlocks, correct sequencing) that are infeasible for standard BNN code.
- **Mechanism:** Using Workcraft's Mpsat backend, the PN is checked for 1-safeness (no place exceeds one token), deadlock-freedom, and correct causal ordering (e.g., weight binarization before STE). These properties bound state explosion and ensure deterministic event sequencing.
- **Evidence anchors:** The abstract and Section IV explicitly state the model passes all verification checks (1-safeness, deadlock-freeness, mutual exclusion, causal sequencing). The corpus shows alternative verification methods (SMT, BDD) for BNNs but not PN-based property checking.

## Architecture Onboarding
- **Component map:** Data Loading -> Weight Initialization/Binarization -> Pre-activation -> Activation -> Neuron Output -> Output Sum/Prediction -> Hinge Loss -> STE -> Gradients -> Learning Rate -> LR×Gradient -> Floating-point Weight Update -> Next Vector -> Epoch Counter (with synchronization points). Individual segments correspond to Figures 3 through 17.
- **Critical path:** Token flow begins at data-point transitions, propagates through weighted sums and activations to generate predictions, flows through loss and gradient computation, triggers weight updates (including floating-point arithmetic), synchronizes via Next Vector, and increments the epoch counter after all data points are processed.
- **Design tradeoffs:** 
  - Explainability vs. Scalability: Full PN instantiation reveals causality but causes combinatorial explosion; parameter sharing/templating is needed but not automated.
  - Floating-point fidelity vs. Complexity: Detailed IEEE-754 subtraction ensures numerical correctness but dominates model size (~13k elements for weight update segment).
  - 1-safeness vs. Progress: Epoch counter is intentionally unsafe (holds >1 token) to limit simulation; all other places are 1-safe.
- **Failure signatures:** 
  - Deadlock: No enabled transitions—indicates missing token flow (e.g., weight update not completing).
  - Unsafe place: Place holds >1 token—indicates concurrent writes to same state (e.g., binarization arbitration failure).
  - Token loss/misrouting: Incorrect arc connections causing missing values in gradient or weight update.
- **First 3 experiments:**
  1. Build and verify the Sign function segment (Fig. 6b) for 1-safeness and correct input-output mapping using Mpsat.
  2. Compose a single hidden neuron's PN (inference only) and validate its output against a reference BNN for all input patterns (XOR).
  3. Assemble full BNN PN, run 1 epoch simulation with metric instrument (Fig. 18), and compare loss/gradient values to reference implementation; then run 100 epochs and compare loss trajectory.

## Open Questions the Paper Calls Out
- **What is the root cause of the divergence in loss trajectories between the PN model and the reference BNN after epoch 3, and why does the PN model eventually achieve a ~10% lower loss?** The paper reports initial matching then gradual divergence without explaining the source of the discrepancy in training dynamics.
- **How can the combinatorial explosion in PN model size for realistic datasets (e.g., MNIST, CIFAR2) be mitigated to maintain causal transparency while scaling to practical BNN architectures?** The paper identifies this as an obvious trade-off and suggests parameter sharing and templating but provides no concrete automated methodology.
- **Can the event-driven PN representation be fully automated via a Workcraft plugin that accepts arbitrary BNN specifications (architecture, loss, optimizer) and produces a formally verified PN model?** Current construction is manual; automation would require handling diverse architectures and ensuring compositional verification.

## Limitations
- Scalability is prohibitive: the PN for a minimal BNN already has ~92k elements; manual construction won’t scale to MNIST-size networks.
- Floating-point weight update details are ambiguous in the paper, risking divergence from reference arithmetic.
- No reference BNN code or random seed is provided, making exact loss trajectory replication difficult.
- Modular composition assumptions (e.g., interface preservation) are untested at scale; no formal proof of compositionality.

## Confidence
- **M1 (causal exposure)**: Medium – Diagrams suggest dependencies, but no equivalence proof between PN and BNN semantics is given.
- **M2 (modular verification)**: Medium – Works for the small XOR example; scaling and interface preservation remain unproven.
- **M3 (PN guarantees)**: Medium – Structural checks (1-safeness, deadlock-freedom) are necessary but not sufficient for numerical correctness of the BNN training dynamics.
