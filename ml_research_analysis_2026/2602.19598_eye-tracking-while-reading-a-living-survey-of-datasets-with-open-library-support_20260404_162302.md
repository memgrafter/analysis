# Eye-Tracking-while-Reading: A Living Survey of Datasets with Open Library Support

## Quick Facts
*   **arXiv ID:** 2602.19598
*   **Source URL:** https://arxiv.org/abs/2602.19598
*   **Reference Count:** 40
*   **Primary Result:** A living, filterable online catalog of eye-tracking-while-reading datasets and their integration into the `pymovements` library, providing a standardized pathway to improve dataset FAIRness and reproducibility.

## Executive Summary
Eye-tracking-while-reading research suffers from fragmented, non-interoperable datasets that hinder reuse and reproducibility. This paper addresses the problem with a three-part intervention: (1) creating a comprehensive, searchable online table cataloging over 45 standardized metadata features for existing datasets; (2) integrating all publicly available datasets into the open-source Python library `pymovements`, which enforces a consistent internal data format and preprocessing pipeline; and (3) actively promoting FAIR data principles. The core outcome is a sustainable, community-editable resource that lowers the barrier to discovering, accessing, and re-processing eye-tracking data in a transparent, standardized manner.

## Method Summary
The method is an engineering and curation effort rather than a traditional empirical study. The authors manually identified and standardized metadata from existing (semi-)naturalistic eye-tracking-while-reading datasets. They then implemented a software integration layer within the `pymovements` library, writing dataset-specific parsers and configs to download raw data from original sources and process it through a unified API with consistent implementations of algorithms like I-DT and I-VT. The online table is published as a living resource, with a community contribution workflow to update entries and add new datasets.

## Key Results
*   Publication of a living, filterable online overview (https://dili-lab.github.io/datasets.html) cataloging numerous datasets with 45+ standardized features.
*   Technical integration of all publicly available datasets into the `pymovements` Python library, enabling standardized, reproducible access and preprocessing.
*   A concrete instantiation of FAIR principles for the field, providing a template for metadata completeness and pipeline transparency.

## Why This Works (Mechanism)

### Mechanism 1: Standardized Interoperability via `pymovements`
*   **Claim:** Integrating diverse eye-tracking datasets into `pymovements` increases interoperability by providing a standardized preprocessing pipeline.
*   **Mechanism:** The library parses raw data from various manufacturers into a consistent internal format and applies the same implementation of gaze event detection algorithms (e.g., I-DT, I-VT) to all datasets. This ensures that, regardless of the original format or preprocessing choices, users can re-process any integrated dataset identically.
*   **Core Assumption:** Consistent algorithmic implementation and transparency about parameters reduce methodological discrepancies that previously hindered cross-dataset comparisons.
*   **Evidence Anchors:**
    *   [abstract] "integrating all publicly available datasets into the Python package `pymovements`... allows the re-user... to perform their own preprocessing using a wide range of preprocessing functionalities... leads to more standardized, transparent, and, most importantly, reproducible pre-processing pipelines."
    *   [section 6] "The package includes an interface for downloading and processing publicly available datasets... The underlying data will not be changed as the standardization refers only to the data formats, and the implementation of the algorithms."
*   **Break Condition:** If the `pymovements` implementation of a core algorithm (e.g., velocity threshold for saccade detection) differs significantly from a widely-used alternative in a way that systematically changes outputs, the claimed standardization benefit is compromised for analyses reliant on that algorithm.

### Mechanism 2: Enhanced Findability via Living Survey
*   **Claim:** The living, filterable online table significantly improves the findability of eye-tracking-while-reading datasets.
*   **Mechanism:** By cataloging over 45 standardized features (e.g., participant demographics, stimulus naturalness, available data formats, licensing) in a centralized, searchable web interface, researchers can efficiently filter and identify datasets matching their specific methodological or theoretical needs.
*   **Core Assumption:** Comprehensive, structured metadata presentation lowers the search cost and technical barrier to discovering suitable existing corpora, moving beyond ad-hoc, discipline-specific knowledge.
*   **Evidence Anchors:**
    *   [abstract] "publishing a living overview online... presenting over 45 features for each dataset... aiming to strengthen the FAIR principles... make the overview easier to use and, most importantly, editable."
    *   [section 5] "The online table is curated by the authors... dataset authors can... request changes and add new datasets through our website... More than 45 features are reported overall."
*   **Break Condition:** If the rate of new dataset submissions or updates plateaus at a very low level (e.g., <1 new dataset per year), the resource ceases to be a "living" survey and its findability value diminishes as new corpora remain uncataloged.

### Mechanism 3: Promoting FAIR Compliance via Community Standard
*   **Claim:** Promoting FAIR principles via this survey and `pymovements` integration incentivizes future dataset creators to share more complete and reusable data.
*   **Mechanism:** The work establishes a visible community standard by articulating and demonstrating the benefits of sharing data in all stages (raw, events, measures) with detailed metadata. The living table and easy integration act as adoption catalysts, creating normative pressure and a practical pathway for compliance.
*   **Core Assumption:** Researchers are more likely to invest in thorough data sharing if they see a clear, low-friction mechanism for others to reuse their work and if community recognition is tied to FAIR compliance.
*   **Evidence Anchors:**
    *   [abstract] "aim to strengthen the FAIR principles in eye-tracking-while-reading research and promote good scientific practices, such as reproducing and replicating studies."
    *   [section 8] "Our goal... is to explicitly strengthen such existing endeavors [like MECO, MultiplEYE] and promote the FAIR principles... By presenting our overview... we intend to make the data more findable... interoperable... easier to reuse."
*   **Break Condition:** If a longitudinal analysis (e.g., in 5 years) shows no statistically significant increase in the proportion of newly published eye-tracking-while-reading datasets that include raw data, full preprocessing metadata, and standardized licensing compared to the pre-paper baseline, the claimed incentive effect is weak or absent.

    *   **Why Needed:** The entire paper is framed as an intervention to improve FAIR compliance in a fragmented field. Understanding each principle is crucial to grasp the specific problems being solved (e.g., "Interoperable" addresses format incompatibility; "Reusable" requires rich metadata).

    *   **Why Needed:** The paper's core argument hinges on the fact that datasets exist at different stages of processing, and reuse is hindered when only a single, aggregated stage is shared. `pymovements`'s value is enabling standardization *across* these stages.
    *   **Quick Check:** What key information (metadata) is required at the "Gaze Events" stage that is not needed for "Raw" data?
*   **Concept: Dataset Curation & Metadata Standardization**

## Architecture Onboarding
**Component Map:**
Living Survey (Web Table) -> `pymovements` Dataset Library -> `pymovements` Core Preprocessing -> Integration Scripts/Configs
Community Contribution Workflow feeds into all components.

**Critical Path:**
1.  Identify a new publicly available eye-tracking-while-reading dataset.
2.  Add its metadata to the online table (via form/PR).
3.  Create a dataset definition class in `pymovements` (specifying download URLs and parsing logic).
4.  Write tests to verify that `dataset.download()` and `preprocess()` run without errors and produce expected output schemas.
5.  Update documentation (lists of integrated datasets).

**Design Tradeoffs:**
*   **Living Table vs. Static Review:** A living table requires ongoing maintenance but maximizes relevance. A static review is citable and stable but becomes outdated. The paper chooses a hybrid: a citable paper *describing* a living resource.
*   **Standardization vs. Flexibility:** `pymovements` enforces a standard internal data model but allows users to choose algorithms and parameters. This favors reproducibility *within* a user's pipeline over enforcing a single "gold standard" preprocessing.
*   **Integration Effort vs. Coverage:** Integrating a dataset requires manual work to write parsers and configs. This limits short-term coverage but ensures higher quality integration for included datasets.

**Failure Signatures:**
*   **Metadata Inconsistency:** Two datasets claim to use the same "I-DT" algorithm but with different dispersion thresholds, and this is not captured in the table's feature set.
*   **Link Rot:** The online table lists a dataset's URL, but the original source removes the data, causing `pymovements` download failures.
*   **Parser Breakage:** A dataset updates its raw data file format (e.g., new column order). The existing `pymovements` parser crashes or misinterprets data without a clear error.
*   **Stagnant Table:** The "Last Updated" timestamp shows no changes for over a year, and community-submitted issues for new datasets are ignored.

**First 3 Experiments:**
1.  **Download & Replicate:** Use `pymovements` to download the Provo Corpus, apply default preprocessing, and try to reproduce a published result (e.g., mean first fixation duration). Compare against the originally provided fixation file and document discrepancies.
2.  **Add a Mock Dataset:** Create a minimal fake eye-tracking dataset. Follow the `pymovements` contributor guide to write the integration class and config. Submit a test PR to validate understanding of the integration process.
3.  **Feature Completeness Audit:** For 5 datasets from the online table, systematically check if all 45+ features are populated. Note which features are most frequently missing (e.g., "data license", "exclusion criteria") and propose reasons.

## Open Questions the Paper Calls Out
*   **Open Question 1:** What set of metadata fields is minimally necessary and sufficient to achieve interoperability across heterogeneous eye-tracking-while-reading datasets?
*   **Open Question 2:** Does integration of datasets into a unified library like `pymovements` actually increase their accessibility, interoperability, and reuse compared to traditional repository-based sharing?
*   **Open Question 3:** How can the field systematically address missing or incomplete metadata, especially for legacy datasets where original researchers are unavailable?
*   **Open Question 4:** To what extent do methodological choices in preprocessing (e.g., fixation detection algorithm, parameter settings) alter the outcomes of psycholinguistic analyses, and can a standardized pipeline like `pymovements` reduce this variability?

## Limitations
*   The exact thresholds for a dataset to be listed as "publicly available" and integrated into `pymovements` are not formally specified, creating ambiguity about coverage.
*   The default preprocessing parameters (e.g., velocity thresholds for I-VT) and their justification for cross-dataset consistency are not enumerated in the paper.
*   The "living" nature of the survey depends on sustained curation effort, and the claimed incentive effect on future dataset sharing behavior remains correlational and unproven over time.
