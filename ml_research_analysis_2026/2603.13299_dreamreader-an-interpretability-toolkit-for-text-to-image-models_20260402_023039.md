# DreamReader: An Interpretability Toolkit for Text-to-Image Models

## Quick Facts
- **arXiv ID:** 2603.13299  
- **Source URL:** https://arxiv.org/abs/2603.13299  
- **Reference count:** 14  
- **Primary result:** Provides a unified, model-agnostic toolkit for interpretability and intervention in text-to-image diffusion models, enabling reproducible steering, stitching, and analysis.

## Executive Summary
The paper introduces **DreamReader**, a toolkit designed to address the fragmentation of interpretability tools for diffusion-based text-to-image models. By formalizing interpretability as a set of composable operators—localization, steering, stitching, and sparse autoencoders (SAEs)—the framework integrates existing techniques and adds novel primitives such as LoReFT subspace-constrained fine-tuning and classifier-guided gradient steering via MLP probes. Experiments are defined declaratively in YAML and executed in batched pipelines, promoting reproducibility.

DreamReader demonstrates **activation stitching** between a LoRA-fine-tuned Stable Diffusion 1.5 and its base version, as well as **LoReFT steering** on SDXL-Turbo to inject features like “spectacles” reliably across prompts. Quantitative metrics (CLIP score, LPIPS, FID) are logged to evaluate interventions. The open-source release aims to standardize causal analysis and intervention across the diffusion stack.

## Method Summary
DreamReader is a model‑agnostic interpretability toolkit that defines four core workflows:  
- **Localization** identifies influential layers, neurons, or timesteps for a given concept.  
- **Steering** modifies model behavior using interventions such as LoReFT (subspace-constrained fine‑tuning), MLP probes for gradient‑based steering, or precomputed steering vectors.  
- **Stitching** transfers activations or parameters between models via learned component‑level mappers (e.g., affine or MLP).  
- **Sparse Autoencoders (SAEs)** are trained to interpret activation patterns with sparse features.  

Experiments are specified declaratively via Hydra/YAML configuration files, which include the target model, dataset or prompts, hook sites (layer/block/timestep), intervention type and parameters, and evaluation metrics. The toolkit supports both training workflows (e.g., learning an MLP mapper, training a LoReFT vector) and inference workflows (e.g., applying a steering vector, batched generation). It integrates with HuggingFace `diffusers` and is extensible to other diffusion architectures.

## Key Results
- **Activation stitching:** An MLP mapper learned between a LoRA‑fine‑tuned SD 1.5 and base SD 1.5 successfully transfers steering directions while preserving semantic edits.  
- **LoReFT steering:** Applied to SDXL‑Turbo cross‑attention blocks, LoReFT reliably injected features like “spectacles” across prompts; effectiveness varied by layer and prompt and was quantified via CLIP score, LPIPS, and FID.  
- **Open‑source release:** DreamReader is publicly available, enabling reproducible, composable interpretability pipelines.

## Why This Works (Mechanism)
DreamReader works by formalizing interpretability as composable operators, allowing interventions to be applied systematically across different diffusion model architectures. The integration of existing techniques (e.g., SAEs, activation stitching) with novel primitives like LoReFT and MLP‑guided steering addresses limitations of prior fragmented tools. Declarative YAML configuration ensures reproducibility and batch execution, while the model‑agnostic design enables the same interface to be used with various backends. By enabling precise localization, steering, and stitching, the toolkit facilitates causal analysis and controllable generation.

## Architecture Onboarding
**Component map:**  
User Configuration (YAML) → Hydra Config Resolver → Experiment Orchestrator → Hook Registry → Intervention Applier → Diffusion Model (UNet, Text Encoder, VAE) → Image Generation → Metric Logger → Output Artifacts  

**Critical path:**  
Parse config → Initialize model → Register hooks → Apply intervention (if any) → Run inference on prompts → Compute metrics → Save outputs and logs.  

**Design tradeoffs:**  
- *Model‑agnosticism vs. performance:* Abstracting hook sites simplifies portability but may incur overhead and requires users to understand model internals to specify correct layers.  
- *Declarative YAML vs. programmatic flexibility:* YAML simplifies batching and reproducibility but can limit dynamic or conditional intervention logic.  
- *Composable operators:* Allows mixing interventions but may lead to unpredictable interactions between multiple applied operators.  

**Failure signatures:**  
- Hydra config validation errors (unknown layer names) indicate mismatched hook sites.  
- CUDA out‑of‑memory suggests batch size or resolution too high for the chosen model.  
- No change in generated images after steering may indicate ineffective intervention parameters or mis‑application.  
- Missing metric files or empty artifact directories suggest logging misconfiguration.  

**First experiments:**  
1. Run a **localization** experiment to identify which cross‑attention layers most influence a specific concept (e.g., “glasses”) using activation statistics.  
2. Apply a precomputed steering vector via **LoReFT** to a model and verify semantic change across a few prompts.  
3. Train an **MLP mapper** for activation stitching between a base model and a LoRA‑fine‑tuned model, then test cross‑model transfer on a small prompt set.

## Limitations
- No publicly available benchmark prompt datasets (e.g., `spectacles-bias-prompts`) require custom substitutes.  
- Hyperparameters for LoReFT and MLP mappers are not fully detailed, limiting exact replication.  
- Model‑agnostic claims only validated on Stable Diffusion 1.5 and SDXL‑Turbo; generalizability to other architectures is untested.

## Confidence
- Unified framework: **High**  
- Novel primitives effective: **Medium**  
- Reproducible interventions: **High**  
- Controllable generation via metrics: **Medium**
