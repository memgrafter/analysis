# DMCD: Semantic-Statistical Framework for Causal Discovery

## Quick Facts
*   **arXiv ID:** 2602.20333
*   **Source URL:** https://arxiv.org/abs/2602.20333
*   **Reference Count:** 38
*   **Primary Result:** Integrates LLM-generated semantic priors with conditional independence testing, achieving up to 50% higher F1 score than baselines on real-world benchmarks (e.g., 0.751±0.02 on Fluxnet2015, 0.82±0.09 on Antivirus).

## Executive Summary
DMCD is a hybrid causal discovery framework that combines the semantic reasoning of large language models (LLMs) with the empirical rigor of statistical conditional independence testing. It operates in two phases: first, an LLM generates a sparse, semantically plausible draft directed acyclic graph (DAG) from variable metadata like names and descriptions; second, this draft is systematically validated and refined by comparing its implied conditional independence relations with those estimated from observational data. Evaluated on industrial, environmental, and IT monitoring benchmarks, DMCD demonstrates substantial gains in recall and F1 score over existing methods, with ablations confirming that improvements stem from the semantic prior rather than memorization.

## Method Summary
DMCD processes a dataset with associated variable metadata (names, descriptions, units). **Phase I** serializes the metadata into a prompt that instructs an LLM (e.g., GPT-5.2, temperature 0.0) to output a valid, sparse DAG representing plausible causal relationships. **Phase II** takes this draft DAG and observational data. For each variable pair, it computes the d-separation status in the draft, performs an appropriate conditional independence (CI) test (e.g., partial correlation, Chi-squared, or XGBoost-based for mixed data) on the data, and flags discrepancies—edges that should be present but are absent (missing) or present but unsupported (spurious). These flagged pairs are presented to the LLM in a revision prompt with consistency guidelines to produce a final, data-validated DAG. Performance is evaluated using structural metrics (F1, SHD, TPR, FDR) against ground truth graphs from three domains.

## Key Results
*   Achieves state-of-the-art or competitive F1 scores on all three benchmark suites, with a 50% improvement on Fluxnet2015 (F1 0.751±0.02 vs. best baseline ~0.50).
*   Shows large recall gains (up to 0.92±0.07 on Antivirus), indicating the semantic prior effectively identifies many true edges.
*   Ablation experiments reveal that removing variable descriptions causes a severe performance drop, confirming the method's reliance on semantic metadata rather than data memorization.

## Why This Works (Mechanism)
### Mechanism 1
*   **Claim:** The LLM can generate a sparse, semantically plausible draft DAG from variable metadata.
*   **Mechanism:** Phase I constructs a prompt with variable names, descriptions, and units, instructing the LLM to output a DAG. The LLM uses background knowledge to infer causal directions from semantic cues (e.g., "Reactor Temperature" likely precedes "Reactor Pressure").
*   **Core assumption:** Variable metadata is causally informative, and the LLM possesses relevant domain knowledge to interpret it correctly.
*   **Evidence anchors:** [abstract] "LLM-generated semantic priors"; [section] 3.1 details prompt structure; [corpus] neighboring LLM-causal papers omit statistical validation, highlighting hybrid novelty.
*   **Break condition:** Uninformative metadata (cryptic IDs) or domain-misaligned LLMs yield random/biased drafts, degrading performance (shown in ablations).

### Mechanism 2
*   **Claim:** Conditional independence testing can systematically identify edges in the draft that conflict with observational data.
*   **Mechanism:** Phase II enumerates all unordered pairs in the draft. For each pair, it compares the d-separation status in the draft with a statistical CI test. Discrepancies are flagged as potential missing edges (d-separated but dependent) or spurious edges (connected but independent). Q-value adjustment controls false discoveries.
*   **Core assumption:** The true graph satisfies the causal Markov condition and faithfulness; CI tests are valid under their assumptions (e.g., linearity for partial correlation).
*   **Evidence anchors:** [abstract] "statistical validation via conditional independence testing"; [section] 3.2 describes discrepancy detection and q-value adjustment; [corpus] CI testing is core to constraint-based methods (e.g., PC), but DMCD applies it selectively to a prior draft.
*   **Break condition:** Small samples, heavy noise, latent confounders, or violated test assumptions (e.g., nonlinearity) make CI tests unreliable, causing incorrect edge edits.

### Mechanism 3
*   **Claim:** The two-phase pipeline yields a DAG that combines semantic plausibility with empirical support, improving recall and F1.
*   **Mechanism:** The LLM draft is a sparse prior with high TPR but some false edges. CI testing prunes edges inconsistent with data, controlling FPs while preserving TPs. A revision step lets semantic reasoning override borderline statistical signals.
*   **Core assumption:** The draft covers a substantial fraction of true edges (high recall) and most CI-flagged discrepancies are correctable errors.
*   **Evidence anchors:** [abstract] "combining semantic priors with principled statistical verification"; [section] Results (Tables 2,3) show F1 gains; ablation (6.4) shows performance drops without descriptions; [corpus] LLM-only methods have lower F1.
*   **Break condition:** Draft misses too many true edges (low coverage) or is too dense, causing CI to remove true edges due to confounding/low power, reducing precision.

## Foundational Learning
*   **Concept: Conditional Independence Testing**
    *   **Why needed:** Phase II evaluates the draft by testing whether variables are conditionally independent given others, as implied by the graph.
    *   **Quick check:** For continuous variables, how would you test X ⊥⊥ Y | Z using linear regression? What null hypothesis does the test assess?
*   **Concept: Directed Acyclic Graphs (DAGs) and d-separation**
    *   **Why needed:** The draft and final outputs are DAGs; discrepancies are defined via d-separation.
    *   **Quick check:** In a DAG with nodes A → B ← C, are A and C d-separated given B? Without conditioning?
*   **Concept: Large Language Models for Structured Generation**
    *   **Why needed:** Phase I uses an LLM to produce a DAG from textual metadata; understanding prompt engineering and output parsing is essential.
    *   **Quick check:** When prompting an LLM to output a causal graph, what constraints should you include in the instructions to ensure a valid DAG?

## Architecture Onboarding
*   **Component map:** Metadata serializer -> LLM drafter -> DAG validator -> CI testing engine -> Discrepancy detector -> Revision module -> Output formatter
*   **Critical path:**
    1. Load dataset (observational data) and metadata.
    2. Serialize metadata → prompt → LLM drafter → parse draft DAG G_draft.
    3. Validate G_draft (if invalid, retry/abort).
    4. For each unordered pair (X,Y) in V_draft: determine d-separation in G_draft; select and run appropriate CI test on observational data; flag discrepancies (missing/spurious edges).
    5. If discrepancies exist, construct revision prompt with guidelines, call LLM, update DAG.
    6. Return final DAG.
*   **Design tradeoffs:**
    *   LLM choice: More capable models yield better drafts but are costlier and less deterministic. Temperature=0 reduces but doesn't eliminate nondeterminism.
    *   CI test selection: Different tests for continuous/discrete/mixed data; each has assumptions (e.g., linearity) that may be violated.
    *   Draft sparsity: Instructing a sparse graph risks missing true edges; a dense graph increases CI burden and false positives.
    *   Revision strategy: Single revision vs. multiple iterations; more iterations increase cost and risk of drift.
*   **Failure signatures:**
    *   LLM returns invalid format (not a DAG, extra nodes) → DAG validator fails.
    *   CI tests fail to converge or produce NaNs due to insufficient data → should skip or warn.
    *   High variability across runs (large std dev in F1) → indicates ambiguous metadata or unstable LLM outputs.
    *   After revision, graph becomes cyclic or loses too many edges → indicates over-revision; may need to adjust discrepancy thresholds.
*   **First 3 experiments:**
    1.  Unit test: Run DMCD on a tiny synthetic dataset (e.g., 4 variables) with known ground truth to verify end-to-end component functionality.
    2.  Ablation test: Compare performance with and without variable descriptions (neutral names only) on Tennessee Eastman to confirm reliance on semantic metadata (per Section 6.4).
    3.  Scalability test: Measure Phase II runtime as number of draft variables increases; identify point where CI testing becomes prohibitive and consider optimizations (e.g., testing only candidate pairs).

## Open Questions the Paper Calls Out
*   **What mechanisms can mitigate non-determinism in DMCD's LLM drafting phase while maintaining semantic fidelity?** (Section 6.5 suggests future "LLM voting" strategies.)
*   **Can Phase II's conditional independence testing be adaptively prioritized based on uncertainty in the draft graph to improve efficiency?** (Conclusions propose adaptive verification guided by structural uncertainty.)
*   **What alternative statistical validation mechanisms beyond conditional independence testing can effectively refine the draft DAG?** (Conclusions suggest score-based or predictive cross-validation could be incorporated.)
*   **How does the semantic richness, ambiguity, and domain specificity of variable metadata systematically affect DMCD's causal recoverability?** (Conclusions call for systematic characterization of the metadata-quality relationship.)

## Limitations
*   **Prompt/Revision Protocol Opacity:** Exact prompt templates and discrepancy formatting for LLM revision are unspecified, introducing implementation variability.
*   **CI Testing Assumptions:** Performance hinges on causal Markov/fairness and correct test selection (linearity, discrete handling); likely degrades with small samples, latent confounders, or nonlinearities.
*   **Metadata Dependency:** System relies on informative, accurate variable descriptions; performance with cryptic IDs or domain-misaligned LLMs is a key risk.
*   **Scalability:** Phase II CI testing complexity grows with draft node count; efficiency for larger graphs (>50 variables) is untested.

## Confidence
*   **Hybrid Framework Efficacy (High):** Supported by strong benchmark results (F1 gains up to 50%) and ablations confirming semantic prior contribution.
*   **LLM Draft as Sparse Prior (Medium):** Plausible from results and mechanism, but draft quality variance due to LLM nondeterminism and metadata quality is not fully quantified.
*   **Statistical Validation as Pruner (Medium):** Core to the method, but exact discrepancy detection logic and q-value handling details are underspecified, affecting reproducibility.
*   **Generalization Beyond Benchmarks (Low):** Evaluation is limited to three domains; robustness to new domains, data types, or noisy metadata is unknown.

## Next Checks
1.  **Prompt Sensitivity Analysis:** Systematically vary prompt phrasing, instruction specificity, and metadata serialization format. Measure resulting draft graph F1 and sparsity on a held-out benchmark to quantify robustness to prompt engineering.
2.  **Revision Protocol Stress Test:** Execute Phase II with LLM revision disabled (single draft only) versus the described revision. Compare final graph metrics to isolate added value and instability from iterative revision. Also run with higher LLM temperature to assess output variability.
3.  **CI Test Assumption Benchmarking:** On a synthetic benchmark (e.g., Sachs network) with known ground truth, evaluate performance when data is perturbed to violate test assumptions (add nonlinear relationships, discretize continuous variables, reduce sample size). Correlate CI test validity (e.g., type I error on null edges) with final F1 degradation to identify operational breakpoints.
