# Fine-Tuning A Large Language Model for Systematic Review Screening

## Quick Facts
- arXiv ID: 2603.24767
- Source URL: https://arxiv.org/abs/2603.24767
- Reference count: 35
- Primary result: Fine-tuning a 1.2B parameter LLM on 315 human-coded titles/abstracts achieved 86.40% agreement with human screening on 8,277 studies, with 91.18% recall for inclusions and 86.38% true negative rate, and perfect consistency across inference temperatures.

## Executive Summary
This paper demonstrates that full fine-tuning of a small (1.2B) instruction-tuned language model on a modest set of 315 human-labeled study titles and abstracts can achieve high agreement with human systematic review screeners (86.40% on 8,277 studies). The fine-tuned model strongly prioritizes sensitivity (91.18% recall for included studies) at the cost of precision (2.69%), reflecting a design to minimize missed studies. The work establishes that even with limited training data, large language models can be effectively adapted to the critical task of automated screening in systematic reviews.

## Method Summary
The authors used the 1.2B parameter LFM2.5-Instruct model as a base. They prepared a dataset of 8,694 studies with binary inclusion/exclusion labels. A curated subset of 371 samples (315 training, 56 validation) was formatted as instruction-response pairs using the model's chat template, with response-only masking applied during training. Full fine-tuning (all parameters) was performed for 320 steps using Unsloth and TRL's SFTTrainer, with hyperparameters: 8-bit AdamW, learning rate 2e-5, batch size 2 (gradient accumulation 4), BF16. The final checkpoint was evaluated on the full dataset (8,277 studies) using greedy decoding; predictions were parsed for a '0' or '1' token, falling back to class 0 if none found. Metrics included accuracy, balanced accuracy, weighted F1, per-class recall/precision, Cohen's κ, Gwet's AC1, and consistency across temperatures.

## Key Results
- Fine-tuned model agreement with human coders: 86.40% on full dataset (vs. 6.52% for base model).
- Include class recall (sensitivity): 91.18%; exclude class true negative rate: 86.38%.
- Weighted F1 improved by 80.79% relative to base model.
- Model predictions perfectly consistent across inference temperatures (κ = 1.0).
- Precision for include class very low (2.69%), but false negative rate only 8.82%.

## Why This Works (Mechanism)
### Mechanism 1: Fine-tuning adapted the model's internal representations to the specific task
Full parameter fine-tuning on 315 instruction-formatted examples updated all model weights, aligning its latent feature space with the patterns of human screening decisions in this domain. The base model's poor baseline (6.52% agreement) indicated it lacked the task-specific mapping, which was induced via supervised training.

**Evidence**: Abstract claim; Section 3.1 direct comparison; neighboring papers show zero-shot methods underperform.

**Break condition**: Extremely small or label-diverse training data might fail to capture decision boundary.

### Mechanism 2: Enriched inclusion rate in training data mitigated class imbalance
The training set had 38.4% inclusion (vs. typical 1-5%), providing enough positive examples for the model to learn the rare include class, achieving high recall (91.18%). This design prioritized sensitivity at the cost of precision (2.69%).

**Evidence**: Section 2.2.4 on intentional enrichment; Section 3.3 per-class metrics.

**Break condition**: Applying to naturally low inclusion rates (<1%) without recalibration would yield many false positives.

### Mechanism 3: Full fine-tuning eliminated adapter constraints, maximizing adaptation
By updating all 1.2B parameters rather than using PEFT (e.g., LoRA), the model could modify foundational reasoning pathways entirely. The authors argue this is optimal for a single-task, small-model setting with limited training steps.

**Evidence**: Section 2.2.1 rationale; Section 4.2 acknowledges as limitation/future.

**Break condition**: For larger models or more complex tasks, full fine-tuning may be computationally prohibitive or cause catastrophic forgetting; PEFT might preserve base knowledge better.

## Foundational Learning
**Concept: Supervised Fine-Tuning (SFT) with instruction formatting**  
*Why needed*: The method transforms human decisions into an instruction-response format (`<|user|>...<|assistant|>0/1`) so the model learns the mapping during training.  
*Quick check*: What is the functional difference between computing loss only on assistant tokens (response-only masking) versus standard language modeling loss on the whole sequence?

**Concept: Evaluation metrics for extreme class imbalance**  
*Why needed*: The true inclusion rate is ~0.4% (34/8277). Accuracy is misleading; the paper uses balanced accuracy, per-class recall, and Fβ-score (F2) to weight recall higher.  
*Quick check*: Why might Cohen's κ be very low (0.045) even with 86.40% observed agreement and strong Gwet's AC1 (0.843) in this imbalanced setting?

**Concept: The sensitivity-precision trade-off in screening contexts**  
*Why needed*: The model is designed to maximize recall (minimize missed studies) even at the cost of precision, because in screening false negatives are more harmful than false positives.  
*Quick check*: In a two-step screening process (LLM first, human second), why is a high false positive rate more tolerable than a high false negative rate?

## Architecture Onboarding
**Component map**:
Base Model (LiquidAI/LFM2.5-1.2B-Instruct) -> Training Stack (Unsloth + Hugging Face TRL) -> Optimizer (8-bit AdamW) -> Data (371 ChatML-formatted, response-masked samples) -> Inference (Chat template + greedy decoding + parsing) -> Evaluation (Scikit-learn + irr package)

**Critical path**:
1. Prepare dataset: Convert titles/abstracts + labels to instruction-response pairs using LFM2 chat template.
2. Configure full fine-tuning: Unsloth with `full_finetuning=True`, bf16, 8-bit optimizer.
3. Train for 320 steps with effective batch size 8 (batch size 2, gradient accumulation 4).
4. Validate on held-out 56-sample test set.
5. Run inference on full 8,277-study dataset using consistent prompt template, parse first '0' or '1'.
6. Compute metrics (accuracy, balanced accuracy, weighted F1, per-class, κ, AC1) and temperature consistency.

**Design tradeoffs**:
- Full fine-tuning vs. PEFT: Full fine-tuning maximizes performance ceiling but is less memory-efficient and risks overfitting; PEFT would be more accessible but may underfit on a single complex task.
- Training data scarcity vs. domain specificity: Using only 315 enriched samples is fast and cheap but limits generalizability; a larger naturally imbalanced dataset would be more realistic but harder to train.
- Sensitivity focus: Optimizing for recall inherently accepts low precision; this is appropriate for screening but means many false positives must be manually verified later.

**Failure signatures**:
- Model collapses to majority class: Include recall near 0% → check training data balance and formatting.
- Perfect temperature consistency (κ=1.0) with poor metrics → overfitting on small/noisy data.
- Discrepancy between held-out test accuracy (94.64%) and full dataset (86.40%) → distribution shift between curated validation and real corpus.
- Low Gwet's AC1 despite moderate accuracy → agreement driven by dominant class, not minority class nuance.

**First 3 experiments**:
1. Replicate baseline: Run base model (no fine-tuning) on a 50-item subset using exact inference prompt; expect sub-10% agreement and near-0% include recall.
2. Sanity-check fine-tuning: After 50 training steps, evaluate on the 56-sample validation; expect include recall >80%.
3. Distribution probe: Compare inclusion rate of 315 training samples (38.4%) vs. full dataset (~0.4%); quantify shift to predict precision drop.

## Open Questions the Paper Calls Out
1. How does model performance change when trained on datasets with more typical inclusion rates (1–5%) rather than the enriched 37.2% used here?
2. What is the minimum number of included studies needed in the training set to achieve acceptable recall (e.g., >90%) for the include class?
3. Does parameter-efficient fine-tuning (e.g., LoRA) achieve comparable performance to full fine-tuning for this task, given the small dataset size?
4. At what false positive rate does the model's output become counterproductive for human screeners, considering cognitive load and time costs?
5. How well does a model fine-tuned on one systematic review topic generalize to screening titles/abstracts from a different research domain or with different inclusion criteria?

## Limitations
- Exact prompt template and parsing fallback logic are unspecified, risking implementation drift.
- Dataset split discrepancy: 8,694 total minus 371 curated equals 8,323, not the reported 8,277 full evaluation set; derivation of 8,277 is unclear.
- Unclear whether final or best-validation checkpoint was used for full-dataset evaluation.
- Model's low precision (2.69%) may be unsustainable in real-world workflows with very low inclusion rates.
- Performance may be domain-specific; generalization to other fields is untested.
