# Token-Efficient Change Detection in LLM APIs
## Quick Facts
- arXiv ID: 2602.11083
- Source URL: https://arxiv.org/abs/2602.11083
- Reference count: 40
- Primary result: B3IT reduces change detection cost by 30× while matching grey-box accuracy, achieving ROC AUC 0.9 on TinyChange at $2.2/year.

## Executive Summary
The paper addresses black-box LLM API change detection, a costly and challenging problem due to lack of internal model access. It introduces B3IT, a method that exploits "Border Inputs" (prompts that cause multiple tokens to tie for the top prediction at very low temperature). Theoretically, these inputs yield a diverging signal-to-noise ratio as temperature approaches zero, making them highly sensitive to parameter changes. Practically, B3IT discovers such inputs cheaply in most non-reasoning endpoints and monitors them using a simple support-mismatch test. Experiments show B3IT matches grey-box detection accuracy at 30× lower cost and identified real-world changes in commercial services.

## Method Summary
B3IT operates in three phases:
1. **Border Input Discovery**: Generate candidate prompts (e.g., one-token strings). For each, query the API a few times (`m=3`) at temperature `T=0`. If multiple distinct output tokens appear, the prompt is a Border Input (BI). Stop after finding `|B|=5` BIs or exhausting candidates.
2. **Reference Collection**: For each BI, collect `n₁=50` samples at `T≈0` to build an empirical token support `S₁`.
3. **Change Detection**: At monitoring intervals, collect `n₂=3` new samples per BI to form `S₂`. Reject the null hypothesis of no change if any BI's support mismatches (`S₁ ≠ S₂`). Optionally, use total variation distance for threshold tuning.
The method is strictly black-box, uses minimal tokens, and achieves cost-efficiency by focusing on the sensitive low-temperature regime.

## Key Results
- B3IT attains ROC AUC 0.9 on the TinyChange benchmark at an annual cost of $2.2, outperforming the best black-box baseline (AUC 0.61, $67/year).
- In 23 days of live monitoring across 93 commercial endpoints, B3IT flagged persistent changes on 8 services; one change was confirmed by the provider's public changelog.
- Border inputs were easily discovered for 62% of endpoints when operating at temperature zero.
- The approach reduces cost by 30× compared to existing grey-box methods with comparable detection accuracy.

## Why This Works (Mechanism)
### Mechanism 1: Diverging SNR at Low Temperature
- **Claim:** At very low temperature, inputs where two or more tokens tie for the top logit ("Border Inputs") exhibit a diverging signal-to-noise ratio (SNR) for detecting parameter changes.
- **Mechanism:** As temperature τ → 0, the output distribution concentrates uniformly on the set of tokens with maximal logits (support M). The Fisher information matrix scales as 1/τ². For inputs with |M| ≥ 2 (BIs), the SNR² ∝ 1/τ → ∞, so infinitesimal parameter changes can flip the distribution from uniform over multiple tokens to a single token. For single-token outputs (non-BIs), SNR² → 0.
- **Core assumption:** The model's logits are smooth functions of parameters and the perturbation direction satisfies a non-degeneracy condition.
- **Evidence anchors:** Abstract and Section 3.4 (Theorem 3.3) formalize the phase transition; related work discusses black-box APIs but not this specific transition.
- **Break condition:** The BI property is lost if the input's logit maximum becomes unique for all perturbations (probability zero) or if temperature is not sufficiently low.

### Mechanism 2: Efficient Border Input Discovery
- **Claim:** Border Inputs can be discovered efficiently in practice for most non-reasoning LLM endpoints using minimal black-box queries.
- **Mechanism:** By sampling a candidate prompt `m` times (e.g., 3) at `T=0`, observing >1 distinct output token confirms the input lies in the |M|≥2 regime. This works because the τ→0 limit ensures uniformity on the tie set, and empirical ties indicate true BIs. Prevalence is high due to floating-point imprecision and inference non-determinism creating near-ties that resolve to ties at T=0.
- **Core assumption:** The endpoint's T=0 behavior approximates the τ→0 limit; observed multi-token outputs reflect a true BI rather than transient noise.
- **Evidence anchors:** Abstract reports BI discovery ease; Section 5.2 shows 62% success rate across 93 endpoints, with failures mainly due to empty strings or reasoning outputs.
- **Break condition:** Discovery fails for endpoints that always return empty strings, require minimum output length, or are reasoning models where short outputs are disabled.

### Mechanism 3: Support-Mismatch Detection Test
- **Claim:** Monitoring a BI's output distribution under low temperature provides a near-optimal, low-cost change detection test with non-asymptotic guarantees.
- **Mechanism:** Under H₀ (no change), both reference and candidate models produce a uniform distribution over the same support S (size k). Under H₁ (change), the candidate's support may shrink (e.g., from k to 1). The test rejects H₀ if any token appears in one sample set but not the other (empirical support mismatch). This leverages the exact uniformity at T=0, so sampling noise only concerns token appearance.
- **Core assumption:** Changes typically cause a collapse in effective support rather than altering uniform probabilities; reference samples (`n₁`) are sufficient to observe all k tokens.
- **Evidence anchors:** Abstract cites cost reduction; Section 4.2 describes the test; Section 4.3 provides non-asymptotic error bounds and optimality for k=2; Section 5.1 validates against grey-box methods.
- **Break condition:** The test may miss changes that alter probabilities within the same support or involve large k where the conservative test becomes suboptimal.

## Foundational Learning
- **Concept: Local Asymptotic Normality (LAN) & Asymptotic SNR**  
  Why needed: The paper uses LAN to model infinitesimal parameter changes and derive the optimal detection power formula (SNR²(h)). This formalizes why certain inputs are more sensitive.  
  Quick check: Under the LAN regime, what does the asymptotic power of the Neyman-Pearson test depend on, and how does temperature τ scale this quantity?

- **Concept: Fisher Information & Softmax Jacobian**  
  Why needed: SNR²(h) = hᵀ(JᵀΣₘJ)h. The paper simplifies this by analyzing the softmax derivative and covariance, leading to the 1/τ² scaling. Understanding Fisher information as inverse covariance of the score is key.  
  Quick check: How does the Jacobian of the softmax output distribution relate to the covariance matrix Σ(p), and why does this lead to 1/τ² scaling?

- **Concept: Total Variation Distance for Discrete Supports**  
  Why needed: The detection statistic (support mismatch) is linked to TV distance. The paper uses TV for ROC curves, and understanding TV for uniform sets clarifies why a mismatch indicates change.  
  Quick check: If two discrete distributions are uniform on sets S₁ and S₂, what is their TV distance in terms of |S₁ Δ S₂|?

## Architecture Onboarding
### Component map
Input Generator -> BI Discovery -> Reference Sampler -> Detection -> Aggregator

### Critical path
1. Find at least one BI (failure halts system).
2. Collect reference distribution.
3. Periodically resample BIs and run support-mismatch test.

### Design tradeoffs
- **Temperature:** Lower τ increases sensitivity but may reduce BI prevalence.
- **Number of BIs (|B|):** More BIs improve reliability but increase per-detection cost linearly. Paper uses |B|=5.
- **Samples per BI (n₁, n₂):** More samples reduce Type-I/II errors but increase cost. Used n₁=50, n₂=3 in vivo.

### Failure signatures
- **No BIs found:** All outputs identical/empty. Likely cause: model requires longer outputs or T=0 is not truly low-temperature.
- **High false positives:** TV high under H₀. May indicate non-deterministic hardware noise or BI not truly in phase-transition regime.
- **Missed changes:** TV remains low after known change. Could be because change did not collapse support on the specific BIs.
- **Cost blow-up:** Many BIs or large n₁. Mitigate by early stopping after 5 BIs and using cheap single-token prompts.

### First 3 experiments
1. **BI Prevalence Scan:** On a new endpoint, query 1000 minimal-token prompts with m=3 at T=0 and T=1e-4. What fraction yield >1 token? If <10%, try reasoning-specific prompts or higher T.
2. **Detection Accuracy Calibration:** Using a known stable model version, run detection with n₁=50, n₂=3 over 100 trials. Estimate empirical Type-I error. Should be close to 0 (Theoretical bound: k·(1−1/k)ⁿ¹ ≈ 0 for k=2, n₁=50).
3. **Cost-Accuracy Sweep:** Vary n₂ from 1 to 10 while keeping |B|=5 fixed. Plot TV histogram under H₀ and under a simple perturbation (e.g., quantized model). Verify TV separation and that n₂=3 suffices.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can B3IT’s theoretical framework be extended to multi-token outputs to improve sensitivity and cost-efficiency?  
  Basis: Conclusion states future work could extend beyond single-token observations. Unresolved because current analysis restricts to first token for tractability. Evidence needed: asymptotic theory for token sequences and empirical comparison.

- **Open Question 2:** How can B3IT be adapted to monitor endpoints that do not produce border inputs, such as reasoning models or those returning empty strings?  
  Basis: Section 5.2 reports 18/121 endpoints yield no BIs. Unresolved because border inputs are essential for high-sensitivity detection; no fallback provided. Evidence needed: identify characteristics predicting absence and design alternative low-cost detectors.

- **Open Question 3:** Why do many endpoints behave differently at exact temperature T=0 than as T→0, and how should this discrepancy influence B3IT’s practical temperature choice and threshold calibration?  
  Basis: Section 5.2 notes hard-coded patterns at T=0 may distort support structure. Unresolved because this violates the core phase-transition assumption. Evidence needed: systematic study of T=0 behavior and robust tests accommodating quirks.

- **Open Question 4:** Does B3IT fail to detect model changes that preserve the set of top-k tokens but alter their relative probabilities, and if so, can a purely black-box test capture such intra-support shifts without exceeding the cost budget?  
  Basis: B3IT focuses on support mismatches; changes within support may go undetected. Unresolved because real updates may reweight probabilities without collapsing support. Evidence needed: controlled experiments with probability-shift changes and evaluating false negatives.

## Limitations
- **Temperature semantics unknown:** Real API implementations of T=0 may include deterministic tie-breaking or clamping, deviating from the theoretical τ→0 limit, which can degrade sensitivity.
- **Reasoning model coverage gap:** B3IT fails on endpoints that always produce multi-token outputs (e.g., reasoning models) or empty strings; 18 of 121 tested endpoints were unsupported.
- **Non-determinism vulnerability:** Inference-time variation (e.g., GPU nondeterminism) can cause occasional extra tokens at T=0, leading to false positives; the paper lacks empirical quantification or mitigation strategies.

## Confidence
- **Theoretical SNR divergence:** High – rigorous LAN and Fisher information derivation; mathematically sound under smoothness assumptions.
- **Practical BI discovery mechanism:** Medium – empirical success (62% rate) is strong but depends on undefined prevalence of near-ties and exact low-temperature implementation; not guaranteed for all endpoints.
- **Cost-accuracy advantage in live monitoring:** Low – based on specific experimental setup; real-world commercial APIs have diverse pricing, rate limits, and update patterns that may affect the 30× claim; only one corroborated detected change provides weak evidence.

## Next Checks
1. **BI Discovery on Reasoning Models:** Test B3IT’s discovery on at least 10 known reasoning/chat endpoints (e.g., o1, Claude Sonnet) using 5,000 minimal-token prompts. Quantify failure rate (zero BIs) and characterize output patterns.
2. **Non-Determinism Stress Test:** For a fixed set of 10 claimed BIs, issue 1,000 identical queries at T=0. Measure the frequency of support size >1. High rates indicate non-determinism violates the stable-uniform assumption and require mitigation.
3. **Cost Model Validation Against Real Pricing:** For the 93 monitored endpoints, recalculate annualized monitoring cost using each provider’s actual pricing (per token, caching) and observed query volume. Compare to the paper’s simplified estimate; discrepancies >20% would challenge the generalizability of the 30× reduction claim.
