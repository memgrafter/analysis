# SAS-Net: Cross-Domain Image Registration as Inverse Rendering via Structure-Appearance Factorization

## Quick Facts
- arXiv ID: 2602.09050  
- Source URL: https://arxiv.org/abs/2602.09050  
- Reference count: 25  
- Primary result: SAS-Net achieves state-of-the-art cross-domain registration (NCC 0.858 on EuroSAT-Reg-256, 0.748 on FIRE-Reg-256) via structure-appearance factorization and inverse rendering.

## Executive Summary
SAS-Net solves cross-domain image registration where traditional brightness constancy fails due to heterogeneous imaging physics. It reformulates registration as inverse rendering: extract a domain-invariant scene structure from the moving image and re-render it under the fixed image’s domain-specific appearance. The method employs instance normalization to isolate structure, a global average-pooled appearance code, and adaptive instance normalization (AdaIN) to synthesize the aligned image. A composite loss combines structure matching, cycle reconstruction, and direct alignment. On EuroSAT-Reg-256 (multispectral satellite) and FIRE-Reg-256 (retinal fundus), SAS-Net delivers top metrics with real-time inference (89 FPS on RTX 5090).

## Method Summary
Given a moving image \(I_m\) and fixed image \(I_f\) from potentially different imaging domains, SAS-Net decomposes each into a shared domain-invariant structure \(s\) and a domain-specific appearance code \(a\). The scene encoder uses instance normalization to strip per-channel mean and variance, yielding a structure feature map resistant to global brightness/contrast shifts. The appearance encoder compresses the image to a 32-D vector via convolutional layers and global average pooling. The forward renderer applies AdaIN: it normalizes \(s_m\) and affine-transforms it with parameters derived from \(a_f\) to produce the aligned output \(\hat{I}\). Training optimizes three losses: \(L_{\text{scene}}\) to align structures \(s_m\) and \(s_f\), \(L_{\text{cycle}}\) to ensure each image reconstructs from its own structure and appearance, and \(L_{\text{align}}\) to directly match \(\hat{I}\) to \(I_f\). This factorization enables registration across domains with severe photometric discrepancies.

## Key Results
- EuroSAT-Reg-256: NCC 0.858, SSIM 0.488, PSNR 19.84 dB, 89 FPS (RTX 5090)  
- FIRE-Reg-256: NCC 0.748, SSIM 0.855  
- 3.35M‑parameter model achieves state-of-the-art performance across heterogeneous domains.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Instance normalization (IN) in the scene encoder implements inverse rendering by stripping domain-specific appearance statistics, yielding domain-invariant structure.
- **Mechanism**: IN normalizes each channel: \(IN(h)_c = (h_c - \mu_c)/\sigma_c\), removing global brightness (μ) and contrast (σ) while preserving spatial layout.
- **Core assumption**: Domain-specific appearance is captured by per-channel mean and variance; structure resides in spatial patterns surviving normalization.
- **Evidence anchors**: [Abstract] states IN implements structure-appearance decomposition; [Section 3.2] describes IN as stripping appearance. Style-transfer literature (MUNIT, DRIT) supports IN for content-style separation.
- **Break condition**: Spatially correlated appearance (vignetting, gradients) not captured by global statistics may remain; structure encoded in mean/variance (e.g., textureless regions) would be degraded.

### Mechanism 2
- **Claim**: Adaptive Instance Normalization (AdaIN) in the renderer implements the differentiable forward rendering step, applying target appearance statistics to the extracted structure.
- **Mechanism**: AdaIN normalizes \(s\) via IN, then applies conditional affine: \(\gamma(a) \odot IN(s) + \beta(a)\), where \(\gamma,\beta\) are learned from appearance code \(a\).
- **Core assumption**: Rendering function \(R(s,a)\) is approximated by a conditional affine transformation in normalized feature space.
- **Evidence anchors**: [Abstract] and [Section 3.4] explicitly state AdaIN realizes the forward renderer. Style transfer (Huang et al.) validates AdaIN for style modulation.
- **Break condition**: Non-affine imaging physics (non-linear tone curves, specular highlights) exceed AdaIN’s linear modulation; under-dimensional appearance code (d=32) may fail for complex appearance.

### Mechanism 3
- **Claim**: Combined loss \(L_{\text{scene}} + L_{\text{cycle}} + L_{\text{align}}\) enforces factorization and drives registration.
- **Mechanism**:
  - \(L_{\text{scene}} = \|s_m - s_f\|_2^2 + \lambda_{\cos}(1 - \cos(s_m,s_f))\) forces structures to be similar.
  - \(L_{\text{cycle}} = \|G(s_m,a_m) - I_m\|_2^2 + \|G(s_f,a_f) - I_f\|_2^2 + \lambda_{\text{ssim}}(2 - \text{SSIM})\) ensures self-reconstruction.
  - \(L_{\text{align}} = \|\hat{I} - I_f\|_2^2 + \lambda_{\text{ncc}}(1 - \text{NCC}) + \lambda_{\text{grad}}L_{\text{grad}}\) aligns rendered \(\hat{I}=G(s_m,a_f)\) to \(I_f\).
- **Core assumption**: Factorization is identifiable under these losses and network capacities.
- **Evidence**: Loss design described in [Section 3.5]; similar composites appear in disentanglement works (e.g., DRIT++).
- **Break condition**: Imbalanced weights may cause mode collapse (appearance matched, structure ignored) or poor reconstruction.

## Foundational Learning
- **Instance Normalization**: Per-channel mean/variance normalization. *Why needed*: Removes domain-specific statistics to extract invariant structure. *Quick check*: Verify IN layers in scene encoder (affine=False).
- **Adaptive Instance Normalization (AdaIN)**: Content-normalized affine modulation by style code. *Why needed*: Differentiably renders structure under target appearance. *Quick check*: Check AdaIN layer maps appearance code to γ,β.
- **Inverse Rendering**: Recovering scene properties (structure, appearance) from images. *Why needed*: Frames registration as recovering shared structure and transforming appearance. *Quick check*: Model decomposes into s and a; forward model re-synthesizes.
- **Structure-Appearance Factorization**: Separating domain-invariant geometry from domain-specific photometry. *Why needed*: Core assumption enabling cross-domain registration despite brightness constancy violations. *Quick check*: Scene encoder output should be visually similar across domains for same scene.
- **Global Average Pooling**: Aggregates spatial features into a vector. *Why needed*: Produces compact, spatially invariant appearance code. *Quick check*: Appearance encoder ends with GAP before fully-connected layers.
- **Composite Loss Design**: Combining multiple objectives to enforce disentanglement. *Why needed*: Balances reconstruction, structure matching, and registration. *Quick check*: Loss includes scene, cycle, and align terms with specified weights.

## Architecture Onboarding

### Component Map
Scene Encoder (E_S) -> structure s (64×H×W); Appearance Encoder (E_A) -> appearance a (32-D); Forward Renderer (G) takes (s, a) -> rendered I_hat (3×H×W). The aligned image is G(s_m, a_f).

### Critical Path
1. Input: moving image I_m, fixed image I_f.
2. E_S(I_m) produces s_m; E_S(I_f) produces s_f.
3. E_A(I_f) produces a_f.
4. G(s_m, a_f) produces aligned image I_hat.
5. Compute losses: L_scene(s_m,s_f), L_cycle(I_m, G(s_m,a_m); I_f, G(s_f,a_f)), L_align(I_hat, I_f).
6. Backpropagate total loss.

### Design Tradeoffs
- **IN vs. BatchNorm**: IN removes instance-specific statistics but may discard useful global cues; BatchNorm would encode batch-level appearance, harming cross-domain invariance.
- **Global appearance code vs. spatial map**: Global code (GAP) is compact but cannot model local illumination changes; spatial map would be more expressive but increases complexity.
- **AdaIN vs. full decoder**: AdaIN assumes affine rendering; a full conditional decoder could model non-linearities but would require more data and risk overfitting.

### Failure Signatures
- Low NCC/SSIM (<0.5) on validation: model not aligning; check if L_align decreasing, visualize I_hat vs. I_f.
- Structure collapse (s_m ≈ s_f for different scenes): L_scene too high; inspect s_m channels for overly smooth features.
- Appearance encoder constant: a_f variance near zero across batch; increase E_A capacity or remove aggressive pooling.
- Training instability (loss spikes): reduce learning rate, use gradient clipping, rebalance loss weights.

### First Three Experiments
1. **Synthetic IN stress test**: Create image pairs with spatially correlated appearance (vignetting, gradients) but same structure. Measure residual appearance in s_m, s_f (e.g., feature similarity, visualization). Expect: IN should remove global stats but may leave spatial patterns.
2. **AdaIN non-affine capability test**: Apply non-affine transforms (gamma, specular highlights) to target appearance. Compare registration metrics against affine-only cases. Expect: Performance drop for strong non-linearities.
3. **Appearance code dimensionality ablation**: Train with d ∈ {16, 32, 64, 128}. Plot SSIM/NCC vs. d on FIRE and EuroSAT. Expect: d=32 may suffice for FIRE but under-provisioned for EuroSAT’s multispectral complexity.

## Open Questions the Paper Calls Out
1. **Spatially-varying domain shifts**: How to extend SAS-Net to model local illumination gradients or vignetting, given the global appearance code discards spatial information?
2. **Non-affine geometric transformations**: How to handle elastic deformations prevalent in medical imaging, as current factorization assumes structure captures all geometry?
3. **Theoretical justification**: Why does instance normalization guarantee domain-invariant structure extraction, and under what conditions? Formal analysis of identifiability is lacking.

## Limitations
- Architectural specifics (encoder depth, channel sizes) are underspecified; reproduction relies on assumptions.
- Instance normalization only removes global statistics; fails for spatially correlated appearance (e.g., vignetting).
- AdaIN’s affine assumption may be insufficient for non-linear imaging physics.
- Generalization to unseen heterogeneous domains remains unverified beyond the two tested datasets.

## Confidence
- **Structure extraction via IN**: Medium. Supported by style-transfer literature but direct application to registration is novel; break conditions exist.
- **Rendering via AdaIN**: Low-Medium. AdaIN is standard in style transfer, but adequacy as a differentiable renderer for heterogeneous physics is unproven; non-affine transformations challenge assumptions.
- **State-of-the-art performance**: Medium. Reported metrics are strong but depend on precise hyperparameters and implementation fidelity; reproduction uncertainties limit confidence.

## Next Checks
1. **Synthetic IN validation**: Generate controlled spatially correlated appearance shifts; quantify residual appearance leakage in s_m, s_f (feature similarity, visual inspection).
2. **AdaIN non-affine robustness**: Introduce gamma corrections and specular highlights; measure NCC/SSIM degradation curve to identify failure thresholds.
3. **Appearance capacity ablation**: Systematically vary appearance code dimension d; assess performance on EuroSAT (multispectral) vs. FIRE (fundus) to determine adequacy of d=32.
