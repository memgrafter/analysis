# Beyond Parameter Arithmetic: Sparse Complementary Fusion for Distribution-Aware Model Merging

## Quick Facts
- **ArXiv ID:** 2602.11717
- **Source URL:** https://arxiv.org/abs/2602.11717
- **Reference count:** 27
- **Primary result:** SCF-RKL maintains repetition rates below 1.6% (versus near 100% for baselines) and achieves the highest average performance across 24 benchmarks, even for strong‑weak merges or simultaneous reasoning/safety improvements.

## Executive Summary
Model merging combines specialized models without retraining, but arithmetic averaging causes destructive interference, notably repetitive generation. This paper introduces Sparse Complementary Fusion with reverse KL (SCF‑RKL), a distribution‑aware method that selectively updates parameters based on functional divergence. SCF‑RKL computes reverse KL between base and secondary model output distributions to identify important parameters, applies a sparse mask via IQR thresholding, and performs discrete (non‑interpolated) fusion, thereby preserving the base model’s coherent output distribution and avoiding unstable interpolations.

Experiments across 24 language benchmarks (reasoning, code, instruction following, safety) and 7 vision tasks show SCF‑RKL reduces repetition dramatically (under 1.6% vs. ~100% for baselines) and achieves the highest average performance. It handles challenging merges, such as strong‑weak pairs and simultaneous reasoning/safety improvements, and generalizes to vision with 63.9% average accuracy, surpassing prior fusion methods.

## Method Summary
SCF‑RKL merges two models of identical architecture via a sparse, discrete update. For each parameter group (e.g., output channels of a linear layer), it treats the logits as categorical distributions via softmax and computes reverse KL divergence `RKL(q∥p)` between the base model distribution `q` and the secondary model distribution `p`. The importance of a parameter group is `I = |θ_s - θ_b| · RKL`, capturing both magnitude difference and functional impact. All importance values are flattened into a single vector; a global threshold `τ = median(I) + 1.5·IQR(I)` is applied to produce a binary mask `M` that selects the top ~5–15% most important parameters. The fused parameters are then `θ_f = θ_b + M ⊙ (θ_s - θ_b)`, a discrete combination that chooses each parameter entirely from either the base or secondary model. No additional training is required.

## Key Results
- Repetition rates kept below 1.6% across diverse benchmarks, while baseline merging methods approach 100%.
- Highest average performance on 24 language tasks, including scenarios merging strong‑weak pairs and improving both reasoning and safety.
- Generalizes to vision models, achieving 63.9% average accuracy on seven image classification benchmarks, surpassing all prior fusion methods.

## Why This Works (Mechanism)
### Mechanism 1: Reverse KL Preserves High‑Probability Regions
- **Claim:** Reverse KL divergence measures functional divergence to preserve the base model's high‑probability output regions, preventing degenerative amplification of low‑probability tokens (e.g., repetition).
- **Mechanism:** For each parameter group, compute `p = softmax(θ_secondary)` and `q = softmax(θ_base)`. The reverse KL `RKL(q∥p) = Σ q_i log(q_i/p_i)` heavily penalizes deviations where the base model assigns high probability but the secondary model does not. This score is multiplied by the absolute parameter difference to yield an importance metric `I = |θ_s - θ_b| · RKL`. Parameters with high `I` are candidates for update.
- **Core assumption:** The base model's output distribution `q` is relatively stable and "correct"; preserving its high‑mass regions is more critical than covering modes of the secondary model.
- **Evidence anchors:** [abstract] mentions use of reverse KL; [section 2.2] derives `I` and justifies reverse KL as mode‑seeking and conservative.
- **Break condition:** If the base model is poorly calibrated or its high‑probability regions are misaligned with the target task, reverse KL may preserve undesirable behaviors.

### Mechanism 2: Sparse Thresholding Limits Parameter Drift
- **Claim:** Sparse, threshold‑based selection (`M_i = 1[I_i ≥ τ]`) limits parameter drift, maintaining entropy and preventing subspace rotation that causes repetition.
- **Mechanism:** Using an IQR‑based dynamic threshold `τ = median(I) + α·IQR(I)`, only the top ~5–15% of parameters (by importance) are updated. This surgical update minimizes the perturbation norm `∥M⊙(θ_s - θ_b)∥`, which bounds changes in model entropy and principal subspace angles (Theorems 3.2, 3.3).
- **Core assumption:** Most parameter updates from fine‑tuning are either redundant or harmful; only a small, information‑rich subset meaningfully contributes new capabilities.
- **Evidence anchors:** [section 2.3] describes the IQR threshold; [section 3.2] and Figures 3–6 empirically link sparsity to lower spectral shift and principal angles.
- **Break condition:** If the important parameters are not concentrated enough (e.g., knowledge is highly distributed), sparsity may discard critical information, hurting performance.

### Mechanism 3: Discrete Composition Avoids Phantom Manifolds
- **Claim:** The binary mask enforces "discrete composition", keeping fused parameters on the union of the parent models' manifolds, avoiding the unstable "phantom" manifold created by linear interpolation.
- **Mechanism:** Because `θ_f,j ∈ {θ_b,j, θ_s,j}` for all `j`, the fused model is a point in the discrete union `M₀ ∪ M₁`, not in the continuous linear subspace between them. This avoids unverified parameter combinations that can distort training dynamics and generation.
- **Core assumption:** The parent models' individual parameter values are optima on their respective manifolds; interpolated values are not necessarily on any well‑behaved manifold.
- **Evidence anchors:** [section 3.3] formally states the "Discrete Composition Property" and Figure 7 shows >80% of parameters in baselines are interpolated "neither" values, while SCF‑RKL uses mostly parent values.
- **Break condition:** If the two parent models are highly dissimilar (e.g., different architectures), even discrete switching may cause discontinuities and performance drops.

## Foundational Learning
- **Output distributions via softmax:** Treating model logits as categorical distributions is essential because SCF‑RKL's importance score uses `softmax(θ)` to interpret parameters as probabilities. Quick check: Given `θ = [1.0, 2.0, 0.5]`, compute `softmax(θ)`; interpret KL divergence between two such vectors.
- **Reverse Kullback‑Leibler divergence:** `D_KL(q∥p)` is mode‑seeking and conservative, heavily penalizing high `q` where `p` is low. This property preserves the base model's high‑probability tokens. Quick check: How does `D_KL(q∥p)` differ from `D_KL(p∥q)` in terms of distribution regions it cares about?
- **Sparsity via IQR thresholding:** The adaptive threshold `τ = median + α·IQR` automatically yields ~5–15% selection depending on data. Understanding quartiles is key to grasping per‑layer adjustment. Quick check: If median=10, IQR=4, α=1.5, what is τ? Roughly what percentage of scores exceed it in a heavy‑tailed distribution?

## Architecture Onboarding
**Component map:** θ_b, θ_s → Importance Scorer (computes I = |Δ|·RKL) → Mask Generator (thresholds I to binary M) → Fusion Module (θ_f = θ_b + M ⊙ (θ_s - θ_b)) → θ_f

**Critical path:** Load state dicts of both models; iterate over tensors (per output channel for 2D, entire vector for 1D); compute softmax distributions and reverse KL; obtain per‑group importance; flatten all I; compute global median and IQR; set τ = median + 1.5·IQR; generate mask; reshape mask to original tensor shapes; fuse parameters; save fused checkpoint.

**Design tradeoffs:**
- **Sparsity level (α):** Controls update fraction; lower α increases integration but risks interference.
- **Grouping granularity:** Per‑weight vs. per‑channel vs. per‑layer; finer gives more precise importance but noisier; coarser may miss critical directions.
- **Base model choice:** The base’s quality heavily influences final performance; a strong base is generally preferred.

**Failure signatures:**
- Repetition rate >5% → insufficient sparsity or poor RKL weighting.
- Significant performance drop vs. the stronger parent → over‑sparsification (τ too high) or model incompatibility.
- Safety benchmark decline after merging a safety‑aligned model → may need layer‑specific adjustments or post‑merge fine‑tuning.

**First 3 experiments:**
1. Repetition diagnostic: merge two well‑behaved models; measure repetition on a long‑generation benchmark; expect <2% for SCF‑RKL vs. ~100% for baselines.
2. Reasoning + safety fusion: merge a reasoning‑specialized model with a safety‑aligned model; evaluate on AIME (reasoning) and HarmBench (safety); expect simultaneous gains.
3. Strong‑weak merge: fuse a strong model (e.g., Qwen2.5‑32B) with a much weaker fine‑tuned variant; SCF‑RKL should preserve the strong model’s performance without collapse, unlike TIES/DARE.

## Limitations
- Exact model checkpoints and evaluation details (few‑shot counts, prompt templates, max tokens) are not fully disclosed.
- Ambiguity in parameter grouping strategy (e.g., which tensors, softmax dimension) and handling of tied embeddings.
- Lack of description of memory‑efficient quantile computation for very large models.
