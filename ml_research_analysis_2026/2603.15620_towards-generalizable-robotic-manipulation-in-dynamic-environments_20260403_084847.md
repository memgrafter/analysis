# Towards Generalizable Robotic Manipulation in Dynamic Environments

## Quick Facts
- arXiv ID: 2603.15620
- Source URL: https://arxiv.org/abs/2603.15620
- Reference count: 40
- Primary result: PUMA integrates historical optical flow and world queries to achieve state-of-the-art dynamic manipulation, with a 6.3% absolute success rate improvement and MS=34.97 on DOMINO.

## Executive Summary
Vision-Language-Action (VLA) models struggle in dynamic environments due to reliance on single-frame observations and lack of dynamic data. This paper introduces DOMINO, a large-scale benchmark with 35 dynamic manipulation tasks across five robots, providing over 110K expert trajectories. The proposed PUMA architecture enhances dynamic awareness by incorporating scene-centric historical optical flow and object-centric world queries for short-horizon prediction. Experiments show PUMA outperforms baselines by 6.3% absolute success rate on DOMINO and transfers robustly to static tasks, demonstrating the generalizability of dynamic data training.

## Method Summary
PUMA builds on the Qwen3-VL backbone. Inputs include current multi-view RGB images, historical frames for optical flow computation, and language instructions. Optical flow maps (64×64) are precomputed and cached. A shared visual encoder processes current views and flow, fused with text features. Two query decoders: action queries output action chunks, while world queries predict future object features extracted from future frames using Grounded-SAM. Training uses behavioral cloning with ℓ1 action loss and an auxiliary cosine loss for future feature prediction (λ=0.05). Key hyperparameters: history window h=4, future horizon N=4, 4 world queries.

## Key Results
- PUMA achieves state-of-the-art on DOMINO with a 6.3% absolute success rate improvement over strongest baselines, reaching a manipulation score of 34.97.
- Training on dynamic data yields spatiotemporal representations that transfer effectively to static manipulation tasks.
- DOMINO benchmark spans 35 diverse dynamic tasks across 5 robot embodiments with 110K+ expert trajectories.

## Why This Works (Mechanism)
**Mechanism 1: Dynamic Data Mitigates Overfitting to Static Configurations**
- Claim: Exposure to dynamic interactions forces the policy to learn motion patterns rather than static spatial biases, enhancing generalization.
- Mechanism: Dynamic data includes moving targets and temporal variations, compelling the model to reason about object motion, which transfers to static tasks.
- Core assumption: Static datasets train policies assuming stationary objects; dynamic data breaks this.
- Evidence anchors: Abstract states training on dynamic data fosters transferable representations; Section 4.4 notes mitigation of overfitting to static positional biases.
- Break condition: If dynamic data lacks motion diversity (e.g., only linear motions), representations may not generalize to varied dynamics or static placements.

**Mechanism 2: Historical Optical Flow Provides Explicit Motion Cues**
- Claim: Optical flow encodes pixel-level displacements, simplifying dynamic perception compared to inferring motion from raw frames.
- Mechanism: Flow maps offer dense motion fields that are easier for the vision encoder to process than sequential raw images.
- Core assumption: Implicit motion extraction from raw frames is harder; explicit flow reduces learning complexity.
- Evidence anchors: Abstract mentions integrating historical optical flow; Section 3.1 argues flow makes learning dynamic patterns easier; Section 4.5 ablation shows flow addition improves SR (11.71% vs 10.86%), while replacing with raw frames degrades (8.15%).
- Break condition: Flow can fail due to large displacements, occlusions, or textureless regions, introducing errors.

**Mechanism 3: Auxiliary Future Prediction Regularizes Representation**
- Claim: World queries trained to predict future object states force the backbone to encode dynamics-relevant information, benefiting action prediction.
- Mechanism: Predicting future features requires understanding underlying dynamics; this shared representation improves the action policy.
- Core assumption: Future state prediction captures dynamics knowledge transferable to control.
- Evidence anchors: Abstract couples history-aware perception with prediction; Section 3.2 states supervision forces latent representation to capture dynamics; Section 4.5 shows adding auxiliary prediction improves SR (14.80% vs 11.71%).
- Break condition: Inappropriate prediction horizon N or loss weight λ can make the auxiliary task noisy or destabilize training.

## Architecture Onboarding
**Component Map**
Inputs (current multi-view RGB, historical RGB frames, language instruction) -> Preprocessing (cached optical flow from historical pairs, cached future object masks/features via Grounded-SAM) -> Shared backbone (Qwen3-VL visual encoder for current and flow, text encoder) -> Feature fusion -> Query decoders (action decoder for action chunk, world queries for future features) -> Losses (L1 action loss + λ cosine loss for future features) -> Output action chunk.

**Critical Path**
1. Data prep: For each episode, cache optical flow maps and future object masks/features.
2. Forward pass: Encode instruction, encode current multi-view and historical flow, fuse features, decode action chunk with action queries, predict future features with world queries.
3. Loss: Compute L_action and L_world; backpropagate.
4. Inference: Compute flow on-the-fly from buffered frames; no future caching.

**Design Tradeoffs**
- Flow vs. raw frames: Flow gives explicit motion but adds compute; raw frames are cheaper but harder to learn from.
- Prediction horizon N: Longer N improves foresight but increases difficulty; paper found N=4 optimal.
- Loss weight λ: Balances action and world losses; set to 0.05.
- World queries count: More queries capture richer dynamics but add parameters.
- Historical window h: Longer history provides context but more frames to process.

**Failure Signatures**
- Performance drop on Level 2/3 dynamic tasks: may indicate overfitting to simple motions; ensure diverse motion types in training.
- No improvement from flow addition: verify flow computation correctness and integration.
- Auxiliary loss not decreasing: check ground-truth object feature quality from Grounded-SAM; adjust λ and query initialization.
- Overfitting on dynamic data but poor static transfer: suggests narrow dynamic data; consider co-training with static data.

**First 3 Experiments**
1. Baseline reproduction: Train OpenVLA-OFT on DOMINO Level 1, expect success rate ~10.86% and manipulation score ~30.49 (Table 3).

## Limitations
- Incomplete documentation of DOMINO's two-stage spatiotemporal synchronization pipeline hinders data regeneration and full replication.
- Underspecified architectural details for integrating action and world queries into Qwen3-VL limit faithful reproduction.
- Limited evaluation of robustness to optical flow errors and mask failures in the caching-dependent system.
