# Code2Math: Can Your Code Agent Effectively Evolve Math Problems Through Exploration?

## Quick Facts
- **arXiv ID**: 2603.03202
- **Source URL**: https://arxiv.org/abs/2603.03202
- **Reference count**: 40
- **Primary result**: A multi-agent system autonomously evolves seed math problems into harder variants with high solvability (86–96% agreement with GPT‑5.2‑High) and demonstrable difficulty increases, though at significant computational cost.

## Executive Summary
Code2Math addresses the scarcity of high-difficulty math problems by using a multi-agent framework to evolve existing problems into more challenging variants. An Evolution Agent performs code-driven exploration (Python, SymPy, constraint solvers) to design harder instances, while separate Solvability and Difficulty Verification Agents ensure logical correctness and genuine cognitive depth increase. Test-time scaling with multiple rollouts enables systematic generation. Experiments across several LLMs show evolved problems are solvable and consistently harder, with reasoning token consumption rising substantially. However, the process is inefficient, requiring many failed rollouts per success, primarily due to solvability verification bottlenecks.

## Method Summary
The approach uses three coordinated agents. The Evolution Agent first analyzes a seed problem’s cognitive bottleneck, then uses code tools to explore modifications that increase difficulty. The Solvability Verification Agent validates that the evolved problem has a correct solution chain, and the Difficulty Verification Agent scores the difficulty increase on a 5-point scale (requiring ≥3 to pass). Inputs include 100 diverse seed problems with solutions and a Python sandbox with libraries like SymPy and Z3. Evaluation metrics include Agreement Rate (internal vs. external solvability), Solve Rate drop on strong solvers, Average Token Consumption, and rollout efficiency. The system operates with a rollout budget (up to 20 attempts per seed) and a maximum trajectory length of 30 steps.

## Key Results
- High solvability: Agreement Rates with GPT‑5.2‑High range 86%–96% across evolution models.
- Clear difficulty increase: Solve rates on original set drop by up to 21 percentage points for strong solvers (e.g., Gemini‑3‑Flash‑Thinking: 56% → 35% on DeepSeek‑Reasoner‑evolved problems).
- Deeper reasoning: Median token consumption rises from 9,606 (original) to 11,434–17,277 (evolved).

## Why This Works (Mechanism)
Code2Math succeeds because it decouples problem creation from verification through specialized agents. The Evolution Agent’s two-phase process—first identifying the cognitive bottleneck, then using code tools to manipulate mathematical structures—allows systematic exploration of variant spaces. Mandatory code usage (e.g., SymPy for algebraic manipulation, Z3 for constraints) grounds the evolution in executable logic, reducing hallucination. Sequential verification by dedicated agents acts as a quality filter: solvability checks ensure solution chains are logically sound, while difficulty scoring (Burden of Discovery) guards against trivial or computationally bloated variants. Test-time scaling with multiple rollouts gives the system chances to find valid evolutions despite a high failure rate.

## Foundational Learning
- **Multi-agent coordination**: Needed to separate creative evolution from rigorous verification, preventing a single model from both designing and judging problems. *Quick check*: Does the pipeline enforce sequential agent passes? Yes—both verifiers must approve.
- **Code-driven exploration**: Tools like SymPy and Z3 enable precise, executable transformations of mathematical expressions and constraints. *Quick check*: Are all Evolution Agent trajectories required to include code execution? Yes, mandatory.
- **Solvability verification**: Validates that an evolved problem has a correct, complete solution chain. *Quick check*: Internal verifier agreement with GPT‑5.2-High is 86–96%, indicating consistent logic checks.
- **Difficulty metric (Burden of Discovery)**: A 5-point scoring rubric assessing conceptual depth beyond mere computation. *Quick check*: Problems must score ≥3 to pass, ensuring non-trivial insight.
- **Test-time scaling**: Multiple rollouts (up to 20 per seed) increase success probability despite per-rollout failure. *Quick check*: Average failed rollouts per success range 1.56–6.55, showing scale compensates for low per-attempt yield.
- **Token consumption as reasoning depth proxy**: Increased tokens suggest more stepwise reasoning. *Quick check*: Evolved problems show 19–80% higher median token use vs. original.

## Architecture Onboarding
Evolution Agent -> Solvability Verification Agent -> Difficulty Verification Agent

**Critical path**: Seed problem analysis → Evolution Agent generates candidate (with code) → Solvability check (solution chain validation) → Difficulty check (Burden of Discovery score) → Accept if both pass.

**Design tradeoffs**: Verification rigor (high AR) vs. efficiency (high failure rate); code tool reliance ensures executability but limits conceptual leaps; difficulty scoring prioritizes insight but relies on qualitative rubric.

**Failure signatures**: 
1. High per-success failure count (1.56–6.55 rollouts) indicates solvability verification bottleneck.
2. Token bloat without solve rate drop suggests artificial complexity inflation.
3. Weak evolution models fail to increase difficulty for top solvers, indicating capability ceiling.

**First three onboarding experiments**:
1. Replicate with a public seed set (e.g., 100 AIME problems) to measure metric variance from undisclosed seeds.
2. Ablate prompt wording in verification rubrics to test robustness of scoring boundaries.
3. Conduct human evaluation on sampled evolved problems to separate token increase from genuine conceptual depth.

## Open Questions the Paper Calls Out
The paper does not explicitly enumerate open questions beyond its immediate scope. However, its discussion of limitations and suggested next checks implies several open research questions:
- How can the solvability verification bottleneck be mitigated to improve rollout efficiency without sacrificing correctness?
- Does the Burden of Discovery difficulty rubric reliably distinguish genuine conceptual depth from superficial complexity? This requires human validation.
- To what extent are the evolved problems dependent on the undisclosed seed distribution? Replication with public seeds is needed.
- How sensitive are the results to prompt engineering variations in the verification agents?
- Can the "Theory of Mind" mechanism be operationalized more concretely to better anticipate solver reasoning?
- What are the long-term effects of scaling test-time compute on problem quality and diversity?

## Limitations
- Seed problem set composition and distribution are undisclosed, risking selection bias.
- Prompt templates may differ from final versions; minor wording changes could alter agent behavior.
- "Theory of Mind" mechanism for anticipating solver reasoning is conceptually described but not operationally specified.
- Verification scoring boundaries (e.g., score 2 vs. 3) are qualitative, leading to potential inconsistency.
- Hardware and resource constraints (GPU type, batch size, wall-clock time) are not fully documented, affecting reproducibility of efficiency claims.

## Confidence
- **Effective evolution of harder problems**: Medium (results promising but depend on undisclosed seeds/prompts; risk of overfitting to verification agents).
- **High solvability agreement (86–96%)**: High (external judge matches internal verifier consistently).
- **Increased difficulty (solve rate drop)**: Medium (proxy evidence; could reflect token bloat rather than conceptual depth).
- **Higher token consumption = deeper reasoning**: Low (tokens are imperfect proxy; may capture verbosity).

## Next Checks
1. Replicate with a public seed set (e.g., 100 AIME problems) and report variance in metrics.
2. Perform ablation on prompt wording: test minor modifications to verification rubrics to measure robustness.
3. Run controlled experiments separating token increase from genuine difficulty (e.g., human eval on sample evolved problems).
