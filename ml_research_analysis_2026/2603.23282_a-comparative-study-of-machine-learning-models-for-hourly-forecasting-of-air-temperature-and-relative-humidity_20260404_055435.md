# A Comparative Study of Machine Learning Models for Hourly Forecasting of Air Temperature and Relative Humidity
## Quick Facts
- arXiv ID: 2603.23282
- Source URL: https://arxiv.org/abs/2603.23282
- Reference count: 17
- Primary result: XGBoost achieved test MAE of 0.302 °C for temperature and 1.271% for humidity, with average R² of 0.989.

## Executive Summary
This study evaluates seven machine learning models for hourly forecasting of air temperature and relative humidity in the topographically complex urban environment of Chongqing, China. Using a unified framework that includes careful preprocessing, lag and rolling statistical feature engineering, and a time-series-aware validation strategy, the authors compare the predictive performance of tree-based ensembles (including XGBoost, Random Forest, Decision Tree), support vector regression, a multi-layer perceptron, and deep learning architectures (LSTM, CNN-LSTM) on a real-world meteorological dataset spanning 2024–2026. XGBoost emerges as the top performer, achieving low errors (MAE 0.302 °C, 1.271% humidity) and a high average R² of 0.989, while the deep learning models, particularly CNN-LSTM, display significantly poorer accuracy, highlighting the strength of gradient-boosted trees for this structured time-series regression task.

## Method Summary
The authors implemented a standardized pipeline: first, they sorted the hourly data chronologically, handled missing values via forward and backward filling, and removed physically impossible outliers (e.g., negative humidity). For each target variable (temperature, humidity), they generated lag features (2, 3, 6, 12, 24 hours) and rolling statistics (mean and standard deviation with windows of 3, 6, 12, 24 hours), then concatenated these with the original auxiliary covariates (precipitation, wind speed, etc.). The dataset was split chronologically: the first 80% served as training, the last 20% as test. Hyperparameter optimization was performed via grid search using `TimeSeriesSplit` (5 folds) on the training set, with the average RMSE across both targets as the selection criterion. The seven models included SVR, MLP, RF, DT, LSTM, CNN-LSTM, and XGBoost; multi-output strategies varied (e.g., `MultiOutputRegressor` for SVR and XGBoost, native multi-output for tree-based models, dual-neuron output for LSTMs). Final evaluation reported MAE, RMSE, R², and MAPE on the test set.

## Key Results
- XGBoost achieved the lowest test errors: MAE 0.302 °C (temperature) and 1.271% (humidity), with an average R² of 0.989.
- Tree-based ensembles (Random Forest, Decision Tree) also performed strongly, while deep learning models (LSTM, CNN-LSTM) were significantly less accurate; CNN-LSTM was the worst.
- The poor showing of deep learning is attributed to the relatively small dataset (~1.25 years of hourly data), which is insufficient for such complex architectures to learn effectively.

## Why This Works (Mechanism)
XGBoost's superior performance stems from its ability to efficiently model nonlinear interactions in tabular data with limited samples, a common scenario in environmental forecasting. The engineered lag and rolling features provide a rich temporal context that tree-based ensembles can readily exploit, as they automatically capture complex decision boundaries without requiring large training sets. In contrast, deep learning models like LSTM and CNN-LSTM are data-hungry; with only ~10,000 hourly observations, they underfit due to insufficient capacity to learn temporal dependencies, especially when the input sequences are relatively short (single-step forecasts). Moreover, the structured nature of the input (hand-crafted features) aligns better with gradient boosting than with sequence architectures that expect raw sequential data.

## Architecture Onboarding
**Component Map**: Raw Data -> Preprocessing -> Feature Engineering -> TimeSeriesSplit (CV) -> GridSearchCV (Model Selection) -> Best Model -> Test Set Evaluation -> Metrics (MAE, RMSE, R², MAPE)

**Critical Path**: The sequence that must be followed to replicate results: Acquire data → Preprocess → Create lag/rolling features → Define chronological train/test split → Perform grid search with TimeSeriesSplit on training data → Retrain best model on full training set → Evaluate on test set.

**Design Tradeoffs**:
- Using many lag/rolling features increases dimensionality and may cause overfitting; tree-based models mitigate this with regularization.
- TimeSeriesSplit reduces the amount of training data in early folds, potentially leading to higher variance in validation scores; choosing `n_splits=5` balances this.
- Deep learning models offer sequence modeling flexibility but require more data and careful hyperparameter tuning; they are not well-suited for this dataset size.

**Failure Signatures**:
- Validation RMSE significantly lower than test RMSE → possible data leakage (e.g., using future information in features or shuffling).
- Deep learning models not converging or showing very high training error → underfitting due to limited data or model complexity.
- Many NaNs in feature matrix after lag/rolling → insufficient data or too many lags; reducing lag depth may be necessary.
