# Explore with Long-term Memory: A Benchmark and Multimodal LLM-based Reinforcement Learning Framework for Embodied Exploration

## Quick Facts
- arXiv ID: 2601.10744
- Source URL: https://arxiv.org/abs/2601.10744
- Reference count: 40
- Primary result: MemoryExplorer achieves state-of-the-art performance on LMEE-Bench (23.53% SR, 14.99 SPL) and GOAT-Bench (46.40% SR, 28.03 SPL), with QA scores of 48.14 MLLM-Score.

## Executive Summary
The paper addresses a critical gap in embodied AI: existing benchmarks and methods neglect the exploration process and long-term memory utilization. It introduces LMEE-Bench, a benchmark unifying multi-goal navigation with memory-based question answering, and proposes MemoryExplorer, a framework that fine-tunes a multimodal LLM via reinforcement learning to proactively query a multimodal episodic memory bank and integrate retrieved memories into decision-making. MemoryExplorer significantly outperforms prior approaches, such as RA-Mem, on LMEE-Bench, and demonstrates transfer to GOAT-Bench. Real-world robot experiments further show promising sim-to-real generalization.

## Method Summary
MemoryExplorer employs a multimodal LLM (Qwen2.5-VL-7B) as its policy network. At each step, the agent receives a task instruction, three egocentric images, and a question. It maintains an external memory bank storing CLIP-based visual and textual features along with positions. The policy may invoke a memory retrieval tool by generating code; the tool queries the memory bank via CLIP similarity and returns top-3 memories. These memories are fed back to the LLM, which then outputs an action (turn_left/move_forward/turn_right), a frontier selection (which view to explore), and an answer. The policy is fine-tuned using Group Relative Policy Optimization (GRPO) with a multi-task reward combining action accuracy, frontier correctness, QA accuracy (or MLLM-Score), and format compliance. A consistency penalty discourages mismatched action-frontier pairs, and a scaling factor amplifies rewards when the memory tool is successfully used, encouraging proactive retrieval.

## Key Results
- On LMEE-Bench, MemoryExplorer achieves up to 23.53% success rate and 14.99 SPL in navigation, with QA scores reaching 48.14 MLLM-Score, outperforming baselines (e.g., RA-Mem).
- On GOAT-Bench, it attains 46.40% SR and 28.03 SPL, demonstrating transferability.
- Ablation studies confirm that both the memory retrieval tool and the consistency penalty in the reward are critical; removing them degrades performance significantly.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Proactive memory retrieval integrated with action planning enables unified cognition and decision-making for long-horizon tasks.
- **Mechanism:** The agent uses a memory retrieval tool (via generated code) to query its multimodal episodic memory bank based on task instructions and current observations. Retrieved memories are fed back to the MLLM for reasoning, influencing both the answer to a QA sub-task and the selection of a frontier/action for navigation. A multi-task reward incentivizes accurate retrieval and its effective use.
- **Core assumption:** That actively querying stored experiences (rather than passively filtering a context window) leads to better scene understanding and more efficient exploration policies.
- **Evidence anchors:**
  - [abstract]: "proactive memory querying... By analyzing its answers and assessing task progress, the agent gains an understanding... and plans subsequent actions."
  - [section 4]: Formalizes the retrieval tool `R` and the final response distribution `y ∼ π_θ(· | I, O, M_re)`. The reward `r_total` includes `r_answer` and `r_frontier`.
  - [corpus]: Weak direct evidence. Corpus titles like "3DLLM-Mem: Long-Term Spatial-Temporal Memory" and "HIMM: Human-Inspired Long-Term Memory Modeling" indicate a research trend, but do not anchor this specific mechanism's efficacy.
- **Break condition:** If the memory retrieval tool frequently returns irrelevant memories, the coupling between cognition and action breaks down, leading to navigation loops or incorrect QA answers, as seen in failure cases (Fig. 10-12).

### Mechanism 2
- **Claim:** A multi-task reward function that jointly optimizes action accuracy, frontier selection, answer precision, and format consistency successfully trains a single policy to handle the coupled cognition-decision loop.
- **Mechanism:** The reward `r_total` combines sub-rewards (`r_action`, `r_frontier`, `r_answer`, `r_format`) with coefficients `w_act`, `w_front`, `w_ans`, `w_fmt`. A consistency penalty `c` discourages logically inconsistent action/frontier pairs. A tool-usage scaling factor `α` amplifies rewards when the tool is successfully invoked, encouraging its use.
- **Core assumption:** That a carefully weighted sum of sparse, task-aligned sub-rewards can shape the MLLM's policy toward the desired integrated behavior without requiring dense, shaped rewards for every intermediate step.
- **Evidence anchors:**
  - [section 4]: Defines `r_total` and its components. "This design enables the model to understand spatial and action relationships while actively invoking memory retrieval tools... facilitating autonomous exploration."
  - [section 5 & Supplementary Table 7]: Ablation study shows removing the consistency penalty `c` or tool-usage penalty `α` degrades performance (SR/SPL/Score), validating their design.
  - [corpus]: No direct anchor. Corpus focuses on memory architectures, not specific reward shaping for unified cognition-action.
- **Break condition:** If sub-reward weights are poorly tuned (e.g., `w_ans` dominates), the model may prioritize answering questions correctly at the expense of efficient navigation, or vice-versa. The ablation in Supplementary Table 8 shows sensitivity to weight changes.

### Mechanism 3
- **Claim:** Reinforcement Fine-Tuning (RFT) with Group Relative Policy Optimization (GRPO) effectively adapts a pre-trained MLLM to learn active memory retrieval and exploration strategies from the multi-task reward signal.
- **Mechanism:** GRPO, a policy gradient method, updates the MLLM policy `π_θ` to maximize the expected multi-task reward `r_ϕ` while regularizing towards a reference model `π_ref` via a KL penalty. It samples multiple responses per prompt to compute advantages, enabling learning from the sparse, binary-like success signals of navigation and QA.
- **Core assumption:** That the gradient signal from the multi-task reward, despite its sparsity, is sufficient to overcome the strong priors of the pre-trained MLLM and teach it the novel skill of invoking a tool and integrating its results into a decision.
- **Evidence anchors:**
  - [abstract]: "fine-tunes a multimodal large language model through reinforcement learning to encourage active memory querying."
  - [section 4]: Presents the RFT objective `max_πθ E[... r_ϕ(...) - β D_KL(...)]` and specifies using GRPO.
  - [section 5 & Fig. 5]: Training reward curve shows improvement over steps, and tool usage percentage increases, correlating with better performance. Ablation in Supplementary Table 6 shows RFT (w/ memory tool) significantly improves over a baseline without active retrieval.
  - [corpus]: Weak anchor. "LLM-Based Offline Learning for Embodied Agents via Consistency-Guided Reward Ensemble" (arxiv:2411.17135) uses RL, but for different purposes. No direct evidence for GRPO's success in this specific memory-integration context.
- **Break condition:** If the reward signal is too sparse or mis-specified (e.g., poor frontier labeling), GRPO may fail to learn, leading to performance similar to the non-RFT baseline (RA-Mem). The paper shows RA-Mem (no RFT) performs worse than MemoryExplorer.

## Foundational Learning

**Concept: Multimodal Large Language Models (MLLMs) as Policy Networks**
- **Why needed here:** The entire MemoryExplorer framework uses an MLLM (Qwen2.5-VL-7B) as the core policy network that perceives multi-view images, understands language instructions/questions, generates structured outputs (action, frontier, answer), and emits code for tool use. Understanding MLLM capabilities (vision-language grounding, code generation) and limitations (context window, hallucination) is essential.
- **Quick check question:** What are the key input and output modalities of the MLLM policy in MemoryExplorer, and how does its pre-training knowledge relate to the fine-tuning task?

**Concept: Reinforcement Learning from Human/Environment Feedback (RLHF/RFT) for Language Models**
- **Why needed here:** The method fine-tunes the MLLM using RL (GRPO) with a manually designed multi-task reward. This moves beyond supervised imitation learning to optimize for long-horizon task success and integrated behavior. Prerequisites include understanding policy gradients, KL regularization, and advantage estimation.
- **Quick check question:** What is the role of the reference model `π_ref` and the KL penalty coefficient `β` in the RFT objective, and why are they important for stable training?

**Concept: Episodic Memory and Retrieval in Embodied AI**
- **Why needed here:** The core innovation is treating exploration as memory construction. Requires understanding what an episodic memory bank stores (position, text features, image features), how it's queried (via text query -> CLIP similarity), and how it differs from working memory or a simple context buffer. The retrieval mechanism is central to the agent's "cognition."
- **Quick check question:** How is the similarity score `s_i` between a current state and a memory entry computed in equation (2), and what do the weights `ω_f`, `ω_o`, `ω_p` represent?

## Architecture Onboarding

**Component map:** Input Interface -> Policy MLLM -> Memory Bank -> Memory Retrieval Tool -> Frontier Manager -> Reward Calculator -> RL Trainer

**Critical path:** Task Input (`I,O,Q`) is parsed and fed to the Policy MLLM. The Policy MLLM may optionally call the Memory Retrieval Tool, which queries the Memory Bank and returns retrieved memories. These memories are incorporated into the Policy MLLM's context for final reasoning, yielding an output (`S,F,A`). The action is executed in the environment, updating the state and memory bank. The Reward Calculator computes `r_total` from the output and ground-truth labels. The RL Trainer (GRPO) uses this reward to update the Policy MLLM parameters.

**Design tradeoffs:**
- Tool invocation adds computational overhead and may return irrelevant memories, but improves exploration; the scaling factor α balances encouragement vs. penalty.
- Multi-task reward uses sparse signals that may conflict; careful weighting and consistency penalty c are needed to navigate trade-offs between navigation efficiency and QA accuracy.
- Memory bank size vs. retrieval cost: a larger bank holds more info but slows retrieval; dynamic filtering and adaptive thresholds manage this trade-off.
- Using a single MLLM for all sub-tasks simplifies training but may not peak each sub-skill; multi-task reward is the compromise.

**Failure signatures:**
1. High tool invocation but low QA score: model retrieves memories but cannot reason from them, indicating poor memory content or reasoning.
2. Low tool invocation + low navigation SPL: agent fails to learn to use memory for exploration, defaulting to heuristics; suggests reward shaping insufficient.
3. Inconsistent ACTION and FRONTIER: e.g., predicted frontier left but action move_forward; indicates spatial reasoning breakdown.
4. "No memory found" or irrelevant retrievals: retrieval query is vague or memory bank lacks relevant info.

**First 3 experiments:**
1. Unit test the Memory Retrieval Tool with a fixed memory bank and known queries to verify CLIP similarity ranking.
2. Test the Policy MLLM zero-shot on QA with a given perfect memory to isolate reasoning capability.
3. Run the RA-Mem baseline (no RFT) on LMEE-Bench and log tool invocation rate, QA accuracy with tool, and navigation SPL to quantify the gap.

## Limitations
- Unspecified details: exact memory update novelty threshold, position similarity function, frontier labeling from expert trajectories.
- Reward signal fidelity: unclear whether the heavy MLLM judge is used during RL or a proxy; scaling factor α's effect on format reward ambiguous.
- Limited real-world validation: only one scene and object category tested, insufficient to claim broad sim-to-real transfer.

## Confidence
- Proactive Memory Retrieval Mechanism: Medium
- Multi-task Reward Design: High
- GRPO Fine-tuning Efficacy: Medium
- Sim-to-Real Generalization: Low
