# STELLA: Self-Reflective Terminology-Aware Framework for Building an Aerospace Information Retrieval Benchmark

## Quick Facts
- **arXiv ID:** 2601.03496
- **Source URL:** https://arxiv.org/abs/2601.03496
- **Reference count:** 40
- **Primary result:** Llama-Embed-Nemotron (8B) achieved the best overall nDCG@10 (0.788) and minimized the TCQ-TAQ gap, demonstrating superior semantic understanding in aerospace IR.

## Executive Summary
This paper addresses the absence of a public aerospace information retrieval (IR) benchmark by introducing STELLA, a framework to automatically construct high-quality evaluation sets from NASA Technical Reports (NTRS). The core innovation lies in generating two complementary query types from the same passage pool: Terminology Concordant Queries (TCQ), which require verbatim inclusion of aerospace terminology to test lexical matching, and Terminology Agnostic Queries (TAQ), which replace terms with context-derived descriptions to force pure semantic retrieval. The query generation pipeline is enhanced with Chain-of-Density and a Self-Reflection loop to enforce precision and constraint adherence. A hybrid cross-lingual extension translates TAQ fully but preserves English terms in TCQ, reflecting real-world multilingual engineering practice. Evaluation of seven embedding models revealed that large decoder-only models (e.g., Llama-Embed-Nemotron, 8B) achieved the highest overall nDCG@10 and most effectively bridged the lexical-semantic performance gap, while BM25 remained highly competitive on TCQ, reaffirming the strength of lexical matching for domain-specific terms.

## Method Summary
STELLA’s pipeline begins by parsing NTRS PDFs with DocLayout-YOLO and recursive token chunking to create a passage pool. A terminology dictionary is constructed via regex-based candidate extraction followed by multi-stage filtering (document frequency, POS tagging, specificity threshold τ≤3.5). Passages are curated by filtering for ≥5 distinct terminology items, classifying intent into five aerospace-specific categories using an LLM, and applying k-medoids clustering (k=5) to select 100 representative passages per intent. For each passage, Chain-of-Density incrementally adds key entities, while a Self-Reflection stage iteratively critiques the generated query against eight hard constraints (e.g., answerability, no external knowledge, format). This produces TCQ (terms included verbatim) and TAQ (terms replaced by descriptions). For cross-lingual evaluation, TCQ undergoes hybrid translation (preserving English terms from the dictionary), whereas TAQ is fully translated. The resulting (query, passage) pairs are validated via intent classifier F1, G-Eval scores, back-translation similarity, and terminology preservation checks.

## Key Results
- STELLA provides the first systematic framework to build a domain-specific IR benchmark from NTRS, enabling isolated evaluation of lexical (TCQ) and semantic (TAQ) retrieval capabilities.
- Large decoder-only embedding models (e.g., Llama-Embed-Nemotron, 8B) achieved the highest nDCG@10 (0.788) and minimized the TCQ-TAQ performance gap, indicating superior alignment of lexical form with semantic meaning.
- BM25 performed strongly on TCQ but dropped sharply on TAQ, highlighting the enduring strength of exact-term matching for technical jargon and the gap semantic models must close.
- Hybrid cross-lingual queries validated the design: TCQ performance significantly outperformed TAQ across all target languages, confirming that preserving English terms aligns with real-world multilingual search behavior.

## Why This Works (Mechanism)

**Mechanism 1: Disentangling lexical and semantic evaluation via dual query types (TCQ/TAQ) isolates distinct model capabilities and reveals specific weaknesses.**  
The framework generates TCQ and TAQ from the same passage pool. TCQ mandates verbatim inclusion of passage terminology, testing exact term matching. TAQ replaces terms with context-derived descriptions, forcing pure semantic retrieval. The performance gap between the two quantifies a model’s dependency on surface-form lexical overlap versus deeper conceptual understanding. Evidence shows BM25 excels on TCQ but fails on TAQ, while Llama-Embed-Nemotron minimizes this gap, demonstrating balanced capability.

**Mechanism 2: Hybrid cross-lingual translation (preserving English terms in TCQ, fully translating TAQ) reflects real-world user query behavior and yields a practically useful, high-signal evaluation for multilingual aerospace IR.**  
For TCQ, technical terms identified by the dictionary are kept in English while surrounding text is translated; for TAQ, the entire query is translated. This exploits the domain convention where engineers retain English for canonical technical concepts (e.g., "propellant"), simplifying TCQ retrieval while keeping TAQ a true cross-lingual semantic test. Empirical results show TCQ performance substantially higher than TAQ across languages, validating the strategy’s alignment with user behavior.

**Mechanism 3: Augmenting LLM-based query generation with Chain-of-Density (CoD) and a Self-Reflection loop enforces hard constraints, improves information density, and significantly boosts synthetic query quality and adherence to intent.**  
CoD incrementally adds key entities from the source passage across three steps. At each step, Self-Reflection critiques the query against eight constraints (e.g., answerability, no external knowledge, format) and prompts iterative refinement. This structured, self-correcting process produces precise, passage-anchored queries. G-Eval scores show large models (GPT-5, DeepSeek-V3) achieve significant gains in constraint adherence with Self-Reflection, while small models benefit less.

## Architecture Onboarding
- **Component map:** NTRS PDFs -> DocLayout-YOLO -> text extraction -> recursive token chunking (RT100-20) -> passage pool -> terminology dictionary (regex + multi-stage filter) -> passage filtering (≥5 terms) -> LLM intent classifier -> intent-specific pools -> k-medoids clustering (k=5) -> 100 representative passages per intent -> query generation (TCQ/TAQ with CoD + Self-Reflection) -> cross-lingual extension (hybrid TCQ, full TAQ) -> validation suite (intent F1, G-Eval, back-translation similarity, terminology check).

- **Critical path:** The pipeline’s throughput and quality are bottlenecked by LLM API calls (for intent classification, term description, CoD query generation, translation). Preprocessing (terminology extraction, passage filtering) reduces the volume from ~2.4M to 500 passages, alleviating but not eliminating the LLM dependency.

- **Design tradeoffs:**  
  - Heuristic vs. Coverage: The "≥5 distinct terminology" filter and fixed k=5 clustering are heuristics to ensure technical density and manageable scale, trading off potential inclusion of valid but less term-dense passages.  
  - Hybrid Translation Fidelity vs. Realism: Preserving English terms in TCQ maximizes alignment with user behavior but creates an easier task; full TAQ translation is harder but may introduce translation errors that confound semantic evaluation.  
  - Synthetic vs. Natural Queries: The CoD/Self-Reflection process enforces constraints but may produce overly "perfect" queries, lacking the ambiguity, verbosity, or multi-hop nature of real user queries.

- **Failure signatures:**  
  - **Terminology Dictionary:** High-frequency generic words (e.g., "system") passing τ≤3.5 indicate a flawed threshold, inflating dictionary size with noise.  
  - **Intent Classification:** Low per-intent F1 (especially for "Comparison" and "Numerical") suggests the classifier prompt is insufficiently discriminative for nuanced aerospace intents.  
  - **Query Generation:** G-Eval scores for "No External Knowledge" or "Format Compliance" near the minimum (1.0) for models *with* Self-Reflection indicate the constraint enforcement loop is failing.  
  - **Cross-lingual:** TCQ back-translation cosine similarity < 0.90 or automated checks finding *any* translated terminology in TCQ output would violate the hybrid rule.

- **First 3 experiments:**  
  1. **Terminology Dictionary Sanity Check:** Manually sample 100 dictionary terms. Verify they are genuinely aerospace-specific (e.g., "propellant", "airfoil") and not overly generic. Check doc frequency distribution for long-tail behavior.  
  2. **Intent Classifier Baseline:** Run the classifier on 100 passages and have a *second* domain expert label them. Compute Cohen's Kappa to measure inter-annotator agreement, complementing the single-expert F1 in the paper.  
  3. **CoD/Self-Reflection Ablation:** For a small sample (N=50 passages), generate queries with: (a) naive single-prompt, (b) CoD only, (c) CoD+Self-Reflection. Score all with G-Eval to directly validate the claimed incremental benefit of the full method.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How well does the STELLA benchmark generalize to diverse aerospace corpora beyond NTRS, such as proprietary industry documents or institutional reports from other space agencies?
- **Basis in paper:** [explicit] The authors state that STELLA relies solely on NTRS as a single public repository, which may not fully represent proprietary documents or materials from other institutions (Limitations section, p. 15).
- **Why unresolved:** The benchmark's design—including document parsing, terminology extraction, and query generation—is optimized for NTRS's structure and conventions. Different sources might have varying layouts, terminology density, or content styles, potentially affecting retrieval performance and model rankings.
- **What evidence would resolve it:** Constructing comparable IR evaluation sets from alternative aerospace corpora (e.g., ESA reports, patent databases, or anonymized corporate archives) and evaluating whether the same model performance trends hold. Cross-corpus consistency checks would reveal if STELLA's insights are robust or source-specific.

### Open Question 2
- **Question:** Do synthetic queries in STELLA accurately reflect the complexity and diversity of real-world aerospace information needs, particularly for ambiguous, multi-hop, or unanswerable queries?
- **Basis in paper:** [explicit] The authors acknowledge that synthetic generation cannot fully emulate real user queries, which may be ambiguous, require combining multiple documents, or be unanswerable (Limitations section, p. 15). Future work includes adding multi-hop queries.
- **Why unresolved:** Current queries are derived from single passages via controlled LLM prompts, which likely underrepresent the uncertainty, partial knowledge, and iterative reasoning seen in actual engineering or research workflows.
- **What evidence would resolve it:** Collecting and annotating real query logs from aerospace professionals (e.g., NASA engineers, industry R&D staff) and comparing query distributions (intent, length, complexity) with STELLA. Additionally, evaluating model performance on both synthetic and real-world query sets to assess correlation.

### Open Question 3
- **Question:** How sensitive are STELLA's results to its heuristic construction choices, such as the "at least five terminology items" filter, the fixed five intent categories, and the k=5 clustering parameter?
- **Basis in paper:** [explicit] The authors note that heuristic assumptions—like the five-term filter, the intent taxonomy, and k=5 for clustering—may oversimplify real-world information needs (Limitations section, p. 15).
- **Why unresolved:** These parameters were selected empirically without systematic ablation. Different thresholds or more granular intents could drastically change the candidate passage pool, query generation, and ultimately the benchmark's difficulty and model comparisons.
- **What evidence would resolve it:** Conducting sensitivity analyses: varying the terminology threshold (e.g., 3–7 terms), testing alternative intent schemas (e.g., 7–10 intents), and adjusting k in clustering. Measuring changes in retrieval metrics, model rankings, and the TCQ-TAQ gap would clarify which design decisions are most critical.

### Open Question 4
- **Question:** Is the specificity filtering threshold (τ≤3.5) for terminology extraction universally appropriate across all aerospace subdomains, or does it require domain-specific tuning to balance term relevance and coverage?
- **Basis in paper:** [inferred] The threshold was chosen empirically to remove generic words while retaining core technical terms, but the paper does not validate its effectiveness across the ten NTRS categories (e.g., Aeronautics vs. Social Sciences). The wordfreq-based score may not equally capture domain-specificity in subfields with different common-language overlap.
- **Why unresolved:** An overly strict threshold might exclude nuanced but important terms in some subdomains, while a lenient one could admit generic words, diluting the terminology dictionary's quality. This directly impacts candidate passage selection and query generation.
- **What evidence would resolve it:** Evaluating term precision/recall against expert-annotated gold-standard terminology sets for each NTRS category. Experimenting with alternative τ values (e.g., 3.0–4.0) and assessing downstream effects on retrieval performance and the lexical-semantic gap.

### Open Question 5
- **Question:** How do alternative cross-lingual query formulations—such as full translation of terms, transliteration, or mixed-language strategies—affect retrieval effectiveness compared to the hybrid terminology-preservation approach?
- **Basis in paper:** [explicit] The authors implement hybrid translation (preserving English terms in TCQ) based on assumed real user behavior but note this may not cover all patterns, such as users who translate or transliterate terms (Limitations section, p. 15).
- **Why unresolved:** The benchmark only evaluates one translation strategy per query type. In practice, multilingual aerospace users may employ varying strategies based on language proficiency, term familiarity, or tool support, leading to different retrieval outcomes.
- **What evidence would resolve it:** Generating multiple cross-lingual variants of the STELLA queries (fully translated terms, fully transliterated terms, hybrid with different term-preservation rules) and measuring model performance across these variants. User surveys in target languages could also identify prevalent query patterns to inform more diverse evaluation sets.

## Limitations
- Synthetic queries may lack the natural ambiguity, verbosity, or multi-hop complexity of real user queries, potentially overestimating model performance.
- The terminology dictionary specificity threshold (τ≤3.5) is heuristic; without expert validation, generic words may leak, diluting domain sensitivity.
- The hybrid cross-lingual strategy assumes non-English engineers retain English technical terms—this lacks empirical query-log evidence and may not hold for all languages/domains.

## Confidence
- **TCQ/TAQ disentanglement:** High. Strong empirical gap analysis and clear mechanistic design isolate lexical vs. semantic evaluation.
- **Hybrid cross-lingual strategy:** Medium. Logical alignment with domain conventions, but absence of real user query data limits generalizability.
- **CoD/Self-Reflection utility:** Medium. G-Eval improvements are model-dependent (large LLMs only); cost-benefit for smaller models remains unclear.
