# Mitigating Hallucination on Hallucination in RAG via Ensemble Voting

## Quick Facts
- **arXiv ID:** 2603.27253  
- **Source URL:** https://arxiv.org/abs/2603.27253  
- **Reference count:** 40  
- **Primary result:** VOTE-RAG introduces a training-free two-stage ensemble voting process that effectively mitigates “hallucination on hallucination” in RAG, achieving comparable or better performance than state‑of‑the‑art methods on six benchmarks while using a fixed LLM call budget and being fully parallelizable.

## Executive Summary
Retrieval‑augmented generation (RAG) suffers from “hallucination on hallucination,” where errors in retrieval amplify LLM hallucinations. This paper presents VOTE-RAG, a simple yet powerful framework that addresses both retrieval and generation failures without any training. VOTE-RAG employs two parallel voting stages: (1) Retrieval Voting aggregates diverse queries from multiple agents to broaden the retrieved evidence pool, and (2) Response Voting collects independent answers from the same retrieved set and selects the majority vote. Evaluated on six QA benchmarks, VOTE-RAG matches or exceeds complex iterative frameworks like DRAG and Self‑RAG, scales predictably with the number of agents, and avoids the “problem drift” that can degrade serial debate approaches. Its fixed LLM call budget (2 N) and embarrassingly parallel design make it efficient and robust.

## Method Summary
VOTE-RAG operates in two stages. First, **Retrieval Voting**: given an input question *x*, *N* independent LLM agents each generate a distinct query *qᵢ*. The union of all queries forms *Q̂*, which is used to retrieve top‑k documents from the corpus *C* via a retriever *R*, yielding an aggregated document set *Ĉ_Q*. Second, **Response Voting**: the same *N* agents (or new copies) independently produce answers *yᵢ* conditioned on *x* and *Ĉ_Q*. The final answer *ŷ* is determined by majority vote over the *yᵢ*. No training is required; the LLM and retriever are used as‑is. The total LLM call count is fixed at 2 *N* (e.g., 10 calls with 5 agents).

## Key Results
- VOTE‑RAG achieves comparable or superior exact match (EM) and token‑level F1 scores on six benchmarks (NQ, TriviaQA, PopQA, 2WikiMultihopQA, HotpotQA, StrategyQA) versus state‑of‑the‑art frameworks such as DRAG, Self‑RAG, and Iter‑RetGen.
- With 5 agents (10 LLM calls), TriviaQA EM reaches 61.10 vs. Naive RAG 60.80; HotpotQA EM 29.80 vs. DRAG 30.80 (comparable performance).
- Performance improves monotonically as the number of agents increases, while DRAG’s performance degrades at higher agent counts. The parallel design avoids “problem drift” and yields lower latency.

## Why This Works (Mechanism)
### Retrieval Voting
**Claim:** Mitigates retrieval failure by broadening the evidence pool through diversified queries.  
**Mechanism:** Multiple independent retrieval agents generate distinct queries for the same input; the aggregated query set *Q̂* is used to retrieve a combined document set, increasing the chance of covering relevant facts missed by a single query.  
**Core assumption:** Different agents produce sufficiently diverse queries that lead to non‑overlapping relevant documents.  
**Evidence anchors:** Abstract and Section IV‑A describe parallel query generation (*qᵢ = Mₐᵢ(x)*) and union aggregation (*Q̂ = ∪{qᵢ}*).  
**Break condition:** If all queries are semantically identical, the retrieved document set offers no coverage advantage over a single query.

### Response Voting
**Claim:** Mitigates generation‑stage hallucination by filtering idiosyncratic errors via majority vote over independent answer candidates.  
**Mechanism:** All response agents receive the identical retrieved set *Ĉ_Q* and independently generate answers *yᵢ*. The final answer *ŷ* is the majority vote string, which statistically favors the correct answer when individual errors are independent and below 50%.  
**Core assumption:** Individual agent errors on the same evidence are independent and have expected error rate *p* < 0.5.  
**Evidence anchors:** Abstract and Section IV‑B detail symmetric answer generation (*yᵢ = Mₐᵢ(x, Ĉ_Q)*) and aggregation. Section IV‑C provides a formal bound: *Pmaj_err(N, p) ≤ exp(−2N(½−p)²)*.  
**Break condition:** If agent errors are highly correlated (correlation *ρ* → 1) or *p* ≥ 0.5, majority voting yields little benefit and may amplify errors.

### Parallelism Avoids Problem Drift
**Claim:** The fully parallel, non‑iterative architecture avoids “problem drift” (error accumulation across sequential interactions) inherent in serial debate frameworks.  
**Mechanism:** Both voting stages are embarrassingly parallel with no feedback loops; all agents operate on identical inputs and aggregate only at the end, eliminating sequential error propagation.  
**Core assumption:** Iterative, adaptive debate processes (e.g., DRAG) risk drifting from the correct solution path through multi‑step interactions.  
**Evidence anchors:** Abstract states “avoids the ‘problem drift’ risk”; Section VI‑B directly compares VOTE‑RAG with DRAG, noting DRAG’s performance degrades at *N*=7 while VOTE‑RAG improves.  
**Break condition:** If the aggregation function introduces systematic bias or the fixed parallel budget is insufficient for task difficulty, the advantage over a tuned iterative method may not hold.

- **Standard RAG Pipeline & Its Failure Modes**: Understanding the two‑stage RAG process (retrieval *Cₓᵏ = R(x, C, k)* and generation *y = M(x, Cₓᵏ)*) clarifies where hallucinations originate. *Quick check:* “In the standard RAG equations, what are the two distinct stages where hallucination can be introduced?”
- **Ensemble Methods & Majority Voting Theory**: The framework relies on ensemble voting; concepts like independent error, correlation *ρ*, and the Condorcet Jury Theorem underpin the analysis. *Quick check:* “According to the paper’s sketch, what two parameters (besides *N*) most directly determine the majority‑vote failure probability?” (Answer: error rate *p* and correlation *ρ*).
- **Parallelism vs. Sequential Iteration in System Design**: Choosing parallel aggregation over iterative debate avoids latency and drift. *Quick check:* “What is the primary operational risk of a multi‑round, adaptive debate framework (like DRAG) that VOTE‑RAG explicitly avoids?” (Answer: problem drift).

## Architecture Onboarding
**Component map**  
Original Input (*x*) → Retrieval Agents (*N* copies) → Query Aggregator → Retriever (*R*, with corpus *C*) → Response Agents (*N* copies) → Voting Aggregator → Final Answer (*ŷ*).

**Critical path**  
*x* → (Parallel: *qᵢ = Mₐᵢ(x)* for *i*=1..*N*) → *Q̂ = ⋃{qᵢ}* → *Ĉ_Q = R(Q̂, C, k)* → (Parallel: *yᵢ = Mₐᵢ(x, Ĉ_Q)* for *i*=1..*N*) → *ŷ = majority\_vote(y₁,…,yₙ)*.

**Design tradeoffs**  
- Simplicity & predictability vs. adaptivity: Fixed parallel aggregation avoids iterative refinement but gains no dynamic adjustments.  
- Diversity volume vs. redundancy: More agents increase coverage and robustness, but linearly increase LLM call cost.  
- Symmetric evidence sharing: All response agents see identical *Ĉ_Q*, simplifying design but assuming the retrieved set is sufficient.

**Failure signatures**  
- Homogeneous agents: Low entropy in queries or answers indicates lack of diversity, nullifying voting benefits.  
- Retrieval pool insufficiency: If *Ĉ_Q* lacks gold documents, answer generation cannot succeed.  
- Systematic LLM bias: Majority vote may reinforce consistent biases present in the base LLM.  
- Tie conditions: Even agent counts or split votes require a tie‑breaking strategy (e.g., random selection).

**First 3 experiments**  
1. **Ablation on agent count (N):** Vary *N* (e.g., 3, 5, 7) on HotpotQA/TriviaQA to verify performance scaling and contrast with DRAG’s degradation.  
2. **Comparison against complex frameworks:** Evaluate VOTE‑RAG (*N*=3) against DRAG, Self‑RAG, Iter‑RetGen on all six benchmarks.  
3. **Efficiency & latency analysis:** Measure average retriever/LLM calls and wall‑clock time under parallel inference vs. DRAG’s serial debate rounds.

## Open Questions the Paper Calls Out
- How can we systematically generate and measure query diversity among multiple retrieval agents to maximize coverage and minimize bias in the retrieved document pool? (Basis: the paper assumes diverse queries but does not define or quantify diversity.)  
- For response voting, how can we aggregate answers that are semantically equivalent but lexically different, moving beyond exact string match? (Basis: the paper’s intuition mentions semantic clustering but does not implement or evaluate it.)  
- How does correlation among agents (using the same LLM and prompt) degrade the benefits of ensemble voting, and what techniques can effectively promote agent independence? (Basis: theoretical analysis accounts for correlation but the implementation likely produces correlated outputs.)  
- Does VOTE‑RAG generalize to non‑QA RAG tasks—such as summarization or dialogue—where the output structure and retrieval needs differ? (Basis: evaluation is limited to six QA datasets.)

## Limitations
- **Prompt engineering gap:** Exact prompts for query/answer generation are undisclosed; implementation may diverge, affecting query diversity and answer quality.  
- **Voting specification ambiguity:** Majority vote details (string vs. semantic clustering, tie‑breaking) are vague, potentially causing brittle aggregation.  
- **Correlated failures:** Using identical models and prompts may produce correlated agent errors, weakening voting benefits; additionally, if the retrieval pool systematically omits gold documents, response voting cannot recover.

## Next Checks
1. **Prompt diversity audit:** Run VOTE‑RAG with *N*=5 on 100 random questions; compute average cosine similarity of query embeddings (e.g., using all‑MiniLM‑L6‑v2). If average > 0.8, diversity is likely insufficient.  
2. **Voting implementation fidelity:** Implement both raw‑string majority and a semantic‑clustering variant (e.g., BERTScore threshold). Compare EM/F1 on a validation subset; large deltas (> 2 points) would indicate sensitivity to unspecified aggregation rules.  
3. **Error correlation analysis:** For a sample of failures, measure pairwise agreement among incorrect answers via n‑gram overlap or embedding similarity. High correlation (*ρ* > 0.7) would violate the independence assumption and explain vote failures.
