# Learning Rewards, Not Labels: Adversarial Inverse Reinforcement Learning for Machinery Fault Detection

## Quick Facts
- **ArXiv ID:** 2602.22297
- **Source URL:** https://arxiv.org/abs/2602.22297
- **Reference count:** 17
- **Primary result:** Achieved earliest robust fault detection on HUMS2023 at Day 22 (file #163), beating the ground truth by 2 days and outperforming all baselines, with consistent post-detection stability (~65% anomaly rate) across three bearing datasets (HUMS2023, IMS, XJTU-SY).

## Executive Summary
The paper tackles a key limitation in reinforcement learning (RL) for machinery fault detection (MFD): existing approaches treat it as a static contextual bandit problem, ignoring the sequential nature of degradation. They propose an Adversarial Inverse Reinforcement Learning (AIRL) framework that learns a reward function directly from healthy operational sequences—no fault labels required. The discriminator’s output serves as an interpretable anomaly score. On the HUMS2023 dataset, the method detects faults earlier (Day 22) than the official ground truth (Day 24) and outperforms baselines, including a contextual bandit RL method that completely fails. It also shows robust post-detection consistency and generalizes to two additional bearing datasets.

## Method Summary
The approach formulates MFD as an offline inverse reinforcement learning problem. States are fixed-length windows of normalized vibration signals. Because control actions are unavailable, the next state is used as a “proxy action” to construct transitions (s_t, a_t=s_{t+1}, s_{t+1}). An AIRL discriminator with a structured reward function (r_θ(s,a) + γV_φ(s') - V_φ(s) - log π(a|s)) is trained to distinguish healthy (expert) transitions from those generated by a policy π. After training, the discriminator’s probability that a transition is healthy is averaged over a test trajectory and inverted to produce an anomaly score. Thresholding (e.g., Otsu’s method) then determines fault onset. The entire pipeline operates solely on normal training data, avoiding manual label engineering.

## Key Results
- Earliest detection on HUMS2023: Day 22 (file #163), two days before official ground truth (Day 24).
- Outperformed all baselines, including a contextual bandit RL method that failed to detect any fault.
- Superior post-detection consistency: anomaly rate stabilizes around 65% after onset; results consistent across IMS and XJTU-SY datasets.

## Why This Works (Mechanism)
1. **Interpretable reward via adversarial discriminator:** The AIRL framework structures the discriminator D(s,a,s') = σ(r_θ(s,a) + γV_φ(s') - V_φ(s) - log π(a|s)). This forces the learned term r_θ(s,a) to represent a robust health score that disentangles from transition dynamics. The discriminator’s confidence directly indicates alignment with normal machine behavior, providing an interpretable anomaly metric.  
   *Evidence: paper’s Eq.1 and Section 2.2; neighboring IRL papers confirm methodology.*  

2. **Sequential modeling respects degradation dynamics:** By treating MFD as an IRL problem with non-zero discount γ, the framework evaluates entire transition sequences rather than isolated states. This captures gradual degradation that contextual bandits miss. The proxy action a_t = s_{t+1} creates a valid MDP transition.  
   *Evidence: abstract and Section 2.1; contrast with prior CB approaches.*  

3. **Trajectory averaging yields stable anomaly signal:** The anomaly score for a trajectory τ is defined as Score(τ)=1− (1/T)∑_t D(s_t,a_t,s_{t+1}). This accumulates “surprise” across transitions, making the signal robust to noise and enabling early detection before individual spikes.  
   *Evidence: Section 2.3; superior post-detection consistency reported.*

## Foundational Learning
- **Inverse Reinforcement Learning (IRL):** Learns a reward function from expert demonstrations instead of a policy. *Why needed:* Enables learning from healthy data without fault labels; reward can score deviations. *Quick check:* How does IRL differ from standard RL, and why is reward learning specifically advantageous for fault detection with only healthy data?  

- **State-Only Imitation Learning (SOIL) & Proxy Actions:** Adapts IRL to settings without recorded control actions by defining a proxy action (e.g., next state). *Why needed:* Industrial datasets typically lack actions; proxy actions allow using standard AIRL. *Quick check:* Why is a proxy action necessary, and what assumption does it make about the system?  

- **Adversarial Discriminator as Anomaly Scorer:** In AIRL, the discriminator outputs the probability that a transition comes from the expert distribution. *Why needed:* This probability is directly reused as an anomaly score without additional classifiers. *Quick check:* What is the purpose of the discriminator’s structural form in AIRL, and how does it support its use as an anomaly score?

## Architecture Onboarding
- **Component map:**  
  Training: Healthy Data -> State Segmenter -> Transition Sampler -> Expert Transitions ->\
            Generator π -> Generated Transitions ->\
            Discriminator D <-> updates π and D.  
  Inference: Test Data -> State Segmenter -> Transition Sampler -> Test Transitions ->\
            Discriminator D (trained) -> Anomaly Scorer -> Thresholding -> Fault Detection.  

- **Critical path:** Healthy data → window segmentation → create (s_t, a_t=s_{t+1}, s_{t+1}) transitions → train AIRL discriminator vs. generator → for test trajectory, compute D for each transition → average → threshold → declare fault onset.

- **Design tradeoffs:**  
  - Window length: trade-off between capturing high-frequency faults and response delay.  
  - Proxy action definition: using s_{t+1} assumes stationarity between windows; major load shifts may cause spurious anomalies.  
  - Thresholding: Otsu assumes bimodal scores; may fail under non-stationary conditions.

- **Failure signatures:**  
  - High false positives: discriminator overconfident on healthy data due to incomplete training coverage.  
  - No detection: discriminator never learns meaningful boundary (accuracy ~50%).  
  - Late detection: window too long or threshold too conservative; scores rise but threshold not crossed.

- **First 3 experiments:**  
  1. Discriminator sanity: verify separation of D scores on held-out healthy vs. artificially corrupted transitions.  
  2. Trajectory scoring validation: on labeled run-to-failure test, check anomaly score monotonic trend after known fault onset.  
  3. Baseline replication: implement contextual bandit RL (CTQN) with γ=0, train on same healthy data, confirm failure to detect on HUMS2023.

## Open Questions the Paper Calls Out
1. **Multi-sensor fusion:** How to extend the framework to effectively incorporate multiple heterogeneous sensors? The current work uses only a single accelerometer. Challenges include alignment, differing modalities, and variable reliability.  
2. **Uncertainty-aware thresholding:** How to integrate methods that adapt thresholds under varying operating conditions to reduce false alarms? Current static thresholding (Otsu, K-means) may not handle non-stationarity.  
3. **Theoretical validity of proxy actions:** Does using the next state as a proxy action preserve the theoretical guarantees of IRL, and how does this approximation affect learned reward quality? No analysis is provided.  
4. **Interpretability of learned reward:** What specific features or temporal patterns does the discriminator’s reward encode, and how can these be translated into actionable diagnostics for engineers? The paper uses the reward only as an anomaly score without examining its semantics.

## Limitations
- Hyperparameter values (window length, discount γ, network sizes) are undisclosed, hindering reproducibility.  
- SOIL implementation details are ambiguous: how the policy π is initialized/updated when actions are proxy states, and how log π is computed for expert transitions.  
- Thresholding assumes bimodal score distributions and may not adapt to changing operating conditions, risking false alarms.

## Confidence
- **Learned reward as interpretable anomaly score**: Medium (grounded in AIRL theory but empirical support limited by missing details).  
- **Sequential modeling enables earlier detection**: Medium‑High (contextual bandit baseline failed; direct comparison limited to one dataset).  
- **Generalization across datasets**: Medium (results on three bearing datasets are promising, but lack statistical testing and domain diversity).
