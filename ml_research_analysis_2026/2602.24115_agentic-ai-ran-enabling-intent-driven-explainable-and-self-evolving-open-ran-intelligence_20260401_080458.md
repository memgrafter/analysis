# Agentic AI-RAN: Enabling Intent-Driven, Explainable and Self-Evolving Open RAN Intelligence
## Quick Facts
- arXiv ID: 2602.24115
- Source URL: https://arxiv.org/abs/2602.24115
- Reference count: 20
- Primary result: Agentic AI controllers reduce average resource usage by 8.83% across eMBB, URLLC, and mMTC slices, improve URLLC slice admission accuracy to 91%, and lower URLLC p99 latency to 7.8 ms via Non-RT LLM coordination.

## Executive Summary
Open RAN's multi-tenant, multi-objective management introduces safety and auditability challenges. This work introduces agentic AI controllers with primitives—explicit planning over O-RAN skills, multi-timescale memory and evidence, and self-management gates—applied across Non-RT RIC, Near-RT RIC, and dApps. In multi-cell simulations, the full agentic framework reduces average resource usage by 8.83% across eMBB, URLLC, and mMTC slices. Adding a Non-RT LLM coordinator improves slice admission accuracy (e.g., URLLC to 91%) and lowers tail latency (e.g., URLLC p99 to 7.8 ms). Compared to conventional RL baselines and ablations, it minimizes SLA violations and tail latency, with transparent trade-offs in control overhead.

## Method Summary
The method implements agentic AI controllers in a simulated O-RAN environment (6 O-RUs, 12 cells, 20 UEs, free-space path loss, NR N77/N78 bands). The agentic loop parses operator intents into structured goals, synthesizes short sequences of verifiable O-RAN skills using episodic memory, executes them incrementally with self-management gates (checking SLA risk, uncertainty, and budgets), observes compact KPM/KQI summaries, and reflects to update memory and evidence. Evaluation compares the full framework against ablations (No-Plan, No-Gate, No-Memory, etc.) and a Deep Q-Learning baseline. A Non-RT LLM coordinator runs every minute to tune cross-slice budgets based on Near-RT summaries. Metrics include resource usage, SLA violation rate, p99 latency, slice admission accuracy, and control overhead (E2 bytes, action count).

## Key Results
- Average resource usage reduced by 8.83% across eMBB, URLLC, and mMTC slices.
- Non-RT LLM coordination improves URLLC slice admission accuracy to 91% and lowers p99 latency to 7.8 ms.
- The framework minimizes SLA violations and tail latency versus conventional RL baselines, with quantifiable trade-offs in control overhead.

## Why This Works (Mechanism)
### Mechanism 1
Claim: A timing-aware Plan-Act-Observe-Reflect loop, aligned with O-RAN control layers (Non-RT, Near-RT, RT), improves safety and auditability over monolithic RL xApps by enabling explicit multi-step interventions with bounded risk. Mechanism: The agent parses operator intents into machine-checkable goals, synthesizes short sequences of "skills" (bounded O-RAN interface calls), executes them incrementally with self-management gates (checking SLA risk, uncertainty, budgets), and observes compact KPM/KQI summaries before reflecting. This separates long-horizon deliberation (Non-RT) from fast execution (Near-RT/RT). Core assumption: Explicit planning over reusable, verifiable skills reduces SLA violations and tail latency compared to reactive policies, provided plan synthesis and gating respect layer-specific deadlines. Evidence anchors: [abstract] and [section IV.A] detail the timed loop and skill sequences; corpus shows weak direct evidence but neighboring papers mention multi-scale frameworks. Break condition: If plan synthesis latency or gate evaluation overhead violates worst-case control-loop latency budgets (e.g., Near-RT 100 ms–1 s), the mechanism fails.

### Mechanism 2
Claim: Representing O-RAN control actions as "skills"—thin, reversible wrappers around A1/E2/E2SM primitives with explicit preconditions, effects, and rollback—enables safe, vendor-agnostic, composable interventions and conflict handling. Mechanism: Each skill is a structured tool with bounded actuation scope and a compensating rollback. The agent executes short skill sequences incrementally, observing outcomes and rolling back if guards fail. Local scoping allows conflict detection without centralized arbitration. Core assumption: Bounded, reversible skills prevent irreversible state damage and allow incremental commitment, necessary for auditability and graceful degradation under uncertainty. Evidence anchors: [section IV.B] defines skills as "thin, verifiable wrappers"; [section IV.D] describes gates triggering rollback; corpus limited. Break condition: If rollback procedures are incomplete or too slow, or skill preconditions frequently violated due to stale context, safety degrades.

### Mechanism 3
Claim: Multi-timescale memory (short-term caches, episodic logs, long-term knowledge) and decision-level evidence records (linking goals, context, actions, outcomes) enable data-efficient adaptation and auditable control loops. Mechanism: Memory stores compact summaries across O-RAN timescales; retrieval informs planning under domain shift. Evidence is emitted at each commit, creating a provenance chain for audit without raw data exposure. Reflection updates memory and refines future gates. Core assumption: Memory retrieval reduces reliance on costly retraining and improves generalization; evidence satisfies regulatory and operational audit requirements. Evidence anchors: [section IV.C] outlines memory layers and evidence; [abstract] states explainable/auditable control; corpus shows related work on LLM-audit trails but not integrated loops. Break condition: If memory corruption or retrieval latency exceeds planning cycles, or evidence records are inconsistent/incomplete, auditability and adaptive planning fail.

## Foundational Learning
- **O-RAN control loop timing hierarchy**: Non-RT (minutes/hours), Near-RT (sub-second), RT (microseconds). Why needed: Agentic primitives must respect strict deadlines per layer; misalignment causes deadline misses. Quick check: What are typical max latency budgets for A1 and E2 updates?
- **Skill-based control abstraction vs monolithic RL policies**: Skills decompose control into verifiable, reusable units (e.g., "capping PRB allocation"), enabling safe sequencing and rollback. Monolithic policies lack composability. Quick check: How does a "skill" for handover pinning differ from a raw RL action outputting a handover threshold?
- **Multi-objective optimization with explicit budgets and constraints**: Operator intents combine performance, cost, and regulatory goals. Agentic gates trade these off dynamically. Quick check: In the simulation, what budget constraints (e.g., B in goal g=(O,C,B)) were adjusted by the Non-RT LLM coordinator?

## Architecture Onboarding
- Component map: Non-RT RIC/SMO (LLM coordinator, digital twin, long-term memory/evidence) -> Near-RT RIC (agentic xApps, short-term memory, active KPM sampler) -> RT/dApps (bounded micro-adjustments) via A1 (Non-RT→Near-RT) and E2/E2SM (Near-RT→RT) interfaces.
- Critical path: Intent -> structured goal -> (Non-RT) plan skills using digital twin/memory -> A1 policy -> (Near-RT) sequence and gate skills -> E2 actions -> (RT) micro-adjust -> observe KPM/KQI -> reflect & update memory/evidence.
- Design tradeoffs: Control overhead vs QoS (active KPM sampling improves SLA but increases E2 bytes/energy); LLM reasoning frequency (minute-level avoids RT latency but may miss fast changes); memory size vs retrieval latency (larger logs help reuse but risk gating delays).
- Failure signatures: Gate failures frequent (rt > α, ut > β, bt > B) → SLA violations or rollbacks; memory retrieval timeout → fallback to reactive default; evidence log gaps → audit failures or inconsistent rollback.
- First 3 experiments: 1) Ablation: No-plan vs full agentic to quantify SLA/tail latency improvement from multi-step planning. 2) Ablation: No-gate vs full agentic to measure SLA violations and instability without self-management. 3) LLM coordination on/off to compare slice admission accuracy and resource usage.

## Limitations
- Key implementation details omitted: simulation framework (ns-3 vs. srsRAN), exact skill definitions (preconditions, rollback), DQL hyperparameters, memory retrieval algorithm, gating thresholds, traffic model, E2 budget for active KPM, LLM input pipeline.
- Evaluation limited to simulation; real-world issues (vendor heterogeneity, deadline misses) unvalidated; LLM coordinator's non-determinism and operational cost unexplored; auditability claims lack empirical operator validation.
