# IWP: Token Pruning as Implicit Weight Pruning in Large Vision Language Models

## Quick Facts
- **arXiv ID:** 2604.00757
- **Source URL:** https://arxiv.org/abs/2604.00757
- **Reference count:** 40
- **Primary result:** IWP achieves state‑of‑the‑art token pruning on LVLMs, preserving >97% accuracy at ~35% token budget on LLaVA‑OneVision‑7B and demonstrating superior computational efficiency.

## Executive Summary
Large Vision-Language Models (LVLMs) are computationally expensive due to the large number of visual tokens. This paper introduces IWP, a training‑free token pruning framework that reinterprets softmax attention as an implicit linear layer whose weights are sums of rank‑1 outer products of key‑value pairs. By framing pruning as selecting a subset of these rank‑1 updates, IWP defines an importance score combining information magnitude and duplication, and employs Progressive Chunked Maximal Marginal Relevance for efficient selection. Experiments on image and video benchmarks with LLaVA‑OneVision‑7B and Qwen2.5‑VL‑7B show that IWP surpasses prior methods, preserving over 97% accuracy at ~35% token budget while reducing generation time and VRAM usage.

## Method Summary
IWP is a training‑free token pruning framework designed to reduce the computational cost of Large Vision‑Language Models (LVLMs) without sacrificing performance. It operates on a pretrained LVLM at a specific layer (default layer 4) and reformulates softmax attention as an implicit linear transformation whose weight matrix \(W_N = \sum_i \phi(k_i)^\top v_i\) is built from rank‑1 outer products of each token’s key‑value pair. Pruning is then equivalent to selecting a subset of these rank‑1 updates that best approximates \(W_N\). The method first computes an aggregated query \(q\) from all text‑token queries in the same layer (by default, the mean). Then, for each visual token, it calculates an information magnitude \(Score_i = \kappa(q, k_i) \|v_i\|^2\) using the exponential kernel \(\kappa\). Token redundancy is quantified by the dual‑form similarity \(S_{ij} = \frac{v_i \cdot v_j}{\|v_i\|\|v_j\|} \cdot \frac{\kappa(k_i,k_j)}{\sqrt{\kappa(k_i,k_i)\kappa(k_j,k_j)}}\). Finally, Progressive Chunked Maximal Marginal Relevance (PC‑MMR) iteratively selects tokens: starting from an initial chunk size \(b_0\), it picks the top‑\(b\) unselected tokens by current score, adds them to the selected set, and for each remaining token multiplies its score by \(\max(0.01, 1 - \lambda \cdot s_{\text{max}})\), where \(s_{\text{max}}\) is the maximum similarity to any token in the newly selected chunk. The chunk size grows by a factor \(g\) (default 2) each iteration until the target token budget is met. The selected subset is retained for all subsequent layers, achieving substantial reductions in generation time and peak VRAM while preserving task accuracy.

## Key Results
- On LLaVA‑OneVision‑7B with a 35.3% token budget, IWP achieves 97.9% relative performance, exceeding the next best method (PACT, 97.3%).
- At an aggressive 11.1% token budget, IWP attains 89.5% accuracy on ScienceQA, significantly outperforming prior works.
- IWP reduces generation time and peak VRAM more effectively than baselines while maintaining accuracy, and generalizes robustly across different model architectures and video tasks.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Standard softmax attention can be reinterpreted as an implicit linear transformation whose weight matrix is the sum of rank‑1 outer products of kernel‑mapped key and value pairs.
- **Mechanism:** Using matrix associativity and the kernel trick, attention output = ϕ(q)η_N(q)W_N, where W_N = Σ_i ϕ(k_i)^T v_i. Each token contributes a rank‑1 update ∆W_i = ϕ(k_i)^T v_i to the dual weight.
- **Core assumption:** The exponential kernel κ is positive definite, enabling a finite feature map ϕ; the dual weight W_N accurately represents the attention operation.
- **Evidence anchors:**
  - [abstract]: "reformulates softmax attention as an implicit linear layer whose weight matrix is constructed from key–value pairs."
  - [section 3.2]: Equations (4)–(6) derive the dual form from softmax attention.
  - [corpus]: Corpus evidence is weak; related papers (FastV, PACT, etc.) do not use this perspective, highlighting novelty but not direct validation.
- **Break condition:** If the kernel mapping ϕ is poorly approximated (e.g., for large hidden dimensions) or if rank‑1 updates cannot capture necessary interactions under aggressive pruning, the dual weight may diverge from true attention.

### Mechanism 2
- **Claim:** Token importance for pruning is given by a score combining a token's information magnitude (κ(q,k_i)∥v_i∥²) and its information duplication (similarity between rank‑1 updates).
- **Mechanism:** Score_i = κ(q,k_i)∥v_i∥² captures both the token’s contribution to the dual weight (via ∥v_i∥) and its effect on the normalization term (via kernel similarity with query). Duplication between tokens i and j is measured by S_ij = (cos(v_i,v_j))·(cos(ϕ(k_i),ϕ(k_j))). Maximal Marginal Relevance (MMR) then selects tokens maximizing Score while minimizing S with already selected tokens.
- **Core assumption:** The score accurately reflects the token’s impact on the attention output; the similarity metric captures redundancy in the dual weight space.
- **Evidence anchors:**
  - [section 4.1]: Equation (10) defines Score_i.
  - [section 4.2]: Equation (12) defines the dual‑form similarity S_ij.
  - [corpus]: Prior methods use attention scores (FastV, PACT) or hidden‑state cosine (DivPrune); this work introduces a dual‑form based metric.
- **Break condition:** If the aggregated query q (e.g., mean of text tokens) is unrepresentative, or if the similarity metric fails to capture true redundancy due to non‑linear interactions beyond rank‑1 updates, token selection may be suboptimal.

### Mechanism 3
- **Claim:** Efficient token selection is achieved by Progressive Chunked Maximal Marginal Relevance (PC‑MMR), which selects tokens in progressively larger chunks while applying a penalty based on maximum similarity to already selected tokens.
- **Mechanism:** Instead of sequential single‑token selection (O(N²)), PC‑MMR iteratively picks top‑k tokens from the remaining pool based on current scores. After each chunk selection, it computes the similarity matrix between the new chunk and all remaining tokens, takes the maximum similarity per remaining token as its redundancy measure, and multiplies its score by max(0.01, 1 − λ·s_max). The chunk size increases by factor g each iteration, accelerating the process.
- **Core assumption:** The max‑pooling over the new chunk approximates the full pairwise redundancy with the selected set; progressive chunking balances speed and accuracy.
- **Evidence anchors:**
  - [section 4.3]: Algorithm 1 details PC‑MMR.
  - [section 6.4]: Shows reduced generation time and VRAM vs. baselines.
  - [corpus]: Other methods use greedy (VisionZip) or clustering (PACT); PC‑MMR is a novel efficient variant.
- **Break condition:** If the chunk size grows too quickly, early selections may include many redundant tokens; if too small, overhead remains high. Max‑pooling may also miss some redundancies when multiple similar tokens are present.

## Architecture Onboarding
- Component map:
  1. **Query aggregator**: Computes a representative query q (e.g., mean of text token queries).
  2. **Score calculator**: Computes Score_i = κ(q,k_i)∥v_i∥² for each visual token.
  3. **Similarity computer**: Computes pairwise dual‑form similarity S_ij (or on‑the‑fly during selection).
  4. **PC‑MMR selector**: Manages iterative chunked selection with penalty updates.
  5. **Pruner**: Applies the selected token indices to the visual token sequence at the specified layer.
- Critical path:
  - At pruning layer l: extract keys K and values V for visual tokens.
  - Compute aggregated query q (from text tokens in the same layer).
  - Compute Score_i for all visual tokens.
  - Initialize C = ∅, U = all visual token indices.
  - While |C| < target budget: select top‑k tokens from U based on current scores, add to C, remove from U; compute similarity between new chunk and U, update U’s scores multiplicatively with max(0.01, 1 − λ·s_max); increase chunk size by g.
  - Prune visual tokens to indices C, then continue forward pass.
- Design tradeoffs:
  - **Chunk size b₀ and growth factor g**: Smaller b₀ yields better selection quality but slower; larger g speeds up but may degrade performance. g = 2 optimal.
  - **Penalty strength λ**: Higher λ increases diversity emphasis; too high suppresses important tokens (λ = 5 default).
  - **Pruning layer**: Earlier layers save more compute but may discard information needed later; paper finds layer 4 optimal for LLaVA‑OneVision.
  - **Query aggregation**: Mean of text tokens works best; using a single last text token degrades performance.
- Failure signatures:
  - Performance drops sharply at very low token budgets (< 5%).
  - Sensitivity to query choice; avoid using image token mean or single last token.
  - May require tuning for models with highly dynamic token generation (e.g., AnyRes), though paper shows robustness.
- First 3 experiments:
  1. **Main benchmark replication**: Run IWP on LLaVA‑OneVision‑7B with token budget 35.3% and reproduce Table 4; expect relative performance > 97% (e.g., 97.9%).
  2. **Ablation on duplication**: Compare Score‑only vs. Score + PC‑MMR at 11.1% budget; expect > 2 pp improvement when adding duplication penalty.
  3. **RoPE ablation**: Test including/excluding RoPE in magnitude and duplication metrics (Table C.2); confirm best performance when RoPE is excluded from magnitude but included in duplication.

## Open Questions the Paper Calls Out
- **Open Question 1**
  - **Question:** Can the IWP framework's dual-form token pruning principle be effectively applied to non-visual continuous modalities (e.g., audio waveforms, point clouds) in multimodal models?
  - **Basis in paper:** [explicit] The "Limitation" section states the current empirical scope is focused on visual modalities and that the method is "modality-agnostic," suggesting extension to audio, speech, or point clouds as future work.
  - **Why unresolved:** The paper only validates IWP on image/video benchmarks. The interaction between the dual-form metrics (which rely on key-value projections) and the representational characteristics of other modalities remains unverified.
  - **What evidence would resolve it:** Systematic experiments applying IWP to audio-visual or 3D point cloud models, measuring performance retention on modality-specific benchmarks compared to modality-specific pruning baselines.

- **Open Question 2**
  - **Question:** What is the precise mechanistic reason why incorporating Rotary Position Embedding (RoPE) into the *information duplication* metric (dual-form similarity) is critical for performance, as suggested by the ablation study?
  - **Basis in paper:** [explicit] Table C.2 shows a significant 3.3% average drop when RoPE is removed from the duplication computation (Setting 4 vs. Setting 1). The text attributes this to capturing "relative positions" and "inductive bias."
  - **Why unresolved:** The paper states the observation but does not provide a theoretical analysis or diagnostic experiments explaining *why* positional awareness is necessary for identifying redundant rank-1 updates in softmax attention. Is it due to positional aliasing in early layers, or a deeper property of how RoPE interacts with the kernel?
  - **What evidence would resolve it:** Analytical probes (e.g., measuring redundancy of tokens at different relative positions) or a modified theoretical derivation showing how RoPE's rotation affects the inner product in Eq. (12) under the dual form.

- **Open Question 3**
  - **Question:** Does the factorization of dual-form similarity \(S_{ij} = (\mathbf{v}_i \cdot \mathbf{v}_j) \cdot \kappa(\mathbf{k}_i, \mathbf{k}_j) / (\|\mathbf{v}_i\|\|\mathbf{v}_j\|)\) hold universally for all positive-definite kernels \(\kappa\), or are there kernel choices where the value and key components are not separable?
  - **Basis in paper:** [inferred] The derivation (Eq. 12) assumes a specific form for the RKHS inner product \(\langle \phi(\mathbf{k}_i), \phi(\mathbf{k}_j) \rangle = \kappa(\mathbf{k}_i, \mathbf{k}_j)\). The final expression factors cleanly because \(\|\Delta\mathbf{W}_i\|_F = \sqrt{\kappa(\mathbf{k}_i,\mathbf{k}_i)}\|\mathbf{v}_i\|_2\). This relies on the norm in the feature space being \(\sqrt{\kappa(\mathbf{x},\mathbf{x})}\), which holds for common kernels (e.g., Gaussian, exponential) but may not be a general property.
  - **Why unresolved:** The paper uses the exponential kernel (Gaussian RBF) without discussing generalizability. If the kernel's feature map norm is not simply \(\sqrt{\kappa(\mathbf{x},\mathbf{x})}\), the factorization might not hold, potentially requiring a different similarity metric.
  - **What evidence would resolve it:** A formal proof or counterexample for a broader class of kernels (e.g., polynomial, sigmoid) showing whether the norm separation property is necessary for the metric's validity, followed by testing alternative kernels in the pruning framework.

- **Open Question 4**
  - **Question:** Can the Progressive Chunked MMR selection algorithm be made adaptive, where the chunk size \(b\) and penalty strength \(\lambda\) are dynamically adjusted per layer or per input based on the distribution of information magnitude scores, to improve performance under extreme token budgets?
  - **Basis in paper:** [inferred] Section 4.3 and Algorithm 1 use fixed hyperparameters (\(b_0\), \(g\), \(\lambda\)) and a linear chunk growth schedule. The ablation (Table C.5) shows sensitivity to these parameters, especially at 11.1% budget. The paper does not explore whether *input-dependent* scheduling could better preserve diverse information.
  - **Why unresolved:** The current approach is static. The optimal trade‑off between speed and redundancy avoidance likely varies with image content (e.g., cluttered vs. sparse scenes) and pruning layer. A one‑size‑fits‑all schedule may be suboptimal.
  - **What evidence would resolve it:** Developing a heuristic (e.g., based on entropy of magnitude scores) to set \(b\) and \(\lambda\) per input, then benchmarking against the fixed schedule on diverse datasets at very low budgets (<10%).

- **Open Question 5**
  - **Question:** What causes the observed drop in mIoU of selected token subsets between middle layers (e.g., layer 4) and the final layer (layer 27) in LLaVA‑OneVision, and does this misalignment correlate with specific types of reasoning errors?
  - **Basis in paper:** [inferred] Fig. C.2 shows high similarity (mIoU > 0.8) between tokens selected at layer 4 and layers 5‑26, but a drop to ~0.6 at layer 27. The paper speculates this is due to "alignment of representations with the next‑token prediction objective" but provides no analysis.
  - **Why unresolved:** If the most informative visual tokens change dramatically in the final layers, pruning based on middle‑layer scores (a common practice) might discard tokens critical for final answer generation. The correlation between this shift and failures in complex reasoning (e.g., MMMU) is unknown.
  - **What evidence would resolve it:** Error analysis on MMMU/MMStar samples where pruned models fail: compare the dual‑form importance scores of *ground‑truth relevant* image regions at layer 4 vs. layer 27. Also, train a probe to predict final‑layer importance from middle‑layer features to quantify the prediction gap.

## Limitations
- **Kernel approximation:** The dual‑form derivation assumes an exact finite‑dimensional feature map for the exponential kernel, but the implementation uses an approximate RBF kernel. Its effect on attention equivalence is unquantified.
- **Multi‑head aggregation:** The method for combining per‑head scores and similarities (e.g., mean, max) is unspecified; this design choice may influence selection quality.
- **Query representation:** Using the mean of all text‑token queries is heuristic; alternative aggregations (learned, layer‑specific) could yield different trade‑offs.
- **Extreme compression:** Performance degrades sharply below ~5% token budget; robustness in high‑compression regimes is unproven.

## Confidence
- Dual‑form attention reinterpretation: **Medium** – mathematically plausible but relies on unvalidated kernel approximation.
- Importance score (magnitude + duplication): **High** – extensive benchmarks and ablations confirm its effectiveness.
- PC‑MMR selection efficiency: **High** – clear algorithm and reproduced speed/VRAM gains.
- Overall superiority over prior methods: **High** – comprehensive comparisons show consistent, statistically significant improvements.
