# MeKi: Memory-based Expert Knowledge Injection for Efficient LLM Scaling

## Quick Facts
- **arXiv ID**: 2602.03359
- **Source URL**: https://arxiv.org/abs/2602.03359
- **Reference count**: 11
- **Primary result**: MeKi-1.7B achieves a 59.7 average zero-shot score, rivaling a 4B dense model’s 60.5 while being 2.26× faster on a Snapdragon 8 Elite.

## Executive Summary
MeKi tackles the challenge of deploying large language models on edge devices by increasing model capacity through additional storage rather than computation. It equips each Transformer layer with token-level memory experts that inject pre-stored semantic knowledge. A re-parameterization strategy folds the training-time non-linear projections of these experts into a compact static lookup table that can be offloaded to ROM, eliminating any extra inference latency. Experiments show that MeKi-1.7B matches the zero-shot performance of a 4B dense model while delivering a 2.26× speedup on a Snapdragon 8 Elite. Across scales (0.6B, 1.7B, 4B), MeKi consistently outperforms dense baselines with identical inference speed and surpasses other memory-based methods like PLE and Engram.

## Method Summary
MeKi augments every Transformer layer with a memory expert that operates at the token level. During training, each memory expert consists of a non-linear projection (e.g., a small MLP) that maps a token’s hidden state to a knowledge vector. At the end of training, these non-linear projections are re-parameterized: the continuous functions are discretized into a static lookup table indexed by token IDs. This table is stored in ROM and used during inference; for each token, the corresponding knowledge vector is retrieved and added to the hidden state, injecting stored semantic information without any additional computation. The re-parameterization ensures that the memory expert adds only a constant-time memory access, preserving the original Transformer’s computational complexity while effectively increasing model capacity.

## Key Results
- MeKi-1.7B achieves a 59.7 average zero-shot score, comparable to a 4B dense model’s 60.5.
- On a Snapdragon 8 Elite, MeKi-1.7B is 2.26× faster than the 4B dense model during decoding.
- Across 0.6B, 1.7B, and 4B scales, MeKi significantly outperforms dense baselines with the same inference speed and beats other memory-based approaches (PLE, Engram).

## Why This Works (Mechanism)
The memory experts provide a way to store and retrieve task-relevant knowledge that is decoupled from the core Transformer parameters. By pre-storing semantic patterns (e.g., factual associations, linguistic rules) in a lookup table, the model can enhance its representations without increasing the computational load of the attention or feed-forward layers. The re-parameterization strategy is key: it transforms the trainable non-linear experts into a fixed, fast-access structure that can be offloaded to ROM. This means inference only incurs a simple table lookup per token, which is orders of magnitude cheaper than a matrix multiplication or MLP forward pass. Thus, MeKi effectively scales model capacity (by adding memory) without scaling compute, making it suitable for resource-constrained edge devices.

## Architecture Onboarding
**Component map**:  
Token IDs -> Embedding -> Transformer Layer (Self-Attention -> FeedForward) -> Memory Expert (ROM Lookup) -> Hidden State -> Next Layer ... -> Output Logits

**Critical path**:  
Tokenization → Embedding lookup → For each Transformer layer: Self-Attention → FeedForward → Memory Lookup (constant-time table access) → LayerNorm → Final LayerNorm → LM Head → Sampling. The memory lookup is inserted after the FeedForward and before the next layer’s input, adding only a memory access latency.

**Design tradeoffs**:
- Memory size (number of entries) vs. accuracy: Larger memory stores more knowledge but consumes more ROM and may increase lookup latency if not cached.
- Number of memory experts per layer vs. speed: More experts (e.g., multiple memory modules) could increase capacity but also increase the number of lookups per token.
- Quantization of stored vectors: Lower bit-width reduces ROM footprint but may degrade the fidelity of injected knowledge.
- ROM capacity limitations: Embedded devices have limited ROM; the total memory footprint must fit within device storage.

**Failure signatures**:
- **Lookup miss**: If a token ID is not present in the memory index, the injection defaults to zero or a fallback, potentially harming performance on tokens with rare IDs.
- **Memory contention**: If many tokens simultaneously access large, uncached memory regions, bandwidth saturation could offset the expected speedup.
- **Over-reliance on memory**: The model might ignore its parametric knowledge and depend too heavily on stored vectors, leading to poor generalization on inputs that require combining stored knowledge with on-the-fly reasoning.

**First experiments**:
1. **Correctness validation**: Compare outputs of the original trainable memory expert model and the re-parameterized MeKi on a held-out set of tokens; ensure differences are within a small tolerance (e.g., 1e-5).
2. **Latency benchmark**: Measure decoding speed (tokens/second) on the target edge device (e.g., Snapdragon 8 Elite) for MeKi vs. a dense model of comparable parametric size and vs. the pre-re-parameterization model.
3. **Capacity sweep**: Vary the size of the memory lookup table (e.g., number of entries) and plot zero-shot accuracy to confirm the expected trade-off curve and identify saturation points.

## Limitations
- Evaluation is limited to a single mobile SoC (Snapdragon 8 Elite); cross-platform generalizability to other edge or desktop hardware remains unverified.
- Performance claims are based solely on zero-shot tasks; effectiveness in fine-tuning, long-context, or interactive settings (e.g., chat, coding) is not addressed.
- The storage cost of the static lookup table and its impact on training efficiency (e.g., memory usage during re-parameterization) are not quantified.
