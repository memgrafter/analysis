# Ran Score: a LLM-based Evaluation Score for Radiology Report Generation

## Quick Facts
- **arXiv ID**: 2603.22935
- **Source URL**: https://arxiv.org/abs/2603.22935
- **Reference count**: 35
- **Primary result**: Clinician-guided LLM extraction of 21 findings achieves macro-F1 0.956, exceeding CheXbert by 15.7%, and enables Ran Score to rank LLM-RG4 highest (0.333) with robust cross-lingual generalization.

## Executive Summary
The paper introduces *Ran Score*, a new evaluation metric for radiology report generation that uses macro-averaged F1 of extracted standard finding labels to assess generated reports, addressing limitations of existing methods especially for low-prevalence findings and nuanced clinical language.

To compute Ran Score, the authors develop a Human-LLM framework: a Qwen3‑14B model is guided by radiologists through iterative prompt optimization on a development set of 300 chest X‑ray reports. The process yields a high-accuracy extractor (macro-F1 0.956) that can be applied to any report (reference or generated) to produce a standardized label set. Ran Score then compares the labels of generated reports against the reference, enabling fine-grained, finding-level evaluation. The approach demonstrates cross-lingual robustness when tested on a Chinese dataset (ChestX‑CN).

## Method Summary
The core task is multi-label extraction of 21 standardized findings from free-text chest X‑ray reports. The authors use a non-overlapping split of MIMIC‑CXR: 3,000 reports define the taxonomy, 300 constitute the development set, and 3,000 are the test set. The development and validation sets have radiologist reference labels obtained from six board‑certified thoracic radiologists via majority vote (binary presence/absence). The goal is to achieve label‑specific accuracy ≥90% (Cohen’s κ≥0.90).

Starting with a structured binary prompt and the open‑weight Qwen3‑14B model, they iterate: radiologists perform error analysis, revise the prompt by adding synonyms, clarifying ambiguous descriptions, and incorporating positive/negative examples; the model is re‑evaluated on the development set. This loop continues until all labels meet the threshold, at which point the prompt is frozen. The finalized prompt is then applied to other LLMs (Qwen‑Plus, GPT‑3.5‑turbo, GPT‑4o‑mini, DeepSeek‑R1) and to reports generated by seven report‑generation models. For each report, the output is a 21‑dimensional binary vector; Ran Score is the macro‑averaged F1 between vectors of generated and reference reports.

## Key Results
- Macro‑averaged F1 on the development set reaches 0.956, improving from an initial 0.753 and surpassing the CheXbert benchmark by 15.7 percentage points.
- Ran Score reveals that LLM‑RG4 is the best report‑generation model (macro‑F1 0.333) among the seven tested, providing a finding‑level ranking.
- The extraction framework shows robust cross‑lingual generalization when evaluated on the ChestX‑CN dataset, maintaining high performance on Chinese reports.

## Why This Works (Mechanism)
The success stems from a clinician‑in‑the‑loop design that aligns the LLM with radiological semantics. Radiologists directly refine the prompt based on systematic error analysis, ensuring that synonyms, negations, and contextual nuances are captured. The iterative process converges on a prompt that elicits reliable extraction from a frozen model, avoiding costly model fine‑tuning. Macro‑F1 as the metric forces balanced performance across all 21 findings, preventing the model from ignoring rare but critical conditions. Moreover, the prompt, tailored on English reports, proves sufficiently semantic to generalize to Chinese because it encodes clinical concepts rather than language‑specific patterns.

## Foundational Learning
- **Prompt Engineering**: Crafting and refining prompts to steer LLM behavior for domain‑specific tasks. *Why needed*: LLMs lack built‑in medical knowledge; prompts must convey the exact extraction schema. *Quick check*: All 21 labels achieve ≥90% accuracy on dev set.
- **Multi‑label Classification**: Predicting multiple binary attributes from a single text input. *Why needed*: A single report may contain several findings; the evaluation must capture the full spectrum. *Quick check*: Macro‑F1 >0.95 indicates balanced labeling across all findings.
- **Clinician‑in‑the‑Loop**: Integrating human expert feedback in the AI development cycle. *Why needed*: Radiologists identify subtle errors and provide high‑quality reference labels; their guidance ensures clinical validity. *Quick check*: Cohen’s κ between extracted labels and radiologist majority ≥0.90.
- **Macro‑Averaged Metrics**: Using macro‑F1 to treat each finding equally, regardless of prevalence. *Why needed*: Prevents dominance of common findings and highlights performance on rare findings. *Quick check*: No individual label F1 drops far below the average.
- **Cross‑lingual Generalization**: Evaluating the extraction system on reports in a different language. *Why needed*: Demonstrates that the system captures abstract clinical concepts rather than English‑specific phrasing. *Quick check*: Performance on Chinese reports remains within a small margin of the English baseline.

## Architecture Onboarding
**Component Map**:  
Report Text -> Prompt Template -> LLM (Qwen3‑14B) -> JSON Parser -> Binary Label Vector

**Critical Path**:  
1. Assemble development set (300 reports) with radiologist majority‑vote labels.  
2. Design initial structured prompt.  
3. Iterate: run LLM, compute per‑label accuracy, radiologists analyze errors, revise prompt, repeat until all labels ≥90% accuracy.  
4. Freeze optimized prompt.  
5. Apply prompt to other LLMs and to generated reports to compute Ran Score.

**Design Tradeoffs**:  
- *Development set size vs. coverage*: 300 reports allows rapid iteration but may miss rare linguistic variations.  
- *Fixed 21 findings vs. open‑ended labeling*: Focused evaluation simplifies comparison but ignores other clinically relevant findings.  
- *Majority‑vote labels vs. full expert consensus*: Majority vote is practical but can obscure disagreements among radiologists.

**Failure Signatures**:  
- Any label accuracy persistently below 90% after several iterations → prompt missing key descriptors.  
- LLM output not matching expected JSON/structured format → insufficient format constraints in prompt.  
- Large performance drop on ChestX‑CN → overfitting to English idioms and lack of true clinical abstraction.

**First Experiments**:  
1. **Baseline run**: Execute the initial (unoptimized) prompt on the development set; record macro‑F1 (~0.753).  
2. **First refinement**: Incorporate a single round of error analysis (e.g., add common synonyms for the lowest‑performing label); measure macro‑F1 improvement.  
3. **Validation**: Apply the finalized prompt to the MIMIC‑CXR‑EN test set; confirm macro‑F1 ≈0.956 and test on ChestX‑CN to verify cross‑lingual robustness.

None

## Limitations
- The exact report IDs for the development/test splits, the finalized optimized prompt, and the generated outputs of the seven report‑generation models are not publicly released, hindering independent verification.  
- Cross‑lingual generalization is assessed on only 150 Chinese reports, a very small sample that may not represent broader robustness.  
- Ran Score itself relies on the unreleased extraction framework; its reliability cannot be audited without full transparency.

## Confidence
- Extraction performance claim (macro‑F1 0.956): Medium  
- Cross‑lingual generalization: Low  
- Model ranking via Ran Score: Low  

## Next Checks
1. **Prompt audit**: Determine whether the exact optimized prompt (with all few‑shot examples and formatting rules) is available in a public repository; without it, macro‑F1 replication is infeasible.  
2. **Splits reconstruction**: Recreate the 300‑report development set by matching the paper’s inclusion criteria (e.g., six‑radiologist majority‑vote labels) if the raw IDs remain undisclosed.  
3. **External stress test**: Run the purported optimal extraction prompt (if obtained) on an entirely new chest X‑ray report corpus with the same 21 findings to evaluate cross‑institutional robustness and identify label‑specific failure modes.
