# Personalizing Mathematical Game-based Learning for Children: A Preliminary Study

## Quick Facts
- **ArXiv ID:** 2603.25925
- **Source URL:** https://arxiv.org/abs/2603.25925
- **Reference Count:** 23
- **Primary Result:** A Random Forest classifier achieved 82.42% accuracy and 72.70% recall in identifying valid, expert-approved player-generated math game levels from a dataset of 206 levels.

## Executive Summary
This study addresses the bottleneck of manually filtering thousands of player-generated levels for math games by developing an automated machine learning pipeline. Using a dataset of 206 levels from a JSON-based level editor, the authors trained and compared four classifiers via nested cross-validation. The Random Forest model performed best, balancing high accuracy with a recall that minimizes discarding valid levels. Feature selection highlighted core structural elements—such as player characters and goals—as the strongest predictors of a level's validity. The work demonstrates a preliminary but feasible approach to automating level screening, which is a necessary step toward scalable, personalized game-based learning where adaptive systems can draw from a large, high-quality pool of user-created content.

## Method Summary
The study used a dataset of 206 distinct math game levels, including 86 expert-designed and 120 player-generated levels, with 44 of the player-generated levels validated as suitable by experts. Sixty-one initial features were extracted from each level's JSON structure, grouped into four categories: player character, goal, physics objects, and obstacles. After recoding missing values, Lasso regression was applied for feature selection within the model training process. Four classifiers—K-Nearest Neighbors, Decision Trees, Support Vector Machines, and Random Forests—were evaluated using a nested cross-validation scheme. The inner loop tuned hyperparameters and performed feature selection, while the outer loop provided an unbiased estimate of performance, reporting metrics including accuracy, precision, recall, F1-score, and ROC-AUC. The primary objective was to maximize recall to avoid discarding potentially valuable levels.

## Key Results
- The Random Forest model achieved the highest outer-loop recall (72.70%) and F1-score (72.70%) with 82.42% accuracy and a stable ROC-AUC.
- Lasso feature selection identified core structural elements (player characters, goals) and specific physics objects (e.g., one-way platforms, bubbles) as the primary predictors of level validity.
- The framework successfully automates the initial screening of player-generated levels, reducing the manual workload for expert validation and supporting the creation of a deployable level pool.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Core structural game features, such as player characters and goals, are strong predictors of level validity.
- **Mechanism:** The classifier relies on these features because expert validation aligns with levels having clear mathematical actions and objectives; Lasso selection highlights their predictive power over peripheral elements.
- **Core assumption:** Expert judgments of quality prioritize how mathematical problem-solving is structurally encoded in gameplay.
- **Evidence anchors:**
  - [abstract]: "Feature selection identified core structural elements like player characters and goals as primary predictors"
  - [section 4]: "player characters and goals emerged as the most critical elements."
- **Break condition:** If the game's fundamental mechanics are redesigned, these features may no longer correlate with validity.

### Mechanism 2
- **Claim:** Random Forest’s ensemble approach yields robust performance for this imbalanced classification task.
- **Mechanism:** RF aggregates multiple decision trees to handle non-linear interactions and reduce overfitting; nested cross-validation stabilizes accuracy and recall estimates despite limited data.
- **Core assumption:** The dataset’s mix of count and value features benefits from RF’s ability to model complex relationships without heavy feature engineering.
- **Evidence anchors:**
  - [abstract]: "Random Forest model achieved the best overall performance, with 82.42% accuracy and 72.70% recall"
  - [section 4 Table 2]: Outer loop metrics show RF leading in recall (72.70%) and F1-score (72.70%) with stable ROC-AUC.
- **Break condition:** If real-time inference becomes critical, RF’s computational cost might necessitate a simpler model with acceptable performance loss.

### Mechanism 3
- **Claim:** Automating level screening enables scalable personalization by maintaining a high-quality pool of player-generated content.
- **Mechanism:** The classifier filters levels before expert review, reducing manual workload and allowing adaptive systems to draw from a larger, vetted set tailored to learner profiles.
- **Core assumption:** Player-generated levels can achieve expert-level quality if structural integrity is ensured, supported by the paper’s focus on intrinsically integrated design.
- **Evidence anchors:**
  - [abstract]: "demonstrating the feasibility of automating level screening to support adaptive, intrinsically integrated mathematical game-based learning."
  - [section 1]: Highlights the "labor-intensive challenge of manually filtering thousands of player-generated math game levels."
- **Break condition:** If recall drops significantly, many valid levels are discarded, shrinking the pool and hindering personalization diversity.

## Architecture Onboarding
- **Component map:** Creative Mode (level editor generating JSON) -> Feature Extractor (parses JSON into 61 variables) -> ML Classifier (RF model trained on expert-validated labels) -> Expert Review UI (for final validation) -> Game Level Pool (storage for approved levels) -> Adaptive Delivery Module (matches levels to player profiles).
- **Critical path:** Player designs level -> JSON exported -> Feature extraction -> Classifier predicts eligibility -> If positive, expert review -> Validated levels deployed to pool -> Adaptive system selects levels based on player data.
- **Design tradeoffs:**
  - Model selection: RF versus SVM/DTree; RF offers better recall but lower interpretability; trade-off in debugging misclassifications.
  - Feature granularity: Using all 61 variables risks overfitting; Lasso reduces to core features but may omit nuanced valid patterns.
  - Threshold tuning: Default 0.5 threshold may discard borderline valid levels; adjusting for higher recall increases false positives.
  - Data dependency: Model performance hinges on expert labels; inconsistent expert judgments introduce noise.
- **Failure signatures:**
  - Declining recall in production: Indicates concept drift as level designs evolve beyond training data.
  - High variance across CV folds: Suggests dataset instability or insufficient samples.
  - Expert override rate: If experts frequently reject classifier-positive levels, the model may be overly permissive.
  - JSON parsing errors: Feature extraction fails for unanticipated level formats.
- **First 3 experiments:**
  1. Expand dataset: Collect 500+ levels from additional Creative Mode modules to test RF generalizability and reduce variance.
  2. Feature ablation: Remove one feature group (e.g., obstacles) at a time to validate Lasso’s importance rankings and identify redundancies.
  3. Pilot adaptive delivery: Integrate classifier with player performance data to test if personalized level sequences improve math engagement compared to static pools.

## Open Questions the Paper Calls Out
- **Question 1:** How can the machine learning classifier be integrated into a functional adaptive system that dynamically selects game levels based on individual player performance and learning progression?
  - Basis: The discussion states, "further exploration is needed and could focus on adaptive and personalized mathematical GBL informed by the proposed framework."
  - Why unresolved: The current study developed a classifier for static level filtering but did not implement or test any adaptive delivery mechanism that responds to real-time player data.
  - Resolution path: Develop and deploy a prototype where the classifier's outputs drive personalized level sequencing, then evaluate its efficacy through controlled experiments measuring learning outcomes, engagement, and adaptivity metrics.
- **Question 2:** Does the Random Forest model's performance and identified feature importance remain consistent when applied to larger, more diverse datasets of player-generated levels across different mathematical games or platforms?
  - Basis: The discussion notes, "the size of the dataset constrains the model comparison," highlighting concerns about generalizability from the 206-level dataset.
  - Why unresolved: Model evaluation was limited to a single app's levels, so robustness to variations in game design, player demographics, or mathematical content is unknown.
  - Resolution path: Collect expanded datasets from multiple sources, replicate the nested cross-validation analysis, and compare performance stability and feature rankings to assess transferability.
- **Question 3:** Which additional features from unexplored game modules in Creative Mode (e.g., advanced physics or scripting elements) enhance the classifier's accuracy in predicting valid game levels?
  - Basis: The discussion mentions, "the Creative Mode includes other game modules with different features. More predictors could be manually selected and explored for further study."
  - Why unresolved: Feature extraction was restricted to 61 variables from four predefined groups, potentially omitting predictive signals from other modules like dynamic event triggers or custom logic.
  - Resolution path: Systematically extract features from all available modules, apply feature selection techniques, and measure improvements in model metrics like recall and F1-score to identify impactful新增 predictors.

## Limitations
- Dataset is small (n=206) and not publicly available, preventing independent replication and limiting generalizability.
- Ambiguous feature description: paper cites 61 variables but only 25 count + 12 value features are detailed; exact variables and encoding unclear.
- Critical hyperparameter search spaces and final values for all models, including Lasso alpha thresholds, are missing.

## Confidence
- **Mechanism 1 (core structural features predict validity):** Medium confidence. Lasso selection in nested CV supports it, but small sample size and lack of external validation reduce certainty.
- **Mechanism 2 (Random Forest robustness):** Medium confidence. RF shows top outer-loop recall (72.70%) and stable ROC-AUC, yet dataset limitations raise overfitting concerns; no benchmark comparison.
- **Mechanism 3 (automated screening enables scalable personalization):** Low confidence. Feasibility is shown only in a preliminary static setting; real-world scalability depends on sustained recall and integration with adaptive delivery, which remains untested.

## Next Checks
1. **Dataset expansion and external validation:** Obtain ≥500 additional levels from varied math modules, then evaluate the trained RF model on a held-out set to assess generalization and variance reduction.
2. **Expert labeling reliability check:** Engage multiple experts to rate a stratified subset (e.g., 50 levels); compute Cohen's kappa. If agreement is low, re-label and retrain to mitigate label noise.
3. **Feature ablation stress test:** Sequentially remove each feature group (player character, goal, physics objects, obstacles) and recompute nested CV metrics; this validates Lasso's selected importance and uncovers any over-reliance on particular groups.
