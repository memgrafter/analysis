# Composition-RL: Compose Your Verifiable Prompts for Reinforcement Learning of Large Language Models

## Quick Facts
*   **arXiv ID:** 2602.12036
*   **Source URL:** https://arxiv.org/abs/2602.12036
*   **Reference count:** 40
*   **Primary result:** A method that automatically composes existing verifiable prompts into harder problems, yielding significant gains (e.g., +21.4% on AIME24 for 30B models) and mitigating the diminishing data problem in reinforcement learning with verifiable rewards.

## Executive Summary
Reinforcement Learning with Verifiable Rewards (RLVR) is effective but suffers from a critical data scarcity issue: as models improve, existing prompts become trivially solvable, reducing the number of effective training examples. This paper introduces Composition-RL, a method to automatically generate new, more challenging verifiable prompts by combining existing ones. It does so through a three-step algebraic transformation process. Evaluated on math benchmarks across 4B to 30B parameter models, Composition-RL consistently improves performance, with a curriculum variant providing further gains. Cross-domain experiments (math and physics) show that composed prompts enhance both in-domain and out-of-domain learning more effectively than simply mixing original datasets.

## Method Summary
Composition-RL addresses the prompt saturation problem in RLVR by algorithmically constructing new problems from a seed pool of verifiable prompts. The process composes two existing prompts (P1 with answer A1, and P2 with answer A2) by first embedding A1 into a modified version of P1. Then, it creates a variable in a modified P2 by replacing a specific value. Finally, it connects the two modified prompts with a relational constraint (e.g., an equality or inequality) that must hold between the embedded answer and the variable. The resulting composed prompt is verifiable: the original verifiers for P1 and P2 can be adapted to check the two sub-problems and the connecting constraint. A curriculum strategy can be applied by gradually increasing the "depth" (number of composed steps) of the generated prompts.

## Key Results
*   **Consistent gains across scales:** On the MATH and AIME24 benchmarks, Composition-RL improves performance for 4B, 8B, and 30B models. On AIME24, relative gains range from +7.2% to +21.4%.
*   **Curriculum benefits:** Incrementally increasing compositional depth yields additional improvements. A final 4B curriculum model achieves 37.9% on AIME24, outperforming several 8B baselines.
*   **Cross-domain superiority:** Composing prompts across domains (e.g., math and physics) leads to better in-domain and out-of-domain performance compared to naive mixing of the original seed datasets, with multi-task average gains of +3.3% to +10.5%.

## Why This Works (Mechanism)
Composition-RL works by systematically increasing the difficulty and diversity of the training distribution without requiring manual problem creation or human annotation. The core mechanism creates novel problems that require multi-step reasoning by forcing the model to solve an embedded sub-problem (from P1) and use its result to satisfy a constraint within a second, structurally different sub-problem (from P2). This forces the model to integrate reasoning across contexts and prevents it from relying on memorized solutions for any single seed prompt pattern. The curriculum over depth further prevents plateauing by steadily introducing problems that require more compositional hops, maintaining a challenging frontier for the learning algorithm.

## Foundational Learning
*   **Concept:** Reinforcement Learning with Verifiable Rewards (RLVR)
    *   **Why needed:** Provides a scalable training signal for precise reasoning tasks where outcome correctness can be automatically checked, bypassing the need for human preference labels.
    *   **Quick check:** Can a given task's output be judged correct/incorrect by a deterministic program or rule?
*   **Concept:** Prompt Saturation / Diminishing Data
    *   **Why needed:** Explains the fundamental limitation RLVR faces as models become capable—the pool of useful training prompts shrinks because the model already solves most of them.
    *   **Quick check:** Does your model's pass rate on your training prompt set approach 100%?
*   **Concept:** Algebraic Prompt Composition
    *   **Why needed:** The specific technique used to generate new, harder problems from existing ones by embedding answers and adding constraints.
    *   **Quick check:** Can you transform two math word problems into one by using the answer from the first to define a variable in the second?
*   **Concept:** Relational Constraints
    *   **Why needed:** The "glue" that binds two sub-problems into a single coherent challenge, ensuring the answer to the first must be used meaningfully in the second.
    *   **Quick check:** Is the constraint (e.g., `x = answer1`) non-trivial and necessary for solving the composed problem?

## Architecture Onboarding
The method is a data generation and processing pipeline, not a model architecture change.

*   **Component Map:**
    Seed Prompt Pool (P1, P2) -> Composer Engine (Modify P1, Modify P2, Add Constraint) -> Filtered Composed Prompt Set -> RL Training Loop (Model + Verifier) -> Updated Model
*   **Critical Path:**
    1.  Select two seed prompts with verifiers and known answers.
    2.  Generate a modified first prompt embedding the first answer.
    3.  Generate a modified second prompt where a value is replaced by a variable.
    4.  Add a relational constraint linking the embedded answer and the variable.
    5.  Validate the composed prompt (e.g., check constraint consistency, solvability).
    6.  Use the new prompt and adapted verifier in the RLVR training step.
*   **Design Tradeoffs:**
    *   **Automation vs. Validity:** Fully automated composition risks generating malformed or unsolvable problems, but manual curation defeats the scalability goal.
    *   **Diversity vs. Coherence:** Combining prompts from very different domains can yield incoherent problems; within-domain composition is safer but may yield less transfer.
    *   **Depth vs. Solvability:** Higher compositional depth increases difficulty but exponentially raises the chance of generating problems that are too hard or broken for the current model to learn from.
*   **Failure Signatures:**
    *   Very low pass rates on a batch of composed prompts during RL training, indicating the problems are likely malformed or impossibly difficult.
    *   The model learns to "ignore" the compositional constraint and finds answers that satisfy sub-problems but violate the relation.
    *   No performance gain or regression compared to training on un-composed seed data, suggesting the new distribution is not meaningfully harder or is misaligned.
*   **Exactly 3 First Experiments:**
    1.  **Human Validity Audit:** Sample 200 automatically composed prompts. Have domain experts rate each for (a) logical coherence, (b) unambiguous solvability, and (c) correct answerability. Report the failure/error rate.
    2.  **Domain Transfer Test:** Apply Composition-RL to a completely different verifiable domain (e.g., programming problems with unit test verifiers). Compare gains to a strong baseline that uses only the original seed prompts for that domain.
    3.  **Ablation on Composition Source:** Compare performance when composing (a) only within the same problem type, (b) only across different types within a domain, and (c) across domains. Measure both in-domain and cross-domain accuracy to isolate the source of the reported transfer benefits.

## Open Questions the Paper Calls Out
Unclear: What is the precise rate of malformed or invalid prompts generated by the automatic composition process? The paper lacks a quantify of this key failure mode.
Unclear: How does the optimal curriculum schedule (e.g., depth progression) depend on the base model's initial capability and the seed prompt pool's diversity?
Unknown: Can the core algebraic composition principle be generalized beyond symbolic reasoning (e.g., to text-based QA with verifiable answers) or does it rely heavily on structured answer formats?

## Limitations
*   Evaluation is confined to math benchmarks and a narrow model scale range (4B–30B); applicability to other domains (e.g., coding, QA) or much larger models remains unknown.
*   The automatic composition process lacks human verification; there is no quantified rate of malformed, biased, or nonsensical generated prompts.
*   The method requires tasks with reliable automated verifiers, making it unsuitable for subjective, creative, or open-ended generation tasks.

## Confidence
*   **Composition-RL improves performance across model sizes on MATH/AIME24.** **High**
*   **A curriculum over increasing compositional depth yields further gains.** **Medium**
