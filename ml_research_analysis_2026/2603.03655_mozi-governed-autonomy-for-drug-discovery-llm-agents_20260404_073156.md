# Mozi: Governed Autonomy for Drug Discovery LLM Agents

## Quick Facts
*   **arXiv ID:** 2603.03655
*   **Source URL:** https://arxiv.org/abs/2603.03655
*   **Reference Count:** 40
*   **Primary Result:** A dual-layer governance architecture (Control Plane + Workflow Plane) that significantly improves accuracy and reliability in long-horizon drug discovery tasks versus existing LLM agents.

## Executive Summary
Mozi is a specialized architecture designed to govern autonomous LLM agents for the multi-stage pipeline of drug discovery. It addresses the twin problems of unconstrained tool use and poor long-horizon reliability by introducing a strict hierarchical control layer and a stateful, composable workflow layer. Evaluated on the PharmaBench benchmark, Mozi demonstrates superior performance on complex tasks, including outperforming state-of-the-art models like Gemini-2.5-Pro on a challenging high-level evaluation subset. Case studies suggest the system can generate viable drug candidates with competitive binding scores while containing errors and filtering toxicity.

## Method Summary
The paper proposes a two-plane architecture. The **Control Plane (Layer A)** acts as a central supervisor, enforcing a hierarchy where workers operate with role-based, isolated tool access and constrained action spaces. It uses reflection to replan when failures are detected. The **Workflow Plane (Layer B)** manages the end-to-end drug discovery process (from Target ID to Lead Optimization) as a series of stateful, composable skill graphs. Each stage has strict data contracts and mandatory human-in-the-loop checkpoints for validation before progression.

## Key Results
*   On PharmaBench (88 tasks), Mozi with Qwen3-235B improved classification accuracy from 20/54 (Biomni baseline) to 33/54 and reduced SMAPE from 1.599 to 1.169.
*   On the challenging HLE subset (28 tasks), Mozi with Deepseek-V3.2 achieved 21.4% exact-match accuracy, exceeding Gemini-2.5-Pro (10.7%) and other models.
*   End-to-end case studies produced in silico drug candidates with binding scores around -8 to -9 kcal/mol and ipTM scores comparable to the clinical benchmark DNL201, demonstrating contained error propagation and effective toxicity filtering.

## Why This Works (Mechanism)
No explicit mechanism analysis or "why" section was provided in the source material. The reported efficacy is attributed to the architectural design principles of governed autonomy (strict control) and stateful, composable workflows.

## Foundational Learning
*   **Agent Governance & Role-Based Isolation:** Limits tool misuse and hallucinations. *Quick Check:* Can the worker model request a tool outside its assigned role?
*   **Stateful Skill Graphs:** Maintains context and intermediate results across long-horizon tasks. *Quick Check:* Is the output of the "Target Validation" stage correctly passed as input to "Hit Discovery"?
*   **Data Contracts & Schema Enforcement:** Ensures interoperable and valid data flow between stages. *Quick Check:* Does a molecule's SMILES string from Lead Optimization conform to the expected schema for the next stage?
*   **Reflection-Based Replanning:** Allows the system to detect and recover from errors without human intervention. *Quick Check:* Does a failed docking simulation trigger a replanning event for the "Hit-to-Lead" skill?
*   **Human-in-the-Loop Checkpoints:** Provides critical validation gates to prevent error cascade. *Quick Check:* Is a human approval step required before moving from "Lead Identification" to "Lead Optimization"?

## Architecture Onboarding
**Component Map:**  
Supervisor (Control Plane) -> Worker (Role-A, Role-B) -> Skill Graph (Workflow Plane: Target ID -> Validation -> Hit Discovery -> Lead ID -> Lead Opt) -> Human Checkpoint -> Next Skill

**Critical Path:** A new task is received by the Supervisor, which selects and instantiates the appropriate Skill Graph from the Workflow Plane. The Supervisor assigns a Worker with a specific role to execute each skill node. The Worker operates within its constrained tool space, with all actions and data validated against contracts. After a node completes, the graph advances to the next skill or triggers a human checkpoint. Failures invoke the Supervisor's reflection module to replan.

**Design Tradeoffs:** Strict governance (Control Plane) reduces autonomy and may increase latency via checkpoints but dramatically improves reliability and error containment. Stateful graphs (Workflow Plane) enable complex multi-stage reasoning but require significant upfront design of skills and contracts, potentially reducing flexibility for novel task formulations.

**Failure Signatures:** A worker repeatedly requesting denied tools; data contracts failing schema validation; reflection loops activating without progress; human checkpoints rejecting outputs with high frequency; a skill graph stalling at a node.

**First Three Experiments:** 1) Execute a single-stage task (e.g., "Predict target for compound X") to validate role-tool alignment and data contracts. 2) Run a two-stage pipeline (e.g., Target ID -> Virtual Screening) to test state passing and a single human checkpoint. 3) Run a full benchmark task from PharmaBench to observe end-to-end behavior, including reflection and checkpoint interactions.

## Limitations
*   **Benchmark Generalization:** Evaluation is limited to PharmaBench and a specific HLE subset; transfer to other scientific domains or real-world wet-lab integration is unproven.
*   **Ablation Analysis:** The precise contribution of the Control Plane vs. Workflow Plane vs. reflection mechanism is not rigorously isolated.
*   **Operational Transparency:** Details on supervision hierarchy (human vs. automated), checkpoint frequency, and computational cost (tokens, latency) are sparse.

## Confidence
*   **PharmaBench Performance Improvement:** Medium-High. Supported by specific metrics on a defined benchmark, but limited by single-benchmark evaluation and lack of statistical testing.
*   **HLE Subset Superiority:** Medium. Compelling head-to-head result, but confidence reduced by specialized task set and potential for unequal inference conditions.
*   **End-to-End Case Study Viability:** Low-Medium. Proof-of-concept with plausible outputs (binding scores), but lacks prospective experimental validation or blinded comparison to human-designed molecules.

## Next Checks
1.  **Cross-Benchmark Generalization:** Replicate Mozi on an external, held-out drug discovery benchmark to test transferability.
2.  **Architectural Ablation Study:** Independently disable or replace Layer A (Control Plane) and Layer B (Workflow Plane) components on a core task subset to quantify each layer's marginal contribution.
3.  **Independent Replication with Cost Analysis:** Reproduce the pipeline while logging: a) nature and frequency of human interventions, b) total API/token costs and wall-clock time per stage, and c) end-to-end success rate without human correction.
