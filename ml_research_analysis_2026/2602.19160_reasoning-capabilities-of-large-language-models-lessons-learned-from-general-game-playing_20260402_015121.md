# Reasoning Capabilities of Large Language Models. Lessons Learned from General Game Playing

## Quick Facts
- **arXiv ID:** 2602.19160
- **Source URL:** https://arxiv.org/abs/2602.19160
- **Reference count:** 40
- **Primary result:** LLMs achieve near-perfect single-step symbolic reasoning in formal game environments but suffer from error accumulation on multi-step tasks, with performance tied to specific structural features of the rule set.

## Executive Summary
This paper evaluates the reasoning capabilities of four large language models (LLMs) within formally specified, rule-governed environments using the framework of General Game Playing (GGP). Models were tested on symbolic forward-simulation tasks—predicting next states, legal actions, and multi-step trajectories—across 35 games defined in Game Description Language (GDL). Performance, measured via Jaccard Index and exact success rate, revealed that top models like Gemini 2.5 Pro excel at single-step state prediction but degrade significantly on longer horizons and action generation. Obfuscation experiments confirmed that reasoning relies on the structural logic of rules rather than natural language cues, though semantically干扰 terms caused notable disruption. Correlation analysis further indicated that different models have distinct architectural weaknesses linked to specific rule-set properties like nesting depth or total rule count.

## Method Summary
The study employs the GGP framework, where games are defined in GDL—a declarative logic language specifying initial states (`init`), state update rules (`next`), and legal move determination (`legal`). A C# interpreter (GDLProject) simulates games to generate ground-truth states and actions. Four tasks are evaluated: single-step next state prediction, legal action enumeration, multi-step state generation, and multi-step action-state generation. To test symbolic grounding, GDL definitions are obfuscated via consistent symbol replacement using random strings, placeholder terms, or real dictionary words. LLMs are queried in a zero-shot manner with strict JSON output format prompts. Model outputs are parsed and validated against the interpreter's ground truth using two metrics: Jaccard Index (partial set similarity) and strict success rate (%S, exact set match). Performance is then correlated with 40 extracted structural features of each game's rule set (e.g., rule depth, total rules, converging property) to identify model-specific bottlenecks.

## Key Results
- Gemini 2.5 Pro achieved near-perfect single-step next state prediction (average Jaccard Index >0.995, strict success >0.95), while all models showed significant performance degradation on multi-step and action generation tasks.
- Obfuscation with random strings or placeholders caused only a mild performance drop, but substitution with real dictionary words led to a much larger decline, indicating reasoning is symbolic yet vulnerable to semantically conflicting cues.
- Correlation analysis revealed model-specific weaknesses: Gemini 2.5 Pro performance strongly negatively correlated with maximum rule depth in NEXT rules; lighter models correlated negatively with total rule count; Llama 3.3 70B showed a strong positive correlation with the "converging" property.
- Common failure modes across models included hallucinated rules, retention of extraneous state facts, formatting errors, and proposing legally invalid actions.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** LLMs can perform accurate single-step symbolic rule application but exhibit error accumulation over multiple inference steps.
- **Mechanism:** The model executes forward-chaining inference over GDL rules for one transition, correctly binding variables and deriving consequent facts from a given state and action. Success depends on local rule matching without needing to track intermediate state inconsistencies across steps.
- **Core assumption:** Each reasoning step can be treated as an isolated symbolic transformation if the input state is fully correct.
- **Evidence anchors:** [abstract] "Gemini 2.5 Pro achieved near-perfect results (average JI >0.995, %S >0.95) on single-step next state prediction"; [section 5] "The easiest task is Next state generation... all but the weakest model achieve very high accuracy."
- **Break condition:** Performance degrades sharply as the number of sequential state transitions increases (n≥2), especially when actions must also be generated.

### Mechanism 2
- **Claim:** LLMs rely on the structural logic of rule definitions rather than surface-level semantic token meanings, but misleading semantics can impair reasoning.
- **Mechanism:** The model parses and operates on the dependency graph of logical predicates and variables. Obfuscation with random strings preserves this graph while removing linguistic cues, allowing performance to remain relatively high. However, dictionary-word obfuscation introduces conflicting real-world associations that disrupt logical processing.
- **Core assumption:** The reasoning process is fundamentally syntactic/graph-based, not driven by pretrained semantic associations.
- **Evidence anchors:** [section 5.3] "Overall, performance decreases under obfuscation, but the degradation is mild... performance remains relatively high despite obfuscation"; [section 5.3] "The 'dictionary words' variant proved to be the hardest... models get confused when words carry real-world meanings."
- **Break condition:** When obfuscation introduces semantically charged but logically irrelevant terms that trigger incorrect commonsense inferences.

### Mechanism 3
- **Claim:** Different LLM architectures have distinct reasoning bottlenecks correlated with specific structural properties of the rule set (e.g., rule depth vs. rule count).
- **Mechanism:** Model performance is limited by different computational constraints: some models (Gemini Pro) are sensitive to recursive/nested rule depth, indicating difficulty with deep compositionality; others (Gemini Flash, GPT-OSS) are sensitive to total rule count, suggesting brittleness in large search spaces; Llama shows correlation with "converging" games, indicating reliance on simpler, monotonic state evolution.
- **Core assumption:** There is no universal "reasoning capacity" metric; instead, models have architecture-specific failure modes exposed by fine-grained feature analysis.
- **Evidence anchors:** [section 5.4] "For the strongest model, Gemini 2.5 Pro... strongest negative correlations are Max rule depth NEXT (r=−0.53)"; [section 5.4] "Gemini 2.5 Flash appears to be limited by... Total rules NEXT (r=−0.60)"; [section 5.4] "Llama 3.3 70B shows strong positive correlation with the Converging property (r= 0.71)."
- **Break condition:** Performance drops when the game's structural feature exceeds the model's effective reasoning depth or capacity.

## Foundational Learning
- **Concept:** Game Description Language (GDL)
  - **Why needed:** The entire evaluation framework uses GDL as a formal, executable specification of game logic. Understanding facts, rules (`<=`), `init`, `next`, and `legal` is essential to interpret the model's task and errors.
  - **Quick check:** What is the difference between an `init` fact and a `next` rule in GDL, and why must all dynamic facts be re-derived at each step?
- **Concept:** Jaccard Index (JI) and Strict Success Rate (%S)
  - **Why needed:** These are the primary evaluation metrics. JI measures partial set similarity, while %S measures exact state correctness. The gap between them indicates partial vs. complete failure.
  - **Quick check:** Why would a model have a high Jaccard Index but a low %S on multi-step tasks?
- **Concept:** Obfuscation Variants (placeholder terms, dictionary words, random strings)
  - **Why needed:** They are the experimental tool to disentangle symbolic reasoning from semantic memorization. Each variant tests a different hypothesis about the model's internal processing.
  - **Quick check:** Why might "random strings" sometimes yield higher performance than "placeholder terms" under obfuscation?

## Architecture Onboarding
- **Component map:** GDL Interpreter (GDLProject) -> Obfuscator (ObfuscatorGDL) -> LLM Runner (llm_runner.py) -> Metric Calculator
- **Critical path:** Game definition -> (optional obfuscation) -> Prompt construction (injecting GDL + current state/action) -> LLM inference (zero-shot, temp=0.2, JSON output) -> Parse JSON output -> Validate against interpreter-generated ground truth -> Record metrics (JI, %S).
- **Design tradeoffs:** Zero-shot testing evaluates inherent reasoning without fine-tuning confounds; strict JSON enables automation but increases formatting errors; low temperature (0.2) reduces stochastic hallucination but may not eliminate non-determinism.
- **Failure signatures:** Hallucinated rules (adding facts not derivable from GDL); extraneous facts (failing to purge outdated information); formatting errors (incorrect GDL syntax like `score(blue,5)` vs `(score blue 5)`); action constraint violation (proposing moves disallowed by `legal` rules).
- **First 3 experiments:**
  1. Baseline single-step prediction (Task 1) on a simple game (e.g., `ticTacToeLarge`) to validate the pipeline and establish high-performance expectation.
  2. Legal action generation (Task 2) on a medium-complexity game (e.g., `checkers`) to expose gaps between state prediction and complete action enumeration.
  3. Obfuscation impact (Task 3, n=5): Run multistep state generation on original vs. placeholder-obfuscated version of a converging game (e.g., `connectfour`) to quantify semantic grounding dependence.

## Limitations
- Causal mechanisms behind model-specific bottlenecks (e.g., why depth harms Gemini Pro more than rule count) remain speculative; correlations do not prove architectural constraints.
- Findings are confined to GDL and game-like environments; generalizability to other formal logics or real-world planning domains is untested.
- Obfuscation tests control for semantic cues but cannot fully isolate whether reasoning is graph-based vs. relying on latent pretrained analogies; the internal process is a black box.

## Confidence
- **Single-step symbolic accuracy:** High
- **Multi-step error accumulation:** High
- **Symbolic reasoning independent of surface semantics:** Medium
- **Model-specific structural weaknesses:** Medium

## Next Checks
1. **Causal failure-mode analysis:** Systematically vary one structural feature (e.g., max rule depth) while holding others constant to establish causation for each model's breaking point.
2. **Process introspection via prompting:** Use chain-of-thought and intermediate state extraction prompts on failing examples to pinpoint where errors originate (rule matching, variable binding, fact persistence).
3. **Cross-formalism transfer:** Replicate core single/multi-step tasks in a different formal specification language (e.g., PDDL) to test generalizability beyond GDL.
