# Tiny, Hardware-Independent, Compression-based Classification

## Quick Facts
- **arXiv ID:** 2603.06359
- **Source URL:** https://arxiv.org/abs/2603.06359
- **Reference count:** 40
- **Primary result:** Kernelised Normalized Compression Distance (NCD) matches or exceeds state-of-the-art accuracy on heterogeneous datasets while reducing distance matrix computation time by ~50% and enabling effective client-side classification with very small, user-specific training samples.

## Executive Summary
This paper tackles the privacy and efficiency limitations of modern machine learning by proposing a method for client-side classification that requires no large centralized datasets or heavy computation. It leverages Normalized Compression Distance (NCD) as a similarity measure, extending its use beyond K-nearest neighbours (KNN) to kernel methods like SVM and logistic regression. Key innovations include practical symmetrisation techniques to address NCD's non-metric properties, which halve runtime and improve stability. Experiments across malware, spam, and network intrusion datasets show that kernelised NCD achieves accuracy on par with or better than traditional metrics, all while operating effectively on tiny, user-private data samples entirely on a client device.

## Method Summary
The method transforms any input data (numeric rows, text) into string representations. It computes pairwise Normalized Compression Distance (NCD) using a general-purpose compressor (e.g., gzip), with a cache that stores compressed lengths to avoid redundancy. To handle NCD's inherent asymmetry, three symmetrisation strategies are introduced: copying the lower-triangle ("Assumed"), sorting inputs to enforce order ("Enforced"), or averaging both directional computations ("Average"). For kernel methods, this (symmetrised) distance matrix is converted into a kernel matrix via formulas like the RBF kernel `K[i,j] = exp(-D[i,j]²/λ)`. Standard scikit-learn classifiers (KNN, LogisticRegression, SVC) are then trained on either the distance matrix (KNN) or kernel matrix (kernel methods). Prediction for a new sample follows the same pipeline: stringify, compress, compute distances to the cached training set, apply symmetrisation, form the test kernel/distance vector, and infer the label.

## Key Results
- Kernelised NCD (using RBF or Hamming kernels) matches or exceeds the accuracy of other distance/kernel combinations across four diverse datasets (KDD-NSL, DDoS IoT, Truthseeker, SMS Spam).
- Proposed symmetrisation techniques reduce the time to compute the full distance matrix by approximately 50% compared to the baseline, asymmetric NCD-KNN implementation.
- The approach maintains high accuracy even when the training set contains only a few hundred samples, demonstrating suitability for privacy-preserving, single-user scenarios with limited local data.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Extending Normalized Compression Distance (NCD) to kernel methods (e.g., RBF, Hamming) enables effective classification with complex decision boundaries, beyond distance-based KNN.
- **Mechanism:** NCD is used as the distance `d` in a kernel function `k(x,x') = exp(-d(x,x')²/λ)` (RBF) or `k(x,x') = 1 - λ * d_H(x,x')/max(|x|,|x'|)` (Hamming). This maps data into a reproducing kernel Hilbert space, allowing models like logistic regression and SVM to learn non-linear patterns.
- **Core assumption:** NCD, despite not being a true metric, can serve as a valid distance input to kernel functions that rely on pairwise dissimilarities, preserving enough structure for learning.
- **Evidence anchors:** The paper states its goal is to "develop it for the wider context of kernel methods to allow modelling of complex data" (abstract) and provides a full derivation of using NCD within RBF and Hamming kernels via the kernel distance formula `d_k(x,x') = 2 - 2k(x,x')` (Section 3.2).
- **Break condition:** If the non-metric properties of NCD (violations of symmetry/triangle inequality) cause the resulting kernel matrix to fail positive semi-definiteness checks, invalidating the kernel method's mathematical foundation.

### Mechanism 2
- **Claim:** Symmetrization techniques (e.g., averaging NCD(x,x') and NCD(x',x), or alphanumeric ordering) enforce symmetry in the distance matrix, improving runtime (~50% reduction) and mitigating erroneous neighbor ordering in KNN.
- **Mechanism:** Instead of computing all pairwise NCD values (which can be asymmetric), either (a) compute only the lower triangular part and mirror it ("Assumed"), (b) sort inputs before computation ("Enforced"), or (c) explicitly average both directional computations ("Average"). This ensures `D[i,j] = D[j,i]`.
- **Core assumption:** Enforcing symmetry corrects a key flaw in raw NCD that could lead to inconsistent nearest-neighbor rankings, and doing so by computing fewer unique pairs halves the computational cost.
- **Evidence anchors:** The abstract mentions "propose techniques to improve the training time" and making the modified NCD "more like a metric". Section 3.1.1 details the three symmetrisation methods and their computational savings (e.g., "Average" method costs 66.67% of Vanilla). Figure 2 demonstrates that "Assumed"/"Enforced"/"Average" reduce time per sample by ~half vs "Vanilla" without a significant accuracy penalty.
- **Break condition:** If the averaging or ordering distorts the semantic similarity signal more than the asymmetry itself harms learning, leading to a net accuracy loss.

### Mechanism 3
- **Claim:** NCD-based classification achieves high accuracy even with very small, user-specific training samples, enabling client-side deployment without large centralized datasets.
- **Mechanism:** Compression algorithms inherently capture statistical and structural patterns in data. NCD measures shared information content between objects via compressed lengths, which is effective for similarity even with few examples because it leverages general-purpose compressors trained on vast corpora (outside the user's data).
- **Core assumption:** A general-purpose compressor (like gzip/brotli) encodes domain-agnostic patterns (e.g., repetitions, common substrings) that are sufficiently informative for classification tasks across heterogeneous data types (strings, logs, messages) without task-specific training on large datasets.
- **Evidence anchors:** The abstract highlights "remarkable accuracy even when trained on a very small number of samples" and "models that are small and effective enough to run entirely on a client device". Section 1.2 notes that "NCD-KNN is known to work well even when trained on small numbers of samples." Results in Section 4 show kernelized NCD matches/exceeds other metrics on datasets with hundreds to thousands of total samples, not large-scale.
- **Break condition:** If the user's data is highly idiosyncratic or sparse such that the compressor's built-in model fails to capture relevant task-specific patterns, requiring more samples than available for a meaningful distance signal.

## Foundational Learning
- **Concept: Normalized Compression Distance (NCD)**
  - *Why needed here:* It is the core similarity measure replacing traditional metrics; understanding its definition `NCD(x,x') = (|C(xx')| - min(|C(x)|,|C(x')|)) / (max(|C(x)|,|C(x')|) + ε)` and reliance on a compressor `C` is essential.
  - *Quick check question:* Why might NCD(x,A) ≠ NCD(A,x) when using practical compressors like gzip?
- **Concept: Kernel Trick / Kernel Methods**
  - *Why needed here:* The paper's key extension is using NCD within kernels (RBF, Hamming) to enable logistic regression/SVM; this requires grasping how a distance function can be plugged into `k(x,x') = exp(-d(x,x')²/λ)` to implicitly map data to a high-dimensional space.
  - *Quick check question:* If you have a valid distance function `d(x,x')`, how would you construct a kernel matrix `K` suitable for an SVM?
- **Concept: Symmetrization of Asymmetric Distances**
  - *Why needed here:* Raw NCD can be asymmetric; the paper's runtime gains and accuracy improvements rely on strategies to force symmetry. Understanding the trade-off between computational savings and potential signal alteration is crucial.
  - *Quick check question:* What is the computational cost (in terms of required NCD computations) of the "Average" symmetrisation method relative to computing all pairwise distances naively?

## Architecture Onboarding
- **Component map:**
  1. **Data Preprocessor:** Converts heterogeneous input (numeric rows, text) into string representations (e.g., Python list cast to string).
  2. **Compressor Cache:** Pre-computes and stores `|C(x)|` for every sample `x` in training and prediction sets to avoid redundant compression.
  3. **Symmetrizer:** Applies chosen symmetrisation (Vanilla/Assumed/Enforced/Average) during distance matrix construction.
  4. **Kernel Generator (Optional):** If using kernel methods, transforms the (possibly symmetrized) distance matrix `D` into a kernel matrix `K` via `K[i,j] = exp(-D[i,j]²/λ)` (RBF) or other kernel formula.
  5. **Classifier:** Standard scikit-learn model (KNN, LogisticRegression, SVC) trained on either the distance matrix (for KNN) or kernel matrix (for kernel methods).
  6. **Prediction Engine:** For a new sample, computes its distances to all training samples (using cached compressions), applies symmetrisation if needed, then uses the trained model for prediction.
- **Critical path:**
  1. Load and stringify training data.
  2. Pre-compress all training samples → `compressed_lengths_train`.
  3. Compute pairwise distances (with symmetrisation) → `D_train`.
  4. If kernel method: compute `K_train` from `D_train`.
  5. Train classifier on `D_train` (KNN) or `K_train` (kernel methods).
  6. For a test sample: stringify, compress, compute its distances to all `compressed_lengths_train`, apply same symmetrisation, form `D_test`/`K_test`, predict.
- **Design tradeoffs:**
  - **Compressor choice (gzip/bz2/brotli):** Affects accuracy (brotli often best) and speed (gzip fastest). No single best; requires empirical tuning per dataset.
  - **Symmetrisation method:** "Average" may be most faithful to original similarity but has higher compute than "Assumed"/"Enforced" (which just copy values). Runtime vs. accuracy trade-off.
  - **Kernel vs. Distance-based:** Kernel methods (RBF) generally more accurate but require hyperparameter λ tuning and kernel matrix inversion (for SVM), increasing training memory. KNN with NCD is simpler but may have lower accuracy.
  - **Stringification heuristic:** Crude list-to-string conversion (e.g., `"[1, 2, 3]"`) is hardware-independent but introduces noise (brackets, commas). More structured encoding could improve accuracy but adds domain-specific preprocessing.
- **Failure signatures:**
  - **Low accuracy despite small data:** Could indicate the compressor is not capturing relevant patterns for the specific task (try different compressor or smarter stringification).
  - **High asymmetry in NCD matrix (before symmetrisation):** Check Lemma 1 counter-examples; if severe, "Average" symmetrisation may be necessary despite cost.
  - **Poor kernel matrix (non-PSD):** If using NCD in an SVM and solver fails, the kernel matrix may not be positive semi-definite due to NCD's metric violations; try stronger symmetrisation or switch to KNN.
  - **Excessive prediction latency:** Dominated by compression of the test sample against all training samples. Cache is critical; if still slow, reduce training set size or use faster compressor (gzip).
- **First 3 experiments:**
  1. **Reproduce Lemma 1 (Non-metric demonstration):** Compute NCD between specific string pairs from the lemma (e.g., `NCD_gzip("AAAA", "AAAA")`) using gzip/bz2/brotli. Verify violations of zero, non-negativity, symmetry, triangle axioms. This confirms the need for symmetrisation.
  2. **Benchmark Symmetrisation Methods:** On a small dataset (e.g., SMS Spam), compute full distance matrix with "Vanilla" and each symmetrisation method. Measure (a) time per distance computation, (b) symmetry error (`max(|D[i,j]-D[j,i]|)`), (c) accuracy of NCD-KNN with `k=5`. Validate that "Assumed"/"Enforced"/"Average" reduce runtime by ~50% and assess accuracy trade-off.
  3. **Kernelized NCD vs. Vanilla NCD-KNN:** For one dataset (e.g., KDD-NSL), train best `λ`-tuned RBF kernel SVM using "Average" symmetrised NCD distances. Compare test accuracy against best NCD-KNN (from paper's Figure 1 right). Confirm kernel method's superiority and note hyperparameter tuning cost.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How do GPU-accelerated compression algorithms affect the runtime and scalability of NCD-based classification compared to CPU-based implementations?
- **Basis in paper:** The authors state that "compression algorithms optimised for graphics processing units (GPUs) have been developed [52]. These are likely to outperform the CPU-based implementations used in this paper when applied to large-scale datasets. Incorporating such GPU-accelerated compressors could significantly reduce processing time and improve scalability."
- **Why unresolved:** The study only evaluated CPU-based compressors (gzip, bz2, brotli); GPU versions were not tested, leaving a gap in understanding performance on resource-constrained client devices with large data.
- **What evidence would resolve it:** Implement and benchmark GPU-accelerated compressors on the same datasets (e.g., DDoS IoT, KDD-NSL) using the proposed NCD-kernel methods, measuring computation time per sample and classification accuracy to compare with CPU baselines.

### Open Question 2
- **Question:** Do more sophisticated encoding methods for heterogeneous tabular data (e.g., schema-aware parsing, embeddings) improve NCD-based classification accuracy over the crude string-casting approach?
- **Basis in paper:** The authors note that their preprocessing "was intentionally kept simple—each row was cast to a Python list then cast again as a string... This approach is crude and may obscure structural or semantic relationships... More sophisticated encoding methods... could improve performance, particularly on more complex or high-dimensional datasets, in particular for the 'Truthseeker' dataset."
- **Why unresolved:** The paper used a baseline string conversion without exploring advanced encodings, so the potential for accuracy gains with better representations is unknown, especially for datasets like Truthseeker with mixed data types.
- **What evidence would resolve it:** Apply alternative encoding techniques (e.g., one-hot for categorical, normalized for numeric, or learned embeddings) to datasets like Truthseeker, compute NCD matrices, and compare test accuracies using kernelised models (e.g., SVM with RBF kernel) against the crude method.

### Open Question 3
- **Question:** How do compression algorithms optimised for specific data types (e.g., text, images) perform in NCD-based classification across diverse domains compared to general-purpose compressors?
- **Basis in paper:** The authors state that "the data preprocessing step... other compressors exist—including those optimised for specific data types [53, 54]—they were considered out of scope for this study." References 53 and 54 cite domain-specific compressors like MP3 and HEVC.
- **Why unresolved:** Only general compressors (gzip, bz2, brotli) were evaluated; compressors tailored for specific modalities (e.g., image or audio compressors) might yield better NCD metrics for relevant datasets, but this is untested.
- **What evidence would resolve it:** Select domain-specific compressors (e.g., JPEG for image datasets, FLAC for audio if applicable) and apply them to corresponding datasets in the study (e.g., using image-based malware or audio spam), then compare NCD-based kernel classification accuracy and runtime against general compressors.

### Open Question 4
- **Question:** What is the theoretical impact of symmetrisation techniques (Assumed, Enforced, Average) on the metric and kernel properties of NCD, and how does this influence the performance of kernel methods like SVM?
- **Basis in paper:** The paper proposes symmetrisation to address NCD's non-metric behaviour (Lemma 1) and shows empirical runtime and accuracy improvements, but does not analyse how symmetrisation affects the positive-definiteness of the derived kernel or its theoretical guarantees for kernel methods.
- **Why unresolved:** Symmetrisation is motivated by practical concerns (symmetry axiom violation), but the relationship between symmetrisation and kernel validity (e.g., Mercer's condition) or its effect on decision boundaries in SVM/logistic regression is not explored, leaving a gap in understanding why it sometimes improves accuracy.
- **What evidence would resolve it:** Conduct theoretical analysis to prove whether symmetrised NCD kernels (e.g., using Equation 8) are positive-definite under certain conditions, and correlate these properties with empirical performance across datasets and models to identify patterns or trade-offs.

## Limitations
- Undersampling strategy (random vs. systematic) and train/test split seeds are unspecified, hindering replication.
- Diagonal handling in distance matrices (for kernel methods) is undocumented; NCD(x,x) ≠ 0 typically.
- Error term ε in NCD formula is not stated (assumed 0).
- Compression parameters (level, encoding) are absent; gzip default assumed but not confirmed.
- Symmetrization method used in kernel results is implied ("Average") but not explicitly verified.
- Hyperparameter tuning ranges, nested CV usage, and random seeds for CV folds are missing.
- Stringification via `str(list)` for tabular data is crude; alternative encodings could alter accuracy.

## Confidence
- **Kernel extension of NCD (M1):** Medium. Empirical results support, but theoretical PSD guarantee is absent; non-metric properties risk invalid kernels.
- **Symmetrization techniques (M2):** High. Clear empirical evidence of ~50% runtime reduction and maintained accuracy across methods.
- **Small-sample effectiveness (M3):** Medium. Results on hundreds of samples are promising, but "very small" (e.g., tens) is untested; break condition for idiosyncratic user data remains.
