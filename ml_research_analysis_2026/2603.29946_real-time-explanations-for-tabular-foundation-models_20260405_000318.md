# Real-Time Explanations for Tabular Foundation Models

## Quick Facts
- arXiv ID: 2603.29946
- Source URL: https://arxiv.org/abs/2603.29946
- Reference count: 8
- Primary result: ShapPFN integrates Shapley value regression into a dual-decoder transformer to yield predictions and explanations in a single forward pass, matching state-of-the-art tabular foundation models (average ROC-AUC 0.848) while accelerating explanation generation by >1000× over KernelSHAP.

## Executive Summary
Tabular foundation models deliver strong predictive performance but typically lack integrated, fast explanations—a critical gap for scientific workflows where traditional SHAP calculations are prohibitively slow. ShapPFN addresses this by embedding Shapley value regression directly into the model architecture through a dual-decoder transformer. This design produces both predictions and per-feature Shapley contributions in one forward pass, enforced by a dedicated loss that preserves Shapley consistency. Evaluations on OpenML-CC18 binary classification tasks show that ShapPFN retains the predictive accuracy of NanoTabPFN (average ROC-AUC 0.848) while providing high-fidelity explanations (R²=0.963, cosine=0.987 relative to KernelSHAP) and achieving a speedup of over 1000× (0.06 s vs 610 s). Consequently, ShapPFN enables real-time, principled feature attribution without sacrificing model quality.

## Method Summary
ShapPFN employs a transformer-based architecture with two decoders: a prediction head for the target variable and a Shapley head for feature-wise contributions. The model is trained with a combined loss comprising a standard predictive loss (e.g., cross-entropy) and a Shapley consistency loss that penalizes violations of Shapley axioms (efficiency, symmetry, dummy, additivity). This joint training ensures that the Shapley head learns to output values that sum to the model’s prediction and respect key properties of Shapley values. Because the Shapley contributions are generated directly by the model rather than by post-hoc approximation, explanations are obtained in a single forward pass, eliminating the costly sampling procedure used by KernelSHAP.

## Key Results
- **Predictive performance**: On OpenML-CC18 binary classification benchmarks, ShapPFN achieves an average ROC-AUC of 0.848, matching NanoTabPFN.
- **Explanation fidelity**: Shapley values from ShapPFN correlate strongly with those from KernelSHAP (R²=0.963, cosine similarity=0.987).
- **Efficiency**: ShapPFN generates explanations in 0.06 s on average, whereas KernelSHAP requires 610 s—a speedup exceeding 1000×.

## Why This Works (Mechanism)
ShapPFN’s speed stems from eliminating the approximating sampling loop of KernelSHAP. The dual-decoder architecture allows the model to produce explanations inline with predictions, while the consistency loss forces the Shapley head to adhere to the theoretical properties of Shapley values. By training on a diverse set of tabular datasets, the model learns a generic mapping from data to Shapley contributions that generalizes across tasks, thus maintaining fidelity. The computational cost of explanation is reduced from exponential (or high‑cost sampling) to that of a single transformer forward pass, enabling real‑time use.

## Architecture Onboarding
### Component Map
Input -> Transformer Encoder -> Prediction Decoder -> y  
                      -> Shapley Decoder -> φ_i (per feature)  
Loss Module: L_total = L_pred + λ L_shap_consistency

### Critical Path
1. Input features embedded into continuous vectors.  
2. Encoder applies self‑attention to capture feature interactions.  
3. The encoded representation is fed to both decoders.  
4. Prediction decoder outputs the target logit/probability.  
5. Shapley decoder outputs a vector of feature contributions that sum to the prediction.  
6. Combined loss computed and backpropagated.

### Design Tradeoffs
- **λ (loss weight)**: Balances predictive accuracy against explanation consistency; too high may impede learning, too low yields invalid Shapley values.  
- **Model size**: Dual decoders increase parameter count modestly versus a single‑task model, but keep inference cost similar.  
- **Training time**: Joint optimization requires careful scheduling to stabilize both tasks.

### Failure Signatures
- Shapley head fails to converge → explanations do not sum to prediction (violates efficiency).  
- Large discrepancy between ShapleyPFN and KernelSHAP on out‑of‑distribution data → potential loss of fidelity.  
- Prediction accuracy drops when λ is set too aggressively → over‑emphasis on explanation constraints.

## Limitations
- Evaluation restricted to binary classification tasks on OpenML‑CC18; performance on regression or multi‑class problems remains unknown.  
- Explanation fidelity measured against KernelSHAP, an approximate method; no comparison to exact Shapley values on small datasets.  
- Speedup claim based on average runtimes; scaling behavior with dataset size (samples/features) and hardware variability not fully explored.
