# Quantization with Unified Adaptive Distillation to enable multi-LoRA based one-for-all Generative Vision Models on edge

## Quick Facts
- **arXiv ID:** 2603.29535
- **Source URL:** https://arxiv.org/abs/2603.29535
- **Reference count:** 21
- **Primary result:** Enables dynamic multi-LoRA switching on edge NPUs with up to 6× memory and 4× latency improvement while preserving generation quality (e.g., FID 5.53, SSIM 0.94).

## Executive Summary
Deploying multiple LoRA adapters for generative vision models on edge devices typically requires separate model binaries per task, causing storage bloat and runtime overhead. This paper addresses this by treating LoRA weights as runtime inputs to a single frozen base model graph, allowing dynamic task switching without recompilation. The QUAD (Quantization with Unified Adaptive Distillation) framework aligns independently trained LoRAs under a shared quantization profile to meet fixed-quantization NPU constraints. Evaluations across Qualcomm, MediaTek, and LSI chipsets demonstrate up to 6× memory reduction and 4× latency improvement while maintaining high-quality outputs (e.g., FID 5.5287 for object removal, SSIM 0.94). The approach supports over-the-air LoRA updates and is designed to be chipset-agnostic.

## Method Summary
The method comprises four key steps. First, the base Large Vision Model (LVM) architecture is modified so that each LoRA‑augmented linear layer exposes additional input nodes for the low‑rank A and B tensors; the base weights are frozen. Second, QUAD computes a Quantization Sensitivity Score (QSS) for each LoRA to select an anchor with the highest sensitivity, fixing its quantization parameters. All other LoRAs are fine‑tuned via knowledge distillation: their quantized outputs (using the anchor’s scale/zero‑point) are matched to their full‑precision outputs, adapting their weight distributions to the shared grid. Third, the modified model (with placeholder LoRA inputs) is exported to ONNX, quantization nodes are inserted using the calibrated parameters, and the graph is compiled to the target NPU’s IR via vendor tools. Finally, a lightweight runtime binds LoRA weights to the input slots at inference, enabling dynamic switching without recompilation. This pipeline stores a single base graph on‑device and loads only small LoRA buffers, drastically cutting ROM and memory usage.

## Key Results
- Up to 6× reduction in memory footprint and 4× latency improvement on edge NPUs across multiple chipsets.
- High generation quality retained: e.g., FID 5.5287 for object removal, SSIM 0.94.
- Supports over‑the‑air LoRA updates and works across Qualcomm, MediaTek, and LSI platforms.

## Why This Works (Mechanism)

### Mechanism 1: Runtime LoRA Weight Injection
**Claim:** Treating LoRA weights (A, B matrices) as runtime inputs to a frozen base model graph enables dynamic task switching without recompilation.  
**Mechanism:** During training, each LoRA‑augmented linear layer is modified to accept A and B as additional input tensors, computing `y = Wx + αA(Bx)`. At inference, the compiled base graph remains static; task‑specific LoRA weights are loaded from memory and bound to these input slots via lightweight APIs.  
**Core assumption:** The NPU runtime can efficiently bind external tensors to predefined graph inputs and execute without graph re‑instantiation.  
**Evidence:** Abstract and Section 3.2 describe the injection pattern; experimental results (Table 2) confirm memory and latency gains.

### Mechanism 2: Unified Quantization via Distillation
**Claim:** QUAD aligns independently trained LoRA adapters under a single shared quantization profile (scale/zero‑point), ensuring compatibility with fixed‑quantization NPU hardware.  
**Mechanism:** A quantization‑sensitive LoRA (highest QSS) is selected as anchor; its PTQ parameters are fixed. Other LoRAs are fine‑tuned via distillation: their quantized outputs using the anchor’s parameters are matched to their full‑precision outputs, adapting weight distributions to the shared grid.  
**Core assumption:** Distillation loss can sufficiently align output distributions under the shared quantization grid, preserving task‑specific performance.  
**Evidence:** Abstract and Section 3.3 outline the strategy; ablations (Table 5) show minimal accuracy drop versus independent quantization.

### Mechanism 3: Single Frozen Quantized Graph
**Claim:** A single frozen, quantized graph compiled once for the base model plus runtime LoRA injection enables efficient multi‑task deployment, reducing ROM and memory overhead.  
**Mechanism:** The restructured model (with LoRA input placeholders) is exported to ONNX, quantization nodes are inserted, and the graph is optimized (scale folding, constant folding). The resulting static graph is compiled to the NPU IR. At runtime, only small LoRA buffers (~100s MB) are swapped, not entire model binaries (~1GB+).  
**Core assumption:** Vendor compilation correctly handles placeholder inputs and inserts stable quantization nodes that require no per‑task recalibration.  
**Evidence:** Abstract reports up to 6× memory reduction; Section 3.4 details the conversion pipeline; empirical results (Table 2) validate across three chipsets.

## Foundational Learning
- **Concept: Low‑Rank Adaptation (LoRA)**  
  *Why needed:* LoRA provides the trainable, low‑rank components (A, B) that can be swapped independently from the frozen base model.  
  *Quick check:* For a `d_out × d_in` linear layer and rank `r`, what is the parameter overhead of LoRA relative to the full `d_out·d_in` weights?
- **Concept: Quantization‑Aware Training (QAT) & Distillation**  
  *Why needed:* QUAD uses distillation to align LoRA distributions under a fixed quantization grid, requiring knowledge of how quantization affects the loss landscape and how a teacher (FP32) guides a student (quantized).  
  *Quick check:* How does minimizing `D(f(x;w) || f(x;˜w))` (Eq. 8) differ from standard QAT that uses straight‑through estimators?
- **Concept: Edge NPU Deployment Constraints**  
  *Why needed:* NPUs often require static graphs, fixed‑precision weights (e.g., INT8), and have limited memory. This context explains why separate LoRA binaries are problematic and why shared quantization is mandatory.  
  *Quick check:* Why would independently quantized LoRAs (each with their own scale/zero‑point) be incompatible with a single compiled NPU graph?

## Architecture Onboarding
**Component map:** Base LVM (frozen, quantized U‑Net + VAE) → LoRA Input Slots (graph placeholders for A, B tensors) → QUAD Module (sensitivity analysis, distillation fine‑tuning script) → Compilation Pipeline (PyTorch → ONNX → Vendor IR) → Runtime Stack (graph executor, LoRA loader/binder, scheduler) → LoRA Buffer Manager (in‑device storage/caching)

**Critical path:** Model modification → QUAD alignment → Graph export/compile → Runtime integration → OTA update mechanism.

**Design tradeoffs:**
- *Shared quantization vs. per‑LoRA accuracy:* Forcing all LoRAs through one grid risks higher degradation for sensitive tasks.
- *Dynamic loading vs. RAM footprint:* LoRA buffers occupy RAM; aggressive caching reduces switch latency but inflates peak RAM.
- *Compilation once vs. hardware flexibility:* The single graph targets a specific NPU operator set; changing chipsets may require recompilation.

**Failure signatures:**
- High FID/LPIPS (>20) on device vs. server FP32 → QUAD alignment failed.
- Runtime crash on LoRA switch → binding API mismatch or buffer size error.
- Memory overflow during switching → LoRA cache eviction policy flawed or buffers too large.
- Vendor compile error → graph modification broke operator fusion patterns.

**First 3 experiments:**
1. *Host validation:* Run modified model (LoRA as inputs) in PyTorch on host; verify task accuracy matches baseline (merged LoRA) within tolerance.
2. *QUAD alignment test:* Apply QUAD to two LoRAs; measure teacher‑student distillation loss convergence and post‑quantization accuracy drop (should be minimal).
3. *Single‑NPU end‑to‑end:* Compile unified graph for target chipset (e.g., GS25); run inference with one LoRA; measure latency, peak RAM, and output quality (FID/SSIM) against FP32 host reference.

## Open Questions the Paper Calls Out
1. **QSS‑based anchor selection at scale:** Does selecting the highest‑QSS LoRA as the shared quantization anchor remain effective when scaling to dozens of adapters? The paper evaluates only 2‑4 adapters.
2. **Portability to other generative models:** Is the LoRA‑as‑input approach applicable beyond diffusion models to transformer‑based generators? The claim is generic but only tested on SD LVM.
3. **Performance on lower‑bit NPUs:** How does QUAD perform on NPUs that use 4‑bit or mixed‑precision quantization? All evaluations used INT8.

## Limitations
- Precise QSS computation details (divergence metric, calibration size, selection threshold) are not provided, hindering faithful reproduction.
- Implementation specifics for ONNX‑to‑vendor‑IR conversion and dynamic LoRA binding APIs are scarce, blocking cross‑platform deployment.
- Evaluation is limited to three NPU chipsets; scalability to other hardware and driver variations remains unknown.

## Confidence
- Dynamic LoRA injection without recompilation: Medium
- QUAD unified quantization preserving quality: Medium
- Chipset‑agnostic deployment: Low‑Medium

## Next Checks
