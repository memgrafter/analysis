# Separators in Enhancing Autoregressive Pretraining for Vision Mamba

## Quick Facts
- **ArXiv ID:** 2603.03806  
- **Source URL:** https://arxiv.org/abs/2603.03806  
- **Reference count:** 37  
- **Primary result:** STAR‑B achieves 83.5% top‑1 accuracy on ImageNet‑1k after 1600 epochs of autoregressive pretraining, outperforming prior Vision Mamba methods and matching MAE on ViT‑B.

## Executive Summary
This paper introduces STAR (Separators for AutoRegressive pretraining) to overcome the short‑sequence limitation of Vision Mamba. By inserting cluster‑based separator tokens before each image, multiple images are concatenated into a single long autoregressive sequence, extending the effective context length fourfold while preserving individual image dimensions. The class token is relocated to the sequence end to better align pretraining and fine‑tuning. STAR‑B obtains 83.5% top‑1 accuracy on ImageNet‑1k, matching MAE on ViT‑B with superior training efficiency.

## Method Summary
STAR processes images by splitting them into patches, grouping spatially adjacent patches into clusters (e.g., 4×4 patches per cluster), and prepending a fixed‑value separator cluster to each image. Multiple such (separator + clusters) sequences are concatenated to form a long sequence for the MambaMLP encoder, which operates autoregressively: each cluster predicts the next cluster. A lightweight cross‑attention decoder reconstructs the target clusters. For fine‑tuning, the encoder uses bidirectional scanning and a class token appended at the end of each image’s cluster sequence. This design leverages Mamba’s strength at long‑range dependency modeling while maintaining image‑level learning objectives.

## Key Results
- STAR‑B reaches 83.5% top‑1 accuracy on ImageNet‑1k after 1600 epochs of pretraining, surpassing prior Vision Mamba methods and matching MAE on ViT‑B.
- The approach quadruples the input sequence length without increasing per‑image token count, significantly improving training efficiency.
- Ablations confirm the importance of cluster‑based separators and the tail class token placement.

## Why This Works (Mechanism)
**Mechanism 1:** Inserting cluster‑based separator tokens before each image creates a clear boundary, enabling multiple images to be treated as a single long autoregressive sequence. The model processes a much longer context (e.g., 8 images × 160 tokens = 1280 tokens) while still reconstructing each image individually, leveraging Mamba’s efficient long‑sequence modeling. Evidence: The absence of separators (“None” baseline) severely degrades performance, while cluster‑based separators restore and improve accuracy.

**Mechanism 2:** Relocating the class token from the middle to the end of the visual sequence aligns the classification objective with the autoregressive pretraining flow. After processing all clusters of an image in order, the final cluster’s representation encodes the complete image, making it a more suitable feature for classification. Empirical support: moving the class token to the tail yields a 0.3% EMA accuracy gain.

**Mechanism 3:** Using separators with the same granularity as the prediction unit (clusters) ensures consistent processing by the MambaMLP. A separator of one cluster (e.g., 4×4 patches) matches the size of the basic autoregressive unit, avoiding mismatch. Ablations show cluster‑based separators significantly outperform token‑based alternatives.

## Foundational Learning
- **Autoregressive Next-Token Prediction**  
  *Why needed:* STAR’s pretraining objective extends language modeling’s next‑token prediction to clustered image patches, requiring a sequential causal loss. This underlies the need for separators to mark image boundaries and the rationale for placing the class token at the end.

- **State Space Model (SSM) Causal Mechanics**  
  *Why needed:* Mamba’s SSM is inherently causal and linear‑complexity, enabling efficient processing of long sequences. Understanding its discretization and convolution implementation explains why Mamba excels at long contexts and why careful sequence structuring (separators) is beneficial.  
  *Quick check:* Why is the causality of SSMs a prerequisite for autoregressive pretraining, and how does the “scan” operation in Mamba implement this for 2D image data?

- **Clustered Image Tokenization**  
  *Why needed:* Converting 2D images to 1D sequences requires tokenization; STAR groups adjacent patches into clusters (e.g., 4×4), reducing sequence length and enhancing local spatial coherence. This choice directly influences separator design and the autoregressive unit.  
  *Quick check:* How does grouping patches into clusters affect sequence length, receptive field, and spatial coherence compared to single‑patch tokens, and what are the trade‑offs?

## Architecture Onboarding
**Component map:**  
Input Processor -> Sequence Builder -> Causal Encoder (MambaMLP) -> Feature Extractor -> Lightweight Decoder -> Classification Head.

**Critical path:**  
Pretraining: [Image] -> [Patches] -> [Clusters] -> + [Separator Cluster] -> [Concatenated Long Sequence] -> [MambaMLP Encoder (1‑scan)] -> [All Cluster Outputs] -> [Causal Attention Decoder] -> [Reconstructed Next Cluster Pixels].  
Fine‑tuning: [Image] -> [Clusters] -> + [Separator Cluster] -> [Concatenated Sequence] -> [MambaMLP Encoder (4‑scan)] -> [Final Output Token] -> [Linear Head] -> [Class Logits].

**Design tradeoffs:**  
- Separator value: simple (zeros) vs. patterned (identity). Simpler may be easier to learn.  
- Number of images per sequence (N): longer sequences (e.g., 8, 16) better leverage Mamba but risk performance drop if too long; optimum around 4 for given compute.  
- Separator placement: prepending (SC) works best; post‑pending or dense separators add overhead without clear benefit.  
- Clustering granularity: smaller clusters increase sequence length and learning granularity but raise compute; larger clusters reduce both.

**Failure signatures:**  
1. No improvement when concatenating multiple images without separators indicates separator mechanism not functioning.  
2. Sharp performance drop when increasing N beyond 4 suggests effective context window exceeded.  
3. Token‑based separator underperforming cluster‑based confirms granularity mismatch.  
4. Decoder loss failing to decrease points to overly difficult targets or insufficient capacity.

**First three experiments to reproduce:**  
1. Baseline replication: single‑image autoregressive pretraining (no separator, class token mid‑sequence) on MambaMLP‑B for 200 epochs to establish ~81.8% FT accuracy.  
2. Separator type ablation: compare “No Separator” vs. “Cluster Separator (Zeros)” when concatenating 4 images; expect the former to degrade and the latter to restore/improve performance.  
3. Long‑sequence scaling (N): train with N=1, N=4, N=8 for equal epochs; verify peak at N=4 and drop at N=8.

## Open Questions the Paper Calls Out
1. **Optimal pretraining length:** What is the performance trajectory beyond 1600 epochs? Does accuracy continue to scale linearly or saturate?  
2. **Length bottleneck:** Why does accuracy decline when input sequences exceed ~640 tokens (4 images)? Is it due to model capacity, gradient flow, or scanning inefficiency?  
3. **Separator design optimality:** Could trainable or adaptive separators outperform the fixed handcrafted patterns (e.g., Identity)?  
4. **Generality of tail class token:** Does relocating the class token to the sequence end benefit other Vision Mamba architectures (e.g., VMamba, Vim) or only MambaMLP?  
5. **Decoder attention patterns:** Would allowing full bidirectional attention within clusters (while keeping inter‑cluster causality) improve reconstruction and downstream accuracy?
