# InnerQ: Hardware-aware Tuning-free Quantization of KV Cache for Large Language Models
## Quick Facts
- **arXiv ID:** 2602.23200
- **Source URL:** https://arxiv.org/abs/2602.23200
- **Reference count:** 40
- **Primary result:** InnerQ achieves up to 22% latency reduction versus prior outer-dimension quantization and up to 88% versus half-precision baselines at 2-bit KV cache, while maintaining GSM8K accuracy comparable to non-quantized models.

## Executive Summary
InnerQ introduces a hardware-aware, tuning-free method for quantizing the key-value (KV) cache in large language models to alleviate the memory bottleneck during decoding. By grouping quantization over the inner (channel) dimension of the KV cache, the method aligns dequantization with vector-matrix multiplication operations, enabling scale factor reuse across GPU compute units and reducing memory traffic. Additional techniques—including hybrid per-group symmetric/asymmetric quantization, high-precision windows for attention sink and recent tokens, and per-channel key normalization—preserve accuracy under aggressive 2-bit compression. Evaluated on Llama models, InnerQ significantly improves decode latency over prior methods while matching or exceeding the accuracy of full-precision baselines on downstream tasks like GSM8K.

## Method Summary
InnerQ modifies the KV cache management during autoregressive decoding. After the prefill phase, a per-channel normalization factor for keys is computed and folded into the query/key weight matrices to suppress outliers before quantization. During decoding, the cache is partitioned into three segments: a fixed-size high-precision buffer for the first tokens (attention sinks), another for the most recent tokens, and a quantized region for older tokens. Quantization applies group-wise 2-bit compression over the inner dimension (head size), with each group adaptively using symmetric or asymmetric mode based on local error. A fused kernel performs dequantization and matrix multiplication in a single pass, reusing scale factors per group to minimize memory accesses.

## Key Results
- Latency speedup of up to 22% over outer-dimension quantization (e.g., KIVI) and up to 88% over FP16 baselines for decode-phase vector-matrix multiplication.
- GSM8K accuracy comparable to full-precision models and superior to KIVI under 2-bit quantization.
- KV cache memory reduction to 2 bits per value plus small overhead for scale factors and hybrid mode masks.

## Why This Works (Mechanism)
### Mechanism 1: Inner-dimension grouping for scale factor reuse
Grouping the KV cache over the inner (channel) dimension ensures that all values in a given row belong to the same quantized group, sharing one scale factor. During the decode-phase vector-matrix multiplication (where a single query vector multiplies a key matrix of shape `[seq_len, head_dim]`), this shared scale factor is loaded once and reused for all multiply-accumulate operations within that group. In contrast, outer-dimension grouping places group boundaries across rows, forcing a separate scale factor load for each element in a row, increasing memory traffic. Because the operation is memory-bandwidth-bound, reducing scale factor loads directly improves throughput. Evidence: Paper shows 15–23% latency reduction for inner vs. outer grouping across models and sequence lengths (Section 5.3, Figure 3b).

### Mechanism 2: Hybrid symmetric/asymmetric quantization per group
For each quantization group, InnerQ computes the error of both symmetric (zero point = 0) and asymmetric quantization on the local statistics, then selects the mode with lower reconstruction error. This adapts to heterogeneous value distributions across groups—some symmetric around zero, others positively shifted—without requiring calibration data or per-sequence tuning. The selection uses "free" compute cycles during the already memory-bound quantization pass, and a 1-bit mask per group indicates the chosen mode with negligible overhead. Evidence: Hybrid quantization matches the latency of symmetric-only (Figure 4) and yields equal or better GSM8K accuracy compared to uniform symmetric or asymmetric modes (Table 2).

### Mechanism 3: High-precision windows and per-channel key normalization
Two techniques mitigate accuracy loss under low-bit quantization:
- **High-precision windows:** The first `wsink` tokens (attention sinks) and last `wrecent` tokens are kept in FP16/FP32 rather than quantized, protecting tokens that disproportionately influence attention or are critical for current prediction.
- **Per-channel key normalization:** At prefill end, compute `normK[i] = max(|K[:, i]|)` for each channel. Multiply the query projection weight matrix `WQ` by `normK` and divide the key projection weight matrix `WK` by `normK`. This folds the normalization into the weight matrices, leaving runtime attention computation unchanged but flattening per-channel key outliers before quantization, reducing quantization error. Evidence: Ablations (Figure 5a) show accuracy collapse when `wsink=0`, highlighting sink protection importance. InnerQ maintains GSM8K accuracy near full-precision while KIVI (without sink protection) degrades more (Table 2).

## Foundational Learning
### Concept: Group-wise Quantization
**Why needed:** InnerQ’s inner-dimension grouping is a specific case of group-wise quantization. Understanding how scale factors and zero points are computed per group, and the trade-offs in memory overhead (scale factors stored per group, not per element), is essential to grasp the efficiency gains.
**Quick check:** For a KV matrix of shape `[seq_len, head_dim]` with group size `G=32` grouped over the inner dimension, how many scale factors are needed per layer? How does this compare to outer-dimension grouping in terms of memory overhead and potential for reuse during decode?

### Concept: Decode-phase Attention Computation
**Why needed:** InnerQ’s design targets the decode phase where a length-1 query vector multiplies the cached key matrix. Knowing the shapes of Q, K, V during decode and how KV caching affects them is crucial to see why inner-dimension grouping helps.
**Quick check:** During autoregressive decoding, what are the dimensions of Q, K, and V? How does the shape of K and V change as the sequence grows?

### Concept: Memory-Bound vs. Compute-Bound Kernels
**Why needed:** The claim that hybrid quantization adds "no overhead" relies on the quantization kernel being memory-bound—extra ALU operations on already-loaded data are "free." Also, the speedup from inner-dimension grouping comes from reduced memory traffic.
**Quick check:** How would you profile a CUDA kernel to determine if it is memory-bound? Why does a memory-bound kernel allow hybrid mode selection to incur negligible latency?

### Concept: Attention Sinks
**Why needed:** InnerQ’s high-precision window specifically protects "attention sink" tokens (early tokens that accumulate disproportionate attention mass). This concept explains why `wsink` is needed beyond just recent tokens.
**Quick check:** What are attention sinks in transformer models, and why might they be especially sensitive to quantization artifacts in the KV cache?

### Concept: Foldable Normalization
**Why needed:** Per-channel key normalization is applied once at prefill and "folded" into the query/key weight matrices to avoid runtime cost. Understanding how to absorb per-channel scaling into linear layer weights is key to the zero-overhead claim.
**Quick check:** Given a per-channel normalization vector `normK` for keys, show mathematically how to modify `WQ` and `WK` so that the overall attention output remains unchanged and no extra runtime operations are needed.

## Architecture Onboarding
### Component map
KV Cache Manager -> Quantization Engine -> Fused Attention Kernels
Prefill Normalizer -> (modifies WQ, WK) -> Fused Attention Kernels
Configuration Store -> all components

### Critical path (during decode of token t)
1. Compute K_t, V_t = X_t @ WK, X_t @ WV (FP16).
2. Append K_t, V_t to Krecent, Vrecent.
3. If len(Krecent) > wrecent, pop oldest G tokens from Krecent/Vrecent, quantize via Quantization Engine, append to Kcache/Vcache.
4. In attention:
   - Compute S = concat( Q @ Ksink^T, QuantizedMatmul(Q, Kcache^T), Q @ Krecent^T )
   - Compute P = softmax(S / sqrt(d_h) + mask)
   - Compute O = concat( P @ Vsink, QuantizedMatmul(P, Vcache), P @ Vrecent )
   - O = O @ WO
5. Return O.
The latency-critical loops are the `QuantizedMatmul` kernels, which must fuse dequantization and matrix multiplication with inner-dimension scale factor reuse.

### Design tradeoffs
- **Group size (G):** Smaller G (e.g., 16) reduces per-group outlier impact but increases scale factor count and may reduce reuse benefit. Paper uses G=32.
- **Window allocation (`wsink` vs. `wrecent`):** Larger `wsink` protects attention sinks but reduces `wrecent` budget. Paper uses fixed `wsink=32, wrecent=96`. Adaptive allocation is future work.
- **Hybrid mask storage:** 1 bit per group adds ~0.2% overhead for G=32. Could be omitted under extreme memory constraints, but accuracy may suffer (Table 2 shows hybrid best).
- **Per-channel norm:** Sometimes disabled (e.g., Llama 2-13B) after hyperparameter search; may be model-dependent.

### Failure signatures
1. **Accuracy collapse on GSM8K:** If exact-match drops >2% vs. baseline:
   - Sink tokens not in high-precision buffer? Check `wsink` implementation.
   - Per-channel norm misapplied? Verify `normK` values are finite and weight folding is mathematically correct.
   - Hybrid mode inactive? Monitor ratio of symmetric vs. asymmetric groups; extreme skew may indicate heuristic failure.
2. **Latency worse than outer-dimension quantization:** If inner-dim speedup < 10% (expected 15–23%):
   - Kernel not fused? Check for separate dequant+gemm launches.
   - Scale factors not reused? Inspect shared memory usage in kernel.
   - Group size too small or sequence length too short.
3. **Memory overhead larger than theoretical:** Expected size = `2 bits * 2 * seq_len * num_layers * num_heads * head_dim / 8 + overhead`. If actual >> expected:
   - Mask stored as 32-bit integers instead of packed bits.
   - High-precision buffers not shared across layers (should be shared).
   - Scale factors stored in FP32 when FP16 suffices.

### First 3 experiments
1. **Functional correctness with dummy data:** Implement a 1-layer, 4-head transformer (head_dim=16). Compute attention output with and without InnerQ (2-bit, G=32) on random input (seq_len=64). Assert max absolute difference < 1e-3 and cosine similarity > 0.999 to validate quantization, dequantization, weight folding, and window management.
2. **Kernel throughput benchmark (reproducing Figure 3):** Implement fused Triton/CUDA kernels for inner-dim and outer-dim grouped dequant+matmul. Measure median latency over 1000 runs for sequence lengths [512, 1024, ..., 131072] on RTX 4090. Confirm inner-dim is 15–23% faster than outer-dim and ~88% faster than FP16 `torch.matmul`.
3. **End-to-end accuracy on GSM8K:** Load pretrained Llama 3.1-8B, apply InnerQ with default hyperparameters (`wsink=32, wrecent=96, G=32, 2-bit`). Run LM-eval few-shot GSM8K. Confirm exact-match within ±1% of full-precision baseline and higher than KIVI baseline. Then ablate: set `wsink=0` and disable per-channel norm to measure their individual impact.

## Limitations
- Unknowns in hybrid quantization mask storage format and exact kernel implementation details may hinder faithful reproduction.
- Fixed window sizes (`wsink=32, wrecent=96`) may not generalize across models or tasks; adaptive strategies unexplored.
- Head dimension must be divisible by group size (32); other dimensions require padding, reducing efficiency.
- Per-channel normalization effectiveness appears model-dependent (e.g., disabled for Llama 2-13B).

## Confidence
- **A. Inner-dimension grouping reduces memory traffic and latency:** High. Mechanism clearly explained; consistent 15–23% speedup reproduced across models/sequence lengths.
- **B. Hybrid per-group quantization maintains 2-bit accuracy with negligible overhead:** High. Hybrid matches/exceeds uniform methods in accuracy; latency parity confirmed.
- **C. High-precision windows + per-channel normalization preserve accuracy:** Medium. Ablation shows sink importance, but normalization benefit may be model-specific; limited hyperparameter study.
- **Overall D. InnerQ outperforms KIVI and matches full-precision:** High. GSM8K results and latency measurements support this, though evaluation restricted to Llama family.
