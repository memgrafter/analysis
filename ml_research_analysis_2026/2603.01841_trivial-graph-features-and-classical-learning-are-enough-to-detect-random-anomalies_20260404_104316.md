# Trivial Graph Features and Classical Learning are Enough to Detect Random Anomalies

## Quick Facts
- arXiv ID: 2603.01841
- Source URL: https://arxiv.org/abs/2603.01841
- Reference count: 34
- Primary result: TGF achieves AUC >0.95 on random anomaly detection across nine datasets, outperforming state-of-the-art methods.

## Executive Summary
Anomaly detection in link streams suffers from a scarcity of labeled data, leading to evaluation via random link injection. This paper introduces TGF (Trivial Graph Features), a method that constructs multi-resolution history graphs—time-based G and size-based H—and extracts simple graph features (e.g., node degrees, link weights) for each candidate link. A random forest classifier trained on normal versus randomly injected anomalous links achieves AUC scores frequently above 0.95 (up to 0.9958) across nine diverse datasets and injection rates (1%, 5%, 10%). TGF also demonstrates high efficiency, processing over 13,000 to 1,000,000 links per second on a standard laptop with O(1) time and space per link, and it surpasses state-of-the-art approaches including RustGraph. The method’s simplicity, interpretability, and computational thriftiness make it a compelling baseline for random anomaly detection in streaming graphs.

## Method Summary
TGF operates on a continuous stream of links (edges with timestamps). It maintains two sliding windows: a time-based graph G that aggregates links within fixed temporal intervals, and a size-based graph H that keeps the most recent N links. When a new link arrives, both graphs are updated incrementally. For the new link, a set of trivial graph features is computed from G and H, including degrees of the endpoint nodes, the weight of the link (number of co-occurrences), counts of common neighbors, and statistics over multiple resolutions. These features form a vector that is fed to a random forest classifier, which outputs an anomaly probability. The design ensures each link is processed in constant time and space, independent of total stream size, by limiting window sizes and updating aggregated statistics in O(1). Training uses a labeled set generated by injecting random links into a normal stream, thus avoiding the need for manual anomaly annotations.

## Key Results
- TGF achieves AUC scores >0.95 across all nine datasets and injection rates (1%, 5%, 10%), reaching up to 0.9958.
- It consistently outperforms state-of-the-art methods, including the recent RustGraph approach.
- The method processes 13,000 to 1,000,000 links per second on a standard laptop with O(1) time and space per link, demonstrating high scalability.

## Why This Works (Mechanism)
Randomly injected anomalies tend to connect nodes that are rarely linked in the normal stream, resulting in low degrees, low co-occurrence weights, and sparse common neighborhoods. Trivial graph features directly capture these deviations. The multi-resolution graphs (time-based and size-based) provide two complementary contexts: the time-based G reflects recent activity within fixed calendar windows, while the size-based H captures recency irrespective of clock time. Both offer stable estimates of normal link characteristics. A random forest can efficiently learn non-linear thresholds on these simple features, separating injected anomalies from normal links. The approach’s simplicity avoids overfitting to complex patterns that are irrelevant for random anomalies, and the features remain interpretable—e.g., anomalous links often connect low-degree nodes—allowing for diagnostic insights.

## Foundational Learning
- **Trivial Graph Features** (e.g., node degrees, link weights)  
  *Why needed*: They offer fast-to-compute, discriminative signals that deviate for random anomalies.  
  *Quick check*: Compare endpoint degrees to historical averages; unusually low values suggest anomalies.

- **Multi-Resolution History Graphs** (time-based G and size-based H)  
  *Why needed*: Provide both temporal and recency-based contexts, capturing different normal-link patterns.  
  *Quick check*: Maintain sliding windows with O(1) updates; ensure features from both graphs are extracted.

- **Random Forest Classification**  
  *Why needed*: Combines multiple weak features into a strong, non-linear classifier with minimal tuning.  
  *Quick check*: Train on a balanced set of normal and random links; validate AUC >0.9 on a holdout set.

- **Random Link Injection**  
  *Why needed*: Generates synthetic anomalies for supervised training when real labels are unavailable.  
  *Quick check*: Inject a known fraction of random links; confirm classifier detects them with high recall.

## Architecture Onboarding
**Component map**  
Link Stream -> Feature Extractor (maintains G and H graphs) -> Feature Vector -> Random Forest Classifier -> Anomaly Score

**Critical path**  
1. Ingest a new link (u, v, timestamp).  
2. Update time-based graph G: add link to current time bucket, evict links older than the time window.  
3. Update size-based graph H: add link, and if size exceeds limit, remove the oldest link.  
4. Compute trivial features from G and H for nodes u, v and the pair (u,v).  
5. Assemble feature vector.  
6. Apply random forest to obtain anomaly probability.  
7. Output score (and flag if above threshold).

**Design tradeoffs**  
- Simplicity vs. expressive power: Trivial features are cheap but may not capture sophisticated attacks.  
- Efficiency vs. resolution: Bounded windows guarantee O(1) operations but limit historical depth, affecting detection of long-term anomalies.  
- Random-injection training vs. realism: Provides a supervision signal but risks bias toward random patterns that differ from real threats.

**Failure signatures**  
- High false negatives for anomalies that mimic normal link statistics (e.g., targeted attacks between high-degree hubs).  
- Degraded performance under concept drift if window size is too small to capture stable normals.  
- Overfitting to random injection artifacts when random forest depth is not controlled.

**First experiments**  
1. Replicate AUC >0.95 on the enron dataset with 5% random injection.  
2. Ablate each feature group (degrees, weights, common neighbors) to measure impact on performance.  
3. Stream 10 million synthetic links, measure throughput and memory, and confirm O(1) per-link behavior.

## Limitations
- Evaluation is based solely on random link injection, which may not reflect real-world anomaly characteristics.
- Experimental validation uses only nine datasets, limiting domain diversity and risking dataset bias.
- Efficiency claims (O(1) per-link, >13,000 links/s) need broader validation on larger streams and diverse hardware.

## Confidence
- Performance on random anomalies: **High**
- Computational efficiency: **Medium**
- Simplicity and interpretability: **Medium**
