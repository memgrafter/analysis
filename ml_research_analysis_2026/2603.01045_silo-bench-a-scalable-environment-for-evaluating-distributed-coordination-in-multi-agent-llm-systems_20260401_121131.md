# Silo-Bench: A Scalable Environment for Evaluating Distributed Coordination in Multi-Agent LLM Systems

## Quick Facts
- **arXiv ID:** 2603.01045  
- **Source URL:** https://arxiv.org/abs/2603.01045  
- **Reference count:** 35  
- **Primary result:** Multi-agent LLM systems spontaneously form task-appropriate communication topologies but fail to synthesize distributed information into correct answers, revealing a fundamental Communication-Reasoning Gap that worsens with scale.

## Executive Summary
This paper introduces SILO-BENCH, a benchmark of 30 algorithmic tasks designed to evaluate whether multi-agent LLM systems can coordinate to compute answers from distributed information shards. Across 1,620 experiments using models like DeepSeek-V3.1 and GPT-OSS-120B, agents successfully self-organized into efficient communication patterns (e.g., star topologies for aggregation tasks). However, they consistently failed to integrate the gathered information into correct final solutions—a failure localized to the reasoning stage rather than communication. As agent count and task complexity increased, coordination overhead compounded nonlinearly, eliminating any parallelization benefits and causing success rates to drop to zero for large-scale complex tasks. The work exposes a critical limitation: current LLM agents can exchange data but cannot collectively reason over it.

## Method Summary
SILO-BENCH operationalizes distributed algorithmic tasks from communication complexity theory (Level I: aggregation, Level II: mesh, Level III: global shuffle). For each run, a global input is partitioned among *N* agents (2 to 100), who interact via one of three protocols (P2P mailboxes, broadcast, or shared filesystem) over up to 100 synchronized rounds. Agents receive only their local shard and a natural language task description; they must use protocol actions (`send_message`, `write_file`, `submit_result`) to collaborate. Primary metrics are Success Rate (fraction of correct final answers) and Partial Correctness Score (fraction of required data acquired). The single-agent baseline with full data enables computing Relative Coordination Cost (RCC) to quantify overhead.

## Key Results
- Agents spontaneously emerged communication topologies matching theoretical optima (e.g., star for global max), demonstrating innate coordination ability.
- A consistent gap between Partial Correctness Score and Success Rate indicated agents gathered data but could not integrate it; on complex tasks at *N*≥50, Success Rate fell to 0% while Partial Correctness remained 8–16%.
- Coordination overhead compounded superlinearly with team size, yielding RCC of 80–100% for medium/complex tasks at *N*=50—multi-agent teams performed no better than a single agent would with full information.

## Why This Works (Mechanism)

### Emergent Topology Formation
Agents independently choose communication partners each round based on task descriptions. Over rounds, aggregate message flows self-organize into patterns approximating the minimal-communication solution (e.g., all-to-one star for Level-I aggregation). The core assumption is that agents infer dependency structures from natural language and adapt routing. Evidence: heatmaps show near-perfect star for Global Max and diagonal bands for Prefix Sum [section 5.1]. Emergence degrades at *N*≥20 as communication grows sparser despite increased coordination need.

### The Communication-Reasoning Gap
The evaluation separates information acquisition (Partial Correctness Score, *P*) from final answer correctness (Success Rate, *S*). The persistent *P* > *S* gap across scales and models shows the bottleneck lies in synthesizing distributed state—agents cannot detect information sufficiency or compute correctly on collected data. Evidence: DeepSeek-V3.1 achieves *P*=88.0% vs. *S*=62.0% (gap 26 pp) on Level-I; at *N*≥50 Level-III, *S*=0% while *P* remains 8–16% [section 4.2]. Failure analysis cites "Computation Error" (28.6%) and "Consensus Failure" (29.9%) [section 5.2].

### Coordination Overhead Compounds Nonlinearly
Each additional agent adds cognitive load (parsing messages, state-tracking) that multiplies rather than adds. Agents produce redundant messages, verification loops, and leader-election chatter, incurring a "synchronization tax." Relative Coordination Cost (RCC = 1 − *SR*(*N*=*k*)/*SR*(*N*=1)) quantifies lost efficiency; RCC reaches 80–100% for Level-II/III at *k*=50 [section 4.2]. Leader emergence actively hurts on Level-III as aggregators become overwhelmed [section 5.3].

Quick check: For global maximum across 10 agents, what is the minimal number of data transfers and which topology achieves it?
- **LLM Agent Execution Loop (Synchronous Rounds, Message Buffers)** – Needed to interpret metrics like Communication Density and understand round boundaries. Quick check: In P2P, when does an agent receive a message sent in round *r*? (Answer: start of round *r*+1.)

## Architecture Onboarding
- **Component map:** Task Generator -> Protocol Engine -> Agent Wrapper -> Metric Aggregator -> Experiment Orchestrator
- **Critical path:** `PARTITION(X, N)` → `INIT(i)` → `for r in 1..Rmax: [agents act concurrently]` → `if all submitted: break` → `compute_metrics()`
- **Design tradeoffs:** 
  - Role-agnostic prompts avoid bias but may inhibit beneficial specialization.
  - Fixed random seeds per configuration ensure reproducibility but limit statistical sampling.
  - Only three protocols (P2P, BP, SFS) cover addressing paradigms but exclude hierarchical/gossip.
- **Failure signatures:**
  - P-S Divergence: Partial Correctness >> Success Rate (e.g., P=88%, S=62% for DeepSeek Level-I).
  - Communication Density ↓ with *N*: Agents interact less as team grows (Figure 4c).
  - Leader emergence correlates with failure on Level-III tasks.
  - RCC → 100%: Multi-agent SR approaches single-agent baseline minus coordination cost.
- **First 3 experiments:**
  1. Baseline sanity check: Global Max (I-01) with *N*=2, P2P, DeepSeek → Expect ~100% SR.
  2. Scale stress test: Distributed Sort (III-21) with *N*=50, P2P, DeepSeek → Expect SR=0%, high PCS (~10-16%), RCC≈100%.
  3. Protocol comparison: Prefix Sum (II-11) with *N*=10 across P2P, BP, SFS → Expect P2P > BP > SFS.

## Open Questions the Paper Calls Out
- **Question:** How to detect information sufficiency? Basis: Sec 5.3 identifies need for sufficiency detection. Unresolved because premature submission and computation errors persist. Evidence needed: Implement sufficiency thresholds; track drop in PCS-SR gap.
- **Question:** How to formalize synchronization checkpoints? Basis: Sec 5.3 suggests checkpoints help. Unresolved because consensus failures remain. Evidence needed: Add commit-reveal steps; measure consensus failure reduction.
- **Question:** Does adaptive protocol selection improve scalability? Basis: Sec 5.3 proposes adaptation. Unresolved because static protocols fail at *N*≥50; model-protocol affinities observed. Evidence needed: Let agents choose protocols per task; compare scaling on Level-III.
- **Question:** How does heterogeneity impact coordination? Basis: Inferred from limitations (only uniform models tested). Unresolved because real systems are heterogeneous. Evidence needed: Mixed-model teams; compare success rate and communication density.

## Limitations
- Prompt reconstruction: Exact wording for all 30 task prompts is unspecified; minor variations could alter agent behavior and topology formation.
- Protocol implementation: Critical runtime details (message delivery guarantees, tokenization of overhead, file-write concurrency) are missing, preventing exact metric replication.
- External validation: The corpus shows near-zero citations; findings lack independent corroboration or cross-study validation.

## Confidence
- **Communication-Reasoning Gap:** High – robustly supported by consistent PCS-SR divergence across scales, models, and tasks (e.g., DeepSeek PCS 88% vs. SR 62% on Level-I).
- **Emergent Topology Formation:** Medium – heatmap evidence aligns with theoretical optima, but emergence degrades sharply at *N*≥20, suggesting fragility.
- **Coordination Overhead Compounding:** Medium-Low – RCC trends are clear (80–100% at *N*=50), but the mechanistic "synchronization tax" is inferred from outcomes, not directly measured.

## Next Checks
1. Reproduce core gap: Run DeepSeek, P2P, Global Max *N*=2 vs. Distributed Sort *N*=50 to confirm SR collapse to 0% despite non-zero PCS.
2. Prompt sensitivity test: Modify Level-III prompts to include explicit integration cues (e.g., "verify you have all data before computing"); measure whether SR improves without increasing PCS.
3. Token overhead audit: Instrument the protocol engine to log metadata (message headers, timestamps, action parsing tokens) and recompute Communication Density and Token Consumption to validate overhead scaling.
