# MUTEX: Leveraging Multilingual Transformers and Conditional Random Fields for Enhanced Urdu Toxic Span Detection
## Quick Facts
- **arXiv ID:** 2603.05057
- **Source URL:** https://arxiv.org/abs/2603.05057
- **Reference count:** 40
- **Primary result:** Achieves 60.0% token-level F1 as the first supervised baseline for Urdu toxic span detection.

## Executive Summary
This study introduces MUTEX, the first explainable framework for detecting toxic spans in Urdu text, addressing challenges like morphological richness, code-switching, and script variation. The authors manually annotate the URTOX dataset (14,342 samples, κ=0.81) and employ a XLM-RoBERTa encoder with a CRF layer for sequence labeling. MUTEX achieves a token-level F1 of 60.0%, surpassing mBERT and BiLSTM baselines by 4.0%. Key contributions include a comprehensive preprocessing pipeline that recovers 6.2% F1, the CRF layer that enforces valid BIO sequences and adds +1.3% F1, and multi-domain training that reduces cross-domain performance gaps from 12% to 3.6%.

## Method Summary
MUTEX uses a preprocessing pipeline tailored for Urdu's heterogeneity (Unicode normalization, diacritic handling, Roman Urdu conversion, noise removal, whitespace normalization, word segmentation). Text is tokenized with a customized SpaCy model and fed into a XLM-RoBERTa base model to generate contextual token embeddings. A linear emission layer projects embeddings to label scores, which are passed to a CRF layer to decode valid BIO tag sequences (B-TOXIC, I-TOXIC, O). The model is trained with a class-weighted loss to handle label imbalance, using Adam optimization and early stopping. For explainability, integrated gradients compute token-level attributions relative to a zero embedding baseline. Multi-domain training mixes samples from social media, news, and YouTube with balanced mini-batches to improve generalization.

## Key Results
- **60.0% token-level F1** on the URTOX test set, establishing the first supervised baseline for Urdu toxic span detection.
- **CRF yields +1.3% F1 gain** and reduces invalid BIO sequences from 8.3% to 0.0%.
- **Multi-domain training** reduces cross-domain performance disparity from 12% (single-domain) to 3.6%.

## Why This Works (Mechanism)
### Mechanism 1: Multilingual Transformer Embeddings
- **Claim:** XLM-RoBERTa provides robust contextual representations for Urdu toxic span detection despite morphological richness and code-switching.
- **Mechanism:** The model processes tokenized Urdu text through multi-head self‑attention, learning contextual embeddings that capture long‑range dependencies and cross‑lingual patterns from its multilingual pretraining on CommonCrawl. This allows it to implicitly handle morphological variations and script inconsistencies.
- **Core assumption:** The pretrained knowledge in XLM‑RoBERTa transfers effectively to the toxic span detection task, even though Urdu constitutes less than 1% of its pretraining corpus.
- **Evidence anchors:**  
  - [abstract] "MUTEX employs XLM‑RoBERTa with a CRF layer for sequence labeling, achieving 60.0% token‑level F1"  
  - [section 3.5.2] "XLM‑RoBERTa is a multi‑lingual transformer, which was trained on the CommonCrawl data and it provides powerful multi‑lingual representation especially in low-resource languages"  
- **Break condition:** If Urdu‑specific features (e.g., Romanization, code‑switching) are not adequately normalized, performance degrades (e.g., Roman Urdu penalty 2.0%, code‑switching penalty 1.4% in bias analysis).

### Mechanism 2: Conditional Random Fields for Sequence Consistency
- **Claim:** Adding a CRF layer on top of the transformer yields a 1.3% token‑level F1 gain and enforces valid BIO tag sequences, improving span boundary detection.
- **Mechanism:** The CRF learns transitional probabilities between consecutive BIO labels, globally optimizing the label sequence to avoid invalid transitions (e.g., an I‑TOXIC without a preceding B‑TOXIC). It leverages emission scores from the transformer’s hidden states to produce coherent spans.
- **Core assumption:** Toxic spans in Urdu follow BIO‑tag structure; modeling label dependencies reduces fragmentation and over‑extension of predicted spans.
- **Evidence anchors:**  
  - [section 3.5.3] "In order to make token‑level span prediction more accurate, a CRF layer is placed over transformer embeddings. The CRF records dependencies between labels, and provides valid BIO sequences, enhancing the consistency of sequences."  
  - [section 4.3.1] "CRF layer improves token‑level F1 by 1.3 percentage points (58.7% → 60.0%) and invalid BIO sequences reduced from 8.3% to 0.0%."  
- **Break condition:** If the transformer embeddings are noisy (e.g., due to insufficient preprocessing), the CRF may still generate valid but incorrect sequences.

### Mechanism 3: Comprehensive Preprocessing Pipeline
- **Claim:** A series of preprocessing steps (Unicode normalization, Roman Urdu conversion, diacritic handling, noise removal, whitespace normalization, word segmentation) collectively boost performance by 6.2% F1.
- **Mechanism:** These steps standardize the raw input text, reducing script variation and noise that would otherwise split tokens or create spurious patterns. For example, converting Roman Urdu to Nastaliq script aligns orthographic variants, while Unicode normalization ensures consistent character encoding.
- **Core assumption:** Raw Urdu social media text is highly heterogeneous; cleaning it yields more uniform tokenization and better model generalization.
- **Evidence anchors:**  
  - [section 3.5.1] Lists the full preprocessing pipeline with specifics for Urdu challenges.  
  - [section 4.3.3] "Roman Urdu conversion is the most sensitive … aggregate impact of eliminating all steps in preprocessing leads to a 6.2% F1 loss."  
- **Break condition:** Incorrect conversion (e.g., ambiguous Roman‑to‑Nastaliq mappings) may remove or distort toxic content, leading to false negatives.

## Foundational Learning
- **Concept: Token‑level sequence labeling with BIO tags**  
  **Why needed:** The task requires marking exact toxic tokens, not whole sentences. BIO tagging defines span boundaries: B‑TOXIC marks start, I‑TOXIC continues, O denotes non‑toxic. This formulation allows the model to learn from fine‑grained annotations in URTOX.  
  **Quick check:** If a toxic phrase "bewakoof aadmi" (stupid person) spans two tokens, how would it be labeled?  
  (Answer: "bewakoof" → B‑TOXIC, "aadmi" → I‑TOXIC)

- **Concept: Conditional Random Fields (CRF)**  
  **Why needed:** CRFs model label dependencies, ensuring valid BIO sequences and improving span coherence beyond independent token classification. They are especially useful when toxic spans follow sequential constraints.  
  **Quick check:** What problem does a CRF solve that a simple softmax classifier per token does not?  
  (Answer: It enforces global sequence consistency, preventing invalid transitions like I‑TOXIC after O.)

- **Concept: Integrated gradients for explainability**  
  **Why needed:** Integrated gradients attribute model predictions to input tokens, providing mathematically grounded rationales for why certain words were flagged as toxic. This aids human moderators in understanding and auditing decisions.  
  **Quick check:** What two axioms does integrated gradients satisfy?  
  (Answer: Sensitivity and implementation invariance.)

## Architecture Onboarding
**Component map:**  
Raw text -> Preprocessor -> Tokenizer (SpaCy) -> XLM-RoBERTa encoder -> Linear emission layer -> CRF decoder -> Predicted BIO tags -> Integrated gradients -> Output interface (highlighted spans & attributions)

**Critical path:**  
`Raw text → Preprocessing → Tokenization → XLM-RoBERTa forward pass → CRF Viterbi decoding → Post-processing (BIO → character offsets) → Integrated gradients attribution → Human‑readable output`

**Design tradeoffs:**  
- **CRF vs. no CRF:** CRF adds ~1.3% F1 gain and eliminates invalid sequences but slightly increases training/inference complexity.  
- **Preprocessing intensity:** Aggressive Roman Urdu conversion reduces script bias but risks losing information if conversion is inaccurate; the ablation shows Roman conversion contributes 3.7% F1, so it is essential.  
- **Multi‑domain vs. single‑domain training:** Multi‑domain reduces cross‑domain gaps (from 12% to 3.6%) but may sacrifice up to 3.7% in‑domain performance on social media; trade‑off favors deployment across platforms.

**Failure signatures:**  
- **Boundary errors (34% of failures):** Spans truncated or extended, e.g., detecting only "stupid" instead of "extremely stupid person."  
- **Code‑switching errors (18%):** Toxic expressions crossing Urdu/English boundaries often partially missed, e.g., "tu bohat stupid hai."  
- **Context‑dependent toxicity (28%):** Sarcasm or cultural references requiring discourse context.  
- **Implicit toxicity (12%):** Indirect insults lacking explicit keywords.

**First 3 experiments:**  
1. **Baseline comparison:** Train XLM-RoBERTa without CRF and compute token-level F1; then add CRF and measure the delta (expected +1.3%).  
2. **Preprocessing ablation:** Remove Roman Urdu conversion, Unicode normalization, etc. sequentially and quantify F1 changes to prioritize steps.  
3. **Cross-domain transfer:** Train on a single domain (e.g., Social Media) and evaluate on the other two domains (News, YouTube) to expose domain gaps; then retrain with multi-domain data to measure improvement.

## Open Questions the Paper Calls Out
- **How can audio-based toxic span detection be integrated with text-based models to improve detection of spoken Urdu toxicity in multimodal content?**  
  *Basis:* Section 6.3.1 proposes extending to audio-based detection, building an ASR pipeline with word-level timestamps, and cross-modal fusion with prosodic cues.  
  *Why unresolved:* MUTEX is text-only, missing spoken toxicity from podcasts, videos, or voice messages; ASR errors and temporal alignment challenges remain unaddressed.  
  *What evidence would resolve it:* Implementing and evaluating an ASR-toxicity pipeline on Urdu speech datasets, measuring F1 degradation from ASR errors, and testing fusion architectures for multimodal improvement.

- **What pretraining or architectural modifications can enhance multilingual transformer performance for Urdu to narrow the ~10% gap with English toxic span detection?**  
  *Basis:* Section 6.3.2 suggests larger Urdu-specific pretraining and few-shot learning; Section 5.2 attributes gaps to limited pretraining data (<1% Urdu in XLM-R) and morphological complexity.  
  *Why unresolved:* XLM-RoBERTa uses minimal Urdu data, leading to weak semantic representations; no Urdu-centric models exist for this task.  
  *What evidence would resolve it:* Training monolingual Urdu transformers on larger corpora (100M+ tokens) or using domain-adaptive pretraining, then comparing token-level F1 against XLM-RoBERTa baseline.

- **Can model architectures be improved to detect sarcasm and context-dependent toxicity, which cause 22.5% of errors in Urdu social media text?**  
  *Basis:* Section 6.1.1 and 6.2.2 identify sarcasm and implicit toxicity as major failure modes; transformers struggle with pragmatic meaning without discourse context.  
  *Why unresolved:* Current models rely on local token patterns and lack mechanisms for conversational intent or cultural nuance reasoning.  
  *What evidence would resolve it:* Incorporating discourse-level features (e.g., conversation threads) or external knowledge, then evaluating on a sarcasm-annotated subset of URTOX for F1 gains.

- **How effective is zero-shot transfer learning from Urdu to other low-resource South Asian languages (e.g., Hindi, Punjabi) for toxic span detection?**  
  *Basis:* Section 6.3.3 mentions expanding to Hindi, Punjabi, Bengali; preliminary zero-shot F1 of 54–62% is noted but not systematically studied.  
  *Why unresolved:* Typological similarities may enable transfer, but script differences and language-specific toxicity expressions require validation without target-language annotations.  
  *What evidence would resolve it:* Training on URTOX and testing on manually annotated or existing datasets for related languages, measuring token-level F1 and error patterns across linguistic boundaries.

- **What span representation techniques can reduce boundary detection errors, which account for 39% of failures in Urdu toxic span detection?**  
  *Basis:* Section 6.2.1 states boundary errors as primary failure mode; CRF layer only gives +1.3% F1 improvement, indicating need for better span modeling.  
  *Why unresolved:* Urdu's morphological richness and multi-word toxic phrases challenge exact boundary localization; current CRF enforces valid BIO but not fine-grained span matching.  
  *What evidence would resolve it:* Implementing span-based pretraining objectives (e.g., SpanBERT) or boundary-refining modules, then evaluating span-level F1 and boundary precision/recall on URTOX.

## Limitations
- **Reproducibility gaps:** Exact Roman Urdu→Nastaliq mapping rules, CRF transition constraints, and final hyperparameters are not released, hindering exact replication of the 60.0% F1.
- **External validity:** URTOX is limited to three domains (social media, news, YouTube); performance on other platforms or dialects is unknown. Corpus analysis shows low average citations (0.0) and moderate FMR (0.474), suggesting limited community validation.
- **Interpretability utility:** Integrated gradients attributions are provided, but no human moderator study confirms they improve decision accuracy or speed. The claim that explainability aids moderation remains unevaluated.
- **Performance ceiling:** 60.0% token F1 leaves substantial error (boundary, code-switching, implicit toxicity). The paper does not compare to newer multilingual LLMs (e.g., mT5, BLOOM) or few-shot prompting, which might outperform the supervised baseline.

## Confidence
- **Primary result (60.0% F1):** **Medium**. Supported by internal experiments and ablations, but dependent on unreleased preprocessing and hyperparameter details.
- **CRF contribution (+1.3% F1):** **High**. Clear ablation with statistical significance reported and invalid sequences reduced to 0%.
- **Preprocessing impact (6.2% gain):** **Medium**. Ablation shows aggregate effect, but individual steps (especially Roman conversion) lack precise error analysis and mapping specifications.
- **Cross-domain generalization:** **Medium**. Multi-domain training reduces gap from 12% to 3.6%, but only tested on the three curated domains; transfer to truly out-of-distribution data is unexplored.
- **Explainability benefit:** **Low**. No empirical study with human moderators; attributions are shown but not linked to performance metrics.

## Next Checks
1. **Roman Urdu conversion fidelity:** Implement the paper's described transliteration rules and compute character/word-level accuracy against a held-out set of Roman-Nastaliq pairs. A >95% accuracy is needed to justify the reported 3.7% F1 gain.
2. **CRF transition constraints replication:** Re-run the baseline (XLM-R without CRF) and full model with a standard BIO CRF (valid transitions: O→B, B→I, I→I, B→O, I→O, O→O). Confirm the 1.3% F1 improvement and 0% invalid sequences. If constraints differ, report sensitivity.
3. **Zero-shot cross-platform evaluation:** Test the trained MUTEX model on a fresh Urdu dataset from a different platform (e.g., Twitter/X or WhatsApp) without retraining. Measure F1 drop relative to in-domain (URTOX) test; a drop >5% would question deployment robustness.
