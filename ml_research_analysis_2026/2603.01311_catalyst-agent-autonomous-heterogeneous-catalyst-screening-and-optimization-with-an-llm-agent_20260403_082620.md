# Catalyst-Agent: Autonomous heterogeneous catalyst screening and optimization with an LLM Agent

## Quick Facts
- **arXiv ID:** 2603.01311
- **Source URL:** https://arxiv.org/abs/2603.01311
- **Reference count:** 40
- **Primary result:** Achieved 23–34% success rate in catalyst discovery, converging in an average of 1–2 trials per success; identified promising candidates such as Sn₃Sc for CO₂ reduction.

## Executive Summary
Catalyst-Agent presents an AI-driven framework for autonomous catalyst discovery and optimization. It leverages a large language model (LLM) as a central orchestrator, interfacing with Model Context Protocol (MCP) servers to perform key tasks: retrieving candidate materials from databases, fetching crystal structures, applying surface modifications (strain, doping), and evaluating adsorption energies using Meta FAIRchem's UMA graph neural network via the AdsorbML workflow. The closed-loop system iteratively refines near-miss candidates by applying physical perturbations until adsorption energies fall within a target window for a given reaction. The system was evaluated on three important reactions—oxygen reduction (ORR), nitrogen reduction (NRR), and carbon dioxide reduction (CO₂RR)—achieving a success rate of 23–34% across tested materials. Moreover, successful catalysts were identified after an average of only 1–2 modification trials per candidate. Notable discoveries include Sn₃Sc as a promising CO₂ reduction catalyst, and the agent demonstrated that surface-level tuning could convert near-miss materials into viable options, highlighting the effectiveness of the iterative refinement loop.

The work demonstrates the potential of LLM agents to automate complex scientific workflows by combining modular tools with machine learning potentials. While the current implementation relies on proprietary LLM APIs and faces limitations such as potential planning errors and restricted modification strategies, it offers a scalable path toward accelerated catalyst screening.

## Method Summary
The Catalyst-Agent system employs an LLM (GPT-5.2 in Codex CLI) to plan and execute a multi-step screening pipeline. The agent interprets a user prompt specifying the target reaction, adsorbates, and desired adsorption energy window. It then sequentially invokes MCP servers: a Catalyst Information Server to generate a candidate list, a Structure Retrieval Server (via OPTIMADE) to fetch crystal structures or a CIF File Resource Server for user-provided structures, an optional Structure Modification Server to apply either in-plane strain or top-layer substitution, and an Energy Evaluation Server that runs AdsorbML to compute minimum adsorption energies using the UMA graph neural network potential. After each evaluation, the agent judges whether the energy falls within the target window; if it is close, it iterates with modifications; if not, it moves to the next candidate. This loop continues until a satisfactory material is found or a trial limit is reached. The modular MCP architecture prevents dependency conflicts and allows parallel evaluation of multiple surface facets.

The use of UMA enables rapid energy estimation (~1 second per relaxation) compared to density functional theory (days), making closed-loop screening feasible. The agent’s ability to autonomously refine near-miss candidates through simple strain or doping significantly expands the pool of viable catalysts, as evidenced by the higher modification rates among successful materials compared to failures.

## Key Results
- Success rate of 23–34% across ORR, NRR, and CO₂RR reactions.
- Average convergence after 1–2 modification trials per successful candidate.
- Identification of promising catalysts (e.g., Sn₃Sc for CO₂ reduction) and effective conversion of near-miss materials via strain/doping.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** An LLM agent autonomously orchestrates a closed-loop catalyst screening workflow by planning sequential tool invocations across modular servers.
- **Mechanism:** The agent receives a natural language prompt specifying the reaction, adsorbates, and acceptance criteria. It decomposes the goal into a sequence of calls to specialized Model Context Protocol (MCP) servers: (1) retrieve candidate materials, (2) fetch crystal structures, (3) optionally apply strain/doping modifications, (4) evaluate adsorption energies via AdsorbML–UMA, and (5) judge success. Results are fed back into the LLM context to decide next steps, enabling iterative refinement of near-miss candidates.
- **Core assumption:** The LLM can correctly interpret tool schemas and outputs, and generate a valid plan that respects physical constraints.
- **Evidence anchors:**
  - [abstract]: "Catalyst-Agent… integrates with Model Context Protocol (MCP) servers. It queries material databases, makes structural modifications, evaluates adsorption energies… and makes useful material suggestions to the researcher in a closed-loop manner."
  - [section 2.1]: "The LLM-based agent… acts as the central orchestrator… It receives a user prompt… and then plans, sequences and invokes the appropriate MCP server tools to execute the end-to-end screening workflow."
- **Break condition:** The agent may hallucinate tool parameters, misinterpret numerical feedback (e.g., defining “soften” adsorption as raising the adsorption energy when the target window requires lowering it), or produce non-physical modification plans that repeatedly fail.

### Mechanism 2
- **Claim:** A graph neural network–based universal machine-learned interatomic potential (UMA) within AdsorbML enables fast adsorption energy evaluation that is accurate enough for high-throughput screening.
- **Mechanism:** AdsorbML generates multiple initial adsorbate placements on a slab, relaxes each using the UMA small model, and returns the global minimum energy. The UMA model was pretrained on large DFT datasets (e.g., OC20) and predicts total energies and forces rapidly on GPU. The energy difference between the adsorbate–slab system, the clean slab, and the gas-phase reference yields the adsorption energy.
- **Core assumption:** UMA’s predictions are within ~0.1 eV of DFT for the relevant adsorbate–surface combinations, sufficient to distinguish promising from poor catalysts.
- **Evidence anchors:**
  - [abstract]: "calculate adsorption energies using Meta FAIRchem’s UMA (GNN) model via FAIRchem’s AdsorbML workflow…"
  - [section 5.2]: "Adsorption energies were computed using FAIRchem’s AdsorbML pipeline… The UMA small model (uma-s-1p1) serves as a machine learning interatomic potential…"
  - [Supp. Info S5]: Table 16 reports UMA’s test adsorption energy MAE ≈ 70 meV (in-range OOD), supporting its accuracy for screening.
- **Break condition:** UMA may poorly extrapolate to chemistries or surface environments absent from its training distribution (e.g., high-index facets with many dangling bonds, non-oxide materials if trained mainly on oxides), leading to ranking errors.

### Mechanism 3
- **Claim:** Iterative surface-level modifications (strain, top-layer substitution) enable the agent to convert near-miss materials into viable catalysts.
- **Mechanism:** After an initial evaluation, the agent checks if the best adsorption energy lies just outside the target window. If so, it applies a single modification (compressive/tensile strain scaling of in-plane lattice vectors or replacing one top-layer atom with a different element) and re-evaluates. This loop repeats until a modification satisfies all descriptors or the candidate is abandoned.
- **Core assumption:** Small, physically plausible surface perturbations can shift adsorption energies into the desired range for materials that are already electronically well-suited.
- **Evidence anchors:**
  - [section 2.1.4]: "The Structure Modification Server supports two modification modes: top-layer substitution (doping) and in-plane strain… These modifications are lightweight, rapid to apply and enable the agent to iteratively refine near-miss candidates."
  - [section 2.3]: "For ORR, 32% of successful materials required modifications compared to only 15% of failures… For NRR, 50% of successful materials needed modification versus 23% of failures. The agent’s iterative refinement loop is a meaningful contributor to expanding the pool of viable candidates."
  - [section 2.4, CoGa₂O₄ example]: Shows trial sequence where strain tuning moved adsorption into the optimal window after three modification attempts.
- **Break condition:** Materials intrinsically far from the descriptor target (e.g., due to bulk electronic structure) are not rescued by simple strain or single-atom substitution; the agent may waste trials on such candidates (e.g., CO₂RR failures in Table 15).

## Foundational Learning

- **Concept:** Adsorption energy as a catalytic activity descriptor  
  **Why needed here:** Catalyst-Agent evaluates materials based on the adsorption energy of key intermediates (e.g., *OH for ORR). Understanding how this quantity relates to reaction barriers and volcano plots is essential to grasp why the agent targets specific energy windows.  
  **Quick check question:** Why is the adsorption energy of *OH used as a descriptor for the oxygen reduction reaction, and what does an optimal value signify?

- **Concept:** Graph Neural Networks (GNNs) for atomistic property prediction  
  **Why needed here:** The UMA model, which powers AdsorbML, is a GNN that takes an atomic structure (nodes = atoms, edges = bonds) and predicts energy/forces. Knowing that GNNs can generalize across materials explains how rapid screening is possible.  
  **Quick check question:** How does a GNN encode atomic environments to predict system-wide properties like total energy?

- **Concept:** Model Context Protocol (MCP) for modular tool integration  
  **Why needed here:** Catalyst-Agent’s architecture hinges on MCP servers that expose discrete computational tools (database querying, slab building, energy evaluation) to an LLM. This modularity prevents dependency conflicts and lets the agent switch between tasks seamlessly.  
  **Quick check question:** What problem does MCP solve when integrating multiple scientific software packages into a single AI agent pipeline?

## Architecture Onboarding

- **Component map:** Catalyst Information Server (seeds candidate list) -> Structure Retrieval Server (OPTIMADE queries) -> CIF File Resource Server (user CIFs) -> Structure Modification Server (strain/doping) -> Energy Evaluation Server (AdsorbML/UMA) -> LLM Agent (GPT-5.2, central planner)
- **Critical path:**
  1. Prompt ingest: User provides reaction, adsorbates, target energy window, and whether to iterate.
  2. Candidate fetch: Agent obtains material list from Catalyst Information Server.
  3. Structure fetch: For each candidate, agent uses Structure Retrieval or CIF Server.
  4. Baseline evaluation: Agent calls Energy Evaluation Server with no modifications.
  5. Success check: Agent compares best energy to target. If within window → record success; if near-miss → invoke Structure Modification Server; if far → skip to next material.
  6. Iterate: After modification, repeat evaluation and check until success or max trials.
  7. Proceed: Agent moves to next candidate, carrying context of prior unsuccessful attempts.
- **Design tradeoffs:**
  - Modularity vs. latency: MCP isolation prevents dependency clashes and enables parallel facet evaluation, but each tool call incurs LLM–server round trips and subprocess startup overhead.
  - Accuracy vs. speed: UMA (GNN) gives ~1 s/relaxation vs. days for DFT, enabling closed loops; however, ML errors can misrank materials.
  - Free LLM API vs. cost: Current provider tiers allow small campaigns (<$100), but scaling to thousands of materials will increase token costs substantially (Supp. Info S6 shows ~$68 total).
  - Exploration vs. exploitation: The agent greedily pursues immediate near-misses; it may miss globally optimal candidates that require non-intuitive multi-step modifications.
- **Failure signatures:**
  - LLM reasoning inconsistency: Agent labels weak binding as “too strong” or misinterprets strain sign effects (see Section 2.4, “Critical assessment”).
  - AdsorbML anomalies: High “anomalies_detected” count or “AdsorbML error—identifier not found” indicates slab generation or model instability.
  - Modification loop traps: Material accumulates many trials (>5) without success; modification success ratio drops (e.g., CO₂RR failures: mean 2.0 successful vs. 2.33 unsuccessful mods).
  - No facet found: Structure Retrieval returns no matching material; agent must skip or request new candidate.
- **First 3 experiments (for a new engineer):**
  1. Single-candidate dry run: Execute the agent on a known good material (e.g., SrTiO₃ for ORR) with a minimal prompt. Observe the tool call sequence and verify that the baseline energy falls in the expected range.
  2. Modification logic probe: Run CoGa₂O₄ (mp‑765466) for ORR and record the agent’s reasoning and modification choices. Compare with the documented CoGa₂O₄ case study (Section 2.4) to confirm replication.
  3. Parameter sweep perturbation: Introduce a non‑recommended strain value (e.g., +10% compression) in a follow‑up prompt after a near‑miss, and check whether the agent incorporates it or rejects it. This tests the agent’s adherence to physically plausible ranges.

## Limitations
- **LLM planner errors:** The agent may generate invalid tool parameters or misinterpret numerical feedback (e.g., confusing binding strength direction), leading to wasted trials.
- **UMA generalization risk:** Although the UMA GNN achieves ~70 meV MAE on oxides, its accuracy on out-of-distribution chemistries (e.g., metals) is unverified, risking misranking of candidates.
- **Limited modification repertoire:** Only strain and single-atom substitution are supported; multi-dopant or surface reconstruction modifications are absent, reducing the ability to rescue materials far from the descriptor optimum.

## Confidence
- **Closed-loop orchestration:** Medium. Feasibility shown, but LLM errors and lack of external validation.
- **UMA screening accuracy:** Medium. Strong benchmark, yet extrapolation risk.
- **Modification rescue:** Medium. Empirical support, but limited to simple tweaks.

## Next Checks
1. Cross-validate UMA against DFT on a diverse candidate set (oxides, metals, alloys) to map error distribution.
2. Conduct adversarial LLM tests: inject misleading tool outputs to probe planner robustness.
3. Implement multi-atom doping and reconstruction modifications; re-evaluate on a fixed near-miss set to quantify gains.
