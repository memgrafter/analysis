# Causal Identification from Counterfactual Data: Completeness and Bounding Results

## Quick Facts
- **arXiv ID:** 2602.23541  
- **Source URL:** https://arxiv.org/abs/2602.23541  
- **Reference count:** 40  
- **Primary result:** The CTFIDU+ algorithm is complete for identifying any counterfactual query from realizable Layer 3 input distributions; it also yields tighter partial identification bounds for non-identifiable quantities when counterfactual data is available.

## Executive Summary
This paper tackles the problem of identifying counterfactual queries (Layer 3 of Pearl’s Causal Hierarchy) when some counterfactual data is available through counterfactual randomization (`ctf-rand`), a scenario previously thought unrealizable. The authors introduce the CTFIDU+ algorithm, which systematically determines whether a counterfactual query can be expressed in terms of given input distributions (observational, interventional, or counterfactual) and returns an explicit expression or `FAIL`. The algorithm is proven complete. They further establish a duality: the exact identifiability frontier coincides exactly with the set of distributions realizable via `ctf-rand`, implying that only counterfactual queries in Layer 2.5 are identifiable from such data. For queries beyond this frontier (e.g., natural total effect), the paper derives novel analytic bounds that are provably tighter than those obtainable from only observational/interventional data; simulations confirm these improvements. The results unify identification theory with the practical possibility of collecting counterfactual data.

## Method Summary
The CTFIDU+ algorithm takes as input a causal diagram \(G\), a counterfactual query \(P(Y^*=y)\), and a set \(\mathcal{A}\) of permissible actions (observe, rand, ctf‑rand) that define available input distributions. It first transforms the query into an equivalent counterfactual (ctf‑) factor using ancestral set transformation and c‑component factorization. For each input action, a sub‑routine REGIME‑REGEX maps the action to an un‑nested Layer‑3 expression, which is likewise factorized. The core IDENTIFY+ procedure then checks whether the target ctf‑factor is identified from any input factor, detecting the presence of a ctf‑hedge certificate that implies non‑identifiability. If all necessary factors are identified, CTFIDU+ composes the final expression; otherwise it returns `FAIL`. For non‑identifiable quantities (e.g., natural total effect), the authors incorporate additional constraints from counterfactual (Layer‑2.5) data into a linear program over canonical SCM parameters, deriving analytic Fréchet‑Höffding‑type bounds that are tighter than those based solely on lower‑layer data.

## Key Results
- **Completeness:** CTFIDU+ is complete for identifying counterfactual queries from arbitrary sets of realizable Layer‑3 input distributions (Theorem 3.5).  
- **Duality:** Exact identifiability of a counterfactual quantity is possible iff its distribution is realizable via counterfactual randomization; in particular, only Layer‑2.5 quantities are identifiable from realizable data (Theorem 4.1, Corollary 4.2).  
- **Tighter bounds:** For non‑identifiable quantities (e.g., natural total effect), incorporating Layer‑2.5 data yields provably tighter partial identification bounds than using only observational/interventional data (Proposition 5.4); simulations confirm narrower credible intervals.

## Why This Works (Mechanism)

**Mechanism 1: CTFIDU+ Algorithm Completeness**  
The algorithm recursively decomposes the target query into necessary and sufficient counterfactual factors via ancestral set transformation and c‑component factorization. It maps each input distribution to a corresponding ctf‑factor and uses IDENTIFY+ to match input to target factors. Completeness is proven via a counterfactual hedge certificate: identification fails if and only if a ctf‑hedge structure exists in the data, which IDENTIFY+ detects. The setup assumes a correct causal diagram, positive distributions, and that input distributions are physically realizable via observe, rand(), or ctf‑rand() actions.

**Mechanism 2: Duality Between Realizability and Identifiability**  
The authors show that the theoretical limits of exact causal identification coincide precisely with the limits of counterfactual data realizability. For counterfactual queries outside Layer 2.5 (i.e., those whose counterfactual ancestor set contains conflicting potential responses from the same variable under different regimes), no lattice pathway exists from any realizable input distribution (Layer 2.5 or below) to compute the query. The proof leverages the causal lattice framework: inconsistency levels increase along pathways, and L3\L2.5 nodes require an upstream node with inconsistency level 5, which cannot originate from L2.5 input.

**Mechanism 3: Tighter Bounds Using Counterfactual Data**  
For non‑identifiable counterfactual quantities (e.g., natural total effect), adding realizable counterfactual (Layer‑2.5) constraints reduces the feasible set of SCMs consistent with the data. Applied to specific structures like the bow‑tie graph, analytic Fréchet‑Höffding bounds applied to the new constraint yield narrower intervals. Simulations on synthetic data confirm that 95% credible intervals become strictly tighter when Layer‑2.5 data are included alongside lower‑layer data.

## Foundational Learning
- **Pearl’s Causal Hierarchy (L1–L3)**  
  *Why needed:* The whole work is framed relative to observational (L1), interventional (L2), and counterfactual (L3) reasoning; CTFIDU+ extends L3 identification to include realizable L3 data, and the duality result identifies L2.5 as the ceiling.  
  *Quick check:* Given a query \(P(Y_x | x')\), which layer(s) does it belong to if the query is ancestral? What about \(P(Y_x, Z_{x'})?\)  

- **Counterfactual Realizability & ctf‑rand()**  
  *Why needed:* Defines the new input data regime: actions that directly sample counterfactual distributions (e.g., `ctf‑rand(X→Y)`). L2.5 membership is defined via the counterfactual ancestor check and determines what is physically collectible versus inferable.  
  *Quick check:* For the graph \(X \rightarrow Y \leftarrow Z \rightarrow W\), is \(P(Y_x, W_z)\) realizable? What about \(P(Y_x, W_{xz})?\)  

- **Counterfactual (ctf‑) Factor & Consistency**  
  *Why needed:* CTFIDU+ manipulates queries at the level of ctf‑factors (Eq. 5). The consistency property (Eq. 43) allows reduction of nested to un‑nested expressions; inconsistent ctf‑factors cannot be identified from lower‑layer data alone (Lem. B.7).  
  *Quick check:* For \(P(A_{xy}, B_{ax})\) in graph \(A \rightarrow B \leftarrow X \rightarrow Y\), what is a consistent rewrite as a ctf‑factor? Is it consistent?

## Architecture Onboarding
**Component map**  
Graph & Query Parser → Ancestral Set Transformer → C‑Component Factorizer → (Regime‑to‑Expression Mapper → AST → C‑Component Factorizer) for each input distribution → IDENTIFY+ Engine → Bounds Engine (if needed)

**Critical path**  
1. Input query \(P(Y^*=y)\) is parsed and converted to a ctf‑factor via ancestral set transformation (AST) and c‑component factorization.  
2. For each action in \(\mathcal{A}\), REGIME‑REGEX translates the action to an un‑nested L3 expression; this expression is likewise transformed into a ctf‑factor.  
3. The IDENTIFY+ sub‑routine checks whether the target ctf‑factor is identified from any input ctf‑factor; it returns a compositional expression or `FAIL`.  
4. If all required factors succeed, the final identification expression is assembled; otherwise the process terminates with `FAIL`.  
5. For non‑identifiable queries, the Bounds Engine adds the input constraints (including any L2.5 distributions) to a linear program or applies analytic formulas to compute tight intervals.

**Design tradeoffs**  
- **Positivity:** All distributions must be positive; zero‑mass cells break divisions in the bounding formulas.  
- **Finite discrete variables:** The derivations assume finite variable domains; continuous variables require density arguments.  
- **Acyclicity:** The SCM is assumed acyclic; cycles need different treatment.  
- **Latent structure:** The hedge detection assumes only confounding (bidirected edges); selection bias or more complex latent structures may require adaptation.

**Failure signatures**  
- **FAIL from CTFIDU+:** Indicates the target is not identifiable from given inputs; check missing ctf‑factors or presence of a ctf‑hedge.  
- **Loose bounds:** If credible intervals with L2.5 data are not strictly contained within those from L2, either the query is actually L2.5‑identifiable (so bounds should collapse) or the causal diagram is misspecified.  
- **Regex mismatch:** If REGIME‑REGEX produces an expression that does not match the intended physical regime, verify the mapping rules for overlapping interventions.

**First 3 experiments**  
1. **Front‑door test:** Apply CTFIDU+ to the classic front‑door graph \(X\rightarrow Z\rightarrow Y\) with only observational input \(P(X,Z,Y)\). The output must equal \(\sum_z\sum_{x'} P(z|x)P(y|z,x')P(x')\).  
2. **L2.5 limit test:** For graph \(X\rightarrow A\rightarrow Z\leftarrow X\) and query \(P(Y_x, Z_{x'})\), use input distributions \(P(Y_x,X)\) and \(P(Z_x,X)\) (both L2.5). CTFIDU+ should return `FAIL`, illustrating the L2.5 ceiling (Theorem 4.1).  
3. **Bounds tightening test:** For the bow‑tie graph \(X\leftrightarrow Y\) (confounded), compute 95% credible intervals for the natural total effect \(P(Y_x \mid x',y')\) using (a) L2 data \(P(Y_x)\) and (b) L2.5 data that additionally include \(P(Y_x|X)\). Verify that the interval from (b) is strictly contained within that from (a), as predicted by Proposition 5.4.

## Open Questions the Paper Calls Out
1. **Optimal counterfactual experiment design** – How can one systematically select counterfactual interventions to yield the tightest possible identification bounds for non‑identifiable quantities?  
2. **Role of stronger assumptions** – In what ways can structural or parametric assumptions complement counterfactual data to overcome the fundamental non‑identification barriers highlighted by the realizability‑identification duality?  
3. **Generalizing bounds beyond the bow graph** – To what extent do the analytic bounds derived for the natural total effect under the bow structure generalize to arbitrary causal diagrams?  
4. **Robustness to diagram misspecification** – How sensitive are identification claims and derived bounds to errors in the causal diagram? What diagnostic tools can detect when proposed counterfactual experiments are insufficient due to hidden confounding?

## Limitations
- **Undetailed simulation methodology:** The random SCM generation parameters, Bayesian prior, MCMC settings, and random seeds are omitted, hindering exact replication of the numerical results.  
- **Strong algorithmic assumptions:** The methods rely on positivity, finite discrete domains, and acyclic graphs; real‑world data may violate these, requiring additional handling.  
- **Potential edge cases in REGIME‑REGEX:** The mapping from action sets to un‑nested expressions is described at a high level; overlapping counterfactual interventions (e.g., multiple `ctf‑rand` on the same variable) may lead to ambiguous or incorrect translations.

## Confidence
- **CTFIDU+ completeness:** High (rigorous proof via ctf‑hedge certificates).  
- **Realizability–identifiability duality:** Medium (depends on the correctness of the L2.5 characterization and the assumption of full `ctf‑rand` availability).  
- **Tighter bounds from counterfactual data:** Medium (analytic bounds are proven, but empirical improvement depends on unreported simulation details and the specific graph structure).
