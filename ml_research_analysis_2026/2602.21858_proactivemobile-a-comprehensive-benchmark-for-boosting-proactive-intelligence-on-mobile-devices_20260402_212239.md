# ProactiveMobile: A Comprehensive Benchmark for Boosting Proactive Intelligence on Mobile Devices

## Quick Facts
- **arXiv ID:** 2602.21858
- **Source URL:** https://arxiv.org/abs/2602.21858
- **Reference count:** 40
- **Primary result:** Fine-tuning Qwen2.5-VL-7B-Instruct on ProactiveMobile achieves a 19.15% success rate, surpassing closed-source models like o1 (15.71%) and GPT-5 (7.39%).

## Executive Summary
This paper introduces ProactiveMobile, the first comprehensive benchmark for evaluating proactive intelligence in mobile agents—systems that must autonomously anticipate user needs from complex on-device context rather than merely react to explicit commands. The benchmark formalizes the task as inferring latent user intent from four contextual signals (user profile, device status, world information, behavioral trajectories) and mapping it to an executable function sequence from a pool of 63 APIs. It comprises 3,660 instances across 14 scenarios, each annotated with 1–3 valid function sequences to accommodate real-world solution variability. Key findings show that supervised fine-tuning on this benchmark yields measurable improvement over state-of-the-art closed models, demonstrating that proactivity is a learnable capability. However, absolute performance remains low (19.15%), with a significant gap between text-only and multimodal (GUI-based) tasks, highlighting substantial challenges ahead.

## Method Summary
The benchmark constructs a supervised learning framework by transforming ambiguous proactive scenarios into a structured prediction task. Each instance aggregates four contextual streams: static user profile,实时 device status, external world information (e.g., weather, calendar), and behavioral trajectories (either textual logs or GUI screenshot sequences). Latent user intents are distilled into ground-truth executable function sequences drawn from a curated pool of 63 mobile APIs. To ensure quality and robustness, each instance undergoes multi-answer annotation (1–3 valid sequences) and three-stage review: rule-based filtering, agent-based consistency checks, and expert human audit.

For training, the authors perform supervised fine-tuning (SFT) on a base multimodal LLM (Qwen2.5-VL-7B-Instruct) using the training split (8,876 items). The model is prompted to output both a natural language recommendation (articulating the inferred intent) and the corresponding function sequence in a standardized syntax. Evaluation relies on two metrics: Success Rate (SR), which measures functional equivalence of the predicted sequence to any ground-truth sequence via an LLM-as-a-Judge protocol (Best-Match Selection); and False Trigger Rate (FTR), which penalizes non-empty outputs when no valid action exists. Exact training hyperparameters (learning rate, batch size, epochs) and the judge’s implementation details are reserved for the appendix and thus unavailable for replication.

## Key Results
- Fine-tuned Qwen2.5-VL-7B-Instruct achieves 19.15% SR, outperforming o1 (15.71%) and GPT-5 (7.39%), indicating that targeted training yields meaningful gains in proactive capability.
- A pronounced performance disparity exists between text-only (24% SR) and multimodal/GUI-based (14% SR) tasks, suggesting visual grounding remains a major bottleneck.
- Ablation studies confirm that enforcing a two-step output format (Recommendation text → Function sequence) drastically reduces safety failures, cutting False Trigger Rate from near 100% (func-only) to 2.21% (with "Think" step).

## Why This Works (Mechanism)
### Mechanism 1: Formalization as Supervised Intent-to-Action Mapping
- **Claim:** The benchmark’s structure—four-dimensional context plus constrained output to a finite API pool—creates a learnable signal for proactive intent inference.
- **Mechanism:** By grounding the ambiguous goal of "anticipating needs" in specific, on-device signals and limiting outputs to a verifiable action space, the task becomes a supervised mapping problem. The model learns to associate statistical patterns across user profile, device status, world info, and behavioral trajectories with correct function sequences.
- **Core assumption:** Predictive correlations exist between the contextual signals and valid API calls; without such signal, supervised fine-tuning would not improve SR.
- **Evidence anchors:** [abstract] "formalizes the proactive task as inferring latent user intent across four dimensions of on-device contextual signals and generating an executable function sequence..."; [section 3.1] defines proactive intelligence using these four dimensions and unified function mapping.
- **Break condition:** If the function pool is incomplete or the four contextual dimensions lack predictive power (no statistical relationship to intents), fine-tuning would fail to yield SR gains.

### Mechanism 2: Multi-Answer Annotations with Functional Equivalence Evaluation
- **Claim:** Allowing 1–3 ground-truth function sequences per instance and judging predictions by functional equivalence (not exact match) accommodates real-world solution variability and yields a robust training signal.
- **Mechanism:** Proactive tasks inherently admit multiple valid actions from the same context. The Best-Match Selection protocol uses an LLM judge to check if a predicted function set achieves the same goal as any ground-truth set, ignoring superficial differences (e.g., parameter naming, order) while flagging functional mismatches.
- **Core assumption:** The set of annotated sequences is sufficiently exhaustive; the LLM judge reliably discerns functional equivalence.
- **Evidence anchors:** [abstract] "features over 3,660 instances of 14 scenarios that embrace real-world complexity through multi-answer annotations"; [section 3.2.2] "each instance is annotated and manually verified with one to three target actions"; [section 4.2.2] describes immediate SR=1 upon functional equivalence match.
- **Break condition:** Incomplete annotation (missing valid sequences) would erroneously penalize correct predictions; a biased judge would inflate or deflate SR inconsistently.

### Mechanism 3: Recommendation Text as a Safety Scaffold
- **Claim:** Requiring a natural language recommendation before the function sequence acts as a reasoning intermediate that improves both task performance and safety (lower FTR).
- **Mechanism:** The two-step output forces the model to first articulate a human-interpretable intent (e.g., "User is hot; pre-cool living room") before committing to an executable plan. This decoupling appears to calibrate the model’s "when to act" judgment, reducing spurious function calls in no-intent contexts.
- **Core assumption:** Articulating intent in natural language imposes a beneficial cognitive constraint that aligns the model’s internal decision process with human-like deliberation.
- **Evidence anchors:** [section 4.5] "Our chosen strategy achieves the highest SR (19.15%)... formats trained without this textual recommendation... exhibit a catastrophic failure in safety, with False Trigger Rate (FTR) rates near 100%"; adding a "Think" step further slashes FTR to 2.21%.
- **Break condition:** If the recommendation generation step introduces hallucinations or conflicts with the function mapping, overall utility could degrade. Success hinges on synergy between the two steps.

## Foundational Learning
- **Causal/Abductive Reasoning over Multimodal Context:** Proactive intelligence requires inferring an unobserved latent intent (e.g., "user will be uncomfortable arriving home") from observed evidence (location, weather, past complaints). This is abductive, not pattern-matching. *Quick check:* Given navigation "arriving home in 5 min", weather "35°C", and profile "prefers AC at 23°C", what intent is most causally plausible?
- **Executable Function Mapping via Constrained Decoding:** Shifting from free-form text to a fixed 63-API pool requires mapping a high-level intent to a precise, syntactically correct sequence. This constraint ensures outputs are objectively verifiable and executable. *Quick check:* For intent "pre-cool living room", which API combination (`turn_on_ac`, `set_temperature`, `set_fan_speed`) is necessary and sufficient?
- **Multi-Answer Robust Evaluation (Functional Equivalence):** Standard exact-match fails due to multiple valid solutions. Evaluation must assess if the predicted function set achieves the same goal as any ground-truth set, using an LLM judge to ignore superficial differences. *Quick check:* If ground truth is `[A then B]` and prediction is `[B then A]`, are they functionally equivalent for a non-commutative sequence? How would the judge decide?

## Architecture Onboarding
- **Component map:** Context Feeder (4 streams) → Proactive Core (Multimodal LLM) → Function Pool (63 APIs) → Evaluation Engine (LLM Judge)
- **Critical path:** Data pipeline: raw trajectory logs → context generation (LLM) → intention annotation (LLM + human) → function mapping → three-stage review → final dataset. Deployment pipeline: real-time context → model inference → function parsing → system execution.
- **Design tradeoffs:** Precision vs. Recall in Function Pool (larger pool increases expressiveness but complicates learning); Noise Injection vs. Signal Clarity (adding irrelevant text improves robustness but may dilute key signals); Recommendation Text Overhead (improves safety but adds latency and potential misalignment).
- **Failure signatures:** High False Trigger Rate (FTR) indicates failure to recognize "no intent"; Low Multimodal SR vs. Text SR points to visual grounding瓶颈; Poor OOD Generalization suggests overfitting to surface patterns.
- **First 3 experiments:** 1. Zero-shot sanity check with o1 on 50 test items to validate judge decisions. 2. Ablate one context dimension (e.g., remove Behavioral Trajectories) and measure SR drop. 3. Compare output formats (Func-only, Rec+Func, Think+Rec+Func) on held-out set, monitoring FTR.

## Limitations
- **Unreproducible training details:** Exact SFT hyperparameters (learning rate, batch size, epochs) and data augmentation strategies are omitted (only referenced in an unavailable Appendix), blocking exact replication of the 19.15% SR result.
- **Evaluation opacity:** The LLM judge’s (Gemini-2.5-Pro) prompt, temperature, and full Best-Match Protocol are unspecified, introducing variance in SR calculation and limiting comparability.
- **Uncured multimodal gap:** The persistent 10-point SR gap between text and GUI tasks is noted but not causally analyzed; the root cause (e.g., visual representation limits, trajectory noise) remains unknown.

## Confidence
- **Benchmark design validity:** High (explicitly defined, contrasts with prior work)
- **Fine-tuning efficacy (SR improvement):** Medium (reported clearly but lacks variance estimates and depends on unreleased details)
- **Safety mechanism (Recommendation + Function):** High (ablation shows catastrophic FTR without recommendation)
- **Multimodal gap persistence:** High (consistent, measured outcome across models)
- **"Proactivity is learnable" thesis:** Medium (supported by SOTA improvement, but absolute SR remains very low)
