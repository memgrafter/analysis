# Sci-CoE: Co-evolving Scientific Reasoning LLMs via Geometric Consensus with Sparse Supervision

## Quick Facts
- **arXiv ID:** 2602.12164
- **Source URL:** https://arxiv.org/abs/2602.12164
- **Reference count:** 28
- **Primary result:** A two-stage framework using anchored correctness and geometric reward boosts Qwen3-8B accuracy on GPQA-Diamond by 4.04% (36.87→40.91) with scalable unlabeled data.

## Executive Summary
Sci-CoE is a two-stage framework that co-evolves a single LLM to act as both a scientific problem solver and a verification strategy generator. It addresses the fragility of self-evaluation in scientific reasoning by first anchoring the model's notion of correctness with a small set of labeled data, then scaling to unlabeled data via a geometric reward mechanism. This reward jointly optimizes solution consensus, verification strategy reliability (cluster proximity), and diversity (angular spread) in an embedding space. Evaluations on MMLU-Pro, GPQA-Diamond, and UGPhysics show consistent improvements over the base model, with gains scaling as more unlabeled data is used.

## Method Summary
Training occurs in two stages using a shared model. **Stage 1** (anchored learning) uses ~4k labeled scientific questions. The model generates solutions and verification strategies; a large external judge model evaluates pairs. Solution reward is a binary match to ground truth. Verifier reward encourages accepting correct solutions and rejecting incorrect ones. Updates are sequential (solver first, then verifier) to establish a stable discriminative prior. **Stage 2** (unsupervised co-evolution) scales to 18k–30k unlabeled questions. The external judge still provides binary feedback. Solution reward is the consensus pass rate across all generated strategies (threshold τ=0.8). Verification strategies are embedded; K-means clustering and PCA compute a geometric reward combining: (a) consistency with high-consensus solutions, (b) reliability (distance to cluster center), and (c) diversity (polar angle dispersion). Both solution and strategy samples are pooled for joint PPO updates, allowing mutual adaptation without ground truth.

## Key Results
- On GPQA-Diamond, Qwen3-8B accuracy improves by **4.04%** (36.87→40.91); on MMLU-Pro by **1.15%** (63.19→64.34); on UGPhysics by **1.34%** (31.76→33.10).
- Performance scales with more unlabeled data (18k→30k), demonstrating the framework's data efficiency.
- Ablations confirm that skipping anchored learning (Stage 1) or using a naive consensus-only verifier reward causes significant performance drops and diversity collapse.

## Why This Works (Mechanism)
### Mechanism 1: Anchored Correctness Initialization
A small set of annotated data establishes stable reference anchors for the Verifier's notion of correctness, preventing initial policy collapse. Stage 1 uses ground-truth answers to compute binary rewards for the Solver and a discriminative reward for the Verifier. Sequential PPO updates alternately align the shared model with solving accuracy and verification discriminability. *Break condition:* Noisy or distributionally misaligned anchor data corrupts the Verifier's initial boundary, derailing co-evolution.

### Mechanism 2: Geometric Reward for Unsupervised Co-evolution
Modeling verification strategies in a latent embedding space and rewarding reliability (cluster proximity) and diversity (angular dispersion) prevents consensus collapse. In Stage 2, strategy reward is a weighted sum of consistency with high-consensus solutions, reliability (Euclidean distance to K-means center), and diversity (polar angle in PCA-projected space). This geometric regularization prevents the Verifier from exploiting trivial, homogeneous strategies. *Break condition:* A poor embedding model misrepresents strategy quality, yielding misleading rewards.

### Mechanism 3: Closed-Loop Solver-Verifier Co-Evolution
Jointly optimizing a single model as both Solver and Verifier via mutual consistency feedback creates a stable self-improving loop. Solution reward is based on pass rate across strategies; strategy reward is geometric. Mixed PPO updates allow shared parameters to adapt solution generation to emerging verification criteria while verification evolves to match solution complexity. *Break condition:* An inconsistent external Judge Model introduces noise, potentially causing co-adaptation to shared incorrect heuristics.

## Foundational Learning
- **Proximal Policy Optimization (PPO):** Needed to jointly optimize the shared model for both roles using dense reward signals while preventing destructive updates via a KL constraint. *Quick check:* How do sequential (Stage 1) vs. joint (Stage 2) PPO updates affect co-evolution stability?
- **Embedding Space Geometry for Reward Shaping:** Transforms unstructured verification strategies into a continuous space where reliability and diversity can be quantified. *Quick check:* Why use polar coordinates on PCA-projected vectors for diversity instead of simple Euclidean distance?
- **Consensus-Based Self-Supervision:** Estimates solution quality by agreement across verification strategies in the absence of ground truth. *Quick check:* What is the risk of using consensus as reward, and how does the geometric reward mitigate it?

## Architecture Onboarding
- **Component map:** Input Question -> Solver (generates N solutions) + Verifier (generates M strategies) -> External Judge Model (evaluates all N×M pairs) -> Binary Pass/Fail Matrix -> Solution Reward (consensus rate) + Strategy Embeddings -> Clustering Module (K-means) & PCA -> Geometric Reward (consistency, reliability, diversity) -> Mixed Buffer -> Joint PPO Trainer (updates shared policy π_θ).
- **Critical path:**  
  1. Stage 1: Sample labeled question -> generate solutions/strategies -> Judge evaluation -> compute GT-based rewards -> **sequential** PPO update (solver then verifier).  
  2. Stage 2: Sample unlabeled question -> generate solutions/strategies -> Judge evaluation -> compute consensus solution reward -> embed strategies -> cluster -> compute geometric strategy rewards -> **joint** PPO update on mixed buffer.
- **Design tradeoffs:**  
  - External Judge dependency: High cost/bias vs. stable binary signal.  
  - Geometric reward hyperparameters (k, α,β,γ): Simplicity (k=1) vs. capturing strategy subtypes.  
  - Sequential vs. joint updates: Early stability vs. dynamic co-adaptation risk.
- **Failure signatures:**  
  - Performance drop after Stage 2: Check strategy diversity (r_div) collapse or reliability (r_rel) decrease.  
  - Repetitive strategies: Visualize embeddings—dense clustering indicates ineffective diversity reward.  
  - Solver exploits Verifier: Rising solution accuracy but falling strategy accuracy; monitor correlation between solution consensus and Judge accuracy on a held-out labeled set.
- **First 3 experiments:**  
  1. **Ablation: Skip Anchored Learning** – Train only Stage 2 from base model on unlabeled data. Expect performance degradation.  
  2. **Ablation: Naive vs. Geometric Reward** – Replace geometric reward with pure consensus (r_ver = r_con). Expect strategy diversity collapse and lower final accuracy.  
  3. **Scaling Test: Data Volume** – Train Stage 2 with 18k vs. 30k unlabeled questions. Expect monotonic accuracy improvement.

## Open Questions the Paper Calls Out
- **Question 1:** How does Sci-CoE performance scale with model size beyond 8B parameters? *Basis:* Limited budget prevented training larger models.
- **Question 2:** Can reliance on an external judging model be removed for full self-containment? *Basis:* External judge adds cost and potential bias.
- **Question 3:** Are the fixed geometric reward hyperparameters (α, β, γ, τ) universally optimal across scientific domains? *Basis:* No sensitivity analysis reported.
- **Question 4:** Does the frozen embedding model limit expressiveness, and can embeddings be learned jointly? *Basis:* Static pretrained embedding is used.

## Limitations
- Heavy reliance on a closed-source Judge model (Qwen3-235B) raises bias, cost, and reproducibility concerns.
- Geometric reward assumes the embedding space reflects verification strategy quality, which may not hold universally.
- Anchoring with only ~4k labeled examples may be insufficient for highly complex domains.

## Confidence
- **Mechanistic claims** (anchored initialization, geometric reward, co-evolution): **High** (supported by ablations and visual evidence).
- **Performance improvements** on MMLU-Pro, GPQA-Diamond, UGPhysics: **Medium** (results from paper not independently replicated).
- **Reproducibility:** **Low** (critical hyperparameters/prompt details missing, closed-source dependencies).

## Next Checks
1. **Anchor robustness:** Systematically vary anchor set size (1k/2k/4k) and inject label noise (5–20%) to measure sensitivity of final accuracy and co-evolution stability.
2. **Embedding sensitivity:** Replace Qwen3-Embedding-8B with alternative models (OpenAI ada-002, BGE) and recompute strategy rewards; assess impact on diversity metrics and benchmark performance.
3. **Out-of-distribution evaluation:** Test the trained model on held-out scientific benchmarks (e.g., ChemBench, MedQA) without adaptation to evaluate transferability beyond the training distribution.
