# A Contextual Help Browser Extension to Assist Digital Illiterate Internet Users

## Quick Facts
- **arXiv ID:** 2603.17592
- **Source URL:** https://arxiv.org/abs/2603.17592
- **Reference count:** 30
- **Primary result:** 92% of low-to-intermediate digital literacy users reported improved term comprehension, 96% confirmed time savings versus manual web searches, and 100% would recommend the extension.

## Executive Summary
This paper presents "Acro Helper", a browser extension designed to assist internet users with low digital literacy by providing on-demand definitions of technical acronyms. The extension employs a dual-layer AI pipeline (Google Cloud NLP taxonomy API and OpenAI ChatGPT) to classify pages as technology-related before injecting hover-activated tooltips. Definitions are sourced either from a fast curated dictionary or, for out-of-dictionary terms, from a context-aware LLM. A mixed-methods study with 25 participants showed 92% reported improved term comprehension and 96% confirmed time savings compared to manual web searches, with all participants finding the tooltips non-disruptive and 100% willing to recommend the extension.

## Method Summary
The extension operates through a four-phase pipeline: (A) sanitizing and parsing the page content using Mozilla Readability; (B) classifying the page as technology-related via a two-step AI process (Google NLP taxonomy, with OpenAI fallback); (C) detecting acronyms via regex against a curated dictionary and generating context-aware definitions for missing terms using OpenAI; (D) injecting hover-activated tooltips by wrapping acronyms in `<dfn><abbr>` tags. The system is built with the Plasmo framework for Manifest V3 extensions. Performance benchmarks indicated dictionary-based definitions averaged 2,135 ms while AI-generated definitions took 16,429 ms, both faster than the mean manual search time of 17,200 ms.

## Key Results
- 92% of participants reported improved term comprehension.
- 96% confirmed time savings versus manual web searches.
- 100% would recommend the extension; all found tooltips non-disruptive.

## Why This Works (Mechanism)
The system's effectiveness stems from three key mechanisms:

1. **Dual-layer AI classification for precise page context**  
   The extension uses Google Cloud NLP taxonomy first; only if no technology category is found does it invoke ChatGPT for a boolean check. This reduces false-positive tooltips on non-technology pages, preventing user distraction and maintaining trust. The core assumption is that irrelevant definitions are the primary adoption barrier, and accurate page classification is essential. The paper explicitly states this pipeline reduces false-positive detections (abstract) and details the logic in Section IV.B.

2. **Hybrid definition sourcing balancing speed and context**  
   For acronym detection, the system first queries a fast curated dictionary (average 2,135 ms). If a definition is not found, a secondary OpenAI call generates a context-aware definition (average 16,429 ms). This hybrid approach ensures all acronyms receive a definition while optimizing performance and cost. The core assumption is that users tolerate the slower AI latency for more relevant definitions as long as common terms are served quickly. Evidence shows that despite slower speed, 70% of participants preferred AI-generated definitions for conciseness and relevance (Section VI.G).

3. **Hover-activated tooltips eliminate context-switching**  
   The tooltips are implemented by wrapping detected acronyms in `<dfn><abbr>` tags with definitions in the `title` attribute, causing native browser tooltips to appear on hover. This eliminates the need to switch tabs or formulate search queries, removing the primary time sink in manual acronym resolution. The paper reports 96% of users confirmed time savings versus manual searches, and all found tooltips non-disruptive (abstract, Section VII.A).

## Foundational Learning
1. **Digital Illiteracy as a Situated Barrier**  
   Why needed: The tool targets a specific failure mode—unfamiliar jargon blocking comprehension in the moment—rather than general digital skills training. This "just-in-time" scaffold requires distinguishing between lack of foundational skills and context-specific knowledge gaps.  
   Quick check: Is the problem a lack of foundational skills, or a knowledge gap in a specific context during a specific task? How does your design change for each?

2. **Information Foraging & Cost-Benefit in Help-Seeking**  
   Why needed: Users decide to look up a term based on perceived effort vs. value. Manual search involves high foraging cost (open tab, type, evaluate). The extension reduces this cost to near-zero hover, changing the cost-benefit calculus.  
   Quick check: What are the three highest-cost steps in a user's manual acronym lookup process? How does your design eliminate each?

3. **Preprocessing vs. On-Demand Computation in Browser Extensions**  
   Why needed: The architecture separates expensive analysis (NLP classification) on page load (preprocessing) from cheap on-hover lookups (on-demand). This trade-off is crucial for performance.  
   Quick check: What operations can be deferred until hover without harming the core user experience? What must happen at page load to enable hover functionality?

## Architecture Onboarding
**Component map:**  
Content Script ↔ Background Service Worker ↔ External APIs (Google Cloud NLP, OpenAI ChatGPT, Remote Dictionary Server)  
Popup/Tab Page ↔ Background Service Worker

**Critical path:**  
1. `window.onload` → Content Script triggers.  
2. Phase A: Clone DOM, strip noise, extract text with `@mozilla/readability`.  
3. Phase B: Send text to Google NLP API. If technology category found → proceed; else → send to OpenAI API for boolean check.  
4. If tech page: Fetch acronym keys from dictionary server. Run regex on extracted text to find matches.  
5. For each match: Fetch definition. If not in dictionary, call OpenAI for contextual definition.  
6. Phase D: Modify live DOM to wrap acronyms in `<abbr title="definition">`.  
7. User hovers → native browser tooltip from `title` attribute appears.

**Design tradeoffs:**  
- **Speed vs. Accuracy/Context:** Dictionary path is fast but static; OpenAI path is slower but context-aware. The system defaults to fast, falling back to slow only when necessary.  
- **Cloud vs. On-Device:** All AI is cloud-based, introducing latency and privacy concerns; future work considers an on-device model.  
- **Generality vs. Precision:** Regex matching across all terms causes polysemy (e.g., "POST"); the system lacks contextual disambiguation before matching.

**Failure signatures:**  
- High latency (>2s) on tooltip: dictionary server down, API throttling, network issues.  
- No tooltips on known tech article: Google NLP misclassification, OpenAI fallback returned false, regex failure.  
- Tooltips on non-tech pages: both classifiers incorrectly approved.  
- Incorrect/weird definitions: OpenAI hallucination, outdated dictionary entry.

**First 3 experiments:**  
1. **Dictionary Lookup Benchmark:** Isolate Phase C for 20 common acronyms across 50 page loads; target mean < 2500 ms.  
2. **Classification Accuracy Test:** 50 test pages (25 tech-valid, 25 tech-invalid); target 0 false positives on invalid, <5% false negatives on valid.  
3. **Tooltip Disruption Stress Test:** Dense tech article with 30+ acronyms; measure reading time vs. baseline; target <10% increase, 0 reports of frequent distraction.

## Open Questions the Paper Calls Out
- **Polysemy disambiguation:** How can the extension reliably distinguish multiple meanings of an acronym (e.g., "POST") in context without remote AI latency? The paper notes current regex matching causes false positives and suggests an on-device NLP model, but this remains unimplemented and untested.
- **Long-term efficacy:** Does the extension maintain user acceptance and comprehension benefits in unsupervised browsing over weeks or months? The study was supervised with a small sample (n=25), limiting generalizability.
- **Domain generalizability:** Can the classification pipeline and dictionary be effectively extended to specialized domains like medical or legal jargon? The current taxonomy and dictionary are technology-specific; empirical validation in other domains is lacking.
- **Definition presentation design:** What is the optimal tooltip format (brief vs. extended, tiered) to maximize comprehension and minimize disruption across diverse literacy levels? The paper reports mixed preferences but no systematic A/B testing.

## Limitations
- Dictionary provenance and coverage are unclear, limiting assessment of generalizability and maintenance.
- Classification logic details (thresholds, prompts) are unspecified, hindering replication.
- Disruption claims rely on self-report without objective metrics, risking bias.
