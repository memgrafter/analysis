# Reinforcement Fine-Tuning for History-Aware Dense Retriever in RAG

## Quick Facts
*   **arXiv ID:** 2602.03645
*   **Source URL:** https://arxiv.org/abs/2602.03645
*   **Reference count:** 12
*   **Primary result:** HARR improves end-to-end QA metrics in 17 of 20 comparisons against supervised baselines, with average EM/F1 gains up to +2.21%/+1.57%.

## Executive Summary
This paper tackles the objective mismatch in Retrieval-Augmented Generation (RAG), where a retriever optimized with supervised methods fails to align with the final question-answering (QA) performance. It introduces HARR, a reinforcement fine-tuning framework that treats retrieval as a Markov decision process. Key innovations include replacing deterministic top-k selection with stochastic sampling (via a Plackett-Luce policy) and incorporating the retrieval history into the state representation to reduce aliasing in multi-hop reasoning. The retriever is optimized using Group Relative Policy Optimization (GRPO) with sparse, terminal F1 rewards. Evaluations on HotpotQA and NQ within ReAct and Search-R1 pipelines show consistent QA improvements. Training converges quickly (∼100 steps) and ablations confirm that both RL fine-tuning and history-aware states contribute to the gains.

## Method Summary
HARR formulates the retriever optimization as a Markov Decision Process. The state at step *t* is `s_t = (H_{t-1}, q_t)`, combining the retrieval history with the current sub-query. The action is an ordered list of *k* documents sampled stochastically from a candidate pool (top-*K* by score) using a Plackett-Luce model parameterized by the retriever's encoder. The environment consists of a fixed LLM that generates observations and next sub-queries. After a terminal step, the episode receives a sparse reward equal to the F1 score between the generated answer and the ground truth. For training, the retriever's state encoder is updated using GRPO, which normalizes terminal rewards within a group of sampled trajectories to compute advantages and applies a clipping mechanism to the policy ratio. Critical approximations include restricting the action space to a small candidate pool (*K*=30) and freezing the document encoder to manage memory.

## Key Results
*   HARR improves end-to-end EM/F1 in 17 of 20 comparisons across HotpotQA and NQ with ReAct and Search-R1 pipelines, with average gains up to +2.21% EM and +1.57% F1.
*   Training converges rapidly within approximately 100 steps (∼3 hours) and requires 17–65 GB GPU memory depending on retriever scale.
*   Ablations confirm that RL fine-tuning is the primary driver, while history-aware states provide a secondary, consistent benefit.

## Why This Works (Mechanism)

### Mechanism 1
*   **Claim:** Replacing deterministic top‑k retrieval with stochastic sampling enables the retriever to be optimized via reinforcement learning.
*   **Mechanism:** The retriever is parameterized as a stochastic policy using the Plackett‑Luce model, which samples ordered document lists based on similarity scores. This stochasticity allows for exploration and gradient estimation via policy gradient methods.
*   **Core assumption:** Stochasticity enables exploration and gradient estimation for RL.
*   **Evidence anchors:**
    *   [abstract] "replace deterministic top‑k selection with stochastic sampling"
    *   [section 4.3] "We parameterize the retriever as a stochastic policy πθ" and "Plackett‑Luce ranking model"
    *   [corpus] Weak; neighboring papers do not focus on stochastic sampling for RL‑based retriever optimization.

### Mechanism 2
*   **Claim:** Incorporating retrieval history into the state representation mitigates state aliasing in multi‑hop reasoning.
*   **Mechanism:** The state is defined as `s_t = (H_{t-1}, q_t)`, where `H_{t-1}` is the accumulation of previous queries and observations. This distinguishes states that have the same current query but different retrieval histories, reducing ambiguity in learning signals.
*   **Core assumption:** Different retrieval histories encode distinct information needs, so conditioning on history reduces state ambiguity.
*   **Evidence anchors:**
    *   [abstract] "incorporating retrieval history into state representations to mitigate aliasing in multi‑hop reasoning."
    *   [section 4.2] "To mitigate the state aliasing issue, we define each state `s_t` ∈ `S` at step `t` as a history‑aware representation `s_t` = (`H_{t-1}`, `q_t`)."
    *   [corpus] Moderate; a neighbor paper "History‑Aware Conversational Dense Retrieval" (arxiv:2401.16659) addresses history‑aware retrieval but not specifically for RL state aliasing.

### Mechanism 3
*   **Claim:** Optimizing the retriever with Group Relative Policy Optimization (GRPO) using sparse terminal F1 rewards directly aligns retrieval with end‑to‑end QA performance.
*   **Mechanism:** The retriever policy is updated by maximizing the GRPO objective, which uses normalized terminal rewards (F1 score) as advantages. This bypasses the need for value function estimation and handles sparse rewards within a group of sampled trajectories.
*   **Core assumption:** Terminal reward signal is sufficient to guide retrieval across multiple hops.
*   **Evidence anchors:**
    *   [abstract] "optimizes the retriever using Group Relative Policy Optimization with F1‑based terminal rewards."
    *   [section 4.4] "We adopt Group Relative Policy Optimization (GRPO)" and equation (12).
    *   [corpus] Weak; while "Optimizing Retrieval for RAG via Reinforcement Learning" (arxiv:2510.24652) explores RL for retrieval, it uses different algorithms and reward structures.

## Architecture Onboarding
*   **Component map (plain text flow):**
    Query -> State Encoder (computes `s_t`) -> Score all docs -> Candidate Pool (top-K) -> Stochastic Sampling (Plackett-Luce) -> k Documents -> LLM (Environment) -> Observation & Next Sub-query -> Update History -> Next State

*   **Critical path:**
    During training, for each batch of queries, sample `G` trajectories per query using the current policy. Each trajectory proceeds in hops: given state `s_t`, compute scores over the full corpus, form candidate pool `C_t` (top-K), sample an ordered list of `k` docs from `C_t` via Plackett-Luce, pass these to the fixed LLM to get an observation and next sub-query, and update the history `H_t`. At termination, compute the terminal F1 reward. Normalize these rewards within the group to obtain advantages, compute the GRPO loss using the log-probability ratio of the new vs. old policy for the sampled actions, and backpropagate to update only the state encoder (and optionally a LoRA module). The document encoder remains frozen.

*   **Design tradeoffs:**
    *   Stochastic vs. deterministic: Stochasticity enables RL exploration but may hurt retrieval precision at inference if temperature is not annealed.
    *   History-aware state: Reduces aliasing but increases state complexity and may introduce noise or require more model capacity; also lengthens LLM context.
    *   Candidate pool restriction: Reduces memory/computation by limiting action space but may exclude optimal documents not in the top-K.
    *   Frozen document encoder: Saves memory and speed but prevents updating document representations, which could be beneficial for some corpora.

*   **Failure signatures:**
    *   Training reward plateaus at low values: Could indicate poor exploration, reward sparsity, or mis-specified state representation.
    *   High gradient norm variance: Suggests unstable updates from sparse rewards; may require more rollouts per group or reward shaping.
    *   Out‑of‑memory errors: Likely caused by a large candidate pool `K` or an unfrozen document encoder; reduce `K` or freeze the encoder.
    *   Degradation on single‑hop datasets: History may add unnecessary noise; consider disabling history for such tasks or using an adaptive mechanism.

*   **First 3 experiments:**
    1.  **Main comparison:** Evaluate HARR against Frozen Retriever and REPLUG baselines on ReAct and Search‑R1 pipelines across HotpotQA and NQ, with two retriever sizes (4B/0.6B). Report EM/F1.
    2.  **Ablation study:** Remove history‑aware state and/or RL fine‑tuning (using only supervised pre-training) to measure each component's contribution on the ReAct agent.
    3.  **Efficiency analysis:** Measure training convergence speed (steps), wall‑clock time, and peak GPU memory consumption for different retriever scales and configurations.

## Open Questions the Paper Calls Out
*   How can training oscillations in HARR be reduced? The paper attributes oscillations to sparse terminal rewards and off‑policy approximations but does not provide a solution.
*   How can history‑aware states be made effective for lightweight retrievers (e.g., 0.6B)? Ablations show history-only without RL fails for small models, and history+RL yields only modest gains.
*   Can HARR be extended to jointly optimize the retriever and LLM, and how can non‑stationarity be managed? The paper keeps the LLM fixed due to cost and non‑stationarity challenges.
*   How does the choice of terminal reward (e.g., F1, EM, LLM‑based scores) affect HARR? The framework uses F1 exclusively without investigating alternatives.

## Limitations
*   LLM prompting templates and generation parameters for the ReAct and Search‑R1 pipelines are not described, hindering exact replication.
*   The training query filtering criterion ("non‑zero reward variance") is ambiguous and not quantitatively defined.
*   Reported GPU memory requirements are high (61–65 GB for the 4B retriever), with no analysis of scaling or memory reduction techniques.
*   Gains are modest (≤ 2.2% EM) and evaluated on only two datasets with fixed pipelines, limiting generalizability claims.
*   Corpus evidence for the core mechanisms (stochastic policy for RL, history for aliasing) is weak, suggesting a need for independent validation.

## Confidence
*   **RL fine‑tuning drives QA gains:** **Medium**. Strong internal ablations but lacks external verification and broad generalization.
*   **Stochastic policy + GRPO enables RL optimization:** **High**. Mechanism is theoretically sound and necessary per ablations.
*   **History‑aware state reduces aliasing:** **Medium**. Ablation shows contribution, but magnitude is small and history design is not thoroughly explored.
*   **Terminal F1 reward suffices:** **Medium**. Convergence is achieved, but sparsity may be problematic in other settings; no reward function comparison.
