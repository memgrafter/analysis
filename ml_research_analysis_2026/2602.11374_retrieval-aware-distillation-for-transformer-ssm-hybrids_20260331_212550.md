# Retrieval-Aware Distillation for Transformer-SSM Hybrids

## Quick Facts
- **arXiv ID**: 2602.11374  
- **Source URL**: https://arxiv.org/abs/2602.11374  
- **Reference count**: 28  
- **Primary result**: Retaining 2% of attention heads (10 heads) recovers >95% teacher performance on retrieval-heavy benchmarks, a 10× reduction over heuristic hybrids, while enabling 8× SSM state reduction and 5–6× better memory efficiency.

## Executive Summary
State Space Models (SSMs) are memory-efficient but lag behind Transformers on in-context retrieval tasks. This work shows that the gap stems from a small set of attention heads that implement a Gather-and-Aggregate (G&A) mechanism for precise key‑value lookup. By scoring every attention head in a pretrained Transformer via ablation on a synthetic KV‑retrieval probe, the authors identify the most retrieval‑critical heads. They then construct a hybrid model that preserves only the top‑k heads (e.g., 10 out of 512) and replaces all others with SSM components (DiscreteMamba2). A two‑stage distillation (MOHAWK) aligns the SSMs to the teacher’s intermediate representations before end‑to‑end knowledge distillation. On 1B‑scale models, retaining just 2% of heads restores over 95% of teacher performance on retrieval‑heavy benchmarks—a 10× reduction versus heuristic hybrids that keep >25% heads. Furthermore, because retrieval is fully offloaded to attention, the SSM state dimension can be shrunk by 8× with minimal loss. The resulting hybrids are 5–6× more memory‑efficient across sequence lengths, closing the Transformer–SSM performance gap at a fraction of the memory cost.

## Method Summary
The method converts a pretrained Transformer into a memory‑efficient hybrid via retrieval‑aware distillation. First, each attention head is ablated on a synthetic key‑value retrieval probe to compute a retrieval‑importance score (higher accuracy drop → more critical). The top‑k heads (e.g., k=10) are retained; all others are replaced by DiscreteMamba2 SSM modules. A parameter‑free LayerNorm “Adapter” is inserted after concatenating the retained attention outputs to match SSM output statistics before the final projection. The student model is trained with a two‑stage MOHAWK pipeline: (1) hidden‑state alignment trains only the new SSM parameters to mimic the teacher’s block outputs; (2) full end‑to‑end knowledge distillation minimizes cross‑entropy between student and teacher logits. This isolates exact retrieval to the preserved G&A heads, allowing the SSM backbone to focus on continuous sequence modeling and enabling aggressive state‑size reduction.

## Key Results
- Retaining only 2% of attention heads (10/512) recovers >95% of teacher performance on retrieval‑heavy benchmarks, a 10× reduction compared to heuristic hybrids that retain >25% heads.
- With retrieval offloaded to attention, the SSM state dimension can be reduced by 8× (from 64 to 8) with minimal performance loss.
- The resulting hybrids achieve 5–6× better memory efficiency across sequence lengths, closing the Transformer–SSM performance gap at a fraction of the memory cost.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Retrieval-aware distillation achieves near‑teacher performance by preserving only the attention heads that implement Gather‑and‑Aggregate (G&A) functionality, while replacing all other heads with SSMs.
- **Mechanism**: Each attention head in the teacher is ablated on a synthetic key‑value (KV) retrieval probe to compute a retrieval‑importance score. The top‑*k* heads (by score) are retained unchanged; all other heads are replaced with SSM components (e.g., DiscreteMamba2). The student is then distilled via hidden‑state alignment and logit matching.
- **Core assumption**: The synthetic KV‑retrieval task isolates heads critical for in‑context retrieval on real benchmarks.
- **Evidence anchors**:
  - [abstract] “We identify the essential heads via ablation on a synthetic retrieval task, producing a hybrid with sparse, non‑uniform attention placement.”
  - [section 4.1] “We systematically ablate each attention head in the teacher model individually and measure the resulting drop in accuracy on the synthetic task.”
  - [corpus] Neighbor paper [66978] reports catastrophic retrieval failure when ablating all attention layers, supporting that retrieval depends on a small subset of attention heads.
- **Break condition**: If the synthetic probe poorly correlates with downstream retrieval tasks (e.g., multi‑hop reasoning), the selected heads may not generalize.

### Mechanism 2
- **Claim**: The Gather‑and‑Aggregate (G&A) pattern—comprising “Gather” heads that compress local information into transport tokens and “Aggregate” heads that globally retrieve from these tokens—is the specific mechanism by which attention performs in‑context retrieval, and SSMs cannot replicate it directly.
- **Mechanism**: Gather heads move key‑value pair information into a designated token (e.g., a newline), creating a summary vector. Aggregate heads then attend primarily to these transport tokens to match the query and extract the corresponding value. This two‑stage process enables precise long‑range lookup.
- **Core assumption**: G&A is the dominant retrieval mechanism in Transformers, and its absence in SSMs explains the performance gap.
- **Evidence anchors**:
  - [abstract] “Prior work links this gap to a small set of attention heads, termed Gather‑and‑Aggregate (G&A), which SSMs struggle to reproduce.”
  - [section 3.2] Detailed description of the G&A pattern with dictionary learning example.
  - [corpus] Neighbor paper [66978] finds retrieval exclusively in self‑attention layers with no compensation from SSM layers, consistent with a distinct G&A mechanism concentrated in attention.
- **Break condition**: If future work discovers alternative retrieval mechanisms in SSMs or shows that G&A can be learned directly by SSMs through architectural changes.

### Mechanism 3
- **Claim**: Once retrieval is fully offloaded to the preserved G&A heads, the SSM backbone’s state dimension can be drastically reduced (e.g., 8×) with minimal performance loss, because the SSM no longer needs to store long‑range information.
- **Mechanism**: Large SSM states in pure models compensate for the lack of explicit retrieval. With G&A heads handling exact lookup, the SSM’s role shifts to local sequence modeling, which requires far less memory capacity.
- **Core assumption**: There is a functional separation: attention handles precise retrieval; SSM handles continuous sequential modeling.
- **Evidence anchors**:
  - [abstract] “with retrieval offloaded to attention, the SSM state dimension can be reduced by 8× with minimal loss.”
  - [section 5.6] Table 4 shows that reducing *d_state* from 64 to 8 yields negligible drop in coverage when top‑20 attention heads are retained.
  - [corpus] Limited direct evidence; however, neighbor paper [4600] discusses state‑size trade‑offs in SSMs, aligning with the principle that specialized attention reduces SSM burden.
- **Break condition**: If aggressive state reduction harms other facets (e.g., commonsense reasoning) or if retrieval tasks prove more coupled to SSM processing than the ablations suggest.

## Architecture Onboarding
- **Component map**: Teacher Transformer -> Ablation Scoring (with Synthetic KV-retrieval Probe) -> Hybrid Student Construction (select top‑k attention heads, replace others with SSM, add Adapter) -> MOHAWK Training (Alignment then Distillation)
- **Critical path**:
  1. Score all teacher attention heads via KV‑retrieval ablation.
  2. Select top‑*k* heads (e.g., 10 for 1B models).
  3. Build student: copy selected attention heads; initialize SSM components for remaining heads.
  4. Insert Adapter in each modified layer (between head concatenation and output projection).
  5. Train: (a) Hidden‑State Alignment on 12B tokens; (b) end‑to‑end distillation.
  6. Optionally reduce SSM state dimension (*d_state*) based on memory‑performance trade‑off.
- **Design tradeoffs**:
  - *k*: Smaller *k* reduces KV‑cache memory but risks insufficient retrieval. Evidence suggests 2% heads suffice at 1B scale; may not hold at larger scales.
  - *d_state*: Reducing state size cuts constant memory, but too low (<8) degrades retrieval‑heavy tasks even with attention anchors.
  - Placement: Retrieval‑aware non‑uniform placement vs. heuristic (e.g., fixed interleaving) saves memory but requires ablation scoring.
  - Distillation cost: Less than full pretraining but still requires 12B tokens and FSDP training.
- **Failure signatures**:
  - Sharp drop on retrieval‑heavy benchmarks (KV‑Retrieval, SWDE) while knowledge‑focused tasks remain stable.
  - Memory savings not realized: check if *k* is too high or *d_state* not reduced.
  - Distillation instability: verify Adapter normalization and alignment stage convergence.
- **First 3 experiments**:
  1. Ablation study on teacher: score all heads, confirm top retrieval heads cluster in specific layers (as in Table 5).
  2. Retention sweep: train hybrids with *k* = {0, 5, 10, 20, 30} and measure coverage on retrieval‑heavy vs. knowledge‑focused benchmarks to find minimal sufficient *k*.
  3. State compression: for the chosen *k*, vary *d_state* ∈ {4, 8, 16, 32, 64} and evaluate both benchmark groups to identify maximal compression without >5% coverage drop on retrieval‑heavy tasks.

## Open Questions the Paper Calls Out
**Open Question 1**: Does retrieval‑aware distillation maintain its efficiency gains at larger model scales (beyond 3B parameters)?  
- *Basis in paper*: First, we only evaluate models below 3B parameters, so it is unclear whether the same small set of heads remains sufficient at larger scale, where retrieval behavior and head redundancy may change.  
- *Why unresolved*: The study only validated on 1B and 1.5B parameter models; scaling dynamics could alter the functional distribution across heads.  
- *What evidence would resolve it*: Apply the same ablation‑and‑retain methodology to models of increasing scale (e.g., 3B, 10B, 70B) and measure whether the number of critical retrieval heads grows superlinearly, linearly, or remains constant relative to total heads.

**Open Question 2**: Is synthetic KV‑retrieval a sufficient proxy for identifying all retrieval‑critical heads across diverse retrieval task distributions?  
- *Basis in paper*: Second, head selection relies on the synthetic KV‑retrieval probe… other retrieval settings (e.g., multi‑hop retrieval) may rely on components not identified by this probe.  
- *Why unresolved*: KV‑retrieval tests simple one‑hop key‑value recall but may not capture more complex retrieval patterns like multi‑hop reasoning or cross‑document retrieval.  
- *What evidence would resolve it*: Run retrieval‑aware distillation using KV‑retrieval ranking, then evaluate on a battery of multi‑hop retrieval benchmarks. Significant performance gaps relative to full Transformers would indicate the probe’s incompleteness.

**Open Question 3**: Can parameter‑sharing techniques for KV‑cache (e.g., cross‑layer or group‑wise sharing) be integrated into the distillation pipeline to further reduce memory overhead?  
- *Basis in paper*: Third, although our hybrid stores fewer total KV pairs than prior hybrids, our distillation does not enforce KV sharing across layers… Enabling KV sharing during distillation could further reduce the KV cache, but we leave this to future work.  
- *Why unresolved*: The current implementation treats each attention head independently; known techniques from literature for reducing KV footprint are not exploited.  
- *What evidence would resolve it*: Implement a hybrid where KV pairs are shared across layers or within groups (similar to Grouped‑Query Attention) during distillation, and measure the memory savings versus any performance degradation.

**Open Question 4**: Can the remaining coupling between SSM backbone and retrieval tasks be eliminated to enable even smaller recurrent states?  
- *Basis in paper*: Finally, retrieval is not fully separated from the recurrent backbone… This coupling limits how aggressively we can shrink d_state without degrading retrieval‑intensive performance, and achieving a cleaner separation remains an open direction.  
- *Why unresolved*: Even with retrieval‑critical attention heads preserved, ablating some SSM heads still hurts retrieval benchmarks, indicating residual interference.  
- *What evidence would resolve it*: Perform mechanistic analysis to identify and modify SSM components that leak into retrieval; test whether d_state can be reduced below 8× without performance loss when this coupling is broken.

## Limitations
- Synthetic KV‑retrieval probe specification is unreproduced; head rankings may not generalize to complex retrieval tasks.
- DiscreteMamba2 implementation details (discretization, initialization) are unspecified, risking incompatible operator mixing during distillation.
- MOHAWK training hyperparameters (alignment steps, loss weighting, convergence criteria) are vague, potentially affecting stability.

## Confidence
- G&A mechanism explanation: **High** (supported by internal analysis and corroborated by neighbor papers)
- 2% head sufficiency: **Medium** (validated at 1B scale on specific benchmarks; scalability and task generality unverified)
- 8× state reduction: **Medium** (depends on clean separation of retrieval vs. sequential modeling; risks hidden coupling)
