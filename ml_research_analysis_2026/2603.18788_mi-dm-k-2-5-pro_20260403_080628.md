# Mi:dm K 2.5 Pro
## Quick Facts
- arXiv ID: 2603.18788
- Source URL: https://arxiv.org/abs/2603.18788
- Reference Count: 40
- Primary Result: Achieves state-of-the-art on Korean-specific benchmarks (Ko-Sovereign, KoBALT, CLIcK-L) and competitive results on global English and code benchmarks, with high safety (36.3% attack success).

## Executive Summary
Mi:dm K 2.5 Pro is a 32B parameter Korean-focused large language model designed for enterprise scenarios requiring advanced reasoning, long-context understanding, and agentic workflows. The authors combine a quality-centric data pipeline—with AST-based code filtering and LLM-based quality evaluation—with efficient pre-training via layer-predictor Depth Upscaling (DuS) and progressive context extension to 128K tokens. Post-training includes multi-stage Reasoning SFT, linear model merging, asynchronous RL (verl + GSPO) with LLM-as-a-Judge rewards, and a final Fusion SFT/RL to balance reasoning, conversational fluency, and tool use. The model reaches state-of-the-art performance on Korean benchmarks and remains competitive on global English and coding benchmarks while maintaining high safety standards (36.3% attack success).

## Method Summary
The training pipeline comprises three phases. Data curation assembles Korean corpora (AI-HUB, NIKL, K-Data Alliance) plus limited multilingual (Chinese/Japanese) and STEM/code/agentic datasets (peS2o, OpenStax, licensed problem banks). Code data is refined with an AST-based executability filter, difficulty labeling, and task classification; mathematics data is domain-balanced and gap-filled synthetically; general tasks receive response style rewriting; and an LLM acts as quality evaluator for SFT data. Pre-training scales a base model to 32B parameters via layer-predictor DuS while extending context from 4K to 128K using YaRN, supported by RegMix data mixing and replay to avoid forgetting. Post-training applies Reasoning SFT with dataset-specific mixtures (packed to 64K), merges specialized models linearly, runs asynchronous RL with GSPO and LLM-as-a-Judge rewards (including formatting/repetition penalties and rollout correction), and performs a final Fusion SFT/RL to restore non-reasoning and tool-use capabilities. Tokenization uses 1-digit units and a chat template with analysis, commentary, and final channels.

## Key Results
- State-of-the-art on Korean benchmarks: Ko-Sovereign, KoBALT, CLIcK-L.
- Competitive on global English benchmarks: MMLU-Pro, GPQA-D, MATH-H, AIME25, and coding/agentic tasks.
- Safety: 36.3% attack success rate with balanced harmlessness-responsiveness.

## Why This Works (Mechanism)
The method succeeds through synergy of high-quality data, efficient scaling, and targeted post-training. AST filtering and LLM evaluation raise the signal of code and reasoning data, which is crucial given limited Korean resources. DuS enables rapid capacity expansion without full pre-training, while progressive context extension preserves short-context knowledge. Reasoning SFT embeds multi-step logic; asynchronous RL with LLM-as-a-Judge further refines reasoning and safety; and the final Fusion stage rebalances for conversational fluency and tool use, preventing over-specialization.

## Foundational Learning
1. **Layer-Predictor Depth Upscaling (DuS)**
   - *Why needed*: Efficiently increase model capacity without full pre-training cost.
   - *Quick check*: Expand layers from a base checkpoint and verify loss continuity and no performance drop on a validation set.

2. **AST-Based Code Filtering**
   - *Why needed*: Ensure code data is executable and syntactically valid, improving training signal.
   - *Quick check*: Measure precision/recall on a held-out set of known good/poor code against execution tests.

3. **Progressive Context Extension (YaRN)**
   - *Why needed*: Adapt to very long contexts (128K) without catastrophic forgetting of short-context knowledge.
   - *Quick check*: Test perplexity and task performance at each intermediate context length (4K→32K→64K→128K).

4. **Asynchronous RL with LLM-as-Judge**
   - *Why needed*: Scale reinforcement learning for reasoning improvement while leveraging a more capable reward model.
   - *Quick check*: Monitor KL divergence between rollout and trainer policies; aim for KL drift <0.1 per 100 steps.

## Architecture Onboarding
- **Component Map**: Korean/Multilingual Corpora -> AST Filter -> LLM Quality Evaluator -> Curated SFT Data -> Pre-trained Model (DuS + YaRN) -> Reasoning SFT -> Model Merging -> Asynchronous RL (verl + GSPO) -> Fusion SFT/RL -> Final Model (Mi:dm K 2.5 Pro)
- **Critical Path**: 1) Data curation 2) DuS pre-training with progressive context 3) Reasoning SFT 4) Model merging 5) Asynchronous RL 6) Fusion training.
- **Design Tradeoffs**:
  - DuS reduces compute but may limit flexibility in depth selection.
  - AST filtering reduces noisy code but risks false positives on atypical valid code.
  - Asynchronous RL improves scalability but introduces policy lag needing robust correction.
  - Model merging combines strengths but can cause task interference.
- **Failure Signatures**:
  - Rising KL divergence in RL (stale rollouts/poor correction).
  - Drop in code execution pass rate after filter updates.
  - Degradation on short-context tasks post-context-extension (forgetting).
  - LLM-as-a-Judge reward hacking (verbose/repetitive outputs).
  - Post-merging performance drops on some tasks (merge conflict).
- **First Experiments**:
  1. Data pipeline audit: replicate AST filtering and LLM evaluation; target ≥90% filter accuracy.
  2. DuS scalability test: apply to a 3-layer proxy (e.g., 1B→3B); verify loss continuity and stable extension to 32K context.
  3. RL stability probe: run short asynchronous RL with GSPO; track KL drift (<0.1 per 100 steps) and reward variance.

## Limitations
- Pre-training hyperparameters and exact data mixture proportions are unspecified, hindering faithful reproduction.
- Korean benchmark claims lack independent external validation.
- Global/code results are competitive but not state-of-the-art, with low reproducibility confidence due to missing architectural details.
- Safety evaluation provides aggregate metrics without detailed threat-model or adversarial sample diversity analysis.

## Confidence
- Korean benchmark performance: **Medium**
- Global/code benchmark performance: **Low**
- Safety metrics: **Medium**

## Next Checks
- Audit the data pipeline: measure AST filter precision/recall and LLM evaluator agreement against a gold standard; target ≥90% filter accuracy.
- Validate DuS scalability: train a small proxy model through depth expansion and progressive context extension; ensure no loss spikes and stable perplexity at 32K context.
- Probe RL stability: run a brief asynchronous rollout with difficulty-aware prompts; monitor KL divergence (goal <0.1 per 100 steps) and reward coefficient of variation; adjust rollout correction frequency if needed.
