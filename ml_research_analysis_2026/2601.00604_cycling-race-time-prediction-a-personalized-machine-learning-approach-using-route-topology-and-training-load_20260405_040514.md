# Cycling Race Time Prediction: A Personalized Machine Learning Approach Using Route Topology and Training Load
## Quick Facts
- **arXiv ID:** 2601.00604
- **Source URL:** https://arxiv.org/abs/2601.00604
- **Reference Count:** 19
- **Primary Result:** A personalized Lasso model using route topology and training load metrics predicts cycling duration with MAE=6.60 minutes and R²=0.922.

## Executive Summary
This study presents a personalized machine learning approach to predict cycling race duration before the ride begins. It leverages two pre-ride data sources: the route's physical topology extracted from a GPX file (distance, elevation, gradient variability, climb metrics) and the athlete's recent training history (CTL, ATL, TSB) as a proxy for fitness and fatigue. By training an individualized Lasso regression model on 96 rides from a single athlete, the method achieves high accuracy (MAE=6.60 min, R²=0.922). Incorporating fitness features reduces prediction error by 14% compared to a model using only topology, underscoring that performance depends on both the terrain and the rider's current state. The work emphasizes rigorous feature engineering to prevent data leakage and demonstrates that regularized linear models outperform more complex algorithms on small, personal datasets.

## Method Summary
The study uses an N-of-1 design with 96 outdoor cycling rides from one athlete, sourced from Intervals.icu. Data includes second-by-second GPS, altitude, and power streams, alongside daily calculated fitness metrics (Chronic Training Load/CTL, Acute Training Load/ATL, Training Stress Balance/TSB). The target variable is moving time (duration). Features are engineered strictly from pre-ride information: 27 topology features (e.g., total distance, total ascent, "punchiness" as gradient variability, climb detection and scoring, gradient distribution, sharp turns) and 52 fitness/history features (CTL, ATL, TSB, ramp rate, and 48 rolling zone hours from power/HR data). To prevent leakage, rolling windows exclude the ride day. Models (Ridge, Lasso, ElasticNet, Random Forest) are evaluated via nested 5-fold cross-validation (outer stratified by distance quintiles, inner for hyperparameter tuning). The best model, Lasso with both topology and fitness features, is selected based on validation MAE. All preprocessing (imputation, scaling) is confined to training folds to avoid contamination.

## Key Results
- Personalized Lasso model (topology + fitness) achieves MAE=6.60 minutes and R²=0.922.
- Adding fitness features reduces error by 14% compared to a topology-only model (MAE=7.66 min).
- Regularized linear models (Lasso) significantly outperform Random Forest (MAE=13.36 min) on this small dataset (N=96), avoiding catastrophic overfitting.
- The model enables progressive checkpoint predictions as the ride unfolds, though prediction error evolves significantly on routes with back-loaded difficulty.

## Why This Works (Mechanism)
### Mechanism 1: Route Topology as Baseline Demand
- **Claim:** Aggregated terrain characteristics (distance, elevation, gradient stats, climb difficulty) establish a baseline duration prediction for any cyclist on a given route.
- **Mechanism:** Features are extracted from pre-ride GPX data. Climbs are detected via a Garmin ClimbPro-like algorithm (≥3% gradient, ≥500m length) and scored by `length × gradient`. Gradient variability ("punchiness") uses `std(|Δg|)` to capture non-linear fatigue from rolling terrain. These metrics act as proxies for physical workload.
- **Core assumption:** The relationship between aggregated terrain metrics and self-paced duration is stable enough within an individual to be learned from historical rides.
- **Evidence:** Paper details climb detection and gradient statistics in section 3.2.1; the abstract lists topology features as core inputs.

### Mechanism 2: Training Load as Fitness/Fatigue Proxy
- **Claim:** CTL (42-day exponential TSS) approximates aerobic fitness; ATL (7-day) captures recent fatigue; their difference (TSB) indicates readiness. These metrics modulate the effective speed achievable on a given topology.
- **Mechanism:** These are computed from historical power data prior to the ride. The model learns how time-varying fitness states correlate with duration on similar past routes, implicitly adjusting predictions for "form."
- **Core assumption:** An athlete's recent training history reliably influences their sustainable power output on a given route, even in self-paced efforts.
- **Evidence:** Sections 1.2 and 3.2.2 explicitly define CTL/ATL/TSB as "athlete state features."

### Mechanism 3: Regularization for Small Data
- **Claim:** Lasso's L1 regularization enables robust prediction on small, personalized datasets (N=96) by preventing overfitting and performing embedded feature selection.
- **Mechanism:** The L1 penalty drives some coefficients to zero, producing a sparse, interpretable model that generalizes better than non-linear ensembles (Random Forest) when features (P=79) are many and correlated (e.g., distance and total ascent, r=0.82).
- **Core assumption:** The true mapping between terrain/fitness and duration is approximately linear or well-approximated by a sparse linear combination.
- **Evidence:** Section 4.2.2 shows Lasso outperforms Random Forest (MAE 6.60 vs. 13.36 min) and reports a learning curve where validation error plateaus near 60 samples.

## Foundational Learning
- **Concept: N-of-1 Study Design**
  - **Why needed:** Inter-individual variability in cycling physiology is huge. A population model would require extensive lab testing per athlete. Personalized models leverage abundant within-subject GPS/power data.
  - **Quick check:** Why might a model trained on one athlete's data be more accurate for *that* athlete than a model trained on 100 different athletes?
- **Concept: Feature Engineering to Prevent Data Leakage**
  - **Why needed:** Using result-derived metrics (e.g., average speed) as inputs would look backward at the outcome, inflating training accuracy but failing at deployment. Only pre-ride available data (GPX + training history) may be used.
  - **Quick check:** Why is "average speed on the route" an invalid feature for predicting duration *before* the ride?
- **Concept: Nested Cross-Validation for Small Datasets**
  - **Why needed:** With N=96, both hyperparameter tuning and performance estimation risk overfitting. Nested CV (outer loop for evaluation, inner for tuning) ensures test folds remain unseen during model selection.
  - **Quick check:** In a 5-fold nested CV, how many times is a given data point used for testing in the outer loop?

## Architecture Onboarding
- **Component map:** Raw Activity → Cleaning → [Topology Pipeline, Fitness Pipeline] → Feature Store → Training Pipeline (Nested CV) → Trained Lasso Model → Deployment Service.
- **Critical path:** `Raw Activity → Clean → [Topology Features, Fitness State] → Scaled Feature Vector → Lasso Model → Predicted Minutes`. The fitness state requires a continuous training history feed (daily TSS).
- **Design tradeoffs:**
  - Personalization vs. Cold Start: High accuracy for users with history vs. no universal model. A topology-only model (MAE 7.66 min) serves new users.
  - Simplicity vs. Accuracy: Lasso (31 features) chosen over Random Forest due to small N. Tradeoff: potential lost non-linear signals for stability.
  - Pre-ride vs. Progressive: Static full-route prediction vs. checkpoint updates. Progressive requires re-extracting topology from partial GPX, more compute, but enables dynamic planning.
- **Failure signatures:**
  - High train-test MAE gap (>2 min): Overfitting or feature leakage (e.g., including speed-derived metrics). Solution: revert to strictly a priori features.
  - Unstable CV predictions (high std): Dataset too small or features noisy. Solution: reduce feature set (topology-only), increase regularization.
  - Systematic bias for long routes: Model under-predicts >400 min rides. Check: missing fatigue accumulation features. Solution: add cumulative climb scores or segment interactions.
- **First 3 experiments:**
  1. Baseline replication: Train Lasso on `distance + total_ascent` only. Expected MAE ~6.9 min. Verifies basic terrain signal.
  2. Leakage test: Intentionally include `average_speed` or `VAM`. Should yield artificially high training R² (>0.95) but catastrophic test drop. Confirms leakage prevention necessity.
  3. Progressive prediction demo: On a back-loaded route, compute predictions at 25%, 50%, 75%, 100% completion using truncated GPX. Expect large prediction evolution (>200% increase), demonstrating utility for dynamic planning.

## Open Questions the Paper Calls Out
1.  What accuracy improvement and feature engineering approach yield the best integration of environmental factors (wind direction/velocity, temperature) into the topology+fitness model?
2.  How much does prediction accuracy improve when transitioning to population-level models trained on multiple athletes, and can transfer learning reduce cold-start requirements for new users?
3.  Can experimental or causal inference methods enable reliable interpretation of fitness feature coefficients for "what-if" scenarios like tapering effects, despite predictor correlation in N-of-1 data?
4.  How accurately can models predict remaining ride duration at arbitrary checkpoints during the ride, and what architectural approach best accounts for accumulated fatigue and remaining terrain?
5.  Would gradient boosting or neural network models provide statistically significant accuracy gains over Lasso for cycling duration prediction with larger datasets (N>500), and which non-linear feature interactions are most predictive?

## Limitations
- **Generalizability Beyond Single Athlete:** The core result (MAE=6.60 min) is from one athlete's 96 rides. It is unknown if the model generalizes to other cyclists with different physiology or to a population model.
- **Climb Detection Fidelity:** Exact implementation of the ClimbPro-like algorithm (gap handling, smoothing, category thresholds) is not fully specified; minor variations could alter topology features.
- **Dataset Representativeness:** The private Intervals.icu dataset (Mar 2023–Oct 2025) may have specific biases (e.g., athlete's preferred terrain, data completeness). No public dataset exists for replication.

## Confidence
- **High:** Within-subject predictive performance of the personalized Lasso model on the reported dataset (N=96). The nested CV procedure and leakage prevention are rigorously described.
- **Medium:** That the specific feature engineering (punchiness, climb scoring) captures meaningful terrain difficulty for *this* athlete. The 14% error reduction from adding fitness features is statistically reliable for this case.
- **Low:** That the identified mechanism (topology + CTL/ATL) is the primary driver of performance across cyclists. The physiological assumption (CTL/ATL as fitness proxies for self-paced efforts) lacks strong external validation in the literature corpus.

## Next Checks
1.  **Temporal Integrity Audit:** Recompute CTL/ATL/TSB and rolling zone hours for a subset of rides, strictly enforcing that the ride's start date is *after* all training days in the calculation window (no same-day TSS). Compare distributions to detect potential leakage.
2.  **Feature Reproduction Spot-Check:** Manually extract topology features (punchiness, climb count/score, sharp turns) for 3-5 example routes using the stated formulas. Quantify deviation from paper-reported feature values/descriptions.
3.  **External Validity Pilot:** Train the identical pipeline on a different single-athlete dataset (≥80 rides) from a public source (e.g., a well-documented pro athlete's Strava). Test if the fitness feature contribution (topology-only vs. full model MAE gap) remains ~14%.
