# GazeMoE: Perception of Gaze Target with Mixture-of-Experts

## Quick Facts
- **arXiv ID:** 2603.06256  
- **Source URL:** https://arxiv.org/abs/2603.06256  
- **Reference count:** 38  
- **Primary result:** Achieves state-of-the-art gaze target estimation with AUC 0.939 (VideoAttentionTarget) and robust generalization to 360° images (GazeFollow360) and zero-shot scenarios (EYEDIAP).

## Executive Summary
GazeMoE tackles the problem of estimating where a person is looking in an image. It uses a frozen DINOv2 foundation model to extract robust visual features and introduces a Mixture-of-Experts (MoE) decoder that adaptively integrates multiple cues (eyes, head pose, gestures, context). A focal loss addresses the inherent class imbalance between in-frame and out-of-frame gazes, and targeted augmentations improve robustness. The method sets new performance records on standard benchmarks and generalizes well to challenging conditions like 360° imagery and unseen datasets.

## Method Summary
The architecture is encoder-decoder: a frozen DINOv2 ViT-L encoder processes the input image (448×448) along with head bounding box prompts. The decoder consists of three transformer blocks, each replacing the standard feed-forward network with an MoE module containing one shared MLP and four routed MLPs (top-2 routing). Two output heads predict a 64×64 heatmap for in-frame gaze location and an in/out-frame classification. Training uses a combined loss: per-pixel BCE for the heatmap and focal loss (γ=2.0, α set by class ratio) for classification. The model is first pre-trained on GazeFollow (15 epochs, batch 60, lr 1e-3) and then fine-tuned on target datasets (e.g., VideoAttentionTarget: λ=1, 10 epochs; ChildPlay: λ=0.1, 3 epochs) with a lower learning rate for the encoder. Augmentations include random cropping (preserving gaze point), flipping, head prompt jitter, and photometric changes.

## Key Results
- On VideoAttentionTarget: AUC 0.939, Mean L2 0.097.
- On ChildPlay: AUC 0.945.
- Demonstrates strong generalization on 360° images (GazeFollow360) and zero-shot (EYEDIAP).

## Why This Works (Mechanism)
GazeMoE works by using a Mixture-of-Experts decoder to dynamically allocate computation to relevant multi-modal cues (e.g., eyes, head pose, gestures, context) extracted from a frozen DINOv2 backbone. The shared expert captures common features while routed experts specialize for scene-specific patterns, enabling adaptive integration. Focal loss mitigates the severe imbalance between in-frame and out-of-frame gazes, and targeted augmentations force the model to rely on robust cues. This combination yields high accuracy and resilience to distribution shifts.

## Foundational Learning
- **Mixture-of-Experts (MoE):** Enables conditional computation, allowing the model to activate only relevant subnetworks per input. *Why needed:* Prevents a single decoder from being overwhelmed by diverse cues. *Quick check:* Monitor gating entropy; low entropy may indicate routing collapse.
- **Focal Loss:** Down-weights easy examples and focuses on hard/rare ones. *Why needed:* In/out-frame class imbalance is extreme (most gazes are in-frame). *Quick check:* Compute per-class precision/recall; if out-of-frame recall is near zero, α may be too low.
- **Foundation Models (DINOv2):** Provides rich, transferable visual representations without extensive labeled data. *Why needed:* Gaze estimation benefits from robust semantic and structural features learned from large-scale data. *Quick check:* Linear probe DINOv2 features on a simple gaze dataset; high accuracy confirms gaze-relevant encoding.
- **Multi-modal Cue Integration:** Combines eye region, head orientation, gestures, and scene context. *Why needed:* No single cue is sufficient in challenging conditions (occlusions, extreme poses). *Quick check:* Ablate each cue by masking inputs; measure performance drop.
- **Heatmap Regression:** Predicts a continuous distribution over image locations. *Why needed:* Gaze target is a spatial probability, not a discrete label. *Quick check:* Visualize predicted heatmaps against Gaussians; check for misalignment or excessive diffusion.
- **Pre-training and Fine-tuning:** Leverages large-scale source data (GazeFollow) then adapts to target domains. *Why needed:* Targets for gaze are scarce; pre-training builds a strong prior. *Quick check:* Compare pre-trained model performance on target test set before and after fine-tuning.

## Architecture Onboarding
**Component map:**  
Input image + head bbox -> DINOv2 ViT-L (frozen) -> [Transformer Block (Self-Attn + MoE FFN)] x3 -> Heatmap Head (1x1 conv) & Classification Head (linear)

**Critical path:**  
1. Encode image and head bbox prompts using DINOv2.  
2. Process tokens through three transformer decoder blocks with MoE in FFN layers.  
3. Generate 64×64 heatmap and in/out-frame logits.

**Design tradeoffs:**  
- *Frozen backbone vs. adaptation:* Freezing DINOv2 ensures stability and leverages generic robust features but may limit domain-specific tuning.  
- *MoE complexity vs. efficiency:* Routing adds computational overhead but allows expert specialization.  
- *Loss weighting (λ):* Balances heatmap and classification; dataset-specific tuning required.

**Failure signatures:**  
- *Expert collapse:* One routed expert dominates (gating entropy < 0.5 bits), indicating poor specialization.  
- *Heatmap mislocalization:* High Mean L2 despite decent AUC, often due to Gaussian σ mismatch or weak supervision.  
- *Poor in/out classification:* Low AP, especially on out-of-frame class, suggesting focal loss α/γ misconfiguration.

**First three experiments:**  
1. Implement the MoE decoder exactly: 1 shared MLP + 4 routed MLPs (hidden dim 256), top-2 routing via softmax on linear projection.  
2. Pre-train on GazeFollow for 15 epochs (batch 60, lr 1e-3) and validate on VideoAttentionTarget; expect AUC ~0.93 before fine-tuning.  
3. Fine-tune on VideoAttentionTarget (λ=1, 10 epochs, encoder lr 1e-5) and ChildPlay (λ=0.1, 3 epochs), then compute AUC, Mean L2, and AP; compare to paper.

## Open Questions the Paper Calls Out
- **Temporal and contextual integration:** How can temporal dynamics and long-range context be incorporated to handle extreme head poses and occlusions? The current frame-based model lacks explicit temporal modeling.
- **Expert specialization interpretation:** Which visual cues (eyes, head pose, gestures, context) are routed to which experts, and how does routing change with input conditions? The adaptive mechanism is not analyzed.
- **Backbone gaze-specificity:** Does the frozen DINOv2 backbone inherently encode gaze-relevant features (e.g., eye regions), and would fine-tuning benefit specialized domains like child or 360° imaging? This trade-off is unexplored.

## Limitations
- **Hyperparameter gaps:** Critical details are missing (DINOv2 checkpoint variant, normalization, augmentation ranges, head bbox encoding, Gaussian σ for heatmaps), hindering exact replication.
- **Evaluation ambiguity:** It is unclear whether GazeFollow test results come from pre-training or fine-tuning, and schedules for some datasets are incompletely described.
- **No backbone analysis:** The paper assumes DINOv2's representations are optimal for gaze without probing or comparing frozen vs. fine-tuned variants.

## Confidence
- **SOTA results on VideoAttentionTarget/ChildPlay:** *Medium* – plausible but depend on unreported implementation choices (e.g., augmentation strengths, heatmap σ).
- **Generalization to 360° and zero-shot:** *Low* – strong claims lack supporting ablations; missing details could explain the gains.
- **MoE decoder and focal loss efficacy:** *Medium* – architecture is described, but routing details and loss weighting uncertainties affect reproducibility.
