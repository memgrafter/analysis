# JAG: Joint Attribute Graphs for Filtered Nearest Neighbor Search

## Quick Facts
- **arXiv ID:** 2602.10258
- **Source URL:** https://arxiv.org/abs/2602.10258
- **Reference count:** 32
- **Primary result:** JAG consistently outperforms all filter-agnostic baselines in throughput (QPS) and recall robustness across five datasets and four filter types, achieving up to 10× higher QPS at recall 0.9 compared to the best prior method.

## Executive Summary
Filtered nearest neighbor search struggles to generalize across varying query selectivity and filter types. Existing algorithms excel only in narrow regimes or for specific filters. JAG addresses this by introducing *attribute distance* and *filter distance*—continuous measures that transform binary constraints into navigational guidance. It constructs a unified proximity graph using capped attribute distances over multiple thresholds, jointly optimizing vector and attribute similarity to prevent dead ends and adapt to any selectivity. Evaluated on five datasets with four filter types (Label, Range, Subset, Boolean), JAG surpasses all filter-agnostic baselines in both throughput and recall. On low-selectivity queries (e.g., MSTuring-10M) it achieves perfect recall with QPS > 1000, while competitors plateau below 0.8 recall. On mixed workloads like LAION-25M and YFCC, JAG attains up to 10× higher QPS at recall 0.9 and matches specialized algorithms (e.g., iRangeGraph) despite full generality.

## Method Summary
JAG builds a *joint attribute graph* where neighbor selection is guided by a combination of vector distance and a *capped attribute distance* (distA) over several thresholds. The construction employs *JointRobustPrune* to partition the candidate pool per threshold and control node degree. Two variants are proposed: *Threshold-JAG* uses a list of thresholds; *Weight-JAG* uses a weighted combination of distances (scale factor *h = σ/σ_A*). Query processing first orders candidates by *filter distance* (distF) to focus on promising regions, then traverses the graph using a comparator that blends (capped) distA and vector distance. Key parameters (degree *R*, thresholds/weights, *α* = 1.2) are dataset-specific and listed in Appendix D.5. The implementation uses greedy search and was evaluated on a 32‑thread Google Cloud VM.

## Key Results
- On low‑selectivity MSTuring-10M, JAG achieves perfect recall with QPS > 1000; other methods plateau below 0.8 recall.
- On mixed workloads (LAION-25M, YFCC), JAG delivers up to 10× higher QPS at recall 0.9 versus the best filter‑agnostic baseline.
- Despite full generality, JAG matches specialized algorithms (e.g., iRangeGraph) that are tailored to specific filter types.

## Why This Works (Mechanism)
JAG’s core insight is to treat attribute constraints as a continuous signal rather than a binary filter. By defining *attribute distance* (distA) and *filter distance* (distF), it converts hard constraints into soft guidance for graph construction and query. The use of *capped* distA ensures that no single threshold dominates; multiple thresholds cover a spectrum of selectivities. *JointRobustPrune* explicitly reserves edges per threshold bucket, maintaining connectivity even for highly selective queries. During query, distF prioritizes candidates likely to satisfy the filter, while the joint comparator (capped distA + vector distance) steers traversal toward both attribute and vector similarity, avoiding dead ends that pure vector graphs encounter under filtering. This joint optimization yields robustness across selectivity regimes and filter types.

## Foundational Learning
- **Attribute distance (distA)**  
  *Why needed:* Turns binary attribute constraints into a continuous measure, enabling smooth integration with vector distance.  
  *Quick check:* For equality filters, identical attribute values yield distA = 0; different values produce a positive distance. For range filters, distA should increase as a point moves outside the query range.

- **Filter distance (distF)**  
  *Why needed:* Guides query traversal toward candidates with higher likelihood of satisfying the filter, improving efficiency.  
  *Quick check:* Points inside the query filter have distF = 0 (or low), while points outside yield a larger value; verify with a few sample queries.

- **Capped attribute distance**  
  *Why needed:* Limits the influence of large attribute differences, allowing vector similarity to rescue candidates for low-selectivity queries.  
  *Quick check:* For a given threshold τ, all distA > τ should be treated equally (capped to τ); confirm that capping does not break the graph’s navigational properties.

- **JointRobustPrune**  
  *Why needed:* Distributes graph degree across thresholds to ensure coverage for all selectivity levels without excessive edges.  
  *Quick check:* After pruning, check that each threshold bucket contributes roughly (0.9·deg/|T|) edges and total in-degree per node is close to the target degree.

- **Comparator D_t^A (capped distA + vector distance)**  
  *Why needed:* Prioritizes neighbors with small capped attribute distance first, then vector closeness, balancing both modalities during construction and search.  
  *Quick check:* On a small set, order neighbors by the comparator and verify that attribute similarity dominates within the same cap bucket.

- **Greedy search with two‑phase ordering**  
  *Why needed:* First filters candidates by distF to quickly identify a high‑quality starting point, then explores using the joint comparator to maintain recall.  
  *Quick check:* Compare recall when using distF ordering versus random start; the ordered version should converge faster.

## Architecture Onboarding

**Component map**  
Data → Attribute distance computation → Threshold selection (sample 500 points, compute quantiles) → JointRobustPrune neighbor selection (per threshold) → Graph index.  
Query → Filter evaluation → Filter distance precomputation → Greedy search (first by distF, then by D_t^A) → Results.

**Critical path**  
Accurate distA/distF definitions; robust threshold selection covering the full selectivity range; effective JointRobustPrune to keep node degrees near target; efficient distF evaluation at query time; proper tuning of beam size and comparator weights.

**Design tradeoffs**  
- *Degree R*: Larger R improves recall but increases graph size and search cost.  
- *Number of thresholds |T|*: More thresholds capture finer selectivity variations but raise construction complexity and memory.  
- *Capping level*: Too low may discard useful attribute information; too high may let attribute distance dominate.  
- *Threshold‑JAG vs. Weight‑JAG*: Thresholds are easier to interpret; weights offer finer control but require additional tuning (scale factor *h*).

**Failure signatures**  
- *Recall near 0 on low‑selectivity queries*: likely missing the 0% (strictest) threshold; include a threshold that forces inclusion of all attribute‑compatible points.  
- *Memory or degree blowup*: JointRobustPrune failed to prune sufficiently; check *α* parameter and early exit condition “0.9·deg/|T|”.  
- *High query latency*: distF computation too expensive (especially Boolean), or beam size *l_s* too large; profile distF and reduce candidate set.  
- *Non‑deterministic results*: Ensure fixed random seeds for neighbor sampling and threshold selection.

**Exactly 3 first experiments**  
1. **SIFT1M label filter validation**: Build JAG with degree=96 and thresholds = {10%, 0%}. Compute recall@10 and QPS; compare against a simple Post‑Filtering baseline.  
2. **ARXIV2.7M range filter**: Use thresholds = {100%, 10%}, degree=96. Expect JAG to outperform HNSW+PostFilter.  
3. **MSTuring10M Boolean filter**: thresholds = {100%, 1%, 0%}, degree=128. Confirm perfect recall at QPS > 1000 and compare against iRangeGraph (if available).

## Limitations
- **Threshold/weight selection opaqueness**: The exact quantiles and validation metric used to pick thresholds/weights are not disclosed, hindering exact replication on new datasets.
- **JointRobustPrune implementation ambiguity**: Details of candidate merging, duplicate handling, and dominance checks are missing; small deviations could significantly alter graph topology.
- **Baseline tuning protocol undisclosed**: The paper reports specific configurations for 10 baselines but does not describe the search space or validation procedure, making fair comparisons difficult.

## Confidence
- General approach validity: **High**
- Parameter choices for published results: **Medium**
- Superiority across all selectivity/filter types: **Medium**
- Specialized‑matching generality claim: **Low**
