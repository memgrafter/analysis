# TikZilla: Scaling Text-to-TikZ with High-Quality Data and Reinforcement Learning

## Quick Facts
- **arXiv ID:** 2603.03072
- **Source URL:** https://arxiv.org/abs/2603.03072
- **Reference count:** 40
- **Primary result:** TikZilla (3B/8B) achieves near-perfect compilation (95–98%) and outperforms base models by 1.5–2 points on human evaluation, matching GPT-5 in image alignment.

## Executive Summary
TikZilla addresses the challenge of generating accurate TikZ code from textual descriptions for scientific figures. Prior works suffered from small, noisy datasets and models that produced uncompilable code with spatial errors. The authors build DaTikZ-V4, a dataset of over 2 million high-quality samples using VLM-generated descriptions and LLM-based debugging. A two-stage training pipeline first aligns the model to TikZ syntax via supervised fine-tuning, then optimizes for visual fidelity using reinforcement learning with a domain-specific reward based on an inverse-graphics image encoder. Results show near-perfect compilation rates, significant improvements over base models and GPT-4o, and more concise code generation.

## Method Summary
The core contributions lie in data curation and training methodology. DaTikZ-V4 is constructed by scraping and filtering LaTeX sources, then augmenting each figure with a detailed description generated by Qwen2.5-VL-7B. Uncompilable code is automatically repaired using Qwen-32B debugging. For training, the authors first perform supervised fine-tuning (SFT) on all pairs to establish TikZ syntax proficiency. They then apply reinforcement learning (RL) with Group-Relative Policy Optimization (GRPO), using a frozen image encoder (DeTikZify-V2) to produce a reward that measures semantic similarity between rendered images via Earth Mover’s Distance. This combination exposes the model to visual feedback, improving spatial accuracy and alignment with the intended figure.

## Key Results
- Near-perfect compilation rates of 95–98% on the test set.
- Outperforms base models by 1.5–2 points (5-point scale) and surpasses GPT-4o by 0.5 points; matches GPT-5 in image alignment evaluation.
- Generates significantly more concise code (~480 tokens) compared to prior work (~740 tokens).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: Replacing noisy raw captions with VLM-generated descriptions and repairing uncompilable code via LLM debugging yields a dataset that enables models to learn spatial and structural accuracy, directly addressing low compilation rates and visual misalignment.
- **Mechanism**: VLM descriptions capture detailed spatial relations and component labels, reducing the gap between text and figure. LLM debugging systematically fixes compilation errors by leveraging error logs, increasing the pool of executable training samples.
- **Core assumption**: VLM descriptions are more semantically faithful than raw captions for reconstruction; LLM debugging can reliably produce compilable code without altering figure semantics.
- **Evidence anchors**:
  - [abstract] "VLM-generated descriptions... LLM-based debugging to fix uncompilable code."
  - [section] Section 3 shows human evaluations and automatic metrics proving VLM descriptions outperform captions; Section 4 details debugging pipeline and compilation rate improvements.
  - [corpus] Nearest papers discuss caption quality but do not provide direct evidence for TikZilla's specific VLM/LLM debugging approach—evidence is indirect.
- **Break condition**: If VLM descriptions introduce systematic hallucinations or LLM debugging corrupts figure semantics.

### Mechanism 2
- **Claim**: A two-stage training pipeline (SFT for TikZ syntax alignment, then RL with visual feedback) enables models to move beyond syntactic correctness to semantic fidelity, reducing hallucinations and spatial errors.
- **Mechanism**: SFT teaches the model the distribution of valid TikZ tokens and structures. RL then uses a reward model that evaluates rendered images, pushing the policy toward outputs that match the visual semantics of the target figure, not just the text description.
- **Core assumption**: Exposure to rendered image feedback during RL corrects the SFT model’s blind spot to visual properties.
- **Evidence anchors**:
  - [abstract] "two-stage pipeline of SFT followed by reinforcement learning (RL)... expose the model to the rendered semantics."
  - [section] Section 5 details GRPO objective and ablation showing RL improves compilation and alignment over SFT alone (Table 3, Figure 4).
  - [corpus] "Rendering-Aware Reinforcement Learning for Vector Graphics Generation" uses RL for SVG, but TikZilla adapts this with a domain-specific reward—corpus provides conceptual precedent, not direct evidence.
- **Break condition**: If the reward model fails to discriminate subtle spatial errors or RL destabilizes the policy.

### Mechanism 3
- **Claim**: A reward model based on an inverse-graphics image encoder (trained on Image→TikZ) provides a semantically faithful, domain-specific similarity metric that correlates strongly with human judgments, guiding RL more effectively than generic metrics.
- **Mechanism**: The encoder is trained to reconstruct TikZ from images, learning representations that capture diagrammatic structure. During RL, patch embeddings from predicted/ground-truth images are compared via Earth Mover’s Distance, producing a scalar reward reflecting semantic similarity.
- **Core assumption**: An encoder trained on TikZ reconstruction encodes features relevant to scientific figure fidelity better than off-the-shelf vision models.
- **Evidence anchors**:
  - [abstract] "reward model derived from an inverse-graphics image encoder that measures semantic similarity."
  - [section] Section 5 describes training DeTikZify-V2 on DaTikZ-V4 and using EMD; Table 5 shows it outperforms CLIP/DreamSIM; correlation analysis (ρ = 0.714) validates alignment with human scores.
  - [corpus] Nearest papers use inverse graphics for zero-shot generation, but TikZilla’s reward model is a novel adaptation—corpus shows feasibility, not exact instantiation.
- **Break condition**: If the encoder overfits to TikZ patterns seen during training or fails on out-of-distribution figure types.

## Foundational Learning
- **Concept: Supervised Fine-Tuning (SFT) for Structured Output**
  - Why needed here: SFT grounds the LLM in TikZ’s precise syntax and token distribution, which is essential before RL can optimize for higher-order properties.
  - Quick check: What would happen if RL were applied without SFT? Expected: high reward noise due to syntax errors, poor convergence.
- **Concept: Reinforcement Learning with Group-Relative Policy Optimization (GRPO)**
  - Why needed here: GRPO optimizes for a non-differentiable reward (image similarity) while stabilizing training via group-centered advantages and KL regularization.
  - Quick check: Why use token-level normalization (Dr.GRPO) instead of response-level? Expected: prevents bias toward longer TikZ sequences.
- **Concept: Inverse Graphics and Metric Learning**
  - Why needed here: The reward model requires an encoder that understands TikZ structure; training on Image→TikZ forces representation learning of diagram semantics.
  - Quick check: Why use Earth Mover’s Distance (EMD) instead of cosine similarity on pooled embeddings? Expected: EMD handles patch-level alignment more robustly for structured images.

## Architecture Onboarding
- **Component map**
  Data pipeline: Source (arXiv/GitHub/TeX SE) → Filtering (subfigure split, package detection) → Compilation → LLM debugging → VLM description.
  Training: SFT on (description, TikZ) pairs → Freeze image encoder (from DeTikZify-V2) → RL (GRPO) with reward = RSim + format bonus.
  Evaluation: Automatic (CLIP, DreamSIM, TED, CR) + Human (text/image alignment).

- **Critical path**: Data curation (DaTikZ-V4) → SFT model → Reward encoder training → RL fine-tuning → Evaluation. The reward encoder must be pretrained before RL.

- **Design tradeoffs**
  - Dataset scale vs. quality: VLM descriptions are costly; LLM debugging adds latency but boosts compilation.
  - Reward specificity: Domain-specific encoder (strong correlation) vs. generic metrics (cheaper but weaker).
  - Model size: Smaller models (3B) benefit more from SFT+RL; larger (8B) may need less SFT.

- **Failure signatures**
  - Low CR (<80%): Inadequate debugging or SFT underfitting.
  - High TED but decent CR: Code is compilable but semantically wrong (reward model failure).
  - Long outputs (>600 tokens): RL not suppressing verbosity; check reward bonus design.

- **First 3 experiments**
  1. Ablate VLM descriptions: Train SFT on caption-only vs. VLM-only subsets; measure CR and human alignment.
  2. Reward model swap: Replace RSim with CLIPScore/DreamSIM in RL; compare correlation with human scores.
  3. Data scaling curve: Train SFT on 25%, 50%, 75%, 100% of DaTikZ-V4; plot performance vs. data size.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: To what extent do current reward models and evaluations distinguish between satisfying textual descriptions versus matching ground-truth images, and how can these two objectives be disentangled?
- Basis in paper: [explicit] The authors note that models often score higher on textual alignment than on image alignment, and that disentangling whether this stems from imperfect VLM descriptions or stricter human judgment for image matching "remains an open question, which we leave for future work." (Page 8)
- Why unresolved: The paper lacks controlled experiments that separate the influence of description quality from the inherent difficulty of visual reconstruction.
- What evidence would resolve it: Human evaluation using gold-standard descriptions, or metrics that independently measure textual fidelity and visual similarity, combined with error analysis.

### Open Question 2
- Question: How can automatic metrics be designed to have stronger alignment with human perception of scientific figure quality?
- Basis in paper: [explicit] The conclusion states that future work should focus on "designing automatic metrics with stronger alignment to human perception."
- Why unresolved: Existing metrics (CLIPScore, DreamSIM) show only moderate correlation with human judgments; the proposed domain-specific reward (RSim) improves correlation but still leaves room for improvement.
- What evidence would resolve it: New metrics validated across diverse scientific figure types with large-scale human evaluations, potentially incorporating fine-grained spatial and structural analysis.

### Open Question 3
- Question: Can the two-stage training pipeline (SFT + RL with domain-specific reward) be effectively transferred to other structured generation domains like LaTeX tables, CAD, or flowcharts?
- Basis in paper: [explicit] The conclusion identifies "extending our approach to other structured generation tasks (e.g., LaTeX tables, CAD, or flowcharts)" as a crucial direction.
- Why unresolved: TikZ has unique characteristics (vector graphics, coordinate systems); other domains may require different reward models, datasets, or adaptations of the RL framework.
- What evidence would resolve it: Reimplementation of the pipeline in new domains, construction of corresponding high-quality datasets and inverse-graphics based reward models, and systematic comparison of performance gains.

### Open Question 4
- Question: What alternative annotation methods can replace VLM-generated descriptions to reduce hallucination and omission, and how can reward functions be made more fine-grained to capture specific aspects of figure quality (e.g., spatial accuracy, label correctness)?
- Basis in paper: [explicit] The conclusion identifies "more reliable annotation methods and fine-grained reward functions" as crucial future directions.
- Why unresolved: VLM descriptions may contain errors that bias training; the current reward model provides a single scalar that does not differentiate between types of mistakes (e.g., spatial misalignment vs. missing objects).
- What evidence would resolve it: Human-in-the-loop annotation pipelines, multi-component reward models with separate terms for layout, semantics, and style, or hierarchical evaluation frameworks.

### Open Question 5
- Question: How does explicit optimization for code efficiency (e.g., token length, computational complexity) compare to the implicit efficiency gains observed from semantic reward models?
- Basis in paper: [explicit] The authors note that RL naturally reduced token length without explicit efficiency rewards and state that "a deeper comparison with explicit efficiency rewards is left for future work." (Page 9)
- Why unresolved: It is unclear whether the observed conciseness is optimal or whether introducing explicit efficiency terms would yield further improvements or undesirable trade-offs (e.g., sacrificing readability for brevity).
- What evidence would resolve it: Ablation studies adding explicit efficiency rewards (e.g., length penalties, complexity metrics) and measuring their impact on semantic accuracy, compilation rate, and human preferences.

## Limitations
- Implementation details missing for Dr.GRPO advantage calculation and EMD solver.
- Generalization to unseen figure types (e.g., SPIQA) not fully established.
- Potential reward hacking (e.g., high CLIP but low human scores) and unquantified computational expense of RL stage.
