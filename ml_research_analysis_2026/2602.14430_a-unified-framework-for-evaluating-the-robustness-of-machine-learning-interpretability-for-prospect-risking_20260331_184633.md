# A unified framework for evaluating the robustness of machine-learning interpretability for prospect risking

## Quick Facts
- arXiv ID: 2602.14430
- Source URL: https://arxiv.org/abs/2602.14430
- Reference count: 18
- Primary result: A unified framework using forward counterfactual perturbations to compute necessity and sufficiency scores; applied to DHI dataset shows SHAP aligns robustly with sufficiency across models, while LIME's necessity alignment is model-dependent.

## Executive Summary
The paper addresses the problem of conflicting explanations from XAI methods (LIME, SHAP) in hydrocarbon prospect risking. It proposes a framework that evaluates the robustness of XAI-generated feature rankings by comparing them with global necessity and sufficiency scores derived from forward counterfactual perturbations. The method is tested on a proprietary DHI dataset with 35 features and 101 test instances across four classifiers. Results indicate that SHAP rankings consistently decrease in sufficiency score with lower ranks (robust), while LIME's necessity alignment holds only for Random Forest; for other models, higher-ranked features are not necessarily more necessary. Global scores partially match domain knowledge, allowing identification of trustworthy XAI-model pairs for geophysical decision-making.

## Method Summary
The framework quantifies robustness by computing necessity (how often changing a feature flips the prediction) and sufficiency (how often setting a feature to a reference value yields a desired outcome) via forward perturbations on the test set. For each instance, LIME or SHAP provides a feature ranking. Local necessity/sufficiency scores are aggregated globally per feature, and the alignment between XAI rankings and these global scores is evaluated (higher rank should correspond to higher score). This approach avoids costly counterfactual generation, is model-agnostic, and scales with the number of features. The pipeline includes training a classifier, generating XAI explanations, perturbing features to compute local scores, aggregating globally, and checking monotonic alignment. Default hyperparameters include 10 perturbations per instance and use of all test instances as references for sufficiency.

## Key Results
- SHAP rankings consistently aligned with decreasing sufficiency scores for all four models, indicating robust sufficiency.
- LIME rankings were robust only for Random Forest; for Gaussian NB and Voting Classifier, the second-ranked feature had a higher average necessity score than the first.
- Global necessity and sufficiency scores partially matched domain knowledge (e.g., DHI index generally high), enabling identification of reliable XAI-model pairs (e.g., SHAP with any model, LIME only with Random Forest).

## Why This Works (Mechanism)
### Mechanism 1
- Claim: XAI feature attributions can be evaluated for robustness by checking whether features ranked as more important also have higher causal necessity and sufficiency scores, computed via forward counterfactual perturbations.
- Mechanism: Generate pseudo-counterfactuals by directly perturbing a single feature on existing test instances. For necessity, measure how often changing that feature flips the model’s prediction from the original outcome. For sufficiency, measure how often setting a reference feature value on instances with an undesired outcome yields the desired outcome. Aggregate globally and compare against XAI ranking.
- Core assumption: Direct perturbations on observed instances approximate causal interventions; the fraction of output changes reflects the causal contribution of the feature under the model. Assumes feature independence during intervention.
- Evidence anchors: [abstract] and [PAGE 4] quotes about grounding ranked features using necessity/sufficiency; neighboring work motivates robustness need.
- Break condition: If model is insensitive to perturbations, scores become uniformly low; strong feature correlations violate independence; out-of-distribution perturbations produce unreliable predictions.

### Mechanism 2
- Claim: Necessity and sufficiency can be computed efficiently without generating explicit counterfactual instances or requiring a causal graph.
- Mechanism: Instead of optimizing for a valid counterfactual, directly perturb a chosen feature on a selected set of existing instances. For necessity: perturb on the same instance; for sufficiency: apply reference value to a set of negative instances. Scores are simple fractions of output changes (Eqs. 4–5). Avoids combinatorial search and scales with the number of features.
- Core assumption: A limited set of perturbations on observed data points estimates the conditional probabilities; varied feature values in test set provide coverage. Perturbed values need not be strictly plausible but should remain reasonable.
- Evidence anchors: [PAGE 5] about model-agnostic, post-hoc scoring; Equations (4) and (5).
- Break condition: Too few perturbations yield noisy estimates; too large perturbations cause extrapolation; sparse feature space regions give unrepresentative fractions.

### Mechanism 3
- Claim: The robustness of an XAI method is quantified by the monotonic alignment between the XAI’s feature ranking and the global necessity/sufficiency rankings; non-monotonic alignment indicates non-robust explanation.
- Mechanism: For each test instance, collect features in the order they appear in the XAI explanation (top‑k). For each rank (1, 2, …), compute the average global necessity/sufficiency score of features occupying that rank across many instances. If explanation is robust, the score should decrease as rank increases. Deviations signal unreliability.
- Core assumption: A good explanation should nominate features that are truly causal; thus importance ranking should correlate with causal strength. Global aggregation smooths instance‑level noise.
- Evidence anchors: [PAGE 6] hypothesis; Figures A‑8 to A‑11; [PAGE 7] about selecting robust explanation method.
- Break condition: XAI attributions highly inconsistent across instances; the hypothesis may not hold universally; some XAI methods may capture non‑causal predictive features.

## Foundational Learning
**Concept: Necessity & Sufficiency (Causal Inference)**
- Why needed: They provide theoretical criteria to judge whether a feature’s attributed importance reflects a genuine causal role in the model’s decision.
- Quick check: For a fixed model and instance, if altering feature X always changes the prediction, is X necessary, sufficient, both, or neither? Use paper’s definitions (Eqs. 1‑2) to justify.

**Concept: Counterfactual Explanations (Forward Perturbation)**
- Why needed: Core scoring relies on simulating ‘what‑if’ changes by perturbing features directly, avoiding computational burden of generating valid counterfactuals via optimization.
- Quick check: How does the paper’s ‘forward counterfactual’ differ from the ‘valid counterfactuals’ required by DICE? Why is the forward approach more scalable to high‑dimensional tabular data?

**Concept: Local vs. Global Explanation Aggregation**
- Why needed: XAI methods like LIME and SHAP produce instance‑level attributions; the framework aggregates these to global scores to evaluate robustness systematically.
- Quick check: Why can we not judge an XAI method’s robustness by looking at a single instance? What does averaging local necessity/sufficiency over many instances achieve?

## Architecture Onboarding
**Component map (pipeline):**
Trained binary classifier -> Test dataset -> XAI wrapper (LIME/SHAP) -> Perturbation engine (for each top-ranked feature) -> Scoring module (compute local necessity/sufficiency) -> Global aggregator (average per feature) -> Robustness evaluator (rank alignment analysis).

**Critical path:**
a. Train model on training split.
b. For each test instance, obtain XAI feature ranking.
c. For each top‑ranked feature:  
   - Necessity: generate n perturbations of that feature on that instance, count output flips.  
   - Sufficiency: choose a reference instance; collect a set K of negative instances; intervene the reference feature value, count flips to positive.
d. Aggregate fractions over instances to produce global necessity/sufficiency per feature.
e. For each model‑XAI pair, compute rank‑wise average scores; plot and compare to the monotonicity hypothesis.

**Design tradeoffs:**
- Forward vs. optimization‑based counterfactuals: Forward sacrifices strict plausibility for speed and scalability; DICE guarantees validity but is computationally heavy.
- Feature independence assumption: Isolated intervention may be unrealistic if features are correlated, leading to misleading scores.
- Aggregation strategy: Global score = mean of local scores; alternatives (median, trimmed mean) could reduce outlier influence but were not explored.
- XAI‑agnostic vs. hypothesis specificity: Framework accepts any attribution method, but monotonicity hypothesis may not hold for all (e.g., methods capturing interactions).

**Failure signatures:**
- Uniform scores (all near 0 or 1) making ranking meaningless.
- High variance in local scores across instances causing unstable global rankings.
- Domain mismatch: global necessity/sufficiency ordering contradicts known geophysical knowledge.
- LIME‑specific anomaly: Necessity scores increasing with rank (e.g., rank‑2 > rank‑1) for certain models (Gaussian NB, Voting Classifier).

**First 3 experiments:**
1. Global feature validation: Compute global necessity/sufficiency for the 7 high‑level DHI features using full‑feature models. Verify that top domain‑known indicators receive high scores (Figures A‑6, A‑7).
2. LIME robustness analysis: For each classifier, run LIME on the 101 test cases. For ranks 1‑5, average the global necessity scores of features at that rank. Plot as in Figure A‑8. Identify models where trend is non‑monotonic.
3. SHAP robustness analysis: Repeat experiment 2 for SHAP (Figures A‑9, A‑10, A‑11). Compare which XAI‑model pairs maintain monotonic decrease and note SHAP generally shows robust sufficiency across models.

## Open Questions the Paper Calls Out
1. Are the features ranked as most important by LIME or SHAP always the most necessary for the model's prediction?  
   Basis: The authors test if the #1 ranked feature has the highest average necessity score. Results show for Gaussian NB and Voting Classifier, the #2 feature had higher necessity.  
   Why unresolved: Inconsistency indicates LIME/SHAP may not always align with causal necessity, but the paper does not explain why for specific models or interactions.

2. Are the features ranked as most important by LIME or SHAP always the most sufficient for generating the model's output?  
   Basis: Test if top-ranked features have decreasing sufficiency scores. SHAP aligned consistently; LIME did not universally.  
   Why unresolved: SHAP shows robust sufficiency but LIME does not; the paper does not investigate whether this stems from SHAP's Shapley values or LIME's local linear approximation.

3. Does the necessity‑sufficiency framework reliably identify trustworthy XAI‑model pairs for geophysical decisions across diverse datasets?  
   Basis: The framework identifies reliable pairs based on robustness tests, but conclusion is from a single proprietary DHI dataset (N=101).  
   Why unresolved: Generalizability is unclear; dataset‑specific feature structure, class balance, and domain semantics may limit applicability to other geophysical tasks.

4. How do feature correlations and high‑dimensional sparsity affect the validity of necessity and sufficiency scores computed via forward perturbations?  
   Basis: Methodology assumes feature independence to avoid requiring a causal model; acknowledges high‑dimensional challenges.  
   Why unresolved: Perturbing one feature while holding others constant may produce implausible counterfactuals if features are correlated, potentially inflating/deflating scores.

5. Why do global necessity and sufficiency scores only partially match domain knowledge, and what do mismatches reveal about model or XAI limitations?  
   Basis: Authors state scores partially matched domain knowledge (e.g., DHI attributes) but do not analyze mismatches.  
   Why unresolved: Mismatches could indicate overfitting, XAI flaws, or incomplete expert knowledge. Without studying specific mismatched features, the framework's diagnostic power remains limited.

## Limitations
- Proprietary DHI dataset and small test set (N=101) limit reproducibility and external validity.
- Critical hyperparameters for LIME/SHAP and perturbation design (number, scale, categorical handling) are not fully specified.
- Feature independence assumption likely violated in correlated geophysical features, potentially biasing necessity/sufficiency estimates.

## Confidence
- Core evaluation method (necessity/sufficiency via forward perturbations): Medium
- Efficiency of scoring: High
- Monotonic alignment as robustness indicator: Medium

## Next Checks
1. Public dataset replication: Apply the framework to three public datasets (Adult, COMPAS, German Credit). Test monotonicity across model-XAI pairs; compare robust explanations with known feature importance where available.
2. Perturbation sensitivity analysis: For one dataset, vary number of perturbations per instance (n = 5, 10, 20, 50) and magnitude of numeric noise (σ = 0.05, 0.1, 0.2 × feature std). Compute global necessity/sufficiency ranks for each setting; measure stability via Spearman correlations.
3. Correlation robustness test: Add a highly correlated duplicate of a top‑ranked feature (e.g., add small Gaussian noise). Check if original and duplicate receive similar necessity/sufficiency scores. Divergence indicates sensitivity to the independence assumption.
