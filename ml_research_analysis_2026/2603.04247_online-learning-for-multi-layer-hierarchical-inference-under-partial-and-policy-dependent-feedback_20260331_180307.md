# Online Learning for Multi-Layer Hierarchical Inference under Partial and Policy-Dependent Feedback

## Quick Facts
- arXiv ID: 2603.04247
- Source URL: https://arxiv.org/abs/2603.04247
- Reference count: 40
- Primary result: VR-Ly-EXP4 reduces inference error (0.292–0.317) and increases hard-task hit rate (0.443–0.446) compared to baselines in hierarchical inference with partial feedback.

## Executive Summary
The paper tackles online routing in multi-layer hierarchical inference systems where feedback (inference error) is only available at the terminal oracle layer, leading to partial and policy-dependent observations. Naive importance-weighted contextual bandit methods suffer from instability due to exponentially decaying feedback probabilities across layers. The proposed VR-Ly-EXP4 algorithm combines Lyapunov optimization for long-term resource constraints with a variance-reduced variant of EXP4. Its core is a task-conditioned variance-reduced loss estimator that subtracts a historical baseline to reduce variance while remaining unbiased. Theoretical analysis shows sublinear regret and near-optimality under stochastic arrivals. Empirical evaluation on large-scale language and vision workloads across 3–5 layer hierarchies demonstrates reduced inference error and improved hard-task hit rates, confirming stable learning under sparse feedback.

## Method Summary
VR-Ly-EXP4 is an online algorithm for hierarchical inference routing under resource constraints. It employs Lyapunov optimization to transform long-term average resource limits into per-slot queue-stabilization objectives using virtual queues. For routing decisions at each node, it uses a contextual bandit approach (EXP4) over a set of expert policies defined by confidence thresholds and offload destinations. The key innovation is a variance-reduced loss estimator that estimates the conditional expected loss for an expert by subtracting a task-conditioned baseline learned from historical terminal feedback. This reduces the variance that would otherwise explode due to the decaying probability of receiving feedback. Additionally, a periodic greedy model placement algorithm manages memory constraints by selecting models to load at each node based on empirical utility estimates. The integration of these components yields a system that learns effective routing while respecting resource limits.

## Key Results
- VR-Ly-EXP4 achieves lower inference error (0.292–0.317) compared to Ly-EXP4 (0.322–0.343) and other baselines.
- It increases hard-task hit rate (0.443–0.446 vs 0.395–0.407), successfully routing difficult tasks to the oracle.
- The algorithm guarantees sublinear regret and near-optimal performance under stochastic job arrivals and bounded costs.

## Why This Works (Mechanism)

### Mechanism 1: Variance-Reduced Loss Estimation
- **Claim:** The task-conditioned variance-reduced estimator reduces amplified variance from depth-decaying feedback probabilities while remaining unbiased.
- **Mechanism:** For a job `j` at node `n` routed to `n'`, the estimator is `ˆF = 1_fb * (f - baseline)/ρ + baseline`. The baseline `¯f_n',n,y(πh)` estimates the conditional expected loss for task type `y` under expert `πh`, learned from historical observations. The term `(f - baseline)/ρ` is unbiased (since `E[1_fb]=ρ`) and has smaller variance than the naive `1_fb*f/ρ` when `baseline ≈ f`.
- **Core assumption:** The baseline is a reasonably accurate estimator of the conditional loss (`0 < baseline ≤ 2f` per Lemma 4.2) and is updated only when feedback is observed (`1_fb=1`), making it an unbiased EMA of `f/ρ`.
- **Break condition:** If the baseline is poorly initialized or the condition `0 < baseline ≤ 2f` is violated frequently, variance reduction fails. Also, if `ρ` becomes too small (deep hierarchies with aggressive local termination), numerical instability can occur.

### Mechanism 2: Lyapunov Drift‑Plus‑Penalty for Resource Constraints
- **Claim:** Virtual queues transform long-term average resource constraints into per-slot queue‑stabilization objectives, enabling online learning under capacity limits.
- **Mechanism:** For each node `n`, a virtual queue `Q_n(t)` evolves as `Q_n(t+1) = max[Q_n(t) + C_n(t) - γ_nτ, 0]`. The per-slot objective (Eq. 6) minimizes `∑ q_n(t) E[C_n] + v E[loss]`. If queues are mean‑rate stable (`E[Q_n(T)]/T→0`), constraints are satisfied (Prop 4.1). This couples resource penalty (`q_n*C_n`) with inference loss.
- **Core assumption:** Slater’s condition holds (strictly feasible resource allocations exist) and per-slot costs are bounded (Assumption 3.1).
- **Break condition:** If resource costs `C_n(t)` are unbounded or arrivals are bursty violating the bounded second moment, the drift bound may not hold, leading to queue instability and constraint violation.

### Mechanism 3: Hierarchical Contextual Bandit with Expert Thresholds
- **Claim:** Decentralized routing is learned via EXP4 over threshold‑destination expert pairs, where each node’s policy indirectly influences upstream observability probabilities `ρπ_n(j)`.
- **Mechanism:** At node `n` for task type `y`, each expert `e=(h, n')` specifies a confidence threshold `θ_h` and an offload destination `n'`. The action distribution mixes exploration (`λ`) with the EXP4 weight‑based probabilities. The loss update uses the variance‑reduced estimator. Crucially, `ρπ_n(j)` is computed recursively backward from the cloud, capturing policy‑dependent feedback decay.
- **Core assumption:** The expert space `E_n(y)` is rich enough to approximate the optimal routing policy (small discretization error `ε0`) and the learning rate `η` is properly tuned.
- **Break condition:** If the threshold grid `θ_h` is too coarse or task types are not well separated, the best fixed expert may be poor. Miscomputation of `ρπ_n(j)` due to policy non‑stationarity during learning can introduce bias.

## Foundational Learning

**Concept: Contextual Bandits (EXP4)**
- Why needed here: The routing decision at each node observes context (task type, confidence) and chooses among many actions (terminate or offload). Only the loss of the chosen action (or terminal loss) is observed, fitting the bandit framework.
- Quick check question: How does importance weighting in standard EXP4 become problematic when the feedback probability `ρ` decays exponentially with hierarchy depth?

**Concept: Lyapunov Optimization for Constrained Control**
- Why needed here: Long-term resource constraints (Eq. 3) must be satisfied despite stochastic arrivals and routing decisions. Lyapunov’s method converts these to queue stability problems.
- Quick check question: Why does mean‑rate stability of the virtual queue `Q_n(t)` imply the long‑term average resource consumption constraint holds?

**Concept: Variance Reduction via Baselines**
- Why needed here: The naive importance‑weighted estimator `1_fb * f / ρ` has variance scaling as `~ 1/ρ` because `ρ` decays with depth. Subtracting a good baseline `¯f` reduces variance while keeping expectation unchanged.
- Quick check question: What property must the baseline `¯f_n',n,y(πh)` satisfy to ensure the variance‑reduced estimator’s variance does not exceed that of the naive estimator (Lemma 4.2)?

## Architecture Onboarding

**Component map**
Per-node routing agent (maintains expert weights, samples actions, updates weights) interacts with Baseline manager (stores task-conditioned baselines), Virtual queue monitor (tracks resource queues), Recursive loss calculator (computes marginal feedback probabilities and expected upstream losses), and Model placement scheduler (periodic greedy knapsack for model selection under memory limits). These components operate per node, with the recursive calculator coordinating across layers when terminal feedback arrives.

**Critical path**
1. Job arrives → node computes confidence `z_n(j)` → forms action probabilities `p_j(a)` using current expert weights.
2. Action sampled → if offload, job proceeds upstream; if terminate, record loss `b(j,x_n)`.
3. When/if job reaches oracle, `1_fb=1` for all nodes on path → compute `ρπ_n(j)` backward from oracle (requires known probabilities on path) → compute `f_n'(j,π_h)` for all experts → compute `ˆF_vr` → update baseline `¯f` → update expert cumulative loss `ˆg`.
4. Update virtual queues `Q_n(t+1)` based on offloading cost.
5. Every `D` slots, run greedy model placement using recent empirical utility estimates.

**Design tradeoffs**
- Exploration rate `λ`: Higher `λ` improves stability by keeping `ρ` from vanishing but slows convergence.
- Learning rate `η`: Controls EXP4 step size; too large causes instability, too small slows learning.
- Lyapunov control parameter `v`: Larger `v` enforces resource constraints more strictly but may sacrifice accuracy.
- Placement period `D`: Smaller `D` adapts faster to workload shifts but increases switching cost `ν` and may cause thrashing.

**Failure signatures**
- High variance in loss estimates: erratic expert weight updates; check if `ρπ_n(j)` extremely small or baseline poorly initialized.
- Queue instability: `Q_n(t)` grows unbounded, indicating resource constraint violation; adjust `v` or cost estimates.
- Poor hard-task hit rate: system never routes difficult jobs to oracle; may need to adjust confidence thresholds or improve baseline learning for rare task types.
- Model placement thrashing: frequent model swaps; reduce `D` or increase utility buffer size.

**First 3 experiments**
1. **Depth scalability test:** Run on 3‑, 4‑, 5‑layer hierarchies (Table 1). Expect feedback rate decay for baselines; VR‑Ly‑EXP4 should maintain stable learning and higher hit rate (~0.44 vs ~0.40).
2. **Variance ablation:** Compare VR‑Ly‑EXP4 vs VR‑Ly‑EXP4‑LocalLoss (no recursive `¯f_n'`). Expect higher error for LocalLoss (paper: 0.3103 vs 0.2923 in 5‑layer), confirming upstream loss modeling necessity.
3. **Baseline sanity check:** Track `¯f_n',n,y(πh)` over time for convergence smoothness and monitor expert weight entropy. Stable baselines and rapid entropy decay indicate effective learning.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** How does VR‑Ly‑EXP4 degrade as hierarchy depth increases beyond 5 layers, where `ρπ_n(j)` decays exponentially?
- **Basis in paper:** Experiments up to 5 layers show feedback rate drops. The estimator’s denominator `ρ` may become extremely small, inflating variance even with reduction.
- **Why unresolved:** No experiments beyond 5 layers; theoretical bound does not explicitly characterize depth dependence.
- **What evidence would resolve it:** Simulate deeper hierarchies (K=10,15) and measure feedback rates, estimator variance, and error. Derive tighter bounds incorporating depth.

### Open Question 2
- **Question:** Under non‑stationary task distributions, can the variance‑reduced estimator remain stable without manual tuning of `η_b` or `λ`?
- **Basis in paper:** Baseline update uses fixed EMA; analysis assumes stationary arrivals (Assumption 3.1). Real workloads shift, but no adaptive mechanism is provided.
- **Why unresolved:** Baseline may lag if distribution changes, especially with sparse feedback. Algorithm lacks change detection or adaptation.
- **What evidence would resolve it:** Test with synthetic non‑stationary workloads (abrupt changes in task frequencies) and compare fixed vs adaptive `η_b`/`λ`.

### Open Question 3
- **Question:** Does jointly optimizing model placement and routing policies improve over the decoupled approach (periodic greedy placement)?
- **Basis in paper:** Model placement is treated as a separate periodic greedy knapsack problem; routing assumes fixed placement between updates. Potential coupling is ignored.
- **Why unresolved:** No analysis or experiments on integrated optimization; placement affects routing options and error.
- **What evidence would resolve it:** Implement a joint optimization (e.g., multi-timescale learning or bilevel) and benchmark against decoupled method on error, resource use, and adaptation speed.

## Limitations
- Theoretical guarantees rely on assumptions (bounded costs, Slater’s condition, baseline accuracy) that may not hold in practice.
- Key experimental parameters (entry node assignment, confidence variance, expert grid size, learning rate schedules, offloading cost formula) are not fully disclosed, hindering exact reproduction.
- Evaluation is limited to two fixed benchmarks; generalisation to other datasets, deeper hierarchies (>5), or higher arrival loads is unclear.
- Numerical stability of the variance‑reduced estimator when `ρ→0` is not analysed; underflow could occur.
- Reported hard‑task hit rate improvements are modest and lack statistical significance testing.

## Confidence
- Sublinear regret & near‑optimality: Medium (proofs exist but assumptions not empirically verified)
- Variance reduction: High (Lemma 4.2 and ablation study confirmed)
- Empirical superiority: Medium (results presented but reproducibility details and confidence intervals absent)
