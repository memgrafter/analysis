# TS-Haystack: A Multi-Scale Retrieval Benchmark for Time Series Language Models

## Quick Facts
- **arXiv ID**: 2602.14200
- **Source URL**: https://arxiv.org/abs/2602.14200
- **Reference count**: 40
- **Primary result**: Latent-resampling TSLMs (OpenTSLM-Flamingo) improve classification at high compression (up to 176×) but suffer retrieval degradation as context grows, while an oracle variant confirms the time series encoder is the bottleneck.

## Executive Summary
This paper introduces TS-Haystack, a needle-in-a-haystack benchmark for evaluating long-context retrieval in Time Series Language Models (TSLMs). The benchmark embeds short activity bouts into up to 2-hour accelerometer recordings across ten retrieval tasks. Evaluation reveals a critical trade-off: latent resampling architectures (OpenTSLM-Flamingo) maintain or improve classification accuracy as context length increases (compression up to 176×), but retrieval performance degrades sharply—from 29.6% at short contexts to 23.2% at 15 minutes. A full-attention baseline (ITFormer) performs below random. An oracle variant, which bypasses the time series encoder by providing ground-truth activity timelines as text, achieves stable high retrieval (82.2%–91.3%) across all context lengths. This points to the time series encoder as the primary bottleneck for long-context retrieval, not the LLM's reasoning capacity.

## Method Summary
The study uses the Capture24 dataset (triaxial wrist accelerometer, 151 participants) to generate TS-Haystack samples. Short activity needles (1–6 seconds) are blended into longer background haystacks (2.56 seconds to 2 hours) via mean alignment and cosine smoothing. For classification, windows are labeled by majority vote. Two model architectures are compared: OpenTSLM-Flamingo (latent resampling with 64 queries, Llama-3.2-1B backbone) and ITFormer (full-attention, Qwen2.5-1.5B-Instruct backbone). OpenTSLM-Flamingo is trained jointly on all context lengths with AdamW (LR=5×10⁻⁵); ITFormer uses prefix-tuning with a frozen LLM. An oracle variant prepends ground-truth activity timelines to the prompt. Evaluation metrics include Macro-F1 for classification and per-task accuracy for retrieval.

## Key Results
- OpenTSLM-Flamingo improves classification Macro-F1 from 32.9% to 41.4% as context grows (compression up to 176×), but retrieval accuracy degrades from 29.6% to 23.2% by 15 minutes.
- Oracle variant maintains stable high retrieval (82.2%–91.3%) across all context lengths, isolating the time series encoder as the bottleneck.
- ITFormer performs below random on retrieval even at short contexts, indicating that preserving resolution alone is insufficient.

## Why This Works (Mechanism)

### Mechanism 1: Compression Trade-off
**Claim**: Latent resampling (e.g., OpenTSLM-Flamingo) maintains classification accuracy at high compression but degrades retrieval because each fixed latent token must summarize increasing temporal information without query-specific guidance.
- **Mechanism**: A fixed set of learned queries (M=64) cross-attends to all patch embeddings (N), reducing sequence length from N to M. As context grows, N/M increases (up to 176×), forcing each latent token to cover more time and lose fine-grained patterns needed for precise localization.
- **Evidence**: Retrieval drops from 29.6% (2.56s) to 23.2% (15min); classification improves. Oracle's high retrieval confirms LLM reasoning capacity is sufficient.
- **Break condition**: If retrieval remained stable with increasing N/M while classification improved, the mechanism would be falsified.

### Mechanism 2: Encoder Bottleneck
**Claim**: The LLM backbone has sufficient reasoning capacity for long-context retrieval; the degradation stems from the time series encoder's failure to preserve temporal granularity in compressed representations.
- **Mechanism**: Oracle bypasses the encoder by providing ground-truth activity timelines as text. The LLM achieves 82.2%–91.3% retrieval across lengths, demonstrating that the encoder's output representation is the limiting factor.
- **Evidence**: Oracle variant stabilizes retrieval; standard model degrades.
- **Break condition**: If oracle showed the same degradation pattern, the bottleneck would lie in the LLM or task design.

### Mechanism 3: Context-Invariant Learning
**Claim**: The non-monotonic retrieval degradation (sharp drop then plateau) suggests training on mixed context lengths induces an encoder strategy that prioritizes global features over localized patterns.
- **Mechanism**: Joint training across context lengths may cause the model to converge toward representations that discard fine-grained details to generalize across scales. The steepest drop coincides with collapse of "State Query" performance (65.3% → 24.7%).
- **Evidence**: State Query drives 78% of overall degradation; non-monotonic curve contrasts with linear compression expectation.
- **Break condition**: If retrieval degraded linearly with compression ratio across all tasks, or if State Query did not dominate, the hypothesis would weaken.

## Architecture Onboarding
**Component map**:  
Raw time series -> Patch Tokenizer (p=4) -> [Latent Resampler (M=64) / Full-Attention Encoder (ITFormer)] -> LLM Backbone -> Output Head  

**Critical path**: The resampler's cross-attention is the key control point for compression; it maps N patch embeddings to M latent tokens.

**Design tradeoffs**:  
- Compression Ratio (N/M): Higher ratios (longer contexts) improve classification efficiency but harm retrieval precision.  
- LLM Backbone finetuning: OpenTSLM-Flamingo finetunes the LLM; ITFormer freezes it, contributing to performance gaps.  
- Patch Granularity: Larger patches reduce N but risk losing fine-grained patterns for short needles.

**Failure signatures**:  
- Symptom: Classification Macro-F1 increases with context length, but retrieval accuracy degrades or plateaus low.  
- Diagnosis: Check fixed M vs. growing N; run oracle to isolate encoder.  
- ITFormer: OOM at N>~40k; below-random retrieval even at short N suggests issues beyond memory (e.g., frozen LLM, patching).

**First 3 experiments**:  
1. Reproduce Classification Scaling: Train OpenTSLM-Flamingo on Capture24 across context lengths; expect Macro-F1 to improve from 32.9% to 41.4%.  
2. Measure Retrieval Degradation: Evaluate same model on TS-Haystack; expect peak retrieval at 2.56s, drop to 23.2% at 15min, then plateau; isolate tasks driving degradation (State Query).  
3. Oracle Ablation: For 15min context, run Oracle variant; expect retrieval >82%, confirming encoder bottleneck.

## Open Questions the Paper Calls Out
- **Why does retrieval degrade non-monotonically with context length?** The paper hypothesizes joint training induces a context-invariant strategy, but lacks direct evidence. Ablations with curriculum learning are needed.
- **What encoder modifications decouple computational complexity from temporal fidelity?** The bottleneck is identified but not dissected. Systematic ablations of resampler queries, patch size, or cross-attention alternatives are required.
- **Is the degradation due to lost signal or noise amplification?** Oracle confirms encoder failure but not whether compression discards fine-grained patterns or corrupts them. Information-theoretic analysis of latent representations is needed.
- **Why does ITFormer fail below random despite full-attention?** Confounded by frozen LLM, patch size, and hyperparameters. Controlled experiments with unfrozen LLM, tuning, and varied patching are necessary.

## Limitations
- Missing training details (batch size, warmup steps) for OpenTSLM-Flamingo may affect reproducibility.
- Cosine blending window size for needle insertion is unspecified, impacting sample generation.
- ITFormer comparison is confounded by different LLM backbone and frozen parameters.

## Confidence
- Mechanism 1 (compression trade-off): High. Empirical retrieval degradation with increasing N/M and oracle control.
- Mechanism 2 (LLM sufficient): High. Oracle maintains stable high retrieval across lengths.
- Mechanism 3 (context-invariant learning): Medium. Non-monotonic drop correlates with State Query failure; needs training-strategy validation.

## Next Checks
1. Reproduce classification scaling: Train OpenTSLM-Flamingo on Capture24; verify Macro-F1 improvement from 32.9% to 41.4% with longer context.
2. Oracle validation: On 15-min context, confirm retrieval >82%. Failure would challenge encoder-bottleneck claim.
3. Training strategy test: Train models per context length separately vs. jointly; compare retrieval degradation to isolate context-invariant learning effect.
