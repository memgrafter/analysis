# End-to-End Efficient RL for Linear Bellman Complete MDPs with Deterministic Transitions

## Quick Facts
- **arXiv ID**: 2603.23461  
- **Source URL**: https://arxiv.org/abs/2603.23461  
- **Reference count**: 40  
- **Primary result**: An end-to-end efficient RL algorithm for linear Bellman complete MDPs with deterministic transitions that outputs an ε-suboptimal policy with sample and computational complexity polynomial in H, d, 1/ε (and log(1/δ)), independent of |A| for infinite action spaces, requiring only an argmax oracle.

## Executive Summary
This paper tackles efficient reinforcement learning in a structured setting: linear Bellman complete MDPs with deterministic transitions. The key challenge is to avoid the computational intractability or strong oracle requirements of prior methods. The solution is a two-phase algorithm. Phase I constructs a compact, layer-by-layer policy cover—a set of policies whose feature expectations form an approximate barycentric spanner for all reachable states. Determinism enables exact trajectory computation and avoids expensive feature-space optimization. For finite actions, this uses Optimistic Constraint Propagation (OCP); for infinite actions, it uses Fitted Q-Iteration (FQI) with a coverage subroutine. Phase II estimates the linear reward parameters via ridge regression using data from the cover policies, then plans optimally with these deterministic proxy rewards using the same planner as Phase I. The result is a statistically and computationally efficient algorithm with theoretical guarantees.

## Method Summary
The algorithm proceeds in two phases. **Phase I** builds a policy cover Γ₁:H, where each Γₕ is a set of d policies whose feature expectations form an approximate barycentric spanner for features reachable at layer ℎ. This is done via a generic `RobustSpanner` procedure that repeatedly queries a linear optimization oracle (`LinOpt`). For finite |A|, `LinOpt` is implemented by `OCP`, which solves a linear program over linear Q-functions while maintaining Bellman consistency. For infinite |A|, `LinOpt` uses `FQI` with a coverage set Ψ₁:ℎ₋₁ (produced by a `SubspaceCover` subroutine) to enable exact least-squares regression. **Phase II** collects rollouts from each policy in Γ to estimate the unknown linear reward parameters wₕ* via ridge regression. These estimates define deterministic proxy rewards ŕₕ(x,a)=⟨ŵₕ, ϕₕ(x,a)⟩. Finally, the same planner (`OCP` or `FQI`) optimizes these deterministic rewards to output the target policy π̂. The method exploits deterministic transitions for exact coverage and planning, and the linear Bellman completeness assumption for realizability.

## Key Results
- For finite action spaces, the algorithm outputs a policy with expected suboptimality ≤ ε using samples and time polynomial in H, d, 1/ε, log(1/δ), and |A|.
- For infinite action spaces, the dependence on |A| is entirely removed; complexity is polynomial in H, d, 1/ε, log(1/δ) only, assuming an argmax oracle.
- The method replaces the linear optimization oracle required by prior work with standard RL primitives (OCP or FQI) and a coverage subroutine, achieving the same guarantees under deterministic transitions.

## Why This Works (Mechanism)
**Mechanism 1: Deterministic transitions enable exact trajectory coverage**  
Deterministic dynamics allow the algorithm to exactly trace any policy's state-action trajectory. This is crucial for building policy covers and solving Bellman backups without distributional uncertainty. In the finite-action variant, OCP exploits this to evaluate Q-functions exactly on sampled trajectories. In the infinite-action variant, FQI solves regression problems exactly because deterministic rewards yield deterministic targets. This exactness avoids the computational overhead of solving constrained optimization problems over feature spaces that prior work required.

**Mechanism 2: Layer-by-layer barycentric spanner construction**  
The algorithm constructs a policy cover Γ₁:H where each Γₕ is an approximate barycentric spanner for the set of feature expectations of policies at layer ℎ. This is achieved via `RobustSpanner`, which uses approximate linear optimization oracles. Deterministic dynamics ensure that feature vectors ϕₕ(xₕ,aₕ) are exactly reachable, and the spanner property guarantees that any policy's expected feature vector can be expressed as a bounded linear combination of spanner policies' features. For finite actions, the `LinOpt` oracle uses OCP; for infinite actions, it uses FQI with `SubspaceCover` to provide exact optimization.

**Mechanism 3: Stochastic-to-deterministic reduction via reward estimation**  
Rewards are linear in features with unknown bounded parameters wₕ*. Phase II estimates these via ridge regression on rollouts from the spanner policies Γₕ. This yields deterministic proxy rewards ŕₕ(x,a)=⟨ϕₕ(x,a), ŵₕ⟩ that match the original rewards in expectation. The deterministic planning phase (OCP or FQI) then optimizes these proxies. This bypasses the need to bound Q-function parameters—a limitation of prior approaches that required a feature-space oracle.

## Foundational Learning
**Concept: Linear Bellman completeness**  
Why needed: It is the core structural condition ensuring that linear representations are sufficient for value functions. The algorithm assumes that for any linear ⟨ϕₕ₊₁, θ⟩, its Bellman backup ⟨ϕₕ, Tₕθ⟩ is also linear. This enables the use of linear function approximation throughout and underlies the realizability assumptions for OCP and FQI.  
Quick check: A linear MDP (Jin et al., 2020) satisfies linear Bellman completeness.

**Concept: Deterministic MDP dynamics**  
Why needed: Determinism allows exact computation of trajectories and Q-function regressions, which is exploited by both OCP and FQI. It prevents error compounding that would arise with stochastic transitions when using approximate spanners.  
Quick check: Under a deterministic policy, all states reachable in H steps can be enumerated as a tree of at most |A|ᴴ leaves.

**Concept: Barycentric spanners**  
Why needed: They provide a compact, span-complete set of policies for each layer. With d policies per layer (instead of potentially infinite), they enable efficient exploration and accurate reward estimation across all relevant feature directions.  
Quick check: In a C-approximate barycentric spanner, any point in the span can be expressed as a linear combination of spanner points with |βᵢ| ≤ C.

**Concept: Optimistic Constraint Propagation (OCP)**  
Why needed: For finite |A|, OCP efficiently optimizes over linear Q-functions via linear programming while maintaining Bellman consistency. It serves as the `LinOpt` oracle in Phase I and as the final planner in Phase II.  
Quick check: OCP maintains an optimistic set of Q-functions and tightens it with observed transitions; it requires Q⋆-realizability, satisfied here by linear Bellman completeness.

**Concept: Fitted Q-Iteration (FQI)**  
Why needed: For infinite |A|, OCP's linear programming per action becomes intractable. FQI solves the Bellman backup via least-squares regression using coverage policies, achieving exact solutions under deterministic rewards if the coverage condition holds.  
Quick check: FQI requires an argmax oracle over actions; here it is called with deterministic proxy rewards, making regression targets deterministic.

**Concept: Ridge regression for linear reward estimation**  
Why needed: Reward functions are assumed linear with bounded wₕ*. Ridge regression estimates these parameters from spanner rollouts, achieving accuracy controlled by sample size and regularization. This step reduces stochastic rewards to deterministic proxies.  
Quick check: The sample complexity for estimating wₕ* to error ε scales as d²/ε² if feature vectors are normalized and rewards are bounded.

## Architecture Onboarding
**Component map**:  
ComputeSpanner (Algorithms 2/5) -> RobustSpanner (Algorithm 11) -> [LinOpt (OCP/FQI) + EstVec (Algorithm 9)]  
For infinite actions: SubspaceCover (Algorithm 4) -> FQI (Algorithm 8) as part of LinOpt  
PolicyOpt (Algorithms 3/6) -> Ridge regression -> [OCP or FQI] -> π̂

**Critical path**:  
Phase I: `ComputeSpanner` calls `RobustSpanner`, which repeatedly queries `LinOpt` (OCP for finite actions; FQI with `SubspaceCover` for infinite actions) and `EstVec`. For infinite actions, `SubspaceCover` must precede FQI calls to provide Ψ₁:ℎ₋₁ coverage policies that enable exact least-squares solutions. `SubspaceCover` itself uses FQI and `ComputeOutlierDirection` to identify new feature directions, iterating up to d times per layer.  
Phase II: The Γ policies provide data for ridge regression; estimated ŵₕ define deterministic rewards; OCP or FQI optimizes these to produce π̂.

**Design tradeoffs**:  
- Finite vs infinite actions: OCP-based approach is simpler but complexity depends polynomially on |A|; FQI-based approach removes |A| dependence but requires building and maintaining coverage policies Ψₕ.  
- Error propagation: Finite actions use approximate spanners with error accumulating as 9dε; infinite actions handle both coverage and spanner errors, yielding larger constants (25dε).  
- Sample complexity: Infinite-action algorithm has an extra d² factor compared to finite-action bound due to subspace identification in `SubspaceCover`.

**Failure signatures**:  
- LinOpt failure: If OCP/FQI returns suboptimal policies for a given linear objective, the spanner property degrades.  
- Coverage insufficiency: `SubspaceCover` requires P[x₁∈Xₕ] ≥ 1-ε'/H; if initial state mass lies outside covered subspaces, Phase II coverage may fail.  
- Reward estimation error: Insufficient samples in ridge regression lead to high ε_stat, dominating suboptimality.  
- Rejection sampling inefficiency: `ComputeOutlierDirection` uses rejection sampling; if outlier probability p is too small, n_reject may become large.  
- Union bound blowup: Confidence δ is split across H layers and events; large H inflates sample sizes via log factors.

**First 3 experiments**:  
1. **Spanner validation**: Run `ComputeSpanner` on a known linear Bellman complete MDP. Check that |Γₕ|=d and that for random policies π, ∥E[ϕπₕ(x₁)] - Σ βⱼ E[ϕπʲₕ(x₁)]∥ ≤ 9dε.  
2. **End-to-end learning curve**: Use the infinite-action algorithm with argmax oracle on a deterministic linear MDP. Sweep total samples and plot expected suboptimality vs n; verify scaling ~ d⁴H²/ε².  
3. **Determinism ablation**: Introduce small stochasticity in transitions (e.g., Gaussian noise). Compare algorithm's performance to pure deterministic case; suboptimality should degrade significantly, and `SubspaceCover`'s concentration condition P[x₁∈Xₕ] should drop.

## Open Questions the Paper Calls Out
- **Can the determinism assumption be relaxed?** The algorithm fundamentally relies on exact trajectory computation; extending to stochastic transitions while retaining polynomial guarantees remains open.
- **What is the tight dimension and horizon dependence?** The current analysis yields high-degree polynomial factors (e.g., d⁴H² for infinite actions); improving these dependencies is an open challenge.
- **How does the method perform empirically?** The paper lacks experiments; practical issues like rejection sampling efficiency, horizon scaling, and sensitivity to misspecified features are unexplored.
- **Can unknown feature maps be handled?** The approach requires a known feature representation; developing sample-efficient methods for learning features jointly is an open direction.
- **Is the argmax oracle essential for infinite actions?** While the algorithm avoids |A| dependence, it still requires an argmax oracle; whether this can be further relaxed is unknown.

## Limitations
- **Determinism reliance**: Guarantees break under stochastic transitions; exact trajectory computation is central.
- **Structural assumptions**: Requires linear Bellman completeness and known feature maps, which may not hold in practice.
- **High sample complexity**: Polynomial but with high-degree dependence (e.g., d⁴H²/ε² for infinite actions) and large constants from union bounds.
- **Infinite-action constraints**: Requires an argmax oracle and a coverage condition on initial states; may fail if P₀ places mass outside covered subspaces.
- **Lack of empirical validation**: No experiments; practical issues like rejection sampling efficiency and horizon scaling remain untested.

## Confidence
- **Polynomial complexity under assumptions**: Medium. Analysis appears sound but under strong assumptions; constants and practical scaling unclear.
- **Infinite-action independence from |A|**: Medium. Achieved via FQI with coverage, but depends on `SubspaceCover` and argmax oracle; extra d² factor and coverage condition limit generality.
- **Feature-space oracle avoidance**: Medium. Replaces constrained optimization with deterministic planning; still requires argmax oracle, so improvement is conditional.
