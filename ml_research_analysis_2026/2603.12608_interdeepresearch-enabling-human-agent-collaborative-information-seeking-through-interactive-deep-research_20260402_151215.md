# InterDeepResearch: Enabling Human-Agent Collaborative Information Seeking through Interactive Deep Research

## Quick Facts
- **arXiv ID:** 2603.12608  
- **Source URL:** https://arxiv.org/abs/2603.12608  
- **Reference count:** 40  
- **Primary result:** A human‑in‑the‑loop deep research system with hierarchical context management and three coordinated views yields high user satisfaction (mean 4.33/5) and competitive automated performance on benchmarks.

## Executive Summary
InterDeepResearch addresses the passive role of users in existing deep research systems by introducing a human‑agent collaborative framework. It organizes research into a hierarchical context (information, actions, sessions) that enables dynamic context reduction to prevent LLM exhaustion and supports cross‑action evidence provenance. The interface integrates three linked views—linear chat, dependency graph, and detail cards—allowing users to navigate and steer the agent’s process. Evaluations on search benchmarks and a user study (N=15) demonstrate effectiveness, with strong ratings for process comprehension, steering flexibility, and navigation.

## Method Summary
The system builds a three‑level hierarchical graph: atomic `ResearchInformation` nodes (search results, notes, sources), `ResearchAction` nodes that generate information and depend on prior actions, and `ResearchSession` milestones grouping related actions. Dynamic minimization reduces low‑level context after milestones while preserving summaries. Three synchronized frontend views display the research process: a linear chat‑style session log, an interactive dependency graph, and a card view for information details. A dedicated backtrace agent recursively navigates the graph to locate evidence for any user‑selected claim. The agent (Claude Sonnet 4.5) executes actions based on context, and users can intervene at any point (e.g., interrupting, injecting information, editing context).

## Key Results
- Competitive automated performance on Xbench‑DeepSearch‑v1 and Seal‑0 benchmarks.
- User study ratings (5‑point Likert): process comprehension μ=4.80, steering flexibility μ=4.40, context navigation μ=4.27, overall collaboration satisfaction μ=4.33.
- Cross‑action backtrace improves provenance verification efficiency (μ=4.33), though some users noted latency.

## Why This Works (Mechanism)

### Mechanism 1: Hierarchical Research Context Architecture
- **Claim:** The three‑level hierarchy (information, actions, sessions) enables detailed visibility and macro tracking while preventing LLM context exhaustion.
- **Mechanism:** Atomic information units are separated from generating actions; actions are grouped into milestone sessions. After processing, low‑level context (e.g., raw source text) is minimized, but milestone summaries and dependencies are retained, allowing cross‑action tracing without overwhelming the LLM.
- **Core assumption:** LLM performance degrades with irrelevant context; humans comprehend hierarchical abstraction and dependency graphs better.
- **Evidence anchors:** Abstract mentions dynamic context reduction and backtracing; Section 4.1 defines the hierarchy and minimization rules; prior work lacks this specific three‑level design.
- **Break condition:** If users primarily need linear narratives (as some study participants did), the hierarchy may be underutilized, reducing the benefit of context reduction tied to milestones.

### Mechanism 2: Coordinated Tri‑View Linkage
- **Claim:** Three synchronized views (linear chat, dependency graph, card details) with cross‑view linkage support multiple sensemaking strategies and efficient navigation.
- **Mechanism:** Each view highlights the same focused research action. Clicking an element in one view updates the others, letting users switch between chronological, structural, and detailed perspectives without losing context.
- **Core assumption:** Different users/tasks require different mental models (linear vs. graph); linkage reduces switching cost.
- **Evidence anchors:** Section 5.1–5.2.1 describes view design and linkage; Section 8.3.1 shows mixed adoption (some switchers benefited, graph‑only users less so); prior systems use spatial organization but not coordinated tri‑view linkage for agent processes.
- **Break condition:** Users aligned with a single view may find the three‑view overhead unnecessary, reducing net benefit.

### Mechanism 3: Cross‑Action Backtrace Agent
- **Claim:** A dedicated LLM agent recursively traces prerequisite information from a selected claim to raw sources, improving provenance verification efficiency.
- **Mechanism:** On user text selection and “Trace” click, the system queries the dependency graph to identify prerequisite information blocks, then an LLM agent examines those blocks for direct evidence, recursing until raw sources are found. Results appear as temporary graph nodes.
- **Core assumption:** Manual verification through final reports and links is inefficient; an agent can automate evidence hunting within the captured context.
- **Evidence anchors:** Section 4.3 describes the recursive backtrace; Section 5.2.2 details the UI (citation superscript highlights, Trace button); Section 8.3.2 gives high user rating (μ=4.33) but notes latency; prior work on analytic provenance does not use LLM‑powered recursive backtrace in research.
- **Break condition:** Inaccurate backtrace (missed evidence/hallucinations) or high latency can disrupt collaborative flow and reduce trust.

## Architecture Onboarding

- **Component map:**  
  User <-> Agent Controller <-> Context Manager  
  Context Manager -> View Renderers (ChatView, GraphView, CardView)  
  View Renderers <-> Linkage Controller (focus synchronization)  
  Context Manager -> Backtrace Agent (dependency queries)

- **Critical path:** User query → Agent Controller plans first action → Context Manager creates action/information nodes → View Renderers render initial state → Agent Controller executes next action → Context updates → Views update. User interruption: injects `User Information` → Context adds node → Agent Controller replans.

- **Design tradeoffs:**  
  - Context reduction vs. traceability: Minimizing raw source text saves tokens but may force backtrace to rely on summaries, risking evidence loss.  
  - View complexity vs. sensemaking: Three coordinated views support diverse strategies but increase UI complexity and learning curve (mixed feedback on linkage utility).  
  - Real‑time backtrace vs. latency: Dedicated agent ensures accurate provenance but introduces wait times that disrupt collaborative flow.

- **Failure signatures:**  
  - Agent ignores interventions: User guidance not reflected in subsequent plans → check Agent Controller’s prompt engineering and context injection.  
  - Context overflow: LLM performance drops despite reduction rules → verify minimization triggers and redundant information.  
  - Backtrace returns no evidence: Selected text’s cited actions missing from graph, or Backtrace Agent parsing fails → inspect graph completeness and agent logic.

- **First 3 experiments:**  
  1. **Context Reduction Validation:** Run a long‑horizon task (50+ actions) with/without minimization; measure token usage and report quality.  
  2. **Cross‑View Navigation Efficiency:** Recruit users with linear vs. graph preferences; measure task time/accuracy with single‑view vs. linked tri‑view.  
  3. **Backtrace Accuracy:** Create test claims with known evidence paths; compare backtrace precision/recall against ground truth graph traversals.

## Open Questions the Paper Calls Out

- **Adaptive interfaces:** How can the system dynamically adapt to users’ distinct navigation patterns (e.g., linear vs. graph preferences) to optimize comprehension and steering? The current fixed tri‑view design showed mixed adoption.
- **Richer modalities:** What are the benefits and trade‑offs of integrating voice commands and multimodal outputs (e.g., audio summaries, dynamic charts) into the collaborative workflow? The present system is purely visual/textual.
- **Multi‑agent/multi‑user scaling:** How can architectures support multiple concurrent agents, multiple humans, and branching research threads without overwhelming users or fragmenting evidence provenance? The current framework assumes a single linear session.

## Limitations
- Exact LLM prompts and context reduction thresholds are unspecified, hindering precise replication.
- Mixed user feedback on multi‑view usage suggests the three‑view design may not benefit all mental models.
- Backtrace agent latency and potential inaccuracies could degrade collaborative flow and trust.
- User study included only 15 participants, limiting statistical power and generalizability.
- Benchmark performance is competitive but not compared against other state‑of‑the‑art deep research systems.

## Confidence
- **Hierarchical context architecture (context reduction + provenance):** Medium. Design reasoning solid and results positive, but lacks direct ablation evidence.
- **Coordinated tri‑view linkage:** Medium. Navigation ratings are high, but mixed adoption indicates benefits are conditional on user preferences.
- **Cross‑action backtrace:** Medium‑High. Direct user evaluation (4.33/5) supports effectiveness, though latency remains a concern.

## Next Checks
1. **Context reduction impact:** Controlled experiment with long‑horizon tasks (50+ actions) comparing token usage and report quality with/without minimization rules.
2. **View linkage utility:** Study users with different sensemaking preferences (linear vs. graph‑oriented) measuring task completion time and accuracy using single‑view versus linked tri‑view.
3. **Backtrace accuracy:** Build a test suite of generated claims with known evidence paths; compute precision/recall of the backtrace agent’s evidence location against ground truth dependency traversals.
