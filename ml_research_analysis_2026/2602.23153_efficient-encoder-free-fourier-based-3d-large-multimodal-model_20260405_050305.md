# Efficient Encoder-Free Fourier-based 3D Large Multimodal Model

## Quick Facts
- **arXiv ID:** 2602.23153  
- **Source URL:** https://arxiv.org/abs/2602.23153  
- **Reference count:** 40  
- **Primary result:** Fase3D achieves comparable or superior performance to encoder-based models (e.g., 90.11 CIDEr with Qwen2.5-3B) while activating only 10.54M parameters and requiring 2.04G FLOPs for tokenization—>5× fewer parameters and >18× fewer FLOPs than prior art like 3D‑LLaVA (58.26M params, 37.75G FLOPs).

## Executive Summary
Fase3D proposes an encoder‑free architecture for 3D Large Multimodal Models that eliminates the need for heavy 3D encoders. Point clouds are tokenized via structured superpoints, space‑filling curve (SFC) serialization, and a Fast Fourier Transform (FFT)‑based context enhancer that approximates self‑attention with near‑linear complexity. A graph‑based token merger reduces the token count, and the resulting tokens are fed to a frozen LLM equipped with Fourier‑augmented LoRA adapters. Despite using only 10.54M activated parameters and 2.04G FLOPs for tokenization, Fase3D matches or exceeds state‑of‑the‑art performance on 3D QA, dense captioning, and embodied QA benchmarks.

## Method Summary
The pipeline begins with a lightweight MLP embedding of raw points, followed by geometric superpoint clustering to produce M semantically coherent tokens. These tokens are serialized along multiple SFCs (Hilbert, Z‑order, and transposed variants) to embed 3D locality into a linear order. A windowed FFT context enhancer then aggregates global information by modulating spectral components and overlap‑adding the results; multi‑curve fusion averages across SFC traversals for robustness. A sparse superpoint graph is constructed via windowed voting along the SFC orders; graph connectivity guides a token merging step that reduces the token count to T (e.g., 256) using farthest‑point sampling anchors and neighborhood pooling. The final tokens (with coordinate embeddings) are concatenated with text prompts and processed by a frozen LLM. To adapt the LLM with minimal extra parameters, LoRA is applied to the first 8 feed‑forward network (FFN) layers, and a Global Filter Module performs channel‑wise frequency filtering on the vision branch, further enhancing performance.

## Key Results
- On ScanQA and SQA3D, Fase3D reaches 90.11 CIDEr when paired with Qwen2.5‑3B.  
- Tokenization costs only 2.04G FLOPs and activates 10.54M parameters—>5× fewer parameters and >18× fewer FLOPs than 3D‑LLaVA (58.26M params, 37.75G FLOPs).  
- Similar efficiency gains and performance parity are observed on dense captioning benchmarks (ScanRefer, Nr3D).

## Why This Works (Mechanism)

### Encoder‑Free Tokenization via Structured Superpoints and SFC Serialization
Fase3D replaces a heavy 3D encoder with a lightweight, permutation‑invariant tokenizer that leverages geometric superpoints and SFC serialization. Superpoint clustering over‑segments the point cloud into geometrically coherent regions; point features are pooled per superpoint to form initial tokens. These superpoints are then serialized into 1D sequences via multiple SFCs (Hilbert, Z‑order, transposed), preserving 3D locality in the linear order and enabling global processing with standard 1D operators. **Evidence:** [abstract], Sections 3.1‑3.2. **Break condition:** Degradation occurs if superpoint clustering fails to capture object‑level semantics (e.g., in cluttered or homogeneous scenes) or if SFC ordering introduces significant long‑range discontinuities that disrupt frequency‑domain mixing.

### FFT‑Based Context Enhancer for Efficient Global Mixing
A windowed FFT applied to SFC‑serialized tokens approximates global self‑attention with near‑linear complexity, injecting long‑range context into each token. The serialized token sequence is split into overlapping windows; each window undergoes real‑valued FFT, where a learnable gate modulates spectral components. An inverse FFT returns to the spatial domain, and overlap‑add blends the windows. Multi‑curve fusion averages results from different SFC traversals to mitigate ordering biases. Complexity is O(M log M) for sequence length M. **Evidence:** [abstract], Section 3.2, Appendix C.1. **Break condition:** If the SFC ordering fails to preserve spatial relationships critical for the task, the frequency‑domain operations may mix irrelevant signals, especially when long‑range dependencies are highly non‑local along all SFC traversals.

### Fourier‑Augmented LoRA for Frequency‑Aware LLM Adaptation
A Global Filter Module (GFM) augments standard LoRA by operating in the frequency domain of LLM input tokens, injecting global context awareness at <0.1% additional LLM parameters. Before entering the LoRA‑adapted FFN layers, each token’s feature vector is transformed via FFT, multiplied by a learnable channel‑wise filter, and inverse transformed. The mixed representation is averaged with the original token and fed into the LoRA branch. **Evidence:** [abstract], Section 3.5, Table 4 (ablation). **Break condition:** If the frozen LLM’s internal representations are saturated or the frequency patterns introduced by GFM conflict with the LLM’s pretrained feature space, the augmentation could destabilize training or provide no benefit; indeed, applying FFT to both vision and text branches reduced gains, indicating sensitivity to placement.

## Foundational Learning

#### Permutation Invariance and Point Cloud Serialization
**Why needed:** Point clouds are unordered sets; any architecture must be permutation‑invariant. Serialization via SFCs imposes an order while preserving spatial coherence, enabling the use of standard 1D operators.  
**Quick check:** Why is using a single fixed SFC traversal potentially problematic, and how does multi‑curve serialization mitigate this?

#### Spectral Domain Processing & FFT Efficiency
**Why needed:** To approximate the quadratic cost of all‑to‑all self‑attention with a near‑linear operation for long‑range context in long 3D sequences. The FFT’s O(N log N) complexity enables efficient spectral mixing.  
**Quick check:** What is the computational complexity of the windowed FFT mixer relative to sequence length M, and why does overlap‑add help?

#### Parameter‑Efficient Fine‑Tuning (LoRA)
**Why needed:** Adapting a huge frozen LLM with minimal added parameters. LoRA decomposes weight updates into low‑rank matrices; Fourier augmentation complements it with a parameter‑minimal pre‑processing step.  
**Quick check:** In standard LoRA, where are the low‑rank matrices inserted, and what does the Fourier augmentation module do relative to these inserted layers?

## Architecture Onboarding

**Component map:**  
Input Point Cloud → MLP Point Embedding → Superpoint Pooling (M tokens) → FFT Context Enhancer (Multi‑curve) → Graph Construction (Window Voting) → Graph‑Based Token Merging (T tokens, T < M) → SFC Serialization (for LLM order) → Prompt Embedding (coordinate tokens + text) → LLM (frozen) with Fourier‑Augmented LoRA in FFN layers

**Critical path:** The most novel and efficiency‑critical path is: Superpoint formation → Multi‑curve SFC serialization → Windowed FFT mixing → Graph‑based merging. Any failure in SFC ordering or FFT windowing propagates to LLM input quality.

**Design tradeoffs**
- Superpoint granularity: Fewer superpoints reduce cost but risk losing fine‑grained details.
- FFT window size (Lw) & stride (Ls): Larger windows capture broader context but increase per‑window cost; stride controls overlap. The paper uses Lw=128, Ls=Lw/2.
- Graph sparsity vs. connectivity: Window‑voting is efficient but may miss weak edges if window/stride too small; re‑ranking with Euclidean distance helps.
- LoRA placement & Fourier augmentation: Adding FFT residuals only to the vision branch (dLoRA+FFT) worked best; adding to both branches hurt performance.

**Failure signatures**
- Poor superpoint clustering: splits single objects or merges distinct ones → semantically incoherent tokens.
- SFC ordering artifacts: abrupt jumps in the serialized token sequence (see curve visualizations) → irrelevant spectral mixing.
- Graph sparsity failures: overly sparse or disconnected graph if window‑voting is too conservative → isolated tokens.
- FFT over‑smoothing: tokens lose discriminative local features if mixing is too aggressive → monitor token feature variance.

**First 3 experiments**
1. **Isolate Tokenizer Quality:** Train a frozen LLM with only the tokenizer (no merging, no Fourier LoRA) on a simple task (e.g., “What objects are present?”). Compare (a) raw downsampled points, (b) superpoints only, (c) superpoints+FFT enhancer. Validates the core tokenization pipeline (Table 3 baseline).
2. **Validate Graph Merging vs. Alternatives:** Freeze all components except the merging module. Compare graph‑based merging against (a) FPS‑only and (b) Q‑Former style cross‑attention pooling on ScanQA. Tests the inductive value of graph connectivity (Table E).
3. **Ablate Fourier‑Augmented LoRA:** Fix all components except LoRA configuration. Train with (a) standard LoRA on vision branch only, (b) depthwise LoRA (dLoRA) on vision branch, (c) dLoRA+FFT on vision branch. Isolates the contribution of the frequency residual (Table 4).

## Open Questions the Paper Calls Out

**Open Question 1:** How can encoder‑free 3D LMMs effectively model non‑Euclidean long‑range spatial relationships in highly cluttered scenes?  
- *Basis:* Explicitly stated as a limitation in the conclusion.  
- *Why unresolved:* The FFT operates on 1D serialized sequences, which can distort true 3D proximity beyond local windows.  
- *What evidence would resolve:* Ablations on cluttered scene benchmarks (e.g., Matterport3D) measuring accuracy on queries requiring reasoning about objects that are close in 3D but far in the serialized order, compared to graph‑based methods.

**Open Question 2:** Can adaptive or learned serialization methods improve upon fixed space‑filling curves for tokenizing unordered point clouds?  
- *Basis:* Listed as a future direction.  
- *Why unresolved:* Fixed curves may not optimally preserve locality for all scene geometries or tasks.  
- *What evidence would resolve:* Implement trainable permutation modules that generate data‑dependent 1D orders and evaluate them against fixed curves on token coherence, context mixing efficiency, and task metrics.

**Open Question 3:** How can additional modalities like RGB images be integrated into the encoder‑free 3D LMM framework without compromising its efficiency gains?  
- *Basis:* Future work mentions integration with RGB images.  
- *Why unresolved:* Adding images would require new tokenization and fusion mechanisms that could increase parameters and FLOPs.  
- *What evidence would resolve:* Design lightweight image tokenizers (e.g., raw‑pixel patch embeddings with linear projection) combined with the existing Fourier pipeline and report parameter count, FLOPs, and accuracy on multi‑modal 3D QA/captioning benchmarks.

**Open Question 4:** What scale and diversity of 3D pretraining corpora are necessary to maximize the generalizability of encoder‑free 3D LMMs like Fase3D?  
- *Basis:* Future work includes pretraining on larger and more diverse 3D corpora.  
- *Why unresolved:* The current pretraining uses a limited ScanNet‑based mixture; it is unclear how performance scales with data size, domain diversity (e.g., outdoor scenes), or multi‑task supervision.  
- *What evidence would resolve:* Systematic experiments varying pretraining data volume and composition (indoor vs. outdoor, synthetic vs. real), measuring zero‑shot and few‑shot transfer to held‑out datasets and tasks while maintaining the encoder‑free constraint.

## Limitations
- **Missing hyperparameters:** Graph neighbor count *k*, dataset mixture ratios, Fourier embedding frequencies, LoRA layer scope, and Global Filter Module FFT dimension are not fully specified.
- **Untested assumptions:** Superpoints yield object‑level semantics; SFC order preserves locality for spectral mixing; FFT reweighting suffices for global context; frequency filter aligns with LLM feature space.
- **Potential failure scenarios:** Poor superpoint segmentation in cluttered scenes; SFC traversal discontinuities causing irrelevant spectral mixing; sparse graph isolation of tokens; FFT over‑smoothing from aggressive frequency gating.
