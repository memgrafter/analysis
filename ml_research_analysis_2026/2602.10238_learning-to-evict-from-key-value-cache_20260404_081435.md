# Learning to Evict from Key-Value Cache

## Quick Facts
- arXiv ID: 2602.10238
- Source URL: https://arxiv.org/abs/2602.10238
- Reference count: 40
- Primary result: Reinforcement learning-based per-head agents for KV cache eviction significantly outperform heuristic baselines across diverse tasks with minimal overhead.

## Executive Summary
The memory burden of key-value (KV) cache during large language model inference is typically addressed by heuristic eviction policies (e.g., recency, past attention), which are indirect proxies for future utility and often incur computational overhead. This paper introduces KV Policy (KVP), which reframes eviction as a reinforcement learning problem. Lightweight per-head agents are trained offline to rank tokens by predicted future usefulness using only key and value vectors, without relying on attention scores or queries. Evaluated on RULER and OASST2-4k, KVP substantially improves accuracy and perplexity over strong baselines across a wide range of cache sizes. It also generalizes zero-shot to various downstream tasks, performs well on the Phi-4 model, and adds only ~1% prefill FLOPs overhead. Ablations confirm the necessity of the RL formulation and reward design. KVP presents a scalable, adaptive approach to KV cache management that preserves model utility while reducing memory.

## Method Summary
KVP treats KV cache eviction as a ranking problem solved via reinforcement learning. For each attention head, a lightweight agent takes a token's key and value vectors as input and outputs a scalar score representing its predicted future usefulness. These agents are trained offline on precomputed traces generated by running the model on a dataset; no online interaction is required during training. The reward function evaluates the quality of the ranking across all possible cache budgets simultaneously, encouraging the agent to learn a generalizable notion of token importance. During inference, agents score all tokens in the cache, and tokens with the lowest scores are evicted to meet the budget. This approach avoids recomputing attention or accessing query vectors, minimizing overhead.

## Key Results
- KVP achieves higher accuracy and lower perplexity than strong baselines (TOVA, SnapKV, StreamingLLM) on RULER and OASST2-4k across a wide range of cache sizes.
- Demonstrates robust zero-shot generalization to downstream tasks (BoolQ, ARC-Challenge, GovReport, MMLU, HellaSwag) and maintains performance on the Phi-4 model.
- Adds only approximately 1% overhead to prefill FLOPs while enabling dynamic cache management.

## Why This Works (Mechanism)
KVP succeeds because per-head RL agents directly learn to predict token utility from the K/V representations, bypassing indirect heuristics like recency or past attention. Training on diverse traces with a multi-budget reward forces agents to produce rankings that remain effective under varying cache constraints. Using only K/V vectors eliminates the need for query vectors or attention recomputation, drastically reducing computational overhead during inference. The per-head design captures specialized attention patterns, and offline training ensures efficiency.

## Foundational Learning
- **Reinforcement Learning for Control**: Why needed: Enables learning an eviction policy through reward signals rather than hand-crafted rules. Quick check: Does policy performance improve with more training episodes? Yes, per ablation curves.
- **Token Importance Ranking**: Why needed: Core task is to order tokens by future usefulness for eviction decisions. Quick check: Is ranking correlation with true future utility high? Measured implicitly via reward.
- **KV Cache Eviction**: Why needed: Memory constraint in LLM inference requires discarding some token states. Quick check: Does eviction preserve model accuracy? Evaluated on benchmarks.
- **Per-Head Modeling**: Why needed: Attention heads exhibit different roles; per-head agents capture specialized importance patterns. Quick check: Do per-head agents outperform a shared agent? Ablation confirms significant gain.
- **Offline RL from Traces**: Why needed: Avoids costly online interaction; leverages precomputed model inference data. Quick check: Does training on traces transfer to new sequences? Partially, but limited domain shift results reported.
- **Reward Design for Multi-Budget Evaluation**: Why needed: Encourages rankings useful at any cache size, not just a single budget. Quick check: Does reward correlate with performance across budgets? Yes, shown in experiments.

## Architecture Onboarding
Component map: Precomputed Traces -> Offline RL Training -> Per-Head Agents -> KV Eviction Policy -> Inference with Dynamic Cache
Critical path: Generate traces by running target model on a dataset → Train per-head agents via RL to output token scores → During inference, agents score all cached tokens → Evict tokens with lowest scores to maintain budget.
Design tradeoffs: Per-head agents vs. single shared agent (specialization vs. parameter count), offline training vs. online adaptation (efficiency vs. adaptability), using only K/V vectors (simplicity vs. lost query context).
Failure signatures: Sharp drop in accuracy when cache size is reduced, agents producing nearly uniform scores (failure to discriminate), poor generalization to new domains (high perplexity on out-of-distribution data).
First experiments:
1. Generalization test: Train agents on traces from Llama-2-7B, evaluate on Mistral-7B without retraining to measure cross-model transfer.
2. Ablate per-head design: Replace per-head agents with a single shared agent across all heads; compare performance on RULER at multiple cache budgets.
3. Reward sensitivity: Modify reward to evaluate ranking at only a single cache budget (instead of all budgets) and measure degradation in robustness across varying cache sizes.

## Limitations
- Evaluation relies on a narrow set of benchmarks (RULER, OASST2-4k, and a few downstream tasks) which may not capture the full spectrum of long-context scenarios.
- Offline RL training requires precomputed traces, potentially limiting applicability to new models or domains lacking such data.
- The claimed ~1% prefill FLOPs overhead may not translate to real-world latency due to implementation and hardware factors.

## Confidence

## Next Checks
1. Replicate experiments across a broader suite of long-context benchmarks (including >100k tokens) and diverse model families (e.g., Llama, Mistral, GPT) to assess generalizability.
2. Measure end-to-end inference latency on commodity hardware to verify the 1% overhead claim, considering memory bandwidth and kernel launch overheads.
3. Test robustness to trace distribution shift: train agents on one domain (e.g., web text) and evaluate on a drastically different domain (e.g., scientific code) without retraining.
