# Privasis: Synthesizing the Largest "Public" Private Dataset from Scratch
## Quick Facts
- **arXiv ID:** 2602.03183
- **Source URL:** https://arxiv.org/abs/2602.03183
- **Reference count:** 40
- **Primary result:** Introduces a million-scale synthetic dataset enabling compact models (≤4B) to achieve state-of-the-art privacy sanitization performance, surpassing larger frontier models.

## Executive Summary
Privasis introduces a fully synthetic dataset of 1.4 million private records across medical, legal, and financial domains, built from scratch without using real individual data. Its core innovation is a pipeline that uses public name databases to generate auxiliary control variables (profiles, record types, contexts), steering LLM-based generation toward diverse, realistic private information. An iterative refinement process balances quality and semantic diversity using a Vendi score. A parallel decomposition-based sanitization corpus enables training compact models to follow complex sanitization instructions. The resulting 4B-parameter model achieves 72.5% success on a rigorous sanitization benchmark, outperforming much larger models and demonstrating strong zero-shot generalization.

## Method Summary
The synthesis pipeline generates records bottom-up: it samples a first name from a public database, uses an LLM to create a detailed profile, then generates a specific record type (e.g., "psychotherapy billing statement") and background context. These variables format a prompt for an initial draft, which undergoes up to three iterative refinements. Refinements are accepted based on a weighted score combining an LLM judge's quality rating and the change in a Vendi diversity score relative to the existing dataset. Final records are filtered for length and plausibility.

The sanitization pipeline decomposes records into chunks (≤512 characters), selects sensitive target attributes with weighted sensitivity, identifies relevant chunks for each target, and generates an instruction to abstract or drop that target's information uniformly across all relevant chunks. Sanitized chunks are merged, and a final coherent user instruction is generated, optionally specifying attributes to retain. This produces parallel (original, instruction, sanitized) triplets for model training.

## Key Results
- The 4B Privasis-Cleaner achieves 72.5% full success rate on vanilla sanitization, exceeding GPT-5 (70.3%) and matching it on the hard set (12.8% vs. 13.1%).
- The model demonstrates strong zero-shot generalization, matching a NaP²-finetuned model on that benchmark despite never seeing NaP² data.
- The dataset shows superior diversity over human-written corpora (MATTR 0.807–0.823) and passes privacy verification with no real individuals identified in a 1K sample audit.

## Why This Works (Mechanism)
### Mechanism 1
Auxiliary control variables (profile, record type, background context) initialized from a public name database enable scalable synthesis of diverse, realistic private records from scratch. The pipeline constructs a semantic and format string from these variables to guide an LLM in generating a specific, constrained first draft, preventing generic outputs.

*Evidence:* Paper sections 2.1 detail the step-by-step generation of profiles, record types, contexts, and formats. The abstract explicitly states the use of these variables for core synthesis.

### Mechanism 2
A diversity-preserving iterative refinement process uses a weighted combination of an LLM quality score and a Vendi diversity score to prevent semantic collapse. Candidates are accepted only if the combined score exceeds a threshold, explicitly rewarding both quality and novelty against the existing record pool.

*Evidence:* Section 2.1 describes the iterative selection with Vendi. Table 9 shows ablations where removing the diversity term increases cosine similarity (redundancy). Table 2 reports high lexical diversity (MATTR) and low cosine similarity for the final dataset.

### Mechanism 3
A decomposition-based sanitization pipeline splits long records into contextually coherent chunks and applies targeted, consistent sanitization per chunk, enabling reliable rewriting of million-scale documents for arbitrary user instructions.

*Evidence:* The abstract and section 3.1 detail the decomposition, target selection, and per-chunk sanitization. Figure 5 shows a performance peak at the 512-character chunk size, and section 4.3 reports SOTA results from models trained on this pipeline's output.

## Architecture Onboarding
- **Component map:** Public DB (Names) -> Profile Generator -> Record Type & Context Generator -> Format Generator -> Initial Draft LLM -> Refinement Loop (LLM Judge + Vendi Calculator) -> Attribute Annotator -> Filter -> [Sanitization: Decomposer -> Target Selector -> Chunk Sanitizer -> Merger -> Instruction Generator].
- **Critical path:** Public Name -> Profile -> Record Type/Context -> Format -> Initial Draft -> Refinement Loop (max 3 iterations) -> Annotation -> Filter -> Decompose -> Select Targets -> Sanitize Chunks (per target) -> Merge -> Final Instruction.
- **Design tradeoffs:**
  - **Scale vs. Quality:** Multiple LLM backbones (GPT-OSS-120B, Qwen3-80B) improve cost efficiency and stylistic diversity but risk distributional inconsistencies.
  - **Diversity vs. Coherence:** Vendi-guided selection prevents collapse but may accept lower-quality drafts for diversity; tuning α, β is critical.
  - **Granularity vs. Tractability:** Chunk size (τ=512) balances context preservation and model performance; deviations hurt sanitization (Figure 5).
  - **Full Automation vs. Human Validation:** The pipeline is automated for scale, but manual checks (profile reality, naturalness) validate key properties.
- **Failure signatures:**
  - **Synthesis:** Low MATTR/Vendi, high cosine similarity, high rate of short/filtered records.
  - **Privacy:** Any 1K-profile sample matches a real person; exact PII strings present in records.
  - **Sanitization:** High direct leak ratio, large gap between Successful Attribute and Successful Record scores.
- **First 3 experiments:**
  1. **Ablation - Diversity Term:** Generate 500 records with full pipeline vs. without ΔVendi term. Expect ablated version to show significantly lower diversity (Vendi, MATTR) and higher similarity.
  2. **Chunk Size Sensitivity:** Run sanitization on 100 records with varying chunk sizes (128, 256, 512, 1024, 2048). Expect peak Full Success rate at τ=512, declining for other sizes.
  3. **Vanilla vs. Hard Set Transfer:** Train a 4B model on 37K vanilla training triplets. Evaluate on Vanilla and Hard test sets. Expect significant drop on Hard set, confirming its difficulty from grouped attributes and long contexts.

## Open Questions the Paper Calls Out
### Open Question 1
What are the reasons compact models (≤4B) trained on Privasis achieve SOTA performance and superior zero-shot generalization compared to larger frontier models and human-curated dataset (NaP²) finetunes? The paper attributes this to "scale and diversity" but does not isolate the contributing factors (data distribution, task formulation, capacity interactions).

### Open Question 2
How does Privasis's quantitative diversity (MATTR, Vendi) translate to *coverage* and *realism* of private information for underrepresented demographic groups and sensitive contexts (e.g., mental health, legal) compared to human-written corpora? The paper notes under-representation but does not assess cultural plausibility or bias in generated scenarios.

### Open Question 3
What are the long-term privacy risks of releasing a massive public synthetic dataset containing detailed private information, even if verified as non-memorized, through indirect avenues like membership inference, model inversion, or cross-dataset correlation? Verification was limited to web-search profile matching.

### Open Question 4
What do failures on the "Hard" test set reveal about fundamental limits of current LLMs in contextual privacy sanitization? The paper notes the hard set's difficulty (grouped attributes, long contexts) but does not analyze specific failure modes to guide architectural or algorithmic innovations.

### Open Question 5
How transferable are Privasis-derived policies and models to real-world regulations (GDPR, HIPAA) and non-English, multilingual contexts? The pipeline conceptually supports flexibility and multilingual generation, but evaluation against legal standards and cultural privacy norms is absent.

## Limitations
- Core pipeline parameters (LLM judge prompts, α/β weights, sensitivity weight formula, target selection distribution) are omitted, hindering precise replication.
- The Vendi score's correlation with human-judged semantic variety in privacy text is unverified; risk of optimizing for a flawed proxy.
- Privacy verification is limited to full-profile matching; does not assess sophisticated membership inference or correlation attacks.

## Confidence
- **Auxiliary Control Variable Steering:** Medium. Mechanism is clear but key prompts/weights are unreported.
- **Vendi-Guided Diversity Preservation:** Medium. Ablations show metric improvements, but human validation of semantic diversity is weak.
- **Decomposition-Based Sanitization:** Medium. Performance peak at τ=512 is empirical, but boundary coherence effects are inferred, not directly measured.
- **Dataset Scale & Privacy Claims:** Medium-High. Scale is specified; privacy check is basic but positive.
- **Model Performance Claims:** High. Results are clear and benchmarked against strong baselines.
