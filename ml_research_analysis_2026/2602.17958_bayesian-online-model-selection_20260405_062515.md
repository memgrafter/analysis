# Bayesian Online Model Selection
## Quick Facts
- **arXiv ID:** 2602.17958
- **Source URL:** https://arxiv.org/abs/2602.17958
- **Reference count:** 40
- **Primary result:** Introduces Bayesian Online Model Selection (B-MS) achieving a Bayesian regret bound of $\tilde{O}(d^\star M\sqrt{T} + \sqrt{M}T)$ and empirically matching the best base learner while improving sample efficiency via a shared global posterior.

## Executive Summary
The paper addresses online model selection in Bayesian stochastic bandits, where a meta-learner must dynamically choose among multiple bandit algorithms to minimize cumulative regret relative to the best fixed learner in hindsight. The authors propose the Bayesian Online Model Selection (B-MS) algorithm, which is bound‑free and uses posterior sampling to estimate each learner’s cumulative regret, selecting the one with the smallest estimate. All data updates a single global posterior, implicitly sharing information across learners. Theoretical analysis yields a Bayesian regret bound of $\tilde{O}(d^\star M\sqrt{T} + \sqrt{M}T)$, improving over frequentist $d^2$ dependence. B-MS recovers Thompson Sampling’s $\tilde{O}(\sqrt{KT})$ when each learner corresponds to a fixed arm. Experiments on multi‑armed and linear bandits show performance comparable to the best base learner, and that data sharing enhances efficiency and mitigates mild prior mis‑specification.

## Method Summary
B-MS operates in a sequential decision setting with a set of base learners. At each round, the algorithm maintains a global posterior over a shared parameter space, updated with all historical data. For each base learner, it draws a sample from the posterior and uses it to estimate that learner’s cumulative regret (a “balancing potential”). The learner with the minimal estimated regret is selected, and its action (e.g., arm pull) is executed. The observed reward is then incorporated into the global posterior. This process creates a bound‑free algorithm: the posterior sampling inherently balances exploration and exploitation without requiring explicit exploration terms. The analysis leverages the Bayesian framework to derive regret bounds that depend on the effective dimension $d^\star$ and the number of learners $M$, rather than the ambient dimension squared.

## Key Results
- Bayesian regret bound $\tilde{O}(d^\star M\sqrt{T} + \sqrt{M}T)$, improving frequentist $d^2$ dependence.
- Recovers Thompson Sampling with $\tilde{O}(\sqrt{KT})$ when each learner corresponds to a fixed arm.
- Empirical results on multi‑armed and linear bandits show performance comparable to the best individual learner, and data sharing mitigates mild prior mis‑specification.

## Why This Works (Mechanism)
B-MS works because posterior sampling provides a natural mechanism for estimating each learner’s cumulative regret while maintaining an up‑to‑date belief about the underlying reward model. The global posterior aggregates all data, so information learned while running any learner benefits all others, leading to improved sample efficiency. The estimated regret balances the potential cost of each learner, effectively combining exploration (by considering uncertainty in the posterior) and exploitation (by favoring learners with low estimated regret). The bound‑free nature eliminates the need to manually tune exploration constants, as the Bayesian posterior automatically adapts.

## Foundational Learning
1. **Bayesian Inference**  
   - *Why needed:* Provides a principled framework to quantify uncertainty over model parameters and adapt beliefs as data arrives.  
   - *Quick check:* Compute posterior p(θ|D) ∝ p(θ) ∏_{d∈D} p(d|θ).

2. **Posterior Sampling**  
   - *Why needed:* Enables efficient exploration by randomly selecting actions according to current uncertainty.  
   - *Quick check:* Draw a sample from the current posterior distribution and use it for decision‑making.

3. **Multi‑Armed Bandits**  
   - *Why needed:* Canonical model for sequential decision problems with exploration‑exploitation trade‑offs.  
   - *Quick check:* Define a set of arms, each with an unknown reward distribution; regret measures cumulative suboptimality.

4. **Linear Bandits**  
   - *Why needed:* Extends bandits to contexts where rewards depend linearly on arm features.  
   - *Quick check:* Rewards follow r = θ⋆·x + ε; learning θ via Bayesian inference.

5. **Regret Minimization**  
   - *Why needed:* Serves as the performance metric for online algorithms.  
   - *Quick check:* Compute cumulative difference between optimal arm reward and chosen arm reward over T rounds.

6. **Model Selection**  
   - *Why needed:* Allows adaptation to unknown environments by combining multiple candidate learners.  
   - *Quick check:* Maintain a set of learners, evaluate their performance online, and select the most promising one.

## Architecture Onboarding
**Component Map:** Data -> Global Posterior Update -> Regret Estimation (per learner) -> Learner Selection -> Action -> Observation -> (new Data)

**Critical Path:** For each decision round:  
(a) Update global posterior using all accumulated data.  
(b) For each base learner, draw a posterior sample and compute estimated cumulative regret.  
(c) Select the learner with minimal regret estimate.  
(d) Execute the chosen learner’s action (e.g., pull an arm).  
(e) Observe reward and append to the data buffer for the next update.

**Design Tradeoffs:**
- *Global vs Independent Posteriors:* A single posterior enables information sharing and reduces sample complexity, but may cause interference if learners assume different model classes.
- *Computational Scalability:* Regret estimation and posterior updates scale with number of learners M and model complexity; for large M the √M term in regret becomes significant.
- *Prior Sensitivity:* While data sharing helps with mild mis‑specification, strong mis‑specification can still degrade performance; robust priors or variational approximations trade off accuracy for speed.

**Failure Signatures:**
- Rapid increase in cumulative regret despite data suggests prior mis‑specification or architectural mismatch.
- Linear growth in runtime with M indicates scalability limits; consider learner pruning or parallelization.
- Frequent switching between learners without sustained improvement may signal noise in regret estimates or inadequate posterior concentration.

**First Experiments:**
1. **Synthetic Bernoulli Multi‑Armed Bandit:** Run B‑MS with base learners being Thompson Sampling with different priors; compare to individual TS and to an oracle that knows the best learner. Verify that B‑MS tracks the best learner and benefits from shared data.
2. **Linear Bandit Dimension Scaling:** Evaluate B‑MS on d‑dimensional linear bandits with increasing d; measure regret and compute effective dimension d⋆ to confirm the theoretical dependence.
3. **Global Posterior Ablation:** Implement a variant with independent posteriors per learner; isolate the contribution of data sharing by comparing regret and sample efficiency against the standard B‑MS.

## Limitations
- Theoretical analysis relies on conjugate priors and Gaussian/sub‑Gaussian noise; extension to heavy‑tailed or non‑parametric settings is open.
- The global posterior update becomes computationally intensive with many (M) or complex base learners; the √M T term may dominate for large M.
- Experiments are restricted to synthetic multi‑armed and linear bandits; performance on real‑world, non‑linear, or delayed‑feedback settings remains untested.

## Confidence
- **Bayesian regret bound $\tilde{O}(d^\star M\sqrt{T} + \sqrt{M}T)$:** Medium (proof appears sound but assumptions are strong, constants not explicit).
- **Recovery of Thompson Sampling $\tilde{O}(\sqrt{KT})$:** High (direct specialization).
- **Empirical competitiveness and data‑sharing benefit:** Medium (promising but narrow benchmarks).
- **Bound‑free property:** High (posterior sampling eliminates explicit exploration tuning).
- **Mitigation of prior mis‑specification:** Low (preliminary evidence only).
