# OfficeQA Pro: An Enterprise Benchmark for End-to-End Grounded Reasoning

## Quick Facts
- arXiv ID: 2603.08655
- Source URL: https://arxiv.org/abs/2603.08655
- Reference count: 40
- Primary result: Frontier LLMs achieve <5% accuracy using parametric knowledge and <12% with web access; state-of-the-art agents with full corpus average 34.1% correctness, best configuration 66.9%.

## Executive Summary
OfficeQA Pro introduces a benchmark for evaluating AI agents on grounded, multi-document reasoning over a century of U.S. Treasury Bulletins (89,000 pages, 26M+ numerical values). The task requires retrieving and analyzing data from a large, heterogeneous corpus with temporal revisions and embedded figures. Results show that even the most advanced LLMs struggle: parametric knowledge yields near-zero accuracy, and web access brings modest improvement. When provided the full parsed corpus, the best agent (Claude Opus 4.6 with oracle parsed documents) reaches only 66.9% correctness, averaging 34.1% across configurations. Using Databricks' `ai_parse_document` for structured representation provides a 16.1% relative gain, but substantial headroom remains across key failure modes: temporal revision handling, parsing fidelity, visual reasoning, and analytical precision.

## Method Summary
OfficeQA Pro comprises 133 complex questions that require multi-step retrieval and quantitative reasoning across the U.S. Treasury Bulletin archive. The corpus spans 89,000 PDF pages with over 26 million numerical values, many in tables that are revised over time. Agents are equipped with tools: file system search/read, web search, and a Python REPL for computation. Evaluation uses strict exact-match at 0.0% allowable relative error for numerical answers, with normalization for punctuation and fuzzy matching for text. The paper compares multiple agent systems (Claude Agent SDK, OpenAI Codex CLI, Gemini CLI) under varying conditions: full corpus vs. oracle page retrieval, raw PDFs vs. parsed documents (including Databricks’ `ai_parse_document`), and different retrieval strategies (file search, vector search, combined). Ablations test table format (HTML vs. Markdown), test-time scaling (plurality voting), and parser choices.

## Key Results
- Frontier LLMs: <5% accuracy relying solely on parametric knowledge; <12% with web access.
- Full-corpus agents: average 34.1% correctness; best (Claude Opus 4.6 + oracle parsed) 66.9%.
- Structured parsing (Databricks’ `ai_parse_document`) yields a 16.1% average relative gain across agents.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Document parsing fidelity directly determines agent retrieval accuracy and downstream analytical correctness.
- Mechanism: High-quality structured parsing preserves table hierarchies, reading order, and numerical values from heterogeneous PDFs. Low-fidelity parsing corrupts data (misread numbers, shifted rows/columns), causing agents to retrieve or compute from incorrect source values. Agent systems cannot recover from information lost during PDF-to-text conversion; their entire reasoning chain operates on the parsed representation.
- Core assumption: Once data is lost or misrepresented in the parsed corpus, no subsequent reasoning step can recover the true values.
- Evidence anchors:
  - [abstract] "Providing agents with a structured document representation produced by Databricks' ai_parse_document yields a 16.1% average relative gain across agents."
  - [section 5.2] "Agent performance is highly sensitive to parsing quality... Baseline agents using the original PDFs exhibit a 40–50% failure rate attributable to parsing errors... Even best-performing agents leveraging state-of-the-art Databricks’ ai_parse_document are impacted by parsing fidelity errors."
  - [corpus] Multiple sections detail parsing error examples (Figure 9) and ablation results showing 6.0–20.3 pp gains from using parsed docs.
- Break condition: Parsing fidelity exceeds a threshold where >99% of numerical values and table structures are correctly extracted and serialized, as verified by human annotation on a stratified sample.

### Mechanism 2
- Claim: Failure to handle temporal revisions (successive updates to the same fiscal/year statistic) is a primary error source.
- Mechanism: The Treasury Bulletins are a continuously revised archive. Agents frequently converge on the first plausible value encountered instead of the most recently published revision, even when instructed otherwise. Enforcing revision checking often triggers recursive search loops that saturate context windows.
- Core assumption: Correct answers require identifying the final, revised value from the latest bulletin, not preliminary estimates from earlier issues.
- Evidence anchors:
  - [section 5.1] "Agents frequently fail to retrieve revised values, often prematurely converging on the first numerically plausible instance retrieved... As the context window saturates, agents lose track of previously validated intermediate results."
  - [section 2.2] "Published statistics are often revised in subsequent months and years, requiring longitudinal reconciliation."
  - [corpus] Describes specific revision patterns (Figure 8) and notes this as a key remaining failure mode.
- Break condition: Agent consistently selects values from the latest bulletin date for a given metric, verified on a held-out set of questions explicitly requiring revision-aware retrieval.

### Mechanism 3
- Claim: Absence of visual figure encoding in parsed representations creates a hard barrier for questions requiring chart/graph interpretation.
- Mechanism: `ai_parse_document` and other evaluated parsers omit visual data (figures, charts). Agents therefore cannot retrieve or reason from these modalities, leading to failure on ~3% of questions that require "visual reasoning over figures, charts, or graphs." Pre-parsed representations suffer from lossy embedding conversion that dissociates visual data from semantic context.
- Core assumption: Questions involving quantitative trends or maxima/minima from plots require pixel-level or vector-level visual understanding that is lost without dedicated figure extraction and embedding.
- Evidence anchors:
  - [section 5.3] "Agents frequently fail to correctly utilize visual figures... When relying on pre-parsed documents, the retrieval pipeline also faces the bottleneck of a lossy embedding conversion that often dissociates the visual data from its semantic context."
  - [abstract] "3% require visual reasoning... substantial headroom remains... visual reasoning."
- Break condition: A parser or retrieval module successfully extracts, serializes, and makes searchable the semantic content (e.g., data points, trend lines) from embedded charts and graphs.

## Foundational Learning
- **Structured Document Parsing**: Why needed: The entire agent workflow depends on the fidelity of the initial document representation. Parsing errors propagate irreversibly through retrieval and computation. Quick check: How would a misaligned table row (e.g., a header row read as a data row) affect a sum calculation across that table?
- **Temporal Revision Awareness**: Why needed: The corpus is a time-evolving archive. Using a preliminary value instead of the final revised value yields a quantitatively incorrect answer, even if all other steps are perfect. Quick check: Given two bulletins reporting "GDP Q4 1975" as $1,200B (Jan 1976) and $1,215B (Mar 1976), which should be used for a question asking for the "final reported value"?
- **Agent Tool Use & Context Management**: Why needed: Agents must orchestrate file search, web search, and Python execution across a 89k-page corpus. Inefficient tool use leads to prohibitive latency and cost, while poor context management causes loss of intermediate results. Quick check: Why might an agent that correctly finds a table in a PDF still fail to answer a multi-step calculation question referencing that table?

## Architecture Onboarding
Corpus Parser -> Retrieval Tools -> Agent Orchestrator -> Computation Sandbox -> Evaluator

**Critical Path**: Parse Corpus → (Search/Retrieve relevant pages/sections) → (Extract & compute using Python) → (Format final answer). Any break in parsing or retrieval fatally flaws downstream steps.

**Design Tradeoffs**:
- Parsing: Cost (`ai_parse_document` vs. `unstructured.io`) vs. fidelity vs. speed. Cheaper/faster parsers introduce more errors.
- Retrieval: Precision (file search) vs. recall (vector search). File search is precise for known keywords but fails on semantic intent; contextual vector search helps but can return mid-table chunks.
- Model: Latency/Cost (Gemini Flash, GPT-5 Mini) vs. correctness (Claude Opus 4.6). Frontier models offer better reasoning but are slower/expensive.
- Test-time scaling: Plurality voting improves correctness but multiplies cost/latency linearly.

**Failure Signatures**:
- Excessive tool calls & latency: Agent brute-forcing with OCR on many pages → parsing choice failure.
- Repeated search loops with context saturation: Agent stuck trying to verify revisions → temporal reasoning failure.
- Avoiding figures / "I cannot find the data": Agent attempts to reason from text-only corpus → visual modality gap.
- Numerical mismatch by small % (0.1%-1%): Rounding cascades or using wrong formula → analytical precision failure.

**First 3 Experiments**:
1. **Parser A/B Test**: Run same agent (e.g., Claude Opus 4.6) on full corpus parsed by `ai_parse_document` vs. `Docling` vs. raw PDFs (with preinstalled OCR tools). Measure correctness, latency, cost. Expected: `ai_parse_document` wins on correctness; raw PDFs have high latency/failure.
2. **Retrieval Tool Comparison**: Using best parser, compare agent performance with (a) file search only, (b) contextual vector search only, (c) combined FS + C-VS. Expected: Combined gives best quality-cost tradeoff; pure vector search underperforms.
3. **Revision Handling Check**: Create a mini-benchmark of 20 questions explicitly requiring "most recent revised value." Run agent with default prompts vs. augmented prompt that forces a "revision check" step. Measure if correctness improves or if recursive search loops increase. Expected: Prompting alone insufficient; may increase loops without gains.

## Open Questions the Paper Calls Out
1. How can AI agents reliably identify and retrieve the most up-to-date revised values across temporal document collections without succumbing to recursive retrieval loops? Basis: Section 5.1 identifies temporal revision handling as a key failure mode where agents fail to retrieve revised values and trigger recursive loops that saturate context.
2. What document parsing architectures can minimize fidelity errors in heterogeneous corpora spanning multiple decadal formats to prevent downstream retrieval and calculation degradation? Basis: Section 5.2 shows parsing errors cause 40–50% failure rates even with advanced parsers.
3. How can agents effectively interpret and extract quantitative insights from embedded visual figures (e.g., line plots, charts) in historical documents? Basis: Section 5.3 states agents "frequently fail" on visual reasoning tasks due to lack of granular resolution and lossy embedding conversion.
4. What mechanisms can enforce precise, context-aware computational fidelity in multi-step quantitative reasoning over large corpora? Basis: Section 5.4 details analytical errors: retrieving subtly wrong values, applying incorrect formulas, ignoring rounding instructions, and performing internal calculations instead of using code.
5. Can agent architectures be optimized to reduce end-to-end latency by an order of magnitude while maintaining or improving correctness on document-intensive workflows? Basis: Section 7 notes latency remains a "major and underexplored challenge": full-corpus PDF runs average 23.6 minutes, and even with parsed documents average 3.9 minutes.

## Limitations
- Small question set (133) and limited coverage of visual reasoning (~3%) reduce statistical power and generalizability.
- Proprietary `ai_parse_document` parser prevents exact replication; open-source alternatives underperform, making the 16.1% gain parser-specific.
- Oracle page selection method undisclosed; reward function details omitted, risking reproducibility of oracle and exact match evaluations.

## Confidence
- Benchmark difficulty: High
- Parsing impact: Medium
- SOTA ceiling: High
- Failure modes: Medium
