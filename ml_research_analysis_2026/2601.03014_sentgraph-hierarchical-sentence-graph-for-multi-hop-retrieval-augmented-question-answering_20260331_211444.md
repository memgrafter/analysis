# SentGraph: Hierarchical Sentence Graph for Multi-hop Retrieval-Augmented Question Answering

## Quick Facts
- **arXiv ID:** 2601.03014  
- **Source URL:** https://arxiv.org/abs/2601.03014  
- **Reference count:** 21  
- **Primary result:** Outperforms state-of-the-art graph-based RAG methods (e.g., KGP) on four multi-hop QA benchmarks, achieving up to +4.8 EM on HotpotQA (BGE retrieval) while reducing input tokens by 29.99–45.26% via finer-grained sentence-level retrieval.

## Executive Summary
SentGraph addresses a key limitation of multi-hop retrieval-augmented question answering (RAG): fixed-length chunk retrieval introduces irrelevant context and disrupts logical evidence chains. The method constructs a hierarchical sentence-level graph offline using an adapted Rhetorical Structure Theory (RST) to model fine-grained logical dependencies (nucleus/satellite relations) and topic-level subgraphs with cross-document entity bridges. During online inference, it performs coarse vector retrieval to identify candidate anchor sentences, refines them with an LLM to assess evidence sufficiency, and expansively traverses the graph to collect complete reasoning paths. This yields more precise evidence selection and significant reductions in retrieved context length, leading to consistent improvements in exact match across HotpotQA, 2WikiMultiHopQA, MuSiQue, and MultiHopRAG.

## Method Summary
SentGraph operates in two phases. **Offline**, it ingests a document corpus to build a hierarchical graph: sentences are split and classified via LLM prompts into core (nucleus) and supplementary (satellite) roles; intra-document RST relations (e.g., conjunction, elaboration, cause) are assigned between sentences; sentences are clustered into topic-level subgraphs; and cross-document bridges are formed using shared entities or topics. **Online**, for a query, a dense retriever (e.g., BGE) fetches top-K sentence anchors. An LLM refines these anchors—filtering irrelevant nodes and judging whether the set suffices to answer. If insufficient, a breadth-first expansion follows graph edges (RST relations and topic bridges) to gather supporting sentences from connected nodes. All collected sentences form the context for an answer-generation LLM.

## Key Results
- Consistent EM/F1 gains over graph-based RAG baselines (e.g., KGP) across four benchmarks, with up to +4.8 EM on HotpotQA using BGE retrieval.
- Input token usage reduced by 29.99–45.26% compared to chunk-based methods, due to sentence-level precision.
- Ablation studies confirm the critical contribution of anchor refinement and graph-guided path expansion; randomizing RST edges causes a notable performance drop.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Reducing retrieval granularity from fixed-length chunks to individual sentences eliminates irrelevant context and enables atomic evidence selection, improving reasoning precision.
- **Mechanism:** Chunks often contain multiple sentences, only some relevant to a multi-hop chain. Sentence-level retrieval selects only semantically necessary evidence units, conserving context window and reducing contradictory noise.
- **Core assumption:** Irrelevant sentences within chunks harm LLM reasoning by consuming space and introducing distraction.
- **Evidence anchors:** Abstract and Section 1 explicitly state chunk-based retrieval provides irrelevant/logically incoherent context; neighboring work on granularity trade-offs aligns.
- **Break condition:** If core sentences are not identifiable or logical relationships between them are too weak, sentence-level benefits diminish.

### Mechanism 2
- **Claim:** Modeling fine-grained logical dependencies via adapted RST creates a structured "reasoning scaffold" that guides graph traversal toward coherent multi-hop paths.
- **Mechanism:** Offline graph uses RST to classify nucleus (core) vs. satellite (support) sentences and define relation types (N-N: conjunction/contrast; N-S: cause/elaboration). Edges represent logical support, not just semantic similarity, enabling valid reasoning trajectories during online expansion.
- **Core assumption:** Multi-hop reasoning requires logically connected hops (e.g., cause → effect), discoverable at sentence level.
- **Evidence anchors:** Section 3.1 details the adapted RST taxonomy; Section 4.5 ablation shows performance drops when RST edges are randomized.
- **Break condition:** If the LLM-based RST relation classifier is inaccurate for the domain, the logical scaffold becomes noisy and misguides retrieval.

### Mechanism 3
- **Claim:** The two-stage anchor refinement followed by adaptive path expansion efficiently identifies a minimal, sufficient evidence set, balancing coverage and precision.
- **Mechanism:** Coarse vector retrieval yields candidate anchors; an LLM referee filters anchors and evaluates evidence sufficiency. If insufficient, a BFS-like expansion traverses graph edges (RST relations, topic bridges) to find connected supports, focusing computation on promising subgraphs.
- **Core assumption:** A high-recall anchor pool can be efficiently refined and expanded within a pre-built graph to form complete chains without exhaustive corpus traversal.
- **Evidence anchors:** Section 3.2 describes coarse-to-fine strategy; Section 4.6 recall@K analysis shows high early recall (e.g., 97.2% at K=10 on MuSiQue).
- **Break condition:** If the initial dense retriever has low recall for first-hop anchors, refinement starts with an insufficient pool, and expansion cannot recover missing starting points.

## Foundational Learning
### Concept: Rhetorical Structure Theory (RST)
- **Why needed:** SentGraph’s core innovation adapts RST’s nucleus/satellite distinction and relation types (e.g., elaboration, cause) to model sentence-level logic. Engineers must understand these relation categories to interpret graph edges and design offline construction prompts.
- **Quick check:** What is the functional difference between a Nucleus-Nucleus (conjunction) and a Nucleus-Satellite (elaboration) relation in the context of evidence chaining for QA?

### Concept: Graph Traversal for Evidence Chains
- **Why needed:** Online retrieval uses BFS-style path expansion along graph edges. Engineers need to understand how traversal parameters (max path length, expansion limits) trade off coverage vs. noise and how edge weights influence path selection.
- **Quick check:** Why might a breadth-first expansion strategy be preferred over a depth-first one for discovering evidence in a sentence logic graph?

### Concept: Multi-hop QA Failure Modes
- **Why needed:** To appreciate *why* chunk-based RAG fails, one must understand typical multi-hop errors: incomplete evidence chains, irrelevant context distraction, and inability to connect weakly-related facts across documents. SentGraph directly targets these.
- **Quick check:** Give an example of a question where a retrieved passage chunk contains a relevant sentence but also many irrelevant sentences, and explain how that hurts the LLM’s answer generation.

## Architecture Onboarding
### Component map
Document Corpus -> Offline Graph Builder (Sentence Splitting → LLM Core/Satellite Classification → Intra-document RST Relation Labeling → Topic Clustering → Cross-document Entity Bridging) -> Hierarchical Sentence Graph (nodes: topic, core, satellite; edges: topic-topic, topic-core, core-core, core-satellite) -> Online Query -> Coarse Dense Retrieval (BGE) -> Top-K Sentence Anchors -> Anchor Refinement (LLM Filtering & Sufficiency Check) -> [If insufficient] Path Expansion (BFS along graph edges with similarity-based neighbor selection) -> Final Evidence Sentences -> Answer Generation (LLM) -> Predicted Answer.

### Critical path
1. Corpus documents are ingested **once** offline into the hierarchical sentence graph.
2. For each query, the system retrieves a small set of initial sentence anchors via fast vector search.
3. An LLM referee decides if these anchors are sufficient; if not, it triggers bounded graph expansion.
4. The final evidence set is the union of sentences from selected paths.
5. The answer LLM reasons over this sentence-level evidence set.

### Design tradeoffs
- **Offline Cost vs. Online Efficiency:** Graph construction is LLM-heavy but amortized; online expansion is fast but limited by graph connectivity.
- **Granularity vs. Context:** Sentence-level precision avoids noise but loses anaphoric context (“it,” “the former”). The topic hierarchy partially mitigates this.
- **Relation Coverage vs. Noise:** Simplified RST reduces complexity but may miss subtle discourse relations; trade-off between modeling power and LLM annotation reliability.

### Failure signatures
- **High recall, low final EM:** Anchor selection finds gold sentences but refinement wrongly discards them, or expansion fails to connect them to answer-supporting paths.
- **Low token reduction vs. KGP:** Graph edges are too dense or topic bridging too coarse, pulling in many unrelated sentences.
- **Ablation sensitivity:** Removing Anchor Refinement (AER) causes a large drop → initial retriever’s candidates are too noisy. Removing Path Expansion (GPE) harms performance on complex datasets (MuSiQue) → anchors alone insufficient for 3+ hop questions.

### First 3 experiments
1. **Granularity Validation:** Compare (a) chunk-passage retrieval, (b) naive sentence retrieval (no graph), (c) SentGraph on EM and average retrieved tokens. Expect (b) > (a), (c) > (b).
2. **Relation Ablation:** Build graphs with (a) full RST relations, (b) only N-N edges, (c) only N-S edges, (d) random edges. Measure EM impact. Expect (a) best, (d) worst, (b) and (c) showing complementary value.
3. **Anchor Set Sensitivity:** Vary initial anchor pool size K (e.g., 5, 10, 20, 30) and plot EM vs. K. Expect performance to rise then plateau; identify diminishing returns point.

## Open Questions the Paper Calls Out
1. **Multimodal extension:** How can SentGraph incorporate images, tables into its hierarchical graph? Current design is text-only.
2. **Cross-lingual/domain portability:** Is the adapted RST relation taxonomy portable across languages and domains with different discourse conventions? Evaluation focused on English Wikipedia.
3. **Scalability of offline construction:** What is the computational and cost profile of graph construction for very large corpora (millions of documents)? No scalability analysis provided.
4. **Traversal strategy optimality:** Are BFS-style expansions optimal, or could heuristic/learned strategies improve evidence recall and efficiency? Only similarity-driven BFS is evaluated.
5. **Task generalizability:** How well does sentence-level logical dependency modeling generalize beyond multi-hop QA (e.g., summarization, causal inference)? Evaluation is QA-specific.

## Limitations
- Offline graph construction details (exact LLM, prompts, temperature, cross-document bridging) are unspecified, hindering faithful reproduction.
- RST relation extraction depends on LLM accuracy; misclassifications introduce noise in the logical scaffold.
- Sentence-level granularity may discard coreferential context (e.g., “it,” “the former”), only partially mitigated by the topic hierarchy.
- Low citation count and neighbor field mean rate (~0.58) indicate recent, limited external validation.

## Confidence
- **Sentence-level granularity benefit:** Medium. Rationale strong and token reduction reported, but direct comparison to naive sentence retrieval (without graph) is not detailed.
- **RST-adapted logical graph:** High. Ablation shows notable drop when RST edges are randomized, confirming structured relations are critical.
- **Two-stage anchor-expansion pipeline:** High. Recall@K analysis shows high early recall; ablation of expansion (GPE) harms MuSiQue performance, supporting necessity.
- **Overall benchmark claims:** High. Consistent EM gains and token savings across four datasets are reported, though long-term robustness uncertain.

## Next Checks
1. **Anchor pool optimization sweep:** Vary initial anchor count (K=5, 10, 20, 30, 50) on all benchmarks; plot EM and token usage to identify recall plateau and optimal cost/accuracy trade-off.
2. **RST relation quality audit:** Randomly sample 200 graph edges; have human experts validate nucleus/satellite labels and relation types; compute inter-annotator agreement (target >85%) to quantify annotation noise.
3. **Cross-document bridge ablation:** Systematically remove entity/topic bridges and re-evaluate on questions requiring inter-document reasoning (e.g., HotpotQA comparison-type questions); measure EM drop to isolate bridges’ contribution.
