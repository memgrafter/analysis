# Stochastic Sequential Decision Making over Expanding Networks with Graph Filtering

## Quick Facts
- **arXiv ID:** 2603.19501  
- **Source URL:** https://arxiv.org/abs/2603.19501  
- **Reference count:** 38  
- **Primary result:** Proposes a multi-agent reinforcement learning framework for graph filtering over expanding graphs, achieving lower RMSE than batch, online, and online GNN baselines on synthetic and real-world tasks.

## Executive Summary
This paper addresses graph filtering in the setting where graphs expand over time with unknown stochastic node attachments. Existing batch and online filter update methods are myopic, optimizing only immediate prediction accuracy. The authors introduce a stochastic sequential decision-making framework that treats each filter shift as an independent agent within a multi-agent reinforcement learning (MARL) paradigm. A context‑aware graph neural network (C‑GNN) parameterizes a policy that jointly considers the current graph topology and the historical states of all agents to produce parameter updates. The policy is trained to maximize the discounted sum of long‑term rewards (negative prediction loss). Experiments on synthetic expanding graphs and two real‑world applications—cold‑start recommendation and COVID‑19 prediction—demonstrate consistent reductions in RMSE compared to baseline approaches.

## Method Summary
The method formulates expanding graph filtering as a constrained Markov Decision Process (MDP). The environment provides a sequence of graph snapshots \((A_t, x_t)\) as new nodes attach stochastically. A classical graph filter of order \(K\) is decomposed into \(K+1\) agents; each agent \(R_k\) manages one filter coefficient \(h_k\) (its state). At each time step \(t\), a shared policy \(\pi\) observes the expanded graph \((A_t, \tilde{x}_t)\) and the previous agent states \((h_{t-1,0}, \dots, h_{t-1,K})\) and outputs a vector of adjustments \(c_t\). The filter coefficients are updated as \(h_t = h_{t-1} + c_t\), and predictions for the newly attached nodes are computed using the updated filter. The immediate reward is the negative prediction loss (RMSE) on those nodes. The policy is implemented by a two‑stage C‑GNN: the first stage processes the graph to extract contextual features emphasizing the new node’s neighborhood; these features are concatenated with each agent’s state, and a second stage GNN propagates information among agents to produce \(c_t\). The policy is trained via a MARL algorithm (e.g., PPO or DDPG) to maximize the expected discounted cumulative reward, thereby learning non‑myopic updates that anticipate future graph growth.

## Key Results
- The proposed G‑MARL approach significantly lowers RMSE compared to batch filter, online filter, and online GNN baselines in synthetic experiments with Erdős–Rényi and preferential attachment expansion models.  
- Gains transfer to real‑world tasks: cold‑start recommendation on Movielens‑100K and COVID‑19 case prediction across cities, where G‑MARL again outperforms all baselines.  
- Ablation analyses (reported in the paper) confirm that both the multi‑agent decomposition and the two‑stage C‑GNN design contribute positively to performance.

## Why This Works (Mechanism)

### Mechanism 1: Multi‑Agent Representation of Filter Shifts
**Claim:** Representing each filter shift as an independent agent with its parameter as state enables modeling long‑term adaptation to expanding graphs via MARL.  
**Mechanism:** The filter order \(K\) defines \(K+1\) agents \(\{R_k\}_{k=0}^K\). Each agent’s state is its coefficient \(h_k\). A shared policy \(\pi\) generates updates \(c_t\) based on all agents’ past states and the current expanded graph context, with dynamics \(h_t = h_{t-1} + c_t\).  
**Core assumption:** Filter shifts are sufficiently independent to be separate agents, yet their joint actions affect long‑term prediction performance.  
**Evidence:** The paper explicitly defines agents and update rules (Sec. III‑A). Prior work on online graph filtering (arXiv:2409.07204) uses myopic updates, highlighting the novelty of this MARL representation.  
**Break condition:** If \(K=0\) (no shifts) or if graph expansion is deterministic and fully predictable, the added MARL complexity provides no benefit.

### Mechanism 2: Context‑Aware Policy Parameterization via C‑GNN
**Claim:** A two‑stage GNN that separately extracts graph context and then aggregates it with agent states allows the policy to make decisions informed by both topology dynamics and filter state history.  
**Mechanism:** The first GNN processes \((A_t, \tilde{x}_t)\) to produce contextual features \(\tilde{x}_t^c\) focused on the new node’s neighborhood. For each agent \(k\), these features are concatenated with \(h_{t-1,k}\) to form intermediate states \(z_{t,k}\). A second GNN operates on the agent graph (nodes = agents, edges = all‑to‑all) to propagate information among agents before outputting \(c_t\).  
**Core assumption:** The most relevant context for deciding filter updates is (a) the structure/features of the current expanded graph, especially around the new node, and (b) the historical state of each filter shift; separating these extraction stages is more effective than a monolithic model.  
**Evidence:** The architecture is detailed in Sec. III‑B and described as integrating information from both graph and agents (abstract). No prior work directly applies this specific two‑stage design to filtering, making it an untested assumption.  
**Break condition:** If graph topology is irrelevant (e.g., fully connected random features) or if agent states are constant, the second GNN stage adds unnecessary computation.

### Mechanism 3: Stochastic Sequential Optimization via MDP Formulation
**Claim:** Framing the expanding graph filter problem as a constrained MDP with discounted long‑term reward allows the policy to learn filters robust to future stochastic attachments, not just current snapshots.  
**Mechanism:** The environment state includes \((A_t, x_t)\). Transition probability \(P_e(A_t, x_t \mid A_{t-1}, x_{t-1}, a_{t-1})\) captures stochastic attachment. Reward at step \(t\) is the negative prediction loss \(-l([\tilde{y}_t]_{N_t}, x_{N_t})\). The policy \(\pi\) is trained to maximize \(\sum_{t=1}^T \gamma^{t-1} \cdot \text{reward}_t\), optimizing cumulative performance over the entire expansion sequence.  
**Core assumption:** Future graph expansion and signal dynamics follow the Markov property given the current state and last attachment, and a fixed discount factor \(\gamma\) appropriately balances immediate vs. future accuracy.  
**Evidence:** The MDP formulation is given in Sec. II‑B, including constraints and reward (6). General RL literature supports MDPs for stochastic sequences, but the specific application to expanding graph filtering is novel.  
**Break condition:** If expansion is non‑Markovian (future depends on longer history) or the planning horizon \(T\) is very short, the MDP framework’s complexity may be unnecessary.

## Architecture Onboarding

**Component map:**  
Environment Simulator → MDP Loop (Policy C‑GNN → Filter Update → Inference & Reward → Store Transition) → Policy Trainer (updates policy parameters θ) → back to Policy.

**Critical path:** The C‑GNN forward pass \((A_t, \tilde{x}_t, h_{t-1} \rightarrow c_t)\) drives the filter update and inference, producing a prediction that yields a reward. This reward is used to compute gradients and update the policy parameters θ. Successful execution depends on accurate graph context extraction by the first GNN and effective coordination among agents by the second GNN.

**Design tradeoffs:**  
- *Computation vs. Adaptability:* The two‑stage C‑GNN adds overhead compared to a single GNN but explicitly separates graph‑context extraction from inter‑agent coordination. The first GNN’s receptive field must capture sufficient multi‑hop information; the second GNN’s depth controls communication complexity among agents.  
- *Stochasticity Handling:* The MDP formulation naturally handles uncertain expansions but requires many trajectories for training. Alternatives like robust optimization may be simpler but less adaptive.  
- *Scalability:* The second GNN operates over only \(K+1\) agents, so scalability is dominated by the first GNN’s efficiency on growing graphs; linear‑time GNNs (e.g., GraphSAGE) are advisable.

**Failure signatures:**  
- *Poor reward convergence:* The policy fails to improve cumulative reward, indicating ineffective credit assignment across agents or uninformative graph context.  
- *High sensitivity to graph topology changes:* Performance drops drastically on unseen expansion models, suggesting the C‑GNN learned spurious correlations rather than generalizable topological features.  
- *Action collapse:* All agents output near‑zero updates \(c_t \approx 0\), meaning the policy did not learn to adapt, possibly due to poor reward signal or exploration failure in MARL.

## Open Questions the Paper Calls Out
- **Adaptation to other tasks:** Can G‑MARL be applied to tasks beyond signal inference (e.g., node classification), and how should rewards be designed? (The authors mention future work.)  
- **Scalability to large graphs:** How does G‑MARL perform computationally on graphs with millions of nodes? Current experiments are limited to small graphs (≤269 nodes).  
- **Robustness to model mismatch:** The method assumes a known stochastic expansion model \(P_e\); how resilient is it when the true attachment dynamics differ from the assumed one? This remains unexplored.

## Limitations
- **Real‑data reproducibility:** Key hyperparameters (filter order \(K\), GNN architecture, learning rates, discount factor \(\gamma\)) and exact stochastic attachment models for Movielens and COVID datasets are not disclosed, hindering exact replication.  
- **Component validation:** The paper attributes success to the MARL representation and C‑GNN design but lacks systematic ablations (e.g., single‑agent vs. multi‑agent, one‑stage vs. two‑stage GNN), leaving individual contributions uncertain.  
- **Assumption robustness:** The MDP formulation relies on Markovian transitions and a fixed discount factor; it is unclear whether these hold for long‑term graph evolution or if the policy overfits to specific expansion dynamics.

## Confidence
- **Overall performance claim (lower RMSE vs. baselines):** Medium (synthetic results are clear, but real‑data details missing)  
- **MARL representation (filter as multi‑agent):** Medium (conceptually sound, but no single‑agent comparison)  
- **C‑GNN architecture (context‑aware policy):** Medium (plausible design, but ablations absent)  
- **MDP optimization (discounted long‑term reward):** Medium (standard RL approach, but credit assignment over many steps not explored)

## Next Checks
