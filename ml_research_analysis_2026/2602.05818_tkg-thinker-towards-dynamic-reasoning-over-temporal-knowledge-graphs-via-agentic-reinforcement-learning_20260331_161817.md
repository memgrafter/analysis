# TKG-Thinker: Towards Dynamic Reasoning over Temporal Knowledge Graphs via Agentic Reinforcement Learning

## Quick Facts
*   **arXiv ID:** 2602.05818
*   **Source URL:** https://arxiv.org/abs/2602.05818
*   **Reference Count:** 40
*   **Primary Result:** Achieves state-of-the-art Hits@1 on MULTITQ and CronQuestions, with up to 7.60% absolute gain over prior methods and 29.70% on complex multi-step queries.

## Executive Summary
TKG-Thinker addresses temporal knowledge graph question answering (TKGQA) by framing it as a sequential decision-making problem solved via a two-stage agentic training regime. It first uses supervised fine-tuning (SFT) with chain-of-thought trajectories to teach a structured "think-plan-act" reasoning protocol and mitigate cold-start. Then, reinforcement learning (RL) with a multi-dimensional reward (outcome, format, retrieval) optimizes a policy for autonomous, temporally-grounded tool use. The agent interacts with the TKG through a discrete action space of temporal search tools (e.g., `search_before`, `search_after`). On MULTITQ and CronQuestions, it significantly outperforms prior methods, with ablations confirming the necessity of both SFT initialization and temporal-aware retrieval.

## Method Summary
The method involves a dual-training pipeline. First, an SFT stage trains the base LLM on high-quality, teacher-generated (GPT-4o) trajectories that demonstrate how to decompose temporal questions, select appropriate temporal tools, and adhere to a strict `think`/`plan`/`<observation>`/`answer` format. This establishes a competent initial policy. Second, an RL stage (using GRPO or PPO) treats the interaction as a Markov decision process. For each question, the policy generates a trajectory of thoughts, tool calls, and observations. A composite reward combines: (1) an outcome reward for exact answer match, (2) a format reward for protocol validity, and (3) a retrieval reward for evidence coverage. The policy is optimized to maximize this reward while staying close to the SFT reference via a KL penalty.

## Key Results
*   TKG-Thinker achieves state-of-the-art Hits@1 on MULTITQ and CronQuestions, with absolute gains up to 7.60% over prior methods.
*   On complex multi-step temporal queries, it shows a 29.70% absolute improvement.
*   Ablations reveal a 26.40% drop without SFT and a 39.70% drop without temporal-aware retrievers, confirming the critical role of both components.

## Why This Works (Mechanism)
The approach succeeds through three synergistic mechanisms. First, SFT with curated CoT trajectories provides a strong behavioral prior that instills the structured ReAct-style reasoning pattern, alleviating the cold-start problem for RL by ensuring initial rollouts are meaningful and follow the required protocol. Second, RL with a composite reward signal shapes the policy beyond static imitation; the multi-dimensional reward (outcome, format, retrieval) guides the agent toward trajectories that are factually correct, structurally valid, and actively seek relevant evidence, overcoming the sparsity of a pure outcome signal. Third, defining a discrete action space of temporal search tools (`search_specific`, `search_before`, `search_after`, `search_between`, `search_time`) grounds the model's temporal reasoning in explicit, executable operations over the graph. This forces explicit handling of time constraints, making reasoning traceable and reducing hallucinations caused by vague linguistic temporal expressions.

## Foundational Learning
*   **ReAct Pattern:** The agent’s `think` -> `plan`/`tool call` -> `observation` loop is a direct implementation of the ReAct framework. It is needed here to interleave internal reasoning with external, verifiable tool interactions. *Quick check:* If the `think` step fails to identify the temporal question type (e.g., "Equal Multi") and the corresponding tool, the agent will likely make an invalid or ineffective tool call.
*   **Reinforcement Learning from Verifiable Feedback (RLVR):** The RL stage uses deterministic rewards (exact match, format checks) instead of human preferences. The KL divergence term (`β·D_KL[π_θ||π_ref]`) in the objective is critical; it prevents the policy from deviating too far from the initial SFT-initialized behavior (`π_ref`) and forgetting the learned protocol during reward optimization.
*   **Temporal Knowledge Graph (TKG) Structure:** Facts are `(subject, relation, object, timestamp)` quadruples. Questions impose temporal constraints. Understanding the timestamp granularity (year, month, day) is essential because tool calls like `search_before(query, "2020-03")` and `search_before(query, "2020-03-31")` have different semantic scopes and can return different evidence sets.

## Architecture Onboarding
Base LLM -> Temporal Tool Executor -> Retriever -> Reward Calculator -> RL Trainer (Verl/PPO/GRPO). The base LLM generates all tokens for the interaction loop. The Temporal Tool Executor runs the defined search functions (e.g., `search_before` filters KG facts by timestamp). The Retriever (e.g., `e5-base-v2`) encodes queries and facts for semantic + temporal matching. The Reward Calculator computes `R_fmt`, `R_ret`, and `R_out`. The RL Trainer collects rollouts, computes advantages from `R_all`, and updates the policy.

The critical path is: 1) **SFT:** Train on trajectory tokens using cross-entropy loss to initialize `π_SFT`. 2) **RL:** For each question, `π_θ` generates a full trajectory (`think`, `plan`, tool calls, `observations`, `answer`). Tools are executed, returning structured observations. Trajectories terminate on `<answer>` or max steps (8). `R_all` is computed from the final trajectory. The policy `π_θ` is updated via PPO/GRPO with a KL penalty to `π_ref` (usually `π_SFT`). 3) **Inference:** Final `π_θ` is used with greedy decoding.

Design tradeoffs include: tool expressivity vs. simplicity (5 tools balance coverage vs. action space size); reward component weighting (sub-dominant intermediate rewards prevent over-optimization for format/retrieval at the cost of factuality); retriever choice (contrastive models like `e5` work best but add dependency); and RL algorithm (PPO vs. GRPO trade-offs in stability and sample efficiency).

Failure signatures are: invalid tool call sequences (e.g., `<answer>` before any search); temporal hallucinations (retrieved facts violate the temporal constraint due to retriever or timestamp extraction errors); reward hacking (repeated valid format but incorrect answers if `R_out` is too sparse); and infinite loops (excessive tool calls without progress if `B_max` not enforced).

**First 3 Experiments:** 1) Ablate SFT: Train RL from base model only. Expect large performance drop (~-26.40%), confirming SFT’s necessity for cold-start. 2) Ablate `plan` action: Remove the planning step, letting the agent directly use the query for tool calls. Expect a performance drop, especially on multi-step questions, showing planning’s role in decomposition. 3) Ablate temporal retriever: Replace the temporal-aware retriever with a pure semantic one. Expect a massive drop (~-39.70%), proving temporal alignment in retrieval is critical.

## Open Questions the Paper Calls Out
*   **How to reward intermediate reasoning steps?** The paper notes the lack of process feedback and suggests an LLM-as-judge reward for step-level correctness as future work.
*   **How to build benchmarks with longer temporal chains?** Current datasets have limited hops; future work needs more complex synthetic multi-hop tasks to evaluate extended temporal planning.
*   **Can TKG-Thinker handle open-world settings?** The framework assumes a static, fully observable TKG; adapting to partially observable or dynamically updating graphs is a key future direction.

## Limitations
*   Reproduction is hindered by the lack of public SFT trajectory data and exact prompt examples, requiring recreation that may introduce distribution shift.
*   Implementation details for temporal tool execution (timestamp parsing, granularity handling) are underspecified.
*   Critical RL hyperparameters (e.g., exact KL coefficient β, sensitivity of reward weights) are not fully reported, making exact replication difficult.

2.  **Tool Robustness:** Systematically test the temporal search tools (`search_before/after/between`) with edge-case timestamps (e.g., boundary dates, granularity mismatches) on MULTITQ to identify failure modes.
3.  **RL Sensitivity:** Perform a grid search over the key reward weights (α, γ, λ, δ) and KL coefficient β to map the performance landscape and confirm the stability of the reported configuration.
