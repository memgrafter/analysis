# Tokenization Tradeoffs in Structured EHR Foundation Models

## Quick Facts
- **arXiv ID**: 2603.15644  
- **Source URL**: https://arxiv.org/abs/2603.15644  
- **Reference count**: 40  
- **Primary result**: Joint event encoding and positional time encoding (RoPE on age) improved downstream performance in 73/74 and 71/74 tasks respectively, while reducing pretraining compute by 39.5% and 9.6%; workflow annotations improved local performance but did not generalize across institutions.

## Executive Summary
This paper systematically evaluates tokenization design choices for structured electronic health record (EHR) foundation models through a 2×2×2 factorial experiment pretraining transformers on pediatric data and assessing 74 downstream clinical prediction tasks. The key findings reveal that joint event encoding (fusing code and attribute into a single token) and positional time encoding using Rotary Position Embeddings (RoPE) on patient age consistently outperform alternatives across nearly all tasks while also reducing pretraining computational cost. Ablations attribute the joint encoding advantage to local binding efficiency, where pre-computing code-attribute associations avoids the need for the model to learn these relationships from limited data. External validation on an adult ICU cohort confirms that the joint encoding benefit generalizes across institutions despite substantial vocabulary mismatch, whereas temporal and workflow effects remain institution-specific. These results establish tokenization as a direct lever for simultaneously improving prediction performance and computational efficiency in EHR foundation models.

## Method Summary
The authors pretrained decoder-only transformers (28 layers, 768 hidden dimension) on a large pediatric EHR dataset (SickKids, ~2M patients, 319M events) using a factorial design manipulating three tokenization factors: event encoding (joint vs. factorized), time encoding (Time-Positions using RoPE on age vs. Time-Tokens inserting discrete intervals), and workflow annotation (with vs. without). Each configuration produced a distinct vocabulary and token sequence. Models were trained for 5 epochs with next-token prediction, using token-budget packing (32,768 tokens per batch) and causal masking per patient. Downstream evaluation used linear probes (L2-regularized logistic regression) on frozen representations for 74 clinical prediction tasks, with full-shot and few-shot settings. Ablations and external validation on MIMIC-IV (adult ICU) tested generalization. Compute efficiency was measured via pretraining FLOPs (6ND where N is non-embedding parameters, D tokens seen).

## Key Results
- Joint event encoding outperformed factorized encoding in 73/74 downstream tasks and reduced pretraining compute by 39.5% by shortening sequences and pre-computing code-attribute associations.
- Positional time encoding (Time-Positions) outperformed alternatives in 71/74 tasks and required 9.6% fewer FLOPs compared to Time-Tokens; Time-Tokens degraded performance relative to order-only encoding.
- Workflow annotations (e.g., order/collection/result stages) improved performance locally (β=0.007, p<0.001) but showed no transfer benefit to an adult ICU cohort (β<0.001, p=0.803), indicating institution-specific workflow signals.

## Why This Works (Mechanism)
### Mechanism 1: Joint Event Encoding and Local Binding Efficiency
- **Claim**: Joint event encoding (fusing code and attribute into a single token) improves downstream performance and reduces pretraining compute by pre-computing code-attribute associations, avoiding the need for the model to learn these relationships from limited data.
- **Mechanism**: Factorized encoding splits a clinical event into separate tokens (e.g., code token followed by value token), requiring the model to learn that the value token modifies the preceding code token—a local binding problem. Joint encoding combines them into one token, so the association is baked into the vocabulary. This reduces the burden on the transformer to discover context-dependent meanings from scarce pretraining data, leading to better performance with shorter sequences and less compute.
- **Core assumption**: Structured EHR pretraining data is orders of magnitude smaller than language corpora, so models cannot reliably learn all local bindings from scratch.
- **Evidence anchors**:
  - [abstract]: "Ablations traced the joint encoding advantage to local binding efficiency, that is, code-attribute pairs are combined into single tokens, rather than split across tokens that the model must learn to associate during pretraining."
  - [section]: Section 3.4 (Event Encoding Ablation) shows that the advantage persists under a Fixed-Event regime (equalizing event count) and that adding value attributes improves joint encoding but not factorized encoding (Factorized × Attributes interaction β = -0.009, P < 0.001).
- **Break condition**: If pretraining data is sufficiently large to learn all code-attribute associations reliably, or if clinical codes have context-independent attributes (e.g., absolute numeric thresholds), then joint encoding may not provide an advantage and could harm due to vocabulary explosion.

### Mechanism 2: Positional Time Encoding via RoPE on Age
- **Claim**: Positional time encoding using RoPE on patient age-in-days (Time-Positions) captures temporal relationships efficiently, outperforming explicit time tokens and providing a modest gain over sequence order alone, while using fewer tokens.
- **Mechanism**: Time-Positions maps each token’s positional index to the patient’s age in days, allowing RoPE to encode temporal distances directly without inserting extra interval tokens. This preserves sequence length and leverages the transformer’s built-in positional mechanism. Time-Tokens inserts discrete interval tokens (e.g., "5m_15m", "1d_3d") between events, fragmenting the sequence and increasing length, which degrades performance.
- **Core assumption**: Temporal proximity in age is a meaningful signal for clinical predictions and can be effectively modeled by relative positional embeddings.
- **Evidence anchors**:
  - [abstract]: "Positional time encoding ... outperformed alternatives ... while requiring ... 9.6% fewer pretraining floating-point operations."
  - [section]: Section 3.5 shows Time-Positions improves over Order-Only (β = 0.003, P < 0.001) and Time-Tokens (β = -0.003, P < 0.001). Time-Tokens degrades performance relative to Order-Only.
- **Break condition**: If the age distribution of the target population differs significantly from pretraining (e.g., pediatric vs. adult ICU), age-calibrated positional encodings become misaligned, as seen in the external evaluation where time encoding effects did not transfer. Also, if temporal dependencies are extremely long-range, RoPE’s relative encoding may be insufficient.

### Mechanism 3: Workflow Stage Annotations are Institution-Specific
- **Claim**: Workflow stage annotations (e.g., order, collection, result) improve local downstream performance because they capture process-stage information, but this benefit is institution-specific and does not generalize across hospitals due to variation in clinical workflows.
- **Mechanism**: Multi-step workflows (e.g., lab tests: order → collection → result) add informative temporal stages that are predictive locally. However, the timing and presence of these stages vary across institutions due to local EHR systems, protocols, and practice patterns. A model trained on one institution’s workflow annotations cannot leverage this signal when transferred to an institution with different or unannotated workflows.
- **Core assumption**: Clinical workflows are not standardized across institutions; thus, workflow-derived signals are not portable.
- **Evidence anchors**:
  - [abstract]: "Workflow annotations ... improved performance ... but did not generalize across institutions ... because the temporal staging of orders, collections, and results varies across institutions."
  - [section]: Section 3.6: Workflow inclusion improved SickKids performance (β = 0.007, P < 0.001) but had no significant effect on MIMIC transfer (β < 0.001, P = 0.803).
- **Break condition**: If clinical workflows become highly standardized (e.g., through common order sets and EHR configurations), workflow annotations may generalize. Alternatively, if downstream tasks are insensitive to process stages (e.g., predicting final outcomes), the local benefit may be minimal.

## Foundational Learning
### Concept 1: Tokenization design for structured EHR
- **Why needed here**: The paper demonstrates that tokenization is a critical, understudied design lever that directly impacts both performance and compute efficiency. It determines what information is preserved (e.g., code-attribute associations, temporal spacing) and what the model must learn from data.
- **Quick check question**: How does joint event encoding affect vocabulary size and sequence length compared to factorized encoding?

### Concept 2: Local binding efficiency
- **Why needed here**: This concept explains why joint encoding outperforms factorized encoding: pre-computing associations between adjacent tokens (code and attribute) solves a local binding problem that would otherwise require the model to learn context-dependent meanings from limited data.
- **Quick check question**: Why might factorized encoding struggle to learn code-attribute bindings when pretraining data is small?

### Concept 3: Positional encoding for temporal data
- **Why needed here**: Time encoding is essential for EHR models because events have timestamps. The paper shows that RoPE applied to patient age (Time-Positions) is effective, while explicit time tokens harm performance. This highlights the importance of how time is encoded, not just that it is encoded.
- **Quick check question**: What is the key difference between Time-Positions and Time-Tokens, and why does Time-Tokens degrade performance?

## Architecture Onboarding
### Component map
Data ingestion → Tokenization module → Pretraining → Evaluation

### Critical path
1. Prepare pretraining data in MEDS format; ensure timestamps and clinical codes are standardized (e.g., OMOP CDM).
2. Choose a tokenization configuration; build vocabulary from pretraining data (separate per configuration).
3. Pretrain transformer with autoregressive next-token prediction for 5 epochs (no early stopping) using token-budget packing.
4. For each downstream task, extract representations from the pretrained model for all admissions at the prediction time (using frozen weights).
5. Train and validate a linear classifier per task; report test AUROC.

### Design tradeoffs
- **Event encoding**: Joint vs. factorized. Joint gives better performance and efficiency but larger vocabulary; factorized reduces vocabulary but increases sequence length and may not learn bindings well with limited data.
- **Time encoding**: Time-Positions (RoPE on age) vs. Time-Tokens (discrete intervals). Time-Positions is more efficient and effective; Time-Tokens fragments sequences and increases compute.
- **Workflow**: Including workflow stages improves local performance but increases sequence length and compute (35.6% more FLOPs) and does not transfer across institutions.

### Failure signatures
- **Poor downstream AUROC** (<0.7 across many tasks): likely due to inappropriate tokenization choice, insufficient pretraining, or data leakage.
- **High OOV rate on external data** (>50%): vocabulary mismatch; especially severe with joint encoding if code sets differ. Consider subword tokenization or code mapping.
- **Training instability** (loss spikes, NaN): could be from incorrect packing (too many short sequences), attention masking errors, or learning rate issues.
- **No transfer gain** (SickKids-pretrained model performs worse than scratch on MIMIC): indicates overfitting to institution-specific patterns (e.g., workflow, age distribution). Try removing workflow or using age-invariant time encoding.

### First 3 experiments
1. **Replicate main factorial results**: Train all 8 tokenization configurations on a small, fixed subset of SickKids data (e.g., 1% of patients, 1 epoch). Evaluate on 2–3 sample tasks (e.g., mortality, lab abnormality) to confirm joint encoding and Time-Positions outperform.
2. **Event encoding ablation**: Run the 2×4×2 ablation (encoding × information content × sequence regime) to verify that the joint encoding advantage persists under Fixed-Event regime and is driven by the +Attributes condition.
3. **Transfer test**: Apply a SickKids-pretrained model (joint + Time-Positions, no workflow) to an external dataset (e.g., MIMIC) with frozen weights. Compare AUROC to a model trained from scratch on the external data. Expect joint encoding to transfer but time/workflow effects to diminish.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: How can temporal encodings be designed to remain robust across patient populations with substantially different age distributions, such as pediatric versus adult cohorts?
- **Basis in paper**: [explicit] ... the paper states that "developing temporal representations robust to demographic shift remains an open challenge," and finds that Time-Positions calibrated to a pediatric population did not generalize to an adult ICU cohort.
- **Why unresolved**: Current temporal encoding strategies, like age-calibrated positional embeddings, embed statistics from the pretraining population, leading to performance degradation under demographic shift. Alternative methods that decouple temporal representation from population-specific age distributions are unexplored.
- **What evidence would resolve it**: Systematic evaluation of temporal encoding variants (e.g., normalized time scales, learned temporal functions) across multiple diverse populations, measuring performance stability and identifying design principles for invariant temporal representations.

### Open Question 2
- **Question**: Does the inclusion of workflow stage annotations during pretraining harm model transferability to institutions with divergent clinical workflows, or merely provide no benefit?
- **Basis in paper**: [explicit] ... the paper notes that "whether mismatched workflow patterns between institutions could negatively affect transfer remains an open question," as workflow annotations improved local performance but did not transfer in their evaluation.
- **Why unresolved**: The study found no transfer benefit, but a neutral effect; however, if workflow patterns conflict (e.g., different stage timings), it could introduce noise or biases that degrade performance. This was not tested due to lack of workflow data in the external cohort.
- **What evidence would resolve it**: Controlled experiments simulating workflow mismatches (e.g., by artificially altering workflow stage sequences in source or target data) or multi-institution studies with detailed workflow annotations to assess transfer performance under varying degrees of workflow alignment.

### Open Question 3
- **Question**: Do the advantages of joint event encoding, attributed to local binding efficiency, persist when using data-driven tokenization methods like byte-pair encoding (BPE) that learn token merges from EHR data?
- **Basis in paper**: [inferred] ... the paper compared fixed joint vs. factorized encoding but explicitly states they "did not investigate data-driven tokenization approaches such as byte-pair encoding," leaving open how learned tokenization interacts with the binding trade-off.
- **Why unresolved**: BPE could potentially merge codes and attributes into tokens in a data-adaptive way, possibly capturing frequent associations without expanding vocabulary as much as joint encoding. This might alter the local binding problem and efficiency gains observed with predefined joint tokens.
- **What evidence would resolve it**: Implement BPE on the same structured EHR data, pretrain foundation models with BPE-derived vocabularies, and compare downstream performance and sequence lengths against the fixed joint and factorized baselines, particularly in data-limited regimes.

### Open Question 4
- **Question**: Are the tokenization trade-offs observed in discriminative linear probe evaluations consistent for generative applications of EHR foundation models, such as next-event prediction or synthetic patient trajectory generation?
- **Basis in paper**: [explicit] ... the paper restricted evaluation to "discriminative prediction tasks using linear probes" and notes they "did not evaluate generative applications," implying that tokenization effects might differ for generative objectives.
- **Why unresolved**: Tokenization determines the granularity and structure of input sequences, which could impact a model's ability to generate coherent, clinically plausible sequences. For instance, joint encoding might limit flexibility in generating attribute values independently from codes.
- **What evidence would resolve it**: Evaluate the same tokenization strategies on generative tasks using metrics like perplexity, clinical validity of generated sequences, or downstream utility of synthetic data, comparing joint, factorized, and other encodings under autoregressive or mask-based generation.

### Open Question 5
- **Question**: How do the performance and efficiency benefits of joint event encoding scale with increased model capacity and pretraining data volume, and does the local binding problem diminish with scale as suggested by the authors' hypothesis?
- **Basis in paper**: [inferred] ... the paper speculates that "compositional generalization might require larger models trained on correspondingly larger datasets," implying that the advantage of pre-computed binding might decrease with scale, but this was not tested due to fixed architecture and data size.
- **Why unresolved**: The study used a single model architecture (115.6M parameters) and one dataset; larger models with more parameters might learn code-attribute associations more effectively from factorized encoding, potentially eroding the joint encoding advantage. Conversely, efficiency gains from shorter sequences might persist.
- **What evidence would resolve it**: Train models across a range of scales (e.g., varying layers, dimensions) and pretraining data volumes (e.g., more patients or longer histories), then compare joint and factorized encoding effects on downstream task performance and pretraining compute, to identify scaling trends and threshold conditions.

## Limitations
- Vocabulary explosion and out-of-vocabulary (OOV) handling: Joint encoding creates large vocabularies; unspecified OOV processing may affect external generalization.
- Population-specific temporal encoding: Time-Positions advantage in pediatrics did not transfer to adult ICU, suggesting age-calibrated RoPE is not robust to demographic shift.
- Workflow annotation variability: Exact stage mapping differs across EHR systems; local benefits may reflect institution-specific process artifacts rather than universal clinical signals.

## Confidence
- **Joint event encoding improves performance/efficiency**: High (supported by 73/74 task wins, compute reduction, external generalization)
- **Time-Positions encoding**: Medium (consistent pediatric benefit but fails to transfer to adults; effect appears population-bound)
- **Workflow annotations improve locally but not across institutions**: High (clear local gain and null transfer)

## Next Checks
1. **OOV stress test**: Pretrain joint/factorized models on SNOMED-coded data, then evaluate on ICD-10-mapped downstream tasks with deliberate code-set mismatch; measure AUROC degradation and OOV rates.
2. **Cross-age generalization**: Pretrain Time-Positions on a mixed pediatric-adult cohort (e.g., combining SickKids and MIMIC) and test on age-stratified tasks; assess whether temporal encoding benefits extend to adults.
3. **Attention mechanism probing**: Compare attention head activations in joint vs. factorized models on code-attribute binding pairs; test if joint encoding reduces attention burden on local binding layers.
