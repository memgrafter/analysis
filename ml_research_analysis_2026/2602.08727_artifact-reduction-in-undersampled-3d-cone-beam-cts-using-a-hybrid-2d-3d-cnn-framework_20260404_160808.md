# Artifact Reduction in Undersampled 3D Cone-Beam CTs using a Hybrid 2D-3D CNN Framework

## Quick Facts
- **arXiv ID:** 2602.08727
- **Source URL:** https://arxiv.org/abs/2602.08727
- **Reference count:** 13
- **Primary result:** A hybrid 2D-3D CNN improves inter-slice consistency in undersampled cone-beam CT with moderate compute overhead vs. a pure 2D U‑Net.

## Executive Summary
This paper tackles artifact reduction in undersampled cone‑beam CT to lower radiation dose and scan time. The proposed framework uses a pre‑trained 2D U‑Net encoder to extract slice‑wise features efficiently, stacks these into a 3D volume, and processes them with a 3D decoder to enforce volumetric consistency. On 100 test volumes, the 3D decoder significantly improved inter‑slice consistency in coronal and sagittal views compared to the 2D U‑Net baseline. Quantitatively, the 2D U‑Net achieved PSNR 39.29±1.30 and SSIM 0.949±0.015, while the 3D decoder attained PSNR 38.09±1.19 and SSIM 0.938±0.016. Processing time per volume increased from 2.41±0.65 s (2D) to 20.28±5.77 s (3D). The authors argue the hybrid design balances computational efficiency with 3D contextual modeling, though the 3D decoder was trained on a much smaller dataset (150 volumes vs. 5,251+ for 2D), which may limit its performance.

## Method Summary
The method uses a two‑stage pipeline. Stage 1: Train a 2D U‑Net on individual axial slices from sparse‑view cone‑beam CT reconstructions (128 views, FDK) to predict full‑view slices. The 2D U‑Net has an encoder with five downsampling blocks (channels: 64, 128, 256, 512) and a decoder with skip connections, trained with MSE loss and AdamW. Stage 2: Freeze the 2D encoder and use it to extract multi‑level features from all slices of a volume. These 2D feature maps are stacked along the slice dimension to form 3D tensors (e.g., shape [C, N, H′, W′]). A 3D decoder, mirroring the 2D decoder but with 3×3×3 convolutions, is then trained on these stacked features (and optionally the sparse volume) to reconstruct the full‑view volume. The 3D decoder processes chunks of 48 neighboring slices during training. This hybrid approach reduces memory overhead compared to a full 3D CNN while still modeling cross‑slice context.

## Key Results
- The 3D decoder substantially improved inter‑slice consistency in coronal and sagittal views compared to the 2D U‑Net.
- Quantitative metrics: 2D U‑Net: PSNR 39.29±1.30, SSIM 0.949±0.015; 3D decoder: PSNR 38.09±1.19, SSIM 0.938±0.016.
- Processing time per volume: 3D decoder 20.28±5.77 s vs. 2D U‑Net 2.41±0.65 s.

## Why This Works (Mechanism)

### Mechanism 1
The hybrid framework reduces computational cost compared to a fully 3D CNN by decoupling expensive volumetric processing from efficient slice‑wise feature extraction. A pre‑trained 2D U‑Net encoder processes each axial slice independently in parallel, generating 2D feature maps. These maps are stacked into a 3D tensor for a single 3D decoder pass, avoiding the memory overhead of a full 3D CNN operating on raw voxel data. Core assumption: the 2D encoder extracts features expressive enough for the 3D decoder to reconstruct volumetric consistency without raw 3D context during feature extraction. Break condition: if the 2D feature maps lack critical cross‑slice contextual information that cannot be recovered by the 3D decoder, volumetric artifacts persist despite the efficiency gain.

### Mechanism 2
The 3D decoder explicitly enforces inter‑slice consistency by modeling contextual relationships across the stacked 2D feature maps. 3D convolutions with 3×3×3 kernels allow the decoder to learn smoothing and consistency constraints along the z‑axis (slice dimension). Skip connections from the stacked 2D features provide multi‑scale information for cross‑slice propagation. Core assumption: undersampling artifacts that manifest as inter‑slice inconsistencies are largely low‑frequency structural errors that can be corrected by a 3D contextual model operating on abstract features. Break condition: if artifacts are high‑frequency or slice‑specific, 3D contextual smoothing may not recover them and could blur fine details.

### Mechanism 3
Pre‑training the 2D U‑Net provides a robust feature extractor that transfers effectively to the 3D task, avoiding end‑to‑end 3D training with larger memory requirements. The 2D U‑Net is first trained in a supervised manner to map sparse‑view slices to full‑view slices. Its encoder weights are frozen and reused. The 3D decoder is then trained on the stacked features from entire volumes, decoupling the in‑plane artifact removal from volumetric harmonization. Core assumption: the features learned by the 2D encoder for in‑plane artifact reduction are a suitable and sufficient representation for the 3D decoder to perform volumetric arbitration. Break condition: if optimal features for resolving inter‑slice inconsistencies differ significantly from those for in‑plane denoising, the frozen 2D encoder becomes a bottleneck.

## Foundational Learning

- **Concept: U‑Net Architecture (Encoder‑Decoder with Skip Connections)**
  - *Why needed:* The framework relies on the U‑Net’s ability to preserve spatial details via skip connections while learning hierarchical features. The 2D U‑Net serves as feature extractor; the 3D decoder adapts this principle volumetrically.
  - *Quick check:* Why are skip connections critical in a U‑Net for medical image reconstruction tasks?

- **Concept: Cone‑Beam CT Undersampling Artifacts (Streaks, Blurring)**
  - *Why needed:* The problem is defined by artifacts from sparse‑view acquisition. Understanding their directional nature (in‑plane vs. through‑plane) motivates the hybrid approach.
  - *Quick check:* How do undersampling artifacts typically differ between axial and coronal/sagittal views in cone‑beam CT?

- **Concept: 3D CNN Memory‑Compute Trade‑off**
  - *Why needed:* The paper’s innovation addresses the prohibitive cost of full 3D CNNs for large CT volumes. Understanding GPU memory scaling (O(n³)) is key.
  - *Quick check:* If you double the resolution of a 3D input patch, approximately how does the memory requirement for a single 3D convolution layer change? Answer: increases by 8×, since volume scales with the cube of linear dimension.

## Architecture Onboarding

- **Component map:** Sparse Volume -> 2D U‑Net Encoder (frozen) -> Stacked 3D Feature Tensor -> 3D Decoder -> Reconstructed Volume.

- **Critical path:** Input volume -> process each slice with 2D encoder -> stack resulting feature maps along slice dimension -> pass stacked tensor to 3D decoder -> output volume.

- **Design tradeoffs:**
  - **Memory vs. Consistency:** Stacking more slices gives the 3D decoder more context but increases GPU memory quadratically. Paper uses 48‑slice chunks.
  - **Training Data Scale:** The 3D decoder trained on only 150 volumes due to storage costs of pre‑extracted features, compared to 5,251+ for 2D.
  - **Feature Dimensionality:** The 2D encoder’s bottleneck channel count (512) dictates the channel dimension of the 3D feature tensor, impacting decoder capacity and memory.

- **Failure signatures:**
  - Persistent vertical streaks: 3D decoder not using cross‑slice context.
  - Blurred fine details: stacked 2D features lost high‑frequency info or 3D decoder over‑smoothing.
  - Memory explosion (OOM): too many adjacent slices or high channel count.
  - No improvement over 2D U‑Net: 3D decoder too weak, insufficient training data, or frozen encoder bottleneck.

- **First 3 experiments:**
  1. **Baseline sanity check:** Run the pre‑trained 2D U‑Net on all slices of a test volume, compute PSNR/SSIM to verify they match reported ~39.29/0.949.
  2. **Validate feature stacking pipeline:** Extract features from a small batch of volumes using the frozen 2D encoder, print shapes of feature maps (N × C × H′ × W′) and stacked tensor (C × N × H′ × W′) to confirm no dimension mismatch.
  3. **Smoke‑test 3D decoder training:** Train the 3D decoder for a few epochs on a tiny subset (e.g., 5 volumes) with reduced channel count (e.g., first 64 channels). Monitor loss to ensure gradient flow and convergence.

## Open Questions the Paper Calls Out

- **Open Question 1:** Does increasing the training data size for the 3D decoder, through methods like on‑the‑fly feature extraction, significantly improve its artifact reduction performance compared to the 2D U‑Net?
  - *Basis:* The authors attribute the 3D decoder’s slightly lower PSNR/SSIM to a smaller training set limited by storage constraints and suggest that extending the training set with on‑the‑fly feature extraction could close the gap.

## Limitations
- Exact 2D U‑Net architecture details (channel counts per layer, normalization specifics) are incompletely specified, hindering precise replication.
- 3D decoder input composition and stacking protocol (which feature levels, how combined with sparse volume) are unclear.
- Training hyperparameters (learning rate, batch size, epochs) for both stages are missing, requiring guesswork.
- The 3D decoder was trained on only 150 volumes vs. 5,251 for the 2D model, potentially limiting its performance and generalizability.

## Confidence
- Computational efficiency claim: **Medium** (unclear comparison to full 3D CNN; hybrid is faster than 2D alone? not directly compared to 3D baseline).
- Inter‑slice consistency improvement: **Medium** (visual improvement but lacking quantitative cross‑slice metrics; axial PSNR is lower for 3D).
- Pre‑trained 2D encoder sufficiency: **Medium** (smaller 3D training set and 2D’s higher axial PSNR raise concerns about bottleneck).
