# LinguistAgent: A Reflective Multi-Model Platform for Automated Linguistic Annotation

## Quick Facts
- **ArXiv ID:** 2602.05493
- **Source URL:** https://arxiv.org/abs/2602.05493
- **Reference count:** 3
- **Primary result:** A reflective dual-agent LLM workflow (Annotator + Reviewer) improves token-level metaphor identification F1 scores, e.g., for Gemini-3-Flash, zero-shot F1 rose from 0.507 to 0.575.

## Executive Summary
LinguistAgent is a platform designed to automate complex semantic annotation tasks such as metaphor identification, addressing the bottleneck in humanities and social sciences. It employs a dual-agent architecture: an Annotator that produces initial labels with chain-of-thought reasoning, and a Reviewer that critiques and revises these labels, simulating a peer-review loop. The system supports multiple LLM application paradigms—prompt engineering (zero/few-shot), retrieval-augmented generation (RAG), and fine-tuning—enabling researchers to compare cost-accuracy trade-offs. In a case study on metaphor identification, enabling Reviewer Mode consistently increased token-level F1 scores across paradigms, demonstrating the efficacy of the reflective workflow for reducing hallucinations and improving annotation quality.

## Method Summary
LinguistAgent integrates LLMs into a unified annotation pipeline. Users input raw text and optionally a gold-standard annotation set and a codebook (theoretical guidelines). The platform configures the chosen paradigm: zero-shot/few-shot prompts, RAG with the codebook injected into the system prompt, or fine-tuning with a user-provided model. For each document, the Annotator agent generates a reasoning chain and XML-style span tags. If Reviewer Mode is activated, a second agent evaluates the Annotator’s output against the codebook, identifies potential errors, and produces a revised annotation. The system tokenizes both predictions and gold standard to compute token-level precision, recall, and F1 in real time. All API interactions and intermediate outputs are logged for debugging and reproducibility. A Streamlit frontend provides configuration controls, live visualizations of metrics, and a debug console for inspecting raw responses.

## Key Results
- For Gemini-3-Flash, Reviewer Mode increased token-level F1: zero-shot from 0.507 to 0.575; few-shot from 0.471 to 0.537; RAG from 0.475 to 0.581.
- The reflective architecture reduced hallucinations and improved annotation accuracy compared to single-pass Annotator-only runs.
- The platform’s monitoring framework enabled traceable error analysis through persistent logging of raw model interactions and reasoning chains.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The reflective dual-agent workflow (Annotator → Reviewer) reduces annotation hallucinations and improves accuracy by simulating a peer-review correction loop.
- **Mechanism:** The Annotator generates initial labels with chain-of-thought reasoning. The Reviewer then critiques this output against the codebook, identifies discrepancies (false positives/negatives), and issues a revised annotation. This self-correction catches errors a single pass would miss.
- **Core assumption:** A separate LLM acting as a "Reviewer" can effectively identify and correct faults in another LLM's linguistic reasoning for complex semantic tasks.
- **Evidence anchors:** Abstract shows F1 improvements; Section 2.2 describes the Review process; neighboring papers corroborate metaphor ID difficulty but not the specific architecture.
- **Break condition:** Performance degrades if the Reviewer's critique is itself flawed or prompts are misaligned with the task protocol (e.g., MIP).

### Mechanism 2
- **Claim:** Supporting multiple paradigms (Prompt Engineering, RAG, Fine-tuning) within a unified platform allows researchers to empirically find the optimal cost-accuracy trade-off for their specific linguistic annotation task.
- **Mechanism:** The system abstracts paradigm-specific implementations, enabling direct comparison. RAG injects full codebook context, few-shot provides examples, fine-tuning uses a specialized model. The same reflective workflow is applied across all, producing comparable metrics.
- **Core assumption:** No single LLM application paradigm is universally superior; the optimal choice depends on task-specific factors like data sparsity, theoretical complexity, and resource constraints.
- **Evidence anchors:** Abstract states support for three paradigms; Section 2.3 lists use cases; neighboring work shows active paradigm comparison but not the integrated approach.
- **Break condition:** Paradigm comparison becomes meaningless if the evaluation metric (token-level F1) does not align with the theoretical goals of the annotation protocol.

### Mechanism 3
- **Claim:** Integrated monitoring and debug consoles (real-time logs, persistent raw response tracking) enable traceable error analysis, critical for diagnosing failures in multi-agent LLM workflows and ensuring scientific transparency.
- **Mechanism:** The system logs every raw API interaction and model response structure (e.g., JSON). Coupled with UI displays of the Annotator's "Reasoning" field, researchers can pinpoint failure origins (prompt gap, model limit, agent flaw).
- **Core assumption:** Black-box LLM failures in sequential agent pipelines are diagnosable through structured logging and exposure of intermediate reasoning, necessary for reproducible humanities research.
- **Evidence anchors:** Section 2.5 describes the Monitoring framework; Section 3.2 notes Structured Output Control; neighboring work does not address this.
- **Break condition:** Debugging efficacy diminishes if models obfuscate reasoning or logs become too large for manual review.

## Foundational Learning
- **Token-Level Sequence Labeling Evaluation (Precision, Recall, F1):** Needed because annotation output is XML-tagged spans; performance is measured by comparing predicted token sequences to human gold standard at token granularity. Understanding harmonic mean (F1) is key to interpreting improvements.  
  *Quick check:* "If a model tags 10 metaphorical tokens correctly (TP), misses 5 (FN), and wrongly tags 3 non-metaphorical tokens (FP), what are its Precision, Recall, and F1?" (Answer: P = 10/(10+3)=0.769, R = 10/(10+5)=0.667, F1 = 2*(P*R)/(P+R)=0.714)

- **Chain-of-Thought (CoT) Prompting:** The Annotator is instructed to output a "Reasoning" field that justifies each tagging decision before final labels. This CoT is displayed in real-time and critiqued by the Reviewer, forming the basis of the reflective mechanism.  
  *Quick check:* "How might requiring an LLM to verbalize its reasoning step (e.g., 'Contextual meaning X differs from basic meaning Y') affect its final metaphorical span prediction, compared to just asking for tags?" (Answer: CoT can improve accuracy by forcing the model to articulate intermediate steps, reducing snap judgments; it also provides a trace for the Reviewer to critique.)

- **Retrieval-Augmented Generation (RAG) for Theoretical Context:** The RAG paradigm integrates the entire "Codebook" (e.g., MIP guidelines) into the system prompt, testing whether full theoretical context improves annotation adherence over prompting alone.  
  *Quick check:* "What is a key risk of using RAG with a dense theoretical codebook, and how might the Reviewer agent's role help mitigate it?" (Answer: Risk: overwhelming context may cause the model to ignore or misapply guidelines; the Reviewer can catch misalignments by critiquing against the same codebook, providing a second pass to enforce consistency.)

## Architecture Onboarding
**Component map:**  
Streamlit Frontend -> Backend Logic -> Annotator Agent -> Reviewer Agent (optional) -> Evaluation Engine; Monitoring intercepts all steps and logs raw API interactions.

**Critical path:**  
1. User uploads raw text, gold standard, and optional codebook.  
2. System selects paradigm and configures agent prompts.  
3. Annotator generates CoT + XML tags for each document.  
4. If enabled, Reviewer critiques and revises the annotation.  
5. Final tags compared to gold standard → update cumulative metrics.  
6. All steps logged; UI updates in real time.

**Design tradeoffs:**  
- Simplicity vs. Flexibility: Streamlit enables rapid, code-free UI but may limit complex frontend logic or large-scale batch processing scalability.  
- Cost vs. Latency: Dual-agent + long context (RAG) increases token cost and latency versus single-agent zero-shot; heterogeneous model selection adds integration complexity.  
- Generality vs. Task Fit: XML tagging is flexible for span labeling but may not suit relational annotations or other schema types.

**Failure signatures:**  
- **JSON Parse Errors:** Likely from model exceeding `max_tokens` or not conforming to enforced JSON structure; check debug console for truncation or error codes, increase `max_output_tokens`.  
- **Consistently Low F1 Across Paradigms:** Suggests misalignment between prompts and task protocol (e.g., MIP) or inadequate model capability; revisit instructions or select a more capable model.  
- **Reviewer Degrades Performance:** Indicates a flawed Reviewer prompt (e.g., over-conservative) or model mismatch (Reviewer weaker than Annotator); adjust prompts or use a more powerful model for review.  
- **High API Error Rates:** Quota limits, network timeouts, or provider issues; visible in debug logs; verify API keys and quotas.

**First 3 experiments:**  
1. **Baseline Zero-Shot (Reviewer Off):** Establish a performance floor with a capable model using only core instruction; assess task feasibility without examples or external context.  
2. **Enable Reviewer Mode (Same Model):** Directly test the reflective mechanism's impact on the baseline; check whether the critique step recovers missed metaphors or reduces false positives.  
3. **Paradigm Swap (RAG With Codebook):** Activate RAG, upload a codebook, and compare to baseline zero-shot; evaluate if explicit theoretical context improves protocol adherence.

## Open Questions the Paper Calls Out
1. How can the integration of standard RAG and Fine-tuning procedures with the reflective dual-agent workflow be optimized to improve annotation accuracy and efficiency? (Future work mentioned in conclusion.)
2. What is the impact of "Human-in-the-loop" verification on the performance, efficiency, and researcher trust in LinguistAgent's automated annotations? (Future direction proposed.)
3. Does employing heterogeneous LLM models for Annotator and Reviewer roles (e.g., different models for initial tagging and critique) enhance annotation quality over using identical models? (Inferred from architecture supporting independent model selection; untested.)
4. How generalizable is the reflective dual-agent workflow to other complex linguistic annotation tasks beyond metaphor identification, such as discourse analysis or semantic role labeling? (Inferred from single-task case study.)

## Limitations
- **Reflective Workflow Efficacy:** Evidence relies on self-reported experiments; no independent verification that the Reviewer's critiques specifically target hallucinations or that gains translate to real-world reliability.  
- **Paradigm Comparison Validity:** Based on one case study; token-level F1 may not fully capture theoretical goals of protocols like MIP, which emphasize discourse-level interpretation.  
- **Debugging Framework Utility:** A novel design claim without external validation; its practical impact on reproducibility depends on model providers' willingness to expose coherent reasoning.
