# MoBiQuant: Mixture-of-Bits Quantization for Token-Adaptive Elastic LLMs

## Quick Facts
- **arXiv ID**: 2602.20191
- **Source URL**: https://arxiv.org/abs/2602.20191
- **Reference count**: 38
- **Primary result**: MoBiQuant enables elastic LLM inference with token-adaptive quantization, matching static PTQ performance across 2–6 bits and achieving up to 2.7× speedup on NVIDIA A100.

## Executive Summary
Post-training quantization (PTQ) for large language models is typically fixed to a single bit-width, and changing precision at runtime requires recalibration due to token-level outlier migration—the phenomenon that tokens causing high error vary across bit-widths. MoBiQuant introduces a mixture-of-bits framework that decouples weight quantization from token sensitivity. Its core components are MoBiSlice, which recursively decomposes full-precision weights into composable 2-bit residual slices, and MoBiRoute, a lightweight router that selects slices per token based on learned sensitivity. This design allows dynamic adjustment of effective precision by simply varying a threshold on router scores, without any recalibration. Evaluations on LLaMA2 and LLaMA3 models show that MoBiQuant attains perplexities comparable to or better than the best static PTQ across a wide 2–6 bit range, reduces outlier migration, and delivers up to 2.7× speedup on A100 GPUs. The method also generalizes robustly to unseen bit-widths and remains stable across different calibration datasets.

## Method Summary
MoBiQuant employs two intertwined mechanisms: recursive residual quantization (MoBiSlice) and a token-aware router (MoBiRoute). In MoBiSlice, each weight matrix is split into a shared most-significant-bit (MSB) slice and several 2-bit residual slices. The MSB slice is calibrated using learned clipping (LWC) and elastic transformations (LET). Residual slices inherit quantization parameters from the MSB slice via floor-aligned mapping, ensuring that summing any number of slices exactly reconstructs the original weight at the corresponding effective bit-width (e.g., two 2-bit slices yield 4-bit precision). MoBiRoute processes token activations through a small MLP to produce per-token scores for each residual slice. A differentiable gating function with temperature annealing yields binary selection masks, and a budget-aware regularization term guides training toward a target average bit budget. The entire system is optimized layer-wise: first the MSB slice is stabilized, then residual slices and router are jointly trained to minimize reconstruction error under the bit constraint. After calibration, the router’s threshold can be tuned at runtime to achieve any effective precision within the supported range, enabling elastic inference without further tuning.

## Key Results
- MoBiQuant matches or exceeds static PTQ performance (e.g., 7.31 perplexity on WikiText2 for LLaMA3-8B at ~4-bit average bits) across a 2–6 bit elasticity spectrum.
- Token outlier migration is significantly reduced, as evidenced by lower correlation of token errors across different bit-widths.
- The approach yields up to 2.7× speedup on NVIDIA A100 GPUs compared to full-precision inference, and generalizes well to unseen bit-widths and varied calibration datasets.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: MoBiSlice’s recursive residual quantization creates composable bit-slices that allow seamless precision switching without recalibration.
- **Mechanism**: A full-precision weight matrix is decomposed into a shared most-significant-bit (MSB) slice and successive residual slices, each quantized at a fixed low bit-width (e.g., 2-bit). Residuals are iteratively quantized using floor-aligned mapping and scale refinement, ensuring that summing a subset of slices exactly reconstructs the weight at a higher effective precision (e.g., 4-bit from two 2-bit slices).
- **Core assumption**: The residual quantization parameters (scale, zero-point) are derived from the MSB slice and fixed across precisions, guaranteeing that lower-precision codes are nested subsets of higher ones (truncation-ready).
- **Evidence anchors**:
  - [abstract]: "recursive residual quantization (MoBiSlice) to decompose weights into composable bit slices"
  - [section 4.1]: Formal recursive decomposition and Eq. (2)-(3) for slice composition.
  - [appendix B]: Mathematical derivation of floor-aligned mapping and error bounds showing truncation preserves MSB bits.
- **Break condition**: If residual slice accumulation introduces drift or non-zero bias due to asymmetric quantization ranges or incompatible scaling, the composable property fails, requiring per-precision recalibration.

### Mechanism 2
- **Claim**: MoBiRoute’s token-aware router mitigates precision-dependent outlier migration by dynamically assigning bit-slices per token based on learned sensitivity.
- **Mechanism**: A lightweight MLP router takes token activations and outputs scores for each bit-slice. A differentiable gating function with temperature annealing learns binary selection masks. During training, a budget-aware regularization term (Eq. 8) forces the router to explore various slice combinations and converge to token-adaptive routing that matches a target average bit-width.
- **Core assumption**: Token-level quantization sensitivity (i.e., contribution to error) is non-uniform and varies with bit-width; routing based on sensitivity generalizes across unseen precisions.
- **Evidence anchors**:
  - [section 3]: Figures 1-2 and analysis showing outlier migration—tokens that are outliers at one bit-width are not necessarily outliers at another.
  - [section 4.2]: Router design with gating function (Eq. 5-7), regularization (Eq. 8-9), and target bit scheduling.
  - [section 5.3]: Figure 5 showing reduced outlier migration with MoBiQuant; Figure 6 showing heterogeneous token precision assignments.
- **Break condition**: If the router learns to ignore sensitivity (e.g., routes all tokens identically) or overfits to the calibration distribution, it fails to generalize to new tokens or bit-widths, re-introducing outlier issues.

### Mechanism 3
- **Claim**: Joint optimization of MoBiSlice parameters and MoBiRoute enables elastic inference that matches static PTQ performance across a range of bit-widths without repeated calibration.
- **Mechanism**: During layer-wise PTQ, the MSB slice parameters are first stabilized to match full-precision outputs. Then, residual slices and router are jointly trained to minimize reconstruction error (L2 between quantized and full-precision outputs) plus the routing regularization. This aligns slice contributions with token-sensitive routing decisions.
- **Core assumption**: A single set of quantization parameters (Θ_q,r) can serve multiple precisions if residual slices are properly aligned and routing decisions are token-adaptive.
- **Evidence anchors**:
  - [section 4.3]: Joint optimization objective (Eq. 10) and layer-wise calibration strategy.
  - [section 5.2]: Table 1 and Figure 4 showing MoBiQuant matches or surpasses static PTQ at unseen bit-widths (e.g., 2-6 bit) on LLaMA models.
  - [section 5.5]: Kernel implementation achieving up to 2.7× speedup on A100, demonstrating practical elasticity.
- **Break condition**: If the joint loss landscape is non-convex or the router regularization conflicts with reconstruction, training may converge to a suboptimal solution where either slice accumulation or routing fails, causing performance collapse at certain bit-widths.

## Architecture Onboarding
- **Component map**:
  - MoBiSlice: Recursive quantizer producing E bit-slices per linear layer (default: four 2-bit slices). Shared MSB slice (W1) always active; residual slices (W2–W4) optional.
  - MoBiRoute: Router MLP producing T×E score matrix S per token sequence. Gating function G(S) converts scores to binary mask for slice selection.
  - Kernel layer: Bit-major packing, token permutation for coalesced memory access, and stream-based BMMA for parallel slice execution.
  - Calibration loop: Layer-wise optimization alternating between MSB stabilization and joint MoBiQuant training (Algorithm 1).
- **Critical path**: During PTQ, for each layer: (1) compute FP reference output; (2) initialize and train MSB slice; (3) derive residual slices from MSB parameters; (4) train router with regularization; (5) commit quantized parameters and propagate quantized activations. Routing thresholds are calibrated post-training per layer for target bit-width control.
- **Design tradeoffs**:
  - *Slice granularity*: More slices (E) or smaller bit-width per slice enable finer elasticity but increase router complexity and memory for slice storage.
  - *Router capacity*: A larger MLP may better model token sensitivity but risks overfitting calibration data and adds latency.
  - *Calibration data*: Performance is robust to dataset choice (Table 2), but extreme distribution mismatch may still degrade router generalization.
- **Failure signatures**:
  - High outlier migration persists: Token error distribution remains bit-width-dependent (analogous to Figure 2), indicating router failed to learn sensitivity.
  - Router collapse: Most tokens select identical slice counts (e.g., all use only MSB or all use all slices), visible in Figure 6 as a spike at one precision.
  - Kernel inefficiency: Speedup <1× over FP16 due to poor memory coalescing from token permutation or underutilized streams; check bit-major packing alignment.
- **First 3 experiments**:
  1. **Slice reconstruction verification**: For a single layer, compute weight reconstruction error at various effective bit-widths (summing top-k slices). Error should decrease monotonically with more slices and be ≤ quantization step size (Appendix B).
  2. **Router sensitivity test**: Visualize token-wise router scores S vs. token quantization error (without routing) for calibration data. Expect negative correlation: high-error tokens should receive higher scores to activate more residual slices.
  3. **Elasticity sweep**: For a calibrated model, vary target bit-width (e.g., 2–6 bit) and measure perplexity. Performance should be smooth and near-optimal across the range (Figure 4), with no sharp degradation at intermediate points.

## Open Questions the Paper Calls Out
- **Outlier migration beyond LLaMA**: The paper only evaluates on LLaMA models; it is unknown whether token outlier migration is a universal phenomenon across architectures (e.g., T5, Mixtral).
- **Target bit independence**: Performance varies with the training target bit; it is unclear whether a single training procedure can yield uniform accuracy across all bits without manual tuning.
- **Optimal slice widths**: The default uniform 2‑bit slices may not be optimal; alternative non‑uniform bit allocations could improve elasticity-performance trade-offs.
- **Router overhead**: The computational cost of the MoBiRoute router has not been isolated in speedup measurements and may impact inference latency, especially for long sequences.

## Limitations
- Evaluation is limited to the LLaMA family; generalizability to other architectures (e.g., encoder‑decoder, mixture‑of‑experts models) is not demonstrated.
- Hyperparameter details (regularization weight λ, learning rates, router architecture) remain vague, making exact reproduction difficult.
- Router robustness to domain shifts and extreme outliers is unproven, and kernel speedup analysis lacks sufficient detail for independent verification.
