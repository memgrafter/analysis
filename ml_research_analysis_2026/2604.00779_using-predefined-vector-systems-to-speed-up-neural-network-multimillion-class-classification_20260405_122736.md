# Using predefined vector systems to speed up neural network multimillion class classification

## Quick Facts
- arXiv ID: 2604.00779
- Source URL: https://arxiv.org/abs/2604.00779
- Reference count: 15
- Primary result: Reduces label prediction complexity from O(n) to O(1) using predefined VD_n vector systems, achieving up to 11.6× speedup on 30M classes with identical accuracy and enabling novel class detection.

## Executive Summary
This paper tackles the O(n) computational cost of label prediction in neural networks for massive classification tasks. By configuring the latent space with predefined VD_n vector systems—where each class center is a vector with exactly *m* ones and *k* negative ones—the nearest class center can be found by extracting the indices of the *m* largest and *k* smallest embedding components via a top‑k operation. This reduces search to O(1) time, independent of the number of classes. Experiments on Vision Transformer (ViT‑S) models across datasets with up to 100 million classes confirm that the method yields predictions identical to cosine similarity search while delivering up to 11.6× total acceleration under GPU memory constraints. Moreover, unused vectors in the VD_n system can signal the presence of novel classes, offering a built‑in mechanism for open‑set recognition.

## Method Summary
The method combines latent space configuration (LSC) during training with a fixed index‑based lookup at inference. First, a predefined VD_n system (e.g., V22_n) is generated to serve as desired class centers. The neural network (e.g., ViT‑S) is trained with an angular loss that forces the normalized embeddings of each class to converge to one of the VD_n vectors. This LSC process does not alter the classification accuracy relative to a standard cosine‑similarity baseline. After training, the set of VD_n vectors is processed once to build a dictionary mapping the sorted tuple of a vector’s top‑*m* and bottom‑*k* indices to its class label. During inference, for a given embedding, the algorithm extracts its top‑*m* and bottom‑*k* indices (via two `topk` calls), forms the same tuple, and performs an O(1) dictionary lookup to retrieve the predicted label. If the tuple is not found (i.e., corresponds to an unlabeled VD_n vector), the system may either return a special “novel” flag or fall back to a secondary search.

## Key Results
- O(1) label prediction complexity: replacing full cosine similarity with fixed‑k index extraction reduces search time from linear to constant in the number of classes.
- Accuracy parity: Across datasets (including synthetic ones with up to 100 M classes), the method produces exactly the same top‑1 accuracy as cosine similarity.
- Significant speedup: For 30 M classes and a batch size of 256, total inference time per 1 M images improves by a factor of 11.6, with the search component becoming negligible.

## Why This Works (Mechanism)
### Mechanism 1: O(1) search via index extraction
**Claim:** Label prediction complexity reduces from O(n) to O(1) by replacing full cosine similarity search with a fixed‑k index extraction.  
**Mechanism:** In a latent space configured with a VD_n vector system (vectors having exactly *m* ones and *k* negative ones), the closest class center to a normalized embedding is the VD_n vector whose ones occupy the *m* largest embedding coordinates and whose negative ones occupy the *k* smallest coordinates. Finding these indices via `topk` is O(d) in the embedding dimension, which is constant during inference.  
**Core assumption:** The training procedure successfully aligns class centers with the predefined VD_n geometry and embeddings are L2‑normalized.  
**Evidence anchors:**  
- [abstract] “By using predefined VD_n vector systems for latent space configuration, closest class center search is reduced to O(1) via top‑k and bottom‑k index extraction from embeddings.”  
- [section 2.2] Theorem 1 mathematically proves that this index‑based search is equivalent to cosine similarity under the VD_n structure.  
- [corpus] Neighboring LSC literature provides indirect support for the feasibility of latent space geometry control.  
**Break condition:** If LSC training does not converge to the target geometry, the extracted indices may not point to the true cosine‑maximum center, leading to accuracy loss.

### Mechanism 2: Novel class detection
**Claim:** Unused vectors in the VD_n system allow the model to signal the presence of previously unseen classes.  
**Mechanism:** The VD_n system contains more vectors (*n_vects*) than there are labeled classes (*n_classes*). A query that maps to an unlabeled center (i.e., its top‑*m* / bottom‑*k* tuple is not in the dictionary) indicates that its embedding lies in a region of the hypersphere that was not assigned a known label, suggesting a potential new class.  
**Core assumption:** Real‑world data distributions include novel categories that form coherent clusters near an unlabeled VD_n center.  
**Evidence anchors:**  
- [abstract] “The proposed method also has unique properties which allow to predict the existence of new classes.”  
- [section 4.2] A toy example (Figure 2) illustrates how queries near an unlabeled center (IV) suggest a new class (cats) while a conventional classifier would mis‑assign them.  
- [corpus] No external validation; this capability remains a theoretical proposal.  
**Break condition:** If novel data is noisy, non‑clustered, or the number of unlabeled vectors is too small (due to high label coefficient *k_l*), the signal may be absent or ambiguous.

### Mechanism 3: Accuracy preservation
**Claim:** The method does not degrade training accuracy relative to a standard cosine‑similarity classifier.  
**Mechanism:** LSC training uses the VD_n centers as targets (via a specific angular loss) but does not modify the classification loss itself. Theorem 1 ensures that the index‑based inference is mathematically equivalent to cosine similarity with the same centers. Hence, decision boundaries are identical.  
**Core assumption:** The LSC loss can successfully drive embeddings into the desired VD_n geometry without harming the model’s representational capacity.  
**Evidence anchors:**  
- [section 1] “We show that the proposed method does not change NN training accuracy computational results.”  
- [section 3.1] Table 1 reports exactly matching top‑1 accuracies between the new method and cosine similarity across multiple datasets.  
- [corpus] Prior LSC studies [3,5,6] provide empirical support for geometry control.  
**Break condition:** Poor LSC hyperparameters, insufficient model capacity, or data incompatibility could cause the latent space to deviate from the VD_n structure, breaking the equivalence in practice.

## Foundational Learning
- **Concept: Predefined Vector System Geometry (VD_n)**  
  The VD_n system (e.g., V22_n) consists of vectors in ℝ^D with exactly *m* entries equal to +1, *k* entries equal to –1, and the rest 0. The notation Vmk_n denotes these parameters. The total number of vectors *n_vects* is given by a combinatorial formula.  
  *Why needed:* The entire index‑based mechanism depends on knowing that class centers have this exact sparse structure; this guarantees a unique mapping between a center and its sorted top‑*m* / bottom‑*k* indices.  
  *Quick check:* For V22^48 (i.e., *n*=48, *m*=2, *k*=2), what is *n_vects* and what are *m* and *k*?

- **Concept: Angular/Cosine Similarity Metric**  
  Cosine similarity measures the angle between two vectors; the method assumes normalized embeddings so that dot product equals cosine. An angular loss (e.g., cosine loss, additive margin) is used during LSC training to align embeddings with target VD_n vectors.  
  *Why needed:* Theorem 1 relies on an angular metric; the index extraction trick only works when similarity is based on direction, not magnitude.  
  *Quick check:* Why is a cosine loss preferred over standard cross‑entropy during LSC training?

- **Concept: Hash Map Lookup (Dictionary)**  
  After generating VD_n centers, a dictionary (`center_dict`) is built that maps the sorted tuple of a center’s top‑*m* and bottom‑*k* indices to its class label. At inference, the same tuple from the query embedding is used to retrieve the label in O(1) time.  
  *Why needed:* The dictionary provides constant‑time label retrieval after index extraction, completing the O(1) pipeline.  
  *Quick check:* What is the memory trade‑off when `center_dict` grows with *n_vects*, and why might “chunking” be necessary?

## Architecture Onboarding
**Component map:**  
Pretrained NN Encoder -> Vector System Repository -> Preprocessing Module -> Inference Engine

**Critical path:**  
1. Offline: Generate the VD_n system *C* for chosen *n* and *D*. Compute each center’s sorted top‑*m* and bottom‑*k* indices and store the mapping to labels in `center_dict`.
2. Online (per batch): Pass images through the encoder to obtain normalized embeddings *z*. Use `torch.topk` to extract the indices of the *m* largest and *k* smallest values in *z*. Sort these indices to form a tuple and look it up in `center_dict`; the retrieved label is the prediction. If the tuple is absent, optionally invoke a fallback.

**Design tradeoffs:**  
- **Memory vs. Generalization:** Picking the minimal *D* (embedding dimension) that satisfies *n_vects* ≥ *n_classes* maximizes the label coefficient *k_l* (fewer unlabeled vectors) for cleaner decision boundaries but limits coverage of the hypersphere. Combining multiple projected VD_n systems (Eq. 6) improves coverage at the cost of searching several dictionaries.
- **Speed vs. Practicality:** The O(1) lookup is only fast if `center_dict` fits in RAM; for extreme *n_vects*, chunking or approximate mechanisms add overhead.  
- **Batch size independence:** Unlike batched matrix multiplication for cosine similarity, the index‑based method’s latency is nearly constant across batch sizes, making it advantageous when GPU memory forces small batches.

**Failure signatures:**  
- High rate of unlabeled center returns → either *D* is too large (many unused vectors) or the data truly contains many novel classes.
- Accuracy drop compared to cosine baseline → LSC training failed; embeddings do not follow the VD_n geometry.
- Dictionary lookup misses → either the tuple generation is incorrect or the dictionary was built with wrong parameters (e.g., mismatched *m*,*k*).

**First 3 experiments (for validation):**  
1. **Accuracy Parity Test:** Train a ViT‑S on a medium‑scale dataset (e.g., 50 k classes) with LSC. Compare top‑1 accuracy between the index‑based method and full cosine search; they must match exactly.  
2. **Breakpoint Scaling Test:** Fix a batch size (e.g., 256) and scale *n_classes* from 1 M to >30 M. Measure search time *t_c* (cosine) and *t_n* (index‑based). Verify that *t_c* grows linearly while *t_n* remains flat, and compute the speedup factors *K_s* and *K_t*.  
3. **Extreme Class Test:** Attempt inference with over 100 M classes. Confirm that the index‑based method completes successfully (memory‑bounded) whereas a naive cosine‑similarity search fails (OOM or prohibitive time).

## Open Questions the Paper Calls Out
1. **Reliability of novel class detection:** How accurately can the method identify truly unseen classes in real‑world streams, and what are its precision/recall under varying query densities? The paper only provides a toy example and calls for further verification.
2. **Parameter selection guidelines:** What systematic framework exists for choosing the vector system parameters (*D*, *n* and projections) to balance hypersphere coverage, accuracy, and speed for different tasks? The paper notes this as future work.
3. **Comparison to approximate nearest neighbor methods:** How does the O(1) approach stand against state‑of‑the‑art ANN techniques (e.g., HNSW, product quantization) in terms of latency, memory, and accuracy trade‑offs? The experiments only compare to brute‑force cosine similarity.
4. **Generalization across architectures and modalities:** To what extent can LSC with VD_n be applied to CNNs, large transformers, or non‑vision data (text, audio)? The paper’s experiments are limited to ViT‑S on image datasets.

## Limitations
- **Scalability of VD_n generation:** The combinatorial explosion of VD_n vectors at high dimensions (e.g., for 100 M classes) is not addressed; efficient generation algorithms are needed.
- **Missing training details:** The exact LSC loss, hyperparameters, and pretrained ViT‑S checkpoints are not provided, hindering faithful reproduction of the required latent geometry.
- **Unvalidated new‑class detection:** The novel‑class signal is supported only by a toy example; its practical utility and error rates remain unknown.
