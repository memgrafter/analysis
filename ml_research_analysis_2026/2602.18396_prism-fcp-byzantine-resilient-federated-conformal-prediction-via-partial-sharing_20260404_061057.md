# PRISM-FCP: Byzantine-Resilient Federated Conformal Prediction via Partial Sharing

## Quick Facts
*   **arXiv ID:** 2602.18396
*   **Source URL:** https://arxiv.org/abs/2602.18396
*   **Reference Count:** 40
*   **Primary Result:** A federated conformal prediction framework that maintains nominal coverage under Byzantine attacks while drastically reducing interval width and communication overhead via partial parameter sharing and histogram-based filtering.

## Executive Summary
PRISM-FCP addresses the challenge of providing reliable uncertainty quantification in federated learning (FL) settings where some clients may be malicious (Byzantine). It proposes a two-pronged defense: during local model training, clients only share a small, random subset of their model parameters (M out of D), which inherently limits the adversarial impact on the global model. During the subsequent conformal calibration phase on the server, a robust histogram-based filtering mechanism uses client-local nonconformity scores to identify and exclude Byzantine clients before computing the final prediction quantile. This end-to-end approach aims to produce tight, valid prediction intervals even in the presence of attacks.

## Method Summary
The framework operates in two distinct phases. In the **training phase**, each client trains a local model on its private data. Instead of transmitting all D parameters to the server, each client randomly selects and uploads only M parameters. The server aggregates these partial updates (e.g., via median or trimmed mean) to update the global model, repeating this process. This partial sharing acts as a first line of defense, as an adversary's ability to corrupt the global model is reduced by a factor of M/D. In the **calibration phase**, clients compute local nonconformity scores on a held-out validation set using their latest model. They send these score distributions (as histograms) to the server. The server then computes a "maliciousness score" for each client based on the pairwise distance between its histogram and the median histogram. Clients with maliciousness scores above a threshold are flagged as Byzantine and excluded. Finally, the server aggregates the nonconformity scores from the remaining (presumably honest) clients to compute the global conformal quantile, which is used to construct prediction intervals for future test points.

## Key Results
*   **Robust Coverage:** Maintains nominal coverage (~90%) under various attack types (e.g., coverage attacks) on synthetic and UCI Superconductivity data, where standard FCP fails.
*   **Drastically Reduced Interval Width:** Under a coverage attack, PRISM-FCP's interval width is 0.91 vs. 1.68 for Rob-FCP and 7.67 for standard FCP.
*   **Efficiency Gains:** With a partial sharing ratio M/D=0.25, communication is reduced by 75% and training mean-square error improves by ~5 dB compared to full sharing under attack.

## Why This Works (Mechanism)
The resilience stems from the synergy between two mechanisms. **Partial parameter sharing** during training attenuates the expected energy (norm) of any single adversary's perturbation by a factor of M/D. Since only a random subset of coordinates is transmitted and aggregated, a Byzantine client's malicious update is diluted across the global model, leading to a lower steady-state mean-square error and a more accurate base model. This sets a foundation for valid calibration. **Histogram-based filtering** during calibration treats each client's distribution of nonconformity scores as a characterization vector. The core insight is that honest clients, having been trained on similar i.i.d. or smoothly heterogeneous data, will produce statistically similar nonconformity score distributions. A Byzantine client attempting to manipulate the calibration quantile (e.g., by sending extremely high or low scores) will produce an outlier histogram. By measuring the distance of each client's histogram from the robust median histogram, the server can effectively identify and remove these outliers before quantile estimation, preventing interval inflation or coverage collapse.

## Architecture Onboarding
**Component Map:** Client Local Training -> Partial Parameter Selection -> Secure Upload -> Server Aggregation (Global Model Update) -> Client Calibration (Score Histogram) -> Secure Upload -> Server Histogram Comparison (Maliciousness Scoring) -> Client Filtering -> Honest Score Aggregation -> Quantile Estimation -> Final Prediction Intervals

**Critical Path:** The sequence from client model updates (partial) to server aggregation, followed by the calibration phase where histogram-based filtering must succeed before quantile computation. A failure at the filtering step (e.g., honest client wrongly flagged) directly corrupts the final interval.

**Design Tradeoffs:**
1.  **Partial Sharing Ratio (M/D):** Lower M/D reduces communication and adversarial impact but may also slow convergence and reduce final model utility due to less information per round. The paper only evaluates M/D=0.25.
2.  **Filtering Threshold:** The threshold on maliciousness scores trades off false positives (e honest clients removed -> coverage drop) and false negatives (Byzantine clients retained -> interval inflation). The threshold setting is not extensively studied.
3.  **Aggregation Rule Choice:** The paper uses median/trimmed mean for partial updates. Different robust aggregators (e.g., Krum) could interact differently with partial sharing.

**Failure Signatures:**
*   **Training Phase Failure:** If M is too small, the global model fails to converge, leading to inherently poor base predictions and unavoidable coverage failure regardless of calibration.
*   **Calibration Phase Failure:** If the histogram filtering is too aggressive, it removes too many honest clients, reducing the effective sample size for quantile estimation and causing high-variance, unreliable intervals (coverage may deviate wildly). If it is too lenient, attackers remain and bias the quantile, leading to systematically under- or over-covered intervals.
*   **End-to-End Failure:** An adaptive attack that crafts nonconformity scores to mimic honest client histograms could bypass the filtering, poisoning the calibration.

**First 3 Experiments:**
1.  **Vary M/D:** Run the full pipeline across Multiple M/D ratios (e.g., 0.1, 0.25, 0.5, 0.9) on a single dataset/attack. Plot interval width vs. achieved coverage and communication savings vs. training MSE to characterize the Pareto frontier.
2.  **Attack Diversity:** Replicate the main experiment on at least one additional standard FL dataset (e.g., FEMNIST for classification) and against a broader attack suite, including label-flipping attacks on targets, Gaussian noise attacks on updates, and adaptive attacks that target the calibration phase directly (e.g., submitting strategically chosen score histograms).
3.  **Ablation - Aggregation vs. Filtering:** Isolate the contributions of the two defenses. Run ablations: (a) Full sharing + standard FCP (no filtering), (b) Full sharing + PRISM-FCP filtering, (c) Partial sharing (M/D=0.25) + standard FCP (no filtering). This comparison will show how much resilience comes from training-phase attenuation vs. calibration-phase filtering.

## Limitations
*   **Limited Evaluation Scope:** Claims are validated on only one real-world dataset (UCI Superconductivity) and synthetic data. Generalizability to more complex, heterogeneous FL scenarios (e.g., medical, finance) and a wider range of attacks is unproven.
*   **Incomplete Parameter Exploration:** The key trade-off parameter M/D is evaluated at a single point (0.25). The full sensitivity and optimal operating range are not characterized.
*   **Lack of Formal Guarantees:** The approach combines heuristic filtering with stochastic partial sharing. There are no certifiable robustness guarantees (e.g., "the interval width will not exceed X under up to f Byzantine clients"), leaving worst-case failure modes unknown.
*   **Reproducibility Barrier:** No public code or detailed implementation notes are provided, making independent verification of the experimental setup, especially the histogram filtering logic and attack implementations, impossible.
