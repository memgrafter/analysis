# A Small-Scale System for Autoregressive Program Synthesis Enabling Controlled Experimentation

## Quick Facts
- **arXiv ID**: 2602.09112
- **Source URL**: https://arxiv.org/abs/2602.09112
- **Reference count**: 17
- **Primary result**: Cadmus attains 100% accuracy on a number comparison task, surpasses GPT-5 (95%), and remains robust under instruction redefinition.

## Executive Summary
This paper introduces Cadmus, a compact system designed to facilitate controlled, low-cost experiments in autoregressive program synthesis. Cadmus integrates three main components: an integer-based virtual machine (VM) with a deterministic stack-based postfix execution model, a large dataset of “true programs” (80 million) generated from diverse templates, and a 280‑million‑parameter decoder‑only transformer trained via next‑token prediction for under $200. The VM defines true programs as those yielding only non‑zero, non‑NaN outputs after execution, providing a crisp binary label. On a number comparison task, Cadmus achieves perfect 100% accuracy, outperforming GPT‑5’s 95%. Moreover, when instruction symbols are arbitrarily redefined (an out‑of‑distribution test), GPT‑5’s accuracy collapses dramatically (e.g., to 49%), while Cadmus remains robust, indicating it has learned the underlying numerical semantics rather than superficial token correlations. The system’s full transparency and controlled environment make it a valuable platform for studying inductive reasoning and generalization.

## Method Summary
The task is autoregressive program completion within a custom integer domain‑specific language. Programs are sequences of postfix VM instructions, each represented by a single token, terminated by a period. The VM executes any instruction sequence without runtime errors; false outputs are defined as 0 or NaN, which propagate through operations. A program is considered “true” if all its outputs are true.

The training dataset comprises 80 million true programs sampled from seven structured templates (e.g., basic math, equality, comparison, sub‑routines). Each template generates syntactically valid programs that are guaranteed to be true by construction, though the exact sampling distributions are described only at a high level.

The model is an 18‑layer decoder‑only transformer with 280 million parameters (vocabulary size 65, d_model 1280, 20 attention heads, feed‑forward dimension 3600, GELU activations). It is trained for 300,000 steps with a batch size of 1024 on 8×H100 GPUs, using the Adam optimizer (learning rate 1e‑4 with cosine decay, betas [0.9, 0.95]). The objective is standard next‑token prediction.

Evaluation focuses on a number comparison task: given a program prefix that computes two values X and Y, the model must predict the correct comparison instruction (e.g., `>` or `<`). Accuracy is measured by whether the VM, after appending the predicted token, produces a true output. The paper also tests out‑of‑distribution (OOD) generalization by arbitrarily redefining instruction symbols (e.g., mapping `+` to subtraction) while keeping the programs otherwise unchanged.

## Key Results
- Cadmus achieves 100% accuracy on the number comparison task, surpassing GPT‑5’s 95%.
- Under arbitrary instruction redefinition, GPT‑5’s accuracy collapses (as low as 49%) while Cadmus remains robust, demonstrating it learns the underlying arithmetic semantics.
- The system provides full transparency of the training distribution and precise numerical representations, offering a clean testbed for studying inductive reasoning and OOD generalization.

## Why This Works (Mechanism)
The success of Cadmus stems from the perfect control it affords: the VM’s deterministic execution and crisp true/false labeling eliminate noise from incorrect programs; the dataset consists exclusively of true programs, so the model learns the distribution of valid sequences without confusion; the diversity of templates ensures the model generalizes across structures. The autoregressive objective forces the model to capture both syntactic and semantic patterns needed to predict the next instruction. The small, fixed vocabulary and integer domain simplify the learning problem, making a 280M‑parameter model sufficient to achieve near‑perfect performance. Crucially, the model’s robustness to symbol redefinition shows it has internalized the numerical relationships (e.g., addition, comparison) rather than relying on token‑level coincidences, because the same abstract operations are invariant under the redefinition.

## Architecture Onboarding
The system architecture can be viewed as a linear pipeline:  
**Template → Program Sampler → VM (filter) → True Program Dataset → Transformer Model → Evaluation**

The critical path to high accuracy consists of three stages: (1) generating a large, diverse set of true programs (covering the target task space), (2) training the transformer with sufficient capacity and appropriate hyperparameters to learn the program distribution, and (3) evaluating on held‑out test prefixes with the VM providing ground truth. A break anywhere—e.g., dataset bias or training instability—will degrade performance.

Design tradeoffs include: the integer VM’s simplicity and controllability vs. limited expressivity; template‑based generation guarantees correctness but may not cover all possible programs; a fixed 65‑token vocabulary simplifies tokenization but limits extensibility; training without execution (pure next‑token) reduces complexity but places the burden of learning semantics on the model; the 280M parameter size balances power and cost.

Failure signatures:
- VM errors: wrong outputs on known examples or mishandled NaN/stack underflow.
- Dataset contamination: presence of false programs or lack of diversity.
- Training issues: loss plateauing, underfitting (low accuracy even on simple templates), or overfitting (high training but low validation accuracy).
- Evaluation mismatch: using subword tokenization or non‑greedy decoding.

First experiments:
1. **VM validation**: Execute all Table 2 examples and assert expected true/false results; also test edge cases (stack underflow, NaN).
2. **Dataset verification**: Generate a small sample (e.g., 10k programs) from each template; confirm 100% pass VM validation and that template‑specific statistics (value ranges, instruction frequencies) match descriptions.
3. **Smoke‑test training**: Train a reduced version (e.g., 1M true programs, 100k steps, smaller model) and evaluate on the number comparison task; expect near‑perfect accuracy to confirm the pipeline’s correctness before full‑scale training.

## Limitations
- The complete 65‑instruction VM semantics (stack behavior, NaN propagation, termination) are only fully specified in the released code, not in the paper.
- The exact pseudo‑code and sampling distributions for all seven template types—especially “random” and “complete algorithm”—are underscribed, hindering exact replication of the training distribution.
- GPT‑5 evaluation details (prompt format, few‑shot examples, decoding parameters) are not provided, limiting independent verification of the comparative claim.

- **Performance results (100% accuracy, GPT‑5 comparison, OOD collapse)**: Medium
