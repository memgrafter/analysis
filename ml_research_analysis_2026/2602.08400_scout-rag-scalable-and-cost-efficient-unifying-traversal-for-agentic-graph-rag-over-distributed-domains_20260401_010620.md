# SCOUT-RAG: Scalable and Cost-Efficient Unifying Traversal for Agentic Graph-RAG over Distributed Domains

## Quick Facts
- **arXiv ID:** 2602.08400
- **Source URL:** https://arxiv.org/abs/2602.08400
- **Reference count:** 3
- **Primary result:** Achieves comparable answer quality to centralized DRIFT (56 vs 63) while reducing token consumption by 81.9% and latency by 81.8% versus exhaustive decentralized retrieval.

## Executive Summary
SCOUT-RAG is a training-free agentic framework for distributed Graph-RAG that operates under privacy and cost constraints. It coordinates four cooperative agents to selectively retrieve relevant information across independent knowledge domains without requiring global graph visibility. The system classifies domains by relevance, performs scoped retrieval (global for high-relevance, local for moderate), synthesizes an initial answer, and then iteratively refines it by assessing quality and deciding between depth, breadth, or hybrid expansion. Evaluated on 89 multi-domain queries from 45 Wikipedia country domains, SCOUT-RAG attains quality comparable to a centralized baseline while drastically cutting token usage and latency.

## Method Summary
SCOUT-RAG employs a three-stage agentic pipeline. Stage 1: Domain Relevance Assessment Agent (DRAA) scores each domain using semantic similarity, knowledge richness (report count), and historical performance, classifying it as HIGH, MODERATE, POTENTIAL, or IRRELEVANT. Stage 2: Domain-Scoped Seeding – Partial Answer Generation Agent (PAGA) retrieves from HIGH domains using global community summaries and from MODERATE domains using local entity-centric chunks, in parallel. Overall Answer Synthesis Agent (OASA) then fuses these partial answers into a seed answer. Stage 3: Iterative Refinement – Answer Quality Assessment Agent (AQAA) evaluates the current answer on comprehensiveness, diversity, empowerment, and directness, yielding a quality vector. A strategy (Depth, Breadth, Hybrid, or Stop) is selected based on thresholds; PAGA retrieves accordingly (e.g., follow-up queries on high-relevance domains for Depth, original query on potential domains for Breadth). OASA updates the answer, and the best answer is tracked. The loop enforces a strict time budget and termination conditions (quality threshold, minimal time, or negligible improvement).

## Key Results
- Overall quality score 56 vs. centralized DRIFT’s 63 (comparable performance).
- Token consumption reduced by 81.9% (159,169 vs. 879,911) compared to exhaustive decentralized retrieval.
- Latency reduced by 81.8% (75.32s vs. 414.88s) under the same comparison.

## Why This Works (Mechanism)
SCOUT-RAG’s efficiency stems from selective cross-domain retrieval guided by domain relevance classification, which avoids unnecessary access to low-relevance domains. The iterative refinement loop focuses retrieval efforts where quality is lacking (via depth or breadth expansion), while the time-budget enforcement curtails excessive token use. The cooperative agents modularize concerns: DRAA minimizes search space, PAGA tailors retrieval scope per domain tier, AQAA provides quality feedback, and OASA synthesizes incremental evidence. This design yields a tunable trade-off between answer quality and cost, achieving near-centralized quality with distributed privacy and far lower resource expenditure than exhaustive decentralization.

## Foundational Learning
- **Domain Relevance Assessment:** Needed to prioritize domains under privacy constraints without full graph visibility. *Quick check:* Verify that DRAA’s similarity and richness signals correlate with human-judged relevance on a sample.
- **Cooperative Agent Design:** Needed to decompose the complex retrieval-synthesis task into manageable, parallelizable units. *Quick check:* Confirm that each agent has a single responsibility and passes well-defined outputs to the next.
- **Time-Budget Enforcement:** Needed to guarantee cost efficiency in token-limited environments. *Quick check:* Measure that total latency per iteration stays below the configured threshold and that termination conditions trigger appropriately.
- **Iterative Refinement with Quality Feedback:** Needed to improve answers without exhaustive initial retrieval. *Quick check:* Ensure that each iteration yields a non-decreasing quality score (until plateau) and that the loop stops when improvement stalls.
- **Scoped Retrieval (Global vs Local):** Needed to respect domain boundaries while maximizing relevant evidence. *Quick check:* Check that HIGH domains receive broader (community summary) retrieval and MODERATE domains receive focused (entity-centric) retrieval.

## Architecture Onboarding
**Component Map:**  
Query q -> DRAA (classifies domains) -> Domain Tiers (HIGH/MODERATE/POTENTIAL/IRRELEVANT) -> [Parallel: PAGA(global) for HIGH, PAGA(local) for MODERATE] -> OASA(synthesize seed answer A0) -> AQAA(evaluate quality (C,V,G,F)) -> Strategy Selection (Depth/Breadth/Hybrid/Stop) -> if not Stop: [Parallel: PAGA(retrieve based on α)] -> OASA(update answer) -> (loop until stop) -> Track Best Answer.

**Critical Path:** The longest sequential dependency per iteration comprises AQAA evaluation (prompted scoring), strategy selection (threshold logic), and the slowest PAGA retrieval among parallel calls, followed by OASA synthesis. The initial seeding phase also forms a critical path: DRAA classification (sequential over domains) then parallel retrieval then OASA synthesis.

**Design Tradeoffs:**  
- *Training-free vs. Quality:* Avoids costly fine-tuning but may underperform learned retrieval policies.  
- *Privacy vs. Efficiency:* Local/global scoping preserves domain privacy but may miss cross-domain connections.  
- *Selective vs. Exhaustive:* Drastically reduces cost but risks omitting obscure relevant domains.  
- *Agent Modularity vs. Coordination Overhead:* Clear separation aids implementation but adds prompt engineering and state-passing complexity.

**Failure Signatures:**  
- Refinement stagnation (quality plateaus or degrades over multiple iterations).  
- Domain misclassification (key domains omitted due to incorrect tier).  
- Latency blowout (parallel retrieval calls exceed time budget).  
- Inconsistent AQAA scores (high variance across LLM calls for same answer).  
- Token overuse (loop runs too many iterations without quality gain).

**First Experiments:**  
1. DRAA threshold calibration: Run on 10 queries with known relevant domains, adjust tier thresholds to maximize F1.  
2. AQAA scoring consistency: For 20 partial answers, compute quality scores with 5 independent LLM calls; assess variance (>10 std dev indicates prompt refinement needed).  
3. Per-domain latency profiling: Instrument PAGA to log retrieval times; identify slowest domains and set concurrency limits (e.g., max 5 parallel) to keep iteration time <10s.

## Limitations
