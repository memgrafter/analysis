# Swimba: Switch Mamba Model Scales State Space Models

## Quick Facts
- **arXiv ID**: 2603.06938
- **Source URL**: https://arxiv.org/abs/2603.06938
- **Reference count**: 40
- **Primary result**: Swimba-14B (4 experts, 1 active) matches Nemotron-H-8B FLOPs per token within 0.2% and achieves slightly better average accuracy on standard benchmarks, but incurs ~10% latency overhead in vLLM decoding due to routing.

## Executive Summary
Swimba introduces a parameter-space Mixture-of-Experts (MoE) approach to scale Selective State Space Models (SSMs) without increasing the dominant recurrence cost. By having each expert produce candidate SSM streams (the B·X injection and C readout) and mixing these parameters before a single shared recurrence, Swimba maintains one state trajectory regardless of the number of experts. Theoretically, this preserves the selective SSM structure and ensures stability under a contractive transition matrix. Empirically, a 14B-parameter Swimba model with 4 experts and top‑1 routing matches the FLOPs per token of an 8B dense baseline (Nemotron‑H‑8B) within 0.2% and attains marginally higher average accuracy across nine language benchmarks. However, end‑to‑end decoding with vLLM shows a slowdown of up to ~10% in latency and throughput, attributed to routing overhead.

## Method Summary
Swimba replaces each Mamba‑2 layer in a dense decoder-only model (Nemotron‑H‑8B) with a Swimba layer. The new layer contains: (1) a router that selects the top‑1 expert per token and produces a softmax weight; (2) multiple expert networks, each projecting the token hidden state to produce candidate B, C, and X streams; (3) a mixing module that computes the weighted sum of the expert products B·X (forming the injection U) and the weighted sum of C (forming the readout C̃). All experts share the same transition matrix A, and the recurrence hₜ = A hₜ₋₁ + Uₜ is performed exactly once per token, followed by yₜ = C̃ₜᵀ hₜ. The model is initialized from the dense checkpoint: non‑MoE parameters (norms, FFNs, attention) are copied and frozen, while the expert projections and router are randomly initialized and trained. Continued training uses the Llama‑Nemotron Post‑Training SFT dataset with standard cross‑entropy loss and only the MoE parameters updated. The resulting architecture (52 layers, with 24 Swimba layers, 24 FFN layers, and 4 attention layers) yields a 14B model that computationally matches the 8B dense baseline per token.

## Key Results
- FLOPs per token are within 0.2% of the Nemotron‑H‑8B baseline.
- Slightly higher average accuracy across nine standard benchmarks (ARC, BoolQ, Hellaswag, MMLU, OpenbookQA, PIQA, RTE, Winogrande).
- vLLM decoding latency and throughput degrade by up to ~10% relative to the baseline due to routing overhead.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: By mixing expert-produced SSM streams in parameter space, Swimba maintains a single hidden state trajectory and evaluates the recurrence only once per token, regardless of the number of experts.
- **Mechanism**: Each expert `e` projects the token hidden state to produce candidate streams `B_t^e`, `C_t^e`, `X_t^e`. A router computes mixture weights `π_{t,e}`. The effective injection `U_t = Σ_{e∈K_t} π_{t,e} B_t^e X_t^e` and readout `C̃_t = Σ_{e∈K_t} π_{t,e} C_t^e`. The recurrence `h_t = A h_{t-1} + U_t` and output `y_t = C̃_t^T h_t` then form a single selective SSM with shared transition matrix `A`. The recurrence is performed once, so computational cost does not scale with experts.
- **Core assumption**: Experts share the same transition matrix `A` (Equation 7) and the router's mixing weights sum to 1. This ensures the mixed system retains the selective SSM structure.
- **Evidence anchors**:
  - [abstract] "parameter-space MoE mixing: experts produce SSM streams, but parameters are aggregated before a single recurrence, maintaining one state trajectory."
  - [section 3.2] Explicit derivation of equations (8)-(9) and statement that "the recurrence is evaluated once".
  - [corpus] MoE-Mamba (neighbor) similarly states "minimal increase in computation" for SSM scaling with MoE, consistent with parameter-space mixing.
- **Break condition**: If experts had distinct transition matrices (`A^e`), mixing would no longer yield a single SSM and recurrence would need to be computed per expert (MoE of separated SSMs). Also if mixing were done after recurrence (separate states), compute would multiply.

### Mechanism 2
- **Claim**: The dominant recurrence cost remains `O(T * cost(step))` independent of the number of experts `E`; adding experts only increases parameter count, not per-token FLOPs.
- **Mechanism**: The forward pass cost is sum of `(T * C_step(N,P))` for recurrence plus `T * C_mix(k,P)` for mixing expert projections. Since `C_step` is much larger than `C_mix` for typical state size `N` and sequence length `T`, total cost is essentially unchanged when `E` increases, provided active experts `k` is fixed (top-1 in Swimba). The recurrence uses the same state dimension `N` regardless of `E`.
- **Core assumption**: The recurrence step (state update and output) dominates the computational complexity over mixing and expert projections; also the router activates at most `k` experts per token (`k=1` in Swimba).
- **Evidence anchors**:
  - [abstract] "parameter-space MoE can increase SSM capacity while keeping the dominant recurrence cost fixed."
  - [section 3.4 Theorem 2] Formal complexity comparison: `O(T * C_step + T * C_mix)` vs `O(T * E * C_step)`.
  - [section 5.2 Table 2] Empirical FLOPs: Nemotron-H-8B `1.51263e10` vs Swimba-14B `1.51282e10` (<0.2% difference).
- **Break condition**: If `k` grows with `E` (e.g., all experts active), mixing cost `O(k*P)` could become significant; also if `N` is very small relative to `P`, mixing might not be negligible. But in practice with top-1, it's minor.

### Mechanism 3
- **Claim**: Under a contractive transition matrix (`||A|| < 1`), the state trajectory `h_t` remains bounded if the mixed injection `U_t` and readout `C̃_t` norms are uniformly bounded, ensuring stability despite routing.
- **Mechanism**: The linear recurrence `h_t = A h_{t-1} + U_t` yields the unrolled form `h_t = A^t h_0 + Σ_{i=1}^t A^{t-i} U_i`. When `A` is contractive, `||A^t||` decays exponentially. Thus `||h_t|| ≤ ρ^t ||h_0|| + (1-ρ^t)/(1-ρ) * sup_t ||U_t||`. Output bound follows from `||y_t|| ≤ ||C̃_t|| ||h_t||`.
- **Core assumption**: `A` is contractive in some induced norm (e.g., spectral norm `ρ<1`); there exist constants `U, C` such that `||U_t|| ≤ U` and `||C̃_t|| ≤ C` for all `t`. This may depend on weight initialization and routing outputs.
- **Evidence anchors**:
  - [section 3.4 Theorem 3] Formal statement and proof of BIBO stability with bounds on `U_t` and `C̃_t`.
  - [section 4.1] Implementation uses shared `A` and does not modify transition matrix, so contractivity can be inherited from the base Mamba-2 if it was stable.
- **Break condition**: If `A` is not contractive (e.g., norm ≥ 1), the state may diverge even with bounded `U_t`. Also if routing produces extremely large `U_t` (e.g., due to unbounded projections), the bound may be violated; careful initialization and normalization of expert outputs may be needed.

## Foundational Learning
- **Concept**: Selective State Space Models (SSMs)
  - **Why needed here**: Swimba's token mixer is built on selective SSMs (Mamba-2), where parameters `Δ`, `B`, `C` are input-dependent. Understanding this baseline is essential to see how MoE modifies the streams.
  - **Quick check question**: How does a selective SSM differ from a standard (non-selective) SSM in terms of parameter time-dependence and computational implications?
- **Concept**: Mixture-of-Experts (MoE) with top-k routing
  - **Why needed here**: Swimba introduces expert specialization via MoE. The top-k routing mechanism determines which experts contribute at each token, directly affecting compute and model capacity.
  - **Quick check question**: Why is top-k sparsity important for keeping inference costs low in MoE models?
- **Concept**: Parameter-space mixing vs output-space mixing
  - **Why needed here**: The core design choice in Swimba is to mix experts before the recurrence (parameter-space) rather than after (output-space). This distinction explains the scaling property.
  - **Quick check question**: If we mixed expert outputs after maintaining separate SSM states (separated SSMs), how would the recurrence cost scale?

## Architecture Onboarding
### Component Map
- **Router**: Computes gating logits from token features; selects top-k experts and produces weights.
- **Expert projection layers**: Each expert `e` has its own linear mappings to generate `B_t^e`, `C_t^e`, `X_t^e` from the token feature.
- **Mixing module**: Computes `U_t = Σ_{e∈K_t} π_{t,e} (B_t^e X_t^e)` and `C̃_t = Σ_{e∈K_t} π_{t,e} C_t^e`.
- **Shared transition matrix `A`**: Fixed across experts and time; used in recurrence.
- **SSM core**: Updates hidden state `h_t` and computes output `y_t = C̃_t^T h_t` (H → P channels) using SSD-style scan.
- **Output projection**: Maps `y_t` to the residual/next layer.
### Critical Path
Token embedding → input features → Router (get `K_t`, `π`) → Parallel expert projections → Mixing (`U_t`, `C̃_t`) → SSM recurrence (single loop over `T`) → output → residual connection → next layer.
### Design Tradeoffs
- Number of experts `E` vs active `k`: Increasing `E` boosts parameter capacity but adds routing and projection overhead; keeping `k` small (e.g., 1) preserves lower latency.
- Shared `A` vs expert-specific `A`: Sharing `A` is essential for single recurrence; permitting per-expert `A` would increase expressivity but multiply recurrence cost.
- Router temperature: Controls sharpness of routing; higher temperature may improve load balance but reduce expert specialization.
- Normalization of expert outputs: To keep `U_t` and `C̃_t` bounded for stability, one may use weight scaling or activation constraints.
### Failure Signatures
- Training instability: Loss spikes or NaNs, often due to unbounded routing logits or large `U_t` norms; monitor router entropy and `U_t` statistics.
- Expert collapse: One expert is selected for >90% of tokens, reducing effective capacity; check routing distribution histograms.
- Unexpected high latency: If decoder throughput degrades beyond ~10%, verify that top-k is indeed 1 and that the implementation uses fused kernels for mixing and SSM.
- Memory blowup: If hidden state memory scales with `E`, accidentally implemented separated SSM.

## Open Questions the Paper Calls Out
- **Question**: What is the empirical performance difference between MoE-parameterized and separated SSMs?
  - **Basis in paper**: [inferred] Theorem 4 compares the designs theoretically but no separated MoE-SSM is implemented or evaluated.
  - **Why unresolved**: Without empirical comparison, it is unclear whether the theoretical bound is tight or if the separated design offers practical advantages despite higher compute.
  - **What evidence would resolve it**: Build a separated MoE-SSM model (multiple state trajectories) and compare its accuracy, stability, and efficiency against Swimba on standard benchmarks.
- **Question**: Can the routing overhead causing ~10% vLLM latency slowdown be eliminated or reduced?
  - **Basis in paper**: [explicit] Section 5.2 explicitly attributes Swimba's throughput/latency drop to routing overhead.
  - **Why unresolved**: The paper does not profile or optimize the router, leaving the potential for improvement unquantified.
  - **What evidence would resolve it**: Profile the routing computations (logits, top-k selection, mixing), implement optimizations (e.g., kernel fusion, batched routing), and measure resulting latency/throughput gains.
- **Question**: Does increasing the total number of experts (with fixed active per token) improve model capacity without proportional inference cost?
  - **Basis in paper**: [inferred] The paper cites prior work [6] suggesting throughput/latency unchanged with fixed active experts, but only evaluates a 4-expert model.
  - **Why unresolved**: Scaling behavior to larger expert counts (e.g., 8, 16) is untested; routing and memory overheads may emerge.
  - **What evidence would resolve it**: Train Swimba models with varying expert counts (e.g., 8, 16) but constant top-1 activation, then compare benchmark accuracy and vLLM efficiency against the 4-expert baseline.
- **Question**: How does time-varying routing affect stability and expressivity for sequences longer than one token?
  - **Basis in paper**: [explicit] Theorem 5 proves expressivity gain only for T=1; the paper does not extend analysis to longer sequences.
  - **Why unresolved**: For T>1, the interaction between input-dependent routing and state evolution is not theoretically characterized, potentially impacting long-sequence modeling.
  - **What evidence would resolve it**: Develop theoretical bounds for T>1 (e.g., state norm control with time-varying mixtures) and evaluate Swimba on long-context tasks, monitoring stability (e.g., gradient norms) and performance.
