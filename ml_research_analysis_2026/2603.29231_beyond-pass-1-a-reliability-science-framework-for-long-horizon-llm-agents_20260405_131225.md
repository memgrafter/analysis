# Beyond pass@1: A Reliability Science Framework for Long-Horizon LLM Agents

## Quick Facts
- **arXiv ID**: 2603.29231
- **Source URL**: https://arxiv.org/abs/2603.29231
- **Reference count**: 11
- **Primary result**: Reliability (consistent success across long-horizon tasks) diverges structurally from short-horizon capability (pass@1); new metrics RDC, VAF, GDS, and MOP expose decay, variance amplification, partial progress, and collapse.

## Executive Summary
Current LLM evaluation prioritizes pass@1 on short tasks, but production deployment demands reliable performance over long horizons. This work introduces a reliability science framework with four metrics capturing failure modes invisible to capability benchmarks. Evaluating 10 models on 396 tasks reveals that reliability decays super-linearly with duration, that variance amplification (VAF) signals capability rather than instability, and that naive memory scaffolds consistently harm long-horizon partial progress (GDS). Frontier models show highest meltdown rates, and reliability rankings often invert capability rankings at scale. The findings establish reliability as a first-class dimension alongside capability.

## Method Summary
The benchmark comprises 396 tasks across three domains (Software Engineering, Web Research, Document Processing) and four duration buckets (short ≤5 min to very long ≥120 min). Each task is decomposed into 3–6 subtasks with criticality weights for partial-credit scoring. Two agent scaffolds are tested: ReAct and a naive episodic memory (scratchpad). Evaluation runs k=3 repeats per task with temperature 0.7, max 70 steps, isolated workspaces, and a 120k token input cap. Outcome metrics are: Reliability Decay Curve (RDC: pass@k vs. duration), Variance Amplification Factor (VAF: ratio of long- to short-horizon outcome variance), Graceful Degradation Score (GDS: weighted subtask completion), and Meltdown Onset Point (MOP: first step where sliding-window tool-call entropy exceeds a calibrated threshold). Programmatic evaluators score success; MOP is computed post-hoc from logged trajectories.

## Key Results
- Domain-stratified decay: SE GDS falls from 0.90 to 0.44 (steep), while DP remains nearly flat (0.74 to 0.71).
- VAF bifurcates by capability tier: frontier models show high VAF (≥2.37) with long-horizon pass@1 >72.7%, while lower-tier models have VAF <1.3 and pass@1 <55.6%.
- Naive memory scaffolds universally degrade long-horizon GDS across all models (6/10 significant penalties), with largest hits on mid-tier capable models (e.g., Kimi K2.5: −0.14).

## Why This Works (Mechanism)
Reliability degrades super-linearly because step-level errors are positively correlated. An early mistake (e.g., wrong tool call) increases the likelihood of subsequent mistakes, creating a persistent erroneous state. This positive inter-step correlation (ρ > 0) makes task failure probability grow super-exponentially with step count T, not geometrically as under independent Bernoulli assumptions. Empirical pass@1 drops (e.g., Qwen3 30B: predicted 33.0% at long horizon vs. observed 22.2%) exceed geometric predictions, supporting the correlation hypothesis.

The Variance Amplification Factor (VAF) acts as a capability signature. VAF compares outcome variance between long- and short-horizon tasks. Only models with a non-trivial long-horizon success probability exhibit mixed outcomes (sometimes succeed, sometimes fail), yielding high variance that amplifies with duration. Weak models uniformly fail on long tasks (near-zero pass@1), so their long-horizon variance is low, producing low VAF. Thus high VAF requires both sufficient baseline success probability and stochastic variability, explaining the observed bifurcation.

Naive episodic memory scaffolds (scratchpad) degrade long-horizon GDS because managing memory consumes step tokens and context length. Each `add_to_memory` operation and the growing scratchpad content injected into every turn grows linearly with task progress. At long horizons, this overhead becomes load-bearing, reducing the budget for task-relevant reasoning and tool use, and lowering partial completion scores. Consistent negative ΔGDS across most models confirms this overhead penalty.

## Foundational Learning
### Graceful Degradation Score (GDS)
- **Why needed here**: Binary pass@1 discards partial progress common on long tasks. GDS weights subtask completion, distinguishing a model that completes 8/10 subtasks from one that completes 1/10.
- **Quick check**: Task subtasks with criticality weights [0.4, 0.3, 0.2, 0.1]; agent completes first two correctly. GDS = 0.7.

### Reliability Decay Curve (RDC) & Slope (RDS)
- **Why needed here**: RDC maps pass@k across duration buckets; RDS (slope of GDS vs. bucket) quantifies decay rate. A shallow RDS (≈0) indicates production-safe reliability across durations.
- **Quick check**: Model A RDS = −0.1, Model B RDS = −0.03. Model B is more reliable at very-long horizons.

### Meltdown Onset Point (MOP)
- **Why needed here**: Detects behavioral collapse (looping, incoherent tool calls) that binary metrics miss. High entropy in a short sliding window signals lost strategic coherence.
- **Quick check**: Tool-call window [read, search, read, write, search] has uniform distribution → high entropy (~1.79 bits for 3 tools), indicating potential meltdown.

## Architecture Onboarding
Task registry -> Workspace isolation -> Agent loop (ReAct/Memory) -> Tool execution layer -> Evaluator -> Metrics calculator -> Logging -> Cost tracker

**Critical path**: Task selection → workspace copy → agent step loop (max 70 steps) → finish call → evaluator score → aggregate metrics. MOP runs post-hoc on logged tool sequences.

**Design tradeoffs**:
- Programmatic vs. LLM-as-judge: Reproducibility vs. nuanced failure detection.
- k=3 repeats: Balances variance estimation with cost; k=1 blind to reliability.
- Temperature=0.7: Induces stochasticity needed for reliability estimation but increases outcome variance.
- 50–70 step limits: Must exceed expected n* but prevent infinite loops.

**Failure signatures**:
- API quota exhaustion (HTTP 429/404) → episode termination; biases short-horizon if frequent.
- Loop detection: same (tool, args) ≥3 times in 6 steps → abort.
- Context blowup: input tokens >120,000 → terminate; catches memory-scaffold overhead failures.

**First 3 experiments**:
1. **Validation run**: Evaluate all models on the 19-task short+medium suite (k=3) to verify harness, calibrate MOP thresholds, and check infrastructure quotas.
2. **Scaffold comparison**: Compare ReAct vs. Memory on long+very-long tasks to test universal memory degradation hypothesis; expect negative ΔGDS for most models.
3. **Domain RDC**: Compute GDS decay slope (RDS) separately for SE, WR, DP to confirm domain-stratified decay (SE steep, DP flat).

## Open Questions the Paper Calls Out
**Does fine-tuning with reliability metrics enhance long-horizon reliability without capability trade-offs?**  
Basis: Section 7.4 proposes "reliability-aware training" using RDC, VAF, GDS, MOP as signals.  
Unresolved: Only pretrained models evaluated; training dynamics and overfitting risks unknown.  
Resolution: Conduct fine-tuning with losses derived from these metrics, then assess on benchmark and held-out tasks.

**Can MOP-triggered context resetting reduce failure rates for frontier models?**  
Basis: Section 7.4 suggests "MOP-triggered context reset interventions" given high meltdown rates in capable models.  
Unresolved: MOP used only for detection; impact of resets on completion rates untested.  
Resolution: Implement resets upon MOP detection, compare GDS and pass@1 against baseline.

**How do proprietary frontier models (e.g., GPT-4o, Claude 3.7) compare on the reliability framework?**  
Basis: Section 7.4 calls for "proprietary model extension" to characterize the proprietary frontier.  
Unresolved: Only open-source models studied; proprietary architectures may exhibit different decay/VAF patterns.  
Resolution: Evaluate identical benchmark on proprietary models with same scaffolds/metrics, compare RDC slopes and VAF distributions.

**Can alternative memory architectures (e.g., hierarchical summaries) avoid the universal long-horizon GDS penalty?**  
Basis: Section 7.4 identifies "memory scaffold redesign" as high-priority due to consistent negative effects.  
Unresolved: Only one naive scratchpad tested; other designs speculative.  
Resolution: Implement and compare multiple memory architectures on long-horizon tasks, measuring GDS, MOP, and step efficiency.

## Limitations
- **Reproduction blockers**: Missing exact repository URL, OpenRouter model identifiers, full subtask weight matrices, MOP calibration details, and web tool harness specifics.
- **Generalizability**: Findings limited to 10 models across 3 domains; may not hold for other architectures or task distributions. Minimal external validation in citing literature.

## Confidence
- **Reliability degrades super-linearly**: Medium (strong empirical mismatch with geometric decay, but weak direct evidence of positive error correlation).
- **VAF bifurcates by capability tier**: Medium (clear data separation, no neighboring work; falsifiable only with rare high-pass@1 + low-variance cases).
- **Naive memory scaffolds degrade GDS**: Medium (consistent negative ΔGDS across models, but scoped to naive scaffolds; redesigns could invert results).

## Next Checks
1. **Error correlation intervention**: Implement early-step verification (e.g., self-consistency) and measure whether long-horizon pass@1 improves disproportionately, testing ρ > 0.
2. **VAF vs. deterministic success**: Evaluate a high-pass@1 model at temperature=0; if VAF drops despite stable success, confirms variance requires stochastic capability ceiling.
3. **Memory scaffold redesign**: Replace scratchpad with hierarchical summarization (e.g., compress every 10 steps); measure ΔGDS on long tasks to test if universal degradation is architecture-specific.
