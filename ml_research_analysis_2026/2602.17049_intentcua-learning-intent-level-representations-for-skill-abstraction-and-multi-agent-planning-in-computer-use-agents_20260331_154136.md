# IntentCUA: Learning Intent-level Representations for Skill Abstraction and Multi-Agent Planning in Computer-Use Agents

## Quick Facts
- **ArXiv ID:** 2602.17049  
- **Source URL:** https://arxiv.org/abs/2602.17049  
- **Reference count:** 40  
- **Primary result:** Achieved 74.83% task success rate on 286 complex desktop tasks with a Step Efficiency Ratio of 0.91 and a 4.5× latency reduction versus strong baselines.

## Executive Summary
Long-horizon computer automation is hindered by intent drift and error accumulation as workflows span multiple windows and dynamic interfaces. IntentCUA addresses these challenges through a multi-agent framework that stabilizes execution by aligning actions with a persistent, intent-grounded plan memory. The system first learns multi-view intent representations from user interaction traces, clusters them hierarchically into intent groups and subgroups, and abstracts reusable parameterized skills. At runtime, a Planner retrieves or synthesizes plans using these skill hints; a Plan-Optimizer grounds steps into atomic GUI actions; and a Critic monitors outcomes, triggering local re-optimization when needed. Evaluated on 286 diverse desktop tasks, IntentCUA attains 74.83% success, high step efficiency, and significantly lower latency than RL-based (UI‑TARS‑1.5) and trajectory-centric (UFO2) baselines.

## Method Summary
IntentCUA operates in two phases. Offline, a multi‑view encoder fuses environment, action/keyword, and description embeddings (via contrastive, cross‑view prediction, and reconstruction losses) into a shared 256‑dimensional space. The embeddings are clustered with HDBSCAN into environment‑driven Intent Groups and finer Subgroups; action sequences within each subgroup are canonicalized into verb‑predicate signatures, and a medoid trace forms a parameterized skill hint. Online, the Planner receives a user command, embeds it, and queries a hierarchical index to retrieve relevant skill hints and stored global plans. For unmatched gaps, it synthesizes steps using retrieved templates. The Plan‑Optimizer then grounds each plan unit into atomic GUI interactions, conditioned on the hints. After every unit the Critic evaluates the post‑state, classifying it as success, retryable, or blocked; retryable cases undergo local re‑optimization. Successful executions are stored in shared memory to enrich future planning.

## Key Results
- Task success rate of 74.83% across 286 complex desktop tasks, exceeding RL and trajectory baselines.
- Step Efficiency Ratio of 0.91, demonstrating near‑perfect completion of planned steps.
- Latency reduced by 4.5× relative to baselines, with the multi‑agent loop providing the largest gains on long‑horizon workflows.

## Why This Works (Mechanism)

**Mechanism 1: Multi‑view intent representation learning**  
Multi‑view alignment produces robust embeddings that enable accurate clustering and retrieval despite noisy or partial observations. A shared encoder aligns environment, action/keyword, and description views using contrastive, cross‑view prediction, and reconstruction losses into a 256‑dimensional space.  
Assumption: Complementary views yield a more discriminative and generalizable representation than any single view.  
Evidence includes the detailed loss formulation (Section 3.1) and ablations showing improved cluster separation.  
Break conditions arise if views are too disparate or loss weights are mis‑specified, leading to misaligned embeddings.

**Mechanism 2: Hierarchical intent clustering and skill abstraction**  
Hierarchical clustering transforms raw traces into reusable parameterized skills, reducing redundant re‑planning. Embeddings are clustered with HDBSCAN into Intent Groups (environment‑driven) and Subgroups (action/description‑driven). Action sequences within each Subgroup are canonicalized into verb‑predicate signatures, and a medoid trace forms a parameterized skill hint.  
Assumption: Similar sub‑intents share actionable patterns that can be generalized, and that a hierarchical organization mirrors natural task decomposition.  
Ablations confirm benefits: adding Subgroup structure and skill hints improved success by 8.21 percentage points and completion by 20.15.  
Over‑fragmentation or under‑clustering degrade retrieval relevance.

**Mechanism 3: Memory‑grounded multi‑agent coordination**  
The Planner‑Plan‑Optimizer‑Critic loop stabilizes long‑horizon execution by reusing stored plans and correcting errors locally. The Planner retrieves or synthesizes plans using intent prototypes and skill hints. The Plan‑Optimizer refines steps conditioned on hints from similar past traces. The Critic validates post‑states and triggers local re‑optimization for retryable failures; only user‑approved plans are stored.  
Assumption: Intent similarity reliably indicates plan applicability and that specialized agents can handle deviations without full re‑planning.  
Long‑horizon results show success rates above 40% beyond 30 steps and a 4.5× latency reduction.  
Failures can arise from noisy retrieval, Critic misclassifications, or memory bloat.

## Architecture Onboarding

**Component map**  
Planner (queries IG/SG index & Shared Memory) → Plan‑Optimizer (uses skill hints for grounding) → Critic (validates state, may trigger re‑optimization). Shared Memory stores validated global plans and skill hints; all agents access this memory.

**Critical path**  
1. User command → Planner builds intent prototype (ENV/ACT/DES embeddings).  
2. Query IG/SG centroids and Shared Memory: exact hit → reuse plan; partial hit → fill gaps with skill hints; miss → synthesize plan from retrieved skill templates.  
3. Execution: Plan‑Optimizer grounds each atomic step using retrieved hint traces; Critic checks post‑state after each unit → retryable triggers local re‑optimization; blocked aborts.  
4. Successful plan stored for future reuse.

**Design tradeoffs**  
- *Cache‑first planning:* Low latency but may miss novel solutions; depends on intent‑similarity accuracy.  
- *Hierarchical clustering:* Balances granularity but sensitive to embedding quality and HDBSCAN parameters.  
- *Multi‑agent loop:* Improves robustness at cost of additional re‑optimization overhead.  
- *Skill abstraction:* Parameterization enables reuse but may oversimplify complex dependencies.

**Failure signatures**  
- Grounding failures under pop‑ups or UI changes.  
- Retrieval mismatch from poor embeddings or bloated memory.  
- Intent drift when synthesizing new plans during cache misses.  
- Memory bloat slowing retrieval and degrading relevance.

**First 3 experiments**  
1. Planning component ablation (Section 5.2, Table 1) isolates contributions of TSG, Z, SSG, and PM.  
2. Representation loss ablation (Appendix C, Tables 3–4) validates the multi‑view loss design via clustering metrics.  
3. End‑to‑end baseline comparison (Section 6, Table 2, Figures 5–6) measures success, SER, and latency on 286 tasks.

## Open Questions the Paper Calls Out

**Open Question 1:** How can retrieval efficiency and accuracy be maintained as plan memory scales to large, diverse interaction corpora?  
*Basis:* The conclusion suggests graph‑based retrieval and vision cues as potential enhancements.  
*Why unresolved:* The centroid‑based retrieval may degrade with size, but no scalable alternative is implemented or evaluated.  
*Resolving evidence:* Benchmarks comparing graph‑based or vision‑augmented retrieval against the current method on progressively larger memory sets, measuring latency and precision.

**Open Question 2:** How can the grounding module be made robust to transient, unpredictable UI changes (e.g., pop‑ups, occlusions) that cause execution failures?  
*Basis:* The case study identifies “script‑based GUI grounding” failure under unexpected pop‑up occlusion.  
*Why unresolved:* Plan‑Optimizer relies on stable screen parsing; no adaptation mechanism is proposed.  
*Resolving evidence:* Controlled experiments with synthetic or real‑world transient UI disruptions, measuring recovery success and reduced retry loops after integrating occlusion handling.

**Open Question 3:** What is the optimal multi‑view representation learning objective for inducing semantically coherent and non‑fragmented intent subgroups?  
*Basis:* Ablation shows trade‑offs: reconstruction increases separation but causes over‑fragmentation; full loss balances purity but weights are heuristic.  
*Why unresolved:* Ideal balance across diverse domains remains unknown.  
*Resolving evidence:* Systematic hyperparameter sweeps or novel objectives tested on clustering metrics (separation, purity, stability) across multiple trace datasets, correlated with downstream planning performance.

**Open Question 4:** To what extent can learned skill abstractions generalize to domains with sparse or no interaction traces, and how can reliance on trace frequency be reduced?  
*Basis:* Domain analysis notes trace sparsity and bias remain limitations; the paper shows non‑trivial success on 65% unseen domains but does not analyze failure modes.  
*Why unresolved:* Plan memory and skill extraction depend on sufficient trace coverage; transfer mechanisms are unexplored.  
*Resolving evidence:* Few‑shot or zero‑shot transfer experiments where skill hints from rich domains are adapted to new tasks, measuring success rates against baselines without such transfer.

## Limitations
- **Unreported hyperparameters:** HDBSCAN settings (min_cluster_size, min_samples) and similarity thresholds for retrieval are not disclosed, risking non‑reproducible clustering.
- **Missing implementation details:** The GUI grounding module (e.g., UI detection model, parsing logic) and exact LLM prompt templates for Planner, Plan‑Optimizer, and Critic are omitted.
- **Domain shift risk:** The offline trace corpus (36 domains) may not cover the distribution of the 286 test tasks (63 domains), potentially affecting retrieval performance.
